## .NET / C#

**DN1** — A `class` is a reference type (allocated on heap, nullable, supports inheritance), while a `struct` is a value type (allocated inline, copied on assignment, sealed by default). Use a struct when the type represents a small, immutable, single logical value (e.g., `Point`, `Guid`, `DateTime`) and when copying is cheaper than heap allocation. Avoid structs for large (>16 bytes) or mutable types.

**DN2** — `IEnumerable<T>` is in-memory (LINQ to Objects) and executes on the client; `IQueryable<T>` is expression-tree-based (LINQ to SQL/EF) and translates to a query on the server. For database queries, `IQueryable` defers execution and allows the DB to optimize (e.g., `WHERE` pushed to SQL). Using `IEnumerable` would fetch all rows into memory first, causing performance issues.

**DN3** — `async/await` uses state machines to suspend execution without blocking threads. `Task` is a reference type; `ValueTask` is a struct that avoids heap allocation when the result is likely synchronous or short-lived. Use `ValueTask` for hot paths (e.g., `IAsyncEnumerable` methods) where allocation overhead matters, but beware it can only be awaited once and not cached.

**DN4** — DI is a pattern where dependencies are injected rather than created. Lifetimes: **Transient** (new per resolution), **Scoped** (one per request/scope), **Singleton** (one per app). Common bug: injecting a Scoped service (e.g., `DbContext`) into a Singleton captures the first request's scope, causing stale data or `ObjectDisposedException` after the scope ends. Fix: use `IServiceProvider` to create a scope inside the Singleton, or make the service Scoped.

**DN5** — `string` is immutable and UTF-16; `ReadOnlySpan<char>` is a stack-allocated view over memory (no allocation). Use `Span<T>` for high-performance parsing, slicing, or processing without allocations (e.g., `string.Split` alternatives). It avoids GC pressure and is ideal for hot paths, but is limited to synchronous, stack-bound usage.

**DN6** — GC uses generations: Gen0 (short-lived, collected often), Gen1 (survivors), Gen2 (long-lived). Large Object Heap (LOH) holds objects >85KB, collected rarely. `IDisposable` is for deterministic cleanup of unmanaged resources (files, sockets) that GC cannot handle; GC only handles managed memory. Without `Dispose`, unmanaged resources leak until finalizer runs (non-deterministic).

**DN7** — `ConfigureAwait(false)` tells the continuation not to capture the current `SynchronizationContext` (e.g., UI thread), avoiding deadlocks in UI apps. Use it in library code (no UI context). Do NOT use it in UI code (WinForms/WPF) where you need to return to the UI thread. In ASP.NET Core, there's no sync context, so it's often unnecessary. Default behavior captures context if present.

**DN8** — .NET 8/9 features: **Primary constructors** allow parameters directly on class declaration; **collection expressions** (`[1,2,3]` or `[]`); **FrozenDictionary** is immutable and optimized for read-only lookups. Example:
```csharp
public class MyService(ILogger<MyService> logger) {
    public void Do() => logger.LogInformation("...");
}
// DI: services.AddSingleton<MyService>();
```

**DN9** — Likely cause: `DbContext` is Scoped, but under high concurrency, a Singleton service holds a reference to a Scoped `DbContext` from a completed request, then disposes it. Fix: ensure `DbContext` is resolved within a scope (e.g., `IServiceScopeFactory.CreateScope()`), or make the service Scoped. EF Core's `DbContext` is not thread-safe; each scope should have its own instance.

**DN10** — `record` is a reference type with value equality, `ToString`, and `with` support; `class` uses reference equality. `record struct` is a value type with similar features. Use `record` for immutable data models (DTOs), `class` for behavior-heavy types, `record struct` for small, immutable value types that need equality semantics.

**DN11** — `ref` requires variable initialized, can read/write; `out` requires variable uninitialized, must assign before return; `in` is read-only reference (avoids copying). Use `ref` for modifying caller's variable, `out` for multiple return values, `in` for passing large structs without copying.

**DN12** — Nullable reference types (`string?`) are compile-time annotations; `#nullable enable` enables them. They don't change runtime behavior—only compiler warnings. Nullable value types (`int?`) are `Nullable<T>` structs that actually hold a value or `null`. Reference types are always nullable at runtime; annotations are for static analysis.

**DN13** — LINQ is a set of methods for querying collections. Method syntax uses extension methods (`list.Where(x => x > 0)`); query syntax is declarative (`from x in list where x > 0 select x`). Deferred execution means the query is not executed until enumerated; intermediate operations are lazy, enabling efficiency (e.g., `Where` before `Take`).

**DN14** — Constraints restrict generic types: `where T : class` (reference type), `struct` (value type), `new()` (parameterless ctor), `IComparable<T>` (implements interface). Combine with `,` (e.g., `where T : class, IComparable<T>, new()`). Use to ensure type supports required operations.

**DN15** — Abstract classes have implementation, state, and constructors; interfaces are pure contracts. Since C# 8, interfaces can have default implementations, but they cannot have state. Use abstract class for shared base logic; interface for capability contracts. Default methods allow adding members without breaking implementers.

**DN16** — Middleware pipeline is a series of delegates (`RequestDelegate`) that process requests. `Use()` adds middleware with `next`; `Map()` branches based on path; `Run()` is terminal (no `next`). Order matters—exception handling must be early. Exception middleware catches exceptions from downstream and returns a response.

**DN17** — `Channel<T>` is a modern, async-first, thread-safe producer-consumer queue. `BlockingCollection<T>` is synchronous and uses `IProducerConsumerCollection`. Bounded channels provide backpressure: `new BoundedChannelOptions(10) { FullMode = Wait }` makes producers await when full. Example:
```csharp
var channel = Channel.CreateBounded<int>(10);
await channel.Writer.WriteAsync(1);
await foreach (var item in channel.Reader.ReadAllAsync()) { ... }
```

**DN18** — Source Generators generate C# code at compile time, avoiding runtime reflection. They differ from reflection (no runtime cost) and IL weaving (compile-time, but IL-level). Incremental generators (`IIncrementalGenerator`) cache intermediate results, improving build performance; `ISourceGenerator` is older and re-runs everything.

**DN19** — TPL Dataflow provides `ActionBlock` (process each item), `TransformBlock` (transform), `BufferBlock` (buffering). It supports complex pipelines with backpressure and parallelism. `Channel<T>` is simpler and more lightweight for basic producer-consumer. Dataflow is better for multi-stage pipelines with error handling and bounded capacity.

**DN20** — Minimal APIs are lightweight endpoints using `app.MapGet("/", () => "Hello")`. They differ from controllers by avoiding MVC overhead, attribute routing, and model binding. Trade-offs: less structure, harder to test (no `ControllerBase`), but faster startup and simpler. Route groups (`MapGroup`) organize endpoints; endpoint filters (`AddFilter`) run before/after handlers for cross-cutting concerns.

## Python

**P1** — Lists are mutable, tuples are immutable. Sets are unordered, mutable, hashable elements; frozensets are immutable sets. Use lists for ordered mutable data, tuples for fixed records, sets for membership tests, frozensets for hashable set keys.

**P2** — GIL is a mutex that serializes Python bytecode execution, preventing true parallelism in CPU-bound threads. It affects CPU-bound workloads (e.g., loops, math) but not I/O-bound (threads release GIL during I/O). Workarounds: use `multiprocessing` (separate processes), `asyncio` for I/O, or C extensions that release GIL.

**P3** — `copy.copy` creates a shallow copy (new object, shared nested objects); `copy.deepcopy` recursively copies all objects. Example: a list of lists—shallow copy shares inner lists, so modifying `copy[0]` affects original. Deepcopy avoids this but is slower and can fail on recursive structures.

**P4** — Decorators are functions that wrap other functions. Example:
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.2f}s")
        return result
    return wrapper
```

**P5** — Generators use `yield` to produce values lazily, one at a time, preserving state. They differ from lists by not storing all values in memory. `yield from` delegates to another iterable (e.g., `yield from subgen`). Useful for infinite sequences or large data streams.

**P6** — `asyncio.run()` starts the event loop and runs a coroutine; `asyncio.gather()` runs multiple coroutines concurrently and waits for all; `create_task()` schedules a coroutine as a task without blocking. `time.sleep()` blocks the thread, not the event loop, so it would block all async tasks. Use `await asyncio.sleep()` instead.

**P7** — Python 3 uses C3 linearization (MRO). For diamond inheritance `D(B, C)`, MRO is `D -> B -> C -> A -> object`. `D().who()` finds `who` in `B` (inherits from `A`), but `C` overrides it, so MRO checks `B` first (no override), then `C` (override), so it prints `"C"`. The MRO ensures each class appears once and preserves monotonicity.

**P8** — A metaclass is a class that creates classes (e.g., `type`). `__init_subclass__` is a hook called when a subclass is created, simpler for class customization. Use metaclass for complex class creation (e.g., registering classes, modifying attributes). Use `__init_subclass__` for simple validation or registration. Example: metaclass for auto-registering plugins; `__init_subclass__` for enforcing attribute presence.

**P9** — `threading` uses threads (GIL-bound, good for I/O); `multiprocessing` uses processes (true parallelism, but pickling overhead); `concurrent.futures` provides high-level `ThreadPoolExecutor`/`ProcessPoolExecutor`. Use threads for I/O-bound, processes for CPU-bound. Multiprocessing requires picklable arguments/returns; lambdas and local functions fail.

**P10** — `__slots__` prevents dynamic attribute creation, saving memory by using fixed-size slots instead of `__dict__`. Use for classes with many instances (e.g., millions) to reduce memory. It prevents adding new attributes and requires `__slots__` in subclasses. Memory savings can be ~50% per instance.

**P11** — A virtual environment isolates dependencies per project. `venv` is built-in, lightweight; `virtualenv` is third-party, more features; `conda` is cross-language, manages packages and environments. Use `venv` for simple Python projects; `conda` for scientific/compiled dependencies.

**P12** — Comprehensions are concise syntax: `[x for x in list]`, `{k: v for ...}`, `{x for x in ...}`. They are more readable and faster than `map()`/`filter()` with lambdas. Prefer comprehensions for clarity; use `map`/`filter` when you have a named function or need to chain.

**P13** — `==` compares values; `is` compares identity (memory address). Object interning caches small integers (-5 to 256) and some strings, so `a is b` may be `True` for those. Use `==` for equality, `is` for `None` or singleton checks.

**P14** — `*args` collects extra positional args as a tuple; `**kwargs` collects extra keyword args as a dict. Positional-only (`/`) forces arguments before it to be positional; keyword-only (`*`) forces arguments after it to be keyword. Example: `def f(a, /, b, *, c):` — `a` positional-only, `c` keyword-only.

**P15** — Context managers use `with` to manage resources. Implement with `__enter__`/`__exit__` or `@contextmanager` decorator. Example beyond files: timing code:
```python
from contextlib import contextmanager
@contextmanager
def timer():
    start = time.time()
    yield
    print(f"Elapsed: {time.time()-start}")
```

**P16** — Type hints annotate function signatures. `Union` (or `|`), `Optional` (`Union[T, None]`), `Literal` (specific values), `TypeVar` (generic), `Protocol` (structural typing). Mypy/pyright use these to statically check types, catch errors before runtime. Example: `def f(x: Union[int, str]) -> Optional[bool]`.

**P17** — Dunder methods define behavior. `__repr__` is unambiguous for debugging; `__str__` is human-readable. `__eq__` defines equality; `__hash__` must be consistent—if you define `__eq__` without `__hash__`, the object becomes unhashable (hash set to `None`). `__getattr__` is called when attribute not found; `__getattribute__` is called for every attribute access.

**P18** — Descriptors implement `__get__`, `__set__`, `__delete__` to control attribute access. `property` uses `__get__`/`__set__`; `classmethod` binds the class; `staticmethod` returns the function unchanged. Descriptors are stored on the class, not instance, enabling shared behavior.

**P19** — Import system: `sys.path` lists directories; `PYTHONPATH` adds to it. `__init__.py` marks packages; namespace packages (PEP 420) don't need it. Relative imports use `.`/`..`; absolute use full path. Finders locate modules, loaders execute them. `importlib` allows custom finders/loaders for dynamic imports.

**P20** — `dataclasses` auto-generates `__init__`, `__repr__`, `__eq__` from annotations. `attrs` is more feature-rich (validators, converters); `Pydantic` adds validation, serialization, and schema. `__post_init__` runs after init; `field(default_factory=...)` for mutable defaults; `frozen=True` makes immutable. Inheritance works but fields are merged. Choose Pydantic for data validation from external sources; dataclasses for internal simple data.
