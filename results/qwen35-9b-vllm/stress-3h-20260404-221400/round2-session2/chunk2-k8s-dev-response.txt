**K1**
A **Deployment** manages stateless applications, ensuring a specific number of replicas with no stable identity (pods are interchangeable). A **StatefulSet** manages stateful applications, providing stable, unique network identifiers (pod names), stable storage (persistent volumes), and ordered deployment/termination.

**K2**
A **ClusterIP** Service creates a virtual IP within the cluster. Traffic routed to this IP is intercepted by **kube-proxy** (via iptables or IPVS rules). kube-proxy forwards the traffic to the IP addresses listed in the Service's **Endpoints** object, which correspond to the running pods.

**K3**
A **PersistentVolume (PV)** is a cluster-wide storage resource provisioned by an admin. A **PersistentVolumeClaim (PVC)** is a request for storage by a user. A **StorageClass** defines the provisioner and parameters for dynamic PVC provisioning. **Relation:** A PVC requests storage; if dynamic, the StorageClass determines how the PV is created; if static, the PV is pre-created and bound to the PVC.

**K4**
1. **Check Logs:** `kubectl logs <pod>` to see application errors.
2. **Check Status:** `kubectl describe pod <pod>` to check `Ready` status and `Last State` (Terminated).
3. **Check Resources:** Verify if the container exceeded memory/CPU limits causing OOMKilled.
4. **Check Entrypoint/Health:** Verify the container command is correct and liveness probes aren't failing.

**K5**
**CoreDNS** provides DNS resolution for services and pods within the cluster (e.g., resolving `my-service.namespace.svc.cluster.local`). If CoreDNS pods are down, internal service discovery fails (pods cannot reach other services via DNS), and external access to cluster services breaks.

**K6**
The scheduler **filters** nodes based on constraints (taints, affinity, resources). It then **scores** nodes based on preferences. **Factors:** 1. **Node Affinity/Labels:** Matching pod requirements to node labels. 2. **Taints/Tolerations:** Ensuring the node accepts the pod. 3. **Resource Availability:** Ensuring CPU/Memory requests fit. 4. **Pod Priority:** Higher priority pods preempt lower ones.

**K7**
**Yes**, the pod will be scheduled because the requested memory (256Mi) is less than the available node memory (3.5GB). However, if the runtime usage exceeds the **limit** (512Mi), the container will be **OOMKilled** (Out Of Memory Killed) by the kernel, causing the pod to crash.

**K8**
1. **External LB:** Receives traffic.
2. **Ingress Controller (NGINX):** Terminates SSL, matches rules, and routes to the backend Service.
3. **Service (ClusterIP):** Internal IP for the application.
4. **Endpoints:** List of Pod IPs backing the Service.
5. **kube-proxy/iptables:** Creates rules on the node to forward traffic from Service IP to Pod IP.
6. **Pod:** Application receives the request.

**K9**
A **NetworkPolicy** restricts ingress/egress traffic to/from pods. **Default behavior:** Without a policy, all traffic is allowed. **Applying one:** Traffic is restricted to only the rules defined (e.g., allow only from specific pods or namespaces).

**K10**
**RollingUpdate** updates pods gradually (zero downtime). **Recreate** stops all old pods before starting new ones (downtime). Choose **Recreate** for stateful databases (e.g., MySQL) where data must be flushed or zero downtime is not required.

**K11**
A **Namespace** is a logical partition for resources (names, quotas). **Default namespaces:** `default`, `kube-system`, `kube-public`, `kube-node-lease`.

**K12**
`kubectl describe pod` shows detailed metadata and runtime status. **3 pieces of info:** 1. **Events:** History of pod lifecycle events. 2. **Conditions:** Detailed readiness/liveness status. 3. **Node Name:** Which node the pod is running on.

**K13**
A **ConfigMap** stores non-confidential key-value data. **Methods:** 1. **Environment Variables:** Mount as env vars. 2. **Volume Mount:** Mount as a directory/files. 3. **Command Args:** Pass as arguments.

**K14**
**ClusterIP:** Internal cluster access only. **NodePort:** Exposes a port on every node's IP. **LoadBalancer:** Exposes an external IP (via cloud LB) to the internet.

**K15**
A **DaemonSet** ensures a copy of a pod runs on all (or selected) nodes. Use it for **system-level tasks** like logging agents (Fluentd), monitoring (Prometheus Node Exporter), or network plugins (Calico), rather than user applications (Deployments).

**K16**
**Taints** (on Node) repel pods; **Tolerations** (on Pod) allow pods to ignore taints. **Node Affinity** (on Pod) attracts pods to specific nodes. **Use Case:** Taints for GPU nodes (only pods with tolerations can run); Affinity for placing DB and App on same zone.

**K17**
An **Operator** is a custom controller that manages the lifecycle of a specific application (e.g., backups, upgrades). It differs from a standard controller (like Deployment) by implementing **domain-specific logic**. It solves problems where standard controllers lack the intelligence to manage complex stateful workflows.

**K18**
Kubernetes uses **Raft consensus** for etcd (linearizable). If **quorum is lost** (e.g., 2/3 nodes fail), the cluster becomes unavailable. **Recovery:** If 2 nodes are lost, only 1 remains (no quorum). You must **restore etcd from a snapshot** or rebuild the cluster from scratch (data loss) if no backup exists.

**K19**
**RBAC** grants permissions based on subjects (Users/Groups) and resources. **Role** (namespace-scoped) defines permissions; **ClusterRole** (cluster-scoped) defines permissions. **Binding** links Subject to Role.
**Manifests:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: dev
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  namespace: dev
  name: read-pods
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20**
**ndots** is the minimum number of dots required to split a domain. If a domain has fewer dots than `ndots`, it is treated as a single name. If `ndots` is high (e.g., 5) and the domain is short (e.g., `google.com`), the resolver tries the full name first, which may fail or be slow, causing retries. **Fix:** Set `ndots: 1` in `dnsConfig` to force splitting.
```yaml
dnsConfig:
  options:
  - name: ndots
    value: "1"
```

**D1**
**Rebase** rewrites history to make it linear (commits move). **Merge** preserves history (creates a merge commit). **Avoid rebasing** on public/shared branches or branches with unpushed commits that others might rely on.

**D2**
**TCP** is reliable, ordered, connection-oriented (HTTP, SSH). **UDP** is unreliable, unordered, connectionless (DNS, Video Streaming).

**D3**
A **race condition** occurs when the outcome depends on the timing of concurrent events. **Example:** Two threads increment a shared counter `count++` without locks; one read-modify-write operation overwrites the other, resulting in `count` being less than expected.

**D4**
**Symmetric** uses one key for encryption/decryption (e.g., AES). **Asymmetric** uses a public/private key pair (e.g., RSA). **TLS:** Uses Asymmetric (RSA/ECC) to exchange a session key, then Symmetric (AES) to encrypt the actual data transfer.

**D5**
A **layer** is a read-only filesystem image in a container. **Caching:** Docker caches layers based on instruction content. **Best Practice:** Combine `RUN` commands to reduce layers, avoid `ARG` in layers, and use `.dockerignore` to exclude unnecessary files.

**D6**
1. **Check App Logs:** Look for 503 errors or DB timeouts.
2. **Check Health Checks:** Verify liveness/readiness probes are passing.
3. **Check Load Balancer:** Ensure the backend pool is healthy.
4. **Check Dependencies:** Verify database connectivity and upstream services.

**D7**
**CAP Theorem:** A distributed system can only guarantee 2 of 3: Consistency, Availability, Partition Tolerance. **CP Example:** ZooKeeper (prioritizes data consistency). **AP Example:** DynamoDB/Cassandra (prioritizes availability during partition).

**D8**
**Horizontal Scaling:** Adding more instances (HPA). **Vertical Scaling:** Increasing resources (CPU/RAM) of existing instances. **Patterns:** Stateless apps, Microservices, Load-balanced pools enable horizontal scaling.

**D9**
An **environment variable** is a dynamic value accessible by processes. **Persist across sessions:** Use `export VAR=value` in the current shell, or add `export VAR=value` to `~/.bashrc` or `~/.profile`.

**D10**
**JSON** is strict, machine-readable (e.g., `{"key": "value"}`). **YAML** is human-readable, indentation-based (e.g., `key: value`). **JSON Advantage:** Strict validation. **YAML Advantage:** Readability for humans.

**D11**
A **REST API** uses HTTP methods to manipulate resources. **GET:** Retrieve data. **POST:** Create new resource. **PUT:** Replace/Update resource. **DELETE:** Remove resource.

**D12**
**Version pinning** locks dependencies to specific versions (e.g., `==1.2.3`). It is important to prevent **breaking changes** from upstream updates and ensure **reproducible builds** across environments.

**D13**
**Compiled languages** translate source to binary machine code (e.g., C++, Rust). **Interpreted languages** execute source code line-by-line or via bytecode (e.g., Python, JavaScript).

**D14**
**Reverse Proxy:** Server-side (e.g., Nginx, HAProxy). Use case: SSL termination, load balancing. **Forward Proxy:** Client-side (e.g., Squid). Use case: Corporate internet access, caching.

**D15**
A **deadlock** is when threads block each other indefinitely. **Coffman Conditions:** 1. Mutual Exclusion. 2. Hold and Wait. 3. No Preemption. 4. Circular Wait.

**D16**
**Eventual Consistency** means data converges over time. **Cassandra:** Uses **Tunable Consistency** (ONE, QUORUM, ALL). **Read-after-write:** If replication factor is high, reads might see old data; consistency level determines how many replicas must confirm the write.

**D17**
**mTLS** authenticates both client and server. **Handshake:** 1. Client sends Client Hello + Client Cert. 2. Server verifies Client Cert. 3. Server sends Server Hello + Server Cert. 4. Client verifies Server Cert. 5. Both establish shared keys. **Use:** Service Mesh (Istio), API Gateways.

**D18**
A **hash table** uses an array and a hash function to map keys to indices. **Collision Resolution:** **Chaining** (linked list at index) vs **Open Addressing** (probing next slot). **Complexity:** Average O(1), Worst O(n) (due to collisions).

**D19**
**Circuit Breaker** prevents cascade failures. **States:** **Closed** (normal, requests pass), **Open** (failures, requests blocked), **Half-Open** (testing, limited requests allowed). **Retry:** Uses exponential backoff to retry requests when the circuit is Half-Open.

**D20**
**Optimistic:** Assume no conflict; check version on commit (CAS). **Pessimistic:** Lock resources immediately. **Example:** **Optimistic:** `UPDATE table SET col=val WHERE id=1 AND version=5`. **Pessimistic:** `SELECT ... FOR UPDATE` (locks row). Choose Optimistic for low contention, Pessimistic for high contention.
