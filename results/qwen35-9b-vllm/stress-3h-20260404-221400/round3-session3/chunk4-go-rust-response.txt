**G1**
In Go, an **array** is a fixed-size sequence of elements stored contiguously in memory; it is a value type. A **slice** is a dynamic view into an underlying array, storing a pointer, length, and capacity.
*   **Difference:** Arrays are values (copied on assignment); slices are references (shallow copy). Arrays have fixed length; slices have dynamic length.
*   **Append:** If a slice's length reaches its capacity, `append` allocates a new underlying array (usually double the capacity), copies the old elements, and returns a new slice pointing to the new array.

**G2**
*   `var x int`: Declares a variable `x` of type `int`, initializes it to the zero value (`0`), and allows reassignment.
*   `x := 0`: Short declaration. Initializes `x` to `0` and assigns it. Type is inferred.
*   **Restriction:** `:=` cannot be used in a function scope if the variable already exists (e.g., `x` declared earlier). It is also not allowed in global scope (must use `var` or `:=` with package-level scope).

**G3**
A **goroutine** is a lightweight thread of execution managed by the Go runtime. It differs from an OS thread in that goroutines are much smaller (stack grows dynamically) and the runtime multiplexes them onto a smaller number of OS threads.
*   **GMP Model:** **G** (Goroutine), **M** (Machine/OS Thread), **P** (Processor). The scheduler runs on P. If a G is blocked, the P is stolen or created. If a P is idle, it steals Gs from other Ps. This enables high concurrency with low OS overhead.

**G4**
Channels are typed conduits for sending/receiving values between goroutines.
*   **Unbuffered:** Send blocks until a receiver is ready.
*   **Buffered:** Send blocks only if the buffer is full.
*   **Full Buffer:** If a buffered channel is full, a send operation blocks until a receiver takes a value.

**G5**
The `context` package manages cancellation, deadlines, and request-scoped values across API boundaries.
*   **Example:**
    ```go
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()
    // Use ctx in HTTP request: http.Get(ctx, url)
    ```

**G6**
Go uses **duck typing**: a type satisfies an interface if it implements the required methods. Java/C# require explicit interface declarations.
*   **`interface{}` (or `any`):** The empty interface. It can hold any value.
*   **Power:** Maximum flexibility for generic-like behavior or serialization.
*   **Danger:** Loses type safety; requires type assertions to use values, leading to runtime panics if incorrect.

**G7**
This code is **unsafe** due to a **data race**. `ready` and `data` are shared variables accessed by the goroutine and the main goroutine without synchronization. The Go memory model does not guarantee visibility of writes across goroutines without memory barriers.
*   **Fix:** Use `sync.WaitGroup` (wait for goroutine), `sync.Mutex` (protect shared state), or channels (pass `data` and signal completion).

**G8**
*   **Mutex:** Exclusive access (write lock).
*   **RWMutex:** Allows multiple concurrent readers, but exclusive access for writers.
*   **sync.Map:** Optimized for concurrent reads and sparse writes. Uses a hash table with per-bucket locks.
*   **Map + Mutex:** Better for high write contention or dense maps. `sync.Map` avoids locking for reads but has higher overhead for writes.

**G9**
Go modules manage dependencies.
*   **`go.mod`:** Manifest containing module path and required dependencies (versions).
*   **`go.sum`:** Checksums of downloaded modules to ensure integrity.
*   **`go mod tidy`:** Removes unused dependencies and updates `go.mod` to match `go.sum`.
*   **MVS:** The algorithm selects the minimum version of a dependency that satisfies all constraints in the module graph.

**G10**
`defer` schedules a function call to run when the surrounding function returns.
*   **Order:** Executes in **LIFO** (Last In, First Out) order.
*   **Gotcha:** In a loop, `defer` captures the loop variable by reference. All deferred calls may see the final value of the loop variable. Use `defer func() { ... }(i)` to capture the value.

**G11**
A pointer holds the memory address of a variable.
*   **Zero Value:** `nil`.
*   **Pointer to Struct Literal:** `&Struct{Field: value}`.

**G12**
`init()` is a function that runs automatically when a package is loaded.
*   **Timing:** Runs before `main()`.
*   **Multiple:** A package can have multiple `init` functions. They execute in the order they are declared in the source files.

**G13**
*   **`make`:** Allocates and initializes built-in types (slices, maps, channels). E.g., `make(map[string]int)`.
*   **`new`:** Allocates zeroed memory and returns a pointer to the type. E.g., `new(int)` returns `*int`.
*   **Types:** `make` works with slices, maps, channels. `new` works with any type.

**G14**
Go uses an `error` interface (`error interface { Error() string }`).
*   **Idiomatic:** `if err != nil { ... }`.
*   **`errors.Is`:** Checks if an error wraps a specific target error (predicate).
*   **`errors.As`:** Type asserts an error to a specific type (e.g., `*net.OpError`).
*   **Difference:** `==` checks identity (same pointer); `Is` checks wrapping; `As` checks type.

**G15**
*   **Map:** Zero value is `nil`.
*   **Slice:** Zero value is `nil`.
*   **Channel:** Zero value is `nil`.
*   **Struct:** Zero value is fields set to their respective zero values (e.g., `0`, `""`, `false`).

**G16**
A **race condition** occurs when two goroutines access shared memory concurrently without synchronization, and at least one is a write.
*   **Fix:** Use `-race` flag to detect.
*   **Example:**
    ```go
    var count int
    go func() { count++ }() // Race
    ```
    **Fix:**
    ```go
    var mu sync.Mutex
    go func() { mu.Lock(); count++; mu.Unlock() }()
    ```

**G17**
`select` chooses a case based on channel readiness.
*   **Difference:** `switch` evaluates expressions; `select` evaluates channel operations.
*   **Multiple Ready:** If multiple cases are ready, one is chosen randomly.
*   **Timeout:** Use `select` with a `time.After` channel to handle timeouts.

**G18**
**Escape analysis** determines if a variable can be allocated on the stack or must be on the heap.
*   **Decision:** If a variable is used outside the current function (e.g., returned, passed to another goroutine), it escapes the stack.
*   **Inspection:** `go build -gcflags="-m"`.
*   **Performance:** Heap allocation incurs GC overhead. Minimizing escapes improves performance.

**G19**
The `reflect` package allows runtime introspection of types and values.
*   **`reflect.Type`:** Metadata about a type.
*   **`reflect.Value`:** The actual value of a variable.
*   **Cost:** Very slow compared to direct access.
*   **Usage:** Justified for generic-like behavior, serialization, or dynamic dispatch where generics aren't available.

**G20**
`go:embed` embeds files or directories at compile time.
*   **Usage:** `//go:embed file.txt` or `//go:embed dir/`.
*   **FS:** `//go:embed dir/` creates an `io/fs.FS` object.
*   **Limitations:** Paths must be relative to the module root. Cannot embed directories with specific file patterns unless using `io/fs.FS`.

**R1**
**Ownership** means exactly one variable owns the data at a time.
*   **Rule 1:** Each value has a single owner.
*   **Rule 2:** When the owner leaves scope, the value is dropped (memory freed).
*   **Rule 3:** When a value is moved, the old owner can no longer access it.

**R2**
*   **`String`:** Owned heap-allocated string. Used when returning data or storing data.
*   **`&str`:** Borrowed slice of UTF-8 bytes. Used for function arguments (input) or literals.
*   **Signatures:** Use `&str` for inputs (avoids cloning); use `String` for outputs (transfers ownership).

**R3**
**Borrowing** allows accessing data without taking ownership.
*   **`&T`:** Shared reference. Can read, cannot mutate. Multiple references allowed.
*   **`&mut T`:** Mutable reference. Can read/write. Only one mutable reference allowed at a time.
*   **Rules:** No aliasing (two mutable refs) or mutable + shared ref simultaneously.

**R4**
*   **`Result<T, E>`:** Represents success (`Ok(T)`) or failure (`Err(E)`).
*   **`Option<T>`:** Represents presence (`Some(T)`) or absence (`None`).
*   **`?` operator:** Propagates errors (returns immediately if `Err`).
*   **Example:**
    ```rust
    fn read_file(path: &str) -> Result<String, std::io::Error> {
        std::fs::read_to_string(path)?
    }
    ```

**R5**
*   **`Box<T>`:** Heap allocation, single owner. Used for recursive types or large data.
*   **`Rc<T>`:** Reference counting, single thread. Used for shared ownership in UI trees.
*   **`Arc<T>`:** Atomic reference counting, multi-thread. Used for shared ownership in concurrent code.

**R6**
*   **Traits:** Define behavior (methods).
*   **Comparison:** Go interfaces are implicit (duck typing); Rust traits are explicit.
*   **`dyn Trait`:** Trait object (dynamic dispatch, heap allocation).
*   **`T: Trait`:** Generic bound (static dispatch, compile-time resolution).

**R7**
**Lifetimes** ensure references don't outlive the data they point to.
*   **Failure:** The compiler cannot guarantee `x` or `y` live long enough for the return value.
*   **Fix:** Add a lifetime parameter:
    ```rust
    fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { ... }
    ```

**R8**
*   **`Send`:** Type can be sent across threads.
*   **`Sync`:** Type can be shared between threads.
*   **`Rc<T>`:** Not `Send` because reference counting is not atomic.
*   **`Arc<T>`:** `Send` and `Sync` because it uses atomic reference counting.

**R9**
Rust's `async/await` compiles to state machines (Futures).
*   **`Future`:** Trait representing a value that will be ready eventually.
*   **Executor:** (e.g., Tokio) polls Futures to drive them to completion.
*   **Difference:** Go uses OS threads (M:N scheduling); Rust uses cooperative multitasking on OS threads (usually 1:1 or 1:N depending on runtime).

**R10**
**`unsafe`** blocks allow bypassing Rust's safety guarantees.
*   **Examples:** Dereferating raw pointers, calling FFI functions, accessing union fields.
*   **Justification:** Only when necessary for FFI, performance-critical code, or interacting with unsafe external libraries.

**R11**
**Pattern matching** (`match`) exhaustively checks all variants of an enum.
*   **`if let`:** Partial match (ignores other cases).
*   **Enforcement:** `match` requires all cases to be handled (exhaustive), preventing runtime panics.

**R12**
*   **`Vec<T>`:** Heap-allocated, dynamic size.
*   **`[T; N]`:** Stack-allocated, fixed size.
*   **Memory:** `Vec` reallocates and copies elements when capacity is exceeded (geometric growth).

**R13**
**Enums** are tagged unions (data + variant tag).
*   **Difference:** C/Java enums are static sets of constants; Rust enums are data structures.
*   **`Option<T>`:** `Some(T)` or `None`.
*   **No Null:** `None` is a valid value, not a pointer error.

**R14**
**`impl` block** defines methods for a type.
*   **`&self`:** Borrowed read access.
*   **`&mut self`:** Borrowed mutable access.
*   **`self`:** Takes ownership (consumes the value).
*   **Associated Functions:** Static methods (e.g., `String::new()`), no `self`.

**R15**
**Derive macros** automatically implement traits.
*   **Examples:** `#[derive(Debug, Clone, PartialEq)]`.
*   **Limitations:** Cannot derive if struct has private fields (for `Clone`/`PartialEq`), or complex types (e.g., `unsafe` types).

**R16**
**`Cow<'a, T>`** (Clone On Write) holds a reference if immutable, or a clone if mutable.
*   **Use:** Avoids cloning large data if it's not modified.
*   **Example:**
    ```rust
    let cow = Cow::Borrowed("hello");
    // cow += " world" -> Cow::Owned("hello world") (allocates)
    ```

**R17**
**Modules** organize code.
*   **`mod`:** Defines a module.
*   **`use`:** Imports items.
*   **`pub`:** Public visibility.
*   **Mapping:** 2015 edition used file names; 2018 edition uses path-based modules (e.g., `src/lib.rs` vs `src/mod.rs`).

**R18**
**`Pin<T>`** prevents a value from being moved.
*   **Need:** Required for self-referential structs (pointers to self) and async tasks (Futures must stay at a stable address).
*   **`Unpin`:** Trait to allow moving a pinned value.

**R19**
**Macros** generate code.
*   **Declarative (`macro_rules!`):** Textual substitution, limited hygiene.
*   **Procedural:** Rust code that generates tokens (derive, attribute, function-like).
*   **Hygiene:** Prevents macro variables from conflicting with outer scope variables.

**R20**
**Zero-cost abstractions** mean high-level code compiles to the same machine code as hand-written low-level code.
*   **Iterators:** No heap allocation; state is on the stack.
*   **Generics:** Monomorphization (code generated for each type).
*   **Traits:** Static dispatch (no vtable overhead) when used with generics.
