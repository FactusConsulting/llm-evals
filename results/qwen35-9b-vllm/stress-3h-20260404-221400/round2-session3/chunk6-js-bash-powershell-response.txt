## JavaScript / TypeScript

**JS1**
`var` is function-scoped, hoisted, and allows redeclaration/reassignment. `let` is block-scoped, hoisted (temporal dead zone), and prevents redeclaration. `const` is block-scoped, hoisted, and prevents reassignment (but allows reassignment of properties). Hoisting moves declarations to the top of the scope during compilation, but initialization does not occur until execution.

**JS2**
The event loop manages asynchronous execution. The call stack executes synchronous code. When the stack is empty, the event loop checks the microtask queue (Promises, `queueMicrotask`) first. Once empty, it processes the macrotask queue (`setTimeout`, I/O, rendering). This cycle repeats.

**JS3**
A closure is a function bundled with its lexical environment. Example: `function outer() { let x = 1; return function() { return x; }; }`. The classic bug is using `var i` in a loop; closures capture the variable reference, not the value at the time of creation. Fix: use `let` (block scope) or `var i = i` inside the loop.

**JS4**
Promises represent async completion. `async/await` is syntactic sugar for Promises. Errors in `async` functions are caught via `try/catch`; Promise errors use `.catch()`. `Promise.all` rejects on the first failure. `Promise.allSettled` waits for all tasks and returns an array of `{status, value}` regardless of errors.

**JS5**
Interfaces define shapes (properties/methods) for objects and are erased at runtime. Types define primitives or unions and are erased. Use Interfaces for object structures; Types for primitives or complex unions. Discriminated unions use a literal type (e.g., `type: 'a'`) to distinguish union members at runtime.

**JS6**
JavaScript uses prototypal inheritance. Objects inherit properties from their prototype. `Object.create(proto)` creates an object with `proto` as its prototype. ES6 classes are syntactic sugar; they compile to functions with a `prototype` property pointing to the constructor's prototype.

**JS7**
`this` refers to the execution context. Binding rules (priority): 1. Explicit binding (`call`, `apply`, `bind`), 2. Implicit binding (method call), 3. Default binding (global/undefined), 4. New binding (constructor). `bind()` returns a new function with `this` permanently bound. It can be re-bound.

**JS8**
`WeakRef` allows weak references to objects (garbage collectable). `FinalizationRegistry` runs a callback when an object is garbage collected. `WeakMap` keys must be objects because they are held weakly; if the object is GC'd, the entry is removed, preventing memory leaks.

**JS9**
V8 optimizes via JIT. Hidden classes group objects with identical property order. Inline caching caches type checks for speed. Deoptimization occurs if assumptions fail (e.g., adding a property to an object), forcing the engine to revert to the interpreter.

**JS10**
Tree-shaking removes unused code. It works with ES Modules because imports are static and analyzable. CommonJS uses dynamic `require`, so the bundler cannot determine which exports are used, preventing effective tree-shaking.

**JS11**
`null` is an empty object value; `undefined` is uninitialized. `==` performs type coercion; `===` does not. `??` returns the right operand if the left is `null` or `undefined`. `?.` safely accesses nested properties (returns `undefined` if path is broken).

**JS12**
`map` transforms elements; `filter` selects elements; `reduce` aggregates into a single value. `reduce` with an initial value starts accumulation from that value. `flatMap` maps and flattens the result one level deep.

**JS13**
Template literals use backticks and allow expressions `${expr}`. Tagged templates pass raw string segments and arguments to a function. Example: `sql` tag function that joins segments and escapes values to prevent SQL injection.

**JS14**
Destructuring extracts values. Object: `{ a: b }`. Array: `[ a, b ]`. Defaults: `{ a = 1 }`. Renaming: `{ a: c }`. Rest operator `...` collects remaining elements into an array.

**JS15**
`for...in` iterates enumerable keys (includes inherited). `for...of` iterates values of iterables. Avoid `for...in` on arrays as it iterates indices and inherited properties, not just array elements.

**JS16**
Generics allow type parameters (`<T>`). Constraints: `T extends U`. Conditional types: `T extends U ? X : Y`. `infer` extracts the type from a conditional type (e.g., `Extract`).

**JS17**
Modules organize code. CommonJS uses `require`/`module.exports`. ES Modules use `import`/`export`. Node.js supports both; `"type": "module"` in `package.json` enables ES Module syntax by default.

**JS18**
TypeScript is structural. Excess property checks apply to object literals, not function arguments. `extends` requires strict subset; `satisfies` allows extra properties. Variance determines if a generic type is covariant (`out`) or contravariant (`in`) based on usage.

**JS19**
`Proxy` wraps an object to intercept operations (get, set, apply). `Reflect` provides standard operations. Example: A proxy that logs property access or validates values before assignment.

**JS20**
`SharedArrayBuffer` allows shared memory between threads/workers. `Atomics` provides atomic operations (wait, notify, exchange). Workers communicate via `postMessage` or shared memory. Ordering guarantees ensure atomicity; `Atomics.wait` blocks until notified.

## Bash

**B1**
`$@` expands to each argument as a separate word. `$*` expands to all arguments as a single string. `"$@"` preserves word boundaries (safe). `"$*"` treats all args as one string (unsafe for filenames with spaces).

**B2**
`set -e`: exit on error. `set -u`: exit on undefined variable. `set -o pipefail`: exit if any command in a pipeline fails.

**B3**
`$(command)` performs command substitution (output). `command` executes the command. `$((expr))` is arithmetic expansion. `expr` is a legacy command for string/regex operations (deprecated).

**B4**
Process substitution `<(command)` creates a file descriptor that outputs command output. Use it to compare streams or iterate. Example: `diff <(sort file1) <(sort file2)`.

**B5**
`for f in $(ls)` is dangerous due to word splitting on spaces. Safe iteration: `for f in *` or `while IFS= read -r -d '' f`.

**B6**
`<<EOF` is a here document (reads until EOF). `<<<` is a here string (passes string as argument). `<<-EOF` strips leading whitespace from lines.

**B7**
`cmd > file 2>&1`: stdout to file, stderr to stdout (file). `cmd 2>&1 > file`: stderr to stdout (pipe), then stdout to file (stdout lost). `cmd &> file`: both stdout and stderr to file.

**B8**
Function: `lock() { mkdir -p "$lockfile" || { rm -rf "$lockfile"; return 1; }; trap "rm -rf $lockfile" EXIT; }`. `mkdir` is atomic, preventing race conditions better than file creation.

**B9**
Single quotes: literal (no expansion). Double quotes: variable expansion, no glob. No quotes: variable expansion + glob. Example: `echo 'a$b'` vs `echo "a$b"`.

**B10**
`-f` (file), `-d` (directory), `-r` (readable). `[ ]` is a shell builtin (word splitting). `[[ ]]` is bash builtin (no word splitting, supports regex).

**B11**
`$?`: exit code of last command. `$$`: current shell PID. `$!`: PID of last background process. `$#`: number of arguments passed to script/function.

**B12**
`function foo {}` and `foo() {}` are equivalent. Return values via `echo` or the last line of output.

**B13**
`PATH` defines command search order. Builtins are shell commands (e.g., `cd`). External commands are binaries (e.g., `ls`). Check with `type` or `which`.

**B14**
`trap` sets signal handlers. `EXIT` runs on exit. `ERR` runs on error. `INT`/`TERM` for interrupts. Execution order: `EXIT` runs last.

**B15**
`xargs` processes arguments. `xargs -0` uses null delimiters (safe for newlines). `xargs -P` runs parallel processes.

**B16**
Arrays: `declare -a arr`. Append: `arr+=("val")`. Length: `${#arr[@]}`. Associative: `declare -A`. Syntax differs; associative uses keys.

**B17**
Subshell `( ... )` creates a new shell; changes are lost. Group `{ ... }` runs in current shell; changes persist. Piping into `while` creates a subshell, losing variable changes.

**B18**
Signals: `SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (hangup), `SIGKILL` (force). Graceful shutdown: `trap "cleanup" TERM INT`.

**B19**
Script: `split file | xargs -P 4 process | cat results`. Parallelism speeds up processing but increases memory usage. Handle errors with `set -o pipefail` and check exit codes.

**B20**
`exec` replaces the current shell. `exec 3>file` redirects FD 3. Coprocess: `coproc name; read -p "Prompt" name`. Used for interactive background processes.

## PowerShell

**PS1**
`Write-Output` sends objects to the pipeline. `Write-Host` writes to the console and breaks the pipeline. Distinction matters for piping data to other commands.

**PS2**
Pipeline passes objects. `ForEach-Object` processes pipeline items. `foreach` is a statement for scalar loops. Use `ForEach-Object` for pipeline processing.

**PS3**
`[PSCustomObject]` creates an object with named properties. `[hashtable]` is key-value pairs. Convert: `[PSCustomObject]@{Key=Value}`.

**PS4**
Terminating errors stop the script. Non-terminating errors continue. `-ErrorAction` controls behavior. `try/catch` handles terminating errors.

**PS5**
Splatting `@params` passes a hashtable as named arguments. Passing a hashtable as a single argument treats it as a single object.

**PS6**
`Invoke-Command -ComputerName` runs a command remotely. `Enter-PSSession` opens an interactive session. Uses WinRM (default) or SSH.

**PS7**
Functions returning scalars (strings) are treated as single items in the pipeline. Returning arrays is correct for pipeline compatibility. If returning 0 items, the pipeline is empty.

**PS8**
`[scriptblock]` is `{...}`. Pass to remote via `-ScriptBlock`. Double-hop: Kerberos authentication fails when proxying. Solve with CredSSP or `-ArgumentList`.

**PS9**
`@()` creates an array. `[array]` is a type. Force single result: `@($result)`. Indexing `$null` throws; empty array returns nothing.

**PS10**
`-eq` (equal), `-like` (wildcard), `-contains` (array), `-in` (array). Case-sensitive variants: `-ceq`, `-clike`. `-contains` checks if item exists in array; `-in` checks if value is in array.

**PS11**
Modules are collections of functions. `.psm1` (script), `.psd1` (manifest), `.ps1` (script module). `Import-Module` loads them.

**PS12**
Interpolation: `"${var}"`. Single quotes `'...'` no interpolation. Here-string: `@"..."@` for multi-line strings.

**PS13**
`Get-Member` explores object properties/methods. Properties are data; Methods are actions. `Select-Object` selects properties; `Where-Object` filters.

**PS14**
PowerShell classes (v5) are dynamic. Unlike C#, they lack strict inheritance/interface support. Use classes for stateful objects; functions for logic.

**PS15**
`[CmdletBinding()]` enables pipeline support. `Process` handles items; `Begin`/`End` handle setup/teardown. `ValueFromPipeline` allows input.

**PS16**
Providers abstract data access. `Get-ChildItem` works on FileSystem, Registry, etc. Registry access: `Get-ItemProperty HKCU:\Software`.

**PS17**
Runspaces are threads. `[runspacepool]` manages them. `ForEach-Object -Parallel` (v7+) is easier than manual runspace management.

**PS18**
`PSScriptAnalyzer` enforces standards. Rules have severity levels. Suppress with `# #`. Integrate with CI/CD via `Invoke-ScriptAnalyzer`.

**PS19**
`$using:` passes variables to remote/background jobs. `-ArgumentList` passes scriptblock arguments. Serialization limits (CLIXML depth) affect complex objects.

**PS20**
DSC manages configuration state. Configurations define resources; LCM applies them. Modern IaC (Ansible/Terraform) often replaces DSC for cloud infrastructure.
