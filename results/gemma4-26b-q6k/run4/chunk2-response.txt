## Kubernetes

**K1** — A **Deployment** manages stateless applications (pods can be replaced/recreated in any order). A **StatefulSet** manages stateful applications, providing stable network identifiers (pod-0, pod-1) and stable, persistent storage that follows the pod even after rescheduling.

**K2** — A **ClusterIP** service creates a virtual IP. It uses `kube-proxy` (via iptables or IPVS) on each node to intercept traffic sent to the ClusterIP and perform DNAT (Destination Network Address Translation) to redirect it to the IP of a healthy pod selected by the service's label selector.

**K3** — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a user's request for storage. **StorageClass** is a template that allows for dynamic provisioning of PVs. Relation: A user creates a **PVC** referencing a **StorageClass**, which triggers the creation of a **PV**.

**K4** — 1. `kubectl logs <pod>` (check application errors/stack traces). 2. `kubectl describe pod <pod>` (check Events for exit codes or OOMKilled). 3. Check environment variables/ConfigMaps (missing required config). 4. Check liveness/readiness probe settings (probes failing too early).

**K5** — **CoreDNS** provides service discovery by resolving Kubernetes service names to ClusterIPs. If CoreDNS pods are down, internal service-to-service communication via DNS names will fail, though direct IP communication will still work.

**K6** — The scheduler uses two phases: **Filtering** (Predicates) removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, port conflicts). **Scoring** (Priorities) ranks remaining nodes. Factors: 1. **Resource Fit** (least requested vs most requested), 2. **Image Locality** (is the image already on the node?), 3. **Affinity/Anti-affinity** rules.

**K7** — **Scheduling:** No. The node has 3.5GB requested, and the pod requests 256Mi (~0.25GB). 3.5 + 0.25 = 3.75GB, which exceeds the 4GB capacity (assuming some overhead). **Runtime:** If it uses 600Mi, it will be **OOMKilled** because it exceeded its 512Mi limit.

**K8** — 1. External LB receives request $\rightarrow$ 2. Forwards to Ingress Controller (Pod) $\rightarrow$ 3. Ingress Controller matches host/path $\rightarrow$ 4. Controller identifies the **Service** $\rightarrow$ 5. Controller uses **Endpoints** (IPs of pods) $\rightarrow$ 6. Traffic routed via `kube-proxy` (iptables/IPVS) directly to the Pod IP.

**K9** — A **NetworkPolicy** defines rules for allowed traffic. By default, if no policy exists, all pods in a namespace can talk to all other pods (Allow All). Once a policy is applied to a pod, it enters "isolation mode," and only traffic explicitly permitted by the policy is allowed.

**K10** — **RollingUpdate** replaces pods one by one to ensure zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when the application cannot handle two versions running simultaneously (e.g., database schema incompatibility).

**K11** — A **Namespace** is a virtual cluster within a physical cluster for resource isolation. Default namespaces: `default`, `kube-system`, `kube-public`, and `kube-node-ca` (in newer versions).

**K12** — Used to inspect the state of a pod. Unlike `get`, it shows: 1. **Events** (recent lifecycle changes), 2. **Container Status/Exit Codes**, 3. **Detailed Resource Requests/Limits**.

**K13** — A **ConfigMap** stores non-confidential configuration data. Consumption methods: 1. As **Environment Variables**, 2. As **Files in a Volume** (mounted).

**K14** — **ClusterIP:** Internal only. **NodePort:** Exposes service on a static port on every Node IP. **LoadBalancer:** Provisions an external LB (e.g., AWS ELB) that routes to the service.

**K15** — A **DaemonSet** ensures a copy of a pod runs on *every* node in the cluster. Use it for background services like logging agents (Fluentd) or monitoring agents (Prometheus Node Exporter).

**K16** — **Taints** are applied to **Nodes** to repel pods (e.g., "don't run here unless you have permission"). **Tolerations** are applied to **Pods** to allow them to stay on tainted nodes. **Node Affinity** is applied to **Pods** to attract them to specific nodes. *Use case:* Taint a GPU node for specialized workloads; use Affinity to ensure a web app runs on SSD-backed nodes.

**K17** — An **Operator** is a custom controller that uses Custom Resource Definitions (CRDs) to manage complex, stateful applications. Unlike standard controllers (which manage simple primitives like Pods), Operators encode domain-specific operational knowledge (e.g., how to back up a database).

**K18** — **etcd** uses the **Raft** consensus algorithm (Strong Consistency). If quorum is lost, the cluster becomes read-only/unresponsive. If 2/3 nodes are lost, you cannot achieve quorum. Recovery requires restoring from a backup or re-initializing a new cluster and manually injecting the data.

**K19** — **RBAC** uses Roles (namespace-scoped) and ClusterRoles (cluster-wide). **RoleBindings** attach Roles to Users/Groups. **ClusterRoleBindings** attach ClusterRoles.
*Manifest:*
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { name: pod-reader, namespace: target-ns }
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { name: read-pods, namespace: target-ns }
subjects: [{ kind: User, name: "developer", apiGroup: rbac.authorization.k8s.io }]
roleRef: { kind: Role, name: pod-reader, apiGroup: rbac.authorization.k8s.io }
```

**K20** — When `ndots` is high (default 5), the resolver tries to append local search domains for every external request (e.g., `google.com` $\rightarrow$ `google.com.default.svc.cluster.local`). This causes multiple failed lookups. **Fix:** Use `dnsConfig` in the pod spec to set `ndots: 1`.

## Development

**D1** — **Merge** combines histories by creating a new commit. **Rebase** rewrites history by moving your changes onto the tip of the target branch. **Avoid rebasing** on public/shared branches as it rewrites history and breaks others' work.

**D2** — **TCP** is connection-oriented/reliable (HTTP, SSH). **UDP** is connectionless/fast (DNS, VoIP).

**D3** — A **Race Condition** occurs when the outcome depends on the timing of uncontrollable events. *Example:* Two threads incrementing a shared integer `x++` simultaneously; both read `5`, both increment to `6`, and the final value is `6` instead of `7`.

**D4** — **Symmetric:** Same key for encryption/decryption (AES). **Asymmetric:** Public/Private key pair (RSA). In **TLS**, asymmetric encryption is used for the initial handshake to securely exchange a symmetric key, which is then used for the bulk data transfer via symmetric encryption.

**D5** — A **Layer** is a read-only filesystem change. **Caching:** Docker caches layers; placing frequently changing instructions (like `COPY . .`) at the bottom of the Dockerfile optimizes build speed by reusing cached layers above them.

**D6** — 1. Check Application Logs (errors). 2. Check Resource usage (CPU/RAM exhaustion). 3. Check Downstream dependencies (DB/External APIs). 4. Check Load Balancer/Ingress health.

**D7** — **CAP:** Consistency, Availability, Partition Tolerance. You can only have two. **CP (Consistency/Partition):** Zookeeper (prioritizes data integrity). **AP (Availability/Partition):** Cassandra (prioritizes uptime/eventual consistency).

**D8** — **Horizontal:** Adding more instances (nodes/pods). **Vertical:** Adding more resources (CPU/RAM) to existing instances. **Patterns:** Statelessness (allows horizontal scaling) and Load Balancing.

**D9** — An **Environment Variable** is a dynamic value used by processes. To persist on Linux: Add `export VAR=value` to your `~/.bashrc` or `~/.profile`.

**D10** — **JSON** is a data format; **YAML** is a human-readable data serialization language. **JSON Advantage:** Native to JavaScript/Web. **YAML Advantage:** Much easier for humans to read/write (config).

**D11** — **REST API:** Architectural style for networked applications. **GET:** Retrieve data. **POST:** Create data. **PUT:** Replace/Update data. **DELETE:** Remove data.

**D12** — **Version Pinning** is specifying exact versions of dependencies (e.g., `lib-x:1.2.3`). It ensures that a build today results in the exact same binary as a build next year, preventing "breaking changes" from silent updates.

**D13** — **Compiled:** Converted to machine code before execution (C++, Go). **Interpreted:** Executed line-by-line by a runtime (Python, Ruby).

**D14** — **Reverse Proxy:** Sits in front of servers to protect/load balance them (Nginx, HAProxy). **Forward Proxy:** Sits in front of clients to hide identity/filter web (Squid).

**D15** — **Deadlock:** A state where processes are stuck waiting for each other. **Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual Consistency:** Data will be consistent across all nodes *eventually*. **Cassandra** uses tunable consistency: `ANY`, `ONE`, `QUORUM`, `ALL`. Higher levels increase consistency but decrease availability/latency.

**D17** — **mTLS:** Both client and server present certificates. **Handshake:** 1. Client sends cert $\rightarrow$ 2. Server validates client $\rightarrow$ 3. Server sends cert $\rightarrow$ 4. Client validates server $\rightarrow$ 5. Session keys generated. Used in **Service Meshes** (Istio/Linkerd).

**D18** — **Hash Table:** Maps keys to indices via a hash function. **Collisions:** 1. **Chaining** (linked list at index), 2. **Open Addressing** (find next empty slot). **Complexity:** Avg: $O(1)$ for all. Worst: $O(n)$ (all keys hash to same index).

**D19** — **Circuit Breaker:** Prevents a service from repeatedly trying an operation that is likely to fail. **States:** 1. **Closed** (normal), 2. **Open** (failing, stop requests), 3. **Half-Open** (testing if service recovered). It works with **Exponential Backoff** to prevent overwhelming a recovering system.

**D20** — **Optimistic:** Assume no conflict; check version at commit (e.g., `WHERE version=1`). Good for low-contention. **Pessimistic:** Lock the row immediately (e.g., `SELECT ... FOR UPDATE`). Good for high-contention where conflicts are frequent.
