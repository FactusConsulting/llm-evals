JS1 — `var` is function-scoped and can be redeclared; `let` and `const` are block-scoped. `const` prevents reassignment of the identifier. Hoisting is the behavior where variable and function declarations are moved to the top of their scope during compilation. `var` is hoisted and initialized as `undefined`; `let`/`const` are hoisted but remain in a "Temporal Dead Zone" until initialized.

JS2 — The event loop manages asynchronous execution. The **Call Stack** executes synchronous code. When an async operation completes, its callback enters a queue. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority; the loop clears the entire microtask queue before moving to the **Macrotask Queue** (setTimeout, setInterval, I/O).

JS3 — A closure is a function that "remembers" its lexical scope even when executed outside that scope. *Example:* A function returning another function that increments a private counter. *Bug:* Using `var` in a `for` loop with an async callback (all callbacks share the same final value). *Fix:* Use `let` in the loop header to create a new binding for each iteration.

JS4 — `Promise` represents an eventual value. `async/await` is syntactic sugar for Promises. Error handling: `try/catch` with `async/await`; `.catch()` with Promises. `Promise.all` rejects immediately if *any* promise fails. `Promise.allSettled` waits for all to finish and returns an array of objects describing the outcome (fulfilled/rejected) of each.

JS5 — `interface` is primarily for defining object shapes and supports declaration merging (adding properties later). `type` is more flexible, allowing unions, primitives, and tuples. Use `interface` for public APIs/objects; use `type` for complex logic/unions. **Discriminated Unions** use a common literal property (e.g., `kind: 'circle' | 'square'`) to allow TypeScript to narrow types in a `switch` statement.

JS6 — Objects inherit properties from a prototype object via the prototype chain. `Object.create(proto)` creates a new object with the specified prototype. ES6 `class` is "syntactic sugar" over prototypal inheritance; it uses the same underlying prototype mechanism but provides a cleaner syntax for constructors and methods.

JS7 — `this` refers to the execution context. **Binding Rules:** 1. `new` (constructor), 2. Explicit (`call`/`apply`/`bind`), 3. Implicit (object method), 4. Default (global/undefined in strict mode). `bind()` returns a new function with a fixed `this`. You cannot re-bind a function once it has been bound via `bind()`.

JS8 — `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` triggers a callback when an object is GC'd. Use them for caches or metadata. `WeakMap` keys must be objects because primitive keys cannot be tracked for GC, and object keys allow the entry to be removed automatically when the key object is no longer reachable.

JS9 — V8 uses **Hidden Classes** (shapes) to optimize property access. **Inline Caching** stores the offset of properties to avoid repeated lookups. **Deoptimization** occurs when code becomes "unstable" (e.g., changing the shape of an object passed to a function). *Patterns:* Adding/deleting properties dynamically, or passing different object shapes to the same function.

JS10 — Tree-shaking is dead-code elimination. It works with **ES Modules** because `import/export` are static (analyzable at compile time). **CommonJS** (`require`) is dynamic; imports can be conditional or computed at runtime, making it impossible for tools to guarantee a module isn't needed, thus preventing effective tree-shaking.

JS11 — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion; `===` checks both value and type. **Nullish coalescing (`??`)** returns the right side only if the left is `null` or `undefined`. **Optional chaining (`?.`)** short-circuits and returns `undefined` if the reference is nullish.

JS12 — `map()` creates a new array by transforming every element. `filter()` creates a new array with elements that pass a test. `reduce()` executes a reducer function on each element to result in a single value. If an **initial value** is provided, `reduce` starts there; otherwise, it uses the first element as the accumulator. `flatMap()` maps each element and then flattens the result by one level, useful for handling nested arrays or expanding elements.

JS13 — Template literals use backticks (`` ` ``). **Tagged templates** allow you to parse template literals with a function. *Example:* `const sql = sqlTag`SELECT * FROM users WHERE id = ${id}``. The function receives the string parts and the interpolated values as arguments, allowing for sanitization or escaping.

JS14 — Destructuring extracts values from arrays/objects into variables. `const {a, b: c} = obj` renames `b` to `c`. `const [x = 10] = arr` sets a default. The **rest operator** (`...`) collects remaining elements into a new array/object: `const {a, ...rest} = obj`.

JS15 — `for...in` iterates over enumerable **keys** (property names) of an object. `for...of` iterates over **values** of an iterable (like an array). Avoid `for...in` on arrays because it iterates over all enumerable properties (including inherited ones) and does not guarantee order.

JS16 — **Generics** allow functions/classes to work with multiple types while maintaining type safety. **Constraints** (`<T extends string>`) limit what `T` can be. **Conditional Types** (`T extends U ? X : Y`) act like ternary operators for types. **`infer`** allows you to "extract" a type from another (e.g., getting the return type of a function). *Example:* `type Unpack<T> = T extends Array<infer U> ? U : T;`.

JS17 — **CommonJS** (Node.js default) uses `require()` (synchronous, runtime). **ES Modules** (ESM) use `import/export` (static, asynchronous loading). Node.js handles both via file extensions (`.cjs`/`.mjs`) or the `"type": "module"` field in `package.json`. `"type": "module"` tells Node to treat all `.js` files in that package as ESM.

JS18 — TS is **structural** (if it looks like a duck, it's a duck). **Excess property checks** occur when assigning an object literal directly to a type; they prevent adding extra properties not in the interface. `satisfies` checks if an object matches a type without widening the type (preserving specific literal values). **Variance** (`in`/`out`) defines how subtyping relates to complex types (e.g., a function accepting a `Dog` can accept a function that returns an `Animal`).

JS19 — `Proxy` wraps an object to intercept operations. `Reflect` provides methods to perform the default behavior of those operations. *Example:* A Proxy with a `get` trap can log every time a property is accessed, and `Reflect.get(target, prop)` ensures the original value is retrieved correctly.

JS20 — `SharedArrayBuffer` allows multiple threads (Web Workers) to access the same raw memory. `Atomics` provides static methods to perform thread-safe operations (like `add`, `load`, `store) to prevent race conditions. `Atomics.wait` pauses a thread until a value changes, and `Atomics.notify` wakes it up.

B1 — `$@` represents all positional parameters as separate words. `$*` represents all parameters as a single string. `"$@"` preserves the exact spacing and quoting of each argument (best for loops), while `"$*"` joins them into one string.

B2 — `set -e`: Exit immediately if a command fails. `-u`: Treat unset variables as an error. `-o pipefail`: The pipeline's return code is the value of the last command to exit with a non-zero status.

B3 — `$(command)` is command substitution (executes command and returns output). `` `command` `` is the older, deprecated version. `$((expression))` is for arithmetic evaluation. `expr` is an external utility for math (slower and less powerful than `$(( ))`).

B4 — Process substitution `<(command)` treats the output of a command as a temporary file. *Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two `ls` commands without creating physical files.

B5 — Use `find . -print0 | xargs -0 ...` or `for f in */; do ... done`. `for f in $(ls)` is dangerous because it splits filenames on whitespace, breaking names like `"My File.txt"`.

B6 — `<<EOF` (here-doc) feeds multiple lines into a command. `<<<` (here-string) feeds a single string. `<<-EOF` strips leading **tabs** (not spaces) from the document, allowing for cleaner indentation in scripts.

B7 — `cmd > file 2>&1`: Redirects stdout to `file`, then redirects stderr to the same place as stdout. `cmd 2>&1 > file`: Redirects stderr to stdout (the terminal), then redirects stdout to `file`. `cmd &> file`: Shorthand to redirect both stdout and stderr to `file`.

B8 — Use `mkdir lockdir` because `mkdir` is an atomic operation at the OS level; if two processes try to `mkdir` the same name, only one succeeds.
```bash
lock() {
  if mkdir "$1" 2>/dev/null; then
    trap 'rmdir "$1"; exit' INT TERM EXIT
    return 0
  else
    return 1
  fi
}
```

B9 — `'...'` (single): Literal string, no expansion. `"..."` (double): Allows variable expansion (`$VAR`) and command substitution. `no quotes`: Allows word splitting and globbing (dangerous). *Example:* `echo '$USER'` prints `$USER`; `echo "$USER"` prints `root`.

B10 — `-e` (exists), `-d` (directory), `-r` (readable). `[ ]` is the standard `test` command (basic). `[[ ]]` is a Bash keyword that is more powerful, supports regex (`=~`), and doesn't require quoting variables to prevent errors.

B11 — `$?`: Exit status of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: Number of positional parameters.

B12 — `foo() { ... }` is the standard POSIX way. `function foo { ... }` is a Bashism. Functions return an exit status (0-255) via `return`. To "return" data, use `echo` and capture it with `$(...)`.

B13 — `PATH` is a colon-separated list of directories searched for executables. Bash searches `PATH` sequentially. A **builtin** (e.g., `cd`) is part of the shell; an **external** (e.g., `ls`) is a file in `PATH`. Use `type -a command` to check.

B14 — `trap 'command' SIGNAL` executes a command when a signal is received. `trap 'cleanup' EXIT` runs on script end. If multiple signals arrive, they are handled sequentially.

B15 — `xargs` converts stdin to arguments for a command. `find -print0 | xargs -0` handles filenames with spaces/newlines by using the null character as a delimiter. `xargs -P N` runs N processes in parallel.

B16 — **Arrays:** `arr=(a b c)`. **Append:** `arr+=(d)`. **Iterate:** `for i in "${arr[@]}"; do`. **Length:** `${#arr[@]}`. **Associative:** `declare -A map`. `map[key]=val`.

B17 — `(...)` (subshell) creates a new process; variables changed inside do not affect the parent. `{ ...; }` (group command) runs in the current shell; variables persist. Piping `cmd | while read...` runs the loop in a subshell, so variable changes inside the loop are lost to the parent.

B18 — `SIGINT` (Ctrl+C), `SIGTERM` (polite kill), `SIGHUP` (terminal closed), `SIGKILL` (immediate, cannot be trapped). For graceful shutdown: `trap 'kill $(jobs -p)' SIGTERM` to kill background processes.

B19 — Use `split -l 1000 logfile` to chunk the file, then `ls chunks* | xargs -P 4 -I {} bash -c 'process_func {}'`. *Trade-off:* Parallelism speeds up processing but increases CPU/IO contention. Error propagation requires checking exit codes of each `xargs` task.

B20 — `exec` replaces the current shell process with the new command. `exec 3>file` opens FD 3 for writing to `file`. `exec 3>&-` closes FD 3. A **coprocess** (`coproc`) allows a shell to communicate with a background process via pipes.

PS1 — `Write-Output` sends objects to the pipeline (useful for downstream processing). `Write-Host` writes directly to the console (not part of the pipeline).

PS2 — The **pipeline** passes objects from one command to the next. `ForEach-Object` is a cmdlet used in a pipeline (efficient for large streams). `foreach` is a language keyword (faster for small, pre-loaded collections).

PS3 — `[PSCustomObject]` is an object with properties (best for pipelines/output). `[hashtable]` is a key-value collection (best for lookups). Convert: `[PSCustomObject]@{key='val'}` or `[hashtable]@{key='val'}`.

PS4 — **Terminating** errors stop execution; **non-terminating** errors continue. `try/catch` only catches terminating errors. Use `-ErrorAction Stop` to turn non-terminating errors into terminating ones. `$ErrorActionPreference = 'Stop'` sets the global behavior.

PS5 — **Splatting** passes a hashtable as arguments to a command: `$p = @{Name='Test'; Force=$true}; Get-Item @p`. It is cleaner than long command lines and differs from passing a single hashtable parameter because it expands the keys into individual parameter names.

PS6 — `Invoke-Command -ComputerName` runs a script on remote machines (one-to-many). `Enter-PSSession` starts an interactive session (one-to-one). Both use **WS-Man** (WinRM) or **SSH**.

PS7 — In the example, `$result` is an array. When returning from a function, PowerShell "unrolls" arrays. If the function returns an array, `$x` becomes the array. If it returns 0 items, `$x` is `$null`. The correct pattern is to cast the return: `[array]$x = Get-Items`.

PS8 — A `[scriptblock]` is a block of code. To pass to a remote session, use `Invoke-Command -ScriptBlock { ... }`. The **double-hop** problem occurs when a remote session tries to access a third resource (like a file share) using your credentials. Solve with **CredSSP** or **Kerberos Delegation**.

PS9 — `@()` creates an array; `[array]` is a type. To force a single result into an array, use `@($result)`. Indexing `$null` returns `$null`; indexing an empty array returns `$null`.

PS10 — `-eq/-ne` (equality), `-like` (wildcard), `-match` (regex), `-contains` (checks if collection contains value), `-in` (checks if value is in collection). `-ceq` etc. are case-sensitive.

PS11 — **Script Module** (`.psm1`) contains functions. **Manifest** (`.psd1`) contains metadata. **Binary Module** is a compiled DLL. `Import-Module` loads the module into the current session.

PS12 — `"Hello $name"` is interpolated; `'Hello $name'` is literal. Use `$()` for expressions: `"Date: $(Get-Date)"`. A **here-string** (`@"..."@`) preserves multi-line formatting and whitespace.

PS13 — `Get-Member` shows the type and members of an object. **Properties** are data, **Methods** are actions, **NoteProperties** are custom properties added to an object. `Select-Object` picks specific properties; `Where-Object` filters objects based on criteria.

PS14 — **Classes** are strongly typed and support inheritance/interfaces like C#. They are more rigid than functions. Use a class for complex data structures/logic; use a function for simple tasks/actions.

PS15 — `[CmdletBinding()]` makes a function behave like a professional cmdlet (adds `-Verbose`, `-ErrorAction`, etc.). `SupportsShouldProcess` enables `-WhatIf`. `ValueFromPipeline` allows receiving input from the pipeline. `Begin`/`Process`/`End` blocks allow handling stream data efficiently.

PS16 — **Providers** allow PowerShell to treat different data stores as a file system. `Get-ChildItem Registry::HKEY_LOCAL_MACHINE` works just like `Get-ChildItem C:\`.

PS17 — A **runspace** is a single thread of execution. A **runspacepool** manages multiple runspaces for reuse. `ForEach-Object -Parallel` (v7+) is a high-level wrapper that manages runspaces automatically for parallel processing.

PS18 — **PSScriptAnalyzer** is a static code analysis tool. It uses **rules** to check for best practices. Rules have **severity** (Error, Warning, Info). You can suppress rules using `# PSScriptAnalyzer Avoids: RuleName` and integrate it into CI/CD via `Invoke-ScriptAnalyzer`.

PS19 — `$using:var` is used to pass a local variable into a remote/parallel scope. `$args` is for positional parameters. **Serialization limits** occur when objects are sent over the wire; complex objects are converted to XML (CLIXML), and deep/circular references may be lost or truncated.

PS11 — **Script Module** (`.psm1`) contains functions. **Manifest** (`.psd1`) contains metadata. **Binary Module** is a compiled DLL. `Import-Module` loads the module into the current session.

PS12 — `"Hello $name"` is interpolated; `'Hello $name'` is literal. Use `$()` for expressions: `"Date: $(Get-Date)"`. A **here-string** (`@"..."@`) preserves multi-line formatting and whitespace.

PS13 — `Get-Member` shows the type and members of an object. **Properties** are data, **Methods** are actions, **NoteProperties** are custom properties added to an object. `Select-Object` picks specific properties; `Where-Object` filters objects based on criteria.

PS14 — **Classes** are strongly typed and support inheritance/interfaces like C#. They are more rigid than functions. Use a class for complex data structures/logic; use a function for simple tasks/actions.

PS15 — `[CmdletBinding()]` makes a function behave like a professional cmdlet (adds `-Verbose`, `-ErrorAction`, etc.). `SupportsShouldProcess` enables `-WhatIf`. `ValueFromPipeline` allows receiving input from the pipeline. `Begin`/`Process`/`End` blocks allow handling stream data efficiently.

PS16 — **Providers** allow PowerShell to treat different data stores as a file system. `Get-ChildItem Registry::HKEY_LOCAL_MACHINE` works just like `Get-ChildItem C:\`.

PS17 — A **runspace** is a single thread of execution. A **runspacepool** manages multiple runspaces for reuse. `ForEach-Object -Parallel` (v7+) is a high-level wrapper that manages runspaces automatically for parallel processing.

PS18 — **PSScriptAnalyzer** is a static code analysis tool. It uses **rules** to check for best practices. Rules have **severity** (Error, Warning, Info). You can suppress rules using `# PSScriptAnalyzer Avoids: RuleName` and integrate it into CI/CD via `Invoke-ScriptAnalyzer`.

PS19 — `$using:var` is used to pass a local variable into a remote/parallel scope. `$args` is for positional parameters. **Serialization limits** occur when objects are sent over the wire; complex objects are converted to XML (CLIXML), and deep/circular references may be lost or truncated.

PS20 — **Desired State Configuration (DSC)** uses **configurations** (the desired state), **resources** (the logic to apply state), and the **Local Configuration Manager (LCM)** (the engine on the node). In modern IaC, DSC is often replaced by tools like Terraform or Ansible.
