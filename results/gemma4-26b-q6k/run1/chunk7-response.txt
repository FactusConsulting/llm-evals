JS1 — `var` is function-scoped and can be redeclared; `let` and `const` are block-scoped. `const` prevents reassignment of the identifier. **Hoisting** is the behavior where variable and function declarations are moved to the top of their scope during compilation. `var` is hoisted and initialized as `undefined`, while `let`/`const` are hoisted but remain in a "Temporal Dead Zone" until the line of declaration is reached.

JS2 — The **Event Loop** manages asynchronous execution. The **Call Stack** executes synchronous code. When an async operation completes, its callback enters a queue. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority than the **Macrotask Queue** (setTimeout, setInterval, I/O). The loop checks the stack; if empty, it exhausts the entire Microtask queue before processing a single task from the Macrotask queue.

JS3 — A **closure** is a function that "remembers" its lexical scope even when executed outside that scope. *Example:* `function outer() { let count = 0; return () => ++count; }`. The **classic loop bug**: `for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i), 1); }` prints `3, 3, 3` because `var` is function-scoped. **Fix**: Use `let` in the loop header to create a new binding for each iteration.

JS4 — **Promise** is an object representing the eventual completion of an async operation. **async/await** is syntactic sugar over Promises. Error handling: `async/await` uses `try/catch` blocks; Promises use `.catch()`. `Promise.all` rejects immediately if *any* promise fails. `Promise.allSettled` waits for all promises to either fulfill or reject, returning an array of objects describing the outcome of each.

JS5 — **Interface** is primarily for defining object shapes and supports declaration merging. **Type** is more flexible, allowing unions, primitives, and intersections. Use `interface` for public APIs/object structures; use `type` for complex logic/unions. **Discriminated Unions** are types that share a common literal property (the "discriminant") used to narrow the type in a conditional block.

JS6 — **Prototypal inheritance** means objects inherit properties from a prototype object via the prototype chain. `Object.create(proto)` creates a new object with the specified `proto` as its prototype. **ES6 Classes** are "syntactic sugar" over prototypes; they don't introduce a new inheritance model but provide a cleaner syntax for constructor functions and prototype methods.

JS7 — `this` refers to the execution context. **Binding rules**: 1. `new` (constructor), 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (object method call), 4. Default (global/undefined). `bind()` returns a **new function** with a fixed `this`. You **cannot** re-bind a function that was created via `bind()`.

JS8 — `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` triggers a callback when an object is GC'd. Use them for caches or metadata. **WeakMap keys must be objects** because primitives cannot be tracked by the GC in the same way, and the "weakness" relies on the ability to detect when the object reference is gone.

JS9 — **V8 Optimizations**: **Hidden Classes** (Shapes) track object properties to avoid expensive hash lookups. **Inline Caching** (IC) remembers the offset of properties from previous lookups. **Deoptimization** occurs when code assumptions fail (e.g., a function receiving a different type than usual). **Patterns causing deoptimization**: Changing object shapes (adding/deleting properties) or passing inconsistent types to polymorphic functions.

JS10 — **Tree-shaking** is dead-code elimination. It works with **ES Modules** because `import/export` are static (analyzable at build time). **CommonJS** (`require`) is dynamic; modules can be loaded conditionally at runtime, making it impossible for bundlers to determine with certainty which exports are unused.

JS11 — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion (e.g., `null == undefined` is `true`); `===` checks both value and type (`null === undefined` is `false`). **Nullish coalescing (`??`)** returns the right side only if the left is `null` or `undefined`. **Optional chaining (`?.`)** short-circuits and returns `undefined` if the reference is nullish.

JS12 — `map()` creates a new array by transforming every element. `filter()` creates a new array with elements that pass a test. `reduce()` executes a reducer function on each element to result in a single value. If an **initial value** is provided, the accumulator starts with it; otherwise, the first element is used as the accumulator. `flatMap()` maps each element and then flattens the result by one level; useful for handling nested arrays returned by a map.

JS13 — **Template literals** use backticks (`` ` ``). **Tagged templates** allow you to pass the string parts and expressions to a function. *Example:* `const sql = (strings, ...vals) => ...;` This allows for sanitizing inputs to prevent SQL injection or escaping HTML.

JS14 — **Destructuring** extracts values from arrays/objects into variables. `const {a, b: renamed = 10} = obj;` (Object). `const [first, ...rest] = arr;` (Array). The **rest operator** (`...`) collects remaining elements into a new array/object.

JS15 — `for...in` iterates over **enumerable property keys** (strings). `for...of` iterates over **iterable values**. Avoid `for...in` on arrays because it iterates over indices as strings and may include inherited properties from the prototype chain.

JS16 — **Generics** allow components to work with multiple types. **Constraints** (`T extends U`) limit the types allowed. **Conditional types** (`T extends U ? X : Y`) act like ternary operators for types. **`infer`** allows you to extract a type from within another type. *Example:* `type GetReturn<T> = T extends (...args: any[]) => infer R ? R : any;`.

JS17 — **CommonJS** (Node.js default) uses `require()` (synchronous). **ES Modules** (ESM) use `import/export` (asynchronous/static). Node.js handles both, but ESM is the standard. The `"type": "module"` in `package.json` tells Node.js to treat `.js` files as ES Modules rather than CommonJS.

JS18 — TS is **structurally typed** (if it looks like a duck, it's a duck). **Excess property checks** apply only to object literals assigned directly to a type. `extends` is for type relationships; `satisfies` ensures an object matches a type without widening the inferred type. **Variance**: `in` (contravariance) relates to function arguments; `out` (covariance) relates to return types.

JS19 — **Proxy** wraps an object to intercept operations. **Reflect** provides methods for the same operations (e.g., `Reflect.get`). *Example:* A Proxy using the `set` trap can validate that a property is a number before assigning it, ensuring data integrity.

JS20 — **SharedArrayBuffer** allows multiple threads (Web Workers) to access the same raw memory. **Atomics** provides static methods to perform thread-safe operations (like `add` or `load`) to prevent race conditions. `Atomics.wait` pauses a thread until `Atomics.notify` is called on a specific index, enabling efficient synchronization.

B1 — `$@` and `$*` represent all positional parameters. `"$@"` preserves individual arguments as separate quoted strings (best for loops). `"$*"` collapses all arguments into a single string separated by the first character of `IFS`.

B2 — `set -e` (exit on error), `-u` (exit on unset variables), `-o pipefail` (return non-zero if any command in a pipeline fails).

B3 — `$(command)` is command substitution (executes and captures output). `` `command` `` is the older, deprecated version. `$((expression))` is for arithmetic expansion; `expr` is an external program for math.

B4 — **Process substitution** `<(command)` creates a temporary file descriptor (like `/dev/fd/63`) that acts as a file. *Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands as if they were files.

B5 — Use `while IFS= read -r f; do ... done < <(find . -print0)` or `find . -print0 | xargs -0 ...`. `for f in $(ls)` is dangerous because it splits filenames on whitespace, breaking names like "My File.txt".

B6 — `<<EOF` (here-doc) passes multiple lines of input. `<<<` (here-string) passes a single string. `<<-EOF` strips leading **tabs** (not spaces) from the input, allowing for cleaner indentation in scripts.

B7 — 
1. `cmd > file 2>&1`: Redirects stdout to `file`, then redirects stderr to where stdout is currently going (`file`).
2. `cmd 2>&1 > file`: Redirects stderr to stdout (the terminal), then redirects stdout to `file`. Stderr still goes to the terminal.
3. `cmd &> file`: Redirects both stdout and stderr to `file`.

B8 — Use `mkdir` for locking because `mkdir` is an **atomic operation** at the kernel level; if two processes try to `mkdir` the same directory, only one succeeds.
```bash
lockdir="/tmp/mylock"
trap 'rmdir "$lockdir" 2>/dev/null' SIGTERM SIGINT EXIT
if mkdir "$lockdir" 2>/dev/null; then
    # critical section
    rmdir "$lockdir"
else
    exit 1
fi
```

B9 — `'...'` (single): Literal string, no expansion. `"..."` (double): Allows variable expansion and command substitution. `no quotes`: Allows expansion but splits on whitespace (dangerous). *Example:* `echo '$USER'` prints `$USER`; `echo "$USER"` prints `john`.

B10 — `-e` (exists), `-d` (directory), `-r` (readable). `[ ]` is the standard `test` command; `[[ ]]` is a Bash keyword that is more powerful, supports regex (`=~`), and doesn't require quoting variables to prevent errors.

B11 — `$?` (exit status of last command), `$$` (PID of current shell), `$!` (PID of last background job), `$#` (number of arguments).

B12 — `foo() {}` is the standard POSIX way; `function foo {}` is a Bashism. Functions return **exit codes** (0-255) via `return`. To return strings, use `echo` and capture with `$(foo)`.

B13 — `PATH` is a colon-separated list of directories searched for executables. A **builtin** (e.g., `cd`) is part of the shell; an **external** command (e.g., `ls`) is a file on disk. Use `type <cmd>` to check.

B14 — `trap` catches signals. `trap 'cleanup' EXIT ERR INT TERM`. If multiple signals arrive, they are handled sequentially, but the shell may terminate immediately if a fatal signal is received.

B15 — `xargs` converts stdin to arguments for a command. `find -print0 | xargs -0` handles spaces/newlines by using the null character as a delimiter. `xargs -P <N>` runs up to N processes in parallel.

B16 — `declare -a arr` (indexed), `declare -A assoc` (associative). Append: `arr+=("val")`. Iterate: `for i in "${!arr[@]}"` (keys) or `for v in "${arr[@]}"` (values). Length: `${#arr[@]}`.

B17 — `(...)` creates a **subshell** (new process, new variable scope). `{ ...; }` is a **group command** (same process, same scope). Piping `cmd | while` runs the loop in a subshell, so variable changes inside the loop are lost when the loop ends.

B18 — `SIGINT` (Ctrl+C), `SIGTERM` (polite kill), `SIGHUP` (terminal closed), `SIGKILL` (immediate, cannot be trapped). For graceful shutdown: `trap 'kill $(jobs -p)' EXIT`.

B19 — Use `split` to break the log, `xargs -P` to run a function on chunks, and `cat` to merge. *Trade-off:* Parallelism speeds up processing but increases CPU/IO contention and makes error tracking harder (use `set -e` or check exit codes).

B20 — `exec` replaces the current shell process with the new command. `exec 3>file` opens file descriptor 3 for writing. A **coprocess** (`coproc`) allows a shell to communicate with a background process via pipes, useful for long-running daemons.

PS1 — `Write-Output` sends objects to the **pipeline** (can be captured by `|`). `Write-Host` writes directly to the **host/console** (cannot be captured).

PS2 — The **pipeline** passes whole objects between commands. `ForEach-Object` is a cmdlet used in a pipeline (efficient for streaming). `foreach` is a language keyword (faster for in-memory collections).

PS3 — `[PSCustomObject]` is an object with properties (best for pipelines/output). `[hashtable]` is a key-value collection (best for internal logic). Convert: `[PSCustomObject]@{key='val'}` or `[hashtable]$obj`.

PS4 — **Terminating** errors stop execution; **non-terminating** errors continue. `$ErrorActionPreference = 'Stop'` turns non-terminating errors into terminating ones, allowing `try/catch` to work.

PS5 — **Splatting** passes a hashtable as arguments: `$params = @{Path='C:\'; Force=$true}; Write-Item @params`. It differs from passing a hashtable as a single parameter because it "unpacks" the keys into parameter names.

PS6 — `Invoke-Command -ComputerName` runs a scriptblock on a remote machine (one-to-many). `Enter-PSSession` starts an interactive session (one-to-one). They use **WS-Management (WinRM)** or **SSH**.

PS7 — In the example, `$x` becomes `[Object[]]` (an array of objects) because `$result += "one"` forces the array to be re-evaluated. If 0 items are returned, it might be `$null`. **Correct pattern**: Use `[System.Collections.Generic.List[string]]` and `.Add()`.

PS8 — A `[scriptblock]` is a piece of code; a function is a named wrapper. Pass via `-ArgumentList`. The **double-hop problem** occurs when you use credentials to jump to Server A, but Server A cannot use those credentials to jump to Server B. Solve with **CredSSP** or **Kerberos Delegation**.

PS9 — `@()` creates an empty array; `[array]` is a type. To force a single result into an array, use `@($result)`. Indexing `$null` results in an error; indexing an empty array returns `$null`.

PS10 — `-eq` (equals), `-match` (regex), `-like` (wildcard). `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection. `-ceq` is the case-sensitive version of `-eq`.

PS11 — **Script module** (`.psm1`) contains functions. **Manifest** (`.psd1`) contains metadata. **Binary module** is a compiled DLL. `Import-Module` loads them into the session.

PS12 — `"Hello $name"` is interpolated; `'Hello $name'` is literal. Use `$()` for expressions: `"Date: $(Get-Date)"`. **Here-strings** use `@"` ... `"@` for multi-line blocks.

PS13 — `Get-Member` shows the type and members of an object. **Properties** (data), **Methods** (actions), **NoteProperties** (custom properties added to an object). `Select-Object` picks properties; `Where-Object` filters objects.

PS14 — **PowerShell Classes** are more similar to C# but have limitations (e.g., no full support for all C# features). Use **classes** for complex data structures; use **functions** for procedural logic/Cmdlets.

PS15 — `[CmdletBinding()]` makes a function behave like a professional cmdlet (enabling `-Verbose`, `-ErrorAction`, etc.). `Begin/Process/End` allows handling pipeline input efficiently.

PS16 — **Providers** allow treating different data stores as a drive. `Get-ChildItem Registry::HKEY_LOCAL_MACHINE\Software` works just like a file system.

PS17 — **Runspaces** are the underlying threads. `ForEach-Object -Parallel` (v7+) is a high-level wrapper that manages a thread pool automatically, whereas manual runspace management is more complex but offers finer control.

PS18 — **PSScriptAnalyzer** is a static code analysis tool. It uses **rules** to check for best practices. You can suppress rules with `# PSScriptAnalyzer Avoids: RuleName` and integrate it into CI/CD via `Invoke-ScriptAnalyzer`.

PS19 — `$using:var` is used to pass a local variable into a remote/parallel scope. **Serialization limits** occur when objects are converted to XML to move between sessions; complex types (like open file handles or database connections) cannot be serialized.

PS20 — **DSC** uses **Configurations** (code), **Resources** (the "how"), and the **LCM** (the engine). Windows PowerShell uses WMF; PowerShell 7+ uses modern modules. Modern IaC (Terraform/Ansible) has largely replaced DSC for cross-platform orchestration.
