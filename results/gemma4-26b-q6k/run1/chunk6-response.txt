DN1 — **Class vs Struct**: A `class` is a reference type (stored on the heap), while a `struct` is a value type (usually stored on the stack). Use a `struct` for small, immutable data structures (typically < 16 bytes) that have a short lifetime to reduce GC pressure.

DN2 — **IEnumerable vs IQueryable**: `IEnumerable<T>` is for in-memory collections; LINQ operations are executed in the application. `IQueryable<T>` is for out-of-memory providers (like EF Core); it builds an expression tree that is translated into a provider-specific language (like SQL). This distinction matters because `IEnumerable` pulls all data into memory before filtering, whereas `IQueryable` filters at the database level.

DN3 — **Async/Await**: `async/await` provides non-blocking asynchronous programming by yielding control back to the caller during I/O-bound operations. A `Task` represents an ongoing operation; a `ValueTask` is a specialized struct used to reduce allocations when an operation might complete synchronously. Use `ValueTask` when the result is often available immediately (e.g., reading from a buffer).

DN4 — **Dependency Injection**: DI is a design pattern where objects receive their dependencies from an external source rather than creating them. 
- **Transient**: New instance every time it is requested.
- **Scoped**: One instance per client request (e.g., per HTTP request).
- **Singleton**: One instance for the lifetime of the application.
**Common Bug**: Injecting a Scoped service into a Singleton. The Scoped service becomes "captured" by the Singleton, effectively becoming a Singleton itself, which can lead to stale data or concurrency issues.

DN5 — **String vs ReadOnlySpan<char>**: `string` is an immutable heap-allocated object. `ReadOnlySpan<char>` is a stack-allocated view into a contiguous region of memory (string, array, or unmanaged memory). Use `Span<T>` for high-performance slicing and parsing to avoid unnecessary string allocations and heap pressure.

DN6 — **Garbage Collector**: The GC manages memory automatically. 
- **Gen 0**: Short-lived objects (collected most frequently).
- **Gen 1**: Buffer between Gen 0 and Gen 2.
- **Gen 2**: Long-lived objects.
- **LOH (Large Object Heap)**: For objects > 85,000 bytes; these are not compacted by default, which can lead to fragmentation.
`IDisposable` is used to manually release unmanaged resources (file handles, DB connections) because the GC only manages managed memory.

DN7 — **ConfigureAwait(false)**: By default, `await` attempts to marshal the continuation back to the original `SynchronizationContext` (e.g., UI thread or ASP.NET request context). `ConfigureAwait(false)` tells the runtime it doesn't need to return to that context. Use it in library code to improve performance and prevent deadlocks; do NOT use it in application code where you need to access UI elements or specific context-bound data.

DN8 — **Modern .NET Features**: 
- **Primary Constructors**: Define parameters directly in the class header.
- **Collection Expressions**: `int[] arr = [1, 2, 3];`
- **FrozenDictionary**: An immutable, highly optimized read-only dictionary.
*Example:*
```csharp
public class UserService(IUserRepository repo) : IUserService {
    public User GetUser(int id) => repo.Find(id);
}
```

DN9 — **ObjectDisposedException**: This is likely caused by a race condition where multiple threads are sharing a single `DbContext` instance. `DbContext` is not thread-safe. **Fix**: Ensure the `DbContext` is registered as `Scoped` (the default) and that you are not manually creating a singleton or sharing a single instance across tasks. Each concurrent request/task must have its own scope.

DN10 — **Record vs Class**: `record` provides built-in value-based equality and non-destructive mutation (`with` expression). `class` uses reference equality. `record struct` combines value-type semantics with record features. Use `record` for DTOs/Data models; use `class` for complex logic/stateful objects.

DN11 — **ref, out, in**: 
- `ref`: Pass by reference; variable must be initialized before passing.
- `out`: Pass by reference; variable must be assigned inside the method.
- `in`: Pass by reference; variable is read-only (prevents copying of large structs).

DN12 — **Nullable Reference Types**: The `?` on a reference type (e.g., `string?`) is a compiler hint for static analysis to warn about potential nulls. It does *not* change the underlying type (it's still a reference type). For value types (e.g., `int?`), it is syntactic sugar for `Nullable<T>`, which wraps the value.

DN13 — **LINQ**: Language Integrated Query. 
- **Method Syntax**: Uses extension methods (`.Where()`).
- **Query Syntax**: Uses SQL-like syntax (`from x in...`).
**Deferred Execution**: The query is not executed when defined, but when the data is actually iterated (e.g., via `foreach` or `.ToList()`).

DN14 — **Generic Constraints**: 
- `where T : class`: T must be a reference type.
- `where T : struct`: T must be a value type.
- `where T : new()`: T must have a public parameterless constructor.
- `where T : IComparable<T>`: T must implement the interface.
Combine them to narrow the type requirements (e.g., `where T : class, new()`).

DN15 — **Abstract Class vs Interface**: An `abstract class` can hold state (fields) and provide implementation; an `interface` defines a contract. **Default Interface Methods** allow interfaces to provide implementation, blurring the line, but interfaces still cannot hold instance state (fields).

DN16 — **Middleware Pipeline**: 
- `app.Use()`: Adds middleware that can call the next component.
- `app.Map()`: Branches the pipeline based on a path.
- `app.Run()`: A terminal middleware that does not call `next()`.
**Ordering**: Order is critical (e.g., Exception Handling must be first to catch errors in subsequent steps). Exception handling works by wrapping the `next()` call in a `try-catch` block.

DN17 — **Channel<T>**: A high-performance, thread-safe queue for producer-consumer scenarios. Unlike `BlockingCollection<T>`, it is fully `async`-compatible. 
*Example:*
```csharp
var channel = Channel.CreateBounded<int>(10); // Backpressure: producer waits if 10 items are in queue
// Producer: await channel.Writer.WriteAsync(item);
// Consumer: await foreach (var item in channel.Reader.ReadAllAsync()) { ... }
```

DN18 — **Source Generators**: They generate C# code during compilation based on user code. Unlike **Reflection** (runtime inspection) or **IL Weaving** (modifying bytecode), they are type-safe and happen at compile-time. **Incremental Generators** are preferred because they only re-run when relevant parts of the syntax tree change, significantly improving IDE performance.

DN19 — **TPL Dataflow**: A library for building actor-based pipelines.
- `ActionBlock`: Executes an action on incoming data.
- `TransformBlock`: Transforms input into output.
- `BufferBlock`: Holds items in a queue.
**vs Channels**: Channels are lower-level, highly optimized for passing data between tasks; TPL Dataflow is higher-level, providing complex routing, buffering, and actor-like logic.

DN20 — **Minimal APIs**: A way to build APIs with minimal ceremony, bypassing the Controller pattern.
- **Trade-offs**: Faster startup and less boilerplate, but harder to organize large-scale logic compared to Controllers.
- **Testing**: Easier to unit test individual handlers.
- **Route Groups**: Allow applying middleware/authorization to a group of endpoints.
- **Endpoint Filters**: Act like middleware specifically for the endpoint execution.
