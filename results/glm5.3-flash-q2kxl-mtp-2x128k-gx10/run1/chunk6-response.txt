# JavaScript / TypeScript

**JS1** — `var` is function-scoped, hoisted and initialized to `undefined`. `let`/`const` are block-scoped, hoisted but left in the Temporal Dead Zone (access before declaration throws `ReferenceError`). `const` requires an initializer and can't be reassigned (though object/array *contents* are mutable). **Hoisting** is the creation-phase behavior where declarations are registered before code runs: `var` gets `undefined`, function declarations are fully hoisted (callable before their line), `let`/`const` are hoisted but uninitialized (TDZ).

**JS2** — The **event loop** dequeues work when the call stack empties. Order per tick: run current script → drain the **microtask queue** completely (promise callbacks, `queueMicrotask`, `MutationObserver`) → take **one macrotask** (timers, I/O callbacks, UI events, `setImmediate`) → drain microtasks again → possibly render. This is why `Promise.resolve().then(...)` always beats `setTimeout(..., 0)`.

**JS3** — A **closure** is a function that retains access to its lexical scope even when executed outside it. Example: `function counter() { let n = 0; return () => ++n; }`. The classic bug:
```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3,3,3
```
`var` is function-scoped, so all callbacks share one `i`, which is 3 when they run. Fix: use `let` (fresh per-iteration binding) or wrap in an IIFE: `((j) => setTimeout(() => console.log(j)))(i)`.

**JS4** — A `Promise` is a placeholder for an async result with states pending → fulfilled/rejected. `async/await` is syntax sugar: `await` pauses the async function, unwraps the promise; rejections become thrown errors caught by `try/catch`; promise chains use `.catch()`. **`Promise.all`** rejects immediately (fast-fail) if any input rejects; **`Promise.allSettled`** never rejects — it waits for all and returns `[{status:'fulfilled', value} | {status:'rejected', reason}]`. Use `all` when all results are required; `allSettled` for "best effort" batch work.

**JS5** — `interface` supports declaration merging (re-openable), can `extends` others, and describes class contracts — best for public APIs and object shapes. `type` can represent unions, intersections, primitives, mapped/conditional types — required for those, preferred for utility types. **Discriminated unions** combine them: a union of variants sharing a literal-typed discriminant field enables narrowing:
```ts
type Shape = { kind: 'circle'; r: number } | { kind: 'square'; s: number };
if (s.kind === 'circle') { /* s.r available */ }
```

**JS6** — Every object has an internal `[[Prototype]]`; property lookup walks the prototype chain until found or `null`. **`Object.create(proto)`** builds an object whose prototype is `proto` (optionally with property descriptors) — the primitive of delegation. ES6 `class` is mostly syntactic sugar over prototypes: `class A {}` creates a function with prototype-linked instances, but adds real differences: it must be `new`-ed, is not hoisted, runs in strict mode, methods are non-enumerable, and it has `[[Construct]]`/`new.target` semantics.

**JS7** — `this` binding rules in priority order: **1) `new` binding** (fresh object), **2) explicit binding** (`call`/`apply`/`bind`), **3) implicit binding** (`obj.fn()` — `this` is the receiver left of the dot), **4) default binding** (`undefined` in strict mode, global otherwise). Arrow functions ignore all of these — they lexically capture `this`. **`bind()`** returns a *new* bound function with permanently fixed `this` and pre-pended args; calling `call`/`apply` on it later **cannot** re-bind `this` (args still append). Only `new` overrides a bound function's `this`.

**JS8** — **`WeakRef`** holds a weak reference that doesn't keep its target alive; `ref.deref()` returns the object or `undefined` if GC'd. **`FinalizationRegistry`** registers a callback to run after an object is collected. Use cases: caches, cleanup of external resources — but both are discouraged for correctness because GC timing is nondeterministic. **`WeakMap` keys must be objects** because weakness requires identity: the key must be *referenced*, not copied. Primitives are copied by value, so there's nothing to weakly point at (registered symbols are the modern exception). This lets entries vanish when the key is unreachable, avoiding leaks in metadata caches.

**JS9** — V8 pipeline: parse → AST → **Ignition** (bytecode interpreter) → **TurboFan** (optimizing compiler using type feedback). **Hidden classes (Maps)**: every object shape gets a hidden class; same-shape objects share one, enabling fast property access. **Inline caching**: each property-access call site caches the last shape+offset pair, making repeated monomorphic access nearly free. **Deoptimization** happens when assumptions break. Deopt-inducing patterns: adding/deleting properties after creation (shape transitions, dictionary mode), objects with different shapes hitting one call site (polymorphic → megamorphic), using objects as string-keyed hashmaps, `arguments` leaking, mixed-type arrays, `try/catch`/`for...in` over hot loops (historically), `Object.defineProperty` with reconfigurable props.

**JS10** — **Tree-shaking** is build-time dead-code elimination of unused exports. ES modules are **static**: `import`/`export` are top-level, fixed syntax, so bundlers (Rollup, webpack, esbuild) can build a dependency graph and mark unused exports. **CommonJS** is dynamic: `require()` can be conditional/computed, `module.exports` is reassigned at runtime, so a bundler can't know which exports are used without executing the module. Support requires `"sideEffects": false` (or a side-effect list) in `package.json` and ESM-friendly packages.

**JS11** — `undefined` means "not assigned"; `null` means intentional "no value" (typeof `'object'` for legacy reasons). With `==`, `null == undefined` is `true` (and only each other — both are `==` to nothing else); `===` distinguishes them. **`??`** returns the right operand only when the left is `null`/`undefined` (unlike `||`, which triggers on `0`, `''`, `false`). **`?.`** short-circuits the whole chain to `undefined` if the base is nullish: `a?.b?.c?.()`.

**JS12** — `map` transforms every element (same length); `filter` keeps elements passing a predicate; `reduce` folds the array into one value: `(acc, cur) => newAcc, initialValue`. With an initial value, iteration starts at index 0; without it, the first element is the seed and iteration starts at index 1 (throws on empty array). **`flatMap`** = `map` then flatten one level — ideal for "expand each item into 0..n items": `str.split('\n').flatMap(l => l.split(','))`.

**JS13** — Template literals (backticks) support interpolation `${expr}`, multiline strings, and raw access. **Tagged templates** call a function instead of producing a string: `tag(strings, ...values)` where `strings` is the cooked (and `.raw`) literal parts. Example — SQL safety:
```js
const sql = (strings, ...vals) =>
  strings.reduce((q, s, i) => q + s + (i > 0 ? '$' + i : ''), '');
db.query(sql`SELECT * FROM users WHERE name = ${userName}`); // parameterized
```
Same pattern powers `lit-html` and escaping helpers.

**JS14** — Destructuring extracts data by pattern. Object: `const { a, b = 5, c: renamed, ...rest } = obj;` (default value, rename via `c: renamed`, rest collects remaining own enumerable props). Array: `const [first, , third, ...tail] = arr;` (holes skip). Works nested, in parameters, and in for-of headers. The **rest operator** (`...`) must be last and collects "everything else" — array elements or object properties.

**JS15** — `for...in` iterates **enumerable string keys** of an object, *including inherited ones*; `for...of` iterates **iterables** (anything with `Symbol.iterator`: arrays, strings, Maps, Sets, generators). Avoid `for...in` on arrays: it yields index keys as *strings*, includes inherited/extended properties (e.g., added to `Array.prototype`), and gives no order guarantee — use `for...of`, `forEach`, or a classic `for` loop.

**JS16** — **Generics** parameterize types: `function identity<T>(v: T): T`. **Constraints** restrict them: `<T extends { id: number }>(x: T) => x.id` — you can now access `.id`. **Conditional types** branch on assignability: `type IsString<T> = T extends string ? true : false`. **`infer`** captures a type inside a pattern: `type Elem<T> = T extends (infer U)[] ? U : never;` — `Elem<string[]>` is `string`. Combined, these power `ReturnType`, `Awaited`, etc.

**JS17** — **CommonJS**: runtime `require()`, synchronous, `module.exports`, copies values, dynamic — Node legacy standard (`.cjs`). **ESM**: static `import`/`export`, hoisted, live bindings, async loading, top-level `await` (`.mjs`). Node resolves each file's type by extension and the **nearest `package.json`**: `"type": "module"` makes sibling `.js` files ESM (and `.cjs` CommonJS); no field means `.js` is CommonJS. ESM can `import()` CJS; CJS can't `require` ESM synchronously (ESM needs async evaluation).

**JS18** — TypeScript is **structural**: types match by shape, not name. **Excess property checks** apply only to *fresh object literals* directly assigned to a typed target — typos like `{ nam: 'x' }` error, but the same object via a variable passes. **`extends`** declares inheritance/constraint (class extends class, interface extends interface, generic constraint). **`satisfies`** (4.9+) validates an expression against a type *while keeping the inferred narrow type*: `const c = {a:1} satisfies Record<string, number>` — `c.a` stays `number` (not `any`/widened). **Variance** (4.7+): `out T` marks covariant positions (produced), `in T` contravariant (consumed); by default TS is structurally covariant, with `strictFunctionTypes` making function parameters checked contravariantly.

**JS19** — **`Proxy`** wraps a target and intercepts fundamental operations via traps: `get`, `set`, `has`, `deleteProperty`, `apply`, `construct`, `ownKeys`, etc. **`Reflect`** provides the default implementations of those operations, so traps can delegate cleanly. Example — reactive binding (Vue-style):
```js
function reactive(obj) {
  return new Proxy(obj, {
    get(t, k, r) { track(k); return Reflect.get(t, k, r); },
    set(t, k, v, r) { Reflect.set(t, k, v, r); trigger(k); return true; }
  });
}
```
Validation: throw in `set` when the value fails a schema. Function interception: `apply` trap on a proxy whose target is a function.

**JS20** — **`SharedArrayBuffer`** is raw memory shared between the main thread and Workers (transferred via `postMessage`); both sides see the same bytes. **`Atomics`** provides lock-free primitives (`load/store/add/exchange/compareExchange`) with **sequential consistency** for atomics and happens-before ordering: writes before `Atomics.wait`/`notify` are visible after wake. `Atomics.wait` (not allowed on the main thread) blocks a worker until `Atomics.notify` fires or timeout — the basis for mutexes/condition variables (see `Atomics.Mutex` proposals / `waitAsync` for main-thread use).

# Bash

**B1** — Unquoted, `$@` and `$*` are identical (all params, word-split). Quoted: **`"$@"`** expands to *separate* words preserving each argument exactly; **`"$*"`** joins all args into *one* string using the first character of `IFS` (usually a space). Rule of thumb: always use `"$@"`; `"$*"` only when you deliberately want a joined string.

**B2** — `set -e` exits on any simple command failure; `set -u` treats unset variables as errors; `-o pipefail` makes a pipeline's exit status the first non-zero (instead of the last command's). Together: fail fast and catch failures hidden inside pipes. Caveats: `-e` is bypassed inside `if` conditions, `&&`/`||` lists, and subshells; some commands (e.g., `grep` no-match) "fail" legitimately.

**B3** — `$(cmd)` is modern command substitution: nestable, quote-friendly; backticks are legacy and can't nest cleanly. `$((expr))` is shell arithmetic (integer, no external process, C-like operators); `expr` is an external legacy utility needing escaped `*`, spaces around operators, and is slower — use `$(( ))` or `let`/`bc` for floats.

**B4** — Process substitution `<(cmd)` connects a command's output to a `/dev/fd/...` filename, letting programs that require file arguments read from streams. Classic use:
```bash
diff <(sort file1) <(sort file2)   # compare sorted views, no temp files
```
Also `grep -f <(gen_patterns)`, `while read < <(cmd)` (fixes the subshell-pipe problem).

**B5** — Safe iteration: use globs (`for f in *.txt`) or null-delimited streams:
```bash
while IFS= read -r -d '' f < <(find . -name '*.txt' -print0); do ...; done
find . -print0 | xargs -0 cmd
```
`for f in $(ls)` is dangerous because the output undergoes word splitting (spaces break names apart) and globbing (metacharacters in filenames expand), and parsing `ls` output is unreliable across locales/formats.

**B6** — `<<EOF` (here-doc) feeds a multi-line literal to stdin; `<<<` (here-string) feeds a single word plus newline: `grep root <<<"$line"`. `<<-EOF` strips **leading tabs only** (not spaces) so nested scripts look clean — it fails visually if you indent with spaces.

**B7** — Order matters because redirections are processed left to right:
- `cmd > file 2>&1` — stdout → file, then stderr → *same* file: **both captured**.
- `cmd 2>&1 > file` — stderr → current stdout (the terminal), then stdout → file: **file gets stdout only; stderr leaks to the terminal**.
- `cmd &> file` — bash shorthand for the first form (both to file; not POSIX).

**B8** —
```bash
LOCK_DIR=/tmp/myscript.lock
if ! mkdir "$LOCK_DIR" 2>/dev/null; then echo "already running" >&2; exit 1; fi
trap 'rm -rf "$LOCK_DIR"' EXIT INT TERM
# ... work ...
```
`mkdir` is preferred because it is a **single atomic syscall** — it either succeeds or fails, so there's no check-then-create race (TOCTOU) that `touch`/`test -f` + create has. The `trap` on `EXIT INT TERM` guarantees removal on normal exit, Ctrl-C, or SIGTERM (SIGKILL can't be trapped — use `flock` with a timeout or stale-lock expiry for that).

**B9** — Single quotes: fully literal (`echo '$HOME'` → `$HOME`). Double quotes: expansion happens but word splitting/globbing of the result is suppressed (`echo "$var"` keeps spaces). Unquoted: expansion + word splitting + globbing (`echo $var` splits into multiple words; `*` expands to filenames). Example: `var="a b"` → `echo $var` prints `a b` (two args), `echo "$var"` prints `a b` (one arg), `echo '$var'` prints `$var`.

**B10** — `[ -e f ]` exists, `[ -f f ]` regular file, `[ -d f ]` directory, `[ -r f ]` readable, `[ -x f ]` executable, `[ -s f ]` non-empty. `[ ]` is POSIX `test`: words are split/globbed, requires quoting, `&&`/`||` unavailable (use `-a`/`-o`). `[[ ]]` is a bash keyword: no splitting/globbing of variables, supports `&&`, `||`, `<`, pattern matching, and `=~` regex.

**B11** — `$?` last exit status (use: `if cmd; then` / error checks); `$$` current shell PID (use: temp-file names, logging); `$!` PID of the last background job (use: `kill $!`, `wait $!`); `$#` count of positional args (use: argument validation `if [ $# -lt 2 ]`).

**B12** — `foo() { ...; }` is POSIX; `function foo { ... }` is a ksh/bash extension — functionally identical in bash. "Return" two ways: `return N` sets the exit status (0–255, checked via `$?`), and *output* values are captured with `result=$(foo)` (stdout). For multiple values, set globals or use `local -n` namereferences.

**B13** — `PATH` is a colon-separated list of directories searched in order for executables. Resolution: bash first checks aliases/functions/builtins, then scans `PATH`. A **builtin** runs inside the bash process (`cd`, `echo`, `printf`); an **external** is a separate binary via fork/exec (`/bin/echo`). Check with `type -a cmd`, `command -v cmd`, or `which -a cmd`.

**B14** — `trap 'commands' SIGNAL` runs commands when the signal arrives. Common setup:
```bash
trap cleanup EXIT      # always runs on exit
trap 'echo err' ERR    # needs -E/-o errtrace for functions/subshells
trap 'exit 130' INT    # Ctrl-C
trap 'exit 143' TERM
```
Bash doesn't interrupt a running command mid-way: the trap runs after the current command finishes. Signals are **not queued** — repeated signals coalesce into one pending trap; handlers run one at a time, and the `EXIT` trap fires after any signal handler that exits.

**B15** — Command substitution captures output into a single string (then word-splits it); `xargs` appends output as arguments to a command, automatically batching to stay under `ARG_MAX`. For arbitrary filenames: `find . -print0 | xargs -0 cmd` (NUL is the only byte a filename can't contain). `xargs -P N` runs up to N invocations concurrently (`-P 0` = unlimited) — great for parallel compression/uploads.

**B16** — Indexed arrays: `a=(x y z)`, append `a+=("w")`, iterate `for v in "${a[@]}"`, length `${#a[@]}`, sparse indices allowed. Associative: `declare -A m; m[key]=val`, iterate keys `for k in "${!m[@]}"`, length `${#m[@]}`. Differences: indexed arrays use automatic integer keys and preserve insertion order; associative arrays use arbitrary string keys, require `declare -A`, and have unspecified iteration order.

**B17** — `(...)` runs in a **subshell**: a forked copy — variable changes, `cd`, and `set` options don't affect the parent; exit status is that of the last command. `{ ...; }` is a **group command** in the *same* shell: full side effects, needs a trailing `;` and surrounding spaces. Piping into `while` (`cat f | while read ...`) runs the loop in a subshell, so counters/variables set inside are lost; fixes: `while ... done < <(cat f)`, `mapfile`, or `shopt -s lastpipe` (with job control off).

**B18** — **SIGINT** (2, Ctrl-C), **SIGTERM** (15, polite "please terminate" — default `kill`), **SIGHUP** (1, terminal hangup; daemons often reuse it as "reload config"), **SIGKILL** (9, uncatchable, unignorable, no cleanup chance). Graceful shutdown with children:
```bash
children=()
trap 'kill -TERM "${children[@]}"; wait "${children[@]}"; cleanup; exit 0' INT TERM
worker & children+=($!)
wait
```
Kill the process group (`kill -- -$$`) if children spawn their own children.

**B19** —
```bash
split -n l/8 -d big.log chunk_          # 8 byte-count-balanced chunks
process_chunk() { gzip -c "$1" > "$1.gz"; }
export -f process_chunk
ls chunk_* | xargs -P 4 -I{} bash -c 'process_chunk "$1"' _ {} || { echo "a chunk failed"; }
cat chunk_*.gz | gzip -d | gzip -c > big.log.gz   # or merge as needed
rm -f chunk_*
```
Trade-offs: parallelism helps until CPU/disk I/O saturates; `split -n` avoids many tiny files; output order is lost (use `sort`/numbered names to reassemble). Error propagation: `xargs` returns non-zero if any invocation fails (and exits 123 if any child fails), so check its exit status; for per-chunk diagnostics, have each worker write a status file or use GNU `parallel --keep-order --joblog`.

**B20** — Normally, a command runs as a child process and the shell continues after it. `exec cmd` **replaces** the shell process with `cmd` (same PID, no return, no cleanup of shell state) — used to hand over a wrapper script's PID. `exec` with only redirections changes the *current shell's* FDs permanently: `exec 3>file` opens FD 3 for writing; `exec 3>&-` closes it; `exec 3<&0` saves/restores stdin. **Coprocess**: `coproc CP { sqlcli; }` starts a background command with its input/output connected to FDs you access via `printf >&"$CP[1]"` / `read -u "$CP[0]"` — ideal for driving an interactive subprocess (database CLI, `ssh` master connection) without re-spawning per command.

# PowerShell

**PS1** — `Write-Output` writes to the **success stream** (the pipeline): it can be captured, filtered, and composed. `Write-Host` writes to the **information stream** (host display only, since PS5) — it bypasses pipeline output. This matters because functions should emit *objects*; `Write-Host` inside a function makes its output unassignable (`$x = f` gets nothing), breaking composability. Use `Write-Host`/`Write-Information` only for user-facing status.

**PS2** — The pipeline streams objects one at a time to the next command. **`ForEach-Object`** is a cmdlet: works mid-pipeline, processes items as they arrive (streaming, low memory), supports `-Parallel` (v7). The **`foreach` statement** is a language construct: operates on an in-memory collection, faster for local collections, and its loop variable persists after the loop. Rule: use `foreach` when you already have a collection in a variable; use `ForEach-Object` when piping or when memory streaming matters.

**PS3** — `[PSCustomObject]` preserves property order, has case-insensitive members, plays well with `Format-Table`/`Export-Csv`, and is the right shape for structured output. `[hashtable]` (and `[ordered]`) offers fast key lookup and dynamic keys but isn't order-preserving (unless `[ordered]`) and renders poorly. Convert: `[PSCustomObject]$ht` (or `New-Object PSObject -Property $ht`); PSCustomObject → hashtable: `$obj.PSObject.Properties | ...` building a hashtable from Name/Value.

**PS4** — **Terminating** errors stop execution and are caught by `try/catch`; **non-terminating** errors write an error record and execution continues. `-ErrorAction` (per cmdlet) and `$ErrorActionPreference` (scope-wide, default `Continue`) control this: `-ErrorAction Stop` promotes a non-terminating error to terminating so `catch` can handle it. `try/catch` alone does *not* catch non-terminating errors — the canonical pattern is `try { Get-Item bad -ErrorAction Stop } catch { ... }`. `-ErrorVariable` captures errors without stopping.

**PS5** — **Splatting** passes a hashtable of parameters: 
```powershell
$p = @{ Path = 'C:\logs'; Recurse = $true; Filter = '*.log' }
Get-ChildItem @p
```
`@p` (with `@` instead of `$`) expands the hashtable into named parameters. Passing `$p` instead would deliver the hashtable itself as a single parameter value (likely a type/parameter error). Splatting also improves readability and enables conditional parameter sets.

**PS6** — `Invoke-Command -ComputerName` runs a script block or command remotely (one-shot or `-Session`), returning **deserialized** objects; `Enter-PSSession` creates an interactive remote session. Transport: **WS-Management (WinRM)** over HTTP 5985 / HTTPS 5985–5986 by default; PowerShell 7 adds **SSH-based remoting** (`-HostName`/`-UserName`, using SSH transport and keys). Both are built on **PS sessions (runspaces)** created over the transport.

**PS7** — The pipeline **unrolls** collections: a function returning a 1-element array returns the element itself. So `$x.GetType().Name` prints **`String`** — the `@()` + `+=` built a `["one"]`, but `return` unrolled it. If the function returns **0 items**, `$x` is `$null` (and `$x.GetType()` throws). Correct patterns: capture with `@()` at the call site (`$x = @(Get-Items)` guarantees an array), use `Write-Output $result -NoEnumerate` or the comma operator `,$result` to preserve array-ness, and avoid `$result += $item` in loops (use `[System.Collections.Generic.List[object]]` or emit to the pipeline directly).

**PS8** — A **scriptblock** is an anonymous, invokable unit of code (`{ ... }`, can be `.Invoke()`, bound with `.GetNewClosure()`); a **function** is a named, registered command in a scope. Remoting serializes script blocks as **strings** and re-parses them remotely, so they arrive without local state. Pass data with `-ArgumentList` (or `$using:`): `Invoke-Command -ComputerName s { param($n) Get-Process $n } -ArgumentList 'notepad'`. The **double-hop problem**: credentials presented to server A are not delegated to server B when A accesses a network resource — solutions: **CredSSP** delegation (enables credential forwarding; security-sensitive), Kerberos resource-based constrained delegation, or explicit credentials/certificates passed via `-ArgumentList` (carefully) or managed identities.

**PS9** — `@(...)` is the array sub-expression operator guaranteeing an array result; `[array]` is a .NET type cast. Force a single item into an array: `@($value)` (also protects against `$null` → gives an empty array). Indexing: `$null[0]` yields `$null` (an error under `Set-StrictMode`); indexing past the end of an array also returns `$null` silently — always test `.Count` / use `@()` wrappers.

**PS10** — `-eq`/`-ne` equality, `-like` wildcard (`*`, `?`), `-match` regex (sets `$Matches`), `-contains` tests whether the **LHS collection** contains the item, `-in` is the reversed form: `item -in collection`. All comparisons are **case-insensitive by default**; the `c`-prefixed variants (`-ceq`, `-clike`, `-cmatch`, `-ccontains`, `-cin`) are case-sensitive. So `'ABC' -eq 'abc'` is `$true`; `-ceq` is `$false`.

**PS11** — A module is a reusable unit of commands. A **script module** (`.psm1`) is a PowerShell file whose functions become exported commands; a **manifest** (`.psd1`) is metadata — version, author, dependencies (`RequiredModules`), explicit export lists (`FunctionsToExport`), PS edition compatibility; a **binary module** is a compiled `.dll` (C# cmdlets). `Import-Module` loads it into the session (respecting `PSModulePath` and manifest exports); `#Requires -Modules` enforces it at parse time.

**PS12** — Double quotes `"..."` interpolate: `$var`, `$obj.Property`, and subexpressions `$( ... )` (e.g., `"Total: $(Get-Date -Format u)"`); format items with `"{0}" -f` or `'{0}'`. Single quotes `'...'` are literal — no interpolation (use doubled `''` for an embedded quote). **Here-strings**: `@" ... "@` (interpolated) and `@' ... '@` (literal); the closing `"@` must be at the start of its own line; ideal for JSON/XML blocks.

**PS13** — `Get-Member` reveals an object's type and members (`gm | more`); pipe any object to it to explore. **Properties** include adapted/inherent .NET properties, **NoteProperties** (added by `Add-Member` or by `Select-Object`/`PSObject` wrapping), plus script properties; **Methods** are callable. `Where-Object` **filters** which objects continue down the pipeline (`? { $_.Len -gt 1 }`); `Select-Object` **projects/reshapes** — picks properties, creates new objects, or takes `-First/-Last/-Unique`.

**PS14** — PowerShell **classes** (v5+) use C#-like syntax but compile at parse time and don't participate in the pipeline (no `Write-Output` streaming, no `Begin/Process/End`). They support inheritance (`class B : A`), static members, overloaded constructors, and can implement .NET interfaces; limitations: no dynamic member access, no pipeline binding, can't be defined conditionally, and validation attributes don't apply to members. Use **classes** for structured types with state and methods (e.g., building an object model, DSC resources); use **functions/cmdlets** for pipeline-centric, parameter-validated operations.

**PS15** — `[CmdletBinding()]` turns a function into an **advanced function**: it gains common parameters (`-Verbose`, `-ErrorAction`, `-WhatIf`...), parameter sets, and validation attributes (`[ValidateNotNull()]`, `[Parameter(Mandatory)]`). **`SupportsShouldProcess`** adds `-WhatIf`/`-Confirm` driven by `ShouldProcess('target','action')`. **`DefaultParameterSetName`** resolves ambiguity when parameters belong to multiple sets. **`ValueFromPipeline`** binds pipeline objects to a parameter. Blocks: **`Begin`** runs once (open resources), **`Process`** once per pipeline item (streaming), **`End`** once after (cleanup/aggregation).

**PS16** — Providers expose non-filesystem data stores as hierarchical, drive-like namespaces navigable with the same item cmdlets. `Get-ChildItem` works on **FileSystem** (`C:\`), **Registry** (`HKLM:\`, `HKCU:\`), **Certificate** (`Cert:\CurrentUser\My`), **Environment** (`Env:`), plus AD, Variable, Function. Browse the registry like files: `Set-Location HKLM:\SOFTWARE\Microsoft`, `Get-ItemProperty`, `New-ItemProperty`, `Get-ChildItem -Recurse`. Providers implement `Get-ChildItem` etc. via dynamic parameters per drive.

**PS17** — A **`[runspace]`** is an isolated PowerShell execution environment (its own session state, variables, error stream) — the unit of thread safety: separate runspaces can't see each other's variables. A **`[powershell]`** object wraps a runspace with an API to add commands/parameters and invoke; a **`[runspacepool]`** manages a pool of runspaces with min/max sizes for many invocations. `ForEach-Object -Parallel` (v7) automates this: spawns runspaces per item, passes data via `$using:`/`-AsJob`-style plumbing, and returns `ThreadJob` results. Manual management (`[runspacefactory]::CreateRunspace`, `[powershell]::Create()`) gives more control (STA, apartment state, preloaded modules) but you must handle open/close, errors, and cleanup yourself.

**PS18** — **PSScriptAnalyzer** is the official static analysis/linting engine for PowerShell. It ships **rules** (e.g., `PSAvoidUsingWriteHost`, `PSUseDeclaredVarsMoreThanAssignments`, `PSUseSingularNouns`) each with a **severity** — Error / Warning / Information — configurable in a settings hashtable or `.EditorConfig`/`PSScriptAnalyzerSettings.psd1`. **Custom rules** are .NET classes deriving from `LoggerBasedGetExternalRule`/AST visitor (`ICustomRule`) passed via `-CustomRulePath`. Suppress with `[System.Diagnostics.CodeAnalysis.SuppressMessageAttribute('PSAvoidUsingWriteHost', '')]` above the offending item or via exclusions in settings. CI/CD: run `Invoke-ScriptAnalyzer -Recurse -Severity Error` and fail the build on errors; it also powers real-time analysis in VS Code's PowerShell extension.

**PS19** — **`$using:`** copies a local variable's value into a remote/job/parallel scope at invocation time (`Invoke-Command`, `Start-Job`, `ForEach-Object -Parallel`); **`-ArgumentList`/`param($args)`** passes values positionally into the script block. Both serialize the value — live object references don't cross. **Serialization limits**: remote output is deserialized from **CLIXML** into property-bag `Deserialized.X` objects — methods are stripped, and nesting is truncated at a limited depth (default depth 2 for implicit remoting), so complex objects lose behavior and deep data. Workarounds: return simple types, rehydrate objects remotely (`Invoke-Command { ... }` doing the work server-side), use `-SerializationDepth`/session options, or `NoLanguage`-safe explicit data contracts.

**PS20** — **DSC** is PowerShell's declarative configuration management: a **Configuration** script declares a desired end state; **Resources** (built-in like `File`/`Service`/`Registry`, plus community/custom) are the units that enforce one aspect of it (each with Get/Set/Test); the **Local Configuration Manager (LCM)** is the agent on each node that applies, re-applies (pull interval), and monitors configurations in push or pull mode. Windows PowerShell 5.1 ships the full DSC (WMF-based, LCM v1/v2, meta-configurations); PowerShell 7+ can *author* configurations and run resources but has no built-in LCM — modern effort is **DSC v3** (cross-platform, C#-based, no LCM dependency, works with any tool). In practice, modern IaC has largely moved to **Ansible, Terraform, Chef, and Pulumi** for orchestration, with DSC v3 positioned as a cross-platform resource model those tools can invoke.
