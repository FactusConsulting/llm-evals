**DN1** — `class` is a reference type (heap-allocated, supports inheritance, nullable, GC-managed). `struct` is a value type (stack/inline-allocated, copy-on-assign, no inheritance, non-nullable by default). Use `struct` for small, immutable, short-lived data that doesn't require inheritance (e.g., coordinates, IDs, math vectors, cache keys).

**DN2** — `IEnumerable<T>` executes in-memory (LINQ to Objects). `IQueryable<T>` builds expression trees that providers (like EF Core) translate to remote queries (SQL). The distinction matters because `IQueryable` pushes filtering, projection, and joins to the database, minimizing memory/network overhead. `IEnumerable` pulls all rows into memory first.

**DN3** — `async/await` compiles to a state machine that captures context, yields control, and resumes when the awaited operation completes, avoiding thread blocking. `Task` is a reference type (heap-allocated). `ValueTask` is a value type that avoids allocation when the async operation completes synchronously. Use `ValueTask` in hot paths or when methods frequently complete synchronously to reduce GC pressure.

**DN4** — DI is a container that manages object creation and dependency wiring. Lifetimes: `Transient` (new each resolution), `Scoped` (one per request/context), `Singleton` (one per app lifetime). Injecting a `Scoped` service into a `Singleton` creates a "captive dependency": the scoped service lives as long as the singleton, causing stale state, memory leaks, and thread-safety violations.

**DN5** — `string` is immutable, heap-allocated, and requires allocations/copies for slicing. `ReadOnlySpan<char>` is a stack-allocated, zero-allocation slice over memory (strings, arrays, buffers). `Span<T>` is the mutable counterpart. Use `Span<T>`/`ReadOnlySpan<char>` in high-performance parsing, string manipulation, or buffer processing to eliminate allocations and improve cache locality.

**DN6** — The GC automatically reclaims unreachable managed objects. Generations: `Gen 0` (short-lived, frequent), `Gen 1` (buffer), `Gen 2` (long-lived, infrequent). Objects age up on survival. The Large Object Heap (LOH) holds objects >85KB, collected only during Gen 2, and isn't compacted by default (causes fragmentation). `IDisposable` is for deterministic cleanup of unmanaged resources (handles, native memory, DB connections); the GC only manages managed memory and doesn't understand OS resources.

**DN7** — Default `async` captures the current `SynchronizationContext` (or `TaskScheduler`) and resumes on it. `ConfigureAwait(false)` skips context capture, resuming on any thread pool thread. Use `ConfigureAwait(false)` in libraries/shared code to avoid deadlocks and improve performance. Do NOT use it in UI apps (need UI thread for updates) or when context is explicitly required. It relates to `SynchronizationContext` because capturing it forces cross-thread marshaling, which is the root cause of sync-over-async deadlocks.

**DN8** — Primary constructors: `public class Service(IOptions<Config> cfg) { }`. Collection expressions: `[1, 2, 3]`, `..array`, `[^1]`. `FrozenDictionary`: Immutable, highly optimized for lookup-heavy scenarios, lower memory footprint, faster than `ImmutableDictionary`. Primary constructor + DI example:
```csharp
public class MyService(IOptions<AppSettings> settings) : IMyService {
    private readonly AppSettings _cfg = settings.Value;
}
```

**DN9** — Cause: `DbContext` is likely registered as `Singleton` or manually resolved outside a request scope. `DbContext` is not thread-safe and follows the Unit of Work pattern. Under high concurrency, multiple requests share the same instance, causing race conditions and disposal conflicts. Fix: Register as `Scoped` (`services.AddScoped<MyDbContext>()`). EF Core's `AddDbContext` defaults to Scoped and uses `IServiceScopeFactory` to create per-request scopes. Sharing it breaks scoping and thread safety.

**DN10** — `record` is a reference type with value-based equality, immutability by default, positional syntax, and `with` expressions. `record struct` is the value-type equivalent. Choose `class` for mutable/stateful objects. Choose `record` for immutable DTOs, domain events, or configuration. Choose `record struct` for performance-critical, small, immutable data where GC allocation must be avoided.

**DN11** — `ref`: Pass by reference, must be initialized before call, read/write. `out`: Pass by reference, must be assigned inside method, caller doesn't need initialization. `in`: Pass by reference, read-only, prevents mutation, avoids copy for large structs. Use `ref` for modifying existing values, `out` for multiple return values/parsing, `in` for performance with large structs.

**DN12** — Nullable Reference Types (`string?`) are compile-time annotations tracked by `#nullable enable`. They warn on potential null dereferences but don't affect runtime behavior. Nullable Value Types (`int?`) are actual CLR types (`Nullable<T>`) that can hold `null` at runtime. NRTs provide static safety for reference types; `T?` for value types is a runtime-capable nullable wrapper.

**DN13** — LINQ is Language Integrated Query, unifying data access across collections, DBs, XML, etc. Method syntax (`.Where(...)`) is fluent, chainable, and preferred for complex queries. Query syntax (`from x in list where ...`) is SQL-like and compiles to method syntax. Deferred execution means the query isn't executed until enumerated (e.g., `foreach`, `.ToList()`), enabling composition and lazy evaluation.

**DN14** — `where T : class` (reference type), `where T : struct` (non-nullable value type), `where T : new()` (parameterless constructor), `where T : IComparable<T>` (implements comparison). Combine them (`where T : class, IComparable<T>, new()`) to enforce compile-time guarantees, enabling type-safe algorithms/collections without runtime casts or exceptions.

**DN15** — Abstract classes can have state, constructors, and partial implementations; support single inheritance. Interfaces define contracts; support multiple inheritance. C# 8+ default interface methods allow interfaces to contain implementations, bridging the gap by enabling backward-compatible API evolution without breaking implementers. Interfaces still cannot hold instance state or constructors.

**DN16** — Middleware processes requests/responses sequentially. `app.Use()` adds middleware to the pipeline. `app.Map()` branches based on path prefix. `app.Run()` is terminal (no `next()` call). Ordering matters: auth before routing, error handling early, static files before MVC. `UseExceptionHandler` catches unhandled exceptions, logs them, and returns a standardized error response; it should be placed early to catch downstream failures.

**DN17** — `Channel<T>` is modern, async-native, high-performance, and supports bounded/unbounded modes with built-in backpressure. `BlockingCollection<T>` is older, sync-focused, and less async-friendly. Bounded channel backpressure example:
```csharp
var channel = Channel.CreateBounded<int>(new BoundedChannelOptions(100) { FullMode = BoundedChannelFullMode.Wait });
await channel.Writer.WriteAsync(item); // Blocks when full, naturally applying backpressure
```

**DN18** — Source Generators compile-time code generation via Roslyn APIs, outputting C# source. Faster and safer than reflection (runtime, slower, breaks AOT) and IL weaving (modifies compiled assemblies, harder to debug). Incremental generators (`IncrementalGenerator`) replace `ISourceGenerator`, support caching, incremental compilation, and better performance. Preferred in modern .NET for compile-time code generation.

**DN19** — TPL Dataflow provides an async pipeline/actor model. `BufferBlock<T>` stores items. `TransformBlock<TIn, TOut>` processes and returns new values. `ActionBlock<T>` processes items (void return). Compared to `Channels`, Dataflow offers richer composition (fan-out/in, join, batch, completion propagation) and is better for complex pipelines. Channels are simpler and better for straightforward producer-consumer patterns.

**DN20** — Minimal APIs are lightweight, inline routing/handlers with less boilerplate and faster startup. Controllers are traditional, attribute-based, and better for complex APIs/large teams. Trade-offs: Minimal APIs have simpler DI/middleware integration but less structured architecture. OpenAPI support is now mature via Swashbuckle/NSwag. Route groups (`app.MapGroup("/api")`) apply prefixes/metadata. Endpoint filters (`AddFilter`) handle cross-cutting concerns (auth, validation) without full middleware.

**P1** — `list`: mutable, ordered, indexed, allows duplicates. `tuple`: immutable, ordered, fixed size, heterogeneous, unpackable. `set`: mutable, unordered, unique elements, hash-based. `frozenset`: immutable set, hashable, usable as dict keys or set elements.

**P2** — GIL (Global Interpreter Lock) is a mutex allowing only one thread to execute Python bytecode at a time. It severely limits CPU-bound multithreaded workloads (no true parallelism). Workarounds: `multiprocessing`, C extensions that release the GIL, `asyncio` for I/O-bound work, or alternative runtimes (PyPy, Jython).

**P3** — `copy.copy()` creates a shallow copy (new container, shared nested objects). `copy.deepcopy()` recursively copies the entire object graph. Shallow copy causes unexpected behavior when nested mutable objects are modified: `a = [[1]]; b = copy.copy(a); b[0].append(2); print(a)` outputs `[[1, 2]]` because inner lists are shared.

**P4** — Decorators wrap functions to extend behavior. Timing decorator:
```python
import time, functools
def log_time(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.4f}s")
        return result
    return wrapper
```

**P5** — Generators use `yield` to produce iterators lazily, avoiding full list allocation. They differ from returning a list by computing values on-demand. `yield from` delegates to another generator/iterable, cleanly forwarding yields without manual iteration loops.

**P6** — The asyncio event loop schedules coroutines and manages I/O events. `asyncio.run()` is the entry point (creates loop, runs coroutine, closes loop). `asyncio.gather()` runs multiple coroutines concurrently and returns results in order. `asyncio.create_task()` schedules a coroutine for concurrent execution. `time.sleep()` blocks the entire thread/event loop; use `await asyncio.sleep()` instead.

**P7** — MRO (Method Resolution Order) defines the search path for attributes/methods. Python 3 uses C3 linearization, ensuring monotonicity and left-to-right precedence. In diamond inheritance `D(B, C)`, MRO is `D -> B -> C -> A`. `D().who()` prints `"C"` because `B` inherits `A` but doesn't override `who`, so lookup continues to `C`, which overrides `A`'s implementation.

**P8** — A metaclass controls class creation (`__new__`, `__init__`), enabling framework-level hooks. `__init_subclass__` is a class method called when a subclass is defined, offering simpler customization. Use metaclasses for automatic method wrapping, strict API enforcement, or registry patterns. Use `__init_subclass__` for plugin registration, automatic validation setup, or simpler inheritance customization.

**P9** — `threading`: I/O-bound, shares memory, GIL-limited. `multiprocessing`: CPU-bound, separate processes, true parallelism, memory isolation. `concurrent.futures`: High-level API (`ThreadPoolExecutor`, `ProcessPoolExecutor`) unifying both. Multiprocessing uses `pickle` for serialization; lambdas, local functions, and some C extensions can't be pickled, requiring workarounds or `pathos`.

**P10** — `__slots__` declares a fixed set of attributes, preventing `__dict__` creation. Use it for memory optimization, performance, and preventing accidental attribute assignment. Memory impact: significantly reduces per-instance overhead (no dict/hash table). Breaks inheritance if base classes don't use `__slots__` properly.

**P11** — Virtual environments isolate project dependencies, preventing conflicts. `venv`: Standard library module (Python 3.3+). `virtualenv`: Third-party, older, more features (e.g., pip upgrade). `conda`: Package + environment manager, handles non-Python dependencies, standard in data science.

**P12** — Comprehensions (`[x for x in lst if x > 0]`) are Pythonic, readable, and often faster. `map()`/`filter()` return iterators, better for lazy evaluation or composing existing functions. Prefer comprehensions for readability. Use `map`/`filter` when working with existing functions or memory-constrained streams.

**P13** — `==` checks value equality. `is` checks object identity (same memory address). CPython interns small integers (-5 to 256) and some strings for performance. `a is b` returns `True` for small integers because they reference the same cached object, not because of value equality.

**P14** — `*args`: variable positional arguments (tuple). `**kwargs`: variable keyword arguments (dict). `/`: marks parameters as positional-only. `*`: marks parameters as keyword-only. Use for flexible APIs, argument forwarding, and enforcing calling conventions.

**P15** — Context managers (`with`) guarantee cleanup via `__exit__` even on exceptions. Class-based: define `__enter__` (setup, return resource) and `__exit__` (cleanup, exception handling). `@contextmanager`: decorator using `yield` for simpler setup/teardown. Example: database transaction, lock acquisition, temporary directory.

**P16** — Type hinting provides static annotations for tooling. `Union[A, B]`/`Optional[T]`: multiple types. `Literal["a"]`: exact value constraint. `TypeVar`: generic variables with constraints. `Protocol`: structural subtyping (duck typing). `mypy`/`pyright` parse annotations, check types statically, and catch bugs before runtime without affecting execution.

**P17** — `__repr__`: unambiguous, developer-focused. `__str__`: readable, user-focused. `__eq__`: value equality. `__hash__`: hashability. Defining `__eq__` without `__hash__` sets `__hash__ = None`, making instances unhashable (breaks sets/dicts). `__getattr__`: fallback when attribute missing. `__getattribute__`: called for every access (dangerous, can cause recursion).

**P18** — Descriptors intercept attribute access via `__get__`, `__set__`, `__delete__`. `property` uses descriptors to run getters/setters. `classmethod`/`staticmethod` are descriptors that modify `self`/`cls` binding. Under the hood, class attributes that are descriptor instances have their methods called during attribute lookup on the owner class.

**P19** — Relative imports (`from . import mod`) resolve relative to the package. Absolute imports (`from pkg import mod`) resolve from `sys.path`. `PYTHONPATH` appends to `sys.path`. `__init__.py` marks directories as packages. Namespace packages allow splitting packages across paths without `__init__.py`. Finders locate modules in `sys.path`; loaders compile/load them into code objects. `importlib` standardizes this.

**P20** — `dataclasses` (built-in) generates `__init__`, `__repr__`, `__eq__`. `attrs` (third-party) offers more features (validators, converters, slots). `Pydantic` adds runtime validation, serialization, type coercion, and async support. `__post_init__` runs after `__init__` for validation. `field(default_factory=list)` avoids mutable default arguments. `frozen=True` creates immutable dataclasses. Choose Pydantic when you need runtime validation, serialization/deserialization, or complex type coercion for API/ORM models.
