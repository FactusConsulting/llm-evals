JS1 — `var` is function-scoped and hoisted with initialization (`undefined`). `let`/`const` are block-scoped, hoisted but in a Temporal Dead Zone (TDZ) until declaration. `const` cannot be reassigned. Hoisting: declarations are moved to the top of their scope during compilation, but initializations remain in place.

JS2 — The event loop continuously checks the call stack. When empty, it processes the microtask queue (promises, `queueMicrotask`) until empty, then executes one macrotask (setTimeout, I/O, UI rendering), repeats. Microtasks run before the next macrotask, ensuring promise resolution isn't delayed by timers.

JS3 — A closure is a function that retains access to its lexical scope after creation. Example: `function makeCounter() { let i=0; return () => ++i; }`. Classic bug: `for (var i=0; i<3; i++) setTimeout(() => console.log(i), 0)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped), IIFE, or `setTimeout(..., 0, i)`.

JS4 — `Promise` represents async state. `async/await` is syntactic sugar for sequential promise handling. Error handling: `try/catch` with `await`, or `.catch()`/second `.then()` arg. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all, returning `{status: 'fulfilled'|'rejected', value|reason}` for each.

JS5 — `interface` defines object contracts, supports declaration merging, and only describes objects. `type` is broader: primitives, unions, intersections, tuples, mapped types. Use `interface` for APIs/classes, `type` for unions/utility types. Discriminated unions: types sharing a literal property (discriminant) enabling type narrowing via `switch`/`if`.

JS6 — Prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar: `class` defines a constructor and attaches methods to `prototype`; `extends` sets up the prototype chain via `Object.setPrototypeOf`.

JS7 — `this` is determined by call site. Priority: 1. `new` (new instance), 2. Explicit (`call`/`apply`/`bind`), 3. Implicit (`obj.method()`), 4. Default (`global`/`undefined`). Arrow functions use lexical `this`. `bind()` returns a new function with fixed `this`. You cannot re-bind it; calling `bind` on a bound function returns a new bound function, but the original binding persists.

JS8 — `WeakRef` holds a weak reference that doesn't prevent GC. `FinalizationRegistry` runs a callback when the target is collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the engine can track when they're GC'd; if keys were primitives, entries would never be cleaned up, causing leaks.

JS9 — V8 optimizes via: Hidden Classes (shape optimization for fast property access), Inline Caching (caches hidden class pointers at call sites), and Deoptimization (reverts to slower code when assumptions break). Patterns causing deopt: dynamic property addition/deletion, type changes, `delete`, `with`, `eval`, modifying `arguments`.

JS10 — Tree-shaking removes unused exports at build time. Works with ES Modules because `import`/`export` are static and parse-time, enabling static analysis. CommonJS uses dynamic `require()`, evaluated at runtime, so bundlers can't safely determine dependencies without executing code.

JS11 — `null` is intentional absence; `undefined` is uninitialized/missing. `==` coerces (`null == undefined` → true); `===` checks type+value. `??` returns right operand if left is `null`/`undefined`. `?.` safely accesses nested properties, short-circuiting on `null`/`undefined` instead of throwing.

JS12 — `map` transforms, `filter` selects, `reduce` accumulates. `reduce` with initial value prevents type errors on empty arrays and defines accumulator type. `flatMap` maps then flattens one level; useful for transforming arrays and flattening results in a single pass (e.g., splitting strings into arrays).

JS13 — Template literals use `` ` `` and `${expr}` for interpolation/multi-line. Tagged templates call a function with an array of string parts and interpolated values. Example: `html` function that escapes values or builds parameterized SQL queries safely.

JS14 — Destructuring unpacks arrays/objects. Object: `{a, b: renamed} = obj`. Array: `[a, b] = arr`. Defaults: `a = 1`. Rest: `const {a, ...rest} = obj` collects remaining keys. Works in function parameters too. Rest operator gathers remaining elements/properties into a new array/object.

JS15 — `for...in` iterates enumerable string keys (including inherited). `for...of` iterates iterable values (arrays, strings, maps). Avoid `for...in` on arrays: it iterates keys, not values, includes prototype properties, and doesn't guarantee order.

JS16 — Generics parameterize types. Constraints: `function id<T extends string | number>(arg: T): T`. Conditional types: `type NonNullable<T> = T extends null | undefined ? never : T`. `infer`: extracts types in contexts: `type ElementType<T> = T extends (infer U)[] ? U : T`.

JS17 — CJS: synchronous `require`/`module.exports`, runtime evaluation, object-based. ESM: static `import`/`export`, async, tree-shakeable. Node.js supports both via `.cjs`/`.mjs` or `"type": "module"` in `package.json`, which treats `.js` as ESM. ESM is the modern standard.

JS18 — Structural typing: compatibility based on shape, not names. Excess property checks apply only to object literals assigned to variables/interfaces, not function arguments. `extends` checks assignability. `satisfies` checks if expression matches a type without widening, preserving the original type. Variance: `in` (contravariant, parameters), `out` (covariant, returns), `in out` (bivariant). TS 4.7+ refines these with stricter defaults.

JS19 — `Proxy` wraps objects to intercept traps (get, set, apply, etc.). `Reflect` provides default behavior mirroring traps. Example: validation proxy that checks types on assignment using `Reflect.set(target, prop, value, receiver)`. Enables reactive data binding, logging, or immutable state.

JS20 — `SharedArrayBuffer` shares memory between main thread and Web Workers. `Atomics` provides atomic ops for synchronization. Communication: write to SAB, use `Atomics.wait(sab, index, value)` (blocks until value changes) and `Atomics.notify(sab, index, count)` (wakes waiters). Guarantees sequential consistency for atomic ops; complex data requires explicit lock/semaphore patterns.

B1 — `$@` expands to separate quoted arguments; `$*` expands to a single string joined by IFS. `"$@"` preserves each argument as a distinct word. `"$*"` joins them into one string. Always use `"$@"` for safe argument forwarding.

B2 — `set -e`: exit on command failure. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns rightmost non-zero exit code. Together, they prevent silent failures and undefined variable usage.

B3 — `$(command)` is POSIX-compliant, nestable, and preferred over legacy `` `command` ``. `$((expression))` is arithmetic expansion. `expr` is an external command, slower, and unsafe with special characters or negative numbers.

B4 — Process substitution `<(cmd)` creates a file descriptor (e.g., `/dev/fd/63`) for command output. Use when a command expects file paths but needs dynamic data. Example: `diff <(sort file1) <(sort file2)`.

B5 — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous: word splitting breaks on spaces/newlines, globbing expands patterns, and `ls` output is unreliable for parsing.

B6 — `<<EOF` passes multi-line stdin. `<<<` passes a single string as stdin. `<<-EOF` strips leading tabs (not spaces) from heredoc lines, allowing clean indentation in scripts.

B7 — `cmd > file 2>&1`: stdout → file, then stderr → stdout (file). `cmd 2>&1 > file`: stderr → terminal (original stdout), then stdout → file. `cmd &> file`: bash shorthand for `> file 2>&1`. Redirections evaluate left-to-right, causing the first two to differ.

B8 — ```bash
lock_dir="/tmp/mylock"
cleanup() { rm -rf "$lock_dir"; }
trap cleanup EXIT INT TERM
if ! mkdir "$lock_dir" 2>/dev/null; then echo "Locked"; exit 1; fi
# work here
```
`mkdir` is atomic on POSIX filesystems, preventing race conditions. `trap` ensures cleanup on normal exit or signals.

B9 — Single quotes: literal, no expansion. Double quotes: allow `$`, `` ` ``, `\`, `!` expansion. No quotes: word splitting and globbing occur. Example: `var="a b"; echo $var` → `a b`; `echo "$var"` → `a b`; `echo '$var'` → `$var`.

B10 — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin: supports `&&`/`||`/`=~`, no word splitting/globbing on RHS, safer. `[ ]` is POSIX: requires spaces, limited operators, subject to splitting.

B11 — `$?`: exit status of last command. `$$`: current shell PID. `$!`: last background job PID. `$#`: number of positional parameters. Use cases: error handling, logging, job control, argument validation.

B12 — `func() { commands; }` or `function func { commands; }`. Return values: `return` sets exit code (0-255). For data, `echo` to stdout or use global variables. `return` is for status, not payload.

B13 — `PATH`: colon-separated directories bash searches for executables. Resolution: `PATH` → builtins → aliases. Builtin: compiled into shell (`cd`, `echo`). External: separate binary. Check: `type cmd` or `command -v cmd`.

B14 — `trap 'handler' EXIT INT TERM ERR`. `EXIT` runs on normal/abnormal exit. `ERR` on non-zero exit. Signals queue (except `SIGKILL`/`SIGSTOP`). Handlers run synchronously; if multiple arrive, bash processes them in order after current command finishes.

B15 — `xargs` builds/execute commands from stdin, handles batching. Command substitution captures output. `xargs -0` + `find -print0` safely handles spaces/newlines. `xargs -P N` runs N processes in parallel.

B16 — Arrays: `arr=(a b c)`, `${arr[0]}`, `${arr[@]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${!assoc[@]}`. Associative requires `declare -A`, supports string keys, unordered, no numeric indexing.

B17 — `(...)` runs in a subshell (child process); variable changes are lost. `{ ...; }` runs in current shell; variables persist. Piping to `while` creates a subshell, losing variable updates. Fix: `while read; do ...; done < <(cmd)`.

B18 — `SIGINT`: interrupt (Ctrl+C). `SIGTERM`: graceful stop (catchable). `SIGHUP`: terminal hangup/reload. `SIGKILL`: force kill (uncatchable). Graceful shutdown: trap `TERM`, set flag, `wait` for children, cleanup. Use `trap` + `wait` to monitor background jobs.

B19 — `split -l 10000 log.log part_`; `find . -name 'part_*' -print0 | xargs -0 -P 4 -I {} bash -c 'process "$1"' _ {}`; merge outputs. Trade-offs: CPU vs I/O bound, splitting/merging overhead. Error propagation: check `$?`, use `set -o pipefail`, aggregate errors in temp files, exit non-zero if any fail.

B20 — `exec` replaces the shell or redirects FDs. `exec 3>file` opens FD 3. `exec 3>&-` closes it. Coprocess: `coproc cmd` creates bidirectional pipe, runs `cmd` in background, exposes `CMD_PID` and `CMD` FDs. Use for persistent IPC without explicit pipe management.

PS1 — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console, bypassing the pipeline. Distinction matters: `Write-Host` breaks automation, piping, and redirection.

PS2 — Pipeline streams objects. `ForEach-Object` processes each object in real-time (streaming, memory-efficient). `foreach` statement iterates over a collection in memory (faster for known collections). Use `ForEach-Object` for streaming/large data, `foreach` for performance with in-memory collections.

PS3 — `[PSCustomObject]`: ordered, strongly typed, pipeline-friendly, supports methods. `[hashtable]`: unordered, key-value, slower, less pipeline-friendly. Convert: `[PSCustomObject]@{a=1}` or `@{a=1} | ForEach-Object {[PSCustomObject]$_}`. Use custom objects for structured data, hashtables for dynamic config.

PS4 — Terminating errors stop execution (`throw`, `Stop-Process`). Non-terminating continue (`Get-Item` on missing file). `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors. Use `-ErrorAction Stop` to convert non-terminating to terminating.

PS5 — Splatting: `@params` passes a hashtable's keys as named parameters. Example: `Get-ChildItem @opts`. Differs from passing a hashtable as a single parameter: splatting expands keys to match command parameters, enabling dynamic invocation.

PS6 — `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` creates an interactive session. Uses WS-Management (WinRM) by default. PowerShell 7+ supports SSH remoting via `Enable-PSRemoting -Transport SSH`.

PS7 — Everything is an object. `$result += "one"` creates an array. `return $result` returns `Object[]`. `$x.GetType().Name` → `Object[]`. If 0 items, returns `$null`. Correct pattern: avoid `+=`, use `[array]$result = @()` or output objects directly without collecting.

PS8 — `[scriptblock]` is a code container; functions are named scriptblocks with parameters. Pass to remote: `Invoke-Command -ScriptBlock $sb -ArgumentList $args`. Double-hop: auth fails when remoting to B then to C. Solve with CredSSP (less secure), Kerberos delegation, or pass data via `-ArgumentList`/`-FilePath` to avoid second hop.

PS9 — `@()` forces array. `[array]` casts. Single result into array: `@($result)`. Indexing `$null` → `$null`. Indexing empty array `@()[0]` → `$null`. `@()` prevents scalar/array inconsistency in pipelines.

PS10 — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (collection contains value), `-in` (value in collection). Case-sensitive: `-ceq`, `-clike`, `-cmatch`. `-contains` checks `$col -contains $val`. `-in` checks `$val -in $col`. `-match` returns match object or `$null`.

PS11 — Module: collection of commands. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies, version). Binary: compiled `.dll`. `Import-Module` loads module, runs manifest/script, exports commands. Auto-imports on command use.

PS12 — Interpolation: `"Hello $name"`. `"..."` expands variables/expressions. `'...'` literal. Expressions: `"Value: $(Get-Date)"`. Here-string: `@"..."@` for multi-line, preserves formatting, supports interpolation.

PS13 — `Get-Member` explores object members. Properties: data. Methods: actions. NoteProperties: added properties. `Select-Object`: projects/selects properties. `Where-Object`: filters objects. Pipeline: `Get-Process | Select-Object Name, CPU | Where-Object CPU -gt 100`.

PS14 — Classes (v5+): `class MyClass { [string]$Prop; MyClass([string]$p) { $this.Prop = $p } }`. Differ from C#: no access modifiers (public by default), no interfaces, single inheritance, limited static members, no constructor overloads easily. Use classes for models, functions for logic.

PS15 — `CmdletBinding()` enables advanced features. `SupportsShouldProcess`: enables `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: sets default param set. `ValueFromPipeline`: binds pipeline input. `Begin`: runs once. `Process`: per pipeline object. `End`: after pipeline finishes.

PS16 — Providers abstract data stores as drives. `Get-ChildItem` works on `HKLM:`, `Cert:`, `Env:`. Registry accessed like filesystem: `Get-ChildItem HKLM:\SOFTWARE`. Providers translate commands to provider-specific operations.

PS17 — Runspaces: lightweight execution contexts. `[runspace]`: single thread. `[runspacepool]`: manages multiple runspaces. `[powershell]`: wraps runspace for commands. `ForEach-Object -Parallel` (v7+): uses runspace pool automatically, thread-safe, serialization overhead. Manual runspace: more control, better for complex state, verbose.

PS18 — PSScriptAnalyzer: linter for PS. Enforces rules (naming, performance, security). Severity: error, warning, info. Custom rules: C# or PS scripts. Suppress: `#pragma disable` or config file. CI/CD: run `Invoke-ScriptAnalyzer`, fail on errors.

PS19 — `$using:` serializes local variable into remote/session context. `-ArgumentList` passes values as parameters. Serialization limits: CLIXML depth (default 64), breaks on circular refs/deep objects. Complex objects lose methods/types. Use `-ArgumentList` for simple data, `$using:` for quick access, monitor size/depth.

PS20 — DSC: declarative config management. Configurations: desired state code. Resources: building blocks (File, Service, Package). LCM: agent that applies config, checks drift. WinPS DSC: Windows-only, MOF. PS7 DSC: cross-platform, JSON, integrated with `PackageManagement`. Replaced/supplemented by Terraform, Ansible, ARM/Bicep, but DSC remains for Windows/PS ecosystems.
