JS1 — `var` is function-scoped and hoisted with `undefined`. `let`/`const` are block-scoped, hoisted but in a Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment. Hoisting is JS moving declarations to the top of their scope during compilation before execution.

JS2 — The event loop continuously checks the call stack. When empty, it processes the microtask queue (promises, `queueMicrotask`), then renders, then processes one macrotask (setTimeout, I/O, UI events). Microtasks run to completion before the next macrotask, ensuring promise resolution isn't delayed.

JS3 — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: counter factory. Classic bug: `var i` in `for` loops shares one reference, causing `setTimeout` callbacks to log the final value. Fix: use `let` (block scope), IIFE, or pass `i` as a third argument to `setTimeout`.

JS4 — `Promise` represents async completion/failure. `async/await` is syntactic sugar for sequential promise handling. Error handling: `try/catch` with `await`, or `.catch()`/second `.then()` arg. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all, returning `{status, value/reason}` per promise.

JS5 — `interface` defines object shapes, supports merging/extension, no implementation. `type` is broader (unions, intersections, primitives, mapped types). Use `interface` for APIs/contracts, `type` for unions/intersections/utility types. Discriminated unions: types sharing a literal property used to narrow at runtime (`if (t.kind === 'a')`).

JS6 — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates an object with `proto` as its prototype. ES6 classes are syntactic sugar: `class A extends B` sets `A.prototype.__proto__ = B.prototype`, and `super` calls parent constructor/methods.

JS7 — `this` is dynamically bound by call site. Priority: 1. `new` (new instance), 2. Explicit (`call`/`apply`/`bind`), 3. Implicit (`obj.method()`), 4. Default (`window`/`undefined`). Arrow functions use lexical `this`. `bind()` returns a new function with permanently bound `this`; it cannot be rebound.

JS8 — `WeakRef` holds a non-owning reference to an object, allowing GC. `FinalizationRegistry` runs a callback when the target is collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the engine can track GC; when a key is collected, the entry is automatically removed.

JS9 — V8 optimizes via hidden classes (shape tracking for fast property access), inline caching (caches shape/type at call sites), and deoptimization (reverts to slower code when assumptions break). Deopt triggers: dynamic property addition, type changes, `delete`, `with`, or `arguments` usage.

JS10 — Tree-shaking removes unused exports at build time. Works with ES modules because `import`/`export` are static and parse-time, enabling static analysis. CommonJS uses dynamic `require()`, evaluated at runtime, so bundlers can't safely analyze dependencies or eliminate dead code.

JS11 — `null` is intentional absence; `undefined` is uninitialized. `==` coerces (`null == undefined` → true); `===` checks type+value (false). `??` returns right operand only if left is `null`/`undefined`. `?.` safely accesses nested properties, short-circuiting on nullish values instead of throwing.

JS12 — `map()` transforms, `filter()` selects, `reduce()` accumulates to a single value. `reduce()` with initial value prevents errors on empty arrays and sets accumulator type. `flatMap()` maps then flattens one level; useful for transforming arrays and flattening results in one pass.

JS13 — Template literals use backticks, support `${expr}` interpolation and multi-line. Tagged templates call a function with an array of string parts and interpolated values. Example: `html` tag function that escapes HTML or builds parameterized SQL queries safely.

JS14 — Destructuring unpacks arrays/objects into variables. Object: `{a, b}` or `{a: x}`. Array: `[a, b]`. Defaults: `{a = 1}`. Rest: `{...rest}` collects remaining. Works in assignments, parameters, and function returns. Prevents repetitive property access.

JS15 — `for...in` iterates enumerable string keys (including inherited), meant for objects. `for...of` iterates iterable values (arrays, strings, maps), meant for collections. Avoid `for...in` on arrays: order isn't guaranteed, includes inherited properties, and iterates keys not values.

JS16 — Generics (`<T>`) enable type-safe reuse. Constraints: `T extends SomeType` limits T. Conditional types: `T extends U ? X : Y` for branching. `infer` extracts types in contexts. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T`.

JS17 — CJS (`require`/`module.exports`) is synchronous, runtime-evaluated, object-based. ESM (`import`/`export`) is static, async, tree-shakeable, native in browsers/Node. Node uses `.mjs` or `"type": "module"` in `package.json` to treat `.js` as ESM. `"type": "module"` switches default module resolution.

JS18 — Structural typing: compatibility based on shape, not names. Excess property checks apply only to object literals assigned directly to a type to catch typos. `extends` defines assignability. `satisfies` validates a value against a type without widening it. Variance: `in` (contravariant params), `out` (covariant returns), `in out` (bivariant).

JS19 — `Proxy` wraps objects to intercept operations (get, set, apply, has, etc.). `Reflect` mirrors traps and provides default behavior. Example: validation proxy that throws on invalid `set`, or reactive proxy that tracks reads/writes for UI binding.

JS20 — `SharedArrayBuffer` is a fixed-length binary buffer shared across threads. `Atomics` provides atomic ops for synchronization. Workers communicate via SAB writes. `Atomics.wait` blocks until value changes; `Atomics.notify` wakes threads. Guarantees: sequential consistency for atomics, implicit memory barriers.

B1 — `$@` expands to separate quoted words (`"$1" "$2"`). `$*` expands to a single string joined by IFS (`"$1 $2"`). `"$@"` preserves each argument individually. `"$*"` joins them into one string. Use `"$@"` for safe argument forwarding.

B2 — `set -e`: exit on command failure. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the exit status of the last failed command. Together: strict, fail-fast scripting.

B3 — `$(command)` is modern, nestable, preferred. `` `command` `` is legacy, harder to read/nest. `$((expression))` is bash arithmetic expansion (fast, built-in). `expr` is an external command, slower, different syntax.

B4 — Process substitution `<(cmd)` creates a file descriptor (e.g., `/dev/fd/63`) pointing to `cmd`'s output. Used when commands expect files but need dynamic data. Example: `diff <(sort file1) <(sort file2)`.

B5 — Use `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous: word splitting breaks on spaces, globbing expands patterns, and `ls` parsing is fragile and locale-dependent.

B6 — Here document `<<EOF` feeds multi-line stdin. Here string `<<<` feeds a single string. `<<-EOF` strips leading tabs (not spaces) from the delimiter line and heredoc content for clean indentation.

B7 — `cmd > file 2>&1`: stdout → file, then stderr → wherever stdout points (file). `cmd 2>&1 > file`: stderr → terminal (where stdout was), then stdout → file. `cmd &> file`: bash shorthand for `> file 2>&1`. Order matters: redirections evaluate left-to-right.

B8 — `mkdir` is atomic on POSIX, preventing race conditions.
```bash
lock() {
  local lockdir="/tmp/mylock.$$"
  trap 'rmdir "$lockdir" 2>/dev/null' EXIT INT TERM
  if ! mkdir "$lockdir" 2>/dev/null; then
    echo "Locked" >&2; exit 1
  fi
  # critical section
}
```

B9 — Single quotes: literal, no expansion. Double quotes: allow `$`, `` ` ``, `\`, `!`. No quotes: subject to word splitting and globbing. Example: `var="a b"; echo '$var'` → `$var`; `echo "$var"` → `a b`; `echo $var` → `a b` (split into two args).

B10 — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash keyword: supports `&&`, `||`, `=~`, no word splitting/globbing on RHS, safer. `[` is POSIX builtin/external, stricter, requires `]` terminator.

B11 — `$?`: exit status of last command. `$$`: PID of current shell. `$!`: PID of last background process. `$#`: number of positional parameters.

B12 — `func() { commands; }` or `function func { commands; }`. Return values: `return <int>` (exit code 0-255), or `echo`/`printf` to stdout and capture with `$()`. Bash functions don't return complex data directly.

B13 — `PATH`: colon-separated directories bash searches for executables. Resolves: builtins first, then PATH. Builtin: compiled into shell (`cd`, `echo`). External: separate binary. Check with `type cmd` or `command -v cmd`.

B14 — `trap 'cleanup' EXIT INT TERM ERR`. Signals are queued and handled sequentially. `EXIT` runs on shell exit. `ERR` runs on command failure. Multiple signals: bash processes one at a time; pending signals execute after the current handler finishes.

B15 — `xargs` builds/executes commands from stdin. Command substitution runs first, stores result. `xargs -0` + `find -print0` handles spaces/newlines safely. `xargs -P N` runs N processes in parallel.

B16 — Indexed: `arr=(a b c)`, `${arr[0]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${!assoc[@]}`. Syntax differs in declaration and key access. Associatives require bash 4+.

B17 — `(...)`: subshell (forks), changes don't affect parent. `{ ...; }`: group command (same shell), changes persist. Piping to `while` creates a subshell, losing variable changes. Fix: `while ... done < <(cmd)` or reverse pipe.

B18 — `SIGINT` (Ctrl+C, interrupt), `SIGTERM` (graceful stop), `SIGHUP` (terminal close), `SIGKILL` (force kill, uncatchable). Handle graceful shutdown: trap `TERM`, `wait` for children, cleanup, exit. Use `trap` + `wait` for background job management.

B19 — Split log: `split -l 10000 log.log part_`. Parallel process: `find . -name "part_*" -print0 | xargs -0 -P 4 -I {} bash process.sh {}`. Merge: `cat part_* > merged.log`. Trade-offs: CPU vs I/O, split/merge overhead. Error propagation: check `$?`, use `set -o pipefail`, log failures, or use a wrapper that aggregates exit codes.

B20 — `exec` replaces the shell process or redirects file descriptors. `exec 3>file` opens fd 3, `exec 3>&-` closes it. Coprocess: `coproc cmd` runs `cmd` in background, connects I/O to `COPROC` array. Use for persistent bidirectional background processes.

PS1 — `Write-Output` sends objects down the pipeline. `Write-Host` writes directly to the console (bypasses pipeline, breaks automation). Matters because pipelines expect structured objects, not formatted text.

PS2 — Pipeline streams objects between cmdlets. `ForEach-Object`: processes each object in real-time (streaming, memory efficient). `foreach` statement: iterates over a collection in memory (faster for known collections). Use `ForEach-Object` for streaming/large data, `foreach` for performance.

PS3 — `[PSCustomObject]`: strongly typed, ordered, pipeline-friendly, supports methods/properties. `[hashtable]`: unordered, untyped, legacy. Convert: `[PSCustomObject]@{Key="Val"}`. Use PSCustomObject for modern pipelines, hashtable for dynamic key-value.

PS4 — Terminating errors stop execution; non-terminating continue. `-ErrorAction` overrides `$ErrorActionPreference` (SilentlyContinue, Stop, Continue, Inquire). `try/catch` only catches terminating errors.

PS5 — Splatting: `@params` passes a hashtable's keys as named parameters. `func @params`. Differs from passing a hashtable as a single parameter: splatting expands to individual arguments. Example: `Get-ChildItem @dirParams`.

PS6 — `Invoke-Command -ComputerName`: one-off remote execution. `Enter-PSSession`: interactive remote session. Uses WS-Management (WinRM) by default. PS 7+ supports SSH remoting via `New-PSSession -HostName`.

PS7 — Pipeline outputs an array of strings. `$x.GetType().Name` is `Object[]`. When 0 items, returns `$null`. Correct pattern: use `[System.Collections.Generic.List[string]]::new()` or force array: `$result = ,@()`. Return `$result.ToArray()` or ensure consistent typing.

PS8 — `[scriptblock]`: code container, serializable, passable. Functions are named scriptblocks. Pass to remote: `Invoke-Command -ScriptBlock $sb -ArgumentList $args`. Double-hop: auth fails on second remoting hop. Solve with CredSSP (less secure) or `-ArgumentList` to pass data directly.

PS9 — `@()` forces array. `[array]` is a type constraint. Indexing `$null` throws. Indexing `@()` returns `$null`. `@()` ensures consistent array type, preventing pipeline enumeration issues.

PS10 — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive: `-ceq`, `-clike`, `-cmatch`. `-contains` checks collection membership. `-in` is reverse, more readable.

PS11 — Module: collection of functions/cmdlets. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies, version). Binary: compiled DLL. `Import-Module` loads module, searches `$env:PSModulePath`.

PS12 — `"..."` allows expansion (`$var`, `` ` ``). `'...'` literal. Expressions: `$($expr)`. Here-string: `@"..."@` for multi-line with expansion. `@'...'@` for multi-line literal.

PS13 — `Get-Member`: shows object members. Pipeline: `cmd | Get-Member`. Properties: data. Methods: actions. NoteProperties: added properties. `Select-Object`: picks properties/creates calculated. `Where-Object`: filters objects.

PS14 — Classes: v5+, C#-like. Limitations: no multiple inheritance, no interfaces (PS 7.2+ experimental), constructors must match signature, limited reflection. Use classes for complex data/models, functions for scripting/automation.

PS15 — `[CmdletBinding()]`: enables advanced function features. `SupportsShouldProcess`: enables `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: sets default param set. `ValueFromPipeline`: binds pipeline input. `Begin`/`Process`/`End`: pipeline processing blocks.

PS16 — Providers: abstract data stores as drives. `Get-ChildItem` works on `HKLM:`, `Cert:`, `Env:`. Registry accessed like filesystem: `cd HKLM:\SOFTWARE`, `Get-ChildItem`.

PS17 — Runspaces: lightweight execution environments. `[runspacepool]`: manages multiple runspaces. `ForEach-Object -Parallel` (PS 7+): uses runspace pool under the hood. Manual runspace: more control, thread-safe via synchronization, but complex. Parallel: easier, but serialization overhead.

PS18 — PSScriptAnalyzer: linting tool. Rules: predefined checks. Severity: Warning, Error, Info. Custom rules: PowerShell scripts. Suppress: `#pragma disable`, `.editorconfig`. CI/CD: run in pipeline, fail on errors, enforce standards.

PS19 — `$using:var`: serializes variable into remote/session context. `-ArgumentList`: passes values to scriptblock. `ForEach-Object -Parallel`: uses `$using:` or local scope. CLIXML limits: depth 64, can't serialize everything (e.g., events, some .NET objects). Use `-ArgumentList` for simple types, `$using:` for remote scope.

PS20 — DSC: declarative config management. Configurations: desired state. Resources: building blocks (File, Service, Package). LCM: agent that applies config. WinPS DSC: XML-based, Windows-only. PS 7+: cross-platform, uses MOF/JSON, integrates with Ansible/Terraform. Modern replacement: Ansible, Terraform, Chef, Puppet.
