G1 — An array has a fixed size baked into its type and is a value type (copying copies all elements). A slice is a dynamic view over an underlying array, represented by a header containing a pointer, length, and capacity. When appending to a slice at capacity, Go allocates a new backing array (typically doubling capacity), copies existing elements, and returns a new slice pointing to it.

G2 — `var x int` declares a variable with explicit type and zero value; `x := 0` is a short variable declaration that infers type. `:=` cannot be used outside functions, when redeclaring an existing variable without introducing a new one, or in type/switch statements where no new variables are introduced.

G3 — A goroutine is a lightweight, multiplexed execution context managed by the Go runtime (~2KB initial stack vs OS thread's MBs). The GMP model: G = goroutine, M = OS thread, P = processor (run queue/context). The scheduler multiplexes Gs onto Ms using Ps, enabling efficient concurrent execution without blocking OS threads.

G4 — Channels are typed conduits for safe goroutine communication. Unbuffered channels block both sender and receiver until both are ready. Buffered channels have a capacity; sends block only when full, receives block only when empty. Sending to a full buffered channel blocks until a receiver consumes an element.

G5 — `context` carries deadlines, cancellation signals, and request-scoped values across API boundaries. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
client.Do(req) // automatically cancels if timeout hits
```

G6 — Go uses implicit interface satisfaction (duck typing); types satisfy interfaces by implementing methods, without `implements` keywords. The empty interface `interface{}` (alias `any` in Go 1.18+) matches any type. Powerful for generic-like flexibility, but dangerous because type assertions can panic and compile-time safety is lost.

G7 — The code has a data race: `ready` is written/read without synchronization, violating Go's happens-before rules. The compiler/CPU may reorder, and `data` may not be visible. Fix with `sync/atomic` or a channel:
```go
var ready atomic.Bool
var data string
go func() { data = "hello"; ready.Store(true) }()
for !ready.Load() {}
fmt.Println(data)
```

G8 — `sync.Mutex` provides exclusive access; `sync.RWMutex` allows concurrent readers or a single writer. `sync.Map` is optimized for read-heavy workloads or known key sets, avoiding mutex contention but incurring higher per-operation overhead and memory usage. Use `map+Mutex` for general cases; `sync.Map` only when profiling shows contention benefits.

G9 — `go.mod` declares direct dependencies, Go version, and replace directives. `go.sum` stores cryptographic hashes of exact dependency versions. `go mod tidy` removes unused deps, adds missing ones, and updates `go.sum`. MVS (Minimum Version Selection) resolves transitive dependencies by selecting the highest compatible version that satisfies all direct/transitive constraints.

G10 — `defer` schedules a function call to run after the surrounding function returns. Multiple defers execute in LIFO order. Classic gotcha: in loops, deferred closures capture the loop variable by reference (pre-Go 1.22), causing all defers to see the final value. Fix by passing the variable as an argument or using Go 1.22+ loop scoping.

G11 — A pointer holds the memory address of a value. Zero value is `nil`. Create a pointer to a struct literal with `&MyStruct{Field: value}`. Pointers enable mutation and avoid copying large structs.

G12 — `init()` runs automatically before `main()`, once per package. Packages initialize in dependency order. A package can have multiple `init()` functions; they execute in declaration order. Used for side effects like registration or configuration.

G13 — `make` initializes built-in reference types (slice, map, channel), returning a typed value (not pointer) with set len/cap. `new` allocates zeroed memory for any type and returns a pointer. Use `make` for types that require runtime initialization.

G14 — Errors implement `error` interface (`Error() string`). Idiomatic: `if err != nil { return err }`. `errors.Is` checks if an error matches a target in the unwrapped chain. `errors.As` checks type and extracts the value. `==` only checks direct equality, ignoring wrapped errors.

G15 — Composite types: `map` (hash table), `slice` (dynamic array), `channel` (concurrency), `struct` (fields). Zero values: `map=nil`, `slice=nil/empty`, `channel=nil`, `struct` has zeroed fields. All require initialization (`make`/`new`/literal) before use except structs.

G16 — A race occurs when concurrent goroutines access shared data without synchronization, with at least one write. `-race` flag instruments runtime to detect conflicting accesses. Fix with `sync.Mutex` (lock around critical section) or channels (serialize access). Example: `var mu sync.Mutex; mu.Lock(); counter++; mu.Unlock()`

G17 — `select` blocks until one channel case is ready, then executes it. Unlike `switch`, it evaluates channel operations asynchronously. If multiple cases ready, one is chosen pseudo-randomly. Timeout: `case <-time.After(d):` or `case <-ctx.Done():`.

G18 — Escape analysis determines stack vs heap allocation. Escapes if: address taken, size unknown at compile time, escapes function scope, or returned as pointer. Inspect with `go build -gcflags="-m"`. Matters because heap allocations trigger GC, impacting latency and throughput.

G19 — `reflect` inspects/manipulates types/values at runtime. `reflect.Type` holds type metadata; `reflect.Value` holds value + operations. Costs: slow, bypasses compile-time checks, allocates. Justified in frameworks/serialization when code generation isn't feasible. Prefer code gen for performance-critical paths.

G20 — `go:embed` embeds static files/dirs into the binary at compile time. Works with patterns (`//go:embed file.txt` or `//go:embed dir/`). Returns `embed.FS` implementing `io/fs.FS`. Limitations: only compile-time static assets, no runtime generation, pattern syntax restricted. Enables zero-dependency static file serving.

R1 — Ownership ensures memory safety without GC. Rules: 1) Each value has exactly one owner. 2) Only one owner at a time. 3) Owner drops value when out of scope. Prevents leaks/double-frees by enforcing lifetime tracking at compile time.

R2 — `String` is heap-allocated, growable, and owned. `&str` is a borrowed, fixed-size reference to UTF-8 data. Use `String` when owning/modifying; use `&str` in signatures for flexibility (accepts both `String` and string literals) and zero-copy slicing.

R3 — Borrowing grants access without transferring ownership. Rules: 1) Either one `&mut` or many `&` references. 2) References must be valid (no dangling). 3) No aliasing mutable references. Enforced by the borrow checker to prevent data races and use-after-free.

R4 — `Result<T, E>` represents success/failure; `Option<T>` represents `Some(T)` or `None`. `?` unwraps `Ok`/`Some` or returns early on `Err`/`None`. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — `Box<T>`: heap allocation, single owner, moves data. `Rc<T>`: reference counting, single-threaded shared ownership. `Arc<T>`: atomic reference counting, thread-safe shared ownership. Use `Box` for large/recursive types, `Rc` for shared read-only single-threaded, `Arc` for cross-thread sharing.

R6 — Traits define behavior; unlike Go, they require explicit `impl Trait for Type`. `dyn Trait` creates a trait object with dynamic dispatch (vtable), enabling heterogeneous collections. `T: Trait` uses static dispatch/monomorphization, generating type-specific code with zero runtime overhead.

R7 — Fails because the compiler can't infer which input lifetime applies to the output. Fix by annotating lifetimes:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```
Both inputs share lifetime `'a`, guaranteeing the returned reference lives at least that long.

R8 — `Send`: types safe to transfer ownership across threads. `Sync`: types safe to share references across threads. `Rc<T>` isn't `Send`/`Sync` due to non-atomic ref count. `Arc<T>` uses atomic ref counting, making it `Send`+`Sync` (if `T` is), enabling safe concurrent sharing.

R9 — `async/await` compiles to a state machine implementing `Future`. `Future::poll` advances execution. The executor (e.g., Tokio) drives futures, handles I/O, and schedules tasks. Differs from Go: Go bundles async runtime + scheduler; Rust separates the `Future` trait from the executor, requiring explicit runtime for I/O/concurrency.

R10 — `unsafe` bypasses compile-time safety checks. Three actions: dereference raw pointers, call `unsafe` functions, implement `unsafe` traits, access/modify `static mut`. Justified when interfacing with C, implementing abstractions, or performance-critical code where safety is provably maintained.

R11 — Pattern matching exhaustively evaluates values. `match` requires all arms; `if let` is shorthand for one arm + optional `else`. Compiler enforces exhaustiveness in `match` (warns/errors if missing), but `if let` doesn't require it. Enables safe, expressive data decomposition.

R12 — `Vec<T>`: heap-allocated, growable array. `[T; N]`: fixed-size, usually stack-allocated. When `Vec` exceeds capacity, it allocates a larger buffer (typically ~1.5x-2x), moves elements, drops old buffer, and updates pointer/len/cap.

R13 — Rust enums are algebraic data types: named variants that can carry data. Unlike C/Java, they're sum types with pattern matching. `Option<T>` = `Some(T)` or `None`. Rust has no `null`; forces explicit handling, eliminating null pointer dereferences.

R14 — `impl` blocks define methods. `&self`: borrows, immutable. `&mut self`: mutable borrow, exclusive access. `self`: takes ownership, consumes. Associated functions (e.g., `String::new()`) don't take `self`, acting like constructors/static methods.

R15 — `#[derive]` auto-implements common traits. Examples: `Debug`, `Clone`, `PartialEq`, `Serialize`. Can't derive if: fields lack the trait, custom logic needed, or trait requires unsafe/custom implementation (e.g., `Drop`, `Fn`).

R16 — `Cow<'a, T>` (Clone-on-Write) holds either borrowed `&'a T` or owned `T`. Useful when a function may return borrowed or owned data. Avoids allocation if input already matches desired form; only clones when mutation/ownership is required.

R17 — `mod` declares a module, `use` imports names, `pub` exposes. File system: `mod.rs` or `module/mod.rs` maps to `mod module`. Rust 2018 changed path resolution (`crate::`, `self::`, `super::`), made `use` paths relative to crate root, and removed `extern crate`.

R18 — `Pin<T>` guarantees a value won't be moved in memory. Needed for self-referential structs and async/await (futures may hold references to their own fields). `Unpin` is the default marker for types that can be safely moved. `Pin` restricts movement to preserve internal reference validity.

R19 — Declarative macros (`macro_rules!`) generate code via pattern matching at call site. Procedural macros (`#[proc_macro_derive]`, `#[proc_macro_attribute]`, `#[proc_macro]`) run as Rust code during compilation. Hygiene ensures macros don't capture/leak caller identifiers; variables are scoped to expansion.

R20 — Zero-cost abstractions compile to efficient machine code. Iterators use loop unrolling and eliminate bounds checks. Generics use monomorphization (type-specific code, no vtable). Trait static dispatch enables direct calls. Achieves C-like performance while maintaining safety and ergonomics.
