### JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted with initialization to `undefined`. `let` and `const` are block-scoped and hoisted but reside in a Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment. Hoisting is the compiler behavior of moving declarations to the top of their scope during the creation phase.

**JS2** — The event loop continuously checks the call stack. When empty, it flushes the microtask queue (promises, `queueMicrotask`), then renders, then executes one macrotask (setTimeout, setInterval, I/O). Microtasks always run before the next macrotask, enabling promise resolution to interrupt pending timers.

**JS3** — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: a counter factory. Classic bug: `for (var i=0; i<3; i++) setTimeout(() => console.log(i), 0)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped), IIFE, or `setTimeout(..., 0, i)`.

**JS4** — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that pauses execution until the promise settles. Error handling: `try/catch` with `await`, or `.catch()`/second `.then()` arg. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all, returning `{status, value/reason}` per promise.

**JS5** — `interface` defines only shapes, supports declaration merging, and is ideal for object contracts/APIs. `type` is broader: unions, intersections, primitives, mapped types. Use `interface` for extensible object shapes, `type` for complex type algebra. Discriminated unions use a common literal property (e.g., `type: 'a' | 'b'`) to enable exhaustive type narrowing in `switch`/`if`.

**JS6** — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar: `class A extends B` sets `A.prototype.__proto__ = B.prototype`, and `new` binds `this` to the instance while calling the constructor.

**JS7** — `this` is determined at call time. Priority: 1. `new` (new instance), 2. explicit (`call`/`apply`/`bind`), 3. implicit (`obj.method()`), 4. default (`window` or `undefined` in strict mode). `bind()` returns a new function with `this` permanently locked. It cannot be re-bound.

**JS8** — `WeakRef` holds a reference that doesn't prevent GC. `FinalizationRegistry` runs a callback when weakly referenced objects are collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the GC can track them; when a key is collected, the entry is automatically removed, preventing memory leaks.

**JS9** — V8 optimizes via: Hidden Classes (shape optimization for fast property access), Inline Caching (caches shape info at call sites), and Deoptimization (reverts to slower code when assumptions break). Deopt patterns: dynamic property addition/removal, type changes in loops, `delete` on objects, `arguments` object, `with` statement.

**JS10** — Tree-shaking removes unused exports at build time. Works with ES Modules because imports/exports are static and analyzable at compile time. CommonJS uses dynamic `require()` at runtime, so bundlers can't statically determine dependencies, making dead code elimination ineffective.

**JS11** — `null` is intentional absence; `undefined` is unassigned. `==` coerces types (`null == undefined` is true); `===` checks type and value. `??` returns right operand only if left is `null`/`undefined`. `?.` safely accesses nested properties without throwing on `null`/`undefined`.

**JS12** — `map()` transforms, `filter()` selects, `reduce()` accumulates. `reduce()` with an initial value prevents type errors on empty arrays and defines the accumulator's type. `flatMap()` maps then flattens one level; useful for transforming elements while expanding them (e.g., splitting strings into arrays).

**JS13** — Template literals use backticks, support `${expr}` interpolation and multi-line strings. Tagged templates pass a function the template's string parts and substitution values. Example: `html` tag for escaping, or `sql` for parameterized queries: `sql`SELECT * FROM users WHERE id = ${id}`.

**JS14** — Destructuring unpacks values. Object: `{a, b}` or `{a: x}`. Array: `[a, b]`. Defaults: `{a = 1}`. Renaming: `{a: newName}`. Rest: `{...rest}` collects remaining properties/elements. Works in assignments, parameters, and loops.

**JS15** — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, maps). Avoid `for...in` on arrays because order isn't guaranteed, includes inherited properties, and is slower.

**JS16** — Generics use type parameters for reusability. Constraints: `T extends SomeType`. Conditional types: `T extends U ? X : Y`. `infer` extracts types in conditional contexts. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T;`.

**JS17** — CJS uses `require`/`module.exports` (synchronous, runtime, Node default historically). ESM uses `import`/`export` (static, async, browser/Node native). `"type": "module"` in `package.json` tells Node to treat `.js` as ESM. Node supports both via extensions (`.cjs`/`.mjs`) or config.

**JS18** — Structural typing checks compatibility by shape, not names. Excess property checks apply only to object literals assigned directly to variables/types, not to properties accessed later. `extends` checks assignment compatibility. `satisfies` checks type without widening, preserving the original type. Variance: `in` (contravariant, parameters), `out` (covariant, returns), `in out` (bivariant). TS 4.7+ improved variance checking and added `satisfies`.

**JS19** — `Proxy` wraps objects to intercept operations (get, set, apply, etc.). `Reflect` mirrors Proxy traps and provides default behavior. Example: validation proxy that throws on invalid `set`, or reactive data binding that tracks reads/writes via `get`/`set` traps.

**JS20** — `SharedArrayBuffer` shares memory between main thread and Web Workers. `Atomics` provides atomic ops for synchronization. Ordering: sequential consistency for atomic ops. `Atomics.wait` blocks until value changes or timeout. `Atomics.notify` wakes waiting threads. Requires cross-origin isolation headers.

### Bash

**B1** — `$@` preserves each argument as a separate word when quoted (`"$@"`). `$*` joins all args into one string using the first char of `IFS`. `"$@"` is safe for iteration; `"$*"` breaks on spaces/globs.

**B2** — `set -e`: exit on error. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the rightmost non-zero exit code.

**B3** — `$(command)` is modern, nestable, and readable vs legacy `` `command` ``. `$((expression))` is bash's built-in arithmetic expansion (fast, supports `**`, bitwise). `expr` is an external command (slower, limited operators).

**B4** — Process substitution `<(cmd)` creates a file descriptor (e.g., `/dev/fd/63`) with the command's output. Used when a command expects a file but needs dynamic input. Example: `diff <(sort file1) <(sort file2)`.

**B5** — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` breaks on spaces, globs, and newlines, and is unsafe.

**B6** — Here doc `<<EOF` provides multi-line input until the delimiter. Here string `<<<` provides a single line/string. `<<-EOF` strips leading tabs from the delimiter line for indentation.

**B7** — `cmd > file 2>&1`: stdout → file, then stderr → wherever stdout points (file). `cmd 2>&1 > file`: stderr → terminal (stdout's original location), then stdout → file. `cmd &> file` is bash shorthand for `> file 2>&1`. Redirections evaluate left-to-right, causing the difference.

**B8** — ```bash
LOCKDIR="/tmp/mylock_$$"
mkdir "$LOCKDIR" || { echo "Locked"; exit 1; }
trap 'rm -rf "$LOCKDIR"' EXIT INT TERM
# ... critical section ...
```
`mkdir` is atomic on POSIX, avoiding TOCTOU races. `trap` ensures cleanup on exit or signals.

**B9** — Single quotes: literal, no expansion. Double quotes: allow `$`, `` ` ``, `\`, `!`. No quotes: word splitting & globbing. Example: `var="hello world"; echo '$var'` → `$var`; `echo "$var"` → `hello world`; `echo $var` → `hello world` (but splits/globs).

**B10** — Check: `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin: supports `&&`, `||`, `=~`, no word splitting/globbing on RHS, safer for strings.

**B11** — `$?`: exit status of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: number of positional parameters.

**B12** — Define: `func() { ...; }` or `function func { ...; }`. Return values: `return` (exit code 0-255), stdout for data, or global variables. Best practice: use stdout or global vars for data.

**B13** — `PATH`: colon-separated dirs bash searches for executables. Resolves by checking `PATH`, then builtins, then aliases. Builtin: compiled into shell (no fork). External: separate binary. Check with `type` or `command -v`.

**B14** — `trap` registers handlers for signals/events. `trap 'cleanup' EXIT INT TERM ERR`. Handlers run in LIFO order. Multiple signals queue and execute sequentially.

**B15** — `xargs` builds/execute commands from stdin, handles quoting better, supports parallelism. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P N` runs N processes in parallel.

**B16** — Arrays: `arr=(a b c)`, `${arr[0]}`, `${#arr[@]}`, `for i in "${arr[@]}"; do`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${!assoc[@]}`. Assoc requires `declare -A`.

**B17** — Subshell `(...)` runs in child process; variable changes lost. Group `{ ...; }` runs in current shell; variables persist. Piping to `while` creates a subshell, so loop vars don't persist. Fix: process substitution `while ...; done < <(cmd)`.

**B18** — `SIGINT` (Ctrl+C, interrupt), `SIGTERM` (graceful stop), `SIGHUP` (terminal hangup/reload), `SIGKILL` (force kill, uncatchable). Graceful shutdown: trap `TERM`, kill background jobs (`kill 0`), wait, cleanup.

**B19** — ```bash
split -l 10000 log.txt log_part_
find . -name "log_part_*" -print0 | xargs -0 -P 4 -I {} bash -c 'process "$1" || echo "FAIL: $1" >> errors.log' _ {}
cat log_part_* > merged.log
```
Trade-offs: I/O vs CPU, splitting/merging overhead. Error propagation: capture exit codes, log failures, aggregate results.

**B20** — `exec` replaces the shell or redirects FDs. `exec 3>file` opens FD 3, `exec 3>&-` closes it. Coprocess: `coproc cmd` creates bidirectional pipe for async communication. Use for long-running daemons or interactive tools in scripts.

### PowerShell

**PS1** — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console (bypasses pipeline, breaks chaining). Matters because pipeline consumers expect objects, not console output.

**PS2** — Pipeline streams objects. `ForEach-Object` is a cmdlet, processes each object, supports `-Parallel` (v7). `foreach` statement is a language construct, iterates over in-memory collections, faster for large arrays, doesn't stream.

**PS3** — `[PSCustomObject]`: strongly typed, ordered, pipeline-friendly. `[hashtable]`: unordered, untyped, faster lookups. Convert: `[PSCustomObject]@{Key="Val"}` or `@{Key="Val"} | ForEach-Object {[PSCustomObject]$_}`.

**PS4** — Terminating errors stop execution (caught by `try/catch`). Non-terminating errors continue (logged to `$Error`). `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors.

**PS5** — Splatting: `@params` passes a hashtable's keys as named parameters. Cleaner, supports dynamic parameter sets, avoids long command lines. Differs from passing a hashtable as a single parameter (which treats it as one argument).

**PS6** — `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` creates an interactive session. Uses WS-Management (WinRM) by default; SSH remoting available in PS7+.

**PS7** — Pipeline returns an array of strings. `$x.GetType().Name` → `Object[]`. Returns 0 items → `$null`. Correct pattern: `[System.Collections.Generic.List[string]]::new()` or force array `$result = @($result)`.

**PS8** — `[scriptblock]` is anonymous code; function is named, supports parameters/pipeline. Pass to remote: `Invoke-Command -ScriptBlock $sb -ArgumentList $args`. Double-hop: auth delegation issue. Solve with `-ArgumentList` (preferred), CredSSP (insecure), or constrained remoting/SSH.

**PS9** — `@()` forces array. `[array]` is a type constraint. Indexing `$null` → error; empty array → `$null`. Force single result: `@($singleItem)`.

**PS10** — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (collection contains value), `-in` (value in collection). Case-sensitive: `-ceq`, `-clike`, etc. `-contains` checks collection; `-in` checks value (PS3+).

**PS11** — Module: collection of commands. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies). Binary: compiled DLL. `Import-Module` loads, checks paths, runs initialization.

**PS12** — Interpolation: `"..."` expands variables/expressions `${expr}`. `'...'` literal. Here-string: `@"..."@` for multi-line, supports interpolation.

**PS13** — `Get-Member` explores object members. Properties (data), Methods (actions), NoteProperties (custom). `Select-Object` projects/renames. `Where-Object` filters.

**PS14** — Classes (v5+): similar to C#, but single inheritance only, no interfaces, constructors use `param()` block, static members need `static` keyword. Use for complex data models, validation, or performance/type safety over functions.

**PS15** — `CmdletBinding()` enables advanced features. `SupportsShouldProcess`: enables `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: sets default param set. `ValueFromPipeline`: binds pipeline input. `Begin/Process/End`: init, per-item, cleanup blocks.

**PS16** — Providers abstract data stores. `Get-ChildItem` works on FileSystem, Registry (`HKLM:\`), Cert (`Cert:\`), Env (`Env:`). Registry accessed like FS: `Get-ChildItem HKLM:\SOFTWARE`.

**PS17** — Runspaces: execution environments. `[runspace]`: single thread. `[runspacepool]`: thread pool. `[powershell]`: wrapper. `ForEach-Object -Parallel` (v7+) uses runspace pool automatically. Manual: create pool, add commands, invoke, handle results. Thread safety: avoid shared state, use thread-safe collections.

**PS18** — PSScriptAnalyzer: linting tool. Rules: static analysis checks. Severity: warning/error/info. Custom rules: C#/PowerShell scripts. Suppress: `#pragma` or config. CI/CD: run in pipeline, fail on errors, enforce standards.

**PS19** — `$using:` serializes local variable into remote/session context. `-ArgumentList` passes values as parameters. Serialization limits: CLIXML depth (default 64); complex objects may fail. Use `-ArgumentList` for large/complex data, or temp files.

**PS20** — DSC: declarative config. Configurations: desired state definitions. Resources: building blocks (File, Package, etc.). LCM: agent that applies config. WinPS vs PS7: PS7 uses OpenDSC, cross-platform, modular. Replaced/supplemented by: Terraform, Ansible, Chef, Puppet, or native cloud IaC.
