G1 — A slice is a runtime descriptor containing a pointer to a backing array, length, and capacity. An array is a fixed-size value type where the size is part of the type. When you append to a slice that has reached capacity, the runtime allocates a new backing array (typically doubling capacity), copies existing elements, updates the slice header, and returns the new slice.

G2 — `var x int` declares a variable with explicit type and zero value; `x := 0` is a short variable declaration that infers type and requires at least one new variable on the left. You cannot use `:=` outside function bodies, in `var` statements, or when all variables on the left already exist in the current scope.

G3 — A goroutine is a lightweight, user-space thread managed by the Go runtime (~2KB initial stack, grows/shrinks). OS threads are kernel-managed, heavier, and 1:1 mapped. The GMP model: G = goroutine, M = machine (OS thread), P = processor (execution context/run queue). The scheduler multiplexes Gs onto Ms using Ps, enabling efficient M:N scheduling with work-stealing and preemption.

G4 — Channels are typed conduits for communication and synchronization. Unbuffered channels block both sender and receiver until both are ready. Buffered channels have a capacity; send blocks only when full, recv blocks only when empty. Sending to a full buffered channel blocks until a receiver consumes an element or the channel is closed.

G5 — The `context` package propagates cancellation, deadlines, timeouts, and request-scoped values across API boundaries. Minimal example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

G6 — Go uses implicit interface satisfaction: any type implementing the required methods satisfies the interface without explicit declaration. Unlike Java/C#, there's no `implements` keyword or inheritance hierarchy. `interface{}` (alias `any`) matches any type. It's powerful for generic-like flexibility but dangerous because type assertions can panic at runtime and bypass compile-time safety.

G7 — The code has a data race: no happens-before relationship exists between the goroutine's writes and the main goroutine's reads. The compiler/CPU may reorder or cache values, making `data` potentially empty or `ready` never observed. Fix: use `sync.Once` to signal completion, or `atomic.Bool`/`atomic.Value` for lock-free visibility, or a channel.

G8 — `sync.Mutex` provides exclusive access. `sync.RWMutex` allows multiple concurrent readers or one writer. `sync.Map` is optimized for sparse key sets, read-heavy workloads, or disjoint key sets where writers rarely touch the same keys. Trade-offs: `sync.Map` has higher read overhead and worse cache locality; a regular `map` + `Mutex` is faster for dense, uniform access patterns.

G9 — `go.mod` declares the module path, Go version, and direct dependencies. `go.sum` stores cryptographic hashes of dependency versions for integrity verification. `go mod tidy` removes unused dependencies, adds missing ones, and updates `go.sum`. MVS (Minimum Version Selection) resolves the minimal compatible version for each dependency across the entire module graph, preventing version skew and ensuring reproducible builds.

G10 — `defer` schedules a function call to run after the surrounding function returns. Multiple defers execute in LIFO order. Common loop gotcha: variables captured by deferred closures are evaluated at defer time, not declaration time. Fix: pass variables as arguments to the deferred function or create a new scope per iteration.

G11 — A pointer holds a memory address. Zero value: `nil`. Create a pointer to a struct literal: `p := &MyStruct{Field: value}`. Pointers are passed by value (copy of address), not by reference.

G12 — `init()` runs automatically before `main()` executes. It runs once per package. A package can have multiple `init()` functions across files; they execute top-to-bottom within a file, and packages are initialized in dependency order. Cannot be called manually or controlled directly.

G13 — `make(T, args)` initializes slice, map, or channel and returns the initialized value (not a pointer). `new(T)` allocates zeroed memory for type `T` and returns `*T`. Use `make` for reference types that require initialization; use `new` for value types or when you explicitly need a pointer.

G14 — Errors implement `error` interface (`Error() string`). Idiomatic pattern: `if err != nil { return err }`. `errors.Is(err, target)` checks if the error or any wrapped error matches `target`. `errors.As(err, &target)` extracts the underlying type from the error chain. `==` only checks exact equality and ignores wrapped errors.

G15 — Map: `nil` (use `make`). Slice: `nil` (len=0, cap=0). Channel: `nil` (blocks forever on send/recv). Struct: zero values of each field. All are safe to use except `nil` maps/channels which panic or block.

G16 — A race condition occurs when concurrent goroutines access shared data without synchronization, leading to undefined behavior. `-race` flag instruments the binary to detect conflicting reads/writes at runtime. Example: two goroutines incrementing a counter. Fix: wrap access in `sync.Mutex` or use a channel to serialize access.

G17 — `select` waits on multiple channel operations. Like `switch` but for channels; cases must be channel sends/recv/closes. If multiple cases are ready, one is chosen pseudo-randomly. Timeout: `case <-time.After(d):`. Blocks until at least one case is ready or default is present.

G18 — Escape analysis determines whether variables allocate on stack or heap. Escapes if: address taken, returned, stored in heap-allocated struct, size unknown at compile time, or exceeds stack limit. Inspect with `go build -gcflags="-m"`. Matters because heap allocations trigger GC, increasing latency and reducing throughput.

G19 — `reflect.Type` holds type metadata (name, kind, methods). `reflect.Value` holds the actual value and allows read/write/set. Costs: slow, bypasses compile-time checks, creates GC roots, and can panic. Justified for serialization, ORMs, testing frameworks. Prefer code generation (`go generate`, `stringer`) for performance-critical paths.

G20 — `//go:embed` embeds static files/directories into the binary at compile time. Works with single files, `dir/...` for directories, and populates an `embed.FS` implementing `io/fs.FS`. Limitations: only static files, paths relative to source, cannot embed in function/init bodies directly, and doesn't support runtime-generated content.

R1 — Ownership ensures memory safety without a GC. Three rules: 1. Each value has exactly one owner. 2. Only one owner at a time. 3. When the owner goes out of scope, the value is dropped. Prevents leaks, double-frees, and dangling references.

R2 — `String` is a heap-allocated, growable, owned string. `&str` is a borrowed reference to UTF-8 bytes with fixed size. Use `String` when you need ownership or mutation; use `&str` in function signatures for borrowing (avoids allocation, more flexible, zero-cost).

R3 — Borrowing allows temporary access without transferring ownership. Rules: 1. Either one `&mut T` or any number of `&T` references. 2. All references must be valid (non-dangling). The borrow checker enforces these at compile time to prevent data races and use-after-free.

R4 — `Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents `Some(T)` or `None`. The `?` operator propagates errors/returns early. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — `Box<T>`: heap-allocates a single value, moves ownership, used for large/recursive types. `Rc<T>`: reference-counted, single-threaded shared ownership. `Arc<T>`: atomic reference-counted, thread-safe shared ownership. Use `Box` for ownership, `Rc` for shared read-only, `Arc` for concurrent sharing.

R6 — Traits define shared behavior with optional default implementations. Unlike Go's implicit interfaces, Rust requires explicit `impl Trait for Type`. Trait object (`dyn Trait`): dynamic dispatch via vtable, heap-allocated, enables heterogeneous collections. Generic (`T: Trait`): static dispatch, monomorphization, zero-cost, type-specific code.

R7 — Fails because the compiler cannot determine which input lifetime the return value should borrow. Fix: explicitly annotate lifetimes:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — `Send`: types safe to transfer ownership across threads. `Sync`: types safe to share references across threads. `Rc<T>` isn't `Send`/`Sync` because its ref count isn't atomic. `Arc<T>` uses `AtomicUsize` for thread-safe counting, making it `Send`+`Sync`.

R9 — `async fn` returns a `Future` (a state machine). `await` yields control until the future is ready. The executor (e.g., Tokio) polls futures, manages I/O, and schedules them on threads. Differs from Go: Go uses runtime-managed M:N cooperative scheduling with hidden allocations; Rust uses explicit futures + external executors, zero-cost, no hidden allocations, but requires explicit lifetime/executor management.

R10 — `unsafe` bypasses compile-time safety checks. Three things: 1. Dereference raw pointers. 2. Call `unsafe` functions. 3. Implement `unsafe` traits or access/modify `static mut`. Justified for FFI, low-level sys ops, performance-critical code where safety is proven by invariants.

R11 — Pattern matching exhaustively handles enum variants. `match` binds values, supports guards, and requires exhaustiveness. `if let` is concise for a single case. The compiler enforces exhaustiveness in `match` (must handle all variants or use `_`), preventing unhandled cases.

R12 — `Vec<T>`: heap-allocated, dynamic size, growable. `[T; N]`: stack-allocated (usually), fixed compile-time size. When `Vec` exceeds capacity, it allocates a new larger buffer, moves/copies elements, drops the old buffer, and updates the pointer/len/cap.

R13 — Enums are algebraic data types where each variant can hold data. Unlike C (integer-backed) or Java (class-based), Rust enums are zero-cost and expressive. `Option<T>` = `Some(T)` | `None`. Rust has no `null` to eliminate null pointer dereferences; `Option` forces explicit handling.

R14 — `impl` blocks define methods. `&self`: borrows immutably. `&mut self`: borrows mutably. `self`: consumes/moves ownership. Associated functions (e.g., `String::new()`) don't take `self` and act like static methods, often used as constructors.

R15 — `derive` macro auto-implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if the trait requires custom logic, or if fields don't implement it (e.g., `Fn` closures, raw pointers, or types with custom drop logic).

R16 — `Cow<'a, T>` (Clone on Write) is either borrowed `&'a T` or owned `T`. Useful when a function might return borrowed or owned data. Example: `fn normalize(s: &str) -> Cow<str>` returns `Cow::Borrowed` if no changes, `Cow::Owned` only if modification occurs, avoiding unnecessary allocations.

R17 — `mod` declares a module, `use` brings items into scope, `pub` exposes items. File system: `mod.rs` or `mod_name.rs` in a directory. Rust 2018 changed path resolution: `use` paths are relative to crate root, introduced `crate::`, `self::`, `super::`, and removed `extern crate`.

R18 — `Pin<T>` guarantees a value won't be moved in memory. Needed for self-referential structs and async/await (futures may contain pointers to their own fields). `Unpin` is the default marker for types that can be safely moved. `Pin` prevents invalidation of internal pointers during `await`.

R19 — Declarative macros (`macro_rules!`) use pattern matching and repetition to generate code. Procedural macros (derive, attribute, function-like) operate on ASTs. Hygiene ensures macro-generated identifiers don't leak or collide with surrounding scope, preventing name pollution.

R20 — Zero-cost abstractions compile to efficient machine code. Iterators use loop unrolling and fusion with no bounds checks. Generics use monomorphization (type-specific code generation) instead of vtables. Trait static dispatch enables direct calls. These achieve C-like performance while providing safety and ergonomics.
