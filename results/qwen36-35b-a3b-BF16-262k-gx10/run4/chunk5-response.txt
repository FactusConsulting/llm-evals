**DN1** — `class` is a reference type (heap-allocated, supports inheritance/polymorphism, nullable). `struct` is a value type (stack/inline allocated, copy-on-assign, limited inheritance, non-nullable by default). Use `struct` for small, immutable, short-lived data where value semantics and allocation avoidance matter (e.g., coordinates, IDs, math vectors). Avoid for large objects or when reference identity is required.

**DN2** — `IEnumerable<T>` executes in-memory (LINQ-to-Objects). `IQueryable<T>` builds expression trees that providers translate to remote queries (e.g., SQL). The distinction matters because `IQueryable` defers execution and pushes filtering/joining to the database, preventing full table pulls into memory. `IEnumerable` materializes immediately, risking performance/memory bottlenecks.

**DN3** — `async/await` compiles to a state machine that captures context, yields control, and resumes when the awaited operation completes, avoiding thread blocking. `Task` is a reference type with heap allocation overhead. `ValueTask` is a value type that avoids allocation when the operation completes synchronously. Use `ValueTask` in hot paths or when async methods frequently complete synchronously to reduce GC pressure.

**DN4** — DI is an IoC pattern where a container resolves dependencies. Lifetimes: `Transient` (new each resolution), `Scoped` (new per request/context), `Singleton` (one per container). Injecting a `Scoped` service into a `Singleton` captures it for the Singleton's lifetime, causing stale state, memory leaks, or thread-safety issues. Fix by injecting `IServiceScopeFactory` and creating a scope manually when the scoped service is needed.

**DN5** — `string` is immutable, heap-allocated, and GC-managed. `ReadOnlySpan<char>` is a stack-only, zero-copy view over memory (strings, arrays, buffers) enabling slicing/parsing without allocations. `Span<T>` is the mutable counterpart. Use `Span<T>`/`ReadOnlySpan<char>` for high-performance string/memory processing (parsing, networking, crypto) where allocation must be minimized. Requires careful lifetime management but is safe in modern C#.

**DN6** — The GC automatically reclaims unreachable objects via tracing. Generations: `Gen 0` (short-lived, frequent GC), `Gen 1` (buffer), `Gen 2` (long-lived, full GC). `LOH` (Large Object Heap) holds objects >85KB, isn't compacted, and is collected only on Gen 2. `IDisposable` provides deterministic cleanup for unmanaged resources (handles, native memory). GC is non-deterministic; `IDisposable` ensures timely release via `using` or explicit disposal.

**DN7** — Default `await` captures the current `SynchronizationContext` (e.g., UI thread) and resumes there. `ConfigureAwait(false)` skips context capture, resuming on any thread pool thread. Use `ConfigureAwait(false)` in libraries/shared code to avoid deadlocks and improve throughput. Do NOT use it in UI/app code where you must update UI or access context-bound resources post-await. It directly controls whether continuations marshal back to the captured context.

**DN8** — Primary constructors reduce boilerplate: `public record User(int Id, string Name);`. Collection expressions: `[1, 2, 3]` or `[..arr]`. `FrozenDictionary<K,V>` is an immutable, read-optimized dictionary using perfect hashing. Primary constructor DI example:
```csharp
public class MyService(IOptions<AppConfig> config) {
    private readonly AppConfig _cfg = config.Value;
}
```

**DN9** — Cause: `DbContext` is likely shared across requests or disposed prematurely. Under high concurrency, race conditions or manual `using` break DI scoping. Fix: Register as `Scoped` (`services.AddScoped<MyDbContext>()`), let ASP.NET Core manage lifetime per request, and avoid manual disposal. EF Core's `DbContext` is scoped per HTTP request; DI creates one at request start and disposes at end. Sharing violates this contract.

**DN10** — `record` is a reference type with value-based equality, immutability by default, positional syntax, and `with` expressions. `record struct` is the value-type equivalent. Choose `class` for mutable/shared state or inheritance. Choose `record` for immutable DTOs/data transfer. Choose `record struct` for performance-critical, small, immutable data where allocation must be avoided.

**DN11** — `ref`: Pass by reference, requires initialization, read/write. `out`: Pass by reference, must be assigned in method, caller doesn't need init. `in`: Pass by reference, read-only, avoids copying large structs. Use `ref` for modifying existing values, `out` for multiple return values, `in` for large read-only structs.

**DN12** — Nullable Reference Types (`string?`) are compile-time warnings activated by `#nullable enable`, tracking nullability in the type system to prevent `NullReferenceException`. Nullable Value Types (`int?`) are runtime wrappers (`Nullable<T>`) allowing value types to be null. NRTs are compile-time safety for references; `int?` is a runtime flag for value types.

**DN13** — LINQ unifies querying across collections, DBs, XML. Method syntax (`list.Where(...)`) is fluent and chainable. Query syntax (`from x in list where ...`) is SQL-like and compiles to method syntax. Deferred execution means the query doesn't run until enumerated (foreach, ToList), enabling composition and lazy evaluation.

**DN14** — Constraints restrict generic types: `class` (reference), `struct` (non-nullable value), `new()` (parameterless constructor), `IComparable<T>` (implements comparison). Combine for specific needs: `where T : class, IComparable<T>, new()` ensures T is a reference type, sortable, and instantiable. Used in factories, collections, and generic algorithms.

**DN15** — Abstract classes can hold state, constructors, and partial implementations; single inheritance. Interfaces define contracts; multiple inheritance. C# 8+ default interface methods allow implementations in interfaces, enabling backward-compatible API additions without breaking implementations. Interfaces still can't hold instance state or have constructors.

**DN16** — Middleware processes requests sequentially. `app.Use()` adds middleware. `app.Map()` branches for paths. `app.Run()` is terminal (no `next`). Ordering matters: auth before routing, error handling at end, static files before MVC. Exception handling middleware (`UseExceptionHandler`) catches unhandled exceptions, logs, and returns error responses; must be early to catch downstream failures.

**DN17** — `Channel<T>` is modern, async-friendly, supports bounded/unbounded, and implements backpressure. `BlockingCollection<T>` is older, synchronous, and wraps concurrent collections. Bounded channel example:
```csharp
var channel = Channel.CreateBounded<int>(10);
// Producer: await channel.Writer.WriteAsync(item); // blocks when full
// Consumer: var item = await channel.Reader.ReadAsync(); // blocks when empty
```
Enables backpressure in async pipelines without thread blocking.

**DN18** — Source Generators inject C# code at compile time via Roslyn. Faster and safer than runtime reflection; easier to debug than IL weaving. Incremental generators (`ISourceGenerator` replacement) support caching, incremental compilation, and IDE responsiveness. Preferred for performance and build scalability.

**DN19** — `ActionBlock<T>`: executes action, no output. `TransformBlock<TIn,TOut>`: transforms input to output. `BufferBlock<T>`: stores messages for manual consumption. Compared to `Channels`, Dataflow is higher-level with built-in backpressure, linking, completion propagation, and ideal for complex pipelines. Channels are lower-level, more flexible for custom async patterns.

**DN20** — Minimal APIs use inline route handlers (`app.MapGet(...)`) with less boilerplate than controllers. Trade-offs: simpler for CRUD, but controllers offer better structure, attribute routing, and easier mocking. Testability uses `WebApplicationFactory` or manual handler invocation. Middleware works identically. OpenAPI via Swashbuckle/NSwag. Route groups (`app.MapGroup("/api")`) share prefixes/middleware. Endpoint filters (`WithFilter()`) apply cross-cutting concerns per endpoint.

**P1** — `list` is mutable, ordered, allows duplicates. `tuple` is immutable, ordered, allows duplicates. `set` is mutable, unordered, unique elements. `frozenset` is immutable, hashable, usable as dict keys. Use tuples for fixed records, frozensets for immutable collections.

**P2** — GIL is a mutex allowing only one thread to execute Python bytecode at a time. It prevents true parallel CPU-bound threading. Workloads affected: CPU-bound multi-threaded code. Workarounds: `multiprocessing`, C extensions that release GIL, `asyncio` for I/O-bound, or offloading to external services.

**P3** — `copy.copy()` creates a shallow copy (container copied, nested objects referenced). `copy.deepcopy()` recursively copies all nested objects. Shallow copy fails when nested mutability must be isolated: `a = [[1]]; b = copy.copy(a); b[0].append(2);` mutates `a`. Use `deepcopy` for independent nested structures.

**P4** — Decorators wrap functions to extend behavior. Timing decorator:
```python
import time, functools
def log_time(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.4f}s")
        return result
    return wrapper
```

**P5** — Generators use `yield` to produce values lazily, preserving state between yields. Unlike lists, they use constant memory and support infinite sequences. `yield from` delegates to another generator, simplifying nested generator composition and forwarding exceptions.

**P6** — The event loop manages async tasks and I/O callbacks. `asyncio.run()` creates/starts/closes the loop. `asyncio.gather()` runs coroutines concurrently and returns results. `asyncio.create_task()` schedules a coroutine for concurrent execution. `time.sleep()` blocks the entire loop; use `asyncio.sleep()` for non-blocking waits.

**P7** — MRO determines method lookup order. Python 3 uses C3 Linearization. Diamond inheritance `D(B, C)` yields MRO: `D → B → C → A`. `D().who()` prints `"C"` because `B` doesn't override `who()`, so lookup continues to `C`. C3 ensures monotonicity and left-to-right precedence, resolving diamond ambiguity predictably.

**P8** — Metaclass controls class creation (`__new__`/`__init__`), powerful but complex. `__init_subclass__` is a simpler hook called per subclass. Use metaclass for global class modification (e.g., ORM registration, singleton enforcement). Use `__init_subclass__` for per-subclass initialization (e.g., auto-registering plugins, setting defaults).

**P9** — Threading: I/O-bound, shares memory, GIL-limited for CPU. Multiprocessing: CPU-bound, separate processes, bypasses GIL. `concurrent.futures`: high-level API wrapping both. Multiprocessing uses `pickle` for serialization; lambdas, local functions, and some C extensions fail. Use `multiprocessing.shared_memory` or `pathos` for complex objects.

**P10** — `__slots__` declares fixed attributes, preventing `__dict__` creation. Use for memory/performance optimization with many instances. Prevents dynamic attribute addition and `__dict__`/`__weakref__` (unless explicitly included). Saves ~40-50% memory per instance by removing dict overhead.

**P11** — Virtual environments isolate Python packages/interpreter per project. Prevents dependency conflicts and ensures reproducibility. `venv`: standard library, lightweight. `virtualenv`: third-party, more features. `conda`: package + env manager, handles non-Python deps, data-science focused.

**P12** — Comprehensions (`[x for x in lst if x>0]`) are Pythonic, readable, and often faster. `map()`/`filter()` return lazy iterators, useful with C functions or functional composition. Prefer comprehensions for readability. Use `map`/`filter` for lazy evaluation or performance with built-ins.

**P13** — `==` checks value equality. `is` checks object identity. CPython interns small integers (-5 to 256) and some strings for memory efficiency. `a is b` returns `True` for small ints because they reference the same cached object. Not guaranteed for larger values or different creation contexts.

**P14** — `*args` collects positional args into a tuple. `**kwargs` collects keyword args into a dict. `/` marks positional-only parameters. `*` marks keyword-only parameters. Use for flexible APIs, backward compatibility, and enforcing calling conventions.

**P15** — Context managers (`with`) ensure setup/teardown and handle exceptions. Class-based: `__enter__`/`__exit__`. Function-based: `@contextmanager` with `yield`. Example beyond files: database transactions, temporary directories, or lock acquisition:
```python
import contextlib
@contextlib.contextmanager
def transaction(db):
    db.begin()
    try: yield; db.commit()
    except: db.rollback(); raise
```

**P16** — `Union[A,B]`: either type. `Optional[T]`: `Union[T,None]`. `Literal["x"]`: exact value. `TypeVar("T")`: generic placeholder. `Protocol`: structural subtyping. `mypy`/`pyright` perform static analysis at dev time, catching type mismatches, enabling IDE autocomplete/refactoring. Not enforced at runtime.

**P17** — `__repr__`: unambiguous, developer-focused. `__str__`: readable, user-focused. `__eq__`: value equality. `__hash__`: hashability (must align with `__eq__`). `__getattr__`: fallback when attribute missing. `__getattribute__`: intercepts all access (risk of recursion). Defining `__eq__` without `__hash__` sets `__hash__ = None`, making instances unhashable.

**P18** — Descriptors implement `__get__`, `__set__`, `__delete__` to intercept attribute access on the owner class. `property`, `classmethod`, and `staticmethod` are descriptors under the hood. Python's attribute lookup checks the descriptor protocol on the class before checking the instance `__dict__`, enabling computed attributes and method binding.

**P19** — Relative imports (`from .mod import x`) resolve relative to the package. Absolute imports resolve from `sys.path`. `PYTHONPATH` prepends to `sys.path`. `__init__.py` marks packages and runs on import. Namespace packages omit `__init__.py` and split across paths. Finders locate modules; loaders execute them. `importlib` standardizes this.

**P20** — `dataclasses` auto-generates `__init__`, `__repr__`, `__eq__`. `__post_init__` handles validation. `field(default_factory=...)` fixes mutable defaults. `frozen=True` enables immutability. `attrs` is a flexible predecessor. `Pydantic` adds runtime validation, type coercion, and serialization. Choose Pydantic for API boundaries/config parsing. Choose dataclasses for internal DTOs/performance. Inheritance requires careful `__post_init__` chaining.
