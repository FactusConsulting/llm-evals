## Kubernetes

**K1** — A **Deployment** manages stateless workloads with interchangeable pods; pods are created/destroyed without stable identities or ordered scaling. A **StatefulSet** manages stateful workloads with stable network IDs, stable storage bindings, and ordered deployment/scaling (0 to N-1).

**K2** — `kube-proxy` watches Services and creates iptables/IPVS rules mapping the ClusterIP:Port to the backend pod IPs. When traffic hits the ClusterIP, `kube-proxy` performs DNAT to randomly select one of the healthy pod IPs.

**K3** — A **PersistentVolume (PV)** is a cluster-wide storage resource. A **PersistentVolumeClaim (PVC)** is a pod's request for storage. A **StorageClass (SC)** defines a provisioning template. Relation: PVCs bind to static PVs or trigger dynamic provisioning via an SC to create a PV.

**K4** — 1. `kubectl logs <pod> --previous` to check crash reason. 2. `kubectl describe pod` for ExitCode, OOMKilled, or probe failures. 3. Verify resource limits/requests vs node capacity. 4. Check app dependencies (DB connectivity, missing config files, invalid binaries).

**K5** — CoreDNS provides internal DNS resolution for `svc.cluster.local` and pod FQDNs. If CoreDNS pods are down, internal service discovery fails, but direct pod IP communication and external DNS resolution remain unaffected.

**K6** — The scheduler uses **filtering** (remove ineligible nodes) then **scoring** (rank remaining nodes). Filtering checks: taints/tolerations, node selectors, resource availability, volume constraints, affinity/anti-affinity. Scoring factors: CPU/memory request ratios, pod anti-affinity (spread), topology spread constraints, zone awareness.

**K7** — Yes, it will schedule. 3.5GB + 256Mi ≈ 3.75GB < 4GB node capacity. At runtime, if it uses 600Mi (>512Mi limit), the kubelet OOMKills the container, restarts it, and it enters CrashLoopBackOff if the usage persists.

**K8** — Client → External Cloud LB (routes to Ingress Controller NodePort/ELB IP) → Ingress Controller (NGINX) parses Ingress resource → matches host/path → forwards to Kubernetes Service → Service routes to Endpoints (pod IPs) → `kube-proxy`/iptables/IPVS DNATs traffic to pod → pod handles request.

**K9** — A `NetworkPolicy` restricts pod-to-pod traffic using selectors. Default behavior (no policies): all ingress/egress allowed. When a policy is applied: all traffic is denied by default, only traffic matching the policy's `ingress`/`egress` rules is permitted.

**K10** — `RollingUpdate` gradually replaces old pods with new ones (zero downtime). `Recreate` terminates all old pods before starting new ones (downtime). Choose `Recreate` for stateful apps requiring exclusive access to shared hardware/files or when config changes mandate a full restart.

**K11** — A namespace provides virtual cluster isolation and resource scoping. Default namespaces: `default`, `kube-system`, `kube-public`, `kube-node-lease`.

**K12** — `kubectl describe pod` shows detailed runtime state. Unlike `get`, it reveals: 1. Container states & exit codes, 2. Kubernetes events (scheduling, pull, probe failures), 3. Resource requests/limits & current usage, 4. Environment variables & volume mounts.

**K13** — A `ConfigMap` stores non-sensitive configuration data. Consumption methods: 1. Environment variables via `env.valueFrom.configMapKeyRef` or `envFrom`, 2. Volume mount exposing keys as files in the container filesystem.

**K14** — `ClusterIP`: internal cluster-only access. `NodePort`: exposes the service on a static port on each node's IP. `LoadBalancer`: provisions a cloud provider external load balancer with a public IP.

**K15** — A `DaemonSet` ensures a copy of a pod runs on every (or selected) node. Use for cluster-level daemons: logging agents, metrics collectors, network plugins, or storage drivers. Deployments are for application replicas.

**K16** — **Taints** repel pods from nodes (node-side); **tolerations** allow pods to schedule on tainted nodes (pod-side). **Node affinity** attracts pods to nodes. Use case: Taints for dedicated GPU nodes (only pods with toleration schedule); Affinity for zone-aware scheduling (prefer nodes in same AZ).

**K17** — An Operator is a custom controller that manages complex stateful applications using CRDs and reconciliation loops. Unlike standard controllers, it encodes domain-specific operational knowledge (backups, upgrades, failover, scaling). Solves manual intervention for stateful workloads.

**K18** — etcd uses the Raft consensus model with linearizable reads/writes. Quorum loss makes the cluster read-only/unwritable. If 2/3 nodes are permanently lost, quorum cannot be restored from etcd data alone. Recovery requires restoring from the latest backup on new nodes or rebuilding the cluster.

**K19** — RBAC controls access via Roles/ClusterRoles (permissions) bound to subjects via RoleBindings/ClusterRoleBindings.
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: dev-ns
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: dev-pod-reader
  namespace: dev-ns
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — Default `ndots:5` in `/etc/resolv.conf` causes Kubernetes to append cluster suffixes (`.svc.cluster.local`, etc.) before querying external DNS if the hostname has <5 dots, causing 5+ sequential queries. Fix: set `dnsConfig: { options: [{ name: "ndots", value: "2" }] }` or use FQDN with trailing dot.

## Development

**D1** — `merge` preserves full history with a merge commit; `rebase` rewrites commit history into a linear sequence. Avoid rebasing on shared/public branches to prevent history collisions and force-push conflicts.

**D2** — TCP is connection-oriented, reliable, and ordered; UDP is connectionless, unreliable, and low-latency. TCP: HTTP, SMTP. UDP: DNS, VoIP/Video streaming.

**D3** — A race condition occurs when concurrent threads/processes access shared state without synchronization, yielding unpredictable results. Example: two threads incrementing a shared counter without a mutex, causing lost updates.

**D4** — Symmetric encryption uses one key for encrypt/decrypt; asymmetric uses a public/private key pair. TLS uses asymmetric crypto for the handshake/key exchange, then switches to symmetric crypto for bulk data encryption (performance).

**D5** — Each Dockerfile instruction creates an immutable image layer. Layer caching reuses unchanged layers. Best practice: order instructions from least to most frequently changing (e.g., copy `package.json`/dependencies first, then source code) to maximize cache hits.

**D6** — 1. Check pod readiness/liveness probes & container status. 2. Verify upstream dependencies (DB, cache, third-party APIs). 3. Check resource limits (OOMKilled, CPU throttling). 4. Inspect load balancer/ingress health checks & connection/connection-pool limits.

**D7** — CAP theorem: a distributed system can only guarantee two of Consistency, Availability, Partition tolerance. CP example: Distributed SQL (CockroachDB, HBase) – prioritizes data correctness during splits. AP example: DynamoDB, Cassandra – prioritizes uptime, allows stale reads.

**D8** — Horizontal scaling adds more nodes/instances; vertical scaling increases CPU/RAM of existing nodes. Horizontal scaling requires: stateless services, distributed databases, message queues, consistent hashing, and external session/state storage.

**D9** — An environment variable is a dynamic key-value pair passed to processes. Persist across sessions: add `export VAR=value` to `~/.bashrc` or `~/.profile`, then run `source ~/.bashrc`.

**D10** — JSON is a strict, machine-parsable key-value format; YAML is human-readable, indentation-based, and supports comments. JSON advantage: universal parsing, strict syntax. YAML advantage: readability, less boilerplate, native comments.

**D11** — REST is an architectural style using standard HTTP methods. GET: retrieve resource. POST: create new resource. PUT: replace/update resource. DELETE: remove resource.

**D12** — Version pinning locks dependencies to exact versions (e.g., `package@1.2.3`). Ensures reproducible builds, prevents unexpected breaking changes from upstream updates, and simplifies debugging.

**D13** — Compiled languages translate source to machine code before execution (C++, Rust). Interpreted languages execute source line-by-line via a runtime (Python, JavaScript). Note: many modern languages use hybrid approaches (Java, C# compile to bytecode + JIT).

**D14** — A reverse proxy sits in front of servers, routing client requests to backends (Nginx, HAProxy). Use: load balancing, SSL termination, caching. A forward proxy sits in front of clients, routing outbound requests. Use: corporate content filtering, outbound caching.

**D15** — A deadlock occurs when two+ processes wait indefinitely for each other's resources. Coffman conditions: 1. Mutual exclusion, 2. Hold and wait, 3. No preemption, 4. Circular wait. All must hold simultaneously.

**D16** — Eventual consistency guarantees all replicas converge if no new updates. Cassandra uses tunable consistency levels: `ONE`, `QUORUM`, `ALL`, `LOCAL_QUORUM`, `EACH_QUORUM`, `SERIALIZABLE`. For read-after-write, use `QUORUM` on both reads and writes, or `SERIALIZABLE` for strict ordering.

**D17** — mTLS authenticates both client and server via X.509 certificates. Handshake: ClientHello → ServerHello + cert → ServerKeyExchange → ClientKeyExchange + cert → CertificateVerify → Finished. Used in: service meshes (Istio/Linkerd), zero-trust microservices, internal API gateways.

**D18** — A hash table maps keys to values via a hash function → array index. Collision resolution: chaining (linked lists at index) or open addressing (linear/quadratic probing, double hashing). Avg complexity: O(1) for insert/lookup/delete. Worst case: O(n) when all keys collide.

**D19** — A circuit breaker prevents cascade failures by failing fast when a downstream service is unhealthy. States: Closed (normal), Open (fail fast, trip after error threshold), Half-open (allow limited test requests). Relates to retries: circuit breakers should wrap retry logic to prevent retry storms during outages.

**D20** — Optimistic concurrency assumes no conflicts, checks at commit (row versioning, `UPDATE ... WHERE version = old`). Pessimistic locks resources during transaction (`SELECT ... FOR UPDATE`). Choose optimistic for high read/low write contention; pessimistic for high write contention or critical financial data.
