JS1 — `var` is function-scoped, hoisted, and re-declarable. `let`/`const` are block-scoped, hoisted but in a Temporal Dead Zone (TDZ) until declaration, and not re-declarable. `const` prevents reassignment (not immutability). Hoisting is JS's compilation-phase behavior where declarations are moved to the top of their scope; `var` initializes to `undefined`, while `let`/`const` remain uninitialized until execution reaches them.

JS2 — The event loop continuously checks if the call stack is empty. If empty, it pulls one macrotask (setTimeout, I/O, UI) from the macrotask queue. Before moving to the next macrotask, it drains the entire microtask queue (Promises, queueMicrotask, MutationObserver). This ensures async callbacks resolve synchronously relative to each other, preventing UI starvation.

JS3 — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: `function makeCounter() { let i=0; return () => ++i; }`. Classic bug: `for (var i=0; i<3; i++) setTimeout(()=>console.log(i), 0)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped), IIFE, or `setTimeout(..., 0, i)` to capture value.

JS4 — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that pauses execution until the promise settles, making async code read synchronously. Error handling: `try/catch` with `await`, or `.catch()`/second `.then()` argument. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all promises, returning `[{status:'fulfilled',value}, {status:'rejected',reason}]`.

JS5 — `interface` declares object shapes, supports declaration merging, and only works with objects/types. `type` is broader: unions, intersections, primitives, mapped types, tuples. Use `interface` for object contracts/APIs, `type` for unions/primitives/computed types. Discriminated unions: types sharing a common literal property (tag) used in `switch` statements for exhaustive type narrowing.

JS6 — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar: `class A extends B` sets `A.prototype.__proto__ = B.prototype`, `constructor` runs on `new`, and methods are placed on the prototype.

JS7 — `this` is dynamically bound based on call site. Priority: 1. `new` (new instance), 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (`obj.method()`), 4. Default (`global`/`undefined` in strict mode). `bind()` returns a new function with `this` permanently bound. It cannot be re-bound; subsequent `call`/`apply`/`bind` calls are ignored.

JS8 — `WeakRef` holds a weak reference that doesn't prevent garbage collection. `FinalizationRegistry` executes a callback when weakly referenced objects are GC'd. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects because GC tracks object lifecycles; if keys were primitives, the engine couldn't know when to remove entries, causing unbounded memory growth.

JS9 — V8 uses hidden classes (shapes) to optimize property access. Inline caching (IC) caches the hidden class lookup at call sites. Deoptimization occurs when assumptions break: dynamic property addition, type polymorphism, `delete`, or `with`. V8 falls back to slower dictionary mode, losing IC speed. Avoid dynamic shapes and maintain consistent types in hot paths.

JS10 — Tree-shaking removes unused exports at build time. It works with ES modules because `import`/`export` are static and parsed at compile time, enabling static analysis. CommonJS uses dynamic `require()`, evaluated at runtime, so bundlers can't safely determine dependencies or eliminate dead code without complex static analysis or transpilation.

JS11 — `null` is intentional absence; `undefined` is uninitialized/missing. `==` coerces types (`null == undefined` is true); `===` checks type and value. `??` returns right operand only if left is `null`/`undefined` (preserves `0`/`""`). `?.` safely accesses nested properties, short-circuiting to `undefined` if intermediate is nullish.

JS12 — `map()` transforms elements, `filter()` keeps matching ones, `reduce()` accumulates to a single value. `reduce()` with initial value prevents `undefined` on empty arrays and sets accumulator type. `flatMap()` maps then flattens one level; useful for transforming while expanding (e.g., splitting strings into arrays).

JS13 — Template literals use backticks, support `${expr}` interpolation and multi-line. Tagged templates call a function with an array of string parts and interpolated values. Example: `function html(strings, ...vals) { return strings.reduce((a,s,i) => a + s + (vals[i] ? escapeHTML(vals[i]) : ''), ''); }`

JS14 — Destructuring unpacks arrays/objects. Object: `{a, b} = obj`. Array: `[a, b] = arr`. Defaults: `{a = 1} = obj`. Renaming: `{a: newName} = obj`. Rest: `{...rest} = obj` collects remaining keys; `[a, ...rest] = arr` collects remaining elements. Rest must be last.

JS15 — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, Maps). Avoid `for...in` on arrays because it iterates keys, not values, includes prototype properties, and doesn't guarantee order.

JS16 — Generics parameterize types. Constraints: `function id<T extends string>(x: T)`. Conditional types: `type IsString<T> = T extends string ? true : false`. `infer`: extracts types in contexts: `type Unpack<T> = T extends Promise<infer U> ? U : T`. Practical: type-safe API clients, extracting return types from function signatures.

JS17 — CJS (`require`/`module.exports`) is synchronous, dynamic, Node's historical default. ESM (`import`/`export`) is static, async, native to browsers/Node. Node supports both; ESM requires `.mjs` or `"type": "module"` in `package.json`. `"type": "module"` tells Node to treat `.js` files as ESM.

JS18 — Structural typing: compatibility based on shape, not names. Excess property checks apply only to object literals assigned directly to variables/types to catch typos. `extends` checks assignability. `satisfies` checks if expression matches type without widening, preserving original type. Variance: `in` (contravariant, parameters), `out` (covariant, returns), `in out` (bivariant). TS 4.7+ enforces stricter function type variance.

JS19 — `Proxy` wraps objects to intercept operations (get, set, apply, etc.). `Reflect` provides default behavior mirroring traps. Example: validation proxy intercepts `set` to check types. Reactive binding: `Proxy` tracks dependencies on `get`, triggers updates on `set`. Always use `Reflect` inside traps to preserve default semantics.

JS20 — `SharedArrayBuffer` shares memory between main thread and Web Workers. `Atomics` provides atomic ops for synchronization. Workers write to SAB, use `Atomics.wait` (blocks until value changes) and `Atomics.notify` (wakes threads). Ordering: sequential consistency for atomic ops; `Atomics.store`/`load` act as memory barriers. Requires `Cross-Origin-Opener-Policy` and `Cross-Origin-Embedder-Policy` headers.

B1 — `$@` expands to separate quoted words (`"$1" "$2"`), preserving spaces. `$*` expands to a single quoted string (`"$1 $2 ..."`). `"$@"` is safe for iteration; `"$*"` joins with the first character of IFS.

B2 — `set -e`: exit on command failure. `set -u`: treat unset variables as errors. `set -o pipefail`: pipeline returns the exit status of the last non-zero command. Together: strict, fail-fast scripting.

B3 — `$(command)` is modern, nestable, and preferred. `` `command` `` is legacy, harder to nest. `$((expression))` is bash-native arithmetic expansion. `expr` is an external command, slower, and lacks modern features.

B4 — Process substitution `<(cmd)` creates a file descriptor (e.g., `/dev/fd/63`) pointing to `cmd`'s output. Use when a command expects a file but needs dynamic input. Example: `diff <(sort file1) <(sort file2)`.

B5 — Use `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous: word splitting breaks on spaces, globbing expands patterns, and `ls` output parsing is fragile and locale-dependent.

B6 — Here doc `<<EOF` passes multi-line string as stdin. Here string `<<<` passes a single string. `<<-EOF` strips leading tabs (not spaces) for indentation, keeping scripts readable.

B7 — `cmd > file 2>&1`: stdout → file, then stderr → wherever stdout points (file). `cmd 2>&1 > file`: stderr → terminal (stdout's original location), then stdout → file. `cmd &> file`: bash shorthand for `> file 2>&1`. Redirections evaluate left-to-right, causing the first two to differ.

B8 — `mkdir` is atomic on POSIX filesystems, preventing race conditions. 
```bash
lock_and_run() {
  local lockdir="/tmp/mylock.$$"
  trap 'rm -rf "$lockdir"' EXIT INT TERM
  if ! mkdir "$lockdir" 2>/dev/null; then
    echo "Locked" >&2; exit 1
  fi
  # critical section
  rm -rf "$lockdir"
}
```
`mkdir` succeeds only if the directory doesn't exist, making it a safe lock.

B9 — Single quotes: literal, no expansion. Double quotes: allow `$`, `` ` ``, `\`, `!` expansion. No quotes: word splitting and globbing occur. Example: `var="hello world"; echo $var` → `hello world`; `echo "$var"` → `hello world`; `echo '$var'` → `$var`.

B10 — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash keyword: supports `&&`, `||`, `=~`, no word splitting/globbing, safer. `[` is POSIX builtin/external, stricter, requires proper quoting.

B11 — `$?`: exit status of last command. `$$`: PID of current shell. `$!`: PID of last background process. `$#`: number of positional parameters. Use cases: error checking, logging, job control, argument validation.

B12 — `func() { commands; }` or `function func { commands; }`. Return values: `return <int>` (exit code 0-255), or echo/print to stdout and capture with `$()`. Bash functions share global scope; use `local` for isolation.

B13 — `PATH`: colon-separated directories bash searches for executables. Resolves by checking PATH, then builtins, then aliases. Builtin: compiled into shell (`cd`, `echo`). External: separate binary. Check with `type cmd` or `command -v cmd`.

B14 — `trap 'cleanup' EXIT INT TERM ERR`. Signals interrupt current command, handler runs, then script continues/exits. Multiple signals: queued or handled sequentially. `ERR` triggers on non-zero exit. Use `trap - INT` to ignore in cleanup.

B15 — `xargs` builds/executes commands from stdin. Differs from substitution by handling whitespace/newlines safely and batching. `find -print0 | xargs -0` handles special chars. `xargs -P N` runs N processes in parallel.

B16 — Indexed: `arr=(a b c)`, `${arr[0]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${#assoc[@]}`. Iterate: `for i in "${arr[@]}"; do`. Append: `arr+=(new)`. Associatives require `declare -A`.

B17 — Subshell `(...)`: runs in child, variable changes lost. Group `{ ...; }`: runs in current shell, variables persist. Piping to `while` creates subshell, losing variable changes. Fix: process substitution `while ... done < <(cmd)`.

B18 — SIGINT (Ctrl+C, interrupt), SIGTERM (graceful stop), SIGHUP (terminal close/reload), SIGKILL (force kill, uncatchable). Handle graceful shutdown: trap SIGTERM, kill background jobs (`kill $(jobs -p)`), cleanup, exit. Use `wait` to handle background processes.

B19 — `split -l 10000 large.log part_`; `find . -name 'part_*' -print0 | xargs -0 -P 4 -I {} bash process.sh {}`; merge results. Trade-offs: I/O vs CPU, split/merge overhead. Error propagation: `set -o pipefail`, check worker exit codes, aggregate errors in temp files, fail if any worker fails.

B20 — `exec` replaces current shell or redirects FDs. `exec 3>file` opens FD 3, `exec 3>&-` closes it. Coprocess: `coproc cmd` runs cmd in background, connects stdin/stdout to FDs. Use for persistent background services or bidirectional communication without explicit pipes.

PS1 — `Write-Output` sends objects down the pipeline. `Write-Host` writes directly to the console, bypassing the pipeline. Distinction matters: `Write-Host` breaks pipeline chaining, redirection, and object streaming.

PS2 — Pipeline streams objects between cmdlets. `ForEach-Object` processes each object in the pipeline (streaming, memory-efficient). `foreach` statement loads entire collection into memory first. Use `ForEach-Object` for large streams, `foreach` for small collections or when you need `break`/`continue`.

PS3 — `[PSCustomObject]`: strongly typed, ordered, pipeline-friendly, supports methods/properties. `[hashtable]`: unordered, key-value, less pipeline-friendly. Convert: `[PSCustomObject]@{key='val'}` or `@{key='val'} | ForEach-Object {[PSCustomObject]$_}`. Use custom objects for structured data, hashtables for dynamic config.

PS4 — Terminating errors stop execution (exceptions, `throw`). Non-terminating errors continue, set `$?` to false. `-ErrorAction` overrides `$ErrorActionPreference` (SilentlyContinue, Stop, Continue, Inquire). `try/catch` only catches terminating errors.

PS5 — Splatting: `@params` passes hashtable keys as named parameters. Example: `Get-ChildItem @opts`. Differs from single param: splatting expands to named parameters, single param passes entire hashtable as one argument.

PS6 — `Invoke-Command -ComputerName`: runs one-off command remotely. `Enter-PSSession`: interactive remote session. Protocol: WinRM (HTTP/HTTPS) by default, SSH in PS 7+. WinRM uses WS-Management.

PS7 — `$result += "one"` creates an array. `return $result` returns `Object[]`. If 0 items, `$result` is `$null`, `return $null` breaks pipeline (returns nothing). Correct pattern: `[array]$result = @()` or `return ,$result` to always return an array. `$x.GetType().Name` is `Object[]`.

PS8 — `[scriptblock]`: code container, can be passed around, executed with `.Invoke()`. Functions are named scriptblocks with parameters. Pass to remote: `Invoke-Command -ScriptBlock $sb -ArgumentList $args`. Double-hop: remote session can't authenticate to second server. Solve with CredSSP (less secure) or `-ArgumentList` to pass data, or use constrained endpoints.

PS9 — `@()` forces array, even if single/null. `[array]` casts to array. Index into `$null` throws error; index into `@()` returns `$null`. `@()` prevents enumeration issues in pipelines.

PS10 — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive: `-ceq`, `-clike`, `-cmatch`. `-contains` checks if collection contains value; `-in` is reverse (value in collection).

PS11 — Module: collection of functions/cmdlets. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies). Binary: compiled DLL. `Import-Module` loads module, searches `$env:PSModulePath`.

PS12 — `"..."` allows expansion (`$var`, `` ` ``). `'...'` literal. Expressions: `$($expr)`. Here-string: `@"..."@` for multi-line, supports expansion.

PS13 — `Get-Member`: shows object properties/methods. Pipeline: objects stream, `Get-Member` inspects them. Properties: data, Methods: actions, NoteProperties: added properties. `Select-Object`: picks properties, `Where-Object`: filters.

PS14 — Classes: v5+, C#-like. Limitations: no multiple inheritance, limited interface support, constructors must match signature, no access modifiers (public by default). Use classes for complex data/models, functions for scripting.

PS15 — `[CmdletBinding()]`: enables advanced features. `SupportsShouldProcess`: adds `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: sets default param group. `ValueFromPipeline`: binds pipeline input. `Begin`: runs once, `Process`: runs per object, `End`: runs after pipeline.

PS16 — Providers: abstract data stores as drives. `Get-ChildItem` works on `HKLM:`, `Cert:`, `Env:`. Registry accessed like filesystem: `Get-ChildItem HKLM:\SOFTWARE`.

PS17 — Runspaces: execution environments. `[runspace]`: single, `[runspacepool]`: manages multiple. `[powershell]`: wraps runspace for cmdlet execution. `ForEach-Object -Parallel` (v7+): easy parallelism. Manual runspace: better control, thread safety requires careful synchronization, use `RunspacePool` for scalability.

PS18 — PSScriptAnalyzer: linting tool. Rules: predefined checks (naming, style). Severity: error, warning, info. Custom rules: PowerShell scripts. Suppress: `#pragma disable`. CI/CD: run in pipeline, fail on errors.

PS19 — `$using:var`: serializes variable for remote/job/parallel context. `-ArgumentList`: passes values, avoids serialization limits. CLIXML depth limit: ~1000, complex objects may fail. Use `-ArgumentList` for large/complex data.

PS20 — DSC: declarative config. Configurations: desired state code. Resources: building blocks (File, Service). LCM: agent that applies config. WinPS vs PS7: PS7 uses OpenDSC, cross-platform. Replaced by: Ansible, Terraform, Chef, or native cloud IaC, but DSC still used in Windows ecosystems.
