G1 — A slice is a lightweight descriptor containing a pointer to an underlying array, length, and capacity (`[]T`). An array is a fixed-size value type (`[N]T`). When appending to a slice that has reached capacity, Go allocates a new backing array (typically double the capacity), copies existing elements, updates the slice header, and returns the new slice.

G2 — `var x int` declares a variable with explicit type and zero value; `x := 0` is a short variable declaration that infers type. You cannot use `:=` in package-level scope, when all variables on the left-hand side already exist in the current scope, or when you need to redeclare an existing variable without introducing a new one.

G3 — A goroutine is a lightweight, user-space thread managed by the Go runtime (~2KB initial stack, grows/shrinks). OS threads are kernel-managed, heavier, and typically 1:1 with user threads. The GMP model: G = goroutine, M = machine (OS thread), P = processor (execution context). The scheduler multiplexs Gs onto Ms using Ps, enabling efficient work-stealing and preemption.

G4 — Channels are typed conduits for communication and synchronization. Unbuffered channels block both sender and receiver until both are ready. Buffered channels have a capacity; send blocks only when full, recv blocks only when empty. Sending to a full buffered channel blocks until a receiver consumes an element or the channel is closed.

G5 — The `context` package propagates deadlines, cancellation signals, and request-scoped values across API boundaries. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
client.Do(req) // cancels automatically if timeout hits
```

G6 — Go uses implicit interface satisfaction: any type implementing the required methods satisfies the interface without explicit declaration. Unlike Java/C#, there's no `implements` keyword. `interface{}` (Go 1.18+ `any`) matches any type. Powerful for generic abstraction, but dangerous because type assertions can panic at runtime and bypass compile-time type safety.

G7 — The code has a data race: concurrent reads/writes to `ready` and `data` without synchronization violate Go's happens-before guarantees. The spin loop `for !ready {}` also causes busy-waiting. Fix with a channel, `sync.Once`, or atomics:
```go
var ready atomic.Bool
var data atomic.String
go func() { data.Store("hello"); ready.Store(true) }()
for !ready.Load() {}
fmt.Println(data.Load())
```

G8 — `sync.Mutex` provides exclusive access; `sync.RWMutex` allows multiple concurrent readers or one writer. `sync.Map` is optimized for read-heavy workloads, known compile-time keys, or disjoint key sets. Trade-offs: `sync.Map` has higher read latency for general use and uses more memory; a regular `map` + `Mutex` is faster for typical mixed read/write patterns.

G9 — `go.mod` declares module path, Go version, and direct dependencies. `go.sum` stores cryptographic checksums of dependency contents for integrity verification. `go mod tidy` removes unused dependencies, adds missing ones, and updates `go.sum`. MVS (Minimum Version Selection) resolves the lowest compatible version for all direct and indirect dependencies to minimize version skew.

G10 — `defer` schedules a function call to run after the surrounding function returns. Multiple defers execute in LIFO order. Common loop gotcha: variables captured by deferred closures are evaluated at defer time, not declaration time. Fix by passing as arguments: `defer func(v int) { fmt.Println(v) }(i)`.

G11 — A pointer holds a memory address. Zero value is `nil`. Create a pointer to a struct literal with `&MyStruct{Field: value}`. Pointers enable mutation of the original value and avoid copying large structs.

G12 — `init()` runs automatically before `main()` executes. It runs once per package. A package can have multiple `init()` functions across files; they execute top-to-bottom within each file, and packages are initialized in dependency order. Cannot be called explicitly.

G13 — `new(T)` allocates zeroed memory and returns `*T`. `make(T, args)` initializes slice, map, or channel and returns the initialized `T` (not a pointer). `new` works for any type; `make` only works for built-in reference types.

G14 — Go uses explicit error values implementing `error` (`Error() string`). Idiomatic pattern: `if err != nil { return err }`. `errors.Is(err, target)` checks if the error or any wrapped error matches `target`. `errors.As(err, &target)` extracts the concrete type from the error chain. `==` only checks direct equality, ignoring wrapped errors.

G15 — Zero values: `map` → `nil` (use `make`), `slice` → `nil` (len=0, cap=0), `channel` → `nil` (blocks forever), `struct` → zero values of each field. All are safe to use except `nil` maps/channels which panic or block.

G16 — A race condition occurs when concurrent goroutines access shared data without synchronization, leading to undefined behavior. `-race` flag instruments the binary to detect conflicting reads/writes at runtime. Fix with `sync.Mutex` (lock around shared access) or channels (pass data, don't share memory).

G17 — `select` waits on multiple channel operations, similar to `switch` but for channels. If multiple cases are ready, one is chosen pseudo-randomly. Implement timeout with: `case <-time.After(d): // timeout logic`. Blocks until at least one case is ready or default is present.

G18 — Escape analysis determines whether variables allocate on stack (fast, auto-freed) or heap (triggers GC). Escapes if: address is taken, size unknown at compile time, escapes function scope, or returned as pointer. Inspect with `go build -gcflags="-m"`. Matters because heap allocations increase GC pressure and latency.

G19 — `reflect.Type` holds type metadata; `reflect.Value` holds the actual value/data. Costs: slow execution, bypasses compile-time checks, causes allocations. Justified in frameworks, ORMs, or serialization libraries. Prefer code generation (`go generate`, `stringer`) for performance-critical reflection-like behavior.

G20 — `//go:embed` embeds static files/directories into the binary at compile time. Works with `io/fs.FS` via `embed.FS`. Limitations: only static files, paths relative to source, cannot embed in test binaries without build tags, and doesn't support runtime-generated content.

R1 — Ownership ensures memory safety without a GC. Three rules: 1. Each value has exactly one owner. 2. Only one owner at a time. 3. When the owner goes out of scope, the value is dropped. Transfers ownership via move semantics; borrowing via references.

R2 — `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is a borrowed string slice (reference to UTF-8 bytes). Use `String` when you need ownership or mutation; use `&str` in function signatures for zero-copy borrowing and maximum flexibility.

R3 — Borrowing allows reading/mutating data without taking ownership. Rules: either one `&mut T` OR any number of `&T`, but never both simultaneously. References must not outlive the data they point to. The borrow checker enforces these at compile time to prevent data races and dangling pointers.

R4 — `Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents `Some(T)` or `None`. The `?` operator propagates errors/returns early. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — `Box<T>`: single-owner heap allocation (use for large/recursive types). `Rc<T>`: reference-counted, single-threaded shared ownership. `Arc<T>`: atomic reference-counted, thread-safe shared ownership. Use `Arc<T>` when sharing across threads; `Rc<T>` for single-thread sharing; `Box<T>` for owned heap data.

R6 — Traits define shared behavior with optional default methods. Unlike Go's implicit satisfaction, Rust requires explicit `impl Trait for Type`. `dyn Trait` creates a trait object (dynamic dispatch, vtable, heap-allocated, heterogeneous). `T: Trait` uses static dispatch (monomorphization, zero-cost, homogeneous).

R7 — The compiler cannot infer which input lifetime applies to the output. Fix by annotating lifetimes:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```
This guarantees the returned reference lives at least as long as both inputs.

R8 — `Send`: types safe to transfer ownership across threads. `Sync`: types safe to share references across threads. `Rc<T>` isn't `Send`/`Sync` because its ref count isn't atomic. `Arc<T>` uses atomic ref counting, making it `Send`+`Sync` (provided `T` is).

R9 — `async/await` compiles to a state machine implementing `Future`. An `async fn` returns a `Future` that yields control when awaiting. An executor (e.g., Tokio) polls futures to completion. Differs from Go: Rust uses explicit executors, zero-cost state machines, and no runtime scheduler; Go uses a built-in M:N scheduler.

R10 — `unsafe` bypasses compile-time safety checks. Three capabilities: 1. Dereference raw pointers. 2. Call `unsafe` functions. 3. Implement `unsafe` traits. 4. Access/modify `static mut`. Justified for FFI, low-level syscalls, performance-critical code, or building safe abstractions over unsafe foundations.

R11 — Pattern matching exhaustively handles enum variants. `match` requires all variants; `if let` is shorthand for one case + optional `else`. The compiler enforces exhaustiveness in `match`, emitting errors/warnings for missing patterns. Enables safe, expressive control flow without `null` checks.

R12 — `Vec<T>` is heap-allocated with dynamic size; `[T; N]` is stack-allocated (usually) with fixed compile-time size. When `Vec` capacity is exceeded, it allocates a new larger buffer, copies elements, drops the old buffer, and updates pointer/length/capacity.

R13 — Rust enums are algebraic data types that can hold data per variant. Unlike C/Java, they're powerful first-class types. `Option<T>` = `Some(T)` | `None`. Rust eliminates `null` to prevent null pointer exceptions; `Option` forces explicit handling at compile time.

R14 — `impl` blocks define methods. `&self`: borrows immutably. `&mut self`: borrows mutably. `self`: consumes the value. Associated functions (e.g., `String::new()`) don't take `self` and act like static constructors or utility functions.

R15 — `#[derive]` auto-implements common traits. Examples: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if the trait requires custom logic, or if fields lack the trait (e.g., `Fn` closures, `!Send` types, or custom drop logic).

R16 — `Cow<'a, T>` (Clone on Write) is either a borrowed `&'a T` or owned `T`. Useful when a function might return borrowed or owned data. Avoids allocation if input already matches the desired format; only clones when mutation is needed, saving memory in read-heavy paths.

R17 — `mod` declares a module, `use` brings items into scope, `pub` exposes items. File system maps: `mod.rs` or `mod_name.rs` in a directory. Rust 2018 changed path resolution from crate-relative to module-relative, removed `extern crate`, and expanded the prelude.

R18 — `Pin<T>` guarantees a value's memory location won't change. Needed for self-referential structs and `Future` polling (which may hold references to its own fields). `Unpin` is a marker trait indicating a type can be safely moved. `!Unpin` types require explicit pinning.

R19 — Declarative macros (`macro_rules!`) use pattern matching and repetition for compile-time code generation. Procedural macros (derive, attribute, function-like) operate on Rust's AST. Hygiene ensures macros don't capture or leak identifiers from caller scope; variables are scoped to the macro expansion.

R20 — Zero-cost abstractions compile high-level features to efficient machine code. Iterators compile to tight loops with no intermediate allocations. Generics use monomorphization (specialized code per type), avoiding vtable overhead. Traits default to static dispatch. Result: C-like performance with safety and ergonomics.
