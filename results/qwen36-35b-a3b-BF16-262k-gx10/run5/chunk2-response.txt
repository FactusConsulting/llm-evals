K1 — A **Deployment** manages stateless workloads with interchangeable pods, random names, and no guaranteed ordering. A **StatefulSet** manages stateful workloads with stable, unique network IDs, ordered deployment/scaling, and stable persistent storage per pod.

K2 — A `ClusterIP` Service creates a virtual IP and port. `kube-proxy` watches the Service and its backing `Endpoints` (pod IPs), then programs `iptables` or `IPVS` rules on each node to DNAT traffic hitting the ClusterIP:Port to one of the healthy pod IPs using round-robin or least-connection balancing.

K3 — A **PersistentVolume (PV)** is a cluster-provisioned storage resource (static or dynamic). A **PersistentVolumeClaim (PVC)** is a user request for storage. A **StorageClass** defines a template for dynamic PV provisioning. A PVC binds to a PV (or triggers a SC to create one); once bound, the PVC acts as a mountable volume for pods.

K4 — 1. `kubectl logs <pod> --previous` to check crash exit codes/stack traces. 2. `kubectl describe pod` to inspect Events, OOMKilled status, or probe failures. 3. Verify resource requests/limits and node capacity. 4. Check external dependencies (DB connectivity, env vars, config mounts, startup scripts).

K5 — CoreDNS provides internal DNS resolution for `svc.namespace.svc.cluster.local` and pod FQDNs. If CoreDNS pods are down, internal service discovery and cross-namespace/pod DNS resolution fail entirely, though external DNS (e.g., 8.8.8.8) remains unaffected.

K6 — The scheduler first **filters** nodes that fail requirements (insufficient resources, taints, node selectors, affinity/anti-affinity). It then **scores** remaining nodes using priority functions. Factors include: LeastRequested (CPU/Mem), NodeAffinity/TaintToleration, PodTopologySpread, and ResourcePressure. The highest-scoring node is selected.

K7 — Yes, it will schedule: 3.5GB + 0.25GB (256Mi) = 3.75GB < 4GB. At runtime, if it uses 600Mi (>512Mi limit), the cgroup enforces the limit, triggers an OOMKilled event, and the container restarts (respecting CrashLoopBackOff).

K8 — Client → External LB (routes to Ingress Controller IP) → Ingress Controller (NGINX) parses Ingress resource → matches host/path → forwards to Kubernetes Service → Service resolves to Endpoints (pod IPs) → `kube-proxy`/`iptables` rules DNAT traffic to pod IP → pod receives request.

K9 — A `NetworkPolicy` restricts pod-to-pod and pod-to-external traffic. Default behavior: all traffic allowed. When applied to selected pods: all ingress/egress is denied by default; only explicitly permitted rules (by pod selector, namespace, or CIDR) are allowed.

K10 — `RollingUpdate` gradually replaces old pods with new ones (zero downtime). `Recreate` terminates all old pods before starting new ones (downtime). Choose `Recreate` for single-writer databases, stateful apps requiring atomic config/state replacement, or when zero-downtime isn't feasible.

K11 — A namespace provides logical isolation within a cluster. Default namespaces: `default`, `kube-system`, `kube-public`, `kube-node-lease`.

K12 — `kubectl describe pod` shows detailed runtime state, Events, Conditions, resource limits/requests, volume mounts, environment variables, and container statuses. `kubectl get pod` only shows basic status, age, and restart count.

K13 — A ConfigMap stores non-confidential configuration data. Pods consume it via: 1. Environment variables (`envFrom` or `env.valueFrom.configMapKeyRef`). 2. Volume mounts (files appear in the container filesystem).

K14 — `ClusterIP`: internal virtual IP, accessible only within the cluster. `NodePort`: exposes the service on a static port on each node's IP. `LoadBalancer`: provisions a cloud provider LB that routes to the NodePort/ClusterIP.

K15 — A DaemonSet ensures one pod runs on every node (or subset via selector). Use it for node-level daemons: logging agents, metrics collectors, network plugins, or storage drivers. Deployments manage a fixed replica count, not node-bound workloads.

K16 — **Taints** repel pods from nodes; **tolerations** allow pods to schedule on tainted nodes. **Node affinity** attracts pods to nodes with matching labels. Taints/tolerations = node-level exclusion (e.g., taint GPU nodes for ML workloads). Affinity = node-level preference/requirement (e.g., schedule to nodes with `zone=us-east-1`).

K17 — An Operator is a custom controller that manages complex, stateful applications using CRDs and custom reconciliation logic. Unlike standard controllers (which just match desired state), Operators handle lifecycle, upgrades, backups, and self-healing. It solves manual ops overhead for stateful services.

K18 — etcd uses **linearizable** consistency (serializable reads/writes). If quorum is lost, the cluster becomes read-only/unwritable. With 2/3 nodes permanently lost, the remaining node can't form quorum. Recovery: restore a recent snapshot on the surviving node (`etcdctl snapshot restore`), then rejoin/replace lost members.

K19 — RBAC uses Roles/ClusterRoles (define permissions) and RoleBindings/ClusterRoleBindings (grant them to users/groups/SAs). Manifest:
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: dev-ns
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: dev-pod-reader
  namespace: dev-ns
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

K20 — Default `ndots:5` causes the resolver to try 5 parent domains (e.g., `svc.cluster.local`, `cluster.local`) before falling back to external DNS, causing >5s timeouts. Fix: set `dnsConfig: { options: [{ name: "ndots", value: "1" }] }` in the pod spec, or append a trailing dot to external FQDNs.

D1 — `merge` creates a merge commit, preserving branch history. `rebase` rewrites commits onto a new base, linearizing history. Avoid rebasing on shared/public branches or when multiple developers are actively committing.

D2 — TCP is connection-oriented, reliable, ordered, and flow-controlled. UDP is connectionless, unreliable, unordered, and low-latency. TCP: HTTP, SSH, SMTP. UDP: DNS, VoIP, video streaming.

D3 — A race condition occurs when concurrent threads/processes access shared state without synchronization, yielding unpredictable results. Example: two threads incrementing a shared counter without a mutex, causing lost updates.

D4 — Symmetric encryption uses one key for encrypt/decrypt (fast). Asymmetric uses a public/private key pair (secure key exchange). TLS uses asymmetric encryption for the handshake/key exchange, then switches to symmetric encryption for bulk data transfer.

D5 — Each Dockerfile instruction creates a read-only image layer. Layer caching speeds builds by reusing unchanged layers. Best practice: order instructions from least to most frequently changing (e.g., copy dependency manifests first, install deps, then copy source code).

D6 — 1. Check upstream service logs/metrics for errors/throttling. 2. Verify resource limits (CPU throttling, OOMKilled). 3. Inspect liveness/readiness probe failures. 4. Review load balancer/connection pool limits or rate-limiting rules.

D7 — CAP theorem: a distributed system can only guarantee two of Consistency, Availability, Partition tolerance. CP example: CockroachDB/HBase (prioritize data accuracy during network splits). AP example: Cassandra/DynamoDB (prioritize availability, accept eventual consistency).

D8 — Horizontal scaling adds more nodes/instances; vertical scaling increases CPU/RAM of existing nodes. Horizontal scaling requires: stateless services, distributed databases, message queues, container orchestration, and load balancers.

D9 — An environment variable is a dynamic value passed to processes. Persist across sessions: add `export VAR=value` to `~/.bashrc` or `~/.profile`, then run `source ~/.bashrc`.

D10 — JSON is strict, syntax-heavy, and universally parsed in web APIs. YAML is indentation-based, human-readable, and supports comments. JSON advantage: strict parsing/universal API support. YAML advantage: readability/less boilerplate for configs.

D11 — REST is an architectural style using HTTP methods on resources. GET: retrieve. POST: create. PUT: replace/update. DELETE: remove.

D12 — Version pinning locks dependencies to exact versions (e.g., `package@1.2.3`). It ensures reproducible builds, prevents unexpected breaking changes, and guarantees CI/CD consistency.

D13 — Compiled languages translate source to machine code before execution (C, Rust). Interpreted languages execute source line-by-line via a runtime (Python, JavaScript). Note: many modern languages use JIT compilation.

D14 — A reverse proxy sits in front of servers, routing client requests to backends. A forward proxy sits in front of clients, routing outbound requests. Reverse proxies: Nginx/HAProxy (use case: load balancing, SSL termination). Forward proxies: Squid/Corporate proxy (use case: content filtering, caching).

D15 — A deadlock occurs when two+ processes wait indefinitely for each other's resources. Coffman conditions: 1. Mutual exclusion. 2. Hold and wait. 3. No preemption. 4. Circular wait.

D16 — Eventual consistency guarantees all replicas converge if no new updates. Cassandra uses tunable consistency levels (`ONE`, `QUORUM`, `ALL`, `LOCAL_QUORUM`). For read-after-write: use `QUORUM` for both reads/writes, or `SERIALIZABLE`/`LINEARIZABLE` (Cassandra 4+) to force strong consistency.

D17 — mTLS authenticates both client and server via X.509 certificates. Handshake: ClientHello → ServerHello+Cert → ServerKeyExchange → ClientKeyExchange+Cert → verify certs → derive session keys. Commonly used in: service meshes (Istio), internal microservices, zero-trust architectures.

D18 — A hash table maps keys to values via a hash function → array index. Collision resolution: chaining (linked lists per index) or open addressing (probing: linear/quadratic/double hashing). Average time: O(1). Worst case (all collide): O(n).

D19 — A circuit breaker prevents cascade failures by failing fast when a downstream service is unhealthy. States: Closed (normal), Open (fail fast after threshold), Half-open (test with limited requests). It should wrap retry logic to prevent retry storms; exponential backoff reduces load during recovery.

D20 — Optimistic concurrency assumes no conflicts, checks at commit (e.g., row versioning, `UPDATE ... WHERE version = ?`). Pessimistic concurrency locks resources during transactions (e.g., `SELECT FOR UPDATE`, `LOCK TABLES`). Choose optimistic for high-read/low-write workloads; pessimistic for high-write contention or critical consistency requirements.
