## Kubernetes

**K1** — A **Deployment** manages stateless workloads: pods are interchangeable, have random names, and are replaced in any order. A **StatefulSet** manages stateful workloads: pods have stable, unique network IDs, are deployed/terminated in strict order, and typically bind to stable PersistentVolumeClaims.

**K2** — The Service controller creates an `Endpoints` object mapping the ClusterIP:Port to backing pod IPs:Ports. `kube-proxy` on each node watches this and programs `iptables` or `IPVS` rules to load-balance traffic hitting the ClusterIP to the pod IPs. Traffic never leaves the node network unless a NodePort/LoadBalancer is used.

**K3** — A **PersistentVolume (PV)** is a cluster-wide storage resource (statically provisioned or dynamically created). A **PersistentVolumeClaim (PVC)** is a namespace-scoped request for storage by a user/pod. A **StorageClass** defines a template for dynamic PV provisioning. Relation: A PVC binds to a PV (or triggers a StorageClass to provision one). Pods consume storage by mounting the bound PVC.

**K4** — 1. `kubectl logs <pod> --previous` to check crash exit codes/stderr. 2. `kubectl describe pod` to inspect `Last State`, `Exit Code`, `OOMKilled`, and Events. 3. Verify resource limits/requests (CPU/Memory throttling or OOM). 4. Check application dependencies (DB connectivity, missing config files, invalid entrypoint/command).

**K5** — CoreDNS provides internal DNS resolution for `svc.cluster.local` and `cluster.local` domains. If CoreDNS pods are down, internal service discovery fails (pods can't resolve other services by name), but external DNS resolution (via host `resolv.conf`) continues to work.

**K6** — The scheduler uses **filtering** (predicate functions) to eliminate unsuitable nodes, then **scoring** to rank remaining nodes. Filters include: taints/tolerations, node selectors, resource requests, affinity/anti-affinity, volume constraints, and topology spread. Scoring factors include: least requested resources (balances load), node affinity weights, pod anti-affinity spread, and zone/node topology constraints.

**K7** — Yes, it will be scheduled. 3.5GB + 256Mi ≈ 3.75GB < 4GB available. At runtime, if the container uses 600Mi (>512Mi limit), the kubelet enforces the limit, triggers an OOMKilled event, and restarts the container.

**K8** — 1. Client hits External LB → routed to Ingress Controller NodePort/LoadBalancer IP. 2. Ingress Controller (NGINX) reads the Ingress resource, matches host/path rules. 3. Forwards request to the Kubernetes Service. 4. Service routes to its Endpoints (pod IPs). 5. `kube-proxy`/`iptables` on the target node redirects traffic to the pod's network namespace. 6. Pod's app handles the request.

**K9** — A `NetworkPolicy` restricts ingress/egress traffic to/from pods using label selectors. Default behavior (no policies): all traffic is allowed. When a policy is applied to a namespace, it denies all traffic by default for selected pods, only allowing traffic explicitly permitted by the policy's `ingress`/`egress` rules.

**K10** — **RollingUpdate** gradually replaces old pods with new ones, ensuring zero downtime. **Recreate** terminates all existing pods before starting new ones, causing downtime. Choose Recreate for stateful single-writer databases, apps requiring full config reloads, or when backward/forward compatibility isn't guaranteed.

**K11** — A namespace provides virtual cluster isolation (resource scoping, RBAC boundaries, network policies). Default namespaces: `default`, `kube-system`, `kube-public`, `kube-node-lease`.

**K12** — `kubectl describe pod` shows detailed runtime state. Three things `get` doesn't: 1. Pod events (scheduling failures, probe failures, OOMKilled). 2. Container conditions & probe status. 3. Mount details, environment variables, and resource requests/limits.

**K13** — A ConfigMap stores non-confidential configuration data. Pods consume it via: 1. Environment variables (`envFrom` or `env.valueFrom.configMapKeyRef`). 2. Volume mounts (files appear in the container filesystem).

**K14** — **ClusterIP**: internal-only virtual IP, accessible only within the cluster. **NodePort**: exposes the service on a static port on each node's IP, accessible externally. **LoadBalancer**: provisions a cloud provider's external load balancer, routes traffic to NodePort/ClusterIP.

**K15** — A DaemonSet ensures a copy of a pod runs on every node (or subset via node selector). Use it for node-level daemons: logging agents (Fluentd), monitoring (Prometheus node-exporter), CNI plugins, or storage daemons (Ceph/Rook). Deployments manage general application replicas.

**K16** — **Taints/Tolerations** are node-level: taints repel pods unless the pod explicitly tolerates them (push model). **Node Affinity** is pod-level: attracts pods to nodes matching labels (pull model). Use case taint: mark GPU nodes with `nvidia.com/gpu=true:NoSchedule`, tolerate only GPU pods. Use case affinity: schedule latency-sensitive pods to `topology.kubernetes.io/zone=us-east-1a`.

**K17** — An Operator is a custom Kubernetes controller that manages complex, stateful applications using Custom Resource Definitions (CRDs) and reconciliation loops. Unlike a standard controller (which just watches resources), an Operator encodes human operational knowledge (backups, upgrades, failover, scaling). It solves the manual ops burden for stateful workloads.

**K18** — etcd uses the Raft consensus algorithm, providing linearizable reads/writes. If quorum is lost, the cluster becomes read-only/unwritable. If 2/3 etcd nodes are permanently lost, quorum cannot be formed. Recovery requires restoring from a recent etcd snapshot/backup on a new node, or adding a new node and running `etcdctl snapshot restore`.

**K19** — RBAC controls access via Roles/ClusterRoles (define permissions) and RoleBindings/ClusterRoleBindings (bind roles to users/groups/serviceaccounts).
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: dev-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: dev-pod-reader
  namespace: dev-ns
subjects:
- kind: User
  name: developer@example.com
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — Default `ndots:5` in `/etc/resolv.conf` causes Kubernetes to append 5 suffixes (`svc.cluster.local`, `cluster.local`, etc.) to every DNS query, generating up to 5 queries per lookup. Fix: set `dnsConfig: options: [{name: "ndots", value: "2"}]` in the pod spec, or use fully qualified domain names with a trailing dot (`service.namespace.svc.cluster.local.`).

## Development

**D1** — `git merge` creates a merge commit, preserving full branch history. `git rebase` rewrites commit history by replaying branches onto a new base, creating a linear history. Avoid rebasing on shared/public branches or when collaborating, as it rewrites history and causes merge conflicts for others.

**D2** — **TCP**: connection-oriented, reliable, ordered, flow/congestion control. Used by: HTTP, SMTP, SSH. **UDP**: connectionless, unreliable, low-latency, no ordering guarantees. Used by: DNS, VoIP, video streaming, DHCP.

**D3** — A race condition occurs when concurrent threads/processes access shared state without synchronization, leading to non-deterministic results. Example: Two threads incrementing a shared counter without a mutex; final value may be less than expected due to lost updates.

**D4** — **Symmetric**: single shared key for encryption/decryption (fast, but key distribution is hard). **Asymmetric**: public/private key pair (secure key exchange, but slower). TLS uses asymmetric crypto for the handshake (authenticating server/client and exchanging a session key), then switches to symmetric crypto for bulk data encryption.

**D5** — A container image layer is an immutable filesystem snapshot created by each Dockerfile instruction. Layer caching speeds up builds: unchanged layers are reused. Best practice: order instructions from least to most frequently changing (e.g., copy dependency manifests first, install deps, then copy source code).

**D6** — Order: 1. Check upstream service logs/metrics for errors or high latency. 2. Verify rate limiting/throttling (API gateways, circuit breakers). 3. Check resource exhaustion (CPU/memory limits, connection pools). 4. Inspect network/connectivity to dependencies (DNS, DB, cache). 5. Review deployment health (crash loops, readiness probe failures).

**D7** — CAP theorem: a distributed system can guarantee at most two of Consistency, Availability, Partition tolerance. **CP**: Banking ledger, distributed SQL (HBase, CockroachDB) – prioritizes data accuracy over availability during network splits. **AP**: DNS, web caching, DynamoDB – prioritizes uptime, tolerates stale data during splits.

**D8** — **Horizontal scaling**: adding more nodes/instances. **Vertical scaling**: increasing CPU/RAM of existing nodes. Patterns enabling horizontal scaling: stateless services, distributed databases, message queues, load balancers, container orchestration, and sharding/partitioning strategies.

**D9** — An environment variable is a dynamic named value that affects process behavior. To persist across sessions on Linux: add `export VAR_NAME="value"` to `~/.bashrc` or `~/.profile`, then run `source ~/.bashrc`.

**D10** — **JSON**: strict syntax, key-value pairs, arrays. **YAML**: indentation-based, human-readable, supports comments. JSON advantage: strict parsing, universal language support. YAML advantage: readability, less verbose, easier for config files.

**D11** — A REST API is an architectural style using standard HTTP methods to interact with resources. **GET**: retrieve data. **POST**: create a new resource. **PUT**: update/replace an existing resource. **DELETE**: remove a resource.

**D12** — Version pinning locks dependencies to exact versions (e.g., `package@1.2.3` or `package==1.2.3`). It ensures reproducible builds, prevents unexpected breaking changes, and simplifies security auditing by knowing exactly what code is deployed.

**D13** — **Compiled**: source code is translated to machine code before execution (C, Rust, Go). **Interpreted**: source code is executed line-by-line by a runtime at execution time (Python, JavaScript, Ruby). Note: many modern languages use JIT compilation (Java, C#).

**D14** — A **reverse proxy** sits in front of backend servers, routing client requests to them. Used for: load balancing, SSL termination, caching (Nginx, HAProxy). A **forward proxy** sits in front of clients, routing outbound requests. Used for: content filtering, corporate anonymity, caching (Squid, corporate proxies).

**D15** — A deadlock occurs when two or more processes are permanently blocked, each waiting for a resource held by another. Coffman conditions: 1. Mutual exclusion, 2. Hold and wait, 3. No preemption, 4. Circular wait.

**D16** — Eventual consistency guarantees that if no new updates occur, all replicas will eventually converge. Cassandra uses tunable consistency levels: `ONE`, `QUORUM`, `ALL`, `LOCAL_QUORUM`, `SERIAL`. For read-after-write consistency, use `QUORUM` (or `LOCAL_QUORUM`) for both reads and writes, or `SERIAL`/`LINEARIZABLE` for strict ordering.

**D17** — mTLS authenticates both client and server using X.509 certificates. Handshake: ClientHello → ServerHello+Cert → ServerKeyExchange → ClientKeyExchange+Cert → CertificateVerify → Finished. Both sides verify each other's certs against a trusted CA. Commonly used in: service meshes (Istio/Linkerd), internal microservices, zero-trust architectures.

**D18** — A hash table maps keys to values via a hash function. Collision resolution: **chaining** (linked lists at each bucket), **open addressing** (probing: linear, quadratic, double hashing). Time complexity: Average O(1) for insert/lookup/delete. Worst O(n) if all keys collide or load factor approaches 1.0.

**D19** — A circuit breaker prevents cascade failures by failing fast when a downstream service is unhealthy. States: **Closed** (normal traffic), **Open** (fail fast, trip after error threshold), **Half-open** (allow limited test requests). Relates to retries: circuit breakers should wrap retry logic to prevent retry storms. Exponential backoff reduces load during recovery, giving the downstream service time to heal.

**D20** — **Optimistic**: assumes no conflicts, checks at commit (row versioning, `UPDATE ... WHERE version = old_version`). **Pessimistic**: locks resources during read/write (`SELECT ... FOR UPDATE`). Choose optimistic for high-read/low-write, low-conflict workloads. Choose pessimistic for high-write/conflict, critical consistency. Example: Optimistic uses `row_version` columns; Pessimistic uses explicit row locks via `FOR UPDATE` or advisory locks.
