G1 — An array has a fixed size baked into its type and is a value type (copied on assignment). A slice is a dynamic view over a contiguous backing array, consisting of a pointer, length, and capacity; it's a reference type. When `append` exceeds a slice's capacity, Go allocates a new backing array (typically doubling capacity), copies existing elements, and returns a new slice pointing to it.

G2 — `var x int` declares a variable with explicit type and zero value; `x := 0` is a short variable declaration that infers type. `:=` cannot be used at package scope, cannot redeclare an existing variable without introducing at least one new variable, and cannot be used in function signatures or type declarations.

G3 — A goroutine is a lightweight, multiplexed execution context managed by the Go runtime. Unlike OS threads (MB:1), goroutines use M:N scheduling with small initial stacks (~2KB) and cooperative yielding. The GMP model: G = goroutine, M = machine (OS thread), P = processor (scheduler context). Ps manage run queues, hand Gs to Ms, and use work-stealing to balance load.

G4 — Channels are typed conduits for safe goroutine communication. Unbuffered channels block both sender and receiver until the other is ready. Buffered channels have a fixed capacity; sends block only when full, receives block only when empty. Sending to a full buffered channel blocks until a receiver consumes an element or the channel is closed.

G5 — `context` propagates deadlines, cancellation signals, and request-scoped values across API boundaries. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
client.Do(req) // automatically cancels if timeout hits
```

G6 — Go uses implicit interface satisfaction (duck typing); types satisfy interfaces without explicit `implements` declarations. The empty interface `interface{}` (aliased as `any` in Go 1.18+) accepts any type. It enables generic-like flexibility but is dangerous because type assertions can panic at runtime and bypass compile-time type safety.

G7 — The code has a data race: `ready` and `data` are written in one goroutine and read in another without synchronization, violating Go's memory model. The spinloop `for !ready {}` also prevents compiler optimizations. Fix with `sync.Once` or `atomic.Bool` + `atomic.Value`, or signal via a channel to guarantee visibility.

G8 — `sync.Mutex` provides exclusive access; `sync.RWMutex` allows concurrent readers or a single writer. `sync.Map` is optimized for read-heavy workloads with keys known at compile time, or when writes are rare. Trade-off: `sync.Map` avoids lock contention for reads but has higher read latency and memory overhead; a regular `map` + `Mutex` is faster for frequent writes/updates or dynamic keys.

G9 — `go.mod` declares direct dependencies, Go version, and replace directives. `go.sum` stores cryptographic hashes of all direct/transitive dependencies for integrity verification. `go mod tidy` removes unused deps, adds missing ones, and updates `go.sum`. MVS (Minimum Version Selection) picks the lowest version of each module that satisfies all requirements, ensuring reproducible builds.

G10 — `defer` schedules a function call to run when the surrounding function returns. Multiple defers execute in LIFO order. Common loop gotcha: variables captured by deferred closures are evaluated at defer time, not loop iteration time. Fix by passing values as arguments (`defer fn(i)`) or scoping (`func() { defer fn(i) }()`).

G11 — A pointer holds a memory address. Its zero value is `nil`. Create a pointer to a struct literal with `&MyStruct{Field: value}`. Pointers enable mutation and avoid copying large structs.

G12 — `init()` runs automatically before `main()`, once per package. A package can have multiple `init()` functions across files; they execute in declaration order. Used for setup, registration, or precomputation. Cannot be called manually.

G13 — `make` initializes slices, maps, and channels, returning an initialized value (not a pointer). `new` allocates zeroed memory for any type and returns a pointer to it. `make` sets internal structures (e.g., map buckets, slice capacity); `new` just zero-fills.

G14 — Errors implement `error` interface with `Error() string`. Idiomatic: `if err != nil { return err }`. `errors.Is(err, target)` checks if `target` exists anywhere in the error chain (via `Unwrap`). `errors.As(err, &target)` checks if any error in the chain matches `target`'s type. `==` only checks direct equality, ignoring wrapped errors.

G15 — Map: nil map (read-only, write panics). Slice: nil slice (len=0, cap=0). Channel: nil channel (blocks forever on send/recv). Struct: zero values of each field. All are safe to use but require initialization for writes.

G16 — A race occurs when concurrent goroutines access shared data without synchronization, with at least one write. `-race` flag instruments the binary, tracking memory accesses and detecting races at runtime. Fix with `sync.Mutex` (wrap critical section) or channels (serialize access). Example: `mu.Lock(); counter++; mu.Unlock()`.

G17 — `select` waits on multiple channel operations, randomizing ready cases to prevent starvation. Unlike `switch`, it evaluates channel ops, not expressions. Timeout: `case <-time.After(d):`. If multiple cases are ready, one is chosen pseudo-randomly.

G18 — Escape analysis determines stack vs heap allocation. Variables escape if: address taken, size unknown at compile time, escapes to caller, or exceeds stack limit. Inspect with `go build -gcflags="-m"`. Matters because heap allocations trigger GC; stack allocations are zero-cost and faster.

G19 — `reflect` inspects/modifies types and values at runtime. `reflect.Type` holds type metadata; `reflect.Value` holds the runtime value. Costs: slow, bypasses compile-time checks, can panic. Justified for serialization, ORMs, or generic utilities. Prefer code generation (`go generate`, `stringer`) for performance-critical paths.

G20 — `//go:embed` embeds compile-time known files/directories into the binary. Works with patterns (`*.txt`, `dir/`). Returns `embed.FS`, which implements `io/fs.FS`. Limitations: only static files, no runtime generation, patterns limited to glob syntax. Enables zero-dependency static asset serving.

R1 — Ownership ensures memory safety without GC. Rules: 1) Each value has exactly one owner. 2) Only one owner at a time. 3) Owner drops value when out of scope. Transfers ownership via move semantics; copies via `Clone`.

R2 — `String` is heap-allocated, growable, and owned. `&str` is a borrowed, fixed-size reference to UTF-8 bytes. Use `String` when you need ownership/modification; use `&str` in signatures for borrowing/reading to avoid allocations.

R3 — Borrowing grants access without taking ownership. Rules: 1) Either one `&mut` or multiple `&` references, never both. 2) References must be valid (no dangling). 3) No aliasing mutable references. Enforced statically by the borrow checker.

R4 — `Result<T, E>` represents success/failure; `Option<T>` represents `Some(T)`/`None`. `?` unwraps `Ok`/`Some` or returns early on `Err`/`None`. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — `Box<T>`: heap-allocated, single owner, moves data. `Rc<T>`: reference-counted, single-threaded shared ownership. `Arc<T>`: atomic reference-counted, thread-safe shared ownership. Use `Box` for large/recursive types, `Rc` for shared read-only single-threaded, `Arc` for concurrent sharing.

R6 — Traits define behavior; unlike Go, they require explicit `impl Trait for Type`. `dyn Trait` creates a trait object (dynamic dispatch, vtable, heap-allocated, enables heterogeneous collections). `T: Trait` uses static dispatch (monomorphization, zero-cost, type-specific code).

R7 — Fails because the compiler can't infer which input lifetime applies to the output. Fix by annotating lifetimes:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — `Send`: types safe to transfer ownership across threads. `Sync`: types safe to share references across threads. `Rc<T>` isn't `Send`/`Sync` due to non-atomic ref count. `Arc<T>` uses atomic ref counting, making it `Send`+`Sync` (if `T` is).

R9 — `async/await` compiles to a state machine implementing `Future`. `Future::poll` advances execution; the executor (e.g., Tokio) drives polling, handles I/O, and schedules tasks. Differs from Go: Go uses preemptive M:N green threads (blocking syscalls yield), Rust uses cooperative async (explicit polling, non-blocking by design, executor-managed).

R10 — `unsafe` bypasses compile-time safety checks. Three actions: dereference raw pointers, call `unsafe` functions, implement `unsafe` traits, mutate `static mut`, access union fields. Justified for FFI, low-level hardware access, or performance-critical code where safety is proven.

R11 — Pattern matching exhaustively evaluates values. `match` requires all arms; `if let` is shorthand for one arm + optional `else`. Compiler enforces exhaustiveness in `match` (warns/errors if missing); `if let` doesn't require it.

R12 — `Vec<T>`: heap-allocated, growable. `[T; N]`: fixed-size, usually stack-allocated. When `Vec` exceeds capacity, it allocates a new buffer (typically doubling), copies elements, drops old buffer, and updates pointer.

R13 — Enums are algebraic data types with named variants that can hold data. Unlike C/Java, they're expressive and can be generic. `Option<T>` = `Some(T)` or `None`. Rust has no `null`; `Option` forces explicit handling, preventing null pointer exceptions.

R14 — `impl` blocks define methods/associated functions. `&self`: borrows, `&mut self`: mutable borrow, `self`: takes ownership. Associated functions (e.g., `String::new()`) don't take `self`, acting like constructors/static methods.

R15 — `#[derive]` auto-implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Can't derive if trait requires custom logic, contains non-derivable fields (e.g., `Fn`, raw pointers), or needs custom formatting/serialization.

R16 — `Cow<'a, T>` (Clone-on-Write) holds either borrowed `&'a T` or owned `T`. Useful when a function might return borrowed or owned data. Avoids allocation if input already matches expected format; only clones when mutation/modification is needed.

R17 — `mod` declares a module, `use` imports paths, `pub` exposes items. File system maps: `mod.rs` or `module/mod.rs`. Rust 2018 changed path resolution (`crate::`, `self::`, `super::`), made `use` paths relative to crate root, and removed `extern crate`.

R18 — `Pin<T>` guarantees a value's memory location doesn't move. Needed for self-referential structs and async/await (futures may hold references to their own fields). `Unpin` is a marker trait indicating a type is safe to move; most types are `Unpin`, but async futures are `!Unpin`.

R19 — Declarative macros (`macro_rules!`) transform syntax, are hygienic (no variable capture). Procedural macros: `derive` (struct/enum), `attribute` (custom attributes), `function-like` (invoked like functions). Hygiene ensures macro-generated identifiers don't leak or collide with surrounding scope.

R20 — Zero-cost abstractions compile high-level features to efficient machine code. Iterators: zero overhead, loop unrolling, no bounds checks. Generics: monomorphization generates type-specific code at compile time. Trait static dispatch: direct function calls, no vtable overhead. Achieves C-like performance with safety/ergonomics.
