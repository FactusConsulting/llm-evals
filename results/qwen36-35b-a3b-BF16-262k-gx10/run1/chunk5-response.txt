DN1 — **class vs struct**: `class` is a reference type allocated on the heap; `struct` is a value type typically allocated on the stack (or inline). `struct` should be used for small, immutable, short-lived data that represents a single logical value (e.g., `Point`, `Color`, `Vector3`), where copying semantics and stack allocation improve performance and avoid GC pressure.

DN2 — **IEnumerable<T> vs IQueryable<T>**: `IEnumerable<T>` executes queries in-memory; `IQueryable<T>` builds expression trees that can be translated to remote query languages (e.g., SQL). This matters for DB queries because `IQueryable<T>` pushes filtering, projection, and sorting to the database, preventing full table loads and reducing memory/network overhead.

DN3 — **async/await & Task vs ValueTask**: `async/await` compiles to a state machine that captures context and resumes continuations without blocking threads. `Task` always allocates a heap object; `ValueTask` is a `struct` that avoids allocation when the result is already available or computed synchronously. Use `ValueTask` in hot paths, caching layers, or when sync completion is frequent.

DN4 — **DI & Service Lifetimes**: DI containers manage object creation and disposal. `Transient`: new instance per resolution. `Scoped`: one instance per request/context. `Singleton`: one instance per app lifetime. **Captive dependency bug**: injecting a `Scoped` service into a `Singleton` causes the scoped service to live for the app's lifetime, leaking request-scoped state, connections, or memory.

DN5 — **string vs ReadOnlySpan<char>**: `string` is immutable, heap-allocated, and slicing creates new allocations. `ReadOnlySpan<char>` is a `ref struct` on the stack enabling zero-allocation slicing and memory-mapped access. Use `Span<T>`/`ReadOnlySpan<T>` for high-performance parsing, networking, or file I/O where avoiding allocations in hot paths is critical.

DN6 — **GC & IDisposable**: The GC manages managed heap memory using generations: Gen 0 (short-lived), Gen 1 (buffer), Gen 2 (long-lived). The Large Object Heap (LOH) stores objects >85KB and is compacted infrequently. `IDisposable` is required for unmanaged resources (file handles, DB connections, native memory) because the GC only tracks managed objects and cannot deterministically release OS resources.

DN7 — **ConfigureAwait(false)**: Prevents capturing/restoring the `SynchronizationContext` after an `await`. Use it in **libraries** to avoid deadlocks and improve throughput. Do NOT use it in **UI or ASP.NET request-scoped code** where context is needed for UI updates, `HttpContext`, or request-local services. It relates to `SynchronizationContext` by decoupling async continuations from the ambient execution context.

DN8 — **.NET 8/9 Features**: Primary constructors reduce boilerplate by injecting parameters directly into the type. Collection expressions (`[1, 2, 3]`) simplify array/span creation. `FrozenDictionary` provides highly optimized, immutable key-value lookups. Example with DI:
```csharp
public record MyService([FromKeyedServices("db")] IDbConnection conn);
// Registered via builder.Services.AddKeyedSingleton<IDbConnection>("db", new SqlConnection(...));
```

DN9 — **DbContext ObjectDisposedException**: Caused by leaking a `Scoped` DbContext outside its request scope (e.g., injected into a `Singleton`, or manually `new`'d). EF Core `DbContext` is not thread-safe and tracks state per request. Fix: resolve it strictly via DI within the request pipeline. DI scoping ensures one instance per HTTP request, preventing cross-request state corruption and disposal conflicts.

DN10 — **record vs class**: `record` is a reference type with value-based equality, immutability by default, and positional syntax. `record struct` is the value-type equivalent. Choose `record` for DTOs, domain events, or immutable data where equality semantics matter. Choose `class` for mutable entities, reference-identity semantics, or when inheritance + state is required.

DN11 — **ref, out, in**: `ref`: pass by reference, caller must initialize. `out`: pass by reference, method must assign before return. `in`: pass by reference, read-only. Use `ref` to modify existing values, `out` for multiple return values, `in` for large structs to avoid copies while preventing mutation.

DN12 — **Nullable Reference Types (NRT)**: `#nullable enable` activates compile-time nullability warnings. `?` annotates reference types as nullable. Differs from `int?` (nullable value type), which is a runtime struct (`Nullable<T>`) with `HasValue`/`Value`. NRTs are purely compile-time annotations with zero runtime overhead, improving safety without boxing.

DN13 — **LINQ & Deferred Execution**: LINQ unifies querying across data sources. Method syntax (`list.Where(...)`) is fluent and composable; query syntax (`from x in list where ...`) is SQL-like and compiles to method syntax. Deferred execution means the query isn't evaluated until enumerated (`foreach`, `ToList`, etc.), enabling composition, lazy evaluation, and remote translation.

DN14 — **Generic Constraints**: `where T : class` (reference type), `struct` (non-nullable value type), `new()` (parameterless constructor), `IComparable<T>` (implements interface). Combine with `&` (e.g., `where T : class, IComparable<T>, new()`). Use when the generic type must support specific operations, instantiation, or interface contracts.

DN15 — **abstract class vs interface**: Abstract classes can contain state, implementation, and constructors; interfaces define contracts. C# 8+ default interface methods allow implementation in interfaces, blurring the line, but abstract classes still support single inheritance + state, while interfaces support multiple implementation and decouple from inheritance hierarchies.

DN16 — **Middleware Pipeline**: Sequential request processing. `app.Use()` adds middleware that can call `next()` to pass control downstream. `app.Map()` branches routing. `app.Run()` is terminal. Ordering matters: auth/rate-limiting before routing, error handling early. Exception handling middleware (`UseExceptionHandler`) catches unhandled exceptions in downstream middleware and returns responses.

DN17 — **Channel<T>**: Async producer-consumer queue. Bounded channels apply backpressure by suspending producers when full. Differs from `BlockingCollection<T>` (sync, older). Example:
```csharp
var ch = Channel.CreateBounded<int>(100);
await ch.Writer.WriteAsync(item); // blocks/suspends if full
var item = await ch.Reader.ReadAsync(); // suspends if empty
```

DN18 — **Source Generators**: Compile-time code generation via Roslyn APIs. Unlike reflection (runtime) or IL weaving (post-compile), generators run during compilation, enabling IDE support and zero runtime overhead. Incremental generators (`IIncrementalGenerator`) track dependencies, cache results, and run per-file, drastically reducing compilation overhead vs legacy `ISourceGenerator`.

DN19 — **TPL Dataflow**: Async message-passing blocks. `ActionBlock` processes items (no output), `TransformBlock` processes and outputs, `BufferBlock` stores items. Compared to `Channels`, Dataflow provides built-in completion propagation, complex graph routing, and integrated backpressure, while Channels are lower-level and better for custom, lightweight pipelines.

DN20 — **Minimal APIs**: Lightweight, inline route handlers. Less boilerplate than controllers, no DI attributes needed. Trade-offs: complex logic harder to test, middleware must be explicitly chained, OpenAPI requires Swashbuckle/AutoGen. Route groups (`app.MapGroup("/api").WithTags("Users")`) organize endpoints. Endpoint filters (`WithFilter(...)`) inject cross-cutting logic (auth, validation) without middleware overhead.

P1 — **list vs tuple / set vs frozenset**: `list` is mutable, ordered; `tuple` is immutable, ordered. `set` is mutable, unordered, unique elements; `frozenset` is immutable, hashable, usable as dict keys or set elements.

P2 — **GIL**: Global Interpreter Lock allows only one thread to execute Python bytecode at a time. Severely impacts CPU-bound multithreading. Workarounds: `multiprocessing`, C-extensions that release the GIL, `asyncio` for I/O concurrency, or alternative runtimes (PyPy, GraalPy).

P3 — **deepcopy vs copy**: `copy` creates a shallow copy (new container, same nested objects). `deepcopy` recursively copies all nested objects. Example: `a = [[1]]; b = copy(a); b[0].append(2); a` becomes `[[1, 2]]` because the inner list is shared.

P4 — **Decorators**: Functions that wrap others to extend behavior. Execution time logger:
```python
import time
def timer(f):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = f(*args, **kwargs)
        print(f"{f.__name__}: {time.perf_counter()-start:.4f}s")
        return result
    return wrapper
```

P5 — **generators & yield**: `yield` pauses function execution, returning an iterator without storing all values in memory. Differs from lists by enabling lazy evaluation and constant memory usage. `yield from` delegates iteration to another generator, flattening nested iteration.

P6 — **asyncio event loop**: Single-threaded concurrency model. `asyncio.run()` starts the loop. `asyncio.gather()` runs coroutines concurrently and waits for all. `asyncio.create_task()` schedules a coroutine to run concurrently. `time.sleep()` blocks the entire loop; use `await asyncio.sleep()` to yield control.

P7 — **MRO**: Python 3 uses C3 linearization. Diamond inheritance resolves left-to-right, depth-first. MRO for `D(B, C)` is `D → B → C → A`. `B` inherits `who` from `A`, but `C` overrides it. `D().who()` follows MRO, finds `C.who()`, prints `"C"`.

P8 — **metaclass vs __init_subclass__**: Metaclass controls class creation (`__new__`/`__init__`), enabling class transformation (e.g., ORMs). `__init_subclass__` is a simpler, instance-level hook called when a class is subclassed. Use `__init_subclass__` for plugin registration or auto-configuration; use metaclasses for deep class-level introspection/modification.

P9 — **multiprocessing vs threading vs concurrent.futures**: Threading: I/O bound, GIL-limited. Multiprocessing: CPU bound, separate processes, memory isolation. `concurrent.futures`: high-level API wrapping both. Multiprocessing uses `pickle` for serialization; fails on lambdas, closures, or unserializable objects, requiring `spawn` or `forkserver` start methods.

P10 — **__slots__**: Restricts instance attributes to predefined names, preventing `__dict__` creation. Saves memory (~40-50%), speeds up attribute access. Prevents dynamic attribute assignment and breaks some inheritance patterns. Use for large numbers of instances with fixed schemas.

P11 — **virtual environment**: Isolated Python environment with its own packages/interpreter. Prevents dependency conflicts and system pollution. `venv`: stdlib, lightweight. `virtualenv`: third-party, more features. `conda`: package + env manager, handles non-Python deps, standard in data science.

P12 — **comprehensions vs map/filter**: Comprehensions (`[x for x in lst if cond]`) are Pythonic, often faster, and more readable. `map`/`filter` return iterators, useful for functional style or lazy evaluation. Prefer comprehensions for simple transformations/filtering; use `map`/`filter` when composing functions or working with large streams.

P13 — **== vs is**: `==` checks value equality; `is` checks object identity. Object interning caches small integers (-5 to 256) and short strings. `a is b` returns `True` for interned objects because they reference the same memory address.

P14 — **\*args/\*\*kwargs & parameter markers**: `*args` packs positional args into a tuple; `**kwargs` packs keyword args into a dict. `/` forces positional-only parameters; `*` forces keyword-only after it. Improves API clarity, prevents accidental argument swapping, and enables strict typing.

P15 — **context managers**: Ensure deterministic cleanup. Class-based: implement `__enter__`/`__exit__`. Function-based: use `@contextmanager` with `yield`. Example beyond files: database transaction management, thread locks, temporary directory creation, or HTTP request session handling.

P16 — **type hinting**: Static annotations for runtime-free type checking. `Union`/`Optional`/`Literal`/`TypeVar`/`Protocol` express complex types. `mypy`/`pyright` parse annotations, perform static analysis, catch mismatches pre-runtime, and enable IDE autocomplete/refactoring.

P17 — **data model/dunder methods**: `__repr__` (dev/debug, unambiguous), `__str__` (user-friendly). `__eq__` vs `__hash__`: defining `__eq__` without `__hash__` sets `__hash__` to `None`, making objects unhashable. `__getattr__` (fallback), `__getattribute__` (always called). Override both for custom attribute resolution.

P18 — **descriptors**: Objects implementing `__get__`, `__set__`, `__delete__` that control attribute access. `property`, `classmethod`, `staticmethod` are descriptors. Under the hood, class attributes are descriptor instances; attribute access routes through `__get__`/`__set__`, enabling lazy loading, validation, and computed properties.

P19 — **import system**: `sys.path`/`PYTHONPATH` define search paths. `__init__.py` marks packages (optional in Python 3.3+ for implicit namespace packages). Relative (`.`) vs absolute (`pkg.mod`) imports. `Finder` locates modules; `Loader` loads/executes them. `importlib` provides the runtime API.

P20 — **dataclasses vs attrs/Pydantic**: `dataclasses` (stdlib, lightweight, mutable by default). `attrs` (third-party, more features). `Pydantic` (validation, serialization, type coercion). `__post_init__` runs after init. `field()` supports defaults/factories. `frozen=True` enables immutability. Choose Pydantic for API validation, serialization, runtime type checking, and complex defaults.
