JS1 — `var` is function-scoped, hoisted, and re-declarable. `let`/`const` are block-scoped, hoisted but in a Temporal Dead Zone (TDZ), and not re-declarable in the same scope. `const` prevents reassignment (not immutability). Hoisting moves declarations to the top of their scope during compilation; `var` initializes as `undefined`, while `let`/`const` remain uninitialized until execution reaches them.

JS2 — The event loop continuously checks the call stack and queues. When the stack is empty, it processes the microtask queue (Promises, `queueMicrotask`, `MutationObserver`) first, then one macrotask (setTimeout, setInterval, I/O, UI rendering). Microtasks run to completion before the next macrotask, ensuring async promise chains resolve before timers.

JS3 — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: `function makeCounter() { let i=0; return () => ++i; }`. Classic bug: `for (var i=0; i<3; i++) setTimeout(()=>console.log(i), 0)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped), IIFE, or `setTimeout`'s 3rd argument.

JS4 — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that pauses execution until the promise settles, making code synchronous-looking. Error handling: `try/catch` with `await`, or `.catch()`/`.then(null, err)` with promises. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all, returning `{status: 'fulfilled'|'rejected', value|reason}` for each.

JS5 — `interface` defines object shapes, supports declaration merging, and cannot contain runtime code. `type` is a broader alias supporting unions, intersections, tuples, and mapped types. Use `interface` for public APIs/objects, `type` for primitives/unions. Discriminated unions use a common literal property (tag) to narrow types: `type Shape = {kind: 'circle'; radius: number} | {kind: 'square'; size: number}; switch(s.kind) { case 'circle': ... }`.

JS6 — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar: `class A extends B` sets `A.prototype.__proto__ = B.prototype`, and `super` calls parent constructors/methods. No new inheritance model is introduced.

JS7 — `this` is dynamically bound based on call site. Priority rules: 1. `new` (constructor), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (`window`/`undefined` in strict mode). `bind()` returns a new function with `this` permanently bound. It cannot be re-bound; subsequent `call`/`apply` are ignored.

JS8 — `WeakRef` holds a weak reference that doesn't prevent garbage collection. `FinalizationRegistry` registers callbacks when weakly referenced objects are collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the GC can track when keys become unreachable and clean up entries. Primitives can't be weakly referenced because they're immutable and always reachable.

JS9 — V8 optimizes via: Hidden Classes (shape optimization for fast property access), Inline Caching (caches shape info at call sites to skip prototype lookups), and Deoptimization (reverts to slower code when assumptions break). Deopt triggers: dynamic property addition/deletion, type changes, `delete`, `with`, `eval`, or modifying `arguments`.

JS10 — Tree-shaking removes unused exports at build time. It works with ES Modules because `import`/`export` are static, lexical, and analyzable at parse time. CommonJS uses dynamic `require()` and `module.exports`, which can be conditional or runtime-evaluated, preventing static analysis and safe removal.

JS11 — `null` is intentional absence; `undefined` is uninitialized/missing. `==` coerces types (`null == undefined` is true); `===` checks type+value (false). `??` returns right operand only if left is `null`/`undefined` (unlike `||` which checks falsy). `?.` safely accesses nested properties without throwing on `null`/`undefined`.

JS12 — `map()` transforms, `filter()` keeps matching elements, `reduce()` accumulates to a single value. `reduce()` with initial value prevents errors on empty arrays and sets accumulator type. `flatMap()` maps then flattens one level; useful for transforming arrays and flattening results simultaneously (e.g., splitting strings into words).

JS13 — Template literals use backticks, support `${expr}` interpolation and multi-line strings. Tagged templates call a function with the first arg as a string array and remaining args as substitution values. Example: `function html(strings, ...vals) { return strings.reduce((acc, s, i) => acc + s + (vals[i]||'').replace(/&/g,'&amp;'), ''); }`.

JS14 — Destructuring unpacks values: `{a, b: renamed} = obj`, `[a, b] = arr`. Default values: `a = 1`. Rest operator: `const {a, ...rest} = obj` collects remaining properties. Works in function parameters too. Prevents verbose property access and enables clean API signatures.

JS15 — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, Maps). Avoid `for...in` on arrays because order isn't guaranteed, it includes inherited properties, and it yields keys not values.

JS16 — Generics use type parameters for reusable code. Constraints: `T extends SomeType` limits T. Conditional types: `T extends U ? X : Y` for branching. `infer` extracts types in conditional contexts. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T; type A = Unpack<Promise<string>>; // string`.

JS17 — CommonJS (CJS) uses `require()`/`module.exports`, is synchronous, dynamic, and Node.js legacy. ES Modules (ESM) use `import`/`export`, are static, async, and standard. Node.js supports both via `.mjs` extension or `"type": "module"` in `package.json`. ESM enables tree-shaking and top-level await; CJS remains for compatibility.

JS18 — TS uses structural typing: compatibility based on shape, not names. Excess property checks apply only to object literals assigned directly to variables/types, not to properties accessed later. `extends` checks assignment compatibility. `satisfies` (TS 4.9+) checks type without widening, preserving original type. Variance (`in`, `out`, `in out`) explicitly controls parameter/return type compatibility (TS 4.7+).

JS19 — `Proxy` wraps objects to intercept operations (get, set, apply, etc.). `Reflect` mirrors Proxy traps and provides default behavior. Example: validation proxy using `set` trap to check types. Intercept function calls via `apply` trap. Useful for reactive data binding, logging, or immutable state.

JS20 — `SharedArrayBuffer` enables shared memory between main thread and Web Workers. `Atomics` provides atomic operations and synchronization. Ordering: sequential consistency for atomic ops. `Atomics.wait` blocks until value changes or timeout. `Atomics.notify` wakes waiting threads. Requires Cross-Origin Isolation headers (`Cross-Origin-Opener-Policy`, `Cross-Origin-Embedder-Policy`).

B1 — `$@` preserves each argument as a separate word when quoted `"$@"`. `$*` joins all args into a single string using the first character of IFS. `"$@"` is safe for iteration; `"$*"` breaks on spaces/globs.

B2 — `set -e`: exit on command failure. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the rightmost non-zero exit code. Together, they prevent silent failures and undefined behavior.

B3 — `$(command)` is preferred over `` `command` ``: supports nesting, easier to read, POSIX-compliant. `$((expression))` is shell arithmetic expansion. `expr` is an external command, slower, and unsafe with special characters or negative numbers.

B4 — Process substitution `<(command)` creates a temporary file descriptor. Used when a command expects a file but needs dynamic input. Example: `diff <(sort file1) <(sort file2)` compares sorted files without creating temp files.

B5 — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous because it splits on spaces/newlines, expands globs, and runs `ls` before the loop, losing filenames starting with `-`.

B6 — Here document `<<EOF` passes multi-line input to a command. Here string `<<<` passes a single line. `<<-EOF` strips leading tabs (not spaces) for indentation, keeping scripts readable.

B7 — `cmd > file 2>&1`: stdout goes to file, then stderr follows stdout to file. `cmd 2>&1 > file`: stderr goes to terminal (stdout's original location), then stdout goes to file. `cmd &> file` is bash shorthand for the first. Redirections evaluate left-to-right, causing the difference.

B8 — ```bash
lock_dir=$(mktemp -d)
trap 'rm -rf "$lock_dir"' EXIT
mkdir "$lock_dir" || { echo "Already locked"; exit 1; }
# Critical section
```
`mkdir` is atomic on POSIX filesystems, avoiding TOCTOU race conditions. `trap` ensures cleanup on exit/signal. `mktemp -d` guarantees uniqueness.

B9 — Single quotes `'...'`: literal, no expansion. Double quotes `"..."`: allow `$`, `` ` ``, `\`, `!`. No quotes: word splitting and globbing. Example: `var="hello world"; echo '$var' → $var; echo "$var" → hello world; echo $var → hello world`.

B10 — Check: `[ -f "$f" ]`, `[ -d "$f" ]`, `[ -r "$f" ]`. `[[ ]]` is a bash builtin: supports `&&`, `||`, regex, no word splitting/globbing. `[ ]` is POSIX `test`: stricter, requires spaces, no advanced features.

B11 — `$?`: exit status of last command. `$$`: PID of current script. `$!`: PID of last background job. `$#`: number of positional parameters.

B12 — Functions: `foo() { ... }` (POSIX) or `function foo { ... }` (bash). Prefer `foo() {}`. Return values: `return <int>` (0-255 exit code) or `echo`/`printf` for stdout capture. Use `return` for status, stdout for data.

B13 — `PATH` is colon-separated dirs bash searches for executables. Resolution order: builtins → hash table → `PATH`. Builtin: part of shell (`cd`, `echo`). External: separate binary. Check with `type` or `command -v`.

B14 — `trap` registers handlers: `trap 'cleanup' EXIT INT TERM`. `ERR` runs on non-zero exit. Execution order: most recent trap for a signal runs first; `EXIT` runs last. Signals interrupt current command; handlers run synchronously.

B15 — `xargs` runs commands multiple times with args, handles whitespace safely. `find ... -print0 | xargs -0 cmd` handles spaces/newlines. `-P N` runs N processes in parallel. Command substitution `$(cmd)` loads all output into memory first.

B16 — Arrays: `arr=(a b c)`, `${arr[0]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${!assoc[@]}`. Associative requires `declare -A`, supports string keys, and lacks numeric indexing.

B17 — Subshell `(...)`: runs in child process, variable changes lost. Group `{ ...; }`: runs in current shell, variables persist. Piping to `while` creates a subshell, so loop vars don't persist. Fix: `while ... done < <(cmd)` or `cmd | while ... done` with process substitution.

B18 — Signals: SIGINT (Ctrl+C, interrupt), SIGTERM (graceful stop), SIGHUP (terminal close/reload), SIGKILL (force kill, uncatchable). Handle graceful shutdown: trap TERM/INT, kill background jobs, `wait`, cleanup. Use `wait` to block until children finish.

B19 — ```bash
split -l 10000 log.log log_part_
find . -name "log_part_*" -print0 | xargs -0 -P 4 -I {} bash -c 'process "$1" && echo "OK: $1" || echo "FAIL: $1"' _ {}
cat log_part_*_result > merged.log
```
Trade-offs: CPU vs I/O bound, overhead of splitting/merging. Error propagation: check exit codes, use `set -o pipefail`, aggregate errors, or use `xargs -P` with a wrapper script that exits non-zero on failure.

B20 — `exec` replaces the current shell process or redirects FDs. `exec 3>file` opens FD 3. `exec 3>&-` closes it. Coprocess: `coproc cmd` runs cmd in background, connects stdin/stdout to FDs. Use for persistent background services or IPC without temp files.

PS1 — `Write-Output` sends objects to the pipeline, respecting `$OutputEncoding`. `Write-Host` writes directly to the console, bypassing the pipeline. This distinction matters for scripting/automation where output must be captured or chained.

PS2 — Pipeline streams objects. `ForEach-Object` is a cmdlet, processes one object at a time, supports `-Parallel` (v7). `foreach` statement is a language construct, faster, loads all into memory first. Use `ForEach-Object` for streaming/large data, `foreach` for small collections.

PS3 — `[PSCustomObject]` is strongly typed, ordered, pipeline-friendly, supports methods/properties. Hashtable is unordered, key-value, less pipeline-friendly. Convert: `[PSCustomObject]@{a=1}` or `@{a=1} | ForEach-Object {[PSCustomObject]$_}`.

PS4 — Terminating errors stop execution and are caught by `try/catch`. Non-terminating errors continue and are logged to `$Error`. `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors; convert non-terminating with `-ErrorAction Stop`.

PS5 — Splatting passes a hashtable as named parameters: `@{Path="."; Recurse=$true} | Get-ChildItem`. Differs from single param: passes multiple named params cleanly, improves readability, supports dynamic params, and avoids quoting issues.

PS6 — `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` is interactive. Uses WinRM (HTTP/HTTPS) by default, SSH in PS7+. Handles auth, serialization, session management, and firewall traversal.

PS7 — Returns an array of strings. `$x.GetType().Name` → `Object[]`. Returns 0 items → `$null`. Correct pattern: `$result = [System.Collections.Generic.List[string]]::new()` or force array `$result = ,@()`. Avoid `$result +=` in loops.

PS8 — `[scriptblock]` is anonymous code; function is named. Pass to remote: `Invoke-Command -ScriptBlock $sb -ArgumentList $args`. Double-hop: auth fails when remoting to a second server. Solve with CredSSP (less secure), `-ArgumentList` to pass data, or constrained endpoints.

PS9 — `@()` forces array. `[array]` casts. Indexing `$null` → `$null`. Indexing `@()` → `$null`. Safe: `$arr[0]` works on both. `@()` prevents scalar expansion and ensures consistent pipeline behavior.

PS10 — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive: `-ceq`, `-clike`, etc. `-contains` checks if collection has item; `-in` checks if item is in collection.

PS11 — Module: collection of functions/cmdlets. `.psm1`: script module code. `.psd1`: manifest (metadata, dependencies, exports). Binary: compiled DLL. `Import-Module` loads, checks paths, runs `.psd1` if present, exports functions, and manages versioning.

PS12 — Interpolation: `"Hello $name"` expands variables. `'...'` literal. Expressions: `"Value: $(Get-Date)"`. Here-string: `@"..."@` for multi-line, preserves formatting, supports interpolation.

PS13 — `Get-Member` explores object members. Properties (data), Methods (actions), NoteProperties (custom added). `Select-Object` picks properties/creates calculated. `Where-Object` filters objects. Use `Select-Object` for projection, `Where-Object` for filtering.

PS14 — Classes (v5+): define types, properties, methods. Limitations: no multiple inheritance, limited interface support, constructors must match signature, no access modifiers (public by default). Use classes for complex data/models, functions for scripting.

PS15 — `CmdletBinding` enables advanced features. `SupportsShouldProcess`: -WhatIf/-Confirm. `DefaultParameterSetName`: parameter groups. `ValueFromPipeline`: accepts pipeline input. `Begin`/`Process`/`End`: lifecycle blocks for streaming processing.

PS16 — Providers abstract data stores. `Get-ChildItem` works on FileSystem, Registry, Env, Cert. Registry accessed as `HKLM:\SOFTWARE\...`. Providers expose consistent cmdlets across stores, enabling uniform scripting.

PS17 — Runspaces: execution environments. `[runspace]`: single thread. `[runspacepool]`: thread pool. `[powershell]`: adds pipeline/cmdlet layer. `ForEach-Object -Parallel` (v7+) uses runspace pool automatically. Manual: create pool, add runspace, invoke, manage concurrency.

PS18 — PSScriptAnalyzer: linting tool. Rules: syntax, performance, best practices. Severity: error, warning, info. Suppress: `#pragma disable`, `.psakefile`. CI/CD: run in pipeline, fail on errors, enforce standards, integrate with VS Code/VS.

PS19 — `$using:` serializes variable into remote/job/parallel context. `-ArgumentList` passes as args to scriptblock. Serialization limits: CLIXML depth/size (typically 64), complex objects may fail. Use `-ArgumentList` for large/complex data, or save to temp file.

PS20 — DSC: declarative config. Configurations: desired state. Resources: building blocks (File, Service). LCM: applies config, checks drift. WinPS vs PS7: PS7 uses OpenDSC, cross-platform. Replaced by: Ansible, Terraform, Chef, or native cloud IaC.
