## Go

G1 — Easy: A **slice** is a descriptor containing a pointer to an underlying array, a length, and a capacity. An **array** has a fixed size known at compile time. When you append to a slice that has reached its capacity, Go allocates a new, larger underlying array, copies the existing elements over, and updates the slice's pointer/capacity.

G2 — Easy: `var x int` declares a variable with the zero value (0) and can be used at package or function level. `x := 0` is a short declaration that infers the type from the right side; it can only be used inside functions. You cannot use `:=` if the variable is already declared in the same scope or at the package level.

G3 — Medium: A **goroutine** is a lightweight thread managed by the Go runtime, not the OS. They have smaller stacks and faster context switching than OS threads. The **GMP model** consists of **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts). P maps Gs onto Ms to balance work across available CPU cores.

G4 — Medium: Channels are typed conduits for communication between goroutines. A **buffered channel** allows sending values without waiting for a receiver until the buffer is full. An **unbuffered channel** blocks the sender until a receiver is ready. Sending to a full buffered channel blocks the sender until space becomes available.

G5 — Medium: Context is used for deadlines, cancellation signals, and passing request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel() // Ensure resources are freed
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
```

G6 — Medium: Go uses **implicit satisfaction**: any type that implements the methods of an interface satisfies it automatically. This differs from Java/C# which require explicit `implements`. `interface{}` (any) can hold any value but loses type safety, requiring frequent type assertions or reflections, making it dangerous if not handled carefully.

G7 — Hard: The memory model does not guarantee visibility of non-atomic writes across goroutines without synchronization. The example is unsafe because there is no "happens-before" relationship established; the CPU might reorder instructions or cache the value of `ready` in a register. Correct alternatives include using `sync.Mutex`, `atomic.Bool`, or a channel.

G8 — Hard: `sync.Mutex` allows exclusive access; `sync.RWMutex` allows multiple concurrent readers OR one writer. Use `sync.Map` for high-concurrency scenarios with many cores where keys are stable and reads heavily outweigh writes. Performance trade-offs: `sync.Map` reduces lock contention on multi-core systems by using atomic operations instead of heavy mutexes for common cases.

G9 — Hard: Go modules manage dependencies via `go.mod` (defines requirements) and `go.sum` (verifies integrity). `go mod tidy` removes unused deps and adds missing ones. **MVS** (Minimum Version Selection) selects the highest version allowed by all constraints in the dependency graph to ensure reproducible builds.

G10 — Medium: `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in LIFO (Last-In, First-Out) order. A common gotcha: if you use `defer` inside a loop that performs an operation like closing a file, the defer won't trigger until the *entire* function finishes, potentially exhausting resources.

G11 — Easy: A pointer holds the memory address of a value. The zero value is `nil`. You create a pointer to a struct literal using the address-of operator: `p := &MyStruct{Field: 1}`.

G12 — Easy: `init()` runs automatically before `main()`. It can be called multiple times in one package; they execute in lexical order (alphabetical order of filenames, then declaration order within files).

G13 — Easy: `new(T)` allocates zeroed memory for type T and returns a pointer (`*T`). `make(T)` initializes complex types—slices, maps, and channels—and returns the initialized instance itself. Both work with any type, but only `make` works on slices/maps/channels.

G14 — Easy: Errors are values implementing the `error` interface. Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error matches a specific target (like `io.EOF`), while `errors.As` checks if an error wraps a specific type and extracts it into a variable.

G15 — Easy: Built-in composite types:
- **Map**: Zero value is `nil` (not usable until `make`).
- **Slice**: Zero value is `nil` (usable as read-only or appended to).
- **Channel**: Zero value is `nil` (blocks forever on send/receive).
- **Struct**: Zero value has all fields set to their respective zero values.

G16 — Medium: A race condition occurs when two goroutines access shared memory simultaneously where at least one is a write. The `-race` flag uses instrumentation to detect unsynchronized access during execution. Fix: Use `sync.Mutex` to lock the critical section or use a channel to pass ownership of data between goroutines.

G17 — Medium: `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, which evaluates expressions, `select` blocks until one case can proceed. If multiple cases are ready, Go picks one pseudo-randomly. Timeout implementation: `case <-time.After(duration):`.

G18 — Hard: Escape analysis determines if a variable lives on the stack (fast) or heap (GC overhead). It decides based on whether a variable's lifetime exceeds the function scope or if it's too large for the stack. Inspect with `go build -gcflags="-m"`. This matters because excessive heap allocation increases GC pressure and latency.

G19 — Hard: Reflection allows inspecting types and values at runtime. `reflect.Type` describes metadata; `reflect.Value` holds actual data. Performance cost is high due to dynamic dispatch/boxing. Reflection is justified for generic libraries (like JSON encoders), but code generation is preferred for performance-critical paths.

G20 — Hard: `go:embed` allows compiling static assets into the binary. It works for files and directories by creating an `embed.FS`. Limitations include OS path limits and file size constraints in certain environments. It integrates with `io/fs.FS` to provide a standard interface for accessing embedded content.

## Rust

R1 — Easy: Ownership is Rust’s memory management system. Rules: 1. Each value has a variable called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped (memory freed).

R2 — Easy: `String` is owned, heap-allocated, and growable. `&str` is a string slice (a reference to a sequence of UTF-8 bytes). Use `String` when you need to own/mutate data; use `&str` as function arguments to allow both `&str` and `&String` inputs efficiently.

R3 — Medium: Borrowing lets you access data without taking ownership. Rules: You can have either **one** mutable reference (`&mut T`) OR **any number** of immutable references (`&T`). You cannot have a mutable reference while any immutable references exist.

R4 — Medium: `Result<T, E>` handles errors (Success or Error); `Option<T>` handles presence (Some or None). The `?` operator returns early if an error occurs in a Result or None in an Option.
```rust
use std::fs;
fn read_file(path: &str) -> std::io::Result<String> {
    let content = fs::read_to_string(path)?; // Returns Err early if file fails
    Ok(content)
}
```

R5 — Medium: `Box<T>` provides heap allocation for single ownership. `Rc<T>` provides reference counting for shared ownership in a *single* thread. `Arc<T>` is the atomic version of `Rc`, allowing shared ownership across multiple threads.

R6 — Medium: Traits define shared behavior (like Go interfaces but explicit). A trait object (`dyn Trait`) uses dynamic dispatch (vtable), incurring a small runtime cost. A generic with a trait bound (`T: Trait`) uses monomorphization (static dispatch), generating specific code for each type used, which allows for compiler optimizations like inlining.

R7 — Hard: Lifetimes ensure references don't outlive their data. This fails because the return value could point to either `x` or `y`, and the compiler can't prove which one lives longer. Fix by adding lifetime annotations:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { ... }
```

R8 — Hard: `Send` means a type can be moved to another thread; `Sync` means it can be shared between threads. `Rc<T>` isn't `Send`/`Sync` because its internal counter is not updated atomically, leading to race conditions. `Arc<T>` makes this safe by using atomic operations for reference counting.

R9 — Hard: Rust async/await transforms functions into state machines that implement the `Future` trait. An executor (like Tokio) polls these futures to progress them. Unlike Go’s M:N scheduler where goroutines are preemptive, Rust’s async is cooperative—tasks only yield when they hit an `.await`.

R10 — Medium: `unsafe` allows bypassing some compiler checks. You can: 1. Dereference raw pointers. 2. Call unsafe C functions. 3. Access mutable static variables. It is justified for low-level systems programming, FFI, or high-performance data structures where safety is manually verified.

R11 — Easy: Pattern matching allows branching based on structure. `match` must be exhaustive (all possible cases covered). `if let` is used for simple "do something if this matches" logic without needing to handle all other branches.

R12 — Easy: `Vec<T>` is a heap-allocated growable array; `[T; N]` is a fixed-size stack-allocated array. When pushing beyond capacity in a `Vec`, it reallocates a larger block of memory and copies elements over.

R13 — Easy: Rust enums are **sum types** (tagged unions), allowing variants to hold different data types. In C/Java, enums are usually just integers. `Option<T>` represents the presence of a value, replacing null with a type-safe way to represent "nothing."

R14 — Easy: An `impl` block defines methods for a type. `&self` borrows immutably, `&mut self` borrows mutably, and `self` consumes the instance (moves ownership). Associated functions (like `String::new()`) do not take any `self` argument.

R15 — Easy: The `derive` macro automatically implements traits like `Debug` (printing), `Clone` (deep copy), `PartialEq` (equality), and `Serialize`. You cannot derive traits that require manual implementation of complex internal logic or those involving non-public fields.

R16 — Medium: `Cow<'a, T>` (Copy on Write) allows you to work with borrowed data but switch to owned data only if modification is needed. It avoids unnecessary allocations when data is only read, which is common in high-performance string processing.

R17 — Medium: `mod` declares a module; `use` brings it into scope; `pub` makes it visible outside its parent. Rust 2018 edition simplified this by allowing modules to be defined in separate files more naturally without requiring nested directory structures as strictly.

R18 — Hard: `Pin<T>` ensures that an object's memory address won't change. This is required for "self-referential" structs created by async state machines where pointers point to other parts of the same struct. `Unpin` is a marker trait indicating a type can safely be moved even if pinned.

R19 — Hard: Declarative macros (`macro_rules!`) perform pattern matching/substitution. Procedural macros are functions that take code as input and produce new code (derive, attribute, function-like). Hygiene refers to how macros handle variable scoping to avoid name collisions.

R20 — Hard: Zero-cost abstractions mean features like iterators or generics don't add runtime overhead compared to manual loops. Iterators compile down to efficient machine code; monomorphization generates specialized versions of generic functions; static dispatch via traits allows the compiler to inline calls across boundaries.
