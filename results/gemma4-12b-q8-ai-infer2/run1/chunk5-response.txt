## .NET / C#

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
A **class** is a reference type (allocated on the heap); a **struct** is a value type (usually allocated on the stack or inline within another object). 
*Use a struct when:* The data is small (e.g., a Point, Color), represents a simple data value, is immutable, and has a short lifecycle. Avoid structs for large objects as copying them on every pass can degrade performance.

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
`IEnumerable<T>` is for in-memory iteration; it executes the query and brings all results into memory before filtering/processing. `IQueryable<T>` allows for **Expression Tree** evaluation, meaning filters (like `.Where()`) are translated into SQL and executed by the database provider. This matters because `IEnumerable` could cause massive over-fetching of data from the DB to the app's RAM.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
`async/await` uses a state machine generated by the compiler to suspend execution without blocking the thread. A `Task` is an object allocated on the heap representing an operation. `ValueTask` is a value type used to reduce allocations. Use `ValueTask` when the result is often available synchronously or when high-frequency operations would create excessive GC pressure from many small `Task` objects.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
*   **Transient:** New instance every time requested.
*   **Scoped:** New instance per request (e.g., per HTTP request).
*   **Singleton:** One instance for the lifetime of the application.
*   **Common Bug:** "Captive Dependency." If you inject a Scoped service into a Singleton, the Scoped service lives as long as the Singleton (the whole app life), effectively turning it into a Singleton, which can cause issues with database connections or multi-threading errors.

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
A `string` is an immutable heap object; slicing a string creates a new string copy. `ReadOnlySpan<char>` provides a view into a contiguous memory region without allocating new memory on the heap. Use `Span<T>` for high-performance parsing (like CSV/JSON parsers) to avoid excessive allocations and reduce GC pressure.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
The GC uses a generational approach: **Gen 0** (short-lived objects like local variables), **Gen 1** (buffer zone), and **Gen 2** (long-lived objects). The **Large Object Heap (LOH)** handles objects >85KB, which are collected differently (usually only in Gen 2). `IDisposable` is necessary because the GC only manages managed memory; it doesn't know how to release unmanaged resources like file handles, database connections, or COM objects promptly.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
By default, `await` captures the current `SynchronizationContext` (e.g., UI thread context). `ConfigureAwait(false)` tells the runtime not to force the continuation back onto that specific context. Use it in library code to improve performance and avoid deadlocks. Do *not* use it in UI applications where you specifically need to update a UI element from the main thread.

**DN8 — Hard: Explain the new .NET 8/9 features: primary constructors, collection expressions, and FrozenDictionary. Write a minimal example using primary constructors with DI.**
*   **Primary Constructors:** Allow defining constructor parameters directly in the class header for cleaner syntax.
*   **Collection Expressions:** New unified syntax `[1, 2, 3]` for initializing arrays/lists.
*   **FrozenDictionary:** A dictionary optimized for read-heavy scenarios where keys are known upfront, offering faster lookups than `Dictionary`.

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
The issue is likely **thread safety**. `DbContext` is not thread-safe; if multiple concurrent requests share the same instance (e.g., it was incorrectly registered as a Singleton or shared via a static variable), one thread might dispose of it while another is still using it. Fix: Ensure `DbContext` is registered as `Scoped` and injected correctly into controllers/services so each request gets its own unique instance.

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
A `record` provides built-in value-based equality and non-destructive mutation (`with` expressions). A `class` is for identity-based equality. A `record struct` combines the stack allocation of a struct with the syntax/equality features of a record. Choose `record` for DTOs, `class` for complex domain models with internal state, and `record struct` for small, immutable data structures.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
*   `ref`: Pass by reference; the variable must be initialized before passing. Use when the method needs to modify the original value.
*   `out`: Pass by reference; the method *must* assign a value before returning. Use for "TryGet" patterns.
*   `in`: Pass by reference (read-only); prevents modification. Use for large structs where you want to avoid copying but ensure the method doesn't change it.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
Nullable Reference Types are a **compile-time static analysis tool**. They don't change runtime behavior (a `string?` can still be null at runtime). Nullable Value Types (`int?`) are actual wrappers that allow a value type to hold a `null` state.

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
LINQ (Language Integrated Query) provides a way to query collections/data sources. Method syntax uses extension methods (more flexible, better for complex logic), while Query syntax mimics SQL (better for readability with joins). **Deferred Execution** means the query isn't executed until you iterate over the result (e.g., via `foreach` or `.ToList()`).

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
Constraints restrict what types can be used as a generic argument. `class`: must be a reference type; `struct`: must be a value type; `new()`: must have a parameterless constructor; `IComparable<T>`: must implement comparison. Combine them when you need specific requirements (e.g., `where T : class, new()`).

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
Abstract classes provide a base implementation and state (fields); interfaces define contracts. Default interface methods allow interfaces to include actual code implementations without breaking existing implementations. This blurs the line slightly by allowing "traits" behavior in interfaces, but they still cannot hold instance state (fields).

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
Middleware are components that handle requests/responses in a pipeline. Order matters because each component passes the request to the next. `Use` allows logic before/after calling the next delegate; `Map` branches the pipeline based on path; `Run` terminates the pipeline. Exception handling middleware wraps the entire execution block in a try-catch to catch errors from downstream components.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
`Channel<T>` is a high-performance async-friendly queue. Unlike `BlockingCollection`, which blocks threads, Channels use non-blocking async waits. A **bounded channel** provides backpressure: if the buffer fills up, the producer's `WriteAsync` will wait until space is available, preventing memory overflow.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
Source Generators run during compilation to generate additional C# source code. Reflection happens at runtime (slow); IL Weaving modifies existing binaries (complex). Incremental generators are preferred because they only regenerate code when specific inputs change, significantly speeding up build times compared to standard Source Generators that might re-run every time any file changes.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
TPL Dataflow provides "blocks" to build complex pipelines. `BufferBlock` stores data; `TransformBlock` processes/transforms data; `ActionBlock` performs an action on final results. While `System.Threading.Channels` is a low-level primitive for building queues, TPL Dataflow is a high-level framework for orchestrating complex parallel workflows with built-in degree of parallelism control.

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**
Minimal APIs provide a way to create HTTP endpoints without the overhead of Controller classes. Trade-offs: They are faster to write but can become messy as logic grows (harder to organize than Controllers). Testability remains similar via `WebApplicationFactory`. Middleware still applies globally or per-endpoint using **Endpoint Filters**, which allow you to apply specific logic (like Auth) only to certain routes within a group.

## Python

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**
A **list** is mutable; a **tuple** is immutable. A **set** is a mutable collection of unique items; a **frozenset** is an immutable version of a set. Because it's immutable, a `frozenset` can be used as a key in a dictionary, whereas a regular `set` cannot.

**P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?**
The GIL is a mutex that allows only one thread to execute Python bytecode at a time. It affects **CPU-bound** tasks (making multi-threading ineffective for heavy math/computation). Workarounds include using the `multiprocessing` module (separate processes), C extensions (which release the GIL), or libraries like NumPy.

**P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.**
A **shallow copy** creates a new object but fills it with references to the original nested objects. If you have a list containing another list (`[[1]]`), a shallow copy will result in both lists pointing to the same inner list. Modifying the inner list in the copy will change the original. `deepcopy` recursively copies everything.

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**
Decorators wrap a function to modify its behavior without changing its source code.
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"Time taken: {time.time() - start}")
        return result
    return wrapper
```

**P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?**
Generators use `yield` to return values one at a time while maintaining state (lazy evaluation). They save memory because they don't store the entire sequence in RAM like a list does. `yield from` is used to delegate to a sub-generator/iterable.

**P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?**
The event loop manages multiple coroutines on a single thread by switching tasks when one hits an I/O wait. `asyncio.run()` starts the loop; `gather()` runs multiple coroutines concurrently; `create_task()` schedules a task for execution. You cannot use `time.sleep()` because it blocks the *entire* thread (and thus the whole loop); you must use `await asyncio.sleep()`.

**P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**
Python uses **C3 Linearization**. In the provided code: D inherits from B then C. The order is [D, B, C, A]. Since B doesn't have `who`, it looks at its parent chain. It finds `who` in C before reaching A. Result: "C".

**P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.**
A metaclass is a class factory (a class that creates classes). Use them for complex logic like registering every subclass into a global registry automatically. `__init_subclass__` is a simpler hook to perform similar registration or validation during class creation without the complexity of a full metaclass.

**P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?**
*   **Threading:** I/O-bound tasks (waiting on network/disk).
*   **Multiprocessing:** CPU-bound tasks (heavy math) to bypass GIL.
*   **Concurrent.futures:** High-level API to manage both threads and processes easily.
*   **Pickling:** Multiprocessing requires objects to be serializable; non-serializable objects (like open files or database connections) will crash the process spawn.

**P10 — Medium: What is \_\_slots\_\_? When should you use it, and what does it prevent? What is the memory impact?**
`__slots__` tells Python not to create a `__dict__` for instances of a class. This significantly reduces memory usage when creating millions of small objects because it pre-allocates space only for specified attributes.

**P11 — Easy: What is a virtual environment, and why should you use one? What is the difference between venv, virtualenv, and conda?**
Virtual environments isolate project dependencies so different projects can have different versions of libraries. `venv` is the standard library tool; `virtualenv` is an older, more feature-rich third-party tool; `conda` is a package and environment manager that handles non-Python dependencies as well.

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?**
Comprehensions are "Pythonic" ways to create collections in a single line. They are generally faster and more readable than `map()` or `filter()` when doing simple transformations. Use `map/filter` if you already have a pre-defined function to apply.

**P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?**
`==` checks value equality; `is` checks identity (memory address). **Interning** is where Python reuses existing objects for common values. Small integers (-5 to 256) are interned by default to save memory, which is why `a is b` returns true for them even if they were created separately.

**P14 — Easy: Explain Python's *args and \*\*kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?**
`*args` captures variable positional arguments as a tuple; `**kwargs` captures variable keyword arguments as a dict. `/` indicates that all arguments before it must be positional only. `*` indicates that all arguments after it must be passed as keywords.

**P15 — Easy: What are context managers (with statement)? How do you write one using \_\_enter\_\_/\_\_exit\_\_ vs @contextmanager? Give an example beyond file handling.**
Context managers manage resources (setup/teardown). Use `__enter__`/`__exit__` for class-based logic or `@contextmanager` with a generator for simple logic. Example: A database connection pooler or a thread lock (`threading.Lock`).

**P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How does mypy or pyright use these for static analysis?**
Type hints provide "hints" to developers and tools about expected types. `Union[int, str]` allows either; `Optional[int]` means `int | None`. `Literal["A", "B"]` restricts values. `TypeVar` handles generic types. `Protocol` defines structural subtyping (static duck typing). Tools like MyPy scan the code without running it to find type mismatches based on these hints.

**P17 — Medium: Explain Python's data model (dunder methods). What are \_\_repr\_\_ vs \_\_str\_\_, \_\_eq\_\_ vs \_\_hash\_\_, and \_\_getattr\_\_ vs \_\_getattribute\_\_? What happens if you define \_\_eq\_\_ but not \_\_hash\_\_?**
*   `__repr__`: For debugging/devs. `__str__`: For end-users.
*   `__eq__`: Equality check. `__hash__`: Required for set membership/dict keys. If you define `__eq__` but not `__hash__`, the object becomes unhashable and cannot be put in a set or used as a dict key.
*   `__getattr__`: Called only if attribute is missing. `__getattribute__`: Called every time an attribute is accessed.

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (\_\_get\_\_, \_\_set\_\_, \_\_delete\_\_). How do property, classmethod, and staticmethod use descriptors under the hood?**
Descriptors are objects that define how attribute access works (e.g., `@property`). The descriptor protocol defines methods to handle getting, setting, and deleting attributes. `property` creates a managed attribute; `classmethod` and `staticmethod` are specialized descriptors that manage how functions are bound to classes vs instances.

**P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, \_\_init\_\_.py, and namespace packages work? What is a finder and a loader?**
Python searches `sys.path` (which includes `PYTHONPATH`) for modules. Absolute imports start from the project root/site-packages; Relative imports (`from . import x`) depend on the package structure. `__init__.py` marks directories as packages. Namespace packages allow multiple directories to share a name without being sub-packages of each other. A **Finder** locates the module file; a **Loader** actually loads it into memory.

**P20 — Hard: What is dataclasses and how does it compare to attrs and Pydantic? Explain \_\_post\_init\_\_, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**
Dataclasses provide boilerplate reduction for data holders. `attrs` provides more advanced features like slots and complex validation. `Pydantic` adds strict runtime type validation and serialization. Use `__post_init__` for logic after initialization. Choose **Pydantic** when you need robust input validation (e.g., parsing JSON API requests) or automatic schema generation.
