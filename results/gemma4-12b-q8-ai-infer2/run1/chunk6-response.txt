## JavaScript / TypeScript

**JS1 — Easy:** `var` is function-scoped and subject to hoisting (declaration moved to top of scope). `let` and `const` are block-scoped and exist in the Temporal Dead Zone (TDZ) until initialized. `const` prevents reassignment but does not make the object itself immutable.

**JS2 — Easy:** The Event Loop is a mechanism that handles asynchronous execution by offloading tasks from the call stack. **Call Stack** executes synchronous code. **Microtask Queue** (Promises, MutationObservers) has higher priority; the loop processes *all* microtasks before moving to the next macrotask. **Macrotask Queue** (setTimeout, I/O) runs one task per loop iteration.

**JS3 — Medium:** A closure is a function bundled together with its lexical environment (variables available at creation time). 
*Example:* A counter function returning an incrementer. 
*Bug:* In a `for` loop using `var`, every callback shares the same final value of the variable. 
*Fix:* Use `let` inside the loop header so each iteration gets its own binding.

**JS4 — Medium:** Promises represent eventual completion/failure. `async/await` provides syntactic sugar for cleaner promise chaining. Error handling: use `.catch()` or `try/catch`. `Promise.all` rejects if *any* promise fails ("fail-fast"). `Promise.allSettled` waits for all promises to finish regardless of success or failure.

**JS5 — Medium:** Interfaces are structural and cannot have implementations. Types can be aliases, unions, intersections, and tuples. Use `interface` for public APIs/objects that might be extended via declaration merging. Use `type` for complex logic like Unions or Mapped types. **Discriminated Unions** use a common literal property (e.g., `type: 'success'`) to allow TypeScript to narrow types in `switch` statements.

**JS6 — Medium:** Prototypal inheritance means objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with a specific prototype. ES6 classes are "syntactic sugar" over prototypes; they create a constructor function and set the `prototype` property accordingly.

**JS7 — Hard:** The `this` keyword value is determined by how a function is called:
1. Default binding (`undefined`).
2. Implicit binding (method call on an object).
3. Explicit binding (`call`, `apply`, `bind`).
4. `new` binding (constructor).
`bind()` returns a *new* function where `this` is permanently locked. You cannot re-bind a bound function because it has already been hardcoded to its context.

**JS8 — Hard:** `WeakRef` holds a reference to an object without preventing Garbage Collection (GC). `FinalizationRegistry` allows you to register a callback that runs after an object is GC'd. Use these for caching large resources or cleaning up manual memory management. **WeakMap keys** must be objects because WeakMaps do not prevent their keys from being garbage collected, ensuring no memory leaks occur when entries are no longer reachable elsewhere.

**JS9 — Hard:** V8 optimizes via **Hidden Classes** (internal shapes of objects), **Inline Caching** (memoizing property lookups based on hidden class), and **Deoptimization** (falling back to slower paths if types change unexpectedly). Patterns causing deopt include: changing the "shape" of an object (adding/deleting properties in different orders) or using dynamic types for variables.

**JS10 — Medium:** Tree-shaking removes unused code during the build step. It works best with ES Modules (ESM) because imports are static (analyzed at compile time). CommonJS (`require`) is dynamic; since `require()` can happen inside an `if` block, the compiler cannot safely determine what will actually be used, making tree-shaking unreliable.

**JS11 — Easy:** `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion (e.g., `null == undefined` is true); `===` checks strict equality (false). Nullish coalescing (`??`) returns the right side only if the left is null/undefined. Optional chaining (`?.`) allows accessing nested properties without throwing errors if a parent is null/undefined.

**JS12 — Easy:** `map()` transforms every element into a new array. `filter()` returns elements that pass a predicate. `reduce()` accumulates values into a single result (use an initial value to handle empty arrays correctly). `flatMap()` maps then flattens one level deep—useful for operations like "get all tags from all posts" where each post might have multiple tags.

**JS13 — Easy:** Template literals use backticks (\`) and `${}` interpolation. **Tagged Templates** allow you to call a function that receives the template parts as arguments. 
*Example:* A SQL tag function could escape variables: `` sql`SELECT * FROM users WHERE id = ${id}` `` would intercept `id` to prevent injection.

**JS14 — Easy:** Destructuring extracts data into variables. Object destructuring: `{ name, age } = user`. Array destructuring: `[first, second] = list`. Default values: `const { name = 'Guest' } = user`. Rest operator (`...rest`) collects remaining items into a new array or object.

**JS15 — Easy:** `for...in` iterates over enumerable property keys (including inherited ones); `for...of` iterates over iterable values (like array elements). Avoid `for...in` on arrays because it may include properties added to the prototype chain and does not guarantee order.

**JS16 — Medium:** Generics provide reusable types. Constraints (`T extends Number`) limit what type can be passed. Conditional Types (`T extends U ? X : Y`) act like ternary operators for types. `infer` allows TypeScript to "guess" a type from an expression (e.g., extracting return type of a promise).

**JS17 — Medium:** CommonJS uses `module.exports`/`require` (synchronous, dynamic). ESM uses `import`/`export` (asynchronous-friendly, static). Node.js supports both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM instead of CommonJS.

**JS18 — Hard:** TS is structurally typed ("duck typing"). **Excess Property Checks** only apply when assigning an object literal directly to a variable; they don't apply if the object was created elsewhere. `extends` defines inheritance/subtyping; `satisfies` checks if a value matches a type without widening the inferred type. Variance: Covariance (output) means you can substitute a more specific type where a general one is expected; Contravariance (input) is the inverse.

**JS19 — Hard:** Proxy intercepts operations (get, set, has, etc.). Reflect provides methods that mirror these operations but return correct results (like handling `this`). 
*Example:* A Proxy can intercept `set` to validate that a user's age never goes below 0 or to trigger a UI update for reactive data binding.

**JS20 — Hard:** `SharedArrayBuffer` allows multiple Web Workers to share the same memory space. `Atomics` provide thread-safe operations (add, load, wait, notify) on this shared buffer. This prevents race conditions by ensuring that while one worker reads, another cannot write simultaneously unless permitted by atomic locks.

## Bash

**B1 — Easy:** `$@` expands as separate words (preserving spaces in arguments); `$*` expands as a single string joined by spaces. Quoting matters: `"$@"` preserves individual arguments; `"$*"` joins them into one word.

**B2 — Easy:** `-e`: Exit immediately if a command fails. `-u`: Treat unset variables as errors. `-o pipefail`: Ensure a pipeline returns a non-zero exit code if any command in it fails (otherwise only the last command's status is returned).

**B3 — Medium:** `$(command)` and `` `command` `` are both command substitutions (backticks are legacy). `((expression))` is used for arithmetic evaluation (integer math), whereas `expr` is an external utility for similar tasks but slower/clunkier.

**B4 — Medium:** Process substitution `<(command)` creates a temporary named pipe (FIFO) or file descriptor. 
*Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands as if they were files.

**B5 — Medium:** Use globbing with quotes: `for f in *.txt; do ... done`. Avoid `for f in $(ls)`, because `ls` splits on whitespace, breaking filenames like "My File.txt". Better to use `find . -name "*.txt"`.

**B6 — Medium:** Here document (`<<EOF`) allows multi-line input until the delimiter. Here string (`<<<`) takes a single line of input. `<<-EOF` ignores leading tabs in the here doc, allowing indentation for readability.

**B7 — Hard:** 
1. `cmd > file 2>&1`: Redirect stdout to file, then redirect stderr to where stdout *was*. Result: Both go to file.
2. `cmd 2>&1 > file`: Redirect stderr to stdout's current location (stdout still goes to terminal). Then redirect stdout to file. Result: Stderr stays in terminal, Stdout goes to file.
3. `cmd &> file`: Shorthand for both going into the same file.

**B8 — Hard:** A lock file should be created using `mkdir`, which is an atomic operation at the filesystem level. If it succeeds, you have the lock. Function logic: Check if directory exists -> try `mkdir` -> handle error/retry -> trap signals (SIGTERM) to remove the folder on exit.

**B9 — Easy:** Single quotes ('') are literal; Double quotes ("") allow variable expansion and command substitution; No quotes treat words as commands or variables. Example: `'echo $VAR'` prints `$VAR`; `"echo $VAR"` prints the value of `$VAR`.

**B10 — Easy:** `-f` (file), `-d` (directory), `-r` (readable). `[ ]` is a shell builtin test command; `[[ ]]` is a bash keyword that supports regex (`=~`), pattern matching, and handles globbing more safely.

**B11 — Easy:** `$?` last exit code; `$$` PID of current shell; `$!` PID of most recent background job; `$#` number of arguments passed to script.

**B12 — Easy:** `foo() { ... }` vs `function foo {}`: The latter allows for local variables inside the function body without polluting global scope in some shells. Return values are usually handled by echoing a string or setting a global variable; functions return an exit status (0-255).

**B13 — Easy:** PATH contains directories searched for executables. Bash resolves commands by checking PATH sequentially. **Builtins** (e.g., `cd`, `echo`) are part of the shell binary itself; **External** commands are separate files on disk. Use `type <cmd>` to check which one it is.

**B14 — Medium:** `trap 'cleanup' SIGNAL` catches signals. Common traps: EXIT (script end), ERR (non-zero exit), INT (Ctrl+C), TERM (kill). If multiple signals arrive simultaneously, they are queued/handled based on priority.

**B15 — Medium:** xargs takes lines from stdin and passes them as args to a command. Command substitution `$(...)` captures output into a variable. For spaces/newlines, use `find -print0 | xargs -0`. `-P [num]` runs jobs in parallel.

**B16 — Medium:** Arrays: `arr=(); arr+=("val")`; Associative arrays: `declare -A map; map[key]=val`. Iterate with `${arr[@]}` or `${!map[@]}`. Length via `${#arr[@]}`. Associative arrays require explicit declaration (`-A`).

**B17 — Hard:** Subshell `(...)` creates a child process; variables changed inside do not persist to parent. Group `{ ...; }` stays in current process but has local scope for some shell features. Piping into a while loop (`cmd | while read...`) puts the loop in a subshell because of the pipe, so any variable changes made inside the loop disappear when the loop ends.

**B18 — Hard:** SIGINT (Interrupt), SIGTERM (Terminate), SIGHUP (Hangup), SIGKILL (Force kill). Graceful shutdown involves trapping signals and using `jobs -p` to find background PIDs, then sending TERM to each before exiting.

**B19 — Hard:** Use `split -n` to divide a file into chunks based on lines/size. Pipe output to `xargs -P [cores] -n 1 ./process_func`. Error propagation is tricky with xargs; you must check exit codes within the processing function itself or use a wrapper that logs failures to a shared log file.

**B20 — Hard:** `exec <command>` replaces the current shell process with the new command. File descriptors: `exec 3>file` opens FD 3 for writing; `exec 3>&-` closes it. A **coprocess** `<&>` creates a two-way communication channel between the script and another process.

## PowerShell

**PS1 — Easy:** Write-Output sends data down the pipeline as an object. Write-Host prints directly to the console host (bypassing the pipeline). This matters because objects in a pipeline can be filtered/processed by subsequent commands.

**PS2 — Easy:** The pipeline passes *objects* from one cmdlet to the next. `ForEach-Object` acts on items coming through the pipe. `foreach ($item in $list)` is a language statement used to iterate over collections already stored in memory.

**PS3 — Medium:** PSCustomObject is a lightweight container for property bags intended for outputting structured data. Hashtable is a mutable dictionary. Convert via `[pscustomobject]@{Key=Val}`. Use PSCustomObject when passing data to other cmdlets.

**PS4 — Medium:** Terminating errors stop execution of the script block. Non-terminating errors allow the script to continue. `-ErrorAction Stop` makes non-terminating errors "catchable" by try/catch blocks. `$ErrorActionPreference` sets the default behavior globally or per session.

**PS5 — Medium:** Splatting uses `@params = @{Param1=$val; Param2=$val}` and then calls `cmdlet @params`. It improves readability. Difference: Passing a hashtable as a single parameter sends it to the first positional argument, whereas splatting maps keys to specific named parameters.

**PS6 — Medium:** Invoke-Command -ComputerName runs code remotely and returns results (one-way). Enter-PSSession provides an interactive remote shell. Both use WinRM (HTTP/HTTPS) which handles authentication and serialization of objects.

**PS7 — Hard:** The pipeline's implicit behavior can cause issues with types. In your example, if `$result` starts empty, adding `"one"` might make it a string array or object depending on initialization. Correct pattern: Initialize with `$result = @()` to ensure it is always treated as an array (`System.Object[]`).

**PS8 — Hard:** Scriptblock `{...}` is a block of code that can be passed around; Function is a named entity in scope. Pass scriptblocks via `-ArgumentList` for remoting. Double-hop occurs when machine A tries to access machine B over network; solve using CredSSP or by passing explicit credentials/data via ArgumentList.

**PS9 — Easy:** `@()` forces a result into an array even if there is only one item. `[array]` is a type definition. Indexing into $null usually throws an error; indexing into an empty array `0` also errors but behaves differently across versions regarding the return value.

**PS10 — Easy:** Comparison operators are case-insensitive by default. Use `-ceq`, `-clike`, etc., for strict case sensitivity. `-contains` checks if a collection contains a specific value; `-in` does the same (inverse syntax).

**PS11 — Easy:** Module (.psm1) contains logic; Manifest (.psd1) defines metadata like version and requirements; Binary (.dll) is compiled .NET code. Import-Module loads these into the current session's scope.

**PS12 — Easy:** Interpolation: `"Value: $var"`. Single quotes `'...'` are literal strings. Here-string: `@""@` allows multi-line strings without escaping internal double quotes.

**PS13 — Easy:** Get-Member shows properties, methods, and NoteProperties (hidden attributes). Select-Object filters columns (properties); Where-Object filters rows based on conditions.

**PS14 — Medium:** PowerShell classes have methods/properties similar to C#. Limitations include limited inheritance depth and no interfaces compared to full .NET. Use Classes when you need stateful objects with complex behavior; use functions for simple actions or data processing.

**PS15 — Medium:** `[CmdletBinding()]` adds standard parameters (`-Verbose`, `-WhatIf`). `SupportsShouldProcess` enables `-WhatIf`. Begin block runs once at start, Process runs for every object in the pipeline, End runs once at completion.

**PS16 — Medium:** Providers allow treating different sources as a filesystem. Example: `Get-ChildItem -Path HKLM:\Software` treats the Registry like a folder structure. You can browse keys and values using standard cmdlets.

**PS17 — Hard:** Runspaces provide isolated threads of execution. A [runspace] is an instance of a PowerShell engine. ForEach-Object -Parallel (v7+) manages runspace pools automatically. Manual management allows fine control over memory limits and specific thread counts.

**PS18 — Hard:** PSScriptAnalyzer is a linter that enforces best practices via rules. Rules have severity levels (Info, Warning, Error). Suppress rules using `#PSCmdlet` or script attributes. Integrate into CI/CD by checking exit codes on "Error" level violations.

**PS19 — Hard:** `$using:` scope allows variables from the local session to be passed into remote sessions or background jobs. Serialization limits CLIXML depth; complex nested objects may fail to serialize if they exceed nesting limits during transmission.

**PS20 — Hard:** DSC defines the desired state (e.g., "Service X must be running"). LCM (Local Configuration Manager) checks current state against this config and applies changes. In modern infra, it has been largely superseded by Terraform/Ansible for cloud resources but remains relevant for Windows node configuration.
