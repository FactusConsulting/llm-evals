## Networking

**N1 — Easy: What is the difference between a Layer 2 switch and a Layer 3 switch?**
A **Layer 2 switch** operates at the Data Link layer of the OSI model. It forwards frames based on MAC addresses within a single broadcast domain (subnet). A **Layer 3 switch** operates at the Network layer; it possesses the intelligence of a router, allowing it to perform inter-VLAN routing and forward packets based on IP addresses using routing tables.

**N2 — Easy: A host has IP 10.0.5.37/20. What is the network address and broadcast address?**
*   **Subnet Mask:** /20 means the mask is `255.255.240.0` (the first 20 bits are the network portion).
*   **Network Address:** The first 20 bits of 10.0.5.37 ($10.0.x.x$) result in **10.0.0.0**.
*   **Broadcast Address:** The last 12 bits are for hosts. In this range, the broadcast is **10.0.15.255**.

**N3 — Medium: Explain the TCP three-way handshake. What happens if the final ACK is lost?**
The process is: 1. Client sends **SYN**, 2. Server responds with **SYN-ACK**, 3. Client sends **ACK**. If the final **ACK** is lost, the server will wait for an acknowledgment; since it didn't receive one, it will retransmit the SYN-ACK packet multiple times until it receives the ACK or a timeout occurs.

**N4 — Medium: What is the difference between SNAT and DNAT? Give a practical example of each.**
*   **SNAT (Source NAT):** Changes the source IP of a packet leaving a private network to a public IP. *Example:* A company using a single public IP for all internal employees browsing the internet via a NAT Gateway.
*   **DNAT (Destination NAT):** Changes the destination IP of an incoming packet to point to an internal host. *Example:* Port forwarding on a home router where hitting `router_ip:80` forwards traffic to an internal web server at `192.168.1.10`.

**N5 — Medium: You run `curl -v https://example.com` and get `SSL: certificate subject name does not match target host name`. List 3 possible causes.**
1.  The certificate was issued for a different domain (e.g., `example.org`) but is being served for `example.com`.
2.  A Load Balancer/Proxy is misconfigured and serving the wrong certificate from its pool.
3.  The client is accessing the site via an IP address, but the certificate only lists DNS names as valid subjects.

**N6 — Medium: Explain the difference between a VLAN and a VxLAN. When would you choose VxLAN over VLAN?**
VLANs are limited by the 802.1Q standard to 4,096 IDs and are restricted to Layer 2 boundaries. **VxLAN** is an overlay technology that encapsulates Layer 2 frames into UDP packets (MAC-in-UDP), allowing for up to 16 million segments and spanning across Layer 3 boundaries. Choose VxLAN when building large-scale multi-tenant cloud environments or data centers where scale exceeds 4k VLANs.

**N7 — Hard: A Linux host has two NICs: eth0 (10.0.0.5/24, default gw 10.0.0.1) and eth1 (192.168.1.5/24). Traffic arriving on eth1 from 192.168.1.0/24 is being replied via eth0. Why, and how do you fix it with policy-based routing?**
*   **Why:** The kernel's main routing table likely sees the return path to `192.168.1.x` as having a higher metric or specific route associated with `eth0`.
*   **Fix:** Use Policy-Based Routing (PBR). Create a separate routing table for `eth1`, add a rule (`ip rule add from 192.168.1.0/24 table 100`), and then add a specific route in that table pointing to the gateway of `eth1`.

**N8 — Hard: Explain how BGP path selection works. List at least 5 attributes in the correct order of preference.**
BGP uses a deterministic algorithm to select the best path. Order of preference:
1.  Weight (Cisco proprietary - highest wins)
2.  Local Preference (Highest wins)
3.  AS_Path Length (Shortest wins)
4.  Origin Type (IGP < EGP < Incomplete)
5.  MED (Multi-Exit Discriminator - Lowest wins)

**N9 — Hard: What is the MTU implication of running VxLAN over an IPsec tunnel? Show the math for the maximum inner payload if the physical MTU is 1500.**
VxLAN adds 50 bytes of overhead. IPsec adds roughly 50–70 bytes (depending on encryption/ESP headers). If Physical MTU = 1500, and we subtract ~120 bytes for both VxLAN + IPsec overhead, the **Maximum Inner Payload MTU** would be approximately **1380 bytes**. To avoid fragmentation, you must set the MSS (Maximum Segment Size) accordingly.

**N10 — Medium: What is the purpose of ARP, and what problem does Gratuitous ARP solve?**
ARP maps Layer 3 IPs to Layer 2 MAC addresses. **Gratuitous ARP** is an unsolicited ARP response used by a host to announce its IP/MAC to the network. It solves two problems: detecting IP address conflicts and updating the ARP tables of neighboring devices when a failover event occurs (e.g., VRRP/HSRP transition).

**N11 — Easy: What is the difference between a public IP address and a private IP address? List the three private IPv4 ranges defined in RFC 1918.**
Public IPs are globally unique and routable on the internet. Private IPs are reserved for internal use and are not routable over the public internet.
*   Ranges: `10.0.0.0 - 10.255.255.255`, `172.16.0.0 - 172.31.255.255`, `192.168.0.0 - 192.168.255.255`.

**N12 — Easy: What is DNS, and what is the difference between an A record, a CNAME record, and an AAAA record?**
DNS translates human-readable names to IP addresses.
*   **A:** Maps a hostname to an **IPv4** address.
*   **CNAME:** An alias; maps one hostname to another hostname.
*   **AAAA:** Maps a hostname to an **IPv6** address.

**N13 — Easy: What is DHCP, and what four-step process (DORA) does a client use to obtain an IP address from a DHCP server?**
DHCP automatically assigns dynamic IP configurations. The DORA process is:
1.  **D**iscover (Client broadcasts request)
2.  **O**ffer (Server responds with available IP)
3.  **R**equest (Client requests that specific IP)
4.  **A**cknowledge (Server confirms lease)

**N14 — Easy: What is the difference between a hub, a switch, and a router? At which OSI layer does each primarily operate?**
*   **Hub:** Broadcasts all incoming data to all ports (**Layer 1**).
*   **Switch:** Forwards frames based on MAC addresses (**Layer 2**).
*   **Router:** Routes packets based on IP addresses/subnets (**Layer 3**).

**N15 — Easy: Explain the difference between half-duplex and full-duplex communication. Which mode do modern Ethernet links use?**
Half-duplex allows communication in both directions but only one at a time (like a walkie-talkie). Full-duplex allows simultaneous two-way communication. Modern Ethernet uses **Full-Duplex**.

**N16 — Medium: What is the purpose of the TTL field in an IP packet? How does traceroute exploit it to map the network path?**
TTL prevents packets from looping infinitely by decrementing by 1 at every hop. `traceroute` sends packets with incrementing TTL values (starting at 1). Each router that receives a packet with $TTL=1$ drops it and sends back an ICMP "Time Exceeded" message, allowing `traceroute` to identify its location.

**N17 — Medium: Explain what a NAT gateway does. What is the difference between static NAT, dynamic NAT, and PAT (port address translation)?**
A NAT Gateway translates private internal IPs to public IPs for internet access.
*   **Static NAT:** One-to-one mapping (e.g., a web server's fixed public IP).
*   **Dynamic NAT:** Maps private IPs to a pool of public IPs on a first-come, first-served basis.
*   **PAT:** Many-to-one; maps multiple private IPs to one public IP using unique source ports.

**N18 — Hard: Explain how ECMP (Equal-Cost Multi-Path) routing works. What hashing strategies are commonly used, and what problems can arise with asymmetric flows when stateful firewalls are involved?**
ECMP allows traffic to be split across multiple paths with equal costs. Hashing usually uses **Source/Dest IP, Source/Dest Port, and Protocol**. Problems occur with **stateful firewalls**: if the hash results in the return path taking a different physical path than the outgoing path, the firewall may drop the packet as "out of state" because it didn't see the initial SYN or connection setup.

**N19 — Hard: A TCP connection shows high latency but no drops. BDP is 10MB, window maxes at 64KB. Explain the problem and how TCP window scaling solves it.**
The throughput is limited by the small receive window ($Throughput = WindowSize / RTT$). Because the window size is much smaller than the Bandwidth-Delay Product (BDP), the sender must stop and wait for ACKs before sending more data, causing underutilization of the pipe. **TCP Window Scaling (RFC 1323)** allows the window size to exceed 65,535 bytes by using a multiplier, allowing the window to match the large BDP.

**N20 — Hard: Describe how 802.1Q trunk ports work. A server with a single NIC needs to communicate on VLANs 10, 20, and 30. Explain how to configure this on Linux using sub-interfaces and what the frame format looks like on the wire.**
Trunking carries multiple VLAN tags over one physical link. On Linux, you create virtual interfaces (`eth0.10`, `eth0.20`, etc.). The kernel adds an **802.1Q tag** to the Ethernet frame header. The frame includes a **TPID (0x8100)** followed by a **TCI** field containing the Priority Code Point (PCP) and the 12-bit VLAN ID.

## Linux

**L1 — Easy: What is the difference between a hard link and a symbolic link?**
A **Hard Link** points to the same inode as the original file; deleting the original doesn't delete the data until all links are gone. A **Symbolic Link (Symlink)** is a separate file that contains the path to another file; if the target is deleted, the symlink becomes "broken."

**L2 — Easy: How do you find all files larger than 100MB under /var/log?**
`find /var/log -type f -size +100M`

**L3 — Medium: A process is in state D (uninterruptible sleep). What does this mean, and can you kill it with kill -9?**
State D means the process is waiting for an I/O operation (like disk or hardware response) and cannot be interrupted by signals. You **cannot** kill it with `kill -9`; it will remain in State D until the kernel receives the requested I/O completion.

**L4 — Medium: Explain the difference between cgroups v1 and cgroups v2. Which does systemd prefer and why?**
Cgroups v2 provides a unified hierarchy where resource controllers (CPU, Memory, etc.) share a single set of rules, whereas v1 had separate hierarchies. Systemd prefers **v2** because its design simplifies management of nested groups and ensures consistent resource accounting across different subsystems.

**L5 — Medium: What is the difference between nftables and iptables? How does the kernel handle both simultaneously?**
`nftables` is the modern successor to `iptables`. It uses a more efficient bytecode-based engine. The kernel handles both via the `nf_tables` subsystem; `iptables` commands are translated into `nftables` expressions at the kernel level.

**L6 — Medium: You run `df -h` and see a filesystem at 100%, but `du -sh /*` totals far less. What is the most likely cause?**
A process has deleted a large file that is still being held open by an active process. `df` counts blocks allocated, while `du` only counts files currently visible in the directory tree. Use `lsof | grep deleted` to find them.

**L7 — Hard: Explain the Linux boot process from UEFI firmware to a running systemd target.**
1.  **UEFI:** Initializes hardware and loads the Boot Manager (e.g., GRUB).
2.  **Bootloader:** Loads the Kernel and Initramfs into memory.
3.  **Kernel:** Initializes drivers/hardware and mounts the root filesystem.
4.  **Initramfs:** Provides necessary scripts/drivers to mount the real root FS.
5.  **systemd:** The first user-space process (`PID 1`) starts, initializing units until reaching the default target (e.g., multi-user.target).

**L8 — Hard: A server has 64GB RAM but only 2GB swap. free -h shows 60GB used, 1GB available, 15GB of that is buff/cache. The OOM killer fires. Explain why available can be low even with high buff/cache, and what kernel tunables affect this behavior.**
"Available" memory accounts for memory that can be reclaimed from cache *minus* the amount needed by the kernel for operations like "dirty page" buffering. If `vm.min_free_kbytes` is set too low or if there's heavy disk I/O causing a backlog of dirty pages, the system may trigger OOM despite having large caches. Tunables include `vm.swappiness`, `vm.min_free_kbytes`, and `vm.dirty_ratio`.

**L9 — Medium: What does `ip netns` do, and how is it used by container runtimes?**
It manages **Network Namespaces**, which isolate the network stack (interfaces, routing tables, IP addresses) of a process. Container runtimes (like Docker/Podman) use namespaces to give each container its own private network environment.

**L10 — Medium: Explain the difference between SIGTERM, SIGKILL, and SIGQUIT. Which can be caught by the process?**
*   **SIGTERM:** Request for graceful shutdown; catchable.
*   **SIGQUIT:** Similar to TERM but produces a core dump; catchable.
*   **SIGKILL:** Forces immediate termination via kernel signal; **cannot** be caught, blocked, or ignored.

**L11 — Easy: What is the difference between stdout, stderr, and stdin? How do you redirect stderr to a file while still displaying stdout on the terminal?**
Stdout (Standard Output - 1), Stderr (Standard Error - 2), Stdin (Standard Input - 0). To redirect only stderr to a file: `command > output.txt 2> error.log` (or simply `command 2> error.log`).

**L12 — Easy: What does the chmod 755 command do? Explain what each digit represents.**
It sets permissions: Owner = Read+Write+Execute (7), Group = Read+Execute (5), Others = Read+Execute (5).

**L13 — Easy: What is the difference between the root user and a user with sudo privileges?**
The **root** user has absolute authority over all system resources and files. A user with **sudo** privileges can execute commands as root by providing their own password/credentials, allowing for "least privilege" administration where users don't need to log in as root directly.

**L14 — Easy: What is a package manager? Name the default package managers for Debian/Ubuntu and RHEL/Fedora.**
A tool used to install, update, and remove software packages.
*   Debian/Ubuntu: **APT** (`apt-get`/`apt`)
*   RHEL/Fedora: **DNF** (formerly YUM)

**L15 — Easy: What is the /etc/fstab file used for? What happens if an entry is misconfigured?**
It contains information about disk partitions and mounts. If an entry is misconfigured (e.g., wrong UUID or mount options), the system may fail to boot or drop into an emergency shell during startup.

**L16 — Medium: Explain what LVM (Logical Volume Manager) is. What are physical volumes, volume groups, and logical volumes, and how do you extend a logical volume on a running system?**
LVM provides a layer of abstraction between physical disks and filesystems.
*   **PV:** Physical disk/partition.
*   **VG:** A pool of PVs combined together.
*   **LV:** A "virtual" partition carved out of a VG.
To extend: `lvextend -r -L +2G /dev/vg0/lv_name`. The `-r` flag resizes the filesystem simultaneously.

**L17 — Hard: Explain how the Linux kernel's I/O scheduler works. Compare mq-deadline, bfq, and none schedulers. When would you choose each, and how do you change the scheduler for a block device at runtime?**
Schedulers manage the order of I/O requests to optimize throughput/latency.
*   **mq-deadline:** Good for general purpose; prioritizes reads over writes.
*   **bfq:** Better for interactive desktop responsiveness (fairness).
*   **none:** Best for high-speed NVMe SSDs where hardware handles scheduling.
Change via: `echo none > /sys/block/sdX/queue/scheduler`.

**L18 — Hard: A system is experiencing intermittent high load averages but CPU usage is low. Explain what load average actually measures on Linux, why I/O wait can inflate it, and how you would diagnose whether the bottleneck is CPU, disk, or network using standard tools.**
Load Average = Number of processes in **R**unning state + **D**iscardable (Uninterruptible Sleep) state. High "D" states indicate an I/O bottleneck (disk/network).
Diagnosis: Use `top` or `uptime` for load, `iostat -x` for disk latency, and `nload` or `iftop` for network saturation.

**L19 — Hard: Explain how SELinux enforces mandatory access control. What is the difference between enforcing, permissive, and disabled modes? How do you troubleshoot a daemon that fails to bind a non-standard port due to SELinux policy?**
SELinux uses security contexts (labels) to define what subjects (processes) can access which objects (files/ports).
*   **Enforcing:** Policy is active; actions are blocked.
*   **Permissive:** Policy is active; actions are allowed but logged.
*   **Disabled:** Policy is off entirely.
Troubleshooting: Check `/var/log/audit/audit.log`, use `sealert` or `ausearch --summary`. To fix a port issue, use `semanage port -a -t http_port_t -p tcp [PORT]`.

**L20 — Hard: Describe how the Linux kernel's virtual memory subsystem handles page faults. What is the difference between a minor and a major page fault? How does transparent huge pages (THP) affect application performance, and when would you disable it?**
A **Page Fault** occurs when a process tries to access a page not currently mapped in its MMU.
*   **Minor:** Page is in RAM but not mapped to this process (fast).
*   **Major:** Page must be fetched from disk (slow).
**THP** groups small pages into 2MB blocks to reduce TLB misses. However, they can cause "memory bloat" or high latency during allocation for some databases (like MongoDB/Redis); these apps often recommend disabling THP via `echo never > /sys/kernel/mm/transparent_hugepage/enabled`.
