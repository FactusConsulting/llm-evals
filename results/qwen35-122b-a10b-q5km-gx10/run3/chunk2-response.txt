## Kubernetes (20 questions)

**K1 — Easy: What is the difference between a Deployment and a StatefulSet?**
A **Deployment** manages stateless applications where pods are interchangeable, have random names, and scale in parallel. A **StatefulSet** manages stateful applications where pods have stable, unique network identifiers (e.g., `pod-0`, `pod-1`), ordered deployment/scaling, and stable persistent storage bindings. Use StatefulSets for databases or apps requiring stable identity.

**K2 — Easy: How does a Kubernetes Service of type ClusterIP route traffic to pods?**
A ClusterIP assigns a virtual IP (VIP) within the cluster. **kube-proxy** runs on each node and configures network rules (iptables or IPVS) to forward traffic destined for the VIP to one of the backing pods. It selects pods based on the Service’s label selector. Traffic stays within the cluster network.

**K3 — Medium: Explain the difference between a PersistentVolume, a PersistentVolumeClaim, and a StorageClass. How do they relate?**
*   **PersistentVolume (PV):** A piece of storage in the cluster (provisioned by admin or dynamically).
*   **PersistentVolumeClaim (PVC):** A request for storage by a user (like a pod requesting CPU).
*   **StorageClass:** Defines the "type" of storage (e.g., SSD, HDD) and enables dynamic provisioning.
*   **Relation:** A PVC binds to a PV. If no PV exists, a StorageClass can dynamically create a PV to satisfy the PVC.

**K4 — Medium: A pod is stuck in CrashLoopBackOff. Describe your troubleshooting steps (at least 4 distinct checks).**
1.  **Check Logs:** `kubectl logs <pod> --previous` to see why the process exited.
2.  **Check Events:** `kubectl describe pod <pod>` to inspect scheduler events or OOMKilled reasons.
3.  **Check Config:** Verify ConfigMaps, Secrets, and Environment variables are mounted correctly.
4.  **Check Resources:** Ensure memory/CPU limits aren't too low causing OOMKills or CPU throttling.

**K5 — Medium: What is the role of CoreDNS in a Kubernetes cluster? What happens to DNS resolution if the CoreDNS pods are down?**
CoreDNS provides internal DNS service discovery, allowing pods to resolve service names (e.g., `my-service.default.svc.cluster.local`) to ClusterIPs. If CoreDNS pods are down, **service discovery fails**; pods cannot communicate with each other using DNS names, though direct IP communication might still work.

**K6 — Hard: Explain how the Kubernetes scheduler decides which node to place a pod on. Cover: filtering, scoring, and at least 3 specific factors it considers.**
The scheduler uses a **Filter** (Predicate) phase to eliminate unsuitable nodes, then a **Score** (Priority) phase to rank remaining nodes.
*   **Factors:**
    1.  **Resource Requests:** Does the node have enough CPU/Memory?
    2.  **Node Affinity/Taints:** Does the node match pod affinity rules or tolerate taints?
    3.  **Topology Spread:** Does the node help balance pods across zones/hosts?
The node with the highest score is selected.

**K7 — Hard: You have a pod with requests.memory: 256Mi and limits.memory: 512Mi. The node has 4GB RAM with 3.5GB already requested. Will the pod be scheduled? What happens if it actually uses 600Mi at runtime?**
*   **Scheduling:** Yes. The node has 512Mi free (4GB - 3.5GB). The pod requests 256Mi, which fits.
*   **Runtime:** If the pod uses 600Mi, it exceeds its **limit** (512Mi). The OOM Killer will terminate the container, causing it to restart (potentially leading to CrashLoopBackOff).

**K8 — Hard: Explain the full lifecycle of a request hitting a Kubernetes Ingress backed by an NGINX ingress controller, all the way to the application pod. Include at least: external LB, ingress controller, Service, Endpoints, kube-proxy/iptables.**
1.  **External LB:** Cloud load balancer forwards traffic to the Ingress Controller Pod IP.
2.  **Ingress Controller:** NGINX pod reads Ingress resources, matches the Host/Path, and determines the target Service.
3.  **Service:** Traffic is sent to the Service ClusterIP.
4.  **kube-proxy/iptables:** Node-level rules DNAT the ClusterIP to a specific Pod IP (Endpoint).
5.  **Pod:** The application container receives the request.

**K9 — Medium: What is a NetworkPolicy? If no NetworkPolicy exists in a namespace, what is the default behavior? What happens when you apply one that selects certain pods?**
A NetworkPolicy acts as a firewall for pod-to-pod traffic.
*   **No Policy:** Default is **allow all** ingress and egress.
*   **Policy Applied:** If a policy selects a pod, **default deny** applies to that pod for the traffic types specified in the policy. Only explicitly allowed traffic is permitted.

**K10 — Medium: Explain the difference between RollingUpdate and Recreate deployment strategies. When would you choose Recreate?**
*   **RollingUpdate:** Gradually replaces old pods with new ones (zero downtime).
*   **Recreate:** Terminates all existing pods before creating new ones (downtime).
*   **Choose Recreate:** When the application cannot run multiple versions simultaneously (e.g., database migrations requiring exclusive access) or stateful apps without shared storage.

**K11 — Easy: What is a Kubernetes namespace, and what are the default namespaces created in a new cluster?**
A Namespace is a virtual cluster within a physical cluster used for logical isolation of resources (RBAC, quotas).
*   **Defaults:** `default`, `kube-system` (system components), `kube-public` (readable by all), `kube-node-lease` (node heartbeats).

**K12 — Easy: What is `kubectl describe pod <name>` used for? Name at least 3 pieces of information it shows that `kubectl get pod` does not.**
It provides detailed status and events. Unlike `get`, it shows:
1.  **Events:** Recent warnings or scheduling info.
2.  **Conditions:** Detailed readiness/liveness probe status.
3.  **Volumes/Mounts:** Specific config maps or secrets mounted.
4.  **Node IP:** The specific node the pod is running on.

**K13 — Easy: What is a ConfigMap, and how can a pod consume it? Name at least two different methods.**
A ConfigMap stores non-confidential configuration data in key-value pairs.
*   **Methods:**
    1.  **Environment Variables:** Injected as env vars in the container spec.
    2.  **Volume Mount:** Mounted as files in a directory within the container.

**K14 — Easy: What is the difference between a Service of type ClusterIP, NodePort, and LoadBalancer?**
*   **ClusterIP:** Exposes service on an internal IP (cluster-only).
*   **NodePort:** Exposes service on a static port on each Node's IP (external access via `<NodeIP>:<Port>`).
*   **LoadBalancer:** Provisions an external cloud load balancer that forwards traffic to the NodePort/ClusterIP.

**K15 — Easy: What is a DaemonSet, and when would you use one instead of a Deployment?**
A DaemonSet ensures a copy of a pod runs on **all (or specific) nodes**. Use it for node-level agents like logging collectors (Fluentd), monitoring agents (Node Exporter), or storage daemons, where one pod per node is required rather than a scalable pool.

**K16 — Medium: What are taints and tolerations? How do they differ from node affinity, and give a practical use case for each.**
*   **Taints/Tolerations:** Taints "repel" pods; Tolerations allow pods to "accept" the taint. Used to reserve nodes (e.g., GPU nodes).
*   **Node Affinity:** "Attracts" pods to nodes based on labels.
*   **Use Case:** Taint a node with `dedicated=database`; only DB pods with the matching toleration can schedule there. Use Affinity to ensure DB pods prefer nodes with `ssd=true`.

**K17 — Medium: Explain what a Kubernetes Operator is. How does it differ from a standard controller, and what problems does the Operator pattern solve?**
An Operator is a method of packaging, deploying, and managing a Kubernetes application using a **Custom Resource Definition (CRD)** and a custom controller.
*   **Difference:** Standard controllers manage built-in resources (Pods, Deployments). Operators manage custom resources specific to an app (e.g., `PostgresCluster`).
*   **Solves:** Automates complex lifecycle tasks (backups, failover, upgrades) that require domain knowledge beyond simple pod management.

**K18 — Hard: Explain the etcd consistency model used by Kubernetes. What happens to the cluster if the etcd quorum is lost? How do you recover from a situation where 2 out of 3 etcd nodes are permanently lost?**
*   **Model:** etcd uses the **Raft consensus algorithm** for strong consistency.
*   **Quorum Lost:** If quorum (majority) is lost, the cluster becomes read-only/unavailable for writes. API Server cannot update state.
*   **Recovery (2/3 lost):** You cannot form a quorum with 1 node. You must restore the cluster from a **snapshot backup** on the remaining node (forcing a single-node cluster temporarily) or provision new nodes and restore data to rebuild the quorum. Data written after the last snapshot is lost.

**K19 — Hard: Describe how Kubernetes RBAC works. Explain the relationship between Role, ClusterRole, RoleBinding, and ClusterRoleBinding. A developer needs read-only access to pods and logs in a single namespace — write the RBAC manifests.**
*   **RBAC:** Role-Based Access Control.
*   **Role/ClusterRole:** Define permissions (verbs on resources). Role is namespace-scoped; ClusterRole is cluster-scoped.
*   **RoleBinding/ClusterRoleBinding:** Bind a User/Group/ServiceAccount to a Role/ClusterRole.
*   **Manifest:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: dev
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods
  namespace: dev
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20 — Hard: You notice pod DNS resolution is slow (>5s) for external domains. Explain how ndots in /etc/resolv.conf inside a pod causes excessive DNS queries, and how you would fix it using dnsConfig in the pod spec.**
*   **Cause:** Default `ndots: 5`. If a domain has fewer than 5 dots (e.g., `google.com`), the resolver tries appending all search domains (e.g., `default.svc.cluster.local.google.com`) before querying the domain directly. This causes multiple failed queries.
*   **Fix:** Set `ndots: 1` in `dnsConfig`.
```yaml
spec:
  dnsConfig:
    options:
    - name: ndots
      value: "1"
```

## Development (20 questions)

**D1 — Easy: What is the difference between git rebase and git merge? When should you avoid rebasing?**
*   **Merge:** Creates a new commit combining histories, preserving branch structure.
*   **Rebase:** Rewrites history by moving commits on top of the target branch, creating a linear history.
*   **Avoid Rebasing:** On **public/shared branches**. Rewriting history forces collaborators to force-push and rebase their own work, causing confusion and conflicts.

**D2 — Easy: Explain the difference between TCP and UDP. Name 2 protocols that use each.**
*   **TCP:** Connection-oriented, reliable, ordered delivery, flow control. (e.g., HTTP, SSH).
*   **UDP:** Connectionless, unreliable, unordered, low overhead. (e.g., DNS, VoIP/Streaming).

**D3 — Medium: What is a race condition? Give a concrete example in any language.**
A race condition occurs when the system's behavior depends on the sequence or timing of uncontrollable events (thread execution).
*   **Example:** Two threads increment a shared counter `x++` without synchronization. Both read `x=0`, both write `x=1`. Result is 1 instead of 2.

**D4 — Medium: Explain the difference between symmetric and asymmetric encryption. How are both used together in TLS?**
*   **Symmetric:** Same key for encryption/decryption (fast).
*   **Asymmetric:** Public key encrypts, Private key decrypts (secure key exchange).
*   **TLS:** Asymmetric encryption is used during the **handshake** to securely exchange a symmetric session key. Symmetric encryption is then used for the **data transfer** for performance.

**D5 — Medium: What is a container image layer? How does layer caching affect Dockerfile best practices?**
A layer is an immutable filesystem diff created by each instruction in a Dockerfile.
*   **Caching:** Docker caches layers. If a layer hasn't changed, it reuses it.
*   **Best Practice:** Order instructions from **least frequently changing** (e.g., `COPY package.json`, `RUN npm install`) to **most frequently changing** (e.g., `COPY .`). This maximizes cache hits during builds.

**D6 — Medium: You have a REST API returning HTTP 503 intermittently. Describe at least 4 things you would check, and in what order.**
1.  **Upstream Health:** Check if backend services are healthy (circuit breakers open?).
2.  **Load Balancer:** Check LB logs for timeout or connection refused errors.
3.  **App Logs:** Look for specific error messages or stack traces in the application logs.
4.  **Resources:** Check for CPU throttling, Memory OOM, or connection pool exhaustion.

**D7 — Hard: Explain the CAP theorem. Give a real-world example of a system that chooses CP over AP, and one that chooses AP over CP.**
*   **CAP:** In a distributed system, you can only guarantee 2 of 3: Consistency, Availability, Partition Tolerance. (P is mandatory in distributed systems, so trade-off is C vs A).
*   **CP (Consistency + Partition Tolerance):** HBase, Zookeeper. (Rejects writes if nodes can't agree).
*   **AP (Availability + Partition Tolerance):** Cassandra, DynamoDB. (Accepts writes even if nodes are out of sync).

**D8 — Medium: What is the difference between horizontal and vertical scaling? What architectural patterns enable horizontal scaling?**
*   **Vertical:** Adding more resources (CPU/RAM) to a single node. Limited by hardware.
*   **Horizontal:** Adding more nodes to the system.
*   **Patterns:** Stateless application design, Load Balancing, Database Sharding, Caching layers.

**D9 — Easy: What is an environment variable? How do you set one that persists across shell sessions on Linux?**
An environment variable is a dynamic value that can affect the way running processes behave on a computer.
*   **Persist:** Add `export VAR_NAME=value` to `~/.bashrc`, `~/.profile`, or `/etc/environment`.

**D10 — Easy: What is JSON, and how does it differ from YAML? Name one advantage of each format.**
*   **JSON:** Data interchange format, strict syntax. **Advantage:** Native support in most languages, easy to parse.
*   **YAML:** Human-readable data serialization. **Advantage:** Supports comments and indentation, easier for config files.

**D11 — Easy: What is a REST API? Explain the difference between GET, POST, PUT, and DELETE HTTP methods.**
REST (Representational State Transfer) is an architectural style for APIs using HTTP.
*   **GET:** Retrieve data (Safe, Idempotent).
*   **POST:** Create new resource (Not idempotent).
*   **PUT:** Replace/Update resource (Idempotent).
*   **DELETE:** Remove resource (Idempotent).

**D12 — Easy: What is version pinning in dependency management, and why is it important for reproducible builds?**
Version pinning locks a dependency to a specific version (e.g., `lodash@4.17.21`).
*   **Importance:** Prevents automatic updates from introducing breaking changes or bugs, ensuring the build produces the exact same output every time.

**D13 — Easy: What is the difference between a compiled language and an interpreted language? Give two examples of each.**
*   **Compiled:** Source code is translated to machine code before execution (faster runtime). Examples: C++, Go.
*   **Interpreted:** Source code is executed line-by-line at runtime (slower, flexible). Examples: Python, JavaScript.

**D14 — Medium: Explain what a reverse proxy is and how it differs from a forward proxy. Name two common reverse proxy servers and a use case for each.**
*   **Reverse Proxy:** Sits in front of servers, forwarding client requests to them (Server-side).
*   **Forward Proxy:** Sits in front of clients, forwarding their requests to the internet (Client-side).
*   **Servers:**
    1.  **Nginx:** Load balancing and static file serving.
    2.  **HAProxy:** High-performance TCP/HTTP load balancing.

**D15 — Medium: What is a deadlock? What four conditions (Coffman conditions) must hold simultaneously for a deadlock to occur?**
A deadlock is a situation where processes are blocked forever, each waiting for the other.
*   **Conditions:**
    1.  **Mutual Exclusion:** Resource cannot be shared.
    2.  **Hold and Wait:** Process holds a resource while waiting for another.
    3.  **No Preemption:** Resources cannot be forcibly taken.
    4.  **Circular Wait:** A chain of processes exists where each waits for the next.

**D16 — Hard: Explain the concept of eventual consistency. How do distributed databases like Cassandra handle read-after-write consistency, and what tunable consistency levels exist?**
*   **Eventual Consistency:** Updates propagate asynchronously; all nodes will agree eventually, but not immediately.
*   **Cassandra:** Uses tunable consistency. For read-after-write, you can increase consistency level.
*   **Levels:** `ONE` (fastest, least consistent), `QUORUM` (majority, balanced), `ALL` (slowest, strongest).

**D17 — Hard: What is mTLS (mutual TLS)? Explain the full handshake process, including how both client and server authenticate each other. Where is mTLS commonly used in infrastructure?**
*   **mTLS:** Both client and server present certificates to verify identity.
*   **Handshake:**
    1.  Client Hello.
    2.  Server Hello + Server Certificate.
    3.  **Client Certificate** (Client sends cert).
    4.  Server verifies Client Cert.
    5.  Client verifies Server Cert.
    6.  Key exchange established.
*   **Use:** Service Meshes (Istio), internal microservice communication, zero-trust networks.

**D18 — Hard: Explain how a hash table works internally, including collision resolution strategies (chaining vs. open addressing). What is the time complexity for insertion, lookup, and deletion in average and worst cases?**
*   **Mechanism:** Key is hashed to an index in an array.
*   **Collision:**
    *   **Chaining:** Array slots point to linked lists of entries.
    *   **Open Addressing:** Find next available slot via probing (linear/quadratic).
*   **Complexity:**
    *   **Average:** O(1) for insert, lookup, delete.
    *   **Worst:** O(n) (if all keys hash to same index).

**D19 — Hard: What is a circuit breaker pattern in microservices? Explain its three states (closed, open, half-open) and how it prevents cascade failures. How does it relate to retry policies and exponential backoff?**
*   **Pattern:** Stops calls to a failing service to prevent resource exhaustion.
*   **States:**
    1.  **Closed:** Normal operation.
    2.  **Open:** Fail fast (return error immediately) after threshold failures.
    3.  **Half-Open:** Allow limited test requests to check if service recovered.
*   **Relation:** Circuit breakers prevent retries from overwhelming a failing service. Retries with exponential backoff are used *inside* the closed state or after the half-open test succeeds.

**D20 — Hard: Explain the difference between optimistic and pessimistic concurrency control in databases. When would you choose each? Give a concrete example using database features (e.g., row versioning, SELECT FOR UPDATE).**
*   **Optimistic:** Assumes conflicts are rare. Checks version on commit.
    *   **Example:** `UPDATE table SET val=1 WHERE id=1 AND version=5`.
    *   **Use:** High read, low write contention.
*   **Pessimistic:** Assumes conflicts are likely. Locks row on read.
    *   **Example:** `SELECT * FROM table WHERE id=1 FOR UPDATE`.
    *   **Use:** High write contention, financial transactions.
