## JavaScript / TypeScript

**JS1 — Easy:** `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but reside in the Temporal Dead Zone (TDZ) until declaration. Hoisting moves declarations to the top of their scope during compilation. `const` cannot be reassigned.

**JS2 — Easy:** The event loop manages execution. The **Call Stack** executes synchronous code. **Microtasks** (Promises, `queueMicrotask`) run immediately after the stack clears, before the next render. **Macrotasks** (`setTimeout`, I/O) run after microtasks. Order: Stack → Microtasks → Render → Macrotasks.

**JS3 — Medium:** A closure is a function bundled with its lexical environment. **Bug:** Loop variable `var i` is shared across iterations, so callbacks log the final value. **Fix:** Use `let` (block scope) or an IIFE to create a new scope per iteration.

**JS4 — Medium:** `Promise` represents a future value. `async/await` is syntactic sugar over Promises. Error handling: `.catch()` for Promises, `try/catch` for async/await. `Promise.all` fails fast on first rejection; `Promise.allSettled` waits for all to finish regardless of outcome.

**JS5 — Medium:** `interface` is extensible (declaration merging) and object-focused. `type` supports unions, primitives, and mapped types. Use `interface` for public API shapes, `type` for complex compositions. **Discriminated unions** use a literal tag field (e.g., `kind: 'circle'`) to narrow types safely.

**JS6 — Medium:** JS uses prototypal inheritance: objects delegate to a prototype chain. `Object.create(proto)` creates an object with `proto` as its `[[Prototype]]`. ES6 `class` is syntactic sugar; `extends` sets up the prototype chain, `super` calls the parent constructor.

**JS7 — Hard:** `this` is determined by call site. **Rules (Priority):** 1. `new` binding, 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (method call `obj.fn()`), 4. Default (`window`/`undefined`). `bind()` returns a new function with bound `this`; it cannot be re-bound to change the original bound `this`.

**JS8 — Medium:** `WeakRef` holds a weak reference allowing GC to collect the target. `FinalizationRegistry` runs a callback when an object is GC'd. `WeakMap` keys must be objects because primitives cannot be weakly referenced; this prevents memory leaks by allowing keys to be garbage collected.

**JS9 — Hard:** V8 uses JIT compilation. **Hidden Classes:** Optimized object shapes for fast property access. **Inline Caching:** Caches property lookup results. **Deoptimization:** Occurs when assumptions break (e.g., adding properties dynamically, `eval`, mixed types). Avoid dynamic property addition after initialization.

**JS10 — Medium:** Tree-shaking removes unused code. Works with **ES Modules** because imports are static (analyzable at build time). **CommonJS** uses dynamic `require()`, making static analysis impossible, so tree-shaking is ineffective without transpilation.

**JS11 — Easy:** `null` is intentional absence; `undefined` is uninitialized. `null == undefined` is `true`; `null === undefined` is `false`. `??` returns RHS if LHS is `null`/`undefined`. `?.` safely accesses nested properties without throwing if intermediate is nullish.

**JS12 — Easy:** `map` transforms elements; `filter` selects elements; `reduce` accumulates to a single value. `reduce` needs an initial value to avoid using the first element as the accumulator. `flatMap` maps then flattens one level; useful for transforming arrays into single arrays.

**JS13 — Easy:** Template literals use backticks, support interpolation `${}`, and multi-line strings. **Tagged templates** pass raw strings and expressions to a function. Example: `sql`SELECT * FROM users WHERE id = ${id}`` sanitizes inputs before query execution.

**JS14 — Easy:** Destructuring extracts values. Object: `{a, b} = obj`. Array: `[x, y] = arr`. Defaults: `{a = 1} = {}`. Renaming: `{a: alias} = obj`. Rest: `{...rest} = obj` collects remaining properties.

**JS15 — Easy:** `for...in` iterates over enumerable **keys** (strings), including prototype chain. `for...of` iterates over **values** of iterable objects. Avoid `for...in` on arrays due to prototype pollution and non-numeric keys.

**JS16 — Medium:** Generics allow reusable type parameters. `extends` constrains types (e.g., `T extends string`). Conditional types: `T extends U ? X : Y`. `infer` captures types within conditional types (e.g., `infer R` in `Promise<R>`).

**JS17 — Medium:** **CommonJS:** `require`/`module.exports`, dynamic, Node default. **ES Modules:** `import`/`export`, static, browser default. Node handles both via file extension (`.mjs` for ESM) or `package.json` `"type": "module"`.

**JS18 — Hard:** Structural typing checks shape, not name. **Excess property checks** apply to object literals assigned to types. `extends` checks assignability; `satisfies` checks compatibility without widening the type. Variance (`in`, `out`) controls type parameter substitutability.

**JS19 — Hard:** `Proxy` intercepts operations (get, set, apply). `Reflect` provides default behavior for these operations. Example: A Proxy wrapping an object to log all property accesses or validate values before assignment (reactive data binding).

**JS20 — Hard:** `SharedArrayBuffer` allows shared memory between Web Workers. `Atomics` ensures atomic read/write operations. `Atomics.wait` blocks a worker until notified; `Atomics.notify` wakes waiters. Guarantees sequential consistency for atomic ops.

## Bash

**B1 — Easy:** `$@` expands to separate arguments; `$*` expands to a single string. `"$@"` preserves argument boundaries (spaces); `"$*"` joins them with the first character of IFS (usually space). Always use `"$@"` for argument passing.

**B2 — Easy:** `set -e` exits on error. `-u` errors on unset variables. `-o pipefail` returns exit code of the first failing command in a pipeline. Combined, they make scripts robust and fail-fast.

**B3 — Medium:** `$(command)` is preferred command substitution (nestable, readable). `` `command` `` is legacy. `$((expression))` is arithmetic expansion. `expr` is an external command, slower and legacy.

**B4 — Medium:** Process substitution `<(cmd)` creates a named pipe (e.g., `/dev/fd/63`). Use when commands expect filenames but need stream input. Example: `diff <(ls dir1) <(ls dir2)` compares directory listings without temp files.

**B5 — Medium:** Use `for f in *` or `while IFS= read -r -d '' f`. `for f in $(ls)` is dangerous because word splitting breaks filenames with spaces/newlines. `ls` output should never be parsed.

**B6 — Medium:** `<<EOF` (heredoc) feeds multiple lines to stdin. `<<<` (here string) feeds a single string. `<<-EOF` strips leading tabs (useful for indentation in scripts).

**B7 — Hard:** `cmd > file 2>&1`: stdout to file, then stderr to *new* stdout (file). `cmd 2>&1 > file`: stderr to *old* stdout (terminal), then stdout to file. `&> file` redirects both to file. Order matters for redirection targets.

**B8 — Hard:** Use `mkdir` for locking (atomic operation). Script: `mkdir lockdir && trap 'rmdir lockdir' EXIT`. Handles SIGTERM via trap. If killed, `trap` ensures cleanup. `mkdir` avoids race conditions better than `touch`.

**B9 — Easy:** `'...'` literal (no expansion). `"..."` expands variables/commands. No quotes splits on whitespace/glob. Example: `echo $var` (value), `echo '$var'` (literal), `echo *` (files).

**B10 — Easy:** `-f` (file), `-d` (dir), `-r` (readable). `[[ ]]` is Bash-specific (safer, supports `&&`, `||`, pattern matching). `[ ]` is POSIX `test`. Prefer `[[ ]]` in Bash scripts.

**B11 — Easy:** `$?` last exit code. `$$` current PID. `$!` last background PID. `$#` argument count. Use `$?` for error checking, `$$` for temp file names, `$!` for monitoring background jobs.

**B12 — Easy:** `function foo {}` or `foo() {}`. Both work. Functions return exit codes (0-255). To return data, `echo` and capture via command substitution `val=$(foo)`.

**B13 — Easy:** `PATH` is a colon-separated list of directories searched for executables. `type -a cmd` shows all locations. Builtin commands are internal to shell; external are files in PATH.

**B14 — Medium:** `trap 'cmd' SIGNAL`. `EXIT` runs on script end. `ERR` on command failure (with `set -e`). `INT`/`TERM` for signals. Order: Signal handler runs, then `EXIT` trap.

**B15 — Medium:** `xargs` builds command lines from stdin. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P` runs jobs in parallel. Command substitution `$(cmd)` captures output; `xargs` passes arguments.

**B16 — Medium:** Arrays: `arr=(a b)`. Associative: `declare -A arr; arr[key]=val`. Append: `arr+=(val)`. Length: `${#arr[@]}`. Associative arrays require Bash 4+.

**B17 — Hard:** `(subshell)` runs in child process (vars lost). `{ group }` runs in current shell. Piping `cmd | while read` creates a subshell for the loop, losing variable changes. Use process substitution or `while read` without pipe.

**B18 — Hard:** `SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (terminal close), `SIGKILL` (uncatchable). Handle `trap 'cleanup' TERM INT`. Background processes inherit traps; use `wait` to monitor them.

**B19 — Hard:** Split log: `split -l 10000 large.log part_`. Process: `xargs -P 4 -I {} process {}`. Merge: `cat part_* > result`. Errors: Check exit codes of `xargs` or use `set -e`. Trade-off: Parallelism vs I/O contention.

**B20 — Hard:** `exec` replaces current shell process. `exec 3>file` opens FD 3. `exec 3>&-` closes it. Coprocess: `coproc cmd` creates bidirectional pipe. Use for interactive CLI tools needing input/output streams.

## PowerShell

**PS1 — Easy:** `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console (no pipeline). Use `Write-Output` for scripting/pipelines; `Write-Host` only for user-facing logs.

**PS2 — Easy:** Pipeline streams objects. `ForEach-Object` is a cmdlet (processes pipeline input). `foreach` is a language statement (loops over collection). Use `ForEach-Object` in pipelines; `foreach` for in-memory arrays.

**PS3 — Medium:** `[PSCustomObject]` creates a typed object with properties. `[hashtable]` is a key-value dictionary. Convert: `[PSCustomObject]$ht`. Use hashtable for dynamic keys; PSCustomObject for structured data/serialization.

**PS4 — Medium:** Terminating errors stop execution (trigger `catch`). Non-terminating continue. `-ErrorAction` (per cmdlet), `$ErrorActionPreference` (global). `try/catch` only catches terminating errors.

**PS5 — Medium:** Splatting `@params` passes a hashtable's keys/values as parameters. Differs from passing hashtable as one arg. Example: `Invoke-Command @params`. Useful for dynamic parameter lists.

**PS6 — Medium:** `Invoke-Command` runs commands remotely (one-off). `Enter-PSSession` opens interactive shell. Protocol: WinRM (default) or SSH. WinRM uses HTTP/HTTPS; SSH uses standard SSH.

**PS7 — Hard:** PowerShell unwraps single-item arrays. If `Get-Items` returns 1 item, `$x` is that item, not an array. If 0 items, `$x` is `$null`. Correct pattern: `return @($result)` to force array.

**PS8 — Hard:** `[scriptblock]` is code. Pass via `-ArgumentList`. **Double-hop:** Credentials don't delegate to 3rd server. Solve: `CredSSP` authentication or `Invoke-Command` with `-Credential` on target.

**PS9 — Easy:** `@()` forces array context. `[array]` casts. `$null` index returns `$null`. Empty array index returns `$null`. `@()` ensures consistent array behavior even if result is single item.

**PS10 — Easy:** `-eq` (equals), `-like` (wildcard), `-match` (regex). Case-insensitive by default. `-ceq` is case-sensitive. `-contains` checks if collection has item; `-in` checks if item is in collection (reverse).

**PS11 — Easy:** Module = package. `.psm1` (script code), `.psd1` (manifest metadata), `.dll` (binary). `Import-Module` loads them. Manifest defines exports, dependencies, version.

**PS12 — Easy:** `"..."` interpolates `$var`. `'...'` literal. `$()` embeds expressions. Here-string `@"... "@` allows multi-line interpolation. Single-quoted here-string `@'...'@` is literal.

**PS13 — Easy:** `Get-Member` inspects object members. Properties = data, Methods = actions, NoteProperties = added at runtime. `Select-Object` picks properties; `Where-Object` filters objects.

**PS14 — Medium:** Classes (v5+) define types. Limited inheritance (no multiple), no interfaces. Constructors `ClassName()`. Use for data models or complex logic encapsulation; functions for cmdlets/scripts.

**PS15 — Medium:** `[CmdletBinding()]` makes function advanced. `SupportsShouldProcess` enables `-WhatIf`. `ValueFromPipeline` allows pipeline input. `Begin/Process/End` blocks handle initialization, per-item, and cleanup.

**PS16 — Medium:** Providers expose data stores as drives. `Get-ChildItem` works on `FileSystem`, `Registry`, `Certificate`. Access registry: `Get-ChildItem HKLM:\Software`.

**PS17 — Hard:** Runspaces = threads. `[runspacepool]` manages pool. `ForEach-Object -Parallel` (v7+) uses runspace pool automatically. Manual runspace gives more control but is verbose.

**PS18 — Hard:** PSScriptAnalyzer = static analysis/linting. Rules check style/security. Severity: Error, Warning, Info. Suppress with `[Diagnostics.CodeAnalysis.SuppressMessageAttribute]`. Integrate into CI via `Invoke-ScriptAnalyzer`.

**PS19 — Hard:** `$using:` captures local vars for remote sessions. `-ArgumentList` passes args. Serialization (CLIXML) limits depth/type (e.g., no open streams). Complex objects may lose methods or become generic.

**PS20 — Hard:** DSC configures systems declaratively. Configurations = scripts, Resources = units, LCM = agent. Windows PowerShell vs PS7: PS7 DSC is modular. Replaced by Ansible, Terraform, Bicep, ARM templates for modern IaC.
