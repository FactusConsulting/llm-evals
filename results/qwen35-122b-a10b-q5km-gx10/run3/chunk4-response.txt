G1 — **Slice vs Array:** An array is a fixed-size value type (e.g., `[5]int`). A slice is a dynamic view over an array, consisting of a pointer, length, and capacity (`struct { ptr, len, cap }`). When appending to a slice that exceeds capacity, Go allocates a new underlying array (usually doubling capacity), copies existing elements, and updates the slice header.

G2 — **`var` vs `:=`:** `var x int` declares a variable with a type (zero-initialized). `x := 0` infers the type and declares/assigns in one step. You cannot use `:=` outside a function, or if the variable is already declared in the same scope (unless you are assigning to at least one new variable).

G3 — **Goroutine vs Thread:** A goroutine is a lightweight user-space thread managed by the Go runtime, not the OS. It uses a small stack (KB vs MB). The Go Scheduler uses the **GMP model**: **G** (Goroutine), **M** (Machine/OS Thread), **P** (Processor/Logical CPU). The scheduler multiplexes many Gs onto fewer Ms, handling blocking syscalls and work-stealing.

G4 — **Channels:** Channels are typed conduits for communication between goroutines. **Unbuffered** channels block on send until a receiver is ready (synchronous). **Buffered** channels queue up to N items. Sending to a full buffered channel blocks until space is available; receiving from an empty one blocks until data arrives.

G5 — **Context:** Used for cancellation, timeouts, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 500*time.Millisecond)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
client.Do(req) // Cancels if >500ms
```

G6 — **Interfaces:** Go uses **implicit satisfaction** (duck typing); a type implements an interface by implementing its methods, no `implements` keyword. Java/C# require explicit declaration. `interface{}` (or `any`) accepts any type. It is powerful for generics (pre-1.18) but dangerous as it bypasses compile-time type safety, requiring type assertions.

G7 — **Memory Model:** This is unsafe due to a **data race**. There is no synchronization, so the compiler/CPU may reorder writes/reads, or the main goroutine may not see the update to `ready` immediately. **Fix:** Use `sync/atomic` for `ready`, a `sync.Mutex`, or a channel to signal completion.

G8 — **Mutex vs RWMutex:** `Mutex` allows exclusive access. `RWMutex` allows multiple readers or one writer. Use `sync.Map` for read-heavy workloads with disjoint keys (avoids lock contention) but avoid it for iteration or overlapping keys due to higher overhead and lack of ordering guarantees compared to `map + Mutex`.

G9 — **Modules:** `go.mod` defines module path and dependencies. `go.sum` stores cryptographic checksums for reproducibility. `go mod tidy` adds missing and removes unused dependencies. **MVS (Minimum Version Selection)** selects the lowest version of a dependency that satisfies all version constraints in the dependency graph.

G10 — **Defer:** Schedules a function call to run when the surrounding function returns. Multiple defers execute in **LIFO** (Last In, First Out) order. **Gotcha:** In a loop, defer captures the loop variable by reference. Fix by passing the variable as an argument to the deferred function.

G11 — **Pointers:** A pointer holds a memory address. Zero value is `nil`. Create a pointer to a struct literal using `&StructType{Field: value}`.

G12 — **`init()`:** Runs automatically before `main()`. A package can have multiple `init()` functions; they execute in declaration order within the package. Across packages, execution order follows the import graph (dependencies first).

G13 — **`make` vs `new`:** `new(T)` allocates zeroed memory and returns `*T`. `make(T, ...)` initializes slices, maps, and channels and returns `T` (not a pointer). `make` sets up internal runtime structures; `new` does not.

G14 — **Error Handling:** Errors are values implementing the `error` interface (`Error() string`). Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error matches a target (handles wrapping). `errors.As` checks if an error is of a specific type (handles wrapping). `==` only checks direct equality.

G15 — **Composite Types:** Map (`map[K]V`), Slice (`[]T`), Channel (`chan T`), Struct (`struct{}`). **Zero Values:** Map: `nil`, Slice: `nil`, Channel: `nil`, Struct: zero value of each field.

G16 — **Race Condition:** Concurrent access to memory where at least one is a write, without synchronization. `-race` uses shadow memory to detect conflicts at runtime. **Fix:** Protect shared state with `sync.Mutex` or use channels to pass ownership.

G17 — **Select:** Like a `switch` for channels. Blocks until one case can proceed. If multiple are ready, one is chosen pseudo-randomly. **Timeout:** Use `case <-time.After(d):` as a case in the select.

G18 — **Escape Analysis:** Compiler decides stack vs heap allocation. Variables "escape" to heap if their address is taken, returned, or stored in a heap-allocated structure. Inspect with `go build -gcflags="-m"`. Matters for performance: heap allocation triggers GC pressure; stack is faster and GC-free.

G19 — **Reflection:** `reflect.Type` describes type metadata; `reflect.Value` holds the data. High performance cost due to dynamic dispatch and lack of static checks. Justified for generic libraries (e.g., ORM, JSON marshalers) or debugging; avoid in hot paths. Prefer generics (1.18+) where possible.

G20 — **`go:embed`:** Embeds files into the binary at compile time. `//go:embed file.txt`. Supports glob patterns for directories. Returns `embed.FS` (implements `io/fs.FS`). Limitations: Files must exist at build time; cannot be updated without recompiling.

R1 — **Ownership:** 1. Each value has exactly one owner. 2. When the owner goes out of scope, the value is dropped. 3. Ownership can be transferred (moved), but not copied (unless `Copy` trait). Prevents double-free and use-after-free.

R2 — **`String` vs `&str`:** `String` is an owned, growable, heap-allocated UTF-8 string. `&str` is a borrowed slice of UTF-8 bytes (view). Use `&str` for function inputs (flexible), `String` for outputs or when ownership is required.

R3 — **Borrowing:** You can have either one mutable reference (`&mut T`) OR any number of immutable references (`&T`), but not both simultaneously. The borrow checker enforces this at compile time to prevent data races and invalid memory access.

R4 — **`Result`/`Option`:** `Result<T, E>` handles success/failure. `Option<T>` handles some/none. `?` operator propagates errors/none to the caller.
```rust
fn read_file(path: &str) -> Result<String, io::Error> {
    fs::read_to_string(path)
}
```

R5 — **Smart Pointers:** `Box<T>`: Heap allocation, single owner. `Rc<T>`: Reference counted, single-threaded shared ownership. `Arc<T>`: Atomic reference counted, thread-safe shared ownership. Use `Box` for recursion/heap, `Rc` for graph structures, `Arc` for concurrency.

R6 — **Traits:** Similar to interfaces but support default implementations and generics. `dyn Trait` is a trait object (dynamic dispatch, vtable, heap). `T: Trait` is a generic bound (static dispatch, monomorphization, stack/inline).

R7 — **Lifetimes:** Annotations ensuring references do not outlive the data they point to. The function fails because the compiler doesn't know if the return value refers to `x` or `y`. **Fix:** `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

R8 — **`Send`/`Sync`:** `Send`: Type can be transferred across thread boundaries. `Sync`: Type can be referenced across threads (`&T` is `Send`). `Rc<T>` is not `Send` (ref count not atomic). `Arc<T>` is `Send`/`Sync` (atomic ref count).

R9 — **Async/Await:** `Future` is a state machine representing a computation. The executor polls the future until ready. Unlike Go's preemptive goroutines, Rust async is cooperative (must yield). This allows zero-cost abstractions but requires explicit `.await` points.

R10 — **`unsafe`:** Allows bypassing safety guarantees. 1. Dereference raw pointers. 2. Call unsafe functions. 3. Access union fields. Justified for FFI, low-level OS interaction, or implementing safe abstractions where the compiler cannot verify safety.

R11 — **Pattern Matching:** `match` requires exhaustive cases (compiler enforces). `if let` handles partial matches. `match` is more powerful for destructuring enums/structs.

R12 — **`Vec` vs Array:** `[T; N]` is fixed size, stack allocated. `Vec<T>` is dynamic, heap allocated. When capacity is exceeded, `Vec` allocates a new larger buffer (usually 2x), copies/moves elements, and frees the old buffer.

R13 — **Enums:** Rust enums are Algebraic Data Types (ADTs) that can hold data (variants with fields). C/Java enums are just integer constants. `Option<T>` is an enum (`Some(T) | None`) replacing null pointers, forcing explicit handling of absence.

R14 — **`impl` Block:** Defines methods for a type. `&self` borrows immutably, `&mut self` borrows mutably, `self` consumes ownership. Associated functions (no `self`) are called via `Type::func()`, used for constructors.

R15 — **`derive` Macro:** Automatically implements standard traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if the trait requires custom logic (e.g., `Drop`) or if the type contains non-derivable fields.

R16 — **`Cow` (Clone on Write):** `Cow<'a, T>` holds either a borrowed reference (`&'a T`) or an owned value (`T`). Useful when you might mutate data. If no mutation occurs, no allocation/clone happens. Example: Normalizing a string only if it contains invalid chars.

R17 — **Modules:** `mod` declares a module. `use` brings paths into scope. `pub` exports visibility. 2018 Edition: `mod.rs` is optional; `mod_name.rs` works directly. File system structure maps to module hierarchy more intuitively.

R18 — **`Pin<T>`:** Prevents moving a value in memory. Required for self-referential structs (common in async `Future`s) where a pointer inside the struct points to the struct itself. `Unpin` indicates a type is safe to move even if pinned.

R19 — **Macros:** Declarative (`macro_rules!`) for pattern matching code. Procedural (derive, attribute, function-like) compile to AST and generate code. Hygiene ensures macro variables don't accidentally capture or conflict with local variables.

R20 — **Zero-Cost Abstractions:** High-level features compile to code as efficient as C. Iterators are inlined (no runtime overhead). Generics use monomorphization (specialized code per type). Traits use static dispatch (vtables only when `dyn` used). No hidden allocations or runtime checks.
