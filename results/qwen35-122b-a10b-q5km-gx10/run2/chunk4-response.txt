G1 — **Slice vs Array:** An array is a fixed-size value type; a slice is a dynamic view (descriptor containing pointer, length, capacity) over an array. **Append:** If capacity is reached, Go allocates a new underlying array, copies data, and updates the slice header.

G2 — **`var` vs `:=`:** `var x int` declares with explicit type; `x := 0` infers type and declares. **Restriction:** `:=` cannot be used at package scope (top-level) or if the variable is already declared in the current scope.

G3 — **Goroutine vs Thread:** Goroutines are lightweight user-space threads managed by the Go runtime. **GMP Model:** The scheduler multiplexes many Goroutines (G) onto fewer OS threads (M) via logical processors (P), allowing efficient concurrency without OS overhead.

G4 — **Channels:** Channels enable typed communication between goroutines. **Buffered vs Unbuffered:** Unbuffered blocks send/receive until the other side is ready (synchronous). Buffered queues values up to capacity. **Full Buffer:** Sending to a full buffered channel blocks until space is available.

G5 — **Context:** Manages cancellation, deadlines, and request-scoped values. **Example:**
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
```

G6 — **Interfaces:** Go uses implicit satisfaction (duck typing); Java/C# require explicit declaration. **`interface{}` (any):** Accepts any type. **Power/Danger:** Powerful for generic code but dangerous as it bypasses compile-time type safety.

G7 — **Memory Model:** Without synchronization, there is no "happens-before" guarantee. The compiler/CPU may reorder writes or cache `ready` in a register, causing the loop to spin forever. **Fix:** Use `sync/atomic`, `sync.Mutex`, or channels.

G8 — **Mutex vs RWMutex:** `RWMutex` allows multiple readers or one writer. **sync.Map:** Optimized for read-heavy workloads with disjoint keys. **Trade-off:** `sync.Map` has higher overhead for writes/updates compared to `map + mutex`.

G9 — **Modules:** `go.mod` lists requirements; `go.sum` stores checksums. **`go mod tidy`:** Removes unused deps, adds missing ones. **MVS:** Minimum Version Selection picks the lowest version satisfying all constraints.

G10 — **Defer:** Schedules a function call to run after the surrounding function returns (LIFO order). **Gotcha:** Deferring inside a loop (e.g., closing files) delays resource release until the function exits, not the iteration.

G11 — **Pointer:** Holds a memory address. **Zero Value:** `nil`. **Creation:** `p := &MyStruct{}`.

G12 — **`init()`:** Runs before `main()` for package initialization. **Multiple:** Allowed per package. **Order:** Undefined within a package; deterministic across packages based on import graph.

G13 — **`make` vs `new`:** `new(T)` allocates zeroed memory (returns `*T`). `make(T)` initializes slices, maps, channels (returns T). `make` works only on reference types.

G14 — **Errors:** Values implementing `Error() string`. **Pattern:** `if err != nil { return err }`. **`errors.Is/As`:** Handle wrapped errors (`Is`) or type assertions (`As`). `==` checks exact equality only.

G15 — **Composite Types:** Map, Slice, Channel, Struct. **Zero Values:** Map (nil), Slice (nil), Channel (nil), Struct (zero values of fields).

G16 — **Race Condition:** Concurrent access where at least one is a write. **`-race`:** Uses shadow memory instrumentation to detect conflicts. **Fix:** Protect shared state with `sync.Mutex` or use channels.

G17 — **Select:** Waits on multiple channel operations. **Switch:** Like `switch` for channels. **Multiple Ready:** One is chosen pseudo-randomly. **Timeout:** `case <-time.After(d)`.

G18 — **Escape Analysis:** Compiler decides stack vs heap allocation. Pointers escaping function scope force heap allocation. **Inspect:** `go build -gcflags="-m"`. **Impact:** Heap allocation increases GC pressure.

G19 — **Reflection:** `reflect.Type` (metadata), `reflect.Value` (data). **Cost:** High runtime overhead. **Justification:** Serialization, CLI tools. **Alternative:** Code generation for performance-critical paths.

G20 — **`go:embed`:** Embeds files into binary at build time. **Usage:** Files, directories, patterns. **FS:** Implements `io/fs.FS`. **Limitations:** Files must exist at build time; immutable at runtime.

R1 — **Ownership:** 1) Each value has one owner. 2) When owner goes out of scope, value is dropped. 3) Ownership transfers (move), not copies. Ensures memory safety without GC.

R2 — **`String` vs `&str`:** `String` is owned, heap-allocated, mutable. `&str` is a borrowed string slice (view). **Usage:** Use `&str` for inputs to avoid allocation; `String` for returning owned data.

R3 — **Borrowing:** Temporary access. **Rules:** Many immutable (`&T`) OR one mutable (`&mut T`). No mixing. **Borrow Checker:** Enforces this at compile time to prevent data races.

R4 — **`Result`/`Option`:** `Result` handles errors; `Option` handles nullability. **`?`:** Propagates errors/none. **Example:** `fs::read_to_string(path)` returns `Result<String, Error>`.

R5 — **Smart Pointers:** `Box<T>`: Heap, single owner. `Rc<T>`: Ref-counted, single thread. `Arc<T>`: Atomic ref-counted, thread-safe. Use `Arc` for shared state across threads.

R6 — **Traits:** Define shared behavior (like interfaces). **`dyn Trait`:** Dynamic dispatch (vtable). **`T: Trait`:** Static dispatch (monomorphization). Go interfaces are dynamic by default.

R7 — **Lifetimes:** Ensure references don't outlive data. **Failure:** Compiler can't infer which input lifetime the output references. **Fix:** `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

R8 — **`Send`/`Sync`:** `Send` allows transferring ownership across threads; `Sync` allows sharing references. **`Rc`:** Not `Send` (non-atomic ref count). **`Arc`:** Uses atomics, making it `Send` and `Sync`.

R9 — **Async/Await:** Compiles to state machines. `Future` is lazy. Executors (Tokio) poll futures. **Go vs Rust:** Go is preemptive/stackful; Rust is cooperative/stackless (no stack per task).

R10 — **`unsafe`:** Bypasses borrow checker. **Capabilities:** 1) Dereference raw pointers. 2) Call unsafe functions. 3) Access union fields. **Justification:** FFI, low-level ops, verified safety.

R11 — **Pattern Matching:** Deconstructs values. **`match`:** Requires exhaustiveness. **`if let`:** Partial matches. **Enforcement:** Compiler warns on non-exhaustive matches.

R12 — **`Vec` vs Array:** `Vec` is heap-allocated dynamic array; `[T; N]` is stack-allocated fixed array. **Capacity:** `Vec` reallocates (typically 2x) and copies when full.

R13 — **Enums:** Sum types that can hold data. **C/Java:** Enums are integers. **`Option<T>`:** `Some(T)` or `None`, eliminating null pointer exceptions.

R14 — **`impl`:** Defines methods. **`&self`:** Immutable borrow. **`&mut self`:** Mutable borrow. **`self`:** Consume. **Associated:** `Self::new()` (no `self`).

R15 — **`derive`:** Generates trait implementations. **Common:** `Debug`, `Clone`, `PartialEq`, `Serialize`. **Limit:** Cannot derive if trait requires custom logic or bounds aren't met.

R16 — **`Cow`:** Clone on Write. Holds borrowed or owned data. **Use:** Avoids cloning if no mutation occurs (e.g., `Cow<'a, str>`).

R17 — **Modules:** `mod` (declare), `use` (import), `pub` (export). **2018:** `mod.rs` optional; file structure maps to hierarchy.

R18 — **`Pin`:** Prevents moving data in memory. **Need:** Self-referential structs (async). **`Unpin`:** Safe to move even if pinned.

R19 — **Macros:** Declarative (`macro_rules!`) matches patterns. Procedural (derive/attr) generates code via AST. **Hygiene:** Prevents variable capture conflicts.

R20 — **Zero-Cost:** No runtime overhead. **Iterators:** Inlined. **Generics:** Monomorphization (unique code per type). **Traits:** Static dispatch. Performance matches C.
