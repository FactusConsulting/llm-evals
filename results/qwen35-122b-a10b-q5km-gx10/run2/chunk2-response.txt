K1 — **Deployment vs. StatefulSet:**
A **Deployment** manages stateless applications with random pod names and unordered scaling. A **StatefulSet** manages stateful applications with stable, unique pod names (e.g., `web-0`, `web-1`), ordered deployment/scaling, and stable network identities. Use StatefulSet for databases or apps requiring persistent identity.

K2 — **ClusterIP Routing:**
A ClusterIP Service exposes an internal virtual IP. **kube-proxy** runs on each node and configures **iptables** (or IPVS) rules to forward traffic destined for the Service IP to one of the backing **Pod IPs** (selected by the Service's label selector).

K3 — **PV, PVC, StorageClass:**
*   **PersistentVolume (PV):** A piece of storage in the cluster (resource).
*   **PersistentVolumeClaim (PVC):** A request for storage by a user (claim).
*   **StorageClass:** Defines the "type" of storage (provisioner) for dynamic provisioning.
*   **Relation:** A PVC binds to a PV. If no static PV exists, the PVC triggers the StorageClass to dynamically create a PV.

K4 — **CrashLoopBackOff Troubleshooting:**
1.  **Logs:** `kubectl logs <pod> --previous` to see why it exited.
2.  **Events:** `kubectl describe pod <pod>` to check for OOMKilled, probe failures, or scheduling issues.
3.  **Resources:** Check if memory/CPU limits are too low causing kills.
4.  **Config:** Verify ConfigMaps/Secrets mount points and application entrypoint arguments.

K5 — **CoreDNS Role:**
CoreDNS provides internal DNS resolution for Kubernetes services (e.g., `my-service.default.svc`). If CoreDNS pods are down, **internal service discovery fails**, causing pods to be unable to resolve other service names. External DNS may still work if configured to use upstream resolvers, but internal traffic breaks.

K6 — **Scheduler Decision Process:**
1.  **Filtering (Predicates):** Eliminates nodes that cannot satisfy constraints (resources, taints, affinity).
2.  **Scoring (Priorities):** Ranks remaining nodes based on factors.
3.  **Factors:** Node resources (CPU/Mem), Node Affinity, Taints/Tolerations, Pod Affinity/Anti-Affinity, Topology Spread Constraints.

K7 — **Memory Scheduling & Runtime:**
*   **Scheduling:** Yes. 3.5GB (used) + 256Mi (request) = 3.75GB < 4GB (capacity).
*   **Runtime:** If usage hits 600Mi (exceeding 512Mi limit), the container is **OOMKilled** by the kubelet.

K8 — **Ingress Request Lifecycle:**
1.  **External LB:** Routes traffic to Ingress Controller Pod IP.
2.  **Ingress Controller:** Reads Ingress Resource rules.
3.  **Service:** Controller forwards to Service ClusterIP.
4.  **Endpoints:** Service resolves to Pod IPs.
5.  **kube-proxy:** Node-level iptables/IPVS rules forward traffic to the specific Pod IP.
6.  **Pod:** Application receives request.

K9 — **NetworkPolicy:**
A firewall for pods. **Default:** Allow all ingress/egress. **When applied:** If a policy selects a pod, it **denies all traffic** not explicitly allowed by the policy rules (default deny for selected pods).

K10 — **RollingUpdate vs. Recreate:**
*   **RollingUpdate:** Spins up new pods before terminating old ones (zero downtime).
*   **Recreate:** Terminates all existing pods before creating new ones (downtime).
*   **Use Recreate:** For stateful apps where parallel instances conflict (e.g., single-writer DB without shared storage) or incompatible version migrations.

K11 — **Namespace:**
A logical isolation mechanism for resources. **Default Namespaces:** `default`, `kube-system`, `kube-public`, `kube-node-lease`.

K12 — **kubectl describe:**
Shows detailed status. **Information not in `get`:** 1. **Events** (recent warnings/info), 2. **Conditions** (Ready, Initialized status), 3. **Mounts/Env** (ConfigMap/Secret details), 4. **Resource Usage** (limits/requests).

K13 — **ConfigMap:**
Stores non-confidential configuration data. **Consumption Methods:** 1. **Environment Variables** (`envFrom` or `env`), 2. **Volume Mounts** (files in container).

K14 — **Service Types:**
*   **ClusterIP:** Internal IP only (default).
*   **NodePort:** Exposes port on each Node's IP.
*   **LoadBalancer:** Provisions external cloud Load Balancer.

K15 — **DaemonSet:**
Ensures a copy of a pod runs on **all (or some) nodes**. Use instead of Deployment for node-level agents like logging (Fluentd), monitoring (Node Exporter), or storage drivers.

K16 — **Taints/Tolerations vs. Affinity:**
*   **Taints/Tolerations:** Repel pods from nodes (e.g., Taint GPU node, Toleration schedule AI pod).
*   **Affinity:** Attract pods to nodes (e.g., Schedule DB on SSD nodes).
*   **Difference:** Taints are node-side constraints; Affinity is pod-side preferences.

K17 — **Kubernetes Operator:**
A controller that manages custom resources (CRDs). **Difference:** Standard controllers manage built-in types (Pods, Deployments); Operators manage complex application lifecycles (e.g., DB upgrades, backups). **Solves:** Automation of stateful app operations beyond simple pod management.

K18 — **etcd Consistency & Recovery:**
*   **Model:** Raft consensus (strong consistency).
*   **Quorum Lost:** Cluster becomes read-only/unavailable (cannot write).
*   **Recovery (2/3 lost):** Quorum is lost. You must **restore from a snapshot** on the surviving node and reconfigure the cluster, or provision new nodes and restore data. Data loss is possible without backups.

K19 — **RBAC & Manifest:**
*   **Role/ClusterRole:** Define permissions (verbs/resources).
*   **RoleBinding/ClusterRoleBinding:** Link users/groups to Roles.
*   **Manifest:**
    ```yaml
    apiVersion: rbac.authorization.k8s.io/v1
    kind: Role
    metadata:
      namespace: dev
      name: pod-reader
    rules:
    - apiGroups: [""]
      resources: ["pods", "pods/log"]
      verbs: ["get", "list", "watch"]
    ---
    apiVersion: rbac.authorization.k8s.io/v1
    kind: RoleBinding
    metadata:
      name: read-pods
      namespace: dev
    subjects:
    - kind: User
      name: developer
    roleRef:
      kind: Role
      name: pod-reader
      apiGroup: rbac.authorization.k8s.io
    ```

K20 — **DNS ndots Issue:**
*   **Cause:** Default `ndots: 5`. If a domain has <5 dots (e.g., `service`), the resolver appends search paths (e.g., `service.ns.svc...`), causing multiple queries before finding the external domain.
*   **Fix:** Set `dnsConfig.options` in Pod spec: `name: ndots`, `value: "1"`.

D1 — **git rebase vs. merge:**
*   **Rebase:** Rewrites history to be linear (moves commits).
*   **Merge:** Preserves history (creates merge commit).
*   **Avoid Rebase:** On **public/shared branches** (e.g., `main`) to prevent forcing others to rewrite their history.

D2 — **TCP vs. UDP:**
*   **TCP:** Reliable, ordered, connection-oriented. (Protocols: HTTP, SSH).
*   **UDP:** Unreliable, unordered, connectionless. (Protocols: DNS, VoIP).

D3 — **Race Condition:**
Outcome depends on the timing of uncontrollable events. **Example:** Two threads incrementing a shared counter `i++` without a lock; one update may overwrite the other, losing an increment.

D4 — **Symmetric vs. Asymmetric Encryption:**
*   **Symmetric:** Same key for encrypt/decrypt (fast).
*   **Asymmetric:** Public/Private key pair (slow, secure exchange).
*   **TLS:** Asymmetric exchanges the session key; Symmetric encrypts the actual data traffic.

D5 — **Container Image Layer:**
A read-only filesystem diff. **Layer Caching:** Docker caches layers. **Best Practice:** Place stable instructions (e.g., `COPY package.json`, `RUN npm install`) **before** changing code to maximize cache hits.

D6 — **HTTP 503 Troubleshooting:**
1.  **Upstream Health:** Check if backend services are healthy.
2.  **Load Balancer:** Verify LB health checks and routing rules.
3.  **Logs:** Check application logs for errors or timeouts.
4.  **Resources:** Check for CPU/Memory saturation causing timeouts.

D7 — **CAP Theorem:**
Consistency, Availability, Partition Tolerance. You can only guarantee 2.
*   **CP (Consistency + Partition Tolerance):** HBase, Zookeeper (sacrifices availability during partition).
*   **AP (Availability + Partition Tolerance):** Cassandra, DynamoDB (sacrifices immediate consistency).

D8 — **Horizontal vs. Vertical Scaling:**
*   **Horizontal:** Add more nodes (scale out).
*   **Vertical:** Add more resources to existing node (scale up).
*   **Patterns:** Stateless architecture, Load Balancing, Database Sharding.

D9 — **Environment Variable:**
Key-value pair in the process environment. **Persist:** Add `export VAR=value` to `~/.bashrc` or `/etc/environment`.

D10 — **JSON vs. YAML:**
*   **JSON:** Data interchange. **Advantage:** Strict, easy to parse.
*   **YAML:** Configuration. **Advantage:** Human-readable, supports comments.

D11 — **REST API:**
Stateless API using HTTP methods.
*   **GET:** Retrieve resource.
*   **POST:** Create resource.
*   **PUT:** Replace/Update resource.
*   **DELETE:** Remove resource.

D12 — **Version Pinning:**
Locking dependencies to specific versions (e.g., `package-lock.json`). **Importance:** Ensures **reproducible builds** and prevents breaking changes from upstream updates.

D13 — **Compiled vs. Interpreted:**
*   **Compiled:** Source -> Binary (Go, C++). Faster execution.
*   **Interpreted:** Source -> Runtime (Python, JS). Faster iteration.

D14 — **Reverse vs. Forward Proxy:**
*   **Reverse Proxy:** Sits in front of servers (Nginx, HAProxy). Use: Load balancing, SSL termination.
*   **Forward Proxy:** Sits in front of clients (Squid). Use: Anonymity, content filtering.

D15 — **Deadlock:**
Processes waiting indefinitely for resources. **Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

D16 — **Eventual Consistency:**
Data converges over time. **Cassandra:** Uses tunable consistency levels (ONE, QUORUM, ALL). **Read-after-write:** May require `QUORUM` reads or read-repair mechanisms to ensure consistency.

D17 — **mTLS (Mutual TLS):**
Both client and server authenticate via certificates. **Handshake:** 1. ClientHello, 2. ServerHello + Server Cert + **Request Client Cert**, 3. Client Cert + Verify, 4. Server verifies Client Cert. **Use:** Service Mesh (Istio), internal microservice APIs.

D18 — **Hash Table:**
Key-value store using hash function to index array. **Collision:** Chaining (linked list at index) or Open Addressing (probe next slot). **Complexity:** Avg O(1), Worst O(n) (all collisions).

D19 — **Circuit Breaker:**
Prevents cascade failures. **States:** 1. **Closed** (requests flow), 2. **Open** (fail fast, stop calls), 3. **Half-Open** (allow test requests). **Relation:** Works with retries; if circuit opens, retries are suppressed to avoid load.

D20 — **Optimistic vs. Pessimistic Concurrency:**
*   **Optimistic:** Assume no conflict; check version on commit (`UPDATE ... WHERE version = X`). Use: High read/low write.
*   **Pessimistic:** Lock row on read (`SELECT ... FOR UPDATE`). Use: High contention.
