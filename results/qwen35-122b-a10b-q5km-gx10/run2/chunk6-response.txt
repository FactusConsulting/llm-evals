## JavaScript / TypeScript

**JS1 — Easy:**
`var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but reside in the Temporal Dead Zone (TDZ) until declaration. `const` cannot be reassigned. **Hoisting** is the behavior where variable and function declarations are moved to the top of their scope during compilation before execution.

**JS2 — Easy:**
The **event loop** monitors the call stack and task queues. When the stack is empty, it pushes tasks from queues to the stack. **Microtask queue** (Promises, `queueMicrotask`) has higher priority than the **macrotask queue** (`setTimeout`, I/O). Microtasks run to completion before the next macrotask.

**JS3 — Medium:**
A **closure** is a function bundled with its lexical environment, allowing access to outer scope variables after the outer function returns.
*Example:* `function makeAdder(x) { return function(y) { return x + y; }; }`
*Bug:* In `for (var i=0; i<3; i++) { setTimeout(() => console.log(i), 100); }`, all logs print `3` because `var` is function-scoped.
*Fix:* Use `let` (block scope) or an IIFE to capture the current `i`.

**JS4 — Medium:**
**Promise** represents a future value. **async/await** is syntactic sugar over Promises. Error handling: `.catch()` for Promises, `try/catch` for async/await.
*Promise.all:* Fails fast if any promise rejects.
*Promise.allSettled:* Waits for all to settle (fulfill or reject), returning an array of status objects.

**JS5 — Medium:**
**Interface:** Structural, mergeable, primarily for object shapes. **Type:** Can define primitives, unions, intersections, tuples. Use `interface` for public API shapes, `type` for complex types. **Discriminated unions:** Unions with a common literal property (tag) used to narrow types (e.g., `{ type: 'a', val: string } | { type: 'b', val: number }`).

**JS6 — Medium:**
**Prototypal inheritance:** Objects link to other objects via `[[Prototype]]`. Property lookup traverses this chain. **Object.create(proto)** creates a new object with `proto` as its prototype. **ES6 classes** are syntactic sugar over prototypes; `class Foo {}` creates a constructor function with a `prototype` property.

**JS7 — Hard:**
**`this`** refers to the execution context. **Binding rules (priority):** 1. `new` binding, 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (method call `obj.fn()`), 4. Default (global/undefined). **`bind()`** returns a new function with `this` permanently bound; it cannot be re-bound.

**JS8 — Hard:**
**WeakRef** holds a weak reference to an object (allows GC). **FinalizationRegistry** registers callbacks to run when an object is GC'd. **WeakMap** keys must be objects because primitives cannot be weakly referenced (they are values, not references). This prevents memory leaks by allowing keys to be garbage collected.

**JS9 — Hard:**
**V8 Optimization:**
*   **Hidden Classes:** Internal structures for object shapes; similar shapes share classes for fast property access.
*   **Inline Caching:** Caches the location of properties based on previous access.
*   **Deoptimization:** Occurs when assumptions break (e.g., changing object shape, using `eval`, mixed types in arrays). Coding patterns: Adding properties dynamically, using `arguments` object, or non-monomorphic code.

**JS10 — Medium:**
**Tree-shaking** removes unused code. It works with **ES Modules** because imports are static (analyzable at build time). **CommonJS** uses dynamic `require()`, making static analysis impossible, so unused code often remains bundled.

**JS11 — Easy:**
**`null`** is an assignment value (intentional empty). **`undefined`** means uninitialized. `null == undefined` is `true`; `null === undefined` is `false`. **`??`** (Nullish Coalescing) returns RHS if LHS is `null` or `undefined`. **`?.`** (Optional Chaining) safely accesses nested properties without throwing if intermediate is nullish.

**JS12 — Easy:**
**`map()`** transforms elements. **`filter()`** selects elements. **`reduce()`** accumulates values. `reduce` with an initial value ensures the accumulator starts correctly (prevents first element being used as accumulator). **`flatMap()`** maps then flattens one level; useful for transforming arrays into a single flat array.

**JS13 — Easy:**
**Template literals** use backticks (`` ` ``), support multiline and `${}` interpolation. **Tagged templates** call a function with the string parts and values.
*Example:* `function sql(strings, ...values) { return strings.reduce((acc, str, i) => acc + str + (values[i] || ''), ''); }`

**JS14 — Easy:**
**Destructuring** unpacks values from arrays/objects.
*   Object: `const { a, b } = obj`.
*   Array: `const [x, y] = arr`.
*   Defaults: `const { a = 1 } = obj`.
*   Renaming: `const { a: alias } = obj`.
*   Rest: `const { a, ...rest } = obj` collects remaining properties.

**JS15 — Easy:**
**`for...in`** iterates over enumerable property **keys** (including prototype chain). **`for...of`** iterates over iterable **values**. Avoid `for...in` on arrays because it iterates indices as strings, includes inherited properties, and order is not guaranteed.

**JS16 — Medium:**
**Generics** allow reusable components with flexible types.
*   **Constraints:** `T extends string` limits type.
*   **Conditional:** `T extends U ? X : Y` (if T is U, return X, else Y).
*   **Infer:** Captures inferred types in conditional types (e.g., `infer R` in `Promise<R>`).
*   *Example:* `type Unwrap<T> = T extends Promise<infer R> ? R : T;`

**JS17 — Medium:**
**CommonJS:** Dynamic `require`, `module.exports`, synchronous. **ES Modules:** Static `import`/`export`, asynchronous, tree-shakeable. **Node.js:** Supports both via file extensions (`.mjs` vs `.cjs`) or `package.json` `"type": "module"`. `"type": "module"` makes `.js` files default to ESM.

**JS18 — Hard:**
**Structural Type System:** Types are compatible if they have the same structure. **Excess property checks** apply to object literals assigned to variables (catches typos). **`extends`** checks assignability (subtype). **`satisfies`** checks compatibility without widening the type (preserves literals). **Variance:** `in` (contravariant), `out` (covariant) control type parameter behavior in generics (TS 4.7+).

**JS19 — Hard:**
**Proxy** creates a wrapper to intercept operations (get, set, apply, construct). **Reflect** provides default behavior for these operations.
*Example:* `new Proxy(target, { get(t, k) { console.log(k); return Reflect.get(t, k); } })`. Used for validation, logging, or reactivity (e.g., Vue 3).

**JS20 — Hard:**
**SharedArrayBuffer** allows shared memory between Web Workers. **Atomics** provide atomic read/write/lock operations. Workers communicate via `SharedArrayBuffer`. **`Atomics.wait`** blocks a worker until a value changes; **`Atomics.notify`** wakes waiting workers. Guarantees sequential consistency for atomic ops.

## Bash

**B1 — Easy:**
`$@` expands to separate arguments; `$*` expands to a single string. `"$@"` preserves each argument as a separate word (handles spaces). `"$*"` joins all arguments into one string separated by the first character of `IFS` (usually space).

**B2 — Easy:**
`set -euo pipefail`:
*   `-e`: Exit immediately if a command exits with non-zero status.
*   `-u`: Treat unset variables as an error.
*   `-o pipefail`: Return exit status of the last command in a pipeline that failed (not just the last one).

**B3 — Medium:**
`$(command)` is modern command substitution (nestable). `` `command` `` is legacy. `$((expression))` is arithmetic expansion (fast, built-in). `expr` is an external command (slower, requires escaping).

**B4 — Medium:**
**Process substitution** `<(command)` creates a named pipe (FIFO) and passes its filename as an argument.
*Example:* `diff <(sort file1) <(sort file2)` compares sorted outputs without creating temp files.

**B5 — Medium:**
Use `while IFS= read -r -d '' file; do ... done < <(find . -print0)` or `for f in *`. `for f in $(ls)` is dangerous because word splitting breaks filenames with spaces or newlines, and `ls` output is not meant for parsing.

**B6 — Medium:**
`<<EOF` (here document) reads multiple lines until EOF. `<<<` (here string) passes a single string to stdin. `<<-EOF` strips leading tabs (useful for indentation in scripts).

**B7 — Hard:**
1.  `cmd > file 2>&1`: Stdout goes to file, then stderr goes to where stdout was (file). **Both to file.**
2.  `cmd 2>&1 > file`: Stderr goes to stdout (console), then stdout goes to file. **Stdout to file, stderr to console.**
3.  `cmd &> file`: Bash shorthand for both stdout and stderr to file.
*Reason:* Redirections are processed left-to-right.

**B8 — Hard:**
*Function:*
```bash
lock() {
  local lock_dir="/tmp/mylock"
  if mkdir "$lock_dir" 2>/dev/null; then
    trap 'rmdir "$lock_dir"' EXIT
    # Do work
  else
    echo "Locked"
    exit 1
  fi
}
```
*Why:* `mkdir` is atomic on POSIX. `touch` is not (race condition). `trap EXIT` ensures cleanup on SIGTERM or normal exit.

**B9 — Easy:**
*   `'...'`: Literal string (no expansion).
*   `"..."`: Interpolates variables/commands.
*   No quotes: Word splitting and globbing.
*Example:* `echo $HOME` (expands), `echo '$HOME'` (literal), `echo *` (lists files).

**B10 — Easy:**
*   `-f file`: Exists and is regular file.
*   `-d dir`: Exists and is directory.
*   `-r file`: Readable.
*   `[ ]`: POSIX test command. `[[ ]]`: Bash keyword (safer, supports `&&`, `||`, pattern matching).

**B11 — Easy:**
*   `$?`: Exit status of last command.
*   `$$`: PID of current shell.
*   `$!`: PID of last background process.
*   `$#`: Number of arguments.
*Use:* Check `$?` for errors, `$$` for unique temp files, `$!` for monitoring jobs.

**B12 — Easy:**
Define: `function foo { ... }` or `foo() { ... }`. Difference: `function` keyword is optional in Bash; `foo()` is POSIX compatible. Return values: Use `return` for exit codes (0-255) or `echo` for data (captured via command substitution).

**B13 — Easy:**
**PATH** is a colon-separated list of directories where the shell searches for executables. Bash resolves commands by scanning PATH. **Builtin** commands are part of the shell (e.g., `cd`). **External** are files in PATH. Check with `type command`.

**B14 — Medium:**
**trap** sets a handler for signals.
*   `trap cleanup EXIT`: Runs on exit (success/fail).
*   `trap handler INT TERM`: Handles Ctrl+C or kill.
*Order:* Specific signal handlers run first, then `EXIT`. Multiple signals: Last one received usually triggers, but `EXIT` always runs at the end.

**B15 — Medium:**
**xargs** builds command lines from stdin. **Command substitution** captures output into a variable.
*Spaces:* `find . -print0 | xargs -0 cmd` (null-delimited).
*Parallel:* `xargs -P 4` runs up to 4 processes concurrently.

**B16 — Medium:**
*   **Indexed:** `arr=(a b)`, `arr+=("c")`, `${#arr[@]}`.
*   **Associative:** `declare -A arr`, `arr[key]=val`, `for k in "${!arr[@]}"`.
*   **Diff:** Indexed uses integers, Assoc uses strings. Assoc requires `declare -A`.

**B17 — Hard:**
*   `(...)`: Subshell (new process, variables lost outside).
*   `{ ...; }`: Group command (same shell, variables persist).
*   **Pipe while:** `cmd | while read` runs in a subshell, so variable changes inside the loop are lost after the loop. Fix: `while read; do ... done < <(cmd)`.

**B18 — Hard:**
*   **SIGINT:** Interrupt (Ctrl+C).
*   **SIGTERM:** Terminate (graceful).
*   **SIGHUP:** Hangup (terminal closed).
*   **SIGKILL:** Force kill (cannot trap).
*Graceful:* `trap 'cleanup; exit' TERM INT`. Kill background jobs in trap handler (`kill 0` or track PIDs).

**B19 — Hard:**
*Script:* Split log (`split -l 1000`), `xargs -P 4 -I {} process {}`, merge (`cat`).
*Trade-offs:* Parallelism speeds up CPU-bound tasks; IO-bound tasks may bottleneck.
*Error:* `set -o pipefail` ensures pipeline fails if any part fails. Check `xargs` exit code.

**C20 — Hard:**
*   **exec:** Replaces current shell process with command (no return).
*   **FD:** `exec 3>file` opens FD 3. `exec 3>&-` closes it.
*   **Coprocess:** `coproc cmd` creates bidirectional pipe. Use for interactive CLI tools needing input/output streams simultaneously.

## PowerShell

**PS1 — Easy:**
**Write-Output** sends objects to the pipeline (default). **Write-Host** writes directly to the console host (bypasses pipeline). Distinction matters because `Write-Host` output cannot be captured or piped to other commands.

**PS2 — Easy:**
**Pipeline** passes objects between commands. **ForEach-Object** is a cmdlet (`%`) that processes pipeline input one by one. **foreach** is a language statement that iterates a collection in memory. Use `ForEach-Object` for streaming large data; `foreach` for in-memory arrays.

**PS3 — Medium:**
**[PSCustomObject]** creates a typed object with properties. **[hashtable]** is a key/value dictionary (`@{}`). Use Hashtable for configuration/params, PSCustomObject for structured data output. Convert: `[PSCustomObject]$hash` or `$obj | ConvertTo-Json`.

**PS4 — Medium:**
**Terminating errors** stop execution (trigger `catch`). **Non-terminating** continue execution. **-ErrorAction** (Stop/Continue) overrides preference. **$ErrorActionPreference** sets global default. **try/catch** only catches terminating errors.

**PS5 — Medium:**
**Splatting** (`@params`) passes a hashtable's keys/values as named parameters.
*Example:* `function Foo { param($a, $b) } $p = @{a=1; b=2}; Foo @p`.
*Diff:* Passing a hashtable directly (`Foo $p`) passes the whole table as the first argument.

**PS6 — Medium:**
**Invoke-Command** runs commands remotely (one-off). **Enter-PSSession** opens an interactive session. Protocol: **WinRM** (default) or **SSH**. WinRM uses HTTP/HTTPS; SSH uses standard SSH.

**PS7 — Hard:**
*Result:* `Object[]`. PowerShell unwraps single-item arrays in the pipeline, but `return $result` (where `$result` is explicitly `@()`) returns the array.
*0 items:* Returns `@()` (empty array), type is `Object[]`.
*Correct Pattern:* Avoid `return` unless necessary. Just output the variable. Ensure array context: `return @($result)`.

**PS8 — Hard:**
**[scriptblock]** is a code block `{ ... }`. **Function** is a named command. Pass scriptblock via `-ScriptBlock` or `-ArgumentList`. **Double-hop:** Credentials aren't forwarded to a second remote server. **Solve:** Use **CredSSP** authentication or pass data via `-ArgumentList` instead of credentials.

**PS9 — Easy:**
**@()**: Array subexpression operator (forces array context). **[array]**: Type cast.
*Force:* `$x = @($result)`.
*Index:* `$null[0]` throws error (in PS 7+); empty array `[0]` returns `$null`.

**PS10 — Easy:**
**-eq**: Equality. **-like**: Wildcard. **-match**: Regex. **-contains**: Checks if collection contains value. **-in**: Reverse of contains (`value -in $list`). Case-sensitive variants use `c` prefix (e.g., `-ceq`).

**PS11 — Easy:**
**Module:** Reusable code package. **Script (.psm1):** Code file. **Manifest (.psd1):** Metadata. **Binary (.dll):** Compiled. **Import-Module:** Loads module into session, making cmdlets available.

**PS12 — Easy:**
**"..."**: Interpolates variables (`$var`) and expressions (`$()`). **'...'**: Literal string. **Here-string:** `@" ... "@` for multiline strings with interpolation.

**PS13 — Easy:**
**Get-Member** (`gm`) lists properties/methods of pipeline objects. **Properties:** Data fields. **Methods:** Actions. **NoteProperties:** Dynamic props added via `Add-Member`. **Select-Object:** Picks properties. **Where-Object:** Filters objects.

**PS14 — Medium:**
**Classes:** v5+ feature. Similar to C# but limited (no inheritance from C# classes, limited constructors). Use for data models or complex logic encapsulation. Functions are preferred for cmdlets/scripts.

**PS15 — Medium:**
**CmdletBinding:** Enables advanced function features. **SupportsShouldProcess:** Adds `-WhatIf`/`-Confirm`. **DefaultParameterSetName:** Sets default param set. **ValueFromPipeline:** Allows piping to param. **Begin/Process/End:** Execution blocks for pipeline stages.

**PS16 — Medium:**
**Providers:** Map data stores to drives (FileSystem, Registry, Cert). **Get-ChildItem** works on `C:\`, `HKLM:\`, `Cert:\`. Access registry: `Get-ChildItem HKLM:\Software`.

**PS17 — Hard:**
**Runspaces:** Lightweight threads. **RunspacePool:** Manages a pool of runspaces. **ForEach-Object -Parallel:** v7+ feature using runspace pool internally. Manual runspace management offers more control (e.g., shared state) but is complex.

**PS18 — Hard:**
**PSScriptAnalyzer:** Static code analysis. **Rules:** Checks (e.g., naming). **Severity:** Error/Warning/Info. **Suppress:** `[Diagnostics.CodeAnalysis.SuppressMessageAttribute]`. **CI:** Fail build if Error severity rules trigger.

**PS19 — Hard:**
**$using:** Captures local variable value into remote session. **-ArgumentList:** Passes arguments to scriptblock. **Serialization:** Complex objects serialize to CLIXML. Depth limits exist; circular references or very deep objects may fail or truncate.

**PS20 — Hard:**
**DSC:** Configuration management. **Configurations:** Scripts defining state. **Resources:** Units of config (e.g., File, Service). **LCM:** Agent applying config. **Diff:** WinPS uses MOF; PS7 uses JSON/PowerShell DSC. **Replaced by:** Ansible, Chef, Puppet, ARM/Bicep, Terraform.
