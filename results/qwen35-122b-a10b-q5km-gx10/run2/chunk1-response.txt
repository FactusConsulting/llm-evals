N1 — **Layer 2 vs. Layer 3 Switch**
A Layer 2 switch forwards frames based on MAC addresses within a broadcast domain (VLAN). A Layer 3 switch can perform routing (forwarding packets based on IP addresses) between VLANs or subnets, effectively acting as a router with hardware-accelerated forwarding.

N2 — **Network and Broadcast Address**
Mask /20 = 255.255.240.0. Block size in 3rd octet is 16.
IP: 10.0.5.37
Network Address: **10.0.0.0**
Broadcast Address: **10.0.15.255**

N3 — **TCP Three-Way Handshake**
1. Client sends SYN.
2. Server replies SYN-ACK.
3. Client sends ACK.
If the final ACK is lost, the server retransmits the SYN-ACK. The client ignores the retransmission (having already sent ACK) but the server eventually times out and resets the connection if no ACK is received.

N4 — **SNAT vs. DNAT**
*   **SNAT (Source NAT):** Modifies source IP of outbound packets. Example: Internal host 10.0.0.5 accessing the internet appears as Public IP 203.0.113.1.
*   **DNAT (Destination NAT):** Modifies destination IP of inbound packets. Example: Port forwarding Public IP 203.0.113.1:80 to Internal Web Server 10.0.0.5:80.

N5 — **SSL Certificate Mismatch Causes**
1. The certificate's Common Name (CN) or Subject Alternative Name (SAN) does not match the requested hostname.
2. The server is presenting a certificate for a different domain (e.g., load balancer misconfiguration).
3. The client is connecting via IP address instead of the domain name covered by the certificate.

N6 — **VLAN vs. VxLAN**
*   **VLAN:** Layer 2 segmentation, limited to 4094 IDs, requires L2 adjacency.
*   **VxLAN:** Layer 3 overlay encapsulation (UDP), supports 16M VNIs, extends L2 domains over L3 networks.
*   **Choice:** Choose VxLAN for large-scale cloud environments, multi-tenant isolation beyond 4094, or stretching networks across data centers.

N7 — **Asymmetric Routing Fix**
**Why:** The default route points to eth0. Return traffic matches the default route, ignoring the incoming interface (eth1).
**Fix:** Use Policy-Based Routing (PBR).
1. Create a custom routing table (e.g., table 100).
2. Add rule: `ip rule add from 192.168.1.0/24 table 100`.
3. Add route: `ip route add default via 192.168.1.1 dev eth1 table 100`.

N8 — **BGP Path Selection (Top 5)**
1. **Weight** (Cisco proprietary, highest wins).
2. **Local Preference** (Highest wins).
3. **Locally Originated** (Locally injected preferred).
4. **AS Path** (Shortest wins).
5. **Origin Code** (IGP < EGP < Incomplete).

N9 — **MTU Implication (VxLAN over IPsec)**
Physical MTU: 1500 bytes.
Overhead:
*   Outer Ethernet: 14B
*   Outer IP: 20B
*   UDP: 8B
*   VxLAN: 8B
*   IPsec (ESP + IV + Auth): ~50B (varies by cipher)
Total Overhead ≈ 100B.
Max Inner Payload = 1500 - 100 = **1400 bytes**.
*Recommendation:* Increase physical MTU to 9000 (Jumbo Frames) or reduce inner MTU to 1400.

N10 — **ARP and Gratuitous ARP**
*   **ARP:** Resolves IPv4 addresses to MAC addresses on a local network.
*   **Gratuitous ARP:** An unsolicited ARP reply. Solves: 1) Updating neighbor caches after IP change, 2) Detecting IP conflicts, 3) Triggering failover updates on switches/load balancers.

N11 — **Public vs. Private IP**
*   **Public:** Globally routable on the internet.
*   **Private:** Reserved for internal networks, not routable on the public internet.
*   **RFC 1918 Ranges:**
    1. 10.0.0.0/8
    2. 172.16.0.0/12
    3. 192.168.0.0/16

N12 — **DNS Records**
*   **DNS:** Translates domain names to IP addresses.
*   **A Record:** Maps hostname to IPv4 address.
*   **CNAME:** Alias of one name to another (canonical name).
*   **AAAA:** Maps hostname to IPv6 address.

N13 — **DHCP and DORA**
*   **DHCP:** Protocol for automatic IP configuration.
*   **DORA Process:**
    1.  **D**iscover (Client broadcasts request).
    2.  **O**ffer (Server proposes IP).
    3.  **R**equest (Client accepts offer).
    4.  **A**cknowledge (Server confirms lease).

N14 — **Hub, Switch, Router**
*   **Hub:** Layer 1. Broadcasts all traffic to all ports.
*   **Switch:** Layer 2. Forwards frames based on MAC addresses.
*   **Router:** Layer 3. Routes packets based on IP addresses between networks.

N15 — **Half vs. Full Duplex**
*   **Half-Duplex:** Communication in one direction at a time (CSMA/CD).
*   **Full-Duplex:** Simultaneous two-way communication.
*   **Modern Ethernet:** Uses Full-Duplex exclusively (no collisions).

N16 — **TTL and Traceroute**
*   **TTL:** Time To Live. Decrementing counter to prevent infinite loops.
*   **Traceroute:** Sends packets with incrementing TTL (1, 2, 3...). Each router decrements TTL to 0, drops packet, and sends ICMP "Time Exceeded" back to source, revealing the path.

N17 — **NAT Gateway Types**
*   **NAT Gateway:** Translates private IPs to public IPs for internet access.
*   **Static NAT:** 1:1 mapping (fixed).
*   **Dynamic NAT:** Many-to-many from a pool.
*   **PAT (NAPT):** Many-to-1 using unique source ports (most common for home/office).

N18 — **ECMP and Asymmetric Flows**
*   **ECMP:** Load balances traffic across multiple equal-cost paths using a hash (src/dst IP, ports).
*   **Problem:** Stateful firewalls track connections. If request goes Path A and reply comes Path B, the firewall on Path B drops the reply (no state entry).
*   **Solution:** Ensure symmetric routing or use stateless firewalls/load balancers that handle ECMP.

N19 — **TCP Window Scaling**
*   **Problem:** Throughput = Window Size / RTT. With 64KB window and high latency, the pipe fills up, limiting bandwidth (BDP > Window).
*   **Solution:** RFC 1323 Window Scaling adds a shift count to the window field, allowing window sizes > 65,535 bytes (up to 1GB), enabling full utilization of high BDP links.

N20 — **802.1Q and Linux VLANs**
*   **802.1Q:** Inserts a 4-byte tag (VLAN ID + Priority) into Ethernet frame between Source MAC and EtherType.
*   **Linux Config:** Create sub-interfaces: `ip link add link eth0 name eth0.10 type vlan id 10`.
*   **Wire Format:** [Dest MAC][Src MAC][802.1Q Tag][EtherType][Payload][FCS].

L1 — **Hard vs. Symbolic Link**
*   **Hard Link:** Direct reference to the same inode (file data). Cannot span filesystems. Deleting original doesn't delete data.
*   **Symbolic Link:** Pointer to a path (like a shortcut). Can span filesystems. Deleting original breaks the link.

L2 — **Find Large Files**
Command: `find /var/log -type f -size +100M`

L3 — **Process State D**
*   **Meaning:** Uninterruptible sleep (usually waiting on I/O).
*   **Kill:** No. `kill -9` sends SIGKILL, but the process cannot handle signals while in state D. It must wait for I/O to complete or the device to reset.

L4 — **cgroups v1 vs. v2**
*   **v1:** Hierarchical, separate controllers (cpu, memory, io).
*   **v2:** Unified hierarchy, single mount point, improved resource control.
*   **Systemd:** Prefers v2 (default on modern distros) for consistency and better integration with unified resource management.

L5 — **nftables vs. iptables**
*   **Difference:** nftables is the successor, offering a unified syntax and backend. iptables is legacy.
*   **Kernel:** Both use the Netfilter framework. nftables replaces the internal rule set logic; iptables commands are often translated to nftables rules in modern kernels.

L6 — **Disk Full but du Low**
**Cause:** Files have been deleted but are still open by a running process. The space is held until the process closes the file or restarts.
**Fix:** Identify process (`lsof | grep deleted`) and restart it or truncate the file.

L7 — **Linux Boot Process**
1.  **UEFI:** Initializes hardware, loads bootloader.
2.  **Bootloader (GRUB):** Loads kernel and initramfs into memory.
3.  **Kernel:** Initializes hardware, mounts initramfs.
4.  **Initramfs:** Loads drivers, mounts real root filesystem.
5.  **Root FS:** Switches to real root.
6.  **Systemd:** Starts as PID 1, manages services to reach target (e.g., multi-user).

L8 — **OOM with High Buff/Cache**
*   **Why:** `available` estimates reclaimable memory. If a process requests large contiguous memory and cache cannot be freed fast enough (or fragmentation exists), OOM triggers.
*   **Tunables:** `vm.swappiness` (prefers swap vs cache reclaim), `vm.vfs_cache_pressure` (pressure to reclaim inode/dentry cache), `vm.overcommit_memory`.

L9 — **ip netns**
*   **Function:** Creates and manages Network Namespaces (isolated network stacks).
*   **Containers:** Runtimes (Docker/Podman) create a namespace per container, assigning virtual interfaces (veth pairs) to connect them to the host bridge.

L10 — **Signals**
*   **SIGTERM (15):** Graceful termination. **Catchable.**
*   **SIGKILL (9):** Force kill. **Not catchable.**
*   **SIGQUIT (3):** Quit + Core Dump. **Catchable.**

L11 — **Stdout, Stderr, Stdin**
*   **Stdout (1):** Normal output.
*   **Stderr (2):** Error output.
*   **Stdin (0):** Input.
*   **Redirect:** `command 2> error.log` (Stderr to file, Stdout to terminal).

L12 — **chmod 755**
*   **Owner (7):** Read (4) + Write (2) + Execute (1).
*   **Group (5):** Read (4) + Execute (1).
*   **Other (5):** Read (4) + Execute (1).
*   **Result:** `rwxr-xr-x`.

L13 — **Root vs. Sudo**
*   **Root:** UID 0. Unrestricted access to all system resources.
*   **Sudo:** Regular user granted specific privileges via `/etc/sudoers`. Auditable and limited scope.

L14 — **Package Managers**
*   **Definition:** Software to install, update, and remove packages.
*   **Debian/Ubuntu:** `apt` (frontend), `dpkg` (backend).
*   **RHEL/Fedora:** `dnf` (frontend), `rpm` (backend).

L15 — **/etc/fstab**
*   **Use:** Defines filesystem mount points and options at boot.
*   **Misconfig:** If `defaults` or critical mount fails without `nofail`, the system may drop to emergency mode or hang during boot.

L16 — **LVM**
*   **Concept:** Abstraction layer for disk management.
*   **PV:** Physical Volume (disk/partition).
*   **VG:** Volume Group (pool of PVs).
*   **LV:** Logical Volume (virtual partition).
*   **Extend:** `lvextend -L +10G /dev/vg/lv` followed by `resize2fs` (ext4) or `xfs_growfs` (xfs).

L17 — **I/O Schedulers**
*   **mq-deadline:** Optimizes for latency (deadlines). Good for HDDs/SSDs.
*   **bfq:** Budget Fair Queueing. Optimizes for fairness/throughput on HDDs.
*   **none:** No scheduling (passes to device). Best for NVMe (device handles queue).
*   **Change:** `echo none > /sys/block/nvme0n1/queue/scheduler`.

L18 — **High Load, Low CPU**
*   **Load Average:** Count of runnable processes + uninterruptible (D state) processes.
*   **Cause:** High I/O wait (D state) inflates load without CPU usage.
*   **Diagnose:** `iostat -x 1` (check `%util`/`await`), `vmstat 1` (check `wa`), `pidstat -d 1`.

L19 — **SELinux**
*   **Enforcement:** Enforcing (blocks), Permissive (logs only), Disabled (off).
*   **Troubleshoot:** Check logs (`/var/log/audit/audit.log` or `dmesg`). Use `ausearch -m avc -ts recent`. Fix with `setsebool` (toggle policy) or `chcon`/`restorecon` (fix context).

L20 — **Page Faults and THP**
*   **Page Fault:** Accessing memory not currently mapped in RAM.
*   **Minor:** Page exists in RAM (copy-on-write or swap cache).
*   **Major:** Page must be read from disk (swap/file).
*   **THP:** Uses 2MB pages instead of 4KB. Reduces TLB misses but can cause latency spikes during allocation/compaction.
*   **Disable:** For latency-sensitive apps (DBs) via `echo never > /sys/kernel/mm/transparent_hugepage/enabled`.
