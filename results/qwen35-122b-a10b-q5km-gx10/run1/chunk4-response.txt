## Go (20 questions)

**G1 — Easy: What is the difference between a slice and an array in Go? What happens when you append to a slice that has reached its capacity?**
An **array** has a fixed length defined at compile time and is a value type (copying copies the whole array). A **slice** is a dynamic view over an array, consisting of a pointer, length, and capacity. When appending to a slice that exceeds its capacity, Go allocates a new, larger underlying array (typically doubling capacity), copies existing elements, and updates the slice header to point to the new array.

**G2 — Easy: Explain the difference between `var x int` and `x := 0`. When can you NOT use `:=`?**
`var x int` explicitly declares a variable with a type. `x := 0` is a short variable declaration that infers the type from the value and declares the variable. You **cannot** use `:=` in the global scope (outside functions) or if the variable is already declared in the current scope (unless you are declaring at least one new variable in the same statement).

**G3 — Medium: What is a goroutine, and how does it differ from an OS thread? What is the role of the Go scheduler (GMP model)?**
A **goroutine** is a lightweight thread managed by the Go runtime, not the OS. It has a small initial stack (2KB) compared to OS threads (MBs). The **GMP model** manages concurrency: **G** (Goroutine), **M** (Machine/OS Thread), **P** (Processor/Logical CPU). The scheduler multiplexes many Gs onto fewer Ms via Ps, handling work stealing and context switching in user space for efficiency.

**G4 — Medium: Explain how channels work in Go. What is the difference between a buffered and unbuffered channel? What happens when you send to a full buffered channel?**
Channels are typed conduits for communication between goroutines. An **unbuffered channel** blocks the sender until a receiver is ready (synchronous). A **buffered channel** has a queue; sending blocks only when the buffer is full. Sending to a **full buffered channel** blocks the sender until space becomes available.

**G5 — Medium: What is the context package used for? Write a minimal example of using context.WithTimeout to cancel a long-running HTTP request.**
`context` manages cancellation signals, deadlines, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
client.Do(req) // Cancels if > 5s
```

**G6 — Medium: Explain Go's interface satisfaction model. How does it differ from Java/C# interfaces? What is the empty interface interface{} (or any) and why is it both powerful and dangerous?**
Go uses **implicit satisfaction** (duck typing); a type implements an interface by implementing its methods, no `implements` keyword. Java/C# require explicit declaration. `interface{}` (or `any`) accepts any type. It is **powerful** for generic-like behavior (pre-1.18) and flexibility, but **dangerous** because it bypasses compile-time type safety, requiring runtime type assertions which can panic.

**G7 — Hard: Explain Go's memory model regarding goroutine visibility. Why is the following unsafe, and what are the correct alternatives?**
```go
var ready bool
var data string
go func() { data = "hello"; ready = true }()
for !ready {}
fmt.Println(data)
```
This is unsafe due to **compiler/CPU reordering** and lack of synchronization guarantees. The main goroutine might see `ready = true` before `data = "hello"` is visible. **Fix:** Use `sync/atomic` for `ready`, `sync.Mutex`, or channels to establish a "happens-before" relationship.

**G8 — Hard: What is the difference between sync.Mutex and sync.RWMutex? When would you use sync.Map vs a regular map with a mutex? What are the performance trade-offs?**
`Mutex` allows exclusive access. `RWMutex` allows multiple readers or one writer. Use `sync.Map` for read-heavy workloads with disjoint keys (avoiding lock contention). **Trade-off:** `sync.Map` avoids locking overhead but uses more memory and is slower for writes or overlapping keys compared to `map + Mutex`.

**G9 — Hard: Explain how Go modules work. What is the difference between go.mod and go.sum? What does go mod tidy do, and what is the Minimum Version Selection (MVS) algorithm?**
Modules manage dependencies. `go.mod` declares requirements; `go.sum` stores cryptographic checksums for verification. `go mod tidy` adds missing requirements and removes unused ones. **MVS** selects the lowest version of a dependency that satisfies all version constraints in the dependency graph to ensure reproducibility.

**G10 — Medium: What is a defer statement? In what order do multiple defers execute? What is a common gotcha with defer in a loop?**
`defer` schedules a function call to run when the surrounding function returns. Multiple defers execute in **LIFO** (Last In, First Out) order. **Gotcha:** In a loop, defer captures the loop variable by reference, not value. If the variable changes, all defers see the final value. Fix: pass the variable as an argument to the deferred function.

**G11 — Easy: What is a pointer in Go? What is the zero value of a pointer? How do you create a pointer to a struct literal?**
A pointer holds a memory address. The zero value is `nil`. Create a pointer to a struct literal using the address-of operator: `&MyStruct{Field: value}`.

**G12 — Easy: Explain Go's init() function. When does it run? Can a package have multiple init() functions, and if so, in what order do they execute?**
`init()` initializes package-level variables. It runs automatically before `main()` and after imports are resolved. A package **can** have multiple `init()` functions; they execute in declaration order within the package. Order across packages is determined by import graph.

**G13 — Easy: What is the difference between make and new in Go? What types does each work with?**
`new(T)` allocates zeroed memory for type T and returns a pointer (`*T`). It works with any type. `make(T, ...)` initializes slices, maps, and channels and returns the value (not a pointer). It works **only** with slice, map, and channel types.

**G14 — Easy: How does error handling work in Go? What is the error interface, and what is the idiomatic pattern for checking errors? How do errors.Is and errors.As differ from ==?**
Errors are values implementing the `error` interface (`Error() string`). Idiomatic pattern: `if err != nil { ... }`. `errors.Is` checks if an error matches a target (handling wrapped errors). `errors.As` checks if an error is of a specific type (handling wrapped errors). `==` only checks exact equality, ignoring wrapping.

**G15 — Easy: What are Go's built-in composite types (map, slice, channel, struct)? What is the zero value of each?**
Map: `nil`. Slice: `nil` (len 0, cap 0). Channel: `nil`. Struct: Zero value of each field (e.g., 0, false, nil).

**G16 — Medium: What is a race condition in Go? How does the -race flag work? Give an example of a data race and show how to fix it with sync.Mutex or a channel.**
A race condition occurs when multiple goroutines access shared data concurrently, and at least one writes. `-race` uses dynamic analysis (shadow memory) to detect races at runtime.
**Fix (Mutex):** Wrap access in `mu.Lock()` / `mu.Unlock()`.
**Fix (Channel):** Send data through a channel to serialize access.

**G17 — Medium: Explain Go's select statement. How does it differ from a switch? What happens when multiple cases are ready? How do you implement a timeout with select?**
`select` waits on multiple channel operations. Like `switch`, but for channels. If multiple cases are ready, one is chosen **randomly**. **Timeout:** Use `case <-time.After(duration):` as one of the cases.

**G18 — Hard: What is escape analysis in Go? How does the compiler decide whether to allocate on the stack or the heap? How can you inspect escape analysis decisions, and why does it matter for performance?**
Escape analysis determines if a variable's lifetime exceeds the function scope. If it escapes (e.g., returned, stored in global, captured by closure), it goes to the **heap**. Inspect with `go build -gcflags="-m"`. Matters because heap allocation triggers GC pressure; stack allocation is faster and GC-free.

**G19 — Hard: Explain Go's reflection package (reflect). What is reflect.Type vs reflect.Value? What are the performance costs, and when is reflection justified vs code generation?**
`reflect.Type` describes type metadata; `reflect.Value` holds the data. Reflection is **slow** (runtime overhead, prevents inlining) and unsafe. Justified for generic libraries (pre-1.18), serialization, or CLI tools. **Code generation** (`go generate`) is preferred for performance-critical paths as it moves work to compile time.

**G20 — Hard: What is the go:embed directive? How does it work for single files, directories, and file systems? What are the limitations, and how does it interact with io/fs.FS?**
`//go:embed` embeds files into the binary at build time. Supports globs for files/directories. Returns `embed.FS` which implements `io/fs.FS`. **Limitations:** Files must exist at build time; cannot embed dynamic content; increases binary size.

## Rust (20 questions)

**R1 — Easy: What is ownership in Rust? Explain the three ownership rules.**
Ownership is Rust's memory management model without garbage collection. **Rules:** 1. Each value has one owner. 2. When the owner goes out of scope, the value is dropped. 3. A value can be moved or borrowed, but not copied (unless `Copy`).

**R2 — Easy: What is the difference between String and &str? When would you use each in function signatures?**
`String` is an owned, growable, heap-allocated string. `&str` is a borrowed string slice (view into UTF-8 data). Use `&str` for function inputs (flexible, accepts `&String` and `&str`). Use `String` for outputs or when ownership is required.

**R3 — Medium: Explain borrowing and the borrow checker. What are the rules for shared (&T) and mutable (&mut T) references?**
Borrowing allows referencing data without taking ownership. **Rules:** You can have either **one mutable reference** OR **any number of immutable references**, but not both simultaneously. The borrow checker enforces this at compile time to prevent data races.

**R4 — Medium: What is a Result<T, E> and an Option<T>? How does the ? operator work? Write a function that reads a file and returns its contents or an error.**
`Result` handles success/failure (`Ok(T)` / `Err(E)`). `Option` handles presence/absence (`Some(T)` / `None`). `?` propagates errors/None to the caller.
```rust
fn read_file(path: &str) -> Result<String, io::Error> {
    fs::read_to_string(path)
}
```

**R5 — Medium: Explain the difference between Box<T>, Rc<T>, and Arc<T>. When would you use each?**
`Box<T>`: Heap allocation, single owner (stack pointer). `Rc<T>`: Reference counted, single-threaded shared ownership. `Arc<T>`: Atomic reference counted, thread-safe shared ownership. Use `Box` for recursion/heap, `Rc` for graph structures (single thread), `Arc` for concurrency.

**R6 — Medium: What are traits in Rust? How do they compare to Go interfaces? What is a trait object (dyn Trait) vs a generic with a trait bound (T: Trait)?**
Traits define shared behavior (like interfaces). Go interfaces are implicit; Rust traits are explicit (`impl Trait for Type`). **Trait Object (`dyn Trait`)**: Dynamic dispatch (vtable), heap allocated, runtime polymorphism. **Generic (`T: Trait`)**: Static dispatch (monomorphization), compile-time polymorphism, usually faster.

**R7 — Hard: Explain lifetimes in Rust. Why does the following fail to compile, and how do you fix it?**
```rust
fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() { x } else { y }
}
```
It fails because the compiler doesn't know which input reference the output borrows from. **Fix:** Explicitly tie the output lifetime to the input lifetimes.
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { ... }
```

**R8 — Hard: What is Send and Sync in Rust? Why can't you send an Rc<T> across threads? What makes Arc<T> safe for concurrent use?**
`Send`: Type can be transferred across thread boundaries. `Sync`: Type can be referenced from multiple threads (`&T` is `Send`). `Rc<T>` is not `Send` because its reference count is not atomic. `Arc<T>` uses atomic operations for the count, making it thread-safe.

**R9 — Hard: Explain how Rust's async/await works under the hood. What is a Future? What is the role of the executor (e.g., Tokio)? How does this differ from Go's goroutines?**
`async fn` returns a `Future` (state machine). The `Future` is lazy; it does nothing until polled. An **executor** (like Tokio) polls futures to drive progress. **Difference:** Go goroutines are preemptive (OS/runtime managed); Rust async is cooperative (executor polls, must yield explicitly).

**R10 — Medium: What is unsafe in Rust? Give 3 things you can do in an unsafe block that you can't do in safe Rust. When is unsafe justified?**
`unsafe` bypasses borrow checker and type safety. **3 things:** 1. Dereference raw pointers. 2. Call unsafe functions. 3. Access mutable static variables. **Justified:** FFI (C bindings), low-level optimization, implementing unsafe traits safely.

**R11 — Easy: What is pattern matching in Rust? How does match differ from if let? What does the compiler enforce about exhaustiveness?**
Pattern matching deconstructs values. `match` must be **exhaustive** (cover all possibilities). `if let` handles a single pattern and ignores others. The compiler enforces exhaustiveness to prevent runtime errors from unhandled cases.

**R12 — Easy: What is the difference between Vec<T> and an array [T; N]? How does Vec manage memory when elements are pushed beyond its current capacity?**
Array: Fixed size, stack allocated. `Vec`: Dynamic size, heap allocated. When capacity is exceeded, `Vec` allocates a new, larger buffer (usually 2x), moves/copies elements, and frees the old buffer.

**R13 — Easy: What are enums in Rust, and how do they differ from enums in C or Java? What is the Option<T> enum, and why does Rust not have null?**
Rust enums are **sum types** that can hold data associated with each variant. C/Java enums are just integer constants. `Option<T>` is `Some(T)` or `None`. Rust has no null to prevent null pointer dereferences; `Option` forces explicit handling of absence.

**R14 — Easy: Explain the impl block. What is the difference between methods that take &self, &mut self, and self? What are associated functions (e.g., String::new())?**
`impl` defines methods for a type. `&self`: borrows instance immutably. `&mut self`: borrows mutably. `self`: consumes the instance. **Associated functions** (no `self`) are constructors or utilities (e.g., `String::new()`).

**R15 — Easy: What is the derive macro? Give examples of commonly derived traits (Debug, Clone, PartialEq, Serialize). When can you NOT derive a trait?**
`#[derive(...)]` auto-implements trait logic. Examples: `Debug`, `Clone`, `PartialEq`, `Serialize`. You **cannot** derive traits that require custom logic (e.g., `Drop`, `Display`) or if the type contains non-derivable fields.

**R16 — Medium: What is Cow<'a, T> (clone on write)? When is it useful? Give an example where it avoids unnecessary allocations compared to always cloning.**
`Cow` (Clone on Write) holds either a borrowed reference or an owned value. It avoids cloning if no mutation occurs. **Example:** A function taking `Cow<str>` can accept `&str` (no alloc) or `String` (owned). If you mutate, it clones; otherwise, it keeps the borrow.

**R17 — Medium: Explain Rust's module system. What is the difference between mod, use, and pub? How does the file system map to modules, and what changed between Rust 2015 and 2018 editions?**
`mod` declares a module. `use` imports paths. `pub` makes items public. **2015:** `mod.rs` required for directory modules. **2018:** `mod.rs` optional (e.g., `foo.rs` or `foo/mod.rs`). Path resolution is more intuitive (absolute paths start with crate name).

**R18 — Hard: What is the Pin<T> type and why is it needed? How does it relate to self-referential structs and async/await? What is Unpin?**
`Pin` ensures a value is not moved in memory. Needed for **self-referential structs** (pointers to self) and **async/await** (state machines holding references to their own stack frames). `Unpin` is a marker trait indicating a type is safe to move even if pinned.

**R19 — Hard: Explain Rust's macro system. What is the difference between declarative macros (macro_rules!) and procedural macros (derive, attribute, function-like)? What are hygiene rules?**
**Declarative (`macro_rules!`):** Pattern matching on syntax trees, simpler. **Procedural:** Compile-time code generation (functions returning tokens), more powerful (e.g., `serde`). **Hygiene:** Macros expand in a way that avoids variable name collisions with the caller's scope.

**R20 — Hard: What are zero-cost abstractions in Rust? Explain how iterators, generics (monomorphization), and trait static dispatch achieve performance comparable to hand-written C while providing high-level ergonomics.**
Zero-cost means no runtime overhead for abstractions. **Iterators:** Inlined and optimized away by LLVM. **Generics:** Monomorphization creates specialized code per type at compile time (no vtable lookup). **Traits:** Static dispatch resolves calls at compile time. Result: High-level code compiles to efficient machine code.
