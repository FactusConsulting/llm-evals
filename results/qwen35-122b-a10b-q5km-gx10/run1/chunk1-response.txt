## Networking (20 questions)

**N1 — Easy:** A Layer 2 switch forwards frames based on MAC addresses within a broadcast domain. A Layer 3 switch can perform routing (forwarding packets based on IP addresses) between VLANs or subnets, effectively combining switching and routing hardware.

**N2 — Easy:**
*   **Subnet Mask:** /20 = 255.255.240.0 (Block size 16 in the 3rd octet).
*   **Network Address:** 10.0.0.0 (5 falls in the 0-15 range).
*   **Broadcast Address:** 10.0.15.255.

**N3 — Medium:**
1.  **SYN:** Client sends SYN to Server.
2.  **SYN-ACK:** Server acknowledges and sends its own SYN.
3.  **ACK:** Client acknowledges Server's SYN.
*   **Lost ACK:** The Server will retransmit the SYN-ACK after a timeout. If the Client receives the retransmission, it sends the ACK again. The connection eventually establishes or times out.

**N4 — Medium:**
*   **SNAT (Source NAT):** Modifies the source IP of outgoing packets. *Example:* Internal hosts accessing the internet (masquerading).
*   **DNAT (Destination NAT):** Modifies the destination IP of incoming packets. *Example:* Port forwarding traffic from a public IP to an internal web server.

**N5 — Medium:**
1.  The certificate is issued for a different domain (e.g., `www.example.com` vs `example.com`).
2.  The client is connecting via an IP address instead of the hostname.
3.  A proxy or load balancer is terminating SSL with a mismatched certificate.

**N6 — Medium:**
*   **VLAN:** 802.1Q tagging, limited to 4094 IDs, requires L2 adjacency.
*   **VxLAN:** UDP encapsulation (L2 over L3), supports 16M VNIs, extends L2 domains over L3 networks.
*   **Choice:** Choose VxLAN for large-scale cloud environments, multi-tenant isolation beyond 4094, or spanning L2 across data centers.

**N7 — Hard:**
*   **Why:** Linux performs Reverse Path Filtering (rp_filter). If the return path (via default gw on eth0) doesn't match the incoming interface (eth1), the kernel may drop the packet or route asymmetrically.
*   **Fix:** Use Policy-Based Routing (PBR).
    ```bash
    ip rule add from 192.168.1.0/24 table 100
    ip route add default via 192.168.1.1 dev eth1 table 100
    ```

**N8 — Hard:**
BGP selects the best path based on attributes in this order:
1.  **Weight** (Cisco proprietary, local to router).
2.  **Local Preference** (Highest wins, within AS).
3.  **Locally Originated** (Network/Aggregate vs Learned).
4.  **AS Path** (Shortest wins).
5.  **Origin Code** (IGP < EGP < Incomplete).
6.  **MED** (Lowest wins, between ASes).

**N9 — Hard:**
*   **Overhead:** Outer Ethernet (14) + Outer IP (20) + UDP (8) + VxLAN (8) = 50 bytes. IPsec (ESP) adds ~20-40 bytes (depending on auth/encryption).
*   **Math:** 1500 (Physical MTU) - 50 (VxLAN/UDP/IP/Eth) - 40 (IPsec) = **1410 bytes** max inner payload.
*   **Implication:** Inner MTU must be reduced (e.g., to 1400) to prevent fragmentation.

**N10 — Medium:**
*   **ARP:** Resolves IPv4 addresses to MAC addresses on the local link.
*   **Gratuitous ARP:** An unsolicited ARP reply. It updates other hosts' ARP caches (e.g., after VM migration) and detects IP address conflicts.

**N11 — Easy:**
*   **Public:** Globally routable on the internet.
*   **Private:** Reserved for internal networks, not routable on the public internet.
*   **RFC 1918 Ranges:**
    1.  10.0.0.0 – 10.255.255.255 (10/8)
    2.  172.16.0.0 – 172.31.255.255 (172.16/12)
    3.  192.168.0.0 – 192.168.255.255 (192.168/16)

**N12 — Easy:**
*   **DNS:** Translates domain names to IP addresses.
*   **A Record:** Maps hostname to IPv4 address.
*   **CNAME:** Alias of one name to another (canonical name).
*   **AAAA:** Maps hostname to IPv6 address.

**N13 — Easy:**
*   **DHCP:** Protocol for automatically assigning IP configuration.
*   **DORA:**
    1.  **D**iscover (Client broadcasts).
    2.  **O**ffer (Server proposes IP).
    3.  **R**equest (Client accepts).
    4.  **A**cknowledge (Server confirms lease).

**N14 — Easy:**
*   **Hub:** Layer 1 (Physical). Broadcasts all traffic to all ports.
*   **Switch:** Layer 2 (Data Link). Forwards frames based on MAC table.
*   **Router:** Layer 3 (Network). Routes packets based on IP table.

**N15 — Easy:**
*   **Half-Duplex:** Communication in one direction at a time (shared medium).
*   **Full-Duplex:** Simultaneous two-way communication.
*   **Modern:** Modern Ethernet links operate in Full-Duplex mode.

**N16 — Medium:**
*   **TTL:** Time To Live; decremented by each router. Prevents infinite loops.
*   **Traceroute:** Sends packets with incrementing TTL (1, 2, 3...). When TTL hits 0, the router sends back an ICMP "Time Exceeded" message, revealing the hop.

**N17 — Medium:**
*   **NAT Gateway:** Translates private IPs to public IPs for internet access.
*   **Static NAT:** One-to-one fixed mapping.
*   **Dynamic NAT:** Maps private IPs to a pool of public IPs.
*   **PAT (NAPT):** Many-to-one mapping using unique source ports (most common for home/office).

**N18 — Hard:**
*   **ECMP:** Routes traffic across multiple equal-cost paths using a hash (usually 5-tuple: src/dst IP, src/dst port, protocol).
*   **Problem:** If a firewall is stateful, it expects return traffic to follow the same path. Asymmetric routing (forward via Path A, return via Path B) causes the firewall to drop the return packet as it lacks session state.

**N19 — Hard:**
*   **Problem:** The TCP Window (64KB) is smaller than the Bandwidth-Delay Product (10MB). The sender stops transmitting while waiting for ACKs, underutilizing the link.
*   **Solution:** TCP Window Scaling (RFC 1323) adds a shift factor to the window field, allowing windows larger than 64KB (up to 1GB), filling the pipe.

**N20 — Hard:**
*   **802.1Q:** Inserts a 4-byte VLAN tag into the Ethernet frame between Source MAC and EtherType.
*   **Linux Config:** Create sub-interfaces: `ip link add link eth0 name eth0.10 type vlan id 10`.
*   **Frame:** [Dest MAC][Src MAC][802.1Q Tag][EtherType][Payload][FCS].

## Linux (20 questions)

**L1 — Easy:**
*   **Hard Link:** Direct reference to the same inode (file data). Cannot span filesystems.
*   **Symbolic Link:** A pointer file containing a path to another file. Can span filesystems; breaks if target is moved.

**L2 — Easy:**
`find /var/log -type f -size +100M`

**L3 — Medium:**
*   **State D:** Uninterruptible sleep, usually waiting on I/O (disk/network).
*   **Kill:** No. `kill -9` sends SIGKILL, which cannot be caught by a process in kernel space (D state). The process must wait for I/O to complete.

**L4 — Medium:**
*   **cgroups v1:** Multiple hierarchies, controllers mounted separately.
*   **cgroups v2:** Unified hierarchy, single mount point, improved resource control.
*   **Systemd:** Prefers v2 for better integration and consistency.

**L5 — Medium:**
*   **Difference:** `nftables` is the modern framework (unified syntax, faster); `iptables` is legacy.
*   **Kernel:** Modern kernels use the `nftables` backend. `iptables` commands are translated to `nftables` rules internally.

**L6 — Medium:**
*   **Cause:** A file was deleted but is still open by a running process. The space is not freed until the process closes the file or exits.
*   **Check:** `lsof | grep deleted`.

**L7 — Hard:**
1.  **UEFI:** Initializes hardware, loads bootloader.
2.  **Bootloader (GRUB):** Loads kernel and initramfs into memory.
3.  **Kernel:** Initializes hardware, mounts root filesystem (via initramfs).
4.  **Initramfs:** Temporary root to load drivers/modules.
5.  **Root FS:** Switches to real root filesystem.
6.  **Systemd:** PID 1, manages services and targets.

**L8 — Hard:**
*   **Why:** "Available" includes reclaimable cache. OOM fires when memory pressure is critical and reclaiming cache isn't enough to satisfy allocations.
*   **Tunables:** `vm.swappiness` (prefers swap vs cache), `vm.vfs_cache_pressure` (reclaim inode/dentry cache), `vm.min_free_kbytes` (reserve buffer).

**L9 — Medium:**
*   **`ip netns`:** Creates/manages network namespaces (isolated network stacks).
*   **Containers:** Runtimes (Docker, Podman) use network namespaces to give each container a unique IP, routing table, and interfaces.

**L10 — Medium:**
*   **SIGTERM:** Graceful termination (catchable).
*   **SIGKILL:** Force kill (uncatchable).
*   **SIGQUIT:** Quit and dump core (catchable).

**L11 — Easy:**
*   **Stdout (1):** Standard output.
*   **Stderr (2):** Error output.
*   **Stdin (0):** Standard input.
*   **Redirect:** `command 2> error.log` (Stderr to file, Stdout to terminal).

**L12 — Easy:**
*   **755:** `rwxr-xr-x`.
*   **Owner (7):** Read (4) + Write (2) + Execute (1).
*   **Group (5):** Read (4) + Execute (1).
*   **Other (5):** Read (4) + Execute (1).

**L13 — Easy:**
*   **Root:** UID 0, unrestricted access to all system resources.
*   **Sudo:** Regular user granted specific elevated privileges via `/etc/sudoers`.

**L14 — Easy:**
*   **Package Manager:** Tool to install, update, and remove software.
*   **Debian/Ubuntu:** `apt` (frontend), `dpkg` (backend).
*   **RHEL/Fedora:** `dnf` (frontend), `rpm` (backend).

**L15 — Easy:**
*   **Purpose:** Defines filesystem mount points and options at boot.
*   **Misconfig:** System may drop to emergency mode or fail to boot if a critical filesystem (e.g., `/`) is missing or invalid.

**L16 — Medium:**
*   **LVM:** Abstraction layer for disk management.
*   **PV:** Physical Volume (disk/partition).
*   **VG:** Volume Group (pool of PVs).
*   **LV:** Logical Volume (virtual disk from VG).
*   **Extend:** `lvextend -L +10G /dev/vg/lv` followed by `resize2fs` (ext4) or `xfs_growfs` (xfs).

**L17 — Hard:**
*   **mq-deadline:** Optimizes for latency (deadline-based). Good for HDDs/SSDs.
*   **bfq:** Budget Fair Queueing. Optimizes for fairness/throughput. Good for multi-user desktops.
*   **none:** No scheduling (FIFO). Best for NVMe (hardware handles queueing).
*   **Change:** `echo mq-deadline > /sys/block/sdX/queue/scheduler`.

**L18 — Hard:**
*   **Load Avg:** Count of runnable processes + uninterruptible (D state) processes.
*   **I/O Wait:** Processes waiting on disk inflate load average without using CPU.
*   **Diagnose:** `top` (check Cpu(s) wa), `iostat -x 1` (check %util/await), `vmstat 1` (check bi/bo).

**L19 — Hard:**
*   **SELinux:** Mandatory Access Control (MAC) enforcing security policies.
*   **Modes:** Enforcing (blocks), Permissive (logs only), Disabled (off).
*   **Troubleshoot:** Check `audit.log` (`ausearch -m avc`), use `setsebool` to enable port, or `restorecon` to fix contexts.

**L20 — Hard:**
*   **Page Fault:** CPU requests memory not mapped.
*   **Minor:** Page exists in RAM (fast).
*   **Major:** Page must be loaded from disk (slow).
*   **THP:** Uses 2MB pages instead of 4KB. Can cause latency spikes due to memory compaction.
*   **Disable:** For latency-sensitive apps (databases) via `echo never > /sys/kernel/mm/transparent_hugepage/enabled`.
