DN1 — **Class vs Struct:** Classes are reference types (allocated on heap, passed by reference); structs are value types (allocated on stack or inline, passed by value). Use structs for small, immutable, value-like data (e.g., `Point`, `Complex`) to reduce GC pressure. Avoid structs for large data or mutable state to prevent copying overhead and unintended mutation.

DN2 — **IEnumerable vs IQueryable:** `IEnumerable<T>` executes queries in-memory (LINQ to Objects). `IQueryable<T>` builds an expression tree translated to a query language (e.g., SQL) by the provider (LINQ to Entities). Distinction matters because `IQueryable` filters data on the database server, reducing network traffic, whereas `IEnumerable` pulls all data to the client before filtering.

DN3 — **Async/Await & Task vs ValueTask:** `async/await` compiles to a state machine that suspends execution without blocking threads. `Task` is a heap-allocated object representing an operation. `ValueTask` is a struct that avoids allocation if the operation completes synchronously. Use `ValueTask` in high-frequency hot paths (e.g., caching layers) to reduce GC pressure, but prefer `Task` for public APIs to avoid complexity (e.g., multiple awaits).

DN4 — **Dependency Injection Lifetimes:** Transient (new instance per request), Scoped (one instance per HTTP request), Singleton (one instance per app lifetime). **Bug:** Injecting a Scoped service (e.g., `DbContext`) into a Singleton service creates a "Captive Dependency." The Scoped service is disposed after the first request, causing errors in subsequent requests. Fix: Inject `IServiceScopeFactory` into Singleton to create scopes manually.

DN5 — **string vs ReadOnlySpan<char>:** `string` is immutable, heap-allocated, and null-terminated. `ReadOnlySpan<char>` is a stack-only view over contiguous memory (array, string, stack). Use `Span<T>` for high-performance parsing, slicing, or string manipulation to avoid allocations and copies. Cannot be stored in fields or returned from async methods.

DN6 — **GC & IDisposable:** GC manages memory via generations: Gen 0 (short-lived), Gen 1 (medium), Gen 2 (long-lived). Large Object Heap (LOH) stores objects >85KB, collected less frequently. `IDisposable` is needed for unmanaged resources (file handles, DB connections) because the GC does not know when to release them deterministically. Use `using` statements for cleanup.

DN7 — **ConfigureAwait:** Default `await` captures the `SynchronizationContext` (ensuring continuation runs on the original thread, e.g., UI). `ConfigureAwait(false)` releases the context, allowing continuation on any thread pool thread. Use `false` in libraries to improve performance and avoid deadlocks. Do **not** use `false` in UI apps or ASP.NET Core middleware where context-specific logic (e.g., `HttpContext`) is required (though ASP.NET Core lacks a SynchronizationContext by default).

DN8 — **.NET 8/9 Features:**
*   **Primary Constructors:** Parameters on class definition available in methods.
*   **Collection Expressions:** `[1, 2, 3]` syntax for arrays/lists.
*   **FrozenDictionary:** Immutable dictionary optimized for read-heavy scenarios.
*   **Example:**
    ```csharp
    public class UserService(string connString) : IUserService {
        public void Connect() => Console.WriteLine(connString);
    }
    // DI Registration
    builder.Services.AddScoped<IUserService, UserService>();
    ```

DN9 — **ObjectDisposedException Diagnosis:** Likely cause: `DbContext` (Scoped) injected into a Singleton service, or `DbContext` used after the request scope ends. Under high concurrency, the Singleton holds a reference to a disposed Scoped instance. **Fix:** Ensure `DbContext` is registered as Scoped. If a Singleton needs DB access, inject `IServiceScopeFactory` to create a new scope per operation.

DN10 — **Record vs Class:** `record` provides value-based equality (structural) and immutability features (`with` expressions). `class` provides reference equality. `record struct` combines value semantics with struct performance. Choose `record` for DTOs, domain models requiring immutability, or data carriers. Choose `class` for mutable entities or when reference identity matters.

DN11 — **ref, out, in:** `ref` passes a reference to an existing variable (must be initialized). `out` passes a reference for output (must be assigned inside method). `in` passes a read-only reference (avoids copy for large structs). Use `in` for large structs passed to methods where mutation isn't needed.

DN12 — **Nullable Reference Types:** `?` on reference types (e.g., `string?`) enables compiler warnings for potential nulls (static analysis). `int?` is `Nullable<int>`, a value type wrapper allowing nulls for value types. NRT does not enforce null checks at runtime; it guides developer behavior and tooling.

DN13 — **LINQ:** Language Integrated Query. **Method Syntax:** `list.Where(x => x > 5)` (fluent, lambda). **Query Syntax:** `from x in list where x > 5 select x` (SQL-like). **Deferred Execution:** Query definition does not execute until enumerated (e.g., `foreach`, `ToList`). Changes to source data affect query results upon execution.

DN14 — **Generic Constraints:** Limit types for `T`. `class` (reference), `struct` (value), `new()` (public parameterless constructor), `IComparable<T>` (interface). Combine constraints to enforce multiple requirements, e.g., `where T : class, IDisposable` ensures `T` is a reference type that can be disposed.

DN15 — **Abstract Class vs Interface:** Abstract class can have state (fields) and partial implementation. Interface defines a contract (methods/properties) without state (prior to C# 8). **Default Interface Methods (C# 8+):** Allow interfaces to provide implementation, enabling versioning without breaking existing implementers, blurring the line slightly but interfaces still cannot hold instance state.

DN16 — **Middleware Pipeline:** Middleware components form a request pipeline. `app.Use()` adds middleware that can call `next()` to pass control. `app.Map()` branches the pipeline based on path. `app.Run()` is terminal (no `next`). **Order:** Matters critically (e.g., Auth before Controller). **Exception Handling:** Wraps the pipeline to catch and handle errors globally.

DN17 — **Channel<T>:** Async producer-consumer queue. `BlockingCollection<T>` is blocking/synchronous. `Channel<T>` supports async `ReadAsync`/`WriteAsync`. **Bounded Channel:** Limits capacity; `WriteAsync` awaits if full, providing backpressure. Example: `Channel.CreateBounded<int>(100)`.

DN18 — **Source Generators:** Compile-time code generation (C# 9+). Differs from reflection (runtime overhead) and IL weaving (post-build). **Incremental Generators:** Only re-run when inputs change, significantly improving build performance compared to `ISourceGenerator` (full re-run). Preferred for performance-critical code gen (e.g., JSON serialization, DI).

DN19 — **TPL Dataflow:** Library for dataflow pipelines (`ActionBlock`, `TransformBlock`, `BufferBlock`). Handles buffering, propagation, and linking blocks. Compared to `Channels`: Dataflow is higher-level with built-in backpressure and options; Channels are lower-level, more flexible for custom backpressure logic and memory management.

DN20 — **Minimal APIs:** `app.MapGet` style endpoints without Controllers. **Trade-offs:** Less boilerplate, faster startup. **Testability:** Harder to mock dependencies compared to Controller injection (requires `WebApplicationFactory`). **OpenAPI:** Requires Swashbuckle configuration. **Route Groups:** `MapGroup("/api")` prefixes routes. **Endpoint Filters:** Middleware-like logic specific to endpoints.

P1 — **List vs Tuple, Set vs FrozenSet:** `list` is mutable, ordered. `tuple` is immutable, ordered. `set` is mutable, unordered, unique elements. `frozenset` is immutable version of set (hashable, usable as dict key).

P2 — **GIL:** Global Interpreter Lock prevents multiple threads from executing Python bytecode simultaneously. Affects CPU-bound multithreading (no parallelism). Workarounds: `multiprocessing` (separate processes), C-extensions (release GIL), `asyncio` (I/O concurrency).

P3 — **Deep vs Shallow Copy:** `copy()` creates a new object but references nested objects (shallow). `deepcopy()` recursively copies nested objects. **Example:** `a = [[1]]; b = copy(a); b[0].append(2)` modifies `a` in shallow copy. Deep copy prevents this.

P4 — **Decorators:** Functions that wrap other functions to modify behavior. **Example:**
```python
import time, functools
def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        res = func(*args, **kwargs)
        print(f"{func.__name__}: {time.time()-start}")
        return res
    return wrapper
```

P5 — **Generators:** Functions using `yield` return an iterator, producing items lazily. Differs from returning a list (memory efficient, one-time use). `yield from` delegates to a sub-generator, flattening iteration.

P6 — **Asyncio:** Event loop manages async tasks. `asyncio.run()` starts the loop. `gather()` waits for multiple tasks concurrently. `create_task()` schedules a task. `time.sleep()` blocks the loop; use `await asyncio.sleep()` to yield control.

P7 — **MRO:** Method Resolution Order uses C3 Linearization. `D(B, C)` MRO: `D -> B -> C -> A`. `D().who()` searches D (no), B (no), C (yes, returns "C"). C overrides A, and C appears before A in MRO.

P8 — **Metaclass:** Class of a class (controls class creation). `__init_subclass__` is a hook called when a class is subclassed (simpler, no metaclass needed). **Use Case:** Metaclass for enforcing complex class invariants (e.g., ORM models). `__init_subclass__` for registering subclasses automatically.

P9 — **Multiprocessing vs Threading:** `threading` shares memory but limited by GIL (good for I/O). `multiprocessing` uses separate processes (bypasses GIL, good for CPU). `concurrent.futures` provides a high-level interface for both. **Serialization:** `multiprocessing` requires arguments to be picklable.

P10 — **__slots__:** Declares fixed attributes, preventing `__dict__` creation. **Impact:** Reduces memory usage per instance, speeds up attribute access. **Prevents:** Dynamic addition of new attributes at runtime.

P11 — **Virtual Environment:** Isolated Python environment for dependencies. **venv:** Standard library tool. **virtualenv:** Third-party, faster, more features. **conda:** Package manager + env manager (common in data science, handles non-Python libs).

P12 — **Comprehensions:** Concise syntax for creating lists/dicts/sets (`[x for x in list]`). Faster than loops. Prefer over `map()`/`filter()` for readability in modern Python.

P13 — **== vs is:** `==` compares values. `is` compares object identity (memory address). **Interning:** Python caches small integers (-5 to 256) and some strings, so `a is b` may be True for identical small values.

P14 — **args/kwargs:** `*args` collects positional args as tuple. `**kwargs` collects keyword args as dict. `/` marks positional-only parameters. `*` marks keyword-only parameters (must be passed by name).

P15 — **Context Managers:** Manage resources (`with` statement). `__enter__`/`__exit__` defines class behavior. `@contextmanager` decorator turns a generator into a context manager. **Example:** Database transaction commit/rollback.

P16 — **Type Hinting:** Static type annotations (`def f(x: int) -> str:`). `Union`/`Optional` (nullable), `Literal` (specific values), `TypeVar` (generics), `Protocol` (structural subtyping). `mypy`/`pyright` check types without execution.

P17 — **Data Model:** Dunder methods customize behavior. `__repr__` (debug), `__str__` (user). `__eq__` defines equality; defining `__eq__` sets `__hash__` to None (unhashable) unless explicitly defined. `__getattr__` (missing attr), `__getattribute__` (all attr access).

P18 — **Descriptors:** Objects defining `__get__`, `__set__`, `__delete__`. Control attribute access. `property` is a descriptor for managed attributes. `classmethod`/`staticmethod` are descriptors that bind methods to class or unbound.

P19 — **Import System:** `sys.path` lists search locations. Relative (`.`) vs Absolute imports. `__init__.py` marks packages (or namespace packages if missing). **Finder:** Locates modules. **Loader:** Loads code into memory. Namespace packages allow splitting one package across multiple directories.

P20 — **Dataclasses:** Auto-generate `__init__`, `__repr__`, etc. `__post_init__` for logic after init. `frozen=True` makes immutable. **Pydantic:** Adds validation, serialization, and type coercion. Choose Pydantic for API models requiring strict validation; Dataclasses for internal data structures.
