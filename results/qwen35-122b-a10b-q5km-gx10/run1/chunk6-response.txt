## JavaScript / TypeScript

**JS1**
`var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but reside in the Temporal Dead Zone (TDZ) until declaration. Hoisting moves declarations to the top of their scope during compilation. `const` requires initialization at declaration.

**JS2**
The event loop manages async execution. The **Call Stack** executes synchronous code. **Microtasks** (Promises, `queueMicrotask`) run immediately after the stack clears, before the next render. **Macrotasks** (`setTimeout`, I/O) run after microtasks. Order: Stack → Microtasks → Render → Macrotasks.

**JS3**
A closure is a function bundled with its lexical environment. Example: `function makeCounter() { let n=0; return () => n++; }`. **Bug:** In `for (var i=0; i<3; i++) { setTimeout(() => console.log(i)) }`, all logs print `3` because `var` is function-scoped. **Fix:** Use `let` (block scope) or an IIFE to capture the value.

**JS4**
`Promise` represents eventual completion. `async/await` is syntactic sugar over Promises. Errors: `.catch()` on Promises, `try/catch` with `await`. `Promise.all` fails fast if any promise rejects. `Promise.allSettled` waits for all to settle (fulfill or reject) and returns status for each.

**JS5**
`interface` is extensible (declaration merging) and structural. `type` supports unions, primitives, and mapped types. Use `interface` for public API shapes, `type` for complex compositions. **Discriminated unions:** Objects with a literal tag field (e.g., `{ type: 'a' } | { type: 'b' }`) used with `switch` for type narrowing.

**JS6**
Prototypal inheritance delegates property lookup to a prototype chain. `Object.create(proto)` creates an object with `proto` as its `[[Prototype]]`. ES6 `class` is syntax sugar; `extends` sets up the prototype chain, and `super` calls the parent constructor.

**JS7**
`this` refers to the execution context. Binding rules (priority): 1. `new` (new binding), 2. `call/apply/bind` (explicit), 3. Object context (implicit), 4. Default (window/undefined). `bind()` returns a new function with bound `this`; it cannot be re-bound.

**JS8**
`WeakRef` holds a weak reference to an object (allows GC). `FinalizationRegistry` runs a callback when an object is GC'd. `WeakMap` keys must be objects because primitives cannot be weakly referenced (they are value-based, not identity-based), enabling garbage collection of keys.

**JS9**
V8 uses **Hidden Classes** (shapes) for property access optimization. **Inline Caching** caches lookup locations. **Deoptimization** occurs when assumptions break (e.g., adding properties dynamically, using `eval`, or mixing types). Patterns causing deopt: dynamic property names, `arguments` object usage.

**JS10**
Tree-shaking removes unused code. It works with **ES Modules** because imports/exports are static (analyzable at build time). **CommonJS** uses dynamic `require()`, making static analysis impossible, so it cannot be effectively tree-shaken.

**JS11**
`null` is an assignment value (empty object pointer); `undefined` means uninitialized. `null == undefined` is `true`; `null === undefined` is `false`. `??` returns RHS if LHS is `null`/`undefined`. `?.` safely accesses nested properties without throwing if intermediate is nullish.

**JS12**
`map` transforms elements; `filter` selects elements; `reduce` accumulates to a single value. `reduce` initial value prevents `undefined` as the first accumulator. `flatMap` maps then flattens one level; useful for transforming arrays into a single flat array.

**JS13**
Template literals use backticks (`` ` ``), support interpolation (`${}`), and multiline strings. **Tagged templates** pass the template string parts and substitutions to a function. Example: `sql`SELECT * FROM users WHERE id = ${id}`` sanitizes inputs to prevent SQL injection.

**JS14**
Destructuring unpacks values. Object: `const {a, b} = obj`. Array: `const [x, y] = arr`. Defaults: `const {a = 1} = {}`. Renaming: `const {a: alias} = obj`. Rest: `const {a, ...rest} = obj` collects remaining properties.

**JS15**
`for...in` iterates over enumerable property **keys** (including prototype chain). `for...of` iterates over iterable **values**. Avoid `for...in` on arrays because it iterates indices as strings, includes inherited properties, and order is not guaranteed.

**JS16**
Generics allow reusable type parameters. Constraints: `T extends Base`. Conditional: `T extends U ? X : Y`. `infer` extracts types within conditionals. Example: `type Unwrap<T> = T extends Promise<infer U> ? U : T`.

**JS17**
**CommonJS:** `require`/`module.exports` (dynamic, Node default). **ES Modules:** `import`/`export` (static, browser/Node). Node handles both via `.mjs` extension or `"type": "module"` in `package.json`. CJS is synchronous; ESM is asynchronous.

**JS18**
Structural typing checks shape, not name. **Excess property checks** apply to object literals assigned to types (catches typos). `extends` checks assignability; `satisfies` checks compatibility without widening the type. Variance (TS 4.7+): `in` (contravariant), `out` (covariant) on generic parameters.

**JS19**
`Proxy` intercepts operations (get, set, apply). `Reflect` provides default behavior for those operations. Example: `new Proxy(obj, { get(target, key) { console.log(key); return target[key]; } })`. Used for validation, logging, or reactivity.

**JS20**
`SharedArrayBuffer` allows shared memory between Web Workers. `Atomics` provides atomic read/write/lock operations. `Atomics.wait` blocks a worker until notified; `Atomics.notify` wakes waiters. Guarantees sequential consistency for atomic ops. Requires Cross-Origin Isolation headers.

## Bash

**B1**
`$@` expands to separate arguments; `$*` expands to one string. `"$@"` preserves argument boundaries (safe for spaces); `"$*"` joins them with the first character of IFS (usually space).

**B2**
`set -e`: Exit on error. `-u`: Error on unset variables. `-o pipefail`: Pipeline fails if any command fails (not just the last). Ensures script robustness.

**B3**
`$(command)` is preferred (nestable, readable); `` `command` `` is legacy. `$((expression))` is arithmetic expansion (fast, built-in); `expr` is an external command (slower, legacy).

**B4**
Process substitution `<(command)` creates a named pipe/file descriptor. Example: `diff <(ls dir1) <(ls dir2)`. Useful when commands expect filenames but you want to pass output streams.

**B5**
Use `for f in *` or `while IFS= read -r -d '' f; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous because word splitting breaks filenames with spaces or newlines.

**B6**
`<<EOF` (here document) reads multiple lines until EOF. `<<<` (here string) passes a single string. `<<-EOF` strips leading tabs from the heredoc content.

**B7**
`cmd > file 2>&1`: Stdout to file, then stderr to stdout (file). `cmd 2>&1 > file`: Stderr to stdout (terminal), then stdout to file (stderr goes to terminal). `&> file`: Redirects both to file. Order matters for FD redirection.

**B8**
Use `mkdir lockdir` (atomic). `trap 'rmdir lockdir' EXIT`. Handle SIGTERM via `trap cleanup TERM`. `mkdir` is preferred because it is atomic; file creation (`touch`) has race conditions.

**B9**
`'...'` literal (no expansion). `"..."` expands variables/commands. No quotes triggers globbing/word splitting. Example: `echo $HOME` (path), `echo '$HOME'` (literal), `echo *` (files).

**B10**
`-f` (file), `-d` (directory), `-r` (readable). `[[ ]]` is Bash-specific (supports `&&`, `||`, pattern matching); `[ ]` is POSIX `test`.

**B11**
`$?` (last exit code), `$$` (current PID), `$!` (last background PID), `$#` (arg count). Use `$?` for error checks, `$$` for temp filenames, `$!` for monitoring bg jobs.

**B12**
`function foo {}` or `foo() {}`. `foo() {}` is POSIX compatible. Return values via `exit code` (0-255) or `echo` (captured via `$()`).

**B13**
`PATH` is a colon-separated list of directories. Bash searches them in order. Builtin commands are internal; external are files. Use `type cmd` to check.

**B14**
`trap 'cmd' SIGNAL`. `EXIT` runs on exit (success/fail). `ERR` runs on command failure. `INT`/`TERM` handle interrupts. Order: Signal handler runs, then `EXIT` trap.

**B15**
`xargs` builds command lines from stdin; `$(cmd)` substitutes output. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P` runs jobs in parallel.

**B16**
Indexed: `arr=(a b)`, `arr+=("c")`, `${#arr[@]}`. Associative: `declare -A arr`, `arr[key]=val`. Iterate: `for k in "${!arr[@]}"`.

**B17**
`(...)` creates a subshell (variables lost outside). `{ ...; }` groups commands in current shell. Piping into `while` creates a subshell, losing variable updates. Use process substitution `while ... done < <(cmd)`.

**B18**
`SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (hangup), `SIGKILL` (force). Use `trap` to catch TERM/INT, cleanup, then exit. Background jobs need `wait` or `kill` handling.

**B19**
Script: `split -l 1000 log.txt part.`, `xargs -P 4 -I {} process {}`, `cat part.* > result`. Trade-off: Parallelism vs IO overhead. Error propagation: Check `set -o pipefail` or capture exit codes from `xargs`.

**B20**
`exec` replaces the current shell process. `exec 3>file` opens FD 3. `exec 3>&-` closes it. Coprocess: `coproc cmd { cmd; }` allows bidirectional communication (stdin/stdout) with a background process.

## PowerShell

**PS1**
`Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console (bypasses pipeline). `Write-Host` breaks piping and testing.

**PS2**
Pipeline streams objects. `ForEach-Object` is a cmdlet (processes pipeline input). `foreach` is a language statement (iterates a collection). Use `ForEach-Object` for streaming; `foreach` for in-memory arrays.

**PS3**
`[PSCustomObject]` creates a typed object with properties. `[hashtable]` is a key-value dictionary. Convert: `[PSCustomObject]$ht`. Use hashtable for config, PSCustomObject for output.

**PS4**
Terminating errors stop execution (caught by `try/catch`). Non-terminating continue (caught by `-ErrorAction`). `$ErrorActionPreference` sets default behavior. `try/catch` only catches terminating errors.

**PS5**
Splatting `@params` passes a hashtable's keys/values as named parameters. `cmd @params`. Differs from passing `$params` (which is a single object argument).

**PS6**
`Invoke-Command` runs commands remotely (one-off). `Enter-PSSession` opens an interactive session. Uses WinRM (default) or SSH. Requires remoting enabled.

**PS7**
Pipeline unwrapping: If a function outputs multiple items, the variable becomes an array. If 0 items, it is `$null`. Correct pattern: `return ,@($result)` or ensure array output explicitly.

**PS8**
`[scriptblock]` is code without a name; functions are named scriptblocks. Pass scriptblocks via `-ScriptBlock`. **Double-hop:** Credentials don't delegate. Solve with CredSSP or Kerberos constrained delegation.

**PS9**
`@()` forces array context. `[array]` is a type cast. Force array: `@($var)`. Indexing `$null` returns `$null`; indexing empty array returns `$null`.

**PS10**
`-eq` (equals), `-like` (wildcard), `-match` (regex). Case-sensitive: `-ceq`, `-clike`. `-contains` checks if collection has item; `-in` checks if item is in collection (reverse).

**PS11**
Module: Reusable code. `.psm1` (script), `.psd1` (manifest), Binary (DLL). `Import-Module` loads them. Manifest defines exports/dependencies.

**PS12**
Interpolation: `"Var: $var"`. Single quotes `'...'` are literal. Expressions: `"Result: $($a+$b)"`. Here-string: `@" ... "@` for multiline strings.

**PS13**
`Get-Member` (`gm`) inspects object members. Properties (data), Methods (actions), NoteProperties (dynamic). `Select-Object` projects properties; `Where-Object` filters objects.

**PS14**
Classes (v5+) define types with methods/properties. Limited inheritance (no interfaces). Use for data models or complex logic encapsulation. Functions are preferred for simple cmdlets.

**PS15**
`[CmdletBinding()]` makes a function an advanced function (supports `-Verbose`, `-ErrorAction`). `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` blocks handle pipeline streaming.

**PS16**
Providers expose data stores as drives. `Get-ChildItem` works on `C:`, `HKLM:`, `Cert:`. Access registry: `cd HKLM:\Software`.

**PS17**
Runspaces allow parallel execution. `[runspacepool]` manages threads. `ForEach-Object -Parallel` (PS7+) simplifies this. Manual runspace needed for complex state sharing.

**PS18**
PSScriptAnalyzer lints code. Rules check standards (severity: Error/Warning/Info). Custom rules via modules. Integrate in CI via `Invoke-ScriptAnalyzer`.

**PS19**
`$using:` captures local variables for remote sessions. `-ArgumentList` passes arguments. Serialization (CLIXML) has depth limits (default 10), truncating complex nested objects.

**PS20**
DSC configures systems declaratively. Resources define state; LCM applies config. Legacy in modern infra. Replaced by Terraform, Ansible, Bicep, or ARM templates for cloud.
