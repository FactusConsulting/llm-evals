## .NET / C#

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
A class is a reference type, meaning it is allocated on the heap, and variables hold a reference to the object. A struct is a value type, meaning it is allocated on the stack (or inline within other types), and variables hold the actual data. You should use a struct when the type is small (typically less than 16 bytes), immutable, and represents a simple data structure (e.g., a point, a color, or a coordinate).

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
`IEnumerable<T>` represents a sequence that can be iterated over in memory. When used with a database context, it typically forces the entire query to be materialized (loaded) into memory on the client side. `IQueryable<T>`, however, represents an expression tree. This allows the query to be translated into a database-specific query (like SQL) and executed on the server side, which is vastly more efficient for large datasets.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
`async/await` is syntactic sugar built on top of the `Task` type. When an `await` keyword is encountered, the method execution is suspended, control is returned to the caller, and the runtime schedules a continuation to resume execution once the awaited operation completes. A `Task` represents an asynchronous operation that might involve heap allocation. A `ValueTask<T>` is a struct that can represent the result synchronously or asynchronously, avoiding heap allocation when the result is available immediately. Use `ValueTask<T>` when the operation is likely to complete synchronously often, as it reduces GC pressure.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
Dependency Injection (DI) is a design pattern where components receive their dependencies from an external source (the DI container) rather than creating them internally.
*   **Transient:** A new instance is created every time it is requested.
*   **Scoped:** A single instance is created once per scope (e.g., per HTTP request in ASP.NET Core).
*   **Singleton:** A single instance is created once for the entire application lifetime.
The common bug is injecting a Scoped service (like `DbContext`) into a Singleton service. Since the Singleton lives for the entire application lifetime, it holds onto the Scoped instance, causing that instance to be used across multiple unrelated HTTP requests, leading to concurrency issues and data corruption.

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
`string` is an immutable reference type in .NET, meaning any modification creates a new string object. `ReadOnlySpan<char>` is a lightweight, stack-allocated structure that provides a safe, high-performance view over an existing contiguous block of memory (like a string or a character array) without copying the underlying data. You use `Span<T>` when you need to perform high-performance, low-allocation string or buffer manipulation (e.g., parsing, searching, or slicing) without creating intermediate string objects.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
The GC is a generational collector that groups objects into generations based on how long they have survived. Gen 0 holds newly allocated, short-lived objects. Gen 1 is a buffer between Gen 0 and Gen 2. Gen 2 holds long-lived objects. The Large Object Heap (LOH) is where objects larger than a threshold (typically 85KB) are placed. The GC is not aware of the internal state of unmanaged resources. `IDisposable` is an interface used to implement deterministic cleanup (e.g., closing file handles, releasing network sockets) for unmanaged resources. You need it because the GC only manages *managed* memory; it cannot automatically clean up external, unmanaged resources.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
By default, when an `await` completes, the runtime attempts to resume the continuation on the original `SynchronizationContext` (e.g., the UI thread or the ASP.NET request thread). `ConfigureAwait(false)` tells the runtime that the continuation does *not* need to resume on the original context. You should use it in library code (especially in asynchronous methods that are consumed by other libraries) to prevent deadlocks and improve performance by avoiding the overhead of context switching. You should *not* use it when you specifically need to interact with UI elements or context-specific state.

**DN8 — Hard: Explain the new .NET 8/9 features: primary constructors, collection expressions, and FrozenDictionary. Write a minimal example using primary constructors with DI.**
*   **Primary Constructors:** Allow parameters to be defined directly in the class signature, which can then be used as properties or injected dependencies.
*   **Collection Expressions:** Provide a concise syntax (`[]`) for creating collections, simplifying initialization.
*   **FrozenDictionary:** A dictionary that is immutable after creation, offering thread-safe, high-performance lookups without the overhead of locking.

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
**Diagnosis:** The likely cause is that the `DbContext` is being registered as a Singleton or Scoped service, but the application logic is somehow reusing the same instance across multiple concurrent requests. When a request finishes, the context might be disposed, but subsequent concurrent requests attempt to use the disposed instance, leading to `ObjectDisposedException`.
**Fix:** Ensure the `DbContext` is registered with the **Scoped** lifetime. This guarantees that a fresh, isolated instance of the `DbContext` is provided for the duration of a single HTTP request.
**Interaction:** EF Core's `DbContext` is designed to be request-scoped. When registered correctly in ASP.NET Core using `AddDbContext<T>(...)`, the DI container ensures that a new, isolated instance is created for each incoming request scope, preventing concurrent access issues.

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
*   **Class:** A mutable, reference type. Used when identity (memory address) matters, and state changes are expected.
*   **Record:** A reference type designed for immutability and value equality. It automatically provides `Equals()` and `GetHashCode()` based on the property values. Use it when the object represents data (a Data Transfer Object or DTO) and should be treated as immutable.
*   **Record Struct:** A value type that combines the immutability and value equality of a record with the stack allocation benefits of a struct. Use it for small, immutable data structures where performance and value semantics are critical.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
*   **`ref`:** Requires the variable to be initialized before the method call. It allows the method to read and modify the original variable. Used when you need to pass an existing variable by reference.
*   **`out`:** Does not require the variable to be initialized before the method call. The method is responsible for assigning a value to the variable. Used when the method needs to return multiple values via parameters.
*   **`in`:** (C# 7.2+) Allows passing a reference to a variable without allowing the method to modify it. Used for performance optimization when passing large structs, ensuring the method reads the data efficiently without copying it, but guarantees the original data remains unchanged.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
Nullable Reference Types (NRTs) are a compile-time safety feature. The `?` annotation on a reference type (e.g., `string?`) tells the compiler that the variable might hold `null`. This is a *warning* system, not a runtime one. Nullable value types (e.g., `int?`) are actual types that wrap the value type and explicitly allow `null` at runtime. The difference is that NRTs enforce null checks at compile time, while `int?` is a concrete type that must be handled at runtime.

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
LINQ (Language Integrated Query) is a set of features that allows developers to write queries against various data sources (collections, databases, XML) using a unified syntax.
*   **Method Syntax:** Uses extension methods (e.g., `list.Where(x => x > 5)`).
*   **Query Syntax:** Uses SQL-like syntax (e.g., `from x in list where x > 5`).
**Deferred Execution:** When using LINQ, the query is not executed immediately. Instead, it returns an `IEnumerable<T>` (or `IQueryable<T>`) that represents the query plan. The query is only executed when the results are iterated over (e.g., in a `foreach` loop or when calling `.ToList()`).

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
Generic constraints restrict the types that can be used as type arguments for a generic type.
*   `where T : class`: T must be a reference type.
*   `where T : struct`: T must be a value type.
*   `where T : new()`: T must have a parameterless constructor.
*   `where T : IComparable<T>`: T must implement the `IComparable<T>` interface, allowing comparison logic.
You combine constraints when a generic type needs to satisfy multiple requirements simultaneously. For example, if you need a generic list that must contain only reference types *and* must be able to be compared, you would use `where T : class, IComparable<T>`.

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
*   **Abstract Class:** Provides a base implementation and can contain concrete methods and fields. It defines an "is-a" relationship (inheritance). A class can only inherit from one abstract class.
*   **Interface:** Defines a contract (a set of methods/properties) without implementation. It defines a "can-do" relationship. A class can implement multiple interfaces.
*   **Change (C# 8+):** Default interface methods allow interfaces to provide a default implementation for methods. This allows interfaces to evolve without breaking existing implementing classes, blurring the line slightly, but the fundamental difference remains: abstract classes provide state and implementation, while interfaces define contracts.

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
The middleware pipeline is a series of components that process HTTP requests sequentially. Each middleware component has the ability to inspect, modify, or terminate the request/response.
*   **`app.Use()`:** Adds standard middleware (e.g., routing, authentication, authorization). It processes the request and typically calls `next()` to pass control to the next component.
*   **`app.Map()`:** Maps a specific path to a handler (endpoint). It terminates the pipeline for that specific route.
*   **`app.Run()`:** Terminates the pipeline and serves the request directly (often used for simple static file serving).
**Ordering:** Ordering is critical. For example, authentication middleware must run *before* authorization middleware, and routing must run *before* endpoint-specific middleware.
**Exception Handling:** Exception handling middleware (e.g., `app.UseExceptionHandler()`) must be placed early in the pipeline. If an exception occurs in a later middleware, the exception handler catches it, logs it, and returns a standardized error response before the request reaches the application logic.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
`Channel<T>` is a modern, asynchronous mechanism for communication between asynchronous producers and consumers. It is designed to work seamlessly with `async/await`. `BlockingCollection<T>` is a synchronous collection designed for thread-safe producer-consumer scenarios, often used with `BlockingCollection.GetConsumingEnumerable()`.
**Comparison:** Channels are inherently asynchronous and non-blocking, making them ideal for modern I/O-bound applications. `BlockingCollection` is synchronous and relies on thread blocking.
**Backpressure Example:** By creating a bounded channel (e.g., `Channel.CreateBounded<int>(capacity: 10)`), if the producer tries to write more items than the capacity, the `WriteAsync()` call will asynchronously block until the consumer reads an item, thus applying backpressure and preventing memory overflow.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
**Source Generators:** Code generators that run during compilation, generating new C# source code files that are then compiled alongside the original code.
*   **Difference from Reflection:** Reflection inspects types and members at *runtime*. Source Generators generate code at *compile time*, eliminating runtime overhead and enabling compile-time checks.
*   **Difference from IL Weaving:** IL Weaving modifies the Intermediate Language (IL) of an assembly *after* compilation. Source Generators modify the source code *before* compilation.
**Incremental Generator:** An incremental generator only generates code for the specific parts of the project that have changed, rather than regenerating the entire code base. This significantly speeds up build times, making the development experience much faster.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
TPL Dataflow provides a set of building blocks for creating complex, asynchronous data processing pipelines.
*   **ActionBlock:** Executes an action (a function) on incoming messages.
*   **TransformBlock:** Executes a function that transforms an incoming message into a new message.
*   **BufferBlock:** Acts as a queue, buffering incoming messages before they are processed.
**Comparison to Channels:** Channels are simpler, focused on point-to-point or fan-out communication (producer $\rightarrow$ consumer). TPL Dataflow is designed for complex, multi-stage *pipelines* where data flows through multiple processing blocks, allowing for sophisticated control over concurrency, parallelism, and backpressure at each stage.

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**
Minimal APIs allow developers to define API endpoints using simple, lightweight lambda functions directly in the `Program.cs` file, bypassing the need for controllers and action methods.
**Differences/Trade-offs:**
*   **Controller-based:** Highly structured, excellent separation of concerns, mature framework for complex business logic, better built-in support for MVC patterns.
*   **Minimal APIs:** Extremely fast startup time, minimal boilerplate, highly concise.
*   **Trade-offs:** Testability is slightly simpler but less structured than controllers. Middleware integration is straightforward. OpenAPI support requires more manual configuration or external libraries compared to the automatic generation provided by controllers.
**Route Groups and Endpoint Filters:** Route groups allow grouping related endpoints under a common prefix or set of policies. Endpoint filters allow you to inject logic (like authorization checks or logging) that runs before or after the endpoint handler, similar to middleware but scoped to specific endpoints.

## Python

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**
*   **List vs. Tuple:** Lists are mutable (can be changed, appended to, or sorted) and are defined using square brackets `[]`. Tuples are immutable (cannot be changed) and are defined using parentheses `()`.
*   **Set vs. FrozenSet:** Sets are mutable collections of unique, unordered elements. They are optimized for fast membership testing. FrozenSets are immutable versions of sets; they cannot be modified and are hashable, allowing them to be used as elements within other sets or as dictionary keys.

**P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?**
The GIL is a mutex (lock) that protects access to Python objects, preventing multiple native threads from executing Python bytecodes simultaneously. It ensures that only one thread can execute Python code at any given time.
**Effect:** It primarily affects CPU-bound workloads (tasks that spend most of their time performing calculations), as the GIL prevents true parallel execution across multiple CPU cores.
**Workarounds:**
1.  **Multiprocessing:** Using the `multiprocessing` module spawns separate processes, each with its own Python interpreter and GIL, allowing true parallel execution.
2.  **I/O-bound tasks:** For I/O-bound tasks (waiting for network, disk), the GIL is released while the thread is waiting, allowing other threads to run, making `threading` effective.

**P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.**
*   **Shallow Copy (`copy.copy()`):** Creates a new container object, but it populates the new container with *references* to the objects found in the original. If the original object contains mutable objects (like lists or dictionaries), modifying those nested objects in the copy will also modify them in the original.
*   **Deep Copy (`copy.deepcopy()`):** Creates a completely independent copy of the object and recursively copies all nested objects. Changes made to the copy do not affect the original.
**Example:**
```python
original = {'a': [1, 2]}
shallow = copy.copy(original)
shallow['a'].append(3) # Modifies the list referenced by both
print(original['a']) # Output: [1, 2, 3] (Unexpected behavior)
```

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**
A decorator is a design pattern that allows you to modify or enhance a function or method without permanently changing its source code. It wraps the original function, allowing you to execute code before or after the original function runs.
**Implementation:**
```python
import time
from functools import wraps

def timing_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"Function '{func.__name__}' executed in {end_time - start_time:.4f} seconds.")
        return result
    return wrapper

@timing_decorator
def calculate_sum(n):
    return sum(range(n))

# Usage: calculate_sum(1000)
```

**P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?**
**Generators** are functions that return an iterator. Instead of calculating and returning all results at once (like a list), they use the `yield` keyword to pause execution and return one value at a time.
**Difference from List:** A list computes and stores all values in memory immediately. A generator computes values *on demand* (lazily), which is highly memory efficient for large datasets.
**`yield from`:** This keyword is used to delegate to a subgenerator. It allows a generator to yield all values produced by another generator or iterable, effectively chaining generators together without needing to manually loop and yield each item.

**P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?**
**Event Loop:** The core mechanism of `asyncio`. It is a single-threaded loop that manages and schedules coroutines (async functions). When a coroutine encounters an `await` (indicating an I/O wait), it yields control back to the loop, allowing the loop to switch execution to another ready coroutine.
*   **`asyncio.run(coro)`:** Runs the top-level coroutine and manages the event loop lifecycle.
*   **`asyncio.gather(*coros)`:** Runs multiple coroutines concurrently and waits for all of them to complete, returning a list of results.
*   **`asyncio.create_task(coro)`:** Schedules a coroutine to run concurrently in the background without blocking the current execution flow.
**`time.sleep()`:** This function is synchronous and blocks the entire thread. In an asynchronous environment, blocking the thread prevents the event loop from switching to other tasks, effectively freezing the entire application. You must use `await asyncio.sleep(seconds)` to yield control back to the event loop.

**P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**
**MRO:** The order in which Python searches for methods and attributes in a class hierarchy.
**Algorithm:** Python 3 uses the C3 Linearization Algorithm. This algorithm ensures a consistent, deterministic, and monotonic ordering of classes, resolving conflicts in complex inheritance structures.
**Diamond Inheritance:** In the provided example, `D` inherits from `B` and `C`, both of which inherit from `A`. The MRO determines the search order. Since `D` inherits from `B` first, and `B` inherits from `A`, the search order is $D \rightarrow B \rightarrow C \rightarrow A \rightarrow object$. When `D().who()` is called, the search hits `B` first, which inherits from `A`. The method `who` is found in `A`, so it returns `"A"`.
*(The MRO is D -> B -> C -> A -> object. The method is found in A.)*

**P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.**
**Metaclass:** A class whose instances are classes. It controls the creation of a class object itself. When you define `class MyClass(metaclass=MyMeta):`, `MyMeta` is responsible for building `MyClass`.
**`__init_subclass__`:** A class method available since Python 3.6. It is called automatically whenever a class inherits from the current class. It is used for configuration or modification *after* the subclass is defined but *before* it is fully initialized.
**Comparison/Use Cases:**
*   **`__init_subclass__`:** Use when you need to perform simple, declarative setup or validation on subclasses (e.g., automatically registering all subclasses with a central registry).
*   **Metaclass:** Use when you need to fundamentally alter the structure or behavior of the class itself (e.g., automatically adding properties, overriding attribute access, or enforcing complex API contracts during class creation).

**P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?**
*   **Threading:** Uses threads within a single process. Best for I/O-bound tasks (waiting for network/disk) because the GIL is released during I/O waits.
*   **Multiprocessing:** Uses separate processes. Best for CPU-bound tasks, as each process has its own GIL and can run truly in parallel across multiple cores.
*   **`concurrent.futures`:** A high-level interface (like `ThreadPoolExecutor` or `ProcessPoolExecutor`) that abstracts away the complexity of managing threads or processes, providing a unified `Executor` interface for submitting tasks.
**When to Use:**
*   I/O-bound: `threading` or `concurrent.futures.ThreadPoolExecutor`.
*   CPU-bound: `multiprocessing` or `concurrent.futures.ProcessPoolExecutor`.
**Serialization (Pickling):** Multiprocessing requires that objects passed between processes (arguments, results) must be serializable (picklable). Pickling converts the Python object structure into a byte stream for transmission. If an object contains non-picklable resources (like open file handles or database connections), multiprocessing will fail.

**P10 — Medium: What is __slots__? When should you use it, and what does it prevent? What is the memory impact?**
`__slots__` is a class attribute that tells Python not to use a standard instance dictionary (`__dict__`) to store instance attributes. Instead, it pre-allocates a fixed set of slots for the attributes defined in the slot list.
**Prevention:** It prevents the creation of the instance dictionary, which is a major source of memory overhead in Python objects. It also prevents the dynamic addition of new attributes after the object has been instantiated.
**Memory Impact:** It significantly reduces memory consumption, especially when creating a large number of instances of the class, as it avoids the overhead of the dictionary structure for every object.

A virtual environment is an isolated directory that contains a specific Python interpreter and its own set of installed packages.

**Differences:**

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?**
These are concise, readable ways to create collections.
*   **List Comprehension:** `[expression for item in iterable if condition]` (Creates a list).
*   **Dict Comprehension:** `{key: value for item in iterable}` (Creates a dictionary).
*   **Set Comprehension:** `{expression for item in iterable if condition}` (Creates a set).
**Relation to `map()` and `filter()`:** Comprehensions are generally preferred over `map()` and `filter()` because they are more readable and idiomatic Python. `map()` and `filter()` return iterators, but comprehensions combine the iteration, mapping, and filtering steps into a single, highly readable expression.

**P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?**
*   **`is`:** Checks for object identity (whether two variables point to the exact same object in memory).
*   **`==`:** Checks for equality (whether the values contained within the objects are equal).
*   **Object Interning:** A memory optimization technique where Python pre-allocates and caches certain immutable objects (like small integers, e.g., -5 to 256, and short strings). When you create a small integer, Python often returns a reference to the cached object instead of creating a new one. This is why `a is b` might return `True` for small integers, even if they are technically separate variables.

**P14 — Easy: Explain Python's *args and **kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?**
*   **`*args`:** Collects an arbitrary number of positional arguments into a tuple.
*   **`**kwargs`:** Collects an arbitrary number of keyword arguments into a dictionary.
*   **Positional-Only (`/`):** Arguments listed before `/` must be passed by position and cannot be passed using a keyword.
*   **Keyword-Only (`*`):** Arguments listed after `*` must be passed using their keyword name and cannot be passed by position.
**Example:** `def func(a, b, *, c, d):` requires `c` and `d` to be passed as keywords.

**P15 — Easy: What are context managers (with statement)? How do you write one using __enter__/__exit__ vs @contextmanager? Give an example beyond file handling.**
A context manager is an object that defines the runtime context to be established when executing a block of code. It guarantees that setup and teardown actions are performed, even if errors occur.
*   **`__enter__`:** The method called upon entering the `with` block (setup). It returns the resource.
*   **`__exit__`:** The method called upon exiting the `with` block (teardown), handling cleanup.
*   **`@contextmanager`:** A simpler way to create a context manager using a generator. The code before `yield` is the setup (`__enter__`), and the code after `yield` is the teardown (`__exit__`).
**Example (Database Connection):**
```python
from contextlib import contextmanager
@contextmanager
def db_session():
    conn = connect_to_db() # Setup
    try:
        yield conn # The resource
    finally:
        conn.close() # Teardown
```

**P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How does mypy or pyright use these for static analysis?**
**Type Hinting:** A system introduced in Python to allow developers to annotate variables, function parameters, and return values with expected types. It does not change Python's runtime behavior but enables static analysis.
*   **`Union[A, B]`:** Indicates a variable can be of type A OR type B.
*   **`Optional[T]`:** A shorthand for `Union[T, None]`. Indicates a variable can be of type T or `None`.
*   **`Literal[value]`:** Constrains a variable to be exactly one of the specified literal values (e.g., `Literal['red', 'blue']`).
*   **`TypeVar`:** A placeholder used to define generic types, similar to generics in C#.
*   **`Protocol`:** Defines a structural type (duck typing). It specifies that any class implementing the required methods/attributes satisfies the protocol, regardless of explicit inheritance.
**Static Analysis:** Tools like Mypy or Pyright read these hints *before* the code runs. They check for type mismatches (e.g., trying to pass a string where an integer is expected) and flag potential bugs, enforcing type safety without sacrificing Python's dynamic nature.

**P17 — Medium: Explain Python's data model (dunder methods). What are __repr__ vs __str__, __eq__ vs __hash__, and __getattr__ vs __getattribute__? What happens if you define __eq__ but not __hash__?**
**Dunder Methods:** Special methods (double underscore) that allow user-defined classes to interact with Python's built-in features.
*   **`__str__` vs `__repr__`:** `__str__` provides a human-readable string representation (for printing). `__repr__` provides an unambiguous, developer-friendly string representation (ideally one that could recreate the object).
*   **`__eq__` vs `__hash__`:** `__eq__` defines equality comparison (`==`). `__hash__` defines how an object is mapped to an integer value for use in hash-based collections (like sets and dictionaries).
**Consequence:** If you define `__eq__` but not `__hash__`, Python will raise a `TypeError` if you try to use that object as a key in a dictionary or add it to a set, because the object cannot be reliably hashed.

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (__get__, __set__, __delete__). How do property, classmethod, and staticmethod use descriptors under the hood?**
**Descriptors:** Objects that define how attribute access (getting, setting, or deleting) works for another object. They allow you to customize attribute access behavior.
**Protocol:** A descriptor must implement three methods:
*   `__get__(self, instance, owner)`: Called when the attribute is accessed (read).
*   `__set__(self, instance, value)`: Called when the attribute is assigned a value (write).
*   `__delete__(self, instance)`: Called when the attribute is deleted (`del`).
**Usage:**
*   **`property`:** A built-in descriptor that wraps a method to allow attribute access syntax (e.g., `obj.value` instead of `obj.get_value()`).
*   **`classmethod` and `staticmethod`:** These are descriptors that modify how the attribute is accessed, ensuring the method receives the correct context (the class or no instance, respectively) when called.

**P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, __init__.py, and namespace packages work? What is a finder and a loader?**
**Import System:** Python searches for modules by looking at directories listed in `sys.path`.
*   **`sys.path`:** A list of directories where Python looks for modules. It includes the current directory and directories specified in the `PYTHONPATH` environment variable.
*   **Absolute Imports:** Start from the root of the package (e.g., `import package.module`).
*   **Relative Imports:** Start from the current package location (e.g., `from . import module`).
*   **`__init__.py`:** Historically, this file marked a directory as a Python package. While less critical in modern Python (3.3+), it still defines package initialization logic.
*   **Namespace Packages:** Allow a package to be split across multiple directories without requiring an `__init__.py` in every subdirectory, useful for large, distributed libraries.
**Finder and Loader:** A **Finder** is responsible for locating a module (finding the correct package/directory). A **Loader** is responsible for loading the module's code into memory and executing it.

**P20 — Hard: What is dataclasses and how does it compare to attrs and Pydantic? Explain __post_init__, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**
**Dataclasses:** A decorator (`@dataclass`) that automatically generates boilerplate methods like `__init__`, `__repr__`, `__eq__`, etc., based on type-hinted class attributes.
**Comparison:**
*   **`attrs`:** A library that provides similar functionality to dataclasses but is often considered more flexible and mature.
*   **Pydantic:** A data validation library. It not only structures data but also *validates* it against defined schemas (e.g., ensuring an email field is a valid email format).
**Features:**
*   **`__post_init__`:** A method called immediately after the generated `__init__` method runs, useful for post-initialization logic (e.g., calculating a derived field).
*   **Field Factories:** Allows you to define default values that are computed dynamically rather than being static values (e.g., `field(default_factory=list)`).
*   **Frozen Dataclasses:** By setting `frozen=True`, the dataclass becomes immutable, preventing attribute modification after initialization.
**Pydantic vs. Dataclasses:** Choose **Pydantic** when data validation, schema enforcement, and serialization (e.g., converting to JSON) are critical. Choose **dataclasses** when you simply need a lightweight, boilerplate-free container for data within your application logic.
