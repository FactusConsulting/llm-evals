## Networking Answers

**N1 — Easy: What is the difference between a Layer 2 switch and a Layer 3 switch?**
A Layer 2 switch operates primarily at the Data Link Layer (Layer 2) and forwards frames based on MAC addresses. It is used for local network segmentation. A Layer 3 switch operates at the Network Layer (Layer 3) and can route traffic between different subnets using IP addresses. It combines the high-speed switching capabilities of a Layer 2 device with the routing capabilities of a router.

**N2 — Easy: A host has IP 10.0.5.37/20. What is the network address and broadcast address?**
The subnet mask for /20 is 255.255.240.0.
*   **Network Address:** 10.0.5.0
*   **Broadcast Address:** 10.0.15.255

**N3 — Medium: Explain the TCP three-way handshake. What happens if the final ACK is lost?**
The TCP three-way handshake establishes a reliable connection:
1.  **SYN (Synchronize):** Client sends a SYN packet to the server (initiating the connection).
2.  **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and replies with a SYN-ACK.
3.  **ACK (Acknowledge):** Client receives SYN-ACK and sends a final ACK back to the server, confirming the connection is established.
If the final ACK is lost, the server will not receive the confirmation. The server will wait for a timeout period and will retransmit the SYN-ACK. The client, however, will eventually time out and retransmit the initial SYN packet, leading to connection failure or re-establishment attempts.

**N4 — Medium: What is the difference between SNAT and DNAT? Give a practical example of each.**
*   **SNAT (Source Network Address Translation):** Changes the source IP address of a packet as it leaves a private network and goes to the public internet. This allows multiple internal hosts to share a single public IP.
    *   *Example:* A private host (10.0.0.5) accessing Google uses the router's public IP (203.0.113.10) as its source address.
*   **DNAT (Destination Network Address Translation):** Changes the destination IP address of a packet as it enters a private network. This is typically used to expose a specific internal service to the public internet.
    *   *Example:* A public user accessing a web server at 203.0.113.10 is translated by the firewall to the internal server's private IP (10.0.0.10).

**N5 — Medium: You run `curl -v https://example.com` and get `SSL: certificate subject name does not match target host name`. List 3 possible causes.**
1.  **Misconfiguration:** The server administrator configured the SSL certificate for a different domain name than the one the user is accessing (e.g., the certificate is for `www.example.com` but the user accessed `example.com`).
2.  **DNS Mismatch:** The DNS record for the domain is pointing to an IP address, but the certificate installed on the server for that IP address does not match the domain name.
3.  **Load Balancer/Proxy Issue:** A load balancer or reverse proxy is terminating the SSL connection, but the certificate presented to the client does not match the hostname the client requested, often due to incorrect hostname configuration in the proxy layer.

**N6 — Medium: Explain the difference between a VLAN and a VxLAN. When would you choose VxLAN over VLAN?**
*   **VLAN (Virtual Local Area Network):** Segments a Layer 2 broadcast domain within a single physical network. VLANs are limited by the 4094 ID space and are constrained by the physical topology of the underlying switches.
*   **VxLAN (Virtual Extensible LAN):** Encapsulates Layer 2 Ethernet frames within a Layer 4 UDP packet, allowing the virtual network to be stretched across an IP network (Layer 3).
*   **When to choose VxLAN:** You choose VxLAN when you need to overcome the limitations of VLANs, specifically when you need to extend a Layer 2 domain across a large, multi-subnet, or multi-datacenter environment (e.g., cloud networking or large campus networks).

**N7 — Hard: A Linux host has two NICs: eth0 (10.0.0.5/24, default gw 10.0.0.1) and eth1 (192.168.1.5/24). Traffic arriving on eth1 from 192.168.1.0/24 is being replied via eth0. Why, and how do you fix it with policy-based routing?**
*   **Why:** The kernel's default routing table (based on the routing table entries) is likely directing all traffic destined for the 192.168.1.0/24 subnet out through the default gateway (eth0), even though the source interface (eth1) is locally connected to that subnet. This is often due to a missing or incorrect route metric or a default route overriding the local route.
*   **Fix with Policy-Based Routing (PBR):** PBR allows routing decisions to be based on criteria other than the destination IP (e.g., source IP, protocol, or interface). You would use `ip rule` and `ip route` to create a specific routing table for traffic originating from the 192.168.1.0/24 subnet, forcing it to use the `eth1` interface.
    *   *Example concept:* `ip rule add from 192.168.1.0/24 table 10` and `ip route add default via 192.168.1.1 dev eth1 table 10`.

**N8 — Hard: Explain how BGP path selection works. List at least 5 attributes in the correct order of preference.**
BGP path selection is a complex algorithm used to determine the best path to a destination prefix. It evaluates various attributes in a strict, ordered sequence.
The general order of preference (simplified, focusing on the most common decision points):
1.  **Weight (Cisco proprietary):** Highest is preferred.
2.  **Local Preference:** Highest is preferred (used internally within an AS).
3.  **AS Path Length:** Shortest is preferred (fewer AS hops).
4.  **Origin Type:** IGP > EGP > Incomplete.
5.  **MED (Multi-Exit Discriminator):** Lowest is preferred (used to influence how external peers enter the AS).

**N9 — Hard: What is the MTU implication of running VxLAN over an IPsec tunnel? Show the math for the maximum inner payload if the physical MTU is 1500.**
Running VxLAN over IPsec adds multiple layers of encapsulation, each adding overhead:
1.  **VxLAN Header:** Adds 50 bytes (UDP/VxLAN header).
2.  **IPsec (ESP/AH):** Adds significant overhead (typically 50-70 bytes, depending on encryption/authentication).
3.  **Outer IP Header:** Adds 20 bytes.
*   **Calculation:**
    *   Physical MTU: 1500 bytes
    *   Total Overhead (Estimate): 50 (VxLAN) + 60 (IPsec) + 20 (Outer IP) = 130 bytes
    *   Maximum Inner Payload: $1500 - 130 = 1370$ bytes.

**N10 — Medium: What is the purpose of ARP, and what problem does Gratuitous ARP solve?**
*   **ARP (Address Resolution Protocol):** ARP's purpose is to map a known Layer 3 IP address to its corresponding Layer 2 MAC address within a local network segment. It works by broadcasting an ARP request asking, "Who has this IP? Tell me your MAC."
*   **Gratuitous ARP:** This is an ARP request sent by a host for its *own* IP address. It solves the problem of stale MAC address entries in switches and ARP caches. It is commonly used during network changes (like failover or DHCP lease renewal) to immediately inform the network that the host's MAC address is still associated with its current IP address, preventing traffic black-holing.

**N11 — Easy: What is the difference between a public IP address and a private IP address? List the three private IPv4 ranges defined in RFC 1918.**
*   **Public IP Address:** An IP address globally unique and routable on the public internet. It must be assigned by an Internet Service Provider (ISP).
*   **Private IP Address:** An IP address reserved for use within private networks (LANs). These addresses are not routable on the public internet and require NAT to communicate externally.
*   **RFC 1918 Ranges:**
    1.  10.0.0.0/8
    2.  172.16.0.0/12
    3.  192.168.0.0/16

**N12 — Easy: What is DNS, and what is the difference between an A record, a CNAME record, and an AAAA record?**
*   **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `google.com`) into machine-readable IP addresses.
*   **A Record:** Maps a domain name to an IPv4 address (e.g., `example.com` $\rightarrow$ 192.0.2.1).
*   **CNAME Record (Canonical Name):** Creates an alias from one domain name to another domain name (e.g., `blog.example.com` $\rightarrow$ `servers.hostingprovider.com`).
*   **AAAA Record:** Maps a domain name to an IPv6 address.

**N13 — Easy: What is DHCP, and what four-step process (DORA) does a client use to obtain an IP address from a DHCP server?**
*   **DHCP (Dynamic Host Configuration Protocol):** A network protocol used to automatically assign IP addresses and other network configuration parameters (like subnet mask, gateway, DNS servers) to devices on a network.
*   **DORA Process:**
    1.  **D**iscover: Client broadcasts a DHCP Discover message to find available DHCP servers.
    2.  **O**ffer: DHCP server responds with a DHCP Offer, proposing an available IP address and configuration.
    3.  **R**equest: Client sends a DHCP Request, formally requesting the offered IP address.
    4.  **A**cknowledge: DHCP server sends a DHCP ACK, confirming the lease and finalizing the configuration.

**N14 — Easy: What is the difference between a hub, a switch, and a router? At which OSI layer does each primarily operate?**
*   **Hub:** A physical layer device (Layer 1). It simply repeats electrical signals to all connected ports, broadcasting data to every device, regardless of the intended recipient.
*   **Switch:** A data link layer device (Layer 2). It learns MAC addresses and forwards frames only to the specific port where the destination MAC address resides, segmenting the network.
*   **Router:** A network layer device (Layer 3). It connects different networks (subnets) and forwards packets between them based on IP addresses.

**N15 — Easy: Explain the difference between half-duplex and full-duplex communication. Which mode do modern Ethernet links use?**
*   **Half-Duplex:** Allows data to travel in both directions, but only one direction at a time. If one device is transmitting, the other must receive, and vice versa. (Like a walkie-talkie).
*   **Full-Duplex:** Allows data to travel simultaneously in both directions. Both devices can transmit and receive at the same time.
*   **Modern Ethernet links use Full-Duplex.**

**N16 — Medium: What is the purpose of the TTL field in an IP packet? How does traceroute exploit it to map the network path?**
*   **Purpose of TTL (Time To Live):** The TTL is a counter in the IP header that prevents packets from circulating indefinitely in routing loops. Each router that processes the packet decrements the TTL value. If the TTL reaches zero, the router discards the packet and typically sends an ICMP Time Exceeded message back to the source.
*   **Traceroute Exploitation:** `traceroute` (or `tracert`) exploits the TTL mechanism. It sends a sequence of packets, starting with a TTL of 1, then 2, then 3, and so on. When the packet reaches the first router (TTL=1), that router drops it and sends back an ICMP Time Exceeded message, revealing the first hop. This process continues until the packet reaches the final destination.

**N17 — Medium: Explain what a NAT gateway does. What is the difference between static NAT, dynamic NAT, and PAT (port address translation)?**
*   **NAT Gateway:** A device (usually a firewall or router) that translates private, non-routable IP addresses used within a local network into public, routable IP addresses when communicating with the external internet.
*   **Static NAT:** A one-to-one, permanent mapping where a specific private IP address is always mapped to a specific public IP address. (Used for servers that need to be consistently reachable from the outside).
*   **Dynamic NAT:** Maps a private IP address to a public IP address from a pool of available public addresses. The mapping is temporary and changes as addresses become available.
*   **PAT (Port Address Translation) / NAT Overload:** The most common form. It maps multiple private IP addresses to a single public IP address by using unique source port numbers to distinguish between the internal hosts.

**N18 — Hard: Explain how ECMP (Equal-Cost Multi-Path) routing works. What hashing strategies are commonly used, and what problems can arise with asymmetric flows when stateful firewalls are involved?**
*   **ECMP:** ECMP allows a router to use multiple paths (interfaces/next-hops) to reach the same destination prefix if all paths have the same routing metric (equal cost). The router distributes traffic across these paths using a hashing algorithm.
*   **Hashing Strategies:** Common strategies hash based on packet headers, typically using a combination of the source IP, destination IP, source port, and destination port. This ensures that all packets belonging to the same flow (flow-based hashing) follow the same path, maintaining session state.
*   **Asymmetric Flow Problem:** If a stateful firewall is involved, asymmetric routing occurs when the traffic flow takes different paths in each direction (e.g., request goes Path A, response comes back via Path B). Stateful firewalls track connections based on the expected return path. If the return traffic arrives on an unexpected interface or through a different firewall, the firewall may drop the packet because it does not match the established session state, causing connection failure.

**N19 — Hard: A TCP connection between two hosts shows high latency but packet captures show no drops. The bandwidth-delay product is 10MB but the TCP window size maxes out at 64KB. Explain the problem and how TCP window scaling (RFC 1323) solves it.**
*   **The Problem (Bandwidth-Delay Product):** The Bandwidth-Delay Product (BDP) represents the maximum amount of unacknowledged data that can be "in flight" on the network at any given time. If the BDP is 10MB, the sender needs to be able to transmit 10MB of data before waiting for an ACK. If the TCP window size is limited to 64KB, the sender is artificially constrained, and the connection will be limited by the small window size, leading to poor utilization and high latency, even if the network path is clear.
*   **Solution (TCP Window Scaling):** RFC 1323 introduced the Window Scale option during the TCP handshake. This option allows the TCP window size to be negotiated beyond the traditional 16-bit limit (65,535 bytes). By scaling the window size, the sender can advertise a much larger receive window, allowing the sender to fill the entire BDP, thus maximizing throughput and minimizing latency.

**N20 — Hard: Describe how 802.1Q trunk ports work. A server with a single NIC needs to communicate on VLANs 10, 20, and 30. Explain how to configure this on Linux using sub-interfaces and what the frame format looks like on the wire.**
*   **802.1Q Trunking:** 802.1Q is a standard that allows a single physical link (trunk) to carry traffic for multiple VLANs. It achieves this by inserting a 4-byte tag (the VLAN tag) into the Ethernet frame header.
*   **Linux Sub-interfaces:** To allow a single NIC to participate in multiple VLANs, you create sub-interfaces (e.g., `eth0.10`, `eth0.20`, `eth0.30`). Each sub-interface is configured with a specific VLAN ID and is treated as a separate logical interface, allowing it to have its own IP address and routing rules.
*   **Frame Format:** The frame format is standard Ethernet, but immediately after the source/destination MAC addresses, the 4-byte 802.1Q tag is inserted. This tag contains the **VLAN ID (VID)**, which tells the receiving switch which VLAN the frame belongs to.

## Linux Answers

**L1 — Easy: What is the difference between a hard link and a symbolic link?**
*   **Hard Link:** A hard link is a direct pointer to the same inode (the data structure containing file metadata) as the original file. It is essentially another name for the same data. Hard links cannot span across different file systems and cannot link to directories.
*   **Symbolic Link (Symlink):** A symbolic link is a special file that contains a text path pointing to another file or directory. It is a pointer, not a direct reference, and can span across different file systems.

**L2 — Easy: How do you find all files larger than 100MB under /var/log?**
Using the `find` command:
`find /var/log -type f -size +100M`

**L3 — Medium: A process is in state D (uninterruptible sleep). What does this mean, and can you kill it with kill -9?**
*   **Meaning:** State D means the process is in uninterruptible sleep. This typically indicates that the process is waiting for a critical I/O operation to complete (e.g., waiting for disk or network hardware). The process is blocked by the kernel and cannot be interrupted by signals.
*   **Killing:** No, you cannot reliably kill a process in state D using `kill -9` (SIGKILL). Since the process is waiting on hardware, the kernel cannot terminate it until the I/O operation completes, making the process immune to standard signals.

**L4 — Medium: Explain the difference between cgroups v1 and cgroups v2. Which does systemd prefer and why?**
*   **cgroups v1:** Used resource controllers (CPU, memory, I/O) in isolation. Each resource was managed by a separate controller, leading to complexity and potential inconsistencies.
*   **cgroups v2:** A unified, hierarchical control group system. It uses a single, unified hierarchy and a unified set of controllers, making resource management simpler, more predictable, and more efficient.
*   **Systemd Preference:** Systemd strongly prefers cgroups v2 because its unified structure aligns perfectly with systemd's goal of managing complex dependencies and resource isolation across the entire system.

**L5 — Medium: What is the difference between nftables and iptables? How does the kernel handle both simultaneously?**
*   **iptables:** The older, traditional firewall framework. It uses a set of chains (INPUT, OUTPUT, FORWARD) and tables (filter, nat, mangle) to process packets.
*   **nftables:** The modern, unified framework. It replaces iptables and provides a more flexible, powerful, and efficient way to manage firewall rules. It uses a single set of tables and chains, allowing for more complex rule sets and better performance.
*   **Kernel Handling:** The kernel maintains compatibility layers. When both are installed, the kernel often runs the `iptables` commands through a compatibility layer that translates them into the underlying `nftables` syntax, allowing older scripts to continue functioning while the system uses the modern framework.

**L6 — Medium: You run `df -h` and see a filesystem at 100%, but `du -sh /*` totals far less. What is the most likely cause?**
The most likely cause is that the disk space is being consumed by **inode usage**, not by file size.
*   **Explanation:** An inode is a data structure that stores metadata about a file (permissions, ownership, location on disk). Even if the files themselves are small, if the system has created a massive number of files (e.g., millions of temporary log files or session files), the system can run out of available inodes, causing the filesystem to report 100% usage, even if the total byte count (`du`) is low.

**L7 — Hard: Explain the Linux boot process from UEFI firmware to a running systemd target. Cover: firmware, bootloader, kernel, initramfs, root, systemd.**
1.  **UEFI Firmware:** The system powers on. The UEFI firmware initializes hardware and locates the bootloader (e.g., GRUB2).
2.  **Bootloader (GRUB2):** The bootloader loads the Linux kernel image and the initial RAM disk (`initramfs`) into memory.
3.  **Kernel:** The kernel takes control. It initializes core components, mounts the `initramfs` (a temporary root filesystem containing necessary drivers and utilities).
4.  **Initramfs:** The kernel executes scripts within the `initramfs`. These scripts handle early tasks, such as loading necessary drivers (like SATA/NVMe drivers) and mounting the real root filesystem (`/`).
5.  **Root Filesystem:** Once the real root filesystem is mounted, the kernel executes the first user-space process, which is typically `/sbin/init` or, in modern systems, `systemd`.
6.  **Systemd:** Systemd takes over, reads its configuration, starts essential services (networking, logging, etc.), and eventually reaches the final target (e.g., `multi-user.target`), resulting in a fully operational system.

**L8 — Hard: A server has 64GB RAM but only 2GB swap. free -h shows 60GB used, 1GB available, 15GB of that is buff/cache. The OOM killer fires. Explain why available can be low even with high buff/cache, and what kernel tunables affect this behavior.**
*   **Explanation:** The `available` metric in `free -h` is a calculated value that estimates how much memory is available for starting new applications. While `buff/cache` memory is technically used, the kernel can reclaim it. However, if the system is under heavy memory pressure (i.e., many processes are actively requesting memory), the kernel prioritizes keeping application memory intact. If the active memory usage (used by running processes) is high, and the kernel needs to free up memory quickly, it may not be able to reclaim enough from the cache to satisfy the request, leading to the OOM killer firing.
*   **Kernel Tunables:** Key tunables include `vm.swappiness` (controls how aggressively the kernel swaps out inactive pages) and `vm.min_free_kbytes` (sets the minimum amount of memory the kernel must keep free).

**L9 — Medium: What does `ip netns` do, and how is it used by container runtimes?**
*   **Function:** `ip netns` (network namespace) allows the creation and management of isolated network environments. A network namespace is a virtual network stack that contains its own set of network resources (interfaces, routing tables, firewall rules, etc.), completely isolated from the host system and other namespaces.
*   **Container Runtime Use:** Container runtimes (like Docker or Kubernetes) use network namespaces to provide network isolation. When a container starts, the runtime places it into a new network namespace. This ensures that the container's network stack (its IP address, its routing table, its interfaces) is completely separate from the host's network stack, providing strong isolation.

**L10 — Medium: Explain the difference between SIGTERM, SIGKILL, and SIGQUIT. Which can be caught by the process?**
*   **SIGTERM (Signal 15):** The standard, polite termination signal. It requests the process to shut down gracefully, allowing it to clean up resources (save files, close connections) before exiting. **Can be caught.**
*   **SIGKILL (Signal 9):** The immediate, forceful termination signal. The kernel kills the process instantly without giving the process any chance to clean up. **Cannot be caught.**
*   **SIGQUIT (Signal 3):** Requests the process to quit and usually dump a core file (a snapshot of the process memory) for debugging. **Can be caught.**

**L11 — Easy: What is the difference between stdout, stderr, and stdin? How do you redirect stderr to a file while still displaying stdout on the terminal?**
*   **stdin (Standard Input):** The stream from which a program receives input (usually the keyboard).
*   **stdout (Standard Output):** The stream where a program writes its normal, expected output (usually the terminal screen).
*   **stderr (Standard Error):** The stream where a program writes error messages, warnings, and diagnostic information.
*   **Redirection:** To redirect stderr to a file (`errors.log`) while keeping stdout on the terminal:
    `command 2> errors.log`

**L12 — Easy: What does the chmod 755 command do? Explain what each digit represents.**
`chmod 755` sets the permissions for a file or directory. The digits represent permissions for the Owner, Group, and Others, respectively.
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = 7. The owner has full permissions.
*   **5 (Group):** Read (4) + Execute (1) = 5. The group can read and execute the file.
*   **5 (Others):** Read (4) + Execute (1) = 5. All other users can read and execute the file.

**L13 — Easy: What is the difference between the root user and a user with sudo privileges?**
*   **Root User (UID 0):** The superuser. The root user has absolute, unrestricted access to the entire operating system. It can read, write, and modify any file, change system configurations, and manage all processes.
*   **Sudo User:** A standard user who is granted specific, limited permissions to execute certain commands as root using the `sudo` command. This allows the user to perform administrative tasks without having full root access, adhering to the principle of least privilege.

**L14 — Easy: What is a package manager? Name the default package managers for Debian/Ubuntu and RHEL/Fedora.**
*   **Package Manager:** A system software that automates the process of installing, upgrading, configuring, and removing software packages. It manages dependencies, ensuring that all required libraries and components are present.
*   **Debian/Ubuntu:** `apt` (Advanced Package Tool)
*   **RHEL/Fedora:** `dnf` (Dandified YUM) or `yum`

**L15 — Easy: What is the /etc/fstab file used for? What happens if an entry is misconfigured?**
*   **/etc/fstab (File System Table):** This file contains static information about the file systems that the system should mount at boot time. It specifies the device (UUID or device name), the mount point, the filesystem type, and mounting options.
*   **Misconfiguration:** If an entry is misconfigured (e.g., pointing to a non-existent device, using an incorrect filesystem type, or specifying an incorrect mount point), the system will fail to mount that file system during the boot process. This can lead to a boot failure, a degraded system state, or the system halting until the issue is resolved.

**L16 — Medium: Explain what LVM (Logical Volume Manager) is. What are physical volumes, volume groups, and logical volumes, and how do you extend a logical volume on a running system?**
*   **LVM:** A layer of abstraction that allows administrators to manage storage volumes flexibly, independent of the underlying physical disk layout.
*   **Physical Volume (PV):** A physical disk or partition that is designated to be used by LVM.
*   **Volume Group (VG):** A pool of storage created by combining one or more Physical Volumes. The VG acts as a large storage container.
*   **Logical Volume (LV):** The actual, flexible volume created within the VG. LVs are what the operating system sees and mounts.
*   **Extending an LV:**
    1.  Extend the Volume Group (VG) by adding more free space (e.g., adding a new PV).
    2.  Extend the Logical Volume (LV) using the command: `lvextend -L +[size] /dev/VG_NAME/LV_NAME`.
    3.  Resize the filesystem on the LV: `resize2fs /dev/VG_NAME/LV_NAME`.

**L17 — Hard: Explain how the Linux kernel's I/O scheduler works. Compare mq-deadline, bfq, and none schedulers. When would you choose each, and how do you change the scheduler for a block device at runtime?**
*   **I/O Scheduler:** The I/O scheduler is a kernel component that manages the queue of read/write requests submitted by applications to the block device. Its job is to reorder these requests to minimize disk seek time and maximize throughput.
*   **Scheduler Comparison:**
    *   **mq-deadline:** Prioritizes requests based on deadlines, ensuring low latency for time-sensitive tasks. Good for mixed workloads.
    *   **bfq (Budget Fair Queueing):** Designed for fairness and low latency, prioritizing interactive workloads (like desktop use) over pure throughput.
    *   **none:** No reordering is performed. Used when the underlying hardware (like NVMe SSDs) is so fast that the overhead of scheduling is detrimental.
*   **Runtime Change:** You can change the scheduler using the `sysfs` interface:
    `echo bfq > /sys/block/sdX/queue/scheduler`

**L18 — Hard: A system is experiencing intermittent high load averages but CPU usage is low. Explain what load average actually measures on Linux, why I/O wait can inflate it, and how you would diagnose whether the bottleneck is CPU, disk, or network using standard tools.**
*   **Load Average:** The load average measures the average number of processes that are either currently running *or* waiting to run (in the run queue). It is a measure of system demand, not necessarily CPU utilization.
*   **I/O Wait Inflation:** When a process is waiting for a slow I/O operation (disk read/write), it enters a waiting state. The kernel counts this waiting process toward the load average, even though the CPU is idle. High I/O wait inflates the load average, making it appear as if the CPU is overloaded when the bottleneck is actually the disk.
*   **Diagnosis:**
    *   **CPU Bottleneck:** High `us` (user) and `sy` (system) CPU usage, low `wa` (wait) time. Use `top` or `htop`.
    *   **Disk Bottleneck:** High `wa` (wait) CPU usage, high I/O queue length (check with `iostat` or `iotop`).
    *   **Network Bottleneck:** High packet drops or high latency observed via `netstat` or `ss`, and high utilization reported by interface statistics (`ip -s link`).

**L19 — Hard: Explain how SELinux enforces mandatory access control. What is the difference between enforcing, permissive, and disabled modes? How do you troubleshoot a daemon that fails to bind a non-standard port due to SELinux policy?**
*   **Mandatory Access Control (MAC):** SELinux enforces MAC by defining strict rules that dictate what subjects (processes) can access which objects (files, ports, sockets), regardless of the traditional Unix permissions (DAC). It operates on security contexts (labels) rather than just user IDs.
*   **Modes:**
    *   **Enforcing:** SELinux actively denies unauthorized access and logs the violation. This is the secure mode.
    *   **Permissive:** SELinux logs all potential violations but does *not* deny access. This is used for testing and debugging.
    *   **Disabled:** SELinux is completely inactive.
*   **Troubleshooting Port Binding:** If a daemon fails to bind a non-standard port, the SELinux policy likely prevents it. The solution is to use `semanage` to tell SELinux that the daemon is allowed to use that specific port/service type:
    `semanage port -a -t http_port_t -p tcp 8080` (Example for port 8080).

**L20 — Hard: Describe how the Linux kernel's virtual memory subsystem handles page faults. What is the difference between a minor and a major page fault? How does transparent huge pages (THP) affect application performance, and when would you disable it?**
*   **Page Fault Handling:** A page fault occurs when a process tries to access a memory address that is not currently mapped into physical RAM. The kernel intercepts this fault, determines if the required data is on disk (swap or file), and initiates the necessary I/O to load the required page into a free physical frame.
*   **Minor vs. Major Page Fault:**
    *   **Minor Page Fault:** The required data is already in physical memory (e.g., in the page cache/buffer cache). The kernel simply updates the page table entry to map the virtual address to the existing physical frame. This is fast.
    *   **Major Page Fault:** The required data is not in physical memory and must be retrieved from secondary storage (disk/swap). This requires a slow I/O operation.
*   **THP (Transparent Huge Pages):** THP attempts to use large memory pages (2MB instead of 4KB) to reduce the overhead of page table management. This can improve performance for large, sequential memory accesses.
*   **When to Disable THP:** THP can introduce unpredictable latency spikes (latency jitter) due to the overhead of its background compaction and coalescing processes. It should be disabled when running latency-sensitive applications (e.g., high-frequency trading, real-time databases) where predictable, low latency is critical.
