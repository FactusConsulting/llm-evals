## Networking

**N1 — Easy: What is the difference between a Layer 2 switch and a Layer 3 switch?**
A Layer 2 switch operates primarily at the Data Link layer (Layer 2) and forwards frames based on MAC addresses. It is used for local network segmentation (LAN). A Layer 3 switch operates at the Network layer (Layer 3) and can forward packets based on IP addresses. It can perform routing between different VLANs or subnets, combining the high-speed switching capabilities of a L2 switch with the routing intelligence of a router.

**N2 — Easy: A host has IP 10.0.5.37/20. What is the network address and broadcast address?**
The subnet mask /20 means $2^{32-20} = 2^{12} = 4096$ addresses.
The network address is $10.0.5.0$.
The broadcast address is $10.0.15.255$. (The range spans from 10.0.5.0 to 10.0.15.255).

**N3 — Medium: Explain the TCP three-way handshake. What happens if the final ACK is lost?**
The TCP three-way handshake establishes a reliable connection:
1.  **SYN (Synchronize):** Client sends a SYN packet to the server, requesting a connection and proposing an initial sequence number (ISN).
2.  **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and responds with a SYN-ACK, acknowledging the client's SYN and providing its own ISN.
3.  **ACK (Acknowledge):** Client receives SYN-ACK and sends a final ACK, acknowledging the server's SYN-ACK.
If the final ACK is lost, the client will retransmit the ACK (or the server will time out and retransmit the SYN-ACK). The connection will eventually time out on the client side, or the server will eventually time out and drop the connection, as the server never receives the final confirmation that the connection is established.

**N4 — Medium: What is the difference between SNAT and DNAT? Give a practical example of each.**
*   **SNAT (Source Network Address Translation):** Changes the source IP address of a packet as it leaves a private network. This is typically used when internal hosts access the internet, allowing multiple private IPs to share a single public IP.
    *   *Example:* An internal host (192.168.1.10) accessing Google (8.8.8.8) is translated to the router's public IP (203.0.113.5) before leaving the network.
*   **DNAT (Destination Network Address Translation):** Changes the destination IP address of a packet as it enters a private network. This is typically used for port forwarding or exposing internal services to the internet.
    *   *Example:* An external user accessing a public IP (203.0.113.5) on port 80 is translated to the internal web server's private IP (192.168.1.10).

**N5 — Medium: You run `curl -v https://example.com` and get `SSL: certificate subject name does not match target host name`. List 3 possible causes.**
1.  **Misconfiguration/Typo:** The domain name used in the URL (`example.com`) does not exactly match the Common Name (CN) or Subject Alternative Name (SAN) listed in the SSL certificate.
2.  **Load Balancer/Proxy Issue:** A load balancer or reverse proxy is terminating the SSL connection using a certificate for one domain, but the traffic is being forwarded to a backend server that is presenting a different certificate.
3.  **Improper Certificate Issuance:** The certificate was issued for a different hostname or IP address than the one currently being accessed, often due to an error during the Certificate Signing Request (CSR) process.

**N6 — Medium: Explain the difference between a VLAN and a VxLAN. When would you choose VxLAN over VLAN?**
*   **VLAN (Virtual Local Area Network):** A Layer 2 segmentation mechanism that logically groups devices within the same broadcast domain, typically limited by the physical infrastructure (e.g., 4094 VLAN IDs). It requires all devices to be within the same physical L2 domain (or connected via trunking).
*   **VxLAN (Virtual Extensible LAN):** A network virtualization overlay technology that encapsulates Layer 2 Ethernet frames within UDP packets. It allows Layer 2 segments (VLANs) to be stretched across a Layer 3 network (IP fabric).
*   **When to choose VxLAN:** You choose VxLAN when you need to extend Layer 2 connectivity (like a traditional VLAN) across a large, multi-subnet, or geographically distributed Layer 3 infrastructure. This overcomes the scaling limitations of traditional VLANs and allows for massive segmentation (using VXLAN Network Identifiers, or VNIs).

**N7 — Hard: A Linux host has two NICs: eth0 (10.0.0.5/24, default gw 10.0.0.1) and eth1 (192.168.1.5/24). Traffic arriving on eth1 from 192.168.1.0/24 is being replied via eth0. Why, and how do you fix it with policy-based routing?**
*   **Why:** The kernel's default routing table (based on the default gateway on eth0) is likely being used for all traffic. When the host receives a packet from 192.168.1.0/24, the kernel determines the return path based on the destination IP (192.168.1.x). If the routing table is not explicitly configured to prefer the local interface (eth1) for that subnet, the kernel might incorrectly route the response back out the default gateway (eth0) if the routing rules are ambiguous or if the routing table is configured to prefer the default route.
*   **Fix with Policy-Based Routing (PBR):** PBR allows routing decisions to be made based on criteria other than the destination IP address, such as the source IP address.
    1.  Create a new routing table (e.g., `table 100`).
    2.  Add a rule to this table that specifies that traffic originating from the 192.168.1.0/24 subnet must use the interface eth1.
    3.  Use `ip rule` to direct traffic originating from 192.168.1.0/24 to use this new routing table (`ip rule add from 192.168.1.0/24 table 100`).

**N8 — Hard: Explain how BGP path selection works. List at least 5 attributes in the correct order of preference.**
BGP (Border Gateway Protocol) is the routing protocol of the internet. Path selection is a complex process where routers evaluate multiple paths to the same destination and select the "best" path based on a strict set of attributes.

The general order of preference (simplified, as the full list is extensive):
1.  **Weight (Cisco proprietary):** Highest weight is preferred.
2.  **Local Preference:** Highest local preference is preferred (used within an AS).
3.  **AS Path Length:** Shortest AS path is preferred.
4.  **Origin Type:** IGP (i) > EGP (e) > Incomplete (?)
5.  **MED (Multi-Exit Discriminator):** Lowest MED is preferred (used to influence neighboring ASes).
6.  **Next-Hop Reachability:** The next-hop must be reachable.

**N9 — Hard: What is the MTU implication of running VxLAN over an IPsec tunnel? Show the math for the maximum inner payload if the physical MTU is 1500.**
The MTU implication is that each encapsulation layer adds overhead, reducing the available payload size.
*   **Encapsulation Layers:**
    1.  Original Ethernet Frame (Payload)
    2.  VxLAN Header (50 bytes)
    3.  UDP Header (8 bytes)
    4.  IP Header (20 bytes)
    5.  IPsec Header (ESP/AH, typically 30-50 bytes, assuming ESP with authentication).
*   **Math:**
    *   Physical MTU: 1500 bytes
    *   Total Overhead (Minimum): VxLAN (50) + UDP (8) + IP (20) + IPsec (30) = 108 bytes.
    *   Maximum Inner Payload = Physical MTU - Total Overhead
    *   Maximum Inner Payload = $1500 - 108 = 1392$ bytes.

**N10 — Medium: What is the purpose of ARP, and what problem does Gratuitous ARP solve?**
*   **ARP (Address Resolution Protocol):** ARP's purpose is to map a known Layer 3 IP address to its corresponding Layer 2 MAC address within a local network segment. It works by broadcasting an ARP request ("Who has IP X? Tell me your MAC address") and receiving a reply.
*   **Gratuitous ARP (GARP):** GARP is an ARP request sent by a host *without* a specific query. It is used to proactively announce a host's IP-to-MAC mapping to the local network.
    *   *Problem Solved:* It is primarily used to solve MAC address conflicts or to inform other devices (like switches) immediately when a host changes its IP address (e.g., after a DHCP lease renewal or failover), ensuring the network quickly updates its ARP cache and prevents traffic black-holing.

**N11 — Easy: What is the difference between a public IP address and a private IP address? List the three private IPv4 ranges defined in RFC 1918.**
*   **Public IP Address:** An IP address globally unique and routable on the public internet. It must be assigned by an Internet Service Provider (ISP) and is used for communication outside a private network.
*   **Private IP Address:** An IP address reserved for use within private, local networks (LANs). These addresses are not routable on the public internet and require NAT to communicate externally.
*   **RFC 1918 Ranges:**
    1.  10.0.0.0/8
    2.  172.16.0.0/12
    3.  192.168.0.0/16

**N12 — Easy: What is DNS, and what is the difference between an A record, a CNAME record, and an AAAA record?**
*   **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses (like 192.0.2.1).
*   **Record Differences:**
    *   **A Record:** Maps a domain name to an IPv4 address (e.g., `www.example.com` $\rightarrow$ 192.0.2.1).
    *   **AAAA Record:** Maps a domain name to an IPv6 address (e.g., `www.example.com` $\rightarrow$ 2001:db8::1).
    *   **CNAME Record (Canonical Name):** Creates an alias, mapping one domain name to another domain name (e.g., `blog.example.com` $\rightarrow$ `servers.hostingprovider.com`).

**N13 — Easy: What is DHCP, and what four-step process (DORA) does a client use to obtain an IP address from a DHCP server?**
*   **DHCP (Dynamic Host Configuration Protocol):** A network management protocol used to automatically assign IP addresses and other network configuration parameters (like subnet mask, gateway, DNS servers) to devices on a network.
*   **DORA Process:**
    1.  **Discover:** Client broadcasts a DHCP Discover message to find available DHCP servers.
    2.  **Offer:** DHCP server responds with a DHCP Offer, proposing an IP address and configuration details.
    3.  **Request:** Client sends a DHCP Request, formally accepting the offered IP address.
    4.  **Acknowledge (ACK):** DHCP server sends a DHCP ACK, confirming the lease and finalizing the configuration.

**N14 — Easy: What is the difference between a hub, a switch, and a router? At which OSI layer does each primarily operate?**
*   **Hub:** A simple physical device that repeats incoming electrical signals to all connected ports. It operates at Layer 1 (Physical Layer) and creates a single collision domain. It is unintelligent.
*   **Switch:** A device that forwards data frames based on MAC addresses. It operates at Layer 2 (Data Link Layer) and creates separate collision domains for each port. It is intelligent and segments the network.
*   **Router:** A device that forwards data packets between different networks (subnets) based on IP addresses. It operates at Layer 3 (Network Layer) and is responsible for path determination.

**N15 — Easy: Explain the difference between half-duplex and full-duplex communication. Which mode do modern Ethernet links use?**
*   **Half-Duplex:** Allows data to travel in both directions, but only one direction at a time. Devices must take turns transmitting and receiving (e.g., a walkie-talkie).
*   **Full-Duplex:** Allows data to travel simultaneously in both directions. Devices can transmit and receive at the same time.
*   **Modern Ethernet Links:** Modern Ethernet links overwhelmingly use **full-duplex** communication, which significantly increases throughput and eliminates collisions.

**N16 — Medium: What is the purpose of the TTL field in an IP packet? How does traceroute exploit it to map the network path?**
*   **TTL (Time To Live):** The TTL field is an 8-bit field in the IP header that specifies the maximum number of hops (routers) a packet can traverse before being discarded. It prevents packets from circulating indefinitely in routing loops.
*   **Traceroute Exploitation:** `traceroute` (or `tracert`) exploits the TTL mechanism. It sends a sequence of packets, starting with a TTL of 1, then 2, 3, and so on. When a router receives a packet with a TTL of 1, it decrements the TTL to 0 and drops the packet, sending back an ICMP Time Exceeded message. By observing the sequence of ICMP Time Exceeded messages, `traceroute` maps the path and identifies every router (hop) along the way.

**N17 — Medium: Explain what a NAT gateway does. What is the difference between static NAT, dynamic NAT, and PAT (port address translation)?**
*   **NAT Gateway:** A device (usually a router or firewall) that translates private IP addresses and port numbers into public IP addresses and port numbers, allowing private networks to communicate with the public internet.
*   **Differences:**
    *   **Static NAT:** A one-to-one, fixed mapping. A specific private IP is permanently mapped to a specific public IP. (Used for hosting servers).
    *   **Dynamic NAT:** Maps private IPs to a pool of available public IPs on a first-come, first-served basis. When a host initiates a connection, it is assigned an available public IP from the pool.
    *   **PAT (Port Address Translation) / NAT Overload:** Maps multiple private IPs to a single public IP address by using unique source port numbers to distinguish between different internal hosts. This is the most common form of NAT used in homes and small businesses.

**N18 — Hard: Explain how ECMP (Equal-Cost Multi-Path) routing works. What hashing strategies are commonly used, and what problems can arise with asymmetric flows when stateful firewalls are involved?**
*   **ECMP:** ECMP allows a router to use multiple paths of equal cost to reach the same destination. Instead of choosing a single path, the router distributes traffic across all available paths, effectively increasing bandwidth and providing redundancy.
*   **Hashing Strategies:** The router uses a hashing algorithm based on packet headers (typically source IP, destination IP, source port, and destination port) to determine which path the packet should take. This ensures that all packets belonging to the same flow (session) consistently follow the same path.
*   **Asymmetric Flow Problems:** If a flow enters the network via Path A (e.g., through Router 1) but the return traffic exits via Path B (e.g., through Router 2), this is an asymmetric flow. Stateful firewalls track connections based on the session state (source/destination IP/port). If the firewall only sees the initial connection on Router 1, it may drop the return traffic arriving on Router 2 because it does not recognize the session state, leading to connection failures.

**N19 — Hard: A TCP connection between two hosts shows high latency but packet captures show no drops. The bandwidth-delay product is 10MB but the TCP window size maxes out at 64KB. Explain the problem and how TCP window scaling (RFC 1323) solves it.**
*   **The Problem (Bandwidth-Delay Product - BDP):** The BDP is the maximum amount of unacknowledged data that can be "in flight" on a network link. If the BDP is 10MB, the sender needs to be able to transmit 10MB of data before waiting for an ACK. If the TCP window size is limited to 64KB, the sender must stop and wait for an ACK after sending only 64KB, regardless of the network capacity. This results in severe underutilization of the link and high latency (the sender is waiting for ACKs instead of filling the pipe).
*   **Solution (TCP Window Scaling):** TCP Window Scaling (RFC 1323) extends the standard 16-bit TCP window field (which limits the window size to 65,535 bytes) by adding a scaling factor. This allows the window size to be increased to gigabytes, enabling the sender to transmit the full BDP amount of data and keep the pipe full, thus maximizing throughput and minimizing latency.

**N20 — Hard: Describe how 802.1Q trunk ports work. A server with a single NIC needs to communicate on VLANs 10, 20, and 30. Explain how to configure this on Linux using sub-interfaces and what the frame format looks like on the wire.**
*   **802.1Q Trunk Ports:** A trunk port is a link that carries traffic for multiple VLANs simultaneously. 802.1Q is the standard that tags Ethernet frames with a 4-byte tag (the VLAN ID) to identify which VLAN the frame belongs to, allowing switches to correctly route the frame.
*   **Linux Configuration (Sub-interfaces):** On a single physical NIC, Linux uses sub-interfaces to represent different VLANs. Each sub-interface is configured with a specific VLAN ID and acts as a virtual interface for that VLAN.
    *   *Example:* `eth0.10` (VLAN 10), `eth0.20` (VLAN 20), `eth0.30` (VLAN 30).
*   **Frame Format on the Wire:** The frame structure is:
    [Preamble/SFD] $\rightarrow$ [Destination MAC] $\rightarrow$ [Source MAC] $\rightarrow$ **[802.1Q Tag (4 bytes: TPID + VLAN ID)]** $\rightarrow$ [EtherType] $\rightarrow$ [Payload] $\rightarrow$ [FCS].

## Linux

**L1 — Easy: What is the difference between a hard link and a symbolic link?**
*   **Hard Link:** A hard link is an additional directory entry (a pointer) that points directly to the same inode (the file's metadata and data blocks) as the original file. It is essentially another name for the same data. Hard links cannot span across different file systems and cannot be created for directories.
*   **Symbolic Link (Symlink):** A symbolic link is a special type of file that contains a text path pointing to another file or directory. It is a pointer to a location, not a pointer to the data itself. Symlinks can span file systems and can point to directories.

**L2 — Easy: How do you find all files larger than 100MB under /var/log?**
Using the `find` command:
```bash
find /var/log -type f -size +100M
```
*   `-type f`: Specifies that only regular files should be matched.
*   `-size +100M`: Specifies files larger than 100 Megabytes.

**L3 — Medium: A process is in state D (uninterruptible sleep). What does this mean, and can you kill it with kill -9?**
*   **Meaning:** State D means the process is in uninterruptible sleep. This typically occurs when the process is waiting for a slow or stalled I/O operation (e.g., waiting for a disk read/write to complete). The kernel cannot interrupt this process because it is waiting on hardware, and the process cannot proceed until the I/O completes.
*   **Can you kill it with kill -9?** Generally, no. `kill -9` (SIGKILL) is a forceful termination signal. However, if the process is stuck in D state due to a kernel-level I/O wait, the kernel may not be able to process the SIGKILL signal until the underlying I/O operation completes. If the I/O is permanently stalled, the process may remain in D state even after SIGKILL, requiring a system reboot.

**L4 — Medium: Explain the difference between cgroups v1 and cgroups v2. Which does systemd prefer and why?**
*   **cgroups v1:** Uses separate controllers (e.g., CPU, Memory, I/O) that operate independently. It is complex to manage resource dependencies across different controllers.
*   **cgroups v2:** Implements a unified, hierarchical control structure. It uses a single, unified hierarchy and a unified resource controller, making resource management more consistent and easier to manage.
*   **Systemd Preference:** Systemd strongly prefers cgroups v2 because its unified hierarchy and unified resource controller provide a more robust, predictable, and manageable environment for containerization and service isolation, simplifying the overall system resource governance.

**L5 — Medium: What is the difference between nftables and iptables? How does the kernel handle both simultaneously?**
*   **iptables:** The traditional, older firewall framework in Linux. It uses chains and rules to filter and manage network traffic based on packet headers.
*   **nftables:** The modern, unified packet filtering framework. It is a complete replacement for iptables, offering a more flexible, powerful, and efficient syntax, and it handles all types of filtering (IPv4, IPv6, connection tracking, etc.) within a single structure.
*   **Kernel Handling:** While they are distinct frameworks, the Linux kernel has mechanisms to allow both to coexist. When both are installed, the kernel typically routes the traffic through the framework that was loaded last or configured to take precedence. However, using both simultaneously is generally discouraged as it can lead to unpredictable or conflicting rules.

**L6 — Medium: You run `df -h` and see a filesystem at 100%, but `du -sh /*` totals far less. What is the most likely cause?**
The most likely cause is that the disk space is being consumed by **inode usage**, not by file size.
*   **Explanation:** An inode is a data structure that stores metadata about a file (permissions, ownership, location of data blocks). Even if the files are small, if there are millions of them, the filesystem can run out of available inodes, making the filesystem appear "full" to `df -h` (which reports inode usage) even though the total disk space used (`du -sh`) is low.

**L7 — Hard: Explain the Linux boot process from UEFI firmware to a running systemd target. Cover: firmware, bootloader, kernel, initramfs, root, systemd.**
1.  **UEFI Firmware:** The system powers on. The UEFI firmware initializes hardware and locates the bootloader (e.g., GRUB2) on the designated storage device.
2.  **Bootloader (GRUB2):** The bootloader loads the Linux kernel image and the initial RAM disk (`initramfs`) into memory.
3.  **Kernel:** The kernel starts, initializes hardware drivers, and mounts the `initramfs`.
4.  **Initramfs:** This temporary, minimal root filesystem contains essential drivers and scripts needed to mount the real root filesystem. Its job is to bridge the gap between the kernel starting and the full system being ready.
5.  **Root Filesystem:** The `initramfs` mounts the actual root filesystem (e.g., ext4). The kernel then executes the first user-space program, which is typically `/sbin/init` or, in modern systems, the `systemd` binary.
6.  **Systemd:** Systemd takes over. It reads configuration files, starts services, manages dependencies, and progresses through various targets (e.g., `multi-user.target`, `graphical.target`) until the system reaches its final operational state.

**L8 — Hard: A server has 64GB RAM but only 2GB swap. free -h shows 60GB used, 1GB available, 15GB of that is buff/cache. The OOM killer fires. Explain why available can be low even with high buff/cache, and what kernel tunables affect this behavior.**
*   **Explanation:** The `available` memory metric is a more accurate measure of usable memory than just "free." It accounts for reclaimable memory (like buffers and cache). However, the OOM killer fires when the kernel determines that *all* memory (including reclaimable cache) is needed to satisfy a new memory request, and it cannot reclaim enough memory to prevent system instability.
*   **The Problem:** Even if 15GB is cache, if the system is under heavy load and processes are constantly requesting large amounts of memory, the kernel may be unable to reclaim the cache fast enough, or the processes might be holding onto memory in ways that prevent efficient reclamation.
*   **Kernel Tunables:**
    *   `vm.swappiness`: Controls how aggressively the kernel swaps out anonymous memory. A lower value (e.g., 10) keeps more data in RAM.
    *   `vm.vfs_cache_pressure`: Controls how aggressively the kernel reclaims memory used for directory and inode caches. A lower value keeps these caches longer.

**L9 — Medium: What does `ip netns` do, and how is it used by container runtimes?**
*   **Function:** `ip netns` (network namespace) is a Linux kernel feature that allows a process to have its own isolated view of the network stack. This means the process has its own set of network interfaces, routing tables, firewall rules, and IP addresses, completely isolated from the host system's network stack.
*   **Container Runtime Usage:** Container runtimes (like Docker or Kubernetes) use network namespaces to provide network isolation for containers. Each container is placed into its own dedicated network namespace. This ensures that the processes running inside the container cannot see or interact with the host's network interfaces or other containers' network traffic, providing strong network security and isolation.

**L10 — Medium: Explain the difference between SIGTERM, SIGKILL, and SIGQUIT. Which can be caught by the process?**
*   **SIGTERM (Signal Terminate):** A polite request for the process to shut down. It allows the process to clean up resources (save files, close connections) before exiting. **Can be caught.**
*   **SIGKILL (Signal Kill):** A forceful, immediate termination signal. The kernel terminates the process instantly without giving it a chance to clean up. **Cannot be caught or ignored.**
*   **SIGQUIT (Signal Quit):** A signal that requests the process to terminate, often used to generate a core dump (a snapshot of the process memory) for debugging. **Can be caught.**

**L11 — Easy: What is the difference between stdout, stderr, and stdin? How do you redirect stderr to a file while still displaying stdout on the terminal?**
*   **stdin (Standard Input):** The stream from which a program receives input (usually the keyboard).
*   **stdout (Standard Output):** The stream where a program writes its normal, successful output (usually the terminal screen).
*   **stderr (Standard Error):** The stream where a program writes error messages and diagnostic information (usually the terminal screen).
*   **Redirection:** To redirect stderr (file descriptor 2) to a file while keeping stdout (file descriptor 1) on the terminal:
    ```bash
    command 2> error.log
    ```

**L12 — Easy: What does the chmod 755 command do? Explain what each digit represents.**
`chmod 755` sets the permissions for the file or directory:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = 7. The owner has full permissions.
*   **5 (Group):** Read (4) + Execute (1) = 5. The group has read and execute permissions.
*   **5 (Others):** Read (4) + Execute (1) = 5. All other users have read and execute permissions.

**L13 — Easy: What is the difference between the root user and a user with sudo privileges?**
*   **Root User (UID 0):** The superuser. The root user has absolute, unrestricted access to the entire operating system. It can read, write, and modify any file, change system configurations, and manage all processes without restriction.
*   **Sudo User:** A standard user who is granted specific, limited permissions to execute certain commands as root, but only when explicitly invoking `sudo`. This is a security best practice, as it limits the potential damage if the user's account is compromised.

**L14 — Easy: What is a package manager? Name the default package managers for Debian/Ubuntu and RHEL/Fedora.**
*   **Package Manager:** A system software that automates the process of installing, upgrading, configuring, and removing software packages on a computer. It handles dependencies, ensuring that all required libraries and components are present.
*   **Package Managers:**
    *   **Debian/Ubuntu:** APT (Advanced Package Tool) or `apt`.
    *   **RHEL/Fedora:** DNF (Dandified YUM) or `yum`.

**L15 — Easy: What is the /etc/fstab file used for? What happens if an entry is misconfigured?**
*   **/etc/fstab (File System Table):** This file contains static configuration information about the file systems that the system should mount at boot time. It specifies the device, mount point, file system type, and mounting options.
*   **Misconfiguration:** If an entry is misconfigured (e.g., incorrect device path, wrong file system type, or incorrect mount options), the system will fail to mount that specific filesystem during the boot sequence. Depending on the severity of the error, the boot process may halt entirely, or the system may boot but be missing critical data/directories.

**L16 — Medium: Explain what LVM (Logical Volume Manager) is. What are physical volumes, volume groups, and logical volumes, and how do you extend a logical volume on a running system?**
*   **LVM:** A layer of abstraction that sits between physical storage devices and the filesystem. It allows administrators to manage storage dynamically, enabling resizing, snapshotting, and pooling of disk space without needing to repartition the underlying physical disks.
*   **Components:**
    *   **Physical Volume (PV):** The actual physical disk or partition that LVM uses.
    *   **Volume Group (VG):** A pool of one or more PVs. The VG aggregates the physical space.
    *   **Logical Volume (LV):** The virtual, flexible volume created from the VG. This is what the filesystem is mounted onto.
*   **Extending LV:**
    1.  Add a new PV to the existing VG (`pvadd`).
    2.  Extend the VG to include the new PV (`vgextend`).
    3.  Extend the LV within the VG (`lvextend`).
    4.  Resize the filesystem on the LV (`resize2fs` or `xfs_growfs`).

**L17 — Hard: Explain how the Linux kernel's I/O scheduler works. Compare mq-deadline, bfq, and none schedulers. When would you choose each, and how do you change the scheduler for a block device at runtime?**
*   **I/O Scheduler:** The scheduler determines the order in which I/O requests (reads/writes) are serviced by the block device, optimizing performance by minimizing disk seek time and maximizing throughput.
*   **Scheduler Comparison:**
    *   **mq-deadline:** Prioritizes requests based on deadlines, ensuring low latency for time-sensitive requests while maintaining good throughput. Good for mixed workloads.
    *   **bfq (Budget Fair Queueing):** Designed to provide fair bandwidth allocation to different processes, ensuring that no single process starves. Excellent for desktop/interactive workloads.
    *   **none:** Disables the scheduler, allowing the device driver to handle requests directly. Best for high-performance, specialized storage (like NVMe) where the driver is highly optimized.
*   **Runtime Change:** The scheduler can be changed using the `udev` or `sysfs` interface:
    ```bash
    echo bfq > /sys/block/sda/queue/scheduler
    ```

**L18 — Hard: A system is experiencing intermittent high load averages but CPU usage is low. Explain what load average actually measures on Linux, why I/O wait can inflate it, and how you would diagnose whether the bottleneck is CPU, disk, or network using standard tools.**
*   **Load Average Measurement:** The load average measures the average number of processes that are either currently running *or* waiting in the run queue (waiting for CPU time) over specific time intervals (1, 5, 15 minutes).
*   **I/O Wait Inflation:** If a process is waiting for a slow disk operation (I/O wait), it is still counted in the load average because it is waiting for a resource, not the CPU. If the disk is slow, many processes can be stuck in I/O wait, artificially inflating the load average even if the CPU utilization is low.
*   **Diagnosis:**
    *   **CPU Bottleneck:** High CPU usage (`top`/`htop`), high load average, and processes consuming high CPU time.
    *   **Disk Bottleneck:** High I/O wait percentage (`top`/`iostat`), high average queue length (`iostat`), and high utilization on the disk device.
    *   **Network Bottleneck:** High network utilization (`iftop`/`nload`), high packet drops/errors reported by the interface, and high latency observed in network tools.

**L19 — Hard: Explain how SELinux enforces mandatory access control. What is the difference between enforcing, permissive, and disabled modes? How do you troubleshoot a daemon that fails to bind a non-standard port due to SELinux policy?**
*   **Mandatory Access Control (MAC):** SELinux enforces MAC by defining security policies that dictate which subjects (processes) can access which objects (files, ports, sockets). Unlike DAC (Discretionary Access Control, which relies on user permissions), SELinux policies are centrally managed by the system administrator and cannot be overridden by the process itself.
*   **Modes:**
    *   **Enforcing:** SELinux actively denies access based on policy violations. This is the secure default.
    *   **Permissive:** SELinux logs policy violations but does not enforce them. This is used for testing and debugging.
    *   **Disabled:** SELinux is completely inactive, and the system relies only on standard DAC permissions.
*   **Troubleshooting Port Binding:**
    1.  Check the audit logs (`/var/log/audit/audit.log`) for AVC (Access Vector Cache) denials.
    2.  Use `sealert` or `audit2allow` to analyze the denial.
    3.  The solution is usually to create a custom policy module that explicitly allows the daemon's security context to bind to the required port/port type.

**L20 — Hard: Describe how the Linux kernel's virtual memory subsystem handles page faults. What is the difference between a minor and a major page fault? How does transparent huge pages (THP) affect application performance, and when would you disable it?**
*   **Page Fault Handling:** When a process tries to access a virtual memory address that is not currently mapped to a physical memory page, a page fault occurs. The kernel intercepts this fault and attempts to resolve it by locating the required data (e.g., loading it from disk or allocating a new page).
*   **Minor vs. Major Page Fault:**
    *   **Minor Page Fault:** The required page is not in physical memory, but it *is* already mapped in the kernel's page cache (e.g., a shared library). The kernel simply needs to load the page into RAM. This is fast.
    *   **Major Page Fault:** The required page is not in physical memory and must be loaded from secondary storage (disk/swap). This is slow, as it involves I/O.
*   **THP (Transparent Huge Pages):** THP attempts to automatically use large memory pages (2MB instead of 4KB) for memory allocation.
    *   **Effect:** It can improve performance by reducing TLB (Translation Lookaside Buffer) misses and reducing the overhead of managing many small pages.
    *   **When to Disable:** It can introduce unpredictable latency spikes (latency jitter) during memory allocation and page fault handling, especially under heavy I/O load. It should be disabled (`echo never > /sys/kernel/mm/transparent_hugepage/enabled`) in latency-sensitive applications or databases where consistent, low latency is critical.
