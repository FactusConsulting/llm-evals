## .NET / C# (20 questions)

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
A class is a reference type, meaning it is allocated on the heap and accessed via a reference. It supports inheritance and can have complex behavior. A struct is a value type, meaning it is allocated on the stack (or inline within other types) and is passed by value. You should use a struct when the type is small (typically less than 16 bytes), immutable, and represents a single value (e.g., a point, a color, or a coordinate).

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
`IEnumerable<T>` represents an in-memory collection and executes operations (like `Where` or `Select`) immediately upon iteration. `IQueryable<T>` represents an expression tree that describes a query. When used with an ORM (like Entity Framework Core), the query is translated into SQL and executed on the database server. This distinction matters because using `IQueryable<T>` allows filtering and projection to happen *at the database level*, minimizing data transfer and improving performance, whereas `IEnumerable<T>` forces the entire dataset to be pulled into memory first.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
`async/await` is syntactic sugar built on top of the Task Parallel Library (TPL). When an `await` keyword is encountered, the method execution is suspended, control is returned to the caller, and the runtime schedules a continuation to resume execution once the awaited operation completes. A `Task` is a reference type representing an asynchronous operation that might return a value. A `ValueTask<T>` is a struct that represents an asynchronous operation. You should use `ValueTask<T>` when the operation is likely to complete synchronously (i.e., without hitting the heap allocation of a `Task`), thereby reducing memory allocation overhead, especially in high-performance scenarios.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
Dependency Injection (DI) is a design pattern where components receive their dependencies from an external source (the IoC container) rather than creating them themselves. The three lifetimes are:
1. **Transient:** A new instance is created every time it is requested.
2. **Scoped:** A single instance is created once per scope (e.g., per HTTP request).
3. **Singleton:** A single instance is created once for the entire application lifetime.
A common bug is injecting a **Scoped** service (like `DbContext`) into a **Singleton** service. Since the Singleton service is instantiated once at startup, it holds a reference to the Scoped service instance created during the first request. This shared instance will then be used across *all* subsequent requests, violating the scope boundary and leading to concurrency issues or unexpected state sharing.

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
`string` is an immutable, managed reference type in C#. Operations on a string often involve creating new strings. `ReadOnlySpan<char>` (and `Span<char>`) is a stack-allocated, non-allocating view over a contiguous block of memory (like a string or a byte array). You use `Span<T>` when you need high-performance, low-allocation string or buffer manipulation. It allows you to slice, read, and process data without copying the underlying data, which is crucial for performance-critical code like parsing or serialization.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
The GC automatically manages memory by periodically running collection cycles. It uses generational collection:
*   **Gen 0:** Holds newly allocated, short-lived objects. Collections here are frequent and fast.
*   **Gen 1:** Acts as a buffer between Gen 0 and Gen 2.
*   **Gen 2:** Holds long-lived objects. Collections here are less frequent but more expensive.
The **Large Object Heap (LOH)** stores objects larger than a threshold (typically 85KB). The LOH is generally not compacted by the GC, which can lead to memory fragmentation.
`IDisposable` is used for **unmanaged resources** (e.g., file handles, network sockets, database connections). The GC only manages *managed* memory. If you hold onto an unmanaged resource, the GC cannot clean it up, so `IDisposable` (and the `using` statement) ensures deterministic cleanup via the `Dispose()` method.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
By default, when an `await` completes, the runtime attempts to resume the continuation on the original `SynchronizationContext` (e.g., the UI thread in WPF/WinForms). `ConfigureAwait(false)` tells the runtime *not* to capture or resume on the original context.
**Use it when:** You are writing library code or infrastructure code where the continuation does not need access to the original context (e.g., in ASP.NET Core services). This prevents deadlocks and improves performance by avoiding context switching overhead.
**Do NOT use it when:** You are writing UI code (e.g., in a button click handler) where the continuation *must* run back on the UI thread to safely update UI elements.

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
**Diagnosis:** The likely cause is that the `DbContext` is being treated as a Singleton (or is being reused across multiple concurrent HTTP requests). Since `DbContext` is not thread-safe, when multiple requests hit the same instance, one request might finish and dispose of the context while another request is still trying to use it, leading to `ObjectDisposedException`.
**Fix:** Ensure the `DbContext` is registered with the DI container using the **Scoped** lifetime. This guarantees that a new, isolated instance of the `DbContext` is created for every incoming HTTP request, ensuring thread safety and proper isolation.
**Interaction:** EF Core's `DbContext` is designed to be scoped. When registered as `AddDbContext<TContext>(...)`, the DI container manages its lifecycle, ensuring it is created at the start of the request scope and disposed of at the end.

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
*   **Class:** A standard reference type, mutable by default, used for complex objects with identity.
*   **Record:** A reference type designed for data modeling. It automatically provides value-based equality (two records are equal if their properties are equal, regardless of memory location) and includes built-in features like `ToString()` and immutability support.
*   **Record Struct:** A value type that combines the benefits of structs (stack allocation, value semantics) with the syntactic sugar and value equality of records.
**Choice:** Use a **Record** when the object's identity is defined by its *content* (data modeling). Use a **Class** when the object's identity is defined by its *reference* (e.g., a service or entity with complex behavior). Use a **Record Struct** for small, immutable data containers where value semantics are critical.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
All three allow passing arguments by reference, avoiding copying the entire value.
*   **`ref`:** The variable must be initialized before the method call. It allows the method to read and modify the variable.
*   **`out`:** The variable does not need to be initialized before the method call. The method *must* assign a value to it before returning. It is used to return multiple values.
*   **`in`:** Introduced in C# 7.2. It allows passing a reference to a variable, but the method is restricted to *reading* the value. It is used for performance optimization when passing large structs that should not be copied.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
**Nullable Reference Types (NRTs):** When `#nullable enable` is used, the compiler tracks whether a reference type (like `string`) is allowed to be `null`. The `?` annotation (e.g., `string?`) tells the compiler that the variable *can* be null, forcing the developer to handle the null case explicitly.
**Nullable Value Types:** (e.g., `int?`) These are value types (like `int`) that are wrapped in a struct to allow them to hold a null state. They are used when you want a value type to optionally hold a value.
**Difference:** NRTs deal with *references* (pointers to objects); nullable value types deal with *values* (the actual data).

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
LINQ (Language Integrated Query) is a set of features in C# that allows querying data from various sources (collections, databases, XML) using a unified syntax.
*   **Method Syntax:** Uses extension methods (e.g., `list.Where(x => x > 5)`). It is generally preferred for complex logic.
*   **Query Syntax:** Uses SQL-like syntax (e.g., `from x in list where x > 5`). It is often more readable for simple filtering/projection.
**Deferred Execution:** When a LINQ query is defined (e.g., `var query = list.Where(...)`), the query is not executed immediately. The query is merely compiled into an expression tree. Execution only occurs when the results are iterated over (e.g., when you call `foreach` or `.ToList()`).

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
Generic constraints restrict the types that can be used when instantiating a generic type.
*   `where T : class`: Ensures T is a reference type.
*   `where T : struct`: Ensures T is a value type.
*   `where T : new()`: Ensures T has a parameterless constructor.
*   `where T : IComparable<T>`: Ensures T implements the `IComparable<T>` interface, allowing comparison operations.
**Combining:** You combine constraints when the generic type needs to satisfy multiple requirements. For example, if you need a type that is both a reference type *and* can be compared, you would use `where T : class, IComparable<T>`.

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
*   **Abstract Class:** Can contain fields, constructors, and both implemented and unimplemented methods. It defines a base type and is used for "is-a" relationships (inheritance). A class can only inherit from one abstract class.
*   **Interface:** Defines a contract—a set of methods and properties that implementing classes must adhere to. It defines "can-do" capabilities. A class can implement multiple interfaces.
*   **Change (C# 8+):** Default interface methods allow interfaces to provide a concrete implementation for some methods. This blurs the line, allowing interfaces to provide partial implementation details, but the fundamental difference (inheritance vs. contract) remains.

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
The middleware pipeline is a sequence of software components that process HTTP requests and responses. Each component can inspect, modify, or terminate the request/response.
*   **`app.Use()`:** Registers middleware that processes the request and passes it down the pipeline (e.g., Authentication, Authorization, Routing).
*   **`app.Map()`:** Maps a specific route or set of routes to a handler, often terminating the pipeline for that route.
*   **`app.Run()`:** Terminates the pipeline and sends the response back to the client.
**Ordering:** Order is critical. Middleware placed earlier executes first (e.g., logging/authentication must run before routing).
**Exception Handling:** Exception handling middleware (e.g., `app.UseExceptionHandler()`) must be placed *early* in the pipeline so that it can catch exceptions thrown by subsequent middleware components.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
`Channel<T>` is a modern, asynchronous, and highly performant mechanism for inter-task communication, designed for producer-consumer scenarios.
**Comparison:** `BlockingCollection<T>` is a synchronous, thread-safe collection designed for blocking producers/consumers. `Channel<T>` is asynchronous and integrates seamlessly with `async/await`.
**Backpressure Example:** By using a **bounded channel** (e.g., `Channel.CreateBounded<T>(capacity)`), if the consumer is slow, the channel buffer fills up. When the buffer is full, the producer attempting to write to the channel will asynchronously block (or await) until the consumer reads an item, thus naturally applying backpressure.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
**Source Generators:** Compile-time code generators that generate new C# source code during the build process. They allow developers to write code that is then compiled into the final assembly, without needing runtime reflection or manual code generation.
**Difference:**
*   **Reflection:** Inspects types and metadata *at runtime*. Slow and requires runtime overhead.
*   **IL Weaving:** Modifies the Intermediate Language (IL) of an assembly *after* compilation. This is powerful but complex and often requires specialized tooling.
*   **Source Generators:** Generate *source code* *before* compilation, allowing the compiler to handle the resulting code naturally.
**Incremental Generator:** An incremental generator only generates code for the parts of the project that have changed since the last build. This significantly speeds up the build process, making it much faster than a standard `ISourceGenerator` which might re-run for the entire project.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
TPL Dataflow provides a set of blocks that allow you to build complex, asynchronous data processing pipelines.
*   **`BufferBlock<T>`:** Acts as a queue, buffering incoming messages.
*   **`TransformBlock<TInput, TOutput>`:** Receives an input, applies a transformation function, and outputs the result.
*   **`ActionBlock<T>`:** Receives an input and executes a side effect (an action) without returning a result.
**Comparison to Channels:** Both are used for producer-consumer patterns. TPL Dataflow is better suited for complex, multi-stage, highly structured pipelines where you need specific block types (e.g., filtering, transforming, aggregating). Channels are simpler, more flexible, and often preferred for basic, high-throughput, point-to-point asynchronous communication.

## Python (20 questions)

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**
*   **List:** Mutable, ordered sequence of items (e.g., `[1, 2, 3]`). Can be changed, appended to, or sorted.
*   **Tuple:** Immutable, ordered sequence of items (e.g., `(1, 2, 3)`). Once created, its contents cannot be changed.
*   **Set:** Mutable, unordered collection of unique items (e.g., `{1, 2, 3}`). Used for fast membership testing and set operations.
*   **Frozenset:** Immutable version of a set. Because it is immutable, it can be used as an element within another set or as a dictionary key.

**P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?**
The GIL is a mutex that protects access to Python objects, ensuring that only one thread executes Python bytecode at any given time.
**Workloads Affected:** It primarily affects CPU-bound workloads (tasks that spend most of their time performing calculations) because the GIL prevents true parallel execution of Python code across multiple CPU cores.
**Workarounds:**
1.  **Multiprocessing:** Using the `multiprocessing` module spawns separate processes, each with its own Python interpreter and GIL, allowing true parallel execution.
2.  **C Extensions:** Offloading heavy computation to libraries written in C/C++ (like NumPy), which release the GIL during intensive operations.
3.  **Asyncio:** Using asynchronous programming for I/O-bound tasks (waiting for network/disk) where the GIL is released while waiting.

**P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.**
*   **Shallow Copy (`copy.copy()`):** Creates a new container object, but populates it with *references* to the objects found in the original. If the original object contains mutable objects (like lists or dictionaries), modifying those nested objects in the copy will also modify them in the original.
*   **Deep Copy (`copy.deepcopy()`):** Creates a completely independent copy of the object and recursively copies all nested objects. The copy is entirely isolated from the original.
**Example:**
```python
original = {'a': [1, 2]}
shallow = copy.copy(original)
shallow['a'].append(3)
# Now, original['a'] is also [1, 2, 3], demonstrating shared reference.
```

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**
A decorator is a design pattern that allows you to modify or enhance a function or method without permanently changing its source code. It wraps the original function with additional logic.
**Decorator Example:**
```python
import time
from functools import wraps

def timing_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"Function {func.__name__} executed in {end_time - start_time:.4f} seconds.")
        return result
    return wrapper

@timing_decorator
def calculate_heavy_task(n):
    sum(i * i for i in range(n))
```

**P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?**
A generator is a special type of function that returns an iterator. Instead of computing and returning all results at once (like a list), a generator computes and yields results one at a time, only when requested.
**Difference from List:** Generators are memory efficient. A list must store all results in memory simultaneously. Generators produce results lazily, making them ideal for processing large datasets without memory overflow.
**`yield from`:** This statement delegates the generator's operation to another generator or iterable. It allows the current generator to yield all values produced by the sub-generator, simplifying the chaining of generator functions.

**P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?**
The **asyncio event loop** is the core mechanism that manages and runs asynchronous tasks. It monitors I/O operations (like network requests) and switches execution between tasks whenever one task is waiting for an external event, preventing the program from blocking.
*   **`asyncio.run(coro)`:** Runs the top-level coroutine and manages the event loop lifecycle.
*   **`asyncio.gather(*coros)`:** Runs multiple coroutines concurrently and waits for all of them to complete, returning a list of their results.
*   **`asyncio.create_task(coro)`:** Schedules a coroutine to run on the event loop immediately, returning a `Task` object that can be awaited later.
**`time.sleep()`:** This function is a *blocking* call. When called inside an `async` function, it halts the entire thread, including the event loop, preventing other scheduled tasks from running. Instead, you must use `await asyncio.sleep(delay)`, which is a non-blocking operation that yields control back to the event loop.

**P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**
**MRO:** MRO is the ordered list of classes Python searches through when looking for a method or attribute.
**Algorithm:** Python 3 uses the **C3 Linearization Algorithm**. This algorithm ensures a consistent, predictable, and monotonic ordering of inheritance, resolving the ambiguity of diamond inheritance.
**Diamond Inheritance:**
```python
class A:
    def who(self): return "A"
class B(A):
    pass
class C(A):
    def who(self): return "C"
class D(B, C):
    pass
print(D().who())
```
The MRO for `D` is `D -> B -> C -> A -> object`. When `D().who()` is called, Python searches the MRO:
1.  Checks `D` (no `who`).
2.  Checks `B` (no `who`).
3.  Checks `C` (has `who`, returns "C").
Python stops at the first definition found in the MRO. Therefore, it prints **"C"**.

A **metaclass** is the "class of a class." It controls how a class itself is created. When you define a class, Python calls the metaclass.
*   **Metaclass Use Case:** Implementing complex, global behavior across a hierarchy of classes (e.g., automatically registering all subclasses with a central registry, or enforcing specific API contracts on all derived classes).
*   **`__init_subclass__` Use Case:** This is a class method available since Python 3.6. It is used to perform setup *after* a subclass has been defined but *before* it is instantiated. It is simpler and less intrusive than a metaclass.
**When to use which:** Use `__init_subclass__` for simple, post-creation setup logic (e.g., logging when a subclass is defined). Use a **metaclass** when you need to fundamentally alter the class creation process itself (e.g., modifying attributes, adding methods, or changing the class structure before it exists).

**P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?**
*   **Threading:** Uses threads within a single process. Best for **I/O-bound** tasks (waiting for network/disk) because the GIL releases during I/O waits. Limited by the GIL for CPU-bound tasks.
*   **Multiprocessing:** Uses separate processes. Best for **CPU-bound** tasks, as each process has its own GIL and can run truly in parallel across multiple cores.
*   **`concurrent.futures`:** A high-level interface that provides a unified API for managing both threads (`ThreadPoolExecutor`) and processes (`ProcessPoolExecutor`). Use this for simplified, high-level concurrency management.
**Pickling Implications:** Multiprocessing requires objects to be serialized (pickled) to be passed between processes. This means that complex, non-serializable objects (like open file handles or certain custom classes without proper `__getstate__`) cannot be passed between processes.

**P10 — Medium: What is __slots__? When should you use it, and what does it prevent? What is the memory impact?**
`__slots__` is a class attribute that explicitly declares the attributes an instance of a class will have.
**What it prevents:** It prevents the creation of the instance dictionary (`__dict__`) for that class. The `__dict__` is what Python uses to store arbitrary attributes dynamically.
**When to use it:** When you are creating classes with many instances (e.g., data structures, game entities) where memory efficiency is critical.
**Memory Impact:** It significantly reduces memory consumption because Python no longer needs to allocate space for the dynamic `__dict__` for every instance.

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?**
These are concise, elegant ways to create collections based on existing iterables.
*   **List Comp:** `[x*2 for x in data]`
*   **Dict Comp:** `{k: v*2 for k, v in data.items()}`
*   **Set Comp:** `{x for x in data if x > 0}`

*   `[f(x) for x in data]` is equivalent to `list(map(f, data))`.

**P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?**
*   **`==` (Equality):** Checks if the *values* of two objects are equal (i.e., they have the same content). This calls the `__eq__` method.
*   **`is` (Identity):** Checks if two variables point to the *exact same object* in memory (i.e., they have the same memory address). This checks if `id(a) == id(b)`.
**Object Interning:** Interning is an optimization where Python pre-allocates and caches certain immutable objects (like small integers, short strings) in memory. When the interpreter encounters a request for that object again, it returns the cached reference instead of creating a new one.
**Small Integers:** Python interns integers in the range of -5 to 256. Therefore, `a = 100` and `b = 100` will often point to the same cached object, causing `a is b` to return `True`.

**P14 — Easy: Explain Python's *args and **kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?**
*   **`*args`:** Collects an arbitrary number of positional arguments into a tuple.
*   **`**kwargs`:** Collects an arbitrary number of keyword arguments into a dictionary.
*   **Positional-Only (`/`):** Arguments listed before `/` *must* be passed by position and cannot be passed using a keyword.
*   **Keyword-Only (`*`):** Arguments listed after `*` *must* be passed using a keyword, even if they are positional.
**Example:** `def func(a, b, /, c, *, d):`
*   `a` and `b` must be positional.
*   `c` can be positional or keyword.
*   `d` must be keyword.

**P15 — Easy: What are context managers (with statement)? How do you write one using __enter__/__exit__ vs @contextmanager? Give an example beyond file handling.**
A context manager is an object that defines the runtime context to be used when executing a block of code. It guarantees that setup and teardown actions (like resource cleanup) are performed, even if errors occur.
*   **`__enter__`:** Called upon entering the `with` block (setup). Returns the resource/context.
*   **`__exit__`:** Called upon exiting the `with` block (teardown). Handles cleanup.
*   **`@contextmanager`:** A simpler generator-based approach (from `contextlib`) that achieves the same goal. The code before `yield` is the setup (`__enter__`), and the code after `yield` is the teardown (`__exit__`).
**Example (Database Session):**
```python
from contextlib import contextmanager
@contextmanager
def db_session(connection):
    cursor = connection.cursor()
    try:
        yield cursor # The resource yielded
    finally:
        cursor.close() # Teardown
```

**P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How does mypy or pyright use these for static analysis?**
Type hinting is the practice of adding type annotations to variables, function arguments, and return values, making code more readable and allowing static analysis tools to catch errors before runtime.
*   **`typing.Union[A, B]`:** Indicates a variable can be of type A *or* type B.
*   **`typing.Optional[T]`:** Shorthand for `Union[T, None]`. Indicates a variable can be T or None.
*   **`typing.Literal[value]`:** Restricts a variable to only one specific literal value (e.g., `Literal["high", "low"]`).
*   **`typing.TypeVar`:** Used to define generic types, allowing functions to work with arbitrary types while maintaining type safety.
*   **`typing.Protocol`:** Defines a structural contract (duck typing) that a class must adhere to, even if it doesn't explicitly inherit from the protocol.
**Static Analysis:** Tools like Mypy or Pyright read these hints and check if the code adheres to the declared types. If you try to pass a string where an integer is expected, the tool will raise an error *before* you run the code.

**P17 — Medium: Explain Python's data model (dunder methods). What are __repr__ vs __str__, __eq__ vs __hash__, and __getattr__ vs __getattribute__? What happens if you define __eq__ but not __hash__?**
Dunder methods (double underscore) are special methods that define how objects interact with Python's built-in operators and functions.
*   **`__repr__` vs `__str__`:** `__repr__` (representation) is the unambiguous, official string representation, often used for debugging (e.g., `repr(obj)`). `__str__` (string) is the informal, user-friendly string representation (e.g., `print(obj)`).
*   **`__eq__` vs `__hash__`:** `__eq__` defines value equality (`a == b`). `__hash__` defines how the object is mapped to an integer for use in hash-based collections (like sets or dict keys).
**`__eq__` without `__hash__`:** If you define `__eq__` but not `__hash__`, Python will typically assign a default hash based on the object's identity (`id()`). However, if you override `__eq__` to define custom equality, you *must* override `__hash__` to ensure that equal objects hash to the same value. If you fail to do this, the object may behave unpredictably or fail to function correctly in sets/dictionaries.

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (__get__, __set__, __delete__). How do property, classmethod, and staticmethod use descriptors under the hood?**
A **descriptor** is an object that defines how attribute access (getting, setting, or deleting) works for another object. It intercepts attribute access.
**Descriptor Protocol:**
*   `__get__(self, instance, owner)`: Called when the attribute is retrieved.
*   `__set__(self, instance, value)`: Called when the attribute is assigned a value.
*   `__delete__(self, instance)`: Called when the attribute is deleted.
**Built-in Methods:**
*   **`property`:** Uses descriptors to allow attribute access (e.g., `obj.age`) while running custom logic (like validation) behind the scenes.
*   **`classmethod`:** Uses descriptors to ensure the method is bound to the class, not the instance.
*   **`staticmethod`:** Uses descriptors to ensure the method is unbound and accessed directly via the class, behaving like a regular function.

**P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, __init__.py, and namespace packages work? What is a finder and a loader?**
The import system is responsible for locating and loading modules.
*   **`sys.path`:** A list of directories Python searches when an `import` statement is executed.
*   **`PYTHONPATH`:** An environment variable that adds directories to `sys.path`.
*   **`__init__.py`:** Historically, this file marked a directory as a Python package, allowing imports from that directory.
*   **Namespace Packages:** A modern feature (Python 3.3+) that allows packages to be split across multiple directories without requiring an `__init__.py` file, enabling large, distributed packages.
**Relative vs. Absolute:**
*   **Absolute:** Imports start from the root of the project (e.g., `import my_package.module`).
*   **Relative:** Imports start from the current package location (e.g., `from . import sibling_module`).
**Finder and Loader:**
*   **Finder:** The component responsible for *finding* the module (i.e., determining where the module file is located on disk).
*   **Loader:** The component responsible for *loading* the module (i.e., executing the code and making it available in memory).

**P20 — Hard: What are dataclasses and how does it compare to attrs and Pydantic? Explain __post_init__, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**
**Dataclasses:** A decorator (`@dataclass`) that automatically generates boilerplate methods (like `__init__`, `__repr__`, `__eq__`) for classes intended primarily to hold data.
**Comparison:**
*   **`attrs`:** Similar to dataclasses, but often more flexible and powerful, especially in older Python versions.
*   **Pydantic:** A data validation library. It not only holds data but also enforces strict type constraints and performs runtime validation (e.g., ensuring an email string is correctly formatted).
**Features:**
*   **`__post_init__`:** A method called immediately after `__init__` finishes, allowing for post-initialization logic (e.g., calculating a derived field).
*   **Field Factories:** Allows defining default values that are computed dynamically rather than being static constants.
*   **Frozen Dataclasses:** Using `frozen=True` makes the instance immutable, preventing attribute modification after creation.
**Inheritance:** Dataclasses support inheritance, but the generated methods must handle the parent class's attributes correctly.
**When to choose Pydantic:** Choose Pydantic when you need **runtime data validation** (e.g., API input parsing, configuration loading) and strict schema enforcement. Choose dataclasses when you need simple, lightweight, memory-efficient data containers where validation is handled elsewhere.
