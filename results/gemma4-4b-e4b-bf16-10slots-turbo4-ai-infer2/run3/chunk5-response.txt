## .NET / C# Answers

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
DN1: A `class` is a reference type, meaning it is allocated on the heap, and variables hold a reference (pointer) to the data. A `struct` is a value type, meaning its data is stored directly where it is declared (on the stack or inline within another object). You should use a `struct` when the type is small (typically less than 16 bytes), immutable, and represents a single value (e.g., a point, a color, or a coordinate).

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
DN2: `IEnumerable<T>` represents a sequence of data and is typically used for in-memory collections. It executes the query *after* the data has been retrieved. `IQueryable<T>` represents an expression tree that describes the query structure. This expression tree is passed to the data provider (like Entity Framework Core), allowing the provider to translate the query into optimized SQL and execute it *on the database server*. This distinction is critical because using `IQueryable<T>` allows filtering and projection to happen at the database level, drastically reducing network traffic and memory usage.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
DN3: `async/await` is syntactic sugar built on top of the `Task` abstraction. When an `await` keyword is encountered, the method execution is suspended, and control is returned to the caller. The continuation (the code after `await`) is scheduled to run when the awaited operation completes. A `Task` represents an asynchronous operation that might or might not have completed. A `ValueTask<T>` is a struct optimization for scenarios where the operation is often synchronous or completes quickly. You should use `ValueTask<T>` when the operation is frequently synchronous or when the overhead of allocating a heap-allocated `Task` object would be unnecessary.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
DN4: Dependency Injection (DI) is a design pattern where components receive their dependencies from an external source (the IoC container) rather than creating them internally. The three lifetimes are:
1. **Transient:** A new instance is created every time it is requested.
2. **Scoped:** A single instance is created once per scope (e.g., once per HTTP request in ASP.NET Core).
3. **Singleton:** A single instance is created once for the entire application lifetime.
The common bug is injecting a `Scoped` service (like `DbContext`) into a `Singleton` service. Since the Singleton lives for the entire application lifetime, it holds onto the Scoped service instance, potentially causing the service to be used across multiple unrelated HTTP requests, violating the scope boundary and leading to concurrency issues or incorrect state.

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
DN5: `string` is an immutable, heap-allocated reference type. `ReadOnlySpan<char>` is a stack-allocated, lightweight, non-allocating view over a contiguous sequence of characters (like a string or a character array). You use `Span<T>` (or `ReadOnlySpan<T>`) when you need to perform high-performance string or buffer manipulation without creating new memory allocations. This is crucial in high-throughput scenarios (like parsing network packets or processing large log files) where minimizing GC pressure is paramount.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
DN6: The GC is a generational collector that attempts to reclaim memory by identifying and removing unreachable objects.
*   **Gen 0:** New objects are allocated here. Frequent, fast collections occur here.
*   **Gen 1:** Objects that survive a Gen 0 collection are promoted here.
*   **Gen 2:** Long-lived objects that survive Gen 1 collections are promoted here. Collections here are less frequent but more expensive.
The **Large Object Heap (LOH)** is a separate area for objects larger than a certain threshold (typically 85KB).
`IDisposable` is needed for **deterministic cleanup**. While the GC handles memory deallocation, it cannot guarantee *when* it will run. `IDisposable` allows you to implement the `Dispose()` method to explicitly release unmanaged resources (like file handles, database connections, or network sockets) immediately, preventing resource leaks, regardless of the GC schedule.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
DN7: By default, when an `await` operation completes, the runtime attempts to resume the continuation on the original `SynchronizationContext` (e.g., the UI thread or the ASP.NET request thread). `ConfigureAwait(false)` tells the runtime that the continuation does *not* need to resume on the original context.
*   **Use it when:** You are writing library code or infrastructure components where you do not need to interact with the specific context (e.g., in a service layer or data access layer). This prevents deadlocks and improves performance by avoiding context switching overhead.
*   **Do NOT use it when:** You are writing UI code (WPF, WinForms) or code that relies on specific UI thread access. If you use `ConfigureAwait(false)` in UI code, the continuation might fail because it won't be able to marshal back to the UI thread.

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
DN9: **Diagnosis:** The likely cause is that the `DbContext` is being treated as a Singleton (or is being reused across multiple concurrent requests/threads). Since `DbContext` manages connections and state, reusing it across concurrent requests leads to race conditions, where one request might dispose of the context while another is still using it, resulting in `ObjectDisposedException`.
**Fix:** Ensure the `DbContext` is registered with a **Scoped** lifetime in the DI container. This guarantees that a new, isolated instance of the `DbContext` is provided for the duration of each incoming HTTP request.
**Interaction:** EF Core's `DbContext` is designed to be request-scoped. When registered as Scoped, the DI container ensures that every incoming request receives its own unique instance, maintaining transactional isolation and preventing concurrent state corruption.

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
DN10:
*   **Class:** A reference type, mutable by default, designed for complex behavior and identity.
*   **Record:** A reference type, designed for data modeling (DTOs). Records automatically provide value equality (equality is based on the *content* of the properties, not the memory address).
*   **Record Struct:** A value type that benefits from the automatic value equality of records while maintaining the performance characteristics of a struct.
**Choice:**
*   Use **Class** when the object has complex behavior, mutable state, or needs to be treated as a unique entity (identity).
*   Use **Record** when the object is a simple data carrier (DTO) and you want equality checks based on its properties.
*   Use **Record Struct** when you need the immutability and value equality of a record, but require the stack allocation and performance of a struct.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
DN11: All three allow passing arguments by reference, but they differ in usage:
*   **`ref`:** The variable must be initialized before the method call. It allows the method to read and modify the variable. Used when the caller needs to pass an existing variable to be modified.
*   **`out`:** The variable does *not* need to be initialized before the method call. The method is responsible for assigning a value to it. Used when the method needs to return multiple values via parameters.
*   **`in`:** The variable must be initialized. It allows the method to read the variable but prevents modification. Used for passing large structs efficiently to avoid copying, ensuring the method cannot change the original data.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
DN12: Nullable Reference Types (NRTs) are a compile-time safety feature introduced in C# 8. They use the `?` annotation (e.g., `string?`) to explicitly tell the compiler that a reference type might be null. This helps prevent `NullReferenceException` at compile time.
*   **Difference from `int?`:** `int?` is a nullable *value type* (it is a struct wrapper around `int` that can hold `null`). NRTs apply to *reference types* (classes, interfaces, strings). NRTs are about compile-time null safety; `int?` is about allowing a value type to represent the absence of a value.

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
DN13: LINQ (Language Integrated Query) is a set of features in C# that allows developers to write queries against various data sources (in-memory collections, databases, XML, etc.) using a unified syntax.
*   **Method Syntax:** Uses lambda expressions and extension methods (e.g., `list.Where(x => x.Age > 30)`). This is generally preferred in modern C# as it is more concise and functional.
*   **Query Syntax:** Uses SQL-like syntax (e.g., `from x in list where x.Age > 30`). This is often more readable for developers coming from SQL backgrounds.
**Deferred Execution:** When using LINQ, the query is not executed immediately. Instead, it returns an `IEnumerable<T>` (or `IQueryable<T>`). The query is only executed when the results are iterated over (e.g., when you call `ToList()`, `ToArray()`, or loop through the collection).

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
DN14: Generic constraints restrict the types that can be used when instantiating a generic class or method, ensuring that the type `T` supports certain operations.
*   `where T : class`: T must be a reference type.
*   `where T : struct`: T must be a value type.
*   `where T : new()`: T must have a parameterless constructor.
*   `where T : IComparable<T>`: T must implement the `IComparable<T>` interface, allowing comparison operations.
You combine multiple constraints (e.g., `where T : class, new(), IComparable<T>`) when the generic type needs to satisfy multiple requirements simultaneously (e.g., it must be a class, it must be instantiable, and it must be comparable).

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
DN15:
*   **Interface:** Defines a contract—a set of methods and properties that implementing classes *must* adhere to. It specifies *what* a class can do, but not *how*. A class can implement multiple interfaces.
*   **Abstract Class:** A partial class that can contain both implemented methods and abstract methods. It defines a base implementation and can share common code among derived classes. A class can only inherit from one abstract class.
**Change with Default Interface Methods (C# 8+):** Default interface methods allow interfaces to provide a concrete implementation for some methods. This blurs the line by allowing interfaces to contain logic, making them more powerful and sometimes replacing the need for simple abstract base classes, especially for defining common behaviors without forcing a specific implementation.

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
DN16: The middleware pipeline is a series of components that process HTTP requests sequentially. Each middleware component inspects the request, performs some action (logging, authentication, routing), and then either passes the request to the next component or terminates the request and sends a response.
*   **`app.Use()`:** Used for general processing middleware (e.g., `UseAuthentication()`, `UseRouting()`, `UseCors()`). It processes the request and typically calls `next()` to pass control down the pipeline.
*   **`app.Map()`:** Used to map specific endpoints or routes to handlers (e.g., `app.MapGet("/hello", ...)`). It terminates the pipeline for that specific route.
*   **`app.Run()`:** Terminates the pipeline. It is typically the last piece of middleware and sends the final response back to the client.
**Ordering:** Ordering is critical. For example, authentication middleware must run *before* authorization middleware, which must run *before* routing.
**Exception Handling:** Exception handling middleware (e.g., `UseExceptionHandler()`) must be placed early in the pipeline. If an error occurs in a later middleware, the exception is caught by the handler, which then formats and sends a standardized error response instead of letting the server crash.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
DN17: `Channel<T>` is a modern, asynchronous, and highly efficient mechanism for communication between asynchronous producers and consumers in .NET. It is designed for concurrent, non-blocking data transfer.
*   **Comparison to `BlockingCollection<T>`:** `BlockingCollection<T>` is older, synchronous, and relies on blocking threads when waiting for data. `Channel<T>` is asynchronous, non-blocking, and integrates seamlessly with `async/await`.
**Bounded Channel Example (Backpressure):**
A bounded channel limits the maximum number of items that can be buffered. If the channel is full, the producer attempting to write (`await channel.Writer.WriteAsync(item)`) will asynchronously block until a consumer reads an item, freeing up space. This mechanism naturally applies **backpressure**, preventing the producer from overwhelming the consumer.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
DN18: Source Generators are compile-time code generators. They analyze the source code during compilation and generate new C# source files that are then compiled alongside the original code.
*   **Difference from Reflection:** Reflection is a runtime mechanism that inspects types and members *at runtime*. Source Generators operate *at compile time*, generating code before runtime, leading to zero runtime overhead.
*   **Difference from IL Weaving:** IL Weaving (e.g., PostSharp) modifies the Intermediate Language (IL) of compiled assemblies *after* compilation. Source Generators modify the source code itself, which is generally safer and more transparent.
**Incremental Generator:** An incremental generator is a specialized type of source generator that only runs when the specific files it depends on have changed. This drastically improves build times, as the compiler doesn't need to re-run the generator for the entire project on every minor change. This is preferred over the base `ISourceGenerator` because it provides highly efficient incremental compilation.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
DN19: TPL Dataflow is a library for building concurrent, asynchronous data processing pipelines. It allows developers to chain blocks that process data items sequentially through a pipeline.
*   **`BufferBlock<T>`:** Acts as a queue. It buffers incoming items until a consumer is ready to process them.
*   **`TransformBlock<TInput, TOutput>`:** Takes an input item, applies a transformation function to it, and outputs the result.
*   **`ActionBlock<T>`:** Executes an action (a method call) on an input item without producing an output.
**Comparison to Channels:**
*   **TPL Dataflow:** Is designed for complex, multi-stage, highly configurable pipelines where you need to control concurrency levels, parallelism, and flow control between stages. It is more complex but offers more control over the pipeline structure.
*   **Channels:** Is simpler, focusing primarily on safe, asynchronous communication between two points (producer $\rightarrow$ consumer). It is excellent for simple backpressure scenarios but less suited for complex, multi-stage transformations.

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**
DN20: Minimal APIs are a lightweight, streamlined way to build APIs in .NET using lambda expressions and minimal boilerplate code, typically defined directly in `Program.cs`.
*   **Difference from Controllers:** Controller-based APIs use classes, attributes, and MVC conventions. Minimal APIs use direct endpoint mapping (`app.MapGet("/users", ...)`), eliminating the need for controllers, action methods, and routing attributes.
*   **Trade-offs:**
    *   **Testability:** Minimal APIs can be slightly harder to test in isolation because they are often tightly coupled to the `WebApplication` host setup.
    *   **Middleware:** Middleware integration is very straightforward and explicit.
    *   **OpenAPI Support:** Requires explicit configuration (e.g., using Swashbuckle) to generate OpenAPI documentation, whereas controllers often benefit from built-in conventions.
*   **Route Groups and Endpoint Filters:**
    *   **Route Groups:** Allow grouping related endpoints under a common prefix or applying common middleware/filters to a set of routes (e.g., `/api/v1/users`).
    *   **Endpoint Filters:** Allow you to inject logic (like authorization checks or model validation) that runs before or after an endpoint is executed, without cluttering the endpoint lambda itself.

## Python Answers

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**
P1:
*   **List vs. Tuple:** Lists (`[]`) are mutable (can be changed, appended to, or sorted after creation). Tuples (`()`) are immutable (cannot be changed after creation). Tuples are generally faster and safer for data that should not change.
*   **Set vs. Frozenset:** Sets (`{}`) are mutable collections of unique, hashable items. Frozensets are immutable versions of sets. They can be used as elements within other sets or as dictionary keys because they are hashable.

**P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?**
P2: The GIL is a mutex (lock) that ensures only one thread executes Python bytecode at any given time, even on multi-core systems.
*   **Workloads Affected:** CPU-bound tasks (tasks that spend most of their time performing calculations, like heavy mathematical processing). The GIL prevents true parallel execution of Python code across multiple cores.
*   **Workarounds:**
    1.  **Multiprocessing:** Using the `multiprocessing` module spawns separate processes, each with its own Python interpreter and its own GIL, allowing true parallel execution of CPU-bound tasks.
    2.  **I/O-bound tasks:** For tasks that spend most of their time waiting (e.g., network requests, file I/O), `threading` or `asyncio` is effective because the thread releases the GIL while waiting for I/O operations to complete.

**P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.**
P3:
*   **Shallow Copy (`.copy()`):** Creates a new container object, but it populates the new container with references to the *same* objects found in the original container. If the original object contains mutable objects (like lists or dictionaries), modifying those nested objects in the copy will also modify them in the original.
*   **Deep Copy (`copy.deepcopy()`):** Creates a completely independent copy of the original object and recursively copies all nested objects.
**Example:**
```python
original = {'a': [1]}
shallow = original.copy()
shallow['a'].append(2) # Modifies the list object referenced by both
print(original['a']) # Output: [1, 2] -> Unexpected behavior
```

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**
P4: Decorators are syntactic sugar that allow you to wrap a function or class, modifying or enhancing its behavior without permanently changing its source code. They are essentially functions that take another function as input and return a new, modified function.
**Example:**
```python
import time
from functools import wraps

def timing_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"Function {func.__name__} executed in {end_time - start_time:.4f} seconds.")
        return result
    return wrapper

@timing_decorator
def calculate_heavy_stuff(n):
    return sum(i * i for i in range(n))

calculate_heavy_stuff(1000000)
```

**P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?**
P5:
*   **Generators:** Functions that use the `yield` keyword instead of `return`. Instead of computing and returning all results at once, a generator pauses its execution state after yielding a value and saves its state. When the next value is requested, it resumes exactly where it left off.
*   **Difference from List:** Returning a list computes and stores *all* results in memory immediately. A generator produces results *lazily* (on demand), which is highly memory efficient for large sequences.
*   **`yield from`:** Used to delegate iteration to a sub-generator. It allows a generator to yield all values produced by another generator or iterable, simplifying the chaining of generators.

**P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?**
P6:
*   **Event Loop:** The core mechanism of `asyncio`. It is a single-threaded loop that manages and schedules concurrent tasks. When one task encounters an I/O wait (e.g., waiting for a network response), it yields control back to the event loop, which then switches context to run another ready task, achieving concurrency without needing multiple threads.
*   **`asyncio.run(coro)`:** Runs the top-level coroutine and manages the event loop lifecycle (starts, runs, and shuts down the loop).
*   **`asyncio.gather(*coros)`:** Runs multiple coroutines concurrently and waits for all of them to complete, returning a list of their results.
*   **`asyncio.create_task(coro)`:** Schedules a coroutine to run concurrently in the background immediately, returning a `Task` object that can be awaited later.
*   **Why `time.sleep()` fails:** `time.sleep()` is a blocking function. If called inside an `async` function, it blocks the entire thread, halting the event loop and preventing *all* other concurrent tasks from running until the sleep is over, defeating the purpose of `asyncio`. You must use `await asyncio.sleep()`.

**P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**
P7:
*   **MRO:** The order in which Python searches for a method or attribute in a class hierarchy.
*   **Algorithm:** Python 3 uses the C3 Linearization algorithm. This algorithm ensures that the MRO is consistent, deterministic, and respects the principle of local precedence (a class is checked before its parents).
*   **Diamond Inheritance:** When a class inherits from two parents that share a common ancestor (the diamond shape), the MRO determines which parent's method is called.
*   **Execution:**
    ```python
    # D inherits from B and C. B inherits A. C inherits A.
    # MRO for D: D -> B -> C -> A -> object
    # When D().who() is called, Python checks D, then B, then C.
    # The method 'who' is found in C first, so C's implementation is executed.
    ```

**P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.**
P8:
*   **Metaclass:** A class whose instances are classes. It controls the creation of classes. When you define a class, Python calls its metaclass's `__new__` method. Metaclasses allow you to hook into the class creation process to modify or enforce structure on *all* subclasses.
*   **`__init_subclass__`:** A class method that is called *after* a subclass has been created. It is used for runtime configuration or modification of the subclass instance.
*   **Comparison:**
    *   **Metaclass:** Used when you need to change *how* the class is constructed (e.g., automatically adding attributes, enforcing API structure) *before* the class object exists.
    *   **`__init_subclass__`:** Used when you need to perform setup or validation *after* the class object has been created.
*   **Use Case:**
    *   **Metaclass:** Creating an ORM layer where all models must automatically register themselves with a central registry upon definition.
    *   **`__init_subclass__`:** Automatically setting a default configuration value for all subclasses of a base configuration class.

**P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What is the serialization implications of multiprocessing (pickling)?**
P9:
*   **Threading:** Uses threads within a single process. Best for **I/O-bound** tasks (waiting for network/disk) because the GIL is released during I/O waits.
*   **Multiprocessing:** Uses separate processes. Best for **CPU-bound** tasks because each process has its own GIL, allowing true parallel execution across multiple cores.
*   **`concurrent.futures`:** A high-level interface (using `ThreadPoolExecutor` or `ProcessPoolExecutor`) that abstracts the complexity of managing threads/processes, making it easier to submit tasks and retrieve results.
*   **Serialization (Pickling):** Since processes are isolated, data passed between them must be serialized (pickled) and deserialized. This process adds overhead and requires that all objects passed between processes be picklable.

**P10 — Medium: What is __slots__? When should you use it, and what does it prevent? What is the memory impact?**
P10: `__slots__` is a class attribute that tells Python not to use a standard instance dictionary (`__dict__`) for storing instance attributes. Instead, it uses a fixed, optimized structure based on the attributes listed in `__slots__`.
*   **When to use:** When creating classes that are instantiated millions of times (e.g., data points, nodes in a graph) and memory efficiency is critical.
*   **What it prevents:** It prevents the creation of the dynamic `__dict__` for each instance, which is a significant memory overhead.
*   **Memory Impact:** It drastically reduces memory consumption per instance, as the memory footprint is fixed and optimized.

**P11 — Easy: What is a virtual environment, and why should you use one? What is the difference between venv, virtualenv, and conda?**
P11: A virtual environment is an isolated directory that contains a specific Python interpreter and its own set of installed packages.
*   **Why use it:** It prevents dependency conflicts. It ensures that a project's dependencies (e.g., Django 3.0) do not conflict with another project's dependencies (e.g., Django 4.0), keeping the global Python installation clean and reproducible.
*   **Differences:**
    *   **`venv`:** The standard, built-in module in Python 3. Used for creating lightweight, standard virtual environments.

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?**
P12: These comprehensions provide a concise, readable, and often faster way to create new collections based on existing iterables.
*   **List Comp:** `[x*2 for x in data if x > 5]`
*   **Dict Comp:** `{k: v*2 for k, v in data.items()}`
*   **Set Comp:** `{x*2 for x in data}`
*   **Relation to `map()`/`filter()`:** Comprehensions are syntactic sugar that combine the functionality of `map()` (transformation) and `filter()` (selection) into a single, readable line.
*   **Preference:** Comprehensions are generally preferred in Python because they are more idiomatic, often faster, and more readable than chaining `map()` and `filter()` calls.

**P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?**
P13:
*   **`==` (Equality):** Checks for *value equality*. It calls the `__eq__` method to determine if the contents of two objects are the same.
*   **`is` (Identity):** Checks for *object identity*. It checks if two variables point to the exact same object in memory (i.e., if they have the same `id()`).
*   **Object Interning:** A memory optimization technique where Python pre-allocates and caches certain immutable objects (like small integers, short strings) to save memory and speed up comparisons.
*   **Small Integers:** Python often "interns" integers in the range of -5 to 256. When you write `a = 10` and `b = 10`, Python often points both `a` and `b` to the same cached object, so `a is b` returns `True`. This is not guaranteed for larger integers.

**P14 — Easy: Explain Python's *args and **kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?**
P14:
*   **`*args`:** Allows a function to accept an arbitrary number of positional arguments. Inside the function, `args` is a tuple containing all the extra positional arguments.
*   **`**kwargs`:** Allows a function to accept an arbitrary number of keyword arguments. Inside the function, `kwargs` is a dictionary containing the extra keyword arguments.
*   **Positional-Only (`/`):** Arguments listed before `/` must be passed by position and cannot be passed using a keyword (e.g., `def func(a, /):`).
*   **Keyword-Only (`*`):** Arguments listed after `*` must be passed using their keyword name, even if they are positional (e.g., `def func(*, b):`).

**P15 — Easy: What are context managers (with statement)? How do you write one using __enter__/__exit__ vs @contextmanager? Give an example beyond file handling.**
P15: A context manager is an object that defines the runtime context to be established when executing a block of code. The `with` statement ensures that setup logic runs before the block, and guaranteed cleanup logic runs afterward, even if errors occur.
*   **`__enter__` / `__exit__`:** The standard way. `__enter__` runs setup and returns the resource. `__exit__` runs cleanup (receiving exception details if an error occurred).
*   **`@contextmanager`:** A simpler, generator-based way (from `contextlib`). The code before `yield` is setup, and the code after `yield` is cleanup.
*   **Example (Database Connection Pool):** Managing a connection to a database.
    ```python
    # Using context manager
    with db_pool.get_connection() as conn:
        conn.execute("SELECT * FROM users")
    # Connection is automatically returned to the pool here
    ```

**P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How does mypy or pyright use these for static analysis?**
P16: Type hinting (PEP 484) is a way to optionally add type annotations to code, making the code more readable and allowing external tools to perform static analysis.
*   **`typing.Union[A, B]`:** Indicates a variable can be of type A or type B.
*   **`typing.Optional[T]`:** A shorthand for `Union[T, None]`, indicating the variable can be type T or None.
*   **`typing.Literal[A, B]`:** Restricts a variable to only one of a specific set of literal values (e.g., `Literal["high", "low"]`).
*   **`typing.TypeVar`:** Used to define generic types, allowing functions to work with types while maintaining type safety (similar to generics in C#).
*   **`typing.Protocol`:** Defines a structural contract (like an interface) based on the methods and attributes a class must possess, regardless of explicit inheritance.
*   **Static Analysis:** Tools like Mypy or Pyright read these hints and check the code *before* execution. They ensure that operations are only performed on variables of the expected type, catching potential type errors (e.g., trying to call a string method on an integer) without running the code.

**P17 — Medium: Explain Python's data model (dunder methods). What are __repr__ vs __str__, __eq__ vs __hash__, and __getattr__ vs __getattribute__? What happens if you define __eq__ but not __hash__?**
P17: Dunder methods (double underscore methods) are special methods that Python calls automatically when certain operations occur (e.g., `len(obj)` calls `__len__`).
*   **`__repr__` vs `__str__`:** `__repr__` (representation) should return an unambiguous string that ideally allows the object to be recreated (e.g., `ClassName(attr=value)`). `__str__` (string) returns a human-readable, user-friendly string.
*   **`__eq__` vs `__hash__`:** `__eq__` defines value equality. `__hash__` defines how an object is mapped to an integer for use in sets or dictionary keys.
*   **`__getattr__` vs `__getattribute__`:** `__getattr__` is called only when an attribute is *not* found normally. `__getattribute__` is called for *every* attribute access, making it powerful but dangerous if not implemented carefully.
*   **Consequence of missing `__hash__`:** If you define `__eq__` (meaning two objects are equal by value), but do not define `__hash__`, Python will raise a `TypeError` if you try to use that object as a key in a dictionary or add it to a set, because the object cannot be reliably hashed.

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (__get__, __set__, __delete__). How do property, classmethod, and staticmethod use descriptors under the hood?**
P18: A descriptor is an object that defines how attribute access (getting, setting, or deleting) works for another object. They allow you to intercept attribute access.
*   **Descriptor Protocol:** An object is a descriptor if it implements one or more of three methods:
    *   `__get__(self, instance, owner)`: Called when the attribute is retrieved.
    *   `__set__(self, instance, value)`: Called when the attribute is assigned a value.
    *   `__delete__(self, instance)`: Called when the attribute is deleted.
*   **Built-in Methods:** `property`, `classmethod`, and `staticmethod` are all implemented using descriptors.
    *   **`property`:** Uses descriptors to allow attribute access (e.g., `obj.attr`) while executing custom getter/setter logic.
    *   **`classmethod`:** Uses a descriptor to ensure the method is bound to the class, not the instance.
    *   **`staticmethod`:** Uses a descriptor to ensure the method is bound neither to the class nor the instance, behaving like a regular function.

**P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, __init__.py, and namespace packages work? What is a finder and a loader?**
P19: The import system is responsible for locating and loading modules (Python files).
*   **`sys.path`:** A list of directories that Python searches when an `import` statement is executed.
*   **`PYTHONPATH`:** An environment variable that adds directories to `sys.path`.
*   **Absolute vs. Relative Imports:**
    *   **Absolute:** Imports start from the root of the package (e.g., `import mypackage.module`).
    *   **Relative:** Imports reference modules relative to the current package (e.g., `from . import module`).
*   **`__init__.py`:** Historically, this file marked a directory as a Python package. While optional in modern Python (3.3+), it is still used for package initialization.
*   **Namespace Packages:** Packages that do not require an `__init__.py` and allow multiple, independent packages to contribute to the same namespace (e.g., `google.cloud`).
*   **Finder and Loader:** A **Finder** is responsible for locating the module (finding the file path). A **Loader** is responsible for loading the module once the path is found.

**P20 — Hard: What is dataclasses and how does it compare to attrs and Pydantic? Explain __post_init__, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**
P20:
*   **Dataclasses:** A standard library feature (Python 3.7+) that automatically generates boilerplate methods (`__init__`, `__repr__`, `__eq__`, etc.) for classes primarily used to hold data.
*   **Comparison:**
    *   **`attrs`:** A third-party library that predates dataclasses and offers similar functionality, often with more customization options.
    *   **Pydantic:** A library focused on data validation and parsing. It uses type hints to enforce data structure and automatically validates incoming data (e.g., JSON payloads) against a schema.
*   **Features:**
    *   **`__post_init__`:** A method called immediately after the standard `__init__` method runs, allowing for post-initialization logic (e.g., calculating a derived field).
    *   **Field Factories:** Functions used within the class definition to provide default values or perform complex logic when defining a field.
    *   **Frozen Dataclasses:** Using `frozen=True` makes the dataclass immutable, preventing attribute modification after creation.
    *   **Inheritance:** Dataclasses support inheritance, but you must be careful to manage the generated methods correctly.
*   **When to choose Pydantic:** Choose Pydantic when the primary requirement is **data validation and parsing** (e.g., validating user input from an API request). Choose dataclasses when the primary requirement is **simple, lightweight data storage** without complex runtime validation logic.
