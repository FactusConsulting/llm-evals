## Networking

**N1** — A Layer 2 switch operates at the Data Link Layer (L2) and uses MAC addresses to forward frames between ports within the same broadcast domain. A Layer 3 switch operates at the Network Layer (L3) and can route packets between different subnets using IP addresses, effectively combining the functions of a switch and a router.

**N2** — The IP is 10.0.5.37/20.
*   The subnet mask for /20 is 255.255.240.0.
*   The network address is the starting address of the block: **10.0.32.0**.
*   The broadcast address is the last address of the block: **10.0.39.255**.

**N3** — The TCP three-way handshake establishes a reliable connection:
1.  **SYN (Synchronize):** Client sends a SYN packet to the server, proposing an initial sequence number (ISN).
2.  **SYN-ACK (Synchronize-Acknowledge):** Server receives the SYN, allocates resources, and replies with a SYN-ACK, acknowledging the client's ISN and proposing its own.
3.  **ACK (Acknowledge):** Client receives the SYN-ACK and sends a final ACK, acknowledging the server's ISN.
If the final ACK is lost, the connection remains in a half-open state on the server side. The server will wait for a timeout period before eventually dropping the connection, but the client will typically retransmit the ACK, eventually leading to a timeout or successful connection establishment if the ACK is resent.

**N4** — **SNAT (Source Network Address Translation):** Changes the source IP address of a packet as it leaves a private network, replacing it with a public IP address. *Example:* A laptop (192.168.1.10) accessing the internet uses the router's public IP (203.0.113.5) as its source address.
**DNAT (Destination Network Address Translation):** Changes the destination IP address of a packet as it enters a private network, redirecting it to an internal host. *Example:* An external user accessing a web server uses the router's public IP (203.0.113.5) as the destination, but the router translates it to the internal server's private IP (192.168.1.50).

**N5** — Possible causes for `SSL: certificate subject name does not match target host name`:
1.  **Incorrect DNS Resolution:** The hostname used in the browser does not resolve to the IP address that holds the certificate.
2.  **Misconfigured Certificate:** The certificate was issued for a different hostname (e.g., `api.example.com`) but the user is accessing a different one (e.g., `www.example.com`).
3.  **Man-in-the-Middle (MITM) Attack:** An attacker is intercepting traffic and presenting a fraudulent certificate.

**N6** — **VLAN (Virtual LAN):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains based on MAC addresses, typically limited to the local network infrastructure.
**VxLAN (Virtual Extensible LAN):** An overlay network technology that encapsulates Layer 2 Ethernet frames within UDP packets.
You would choose **VxLAN** over VLAN when you need to extend Layer 2 connectivity (broadcast domains) across a large, multi-tenant, or geographically dispersed network (e.g., in a cloud data center), as it overcomes the 4094-VLAN limit and allows for tunneling over an existing IP infrastructure.

**N7** — The traffic is being replied via eth0 because the routing table (or the kernel's routing decision process) determines that the best path back to the source subnet (192.168.1.0/24) is via the default gateway (10.0.0.1) and the interface eth0. The kernel uses the source IP address of the incoming packet (192.168.1.5) and determines the return path based on the routing table, which points to the default gateway.
**Fix using Policy-Based Routing (PBR):** You must create a routing rule that specifically dictates that traffic originating from the 192.168.1.0/24 subnet must exit via the eth1 interface, overriding the default routing table. This is typically done using `ip rule add from 192.168.1.0/24 table <custom_table>` and defining the next hop in that custom table to be the local gateway on eth1.

**N8** — BGP path selection is a complex process used to determine the best path for a route advertised between Autonomous Systems (ASes). It is a decision-making process that evaluates multiple attributes.
The general order of preference (though specific implementations may vary slightly) is:
1.  **Weight** (Local preference, highest wins)
2.  **Local Preference** (Highest wins)
3.  **AS Path Length** (Shortest path wins)
4.  **Origin Type** (IGP > EGP > Incomplete)
5.  **MED (Multi-Exit Discriminator)** (Lowest wins)

**N9** — When running VxLAN over an IPsec tunnel, the encapsulation process adds multiple layers: Ethernet $\rightarrow$ VxLAN Header $\rightarrow$ UDP Header $\rightarrow$ IPsec Header (ESP/AH) $\rightarrow$ IP Header. Each layer adds overhead.
The physical MTU is 1500 bytes.
*   VxLAN Header overhead: $\approx 50$ bytes (UDP/VxLAN/Outer IP)
*   IPsec Overhead (ESP): $\approx 50$ bytes (depending on encryption/auth)
*   Total Overhead: $\approx 100$ bytes
Maximum Inner Payload = Physical MTU - Total Overhead
Maximum Inner Payload = $1500 - 100 = \mathbf{1400 \text{ bytes}}$.

**N10** — **ARP (Address Resolution Protocol):** Maps an IP address (Layer 3) to a corresponding MAC address (Layer 2) within a local network segment. It is essential for local communication.
**Gratuitous ARP (GARP):** A host sends an ARP request for its *own* IP address. This solves two problems:
1.  **Cache Poisoning/Stale Entries:** It forces other devices on the network to update their ARP caches immediately, preventing them from using old, incorrect MAC addresses.
2.  **Duplicate IP Detection:** It can quickly detect if another host is using the same IP address.

**N11** — **Public IP:** Globally unique IP address routable on the public internet.
**Private IP:** IP address reserved for use within private networks (LANs) and not routable on the public internet.
The three private IPv4 ranges (RFC 1918) are:
1.  **10.0.0.0/8** (10.0.0.0 to 10.255.255.255)
2.  **172.16.0.0/12** (172.16.0.0 to 172.31.255.255)
3.  **192.168.0.0/16** (192.168.0.0 to 192.168.255.255)

**N12** — **DNS (Domain Name System):** A hierarchical naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses.
*   **A Record:** Maps a hostname to an IPv4 address (e.g., `www.example.com` $\rightarrow$ 192.0.2.1).
*   **CNAME Record (Canonical Name):** Creates an alias, mapping one domain name to another domain name (e.g., `blog.example.com` $\rightarrow$ `servers.example.com`).
*   **AAAA Record:** Maps a hostname to an IPv6 address.

**N13** — **DHCP (Dynamic Host Configuration Protocol):** A network protocol used to automatically assign IP addresses and other network configuration parameters (like subnet mask, gateway, DNS servers) to devices on a network.
The four-step DORA process:
1.  **Discover:** Client broadcasts a DHCP Discover message to find available DHCP servers.
2.  **Offer:** Server responds with a DHCP Offer, proposing an IP address and configuration.
3.  **Request:** Client broadcasts a DHCP Request, formally accepting the offered IP address.
4.  **Acknowledge:** Server sends a DHCP ACK, confirming the lease and providing the final configuration details.

**N14** — **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming data to all connected ports, creating a single large collision domain.
**Switch:** Operates at Layer 2 (Data Link). It uses MAC addresses to intelligently forward frames only to the intended recipient port, segmenting collision domains.
**Router:** Operates at Layer 3 (Network). It uses IP addresses to forward packets between different networks (subnets), determining the optimal path based on routing tables.

**N15** — **Half-duplex:** Allows data to be transmitted or received, but not simultaneously. Devices must take turns (e.g., walkie-talkie).
**Full-duplex:** Allows data to be transmitted and received simultaneously over the same link.
Modern Ethernet links overwhelmingly use **full-duplex** communication to maximize throughput and efficiency.

**N16** — **TTL (Time To Live):** A field in the IP header that specifies the maximum number of hops (routers) a packet can traverse.
**Traceroute Exploitation:** Traceroute works by setting the TTL field to 1, then 2, then 3, and so on. When a router receives a packet with TTL=1, it decrements the TTL to 0 and drops the packet, sending back an ICMP "Time Exceeded" message. By observing which router sends the ICMP message for each incremented TTL, the path (hops) to the destination can be mapped.

**N17** — **NAT Gateway:** A router or firewall that performs Network Address Translation (NAT), allowing multiple private IP addresses to share a single public IP address when accessing the internet.
*   **Static NAT:** Maps a specific private IP address to a specific public IP address permanently (1:1 mapping). Used for servers that need to be consistently reachable from the outside.
*   **Dynamic NAT:** Maps private IP addresses to a pool of available public IP addresses on a first-come, first-served basis.
*   **PAT (Port Address Translation) / NAT Overload:** The most common form. It maps multiple private IPs to a single public IP address by tracking unique source port numbers. This allows thousands of internal devices to share one public IP.

**N18** — **ECMP (Equal-Cost Multi-Path):** A routing technique where a router installs multiple paths into its routing table for the same destination prefix, provided all paths have the same administrative cost (metric). The router then distributes traffic across these multiple paths.
**Hashing Strategies:** Common strategies include hashing based on:
1.  **Source IP Address**
2.  **Destination IP Address**
3.  **Source/Destination Port Pair**
**Asymmetric Flows Problem:** If a firewall is stateful, it tracks the connection state (e.g., SYN $\rightarrow$ ACK). If the return traffic (the response) takes a different path than the initial request (due to ECMP), the firewall may not recognize the return traffic as part of an established session, causing the connection to be dropped or flagged as suspicious.

**N19** — **The Problem:** The high latency and limited TCP window size (64KB) indicate a **Bandwidth-Delay Product (BDP) bottleneck**. The BDP is the maximum amount of data that can be "in flight" at any given time (Bandwidth $\times$ Round Trip Time). If the BDP is 10MB, but the TCP window size is only 64KB, the sender cannot transmit enough data to keep the pipe full, leading to underutilization and high latency.
**Solution (TCP Window Scaling):** RFC 1323 allows the TCP window size to exceed the traditional 16-bit limit (65,535 bytes). By using a scaling factor, the window size can be increased to match the BDP (e.g., 10MB), allowing the sender to transmit the necessary amount of data to saturate the link.

**N20** — **802.1Q Trunk Ports:** A mechanism that allows a single physical link to carry traffic for multiple VLANs. It uses a 4-byte tag inserted into the Ethernet frame header to identify which VLAN the frame belongs to.
**Linux Configuration (Sub-interfaces):** The physical NIC (e.g., `eth0`) is configured as a trunk, and logical sub-interfaces are created for each VLAN.
*   `eth0.10` (VLAN 10): Configured with the IP for VLAN 10.
*   `eth0.20` (VLAN 20): Configured with the IP for VLAN 20.
*   `eth0.30` (VLAN 30): Configured with the IP for VLAN 30.
**Frame Format:** The frame structure is standard Ethernet, but immediately following the MAC addresses, the 4-byte **802.1Q tag** is inserted, containing the VLAN ID (VID) for that specific frame.

## Linux

**L1** — **Hard Link:** A hard link is a directory entry that points directly to the same inode (the data structure containing file metadata and data blocks) as the original file. It is essentially another name for the same data. Deleting one hard link does not delete the data until the last link is removed.
**Symbolic Link (Symlink):** A special file that contains a text path pointing to another file or directory. It is a pointer or shortcut. If the target file is deleted, the symlink breaks (dangling link).

**L2** — Use the `find` command:
`find /var/log -type f -size +100M`

**L3** — State D (uninterruptible sleep) means the process is waiting for an I/O operation (e.g., disk read/write) to complete. The kernel cannot interrupt this process, even with `kill -9`. The process is blocked waiting for hardware or kernel resources.

**L4** — **cgroups v1:** Used resource control based on hierarchical controllers (e.g., CPU, Memory). It is older and less unified.
**cgroups v2:** A unified, hierarchical system that provides a single, consistent interface for resource management across all controllers (CPU, Memory, I/O, etc.). It is designed to be more robust and easier to manage.
**systemd** prefers **cgroups v2** because it offers a cleaner, more unified, and modern resource management model, which is crucial for containerization and system stability.

**L5** — **iptables:** The older, traditional firewall framework. It operates by chaining rules and processing packets sequentially.
**nftables:** The modern, unified packet filtering framework. It is designed to be more efficient, flexible, and handle complex rulesets more cleanly than iptables.
**Kernel Handling:** The kernel provides a unified networking stack interface. When both are present, the kernel typically handles the ruleset based on which framework is currently active or configured. Modern distributions are migrating entirely to nftables, which can often replace iptables functionality.

**L6** — The most likely cause is that the filesystem contains a large number of **small files**. `df -h` reports usage based on the number of inodes and blocks allocated, while `du -sh` (disk usage) only reports the total space consumed by the file contents. A high inode count can exhaust the available inodes on the filesystem, even if the total data size is low.

**L7** — **UEFI Firmware:** The system firmware initializes hardware and locates the bootloader.
**Bootloader (e.g., GRUB):** Loads the Linux kernel into memory and passes necessary parameters (like root filesystem location) to the kernel.
**Kernel:** The core operating system component. It initializes drivers, sets up memory management, and starts the boot process.
**Initramfs (Initial RAM Filesystem):** A small, temporary root filesystem loaded into RAM. It contains minimal drivers and scripts necessary to mount the real root filesystem, especially if the root filesystem is on a complex device (like LVM or encrypted).
**Root:** The actual root filesystem is mounted.
**Systemd:** The init system takes over, reading configuration files, starting essential services, and reaching a final target state (e.g., `multi-user.target`), completing the boot process.

**L8** — The OOM killer fires because the kernel prioritizes *available* memory, not just free memory. While `buff/cache` (buffers and caches) is memory used by the kernel for performance, the kernel can reclaim this memory instantly if an application needs it. However, if the *actual* free memory (memory not used by processes and not reclaimable) is low, and the system is under memory pressure, the OOM killer will activate to prevent system collapse, even if the total `buff/cache` is high.
**Kernel Tunables:** `vm.swappiness` (controls how aggressively the kernel swaps out anonymous memory) and `vm.min_free_kbytes` (sets the minimum amount of memory the kernel should keep free).

**L9** — `ip netns` is used to create and manage **network namespaces**. A network namespace provides an isolated view of the network stack (interfaces, routing tables, firewall rules) for a process or group of processes.
**Container Runtimes:** Container runtimes (like Docker or Kubernetes) use network namespaces to isolate each container's network stack. This ensures that a process inside a container has its own private IP address, routing table, and network interfaces, completely separate from the host system.

**L10** — **SIGTERM (Signal 15):** A graceful termination request. The process can catch this signal, clean up resources, and exit cleanly.
**SIGKILL (Signal 9):** An immediate, non-catchable termination signal. The kernel kills the process instantly; the process has no chance to clean up.
**SIGQUIT (Signal 3):** Requests the process to quit and typically dump a core file for debugging. This signal can be caught by the process.

**L11** — **stdin (Standard Input):** Where a program receives input (e.g., keyboard input).
**stdout (Standard Output):** Where a program sends normal, expected output.
**stderr (Standard Error):** Where a program sends error messages and diagnostic output.
To redirect stderr to a file while displaying stdout on the terminal:
`command 2> error.log` (Redirects file descriptor 2, stderr, to the file)

**L12** — `chmod 755` sets permissions for the owner, group, and others.
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = 7. The owner has full permissions.
*   **5 (Group):** Read (4) + Execute (1) = 5. The group can read and execute, but not write.
*   **5 (Others):** Read (4) + Execute (1) = 5. Others can read and execute, but not write.

**L13** — **Root User (UID 0):** Has absolute, unrestricted access to the entire system, including the ability to modify any file, change kernel parameters, and manage all system resources.
**Sudo Privileges:** A user with `sudo` can execute specific commands as another user (usually root) but is restricted by the `/etc/sudoers` file. This allows for granular control, meaning the user can run specific administrative tasks without having full root access.

**L14** — **Package Manager:** Software used to automate the installation, configuration, upgrading, and removal of software packages on a Linux system.
**Debian/Ubuntu:** `apt` (Advanced Package Tool)
**RHEL/Fedora:** `dnf` (Dandified YUM)

**L15** — `/etc/fstab` (File System Table) is a configuration file that defines how and where filesystems (partitions, network mounts, etc.) should be mounted during the system boot process.
If an entry is misconfigured (e.g., incorrect UUID, wrong mount point, or incorrect filesystem type), the system may fail to boot, halt during the mounting phase, or fail to mount the intended filesystem, leading to a broken system state.

**L16** — **LVM (Logical Volume Manager):** A storage management abstraction layer that allows administrators to create, manage, and resize storage volumes dynamically, independent of the underlying physical disk layout.
*   **Physical Volumes (PV):** The actual physical storage devices (hard drives, partitions) that LVM uses.
*   **Volume Groups (VG):** A pool of storage capacity created by combining one or more PVs.
*   **Logical Volumes (LV):** The flexible, usable partitions created from the VG.
**Extending an LV:** You first extend the Volume Group (VG) by adding more physical space (e.g., adding a new PV). Then, you extend the Logical Volume (LV) using `lvextend`, and finally, you resize the filesystem within that LV using `resize2fs` (for ext4) or `xfs_growfs`.

**L17** — **I/O Scheduler:** Algorithms that determine the order in which block I/O requests are serviced by the disk.
*   **mq-deadline:** Prioritizes requests based on deadlines, ensuring low latency for time-sensitive operations. Good for mixed workloads.
*   **bfq (Budget Fair Queueing):** Focuses on fairness, ensuring that all processes receive a proportional share of I/O bandwidth. Excellent for desktop/interactive workloads.
*   **none:** Disables the scheduler, allowing the device driver to handle requests directly. Best for specialized, high-performance storage arrays.
**Changing Scheduler:** Use the `echo` command with `sysfs`: `echo bfq > /sys/block/<device_name>/queue/scheduler`

**L18** — **Load Average:** Measures the average number of processes that are either currently running or waiting to run (in uninterruptible sleep, D state). It is a measure of system *demand*, not necessarily CPU utilization.
**I/O Wait Inflation:** If the system is waiting for slow disk operations, processes enter the D state. These processes contribute to the load average, making it appear that the CPU is overloaded, even if the CPU utilization percentage is low.
**Diagnosis:**
*   **CPU Bottleneck:** High load average AND high CPU utilization (user/system time).
*   **Disk Bottleneck:** High load average AND high I/O wait time (`iowait` in `top`). Use `iostat` to check disk queue lengths and utilization.
*   **Network Bottleneck:** High load average AND high network utilization (check `netstat` or `ss`).

**L19** — **SELinux (Security-Enhanced Linux):** Enforces Mandatory Access Control (MAC). Instead of relying solely on traditional Discretionary Access Control (DAC, i.e., file permissions), SELinux assigns security contexts (labels) to every subject (processes) and object (files, ports). Access is only granted if the policy explicitly permits the interaction between the subject's context and the object's context.
**Modes:**
*   **Enforcing:** SELinux actively denies access based on policy.
*   **Permissive:** SELinux logs violations but does not deny access.
*   **Disabled:** SELinux is completely inactive.
**Troubleshooting:** If a daemon fails to bind a non-standard port, check the SELinux audit logs (`/var/log/audit/audit.log`). If the policy is blocking the port, you must either change the daemon's configuration to use a standard port or use `semanage port` to explicitly tell SELinux that the daemon is allowed to use that specific port.

**L20** — **Page Fault:** An event where a program tries to access a memory page that is not currently in physical RAM. The kernel must handle this fault.
**Minor Page Fault:** Occurs when the required page is not in RAM, but it *can* be satisfied by moving a page from another process's memory or by allocating a new page. The page is typically loaded from the swap file or memory cache.
**Major Page Fault:** Occurs when the required page must be loaded from secondary storage (e.g., the hard drive/SSD) because it was swapped out or never loaded. This is a much slower operation.
**THP (Transparent Huge Pages):** A kernel feature that attempts to automatically use large memory pages (e.g., 2MB instead of 4KB) for memory allocation. This reduces Translation Lookaside Buffer (TLB) misses and improves performance for memory-intensive applications.
**Disabling THP:** It should be disabled if an application is highly sensitive to latency or if it relies on specific memory allocation patterns, as THP can sometimes introduce unpredictable latency spikes during the huge page allocation process.
