## .NET / C#

DN1 — **Class vs Struct**: A `class` is a reference type (stored on the heap), while a `struct` is a value type (usually stored on the stack or inline within another object). You should use a `struct` for small, immutable data structures (e.g., a Point, Color, or Complex number) where you want to avoid heap allocation overhead and don't need inheritance.

DN2 — **IEnumerable<T> vs IQueryable<T>**: `IEnumerable<T>` represents an in-memory collection; it executes logic using LINQ providers locally. `IQueryable<T>` extends this by supporting expression trees, allowing the provider (like Entity Framework) to translate the LINQ query into SQL to be executed on the database side. This distinction matters because `IEnumerable` would pull all records into memory before filtering, whereas `IQueryable` filters at the source.

DN3 — **Async/Await & Task vs ValueTask**: `async/await` uses a state machine to suspend execution without blocking the thread. A `Task` represents an asynchronous operation that returns a result. `ValueTask` is a struct that can represent either a completed result or a pending task. Use `ValueTask` when the method often returns a result synchronously (e.g., reading from a cache) to avoid unnecessary heap allocations of the `Task` object.

DN4 — **Dependency Injection Lifetimes**: 
1. **Transient**: Created every time they are requested.
2. **Scoped**: Created once per request (e.g., per HTTP request).
3. **Singleton**: Created once and live for the app's lifetime.
**Common Bug**: Injecting a Scoped service into a Singleton creates a "Captive Dependency." The Scoped service will be held by the Singleton forever, effectively making it a Singleton but potentially causing issues if the Scoped service relies on a request-specific context (like a DB connection) that has been disposed.

DN5 — **String vs ReadOnlySpan<char>**: A `string` is an immutable sequence; slicing it (`substring`) creates a new string allocation. `ReadOnlySpan<char>` provides a view over a contiguous block of memory (stack-only) without allocating new memory. Use `Span<T>` for high-performance parsing/slicing where you want to minimize GC pressure.

DN6 — **Garbage Collector & IDisposable**: The GC manages memory using generations: Gen 0 (short-lived objects), Gen 1 (buffer), and Gen 2 (long-lived/static-ish). The Large Object Heap (LOH) holds objects >85k bytes and is handled differently as it isn't compacted frequently. You need `IDisposable` because the GC only manages *memory*; it cannot automatically release unmanaged resources like file handles, database connections, or network sockets.

DN7 — **ConfigureAwait(false)**: By default, `await` attempts to resume on the original synchronization context (e.g., the UI thread in WPF or the Request Context in ASP.NET). `ConfigureAwait(false)` tells the runtime not to marshal back to that context. Use it in library code to avoid deadlocks and improve performance. Do NOT use it if you specifically need access to the UI context (like updating a Label text).

DN8 — **.NET 8/9 Features**:
*   **Primary Constructors**: Allows defining constructor parameters directly in the class header.
*   **Collection Expressions**: Simplified syntax for initializing arrays/lists (`int[] x = [1, 2];`).
*   **FrozenDictionary**: An immutable dictionary optimized for read-heavy scenarios where keys are known at creation.
Example:
```csharp
public class UserService(IDbContext db) : IUserService { // Primary Constructor
    public List<User> GetUsers() => db.Users.ToList();
}
// Collection expression usage:
var ids = [101, 102, 103];
```

DN9 — **ObjectDisposedException under High Load**: This usually occurs because a `DbContext` instance is being shared across multiple threads simultaneously or accessed after its scope has ended. In EF Core, `DbContext` is not thread-safe. The fix is to ensure the `DbContext` is registered as "Scoped" (default) and injected into services that also have a Scoped lifetime, ensuring one instance per request. If using background tasks, use a `IServiceScopeFactory` to create a new scope manually.

DN10 — **Record vs Class vs Record Struct**: A `record` provides value-based equality and concise syntax; it's perfect for DTOs. A `class` is for complex logic with reference identity. A `record struct` combines the stack-allocation of a struct with the value-equality/concise syntax of a record. Choose based on memory requirements (struct) vs behavior complexity (class).

DN11 — **ref, out, in**:
*   **ref**: Pass by reference; variable must be initialized before passing.
*   **out**: Variable passed by reference but doesn't need initialization; method *must* assign it a value.
*   **in**: Passed by reference but is read-only; used to pass large structs efficiently without copying while preventing modification.

DN12 — **Nullable Reference Types**: `#nullable enable` allows you to distinguish between types that can be null and those that shouldn't be. It is a compile-time check only. Nullable value types (`int?`) are actual wrappers (`Nullable<T>`) that allow value types to hold null values at runtime.

DN13 — **LINQ & Deferred Execution**: LINQ is a query language for collections. Method syntax uses extension methods (`.Where()`), Query syntax mimics SQL. **Deferred execution** means the query isn't executed when defined, but rather when the result is iterated over (e.g., via `foreach` or `.ToList()`).

DN14 — **Generic Constraints**: 
*   `where T : class`: Must be a reference type.
*   `where T : struct`: Must be a value type.
*   `where T : new()`: Must have a parameterless constructor.
*   `where T : IComparable<T>`: Must implement an interface/base class.
Combine them using commas (e.g., `where T : class, new()`). Use these to ensure type safety in generic logic.

DN15 — **Abstract Class vs Interface**: An abstract class can contain state (fields) and partial implementation; an interface is purely a contract. With C# 8+ default interface methods, interfaces *can* provide default implementations, blurring the line slightly, but they still cannot hold instance fields.

DN16 — **ASP.NET Core Middleware**: The pipeline is a series of components that handle requests.
*   `Use()`: Adds middleware to the pipe.
*   `Map()`: Branches the pipe based on path.
*   `Run()`: A terminal middleware (ends the request).
Ordering matters because each piece passes the request to the next. Exception handling middleware works by wrapping the subsequent calls in a try-catch block.

DN17 — **Channel<T>**: A high-performance producer-consumer library. Unlike `BlockingCollection<T>`, it supports `async` natively. For backpressure, use a **Bounded Channel**; when the capacity is reached, the `WriteAsync` call will asynchronously wait until space is available, preventing memory overflow.

DN18 — **Source Generators**: These generate C# code during compilation rather than using Reflection at runtime or IL Weaving post-compilation. They are faster for the end user as there's no reflection overhead. **Incremental Generators** only re-run if specific inputs change, making them much faster than standard Source Generators which might re-generate everything every build.

DN19 — **TPL Dataflow vs Channels**: TPL Dataflow provides "building blocks" like `ActionBlock` and `TransformBlock` to create complex pipelines with built-in concurrency management. `System.Threading.Channels` is lower-level, providing a raw queue mechanism where you manually manage the consumption logic. Use Dataflow for complex branching/parallelism; use Channels for simple, high-throughput producer-consumer patterns.

DN20 — **Minimal APIs**: Designed for small microservices. They reduce boilerplate by removing the need for Controllers. Trade-offs: they can be harder to organize in very large projects but offer better performance and simpler routing. Route groups allow logical grouping of endpoints, and Endpoint Filters provide cross-cutting concerns (like Auth) without extra middleware layers.

## Python

P1 — **List vs Tuple / Set vs Frozenset**: A list is mutable; a tuple is immutable. A set contains unique elements; a frozenset is an immutable version of a set. You cannot add items to a frozenset once created.

P2 — **GIL (Global Interpreter Lock)**: The GIL prevents multiple native threads from executing Python bytecodes at once. This affects CPU-bound workloads (e.g., heavy math). Workarounds include using the `multiprocessing` module (separate processes), using C extensions (NumPy/Pandas), or switching to Jython/IronPython.

P3 — **Deepcopy vs Copy**: A shallow copy (`copy.copy`) copies the object but keeps references to nested objects. If you modify a nested list in a shallow copy, it changes in both original and copy. Deepcopy recursively copies everything. Example: `a = [[1, 2]]; b = copy.copy(a); b[0][0] = 99`. Now `a[0][0]` is also 99.

P4 — **Decorators & Timer**:
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"Time taken: {time.perf_counter() - start}")
        return result
    return wrapper
```

P5 — **Generators & Yield**: Generators produce values one by one on demand, saving memory compared to lists which store all elements at once. `yield from` allows delegating to a sub-generator. Use generators for large datasets where you don't need the whole list in memory simultaneously.

P6 — **Asyncio Event Loop**: `asyncio.run()` starts the loop; `gather()` runs multiple coroutines concurrently; `create_task()` schedules a task to run "in the background." You cannot use `time.sleep()` because it blocks the entire thread (and thus the event loop). Use `await asyncio.sleep()` instead to yield control back to the loop.

P7 — **MRO (Method Resolution Order)**: Python uses C3 Linearization. In your example, `D` inherits from `B` and `C`. Since `B` is first in the inheritance list, but `B` doesn't override `who`, it looks at its parent `A`. However, since `C` *does* have an implementation of `who`, and `C` is part of the MRO, the order matters. For `class D(B, C)`, the result is `"C"` if `C` was checked before `B` or if `C` overrides something that `B` also inherited. Actually, in this specific code, `D().who()` returns `"C"` because `C` provides a definition while `B` does not.

P8 — **Metaclass vs __init_subclass__**: A metaclass defines how classes are created (a class factory). `__init_subclass__` is a hook called whenever a class is subclassed. Use a Metaclass for complex logic like registering types; use `__init_subclass__` for simpler tasks like enforcing naming conventions on subclasses.

P9 — **Multiprocessing vs Threading vs Concurrent.futures**:
-   **Threading**: Shared memory, good for I/O bound.
-   **Multiprocessing**: Separate memory space, bypasses GIL, good for CPU bound.
-   **Concurrent.futures**: High-level API to manage both threads and processes easily.
Pickling: Multiprocessing requires objects to be "picklable" (serializable) to move between processes.

P10 — **\_\_slots\_\_**: It tells Python not to create a `__dict__` for instances of the class. This significantly reduces memory usage when creating millions of small objects (e.g., points or nodes in a tree) by preventing the overhead of an instance dictionary.

P11 — **Virtual Environments**: They isolate project dependencies so different projects can have different versions of libraries. 
*   `venv`: Standard library tool.
*   `virtualenv`: Older, more features (like handling older python versions).
*   `conda`: A package manager that handles non-python dependencies as well.

P12 — **Comprehensions**: List/Dict/Set comprehensions are concise ways to build collections from iterables. They are generally faster than `map()` because they avoid function call overhead inside the loop. Use map() if you already have a pre-defined function; use comprehensions for simple logic.

P13 — **== vs is / Interning**: `is` checks identity (memory address), `==` checks value equality. Small integers (-5 to 256) are interned (cached in memory); hence `a = 10; b = 10; a is b` returns True.

P14 — **Args and Kwargs**: `*args` captures variable positional arguments into a tuple; `**kwargs` captures keyword arguments into a dict. `/` forces all preceding args to be positional only; `*` forces all following args to be keyword only.

P15 — **Context Managers**: Used to manage resources (setup/teardown). You can write one using a class with `__enter__`/`__exit__` or use the `@contextmanager` decorator which yields a value. Example: Managing a database connection pool where you ensure the connection returns to the pool even if an error occurs.

P16 — **Type Hinting**: Static analysis tools like Mypy check types without runtime cost.
*   `Union`: A or B.
*   `Optional`: A or None.
*   `Literal`: Specific allowed values (e.g., "red", "blue").
*   `TypeVar`: Generic type variables.
*   `Protocol`: Structural typing (similar to interfaces but not required by inheritance).

P17 — **Data Model**: `__repr__` is for developers (debugging, shows object state); `__str__` is for end-users. `__eq__` defines equality; it must have a corresponding `__hash__` (unless the object is unhashable) so that objects can be used in sets/dicts. `__getattr__` handles missing attributes; `__getattribute__` intercepts every attribute access.

P18 — **Descriptors**: The descriptor protocol (`__get__`, `__set__`) allows defining how an attribute's access is handled. Properties are descriptors that manage logic during get/set. `classmethod` and `staticmethod` use descriptors to change how they bind to instances vs classes.

P19 — **Import System**: Python looks at `sys.path`. Relative imports (`from . import x`) require the module to be part of a package. Namespace packages allow multiple independent modules to share a namespace without an `__init__.py`. A *Finder* locates the source code; a *Loader* loads it into memory as a module object.

P20 — **Dataclasses vs Pydantic**: Dataclasses provide boilerplate reduction for data storage. `attrs` provides more advanced features like complex default factories. Pydantic adds runtime validation and serialization (JSON schema). Use Pydantic when you need to validate incoming API request bodies; use dataclasses for internal state management where performance is critical and input is already trusted.
