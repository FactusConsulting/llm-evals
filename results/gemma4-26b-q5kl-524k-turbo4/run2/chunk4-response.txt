## Go

**G1** — An **array** has a fixed size defined at compile time. A **slice** is a descriptor containing a pointer to an underlying array, a length, and a capacity. When you `append` to a slice that has reached capacity, Go allocates a new, larger underlying array (usually doubling capacity), copies the old elements, and returns a new slice descriptor.

**G2** — `var x int` declares a variable and initializes it to its zero value (`0`). `x := 0` is short-variable declaration, which declares and initializes in one step. You **cannot** use `:=` outside of a function body (e.g., at the package level).

**G3** — A **goroutine** is a lightweight, user-space thread managed by the Go runtime. Unlike OS threads, they have small, growable stacks. The **GMP model** consists of **G** (Goroutines), **M** (Machine/OS Threads), and **P** (Processor/Context). The scheduler maps $M$ goroutines onto $P$ processors to execute on $M$ OS threads, ensuring efficient multiplexing.

**G4** — **Channels** are primitives for communication between goroutines. An **unbuffered channel** is synchronous; the sender blocks until a receiver is ready. A **buffered channel** allows sending up to $N$ elements before blocking. Sending to a full buffered channel blocks the sender until space is available.

**G5** — The `context` package handles cancellation, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
// If the request takes > 2s, ctx.Done() closes, and the request is aborted.
```

**G6** — Go uses **implicit satisfaction**: if a type implements all methods of an interface, it satisfies it (no `implements` keyword). This differs from Java/C# where satisfaction is explicit. `interface{}` (or `any`) can hold any value, making it powerful for generic containers, but dangerous because it bypasses type safety, requiring type assertions that can panic.

**G7** — This is a **data race**. There is no "happens-before" relationship between the goroutine writing to `data`/`ready` and the main loop reading them. The compiler or CPU might reorder instructions, or the value might stay in a CPU cache. **Correct alternatives**: Use `sync.Mutex`, `sync/atomic` (e.g., `atomic.Bool`), or a channel to signal completion.

**G8** — `sync.Mutex` is an exclusive lock. `sync.RWMutex` allows multiple concurrent readers OR one single writer. Use `sync.Map` for high-concurrency scenarios with stable keys (read-heavy) or when multiple goroutines write to disjoint sets of keys. A regular map + `Mutex` is generally faster for simple, write-heavy, or small-scale use cases.

**G9** — `go.mod` tracks dependencies and versions; `go.sum` contains cryptographic checksums of dependencies to ensure integrity. `go mod tidy` removes unused modules and adds missing ones. **MVS (Minimum Version Selection)** selects the highest version of a module that satisfies all constraints in the dependency graph.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. **Gotcha**: Using `defer` inside a loop can cause resource exhaustion (e.g., file descriptors) because the calls don't execute until the *outer* function returns, not the loop iteration.

**G11** — A **pointer** is a variable that stores the memory address of another value. The zero value of a pointer is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs automatically when a package is initialized, before `main()`. A package can have multiple `init()` functions, and they execute in the order they appear in the source file (lexical order) after all imported packages are initialized.

**G13** — `make` is used for slices, maps, and channels; it initializes the internal data structures. `new` allocates zeroed memory for any type and returns a pointer (`*T`).

**G14** — Errors are values implementing the `error` interface (a single `Error() string` method). Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error matches a specific value (useful for wrapped errors), while `errors.As` checks if an error matches a specific type.

**G15** — **Map**: `nil`. **Slice**: `nil`. **Channel**: `nil`. **Struct**: All fields set to their respective zero values.

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one access is a write. The `-race` flag enables a data race detector that instruments code at runtime to find unsynchronized access.
*Example Fix*: Wrap access in `mu.Lock()`/`mu.Unlock()`.

**G17** — `select` lets a goroutine wait on multiple channel operations. Unlike `switch` (which evaluates values), `select` evaluates channel readiness. If multiple cases are ready, one is chosen pseudo-randomly. **Timeout**: `case <-time.After(d):`.

**G18** — **Escape analysis** is a compiler optimization to decide if a variable can live on the **stack** (fast, automatic cleanup) or must "escape" to the **heap** (slower, GC managed). Variables escape if they are returned as pointers, are too large, or are passed to interfaces. Inspect via `go build -gcflags="-m"`.

**G19** — `reflect.Type` describes the type metadata; `reflect.Value` holds the actual data. Reflection is computationally expensive due to runtime type checking and heap allocations. Use **code generation** (e.g., `stringer`) for performance-critical paths.

**G20** — `//go:embed` allows embedding files/directories into the binary at compile time. It works with `embed.FS`. Limitations include the inability to embed files outside the module root. It integrates with `io/fs` to provide a standard filesystem interface.

## Rust

**R1** — **Ownership** rules: 1. Each value has a variable called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable string. `&str` is an immutable string slice (a view). Use `&str` in function signatures to allow the function to accept both `String` and `&str`.

**R3** — **Borrowing** allows accessing data without taking ownership. Rules: You can have either **one** mutable reference (`&mut T`) OR **any number** of immutable references (`&T`) at any given time.

**R4** — `Result<T, E>` handles success/failure; `Option<T>` handles presence/absence. The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>` is a single-owner heap pointer. `Rc<T>` is a reference-counted pointer for single-threaded use. `Arc<T>` (Atomic Reference Counted) is for multi-threaded use.

**R6** — **Traits** define shared behavior (like Go interfaces). `dyn Trait` uses **dynamic dispatch** (vtable lookup at runtime). `T: Trait` uses **static dispatch** (monomorphization at compile time), which is faster.

**R7** — It fails because the compiler cannot guarantee that the returned reference lives as long as the inputs. **Fix**: Use explicit lifetimes: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8** — `Send` means ownership can be transferred between threads. `Sync` means a reference can be shared between threads. `Rc<T>` is not `Send/Sync` because its reference count is not atomic. `Arc<T>` uses atomic operations, making it safe for concurrent use.

**R9** — Rust's async is **poll-based**. A `Future` is a state machine that does nothing until `poll()` is called. The **executor** (e.g., Tokio) manages the polling loop. Unlike Go, where the runtime manages goroutines automatically, Rust requires an external executor.

**R10** — `unsafe` allows bypassing compiler safety checks. You can: 1. Dereference raw pointers. 2. Call FFI (C functions). 3. Mutate static variables. It is justified when interfacing with hardware or low-level C libraries.

**R11** — `match` is a control flow operator that performs pattern matching. `if let` is syntactic sugar for matching a single pattern. `match` is **exhaustive**; the compiler forces you to handle every possible case.

**R12** — `[T; N]` is a fixed-size array on the stack. `Vec<T>` is a heap-allocated, growable buffer. When a `Vec` exceeds capacity, it allocates a larger block of memory and moves the elements.

**R13** — Rust enums are **sum types** (can hold data in variants). `Option<T>` is an enum (`Some(T)` or `None`). Rust has no `null` to prevent null-pointer exceptions; you must explicitly handle the `None` case.

**R14** — `impl` defines methods for a type. `&self` (immutable borrow), `&mut self` (mutable borrow), and `self` (consumes the value/takes ownership). **Associated functions** (like `String::new()`) do not take `self` and are called via the type.

**R15** — `#[derive]` automatically implements traits. Common: `Debug` (printing), `Clone` (deep copy), `PartialEq` (equality), `Serialize` (serde). You cannot derive a trait if the underlying types do not also implement the required bounds.

**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that provides both borrowed and owned data. It is useful for functions that only need to mutate data if a certain condition is met, avoiding an allocation if no mutation occurs.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. In Rust 2018+, the module tree is more closely aligned with the file system compared to the 2015 edition's explicit `mod` declarations.

**R18** — `Pin<T>` ensures that the data at a specific memory address will not move. This is required for **self-referential structs** (common in `async` state machines). `Unpin` is a marker trait for types that are safe to move even when pinned.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching on code tokens. **Procedural macros** act on the AST (Abstract Syntax Tree). **Hygiene** ensures that macro-generated code doesn't accidentally clash with local variable names.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use. **Generics** use monomorphization (creating specialized versions of functions). **Iterators** and **Trait Static Dispatch** compile down to highly optimized machine code, often matching hand-written C.
