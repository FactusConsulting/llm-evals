## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted with an initial value of `undefined`. `let` and `const` are block-scoped and hoisted but reside in the "Temporal Dead Zone" (TDZ) until declaration. `const` prevents reassignment of the identifier. **Hoisting** is the JS engine's behavior of moving declarations to the top of their scope during the compile phase.

**JS2** — The **Event Loop** manages asynchronous execution. The **Call Stack** handles synchronous tasks. When an async task finishes, its callback enters the **Microtask Queue** (Promises, `queueMicrotask`). The **Macrotask Queue** (setTimeout, I/O) is processed after the Microtask queue is completely emptied.

**JS3** — A **closure** is a function that remembers its lexical scope even when executed outside that scope. *Example:* A function returning a counter. *Bug:* Using `var` in a `for` loop with `setTimeout` causes all iterations to see the final value of `i`. *Fix:* Use `let` to create a new binding for each iteration.

**JS4** — `async` functions return a `Promise`. `await` pauses execution until the promise settles. Error handling: `try/catch` works with `await`; with raw Promises, use `.catch()`. `Promise.all` rejects immediately if *any* promise fails; `Promise.allSettled` waits for all to finish, regardless of success/failure.

**JS5** — `interface` is primarily for defining object shapes and supports "declaration merging" (adding properties to the same interface later). `type` is used for unions, primitives, and aliases. **Discriminated unions** are a pattern where multiple types in a union share a common literal property (a "tag") to allow type narrowing in `switch` or `if` blocks.

**JS6** — **Prototypal inheritance** means objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with `proto` as its `[[Prototype]]`. **ES6 classes** are "syntactic sugar" over the existing prototype-based inheritance system.

**JS7** — `this` refers to the execution context. **Binding Rules (Priority):** 1. `new` binding, 2. Explicit binding (`call`, `apply`, `bind`), 3. Implicit binding (the object before the dot), 4. Default binding (global object or `undefined` in strict mode). `bind()` returns a **new function** with a fixed `this`; it cannot be re-bound.

**JS8** — `WeakRef` allows holding a reference to an object without preventing it from being garbage collected. `FinalizationRegistry` allows running a callback after an object is GC'd. `WeakMap` keys must be objects because primitives cannot be uniquely identified for garbage collection purposes.

**JS9** — **V8 Optimizations:** **Hidden Classes** (storing object shapes to avoid expensive lookups), **Inline Caching** (remembering property locations), and **Deoptimization** (reverting to slower code when assumptions fail). *Deoptimization causes:* Changing the shape of an object (adding/deleting properties) after it has been "optimized."

**JS10** — **Tree-shaking** is dead-code elimination. It works with **ES Modules** because `import/export` are static (analyzable at compile time). **CommonJS** (`require`) is dynamic/runtime-based, making it difficult for bundlers to prove a module is unused.

**JS11** — `null` is an intentional absence; `undefined` means a variable is uninitialized. `==` performs type coercion (treating `null == undefined` as true); `===` checks both value and type. **Nullish coalescing (`??`)** only triggers on `null`/`undefined`; **Optional chaining (`?.`)** safely accesses properties of potentially nullish objects.

**JS12** — `map()` transforms elements; `filter()` selects a subset; `reduce()` accumulates values. `reduce()` uses an **initial value** to prevent errors on empty arrays and define the accumulator type. `flatMap()` maps each element to an array and then flattens the result by one level.

**JS13** — **Template literals** use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** allow a function to parse the template. *Example:* `` sql`SELECT * FROM users WHERE id = ${id}` `` where the function escapes the `id` to prevent SQL injection.

**JS14** — **Destructuring** extracts values from arrays/objects. *Object:* `const {a, b} = obj`. *Array:* `const [x, y] = arr`. *Default:* `const {a=1} = obj`. *Renaming:* `const {a: newName} = obj`. **Rest operator (`...`)** gathers remaining elements into a new array/object.

**JS15** — `for...in` iterates over **enumerable property keys** (strings). `for...of` iterates over **iterable values**. Avoid `for...in` on arrays because it iterates over all enumerable properties (including prototype chain) and does not guarantee order.

**JS16** — **Generics** allow reusable components. `extends` (constraints) limits `T` to a specific type. **Conditional types** (`T extends U ? X : Y`) act like ternary operators for types. `infer` allows extracting a type from within another type (e.g., getting the return type of a function).

**JS17** — **CommonJS** (`require`) is synchronous and used in Node.js. **ES Modules** (`import`) are static and the standard for browsers/modern Node. In `package.json`, `"type": "module"` tells Node to treat `.js` files as ESM.

**JS18** — **Structural typing** means types are compatible if their shapes match. **Excess property checks** occur when assigning an object literal directly to a type that doesn't expect extra properties. `extends` is for subtyping; `satisfies` (TS 4.9+) checks a type without losing the specific inferred shape. **Variance:** `in` (contravariance) and `out` (covariance) define how subtyping relates to function parameters/returns.

**JS19** — `Proxy` wraps an object to intercept operations (get, set, etc.). `Reflect` is a built-in object providing methods to perform those same operations (e.g., `Reflect.get`). *Example:* A Proxy can intercept a `set` operation to validate that a value is a number before assigning it.

**JS20** — `SharedArrayBuffer` provides a way to share raw binary data between the main thread and Web Workers. `Atomics` provides thread-safe operations (add, load, store, wait, notify) to prevent race conditions. `Atomics.wait` pauses a thread until `Atomics.notify` is called on a specific index.

## Bash

**B1** — `$@` represents all arguments as separate words. `$*` represents all arguments as a single string. `"$@"` preserves word boundaries (essential for filenames with spaces); `"$*"` joins all arguments into one string.

**B2** — `set -e` (exit on error), `-u` (error on unset variables), `-o pipefail` (the entire pipeline returns the exit code of the last command to fail, rather than the last command in the pipe).

**B3** — `$(command)` is command substitution (modern). `` `command` `` is the legacy version. `$((expression))` is for arithmetic. `expr` is an external utility for math.

**B4** — **Process substitution** `<(command)` creates a temporary file descriptor that acts like a file. *Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands as if they were files.

**B5** — Use `while read -r line; do ... done < <(find . -print0)` with `IFS=`. `for f in $(ls)` is dangerous because it splits on whitespace, breaking filenames containing spaces.

**B6** — `<<EOF` is a **here document** (multi-line input). `<<<` is a **here string** (passes a single string to stdin). `<<-EOF` strips leading **tabs** from the input.

**B7** — `cmd > file 2>&1` redirects stdout to file and stderr to stdout (so both go to file). `cmd 2>&1 > file` redirects stderr to stdout (terminal), then stdout to file (stderr stays on terminal). `&> file` is a Bash shortcut to redirect both to a file.

**B8** — Use `mkdir lockdir` because `mkdir` is an **atomic** operation at the kernel level; if two processes try to create the same directory, only one succeeds. Use `trap 'rmdir lockdir' EXIT INT TERM` to ensure cleanup.

**B9** — `'...'` (single) treats everything literally. `"..."` (double) allows variable interpolation. No quotes allow word splitting and globbing. *Example:* `echo "$VAR"` vs `echo '$VAR'` vs `echo $VAR`.

**B10** — `-e` (exists), `-d` (directory), `-r` (readable). `[ ]` is the standard `test` command; `[[ ]]` is a Bash keyword that is more powerful (supports regex and logical operators without escaping).

**B11** — `$?` (exit status of last command), `$$` (PID of current script), `$!` (PID of last background job), `$#` (number of arguments).

**B12** — `foo() {}` is the standard syntax. `function foo {}` is a Bash-specific extension. Functions return an **exit code** (0-255) via `return`, not a data value. Use `echo` to "return" data.

**B13** — `PATH` is a colon-separated list of directories searched for commands. **Builtins** are part of the shell itself; **External** commands are files in `PATH`. Use `type -a command` to check.

**B14** — `trap` catches signals. `trap 'cleanup' EXIT INT TERM`. If multiple signals arrive, they are handled sequentially.

**B15** — `xargs` reads items from stdin. `find . -print0 | xargs -0` handles spaces/newlines by using the null character as a delimiter. `xargs -P <N>` runs up to N processes in parallel.

**B16** — Arrays: `arr=(a b c)`. Associative: `declare -A map`. Append: `arr+=("d")`. Length: `${#arr[@]}`. Associative arrays use `map[key]=value`.

**B17** — `(...)` is a **subshell** (new PID, new environment). `{ ...; }` is a **group command** (same PID/environment). Piping into a `while` loop creates a subshell, so variable changes inside the loop are lost in the parent.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (graceful kill), `SIGHUP` (terminal closed), `SIGKILL` (immediate, cannot be trapped). Use `trap` to catch `TERM` and kill child processes before exiting.

**B19** — Use `split -l 1000 file` to chunk, then `find ... -print0 | xargs -0 -P 4 -I {} my_func {}`. Use `wait` to ensure all parallel jobs finish. Error propagation is handled by checking exit codes of the `xargs` process.

**B20** — `exec` replaces the current shell process with the new command. `exec 3>file` opens FD 3. `exec 3>&-` closes it. A **coprocess** (`coproc`) runs a command in the background with two-way pipes for communication.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the host (screen). `Write-Host` cannot be captured by a variable or redirected via pipeline.

**PS2** — The **pipeline** passes objects between cmdlets. `ForEach-Object` is a cmdlet that processes pipeline input. `foreach` is a language keyword that is significantly faster for in-memory collections but doesn't support the pipeline directly.

**PS3** — `[PSCustomObject]` is an ordered object with properties, ideal for the pipeline. `[hashtable]` is a key-value collection. Convert: `[PSCustomObject]@{Key='Val'}` or `[ordered]@{...}`.

**PS4** — **Terminating** errors stop execution; **non-terminating** errors continue. `try/catch` only catches terminating errors. Use `-ErrorAction Stop` to turn non-terminating errors into terminating ones.

**PS5** — **Splatting** uses a hashtable to pass multiple parameters: `$params = @{Name='Test'; Path='C:\'}; Do-Something @params`.

**PS6** — `Invoke-Command` is for remote execution (one-to-many). `Enter-PSSession` is for interactive sessions. It uses **WinRM** (WS-Man) or **SSH**.

**PS7** — The function returns an empty array `[]`. `$x.GetType().Name` will be `Object[]`. If it returns `$null`, `$x.GetType()` will throw an error. Correct pattern: `[array]$x = Get-Items`.

**PS8** — A `[scriptblock]` is a block of code. To solve the **double-hop** problem (where credentials don't pass to a second remote server), use **CredSSP** or Kerberos delegation.

**PS9** — `@()` is an empty array. `[array]` is a type. To force a single result into an array, use `@($result)`. Indexing `$null` returns `$null`; indexing an empty array returns `$null`.

**PS10** — `-eq` (equality), `-match` (regex), `-contains` (checks if a collection contains a value), `-in` (checks if a value is in a collection). `-ceq` is the case-sensitive version.

**PS11** — `.psm1` is a script module (logic). `.psd1` is a manifest (metadata). Binary modules are DLLs. `Import-Module` loads them into the session.

**PS12** — `"..."` interpolates. `'...'` is literal. `@'...'@` is a **here-string** for multi-line blocks.

**PS13** — `Get-Member` shows properties/methods. `Select-Object` picks properties; `Where-Object` filters based on criteria.

**PS14** — **Classes** provide formal structure (inheritance, access modifiers). Functions are more lightweight. Classes are better for complex data structures; functions are better for procedural tasks.

**PS15** — `[CmdletBinding()]` makes a function "advanced." `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` blocks allow efficient pipeline processing (Process runs once per object).

**PS16** — **Providers** allow PowerShell to treat different data stores (Registry, Cert, Env) as file systems. `cd Registry::HKEY_LOCAL_MACHINE` works just like `cd C:\`.

**PS17** — `[runspace]` is a single thread. `[runspacepool]` manages multiple threads. `ForEach-Object -Parallel` (v7+) is a high-level wrapper around runspace management.

**PS18** — **PSScriptAnalyzer** is a static code analysis tool. It uses rules to check for best practices. Suppress via `# PSScriptAnalyzer Ignore: RuleName`.

**PS19** — `$using:var` is used to pass local variables into a remote/parallel scope. Complex objects are serialized via **CLIXML**; deep nesting can hit serialization limits.

**PS20** — **DSC** uses a **Local Configuration Manager (LCM)** to ensure a system matches a desired state. In modern infra, **Terraform** or **Ansible** have largely replaced DSC for cross-platform orchestration.
