## OpenTofu / Terraform

**T1** — `tofu plan` is a dry-run that generates an execution plan, showing what changes (create, update, destroy) will occur without actually making them. `tofu apply` executes those changes to reach the desired state.

**T2** — **State** is a JSON file mapping your configuration to real-world resources. **Remote state** is critical for collaboration (shared source of truth), security (sensitive data), and state locking (preventing concurrent writes).

**T3** — `count` uses an index (integer), making it difficult to remove items from the middle of a list without shifting indices and causing recreation. `for_each` uses keys (map or set), allowing you to add or remove specific items without affecting others. `for_each` is preferred for collections of resources where identity matters.

**T4** — This is "drift." During `tofu plan`, OpenTofu refreshes the state by querying the provider API. It compares the real-world resource attributes against the state file. If they differ, it proposes an update to revert the manual change to match the configuration.

**T5**
```hcl
resource "aws_instance" "web" {
  for_each = toset(["web1", "web2", "web3"])
  # ... other config
}
```

**T6** — `terraform_remote_state` reads the entire state file of another workspace, which can be a security risk and creates tight coupling. The recommended alternative is to use **Outputs** from a module or, better yet, a dedicated data store (like AWS SSM Parameter Store or HashiCorp Vault) to share specific, granular values.

**T7** — This is a race condition/dependency issue. The `null_resource` executes, but the output is not available until the provider completes the cycle. To fix, ensure the resource producing the kubeconfig has a formal output and use `depends_on` in the dependent resource to force the graph to wait for the `null_resource` to finish.

**T8** — `tofu import` brings existing unmanaged infrastructure into state. **Limitations:** It only imports the state, not the code; you must write the HCL manually. The **import block (1.5+)** is declarative; you define the resource in code and the block, allowing you to `plan` the import before executing it, making it much safer and more repeatable.

**T9** — A **variable** is an input parameter used to pass values into a module. An **output** is a value returned by a module to its caller.

**T10** — A **provider** is a plugin that enables OpenTofu to interact with specific APIs (AWS, Azure, etc.). If you run `tofu plan` without `tofu init`, it will fail because the necessary provider binaries have not been downloaded to the `.terraform` directory.

**T11** — It is the dependency lock file. It should be committed to ensure all team members and CI/CD pipelines use the exact same version of provider plugins, preventing "works on my machine" issues.

**T12** — `tofu destroy` removes all resources managed by the current state. To target a single resource: `tofu destroy -target=resource_type.resource_name`.

**T13** — A **data source** allows you to fetch information from an existing resource not managed by your current OpenTofu code. Example: Using `data "aws_vpc" "selected" {}` to get the ID of a VPC created by a different team.

**T14** — **Variables** are external inputs (user-provided). **Locals** are internal constants or derived values used for logic within the module. Use `locals` for complex transformations or to avoid repeating the same expression.

**T15** — 
- `create_before_destroy`: Creates the new resource before deleting the old one (useful for zero-downtime).
- `prevent_destroy`: Prevents accidental deletion of critical resources.
- `ignore_changes`: Tells OpenTofu to ignore updates to specific attributes (e.g., ignoring tags added by an external process).

**T16** — A `moved` block allows you to rename a resource or move it into a module within the code. It updates the state file to reflect the new address without destroying and recreating the actual physical resource.

**T17** — The dependency graph is a directed acyclic graph (DAG). **Implicit dependencies** are created when one resource references an attribute of another. **Explicit dependencies** are created via `depends_on`. `depends_on` forces a specific order but limits parallelism because OpenTofu cannot start the dependent resource until the target is fully complete. Use it sparingly to avoid slowing down execution.

**T18** — 
1. **State Splitting:** Break large state files into smaller, decoupled workspaces (Tradeoff: increased complexity in managing cross-state dependencies).
2. **`-refresh=false`:** Skips API calls to refresh state during plan (Tradeoff: risk of planning against stale data).
3. **Targeting:** Use `-target` to plan only specific parts (Tradeoff: ignores the rest of the infrastructure).
4. **Reduce Resource Count:** Use modules to group resources (Tradeoff: requires architectural redesign).

**T19** — State locking prevents two users from running `apply` simultaneously, which would corrupt the state. If a CI pipeline crashes, a `.lock` file remains in the backend. You break it with `tofu force-unlock <LOCK_ID>`. **Risk:** If you force-unlock while another process is actually writing, you will corrupt the state file.

**T20** — 
1. Write the new `backend` configuration block in your `.tf` files.
2. Run `tofu init`. OpenTofu will detect the change and ask if you want to migrate the state.
3. Select "yes" to copy the state from local to S3/DynamoDB.
4. **Verify:** Run `tofu state list` to ensure resources are present and check the S3 bucket to ensure the `.tfstate` file exists.

## Ansible

**A1** — A **task** is a single action. A **playbook** is a collection of plays (mapping hosts to tasks). A **role** is a structured, reusable collection of tasks, variables, and files.

**A2** — `ansible_facts` is a dictionary of system information gathered by the setup module. Access OS family via `ansible_facts['os_family']`.

**A3** — `command` runs a command without a shell environment (fast/secure). `shell` runs through `/bin/sh` (allows pipes/redirects). `raw` sends a command via SSH without using any Python modules (used for bootstrapping).

**A4** — **Idempotent:** `apt: name=nginx state=present` (running it twice changes nothing). **NOT idempotent:** `shell: echo "hello" >> /tmp/file` (running it twice adds two lines).

**A5**
```yaml
- name: Install htop
  package:
    name: "{{ 'epel-release' if ansible_os_family == 'RedHat' else 'htop' }}"
    state: present
  # Note: For a single task to handle both, you'd typically use two tasks or a loop with 'when'
```
*Corrected approach for a single task file:*
```yaml
- name: Install htop on Debian
  apt: name=htop state=present
  when: ansible_os_family == "Debian"

- name: Install htop on RedHat
  yum: name=htop state=present
  when: ansible_os_family == "RedHat"
```

**A6** — (Lowest to Highest): `role defaults` < `group_vars` < `host_vars` < `set_fact` < `extra_vars`.

**A7** — Use `serial: [3, 50]` in the play to process the first 3, then the rest. Use `wait_for` in a post-task to ensure the agent is listening before the next batch starts.

**A8** — `ansible-vault encrypt_string 'my_secret_value'` creates an encrypted string that can be stored in a plain text file.

**A9** — **Static:** A hardcoded file. **Dynamic:** A script or plugin that queries a cloud provider (AWS/GCP) to get a real-time list of hosts.

**A10** — `ansible webservers -a "df -h"`

**A11** — A **handler** is a task that only runs when "notified" by another task. It runs at the end of the play. Triggered via `notify: handler_name`.

**A12** — Configuration file for Ansible settings. Common settings: `inventory`, `remote_user`, `roles_path`.

**A13** — `register` saves the output of a task into a variable. Example: `register: result` followed by `when: result.rc == 0`.

**A14** — `import_tasks` is static (evaluated when the playbook is parsed). `include_tasks` is dynamic (evaluated when the task is reached). `include_tasks` allows for conditional logic/loops during runtime.

**A15** — A repository of roles/collections. Use `requirements.yml` and run `ansible-galaxy install -r requirements.yml`.

**A16** — `ssh` is the default (uses SSH to run Python). `local` runs tasks on the control node. `network_cli` is used for network devices (switches/routers) that don't support Python.

**A17** — `delegate_to` runs a task on a different host. `run_once` runs a task only once per play. 
*Example:*
```yaml
- name: Save remote info to local file
  shell: "hostname"
  register: host_name
  delegate_to: localhost
  run_once: true
```

**A18** — 
1. **Forks:** Increase `forks` in `ansible.cfg` to run more parallel processes.
2. **Pipelining:** Enable `pipelining = True` to reduce SSH connections.
3. **Fact Caching:** Use a Redis/JSON file to avoid re-gathering facts.
4. **Mitogen:** Use the Mitogen plugin to replace the SSH execution engine for massive speedups.

**A19** — `{{ }}` is for expressions/variables. `{% %}` is for control logic (loops/ifs). `{# #}` is for comments.
```jinja2
upstream my_app {
{% for server in backend_servers %}
  server {{ server }}; # Health check enabled
{% endfor %}
}
```

**A20** — 
1. Set `serial: 1` (or a small batch).
2. **Pre-task:** Use `uri` module to check health, then a task to remove the node from the Load Balancer.
3. **Task:** Update the application.
4. **Post-task:** Use `uri` to verify the app is up, then re-add to the LB.
5. **Rollback:** Wrap the deployment in a `block`. In the `rescue` section, use tasks to revert the application version and re-add the failed node to the LB.
