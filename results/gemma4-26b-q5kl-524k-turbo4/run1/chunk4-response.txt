## Go

**G1** — An **array** has a fixed size defined at compile time. A **slice** is a descriptor for a contiguous segment of an array, containing a pointer, a length, and a capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array (usually doubling in size), copies the old elements, and returns a new slice descriptor pointing to the new array.

**G2** — `var x int` declares a variable and initializes it to its zero value (`0`). `x := 0` is short variable declaration, which declares and assigns a value simultaneously. You **cannot** use `:=` at the package level (outside of functions); you must use the `var` keyword there.

**G3** — A **goroutine** is a lightweight, user-space thread managed by the Go runtime, not the OS. Unlike OS threads (which have large, fixed stacks and expensive context switches), goroutines start with small, segmented stacks (~2KB) that grow/shrink. The **GMP model** consists of **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts). The scheduler multiplexes many Gs onto a smaller number of Ms using Ps to ensure efficient CPU utilization.

**G4** — Channels are primitives for communication between goroutines. An **unbuffered channel** requires both a sender and receiver to be ready simultaneously (synchronous). A **buffered channel** allows sending until the buffer is full. If you send to a **full buffered channel**, the sending goroutine blocks until a receiver reads a value.

**G5** — The `context` package manages cancellation signals, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
// If the request takes > 2s, ctx.Done() closes, and the request is aborted.
```

**G6** — Go uses **implicit interface satisfaction** (duck typing): if a type implements the methods of an interface, it satisfies that interface automatically without an explicit `implements` keyword. This differs from Java/C# where implementation must be explicit. `interface{}` (or `any`) can hold any value, making it powerful for generic programming, but dangerous because it bypasses type safety, requiring runtime type assertions that can panic.

**G7** — This is unsafe due to a **data race** and lack of a "happens-before" relationship. The compiler or CPU may reorder the assignments, or the `for` loop might see `ready` as `true` before `data` is visible in main memory. **Correct alternatives**: Use `sync.Mutex`, `sync/atomic` (e.g., `atomic.Bool`), or a channel to signal completion.

**G8** — `sync.Mutex` provides exclusive access (one goroutine at a time). `sync.RWMutex` allows multiple concurrent readers OR one single writer. Use `sync.Map` when you have a "read-heavy" workload with disjoint keys or when multiple goroutines read/write/overwrite for different keys, as it reduces lock contention compared to a single mutex protecting a standard map.

**G9** — **Go modules** manage dependencies. `go.mod` defines the module path and requirements. `go.sum` contains cryptographic checksums of dependencies to ensure integrity. `go mod tidy` removes unused dependencies and adds missing ones. **MVS (Minimum Version Selection)** selects the highest version of a module that satisfies all constraints in the dependency graph.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common gotcha is using `defer` inside a loop; the calls don't execute until the *outer* function returns, which can lead to resource exhaustion (e.g., leaving many files open).

**G11** — A **pointer** is a variable that stores the memory address of another value. The zero value of a pointer is `nil`. You create a pointer to a struct literal using the address-of operator: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs automatically when a package is initialized, before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source code (within the package) and follow the dependency graph of imported packages.

**G13** — `make` is used for slices, maps, and channels; it allocates and initializes the internal data structures. `new` allocates zeroed memory for any type and returns a pointer (`*T`).

**G14** — Errors are values implementing the `error` interface (a `Error() string` method). The idiomatic pattern is `if err != nil`. `errors.Is` checks if an error matches a specific value (useful for wrapped errors), while `errors.As` checks if an error matches a specific type (useful for extracting error data).

**G15** — **Map**: `nil` (can be read, but writing to it panics). **Slice**: `nil` (length/cap 0). **Channel**: `nil` (sending/receiving blocks forever). **Struct**: All fields are set to their respective zero values.

**G16** — A **race condition** occurs when two or more goroutines access the same memory concurrently, and at least one access is a write. The `-race` flag enables the runtime data race detector. 
*Example Fix*:
```go
var mu sync.Mutex
var count int
// Fix:
mu.Lock()
count++
mu.Unlock()
```

**G17** — `select` lets a goroutine wait on multiple channel operations. Unlike `switch`, which evaluates values, `select` evaluates channel readiness. If multiple cases are ready, one is chosen **pseudo-randomly**. To implement a timeout: `case <-time.After(time.Second):`.

**G18** — **Escape analysis** is a compiler optimization that determines if a variable can reside on the stack or must "escape" to the heap. Variables stay on the stack if their lifetime is strictly bounded by the function. You can inspect this with `go build -gcflags="-m"`. It matters because heap allocations increase GC pressure and latency.

**G19** — `reflect.Type` represents the metadata of a type; `reflect.Value` represents the actual data. Reflection is computationally expensive due to runtime type checking and overhead. It is justified for generic libraries (like `encoding/json`) but should be replaced by **code generation** for performance-critical paths.

**G20** — `//go:embed` allows embedding files into the binary at compile time. It works for files and directories via the `embed` package. It interacts with `io/fs.FS`, allowing you to treat embedded files as a virtual file system. Limitations include being read-only and requiring the files to be present at compile time.

## Rust

**R1** — **Ownership** is Rust's memory management system. Rules: 1. Each value has a variable called its *owner*. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is a heap-allocated, growable buffer. `&str` is an immutable string slice (a view into a string). In function signatures, use `&str` to allow the function to accept both `String` and `&str` without taking ownership.

**R3** — **Borrowing** allows accessing data without taking ownership. Rules: You can have either **one** mutable reference (`&mut T`) OR **any number** of immutable references (`&T`) at a time, but never both simultaneously.

**R4** — `Result<T, E>` represents success (`Ok`) or failure (`Err`). `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>` is for unique heap ownership. `Rc<T>` (Reference Counted) is for multiple ownership in a single thread. `Arc<T>` (Atomic Reference Counted) is for multiple ownership across multiple threads.

**R6** — **Traits** define shared behavior. Unlike Go interfaces (implicit), Rust traits must be explicitly implemented. A **trait object** (`dyn Trait`) uses dynamic dispatch (runtime), while a **generic with a trait bound** (`T: Trait`) uses static dispatch (monomorphization/compile-time).

**R7** — It fails because the compiler cannot guarantee that the returned reference lives as long as the inputs.
*Fix*: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { ... }`

**R8** — `Send` means a type can be transferred between threads. `Sync` means a type can be safely shared between threads via references. `Rc<T>` is not `Send` or `Sync` because its reference count is not updated atomically, making it unsafe for concurrency. `Arc<T>` uses atomic operations, making it safe.

**R9** — **Async/await** is a state-machine transformation. A `Future` is a trait representing a value that will eventually be available. An **executor** (like Tokio) polls futures to make progress. Unlike Go, where the runtime handles scheduling automatically, Rust's async is "lazy"—nothing happens until a future is polled by an executor.

**R10** — `unsafe` allows: 1. Dereferencing raw pointers. 2. Calling FFI (C functions). 3. Mutating static variables. It is justified when performing low-level optimizations or interacting with hardware/C libraries where the compiler cannot guarantee safety.

**R11** — **Pattern matching** (`match`) is a control flow construct that compares a value against patterns. `if let` is a shorthand for matching a single pattern. The compiler enforces **exhaustiveness**, meaning every possible value of the type must be handled.

**R12** — `[T; N]` is a fixed-size array on the stack. `Vec<T>` is a growable heap-allocated array. When a `Vec` exceeds capacity, it reallocates a larger buffer (usually doubling) and moves the elements.

**R13** — Rust **enums** are "sum types" (can hold data per variant), unlike C/Java enums which are just named integers. `Option<T>` is used instead of `null` to force developers to explicitly handle the "none" case, preventing null-pointer exceptions.

**R14** — `impl` defines methods for a type. `&self` is an immutable borrow; `&mut self` is a mutable borrow; `self` consumes the value (moves it). **Associated functions** (like `String::new()`) do not take `self` and are called via the type name.

**R15** — `derive` is a macro that automatically implements traits like `Debug` (printing), `Clone` (copying), `PartialEq` (equality), and `Serialize` (Serde). You cannot derive a trait if the underlying types do not also implement that trait.

**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that can hold either borrowed or owned data. It is useful for functions that only need to borrow data most of the time but must clone it if they need to modify it, avoiding unnecessary allocations.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. In the 2018 edition, the module system was simplified to allow more intuitive file-to-module mapping without requiring explicit `mod` declarations in every sub-file.

**R18** — `Pin<T>` ensures that the data at a specific memory address does not move. This is vital for **self-referential structs**, which are common in `async` state machines. `Unpin` is a marker trait for types that are safe to move even when pinned.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching to expand code. **Procedural macros** are functions that act on the AST (Abstract Syntax Tree). **Hygiene** ensures that macro-generated names do not accidentally collide with variables in the user's scope.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use. **Iterators** are often optimized into tight loops; **Generics** use monomorphization to generate specialized code for each type (static dispatch); **Trait static dispatch** resolves calls at compile time, allowing the compiler to inline code as if it were hand-written.
