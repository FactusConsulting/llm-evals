## Go

**G1** — An **array** has a fixed size defined at compile time. A **slice** is a descriptor for a contiguous segment of an array (containing a pointer, length, and capacity). When you `append` to a slice and exceed its capacity, Go allocates a new, larger array (typically doubling in size), copies the old elements to the new array, and returns a new slice pointing to the new memory.

**G2** — `var x int` declares a variable and initializes it to its zero value (`0`). `x := 0` is short-hand declaration and initialization. You **cannot** use `:=` outside of a function body, and you cannot use it to re-assign an existing variable unless it is part of a multi-variable declaration where at least one new variable is being introduced.

**G3** — A **goroutine** is a lightweight, user-space thread managed by the Go runtime, not the OS. An **OS thread** is managed by the kernel and has a much larger stack (MBs vs KBs). The **GMP model** consists of **G** (Goroutines), **M** (Machine/OS Threads), and **P** (Processors/Logical Contexts). The scheduler maps $G$ onto $M$ using $P$ to ensure efficient work-stealing and concurrency.

**G4** — **Channels** are pipes used for communication between goroutines. An **unbuffered channel** is synchronous; the sender blocks until a receiver is ready. A **buffered channel** allows sending up to $N$ elements before blocking. If you send to a **full buffered channel**, the sending goroutine blocks until a receiver removes an element.

**G5** — The `context` package handles cancellation signals, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
// If 2 seconds pass, the request is automatically canceled.
```

**G6** — Go uses **implicit interface satisfaction**: a type satisfies an interface simply by implementing its methods (no `implements` keyword). This differs from Java/C# where interfaces must be explicitly declared. The **empty interface `interface{}`** (or `any` in 1.18+) can hold any value, making it powerful for generic data handling but dangerous because it bypasses type safety and requires type assertions/switches which can panic if incorrect.

**G7** — This is unsafe due to a **data race** and lack of **memory visibility**. The compiler or CPU might reorder instructions or cache `ready` in a register, so the loop might never see the update. **Alternatives**: Use `sync.Mutex`, `sync/atomic` (e.g., `atomic.Bool`), or a channel to establish a "happens-before" relationship.

**G8** — `sync.Mutex` provides exclusive access (one holder). `sync.RWMutex` allows multiple concurrent readers OR one writer. Use `sync.Map` for high-concurrency scenarios with **disjoint keys** or **read-heavy** workloads where keys are stable. A regular `map` + `Mutex` is faster for write-heavy workloads or when many goroutines access the same keys.

**G9** — `go.mod` defines the module path and dependencies. `go.sum` contains cryptographic checksums of dependencies to ensure integrity. `go mod tidy` removes unused dependencies and adds missing ones. **MVS (Minimum Version Selection)** is the algorithm Go uses to select the lowest compatible version of a module that satisfies all requirements, ensuring reproducible builds.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common **gotcha** is using `defer` inside a loop; since defers only execute when the *function* returns, not the loop iteration, this can lead to resource exhaustion (e.g., leaking file descriptors).

**G11** — A **pointer** is a variable that stores the memory address of another value. The zero value of a pointer is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs automatically when the package is initialized, before `main()`. A package can have **multiple** `init()` functions; they execute in the order they appear in the source files (and across files based on import order).

**G13** — `make` is used for slices, maps, and channels; it initializes the internal data structures and returns an initialized value. `new` allocates zeroed memory for any type and returns a **pointer** to it.

**G14** — Errors are values implementing the `error` interface. The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error matches a specific target (including wrapped errors), while `errors.As` checks if an error matches a specific type (including wrapped errors). `==` only checks for direct equality.

**G15** — 
- **Map**: `nil`
- **Slice**: `nil`
- **Channel**: `nil`
- **Struct**: Zero value of its fields.

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one access is a write. The `-race` flag enables the dynamic race detector.
*Example Fix*:
```go
// Bad: count++ (race)
// Good:
var mu sync.Mutex
mu.Lock()
count++
mu.Unlock()
```

**G17** — `select` lets a goroutine wait on multiple channel operations. Unlike `switch` (which evaluates values), `select` evaluates channel readiness. If multiple cases are ready, one is chosen **pseudo-randomly**. To implement a timeout: `case <-time.After(time.Second):`.

**G18** — **Escape analysis** is a compiler optimization that determines if a variable can reside on the **stack** (fast, automatic cleanup) or must "escape" to the **heap** (slower, GC managed). Variables escape if they are returned from a function, shared via pointers to long-lived objects, or are too large. Use `go build -gcflags="-m"` to inspect. Minimizing heap allocations reduces GC pressure and improves performance.

**G19** — `reflect.Type` describes the metadata (name, kind, etc.), while `reflect.Value` represents the actual data. Reflection is computationally expensive due to runtime type checking and overhead. It is justified for generic libraries (like JSON encoders) but should be replaced by **code generation** in performance-critical paths.

**G20** — `//go:embed` allows embedding files into the binary at compile time. It works for single files or entire directories using `embed.FS`. Limitations include the files must be within the module's directory. It integrates with `io/fs` to provide a standard filesystem interface.

## Rust

**R1** — **Ownership** is Rust's memory management system. Rules: 1. Each value has a variable called its *owner*. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable string. `&str` is a string slice (a view into a string). Use `String` when you need to own/mutate the data, and `&str` in function signatures to allow the function to accept both `String` and `&str` (flexibility).

**R3** — **Borrowing** allows accessing data without taking ownership. Rules: You can have **either** any number of immutable references (`&T`) **OR** exactly one mutable reference (`&mut T`) at any given time. You cannot have both simultaneously.

**R4** — `Result<T, E>` represents success/failure; `Option<T>` represents presence/absence. The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>` is for heap allocation with a single owner. `Rc<T>` (Reference Counted) allows multiple owners on a single thread. `Arc<T>` (Atomic Reference Counted) allows multiple owners across multiple threads safely.

**R6** — **Traits** define shared behavior (similar to interfaces). **Trait objects** (`dyn Trait`) use dynamic dispatch (vtable lookup at runtime). **Generics with trait bounds** (`T: Trait`) use static dispatch (monomorphization at compile time), which is faster.

**R7** — It fails because the compiler cannot guarantee that the returned reference lives as long as the inputs. Fix with **lifetimes**:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** — `Send` means a type can be transferred between threads. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send` because its internal reference count is not atomic, leading to data races. `Arc<T>` uses atomic operations, making it safe for concurrent use.

**R9** — Rust's async is **poll-based**. A `Future` is a state machine that does nothing until `poll()` is called. An **executor** (like Tokio) manages these futures, calling `poll` until they are ready. Unlike Go's preemptive goroutines, Rust's async is **cooperative**; a task must yield (via `.await`) to allow others to run.

**R10** — `unsafe` allows bypassing certain compiler checks. You can: 1. Dereference raw pointers. 2. Call FFI (C functions). 3. Mutate static variables. It is justified when interfacing with hardware or C libraries where the compiler cannot prove safety.

**R11** — **Pattern matching** (`match`) is a control flow construct that compares a value against a series of patterns. `if let` is a concise way to handle a single pattern. `match` is **exhaustive**; the compiler forces you to handle every possible case.

**R12** — `Vec<T>` is a heap-allocated, growable array. `[T; N]` is a fixed-size array on the stack. When a `Vec` exceeds capacity, it reallocates a larger block of memory, moves the elements, and deallocates the old block.

**R13** — Rust **enums** are "sum types" (can hold data per variant), unlike C enums (integers). `Option<T>` is an enum (`Some(T)` or `None`) used to represent optionality, eliminating `null` and preventing null-pointer exceptions.

**R14** — `impl` blocks define methods for a type. `&self` borrows immutably; `&mut self` borrows mutably; `self` consumes the value (moves ownership). **Associated functions** (like `new`) do not take `self` and are called on the type itself.

**R15** — `#[derive]` is a macro that automatically implements common traits. Examples: `Debug` (printing), `Clone` (copying), `PartialEq` (equality), `Serialize` (conversion to formats like JSON). You cannot derive a trait if its requirements (like `Clone`) aren't met by the types it contains.

**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that can hold either borrowed or owned data. It is useful for functions that mostly read data but occasionally need to modify it, avoiding unnecessary allocations unless a mutation occurs.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. The **2018 edition** moved to a more intuitive module system where the file system structure maps directly to the module tree without needing explicit `mod` declarations for every file in a folder.

**R18** — `Pin<T>` ensures that the data it points to cannot be moved in memory. This is critical for **self-referential structs** (common in `async` futures where a future might hold a reference to its own data). `Unpin` is a marker trait for types that are safe to move even after being pinned.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching on code tokens. **Procedural macros** are functions that run at compile time to transform code (derive, attribute, or function-like). **Hygiene** ensures that macro-generated variables don't accidentally collide with variables in the user's scope.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use. **Iterators** are optimized into tight loops; **Generics** use **monomorphization** (generating specialized code for each type used); **Static dispatch** resolves calls at compile time, making them as fast as manual C code.
