## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted with `undefined`. `let` and `const` are block-scoped and hoisted into the Temporal Dead Zone (TDZ), meaning they cannot be accessed before declaration. `const` prevents reassignment of the identifier. **Hoisting** is the behavior where declarations are moved to the top of their scope during the compile phase.

**JS2** — The **Event Loop** manages asynchronous execution. The **Call Stack** handles synchronous tasks. When an async task completes, its callback enters the **Microtask Queue** (Promises, `queueMicrotask`) or the **Macrotask Queue** (setTimeout, setInterval, I/O). Microtasks are processed entirely after the current task and before the next macrotask.

**JS3** — A **closure** is a function that retains access to its lexical scope even when executed outside that scope. *Example:* A function returning a counter. *Classic Bug:* Using `var` in a `for` loop with `setTimeout` results in all callbacks seeing the final value of the variable. *Fix:* Use `let` (block-scoped) or an IIFE to create a new scope for each iteration.

**JS4** — A **Promise** represents the eventual completion of an async operation. `async/await` is syntactic sugar for working with Promises. Error handling: `try/catch` is used with `await`; `.catch()` is used with Promise chains. `Promise.all` rejects immediately if *any* promise fails; `Promise.allSettled` waits for all to finish, regardless of success/failure.

**JS5** — **Interfaces** define the shape of an object and support "declaration merging" (extending via multiple definitions). **Types** are used for unions, primitives, and aliases. Use `interface` for public API object shapes; use `type` for complex logic/unions. **Discriminated unions** use a common literal property (a "tag") to allow TypeScript to narrow the type in a conditional block.

**JS6** — **Prototypal inheritance** means objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with `proto` as its direct prototype. **ES6 Classes** are "syntactic sugar" over the existing prototypal system; they don't introduce a new inheritance model but simplify the syntax for creating constructor functions and managing the prototype chain.

**JS7** — `this` refers to the execution context. **Binding Rules (Priority):** 1. `new` keyword (new instance), 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (the object calling the method), 4. Default (global object or `undefined` in strict mode). `bind()` returns a **new function** with a fixed `this` context and **cannot be re-bound**.

**JS8** — `WeakRef` allows holding a reference to an object without preventing it from being garbage collected (GC). `FinalizationRegistry` allows a callback to run after an object is GC'd. Use them for memory-sensitive caches. `WeakMap` keys must be objects so that if the only reference to the key is the map itself, the key (and value) can be GC'd.

**JS9** — V8 optimizes via **Hidden Classes** (tracking object shapes) and **Inline Caching** (storing offsets for property access). **Deoptimization** occurs when the engine's assumptions are broken (e.g., changing an object's shape by adding properties later or changing a property's type), forcing the engine to fall back to slower, generic code.

**JS10** — **Tree-shaking** is the removal of unused code during build. It works with **ES Modules** because `import/export` are static and analyzable at build time. **CommonJS** (`require`) is dynamic/runtime-based, making it impossible for bundlers to safely determine if a module is truly unused without running the code.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion; `===` checks both value and type. **Nullish coalescing (`??`)** returns the right side only if the left is `null` or `undefined`. **Optional chaining (`?.`)** short-circuits and returns `undefined` if the operand is nullish.

**JS12** — `map()` creates a new array by transforming elements; `filter()` creates a subset based on a predicate; `reduce()` accumulates values into a single result. `reduce()` needs an initial value to handle empty arrays safely. `flatMap()` maps each element to an array and then flattens the result by one level, useful for normalizing nested data.

**JS13** — **Template literals** use backticks (`` ` ``) for multi-line strings and interpolation. **Tagged templates** allow a function to parse the template. *Example:* `const sql = (strings, ...vals) => ...` can be used to sanitize inputs for SQL queries by intercepting the strings and values.

**JS14** — **Destructuring** extracts values from arrays/objects. *Object:* `const {a, b} = obj`. *Array:* `const [x, y] = arr`. *Default:* `const {a = 1} = obj`. *Renaming:* `const {a: newName} = obj`. The **rest operator (`...`)** collects remaining elements into a new array or object.

**JS15** — `for...in` iterates over enumerable **keys** (properties) of an object. `for...of` iterates over the **values** of an iterable (like an array). Avoid `for...in` on arrays because it iterates over all enumerable properties (including non-index properties) and does not guarantee order.

**JS16** — **Generics** allow functions/classes to work with multiple types. `extends` constrains a type: `<T extends string>`. **Conditional types** use ternary logic: `T extends string ? number : string`. The `infer` keyword allows you to "extract" a type from another: `type Unpack<T> = T extends Array<infer U> ? U : T`.

**JS17** — **CommonJS** uses `require`/`module.exports` (synchronous, runtime). **ES Modules** use `import`/`export` (static, compile-time). Node.js handles both, but ESM is the standard. Setting `"type": "module"` in `package.json` tells Node to treat `.js` files as ES Modules.

**JS18** — TS is **structural** (if it looks like a duck, it is a duck). **Excess property checks** occur when assigning an object literal directly to a type that has more properties than the literal. `extends` is for subtyping; `satisfies` validates that an expression matches a type without changing the inferred type of the expression. **Variance**: `in` (contravariant) and `out` (covariant) define how subtyping relates to complex types like functions.

**JS19** — `Proxy` wraps an object to intercept operations; `Reflect` provides methods to perform those same operations. *Example:* A Proxy can intercept `get` to log access or `set` to validate that a value is a number before assignment.

**JS20** — `SharedArrayBuffer` allows multiple Web Workers to share the same raw memory. **Atomics** provides thread-safe operations (like `add`, `load`, `store`) to prevent race conditions. `Atomics.wait` pauses a thread until a value changes, and `Atomics.notify` wakes up threads waiting on a specific index.

## Bash

**B1** — `$@` and `$*` both represent all arguments. `"$@"` (quoted) preserves each argument as a separate string, which is safe for spaces. `"$*"` (quoted) joins all arguments into a single string.

**B2** — `set -e` (exit on error), `-u` (error on unset variables), `-o pipefail` (the pipeline returns the exit code of the last command to fail, not just the last command in the pipe).

**B3** — `$(command)` is command substitution (modern). `` `command` `` is the legacy version. `$((expression))` is for arithmetic expansion. `expr` is an external program for math.

**B4** — **Process substitution** `<(command)` treats the output of a command as a file. *Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands as if they were files.

**B5** — Use `while read -r line; do ... done < file` or `find . -print0 | xargs -0`. `for f in $(ls)` is dangerous because it splits on any whitespace, breaking filenames with spaces.

**B6** — `<<EOF` is a **here document** (multi-line input). `<<<` is a **here string** (single line). `<<-EOF` strips leading **tabs** from the input, which is useful for indented code blocks.

**B7** — `cmd > file 2>&1` redirects stdout to a file and then redirects stderr to the same place as stdout. `cmd 2>&1 > file` redirects stderr to the *original* stdout (the terminal) and then redirects stdout to a file. `&> file` is a shorthand for both to the same file.

**B8** — `mkdir` is preferred for locking because it is an **atomic operation** at the OS level; if two processes try to `mkdir` the same path, only one will succeed. *Function:* `lock() { mkdir /tmp/lock || exit 1; trap 'rmdir /tmp/lock' EXIT; }`.

**B9** — `'...'` (single) is literal (no expansion). `"..."` (double) allows variable expansion and command substitution. No quotes allows word splitting and globbing. *Example:* `echo "$VAR"` vs `echo '$VAR'`.

**B10** — `-f` (file), `-d` (directory), `-r` (readable). `[ ]` is the standard `test` command; `[[ ]]` is a Bash keyword that is more powerful (supports regex and logical operators like `&&`).

**B11** — `$?` (exit status of last command), `$$` (PID of current script), `$!` (PID of last background job), `$#` (number of arguments).

**B12** — `function foo {}` is Bash-specific; `foo() {}` is POSIX-compliant. Functions return an exit status (0-255) via `return`, but actual data is usually passed via `stdout` (`echo`).

**B13** — `PATH` is a list of directories searched for commands. **Builtins** are part of the shell; **External** commands are files in `PATH`. Use `type -a command` to see which is being used.

**B14** — `trap 'handler' SIGNAL` catches signals. `EXIT` is a special "signal" for script termination. Multiple signals are handled sequentially as they arrive.

**B15** — `xargs` reads from stdin. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P N` runs up to N processes in parallel.

**B16** — Arrays: `arr=(1 2 3)`. Associative: `declare -A map`. Append: `arr+=(4)`. Length: `${#arr[@]}`. Iterate: `for i in "${arr[@]}"`.

**B17** — `(...)` is a **subshell** (new process, new variable scope). `{ ...; }` is a **group command** (same shell, same scope). Piping into `while` creates a subshell, so variable changes inside the loop are lost when the loop ends.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (request stop), `SIGHUP` (terminal closed), `SIGKILL` (immediate/unblockable). Graceful shutdown: `trap 'cleanup_func' SIGTERM`.

**B19** — `split -l 1000 log.txt part_ && ls part_* | xargs -P 4 -I {} bash -c 'process {}'`. Trade-off: Parallelism increases speed but increases CPU/IO contention. Error propagation requires checking exit codes of each sub-process.

**B20** — `exec` replaces the current shell with the command. `exec 3>file` opens FD 3. A **coprocess** (`coproc`) allows a background process to communicate with the shell via pipes.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline; `Write-Host` sends text directly to the host (screen). `Write-Host` cannot be captured by a pipeline.

**PS2** — `ForEach-Object` is a cmdlet (works on pipeline objects); `foreach` is a language keyword (faster, works on collections in memory).

**PS3** — `[PSCustomObject]` is an ordered object with properties; `[hashtable]` is a key-value collection. Convert: `[PSCustomObject]@{k=v}` or `[hashtable]@{k=v}`.

**PS4** — **Terminating** errors stop execution; **non-terminating** errors allow the script to continue. `try/catch` only catches terminating errors unless you use `-ErrorAction Stop` on a cmdlet.

**PS5** — **Splatting** uses a hashtable to pass multiple parameters: `$p = @{Name="A"; Age=1}; Get-User @p`. It differs from passing a single hashtable as a parameter because it expands the keys into individual argument names.

**PS6** — `Invoke-Command` is for remote execution (one-to-many); `Enter-PSSession` is for interactive sessions. It uses **WinRM** (WS-Man) or **SSH**.

**PS7** — If a function returns an empty array, `$x.GetType().Name` will be `Object[]`. If it returns one item, it becomes the object itself (e.g., `String`). The correct pattern is to force an array: `$x = @(Get-Items)`.

**PS8** — A `[scriptblock]` is a piece of code. To pass variables to remote sessions, use `$using:var`. The **double-hop problem** occurs when a remote session cannot use your credentials to access a *third* machine. Solve with **CredSSP** or Kerberos delegation.

**PS9** — `@()` creates an array. `[array]` is a type. To force a single result into an array, use `@($result)`. Indexing `$null` causes an error; an empty array returns `$null`.

**PS10** — `-eq` is case-insensitive; `-ceq` is case-sensitive. `-contains` checks if a collection contains a value; `-in` checks if a value exists within a collection.

**PS11** — `.psm1` is a script module; `.psd1` is a manifest (metadata); Binary is a DLL. `Import-Module` loads the module into the session.

**PS12** — `"$var"` is interpolated; `'$var'` is literal. Use `"$($expression)"` for expressions. `@' ... '@` is a here-string.

**PS13** — `Get-Member` shows properties and methods. `Select-Object` picks specific properties; `Where-Object` filters the objects themselves.

**PS14** — **Classes** are strongly typed and support inheritance. They are more rigid than functions. Use classes for complex data structures; use functions for procedural tasks.

**PS15** — `[CmdletBinding()]` enables common parameters (`-Verbose`, etc.). `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` blocks allow fine-grained control over pipeline processing.

**PS16** — **Providers** allow PowerShell to treat different data stores (Registry, Cert, Env) as drives. `cd Registry::HKEY_LOCAL_MACHINE`.

**PS17** — `[runspace]` is a single thread. `[runspacepool]` manages multiple threads. `ForEach-Object -Parallel` (v7+) is a high-level abstraction for running tasks in parallel.

**PS18** — **PSScriptAnalyzer** is a static code analysis tool. It uses rules and severity levels. Suppress via `# PSScriptAnalyzer Ignore RuleName`.

**PS19** — `$using:scope` is required for remote/parallel sessions to access local variables. **Serialization** (CLIXML) can strip complex types/methods when objects move across boundaries.

**PS20** — **DSC** uses a Local Configuration Manager (LCM) to ensure a machine reaches a "desired state." Modern IaC has largely moved toward tools like **Ansible, Terraform, or Pulumi**.
