## .NET / C#

**DN1**: A **class** is a reference type (allocated on the heap), while a **struct** is a value type (usually allocated on the stack). Use a struct for small, immutable data structures (PODs - Plain Old Data) that are short-lived to reduce Garbage Collector (GC) pressure.

**DN2**: `IEnumerable<T>` provides a read-only forward-only cursor over a collection (client-side filtering). `IQueryable<T>` extends this by providing an expression tree that allows providers (like EF Core) to translate filters into SQL and execute them on the database server. This distinction prevents "over-fetching" data into application memory.

**DN3**: `async/await` uses a state machine to perform non-blocking I/O. A `Task` represents an ongoing operation and is a class (heap allocation). A `ValueTask` is a struct; it is used when a method often completes synchronously, avoiding a heap allocation if the result is already available.

**DN4**: Dependency Injection (DI) manages object lifetimes:
*   **Transient**: Created every time they are requested.
*   **Scoped**: Created once per client request (e.g., HTTP request).
*   **Singleton**: Created once for the lifetime of the app.
**Common Bug**: Injecting a Scoped service into a Singleton creates a **Captive Dependency**, where the scoped service effectively becomes a singleton, potentially leading to stale data or threading issues (especially with DbContext).

**DN5**: `string` is an immutable heap object. `ReadOnlySpan<char>` is a stack-allocated view of a contiguous region of memory. Use `Span<T>` or `ReadOnlySpan<T>` for high-performance slicing and parsing because they avoid creating new string allocations during operations like `Substring`.

**DN6**: The GC uses generations to optimize collection: **Gen 0** (short-lived), **Gen 1** (buffer), and **Gen 2** (long-lived). The **Large Object Heap (LOH)** handles objects >85KB to avoid expensive memory compaction. `IDisposable` is needed for unmanaged resources (file handles, sockets) because the GC only tracks managed memory.

**DN7**: `ConfigureAwait(false)` tells the task not to marshal back to the original `SynchronizationContext` (like the UI thread). Use it in library code to prevent deadlocks and improve performance. Do NOT use it in application code that must update UI elements directly.

**DN8**:
*   **Primary Constructors**: Define parameters directly on the class declaration.
*   **Collection Expressions**: Simplified syntax using brackets `[...]`.
*   **FrozenDictionary**: A read-only dictionary optimized for extremely fast lookups.

```csharp
// Minimal DI example with Primary Constructor
public class UserService(IUserRepository repository) {
    public async Task<User> GetUser(int id) => await repository.GetByIdAsync(id);
}
```

**DN9**: Likely cause: **DbContext Threading**. `DbContext` is not thread-safe. High concurrency often reveals cases where a single scoped context is shared across multiple asynchronous tasks or leaked into a background thread. Fix: Ensure each request has its own scope and avoid sharing the context across threads; use `IServiceScopeFactory` if creating background tasks.

**DN10**: A **record** provides value-based equality by default, whereas a **class** uses reference equality. A **record struct** combines record features with value-type performance. Choose records for DTOs/immutable data; classes for complex behavior/stateful objects.

**DN11**: 
*   `ref`: Passes by reference; variable must be initialized before passing.
*   `out`: Passes by reference; method *must* initialize it before returning.
*   `in`: Passes by reference but makes the variable read-only (prevents modification).

**DN12**: Nullable Reference Types (`string?`) are static analysis hints to prevent `NullReferenceException`. They differ from nullable value types (`int?`), which are actual runtime wrappers (`Nullable<T>`). NRTs do not change the runtime representation of the object.

**DN13**: LINQ allows querying collections. **Method syntax** (`list.Where(...)`) is fluent and concise; **Query syntax** (`from x in list...`) resembles SQL. **Deferred execution** means the query is defined but not executed until you iterate over it (e.g., via `foreach` or `.ToList()`).

**DN14**: Constraints restrict generic types:
*   `where T : class`: Must be a reference type.
*   `where T : struct`: Must be a value type.
*   `where T : new()`: Must have a public parameterless constructor.
*   `where T : IComparable<T>`: Must implement that interface.
Combine them for specific requirements, e.g., `where T : class, new()` ensures a reference type that can be instantiated.

**DN15**: An **abstract class** defines "what an object is" (inheritance/state), while an **interface** defines "what an object can do" (contract). Default Interface Methods allow adding logic to interfaces without breaking existing implementations, blurring the line slightly by allowing behavior in interfaces.

**DN16**: The pipeline is a series of delegates called in order. 
*   `.Use()`: Can call the next middleware.
*   `.Map()`: Branches the pipeline based on path.
*   `.Run()`: Terminal middleware; stops the chain.
Ordering matters because requests flow through sequentially. Exception handling middleware must be placed first to catch errors from all subsequent steps.

**DN17**: `Channel<T>` is a high-performance producer-consumer queue. Unlike `BlockingCollection`, it supports `async/await` natively. Bounded channels provide backpressure: if the channel is full, the producer's `WriteAsync` will asynchronously wait until space becomes available.

**DN18**: Source Generators produce C# code during compilation. Reflection happens at runtime; IL weaving modifies binary files after compilation. **Incremental generators** are optimized to only re-generate parts of the code that changed, significantly improving IDE performance over `ISourceGenerator`.

**DN19**: TPL Dataflow provides blocks for processing pipelines. `ActionBlock` consumes data, `TransformBlock` transforms input $\rightarrow$ output, and `BufferBlock` acts as a queue. Compared to Channels (which are simple queues), TPL Dataflow allows building complex Directed Acyclic Graphs (DAGs) of processing logic.

**DN20**: Minimal APIs use lambda endpoints instead of Controllers. They offer faster startup and less boilerplate. Trade-offs: they can become disorganized in large apps. Route groups organize endpoints, and endpoint filters allow cross-cutting concerns (like validation) without full middleware overhead.

## Python

**P1**: A **list** is mutable; a **tuple** is immutable. A **set** contains unique elements and is mutable; a **frozenset** is an immutable version of a set.

**P2**: The GIL prevents multiple native threads from executing Python bytecodes simultaneously. It affects CPU-bound workloads. Workarounds include using the `multiprocessing` module (separate processes) or writing C extensions/using libraries like NumPy.

**P3**: `copy` creates a shallow copy (copies references); `deepcopy` recursively copies everything. 
*Example*: If you have `a = [[1], [2]]`, a shallow copy `b = copy.copy(a)` results in `b[0].append(3)` modifying both `a` and `b`.

**P4**: Decorators wrap functions to modify behavior.
```python
import time
from functools import wraps

def log_time(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"Execution time: {time.perf_counter() - start:.4f}s")
        return result
    return wrapper
```

**P5**: Generators use `yield` to produce values one at a time lazily, returning an iterator rather than a full list in memory. `yield from` allows a generator to delegate part of its operations to another generator.

**P6**: The event loop schedules tasks. `asyncio.run()` starts the loop; `gather()` runs multiple coroutines concurrently; `create_task()` schedules a task for background execution. `time.sleep()` is blocking; it stops the entire thread (and the loop). Use `await asyncio.sleep()`.

**P7**: Python uses C3 Linearization for MRO. In diamond inheritance, it searches depth-first but ensures parents are visited after children. For `D(B, C)`, the order is `[D, B, C, A]`. Since `B` doesn't define `who`, it checks `C`. Output: `"C"`.

**P8**: A **metaclass** is a class that creates classes. `__init_subclass__` is a simpler way to customize subclass creation without a metaclass. 
*Metaclass*: Enforcing API constraints across all subclasses globally.
*`__init_subclass__`*: Registering a subclass into a registry automatically upon definition.

**P9**: 
*   **Threading**: Best for I/O bound tasks (shared memory).
*   **Multiprocessing**: Best for CPU bound tasks (bypasses GIL).
*   **Concurrent.futures**: High-level wrapper for both via `ThreadPoolExecutor` and `ProcessPoolExecutor`.
Multiprocessing requires **pickling** (serialization) to send data between processes, which can be slow or fail for complex objects.

**P10**: `__slots__` tells Python not to create a `__dict__` for each instance. It prevents dynamic attribute addition and significantly reduces memory usage per object by using fixed-size arrays instead of dictionaries.

**P11**: A virtual environment isolates project dependencies. `venv` is the standard library tool; `virtualenv` is an older, more feature-rich alternative; `conda` manages both Python packages and non-Python binary dependencies (C++ libraries, etc.).

**P12**: Comprehensions provide concise ways to create collections: `[x for x in list]` (list), `{x for x in list}` (set), `{k: v for ...}` (dict). They are generally faster and more readable than `map()` and `filter()`, though generators (`(...)`) should be used for very large datasets.

**P13**: `==` checks value equality; `is` checks identity (memory address). Small integers (-5 to 256) are interned by Python, meaning they point to the same memory location, so `a is b` returns True for these values.

**P14**: `*args` collects positional arguments into a tuple; `**kwargs` collects keyword arguments into a dictionary. `/` marks parameters that *must* be positional; `*` marks all following parameters as *keyword-only*.

**P15**: Context managers handle setup/teardown via the `with` statement.
*   Class way: Define `__enter__` and `__exit__`.
*   Decorator way: Use `@contextmanager` with `yield`.
Example: A database transaction manager that commits on success or rolls back on exception.

**P16**: Type hinting provides static analysis hints. `Union` (A or B), `Optional` (T or None), `Literal` (specific constant values), `TypeVar` (generics), and `Protocol` (structural typing/interfaces). Tools like Mypy check these without executing the code.

**P17**: Dunder methods define object behavior. `repr` is for developers; `str` is for users. `eq` defines equality; if you override `eq`, you must override `hash` to keep the object hashable (for sets/dicts). `getattr` handles missing attributes; `getattribute` intercepts every access.

**P18**: Descriptors are objects implementing `__get__`, `__set__`, or `__delete__`. They allow custom logic during attribute access. `@property`, `@classmethod`, and `@staticmethod` are all implemented as descriptors under the hood.

**P19**: The import system uses **finders** (to locate modules) and **loaders** (to load them into memory). Absolute imports start from the root; relative imports use `.`. Namespace packages allow a single package to be spread across multiple directories by omitting `__init__.py`.

**P20**: `dataclasses` automate boilerplate (`__init__`, `__repr__`). `attrs` provides more power; Pydantic adds runtime validation. Use Pydantic for data entering your system (API requests); use dataclasses for internal state. `__post_init__` allows logic after initialization.
