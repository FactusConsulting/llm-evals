## Go

**G1**: An **array** has a fixed size defined at compile time; a **slice** is a descriptor for a contiguous segment of an underlying array. When you append to a slice that has reached its capacity, Go allocates a new, larger array (typically doubling the size), copies existing elements over, and returns a new slice pointing to this new array.

**G2**: `var x int` declares a variable with its zero value (0). `x := 0` is short-variable declaration which both declares and initializes. You cannot use `:=` at the package/global scope or when declaring a variable without providing an initial value.

**G3**: A **goroutine** is a lightweight thread managed by the Go runtime. Unlike OS threads (which have large stacks ~MBs), goroutines start small (~2KB) and grow dynamically. The **GMP model** consists of **G** (Goroutine), **M** (Machine/OS Thread), and **P** (Processor/Context). P schedules Gs onto Ms, allowing M:N multiplexing to minimize context switching overhead.

**G4**: Channels are typed conduits for communication. **Unbuffered channels** provide synchronous communication (rendezvous); the sender blocks until a receiver is ready. **Buffered channels** allow sending values without an immediate receiver up to the buffer limit. If a buffered channel is full, the sender blocks until space becomes available.

**G5**: The `context` package manages deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
_, err := http.DefaultClient.Do(req) // Cancels if it takes > 2 seconds
```

**G6**: Go uses **implicit satisfaction**. A type satisfies an interface by implementing its methods; no `implements` keyword is needed. This differs from Java/C# where interfaces must be explicitly declared. `interface{}` (or `any`) can hold any value. It is powerful for generic containers but dangerous because it bypasses compile-time type safety, requiring runtime type assertions.

**G7**: Go's memory model does not guarantee that writes in one goroutine are visible to another without synchronization. In the example, the loop may run forever or read stale data because there is no "happens-before" relationship between the write to `ready` and the read. Correct alternatives: use a `sync.Mutex`, `atomic.Bool`, or a channel signal (`chan struct{}`).

**G8**: `sync.Mutex` provides exclusive access. `sync.RWMutex` allows multiple concurrent readers OR one writer. Use `sync.Map` when you have high contention with many reads and few writes, or when keys are disjoint across threads. Regular maps + mutex are generally faster for most common workloads due to lower overhead per operation.

**G9**: Modules manage dependencies via `go.mod` (defines requirements) and `go.sum` (cryptographic checksums of versions). `go mod tidy` adds missing modules and removes unused ones. **Minimum Version Selection (MVS)** ensures reproducible builds by selecting the *lowest* version that satisfies all constraints, rather than always picking the latest.

**G10**: `defer` schedules a function call to execute immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In-First-Out)** order. A common gotcha is using `defer` inside a loop; since they only run at the end of the function, resources may not be released until the entire loop finishes, potentially causing resource exhaustion.

**G11**: A pointer stores the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `p := &User{Name: "Alice"}`.

**G12**: `init()` functions perform package initialization. They run once per package upon startup, after variable initialization but before `main()`. A package can have multiple `init()` functions across different files; they execute in lexical order within a file and dependency order between packages.

**G13**: `new(T)` allocates zeroed memory for type `T` and returns its address (`*T`). `make` is used specifically for slices, maps, and channels to initialize their internal data structures and return the initialized object itself.

**G14**: Go treats errors as values returned as the last parameter. The `error` interface has one method: `Error() string`. Idiomatic check: `if err != nil { ... }`. `errors.Is` checks if an error wraps a specific target (equality), while `errors.As` attempts to cast/assign an error to a specific type.

**G15**: 
- **Map**: Zero value `nil`.
- **Slice**: Zero value `nil`.
- **Channel**: Zero value `nil`.
- **Struct**: Fields are set to their respective zero values.

**G16**: A race condition occurs when two goroutines access the same memory concurrently and at least one is a write. `-race` uses ThreadSanitizer to detect this at runtime. Fix: wrap shared state in a `sync.Mutex` or communicate via channels to "share memory by communicating."

**G17**: `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, it blocks until *one* of its cases can proceed. If multiple are ready, one is chosen pseudo-randomly. Timeout implementation: `case <-time.After(duration):`.

**G18**: Escape analysis determines whether a variable should be allocated on the stack or heap. If a reference to a local variable is returned or stored globally, it "escapes" to the heap. Inspect using `go build -gcflags="-m"`. Heap allocation increases GC pressure; keeping data on the stack improves performance.

**G19**: The `reflect` package allows runtime introspection. `reflect.Type` describes the type (metadata), while `reflect.Value` represents the actual instance. Reflection has high overhead due to boxing/interface conversions. It's justified for generic libraries (e.g., JSON encoders) where types aren't known at compile time; otherwise, code generation is preferred for performance.

**G20**: `//go:embed` embeds static files into the binary. Single files use `//go:embed file.txt`; directories use `//go:embed folder/*`. It returns an `embed.FS` which implements `io/fs.FS`. Limitations include read-only access and only supporting static assets available at build time.

## Rust

**R1**: Ownership ensures memory safety without a garbage collector. Rules: 1) Each value has one owner. 2) There can only be one owner at a time. 3) When the owner goes out of scope, the value is dropped.

**R2**: `String` is an owned, growable, heap-allocated string. `&str` is a borrowed slice (reference) to a string. In function signatures, prefer `&str` as it accepts both `&String` and literal strings, making the API more flexible.

**R3**: The borrow checker enforces that you may have either **one mutable reference (`&mut T`) OR any number of immutable references (`&T`)**, but not both simultaneously. This prevents data races at compile time.

**R4**: `Result<T, E>` handles recoverable errors; `Option<T>` handles optional values. The `?` operator unwraps a `Result`/`Option` or returns the error early from the current function.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path) // Returns Result
}
```

**R5**: `Box<T>` provides single ownership on the heap. `Rc<T>` allows multiple shared owners in a single thread via reference counting. `Arc<T>` (Atomic Rc) does the same but is thread-safe using atomic counters.

**R6**: Traits define shared behavior (similar to interfaces). Go's are implicit; Rust's are explicit. A trait bound `T: Trait` uses static dispatch (monomorphization), creating specific code for each type. A trait object `dyn Trait` uses dynamic dispatch via a vtable, allowing heterogeneous collections.

**R7**: Lifetimes ensure references don't outlive their data. The example fails because the compiler doesn't know if the returned reference comes from `x` or `y`. Fix by adding lifetime annotations: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8**: `Send` indicates a type can be transferred between threads. `Sync` indicates a type can be referenced across threads. `Rc<T>` isn't `Send`/`Sync` because its counter is non-atomic; updating it from two threads would cause a race condition. `Arc<T>` solves this with an atomic counter.

**R9**: Async/await transforms functions into state machines. A `Future` is a trait that represents a value that will eventually exist. An **executor** (like Tokio) polls futures until they complete. Unlike goroutines (preemptive), Rust async is cooperative and poll-based.

**R10**: `unsafe` allows bypassing certain safety checks. 3 things allowed: dereferencing raw pointers, calling unsafe functions (FFI), mutating static variables. It is justified for low-level hardware access, FFI, or extreme performance optimizations where the programmer guarantees safety manually.

**R11**: Pattern matching uses `match` to handle all possible cases of an enum. `if let` is syntactic sugar for when you only care about one specific pattern. The compiler enforces exhaustiveness in `match`, ensuring no case is forgotten.

**R12**: `[T; N]` is a fixed-size array on the stack. `Vec<T>` is a growable heap-allocated vector. When capacity is exceeded, `Vec` allocates a larger block of memory (usually doubling size) and moves elements there.

**R13**: Enums are "sum types" that can carry data per variant. This differs from C enums which are just integers. `Option<T>` is an enum (`Some(T)` or `None`), replacing nulls by forcing developers to explicitly handle the absence of a value.

**R14**: An `impl` block defines implementation logic. `&self` borrows immutably, `&mut self` borrows mutably, and `self` consumes ownership. Associated functions (like `String::new()`) do not take any `self` parameter.

**R15**: `derive` is a procedural macro that auto-implements traits. Common ones: `Debug` (printing), `Clone` (duplicating), `PartialEq` (equality). You cannot derive a trait if any field within the struct does not also implement that trait.

**R16**: `Cow<'a, T>` (Clone-on-Write) allows a type to be either borrowed or owned. It avoids allocation by keeping a reference until mutation is required, at which point it clones the data into an owned version. Useful for strings where most inputs are static but some need modification.

**R17**: `mod` declares a module; `use` creates a shortcut to a path; `pub` makes items visible. In Rust 2018+, modules map directly to files/folders more intuitively than in 2015, allowing absolute paths from the crate root.

**R18**: `Pin<T>` prevents a value from being moved in memory. This is critical for async futures containing references to their own fields (self-referential structs). `Unpin` is a marker trait for types that *can* be safely moved.

**R19**: Declarative macros (`macro_rules!`) use pattern matching on tokens. Procedural macros act as compiler plugins (derive, attribute, function-like). Hygiene ensures that variables introduced inside a macro don't accidentally clash with names in the calling code.

**R20**: Zero-cost abstractions mean you don't pay for what you don't use. **Monomorphization** generates specialized versions of generic functions for each type used, removing runtime overhead. Iterators and traits compile down to assembly equivalent to hand-written C loops via LLVM optimization.
