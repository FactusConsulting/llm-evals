## JavaScript / TypeScript

**JS1**: `var` is function-scoped and hoisted (initialized to `undefined`). `let` and `const` are block-scoped and reside in the Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment. **Hoisting** is the JS engine moving declarations to the top of their scope during the compilation phase.

**JS2**: The **Event Loop** coordinates execution. The **Call Stack** handles synchronous code. When async tasks finish, they enter queues: **Microtask Queue** (Promises, `queueMicrotask`) has priority over the **Macrotask Queue** (setTimeout, I/O). The loop clears the stack, then exhausts *all* microtasks before processing one macrotask.

**JS3**: A **closure** is a function that remembers its lexical environment even when executed outside that scope. Example: `const counter = () => { let count=0; return () => ++count; };`. **Loop bug**: Using `var` in a for-loop creates one variable shared by all closures created in that loop. Fix: Use `let`, which creates a new binding per iteration.

**JS4**: **Promise** represents a future value. `async/await` is syntactic sugar for Promises. Error handling: `.catch()` for Promises, `try/catch` for `await`. `Promise.all` rejects immediately if any promise fails; `Promise.allSettled` waits for all to complete regardless of outcome.

**JS5**: **Interfaces** define object shapes and support declaration merging (adding fields later). **Types** are aliases for any type (unions, primitives, tuples). Use interfaces for public API contracts; types for complex logic. **Discriminated Unions** use a common literal property (e.g., `type: 'circle' | 'square'`) to allow TypeScript to narrow types via switch/if statements.

**JS6**: JS uses **prototypal inheritance**, where objects inherit directly from other objects. `Object.create(proto)` creates a new object with the specified prototype. ES6 classes are "syntactic sugar"; they still use prototypes under the hood (`class X extends Y` sets the prototype chain).

**JS7**: `this` refers to the execution context. Priority rules: 1) **New** (constructor), 2) **Explicit** (`call`, `apply`, `bind`), 3) **Implicit** (object method call), 4) **Default** (global window or `undefined` in strict mode). `bind()` returns a *new* function with a fixed `this`; it cannot be re-bound.

**JS8**: `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` triggers a callback after GC collects the object. `WeakMap` keys must be objects so that if no other references exist, the entry can be GC'd automatically.

**JS9**: V8 optimizes using **Hidden Classes** (assigning shapes based on property order) and **Inline Caching** (caching lookup results for those shapes). **Deoptimization** occurs when code becomes polymorphic (changing object shapes by adding properties later or changing types of variables), forcing V8 back to slower interpreted execution.

**JS10**: **Tree-shaking** is dead-code elimination. It works with ES Modules because `import/export` are static; tools know exactly what is used at compile time. CommonJS (`require`) is dynamic, meaning dependencies are resolved at runtime, making it nearly impossible for bundlers to safely remove unused exports.

**JS11**: `null` is an intentional absence of value; `undefined` means a variable was declared but not assigned. `==` performs type coercion (`null == undefined` is true); `===` checks strict equality. `??` returns the right side only if left is `null`/`undefined`. `?.` stops evaluation if the preceding reference is nullish.

**JS12**: `map()` transforms each element; `filter()` selects elements based on a predicate; `reduce()` aggregates into one value. If `reduce` has no initial value, it uses the first array element as the accumulator. `flatMap()` maps then flattens one level deep—useful for mapping 1:N relationships.

**JS13**: Template literals use backticks and `${}` for interpolation. **Tagged templates** pass the string parts and interpolated values to a function. Example (SQL): `` sql`SELECT * FROM users WHERE id = ${id}` `` allows the tag function to sanitize inputs to prevent SQL injection.

**JS14**: Destructuring extracts data from arrays/objects into variables. Object: `{ name } = obj`; Array: `[first] = arr`. Default values: `{ name = 'Guest' }`. Renaming: `{ name: userName }`. The rest operator `...` collects remaining properties into a new object or array.

**JS15**: `for...in` iterates over enumerable keys of an object (including prototype chain). `for...of` iterates over iterable values (Array, Map, Set). Avoid `for...in` on arrays because it may iterate over non-index properties added to the Array prototype.

**JS16**: Generics allow reusable components. Constraints (`T extends U`) limit what types can be passed. Conditional Types (`T extends U ? X : Y`) act as logic gates for types. `infer` is used within conditional types to extract a type from another (e.g., extracting return type from a function).

**JS17**: CommonJS uses `require`/`module.exports` (synchronous); ESM uses `import`/`export` (static/async). Node handles both via `.mjs`/`.cjs` extensions or `"type": "module"` in `package.json`, which tells Node to treat all `.js` files as ES modules.

**JS18**: Structural typing means compatibility is based on shape, not explicit inheritance. **Excess property checks** occur when assigning a literal directly to a typed variable; they are skipped if assigned via a reference. `extends` defines constraints; `satisfies` validates that a value matches a type without changing its inferred type. Variance: Covariance allows wider types (out), Contravariance narrower (in).

**JS19**: `Proxy` wraps an object to intercept operations like `get`, `set`, and `apply`. `Reflect` provides static methods that mirror these traps. Example: A reactive state system where the `set` trap triggers a UI re-render whenever a property changes.

**JS20**: `SharedArrayBuffer` provides memory shared between Web Workers. `Atomics` ensures thread-safe access to this memory. `Atomics.wait()` puts a thread to sleep until a specific index changes, and `Atomics.notify()` wakes it up, preventing race conditions.

## Bash

**B1**: `$@` and `$*` both represent all positional parameters. In double quotes, `"$@"` treats each argument as a separate quoted string; `"$*"` joins them into one single string separated by the first character of `IFS`.

**B2**: `-e`: Exit immediately if a command fails. `-u`: Treat unset variables as errors. `-o pipefail`: The pipeline return status is the value of the last (rightmost) command to exit with a non-zero status.

**B3**: `$(command)` and `` `command` `` are both subshells, but `$( )` allows nesting and handles escaping better. `$((expression))` is for shell arithmetic expansion; `expr` is an external utility that is slower and has different syntax.

**B4**: Process substitution `<(command)` makes the output of a command appear as a file. Use case: Comparing two directory listings without creating temporary files: `diff <(ls dir1) <(ls dir2)`.

**B5**: Iterate using globs (`for f in *.txt`) or `find -print0 | xargs -0`. Avoid `for f in $(ls)` because it performs word splitting on spaces/newlines in filenames, breaking the loop.

**B6**: Here document `<<EOF` sends multi-line text to stdin until "EOF" is found. Here string `<<< "string"` sends a single string to stdin. `<<-EOF` strips leading tabs from lines in the here doc.

**B7**: 
1. `cmd > file 2>&1`: Stdout goes to file $\rightarrow$ Stderr redirected to where stdout currently points (file). Result: Both in file.
2. `cmd 2>&1 > file`: Stderr redirected to current stdout (terminal) $\rightarrow$ Stdout redirected to file. Result: Stderr at terminal, Stdout in file.
3. `cmd &> file`: Shorthand for both to go to file.

**B8**: Use `mkdir lockdir` because it's an atomic operation across most filesystems. Cleanup via `trap 'rmdir lockdir' EXIT SIGTERM INT`. If the script is killed, the trap ensures the directory is removed.

**B9**: Single quotes `'...'` are literal; no expansion. Double quotes `"..."` allow variable and command interpolation. No quotes allow word splitting and globbing (e.g., `*`). Example: `echo "$VAR"` vs `echo $VAR` (the latter splits if `$VAR` contains spaces).

**B10**: `-f` checks if file exists/is regular; `-d` checks if directory; `-r` checks readability. `[ ]` is POSIX standard; `[[ ]]` is a Bash extension that supports regex (`=~`), logical operators (`&&`, `||`) without needing separate flags, and handles empty variables more safely.

**B11**: `$?`: Exit status of last command. `$$`: PID of current shell. `$!`: PID of last background process. `$#`: Number of positional arguments passed to script.

**B12**: Defined as `foo() { ... }` or `function foo { ... }`. The former is POSIX compliant. Functions return values by echoing to stdout (captured via `$( )`) or returning an exit code (0-255) using the `return` keyword.

**B13**: `PATH` is a colon-separated list of directories searched for executables. Builtins are internal to bash (`cd`, `pwd`); external commands are binaries on disk (`ls`, `grep`). Use `type -a <command>` to check.

**B14**: `trap 'handler' signal` catches signals. Common: `EXIT` (script ends), `ERR` (command fails), `INT` (Ctrl+C), `TERM` (kill). If multiple arrive, they are queued; traps execute in order of arrival.

**B15**: Command substitution returns output as a string; `xargs` converts stdin into arguments for another command. To handle spaces/newlines safely: `find . -print0 | xargs -0`. `-P N` runs up to $N$ processes in parallel.

**B16**: Arrays: `arr=(val1 val2)`; append with `arr+=("val3")`; length `${#arr[@]}`. Associative arrays require declaration: `declare -A map`; set via `map[key]=value`. Iterate associative arrays using `for key in "${!map[@]}"`.

**B17**: Subshell `(...)` forks a new process; variables changed inside are lost to the parent. Group `{ ...; }` executes in current shell scope. Piping into a while loop (`cmd | while read...`) creates a subshell, meaning variable changes inside the loop disappear after it finishes.

**B18**: SIGINT (Interrupt), SIGTERM (Terminate request), SIGHUP (Hangup), SIGKILL (Force kill—cannot be trapped). Graceful shutdown is achieved by trapping `SIGTERM`, cleaning up resources, and then exiting.

**B19**: Use `split` to chunk logs $\rightarrow$ `xargs -P N` calling a processing function. Trade-off: Parallelism increases CPU usage but can bottleneck on Disk I/O. Error propagation requires checking exit codes of child processes or writing errors to a shared log file.

**B20**: `exec` replaces the current shell process with the command's process image. For FD manipulation: `exec 3>file` opens FD 3 for writing; `exec 3>&-` closes it. A coprocess (`coproc`) allows bidirectional communication via pipes between the main script and a background process.

## PowerShell

**PS1**: `Write-Output` sends objects to the pipeline for the next cmdlet. `Write-Host` prints directly to the console host, bypassing the pipeline entirely. Using `Write-Host` in a function prevents other cmdlets from receiving that data.

**PS2**: The pipeline passes *objects*, not text. `ForEach-Object` is a cmdlet used within a pipeline (streaming); `foreach` statement is a language keyword (faster, loads entire collection into memory first).

**PS3**: `[hashtable]` is a key-value pair collection (mutable, unordered). `[PSCustomObject]` is a structured object with fixed properties. Use hashtables for lookups; PSCustomObjects for outputting data. Convert using `[PSCustomObject] @{ Key = 'Value' }`.

**PS4**: Terminating errors stop execution immediately; non-terminating errors print a warning but continue. `-ErrorAction Stop` converts a non-terminating error into a terminating one so it can be caught by a `try/catch` block. `$ErrorActionPreference` sets the global default behavior.

**PS5**: Splatting `@params` allows passing a hashtable of parameter names and values to a cmdlet. Example: `$p = @{ Path = 'C:\log'; Recurse = $true }; Get-ChildItem @p`. It differs from passing a hashtable as a single argument because PowerShell maps keys directly to parameters.

**PS6**: Remoting uses WinRM (WSMan) or SSH. `Invoke-Command -ComputerName` runs a scriptblock once on remote machines; `Enter-PSSession` creates an interactive 1:1 session. Both use serialized XML (CLIXML) over the network.

**PS7**: Implicit unrolling occurs when a function returns a collection containing only one item—PowerShell "unwraps" it, returning just that item instead of an array. If it returns 0 items, it returns `$null`. Correct pattern: force array type using `@(Get-Items)` or return `, $result` (the comma operator).

**PS8**: A `[scriptblock]` is a reusable piece of code `{ ... }`. The **double-hop problem** happens when credentials passed to a remote server cannot be delegated further to another server. Solve via CredSSP or by explicitly passing credentials in `-ArgumentList`.

**PS9**: `@()` ensures the result is always an array, even if there's one or zero results. Indexing into `$null` or an empty array both return `$null`, but indexing into a non-array object may cause errors unless handled as a collection.

**PS10**: Comparison operators are case-insensitive (`-eq`). Case-sensitive versions start with 'c' (`-ceq`). `-contains` checks if a collection contains a value; `-in` does the same but reverses the order of operands.

**PS11**: Modules package cmdlets/functions. `.psm1` contains logic; `.psd1` is a manifest for metadata and dependencies. Binary modules are .NET DLLs. `Import-Module` loads these into the current session scope.

**PS12**: Double quotes `"..."` allow interpolation; single quotes `'...'` are literal. Use `$(expression)` inside double quotes for complex expressions. Here-strings `@" ... "@` allow multi-line strings without escaping.

**PS13**: `Get-Member` lists properties and methods of an object. Properties store data; Methods perform actions. NoteProperties are custom properties added dynamically. `Select-Object` filters columns (properties); `Where-Object` filters rows based on criteria.

**PS14**: PS Classes provide strong typing and constructors. They differ from C# classes in that they lack interfaces and have limited inheritance capabilities. Use classes for structured data models; functions for operational tasks.

**PS15**: `[CmdletBinding()]` enables advanced features like `-Verbose`, `-WhatIf`. `SupportsShouldProcess` allows `-WhatIf`/`-Confirm`. The `Process` block handles pipeline input one by one, while `Begin` and `End` run once at start and finish.

**PS16**: Providers map different stores as drives. `FileSystem` is standard; `Registry` maps HKLM/HKCU as drives (`HKLM:\`). You can use `Get-ChildItem` to browse the registry exactly like a folder structure.

**PS17**: A `runspace` is an isolated execution environment. For parallel execution: `ForEach-Object -Parallel` (v7+) uses a runspace pool internally. Manual runspaces offer more control but require managing thread safety and synchronization manually.

**PS18**: PSScriptAnalyzer is a static analysis tool. It enforces standards via rules with severity levels (Error, Warning). Rules are suppressed using attributes like `[Diagnostics.SuppressMessage()]` and integrated into CI pipelines as linting steps.

**PS19**: `$using:` scope lets you reference local variables inside remote sessions or parallel blocks. Serialization limits occur because objects are converted to CLIXML; deeply nested or complex .NET types may lose data during this process.

**PS20**: DSC ensures "Desired State" through configurations and resources managed by the Local Configuration Manager (LCM). In modern infrastructure, it has largely been superseded by tools like Terraform, Ansible, or Azure Automanage / Guest Configuration.
