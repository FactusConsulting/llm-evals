## JavaScript / TypeScript

**JS1**: `var` is function-scoped and hoisted; `let` and `const` are block-scoped. `const` prevents reassignment. **Hoisting** is the behavior where declarations (not initializations) are moved to the top of their scope during the compilation phase.

**JS2**: The **Event Loop** coordinates execution. The **Call Stack** handles synchronous code. When an async operation finishes, it enters a queue. The loop prioritizes the **Microtask Queue** (Promises, `process.nextTick`) over the **Macrotask Queue** (`setTimeout`, I/O). Microtasks must be fully cleared before the next macrotask begins.

**JS3**: A **closure** is a function that remembers its lexical environment even when executed outside that scope. *Example*: A counter function returning an inner function that increments a private variable. *Loop bug*: Using `var` in a for-loop creates one shared variable across all iterations; fix this by using `let`, which creates a new binding per iteration.

**JS4**: A **Promise** represents a future value. `async/await` is syntactic sugar for Promises. Error handling: `.catch()` for promises or `try/catch` blocks for `async/await`. `Promise.all` rejects immediately if any promise fails; `Promise.allSettled` waits for all to complete regardless of outcome.

**JS5**: **Interfaces** define object shapes and support "declaration merging" (adding fields later); **Types** are aliases for any type (unions, primitives, tuples). Use interfaces for public APIs/objects and types for complex logic/unions. **Discriminated Unions** use a common literal property (a "tag") to differentiate between members of a union at runtime.

**JS6**: JavaScript uses **prototypal inheritance**, where objects inherit directly from other objects via a prototype chain. `Object.create(proto)` creates a new object with the specified prototype. ES6 classes are "syntactic sugar"; they still use prototypes under the hood but provide a cleaner syntax for constructors and methods.

**JS7**: `this` refers to the execution context. Priority order: 1. **New binding** (`new Class()`), 2. **Explicit binding** (`call`, `apply`, `bind`), 3. **Implicit binding** (object method call), 4. **Default binding** (global window/undefined). `bind()` returns a *new* function with a fixed `this`; it cannot be re-bound.

**JS8**: `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` provides a callback when an object is GC'd. `WeakMap` keys must be objects because only then can the engine track if the key is no longer referenced elsewhere, allowing the entry to be purged.

**JS9**: V8 optimizes using **Hidden Classes** (assigning internal shapes to objects) and **Inline Caching** (caching property lookups based on those shapes). **Deoptimization** occurs when code becomes polymorphic (e.g., changing the structure of an object by adding properties in different orders), forcing V8 to drop back to slower interpreted execution.

**JS10**: **Tree-shaking** removes unused exports from the final bundle. It works with ES Modules (ESM) because they are statically analyzable (`import`/`export`). CommonJS (`require`) is dynamic; since imports happen at runtime, bundlers cannot safely determine which parts of a module are truly unused.

**JS11**: `null` is an intentional absence of value; `undefined` means a variable was declared but not assigned. `==` performs type coercion; `===` checks strict equality. `??` (**Nullish Coalescing**) returns the right side only if the left is `null` or `undefined`. `?.` (**Optional Chaining**) short-circuits to `undefined` if the reference is nullish.

**JS12**: `map()` transforms each element; `filter()` selects elements based on a predicate; `reduce()` aggregates an array into a single value. An initial value for `reduce` provides the starting accumulator. `flatMap()` maps then flattens one level deep; it's useful for mapping one item to zero or multiple items.

**JS13**: Template literals use backticks (\`) and allow interpolation `${}`. **Tagged templates** call a function with the string segments and interpolated values as arguments. *Example*: `` sql`SELECT * FROM users WHERE id = ${id}` `` allows the tag function to sanitize inputs to prevent SQL injection.

**JS14**: **Destructuring** extracts data from arrays/objects: `const { name, age } = user`. Renaming uses `{ oldName: newName }`. Default values are set via `name = 'Guest'`. The **rest operator** (`...rest`) collects remaining properties/elements into a new object or array.

**JS15**: `for...in` iterates over enumerable keys (including inherited ones); `for...of` iterates over iterable values (Array, Map). Avoid `for...in` on arrays because it may iterate over non-index properties added to the prototype chain.

**JS16**: **Generics** provide type safety for flexible types. **Constraints** (`T extends U`) limit what T can be. **Conditional Types** (`T extends U ? X : Y`) choose a type based on a condition. `infer` is used within conditional types to extract a specific part of a type. *Example*: `type Unpack<T> = T extends Array<infer R> ? R : T`.

**JS17**: CommonJS uses `require`/`module.exports` (synchronous); ESM uses `import`/`export` (static/async). Node handles both; `"type": "module"` in `package.json` tells Node that `.js` files should be treated as ESM. Otherwise, `.mjs` is ESM and `.cjs` is CommonJS.

**JS18**: TypeScript's **structural typing** cares about shape, not name ("if it looks like a duck"). **Excess property checks** apply when assigning an object literal directly to a typed variable. `extends` defines inheritance/constraints; `satisfies` validates a value against a type without changing its inferred type. Variance: Covariance (out) allows wider types; Contravariance (in) allows narrower types.

**JS19**: `Proxy` intercepts operations (get, set, etc.) on an object; `Reflect` provides static methods for the same operations. *Practical example*: A reactive state system where setting a property triggers a UI re-render via a Proxy `set` trap.

**JS20**: `SharedArrayBuffer` allows memory sharing between Web Workers. `Atomics` provide thread-safe operations (add, load, store) to prevent race conditions. `Atomics.wait()` puts a thread to sleep until a specific index changes, while `Atomics.notify()` wakes sleeping threads.

## Bash

**B1**: `$@` treats all arguments as separate words; `$*` treats them as one single string. When quoted, `"$@"` preserves individual argument quoting exactly as passed; `"$*"` joins all arguments into one string separated by spaces.

**B2**: `-e`: Exit immediately if a command fails. `-u`: Treat unset variables as errors. `-o pipefail`: The return value of a pipeline is the value of the last command to exit with a non-zero status, rather than just the final command.

**B3**: `$(command)` is preferred over backticks because it supports nesting and handles escaping better. `$((expression))` is shell arithmetic expansion (fast/internal); `expr` is an external utility that spawns a new process.

**B4**: **Process substitution** `<(command)` makes the output of a command appear as a file. *Example*: `diff <(ls dir1) <(ls dir2)` compares the directory listings without creating temporary files.

**B5**: Always quote variables: `for f in "$@"` or use globbing `for f in *.txt`. `for f in $(ls)` is dangerous because filenames containing spaces will be split into multiple iterations.

**B6**: A **here document** (`<<EOF`) redirects multi-line strings to stdin. A **here string** (`<<<"string"`) passes a single string to stdin. `<<-EOF` strips leading tab characters from lines for cleaner indentation in scripts.

**B7**: 
1. `cmd > file 2>&1`: Stdout goes to file; stderr follows stdout to the file.
2. `cmd 2>&1 > file`: Stderr goes to current stdout (terminal), then stdout is redirected to the file. Result: errors go to terminal, normal output to file.
3. `cmd &> file`: Shorthand for sending both stdout and stderr to the file.

**B8**: Use `mkdir lockdir` because it is an atomic operation at the OS level. Cleanup via `trap 'rmdir lockdir' EXIT SIGTERM`. File creation can suffer race conditions where two processes check if a file exists before writing.

**B9**: Single quotes `'...'` are literal (no expansion). Double quotes `"..."` allow variable/command interpolation. No quotes allow word splitting and globbing. *Example*: `echo "$VAR"` preserves spaces; `echo $VAR` splits them into separate arguments.

**B10**: `-f` checks if file exists/is regular; `-d` checks if directory; `-r` checks readability. `[ ]` is POSIX standard; `[[ ]]` is a Bash extension that supports regex (`=~`) and doesn't require quoting variables to prevent word-splitting.

**B11**: `$?` last command exit status; `$$` PID of current script; `$!` PID of most recent background process; `$#` number of positional parameters passed to the script.

**B12**: Define as `foo() { ... }`. `function foo {}` is mostly synonymous but less portable. Functions return **exit codes** (0-255); to "return" data, use `echo` and capture it with command substitution: `result=$(foo)`.

**B13**: `PATH` is a colon-separated list of directories searched for binaries. Builtins (e.g., `cd`, `pwd`) run inside the shell; external commands (e.g., `ls`, `grep`) are binary files on disk. Use `type -a <command>` to check which one is used.

**B14**: `trap` defines handlers for signals. Setup: `trap 'cleanup_func' EXIT INT TERM`. Execution order depends on signal arrival; if multiple traps exist for different signals, they execute when their specific signal arrives.

**B15**: Command substitution puts output into a string variable; `xargs` passes stdin as arguments to a command. To handle spaces/newlines: `find . -print0 | xargs -0`. `-P` allows running processes in parallel.

**B16**: Arrays: `arr=(1 2)`; Associative: `declare -A map`. Append via `arr+=("val")`. Iterate using `${arr[@]}` or keys `${!map[@]}`. Length is `${#arr[@]}`.

**B17**: Subshell `(...)` forks a new process; variables changed inside do not affect the parent. Group `{ ...; }` runs in the current process. Piping into a while loop (`cat file | while...`) creates a subshell, meaning any variable changes inside the loop are lost after it ends.

**B18**: SIGINT (Ctrl+C), SIGTERM (polite request to stop), SIGHUP (terminal closed), SIGKILL (forced kill). Graceful shutdown: use `trap` to catch SIGTERM and send `kill` to child PIDs before exiting.

**B19**: Use `split -l N logfile` to chunk data, then `xargs -P <cores> -I {} bash -c "process_func {}"`. Trade-off: Parallelism increases CPU usage but can bottleneck on Disk I/O. Error propagation requires logging return codes of each job to a temporary status file.

**B20**: `exec command` replaces the shell process with the target command entirely. For FD manipulation: `exec 3>file` opens FD 3 for writing. A **coprocess** (`coproc`) allows bidirectional communication via pipes between the script and a background process.

## PowerShell

**PS1**: `Write-Output` sends objects to the pipeline (can be captured by other cmdlets); `Write-Host` writes directly to the console host (cannot be captured in the pipeline).

**PS2**: The pipeline passes *objects*, not strings. `ForEach-Object` is a cmdlet that processes items one-by-one as they arrive; the `foreach` statement loads the entire collection into memory first and iterates over it (faster, but higher memory use).

**PS3**: `[hashtable]` is a key-value map; `[PSCustomObject]` is a structured object with properties. Use CustomObjects for data passing in pipelines because they are easier to filter/sort. Convert using `[PSCustomObject]$hash`.

**PS4**: Terminating errors stop execution immediately (catchable via `try/catch`). Non-terminating errors print red text but continue. `-ErrorAction Stop` converts non-terminating errors into terminating ones. `$ErrorActionPreference = 'Stop'` sets this globally.

**PS5**: **Splatting** `@params` expands a hashtable so its keys become parameter names and values become arguments. It differs from passing a hashtable as a single argument because it maps specifically to the function's defined parameters.

**PS6**: `Invoke-Command -ComputerName` runs a script block on remote machines once; `Enter-PSSession` starts an interactive shell. They typically use WinRM (WSMan) or SSH. Remoting requires the WinRM service to be configured on the target.

**PS7**: PowerShell "unrolls" arrays returned by functions. If a function returns 0 items, it returns `$null`. In the snippet: if multiple items return, `$x` becomes an `Object[]`. The correct pattern to ensure an array is returning `@($result)` or casting with `[array]`.

**PS8**: A `scriptblock` `{...}` is code treated as data. Pass them via `-ScriptBlock`. The **double-hop problem** occurs when credentials aren't passed beyond the first remote hop; solve using CredSSP or explicit credential objects in `Invoke-Command`.

**PS9**: `@()` explicitly creates an array. `[array]` casts a value to an array. Indexing into `$null` usually doesn't throw an error in PS due to its flexible type system; indexing an empty array also generally returns null without crashing.

**PS10**: `-eq` (equal), `-like` (wildcards), `-match` (regex). Case-insensitive by default (`-ceq` for case-sensitive). `-contains` checks if a collection contains a value; `-in` is the reverse (`value -in collection`).

**PS11**: Modules package cmdlets/functions. `.psm1` contains logic; `.psd1` is a manifest (metadata/dependencies). Binary modules are .NET DLLs. `Import-Module` loads these into the current session scope.

**PS12**: Double quotes `"..."` allow interpolation; single quotes `'...'` are literal. Use `$($expression)` for complex expressions inside strings. Here-strings start with `@"` and end with `"@` on new lines.

**PS13**: `Get-Member` reveals properties, methods, and NoteProperties (dynamic properties added at runtime). `Select-Object` picks specific properties (columns); `Where-Object` filters objects based on criteria (rows).

**PS14**: PowerShell classes provide strong typing. They differ from C# as they have limited inheritance and no interfaces. Use classes for data models; use functions for operational tasks.

**PS15**: `[CmdletBinding()]` enables advanced features like `-WhatIf`, `-Confirm` (via `SupportsShouldProcess`), and pipeline input via `ValueFromPipeline`. `Begin`, `Process`, and `End` blocks manage initialization, per-object processing, and cleanup.

**PS16**: Providers map different stores to drives. `FileSystem` is standard; `Registry` allows accessing the registry via paths like `cd HKLM:\`. This abstracts diverse data sources into a unified file-like interface.

**PS17**: A **runspace** is an isolated execution environment. `ForEach-Object -Parallel` (v7+) simplifies parallel execution by managing runspaces automatically. Manual runspace pools allow fine-grained control over thread counts and shared state.

**PS18**: PSScriptAnalyzer performs static analysis of code. It uses rules with severity levels (Error/Warning). Suppress rules using attributes like `[Diagnostics.SuppressMessage]`. Integrate it into CI pipelines to fail builds on "Error" level violations.

**PS19**: `$using:var` brings a local variable into a remote or parallel scope. `-ArgumentList` passes values during creation. Serialization limits mean complex objects are converted to CLIXML; deep nesting can lead to loss of type fidelity or truncated data.

**PS20**: DSC ensures system state through configurations and resources managed by the Local Configuration Manager (LCM). In modern infrastructure, this has largely been replaced by Guest Configuration in Azure or tools like Terraform and Ansible.
