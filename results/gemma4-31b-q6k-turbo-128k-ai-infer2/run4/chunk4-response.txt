## Go

**G1**: An **array** has a fixed size defined at compile time; it is a value type. A **slice** is a descriptor for a contiguous segment of an underlying array (containing a pointer, length, and capacity). When you append to a slice that has reached its capacity, Go allocates a new, larger array (usually doubling), copies existing elements over, and returns a new slice header pointing to the new array.

**G2**: `var x int` declares a variable with its zero value (0 for ints) without initializing it explicitly. `x := 0` is short-variable declaration, which both declares and initializes based on the right-hand side's type. You cannot use `:=` outside of functions or when you only want to assign a value to an already declared variable.

**G3**: A **goroutine** is a lightweight thread managed by the Go runtime, not the OS. While OS threads have large stacks (~MBs), goroutines start small (~2KB) and grow dynamically. The **GMP model** consists of: **G** (Goroutine), **M** (Machine/OS Thread), and **P** (Processor/Context). P schedules Gs onto Ms, allowing M:N scheduling and efficient work-stealing across CPU cores.

**G4**: Channels are pipes used for communication between goroutines. An **unbuffered channel** blocks the sender until a receiver is ready. A **buffered channel** allows sending up to $N$ values without blocking; once full, subsequent sends block until a value is read. Sending to a full buffered channel blocks the current goroutine.

**G5**: The `context` package manages request scoped data, cancellation signals, and deadlines.
```go
ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
_, err := http.DefaultClient.Do(req) // Cancels if it takes > 1s
```

**G6**: Go uses **implicit satisfaction**. If a type implements all methods of an interface, it satisfies it automatically—no `implements` keyword needed. This differs from Java/C# where interfaces must be explicitly declared. `interface{}` (or `any`) can hold any value. It's powerful for generic containers but dangerous because it bypasses compile-time type safety, requiring runtime type assertions or reflection.

**G7**: In Go's memory model, there is no guarantee that one goroutine will see writes from another unless synchronized. The provided code has a **data race** on `ready` and `data`. The loop might never terminate due to compiler optimizations (hoisting the read). Correct alternatives: use `sync.Mutex`, `atomic.Bool`, or a channel signal.

**G8**: `sync.Mutex` provides exclusive access; `sync.RWMutex` allows multiple concurrent readers OR one writer. Use `sync.Map` when you have high contention with many reads and few writes, or when keys are disjoint across cores. A regular map + mutex is faster for most general cases due to lower overhead and better type safety.

**G9**: Modules manage dependencies via `go.mod` (defines module path and requirements) and `go.sum` (contains cryptographic hashes of dependencies for reproducibility). `go mod tidy` adds missing modules and removes unused ones. **MVS (Minimum Version Selection)** selects the lowest version of a dependency that satisfies all constraints, ensuring stability over "latest" versions.

**G10**: `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In-First-Out)** order. Common gotcha: using a loop variable inside a defer closure without passing it as an argument; since the loop continues, the deferred functions will see the final value of the variable rather than its value at the time of scheduling.

**G11**: A pointer stores the memory address of another value. The zero value is `nil`. To create a pointer to a struct literal: `p := &User{Name: "Alice"}`.

**G12**: `init()` runs once per package upon import, after variables are initialized but before `main()`. A package can have multiple `init()` functions across different files; they execute in the order the files are presented to the compiler (lexical order), though generally, you should avoid relying on this specific ordering.

**G13**: `make` initializes slices, maps, and channels (returning an initialized object). `new(T)` allocates zeroed memory for type $T$ and returns a pointer (`*T`). `make` is used for reference types that require internal initialization; `new` is for any type.

**G14**: Go uses explicit return values for errors. The `error` interface has one method: `Error() string`. Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error wraps a specific sentinel value; `errors.As` attempts to cast an error to a specific custom type. Both handle wrapped errors, whereas `==` only works for direct equality.

**G15**: 
- **Map**: Zero value `nil`.
- **Slice**: Zero value `nil`.
- **Channel**: Zero value `nil`.
- **Struct**: Zero value is a struct with all fields set to their respective zero values.

**G16**: A race condition occurs when two goroutines access the same variable concurrently and at least one is a write. `-race` uses a runtime instrumentation tool to detect these during execution. Fix example: wrap map access in `sync.Mutex.Lock()`/`Unlock()` or use a channel to serialize updates.

**G17**: `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, it blocks until *any* case can proceed. If multiple cases are ready, one is chosen pseudo-randomly. Timeout implementation:
```go
select {
case res := <-ch: // process result
case <-time.After(1 * time.Second): // timeout
}
```

**G18**: Escape analysis determines if a variable can be allocated on the stack (fast) or must "escape" to the heap (slower, GC'd). The compiler moves variables to the heap if they are referenced outside the function scope or are too large for the stack. Inspect via `go build -gcflags="-m"`. It matters because reducing heap allocations reduces GC pressure.

**G19**: `reflect.Type` describes the structure of a type; `reflect.Value` represents the actual data. Reflection allows inspecting types at runtime but has high overhead due to boxing and dynamic checks. Use reflection for generic libraries (e.g., JSON encoders); use code generation (`stringer`, `protobuf`) for performance-critical paths.

**G20**: `go:embed` allows embedding static files into binaries. Single files use `//go:embed file.txt`; directories/patterns use `//go:embed folder/*`. It returns an `embed.FS` which implements `io/fs.FS`, allowing read-only access to embedded assets without external dependencies. Limitation: it only supports read-only access.

## Rust

**R1**: Ownership is a system where each value has a single owner. Rules: 1) Each value has one owner. 2) When the owner goes out of scope, the value is dropped. 3) Ownership can be moved (transferred), after which the previous owner cannot be used.

**R2**: `String` is an owned, growable, heap-allocated UTF-8 string. `&str` is a borrowed "string slice" (a pointer + length). In function signatures, use `&str` for input parameters to accept both `String` and `&str` efficiently; return `String` if the function must produce a new, owned string.

**R3**: Borrowing allows accessing data without taking ownership. **Shared references (`&T`)** allow multiple readers but no writers. **Mutable references (`&mut T`)** allow exactly one writer and no other readers. The borrow checker enforces these rules at compile time to prevent data races.

**R4**: `Option<T>` handles absence (`Some(T)` or `None`). `Result<T, E>` handles errors (`Ok(T)` or `Err(E)`). The `?` operator unwraps `Ok`/`Some` or returns the error/None immediately from the current function.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path) // Returns Result
}
```

**R5**: 
- `Box<T>`: Single ownership, heap allocation. Use for recursive types or large objects on the heap.
- `Rc<T>`: Reference counted, single-threaded shared ownership.
- `Arc<T>`: Atomic reference counted, thread-safe shared ownership. Use when sharing data across threads.

**R6**: Traits define shared behavior (similar to interfaces). Go interfaces are implicit; Rust traits are explicit. A **trait object (`dyn Trait`)** uses dynamic dispatch (vtable), allowing a collection of different types that implement the trait. **Generics with bounds (`T: Trait`)** use static dispatch via monomorphization, which is faster but increases binary size.

**R7**: Lifetimes ensure references don't outlive their data. The example fails because the compiler doesn't know if the returned reference points to `x` or `y`. Fix by adding lifetime parameters:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8**: `Send` indicates a type can be transferred between threads. `Sync` indicates a type can be accessed concurrently from multiple threads. `Rc<T>` isn't `Send`/`Sync` because its reference count is not atomic; updating it from two threads would cause a race condition. `Arc<T>` uses atomic operations for the counter, making it thread-safe.

**R9**: Async/await in Rust is "pull-based." A `Future` is a state machine that does nothing until polled. An **executor** (like Tokio) polls futures and wakes them when they are ready. Unlike Go's goroutines (which are preemptive), Rust async is cooperative and requires an explicit runtime.

**R10**: `unsafe` allows bypassing some borrow checker rules. 3 things allowed: dereferencing raw pointers (`*const T`, `*mut T`), calling unsafe functions (FFI), and mutating static variables. It is justified for low-level hardware access or implementing high-performance abstractions where the programmer can prove safety manually.

**R11**: Pattern matching via `match` provides exhaustive checking—the compiler forces you to handle every possible case of an enum. `if let` is syntactic sugar for cases where you only care about one specific pattern and want to ignore others.

**R12**: `Vec<T>` is a heap-allocated growable array; `[T; N]` is a fixed-size stack array. When `Vec` exceeds capacity, it allocates a new larger buffer (usually doubling), moves elements over, and frees the old buffer.

**R13**: Rust enums are "sum types" (algebraic data types); unlike C/Java, variants can hold associated data. `Option<T>` is an enum with `Some(T)` and `None`. This replaces `null` by forcing the developer to explicitly handle the absence of a value at compile time.

**R14**: An `impl` block defines methods for a type. `&self` is an immutable borrow; `&mut self` is a mutable borrow; `self` takes ownership. **Associated functions** do not take `self` as a parameter and are called like static methods (`Type::func()`).

**R15**: The `derive` macro automatically implements traits. Examples: `Debug` (printing), `Clone` (duplicating), `PartialEq` (equality). You cannot derive a trait if the type contains fields that don't implement that trait or if you need custom logic.

**R16**: `Cow<'a, T>` (Clone-on-Write) allows a value to be either borrowed or owned. It avoids allocation by keeping a reference until mutation is required, at which point it clones the data into an owned version. Example: parsing a string where most inputs are already in the correct format but some require normalization.

**R17**: `mod` declares a module; `use` creates a shortcut/import; `pub` makes items visible. Files map to modules (e.g., `src/lib.rs` $\rightarrow$ crate root). In Rust 2018+, the module system was simplified so that files can be treated as modules without needing explicit `mod` declarations inside every file for external paths.

**R18**: `Pin<T>` prevents a value from moving in memory. This is critical for **self-referential structs** (where a pointer points to another field in the same struct); if the struct moved, the pointer would become dangling. Async futures often create self-references when capturing local variables across `.await` points. `Unpin` is a marker trait for types that are safe to move.

**R19**: Declarative macros (`macro_rules!`) use pattern matching on tokens. Procedural macros act like compiler plugins: `derive` adds traits, attribute macros modify functions/structs, and function-like macros generate code. Hygiene ensures macros don't accidentally capture or clash with variables in the surrounding scope.

**R20**: Zero-cost abstractions mean you don't pay for what you don't use. Iterators are optimized into loops by the LLVM backend. Generics use **monomorphization**, where the compiler generates specialized versions of a function for each concrete type used, allowing static dispatch (direct function calls) instead of dynamic vtable lookups.
