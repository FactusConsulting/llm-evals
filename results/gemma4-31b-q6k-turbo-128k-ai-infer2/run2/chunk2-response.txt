## Kubernetes

**K1 — Easy:** A **Deployment** manages stateless pods that are interchangeable; any pod can handle a request. A **StatefulSet** manages pods with unique, persistent identities (stable network IDs and stable storage), ensuring ordered deployment, scaling, and termination.

**K2 — Easy:** A ClusterIP service provides a virtual IP. `kube-proxy` (via iptables or IPVS) intercepts traffic sent to this VIP and load-balances it across the set of healthy Pod IPs listed in the Service's **Endpoints** object.

**K3 — Medium:** 
- **PersistentVolume (PV):** The actual piece of storage (the "disk") provisioned by an admin or StorageClass.
- **PersistentVolumeClaim (PVC):** A user's request for storage (e.g., "I need 5Gi").
- **StorageClass (SC):** A template used for dynamic provisioning. When a PVC requests a specific SC, K8s automatically creates the PV.
*Relation:* $\text{StorageClass} \rightarrow \text{creates PV} \rightarrow \text{bound to PVC}$.

**K4 — Medium:**
1. `kubectl logs <pod>`: Check application crash logs/stack traces.
2. `kubectl describe pod <pod>`: Look at the "Events" section for OOMKills, failed probes, or image pull errors.
3. Check Liveness/Readiness probe configurations (too aggressive?).
4. Verify environment variables, secrets, and config maps are correctly mapped and present.

**K5 — Medium:** CoreDNS provides service discovery; it allows pods to resolve other services via DNS names (e.g., `my-svc.my-namespace.svc.cluster.local`). If CoreDNS is down, internal DNS resolution fails, meaning pods cannot communicate with each other using service names, effectively breaking most microservice communication.

**K6 — Hard:** The scheduler uses two main phases:
1. **Filtering (Predicates):** Eliminates nodes that don't meet requirements (e.g., insufficient CPU/RAM, taints without tolerations).
2. **Scoring (Priorities):** Ranks remaining nodes based on factors like:
    - **Least Requested Priority:** Prefers nodes with more free resources.
    - **Image Locality:** Prefers nodes where the container image is already cached.
    - **Balanced Resource Usage:** Spreads pods across nodes to avoid hotspots.

**K7 — Hard:** 
- **Scheduling:** Yes. Total requested memory = $3.5\text{GB} + 0.256\text{GB} \approx 3.756\text{GB}$, which is $\le 4\text{GB}$. It will be scheduled.
- **Runtime:** If it uses 600Mi, it exceeds its `limits.memory` (512Mi). The Linux kernel OOM killer will terminate the process, and Kubernetes will report an **OOMKilled** status.

**K8 — Hard:** 
$\text{External LB} \rightarrow \text{Ingress Controller Pod (NGINX)} \rightarrow \text{Service Endpoints} \rightarrow \text{Pod IP}$.
The Ingress Controller watches the K8s API for Ingress rules. When a request arrives, NGINX matches the host/path to a Service. Instead of routing through the Service VIP (which would add another hop), the controller looks up the actual **Endpoints** (the list of healthy pod IPs) and routes traffic directly to the pod via iptables/network routing.

**K9 — Medium:** A NetworkPolicy is a L3/L4 firewall for pods. By default, all pods in a namespace are "non-isolated" (all traffic allowed). Once any NetworkPolicy selects a pod, that pod becomes isolated; only traffic explicitly allowed by the policy is permitted; everything else is denied.

**K10 — Medium:** 
- **RollingUpdate:** Gradually replaces old pods with new ones (zero downtime).
- **Recreate:** Kills all existing pods before starting new ones (downtime).
*Choose Recreate when:* The application cannot handle two different versions running simultaneously (e.g., during a breaking database schema migration).

**K11 — Easy:** A namespace provides logical isolation within a cluster. Default namespaces: `default` (user apps), `kube-system` (cluster internals), and `kube-public` (publicly readable info).

**K12 — Easy:** Used for detailed debugging. It shows:
1. **Events:** Recent lifecycle events (scheduling failures, pulls).
2. **Container Status:** Exact restart counts and exit codes.
3. **Resource Limits:** Actual requests vs limits assigned to containers.

**K13 — Easy:** A ConfigMap stores non-confidential configuration key-value pairs. Consumption methods:
1. As environment variables inside the container.
2. Mounted as files in a volume.

**K14 — Easy:** 
- **ClusterIP:** Internal IP only; accessible only from within the cluster.
- **NodePort:** Exposes the service on a static port on every Node's IP.
- **LoadBalancer:** Provisions an external cloud LB that routes traffic to the NodePort $\rightarrow$ ClusterIP.

**K15 — Easy:** A DaemonSet ensures one copy of a pod runs on all (or selected) nodes. Use it instead of a Deployment for infrastructure agents like log collectors (Fluentd) or monitoring agents (Prometheus Node Exporter).

**K16 — Medium:** 
- **Taints/Tolerations:** Taints are applied to *nodes* to repel pods. Tolerations are applied to *pods* to allow them onto tainted nodes. (*Use case:* Dedicating GPU nodes to ML workloads).
- **Node Affinity:** Pods express preference/requirement for certain node labels. (*Use case:* Ensuring high-performance apps land on SSD-backed nodes).

**K17 — Medium:** An Operator is a custom controller using Custom Resource Definitions (CRDs). While standard controllers manage generic objects (like Deployments), Operators encode domain-specific operational knowledge (e.g., how to perform a Postgres backup, handle failover, and scale a database). It solves the problem of automating complex stateful application lifecycles.

**K18 — Hard:** etcd uses the **Raft consensus algorithm**, ensuring strong consistency. If quorum ($n/2 + 1$) is lost, the cluster becomes read-only or unavailable because writes cannot be committed. To recover from losing 2 out of 3 nodes: you must restore from a recent snapshot backup to a new cluster.

**K19 — Hard:** RBAC links users/groups to permissions via Roles.
- **Role/RoleBinding:** Namespace-scoped.
- **ClusterRole/ClusterRoleBinding:** Cluster-wide scope.

```yaml
# Role for read-only pods/logs in one namespace
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { name: pod-reader }
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { name: dev-read-binding }
subjects: [{ kind: User, name: "developer" }]
roleRef: { kind: Role, name: pod-reader, apiGroup: rbac.authorization.k8s.io }
```

**K20 — Hard:** By default, `ndots` is set to 5. For an external domain like `google.com`, the resolver tries appending local search suffixes (e.g., `google.com.default.svc.cluster.local`) before trying the absolute name. This causes multiple failed queries per request. Fix via `dnsConfig`:
```yaml
spec:
  dnsConfig:
    options:
      - name: ndots
      - "1"
```

## Development

**D1 — Easy:** **Merge** creates a new merge commit combining two histories; it preserves the actual chronological sequence of events. **Rebase** rewrites history by moving commits from one branch onto another for a linear timeline. Avoid rebasing public branches as it disrupts other developers' histories.

**D2 — Easy:** **TCP** is connection-oriented and reliable (guarantees delivery/order). Examples: HTTP, SSH. **UDP** is connectionless and fast (no guarantee of delivery). Examples: DNS, VoIP.

**D3 — Medium:** A race condition occurs when the outcome depends on the timing or order of execution of concurrent threads accessing shared data. *Example:* Two threads incrementing a global variable `count++` simultaneously without a lock; both read `10`, both add 1, and write back `11` instead of `12`.

**D4 — Medium:** **Symmetric** uses one key for encryption/decryption (AES). **Asymmetric** uses a public key to encrypt and a private key to decrypt (RSA). In TLS, asymmetric encryption is used during the handshake to securely exchange a symmetric session key, which is then used for bulk data transfer due to its speed.

**D5 — Medium:** Each instruction in a Dockerfile creates a read-only layer. Layer caching reuses unchanged layers to speed up builds. Best practice: Put stable instructions (OS install, dependency installation) at the top and frequently changing code at the bottom.

**D6 — Medium:**
1. Check application logs for timeouts or "Connection Refused" errors.
2. Verify health check endpoints (Liveness/Readiness probes).
3. Monitor resource saturation (CPU spikes or Memory leaks causing GC pauses).
4. Inspect downstream dependencies (Database connection pool exhaustion or API rate limits).

**D7 — Hard:** CAP Theorem states a distributed system can only provide two of three: Consistency, Availability, Partition Tolerance.
- **CP (Consistency/Partition):** MongoDB (strict consistency; will stop accepting writes if partition occurs).
- **AP (Availability/Partition):** Cassandra (eventual consistency; allows reads/writes during partitions).

**D8 — Medium:** **Horizontal scaling** adds more instances (nodes); **Vertical scaling** increases resources (CPU/RAM) on one instance. Horizontal scaling is enabled by statelessness, load balancing, and database sharding.

**D9 — Easy:** An environment variable is a dynamic value stored by the OS that processes can access. To persist it across sessions on Linux, add `export VAR_NAME=value` to your `~/.bashrc` or `/etc/environment`.

**D10 — Easy:** JSON is a strict, lightweight data interchange format. YAML is a human-readable superset of JSON. 
- **JSON Advantage:** Faster parsing, universal standard for APIs.
- **YAML Advantage:** Supports comments and complex nesting with cleaner syntax.

**D11 — Easy:** A REST API uses HTTP methods to manipulate resources.
- **GET:** Retrieve resource.
- **POST:** Create new resource.
- **PUT:** Update/Replace existing resource.
- **DELETE:** Remove resource.

**D12 — Easy:** Version pinning is specifying an exact version of a dependency (e.g., `requests==2.25.1`). It ensures reproducible builds so that a "silent" update in a library doesn't introduce breaking changes into production.

**D13 — Easy:** **Compiled** languages are translated to machine code before execution (C++, Rust). **Interpreted** languages are executed line-by-line at runtime (Python, JavaScript).

**D14 — Medium:** A **forward proxy** acts on behalf of the client; a **reverse proxy** acts on behalf of the server.
- **Nginx:** Used as a load balancer to distribute traffic across servers.
- **HAProxy:** Used for high-performance TCP/HTTP routing and health checking.

**D15 — Medium:** A deadlock is a state where two or more processes are unable to proceed because each is waiting for the other to release a resource. Coffman conditions: 
1. Mutual Exclusion $\rightarrow$ 2. Hold and Wait $\rightarrow$ 3. No Preemption $\rightarrow$ 4. Circular Wait.

**D16 — Hard:** Eventual consistency means if no new updates are made, all accesses will eventually return the last updated value. Cassandra handles this via tunable consistency levels ($R+W > N$). Levels include `ONE` (fastest), `QUORUM` (majority agreement), and `ALL` (strongest consistency).

**D17 — Hard:** mTLS requires both client and server to present certificates. Handshake: Server sends cert $\rightarrow$ Client verifies against CA $\rightarrow$ Client sends its own cert $\rightarrow$ Server verifies against CA $\rightarrow$ Both derive a symmetric session key. Commonly used in Service Meshes (Istio) for zero-trust internal networking.

**D18 — Hard:** A hash table uses a function to map keys to array indices. 
- **Collision Resolution:** Chaining (linked lists at index) or Open Addressing (probing for next empty slot).
- **Complexity:** Average $O(1)$ for insertion/lookup/deletion; Worst case $O(n)$ when many collisions occur.

**D19 — Hard:** The circuit breaker prevents cascading failures by stopping requests to a failing service.
- **Closed:** Normal operation; traffic flows.
- **Open:** Failure threshold reached; fail fast immediately without calling the service.
- **Half-Open:** Periodically tests if the service has recovered.
It relates to retry policies via **exponential backoff**, which ensures retries don't overwhelm a recovering system ("thundering herd").

**D20 — Hard:** 
- **Optimistic:** Assumes no conflict; checks version/timestamp before committing. If changed, it fails and retries. (*Use: High read/low contention*). Example: Row versioning (`WHERE version = 5`).
- **Pessimistic:** Locks the resource immediately so others cannot access it until finished. (*Use: Critical data/high contention*). Example: `SELECT ... FOR UPDATE`.
