## JavaScript / TypeScript

**JS1**: `var` is function-scoped and hoisted (declaration moved to top), allowing usage before declaration (as `undefined`). `let` and `const` are block-scoped. `const` prevents reassignment of the identifier. **Hoisting** is the JS behavior where declarations are processed before any code is executed.

**JS2**: The **Event Loop** manages execution by monitoring the Call Stack. When the stack is empty, it processes tasks in this priority: 1) **Call Stack** (synchronous code), 2) **Microtask Queue** (Promises, `queueMicrotask`), 3) **Macrotask Queue** (`setTimeout`, `setInterval`, I/O). Microtasks always execute fully before the next macrotask begins.

**JS3**: A **closure** is a function that remembers its lexical scope even when executed outside that scope. *Example*: A counter function returning an inner function that increments a private variable. *Loop bug*: Using `var` in a `for` loop creates one shared variable across all iterations; fixing it requires using `let`, which creates a new binding per iteration.

**JS4**: A **Promise** represents a future value. `async/await` is syntactic sugar for Promises, making asynchronous code look synchronous. Error handling uses `.catch()` or `try...catch`. `Promise.all` rejects immediately if any promise fails ("fail fast"); `Promise.allSettled` waits for all to complete regardless of outcome.

**JS5**: An **interface** defines the shape of an object and can be merged via declaration merging. A **type** alias can represent primitives, unions, tuples, or intersections. Use interfaces for public APIs/objects and types for complex logic/unions. **Discriminated Unions** are types sharing a common literal property (a "tag") used to narrow the type in a switch/if block.

**JS6**: JS uses **prototypal inheritance**, where objects inherit properties from a prototype chain. `Object.create(proto)` creates a new object with the specified prototype. ES6 classes are "syntactic sugar"; they provide a cleaner syntax but still use prototypes under the hood (`class` methods are added to the prototype).

**JS7**: `this` refers to the execution context. Binding priority: 1) New binding (`new Class()`), 2) Explicit binding (`call`, `apply`, `bind`), 3) Implicit binding (object method), 4) Default binding (global window/undefined). `bind()` returns a *new* function; it cannot be re-bound once bound.

**JS8**: `WeakRef` allows holding a reference to an object without preventing its garbage collection. `FinalizationRegistry` triggers a callback when a `WeakRef` target is collected. `WeakMap` keys must be objects because they are held weakly; if no other strong references exist, the key (and value) can be GC'd.

**JS9**: V8 optimizes via **Hidden Classes** (assigning shapes based on property order) and **Inline Caching** (caching lookup results for those shapes). **Deoptimization** occurs when code becomes polymorphic (e.g., changing the shape of an object by adding properties in different orders or types mid-life).

**JS10**: **Tree-shaking** removes unused exports from the final bundle. It works with ES Modules (ESM) because `import`/`export` are static, allowing tools like Webpack to analyze dependencies at build time. CommonJS (`require`) is dynamic, meaning imports happen at runtime, making static analysis nearly impossible.

**JS11**: `null` is an intentional absence of value; `undefined` means a variable was declared but not assigned. `==` performs type coercion (treating them as loosely equal), while `===` checks strict equality. `??` returns the right side only if the left is `null` or `undefined`; `?.` short-circuits and returns `undefined` if the chain is broken.

**JS12**: `map()` transforms each element; `filter()` selects elements based on a predicate; `reduce()` aggregates an array into a single value. An initial value in `reduce()` provides the starting accumulator state. `flatMap()` maps then flattens one level deep—useful for splitting strings into arrays and flattening the result.

**JS13**: Template literals use backticks (\`) and `${}` for interpolation. **Tagged templates** allow calling a function that processes the string parts and values separately. *Example*: A `sql` tag that escapes variables to prevent SQL injection: `` sql`SELECT * FROM users WHERE id = ${id}` ``.

**JS14**: Destructuring extracts data from objects `{a, b} = obj` or arrays `[x, y] = arr`. Default values are set via `= val`. Renaming occurs via `{oldName: newName} = obj`. The rest operator `...rest` collects all remaining properties/elements into a new object/array.

**JS15**: `for...in` iterates over enumerable keys (strings) of an object. `for...of` iterates over iterable values (arrays, Maps). Avoid `for...in` on arrays because it iterates over indices as strings and may include inherited prototype properties.

**JS16**: Generics `<T>` create reusable components. **Constraints** (`T extends U`) limit what types can be passed. **Conditional Types** (`T extends U ? X : Y`) choose a type based on a condition. `infer` allows extracting a type from another (e.g., getting the return type of a function).

**JS17**: CommonJS uses `require`/`module.exports` (synchronous); ESM uses `import`/`export` (static). Node handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM by default otherwise they are treated as CommonJS.

**JS18**: TS is **structurally typed** (if shapes match, types match). Excess property checks apply only during literal assignments. `extends` defines inheritance or constraints; `satisfies` validates that a value matches a type without changing its inferred type. Variance: Covariance (out/return types), Contravariance (in/parameter types).

**JS19**: `Proxy` intercepts object operations (get, set, etc.); `Reflect` provides low-level methods for those same operations. *Example*: A reactive state system where a Proxy's `set` trap triggers a UI re-render whenever a variable changes.

**JS20**: `SharedArrayBuffer` allows memory sharing between Web Workers. `Atomics` provide thread-safe operations (add, load, store) on that buffer. `Atomics.wait` puts a worker to sleep until another worker calls `Atomics.notify`, ensuring synchronized communication.

## Bash

**B1**: `$@` and `$*` both represent all positional parameters. In double quotes, `"$@"` treats each argument as a separate quoted string; `"$*"` joins them into one single string separated by the first character of `IFS`.

**B2**: `-e`: Exit immediately if a command fails. `-u`: Treat unset variables as an error. `-o pipefail`: The return value of a pipeline is the status of the last command to exit with a non-zero status, or zero if all succeeded.

**B3**: `$(command)` is preferred over backticks because it supports nesting and handles escaping better. `$((expression))` is shell arithmetic (fast); `expr` is an external utility (slow).

**B4**: Process substitution `<(command)` makes the output of a command appear as a file. *Example*: `diff <(ls dir1) <(ls dir2)` compares the directory listings without creating temporary files.

**B5**: Always quote variables: `for f in "$@"` or `while read -r f`. Avoid `for f in $(ls)` because word splitting will break filenames containing spaces or newlines. Use globbing (`for f in *`) instead.

**B6**: Here doc `<<EOF` allows multi-line input until "EOF" is found. Here string `<<< "string"` passes a single string to stdin. `<<-EOF` strips leading tab characters from each line for cleaner indentation.

**B7**: 
1. `cmd > file 2>&1`: stdout $\to$ file; stderr $\to$ where stdout currently goes (file). Result: both captured.
2. `cmd 2>&1 > file`: stderr $\to$ current stdout (terminal); then stdout $\to$ file. Result: only stdout captured.
3. `cmd &> file`: Shorthand for capturing both.

**B8**: Use `mkdir lockdir` for locking because it's an atomic operation at the OS level. Cleanup via `trap 'rmdir lockdir' EXIT SIGTERM`. File creation (`touch`) can suffer race conditions between checking and creating.

**B9**: Single quotes ('') are literal strings. Double quotes ("") allow interpolation of variables/commands. No quotes lead to word splitting and glob expansion. Example: `$VAR="a b"; echo $VAR` prints two words; `echo "$VAR"` prints one.

**B10**: `-f` checks if file exists, `-d` for directory, `-r` for readable. `[ ]` is POSIX standard test; `[[ ]]` is a Bash extension that supports regex (`=~`), logical operators without escaping, and doesn't require quoting as strictly.

**B11**: `$?`: Exit status of last command. `$$`: PID of current shell. `$!`: PID of most recent background job. `$#`: Number of arguments passed to script.

**B12**: Defined as `foo() { ... }` or `function foo { ... }`. The former is more portable (POSIX). Functions return values by echoing output to stdout or returning an exit code ($0-255) using the `return` keyword.

**B13**: `PATH` is a colon-separated list of directories searched for executables. Builtins (e.g., `cd`) run inside the shell process; external commands (e.g., `ls`) spawn new processes. Use `type -a <cmd>` to check which is being used.

**B14**: `trap 'handler' signal` catches signals. EXIT handles normal termination; INT/TERM handle interrupts. When multiple signals arrive, they are queued; however, if a trap is already running, it may be interrupted depending on the signal priority.

**B15**: Command substitution returns a string; `xargs` passes input as arguments to a command. To handle spaces: `find . -print0 | xargs -0`. `-P` allows parallel execution of jobs.

**B16**: Arrays: `arr=(1 2)`; Associative arrays: `declare -A map`. Append: `arr+=("val")`. Length: `${#arr[@]}`. Iteration uses `for i in "${arr[@]}"` or keys via `"${!map[@]}"`.

**B17**: Subshell `(...)` forks a child process with its own scope. Group `{ ...; }` executes in the current shell. Piping into a while loop (`cat file | while read...`) creates a subshell, meaning variable changes inside the loop are lost after the pipe ends.

**B18**: SIGINT (Ctrl+C), SIGTERM (polite request to stop), SIGHUP (terminal closed), SIGKILL (forced kill). Graceful shutdown involves trapping TERM and iterating through an array of background PIDs to send them termination signals.

**B19**: Logic: Use `split` to chunk logs $\to$ `xargs -P <num> processing_func` for CPU parallelism $\to$ merge results using `sort` or `cat`. Trade-off: Parallelism increases speed but adds overhead for merging and error tracking. Error propagation is handled by checking exit codes of parallel jobs.

**B20**: `exec` replaces the current process image with another command. For FD manipulation: `exec 3>file` opens fd 3 for writing. A coprocess (`coproc`) allows bidirectional communication between the main script and a background process.

## PowerShell

**PS1**: `Write-Output` sends objects to the pipeline for downstream cmdlets. `Write-Host` writes directly to the console host; it bypasses the pipeline entirely, making its output invisible to subsequent commands.

**PS2**: The pipeline passes *objects*, not text. `ForEach-Object` is a cmdlet that processes items as they stream through the pipeline. The `foreach` statement is a language keyword that loads the entire collection into memory first—it's faster but uses more RAM.

**PS3**: `[hashtable]` is an unordered key-value map. `[PSCustomObject]` is a structured object with properties. Convert via `[PSCustomObject]$hash`. Use CustomObjects when you want to return "rows" of data (e.g., for CSV export).

**PS4**: Terminating errors stop execution and can be caught by `try/catch`. Non-terminating errors just print a warning. `-ErrorAction Stop` converts non-terminating errors into terminating ones. `$ErrorActionPreference = 'Stop'` does this globally.

**PS5**: **Splatting** (`@params`) allows passing a hashtable as parameters: `$p = @{Path='C:\'; Recurse=$true}; Get-ChildItem @p`. This differs from passing a hash as a single parameter value; splatting maps keys directly to named parameters of the cmdlet.

**PS6**: Remoting uses WinRM (WSMan) or SSH. `Invoke-Command -ComputerName` runs a script block on remote machines and returns results. `Enter-PSSession` creates an interactive shell. It relies on encrypted channels provided by these protocols.

**PS7**: PowerShell unrolls arrays returned by functions. If a function returns 3 items, they are emitted one by one into the pipeline. The result of the code snippet is an `ObjectArray`. If it returns 0 items, it returns `$null`. Correct pattern: use `@()` to force array output if consistency is needed.

**PS8**: A `[scriptblock]` is a piece of executable code `{...}`; a function is a named scriptblock. Double-hop problem occurs when credentials aren't passed to a second remote hop. Solve via CredSSP or using `-ArgumentList` with explicit credentials.

**PS9**: `@()` ensures a result is treated as an array even if only one item is returned. Indexing into `$null` or an empty array both return `$null`, but indexing into a populated array returns the specific element.

**PS10**: Operators like `-eq` are case-insensitive; `-ceq` is case-sensitive. `-contains` checks if a collection contains a value (Collection -contains Value). `-in` does the opposite (Value -in Collection).

**PS11**: `.psm1` (Script Module) contains logic; `.psd1` (Manifest) defines metadata and dependencies. Binary modules are .NET DLLs. `Import-Module` loads these into the current session for use.

**PS12**: Interpolation in `"..."` allows variables. `'...'` is literal. Expressions use sub-expressions: `"Result: $($expr)"`. Here-strings (`@" ... "@`) allow multi-line strings without escaping quotes.

**PS13**: `Get-Member` reveals properties, methods, and NoteProperties (dynamically added properties). `Select-Object` filters which *properties* to keep; `Where-Object` filters which *objects* based on a condition.

**PS14**: PS Classes provide strong typing. They differ from C# classes by being more dynamic and having simpler syntax. Limitations include lack of interfaces and limited inheritance. Use classes for complex data models; functions for actions/logic.

**PS15**: `[CmdletBinding()]` enables advanced features like `-WhatIf`, `-Confirm`, and parameter sets. `Begin`, `Process`, and `End` blocks handle pipeline streaming—`Process` runs once per object coming through the pipe.

**PS16**: Providers map different stores (Registry, FileSystem, Cert) to a common interface. You can access the registry as if it were a drive: `cd HKLM:\Software\Microsoft`.

**PS17**: A `runspace` is an isolated execution environment. `ForEach-Object -Parallel` (v7+) manages a runspace pool automatically. Manual management involves creating a `RunspacePool` and assigning threads to tasks for maximum control over concurrency.

**PS18**: PSScriptAnalyzer lints code against best practices. It uses rules with severity levels (Warning, Error). Rules are suppressed using attributes like `[Diagnostics.SuppressMessage]`. Integration into CI pipelines ensures consistent coding standards across teams.

**PS19**: `$using:` injects local variables into remote scopes or parallel loops. `-ArgumentList` passes values during call time. Serialization limits mean some deep .NET objects cannot be passed via CLIXML without losing data/state.

**PS20**: DSC defines desired state via Configurations $\to$ Resources $\to$ LCM (Local Configuration Manager). Modern infrastructure has largely shifted toward Terraform/Ansible, though PS 7+ continues to evolve DSC resources as standalone modules.
