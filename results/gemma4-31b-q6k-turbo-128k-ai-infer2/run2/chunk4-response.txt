## Go

**G1**: An **array** has a fixed size defined at compile time (e.g., `[5]int`). A **slice** is a descriptor consisting of a pointer to an underlying array, a length, and a capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array (typically doubling the size), copies the existing elements over, and returns a new slice header pointing to this new array.

**G2**: `var x int` declares a variable with its zero value (`0`). `x := 0` is short variable declaration; it infers the type from the right side and assigns it. You cannot use `:=` at the package level (top-level) or when declaring a variable without providing an initial value.

**G3**: A **goroutine** is a lightweight thread managed by the Go runtime, not the OS. While OS threads have large stacks (~MBs), goroutines start small (~2KB) and grow dynamically. The **GMP model** consists of:
*   **G (Goroutine):** The execution state.
*   **M (Machine):** An OS thread.
*   **P (Processor):** A logical context/resource required to execute Gs on Ms. It handles local run queues to reduce lock contention on the global queue.

**G4**: Channels are typed conduits for communication between goroutines. **Unbuffered channels** block the sender until a receiver is ready (synchronous). **Buffered channels** allow sending values without a corresponding receiver until the buffer is full. Once full, any further send operations will block until a value is read.

**G5**: The `context` package manages request lifecycles, cancellation signals, and deadlines across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2 * time.Second)
defer cancel() // Always cancel to release resources

req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
_, err := http.DefaultClient.Do(req) // Returns error if timeout expires
```

**G6**: Go uses **implicit satisfaction**. If a type implements all methods of an interface, it satisfies that interface automatically; no `implements` keyword is needed. This decouples producers from consumers. `interface{}` (or `any`) can hold any value because every type has at least zero methods. It is powerful for generic-like behavior but dangerous because it bypasses compile-time type safety, requiring runtime type assertions/switches.

**G7**: This code contains a **data race**. There is no synchronization ensuring that the write to `ready = true` in the goroutine is visible to the loop in the main thread. The compiler or CPU might reorder instructions or cache the value of `ready`. Correct alternatives: use a **channel** (`chan bool`) or `sync/atomic` values.

**G8**: `sync.Mutex` provides exclusive access. `sync.RWMutex` allows multiple concurrent readers OR one writer, improving performance for read-heavy workloads. Use `sync.Map` when you have many disjoint keys with high read rates and few writes, as it reduces lock contention via internal sharding and atomic operations. A regular map + mutex is generally faster for most general-purpose cases due to lower overhead per operation.

**G9**: Go modules manage dependency versions. `go.mod` defines the module path and required dependencies; `go.sum` stores cryptographic checksums to ensure builds are reproducible. `go mod tidy` adds missing and removes unused modules. **Minimum Version Selection (MVS)** selects the *lowest* version of a dependency that satisfies all constraints in the graph, providing stability over "latest" semantics.

**G10**: `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. Common gotcha: calling `defer` inside a loop can cause memory leaks or resource exhaustion because they don't execute until the outer function exits, not at the end of each iteration.

**G11**: A pointer holds the memory address of a value. The zero value of any pointer is `nil`. To create a pointer to a struct literal, use the ampersand operator: `p := &User{Name: "Alice"}`.

**G12**: `init()` functions run automatically during package initialization. They run after variable initialization but before `main()`. A package can have multiple `init()` functions across different files; they execute in the order they appear in the files, following the package dependency graph.

**G13**: `new(T)` allocates zeroed memory for type `T` and returns a pointer (`*T`). `make` is used only for slices, maps, and channels; it initializes the internal data structures (like the underlying array for a slice) and returns an initialized value of that type.

**G14**: Go treats errors as values. The `error` interface has one method: `Error() string`. Idiomatic pattern: `if err != nil { return ..., err }`. `errors.Is` checks if an error matches a specific target (traversing wrapped errors), while `errors.As` attempts to cast an error to a specific custom type.

**G15**: 
- **Map:** Zero value `nil`.
- **Slice:** Zero value `nil`.
- **Channel:** Zero value `nil`.
- **Struct:** Fields are initialized to their respective zero values.

**G16**: A race condition occurs when two or more goroutines access shared data concurrently and at least one access is a write. `-race` uses instrumentation to detect these at runtime.
Example fix: Use `sync.Mutex`:
```go
mu.Lock()
count++
mu.Unlock()
```

**G17**: `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, which evaluates expressions, `select` blocks until *one* of its cases can proceed. If multiple are ready, it picks one randomly. Timeout implementation:
```go
select {
case res := <-ch: // handle result
case <-time.After(1 * time.Second): // timeout case
}
```

**G18**: Escape analysis determines whether a variable should be allocated on the stack or heap. If a variable's reference "escapes" the function (e.g., returning a pointer to a local variable), it is moved to the heap. Inspect via `go build -gcflags="-m"`. It matters because heap allocation increases GC pressure and reduces performance.

**G19**: The `reflect` package allows runtime introspection. `reflect.Type` describes the type; `reflect.Value` represents the actual value. Costs include high CPU overhead and loss of type safety. Reflection is justified for generic libraries (like JSON encoders); code generation (`go generate`) is preferred for performance-critical paths.

**G20**: `go:embed` allows embedding files into the binary at compile time. Single files use `string` or `[]byte`; directories/file systems use `embed.FS`. It interacts with `io/fs.FS`, allowing you to treat embedded data as a read-only filesystem. Limitation: only static assets can be embedded.

## Rust

**R1**: Ownership ensures memory safety without a garbage collector. Rules: 1) Each value has a variable called its owner, 2) There can only be one owner at a time, 3) When the owner goes out of scope, the value is dropped.

**R2**: `String` is an owned, growable, heap-allocated string. `&str` is a "string slice," a reference to some string data (could be in the binary's read-only memory or on the heap). In function signatures, prefer `&str` for inputs to accept both `String` and literal strings.

**R3**: The borrow checker enforces rules to prevent data races. **Shared references (`&T`)** allow multiple readers but no mutation. **Mutable references (`&mut T`)** allow exactly one writer and NO other readers/writers simultaneously.

**R4**: `Result<T, E>` handles recoverable errors; `Option<T>` handles optional values (`Some`/`None`). The `?` operator returns the error early if it encounters an `Err`.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path) // Returns Result
}
```

**R5**: `Box<T>` provides single ownership of heap memory. `Rc<T>` allows shared ownership via reference counting (single-threaded). `Arc<T>` (Atomic Reference Counted) is the thread-safe version of `Rc`. Use `Arc` when sharing data across threads.

**R6**: Traits define shared behavior (similar to interfaces). Go interfaces are implicit; Rust traits must be explicitly implemented. A generic bound `T: Trait` uses **static dispatch** (monomorphization), while a trait object `dyn Trait` uses **dynamic dispatch** (vtable), allowing for heterogeneous collections.

**R7**: Lifetimes ensure references don't outlive their data. The example fails because the compiler doesn't know which input slice the return value refers to. Fix by adding lifetime annotations:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { ... }
```

**R8**: `Send` indicates a type can be transferred between threads. `Sync` indicates a type can be accessed from multiple threads via references. `Rc<T>` isn't `Send`/`Sync` because its reference counter is not atomic; incrementing it concurrently would cause a race condition. `Arc<T>` uses atomic operations for the count, making it safe.

**R9**: Async/await in Rust creates a state machine. A `Future` is a trait representing a value that will eventually exist. An **executor** (like Tokio) polls these futures until they complete. Unlike Go's preemptive scheduler, Rust async is cooperative—the future must yield control back to the executor.

**R10**: `unsafe` allows bypassing certain borrow checker rules. You can: 1) Dereference raw pointers, 2) Call unsafe functions, 3) Mutate static variables. It is justified for FFI (C-interop), implementing low-level data structures (e.g., `Vec`), or extreme performance optimizations.

**R11**: Pattern matching (`match`) is an exhaustive expression used to destructure values. `if let` is syntactic sugar for when you only care about one specific pattern. The compiler enforces exhaustiveness by requiring all enum variants to be handled in a `match`.

**R12**: `Vec<T>` is a dynamic heap array; `[T; N]` is a fixed-size stack array. When a `Vec` exceeds capacity, it reallocates a larger block of memory (usually doubling size) and moves elements there.

**R13**: Enums are "sum types" that can hold associated data per variant. C/Java enums are just named integers. `Option<T>` replaces null with `Some(T)` or `None`, forcing developers to handle the absence of a value explicitly.

**R14**: An `impl` block defines methods for a type. `&self` borrows immutably, `&mut self` borrows mutably, and `self` consumes ownership. Associated functions (like `String::new()`) do not take any `self` parameter.

**R15**: `derive` is a procedural macro that automatically implements traits like `Debug`, `Clone`, `PartialEq`, etc. You cannot derive a trait if any field within the struct does not also implement that trait.

**R16**: `Cow<'a, T>` (Clone-on-Write) allows a value to be either borrowed or owned. It avoids allocation by using a reference until mutation is required, at which point it clones the data into an owned version. Useful for string processing where most inputs aren't modified.

**R17**: `mod` declares a module; `use` creates a shortcut to a path; `pub` makes items visible outside the module. In Rust 2018+, modules can be defined in separate files without needing explicit `mod.rs` files as strictly as in 2015.

**R18**: `Pin<T>` prevents a value from being moved in memory. This is critical for async futures because they may contain references to their own fields (self-referential). If the future moved, those pointers would become invalid. `Unpin` is a marker trait for types that are safe to move.

**R19**: Declarative macros (`macro_rules!`) use pattern matching on tokens. Procedural macros act like functions that take a stream of tokens and return new tokens (e.g., `derive`). Hygiene ensures that macro-generated variables don't accidentally clash with user variables.

**R20**: Zero-cost abstractions mean you don't pay for what you don't use. **Monomorphization** generates specialized code for each generic type used, removing runtime overhead. Iterators compile down to assembly identical to manual loops, and static dispatch avoids vtable lookups entirely.
