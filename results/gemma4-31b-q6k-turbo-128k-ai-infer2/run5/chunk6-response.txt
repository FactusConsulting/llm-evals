## JavaScript / TypeScript

**JS1**: `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped; `let` can be reassigned, while `const` cannot. **Hoisting** is the JS behavior where declarations are moved to the top of their scope during compilation.

**JS2**: The **Event Loop** coordinates execution. It monitors the **Call Stack** (synchronous code). When the stack is empty, it processes the **Microtask Queue** (Promises, `queueMicrotask`) entirely before moving to the **Macrotask Queue** (setTimeout, setInterval, I/O), which handles one task per loop iteration.

**JS3**: A **closure** is a function that remembers its lexical environment even when executed outside that scope. *Example*: A counter function returning an inner function that increments a private variable. *Loop bug*: Using `var` in a for-loop creates one shared variable across iterations; fix this by using `let`, which creates a new binding for every iteration.

**JS4**: A **Promise** represents a future value. `async/await` is syntactic sugar for Promises, making asynchronous code look synchronous. Error handling: `.catch()` for Promises or `try...catch` blocks for `await`. `Promise.all` rejects immediately if any promise fails; `Promise.allSettled` waits for all promises regardless of outcome.

**JS5**: **Interfaces** define object shapes and support "declaration merging" (adding fields later); **Types** are aliases for any type (unions, primitives, tuples). Use interfaces for public APIs/objects and types for complex logic/unions. **Discriminated Unions** use a common literal property (e.g., `type: 'circle' | 'square'`) to allow TypeScript to narrow the specific type within a conditional block.

**JS6**: JS uses **prototypal inheritance**, where objects inherit properties from a prototype chain. `Object.create(proto)` creates a new object with `proto` as its internal `[[Prototype]]`. ES6 classes are "syntactic sugar"; they still use prototypes under the hood via the `prototype` property on the class constructor.

**JS7**: The `this` keyword refers to the execution context. Binding priority: 1) New binding (`new`), 2) Explicit binding (`call`, `apply`, `bind`), 3) Implicit binding (method call), 4) Default binding (global window/undefined in strict mode). `bind()` returns a *new* function with a fixed `this`; it cannot be re-bound once created.

**JS8**: `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` triggers a callback when a referenced object is GC'd. `WeakMap` keys must be objects because only then can the engine track if no other strong references exist, allowing the key and value to be collected together.

**JS9**: V8 optimizes using **Hidden Classes** (assigning a shape based on property order) and **Inline Caching** (caching the offset of a property lookup). Deoptimization occurs when shapes change dynamically (e.g., adding properties in different orders or changing types), forcing V8 to fall back to slower generic lookups.

**JS10**: **Tree-shaking** removes unused code during bundling. It works with ES Modules (ESM) because `import`/`export` are static; CommonJS uses dynamic `require()`, meaning the bundler cannot determine what is used until runtime, making effective tree-shaking nearly impossible.

**JS11**: `null` is an intentional absence of value; `undefined` means a variable was declared but not assigned. `==` performs type coercion (`null == undefined` is true); `===` does not. `??` (**Nullish Coalescing**) returns the right side only if the left is `null/undefined`. `?.` (**Optional Chaining**) short-circuits to `undefined` if the chain is broken by `null/undefined`.

**JS12**: `map()` transforms each element; `filter()` selects elements meeting a predicate; `reduce()` aggregates values into one result. An initial value for `reduce` prevents errors on empty arrays and sets the starting accumulator. `flatMap()` maps then flattens one level deep; useful when mapping 1 item to multiple items.

**JS13**: Template literals use backticks (\`) for interpolation `${}`. **Tagged templates** allow passing a function as a prefix to a template literal to process it. *Example*: A `sql` tag that escapes variables to prevent SQL injection: `` sql`SELECT * FROM users WHERE id = ${id}` ``.

**JS14**: Destructuring extracts data from objects `{a, b} = obj` or arrays `[x, y] = arr`. You can rename via `{oldName: newName}` and set defaults `{port = 80}`. The rest operator `...rest` collects all remaining properties/elements into a new object/array.

**JS15**: `for...in` iterates over enumerable keys (strings) of an object; `for...of` iterates over iterable values (arrays, strings). Avoid `for...in` on arrays because it may include inherited prototype properties and does not guarantee order.

**JS16**: Generics `<T>` create reusable components. **Constraints** (`T extends U`) limit types. **Conditional Types** (`T extends U ? X : Y`) choose types based on logic. `infer` allows extracting types within conditionals. *Example*: `type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never`.

**JS17**: CommonJS uses `require`/`module.exports` (synchronous); ESM uses `import`/`export` (asynchronous/static). Node handles both by checking the `.mjs` extension or the `"type": "module"` field in `package.json`, which treats all `.js` files as ESM.

**JS18**: TypeScript is **structurally typed** (if shapes match, they are compatible). Excess property checks apply only when assigning object literals directly to a type. `extends` creates a subtype; `satisfies` validates that a value matches a type without changing its inferred type. Variance refers to how subtypes relate to generic parameters (covariance for output, contravariance for input).

**JS19**: `Proxy` wraps an object to intercept operations via traps (e.g., `get`, `set`). `Reflect` provides methods that mirror these traps. *Practical example*: A reactive state system where setting a property automatically triggers a UI re-render.

**JS20**: `SharedArrayBuffer` allows memory sharing between Web Workers. `Atomics` provide thread-safe operations (`add`, `load`, `store`) on this shared buffer. `Atomics.wait()` puts a thread to sleep until another thread calls `Atomics.notify()`, ensuring synchronized communication.

## Bash

**B1**: `$@` and `$*` both represent all positional parameters. When quoted: `"$@"` preserves each argument as a separate word; `"$*"` joins them into a single string separated by the first character of `IFS`.

**B2**: `set -euo pipefail`: `-e` exits immediately if a command fails; `-u` treats unset variables as errors; `-o pipefail` ensures a pipeline returns the exit code of the last non-zero command in the chain.

**B3**: `$(command)` is modern command substitution; `` `command` `` is legacy. `$((expression))` performs shell arithmetic (fast, internal); `expr` is an external utility for math.

**B4**: Process substitution `<(command)` creates a temporary file descriptor that acts like a file. *Example*: Comparing two directory listings without creating temp files: `diff <(ls dir1) <(ls dir2)`.

**B5**: Use quotes around variables `" "$f" "`. Avoid `for f in $(ls)` because it splits filenames containing spaces. The safe way is using globbing (`for f in *`) or `find -print0 | while read -d '' f`.

**B6**: Here doc `<<EOF` reads multi-line input until a delimiter. Here string `<<< "str"` passes a single string to stdin. `<<-EOF` strips leading tab characters from each line.

**B7**: 
1. `cmd > file 2>&1`: stdout $\to$ file, then stderr $\to$ where stdout goes (file). Both captured.
2. `cmd 2>&1 > file`: stderr $\to$ current stdout (screen), then stdout $\to$ file. Only stdout captured.
3. `cmd &> file`: Shorthand for both redirected to the same file.

**B8**: Use `mkdir lockdir` as an atomic operation; if it succeeds, you have the lock. Trap `SIGTERM`, `INT`, and `EXIT` to run `rmdir lockdir`. `mkdir` is preferred over files because it's an atomic system call at the OS level, preventing race conditions between checking existence and creating the file.

**B9**: Single quotes `'...'` are literal. Double quotes `"..."` allow interpolation of variables/commands. No quotes lead to word splitting and globbing. *Example*: `echo "$VAR"` vs `echo $VAR` behaves differently if `$VAR` contains spaces.

**B10**: `-f` checks if file exists/is regular; `-d` checks directory; `-r` checks readability. `[ ]` is POSIX standard; `[[ ]]` is a Bash extension supporting regex (`=~`) and logical operators without needing separate flags.

**B11**: `$?` last command exit status; `$$` PID of current script; `$!` PID of most recent background process; `$#` number of arguments passed to script.

**B12**: Define via `foo() { ... }` or `function foo { ... }`. The former is POSIX compliant. Functions return values by printing to stdout (captured via `$(...)`) or setting global variables; the `return` keyword only returns 0-255 exit codes.

**B13**: `PATH` is a colon-separated list of directories searched for executables. Builtins (e.g., `cd`, `echo`) run inside the shell; external commands are binaries in `PATH`. Use `type -a <cmd>` to check which one is being used.

**B14**: `trap 'handler' SIGNAL` catches signals. `EXIT` runs on any termination, `ERR` on non-zero exits, `INT` on Ctrl+C, `TERM` on kill. If multiple arrive, they are queued/handled sequentially based on when the shell processes them.

**B15**: Command substitution puts output into a string; `xargs` passes stdin as arguments to a command. To handle spaces: `find . -print0 | xargs -0`. `-P` allows running $N$ processes in parallel.

**B16**: Arrays: `arr=(1 2)`; Associative: `declare -A map`. Append: `arr+=("val")`. Length: `${#arr[@]}`. Iterate associative arrays using keys: `for k in "${!map[@]}"; do echo ${map[$k]}; done`.

**B17**: Subshell `(...)` creates a child process with its own scope; changes to variables are lost. Group `{ ...; }` executes in current shell and preserves variable changes. Piping into a while loop (`cat file | while...`) creates a subshell, losing internal variable updates.

**B18**: SIGINT (Ctrl+C), SIGTERM (polite request), SIGHUP (terminal closed), SIGKILL (immediate force). Graceful shutdown is achieved by trapping `SIGTERM`, cleaning up background PIDs via `wait`, then exiting.

**B19**: Logic: Use `split` to chunk the log $\to$ `xargs -P N` to run processing function on chunks $\to$ merge results files. Trade-off: Parallelism increases CPU usage but may be bottlenecked by Disk I/O. Error propagation requires checking exit codes of worker processes or writing errors to a shared log.

**B20**: `exec cmd` replaces the current shell process with the new command. FD manipulation: `exec 3>file` opens fd 3 for output; `exec 3>&-` closes it. A coprocess (`coproc`) allows bidirectional communication using pipes between the main script and a background process.

## PowerShell

**PS1**: `Write-Output` sends objects to the pipeline for further processing. `Write-Host` writes directly to the console host (UI) and bypasses the pipeline entirely. Using `Write-Host` in a function prevents other commands from receiving that data.

**PS2**: The pipeline passes *objects*, not text. `ForEach-Object` is a cmdlet that streams items one-by-one through the pipeline. The `foreach` statement loads the entire collection into memory first, making it faster for small sets but less efficient for large ones.

**PS3**: `[hashtable]` is an unordered key-value pair collection. `[PSCustomObject]` is an ordered object with properties. Use hashtables for lookups and PSCustomObjects for structured data meant for export/display. Convert via casting: `[pscustomobject]$myHash`.

**PS4**: Terminating errors stop execution immediately (catchable by `try/catch`). Non-terminating errors produce a warning but continue. `-ErrorAction Stop` converts non-terminating errors into terminating ones. `$ErrorActionPreference = 'Stop'` applies this globally.

**PS5**: Splatting `@params` allows passing a hashtable of parameter names and values to a cmdlet. Unlike passing a hashtable as a single argument (which would be treated as one value), splatting maps keys directly to named parameters.

**PS6**: Remoting uses WinRM (WSMan) or SSH. `Invoke-Command -ComputerName` runs a script block once; `Enter-PSSession` starts an interactive shell. It relies on the Windows Remote Management service unless configured for SSH.

**PS7**: PowerShell "unrolls" arrays returned by functions in the pipeline. If a function returns 1 item, it's passed as that item; if multiple, they are streamed individually. Result of example: `$x` becomes a string ("one") rather than an array because PS unrolled the single-element array. Correct pattern: use `,@()` to force array return.

**PS8**: A `[scriptblock]` is code stored as data `{ ... }`. Pass via `-ScriptBlock`. The **double-hop problem** occurs when credentials aren't delegated from the second remote machine back to a third. Solve using CredSSP or passing explicit credentials via `-ArgumentList`.

**PS9**: `@()` creates an empty array; `[array]` casts a value to an array. To force a result into an array, wrap it: `@($result)`. Indexing `$null` usually returns null without error; indexing an empty array also returns null but maintains object type consistency.

**PS10**: Operators like `-eq`, `-like`, and `-match` are case-insensitive. Case-sensitive versions start with 'c' (e.g., `-ceq`). `-contains` checks if a collection contains a specific element (`$list -contains $item`); `-in` is the reverse (`$item -in $list`).

**PS11**: Modules encapsulate logic. `.psm1` (script module) contains functions; `.psd1` (manifest) defines metadata/dependencies; binary modules are C# DLLs. `Import-Module` loads these into the current session scope.

**PS12**: Double quotes `"..."` interpolate variables; single quotes `'...'` are literal. Use sub-expressions `$($expr)` for complex interpolation. Here-strings `@" ... "@` allow multi-line strings while preserving formatting.

**PS13**: `Get-Member` reveals properties and methods of an object. Properties store data; Methods perform actions; NoteProperties are dynamic additions. `Select-Object` filters columns (properties); `Where-Object` filters rows based on criteria.

**PS14**: PS Classes provide strong typing and inheritance, similar to C#. They differ by being more flexible but have limitations in constructor complexity compared to full .NET classes. Use classes for structured data models and functions for procedural tasks.

**PS15**: `[CmdletBinding()]` enables advanced features like `-WhatIf`, `-Confirm`, and common parameters. `SupportsShouldProcess` allows those flags. `Begin` runs once at start, `Process` runs per pipeline item, `End` runs once at completion.

**PS16**: Providers map different stores (Registry, Certs) as drives. You can access the registry using file system syntax: `cd HKCU:\Software\MyApp`. This abstracts diverse data sources into a unified "drive" interface.

**PS17**: A `runspace` is an isolated execution environment. `RunspacePool` manages multiple runspaces for parallel work. `ForEach-Object -Parallel` (v7+) simplifies this by managing pools automatically, whereas manual management offers finer control over thread safety and state.

**PS18**: PSScriptAnalyzer performs static analysis of AST against rules. Severity levels include Info, Warning, Error. Custom rules are defined via XML or script; suppress specific warnings using attributes like `[Diagnostics.SuppressMessage]`.

**PS19**: `$using:` injects local variables into remote/parallel scopes. Serialization uses CLIXML; complex objects may lose fidelity if they exceed serialization depth limits or contain non-serializable types (like open file handles).

**PS20**: DSC ensures infrastructure stays in a desired state. The Local Configuration Manager (LCM) applies MOF files to ensure consistency. Modern IaC has largely shifted toward Terraform or Azure Automanage, though DSC remains used for OS-level configuration.
