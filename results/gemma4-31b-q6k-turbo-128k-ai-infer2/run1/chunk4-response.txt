## Go

**G1**: An **array** has a fixed size defined at compile time; a **slice** is a descriptor of an array segment (pointer, length, and capacity). When appending to a slice that reaches its capacity, Go allocates a new, larger underlying array (usually doubling in size for small slices), copies existing elements over, and returns a new slice header pointing to the new array.

**G2**: `var x int` declares a variable with its zero value (`0`); `x := 0` is short-variable declaration which both declares and initializes. You cannot use `:=` outside of functions (package level) or when you only want to assign a value to an already declared variable without introducing a new one.

**G3**: A **goroutine** is a lightweight thread managed by the Go runtime. Unlike OS threads (which have large stacks ~MBs), goroutines start small (~2KB) and grow dynamically. The **GMP model** consists of: **G** (Goroutine), **M** (Machine/OS Thread), and **P** (Processor/Logical Context). P schedules Gs onto Ms to maximize CPU utilization via work-stealing.

**G4**: Channels are pipes for communication between goroutines. **Unbuffered** channels block the sender until a receiver is ready. **Buffered** channels allow sending up to $N$ values without blocking. If a buffered channel is full, the sender blocks until a receiver removes an element.

**G5**: The `context` package manages request scoped values, cancellation signals, and deadlines.
```go
ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
_, err := http.DefaultClient.Do(req) // Returns error if timeout hits
```

**G6**: Go uses **implicit satisfaction**: any type that implements the required methods satisfies an interface; no `implements` keyword is needed. This allows decoupled design. `interface{}` (or `any`) can hold any value. It's powerful for generic containers but dangerous because it bypasses compile-time type safety, requiring runtime type assertions.

**G7**: The code has a **data race**. There is no synchronization ensuring the write to `ready` in one goroutine is visible to the read in the main loop. In the Go memory model, this is undefined behavior. Fix: Use a `channel` or `sync.Mutex`.
*Correct alternative:* `ready := make(chan bool); go func(){ ... ready <- true }(); <-ready`.

**G8**: `sync.Mutex` provides exclusive access. `sync.RWMutex` allows multiple concurrent readers OR one writer. Use `sync.Map` for caches with high contention where keys are stable and reads far outweigh writes. A regular map + mutex is faster for most general cases due to lower overhead.

**G9**: Modules manage dependencies via `go.mod` (requirements/versions) and `go.sum` (cryptographic checksums for reproducibility). `go mod tidy` adds missing modules and removes unused ones. **MVS (Minimum Version Selection)** selects the lowest version that satisfies all constraints, avoiding "latest" instability.

**G10**: `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In-First-Out)** order. Gotcha: Using `defer` inside a loop can lead to resource exhaustion because they don't execute until the *function* ends, not the loop iteration.

**G11**: A pointer stores the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `p := &User{Name: "Alice"}`.

**G12**: `init()` runs once per package upon import, after variable initialization but before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source files.

**G13**: `make` initializes slices, maps, and channels (returning an initialized object); `new` allocates zeroed memory for any type and returns a pointer (`*T`). Use `make` for reference types; use `new` when you just need a pointer to a zeroed value.

**G14**: Go uses explicit return values for errors. The `error` interface has one method: `Error() string`. Idiom: `if err != nil { return ... }`. `errors.Is` checks if an error matches a specific sentinel; `errors.As` attempts to cast an error to a specific type. Both handle wrapped errors, whereas `==` does not.

**G15**: 
- **Slice**: `nil`
- **Map**: `nil`
- **Channel**: `nil`
- **Struct**: All fields set to their respective zero values.

**G16**: A race condition occurs when two goroutines access shared memory concurrently and at least one is a write. `-race` uses a runtime instrumentation tool to detect these. Fix: Wrap the shared variable in a `sync.Mutex` or communicate via channels to "share memory by communicating."

**G17**: `select` blocks until one of its communication operations can proceed. Unlike `switch`, it handles channel ops. If multiple cases are ready, one is chosen **pseudo-randomly**. Timeout implementation: `case <-time.After(duration):`.

**G18**: Escape analysis determines if a variable can stay on the stack or must move to the heap (escapes). It escapes if it's referenced outside the function scope. Use `go build -gcflags="-m"` to inspect. Heap allocation increases GC pressure, reducing performance.

**G19**: `reflect` allows inspecting types/values at runtime. `Type` describes the structure; `Value` represents the actual data. Reflection is slow due to dynamic checks and boxing. Justified for generic libraries (e.g., JSON encoders); otherwise, code generation (`stringer`) is preferred for performance.

**G20**: `go:embed` allows embedding files into binaries at compile time. Single files use `[]byte` or `string`; directories use `embed.FS`. It implements `io/fs.FS`, allowing the embedded filesystem to be used with standard library functions that accept an FS interface.

## Rust

**R1**: Ownership ensures memory safety without a GC. Rules: 
1. Each value has a variable called its owner.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the value is dropped.

**R2**: `String` is a heap-allocated, growable UTF-8 string (owned). `&str` is a string slice (a reference to some sequence of UTF-8 bytes). Use `&str` in function signatures for flexibility (accepts both), and `String` when you need ownership or modification.

**R3**: Borrowing lets you access data without taking ownership. **Shared references (`&T`)** allow multiple read-only accesses. **Mutable references (`&mut T`)** allow exactly one exclusive write access. You cannot have a mutable reference while shared references exist.

**R4**: `Result<T, E>` handles recoverable errors; `Option<T>` handles optionality (Some/None). The `?` operator unwraps a `Result`/`Option` or returns the error early.
```rust
fn read_file() -> Result<String, std::io::Error> {
    std::fs::read_to_string("file.txt") // Returns Result
}
```

**R5**: 
- `Box<T>`: Heap allocation with single ownership.
- `Rc<T>`: Reference counted pointer for multiple owners (single-threaded).
- `Arc<T>`: Atomic Reference Counted pointer for multi-threaded sharing.

**R6**: Traits define shared behavior (similar to interfaces). Unlike Go's implicit satisfaction, Rust requires explicit implementation (`impl Trait for Type`). `dyn Trait` is a trait object (dynamic dispatch via vtable), whereas `T: Trait` uses generics (static dispatch via monomorphization).

**R7**: It fails because the compiler doesn't know which input slice the returned reference refers to. Fix by adding lifetime annotations:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8**: `Send` allows transferring ownership between threads; `Sync` allows sharing references across threads. `Rc<T>` isn't `Send`/`Sync` because its reference count update isn't atomic (race condition risk). `Arc<T>` uses atomic operations for the counter, making it thread-safe.

**R9**: Async in Rust is **poll-based**. A `Future` is a state machine that does nothing until polled. The **Executor** (e.g., Tokio) manages these futures and wakes them when they are ready. This differs from Go’s "push" model where goroutines are scheduled preemptively/cooperatively by the runtime.

**R10**: `unsafe` lets you bypass some safety checks. 3 things: Dereferencing raw pointers, calling unsafe functions (FFI), mutating static variables. Justified for low-level hardware access or implementing high-performance abstractions (like `Vec`).

**R11**: Pattern matching (`match`) evaluates an expression against patterns. `if let` is syntactic sugar for match when only one case matters. Match must be **exhaustive**; all possible values of the type must be covered.

**R12**: `Vec<T>` is dynamic; `[T; N]` is fixed size. When a `Vec` exceeds capacity, it reallocates a larger block of memory on the heap, copies elements over, and frees the old allocation.

**R13**: Enums in Rust are **sum types** (can hold data). Unlike C enums (integers), each variant can have different fields. `Option<T>` replaces null with `Some(T)` or `None`, forcing developers to handle the absence of value explicitly.

**R14**: `impl` blocks define methods. `&self`: immutable borrow; `&mut self`: mutable borrow; `self`: consumes ownership. Associated functions (e.g., `String::new()`) do not take `self` as a parameter.

**R15**: `derive` automatically implements traits via macros. Common: `Debug` (printing), `Clone` (duplicating), `PartialEq` (equality), `Serialize` (Serde). You cannot derive if the trait requires custom logic that doesn't fit the generic implementation.

**R16**: `Cow` (Clone-on-Write) allows a type to be either borrowed or owned. It avoids allocation by keeping a reference until mutation is required, at which point it clones the data into an owned version. Useful for parsing where most strings don't need modification.

**R17**: `mod` declares a module; `use` brings paths into scope; `pub` makes items visible. Files map to modules (`mod file_name`). In Rust 2018+, `extern crate` was replaced by simplified pathing and automatic discovery in `src/`.

**R18**: `Pin<T>` prevents a value from moving in memory. This is critical for **self-referential structs** used in async blocks, where a pointer inside the struct points to another field within the same struct. `Unpin` is a marker trait for types that are safe to move.

**R19**: Declarative macros (`macro_rules!`) use pattern matching on tokens. Procedural macros act as compiler plugins: `derive` adds traits, attribute macros modify functions/structs, function-like macros generate code. Hygiene ensures macro variables don't clash with local scope.

**R20**: Zero-cost abstractions mean you don't pay for what you don't use. Iterators compile down to loops; generics use **monomorphization** (generating specific code for each type), resulting in static dispatch that allows the compiler to inline calls, matching C performance.
