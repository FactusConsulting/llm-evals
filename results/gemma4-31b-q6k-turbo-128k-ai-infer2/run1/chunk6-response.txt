## JavaScript / TypeScript

**JS1**: `var` is function-scoped and hoisted (initialized as `undefined`), allowing it to be used before declaration. `let` and `const` are block-scoped. `const` prevents reassignment of the identifier. **Hoisting** is JS's behavior of moving declarations to the top of their scope during the compilation phase.

**JS2**: The **Event Loop** manages execution by monitoring the Call Stack. When the stack is empty, it processes tasks in order: first all available **Microtasks** (Promises, `queueMicrotask`) until the queue is exhausted, then one **Macrotask** (setTimeout, setInterval, I/O) from the macrotask queue.

**JS3**: A **closure** is a function that remembers its lexical environment even when executed outside that scope. *Example*: A counter function returning an inner function that increments a private variable. *Bug*: In old `for` loops with `var`, the closure captured the reference to the variable, not the value at each iteration; fixed using `let` (which creates a new binding per iteration).

**JS4**: A **Promise** represents a future value. `async/await` is syntactic sugar for Promises. Error handling uses `.catch()` for Promises or `try...catch` blocks for `async/await`. `Promise.all` rejects immediately if any promise fails; `Promise.allSettled` waits for all promises to complete regardless of success or failure.

**JS5**: **Interfaces** are primarily for defining object shapes and can be merged (declaration merging); **Types** are aliases for any type (unions, primitives, intersections). Use interfaces for public APIs/classes and types for complex unions. **Discriminated Unions** use a common literal property (e.g., `type: 'circle' | 'square'`) to allow TypeScript to narrow the specific type in a switch/if block.

**JS6**: JS uses **prototypal inheritance**, where objects inherit directly from other objects via a prototype chain. `Object.create(proto)` creates a new object with the specified prototype. ES6 classes are "syntactic sugar"; they still use prototypes under the hood but provide a cleaner syntax for constructor functions and method definitions.

**JS7**: `this` refers to the execution context. Binding rules (priority): 1. **New** (constructor), 2. **Explicit** (`call`, `apply`, `bind`), 3. **Implicit** (object method call), 4. **Default** (global/undefined). `bind()` returns a *new* function with `this` permanently bound; it cannot be re-bound by subsequent calls.

**JS8**: `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` executes a callback after GC collects the object. `WeakMap` keys must be objects because only then can the engine track if the key is no longer referenced elsewhere, allowing the entry to be removed automatically.

**JS9**: V8 optimizes using **Hidden Classes** (shapes) to track property layouts. **Inline Caching** remembers these shapes to skip lookup overhead. **Deoptimization** occurs when code changes its shape (e.g., adding properties in different orders or changing types), forcing V8 to fall back to slower interpreted code.

**JS10**: **Tree-shaking** removes unused exports from the final bundle. It works with ES Modules (ESM) because `import`/`export` are static and analyzable at build time. CommonJS (`require`) is dynamic (can happen inside conditionals), making it nearly impossible for tools to determine what is truly unused.

**JS11**: `null` is an intentional assignment of "no value"; `undefined` means a variable was declared but not assigned. `==` performs type coercion; `===` checks both type and value. `??` (nullish coalescing) returns the right side only if the left is `null` or `undefined`. `?.` (optional chaining) short-circuits to `undefined` if a reference is nullish.

**JS12**: `map()` transforms each element into a new array; `filter()` selects elements based on a predicate; `reduce()` aggregates values into a single result. An initial value in `reduce()` prevents errors on empty arrays and sets the starting accumulator. `flatMap()` maps then flattens one level, useful for mapping 1:N relationships.

**JS13**: Template literals use backticks (\`${}\`). **Tagged templates** allow you to pass the string parts and interpolated values to a function. *Example*: `` sql`SELECT * FROM users WHERE id = ${id}` `` where the tag function escapes the ID to prevent SQL injection.

**JS14**: Destructuring extracts data from arrays/objects into variables. Object: `{ name, age } = user`; Array: `[first, second] = list`. Default values are set via `= default`. The rest operator (`...`) collects remaining items into an array or object.

**JS15**: `for...in` iterates over enumerable keys (strings), including inherited ones. `for...of` iterates over iterable values (arrays, strings). Avoid `for...in` on arrays because it may iterate over non-index properties and treats indices as strings rather than numbers.

**JS16**: Generics `<T>` create reusable components. **Constraints** (`T extends U`) limit what types can be passed. **Conditional Types** (`T extends U ? X : Y`) choose a type based on a condition. `infer` allows extracting a type from another (e.g., getting the return type of a function).

**JS17**: CommonJS uses `require`/`module.exports` (synchronous); ESM uses `import`/`export` (static/asynchronous). Node handles both; `.mjs` is always ESM, `.cjs` is CJS. `"type": "module"` in `package.json` tells Node to treat all `.js` files as ESM.

**JS18**: TypeScript's structural system cares about the *shape* of data, not its name. **Excess property checks** occur when assigning an object literal directly to a typed variable. `extends` creates a subtype; `satisfies` validates that a value matches a type without changing the inferred type of the value. Variance: Covariance (out) allows wider types; Contravariance (in) requires narrower types for inputs.

**JS19**: `Proxy` intercepts operations (get, set, etc.) via traps. `Reflect` provides static methods to perform those same operations. *Example*: A Proxy can implement reactive data binding by triggering a UI update whenever a property is modified (`set` trap).

**JS20**: `SharedArrayBuffer` allows memory sharing between Web Workers. `Atomics` provide thread-safe operations on this buffer. `Atomics.wait()` puts a thread to sleep until a specific index changes, and `Atomics.notify()` wakes it up, ensuring strict ordering and preventing race conditions.

## Bash

**B1**: `$@` and `$*` both represent all positional parameters. In double quotes, `"$@"` expands each argument as a separate quoted string; `"$*"` joins them into one single string separated by spaces.

**B2**: `-e`: Exit immediately if a command fails. `-u`: Treat unset variables as an error. `-o pipefail`: The pipeline return status is the value of the last (rightmost) command to exit with a non-zero status.

**B3**: `$(command)` is preferred over backticks because it supports nesting and handles escaping better. `$((expression))` is for shell arithmetic expansion; `expr` is an external utility that is slower and has more complex quoting rules.

**B4**: Process substitution `<(command)` makes the output of a command appear as a file. *Example*: `diff <(ls dir1) <(ls dir2)` compares two directory listings without creating temporary files.

**B5**: Always quote variables: `for f in "$files"; do ...`. Avoid `for f in $(ls)` because it splits filenames containing spaces or newlines. Use globbing (`for f in *.txt`) or `find -print0 | while read -d '' f`.

**B6**: Here document `<<EOF` allows multi-line input until "EOF" is found. Here string `<<< "string"` passes a single string to stdin. `<<-EOF` strips leading tabs from the input lines.

**B7**: 
1. `cmd > file 2>&1`: Stdout $\rightarrow$ file, then Stderr $\rightarrow$ where stdout currently goes (file). Result: both in file.
2. `cmd 2>&1 > file`: Stderr $\rightarrow$ current stdout (screen), then Stdout $\rightarrow$ file. Result: stderr on screen, stdout in file.
3. `cmd &> file`: Shorthand for redirecting both to file.

**B8**: Use `mkdir lockdir` because it is an atomic operation at the OS level; if the directory exists, it fails immediately. Cleanup via `trap 'rm -rf lockdir' EXIT SIGTERM SIGINT`.

**B9**: Single quotes ('') treat everything literally. Double quotes ("") allow variable and command interpolation. No quotes allow word splitting and glob expansion. *Example*: `echo "$VAR"` vs `echo $VAR` (the latter splits if `$VAR` contains spaces).

**B10**: `-f` (exists/file), `-d` (directory), `-r` (readable). `[ ]` is POSIX standard; `[[ ]]` is a Bash extension that supports regex (`=~`), logical operators (`&&`, `||`) without needing separate flags, and prevents word-splitting errors.

**B11**: `$?` last exit status (e.g., check if previous cmd succeeded); `$$` PID of current shell; `$!` PID of last background process; `$#` number of arguments passed to script.

**B12**: Defined as `foo() { ... }` or `function foo { ... }`. The former is POSIX compliant. Return values are handled by returning an exit code (0-255) using `return` or echoing output for data retrieval.

**B13**: `PATH` is a colon-separated list of directories searched for executables. Builtins (like `cd`) run inside the shell; external commands (like `ls`) are binaries in PATH. Use `type -a command` to see which one is used.

**B14**: `trap 'handler' signal` catches signals. Common: `EXIT` (script ends), `ERR` (command fails), `INT` (Ctrl+C), `TERM` (kill). Signals arrive asynchronously; handlers execute sequentially as they are triggered.

**B15**: Command substitution returns a string; `xargs` converts stdin into arguments for a command. To handle spaces, use `find -print0 | xargs -0`. `-P N` allows running $N$ processes in parallel.

**B16**: Arrays: `arr=(1 2 3)`, append with `arr+=(4)`, length `${#arr[@]}`. Associative arrays: `declare -A assoc`, set via `assoc[key]=val`, iterate over keys using `${!assoc[@]}`.

**B17**: Subshell `(...)` forks a new process; changes to variables are lost when it exits. Group `{ ...; }` runs in current shell scope. Piping (`cmd | while...`) creates a subshell, meaning variable updates inside the loop don't persist outside.

**B18**: SIGINT (Interrupt/Ctrl+C), SIGTERM (Polite request to stop), SIGHUP (Terminal closed), SIGKILL (Forced kill, cannot be trapped). Graceful shutdown is achieved by trapping SIGTERM and cleaning up background PIDs stored in an array.

**B19**: Use `split` to break logs $\rightarrow$ `xargs -P N` calling a processing function $\rightarrow$ merge results files. Trade-off: Parallelism increases CPU usage but can bottleneck on Disk I/O. Error propagation requires checking exit codes of xargs or writing errors to a log file.

**B20**: `exec` replaces the current shell process with the new command. For FD manipulation: `exec 3>file` opens FD 3 for writing; `exec 3>&-` closes it. A coprocess (`coproc`) allows bidirectional communication via two pipes using `read` and `echo`.

## PowerShell

**PS1**: `Write-Output` sends objects into the pipeline for further processing. `Write-Host` writes directly to the console host (UI) and bypasses the pipeline entirely. Using `Write-Host` inside a function prevents other cmdlets from receiving that data.

**PS2**: The pipeline passes *objects*, not text. `ForEach-Object` is a cmdlet used within a pipeline (lazy evaluation); `foreach` statement is a language keyword (faster, loads collection into memory first).

**PS3**: `[hashtable]` is an unordered key-value pair; `[PSCustomObject]` is an ordered object with properties. Use hashtables for lookups and PSCustomObjects for structured output. Convert via casting: `[PSCustomObject]$myHash`.

**PS4**: Terminating errors stop execution immediately; non-terminating errors print a warning but continue. `-ErrorAction Stop` converts a non-terminating error into a terminating one so it can be caught by a `try/catch` block.

**PS5**: Splatting `@params` takes a hashtable and expands its keys as named parameters to a cmdlet. Unlike passing a hashtable as a single argument, splatting mimics typing each parameter individually on the command line.

**PS6**: Remoting uses WinRM or SSH. `Invoke-Command -ComputerName` runs a scriptblock once and returns results; `Enter-PSSession` creates an interactive remote shell. Both use WSMan (WinRM) or SSH protocols.

**PS7**: PowerShell implicitly unwraps collections. If a function returns 0 items, result is `$null`; if 1 item, it's that object; >1, it's an array. This causes "unwrapping" bugs. Correct pattern: wrap return in `@(...)` to force an array regardless of count.

**PS8**: A `[scriptblock]` is a reusable piece of code `{...}`. Pass them via `-ScriptBlock` parameter. The **double-hop problem** occurs when credentials aren't passed from the first remote hop to a second. Solve using CredSSP or explicitly passing credentials with `Invoke-Command`.

**PS9**: `@()` ensures the result is always an array. Indexing into `$null` usually returns `$null` without error in PS, whereas indexing an empty array also returns `$null`. Use `@($result)[0]` to safely get the first element.

**PS10**: Operators are case-insensitive by default (`-eq`). Case-sensitive versions start with 'c' (`-ceq`). `-contains` checks if a collection contains a value; `-in` is the inverse (checks if a value is in a collection).

**PS11**: Modules package functions/variables. `.psm1` contains logic; `.psd1` is a manifest for metadata/dependencies. Binary modules are .NET DLLs. `Import-Module` loads these into the current session.

**PS12**: Interpolation uses double quotes `"Hello $name"`. For expressions, use subexpressions: `"Value: $($obj.Property)"`. Here-strings `@" ... "@` allow multi-line strings without escaping quotes.

**PS13**: `Get-Member` reveals the object type and its members. Properties are data; Methods are actions; NoteProperties are dynamic properties added at runtime. `Select-Object` picks specific properties; `Where-Object` filters objects based on criteria.

**PS14**: PowerShell classes provide strong typing and structure but have limited inheritance compared to C#. They lack interfaces. Use classes for complex data models/DTOs and functions for operational tasks.

**PS15**: `[CmdletBinding()]` turns a function into an "Advanced Function," enabling common parameters like `-Verbose`. `SupportsShouldProcess` enables `-WhatIf`/`-Confirm`. `Begin`, `Process`, and `End` blocks handle pipeline input sequentially.

**PS16**: Providers map different stores (Registry, Certs) as drives. You can access the registry using file system syntax: `Get-ChildItem HKLM:\Software\Microsoft`.

**PS17**: A `runspace` is an isolated execution environment. `RunspacePool` manages multiple runspaces for parallelism. `ForEach-Object -Parallel` (v7+) simplifies this by managing a pool of runspaces internally.

**PS18**: PSScriptAnalyzer performs static analysis against rules (e.g., avoiding `Write-Host`). Rules have severity levels (Error, Warning). It integrates into CI/CD via build pipelines to fail builds if coding standards aren't met.

**PS19**: `$using:var` injects a local variable into a remote session or parallel block. Serialization uses CLIXML; very deep objects or non-serializable .NET types may be truncated or cause errors during transmission.

**PS20**: DSC ensures a machine stays in a specific state. The LCM (Local Configuration Manager) is the engine that applies and monitors configurations. Modern infrastructure has largely shifted toward guest configuration or tools like Terraform/Ansible.
