**G1 — Easy:** An array in Go has a fixed length and type (e.g., `[5]int`), while a slice is a dynamic view (header) over a contiguous segment of an array, defined by its length and capacity. When you append to a slice that has reached its capacity, Go allocates a new underlying array (usually with a larger size), copies the existing elements, and updates the slice's pointer and length.

**G2 — Easy:** `var x int` declares a variable and initializes it to its zero value (0). `x := 0` is a short variable declaration that declares and initializes the variable in one step. You cannot use `:=` in function parameters or outside of a function (at the package level).

**G3 — Medium:** A goroutine is a lightweight thread managed by the Go runtime, not the OS. It differs from an OS thread in that it is much cheaper to create and has a smaller stack (default 2KB). The Go scheduler uses the **GMP model**: **G**oroutines (G), **M**achine threads (M), and **P**rocessors (P). The scheduler multiplexes Gs onto Ms, utilizing Ps to manage concurrency.

**G4 — Medium:** Channels provide typed conduits for communication. An **unbuffered** channel blocks the sender until the receiver is ready and vice versa. A **buffered** channel allows a certain number of messages to be sent without blocking. If you send to a full buffered channel, the operation blocks until a receiver takes a value.

**G5 — Medium:** The `context` package manages deadlines, cancellations, and request-scoped values. It is used to propagate cancellation signals to long-running operations.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()

req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
client := &http.Client{}
resp, err := client.Do(req)
```

**G6 — Medium:** Go interfaces are satisfied **implicitly** by any type that implements the methods, without explicit declaration. This differs from Java/C# where you must explicitly declare "implements". The **empty interface** `interface{}` (or `any`) accepts any type. It is powerful because it allows polymorphism without strict typing, but it is dangerous because it removes compile-time type safety, often requiring runtime type assertions.

Due to the Go memory model, the compiler or CPU might reorder the writes, causing the main loop to see `ready == true` while `data` is still empty. **Correct alternatives:** Use a `sync.Mutex` to protect access, or use a channel to signal completion and send the data.

**G8 — Hard:** `sync.Mutex` provides exclusive locking. `sync.RWMutex` allows multiple concurrent readers or a single writer. Use `sync.Map` when you have high contention on a map and read-heavy workloads, as it uses sharding to reduce lock contention. The performance trade-off is that `sync.Map` has higher overhead per operation than a standard map protected by a mutex.

**G9 — Hard:** Go modules manage dependencies. `go.mod` is the manifest file listing module path and dependencies. `go.sum` is a checksum file ensuring reproducible builds. `go mod tidy` removes unused dependencies and adds missing ones. **Minimum Version Selection (MVS)** is the algorithm used to determine the minimum compatible version of a dependency to use.

**G10 — Medium:** A `defer` statement schedules a function call to be run after the surrounding function returns. Multiple defers execute in **LIFO** (Last-In, First-Out) order. A common gotcha is capturing loop variables by reference in a closure; since the loop variable is shared, all deferred functions might print the same final value.

**G11 — Easy:** A pointer stores the memory address of a variable. The zero value of a pointer is `nil`. To create a pointer to a struct literal, use the address-of operator: `p := &MyStruct{Field: 1}`.

**G12 — Easy:** `init()` functions run automatically before `main()`. They run in the order of package imports (depth-first). A package can have multiple `init()` functions, and they execute in the order they appear in the source file.

**G13 — Easy:** `new(T)` allocates zeroed memory for a type `T` and returns a pointer to it. It works for all types. `make(T)` allocates and initializes a specific type: slices, maps, and channels. It returns the value (not a pointer) for these container types.

**G14 — Easy:** Error handling is explicit. The `error` interface is `type error interface { Error() string }`. The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error matches a specific error value (handling wrapped errors), while `errors.As` casts an error to a specific type to check for a specific underlying error.

**G15 — Easy:** Built-in composite types are `map`, `slice`, `channel`, and `struct`. Their zero values are: `nil` for `map`, `slice`, and `channel`; and the zero value of their fields for `struct`.

**G16 — Medium:** A race condition occurs when two goroutines access shared data concurrently without synchronization. The `-race` flag enables the race detector, which uses thread sanitization to detect data races at runtime. **Example:** A loop incrementing a counter. **Fix:** Use `sync.Mutex` to lock access or use a channel to send increments to a dedicated worker.

**G17 — Medium:** `select` waits for multiple channel operations to become ready. Unlike `switch`, it only works with channels. If multiple cases are ready, one is chosen arbitrarily. To implement a timeout, use `select { case <-ch: ... case <-time.After(time.Second): ... }`.

**G18 — Hard:** Escape analysis determines if a variable lives on the stack or heap. If a variable's address escapes the function scope (e.g., returned to the caller) or is too large for the stack, it is allocated on the heap. You can inspect this with `go build -gcflags="-m"`. **G19 — Hard:** `reflect.Type` describes the type of a value, while `reflect.Value` holds the actual value. Reflection is expensive (dynamic dispatch, bounds checking) and should be avoided in hot paths. ## Rust (20 questions)

**R1 — Easy:** Ownership is a set of rules that govern how Rust manages memory. The three rules are: 1) Each value in Rust has a variable that is called its **owner**. 2) There can only be one owner at a time. 3) When the owner goes out of scope, the value will be dropped.

**R2 — Easy:** `String` is an owned, heap-allocated string type. `&str` is a string slice (reference to a UTF-8 string). Use `String` when you need to own the data or modify it; use `&str` for function arguments or when borrowing existing data (e.g., string literals).

**R3 — Medium:** Borrowing allows reading or modifying data without taking ownership. The **borrow checker** enforces the rules: 1) You can have either one mutable reference or any number of immutable references at a time. 2) References must always be valid (non-null, non-dangling).

**R4 — Medium:** `Result<T, E>` represents a value that could be success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents a value that might be present (`Some(T)`) or absent (`None`). The `?` operator propagates errors from a function returning `Result` or `Option` if the value is `Err` or `None`.
```rust
use std::fs::File;
use std::io::{self, Read};

fn read_file(path: &str) -> io::Result<String> {
    let mut file = File::open(path)?; // Propagates error if open fails
    let mut contents = String::new();
    file.read_to_string(&mut contents)?;
    Ok(contents)
}
```

**R5 — Medium:** `Box<T>` allocates data on the heap. `Rc<T>` (Reference Counting) allows multiple owners of the same data on the stack, but only on a single thread. `Arc<T>` (Atomic Reference Counting) is the thread-safe version of `Rc<T>` for concurrent access across threads.

**R6 — Medium:** Traits define behavior. Like Go interfaces, they are implicit, but Rust traits are more rigid (must be explicitly implemented). A **trait object** (`dyn Trait`) allows a value of a specific type to be treated as a trait, enabling dynamic dispatch. Generics with trait bounds (`T: Trait`) use static dispatch (monomorphization), which is generally faster but less flexible.

**R7 — Hard:** The code fails because the return type `&str` borrows from the arguments, but the lifetime of the returned reference is not specified. The compiler cannot guarantee that the returned string slice outlives the arguments. **Fix:** Add a lifetime annotation.
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8 — Hard:** `Send` and `Sync` are unsafe traits. `Send` allows a type to be transferred across thread boundaries. `Sync` allows a type to be shared immutably across threads (i.e., `&T` is `Send`). `Rc<T>` is not `Send` because it doesn't handle thread-safe reference counting. `Arc<T>` wraps `Rc<T>` and implements `Send`/`Sync` using atomic operations.

**R9 — Hard:** Rust's async/await relies on the `Future` trait, which defines a `poll` method. The **executor** (like Tokio) repeatedly polls futures until they complete. Unlike Go's goroutines (which are managed by a runtime scheduler yielding to the OS), Rust's async is single-threaded and relies on explicit polling; it requires the user to provide an executor.

**R10 — Medium:** `unsafe` allows bypassing Rust's safety guarantees. Three things you can do: 1) Dereference a raw pointer that might be null or invalid. 2) Call an `unsafe` function. 3) Transmute between unrelated types. It is justified when you have proven the code is safe (e.g., interfacing with C) and performance is critical.

**R11 — Easy:** Pattern matching (`match`) is exhaustive; the compiler ensures all possible cases are handled. `if let` is syntactic sugar for a `match` with a single arm, useful for matching one pattern while ignoring others. The compiler enforces exhaustiveness in `match` statements to prevent panics.

**R12 — Easy:** `Vec<T>` is a dynamic array on the heap that can grow or shrink. An array `[T; N]` is a fixed-size sequence on the stack. When `Vec::push` is called and the capacity is exceeded, it allocates a new, larger underlying array (usually doubling the capacity) and copies the elements.

**R13 — Easy:** Enums in Rust are algebraic data types that can hold data. Unlike C/Java, they are not just integers. `Option<T>` is an enum with `Some(T)` and `None`. Rust does not have null to force developers to handle the "absence of a value" explicitly, preventing null pointer exceptions.

**R14 — Easy:** An `impl` block defines methods for a type. `&self` borrows immutably, `&mut self` borrows mutably, and `self` takes ownership. Associated functions (e.g., `String::new()`) are functions defined within an `impl` block that do not take `self` (static methods).

**R15 — Easy:** The `derive` macro automatically implements traits for a struct or enum. Common ones: `Debug` (printing), `Clone` (copying), `PartialEq` (equality), `Serialize` (serialization). You cannot derive `Copy` on a type that has a `Drop` implementation (custom destructor).

**R16 — Medium:** `Cow<'a, T>` (Clone on Write) is an enum (`Borrowed` or `Owned`) that holds a reference or an owned value. It is useful when you might need to mutate data but want to avoid cloning if it's not necessary. Example: A function that takes `&str` but needs to modify it; `Cow` allows returning a `String` if modified, or the original `&str` if not.

**R17 — Medium:** The module system uses `mod` to declare a module, `use` to import items, and `pub` to make items visible. In the 2018 edition, the file system maps directly to modules (e.g., `src/lib.rs` is the root, `src/foo.rs` is `mod foo`). In 2015, you needed a `mod.rs` file to group submodules.

**R18 — Hard:** `Pin<T>` prevents a value from being moved out of its location. It is needed for self-referential structs (like `Future`) where a pointer inside the struct points to itself. `Unpin` is a marker trait; if a type implements `Unpin`, it can be moved even if wrapped in `Pin`.

**R19 — Hard:** Rust has two macro types: **Declarative** (`macro_rules!`) for pattern matching and expansion, and **Procedural** (derive, attribute, function-like) for generating code at compile time. **Hygiene** ensures that macro variables do not capture identifiers from the surrounding code scope, preventing unintended variable capture.

**R20 — Hard:** Zero-cost abstractions mean that abstractions (like iterators, generics, and traits) do not incur runtime overhead compared to hand-written code. Generics use **monomorphization** (inlining specific implementations for each type), and trait dispatch is optimized to be as fast as direct function calls.
