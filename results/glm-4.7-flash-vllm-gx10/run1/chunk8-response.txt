**CL1 — Easy:** IaaS (Infrastructure as a Service) provides virtualized computing resources (VMs, storage, networking) over the internet. You manage the OS and applications. *Example: AWS EC2.*
PaaS (Platform as a Service) provides a platform allowing you to deploy applications without managing the underlying infrastructure (servers, OS). *Example: AWS Elastic Beanstalk.*
SaaS (Software as a Service) provides complete software applications over the internet, managed by the provider. *Example: Microsoft 365 (Office 365).*

**CL2 — Easy:** The Shared Responsibility Model defines security duties.
*   **IaaS VMs:** Provider manages physical hardware, networking, and virtualization. You manage the OS, runtime, data, and applications.
*   **Managed Kubernetes:** Provider manages the control plane (API server, etcd, scheduler). You manage the worker nodes, workloads, and configuration.
*   **SaaS (M365):** Provider manages the entire stack (infrastructure, platform, software, and data). You manage user identities and application configuration.

**CL3 — Medium:**
*   **VPC (Virtual Private Cloud):** A logically isolated virtual network in the cloud.
*   **Subnet:** A range of IP addresses within a VPC (Public vs. Private).
*   **Security Group:** A virtual firewall at the instance level that controls inbound/outbound traffic. It is **stateful** (allows return traffic automatically).
*   **NACL (Network ACL):** A firewall at the subnet level that controls traffic flow. It is **stateless** (requires explicit rules for both directions).
*   **Layering:** Traffic flows from the Instance -> Security Group -> Subnet NACL -> Route Table -> Internet Gateway. Security Groups filter at the host level; NACLs filter at the subnet level.

**CL4 — Medium:** A **Landing Zone** is the foundational multi-account structure providing core networking, identity, and governance. **Organizational Units (OUs)** group accounts for management (e.g., Finance, Dev, Prod). **Guardrails** are policies (e.g., AWS SCPs, OPA Gatekeeper) enforcing security and compliance standards. **Shared Networking** (e.g., Transit Gateway) connects accounts without individual VPNs. **Centralized Logging** aggregates logs (CloudWatch, Sentinel) for auditing.
A single-account approach is problematic because it lacks security isolation (a compromised app can access all resources), makes cost allocation difficult, and complicates compliance auditing.

**CL5 — Medium:** **Infrastructure as Code (IaC)** is the practice of managing infrastructure through code rather than manual processes.
*   **Terraform/OpenTofu:** Declarative, provider-agnostic, Terraform Cloud for state management.
*   **Pulumi:** Uses general-purpose programming languages (Python, Go), offering more flexibility and complex logic.
*   **CloudFormation/Bicep:** Cloud-native (AWS/Azure), JSON/YAML based, limited portability between clouds.
*   **Crossplane:** Extends Kubernetes as a control plane to manage cloud resources, ideal for Kubernetes-native environments.
*   *Choice:* Terraform for portability; Pulumi for complex logic; CloudFormation for AWS-only speed; Crossplane for K8s-first teams.

**CL6 — Medium:**
*   **HPA:** Scales pods based on CPU/Memory metrics.
*   **VPA:** Scales pods by resizing resource requests/limits (can cause rolling restarts).
*   **Cluster Autoscaler:** Scales the underlying node pool based on pending pods.
*   **KEDA:** Scales pods based on external event queues (Kafka, RabbitMQ, IoT).
*   *KEDA over HPA:* Use KEDA when scaling is driven by event throughput (e.g., processing millions of IoT messages) rather than just compute utilization.

## OT Infrastructure Architecture

**OT1 — Easy:** The **Purdue Model (ISA-95)** standardizes levels of automation:
*   **Level 0:** Field devices (sensors, actuators).
*   **Level 1:** PLCs/RTUs (control logic).
*   **Level 2:** Supervisory control (SCADA, HMIs).
*   **Level 3:** Manufacturing Operations Management (MES, Historians).
*   **Level 4:** Enterprise Resource Planning (ERP, Business systems).

**OT2 — Easy:** **IT** focuses on data processing, storage, and information security. **OT** focuses on the physical control of machinery and safety.
Standard IT patching is dangerous in OT because it can cause downtime, process instability, or physical damage to equipment. OT systems prioritize uptime and deterministic latency over the latest security patches.

**OT3 — Medium:** An **IDMZ (Industrial DMZ)** is a demilitarized zone separating the corporate IT network from the OT network.
*   **Traffic:** Primarily allows IT -> OT (reporting, monitoring) and OT -> IT (reporting, analytics). Control traffic is restricted.
*   **L4 to L1 Danger:** Direct connectivity bypasses supervision layers (Level 3/4), potentially allowing an attacker to bypass safety logic or cause immediate physical damage without detection.

**OT4 — Medium:**
*   **Modbus TCP:** Industrial protocol for reading/writing registers. Operates at Level 2/3.
*   **OPC UA:** Secure, platform-independent protocol for industrial automation. Operates at Level 3.
*   **EtherNet/IP (CIP):** Industrial protocol over Ethernet. Operates at Level 2.
*   **PROFINET:** Industrial Ethernet protocol. Operates at Level 2.
*   **MQTT:** Lightweight publish/subscribe messaging protocol. Operates at Level 3/4.

**OT5 — Medium:** A **Data Diode** is a hardware device that allows data to flow in only one direction (unidirectional). A **Firewall** allows bidirectional traffic based on rules.
*   **Use Data Diode:** When you need guaranteed, unidirectional data flow (e.g., sending telemetry to the cloud) and want to prevent any data leakage back to the source.
*   **Limitation:** It is one-way only; you cannot receive data or feedback through it.

**OT6 — Medium:**
*   **Flow:** PLCs collect data -> **Historian** stores data -> **OPC UA Server** exposes data -> **MQTT Broker** publishes data -> **Edge Gateway** (security boundary) -> Cloud Ingestion.
*   **Security Boundaries:** Place firewalls/data diodes at the Edge Gateway (between OT and IT) and between IT and Cloud.

**OT7 — Hard:** **IEC 62443** defines security zones (group of assets with same security level) and conduits (paths between zones).
*   **Zone:** A logical grouping of assets (e.g., a production line).
*   **Conduit:** A controlled path between zones.
*   **Design:**
    *   **Corporate (Z4):** High security, low risk.
    *   **Engineering (Z4):** High security.
    *   **SCADA (Z3):** Medium security.
    *   **PLCs (Z2):** Medium security.
    *   **SIS (Z1):** Highest security, lowest risk.

**OT8 — Hard:**
*   **Strategy:** Implement VLANs for each level (0-4). Use Layer 3 firewalls between VLANs.
*   **Switches:** Use managed switches with VLAN tagging and ACLs.
*   **Remote Access:** Use a Jump Host (Bastion) with MFA and session recording.
*   **Transition:** Use a "Shadow IT" monitoring phase to identify hidden devices before hard segmentation.

**OT9 — Hard:** **SIS** is dedicated to safety (preventing accidents). **BPCS** is for process efficiency.
*   **IEC 61511:** Standard for safety instrumented systems.
*   **Isolation:** The SIS network must be air-gapped or isolated to prevent malware from corrupting safety logic.
*   **Ransomware Impact:** If ransomware reaches the SIS, it could disable safety interlocks, leading to catastrophic physical damage or environmental release.

**OT10 — Medium:**
*   **PLC:** Programmable Logic Controller for discrete or simple process control.
*   **DCS:** Distributed Control System for complex, continuous processes (e.g., refineries).
*   **SCADA:** Supervisory Control and Data Acquisition for remote monitoring and control.
*   **Coexistence:** Yes, they often coexist in hybrid plants (e.g., DCS for continuous process, PLCs for batch operations).

**OT11 — Medium:**
*   **Architecture:** Use a **Jump Host** (Bastion) in the IDMZ. Connect via VPN. Require **MFA**.
*   **Vendor Access:** Managed accounts with time-limited access.
*   **RDP to HMI:** Unacceptable because it bypasses the IDMZ, exposing the plant network directly to the corporate network.

**OT12 — Hard:**
*   **Detection:** Deploy IDS/IPS on the L3 network. Use anomaly detection for protocol behavior.
*   **Inventory:** Update asset inventory immediately.
*   **Response:** Isolate the compromised L3 network segment. If the threat reaches the SIS, isolate the SIS network immediately.
*   **Operator Role:** Stop the process safely, ensure safety systems are active, and notify the SOC.
*   **Coordination:** Work with the control room to maintain safe operations while the incident is investigated.

**OT13 — Easy:** An **HMI** is a user interface (screen) allowing operators to monitor and control machinery. It is the operator's primary tool.
An **Engineering Workstation** is used for configuring, programming, and maintaining the control system. It has higher privileges and connectivity than an HMI.

**OT14 — Easy:** A **Historian** stores time-series data from the plant for analysis and trending.
*   **Importance:** Critical for process optimization, predictive maintenance, and root cause analysis.
*   **Plant Historian:** Located at Level 3, stores local process data.
*   **Enterprise Historian:** Located at Level 4, aggregates data from multiple plant historians for corporate reporting.

**OT15 — Easy:** **Ladder Logic** is a programming language that uses graphical symbols resembling electrical relay logic.
*   **Device:** Executed by PLCs.
*   **Dominance:** It is still dominant because it is intuitive for electricians, legacy code is extensive, and it maps well to physical relay logic.

**OT16 — Easy:** An **RTU** (Remote Terminal Unit) is a microprocessor-controlled device that interfaces with field devices in remote locations.
*   **Difference:** RTUs typically use serial communication (RS-232/485) and are used in remote or harsh environments (pipelines, substations).
*   **Deployment:** Used where cabling to a central PLC room is difficult or where protocols differ significantly from Ethernet-based PLCs.

**OT17 — Easy:** **Analog signals** (4-20mA, 0-10V) represent continuous values. **Digital signals** represent discrete states (on/off).
*   **4-20mA vs 0-20mA:** 4-20mA is preferred because the "4mA" signal represents zero flow/pressure, allowing the system to detect an open circuit (0mA) and distinguish it from a valid zero signal.

**OT18 — Medium:** **Asset Inventory** is the complete list of hardware and software assets in the OT environment.
*   **Tools:** Passive monitoring (Nmap, Netflow, SNMP) is safer. Active scanning (ping sweeps) is dangerous.
*   **Danger of Active Scanning:** Can cause PLCs to reset or crash, disrupting production.

**OT19 — Hard:** **MITRE ATT&CK for ICS** is a knowledge base of tactics and techniques specific to industrial control systems.
*   **Tactics:** Resource Development, Initial Access, Execution, Persistence, Defense Evasion, Impact.
*   **Techniques:** Specific actions like "SCADA Protocol Flood" or "PLC Code Modification".
*   **Difference:** Focuses on ICS protocols (Modbus, DNP3) and physical impacts, unlike the enterprise matrix which focuses on Windows/Mac/Linux.
*   **Use:** To identify gaps in detection and response capabilities specific to industrial environments.

**OT20 — Hard:**
*   **SOC:** Use passive collectors (Syslog, OPC UA logs) to avoid impacting real-time control loops.
*   **SIEM:** Correlate logs with OT-specific rules.
*   **Staffing:** Hybrid team of IT analysts and OT engineers.
*   **False Positives:** High in OT; requires OT engineers to tune rules.
*   **Firmware Alert:** Verify via vendor, check logs for unauthorized changes, isolate the PLC if confirmed, and restore from a known good backup.
