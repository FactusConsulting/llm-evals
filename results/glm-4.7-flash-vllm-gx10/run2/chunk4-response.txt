**G1 — Easy:** An array has a fixed length and type (e.g., `[5]int`), while a slice is a dynamic view into an array with a length and capacity. When you append to a slice that has reached its capacity, Go allocates a new underlying array, copies the existing elements, and appends the new element.

**G2 — Easy:** `var x int` declares a variable and initializes it to its zero value (0). `x := 0` is a short variable declaration that declares and initializes in one step. You cannot use `:=` in function parameters or outside of a function (at the package level).

**G3 — Medium:** A goroutine is a lightweight thread managed by the Go runtime, not the OS. It differs from an OS thread in that it is much cheaper to create and manage. The Go scheduler uses the GMP model: **G**oroutines (tasks), **M**achines (OS threads), and **P**rocessors (logical processors) that schedule work.

**G4 — Medium:** Channels send and receive values between goroutines. An unbuffered channel blocks the sender until the receiver is ready, and vice versa. A buffered channel holds a finite number of items; sending to a full buffered channel blocks until a slot is available.

**G5 — Medium:** The `context` package manages deadlines, cancellations, and request-scoped values. It is used to propagate cancellation signals to long-running operations.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
resp, err := http.GetWithContext(ctx, "http://example.com")
```

**G6 — Medium:** Go interfaces are implicit; a type satisfies an interface if it implements the required methods, without an explicit `implements` keyword. The empty interface `interface{}` (or `any`) accepts any type. It is powerful for polymorphism but dangerous because it requires type assertions to use specific methods, potentially leading to runtime panics.

**G7 — Hard:** The code is unsafe because the compiler is allowed to reorder memory writes (optimization) or optimize the loop away because it assumes `ready` is always true. The visibility of the goroutine's writes to the main thread is not guaranteed. The correct alternatives are using `sync/atomic` for the boolean flag or using a channel to signal completion.

**G8 — Hard:** `sync.Mutex` provides exclusive locking (read/write). `sync.RWMutex` allows multiple concurrent readers or a single writer. `sync.Map` is optimized for concurrent reads/writes of single values (like caches) and avoids locking overhead for simple maps, but it has higher overhead for simple operations compared to a map protected by a mutex.

**G9 — Hard:** Go modules manage dependencies. `go.mod` is the manifest file listing module paths and versions. `go.sum` contains cryptographic hashes of the exact versions of dependencies used to ensure reproducibility. `go mod tidy` removes unused dependencies and adds missing ones. **G10 — Medium:** A `defer` statement schedules a function call to run immediately before the function returns. Multiple defers execute in Last-In-First-Out (LIFO) order. A common gotcha is capturing variables by reference in a loop; the variable is updated before the defer runs, so all defers might print the same final value.

**G12 — Easy:** `init()` functions run automatically before `main()` when a package is imported. A package can have multiple `init()` functions, and they execute in the order they appear in the source files.

**G13 — Easy:** `make` is used to create slices, maps, and channels (allocating memory). `new` is used to allocate memory for any type and returns a pointer to a zero value of that type.

**G14 — Easy:** Errors are handled via the `error` interface (a method returning a string). The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error matches a specific error value (handling wrapped errors), while `errors.As` casts an error to a concrete type.

**G15 — Easy:** Built-in composite types are `map`, `slice`, `channel`, and `struct`. Their zero values are `nil` for `map`, `slice`, and `channel`, and the zero value of their fields for `struct`.

**G16 — Medium:** A race condition occurs when two goroutines access shared data concurrently without synchronization. The `-race` flag enables a data race detector that inserts checks at runtime. An example fix involves wrapping the shared data in a `sync.Mutex` or communicating via a channel.

**G17 — Medium:** `select` waits for multiple channel operations to become ready. It differs from `switch` by only accepting channel expressions. If multiple cases are ready, one is chosen arbitrarily. A timeout is implemented using `select` with a `default` case or a `time.After` channel.

## Rust (20 questions)

**R1 — Easy:** Ownership means a variable has exclusive access to its value. The three rules are: 1. Each value has a variable that is called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value will be dropped.

**R2 — Easy:** `String` is an owned, heap-allocated string. `&str` is a string slice (reference to a string). Use `&str` for function arguments to accept both `String` and `&str`, and use `String` when you need to own the data or modify it.

**R3 — Medium:** Borrowing allows temporary access to data without taking ownership. The borrow checker enforces: 1. You can have either one mutable reference or any number of immutable references. 2. References must always be valid (no dangling references).

**R4 — Medium:** `Result<T, E>` represents success or failure, while `Option<T>` represents the presence or absence of a value. The `?` operator propagates errors up the call stack if the result is `Err`. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

**R5 — Medium:** `Box<T>` allocates on the heap. `Rc<T>` (Reference Counting) allows multiple ownership on the heap within a single thread. `Arc<T>` (Atomic Reference Counting) is the thread-safe version of `Rc<T>` for concurrent use across threads.

**R6 — Medium:** Traits define behavior. Like Go interfaces, they are implicit, but Rust traits are more rigid (must be implemented explicitly). A trait object (`dyn Trait`) allows a value of a trait type, while a generic with a trait bound (`T: Trait`) enforces the trait at compile time for all instantiations.

**R7 — Hard:** The function fails because it returns a reference to a local variable (`x` or `y`). The borrow checker cannot guarantee the lifetime of the returned reference. The fix is to return an owned type (e.g., `String`) or add a lifetime parameter: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8 — Hard:** `Send` allows a type to be transferred across thread boundaries. `Sync` allows a type to be shared immutably across threads. `Rc<T>` is not `Send` because it assumes single-threaded ownership. `Arc<T>` is `Send` + `Sync` because it uses atomic operations for reference counting.

**R9 — Hard:** Rust's async/await relies on `Future` traits that resolve to values. The executor (like Tokio) polls futures to completion. Unlike Go's goroutines (which are OS threads), Rust's async is cooperative multitasking on a thread pool, avoiding blocking threads.

**R10 — Medium:** `unsafe` allows bypassing Rust's safety guarantees. 1. Dereferencing a raw pointer. 2. Transmuting types. 3. Calling an `unsafe` function. It is justified when interfacing with C code, implementing low-level abstractions, or when the programmer can mathematically prove safety.

**R11 — Easy:** Pattern matching (`match`) is exhaustive; the compiler ensures all cases are handled. `if let` is syntactic sugar for a `match` with one pattern and a catch-all `_`. It is useful for matching a single option without boilerplate.

**R12 — Easy:** `Vec<T>` is a dynamic array that manages its own memory on the heap. An array `[T; N]` has a fixed size. When `Vec` pushes beyond its capacity, it allocates a new, larger block of memory and copies the elements.

**R13 — Easy:** Enums in Rust are algebraic data types. `Option<T>` is an enum with `Some(T)` and `None`. Rust does not have null to prevent null pointer exceptions; instead, it uses `Option` to explicitly handle the absence of a value.

**R14 — Easy:** An `impl` block defines methods for a type. `&self` borrows immutably, `&mut self` borrows mutably, and `self` takes ownership. Associated functions (e.g., `String::new()`) are static methods that don't take `self`.

**R15 — Easy:** The `derive` macro automatically implements standard traits. Common ones include `Debug`, `Clone`, `PartialEq`, and `Serialize`. You cannot derive traits like `Copy` on types that implement `Drop`.

**R16 — Medium:** `Cow<'a, T>` (Clone on Write) is a smart pointer that can be either a borrow (`&T`) or an owned (`T`). It is useful when you might need to mutate data; if you try to mutate a borrowed `Cow`, it clones the data first. This avoids unnecessary allocations if the data isn't changed.

**R17 — Medium:** The module system uses `mod` to define modules, `use` to import items, and `pub` to make items visible. In the 2018 edition, the file system maps directly to modules (e.g., `src/lib.rs` is the root, `src/foo.rs` is `mod foo`).

**R18 — Hard:** `Pin<T>` prevents a value from being moved out of its location. It is needed for self-referential structs (e.g., a `Future` that holds a reference to itself) and async/await. `Unpin` is a trait that indicates a type can be safely moved even if pinned.

**R19 — Hard:** Macros are code generators. Declarative macros (`macro_rules!`) define patterns and replacements. Procedural macros (derive, attribute, function-like) are written in Rust and run during compilation. Hygiene rules ensure macro-generated code doesn't accidentally capture or conflict with identifiers in the surrounding code.

**R20 — Hard:** Zero-cost abstractions mean that abstractions (like iterators, generics, and traits) do not incur runtime overhead compared to hand-written code. Generics use monomorphization (generating specific code for each type), and trait dispatch is often static (inlined), achieving performance comparable to C while maintaining high-level ergonomics.
