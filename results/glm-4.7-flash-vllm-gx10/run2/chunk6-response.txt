**JS1 — Easy:** `var` is function-scoped and hoisted (initialized as `undefined`), allowing reassignment. `let` is block-scoped, hoisted but in a Temporal Dead Zone (cannot be accessed before declaration), and reassignable. `const` is block-scoped, hoisted in the TDZ, and immutable (cannot reassign the variable, though the object it holds can be mutated). **Hoisting** is the JavaScript engine's behavior of moving variable and function declarations to the top of their scope during the compilation phase.

**JS2 — Easy:** The **event loop** manages asynchronous operations. The **call stack** executes code synchronously. When the stack is empty, the engine checks the **microtask queue** (e.g., Promises, queueMicrotask) and executes them. Once microtasks are cleared, it checks the **macrotask queue** (e.g., `setTimeout`, `setInterval`, I/O) and executes the oldest task. This cycle repeats.

**JS3 — Medium:** A **closure** is a function that retains access to variables from its outer (lexical) scope even after the outer function has finished executing. **Example:** A counter function where the inner function increments a variable from the outer scope. The **classic for loop bug** occurs because the loop variable is shared across all iterations; by the time the callbacks execute, the loop has finished and the variable holds the last value. **Fix:** Use an IIFE (Immediately Invoked Function Expression) or use `let` (block scoping) inside the loop.

**JS4 — Medium:** A **Promise** is an object representing the eventual completion or failure of an asynchronous operation. **async/await** is syntactic sugar over Promises, allowing asynchronous code to be written in a synchronous style using `await`. Error handling with `async/await` uses `try/catch` blocks, while raw Promises use `.catch()`. **Promise.all** resolves only when all promises resolve; if one rejects, it rejects immediately. **Promise.allSettled** resolves when all promises settle (either resolve or reject) and returns the status of each.

**JS5 — Medium:** **Interface** is used for defining the shape of objects and is extensible via `extends`. **Type** is more flexible, allowing unions, primitives, tuples, and intersections. Use interfaces for object shapes and contracts; use types for complex logic like unions. **Discriminated unions** are types where a common property (discriminator) is used to narrow the type within a switch statement (e.g., `kind: 'foo'`).

**JS6 — Medium:** **Prototypal inheritance** means objects inherit directly from other objects. **Object.create(proto)** creates a new object with a specified prototype. **ES6 classes** are syntactic sugar over prototypes; they provide a cleaner syntax for defining constructors and prototypes using `class`, `extends`, and `constructor`.

**JS7 — Hard:** **this** refers to the context in which a function is executed. The 4 binding rules (in priority order) are: 1. **New Binding** (if `new` is used, `this` is the new object), 2. **Explicit Binding** (using `call`, `apply`, or `bind`), 3. **Implicit Binding** (context is the object calling the function), 4. **Default Binding** (global object in strict mode, `window` otherwise). **bind()** returns a *new* function permanently bound to the context and can be re-bound.

**JS8 — Hard:** **WeakRef** provides a weak reference to an object, allowing the garbage collector to reclaim the object if no other strong references exist. **FinalizationRegistry** allows you to register a callback to be executed when a registered object is garbage collected. **WeakMap** keys must be objects; because keys are weak references, they do not prevent garbage collection, preventing memory leaks.

**JS9 — Hard:** The V8 engine optimizes by using **hidden classes** (shape) to track object properties, allowing fast property access. **Inline caching** caches the location of object properties to avoid repeated lookups. **Deoptimization** occurs when the engine detects that assumptions about code execution (e.g., property order changes or type changes) are violated, causing it to revert to slower interpreter mode. Patterns causing this include adding properties dynamically or changing types mid-execution.

**JS10 — Medium:** **Tree-shaking** is dead code elimination. It removes unused code from the final bundle. **ES Modules** use static analysis (imports/exports at top level), making tree-shaking possible. **CommonJS** (`require`) is dynamic (can be called anywhere), making static analysis impossible, so tree-shaking is ineffective.

**JS11 — Easy:** `null` is an explicit assignment meaning "no value" (type is object). `undefined` is the default value of uninitialized variables (type is undefined). `==` performs type coercion, while `===` checks strict equality. **Nullish coalescing (`??`)** returns the right-hand side only if the left is `null` or `undefined`. **Optional chaining (`?.`)** safely accesses nested properties, returning `undefined` if the reference is nullish.

**JS12 — Easy:** `map()` transforms each element, `filter()` selects elements, and `reduce()` accumulates elements into a single result (takes an accumulator, current value, index, and array). `reduce()` works with an initial value to avoid the "empty array" edge case. **flatMap()` applies a mapping function to each element and then flattens the result one level deep (useful for transforming arrays of arrays).

**JS13 — Easy:** **Template literals** use backticks and allow string interpolation via `${expression}`. **Tagged templates** are function calls on template literals (e.g., `func` `a` `b`). **Example:** A function that escapes HTML characters to prevent XSS: `const escape = (strings, ...values) => strings.reduce((acc, str, i) => acc + str + (values[i] || '').replace(/&/g, "&amp;").replace(/</g, "&lt;"), "")`.

**JS14 — Easy:** **Destructuring** unpacks values from arrays or properties from objects. **Object destructuring** uses `{a, b}`; **array destructuring** uses `[a, b]`. **Default values** are set with `a = 1`. **Renaming** is done with `const {a: b} = obj`. The **rest operator** (`...rest`) collects remaining elements into an array or object.

**JS15 — Easy:** `for...in` iterates over **enumerable string keys** (including inherited ones) of an object. `for...of` iterates over **values** of an iterable (like arrays). You should avoid `for...in` on arrays because it iterates over string indices (0, 1, 2) and is slower than `for...of`.

**JS16 — Medium:** **Generics** allow writing reusable code with type parameters (`<T>`). **Constraints** (`T extends SomeType`) restrict the type. **Conditional types** (`T extends U ? X : Y`) select types based on conditions. The **infer** keyword extracts types from generic types (e.g., `ReturnType`). **Example:** `function identity<T>(arg: T): T { return arg; }`.

**JS17 — Medium:** **CommonJS** uses `require` and `module.exports` (synchronous, dynamic). **ES Modules** use `import` and `export` (asynchronous, static). In Node.js, setting `"type": "module"` in `package.json` enables ES Module behavior for `.js` files.

**JS18 — Hard:** **Structural typing** means "if it has the shape, it's compatible." **Excess property checks** occur when assigning an object with extra properties to a narrower type (e.g., `const x: {a:1} = {a:1, b:2}`), causing a compile error. **extends** is for inheritance; **satisfies** checks types without widening them. **Variance** (in/out) in TS 4.7+ controls how generic types behave with inheritance (e.g., `ReadonlyArray` is covariant).

**JS19 — Hard:** **Proxy** allows intercepting and modifying operations on objects (get, set, apply). **Reflect** provides a mirror of Proxy methods. **Example:** A validation proxy that throws an error if a property is set to an invalid value. **SharedArrayBuffer** and **Atomics** allow Web Workers to share memory safely. Workers communicate via `postMessage` (structured clone) or SharedArrayBuffer. **Atomics.wait/notify** provide blocking synchronization with ordering guarantees (SeqCst).

**JS20 — Hard:** **SharedArrayBuffer** creates a buffer shared across threads. **Atomics** provides atomic operations on this buffer. Web Workers use `postMessage` to communicate. **Ordering guarantees** (like SeqCst) ensure visibility of writes. **Atomics.wait** blocks the thread until a value changes (requires cross-origin isolation headers).

## Bash (20 questions)

**B1 — Easy:** `$@` (unquoted) passes each argument as a separate word. `$*` (unquoted) passes all arguments as a single word. `"$@"` preserves quoting and passes arguments as separate words. `"$*"` preserves quoting but passes all arguments as a single word.

**B2 — Easy:** `set -e` exits the script immediately if any command returns a non-zero exit status. `set -u` exits if an undefined variable is used. `set -o pipefail` ensures the exit status of a pipeline is the exit status of the last command to fail, rather than the exit status of the leftmost command.

**B3 — Medium:** `$(command)` is the standard POSIX command substitution. `` `command` `` is the older backtick syntax. `$((expression))` is arithmetic expansion (faster, built-in). `expr` is an external command for arithmetic and string operations (slower).

**B4 — Medium:** **Process substitution** (`<(command)`) creates a named pipe (FIFO) or temporary file representing the command's output. It allows commands to read from the output of another command as if it were a file. **Example:** `diff <(sort file1.txt) <(sort file2.txt)`.

**B5 — Medium:** Safely iterate using `for f in *` or `find . -print0 | while IFS= read -r -d '' f; do ... done`. `for f in $(ls)` is dangerous because it relies on word splitting and globbing on the output of `ls`, which breaks if filenames contain spaces or special characters.

**B6 — Medium:** A **here document** (`<<EOF ... EOF`) is a multi-line string literal that expands variables. A **here string** (`<<<"string"`) is a single-line string literal that expands variables. `<<-EOF` strips leading tabs from lines in the heredoc.

**B7 — Hard:** `cmd > file 2>&1` redirects stdout to `file` and then redirects stderr to the current stdout (which is now `file`). `cmd 2>&1 > file` redirects stderr to the current stdout (terminal) and then redirects stdout to `file`. `cmd &> file` redirects both stdout and stderr to `file` (bash specific). The first two differ because the redirection order matters.

**B8 — Hard:** A function creating a lock file should use `mkdir` in a directory (e.g., `/tmp/lockdir`). It checks if the directory exists (`mkdir -p` returns 0 if created, 1 if exists). It sets a `trap` on `SIGTERM` to `rm -rf /tmp/lockdir`. `mkdir` is preferred over file creation because it is an atomic operation and handles race conditions better.

**B9 — Easy:** No quotes: Word splitting and globbing occur. Single quotes: Literal string, no expansion. Double quotes: Variable expansion and command substitution occur, but no globbing.

**B10 — Easy:** Check with `[ -f file ]` (exists and is file), `[ -d dir ]` (exists and is directory), `[ -r file ]` (exists and is readable). `[ ]` is the POSIX test command. `[[ ]]` is the Bash-specific test command with regex support (`=~`), logical operators (`&&`, `||`), and no globbing unless escaped.

**B11 — Easy:** `$?` is the exit status of the last command. `$$` is the Process ID (PID) of the current shell. `$!` is the PID of the last background job. `$#` is the number of positional parameters passed to the script.

**B12 — Easy:** Functions are defined with `function foo {}` or `foo() {}`. Both work. Functions return values via the exit status (e.g., `return 1`). They do not return variables like C functions; variables are global unless declared local.

**B13 — Easy:** The **PATH** variable is a list of directories searched for commands. Bash resolves commands by looking in these directories. A **builtin** command is built into the shell (e.g., `cd`, `echo`) and runs faster without forking a process. An **external** command is an executable file on disk. Check with `type command` or `command -V command`.

**B14 — Medium:** **trap** allows setting commands to run on signals. `trap 'commands' EXIT` runs on script exit. `trap 'commands' ERR` runs on error. `trap 'commands' INT` runs on Ctrl+C. `trap 'commands' TERM` runs on kill. Signals are handled sequentially.

**B15 — Medium:** **xargs** processes input line by line, which is memory efficient for large lists. **Command substitution** (`$(cmd)`) loads all output into memory. **xargs -0** uses the null character (`\0`) as a delimiter, handling filenames with spaces and newlines. **xargs -P** runs commands in parallel.

**B16 — Medium:** **Arrays** are indexed lists (`arr=(a b c)`). **Associative arrays** use string keys (`declare -A assoc=(["key"]=val)`). Iterate with `for i in "${!arr[@]}"` for associative keys. Length is `${#arr[@]}`.

**B17 — Hard:** A **subshell** (`(...)`) runs in a new process. Variables defined inside do not leak out, and the exit code is the last command's status. A **group command** (`{ ...; }`) runs in the current shell. Variables leak. **Piping into a while loop** creates a subshell for the loop, so variable changes inside the loop are lost when the loop finishes.

**B18 — Hard:** **SIGINT** (Ctrl+C) interrupts the process. **SIGTERM** (kill) terminates the process but can be caught. **SIGHUP** (Hangup) occurs when the terminal session ends. **SIGKILL** (kill -9) terminates the process and cannot be caught. Graceful shutdown involves trapping signals and killing child processes.

**B19 — Hard:** A script can use `split -l 1000 log.txt log_part_` to split the file, then `xargs -P 4 -I {} bash process.sh log_part_{}` to process in parallel, and finally `cat log_part_* > merged.log` to merge. **Trade-offs:** Parallelism reduces wall-clock time but adds overhead and complexity. **Error propagation:** Check the exit status of `xargs` or write error logs to a summary file.

**B20 — Hard:** **exec** replaces the current shell process with the command, changing the PID. **File descriptor manipulation** uses `exec 3>file` (open file for FD 3) and `exec 3>&-` (close FD 3). A **coprocess** (`coproc myproc { cat; }`) allows reading/writing to a background process via `&>`, `<&`, and `&>>`, useful for non-blocking I/O.

## PowerShell (20 questions)

**PS1 — Easy:** **Write-Output** adds objects to the pipeline (default behavior). **Write-Host** writes directly to the console host. The distinction matters because `Write-Host` does not pass objects to the pipeline, whereas `Write-Output` does.

**PS2 — Easy:** The **pipeline** passes objects from one command to the next. **ForEach-Object** is a cmdlet that processes pipeline objects. The **foreach statement** is a language construct that iterates over a collection in memory. Use `ForEach-Object` for streaming pipeline data and the `foreach` statement for local loops.

**PS3 — Medium:** **[PSCustomObject]** is a PowerShell object with properties and methods. **[hashtable]** is a key-value collection. Use PSCustomObject for output/objects; use Hashtables for configuration. Convert with `[PSCustomObject]@{}` or `@{}`.

**PS4 — Medium:** **Terminating errors** stop the script execution (e.g., `throw`, `Stop-Function`). **Non-terminating errors** continue execution (e.g., `Write-Error`). `-ErrorAction` controls non-terminating errors. `$ErrorActionPreference` sets the global preference. `try/catch` catches terminating errors.

**PS5 — Medium:** **Splatting** (`@params`) passes a hashtable or array of arguments to a function cleanly. It differs from passing a hashtable as a single parameter by unpacking the arguments individually, making the function call cleaner and handling dynamic arguments better.

**PS6 — Medium:** **Invoke-Command** runs commands on remote computers and returns results. **Enter-PSSession** creates an interactive shell on a remote computer. It uses the **WinRM** protocol (default) or SSH. It relates to WinRM as the underlying transport mechanism.

**PS7 — Hard:** In the example, `$result += "one"` creates a new array every time because arrays are immutable in PowerShell. `$x.GetType().Name` returns `Object[]`. When returning 0 items, `$x` is `$null`. The correct pattern is to use `[System.Collections.Generic.List[string]]` or `@($result)` to force an array type.

**PS8 — Hard:** **[scriptblock]** is a block of code that can be passed around. To pass to a remote session, use `Invoke-Command -ScriptBlock { ... }`. The **double-hop problem** occurs when passing credentials from a client to a remote server to a third machine. It is solved using **CredSSP** or `Invoke-Command -ArgumentList`.

**PS9 — Easy:** `@()` creates a literal array (can be empty). `[array]` forces a type constraint. To force a single result into an array, use `@(Get-Item)`. Indexing `$null` throws an error.

**PS10 — Easy:** Comparison operators: `-eq` (equal), `-ne` (not equal), `-like` (wildcard), `-match` (regex), `-contains` (membership), `-in` (value in collection). Case-sensitive variants use `-c` prefix (e.g., `-ceq`). `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection.

**PS11 — Easy:** A **PowerShell module** is a package of cmdlets, functions, and scripts. **Script module (.psm1)** contains code. **Manifest (.psd1)** contains metadata. **Binary module** is a compiled DLL. `Import-Module` loads the module into the session.

**PS12 — Easy:** **String interpolation** uses `$var` inside double quotes. Double quotes expand variables; single quotes are literal. To include expressions, use `"$(1+1)"`. A **here-string** (`@"..."@`) is a multi-line string literal that preserves formatting and does not expand variables.

**PS13 — Easy:** **Get-Member** inspects the properties and methods of an object. **Properties** are dynamic data, **Methods** are functions, **NoteProperties** are static properties defined in the type definition. **Select-Object** selects specific properties. **Where-Object** filters objects.

**PS14 — Medium:** **PowerShell classes** (v5+) define structured types. They differ from C# by lacking inheritance, interfaces, and explicit constructors (default is parameterless). Use classes for complex logic or replacing advanced functions.

**PS15 — Medium:** **[CmdletBinding()]** enables common parameters (Verbose, Debug, ErrorAction). **SupportsShouldProcess** enables `Confirm` and `WhatIf`. **ValueFromPipeline** allows input binding. **Begin/Process/End** blocks define execution phases.

**PS16 — Medium:** The **PowerShell providers** system exposes data as drives (e.g., `FileSystem`, `Registry`, `Certificate`). **Get-ChildItem** works across providers. The Registry is accessed like a file system using paths like `HKLM:\Software`.

**PS17 — Hard:** **Runspaces** are isolated execution environments. **RunspacePool** manages a pool of runspaces. **[powershell]** objects allow running scriptblocks in a specific runspace. **ForEach-Object -Parallel** (v7+) uses runspaces internally for parallel execution.

**PS18 — Hard:** **PSScriptAnalyzer** is a static analysis tool. It enforces coding standards via **rules** (e.g., `UseShouldProcessForStateChangingFunctions`). **Severity levels** are Error, Warning, and Note. It integrates with CI/CD pipelines (e.g., Azure Pipelines).

**PS19 — Hard:** **$using: scope** allows accessing variables from the caller's scope in remote/background jobs. **-ArgumentList** passes arguments to remote sessions. **Serialization limits** (CLIXML depth) affect complex objects; they must be serialized to be passed.

**PS20 — Hard:** **Desired State Configuration (DSC)** is a declarative infrastructure-as-code tool. **Configurations** define the desired state. **Resources** implement the logic (e.g., File, Service). The **Local Configuration Manager (LCM)** is the agent on the machine. In modern IaC, tools like **Terraform** or **Ansible** have largely replaced DSC for cross-platform and cloud-native management.
