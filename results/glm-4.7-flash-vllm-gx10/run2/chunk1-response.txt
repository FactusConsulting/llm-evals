**N3 — Medium: Explain the TCP three-way handshake. What happens if the final ACK is lost?**
*   1. SYN: Client sends SYN, seq=x.
*   2. SYN-ACK: Server receives SYN, sends SYN-ACK, seq=y, ack=x+1.

4.  **AS Path Length** (shorter preferred)
5.  **Origin Code** (IGP < EGP < Incomplete)
6.  **MED** (Multi-Exit Discriminator, lower preferred)
7.  **eBGP over iBGP** (closer preferred)
8.  **Lowest IGP metric** to next hop

**N9 — Hard:** Running VxLAN over IPsec adds significant overhead. VxLAN adds 50 bytes (8 UDP + 20 VxLAN + 4 Ethernet). IPsec ESP (Tunnel mode) adds approximately 28 bytes (20 header + 8 ICV).
*Math:* `1500 (MTU) - 50 (VxLAN) - 28 (IPsec) = 1422 bytes`.
The maximum inner payload is **1422 bytes**.

**N10 — Medium:** **ARP** maps IP addresses to MAC addresses on a local network. **Gratuitous ARP** solves the problem of ensuring the network knows a device's new MAC address (e.g., after a failover) or detecting duplicate IP addresses without waiting for a request.

**N11 — Easy:** A **public IP** is routable on the global internet. A **private IP** is not routable on the internet and is used for internal networks.
The three RFC 1918 private ranges are:
1.  10.0.0.0/8
2.  172.16.0.0/12
3.  192.168.0.0/16

**N12 — Easy:** **DNS** translates human-readable domain names to IP addresses.
*   **A Record:** Maps a hostname to an IPv4 address.
*   **CNAME Record:** Maps a hostname to another hostname (alias).
*   **AAAA Record:** Maps a hostname to an IPv6 address.

**N13 — Easy:** **DHCP** is a protocol that automatically assigns IP addresses and network configuration to devices.
The **DORA** process is:
1.  **D**iscover: Client broadcasts for a server.
2.  **O**ffer: Server offers an IP.
3.  **R**equest: Client requests the IP.
4.  **A**cknowledgment: Server confirms and leases the IP.

**N14 — Easy:**
*   **Hub:** Repeats electrical signals to all ports. Operates at **Layer 1** (Physical).
*   **Switch:** Filters/forwards frames based on MAC addresses. Operates at **Layer 2** (Data Link).
*   **Router:** Routes packets between different networks. Operates at **Layer 3** (Network).

**N15 — Easy:** **Half-duplex** allows communication in one direction at a time (like a walkie-talkie). **Full-duplex** allows communication in both directions simultaneously (like a phone call). Modern Ethernet links use **full-duplex**.

**N16 — Medium:** The **TTL** (Time To Live) field prevents packets from looping indefinitely. **Traceroute** exploits this by sending packets with incrementing TTL values (starting at 1). Each router decrements TTL; when it hits 0, the router sends an ICMP "Time Exceeded" message back to the source, revealing the hop.

**N17 — Medium:** A **NAT gateway** translates IP addresses of packets traversing it to allow private networks to access the internet.
*   **Static NAT:** 1-to-1 mapping (e.g., internal 10.0.0.5 -> external 203.0.113.5).
*   **Dynamic NAT:** Maps from a pool of addresses (e.g., internal 10.0.0.5 -> external 203.0.113.50-100).
*   **PAT (Port Address Translation):** Maps multiple internal IPs to a single external IP using different ports (e.g., 10.0.0.5:80 -> 203.0.113.1:8080).

**N18 — Hard:** **ECMP** distributes traffic across multiple equal-cost links based on a hash of the 5-tuple (Src IP, Dst IP, Src Port, Dst Port, Protocol).
*   **Hashing:** Usually uses the 5-tuple.
*   **Problem:** If the request takes Link A and the reply takes Link B (asymmetric flow), a stateful firewall tracking the connection by 5-tuple may not find the state on Link B and drop the reply.

**N19 — Hard:** The problem is **TCP Window Sizing**. The bandwidth-delay product (10MB) is much larger than the TCP window (64KB). The sender stops sending to avoid overwhelming the receiver, causing high latency.
**TCP Window Scaling** (RFC 1323) solves this by using the "Window Scale" option in the TCP header to multiply the advertised window size by a factor (up to 14), allowing the window to grow to 10MB.

**N20 — Hard:** **802.1Q trunk ports** carry multiple VLANs over a single physical link by adding a 4-byte tag to the Ethernet frame.
*   **Linux Config:** Create sub-interfaces: `ip link add link eth0 name eth0.10 type vlan id 10`, `ip link add link eth0 name eth0.20 type vlan id 20`, etc.
*   **Frame Format:** On the wire, the frame consists of the standard Ethernet Header (14 bytes) + **802.1Q Tag** (4 bytes: TPID + TCI) + Original Ethernet Frame (Payload).

## Linux (20 questions)

**L1 — Easy:** A **hard link** shares the same inode as the original file and must reside on the same filesystem. If the original file is deleted, the hard link remains. A **symbolic link** (soft link) is a separate file containing a path to the target; it can span filesystems and breaks if the target is deleted.

**L2 — Easy:** `find /var/log -type f -size +100M`

**L3 — Medium:** State **D** (uninterruptible sleep) means the process is blocked waiting for I/O that cannot be interrupted (e.g., waiting for disk I/O on a mounted filesystem). **No**, you cannot kill it with `kill -9` (SIGKILL). The process will remain in this state until the I/O operation completes.

**L4 — Medium:** **cgroups v1** uses separate hierarchies for different resources (cpu, memory, blkio), making it difficult to mix resources. **cgroups v2** uses a unified hierarchy where all resources are tracked in a single tree, simplifying nesting and resource management.
Systemd prefers **v2** because of the unified hierarchy, which simplifies resource management and container nesting.

**L5 — Medium:** **nftables** is the modern replacement for iptables, using a single table with chains and a scripting language. **iptables** uses separate tables (filter, nat, mangle) and command-line arguments.
The kernel handles both simultaneously by maintaining a single netfilter hook infrastructure. However, they are generally mutually exclusive for a given hook; you cannot mix rules from iptables and nftables on the same chain.

**L6 — Medium:** The most likely cause is **inode exhaustion**. `df` reports block usage, while `du` counts files. If there are thousands of tiny files, the block usage might be low, but the inode count could be full.

**L7 — Hard:** The boot process is:
1.  **UEFI Firmware:** Initializes hardware (CPU, memory, devices).
2.  **Bootloader (e.g., GRUB2):** Loaded from the EFI System Partition (ESP).
3.  **Kernel:** Bootloader loads the Linux kernel and initramfs into memory.
4.  **Initramfs:** Kernel mounts the root filesystem using drivers in initramfs.
5.  **Root:** Kernel switches to the real root filesystem.
6.  **Systemd:** Init process (PID 1) starts, mounts filesystems, sets up networking, and starts services to reach the target (e.g., `multi-user.target`).

**L8 — Hard:** "Available" is an estimate of memory that can be reclaimed for applications. While it includes `buff/cache`, if the application is a memory hog (e.g., database) and the cache holds data the app needs, reclaiming it doesn't help. Also, pinned memory (e.g., hugepages) isn't "freeable".
Kernel tunables affecting this include `vm.swappiness` (preference for swapping), `vm.vfs_cache_pressure` (reclaiming inode/dentry cache), and `overcommit_memory`.

**L9 — Medium:** `ip netns` creates, lists, and manipulates **network namespaces**.
Container runtimes use this to isolate each container's network stack (interfaces, routes, iptables) from the host, allowing containers to have their own IP addresses and network configurations.

**L10 — Medium:**
*   **SIGTERM (15):** Graceful termination. Can be caught/ignored.
*   **SIGKILL (9):** Immediate termination. Cannot be caught/ignored.
*   **SIGQUIT (3):** Quit signal (often generates a core dump). Can be caught/ignored.

**L11 — Easy:** **Stdin** (0) is standard input, **Stdout** (1) is standard output, and **Stderr** (2) is standard error.
To redirect stderr to a file while keeping stdout on the terminal: `command 2>error.log` (stdout goes to terminal by default).

**L12 — Easy:** `chmod 755` grants:
*   **7 (Owner):** Read, Write, Execute.
*   **5 (Group):** Read, Execute.
*   **5 (Others):** Read, Execute.

**L13 — Easy:** The **root user** is the superuser (UID 0) with absolute control and no password requirement. A user with **sudo** privileges can execute commands as another user (usually root) but requires authentication and leaves an audit trail.

**L14 — Easy:** A **package manager** manages software installation, upgrade, and removal.
*   **Debian/Ubuntu:** `apt` / `dpkg`.
*   **RHEL/Fedora:** `dnf` / `yum`.

**L15 — Easy:** `/etc/fstab` defines static filesystems to mount at boot.
If an entry is misconfigured (e.g., a filesystem marked "auto" fails to mount), the boot process may hang waiting for a timeout.

**L16 — Medium:** **LVM** (Logical Volume Manager) abstracts physical disks into flexible logical volumes.
*   **PV:** Physical disk/partition.
*   **VG:** Collection of PVs.
*   **LV:** Partition of a VG.
To extend a logical volume on a running system: `lvextend -L +10G /dev/vg0/lv01` followed by `resize2fs /dev/vg0/lv01` (or `xfs_growfs`).

**L17 — Hard:** The I/O scheduler determines the order of I/O requests.
*   **mq-deadline:** Fairness and latency bound (good for databases).
*   **bfq:** Budget Fair Queueing (good for interactive workloads/SSDs).
*   **none:** No queueing (good for high-performance NVMe where the device handles queueing).
To change at runtime: `echo mq-deadline > /sys/block/sda/queue/scheduler`.

**L18 — Hard:** **Load average** measures the average number of processes waiting in the run queue. **I/O wait** inflates this because processes waiting for disk/network are in the run queue but not using CPU.
To diagnose: Use `top` (check %wa), `iostat -x 1` (check disk wait/avg service time), and `iftop`/`nload` (check network load).

**L19 — Hard:** **SELinux** enforces Mandatory Access Control (MAC) on top of standard permissions, using context labels (user:role:type:level).
*   **Enforcing:** Enforces policies and logs denials.
*   **Permissive:** Logs denials but allows access.
*   **Disabled:** No MAC.
To troubleshoot a port binding issue: Check logs (`audit2allow -w`), use `audit2allow` to generate a policy module, or check contexts with `ls -Z`.

**L20 — Hard:** A **page fault** occurs when a process accesses a virtual memory page not currently mapped to physical RAM.
*   **Minor:** Page is in swap or page cache (fast).
*   **Major:** Page must be loaded from disk (slow).
**Transparent Huge Pages (THP)** uses 2MB pages to reduce TLB pressure and overhead, improving performance.
Disable THP if an application suffers from "thundering herd" or performance degradation due to page splitting (e.g., databases): `echo never > /sys/kernel/mm/transparent_hugepage/enabled`.
