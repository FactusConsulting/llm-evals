**G1 — Easy:** An array in Go has a fixed length and type (e.g., `[5]int`), whereas a slice is a dynamic view onto an array with a length and capacity. When you append to a slice that has reached its capacity, Go allocates a new underlying array (usually with a larger capacity), copies the existing elements, and appends the new element.

**G2 — Easy:** `var x int` declares a variable `x` of type `int` and initializes it to its zero value (0). `x := 0` declares and initializes `x` in a single step. You cannot use `:=` in function parameters or outside of a function (at the package level).

**G3 — Medium:** A goroutine is a lightweight thread managed by the Go runtime, not the OS. It differs from an OS thread in that it has a much smaller memory footprint and is multiplexed onto a smaller number of OS threads. The Go scheduler uses the GMP model: **G**oroutines (tasks), **M**achines (OS threads), and **P**rocessors (logical processors) that schedule Gs onto Ms.

**G4 — Medium:** Channels provide typed conduits for communication. An unbuffered channel blocks the sender until the receiver is ready and vice versa. A buffered channel allows a specified number of messages to be sent without blocking. Sending to a full buffered channel blocks until a receiver takes a value.

**G5 — Medium:** The `context` package is used to propagate cancellation signals, deadlines, and request-scoped values across API boundaries and goroutines. It is the standard way to manage lifecycle in Go.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()

resp, err := http.GetWithContext(ctx, "http://example.com")
if err != nil {
    // Handle timeout or network error
}
```

**G6 — Medium:** Go interfaces are implicit; a type satisfies an interface if it implements the required methods (duck typing), unlike Java/C# where you must explicitly declare implementation. `interface{}` (empty interface) holds any type. It is powerful for polymorphism but dangerous because it requires type assertions to use specific methods, losing compile-time type safety and incurring performance overhead.

**G7 — Hard:** The code is unsafe because it relies on the memory model's "happens-before" guarantees, which are not enforced by the compiler or CPU for simple variable assignments. The loop `for !ready {}` creates a "load-load" race condition; the compiler may optimize the read of `ready` out of the loop because it assumes no other goroutine modifies it. The correct alternatives are using a `sync.Mutex` to protect the variables or using a channel to signal completion.

**G8 — Hard:** `sync.Mutex` is a simple mutual exclusion lock. `sync.RWMutex` allows multiple concurrent readers but exclusive writers. Use `RWMutex` for read-heavy workloads. `sync.Map` is optimized for concurrent reads and writes of map keys, avoiding locks for reads. The trade-off is that `sync.Map` has higher overhead for simple cases compared to a standard map protected by a mutex.

**G9 — Hard:** Go modules define dependencies. `go.mod` lists the module path and dependencies. `go.sum` contains cryptographic hashes of the exact versions of dependencies to ensure reproducibility. `go mod tidy` removes unused dependencies and adds missing ones. Minimum Version Selection (MVS) is the algorithm used to determine the minimum compatible version of a dependency based on the requirements of the current module and its dependencies.

**G10 — Medium:** A `defer` statement schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in LIFO (Last-In, First-Out) order. A common gotcha is using `defer` inside a loop: the function is deferred, but the *execution* happens after the loop finishes. If the deferred function captures a loop variable, it will use the final value of that variable, not the value at the moment of the loop iteration.

**G11 — Easy:** A pointer stores the memory address of a variable. The zero value of a pointer is `nil`. To create a pointer to a struct literal, use the address-of operator: `p := &MyStruct{}`.

**G12 — Easy:** The `init()` function runs automatically before `main()` when a package is imported. A package can have multiple `init()` functions, but they execute in lexical order (the order they appear in the source files).

**G13 — Easy:** `new(T)` allocates zeroed memory for a type `T` and returns a pointer to it; it works for structs and pointers. `make(T)` allocates and initializes a slice, map, or channel; it does not return a pointer. `make` is used for the three composite types mentioned; `new` is used for structs and pointers.

**G14 — Easy:** Errors are handled via the `error` interface, which has a single method `Error() string`. The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error matches a specific error value (handling wrapped errors), while `errors.As` attempts to cast an error to a specific type.

**G15 — Easy:** Built-in composite types are `map`, `slice`, `channel`, and `struct`. Their zero values are: `nil` map, `nil` slice (length 0, capacity 0), `nil` channel, and a struct with all fields set to their zero values.

**G16 — Medium:** A race condition occurs when two goroutines access shared data concurrently without synchronization. The `-race` flag enables the race detector, which inserts checks to detect data races at runtime. Example: a shared counter incremented by two goroutines. Fix: Use a `sync.Mutex` or a channel to serialize access.

**G17 — Medium:** `select` is a control structure that waits on multiple channel operations. It differs from `switch` in that it only works with channels. If multiple cases are ready, one is chosen arbitrarily. To implement a timeout, you can use `select { case <-time.After(5 * time.Second): ... }`.

**G18 — Hard:** Escape analysis is a compiler optimization that determines if a variable can be stored on the stack or must be moved to the heap. It decides based on whether the variable's reference outlives the function call. You can inspect decisions using `go build -gcflags="-m -l=0"`. It matters because heap allocations increase Garbage Collection (GC) pressure and latency.

**G19 — Hard:** `reflect.Type` describes the type of a value, while `reflect.Value` holds the actual value. Reflection is expensive (slower than direct calls, breaks inlining) and unsafe (can violate type safety). It is justified for generic libraries (e.g., JSON marshaling) or when working with dynamic data structures where the type is unknown at compile time.

**G20 — Hard:** The `go:embed` directive allows embedding static files into the Go binary. For a single file: `//go:embed file.txt`. For a directory: `//go:embed assets/*`. It returns an `embed.FS` which implements `io/fs.FS`. Limitations include relative paths, no globbing in subdirectories, and inability to modify embedded files.

## Rust (20 questions)

**R1 — Easy:** Ownership in Rust means every value has a variable that is its owner. The three rules are: 1. Each value has exactly one owner. 2. When the owner goes out of scope, the value is dropped. 3. There can only be one mutable owner or multiple immutable owners at a time.

**R2 — Easy:** `String` is an owned, heap-allocated, growable string. `&str` is a string slice (a reference to a string slice). Use `String` when you need to own the data or modify it; use `&str` for function arguments or references to existing data to avoid unnecessary allocations.

**R3 — Medium:** Borrowing allows temporary access to data. The borrow checker enforces: 1. You can have either one mutable reference or any number of immutable references. 2. References must always be valid (non-overlapping). 3. References must not outlive the data they reference.

**R4 — Medium:** `Result<T, E>` represents a value that could be success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents a value that could be present (`Some(T)`) or absent (`None`). The `?` operator propagates errors from a function returning `Result` or `Option` if the result is `Err` or `None`.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

**R5 — Medium:** `Box<T>` allocates on the heap for single ownership. `Rc<T>` (Reference Counting) allows multiple ownership on a single thread. `Arc<T>` (Atomic Reference Counting) allows multiple ownership across threads safely. Use `Box` for recursion or large data; `Rc` for shared ownership in single-threaded contexts; `Arc` for shared ownership in multi-threaded contexts.

**R6 — Medium:** Traits define behavior, similar to interfaces. Rust requires explicit trait bounds (`T: Trait`), whereas Go uses implicit satisfaction. A trait object (`dyn Trait`) enables dynamic dispatch (runtime lookup of methods via vtable), while generics with trait bounds enable static dispatch (monomorphization) for better performance.

**R7 — Hard:** The function fails because the return type `&str` does not have a lifetime parameter. The compiler cannot guarantee that the returned string slice outlives the arguments. Fix: Add a lifetime parameter to the function signature:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8 — Hard:** `Send` and `Sync` are unsafe traits. `Send` allows a type to be transferred across thread boundaries. `Sync` allows a type to be shared via `&` across threads. `Rc<T>` is not `Send` because its reference counting is not atomic. `Arc<T>` is `Send` and `Sync` because it uses atomic operations for its reference count.

**R9 — Hard:** Rust's async/await relies on the `Future` trait, which represents a value that may not be ready yet. An executor (like Tokio) polls futures to drive them to completion. Unlike Go's goroutines (which are lightweight threads managed by the runtime), Rust's async is based on callbacks and polling, requiring an explicit executor to run the code.

**R10 — Medium:** `unsafe` allows bypassing Rust's safety guarantees. 1. Dereferencing raw pointers. 2. Calling unsafe functions. 3. Accessing union fields. It is justified when interfacing with low-level systems programming, FFI, or implementing low-level abstractions where the programmer can guarantee safety.

**R11 — Easy:** Pattern matching (`match`) is exhaustive (the compiler ensures all cases are handled). `if let` is syntactic sugar for a `match` with one pattern and a catch-all `_`. `match` is preferred for clarity and safety, while `if let` is useful for matching one specific case without boilerplate.

**R12 — Easy:** `Vec<T>` is a dynamic array that manages its own memory on the heap. An array `[T; N]` has a fixed size. When a `Vec` is pushed beyond its current capacity, it allocates a new, larger block of memory, copies the existing elements, and appends the new one.

**R13 — Easy:** Enums in Rust are algebraic data types that can hold data. Unlike C/Java, Rust enums can have associated data. `Option<T>` is `Some(T)` or `None`. Rust does not have null to enforce safety; instead, it uses `Option` to explicitly handle the absence of a value.

**R14 — Easy:** An `impl` block defines methods for a type. `&self` allows shared, immutable access. `&mut self` allows shared, mutable access. `self` takes ownership. Associated functions (e.g., `String::new()`) are functions defined inside an `impl` block that do not take `self` (static-like behavior).

**R15 — Easy:** The `derive` macro automatically implements traits for a struct. Common examples: `Debug` (printing), `Clone` (copying), `PartialEq` (equality), `Serialize` (serialization). You cannot derive traits that require complex logic (e.g., `Hash` on generic types without bounds, `Eq` on types not `PartialEq`).

**R16 — Medium:** `Cow<'a, T>` (Clone on Write) is a smart pointer that can be either a borrow (`&T`) or an owned value (`T`). It is useful when you might need to mutate data but want to avoid cloning if the data is already owned. Example: Parsing a string; if it's already owned, keep it; if it's a slice, clone it only if modified.

**R17 — Medium:** The module system uses `mod` to declare a module, `use` to import items, and `pub` to make items visible. In the 2018 edition, the file system maps directly: `src/lib.rs` is the root, and `src/foo.rs` is a module named `foo`. In 2015, `src/foo.rs` required a `mod foo;` declaration in `lib.rs`.

**R18 — Hard:** `Pin<T>` prevents a value from being moved out of its location. It is needed for self-referential structs (e.g., a struct holding a pointer to itself) and `Future` objects in async/await to ensure the memory location remains stable during polling. `Unpin` is the opposite trait; types that implement `Unpin` can be moved even if pinned.

**R19 — Hard:** Rust has two macro types: declarative (`macro_rules!`) and procedural (derive, attribute, function-like). Hygiene rules ensure that macros do not see the surrounding scope, preventing variable name collisions and ensuring that the macro's generated code is self-contained.

**R20 — Hard:** Zero-cost abstractions mean that high-level abstractions (like iterators, generics, and traits) compile down to efficient, low-level code. Generics use monomorphization (inlining specific implementations for each type), and trait dispatch is often static, achieving performance comparable to hand-written C while providing high-level ergonomics.
