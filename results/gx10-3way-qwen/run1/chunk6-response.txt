## JavaScript / TypeScript

**JS1 — Easy**  
`var` is function/global scoped, hoisted and initialized to `undefined`, and can be redeclared. `let` and `const` are block scoped and have a temporal dead zone until initialized. `const` prevents rebinding the variable, though object contents can still mutate. Hoisting means declarations are processed before code execution: `var` declarations exist early as `undefined`; `let`/`const` exist but are uninitialized.

**JS2 — Easy**  
The event loop coordinates asynchronous JavaScript. The call stack runs synchronous code. When it empties, the engine drains the microtask queue first: promise callbacks, `queueMicrotask`, `MutationObserver`. Then it processes one macrotask: timers, I/O, UI events. Rendering may occur between macrotasks.

**JS3 — Medium**  
A closure is a function that retains access to its lexical scope even after that scope has finished executing.

```js
function counter() {
  let n = 0;
  return () => ++n;
}
```

Classic `for` loop bug:

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 3, 3, 3
}
```

Fix with `let`, an IIFE, or `bind`:

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 0, 1, 2
}
```

**JS4 — Medium**  
A `Promise` represents an eventual value or failure. It can be pending, fulfilled, or rejected. `then`, `catch`, and `finally` handle outcomes. `async/await` is syntax over promises; `await` pauses the async function until the promise settles.

```js
try {
  const data = await fetch(url);
} catch (err) {
  // handles rejected promise
}
```

`Promise.all` rejects as soon as any promise rejects. `Promise.allSettled` always resolves with an array describing each promise’s status: `fulfilled` or `rejected`.

**JS5 — Medium**  
`interface` describes object shapes, supports declaration merging, and is often used for public API contracts. `type` can describe unions, intersections, primitives, tuples, mapped types, and conditional types.

Use `interface` for object contracts and extensibility. Use `type` for unions, complex type operations, and non-object types.

Discriminated unions use a common literal tag field:

```ts
type Result =
  | { kind: "ok"; value: number }
  | { kind: "error"; message: string };

function handle(r: Result) {
  if (r.kind === "ok") return r.value;
  return r.message;
}
```

**JS6 — Medium**  
JavaScript uses prototypal inheritance: objects delegate property lookup to their prototype chain.

```js
const proto = { greet() { return "hi"; } };
const obj = Object.create(proto);
obj.greet(); // "hi"
```

`Object.create(proto)` creates a new object whose internal `[[Prototype]]` is `proto`.

ES6 classes are syntactic sugar over prototypes. Instance methods live on `Constructor.prototype`, static methods live on the constructor, and `extends` sets up prototype chains.

**JS7 — Hard**  
`this` is determined by how a function is called. Binding rules, highest to lowest priority:

1. `new` binding: `new Foo()` makes `this` the new object.
2. Explicit binding: `call`, `apply`, `bind`.
3. Implicit binding: `obj.method()` makes `this` `obj`.
4. Default binding: global object in sloppy mode, `undefined` in strict mode.

`bind()` returns a new function with a fixed `this` and optional preset arguments. You cannot re-bind its `this`; later `bind`, `call`, or `apply` ignore the new `thisArg`.

**JS8 — Hard**  
`WeakRef` holds a weak reference to an object. `deref()` returns the object if still alive, otherwise `undefined`.

```js
const ref = new WeakRef(obj);
const target = ref.deref();
```

`FinalizationRegistry` runs a callback after a registered object is garbage collected.

Use them for caches, observers, or cleanup where you do not want to prevent garbage collection.

`WeakMap` keys must be GC-managed objects, or symbols in modern engines, because weak references rely on object identity. Primitive values are not heap objects and cannot be weakly tracked in the same way.

**JS9 — Hard**  
V8 parses JavaScript into an AST, compiles to bytecode for Ignition, and optimizes hot code with TurboFan.

Hidden classes, or maps, describe object shapes. V8 uses inline caches to store property offsets for fast access. Monomorphic access is fastest; polymorphic and megamorphic access are slower.

Deoptimization occurs when optimized code assumptions fail. Common causes:

- Adding or deleting properties after object creation.
- Changing property types.
- Using `delete`.
- Dynamic property names.
- Polymorphic call sites.
- `eval`, `with`, or `arguments` object misuse.

**JS10 — Medium**  
Tree-shaking removes unused exported code during bundling.

ES modules are static: `import` and `export` are analyzable at build time, so bundlers can detect unused exports.

CommonJS is dynamic: `require` can be conditional, `module.exports` can be mutated, and side effects are harder to prove. Therefore CommonJS cannot be tree-shaken effectively.

**JS11 — Easy**  
`undefined` means a variable exists but has no assigned value, or a property is missing. `null` is an intentional absence value.

```js
null == undefined;   // true
null === undefined;  // false
```

`??` returns the right side only if the left side is `null` or `undefined`.

```js
const value = input ?? "default";
```

`?.` short-circuits if the left side is `null` or `undefined`.

```js
const city = user?.address?.city;
```

**JS12 — Easy**  
`map()` transforms each element and returns a new array.

```js
[1, 2].map(x => x * 2); // [2, 4]
```

`filter()` keeps elements where the callback returns truthy.

```js
[1, 2, 3].filter(x => x % 2 === 1); // [1, 3]
```

`reduce()` accumulates values.

```js
[1, 2, 3].reduce((acc, x) => acc + x, 0); // 6
```

With an initial value, the accumulator starts with that value and iteration starts at index 0. Without an initial value, the first element becomes the accumulator and iteration starts at index 1; an empty array throws.

`flatMap()` maps each element, then flattens one level. Useful when each input produces zero or more outputs.

**JS13 — Easy**  
Template literals use backticks and support interpolation and multiline strings.

```js
const name = "Ada";
const msg = `Hello, ${name}!`;
```

Tagged templates call a function with the string parts and interpolated values.

```js
function sql(strings, ...values) {
  return strings.reduce((acc, s, i) => {
    const v = values[i];
    const safe = String(v).replace(/'/g, "''");
    return acc + s + (i < values.length ? `'${safe}'` : "");
  }, "");
}

sql`SELECT * FROM users WHERE name = ${name}`;
```

**JS14 — Easy**  
Destructuring unpacks values from arrays or objects.

Object destructuring:

```js
const { a, b: c = 10 } = obj;
```

Array destructuring:

```js
const [first, second] = arr;
```

Default values apply when the value is `undefined`. Renaming uses `key: newName`.

Rest collects remaining values:

```js
const [a, ...rest] = [1, 2, 3];
const { x, ...others } = { x: 1, y: 2, z: 3 };
```

**JS15 — Easy**  
`for...in` iterates enumerable string keys, including inherited enumerable properties.

```js
for (const key in obj) { ... }
```

`for...of` iterates values of iterable objects: arrays, strings, Maps, Sets, generators.

```js
for (const value of arr) { ... }
```

Avoid `for...in` on arrays because it iterates keys as strings, may include prototype properties, and does not guarantee numeric order.

**JS16 — Medium**  
Generics parameterize types.

```ts
function identity<T>(x: T): T {
  return x;
}
```

Constraints use `extends`:

```ts
function getId<T extends { id: number }>(x: T) {
  return x.id;
}
```

Conditional types choose a type based on a condition:

```ts
type TypeName<T> =
  T extends string ? "string" :
  T extends number ? "number" :
  "other";
```

`infer` extracts a type inside a conditional type:

```ts
type ElementType<T> = T extends (infer U)[] ? U : never;
type X = ElementType<number[]>; // number
```

**JS17 — Medium**  
Modules encapsulate code and expose selected exports.

CommonJS uses `require` and `module.exports`. It is dynamic and synchronous.

```js
const fs = require("fs");
module.exports = { foo };
```

ES Modules use static `import`/`export`, support top-level await, and are analyzable by bundlers.

```js
import fs from "fs";
export { foo };
```

Node.js supports both. `.mjs` is ESM, `.cjs` is CommonJS, and `.js` depends on `"type"` in `package.json`. `"type": "module"` makes `.js` files ESM. ESM can import CommonJS; CommonJS can use dynamic `import()` to load ESM portably.

**JS18 — Hard**  
TypeScript uses structural typing: types are compatible if their shapes are compatible, not by name.

Excess property checks apply to fresh object literals assigned directly to a typed target.

```ts
type Point = { x: number; y: number };
const p: Point = { x: 1, y: 2, z: 3 }; // error
const obj = { x: 1, y: 2, z: 3 };
const q: Point = obj; // allowed
```

`extends` is used for interface inheritance and generic constraints. `satisfies` checks a value against a type while preserving the value’s inferred type.

```ts
const config = { a: 1 } satisfies Record<string, number>;
```

TypeScript 4.7+ variance annotations declare how a type parameter affects assignability:

```ts
interface Producer<out T> { get(): T; }
interface Consumer<in T> { set(value: T): void; }
```

`out` is covariant, `in` is contravariant, and `inout` is invariant.

**JS19 — Hard**  
`Proxy` wraps an object and intercepts operations through traps. `Reflect` provides default behavior for those traps.

Common traps: `get`, `set`, `has`, `deleteProperty`, `apply`, `construct`.

```js
const validator = {
  set(target, prop, value) {
    if (prop === "age" && typeof value !== "number") {
      throw new TypeError("age must be a number");
    }
    return Reflect.set(target, prop, value);
  }
};

const user = new Proxy({ age: 30 }, validator);
user.age = "x"; // throws
```

Use cases include validation, logging, reactive data binding, immutability, and access control.

**JS20 — Hard**  
`SharedArrayBuffer` is raw memory that can be shared across Web Workers. Workers create typed array views over the same buffer.

```js
const sab = new SharedArrayBuffer(1024);
const view = new Int32Array(sab);
```

`Atomics` provides indivisible operations on typed arrays: `load`, `store`, `add`, `compareExchange`, `wait`, `notify`.

Atomics operations are indivisible and provide memory-ordering guarantees, effectively sequential consistency for atomic operations. Non-atomic accesses are not synchronized.

`Atomics.wait(view, index, expected, timeout)` blocks the current thread if the value equals `expected`. `Atomics.notify(view, index, count)` wakes waiting threads. In browsers, `Atomics.wait` is not allowed on the main thread.

## Bash

**B1 — Easy**  
`$@` expands to all positional parameters as separate words. `$*` expands to all positional parameters as a single word.

```bash
"$@"  # preserves each argument separately
"$*"  # joins arguments using the first character of IFS
```

Unquoted `$@` and `$*` are both subject to word splitting and globbing.

**B2 — Easy**  
`set -euo pipefail` enables safer bash behavior.

- `-e`: exit immediately if a command fails, with exceptions such as commands in `if`, `while`, `until`, `&&`, `||`, or negated commands.
- `-u`: error if an unset variable is used.
- `-o pipefail`: pipeline returns the rightmost non-zero exit status instead of only the last command’s status.

**B3 — Medium**  
`$(command)` is modern command substitution. It is nestable and readable.

```bash
result=$(echo $(date))
```

Backticks, `` `command` ``, are older and harder to nest.

`$((expression))` is bash arithmetic expansion.

```bash
x=$((1 + 2))
```

`expr` is an external command, slower, and uses different syntax.

```bash
x=$(expr 1 + 2)
```

**B4 — Medium**  
Process substitution creates a file descriptor that behaves like a file.

```bash
<(command)  # command output as a file
>(command)  # command input as a file
```

Useful when a command expects filenames.

```bash
diff <(sort file1) <(sort file2)
```

This avoids temporary files.

**B5 — Medium**  
Use null-delimited input or bash globbing.

```bash
find . -maxdepth 1 -type f -print0 |
while IFS= read -r -d '' f; do
  printf '%s\n' "$f"
done
```

Or:

```bash
shopt -s nullglob
for f in *.txt; do
  printf '%s\n' "$f"
done
```

`for f in $(ls)` is dangerous because it splits on whitespace, breaks on spaces/newlines, and can trigger globbing.

**B6 — Medium**  
A here document feeds stdin until a delimiter.

```bash
cat <<EOF
line 1
line 2
EOF
```

A here string feeds a single string.

```bash
grep foo <<< "foo bar"
```

`<<-EOF` strips leading tabs from the delimiter and content. It does not strip leading spaces.

**B7 — Hard**  
Redirections are processed left to right.

```bash
cmd > file 2>&1
```

Stdout goes to `file`, then stderr is duplicated to stdout, so both go to `file`.

```bash
cmd 2>&1 > file
```

Stderr is duplicated to the current stdout, usually the terminal. Then stdout is redirected to `file`. So stderr goes to the terminal, stdout goes to `file`.

```bash
cmd &> file
```

Bash shorthand for redirecting both stdout and stderr to `file`.

**B8 — Hard**  

```bash
cleanup_lock() {
  local lock_dir="$1"
  rmdir "$lock_dir" 2>/dev/null || true
}

lock() {
  local lock_dir="$1"
  local timeout="${2:-30}"
  local start=$SECONDS

  while ! mkdir "$lock_dir" 2>/dev/null; do
    if (( SECONDS - start >= timeout )); then
      return 1
    fi
    sleep 0.1
  done

  trap 'cleanup_lock "$lock_dir"' EXIT
  trap 'cleanup_lock "$lock_dir"; exit 130' INT
  trap 'cleanup_lock "$lock_dir"; exit 143' TERM
}
```

`mkdir` is preferred because directory creation is atomic on POSIX filesystems: it either succeeds or fails if the directory already exists. File creation with `>` is not atomic unless using `O_EXCL`. `SIGKILL` cannot be trapped, so stale locks may require timeouts or `flock`.

**B9 — Easy**  
Single quotes are literal. Double quotes allow expansion. No quotes allow expansion, word splitting, and globbing.

```bash
f="*"
echo '$f'   # $f
echo "$f"   # *
echo $f     # list of files
```

**B10 — Easy**  

```bash
[ -e file ]  # exists
[ -d file ]  # directory
[ -r file ]  # readable
```

`[ ]` is the `test` command. `[[ ]]` is a bash keyword. It is safer because it avoids word splitting and pathname expansion, supports `&&`, `||`, regex with `=~`, and pattern matching.

**B11 — Easy**  

- `$?`: exit status of the last command.
- `$$`: PID of the current shell.
- `$!`: PID of the most recent background job.
- `$#`: number of positional parameters.

Use cases:

```bash
if [ $? -ne 0 ]; then echo failed; fi
echo $$
kill "$!"
echo "$# args"
```

**B12 — Easy**  

```bash
foo() {
  echo "hello"
}

function bar {
  echo "hello"
}
```

`foo() {}` is POSIX. `function foo {}` is a bashism.

Functions return an exit status with `return`, usually `0` for success. To return data, write to stdout and capture it:

```bash
result=$(foo)
```

**B13 — Easy**  
`PATH` is a colon-separated list of directories where bash searches for external commands.

Bash resolves commands in this order: aliases, functions, builtins, then external commands found in `PATH`.

Builtins are implemented inside bash, such as `cd`, `echo`, `read`. External commands are separate executables, such as `/usr/bin/ls`.

Check resolution with:

```bash
type ls
command -v ls
which ls
```

**B14 — Medium**  
`trap` runs commands when signals or shell events occur.

```bash
trap 'cleanup' EXIT
trap 'echo error' ERR
trap 'echo interrupted; exit 130' INT
trap 'echo terminating; exit 143' TERM
```

`EXIT` runs when the shell exits. `ERR` runs when a command fails, except in conditionals or `&&`/`||` contexts. `INT` and `TERM` handle Ctrl-C and termination requests.

If multiple signals arrive, bash processes trap handlers as signals are delivered. If a handler is already running, additional signals may be queued or ignored depending on the signal and shell state. `EXIT` runs after normal exit or after a signal handler exits.

**B15 — Medium**  
`xargs` builds and executes commands from stdin, often in batches. Command substitution expands everything at once and can exceed `ARG_MAX`.

Handle spaces and newlines with null delimiters:

```bash
find . -type f -print0 | xargs -0 rm --
```

`xargs -P N` runs up to `N` commands in parallel.

```bash
find . -type f -print0 | xargs -0 -P 4 -I{} sh -c 'process "$0"' {}
```

**B16 — Medium**  
Indexed arrays:

```bash
declare -a arr=(a b c)
arr+=(d)
echo "${arr[@]}"
echo "${#arr[@]}"
for x in "${arr[@]}"; do
  echo "$x"
done
```

Associative arrays require bash 4+:

```bash
declare -A map=([k1]=v1 [k2]=v2)
map[k3]=v3
echo "${map[@]}"
echo "${#map[@]}"
for key in "${!map[@]}"; do
  echo "$key=${map[$key]}"
done
```

Indexed arrays use numeric indices. Associative arrays use string keys.

**B17 — Hard**  
A subshell runs in a child process.

```bash
( x=1 )
echo "$x"  # unchanged in parent
```

A group command runs in the current shell.

```bash
{ x=1; }
echo "$x"  # 1
```

Both return the exit status of the last command.

Piping creates subshells for pipeline components:

```bash
echo hi | while read line; do x=1; done
echo "$x"  # unchanged
```

Fix with process substitution:

```bash
while read line; do x=1; done < <(echo hi)
```

Or enable `shopt -s lastpipe` in bash.

**B18 — Hard**  
Signals:

- `SIGINT`: interrupt, usually Ctrl-C. Can be trapped.
- `SIGTERM`: termination request. Can be trapped.
- `SIGHUP`: terminal hangup. Can be trapped.
- `SIGKILL`: immediate kill. Cannot be trapped or ignored.

Job control manages background jobs with `&`, `jobs`, `fg`, `bg`, and `kill`.

Graceful shutdown:

```bash
pids=()
trap 'kill "${pids[@]}" 2>/dev/null; wait' TERM INT

long_task & pids+=($!)
another_task & pids+=($!)

wait
```

The script traps termination, signals children, waits for them, then exits.

**B19 — Hard**  

```bash
#!/usr/bin/env bash
set -euo pipefail

log="${1:?usage: $0 big.log [jobs]}"
jobs="${2:-$(nproc)}"
tmp=$(mktemp -d)
trap 'rm -rf "$tmp"' EXIT

process_chunk() {
  local file="$1"
  awk '/ERROR/ { print FILENAME ":" FNR ":" $0 }' "$file" > "${file}.out"
}
export -f process_chunk

split -l 100000 --additional-suffix=.part "$log" "$tmp/chunk_"

find "$tmp" -maxdepth 1 -name 'chunk_*.part' -print0 |
  xargs -0 -r -P "$jobs" -I{} bash -c 'process_chunk "$0"' {}

cat "$tmp"/chunk_*.part.out > merged.out
```

Trade-offs:

- Parallelism improves CPU-bound work.
- Disk I/O may become the bottleneck.
- Splitting and merging add overhead.
- Output order is lost unless explicitly preserved.
- Too many workers can cause contention.

Error propagation: GNU `xargs` returns `123` if any child command fails. With `set -e` and `pipefail`, the script fails. For better reporting, use GNU `parallel --halt now,fail=1` or collect per-chunk exit statuses.

**B20 — Hard**  
Running a command normally forks a child process. `exec command` replaces the current shell process with the command, so the shell does not continue afterward.

`exec` can also manipulate file descriptors without running a command:

```bash
exec 3>file      # open fd 3 for writing
exec 3>&-        # close fd 3
exec 4<file      # open fd 4 for reading
```

A coprocess runs a command with pipes for bidirectional communication:

```bash
coproc cat {
  echo hello
}

read -u "${COPROC[0]}" line
printf '%s\n' "$line" >&"${COPROC[1]}"
wait
```

Use coprocesses for interactive programs or long-running processes needing stdin/stdout control.

## PowerShell

**PS1 — Easy**  
`Write-Output` sends objects into the pipeline.

```powershell
Write-Output "value" | Measure-Object
```

`Write-Host` writes to the host console, usually the information stream, not the success pipeline.

```powershell
Write-Host "message"
```

This matters because pipelines capture `Write-Output`, not `Write-Host`.

**PS2 — Easy**  
The PowerShell pipeline passes objects between commands.

`ForEach-Object` is a cmdlet that processes pipeline input.

```powershell
1..3 | ForEach-Object { $_ * 2 }
```

`foreach` is a language statement.

```powershell
foreach ($x in 1..3) { $x * 2 }
```

Use `ForEach-Object` for pipeline processing and `-Parallel`. Use `foreach` for faster simple loops and `break`/`continue`.

**PS3 — Medium**  
`[PSCustomObject]` creates an object with named properties.

```powershell
[PSCustomObject]@{ Name = "Alice"; Age = 30 }
```

A hashtable is a key-value dictionary.

```powershell
@{ Name = "Alice"; Age = 30 }
```

Use `PSCustomObject` for structured output and object pipelines. Use hashtables for lookup, dynamic keys, and parameter splatting.

Convert hashtable to object:

```powershell
[PSCustomObject]$hashtable
```

Convert object to hashtable:

```powershell
$obj.PSObject.Properties | ForEach-Object {
  $h[$_.Name] = $_.Value
}
```

**PS4 — Medium**  
Terminating errors stop execution and can be caught with `try/catch`. Non-terminating errors report an error but allow execution to continue.

```powershell
try {
  Get-Item -Path "missing" -ErrorAction Stop
} catch {
  Write-Warning $_.Exception.Message
}
```

`-ErrorAction` controls a single command. `$ErrorActionPreference` sets the default for the session or script.

Common values:

- `Stop`: makes errors terminating.
- `Continue`: default for many cmdlets.
- `SilentlyContinue`: suppresses errors.

`try/catch` catches terminating errors. Non-terminating errors are not caught unless promoted with `-ErrorAction Stop` or `$ErrorActionPreference = "Stop"`.

**PS5 — Medium**  
Splatting expands a hashtable or array into named or positional parameters.

```powershell
$params = @{
  Path    = "C:\"
  Recurse = $true
}

Get-ChildItem @params
```

Passing a hashtable without `@` passes it as one parameter value:

```powershell
Get-ChildItem $params  # not splatted
```

Splatting improves readability and dynamic parameter construction.

**PS6 — Medium**  
PowerShell remoting executes commands on remote machines.

`Invoke-Command -ComputerName` runs a command remotely and returns results.

```powershell
Invoke-Command -ComputerName Server1 -ScriptBlock { hostname }
```

`Enter-PSSession` opens an interactive remote session.

```powershell
Enter-PSSession -ComputerName Server1
```

Default remoting uses WinRM over HTTP/HTTPS. PowerShell 7 also supports SSH remoting.

**PS7 — Hard**  

```powershell
function Get-Items {
    $result = @()
    $result += "one"
    return $result
}
$x = Get-Items
$x.GetType().Name
```

The result is `String`.

PowerShell enumerates pipeline output. A single-element array returned from a function becomes a scalar when assigned.

If the function returns zero items, `$x` is `$null`.

Correct patterns:

```powershell
return ,$result
```

or:

```powershell
$x = @(Get-Items)
```

This preserves an array even for zero or one item.

**PS8 — Hard**  
A scriptblock is an anonymous block of code.

```powershell
$block = { param($x) $x * 2 }
& $block 5
```

A function is a named command with parameter binding and help support.

Pass scriptblocks remotely with `-ArgumentList`:

```powershell
Invoke-Command -ComputerName Server1 -ScriptBlock {
  param($name)
  "Hello $name"
} -ArgumentList "Alice"
```

The double-hop problem occurs when a remote session tries to authenticate to a second remote resource using the caller’s credentials. Default WinRM does not delegate credentials.

Solutions:

- CredSSP.
- Kerberos constrained delegation.
- Explicit credentials passed securely.
- Nested `Invoke-Command` with credentials available on the first hop.

**PS9 — Easy**  
`@()` creates an empty array.

```powershell
$x = @()
```

`[array]` is a type accelerator used for casting or parameter types.

```powershell
$x = [array]$singleValue
```

Force a single result into an array:

```powershell
$x = @($singleValue)
```

Indexing `$null` returns `$null`. Indexing an empty array also returns `$null`.

```powershell
$null[0]
@()[0]
```

Use `@()` when you need guaranteed array behavior.

**PS10 — Easy**  
Comparison operators:

- `-eq`: equal.
- `-ne`: not equal.
- `-like`: wildcard match.
- `-match`: regex match.
- `-contains`: collection contains item.
- `-in`: item is in collection.

Default comparisons are case-insensitive. Case-sensitive variants use `c`:

```powershell
-ceq
-cne
-clike
-cmatch
-ccontains
-cin
```

Difference:

```powershell
$collection -contains $item
$item -in $collection
```

**PS11 — Easy**  
A PowerShell module packages functions, variables, classes, and resources for reuse.

- Script module: `.psm1` file containing PowerShell code.
- Manifest module: `.psd1` file describing metadata, version, dependencies, and root module.
- Binary module: compiled `.dll` exposing cmdlets or types.

`Import-Module` loads a module into the session.

```powershell
Import-Module MyModule
Import-Module C:\Modules\MyModule\MyModule.psd1
```

PowerShell can also auto-load modules from `PSModulePath`.

**PS12 — Easy**  
Double-quoted strings interpolate variables and subexpressions.

```powershell
$name = "Alice"
"Hello $name"
"Hello $($user.Name)"
```

Single-quoted strings are literal.

```powershell
'Hello $name'
```

Here-strings support multiline text.

Interpolating here-string:

```powershell
@"
Hello $name
"@
```

Literal here-string:

```powershell
@'
Hello $name
'@
```

**PS13 — Easy**  
`Get-Member` shows an object’s type, properties, and methods.

```powershell
Get-Process | Get-Member
```

Properties are actual object properties. Methods are callable members. NoteProperties are added properties, often created by `Select-Object` or calculated properties.

`Select-Object` selects, renames, or creates properties.

```powershell
Get-Process | Select-Object Name, Id
```

`Where-Object` filters objects.

```powershell
Get-Process | Where-Object CPU -gt 100
```

**PS14 — Medium**  
PowerShell classes were introduced in v5.

```powershell
class Person {
  [string]$Name
  Person([string]$name) { $this.Name = $name }
  [string]Greet() { return "Hello $($this.Name)" }
}

[Person]::new("Alice").Greet()
```

They support properties, methods, constructors, inheritance, and static members.

Limitations compared with C#:

- No interfaces.
- No generics.
- No attributes.
- No multiple inheritance.
- Limited access modifiers.
- Less flexible constructor behavior.

Use classes for typed object models and stateful behavior. Use functions for cmdlets, scripts, and simple utilities.

**PS15 — Medium**  
`[CmdletBinding()]` turns a function into an advanced function.

It enables common parameters, parameter sets, validation, pipeline binding, and cmdlet-like behavior.

```powershell
function Get-Thing {
  [CmdletBinding(SupportsShouldProcess, DefaultParameterSetName = "ById")]
  param(
    [Parameter(ValueFromPipeline)]
    [string]$Name
  )

  begin { }
  process {
    if ($PSCmdlet.ShouldProcess($Name)) {
      "Processing $Name"
    }
  }
  end { }
}
```

`SupportsShouldProcess` adds `-WhatIf` and `-Confirm`. `DefaultParameterSetName` selects the default parameter set. `ValueFromPipeline` binds pipeline input to a parameter.

`begin` runs once, `process` runs per pipeline item, and `end` runs once after all input.

**PS16 — Medium**  
PowerShell providers expose different data stores as drives.

`Get-ChildItem` works across providers:

```powershell
Get-ChildItem C:\
Get-ChildItem HKLM:\Software
Get-ChildItem Cert:\LocalMachine\My
Get-ChildItem Env:
```

Registry access:

```powershell
Get-ItemProperty -Path HKLM:\Software\MyApp
New-ItemProperty -Path HKCU:\Software\MyApp -Name Value -Value 1
```

Providers let you navigate registry, certificates, environment variables, aliases, and variables similarly to the file system.

**PS17 — Hard**  
A runspace is an isolated PowerShell execution environment. A runspace pool manages multiple runspaces for reuse. A `[powershell]` object creates a pipeline that can be invoked in a runspace.

Manual runspace example:

```powershell
$ps = [powershell]::Create()
$ps.AddScript("Get-Date").Invoke()
$ps.Dispose()
```

`ForEach-Object -Parallel` in PowerShell 7+ uses runspaces internally.

```powershell
1..10 | ForEach-Object -Parallel {
  "Processing $_"
} -ThrottleLimit 4
```

Use `ForEach-Object -Parallel` for simple parallelism. Use manual runspaces for fine-grained control, custom thread management, or integration with .NET.

Thread safety: runspaces are not thread-safe. Each runspace should be used by one thread at a time. Shared state must be thread-safe.

**PS18 — Hard**  
PSScriptAnalyzer is a static analysis tool for PowerShell.

It enforces coding standards through rules such as avoiding `Write-Host`, using approved verbs, and avoiding aliases.

Rules have severity levels:

- Error.
- Warning.
- Information.

Custom rules can be written as PowerShell functions in a module.

Suppress rules with attributes:

```powershell
[Diagnostics.CodeAnalysis.SuppressMessageAttribute('PSAvoidUsingWriteHost', '')]
param()
```

CI/CD integration:

```powershell
Invoke-ScriptAnalyzer -Path . -Severity Error,Warning
```

Fail the pipeline if issues are found. PSScriptAnalyzer can also output SARIF for GitHub code scanning.

**PS19 — Hard**  
`$using:` references variables from the caller’s scope inside remote scriptblocks, background jobs, and `ForEach-Object -Parallel`.

```powershell
$name = "Alice"
Invoke-Command -ComputerName Server1 -ScriptBlock {
  "Hello $using:name"
}
```

`-ArgumentList` passes values into the scriptblock as parameters.

```powershell
Invoke-Command -ComputerName Server1 -ScriptBlock {
  param($name)
  "Hello $name"
} -ArgumentList "Alice"
```

`$args` contains unbound arguments passed to a scriptblock.

Remote and parallel execution serialize objects to CLIXML. Default serialization depth is limited, commonly 5. Complex objects may lose methods, type fidelity, and deep properties. They may arrive as `PSCustomObject` or hashtables. Pass simple values or explicitly serialize/deserialize when needed.

**PS20 — Hard**  
Desired State Configuration, DSC, is a declarative configuration management system.

A configuration defines desired state:

```powershell
Configuration Example {
  Node "Server1" {
    WindowsFeature IIS {
      Ensure = "Present"
      Name   = "Web-Server"
    }
  }
}
```

Resources implement specific settings, such as files, services, registry keys, or Windows features.

The Local Configuration Manager, LCM, applies, monitors, and reports configuration state.

Windows PowerShell 5.1 includes DSC and the Windows LCM. PowerShell 7 supports DSC through modules and newer DSC versions, but the traditional Windows LCM integration is not identical.

Modern infrastructure-as-code tools that replaced or superseded DSC include Ansible, Puppet, Chef, Terraform, Azure Policy, and GitOps-based systems.
