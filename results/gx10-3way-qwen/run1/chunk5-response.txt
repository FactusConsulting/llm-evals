## .NET / C#

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**  
A `class` is a reference type: variables hold references to heap-allocated objects, supports inheritance, can be `null`, and has reference equality by default. A `struct` is a value type: variables hold the data directly, is copied on assignment, cannot inherit from another struct/class except interfaces, and cannot be `null` unless wrapped in `Nullable<T>`. Use a `struct` for small, immutable, short-lived data types where copying is cheap and you want to avoid heap allocation/boxing, e.g. `Point`, `DateTime`, `Guid`, numeric wrappers.

**DN2 — Easy: Explain the difference between `IEnumerable<T>` and `IQueryable<T>`. Why does this distinction matter for database queries?**  
`IEnumerable<T>` represents an in-memory sequence and executes LINQ operators locally. `IQueryable<T>` represents a query expression tree that a provider, such as EF Core, can translate into SQL or another backend query. This matters because `IQueryable.Where(...)` can push filtering to the database, while `IEnumerable.Where(...)` usually fetches all rows first and filters in memory. Switching from `IQueryable` to `IEnumerable`, e.g. via `AsEnumerable()`, can cause major performance regressions.

**DN3 — Medium: How does `async/await` work in C#? What is a `Task` vs a `ValueTask`? When should you use `ValueTask`?**  
`async/await` is compiler-generated state-machine code. When an `await` is reached, the method may suspend and register a continuation, freeing the current thread. `Task` is a reference type representing an asynchronous operation. `ValueTask<T>` is a struct that can represent either a completed result or a `Task<T>`, avoiding allocation when the operation completes synchronously. Use `ValueTask` in hot paths where methods often complete synchronously and the result is awaited only once; avoid storing or awaiting a `ValueTask` multiple times.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes, and what is a common bug when injecting a Scoped service into a Singleton?**  
Dependency injection provides objects with their dependencies instead of creating them internally. .NET’s built-in container supports:  
- **Transient**: new instance every time requested.  
- **Scoped**: one instance per scope, typically one per HTTP request.  
- **Singleton**: one instance for the application lifetime.  
A common bug is a **captive dependency**: a Singleton holds a Scoped service, causing the Scoped service to live as long as the Singleton. This can cause thread-safety issues, stale data, memory leaks, and `DbContext` concurrency problems. Fix by injecting `IServiceScopeFactory` and creating a scope, or by making the service lifetime appropriate.

**DN5 — Medium: What is the difference between `string` and `ReadOnlySpan<char>` for string processing? When would you use `Span<T>` and why?**  
`string` is an immutable heap-allocated object. `ReadOnlySpan<char>` is a stack-only view over characters, allowing slicing without allocating new strings. `Span<T>` is a mutable stack-only view over contiguous memory. Use `Span<T>`/`ReadOnlySpan<char>` for high-performance parsing, formatting, or text processing where avoiding substring allocations and reducing GC pressure matters. They cannot be used as fields or across `await` boundaries.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations? What is the Large Object Heap? What is `IDisposable` and why do you need it if you have a GC?**  
The GC manages heap memory and reclaims unreachable objects. It uses generations: **Gen 0** for short-lived allocations, **Gen 1** as a buffer, and **Gen 2** for long-lived objects. Surviving objects are promoted. The **Large Object Heap** stores objects typically 85 KB or larger and is collected with Gen 2. `IDisposable` provides deterministic cleanup of unmanaged resources such as file handles, sockets, database connections, and native memory. The GC may eventually finalize objects, but it does not know when OS-level resources should be released, so `Dispose` is needed.

**DN7 — Hard: What is the difference between `ConfigureAwait(false)` and the default behavior? When should you use it, and when should you NOT? How does this relate to `SynchronizationContext`?**  
By default, `await` captures the current `SynchronizationContext` and resumes on it, which is important in UI apps or legacy ASP.NET. `ConfigureAwait(false)` avoids capturing the context and resumes on a thread-pool thread, reducing overhead and avoiding some deadlocks. Use it in library code that does not need the original context. Do not use it when code must interact with UI thread affinity or context-dependent APIs. In ASP.NET Core there is usually no `SynchronizationContext`, so it is less critical but still useful in reusable libraries.

**DN8 — Hard: Explain the new .NET 8/9 features: primary constructors, collection expressions, and `FrozenDictionary`. Write a minimal example using primary constructors with DI.**  
Primary constructors declare parameters directly on the class and make them available throughout the class body. Collection expressions use `[...]` to initialize arrays, lists, spans, and other collections. `FrozenDictionary` is an immutable, read-optimized dictionary created via `ToFrozenDictionary()`.

```csharp
public class OrderService(IOrderRepository repo, ILogger<OrderService> logger)
{
    private static readonly FrozenDictionary<string, decimal> Discounts =
        new Dictionary<string, decimal> { ["VIP"] = 0.10m }
            .ToFrozenDictionary();

    public Task<Order?> GetAsync(int id) => repo.GetAsync(id);

    public decimal GetDiscount(string tier) =>
        Discounts.GetValueOrDefault(tier, 0m);
}

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddScoped<IOrderRepository, SqlOrderRepository>();
builder.Services.AddScoped<OrderService>();

var app = builder.Build();

app.MapGet("/orders/{id}", async (int id, OrderService svc) =>
    await svc.GetAsync(id));
```

**DN9 — Hard: You have a .NET API that works fine under low load but throws `ObjectDisposedException` on the `DbContext` under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core’s `DbContext` lifetime interact with DI scoping?**  
The likely cause is a `DbContext` being shared across concurrent requests or threads, or being disposed while still in use. EF Core `DbContext` is not thread-safe. `AddDbContext` registers `DbContext` as **Scoped** by default, meaning one context per HTTP request scope. If it is registered as Singleton, captured in a Singleton service, used in fire-and-forget tasks, or reused across `Task.WhenAll`, one request may dispose it while another is still using it. Fix: keep `DbContext` scoped, inject it only into scoped/transient services, create a new scope for background work using `IServiceScopeFactory`, and avoid sharing one context across parallel operations.

**DN10 — Medium: What is the difference between `record` and `class` in C#? What about `record struct`? When would you choose each?**  
A `class` is a reference type with identity equality and mutable state by default. A `record` is usually a reference type with value equality, positional syntax, `with` expressions, and immutability-friendly design. A `record struct` is a value type with value equality, no heap allocation, and copy semantics. Use `class` for entities/services with identity and mutation. Use `record` for immutable DTOs, messages, and value-like reference types. Use `record struct` for small immutable value types where you want value semantics and low allocation.

**DN11 — Easy: What is the difference between `ref`, `out`, and `in` parameter modifiers in C#? When would you use each?**  
`ref` passes a variable by reference; the caller must initialize it, and the method can read/write it. `out` also passes by reference, but the method must assign it before returning; the caller does not need to initialize it. `in` passes by reference as read-only, avoiding copying large structs while preventing reassignment of the variable. Use `ref` for bidirectional parameters, `out` for multiple outputs, and `in` for large read-only structs or performance-sensitive APIs.

**DN12 — Easy: Explain nullable reference types in C# (`?` annotation and `#nullable enable`). How do they differ from nullable value types (`int?`)?**  
Nullable reference types are compile-time annotations that warn when a reference may be null. `#nullable enable` turns on nullable analysis for a file or project. They do not change runtime behavior or throw automatically. `int?` is `Nullable<int>`, a real runtime value type with `HasValue` and `Value`. Nullable reference types are metadata and flow-analysis hints; nullable value types are actual runtime containers for optional values.

**DN13 — Easy: What is LINQ? Explain the difference between method syntax and query syntax. What is deferred execution?**  
LINQ is Language Integrated Query, a unified way to query collections, databases, XML, and other data sources. Method syntax uses extension methods like `list.Where(x => x.Age > 18)`. Query syntax uses SQL-like syntax like `from x in list where x.Age > 18 select x`; the compiler translates it to method syntax. Deferred execution means the query is not executed when defined, but when enumerated, e.g. by `foreach`, `ToList()`, or `First()`.

**DN14 — Easy: What are generic constraints in C#? Explain `where T : class`, `where T : struct`, `where T : new()`, and `where T : IComparable<T>`. When would you combine multiple constraints?**  
Generic constraints restrict what types can be used for a type parameter.  
- `where T : class`: reference type.  
- `where T : struct`: non-nullable value type.  
- `where T : new()`: has a public parameterless constructor.  
- `where T : IComparable<T>`: implements `IComparable<T>`.  
Combine constraints when generic code needs multiple capabilities, e.g. `where T : class, new(), IComparable<T>` for a generic factory that creates and sorts objects.

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods change this distinction?**  
An abstract class can contain state, constructors, access modifiers, fields, and partial implementation, but supports only single inheritance. An interface defines a contract and supports multiple inheritance. Before C# 8, interfaces could not contain implementation. Default interface methods allow interfaces to provide default implementations, enabling API evolution and multiple default behaviors. However, interfaces still cannot have instance state or constructors, so abstract classes remain useful for shared state and protected implementation.

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between `app.Use()`, `app.Map()`, and `app.Run()`? How does ordering matter, and how does exception handling middleware work?**  
Middleware are ordered components that process requests and responses. `app.Use()` adds middleware that can call `next` to continue the pipeline. `app.Map()` creates a branch for a path predicate; if matched, the branch runs and does not continue to later outer middleware. `app.Run()` adds terminal middleware that does not call `next`. Ordering matters: first middleware runs first on request and last on response. Exception handling middleware should be early in the pipeline so it can catch exceptions from downstream middleware and endpoints.

**DN17 — Medium: What is `Channel<T>` in .NET? How does it compare to `BlockingCollection<T>`? Give an example of using bounded channels for producer-consumer backpressure.**  
`Channel<T>` is an async-friendly producer-consumer queue. Unlike `BlockingCollection<T>`, which is thread-blocking and less async-native, `Channel<T>` supports `await`-based reads/writes and backpressure.

```csharp
var channel = Channel.CreateBounded<int>(new BoundedChannelOptions(10)
{
    FullMode = BoundedChannelFullMode.Wait
});

await channel.Writer.WriteAsync(42);

await foreach (var item in channel.Reader.ReadAllAsync())
{
    Console.WriteLine(item);
}
```

When the channel is full, `WriteAsync` waits until space is available.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over `ISourceGenerator`?**  
Source generators are Roslyn components that generate C# source code at compile time. Unlike reflection, which runs at runtime and can be slow or incompatible with trimming/AOT, source generators produce normal compile-time code. Unlike IL weaving, which modifies compiled IL, source generators emit readable C# before compilation. An incremental generator, `IIncrementalGenerator`, caches inputs and regenerates only affected outputs, improving IDE responsiveness. `ISourceGenerator` regenerates everything on every change, making it slower.

**DN19 — Hard: What is the `System.Threading.Tasks.Dataflow` library? Explain `ActionBlock`, `TransformBlock`, and `BufferBlock`. How does it compare to `System.Threading.Channels` for pipeline processing?**  
TPL Dataflow builds asynchronous data pipelines using blocks. `ActionBlock<T>` consumes data and performs work. `TransformBlock<TInput, TOutput>` transforms data. `BufferBlock<T>` buffers data, though it is largely legacy compared to `Channel<T>`. Dataflow supports linking, completion propagation, fault propagation, and backpressure. `System.Threading.Channels` is lower-level, simpler, and often preferred for straightforward producer-consumer pipelines. Dataflow is useful for more complex block-based orchestration but can be heavier and more complex.

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**  
Minimal APIs define endpoints directly in `Program.cs` using methods like `MapGet`, `MapPost`, etc. They reduce boilerplate compared to controllers but provide less built-in structure. Middleware works the same way. OpenAPI support exists via built-in or Swashbuckle integration, though controllers often provide richer metadata through attributes. Testability can be slightly less conventional than controller unit tests, but integration testing with `WebApplicationFactory` works well. Route groups organize endpoints:

```csharp
var orders = app.MapGroup("/api/orders")
    .RequireAuthorization()
    .WithTags("Orders");

orders.MapGet("/{id}", async (int id, OrderService svc) => await svc.GetAsync(id));
```

Endpoint filters run per endpoint after routing and can modify requests/responses or short-circuit execution:

```csharp
orders.AddEndpointFilter(async (context, next) =>
{
    var result = await next(context);
    return result;
});
```

## Python

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**  
A `list` is mutable, ordered, and allows duplicates. A `tuple` is immutable, ordered, and allows duplicates. A `set` is mutable, unordered, and contains unique elements. A `frozenset` is immutable, unordered, unique, and hashable, so it can be used as a dictionary key or element of another set.

**P2 — Easy: Explain the GIL. What types of workloads does it affect, and what are the workarounds?**  
The Global Interpreter Lock is a mutex in CPython that allows only one thread to execute Python bytecode at a time. It mainly affects CPU-bound Python code, preventing true parallelism across threads. I/O-bound workloads can still benefit from threads because the GIL is released during many I/O operations. Workarounds include `multiprocessing`, `ProcessPoolExecutor`, C extensions that release the GIL, `asyncio` for I/O concurrency, and experimental free-threaded Python builds.

**P3 — Medium: What is the difference between `deepcopy` and `copy`? Give an example where shallow copy causes unexpected behavior.**  
`copy.copy()` creates a shallow copy: the outer container is new, but nested objects are shared. `copy.deepcopy()` recursively copies nested objects.

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.copy(a)
b[0][0] = 99

print(a[0][0])  # 99
```

The inner list is shared, so modifying `b` affects `a`.

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**  
A decorator is a function that takes a function and returns a wrapped function. It is syntactic sugar for `func = decorator(func)`.

```python
import functools
import time

def log_time(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{func.__name__} took {elapsed:.4f}s")
        return result
    return wrapper

@log_time
def add(a, b):
    return a + b
```

**P5 — Medium: What are generators and `yield`? How do they differ from returning a list? What is `yield from`?**  
A generator is a function containing `yield`. Calling it returns an iterator that produces values lazily. Unlike returning a list, generators do not build the entire sequence in memory and can represent infinite streams. `yield from` delegates to another iterable or generator, forwarding values, sent values, and exceptions cleanly.

```python
def numbers():
    yield 1
    yield from [2, 3]
```

**P6 — Medium: Explain Python’s asyncio event loop. What is the difference between `asyncio.run()`, `asyncio.gather()`, and `asyncio.create_task()`? Why can’t you call `time.sleep()` inside an async function?**  
The asyncio event loop schedules coroutines and non-blocking I/O on a single thread. `asyncio.run()` creates an event loop, runs a coroutine, and closes the loop. `asyncio.gather()` runs multiple coroutines concurrently and collects results. `asyncio.create_task()` schedules a coroutine as a `Task` immediately. `time.sleep()` blocks the entire event loop; use `await asyncio.sleep()` instead.

**P7 — Hard: Explain Python’s MRO. What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**  
Python 3 uses C3 linearization to compute the Method Resolution Order. It preserves local precedence order and produces a consistent linear order.

```python
class A:
    def who(self): return "A"
class B(A):
    pass
class C(A):
    def who(self): return "C"
class D(B, C):
    pass
print(D().who())
```

`D.__mro__` is `D, B, C, A, object`. `B` does not define `who`, so lookup continues to `C`, which defines `who`. Therefore it prints `C`.

**P8 — Hard: What is a metaclass? When would you use `__init_subclass__` vs a metaclass? Give a practical use case for each.**  
A metaclass is the class of a class; it controls class creation. `__init_subclass__` is a simpler hook called when a subclass is created. Use `__init_subclass__` for simple subclass registration or validation. Use a metaclass for complex class creation, customizing `type`, intercepting all class creation, or implementing advanced frameworks.

```python
class Plugin:
    registry = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Plugin.registry[cls.__name__] = cls
```

Metaclass example: singleton enforcement.

**P9 — Hard: Explain the difference between `multiprocessing`, `threading`, and `concurrent.futures` in Python. When would you use each? What are the serialization implications of multiprocessing?**  
`threading` uses threads and is useful for I/O-bound work or C extensions that release the GIL. `multiprocessing` uses separate processes and is useful for CPU-bound Python code because it bypasses the GIL. `concurrent.futures` provides a high-level `Executor` API, with `ThreadPoolExecutor` and `ProcessPoolExecutor`. Multiprocessing communicates between processes by pickling arguments and results, so objects must be picklable. Lambdas, local functions, open files, sockets, and some objects may not pickle.

**P10 — Medium: What is `__slots__`? When should you use it, and what does it prevent? What is the memory impact?**  
`__slots__` declares a fixed set of instance attributes, preventing the creation of a per-instance `__dict__`. It reduces memory usage and can speed up attribute access. It prevents adding arbitrary attributes dynamically unless `__dict__` is included. It can also prevent weak references unless `__weakref__` is included. Use it for many instances of simple classes where memory matters.

**P11 — Easy: What is a virtual environment, and why should you use one? What is the difference between `venv`, `virtualenv`, and `conda`?**  
A virtual environment isolates Python packages and dependencies for a project. It prevents conflicts between projects and system packages. `venv` is the standard library tool. `virtualenv` is a third-party tool with more features and broader compatibility. `conda` manages environments, Python versions, and non-Python dependencies, often used in data science.

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to `map()` and `filter()`? When would you prefer one over the other?**  
Comprehensions create collections from iterables with optional conditions:

```python
squares = [x * x for x in range(5)]
mapping = {x: x * x for x in range(5)}
unique = {x % 3 for x in range(10)}
```

`map()` applies a function to each item; `filter()` selects items. In Python 3, `map` and `filter` return lazy iterators. Comprehensions are often more readable for expressions and conditions; `map`/`filter` can be cleaner when using existing functions or building lazy pipelines.

**P13 — Easy: What is the difference between `==` and `is` in Python? What is object interning, and why does `a is b` sometimes return `True` for small integers?**  
`==` checks value equality. `is` checks identity, whether two names refer to the same object. CPython interns some objects, including small integers typically from `-5` to `256` and some strings, so equal small integers may be the same object. Do not rely on `is` for equality except for `None`, `True`, `False`, or sentinel objects.

**P14 — Easy: Explain Python’s `*args` and `**kwargs`. How do positional-only (`/`) and keyword-only (`*`) parameter markers work in function signatures?**  
`*args` collects extra positional arguments into a tuple. `**kwargs` collects extra keyword arguments into a dictionary. Parameters before `/` are positional-only. Parameters after `*` are keyword-only.

```python
def f(a, /, b, *, c):
    pass

f(1, 2, c=3)
```

`a` must be positional, `b` can be positional or keyword, and `c` must be keyword.

**P15 — Easy: What are context managers (`with` statement)? How do you write one using `__enter__`/`__exit__` vs `@contextmanager`? Give an example beyond file handling.**  
Context managers manage setup and teardown. `__enter__` returns the resource; `__exit__` handles cleanup and exceptions. `@contextmanager` uses a generator: code before `yield` is setup, code after is cleanup.

```python
from contextlib import contextmanager

@contextmanager
def transaction(conn):
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
```

**P16 — Medium: What is type hinting in Python? Explain `typing.Union`, `Optional`, `Literal`, `TypeVar`, and `Protocol`. How does mypy or pyright use these for static analysis?**  
Type hints annotate expected types but are not enforced at runtime. `Union[X, Y]` or `X | Y` means either type. `Optional[X]` means `X | None`. `Literal["a", "b"]` restricts values to specific literals. `TypeVar` defines generic type variables. `Protocol` defines structural typing, where objects match by behavior rather than inheritance. Tools like mypy and pyright use hints to infer types and detect mismatches statically.

**P17 — Medium: Explain Python’s data model. What are `__repr__` vs `__str__`, `__eq__` vs `__hash__`, and `__getattr__` vs `__getattribute__`? What happens if you define `__eq__` but not `__hash__`?**  
`__repr__` is an unambiguous developer representation; `__str__` is a user-friendly string. If `__str__` is missing, Python falls back to `__repr__`. `__eq__` defines equality; `__hash__` defines hashability. If you define `__eq__` but not `__hash__`, Python sets `__hash__ = None`, making instances unhashable. `__getattr__` is called only when normal attribute lookup fails. `__getattribute__` is called for every attribute access and should be overridden carefully.

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (`__get__`, `__set__`, `__delete__`). How do `property`, `classmethod`, and `staticmethod` use descriptors under the hood?**  
A descriptor is an object that controls attribute access by defining `__get__`, `__set__`, and/or `__delete__`. Data descriptors with `__set__` or `__delete__` take precedence over instance `__dict__`. `property` is a data descriptor implementing getter/setter/deleter behavior. `classmethod` is a descriptor that returns a method bound to the class. `staticmethod` is a descriptor that returns the underlying function without binding.

**P19 — Hard: Explain Python’s import system in detail. What is the difference between relative and absolute imports? How does `sys.path`, `PYTHONPATH`, `__init__.py`, and namespace packages work? What is a finder and a loader?**  
Python imports use `sys.modules` as a cache. If not cached, finders on `sys.meta_path` locate a module spec, and loaders execute the module. `sys.path` lists directories searched by `PathFinder`; `PYTHONPATH` adds entries to `sys.path`. Absolute imports start from top-level packages/modules. Relative imports use dots within a package. `__init__.py` marks a regular package. Namespace packages have no `__init__.py` and can span multiple directories. A finder locates a module; a loader loads/executes it.

**P20 — Hard: What are `dataclasses` and how does it compare to `attrs` and Pydantic? Explain `__post_init__`, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**  
`dataclasses` generate common methods like `__init__`, `__repr__`, and `__eq__`. `attrs` is similar but historically richer, with validators, converters, and less boilerplate. Pydantic adds runtime validation, coercion, and serialization. `__post_init__` runs after generated `__init__`. Mutable defaults require factories:

```python
from dataclasses import dataclass, field

@dataclass(frozen=True)
class Config:
    tags: list[str] = field(default_factory=list)
```

`frozen=True` makes instances immutable. Inheritance collects fields from base classes, and default ordering rules apply. Choose Pydantic when validating external input, JSON APIs, or enforcing runtime constraints; choose dataclasses for lightweight internal structures.
