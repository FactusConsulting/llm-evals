## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but in a "Temporal Dead Zone" (TDZ) until declaration. `const` prevents reassignment but allows mutation of objects/arrays. **Hoisting** is the JS engine's behavior of moving declarations to the top of their scope during the compilation phase.

**JS2** — The **Event Loop** manages execution. The **Call Stack** handles synchronous code. When an async operation completes, its callback enters a queue. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority; the loop clears it entirely before moving to the **Macrotask Queue** (setTimeout, I/O).

**JS3** — A **Closure** is a function bundled with its lexical environment. Example: A counter function returning an incrementer. **Classic bug**: Using `var` in a loop with async calls (all share the same final value). **Fix**: Use `let` (block scoping) or an IIFE.

**JS4** — **Promise** represents a future value. **Async/await** is syntactic sugar over Promises. Errors are caught via `.catch()` or `try/catch`. **Promise.all** rejects if *any* fail; **Promise.allSettled** waits for all to finish regardless of success/failure.

**JS5** — **Interface** is for defining shapes (structural); **Type** is for aliases and unions. Use `interface` for public APIs/objects (supports declaration merging) and `type` for complex logic/unions. **Discriminated Unions** use a common literal property (e.g., `type: 'success'`) to allow exhaustive type narrowing.

**JS6** — **Prototypal Inheritance**: Objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with a specific prototype. **ES6 Classes** are "syntactic sugar" over prototypes; they don't change the underlying inheritance model but provide a cleaner syntax.

**JS7** — `this` binding priority: 1. `new` binding, 2. `call/apply/bind`, 3. Implicit (object before dot), 4. Default (global/undefined). `bind()` returns a *new* function with a fixed `this`; it cannot be re-bound.

**JS8** — **WeakRef** allows holding a reference to an object without preventing GC. **FinalizationRegistry** allows executing a callback when an object is GC'd. **WeakMap** keys must be objects because they are held weakly; if the only reference to a key is in the WeakMap, the GC can reclaim it, preventing memory leaks.

**JS9** — V8 uses **Hidden Classes** (shapes) to track object properties and **Inline Caching** to skip lookups for stable shapes. **Deoptimization** occurs when shapes change (e.g., adding properties in different orders, changing types of variables). Patterns: Dynamic property addition, `arguments` object usage, and "megamorphic" call sites.

**JS10** — **Tree-shaking** removes unused code. **ESM** is static (imports are at top-level), allowing the bundler to know what's used without running code. **CommonJS** is dynamic (`require` can be inside `if`), making it impossible to determine dead code statically.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable hasn't been assigned. `null == undefined` is true; `null === undefined` is false. **Nullish coalescing (`??`)** returns right side only if left is `null/undefined`. **Optional chaining (`?.`)** short-circuits if the left side is `null/undefined`.

**JS12** — `map`: returns new array with transformed elements. `filter`: returns elements passing a predicate. `reduce`: accumulates values (initial value defines starting point). `flatMap`: maps then flattens one level deep (useful for filtering and mapping simultaneously).

**JS13** — **Template Literals** use backticks (`` ` ``) for interpolation `${}`. **Tagged Templates** allow a function to parse the template. Example: `sql`tag`SELECT * FROM users WHERE id = ${id}` where the function escapes `id`.

**JS14** — **Destructuring** extracts values into variables. Object: `{a, b} = obj`. Array: `[x, y] = arr`. **Default values**: `[x = 0]`. **Renaming**: `{a: renamed} = obj`. **Rest (`...`)**: Collects remaining elements into a new array/object.

**JS15** — `for...in` iterates over enumerable **keys** (properties). `for...of` iterates over **values** (iterable). Avoid `for...in` on arrays because it includes inherited properties and non-index keys.

**JS16** — **Generics** allow reusable types. **Constraints** (`<T extends string>`) limit types. **Conditional Types** (`T extends U ? X : Y`) act like ternary operators for types. **Infer** extracts types from expressions. Example: `type Unpacked<T> = T extends Array<infer U> ? U : T`.

**JS17** — **CommonJS** is synchronous (Node default). **ESM** is asynchronous/static. Node handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM. ESM uses `import/export`, CJS uses `require/module.exports`.

**JS18** — **Structural typing** means if it looks like a duck, it is a duck. **Excess property checks** only apply to object literals, not variables. **Extends** is for inheritance; **Satisfies** checks if an object matches a type without widening the type. **Variance** defines how subtyping of complex types (like functions) relates to subtyping of their inputs/outputs.

**JS19** — **Proxy** intercepts operations (get, set, etc.). **Reflect** provides the underlying methods to perform those operations. Example: A Proxy to validate that a `user` object only accepts numeric `age` values.

**JS20** — **SharedArrayBuffer** allows multiple threads (Web Workers) to share the same memory. **Atomics** provides thread-safe operations (add, load, wait). `Atomics.wait` puts a thread to sleep until `Atomics.notify` wakes it, preventing race conditions.

## Bash

**B1** — `$*` expands to a single string (all arguments joined by space). `$@` expands to separate words. `"$*"` is one string; `"$@"` is separate quoted strings (the standard for safe iteration).

**B2** — `-e`: Exit on error. `-u`: Exit if variable is unset. `-o pipefail`: Exit if any command in a pipeline fails.

**B3** — `$(command)` is command substitution (returns output). `` `command` `` is the deprecated version. `$((expression))` is for integer arithmetic. `expr` is an external command for arithmetic (legacy).

**B4** — **Process substitution** `<(command)` makes the output of a command look like a file. Example: `diff <(ls dir1) <(ls dir2)`.

**B5** — Use `find . -name "*.txt" -print0 | while IFS= read -r -d '' file; do ... done`. `for f in $(ls)` fails because `ls` splits on spaces, breaking filenames like "My File.txt".

**B6** — `<<EOF` is a **Here Document** (multi-line input). `<<<` is a **Here String** (single line). `<<-EOF` ignores leading tabs (but not spaces).

**B7** — `> file 2>&1`: Redirects stdout to file, then redirects stderr to the same place as stdout. `2>&1 > file`: Redirects stderr to stdout (still going to terminal), then redirects stdout to file (stderr stays on terminal). `&> file`: Bash shorthand for both.

**B8** — `mkdir /tmp/lock_dir 2>/dev/null && echo $$ > /tmp/lock_dir/pid`. Use `trap 'rm -rf /tmp/lock_dir' EXIT` for cleanup. `mkdir` is atomic at the OS level; file creation is not (two processes can create the same file simultaneously).

**B9** — `'...'`: Literal (no expansion). `"..."`: Interpolated (expands `$`, `` ` ``, `\`). No quotes: Word splitting and globbing occur. Example: `echo "Hello $USER"` vs `echo 'Hello $USER'`.

**B10** — `-e $file` (exists), `-d $file` (directory), `-r $file` (readable). `[ ]` is the standard test command; `[[ ]]` is a Bash keyword that supports regex, logical operators, and doesn't split variables.

**B11** — `$?`: Exit code of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: Number of arguments passed to script.

**B12** — `foo() { ...; }` is standard. `function foo {}` is also valid but slightly different in some shells. Return values: Bash functions don't return values like JS; they return exit codes (0-255). To "return" data, use `echo` and capture with `result=$(foo)`.

**B13** — `PATH` is a colon-separated list of directories. Bash searches them in order. **Builtin**: executed by the shell (e.g., `cd`). **External**: separate binary (e.g., `/bin/ls`). Check with `type command`.

**B14** — `trap` catches signals. `trap 'cleanup' EXIT` (script ends), `ERR` (non-zero exit), `INT` (Ctrl+C), `TERM` (kill). If multiple signals arrive, they are queued; traps execute in the order they were defined or as signals are processed.

**B15** — `xargs` builds commands from input. Command substitution `$(...)` runs one command. `find ... -print0 | xargs -0` handles spaces/newlines. `xargs -P` runs jobs in parallel.

**B16** — `arr=(a b c)` (Array). `declare -A map` (Associative). Append: `arr+=("d")`. Iterate: `for i in "${arr[@]}"; do ...`. Length: `${#arr[@]}`. Associative arrays require keys and values.

**B17** — `(...)` is a **subshell** (new PID, variables lost). `{ ...; }` is a **group command** (same PID, variables preserved). Piping `ls | while read line; do var=1; done` loses `var` because the `while` loop runs in a subshell.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (Default kill), `SIGHUP` (Terminal closed), `SIGKILL` (Unstoppable). Use `trap` to catch `TERM` and `INT` to send `kill` signals to background PIDs stored in an array.

**B19** — `split -l 1000 log.txt` -> `xargs -P 4 -I {} ./process_chunk.sh {}` -> `cat results_*.txt > final.txt`. Trade-off: Parallelism increases speed but makes error handling harder (need to check exit codes of all PIDs).

**B20** — `exec` replaces the current shell process with the command. `exec 3>file` opens a file descriptor. `exec 3>&-` closes it. **Coprocess** (`coproc`) allows two-way communication between a background process and the shell.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline. `Write-Host` sends text directly to the console. Using `Write-Host` inside a function breaks pipeline processing.

**PS2** — **Pipeline**: Streams objects. `ForEach-Object` (Cmdlet) processes one by one in the pipeline. `foreach` (Statement) iterates over a collection in memory. Use `ForEach-Object` for large streams; `foreach` for speed on small collections.

**PS3** — `[PSCustomObject]` is a structured object with properties (best for pipelines). `[hashtable]` is a key-value collection (best for lookups). Convert: `[PSCustomObject]$obj = $hash`.

**PS4** — **Terminating**: Stops script (e.g., `Stop-Process` on non-existent PID). **Non-terminating**: Continues (e.g., `Get-ChildItem` on restricted folder). `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors.

**PS5** — **Splatting** passes a hashtable as parameters: `Get-ChildItem @params`. It improves readability and allows dynamic parameter construction. Passing a hashtable as a single parameter would treat the whole hash as one value.

**PS6** — `Invoke-Command` is one-to-many (remote execution). `Enter-PSSession` is interactive (remote shell). Uses **WinRM** (HTTP/HTTPS) or **SSH**.

**PS7** — PowerShell's pipeline often converts types to `System.Object`. If a function returns an array, but only one item is returned, it might be unrolled. The correct pattern is to ensure the function always returns an array: `[array]$result = @()`.

**PS8** — **Scriptblock** is a block of code; **Function** is a named, reusable entity. Pass scriptblocks via `Invoke-Command -ScriptBlock`. **Double-hop**: Client -> Server A -> Server B (credentials lost). Solve with **CredSSP** or passing credentials explicitly.

**PS9** — `@()` is an array literal. `[array]` is a type accelerator. To force a single result into an array: `$x = @($result)`. Indexing `$null` returns `$null`; indexing an empty array ` @() ` returns `$null`.

**PS10** — `-eq` (case-insensitive), `-ceq` (case-sensitive). `-like` uses wildcards (`*`). `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection.

**PS11** — **Module**: A collection of cmdlets. `.psm1` (Script module), `.psd1` (Manifest - metadata/dependencies), **Binary** (compiled DLLs). `Import-Module` loads them into the session.

**PS12** — `"Hello $Name"` interpolates variables. `'Hello $Name'` is literal. `$(Get-Date)` interpolates expressions. **Here-string**: `@ " ... "@` for multi-line strings.

**PS13** — `Get-Member` shows properties/methods. **Properties** (data), **Methods** (actions), **NoteProperties** (metadata). `Select-Object` picks properties; `Where-Object` filters rows.

**PS14** — **Classes** (v5+) are C#-like types with strict schemas. They differ from C# by lacking full inheritance/interfaces in some contexts. Use **Classes** for complex data models; **Functions** for actions.

**PS15** — `[CmdletBinding()]` adds standard parameters (`-Verbose`, `-WhatIf`). `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` blocks allow processing items as they arrive in the pipeline.

**PS16** — **Providers** allow uniform access to different data sources. `Get-ChildItem` works on `FileSystem:`, `Registry::HKEY_LOCAL_MACHINE`, `Cert:`, and `Env:`. Access registry like a file system using `cd Registry::HKEY_LOCAL_MACHINE`.

**PS17** — **Runspaces** are lightweight threads for PowerShell. `[runspacepool]` manages multiple runspaces. `ForEach-Object -Parallel` (v7+) is a wrapper around runspaces. Manual management is needed for complex state sharing.

**PS18** — **PSScriptAnalyzer** is a static analysis tool. It checks for best practices (e.g., "no `Write-Host`"). Rules have severities (Warning, Error). Suppress via `#psanalyzer:ignore`. Integrate into CI/CD via `Invoke-ScriptAnalyzer`.

**PS19** — `$using:` is for passing variables into remote sessions/jobs. `-ArgumentList` is for passing variables to `Invoke-Command`. **CLIXML depth** limits how complex an object can be serialized for transport.

**PS20** — **DSC** is declarative configuration (Define "what", not "how"). **Resources** are the building blocks. **LCM** is the engine that enforces state. In modern infra, **Terraform** or **Ansible** have largely replaced DSC for multi-platform use.
