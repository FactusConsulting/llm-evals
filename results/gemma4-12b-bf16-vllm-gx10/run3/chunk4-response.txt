## Go

**G1 — Easy:** An array has a fixed size defined at compile time; a slice is a descriptor (header) containing a pointer to an underlying array, a length, and a capacity. When a slice reaches capacity during an `append`, Go allocates a new, larger underlying array, copies the existing elements, and returns a new slice header.

**G2 — Easy:** `var x int` declares a variable with the zero value (0) and can be used at the package level. `x := 0` is a short variable declaration that declares and initializes a variable within a function body. You cannot use `:=` at the package level or if the variable has already been declared in the same scope.

**G3 — Medium:** A goroutine is a lightweight thread managed by the Go runtime, not the OS. They have smaller stacks (starting at ~2KB) and faster context switching. The GMP model consists of **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts). **P** schedules **G**s onto **M**s, allowing for efficient work stealing and multi-core utilization.

**G4 — Medium:** Channels are typed conduits for communication. Unbuffered channels require both sender and receiver to be ready simultaneously (blocking). Buffered channels allow sending until the buffer is full. Sending to a full buffered channel blocks the goroutine until a receiver consumes an element.

**G5 — Medium:** The `context` package handles deadlines, cancellation signals, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
```

**G6 — Medium:** Go uses "implicit" satisfaction: a type satisfies an interface simply by implementing its methods (no `implements` keyword). Java/C# require explicit declaration. `interface{}` (or `any`) can hold any value, making it powerful for generic-like behavior but dangerous because it bypasses type safety, requiring type assertions or reflection.

**G7 — Hard:** The Go memory model does not guarantee that writes in one goroutine are visible to another without explicit synchronization (happens-before relationship). The example is unsafe because the CPU or compiler might reorder the `ready = true` write before the `data` write, or the loop might not see the updated `ready` value. **Fix:** Use `sync.WaitGroup`, `sync.Mutex`, or an atomic variable/channel.

**G8 — Hard:** `sync.Mutex` is exclusive; `sync.RWMutex` allows multiple concurrent readers OR one writer. Use `sync.Map` for high-concurrency scenarios with stable keys and frequent updates/reads (it optimizes for cache contention). A `map` + `Mutex` is usually faster for low-contention or write-heavy workloads.

**G9 — Hard:** `go.mod` defines the module path and dependencies; `go.sum` contains cryptographic hashes of dependencies to ensure integrity. `go mod tidy` removes unused and adds missing modules. **MVS** (Minimum Version Selection) selects the highest minimum version of a dependency required by the graph, rather than the "latest" version.

**G10 — Medium:** `defer` schedules a function call to run immediately before the surrounding function returns. They execute in LIFO (Last-In, First-Out) order. **Gotcha:** In a loop, `defer` statements accumulate and only run when the *function* returns, not the loop iteration, potentially causing memory leaks or delayed execution.

**G11 — Easy:** A pointer holds the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `p := &Struct{Field: 1}`.

**G12 — Easy:** `init()` runs automatically after package variables are initialized but before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source files (lexical order).

**G13 — Easy:** `new(T)` allocates memory for a type `T`, zeros it, and returns a pointer `*T`. `make(T)` initializes and returns an actual value of type `T` (only for slices, maps, and channels).

**G14 — Easy:** Errors are values implementing the `error` interface (`Error() string`). Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks for a specific error instance (wrapped), while `errors.As` checks if an error can be cast to a specific type. `==` only works for simple equality.

**G15 — Easy:**
- Map: `map[K]V` (zero: `nil`)
- Slice: `[]T` (zero: `nil`)
- Channel: `chan T` (zero: `nil`)
- Struct: `struct{...}` (zero: all fields zeroed)

**G16 — Medium:** A race condition occurs when two goroutines access the same memory concurrently and at least one is a write. The `-race` flag uses instrumentation to detect unsynchronized access. **Fix:** Use `sync.Mutex` to lock the critical section or use a channel to pass ownership of the data.

**G17 — Medium:** `select` blocks until one of its cases can proceed (similar to a switch but for channel operations). If multiple cases are ready, one is chosen pseudo-randomly. Timeout: `case <-time.After(1 * time.Second):`.

**G18 — Hard:** Escape analysis determines if a variable can be allocated on the stack (fast, automatic cleanup) or must "escape" to the heap (slower, GC managed). It escapes if it's returned as a pointer, captured by a closure, or is too large. Inspect via `go build -gcflags="-m"`. It matters because heap allocations increase GC pressure.

**G19 — Hard:** `reflect.Type` describes the structure (name, fields); `reflect.Value` holds the actual data. Reflection is slow because it involves dynamic type checking and heap allocations. Use it for generic libraries (JSON encoders, ORMs); otherwise, use code generation (e.g., `protoc`) for better performance.

**G20 — Hard:** `go:embed` allows compiling static files into the binary. It works for files and directories (via `//go:embed dir/*`). It produces a `embed.FS` or `embed.TS` (Text). It interacts with `io/fs.FS` to provide a standard interface for reading embedded content.

## Rust

**R1 — Easy:** Ownership is the system where each value has a single owner. Rules: 1. Each value has a variable called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2 — Easy:** `String` is an owned, heap-allocated string (growable). `&str` is an immutable reference (a "slice" of a string). Use `String` when you need to own/mutate data; use `&str` for function arguments to accept both `String` and literals.

**R3 — Medium:** Borrowing allows using a value without taking ownership. **Rules:** 1. You can have either one mutable reference (`&mut T`) OR any number of immutable references (`&T`) at a time. 2. References must always be valid (no dangling pointers).

**R4 — Medium:** `Option<T>` handles the presence/absence of a value (`Some` or `None`). `Result<T, E>` handles success/failure (`Ok` or `Err`). The `?` operator returns the error early if it occurs.
```rust
fn read_file(path: &str) -> std::io::Result<String> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5 — Medium:** `Box<T>` is a heap-allocated pointer (single ownership). `Rc<T>` is a reference-counted pointer (multiple owners, single-threaded). `Arc<T>` is an atomic reference-counted pointer (multiple owners, multi-threaded).

**R6 — Medium:** Traits define shared behavior (similar to Go interfaces). `dyn Trait` is a trait object (dynamic dispatch via vtable). `T: Trait` is a generic with a trait bound (static dispatch via monomorphization).

**R7 — Hard:** Lifetimes ensure references don't outlive their data. The example fails because the compiler doesn't know if the returned `&str` comes from `x` or `y`. **Fix:** Add a lifetime parameter: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8 — Hard:** `Send` means a type can be transferred between threads; `Sync` means it can be shared between threads. `Rc<T>` is not `Send` because its reference count is not atomic (data race risk). `Arc<T>` uses atomic operations to update the count safely.

**R9 — Hard:** Rust's `async` is "lazy." A `Future` is a state machine that does nothing until polled. The executor (Tokio) manages the polling. Unlike Go's goroutines (preemptive, managed by runtime), Rust's async is cooperative and zero-cost (no extra stack per future).

**R10 — Medium:** `unsafe` allows actions the compiler cannot guarantee are safe. 3 things: Dereferencing raw pointers, calling unsafe C functions, and accessing mutable statics. Justified for low-level hardware access, FFI, or high-performance data structures.

**R11 — Easy:** `match` is an expression that checks a value against patterns; `if let` is a concise way to handle only one specific pattern. `match` must be exhaustive (all possible cases must be covered).

**R12 — Easy:** `Vec<T>` is a growable heap-allocated array; `[T; N]` is a fixed-size stack-allocated array. When `Vec` exceeds capacity, it reallocates a larger block of memory and moves elements.

**R13 — Easy:** Rust enums are "sum types" (can hold data), unlike C/Java enums which are just named integers. `Option<T>` is an enum (`Some(T)` or `None`). Rust lacks `null` to prevent null pointer exceptions at compile time.

**R14 — Easy:** `impl` defines methods for a type. `&self` borrows the instance (read-only), `&mut self` borrows mutably, and `self` consumes the instance (moves it). Associated functions (no `self`) are like static methods.

**R15 — Easy:** `derive` automatically implements traits. Common: `Debug` (printing), `Clone` (deep copy), `PartialEq` (comparison), `Serialize` (JSON/Binary). You cannot derive traits that require manual implementation or are not provided by the macro system.

**R16 — Medium:** `Cow<'a, T>` is "Clone on Write." It allows you to return either a borrowed `&T` or an owned `T`. It avoids allocating a new `String` if the data doesn't need modification, but provides an owned version if it does.

**R17 — Medium:** `mod` declares a module; `use` brings it into scope; `pub` makes it accessible to others. In 2018 edition, modules can be declared in the same file as their contents, and `pub use` (re-exporting) is more flexible.

**R18 — Hard:** `Pin<T>` ensures that a value cannot be moved in memory. This is required for `async` blocks because they may contain self-referential pointers (pointers to other fields within the same future). `Unpin` is a marker trait for types that are safe to move even when pinned.

**R19 — Hard:** `macro_rules!` is a declarative macro (pattern matching). Procedural macros (derive, attribute, function-like) are essentially functions that run during compilation to generate code. Hygiene ensures that macro-generated identifiers don't accidentally clash with local variables.

**R20 — Hard:** Zero-cost abstractions mean you don't pay for what you don't use. **Iterators** compile down to loops; **Generics** use monomorphization (generating specific code for each type at compile time); **Trait static dispatch** allows the compiler to inline calls, achieving C-level performance with high-level syntax.
