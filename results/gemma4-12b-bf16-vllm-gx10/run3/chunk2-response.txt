## Kubernetes

**K1** — A **Deployment** manages stateless pods where any pod can replace another (identical replicas). A **StatefulSet** manages stateful pods where each pod has a unique, persistent identity (e.g., `web-0`, `web-1`) and a stable network ID/persistent storage mapping.

**K2** — A **ClusterIP** Service provides a stable internal IP. It uses `kube-proxy` (via iptables or IPVS) to intercept traffic to that IP and load-balance it across the backend Pod IPs listed in the Service's **Endpoints** object.

**K3** — **PersistentVolume (PV)** is a piece of storage provisioned by an admin. **PersistentVolumeClaim (PVC)** is a request for storage by a user. **StorageClass** is a blueprint for dynamic provisioning. **Relationship:** A user creates a PVC; the cluster uses a StorageClass to automatically create a PV that satisfies that PVC.

**K4** — 1. `kubectl logs <pod>` to check application errors. 2. `kubectl describe pod <pod>` to check events (OOMKilled, Liveness probe failures). 3. Check resource limits/requests vs. node capacity. 4. Verify environment variables, secrets, and configmap mounts.

**K5** — **CoreDNS** is the cluster's internal DNS server, resolving service names (e.g., `my-svc.default.svc.cluster.local`). If CoreDNS pods are down, pods cannot resolve internal or external hostnames, causing connection failures.

**K6** — The scheduler uses two phases: **Filtering** (predicates) to remove nodes that don't meet requirements (e.g., insufficient CPU, taints), and **Scoring** (priorities) to rank remaining nodes. **Factors:** Resource requests (CPU/RAM), Node Affinity, Taints/Tolerations, and Pod Topology Spread Constraints.

**K7** — **Scheduled?** Yes. The node has 4GB (4096Mi) total. 3.5GB is requested, leaving ~512Mi available. The pod requests 256Mi, which fits. **Runtime?** If it uses 600Mi, it exceeds its 512Mi limit and will be **OOMKilled** by the kernel.

**K8** — 1. External LB receives traffic $\rightarrow$ 2. Ingress Controller (NGINX) receives it $\rightarrow$ 3. NGINX matches Host/Path rules $\rightarrow$ 4. NGINX looks up Service $\rightarrow$ 5. `kube-proxy` (iptables/IPVS) routes traffic to a specific Pod IP $\rightarrow$ 6. Pod processes request.

**K9** — A **NetworkPolicy** is a firewall for pods. **Default behavior:** If no policy exists, all ingress/egress is allowed. **Applied policy:** If you apply a policy selecting specific pods, those pods become "isolated"—only traffic explicitly allowed by the policy is permitted.

**K10** — **RollingUpdate** replaces pods one-by-one (zero downtime). **Recreate** kills all old pods before starting new ones (downtime). **Choose Recreate** when the application does not support running two versions simultaneously (e.g., a database schema change that is not backward compatible).

**K11** — A **Namespace** is a virtual cluster for isolating resources. **Default namespaces:** `default`, `kube-system`, `kube-public`, and `kube-default` (depending on the distribution).

**K12** — `kubectl describe` shows detailed metadata and status. **3 items:** Events (e.g., "Failed to pull image"), Container Status (Restart counts, exit codes), and Node/Volume details.

**K13** — A **ConfigMap** stores non-confidential key-value pairs. **Methods:** 1. Environment variables (via `envFrom`). 2. Mounted as files in a volume (via `volumeMounts`).

**K14** — **ClusterIP:** Internal only. **NodePort:** Exposes service on a specific port on every Node's IP. **LoadBalancer:** Provisions a cloud provider's external LB to route traffic to the NodePort/ClusterIP.

**K15** — A **DaemonSet** ensures that all (or some) nodes run exactly one copy of a pod. **Use case:** Logging agents (Fluentd), monitoring agents (Prometheus Node Exporter), or networking plugins (Calico).

**K16** — **Taints** are on Nodes (repel pods); **Tolerations** are on Pods (allow them to stay on tainted nodes). **Node Affinity** is on Pods (attract pods to specific nodes). **Use case:** Taints for GPU nodes (only allow GPU pods); Affinity for "Data-locality" (ensure pods run in the same zone as storage).

**K17** — An **Operator** is a custom controller that uses **CRDs** (Custom Resource Definitions) to manage complex applications. It differs by encoding "human operational knowledge" (e.g., how to backup a DB, how to scale a cluster) into code. It solves the problem of manual, complex lifecycle management.

**K18** — **etcd** uses the **Raft** consensus algorithm (Strong Consistency). If **quorum** is lost (e.g., 2/3 nodes down), the cluster becomes read-only/unavailable for writes. **Recovery:** Replace the 2 lost nodes with new ones, then perform a `snapshot restore` or `member add` to re-sync the state.

**K19** — **Role:** Permissions in a namespace. **ClusterRole:** Permissions cluster-wide. **RoleBinding:** Links Role to User/ServiceAccount in a namespace. **ClusterRoleBinding:** Links ClusterRole to User/ServiceAccount cluster-wide.
**Manifests:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: my-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: my-ns
subjects:
- kind: User
  name: developer-user
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — `ndots:5` causes the resolver to try many search paths (e.g., `google.com.default.svc.cluster.local`) before trying the actual domain. This creates $N$ failed queries for every 1 success. **Fix:** Set `dnsConfig.options` to `["timeout=2"]` or, preferably, set `ndots:1` in the pod spec to stop the search path logic for external domains.

## Development

**D1** — **Merge** combines histories with a "merge commit." **Rebase** rewrites history by moving the base of your branch to the tip of the target branch. **Avoid rebasing** on public/shared branches because it rewrites history and causes conflicts for others.

**D2** — **TCP:** Connection-oriented, reliable (e.g., HTTP, SSH). **UDP:** Connectionless, fast, "fire and forget" (e.g., DNS, VoIP).

**D3** — A **race condition** occurs when the output depends on the timing of uncontrollable events. **Example:** Two threads incrementing a shared variable `count++` simultaneously; both read `5`, both increment to `6`, and write `6` back, losing one increment.

**D4** — **Symmetric:** Same key for encryption/decryption (fast). **Asymmetric:** Public key encrypts, Private key decrypts (secure key exchange). **TLS:** Uses Asymmetric to exchange a "session key," then uses Symmetric for the actual data transfer.

**D5** — A **layer** is a read-only filesystem change. **Caching:** Docker reuses layers. **Best Practice:** Put frequently changing lines (like `COPY . .`) at the bottom of the Dockerfile so that changes don't invalidate the cache for preceding layers (like `apt-get install`).

**D6** — 1. Check Application Logs (errors/exceptions). 2. Check Resource Usage (CPU/Memory/DB connections). 3. Check Downstream Dependencies (DB, 3rd party APIs). 4. Check Network/Load Balancer health.

**D7** — **CAP:** Consistency, Availability, Partition Tolerance. **CP (Consistency/Partition):** MongoDB or etcd (rejects writes if they can't be synced). **AP (Availability/Partition):** Cassandra or DynamoDB (accepts writes, resolves conflicts later).

**D8** — **Horizontal:** Adding more machines (Scaling Out). **Vertical:** Adding more CPU/RAM to one machine (Scaling Up). **Patterns:** Statelessness, Load Balancing, and Database Sharding/Partitioning.

**D9** — An **environment variable** is a dynamic value used by processes. **Persistence:** Add `export VAR_NAME=value` to `~/.bashrc` or `~/.zshrc`.

**D10** — **JSON:** Lightweight, native to JS. **YAML:** Human-readable, supports comments. **Advantage:** JSON is faster to parse; YAML is easier for humans to write/configure.

**D11** — **REST:** Architectural style for networked apps. **GET:** Retrieve data. **POST:** Create data. **PUT:** Update/Replace data. **DELETE:** Remove data.

**D12** — **Version pinning** (e.g., `requests==2.25.1`) ensures that the exact same code is installed every time. It prevents "breaking changes" from upstream updates from crashing your build.

**D13** — **Compiled:** Source code converted to machine code before execution (C++, Go). **Interpreted:** Source code executed line-by-line by an interpreter (Python, Ruby).

**D14** — **Reverse Proxy:** Sits in front of web servers (e.g., Nginx, HAProxy) to handle load balancing/SSL. **Forward Proxy:** Sits in front of clients (e.g., corporate proxy) to hide client identity/filter traffic.

**D15** — **Deadlock:** A state where two or more processes are blocked forever, each waiting for the other. **Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual Consistency:** Data will eventually be the same across all nodes. **Cassandra:** Uses "Quorum" (e.g., `LOCAL_QUORUM` requires a majority of nodes in a DC to acknowledge). **Tunable:** `ONE` (fast, low consistency), `QUORUM` (balanced), `ALL` (slow, high consistency).

**D17** — **mTLS:** Both client and server present certificates. **Handshake:** 1. Client sends "Hello" + Certificate. 2. Server validates Client Cert + sends Server Cert. 3. Both verify signatures against trusted CAs. 4. Session keys are established. **Use case:** Service-to-service communication in a Service Mesh (Istio/Linkerd).

**D18** — **Hash Table:** Maps keys to indices via a hash function. **Chaining:** Store collisions in a linked list at that index. **Open Addressing:** Find the next empty slot. **Complexity:** Average $O(1)$ for all; Worst $O(n)$ (if all keys hash to the same index).

**D19** — **Circuit Breaker:** Prevents a failing service from dragging down others. **Closed:** Normal operation. **Open:** Failure detected; requests fail immediately without hitting the service. **Half-Open:** Periodically allows a few requests to see if the service recovered. **Relation:** Retries + Exponential Backoff prevent "hammering" a failing service, while Circuit Breakers stop the attempt entirely for a window of time.

**D20** — **Optimistic:** Assume no conflict; check for changes at commit time (e.g., `UPDATE ... WHERE version = 5`). Use for high-concurrency, low-conflict apps. **Pessimistic:** Lock the record immediately (e.g., `SELECT FOR UPDATE`). Use for high-conflict, high-value transactions (e.g., banking).
