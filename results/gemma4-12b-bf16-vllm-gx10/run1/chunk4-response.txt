## Go

**G1 — Easy:** An array has a fixed size defined at compile time; a slice is a descriptor (header) containing a pointer to an underlying array, a length, and a capacity. When a slice reaches capacity during an `append`, Go allocates a new, larger underlying array, copies the existing elements, and returns a new slice header.

**G2 — Easy:** `var x int` declares a variable with the zero value (0) and can be used at the package level. `x := 0` is a short variable declaration that declares and initializes a variable within a function body. You cannot use `:=` at the package level or if the variable has already been declared in the same scope.

**G3 — Medium:** A goroutine is a lightweight thread managed by the Go runtime, not the OS. They have smaller stacks (starting at ~2KB) and faster context switching. The GMP model consists of **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts). **P** schedules **G**s onto **M**s, allowing for efficient work stealing and multi-core utilization.

**G4 — Medium:** Channels are typed conduits for communication. Unbuffered channels require both sender and receiver to be ready simultaneously (blocking). Buffered channels allow sending until the buffer is full. Sending to a full buffered channel blocks the sender until a receiver consumes an element.

**G5 — Medium:** The `context` package handles deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
```

**G6 — Medium:** Go uses "implicit" satisfaction: a type satisfies an interface simply by implementing its methods (no `implements` keyword). Java/C# require explicit declaration. `interface{}` (or `any`) can hold any value, making it powerful for generic-like behavior but dangerous because it bypasses type safety, requiring type assertions or reflection.

**G7 — Hard:** The Go memory model does not guarantee that a write in one goroutine is visible to another without synchronization. The provided code is a data race because `ready` is accessed without atomic operations or mutexes. The compiler/CPU might reorder instructions or cache values. **Fix:** Use `sync.WaitGroup`, `sync.Mutex`, or `atomic.Bool`.

**G8 — Hard:** `sync.Mutex` is exclusive; `sync.RWMutex` allows multiple concurrent readers OR one writer. Use `sync.Map` for high-concurrency scenarios with stable keys and frequent updates/reads across many cores (it reduces cache contention). A `map` + `Mutex` is usually faster for low-contention or write-heavy workloads.

**G9 — Hard:** `go.mod` defines the module path and dependencies; `go.sum` contains cryptographic hashes of dependencies to ensure integrity. `go mod tidy` removes unused and adds missing modules. **MVS** (Minimum Version Selection) selects the highest minimum version of a dependency required by the graph, rather than the "latest" version.

**G10 — Medium:** `defer` schedules a function call to run immediately before the surrounding function returns. They execute in LIFO (Last-In, First-Out) order. **Gotcha:** In a loop, `defer` statements accumulate and only execute when the *function* returns, not the loop iteration, potentially causing memory leaks or delayed execution.

**G11 — Easy:** A pointer holds the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: 1}`.

**G12 — Easy:** `init()` runs automatically after package variables are initialized but before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source files (lexical order).

**G13 — Easy:** `new(T)` allocates memory for a type `T`, zeros it, and returns a pointer `*T`. `make(T)` initializes internal structures for slices, maps, and channels and returns the type itself (not a pointer). `new` works on all types; `make` only on slices, maps, and channels.

**G14 — Easy:** Errors are values implementing the `error` interface (`Error() string`). Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks for a specific error instance (wrapped), while `errors.As` checks if an error can be cast to a specific type. `==` only works for simple equality.

**G15 — Easy:**
- Map: `map[K]V` (Zero: `nil`)
- Slice: `[]T` (Zero: `nil`)
- Channel: `chan T` (Zero: `nil`)
- Struct: `struct{...}` (Zero: all fields at zero value)

**G16 — Medium:** A race condition occurs when two goroutines access the same memory concurrently and at least one is a write. The `-race` flag uses instrumentation to detect unsynchronized access at runtime. **Fix:** Use `sync.Mutex` to lock the critical section or use a channel to pass ownership of the data.

**G17 — Medium:** `select` lets a goroutine wait on multiple channel operations. Unlike `switch` (which evaluates expressions), `select` blocks until one case is ready. If multiple are ready, one is chosen pseudo-randomly. **Timeout:** `case <-time.After(d):`.

**G18 — Hard:** Escape analysis determines if a variable can stay on the stack (fast) or must move to the heap (slower, requires GC). Variables "escape" if they are returned as pointers, captured by closures, or are too large. Inspect via `go build -gcflags="-m"`. It matters because heap allocations increase GC pressure.

**G19 — Hard:** `reflect.Type` describes the structure (name, fields); `reflect.Value` holds the actual data. Reflection is slow because it involves dynamic type checking and heap allocations. It is justified for generic libraries (e.g., JSON encoders) where code generation is impractical.

**G20 — Hard:** `go:embed` allows compiling static assets (images, HTML) into the binary. It works for files and directories (via `//go:embed dir/*`). It provides an `fs.FS` interface for structured access. Limitation: It cannot embed files outside the module or files that are modified by the program at runtime.

## Rust

**R1 — Easy:** Ownership is Rust's memory management system. Rules: 1. Each value has a variable called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2 — Easy:** `String` is an owned, heap-allocated buffer; `&str` is an immutable reference (slice) to a string. Use `String` when you need to own/mutate the data; use `&str` in function arguments to accept any string-like data efficiently.

**R3 — Medium:** Borrowing allows using a value without taking ownership. **Rules:** 1. You can have either one mutable reference (`&mut T`) OR any number of immutable references (`&T`) at a time. 2. References must always be valid (no dangling pointers).

**R4 — Medium:** `Option<T>` handles the presence/absence of a value (no nulls). `Result<T, E>` handles success/failure. The `?` operator returns the error early if it occurs, otherwise unwraps the value.
```rust
fn read_file(path: &str) -> std::io::Result<String> {
    std::fs::read_to_string(path)
}
```

**R5 — Medium:** `Box<T>` is a heap-allocated pointer (single ownership). `Rc<T>` is a reference-counted pointer for multiple owners in a single thread. `Arc<T>` is an atomic reference-counted pointer for multiple owners across threads.

**R6 — Medium:** Traits define shared behavior (similar to Go interfaces). `dyn Trait` is a trait object (dynamic dispatch via vtable), while `T: Trait` is a generic with a trait bound (static dispatch via monomorphization).

**R7 — Hard:** Lifetimes ensure references don't outlive their data. The example fails because the compiler doesn't know if the returned `&str` comes from `x` or `y`. **Fix:** Add a lifetime parameter: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8 — Hard:** `Send` means a type can be transferred between threads; `Sync` means it can be shared between threads. `Rc<T>` is not `Send` because its reference count is not atomic (data race risk). `Arc<T>` is safe because it uses atomic operations to update the count.

**R9 — Hard:** Rust's `async` is "lazy." A `Future` is a state machine that does nothing until polled. The executor (Tokio) manages the polling. Unlike Go's goroutines (preemptive, managed by runtime), Rust's async is cooperative and poll-based, allowing for much higher scalability with lower overhead.

**R10 — Medium:** `unsafe` allows bypassing the compiler's safety checks. 3 things: Dereferencing raw pointers, calling unsafe C functions, and accessing mutable statics. Justified for low-level hardware access, FFI, or high-performance data structures.

**R11 — Easy:** `match` is an expression that checks a value against patterns; `if let` is a concise way to handle a single pattern. `match` must be exhaustive (all possible cases must be covered).

**R12 — Easy:** `Vec<T>` is a growable heap-allocated array; `[T; N]` is a fixed-size stack-allocated array. When `Vec` exceeds capacity, it reallocates a larger block of memory and moves elements.

**R13 — Easy:** Rust enums are "algebraic data types" (can hold data per variant), unlike C/Java enums. `Option<T>` is an enum with `Some(T)` and `None`. Rust has no `null` to prevent null pointer exceptions at compile time.

**R14 — Easy:** `impl` defines methods for a type. `&self` borrows the instance (read-only), `&mut self` borrows mutably, and `self` consumes the instance (moves it). Associated functions (no `self`) are like static methods.

**R15 — Easy:** `derive` automatically implements traits. Common: `Debug` (printing), `Clone` (deep copy), `PartialEq` (comparison), `Serialize` (JSON/binary). You cannot derive traits that require manual implementation or are not provided by the macro system.

**R16 — Medium:** `Cow<'a, T>` is "Clone on Write." It allows you to return either a borrowed `&T` or an owned `T`. It avoids allocating a new `String` if the data doesn't need modification, but provides an owned version if it does.

**R17 — Medium:** `mod` declares a module, `use` brings it into scope, and `pub` makes it accessible. In 2015, modules were tied to files; in 2018, modules can be nested in files more flexibly (e.g., `mod.rs` is no longer required).

**R18 — Hard:** `Pin<T>` ensures that a value cannot be moved in memory. This is required for `async` blocks because they may contain self-referential pointers (pointers to other fields within the same state machine). `Unpin` is a marker trait for types that are safe to move.

**R19 — Hard:** `macro_rules!` are declarative (pattern matching on code). Procedural macros are functions that take token streams and return new token streams (Derive, Attribute, Function-like). Hygiene ensures macros don't accidentally capture variables from the surrounding scope.

**R20 — Hard:** Zero-cost abstractions mean you don't pay for what you don't use. Iterators are compiled into loops (no overhead). Generics use monomorphization (generating specific code for each type). Trait static dispatch uses direct calls. These provide high-level code that compiles to the same assembly as manual C.
