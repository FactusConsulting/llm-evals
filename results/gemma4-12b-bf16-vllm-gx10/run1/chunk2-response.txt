## Kubernetes

**K1** — A **Deployment** manages stateless pods where each pod is interchangeable; it uses a ReplicaSet to ensure the desired number of pods are running. A **StatefulSet** manages stateful pods where each pod has a unique, persistent identity (ordinal index), stable network identifiers, and dedicated persistent storage.

**K2** — A **ClusterIP** Service provides a stable internal IP. It uses `kube-proxy` (via iptables or IPVS) to intercept traffic sent to that IP and load-balance it across the backend Pod IPs listed in the Service's **Endpoints** object.

**K3** — **PersistentVolume (PV)** is a piece of storage provisioned by an admin (the "physical" disk). **PersistentVolumeClaim (PVC)** is a request for storage by a user (the "ticket"). **StorageClass** is a blueprint that allows for dynamic provisioning (automatically creating a PV when a PVC is created). **Relation:** A PVC requests storage from a StorageClass, which then creates a PV, which is finally mounted by a Pod.

**K4** — 1. `kubectl logs <pod>` to check application errors. 2. `kubectl describe pod <pod>` to check events (e.g., OOMKilled, Liveness probe failures). 3. Check resource limits/requests vs. actual usage. 4. Verify environment variables, secrets, and configmap mounts are correct.

**K5** — **CoreDNS** is the cluster's internal DNS server, resolving service names (e.g., `my-svc.namespace.svc.cluster.local`) to ClusterIPs. If CoreDNS pods are down, pods cannot resolve internal or external hostnames, causing service discovery and external API calls to fail.

**K6** — The scheduler uses two phases: **Filtering** (Predicates) to remove nodes that don't meet requirements (e.g., insufficient CPU/RAM, Taints, NodeSelectors), and **Scoring** (Priorities) to rank remaining nodes. Factors include: **LeastRequestedPriority** (balance load), **ImageLocality** (prefer nodes with the image cached), and **PodAffinity/AntiAffinity**.

**K7** — **Scheduled?** Yes. The node has 4GB (4096Mi). 3.5GB is requested, leaving 516Mi available. The pod's *request* is 256Mi, which fits. **Runtime?** If it uses 600Mi, it will not be killed immediately because the *limit* is 512Mi. However, since 600Mi > 512Mi, the **OOMKiller** will terminate the pod as soon as it exceeds the 512Mi limit.

**K8** — 1. External request hits **External LB**. 2. LB forwards to **Ingress Controller** (NGINX) NodePort/LoadBalancer. 3. NGINX matches the Host/Path and forwards to the **Service** IP. 4. `kube-proxy` (iptables/IPVS) intercepts the Service IP and routes it to a specific **Pod IP** from the **Endpoints** list. 5. Request reaches the **Application Pod**.

**K9** — A **NetworkPolicy** is a firewall for pods, controlling ingress/egress traffic based on labels/selectors. **Default behavior:** If no policy exists, all traffic is allowed (non-isolated). **Applied policy:** If you apply a policy to specific pods, those pods become "isolated," and only traffic explicitly allowed by the policy is permitted.

**K10** — **RollingUpdate** replaces pods one-by-one (zero downtime). **Recreate** kills all existing pods before starting new ones (downtime). Choose **Recreate** when the application does not support running two versions simultaneously (e.g., a database schema change that is not backward compatible).

**K11** — A **Namespace** is a virtual cluster used to partition resources and provide isolation. Default namespaces are: `default`, `kube-system`, `kube-public`, and `kube-node-legacy` (in some versions).

**K12** — `kubectl describe` provides detailed metadata and status. 3 pieces not in `get`: **Events** (reasons for failures), **Container Status** (restart counts, exit codes), and **Node Affinity/Tolerations** details.

**K13** — A **ConfigMap** stores non-confidential key-value pairs. Methods: 1. **Environment Variables** (injected into the container). 2. **Mounted Files** (projected into a volume at a specific path).

**K14** — **ClusterIP:** Internal only (default). **NodePort:** Exposes service on a specific port on every Node's IP (used for external access without a LB). **LoadBalancer:** Provisions a cloud provider's LB to route external traffic to the service.

**K15** — A **DaemonSet** ensures that all (or some) nodes run a copy of a pod. Use it for infrastructure tasks like **Log Collection** (Fluentd), **Monitoring Agents** (Prometheus Node Exporter), or **Networking Plugins**.

**K16** — **Taints** are on Nodes (repel pods); **Tolerations** are on Pods (allow them to stay on tainted nodes). **Node Affinity** is on Pods (attract pods to specific nodes). **Use Case:** Taints/Tolerations for dedicated GPU nodes (keep general pods off). Node Affinity for "Zone-aware" deployments (keep pods in the same region as the DB).

**K17** — An **Operator** is a custom controller that uses **CRDs** (Custom Resource Definitions) to manage complex applications (e.g., a Postgres Operator). It differs from a standard controller by encoding "human operational knowledge" (backups, upgrades, failovers) into code. It solves the problem of automating complex, stateful application lifecycles.

**K18** — **etcd** uses the **Raft** consensus algorithm (Strong Consistency). If **quorum** is lost (e.g., 2/3 nodes down), the cluster becomes read-only/unavailable for writes. **Recovery:** You must restore the data from a snapshot to a new node and manually force the cluster to recognize the new configuration/member list.

**K19** — **Role:** Permissions in a namespace. **ClusterRole:** Permissions cluster-wide. **RoleBinding:** Links Role to a user in a namespace. **ClusterRoleBinding:** Links ClusterRole to a user cluster-wide.
**Manifests:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: my-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: my-ns
subjects:
- kind: User
  name: "developer-name"
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — `ndots:5` means if a name has fewer than 5 dots, it tries to append the search path (e.g., `google.com` becomes `google.com.default.svc.cluster.local`). This causes many failed queries before the real one. **Fix:** Set `dnsConfig.options.ndots: 1` or use the Fully Qualified Domain Name (FQDN) ending in a dot (e.g., `google.com.`).

## Development

**D1** — **Merge** combines histories with a "merge commit." **Rebase** rewrites history by moving the entire branch to the tip of the target branch. **Avoid rebasing** on public/shared branches because it rewrites history and causes conflicts for other collaborators.

**D2** — **TCP** is connection-oriented, reliable, and ordered (e.g., HTTP, SSH). **UDP** is connectionless, faster, and unreliable (e.g., DNS, VoIP).

**D3** — A **Race Condition** occurs when the output depends on the timing of uncontrollable events. **Example:** Two threads incrementing a shared variable `count++` simultaneously; both read `5`, both increment to `6`, and write `6`, losing one increment.

**D4** — **Symmetric:** Same key for encryption/decryption (fast). **Asymmetric:** Public key encrypts, Private key decrypts (secure key exchange). **TLS:** Uses Asymmetric encryption to exchange a "session key," then uses Symmetric encryption for the actual data transfer.

**D5** — A **Layer** is a read-only filesystem change. **Caching:** Docker reuses layers. **Best Practice:** Put instructions that change frequently (like `COPY .`) at the bottom of the Dockerfile and stable ones (like `RUN apt-get install`) at the top to maximize cache hits.

**D6** — 1. Check **Application Logs** (Internal errors). 2. Check **Resource Usage** (CPU/RAM throttling). 3. Check **Downstream Dependencies** (Database/Third-party APIs). 4. Check **Network/Load Balancer** limits.

**D7** — **CAP Theorem:** A distributed system can only provide 2 of 3: Consistency, Availability, Partition Tolerance. **CP Example:** MongoDB (Consistency/Partition Tolerance). **AP Example:** Cassandra (Availability/Partition Tolerance).

**D8** — **Horizontal:** Adding more machines (Scaling out). **Vertical:** Adding more power to one machine (Scaling up). **Patterns:** Load balancing, statelessness, and database sharding/replication.

**D9** — An **Environment Variable** is a dynamic value used by processes. On Linux, set it in `~/.bashrc` or `~/.zshrc` using `export VAR_NAME="value"`.

**D10** — **JSON:** Lightweight, easy for machines to parse. **YAML:** Human-readable, supports comments. **Advantage:** JSON is faster to parse; YAML is easier to write/read for config files.

**D11** — **REST:** Architectural style for networked apps. **GET:** Retrieve data. **POST:** Create data. **PUT:** Update/Replace data. **DELETE:** Remove data.

**D12** — **Version Pinning** is specifying an exact version (e.g., `requests==2.25.1`). It ensures that every build uses the same dependencies, preventing "breaking changes" from upstream updates.

**D13** — **Compiled:** Source code is converted to machine code before execution (e.g., C++, Rust). **Interpreted:** Code is executed line-by-line by an interpreter (e.g., Python, JavaScript).

**D14** — **Reverse Proxy:** Sits in front of web servers (e.g., NGINX, HAProxy) to handle load balancing/SSL. **Forward Proxy:** Sits in front of clients (e.g., corporate proxy) to hide client identity/filter traffic.

**D15** — **Deadlock:** A state where two or more processes are blocked forever, each waiting for the other. **Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual Consistency:** Data will eventually be the same across all nodes. **Cassandra:** Uses "Tunable Consistency." **Levels:** `ONE` (fast, low consistency), `QUORUM` (majority of nodes must agree), `ALL` (slow, high consistency).

**D17** — **mTLS:** Both client and server present certificates to verify each other. **Handshake:** 1. Client sends "Hello" + Certificate. 2. Server sends "Hello" + Certificate. 3. Both verify signatures against trusted CAs. 4. Exchange session keys. **Use Case:** Service-to-service communication in a Service Mesh (Istio/Linkerd).

**D18** — **Hash Table:** Uses a hash function to map keys to array indices. **Chaining:** Store collisions in a linked list at that index. **Open Addressing:** Find the next empty slot. **Complexity:** Average $O(1)$ for all; Worst $O(n)$ if many collisions occur.

**D19** — **Circuit Breaker:** Prevents a failing service from dragging down others. **Closed:** Normal operation. **Open:** Failure detected; requests fail immediately. **Half-Open:** Periodically allows a few requests to see if the service recovered. **Relation:** Retries with exponential backoff can overwhelm a failing service; a circuit breaker stops the retries until the service is healthy.

**D20** — **Optimistic:** Assumes no conflict; checks for changes at the moment of commit (e.g., Versioning/ETags). Use for high-concurrency, low-conflict apps. **Pessimistic:** Locks the record until the transaction is done (e.g., `SELECT FOR UPDATE`). Use for high-conflict, high-value transactions (e.g., banking).
