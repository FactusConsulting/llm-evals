## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but in a "Temporal Dead Zone" (TDZ) until declaration. `const` prevents reassignment but allows mutation of objects/arrays. **Hoisting** is the JS engine's behavior of moving declarations to the top of their scope during the compilation phase.

**JS2** — The **Event Loop** manages execution. The **Call Stack** handles synchronous code. When an async operation completes, its callback enters a queue. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority; the loop exhausts it entirely before moving to the **Macrotask Queue** (setTimeout, I/O).

**JS3** — A **Closure** is a function bundled with its lexical environment. *Example:* A counter function returning an incrementor. *Bug:* Using `var` in a loop with async calls (all share the same final value). *Fix:* Use `let` (block scoping) or an IIFE.

**JS4** — **Promise** represents a future value. **Async/await** is syntactic sugar for Promises. Errors are handled via `.catch()` or `try/catch`. **Promise.all** rejects if *any* fail; **Promise.allSettled** waits for all to finish regardless of success/failure.

**JS5** — **Interface** is for defining shapes (structural); **Type** is for aliases and unions. Use `interface` for public APIs/objects (supports declaration merging) and `type` for complex logic (unions, intersections). **Discriminated Unions** use a common literal property (e.g., `type: 'success'`) to allow type narrowing via `switch`.

**JS6** — **Prototypal Inheritance** means objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with a specific prototype. **ES6 Classes** are "syntactic sugar" over prototypes; they don't change the underlying inheritance model but provide a cleaner syntax for constructors and methods.

**JS7** — `this` refers to the execution context. **Binding Rules (Priority):** 1. `new` binding, 2. Explicit binding (`call`, `apply`, `bind`), 3. Implicit binding (object method), 4. Default binding (global/undefined). `bind()` returns a *new* function; you cannot re-bind a function that was already created via `bind()`.

**JS8** — **WeakRef** allows holding a reference to an object without preventing GC. **FinalizationRegistry** allows registering a callback to run after an object is GC'd. **WeakMap** keys must be objects because they are held weakly; if the only reference to a key is in the WeakMap, the GC can reclaim it, preventing memory leaks.

**JS9** — V8 uses **Hidden Classes** (shapes) to track object properties and **Inline Caching** to remember property offsets. **Deoptimization** occurs when the "shape" changes (e.g., adding properties in different orders or changing types of properties). Patterns: dynamic property addition, using `arguments`, or changing types of variables.

**JS10** — **Tree-shaking** removes unused code. **ESM** is static (imports are known at compile time), making it easy to shake. **CommonJS** is dynamic (`require` can be inside `if` blocks), making it nearly impossible for bundlers to determine what is used without executing the code.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable hasn't been assigned. `==` performs type coercion (`null == undefined` is true); `===` does not (`null === undefined` is false). `??` returns the right side if the left is `null/undefined`. `?.` short-circuits if the left side is `null/undefined`.

**JS12** — `map` transforms each element; `filter` selects elements based on a predicate; `reduce` accumulates values into a single result. `reduce` with an initial value starts the accumulator with that value. `flatMap` maps then flattens one level deep (useful for filtering and mapping simultaneously).

**JS13** — **Template literals** use backticks (`` ` ``) for interpolation `${}`. **Tagged templates** allow a function to parse the template literal. *Example:* `sql`tag`SELECT * FROM users WHERE id = ${id}` where the function handles escaping the `id` variable.

**JS14** — **Destructuring** extracts values into variables. *Object:* `{a, b} = obj`. *Array:* `[x, y] = arr`. *Default:* `const {x = 10} = obj`. *Renaming:* `const {x: newX} = obj`. **Rest operator** `...` collects remaining elements into a new array/object.

**JS15** — `for...in` iterates over **enumerable keys** (properties); `for...of` iterates over **iterable values**. Avoid `for...in` on arrays because it includes inherited properties and non-numeric keys, which can lead to unexpected behavior.

**JS16** — **Generics** allow reusable components with type safety. **Constraints** (`<T extends string>`) limit types. **Conditional types** (`T extends U ? X : Y`) act like ternary operators for types. **Infer** allows extracting types from expressions. *Example:* `type Unpacked<T> = T extends Array<infer U> ? U : T`.

**JS17** — **CommonJS** is synchronous (Node default); **ESM** is asynchronous/static (Browser/Modern Node). Node handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM. ESM uses `import/export`, CJS uses `require/module.exports`.

**JS18** — **Structural typing** means if it looks like a duck, it is a duck. **Excess property checks** only apply to object literals (not variables). `extends` is for inheritance; `satisfies` checks if an expression matches a type while keeping the most specific type. **Variance** defines how subtyping of complex types (like functions) relates to subtyping of their components.

**JS19** — **Proxy** wraps an object to intercept operations (get, set, etc.). **Reflect** provides a mirror API for those same operations. *Example:* A Proxy can intercept `set` to validate that a "price" property is always a positive number before updating the object.

**JS20** — **SharedArrayBuffer** allows multiple threads (Web Workers) to share the same memory. **Atomics** provides thread-safe operations (add, load, wait) on that memory. `Atomics.wait` puts a thread to sleep until `Atomics.notify` is called, preventing race conditions.

## Bash

**B1** — `$*` expands to a single string with all arguments joined by spaces. `$@` expands to a list of separate arguments. `"$*"` is a single quoted string; `"$@"` is a list of quoted strings (the standard for safe script arguments).

**B2** — `-e`: Exit immediately if a command fails. `-u`: Exit if an uninitialized variable is used. `-o pipefail`: Return the exit code of the last command in a pipe that failed (otherwise, only the last command's exit code is returned).

**B3** — `$(command)` is command substitution (returns output); `` `command` `` is the older, deprecated syntax. `$((expression))` is for integer arithmetic; `expr` is an external binary for arithmetic (slower, rarely used now).

**B4** — **Process substitution** `<(command)` makes the output of a command look like a file. *Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands as if they were files.

**B5** — Use `find . -name "* "* -print0 | while IFS= read -r -d '' file; do ... done`. `for f in $(ls)` is dangerous because it splits on spaces, breaking filenames like "My File.txt".

**B6** — `<<EOF` is a **Here Document** (multi-line input); `<<<` is a **Here String** (single line). `<<-EOF` ignores leading tabs (but not spaces) in the input block.

**B7** — `cmd > file 2>&1`: Redirects stdout to file, then redirects stderr to where stdout *was* (the shell). `cmd 2>&1 > file`: Redirects stderr to stdout, then redirects stdout to file (stderr stays on terminal). `cmd &> file`: Bash shorthand for both.

**B8** — `mkdir /tmp/lock_dir 2>/dev/null && echo $$ > /tmp/lock_dir/pid`. Use `trap 'rm -rf /tmp/lock_dir' EXIT SIGTERM`. `mkdir` is atomic at the OS level; file creation (`>`) is not (two processes can create the same file simultaneously).

**B9** — `'...'`: No expansion (literal). `"..."`: Variable/command expansion. `No quotes`: Word splitting and globbing. *Example:* `echo "Hi $USER"` vs `echo 'Hi $USER'`.

**B10** — `-e $file` (exists), `-d $file` (directory), `-r $file` (readable). `[ ]` is the standard test command; `[[ ]]` is a Bash keyword that supports regex, logical operators, and doesn't require quoting variables to prevent word splitting.

**B11** — `$?`: Exit code of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: Number of positional parameters.

**B12** — `foo() { ...; }` is standard; `function foo {}` is a Bash-specific syntax. To return values, use `echo` and capture it: `result=$(foo)`. Bash functions return exit codes (0-255) via `return`.

**B13** — `PATH` is a colon-separated list of directories searched for executables. Bash checks **Builtins** (internal to shell) first, then **Aliases**, then **Functions**, then **External commands** in `PATH`. Use `type command` to check.

**B14** — `trap` catches signals. `trap 'cleanup' EXIT ERR INT TERM`. If multiple signals arrive, they are queued; `EXIT` runs when the shell exits or a command fails.

**B15** — `xargs` builds commands from input; command substitution `$(...)` runs a command once. `find ... -print0 | xargs -0` handles spaces/newlines. `xargs -P` runs jobs in parallel.

**B16** — `arr=(a b c)` is an array; `declare -A map` is an associative array. Append: `arr+=("d")`. Length: `${#arr[@]}`. Associative arrays require keys (strings).

**B17** — `(...)` is a **subshell** (new PID, variables lost). `{ ...; }` is a **group command** (same PID, variables preserved). Piping `ls | while read line; do var=1; done` loses `var` because the `while` loop runs in a subshell.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (terminal closed), `SIGKILL` (forced). To handle graceful shutdown, `trap` a signal to send `kill` commands to background PIDs stored in a variable.

**B19** — `split -l 10000 log.txt` -> `xargs -P 4 -I {} ./process_chunk.sh {}` -> `cat results_*.txt > final.txt`. *Trade-off:* Parallelism increases speed but makes error ordering and partial failures harder to manage.

**B20** — `exec` replaces the current shell process with the command. `exec 3>file` opens a file descriptor. **Coprocess** `coproc my_proc { command; }` runs a command in the background with two-way communication pipes.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline; `Write-Host` sends text directly to the console. `Write-Host` is ignored by the pipeline.

**PS2** — The pipeline passes objects. `ForEach-Object` is used for pipeline processing (streaming); `foreach` is a statement for iterating over a collection in memory.

**PS3** — `[PSCustomObject]` is a structured object with properties (best for pipelines); `[hashtable]` is a key-value collection. Convert: `[PSCustomObject]@{Key=$val}` or `(Get-Member).Name | % { Add-Member ... }`.

**PS4** — **Terminating** errors stop execution (caught by `try/catch`). **Non-terminating** errors continue (logged to `$Error`). `-ErrorAction Stop` turns non-terminating into terminating.

**PS5** — **Splatting** passes a hashtable as parameters: `Get-ChildItem @params`. It improves readability and allows dynamic parameter construction.

**PS6** — `Invoke-Command` runs commands on remote machines; `Enter-PSSession` is an interactive shell. Both use **WinRM** (WS-Man) by default, but `Invoke-Command` can use SSH.

**PS7** — PowerShell's pipeline is "streaming." If a function returns an array, the pipeline might treat it as a collection of items. The example returns a `System.Object[]`. The correct pattern is to ensure the function returns a single object or use `Write-Output` explicitly.

**PS8** — **Scriptblock** is a block of code; **Function** is a named, reusable entity. `Invoke-Command -ArgumentList` passes values. **Double-hop** occurs when a remote machine tries to access a third machine using your credentials; solved by **CredSSP** or passing credentials explicitly.

**PS9** — `@()` is an array literal; `[array]` is a type accelerator. To force a single result into an array: `@(Get-Item $path)`. Indexing into `$null` throws an error; indexing into `@()` returns `$null`.

**PS10** — `-eq` is case-insensitive; `-ceq` is case-sensitive. `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection (syntactically reversed).

**PS11** — **Module** is a collection of scripts/functions. `.psm1` is the script file; `.psd1` is the manifest (metadata/versioning). `Import-Module` loads them into the session.

**PS12** — `"Hello $Name"` interpolates variables. `'...'` is literal. `$(Get-Date)` interpolates expressions. **Here-string** `@""@` allows multi-line strings.

**PS13** — `Get-Member` shows properties/methods. **Properties** are data; **Methods** are actions; **NoteProperties** are extra metadata. `Select-Object` picks properties; `Where-Object` filters rows.

**PS14** — **Classes** (v5+) are C#-like types with strict schemas. They differ from C# by lacking some inheritance/constructor features. Use a **Class** for complex data models/methods; use a **Function** for actions.

**PS15** — `[CmdletBinding()]` adds standard parameters (`-Verbose`, `-WhatIf`). `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` blocks allow processing items one-by-one as they arrive in the pipeline.

**PS16** — **Providers** allow `Get-ChildItem` to work on Registry, Certificate, and FileSystem using the same syntax. Access registry via `Get-ChildItem HKCU:\Software`.

**PS17** — **Runspaces** are lightweight threads for parallel execution. `ForEach-Object -Parallel` (v7+) manages a runspace pool automatically. Manual management requires `[RunspaceFactory]` and `[PowerShell]::Create()`.

**PS18** — **PSScriptAnalyzer** is a static analysis tool. It checks for best practices (e.g., "no uninitialized variables"). Rules have severities (Warning, Error). Suppress via `#rts` or `[Diagnostics.CodeAnalysis]`.

**PS19** — `$using:` is for passing variables into a remote session/parallel block. `-ArgumentList` passes values to a script block. **CLIXML** depth limits how many nested objects can be serialized across the pipeline.

**PS20** — **DSC** is a declarative "Desired State" system. **Configurations** define the state; **Resources** are the "how"; **LCM** is the engine that enforces it. In modern infra, **Terraform** or **Ansible** have largely replaced DSC for multi-platform use.
