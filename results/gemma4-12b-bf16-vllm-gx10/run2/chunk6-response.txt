## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but in a "Temporal Dead Zone" (TDZ) until declaration. `const` prevents reassignment but allows mutation of objects/arrays. **Hoisting** is the JS engine's behavior of moving declarations to the top of their scope during the compilation phase.

**JS2** — The **Event Loop** manages execution. The **Call Stack** handles synchronous code. When an async operation completes, its callback enters a queue. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority; the loop clears it entirely before moving to the **Macrotask Queue** (setTimeout, I/O).

**JS3** — A **Closure** is a function bundled with its lexical environment. *Example:* A counter function returning an incrementor. *Bug:* Using `var` in a loop with async calls (all share the same final value). *Fix:* Use `let` (block scoping) or an IIFE.

**JS4** — **Promise** represents a future value. **Async/await** is syntactic sugar for Promises. Errors are handled via `.catch()` or `try/catch`. **Promise.all** rejects if *any* fail; **Promise.allSettled** waits for all to finish regardless of outcome.

**JS5** — **Interface** is for defining shapes (structural); **Type** is for aliases and unions. Use `interface` for public APIs/objects (mergable) and `type` for complex logic (unions, intersections). **Discriminated Unions** use a common literal property (e.g., `type: 'success'`) to allow type narrowing via `switch`.

**JS6** — **Prototypal Inheritance** means objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with a specific prototype. **ES6 Classes** are "syntactic sugar" over prototypes; they don't change the underlying inheritance model.

**JS7** — `this` is determined by: 1. `new` binding, 2. Explicit binding (`call`/`apply`/`bind`), 3. Implicit binding (object method), 4. Default binding (global/undefined). `bind()` returns a *new* function with the context locked; it cannot be re-bound.

**JS8** — **WeakRef** allows holding a reference to an object without preventing GC. **FinalizationRegistry** allows running a callback when an object is GC'd. **WeakMap** keys must be objects because they are held weakly; if the only reference to a key is in the WeakMap, the GC can reclaim it.

**JS9** — V8 uses **Hidden Classes** (shapes) to track object properties and **Inline Caching** to skip lookups for stable shapes. **Deoptimization** occurs when shapes change (e.g., adding properties in different orders). Patterns: dynamic property addition, changing types of variables in hot loops.

**JS10** — **Tree-shaking** removes unused code. **ESM** is static (imports are at top-level), allowing the compiler to know what's used. **CommonJS** is dynamic (`require` can be inside `if`), making it impossible to determine dead code statically.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable hasn't been assigned. `==` performs type coercion (`null == undefined` is true); `===` does not (false). `??` returns the right side if left is `null/undefined`. `?.` stops evaluation if the left side is `null/undefined`.

**JS12** — `map` transforms each element; `filter` selects elements; `reduce` accumulates into a single value. `reduce` with an initial value starts the accumulator with that value. `flatMap` maps then flattens one level deep (useful for filtering and mapping simultaneously).

**JS13** — **Template Literals** use backticks (`` ` ``) for interpolation `${}`. **Tagged Templates** allow a function to parse the literal. *Example:* `html`tag`<div>${content}</div>`` where the function escapes `content` for HTML safety.

**JS14** — **Destructuring** extracts values into variables. *Object:* `{a, b} = obj`. *Array:* `[x, y] = arr`. *Default:* `[x = 0] = arr`. *Renaming:* `{a: newA} = obj`. **Rest (...)** collects remaining elements into a new array/object.

**JS15** — `for...in` iterates over enumerable **keys** (properties). `for...of` iterates over **values** (iterable). Avoid `for...in` on arrays because it includes inherited properties and non-index keys.

**JS16** — **Generics** allow reusable types. **Constraints** (`<T extends string>`) limit types. **Conditional Types** (`T extends U ? X : Y`) act like ternary operators for types. **Infer** extracts types from expressions. *Example:* `type Unpacked<T> = T extends Array<infer U> ? U : T`.

**JS17** — **CommonJS** is synchronous/dynamic (Node default). **ESM** is asynchronous/static (Browser/Modern Node). Node handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM.

**JS18** — **Structural typing** means if it looks like a duck, it is a duck. **Excess property checks** only apply to object literals, not variables. **Extends** is for inheritance; **Satisfies** checks if an expression matches a type without widening the type. **Variance** defines how subtyping of inputs/outputs relates to subtyping of functions.

**JS19** — **Proxy** intercepts operations (get, set, etc.); **Reflect** provides the underlying methods to perform those operations. *Example:* A Proxy can intercept `set` to validate that a "price" property is always a positive number.

**JS20** — **SharedArrayBuffer** allows multiple threads (Web Workers) to share the same memory. **Atomics** provides thread-safe operations (add, load, wait). `Atomics.wait` puts a thread to sleep until `Atomics.notify` is called on the same index.

## Bash

**B1** — `$*` expands to a single string with all arguments joined by spaces. `$@` expands to a list of separate arguments. `"$*"` is one string; `"$@"` is a list of quoted strings (the standard for safe looping).

**B2** — `-e`: Exit on error. `-u`: Exit on unset variables. `-o pipefail`: If any command in a pipeline fails, the whole pipeline returns the exit code of the failed command.

**B3** — `$(command)` is command substitution (returns output). `` `command` `` is the deprecated version. `$((expression))` is for integer arithmetic. `expr` is an external utility for arithmetic (now largely obsolete).

**B4** — **Process Substitution** `<(command)` makes the output of a command look like a file. *Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands as if they were files.

**B5** — Use `find . -name "*.txt" -print0 | while IFS= read -r -d '' file; do ... done`. `for f in $(ls)` fails because `ls` splits on spaces, breaking filenames like "My File.txt".

**B6** — `<<EOF` is a **Here Document** (multi-line input). `<<<` is a **Here String** (single line). `<<-EOF` ignores leading tabs (but not spaces) in the input.

**B7** — `> file 2>&1`: Redirects stdout to file, then redirects stderr to the same place as stdout (the file). `2>&1 > file`: Redirects stderr to stdout (still the terminal), then redirects stdout to the file (stderr remains on terminal). `&> file` is a Bash shortcut for `> file 2>&1`.

**B8** — `mkdir /tmp/lock_dir 2>/dev/null && echo "$$" > /tmp/lock_dir/pid`. Use `trap 'rm -rf /tmp/lock_dir' EXIT` for cleanup. `mkdir` is atomic at the OS level; file creation (`>`) is not (two processes can create the same file simultaneously).

**B9** — `'...'` (Single): Literal, no expansion. `"..."` (Double): Interpolates variables/commands. No quotes: Word splitting and globbing occur. *Example:* `echo "Hi $USER"` vs `echo 'Hi $USER'`.

**B10** — `-e $file` (exists), `-d $file` (directory), `-r $file` (readable). `[ ]` is the standard test command; `[[ ]]` is a Bash keyword that supports regex, logical operators, and doesn't require quoting variables as strictly.

**B11** — `$?`: Exit code of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: Number of positional parameters.

**B12** — `foo() { ...; }` is standard. `function foo {}` is also valid but slightly different in some shells. Return values: Bash functions don't return values like Python; they return exit codes (`return 0`). To "return" data, use `echo` and capture with `var=$(foo)`.

**B13** — `PATH` is a colon-separated list of directories searched for executables. Bash checks: 1. Aliases, 2. Builtins, 3. Functions, 4. PATH. Use `type command` to see if it's a builtin or external.

**B14** — `trap` catches signals. `trap 'cleanup' EXIT` (script ends), `ERR` (non-zero exit), `INT` (Ctrl+C), `TERM` (kill). If multiple signals arrive, they are queued; traps execute in the order they were defined or based on signal priority.

**B15** — `xargs` builds commands from input. Command substitution `$(...)` runs one command. `find ... -print0 | xargs -0` handles spaces/newlines. `xargs -P` runs jobs in parallel.

**B16** — `arr=(a b c)` (Array). `declare -A map` (Associative). Append: `arr+=("d")`. Iterate: `for i in "${arr[@]}"; do ...`. Length: `${#arr[@]}`. Associative arrays require keys and values.

**B17** — `(...)` is a **Subshell** (new PID, variables lost). `{ ...; }` is a **Group Command** (same PID, variables preserved). Piping `ls | while read line; do var=1; done` runs the loop in a subshell, so `var` is lost outside the loop.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (Default kill), `SIGHUP` (Terminal closed), `SIGKILL` (Force kill, cannot be trapped). To handle graceful shutdown: `trap 'kill $PID_LIST' SIGTERM`.

**B19** — `split -l 1000 log.txt` -> `xargs -P 4 -I {} ./process.sh {}` -> `cat results_*.txt > final.txt`. *Trade-offs:* Parallelism increases speed but risks out-of-order results and makes error propagation harder (need to check exit codes of all parallel jobs).

**B20** — `exec` replaces the current shell process with the command. `exec 3>file` opens a file descriptor. `exec 3>&-` closes it. A **Coprocess** (`coproc`) is a background process with two-way communication (stdin/stdout) via pipes.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline. `Write-Host` sends text directly to the console. Using `Write-Host` inside a function breaks the ability to pipe the result to another command.

**PS2** — Pipeline: Objects flow from left to right. `ForEach-Object` (Pipeline) processes one at a time from the stream. `foreach` (Statement) takes a collection and iterates in memory. Use `ForEach-Object` for large streams; `foreach` for small, pre-loaded collections.

**PS3** — `[PSCustomObject]` is a structured object with properties (best for pipelines). `[hashtable]` is a key-value collection (best for lookups). Convert: `[PSCustomObject]$obj = $hash` or `$hash = [hashtable]$obj`.

**PS4** — Terminating errors stop execution; non-terminating errors continue. `-ErrorAction` (local), `$ErrorActionPreference` (session-wide), and `try/catch` (only catches terminating errors unless `-ErrorAction Stop` is used).

**PS5** — **Splatting** passes a hashtable as parameters. `Get-ChildItem @params`. It improves readability and allows dynamic parameter construction. Passing a hashtable as a single parameter would treat the entire hash as one argument.

**PS6** — `Invoke-Command -ComputerName` runs a command remotely (one-off). `Enter-PSSession` is an interactive remote shell. Both use **WinRM** (WS-Man) by default, but can use **SSH** in newer versions.

**PS7** — PowerShell's pipeline often converts types to `System.Object` or `System.String`. In the example, `$x` becomes an `Object[]` because the function returns a collection. If 0 items are returned, it's `$null`. *Correct pattern:* Use `[PSCustomObject]` and ensure consistent return types.

**PS8** — `[scriptblock]` is a block of code; a function is a named entity. Pass scriptblocks via `-ScriptBlock`. **Double-hop** occurs when a remote machine tries to access a third machine using your credentials. Solve with **CredSSP** or by passing credentials explicitly.

**PS9** — `@()` is an array literal; `[array]` is a type accelerator. To force a single result into an array: `@(result)`. Indexing into `$null` returns `$null`; indexing into an empty array ` @() ` throws an error.

**PS10** — `-eq` (Equals), `-like` (Wildcards), `-match` (Regex), `-contains` (Checks if value is in array), `-in` (Checks if value is in collection). Case-sensitive variants use `c` (e.g., `-ceq`). `-contains` is a method on arrays; `-in` is an operator.

**PS11** — **Module** is a collection of cmdlets. `.psm1` (Script module), `.psd1` (Manifest - metadata/dependencies), Binary (DLLs). `Import-Module` loads the module into the current session.

**PS12** — `"String $var"` interpolates variables. `'String'` is literal. `$(expression)` inside double quotes runs code. **Here-string** (`@" ... "@`) allows multi-line strings while preserving formatting.

**PS13** — `Get-Member` shows properties/methods. **Properties** (data), **Methods** (actions), **NoteProperties** (custom data). `Select-Object` picks properties; `Where-Object` filters rows.

**PS14** — **Classes** (v5+) are C#-like structures with types and methods. They differ from C# by lacking full inheritance/interfaces and having limited constructors. Use a **Class** for complex, reusable data models; use a **Function** for actions.

**PS15** — `[CmdletBinding()]` enables standard parameters (`-Verbose`, `-WhatIf`). `SupportsShouldProcess` enables `-WhatIf`. `ValueFromPipeline` allows input from the pipe. `Begin` (once), `Process` (per item), `End` (once).

**PS16** — **Providers** allow uniform access to different data sources. `Get-ChildItem` works on `FileSystem`, `Registry` (e.g., `HKLM:\Software`), `Certificate`, and `Environment`.

**PS17** — **Runspaces** are lightweight threads for parallel execution. `[runspace]` is a single thread; `[runspacepool]` manages multiple. `ForEach-Object -Parallel` (v7+) is a high-level wrapper for runspaces.

**PS18** — **PSScriptAnalyzer** is a static analysis tool. It checks for best practices (rules). Severity levels (Warning, Error). Suppress via `#rts` or `[Diagnostics.CodeAnalysis...]`. Integrate into CI/CD by running the analyzer and failing on errors.

**PS19** — `$using:` is for passing variables into a remote session/background job. `$args` is for passing data into a scriptblock. **CLIXML depth** limits how complex an object can be serialized for transport; deep nested objects may fail.

**PS20** — **DSC** is a declarative "Desired State" system. **Configurations** (the "what"), **Resources** (the "how"), **LCM** (the engine that enforces it). In PS7+, it's often replaced by **Terraform** or **Ansible** for cross-platform infra.
