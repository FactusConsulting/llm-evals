## Kubernetes

**K1** — A **Deployment** is used for stateless applications where pods are interchangeable; it manages ReplicaSets to ensure a specific number of pods are running. A **StatefulSet** is used for stateful applications (like databases) where each pod requires a unique, persistent identity (ordinal index), stable network identifiers, and dedicated persistent storage.

**K2** — A **ClusterIP** Service provides a stable internal IP. When a request hits this IP, `kube-proxy` (via iptables or IPVS) intercepts the packet and load-balances it across the backend Pod IPs associated with that Service's Endpoints/EndpointSlice.

**K3** — **PersistentVolume (PV)** is a piece of storage provisioned by an admin (the "physical" disk). **PersistentVolumeClaim (PVC)** is a request for storage by a user (the "ticket"). **StorageClass** is the blueprint that allows for dynamic provisioning (automatically creating a PV when a PVC is created). Relation: A PVC requests storage based on a StorageClass, which then automatically creates a PV for the pod to use.

**K4** — 1. `kubectl logs <pod>` to check application-level errors/stack traces. 2. `kubectl describe pod <pod>` to check for events (OOMKilled, Liveness probe failures). 3. Check resource limits (is it hitting memory/CPU limits?). 4. Check environment variables and mounted secrets/configmaps for incorrect values.

**K5** — **CoreDNS** is the cluster's internal DNS server, resolving service names (e.g., `my-svc.namespace.svc.cluster.local`) to ClusterIPs. If CoreDNS pods are down, pods cannot resolve internal or external hostnames, causing connection failures for any service relying on DNS.

**K6** — The scheduler uses two main phases: **Filtering** (Predicates) to remove nodes that don't meet requirements (e.g., insufficient CPU/RAM, taints, selector mismatches) and **Scoring** (Priorities) to rank remaining nodes. Factors include: 1. Resource Fit (least requested/most requested), 2. Affinity/Anti-affinity rules, 3. Data Locality (proximity to storage/other pods).

**K7** — **Scheduling:** The pod **will** be scheduled. The node has 4GB (4096Mi) total. 3.5GB is requested, leaving 512Mi available. The pod's *request* is 256Mi, which fits in the 512Mi remaining. **Runtime:** If it uses 600Mi, it will **not** be killed immediately because the *limit* is 512Mi. However, since 600Mi exceeds the 512Mi limit, the pod will be **OOMKilled** (Out of Memory Killed) by the kubelet.

**K8** — 1. External request hits **External LB**. 2. LB forwards to **Ingress Controller** (NGINX) NodePort/LoadBalancer. 3. NGINX matches the Host/Path and looks up the **Service**. 4. NGINX identifies the **Endpoints** (Pod IPs). 5. Traffic is routed to the **Pod**. (Note: `kube-proxy` handles the Service-to-Pod translation via iptables/IPVS rules).

**K9** — A **NetworkPolicy** is a firewall for pods, controlling ingress/egress traffic at L3/L4. **Default behavior:** If no policy exists, all traffic is allowed (non-isolated). When you apply a policy to specific pods, those pods become "isolated"—only traffic explicitly allowed in the policy is permitted; all other traffic is dropped.

**K10** — **RollingUpdate** replaces pods one-by-one (zero downtime). **Recreate** kills all existing pods before starting new ones (causes downtime). Choose **Recreate** when the application does not support running two versions simultaneously (e.g., a database schema change that prevents dual-version compatibility).

**K11** — A **Namespace** is a virtual cluster used to partition resources and provide isolation between teams/projects. Default namespaces are: `default`, `kube-system`, and `kube-public`.

**K12** — `kubectl describe` provides detailed metadata and status. 3 pieces of info not in `get`: 1. **Events** (e.g., "Failed to pull image"), 2. **Container Status** (Restart counts, exit codes), 3. **Node Affinity/Taints** details.

**K13** — A **ConfigMap** stores non-confidential key-value pairs. Methods: 1. **Environment Variables** (injected into the container's env). 2. **Mounted Volumes** (files projected into a directory inside the container).

**K14** — **ClusterIP:** Internal only (default). **NodePort:** Exposes service on a specific port on every Node's IP (accessible externally). **LoadBalancer:** Provisions a cloud provider's LB to route external traffic to the service.

**K15** — A **DaemonSet** ensures that all (or some) nodes run a copy of a pod. Use it instead of a Deployment for infrastructure tasks like log collection (Fluentd), monitoring agents (Prometheus Node Exporter), or networking plugins.

**K16** — **Taints** are applied to Nodes (repel pods); **Tolerations** are applied to Pods (allow them to stay on tainted nodes). **Node Affinity** is the opposite: it's a preference/requirement on the Pod to be scheduled on specific nodes. *Use case:* Taints/Tolerations for dedicated GPU nodes; Node Affinity for ensuring a pod stays in a specific Availability Zone.

**K17** — An **Operator** is a custom controller that uses **CRDs** (Custom Resource Definitions) to manage complex, stateful applications (e.g., a Postgres Operator). It differs from a standard controller by encoding "human operational knowledge" (backups, upgrades, failovers) into code. It solves the problem of manual operational overhead for complex software.

**K18** — etcd uses the **Raft** consensus algorithm (Strong Consistency). If **quorum** is lost (e.g., 2 out of 3 nodes down), the cluster becomes read-only/unavailable for writes. To recover from 2/3 permanent losses: You must restore the etcd data from a backup to a new node, then manually force the cluster to recognize the new node as the leader.

**K19** — **Role:** Permissions in a namespace. **ClusterRole:** Permissions across the whole cluster. **RoleBinding:** Links a Role to a user/service account in a namespace. **ClusterRoleBinding:** Links a ClusterRole to a user/service account cluster-wide.
*Manifests:*
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: my-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: my-ns
subjects:
- kind: User
  name: developer-user
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — `ndots:5` means if a name has fewer than 5 dots, the resolver appends each search domain in `/etc/resolv.conf` until it finds a match. This causes many failed queries for external domains (e.g., `google.com` becomes `google.com.default.svc.cluster.local`). **Fix:** Set `dnsConfig` in the pod spec to `options: ["ndots:1"]` or use a Fully Qualified Domain Name (FQDN) ending in a dot (e.g., `google.com.`).

## Development

**D1** — **Merge** combines histories, creating a "merge commit." **Rebase** rewrites history by moving the entire branch to begin on the tip of the target branch. **Avoid rebasing** on public/shared branches because it rewrites history and causes conflicts for other collaborators.

**D2** — **TCP** is connection-oriented, reliable, and ordered (e.g., HTTP, SSH). **UDP** is connectionless, faster, and unreliable (e.g., DNS, VoIP).

**D3** — A **race condition** occurs when the output/behavior depends on the timing of uncontrollable events. *Example:* Two threads incrementing a shared variable `count++` simultaneously; both read `5`, both increment to `6`, and write `6`, losing one increment.

**D4** — **Symmetric:** Same key for encryption/decryption (fast). **Asymmetric:** Public key encrypts, Private key decrypts (secure key exchange). **TLS:** Uses Asymmetric encryption to securely exchange a Symmetric "session key," then uses Symmetric encryption for the actual data transfer.

**D5** — A **layer** is a read-only filesystem change (e.g., a `RUN` command). **Caching:** Docker reuses layers if the command hasn't changed. *Best Practice:* Put commands that change frequently (like `COPY . .`) at the bottom of the Dockerfile to maximize cache hits for dependencies (like `npm install`).

**D6** — 1. Check Application Logs (errors/exceptions). 2. Check Infrastructure Metrics (CPU/Memory/Disk). 3. Check Upstream Dependencies (Database/Third-party APIs). 4. Check Network/Load Balancer logs (timeouts/connection drops).

**D7** — **CAP Theorem:** A distributed system can only provide 2 of 3: Consistency, Availability, Partition Tolerance. *CP Example:* MongoDB/HBase (Consistency over Availability during a partition). *AP Example:* Cassandra/DynamoDB (Availability over Consistency during a partition).

**D8** — **Horizontal:** Adding more machines (scaling out). **Vertical:** Adding more power (CPU/RAM) to one machine (scaling up). **Patterns:** Statelessness, Load Balancing, Database Sharding, and Message Queues.

**D9** — An **environment variable** is a dynamic value used by processes. On Linux, set a persistent one by adding `export KEY=VALUE` to the `~/.bashrc` or `~/.zshrc` file.

**D10** — **JSON:** Lightweight, standard for web APIs. *Advantage:* Native support in almost all languages. **YAML:** Human-readable, supports comments. *Advantage:* Easier for configuration files (Kubernetes, Docker Compose).

**D11** — **REST API:** An architectural style for networked applications using HTTP. **GET:** Retrieve data. **POST:** Create data. **PUT:** Update/Replace data. **DELETE:** Remove data.

**D12** — **Version pinning** is specifying an exact version (e.g., `requests==2.25.1`). It ensures **reproducible builds** by preventing the build from breaking when a dependency releases a new, incompatible version.

**D13** — **Compiled:** Source code is converted to machine code before execution (e.g., C++, Rust). **Interpreted:** Source code is executed line-by-line by an interpreter (e.g., Python, Ruby).

**D14** — **Reverse Proxy:** Sits in front of web servers (e.g., NGINX, HAProxy) to handle load balancing, SSL termination, and caching. **Forward Proxy:** Sits in front of clients (e.g., corporate proxy) to hide client IPs or filter web access.

**D15** — A **deadlock** is a state where two or more processes are blocked forever, each waiting for the other. **Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual Consistency:** Data will eventually be the same across all nodes, but not immediately. **Cassandra:** Uses "Tunable Consistency." You can choose `ONE` (fast, low consistency), `QUORUM` (majority), or `ALL` (slow, high consistency) for read/write operations.

**D17** — **mTLS:** Both client and server present certificates to authenticate each other. **Handshake:** 1. Client sends "Hello" + Certificate. 2. Server validates Client Cert and sends its own Cert. 3. Both verify signatures against trusted CAs. 4. Session keys are established. *Use case:* Service-to-service communication in a Service Mesh (Istio/Linkerd).

**D18** — **Hash Table:** Maps keys to indices using a hash function. **Chaining:** Store collisions in a linked list at that index. **Open Addressing:** Find the next empty slot. **Complexity:** Average: O(1) for all. Worst: O(n) (if all keys hash to the same index).

**D19** — **Circuit Breaker:** Prevents a failing service from dragging down others. **Closed:** Normal operation. **Open:** Failure detected; requests fail immediately without hitting the service. **Half-Open:** Periodically allows a few requests to see if the service recovered. It works with **Retries** by ensuring we don't retry against a known-down service, and **Exponential Backoff** to space out retries.

**D20** — **Optimistic:** Assumes no conflict; checks for changes at the moment of commit (e.g., using a `version` column). Choose for high-concurrency, low-conflict apps. **Pessimistic:** Locks the record during the transaction (e.g., `SELECT FOR UPDATE`). Choose for high-conflict apps where data integrity is critical and collisions are frequent.
