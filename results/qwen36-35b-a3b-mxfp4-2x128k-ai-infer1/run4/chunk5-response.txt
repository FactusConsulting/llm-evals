DN1 — Class vs struct: `class` is a reference type allocated on the heap; `struct` is a value type allocated inline (stack or heap-embedded). Structs are copied by value, lack inheritance, and have no nullability. Use structs for small, immutable, short-lived data with value semantics (e.g., coordinates, IDs, math vectors) to avoid heap allocations and GC pressure.

DN2 — `IEnumerable<T>` executes in-memory (LINQ to Objects); `IQueryable<T>` builds expression trees that providers (like EF Core) translate to SQL. The distinction matters because `IQueryable` pushes filtering, projection, and pagination to the database, reducing memory usage and network round-trips. Using `IEnumerable` on a DB context materializes the entire table before filtering.

DN3 — `async/await` compiles to a state machine that suspends/resumes without blocking threads. `Task` represents an async operation returning a value/reference. `ValueTask` avoids heap allocation when the result is already available or the operation completes synchronously. Use `ValueTask` in hot paths, library APIs, or when async operations frequently complete synchronously.

DN4 — DI manages object creation and lifetime. `Transient`: new instance per request. `Scoped`: new per logical scope (e.g., HTTP request). `Singleton`: one instance per app lifetime. Bug: injecting a `Scoped` service into a `Singleton` captures the first request's scope, causing stale state, memory leaks, and thread-safety violations. Fix: inject into scoped/singletons only if the service is thread-safe and stateless, or use `IServiceScopeFactory` to create scopes manually.

DN5 — `string` is immutable, heap-allocated, and GC-managed. `ReadOnlySpan<char>` is a stack-allocated, zero-allocation view over contiguous memory (string, array, buffer). `Span<T>` is mutable. Use `Span<T>`/`ReadOnlySpan<T>` for high-performance parsing, slicing, or encoding to avoid allocations, copying, and GC pressure.

DN6 — GC automatically reclaims unreachable objects. Generations: Gen 0 (short-lived, frequent GC), Gen 1 (buffer), Gen 2 (long-lived, infrequent). LOH (>85KB) is collected less often and not compacted, causing fragmentation. `IDisposable` is needed for unmanaged resources (file handles, DB connections, native memory) that GC doesn't track. Use the `using` statement or explicit `Dispose()` to release them promptly.

DN7 — `ConfigureAwait(false)` tells the awaiter not to capture/restore the current `SynchronizationContext`. Use it in libraries to avoid deadlocks and improve throughput. Do NOT use it in UI/app code where you must resume on the original context (e.g., updating UI controls). It bypasses `SynchronizationContext` capture, preventing context-switching overhead.

DN8 — .NET 8/9 features: Primary constructors (`public class Service(IDep dep) { _dep = dep; }`), collection expressions (`int[] arr = [1, 2, 3];`), `FrozenDictionary` (immutable, optimized for lookup, low memory). DI example: `public record MyService([FromKeyedServices("myKey")] IDependency dep);` registers/resolves keyed dependencies inline.

DN9 — `ObjectDisposedException` under high concurrency usually means a `DbContext` is shared across requests (e.g., static field, singleton DI) or manually disposed prematurely. EF Core `DbContext` is not thread-safe and is designed to be `Scoped` (one per HTTP request). Fix: rely on DI for lifetime, never share instances, and let DI dispose it. If using manual lifetimes, wrap in `using` and ensure strict request boundaries.

DN10 — `record` is a reference type with value-based equality, immutable by default (`init` properties), and positional syntax. `record struct` is the same but value-type semantics. Choose `record` for DTOs, domain models, and immutable data. Choose `class` for mutable, reference-heavy, or polymorphic objects. Choose `record struct` for performance-critical, small, immutable data where heap allocation must be avoided.

DN11 — `ref`: passes a reference to an already-initialized variable; callee can modify caller's variable. `out`: passes a reference; callee must assign before return; caller doesn't need initialization. `in`: passes a read-only reference; prevents modification, avoids copying large structs. Use `ref` for bidirectional updates, `out` for multiple returns/initialization, `in` for large structs to avoid copy while ensuring read-only access.

DN12 — Nullable reference types (NRTs) are compile-time annotations (`string?`) that warn about potential null dereferences. `#nullable enable` activates them. They differ from nullable value types (`int?` = `Nullable<int>`) which are runtime structs with `HasValue`/`Value`. NRTs are purely compile-time; value types are actual runtime types.

DN13 — LINQ is Language Integrated Query. Method syntax (`list.Where(...).Select(...)`) is fluent and chainable. Query syntax (`from x in list where ... select x`) is SQL-like and compiles to method syntax. Deferred execution means the query isn't executed until enumerated (e.g., `foreach`, `ToList()`), enabling composition, lazy evaluation, and provider translation.

DN14 — Generic constraints restrict `T`. `class` (reference type), `struct` (value type, non-nullable), `new()` (parameterless constructor), `IComparable<T>` (implements interface). Combine with commas: `where T : class, IComparable<T>, new()`. Use when algorithms require specific capabilities (e.g., sorting, instantiation, reference semantics).

DN15 — Abstract classes support state, implementation, constructors, and single inheritance. Interfaces define contracts only. C# 8+ default interface methods allow implementation in interfaces, blurring the line. Still, abstract classes support inheritance + state; interfaces support multiple contracts + default methods + structural typing. Prefer interfaces for polymorphism/contracts, abstract classes for shared base implementation.

DN16 — Middleware pipeline is a sequence of delegates handling request/response. `Use()` adds middleware to the pipeline. `Map()` branches based on path prefix. `Run()` is terminal (no `next`). Ordering matters: auth/rate-limit before routing, error handling early. Exception handling middleware (`UseExceptionHandler`) catches unhandled exceptions, logs them, and can rewrite the response before it reaches the client.

DN17 — `Channel<T>` is a high-performance, thread-safe producer-consumer queue. Bounded channels apply backpressure by blocking producers when full. Differs from `BlockingCollection<T>` (older, less efficient, fewer features). Example: `Channel.CreateBounded<int>(10)`. Producer: `await channel.Writer.WriteAsync(item)`. Consumer: `await channel.Reader.ReadAsync()`. Backpressure naturally throttles throughput.

DN18 — Source Generators compile-time code generation via Roslyn APIs. Differs from reflection (runtime) and IL weaving (post-compilation, e.g., Fody). Incremental generators (`IncrementalGenerator`) use `IncrementalGeneratorInitializationContext`, cache results, and only re-run when inputs change, drastically improving build times. Preferred over legacy `ISourceGenerator` for performance and incremental compilation support.

DN19 — TPL Dataflow provides a pipeline/actor model. `ActionBlock` processes messages (no output), `TransformBlock` processes and outputs, `BufferBlock` stores messages. Differs from `Channels`: Dataflow offers built-in backpressure, completion propagation, linking, message filtering, and degree-of-parallelism control. Channels are simpler, lower-level primitives; Dataflow is higher-level orchestration.

DN20 — Minimal APIs map routes directly to code with minimal boilerplate. Differs from controllers: inline middleware, simpler routing, less structure. Trade-offs: less natural for complex apps, OpenAPI requires Swashbuckle/NSwag, testability uses `WebApplicationFactory`. Route groups organize endpoints with shared middleware/filters. Endpoint filters intercept execution (auth, validation, logging) before/after handlers.

P1 — List: mutable, ordered sequence. Tuple: immutable, ordered sequence. Set: unordered, unique elements, mutable. Frozenset: immutable set. Use tuples for fixed data/records, sets for membership testing/unique values, frozensets when immutability is required (e.g., dict keys).

P2 — GIL: mutex allowing only one thread to execute Python bytecode at a time. Affects CPU-bound multithreading. Workarounds: `multiprocessing` (separate processes), C-extensions that release GIL, `asyncio` (I/O bound), or Python 3.13+ free-threading (experimental).

P3 — `copy()` creates a shallow copy (new container, same object references). `deepcopy()` recursively copies. Example: `a = [[1]]; b = copy(a); b[0].append(2); a` becomes `[[1, 2]]`. Shallow copies fail when nested mutable objects are modified.

P4 — Decorators wrap functions. Example:
```python
import time, functools
def log_time(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        res = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter()-start:.4f}s")
        return res
    return wrapper
```

P5 — Generators/yield produce values lazily, preserving state between yields. Returning a list eagerly loads all values into memory. `yield from` delegates to another generator/iterable, flattening iteration. Use generators for large datasets, streams, or memory-constrained pipelines.

P6 — `asyncio` event loop manages single-threaded concurrency. `asyncio.run()` executes a coroutine. `asyncio.gather()` runs multiple coroutines concurrently, returning results. `asyncio.create_task()` schedules a coroutine, returning a `Task`. `time.sleep()` blocks the event loop; use `asyncio.sleep()` to yield control.

P7 — MRO uses C3 linearization. For `D(B, C)`, MRO is `D → B → C → A`. `D().who()` checks D (no), B (no), C (yes, returns `"C"`). Prints `"C"`. Diamond inheritance is resolved left-to-right, depth-first, ensuring each class appears once.

P8 — Metaclass: class of a class, controls class creation (`__new__`/`__init__`). `__init_subclass__`: simpler hook called when a subclass is created. Use metaclass for complex class-level manipulation (e.g., ORM model registration, plugin systems). Use `__init_subclass__` for simple subclass hooks (e.g., auto-registering commands, tracking subclasses).

P9 — Threading: I/O bound, shares memory, GIL limits CPU. Multiprocessing: CPU bound, separate processes, memory isolation, requires pickling (limits complex objects). `concurrent.futures`: high-level API wrapping both. Use threading for I/O, multiprocessing for CPU, futures for clean API and result collection.

P10 — `__slots__` restricts instance attributes to predefined names. Prevents `__dict__` creation, saving ~40-50% memory per instance and speeding up attribute access. Use for large numbers of instances with fixed attributes. Prevents dynamic attribute addition and `__weakref__` unless explicitly included.

P11 — Virtual environment: isolated Python environment with its own packages/interpreter. Prevents dependency conflicts. `venv`: stdlib, lightweight. `virtualenv`: third-party, more features. `conda`: package + env manager, handles non-Python deps, common in data science.

P12 — Comprehensions: concise syntax for creating collections (`[x for x in y]`, `{k: v for k, v in z}`). `map()`/`filter()` return iterators. Prefer comprehensions for readability and concrete collections. Use `map`/`filter` when composing functions or working with lazy evaluation.

P13 — `==`: value equality. `is`: identity (same object in memory). Object interning: Python caches small integers (-5 to 256) and short strings for performance. `a is b` returns `True` for interned values.

P14 — `*args`: variable positional args (tuple). `**kwargs`: variable keyword args (dict). `/`: positional-only parameters (before `/`). `*`: keyword-only parameters (after `*`). Used for API design, enforcing argument types, and improving function signatures.

P15 — Context managers ensure setup/teardown. `__enter__`/`__exit__` for classes. `@contextmanager` (yield-based) for functions. Example: database transaction, lock acquisition, temp directory creation, ensuring cleanup even on exceptions.

P16 — Type hinting: static type annotations. `Union`/`Optional` (pre-3.10 `|`), `Literal` (exact values), `TypeVar` (generic constraints), `Protocol` (structural typing). `mypy`/`pyright` parse hints, check consistency, catch bugs before runtime, and enable IDE autocomplete.

P17 — Data model: dunder methods define behavior. `__repr__` (dev/debug, unambiguous), `__str__` (user-friendly). `__eq__` (equality), `__hash__` (hashability). Defining `__eq__` without `__hash__` makes the object unhashable (can't be dict key/set member). `__getattr__` (fallback), `__getattribute__` (always called, dangerous to override).

P18 — Descriptors: objects implementing `__get__`, `__set__`, `__delete__` that control attribute access. `property`, `classmethod`, `staticmethod` are descriptors. Used for validation, computed attributes, lazy loading. Under the hood, they intercept attribute lookup on class instances via the descriptor protocol.

P19 — Import system: `sys.path`/`PYTHONPATH` define search paths. `__init__.py` marks directories as packages (optional in Python 3.3+ for namespace packages). Relative (`.`) vs absolute imports. Finder: locates modules. Loader: loads/executes them. Namespace packages: split across directories without `__init__.py`, merging imports.

P20 — `dataclasses`: boilerplate reduction for data containers. `attrs`: older, more flexible. `Pydantic`: validation, serialization, type coercion. `__post_init__`: post-init logic. Field factories: `field(default_factory=...)`. Frozen: immutable. Inheritance: works but defaults can be tricky. Choose Pydantic for API models, validation, serialization, and config.
