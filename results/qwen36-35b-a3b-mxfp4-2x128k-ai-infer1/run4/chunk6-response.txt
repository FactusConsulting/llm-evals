JS1 — `var` is function-scoped and hoisted with initialization to `undefined`. `let`/`const` are block-scoped, hoisted but in a Temporal Dead Zone until declaration. `const` prevents reassignment. Hoisting is the compiler behavior of moving declarations to the top of their scope during the creation phase.

JS2 — The event loop continuously checks the call stack. When empty, it drains the microtask queue (Promises, `queueMicrotask`) first, then processes one macrotask (setTimeout, I/O, UI events). This ensures async callbacks run in predictable order without blocking the main thread.

JS3 — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: a counter factory. Classic bug: `var` in `for` loops shares one variable reference, causing `setTimeout` callbacks to log the final value. Fix: use `let` (block-scoped) or wrap in an IIFE to capture the current value.

JS4 — `Promise` represents an async operation's eventual result. `async/await` syntactically flattens promise chains. Errors: `try/catch` with `await`, or `.catch()`/second `.then()` arg. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all promises, returning an array of `{status, value/reason}` objects.

JS5 — `interface` defines object shapes, supports declaration merging, and cannot hold primitives/unions. `type` is a broader alias supporting unions, intersections, tuples, and primitives. Use `interface` for APIs/contracts, `type` for complex unions/utility types. Discriminated unions use a common literal property (tag) to enable type narrowing in `switch`/`if`.

JS6 — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar: `extends` sets the prototype chain, `super` calls parent constructors/methods, but runtime behavior remains prototype-based.

JS7 — `this` is dynamically bound based on call site. Priority: 1. `new` (constructor instance), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (global or `undefined` in strict mode). `bind()` returns a new function with `this` permanently locked. It cannot be re-bound.

JS8 — `WeakRef` holds a non-preventing reference to an object; `FinalizationRegistry` triggers callbacks when the target is garbage collected. Used for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the GC can track when keys become unreachable and clean up entries automatically.

JS9 — V8 uses hidden classes (shapes) to optimize property access. Inline caching (IC) caches shape lookups based on observed object types. Deoptimization occurs when assumptions break (e.g., adding properties to different shapes, type switching, `arguments` usage). Patterns: dynamic property injection, `with` statement, type polymorphism.

JS10 — Tree-shaking removes unused exports at build time. It works with ES modules because `import`/`export` are static and lexical, enabling static analysis. CommonJS uses dynamic `require()` and `module.exports`, which can be conditionally executed, making static analysis unsafe and preventing effective tree-shaking.

JS11 — `null` is intentional absence (assigned); `undefined` is unassigned/default. `==` coerces (`null == undefined` is true); `===` is strict (false). `??` returns right operand if left is `null`/`undefined`. `?.` safely accesses nested properties, returning `undefined` instead of throwing on `null`/`undefined`.

JS12 — `map()` transforms elements, `filter()` keeps matching ones, `reduce()` accumulates to a single value. `reduce()` with an initial value prevents `undefined` on empty arrays and sets the accumulator type. `flatMap()` maps then flattens one level; useful when each element produces multiple outputs.

JS13 — Template literals use backticks, support `${}` interpolation and multi-line strings. Tagged templates pass literal parts and values to a function. Example: an `html` tag function that escapes values to prevent XSS by iterating over strings/values and sanitizing them before reconstruction.

JS14 — Destructuring unpacks arrays/objects. Object: `{a, b}` or `{a: x}`. Array: `[a, b]`. Defaults: `{a = 1}`. Renaming: `{a: newName}`. Rest: `{...rest}` collects remaining properties. Works in assignments, parameters, and loops.

JS15 — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, maps). Avoid `for...in` on arrays because it iterates keys, not values, includes prototype properties, and doesn't guarantee order.

JS16 — Generics parameterize types. Constraints: `T extends Base` limits T. Conditional types: `T extends U ? X : Y` for type logic. `infer` extracts types in conditional contexts. Example: `type Unwrap<T> = T extends Promise<infer U> ? U : T`.

JS17 — CJS: synchronous, object-based (`require`/`module.exports`), Node's historical default. ESM: asynchronous, static syntax (`import`/`export`), standard. Node supports both via `.mjs` or `"type": "module"` in `package.json`. ESM enables tree-shaking, top-level await, and strict module semantics.

JS18 — Structural typing checks compatibility by shape, not names. Excess property checks apply only when assigning object literals directly to a type to catch typos. `extends` defines subtyping. `satisfies` validates shape while preserving specific type info. Variance: `in` (contravariant/parameters), `out` (covariant/returns), `in out` (bivariant). TS 4.7+ adds `in`/`out` modifiers to generics.

JS19 — `Proxy` intercepts object operations (get, set, apply, has, etc.). `Reflect` mirrors traps and provides default behavior. Example: a validation proxy that throws on invalid assignment, or a reactive proxy that tracks dependencies for state management by intercepting property access/assignment.

JS20 — `SharedArrayBuffer` enables shared memory between main thread and Web Workers. `Atomics` provides synchronization primitives (load, store, add, wait, notify). Ordering: sequential consistency. `Atomics.wait` blocks until value changes or timeout. `Atomics.notify` wakes threads. Requires cross-origin isolation headers.

B1 — `$@` expands to separate quoted words (`"$1" "$2"...`), preserving individual arguments. `$*` expands to a single string (`"$1 $2..."`). `"$@"` is safe for argument passing; `"$*"` joins them, breaking array semantics.

B2 — `set -e`: exit on command failure. `-u`: error on unset variables. `-o pipefail`: pipe returns rightmost non-zero exit code. Together, they prevent silent failures, undefined var usage, and masked pipeline errors.

B3 — `$(command)` and `` `command` `` are command substitution; `$(...)` is nestable and preferred. `$((expression))` is built-in arithmetic expansion. `expr` is an external command; `$(( ))` is faster, supports more operators, and avoids subshell overhead.

B4 — Process substitution `<(command)` creates a file descriptor (e.g., `/dev/fd/63`) with command output. Used when commands expect files but need dynamic input. Example: `diff <(sort file1) <(sort file2)`.

B5 — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous due to word splitting on spaces/newlines, glob expansion altering names, and fragile parsing of `ls` output.

B6 — Here document `<<EOF` passes multi-line stdin. Here string `<<<` passes a single string. `<<-EOF` strips leading tabs (not spaces) from the delimiter line, allowing indented heredocs without affecting content.

B7 — `cmd > file 2>&1`: stdout → file, then stderr → stdout (now file). `cmd 2>&1 > file`: stderr → current stdout (terminal), then stdout → file (stderr stays on terminal). `cmd &> file`: bash shorthand for both to file. Order of evaluation causes the difference.

B8 — ```bash
lock() {
  local lockdir
  lockdir=$(mktemp -d)
  trap 'rm -rf "$lockdir"' EXIT INT TERM
  mkdir "$lockdir" || { echo "Locked"; exit 1; }
  echo "Lock acquired: $lockdir"
}
```
`mkdir` is atomic on POSIX; it fails if the directory exists, avoiding TOCTOU race conditions inherent in file creation.

B9 — Single quotes: literal, no expansion. Double quotes: allow `$`, `` ` ``, `\`, `!` expansion. No quotes: word splitting & globbing. Example: `var="hello world"; echo '$var'` → `$var`; `echo "$var"` → `hello world`; `echo $var` → `hello world` (splits/globs).

B10 — Checks: `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin supporting `&&`, `||`, regex, and no word splitting/globbing on RHS. `[ ]` is POSIX, requires spaces, and is stricter.

B11 — `$?`: last command exit status. `$$`: current script PID. `$!`: last background job PID. `#$`: number of positional parameters. Use cases: error handling, logging PID, job control, argument validation.

B12 — `foo() { ... }` (POSIX) vs `function foo { ... }` (bash-specific). Return values: `return` sets exit code (0-255). For data, use stdout, global variables, or `declare -n` namerefs.

B13 — `PATH`: colon-separated dirs bash searches for executables. Resolution order: builtins → aliases → external commands in `PATH`. Builtin: part of shell (`cd`, `echo`). External: separate binary. Check with `type` or `command -v`.

B14 — `trap` registers handlers for signals/events. `trap 'cleanup' EXIT INT TERM ERR`. Handlers run in LIFO order. Multiple signals queue and execute sequentially. `ERR` triggers on non-zero exit.

B15 — `xargs` builds/ executes commands from stdin, handles batching. `$(...)` replaces text. `xargs -0` + `find -print0` handles spaces/newlines safely. `xargs -P N` runs N processes in parallel.

B16 — Indexed: `arr=(a b c)`, append `arr+=("d")`, iterate `for i in "${arr[@]}"`, length `${#arr[@]}`. Associative: `declare -A assoc`, set `assoc[key]=val`, iterate keys/values similarly. Assoc requires `declare -A`, supports string keys.

B17 — Subshell `(cmd)` runs in child; changes don't affect parent. Group `{ cmd; }` runs in current shell. Piping to `while` creates a subshell, losing variable changes. Fix: `while ... done < <(cmd)` or use process substitution.

B18 — SIGINT (interrupt), SIGTERM (graceful), SIGHUP (reload), SIGKILL (force, uncatchable). Handle graceful shutdown: trap SIGTERM, `wait` for background jobs, cleanup, exit. Use `wait` to monitor children.

B19 — `split -l 10000 log.log log.part.`, `find . -name "log.part.*" -print0 | xargs -0 -P 4 -I {} bash -c 'process "$1"' _ {}`, merge with `cat log.part.* > merged.log`. Trade-offs: I/O vs CPU, process overhead. Error propagation: `set -o pipefail`, check exit codes, log to stderr, aggregate in merge.

B20 — `exec` replaces the shell or redirects file descriptors. `exec 3>file` opens fd 3, `exec 3>&-` closes it. Coprocess: `coproc cmd` creates bidirectional pipe for parent/child communication. Use for persistent background tasks or interactive daemons.

PS1 — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console, bypassing the pipeline and breaking automation. Distinction matters for scripting, piping, and redirection.

PS2 — Pipeline streams objects. `ForEach-Object` is a cmdlet, processes objects one-by-one, supports `-Parallel`. `foreach` is a language construct, faster for known collections, doesn't stream. Use `ForEach-Object` for pipelines, `foreach` for in-memory arrays.

PS3 — `[PSCustomObject]`: strongly-typed, ordered, pipeline-friendly. Hashtable: unordered, key-value, faster lookups. Convert: `[PSCustomObject]$hashtable` or `[ordered]@{...}`. Use PSCustomObject for output/objects, hashtable for config/lookups.

PS4 — Terminating errors stop execution and are caught by `try/catch`. Non-terminating errors continue and log to `$Error`. `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors.

PS5 — Splatting `@params` passes a hashtable as named parameters. Expands to multiple arguments, unlike passing a hashtable as a single parameter. Example: `Get-ChildItem @commonParams`. Cleaner, reusable parameter sets.

PS6 — `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` creates an interactive session. Uses WS-Management (WinRM) by default. PS 7+ supports SSH remoting via OpenSSH.

PS7 — `$result += "one"` creates an array. `return $result` returns `Object[]`. `$x.GetType().Name` → `Object[]`. If 0 items, returns `$null`. Correct pattern: `[array]$result = @()` or `return @("one")` to ensure consistent typing and avoid pipeline scalar/array confusion.

PS8 — `[scriptblock]` is anonymous code; function is named. Pass to remote via `Invoke-Command -ScriptBlock $sb`. Double-hop: auth fails when remoting to B then to C. Solve with CredSSP (insecure), `-ArgumentList` to pass data, or constrained remoting/delegation.

PS9 — `@()` forces array. `[array]` is a type constraint. Indexing `$null` returns `$null`. Indexing empty array returns `$null`. Single pipeline result becomes scalar; use `@()` to force array.

PS10 — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive: `-ceq`, `-clike`, `-cmatch`. `-contains` checks collection membership; `-in` checks item membership (PS 3+).

PS11 — Module: collection of commands. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies). Binary: compiled `.dll`. `Import-Module` loads into session, searches `$env:PSModulePath`.

PS12 — Interpolation: `"..."` expands variables/expressions. `'...'` literal. Expressions: `$(...)` or `${...}`. Here-string: `@"..."@` allows multi-line interpolation.

PS13 — `Get-Member` explores object members. Properties (data), Methods (actions), NoteProperties (custom). `Select-Object` picks properties/creates new objects. `Where-Object` filters objects based on conditions.

PS14 — Classes (v5+): define types. Differ from C#: no access modifiers, single inheritance only, no interfaces, constructors use `ClassName() {}`. Limitations: no overloading, limited reflection. Use for complex data structures, not simple scripts.

PS15 — `CmdletBinding` enables advanced features. `SupportsShouldProcess`: `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: selects params. `ValueFromPipeline`: binds pipeline input. `Begin`/`Process`/`End`: lifecycle blocks. `Process` runs per pipeline object.

PS16 — Providers abstract data stores. `Get-ChildItem` works on FileSystem, Registry, Cert, Env. Registry accessed as `HKLM:\SOFTWARE\...` like files. Providers translate cmdlets to store-specific operations.

PS17 — Runspaces: execution environments. `[runspace]`: single thread. `[runspacepool]`: thread pool. `[powershell]`: command wrapper. `ForEach-Object -Parallel` (v7+): easy parallelism. Manual runspace: complex, full control, thread-safe via synchronization.

PS18 — PSScriptAnalyzer: linting tool. Rules: style, performance, correctness. Severity: error, warning, info. Custom rules: PowerShell scripts. Suppress: `#pragma` or config file. CI/CD: run in pipeline, fail on errors.

PS19 — `$using:` scope serializes variables for remote/parallel contexts. `-ArgumentList` passes values explicitly. Serialization limits: CLIXML depth/size limits; complex objects may fail. Use simple types or serialize manually.

PS20 — DSC: declarative config. Configurations: desired state. Resources: components (File, Service). LCM: applies config, checks drift. WinPS vs PS7: PS7 uses MOF-less, JSON-based, cross-platform. Replaced by: Terraform, Ansible, Chef, or native cloud IaC.
