JS1 — `var` is function-scoped and hoisted with initialization to `undefined`. `let`/`const` are block-scoped, hoisted but in a Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment. Hoisting is the compiler behavior of moving declarations to the top of their scope during the creation phase.

JS2 — The event loop continuously checks if the call stack is empty. If empty, it drains the microtask queue (Promises, `queueMicrotask`) completely, then processes one macrotask (setTimeout, I/O, UI events). Microtasks always run before the next macrotask, ensuring promise resolution isn't delayed by timers.

JS3 — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: a counter factory. Classic bug: `var i` in a `for` loop shares one closure scope; all callbacks reference the final `i`. Fix: use `let i` (block-scoped) or an IIFE to capture the current value.

JS4 — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that makes promise chains sequential. Error handling: `try/catch` with `await`, or `.catch()`/second argument for promises. `Promise.all` fails fast on first rejection. `Promise.allSettled` waits for all, returning `{status, value/reason}` per promise.

JS5 — `interface` defines only object shapes, supports declaration merging, and cannot implement logic. `type` is broader (unions, intersections, primitives, function signatures). Use `interface` for API contracts/inheritance, `type` for unions/utility types. Discriminated unions use a common literal property (tag) to enable safe type narrowing in `switch`/`if`.

JS6 — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar: `class` defines a constructor, `extends` sets the prototype chain, and `super` calls parent constructors/methods.

JS7 — `this` is dynamically bound based on call site. Priority: 1. `new` (constructor), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (global or `undefined` in strict mode). `bind()` returns a new function with `this` permanently bound. It cannot be re-bound.

JS8 — `WeakRef` holds a weak reference that doesn't prevent GC. `FinalizationRegistry` triggers callbacks when targets are collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the GC can track when they're collected and clean up entries; primitives can't be garbage collected, breaking the weak reference contract.

JS9 — V8 uses hidden classes (shapes) to optimize property access. Inline caching (IC) caches shape lookups at call sites. Deoptimization occurs when assumptions break: dynamic property addition, type changes, `eval`, `with`, or `arguments` usage. V8 drops optimized code and falls back to generic interpreters.

JS10 — Tree-shaking removes unused exports at build time. It works with ES modules because imports/exports are static and analyzable at compile time. CommonJS uses `require()` (dynamic/runtime), so bundlers can't statically determine what's unused, making effective tree-shaking impossible.

JS11 — `null` is intentional absence; `undefined` is uninitialized/missing. `==` coerces types (`null == undefined` is `true`); `===` checks type & value (`false`). `??` returns right operand if left is `null`/`undefined`. `?.` safely accesses nested properties without throwing on `null`/`undefined`.

JS12 — `map` transforms, `filter` selects, `reduce` accumulates. `reduce` with an initial value prevents `undefined` on empty arrays and sets accumulator type. `flatMap` maps then flattens one level; useful when each element produces multiple outputs (e.g., splitting strings into arrays).

JS13 — Template literals use backticks, support `${expr}` interpolation and multiline. Tagged templates pass string parts and expressions to a function. Example: `sql` tag for parameterized queries or `html` tag for escaping: `html`<div>${user.name}</div>`.

JS14 — Destructuring unpacks arrays/objects: `{a, b}` or `[a, b]`. Defaults: `{a = 1}`. Renaming: `{a: x}`. Rest: `{...rest}` collects remaining keys. Works in assignments, parameters, and loops. Prevents verbose property access.

JS15 — `for...in` iterates enumerable string keys (including inherited). `for...of` iterates iterable values (arrays, strings, maps). Avoid `for...in` on arrays: iterates keys not values, includes inherited properties, order isn't guaranteed, and performance is poor.

JS16 — Generics parameterize types. Constraints: `T extends Base` limits T. Conditional types: `T extends U ? X : Y` for type logic. `infer` extracts types in conditional contexts. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T`.

JS17 — CJS: synchronous, `require`/`module.exports`, object caching. ESM: asynchronous, `import`/`export`, static analysis, tree-shaking. Node.js defaults to CJS; ESM via `.mjs` or `"type": "module"` in `package.json`. The field tells Node to treat `.js` as ESM.

JS18 — Structural typing checks compatibility by shape, not names. Excess property checks apply only during object literal creation to catch typos. `extends` defines assignability; `satisfies` checks type without widening, preserving specific info. Variance (`in`/`out`) controls generic parameter mutability; TS 4.7+ supports explicit annotations.

JS19 — `Proxy` wraps objects to intercept operations (get, set, apply, etc.). `Reflect` mirrors traps and provides default behavior. Example: validation proxy intercepts `set`, checks types before assignment. Reactive binding: Proxy tracks dependencies on `get`, triggers updates on `set`.

JS20 — `SharedArrayBuffer` shares memory between main thread and Web Workers. `Atomics` provides synchronization (load, store, add, wait, notify). Ordering: sequential consistency. `Atomics.wait` blocks until value changes/timeout. `Atomics.notify` wakes threads. Requires cross-origin isolation headers.

B1 — `$@` expands to separate quoted words (`"$1" "$2"`), `$*` expands to a single string (`"$1 $2 ..."`). `"$@"` preserves individual arguments. `"$*"` joins them with IFS. Use `"$@"` for safe argument forwarding.

B2 — `set -e`: exit on error. `-u`: treat unset vars as error. `-o pipefail`: pipeline returns rightmost non-zero exit code. Prevents silent failures, undefined var bugs, and masked pipeline errors.

B3 — `$(command)` is modern; `` `command` `` is legacy. `$((expression))` is native arithmetic expansion. `expr` is an external command, slower, and less robust. Prefer `$(( ))`.

B4 — Process substitution `<(cmd)` creates a temp file descriptor. `diff <(sort a) <(sort b)` compares sorted streams without temp files. Use when commands expect file paths but produce streams.

B5 — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous: word splitting on spaces/newlines, glob expansion, breaks on special chars, ignores hidden files.

B6 — `<<EOF` is a here document (multi-line input). `<<<` is a here string (single line). `<<-EOF` strips leading tabs from the marker line for indentation.

B7 — `cmd > file 2>&1`: stdout → file, then stderr → stdout (now file). `cmd 2>&1 > file`: stderr → original stdout (terminal), then stdout → file → stderr goes to terminal. `cmd &> file`: both to file. Order matters because redirections evaluate left-to-right.

B8 — ```bash
lock() {
  local lockdir="/tmp/$(basename "$0").lock"
  if ! mkdir "$lockdir" 2>/dev/null; then
    echo "Already running" >&2; exit 1
  fi
  trap 'rm -rf "$lockdir"' EXIT INT TERM
  # critical section
}
```
`mkdir` is atomic on POSIX; it fails if the directory exists, unlike `touch`. Traps ensure cleanup on exit/error/signals.

B9 — `'...'`: literal, no expansion. `"..."`: allows `$var`/`$(cmd)`, preserves spaces. No quotes: word splitting & globbing. Example: `var="a b"; echo $var` → `a b`; `echo "$var"` → `a b`; `echo '$var'` → `$var`.

B10 — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin: supports `&&`/`||`, regex, no word splitting/globbing, safer. `[ ]` is POSIX `test`, stricter and slower.

B11 — `$?`: last exit code. `$$`: script PID. `$!`: last background job PID. `$#`: argument count. Use cases: error checking, logging PID, `wait $!`, validating input count.

B12 — `foo() { ... }` or `function foo { ... }` (latter allows `function foo()`). Return values: `return` sets exit code (0-255); use `echo` for stdout or global vars for complex data. Functions share scope.

B13 — PATH: colon-separated dirs for command lookup. Bash resolves: aliases → functions → builtins → PATH. `type cmd` or `command -v cmd` shows which. Builtins are faster; external require fork/exec.

B14 — `trap 'cleanup' EXIT ERR INT TERM`. ERR triggers on command failure, EXIT on script end, signals interrupt. Multiple signals: last trap wins, handlers run sequentially. Use `trap - ERR` to disable.

B15 — `xargs` builds/invokes commands from stdin, handles batching. `find -print0 | xargs -0` handles spaces/newlines safely. `xargs -P N` runs N processes in parallel. Cmd substitution runs once; xargs batches.

B16 — Indexed: `arr=(a b c)`, append `arr+=("d")`, iterate `for i in "${arr[@]}"`, length `${#arr[@]}`. Associative: `declare -A assoc`, set `assoc[key]=val`, iterate keys/values similarly. Syntax differs in declaration and key access.

B17 — Subshell `(cmd)` runs in child; changes don't affect parent. Group `{ cmd; }` runs in current shell. Piping `cmd | while read` runs `while` in subshell, losing var changes. Fix: `while read ... done < <(cmd)`.

B18 — SIGINT (Ctrl+C, interrupt), SIGTERM (graceful stop), SIGHUP (terminal close/reload), SIGKILL (force kill, uncatchable). Graceful shutdown: trap SIGTERM, `wait` for bg jobs, cleanup, exit. Use `trap` and `wait`.

B19 — `split -l 10000 log.log log.part.`, `find . -name "log.part.*" -print0 | xargs -0 -P 4 -I {} bash -c 'process "$1"' _ {}`. Merge: `cat log.part.* > merged.log`. Trade-offs: I/O vs CPU, process overhead. Error propagation: check exit codes, `set -o pipefail`, aggregate errors in temp files.

B20 — `exec` replaces shell or redirects FDs. `exec 3>file` opens FD 3, `exec 3>&-` closes it. Coprocess: `coproc cmd` creates bidirectional pipe for parent/child IPC. Use for persistent background tasks or streaming data.

PS1 — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console (bypasses pipeline). Distinction matters: `Write-Host` breaks pipeline chaining, causing issues in scripts/functions expecting output.

PS2 — Pipeline streams objects. `ForEach-Object` (`%`) processes each object in the stream. `foreach` statement iterates over a collection in memory. Use `ForEach-Object` for streaming/large data, `foreach` for known collections/memory-safe iteration.

PS3 — `[PSCustomObject]`: strongly typed, ordered, pipeline-friendly. `[hashtable]`: unordered, key-value, slower, less pipeline support. Convert: `[PSCustomObject]@{a=1}` or `@{a=1} | ForEach-Object { [PSCustomObject]$_ }`.

PS4 — Terminating errors stop execution; non-terminating continue. `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors. Use `-ErrorAction Stop` to convert non-terminating to terminating.

PS5 — Splatting: `@params` passes a hashtable as named parameters. `Get-Process @params`. Differs from single param: splatting expands to multiple arguments; single param passes the entire hashtable as one value.

PS6 — `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` is interactive. Uses WinRM (HTTP/HTTPS) by default; PowerShell 7+ supports SSH remoting.

PS7 — `$result += "one"` creates an array. `return $result` returns `Object[]`. `$x.GetType().Name` → `Object[]`. If 0 items, returns `$null`. Correct pattern: `[array]$result = @()` or `,$result` to prevent enumeration.

PS8 — `[scriptblock]` is anonymous code; function is named. Pass to remote: `Invoke-Command -ScriptBlock $sb`. Double-hop: auth fails when remoting to a second server. Solve with CredSSP (insecure) or `-ArgumentList`/SSH.

PS9 — `@()` forces array. `[array]` is a type constraint. Index `$null[0]` → error, `$arr[0]` on empty → `$null`. Force single result: `,$singleValue`.

PS10 — `-eq` (equal), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive: `-ceq`, `-clike`, `-cmatch`, `-ccontains`, `-cin`. `-contains` checks collection; `-in` checks item (reversed operands).

PS11 — Module: `.psm1` (code), `.psd1` (manifest/metadata), binary (compiled .dll). `Import-Module` loads into session, respects manifest, exports functions/cmdlets, manages scope/version.

PS12 — String interpolation: `"..."` expands variables/expressions `${expr}`. `'...'` literal. Here-string `@"..."@` allows multi-line interpolation.

PS13 — `Get-Member` explores object members. Properties (data), Methods (actions), NoteProperties (custom). `Select-Object` picks properties; `Where-Object` filters based on conditions.

PS14 — Classes (v5+): define types, properties, methods. Limitations: no multiple inheritance, limited interface support, constructors must match signatures. Use classes for complex data models; functions for scripting/utility.

PS15 — `CmdletBinding`: enables advanced features. `SupportsShouldProcess` adds `-WhatIf`/`-Confirm`. `DefaultParameterSetName` sets default. `ValueFromPipeline` allows pipeline input. `Begin`/`Process`/`End` blocks: init, per-object processing, cleanup.

PS16 — Providers abstract data stores. `Get-ChildItem` works on FileSystem, Registry (`HKLM:`), Certificates (`Cert:`), Environment. Registry accessed as `HKLM:\SOFTWARE\...` like files.

PS17 — Runspaces: execution environments. `[runspace]` single, `[runspacepool]` manages multiple. `[powershell]` object runs commands. `ForEach-Object -Parallel` (v7+) uses runspace pool automatically. Manual runspace: higher control, complex setup.

PS18 — PSScriptAnalyzer: linting tool. Rules check style, performance, security. Severity: error, warning, info. Suppress: `#pragma disable`, config file. CI/CD: run in pipeline, fail on errors, enforce standards.

PS19 — `$using:` scope serializes variables into remote/job/parallel context. `-ArgumentList` passes values safely. CLIXML serialization limits depth/size, breaks on complex objects/circular refs. Use `-ArgumentList` or `$using:` for simple types.

PS20 — DSC: declarative config. Configurations define state, resources implement it, LCM applies/enforces. WinPS DSC uses MOF; PS7+ uses JSON. Modern replacement: Ansible, Terraform, Chef, or native cloud IaC. DSC remains in Windows ecosystems but less dominant.
