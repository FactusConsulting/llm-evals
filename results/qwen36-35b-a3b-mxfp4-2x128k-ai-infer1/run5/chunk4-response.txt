G1 — Arrays have fixed compile-time size `[N]T` and are value types. Slices are dynamic runtime descriptors containing a pointer, length, and capacity over an underlying array. Appending to a full slice triggers reallocation (typically doubling capacity), copies elements to a new backing array, and returns a new slice header pointing to it.

G2 — `var x int` declares with explicit type and zero value `0`. `x := 0` is short variable declaration, infers type, and can only appear inside functions. `:=` cannot be used in package-level declarations, cannot redeclare a variable in the same scope without assigning to at least one new variable, and cannot be used with `const` or `var`.

G3 — Goroutines are lightweight user-space threads (~2–4KB stack) multiplexed by the Go runtime. OS threads are kernel-managed (~1–2MB stack). The GMP model: G (goroutine), M (machine/OS thread), P (processor/scheduler context). The scheduler runs on Ps, multiplexing Gs onto Ms using work-stealing and non-blocking queues, enabling high concurrency with minimal OS thread overhead.

G4 — Channels are typed conduits for goroutine communication. Unbuffered channels block sender and receiver until both are ready. Buffered channels queue messages; send blocks only when full, receive blocks only when empty. Sending to a full buffered channel blocks until space opens or the channel is closed.

G5 — `context` propagates cancellation, deadlines, and request-scoped values across API boundaries. Minimal example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
http.DefaultClient.Do(req) // automatically cancels on timeout
```

G6 — Go uses structural (duck) typing: any type implementing an interface's methods satisfies it implicitly. Java/C# require explicit declaration. `interface{}`/`any` accepts any type. Powerful for flexible APIs, but dangerous because it bypasses compile-time type safety, requiring runtime type assertions that can panic.

G7 — Unsafe due to data race: no synchronization guarantees `data` write happens-before `ready` read. The loop also busy-waits, wasting CPU. Fixes: use `sync/atomic` for visibility, or channels (`ch := make(chan string); go func(){ ch <- "hello" }(); data := <-ch`), or `sync.Once`/mutex.

G8 — `Mutex` allows exclusive access; `RWMutex` allows concurrent readers or one writer. `sync.Map` optimizes for read-heavy or disjoint-key workloads, avoiding mutex contention. Trade-offs: `sync.Map` has higher memory overhead and slower writes/reads for hot paths vs a plain `map` + `Mutex`.

G9 — Modules version dependencies. `go.mod` declares direct deps and Go version; `go.sum` cryptographically hashes dependency versions for integrity. `go mod tidy` removes unused deps, adds missing ones, and updates `go.sum`. MVS selects the minimum version satisfying all direct/indirect requirements to prevent dependency bloat.

G10 — `defer` schedules a call to run after the surrounding function returns. Multiple defers execute in LIFO order. Gotcha in loops: loop variables are captured by reference, so all defers see the final value. Fix: pass loop variable as argument to deferred function or shadow it inside the loop.

G11 — A pointer holds a memory address. Zero value is `nil`. Create pointer to struct literal: `p := &MyStruct{Field: 1}`.

G12 — `init()` runs automatically before `main()` during package initialization. Runs once per package. Multiple `init()` functions in a file execute in source order; across files, order is deterministic per package load but unspecified. Overuse harms testability and should be avoided.

G13 — `new(T)` allocates zeroed memory of type `T` and returns `*T`. `make(T, args...)` allocates and initializes internal data structures for slices, maps, and channels, returning the value itself (not a pointer).

G14 — Errors are values implementing `error` interface (`Error() string`). Idiomatic: `if err != nil { return err }`. `errors.Is(err, target)` checks if error wraps target; `errors.As(err, &target)` extracts wrapped error type. `==` only checks exact equality, failing with wrapped/custom errors.

G15 — `map`: `nil` (readable, write panics); `slice`: `nil` (len/cap 0, append works); `channel`: `nil` (blocks forever); `struct`: fields set to their type's zero values.

G16 — Race condition: concurrent unsynchronized access to shared data causing unpredictable behavior. `-race` flag instruments code to detect concurrent reads/writes. Example: `var c int; go func(){ c++ }(); c++`. Fix: `sync.Mutex` or channel `ch := make(chan int); go func(){ ch <- 1 }(); <-ch`.

G17 — `select` waits on multiple channel operations. Unlike `switch`, it evaluates cases randomly if multiple are ready (no fallthrough). Timeout via `time.After`: `select { case <-ch: ... case <-time.After(1*time.Second): ... }`.

G18 — Escape analysis determines if variables live on stack (fast, auto-freed) or heap (slower, GC-managed). Decides based on lifetime: if variable outlives function, it escapes. Inspect with `go build -gcflags="-m"`. Matters because heap allocations increase GC pressure and reduce cache locality.

G19 — `reflect` inspects/manipulates types/values at runtime. `reflect.Type` is metadata; `reflect.Value` is the actual data. Costs: slow, bypasses compile-time checks, generates GC roots. Justified for serialization, testing, or generic frameworks; prefer code generation (`go generate`) for performance-critical paths.

G20 — `go:embed` embeds files/dirs into binary at compile time. Works with single files, directories (`//go:embed dir/`), and glob patterns. Limitations: only static files, no runtime modification, must be in same package. Returns an `embed.FS` implementing `io/fs.FS`, enabling standard filesystem APIs on embedded data.

R1 — Ownership ensures memory safety without GC. Rules: 1) Each value has exactly one owner. 2) Owner drops value when out of scope. 3) Only one mutable reference (`&mut T`) or multiple shared references (`&T`) allowed at a time.

R2 — `String` is heap-allocated, growable, owned. `&str` is a borrowed UTF-8 byte slice (from `String`, literal, or slice). Use `String` for ownership/modification; use `&str` in function signatures to avoid allocations and accept both literals and owned strings.

R3 — Borrowing grants temporary access without transferring ownership. Rules: 1) Any number of `&T` or exactly one `&mut T`. 2) References must always be valid. 3) No simultaneous mutable and shared references. Borrow checker enforces these at compile time.

R4 — `Result<T, E>` represents success/failure; `Option<T>` represents presence/absence. `?` operator propagates errors/returns `None` early. Example:
```rust
use std::fs;
fn read_file(path: &str) -> Result<String, std::io::Error> {
    fs::read_to_string(path)
}
```

R5 — `Box<T>`: heap-allocated, single owner, used for large types or recursive types. `Rc<T>`: reference-counted, single-threaded shared ownership. `Arc<T>`: atomic reference-counted, thread-safe shared ownership. Use `Arc` across threads; `Rc` otherwise; `Box` for ownership/size.

R6 — Traits define shared behavior. Like Go interfaces but require explicit implementation. Trait object `dyn Trait` enables dynamic dispatch (vtable, heap allocation, type erasure). Generic `T: Trait` uses static dispatch (monomorphization, zero-cost, code bloat).

R7 — Fails because compiler can't determine which input lifetime the output borrows from. Fix: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { if x.len() > y.len() { x } else { y } }`. Assumes both inputs live at least as long as the output.

R8 — `Send`: type can be transferred across threads. `Sync`: type can be shared across threads (`&T` is `Send`). `Rc<T>` isn't `Send`/`Sync` due to non-atomic ref count. `Arc<T>` uses atomic operations for ref counting, making it thread-safe.

R9 — `async`/`await` compiles to a state machine implementing `Future`. The future holds state and resumes on `.poll()`. Executors (Tokio, async-std) drive futures, multiplexing I/O and CPU tasks. Differs from Go: Go uses cooperative scheduling in runtime threads; Rust futures are lazy and polled by user-space executors.

R10 — `unsafe` bypasses compile-time safety checks. Three things: 1) Dereference raw pointers. 2) Call `unsafe` functions. 3) Access/modify `static mut`. Justified when interfacing with C, implementing low-level primitives, or optimizing performance where safety is proven manually.

R11 — Pattern matching deconstructs values. `match` is exhaustive and can bind variables; `if let` is a shorthand for a single case. Compiler enforces exhaustiveness in `match`, requiring `_` or explicit handling of all variants to prevent runtime panics.

R12 — `[T; N]` is fixed-size, stack-allocated (usually), known at compile time. `Vec<T>` is heap-allocated, dynamically sized. When capacity is exceeded, `Vec` allocates a larger array, copies elements, and drops the old one (typically doubles capacity).

R13 — Rust enums can hold data per variant (algebraic data types), unlike C/Java enums which are just named integers. `Option<T>` is `enum Option<T> { Some(T), None }`. Rust has no `null`; `Option` forces explicit handling, eliminating null pointer exceptions.

R14 — `impl` blocks define methods/associated functions. `&self`: borrows instance, can't modify. `&mut self`: mutable borrow, can modify. `self`: takes ownership, consumes instance. Associated functions (`String::new()`) don't take `self`, act like static methods.

R15 — `derive` auto-implements common traits. Examples: `#[derive(Debug, Clone, PartialEq, Serialize)]`. Cannot derive if the type contains fields that don't implement the trait (e.g., `Fn` closures, raw pointers, or custom logic required).

R16 — `Cow<'a, T>` (Clone on Write) holds either a borrowed `&'a T` or an owned `T`. Useful when a function might return borrowed or owned data. Example: `fn process(s: &str) -> Cow<str> { if s.contains("X") { Cow::Owned(s.replace("X", "Y")) } else { Cow::Borrowed(s) } }` avoids allocation when no modification is needed.

R17 — Module system organizes code. `mod` declares a module; `use` imports names into scope; `pub` exposes items. File system maps: `mod.rs` or `mod_name.rs` in same dir, or `mod_name/mod.rs` with `mod_name.rs` for submodules. Rust 2018 unified path resolution (`crate::`, `self::`, `super::`) and removed `extern crate`.

R18 — `Pin<T>` ensures a value's memory address doesn't move. Needed for self-referential structs and async/await (futures may hold references to their own fields). `Unpin` is a marker trait indicating a type can be safely moved; most types are `Unpin`, but async futures are `!Unpin`.

R19 — Macros generate code. Declarative (`macro_rules!`) uses pattern matching for syntax transformation. Procedural (derive, attribute, function-like) runs as Rust code during compilation, operating on AST. Hygiene ensures macro-generated identifiers don't accidentally capture or shadow outer scope variables.

R20 — Zero-cost abstractions: high-level features compile to efficient machine code. Iterators use zero-cost abstractions via inlining and loop unrolling. Generics use monomorphization (compiler generates specialized code per type). Trait static dispatch uses compile-time resolution. Result: performance matches hand-written C with ergonomic safety.
