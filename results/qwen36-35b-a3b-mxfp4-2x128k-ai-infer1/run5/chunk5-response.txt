**DN1** — `class` is a reference type allocated on the managed heap; `struct` is a value type typically allocated on the stack or inline. Use `struct` for small, immutable, short-lived data (e.g., coordinates, IDs, math vectors) to avoid heap allocations and GC pressure. Avoid structs with large fields or mutable state due to copy semantics and stack/inline overhead.

**DN2** — `IEnumerable<T>` represents in-memory collections; LINQ queries compile to delegates and execute in-process. `IQueryable<T>` represents query expressions (expression trees) that can be translated to other languages (e.g., SQL). The distinction matters because `IQueryable` pushes filtering/joining to the database, reducing network traffic and memory usage, while `IEnumerable` pulls all data into memory first.

**DN3** — `async/await` compiles to a state machine that captures context, yields control, and resumes when the awaited operation completes. `Task` is a reference type (heap-allocated); `ValueTask` is a value type that avoids allocations when a method completes synchronously or returns a cached result. Use `ValueTask` for hot paths, synchronous-heavy methods, or when wrapping existing `Task`/`T` results to reduce GC pressure.

**DN4** — DI containers manage object creation and lifecycle. `Transient`: new instance per request. `Scoped`: new instance per logical scope (e.g., HTTP request). `Singleton`: one instance per container lifetime. **Captive dependency bug**: injecting a `Scoped` service into a `Singleton` keeps the scoped instance alive for the app's lifetime, causing memory leaks, stale state, and thread-safety issues.

**DN5** — `string` is immutable, heap-allocated, and triggers GC. `ReadOnlySpan<char>` is a stack-only, zero-copy slice that avoids allocations and enables high-performance substring/trim/parsing operations. Use `Span<T>`/`ReadOnlySpan<T>` for hot-path string/buffer manipulation, binary parsing, or when working with `Memory<T>` to eliminate temporary allocations.

**DN6** — The GC manages the managed heap using mark-and-sweep/compact. **Gen 0**: short-lived objects, frequent collections. **Gen 1**: buffer between Gen 0/2. **Gen 2**: long-lived objects, infrequent collections. **LOH**: objects >85KB, compacted less often, can cause fragmentation. `IDisposable` is needed for unmanaged resources (file handles, DB connections, native memory) since the GC only tracks managed memory; `using` ensures deterministic cleanup.

**DN7** — `ConfigureAwait(false)` prevents capturing/restoring the `SynchronizationContext` (e.g., UI thread or ASP.NET request context). Use it in **libraries** to avoid deadlocks and improve throughput. Do NOT use it in **application/UI code** where context is required (e.g., updating UI, accessing `HttpContext`). Default behavior captures context for seamless continuation.

**DN8** — **Primary constructors** (C# 12): `class AppConfig(string Url, int Timeout) { }` automatically generates properties/fields. **Collection expressions** (C# 12): `[1, 2, 3]` creates arrays/lists with syntax sugar. **FrozenDictionary** (.NET 7+): immutable, optimized for lookup with minimal memory overhead. DI example:
```csharp
public record AppConfig(string Url, int Timeout);
builder.Services.AddSingleton<AppConfig>(sp => 
    new AppConfig(sp.Configuration["Url"]!, 30));
```

**DN9** — `ObjectDisposedException` under high concurrency usually means a `DbContext` is shared across requests (e.g., static, Singleton, or manually disposed too early). `DbContext` is **not thread-safe** and must be scoped per request. Fix: register as `Scoped`, never dispose manually, use `using var` or let DI dispose at scope end. EF Core ties DbContext lifetime to DI scope; crossing scope boundaries causes reuse/disposal conflicts.

**DN10** — `record` provides immutable-by-default, value-based equality, and positional syntax. `class` is mutable with reference equality. `record struct` is a value-type record (zero-allocation, immutable). Choose `record` for DTOs/config, `record struct` for performance-critical value types, and `class` for mutable/stateful entities or when inheritance is required.

**DN11** — `ref`: passes by reference, caller must initialize. `out`: passes by reference, method must assign before return. `in`: passes by reference, read-only. Use `ref` to modify existing values, `out` for multiple return values, and `in` for large structs to avoid copying while preventing mutation.

**DN12** — Nullable Reference Types (NRTs) use `?` to mark potential nulls for reference types at compile time (`string?`). They are compiler annotations, not runtime changes. Nullable value types (`int?`) are `Nullable<T>` structs that allow null for value types at runtime. NRTs catch null-reference bugs statically; value types use boxing/struct semantics.

**DN13** — LINQ unifies querying across data sources. **Method syntax**: fluent, chainable (`list.Where(...).Select(...)`). **Query syntax**: SQL-like, compiles to method syntax (`from x in list where ... select x`). **Deferred execution**: queries don't run until enumerated (e.g., `foreach`), enabling composition, lazy evaluation, and dynamic filtering.

**DN14** — Generic constraints restrict `T`. `class` (reference), `struct` (non-nullable value), `new()` (parameterless constructor), `IComparable<T>` (implements interface). Combine with commas: `where T : class, IComparable<T>, new()`. Use when algorithms require specific capabilities (e.g., sorting, instantiation, inheritance).

**DN15** — Abstract classes support state, implementation, and single inheritance. Interfaces define contracts with multiple inheritance. C# 8+ default interface methods allow implementation in interfaces, blurring lines, but abstract classes still support fields, protected members, and constructor logic. Prefer interfaces for polymorphism/contracts, abstract classes for shared base implementation.

**DN16** — Middleware pipeline processes requests sequentially. `app.Use()` adds middleware, `app.Map()` branches routing, `app.Run()` is terminal. Ordering matters: auth/validation before endpoints, error handling early. Exception handling middleware (`UseExceptionHandler`) catches unhandled exceptions, can short-circuit the pipeline, and returns error responses.

**DN17** — `Channel<T>` is high-performance, async-native, and supports bounded/unbounded modes. `BlockingCollection<T>` is synchronous, older, and blocks threads. Bounded channel example:
```csharp
var ch = Channel.CreateBounded<int>(10);
// Producer: await ch.Writer.WriteAsync(item); (blocks when full)
// Consumer: await ch.Reader.ReadAsync(); (blocks when empty)
```
Implements backpressure naturally without thread blocking.

**DN18** — Source Generators compile-time code generation via Roslyn. Unlike reflection (runtime overhead) or IL weaving (post-compilation complexity), generators produce C# code before compilation. **Incremental generators** (`ISourceGenerator` successor) use caching, incremental compilation, and avoid full re-generation. Preferred for IDE integration, performance, and build-time safety.

**DN19** — TPL Dataflow enables message-passing pipelines. `ActionBlock` processes items, `TransformBlock` processes + returns, `BufferBlock` stores. `Channels` are simpler, async-native, and better for streaming. Dataflow excels at batching, completion propagation, complex routing, and synchronous/asynchronous mixing, but has higher overhead than channels.

**DN20** — Minimal APIs map routes directly to functions, reducing boilerplate vs controllers. Trade-offs: simpler setup, but less built-in model binding/validation, OpenAPI requires Swashbuckle/NSwag, testability via `WebApplicationFactory`. Route groups (`MapGroup`) organize endpoints. Endpoint filters (`EndpointFilter`) handle per-route validation/auth, replacing middleware for granular control.

**P1** — `list` is mutable, ordered, allows duplicates. `tuple` is immutable, ordered, often used for fixed records. `set` is unordered, unique, mutable. `frozenset` is immutable, hashable, usable as dict keys or set elements.

**P2** — GIL ensures only one thread executes Python bytecode at a time. It severely impacts CPU-bound single-threaded workloads. Workarounds: `multiprocessing` (separate processes), C-extensions that release GIL, `asyncio` for I/O-bound concurrency, or Python 3.13+ free-threading (experimental).

**P3** — `copy` creates a shallow copy (new container, same nested objects). `deepcopy` recursively copies all nested objects. Shallow copy fails with nested mutables:
```python
a = [[1]]; b = copy(a); b[0].append(2); a[0]  # [1, 2]
```

**P4** — Decorators wrap functions. Execution time example:
```python
import time
def timer(f):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = f(*args, **kwargs)
        print(f"{f.__name__}: {time.perf_counter()-start:.4f}s")
        return result
    return wrapper
```

**P5** — Generators (`yield`) produce items lazily, saving memory vs returning full lists. `yield from` delegates to another generator/collection, flattening iteration and improving readability. Generators are iterators; lists are eager and consume memory.

**P6** — `asyncio.run()` starts the event loop and runs a coroutine. `asyncio.gather()` runs multiple coroutines concurrently and returns results. `asyncio.create_task()` schedules a coroutine for later execution. `time.sleep()` blocks the event loop; use `await asyncio.sleep()` to yield control.

**P7** — Python 3 uses **C3 linearization** for MRO. Diamond inheritance resolves left-to-right, depth-first. `D(B, C)` MRO: `D → B → C → A`. `B` inherits `who` from `A`? No, `B` has none, `C` overrides. `D().who()` follows MRO → `C.who()` → prints `"C"`.

**P8** — Metaclass controls class creation (`__new__`/`__init__`). `__init_subclass__` is a simpler per-class hook. Use metaclass for global class modification (e.g., ORM model registration, auto-validating base classes). Use `__init_subclass__` for per-subclass setup (e.g., auto-registering plugins, setting class attributes).

**P9** — `threading`: I/O-bound, GIL limits CPU parallelism. `multiprocessing`: CPU-bound, separate processes, requires pickling (objects must be serializable; closures/DB connections fail). `concurrent.futures`: high-level API (`ThreadPoolExecutor`/`ProcessPoolExecutor`) standardizing async/concurrent patterns.

**P10** — `__slots__` restricts instance attributes to predefined names, preventing `__dict__` creation. Saves memory (~40-50% per instance), speeds up attribute access. Use for large collections of instances with fixed attributes (e.g., nodes, records). Prevents dynamic attribute assignment.

**P11** — Virtual environments isolate project dependencies. `venv` (stdlib, modern, recommended). `virtualenv` (third-party, older, extra features). `conda` (package + env manager, handles non-Python deps, ideal for data science). Prevents dependency conflicts and system pollution.

**P12** — Comprehensions (`[x for x in y]`, `{k:v for ...}`, `{x for ...}`) are Pythonic, readable, and often faster. `map()`/`filter()` return iterators, useful for lazy evaluation or functional style. Prefer comprehensions for simple transformations/filtering; `map`/`filter` when composing functions or avoiding intermediate lists.

**P13** — `==` checks value equality; `is` checks object identity (memory address). Object interning caches small integers (`-5` to `256`) and some strings. `a is b` returns `True` for interned values because Python reuses the same memory address.

**P14** — `*args` collects extra positional args into a tuple. `**kwargs` collects extra keyword args into a dict. `/` marks positional-only parameters (before). `*` marks keyword-only parameters (after). Used for flexible APIs, avoiding keyword collisions, and enforcing call signatures.

**P15** — Context managers (`with`) guarantee cleanup. Implement via `__enter__`/`__exit__` (classes) or `@contextmanager` (functions using `yield`). Example beyond files: database transactions, temporary directories, lock acquisition, or HTTP request timeouts.

**P16** — Type hinting (`: type`, `-> type`) enables static analysis. `Union`/`Optional` (multiple types), `Literal` (exact values), `TypeVar` (generic constraints), `Protocol` (structural typing). `mypy`/`pyright` parse hints at compile-time for type safety without runtime overhead.

**P17** — Dunder methods define object behavior. `__repr__` (dev/debug, unambiguous) vs `__str__` (user-friendly). `__eq__` vs `__hash__`: defining `__eq__` without `__hash__` makes instances unhashable. `__getattr__` (fallback for missing attrs) vs `__getattribute__` (intercepts all, dangerous if misused).

**P18** — Descriptors control attribute access via `__get__`, `__set__`, `__delete__`. `property` is a data descriptor. `classmethod`/`staticmethod` are non-data descriptors. Under the hood, they intercept attribute lookup on class/instance, enabling lazy evaluation, validation, and method binding.

**P19** — Import system searches `sys.path`/`PYTHONPATH`. `__init__.py` marks packages (optional in Python 3.3+ for namespace packages). Relative (`.`) vs absolute (`pkg.mod`) imports. **Finders** locate modules; **loaders** execute/compile them. Namespace packages allow split distributions without `__init__.py`.

**P20** — `dataclasses` auto-generates `__init__`, `__repr__`, etc. `attrs` (more features, faster), `Pydantic` (validation, serialization, ORM-like). `__post_init__` for custom logic. `frozen=True` makes immutable. Choose `Pydantic` for validation, serialization, config management, complex type coercion, and integration with FastAPI/ORMs.
