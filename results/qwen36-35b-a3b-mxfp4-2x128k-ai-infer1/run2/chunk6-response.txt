JS1 — `var` is function-scoped and hoisted with initialization to `undefined`. `let` and `const` are block-scoped, hoisted but reside in the Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment. Hoisting is the JS compilation phase where declarations are moved to the top of their scope before execution.

JS2 — The event loop continuously checks the call stack. When empty, it processes the microtask queue (Promises, `queueMicrotask`) completely, then runs one macrotask (setTimeout, I/O, UI). Microtasks always drain before the next macrotask, ensuring async promise chains execute synchronously relative to each other.

JS3 — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: a counter factory. Classic bug: `for (var i=0; i<3; i++) setTimeout(()=>console.log(i), 0)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped) or `setTimeout(..., 0, i)` to capture the value.

JS4 — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that pauses execution until the promise settles, making async code read synchronously. Error handling: `try/catch` with `await`, or `.catch()`/second `.then()` arg. `Promise.all` fails fast on first rejection. `Promise.allSettled` waits for all promises, returning an array of `{status, value/reason}` objects.

JS5 — `interface` defines only object shapes, supports declaration merging, and can be implemented by classes. `type` is broader: unions, intersections, primitives, function signatures, mapped types. Use `interface` for public APIs/classes, `type` for unions/utility types. Discriminated unions use a common literal property (tag) to narrow types in `switch`/`if` statements.

JS6 — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar: `class A extends B` sets `A.prototype.__proto__ = B.prototype`, and `super` calls the parent constructor/methods.

JS7 — `this` is dynamically bound based on call site. Priority: 1. `new` (constructor instance), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (global/window or `undefined` in strict mode). `bind()` returns a new function with `this` permanently locked. It cannot be re-bound.

JS8 — `WeakRef` holds a weak reference that doesn't prevent garbage collection. `FinalizationRegistry` triggers a callback when the referenced object is GC'd. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the GC can track when keys become unreachable and clean up entries; primitives can't be weakly referenced.

JS9 — V8 optimizes via hidden classes (shapes) for fast property access, inline caching (IC) to cache shape lookups, and deoptimization when assumptions fail. Deopt patterns: dynamic property addition/removal, type switching, `delete`, `with`, `eval`, or missing properties in hot loops. V8 recompiles to generic code, hurting performance.

JS10 — Tree-shaking removes unused exports at build time. It works with ES modules because imports/exports are static and analyzable at compile time. CommonJS uses dynamic `require()` at runtime, so bundlers can't statically determine dependencies, making dead code elimination ineffective.

JS11 — `null` is intentional absence; `undefined` is uninitialized. `==` coerces types (`null == undefined` is `true`), `===` checks type & value (`false`). `??` returns right operand if left is `null`/`undefined`. `?.` safely accesses nested properties without throwing on `null`/`undefined`.

JS12 — `map()` transforms elements, `filter()` keeps matching ones, `reduce()` accumulates to a single value. `reduce()` with an initial value prevents `undefined` on empty arrays and sets the accumulator type. `flatMap()` maps then flattens one level; useful when each input produces multiple outputs.

JS13 — Template literals use backticks, support `${}` interpolation and multi-line strings. Tagged templates pass string parts and expressions to a function. Example: `sql` tag for parameterized queries or `html` tag for escaping: `function html(strings, ...values) { return strings.reduce((acc, s, i) => acc + s + (values[i] || ''), ''); }`

JS14 — Destructuring unpacks arrays/objects into variables. Object: `{a, b}` or `{a: x}`. Array: `[a, b]`. Defaults: `{a = 1}`. Rest: `{...rest}` collects remaining. Works in assignments, parameters, and loops. Prevents verbose property access and enables clean API signatures.

JS15 — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, maps). Avoid `for...in` on arrays because it iterates keys, not values, includes inherited properties, and doesn't guarantee order.

JS16 — Generics parameterize types. Constraints: `T extends Base` limits T. Conditional types: `T extends U ? X : Y` for branching. `infer` extracts types in conditional contexts. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T`. Constraints ensure type safety; `infer` enables type extraction without manual specification.

JS17 — CommonJS uses `require()`/`module.exports`, synchronous, runtime resolution, object caching. ES Modules use `import`/`export`, static, async, tree-shakable. Node.js supports both; `"type": "module"` in `package.json` treats `.js` as ESM. `.mjs` is always ESM, `.cjs` always CJS. ESM is the modern standard.

JS18 — Structural typing checks compatibility by shape, not names. Excess property checks apply only during object literal creation to catch typos. `extends` defines assignability; `satisfies` checks type without widening, preserving the original type. Variance: `in` (contravariant/input), `out` (covariant/output), `inout` (bivariant). TS 4.7+ uses `in`/`out` for generic parameters.

JS19 — `Proxy` intercepts object operations (get, set, apply, etc.). `Reflect` mirrors traps and provides default behavior. Example: validation proxy that checks types on assignment. Reactive data binding: Proxy tracks dependencies on `get`, triggers updates on `set`, enabling frameworks like Vue/Solid.

JS20 — `SharedArrayBuffer` enables shared memory between workers/main thread. `Atomics` provides atomic operations on typed arrays in SAB. Communication: write to SAB, use `Atomics.wait` (blocks until value changes) and `Atomics.notify` (wakes threads). Guarantees: acquire/release memory ordering, preventing race conditions in concurrent access.

B1 — `$@` expands to separate quoted words (`"$1" "$2"`), preserving individual arguments. `$*` expands to a single string (`"$1 $2 ..."`). `"$@"` is safe for argument passing. `"$*"` joins them with IFS, losing argument boundaries.

B2 — `set -e`: exit on command failure. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the rightmost non-zero exit code. Together, they enforce strict error handling and prevent silent failures.

B3 — `$(command)` and `` `command` `` are both command substitution, but `$()` supports nesting and is preferred. `$((expression))` is arithmetic expansion. `expr` is an external command for arithmetic/string ops, slower and less robust than shell-native `$(( ))`.

B4 — Process substitution `<(cmd)` creates a file descriptor (e.g., `/dev/fd/63`) for a command's output. Use when a command expects a file but you have a stream. Example: `diff <(sort file1) <(sort file2)` compares sorted outputs without temp files.

B5 — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous due to word splitting on spaces/newlines, glob expansion, and fragile `ls` parsing. `find -print0` + `read -d ''` handles all filenames safely.

B6 — Here doc `<<EOF` provides multi-line input until the marker. Here string `<<<` provides a single line. `<<-EOF` strips leading tabs from both the document and marker for cleaner indentation in scripts.

B7 — `cmd > file 2>&1`: stdout → file, then stderr → stdout (now file). `cmd 2>&1 > file`: stderr → original stdout (terminal), then stdout → file (stderr goes to terminal). `cmd &> file` is bash shorthand for `> file 2>&1`. Order matters because redirections evaluate left-to-right.

B8 — Use `mkdir` for atomic locking (fails if dir exists). Trap signals for cleanup. Example:
```bash
LOCKDIR="/tmp/mylock.$$"
mkdir "$LOCKDIR" || { echo "Locked"; exit 1; }
trap 'rm -rf "$LOCKDIR"' EXIT INT TERM
# ... work ...
```
`mkdir` is atomic on POSIX, avoiding TOCTOU race conditions.

B9 — Single quotes `'...'`: no expansion. Double quotes `"..."`: allows `$`, `` ` ``, `\`, `!` expansion. No quotes: word splitting & globbing occur. Example: `var="a b"; echo $var` → `a b`, `echo "$var"` → `a b`, `echo '$var'` → `$var`.

B10 — Checks: `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin supporting `&&`, `||`, regex, and no word splitting/globbing. Safer and more powerful than POSIX `[ ]`.

B11 — `$?`: last exit status. `$$`: script PID. `$!`: last background job PID. `$#`: argument count. Use cases: error handling, logging PIDs, `wait $!`, validating input count.

B12 — Functions: `foo() { ... }` (POSIX) or `function foo { ... }` (bash). Return values: `return <int>` (exit code 0-255). Use `echo` for stdout or global variables for complex returns.

B13 — PATH: colon-separated dirs bash searches for executables. Resolves: PATH → builtins → aliases. Builtin: compiled into shell (`cd`, `echo`). External: separate binary. Check with `type cmd` or `command -v cmd`.

B14 — `trap` registers handlers for signals/events. `trap 'cleanup' EXIT ERR INT TERM`. ERR triggers on command failure, EXIT on script end, signals interrupt. Multiple signals: last trap wins, handlers run sequentially. Use `trap - INT` to ignore or re-register.

B15 — `xargs` builds/ executes commands from stdin, handles batching. Command substitution runs once. `xargs -0` + `find -print0` handles spaces/newlines safely. `xargs -P N` runs N processes in parallel, improving throughput for I/O-bound tasks.

B16 — Indexed arrays: `arr=(a b c)`, append `arr+=("d")`, iterate `for i in "${arr[@]}"`, length `${#arr[@]}`. Associative: `declare -A assoc`, set `assoc[key]=val`, iterate keys/values similarly. Associative requires `declare -A` and uses string keys.

B17 — Subshell `(cmd)` runs in a child process; variable changes are lost. Group `{ cmd; }` runs in current shell; variables persist. Piping to `while` creates a subshell, so loop vars don't persist. Fix: `while ... done < <(cmd)` or `cmd | while ... done` with process substitution.

B18 — Signals: SIGINT (Ctrl+C, interrupt), SIGTERM (graceful stop), SIGHUP (terminal hangup/reload), SIGKILL (force kill, uncatchable). Graceful shutdown: trap SIGTERM, wait for bg jobs, cleanup resources, exit. Use `trap 'cleanup' TERM` and `wait` for bg processes.

B19 — Parallel log processing: `split -l 10000 log.log log.part.`, `find . -name "log.part.*" -print0 | xargs -0 -P 4 -I {} bash process.sh {}`. Merge: `cat log.part.* > merged.log`. Trade-offs: CPU vs I/O, process spawn overhead. Error propagation: check exit codes, use `set -o pipefail`, log failures, aggregate status.

B20 — `exec` replaces the current shell or redirects file descriptors. `exec 3>file` opens fd 3, `exec 3>&-` closes it. Coprocess: `coproc cmd` creates bidirectional pipe, allowing main shell to read/write to cmd's stdin/stdout. Use for persistent background tasks or interactive daemons.

PS1 — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console (bypasses pipeline). Distinction matters because `Write-Host` breaks pipeline chaining, complicates redirection, and interferes with logging/testing.

PS2 — Pipeline streams objects between cmdlets. `ForEach-Object` is a cmdlet that processes each object in the pipeline. `foreach` is a language construct that iterates collections in-memory. Use `ForEach-Object` for streaming/large data, `foreach` for in-memory arrays (faster).

PS3 — `[PSCustomObject]` is a strongly-typed object with properties/methods, pipeline-friendly. `[hashtable]` is an untyped key-value collection, faster for lookups, no methods. Convert: `[PSCustomObject]$hash` or `[hashtable]$obj.PSObject.Properties`.

PS4 — Terminating errors stop execution; non-terminating continue. `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors. Use `try/catch` for critical failures, `-ErrorAction SilentlyContinue` for expected failures.

PS5 — Splatting `@params` passes a hashtable as named parameters to a cmdlet. Example: `@{Path = "C:\test"; Recurse = $true} | Get-ChildItem`. Differs from single param because it expands to multiple parameters, not a single hashtable argument.

PS6 — `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` creates an interactive session. Uses WinRM (HTTP/HTTPS) by default; PowerShell 7+ supports SSH remoting. Both rely on secure, authenticated channels.

PS7 — Pipeline type coercion causes issues. `Get-Items` returns an array. `$x.GetType().Name` is `Object[]`. If returns 0 items, `$x` is `$null`. Correct pattern: `[array]$result = @()` or ensure consistent return type, or handle empty arrays explicitly with `[PSCustomObject[]]`.

PS8 — `[scriptblock]` is anonymous code; function is named. Pass to remote: `Invoke-Command -ScriptBlock $sb -ArgumentList $args`. Double-hop: auth fails when remoting to a second server. Solve with CredSSP (insecure), Kerberos delegation, or pass data via `-ArgumentList` and execute locally.

PS9 — `@()` forces array, `[array]` is a type constraint. Force single result: `@($result)`. Indexing `$null` throws; empty array `@()` returns `$null` on index. `@()` prevents scalar/array inconsistency in pipelines.

PS10 — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive: `-ceq`, `-clike`, `-cmatch`. `-contains` checks if collection contains value; `-in` checks if value is in collection (reversed operands).

PS11 — Module: collection of functions/cmdlets. `.psm1`: script module code. `.psd1`: manifest (metadata, dependencies). Binary: compiled .NET. `Import-Module` loads into session, checks `$env:PSModulePath`, caches in memory.

PS12 — String interpolation: `"..."` allows `$var` and `$(expr)`. `'...'` literal. Here-string `@"..."@` for multi-line. Expressions: `$(Get-Date)`. Interpolation evaluates at runtime.

PS13 — `Get-Member` explores object members. Properties (data), Methods (actions), NoteProperties (custom added). `Select-Object` picks properties, `Where-Object` filters objects. Use `Get-Member` to discover available operations.

PS14 — Classes (v5+): define types with properties/methods. Differ from C#: no multiple inheritance, limited interfaces, constructors use `param()` block, no access modifiers (public by default). Use classes for complex data models, functions for simple scripts.

PS15 — `CmdletBinding`: enables advanced function features. `SupportsShouldProcess` adds `-WhatIf`/`-Confirm`. `DefaultParameterSetName` sets default params. `ValueFromPipeline` allows pipeline input. `Begin`/`Process`/`End` blocks: init, per-object processing, cleanup.

PS16 — Providers: abstract data stores. `Get-ChildItem` works on FileSystem, Registry (`HKLM:`), Certificates (`Cert:`), Environment. Registry accessed via `HKLM:\SOFTWARE\...` paths, treated like directories/files. Providers unify data access.

PS17 — Runspaces: execution environments. `[runspace]` single, `[runspacepool]` manages multiple. `[powershell]` object runs commands in runspace. `ForEach-Object -Parallel` (v7+) uses runspace pool automatically. Manual runspace management offers finer control but is complex.

PS18 — PSScriptAnalyzer: linting tool. Enforces standards via rules (naming, performance, security). Severity: error, warning, info. Suppress: `#pragma disable`, `.psake.ps1`, or config file. Integrates with CI/CD via `Invoke-ScriptAnalyzer` in build scripts.

PS19 — `$using:` scope serializes variables from caller to remote/job/parallel context. `-ArgumentList` passes values explicitly. CLIXML serialization limits depth/complexity, breaks on custom objects with methods/circular refs. Use `-ArgumentList` for simple data, `$using:` for convenience but watch serialization.

PS20 — DSC: declarative config management. Configurations define state, resources implement changes, LCM applies/enforces. WinPS DSC uses MOF files, PS7+ uses JSON. Modern replacement: Ansible, Terraform, Chef, or native cloud IaC. DSC still used in Windows enterprise but less dominant.
