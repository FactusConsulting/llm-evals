SC1-A
The failure stems from the shift to the **Restricted Pod Security Standard**. Restricted PSS mandates:
1. `runAsUser` must be explicitly set to a non-zero UID.
2. `runAsNonRoot: true` must be enforced.
3. `allowPrivilegeEscalation: false` is required.
4. No host namespaces or privileged containers.

When `runAsNonRoot: true` is set without `runAsUser`, Kubernetes defaults to UID `0` (root). This violates both `runAsNonRoot: true` and the Restricted policy's explicit UID requirement. Additionally, the new base image (`cgr.dev/chainguard/static:latest`) sets `USER root` in the Dockerfile, so the container process runs as root. The combination of an implicit root UID and a root-defaulting image triggers the Restricted policy admission failure, causing pods to crash or fail to start.

SC1-B
```bash
kubectl get pods -A -o json | jq -r '.items[] | select(.status.containerStatuses[]?.state.waiting.reason == "CrashLoopBackOff") | {namespace: .metadata.namespace, pod: .metadata.name, securityContext: .spec.securityContext}'
```

SC1-C
**Immediate Fix:** Patch deployments to add explicit non-root UID and policy-compliant securityContext:
`kubectl set env deployment/<name> --dry-run=client -o yaml | kubectl patch deployment <name> --type=json -p '[{"op":"add","path":"/spec/template/spec/securityContext","value":{"runAsUser":1000,"runAsNonRoot":true,"allowPrivilegeEscalation":false}}]'`
Roll out with `kubectl rollout restart deployment/<name>` using `maxUnavailable: 0` and readiness probes to avoid downtime.

**Image-Level Fix:** Rebuild base image with `RUN adduser -D appuser` and `USER appuser`. Pin to digest (`cgr.dev/chainguard/static@sha256:...`).

**CI Gate:** 
- OPA/Kyverno admission controller enforcing Restricted PSS in CI preview.
- `syft` + `grype` to verify base image digest and non-root USER.
- Policy-as-code in CI pipeline blocking merges that omit `runAsUser` or use mutable tags.

**Rollout:** Use rolling updates with `strategy.rollingUpdate.maxSurge=1 maxUnavailable=0`. Health checks ensure new pods pass before old ones terminate.

SC2-A
Cross-region async replication ships WAL asynchronously. Promoting a replica severs replication, so any WAL not yet shipped or replayed is permanently lost. The data loss window equals the replication lag at promotion time. PostgreSQL streaming replication buffers WAL on the primary; if the primary fails before shipping, those transactions are lost.

**To quantify loss:**
- Check `pg_last_wal_receive_lsn()` on the replica vs `pg_last_wal_replay_lsn()`.
- Monitor `pg_stat_replication` on the primary pre-failover for `sent_lsn`, `write_lsn`, `flush_lsn`, `replay_lsn`.
- Review application logs for replication lag metrics (`pg_stat_replication` lag columns).
- Post-failover, compare application transaction IDs or timestamps to estimate missing writes.

SC2-B
1. Update Terraform code to reference the promoted replica's ARN and update dependent resources (SGs, Route53, parameter groups).
2. Import the promoted instance: `terraform import aws_db_instance.promoted_replica <arn>`
3. Verify no destroy/recreate: `terraform plan` (should show only attribute updates)
4. Apply: `terraform apply`
5. Remove old instance from state: `terraform state rm aws_db_instance.old_primary`
6. Destroy old instance: `terraform apply` (will trigger `aws_db_instance.old_primary` deletion)
7. Verify state consistency: `terraform plan` (should show no changes)

SC2-C
**Architecture:**
- **RDS Proxy:** Replaces PgBouncer. Managed, handles connection pooling, retries, and idle connection management. Reduces server login errors and scales with workload.
- **Route53 Failover:** Health checks on RDS Proxy endpoints. Failover routing policy switches traffic automatically.
- **App Retry Logic:** Exponential backoff with jitter, idempotent writes, and circuit breakers for transient failures.
- **RPO < 1s:** Requires synchronous replication or Aurora Global Database. Standard RDS async replication cannot guarantee <1s RPO across regions.
- **Aurora Global DB Recommendation:** Yes. Provides cross-region async replication with <1s lag, automatic failover in <30s, and global data distribution. Eliminates manual promotion, reduces Terraform drift, and simplifies connection routing.

SELECT blocked_locks.pid AS blocked_pid,
       blocked_activity.usename AS blocked_user,
       blocking_locks.pid AS blocking_pid,
       blocking_activity.usename AS blocking_user,
       blocked_activity.query AS blocked_statement,
       blocking_activity.query AS current_statement_in_blocking_process
FROM pg_catalog.pg_locks blocked_locks

JOIN pg_catalog.pg_locks blocking_locks ON blocking_locks.locktype = blocked_locks.locktype
  AND blocking_locks.database IS NOT DISTINCT FROM blocked_locks.database
  AND blocking_locks.relation IS NOT DISTINCT FROM blocked_locks.relation
  AND blocking_locks.pid != blocked_locks.pid
JOIN pg_catalog.pg_stat_activity blocking_activity ON blocking_activity.pid = blocking_locks.pid
WHERE NOT blocked_locks.granted;

SC5-C
**Architectural Solution:**
- **CQRS:** Separate read/write paths. Serving pods query read replica; reconciliation job writes to primary.
- **Read Replica:** Reconciliation job runs against replica, eliminating lock contention on primary.
- **Bulkhead Isolation:** Separate DB connection pools for serving vs background jobs. Use `pgbouncer` with pool modes `transaction` for serving, `statement` for jobs.

SC6-C
**Comparison:**
- **AWS Direct Connect:** Dedicated 10Gbps/100Gbps link. Lower latency, higher throughput. Requires BGP, MACsec/IPsec for encryption. Fits ZT when combined with overlay encryption. Routing: BGP peering, static routes.
- **Second VPN + ECMP:** Two IPsec tunnels with ECMP. Cheaper, easier. Still IPsec overhead, limited by tunnel MTU. Routing: BGP with multiple paths, ECMP load balancing.
- **Tailscale/Netbird:** WireGuard mesh, ZT-native. Low latency, automatic routing. May not meet enterprise compliance/bandwidth guarantees. Routing: Overlay mesh, automatic route propagation.
**Recommendation:** Direct Connect for primary backbone (compliance, bandwidth), Tailscale/Netbird for secure service-to-service overlay (ZT, encryption). ECMP VPN as fallback.
