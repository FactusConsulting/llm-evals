G1 — An array `[T; N]` has a fixed size known at compile time, is a value type, and its size is part of its type. A slice `[]T` is a dynamic view over contiguous memory, represented as a runtime header `{ptr, len, cap}`. When `append` exceeds a slice's capacity, Go allocates a new backing array (typically 2× the old capacity), copies the elements, and returns a new slice pointing to it.

G2 — `var x int` declares a variable with an explicit type and zero value; it can be used at package level or inside functions. `x := 0` is a short variable declaration that infers the type and initializes simultaneously; it only works inside functions. You cannot use `:=` outside functions, when redeclaring an existing variable in the same scope, or when type inference is ambiguous/insufficient.

G3 — A goroutine is a lightweight, ~2KB stack thread managed by the Go runtime. OS threads are heavy (~1MB+ stack) and managed by the kernel. The GMP model: G = goroutine, M = machine (OS thread), P = processor (execution context/cache). The scheduler multiplexes Gs onto Ms using Ps for work-stealing, preemption, and cache locality, enabling efficient M:N scheduling without kernel involvement.

G4 — Channels are typed communication pipes. Unbuffered channels synchronize sender and receiver (blocking until both are ready). Buffered channels allow sends to succeed up to `cap` without a receiver; they block only when full. Sending to a full buffered channel blocks until space opens or the channel is closed.

G5 — `context` carries deadlines, cancellation signals, and request-scoped values across API boundaries. Minimal example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

G6 — Go uses structural interface satisfaction (duck typing): a type implements an interface if it has the required methods, with no explicit `implements` keyword. Java/C# use nominal interfaces. `interface{}` (Go 1.18+) / `any` accepts any type. Powerful for generics/JSON, but dangerous because it erases type safety, forces runtime type assertions, and can mask logic errors.

G7 — Unsafe due to a data race: no synchronization, compiler/CPU reordering, and cache visibility mean `ready` may be cached while `data` isn't visible. Fixes: use `sync/atomic` (`atomic.Bool`, `atomic.StorePointer`), or signal via a channel (`readyCh := make(chan struct{})`). Channels are idiomatic for goroutine synchronization.

G8 — `sync.Mutex` provides exclusive access. `sync.RWMutex` allows concurrent readers or a single writer. `sync.Map` is optimized for key-heavy read / sparse write or key-heavy write / sparse read workloads. Trade-offs: `sync.Map` has higher read latency and memory overhead vs `map+mutex` for balanced workloads. `map+mutex` is generally preferred for most cases.

G9 — Modules manage versioned dependencies. `go.mod` declares dependencies, versions, and replace directives. `go.sum` stores cryptographic hashes for integrity verification. `go mod tidy` removes unused deps, adds missing ones, and updates both files. MVS (Minimum Version Selection) resolves the dependency tree by selecting the lowest version that satisfies all constraints, avoiding version conflicts.

G10 — `defer` schedules a function call to run after the surrounding function returns. Multiple defers execute in LIFO order. Gotcha in loops: variables captured by deferred closures are evaluated at defer time, not call time. Fix: pass as arguments `defer func(v int) { fmt.Println(v) }(v)` or create a new scope per iteration.

G11 — A pointer stores the memory address of another variable. Zero value: `nil`. Pointer to a struct literal: `&MyStruct{Field: value}`.

G12 — `init()` runs automatically before `main()`. It executes after all package imports are initialized. A package can have multiple `init()` functions; they run in declaration order across files. Order: imports → file order → `init()` order.

G13 — `new(T)` allocates zeroed memory for type `T` and returns `*T`. Works with any type. `make(T, args)` initializes internal data structures (slice, map, channel) and returns the value itself (not a pointer). Only works with built-in types.

G14 — Errors are returned as values, not exceptions. `error` is an interface with `Error() string`. Idiomatic: `if err != nil { return err }`. `errors.Is(err, target)` checks if `err` wraps `target`. `errors.As(err, &target)` extracts a specific error type. `==` only checks exact equality and doesn't unwrap error chains.

G15 — Map: `nil` (readable, not writable). Slice: `nil` (len/cap 0). Channel: `nil` (blocks forever). Struct: zero values of each field.

G16 — A race occurs when concurrent goroutines access shared data without synchronization, with at least one write. `-race` instruments the runtime to detect concurrent unsynchronized accesses and reports stack traces. Example: two goroutines incrementing a counter. Fix: wrap with `sync.Mutex` or communicate via a channel.

G17 — `select` waits on multiple channel operations. Like `switch` but for channels. If multiple cases are ready, it picks one pseudo-randomly. Timeout: `case <-time.After(d):` or `case <-ctx.Done():`.

G18 — Escape analysis determines if a variable lives on the stack or heap. If a variable's lifetime exceeds the function, it escapes to the heap. Inspect with `go build -gcflags="-m"`. Matters because heap allocations trigger GC; minimizing escapes improves latency and throughput.

G19 — Reflection inspects/manipulates types/values at runtime. `reflect.Type` holds type metadata; `reflect.Value` holds the actual data. Costs: slow, no compile-time checks, allocates. Justified for frameworks (JSON, ORMs), but code generation (e.g., `stringer`, `protobuf`) is preferred for performance-critical paths.

G20 — `go:embed` embeds files/dirs into the binary at compile time. Patterns: `*` for files, `...` for dirs. Limitations: must be in the same package, patterns are relative, no runtime modification. Returns `embed.FS` implementing `io/fs.FS`, enabling use with `http.FS`, `os.DirFS`, and standard filesystem APIs.

R1 — Ownership is Rust's core memory management model. Rules: 1) Each value has exactly one owner. 2) Only one owner exists at a time. 3) When the owner goes out of scope, the value is dropped. Enables memory safety without a garbage collector.

R2 — `String` is a heap-allocated, growable, owned UTF-8 string. `&str` is an immutable reference to UTF-8 bytes. Use `String` when you need ownership/modification; use `&str` in function signatures to avoid cloning and accept both `String` and string literals.

R3 — Borrowing accesses data without transferring ownership. Rules: 1) Either one `&mut` or many `&` references. 2) References must be valid (no dangling). 3) No aliasing mutable references. `&T` = shared/immutable. `&mut T` = exclusive/mutable.

R4 — `Result<T, E>` represents success/failure. `Option<T>` represents `Some(T)` or `None`. `?` propagates errors/returns early. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — `Box<T>`: heap allocation, single owner, moves data. `Rc<T>`: reference counting, single-threaded shared ownership. `Arc<T>`: atomic reference counting, thread-safe shared ownership. Use `Box` for large/recursive types, `Rc` for shared single-thread, `Arc` for shared multi-thread.

R6 — Traits are Rust's interface mechanism. Like Go, they use structural satisfaction, but require explicit implementation or blanket impls. `dyn Trait`: trait object, dynamic dispatch, vtable, heap-allocated, enables heterogeneous collections. `T: Trait`: generic static dispatch, monomorphization, zero-cost, compile-time resolved.

R7 — Fails: compiler can't determine which input lifetime applies to the output. Fix:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```
Both inputs share lifetime `'a`, so the output borrows from them safely.

R8 — `Send`: type can be transferred across threads. `Sync`: type can be shared across threads (`&T` is `Send`). `Rc<T>` isn't `Send`/`Sync` due to non-atomic ref count. `Arc<T>` uses atomic ref counting, making it `Send`+`Sync` (if `T` is).

R9 — `async`/`await` compiles to a state machine implementing `Future`. `Future::poll()` advances execution. Executors (e.g., Tokio) drive futures, handle I/O, and schedule tasks. Differs from Go: Go uses preemptive green threads (blocking syscalls yield), Rust uses cooperative async (explicit polling, no blocking in async context without `spawn_blocking`).

R10 — `unsafe` bypasses compile-time safety checks. Three things: dereference raw pointers, call unsafe functions, implement unsafe traits. Justified when interfacing with C, building safe abstractions, performance-critical code, or hardware interaction. Must uphold safety invariants manually.

R11 — Pattern matching: `match` exhaustively matches values. `if let` matches a single pattern, ignoring others. Compiler enforces exhaustiveness in `match` (must cover all variants or use `_`). `if let` doesn't require exhaustiveness.

R12 — `Vec<T>`: heap-allocated, growable array. `[T; N]`: fixed-size stack array. Vec manages capacity by allocating a new larger buffer (typically 2×), copying elements, and dropping the old one. Amortized O(1) push.

R13 — Enums are algebraic data types that can hold data per variant. Unlike C/Java, they're heterogeneous and pattern-matchable. `Option<T>` = `Some(T)` or `None`. Rust has no `null`; `Option` forces explicit handling, preventing null pointer dereferences.

R14 — `impl` blocks define methods/associated functions. `&self`: borrows instance, immutable. `&mut self`: mutable borrow, can modify. `self`: takes ownership, consumes instance. Associated functions (e.g., `String::new()`) don't take `self` and act like constructors/static methods.

R15 — `derive` macro auto-implements traits. Examples: `#[derive(Debug, Clone, PartialEq)]`. Can't derive when custom logic is needed (e.g., `Serialize` without serde, `PartialEq` with complex state, or when struct contains non-derivable types like `Rc`/`Arc` for certain traits).

R16 — `Cow<'a, T>` (Clone-on-Write) holds either borrowed `&'a T` or owned `T`. Useful when a function might return borrowed or owned data. Example:
```rust
fn process(s: &str) -> Cow<str> {
    if s.is_ascii() { Cow::Borrowed(s) } else { Cow::Owned(s.to_uppercase()) }
}
```
Avoids allocation when input already matches output.

R17 — Module system: `mod` declares a module, `use` imports paths, `pub` exposes. File mapping: `mod.rs` or `module/mod.rs`. 2015: `mod.rs` required, `use` paths relative to crate root. 2018: `mod.rs` optional (file named `module.rs`), `use` paths relative to current module, introduced `super`/`crate` keywords.

R18 — `Pin<T>` guarantees pointer/address stability. Needed for self-referential structs and async/await (futures may move but must keep internal pointers valid). `Unpin` is the default marker trait for types that don't need pinning. `Pin` restricts moves, ensuring `&mut self` remains valid during `poll`.

R19 — Macros generate code. Declarative (`macro_rules!`): pattern matching + token substitution, hygienic (macro-local variables don't leak). Procedural: `derive` (struct/enum impl), `attribute` (custom attributes), `function-like` (transform input). Hygiene ensures macro variables don't collide with caller scope.

R20 — Zero-cost abstractions: high-level features compile to efficient machine code. Iterators: lazy, inlined, zero overhead. Generics: monomorphization generates specialized code per type, no vtable overhead. Trait static dispatch: compile-time resolution, inlined calls. Achieves C-like performance while maintaining safety/ergonomics.
