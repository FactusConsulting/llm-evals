DN1 — **class vs struct**: `class` is a reference type (heap-allocated, supports inheritance, nullable, GC-managed). `struct` is a value type (stack/inline-allocated, copied on assignment, no inheritance, cannot be null unless `Nullable<T>`). Use `struct` for small, immutable, short-lived data that doesn't require inheritance (e.g., coordinates, points, simple DTOs). Avoid if large or frequently boxed.

DN2 — **IEnumerable<T> vs IQueryable<T>**: `IEnumerable<T>` executes in-memory (LINQ to Objects). `IQueryable<T>` builds an expression tree that can be translated to a remote query language (SQL, etc.). Distinction matters because `IQueryable` pushes filtering, projection, and paging to the database, drastically reducing memory and network overhead. `IEnumerable` pulls all data first.

DN3 — **async/await, Task vs ValueTask**: `async` marks a method; `await` suspends execution until the task completes without blocking the thread. `Task` is a heap-allocated reference type representing async work. `ValueTask` is a value type that avoids allocation when the operation completes synchronously. Use `ValueTask` in hot paths or when async operations frequently complete synchronously (e.g., cached reads).

DN4 — **DI & lifetimes**: DI inverts control by injecting dependencies instead of creating them internally. Lifetimes: `Transient` (new each resolution), `Scoped` (new per request/context), `Singleton` (one per container). Bug: Injecting a `Scoped` service into a `Singleton` captures it for the Singleton's lifetime, breaking per-request semantics, causing memory leaks, stale state, and thread-safety violations.

DN5 — **string vs ReadOnlySpan<char>, Span<T>**: `string` is heap-allocated and immutable. `ReadOnlySpan<char>` is a stack-allocated, zero-copy slice. `Span<T>` is the mutable counterpart. Use `Span<T>`/`ReadOnlySpan<char>` for high-performance parsing, string manipulation, or buffer handling to avoid allocations and GC pressure.

DN6 — **GC, generations, LOH, IDisposable**: GC traces live objects and compacts memory. Generations: `Gen 0` (short-lived, frequent), `Gen 1` (buffer), `Gen 2` (long-lived, infrequent). LOH (Large Object Heap) holds objects >85KB, isn't compacted, and is collected only in Gen 2. `IDisposable` is needed for deterministic cleanup of unmanaged resources (file handles, DB connections, native memory); GC only manages managed heap memory.

DN7 — **ConfigureAwait(false)**: Default `await` captures the current `SynchronizationContext` (e.g., UI thread) to resume on it. `ConfigureAwait(false)` skips context capture, resuming on any thread pool thread. Use in libraries, background services, and non-UI code. Avoid in UI apps or code that must resume on a specific context. `SynchronizationContext` dictates continuation affinity; `ConfigureAwait(false)` bypasses it.

DN8 — **.NET 8/9 features**: Primary constructors let you declare parameters directly in the type signature (`public record Point(int X, int Y);`). Collection expressions (`[1, 2, 3]`, `[.. array]`) simplify array/span creation. `FrozenDictionary` is an immutable, read-optimized dictionary with lower memory and faster lookups. DI example: `public class MyService(IRepository repo) { _repo = repo; }` (compiler generates property/constructor).

DN9 — **ObjectDisposedException on DbContext**: Cause: DbContext is likely registered as `Singleton` or shared across threads. DbContext is **not thread-safe** and must be `Scoped`. Fix: Register as `Scoped` in DI. EF Core's DbContext tracks entities, caches queries, and manages connections per request. Scoped lifetime ensures fresh state per request, preventing disposal conflicts and state pollution.

DN10 — **record vs class, record struct**: `record` is a reference type with value-based equality, immutability by default, positional syntax, and `with` expressions. `record struct` is the value-type equivalent. Use `class` for mutable/stateful entities. Use `record` for DTOs, domain events, immutable data. Use `record struct` for high-performance, short-lived, immutable value objects.

DN11 — **ref, out, in**: `ref` passes by reference; must be initialized before call, can be read/written. `out` passes by reference; must be assigned inside method, can be uninitialized before call. `in` passes by reference, read-only; prevents copying large structs. Use `ref` for modifying existing values, `out` for multiple returns/parsing, `in` for performance with large structs.

DN12 — **Nullable Reference Types vs Value Types**: NRT (`string?`) is a compile-time annotation that warns about potential null references. Erased at runtime. Nullable value types (`int?`) are runtime types (`Nullable<T>`) that can actually hold null. NRT prevents NREs via static analysis; `int?` is a real nullable value type.

DN13 — **LINQ, syntax, deferred execution**: LINQ unifies querying across collections, DBs, XML. Method syntax (`list.Where(...)`) is fluent and preferred for complex queries. Query syntax (`from x in list where ...`) is SQL-like and readable for joins/grouping. Deferred execution means the query isn't executed until enumerated (e.g., `foreach`, `.ToList()`), enabling composition and lazy evaluation.

DN14 — **Generic constraints**: `where T : class` (reference type), `where T : struct` (value type, non-nullable), `where T : new()` (parameterless constructor), `where T : IComparable<T>` (implements comparison). Combine when you need multiple guarantees, e.g., `where T : class, IComparable<T>, new()` for flexible, safe generic algorithms.

DN15 — **abstract class vs interface**: Abstract classes can have state, constructors, non-virtual methods, and partial implementation (single inheritance). Interfaces are contracts only (no state/constructors, multiple inheritance). C# 8+ default interface methods allow implementations in interfaces, enabling backward-compatible evolution and blurring the line, but interfaces still cannot hold instance fields.

DN16 — **Middleware pipeline**: Sequential request/response processing. `app.Use()` adds middleware to the pipeline. `app.Map()` branches based on path prefix. `app.Run()` is terminal (doesn't call `next()`). Ordering matters: auth before routing, error handling early, static files before MVC. `UseExceptionHandler` catches unhandled exceptions, logs, and returns error responses; place it early.

DN17 — **Channel<T> vs BlockingCollection<T>**: `Channel<T>` is modern, async-native, high-performance. `BlockingCollection<T>` is older, sync/blocking, wraps concurrent collections. Bounded example:
```csharp
var ch = Channel.CreateBounded<int>(10);
// Producer: await ch.Writer.WriteAsync(item); // blocks when full
// Consumer: var item = await ch.Reader.ReadAsync(); // blocks when empty
```
Enables backpressure by naturally throttling producers when consumers lag.

DN18 — **Source Generators**: Compile-time code generation via Roslyn APIs, outputting C# source. Faster and safer than reflection (runtime) or IL weaving (modifies assemblies). `IncrementalGenerator` uses `IncrementalGeneratorInitializationContext`, supports caching, incremental compilation, and is preferred over legacy `ISourceGenerator` for .NET 5+.

DN19 — **TPL Dataflow**: Pipeline/actor model for async data processing. `BufferBlock<T>` stores items. `TransformBlock<TIn,TOut>` async transforms one-to-one. `ActionBlock<T>` async actions one-to-none. Compared to `Channels`, Dataflow offers richer pipeline composition, automatic completion propagation, built-in backpressure, and declarative routing, but has higher overhead.

DN20 — **Minimal APIs**: Lightweight, inline route handlers with less boilerplate vs controller-based APIs (classes, attributes, model binding). Trade-offs: Minimal APIs are faster to write and have lower overhead, but can be harder to mock/test, share middleware less cleanly, and require explicit OpenAPI attributes. Route groups (`app.MapGroup("/api")`) share prefixes/middleware. Endpoint filters handle cross-cutting concerns (auth, validation) without full middleware.

P1 — **list vs tuple, set vs frozenset**: List is mutable, ordered, indexed. Tuple is immutable, ordered, fixed-size, heterogeneous. Set is mutable, unordered, unique elements. Frozenset is immutable set, hashable, usable as dict keys.

P2 — **GIL**: Mutex allowing only one thread to execute Python bytecode at a time. Affects CPU-bound multithreading (no parallelism). I/O-bound workloads benefit (threads release GIL during I/O). Workarounds: Multiprocessing, C extensions (release GIL), `asyncio`, or external processes.

P3 — **deepcopy vs copy**: `copy.copy()` creates a shallow copy (new container, same nested objects). `copy.deepcopy()` recursively copies all nested objects. Shallow copy fails with nested mutables: `a = [[1]]; b = copy.copy(a); b[0].append(2);` → `a` also changes.

P4 — **Decorators & execution time**:
```python
import time, functools
def log_time(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.4f}s")
        return result
    return wrapper
```

P5 — **Generators & yield**: Functions that produce iterators lazily via `yield`. Unlike lists, they use O(1) memory and maintain state across yields. `yield from` delegates to another generator/iterable, simplifying delegation and properly propagating exceptions.

P6 — **asyncio event loop**: Core runtime managing tasks and I/O. `asyncio.run()` creates loop and runs main coroutine. `asyncio.gather()` runs multiple coroutines concurrently, returning results. `asyncio.create_task()` schedules a coroutine for concurrent execution. `time.sleep()` blocks the entire thread/loop; use `await asyncio.sleep()` to yield control.

P7 — **MRO & diamond inheritance**: Python 3 uses C3 linearization to ensure monotonic, left-to-right method resolution. For `D(B, C)` where `B,C` inherit `A`, MRO is `D → B → C → A`. `D().who()` prints `"C"` because `B` doesn't override `who()`, so lookup continues to `C`, which does.

P8 — **Metaclass vs __init_subclass__**: Metaclass controls class creation (`__new__`/`__init__`), used for global registration, strict schemas, or ORM bases. `__init_subclass__` is a class method called when a subclass is created; simpler, instance-level, no metaclass needed. Use metaclass for cross-cutting class creation logic; use `__init_subclass__` for plugin registration or automatic field setup.

P9 — **multiprocessing, threading, concurrent.futures**: Threading: I/O-bound, shares memory, GIL limits CPU parallelism. Multiprocessing: CPU-bound, separate processes, bypasses GIL, higher overhead. `concurrent.futures` provides high-level `ThreadPoolExecutor`/`ProcessPoolExecutor` APIs. Multiprocessing uses `pickle` for serialization; lambdas, open files, and some C extensions fail to pickle.

P10 — **__slots__**: Declares fixed attributes, prevents `__dict__` creation. Use for memory optimization and performance. Prevents dynamic attribute assignment. Memory impact: Eliminates per-instance `__dict__` overhead, significantly reducing memory footprint for large numbers of instances.

P11 — **Virtual environments**: Isolated Python environments with independent packages/interpreters, preventing dependency conflicts. `venv`: Standard library (Python 3.3+). `virtualenv`: Third-party, older, more features (e.g., Python version selection). `conda`: Package + environment manager, handles non-Python deps, data-science focused.

P12 — **Comprehensions vs map/filter**: Comprehensions (`[x for x in lst if cond]`) are Pythonic, readable, and often faster. `map()`/`filter()` return lazy iterators, useful with C functions or functional pipelines. Prefer comprehensions for readability; use `map`/`filter` for performance with built-ins or chaining.

P13 — **== vs is, interning**: `==` checks value equality. `is` checks object identity. CPython interns small integers (-5 to 256) and some strings, caching them in memory. `a is b` returns `True` because both reference the same cached object. Never rely on interning for logic; use `==`.

P14 — **\*args, \*\*kwargs, positional/keyword-only**: `*args` collects extra positional args into a tuple. `**kwargs` collects extra keyword args into a dict. `/` marks parameters before it as positional-only. `*` marks parameters after it as keyword-only. Use for flexible APIs, configuration, and avoiding argument confusion.

P15 — **Context managers**: `with` ensures cleanup (`__exit__`) even on exceptions. Class-based: implement `__enter__`/`__exit__`. Generator-based: use `@contextmanager` for simpler functions. Example: Database transaction, lock acquisition, or temporary directory creation.

P16 — **Type hinting**: Static annotations for IDEs/linters, not runtime enforced. `Union[A, B]`: either type. `Optional[T]`: `Union[T, None]`. `Literal["a"]`: exact value. `TypeVar`: generic variable with constraints. `Protocol`: structural typing (duck typing). `mypy`/`pyright` parse hints to catch type mismatches at compile-time.

P17 — **Data model (dunder methods)**: `__repr__` is unambiguous/developer-focused; `__str__` is readable/user-focused. `__eq__` defines value equality. If `__eq__` is defined without `__hash__`, Python sets `__hash__ = None`, making instances unhashable. `__getattr__` triggers on missing attributes; `__getattribute__` triggers on every access (dangerous, can cause recursion).

P18 — **Descriptors**: Objects implementing `__get__`, `__set__`, `__delete__` that intercept attribute access on the owner class. `property` uses descriptors for computed attributes. `classmethod`/`staticmethod` are descriptors that modify method binding. Under the hood, `type.__getattribute__` checks for descriptor protocol before returning values.

P19 — **Import system**: Relative imports (`from . import mod`) resolve relative to the package. Absolute imports (`from pkg import mod`) resolve from `sys.path`. `PYTHONPATH` adds paths. `__init__.py` marks directories as packages and runs on import. Namespace packages (PEP 420) omit `__init__.py`, allowing split packages. Finders locate modules; loaders load/initialize them.

P20 — **dataclasses vs attrs vs Pydantic**: `dataclasses` (built-in) generates `__init__`, `__repr__`, `__eq__`; simple and fast. `attrs` (third-party) offers more features and faster generation. `Pydantic` adds validation, serialization, type coercion, and ORM integration; heavier but essential for config/API validation. `__post_init__` runs after init. `field(default_factory=list)` prevents mutable default pitfalls. Frozen = immutable. Choose Pydantic when validation/serialization is required.
