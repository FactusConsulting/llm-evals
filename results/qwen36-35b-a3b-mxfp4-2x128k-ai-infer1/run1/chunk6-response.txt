JS1 — `var` is function-scoped and hoisted with initialization to `undefined`. `let`/`const` are block-scoped, hoisted but reside in a Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment. Hoisting is the JS compilation phase where declarations are moved to the top of their scope before execution.

JS2 — The event loop continuously checks if the call stack is empty. When empty, it drains the microtask queue (Promises, `queueMicrotask`) completely, then picks one macrotask (setTimeout, I/O, UI events) to push onto the stack. Microtasks always run before the next macrotask.

JS3 — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: a counter factory. Classic bug: `var i` in a `for` loop causes all `setTimeout` callbacks to reference the same `i` (value 5). Fix: use `let i` (block-scoped) or wrap in an IIFE to capture the current value.

JS4 — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that makes promise chains read synchronously. Error handling: `try/catch` for `await`, `.catch()` or rejection handler for raw promises. `Promise.all` fails fast on first rejection. `Promise.allSettled` waits for all promises, returning an array of `{status, value/reason}` objects.

JS5 — `interface` defines object shapes, supports declaration merging, and only applies to objects. `type` is a broader alias supporting unions, intersections, tuples, and primitives. Use `interface` for public APIs/contracts, `type` for complex mappings/unions. Discriminated unions use a common literal property to narrow types in `switch`/`if` statements.

JS6 — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar: `class` defines a constructor, `extends` sets the prototype chain via `Object.setPrototypeOf`, and `super` calls parent constructors/methods.

JS7 — `this` is dynamically bound based on call site. Priority rules: 1. `new` (constructor), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (global/window or `undefined` in strict mode). `bind()` returns a new function with `this` permanently locked. It cannot be re-bound.

JS8 — `WeakRef` holds a weak reference that doesn't prevent GC. `FinalizationRegistry` triggers a callback when a weak ref is collected. Used for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the engine can track when they're garbage collected; primitives can't be GC'd, so entries would never be cleaned up.

JS9 — V8 uses hidden classes (shapes) to optimize property access. Inline caching (IC) caches shape lookups at call sites for O(1) access. Deoptimization occurs when assumptions break (e.g., adding properties in a different order, type changes, `delete`). Patterns causing deopt: dynamic property addition, `with` statement, type switching, and `delete`.

JS10 — Tree-shaking eliminates unused exports during bundling. It works with ES modules because `import`/`export` are static and analyzable at build time. CommonJS uses dynamic `require()`, which executes at runtime, preventing static analysis and making tree-shaking ineffective.

JS11 — `null` is an intentional absence of value; `undefined` is unassigned or missing. `null == undefined` is `true` (coercion), `null === undefined` is `false`. `??` returns the right operand if the left is `null`/`undefined`. `?.` safely accesses nested properties, returning `undefined` instead of throwing.

JS12 — `map()` transforms elements, `filter()` selects elements, `reduce()` accumulates into a single value. `reduce()` with an initial value: `arr.reduce((acc, val) => ..., init)` prevents type errors on empty arrays. `flatMap()` maps then flattens one level; useful when each element produces multiple results.

JS13 — Template literals use backticks, enable `${}` interpolation, and support multi-line strings. Tagged templates pass the literal parts and values to a function. Example: `sql` tag for parameterized queries or HTML escaping by processing `strings` and `values` arrays.

JS14 — Destructuring unpacks arrays/objects: `const {a, b} = obj`, `const [x, y] = arr`. Defaults: `const {a = 1} = obj`. Renaming: `const {a: newName} = obj`. Rest operator: `const {a, ...rest} = obj` collects remaining properties into a new object.

JS15 — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, maps). Avoid `for...in` on arrays: it iterates keys, not values; includes inherited properties; and doesn't guarantee order.

JS16 — Generics use type parameters: `function identity<T>(arg: T): T`. Constraints: `T extends SomeType`. Conditional types: `T extends U ? X : Y`. `infer` extracts types in conditionals. Example: `type Unwrap<T> = T extends Promise<infer U> ? U : T`.

JS17 — CommonJS (CJS) uses dynamic `require()`/`module.exports`, synchronous, Node's historical default. ES Modules (ESM) use static `import`/`export`, async, browser/Node native. `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM instead of CJS.

JS18 — TypeScript uses structural typing: compatibility based on shape, not names. Excess property checks apply only during object literal creation/assignment to catch typos. `extends` defines type relationships; `satisfies` validates a type without widening it. Variance (`in`/`out`) controls type compatibility in function parameters (TS 4.7+).

JS19 — `Proxy` intercepts fundamental object operations (get, set, apply, has, etc.). `Reflect` mirrors these traps. Example: validation proxy that throws on invalid assignment: `new Proxy(obj, { set(target, prop, val) { if (typeof val !== 'number') throw new Error(); target[prop] = val; } })`.

JS20 — `SharedArrayBuffer` enables shared memory between Web Workers. `Atomics` provides atomic operations for synchronization. Guarantees sequential consistency. `Atomics.wait(thread, index, value)` blocks until value changes or timeout. `Atomics.notify(thread, index, count)` wakes waiting threads. Requires cross-origin isolation headers.

B1 — `$@` preserves each argument as a separate word when quoted `"$@"`. `$*` joins all arguments into a single string when quoted `"$*"`. Unquoted, both split on IFS. Use `"$@"` for safe argument passing.

B2 — `set -e`: exit on command failure. `set -u`: error on unset variables. `set -o pipefail`: pipe returns the last non-zero exit code (or first failure). Together, they enforce strict error handling.

B3 — `$(command)` and `` `command` `` are equivalent; `$(...)` is preferred for nesting and readability. `$((expression))` is bash arithmetic expansion (fast, no subshell). `expr` is an external command, slower, and requires spaces around operators.

B4 — Process substitution `<(command)` creates a file descriptor with command output. Use when a command expects file input but needs dynamic data. Example: `diff <(sort a.txt) <(sort b.txt)` avoids temp files.

B5 — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous: word splitting, glob expansion, and fails on spaces/newlines in filenames.

B6 — Here document `<<EOF` provides multi-line input. Here string `<<<` provides single-line input. `<<-EOF` strips leading tabs (not spaces) from the heredoc body for indentation.

B7 — `cmd > file 2>&1`: stdout goes to file, then stderr follows stdout to file. `cmd 2>&1 > file`: stderr goes to original stdout (terminal), then stdout goes to file. `&> file` redirects both to file. Order matters because redirections are evaluated left-to-right.

B8 — ```bash
lock_dir="/tmp/myapp.lock"
cleanup() { rm -rf "$lock_dir"; }
trap cleanup EXIT ERR INT TERM
mkdir "$lock_dir" 2>/dev/null || { echo "Locked"; exit 1; }
```
`mkdir` is atomic on POSIX filesystems, preventing race conditions. Trap ensures cleanup on normal exit, errors, or signals.

B9 — Single quotes `'...'`: literal, no expansion. Double quotes `"..."`: variable/command expansion, preserves spaces. No quotes: word splitting and glob expansion. Example: `var="hello world"; echo '$var'` → `$var`, `echo "$var"` → `hello world`, `echo $var` → `hello world` (split).

B10 — Checks: `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin: supports `&&`/`||`, regex, no word splitting/globbing, and is safer for string comparisons.

B11 — `$?`: last command exit status. `$$`: PID of current script. `$!`: PID of last background job. `$#`: number of positional parameters.

B12 — Define: `foo() { ... }` or `function foo { ... }` (latter allows `function foo()`). Return values: `return` sets exit code; use `echo`/`printf` for stdout. Use `local` for function-scoped variables.

B13 — `PATH` is a colon-separated list of directories. Bash resolves: alias → builtin → hash cache → external binary. Builtin: part of shell. External: separate executable. Use `type cmd` or `command -v cmd` to check.

B14 — `trap 'cleanup' EXIT ERR INT TERM`. ERR/INT/TERM trigger immediately; EXIT runs on script termination. Multiple signals: last received wins, or handled sequentially depending on shell state. Use `trap - INT` to ignore in cleanup.

B15 — `xargs` builds and executes commands from stdin, handling batching. `find -print0 | xargs -0` safely handles spaces/newlines. `xargs -P N` runs N processes in parallel. Cmd substitution runs once; `xargs` runs multiple times.

B16 — Arrays: `arr=(a b c)`, `${arr[0]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[@]}`. Associative uses string keys, supports `declare -A`, and lacks numeric indexing.

B17 — Subshell `(cmd)` runs in a child process; variables don't persist. Group `{ cmd; }` runs in current shell; variables persist. Piping `cmd | while read` runs `while` in a subshell, losing variable changes. Use process substitution: `while read ... done < <(cmd)`.

B18 — SIGINT (Ctrl+C, interrupt), SIGTERM (graceful kill, catchable), SIGHUP (terminal close), SIGKILL (force kill, uncatchable). Graceful shutdown: trap SIGTERM, kill background jobs, cleanup resources, then `exit`.

B19 — ```bash
split -l 10000 log.log part_
find parts -name "part_*" -print0 | xargs -0 -P 4 -I {} bash process.sh {}
cat part_* > merged.log
```
Trade-offs: CPU vs I/O bound, overhead of process creation. Error propagation: use `set -o pipefail`, check exit codes in `process.sh`, and aggregate errors in a temp file.

B20 — `exec` replaces the current shell process or manipulates file descriptors. `exec 3>file` opens FD 3; `exec 3>&-` closes it. Coprocess: `coproc cmd` creates FDs for stdin/stdout. Use for persistent background processes communicating via pipes (e.g., daemon-like scripts).

PS1 — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console, bypassing the pipeline. This matters because `Write-Host` breaks automation, logging, and pipeline chaining.

PS2 — Pipeline streams objects. `ForEach-Object` is a cmdlet that processes each object in the pipeline (streaming). `foreach` is a statement that iterates over a collection in memory. Use `ForEach-Object` for large/streaming data, `foreach` for small collections or when you need index/early exit.

PS3 — `[PSCustomObject]` is strongly typed, ordered, and pipeline-friendly. `[hashtable]` is unordered, untyped, and legacy. Convert: `[PSCustomObject]$hash` or `[ordered]@{}`. Use `PSCustomObject` for modern pipelines, `hashtable` for dynamic key-value manipulation.

PS4 — Terminating errors stop execution and are catchable. Non-terminating errors continue and are logged. `-ErrorAction` overrides per-command. `$ErrorActionPreference` sets global default. `try/catch` only catches terminating errors.

PS5 — Splatting `@params` passes a hashtable as named parameters. Example: `Get-ChildItem @opts`. Differs from passing a hashtable as a single parameter: splatting expands to multiple arguments, matching parameter names.

PS6 — `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` creates an interactive session. Uses WinRM (HTTP/HTTPS) by default; PowerShell 7+ supports SSH remoting.

PS7 — `$result += "one"` creates an array. `return $result` returns `Object[]`. `$x.GetType().Name` is `Object[]`. If 0 items, returns `$null`. Correct pattern: `[array]$result = @()` or `return @("one")`. Avoid `+=` in loops due to performance and type coercion issues.

PS8 — `[scriptblock]` is anonymous code; a function is named. Pass to remote: `-ScriptBlock $sb` or `-ArgumentList`. Double-hop: authentication fails when remoting to a second server. Solve with `-ArgumentList` (pass data, not creds), CredSSP (insecure), or delegated credentials.

PS9 — `@()` is an array subexpression; `[array]` is a type constraint. Force single result: `@($result)`. Index `$null`: throws. Index empty array: returns `$null`.

PS10 — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive variants: `-ceq`, `-clike`, `-cmatch`, `-ccontains`, `-cin`. `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection.

PS11 — `.psm1`: script module (code). `.psd1`: manifest module (metadata, dependencies). Binary module: compiled `.dll`. `Import-Module` loads into session, respects manifest, and can be automatic or explicit.

PS12 — `"..."` expands variables/expressions. `'...'` is literal. Expressions: `$(...)` or `${...}`. Here-string: `@"..."@` for multi-line strings, preserves formatting and indentation.

PS13 — `Get-Member` shows object metadata. Properties: data. Methods: actions. NoteProperties: dynamically added. `Select-Object` picks properties. `Where-Object` filters objects based on conditions.

PS14 — Classes (v5+) resemble C# but are simpler. Limitations: no multiple inheritance, limited interfaces, constructors must match signature. Use classes for complex data/models, functions for scripting.

PS15 — `[CmdletBinding()]` enables advanced features. `SupportsShouldProcess`: `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: selects params. `ValueFromPipeline`: accepts pipeline input. `Begin`/`Process`/`End`: lifecycle blocks for setup, streaming, and teardown.

PS16 — Providers abstract data stores. `Get-ChildItem` works across FileSystem, Registry, Certificate, Environment. Registry accessed like files: `Get-ChildItem HKLM:\SOFTWARE\...`.

PS17 — `[runspace]`: single-threaded execution environment. `[runspacepool]`: thread pool. `[powershell]`: API to run commands. `ForEach-Object -Parallel` (PS7+) uses built-in parallelism. Manual: create runspacepool, add commands, invoke, and manage threads.

PS18 — `PSScriptAnalyzer` enforces coding standards. Rules: predefined checks. Severity: error, warning, info. Custom rules: PowerShell scripts. Suppress: `# noqa` or config file. CI/CD: run in pipeline, fail on errors.

PS19 — `$using:` serializes variables for remote/parallel sessions. `-ArgumentList` passes values. Serialization uses CLIXML with depth/size limits (~100 depth, ~1MB). Complex objects may fail; use simple types or manual serialization.

PS20 — DSC manages desired state. Configurations: desired state definitions. Resources: components (File, Service). LCM: applies and enforces config. WinPS vs PS7: PS7 uses OpenDSC, cross-platform. Replaced by: Ansible, Terraform, Chef, Puppet, or native cloud IaC.
