G1 — Arrays are fixed-size value types with compile-time length. Slices are dynamic descriptors (ptr, len, cap) referencing an underlying array. Appending to a full-capacity slice triggers reallocation: the runtime allocates a new backing array (typically 2x capacity), copies elements, updates the slice header, and returns the new slice.

G2 — `var x int` declares with explicit type and zero value; `x := 0` is short variable declaration with type inference. You cannot use `:=` outside functions, when all variables on the LHS are already declared, or when type inference is ambiguous.

G3 — Goroutines are lightweight, multiplexed execution contexts managed by the Go runtime, unlike OS threads which are kernel-scheduled and heavier. The GMP model: G (goroutine), M (OS thread/machine), P (processor/context). The scheduler handles work-stealing, preemption, blocking syscalls, and dynamic thread pooling to maximize CPU utilization.

G4 — Channels provide synchronized communication between goroutines. Unbuffered channels block until both sender and receiver are ready. Buffered channels have a capacity; sends block only when full, receives block only when empty. Sending to a full buffered channel blocks until a receiver consumes an element.

G5 — `context` propagates cancellation, deadlines, timeouts, and request-scoped values across API boundaries. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
client.Do(req) // automatically cancels if timeout hits
```

G6 — Go uses implicit interface satisfaction (duck typing); types satisfy interfaces by implementing methods, without explicit `implements` declarations. `interface{}`/`any` holds any type, enabling generic-like flexibility but sacrificing compile-time type safety. Dangerous because type assertions can panic or silently misbehave if types don't match.

G7 — The code has a data race: no synchronization guarantees visibility of `data` and `ready` across goroutines. The compiler/CPU may reorder writes, and cache coherence isn't enforced. Fix with `sync/atomic` or `sync.Once`/channels:
```go
var ready atomic.Bool
var data atomic.Pointer[string]
go func() {
    data.Store(ptrTo("hello"))
    ready.Store(true)
}()
for !ready.Load() {}
fmt.Println(data.Load())
```

G8 — `sync.Mutex` provides exclusive access; `sync.RWMutex` allows concurrent readers or a single writer. `sync.Map` is optimized for read-heavy or key-disjoint workloads, avoiding lock contention for reads but incurring higher memory/CPU overhead. For most mixed workloads, a regular `map` + `sync.Mutex` is faster and simpler.

G9 — `go.mod` declares module path and direct dependencies. `go.sum` stores cryptographic hashes for reproducible builds. `go mod tidy` removes unused deps, adds missing ones, and cleans `go.mod`. MVS (Minimum Version Selection) resolves the dependency graph to pick the lowest compatible version for each module that satisfies all constraints.

G10 — `defer` schedules a function call to run when the enclosing function returns. Multiple defers execute in LIFO order. Gotcha in loops: variables captured by deferred closures are evaluated at defer time, not call time. Fix by passing as arguments: `defer f(i)` or shadowing inside the loop.

G11 — A pointer holds a memory address. Zero value is `nil`. Create pointer to struct literal: `&MyStruct{Field: val}`. Pointers enable mutation and avoid copying large structs.

G12 — `init()` runs once per package before `main()`. Multiple `init()` functions execute in declaration order. Across files, they run in filename-sorted order. Cannot be called manually; used for package initialization.

G13 — `make` initializes slice, map, or channel (returns initialized value). `new` allocates zeroed memory for any type and returns a pointer. `make` sets up internal structures; `new` only zero-fills.

G14 — Errors implement `error` interface with `Error() string`. Idiomatic: `if err != nil { return err }`. `errors.Is` checks against sentinel errors (unwrap chain). `errors.As` type-asserts to extract error details. `==` only matches exact pointers/values, failing with wrapped errors.

G15 — Map: nil (read-only, panics on write). Slice: nil (appendable, len=0). Channel: nil (blocks forever on send/receive). Struct: zero values of each field. All are safe to use except nil maps/channels for writes.

G16 — Race condition: concurrent unsynchronized access to shared data. `-race` flag instruments memory accesses, tracks ownership, and detects races at runtime. Example: two goroutines incrementing `counter`. Fix: `sync.Mutex` around increments, or channel-based message passing.

G17 — `select` waits on multiple channel operations. Like `switch` but non-deterministic when multiple cases are ready (random selection). Timeout: `case <-time.After(d):`. Blocks until at least one case is ready or default executes.

G18 — Escape analysis determines stack vs heap allocation based on lifetime. If a pointer outlives its function, it escapes to heap. Inspect with `go build -gcflags="-m"`. Matters because heap allocations trigger GC; excessive escaping degrades performance.

G19 — `reflect.Type` holds type metadata; `reflect.Value` holds value + operations. Costs: slow, no compile-time checks, breaks type safety. Justified for serialization, testing, ORMs. Prefer code generation (`go generate`, `stringer`) for performance-critical reflection.

G20 — `go:embed` compiles static files into `embed.FS` at build time. Works for files, directories, and glob patterns. Limitations: only static assets, no runtime modification, must be in same package. `embed.FS` implements `io/fs.FS`, enabling standard filesystem APIs on embedded data.

R1 — Ownership rules: 1. Each value has exactly one owner. 2. Only one owner at a time. 3. Owner drops value when out of scope. Prevents memory leaks/dangling pointers without GC.

R2 — `String` is owned, heap-allocated, mutable. `&str` is a borrowed string slice (immutable reference). Use `String` for ownership/modification; use `&str` in function signatures to avoid cloning and accept both `String` and `&str`.

R3 — Borrowing rules: either one `&mut T` OR any number of `&T`, both valid in same scope. Prevents data races and dangling references. Borrow checker enforces these at compile time via lifetime tracking.

R4 — `Result<T, E>` represents success/error; `Option<T>` represents `Some(T)` or `None`. `?` propagates errors/returns early. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — `Box<T>`: single owner, heap allocation. `Rc<T>`: reference-counted, single-threaded shared ownership. `Arc<T>`: atomic reference-counted, thread-safe shared ownership. Use `Box` for large/recursive types, `Rc` for single-thread sharing, `Arc` for cross-thread sharing.

R6 — Traits define shared behavior. Unlike Go interfaces, traits can have default implementations and be implemented for external types. `dyn Trait` uses dynamic dispatch (vtable, heap allocation). `T: Trait` uses static dispatch (monomorphization, zero overhead).

R7 — Compiler cannot infer which input lifetime applies to the output. Fix with explicit lifetime annotation:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — `Send`: safe to transfer ownership across threads. `Sync`: safe to share `&T` across threads. `Rc<T>` isn't `Send`/`Sync` due to non-atomic ref count. `Arc<T>` uses atomic ref counting, making it `Send`+`Sync`.

R9 — `async fn` returns a `Future` (state machine representing pending computation). Executors (Tokio) poll futures, manage I/O, and schedule on threads. Differs from Go: Rust async is library-level, lazy, and requires explicit executors; Go uses runtime-integrated, preemptive/cooperative goroutines.

R10 — `unsafe` bypasses compile-time safety. 3 capabilities: dereference raw pointers, call `unsafe` functions, implement `unsafe` traits. Justified for FFI, low-level concurrency, or performance-critical code where safety is mathematically/provenly guaranteed.

R11 — Pattern matching exhaustively handles variants. `match` requires all cases; `if let` handles one. Compiler enforces exhaustiveness in `match` (requires `_` or explicit handling), preventing unhandled cases.

R12 — `Vec<T>`: dynamic, heap-backed. `[T; N]`: fixed size, stack/inline. Vec reallocates when capacity exceeded (typically doubles), copies elements, drops old allocation, and updates pointer/len/cap.

R13 — Enums are algebraic data types; variants can hold data. `Option<T>` = `Some(T)` | `None`. Rust lacks `null` because `Option` forces explicit handling, eliminating null pointer dereferences at compile time.

R14 — `impl` blocks define methods. `&self`: borrow (immutable). `&mut self`: borrow (mutable). `self`: consume (move ownership). Associated functions (`Self::new()`) don't take `self`, acting as constructors/static methods.

R15 — `derive` macro auto-implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if fields contain types that don't implement it (e.g., `Fn` closures, raw pointers, `std::thread::Thread`).

R16 — `Cow<'a, T>` (Clone-on-Write) holds either `&'a T` or `T`. Useful when a function might return borrowed or owned data. Example: `to_lowercase()` returns `&str` if input already lowercase, clones only when mutation needed, avoiding unnecessary allocations.

R17 — `mod` declares module, `use` imports, `pub` exposes. File system: `mod.rs` or `mod_name.rs` in directory. Rust 2018: `use` paths relative to crate root, `extern crate` removed, modules can live in `src/mod_name.rs` without `mod.rs`.

R18 — `Pin<T>` guarantees a value stays at a fixed memory address. Needed for self-referential structs and async/await (futures may borrow their own fields). `Unpin` is auto-implemented for types that can be safely moved. `!Unpin` types require pinning to prevent invalidation.

R19 — Declarative macros (`macro_rules!`) use pattern matching and hygiene via `$crate`. Procedural macros: `derive` (struct/impl), `attribute` (custom attributes), `function-like` (custom functions). Hygiene prevents macro variables from leaking/colliding with caller scope.

R20 — Zero-cost abstractions: high-level features compile to efficient machine code. Iterators: zero overhead, loop unrolling, no bounds checks. Generics: monomorphization generates specialized code per type. Trait static dispatch: inline calls. Performance matches hand-written C while providing ergonomics.
