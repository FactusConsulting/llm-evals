**JS1** — `var` is function-scoped and hoisted with `undefined` initialization. `let`/`const` are block-scoped, hoisted but reside in a Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment. Hoisting is the JS compilation phase where declarations are moved to the top of their scope before execution.

**JS2** — The event loop continuously checks if the call stack is empty. If so, it drains the microtask queue (Promises, `queueMicrotask`) completely, then renders, then executes one macrotask (setTimeout, I/O, UI events). Microtasks always run before macrotasks, ensuring async promise resolution isn't starved.

**JS3** — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: a counter factory. Classic bug: `for (var i=0; i<3; i++) setTimeout(()=>console.log(i), 0)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped) or wrap in an IIFE to capture `i`.

**JS4** — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that pauses execution until the promise settles, making async code read synchronously. Error handling: `try/catch` with `await`, or `.catch()`/second `.then()` arg. `Promise.all` fails fast on first rejection. `Promise.allSettled` waits for all promises, returning an array of `{status, value/reason}` objects.

**JS5** — `interface` defines only contracts (methods/properties), supports declaration merging, and cannot hold implementations. `type` is a broader alias supporting unions, intersections, tuples, and computed types. Use `interface` for object shapes/API contracts; `type` for primitives, unions, or complex mappings. Discriminated unions use a common literal property (tag) to narrow types in `switch`/`if` statements.

**JS6** — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar over this system: `extends` sets the prototype chain, `super` calls parent constructors/methods, and `new` binds `this` and returns the instance.

**JS7** — `this` is dynamically bound based on call site. Priority order: 1. `new` (constructor instance), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (`window` or `undefined` in strict mode). `bind()` returns a new function with `this` permanently locked. It cannot be re-bound; subsequent `call`/`apply`/`bind` calls are ignored.

**JS8** — `WeakRef` holds a weak reference that doesn't prevent garbage collection. `FinalizationRegistry` triggers a callback when the target is GC'd. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the GC can track when the key is collected and automatically clean up the entry. Primitives can't be weakly referenced because they're immutable and always live.

**JS9** — V8 uses hidden classes (shapes) to optimize property access. Inline caching (IC) caches the shape lookup at call sites for O(1) access. Deoptimization occurs when assumptions break: adding properties in different orders, type changes, `eval`, `arguments` object, or `with` statements. V8 then falls back to slower dictionary mode.

**JS10** — Tree-shaking eliminates unused exports at build time. It works with ES Modules because imports/exports are static and analyzable at compile time. CommonJS uses `require()` (dynamic/runtime evaluation), so bundlers can't statically determine dependencies, making dead code elimination ineffective.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable exists but hasn't been assigned. `==` coerces types (`null == undefined` is `true`); `===` checks type and value (`false`). `??` returns the right operand only if the left is `null`/`undefined`. `?.` safely accesses nested properties without throwing on `null`/`undefined`.

**JS12** — `map()` transforms each element; `filter()` keeps elements matching a predicate; `reduce()` accumulates to a single value. Providing an initial value to `reduce()` prevents `undefined` on empty arrays and sets the accumulator type. `flatMap()` maps then flattens one level; useful for transforming arrays and flattening results in a single pass.

**JS13** — Template literals use backticks, support `${}` interpolation and multiline strings. Tagged templates pass a function an array of string parts and expression values. Example: `sql` tag for parameterized queries or `html` tag for escaping: `function html(strings, ...values) { return strings.reduce((acc, s, i) => acc + s + (values[i] ? escape(values[i]) : ''), ''); }`

**JS14** — Destructuring unpacks values from arrays/objects. Object: `{a, b}` or `{a: x}`. Array: `[a, b]`. Defaults: `{a = 1}`. Renaming: `{a: newName}`. Rest: `{...rest}` collects remaining properties. Works in assignments, function parameters, and loops. Prevents verbose property access and enables clean API contracts.

**JS15** — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, Maps). Avoid `for...in` on arrays because it iterates keys, not values, includes inherited properties, and doesn't guarantee order. Use `for...of` for value iteration.

**JS16** — Generics parameterize types. Constraints: `T extends SomeType` limits valid types. Conditional types: `T extends U ? X : Y` branches based on type. `infer` extracts a type in conditional context. Example: `type Unwrap<T> = T extends Promise<infer U> ? U : T;` extracts the resolved type from a Promise.

**JS17** — CommonJS (CJS) uses `require()`/`module.exports`, is synchronous, and exports an object that can be mutated. ES Modules (ESM) use `import`/`export`, are static, immutable, and async by default. Node.js supports both via `.mjs` extension or `"type": "module"` in `package.json`. ESM enables tree-shaking and better static analysis.

**JS18** — TypeScript uses structural typing: compatibility is based on shape, not names. Excess property checks apply only during object literal creation to catch typos. `extends` checks assignability; `satisfies` checks if an expression matches a type without widening, preserving the original type. TS 4.7+ supports `in`/`out`/`in out` variance modifiers on type parameters for safer generic covariance/contravariance.

**JS19** — `Proxy` wraps an object to intercept operations (get, set, apply, etc.). `Reflect` mirrors Proxy traps and provides default behavior. Example: validation proxy that throws on invalid assignment. Reactive data binding: Proxy tracks changes via `Reflect.get/set`, triggers update listeners, and enables frameworks like Vue to track dependencies automatically.

**JS20** — `SharedArrayBuffer` enables shared memory between the main thread and Web Workers. `Atomics` provides atomic operations and synchronization. Ordering guarantees are sequential consistency. `Atomics.wait` blocks until a value changes or timeout; `Atomics.notify` wakes waiting threads. Requires Cross-Origin Isolation headers to prevent Spectre attacks.

**B1** — `$@` expands to separate quoted words (`"$1" "$2"`), preserving individual arguments. `$*` expands to a single string (`"$1 $2 ..."`). `"$@"` is safe for argument passing; `"$*"` joins them with `$IFS`. Use `"$@"` in loops or command forwarding.

**B2** — `set -e`: exit immediately on non-zero exit status. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the rightmost non-zero exit code (or zero if all succeed). Together, they enforce strict error handling and prevent silent failures.

**B3** — `$(command)` is modern, supports nesting, and is preferred over legacy backticks `` `command` ``. `$((expression))` is built-in arithmetic expansion (faster, supports more operators, no external process). `expr` is an external command, slower, and limited in operator support.

**B4** — Process substitution `<(command)` creates a temporary file descriptor (e.g., `/dev/fd/63`) containing the command's output. Used when a command expects file input but needs dynamic data. Example: `diff <(sort file1) <(sort file2)` compares sorted outputs without creating temp files.

**B5** — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous because it splits on spaces, expands globs, fails on newlines, and is an unnecessary use of `ls`.

**B6** — Here document `<<EOF` feeds multi-line input until `EOF`. Here string `<<<` feeds a single line. `<<-EOF` strips leading tabs (not spaces) from the heredoc body, allowing clean indentation in scripts.

**B7** — `cmd > file 2>&1`: stdout goes to file, then stderr redirects to stdout (now file). `cmd 2>&1 > file`: stderr redirects to original stdout (terminal), then stdout goes to file. `cmd &> file` is bash shorthand for the first. The first two differ because redirections are evaluated left-to-right.

**B8** — ```bash
lock_dir="my.lock"
trap 'rmdir "$lock_dir" 2>/dev/null' EXIT INT TERM
mkdir "$lock_dir" 2>/dev/null || { echo "Locked"; exit 1; }
# ... work ...
```
`mkdir` is atomic on POSIX filesystems, preventing race conditions. `trap` ensures cleanup on normal exit or signals. `2>/dev/null` suppresses errors if already locked.

**B9** — Single quotes `'...'`: literal, no expansion. Double quotes `"..."`: allows variable/command expansion, preserves spaces. No quotes: triggers word splitting and globbing. Example: `var="a b"; echo '$var'` → `$var`; `echo "$var"` → `a b`; `echo $var` → `a b` (or splits if IFS contains space).

**B10** — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]` check existence, directory, readability. `[[ ]]` is a bash builtin: supports `&&`/`||`, regex (`=~`), no word splitting/globbing on RHS, and is safer for complex conditions.

**B11** — `$?`: last command exit status (error handling). `$$`: current script PID (logging/temp files). `$!`: last background job PID (job control). `$#`: number of positional parameters (argument validation).

**B12** — `foo() { ... }` or `function foo { ... }` (latter allows `function foo()`). Return values: `return` sets exit code (0-255). For data, `echo` to stdout or use global variables. Functions share the parent scope, so variable assignment persists.

**B13** — `PATH` is a colon-separated list of directories bash searches for executables. Resolution order: aliases → functions → builtins → PATH. Builtins are compiled into the shell (faster, no fork). External commands are separate binaries. `type cmd` or `command -v cmd` shows which is used.

**B14** — `trap 'cleanup' EXIT INT TERM` sets handlers. `ERR` fires on non-zero exit. Signals interrupt execution; traps run sequentially. Multiple signals arriving during a trap are queued or handled based on shell state. `EXIT` always runs, even on `exit` or script end.

**B15** — `xargs` builds command lines from stdin; command substitution runs once. `xargs -0` + `find -print0` handles spaces/newlines safely. `xargs -P N` runs N processes in parallel, improving throughput for I/O-bound tasks.

**B16** — Indexed arrays: `arr=(a b c)`, length `${#arr[@]}`, iterate `for i in "${arr[@]}"`. Associative arrays: `declare -A assoc`, key-value pairs, similar syntax but uses keys. Associative arrays require explicit declaration and support string keys.

**B17** — Subshell `(cmd)` runs in a child process; variable changes don't affect parent. Group `{ cmd; }` runs in the current shell. Piping to `while` creates a subshell, so variable changes are lost. Fix: `while ... done < <(cmd)` or `cmd | while ... done` with process substitution.

**B18** — SIGINT (Ctrl+C, interrupt), SIGTERM (graceful kill, catchable), SIGHUP (terminal close/reload), SIGKILL (force kill, uncatchable). Graceful shutdown: trap SIGTERM, wait for background jobs (`wait`), cleanup resources, then exit.

**B19** — ```bash
split -l 10000 log.log log.part.
find . -name "log.part.*" -print0 | xargs -0 -P 4 -I {} bash process.sh {}
cat log.part.* > merged.log
```
Trade-offs: parallelism increases CPU usage but reduces wall time; overhead from spawning processes. Error propagation: use `set -o pipefail`, check exit codes in `process.sh`, and aggregate errors in a temp file.

**B20** — `exec` replaces the current shell process or redirects file descriptors. `exec 3>file` opens FD 3; `exec 3>&-` closes it. Coprocess: `coproc CMD` creates a bidirectional pipe. Use for persistent background processes communicating with the parent (e.g., daemon-like scripts).

**PS1** — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console, bypassing the pipeline. Distinction matters because `Write-Host` breaks automation, logging, and piping; use `Write-Output` for data flow.

**PS2** — Pipeline streams objects. `ForEach-Object` is a cmdlet that processes each object in the pipeline (streaming, memory-efficient). `foreach` is a statement that iterates over a collection in memory. Use `ForEach-Object` for large streams; `foreach` for small collections or when you need index/early exit.

**PS3** — `[PSCustomObject]` is strongly typed, ordered, and pipeline-friendly. Hashtable is unordered, faster for lookups. Convert: `[PSCustomObject]$hash` or `[ordered]@{}`. Use `PSCustomObject` for output/serialization; hashtable for config/lookup tables.

**PS4** — Terminating errors stop execution and can be caught by `try/catch`. Non-terminating errors continue execution and are logged. `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors; use `-ErrorAction Stop` to convert non-terminating to terminating.

**PS5** — Splatting `@params` passes a hashtable as named parameters. `@params` expands to individual arguments; passing a hashtable as a single parameter sends the entire object as one argument. Splatting improves readability and enables dynamic parameter passing.

**PS6** — `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` creates an interactive session. Uses WinRM (HTTP/HTTPS) by default; PowerShell 7+ supports SSH. Remoting serializes objects via CLIXML.

**PS7** — Pipeline flattens arrays. `$result += "one"` creates an array. If function returns 0 items, it returns `$null`. `$x.GetType().Name` → `Object[]` (or `String` if single). Correct pattern: `[array]$result = @()` or `@()` to force array. Pipeline behavior can cause unexpected type coercion.

**PS8** — `[scriptblock]` is an anonymous code block; functions are named. Pass to remote via `-ScriptBlock` or `-ArgumentList`. Double-hop: auth fails when remoting to B then C. Solve with `-ArgumentList` (pass data, not credentials), CredSSP (insecure), or constrained endpoints.

**PS9** — `@()` is an array subexpression; `[array]` is a type constraint. Force single result: `@($result)`. Indexing `$null` throws; indexing empty array returns nothing. `@()` ensures consistent array output in pipelines.

**PS10** — `-eq`/`-ne` (equality), `-like` (wildcards), `-match` (regex), `-contains`/`-in` (membership). Case-sensitive: `-ceq`, `-clike`, `-cmatch`, `-ccontains`, `-cin`. `-contains`: left is collection, right is item. `-in`: left is item, right is collection.

**PS11** — Module: `.psm1` (code), `.psd1` (manifest/metadata), binary (`.dll`). `Import-Module` loads into session, respects scope, path, and manifest. Manifest controls version, dependencies, and exported commands.

**PS12** — `"..."` expands variables/expressions `${}`. `'...'` is literal. Here-string `@"..."@` for multi-line. Expressions in strings: `"Value: $var"` or `"Value: ${complex}"`.

**PS13** — `Get-Member` explores object members. Properties (data), Methods (actions), NoteProperties (custom). `Select-Object` picks properties. `Where-Object` filters objects. Use `Get-Member` to discover available members.

**PS14** — Classes (v5+) are C#-like. Limitations: no multiple inheritance, limited interface support, constructors must match signature. Use classes for complex data/models; functions for scripting. Classes enable encapsulation and type safety.

**PS15** — `CmdletBinding` enables advanced features: parameters, help, pipeline binding. `SupportsShouldProcess` enables `-WhatIf`/`-Confirm`. `DefaultParameterSetName` selects params. `Begin`/`Process`/`End` blocks handle pipeline lifecycle.

**PS16** — Providers abstract data stores. `Get-ChildItem` works on FileSystem, Registry, Cert, Env. Registry accessed via `HKLM:\` or `HKCU:\` like filesystem. Providers enable consistent cmdlet usage across data sources.

**PS17** — Runspaces: `[runspace]` (single), `[runspacepool]` (multiple), `[powershell]` (command container). `ForEach-Object -Parallel` (v7+) uses runspace pool automatically. Manual: create pool, add runspace, manage jobs. Thread safety: PS objects aren't thread-safe; use locks or runspace isolation.

**PS18** — PSScriptAnalyzer: linting tool. Rules: syntax, performance, best practices. Severity: error, warning, info. Suppress: `#pragma` or config file. CI/CD: run in pipeline, fail on errors. Enforces consistent, maintainable code.

**PS19** — `$using:` scope serializes variables for remote/parallel contexts. `-ArgumentList` passes values. Serialization limits: CLIXML depth/size, complex objects may fail. Use simple types or serialize to JSON. `$using:` is convenient but has overhead.

**PS20** — DSC: declarative config. Configurations: desired state. Resources: components (File, Service). LCM: applies config. WinPS vs PS7: PS7 uses MOF-less, JSON-based, cross-platform. Replaced by: Terraform, Ansible, Chef, or native cloud IaC for modern infrastructure.
