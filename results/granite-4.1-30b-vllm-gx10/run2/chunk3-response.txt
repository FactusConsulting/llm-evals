**OpenTofu / Terraform**

**T1 — Easy:**  
`tofu plan` generates and displays the execution plan, showing what actions will be performed without making any changes. `tofu apply` executes the actions in the plan, creating, updating, or deleting resources in the infrastructure.

**T2 — Easy:**  
State in OpenTofu is a snapshot of the current infrastructure (resource IDs, attributes, metadata) stored in a file (or remote backend). Remote state is crucial for collaboration (multiple users can safely run commands), state consistency across environments, and security (sensitive data can be encrypted and access‑controlled).

**T3 — Medium:**  
- `count` creates a fixed number of identical instances based on an integer.  
- `for_each` creates instances based on a map or set, allowing each instance to have distinct attributes (e.g., names, tags).  
`for_each` is preferred when you need unique identifiers or per‑instance configuration; `count` is simpler for homogeneous copies.

**T4 — Medium:**  
If a resource is changed manually, the next `tofu plan` will detect a drift: the current configuration (from the provider) differs from the state. OpenTofu will propose an update to reconcile the difference (e.g., overwrite the manual change or adjust the state). To preserve manual changes, use `lifecycle { prevent_destroy = true }` or `ignore_changes`.

**T5 — Medium:**  
```hcl
resource "example_vm" "web" {
  for_each = toset(["web1", "web2", "web3"])
  name     = each.value
  # other arguments...
}
```

**T6 — Hard:**  
`terraform_remote_state` data source reads state from another workspace/backend, exposing its outputs as local values. Output values are defined within a module and returned to its caller. The recommended alternative is **module composition** (calling the module directly) because it keeps dependencies explicit, avoids stale state, and enables better versioning and plan/apply consistency.

**T7 — Hard:**  
The `kubeconfig` output depends on a `null_resource` with a `remote-exec` provisioner that runs after the cluster is up. On the first apply, the provisioner hasn’t executed yet, so the output is empty, causing downstream resources to fail. Fix:  
- Use `depends_on` to explicitly order resources, **or**  
- Move the kubeconfig generation into a separate `local-exec` script that runs after the cluster is ready, **or**  
- Use `null_resource` with `triggers` that ensure the provisioner runs before the output is consumed.

**T8 — Medium:**  
`tofu import` brings existing infrastructure under Terraform management by mapping live resources to configuration. Limitations: complex attribute mapping, state‑only import (no configuration), and potential for state drift. The `import` block (1.5+) allows declarative import definitions, version‑controlled mapping, and automatic handling of missing attributes, reducing CLI‑only errors.

**T9 — Easy:**  
A **variable** (input) lets users supply values to a module/configuration. An **output** exposes values (e.g., IDs, endpoints) produced by the configuration for consumption by other modules or scripts.

**T10 — Easy:**  
A **provider** defines the API and authentication for a cloud/service (AWS, Azure, etc.). Running `tofu plan` without `tofu init` fails because the provider plugins and modules aren’t downloaded; `init` prepares the working directory.

**T11 — Easy:**  
`.terraform.lock.hcl` records exact versions of providers and modules used, ensuring reproducible runs. Committing it guarantees all collaborators use the same dependency graph, preventing “works on my machine” issues.

**T12 — Easy:**  
`tofu destroy` deletes all resources managed by the current configuration. To target a single resource: `tofu destroy -target=resource_type.resource_name`.

**T13 — Easy:**  
A **data source** reads information from external systems without creating resources (e.g., `aws_ami` lookup, `http` GET). Use a data source when you need existing state (like an AMI ID) rather than provisioning a new resource.

**T14 — Medium:**  
- **locals** are computed values scoped to the module, derived from inputs or constants, and are not configurable by users.  
- **variables** are inputs supplied by users.  
Use **locals** for reusable derived values, defaults, or complex expressions that shouldn’t be exposed as configurable parameters.

**T15 — Medium:**  
The **lifecycle** block customizes resource behavior:  
- `create_before_destroy` ensures a new resource is created before the old one is removed (useful for zero‑downtime migrations).  
- `prevent_destroy` blocks accidental deletion (protect critical resources).  
- `ignore_changes` tells Terraform to tolerate modifications to certain attributes (e.g., externally managed tags).  

**T16 — Medium:**  
A **moved block** records that a resource’s configuration has been relocated (e.g., from one module to another) without destroying/recreating it. It updates the state file to reflect the new path, preserving the underlying infrastructure.

**T17 — Hard:**  
OpenTofu builds a **dependency graph** from implicit references (attribute values) and explicit `depends_on`. Implicit dependencies enable automatic ordering; explicit `depends_on` forces additional ordering but can reduce parallelism because Terraform may delay execution of dependent resources. Use `depends_on` sparingly to avoid unnecessary serial execution.

**T18 — Hard:**  
Strategies to reduce long `plan` times:  
1. **Targeted planning** (`-target`) to limit scope.  
2. **State pruning** (remove unused resources).  
3. **Parallelism tuning** (`-refresh=false`, `-compact-warnings`).  
4. **Remote execution** (use a faster CI runner or provisioner caching).  
5. **Modularization** (split large configs into smaller modules).  
Trade‑offs include increased complexity, risk of missing cross‑module dependencies, and potential for stale state if refresh is disabled.

**T19 — Hard:**  
OpenTofu locks the state file (via backend‑specific mechanisms like DynamoDB) before any write operation to prevent concurrent modifications. If a lock isn’t released (e.g., CI crash), subsequent runs block. To break a lock manually: use `tofu force-unlock <lock-id>` (or backend‑specific CLI). Risks include state corruption if another process was mid‑apply; always verify state integrity afterward.

**T20 — Hard:**  
1. **Add remote backend** in configuration:  
   ```hcl
   terraform {
     backend "s3" {
       bucket         = "my-terraform-state"
       key            = "path/to/state.tfstate"
       region         = "us-east-1"
       dynamodb_table = "terraform-locks"
     }
   }
   ```
2. Run `tofu init -migrate-state` – this copies the local `.tfstate` to the S3 bucket and creates the lock table entry.  
3. Verify: `tofu state list` should show resources from the remote state; `tofu plan` should succeed without local state file.  
4. Remove the old local `terraform.tfstate` (or keep a backup) and commit the updated `terraform` block.

**Ansible**

**A1 — Easy:**  
- **Playbook**: YAML file that defines a set of plays (host groups + tasks).  
- **Role**: Reusable modular directory structure (tasks, handlers, templates, vars, defaults) that encapsulates functionality.  
- **Task**: A single action (module call) executed on a host, defined inside a play or role.

**A2 — Easy:**  
`ansible_facts` is a dictionary of system information gathered by the `setup` module. Access the OS family via `{{ ansible_facts.os_family }}` (e.g., “Debian”, “RedHat”).

**A3 — Medium:**  
- **command**: Executes a system command without a shell; arguments are passed directly (no shell expansion).  
- **shell**: Runs through the target’s shell, allowing pipes, redirects, and variable expansion.  
- **raw**: Bypasses Python dependency, sending raw SSH commands; used for bootstrapping Python‑less hosts.  
Use **command** for simple, predictable calls; **shell** when shell features are needed; **raw** for initial provisioning.

**A4 — Medium:**  
Idempotency means running a task multiple times produces the same state without side effects.  
- **Idempotent**: `apt: name=nginx state=present` (re‑running leaves nginx installed).  
- **Non‑idempotent**: `command: echo "hello" > /tmp/file` (each run overwrites, changing file content). Use modules with state parameters or `register` + `when` to achieve idempotence.

**A5 — Medium:**  
```yaml
- name: Install htop with correct package manager
  package:
    name:
      - "{{ ansible_facts.os_family == 'Debian' | ternary('htop', 'htop') }}"
      - "{{ ansible_facts.os_family == 'RedHat' | ternary('epel-release', '') }}"
    state: present
  when: ansible_facts.os_family == 'Debian' or ansible_facts.os_family == 'RedHat'
  become: yes
```
(Alternatively, use two tasks with separate `when` clauses.)

**A6 — Hard:**  
Variable precedence (highest → lowest):  
1. **Role defaults**  
2. **Role vars (role/vars)**  
3. **Included/required role vars**  
4. **Play vars** (`vars:` section)  
5. **Play vars_prompt / vars_files**  
6. **Host vars** (`host_vars/<host>`)  
7. **Group vars** (`group_vars/<group>`)  
8. **Extra vars** (`-e var=val` on CLI)  
9. **set_fact / register** (runtime facts)  
10. **Inventory source vars**  

**A7 — Hard:**  
```yaml
- hosts: rke2_nodes
  serial: 3                 # first 3 nodes run concurrently
  tasks:
    - name: Deploy RKE2 agent
      include_role:
        name: rke2_agent
  post_tasks:
    - name: Wait for first 3 nodes to finish
      wait_for:
        host: "{{ inventory_hostname }}"
        port: 6443
        delay: 10
        timeout: 300
  when: inventory_hostname in groups['rke2_nodes'][:3]
  
- hosts: rke2_nodes:!rke2_nodes[:3]
  serial: 5                 # remaining nodes in batches of 5
  tasks:
    - name: Deploy RKE2 agent (remaining)
      include_role:
        name: rke2_agent
```
Use `wait_for` or `pause` after the first batch to ensure they’re ready before the rest start.

**A8 — Hard:**  
`ansible-vault` encrypts sensitive data. To encrypt a single variable:  
```bash
ansible-vault encrypt_string 'secret_value' --name 'my_var' --vault-password-file .vault_pass.txt
```  
Insert the resulting ciphertext into the vars file, e.g., `my_var: !vault | ...`. The rest of the file remains plain text.

**A9 — Easy:**  
An **inventory** lists managed hosts.  
- **Static inventory**: Plain text file (INI or YAML) manually edited.  
- **Dynamic inventory**: Script or program that generates JSON host lists (e.g., AWS EC2, OpenStack) on demand.

**A10 — Easy:**  
```bash
ansible webservers -m command -a "df -h /"
```  
or using the `setup` module: `ansible webservers -m setup -a "filter=ansible_mounts"`.  

**A11 — Easy:**  
A **handler** is a special task notified by other tasks via `notify`. It runs **once** after all tasks in a play complete, typically for service restarts. Trigger with `notify: restart apache`.

**A12 — Easy:**  
`ansible.cfg` centralizes configuration. Common settings:  
- `inventory = ./inventory`  
- `remote_user = ubuntu`  
- `private_key_file = ~/.ssh/id_rsa`  
- `roles_path = ./roles`  

**A13 — Easy:**  
`register` captures output of a task for later use:  
```yaml
- name: Get package list
  command: dpkg -l
  register: pkg_list

- name: Show installed packages
  debug:
    msg: "{{ pkg_list.stdout }}"
```  

**A14 — Medium:**  
- **include_tasks**: Dynamic inclusion; evaluated at runtime, supports conditionals (`when`).  
- **import_tasks**: Static inclusion; parsed at compile time, cannot use `when` on the include itself (only on tasks inside).  
Use **include_tasks** for conditional task sets; **import_tasks** for fixed, reusable task collections.

**A15 — Hard:**  
**Ansible Galaxy** is a repository for roles and collections. A `requirements.yml` lists items:  
```yaml
roles:
  - src: geerlingguy.docker
    version: 3.2.0
collections:
  - name: community.general
```
Run `ansible-galaxy install -r requirements.yml` to fetch them.

**A16 — Hard:**  
Connection plugins determine how Ansible reaches hosts.  
- **ssh**: Default, uses SSH for Linux/Unix.  
- **local**: Runs tasks on the control node itself.  
- **network_cli**: For network devices using CLI (e.g., Cisco IOS).  
Choose based on target type: SSH for servers, local for control‑node ops, network_cli for routers/switches.

**A17 — Hard:**  
`delegate_to: localhost` runs a task on the control node. `run_once: true` ensures it executes a single time even if multiple hosts are delegated. Example: gather IPs from all web servers, then create a firewall rule on the bastion:  
```yaml
- name: Collect web server IPs
  command: hostname -I
  run_once: false
  register: web_ips

- name: Add IPs to bastion firewall
  lineinfile:
    path: /etc/firewall/allowed_ips.conf
    line: "{{ item }}"
  with_items: "{{ web_ips.results | map(attribute='stdout') | list }}"
  delegate_to: localhost
  run_once: true
```

**A18 — Hard:**  
Performance tactics for 500 hosts:  
1. **Increase forks** (`forks: 100` in ansible.cfg) to parallelize more tasks.  
2. **Enable pipelining** (`pipelining = true`) to reduce SSH overhead.  
3. **Fact caching** (`fact_caching = jsonfile`) avoids repeated fact gathering.  
4. **Mitogen** plugin accelerates connection handling, cutting latency dramatically.  
Trade‑offs: higher forks consume more control‑node resources; pipelining requires Python on remote hosts; cached facts may become stale; Mitogen adds dependency complexity.

**A19 — Hard:**  
Jinja2 templating syntax:  
- `{{ }}` – expression evaluation (output).  
- `{% %}` – control structures (loops, conditionals).  
- `{# #}` – comments (not rendered).  

Template snippet for Nginx upstream:  
```jinja
upstream backend {
{%- for server in servers %}
  server {{ server.host }}:{{ server.port }} {% if server.health_check %} # health check enabled {% endif %};
{%- endfor %}
}
```

**A20 — Hard:**  
Zero‑downtime rolling deployment (20 servers):  
```yaml
- hosts: webservers
  serial: 4                     # update 4 servers at a time
  become: yes
  vars:
    lb_group: loadbalancers

  pre_tasks:
    - name: Remove server from LB
      uri:
        url: "http://{{ inventory_hostname }}:8080/lb/remove"
        method: POST
        body: "{{ ansible_host }}"

  tasks:
    - name: Deploy new release
      include_role:
        name: deploy_app

  post_tasks:
    - name: Health check
      uri:
        url: "http://{{ ansible_host }}/health"
        status_code: 200
      retries: 5
      delay: 10
      until: result.status == 200

    - name: Add server back to LB
      uri:
        url: "http://{{ inventory_hostname }}:8080/lb/add"
        method: POST
        body: "{{ ansible_host }}"

  rescue:
    - name: Rollback on failure
      include_role:
        name: rollback_app
    - name: Re‑add to LB after rollback
      uri:
        url: "http://{{ inventory_hostname }}:8080/lb/add"
        method: POST
        body: "{{ ansible_host }}"
```
Explanation:  
- **serial** limits concurrent updates.  
- **pre_tasks** deregister the server from the load balancer.  
- **post_tasks** verify health before re‑registration.  
- **rescue** block performs rollback and re‑adds the server if any step fails.
