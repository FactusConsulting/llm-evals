**Networking**

**N1** — A Layer 2 (L2) switch forwards Ethernet frames based solely on MAC addresses within a single broadcast domain. It builds a MAC‑address table and learns ports dynamically. A Layer 3 (L3) switch, in addition to L2 switching, can route IP packets by examining the IP header, maintaining an IP routing table, and performing inter‑VLAN routing. Essentially, an L3 switch combines switching with router functionality.

**N2** — A /20 mask is 255.255.240.0 (binary: 11111111.11111111.11110000.00000000).  
- **Network address**: 10.0.0.0 (the first address of the block).  
- **Broadcast address**: 10.0.15.255 (the last address, all host bits set to 1).

**N3** — The TCP three‑way handshake:  
1. **SYN** – Client → Server (client proposes initial sequence number).  
2. **SYN‑ACK** – Server → Client (server acknowledges client’s SYN and sends its own SYN with its ISN).  
3. **ACK** – Client → Server (client acknowledges the server’s SYN).  
After step 2 the server is in **SYN_RCVD** and holds a half‑open connection. If the final ACK is lost, the client moves to **ESTABLISHED**, but the server stays in **SYN_RCVD** and will retransmit the SYN‑ACK a few times before timing out and discarding the half‑open state. Retransmissions eventually expire, leaving the connection non‑functional.

**N4** — **SNAT (Source NAT)** rewrites the source IP/port of an outgoing packet so that replies return to the NAT device. *Example*: A home router changes 192.168.1.10:1234 to its public WAN IP (e.g., 203.0.113.5:5000) so that external servers can reply to the router.  
**DNAT (Destination NAT)** rewrites the destination IP/port of an incoming packet, typically for inbound services. *Example*: A firewall translates traffic to its public IP 203.0.113.5:80 to an internal web server at 10.0.0.2:80.  

**N5** — Possible causes for “SSL: certificate subject name does not match target host name”:  
1. **Server misconfiguration** – the TLS certificate’s Common Name (CN) or Subject Alternative Names (SANs) do not include `example.com`.  
2. **DNS mismatch** – the resolved IP address may point to a different host whose certificate is for another name.  
3. **Local hostname override** – using an IP address directly (`curl http://203.0.113.5`) while the certificate is issued for a domain name, causing the name check to fail.

**N6** — **VLAN (Virtual LAN)** segments traffic at Layer 2 using a 12‑bit tag (802.1Q) within a single physical network. It is limited to 4096 IDs and requires each physical switch to be configured for the VLANs it carries.  
**VxLAN (Virtual Extensible LAN)** encapsulates Layer 2 frames inside UDP packets, allowing up to 16 million logical segments (24‑bit VNI) and extending VLANs over Layer 3 networks (IP or overlay). Choose VxLAN when you need:  
- Large scale multi‑tenant environments,  
- Spanning Layer 3 domains (e.g., data‑center interconnects), or  
- Overcoming 4096 VLAN limit while preserving L2 semantics.

**N7** — The default routing table sends all non‑local traffic out the interface with the default gateway (eth0). Because eth1’s subnet (192.168.1.0/24) is directly connected, replies to traffic arriving on eth1 are routed via the default gateway (eth0) instead of the incoming interface.  
**Fix with policy‑based routing**:  
```bash
# Create a routing table
echo "200 outvia_eth1" >> /etc/iproute2/rt_tables

# Add a rule that matches source address from eth1
ip rule add from 192.168.1.5 lookup outvia_eth1

# Populate the table with a default route via eth1’s gateway (if any) or directly
ip route add default via 192.168.1.1 dev eth1 table outvia_eth1
```
Now packets sourced from 192.168.1.5 use the `outvia_eth1` table, sending replies out eth1.

**N8** — BGP path selection (in order of preference):  
1. **Neighbor type** – Prefer eBGP paths over iBGP.  
2. **Highest weight** (Cisco‑specific, not standardized).  
3. **Highest local preference** (`LOCAL_PREF`).  
4. **Shortest AS_PATH** (fewest AS numbers).  
5. **Origin code** – Prefer `IGP` (i) over `EGP` (e) over `Incomplete` (?).  
6. **Lowest MED** (`MULTI_EXIT_DISC`) – lower is better, but only compared between paths to the same AS.  
7. **Prefer eBGP over iBGP** (again, if not already decided).  
8. **Shortest IGP metric to next hop** (router’s IGP best path).  
9. **Oldest path** (lowest router ID or lowest neighbor ID as tiebreaker).  

**N9** — VxLAN adds an outer header (UDP + IP) plus an 8‑byte VTEP header, totaling ≈ 50 bytes. IPsec (ESP) adds another ≈ 50 bytes (plus possible authentication header).  
**MTU math**:  
- Physical MTU = 1500 bytes.  
- Subtract outer IP (20) + UDP (8) + VxLAN (8) + ESP (50) + optional ESP‑auth (0‑56).  
Assuming no auth header: 1500 − (20 + 8 + 8 + 50) = **1414 bytes** maximum inner payload (including inner IP header). With ESP‑auth (e.g., 56 bytes) it would be 1500 − (20 + 8 + 8 + 50 + 56) = **1358 bytes**.

**N10** — **ARP (Address Resolution Protocol)** resolves an IPv4 address to a MAC address on the local link.  
**Gratuitous ARP** is an ARP reply sent by a host without a preceding ARP request, announcing “my IP is at this MAC”. It solves:  
- Notifying other hosts of a changed MAC (e.g., after NIC replacement or VM migration).  
- Detecting IP conflicts (if another host replies with the same IP).  

**N11** — **Public IP** addresses are globally unique and routable on the Internet (e.g., 8.8.8.8). **Private IP** addresses are reserved for internal use and not routed on the public Internet. RFC 1918 defines three private ranges:  
- 10.0.0.0 – 10.255.255.255 (/8)  
- 172.16.0.0 – 172.31.255.255 (/12)  
- 192.168.0.0 – 192.168.255.255 (/16)

**N12** — **DNS (Domain Name System)** translates domain names to IP addresses.  
- **A record** maps a domain name to an IPv4 address.  
- **AAAA record** maps a domain name to an IPv6 address.  
- **CNAME record** aliases one name to another (canonical name); the target must be an A/AAAA or another CNAME, and a CNAME cannot coexist with other record types at the same name.

**N13** — **DHCP (Dynamic Host Configuration Protocol)** automates IP address assignment. The client follows the **DORA** sequence:  
1. **Discover** – Broadcasts DHCPDISCOVER to locate servers.  
2. **Offer** – Servers respond with DHCPOFFER (proposed IP, lease, options).  
3. **Request** – Client selects an offer and broadcasts DHCPREQUEST to claim it.  
4. **ACK** – Server sends DHCPACK confirming the lease; client configures its interface.

**N14** — **Hub**: Operates at **OSI Layer 1** (physical). It blindly repeats bits on all ports, creating a single collision domain.  
**Switch**: Works at **Layer 2** (data link). It learns MAC addresses, forwards frames only to the destination port, reducing collisions.  
**Router**: Functions at **Layer 3** (network). It examines IP headers, performs inter‑network routing, and can enforce policies (NAT, firewall, etc.).

**N15** — **Half‑duplex** allows transmission **or** reception on a medium at a time (e.g., classic 10BASE‑T hubs). Collisions occur, and CSMA/CD manages access.  
**Full‑duplex** enables simultaneous send and receive over separate wire pairs, eliminating collisions. Modern Ethernet (fast/​gigabit/​10GbE) almost universally uses full‑duplex when connected via switches or point‑to‑point links.

**N16** — **TTL (Time‑to‑Live)** limits an IP packet’s lifespan; each router decrements TTL by 1 and discards the packet if it reaches 0, preventing endless loops.  
**traceroute** exploits TTL by sending packets with incrementing TTL values (1, 2, 3,…). When a router decrements TTL to 0, it returns an ICMP “Time Exceeded” message, revealing the hop’s IP address. By iterating TTL, traceroute maps the path.

**N17** — A **NAT gateway** translates private IP addresses to a public address (or vice‑versa) for traffic crossing network boundaries.  
- **Static NAT**: One‑to‑one mapping (e.g., internal 10.0.0.5 ↔ public 203.0.113.5).  
- **Dynamic NAT**: Maps a private IP to any available address from a pool.  
- **PAT (Port Address Translation, also NAT‑overload)**: Maps multiple private IPs to a single public IP using distinct source ports, allowing thousands of simultaneous connections with one public address.

**N18** — **ECMP (Equal‑Cost Multi‑Path)** routes traffic over multiple next‑hops that have identical metric costs. The router hashes packet‑level fields (src/dst IP, ports, etc.) to select a path, aiming for even load distribution.  
**Hashing strategies**: simple modulo, CRC‑based, or universal hashing.  
**Asymmetric flow issue**: Stateful firewalls inspect full 5‑tuple; if ECMP sends packets of the same flow over different paths, the firewall may see them as unrelated sessions, dropping or mis‑ordering packets. Solutions include using a consistent hash that includes all 5‑tuple fields or employing firewalls that support ECMP awareness.

**N19** — The **bandwidth‑delay product (BDP)** = bandwidth (bits/s) × round‑trip time (s). With a BDP of 10 MB, the sender could have 10 MB of unacknowledged data in flight. The default TCP window size without scaling is 64 KB, far too small to utilize the available capacity, causing the sender to throttle and experience high latency.  
**TCP window scaling (RFC 1323)** allows the window size to be multiplied by a shift value (0‑14), enabling windows up to 1 GB. Enabling scaling lets the sender advertise a larger window, filling the BDP and restoring throughput.

**N20** — **802.1Q trunk ports** carry traffic for multiple VLANs by inserting a 4‑byte 802.1Q tag (TPID 0x8100 + TCI) into each Ethernet frame. The tag includes a VLAN ID (VID, 12 bits) and optional priority bits.  
**Linux configuration for a single NIC to reach VLAN 10, 20, 30**:  
```bash
# Assume physical interface is eth0
ip link add link eth0 name eth0.10 type vlan id 10
ip link add link eth0 name eth0.20 type vlan id 20
ip link add link eth0 name eth0.30 type vlan id 30

ip addr add 10.10.10.5/24 dev eth0.10
ip addr add 10.20.20.5/24 dev eth0.20
ip addr add 10.30.30.5/24 dev eth0.30
ip link set eth0.10 up
ip link set eth0.20 up
ip link set eth0.30 up
```
**On‑wire frame format**: `Preamble → SFD → Destination MAC → Source MAC → 8100 (TPID) → Priority/CFI → VID (12 bits) → Ethertype/Length → Payload → FCS`.

**Linux**

**L1** — **Hard link**: Points to the same inode; multiple names share data blocks. Cannot cross filesystems and is removed only when the link count drops to zero.  
**Symbolic link (symlink)**: Contains the path to another file; can link across filesystems, can point to non‑existent targets, and is a separate inode.

**L2** — Use `find` with size filter:  
```bash
find /var/log -type f -size +100M
```
This lists all regular files larger than 100 MiB.

**L3** — **State D (uninterruptible sleep)** means the process is waiting for I/O (e.g., disk, NFS) and cannot be interrupted. `kill -9` (SIGKILL) cannot terminate a D‑state process until the I/O completes or the kernel decides it’s hung (e.g., via `SIGKILL` after a timeout on some kernels). In practice, the process will remain D until the I/O finishes.

**L4** — **cgroups v1**: Hierarchical control groups with separate subsystems (cpu, memory, blkio, etc.), each mounted under its own hierarchy.  
**cgroups v2**: Unified, single hierarchy where all controllers are merged into one mount namespace, simplifying resource management and eliminating corner‑case bugs (e.g., “cgroup freezer” interactions).  
**systemd** prefers **cgroups v2** because it provides a cleaner, more consistent model and aligns with modern kernel features (e.g., `io.lat`, `memory.high`). Systemd automatically mounts the v2 tree when the kernel supports it.

**L5** — **nftables** is the successor to iptables, offering a more expressive language, faster matching (using expression trees), and a unified framework for IPv4/IPv6, ARP, and bridging.  
The kernel can load both **iptables** (legacy) and **nftables** modules simultaneously; they operate on separate “tables” (`filter`, `nat`, etc.). When a rule is added via iptables, the kernel translates it into nftables expressions behind the scenes (if nftables is the active framework). Administrators typically choose one userspace tool; mixing them is discouraged.

**L6** — The discrepancy usually indicates **deleted files that are still open** by a running process. `du` only sees files referenced by the filesystem namespace; if a process holds a descriptor to a file that has been unlinked, the space remains allocated until the process closes it. Running `lsof | grep deleted` can identify such files.

**L7** — **Linux boot sequence (UEFI)**:  
1. **UEFI firmware** initializes hardware, loads the EFI System Partition (ESP) and runs the EFI executable of the bootloader (e.g., `grubx64.efi`).  
2. **Bootloader** (GRUB) reads its configuration, loads the Linux kernel (`vmlinuz-…`) and an **initramfs** (or initrd) into memory.  
3. **Kernel** decompresses, runs early init (sets up memory, detects devices), and mounts the initial RAM disk as the root filesystem.  
4. **Initramfs** may perform low‑level tasks (e.g., udev, module loading, LVM activation, network config) and eventually switches root to the real root filesystem using `pivot_root`.  
5. **systemd** (PID 1) is started; it reads unit files, mounts filesystems, starts services, and reaches the default target (e.g., `graphical.target` or `multi-user.target`).  

**L8** — **Available** memory shown by `free -h` includes memory that can be reclaimed (buffers + cache). Even with 15 GB of buff/cache, the kernel may consider the system low on “free” memory if the **min_free_kbytes** or **watermark** thresholds are crossed, especially under memory pressure. The OOM killer triggers when the system cannot satisfy a memory request after reclaiming. Tunables affecting this behavior:  
- `/proc/sys/vm/min_free_kbytes` – minimum free memory to keep.  
- `/proc/sys/vm/overcommit_memory` and `overcommit_ratio` – control memory overcommit policy.  
- `/proc/sys/vm/swappiness` – bias toward swapping vs. reclaiming cache.  
- `/proc/sys/vm/dirty_background_ratio` / `dirty_ratio` – affect how aggressively dirty pages are written out, influencing cache size.

**L9** — `ip netns` creates isolated network namespaces, each with its own network stack (interfaces, routing table, iptables rules). Container runtimes (e.g., Docker, CRI‑O) use `ip netns` to:  
- Create a private namespace for each container.  
- Move a veth pair: one end stays in the host namespace, the other is attached to the container’s namespace, providing isolated networking.  
- Apply per‑container routing, iptables, and DNS settings without affecting the host.

**L10** — **SIGTERM (15)**: Termination signal; can be caught, allowing graceful shutdown (close files, release resources).  
**SIGKILL (9)**: Non‑catchable, non‑ignorable; forces immediate process termination.  
**SIGQUIT (3)**: Like SIGTERM but also generates a core dump; can be caught for debugging.  
Only **SIGTERM** and **SIGQUIT** can be caught or ignored by the process; **SIGKILL** cannot.

**L11** — **stdout (file descriptor 1)**: Standard output, typically console text.  
**stderr (file descriptor 2)**: Standard error, used for diagnostic messages.  
**stdin (file descriptor 0)**: Standard input, source of data for programs.  
To redirect **stderr** to a file while keeping **stdout** on the terminal:  
```bash
command 2>error.log
```
or, using file descriptor duplication:  
```bash
command 2>&1 1>out.log   # both to out.log (example)
```
For the asked case: `command 2>stderr.txt` keeps stdout visible.

**L12** — `chmod 755` sets permissions:  
- **7** (owner) = rwx (read + write + execute).  
- **5** (group) = rx (read + execute).  
- **5** (others) = rx (read + execute).  
Thus the file is executable by everyone, writable only by the owner, and readable by all.

**L13** — **root** is the superuser with UID 0, possessing unrestricted privileges by default. A user with **sudo** can execute specific commands (or all) as root after authenticating, limited by the `/etc/sudoers` policy. Sudo provides auditability and the ability to delegate only needed privileges.

**L14** — A **package manager** automates installation, upgrade, and removal of software.  
- **Debian/Ubuntu**: `apt` (or `apt-get`, `aptitude`).  
- **RHEL/Fedora**: `dnf` (replacing older `yum`).  

**L15** — `/etc/fstab` defines how storage devices are mounted at boot. Each line specifies device, mount point, filesystem type, options, dump frequency, and fsck order. A misconfigured entry (wrong device name, bad options, non‑existent mount point) can prevent the system from booting or cause mount failures, potentially dropping to an emergency shell.

**L16** — **LVM (Logical Volume Manager)** abstracts physical storage into logical units:  
- **Physical Volume (PV)**: Whole disk or partition initialized for LVM.  
- **Volume Group (VG)**: Collection of one or more PVs, providing a pool of space.  
- **Logical Volume (LV)**: Allocated portion of a VG, formatted with a filesystem.  
To extend an LV on‑the‑fly:  
```bash
# Assuming LV is /dev/vg0/lv_data and VG has free space
lvextend -L +10G /dev/vg0/lv_data   # add 10 GB
# Resize filesystem (e.g., ext4)
resize2fs /dev/vg0/lv_data
```
No downtime is required for most filesystems.

**L17** — The **I/O scheduler** decides the order of block I/O requests to optimize latency or throughput.  
- **mq‑deadline**: Adds a time slice (deadline) to each request; good for mixed workloads, reduces starvation.  
- **BFQ (Budget Fair Queueing)**: Allocates I/O budget per process, excellent for desktop responsiveness and interactive tasks.  
- **none**: No queuing; passes requests directly to the device (useful for devices that perform their own scheduling, e.g., SSDs with internal controllers).  
Choose **mq‑deadline** for general servers, **BFQ** for latency‑sensitive desktops, and **none** for SSDs or when the device driver handles scheduling. Runtime change:  
```bash
echo deadline > /sys/block/sda/queue/scheduler   # example for sda
```

**L18** — **Load average** on Linux is the exponentially damped moving average of the number of processes (or threads) that are:  
1. In **runnable** state (ready to execute), or  
2. In **uninterruptible** I/O sleep (D state).  
High load with low CPU usage often indicates **I/O wait**: processes are blocked on disk/network, inflating the runnable count. Diagnose:  
- `top`/`htop` → look at `%Cpu(s)` and `%wa` (I/O wait).  
- `iostat -xz 1` → disk utilization, await times.  
- `vmstat 1` → bi/bo (blocks in/out) and wa.  
- `sar -d` or `pidstat -u 1` for per‑process CPU.  
- Network: `ifstat`, `nload`, or `ss -s`.  
If `wa` is high, the bottleneck is disk; if CPU %us/%sy is high, CPU is the limit; if network queues are saturated, check `netstat -s` or `tcptrace`.

**L19** — **SELinux** enforces **Mandatory Access Control (MAC)** using security contexts (user, role, type, level) attached to subjects (processes) and objects (files, sockets).  
- **Enforcing**: Policy rules are actively enforced; violations are denied and logged.  
- **Permissive**: Violations are allowed but logged, useful for troubleshooting.  
- **Disabled**: SELinux is turned off; the kernel does not evaluate contexts.  
To troubleshoot a daemon failing to bind a non‑standard port:  
1. Check messages with `dmesg` or `journalctl -u <service>`.  
2. Use `ausearch -m avc -ts recent` to find SELinux denials.  
3. Examine the context: `ps -eZ | grep <daemon>` and `ls -Z /path/to/socket`.  
4. If a denial is found (e.g., `type=AVC msg=audit(...): avc: denied { name_bind }`), either adjust the policy with `semanage port -a -t <type> -p tcp <port>` or set the appropriate type label on the socket/file.

**L20** — **Page faults** occur when a process accesses a virtual page not present in physical RAM. The kernel handles two main types:  
- **Minor (soft) page fault**: Page is present in memory but not mapped; the kernel simply updates page tables. No disk I/O.  
- **Major (hard) page fault**: Page is not in memory; the kernel reads it from the backing store (swap or filesystem), which involves disk I/O and is costly.  
**Transparent Huge Pages (THP)** attempt to use larger (2 MiB) pages automatically to reduce TLB misses and page‑table overhead. However, THP can increase memory fragmentation and cause latency spikes during compaction. Disable THP for latency‑sensitive workloads (e.g., databases, real‑time) via:  
```bash
echo never > /sys/kernel/mm/transparent_hugepage/enabled
echo never > /sys/kernel/mm/transparent_hugepage/defrag
``` 
or by booting with `transparent_hugepage=never`.
