**DN1**  
- **Class**: Reference type, allocated on the heap, supports inheritance, can have a parameterless constructor, and can be `null`.  
- **Struct**: Value type, allocated on the stack (or inline in a containing object), cannot inherit from other reference types (except `System.ValueType`), and is never `null` (it has a default value).  
- **When to use a struct**: For small, immutable data structures where the overhead of heap allocation and garbage collection is undesirable (e.g., `Point`, `DateTime`, numeric vectors). Avoid structs for large or mutable data because copying can be expensive and can lead to subtle bugs.

**DN2**  
- **IEnumerable<T>**: Represents a forward‑only, in‑memory collection. LINQ methods (e.g., `Where`, `Select`) are executed **client‑side** after the enumerator is obtained. Ideal for in‑process collections.  
- **IQueryable<T>**: Represents a query that can be translated into an expression tree and executed by a remote data source (e.g., a database). LINQ methods are **translated** into SQL (or other query language) and executed on the server.  
- **Why it matters**: Using `IQueryable<T>` enables deferred execution and server‑side filtering, projection, and paging, reducing data transferred over the network. Using `IEnumerable<T>` on a database context forces loading all rows into memory first.

**DN3**  
- **async/await** lets a method asynchronously wait for a `Task` (or `ValueTask`) without blocking a thread. The compiler rewrites the method into a state machine.  
- **Task**: Represents an asynchronous operation that may be long‑running; allocated on the heap.  
- **ValueTask**: A struct wrapper that can avoid heap allocation when the operation completes synchronously.  
- **When to use `ValueTask`**: When the async method often completes synchronously (e.g., cached results, simple I/O) to reduce GC pressure. Use `Task` for truly asynchronous, potentially long‑running work.

**DN4**  
- **Dependency Injection (DI)** in .NET registers services with a container and resolves them at runtime, promoting loose coupling and testability.  
- **Service lifetimes**:  
  - **Transient** – a new instance per resolution (stateless services).  
  - **Scoped** – a single instance per request (or DI scope) – useful for per‑request data like `DbContext`.  
  - **Singleton** – a single instance for the app lifetime.  
- **Common bug**: Injecting a **Scoped** service into a **Singleton** causes the scoped instance to be stored beyond its intended lifetime, leading to shared state across requests and potential corruption (e.g., stale `DbContext` state). The fix is to inject the appropriate lifetime or use `IServiceScopeFactory` to create a new scope when needed.

**DN5**  
- **string**: Immutable reference type, stored on the heap, involves indirection and potential GC overhead for large processing.  
- **ReadOnlySpan<char>**: A ref‑like value type that points to a contiguous memory region (stack‑allocated or part of an existing object) without copying. It enables zero‑copy string slicing and fast, low‑overhead processing.  
- **When to use `Span<T>`/`ReadOnlySpan<char>`**: High‑performance scenarios (parsing, text manipulation, networking) where you can guarantee the data lives for the span’s lifetime (e.g., inside a method, using `stackalloc` or `MemoryMarshal`). Avoid using spans with data that may be moved or collected (e.g., heap‑allocated strings) without pinning.

**DN6**  
- **Garbage Collector (GC)**: Automatically reclaims memory by identifying unreachable objects.  
- **Generations**:  
  - **Gen 0** – new objects; collected frequently.  
  - **Gen 1** – survivors of Gen 0; collected less often.  
  - **Gen 2** – long‑living objects; collected rarely.  
- **Large Object Heap (LOH)**: Separate heap for objects > 85 KB; allocations are slower and collections are less frequent.  
- **IDisposable**: Provides deterministic cleanup of unmanaged resources (file handles, sockets, etc.) that the GC cannot release. Even with a GC, you need `IDisposable` to free native resources promptly and avoid leaks.

**DN7**  
- **ConfigureAwait(false)**: Configures the awaiter to **not capture the current `SynchronizationContext`** (or `TaskScheduler`). The continuation runs on any thread pool thread.  
- **Default behavior** (`ConfigureAwait(true)` or omitted): Captures the context; on UI or ASP.NET request threads, the continuation **marshals back** to that context, which can cause deadlocks or unnecessary context switches.  
- **When to use**: In library code or non‑UI async methods where you don’t need to resume on the original context—reduces overhead and avoids deadlocks.  
- **When NOT to use**: In UI code (WinForms, WPF, Blazor) or ASP.NET request processing where you must update UI controls or access thread‑affinitive resources; you need the original context.

**DN8**  
- **Primary Constructors (C# 12+)**: Allow declaring constructor parameters directly in the class header, reducing boilerplate.  
- **Collection Expressions**: Concise syntax for building collections (`[1, 2, 3]`, `new List<int> { 1, 2, 3 }` with expression bodies).  
- **FrozenDictionary**: Immutable dictionary with O(1) lookups, created via `FrozenDictionary<TKey, TValue>.Create` or the new collection expression syntax.  
- **Minimal example with DI**:
  ```csharp
  record DataService(IOptions<Settings> Options); // primary constructor

  // In Program.cs
  builder.Services.AddScoped<DataService>(sp => new DataService(sp.GetRequiredService<IOptions<Settings>>()));
  ```
  The `record` uses a primary constructor, and DI injects the required services.

**DN9**  
- **Likely cause**: `DbContext` is registered as **Scoped** but is being **captured** by a **Singleton** (e.g., a static cache, event handler, or background service) and used after the request scope ends, leading to `ObjectDisposedException`.  
- **Fix**: Ensure `DbContext` is only used within its scoped lifetime. Options:  
  1. Refactor the singleton to resolve `IServiceScopeFactory` and create a new scope each time it needs the context.  
  2. Use an **ambient** `DbContext` pattern with proper disposal checks.  
  3. Register the context as **Transient** if truly stateless (rare).  
- **EF Core & DI**: By default, `AddDbContext<T>` registers `DbContext` as **Scoped**, matching the typical web request lifecycle. The DI container creates a new instance per request and disposes it at the end.

**DN10**  
- **record vs class**:  
  - **record**: Immutable by default, provides value‑based equality (`==`), `with` expressions for cloning, and synthesized `Deconstruct`. Suitable for data‑centric, immutable DTOs.  
  - **class**: Reference type, mutable by default, no value equality unless overridden. Use for behavior‑rich types or when mutability is needed.  
- **record struct**: A **value‑type record** (introduced in C# 10). It combines struct semantics (stack allocation, no heap GC) with record features (positional parameters, value equality). Use when you need a small, immutable value type (e.g., `Point`).  
- **Choosing**: Use `record` for immutable POCOs, `class` for typical OOP with identity, and `record struct` for lightweight value objects.

**DN11**  
- **ref**: Passes a variable’s storage location; the called method can read/write it. The argument must be initialized before the call.  
- **out**: Similar to `ref` but guarantees the variable will be assigned before the method returns. Useful for methods that produce an output (e.g., `int.TryParse`).  
- **in** (C# 7.2+): Passes a read‑only reference; the called method cannot modify the argument. Provides safety and can avoid copies for large structs.  
- **When to use**:  
  - `ref`/`out` for methods that need to modify the caller’s variable.  
  - `in` for large readonly structs where you want to avoid copying while ensuring no mutation.

**DN12**  
- **Nullable reference types** (`?`): Introduced in C# 8 to make nullability explicit. `string?` means the variable may be `null`; `string` means it cannot be `null` (unless `#nullable disable`). The compiler warns about potential dereferences of possibly‑null references.  
- **Nullable value types** (`int?`): Wrapper around a value type allowing `null`. They are instances of `Nullable<T>` and use the `HasValue`/`Value` pattern.  
- **Difference**: Reference types have built‑in nullability; value types need the `?` syntax to become nullable. The language treats them differently at the type system level.

**DN13**  
- **LINQ (Language Integrated Query)** provides a uniform way to query collections.  
- **Method syntax** (`list.Where(x => x > 0).Select(x => x * 2)`) is more flexible, supports extension methods, and is often clearer for complex pipelines.  
- **Query syntax** (`from x in list where x > 0 select x * 2`) resembles SQL and is syntactic sugar for method calls.  
- **Deferred execution**: LINQ queries return an `IEnumerable<T>` (or `IQueryable<T>`) that isn’t evaluated until enumerated (e.g., `ToList()`, `foreach`). This enables composition and reduces unnecessary work.

**DN14**  
- **Generic constraints** restrict the types that can be used for a type parameter.  
  - `where T : class` – `T` must be a reference type.  
  - `where T : struct` – `T` must be a value type (excluding nullable structs).  
  - `where T : new()` – `T` must have a parameterless constructor.  
  - `where T : IComparable<T>` – `T` must implement the interface.  
- **Combining constraints**: You can list multiple constraints separated by commas (`where T : struct, IComparable<T>`). This is useful when a method needs both a value type and a specific interface.

**DN15**  
- **abstract class**: Can contain implementation, fields, and constructors. Supports multiple inheritance of interfaces only. Use when you want shared base code and/or protected members.  
- **interface**: Pure contract; no implementation (except default methods). A class can implement many interfaces.  
- **Default interface methods (C# 8+)**: Allow adding method bodies to interfaces, enabling library evolution without breaking existing implementations. This narrows the distinction: interfaces can now provide default behavior, but they still cannot hold state.

**DN16**  
- **Middleware pipeline** in ASP.NET Core is a series of components that process `HttpContext` sequentially.  
- **`app.Use()`**: Adds a middleware that **invokes the next middleware** (`next`) and can short‑circuit the pipeline.  
- **`app.Map()`**: Branches the pipeline based on a matching path; only the matched branch executes its chained middleware.  
- **`app.Run()`**: Terminal middleware; calls `next` only if explicitly invoked. Typically used for request handling (e.g., MVC, static files).  
- **Ordering matters**: Early middleware can modify the request (e.g., authentication, logging) before later middleware sees it. Exception‑handling middleware (e.g., `app.UseExceptionHandler`) must be placed **before** the middleware that might throw.  
- **Exception handling**: Middleware can catch exceptions, set `context.Response`, and call `context.Response.Body.WriteAsync` or forward to an error‑handling endpoint.

**DN17**  
- **Channel<T>** (System.Threading.Channels) provides a high‑performance, asynchronous producer‑consumer queue with built‑in backpressure and completion semantics.  
- **Differences from `BlockingCollection<T>`**:  
  - `Channel` is **asynchronous** (`WaitToReadAsync`, `WaitToWriteAsync`) and integrates with `async/await`.  
  - It supports **bounded capacity** with automatic completion when `Complete()` is called.  
  - `BlockingCollection` is synchronous, uses `BlockingCollection<T>.Take/ Add`, and lacks the same async ergonomics.  
- **Bounded channel example**:
  ```csharp
  var ch = Channel.CreateBounded<int>(capacity: 10);
  // Producer
  await foreach (var item in ProduceItems())
      await ch.Writer.WaitToWriteAsync();
      if (ch.Writer.TryWrite(item)) continue;
      // backpressure: wait or drop
  ch.Writer.Complete();

  // Consumer
  await foreach (var item in ch.Reader.ReadAllAsync())
      Process(item);
  ```
  The consumer blocks when the channel is empty, and the producer blocks when full, providing natural backpressure.

**DN18**  
- **Source Generators** (introduced in C# 9) are compiler plugins that analyze source code and emit additional C# files at compile time.  
- **Differences**:  
  - **Reflection**: Runtime introspection; incurs runtime overhead and cannot generate code.  
  - **IL weaving**: Modifies compiled IL after compilation; more invasive and less type‑safe than source generators.  
- **Incremental Generator**: A specialized source generator that receives **incremental execution contexts**, allowing it to efficiently re‑generate only affected outputs when inputs change. Preferred because it minimizes recompilation work and integrates with the Roslyn incremental pipeline.  

**DN19**  
- **TPL Dataflow** (`System.Threading.Tasks.Dataflow`) offers a higher‑level abstraction for building data‑processing pipelines.  
- **Key blocks**:  
  - **ActionBlock<T>**: Executes an action for each received message; can have concurrency limits.  
  - **TransformBlock<TInput, TOutput>**: Transforms input to output, propagating the result downstream.  
  - **BufferBlock<T>**: Simple in‑memory buffer that stores messages until a consumer pulls them.  
- **Comparison with Channels**:  
  - **Channels** are lower‑level, focus on async producer/consumer with explicit `Reader/Writer`.  
  - **Dataflow** provides built‑in **linking**, **propagation rules**, **cancellation**, and **completion** semantics, making complex fan‑in/out patterns easier (e.g., `JoinBlock`, `BroadcastBlock`).  
  - Use **Channels** for simple, high‑performance queues; use **Dataflow** for richer orchestration (parallelism, backpressure, dynamic linking).

**DN20**  
- **Minimal APIs** (introduced in .NET 6) allow defining HTTP endpoints with simple lambda expressions without controllers or attributes.  
- **Differences from controller‑based APIs**:  
  - **Simplicity**: Fewer classes/files, less boilerplate.  
  - **Performance**: Slightly lower overhead as there’s no controller activation.  
  - **Testability**: Endpoints are just delegates; you can invoke them directly for unit tests, but integration tests need the host.  
  - **Middleware**: Applied at the app level; endpoint‑specific middleware must be added via `Map*` or filters.  
  - **OpenAPI**: Requires explicit registration (`app.UseOpenApi()`, `app.UseSwaggerUI()`) and may need additional attributes for full schema generation.  
- **Route groups & endpoint filters**:  
  - **Route groups** (`app.MapGroup("/api/v1")`) prefix routes and can share common middleware/filters.  
  - **Endpoint filters** (`[HttpPost]` style filters) run before/after the delegate, useful for cross‑cutting concerns (logging, authorization).

**P1**  
- **List vs Tuple**:  
  - **List** (`[]` or `List<T>`): Mutable sequence, dynamic size, stored on the heap.  
  - **Tuple** (`(a, b)` or `Tuple<T1, T2>`): Immutable fixed‑size collection, often used for returning multiple values.  
- **Set vs Frozenset**:  
  - **Set** (`{}` or `set()`): Mutable unordered collection of unique items.  
  - **Frozenset**: Immutable version of a set; hashable, can be used as dictionary keys or elements of other sets.

**P2**  
- **GIL (Global Interpreter Lock)**: A mutex that protects access to Python objects, ensuring only one thread executes Python bytecode at a time in CPython.  
- **Affected workloads**: CPU‑bound pure Python code suffers because threads cannot run truly in parallel. I/O‑bound or extensions that release the GIL (e.g., NumPy, I/O operations) benefit from threading.  
- **Workarounds**:  
  - Use **multiprocessing** to spawn separate processes (each with its own GIL).  
  - Use native extensions or libraries that release the GIL during long computations.  
  - Use alternative implementations like **Jython** or **IronPython** that lack a GIL.

**P3**  
- **copy** (`import copy; copy.copy(obj)`): Shallow copy – creates a new container but references the same nested objects.  
- **deepcopy** (`copy.deepcopy(obj)`): Recursively copies all nested objects, producing a fully independent replica.  
- **Example of shallow copy issue**:
  ```python
  a = [[1, 2], [3, 4]]
  b = copy.copy(a)
  b[0][0] = 99          # mutates nested list
  print(a)              # [[99, 2], [3, 4]]  <-- a is affected
  ```
  `deepcopy` would create a new inner lists, so `a` remains unchanged.

**P4**  
- **Decorator** syntax:
  ```python
  import time
  from functools import wraps

  def log_time(func):
      @wraps(func)
      def wrapper(*args, **kwargs):
          start = time.time()
          result = func(*args, **kwargs)
          elapsed = time.time() - start
          print(f"{func.__name__} took {elapsed:.4f}s")
          return result
      return wrapper

  @log_time
  def compute():
      time.sleep(0.5)
  compute()
  ```
  The `@log_time` line applies the decorator, wrapping `compute` to log its execution time.

**P5**  
- **Generators** use `yield` to produce values one at a time, maintaining state between yields. They return an iterator and compute values lazily, saving memory.  
- **Difference from returning a list**: A list materializes all elements upfront; a generator computes on demand.  
- **`yield from`**: Delegates part of the generator’s yielding to another iterable or sub‑generator, flattening nested iteration. Example:
  ```python
  def concat(a, b):
      yield from a
      yield from b
  ```

**P6**  
- **asyncio event loop**: Central scheduler that runs coroutines, I/O callbacks, and tasks.  
- **`asyncio.run(main())`**: Convenience function to run the top‑level coroutine, creating and closing the loop.  
- **`asyncio.gather(*tasks)`**: Takes multiple awaitables and returns when all complete, collecting results in order.  
- **`asyncio.create_task(coro)`**: Schedules a coroutine as a `Task` on the running loop, returning the `Task` object.  
- **Why not `time.sleep()`**: `time.sleep()` blocks the thread, preventing the event loop from running other tasks. Use `asyncio.sleep()` which is a non‑blocking `await`able.

**P7**  
- **MRO (Method Resolution Order)** determines the order in which base classes are searched for methods. Python 3 uses the **C3 linearization** algorithm.  
- **Diamond inheritance example**:
  ```python
  class A: def who(self): return "A"
  class B(A): pass
  class C(A): def who(self): return "C"
  class D(B, C): pass
  print(D().who())   # Outputs: C
  ```
  The C3 MRO for `D` is `[D, B, C, A, object]`. `C` appears before `A`, so `D.who` resolves to `C.who`.

**P8**  
- **Metaclass**: The class of a class; defines how a class is constructed (`__new__`, `__init__`). Used for class‑level validation, registration, or modification.  
- **`__init_subclass__`**: A class method called when a subclass is created; simpler for many use‑cases (e.g., auto‑registering subclasses).  
- **Practical metaclass use**: Enforcing interface contracts or automatically adding methods.  
  ```python
  class InterfaceMeta(type):
      def __new__(cls, name, bases, attrs):
          if not all(hasattr(attrs, m) for m in ('required_method',)):
              raise TypeError(f"{name} must implement required_method")
          return super().__new__(cls, name, bases, attrs)
  class MustImplement(metaclass=InterfaceMeta):
      pass
  ```
- **`__init_subclass__` use**: Registry pattern.
  ```python
  class PluginBase:
      registry = []
      def __init_subclass__(cls, **kwargs):
          super().__init_subclass__(**kwargs)
          cls.registry.append(cls)
  class PluginA(PluginBase): pass
  print(PluginBase.registry)  # [<class '__main__.PluginA'>]
  ```

**P9**  
- **multiprocessing**: Spawns separate OS processes, each with its own Python interpreter and memory space; bypasses the GIL. Ideal for CPU‑bound tasks. Serialization (pickling) is required to send objects between processes.  
- **threading**: Uses OS threads within the same process; subject to the GIL, so best for I/O‑bound work. No pickling needed for shared objects (but requires synchronization primitives).  
- **concurrent.futures**: High‑level API providing `ThreadPoolExecutor` (wraps threading) and `ProcessPoolExecutor` (wraps multiprocessing). Simplifies submission of callables and retrieval of `Future` results. Choose based on workload (I/O vs CPU) and ease of use.

**P10**  
- **`__slots__`**: Declares a fixed set of instance attributes, preventing the creation of a per‑instance `__dict__`.  
- **When to use**: In classes with many instances where memory footprint and attribute access speed matter (e.g., data models, performance‑critical code).  
- **What it prevents**: Dynamic addition of new attributes (raises `AttributeError`).  
- **Memory impact**: Reduces memory per instance by avoiding the dict overhead, often saving tens of bytes per object.

**P11**  
- **Virtual environment**: Isolated Python installation with its own site packages, allowing per‑project dependencies without affecting system Python.  
- **Differences**:  
  - **`venv`**: Built‑in (Python 3.3+), lightweight, creates environments with a copy of the `python` executable.  
  - **`virtualenv`**: Third‑party, older, offers more configuration options (e.g., system‑site‑packages flag).  
  - **`conda`**: Not limited to Python; manages packages and environments for multiple languages, including binary dependencies.  
- **Why use**: Avoid version conflicts, ensure reproducibility, and keep global site‑packages clean.

**P12**  
- **Comprehensions** (`[expr for item in iterable if cond]`, `{key: value for ...}`, `{expr for ...}`) are concise ways to build lists, dicts, or sets.  
- **Relation to `map`/`filter`**: `map(func, iter)` applies a function (similar to `[func(x) for x in iter]`). `filter(pred, iter)` selects items (`[x for x in iter if pred(x)]`). Comprehensions are generally more readable and allow inline conditionals.  
- **When to prefer**: Use comprehensions for readability and when you need both mapping and filtering in one expression. Use `map`/`filter` for functional‑style pipelines or when working with iterators that should remain lazy (though Python’s comprehensions are also lazy only when used as generator expressions `(...)`).

**P13**  
- **`==`**: Value equality – compares the contents or values of objects.  
- **`is`**: Identity comparison – checks whether two references point to the **same object** in memory.  
- **Object interning**: Python caches and reuses certain immutable objects (e.g., small integers, some strings) to save memory. This makes `a is b` true for those cached values (e.g., `-5 is -5`, `'hello' is 'hello'` in many implementations).  
- **Use `is`** for singleton checks (`None`, `True`, `False`, custom singletons). Use `==` for semantic equality.

**P14**  
- **`*args`**: Captures additional positional arguments as a tuple.  
- **`**kwargs`**: Captures additional keyword arguments as a dictionary.  
- **Positional‑only (`/`)** and **keyword‑only (`*`)** markers (PEP 570) restrict how arguments can be passed:  
  - `def f(a, b, /, c, d, *, e, f):` – `a` and `b` must be positional, `c` and `d` can be positional **or** keyword, `e` and `f` must be keyword.  
- **Usage**: Enforce clear API contracts and prevent accidental misuse.

**P15**  
- **Context managers** provide `__enter__` and `__exit__` methods to allocate and release resources automatically (`with` statement).  
- **Using `__enter__/__exit__`**:
  ```python
  class Timer:
      def __enter__(self):
          self.start = time.time()
          return self
      def __exit__(self, *exc):
          self.end = time.time()
          print(f"Elapsed: {self.end - self.start}")
  ```
- **Using `@contextmanager`** from `contextlib`:
  ```python
  from contextlib import contextmanager
  @contextmanager
  def timer():
      start = time.time()
      try:
          yield
      finally:
          print(f"Elapsed: {time.time() - start}")
  ```
- **Beyond file handling**: database connections, locks, temporary directories, HTTP sessions, etc.

**P16**  
- **Type hinting** adds static type information.  
- **Key constructs**:  
  - `Union[A, B]` (or `A | B` in Python 3.10+): One of several types.  
  - `Optional[T]` (`T | None`): `T` or `None`.  
  - `Literal['a', 'b']`: Restricts a value to exact literals.  
  - `TypeVar('T')`: Generic type variable.  
  - `Protocol`: Defines structural subtyping (duck typing).  
- **Static analysis tools** (`mypy`, `pyright`) read these hints to check for type errors without running the code.

**P17**  
- **Data model (dunder methods)** control object behavior.  
  - `__repr__`: Official string representation, ideally unambiguous (`<ClassName(attr=...)>`). Used by `repr()`.  
  - `__str__`: Informal, human‑readable string (`str()`).  
  - `__eq__`: Defines equality (`==`). If defined, Python expects a corresponding `__hash__` if the object is hashable.  
  - `__hash__`: Enables use in sets/dicts. If `__eq__` is custom and the object is mutable, **do not** implement `__hash__` (or set it to `None`).  
  - `__getattr__`: Called for attribute lookup that fails normally; can provide dynamic attributes.  
  - `__getattribute__`: Called for every attribute access; must avoid infinite recursion.  
- **If `__eq__` is defined but not `__hash__`**: The object becomes **unhashable** (its `__hash__` is set to `None`), so it cannot be used as a dict key or set member.

**P18**  
- **Descriptors** implement the descriptor protocol (`__get__`, `__set__`, `__delete__`). When an attribute is accessed on a class, Python checks for these methods.  
- **How built‑ins use descriptors**:  
  - `property`: Combines `__get__`, `__set__`, `__delete__` to create managed attributes.  
  - `classmethod`: Descriptor that wraps a function to receive the class as the first argument.  
  - `staticmethod`: Descriptor that removes the implicit first argument, returning the underlying function.  
- **Use case**: Custom validation, lazy loading, or logging on attribute access.

**P19**  
- **Python import system**:  
  - **Finders** (`sys.meta_path`) locate modules (file system, zip, namespace packages).  
  - **Loaders** (`sys.path_importer_cache`) load the module code (compile, execute).  
  - **`sys.path`**: List of directories searched for modules; can be augmented with `PYTHONPATH`.  
  - **`__init__.py`**: Marks a directory as a package; can contain package‑level code.  
  - **Namespace packages** (PEP 420): Allow a package to be split across multiple directories without `__init__.py`.  
  - **Relative vs absolute imports**:  
    - Absolute (`import foo.bar`) starts search from the top‑level package.  
    - Relative (`from . import sibling`) is resolved relative to the current module’s package.  
- **Finder/Loader interaction**: Finders return a loader if they can handle the module; loaders then execute the code and return a module object.

**P20**  
- **dataclasses** (module `dataclass`) automatically generate `__init__`, `__repr__`, `__eq__`, and optionally `__hash__` from class fields.  
- **Comparison**:  
  - **attrs**: Older library with more features (validators, converters, freezing, class decorators).  
  - **Pydantic**: Focuses on data validation and parsing from JSON, env vars, etc., with runtime type checking and rich error messages.  
- **Key features**:  
  - `__post_init__`: Hook called after `__init__` to perform validation or derived field computation.  
  - **Field factories** (`field(default_factory=list)`) create mutable defaults safely.  
  - **Frozen dataclasses**: Instances become immutable; attempting to assign to fields raises `FrozenInstanceError`.  
  - **Inheritance**: Works with standard Python inheritance; fields are merged from base classes.  
- **When to choose Pydantic**: When you need **runtime validation**, parsing from external data (JSON, YAML, env), custom validators, or strict type enforcement beyond compile‑time hints. Use dataclasses for simple, internal data containers where validation is handled elsewhere.
