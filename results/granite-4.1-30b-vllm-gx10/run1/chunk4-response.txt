**Go (20 questions)**  

**G1** — *Easy*:  
- **Array**: Fixed-size, value type. The size is part of the type (`[5]int`).  
- **Slice**: Describes a segment of an underlying array (`[]int`). It holds a pointer, length, and capacity.  
- **Appending**: When you `append` to a slice and its length exceeds its capacity, Go allocates a new, larger backing array (typically doubling the capacity), copies the existing elements, and returns the new slice. The original slice may point to the old array if it’s used elsewhere.

**G2** — *Easy*:  
- `var x int` declares a variable `x` of type `int` with the zero value `0`. It can appear at package or function scope.  
- `x := 0` is short‑hand declaration **and** initialization; it infers the type from the RHS.  
- **When `:=` cannot be used**: inside a function scope where the variable already exists, at package level (only `var` is allowed), or in places that require an explicit type (e.g., when the expression isn’t a simple literal or when you need to declare without initializing).

**G3** — *Medium*:  
- **Goroutine**: A lightweight thread managed by the Go runtime. It’s a function/Go‑statement that runs concurrently with others.  
- **Difference from OS thread**: Goroutines have a small stack (few KB) that can grow/shrink; the runtime multiplexes many goroutines onto a smaller set of OS threads.  
- **Go scheduler (GMP model)**:  
  - **M** (Machine) = OS thread.  
  - **P** (Processor) = scheduler context holding a run queue of goroutines and runtime resources.  
  - **G** (Goroutine) = the actual concurrent unit.  
  The scheduler assigns a G to a P, and a P to an M, balancing load and enabling parallel execution.

**G4** — *Medium*:  
- **Channels** are typed conduits for sending/receiving values between goroutines.  
- **Unbuffered**: The sender blocks until a receiver is ready; the receiver blocks until a sender arrives.  
- **Buffered**: Created with `make(chan T, capacity)`. Sends block only when the buffer is full; receives block only when empty.  
- **Full buffered channel**: `ch <- value` blocks until a receiver takes an element, freeing space.

**G5** — *Medium*:  
- **context package** propagates deadlines, cancellation signals, and request‑scoped values.  
- **Minimal example**:
  ```go
  ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
  defer cancel()
  req, _ := http.NewRequest("GET", "https://api.example.com", nil)
  req = req.WithContext(ctx)
  resp, err := http.DefaultClient.Do(req)
  // err will be context.Canceled or context.DeadlineExceeded if timeout fires
  ```
- The context is attached to the HTTP request, causing the client to abort if the deadline passes.

**G6** — *Medium*:  
- **Interface satisfaction**: A type implements an interface by providing all its methods. No `implements` keyword; satisfaction is *implicit*.  
- **Difference from Java/C#**: Those languages require explicit declaration; Go’s duck typing is structural.  
- **Empty interface `interface{}`**: Can hold any value (similar to `Object` or `any`).  
  - **Powerful**: Enables generic containers, type‑assertions, and polymorphism without casting.  
  - **Dangerous**: Hides type information; runtime `type‑assertion` failures can panic if the stored value doesn’t match the asserted type.

**G7** — *Hard*:  
- The snippet suffers from **data races** and **visibility** issues. The compiler/runtime may reorder reads/writes, so the main goroutine could see `ready = true` before `data = "hello"` is visible.  
- **Why unsafe**: No memory barrier or synchronization guarantees ordering across goroutines.  
- **Correct alternatives**:  
  1. **Channel**:  
     ```go
     ch := make(chan struct{})
     go func() {
         data = "hello"
         close(ch) // signals readiness
     }()
     <-ch // waits for signal
     fmt.Println(data)
     ```
  2. **sync.WaitGroup + atomic**:  
     ```go
     var wg sync.WaitGroup
     wg.Add(1)
     go func() {
         data = "hello"
         ready = true
         wg.Done()
     }()
     wg.Wait()
     fmt.Println(data)
     ```
  3. **atomic package** for `ready` with memory_order_release/consume semantics (more advanced).

**G8** — *Hard*:  
- **sync.Mutex**: Exclusive lock. Only one goroutine can hold it at a time.  
- **sync.RWMutex**: Reader‑writer lock. Multiple readers may hold it concurrently; writers get exclusive access. Use when reads dominate and are thread‑safe without writes.  
- **sync.Map vs map with mutex**:  
  - `sync.Map` is a *concurrent* map with built‑in optimizations (lock‑striping, cache friendliness). Good for workloads with many independent inserts/lookups and few mutations.  
  - Regular `map` + `sync.Mutex` is simpler and can be faster if the map is mostly read‑only or mutations are batched.  
- **Performance trade‑offs**: `sync.Map` avoids a single global lock but has overhead for versioning and cleanup; a plain map+mutex can be cheaper when contention is low or writes are frequent.

**G9** — *Hard*:  
- **Go modules** manage dependencies using a `go.mod` file (lists module path and required versions) and a `go.sum` file (contains cryptographic hashes of module contents for integrity).  
- **go mod tidy**: Reconciles `go.mod` with the actual imports in the code: adds missing dependencies, removes unused ones, and ensures `go.sum` is up‑to‑date.  
- **Minimum Version Selection (MVS)**: The algorithm that picks the *lowest* acceptable version for each dependency that satisfies all constraints, aiming to minimize version upgrades and thus reduce breakage. It builds a dependency graph, resolves indirect requirements, and selects minimal versions that meet all `require` directives.

**G10** — *Medium*:  
- **defer** schedules a function call to run **after** the surrounding function returns (LIFO order).  
- **Execution order**: Multiple `defer`s are pushed onto a stack; the last deferred call is executed first when the function exits.  
- **Common gotcha in loops**: Deferring inside a loop defers the *closure* at each iteration, so the most recent iteration runs first. If you need the loop variable’s value at defer time, capture it in a local variable or use an anonymous function.

**G11** — *Easy*:  
- **Pointer**: Holds the memory address of a value. Declared with `*T`.  
- **Zero value**: `nil` (no valid address).  
- **Pointer to struct literal**:  
  ```go
  p := &struct{ X int }{X: 42}
  ```

**G12** — *Easy*:  
- **init()**: Special function called automatically before `main()` for each package, in **dependency order** (packages imported first are init‑ed first).  
- A package may have **multiple** `init()` functions; they run in the order they appear in the source file.  
- They cannot be called directly and have no arguments/return values.

**G13** — *Easy*:  
- **new(T)**: Allocates zero‑value of type `T` on the heap and returns a pointer `*T`. Works for any type `T`.  
- **make(T)**: Creates *initialized* values for **built‑in reference types** (`chan`, `map`, `slice`). It returns an *initialized* instance, not a pointer (except `make([]*T, n)` which returns a slice of pointers).  
- **Types**: `new` works for structs, arrays, interfaces, etc.; `make` only for `chan`, `map`, `slice`.

**G14** — *Easy*:  
- **Error handling**: The `error` type (`interface{ Error() string }`). Functions return an `error` value; callers check it.  
- **Idiomatic pattern**:  
  ```go
  result, err := someFunc()
  if err != nil {
      return nil, err // or handle
  }
  ```  
- **errors.Is**: Tests if an error matches a target (including wrapped errors).  
- **errors.As**: Tries to assert an error to a specific type, useful for sentinel errors or custom error types.  
- Direct `==` works only for the exact same error instance or sentinel values; it doesn’t traverse wrapped errors.

**G15** — *Easy*:  
- **Composite types**:  
  - **map**: `map[K]V` – zero value `nil` (uninitialized; cannot be written to).  
  - **slice**: `[]T` – zero value `nil`.  
  - **channel**: `chan T` – zero value `nil`.  
  - **struct**: Collection of named fields – zero value with each field set to its zero value.  

**G16** — *Medium*:  
- **Race condition**: Concurrent access to shared mutable state without proper synchronization, leading to nondeterministic behavior.  
- **-race flag**: Instruments the binary with the race detector (based on the Happens‑Before model) that records memory accesses and flags conflicting accesses.  
- **Example**:
  ```go
  var cnt int
  for i := 0; i < 1000; i++ {
      go func() { cnt++ }()
  }
  ```
  *Fix*: Use `sync.Mutex` or a channel to serialize increments:
  ```go
  var mu sync.Mutex
  for i := 0; i < 1000; i++ {
      go func() {
          mu.Lock()
          cnt++
          mu.Unlock()
      }()
  }
  ```

**G17** — *Medium*:  
- **select**: Allows a goroutine to wait on multiple channel operations simultaneously.  
- **Difference from switch**: Cases are channel communications (`case <-ch:` or `case ch <- v:`) and execution is nondeterministic when multiple are ready; `switch` evaluates a constant expression.  
- **Multiple ready cases**: The runtime picks one *fairly* (not LIFO, not FIFO).  
- **Timeout**: Use a `time.After` channel:
  ```go
  select {
  case v := <-ch:
      // received value
  case <-time.After(10 * time.Second):
      // timeout
  }
  ```

**G18** — *Hard*:  
- **Escape analysis**: The compiler decides whether an object can be allocated on the stack or must be heap‑allocated. If a pointer to the object escapes the function’s scope (e.g., stored in a global, returned, or passed to another goroutine), it escapes to the heap.  
- **Decision factors**: Lifetime extension, aliasing, and whether the address is observable outside the function.  
- **Inspecting**: Compile with `-gcflags="-m"` (or `-m -m` for more detail) to see escape reasons.  
- **Performance impact**: Stack allocation is faster (no GC overhead) and reduces heap pressure; heap allocation incurs allocation and later GC cost.

**G19** — *Hard*:  
- **reflect package**: Provides runtime introspection.  
  - **reflect.Type**: Describes a type (e.g., `*int`, `[]string`). Immutable, safe to share.  
  - **reflect.Value**: Holds an actual value; supports `Kind()`, `Interface()`, `Elem()`, method invocation, etc.  
- **Performance costs**: Reflection bypasses static type checking, involves interface conversions, and may trigger dynamic method lookups—significantly slower than direct code.  
- **When justified**: Code generation tools, serialization libraries, dynamic proxies, or when the type cannot be known at compile time. Prefer code generation (`go generate`) for performance‑critical paths.

**G20** — *Hard*:  
- **go:embed**: Directive (added in Go 1.16) allows embedding arbitrary files directly into the binary.  
  - **Single file**: `//go:embed file.txt` then `var content = fs.MustBytes(embed.FS, "file.txt")`.  
  - **Directory**: `//go:embed dir/*` embeds the whole directory tree; accessed via `fs.FS` methods (`Open`, `ReadFile`).  
  - **File system**: `//go:embed *` with `embed.FS` gives a virtual `http.FileSystem`.  
- **Limitations**: Cannot embed files conditionally at runtime; size of binary grows; no built‑in compression (though you can embed compressed data and decompress at runtime).  
- **Interaction with `io/fs.FS`**: The embedded file system implements `fs.FS`, enabling use with standard library functions like `http.FileServer` or `os.ReadFile` via `fs.ReadFile`.

**Rust (20 questions)**  

**R1** — *Easy*:  
- **Ownership** enforces a set of rules to ensure memory safety without a GC.  
  1. **Each value has a single owner** (`&T` borrows, `&mut T` exclusive borrow).  
  2. **When the owner goes out of scope, the value is dropped** (resource freed).  
  3. **You can either move or borrow a value**, not both simultaneously.  

**R2** — *Easy*:  
- **String**: Heap‑allocated, growable, UTF‑8 encoded, owned (`String`).  
- **&str**: Borrowed string slice (`&str`) – a reference to a sequence of UTF‑8 bytes with a known length.  
- **Usage**: Use `&str` in function signatures when you only need to read a string slice (e.g., `fn takes_str(s: &str)`). Use `String` when ownership or mutability is required (e.g., `fn takes_owned(s: String)`).

**R3** — *Medium*:  
- **Borrowing** lets you temporarily lend access to data without transferring ownership.  
- **Borrow checker** enforces:  
  - **Shared borrows** (`&T`) can be multiple *but* never together with a mutable borrow.  
  - **Mutable borrows** (`&mut T`) are *exclusive* – only one at a time, and the borrow must be the only reference to the data.  
- These rules prevent data races and dangling pointers at compile time.

**R4** — *Medium*:  
- **Result<T, E>**: Enum for success (`Ok(T)`) or error (`Err(E)`). Propagates errors explicitly.  
- **Option<T>**: Enum for presence (`Some(T)`) or absence (`None`).  
- **`?` operator**: In a function returning `Result` or `Option`, `expr?` propagates `Ok`/`Some` value or returns `Err`/`None` early.  
- **Example** (read file):
  ```rust
  use std::fs::File;
  use std::io::{self, Read};

  fn read_file(path: &str) -> Result<String, io::Error> {
      let mut file = File::open(path)?; // propagate error
      let mut contents = String::new();
      file.read_to_string(&mut contents)?; // propagate error
      Ok(contents)
  }
  ```

**R5** — *Medium*:  
- **Box<T>**: Simple heap allocator; owns a value with unknown size at compile time (e.g., for recursive types).  
- **Rc<T>**: Reference‑counted shared ownership (thread‑unsafe). Use when you need multiple owners in a single thread.  
- **Arc<T>**: Atomically reference‑counted version of `Rc`; safe for concurrent use across threads.  
- **When to use**: `Box` for moving values to heap, `Rc` for cheap shared ownership in single‑threaded code, `Arc` for shared ownership across threads.

**R6** — *Medium*:  
- **Traits**: Define a set of methods a type must implement. Similar to Go interfaces but *declared* explicitly.  
- **Trait object** (`dyn Trait`): Erases the concrete type, allowing heterogeneous collections; stored as a pointer with vtable.  
- **Generic with trait bound** (`T: Trait`): Monomorphized at compile time; each concrete `T` gets its own code version, enabling static dispatch and zero‑cost abstraction.  
- **Difference**: Trait objects give runtime polymorphism (dynamic dispatch) at the cost of indirection; generics give compile‑time polymorphism (static dispatch) with no runtime overhead.

**R7** — *Hard*:  
- The function returns a reference to either `x` or `y`, but the compiler cannot guarantee which string lives longer. The returned reference could dangle if the chosen argument goes out of scope.  
- **Fix with lifetimes**:
  ```rust
  fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
      if x.len() > y.len() { x } else { y }
  }
  ```
  The `'a` bound states that the result lives at least as long as both inputs.

**R8** — *Hard*:  
- **Send**: Marker trait indicating a type is safe to transfer across thread boundaries (ownership moves).  
- **Sync**: Marker trait indicating a type is safe to share between threads (`&T` is thread‑safe).  
- **Rc<T>**: Not `Send` because its internal reference count is not atomic; sharing it across threads would cause data races.  
- **Arc<T>**: Implements `Send` + `Sync` because its reference count uses atomic operations, making it safe for concurrent access.

**R9** — *Hard*:  
- **async/await**: Syntactic sugar for building state machines (`Future`s). An `async fn` returns a `Future` that can be polled to completion.  
- **Future**: A `trait` with a single method `poll` that the executor calls to resume execution until ready or complete.  
- **Executor**: Runtime component (e.g., Tokio, async‑std) that manages scheduling of `Future`s, often using a thread pool.  
- **Difference from goroutines**: Goroutines are *preemptively* scheduled by the Go runtime on OS threads; Rust `Future`s are *cooperatively* scheduled—polling continues until the future explicitly yields (e.g., awaiting I/O). This gives fine‑grained control but requires an executor.

**R10** — *Medium*:  
- **unsafe**: Bypasses Rust’s safety guarantees; used only when the programmer can prove safety manually.  
- **Three things you can do in `unsafe` but not in safe Rust**:  
  1. **Dereference raw pointers** (`*const T`, `*mut T`) without proving they are valid.  
  2. **Call `extern` functions** or FFI code where Rust cannot verify memory safety.  
  3. **Access or modify `union` fields** (except the last written field) and perform **pointer arithmetic** that could break aliasing rules.  
- **When justified**: Implementing low‑level system code, FFI wrappers, or performance‑critical algorithms where the safety can be formally reasoned about (e.g., in libraries like `rayon`, `crossbeam`, or the standard library itself).

**R11** — *Easy*:  
- **Pattern matching** via `match` exhaustively checks a value against patterns.  
- **`match` vs `if let`**: `match` requires handling all possible patterns (compiler enforces exhaustiveness); `if let` is a concise guard for a single pattern, ignoring others.  
- **Exhaustiveness**: The compiler errors if a `match` could miss a possible value (e.g., missing `None` for `Option`). Use `_` as a catch‑all or add the missing arms.

**R12** — *Easy*:  
- **Vec<T>**: Dynamically sized, growable array on the heap; provides methods like `push`, `pop`. Capacity grows (often doubling) when needed, triggering a realloc.  
- **Array `[T; N]`**: Fixed size known at compile time; stored on the stack (unless behind a pointer). No runtime resizing.  
- **Memory management**: When `Vec`’s length equals its capacity, `push` allocates a new larger backing buffer, copies existing elements, and updates the pointer/length/capacity fields.

**R13** — *Easy*:  
- **Enums**: Algebraic data types that can hold variants, each possibly with different types/values. Unlike C/Java enums (simple integer constants), Rust enums can carry data.  
- **Option<T>**: `Some(T)` or `None`; replaces null/nil, forcing explicit handling of absence. Rust’s type system eliminates the “billion‑dollar mistake” of null references.

**R14** — *Easy*:  
- **impl block**: Associates methods and trait implementations with a type.  
- **Method receivers**:  
  - `&self`: Borrowed immutable reference (read‑only access).  
  - `&mut self`: Borrowed mutable reference (can modify).  
  - `self`: Takes ownership (used for consuming methods).  
- **Associated functions**: Defined without `self` (e.g., `String::new()`); act like static methods but are in the type’s namespace.

**R15** — *Easy*:  
- **derive macro**: `#[derive(Debug, Clone, PartialEq)]` automatically generates boilerplate trait implementations.  
- **Commonly derived**: `Debug` (pretty printing), `Clone` (copying), `Copy` (stack semantics for `Clone` types), `PartialEq`/`Eq` (equality), `Default` (default value), `Serialize`/`Deserialize` (serde).  
- **When you cannot derive**: If the trait requires custom logic (e.g., `Ord` needing a specific ordering), or if the type contains fields that themselves don’t implement the required trait.

**R16** — *Medium*:  
- **Cow<'a, T>` (Clone‑On‑Write)**: An enum (`Owned`, `Borrowed`) that may contain a borrowed reference or an owned value. It avoids copying unless mutation is needed.  
- **Use case**: API that may return a value that is often already owned but sometimes needs to clone:
  ```rust
  fn maybe_clone(s: &str) -> Cow<str> {
      if some_condition() {
          Cow::Owned(s.to_string())
      } else {
          Cow::Borrowed(s)
      }
  }
  // Later, if we need to mutate:
  let mut owned: String = maybe_clone("hello").into_owned();
  ```
  Without `Cow`, you’d always allocate a new `String`.

**R17** — *Medium*:  
- **Module system**: Organizes code hierarchically.  
  - **`mod`**: Declares a module; can be in‑file or separate `.rs` file.  
  - **`use`**: Brings names into scope (`use std::fs;`). Supports glob (`use std::io::*`), re‑exports (`use super::foo::bar as Baz`).  
  - **`pub`**: Makes items publicly accessible outside the module.  
- **File‑system mapping (2015 edition)**: Each `mod` in `mod.rs` or same‑name `.rs` file defines a module; subdirectories become submodules.  
- **2018 edition**: Relaxed rules – `src/main.rs` and `src/lib.rs` are crate roots; `mod.rs` optional (directory name itself is the module). Improves ergonomics and reduces boilerplate.

**R18** — *Hard*:  
- **Pin<T>**: Marks a value as *pinned*—its memory location cannot change. Used for self‑referential structs (e.g., a struct holding a pointer to one of its fields).  
- **Why needed**: In async, a `Future` may be moved after `await`; if it contains interior references, moving would break them. `Pin` guarantees the `Future` stays at the same address while it’s being polled.  
- **Unpin**: Auto‑derived for types that are safe to move even when pinned. If a type implements `Unpin`, `Pin<T>` behaves like a no‑op.

**R19** — *Hard*:  
- **Macro system**: Two main kinds.  
  - **Declarative (`macro_rules!`)**: Pattern‑based, hygienic, works at the syntax level. Good for simple code generation (e.g., `vec!`, `format!`).  
  - **Procedural**:  
    - **Derive**: `#[derive(Debug)]` expands to a function that generates code.  
    - **Attribute**: `#[some_attr]` custom attributes processed by a proc‑macro crate.  
    - **Function‑like**: `my_macro!(...)` that returns an entire item or expression.  
- **Hygiene**: Ensures identifiers inside a macro don’t accidentally capture or clash with surrounding code. `$crate`, `tt`, and `ident` are scoped appropriately.

**R20** — *Hard*:  
- **Zero‑cost abstractions**: Rust aims for abstractions that compile down to the same efficiency as hand‑written code.  
  - **Iterators**: Implemented via *generator* state machines; the loop is unrolled at compile time, inlining iterator methods, resulting in no runtime overhead beyond the loop itself.  
  - **Generics & Monomorphization**: Generic code is instantiated for each concrete type at compile time, allowing the compiler to specialize and inline, eliminating virtual dispatch overhead.  
  - **Trait static dispatch**: When a trait is used with a concrete type (e.g., `T: Trait` in a generic function), the compiler can statically resolve method calls, achieving the same performance as direct function calls.  
- Together, these features let Rust provide high‑level constructs (like `map`, `filter`, `async`/`await`) without runtime penalties, matching or surpassing hand‑optimized C code.
