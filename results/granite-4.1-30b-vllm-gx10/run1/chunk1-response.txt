**Networking**

**N1** — A Layer 2 switch forwards Ethernet frames based solely on MAC addresses within a single broadcast domain. A Layer 3 switch can also route IP packets, examining the IP header and using routing tables to forward traffic between different subnets/VLANs.

**N2** — /20 mask = 255.255.240.0 (14 host bits).  
- Network address: 10.0.0.0  
- Broadcast address: 10.0.15.255  
The host 10.0.5.37 belongs to this subnet.

**N3** — TCP three‑way handshake:  
1. Client → SYN (seq=x)  
2. Server → SYN‑ACK (seq=y, ack=x+1)  
3. Client → ACK (ack=y+1)  
If the final ACK is lost, the server stays in **SYN‑RECV** (half‑open) and will retransmit the SYN‑ACK a few times (typically 5‑6 attempts) before timing out and closing the socket. The client, having sent the ACK, believes the connection is established and will respond with a RST if it later receives a SYN‑ACK.

**N4** — **SNAT (Source NAT)** rewrites the source IP/port of an outgoing packet so that replies return to the NAT device. *Example*: a home router masquerades all internal clients (192.168.1.0/24) as its public WAN IP.  
**DNAT (Destination NAT)** rewrites the destination IP/port of an incoming packet, redirecting traffic to an internal server. *Example*: port‑forwarding HTTP (port 80) from the public IP to an internal web server at 192.168.1.10.

**N5** — Possible causes for “certificate subject name does not match target host name”:  
1. The server’s certificate’s **Common Name** or **SAN** does not include `example.com`.  
2. DNS resolution returned an IP that points to a different server whose certificate is for another name.  
3. The client is using an outdated or cached CNAME that points to a different hostname.  
4. The request is being redirected (via HTTP 302) to a different host before the TLS handshake completes.  
5. A man‑in‑the‑middle proxy presents its own certificate instead of the origin’s.

**N6** — **VLAN** (IEEE 802.1Q) segments traffic at Layer 2 within a single physical switch fabric using a 12‑bit tag (max 4096 IDs). It requires PVST/STP and is limited to the local LAN.  
**VxLAN** encapsulates Layer 2 frames inside UDP/IP, allowing VLAN IDs to be stretched over Layer 3 networks, providing up to 16 million VNI identifiers and enabling multi‑tenant, data‑center‑scale overlay networks. Choose VxLAN when you need large‑scale segmentation, stretch VLANs across data centers, or run on top of existing IP infrastructure.

**N7** — The host uses the **default route** (via eth0) for replies because the source IP (192.168.1.5) does not match any routing table entry that points to eth1 as the egress interface. To force replies out eth1, add policy‑based routing:  

```bash
ip rule add from 192.168.1.0/24 table eth1
ip route add 192.168.1.0/24 dev eth1 table eth1
ip route add default via 10.0.0.1 dev eth0 table main
```

Now packets sourced from 192.168.1.0/24 will consult the `eth1` table and use eth1 for replies.

**N8** — BGP path selection (in order of preference):  
1. **Neighbor type** (internal vs. external) – prefer external.  
2. **Highest WEIGHT** (Cisco‑specific, not standardized).  
3. **LOCAL_PREF** – highest wins.  
4. **Origin** – prefer `IGP` (i) over `EGP` (e) over `Incomplete` (?).  
5. **AS_PATH length** – shortest path.  
6. **ORIGINATOR_ID** (if AS_PATH identical).  
7. **CLUSTER_LIST length** (for route reflectors).  
8. **MED (Multi‑Exit Discriminator)** – lower is better (evaluated when paths are from the same AS).  
9. **Prefer eBGP over iBGP**.  
10. **Shortest IGP metric to next‑hop**.  
11. **Oldest BGP route** (tie‑breaker).  

(Only the first five are required by the question; the list above shows the full standard order.)

**N9** — VxLAN adds a UDP header (8 B) + VxLAN header (8 B) = **16 B**. IPsec (ESP) adds ≈ 50 B overhead. Total overhead = 66 B.  
Maximum inner payload = Physical MTU – overhead = 1500 B – 66 B = **1434 bytes**.

**N10** — **ARP** resolves an IPv4 address to a MAC address on the local link. **Gratuitous ARP** is an ARP reply sent without a prior ARP request, announcing “this IP is now at this MAC”. It helps:  
- Notify other hosts of a changed MAC (e.g., after NIC replacement or VM migration).  
- Detect IP conflicts (if another host replies with the same IP).  

**N11** — **Public IP** is globally routable on the Internet (e.g., 8.8.8.8). **Private IP** is reserved for internal use and not routed on the public Internet. RFC 1918 private ranges:  
- 10.0.0.0 – 10.255.255.255 (10/8)  
- 172.16.0.0 – 172.31.255.255 (172.16/12)  
- 192.168.0.0 – 192.168.255.255 (192.168/16)

**N12** — **DNS** translates domain names to IP addresses.  
- **A record**: maps a name to an IPv4 address.  
- **AAAA record**: maps a name to an IPv6 address.  
- **CNAME record**: maps an alias name to another canonical name (must be the only record for that name).

**N13** — **DHCP** (Dynamic Host Configuration Protocol) automates IP address assignment. The client follows **DORA**:  
1. **Discover** – broadcast DHCPDISCOVER to locate servers.  
2. **Offer** – servers respond with DHCPOFFER (proposed IP, lease, options).  
3. **Request** – client selects an offer and broadcasts DHCPREQUEST.  
4. **ACK** – server confirms with DHCPACK (final lease info) or DHCPNACK (reject).

**N14** — **Hub**: OSI Layer 1 (physical) device that repeats bits on all ports (no intelligence).  
**Switch**: OSI Layer 2 device that learns MAC addresses and forwards frames only to the destination port.  
**Router**: OSI Layer 3 device that routes IP packets between different networks using routing tables.

**N15** — **Half‑duplex** allows transmission in only one direction at a time (shared medium, collision detection, e.g., old Ethernet hubs). **Full‑duplex** enables simultaneous send and receive on a point‑to‑point link (modern Ethernet with switches or fiber). Modern Ethernet links almost universally use **full‑duplex**.

**N16** — **TTL (Time‑to‑Live)** limits the lifespan of a packet; each router decrements it by 1 and discards if it reaches 0, preventing endless loops. **traceroute** sends UDP/ICMP packets with incrementing TTL values (1, 2, 3…). When a router decrements TTL to 0, it replies with a “time exceeded” message, revealing the hop’s IP address. By iterating TTL, traceroute maps the path.

**N17** — A **NAT gateway** translates private IP addresses to a public address (and vice‑versa).  
- **Static NAT**: one‑to‑one mapping (e.g., internal 10.0.0.5 ↔ public 203.0.113.5).  
- **Dynamic NAT**: maps a private IP to any available address from a pool.  
- **PAT (Port Address Translation, also NAT‑overload)**: maps multiple private IPs to a single public IP using different source ports, allowing thousands of simultaneous connections.

**N18** — **ECMP (Equal‑Cost Multi‑Path)** load‑balances traffic across multiple next‑hops with identical metric. The kernel uses a **hash tuple** (source/destination IP, ports, protocol) to deterministically select a path, ensuring that packets of a flow follow the same route (preserving order). Common hash functions: 5‑tuple XOR, CRC32.  
**Problems with stateful firewalls**: If each firewall instance maintains its own connection state, a flow that is hashed to a different firewall on the return path may be dropped because the state isn’t present. Solutions include **consistent hashing**, **firewall clustering**, or **source‑based routing**.

**N19** — The **bandwidth‑delay product (BDP)** = 10 MB, but the TCP window is capped at 64 KB (default maximum). With a small window, the sender can only have ~64 KB in flight, far below the pipe capacity, causing the link to be under‑utilized and latency to appear “high” (slow start ramps up slowly). **TCP window scaling (RFC 1323)** allows the window size to be multiplied by a shift value (up to 14 bits), raising the maximum window to ~1 GB, matching the BDP and enabling full‑pipe throughput.

**N20** — **802.1Q trunk** carries frames tagged with VLAN IDs, allowing multiple VLANs over a single physical link.  
On Linux, to let a single NIC serve VLAN 10, 20, 30:  

```bash
ip link add link eth0 name eth0.10 type vlan id 10
ip link add link eth0 name eth0.20 type vlan id 20
ip link add link eth0 name eth0.30 type vlan id 30
ip addr add 10.10.10.2/24 dev eth0.10
ip addr add 10.20.20.2/24 dev eth0.20
ip addr add 10.30.30.2/24 dev eth0.30
ip link set eth0 up
ip link set eth0.10 up
ip link set eth0.20 up
ip link set eth0.30 up
```

**On‑wire frame format**: Ethernet header → 802.1Q tag (2 bytes TPID = 0x8100, 2 bytes TCI containing VLAN ID and PCP/CNP) → original Ethernet payload (IP packet). The tag is inserted between the source MAC and the EtherType.

**Linux**

**L1** — **Hard link**: points to the same inode; indistinguishable from the original file, cannot cross filesystems, and remains valid even if the original is renamed or deleted (as long as link count > 0).  
**Symbolic link (symlink)**: a separate inode containing the path to the target; can link across filesystems, is identifiable (e.g., `ls -l` shows `->`), and becomes dangling if the target is removed.

**L2** — `find /var/log -type f -size +100M` (or `-size 100M` for exactly 100 MB).

**L3** — **State D (uninterruptible sleep)** means the process is waiting for I/O (e.g., disk, NFS) and cannot be interrupted. `kill -9` (SIGKILL) **cannot** terminate a D‑state process because it cannot be scheduled; the process will only wake when the I/O completes or fails.

**L4** — **cgroups v1** uses a separate hierarchy per controller (cpu, memory, blkio, …) with individual mount points; configuration is done via files in each hierarchy. **cgroups v2** unifies all controllers into a single hierarchical tree, enforcing a “no internal tasks” rule (only leaf nodes can have processes) and providing a more atomic `cgroup.procs`. **systemd** prefers cgroups v2 because it simplifies resource management and aligns with its slice/unit model.

**L5** — **nftables** is the next‑generation framework with a cleaner syntax, integrated IPv4/IPv6, and better performance. **iptables** is the older userspace tool for the `netfilter` kernel subsystem. The kernel can load both because `iptables` translates its rules into the same `netfilter` tables that `nftables` uses; however, mixing them on the same table is discouraged. Typically only one userspace tool manages a given table.

**L6** — The discrepancy usually indicates **deleted files that are still open** by a running process. Those files’ disk space is not freed until the process closes the file descriptor. Use `lsof | grep deleted` to identify them.

**L7** — **Linux boot (UEFI)**:  
1. **UEFI firmware** loads the EFI application (`/EFI/linux/kernel.efi` or via Boot Loader).  
2. **Bootloader** (e.g., systemd‑boot, GRUB) reads its config, loads the kernel image and an **initramfs** (or initrd).  
3. **Kernel** decompresses and mounts the initramfs as the temporary root, runs `init` from it to perform early‑boot tasks (module loading, device discovery, LVM/MD, network).  
4. When the real root filesystem is found, the initramfs pivots (`switch_root`) to it.  
5. **systemd** becomes PID 1, reads its default target (e.g., `graphical.target`), and starts services according to unit files.

**L8** — `free -h` shows **available** memory as an estimate of what can be allocated without swapping, calculated by the kernel using heuristics that count **cached** and **buffer** memory as reclaimable. Even with 15 GB of `buff/cache`, the kernel may consider most of it non‑urgent, leaving a low “available” value. The OOM killer triggers when memory pressure exceeds the **oom_score_adj** thresholds. Tunables affecting this:  
- `/proc/sys/vm/min_free_kbytes` – minimum free memory.  
- `/proc/sys/vm/overcommit_memory` and `overcommit_ratio` – memory overcommit policy.  
- `/proc/sys/vm/swappiness` – tendency to swap.  
- `vm.drop_caches` – manually free caches.

**L9** — `ip netns` creates isolated network namespaces, each with its own network stack (interfaces, routing table, iptables). Container runtimes (e.g., Docker, CRI‑O) create a namespace per container, attach veth pairs to link it to the host, and configure IP, routes, DNS inside that namespace.

**L10** — **SIGTERM** (15) requests graceful termination; it can be caught and handled. **SIGKILL** (9) cannot be caught or ignored; the kernel forces exit. **SIGQUIT** (3) requests termination **and** generates a core dump; it can be caught. Only SIGTERM and SIGQUIT are catchable.

**L11** — **stdin** (0) is the standard input stream, **stdout** (1) is standard output, **stderr** (2) is standard error. To redirect stderr to `errors.log` while keeping stdout on the terminal:  

```bash
command 2>errors.log
```

or  

```bash
command >output.txt 2>&1   # both to output.txt (if you want stderr merged)
```

**L12** — `chmod 755` sets permissions:  
- **7** (owner) = rwx (read + write + execute)  
- **5** (group) = rx (read + execute)  
- **5** (others) = rx (read + execute)  

**L13** — **root** (UID 0) has unrestricted privileges by default. A user with **sudo** can execute specific commands (or all) as root after authenticating, limited by the `/etc/sudoers` file. This provides accountability and reduces the need for the root password.

**L14** — A **package manager** automates installation, upgrade, and removal of software. Default managers:  
- **Debian/Ubuntu** → `apt` (uses `.deb` packages).  
- **RHEL/Fedora** → `dnf` (successor to `yum`, uses `.rpm` packages).

**L15** — `/etc/fstab` defines how storage devices are mounted at boot. Each line specifies device, mount point, filesystem type, options, dump frequency, and fsck order. A misconfiguration (wrong UUID/device, bad options, missing filesystem) can prevent the mount, cause boot failure, or lead to a read‑only root filesystem.

**L16** — **LVM (Logical Volume Manager)** abstracts physical storage:  
- **Physical Volume (PV)**: a whole disk or partition initialized for LVM.  
- **Volume Group (VG)**: a pool of one or more PVs.  
- **Logical Volume (LV)**: a resizable block device carved from a VG.  
To extend an LV on‑the‑fly:  

```bash
lvextend -L +10G /dev/vg0/lv_name   # add 10 GB
resize2fs /dev/vg0/lv_name         # (or xfs_growfs) to expand filesystem
```

**L17** — The **I/O scheduler** orders pending block I/O requests to optimize latency or throughput.  
- **mq‑deadline**: adds a time slice to ensure fairness, good for mixed workloads.  
- **BFQ (Budget Fair Queueing)**: allocates bandwidth based on I/O‑bound process “budgets”, excellent for desktop responsiveness and interactive tasks.  
- **none**: no queuing; passes requests directly (used for devices that perform their own scheduling, e.g., SSDs).  
Choose **mq‑deadline** for general servers, **BFQ** for desktops/VMs with many concurrent interactive tasks, and **none** for high‑performance SSDs. Change at runtime:  

```bash
echo deadline > /sys/block/sda/queue/scheduler   # example
```

**L18** — **Load average** on Linux is the exponentially damped moving average of the number of processes **runnable** (state R) plus those in **uninterruptible sleep** (state D) over 1, 5, and 15 minutes. High load with low CPU% often means many processes are waiting on **I/O** (disk, NFS, or storage latency), inflating the average. Diagnosis steps:  
1. `top`/`htop` → check %CPU vs %WAIT (IOW).  
2. `iostat -xz 1` → look for high await, svctm, or %util.  
3. `vmstat 1` → examine bi/bo (block in/out) and wa (wait).  
4. `pidstat -u 1` → per‑process CPU usage.  
5. `sar -d` or `ioping` for disk latency.  
6. Network: `ifstat`, `nload`, or `ss -s`.  

**L19** — **SELinux** enforces **Mandatory Access Control (MAC)** by labeling subjects (processes) and objects (files, sockets) with security contexts and checking policy rules for every access. Modes:  
- **Enforcing**: policy decisions are applied and denials are logged.  
- **Permissive**: violations are logged but not blocked (useful for troubleshooting).  
- **Disabled**: SELinux is turned off.  
To troubleshoot a daemon failing to bind a non‑standard port:  
1. Check messages in `dmesg` or `journalctl -u <service>` for `AVC denied`.  
2. Use `ausearch -m avc -ts recent` to find the denial.  
3. Run `sealert -l <audit.log>` for a human‑readable report.  
4. Adjust policy with `semanage port -a -t <type> -p tcp <port>` or create a custom module via `audit2allow`.

**L20** — **Page faults** occur when a process references a virtual page not present in RAM.  
- **Minor page fault**: page is already in memory (e.g., shared copy) but not mapped; the kernel simply updates page tables—fast.  
- **Major page fault**: page must be read from disk (or swapped) → I/O, longer latency.  
**Transparent Huge Pages (THP)** automatically collapses many 4 KB pages into 2 MB (or 1 GB) pages to reduce TLB misses. Benefits: lower TLB pressure, fewer page table entries. Downsides: can cause fragmentation, higher memory usage, and occasional latency spikes during compaction. Disable THP when running workloads sensitive to latency or memory fragmentation (e.g., databases, real‑time systems) via:  

```bash
echo never > /sys/kernel/mm/transparent_hugepage/enabled
echo never > /sys/kernel/mm/transparent_hugepage/defrag
```
