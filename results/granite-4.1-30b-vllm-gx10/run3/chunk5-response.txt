**DN1**  
- **Class**: Reference type, allocated on the heap, supports inheritance, can have a parameterless constructor, and can be `null`.  
- **Struct**: Value type, allocated on the stack (or inline in containing objects), cannot inherit from other reference types (except `System.ValueType`), and cannot be `null` (unless nullable `struct?`).  
- **When to use a struct**: For small, immutable data that is frequently allocated and deallocated (e.g., `Point`, `DateTime`, numeric tuples) to avoid heap pressure and GC overhead. Avoid structs for larger or mutable data because copying can be expensive.

**DN2**  
- **IEnumerable<T>**: Represents a forward‑only, in‑memory collection. Methods like `Where`, `Select` are evaluated in **LINQ to Objects** (client‑side) after the query is enumerated.  
- **IQueryable<T>**: Represents a query that can be translated into an expression tree and executed by a remote data source (e.g., EF Core, LINQ to SQL). The provider (database) performs filtering, projection, etc., before data is returned.  
- **Why it matters**: Using `IQueryable<T>` enables the database to do heavy lifting (filtering, paging) reducing memory usage and network traffic. Using `IEnumerable<T>` forces all data to be loaded into memory first.

**DN3**  
- **async/await** lets a method asynchronously wait for a `Task` without blocking a thread. The compiler rewrites the method into a state machine.  
- **Task**: Represents an asynchronous operation that may be long‑running; allocates an object on the heap.  
- **ValueTask**: A struct wrapper that can avoid allocation when the operation completes synchronously (checked via `IsCompleted`). Use `ValueTask` for hot paths where the async operation often completes immediately to reduce GC pressure.  
- **When to use ValueTask**: High‑frequency APIs (e.g., I/O pipelines, protocol handlers) where you can cache or compute the result synchronously. Avoid for operations that always involve async I/O or where the result is not readily available.

**DN4**  
- **Dependency Injection (DI)** in .NET registers services with a container and resolves dependencies at runtime.  
- **Service lifetimes**:  
  - **Transient** – new instance per resolution (stateless services).  
  - **Scoped** – single instance per request (web request, EF `DbContext`).  
  - **Singleton** – single instance for the app lifetime.  
- **Common bug**: Injecting a **Scoped** service into a **Singleton** causes the scoped instance to be reused across requests, leading to state leakage (e.g., stale DB context, per‑request data). The fix is to inject the scoped service directly where needed or use `IServiceScopeFactory` to create a new scope.

**DN5**  
- **string**: Immutable reference type, stored on the heap, involves indirection and potential allocations for slicing/substrings.  
- **ReadOnlySpan<char>**: Inline, stack‑only view over contiguous memory (could be a `string`, char array, or native buffer). No heap allocation, faster for parsing/processing.  
- **When to use Span<T>**: High‑performance text processing, parsing, or when you need zero‑copy access to memory buffers (e.g., network packets, binary formats). Use when you can guarantee the data lives for the span’s lifetime (avoid capturing in async methods or returning across call boundaries).

**DN6**  
- **Garbage Collector (GC)**:  
  - **Generations**:  
    - **Gen 0** – new objects; collected frequently.  
    - **Gen 1** – survivors of Gen 0; collected less often.  
    - **Gen 2** – long‑living objects; collected rarely.  
  - **Large Object Heap (LOH)**: Separate heap for objects > 85 KB; allocations are slower and collections are less frequent (Gen 2 only).  
- **IDisposable**: Provides deterministic cleanup of unmanaged resources (file handles, sockets, DB connections) that the GC cannot automatically free. Even with a GC, you need `IDisposable` to release native resources promptly and avoid leaks.

**DN7**  
- **ConfigureAwait(false)**: Configures the awaited `Task` to **not capture the current `SynchronizationContext`** (or `TaskScheduler`). The continuation runs on any thread pool thread.  
- **Default behavior** (`ConfigureAwait(true)` or omitted): Captures the context; on UI or ASP.NET request threads, the continuation marshals back to that context, which can cause deadlocks or unnecessary context switches.  
- **When to use**: In library code or non‑UI async methods where you don’t need to resume on a specific context (e.g., I/O, background services). **Don’t use** when you must update UI controls, access request‑scoped services, or any API that requires the original context.

**DN8**  
- **.NET 8/9 new features**:  
  - **Primary constructors**: Concise class syntax where constructor parameters are part of the type declaration, automatically creating backing fields.  
  - **Collection expressions**: Literal syntax for building collections (`[1, 2, 3]`, `new HashSet<int> { 1, 2 }` with modifiers).  
  - **FrozenDictionary**: Immutable dictionary with O(1) lookups, created via `FrozenDictionary<TKey, TValue>.Create` or collection expressions.  
- **Example with primary constructors & DI**:
  ```csharp
  record HttpClientWrapper(
      [property: FromServices] HttpClient Http); // primary constructor with attribute injection

  // In Program.cs
  builder.Services.AddHttpClient<HttpClientWrapper>();
  ```

**DN9**  
- **Likely cause**: `DbContext` is registered as **Scoped** but is being injected into a **Singleton** (e.g., a static cache, background service) causing the same context to be reused across concurrent requests, leading to `ObjectDisposedException` once the original request scope ends.  
- **Fix**: Ensure `DbContext` is resolved per request (let DI inject it directly where needed) or use `IServiceScopeFactory` to create a fresh scope for each operation. Avoid singleton storage of the context.  
- **EF Core & DI**: By default, `AddDbContext<T>` registers `DbContext` as scoped, matching the lifetime of an HTTP request. Misaligning lifetimes breaks disposal semantics.

**DN10**  
- **record vs class**:  
  - **record**: Immutable (unless properties are `set`), provides value‑based equality (`==`), `with` expressions for cloning, and synthesized `Deconstruct`. Ideal for DTOs, data carriers.  
  - **class**: Reference type, mutable by default, no automatic value equality. Use when you need identity or mutable state.  
- **record struct**: A **value‑type record** (struct) that is also immutable and provides value equality. Use for tiny, performance‑critical data (e.g., coordinates) where heap allocation must be avoided.  
- **Choice**: Use `record` for POCO data models; use `class` for objects with behavior or identity; use `record struct` for ultra‑lightweight value objects.

**DN11**  
- **ref**: Caller must provide a variable that is definitely assigned; the called method can read/write the same storage.  
- **out**: Similar to `ref` but the variable does **not** need to be initially assigned; the called method must assign a value before returning.  
- **in** (C# 7.2+): Indicates the argument is **read‑only**; the called method cannot modify it. Useful for large structs to avoid copying while guaranteeing no mutation.  
- **Usage**: Use `ref`/`out` for methods that need to return multiple values or modify caller state (e.g., `TryParse`). Use `in` for high‑performance scenarios where you pass large structs but don’t want a copy.

**DN12**  
- **Nullable reference types** (`?`): Enabled via `#nullable enable`. The compiler enforces that reference variables are non‑nullable unless explicitly annotated with `?`. Helps prevent `NullReferenceException`s at compile time.  
- **Nullable value types** (`int?`): Wrapper around a value type allowing `null`. They are `Nullable<T>` structs and follow normal value‑type semantics (boxing, unboxing).  
- **Difference**: Nullable reference types are a **type system** feature affecting how references are treated; nullable value types are a **runtime** construct enabling `null` for structs.

**DN13**  
- **LINQ** (Language Integrated Query) provides a uniform way to query collections.  
- **Method syntax** (`list.Where(x => x > 0).Select(x => x * 2)`) is more flexible, supports extension methods, and is easier to chain complex logic.  
- **Query syntax** (`from x in list where x > 0 select x * 2`) resembles SQL and is syntactic sugar for method calls.  
- **Deferred execution**: LINQ queries return an `IEnumerable<T>` (or `IQueryable<T>`) that isn’t evaluated until enumerated (`foreach`, `ToList`, `ToArray`). This allows composition and reduces unnecessary work.

**DN14**  
- **Generic constraints** restrict type parameters:  
  - `where T : class` – `T` must be a reference type.  
  - `where T : struct` – `T` must be a value type (non‑nullable).  
  - `where T : new()` – `T` must have a parameterless constructor (useful for factories).  
  - `where T : IComparable<T>` – `T` must implement the interface, enabling method calls.  
- **Combining**: You can stack constraints (`where T : class, IComparable<T>`). This narrows the allowable types, allowing the compiler to generate safer code (e.g., calling interface methods).

**DN15**  
- **abstract class**: Can contain implementation, fields, and a mix of abstract/virtual members. Supports multiple inheritance of interfaces only.  
- **interface**: Pure contract; no implementation (except default methods). A class can implement many interfaces.  
- **Default interface methods (C# 8+)**: Allow adding method bodies to interfaces, reducing the need for abstract base classes while preserving binary compatibility. This blurs the line: interfaces can now provide shared implementation, but they still cannot hold state.

**DN16**  
- **Middleware pipeline**: A series of components that process `HttpContext` sequentially. Each middleware can invoke the next via `await _next(context)`.  
- **app.Use()**: Adds a middleware that **always** runs for every request.  
- **app.Map()**: Branches the pipeline based on a matching path; only invoked when the path matches.  
- **app.Run()**: Terminates the pipeline; no further middleware executes. Typically used for terminal handlers (e.g., static files, final response).  
- **Ordering**: Matters because early middleware can modify the request (e.g., authentication, routing) and later middleware sees the result. Exception‑handling middleware (e.g., `app.UseDeveloperExceptionPage()`) must be placed **before** the middleware that might throw.  
- **Exception handling**: Middleware can catch exceptions, log them, and produce an error response, preventing unhandled exceptions from bubbling to the host.

**DN17**  
- **Channel<T>**: A high‑performance, asynchronous, bounded (or unbounded) pipe for producer‑consumer scenarios. Supports `Writer`/`Reader` APIs, completion, and cancellation.  
- **BlockingCollection<T>**: Older, thread‑safe collection with blocking `Take/Add` operations. Simpler but less flexible; lacks built‑in cancellation and completion semantics.  
- **Bounded channel example** (back‑pressure):
  ```csharp
  var ch = Channel.CreateBounded<int>(capacity: 10);
  // Producer
  _ = Task.Run(async () => {
      for (int i = 0; i < 100; i++) {
          await ch.Writer.WaitToWriteAsync();
          if (ch.Writer.TryWrite(i)) continue;
          await ch.Writer.WriteAsync(i); // blocks when full
      }
      ch.Writer.Complete();
  });
  // Consumer
  _ = Task.Run(async () => {
      await foreach (var item in ch.Reader.ReadAllAsync()) {
          Console.WriteLine(item);
      }
  });
  ```
  The producer blocks on `WriteAsync` when the channel is full, providing natural back‑pressure.

**DN18**  
- **Source Generators**: Compile‑time code generators that analyze syntax/semantic models and emit C# source files. They run as part of the Roslyn compilation pipeline.  
- **Differences**:  
  - **Reflection**: Runtime introspection; incurs overhead and cannot generate code.  
  - **IL weaving**: Post‑compile binary manipulation; harder to debug and less type‑safe.  
  - **Source Generators** produce readable C# that the compiler compiles normally, enabling full IDE/tooling support.  
- **Incremental Generator**: Subclass of `ISourceGenerator` that receives an `IncrementalGenerator` API. It can track dependencies between inputs and outputs, allowing the generator to re‑run only when relevant inputs change, dramatically improving build performance for large projects.

**DN19**  
- **TPL Dataflow** (`System.Threading.Tasks.Dataflow`): Provides a set of building blocks for message passing and dataflow pipelines.  
  - **ActionBlock<T>**: Executes an action for each received message (consumer).  
  - **TransformBlock<TInput, TOutput>**: Transforms input to output, propagating the result downstream.  
  - **BufferBlock<T>**: Simple in‑memory buffer that holds messages; can be linked to other blocks.  
- **Comparison with Channels**:  
  - **Channels** are lower‑level, focus on async streaming with explicit `Writer/Reader`.  
  - **Dataflow** offers higher‑level abstractions (linking, broadcasting, batch processing, cancellation, exception handling) and built‑in back‑pressure via `MaxMessages` and `BoundedCapacity`. Use Dataflow for complex orchestration; use Channels for simple, high‑performance producer‑consumer queues.

**DN20**  
- **Minimal APIs**: Introduced in .NET 6, allow building HTTP endpoints with simple lambda expressions without controllers.  
- **Differences from controller‑based APIs**:  
  - **Simplicity**: No need for `Controller` classes, attributes on methods, or action results; everything is expressed via `app.MapGet`, `app.MapPost`, etc.  
  - **Testability**: Endpoints are first‑class delegates, easier to unit‑test by invoking directly. Integration tests still use `WebApplicationFactory`.  
  - **Middleware**: Middleware still applies globally; endpoint‑specific middleware can be added via `RequireAuthorization`, `MapToGroup`, or custom `EndpointFilter`.  
  - **OpenAPI**: Minimal APIs can generate Swagger via `app.UseSwagger()` and `app.UseSwaggerUI()`, but some advanced features (e.g., XML comments on controllers) require additional configuration.  
- **Route groups & endpoint filters**:  
  - **Route groups** (`app.MapGroup("/api/v1")`) let you prefix routes and share common middleware/filters.  
  - **Endpoint filters** (`app.UseEndpoints(e => e.RequireAuthorization())` or custom filters) allow cross‑cutting concerns (auth, logging) to be applied declaratively to a set of endpoints.

**P1**  
- **List vs Tuple**:  
  - **List** (`[]` or `List<T>`): Mutable sequence, dynamic size, stored on the heap. Ideal when you need to modify contents.  
  - **Tuple**: Immutable fixed‑size collection (created with `()` or `tuple()`). Good for returning multiple values or when the structure is known at compile time.  
- **Set vs Frozenset**:  
  - **Set** (`{}` or `set()`): Mutable unordered collection of unique items.  
  - **Frozenset**: Immutable version; can be used as dictionary keys or elements of other sets.

**P2**  
- **GIL (Global Interpreter Lock)**: A mutex that protects access to Python objects, ensuring only one thread executes Python bytecode at a time in CPython.  
- **Affected workloads**: CPU‑bound pure Python code suffers because threads cannot run truly in parallel. I/O‑bound or extensions that release the GIL (e.g., NumPy, I/O operations) still benefit from threading.  
- **Workarounds**:  
  - Use **multiprocessing** to spawn separate processes (each with its own GIL).  
  - Use native extensions or libraries that release the GIL during long computations.  
  - Switch to alternative implementations like **Jython** or **IronPython** that lack a GIL.

**P3**  
- **copy** (`import copy; copy.copy(obj)`): Shallow copy – creates a new container but references the same nested objects.  
- **deepcopy** (`copy.deepcopy(obj)`): Recursively copies all nested objects, producing a fully independent replica.  
- **Example of shallow copy issue**:
  ```python
  a = [[1, 2], [3, 4]]
  b = copy.copy(a)
  b[0][0] = 99          # modifies nested list in both a and b
  print(a)              # -> [[99, 2], [3, 4]]
  ```
  Here `b` is a shallow copy; changing an inner list affects `a`.

**P4**  
- **Decorator** that logs execution time:
  ```python
  import time
  from functools import wraps

  def log_time(func):
      @wraps(func)
      def wrapper(*args, **kwargs):
          start = time.perf_counter()
          result = func(*args, **kwargs)
          elapsed = time.perf_counter() - start
          print(f"{func.__name__} executed in {elapsed:.6f}s")
          return result
      return wrapper

  @log_time
  def example():
      time.sleep(0.5)
  ```

**P5**  
- **Generators** use `yield` to produce values one at a time, suspending and resuming execution. They compute values lazily, saving memory.  
- **Returning a list** computes all items upfront, storing them in memory.  
- **`yield from`**: Delegates part of the generator to another iterable or sub‑generator, flattening nested iteration. Example:
  ```python
  def concat(a, b):
      yield from a
      yield from b
  ```

**P6**  
- **asyncio event loop**: Central scheduler that runs coroutines, I/O callbacks, and tasks.  
- **`asyncio.run(main())`**: Convenience function to run the top‑level coroutine and close the loop.  
- **`asyncio.gather(*tasks)`**: Creates a task that waits for multiple awaitables concurrently, returning results in order.  
- **`asyncio.create_task(coro)`**: Schedules a coroutine as a `Task` on the running loop, returning the `Task` object.  
- **Why not `time.sleep()`**: `time.sleep()` blocks the thread, preventing the event loop from running other tasks. Use `asyncio.sleep()` which is a non‑blocking awaitable.

**P7**  
- **MRO (Method Resolution Order)** uses the **C3 linearization** algorithm (since Python 2.3). It produces a consistent, monotonic order that respects local declarations and covariance.  
- **Diamond inheritance** example:
  ```python
  class A: def who(self): return "A"
  class B(A): pass
  class C(A): def who(self): return "C"
  class D(B, C): pass
  print(D().who())   # Outputs: C
  ```
  The MRO for `D` is `[D, B, C, A, object]`. `C` appears before `A`, so `D().who()` calls `C`'s implementation.

**P8**  
- **Metaclass**: The class of a class; defines how a class is constructed (`__new__`, `__init__`). Used for class‑level validation, registration, or modification.  
- **`__init_subclass__`**: A class method called when a subclass is created; simpler for many use‑cases (e.g., auto‑registering subclasses).  
- **Use cases**:  
  - **Metaclass**: Enforcing interface contracts, automatically adding methods/attributes, creating ABCs with custom behavior.  
  - **`__init_subclass__`**: ORM model base classes that register subclasses in a global registry, or applying mixins uniformly.  

**P9**  
- **multiprocessing**: Spawns separate OS processes, each with its own Python interpreter and memory space; bypasses the GIL. Ideal for CPU‑bound tasks. Serialization (pickling) is required to share objects between processes.  
- **threading**: Uses OS threads within a single process; subject to the GIL, thus best for I/O‑bound work. No pickling needed for shared objects (but requires synchronization primitives).  
- **concurrent.futures**: High‑level API providing `ThreadPoolExecutor` (wraps threading) and `ProcessPoolExecutor` (wraps multiprocessing). Simplifies submission of callables and retrieval of `Future` results. Choose based on task nature (I/O vs CPU) and ease of use.

**P10**  
- **`__slots__`**: Declares a fixed set of instance attributes, preventing the creation of a per‑instance `__dict__`.  
- **When to use**: Memory‑critical applications with many small objects (e.g., node structures, protocol messages) where attribute lookup speed and reduced memory footprint matter.  
- **What it prevents**: Dynamic addition of new attributes (raises `AttributeError`).  
- **Memory impact**: Saves the overhead of a `dict` per instance (typically 64‑128 bytes) and can reduce fragmentation.

**P11**  
- **Virtual environment**: Isolated Python installation with its own site packages, allowing per‑project dependencies without affecting system Python.  
- **venv**: Built‑in, lightweight, creates environments with a symlinked Python executable.  
- **virtualenv**: Older third‑party tool offering more customization (e.g., specifying system site packages).  
- **conda**: Environment manager from Anaconda/Miniconda that handles not only Python packages but also binary dependencies (e.g., R, compilers). Useful for data‑science stacks.

**P12**  
- **Comprehensions** (`[x for x in iterable if cond]`, `{k: v for k, v in d.items() if cond}`, `{x for x in iterable}`) are concise, readable ways to build collections.  
- **Relation to `map`/`filter`**: `map(func, iter)` applies a function (similar to `[func(x) for x in iter]`). `filter(pred, iter)` selects items (`[x for x in iter if pred(x)]`). Comprehensions are generally faster and more Pythonic.  
- **Preference**: Use comprehensions for readability and when you need combined filtering/transformation. Use `map`/`filter` for functional pipelines or when working with iterators that should remain lazy (e.g., with `itertools`).

**P13**  
- **`==`**: Value equality test; compares the contents or values of objects.  
- **`is`**: Identity test; checks whether two references point to the **same object** in memory.  
- **Object interning**: Python interns small integers (typically -5 to 256) and some strings, reusing the same instance. Hence `a is b` can be `True` for `a = 42; b = 42`.  
- **Use `is`** for singletons (`None`, `True`, `False`), identity checks, or custom singleton patterns. Use `==` for semantic equality.

**P14**  
- **`*args`**: Captures additional positional arguments as a tuple.  
- **`**kwargs`**: Captures additional keyword arguments as a dictionary.  
- **Positional‑only (`/`)**: Parameters before `/` must be supplied positionally and cannot be passed as keywords (Python 3.8+).  
- **Keyword‑only (`*`)**: Parameters after `*` must be supplied by keyword.  
- **Example**:
  ```python
  def foo(a, b, /, c, *, d):
      pass
  # a, b are positional‑only; c must be positional or keyword; d is keyword‑only.
  ```

**P15**  
- **Context managers** provide `__enter__` and `__exit__` methods to allocate/release resources automatically within a `with` block.  
- **Using `__enter__/__exit__`**:
  ```python
  class FileOpener:
      def __init__(self, filename, mode):
          self.filename = filename
          self.mode = mode
      def __enter__(self):
          self.f = open(self.filename, self.mode)
          return self.f
      def __exit__(self, exc_type, exc, tb):
          self.f.close()
  ```
- **Using `@contextmanager`** from `contextlib`:
  ```python
  from contextlib import contextmanager
  @contextmanager
  def open_file(filename, mode):
      f = open(filename, mode)
      try:
          yield f
      finally:
          f.close()
  ```
- **Beyond files**: database connections, locks, temporary directories, or custom cleanup logic.

**P16**  
- **Type hinting** adds static type information.  
- **Key constructs**:  
  - **Union** (`Union[int, str]` or `int | str` in Python 3.10+): One of several types.  
  - **Optional** (`Optional[int]` ≡ `Union[int, None]`): Indicates a value may be `None`.  
  - **Literal** (`Literal['up', 'down']`): Restricts a value to exact constants.  
  - **TypeVar**: Generic type variable, e.g., `T = TypeVar('T')`. Can have bounds (`TypeVar('T', int, str)`).  
  - **Protocol**: Defines structural subtyping via `@protocol` or `typing.Protocol`; allows duck typing with static checks.  
- **Static analysis tools** (`mypy`, `pyright`) consume these hints to detect type mismatches without running the code.

**P17**  
- **Data model (dunder methods)**: Special methods that the interpreter calls for operations.  
  - **`__repr__`**: Official string representation, ideally unambiguous (`<ClassName(attr=...)>`). Used by `repr()`.  
  - **`__str__`**: Informal, human‑readable string (`str()`). Defaults to `__repr__` if missing.  
  - **`__eq__`**: Defines equality (`==`).  
  - **`__hash__`**: Provides hash value for use in sets/dicts. If `__eq__` is defined, you **must** also define `__hash__` (or set it to `None` to make the object unhashable). Inconsistent definitions break hash invariants.  
  - **`__getattr__`**: Called for attribute lookup that fails normally; can implement dynamic attributes.  
  - **`__getattribute__`**: Called for every attribute access; must avoid infinite recursion (call `object.__getattribute__(self, name)`).  
- **If `__eq__` is defined without `__hash__`**: The object becomes **unhashable** (its `__hash__` is set to `None`), so it cannot be used as a dict key or set member.

**P18**  
- **Descriptors**: Objects implementing `__get__`, `__set__`, `__delete__`. They control access to instance attributes.  
- **Protocol**:  
  - **`__get__(self, instance, owner)`**: Called when attribute is accessed. If `instance` is `None` (access via class), it returns the descriptor itself.  
  - **`__set__` / `__delete__`**: Similar for assignment and deletion.  
- **Built‑ins using descriptors**:  
  - **`property`**: Combines getter/setter/deleter methods into a descriptor.  
  - **`classmethod`** and **`staticmethod`**: Descriptors that wrap functions to produce class‑method or static‑method behavior.  
- **Use case**: Custom validation logic, lazy loading, or logging attribute access.

**P19**  
- **Python import system**:  
  - **Import process**:  
    1. **sys.modules** cache – if module already loaded, return it.  
    2. **Import hooks** (`sys.meta_path` finders) search for a loader.  
    3. **Loader** reads source/bytecode and executes it, populating the module namespace.  
  - **Absolute import** (`import package.module`) starts search at the top‑level package.  
  - **Relative import** (`from . import sibling`) starts from the current package (`__package__`).  
  - **`sys.path`**: List of directories (including the current directory) where modules are searched.  
  - **`PYTHONPATH`**: Environment variable extending `sys.path`.  
  - **`__init__.py`**: Marks a directory as a package; can initialize package state. In Python 3.3+, packages can be **namespace packages** without `__init__.py`, allowing split packages across distributions.  
  - **Finder vs Loader**:  
    - **Finder** (`sys.meta_path`): Determines if a module can be found and provides a loader.  
    - **Loader** (`sys.path_importer_cache`): Actually loads the module (reads source, compiles, executes).  

**P20**  
- **dataclasses** (module `dataclass`): Decorator/auto‑generate `__init__`, `__repr__`, `__eq__`, and optionally `__hash__` from class fields.  
  - **`__post_init__`**: Hook called after `__init__` to perform validation or derived field computation.  
  - **Field factories** (`field(default_factory=list)`): Provide mutable default values safely.  
  - **Frozen dataclasses** (`@dataclass(frozen=True)`): Makes instances immutable; attempting assignment raises `FrozenInstanceError`.  
  - **Inheritance**: Fields are inherited; you can add new fields or override defaults.  
- **attrs**: Similar purpose but older, offers more customization (validators, converters) and works on earlier Python versions.  
- **Pydantic**: Builds on `attrs` (or dataclasses in newer versions) adding **validation**, **parsing**, and **serialization** (JSON, YAML) with rich error messages. Ideal for data validation from untrusted sources (API requests, config files).  
- **When to choose Pydantic**: Need runtime validation, custom parsing (e.g., email, URLs), or strict schema enforcement. Use plain `dataclass` for internal DTOs where validation isn’t required.
