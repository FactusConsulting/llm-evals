**Networking**

**N1** — A Layer 2 (L2) switch forwards Ethernet frames based solely on MAC addresses within a single broadcast domain. It builds a MAC‑address table and learns ports dynamically. A Layer 3 (L3) switch, in addition to L2 switching, can route IP packets by examining the IP header, maintaining an IP routing table, and performing inter‑VLAN routing. Essentially, an L3 switch combines switching with router functionality.

**N2** — A /20 mask is 255.255.240.0 (binary: 11111111.11111111.11110000.00000000).  
- **Network address**: 10.0.0.0 (the first address in the block).  
- **Broadcast address**: 10.0.15.255 (the last address before the next block, 10.0.16.0).

**N3** — The TCP three‑way handshake:  
1. **SYN** – Client → Server (client initiates, sends initial sequence number).  
2. **SYN‑ACK** – Server → Client (server acknowledges client’s SYN and sends its own SYN with its ISN).  
3. **ACK** – Client → Server (client acknowledges the server’s SYN).  
If the final ACK is lost, the server stays in **SYN‑RECV** (half‑open) state, waiting for the ACK. After a retransmission timeout (typically 3× the initial RTO), the server re‑sends the SYN‑ACK. If the ACK still never arrives, the server eventually times out (usually after 5–6 retransmissions) and closes the connection.

**N4** — **SNAT (Source NAT)** rewrites the source IP/port of an outgoing packet so that replies return to the NAT device. *Example*: A home router changes a private 192.168.1.10:1234 to its public WAN IP 203.0.113.5:5000.  
**DNAT (Destination NAT)** rewrites the destination IP/port of an incoming packet, allowing traffic to be forwarded to an internal server. *Example*: A public IP 203.0.113.5:80 is translated to an internal web server 10.0.0.2:80.  

**N5** — Possible causes for “certificate subject name does not match target host name”:  
1. **Server misconfiguration** – the TLS certificate’s Common Name (CN) or Subject Alternative Names (SANs) do not include `example.com`.  
2. **DNS mismatch** – the resolved IP address may point to a different server than the one holding the correct certificate.  
3. **Typo or wrong hostname** – the URL used (`example.com`) differs from the name the client expects (e.g., `www.example.com`).

**N6** — **VLAN (Virtual LAN)** segments traffic at Layer 2 using a 12‑bit tag (802.1Q) within a single physical network, limited to 4096 IDs and requiring trunk links. **VxLAN (Virtual Extensible LAN)** encapsulates Layer 2 frames inside UDP packets, providing a 24‑bit VNI (Virtual Network Identifier) for up to 16 million logical networks and enabling transport over Layer 3 networks (IP). Choose VxLAN when you need large‑scale multi‑tenant segmentation, stretch VLANs across data centers, or overlay networks without reconfiguring the underlying physical infrastructure.

**N7** — The host replies via **eth0** because the default route (0.0.0.0/0) points to `gw 10.0.0.1`, which is reachable only through eth0. The kernel selects the outbound interface based on the routing table, not the inbound interface.  
**Fix with policy‑based routing**:  
```bash
# Create a new routing table (e.g., table 10)
echo "10    eth1_out" >> /etc/iproute2/rt_tables

# Add a default route in that table via the gateway on eth1 (if any) or directly to the source network
ip route add default via 192.168.1.1 table eth1_out   # adjust gateway as needed

# Rule to select table 10 for traffic whose source is 192.168.1.0/24
ip rule add from 192.168.1.0/24 lookup eth1_out pref 100
```  
Now replies to packets arriving on eth1 will use eth1 for egress.

**N8** — BGP path selection (in order of preference):  
1. **Neighbor type** – Prefer eBGP paths over iBGP.  
2. **Highest weight** (Cisco‑specific, not standardized).  
3. **Highest local preference** (`LOCAL_PREF`).  
4. **Shortest AS_PATH** (fewest AS numbers).  
5. **Origin code** – Prefer `IGP` (i) over `EGP` (e) over `Incomplete` (?).  
6. **Lowest MED** (`MULTI_EXIT_DISC`) – lower is better, but only compared between paths with the same originating AS.  
7. **Prefer eBGP over iBGP** (again, if not already decided).  
8. **Shortest IGP metric to next hop** (router’s IGP best path).  
9. **Oldest path** (lowest router ID or lowest neighbor ID as tiebreaker).  

**N9** — VxLAN adds an outer header (UDP + IP) plus an 8‑byte VTEP header, while IPsec (ESP) adds its own header (typically 50‑60 bytes) plus optional authentication data.  
**MTU math (physical MTU = 1500):**  
- Outer IPsec header ≈ 50 bytes.  
- VxLAN header = 50 bytes (UDP) + 20 bytes (outer IP) + 8 bytes (VXLAN) = 78 bytes.  
- Total overhead = 50 + 78 = 128 bytes.  
- **Maximum inner payload** = 1500 – 128 = **1372 bytes**.  
Thus the inner Ethernet frame (including its own IP header, TCP/UDP, etc.) can be at most 1372 bytes.

**N10** — **ARP (Address Resolution Protocol)** maps an IPv4 address to a MAC address on the local link. When a device needs to send an IP packet, it broadcasts an ARP request; the owner replies with its MAC.  
**Gratuitous ARP** is an unsolicited ARP reply (IP → MAC) that announces or reaffirms a mapping, often used when an interface comes up, changes IP, or after a failover to update neighbors’ caches, preventing stale entries.

**N11** — **Public IP addresses** are globally unique and routable on the Internet (e.g., 8.8.8.8). **Private IP addresses** are reserved for internal use and not routed on the public Internet. RFC 1918 defines three private ranges:  
- 10.0.0.0 – 10.255.255.255 (/8)  
- 172.16.0.0 – 172.31.255.255 (/12)  
- 192.168.0.0 – 192.168.255.255 (/16)

**N12** — **DNS (Domain Name System)** translates domain names to IP addresses.  
- **A record** – maps a hostname to an IPv4 address.  
- **AAAA record** – maps a hostname to an IPv6 address.  
- **CNAME record** – maps an alias name to the canonical name (another DNS name); the target must be a fully‑qualified domain name, not an IP address.

**N13** — **DHCP (Dynamic Host Configuration Protocol)** automates IP address assignment. The client follows the **DORA** sequence:  
1. **Discover** – Broadcasts DHCPDISCOVER to locate servers.  
2. **Offer** – Servers respond with DHCPOFFER (proposed IP, lease, options).  
3. **Request** – Client selects an offer and broadcasts DHCPREQUEST to claim it.  
4. **ACK** – Server sends DHCPACK confirming the lease; client configures its interface.

**N14** — **Hub** – Operates at **OSI Layer 1** (physical). It blindly repeats bits on all ports, creating a single collision domain.  
**Switch** – Works at **Layer 2** (data link). It learns MAC addresses, forwards frames only to the destination port, reducing collisions.  
**Router** – Functions at **Layer 3** (network). It routes IP packets between different networks, maintaining routing tables and performing inter‑network forwarding.

**N15** — **Half‑duplex** allows transmission **or** reception on a medium at a time (e.g., classic 10BASE‑T hubs). **Full‑duplex** enables simultaneous send and receive, doubling effective bandwidth. Modern Ethernet (fast/​gigabit/​10 GbE) uses **full‑duplex** when connected via switches or directly‑connected point‑to‑point links.

**N16** — **TTL (Time‑to‑Live)** limits an IP packet’s lifespan; each router decrements TTL by 1 and discards the packet if it reaches zero, preventing endless loops. **traceroute** exploits TTL by sending packets with incrementing TTL values (1, 2, 3…). When a router decrements TTL to zero, it replies with an ICMP “Time Exceeded” message, revealing its IP address. By observing successive TTL expirations, traceroute maps the hop‑by‑hop path.

**N17** — A **NAT gateway** translates private IP addresses to a public address (or vice‑versa) to enable communication between private networks and the Internet.  
- **Static NAT** – One‑to‑one mapping (e.g., internal 10.0.0.5 ↔ public 203.0.113.5).  
- **Dynamic NAT** – Maps a private IP to any available address from a pool of public IPs.  
- **PAT (Port Address Translation, also NAT Overload)** – Maps multiple private IPs to a single public IP using different source ports, allowing thousands of internal hosts to share one address.

**N18** — **ECMP (Equal‑Cost Multi‑Path)** allows a router to forward packets over multiple next‑hops that have identical metric costs. The router hashes packet header fields (src/dst IP, ports, etc.) to select a path, ensuring the same flow consistently uses one link. Common hash functions: 5‑tuple (srcIP, dstIP, proto, srcPort, dstPort) or simpler src/dst IP. **Asymmetric flows** arise when stateful devices (firewalls, load balancers) inspect traffic in one direction but not the other, causing return traffic to take a different path and potentially breaking state. Solutions include using the same device for both directions or employing flow‑aware ECMP that shares state.

**N19** — The **bandwidth‑delay product (BDP)** = bandwidth × round‑trip time. With BDP = 10 MB, the sender could have 10 MB of unacknowledged data in flight. The default TCP window size without scaling is 64 KB, far too small to utilize the available capacity, causing the sender to throttle and experience high latency. **TCP window scaling (RFC 1323)** enlarges the window size via a 14‑bit shift value (up to ~1 GB), allowing the sender to keep the pipe full and eliminate the bottleneck.

**N20** — **802.1Q trunk ports** carry traffic for multiple VLANs by inserting a 4‑byte 802.1Q tag (TPID = 0x8100 and TCI) into each Ethernet frame. The tag includes a VLAN ID (VID, 12 bits) and optional priority bits.  
**Linux configuration for a single NIC to reach VLAN 10, 20, 30**:  
```bash
# Assume physical interface is eth0
ip link add link eth0 name eth0.10 type vlan id 10
ip link add link eth0 name eth0.20 type vlan id 20
ip link add link eth0 name eth0.30 type vlan id 30

ip addr add 10.10.0.2/24 dev eth0.10
ip addr add 10.20.0.2/24 dev eth0.20
ip addr add 10.30.0.2/24 dev eth0.30
ip link set eth0.10 up
ip link set eth0.20 up
ip link set eth0.30 up
```  
**On‑wire frame format**: `Preamble → SFD → Destination MAC → Source MAC → 8100 (TPID) → Priority/CFI → VID (12 bits) → EtherType → Payload → FCS`.

**Linux**

**L1** — **Hard link**: references the same inode; multiple names point to identical file data. Cannot cross filesystems and is removed only when the link count drops to zero. **Symbolic link (symlink)**: a special file containing a path string that points to another file; can link across filesystems and becomes dangling if the target moves/removed.

**L2** — Use `find` with size filter:  
```bash
find /var/log -type f -size +100M
```  
(`+100M` means > 100 MiB).

**L3** — **State D (uninterruptible sleep)** indicates the process is waiting for I/O (e.g., disk, NFS) and cannot be interrupted. `kill -9` (SIGKILL) cannot terminate a D‑state process until the I/O completes or the kernel decides to kill it (rare). You may need to wait or reboot.

**L4** — **cgroups v1** uses a separate hierarchy per controller (cpu, memory, blkio, …) with individual mount points; configuration is done via files in each hierarchy. **cgroups v2** unifies all controllers into a single hierarchical tree, enforcing a “no internal tasks” rule (only leaf nodes can have processes) and providing a more consistent API. **systemd** prefers **cgroups v2** because it simplifies resource management, reduces mount‑point complexity, and aligns with modern kernel features (e.g., `io.lat`, `memory.high`).

**L5** — **nftables** is the next‑generation framework offering a cleaner syntax, faster matching, and unified IPv4/IPv6 tables. **iptables** is the older userspace tool for the `netfilter` kernel subsystem. The kernel can handle both because `iptables` translates rules into `nftables` structures internally (via the `nf_tables` API) when the `nftables` module is loaded. Administrators can run either userspace tool; mixing them on the same host is possible but not recommended for clarity.

**L6** — The discrepancy usually means **deleted files that are still open** by running processes. Those files’ disk space isn’t freed until the process closes the file descriptor. Check with:  
```bash
lsof | grep '(deleted)'
```  
or `sudo find /proc/*/fd -lname 'deleted' -exec ls -l {} \;`.

**L7** — **Linux boot (UEFI)**:  
1. **UEFI firmware** initializes hardware, loads the EFI shell, and searches for EFI applications (`*.efi`).  
2. **Bootloader** (e.g., systemd-boot, GRUB) is loaded from the EFI System Partition (ESP). It parses config, selects kernel/initramfs, and passes parameters.  
3. **Kernel** decompresses and starts executing, mounting the initial RAM filesystem (`initramfs`) as root.  
4. **initramfs** performs early‑boot tasks (module loading, device detection, LVM/MD RAID assembly, root= lookup).  
5. **Real root** is switched to (`pivot_root`), and control is transferred to **systemd** (or an init script).  
6. **systemd** reads targets (e.g., `graphical.target`) and starts services, bringing the system to the desired runtime state.

**L8** — **`free -h`** shows “available” as an estimate of memory that can be allocated without swapping, calculated by the kernel using heuristics that consider **buff/cache** but also reserves some for kernel allocations and future fragmentation. Even with 15 GB in `buff/cache`, the kernel may deem only ~1 GB truly free because:  
- **Page cache** and **buffer cache** are reclaimable but not instantly; the kernel keeps a portion for metadata and to avoid excessive scanning.  
- **Memory pressure** (e.g., `vm.min_free_kbytes`, `vm.swappiness`) influences the estimate.  
- **ZRAM** or **transparent huge pages** may consume hidden memory.  
**OOM killer** fires when allocation requests exceed the “available” threshold and the system cannot reclaim enough memory. Tunables affecting this: `vm.swappiness`, `vm.min_free_kbytes`, `vm.overcommit_*`, and cgroup memory limits.

**L9** — `ip netns` creates isolated **network namespaces**, each with its own network stack (interfaces, routing table, iptables rules). Container runtimes (e.g., Docker, CRI‑O) use `ip netns` to:  
- Spawn a private namespace for each container.  
- Move a veth pair: one end stays in the host namespace, the other is attached to the container’s namespace, providing isolated networking.  
- Apply per‑container iptables, routes, and DNS settings.

**L10** — **SIGTERM (15)** – Termination signal; can be caught, allowing graceful shutdown. **SIGKILL (9)** – Forced termination; cannot be caught or ignored. **SIGQUIT (3)** – Like SIGTERM but also generates a core dump; can be caught. Only SIGTERM and SIGQUIT are catchable; SIGKILL is not.

**L11** — **stdout (file descriptor 1)** – Standard output (default console). **stderr (fd 2)** – Standard error, typically for diagnostics. **stdin (fd 0)** – Standard input. To redirect **stderr** to `errors.log` while keeping **stdout** on the terminal:  
```bash
command 2>errors.log
```  
or, preserving order:  
```bash
command >output.txt 2>&1   # both to output.txt (if you want stderr merged)
```  
For separate files: `command >stdout.txt 2>stderr.log`.

**L12** — `chmod 755` sets permissions:  
- **7** (owner) = rwx (read + write + execute).  
- **5** (group) = rx (read + execute).  
- **5** (others) = rx (read + execute).  
Thus the file is executable by everyone, writable only by the owner, and readable by all.

**L13** — **root** is the superuser with UID 0, possessing unrestricted privileges by default. A user with **sudo** can execute specific commands (or all) as root after authenticating, limited by the `/etc/sudoers` policy. Sudo provides **auditability** and **fine‑grained control**, while root is all‑powerful without such constraints.

**L14** — A **package manager** automates installation, upgrade, and removal of software. Default managers:  
- **Debian/Ubuntu** – `apt` (uses `.deb` packages).  
- **RHEL/Fedora** – `dnf` (successor to `yum`, uses `.rpm` packages).

**L15** — **/etc/fstab** defines static filesystem mount points, options, and dump/pass numbers for `mount -a` at boot. A misconfigured entry (wrong device name, bad UUID, incorrect filesystem type, or missing `nofail` for optional devices) can prevent boot or cause mount failures, potentially dropping the system into emergency mode.

**L16** — **LVM (Logical Volume Manager)** abstracts physical storage:  
- **Physical Volume (PV)** – Initialized block device (e.g., `/dev/sda`).  
- **Volume Group (VG)** – Collection of one or more PVs, providing a pool of space.  
- **Logical Volume (LV)** – Allocated portion of a VG, formatted as a filesystem.  
To extend an LV on‑the‑fly:  
```bash
# Assuming LV is /dev/vg0/lv_data and VG has free space
lvextend -L +10G /dev/vg0/lv_data   # add 10 GB
# Resize filesystem (e.g., ext4)
resize2fs /dev/vg0/lv_data
```
No downtime needed for most filesystems.

**L17** — The **I/O scheduler** decides request order to optimize latency vs. throughput.  
- **mq‑deadline** – Prioritizes latency, groups requests by deadline, good for interactive workloads.  
- **BFQ (Budget Fair Queueing)** – Fairly slices bandwidth among processes, excellent for desktops with mixed I/O.  
- **none** – No queuing (pass‑through), used for devices that perform their own scheduling (e.g., SSDs, NVMe).  
Choose **deadline** for latency‑sensitive DBs, **BFQ** for desktops, **none** for modern SSDs/NVMe. Change at runtime:  
```bash
echo deadline > /sys/block/sda/queue/scheduler   # or bfq / none
```

**L18** — **Load average** on Linux is the exponentially damped moving average of the number of processes **runnable** (CPU‑bound) **plus** those **waiting for I/O** (in D state) over 1, 5, and 15 minutes. High load with low CPU% often means **I/O wait** dominates. Diagnose:  
- `top`/`htop` → check `%wa` (I/O wait).  
- `iostat -xz 1` → disk utilization, await.  
- `vmstat 1` → bi/bo, cs (context switches).  
- `sar -d` or `pidstat -u 1` for per‑process CPU.  
- Network: `ifstat`, `nload`, or `ss -s`.  
If `%wa` is high, the bottleneck is disk; if CPU% is high, it’s CPU; if network queues are saturated, check `netstat -s` or `tcptrace`.

**L19** — **SELinux** enforces **Mandatory Access Control (MAC)** via security contexts (user, role, type, level) attached to subjects (processes) and objects (files, sockets).  
- **Enforcing** – Policy rules are active; violations are denied and logged.  
- **Permissive** – Violations are allowed but logged, useful for troubleshooting.  
- **Disabled** – SELinux is turned off; only discretionary Linux permissions apply.  
To troubleshoot a daemon failing to bind a non‑standard port:  
1. Check messages with `journalctl -u <service>` or `dmesg`.  
2. Use `ausearch -m avc -ts recent` to find SELinux denials.  
3. Run `sealert -l <audit.log>` for a human‑readable report.  
4. Adjust policy with `semanage port -a -t <type> -p tcp <port>` or create a custom module via `audit2allow`.

**L20** — **Page faults** occur when a process accesses a virtual page not present in physical RAM. The kernel handles two main types:  
- **Minor (soft) page fault** – Page is present in memory but not mapped; the kernel simply updates page tables (no disk I/O).  
- **Major page fault** – Page is not in memory; the kernel reads it from swap or the backing file, incurring disk I/O and higher latency.  
**Transparent Huge Pages (THP)** automatically collapses contiguous 4 KB pages into 2 MB (or 1 GB) huge pages to reduce TLB misses and improve throughput for memory‑intensive workloads. However, THP can increase memory fragmentation and cause latency spikes during compaction. Disable THP for latency‑critical apps (e.g., databases, real‑time systems) via:  
```bash
echo never > /sys/kernel/mm/transparent_hugepage/enabled
echo never > /sys/kernel/mm/transparent_hugepage/defrag
```  
or use `nohugepages` kernel boot parameter.
