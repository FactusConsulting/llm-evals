**N1** — A Layer 2 switch operates primarily at the Data Link Layer (Layer 2) and forwards frames based on MAC addresses. It functions as a high-speed bridge within a single broadcast domain. A Layer 3 switch operates at the Network Layer (Layer 3) and forwards packets based on IP addresses. It includes routing capabilities, allowing it to route traffic between different subnets, effectively acting as a router but with the high-speed switching performance of a L2 switch.

**N2** — The host IP is 10.0.5.37/20.
The subnet mask for /20 is 255.255.240.0.
The block size is $2^{(32-20)} = 2^{12} = 4096$ addresses.
The network address is the starting address of the block: **10.0.32.0**.
The broadcast address is the last address of the block: **10.0.47.255**.

**N3** — The TCP three-way handshake establishes a reliable connection:
1. **SYN (Synchronize):** Client sends a SYN packet to the server, proposing an initial sequence number (ISN).
2. **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and replies with a SYN-ACK packet, acknowledging the client's ISN and proposing its own ISN.
3. **ACK (Acknowledge):** Client receives SYN-ACK and sends a final ACK packet, acknowledging the server's ISN. The connection is established.
If the final ACK is lost, the server will wait for a timeout period. If no ACK is received, the server will retransmit the SYN-ACK packet multiple times. If the client never receives the SYN-ACK, it will retransmit the initial SYN packet until the connection times out.

**N4** — **SNAT (Source Network Address Translation):** Translates the source IP address of a packet as it leaves a private network to a public IP address. *Example: A host on a private LAN (192.168.1.10) accessing Google uses the router's public IP as the source address.*
**DNAT (Destination Network Address Translation):** Translates the destination IP address of a packet as it enters a private network from the public internet. *Example: A public server IP (203.0.113.5) receives traffic, and DNAT translates the destination to the internal server's private IP (192.168.1.50).*

**N5** — Three possible causes for `SSL: certificate subject name does not match target host name`:
1. **Incorrect Hostname:** The hostname used in the `curl` command does not match the Common Name (CN) or Subject Alternative Name (SAN) listed in the certificate.
2. **Expired Certificate:** The certificate has passed its validity date.
3. **Misconfigured Proxy/Load Balancer:** An intermediary device is presenting a certificate that belongs to a different domain or is self-signed, rather than the intended target.

**N6** — **VLAN (Virtual LAN):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains within the same physical switch infrastructure. VLANs are limited to 4094 segments.
**VxLAN (Virtual Extensible LAN):** A network virtualization overlay technology that encapsulates Layer 2 Ethernet frames within a Layer 3 UDP/IP packet. It allows L2 adjacency to be stretched across an L3 network fabric.
You would choose VxLAN over VLAN when you need to scale beyond the 4094 VLAN limit, or when you need to extend Layer 2 domains across a large, multi-subnet, or geographically dispersed IP network (L3 underlay).

**N7** — Traffic arriving on eth1 from 192.168.1.0/24 is being replied via eth0 because the kernel's routing table determines that the return path (the source IP, 192.168.1.5) is best reached via the default gateway associated with eth0 (10.0.0.1). The kernel uses the destination IP of the incoming packet to determine the egress interface.
To fix this with policy-based routing, you must create a routing rule that forces traffic originating from the 192.168.1.0/24 subnet to use the eth1 interface/gateway, regardless of the main routing table:
1. Add a route specific to the subnet: `ip route add 192.168.1.0/24 dev eth1 src 192.168.1.5`
2. Add a routing rule to match traffic originating from that source: `ip rule add from 192.168.1.0/24 table 100` (where table 100 points to the specific route).

**N8** — BGP path selection is a complex algorithm used by routers to determine the best path to a destination prefix when multiple paths exist. The router evaluates several attributes in a strict, ordered preference list.
The general order of preference (highest to lowest) is:
1. **Weight** (Cisco proprietary, highest local preference)
2. **Local Preference** (Highest is preferred, used within an AS)
3. **AS Path Length** (Shortest path is preferred)
4. **Origin Type** (IGP > EGP > Incomplete)
5. **MED (Multi-Exit Discriminator)** (Lowest is preferred, used by external peers)
6. **eBGP over iBGP** (External BGP is preferred over Internal BGP)

**N9** — When running VxLAN over an IPsec tunnel, the encapsulation adds significant overhead.
The process is: Original L2 Frame $\rightarrow$ VxLAN Header $\rightarrow$ UDP Header $\rightarrow$ IP Header $\rightarrow$ IPsec Header (ESP/AH) $\rightarrow$ Outer IP Header.
Assuming the physical MTU is 1500 bytes:
1. **VxLAN Overhead:** $\approx 50$ bytes (VNI, UDP, IP headers).
2. **IPsec Overhead:** $\approx 50$ bytes (ESP header + padding/trailer).
3. **Total Overhead:** $\approx 100$ bytes.
Maximum Inner Payload = Physical MTU - Total Overhead
Maximum Inner Payload = $1500 - 100 = \mathbf{1400}$ bytes.

**N10** — **ARP (Address Resolution Protocol):** ARP is used to map a known Layer 3 IP address to its corresponding Layer 2 MAC address within a local network segment. It operates by broadcasting an ARP request asking, "Who has this IP address? Tell me your MAC address."
**Gratuitous ARP:** This is an ARP request sent by a host to itself (or broadcasted without a specific request). It solves the problem of stale ARP caches. It proactively informs neighboring devices of a host's current MAC address, which is crucial when a host changes its MAC address or when a host comes online to prevent IP address conflicts.

**N11** — **Public IP Address:** An IP address globally unique and routable on the public internet. It must be assigned by an IANA-approved registry.
**Private IP Address:** An IP address reserved for use within private, internal networks (LANs). These addresses are not routable on the public internet and require NAT to communicate externally.
The three private IPv4 ranges defined in RFC 1918 are:
1. **10.0.0.0/8** (10.0.0.0 to 10.255.255.255)
2. **172.16.0.0/12** (172.16.0.0 to 172.31.255.255)
3. **192.168.0.0/16** (192.168.0.0 to 192.168.255.255)

**N12** — **DNS (Domain Name System):** A hierarchical naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses (like 192.0.2.1).
**A Record:** Maps a domain name to an IPv4 address.
**AAAA Record:** Maps a domain name to an IPv6 address.
**CNAME Record (Canonical Name):** Creates an alias, mapping one domain name to another domain name (e.g., `blog.example.com` CNAMEs to `servers.example.com`).

**N13** — **DHCP (Dynamic Host Configuration Protocol):** A network protocol used to automatically assign IP addresses and other network configuration parameters (subnet mask, gateway, DNS servers) to devices on a network.
The DORA process is:
1. **Discover:** Client broadcasts a DHCP Discover message to find available servers.
2. **Offer:** DHCP server responds with a DHCP Offer, proposing an IP address lease.
3. **Request:** Client broadcasts a DHCP Request, formally accepting the offered IP address.
4. **Acknowledge:** DHCP server sends a DHCP ACK, confirming the lease and providing all necessary configuration details.

**N14** — **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming data to every connected port, creating a single large collision domain.
**Switch:** Operates at Layer 2 (Data Link). It learns MAC addresses and forwards frames only to the intended destination port, segmenting collision domains.
**Router:** Operates at Layer 3 (Network). It uses IP addresses to determine the best path for packets between different networks (subnets).

**N15** — **Half-duplex:** Allows data to travel in both directions, but only one direction at a time. If both devices transmit simultaneously, a collision occurs.
**Full-duplex:** Allows data to travel simultaneously in both directions without collisions, as separate dedicated paths are used for transmission and reception.
Modern Ethernet links overwhelmingly use **full-duplex** communication.

**N16** — The **TTL (Time To Live)** field is an 8-bit field in the IP header that limits the lifespan of a packet. Each router that forwards the packet decrements the TTL by one. If the TTL reaches zero, the router discards the packet and sends an ICMP Time Exceeded message back to the source.
**Traceroute** exploits this by sending a sequence of packets with incrementally increasing TTL values (starting at 1). When the first router receives a packet with TTL=1, it drops it and sends an ICMP Time Exceeded message, revealing the identity of the first hop. This process is repeated until the destination is reached.

**N17** — A **NAT Gateway** is a device (usually a router or firewall) that performs Network Address Translation, allowing multiple private IP addresses to share a single public IP address when accessing the internet.
*   **Static NAT:** A fixed, one-to-one mapping between a private IP and a public IP. The mapping never changes. (Used for servers that need a consistent public address).
*   **Dynamic NAT:** Maps private IPs to a pool of available public IPs on a first-come, first-served basis.
*   **PAT (Port Address Translation) / NAT Overload:** The most common form. It maps many private IPs to a single public IP by tracking unique source port numbers for each connection, allowing thousands of internal hosts to share one public IP.

**N18** — **ECMP (Equal-Cost Multi-Path):** ECMP allows a router to install multiple next-hop paths into the routing table for the same destination prefix, provided all paths have the same routing metric (cost). The router then distributes traffic across these paths.
**Hashing Strategies:** Common strategies use a hash function applied to the packet headers, typically combining the Source IP, Destination IP, Source Port, and Destination Port. This ensures that all packets belonging to the same flow (e.g., a single TCP session) follow the same path.
**Asymmetric Flows:** If a stateful firewall is involved, asymmetric flows occur when the outbound packet takes one path (e.g., Path A) and the return traffic takes a different path (e.g., Path B). The firewall only sees the initial connection state on Path A, and when the return packet arrives on Path B, the firewall does not recognize the session state, causing it to drop the packet.

**N19** — The **Bandwidth-Delay Product (BDP)** is the maximum amount of unacknowledged data that can be "in flight" on the network at any given time, calculated as Bandwidth $\times$ Round Trip Time (RTT).
The problem is that the TCP window size (the advertised buffer size) limits the amount of data that can be sent before an acknowledgment is required. If the BDP (10MB) is much larger than the TCP window size (64KB), the connection is severely bottlenecked by the small window, not the available bandwidth.
**TCP Window Scaling (RFC 1323)** solves this by allowing the TCP header to advertise a window size much larger than the standard 16-bit limit (65,535 bytes). This allows the sender to fill the pipe up to the BDP, maximizing throughput.

**N20** — **802.1Q Trunk Ports:** This standard allows a single physical link to carry traffic for multiple VLANs. It achieves this by inserting a 4-byte VLAN tag (Tag Protocol Identifier and VLAN ID) into the Ethernet frame header.
To configure a server with a single NIC to communicate on VLANs 10, 20, and 30 on Linux, you create multiple virtual sub-interfaces on the physical interface (`eth0`):
1. `eth0.10` (for VLAN 10)
2. `eth0.20` (for VLAN 20)
3. `eth0.30` (for VLAN 30)
Each sub-interface is configured with the appropriate IP address for its respective VLAN subnet.
**Frame Format on the Wire:** The frame structure is: Ethernet Header $\rightarrow$ **802.1Q Tag (4 bytes)** $\rightarrow$ Original Ethernet Header (containing L3/L4 info) $\rightarrow$ Payload.

**L1** — **Hard Link:** A hard link is a directory entry that points directly to the same inode (the metadata structure containing file data) as the original file. If you delete the original file, the data remains accessible via the hard link until the last link is removed. They share the same data blocks.
**Symbolic Link (Symlink):** A symbolic link is a special file that contains a text path pointing to another file or directory. It is a pointer, not a pointer to the inode itself. If the target file is moved or deleted, the symlink breaks (dangling link).

**L2** — Use the `find` command with the `-size` flag:
`find /var/log -type f -size +100M`
This searches `/var/log` for files (`-type f`) whose size is greater than 100 Megabytes (`+100M`).

**L3** — State D (Uninterruptible Sleep) means the process is blocked, waiting for an I/O operation to complete (e.g., waiting for disk read/write). The kernel cannot interrupt this process because it is waiting on hardware, and the process cannot be safely stopped or killed until the I/O completes. Therefore, `kill -9` (SIGKILL) will fail to terminate a process in state D.

**L4** — **cgroups v1:** Uses a monolithic structure where different resource controllers (CPU, Memory, I/O) operate independently. Resource limits are applied per controller.
**cgroups v2:** Implements a unified hierarchy and a unified control plane. All controllers share a common hierarchy, allowing for more coherent and predictable resource management across different subsystems.
Systemd prefers cgroups v2 because its unified hierarchy simplifies resource management, improves isolation, and provides a more consistent view of resource usage across all managed services.

**L5** — **iptables:** The older firewall framework that uses Netfilter hooks to filter packets based on chains (INPUT, OUTPUT, FORWARD). It is powerful but can become complex and verbose for large rule sets.
**nftables:** The modern replacement for iptables. It uses a unified expression language, is more flexible, and is designed to handle complex packet matching and state management more efficiently.
The kernel handles both simultaneously because both are implemented within the Linux **Netfilter** framework. While `nftables` is the modern implementation path, the kernel maintains compatibility layers to allow older `iptables` commands to function by translating them into `nftables` rules internally.

**L6** — The most likely cause is that the filesystem usage reported by `df -h` includes space reserved for **metadata, journal files, or deleted files** that have not yet been fully reclaimed by the filesystem driver. `du -sh /*` only sums the actual data blocks used by files and directories, not the overhead managed by the filesystem itself.

**L7** — 1. **UEFI Firmware:** Initializes hardware and locates the bootloader.
2. **Bootloader (e.g., GRUB):** Loads the Linux kernel image and the initial RAM disk (`initramfs`) into memory.
3. **Kernel:** Takes control, initializes drivers, and mounts the `initramfs`. The kernel's primary job is to prepare the environment.
4. **Initramfs:** A minimal, temporary root filesystem containing necessary drivers and scripts to mount the actual root filesystem.
5. **Root Filesystem Mount:** The kernel mounts the real root partition (e.g., `/dev/sda1`).
6. **Systemd:** Systemd (PID 1) is executed. It takes over as the init system, reads configuration, and sequentially starts all required services and targets (e.g., networking, logging, SSH) until the system reaches a fully operational state.

**L8** — Available memory is the amount of memory immediately available for new processes without needing to reclaim cache or swap. Even if 15GB is in `buff/cache`, the kernel might need contiguous physical pages for a new process, and if the system is under heavy pressure, it may not be able to satisfy this request immediately.
The OOM killer fires when the kernel determines that the system is critically low on memory and must terminate a process to free up resources.
Kernel tunables affecting this include:
*   `vm.swappiness`: Controls the kernel's tendency to swap out anonymous memory. Lower values keep more data in RAM.
*   `vm.vfs_cache_pressure`: Controls how aggressively the kernel reclaims memory used for directory and inode caches.

**L9** — `ip netns` is used to manage **network namespaces**. A network namespace provides an isolated view of the network stack (including interfaces, routing tables, firewall rules, and sockets) for a specific process or group of processes.
Container runtimes (like Docker or Kubernetes) use network namespaces to give each container its own isolated network environment. When a container starts, the runtime places it into a new network namespace, ensuring that its network configuration is independent of the host system's configuration.

**L10** — **SIGTERM (Signal 15):** The standard, graceful termination signal. It requests the process to shut down, allowing it time to clean up resources, save state, and exit cleanly. It is **catchable**.
**SIGKILL (Signal 9):** The immediate, forceful termination signal. The kernel kills the process instantly without giving it a chance to clean up. It is **uncatchable**.
**SIGQUIT (Signal 3):** Requests the process to quit and typically generates a core dump file containing memory state for debugging. It is **catchable**.

**L11** — **STDOUT (Standard Output, FD 1):** The primary stream for normal program output.
**STDERR (Standard Error, FD 2):** The stream reserved for error messages and diagnostic output.
**STDIN (Standard Input, FD 0):** The stream from which a program reads input (usually the keyboard).
To redirect stderr to a file while displaying stdout on the terminal:
`command 2> error.log` (This redirects file descriptor 2 to the specified file, leaving FD 1 untouched).

**L12** — `chmod 755 filename` sets the file permissions:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = rwx. The owner has full permissions.
*   **5 (Group):** Read (4) + Execute (1) = r-x. The group has read and execute permissions.
*   **5 (Others):** Read (4) + Execute (1) = r-x. All other users have read and execute permissions.

**L13** — **Root User:** The superuser (UID 0) has absolute, unrestricted access to the entire operating system. It can read, write, modify, or delete any file, change any configuration, and manage all processes.
**Sudo Privileges:** A standard user with `sudo` privileges can execute specific commands as the root user, but this access is controlled and audited via the `/etc/sudoers` file. The user cannot arbitrarily change system configurations or access files outside the scope defined by their `sudoers` entry.

**L14** — A **Package Manager** is a system utility that automates the process of installing, upgrading, configuring, and removing software packages while automatically resolving and managing dependencies between those packages.
*   **Debian/Ubuntu:** APT (Advanced Package Tool) or dpkg.
*   **RHEL/Fedora:** DNF (Dandified YUM) or YUM.

**L15** — The `/etc/fstab` (File System Table) file defines how disk partitions, network shares, and other filesystems should be mounted automatically when the system boots up.
If an entry is misconfigured (e.g., incorrect UUID, wrong mount point, or invalid filesystem type), the system may fail to mount that specific filesystem during boot, potentially leading to a partial boot or a complete failure if the misconfigured entry is critical (like the root filesystem).

**L16** — **LVM (Logical Volume Manager):** A storage management layer that abstracts physical storage devices into flexible, manageable logical volumes.
*   **Physical Volume (PV):** A physical disk partition or entire disk that LVM uses as raw storage.
*   **Volume Group (VG):** A pool of one or more PVs. It aggregates the physical space into a single, large storage pool.
*   **Logical Volume (LV):** The usable, flexible partition carved out of the VG.
To extend an LV on a running system:
1. Extend the underlying VG by adding more PVs (if available).
2. Extend the LV using `lvextend -L +XG /dev/vg_name/lv_name` (where XG is the desired size increase).
3. Resize the filesystem on the LV using `resize2fs /dev/vg_name/lv_name` (or `xfs_growfs` for XFS).

**L17** — The I/O scheduler manages the queue of read/write requests destined for a block device, deciding the order in which these requests are sent to the physical hardware to optimize throughput and latency.
*   **mq-deadline:** Prioritizes requests based on deadlines, aiming to prevent starvation and ensure low latency for time-sensitive operations.
*   **bfq (Budget Fair Queueing):** Designed for interactive workloads (like desktop use). It aims for fairness, ensuring that no single process monopolizes the disk bandwidth, providing consistent latency for all processes.
*   **none:** Passes I/O requests directly to the device driver without reordering. This is best for modern, high-performance storage like NVMe, where the device controller handles scheduling efficiently.
To change the scheduler at runtime: `echo bfq > /sys/block/sdX/queue/scheduler` (where sdX is the target block device).

**L18** — **Load Average:** Measures the average number of processes that are either currently running on a CPU or are in an uninterruptible sleep state (waiting for I/O). It is a measure of system utilization and contention, not just CPU usage.
High I/O wait inflates the load average because processes waiting for disk operations are counted as "running" or "in process state" by the kernel, even though they are blocked.
**Diagnosis:**
*   **CPU Bottleneck:** High `%us` (user) and `%sy` (system) in `top`, low `%wa`.
*   **Disk Bottleneck:** High `%wa` (I/O wait) in `top`, high utilization and high `await` times in `iostat`.
*   **Network Bottleneck:** High queue depth or packet drops visible via `netstat` or `ss` on network interfaces.

**L19** — SELinux enforces **Mandatory Access Control (MAC)** by assigning security contexts (labels) to every subject (process) and object (file, port, socket). Access is only granted if the policy explicitly permits the interaction between the subject's context and the object's context.
*   **Enforcing Mode:** SELinux actively denies access based on policy violations.
*   **Permissive Mode:** SELinux logs all policy violations but allows the action to proceed. This is used for auditing.
*   **Disabled Mode:** SELinux is inactive, and access is governed only by traditional DAC (Discretionary Access Control, i.e., standard Linux permissions).
To troubleshoot a daemon failing to bind a non-standard port: Check the audit logs (`/var/log/audit/audit.log`) for a `denial` message related to the port. Then, use `semanage port -a -t http_port_t 8080` to explicitly tell SELinux that the daemon is allowed to use that port type.

**L20** — A **Page Fault** occurs when a process attempts to access a virtual memory address whose corresponding physical page is not currently mapped in RAM.
*   **Minor Page Fault:** The page is not in RAM, but the kernel can resolve the fault by updating the page table entries (e.g., marking a page as dirty or mapping it from shared memory) without needing to load data from disk.
*   **Major Page Fault:** The page must be loaded from secondary storage (disk or swap space) into physical RAM. This is a slow, blocking operation.
**Transparent Huge Pages (THP):** THP attempts to improve performance by automatically merging small, standard 4KB memory pages into larger 2MB or 1GB pages. This reduces the overhead of the Translation Lookaside Buffer (TLB) misses. You would disable THP if your application has highly random memory access patterns or if you require strict, predictable memory allocation, as THP's background compaction can introduce unpredictable latency spikes.
