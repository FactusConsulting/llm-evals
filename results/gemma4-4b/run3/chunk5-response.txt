**DN1**
The difference is that a `class` is a reference type (allocated on the heap, managed by GC) and can inherit from other classes. A `struct` is a value type (allocated on the stack or inline within containing types) and is designed for small, immutable data structures. You should use a `struct` when the type represents a small, lightweight value (e.g., a point, color, or coordinate) and when copying the value is cheap and desirable, avoiding heap allocation overhead.

**DN2**
`IEnumerable<T>` represents a sequence that can be iterated over. It only knows *how* to iterate; it does not know *where* the data comes from or how to query it. `IQueryable<T>` represents an expression tree that describes a query. This distinction matters because when using `IEnumerable<T>`, the entire dataset is pulled into memory and processed by the application code (client-side evaluation). When using `IQueryable<T>`, the query expression is translated into a database-specific language (like SQL) and executed on the database server (server-side evaluation), which is vastly more efficient for large datasets.

**DN3**
`async/await` allows asynchronous code to be written in a synchronous-looking style. When an `await` keyword is encountered, the method execution is suspended, control is returned to the caller, and the thread is released back to the thread pool until the awaited operation completes. The continuation (the code after `await`) is then scheduled to run.
A `Task` represents an asynchronous operation that might involve I/O or CPU work and is generally used for operations that might be awaited multiple times or are long-running. A `ValueTask<T>` is a struct that can represent either a completed result immediately or a pending `Task<T>`. You should use `ValueTask<T>` when the operation is frequently completed synchronously (i.e., the result is available immediately), as it avoids the heap allocation overhead associated with creating a `Task` object when the result is ready instantly.

**DN4**
Dependency Injection (DI) is a design pattern where components receive their dependencies from an external source (the DI container) rather than creating them internally. This promotes loose coupling, testability, and modularity.
The lifetimes are:
1. **Transient:** A new instance is created every single time it is requested.
2. **Scoped:** A single instance is created per scope (typically per HTTP request in ASP.NET Core).
3. **Singleton:** A single instance is created for the entire application lifetime.
A common bug when injecting a Scoped service into a Singleton is that the Singleton holds a reference to the Scoped service. Since the Singleton lives for the entire application lifetime, it effectively keeps the Scoped service alive for the entire application lifetime, violating the intended request-scoped lifecycle and potentially leading to resource leaks or unexpected state sharing across different requests.

**DN5**
`string` is an immutable reference type in C#. Any modification creates a new string object on the heap. `ReadOnlySpan<char>` is a stack-allocated, type-safe view over a contiguous block of memory (like a string's underlying character array).
You use `Span<T>` (or `ReadOnlySpan<T>`) when you need to process large amounts of data without allocating new memory for substrings or slices. It allows for zero-copy operations, significantly improving performance by operating directly on the existing memory buffer.

**DN6**
The .NET GC is a generational, tracing garbage collector. It periodically scans memory to identify and reclaim objects that are no longer reachable by the application.
*   **Gen 0:** Where short-lived objects are allocated. Collections here are frequent and fast.
*   **Gen 1:** Acts as a buffer between Gen 0 and Gen 2. Objects surviving Gen 0 collections are promoted here.
*   **Gen 2:** Where long-lived objects reside. Collections here are less frequent but more expensive.
The **Large Object Heap (LOH)** is a separate area for objects larger than a threshold (typically 85KB). Objects in the LOH are generally not compacted, which can lead to memory fragmentation.
`IDisposable` is an interface that signals that an object holds unmanaged resources (like file handles, network sockets, or database connections) that the GC cannot automatically clean up. You need it because the GC only manages managed memory; `IDisposable` allows the developer to explicitly release these external resources via the `Dispose()` method, typically using a `using` statement.

**DN7**
`ConfigureAwait(false)` tells the runtime that the continuation of the asynchronous method does not need to resume on the original synchronization context.
**When to use it:** When writing library code or infrastructure components where you do not need to interact with UI elements or context-specific state (e.g., in a background service or API library). This prevents deadlocks and improves performance by avoiding the overhead of capturing and restoring the context.
**When NOT to use it:** When writing UI code (WPF, WinForms, etc.) where the continuation *must* resume on the UI thread to safely update the UI.
This relates to the **SynchronizationContext**, which captures the context (like the UI thread context) when an `await` occurs. If `ConfigureAwait(false)` is used, the context capture is bypassed, allowing the continuation to run on any available thread pool thread.

**DN8**
**Primary Constructors:** Allow parameters to be defined directly in the class/struct declaration, which are automatically used to initialize properties or fields.
**Collection Expressions:** Provide a concise syntax (`[...]`, `{...}`) for creating collections, simplifying initialization.
**FrozenDictionary:** A dictionary whose contents cannot be changed after creation, providing thread-safe, immutable lookups.

*Minimal Example (Primary Constructor with DI):*
```csharp
// Service definition
public record Configuration(int TimeoutMs, string Endpoint) : IOptions { }

// Consumer class using primary constructor
public class Worker(IOptions<Configuration> config)
{
    public void Run()
    {
        Console.WriteLine($"Connecting to {config.Value.Endpoint} with timeout {config.Value.TimeoutMs}ms.");
    }
}

// In Program.cs (DI setup)
builder.Services.Configure<Configuration>(options =>
{
    options.TimeoutMs = 5000;
    options.Endpoint = "https://api.example.com";
});
builder.Services.AddTransient<Worker>();
```

**DN9**
The likely cause is that the `DbContext` instance is being shared across multiple concurrent requests or threads, violating its intended request-scoped lifetime. EF Core's `DbContext` is *not* thread-safe and is designed to be scoped to a single unit of work (usually one HTTP request). Under high concurrency, multiple threads attempt to use the same context instance simultaneously, leading to race conditions, state corruption, and eventually `ObjectDisposedException` when one thread prematurely closes or disposes the context.
**The fix** is to ensure that the `DbContext` is registered with a **Scoped** lifetime in the DI container, guaranteeing that a fresh, isolated instance is provided for every incoming HTTP request.

**DN10**
**Class:** A reference type. It is mutable by default and is designed for modeling complex entities that require inheritance and identity.
**Record:** A reference type introduced in C# 9 designed for modeling immutable data carriers (DTOs). Records automatically provide value-based equality (two records are equal if all their properties are equal, regardless of memory address) and offer concise syntax for immutability.
**Record Struct:** A value type that inherits the value-based equality semantics of a record while maintaining the stack/value semantics of a struct.
**Choice:** Use a `class` when identity matters (e.g., a database entity with a primary key) or when you need complex inheritance. Use a `record` when you are modeling data transfer objects (DTOs) where equality based on content is paramount. Use a `record struct` for small, immutable value types that benefit from stack allocation.

**DN11**
*   **`ref`:** Passes a reference to an existing variable. The variable must be initialized before the method call, and the method can modify it. Used when you need to pass a variable by reference for efficiency or modification.
*   **`out`:** Passes a reference to a variable that the method *must* assign a value to before returning. The variable does not need to be initialized before the method call. Used when the method is expected to return multiple values via parameters.
*   **`in`:** Passes a reference to a variable, but the method is guaranteed *not* to modify it. This is used for performance optimization when passing large structs, allowing the method to read the data without copying it, while enforcing immutability at the call site.

**DN12**
**Nullable Reference Types (NRTs):** Enabled by `#nullable enable`. The `?` annotation (e.g., `string?`) tells the compiler that a reference type variable *might* hold `null`. The compiler then enforces null checks, preventing potential `NullReferenceException`s at compile time.
**Nullable Value Types:** (e.g., `int?`, `DateTime?`). These are structs that wrap a value type and explicitly allow the value to be `null`. They are distinct from NRTs because they are value types that can hold a null state.

**DN13**
**LINQ (Language Integrated Query):** A set of features in C# that allows developers to write queries against various data sources (collections, databases, XML) using a unified syntax.
**Method Syntax:** Uses extension methods on the collection (`list.Where(x => x.Age > 30).Select(x => x.Name)`). This is generally preferred for its functional programming style and chaining capability.
**Query Syntax:** Uses SQL-like syntax (`from x in list where x.Age > 30 select x.Name`). This is often preferred for readability when the query logic is complex or resembles SQL.
**Deferred Execution:** The query is not executed immediately when it is defined. Instead, the query is compiled into an expression tree, and the execution only occurs when the results are iterated over (e.g., in a `foreach` loop or by calling `.ToList()`).

**DN14**
Generic constraints restrict the types that can be used when instantiating a generic type.
*   `where T : class`: T must be a reference type (a class or interface).
*   `where T : struct`: T must be a value type (a struct).
*   `where T : new()`: T must have a public parameterless constructor.
*   `where T : IComparable<T>`: T must implement the `IComparable<T>` interface, allowing comparisons between instances of T.
You combine constraints when the generic type needs to satisfy multiple requirements simultaneously (e.g., `where T : class, new(), IComparable<T>`).

**DN15**
**Abstract Class:** A class that cannot be instantiated directly. It can contain both implemented methods and abstract methods (methods without a body) that derived classes *must* implement. It supports state (fields) and inheritance hierarchy.
**Interface:** A contract that defines a set of methods and properties that implementing classes *must* adhere to. It defines *what* a class can do, not *how* it does it.
**Default Interface Methods (C# 8+):** This feature allows interfaces to contain method implementations. This blurs the line because an interface can now provide default behavior, making it easier to evolve interfaces without breaking existing implementations, but it does not change the fundamental distinction: an abstract class provides implementation *and* structure, while an interface provides only a contract.

**DN16**
The middleware pipeline is a series of software components (middleware) that process HTTP requests and responses sequentially as they pass through the ASP.NET Core application. Each middleware component can inspect, modify, or short-circuit the request/response cycle.
*   **`app.Use()`:** Registers middleware that processes the request/response flow (e.g., Authentication, Routing, CORS). It typically calls `next()` to pass control to the next component.
*   **`app.Map()`:** Maps a specific path or set of paths to a handler (endpoint). It is used to define routes and often terminates the pipeline for that specific route.
*   **`app.Run()`:** Terminates the pipeline. It is typically used as the final middleware, often to serve static files or handle the final request if no other middleware has handled it.
**Ordering matters** because the pipeline is sequential; the first middleware to handle the request dictates the outcome. Exception handling middleware must be placed early in the pipeline to catch errors from subsequent components.

**DN17**
`Channel<T>` is a type-safe, asynchronous stream provided by `System.Threading.Channels`. It is designed for producer-consumer scenarios, allowing multiple producers to write data and multiple consumers to read data asynchronously.
**Comparison to `BlockingCollection<T>`:** `BlockingCollection<T>` is a thread-safe collection designed for synchronous blocking operations (threads wait until data is available). `Channel<T>` is inherently asynchronous, designed to work seamlessly with `async/await` and non-blocking I/O.
**Bounded Channel Example (Backpressure):** A bounded channel has a fixed capacity. If producers write data faster than consumers can read it, the channel fills up. When full, the producer attempting to write will asynchronously await until space becomes available, naturally applying backpressure to slow down the producer.

**DN18**
**Source Generators:** A compile-time feature in .NET that allows developers to write code that generates other source code during the compilation process. This generated code is then compiled alongside the original code.
**Difference from Reflection/IL Weaving:**
*   **Reflection:** Inspects metadata at *runtime* to discover types and members. It is slow and incurs runtime overhead.
*   **IL Weaving:** Modifies the Intermediate Language (IL) of an assembly *after* compilation but *before* runtime. It is powerful but complex and often requires specialized tooling.
*   **Source Generators:** Generate *actual C# source code* before compilation, allowing the compiler to process it normally. This is fast, type-safe, and avoids runtime overhead.
An **incremental generator** is preferred because it only regenerates the source code files that are affected by changes in the input code, rather than regenerating everything, drastically speeding up the build time.

**DN19**
**TPL Dataflow:** A library providing building blocks (blocks) for creating asynchronous, data-flow pipelines.
*   **`ActionBlock`:** Executes an action (a side effect) on each incoming message concurrently or sequentially. It is used when the primary goal is to perform an operation on data without needing to pass the result downstream.
*   **`TransformBlock`:** Executes a transformation function on each incoming message and passes the result to the next block in the pipeline. It is used for data processing stages.
*   **`BufferBlock`:** Acts as a queue, buffering incoming messages until a consumer is ready to process them.
**Comparison to Channels:** Channels are a simpler, more direct asynchronous queue/stream mechanism. Dataflow is a more complex, structured framework for building multi-stage, complex processing pipelines where data flows through distinct, specialized processing blocks.

**DN20**
**Minimal APIs:** A lightweight, streamlined way to build HTTP endpoints directly in the `Program.cs` file using lambda expressions and minimal boilerplate, contrasting with the traditional MVC/Controller pattern.
**Differences from Controllers:** Controllers require classes, explicit routing attributes, and boilerplate setup. Minimal APIs are function-based, reducing boilerplate significantly.
**Trade-offs:**
*   **Testability:** Minimal APIs can be slightly harder to unit test in isolation compared to traditional controllers, as they are tightly coupled to the host builder setup.
*   **Middleware:** Both support middleware, but the structure in Minimal APIs is often more implicit.
*   **OpenAPI Support:** Both can support OpenAPI, but Minimal APIs require explicit configuration or use of specialized libraries to generate robust documentation compared to the convention-based approach of controllers.
**Route Groups and Endpoint Filters:** Route groups allow grouping related endpoints under a common prefix or set of middleware. Endpoint filters allow you to inject logic (like authorization checks or logging) that executes before or after the endpoint handler runs, without cluttering the handler method itself.

**P1**
**List:** A mutable, ordered sequence of items. Items can be added, removed, or changed. Lists are implemented using dynamic arrays.
**Tuple:** An immutable, ordered collection of items. Once created, its contents cannot be changed. Tuples are often used to return multiple values from a function.
**Set:** An unordered collection of unique, immutable items. It is optimized for fast membership testing (checking if an item exists).
**Frozenset:** An immutable version of a set. Because it is immutable, it can be used as an element within another set or as a dictionary key.

**P2**
The **Global Interpreter Lock (GIL)** is a mutex that protects access to Python objects, ensuring that only one thread executes Python bytecode at any given time, even on multi-core processors.
**Workloads Affected:** It severely limits the performance of CPU-bound tasks (heavy computation) because threads cannot run truly in parallel.
**Workarounds:**
1.  **Multiprocessing:** Using the `multiprocessing` module spawns separate OS processes, each with its own Python interpreter and memory space, bypassing the GIL. This is ideal for CPU-bound tasks.
2.  **Threading for I/O:** For I/O-bound tasks (network requests, disk reads), the GIL is released while waiting for external operations, allowing other threads to run, making threading effective for concurrency, even if not true parallelism.

**P3**
**Shallow Copy:** Creates a new container object, but populates it with *references* to the objects contained in the original. If the original object contains mutable objects (like lists), modifying those nested objects in the copy will also affect the original.
**Deep Copy:** Creates a completely independent copy of the original object and recursively copies all nested objects.
**Example of Shallow Copy Failure:**
```python
original = {'data': [1, 2]}
shallow = original.copy() # Shallow copy
shallow['data'].append(3)
print(original['data']) # Output: [1, 2, 3] -> Original was modified!
```
A deep copy would ensure `original['data']` remains `[1, 2]`.

**P4**
Decorators are syntactic sugar in Python that allow you to wrap a function or class, modifying its behavior without permanently altering its source code. They are essentially functions that take another function as an argument and return a new, enhanced function.
*Example Decorator:*
```python
import time
from functools import wraps

def timing_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"Function {func.__name__} executed in {end_time - start_time:.4f} seconds.")
        return result
    return wrapper

@timing_decorator
def heavy_computation(n):
    sum(i*i for i in range(n))

heavy_computation(100000)
```

**P5**
**Generators and `yield`:** A generator function uses `yield` instead of `return`. When `yield` is encountered, the function pauses its execution, returns the yielded value, and saves its entire local state. When the next value is requested (e.g., in a `for` loop), execution resumes exactly where it left off. This allows generators to produce an arbitrary sequence of values lazily, one at a time, without storing the entire sequence in memory.
**Difference from Returning a List:** Returning a list computes and stores *all* values in memory immediately. Generators compute values *on demand*, making them highly memory-efficient for infinite or very large sequences.
**`yield from`:** This delegates iteration to a sub-generator or iterable. It allows a generator to seamlessly pass values through from one generator to another, simplifying the chaining of generators.

**P6**
The **asyncio event loop** is the core mechanism in Python's asynchronous programming. It is a single-threaded loop that manages and schedules the execution of asynchronous tasks. When an `await` call is made, the coroutine yields control back to the event loop, which then runs other ready tasks until the awaited operation completes, at which point the original coroutine is resumed.
*   **`asyncio.run(coro)`:** Runs the top-level coroutine and manages the event loop lifecycle (starts, runs, and closes the loop).
*   **`asyncio.gather(*coros)`:** Runs multiple awaitables concurrently and waits for all of them to complete, returning a list of their results.
*   **`asyncio.create_task(coro)`:** Schedules a coroutine to run concurrently on the event loop immediately, returning a `Task` object that can be awaited later.
**Why `time.sleep()` fails:** `time.sleep()` is a *blocking* call. When called inside an `async` function, it blocks the entire thread, halting the event loop. Since the event loop is single-threaded, blocking it prevents *any* other scheduled coroutines from running, defeating the purpose of asynchronous programming. You must use `await asyncio.sleep(delay)` instead, which yields control back to the loop.

**P7**
**MRO (Method Resolution Order):** The algorithm Python uses to determine the order in which base classes are searched when looking for a method or attribute.
**Algorithm:** Python 3 uses the **C3 Linearization Algorithm**. This algorithm ensures a consistent, predictable, and monotonic ordering of inheritance, resolving the ambiguity of diamond inheritance.
**Diamond Inheritance:** When a class inherits from two classes that share a common ancestor (like D inheriting from B and C, both inheriting from A), C3 ensures that the common ancestor (A) is searched only once, and the order of inheritance is respected.
**Output Explanation:** The MRO for `D` is `(D, B, C, A, object)`. When `D().who()` is called, Python searches D (not found), then B (not found), then C (found), and executes C's `who` method, returning "C".

**P8**
**Metaclass:** A "class of a class." It is the mechanism that controls how a class itself is created. When you define a class, Python uses its metaclass to construct the class object.
**`__init_subclass__` vs Metaclass:**
*   **`__init_subclass__`:** A class method available since Python 3.6. It is used to perform setup or modification *after* a subclass has been created but *before* it is fully initialized. It is simpler and preferred for simple subclass modifications.
*   **Metaclass:** Used to fundamentally alter the class creation process itself. It intercepts the creation of the class object, allowing you to inject methods, modify attributes, or enforce complex structural rules *during* the class definition phase.
**Use Cases:**
*   **`__init_subclass__`:** Automatically adding logging or validation hooks to all subclasses of a base class (e.g., ensuring all subclasses implement a specific method).
*   **Metaclass:** Creating an ORM or a framework where the structure of the class itself must be dynamically generated or validated based on complex rules (e.g., automatically registering all subclasses with a central registry).

**P9**
*   **Threading:** Uses threads within a single process. Best for I/O-bound tasks where the GIL can be released during waiting periods. Threads share the same memory space.
*   **Multiprocessing:** Uses separate OS processes. Bypasses the GIL, allowing true parallel execution on multiple CPU cores. Best for CPU-bound tasks.
*   **`concurrent.futures`:** A high-level interface that abstracts away the complexity of managing threads or processes. It provides `ThreadPoolExecutor` (for I/O) and `ProcessPoolExecutor` (for CPU).
**When to Use Each:** I/O-bound $\rightarrow$ Threading/ThreadPoolExecutor. CPU-bound $\rightarrow$ Multiprocessing/ProcessPoolExecutor. General concurrency $\rightarrow$ `concurrent.futures`.
**Serialization Implications:** Multiprocessing requires **pickling** (serialization) to pass objects between separate processes. This process can be slow and requires that all objects passed between processes are picklable.

**P10**
`__slots__` is a class attribute that tells Python not to use a dynamic dictionary (`__dict__`) to store instance attributes. Instead, it reserves a fixed, predefined set of slots for attributes.
**When to Use:** When creating classes that are instantiated millions of times, especially in memory-constrained environments, or when you need to enforce a fixed structure on an object.
**What it Prevents:** It prevents the creation of the instance `__dict__`, which is the standard mechanism Python uses to store arbitrary attributes dynamically.
**Memory Impact:** It significantly reduces memory consumption per instance because it avoids the overhead of the dictionary structure for every object.

**P11**
A **virtual environment** is an isolated directory that contains a specific Python interpreter and its own set of installed packages.
**Why Use:** It prevents dependency conflicts between different projects. Project A might require Django 2.0, while Project B requires Django 4.0. Using separate environments ensures that installing a package for Project A does not break Project B.
**Differences:**
*   **`venv`:** The standard, built-in module in Python 3.x for creating lightweight virtual environments.
*   **`virtualenv`:** An older, more feature-rich third-party tool that predates `venv`. It is often used for compatibility or advanced features.
*   **`conda`:** A comprehensive package and environment manager (often used in data science). It manages not just Python packages but also non-Python dependencies (like specific versions of NumPy or compilers), making it broader than standard Python virtual environments.

**P12**
**List Comprehension:** `[expression for item in iterable if condition]` (Creates a list).
**Dict Comprehension:** `{key: value for item in iterable if condition}` (Creates a dictionary).
**Set Comprehension:** `{expression for item in iterable if condition}` (Creates a set).
**Relation to `map()` and `filter()`:** Comprehensions are syntactic sugar that combine the functionality of `map()` (transformation) and `filter()` (selection) into a single, readable line.
**Preference:** Comprehensions are generally preferred over `map()`/`filter()` because they are more concise and Pythonic. They are often faster and easier to read, especially when combining filtering and mapping in one step.

**P13**
**`==` vs `is`:**
*   `==` checks for **equality** (Do the objects have the same value?).
*   `is` checks for **identity** (Are both variables pointing to the exact same object in memory?).
**Object Interning:** Python pre-allocates and caches certain immutable objects (like small integers, e.g., -5 to 256, and short strings) to save memory and speed up lookups.
**Why `a is b` returns True:** When you write `a = 100` and `b = 100`, Python often reuses the same object ID for both variables because 100 falls within the interned range, meaning they point to the same memory location.

**P14**
**`*args`:** Collects an arbitrary number of positional arguments into a tuple.
**`**kwargs`:** Collects an arbitrary number of keyword arguments into a dictionary.
**Positional-Only (`/`):** Arguments placed before `/` must be passed by position and cannot be passed using a keyword name.
**Keyword-Only (`*`):** Arguments placed after `*` must be passed using a keyword name; positional arguments are not allowed after this marker.
*Example:* `def func(a, b, /, c, *, d):` requires `a` and `b` positionally, `c` positionally or by keyword, and `d` *must* be by keyword.

**P15**
**Context Managers (`with` statement):** A mechanism that ensures setup actions are performed before a block of code runs, and guaranteed cleanup actions are performed afterward, even if errors occur within the block.
**`__enter__` / `__exit__`:** This is the class-based implementation. `__enter__` runs upon entering the `with` block and returns the resource. `__exit__` runs upon exiting, receiving exception details if one occurred.
**`@contextmanager`:** A simpler, generator-based implementation from the `contextlib` module. The code before `yield` is setup; the code after `yield` is cleanup.
**Example beyond file handling:** Database connection management.
```python
from contextlib import contextmanager
@contextmanager
def get_db_connection():
    conn = connect_to_db() # Setup
    try:
        yield conn # Execution block
    finally:
        conn.close() # Cleanup
```

**P16**
**Type Hinting:** The practice of adding optional type annotations to variables, function parameters, and return values in Python. It does not change runtime behavior but allows static analysis tools to check for type errors before execution.
*   **`typing.Union[A, B]`:** Indicates a variable can be of type A OR type B.
*   **`Optional[T]`:** A shorthand for `Union[T, None]`, indicating the variable can be T or None.
*   **`Literal[value]`:** Restricts a variable to only accept a specific, fixed set of literal values (e.g., `Literal["read", "write"]`).
*   **`TypeVar`:** A placeholder for types that will be specified later, used to create generic functions or classes (like `T` in C# generics).
*   **`Protocol`:** Defines a structural type. Instead of inheriting from a class, a class conforms to a `Protocol` if it implements the required methods/attributes, enabling structural subtyping.
**Static Analysis:** Tools like Mypy or Pyright read these hints and build a type graph of the code. They then traverse this graph, flagging potential type mismatches (e.g., trying to call a string method on an integer variable) before the code ever runs.

**P17**
**Data Model (Dunder Methods):** These are special "dunder" (double underscore) methods (e.g., `__init__`, `__str__`) that Python calls automatically when specific operations are performed on an object.
*   **`__repr__` vs `__str__`:** `__repr__` (representation) should return an unambiguous string that ideally allows the object to be recreated (e.g., `ClassName(arg1=value1)`). `__str__` (string) should return a readable, user-friendly string.
*   **`__eq__` vs `__hash__`:** `__eq__` defines when two objects are considered equal. `__hash__` generates an integer hash value for the object.
*   **`__getattr__` vs `__getattribute__`:** `__getattr__` is called only when a requested attribute is *not* found normally. `__getattribute__` is called for *every* attribute access, making it powerful but dangerous if not implemented carefully.
**If you define `__eq__` but not `__hash__`:** Python will raise a `TypeError` if you try to use that object in a set or as a dictionary key, because the hashing mechanism relies on the equality definition. If two objects are equal (`__eq__` returns True), they *must* have the same hash value.

**P18**
**Descriptors:** Objects that define how attribute access (getting, setting, deleting) works for another object. They implement the descriptor protocol.
**Descriptor Protocol:** A descriptor object must implement one or more of these methods:
*   `__get__(self, instance, owner)`: Called when the attribute is accessed.
*   `__set__(self, instance, value)`: Called when the attribute is assigned a value.
*   `__delete__(self, instance)`: Called when the attribute is deleted.
**How Built-ins Use Them:**
*   **`property`:** Uses descriptors to allow controlled access to attributes (getters, setters, deleters).
*   **`classmethod`:** Uses descriptors to ensure the method is bound to the class, not the instance.
*   **`staticmethod`:** Uses descriptors to ensure the method is bound neither to the class nor the instance, acting as a regular function within the class namespace.

**P19**
**Import System:** Python uses a sophisticated system to locate and load modules. When `import module_name` is called, Python searches paths defined in `sys.path`.
**Relative vs Absolute Imports:**
*   **Absolute:** Imports start from the root of the package (e.g., `from my_package import module`).
*   **Relative:** Imports reference modules relative to the current package (e.g., `from . import sibling_module` or `from ..parent import module`).
**Components:**
*   **`sys.path`:** A list of strings that specifies the search path for modules.
*   **`PYTHONPATH`:** An environment variable that adds directories to `sys.path` before the script runs.
*   **`__init__.py`:** Historically, this file marked a directory as a Python package, allowing imports from it. (In modern Python 3.3+, namespace packages can exist without it).
*   **Namespace Packages:** Allow multiple, unrelated packages to contribute to the same top-level package name, often used in large distributed systems.
**Finder and Loader:** A **Finder** is responsible for locating a module (finding the correct path). A **Loader** is responsible for loading the module object once the path has been found.

**P20**
**Dataclasses:** A decorator (`@dataclass`) that automatically generates boilerplate methods (like `__init__`, `__repr__`, `__eq__`) for classes primarily used to hold data.
**Comparison:**
*   **`attrs`:** A library that achieves similar goals to dataclasses but offers more flexibility and was the predecessor.
*   **Pydantic:** A data validation and settings management library. It uses type hints to *validate* incoming data (e.g., ensuring a string field is actually a valid email format) and automatically handles serialization/deserialization (JSON).
**Features:**
*   **`__post_init__`:** A method called immediately after the standard `__init__` method runs, allowing for custom initialization logic based on the provided fields.
*   **Field Factories:** Allows defining default values that are calculated dynamically rather than being static constants.
*   **Frozen Dataclasses:** Setting `frozen=True` makes the instance immutable, similar to a `dataclass` record in C#.
*   **Inheritance:** Dataclasses support inheritance, but care must be taken regarding how generated methods interact across the hierarchy.
**When to choose Pydantic:** Choose Pydantic when the data structure needs to be validated, coerced, or serialized/deserialized from external sources (like API payloads or configuration files). Choose dataclasses when you primarily need a simple, lightweight, immutable container for internal application state.
