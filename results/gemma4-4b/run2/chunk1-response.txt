**N1**
A Layer 2 switch operates at the Data Link Layer (Layer 2) and uses MAC addresses to forward frames within the same broadcast domain (VLAN). A Layer 3 switch operates at the Network Layer (Layer 3) and uses IP addresses to route packets between different subnets/VLANs. Essentially, a Layer 3 switch has routing capabilities built-in, allowing it to perform inter-VLAN routing efficiently in hardware.

**N2**
The subnet mask for /20 is $255.255.240.0$.
*   **Network Address:** $10.0.32.0$ (The first address in the range).
*   **Broadcast Address:** $10.0.47.255$ (The last address in the range).

**N3**
The TCP three-way handshake establishes a reliable connection:
1.  **SYN (Synchronize):** Client sends a segment to the server with the SYN flag set, proposing an initial sequence number (ISN).
2.  **SYN-ACK (Synchronize-Acknowledge):** Server receives the SYN, allocates resources, and replies with a segment having both SYN and ACK flags set, acknowledging the client's ISN and proposing its own ISN.
3.  **ACK (Acknowledge):** Client receives the SYN-ACK and sends a final segment with the ACK flag set, acknowledging the server's ISN.

If the final ACK is lost, the client will retransmit the ACK (or the server will time out waiting for the final ACK and retransmit the SYN-ACK). The connection will remain in a half-open state until the retransmission timeout expires, at which point the connection attempt will fail or eventually succeed upon successful retransmission.

**N4**
*   **SNAT (Source Network Address Translation):** Translates the *source* IP address of a private internal host to a public IP address when the host initiates outbound traffic. *Example: An internal web server (192.168.1.10) accessing an external API uses the firewall's public IP as its source address.*
*   **DNAT (Destination Network Address Translation):** Translates the *destination* IP address of incoming traffic from the public internet to a private internal host. *Example: Port forwarding, where external traffic hitting the public IP on port 80 is translated to reach an internal web server at 192.168.1.10.*

**N5**
1.  **Hostname Mismatch:** The Common Name (CN) or Subject Alternative Name (SAN) listed in the certificate does not exactly match `example.com`.
2.  **Certificate Expiration/Revocation:** The certificate has expired or has been revoked by the Certificate Authority (CA).
3.  **Incorrect Chain of Trust:** The client cannot validate the certificate because the intermediate or root CA certificate is missing or untrusted on the client machine.

**N6**
*   **VLAN (Virtual Local Area Network):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains using 802.1Q tagging on trunk links. It is limited by the physical infrastructure's capacity (typically 4094 VLAN IDs).
*   **VxLAN (Virtual Extensible LAN):** A network virtualization overlay protocol that encapsulates Layer 2 Ethernet frames within UDP/IP packets. It uses a VXLAN Network Identifier (VNI) instead of a VLAN ID.

You would choose VxLAN over VLAN when you need to scale Layer 2 domains beyond the 4094 limit, or when you need to extend Layer 2 connectivity across a large, multi-subnet, or geographically dispersed IP network (i.e., over an existing L3 infrastructure).

**N7**
The traffic is being replied via eth0 because the Linux kernel uses the **FIB (Forwarding Information Base)**, which is primarily based on the routing table. Since the default gateway (10.0.0.1) is associated with eth0, the kernel determines that the return path for traffic originating from the 10.0.0.0/24 subnet must exit via eth0.

To fix this using Policy-Based Routing (PBR), you must create a routing rule that dictates traffic originating from the 192.168.1.0/24 subnet must use the interface associated with eth1 for both ingress and egress. This is typically done using `ip rule` combined with a specific routing table entry pointing to the gateway associated with eth1.

**N8**
BGP path selection is a deterministic process used to choose the best path among multiple available routes advertised by different peers. The attributes are evaluated sequentially until a single best path is selected.

The standard order of preference (simplified, focusing on the most critical attributes):
1.  **Weight** (Cisco proprietary, highest preference)
2.  **Local Preference** (Highest is preferred, used internally within an AS)
3.  **AS Path Length** (Shortest path is preferred)
4.  **Origin Type** (IGP > EGP > Incomplete)
5.  **MED (Multi-Exit Discriminator)** (Lowest is preferred, used to influence ingress traffic from external ASes)

**N9**
When running VxLAN over an IPsec tunnel, the encapsulation process adds multiple layers:
1.  Original Ethernet Frame (Inner Payload)
2.  VxLAN Header
3.  UDP Header
4.  IP Header (Outer Header)
5.  IPsec Header (ESP/AH)
6.  Outer IP Header (for the tunnel endpoint)

The physical MTU (1500 bytes) must accommodate all these headers.
*   Standard Ethernet Frame Overhead: 14 bytes (L2)
*   VxLAN/UDP/IP Overhead: $\approx 50$ bytes
*   IPsec Overhead (e.g., ESP): $\approx 50$ bytes
*   Total Overhead $\approx 114$ bytes.

Maximum Inner Payload = Physical MTU - Total Overhead
Maximum Inner Payload = $1500 - 114 = 1386$ bytes.

**N10**
ARP (Address Resolution Protocol) is used to map a known Layer 3 IP address to its corresponding Layer 2 MAC address within a local subnet. It works by broadcasting an ARP request asking, "Who has IP X.X.X.X? Tell me your MAC address."

Gratuitous ARP (GARP) is a packet sent by a host to itself (or broadcasted without a specific request). It solves the problem of stale ARP caches. When a host changes its MAC address, or when a host comes online, sending a GARP immediately updates the ARP tables of neighboring devices, preventing traffic from being sent to an old, incorrect MAC address.

**N11**
*   **Public IP Address:** An IP address globally unique and routable on the public internet. It must be assigned by an IANA-approved registry or ISP.
*   **Private IP Address:** An IP address reserved for use within private networks (LANs). These addresses are not routable on the public internet and require NAT to access external resources.

The three private IPv4 ranges (RFC 1918) are:
1.  $10.0.0.0/8$
2.  $172.16.0.0/12$
3.  $192.168.0.0/16$

**N12**
*   **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses (like `93.184.216.34`).

*   **A Record:** Maps a domain name to an IPv4 address.
*   **CNAME Record (Canonical Name):** Creates an alias, mapping one domain name to another domain name (which, in turn, points to an A record).
*   **AAAA Record:** Maps a domain name to an IPv6 address.

**N13**
*   **DHCP (Dynamic Host Configuration Protocol):** A network management protocol used to automatically assign IP configuration parameters (IP address, subnet mask, default gateway, DNS servers) to client devices on a network.

The DORA process is:
1.  **Discover:** Client broadcasts a DHCP Discover message to find available servers.
2.  **Offer:** Server responds with a DHCP Offer, proposing an IP address and configuration.
3.  **Request:** Client sends a DHCP Request, formally accepting the offered configuration.
4.  **Acknowledge:** Server sends a DHCP ACK, finalizing the lease and providing all necessary configuration details.

**N14**
*   **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming electrical signals to every connected port, creating a single collision domain.
*   **Switch:** Operates at Layer 2 (Data Link). It uses MAC addresses to intelligently forward frames only to the intended destination port, creating separate collision domains.
*   **Router:** Operates at Layer 3 (Network). It uses IP addresses to determine the best path for packets to travel between different networks (subnets).

**N15**
*   **Half-Duplex:** Allows data transmission in both directions, but only one direction at a time (e.g., a walkie-talkie). Collisions can occur if both sides transmit simultaneously.
*   **Full-Duplex:** Allows simultaneous transmission and reception of data over the same link. Collisions are eliminated.

Modern Ethernet links overwhelmingly use **full-duplex** communication.

**N16**
The TTL (Time To Live) field is an 8-bit counter in the IP header that limits the lifespan of a packet. Each router that forwards the packet decrements the TTL value by one. If the TTL reaches zero, the router discards the packet and typically sends an ICMP Time Exceeded message back to the source.

Traceroute exploits this by sending a sequence of packets with incrementally increasing TTL values (starting at 1, then 2, 3, etc.). When the TTL hits 1, the first router drops the packet and sends back an ICMP Time Exceeded message, revealing the identity of that first hop. Subsequent packets reveal subsequent hops until the destination is reached.

**N17**
A NAT gateway acts as a boundary device (usually a firewall or router) that translates private, internal IP addresses into one or more public, routable IP addresses when traffic crosses the network boundary.

*   **Static NAT:** A one-to-one, permanent mapping. A specific private IP is always mapped to a specific public IP. (Used for servers that need to be consistently reachable from the outside).
*   **Dynamic NAT:** Maps private IPs to a pool of public IPs on a first-come, first-served basis. The mapping is temporary.
*   **PAT (Port Address Translation) / NAT Overload:** Maps many private IPs to a single public IP address by utilizing unique source port numbers. This is the most common form of NAT used in homes and small offices.

**N18**
ECMP (Equal-Cost Multi-Path) routing allows a router to install multiple paths into the routing table for the same destination prefix, provided all paths have the same metric (cost). The router then distributes traffic across these paths.

Common hashing strategies include:
1.  **Source IP Address**
2.  **Destination IP Address**
3.  **Source/Destination Port Pair** (Most granular)

Asymmetric flows occur when the forward path and the return path take different routes. If a stateful firewall is involved, the firewall tracks the connection state based on the initial ingress path. If the return traffic arrives via a different path, the firewall may not recognize the return packet as part of an established session, causing it to drop the packet.

**N19**
The problem is **Bandwidth-Delay Product (BDP) limitation**. BDP = Bandwidth $\times$ Round Trip Time (RTT). If the BDP is 10MB, the pipe can theoretically hold 10MB of unacknowledged data in transit. However, if the TCP window size is capped at 64KB, the sender can only inject 64KB into the pipe before waiting for an ACK. The sender spends most of its time waiting for ACKs, leading to underutilization and high latency relative to the potential throughput.

TCP Window Scaling (RFC 1323) solves this by allowing the TCP header to negotiate a window size much larger than the standard 16-bit limit (65,535 bytes). This allows the sender to advertise a much larger receive window, enabling it to fill the entire BDP buffer and maintain high throughput.

**N20**
802.1Q trunk ports allow a single physical link to carry traffic for multiple VLANs simultaneously. The switch inserts a 4-byte **VLAN Tag** into the Ethernet frame header. This tag contains the VLAN ID (VID) and a Priority Code Point (PCP).

To configure a server with a single NIC to communicate on VLANs 10, 20, and 30 on Linux, you create **VLAN sub-interfaces** on the physical interface (e.g., `eth0`).
1.  The physical interface (`eth0`) is configured as a trunk port.
2.  Sub-interfaces are created: `eth0.10`, `eth0.20`, `eth0.30`.
3.  Each sub-interface is assigned the specific VLAN ID and the corresponding IP address for that VLAN.

On the wire, the frame format is:
[Preamble/SFD] $\rightarrow$ [Destination MAC] $\rightarrow$ [Source MAC] $\rightarrow$ **[802.1Q Tag (VID=10)]** $\rightarrow$ [EtherType] $\rightarrow$ [Payload] $\rightarrow$ [FCS].

**L1**
*   **Hard Link:** A directory entry that points directly to the same inode (the file's metadata structure) on the disk as the original file. Deleting one hard link does not delete the file data until the last hard link is removed.
*   **Symbolic Link (Symlink):** A special file that contains a text path pointing to another file or directory. It is a pointer, not a direct reference to the inode.

**L2**
`find /var/log -type f -size +100M`

**L3**
State D (Uninterruptible Sleep) means the process is waiting for an I/O operation (e.g., disk read/write) to complete. It is blocked waiting for hardware, and the kernel cannot interrupt it, even with `SIGKILL` (kill -9). Sending `kill -9` will fail or be ignored because the process is in kernel space waiting for hardware completion.

**L4**
*   **cgroups v1:** Uses a hierarchical structure with separate controllers (e.g., CPU, Memory) that manage resources independently. It is less unified and can lead to complex resource interactions.
*   **cgroups v2:** Implements a unified hierarchy where all controllers share a single hierarchy structure. It enforces stricter resource isolation and provides a more coherent view of resource usage across the entire system.

Systemd prefers cgroups v2 because it offers a more modern, unified, and robust resource management model, simplifying resource accounting and control.

**L5**
*   **iptables:** The older, traditional Linux firewall framework. It uses chains (INPUT, OUTPUT, FORWARD) and tables to process packet filtering rules.
*   **nftables:** The modern replacement for iptables. It is a unified framework that supports multiple hooks, complex expressions, and a more flexible syntax, often offering better performance.

The kernel handles both by maintaining compatibility layers. When you use `iptables`, the commands are translated by the kernel into the underlying `nftables` ruleset structure, allowing older tools to function while leveraging the modern kernel implementation.

**L6**
The most likely cause is **deleted files still held open by a running process**. When a file is deleted, the directory entry is removed, but the underlying data blocks remain allocated until the process that holds the file descriptor closes it. `du -sh /*` only measures the size of currently accessible directories, not the space occupied by these "ghost" files.

**L7**
1.  **UEFI Firmware:** Initializes hardware and locates the bootloader.
2.  **Bootloader (e.g., GRUB):** Loads the Linux kernel image and the initial RAM disk (`initramfs`) into memory.
3.  **Kernel:** Takes control. It mounts the `initramfs` (a temporary root filesystem containing necessary drivers).
4.  **Initramfs:** Executes the initial scripts, loads necessary modules (like storage drivers), and then executes the first user-space process, which is typically `systemd`.
5.  **Root Filesystem:** `systemd` mounts the actual, persistent root filesystem (`/`).
6.  **Systemd:** Takes over as PID 1. It initializes services, manages system state, and brings the entire operating system online according to defined targets (e.g., `multi-user.target`).

**L8**
Available memory is low because the kernel reserves a portion of RAM for critical operations, even if `buff/cache` is high. The kernel uses free memory for caching (buff/cache) to speed up I/O. However, when the OOM killer fires, it means the system is under memory pressure, and the kernel cannot satisfy a request for contiguous memory or a specific allocation, even if the total free memory is high.

Kernel tunables affecting this include `vm.min_free_kbytes` (the minimum amount of memory the kernel tries to keep free) and memory pressure settings within cgroups.

**L9**
`ip netns` is used to manage network namespaces. A network namespace is an isolated environment that contains its own independent view of network resources (interfaces, routing tables, firewall rules, sockets).

Container runtimes (like Docker or Kubernetes) use network namespaces to isolate the network stack of each container. Each container runs in its own namespace, meaning its network configuration is completely separate from the host's network configuration, providing strong network isolation.

**L10**
*   **SIGTERM (Signal 15):** The standard, polite termination signal. It requests the process to shut down gracefully, allowing it to clean up resources before exiting.
*   **SIGKILL (Signal 9):** The forceful, immediate termination signal. The kernel kills the process instantly; the process has no chance to clean up.
*   **SIGQUIT (Signal 3):** Requests the process to terminate and usually dump a core file for debugging.

Only **SIGTERM** and **SIGQUIT** can be caught, handled, or ignored by the process using signal handlers. SIGKILL cannot be caught or ignored.

**L11**
*   **stdin (Standard Input):** Where a program reads input from (usually the keyboard).
*   **stdout (Standard Output):** Where a program writes normal, expected output to (usually the terminal screen).
*   **stderr (Standard Error):** Where a program writes error messages and diagnostic output to (usually the terminal screen).

To redirect stderr to a file while displaying stdout on the terminal:
`command 2> error.log` (This redirects file descriptor 2, stderr, to the file).

**L12**
`chmod 755` sets permissions for the file/directory:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = 7. The owner has full control.
*   **5 (Group):** Read (4) + Execute (1) = 5. The group can read and execute.
*   **5 (Others):** Read (4) + Execute (1) = 5. All other users can read and execute.

**L13**
*   **Root User (UID 0):** Has absolute, unrestricted access to the entire operating system. It can read, write, and modify any file, change system configurations, and manage all processes.
*   **Sudo User:** A standard user who is granted specific, limited permissions via the `sudo` command. They can execute specific commands as another user (usually root) but are constrained by the rules defined in the `/etc/sudoers` file, preventing them from having blanket administrative control.

**L14**
A package manager is a system software that automates the installation, upgrading, configuration, and removal of software packages on a Linux system.

*   **Debian/Ubuntu:** APT (Advanced Package Tool) or dpkg.
*   **RHEL/Fedora:** YUM or DNF (Dandified Yum).

**L15**
`/etc/fstab` (File System Table) is a configuration file that defines how disk partitions, network shares (NFS/SMB), and other file systems should be mounted automatically at boot time.

If an entry is misconfigured (e.g., incorrect UUID, wrong mount point, or invalid filesystem type), the system will fail to mount that specific filesystem during the boot sequence. Depending on the severity, this can halt the boot process or result in the filesystem being mounted read-only or not at all.

**L16**
LVM (Logical Volume Manager) is a storage management abstraction layer that allows administrators to pool physical storage devices into flexible volumes that can be dynamically resized and managed, independent of the underlying physical disk layout.

*   **Physical Volumes (PVs):** The actual physical storage devices (hard drives, partitions) that LVM uses.
*   **Volume Groups (VGs):** A pool of storage capacity created by combining one or more PVs.
*   **Logical Volumes (LVs):** The virtual, flexible partitions carved out of a VG that are then formatted and mounted like traditional partitions.

To extend an LV on a running system:
1.  Add a new PV (or extend an existing one) to the Volume Group (`vgextend`).
2.  Extend the Logical Volume using the newly available space (`lvextend`).
3.  Resize the filesystem on the LV to utilize the new space (`resize2fs` for ext4, or equivalent).

**L17**
The I/O scheduler manages how the kernel queues and services read/write requests from block devices to optimize disk throughput and latency.

*   **mq-deadline:** Prioritizes requests based on deadlines, balancing throughput and latency. Good for mixed workloads.
*   **bfq (Budget Fair Queueing):** Designed for interactive workloads, it aims to provide fair bandwidth allocation to different processes, minimizing latency for small, random I/O.
*   **none:** Disables the scheduler, allowing the device driver to handle scheduling directly. Best for devices with their own highly optimized internal scheduling logic (e.g., NVMe SSDs).

Choose **bfq** for desktop/interactive servers; **mq-deadline** for general-purpose servers; and **none** for high-performance SSDs.

To change the scheduler at runtime:
`echo bfq > /sys/block/sdX/queue/scheduler` (where `sdX` is the block device name).

**L18**
Load average measures the average number of processes that are either running or waiting to run (in uninterruptible sleep state, D). It is a measure of system *demand* relative to available CPU capacity.

I/O wait inflates the load average because processes waiting for disk I/O are counted as "running" (or waiting in the run queue) by the load average calculation, even though the CPU is idle.

Diagnosis:
*   **CPU Bottleneck:** High `us` (user) and `sy` (system) CPU usage, low `wa` (I/O wait). Use `top` or `htop`.
*   **Disk Bottleneck:** High `wa` CPU usage, high I/O utilization reported by `iostat` (high `%util`).
*   **Network Bottleneck:** High network interface errors/drops reported by `ip -s link` or `netstat`, and high queue depth on the NIC.

**L19**
SELinux enforces Mandatory Access Control (MAC) by enforcing policies that dictate which subjects (processes) can interact with which objects (files, ports, sockets), regardless of the traditional DAC (Discretionary Access Control) permissions (owner/group/other). SELinux uses security contexts (labels) to define these relationships.

*   **Enforcing:** SELinux actively denies access attempts that violate policy and logs the denial.
*   **Permissive:** SELinux logs policy violations but does *not* deny access, allowing the application to run while logging what *would* have been denied.
*   **Disabled:** SELinux is inactive, and only standard DAC rules apply.

To troubleshoot a daemon failing to bind a non-standard port:
1.  Set SELinux to **Permissive** mode temporarily.
2.  Attempt to run the daemon. If it succeeds, SELinux is the cause.
3.  Use `sealert` or `audit2allow` to generate a custom policy module that explicitly allows the daemon's context to bind to that specific port/socket type.

**L20**
The kernel handles page faults when a process attempts to access a virtual memory address whose corresponding physical page is not currently mapped in RAM.

*   **Minor Page Fault:** Occurs when the page is not in RAM, but the required data *is* present on disk (e.g., in the page cache). The kernel simply updates the page table entry to map the existing cached data into the process's address space. This is fast.
*   **Major Page Fault:** Occurs when the required data is not in RAM and is not in the page cache (i.e., it must be read from the backing store, like the swap file or original executable file). This requires a slow disk I/O operation to load the page into RAM.

**Transparent Huge Pages (THP)** attempts to use large memory pages (e.g., 2MB instead of 4KB) to reduce TLB misses and improve performance for memory-intensive applications. However, it can cause performance degradation due to memory fragmentation or latency spikes during background compaction. You would disable THP (`echo never > /sys/kernel/mm/transparent_hugepage/enabled`) if your application exhibits unpredictable latency or if you are running on a system where memory fragmentation is a known issue.
