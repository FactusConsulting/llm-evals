### .NET / C#

**DN1:** Classes are reference types allocated on the heap, support inheritance, and are garbage-collected. Structs are value types allocated inline (stack or within containing objects), copied on assignment, and cannot inherit from other structs (only implement interfaces). Use structs for small, immutable, short-lived data representing a single value (e.g., `Point`, `DateTime`, `Guid`) to avoid GC pressure and improve cache locality.

**DN2:** `IEnumerable<T>` executes queries in-memory (client-side). `IQueryable<T>` builds an expression tree that providers (like EF Core) translate to SQL, executing on the database (server-side). The distinction matters because `IEnumerable` pulls all rows into memory before filtering, causing severe performance/memory issues with large datasets, while `IQueryable` pushes filtering/projection to the DB.

**DN3:** `async/await` compiles into a state machine that yields control when awaiting, resuming on a thread pool thread when complete. `Task` is a reference type representing an async operation. `ValueTask` is a struct that avoids heap allocation when the result is already available synchronously. Use `ValueTask` in high-frequency, low-latency code paths (e.g., middleware, hot loops) where synchronous completion is common; otherwise, prefer `Task` for simplicity and compatibility.

**DN4:** DI is a pattern/framework for injecting dependencies rather than hardcoding them. Lifetimes: `Transient` (new instance per resolution), `Scoped` (one per logical scope, e.g., HTTP request), `Singleton` (one per application). Common bug: injecting a `Scoped` service into a `Singleton`. The scoped service is resolved once at startup and lives for the app's lifetime, causing stale state, memory leaks, and thread-safety violations. Fix: use `IServiceScopeFactory` to create scopes manually, or change the dependency to `Transient`/`Singleton`.

**DN5:** `string` is immutable, heap-allocated, and causes GC pressure on slicing/parsing. `ReadOnlySpan<char>` is a stack-only, zero-allocation view over contiguous memory. `Span<T>` is the mutable counterpart. Use `Span<T>`/`ReadOnlySpan<T>` for high-performance string parsing, substring operations, or interop where avoiding allocations is critical. They cannot be stored in fields or used with `async`/`await` directly due to stack-only constraints.

**DN6:** The GC automatically reclaims memory from unreachable objects. Generations optimize collection: Gen 0 (new, short-lived, collected frequently), Gen 1 (buffer), Gen 2 (long-lived, collected rarely). LOH stores objects >85KB; it's collected with Gen 2 and prone to fragmentation. `IDisposable` enables deterministic cleanup of unmanaged resources (file handles, DB connections, native memory) because the GC is non-deterministic and doesn't know how to release external resources.

**DN7:** Default `await` captures the current `SynchronizationContext` to resume on the original context (e.g., UI thread, classic ASP.NET request context). `ConfigureAwait(false)` skips capture, allowing continuation on any thread pool thread. Use it in libraries to avoid deadlocks and reduce context-switching overhead. Do NOT use it in UI apps or classic ASP.NET where context marshaling is required. In ASP.NET Core, `SynchronizationContext` is not used by default, so `ConfigureAwait(false)` is generally unnecessary.

**DN8:** Primary constructors allow parameters in the type declaration, accessible in the body. Collection expressions (`[1, 2, 3]`) unify array/list/span syntax. `FrozenDictionary` is an immutable, highly optimized dictionary with zero allocations on reads. DI example:
```csharp
public class OrderService(string tenantId, ILogger<OrderService> logger) { }
// Registration:
builder.Services.AddSingleton<OrderService>(sp => 
    new OrderService(sp.GetRequiredService<IOptions<AppSettings>>().Value.TenantId, 
                     sp.GetRequiredService<ILogger<OrderService>>()));
```

**DN9:** Likely cause: `DbContext` is being cached in a `Singleton`/static field, or an `IQueryable` is enumerated after the HTTP request scope ends, or async operations outlive the scope. `DbContext` is not thread-safe and must be `Scoped`. Fix: Ensure `AddDbContext<T>()` (defaults to Scoped), never cache it, materialize queries (`.ToList()`) before returning from async methods, and verify no background tasks hold the context. Use `IAsyncDisposable` properly and consider `DbContext` pooling for high concurrency.

**DN10:** `record` is immutable by default, provides value-based equality, positional syntax, and `with` expressions. `record struct` is the value-type equivalent, stack-allocated, ideal for performance-critical immutable data. `class` is mutable, reference-based, identity equality. Use `record` for DTOs/domain models, `record struct` for math/geometry types, `class` for entities requiring mutability or inheritance.

**DN11:** `ref`: passed by reference, must be initialized before call, can be modified. `out`: passed by reference, need not be initialized before call, must be assigned in method. `in`: passed by reference but read-only, avoids copying large structs. Use `ref` for in/out parameters, `out` for multiple return values, `in` for performance with large structs where mutation isn't needed.

**DN12:** Nullable reference types (`string?`) are compile-time annotations indicating a reference may be null. `#nullable enable` activates compiler warnings. They differ from `int?` (`Nullable<int>`), which is a runtime value-type wrapper. NRTs have zero runtime overhead; they only affect static analysis.

**DN13:** LINQ (Language Integrated Query) provides declarative data querying. Method syntax uses extension methods (`list.Where(...)`); query syntax uses SQL-like keywords (`from x in list where ...`), which the compiler translates to method syntax. Deferred execution means the query isn't executed until enumerated (e.g., `foreach`, `.ToList()`), enabling composition, optimization, and lazy evaluation.

**DN14:** Generic constraints restrict type parameters: `where T : class` (reference type), `where T : struct` (non-nullable value type), `where T : new()` (parameterless constructor), `where T : IComparable<T>` (implements interface). Combine to enable specific operations: `where T : class, IComparable<T>, new()` allows instantiation, comparison, and reference semantics.

**DN15:** Abstract classes can hold state, constructors, and partial implementations; support single inheritance. Interfaces define contracts; support multiple inheritance. C# 8+ default interface methods allow implementation in interfaces, blurring the line, but interfaces still cannot hold instance state or constructors. Use abstract classes for shared base behavior/state, interfaces for cross-cutting contracts.

**DN16:** Middleware pipeline executes request delegates in registration order. `Use`: can short-circuit, calls `next`. `Map`: branches pipeline based on path. `Run`: terminal, doesn't call `next`. Ordering is critical: error handling first, auth before routing, logging early. Exception handling middleware catches downstream exceptions, transforms them into HTTP responses, and prevents unhandled crashes.

**DN17:** `Channel<T>` is an async, lock-free producer-consumer queue. `BlockingCollection<T>` is synchronous, uses locks, and blocks threads. Bounded channel example:
```csharp
var ch = Channel.CreateBounded<int>(new BoundedChannelOptions(10) { FullMode = BoundedChannelFullMode.Wait });
// Producer: await ch.Writer.WriteAsync(item);
// Consumer: while (await ch.Reader.WaitToReadAsync()) while (ch.Reader.TryRead(out var item)) Process(item);
```
Prevents memory blowup by backpressuring producers when the buffer is full.

**DN18:** Source Generators run at compile-time to emit C# code. Unlike reflection (runtime, slower) or IL weaving (post-compile, modifies binaries), they produce source files integrated into compilation. `IIncrementalGenerator` tracks inputs/outputs and only regenerates changed code, drastically improving build times vs `ISourceGenerator` (runs every build, no caching). Preferred for performance and IDE integration.

**DN19:** TPL Dataflow provides async message-passing blocks. `ActionBlock` processes items, `TransformBlock` processes & outputs, `BufferBlock` stores. Compared to Channels: Dataflow is higher-level, supports complex topologies, backpressure, and completion signaling. Channels are lower-level, simpler, and better for linear pipelines. Dataflow has higher overhead but richer orchestration.

**DN20:** Minimal APIs map endpoints directly to delegates without controllers. Trade-offs: less boilerplate, but harder to unit test (no controller isolation), middleware applies globally, OpenAPI requires extra setup. Route groups (`app.MapGroup("/api")`) share configuration. Endpoint filters (`IEndpointFilter`) apply cross-cutting concerns (auth, validation) per endpoint without middleware complexity.

### Python

**P1:** `list` is mutable, ordered (`[]`). `tuple` is immutable, ordered (`()`). `set` is mutable, unordered, unique (`{}`). `frozenset` is immutable, hashable, can be used as dict keys or set elements.

**P2:** GIL is a mutex preventing multiple threads from executing Python bytecode simultaneously. It blocks CPU-bound multithreading from scaling. Workarounds: `multiprocessing`, `concurrent.futures.ProcessPoolExecutor`, C-extensions that release the GIL, or `asyncio` for I/O-bound workloads.

**P3:** `copy` creates a shallow copy (new container, same nested references). `deepcopy` recursively copies all objects. Example: `a = [[1,2]]; b = copy.copy(a); b[0].append(3); print(a)` → `[[1,2,3]]`. Shallow copy shares nested lists, causing unexpected mutation.

**P4:** Decorators wrap functions to extend behavior. Example:
```python
import time, functools
def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__}: {time.perf_counter()-start:.4f}s")
        return result
    return wrapper
```

**P5:** Generators use `yield` to pause/resume execution, returning an iterator. Unlike lists, they evaluate lazily, using O(1) memory. `yield from` delegates to another generator/iterable, flattening it into the current generator's output.

**P6:** `asyncio` event loop schedules coroutines on a single thread. `asyncio.run()` creates/runs the loop. `asyncio.gather()` runs coroutines concurrently, returns results. `asyncio.create_task()` schedules a coroutine, returns a `Task`. `time.sleep()` blocks the thread, starving the loop; use `await asyncio.sleep()` instead.

**P7:** MRO uses C3 linearization. For `D(B, C)`, MRO is `[D, B, C, A]`. `D().who()` checks D (no), B (no), C (yes, returns `"C"`). Output: `C`. Diamond inheritance is resolved left-to-right, depth-first with consistency checks.

**P8:** Metaclasses control class creation (`type` is the default). `__init_subclass__` is a simpler hook called on subclass creation, preferred for most cases. Use `__init_subclass__` for auto-registration or validation. Use metaclasses for complex class creation logic, modifying `__new__`, or enforcing strict interfaces.

**P9:** `threading`: GIL-limited, good for I/O. `multiprocessing`: separate processes, bypasses GIL, good for CPU, requires pickling args/results. `concurrent.futures`: high-level API wrapping both. Pickling implications: objects must be serializable, can't pass open files/locks, adds overhead for large data.

**P10:** `__slots__` declares instance attributes explicitly, preventing `__dict__` creation. Saves memory, speeds up attribute access, prevents dynamic attribute assignment. Significant memory reduction for millions of instances.

**P11:** Virtual environments isolate Python packages per project, preventing dependency conflicts. `venv`: stdlib, basic. `virtualenv`: faster, cross-version, more features. `conda`: language-agnostic, handles non-Python deps (C libs), robust environment management.

**P12:** Comprehensions: `[x for x in ...]`, `{k:v for ...}`, `{x for ...}`. More readable than `map()`/`filter()`. Prefer comprehensions for simplicity; use `map`/`filter` for functional pipelines or when passing functions as arguments.

**P13:** `==` checks value equality. `is` checks identity (same memory address). Interning caches small integers (-5 to 256) and certain strings. `a is b` returns `True` for small ints due to interning, not guaranteed for larger values.

**P14:** `*args` collects positional args into a tuple. `**kwargs` collects keyword args into a dict. `/` marks positional-only parameters (before it). `*` marks keyword-only parameters (after it). Example: `def f(a, /, b, *, c):` → `a` pos-only, `b` pos/keyword, `c` keyword-only.

**P15:** Context managers handle setup/teardown. Class-based: implement `__enter__`/`__exit__`. Generator-based: use `@contextmanager` with `yield`. Example: `threading.Lock()` or custom DB transaction manager that rolls back on exception.

**P16:** Type hints annotate variables/functions for static analysis. `Union[A,B]`/`A|B`, `Optional[T]`=`T|None`, `Literal['x']` restricts values, `TypeVar` enables generics, `Protocol` enables structural typing. `mypy`/`pyright` analyze code without execution, catching type errors early.

**P17:** Dunder methods define object behavior. `__repr__` (dev/debug), `__str__` (user). `__eq__` (equality), `__hash__` (hashable). Defining `__eq__` without `__hash__` makes the object unhashable. `__getattr__` (fallback for missing attrs), `__getattribute__` (intercepts all attr access).

**P18:** Descriptors implement `__get__`, `__set__`, `__delete__` to control attribute access. `property` uses descriptors for getters/setters. `classmethod`/`staticmethod` are descriptors returning bound methods or functions. Used for validation, lazy loading, or custom attribute behavior.

**P19:** Import system uses `importlib`. Absolute: `import pkg.mod`. Relative: `from . import mod`. `sys.path`/`PYTHONPATH`: search dirs. `__init__.py`: marks regular packages (optional in 3.3+). Namespace packages: split across dirs without `__init__.py`. Finder locates modules; loader executes them.

**P20:** `dataclasses` auto-generate `__init__`, `__repr__`, etc. `__post_init__` for validation. `field(default_factory=list)` for mutable defaults. `frozen=True` makes immutable. Inheritance merges fields. `attrs` is faster/more feature-rich. `Pydantic` adds validation, serialization, JSON schema. Choose Pydantic for APIs/data validation; dataclasses for internal DTOs/simple models.
