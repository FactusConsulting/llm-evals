JS1 — `var` is function-scoped, hoisted and initialized as `undefined`. `let` and `const` are block-scoped, hoisted but trapped in a temporal dead zone until declaration. `const` prevents reassignment. Hoisting is JavaScript's compilation-phase behavior of moving declarations to the top of their scope, allowing references before declaration (though TDZ blocks `let`/`const`).

JS2 — The event loop continuously checks the call stack. If empty, it pulls tasks from queues. Macrotasks (`setTimeout`, I/O, UI rendering) go to the task queue. Microtasks (`Promise` callbacks, `queueMicrotask`) go to the microtask queue. After each macrotask, the loop drains the entire microtask queue before rendering or picking the next macrotask.

JS3 — A closure is a function bundled with its lexical environment, retaining access to outer variables. Example: factory functions returning inner functions. The classic `for` loop bug occurs when `var i` is used in `setTimeout`; all callbacks capture the same reference, logging the final loop value. Fix: use `let i` (block-scoped per iteration) or wrap in an IIFE.

JS4 — `Promise` represents async completion. `async/await` is syntactic sugar over promises. Errors in promises are caught via `.catch()` or `try/catch` with `await`. `Promise.all` rejects fast on first failure; `Promise.allSettled` waits for all to settle and returns `{status, value/reason}` objects, ideal for non-critical parallel tasks where partial success is acceptable.

JS5 — `interface` is extendable, supports declaration merging, and is primarily for object shapes. `type` is more flexible (unions, intersections, primitives, tuples). Use `interface` for public APIs/contracts, `type` for complex aliases. Discriminated unions are tagged unions where a common literal property (discriminant) allows TypeScript to narrow types in `if/switch` blocks.

JS6 — Prototypal inheritance links objects via an internal `[[Prototype]]` chain. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar over prototypes; `class B extends A` sets up `B.prototype.[[Prototype]] = A.prototype` and handles constructor chaining automatically.

JS7 — `this` is determined at call time. Priority: 1. `new` binding, 2. explicit binding (`call`/`apply`/`bind`), 3. implicit binding (object method call), 4. default binding (global/`undefined` in strict mode). `bind()` returns a new permanently bound function. You cannot re-bind it; subsequent `call`/`apply`/`bind` are ignored.

JS8 — `WeakRef` holds a non-preventing reference to an object, allowing GC. `FinalizationRegistry` registers callbacks when objects are GC'd. Used for caches, DOM references, or cleanup. `WeakMap` keys must be objects because primitives are value-typed and lack identity/lifetime tracking; object keys allow GC to collect both key and value when unreferenced.

JS9 — V8 uses hidden classes (shapes) to track object property layouts for fast property access. Inline caching optimizes repeated property/method calls by caching the hidden class. Deoptimization occurs when assumptions break (e.g., adding new properties, changing types, prototype changes). Patterns causing deopt: dynamic property addition, mixed types in arrays, prototype pollution, frequent shape changes.

JS10 — Tree-shaking eliminates unused code during bundling. It works with ES modules because `import`/`export` are static and analyzable at compile time. CommonJS (`require`/`module.exports`) is dynamic/runtime, making static analysis impossible, so bundlers must include entire modules.

JS11 — `undefined` means declared but not assigned; `null` is an intentional absence of value. `==` coerces (`null == undefined` is true); `===` checks type and value (false). `??` returns right operand if left is `null`/`undefined` (unlike `||` which checks falsy). `?.` safely accesses nested properties, returning `undefined` if any part is nullish.

JS12 — `map` transforms elements, `filter` selects based on predicate, `reduce` accumulates to a single value. `reduce` takes `(acc, curr, idx, arr) => newAcc` and an optional initial value (if omitted, first element is used). `flatMap` maps then flattens one level deep; useful for combining mapping and flattening (e.g., splitting strings into words).

JS13 — Template literals use backticks, support interpolation `${expr}` and multiline strings. Tagged templates pass a function the literal parts array and interpolated values. Example: `html`<div>${name}</div>`` where `html` escapes `${name}` to prevent XSS.

JS14 — Destructuring extracts values from arrays/objects into variables. Object: `const {a, b: c} = obj` (renames b to c). Array: `const [x, y] = arr`. Defaults: `const {a = 1} = obj`. Rest: `const {a, ...rest} = obj` or `const [first, ...rest] = arr`.

JS15 — `for...in` iterates over enumerable property keys (including inherited), order not guaranteed. `for...of` iterates over iterable values. Avoid `for...in` on arrays because it iterates indices as strings, includes non-index properties, and breaks with sparse arrays.

JS16 — Generics allow reusable types. Constraints: `T extends Base`. Conditional: `T extends U ? X : Y`. `infer` extracts types in conditionals. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T;` extracts resolved type from Promise.

JS17 — CJS uses `require`/`module.exports`, synchronous, Node default. ESM uses `import`/`export`, asynchronous, static. Node supports both; `"type": "module"` in package.json makes `.js` files ESM. CJS files can use `.cjs`, ESM `.mjs`.

JS18 — TS uses structural typing (shape-based). Excess property checks only apply to object literals directly assigned to typed variables/functions. `extends` checks assignability; `satisfies` checks type compatibility without widening/narrowing the resulting type. Variance (`in`/`out`) controls generic parameter directionality for safe subtyping (contravariant/covariant).

JS19 — `Proxy` wraps an object to intercept operations via traps (`get`, `set`, `apply`). `Reflect` provides corresponding methods for default behavior. Example: `new Proxy(target, { set(t, p, v) { if (typeof v !== 'string') throw new Error(); return Reflect.set(t, p, v); } })` for validation.

JS20 — `SharedArrayBuffer` allows typed arrays to share memory across threads. `Atomics` provides lock-free, thread-safe operations with guaranteed ordering. Workers communicate via shared memory + `Atomics.wait`/`notify` for synchronization. `wait` blocks until `notify` or timeout, avoiding busy-waiting.

B1 — `$@` and `$*` expand to positional parameters. Unquoted, identical. Quoted: `"$@"` expands to each parameter as a separate quoted word (`"$1" "$2"`). `"$*"` expands to a single word with IFS-separated parameters (`"$1 $2"`).

B2 — `set -e`: exit on error. `set -u`: treat unset variables as errors. `set -o pipefail`: pipeline returns exit status of last command to exit non-zero (or 0 if all succeed). Crucial for robust scripts.

B3 — `$(cmd)` is modern command substitution, nestable, readable. `` `cmd` `` is legacy, harder to nest. `$((expr))` is arithmetic expansion (fast, built-in). `expr` is an external command, slower, requires escaping operators.

B4 — Process substitution `<(...)` runs a command and provides its output as a file descriptor. Useful when commands expect files. Example: `diff <(sort file1) <(sort file2)` compares sorted outputs without temp files.

B5 — Use `while IFS= read -r -d '' file; do ... done < <(find . -type f -print0)`. `for f in $(ls)` splits on whitespace/newlines, breaks on spaces/special chars, and is vulnerable to globbing.

B6 — Here doc `<<EOF` feeds multiline input until EOF. Here string `<<<` feeds a single string. `<<-EOF` strips leading tabs (not spaces) from the delimiter and content, useful for indentation.

B7 — `cmd > file 2>&1`: stdout to file, stderr redirected to stdout (goes to file). `cmd 2>&1 > file`: stderr goes to original stdout (terminal), stdout goes to file. `cmd &> file`: both to file (bashism). Order matters because redirections are processed left-to-right.

B8 — 
```bash
acquire_lock() {
  local lockdir="/tmp/myapp.lock"
  if mkdir "$lockdir" 2>/dev/null; then
    trap 'rmdir "$lockdir"' EXIT
    return 0
  else
    return 1
  fi
}
```
`mkdir` is atomic on POSIX, preventing race conditions. `touch` isn't atomic. `trap ... EXIT` ensures cleanup on normal exit, SIGTERM, SIGINT.

B9 — Single quotes: literal, no expansion. Double quotes: allow variable/command expansion, preserve spaces. No quotes: word splitting and globbing occur. Example: `echo $var` (splits), `echo "$var"` (preserves), `echo '$var'` (prints literal $var).

B10 — `[ -f file ]` (exists & regular), `[ -d dir ]`, `[ -r file ]`. `[ ]` is POSIX `test`, limited parsing. `[[ ]]` is bash keyword, supports regex `=~`, logical `&&`/`||`, no word splitting/globbing, safer.

B11 — `$?`: exit status of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: number of positional parameters. Use cases: error checking, logging, job control, argument validation.

B12 — `foo() { ... }` is POSIX standard. `function foo { ... }` is bash/ksh extension. Functions return exit codes via `return` (0-255). To return data, `echo` and capture with `$(foo)`.

B13 — `PATH` is colon-separated directories for command lookup. Bash checks builtins first, then aliases/functions, then `PATH`. Builtins run in shell process; externals fork. Use `type cmd` or `command -v cmd` to check.

B14 — `trap 'cmd' SIGNAL` runs `cmd` on signal. `EXIT` runs on script termination. `ERR` runs on command failure (with `-e`). `INT`/`TERM` for interrupts. Signals are processed asynchronously; `trap` handlers run when shell reaches a safe point. Order: signal handler -> EXIT trap.

B15 — `xargs` builds/executes commands from stdin. Command substitution captures output. `find -print0 | xargs -0` handles spaces/newlines safely. `xargs -P N` runs up to N jobs in parallel.

B16 — Indexed arrays: `arr=()`, `arr+=("val")`, `${arr[@]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]="val"`, `${!assoc[@]}` (keys), `${assoc[@]}` (values). Syntax differs; associative requires bash 4+.

B17 — `(...)` runs in subshell (new process), variables don't persist. `{ ...; }` runs in current shell, variables persist. Piping creates subshells for each segment, so `cat file | while read; do var=1; done` loses `var`. Use process substitution or `while read; done < file`.

B18 — `SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (hangup), `SIGKILL` (unblockable, immediate). Job control tracks foreground/background jobs. Graceful shutdown: trap `TERM`/`INT`, kill child PIDs (`kill 0` or track in array), wait, then exit.

B19 — 
```bash
process_chunk() { grep "ERROR" "$1" > "${1}.out"; }
export -f process_chunk
split -l 1000000 large.log chunk_
xargs -P $(nproc) -I {} bash -c 'process_chunk "$@"' _ {} < <(ls chunk_*)
cat chunk_*.out > merged.log
rm chunk_*
```
Trade-offs: disk I/O for split/merge, memory vs CPU balance. Error propagation: check `$?` in function, use `set -o pipefail`, or collect exit codes.

B20 — `exec` replaces shell process with command (no return). For FDs: `exec 3>file` opens FD 3, `exec 3>&-` closes it. Coprocess: `coproc cmd { read/write }` creates bidirectional pipe. Used for interactive programs or continuous data streams.

PS1 — `Write-Output` sends objects down the pipeline. `Write-Host` writes directly to the console host, bypassing the pipeline. Using `Write-Host` breaks pipeline chaining and makes output untestable/unredirectable.

PS2 — Pipeline passes objects cmdlet-to-cmdlet. `ForEach-Object` processes objects one-by-one in the pipeline (streaming). `foreach` is a language statement that enumerates the entire collection in memory first. Use `ForEach-Object` for large streams, `foreach` for performance on in-memory collections.

PS3 — `[hashtable]` is unordered, key-value, mutable. `[PSCustomObject]` is ordered, strongly-typed properties, pipeline-friendly, supports methods. Convert: `@{k='v'} | ConvertTo-Json` or `[PSCustomObject]@{k='v'}`. Use PSCustomObject for pipeline output, hashtable for internal config.

PS4 — Terminating errors stop execution, caught by `try/catch`. Non-terminating continue, written to error stream. `-ErrorAction Stop` makes non-terminating terminating. `$ErrorActionPreference` sets default. `try/catch` only catches terminating errors.

PS5 — Splatting passes a hashtable/array as named parameters: `@params = @{ Verb='Get'; Name='Service' }; Get-Service @params`. Differs from passing hashtable as a single param because splatting expands keys to parameter names.

PS6 — `Invoke-Command` runs scriptblock remotely, returns results. `Enter-PSSession` opens interactive remote shell. Uses WS-Management (WinRM) over HTTP/HTTPS. PowerShell 7+ supports SSH remoting natively.

PS7 — PowerShell unrolls arrays in the pipeline. `$result += "one"` creates an array, but `return $result` outputs the array elements individually. `$x.GetType().Name` is `String`. If empty, returns `$null`. Correct pattern: `return ,@()` or `Write-Output -NoEnumerate $result` to preserve array type.

PS8 — `[scriptblock]` is a compiled code block, functions are named scriptblocks. Pass via `-ScriptBlock`. Double-hop: credential delegation fails when remote session accesses another resource. Solve with CredSSP, Kerberos constrained delegation, or `Invoke-Command -ArgumentList` to pass data instead of credentials.

PS9 — `@()` is array literal, `[array]` is type accelerator. Force array: `@($result)` or `,$result`. Indexing `$null[0]` throws or returns `$null` depending on version; empty array `@()[0]` returns `$null`. Always use `@()` for safety.

PS10 — `-eq`/`-ne` equality, `-like` wildcard, `-match` regex, `-contains`/`-in` membership. Case-sensitive: `-ceq`, `-clike`, etc. `-contains` checks if collection has item (`$arr -contains $item`). `-in` checks if item is in collection (`$item -in $arr`).

PS11 — Module packages functions/cmdlets. `.psm1` is script module (code). `.psd1` is manifest (metadata, dependencies). Binary is compiled DLL. `Import-Module` loads into session, adds to `$env:PSModulePath`.

PS12 — `"..."` allows interpolation `$var`. `'...'` is literal. Expressions: `"$($obj.Property)"`. Here-strings: `@" ... "@` preserve formatting, support interpolation.

PS13 — `Get-Member` shows object type, properties, methods. NoteProperties are custom properties added by cmdlets. `Select-Object` filters/creates properties. `Where-Object` filters objects based on conditions.

PS14 — Classes (v5+) define types with properties/methods. Differs from C#: no inheritance, limited interfaces, static members only, no operators. Use for structured data/validation. Functions better for pipeline/cmdlet behavior.

PS15 — `[CmdletBinding()]` enables advanced function features: parameter validation, pipeline binding, `-WhatIf`/`-Confirm` (`SupportsShouldProcess`), parameter sets. `Begin` runs once, `Process` per pipeline object, `End` once at finish.

PS16 — Providers expose data stores as drives. `Get-ChildItem` works on `C:\`, `HKLM:\`, `Cert:\`, `Env:`. Registry: `Get-ChildItem HKLM:\SOFTWARE` navigates like files.

PS17 — Runspaces are isolated execution environments. `[runspacepool]` manages multiple. `[powershell]` object adds commands to runspace. `ForEach-Object -Parallel` (v7+) simplifies parallelism but has serialization limits. Manual runspace gives full control but is verbose.

PS18 — PSScriptAnalyzer is static analysis tool. Rules check style/security. Severity: Error/Warning/Information. Custom rules via modules. Suppress with `[SuppressMessage()]` or settings file. CI/CD: run as pre-commit or pipeline step.

PS19 — `$using:var` passes variables to remote/parallel contexts. `$args`/`-ArgumentList` passes positional. CLIXML serializes objects; depth limit ~5-10, complex objects lose methods/properties. Use simple types or JSON for complex data.

PS20 — DSC maintains system state. Configurations define desired state, resources implement it, LCM enforces it. WinPS uses MOF files, PS7+ uses PowerShell DSC (PSDSC) with native PS resources. Modern IaC: Terraform, Ansible, Bicep, ARM templates.
