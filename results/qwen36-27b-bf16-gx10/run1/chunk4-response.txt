G1 — Arrays have fixed size and are value types; slices are dynamic views over arrays containing a pointer, length, and capacity. When `append` exceeds capacity, Go allocates a new underlying array (typically 2× the old capacity), copies existing elements, updates the slice header, and drops the old array.

G2 — `var x int` declares `x` with its zero value (`0`). `x := 0` is a short variable declaration that infers the type from the initializer. You cannot use `:=` at package level, when redeclaring a variable without introducing a new one, or when you need to explicitly declare a type without initialization.

G3 — A goroutine is a lightweight, user-space thread managed by the Go runtime. Unlike OS threads (1:1 mapping, ~MB stacks), goroutines start with ~2KB stacks that grow/shrink dynamically and are multiplexed onto OS threads. The GMP scheduler maps Goroutines (G) to logical Processors (P), which are bound to OS threads (M). The scheduler preemptively switches Gs on syscalls, timers, or after a time slice, enabling massive concurrency with minimal overhead.

G4 — Channels are typed conduits for safe goroutine communication. Unbuffered channels block until both sender and receiver are ready (synchronous). Buffered channels hold up to N values; sends block only when full, receives block only when empty. Sending to a full buffered channel blocks the sender until a receiver frees a slot.

G5 — `context` carries deadlines, cancellation signals, and request-scoped values across API boundaries. Minimal timeout example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, http.MethodGet, "https://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```
The request is automatically canceled if it exceeds 5s.

G6 — Go uses implicit/structural interface satisfaction: a type implements an interface if it defines all its methods, with no explicit declaration. Java/C# require explicit `implements`. `interface{}` (now `any`) matches all types, enabling polymorphism and generic-like behavior pre-1.18, but is dangerous because it erases compile-time type safety, forcing runtime type assertions or type switches.

G7 — Go's memory model provides no happens-before guarantee between goroutines without synchronization. The loop may never see `ready = true` due to CPU caching or instruction reordering, and `data` may be partially visible. Fix: use `sync/atomic` (`atomic.StoreInt32`/`atomic.LoadInt32`), a channel (`ch <- struct{}{}`), or `sync.WaitGroup`/`sync.Once` to establish proper synchronization.

G8 — `sync.Mutex` allows exclusive access; `sync.RWMutex` allows multiple concurrent readers or one exclusive writer. `sync.Map` is optimized for concurrent read-heavy workloads with mostly distinct keys, handling synchronization internally and avoiding lock contention. Regular map + mutex is better for write-heavy or mixed workloads, with lower overhead for simple cases. `sync.Map` trades write performance and memory overhead for lock-free reads.

G9 — Go modules manage dependencies. `go.mod` declares the module path, Go version, and direct dependencies. `go.sum` stores cryptographic hashes of all resolved dependencies for reproducibility. `go mod tidy` adds missing and removes unused dependencies. Minimum Version Selection (MVS) resolves the dependency graph by picking the lowest version of each module that satisfies all requirements, ensuring a single, deterministic tree without version conflicts.

G10 — `defer` schedules a function call to run after the surrounding function returns, in LIFO order. Common loop gotcha: deferred closures capture the loop variable by reference, so all defers see the final iteration value. Fix: pass the loop variable as an argument to the deferred function (`defer func(i int){...}(i)`).

G11 — A pointer holds the memory address of another value. Its zero value is `nil`. Create a pointer to a struct literal with `&Struct{Name: "val"}`.

G12 — `init()` is a package initialization function that runs after imported packages initialize and before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source file. Across packages, initialization follows import order.

G13 — `make` initializes and returns slices, maps, and channels with internal structures ready for use. `new` allocates zeroed memory for any type and returns a pointer. `make` does not return a pointer; `new` does not initialize internal structures (e.g., `new(map)` returns a `nil` map pointer).

G14 — Errors are explicit return values implementing the `error` interface (`Error() string`). Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error matches a target (supports wrapping). `errors.As` unwraps to find a specific error type. `==` only checks exact identity and fails with wrapped errors.

G15 — Built-in composite types: `map`, `slice`, `channel`, `struct`. Zero values: `map`, `slice`, `channel` are `nil`. `struct` is a value with all fields at their zero values.

G16 — A race condition occurs when concurrent goroutines access shared memory without synchronization, with at least one write. `-race` enables a thread sanitizer that instruments memory accesses at runtime to detect races. Example: concurrent map writes. Fix: protect with `sync.Mutex` or serialize access via a channel.

G17 — `select` waits on multiple channel operations. Unlike `switch`, it blocks until at least one case is ready. If multiple are ready, it picks one pseudo-randomly. Timeout: `select { case <-ch: ...; case <-time.After(5 * time.Second): ... }`.

G18 — Escape analysis determines if a variable's lifetime exceeds the function scope. If yes, it allocates on the heap; otherwise, on the stack. Inspect with `go build -gcflags="-m"`. It matters because heap allocations trigger GC and add latency, while stack allocations are cheap and automatic. Avoiding escapes reduces GC pressure and improves throughput.

G19 — `reflect` inspects/modifies types and values at runtime. `reflect.Type` describes type metadata; `reflect.Value` holds the actual data. Costs: dynamic dispatch, type checks, heap allocation, and broken inlining. Justified for serialization, frameworks, and plugins. Prefer code generation (`go generate`) for performance-critical paths to retain compile-time safety and speed.

G20 — `//go:embed` embeds files into the binary at compile time. Single file: `var f string //go:embed file.txt`. Directory: `var d embed.FS //go:embed dir/*`. `embed.FS` implements `io/fs.FS`, enabling runtime reading via `fs.ReadFile`, `http.FS`, etc. Limitations: only static files, increases binary size, no dynamic generation.

R1 — Ownership is Rust's memory management system. Rules: 1. Each value has exactly one owner (variable). 2. Only one owner exists at a time. 3. When the owner goes out of scope, the value is dropped (memory freed).

R2 — `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is an immutable borrowed string slice (view into a `String` or literal). Use `&str` in function signatures for flexibility (accepts both); use `String` when taking ownership or modifying the data.

R3 — Borrowing allows temporary references without taking ownership. Rules: either one `&mut T` OR any number of `&T`, but never both simultaneously. References must not outlive the data they point to. The borrow checker enforces these rules at compile time to prevent data races and dangling pointers.

R4 — `Result<T, E>` represents success/failure with values; `Option<T>` represents some/none. `?` unwraps `Ok`/`Some`, or returns `Err`/`None` early. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)?
}
```

R5 — `Box<T>`: heap allocation, single ownership. `Rc<T>`: reference counting, single-threaded shared ownership. `Arc<T>`: atomic reference counting, thread-safe shared ownership. Use `Box` for recursive types/large data, `Rc` for shared data in one thread, `Arc` for concurrent shared data.

R6 — Traits define shared behavior. Similar to Go interfaces but support associated types, generics, and conditional implementations. `dyn Trait` enables dynamic dispatch (vtable, fat pointer, runtime resolution). `T: Trait` enables static dispatch (monomorphization, compile-time resolution, zero overhead).

R7 — Lifetimes annotate reference validity. The function fails because the compiler cannot infer which input lifetime the output should match. Fix:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — `Send`: type can be transferred across threads. `Sync`: type can be shared across threads (`&T` is `Send`). `Rc<T>` isn't `Send`/`Sync` because its reference counting uses non-atomic operations. `Arc<T>` uses atomic operations, making it safe for concurrent use.

R9 — Async/await uses cooperative multitasking. A `Future` is a lazy state machine representing an async computation, polled by an executor. Executors (e.g., Tokio) manage I/O, schedule tasks on threads, and drive futures to completion. Differs from Go: Go uses preemptive M:N scheduling with lightweight goroutines managed by the runtime; Rust futures are lazy, require an explicit runtime, and have no built-in scheduler in `std`.

R10 — `unsafe` opts out of Rust's safety guarantees. Allows: 1. Dereferencing raw pointers. 2. Calling unsafe functions/FFI. 3. Accessing `mut static` variables or union fields. Justified for low-level optimizations, FFI, implementing core abstractions, or interacting with hardware. Must manually uphold safety invariants.

R11 — Pattern matching decomposes values using `match`. `match` requires exhaustive coverage (compiler enforces); `if let` matches one pattern and ignores others. The compiler rejects non-exhaustive `match` unless a catch-all `_` is provided.

R12 — `Vec<T>` is a growable, heap-allocated array. `[T; N]` is a fixed-size, stack-allocated array. When `Vec` exceeds capacity, it allocates a new larger buffer (usually 2×), moves elements, and drops the old buffer.

R13 — Enums are algebraic data types that can hold different payloads per variant. Unlike C/Java enums (integer constants), Rust enums are type-safe and can carry data. `Option<T>` (`Some(T)`/`None`) replaces null, forcing explicit handling and eliminating null pointer exceptions.

R14 — `impl` defines methods/associated items for a type. `&self`: immutable borrow (reader). `&mut self`: mutable borrow (writer). `self`: takes ownership (consuming). Associated functions don't take `self`, are called on the type (e.g., `String::new()`), and act as constructors or utilities.

R15 — `#[derive(...)]` is a procedural macro that auto-implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize` (serde). Cannot derive if fields don't implement the trait, or if custom logic is required (e.g., `Hash` with custom equality, or traits requiring manual invariants).

R16 — `Cow<'a, T>` (Clone on Write) is a smart pointer for borrow-or-own semantics (`Borrowed(&'a T)` or `Owned(T)`). Useful when you might or might not modify data. Avoids cloning if the input is already owned or remains unmodified. Example: string processing where most inputs are already `String` or don't require mutation.

R17 — `mod` declares a module, `use` imports into scope, `pub` controls visibility. Rust 2015: `mod foo;` expected `foo.rs` or `foo/mod.rs`. Rust 2018+: `mod foo;` primarily expects `foo.rs` as the module root; `foo/mod.rs` is deprecated (removed in 2024). Modules map directly to the file system.

R18 — `Pin<T>` prevents memory movement of a value after pinning. Required for self-referential structs (pointers to own fields) and async state machines (which hold references to their own buffers). `Unpin` is a marker trait for types that don't need pinning (most types). `Pin` ensures `&mut T` cannot be used to relocate the data.

R19 — Macros generate code at compile time. Declarative (`macro_rules!`): pattern-based, hygienic by default, limited to expressions/items. Procedural: functions transforming tokens, used for `#[derive]`, attributes, function-like macros. Hygiene prevents variable name collisions between macro expansion and surrounding scope.

R20 — Zero-cost abstractions compile to efficient machine code with no runtime overhead. Iterators are inlined into tight loops. Generics use monomorphization to create type-specific code at compile time. Trait static dispatch resolves at compile time, eliminating vtable lookups. This matches hand-written C performance while providing memory safety and high-level ergonomics.
