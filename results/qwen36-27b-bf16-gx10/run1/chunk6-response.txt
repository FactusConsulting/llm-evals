## JavaScript / TypeScript

JS1 — `var` is function-scoped, hoisted with initialization to `undefined`, and reassignable. `let` and `const` are block-scoped, hoisted but trapped in the Temporal Dead Zone (TDZ) until declaration, and reassignable (`let`) or not (`const`). Hoisting is the JavaScript engine's behavior of moving declarations to the top of their scope during compilation, allowing references before declaration (though TDZ prevents early access for `let`/`const`).

JS2 — The event loop continuously checks the call stack and queues. Synchronous code runs on the call stack. When async operations complete, callbacks are queued: microtasks (Promises, `queueMicrotask`) have higher priority and drain completely before the next macrotask (setTimeout, I/O, UI rendering). The loop order: sync → microtasks → render → macrotask → repeat.

JS3 — A closure is a function that retains access to its lexical scope's variables even after the outer function returns. Example: counter factory returning increment/decrement functions sharing a private `count`. The classic `for` loop bug occurs with `var` because all iterations share the same `i` reference, logging the final value. Fix: use `let` (creates new binding per iteration) or wrap in an IIFE.

JS4 — `Promise` represents an async operation's eventual completion/failure. `async/await` is syntactic sugar that makes promise chains read synchronously. Errors are handled via `.catch()` or `try/catch` around `await`. `Promise.all` rejects immediately on the first failure. `Promise.allSettled` waits for all promises to settle, returning an array of `{status, value/reason}` objects, useful for non-critical parallel tasks.

JS5 — `interface` is extensible, supports declaration merging, and is primarily for object shapes. `type` is an alias that supports unions, intersections, primitives, and mapped types, but cannot be merged. Use `interface` for public APIs/contracts; `type` for complex/union types. Discriminated unions are union types with a common literal property (tag) that TypeScript uses to narrow types safely in conditionals.

JS6 — Prototypal inheritance links objects via the `[[Prototype]]` chain; property lookups traverse up until found or `null`. `Object.create(proto)` creates a new object with the specified prototype. ES6 `class` syntax is syntactic sugar over prototypes: `class A {}` creates a constructor function, `extends` sets up prototype chain inheritance, and methods are defined on `prototype`.

JS7 — `this` binding rules (priority): 1. `new` binding, 2. explicit (`call`/`apply`/`bind`), 3. implicit (object method call), 4. default (global/`undefined` in strict). `bind()` returns a new function with `this` permanently fixed. You can call `bind()` again on the bound function, but it overrides the previous binding; the original `this` cannot be recovered.

JS8 — `WeakRef` holds a non-preventing reference to an object, allowing GC to collect it. `FinalizationRegistry` registers callbacks when objects are GC'd. Used for caching, tracking native resources, or debugging. `WeakMap` keys must be objects because GC only tracks object references; primitives are copied by value, making weak tracking impossible and breaking memory safety guarantees.

JS9 — V8 optimizes via hidden classes (inline property layouts for fast access), inline caching (IC) for repeated property/method lookups, and deoptimization when assumptions break. Deopt triggers: adding properties to existing objects, changing property types, prototype changes, or polymorphic calls. Patterns to avoid: dynamic property addition, mixed-type arrays, and prototype pollution.

JS10 — Tree-shaking is static analysis that removes unused exports. It works with ES modules because `import`/`export` are static and analyzable at build time. CommonJS (`require`/`module.exports`) is dynamic/runtime, so bundlers cannot statically determine dependencies, making effective tree-shaking impossible without manual hints or ESM conversion.

JS11 — `undefined` means declared but unassigned; `null` means intentional absence. `==` coerces types, so `null == undefined` is `true`. `===` checks type and value, so `null === undefined` is `false`. `??` returns the right operand only if left is `null`/`undefined` (unlike `||` which catches falsy values). `?.` safely accesses nested properties, short-circuiting on `null`/`undefined`.

JS12 — `map` transforms each element, returning a new array. `filter` keeps elements matching a predicate. `reduce` accumulates values into a single result; an initial value sets the starting accumulator (otherwise first element is used). `flatMap` maps then flattens one level; useful for avoiding nested arrays when transforming collections (e.g., splitting strings into words).

JS13 — Template literals use backticks and `${}` for interpolation. Tagged templates pass a function that receives an array of static strings and interpolated values. Example: `html`<div>${userInput}</div>`` where the tag function escapes HTML entities in values before concatenation, preventing XSS.

JS14 — Destructuring unpacks values from arrays/objects. Object: `const {a, b} = obj`. Array: `const [x, y] = arr`. Defaults: `const {a = 1} = obj`. Renaming: `const {a: x} = obj`. Rest operator `...` collects remaining properties/elements: `const {a, ...rest} = obj` or `const [first, ...rest] = arr`.

JS15 — `for...in` iterates enumerable property keys (including inherited). `for...of` iterates iterable values. Avoid `for...in` on arrays because it iterates indices as strings, includes non-index properties, and iteration order isn't guaranteed. Use `for...of` or array methods for arrays.

JS16 — Generics (`<T>`) enable reusable type-safe code. Constraints (`T extends SomeType`) limit valid types. Conditional types (`T extends U ? X : Y`) branch types. `infer` extracts types in conditional contexts. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T;` extracts the resolved type from a Promise.

JS17 — CommonJS (`require`/`module.exports`) is synchronous, runtime-evaluated, Node's default. ES Modules (`import`/export) are static, async, and standard. Node handles both via detection or `"type": "module"` in `package.json` (treats `.js` as ESM). ESM enables static analysis, top-level `await`, and better tree-shaking.

JS18 — TypeScript uses structural typing: compatibility depends on shape, not declaration. Excess property checks only apply to object literals directly assigned to typed variables (freshness check). `extends` checks assignability and widens types. `satisfies` checks compatibility without widening/narrowing. Variance (`in`/`out`) in TS 4.7+ controls generic parameter directionality for type safety in complex generics.

JS19 — `Proxy` intercepts fundamental object operations via traps. `Reflect` provides static methods mirroring Proxy traps. Intercept access with `get`, assignment with `set`, calls with `apply`. Example: reactive validation by tracking property access/mutation in `get`/`set` traps, triggering re-renders or validation rules automatically.

JS20 — `SharedArrayBuffer` provides fixed-length binary memory shared across threads. `Atomics` provides thread-safe operations. Workers communicate via shared memory + `Atomics.wait`/`notify` for synchronization. Ordering is sequentially consistent. `wait` blocks until value changes or timeout; `notify` wakes waiting threads. Enables lock-free, high-performance parallelism.

## Bash

B1 — `$@` and `$*` expand to positional parameters. `"$@"` expands to each parameter as a separate quoted word (`"$1" "$2"`), preserving spaces. `"$*"` expands to a single word with all parameters joined by the first character of `IFS` (`"$1 $2"`). Always use `"$@"` for safe argument forwarding.

B2 — `set -e`: exit immediately on command failure. `set -u`: treat unset variables as errors. `set -o pipefail`: pipeline returns the exit status of the last command to exit non-zero (or 0 if all succeed). Together they form strict mode, preventing silent failures and undefined variable bugs.

B3 — `$(command)` and `` `command` `` both perform command substitution, but `$()` is nestable, readable, and doesn't require escaping backticks. `$((expression))` is arithmetic expansion (evaluates math natively). `expr` is an external command for arithmetic/regex, slower, and requires escaping operators.

B4 — Process substitution `<(cmd)` runs a command and provides its output as a file descriptor path (e.g., `/dev/fd/63`). Used when commands expect file arguments. Example: `diff <(sort file1) <(sort file2)` compares sorted outputs without creating temporary files.

B5 — Use `while IFS= read -r -d '' file; do ... done < <(find . -type f -print0)` or `find . -type f -exec ... {} +`. `for f in $(ls)` is dangerous because it splits on whitespace/newlines, breaks on spaces/special characters, and triggers glob expansion.

B6 — Here document `<<EOF` feeds multi-line input until the EOF delimiter. Here string `<<<` feeds a single string. `<<-EOF` strips leading tabs (not spaces) from the delimiter and content, allowing indented scripts without affecting input.

B7 — `cmd > file 2>&1`: stdout to file, stderr redirected to where stdout points (file). Both go to file. `cmd 2>&1 > file`: stderr redirected to original stdout (terminal), then stdout redirected to file. Only stdout goes to file. `cmd &> file`: bash shorthand for both to file. Redirections are processed left-to-right, so order matters.

B8 — 
```bash
lock() {
  local lockdir="/tmp/myapp.lock"
  mkdir "$lockdir" 2>/dev/null || { echo "Already running"; exit 1; }
  trap 'rmdir "$lockdir" 2>/dev/null' EXIT
}
```
`mkdir` is atomic across POSIX filesystems, preventing race conditions. `rmdir` only succeeds if empty, ensuring safe cleanup. `trap EXIT` handles normal exit, `SIGTERM`, and `SIGINT`.

B9 — Single quotes `'...'`: literal, no expansion. Double quotes `"..."`: allow variable/command expansion, preserve spaces. No quotes: word splitting and globbing occur. Example: `echo $var` splits on spaces; `echo "$var"` preserves; `echo '$var'` prints literal `$var`.

B10 — `-f` regular file, `-d` directory, `-r` readable. `[ ]` is POSIX `test`, limited, requires careful quoting. `[[ ]]` is a bash keyword, supports pattern matching, regex, logical operators without quoting, and is safer/more powerful.

B11 — `$?`: exit status of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: number of positional parameters. Use cases: error checking, logging, job control, argument validation.

B12 — Define: `foo() { ... }` or `function foo { ... }`. POSIX prefers `foo()`. `return` sets exit status (0-255). To return values, use `echo`/`printf` and capture with `$(foo)`, or modify global variables. Functions don't return data like languages with `return value`.

B13 — `PATH`: colon-separated directories for command lookup. Bash checks builtins first, then aliases/functions, then `PATH`. Builtins run in the shell process; externals fork. Check with `type cmd` or `command -v cmd`.

B14 — `trap 'cmd' SIGNAL` runs `cmd` on signal. `EXIT` runs on script exit. `ERR` on command failure (with `-e`). `INT`/`TERM` on Ctrl+C/kill. Signals are handled asynchronously; `EXIT` runs last. Use `trap -p` to list. Order: signal handler → cleanup → exit.

B15 — `xargs` builds/executes commands from stdin. Command substitution captures output. `find -print0 | xargs -0` handles spaces/newlines safely. `xargs -P N` runs N jobs in parallel. Trade-off: parallelism vs resource contention and output ordering.

B16 — Indexed arrays: `arr=(a b c)`, append `arr+=d`, iterate `${arr[@]}`, length `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, iterate `${!assoc[@]}` (keys) or `${assoc[@]}` (values). Syntax differs; associative requires bash 4+.

B17 — Subshell `(...)`: runs in child process, variables don't persist, exit code is last command's. Group `{ ...; }`: runs in current shell, variables persist, requires semicolon after last cmd. Piping creates subshells for each segment, so `while` in pipe loses variable changes. Use process substitution or `shopt -s lastpipe` to fix.

B18 — Signals: `SIGINT` (Ctrl+C), `SIGTERM` (graceful kill), `SIGHUP` (hangup/terminal close), `SIGKILL` (force, uncatchable). Job control: `jobs`, `fg`, `bg`, `disown`. Graceful shutdown: trap `TERM`/`INT`, kill child PIDs, cleanup, exit.

B19 — 
```bash
split -l 10000 log.txt chunk_
xargs -P 4 -I {} bash -c 'process {} > {}.out' _ chunk_*
cat chunk_*.out > merged.log
```
Trade-offs: I/O vs CPU, memory overhead, error propagation. Track failures in temp files or use `set -o pipefail` with parallel job monitoring.

B20 — `exec` replaces shell process with command (no return). For FDs: `exec 3>file` opens FD 3, `exec 3>&-` closes it. Coprocess: `coproc name { cmd; }` creates bidirectional pipe. Used for interactive programs needing continuous I/O.

## PowerShell

PS1 — `Write-Output` sends objects down the pipeline. `Write-Host` writes directly to the host/console, bypassing the pipeline. This matters because `Write-Host` breaks pipeline chaining, makes output untestable, and prevents downstream cmdlets from processing data.

PS2 — The pipeline passes objects cmdlet-to-cmdlet. `ForEach-Object` processes pipeline objects one-by-one (streaming). `foreach` statement loads the entire collection into memory first, then iterates. Use `ForEach-Object` for large streams/memory efficiency; `foreach` for speed on in-memory collections.

PS3 — `[PSCustomObject]` is a strongly-typed, ordered, pipeline-friendly object. `[hashtable]` is unordered, mutable, key-value collection. Use PSCustomObject for structured data/pipelines, hashtable for config/dynamic keys. Convert: `[PSCustomObject]@{k='v'}` or `@{k='v'} | ConvertTo-Json`.

PS4 — Terminating errors stop execution, caught by `try/catch`. Non-terminating continue, written to error stream. `-ErrorAction`/`$ErrorActionPreference` control behavior (`Stop`, `Continue`, `SilentlyContinue`). `try/catch` only catches terminating; use `-ErrorAction Stop` to make non-terminating terminating.

PS5 — Splatting `@params` passes hashtable/array as named parameters. Example: `$p = @{Path='C:\'; Recurse=$true}; Get-ChildItem @p`. Differs from single param: splatting expands keys to named args, not a single object argument.

PS6 — Remoting executes commands on remote systems. `Invoke-Command` runs scriptblock remotely, returns results. `Enter-PSSession` opens interactive remote shell. Uses WS-Management (WinRM) over HTTP/HTTPS. PowerShell 7+ supports SSH remoting natively.

PS7 — PowerShell unwraps single-element arrays. `$result += "one"` creates array, but `return $result` unwraps to string. `GetType().Name` is `String`. Returns `$null` for 0 items. Correct pattern: `return ,$result` (comma forces array) or declare `[string[]]$result = @()`.

PS8 — `[scriptblock]` is compiled code block, functions are named scriptblocks with parameters. Pass via `-ScriptBlock` or `-ArgumentList`. Double-hop: credential delegation fails on second network hop. Solve with CredSSP, Kerberos constrained delegation, or `Invoke-Command -ArgumentList` to pass data instead of credentials.

PS9 — `@()` is array literal, `[array]` is type accelerator. Force single to array: `@($item)` or `,$item`. Indexing `$null` returns `$null`; indexing empty array `@()[0]` returns `$null`. Both behave similarly, but `@()` guarantees array type.

PS10 — `-eq`/`-ne`: equality/inequality. `-like`/`-notlike`: wildcard. `-match`/`-notmatch`: regex. `-contains`/`-in`: membership. Case-sensitive: `-ceq`, `-clike`, `-cmatch`, `-ccontains`. `-contains` checks if collection has item; `-in` checks if item is in collection (reversed operands).

PS11 — Module: reusable package of functions/cmdlets. Script module `.psm1`: PowerShell script. Manifest `.psd1`: metadata/config. Binary: compiled DLL. `Import-Module` loads into session, adds to auto-load path, exports members.

PS12 — Interpolation: `"Value is $var"`. Single quotes `'...'` are literal. Expressions: `"$($obj.Property)"`. Here-string: `@" ... "@` or `@' ... '@` for multi-line, preserves formatting, allows unescaped quotes.

PS13 — `Get-Member` shows object type, properties, methods. `Properties`: data fields. `Methods`: actions. `NoteProperties`: dynamic properties added at runtime. `Select-Object` filters/creates new objects with specific properties. `Where-Object` filters pipeline objects by condition.

PS14 — Classes (v5+): define types with properties/methods. Differs from C#: no inheritance, no interfaces, limited constructors (only parameterless or explicit), no access modifiers (all public). Use for structured data/validation; functions for logic/pipeline processing.

PS15 — `[CmdletBinding()]` enables advanced function features: common params (`-Verbose`, `-Debug`), parameter sets, pipeline binding. `SupportsShouldProcess` enables `-WhatIf`/`-Confirm`. `Begin`/`Process`/`End` control pipeline execution: `Begin` once, `Process` per object, `End` once.

PS16 — Providers: expose non-filesystem data as drive-like paths. `Get-ChildItem` works across them via `PSProvider` property. Registry: `HKLM:\Software`. Certificate: `Cert:\LocalMachine\My`. Environment: `Env:\PATH`. Access via drive letters or full paths.

PS17 — Runspaces: isolated PowerShell execution environments. `[runspace]` single, `[runspacepool]` multiple. `[powershell]` object adds commands to runspace. `ForEach-Object -Parallel` (v7+) simplifies parallelism, handles serialization automatically. Manual runspace gives more control but requires thread-safety management.

PS18 — PSScriptAnalyzer: static analysis tool. Enforces standards via rules (e.g., `PSUseShouldProcessForStateChangingFunctions`). Severity: Error, Warning, Information. Custom rules via modules. Suppress with `[Diagnostics.CodeAnalysis.SuppressMessageAttribute()]`. Integrates via CI/CD for linting.

PS19 — `$using:var` passes variables to remote/parallel contexts by value. `$args`/`-ArgumentList` passes positional args. Serialization uses CLIXML, limited depth/size (~100MB, complex objects may lose methods/state). Affects custom objects, COM objects, streams. Use simple types or serialize manually.

PS20 — DSC: declarative config management. Configurations define desired state, resources implement it, LCM enforces it. Windows PS uses MOF files, PS 7+ supports cross-platform. Replaced/supplemented by modern IaC: Terraform, Ansible, Bicep, ARM templates, which offer better state management, cloud integration, and declarative syntax.
