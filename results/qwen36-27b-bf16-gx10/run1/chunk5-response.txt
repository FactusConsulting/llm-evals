## .NET / C#

**DN1** — Classes are reference types (heap-allocated, support inheritance, default `null`). Structs are value types (stack/inline-allocated, no inheritance, zero-initialized). Use structs for small, immutable data representing a single value (e.g., `Point`, `DateTime`, `Complex`) where copying is cheap and you want to avoid GC pressure. Avoid for large payloads or when reference/identity semantics are required.

**DN2** — `IEnumerable<T>` executes LINQ in-memory (LINQ to Objects). `IQueryable<T>` holds an expression tree and delegates execution to a provider (e.g., EF Core → SQL). The distinction matters because `IEnumerable` pulls all rows into memory before filtering, while `IQueryable` translates filters to SQL, drastically reducing network traffic, memory usage, and GC pressure.

**DN3** — `async/await` compiles to a state machine that registers continuations on task completion, freeing the thread during I/O. `Task` is a reference type representing an async operation. `ValueTask` is a struct that wraps either a completed result or a `Task`, avoiding heap allocation when the operation completes synchronously. Use `ValueTask` in high-frequency, low-latency APIs (e.g., cache hits, pooled buffers). Avoid in general-purpose libraries due to struct semantics (must be awaited immediately or stored carefully).

**DN4** — DI manages object creation and dependency resolution. Lifetimes: `Transient` (new per request), `Scoped` (one per logical scope, e.g., HTTP request), `Singleton` (one per app). Bug: **Captive Dependency**. Injecting a `Scoped` service into a `Singleton` causes the scoped service to live as long as the singleton, breaking scope boundaries (e.g., `DbContext` outliving the request, causing concurrency/state corruption). Fix: use `IServiceScopeFactory` to create explicit scopes, or align lifetimes correctly.

**DN5** — `string` is immutable, heap-allocated, reference type. `ReadOnlySpan<char>` is a stack-only struct providing a zero-allocation view over contiguous memory (strings, arrays, `stackalloc`). Use `Span<T>`/`ReadOnlySpan<T>` for high-performance parsing, slicing, or interop where you want to avoid allocations and GC pressure. Cannot be stored in fields, used in `async` methods, or passed across `await` boundaries.

**DN6** — The GC uses mark-sweep-compact. Generations: Gen 0 (short-lived, frequent collection), Gen 1 (buffer), Gen 2 (long-lived, infrequent). Objects promote as they survive collections. LOH: heap for objects >85KB; not compacted by default (causes fragmentation), collected with Gen 2. `IDisposable` enables deterministic cleanup of unmanaged resources (files, DB connections, handles). The GC is non-deterministic; relying on it for unmanaged resources causes handle exhaustion. Use `using`/`await using`.

**DN7** — Default `await` captures the current `SynchronizationContext`/`TaskScheduler` and resumes on it. `ConfigureAwait(false)` tells the awaiter not to capture context, resuming on the thread pool. Use in library code, background tasks, or when you don't need UI/ASP.NET context. Prevents deadlocks and improves performance. Avoid in UI apps or ASP.NET Core request handlers where you need `HttpContext` or UI thread access. ASP.NET Core lacks a `SynchronizationContext` by default, making `ConfigureAwait(false)` less critical but still best practice for libraries.

**DN8** — Primary constructors: parameters in type declaration, available in body/constructors. Collection expressions: `[]` syntax for arrays/lists, `..` for spreading. `FrozenDictionary`: immutable, highly optimized lookup table. Example:
```csharp
public class WeatherService(ILogger<WeatherService> logger, IConfiguration config) : IWeatherService {
    public FrozenDictionary<string, string> Regions { get; } = 
        config.GetSection("Regions").Get<FrozenDictionary<string, string>>();
    public Task<Forecast> GetAsync(string city) => Task.FromResult(new Forecast(city));
}
```

**DN9** — Cause: `DbContext` is `Scoped`. Under high concurrency, if a background task, singleton, or async continuation outlives the HTTP request scope, the context is disposed while still in use. EF Core also tracks entities; concurrent requests sharing a context cause race conditions. Fix: ensure `DbContext` is strictly scoped per request. Use `IServiceScopeFactory` for background work. Avoid capturing contexts in long-lived closures. Use `AsNoTracking()` for reads. Consider `DbContextPool` for high-throughput scenarios. DI registers `DbContext` as `Scoped` by default; resolving it outside a scope breaks this contract.

**DN10** — `record`: reference type, value-based equality, immutable by default, generates `with`, `ToString()`, `Equals()`. `record struct`: value type, same value semantics, stack-allocated. Choose `record` for DTOs, domain entities with value semantics, or when you want built-in immutability/equality. Use `class` for mutable state, identity semantics, or inheritance. Use `record struct` for performance-critical, small, immutable value types.

**DN11** — `ref`: pass by reference, must be initialized before call, read/write. `out`: pass by reference, no prior initialization needed, must be assigned before return. `in`: pass by reference (read-only), prevents copying, guarantees no mutation. Use `ref` for in/out parameters, `out` for multiple return values, `in` for large structs to avoid copy overhead without mutation.

**DN12** — `int?` (`Nullable<T>`): value type wrapper, holds value or `null`, compiles to `Nullable<int>`. `string?` (nullable reference type): compiler annotation only (with `#nullable enable`). No runtime difference. Tells the compiler to track nullability and warn on potential null dereferences. Enables static analysis for null safety without runtime overhead.

**DN13** — LINQ: language-integrated query for collections, DBs, XML. Method syntax: fluent extension methods (`Where`, `Select`). Query syntax: SQL-like (`from x in list where ...`). Compiler translates query to method syntax. Deferred execution: query isn't executed until enumerated (`.ToList()`, `foreach`). Allows composition and efficient DB translation. Immediate execution: `.Count()`, `.First()`, `.ToList()`.

**DN14** — Constraints restrict generic type parameters: `where T : class` (reference type), `where T : struct` (non-nullable value type), `where T : new()` (parameterless constructor), `where T : IComparable<T>` (implements interface). Combine with commas: `where T : class, IComparable<T>, new()`. Used to enable type-specific operations inside generics while maintaining type safety.

**DN15** — Abstract class: can have state, constructors, partial implementation, single inheritance. Interface: contract, multiple inheritance, historically no state. Default interface methods (C# 8+): interfaces can provide implementation, enabling versioning without breaking implementers. Still no instance state. Use abstract class for shared state/behavior; interface for contracts/multiple inheritance.

**DN16** — Middleware pipeline: delegates executed sequentially per request. `app.Use()`: can short-circuit, calls `next()` to continue. `app.Map()`: branches pipeline based on path, creates sub-pipeline. `app.Run()`: terminal middleware, doesn't call `next()`. Ordering is critical: logging/auth first, endpoints last. Exception handling middleware (`UseExceptionHandler`) must be early; catches unhandled exceptions and returns formatted responses without breaking the pipeline.

**DN17** — `Channel<T>`: async, lock-free, built on `TaskCompletionSource`, supports backpressure, cancellation, high throughput. `BlockingCollection<T>`: sync, lock-based, older, less performant. Bounded channel example:
```csharp
var channel = Channel.CreateBounded<int>(new BoundedChannelOptions(100) { FullMode = BoundedChannelFullMode.Wait });
// Producer: await channel.Writer.WriteAsync(item);
// Consumer: while (await channel.Reader.WaitToReadAsync()) while (channel.Reader.TryRead(out var item)) { }
```
Backpressure: `FullMode.Wait` blocks producer when full; `DropOldest`/`DropNewest` drops items.

**DN18** — Source Generators: compile-time code generation. Run during compilation, emit C# source files. No runtime overhead, no IL manipulation. vs Reflection: runtime, slower, breaks encapsulation. vs IL Weaving: post-compilation, complex, runtime overhead. Incremental Generator (`IIncrementalGenerator`): caches results, only re-runs on changed inputs. Preferred for performance in large solutions. `ISourceGenerator` runs on every build.

**DN19** — TPL Dataflow: block-based pipeline, built on `Task`, supports fan-in/fan-out, ordering, buffering, backpressure. `ActionBlock<T>`: consumes, executes action. `TransformBlock<TIn, TOut>`: consumes, transforms, produces. `BufferBlock<T>`: stores, forwards. vs Channels: Channels are simpler, async-first, lower overhead, better for 1:1 or simple producer-consumer. Dataflow is better for complex DAGs, parallel processing, and rich backpressure/flow control.

**DN20** — Minimal APIs: lightweight, delegate-based routing (`app.MapGet(...)`), no controller classes, less boilerplate. vs Controllers: Controllers offer structure, inheritance, filters, model binding conventions, easier unit testing. Minimal APIs are harder to test in isolation, less structured for large apps. Trade-offs: Minimal = fast dev, low overhead, great for microservices. Controllers = enterprise features, testability, OpenAPI/Swagger out-of-box. Route groups: `app.MapGroup("/api/v1")` for shared prefixes/middleware. Endpoint filters: `IEndpointFilter` for cross-cutting concerns (auth, validation, caching) applied per endpoint or group.

## Python

**P1** — `list`: mutable, ordered, heterogeneous, `[]`. `tuple`: immutable, ordered, heterogeneous, `()`. Hashable if contents are hashable. `set`: mutable, unordered, unique elements, `{}`. `frozenset`: immutable set, hashable, can be dict keys or set elements.

**P2** — GIL: mutex protecting Python object access, allows only one thread to execute bytecode at a time. Affects CPU-bound multithreaded code (no true parallelism). Workarounds: `multiprocessing` (separate processes, separate GILs), `asyncio` (I/O bound), C-extensions that release GIL, or switch to Jython/IronPython (no GIL, but niche).

**P3** — `copy.copy()`: shallow copy. New container, references to same nested objects. `copy.deepcopy()`: recursive copy. New container, new nested objects. Example: `a = [1, [2, 3]]; b = copy.copy(a); b[1].append(4); print(a)` → `[1, [2, 3, 4]]`. Shallow copy shares inner list.

**P4** — Decorator: function that takes a function, returns a wrapper, modifies behavior. Uses `@` syntax.
```python
import time, functools
def log_time(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.4f}s")
        return result
    return wrapper
```

**P5** — Generator: function with `yield`, returns iterator. Lazy evaluation, memory efficient. vs list: list computes all at once, stores in memory. Generator computes on demand. `yield from`: delegates to another generator/iterable, forwards `send()`/`throw()`, simplifies nested iteration.

**P6** — Event loop: single-threaded scheduler for coroutines, handles I/O callbacks. `asyncio.run()`: creates loop, runs coroutine, closes loop. Entry point. `asyncio.gather()`: runs multiple coroutines concurrently, returns results. `asyncio.create_task()`: schedules coroutine, returns Task. Runs concurrently with caller. `time.sleep()` blocks thread, halts event loop. Use `await asyncio.sleep()` instead (non-blocking).

**P7** — MRO: order Python searches for methods. Algorithm: C3 Linearization (Python 3). Ensures monotonicity, respects left-to-right declaration. Diamond: `D(B, C)`, `B(A)`, `C(A)`. MRO: `D -> B -> C -> A -> object`. Code output: `C`. `D` inherits from `B` first, but `B` doesn't override `who`. Next is `C`, which overrides `who` to return `"C"`.

**P8** — Metaclass: class of a class. Controls class creation (`__new__`, `__init__`). `__init_subclass__`: class method called when subclass is created. Simpler, preferred for most cases. Use `__init_subclass__` for registering subclasses, validating attributes, or modifying class dict. Use metaclass for complex class creation logic, overriding `__call__` (instance creation), or when you need to intercept class creation before `__init_subclass__` runs. Example: `__init_subclass__` for plugin registry; metaclass for ORM model base that auto-generates table names.

**P9** — `threading`: shares memory, GIL-limited, good for I/O bound. `multiprocessing`: separate processes, bypasses GIL, good for CPU bound. Uses IPC. `concurrent.futures`: high-level API wrapping both (`ThreadPoolExecutor`, `ProcessPoolExecutor`). Easier to use. Pickling: `multiprocessing` serializes args/results via pickle. Objects must be picklable. Can't pass lambdas, open files, or complex C-objects. Use `multiprocessing.shared_memory` or queues for large data.

**P10** — `__slots__`: declares allowed instance attributes. Replaces `__dict__` with fixed-size array. Prevents dynamic attribute assignment, saves memory, speeds up attribute access. Use when creating millions of instances, memory is tight, or you want strict attribute enforcement. Impact: reduces memory per instance by ~40-50%, but breaks pickling (sometimes), prevents `__dict__`/`__weakref__` unless explicitly added.

**P11** — Virtual environment: isolated Python environment with its own site-packages. Prevents dependency conflicts, enables reproducible builds. `venv`: stdlib, basic, Python 3.3+. `virtualenv`: third-party, faster, supports older Python, more features. `conda`: cross-language (R, C++), manages non-Python deps, uses its own package manager, heavier but great for data science.

**P12** — Comprehensions: `[x for x in iterable if cond]`, `{k:v for ...}`, `{x for ...}`. Readable, Pythonic. `map()`/`filter()`: functional, apply function/predicate. Return iterators. Prefer comprehensions for readability and complex transformations. Prefer `map`/`filter` for simple function application, lazy evaluation, or when passing functions as arguments.

**P13** — `==`: value equality. `is`: identity (same memory address). Interning: Python caches small integers (-5 to 256) and short strings. `a is b` is True for cached objects. Don't rely on `is` for value comparison.

**P14** — `*args`: packs extra positional args into tuple. `**kwargs`: packs extra keyword args into dict. `/`: positional-only parameters (left of `/`). Can't be passed as keywords. `*`: keyword-only parameters (right of `*`). Must be passed as keywords. Example: `def f(a, /, b, *, c):` → `a` positional-only, `b` either, `c` keyword-only.

**P15** — Context manager: handles setup/teardown via `with` statement. Class-based: implement `__enter__` (return resource) and `__exit__` (handle cleanup/exceptions). `@contextmanager`: generator-based, `yield` separates setup/teardown. Simpler. Example: database transaction, lock acquisition, or temporarily changing environment variables.

**P16** — Type hints: static annotations for IDE/type checkers. No runtime enforcement. `Union[A, B]` / `A | B`: multiple types. `Optional[T]` / `T | None`: nullable. `Literal["a", "b"]`: exact values. `TypeVar`: generic type parameter. `Protocol`: structural subtyping (duck typing). `mypy`/`pyright`: static analyzers that check hints, catch type errors before runtime, support gradual typing.

**P17** — `__repr__`: unambiguous, for devs/debugging. `__str__`: readable, for users. `__eq__`: equality. `__hash__`: hash for dicts/sets. If `__eq__` is defined, `__hash__` is set to `None` (unhashable) unless explicitly defined. `__getattr__`: called when attribute not found. `__getattribute__`: called for every attribute access (dangerous if not careful). Defining `__eq__` without `__hash__` makes instances unhashable (can't be dict keys/set members).

**P18** — Descriptor: object implementing `__get__`, `__set__`, `__delete__`. Controls attribute access. Data descriptor: has `__set__` or `__delete__` (takes precedence over instance dict). Non-data: only `__get__`. `property`: data descriptor, wraps getter/setter/deleter. `classmethod`/`staticmethod`: non-data descriptors, `__get__` returns bound method or function. Used for validation, lazy loading, caching, or custom attribute behavior.

**P19** — Import system: finds and loads modules. Absolute: `import os` or `import mypkg.module`. Relative: `from . import module` (requires package context). `sys.path`: list of directories Python searches. `PYTHONPATH` env var prepends to it. `__init__.py`: marks directory as package, runs on import. Can be empty. Namespace packages: split across directories without `__init__.py` (PEP 420). Finder: locates module (`sys.meta_path`). Loader: loads/executes it. `importlib` abstracts this.

**P20** — `dataclasses`: stdlib, generates `__init__`, `__repr__`, `__eq__`. Lightweight. `attrs`: third-party, more features, faster, better validation. `Pydantic`: validation-focused, JSON/schema integration, runtime type coercion, great for APIs/config. `__post_init__`: runs after `__init__`, for validation/computed fields. Field factories: `field(default_factory=list)` for mutable defaults. Frozen: `frozen=True` makes immutable. Inheritance: dataclasses support it, but `__init__` signature merging can be tricky. Choose Pydantic for web APIs, config parsing, or when you need strict validation, serialization, and OpenAPI integration. Use dataclasses for internal DTOs/domain models where stdlib is preferred.
