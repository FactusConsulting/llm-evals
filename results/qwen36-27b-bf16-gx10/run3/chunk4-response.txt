G1 — Arrays have a fixed size known at compile time and are value types. Slices are dynamic views into underlying arrays, consisting of a pointer, length, and capacity. When `append` exceeds capacity, Go allocates a new underlying array (typically 2× the old capacity for small slices, ~1.25× for large ones), copies existing elements, updates the slice header, and returns the new slice.

G2 — `var x int` declares a package- or block-level variable initialized to the zero value (`0`). `x := 0` is a short variable declaration that infers the type and requires an initializer. You cannot use `:=` at package scope, when redeclaring a variable without introducing at least one new variable, or when you need to explicitly declare a type without initialization.

G3 — A goroutine is a lightweight, user-space thread managed by the Go runtime. Unlike OS threads (1–8MB stack, 1:1 kernel mapping), goroutines start with ~2KB stacks that grow/shrink dynamically and use M:N scheduling. The GMP model: G=goroutine, M=OS thread, P=logical processor. The scheduler binds Gs to Ps, Ps run on Ms, and handles preemption, syscall parking, and work-stealing to maximize CPU utilization.

G4 — Channels are typed conduits for safe goroutine communication. Unbuffered channels block until both sender and receiver are ready, enforcing synchronization. Buffered channels hold N values; sends block only when full, receives block only when empty. Sending to a full buffered channel blocks the sender until a receiver frees a slot.

G5 — `context` carries deadlines, cancellation signals, and request-scoped values across API boundaries. Minimal example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, http.MethodGet, "https://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```
The request cancels automatically after 5s or when `cancel()` is called.

G6 — Go uses implicit/structural interface satisfaction: a type implements an interface if it defines all its methods, with no explicit declaration. Java/C# require explicit `implements`. `interface{}` (now `any`) matches any type. It's powerful for generic-like behavior but dangerous because it erases compile-time type safety, forces runtime type assertions/switches, and can hide bugs.

G7 — The code violates Go's memory model: there's no happens-before relationship between the goroutine's writes and the main goroutine's reads. The compiler/CPU may reorder `data = "hello"` and `ready = true`, or cache `ready`, causing infinite loops or reading uninitialized `data`. Fixes: use `sync/atomic` for `ready`, a `sync.Once`, a channel, or a `sync.Mutex`.

G8 — `sync.Mutex` allows exclusive access. `sync.RWMutex` allows multiple concurrent readers or one exclusive writer. `sync.Map` is optimized for concurrent read-heavy workloads with mostly distinct key sets per goroutine. Regular map + mutex is better for mixed workloads, frequent updates, or overlapping keys. `sync.Map` trades write/delete performance and lacks `len()` for lock-free reads.

G9 — Go modules manage dependencies. `go.mod` declares the module path, Go version, and direct dependencies. `go.sum` stores cryptographic hashes of all resolved dependencies for reproducibility. `go mod tidy` adds missing and removes unused dependencies. MVS (Minimum Version Selection) picks the lowest version of each dependency that satisfies all requirements, guaranteeing a single, deterministic dependency tree without version conflicts.

G10 — `defer` schedules a function call to run after the surrounding function returns, in LIFO order. Common loop gotcha: deferred closures capture loop variables by reference, so all defers see the final loop value. Fix: pass the loop variable as an argument to the deferred function (`defer func(i int){...}(i)`).

G11 — A pointer holds the memory address of another value. Its zero value is `nil`. Create a pointer to a struct literal with `&Struct{Name: "val"}`.

G12 — `init()` is a special function with no parameters or return values. It runs after package-level variables are initialized and before `main()`. A package can have multiple `init()` functions; their execution order within the package is unspecified, but packages initialize in dependency order (imported packages first).

G13 — `make` initializes and returns slices, maps, and channels by setting up their internal data structures. `new` allocates zeroed memory for any type and returns a pointer. `make` returns the type itself; `new` returns `*T`.

G14 — Errors are values implementing `error` (`Error() string`). Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error matches a target (supports wrapping). `errors.As` unwraps to find a specific error type. `==` only checks pointer equality and fails with wrapped errors.

G15 — Built-in composite types: `map`, `slice`, `channel`, `struct`. Zero values: `map`, `slice`, `channel` → `nil`. `struct` → all fields set to their respective zero values.

G16 — A race condition occurs when concurrent goroutines access shared memory without synchronization, with at least one write. `-race` instruments code to track memory accesses and reports data races at runtime. Example: concurrent map writes. Fix: protect with `sync.Mutex` or serialize access via a channel.

G17 — `select` waits on multiple channel operations. Unlike `switch`, it blocks until at least one case is ready. If multiple are ready, it picks one pseudo-randomly. Timeout: `select { case <-ch: ... case <-time.After(d): ... }`.

G18 — Escape analysis determines if a variable's lifetime exceeds the function scope. If yes, it's heap-allocated; otherwise, stack-allocated. Inspect with `go build -gcflags="-m"`. It matters because heap allocations trigger GC overhead, while stack allocations are cheap and automatic. Avoiding escapes reduces GC pressure and latency.

G19 — `reflect` inspects/modifies types and values at runtime. `reflect.Type` describes type metadata; `reflect.Value` holds the actual data. Costs: dynamic dispatch, type checks, heap allocations, broken inlining. Justified for serialization, frameworks, or testing. Prefer code generation (`go generate`) for performance-critical paths.

R20 — `//go:embed` embeds files into the binary at compile time. Single file: `//go:embed file.txt var f string`. Directory: `//go:embed dir/* var fs embed.FS`. Works with `io/fs.FS` for standard file operations. Limitations: only static files, increases binary size, path restrictions, no runtime updates.

R1 — Ownership is Rust's memory management system. Rules: 1. Each value has exactly one variable (owner). 2. Only one owner exists at a time. 3. When the owner goes out of scope, the value is dropped (memory freed).

R2 — `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is an immutable borrowed slice of UTF-8, pointing to string literals or parts of a `String`. Use `&str` in function signatures for flexibility (accepts both); use `String` when you need ownership, mutation, or to return newly allocated data.

R3 — Borrowing allows temporary references to data without taking ownership. Rules: either one `&mut T` OR any number of `&T`, but never both simultaneously. References must not outlive the data they point to. The borrow checker enforces these rules at compile time to prevent data races and dangling pointers.

R4 — `Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents a value (`Some(T)`) or absence (`None`). `?` propagates `Err`/`None` by returning early, or unwraps `Ok`/`Some`. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — `Box<T>`: heap allocation with single ownership. `Rc<T>`: reference counting for shared ownership in single-threaded contexts. `Arc<T>`: atomic reference counting for thread-safe shared ownership. Use `Box` for recursive types/large data, `Rc` for shared single-threaded data, `Arc` for concurrent sharing.

R6 — Traits define shared behavior. Similar to Go interfaces but support associated types, generics, and default implementations. `dyn Trait` (trait object) uses dynamic dispatch (fat pointer + vtable), resolved at runtime. `T: Trait` (generic) uses static dispatch (monomorphization), resolved at compile time, typically faster.

R7 — Lifetimes annotate how long references are valid. The function fails because the compiler doesn't know if the return reference points to `x` or `y`. Fix:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```
This ties the return lifetime to the inputs.

R8 — `Send`: type can be transferred across threads. `Sync`: type can be shared across threads (`&T` is `Send`). `Rc<T>` isn't `Send`/`Sync` because its reference counting uses non-atomic operations. `Arc<T>` uses atomic operations, making it safe for concurrent use.

R9 — Async/await uses cooperative multitasking. A `Future` is a lazy state machine representing an async computation, polled by an executor. Executors (e.g., Tokio) manage I/O, schedule tasks on threads, and drive futures to completion. Differs from Go: Go uses eager goroutines with an M:N runtime scheduler and preemption; Rust uses lazy futures, explicit executors, and yields only at `.await` points.

R10 — `unsafe` opts out of Rust's safety guarantees. Allows: 1. Dereferencing raw pointers, 2. Calling unsafe functions/FFI, 3. Accessing `mut static` variables, 4. Implementing unsafe traits, 5. Accessing union fields. Justified for FFI, low-level syscalls, or performance-critical code where safety is manually verified.

R11 — Pattern matching decomposes values using `match`. `match` requires exhaustive coverage (compiler enforces handling all variants or using `_`). `if let` matches a single pattern and ignores others, useful for optional/conditional logic without full exhaustiveness.

R12 — `Vec<T>` is a growable heap-allocated array. `[T; N]` is a fixed-size stack array. When `push` exceeds capacity, `Vec` allocates a larger buffer (typically ~1.5×–2×), moves/copies existing elements, and updates capacity.

R13 — Enums are algebraic data types where each variant can hold different data. Unlike C/Java enums (integer-backed), Rust enums are type-safe and payload-capable. `Option<T>` (`Some(T)`/`None`) replaces `null`, forcing explicit handling of absence and eliminating null pointer exceptions.

R14 — `impl` blocks define methods and associated functions for a type. `&self`: immutable borrow, `&mut self`: mutable borrow, `self`: takes ownership. Associated functions don't take `self`, are called on the type directly (e.g., `String::new()`), and are typically constructors.

R15 — `#[derive(...)]` is a procedural macro that auto-implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize` (serde). Cannot derive if fields don't implement the trait, or if custom logic is required (e.g., `Hash` with custom equality, or traits requiring manual implementation like `Send`/`Sync` in some cases).

R16 — `Cow<'a, T>` (Clone on Write) is a smart pointer that can either borrow (`Borrowed(&'a T)`) or own (`Owned(T)`) data. Useful when you might or might not need to modify data. Avoids cloning if the data is already owned or remains unmodified. Example: processing string slices that may require mutation only in rare cases.

R17 — Modules organize code. `mod` declares a module, `use` imports into scope, `pub` controls visibility. File mapping: `mod foo;` looks for `foo.rs` or `foo/mod.rs`. Rust 2018 simplified resolution: removed mandatory `mod.rs` for nested modules, improved path resolution, and allowed `mod.rs` to be optional.

R18 — `Pin<T>` prevents memory movement of a value. Required for self-referential structs (pointers to own fields) and async state machines (futures contain references to their own state). `Unpin` is a marker trait for types that can be safely moved; most types implement it. `Pin` is only needed when self-references exist.

R19 — Macros generate code at compile time. Declarative (`macro_rules!`): pattern-based, hygienic, limited to expressions/items. Procedural: functions generating code, used for `derive`, `attr`, `func-like`. Hygiene ensures macro-generated identifiers don't clash with surrounding scope, preventing accidental capture.

R20 — Zero-cost abstractions provide high-level ergonomics without runtime overhead. Iterators compile to inlined loops with no function call overhead. Generics use monomorphization to generate type-specific code. Trait static dispatch resolves at compile time, avoiding vtable lookups. Together, they match hand-written C performance while guaranteeing memory safety.
