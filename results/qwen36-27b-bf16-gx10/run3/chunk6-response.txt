## JavaScript / TypeScript

**JS1** `var` is function-scoped, hoisted with initialization to `undefined`, and allows redeclaration/reassignment. `let` and `const` are block-scoped, hoisted but trapped in the Temporal Dead Zone (TDZ) until declaration, and prevent redeclaration. `const` prevents reassignment (though object/array contents remain mutable). Hoisting is JavaScript's behavior of moving declarations to the top of their scope during compilation, allowing references before declaration (though `let`/`const` throw TDZ errors until initialized).

**JS2** The event loop coordinates async execution. The call stack runs synchronous code. When async callbacks complete, they're queued: microtasks (Promises, `queueMicrotask`, `MutationObserver`) and macrotasks (`setTimeout`, `setInterval`, I/O, UI rendering). After the call stack empties, the event loop drains the microtask queue completely before processing one macrotask, then renders, then repeats. This ensures microtasks execute before UI updates or timers.

**JS3** A closure is a function that retains access to variables from its lexical scope even after the outer function returns. Example: `const counter = (() => { let n = 0; return () => ++n; })();`. The classic `for` loop bug occurs with `var`: `for(var i=0; i<3; i++) setTimeout(()=>console.log(i), 10)` logs `3,3,3` because `var` is function-scoped and shared. Fix: use `let` (creates a new binding per iteration) or wrap in an IIFE.

**JS4** A `Promise` represents an async operation's eventual completion/failure. `async/await` is syntactic sugar that makes promise chains read synchronously. Error handling: `.catch()` for promises, `try/catch` for `await`. `Promise.all` rejects immediately on the first failure, short-circuiting others. `Promise.allSettled` waits for all promises to settle, returning an array of `{status, value/reason}` objects, useful when you need results regardless of individual failures.

**JS5** `interface` is extensible, supports declaration merging, and is primarily for object/function shapes. `type` is an alias that supports unions, intersections, primitives, and mapped types, but doesn't merge. Use `interface` for public APIs/contracts; use `type` for complex unions/intersections. Discriminated unions are union types with a common literal property (tag) that TypeScript uses to narrow types safely in `if/switch` blocks.

**JS6** Prototypal inheritance links objects via the `[[Prototype]]` chain. When a property isn't found on an object, JS looks up the chain. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` syntax is syntactic sugar over prototypes: `class B extends A` sets `B.prototype.[[Prototype]] = A.prototype` and calls `super()` to invoke the parent constructor.

**JS7** `this` refers to the execution context. Priority rules: 1. `new` binding (constructor), 2. Explicit binding (`call`/`apply`/`bind`), 3. Implicit binding (object method call), 4. Default binding (`undefined` in strict mode, global otherwise). `bind()` returns a new function with `this` permanently fixed. You cannot re-bind it; subsequent `call`/`apply`/`bind` calls are ignored.

**JS8** `WeakRef` holds a non-preventing reference to an object, allowing GC to collect it. `FinalizationRegistry` registers callbacks invoked when a tracked object is GC'd. Use for caches, tracking native resources, or memory profiling. `WeakMap` keys must be objects because GC tracks object identity/lifetime; primitives are copied by value and lack a stable memory address for weak referencing.

**JS9** V8 optimizes via hidden classes (shapes) for fast property access, and inline caching (IC) for repeated property/method lookups. Deoptimization occurs when assumptions break: dynamic property addition, changing property types, prototype changes, or using `delete`. Patterns causing deopt: adding properties after object creation, mixing types in arrays, heavy prototype manipulation, and using `with`/`eval`.

**JS10** Tree-shaking is static analysis that removes unused exports from bundles. It works with ES modules because `import`/`export` are statically analyzable. CommonJS (`require`/`module.exports`) is dynamic/runtime-evaluated, so bundlers can't determine dependencies at build time, making effective tree-shaking impossible without workarounds.

**JS11** `undefined` means declared but unassigned; `null` means intentional absence. `==` coerces types: `null == undefined` is `true`. `===` checks type & value: `null === undefined` is `false`. `??` (nullish coalescing) returns the right operand only if left is `null`/`undefined`. `?.` (optional chaining) safely accesses nested properties, short-circuiting to `undefined` if any part is nullish.

**JS12** `map()` transforms each element, returning a new array. `filter()` keeps elements matching a predicate. `reduce()` accumulates values into a single result; the initial value sets the starting accumulator (avoids `undefined` on empty arrays). `flatMap()` maps then flattens one level; useful when mapping produces arrays (e.g., splitting strings, avoiding nested loops).

**JS13** Template literals use backticks with `${expr}` interpolation. Tagged templates pass a function that receives an array of static strings and interpolated values. Example: `function escape(strings, ...values) { return strings.reduce((acc, str, i) => acc + str + (values[i]?.replace(/[&<>"']/g, m => `&#${m.charCodeAt(0)};`) || ''), ''); }` enables safe HTML/SQL generation.

**JS14** Destructuring unpacks values into variables. Object: `const {a, b} = obj`. Array: `const [x, y] = arr`. Defaults: `const {a = 1} = obj`. Renaming: `const {a: b} = obj`. Rest operator `...` collects remaining items: `const {a, ...rest} = obj` or `const [x, ...rest] = arr`.

**JS15** `for...in` iterates enumerable property keys (including inherited), order is not guaranteed. `for...of` iterates iterable values. Avoid `for...in` on arrays because it iterates indices as strings, includes non-index properties/methods, and order is unreliable. Use `for...of`, `forEach`, or standard `for` loops for arrays.

**JS16** Generics create reusable types with placeholders. Constraints: `T extends U` limits `T` to subtypes of `U`. Conditional types: `T extends U ? X : Y` branches types. `infer` extracts types in conditional contexts. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T;` extracts the resolved type from a Promise.

**JS17** CommonJS (`require`/`module.exports`) is synchronous, runtime-evaluated, Node's default. ES Modules (`import`/`export`) are asynchronous, static, web-standard. Node handles both via file extension detection or `"type": "module"` in `package.json` (treats `.js` as ESM). ESM enables static analysis, top-level `await`, and better tree-shaking.

**JS18** TypeScript uses structural typing: compatibility depends on shape, not declaration. Excess property checks only apply to direct object literals assigned to typed variables/functions. `extends` checks assignability. `satisfies` (TS 4.9) checks type compatibility without widening/narrowing, preserving inference. Variance (`in`/`out`, TS 4.7+) marks generic parameters as contravariant (input) or covariant (output) for stricter checking.

**JS19** `Proxy` intercepts fundamental operations via traps. `Reflect` provides static methods mirroring traps, used for default behavior. Intercept access: `get`, assignment: `set`, calls: `apply`. Example: reactive validation by logging/validating in the `set` trap, or creating observable objects that trigger callbacks on property changes.

**JS20** `SharedArrayBuffer` is a fixed-length binary buffer shared across threads. `Atomics` provides thread-safe operations. Workers communicate via shared memory + `Atomics.wait`/`notify` for synchronization. Ordering is sequentially consistent. `Atomics.wait` blocks until the value changes or times out; `Atomics.notify` wakes waiting threads. Enables lock-free, high-performance parallelism.

## Bash

**B1** `$@` and `$*` expand to positional parameters. `"$@"` expands to each parameter as a separate quoted word, preserving spaces/newlines. `"$*"` expands to a single word with parameters joined by the first character of `IFS` (usually space). Unquoted, both undergo word splitting and globbing.

**B2** `set -e`: exit immediately if any command fails. `set -u`: treat unset variables as errors. `set -o pipefail`: pipeline returns the exit status of the last command to exit non-zero (or 0 if all succeed). Together they form "strict mode" for robust, fail-fast scripts.

**B3** `$(command)` and `` `command` `` both perform command substitution, but `$()` is nestable, cleaner, and doesn't require escaping backticks. `$((expression))` is built-in arithmetic expansion (fast, no subshell). `expr` is an external command, slower, and requires escaping operators like `*` and `(`.

**B4** Process substitution `<(...)` runs a command and provides its output as a file descriptor path. Useful when commands expect files but you have command output. Example: `diff <(sort file1) <(sort file2)` compares sorted outputs without creating temporary files.

**B5** Use `while IFS= read -r -d '' file; do ... done < <(find . -type f -print0)` or globbing `for f in *; do ...`. `for f in $(ls)` is dangerous because word splitting breaks on spaces/newlines, globbing expands unexpectedly, and it fails on filenames with special characters.

**B6** Here document `<<EOF` feeds multi-line input until the delimiter. Here string `<<<` feeds a single string. `<<-EOF` strips leading tabs (not spaces) from the delimiter and content, allowing indented scripts without affecting input.

**B7** Redirections process left-to-right. `cmd > file 2>&1`: stdout goes to file, stderr redirected to where stdout points (file). Both go to file. `cmd 2>&1 > file`: stderr redirected to original stdout (terminal), then stdout redirected to file. Only stdout goes to file. `cmd &> file` is bash shorthand for both to file.

**B8** Use `mkdir` for atomic locking: `if mkdir /tmp/mylock 2>/dev/null; then trap 'rmdir /tmp/mylock' EXIT; ... else echo "locked"; exit 1; fi`. `mkdir` is atomic on POSIX, preventing race conditions. `trap` ensures cleanup on `EXIT`/`SIGTERM`. File creation (`touch`) isn't atomic for exclusive locking.

**B9** Single quotes `'...'`: literal, no expansion. Double quotes `"..."`: allow variable/command expansion, preserve spaces. No quotes: word splitting and globbing occur. Example: `echo $var` (splits on spaces), `echo "$var"` (preserves), `echo '$var'` (prints literal `$var`).

**B10** `-e` exists, `-d` directory, `-r` readable. `[ ]` is POSIX `test`, limited, requires careful quoting. `[[ ]]` is a bash keyword supporting pattern matching, regex, logical operators without quoting, and safer evaluation.

**B11** `$?`: exit status of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: number of positional parameters. Use cases: error checking, logging/debugging, job control, argument validation.

**B12** Define: `foo() { ... }` (POSIX) or `function foo { ... }` (bash). Both work; POSIX prefers the former. Return values: `return` sets exit status (0-255). Output via `echo`/`printf` captured with `$()`. Bash functions don't return values like other languages.

**B13** `PATH`: colon-separated directories for command lookup. Bash searches builtins first, then functions, then `PATH`. Builtins are part of the shell (faster, no fork). External commands are separate binaries. Check with `type cmd` or `command -v cmd`.

**B14** `trap 'cmd' SIGNAL` runs `cmd` on signal. `EXIT` runs on script exit. `ERR` on command failure (with `-e`). `INT`/`TERM` on signals. Signals handled immediately; `EXIT` runs last. Multiple traps for same signal: last one wins. Use `trap -p` to list.

**B15** `xargs` builds/executes commands from stdin. Command substitution captures output. `find -print0 | xargs -0` handles spaces/newlines safely. `xargs -P N` runs N jobs in parallel. Trade-offs: CPU/memory vs I/O, output interleaving, error propagation requires tracking exit statuses.

**B16** Indexed arrays: `arr=(a b c)`, append `arr+=d`, iterate `for i in "${arr[@]}"; do`, length `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, iterate `for k in "${!assoc[@]}"; do`, length `${#assoc[@]}`. Associative requires bash 4+, syntax differs, unordered.

**B17** Subshell `(...)`: runs in child process, variables don't persist, exit code is last command's. Group `{ ...; }`: runs in current shell, variables persist, requires semicolon after last command. Piping creates subshells for each segment, so `while` in pipe loses variable changes. Use process substitution or `shopt -s lastpipe`.

**B18** Signals: `SIGINT` (Ctrl+C), `SIGTERM` (graceful kill), `SIGHUP` (hangup/terminal close), `SIGKILL` (force, uncatchable). Job control: `jobs`, `fg`, `bg`, `disown`. Graceful shutdown: trap `TERM`/`INT`, kill child PIDs, cleanup, exit. Use `wait` for background jobs.

**B19** Script: `split -l 10000 log.txt chunk_`, `xargs -P 4 -I {} bash -c 'process_chunk {} > {}.out' _ < <(ls chunk_*)`, `cat chunk_*.out > merged.log`. Trade-offs: CPU/memory vs I/O, race conditions on output, error propagation requires checking each job's exit status (e.g., `set -o pipefail`, track failures in temp files).

**B20** `exec` replaces shell process with command (no return). For FDs: `exec 3>file` opens FD 3, `exec 3>&-` closes it. Coprocess: `coproc name { cmd; }` creates bidirectional pipe. Use for interactive programs or continuous data streams. FD manipulation enables custom logging, input/output routing.

## PowerShell

**PS1** `Write-Output` sends objects down the pipeline. `Write-Host` writes directly to the console, bypassing the pipeline. This matters because `Write-Host` breaks pipeline chaining and should only be used for user-facing display, not data passing.

**PS2** The pipeline passes objects cmdlet-to-cmdlet. `ForEach-Object` processes pipeline objects one-by-one (streaming, memory efficient). `foreach` statement loads the entire collection into memory first, then iterates (faster for in-memory data). Use `ForEach-Object` for large streams, `foreach` for speed on arrays.

**PS3** `[PSCustomObject]` is strongly typed, preserves property order, supports methods, and is pipeline-friendly. `[hashtable]` is unordered, key-value pairs, faster for lookups. Convert: `[PSCustomObject]@{k='v'}` or `@{k='v'} | ConvertTo-Json`. Hashtables to objects via casting or `New-Object`.

**PS4** Terminating errors stop execution, caught by `try/catch`. Non-terminating errors continue, written to the error stream, controlled by `-ErrorAction`/`$ErrorActionPreference`. `try/catch` only catches terminating. Set `$ErrorActionPreference = 'Stop'` or use `-ErrorAction Stop` to make non-terminating errors terminating.

**PS5** Splatting: `@{Param1='val'; Param2='val'}` passed as `Cmdlet @params`. Expands to named arguments. Differs from passing a hashtable as a single parameter because splatting maps keys to cmdlet parameters, while a single parameter passes the hashtable object itself.

**PS6** Remoting: `Invoke-Command` runs a scriptblock on a remote machine, returns results. `Enter-PSSession` opens an interactive remote shell. Uses WS-Management (WinRM) over HTTP/HTTPS, or SSH in PS7. Requires firewall/config setup and proper authentication.

**PS7** PowerShell unwraps single-element arrays. `$x.GetType().Name` is `String`, not `Object[]`. Returns 0 items: `$null`. Correct pattern: use `return @($result)` or `[array]$result` to force array type, or explicitly handle unwrapping. Functions should avoid `+=` on arrays for performance; use `[System.Collections.Generic.List[object]]` instead.

**PS8** `[scriptblock]` is a compiled code block; functions are named scriptblocks with parameters. Pass via `-ScriptBlock` or `-ArgumentList`. Double-hop: credential delegation fails when a remote session accesses another resource. Solve with CredSSP, Kerberos constrained delegation, or pass data via `-ArgumentList` instead of credentials.

**PS9** `@()` is an array literal; `[array]` is a type accelerator. Force single to array: `@($item)` or `[array]$item`. Indexing `$null[0]` returns `$null`; empty array `@()[0]` returns `$null`. Use `@()` to guarantee array type and avoid unwrapping surprises.

**PS10** `-eq`/`-ne`: equality/inequality. `-like`/`-notlike`: wildcard. `-match`/`-notmatch`: regex. `-contains`/`-in`: membership. Case-sensitive: `-ceq`, `-clike`, `-cmatch`, `-ccontains`, `-cin`. `-contains` checks if collection has item; `-in` checks if item is in collection (reversed operands).

**PS11** Module: reusable package of functions/cmdlets. Script module: `.psm1` file. Manifest: `.psd1` metadata/config. Binary: compiled `.dll`. `Import-Module` loads into session, searches `$env:PSModulePath`, exports members based on manifest/script.

**PS12** Interpolation: `"Value is $var"` or `"Value is $($expr)"`. Single quotes `'...'` are literal. Here-string: `@" ... "@` or `@' ... '@` for multi-line, preserves formatting. Expressions in strings require `$()`.

**PS13** `Get-Member` shows object type, properties, methods. `Properties`: data, `Methods`: actions, `NoteProperties`: custom added via `Add-Member` or `Select-Object`. `Select-Object` filters/creates new objects with specific properties. `Where-Object` filters pipeline objects by condition.

**PS14** Classes (v5+): define types with properties/methods. Differs from C#: no inheritance, no interfaces, limited constructors, no access modifiers beyond `hidden`. Use for structured data/validation. Functions better for logic/pipeline processing.

**PS15** `[CmdletBinding()]` enables advanced function features: common parameters, pipeline binding, should process. `SupportsShouldProcess`: enables `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: controls parameter sets. `ValueFromPipeline`: binds pipeline input. `Begin/Process/End`: `Begin` runs once, `Process` per item, `End` once after pipeline.

**PS16** Providers: expose non-filesystem data as drive-like paths. `Get-ChildItem` works across them via `PSProvider` property. Registry: `HKLM:\`, Certificates: `Cert:\`, Environment: `Env:\`. Access registry like FS: `Get-ChildItem HKLM:\SOFTWARE`.

**PS17** Runspaces: isolated execution environments. `[runspace]` single, `[runspacepool]` multiple. `[powershell]` object adds commands to runspace. `ForEach-Object -Parallel` (v7+) simplifies parallelism, handles serialization automatically. Manual runspace gives more control but requires thread safety management.

**PS18** PSScriptAnalyzer: static analysis tool. Enforces standards via rules (e.g., `PSAvoidUsingWriteHost`). Severity: Error/Warning/Information. Custom rules: C# or PowerShell scripts. Suppress: `[SuppressMessage()]` or `PSScriptAnalyzerSettings.psd1`. CI/CD: run as pre-commit or pipeline step, fail on errors.

**PS19** `$using:var` passes variable value to remote/parallel context. `$args`/`-ArgumentList` passes positional/named args. Serialization: CLIXML depth limit (~50), complex objects (COM, WMI, custom) may lose data or fail. Use `[PSCustomObject]` or serialize to JSON for complex data.

**PS20** DSC: declarative config management. Configurations: define desired state. Resources: modules implementing state enforcement. LCM: agent enforcing config. PS5 vs PS7: PS7 drops some Windows-specific resources, focuses on cross-platform. Replaced by modern IaC: Terraform, Ansible, Bicep, ARM templates.
