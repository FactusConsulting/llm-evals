# Complete Answers

## Networking (20 questions)

**N1** — A Layer 2 switch forwards frames based on MAC addresses using a MAC address table. It operates at the Data Link layer and cannot route between subnets. A Layer 3 switch can perform both Layer 2 switching and Layer 3 routing—it maintains a routing table, supports IP routing, and can do inter-VLAN routing without needing an external router.

**N2** — For 10.0.5.37/20:
- Subnet mask: 255.255.240.0
- Network address: **10.0.0.0** (10.0.5.37 AND 255.255.240.0)
- Broadcast address: **10.0.15.255** (network + 4095)
- Host range: 10.0.0.1 – 10.0.15.254

**N3** — The TCP three-way handshake:
1. **SYN**: Client sends SYN with initial sequence number (ISN)
2. **SYN-ACK**: Server responds with its own SYN and ACK for client's ISN
3. **ACK**: Client acknowledges server's SYN

If the final ACK is lost, the server retransmits its SYN-ACK. The connection is half-open from the server's perspective until it receives the ACK or times out. The client considers the connection established and can send data.

**N4** — **SNAT (Source NAT)** changes the source IP of outbound packets. Example: Internal hosts (10.0.0.0/24) accessing the internet appear to come from the gateway's public IP.

**DNAT (Destination NAT)** changes the destination IP of inbound packets. Example: Port forwarding—external traffic to public IP:8080 is redirected to internal server 10.0.0.50:80.

**N5** — Three possible causes:
1. The certificate was issued for a different hostname (wrong CN or SAN)
2. SNI (Server Name Indication) is not configured, and the server returns a default certificate
3. The certificate has expired or is not yet valid

**N6** — **VLAN** uses 802.1Q tagging with a 12-bit VLAN ID (max 4094 VLANs), operates at Layer 2, and is limited to a single broadcast domain. **VxLAN** encapsulates Ethernet frames in UDP with a 24-bit VNI (16 million segments), creating an overlay network.

Choose VxLAN for: multi-tenant cloud environments, large-scale deployments exceeding 4094 segments, multi-site connectivity, or when you need to extend Layer 2 across Layer 3 boundaries.

**N7** — **Why**: The default route points to eth0 (10.0.0.1), so all non-local traffic—including replies to eth1—goes out eth0.

**Fix with policy-based routing**:
```bash
# Create custom routing table (e.g., table 100)
echo "100 eth1" >> /etc/iproute2/rt_tables

# Add route for eth1's subnet in custom table
ip route add 192.168.1.0/24 dev eth1 src 192.168.1.5 table 100

# Add default route via eth1's gateway in custom table
ip route add default via 192.168.1.1 dev eth1 table 100

# Create policy rule: traffic from eth1's subnet uses table 100
ip rule add from 192.168.1.5 table 100

# Or use iif (incoming interface) for more precision
ip rule add iif eth1 table 100
```

**N8** — BGP path selection (in order of preference):
1. **Highest LOCAL_PREF** (local preference)
2. **Shortest AS_PATH** (fewest AS hops)
3. **Lowest ORIGIN type** (IGP < EGP < INCOMPLETE)
4. **Lowest MED** (Multi-Exit Discriminator)
5. **eBGP over iBGP** paths
6. **Lowest IGP metric** to next-hop
7. **Oldest path** (for eBGP)
8. **Lowest Router ID**
9. **Lowest cluster list length** (for route reflectors)
10. **Lowest peer IP**

**N9** — MTU calculation with VxLAN over IPsec:
- Physical MTU: 1500 bytes
- IPsec overhead: ~60 bytes (ESP header + trailer + auth)
- Outer IP header: 20 bytes
- UDP header: 8 bytes
- VxLAN header: 8 bytes
- Inner Ethernet header: 14 bytes
- Inner IP header: 20 bytes

**Maximum inner payload**: 1500 - 60 - 20 - 8 - 8 - 14 - 20 = **1370 bytes**

This means you need jumbo frames (MTU 9000) on physical interfaces for normal TCP MSS, or reduce MSS via MTU discovery.

**N10** — **ARP (Address Resolution Protocol)** maps IP addresses to MAC addresses on a local network. A host broadcasts an ARP request ("Who has IP X?") and the owner replies with its MAC.

**Gratuitous ARP** is an unsolicited ARP reply broadcast by a host announcing its own IP-MAC mapping. It solves:
- IP conflict detection (another host responds if it has the same IP)
- Updating ARP caches after NIC replacement or failover
- Initial ARP cache population

**N11** — **Public IP**: Globally routable, assigned by ISPs/RIRs, unique on the internet. **Private IP**: Not routable on the internet, used within private networks, can be reused.

**RFC 1918 private ranges**:
- 10.0.0.0 – 10.255.255.255 (10.0.0.0/8)
- 172.16.0.0 – 172.31.255.255 (172.16.0.0/12)
- 192.168.0.0 – 192.168.255.255 (192.168.0.0/16)

**N12** — **DNS (Domain Name System)** translates human-readable domain names to IP addresses.

- **A record**: Maps hostname to IPv4 address (e.g., `example.com → 93.184.216.34`)
- **CNAME record**: Alias pointing to another hostname (e.g., `www.example.com → example.com`)
- **AAAA record**: Maps hostname to IPv6 address (e.g., `example.com → 2606:2800:220:1:248:1893:25c8:1946`)

**N13** — **DHCP (Dynamic Host Configuration Protocol)** automatically assigns IP addresses and network configuration.

**DORA process**:
1. **Discover**: Client broadcasts DHCPDISCOVER
2. **Offer**: Server responds with DHCPOFFER (proposed IP)
3. **Request**: Client broadcasts DHCPREQUEST (accepts offer)
4. **Acknowledge**: Server sends DHCPACK with lease details

**N14** — 
- **Hub**: Physical layer (Layer 1) device that repeats signals to all ports. Creates a single collision domain.
- **Switch**: Data Link layer (Layer 2) device that forwards frames based on MAC addresses. Creates separate collision domains per port.
- **Router**: Network layer (Layer 3) device that forwards packets between networks based on IP addresses. Creates separate broadcast domains.

**N15** — **Half-duplex**: Communication in only one direction at a time (like walkie-talkies). Uses CSMA/CD for collision detection. **Full-duplex**: Simultaneous two-way communication (like a phone call). Uses separate transmit/receive pairs.

Modern Ethernet links use **full-duplex** exclusively. Half-duplex is obsolete except for legacy 10BASE2/10BASE5 coaxial networks.

**N16** — **TTL (Time To Live)** is an 8-bit field that limits packet lifetime. Each router decrements TTL by 1; when TTL reaches 0, the packet is dropped and an ICMP "Time Exceeded" message is sent.

**Traceroute** exploits this by:
1. Sending packets with TTL=1 (first hop drops and replies)
2. Sending packets with TTL=2 (second hop drops and replies)
3. Continuing until destination is reached
Each ICMP reply reveals one hop's IP address.

**N17** — A **NAT gateway** translates private IPs to public IPs (and vice versa) for internet connectivity.

- **Static NAT**: One-to-one fixed mapping (e.g., internal 10.0.0.5 always maps to public 203.0.113.5)
- **Dynamic NAT**: One-to-one mapping from a pool of public IPs (first-come, first-served)
- **PAT (Port Address Translation)**: Many-to-one mapping using port numbers (most common; multiple internal hosts share one public IP with different source ports)

**N18** — **ECMP** distributes traffic across multiple equal-cost paths to the same destination.

**Hashing strategies**:
- 5-tuple hash (src IP, dst IP, src port, dst port, protocol)
- 3-tuple hash (src IP, dst IP, protocol)
- XOR-based hashing for load balancing

**Asymmetric flow problem**: If a request takes path A but the reply takes path B, a stateful firewall on path A sees an unsolicited incoming packet and drops it. Solutions include: pinning flows to specific paths, using stateless firewalls, or ensuring symmetric routing.

**N19** — **Problem**: The bandwidth-delay product (BDP) is 10MB, but the TCP window is capped at 64KB. This means only 64KB of data can be "in flight" at once, severely underutilizing the available bandwidth on high-latency links.

**TCP Window Scaling (RFC 1323)**: The window scale option allows the window field to be shifted left by up to 14 bits, effectively multiplying the 16-bit window by up to 16384. This enables windows up to ~1GB, allowing full utilization of high BDP connections.

**N20** — **802.1Q trunk ports** carry traffic for multiple VLANs by inserting a 4-byte tag between the source MAC and EtherType fields.

**Linux configuration**:
```bash
# Create VLAN sub-interfaces
ip link add link eth0 name eth0.10 type vlan id 10
ip link add link eth0 name eth0.20 type vlan id 20
ip link add link eth0 name eth0.30 type vlan id 30

# Assign IPs and bring up
ip addr add 10.0.10.5/24 dev eth0.10
ip addr add 10.0.20.5/24 dev eth0.20
ip addr add 10.0.30.5/24 dev eth0.30
ip link set eth0.10 up
ip link set eth0.20 up
ip link set eth0.30 up
```

**Frame format on wire**:
```
| Dest MAC (6) | Src MAC (6) | 8100 (2) | Priority (3) | CFI (1) | VLAN ID (12) | EtherType (2) | Payload | FCS (4) |
```

## Linux (20 questions)

**L1** — A **hard link** is another directory entry pointing to the same inode as the original file. It cannot cross filesystems, and the file persists until all hard links are deleted. A **symbolic link (symlink)** is a special file containing a path to another file. It can cross filesystems, can point to non-existent targets (dangling), and is deleted independently of its target.

**L2** — 
```bash
find /var/log -type f -size +100M
```
Or with human-readable output:
```bash
find /var/log -type f -size +100M -exec ls -lh {} \;
```

**L3** — State **D (uninterruptible sleep)** means the process is waiting for I/O (typically disk) to complete. The process **cannot be killed with `kill -9`** because it's in kernel space waiting for hardware. It will only become killable when the I/O completes or the device becomes responsive. This often indicates disk problems or NFS hangs.

**L4** — **cgroups v1**: Hierarchical, per-subsystem trees (cpu, memory, etc. each have their own hierarchy). **cgroups v2**: Single unified hierarchy, simpler design, better performance, supports more controllers.

**systemd prefers cgroups v2** because: unified hierarchy simplifies management, better integration with systemd slices, improved performance, and it's the direction of kernel development. Enable with `systemd.unified_cgroup_hierarchy=1` kernel parameter.

**L5** — **iptables** is the legacy netfilter interface with separate tables (filter, nat, mangle, raw). **nftables** is the modern replacement with a unified syntax, better performance, and more flexible rule organization.

The kernel handles both via the same netfilter hooks. When nftables is used, iptables commands are translated to nftables rules via `libnftnl`. They can coexist but using both simultaneously is discouraged.

**L6** — The most likely cause is **deleted files that are still open by running processes**. When a file is deleted but a process holds it open, the space isn't freed until the process closes it or terminates.

Check with:
```bash
lsof +L1 /var/log
# or
find /proc/*/fd -lname 'deleted:' 2>/dev/null
```

**L7** — **Linux boot process**:

1. **UEFI firmware**: Initializes hardware, loads Secure Boot keys, reads EFI System Partition
2. **Bootloader (GRUB)**: Loads kernel image and initramfs into memory, passes kernel parameters
3. **Kernel**: Initializes CPU, memory, drivers; mounts initramfs as root
4. **Initramfs**: Contains minimal userspace; runs `/init` script to mount real root filesystem
5. **Real root**: Kernel switches to actual root filesystem
6. **systemd**: PID 1 starts; reads `/etc/systemd/system.target.wants/` and starts services
7. **Target reached**: `multi-user.target` or `graphical.target` completes; login prompts appear

**L8** — **Why available is low**: The 15GB buff/cache is not immediately reclaimable because:
- Some cache is "dirty" (modified but not written to disk)
- Kernel's memory pressure algorithm may not aggressively reclaim under certain conditions
- The OOM killer uses a different calculation than `free -h`

**Relevant kernel tunables**:
- `vm.swappiness`: Controls swap usage (0-100)
- `vm.overcommit_memory`: Memory overcommit strategy
- `vm.vfs_cache_pressure`: How aggressively to reclaim inode/dentry cache
- `vm.min_free_kbytes`: Minimum free memory to maintain

**L9** — **`ip netns`** creates isolated network namespaces—each has its own network stack (interfaces, routing tables, firewall rules, port bindings).

**Container runtimes use netns** to give each container its own network isolation. Docker creates a network namespace per container, adds a veth pair (one end in container, one in host), and bridges them. This allows containers to have independent IP addresses, routing, and firewall rules while sharing the host kernel.

**L10** — 
- **SIGTERM (15)**: Polite termination request. Process can catch, handle cleanup, and exit gracefully.
- **SIGKILL (9)**: Immediate termination. Cannot be caught or ignored. Kernel forcibly stops the process.
- **SIGQUIT (3)**: Termination with core dump. Can be caught; often used to trigger debug dumps.

**SIGTERM and SIGQUIT can be caught**; SIGKILL cannot.

**L11** — 
- **stdin (fd 0)**: Standard input
- **stdout (fd 1)**: Standard output
- **stderr (fd 2)**: Standard error

**Redirect stderr to file, stdout to terminal**:
```bash
command 2>error.log
# or with tee to also see stdout
command 2>error.log | tee output.log
```

**L12** — `chmod 755` sets:
- **7 (owner)**: read (4) + write (2) + execute (1) = full access
- **5 (group)**: read (4) + execute (1) = read and execute
- **5 (others)**: read (4) + execute (1) = read and execute

Result: Owner can read/write/execute; group and others can only read and execute.

**L13** — **Root user** (UID 0) has unrestricted system access—can modify any file, kill any process, change kernel parameters. **Sudo privileges** grant temporary elevated access to specific commands or all commands, with logging and potential restrictions via `/etc/sudoers`. Sudo provides accountability and can be limited to specific actions.

**L14** — A **package manager** automates software installation, updates, and dependency resolution.

- **Debian/Ubuntu**: `apt` (or `apt-get`, `aptitude`)
- **RHEL/Fedora**: `dnf` (Fedora, RHEL 8+) or `yum` (older RHEL/CentOS)

**L15** — **`/etc/fstab`** defines filesystem mount points, options, and order at boot. Format: `<device> <mountpoint> <type> <options> <dump> <pass>`

**If misconfigured**: System may fail to boot, hang waiting for a non-existent device, or mount filesystems with wrong options. Check with `mount -a` before rebooting.

**L16** — **LVM** provides flexible storage management:
- **Physical Volume (PV)**: Raw storage device or partition
- **Volume Group (VG)**: Pool of one or more PVs
- **Logical Volume (LV)**: Virtual partition carved from a VG

**Extend a logical volume**:
```bash
# Add new disk as PV
pvcreate /dev/sdb

# Extend VG
vgextend myvg /dev/sdb

# Extend LV
lvextend -L +10G /dev/myvg/mylv

# Resize filesystem
resize2fs /dev/myvg/mylv    # ext4
xfs_growfs /mount/point     # xfs
```

**L17** — **I/O schedulers** order disk requests:

- **mq-deadline**: Maintains separate read/write queues with deadlines. Good for general-purpose workloads.
- **bfq (Budget Fair Queueing)**: Per-process fairness, good for mixed workloads and latency-sensitive applications.
- **none**: No scheduling; requests go directly to hardware. Best for SSDs with native queuing.

**Change scheduler at runtime**:
```bash
echo none > /sys/block/sda/queue/scheduler
# Or permanently via kernel parameter: elevator=none
```

**L18** — **Load average** measures processes in **R (running)** and **D (uninterruptible sleep)** states over 1, 5, and 15 minutes.

**I/O wait inflates load** because processes waiting for disk are in state D, counted in load average but not in CPU usage.

**Diagnosis**:
```bash
# Overall system state
top -b -n 1 | head -20

# I/O wait specifically
iostat -x 1 5

# Per-process I/O
pidstat -d 1 5

# Check for slow disks
iostat -x 1 | grep -E "await|await|util"

# Network I/O
iftop -n
```

High `await` (>10ms) indicates disk bottleneck; high `%util` (>80%) indicates saturation.

**L19** — **SELinux** enforces Mandatory Access Control (MAC) by labeling all objects (files, processes, ports) with types and enforcing policies that define allowed interactions.

**Modes**:
- **Enforcing**: Violations are blocked and logged
- **Permissive**: Violations are logged but allowed
- **Disabled**: SELinux is turned off

**Troubleshoot port binding**:
```bash
# Check current mode
getenforce

# View denials
ausearch -m avc -ts recent | grep port

# Check allowed ports for the service type
semanage port -l | grep http_port_t

# Add port to allowed list
semanage port -a -t http_port_t -p tcp 8080

# Or temporarily set permissive for debugging
setenforce 0
```

**L20** — **Page faults** occur when a process accesses a virtual address not mapped to physical memory.

- **Minor page fault**: Page is in memory but not mapped to the process (e.g., copy-on-write). Fast resolution.
- **Major page fault**: Page must be read from disk (swap or file). Slow, involves I/O.

**Transparent Huge Pages (THP)**: Automatically uses 2MB pages instead of 4KB, reducing TLB misses. However, THP can cause:
- Latency spikes during page allocation
- Memory fragmentation
- Performance issues with certain workloads (databases, real-time apps)

**Disable THP**:
```bash
echo never > /sys/kernel/mm/transparent_hugepage/enabled
echo never > /sys/kernel/mm/transparent_hugepage/defrag
```
