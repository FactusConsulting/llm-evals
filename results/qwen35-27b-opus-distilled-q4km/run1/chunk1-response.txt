# Complete Answers

## Networking (20 questions)

**N1** — A Layer 2 switch forwards frames based on MAC addresses using a MAC address table. It operates at the Data Link layer and cannot route between subnets. A Layer 3 switch can perform both Layer 2 switching and Layer 3 routing, forwarding packets based on IP addresses and routing between VLANs/subnets without needing an external router.

**N2** — For 10.0.5.37/20:
- Subnet mask: 255.255.240.0
- Network address: **10.0.0.0** (10.0.5.37 AND 255.255.240.0)
- Broadcast address: **10.0.15.255** (network + 4095)
- Host range: 10.0.0.1 - 10.0.15.254

**N3** — TCP three-way handshake:
1. **SYN**: Client sends SYN with initial sequence number (ISN)
2. **SYN-ACK**: Server responds with its own SYN and ACK for client's ISN
3. **ACK**: Client acknowledges server's SYN

If the final ACK is lost, the server retransmits the SYN-ACK. The client, having already sent the ACK, will respond with another ACK when it receives the retransmitted SYN-ACK. The connection is established on the client side after sending the ACK, but the server won't consider it established until it receives the ACK.

**N4** — 
- **SNAT (Source NAT)**: Changes the source IP of outbound packets. Example: Internal hosts (10.0.0.0/24) accessing the internet appear to come from the gateway's public IP.
- **DNAT (Destination NAT)**: Changes the destination IP of inbound packets. Example: A load balancer with public IP 203.0.113.1:80 forwards traffic to backend servers at 10.0.1.10:8080, 10.0.1.11:8080.

**N5** — Three possible causes:
1. The certificate was issued for a different hostname (e.g., `www.example.com` instead of `example.com`)
2. The certificate's Subject Alternative Name (SAN) doesn't include the target hostname
3. You're connecting via IP address instead of the domain name, and the certificate doesn't include that IP

**N6** — 
- **VLAN**: Uses 802.1Q tagging with a 12-bit VLAN ID (max 4094 VLANs). Operates at Layer 2 within a single broadcast domain.
- **VxLAN**: Uses a 24-bit VNI (16 million segments). Encapsulates Ethernet frames in UDP packets, allowing overlay networks across Layer 3 boundaries.

Choose VxLAN when you need more than 4094 segments, multi-tenant cloud environments, or when you need to extend Layer 2 across Layer 3 boundaries (e.g., across data centers).

**N7** — The problem occurs because the default route points to eth0 (10.0.0.1), so all return traffic uses eth0 regardless of which interface received the request.

**Fix with policy-based routing:**
```bash
# Create custom routing table (e.g., table 100)
echo "100 eth1_table" >> /etc/iproute2/rt_tables

# Add route for eth1's subnet in custom table
ip route add 192.168.1.0/24 dev eth1 src 192.168.1.5 table 100

# Add default route via eth1's gateway in custom table
ip route add default via 192.168.1.1 dev eth1 table 100

# Add policy rule: traffic from eth1's subnet uses table 100
ip rule add from 192.168.1.5 table 100

# Or use iif (incoming interface) based routing
ip rule add iif eth1 table 100
```

**N8** — BGP path selection (in order of preference):
1. **Highest LOCAL_PREF** (local preference)
2. **Shortest AS_PATH** (fewest AS hops)
3. **Lowest ORIGIN type** (IGP < EGP < INCOMPLETE)
4. **Lowest MED** (Multi-Exit Discriminator)
5. **eBGP over iBGP** paths
6. **Lowest IGP metric** to next-hop
7. **Oldest route** (for eBGP)
8. **Lowest Router ID**
9. **Lowest cluster list length** (for route reflectors)
10. **Lowest peer IP address**

**N9** — MTU calculation with VxLAN over IPsec:
- Physical MTU: 1500 bytes
- Ethernet header: 14 bytes
- Outer IP header: 20 bytes
- ESP header + trailer + auth: ~50-60 bytes (IPsec)
- Outer UDP header: 8 bytes
- VxLAN header: 8 bytes
- Inner Ethernet header: 14 bytes
- Inner IP header: 20 bytes

**Maximum inner payload** = 1500 - 14 - 20 - 60 - 8 - 8 - 14 - 20 = **1356 bytes**

This is well below the typical 1460-byte TCP MSS, causing fragmentation. Solution: Enable jumbo frames (MTU 9000) on physical interfaces.

**N10** — ARP (Address Resolution Protocol) resolves IPv4 addresses to MAC addresses on a local network. A host broadcasts an ARP request asking "Who has IP X?" and the owner responds with its MAC address.

**Gratuitous ARP** is an ARP request a host sends for its own IP address. It solves:
- Announcing a new host's presence on the network
- Updating ARP caches after a MAC address change (e.g., NIC replacement)
- Detecting IP address conflicts
- Failover announcements in HA setups

**N11** — 
- **Public IP**: Routable on the internet, assigned by ISPs/RIRs
- **Private IP**: Not routable on the internet, used within private networks

**RFC 1918 private ranges:**
- 10.0.0.0 – 10.255.255.255 (10.0.0.0/8)
- 172.16.0.0 – 172.31.255.255 (172.16.0.0/12)
- 192.168.0.0 – 192.168.255.255 (192.168.0.0/16)

**N12** — DNS (Domain Name System) translates human-readable domain names to IP addresses.
- **A record**: Maps hostname to IPv4 address (e.g., `example.com → 93.184.216.34`)
- **AAAA record**: Maps hostname to IPv6 address (e.g., `example.com → 2606:2800:220:1:248:1893:25c8:1946`)
- **CNAME record**: Alias that points to another hostname (e.g., `www.example.com → example.com`)

**N13** — DHCP (Dynamic Host Configuration Protocol) automatically assigns IP addresses and network configuration.

**DORA process:**
1. **Discover**: Client broadcasts DHCPDISCOVER to find DHCP servers
2. **Offer**: Server responds with DHCPOFFER containing available IP
3. **Request**: Client broadcasts DHCPREQUEST to accept the offer
4. **Acknowledge**: Server sends DHCPACK confirming the lease

**N14** — 
- **Hub**: Physical layer (Layer 1) device that repeats signals to all ports. Creates a single collision domain.
- **Switch**: Data Link layer (Layer 2) device that forwards frames based on MAC addresses. Creates separate collision domains per port.
- **Router**: Network layer (Layer 3) device that forwards packets between networks based on IP addresses. Creates separate broadcast domains.

**N15** — 
- **Half-duplex**: Communication in only one direction at a time (like a walkie-talkie). Uses CSMA/CD for collision detection.
- **Full-duplex**: Simultaneous two-way communication (like a telephone). No collisions possible.

Modern Ethernet links (100Mbps and above) use **full-duplex** exclusively.

**N16** — The TTL (Time To Live) field prevents packets from circulating indefinitely. Each router decrements TTL by 1; when TTL reaches 0, the packet is dropped and an ICMP "Time Exceeded" message is sent back.

**Traceroute** exploits this by:
1. Sending packets with TTL=1, receiving ICMP from first hop
2. Sending packets with TTL=2, receiving ICMP from second hop
3. Continuing until destination is reached
This reveals each router along the path.

**N17** — A NAT gateway translates private IPs to public IPs (and vice versa) to allow private networks to access the internet.

- **Static NAT**: One-to-one fixed mapping (e.g., internal 10.0.0.5 always maps to public 203.0.113.5)
- **Dynamic NAT**: One-to-one mapping from a pool of public IPs (first-come, first-served)
- **PAT (Port Address Translation)**: Many-to-one mapping using port numbers. Multiple internal hosts share one public IP, distinguished by source port. This is the most common form (also called NAT overload).

**N18** — ECMP allows traffic to be load-balanced across multiple equal-cost paths to the same destination.

**Hashing strategies:**
- 5-tuple hash (src IP, dst IP, src port, dst port, protocol)
- 3-tuple hash (src IP, dst IP, protocol)
- Source IP hash only

**Asymmetric flow problem:** When traffic takes different paths in each direction, stateful firewalls may drop return packets because they weren't seen on the forward path. Solutions include:
- Using source IP hashing (ensures bidirectional traffic uses same path)
- Stateless firewall rules
- Connection tracking synchronization between firewalls

**N19** — The problem is a **small TCP window** limiting throughput. With a 10MB bandwidth-delay product but only 64KB window, the connection can only utilize ~0.6% of available capacity.

**TCP Window Scaling (RFC 1323)** adds a 4-bit shift count to the TCP header, allowing the window to be scaled by 2^shift. This enables windows up to 1GB (65535 × 2^14), matching high BDP networks.

**N20** — 802.1Q trunk ports carry traffic for multiple VLANs by adding a 4-byte tag to Ethernet frames.

**Linux configuration:**
```bash
# Create VLAN sub-interfaces
ip link add link eth0 name eth0.10 type vlan id 10
ip link add link eth0 name eth0.20 type vlan id 20
ip link add link eth0 name eth0.30 type vlan id 30

# Assign IPs and bring up
ip addr add 10.0.10.5/24 dev eth0.10
ip addr add 10.0.20.5/24 dev eth0.20
ip addr add 10.0.30.5/24 dev eth0.30
ip link set eth0.10 up
ip link set eth0.20 up
ip link set eth0.30 up
```

**Frame format on wire:**
```
| Dest MAC (6) | Src MAC (6) | 8100 (2) | Priority (3) | DEI (1) | VLAN ID (12) | EtherType (2) | Payload | FCS (4) |
```

## Linux (20 questions)

**L1** — 
- **Hard link**: Another directory entry pointing to the same inode. Cannot cross filesystems, cannot link directories. File persists until all hard links are deleted.
- **Symbolic link (soft link)**: A special file containing a path to another file. Can cross filesystems, can link directories, becomes broken if target is deleted.

**L2** — 
```bash
find /var/log -type f -size +100M
```
Or with human-readable sizes:
```bash
find /var/log -type f -size +100M -exec ls -lh {} \;
```

**L3** — State D (uninterruptible sleep) means the process is waiting for I/O (typically disk). It **cannot** be killed with `kill -9` because the kernel ignores signals for processes in this state. The process must complete its I/O operation first. This often indicates disk problems or slow storage.

**L4** — 
- **cgroups v1**: Hierarchical controllers in separate mount points (`/sys/fs/cgroup/cpu`, `/sys/fs/cgroup/memory`, etc.). Complex hierarchy management.
- **cgroups v2**: Unified hierarchy with all controllers in one mount point (`/sys/fs/cgroup`). Simpler, more consistent.

**systemd prefers cgroups v2** because it provides a unified view, better integration with systemd slices, and simpler management. However, v1 is still widely used for compatibility.

**L5** — 
- **iptables**: Legacy netfilter interface using tables (filter, nat, mangle, raw) and chains.
- **nftables**: Modern replacement with unified syntax, better performance, and more flexible rule sets.

The kernel handles both via the **netfilter framework**. nftables uses the same hooks but a different userspace API. They can coexist but shouldn't be used together for the same traffic.

**L6** — The most likely cause is **deleted files that are still open** by running processes. When a file is deleted but a process holds it open, the space isn't freed until the process closes it or terminates.

Check with:
```bash
lsof +L1 /var/log
# or
find /var/log -delete -exec ls -l {} \;  # won't work directly
# Better:
lsof | grep deleted
```

**L7** — Linux boot process:
1. **UEFI firmware**: Initializes hardware, loads bootloader from EFI System Partition
2. **Bootloader (GRUB)**: Presents menu, loads kernel and initramfs into memory
3. **Kernel**: Initializes hardware, mounts initramfs as temporary root
4. **Initramfs**: Contains minimal tools/drivers, runs scripts to mount real root filesystem
5. **Real root**: Kernel switches to actual root filesystem
6. **systemd**: Init process (PID 1) starts, loads units, reaches target (e.g., `multi-user.target` or `graphical.target`)

**L8** — Available memory can be low because:
- Buff/cache is reclaimable but not immediately available for new allocations
- The kernel's "available" calculation considers what can be freed quickly without swapping
- High memory pressure causes the kernel to be conservative about reclaiming cache

**Relevant tunables:**
- `vm.swappiness`: Controls tendency to swap (0-100)
- `vm.vfs_cache_pressure`: Controls reclaiming of inode/dentry cache
- `vm.min_free_kbytes`: Minimum free memory to maintain
- `vm.watermark_scale_factor`: Watermark scaling for memory zones

**L9** — `ip netns` creates isolated network namespaces, each with its own:
- Network stack (interfaces, routing tables, firewall rules)
- Port space
- ARP tables

**Container runtimes** (Docker, containerd) use network namespaces to isolate container networking. Each container gets its own namespace with a veth pair connecting it to the host or a bridge network.

**L10** — 
- **SIGTERM (15)**: Request for graceful termination. **Can be caught** and handled.
- **SIGKILL (9)**: Immediate termination. **Cannot be caught** or ignored.
- **SIGQUIT (3)**: Terminate and produce core dump. **Can be caught**.

**L11** — 
- **stdin (fd 0)**: Standard input
- **stdout (fd 1)**: Standard output
- **stderr (fd 2)**: Standard error

**Redirect stderr to file, stdout to terminal:**
```bash
command 2>error.log
```
Or redirect both separately:
```bash
command >output.txt 2>error.log
```

**L12** — `chmod 755` sets:
- **7 (owner)**: read (4) + write (2) + execute (1) = full permissions
- **5 (group)**: read (4) + execute (1) = read and execute
- **5 (others)**: read (4) + execute (1) = read and execute

Result: Owner can read/write/execute; group and others can only read and execute.

**L13** — 
- **Root user**: UID 0, has unrestricted system access, bypasses most security checks
- **Sudo privileges**: Regular user who can execute specific commands as root (or another user) via `/etc/sudoers`. Provides audit trail and can be restricted to specific commands.

**L14** — A package manager handles software installation, updates, and dependency resolution.

- **Debian/Ubuntu**: `apt` (or `apt-get`, `aptitude`)
- **RHEL/Fedora**: `dnf` (Fedora, RHEL 8+) or `yum` (older RHEL/CentOS)

**L15** — `/etc/fstab` defines filesystem mount points, options, and mount order at boot.

**If misconfigured:**
- System may fail to boot or enter emergency mode
- Filesystems may not mount or mount with wrong options
- Can cause boot loops if root filesystem entry is wrong

**L16** — LVM provides flexible storage management:
- **Physical Volume (PV)**: Physical disk or partition
- **Volume Group (VG)**: Pool of one or more PVs
- **Logical Volume (LV)**: Virtual partition carved from a VG

**Extend a logical volume:**
```bash
# Add new disk as PV
pvcreate /dev/sdb

# Extend VG
vgextend myvg /dev/sdb

# Extend LV
lvextend -L +10G /dev/myvg/mylv
# or use all free space
lvextend -l +100%FREE /dev/myvg/mylv

# Resize filesystem
resize2fs /dev/myvg/mylv    # ext4
xfs_growfs /mount/point     # xfs
```

**L17** — I/O schedulers order disk operations:
- **mq-deadline**: Maintains read/write queues with deadlines. Good for general-purpose, low latency.
- **bfq (Budget Fair Queueing)**: Per-process budgeting, good for desktops with mixed workloads.
- **none**: No scheduling, passes requests directly. Best for SSDs/NVMe.

**Change scheduler at runtime:**
```bash
echo none > /sys/block/sda/queue/scheduler
# Check available schedulers
cat /sys/block/sda/queue/scheduler
```

**L18** — Load average measures processes in **running or uninterruptible sleep (D) state**, not just CPU usage.

**I/O wait inflates load** because processes waiting for disk I/O are in D state and counted in load average.

**Diagnosis:**
```bash
# Overall system state
top -b -n 1 | head -20

# CPU breakdown
mpstat -P ALL 1 5

# I/O wait specifically
iostat -x 1 5

# Per-process I/O
pidstat -d 1 5

# Check for D-state processes
ps aux | awk '$8 ~ /D/ {print}'

# Network stats
netstat -s | grep -i drop
ss -s
```

**L19** — SELinux enforces MAC by labeling all objects (files, processes, ports) with types and enforcing policies that define allowed interactions.

**Modes:**
- **Enforcing**: Violations are blocked and logged
- **Permissive**: Violations are logged but not blocked
- **Disabled**: SELinux is turned off

**Troubleshoot port binding:**
```bash
# Check current mode
getenforce

# View denials
ausearch -m avc -ts recent | audit2why

# Check port context
semanage port -l | grep <port>

# Add port to policy
semanage port -a -t http_port_t -p tcp 8080

# Or temporarily set permissive for debugging
setenforce 0  # then setenforce 1 to restore
```

**L20** — Page faults occur when a process accesses a virtual address not mapped to physical memory.

- **Minor page fault**: Page is in memory but not mapped to process. Fast resolution.
- **Major page fault**: Page must be read from disk. Slow, involves I/O.

**THP (Transparent Huge Pages)** automatically uses 2MB pages instead of 4KB pages, reducing TLB misses but potentially causing:
- Memory fragmentation
- Latency spikes during allocation
- Issues with certain workloads (databases, real-time apps)

**Disable THP:**
```bash
echo never > /sys/kernel/mm/transparent_hugepage/enabled
echo never > /sys/kernel/mm/transparent_hugepage/defrag
```
