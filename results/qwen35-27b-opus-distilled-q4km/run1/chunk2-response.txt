# Kubernetes (20 questions)

**K1:** A **Deployment** manages stateless, interchangeable pods with no identity guarantees, while a **StatefulSet** manages stateful applications requiring stable network identities, ordered deployment/scaling, and persistent storage tied to specific pod instances.

**K2:** A ClusterIP Service creates an internal virtual IP. kube-proxy programs iptables/IPVS rules that redirect traffic to the Service IP toward the backing pod IPs. Endpoints objects track which pods match the Service selector, and kube-proxy updates rules when pods change.

**K3:** A **PersistentVolume (PV)** is a cluster-wide storage resource. A **PersistentVolumeClaim (PVC)** is a namespace-scoped request for storage by a pod. A **StorageClass** defines dynamic provisioning parameters. When a PVC references a StorageClass, Kubernetes dynamically creates a matching PV.

**K4:** (1) `kubectl logs <pod>` for application errors. (2) `kubectl describe pod <pod>` for events, OOMKilled, or probe failures. (3) Check resource limits vs. actual usage. (4) Verify config/secrets are mounted correctly. (5) Test image locally or with `kubectl run`.

**K5:** CoreDNS provides internal DNS resolution for services and pods. If CoreDNS pods are down, DNS queries fail, breaking service discovery and any application relying on DNS (including external domain resolution via upstream servers).

**K6:** The scheduler **filters** nodes against hard constraints (resources, taints, affinity, topology). It then **scores** remaining nodes using predicates like: (1) resource utilization balance, (2) image locality, (3) inter-pod affinity/anti-affinity, (4) topology spread. Highest-scoring node is selected.

**K7:** **No**, the pod won't be scheduled. The node has 4GB total, 3.5GB requested, leaving 512Mi available. The pod requests 256Mi, but Kubernetes also reserves overhead (~10-15%). Even without overhead, 3.5GB + 256Mi = 3.756GB < 4GB, so it *might* fit, but realistically node allocatable is less than total. If it uses 600Mi at runtime (exceeding 512Mi limit), it gets **OOMKilled**.

**K8:** External LB → NGINX Ingress Controller (pods) → Ingress rules match host/path → NGINX routes to backend Service → Service ClusterIP → kube-proxy iptables rules → Pod IP → Application. Endpoints object links Service to pod IPs; kube-proxy updates iptables on changes.

**K9:** A **NetworkPolicy** controls pod-to-pod and pod-to-external traffic. With **no NetworkPolicy**, all traffic is allowed. When you apply one, it becomes **restrictive by default**—only explicitly allowed traffic flows; all other traffic is denied.

**K10:** **RollingUpdate** replaces pods incrementally, maintaining availability. **Recreate** kills all old pods before creating new ones. Choose Recreate for database migrations, schema changes, or when old/new versions can't coexist.

**K11:** A **namespace** provides logical isolation for resources. Default namespaces: `default`, `kube-system` (control plane), `kube-public` (cluster-wide info), `kube-node-lease` (node liveness).

**K12:** `kubectl describe pod` shows detailed pod info including: (1) Events (scheduling, probe failures), (2) Container state/reason, (3) Resource requests/limits, (4) Volume mounts, (5) Node assignment, (6) QoS class.

**K13:** A **ConfigMap** stores non-sensitive config data. Pods consume it via: (1) Environment variables (`envFrom` or `valueFrom`), (2) Mounted as files in a volume.

**K14:** **ClusterIP**: Internal-only virtual IP. **NodePort**: Exposes service on each node's IP at a static port (30000-32767). **LoadBalancer**: Provisions external cloud load balancer routing to NodePort.

**K15:** A **DaemonSet** ensures exactly one pod runs on each (or selected) node. Use for node-level agents: log collectors (Fluentd), monitoring (Node Exporter), network plugins (Calico).

**K16:** **Taints/tolerations** push pods away from nodes (taint) or allow scheduling despite taints (toleration). **Node affinity** pulls pods toward nodes with matching labels. Taints: dedicate GPU nodes to GPU jobs. Affinity: schedule pods near specific hardware or zones.

**K17:** An **Operator** is a controller managing complex applications using Custom Resources (CRDs). Unlike standard controllers managing built-in types, Operators encode operational knowledge (backups, upgrades, healing) for stateful apps like databases.

**K18:** etcd uses **Raft consensus** for strong consistency. Losing quorum (2 of 3 nodes) makes the cluster unavailable. Recovery: restore from snapshot of surviving node, rebuild cluster with new nodes, or use etcd snapshot restore tool.

**K19:** **Role/ClusterRole** define permissions; **RoleBinding/ClusterRoleBinding** grant them to subjects. Role/RoleBinding are namespace-scoped; ClusterRole/ClusterRoleBinding are cluster-wide.

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: dev
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  namespace: dev
  name: read-pods-binding
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20:** `ndots:5` means queries with <5 dots try each search domain before going to root servers. For "google.com", it tries "google.com.ns1", "google.com.ns2", etc., causing delays. Fix:
```yaml
dnsConfig:
  options:
  - name: ndots
    value: "1"
```

# Development (20 questions)

**D1:** **Merge** creates a merge commit preserving history; **rebase** rewrites history by moving commits on top of another branch. Avoid rebasing shared/public branches—it rewrites history and causes chaos for collaborators.

**D2:** **TCP** is connection-oriented, reliable, ordered (HTTP, SSH). **UDP** is connectionless, unreliable, unordered (DNS, VoIP).

**D3:** A **race condition** occurs when program behavior depends on unpredictable timing. Example:
```python
counter = 0
def increment():
    global counter
    temp = counter
    counter = temp + 1  # Another thread may modify counter here
```

**D4:** **Symmetric** uses one key for encrypt/decrypt (fast, e.g., AES). **Asymmetric** uses public/private key pairs (slower, e.g., RSA). TLS uses asymmetric for key exchange (authenticates server, negotiates session key), then symmetric for data transfer.

**D5:** An **image layer** is a read-only filesystem snapshot. Layers are cached; changing a layer invalidates all subsequent layers. Best practice: order Dockerfile commands from least to most frequently changing (dependencies before source code).

**D6:** (1) Check application logs for errors. (2) Verify upstream service health (database, cache). (3) Check resource utilization (CPU, memory, connections). (4) Review recent deployments or config changes. (5) Check circuit breaker status if microservices.

**D7:** **CAP theorem**: distributed systems can only guarantee 2 of 3: Consistency, Availability, Partition tolerance. **CP**: ZooKeeper (consistent, unavailable during partition). **AP**: Cassandra (available, eventually consistent during partition).

**D8:** **Horizontal scaling** adds more instances; **vertical scaling** adds resources to existing instance. Horizontal scaling enabled by: stateless design, load balancers, distributed databases, message queues, session externalization.

**D9:** An **environment variable** is a key-value pair available to processes. To persist across sessions: add `export VAR=value` to `~/.bashrc`, `~/.profile`, or `/etc/environment`.

**D10:** **JSON** is key-value data format with strict typing; **YAML** is human-readable superset of JSON with anchors, comments, less punctuation. JSON advantage: universal parsing. YAML advantage: readability, anchors for reuse.

**D11:** **REST API** uses HTTP for stateless resource manipulation. **GET**: retrieve, **POST**: create, **PUT**: replace/update, **DELETE**: remove.

**D12:** **Version pinning** fixes dependency versions (e.g., `requests==2.28.0`). Ensures reproducible builds—same code produces identical artifacts regardless of when built.

**D13:** **Compiled** languages translate to machine code before execution (C, Go). **Interpreted** languages execute via interpreter at runtime (Python, JavaScript).

**D14:** A **reverse proxy** sits in front of servers, forwarding client requests (NGINX for load balancing, HAProxy for SSL termination). A **forward proxy** sits in front of clients, forwarding their requests outward (corporate proxy for filtering).

**D15:** A **deadlock** is when processes wait indefinitely for each other. **Coffman conditions**: (1) Mutual exclusion, (2) Hold and wait, (3) No preemption, (4) Circular wait.

**D16:** **Eventual consistency**: after updates stop, all replicas converge to same state. Cassandra uses **read repair** and **anti-entropy** for convergence. Consistency levels: ONE, QUORUM, ALL, LOCAL_QUORUM, etc.—tunable per operation.

**D17:** **mTLS** requires both client and server to present certificates. Handshake: (1) ClientHello, (2) Server sends cert + requests client cert, (3) Client sends cert, (4) Both verify each other's certs against trusted CAs, (5) Establish session keys. Used in: service mesh (Istio), internal microservices, zero-trust networks.

**D18:** A **hash table** maps keys to indices via hash function. **Chaining**: collisions store values in linked list at index. **Open addressing**: collisions probe for next available slot. Average: O(1) insert/lookup/delete. Worst: O(n) with poor hash or many collisions.

**D19:** **Circuit breaker** prevents cascade failures by stopping calls to failing services. **Closed**: normal operation. **Open**: calls fail fast after threshold failures. **Half-open**: test if service recovered. Works with retries (don't retry when open) and exponential backoff (space out retries).

**D20:** **Optimistic** assumes conflicts rare; validates at commit time (row versioning, CAS). **Pessimistic** assumes conflicts likely; locks resources upfront (SELECT FOR UPDATE). Choose optimistic for read-heavy, low-conflict workloads. Pessimistic for financial transactions, high-contention updates.
