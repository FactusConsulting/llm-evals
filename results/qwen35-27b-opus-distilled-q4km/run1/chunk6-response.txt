# Comprehensive Technical Interview Answers

## JavaScript / TypeScript (20 questions)

### JS1 — Easy: var, let, const, and hoisting

**var**: Function-scoped, can be redeclared and reassigned. Hoisted with initialization to `undefined`.

**let**: Block-scoped, cannot be redeclared in same scope, can be reassigned. Hoisted but not initialized (temporal dead zone).

**const**: Block-scoped, cannot be reassigned (but object properties can be mutated). Hoisted but not initialized.

```javascript
console.log(a); // undefined (hoisted)
var a = 1;

console.log(b); // ReferenceError (TDZ)
let b = 2;

console.log(c); // ReferenceError (TDZ)
const c = 3;
```

**Hoisting**: JavaScript moves declarations to the top of their scope during compilation. `var` is initialized to `undefined`, while `let`/`const` are not initialized until their declaration is reached.

### JS2 — Easy: Event loop, call stack, microtask/macrotask queues

**Call Stack**: LIFO structure tracking function execution. Synchronous code runs here.

**Microtask Queue**: Higher priority. Contains: Promise callbacks, `queueMicrotask()`, `process.nextTick()` (Node).

**Macrotask Queue**: Lower priority. Contains: `setTimeout`, `setInterval`, I/O callbacks, UI rendering.

**Event Loop Cycle**:
1. Execute call stack until empty
2. Run ALL microtasks until queue empty
3. Run ONE macrotask
4. Render (browsers)
5. Repeat

```javascript
console.log('1'); // Call stack

setTimeout(() => console.log('2'), 0); // Macrotask

Promise.resolve().then(() => console.log('3')); // Microtask

console.log('4'); // Call stack

// Output: 1, 4, 3, 2
```

### JS3 — Medium: Closures and for loop bug

**Closure**: A function that captures variables from its enclosing scope, maintaining access even after the outer function returns.

```javascript
function makeCounter() {
  let count = 0;
  return function() {
    return ++count;
  };
}
const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2
```

**Classic for loop bug**:
```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Output: 3, 3, 3 (all closures reference same i)
```

**Fixes**:
```javascript
// 1. Use let (block-scoped)
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}

// 2. IIFE with var
for (var i = 0; i < 3; i++) {
  (function(j) {
    setTimeout(() => console.log(j), 100);
  })(i);
}

// 3. setTimeout with argument
for (var i = 0; i < 3; i++) {
  setTimeout((j) => console.log(j), 100, i);
}
```

### JS4 — Medium: Promises, async/await, error handling

**Promise**: Object representing eventual completion/failure of async operation.

```javascript
const promise = new Promise((resolve, reject) => {
  setTimeout(() => resolve('done'), 1000);
});

promise
  .then(value => console.log(value))
  .catch(error => console.error(error));
```

**async/await**: Syntactic sugar over Promises.

```javascript
async function fetchData() {
  const response = await fetch('/api');
  const data = await response.json();
  return data;
}
```

**Error handling**:
```javascript
// Promise
promise.catch(err => console.error(err));

// async/await
try {
  await fetchData();
} catch (err) {
  console.error(err);
}
```

**Promise.all vs Promise.allSettled**:
```javascript
// all: rejects immediately if any promise rejects
Promise.all([p1, p2, p3]); // [value1, value2, value3] or throws

// allSettled: waits for all, returns status for each
Promise.allSettled([p1, p2, p3]); 
// [{status: 'fulfilled', value: ...}, {status: 'rejected', reason: ...}]
```

### JS5 — Medium: TypeScript interface vs type, discriminated unions

**interface**: Extensible, can be merged, used for object shapes.

**type**: More flexible, can define primitives, unions, tuples, mapped types.

```typescript
interface User {
  id: number;
  name: string;
}

type UserAlias = {
  id: number;
  name: string;
};

// Interface merging
interface User {
  email: string; // Added to existing User
}

// Type cannot merge, must redefine
```

**When to use each**:
- `interface`: Object shapes, declaration files, extensibility needed
- `type`: Unions, primitives, tuples, mapped types, conditional types

**Discriminated unions**:
```typescript
type Shape = 
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number };

function area(shape: Shape): number {
  if (shape.kind === 'circle') {
    return Math.PI * shape.radius ** 2;
  }
  return shape.side ** 2;
}
```

### JS6 — Medium: Prototypal inheritance

**Prototypal inheritance**: Objects inherit directly from other objects via `__proto__` (internal [[Prototype]]).

```javascript
const animal = { eats: true };
const rabbit = { jumps: true };
rabbit.__proto__ = animal;

console.log(rabbit.eats); // true (inherited)
```

**Object.create()**: Creates object with specified prototype.

```javascript
const animal = { eats: true };
const rabbit = Object.create(animal);
rabbit.jumps = true;
```

**ES6 classes**: Syntactic sugar over prototypes.

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
  eats() { return true; }
}

class Rabbit extends Animal {
  jumps() { return true; }
}

// Equivalent to:
// Animal.prototype.eats = function() { return true; };
// Rabbit.prototype = Object.create(Animal.prototype);
// Rabbit.prototype.constructor = Rabbit;
```

### JS7 — Hard: this keyword and binding rules

**4 binding rules (priority order)**:

1. **New binding**: `new` keyword creates new object, `this` = new object
2. **Explicit binding**: `call()`, `apply()`, `bind()` explicitly set `this`
3. **Implicit binding**: `obj.method()` → `this` = `obj`
4. **Default binding**: Function called alone → `this` = `undefined` (strict) or `global` (non-strict)

```javascript
function foo() { console.log(this); }

foo();                    // Default: undefined (strict mode)
const obj = { foo };
obj.foo();               // Implicit: obj
foo.call({});            // Explicit: {}
new foo();               // New: new object
```

**bind()**: Returns a new function with permanently bound `this`.

```javascript
const bound = foo.bind({});
bound(); // this = {}
bound.call({}); // Still {} - cannot re-bind
```

### JS8 — Hard: WeakRef and FinalizationRegistry

**WeakRef**: Weak reference to object that doesn't prevent garbage collection.

```javascript
const obj = { data: 'value' };
const weakRef = new WeakRef(obj);
console.log(weakRef.deref()); // { data: 'value' }

obj = null;
// GC may collect original object
console.log(weakRef.deref()); // May be undefined
```

**FinalizationRegistry**: Register cleanup callback when object is garbage collected.

```javascript
const registry = new FinalizationRegistry((heldValue) => {
  console.log(`Cleaning up: ${heldValue}`);
});

const obj = { id: 1 };
registry.register(obj, 'Resource 1');

obj = null;
// Eventually logs: "Cleaning up: Resource 1"
```

**Use cases**: Memory leaks prevention, resource cleanup, caching with automatic eviction.

**WeakMap keys must be objects**: Only objects can be garbage collected. Primitives are not heap-allocated in the same way, so weak references don't apply.

```javascript
const wm = new WeakMap();
wm.set({}, 'value'); // OK
wm.set(42, 'value'); // TypeError: Invalid value used as weak map key
```

### JS9 — Hard: V8 optimization

**Hidden classes**: V8 assigns hidden classes to objects based on property access patterns.

```javascript
// Monomorphic - same hidden class
function add(a, b) { return a + b; }
add(1, 2); add(3, 4); // Fast - inline cache works

// Polymorphic - different hidden classes
function addMixed(a, b) { return a + b; }
addMixed(1, '2'); addMixed('3', 4); // Slower - cache miss
```

**Inline caching**: Caches property access results for faster subsequent access.

**Deoptimization**: V8 reverts to interpreter when assumptions break.

**Patterns causing deoptimization**:
```javascript
// 1. Type feedback changes
function f(x) { return x + 1; }
f(1); f('a'); // Deoptimizes

// 2. Hidden class transitions
const obj = {};
obj.a = 1; obj.b = 2; obj.c = 3; // Multiple hidden classes

// 3. Escape analysis failure
function create() {
  const arr = [];
  arr.push(1);
  return arr; // Escapes - can't optimize
}

// 4. Dynamic property access
const obj = { a: 1 };
const key = 'a';
obj[key]; // Can't inline cache
```

### JS10 — Medium: Tree-shaking

**Tree-shaking**: Dead code elimination for unused exports.

**ES Modules**: Static imports/exports allow analysis at build time.

```javascript
// utils.js
export function used() { return 1; }
export function unused() { return 2; }

// main.js
import { used } from './utils.js';
// 'unused' is tree-shaken out
```

**CommonJS**: Dynamic `require()` prevents static analysis.

```javascript
// utils.js
module.exports = { used, unused };

// main.js
const { used } = require('./utils');
// Entire module loaded - cannot tree-shake
```

**Why CommonJS can't be tree-shaken**:
1. `require()` is dynamic (runtime evaluation)
2. Module exports can be modified after definition
3. No static import/export syntax

### JS11 — Easy: null vs undefined, == vs ===, ?? and ?.

**null**: Intentional absence of value (assigned by developer).

**undefined**: Variable declared but not assigned, missing function parameter, missing object property.

```javascript
let a;           // undefined
let b = null;    // null
const obj = {};
obj.prop;        // undefined
```

**== vs ===**:
```javascript
null == undefined;  // true (special case)
null === undefined; // false
null == 0;          // false
null === 0;         // false
```

**Nullish coalescing (??)**: Returns right operand if left is `null` or `undefined`.

```javascript
0 ?? 10;      // 0 (0 is valid)
null ?? 10;   // 10
'' ?? 'def';  // '' (empty string is valid)
```

**Optional chaining (?.)**: Safely access nested properties.

```javascript
user?.address?.city; // undefined if user or address is null/undefined
```

### JS12 — Easy: map, filter, reduce, flatMap

**map()**: Transform each element.
```javascript
[1, 2, 3].map(x => x * 2); // [2, 4, 6]
```

**filter()**: Keep elements matching predicate.
```javascript
[1, 2, 3].filter(x => x > 1); // [2, 3]
```

**reduce()**: Accumulate into single value.
```javascript
[1, 2, 3].reduce((acc, x) => acc + x, 0); // 6
// Without initial value: first element becomes initial accumulator
[1, 2, 3].reduce((acc, x) => acc + x); // 6
```

**flatMap()**: map + flatten one level.
```javascript
[[1, 2], [3, 4]].flatMap(x => x); // [1, 2, 3, 4]
// Equivalent to:
[[1, 2], [3, 4]].map(x => x).flat();
```

**flatMap use case**:
```javascript
users.flatMap(user => user.posts); // Flatten user posts into single array
```

### JS13 — Easy: Template literals and tagged templates

**Template literals**: Backtick strings with interpolation.

```javascript
const name = 'Alice';
const greeting = `Hello, ${name}!`; // "Hello, Alice!"
```

**Tagged templates**: Function receives template strings and values.

```javascript
function tag(strings, ...values) {
  console.log(strings); // ['Hello, ', '!']
  console.log(values);  // ['Alice']
  return 'result';
}

tag`Hello, ${name}!`;
```

**HTML escaping example**:
```javascript
function html(strings, ...values) {
  return strings.reduce((acc, str, i) => {
    const val = values[i]?.replace(/[&<>"']/g, c => 
      ({ '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' })[c]
    ) ?? '';
    return acc + str + val;
  }, '');
}

const name = '<script>alert(1)</script>';
console.log(html`<div>Hello ${name}!</div>`);
// <div>Hello &lt;script&gt;alert(1)&lt;/script&gt;!</div>
```

### JS14 — Easy: Destructuring

**Object destructuring**:
```javascript
const { a, b } = { a: 1, b: 2 };
const { a: x, b: y } = { a: 1, b: 2 }; // Renaming
const { a = 10 } = { b: 2 }; // Default: a = 10
```

**Array destructuring**:
```javascript
const [first, second] = [1, 2, 3];
const [first, , third] = [1, 2, 3]; // Skip second
const [first = 10] = []; // Default
```

**Rest operator**:
```javascript
const [first, ...rest] = [1, 2, 3, 4]; // first=1, rest=[2,3,4]
const { a, ...rest } = { a: 1, b: 2, c: 3 }; // rest={b:2, c:3}
```

**Function parameters**:
```javascript
function log({ name, age = 18 }) {
  console.log(name, age);
}
log({ name: 'Alice' }); // Alice 18
```

### JS15 — Easy: for...in vs for...of

**for...in**: Iterates over enumerable property keys (including inherited).

```javascript
for (const key in obj) {
  console.log(key); // Property names as strings
}
```

**for...of**: Iterates over iterable values.

```javascript
for (const value of array) {
  console.log(value); // Actual values
}
```

**Why avoid for...in on arrays**:
```javascript
const arr = [1, 2, 3];
arr.customProp = 'extra';

for (const key in arr) {
  console.log(key); // "0", "1", "2", "customProp"
}

for (const value of arr) {
  console.log(value); // 1, 2, 3
}
```

**for...in issues**:
1. Iterates inherited properties
2. Returns keys as strings, not values
3. Non-deterministic order
4. Includes non-numeric properties

### JS16 — Medium: TypeScript generics

**Generics**: Type parameters for reusable functions/types.

```typescript
function identity<T>(arg: T): T {
  return arg;
}
```

**Generic constraints (extends)**:
```typescript
function logLength<T extends { length: number }>(arg: T): number {
  return arg.length;
}
```

**Conditional types**:
```typescript
type IsString<T> = T extends string ? true : false;
type A = IsString<string>; // true
type B = IsString<number>; // false
```

**infer keyword**:
```typescript
type Head<T> = T extends readonly (infer U)[] ? U : never;
type First = Head<[string, number]>; // string
```

**Practical example**:
```typescript
type Database<T> = {
  get(id: string): Promise<T | null>;
  save(entity: T): Promise<void>;

type User = { id: string; name: string };
const userDb: Database<User> = {
  get: async (id) => ({ id, name: 'Alice' }),
  save: async (user) => {},
```

### JS17 — Medium: Module systems

**CommonJS** (Node.js default historically):
```javascript
// Export
module.exports = { foo };
exports.bar = 1;

// Import
const mod = require('./mod');
```

**ES Modules**:
```javascript
// Export
export const foo = 1;
export default function() {}

// Import
import foo, { bar } from './mod.js';
```

**Key differences**:
| Aspect | CommonJS | ES Modules |
|--------|----------|------------|
| Loading | Synchronous | Asynchronous |
| Scope | Function-scoped | Module-scoped |
| Exports | Mutable | Immutable (live bindings) |
| Format | `.js` | `.mjs` or `"type": "module"` |

**Node.js handling**:
```json
{
  "type": "module"  // Treats .js as ES modules
}
```

Without `"type": "module"`, `.js` files are CommonJS. Use `.mjs` extension for ES modules.

### JS18 — Hard: TypeScript structural typing

**Structural type system**: Types are compatible based on structure, not declaration.

```typescript
interface Point { x: number; y: number; }
const p = { x: 1, y: 2 };
function f(p: Point) {}
f(p); // OK - p has required structure
```

**Excess property checks**: Applied only to object literals assigned to variables or passed to functions.

```typescript
interface Point { x: number; y: number; }

const p1: Point = { x: 1, y: 2, z: 3 }; // Error - excess property
const p2 = { x: 1, y: 2, z: 3 };
const p3: Point = p2; // OK - not a literal

function f(p: Point) {}
f({ x: 1, y: 2, z: 3 }); // Error - excess property
```

**extends vs satisfies** (TypeScript 5.0+):
```typescript
type Base = { a: number };

// extends: narrows the type
type Derived extends Base = { a: number; b: string };
const d: Derived = { a: 1, b: 'x' };
d.a; // number
d.b; // string

// satisfies: validates but preserves type
type Preserved = { a: number; b: string } satisfies Base;
const p: Preserved = { a: 1, b: 'x' };
p.a; // number (preserved, not narrowed)
```

**Variance (TypeScript 4.7+)**:
```typescript
type Producer<out T> = () => T;  // Covariant
type Consumer<in T> = (t: T) => void;  // Contravariant
type Transformer<in out T> = (t: T) => T;  // Both
```

### JS19 — Hard: Proxy and Reflect

**Proxy**: Intercept and customize object operations.

```javascript
const handler = {
  get(target, prop, receiver) {
    console.log(`Getting ${prop}`);
    return Reflect.get(target, prop, receiver);
  },
  set(target, prop, value, receiver) {
    console.log(`Setting ${prop} = ${value}`);
    return Reflect.set(target, prop, value, receiver);
  },
  apply(target, thisArg, args) {
    console.log(`Called with`, args);
    return Reflect.apply(target, thisArg, args);
  }
};

const proxy = new Proxy({ a: 1 }, handler);
proxy.a; // Logs "Getting a"
proxy.a = 2; // Logs "Setting a = 2"
```

**Reflect**: Companion to Proxy, provides standard object operations.

```javascript
Reflect.get(obj, 'prop');
Reflect.set(obj, 'prop', value);
Reflect.apply(func, thisArg, args);
Reflect.construct(Constructor, args);
```

**Practical example - reactive data binding**:
```javascript
class Reactive {
  constructor(data) {
    this.dependencies = new Set();
    return new Proxy(data, {
      get(target, prop) {
        if (this.dependencies) this.dependencies.add(prop);
        return target[prop];
      },
      set(target, prop, value) {
        target[prop] = value;
        this.dependencies.forEach(dep => console.log(`Notify: ${dep}`));
        return true;
      }
    });
  }
}
```

### JS20 — Hard: SharedArrayBuffer and Atomics

**SharedArrayBuffer**: Shared memory between threads.

```javascript
const sab = new SharedArrayBuffer(1024);
const view = new Int32Array(sab);
```

**Atomics**: Atomic operations on shared memory.

```javascript
Atomics.store(view, 0, 42);
const val = Atomics.load(view, 0);
Atomics.add(view, 0, 1); // Atomic increment
```

**Web Worker communication**:
```javascript
// Main thread
const sab = new SharedArrayBuffer(4);
const view = new Int32Array(sab);
const worker = new Worker('worker.js');
worker.postMessage(sab, [sab]);

// Worker thread
self.onmessage = (e) => {
  const sab = e.data;
  const view = new Int32Array(sab);
  Atomics.store(view, 0, 42);
  Atomics.notify(view, 0, 1);
};
```

**Ordering guarantees**: Sequential consistency for atomic operations.

**Atomics.wait/notify**:
```javascript
// Wait until value changes
Atomics.wait(view, 0, 0); // Wait until view[0] != 0

// Notify waiting threads
Atomics.store(view, 0, 1);
Atomics.notify(view, 0, 1); // Wake up 1 waiter
```

## Bash (20 questions)

### B1 — Easy: $@ vs $*

**$@**: All positional parameters as separate words.

**$***: All positional parameters as single word (joined by first char of IFS).

**"$@"**: Each parameter as separate quoted word (preserves spaces).

**"$*"**: Single quoted word (all parameters joined).

```bash
set -- "one two" "three"

echo $@    # one two three (3 words split)
echo $*    # one two three (1 word)
echo "$@"  # "one two" "three" (2 words, preserved)
echo "$*"  # "one two three" (1 word)

for arg in "$@"; do echo "$arg"; done
# Outputs: "one two" then "three" (correct)

for arg in "$*"; do echo "$arg"; done
# Outputs: "one two three" (incorrect - merged)
```

### B2 — Easy: set -euo pipefail

```bash
set -euo pipefail
```

**-e (errexit)**: Exit immediately on command failure.

**-u (nounset)**: Treat unset variables as errors.

**-o pipefail**: Pipeline returns exit status of last failing command.

```bash
# Without pipefail
false | true; echo $?  # 0 (true succeeds)

# With pipefail
set -o pipefail
false | true; echo $?  # 1 (false fails)
```

**Combined effect**: Strict error handling for scripts.

### B3 — Medium: $(command) vs `command`, $((expr)) vs expr

**$(command)**: Modern command substitution. Nestable, readable.

**`command`**: Legacy command substitution. Harder to nest.

```bash
echo $(echo $(echo hello))  # Clean nesting
echo `echo `echo hello``    # Messy nesting
```

**$((expression))**: Arithmetic expansion (bash builtin).

**expr**: External command for arithmetic.

```bash
echo $((1 + 2 * 3))    # 7 (fast, builtin)
echo $(expr 1 + 2 \* 3)  # 7 (slower, external)
```

**$(( )) advantages**:
- No escaping needed
- Supports more operators
- Faster (no fork)
- Returns exit status

### B4 — Medium: Process substitution

**Process substitution**: `< (command)` creates a named pipe (FIFO) or `/dev/fd/N`.

```bash
grep pattern <(some_command)
```

**Why useful**: Allows commands expecting file arguments to work with command output.

### B5 — Medium: Safe file iteration

**Dangerous pattern**:
```bash
for f in $(ls); do
  echo "$f"
done
# Breaks on spaces, newlines, special chars
```

**Safe patterns**:

```bash
# 1. While read loop (most portable)
while IFS= read -r -d '' file; do
  echo "$file"
done < <(find . -type f -print0)

# 2. For with glob (simple cases)
for file in *.txt; do
  [[ -f "$file" ]] && echo "$file"
done

# 3. Mapfile/readarray (bash 4+)
mapfile -d '' files < <(find . -type f -print0)
for file in "${files[@]}"; do
  echo "$file"
done
```

**Why `for f in $(ls)` is dangerous**:
1. Word splitting breaks filenames with spaces
2. Globbing expands `*` and `?`
3. Newlines in filenames cause issues
4. `ls` output parsing is fragile

### B6 — Medium: Here documents vs here strings

**Here document (<<)**: Multi-line input from script.

```bash

Line 1

```

**Here string (<<<)**: Single-line input.

```bash
EOF

# Here string - single line

# Here document with tab stripping

    indented content
EOF
```

### B7 — Hard: Redirection order

```bash
cmd > file 2>&1    # stdout to file, stderr to stdout (file)
cmd 2>&1 > file    # stderr to stdout (terminal), stdout to file
cmd &> file        # Both stdout and stderr to file
```

**Why first two differ**:

```bash
# Order of operations matters
cmd > file 2>&1
# 1. stdout redirected to file
# 2. stderr redirected to wherever stdout goes (file)
# Result: Both go to file ✓

cmd 2>&1 > file
# 1. stderr redirected to wherever stdout goes (terminal)
# 2. stdout redirected to file
# Result: stdout to file, stderr to terminal ✗
```

**Visual**:
```
cmd > file 2>&1:
  stdout ──┐
           ├─> file
  stderr ──┘

cmd 2>&1 > file:
  stdout ─────────> file
  stderr ────────> terminal
```

**&> is shorthand**: `cmd &> file` ≡ `cmd > file 2>&1`

### B8 — Hard: Lock file with mkdir

```bash
#!/bin/bash
set -euo pipefail

LOCK_DIR="/var/lock/myscript"
LOCK_NAME="instance.lock"

cleanup() {
  rm -rf "$LOCK_DIR/$LOCK_NAME"
  exit "${1:-0}"
}

trap 'cleanup $?' EXIT
trap 'cleanup 130' INT
trap 'cleanup 143' TERM

# Acquire lock (atomic, race-condition safe)
if ! mkdir "$LOCK_DIR/$LOCK_NAME" 2>/dev/null; then
  echo "Another instance is running" >&2
  exit 1
fi

# Store PID
echo $$ > "$LOCK_DIR/$LOCK_NAME/pid"

echo "Lock acquired, PID: $$"

# Main work
sleep 3600

# Cleanup happens via trap
```

**Why mkdir is preferred**:
1. **Atomic**: `mkdir` fails if directory exists (no race window)
2. **No TOCTOU**: File creation + check has race condition
3. **Simple cleanup**: `rm -rf` removes everything

**Race condition with file creation**:

```bash
  touch lockfile  # Another process could create it here
fi
```

### B9 — Easy: Quotes in bash

**No quotes**: Word splitting and globbing occur.

### B14 — Medium: trap

```bash
# Set trap
trap 'command' SIGNAL

# Common signals
trap 'cleanup' EXIT      # Run on exit
trap 'error_handler' ERR # Run on command failure (with -e)
trap 'interrupt_handler' INT  # Ctrl+C
trap 'terminate_handler' TERM # kill signal
```

**Example**:
```bash
#!/bin/bash
set -euo pipefail

TEMP_FILE=$(mktemp)

cleanup() {
  rm -f "$TEMP_FILE"
  echo "Cleaned up"
}

trap 'echo "Interrupted!"; exit 130' INT
trap 'echo "Terminated!"; exit 143' TERM

echo "Working..."
echo "data" > "$TEMP_FILE"
sleep 100
```

**Execution order**: When multiple signals arrive, traps execute in order received. EXIT trap runs last.

### B17 — Hard: Subshell vs group

**Subshell `( ... )`**: Runs in child process.

**Group `{ ...; }`**: Runs in current shell.

```bash
# Subshell - variable changes lost
(x=1); echo $x  # Empty

# Group - variable changes persist
{x=1;}; echo $x  # 1

# Exit code difference
( false; true ); echo $?  # 0 (last command in subshell)
{ false; true; }; echo $? # 0 (last command in group)
```

**Why piping loses variables**:
```bash
echo "1 2 3" | while read n; do
  sum=$((sum + n))
done
echo $sum  # Empty - while ran in subshell!

# Fix: process substitution
while read n; do
  sum=$((sum + n))
done < <(echo "1 2 3")
echo $sum  # 6
```

**Summary**:
- `( )` = subshell, new process, isolated environment
- `{ }` = group, same shell, shared environment
- Pipes create subshells for right side


### B19 — Hard: Parallel log processing

```bash
#!/bin/bash
set -euo pipefail

LOG_FILE="$1"
OUTPUT_FILE="$2"
NUM_PROCESSES=${3:-4}

TEMP_DIR=$(mktemp -d)
trap 'rm -rf "$TEMP_DIR"' EXIT

# Split log into chunks
split -l 10000 -d -a 4 "$LOG_FILE" "$TEMP_DIR/chunk_"

# Process function
process_chunk() {
  local chunk="$1"
  local output="$2"
  grep -E 'ERROR|WARN' "$chunk" >> "$output"
}
export -f process_chunk

# Parallel processing
ls "$TEMP_DIR"/chunk_* | xargs -P "$NUM_PROCESSES" -I {} bash -c '
  chunk="{}"
  basename=$(basename "$chunk")
  process_chunk "$chunk" "$TEMP_DIR/${basename}.out"
'

# Merge results
cat "$TEMP_DIR"/*.out > "$OUTPUT_FILE" 2>/dev/null || true

# Error handling
if [[ $? -ne 0 ]]; then
  echo "Processing failed" >&2
  exit 1
fi
```

**Trade-offs**:
- **Pros**: Faster on multi-core, scales with data size
- **Cons**: Overhead for small files, complexity, error propagation harder

**Error propagation**:
```bash
# Check each parallel job
xargs -P 4 -I {} process {} || {
  echo "Parallel job failed" >&2
  exit 1
}
```
