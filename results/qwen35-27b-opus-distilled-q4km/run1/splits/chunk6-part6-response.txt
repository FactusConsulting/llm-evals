# PowerShell Technical Questions - Detailed Answers

## PS11 — PowerShell Modules

**What is a PowerShell Module?**
A PowerShell module is a container that packages related functionality—functions, cmdlets, variables, aliases, classes, and resources—into a single distributable unit.

**Module Types:**

| Type | Extension | Description |
|------|-----------|-------------|
| Script Module | `.psm1` | Pure PowerShell script containing functions and logic |
| Manifest Module | `.psd1` | Hash table describing module metadata and pointing to resources |
| Binary Module | `.dll` | Compiled .NET assembly containing cmdlets |

**Script Module (.psm1)**
- A pure PowerShell script file containing functions, variables, and logic
- Uses `Export-ModuleMember` to control what's exposed
- Most common for pure PowerShell modules
- Example:
```powershell
function Get-MyData { ... }
Export-ModuleMember -Function Get-MyData
```

**Manifest Module (.psd1)**
- A PowerShell data file (hash table) that describes the module
- Points to script files, binary assemblies, or other resources
- Defines metadata: version, author, required modules, dependencies
- Can combine multiple .psm1 files or .dll files
- Example:
```powershell
@{
    RootModule = 'MyModule.psm1'
    ModuleVersion = '1.0.0'
    FunctionsToExport = @('Get-MyData')
}
```

**Binary Module**
- A compiled .NET assembly (.dll) containing PowerShell cmdlets
- Highest performance, can expose native code
- Requires C# or other .NET language compilation
- Example: `System.Management.Automation.dll`

**How Import-Module Works:**
1. Searches module paths (`$env:PSModulePath`)
2. Locates module by name (folder or .psd1/.psm1 file)
3. Reads .psd1 manifest if present for metadata
4. Loads .psm1 script(s) or .dll assembly into current session
5. Executes `ModuleInitializationScript` if defined
6. Exports members based on `Export-ModuleMember` or manifest settings
7. Adds module to `$PSModuleAutoLoadingPreference` cache

## PS12 — String Interpolation

**How String Interpolation Works:**
PowerShell evaluates expressions inside double-quoted strings, replacing them with their values.

**Difference Between "..." and '...':**
| Double Quotes `"..."` | Single Quotes `'...'` |
|----------------------|----------------------|
| Enables variable expansion | Literal string only |
| Supports escape sequences (`\n`, `\t`) | No escape sequences (except `''` for a single quote) |
| Supports subexpressions `$()` | No expression evaluation |

**Examples:**
```powershell
$name = "World"
"Hello, $name!"        # "Hello, World!"
'Hello, $name!'        # "Hello, $name!"
"Line1`nLine2"         # Two lines
'Line1`nLine2'         # Literal backslash-n
```

**Including Expressions in Interpolated Strings:**
```powershell
$name = "World"
"Hello, $name!"                    # Variable
"Hello, $($name.ToUpper())!"      # Expression in subexpression
"Value: $($1 + 2)"                # Arithmetic
"Date: $(Get-Date -Format 'yyyy-MM-dd')"  # Command
```

**Here-Strings (@"..."@ or @'...'@):**
- Multi-line string literals using `@` prefix and `@` suffix
- `@"..."@` = double-quoted here-string (supports interpolation)
- `@'...'@` = single-quoted here-string (literal only)
- Useful for multi-line output, SQL queries, templates
```powershell
$multiLine = @"
Line 1
Line 2 with $variable
Line 3
"@
```

## PS13 — Get-Member and Object Exploration

**What is Get-Member?**
`Get-Member` displays the properties, methods, and other members of objects.

**Exploring Objects in the Pipeline:**
```powershell
Get-Process | Get-Member          # Show all members
Get-Process | Get-Member -MemberType Property
Get-Process | Get-Member -MemberType Method
Get-Process | Select-Object -First 1 | Get-Member -Name *Name*
```

**Properties vs Methods vs NoteProperties:**
| Type | Description | Example |
|------|-------------|---------|
| **Properties** | .NET properties from the object's type | `Process.Name`, `Process.Id` |
| **Methods** | Functions the object can execute | `Process.Kill()`, `Process.WaitForExit()` |
| **NoteProperties** | Custom properties added by PowerShell | `PSComputerName`, `PSDrive` |

`Get-Member -NameType NoteProperty` shows only NoteProperties.

**Select-Object vs Where-Object:**
| Select-Object | Where-Object |
|---------------|--------------|
| Filters/transforms **properties** | Filters **objects** based on conditions |
| `Get-Process \| Select-Object Name, Id` | `Get-Process \| Where-Object {$_.CPU -gt 100}` |
| Returns subset of properties | Returns subset of objects |
| Can rename, calculate, format | Can use `-Filter` for faster string-based filtering |

## PS14 — PowerShell Classes (v5+)

**What Are PowerShell Classes?**
PowerShell 5 introduced native class support for defining custom types with properties, methods, and constructors.

**Differences from C# Classes:**
| PowerShell Classes | C# Classes |
|-------------------|------------|
| No inheritance (no `extends`) | Full inheritance support |
| No interfaces | Interface implementation |
| No static members (except `new`) | Static members supported |
| No access modifiers (public/private) | Full access control |
| No generics | Generics supported |
| No operator overloading | Operator overloading |
| Compiled at runtime, not ahead-of-time | AOT compilation |

**Limitations:**
```powershell
# No inheritance
class Base { }
class Derived : Base { }  # ❌ Error

# No interfaces
interface IMyInterface { }  # ❌ Error

# No static members
class MyClass {
    static $Count = 0  # ❌ Error
}

# No access modifiers
class MyClass {
    private $secret = "hidden"  # ❌ Error - all public
}
```

**Constructors:**
```powershell
class Person {
    [string]$Name
    [int]$Age
    
    Person([string]$name, [int]$age) {
        $this.Name = $name
        $this.Age = $age
    }
}
$person = [Person]::new("Alice", 30)
```

**Class vs Function:**
| Use Class When | Use Function When |
|----------------|-------------------|
| Need to maintain state between calls | Performing a single operation |
| Creating reusable objects with behavior | Transforming data in pipeline |
| Modeling domain entities | Wrapping cmdlets or logic |
| Need type safety and IntelliSense | Quick scripting or one-off tasks |

## PS15 — CmdletBinding and Advanced Functions

**What Does [CmdletBinding()] Enable?**
The `[CmdletBinding()]` attribute transforms a function into an advanced function with common PowerShell features:
- Common parameters: `-Verbose`, `-Debug`, `-ErrorAction`, `-WhatIf`, `-Confirm`
- Pipeline support
- Parameter sets
- Transaction support
- Progress reporting

**Key Attributes:**

**1. SupportsShouldProcess:**
```powershell
function Remove-ItemSafe {
    [CmdletBinding(SupportsShouldProcess = $true)]
    param([string]$Path)
    
    if ($PSCmdlet.ShouldProcess($Path, "Remove")) {
        Remove-Item $Path
    }
}
# Usage: Remove-ItemSafe -Path "file.txt" -WhatIf
```

**2. DefaultParameterSetName:**
```powershell
function Get-Data {
    [CmdletBinding(DefaultParameterSetName = 'ByName')]
    param(
        [Parameter(ParameterSetName = 'ByName')]
        [string]$Name,
        
        [Parameter(ParameterSetName = 'ById')]
        [int]$Id
    )
}
```

**3. ValueFromPipeline:**
```powershell
function Process-Item {
    [CmdletBinding()]
    param(
        [Parameter(ValueFromPipeline = $true)]
        [string]$InputObject
    )
    process {
        Write-Output "Processing: $InputObject"
    }
}
# Usage: "a","b","c" | Process-Item
```

**Begin, Process, End Blocks:**
```powershell
function Measure-Items {
    [CmdletBinding()]
    param([Parameter(ValueFromPipeline = $true)][string[]]$Items)
    
    begin {
        # Runs once before any input - initialization
        $count = 0
        Write-Verbose "Starting measurement"
    }
    
    process {
        # Runs once per input object - main processing
        foreach ($item in $Items) {
            $count++
        }
    }
    
    end {
        # Runs once after all input - cleanup/summary
        Write-Output "Total items: $count"
    }
}
```

**Execution Order:**
1. `begin` - once, before pipeline input
2. `process` - once per pipeline object
3. `end` - once, after all input consumed

## PS16 — PowerShell Providers System

**What is the Providers System?**
PowerShell providers expose different data stores as navigable drives and paths, allowing unified access using cmdlets like `Get-ChildItem`, `Set-Location`, etc.

**How Get-ChildItem Works Across Providers:**
```powershell
# FileSystem provider (default)
Get-ChildItem C:\Windows

# Registry provider
Get-ChildItem HKLM:\SOFTWARE

# Certificate provider
Get-ChildItem Cert:\LocalMachine\My

# Environment provider
Get-ChildItem Env:

# Alias provider
Get-ChildItem Alias:
```

**Accessing Registry Like a File System:**
```powershell
# Navigate registry
Set-Location HKLM:\SOFTWARE\Microsoft

# List keys
Get-ChildItem

# Read value
Get-ItemProperty .\Windows\CurrentVersion | Select-Object CurrentVersion

# Create key
New-Item -Path .\MyApp -Force

# Set value
New-ItemProperty -Path .\MyApp -Name "Version" -Value "1.0" -PropertyType String

# Delete key
Remove-Item .\MyApp -Recurse
```

**Provider Comparison:**
| Provider | Drive | Path Example | Get-ChildItem Returns |
|----------|-------|--------------|----------------------|
| FileSystem | C:, D: | `C:\Windows` | Files/Folders |
| Registry | HKLM:, HKCU: | `HKLM:\SOFTWARE` | Registry Keys |
| Certificate | Cert: | `Cert:\LocalMachine\My` | Certificates |
| Environment | Env: | `Env:` | Environment Variables |
| Variable | Variable: | `Variable:` | Variables |
| Function | Function: | `Function:` | Functions |
| Alias | Alias: | `Alias:` | Aliases |

## PS17 — Runspaces and Thread Safety

**What are Runspaces?**
A runspace is an isolated execution environment for PowerShell code—essentially a separate session with its own state, variables, and pipeline.

**Key Objects:**

**1. [runspace]:** Single-threaded execution environment
```powershell
$runspace = [runspace]::Create()
$runspace.Open()
```

**2. [runspacepool]:** Pool of threads for parallel execution
```powershell
$pool = [runspacepool]::Create(1, 4)  # Min 1, Max 4 threads
$pool.Open()
```

**3. [powershell]:** Pipeline execution object
```powershell
$ps = [powershell]::Create()
$ps.RunspacePool = $pool
$ps.AddScript("1 + 2").AddBeginScript("$result = ")
$result = $ps.Invoke()
```

**ForEach-Object -Parallel (v7+) vs Manual Runspace:**

**ForEach-Object -Parallel (Simpler):**
```powershell
1..100 | ForEach-Object -Parallel {
    $using:results += [PSCustomObject]@{
        Number = $_
        Square = $_ * $_
    }
} -ThrottleLimit 4
```

**Manual Runspace (More Control):**
```powershell
$pool = [runspacepool]::Create(1, 4)
$pool.Open()

$scripts = 1..100 | ForEach-Object {
    $ps = [powershell]::Create()
    $ps.RunspacePool = $pool
    $ps.AddScript("$_ * $_")
    $ps.BeginInvoke()
}

$results = $scripts | ForEach-Object { $_.EndInvoke() }
$pool.Close()
```

**Comparison:**
| ForEach-Object -Parallel | Manual Runspace |
|-------------------------|-----------------|
| Simpler syntax | More control over threading |
| Automatic variable sharing via `$using:` | Full control over runspace state |
| Limited to pipeline scenarios | Can execute arbitrary scripts |
| No fine-grained error handling | Custom error handling per runspace |
| PowerShell 7+ only | Works in all versions |

**Thread Safety:**
- Runspaces are NOT thread-safe for shared state
- Use `[concurrent:concurrentdictionary]` for thread-safe collections
- Avoid modifying shared variables across runspace boundaries
