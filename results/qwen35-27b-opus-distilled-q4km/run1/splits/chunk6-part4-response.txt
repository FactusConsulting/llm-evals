# Bash Interview Questions - Detailed Answers

## B11 — Special Variables in Bash

| Variable | Meaning | Use Case |
|----------|---------|----------|
| ` $? ` | Exit status of last command | `if [ $? -eq 0 ]; then echo "Success"; fi` |
| ` $$ ` | PID of current shell | `echo "My PID: $$"` (for lock files, logging) |
| ` $! ` | PID of last background job | `sleep 100 & echo "Background PID: $!"` |
| ` $# ` | Number of positional parameters | `if [ $# -lt 2 ]; then echo "Need 2 args"; fi` |

## B12 — Bash Functions

**Definition and Usage:**
```bash
# Two equivalent syntaxes
function foo {
    echo "Hello"
}

foo() {
    echo "Hello"
}

# Usage
foo
```

**Difference:** `function foo {}` is POSIX-incompatible (bashism); `foo() {}` works in POSIX sh.

**Return Values:**
```bash
# Return exit status (0-255)
my_func() {
    return 42  # Exit status
}

# Return data via stdout
get_value() {
    echo "result"
}
value=$(get_value)

# Return multiple values via global variables
set_result() {
    RESULT_VAR="value"
}
```

## B13 — PATH and Command Resolution

**PATH:** Colon-separated list of directories where bash searches for executables.

**Resolution Order:**
1. Shell builtins
2. Shell functions
3. Hashed commands (cached paths)
4. PATH directories (in order)
5. Current directory (if in PATH)

**Builtin vs External:**
- **Builtin:** Compiled into shell (e.g., `cd`, `echo`, `read`) — faster, can manipulate shell state
- **External:** Separate executable in filesystem — spawns new process

**Check Which Type:**
```bash
type ls        # Shows "ls is a hashed binary"
type cd        # Shows "cd is a shell builtin"
command -v ls  # Returns path to external command
```

## B14 — Trap and Signal Handling

**Setup:**
```bash
#!/bin/bash

cleanup() {
    echo "Cleaning up..."
    rm -f /tmp/mylock.$$
}

trap cleanup EXIT      # Run on normal exit
trap 'echo "Error!"; exit 1' ERR  # On command failure (with set -e)
trap 'echo "Interrupted!"; exit 130' INT  # Ctrl+C
trap 'echo "Terminated!"; exit 143' TERM  # kill signal

main() {
    # ... work ...
}

main "$@"
```

**Execution Order:** When multiple signals arrive, they're queued. EXIT trap runs last, after all signal handlers.

## B15 — xargs vs Command Substitution

| Aspect | Command Substitution | xargs |
|--------|---------------------|-------|
| Arguments | Limited by shell | No limit |
| Memory | Loads all into memory | Streams |
| Parallelism | No | Yes (`-P`) |
| Use case | Small data | Large datasets |

**Filenames with Spaces/Newlines:**
```bash
# Safe pattern
find /path -print0 | xargs -0 -I {} process "{}"

# Or with -d for delimiter
find /path -print0 | xargs -0 -d '\n' process
```

**Parallel Execution:**
```bash
find . -name "*.txt" -print0 | xargs -0 -P 4 -I {} cat {}
# -P 4: Run up to 4 processes in parallel
```

## B16 — Bash Arrays

**Indexed Arrays:**
```bash
# Declare
declare -a arr
arr=(a b c)

# Append
arr+=(d)

# Iterate
for item in "${arr[@]}"; do echo "$item"; done

# Length
echo "${#arr[@]}"  # Number of elements
```

**Associative Arrays:**
```bash
# Declare (requires bash 4+)
declare -A assoc

# Set
assoc[key1]=value1
assoc[key2]=value2

# Iterate
for key in "${!assoc[@]}"; do
    echo "$key: ${assoc[$key]}"
done

# Length
echo "${#assoc[@]}"
```

| Feature | Indexed | Associative |
|---------|---------|-------------|
| Key type | Integer (0,1,2...) | String |
| Declaration | `declare -a` or implicit | `declare -A` required |
| Access | `arr[0]` | `assoc["key"]` |

## B17 — Subshell vs Group Command

```bash
# Group command - same shell
{ echo "A"; VAR=1; }
echo "$VAR"  # Prints: 1

# Subshell - separate process
( echo "B"; VAR=2 )
echo "$VAR"  # Prints: 1 (unchanged)
```

| Aspect | `{ ...; }` | `( ... )` |
|--------|------------|-----------|
| Variable scope | Same shell | New subshell |
| Exit code | Last command in group | Last command in subshell |
| Syntax | Requires newline/semicolon after `{` | No special requirements |

**Piping and While Loop:**
```bash
# Problem: while runs in subshell
echo "1 2 3" | while read n; do
    count=$((count + 1))
done
echo "$count"  # Empty! Lost in subshell

# Solution: Process substitution
while read n; do
    count=$((count + 1))
done < <(echo "1 2 3")
echo "$count"  # Prints: 3
```

## B18 — Signals and Job Control

**Signal Differences:**
| Signal | Value | Meaning | Catchable? |
|--------|-------|---------|------------|
| SIGINT | 2 | Ctrl+C | Yes |
| SIGTERM | 15 | kill (default) | Yes |
| SIGHUP | 1 | Terminal closed | Yes |
| SIGKILL | 9 | kill -9 | **No** (cannot be caught) |

**Graceful Shutdown Script:**
```bash
#!/bin/bash

PIDS=()

cleanup() {
    echo "Shutting down..."
    for pid in "${PIDS[@]}"; do
        kill "$pid" 2>/dev/null
        wait "$pid" 2>/dev/null
    done
    exit 0
}

trap cleanup SIGINT SIGTERM SIGHUP EXIT

worker() {
    while true; do
        sleep 1
    done
}

# Start background jobs
worker & PIDS+=($!)
worker & PIDS+=($!)

wait
```

## B19 — Parallel Log Processing Script

```bash
#!/bin/bash
set -euo pipefail

LOG_FILE="$1"
OUTPUT_FILE="$2"
NUM_WORKERS="${3:-$(nproc)}"
TEMP_DIR=$(mktemp -d)

trap "rm -rf $TEMP_DIR; exit \$?" EXIT

# Processing function
process_chunk() {
    local chunk="$1"
    local output="$2"
    # Example: count error lines
    grep -c "ERROR" "$chunk" > "$output" 2>&1
}
export -f process_chunk

# Split log into chunks
split -l 10000 -d -a 4 "$LOG_FILE" "$TEMP_DIR/chunk_"

# Process in parallel
find "$TEMP_DIR" -name "chunk_*" -print0 | \
    xargs -0 -P "$NUM_WORKERS" -I {} bash -c '
        process_chunk "$1" "$2"
    ' _ {} "$TEMP_DIR/{}.out"

# Merge results (sum all counts)
total=0
for f in "$TEMP_DIR"/*.out; do
    count=$(cat "$f")
    total=$((total + count))
done
echo "$total" > "$OUTPUT_FILE"

echo "Processed $(wc -l < "$LOG_FILE") lines with $NUM_WORKERS workers"
```

**Performance Trade-offs:**
- **Split overhead:** Minimal for large files
- **Parallelism:** Limited by CPU cores and I/O
- **Merge cost:** Linear in number of chunks

**Error Propagation:**
```bash
# Check individual chunk errors
for f in "$TEMP_DIR"/*.out; do
    if ! grep -q "^[0-9]" "$f"; then
        echo "Error in chunk: $(cat "$f")" >&2
        exit 1
    fi
done
```

## B20 — exec and File Descriptors

**exec vs Normal Command:**
```bash
# Normal: Creates subshell, returns to shell
ls
echo "Still in shell"

# exec: Replaces current shell process
exec ls
# echo never runs - shell is gone
```

**File Descriptor Manipulation:**
```bash
# Open FD 3 for writing
exec 3>output.log
echo "Normal stdout"
echo "To FD 3" >&3
exec 3>&-  # Close FD 3

# Redirect all output
exec >output.log 2>&1  # All stdout/stderr to file
```

**Coprocess:**
```bash
#!/bin/bash

# Start coprocess (bash 4+)
coproc MYPROC { cat; }

# Write to coprocess
echo "Hello" >&${MYPROC[1]}

# Read from coprocess
read line <&${MYPROC[0]}
echo "Received: $line"

# Kill coprocess
kill ${MYPROC_PID}
```

**When to Use Coprocess:**
- Bidirectional communication with background process
- Interactive sessions (e.g., database queries, REPL)
- Streaming data both ways without pipes

**Key insight:** Coprocesses provide two-way pipes; regular background jobs only one-way.
