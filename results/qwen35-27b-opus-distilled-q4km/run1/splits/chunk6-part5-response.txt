# PowerShell Interview Questions - Detailed Answers

## PS1 — Write-Output vs Write-Host

| Aspect | Write-Output | Write-Host |
|--------|--------------|------------|
| **Pipeline** | ✅ Passes to next command | ❌ Goes directly to console |
| **Return Value** | Returns object | Returns `$null` |
| **Use Case** | Data processing | Display messages only |

```powershell
# Write-Output passes to pipeline
1..5 | ForEach-Object { Write-Output ($_ * 2) } | Where-Object { $_ -gt 6 }
# Output: 8, 10

# Write-Host bypasses pipeline
1..5 | ForEach-Object { Write-Host ($_ * 2) } | Where-Object { $_ -gt 6 }
# Output: 2, 4, 6, 8, 10 (printed) then nothing (pipeline empty)
```

**Why it matters:** Write-Host breaks pipeline flow. Use Write-Output (or just output the value) for data that needs further processing.

## PS2 — Pipeline & ForEach-Object vs foreach

**Pipeline:** PowerShell's pipeline passes **objects** (not text) between commands. Each command receives objects, processes them, and emits objects.

```powershell
Get-Process | Where-Object { $_.CPU -gt 100 } | Select-Object Name, CPU
# Objects flow: Process[] → Process[] → SelectedObject[]
```

**ForEach-Object vs foreach:**

| ForEach-Object | foreach |
|----------------|---------|
| Cmdlet, pipeline-aware | Language statement, not pipeline-aware |
| Processes each pipeline item | Loops over collection |
| Can be piped to/from | Cannot be piped |

```powershell
# ForEach-Object - pipeline-aware
1..5 | ForEach-Object { $_ * 2 } | Where-Object { $_ -gt 6 }
# Output: 8, 10

# foreach - not pipeline-aware
foreach ($i in 1..5) { $i * 2 } | Where-Object { $_ -gt 6 }
# Output: 2, 4, 6, 8, 10 (all values, then filtered to nothing)
```

**Use ForEach-Object** in pipelines. **Use foreach** for control flow outside pipelines.

## PS3 — [PSCustomObject] vs [hashtable]

| Feature | [PSCustomObject] | [hashtable] |
|---------|------------------|-------------|
| **Order** | ✅ Preserved | ❌ Unordered |
| **Keys** | Case-insensitive | Case-insensitive |
| **Pipeline** | ✅ Objects flow naturally | ❌ Emits key-value pairs |
| **JSON Serialization** | ✅ Native support | ❌ Requires conversion |
| **Property Access** | `$obj.Property` | `$hash['Key']` |

```powershell
# PSCustomObject - ordered, pipeline-friendly
$obj = [PSCustomObject]@{ Name='Alice'; Age=30 }
$obj.Name  # "Alice"

# Hashtable - unordered, not pipeline-friendly
$hash = @{ Name='Alice'; Age=30 }
$hash['Name']  # "Alice"

# Conversion
$hashToObj = $hash | ConvertTo-Json -Depth 10 | ConvertFrom-Json
$objToHash = $obj | ConvertTo-Json -Depth 10 | ConvertFrom-Json | Get-AdaptedObject
```

**Use [PSCustomObject]** for structured data, pipelines, JSON. **Use [hashtable]** for key-value lookups, parameter splatting.

## PS4 — Error Handling

```powershell
# Non-terminating: continues execution
Get-Item "nonexistent"  # Error printed, script continues

# Terminating: stops execution
Get-Item "nonexistent" -ErrorAction Stop  # Throws exception
```

**Hierarchy:**
1. `-ErrorAction` (per-command) overrides
2. `$ErrorActionPreference` (session-wide)
3. `$ErrorActionPreference` values: Continue, Stop, SilentlyContinue, Break, Inquire

**Interaction:**
```powershell
$ErrorActionPreference = "Continue"  # Default

try {
    Get-Item "nonexistent"  # Non-terminating, caught by $Error variable
} catch {
    # NOT executed - non-terminating errors don't trigger catch
}

try {
    Get-Item "nonexistent" -ErrorAction Stop  # Terminating
} catch {
    # EXECUTED - terminating errors trigger catch
}
```

**Key insight:** Non-terminating errors go to `$Error` array. Terminating errors throw exceptions caught by try/catch.

## PS5 — Splatting

```powershell
# Splatting with @params
$Params = @{
    ComputerName = "Server01"
    Credential   = $cred
    ErrorAction  = "Stop"
}
Invoke-Command @Params -ScriptBlock { Get-Process }

# Splatting with @()
Invoke-Command @($ComputerName, $ScriptBlock)
```

**Difference from hashtable parameter:**
```powershell
# Splatting - expands into individual parameters
Invoke-Command @Params  # ComputerName="Server01", Credential=$cred, ErrorAction="Stop"

# Hashtable as single parameter - passed as one object
function Test-Hash { param($Data) }
Test-Hash $Params  # $Data receives the entire hashtable
```

## PS6 — PowerShell Remoting

```powershell
# Invoke-Command -ComputerName: One-way, fire-and-forget
Invoke-Command -ComputerName "Server01" -ScriptBlock { Get-Process }

# Enter-PSSession: Interactive, persistent session
Enter-PSSession -ComputerName "Server01"
PS [Server01]> Get-Process
Exit-PSSession
```

**Protocol:**
- **Windows:** WinRM (WS-Management over HTTP/HTTPS, port 5985/5986)
- **Cross-platform:** SSH (PowerShell 7+, port 22)

```powershell
# WinRM (default on Windows)
Enter-PSSession -ComputerName "Server01"

# SSH (PowerShell 7+)
Enter-PSSession -ComputerName "Server01" -ConfigurationName SSH
```

## PS7 — Type System & Pipeline Behavior

```powershell
function Get-Items {
    $result = @()
    $result += "one"
    return $result
}
$x = Get-Items
$x.GetType().Name  # "String" - NOT "Array"!
```

**Why:** PowerShell's pipeline **unwraps single-element arrays**. When a function returns one item, the pipeline treats it as that item, not an array.

```powershell
# Correct pattern - always return array
function Get-Items {
    $result = @()
    $result += "one"
    return ,$result  # Unwrapping operator forces array
}
# OR
function Get-Items {
    return @("one")  # Array subexpression
}
```

**When 0 items:**
```powershell
function Get-Items {
    return @()  # Returns empty array
}
$x = Get-Items
$x.Count  # 0
$x.GetType().Name  # "Object[]"
```

## PS8 — ScriptBlock vs Function

| Aspect | Function | ScriptBlock |
|--------|----------|-------------|
| **Definition** | Named, reusable | Anonymous code block |
| **Scope** | Global/Script scope | Captures enclosing scope |
| **Remote Pass** | Requires serialization | Can be passed directly |
| **Closure** | Limited | Full closure support |

```powershell
# Function
function Get-Hello { return "Hello" }

# ScriptBlock
$sb = { return "Hello" }
& $sb  # Invoke with call operator

# Passing to remote session
Invoke-Command -ComputerName "Server01" -ScriptBlock { Get-Process }

# Double-hop problem: Credentials don't pass through
# Client -> Server1 (OK) -> Server2 (FAIL - no creds)

# Solutions:
# 1. CredSSP (delegated authentication)
Enter-PSSession -ComputerName "Server01" -Authentication CredSSP

# 2. -ArgumentList (pass data, not credentials)
Invoke-Command -ComputerName "Server01" -ScriptBlock {
    param($Target)
    Invoke-Command -ComputerName $Target -ScriptBlock { Get-Process }
} -ArgumentList "Server02"
```

## PS9 — @() vs [array]

```powershell
# @() - Array subexpression (creates array)
$arr = @("one", "two")  # Array with 2 elements
$single = @("one")      # Array with 1 element

# [array] - Type accelerator (casts to array)
$arr = [array]"one"     # "one" (string, not array!)
$arr = [array]@("one")  # Array with 1 element
```

**Force single result into array:**
```powershell
$result = "single"
$asArray = @($result)  # Array with 1 element
```

**Indexing behavior:**
```powershell
# Indexing $null
$null[0]  # Returns $null (no error)

# Indexing empty array
$arr = @()
$arr[0]   # Returns $null (no error)

# Both return $null, but different types
$null.GetType()  # Error - $null has no type
$arr.GetType()   # "Object[]"
```

## PS10 — Comparison Operators

| Operator | Description | Example |
|----------|-------------|---------|
| `-eq` | Equals | `1 -eq 1` → True |
| `-ne` | Not equals | `1 -ne 2` → True |
| `-like` | Wildcard match | `"test" -like "t*t"` → True |
| `-match` | Regex match | `"test" -match "^t.*t$"` → True |
| `-contains` | Contains (left in right) | `@(1,2,3) -contains 2` → True |
| `-in` | In (left in right) | `2 -in @(1,2,3)` → True |

**Case sensitivity:**
```powershell
"Test" -eq "test"    # True (case-insensitive)
"Test" -ceq "test"   # False (case-sensitive)
"Test" -like "t*"    # True
"Test" -clike "t*"   # False
```

**Key difference: -contains vs -in**
```powershell
# -contains: Does collection contain value?
@(1,2,3) -contains 2  # True

# -in: Is value in collection?
2 -in @(1,2,3)        # True

# They're opposites in syntax, same in meaning
# -contains: Collection -contains Value
# -in: Value -in Collection
```
