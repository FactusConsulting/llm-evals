# SC7 — CI/CD Pipeline Causing Production Drift

## Part A: Drift Sources Analysis

**Drift Source 1: Manual `tofu apply` commands (14 instances)**
- **How it occurred**: Developers bypassed the CI/CD pipeline, running `tofu apply` directly from laptops with local credentials
- **Why dangerous**: Changes not tracked in Git, no peer review, no audit trail, state file corruption risk
- **Data loss scenarios without state locking**:
  - Engineer A creates a database; Engineer B's concurrent apply deletes it (B's plan doesn't know it exists)
  - State file corruption from concurrent S3 writes creates "orphaned" resources OpenTofu can't track
  - Race condition: both engineers read state → both apply → second apply overwrites first's changes

**Drift Source 2: Diverged Helm values files**
- **How it occurred**: Developers used `helm upgrade --set` or local `-f` files not committed to Git
- **Why dangerous**: Staging doesn't match production, can't reproduce environments, rollback impossible

**Drift Source 3: Direct `kubectl edit` on ConfigMaps**
- **What happens with simultaneous `tofu apply`**:
  1. Both engineers read identical state file
  2. Both compute plans based on same baseline
  3. Both apply changes
  4. Second apply may delete resources first engineer created, or create duplicates
  5. S3 state file may be corrupted by concurrent writes

# SC8 — Observability Stack Scaling Failure

## Part A: Diagnosis

**1. Prometheus OOM (64GB RAM, 8.2M series)**
- **Root cause**: High cardinality. Each series ≈ 7.8KB in memory. 8.2M × 7.8KB ≈ 64GB
- **Architectural limit**: Single Prometheus instance max ~5-10M series comfortably
- **High cardinality**: Too many unique label value combinations creating excessive series
- **Confirm with**:
  ```promql
  # Memory usage
  process_resident_memory_bytes
  
  # Series count
  count(up)
  
  # Top cardinality metrics
  topk(20, count by(__name__) (up))
  
  # Find offending labels
  topk(10, count by(pod) (up{job="my-app"}))
  ```

**2. Loki Drops (15% during peak)**
- **Root cause**: Ingester buffer overflow during peak ingestion
- **Architectural limit**: Single ingester ~100K lines/sec max
- **Confirm with**:
  ```bash
  # Loki metrics
  loki_dropped_samples_total
  loki_ingester_memory_chunks
  ```

**3. Tempo Timeouts (>2hr traces)**
- **Root cause**: Local storage not indexed for long-term queries; no partitioning
- **Architectural limit**: Local storage degrades after ~24hr retention
- **Confirm with**:
  ```bash
  tempo_traces_received_total
  tempo_traces_query_duration_seconds
  ```

**4. Thanos Compactor Lag (3 days behind)**
- **Root cause**: 500GB/week growth exceeds compaction capacity
- **Architectural limit**: Compactor needs ~2x compute of ingestion rate
- **Confirm with**:
  ```bash
  thanos_compactor_blocks_pending
  thanos_compactor_compactions_total
  ```

# cardinality-report.sh

PROMETHEUS_URL="${PROMETHEUS_URL:-http://prometheus:9090}"

  --data-urlencode 'query=topk(20, count by(__name__)(up))' | \

  head -20 | \
  awk '{rank++; printf "| %d | %-25s | %s |\n", rank, $1, $2}'

echo "1. Review metrics with >100K series for label optimization"
echo "2. Consider dropping high-cardinality labels via relabeling"
echo "3. Implement recording rules for expensive queries"

**Chargeback Implementation:**

# chargeback_calculator.py
from dataclasses import dataclass
from typing import Dict, List

@dataclass
class TeamUsage:
    team: str
    metrics_bytes: float
    log_bytes: float
    trace_bytes: float
    query_count: int

def calculate_chargeback(usage: List[TeamUsage], rates: Dict[str, float]) -> Dict[str, float]:
    """Calculate per-team charges based on telemetry consumption."""
    charges = {}
    for team in usage:
        charges[team.team] = (
            team.metrics_bytes * rates['metrics_gb'] +
            team.log_bytes * rates['logs_gb'] +
            team.trace_bytes * rates['traces_gb'] +
            team.query_count * rates['query']
        )
    return charges

# Rates per GB/month
RATES = {
    'metrics_gb': 0.50,
    'logs_gb': 0.25,
    'traces_gb': 0.75,
    'query': 0.001
}

# SC9 — Securing a Public-Facing API After a Breach

## Part A: Vulnerability Analysis

**1. BOLA (Broken Object Level Authorization)**
- **OWASP Category**: API1:2023 Broken Object Level Authorization
- **Blast radius**: Complete data breach — attacker accesses all user records
- **Fix**: Object-level permissions in DRF

```python
# permissions.py
from rest_framework import permissions

class IsObjectOwner(permissions.BasePermission):
    """Only allow access to objects owned by the requesting user."""
    
    def has_object_permission(self, request, view, obj):
        return obj.owner == request.user

# views.py
from rest_framework.generics import RetrieveUpdateDestroyAPIView

class UserRecordView(RetrieveUpdateDestroyAPIView):
    queryset = UserRecord.objects.all()
    serializer_class = UserRecordSerializer
    permission_classes = [IsAuthenticated, IsObjectOwner]
    
    def get_object(self):
        # Enforce ownership at object retrieval level
        obj = super().get_object()
        if obj.owner != self.request.user:
            raise PermissionDenied("Access denied")
        return obj
```

**2. Sensitive Data Exposure**
- **OWASP Category**: API2:2023 Broken Authentication / API6:2023 Missing Object Level Authorization
- **Blast radius**: Internal system details exposed, employee IDs leaked
- **Fix**: Field-level serialization control

```python
# serializers.py
from rest_framework import serializers

class UserRecordSerializer(serializers.ModelSerializer):
    class Meta:
        model = UserRecord
        fields = ['id', 'username', 'email', 'created_at']
        # Explicitly exclude sensitive fields
        exclude = ['created_by_employee_id', 'internal_notes', 'password_hash']
```

**3. No Rate Limiting**
- **OWASP Category**: API4:2023 Unrestricted Resource Consumption
- **Blast radius**: Complete database extraction, DoS, resource exhaustion
- **Fix**: DRF Throttling

```python
# settings.py
REST_FRAMEWORK = {
    'DEFAULT_THROTTLE_CLASSES': [
        'rest_framework.throttling.AnonRateThrottle',
        'rest_framework.throttling.UserRateThrottle',
    ],
    'DEFAULT_THROTTLE_RATES': {
        'anon': '100/hour',
        'user': '1000/hour',
        'burst': '100/minute',
    },
}

# throttling.py
from rest_framework.throttling import SimpleRateThrottle

class BurstThrottle(SimpleRateThrottle):
    scope = 'burst'
    
    def get_cache_key(self, request, view):
        if request.user and request.user.is_authenticated:
            return f'{self.scope}:{request.user.username}'
        return f'{self.scope}:{self.get_ident(request)}'
```

**4. API Keys in Query Parameters**
- **OWASP Category**: API7:2023 Server-Side Request Forgery (indirectly)
- **Blast radius**: API keys logged everywhere, easily scraped, no rotation possible
- **Fix**: Header-based authentication

```python
# authentication.py
from rest_framework.authentication import BaseAuthentication
from django.core.exceptions import PermissionDenied

class APIKeyHeaderAuthentication(BaseAuthentication):
    """API key must be in Authorization header, never query params."""
    
    def authenticate(self, request):
        # Reject query parameter API keys
        if 'api_key' in request.query_params:
            raise PermissionDenied("API keys must be in Authorization header")
        
        auth_header = request.META.get('HTTP_AUTHORIZATION', '')
        if not auth_header.startswith('API-Key '):
            return None
        
        api_key = auth_header[8:]  # Remove 'API-Key ' prefix
        api_key_obj = APIKey.objects.filter(key=api_key, active=True).first()
        
        if not api_key_obj:
            return None
        
        return (api_key_obj.user, api_key_obj)
```
