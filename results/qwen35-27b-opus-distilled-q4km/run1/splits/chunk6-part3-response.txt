# Bash Questions - Detailed Answers

## B1 — $@ vs $* and "$@" vs "$*"

| Variable | Behavior |
|----------|----------|
| `$*` | All positional parameters as a **single word** (joined by first char of IFS) |
| `$@` | Each positional parameter as a **separate word** |
| `"$*"` | All parameters as **one quoted string** |
| `"$@"` | Each parameter as a **separately quoted word** |

```bash
set -- "hello world" "foo bar"
echo $*    # "hello world foo bar" (2 words)
echo $@    # "hello world foo bar" (2 words)
echo "$*"  # "hello world foo bar" (1 word)
echo "$@"  # "hello world" "foo bar" (2 words, properly quoted)
```

**Use `"$@"`** when passing arguments to preserve word boundaries.

## B2 — `set -euo pipefail`

| Flag | Meaning |
|------|---------|
| `e` | Exit immediately on command failure |
| `u` | Treat unset variables as errors |
| `o pipefail` | Pipeline returns exit status of rightmost failing command |

```bash
set -euo pipefail
false | true   # Exits with 1 (pipefail catches the false)
echo $UNSET    # Exits with error (u catches unset)
```

## B3 — `$(command)` vs `` `command` `` and `$((expr))` vs `expr`

**Command Substitution:**
- `$(command)` — Modern, nestable, readable
- `` `command` `` — Legacy, harder to nest, requires escaping backticks

```bash
# Nesting is clean with $()
echo $(echo $(echo nested))
# vs backticks (messy)
echo `echo `echo nested``
```

**Arithmetic:**
- `$((expression))` — Bash built-in, fast, no subshell
- `expr` — External command, spawns process, slower

```bash
result=$((5 + 3))    # Built-in, fast
result=$(expr 5 + 3) # External command, slower
```

## B4 — Process Substitution `<()`

Process substitution creates a named pipe (FIFO) or `/dev/fd/N` file descriptor that acts like a file but feeds command output.

```bash
diff <(sort file1) <(sort file2)
```

This compares sorted outputs **without creating temporary files**. The `<()` creates file descriptors that `diff` can read as if they were regular files.

## B5 — Safe File Iteration

```bash
# DANGEROUS - word splitting breaks on spaces
for f in $(ls); do
    echo "$f"
done

# SAFE - null-delimited, no word splitting
while IFS= read -r -d '' file; do
    echo "$file"
done < <(find . -type f -print0)

# Or with mapfile (bash 4+)
mapfile -d '' files < <(find . -type f -print0)
for f in "${files[@]}"; do
    echo "$f"
done
```

**Why `for f in $(ls)` is dangerous:**
1. Word splitting breaks filenames with spaces
2. Glob expansion can match unintended files
3. Newlines in filenames cause issues
4. `ls` parsing is inherently fragile

## B6 — Here Documents vs Here Strings

```bash
# Here document - multi-line input from script
cat <<EOF
Line 1
Line 2
EOF

# Here string - single line input
cat <<< "single line"

# <<-EOF - removes leading tabs from lines
cat <<-EOF
    Line with leading tab (removed)
    Another line
EOF
```

**Key differences:**
- `<<EOF` reads until EOF marker on its own line
- `<<<` provides a single string as input
- `<<-` strips leading tabs from each line

## B7 — Redirection Order Matters

```bash
cmd > file 2>&1    # stdout to file, stderr to stdout (which is file)
cmd 2>&1 > file    # stderr to stdout (terminal), stdout to file
cmd &> file        # Both stdout and stderr to file (bash 3.1+)
```

**Why first two differ:**
- `> file 2>&1`: stdout redirected first, then stderr follows stdout → **both go to file**
- `2>&1 > file`: stderr follows stdout (terminal), then stdout goes to file → **stderr to terminal, stdout to file**

## B8 — Lock File Function

```bash
acquire_lock() {
    local lockdir="/var/lock/myscript"
    
    # mkdir is atomic - either succeeds or fails, no race condition
    if ! mkdir "$lockdir" 2>/dev/null; then
        echo "Lock already held" >&2
        return 1
    fi
    
    # Trap for cleanup on exit, interrupt, or termination
    trap 'rm -rf "$lockdir"' EXIT INT TERM
    
    echo "Lock acquired"
    return 0
}

release_lock() {
    rm -rf "$lockdir"
}
```

**Why `mkdir` is preferred:**
1. **Atomic operation** - no race condition between check and create
2. `touch file; test -f file` has race window
3. `flock` requires file descriptor management
4. `mkdir` fails cleanly if directory exists

## B9 — Quote Types

```bash
name="World"
file="test file.txt"

echo 'Hello $name'      # Hello $name (no expansion)
echo "Hello $name"      # Hello World (expansion)
echo Hello $name        # Hello World (expansion, word splitting)

echo 'file with spaces' # file with spaces (1 word)
echo "file with spaces" # file with spaces (1 word)
echo file with spaces   # file, with, spaces (3 words)
```

| Type | Variable Expansion | Command Substitution | Word Splitting |
|------|-------------------|---------------------|----------------|
| Single quotes | No | No | No |
| Double quotes | Yes | Yes | No |
| No quotes | Yes | Yes | Yes |

## B10 — File Tests and `[ ]` vs `[[ ]]`

```bash
# File tests
[ -e file ]    # Exists
[ -d file ]    # Is directory
[ -f file ]    # Is regular file
[ -r file ]    # Is readable
[ -w file ]    # Is writable
[ -x file ]    # Is executable

# Combined test
if [ -f "$file" ] && [ -r "$file" ]; then
    echo "File exists and is readable"
fi
```

**`[ ]` vs `[[ ]]`:**

| Feature | `[ ]` (test) | `[[ ]]` |
|---------|--------------|---------|
| String comparison | `=` | `=`, `==`, `!=` |
| Pattern matching | No | `==`, `=~` (regex) |
| Logical operators | `-o`, `-a` | `||`, `&&` |
| Word splitting | Yes | No |
| Glob expansion | Yes | No |
| Portability | POSIX | Bash/Ksh/Zsh |

```bash
# [[ ]] is safer - no word splitting or glob expansion
name="file*.txt"
[ -f "$name" ]    # Checks for literal "file*.txt"
[[ -f "$name" ]]  # Same, but safer in complex expressions

# [[ ]] supports regex
[[ $name =~ ^[A-Z]+$ ]] && echo "All uppercase"
```
