# JavaScript / TypeScript Questions

## JS1 — var, let, const, and Hoisting

| Feature | var | let | const |
|---------|-----|-----|-------|
| Scope | Function-scoped | Block-scoped | Block-scoped |
| Hoisting | Yes (initialized as undefined) | Yes (temporal dead zone) | Yes (temporal dead zone) |
| Redeclaration | Allowed | Not allowed | Not allowed |
| Reassignment | Allowed | Allowed | Not allowed |

**Hoisting**: Variable/function declarations are moved to the top of their scope during compilation.

- `var`: Declared but initialized as `undefined`
- `let`/`const`: Declared but in Temporal Dead Zone (TDZ) — accessing before initialization throws ReferenceError

```javascript
console.log(a); // undefined (var hoisted)
var a = 1;

console.log(b); // ReferenceError (TDZ)
let b = 2;
```

## JS2 — Event Loop, Call Stack, and Task Queues

**Architecture:**
```
┌─────────────────────────────────────────────────┐
│                    Call Stack                    │
│  (Synchronous code, LIFO, one thread)            │
└─────────────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────────┐
│              JavaScript Engine                  │
└─────────────────────────────────────────────────┘
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
┌──────────────┐        ┌──────────────┐
│  Microtask   │        │   Macrotask  │
│   Queue      │        │    Queue     │
│ (Promises,  │        │ (setTimeout, │
│  queueMicro) │        │  setInterval)│
└──────────────┘        └──────────────┘
```

**Execution Order:**
1. **Call Stack**: Executes synchronous code
2. **When empty** → Check **Microtask Queue** (drain completely)
3. **Then** → Take **ONE** macrotask from Macrotask Queue
4. **Repeat**

```javascript
console.log('1'); // Sync

setTimeout(() => console.log('2'), 0); // Macrotask

Promise.resolve().then(() => console.log('3')); // Microtask

console.log('4'); // Sync

// Output: 1, 4, 3, 2
```

## JS3 — Closures

**Definition**: A closure is a function that captures and retains access to variables from its outer (enclosing) scope, even after the outer function has returned.

```javascript
function outer() {
  let count = 0;
  return function inner() {
    count++;
    return count;
  };
}
const counter = outer();
console.log(counter()); // 1
console.log(counter()); // 2
```

**Classic For Loop Bug:**

```javascript
// BUGGY
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Output: 3, 3, 3 (all closures reference same `i`)

// FIX 1: Use let (block-scoped, new binding per iteration)
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Output: 0, 1, 2

// FIX 2: IIFE with var
for (var i = 0; i < 3; i++) {
  (function(j) {
    setTimeout(() => console.log(j), 100);
  })(i);
}
```

## JS4 — Promises, async/await, Error Handling

**Promise States**: pending → fulfilled OR rejected

```javascript
// Promise
fetch('/api')
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.error(err));

// async/await
async function getData() {
  try {
    const res = await fetch('/api');
    const data = await res.json();
    console.log(data);
  } catch (err) {
    console.error(err);
  }
}
```

**Error Handling:**
- **Promises**: `.catch()` or second argument to `.then()`
- **async/await**: `try/catch` blocks

**Promise.all vs Promise.allSettled:**

```javascript
// Promise.all - fails fast, returns array of results or throws
Promise.all([p1, p2, p3])
  .then(results => console.log(results))
  .catch(err => console.error('One failed:', err));

// Promise.allSettled - waits for all, returns status for each
Promise.allSettled([p1, p2, p3])
  .then(results => {
    // [{status: 'fulfilled', value: ...}, {status: 'rejected', reason: ...}]
    console.log(results);
  });
```

## JS5 — TypeScript: interface vs type, Discriminated Unions

**interface vs type:**

| Aspect | interface | type |
|--------|-----------|------|
| Mergeable | Yes (declaration merging) | No |
| Extends | `extends` | `extends` |
| Implements | Yes (for classes) | No |
| Object Types | Yes | Yes |
| Union Types | No | Yes |
| Tuple Types | No | Yes |
| Type Aliases | No | Yes |

```typescript
// Interface - mergeable, good for object shapes
interface User { id: number; name: string; }
interface User { email: string; } // Merged!

// Type - more flexible, supports unions/tuples
type Id = number | string;
type Point = [number, number];

// Use interface for: Object shapes, class contracts, declaration merging
// Use type for: Unions, tuples, primitives, mapped types
```

**Discriminated Unions:**

```typescript
type Shape = 
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number };

function area(shape: Shape): number {
  if (shape.kind === 'circle') {
    return Math.PI * shape.radius ** 2;
  }
  return shape.side ** 2;
}
```

## JS6 — Prototypal Inheritance

```javascript
// Object.create() - creates object with specified prototype
const animal = { eats: true };
const rabbit = Object.create(animal);
rabbit.jumps = true;
console.log(rabbit.eats); // true (inherited)

// Prototype chain
console.log(rabbit.__proto__ === animal); // true
console.log(animal.__proto__ === Object.prototype); // true
```

**ES6 Classes and Prototypes:**

```javascript
class Animal {
  constructor(name) { this.name = name; }
  speak() { console.log(this.name + ' speaks'); }
}

class Dog extends Animal {
  bark() { console.log('Woof!'); }
}

// Under the hood:
// - Animal.prototype has speak()
// - Dog.prototype.__proto__ === Animal.prototype
// - new Dog() creates object with Dog.prototype as __proto__
```

## JS7 — The `this` Keyword

**Four Binding Rules (priority order):**

1. **New Binding**: `new` keyword — `this` = newly created object
2. **Explicit Binding**: `call()`, `apply()`, `bind()` — `this` = first argument
3. **Implicit Binding**: Object method call — `this` = calling object
4. **Default Binding**: Standalone function — `this` = `undefined` (strict) or `window` (non-strict)

```javascript
const obj = {
  name: 'Alice',
  greet() { console.log(this.name); }
};

obj.greet(); // "Alice" (implicit)

const greet = obj.greet;
greet(); // undefined (default, strict mode)

greet.call({ name: 'Bob' }); // "Bob" (explicit)

const boundGreet = greet.bind({ name: 'Charlie' });
boundGreet(); // "Charlie" (explicit via bind)

function Person(name) { this.name = name; }
const p = new Person('Dave'); // "Dave" (new binding)
```

**bind()** returns a new function with permanently bound `this`. You **cannot** re-bind it — the binding is permanent.

## JS8 — WeakRef and FinalizationRegistry

**WeakRef**: A weak reference to an object that doesn't prevent garbage collection.

```typescript
const original = new Map();
const weakRef = new WeakRef(original);

// Access via .deref()
const retrieved = weakRef.deref(); // May be undefined if GC'd

// Clear the reference
weakRef.deref(); // undefined after GC
```

**FinalizationRegistry**: Callback when object is garbage collected.

```typescript
const registry = new FinalizationRegistry((heldValue, weakRef) => {
  console.log(`Resource ${heldValue} cleaned up`);
});

const obj = { id: 1 };
registry.register(obj, 'resource-1');

obj = null; // May be GC'd
// Eventually: "Resource resource-1 cleaned up"
```

**WeakMap Keys Must Be Objects:**

```typescript
const wm = new WeakMap();
wm.set({}, 'value'); // OK
wm.set(42, 'value'); // TypeError!
```

**Reason**: WeakMap keys are held weakly — if they could be primitives, they'd never be garbage collected (primitives aren't GC'd). Objects can be collected when no strong references exist.

## JS9 — V8 Optimization

**Hidden Classes:**

```javascript
// Shape 1: {a: 1}
let obj = {a: 1};

// Shape 2: {a: 1, b: 2} — new hidden class
obj.b = 2;

// Shape 3: {a: 1, b: 2, c: 3} — another new class
obj.c = 3;
```

V8 creates hidden classes for objects with same property layout. Objects in same class share optimization.

**Inline Caching:**

```javascript
// Monomorphic — fast (single hidden class)
function add(a, b) { return a + b; }
add(1, 2); add(3, 4); // Both numbers, cached

// Polymorphic — slower (multiple types)
add(1, 2); add('a', 'b'); // Number then string

// Megamorphic — slowest (many types)
add(1, 2); add('a', 'b'); add({}, []); // Many types
```

**Deoptimization Triggers:**

```javascript
// 1. Type changes
let x = 1;
x = 'string'; // Deoptimizes number optimization

// 2. Property added dynamically
function f(obj) {
  obj.newProp = 1; // May deoptimize if hidden class changes
}

// 3. Breaks assumptions
function g(arr) {
  for (let i = 0; i < arr.length; i++) {
    arr[i] = arr[i] * 2; // Assumes numbers
  }
}
g([1, 2, 3]); // OK
g(['a', 'b']); // Deoptimizes
```

## JS10 — Tree-Shaking

**Tree-shaking**: Dead code elimination for unused exports.

**ES Modules (tree-shakeable):**

```javascript
// utils.js
export function used() { return 1; }
export function unused() { return 2; }

// main.js
import { used } from './utils.js';
used(); // `unused` is eliminated
```

**Why ES Modules work:**
- Static analysis possible (imports at top level)
- `export` is a declaration, not a statement
- Module scope is strict

**CommonJS (not tree-shakeable):**

```javascript
// utils.js
module.exports = {
  used: () => 1,
  unused: () => 2
};

// main.js
const { used } = require('./utils');
used(); // `unused` NOT eliminated
```

**Why CommonJS fails:**
- `require()` is a runtime function call
- Dynamic property access (`obj.prop`)
- Module is an object, not a namespace
- Side effects in module scope
