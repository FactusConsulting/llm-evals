# SC10 — Multi-Cluster Disaster Recovery Platform

## SC10-Part A: Kubernetes Multi-Cluster Architecture Design

### Architecture Comparison

| Aspect | Active-Passive (Velero) | Active-Active (Service Mesh) |
|--------|------------------------|------------------------------|
| **RPO Capability** | ❌ Cannot meet 15 min | ✅ Can meet 15 min |
| **RTO Capability** | ❌ Cannot meet 1 hour | ✅ Can meet 1 hour |
| **Complexity** | Low | High |
| **Cost** | Lower | Higher (2x compute) |
| **Data Consistency** | Point-in-time | Near real-time |

### RPO/RTO Calculations

**Active-Passive with Velero:**
- **RPO**: Velero backups typically run hourly → **FAILS 15 min requirement**
- **RTO**: Restore 200TB at 10 Gbps:
  ```
  200 TB × 8 bits/byte = 1,600,000 Gb
  1,600,000 Gb ÷ 10 Gbps = 160,000 seconds = 44.4 hours
  ```
  **FAILS 1 hour requirement**

**Active-Active with Service Mesh:**
- **RPO**: Real-time replication → **MEETS 15 min requirement**
- **RTO**: Failover in seconds/minutes → **MEETS 1 hour requirement**

### Stateful Component Replication Strategies

| Component | Replication Strategy | RPO | Notes |
|-----------|---------------------|-----|-------|
| **PostgreSQL** | Synchronous streaming (2 nodes sync, 1 async) | <1 sec | Patroni manages failover |
| **Redis** | Master-Slave with Sentinel | <1 sec | Sentinel auto-failover |
| **RabbitMQ** | Quorum queues + Federation | <1 sec | Quorum for critical queues |
| **MinIO** | Site replication (async) | 1-5 min | 200TB sync takes 44h initially |

### Service Mesh Recommendation: Cilium Cluster Mesh

**Why Cilium over Istio for this scenario:**
1. **Lower latency**: eBPF-based, no sidecar overhead
2. **Better performance**: Native Kubernetes integration
3. **Simpler multi-cluster**: Built-in Cluster Mesh feature
4. **Resource efficiency**: Critical for 200TB data movement

```yaml
# Configures primary (Chicago) and standby (Dallas) replication

- name: Configure PostgreSQL Streaming Replication with Patroni
  hosts: "{{ group_names['patroni_cluster'] }}"

        dest: "/etc/postgresql/{{ postgres_version }}/main/pg_hba.conf"
        owner: postgres
        group: postgres
        mode: '0640'
      notify: Reload PostgreSQL

      ansible.builtin.postgresql_user:
        name: "{{ replication_user }}"
        password: "{{ replication_password }}"

          cacert-file = /etc/ssl/certs/etcd/ca.crt

        mode: '0600'

    - name: Verify etcd connectivity
      ansible.builtin.command: >
        ETCDCTL_API=3 etcdctl --endpoints={{ etcd_chicago_hosts | join(',') }}
        --cert=/etc/ssl/certs/etcd/client.crt
        --key=/etc/ssl/private/etcd/client.key
        --cacert=/etc/ssl/certs/etcd/ca.crt

      register: etcd_health
      changed_when: false
      failed_when: "'not healthy" in etcd_health.stdout

    # SECTION 4: Template Patroni Configuration
    # ========================================================================

    - name: Create Patroni configuration directory
      ansible.builtin.file:
        path: /etc/patroni
        state: directory
        owner: patroni
        group: patroni
        mode: '0750'

    - name: Template patroni.yml configuration
      ansible.builtin.template:
        src: templates/patroni.yml.j2
        dest: /etc/patroni/patroni.yml
        owner: patroni
        group: patroni
        mode: '0600'

    # ========================================================================
    # SECTION 5: Configure Systemd Service
    # ========================================================================

      ansible.builtin.template:
        src: templates/patroni.service.j2
        dest: /etc/systemd/system/patroni.service
        mode: '0644'
      notify:
        - Reload systemd
        - Restart Patroni

    - name: Enable and start Patroni service
      ansible.builtin.systemd:
        name: patroni
        enabled: true
        state: started
        daemon_reload: true

    # ========================================================================
    # SECTION 6: Configure Replication Slots
    # ========================================================================

    - name: Create physical replication slot for standby
      ansible.builtin.command: >
        psql -h localhost -U postgres -c
        "SELECT pg_create_physical_replication_slot('{{ inventory_hostname }}_slot');"
      register: slot_creation
      changed_when: "'CREATE_REPLICATION_SLOT' in slot_creation.stdout"
      failed_when: "'already exists' not in slot_creation.stderr and 
                    'CREATE_REPLICATION_SLOT' not in slot_creation.stdout"
      become_user: postgres
      when: patroni_role == "master"

    # ========================================================================
    # SECTION 7: Verify Replication Configuration
    # ========================================================================

    - name: Verify replication settings
      ansible.builtin.command: >
        psql -h localhost -U postgres -t -c
        "SHOW synchronous_standby_names;"
      register: sync_standby_check
      become_user: postgres
      changed_when: false

    - name: Display synchronous standby names
      ansible.builtin.debug:
        msg: "Synchronous Standby Names: {{ sync_standby_check.stdout }}"

    - name: Check replication lag
      ansible.builtin.command: >
        psql -h localhost -U postgres -t -c
        "SELECT client_addr, state, sent_lsn, write_lsn, flush_lsn, 
         replay_lsn, sync_state FROM pg_stat_replication;"
      register: replication_status
      become_user: postgres
      changed_when: false
      when: patroni_role == "master"

    - name: Display replication status
      ansible.builtin.debug:
        msg: "Replication Status: {{ replication_status.stdout }}"

  handlers:
    - name: Reload systemd
      ansible.builtin.systemd:
        daemon_reload: true

    - name: Restart PostgreSQL
      ansible.builtin.systemd:
        name: "postgresql@{{ postgres_version }}-main"
        state: restarted

    - name: Reload PostgreSQL
      ansible.builtin.systemd:
        name: "postgresql@{{ postgres_version }}-main"
        state: reloaded

    - name: Restart Patroni
      ansible.builtin.systemd:
        name: patroni
        state: restarted
```

### Detailed Component Failover Procedures

#### 1. Failure Detection

```yaml
# Prometheus Alerting Rules for Site Failure Detection
groups:
  - name: site-health
    rules:
      # Node availability check
      - alert: SiteNodesDown
        expr: |
          sum(up{job="node_exporter", site="chicago"}) 
          != count(up{job="node_exporter", site="chicago"})
        for: 30s
        labels:
          severity: critical
          site: chicago
        annotations:
          summary: "Chicago site nodes are down"
          runbook_url: "https://runbooks.insurance.internal/site-failover"

      # Database master unreachable
      - alert: PatroniMasterUnreachable
        expr: |
          patroni_master{site="chicago"} == 0
        for: 15s
        labels:
          severity: critical
          component: postgresql

      # Redis master down
      - alert: RedisMasterDown
        expr: |
          redis_master_up{site="chicago"} == 0
```
