## .NET / C# (20 questions)

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
*   **Class:** Reference type. Stored on the heap. Passed by reference (copy of the pointer). Supports inheritance. Can be null.
*   **Struct:** Value type. Stored on the stack (or inline within objects). Passed by value (copied). Does not support inheritance (only interfaces). Cannot be null (unless `Nullable<T>`).
*   **When to use struct:** Small, immutable data structures (e.g., `Point`, `Complex`, `DateTime`) that represent a single value rather than an object with identity. Avoid structs if they are large (>16 bytes) or if you need polymorphism.

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
*   **IEnumerable<T>:** Represents in-memory collections. LINQ queries execute immediately on the client side (pulling all data into memory first).
*   **IQueryable<T>:** Represents a queryable data source (like a database). LINQ queries are translated into an expression tree and executed on the server side (SQL generation).
*   **Distinction:** Using `IEnumerable` on a database context forces a `.ToList()` call, loading the entire table into memory before filtering. `IQueryable` pushes the filtering logic to the database, optimizing performance.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
*   **Async/Await:** Transforms a callback-based asynchronous operation into a state machine. `await` pauses the method, returns control to the caller, and resumes when the operation completes.
*   **Task:** A reference type representing an asynchronous operation. It allocates memory on the heap.
*   **ValueTask:** A struct (value type) that can hold either a `Task` or a completed result.
*   **When to use ValueTask:** In high-performance scenarios (like middleware or tight loops) where the operation might complete synchronously. It avoids heap allocation for the `Task` object if the result is ready immediately.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
*   **DI:** A pattern where dependencies are provided to a class rather than created inside it.
*   **Lifetimes:**
    *   **Transient:** Created every time requested.
    *   **Scoped:** Created once per HTTP request (or logical scope).
    *   **Singleton:** Created once for the application lifetime.
*   **Bug (Captive Dependency):** Injecting a Scoped service (e.g., `DbContext`) into a Singleton service. The Singleton lives forever, but the Scoped service is tied to a request. The Singleton will hold onto the Scoped service from the first request, causing stale data or memory leaks.

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
*   **String:** Immutable reference type on the heap. Operations often create new strings (allocations).
*   **ReadOnlySpan<char>:** A stack-only struct representing a contiguous region of memory. It does not allocate memory.
*   **Why use Span:** For high-performance string manipulation (parsing, splitting) where you want to avoid heap allocations and GC pressure. It allows slicing strings without copying data.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
*   **GC:** Automatic memory management. Traces object references to find unreachable objects.
*   **Generations:**
    *   **Gen 0:** Short-lived objects. Collected frequently.
    *   **Gen 1:** Buffer between Gen 0 and 2.
    *   **Gen 2:** Long-lived objects. Collected rarely (expensive).
*   **LOH:** Objects > 85KB go here. Not compacted by default (to avoid moving large blocks).
*   **IDisposable:** Used for deterministic cleanup of unmanaged resources (file handles, DB connections, sockets). The GC only manages managed memory; it doesn't know when to close a file handle immediately.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
*   **Default:** Captures the current `SynchronizationContext` (e.g., UI thread in WPF/WinForms) and marshals the continuation back to it.
*   **ConfigureAwait(false):** Tells the runtime not to capture the context. The continuation runs on a thread pool thread.
*   **When to use:** In library code or server-side code (ASP.NET) to avoid deadlocks and improve performance by not blocking the UI or request thread.
*   **When NOT to use:** In UI code where you need to update UI controls (which require the UI context).

**DN8 — Hard: Explain the new .NET 8/9 features: primary constructors, collection expressions, and FrozenDictionary. Write a minimal example using primary constructors with DI.**
*   **Primary Constructors:** Define parameters in the class declaration, reducing boilerplate for properties and constructors.
*   **Collection Expressions:** `var list = [1, 2, 3];` syntax for creating lists/arrays.
*   **FrozenDictionary:** Immutable, high-performance dictionary optimized for read-only scenarios.
*   **Example:**
    ```csharp
    public class MyService(string name) {
        public string Name { get; } = name;
    }
    // DI Registration
    services.AddSingleton<MyService>("MyServiceName");
    ```

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
*   **Cause:** A Singleton service is holding a reference to a Scoped `DbContext`. When the HTTP request ends, the Scope disposes the `DbContext`. Later, the Singleton tries to use it, causing `ObjectDisposedException`.
*   **Fix:** Ensure `DbContext` is injected only into Scoped services. If a Singleton needs data, it should fetch it within a scoped context or use a repository pattern that creates a scope per operation.
*   **Interaction:** EF Core `DbContext` is designed to be lightweight and short-lived. It maps 1:1 with the DI Scope (usually an HTTP Request).

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
*   **Record:** Reference type optimized for immutability. Provides value-based equality (overrides `Equals`, `GetHashCode`), `with` expressions for copying, and concise syntax.
*   **Record Struct:** Value type version of a record. Immutable, value equality, stack-allocated.
*   **Choice:** Use `class` for mutable objects with identity. Use `record` for DTOs and immutable data carriers. Use `record struct` for small, high-performance geometric or math types.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
*   **ref:** Pass by reference. Caller must initialize. Can read and write.
*   **out:** Pass by reference. Caller does not need to initialize. Method must assign before returning. Used for multiple return values.
*   **in:** Pass by reference (read-only). Prevents the method from modifying the argument. Avoids copying large structs.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
*   **Nullable Reference Types (NRT):** A compile-time feature (annotations) to track nullability. `string?` means "can be null", `string` means "cannot be null". No runtime change.
*   **Nullable Value Types:** `int?` is actually `Nullable<int>`. It wraps the value type and adds a `HasValue` property. It has runtime overhead.
*   **Difference:** NRT is for static analysis/safety; `Nullable<T>` is for storing null in value types.

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
*   **LINQ:** Language Integrated Query. Standardized way to query data.
*   **Syntax:** Query syntax is sugar translated into method syntax by the compiler. Method syntax supports more advanced features (like async methods).
*   **Deferred Execution:** The query isn't run until you enumerate the results (e.g., `foreach`, `.ToList()`). This allows composing queries efficiently.

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
*   **Constraints:** Limit what types can be used for `T`.
*   **`class`**: Reference type only.
*   **`struct`**: Value type only.
*   **`new()`**: Must have a public parameterless constructor.
*   **`IComparable<T>`**: Must implement this interface.
*   **Combining:** `where T : class, IComparable<T>, new()` ensures T is a reference type, comparable, and instantiable.

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
*   **Abstract Class:** Can have state (fields), constructors, and partial implementations. Single inheritance.
*   **Interface:** Pure contract (historically). Multiple inheritance.
*   **Change:** C# 8+ allows default implementations in interfaces, blurring the line. However, abstract classes still support state and constructors, which interfaces cannot.

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
*   **Pipeline:** A series of delegates that process requests sequentially.
*   **`Use()`:** Adds middleware that can pass the request to the next component (`next()`).
*   **`Map()`:** Branches the pipeline based on a path.
*   **`Run()`:** Terminal middleware. Does not call `next()`. Ends the pipeline.
*   **Ordering:** Critical. Authentication must come before Authorization. Logging usually comes first.
*   **Exception Handling:** Wraps the pipeline in a `try/catch`. If an exception occurs, it short-circuits the rest of the pipeline and returns an error response.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
*   **Channel<T>:** Modern, async-first thread-safe queue for producer-consumer scenarios.
*   **vs BlockingCollection:** `BlockingCollection` is sync-first and based on `IEnumerable`. `Channel` supports `await` and cancellation tokens natively.
*   **Backpressure:**
    ```csharp
    var channel = Channel.CreateBounded<int>(new BoundedChannelOptions(10) { FullMode = BoundedChannelFullMode.Wait });
    // Writer waits if buffer is full
    await channel.Writer.WriteAsync(value);
    ```

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
*   **Source Generators:** Run at compile time to generate C# code based on annotations or existing code.
*   **vs Reflection:** Reflection runs at runtime (slow). Generators run at compile time (zero runtime cost).
*   **vs IL Weaving:** Weaving modifies compiled binaries (DLLs). Generators modify source code before compilation.
*   **Incremental Generator:** Tracks changes in input files and only regenerates code for what changed. Preferred for build performance in large solutions.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
*   **TPL Dataflow:** Library for building concurrent pipelines.
*   **Blocks:**
    *   `ActionBlock<T>`: Consumes data and performs an action.
    *   `TransformBlock<TIn, TOut>`: Transforms input to output.
    *   `BufferBlock<T>`: Stores data for later retrieval.
*   **vs Channels:** Dataflow is higher-level, offering built-in buffering and backpressure logic between blocks. Channels are lower-level primitives requiring manual orchestration of readers/writers.

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**
*   **Minimal APIs:** Define endpoints as delegates in `Program.cs` without Controllers.
*   **Trade-offs:**
    *   **Pros:** Less boilerplate, great for microservices/scripts.
    *   **Cons:** Harder to organize in large apps. Testability requires more setup (no built-in controller context).
*   **OpenAPI:** Supported via Swashbuckle, but requires manual configuration compared to Controllers.
*   **Route Groups:** `app.MapGroup("/api")` allows sharing middleware/routes.
