# .NET / C# Answers

## DN1 — Class vs Struct

| Aspect | Class | Struct |
|--------|-------|--------|
| Type | Reference type | Value type |
| Memory | Heap (usually) | Stack (usually) |
| Copy semantics | Copy by reference | Copy by value |
| Inheritance | Supports inheritance | Cannot inherit (except from System.ValueType) |
| Default value | null | Zero-initialized |
| Nullability | Can be null | Cannot be null (use Nullable<T>) |

**When to use struct:**
- Small, immutable data types (Point, Rectangle, Complex)
- When you want value semantics (copy on assignment)
- When avoiding heap allocation matters for performance
- When the type logically represents a single value, not an object

## DN2 — IEnumerable<T> vs IQueryable<T>

```csharp
IEnumerable<T> - In-memory enumeration
IQueryable<T> - Deferred query expression tree
```

**Key differences:**
- `IEnumerable<T>`: Operations execute in memory. Filters, projections happen client-side.
- `IQueryable<T>`: Builds an expression tree that can be translated to SQL (or other query languages).

**Why it matters for databases:**
```csharp
// IEnumerable - loads ALL records, then filters in memory (BAD)
var users = context.Users.ToList();  // N+1 problem
var active = users.Where(u => u.IsActive);

// IQueryable - filters in database (GOOD)
var active = context.Users.Where(u => u.IsActive).ToList();  // SQL WHERE clause
```

## DN3 — async/await, Task vs ValueTask

**How async/await works:**
1. Compiler transforms async method into a state machine
2. `await` suspends execution, returns control to caller
3. When awaited task completes, state machine resumes
4. No thread blocking during wait

**Task vs ValueTask:**
| Task | ValueTask |
|------|-----------|
| Captures state on heap | Stack-allocated when synchronous |
| Always async overhead | Zero allocation for sync completion |
| Reference type | Struct (value type) |

**When to use ValueTask:**
- High-performance scenarios with many synchronous completions
- Library APIs where you want to avoid allocations
- When you can guarantee the task completes synchronously often

```csharp
// ValueTask is beneficial here
public async ValueTask<int> GetCachedValueAsync(string key)
{
    if (cache.TryGetValue(key, out var value))
        return value;  // Synchronous, no allocation
    return await FetchFromDatabaseAsync(key);
}
```

## DN4 — Dependency Injection

**Three service lifetimes:**
| Lifetime | Description | Created When |
|----------|-------------|--------------|
| Transient | New instance each request | Every injection |
| Scoped | One instance per request | First injection in request |
| Singleton | One instance per application | First injection ever |

**Scoped-in-Singleton Bug:**
```csharp
// BUG: Scoped service captured in singleton
public class SingletonService {
    private readonly ScopedService _scoped;  // Captured ONCE at startup
    public SingletonService(ScopedService scoped) => _scoped = scoped;
}

// The scoped service lives as long as the singleton (wrong!)
```

**Fix:** Use `IServiceScopeFactory` or inject `IServiceProvider`:
```csharp
public class SingletonService {
    private readonly IServiceProvider _provider;
    public SingletonService(IServiceProvider provider) => _provider = provider;
    
    public async Task DoWorkAsync() {
        using var scope = _provider.CreateScope();
        var scoped = scope.ServiceProvider.GetRequiredService<ScopedService>();
        await scoped.DoWorkAsync();
    }
}
```

## DN5 — string vs ReadOnlySpan<char>

| string | ReadOnlySpan<char> |
|--------|-------------------|
| Heap-allocated reference | Stack-allocated view |
| GC pressure | No GC pressure |
| Bounds checking | Bounds checking |
| Can't be stored in fields | Can't be stored (stack-only) |
| Immutable | Immutable view |

**When to use Span<T>:**
- High-performance string parsing
- Avoiding allocations in hot paths
- Working with substrings without copying
- Interop with native code

```csharp
// Without Span - creates new string allocations
var parts = line.Split(',');  // Allocates array of strings

// With Span - zero allocation
ReadOnlySpan<char> lineSpan = line;
int commaPos = lineSpan.IndexOf(',');
ReadOnlySpan<char> firstPart = lineSpan.Slice(0, commaPos);
```

## DN6 — Garbage Collector

**Generations:**
- **Gen 0**: Short-lived objects, collected frequently
- **Gen 1**: Buffer between Gen 0 and Gen 2
- **Gen 2**: Long-lived objects, collected rarely (expensive)

**Large Object Heap (LOH):**
- Objects > 85KB go here
- Not generational (by default)
- Can cause fragmentation

**Why IDisposable with GC?**
```csharp
// GC only manages memory, not external resources
public class DatabaseConnection : IDisposable {
    private IntPtr _handle;  // OS handle, not managed memory
    
    public void Dispose() {
        CloseHandle(_handle);  // Release OS resource immediately
    }
}
```

Without Dispose: Resources held until GC runs (non-deterministic)

## DN7 — ConfigureAwait(false)

**Default behavior:**
- Captures `SynchronizationContext`
- Continues on same context (UI thread in WinForms/WPF)
- Can cause deadlocks in UI apps

**ConfigureAwait(false):**
- Doesn't capture context
- Continues on thread pool thread
- Better for library code, server apps

```csharp
// Library code - use ConfigureAwait(false)
public async Task<string> FetchDataAsync() {
    return await httpClient.GetStringAsync(url).ConfigureAwait(false);
}

// UI code - default is fine (need UI thread)
private async void Button_Click() {
    var data = await FetchDataAsync();  // Can update UI directly
    Label.Text = data;
}
```

**When NOT to use:**
- UI code that needs to update controls
- When you specifically need the synchronization context

## DN9 — ObjectDisposedException Diagnosis

**Problem:** DbContext is Scoped, but being used beyond request scope.

**Likely causes:**
1. DbContext injected into Singleton service
2. Async operation completes after request ends
3. Background service holding DbContext reference

```csharp
// BUG: Background service with scoped DbContext
public class BackgroundService : BackgroundService {
    private readonly DbContext _context;  // Disposed after first request!
    
    public BackgroundService(DbContext context) => _context = context;
    
    protected override async Task ExecuteAsync(CancellationToken ct) {
        while (!ct.IsCancellationRequested) {
            await _context.QueryAsync();  // ObjectDisposedException!
        }
    }
}
```

**Fix:**
```csharp
public class BackgroundService : BackgroundService {
    private readonly IServiceScopeFactory _scopeFactory;
    
    protected override async Task ExecuteAsync(CancellationToken ct) {
        while (!ct.IsCancellationRequested) {
            using var scope = _scopeFactory.CreateScope();
            var context = scope.ServiceProvider.GetRequiredService<DbContext>();
            await context.QueryAsync();
        }
    }
}
```

## DN10 — record vs class vs record struct

| Type | Semantics | Use Case |
|------|-----------|----------|
| class | Reference, mutable | Objects with identity |
| record | Reference, value equality | Immutable DTOs, data carriers |
| record struct | Value type, value equality | Small immutable types (Point, Money) |

```csharp
// Record struct - value type semantics
public readonly record struct Point(double X, double Y);
```

## DN11 — ref, out, in

| Modifier | Direction | Must Initialize | Use Case |
|----------|-----------|-----------------|----------|
| ref | Bidirectional | Yes (caller) | Modify existing value |
| out | Output only | No (callee) | Return multiple values |
| in | Input only | Yes (caller) | Pass large structs by ref (read-only) |

```csharp

void Create(out int x) { x = 10; }     // Caller doesn't init
void Read(in Point p) { ... }          // Large struct, read-only
```

## DN13 — LINQ

**Method syntax vs Query syntax:**
```csharp
// Method syntax (fluent)
var result = list.Where(x => x > 5).Select(x => x * 2);

// Query syntax (SQL-like)
var result = from x in list
             where x > 5
             select x * 2;
```

Both compile to same IL. Query syntax is syntactic sugar.

**Deferred execution:**
```csharp
var query = list.Where(x => x > 5);  // Nothing executed yet!
list.Add(10);
var result = query.ToList();  // NOW it executes (includes 10)
```

## DN18 — Source Generators

```csharp
[Generator]
public class MyGenerator : IIncrementalGenerator {
    public void Initialize(IncrementalGeneratorInitializationContext context) {
        context.RegisterSourceOutput(..., (spc, source) => {
            source.AddSource("Generated.cs", "public class Generated { }");
```

- Reflection runs at runtime (slower, breaks encapsulation)
- IL weaving modifies compiled assemblies (complex, tooling issues)

**Incremental generators preferred:**
- Only re-run when inputs change
- Much faster compilation

## P2 — GIL (Global Interpreter Lock)

The GIL prevents multiple threads from executing Python bytecode simultaneously.

**Affected workloads:**
- CPU-bound tasks (computation, parsing)
- Multi-core utilization blocked

**Workarounds:**
```python
# 1. Multiprocessing (separate processes)
from multiprocessing import Pool
with Pool() as p: p.map(cpu_bound_func, data)

# 2. Async I/O (for I/O-bound tasks)
import asyncio
await asyncio.gather(io_bound1(), io_bound2())

# 3. Release GIL in C extensions
# NumPy, many C extensions release GIL during computation
```

## P3 — deepcopy vs copy

```python
import copy

# Shallow copy - nested objects shared
original = {"users": [{"name": "Alice"}]}
shallow = copy.copy(original)
shallow["users"][0]["name"] = "Bob"
print(original["users"][0]["name"])  # "Bob" - modified!

# Deep copy - completely independent
original = {"users": [{"name": "Alice"}]}
deep = copy.deepcopy(original)
deep["users"][0]["name"] = "Bob"
print(original["users"][0]["name"])  # "Alice" - unchanged!
```

## P4 — Decorators

```python
import time
from functools import wraps

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        end = time.perf_counter()
        print(f"{func.__name__} took {end - start:.4f}s")
        return result
    return wrapper

@timer
def slow_function():
    time.sleep(1)
    return "done"
```

## P5 — Generators and yield

```python
# Generator - lazy evaluation, one value at a time
def count_up_to(n):
    i = 1
    while i <= n:
        yield i  # Pause, return value, resume later
        i += 1

for num in count_up_to(5):
    print(num)  # 1, 2, 3, 4, 5

# yield from - delegate to another generator
def chain(gen1, gen2):
    yield from gen1
    yield from gen2
```

**vs returning list:**
- Generator: O(1) memory, lazy
- List: O(n) memory, eager

## P7 — MRO (Method Resolution Order)

Python 3 uses **C3 linearization** algorithm.

```python
class A:
    def who(self): return "A"
class B(A):
    pass
class C(A):
    def who(self): return "C"
class D(B, C):
    pass

print(D().who())  # "C"
```

**MRO:** `D -> B -> C -> A -> object`

**Why "C"?**
1. D doesn't have `who()`
2. B doesn't have `who()`
3. C has `who()` → returns "C"

```python
print(D.__mro__)  # Shows the resolution order
```

## P8 — Metaclasses vs __init_subclass__

**Metaclass:**
```python
class Meta(type):
    def __new__(mcs, name, bases, namespace):
        # Modify class before creation
        namespace['created_by'] = mcs.__name__
        return super().__new__(mcs, name, bases, namespace)

class Base(metaclass=Meta):
    pass

print(Base.created_by)  # "Meta"
```

**__init_subclass__:**
```python
class Base:
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        cls.registered = True

class Child(Base):
    pass

print(Child.registered)  # True
```

**Use `__init_subclass__` when possible** (simpler, more Pythonic).

## P9 — multiprocessing vs threading vs concurrent.futures

```python
# Threading - for I/O bound (GIL limits CPU bound)
from threading import Thread

# Multiprocessing - for CPU bound (bypasses GIL)
from multiprocessing import Process

# concurrent.futures - unified API
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

with ThreadPoolExecutor() as executor:
    results = executor.map(io_bound_func, data)

with ProcessPoolExecutor() as executor:
    results = executor.map(cpu_bound_func, data)
```

**Pickling implications:**
- Multiprocessing requires objects to be picklable
- Lambdas, local functions, class instances often not picklable
- Use `__main__` module functions for worker functions

## P10 — __slots__

```python
class WithoutSlots:
    def __init__(self):
        self.x = 1
        self.y = 2

class WithSlots:
    __slots__ = ['x', 'y']
    def __init__(self):
        self.x = 1
        self.y = 2
```

**Benefits:**
- Memory savings (no `__dict__` per instance)
- Faster attribute access
- Prevents arbitrary attribute assignment

**Trade-offs:**
- Cannot add dynamic attributes
- No `__dict__` available
- Slightly more complex inheritance

## P14 — *args, **kwargs, /, *


## P15 — Context Managers

```python
# Using __enter__/__exit__
class DatabaseConnection:
    def __enter__(self):
        self.conn = connect()
        return self.conn
    def __exit__(self, exc_type, exc_val, exc_tb):
        self.conn.close()
        return False  # Don't suppress exceptions

with DatabaseConnection() as conn:
    conn.query("SELECT *")

# Using @contextmanager
from contextlib import contextmanager

@contextmanager
def timer():
    start = time.perf_counter()
    yield
    print(f"Took {time.perf_counter() - start}s")

with timer():
    do_work()
```

## P17 — Data Model (Dunder Methods)

```python
class MyClass:
    def __repr__(self):   # For debugging, unambiguous
        return f"MyClass({self.value})"
    
    def __str__(self):    # For users, readable
        return f"Value: {self.value}"
    
    def __eq__(self, other):  # Equality
        return self.value == other.value
    
    def __hash__(self):       # For dict keys, set members
        return hash(self.value)
    
    def __getattr__(self, name):  # Only if attribute missing
        return 0
    
    def __getattribute__(self, name):  # Always called
        return object.__getattribute__(self, name)
```

**If you define `__eq__` but not `__hash__`, the object becomes unhashable** (can't be in sets or dict keys).

## P18 — Descriptors

```python
class Temperature:
    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return obj._temperature * 1.8 + 32  # Convert to Fahrenheit
    
    def __set__(self, obj, value):
        obj._temperature = (value - 32) / 1.8  # Store as Celsius

class Weather:
    temp = Temperature()  # Descriptor instance

w = Weather()
w.temp = 0      # __set__ called, stores 0°C
print(w.temp)   # __get__ called, returns 32°F
```

`property`, `classmethod`, `staticmethod` are all descriptors.

## P20 — dataclasses vs attrs vs Pydantic

```python
from dataclasses import dataclass, field
from typing import List

@dataclass
class User:
    name: str
    age: int
    tags: List[str] = field(default_factory=list)  # Mutable default
    
    def __post_init__(self):
        self.name = self.name.upper()

@dataclass(frozen=True)
class ImmutableUser:
    name: str
    age: int
```

**Comparison:**
| Feature | dataclasses | attrs | Pydantic |
|---------|-------------|-------|----------|
| Built-in | Standard library | Third-party | Third-party |
| Validation | None | Basic | Full (with types) |
| Serialization | Manual | Manual | Built-in |
| Performance | Good | Good | Slower (validation) |

**Choose Pydantic when:**
- You need validation (email format, min/max values)
- You need automatic serialization/deserialization
- You're building APIs (FastAPI integration)
