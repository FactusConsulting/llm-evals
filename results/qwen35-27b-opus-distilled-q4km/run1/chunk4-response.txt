# Go Questions (G1-G20)

## G1 — Slice vs Array
- **Array**: Fixed-size, value type, stored inline. `var arr [3]int`
- **Slice**: Dynamic view into array, reference type (header with ptr, len, cap). `var s []int`
- **Append beyond capacity**: Allocates new underlying array (typically 2x capacity), copies elements, updates slice header.

## G2 — `var x int` vs `x := 0`
- `var x int`: Package-level or function-level declaration, zero value (0).
- `x := 0`: Short variable declaration, type inferred, only inside functions.
- **Cannot use `:=`**: At package level, when redeclaring existing variable, or when you need explicit type.

## G3 — Goroutines and GMP Model
- **Goroutine**: Lightweight thread managed by Go runtime (stack starts at ~2KB, grows/shrinks).
- **vs OS thread**: Much cheaper (~2KB vs ~1MB stack), millions possible vs thousands.
- **GMP Model**: G (goroutine), M (machine/OS thread), P (processor). P holds G queue; M executes G from P. Scheduler moves G between P, parks/unparks M.

## G4 — Channels
- **Channel**: Typed conduit for goroutine communication, enforces synchronization.
- **Unbuffered**: Blocks sender until receiver ready (rendezvous).
- **Buffered**: Holds up to N values; sender blocks only when full.
- **Send to full buffered channel**: Blocks until receiver reads.

## G5 — Context Package
- **Purpose**: Carry deadlines, cancellation signals, request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
resp, err := http.GetWithContext(ctx, "http://example.com")
```

## G6 — Interface Satisfaction
- **Implicit satisfaction**: Type satisfies interface if it has all methods (no `implements` keyword).
- **vs Java/C#**: Explicit declaration required.
- **`interface{}` (or `any`)**: Empty interface satisfied by all types.
- **Powerful**: Enables generics before Go 1.18, type-erased containers.
- **Dangerous**: Requires type assertions, runtime type checks, no compile-time safety.

## G7 — Memory Model / Data Race
- **Unsafe**: No synchronization; `ready` read may not see `true` due to reordering/caching.
- **Correct alternatives**:
  - `sync.WaitGroup` or `sync.Cond`
  - Channel: `done := make(chan struct{})`; close when ready
  - `sync.Once` for one-time initialization

## G8 — Mutex vs RWMutex vs sync.Map
- **`Mutex`**: Exclusive lock for read/write.
- **`RWMutex`**: Multiple readers OR one writer; better for read-heavy workloads.
- **`sync.Map`**: Optimized for (1) per-goroutine keys, or (2) infrequently changing keys.
- **Trade-off**: `sync.Map` has higher overhead for frequent updates/deletes; regular map + mutex better for write-heavy or small maps.

## G9 — Go Modules
- **`go.mod`**: Module definition, dependencies, requirements.
- **`go.sum`**: Lock file with checksums for reproducible builds.
- **`go mod tidy`**: Adds missing, removes unused dependencies.
- **MVS**: Selects minimum version satisfying all requirements (resolves to lowest compatible version).

## G10 — Defer
- Executes on function return (after locals computed, before actual return).
- **Order**: LIFO (last deferred, first executed).
- **Gotcha in loop**: `defer` captures loop variable by reference; all defers may see final value.
```go
for i := 0; i < 3; i++ {
    defer fmt.Println(i) // All print 3!
}
```

## G11 — Pointers
- **Pointer**: Memory address of a value.
- **Zero value**: `nil`.
- **Pointer to struct literal**: `&Struct{Field: value}`

## G12 — init() Function
- Runs before `main()` in package initialization order.
- **Multiple `init()` allowed**; order unspecified within package, but after imported packages init.

## G13 — make vs new
- **`new(T)`**: Allocates zeroed memory, returns `*T`. Works with any type.
- **`make(T, args)`**: Initializes slice, map, or channel; returns the value (not pointer).

## G14 — Error Handling
- **`error` interface**: `type error interface { Error() string }`
- **Idiomatic**: `if err != nil { ... }`
- **`errors.Is(err, target)`**: Checks if err equals target or wraps it.
- **`errors.As(err, target)`**: Extracts underlying type from wrapped error.

## G15 — Composite Types Zero Values
- **`map[K]V`**: `nil` (must make before use)
- **`[]T`**: `nil` (len=0, cap=0)
- **`chan T`**: `nil` (blocks on send/receive)
- **`struct{}`**: All fields at zero values

## G16 — Race Condition
- **Race**: Concurrent access where at least one is write, without synchronization.
- **`-race`**: Data race detector (sanitizer), catches races at runtime.
- **Example**:
```go
var count int
go func() { count++ }()
go func() { count++ }()
```
- **Fix with Mutex**:
```go
var mu sync.Mutex
mu.Lock(); count++; mu.Unlock()
```

## G17 — Select Statement
- Waits on multiple channel operations; blocks until one is ready.
- **vs switch**: `switch` evaluates expressions; `select` waits on channels.
- **Multiple ready**: Pseudo-randomly picks one.
- **Timeout**:
```go
select {
case result := <-ch:
    // got result
case <-time.After(2 * time.Second):
    // timeout
}
```

## G18 — Escape Analysis
- Compiler determines if variable can stay on stack or must move to heap.
- **Escapes to heap if**: address taken and returned, stored in heap-allocated struct, used after function returns.
- **Inspect**: `go build -gcflags="-m"` or `-m -m` for details.
- **Matters**: Heap allocation is slower, adds GC pressure.

## G19 — Reflection
- **`reflect.Type`**: Static type information.
- **`reflect.Value`**: Runtime value + type.
- **Costs**: 10-100x slower than direct calls, heap allocations.
- **Justified**: Frameworks, ORMs, serializers. Prefer code generation (go generate, genny) for performance-critical paths.

## G20 — go:embed
- Embeds files at compile time into binary.
```go
//go:embed file.txt
var file []byte

//go:embed dir/*
var dirFS embed.FS

//go:embed templates/*.html
var templates embed.FS
```
- **Limitations**: Cannot embed directories with `*` at top level without pattern; max file size limits may apply.
- **`io/fs.FS`**: Embedded FS implements this interface for standard file operations.

# Rust Questions (R1-R20)

## R1 — Ownership
- Every value has exactly one owner.
- When owner goes out of scope, value is dropped.
- **Move semantics**: Assigning transfers ownership (original invalid).
- **Three rules**: One owner, move on assign, drop on scope exit.

## R2 — String vs &str
- **`String`**: Heap-allocated, owned, growable string.
- **`&str`**: String slice, borrowed view into string data.
- **Function signatures**: Use `&str` for parameters (accepts `&String` or string literals), `String` for owned return values.

## R3 — Borrowing
- **Shared reference `&T`**: Read-only, multiple allowed simultaneously.
- **Mutable reference `&mut T`**: Read/write, exclusive (only one at a time).
- Cannot have `&mut` and `&` to same data simultaneously.
- **Borrow checker enforces at compile time**.

## R4 — Result and Option
- **`Result<T, E>`**: Success (`Ok(T)`) or error (`Err(E)`).
- **`Option<T>`**: Some value (`Some(T)`) or none (`None`).
- **`?` operator**: Propagates errors, returns early on `Err`/`None`.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)?
}
```

## R5 — Box, Rc, Arc
- **`Box<T>`**: Heap allocation, single owner, known size at compile time.
- **`Rc<T>`**: Reference-counted, single-threaded, shared ownership.
- **`Arc<T>`**: Atomic reference-counted, thread-safe, shared ownership.
- **Use `Box`** for recursive types/large data; **`Rc`** for single-threaded sharing; **`Arc`** for multi-threaded sharing.

## R6 — Traits
- Similar to Go interfaces but with associated types, defaults, and bounds.
- **Trait object `dyn Trait`**: Dynamic dispatch (vtable), heap-allocated.
- **Generic `T: Trait`**: Static dispatch (monomorphization), inlined.
- **Static dispatch is faster**; dynamic dispatch enables heterogeneous collections.

## R7 — Lifetimes
- **Fails**: Return type lifetime not tied to inputs; could return dangling reference.
- **Fix with lifetime annotations**:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```
- `'a` ensures return reference lives at least as long as both inputs.

## R8 — Send and Sync
- **`Send`**: Type can be transferred across threads (via `move`).
- **`Sync`**: `&T` is `Send` — type can be safely shared via reference.
- **`Rc<T>` not `Send`**: Reference count not atomic; data races on count.
- **`Arc<T>` is `Send`**: Atomic reference count, thread-safe increments/decrements.

## R9 — Async/Await
- **`Future`**: State machine representing pending computation; polled by executor.
- **Executor (Tokio)**: Drives futures by polling `.poll()` until complete.
- **vs Go goroutines**: Go uses OS threads + M:N scheduler; Rust async is cooperative, single-threaded by default (unless using multi-threaded runtime).

## R10 — Unsafe
- **Three things**: Dereference raw pointers, call unsafe functions, access mutable statics.
- **Also**: Implement unsafe traits, manipulate union fields.
- **Justified**: FFI, low-level optimizations, implementing safe abstractions.

## R11 — Pattern Matching
- **`match`**: Exhaustive pattern matching on expressions.
- **`if let`**: Non-exhaustive, matches one pattern, ignores rest.
- **Compiler enforces exhaustiveness**: Must handle all variants or use `_` wildcard.

## R12 — Vec vs Array
- **`[T; N]`**: Stack-allocated, fixed size, known at compile time.
- **`Vec<T>`**: Heap-allocated, growable.
- **Growth**: Allocates new capacity (typically 2x), moves elements, drops old allocation.

## R13 — Enums
- Rust enums are algebraic data types (can hold data).
- **vs C/Java**: C enums are integers; Java enums are singletons.
- **`Option<T>`**: `enum Option<T> { Some(T), None }`
- **No null**: `Option<T>` forces explicit handling of absence.

## R14 — impl Block
- **`&self`**: Immutable borrow, read-only methods.
- **`&mut self`**: Mutable borrow, can modify self.
- **`self`**: Takes ownership, consumes self (e.g., `into()` methods).
- **Associated functions**: `Self::new()` — don't take self, like static methods.

## R15 — Derive Macro
- **`#[derive(Debug, Clone)]`** generates trait implementations.
- **Common**: `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `PartialOrd`, `Ord`, `Hash`, `Serialize`, `Deserialize`.
- **Cannot derive**: If type contains non-derivable fields (e.g., raw pointers, certain FFI types).

## R16 — Cow (Clone on Write)
- **`Cow<'a, T>`**: Borrowed (`&'a T`) or owned (`T`) data.
- **Useful** when data might need mutation: borrow if unchanged, clone only if mutated.
```rust
fn process(data: Cow<str>) -> String {
    if needs_change {
        let mut s = data.into_owned();
        s.make_ascii_uppercase();
        s
    } else {
        data.into_owned()
    }
}
```

## R17 — Module System
- **`mod`**: Declares module.
- **`use`**: Imports items into scope.
- **`pub`**: Makes item visible outside module.
- **File mapping**: `mod foo;` → `foo.rs` or `foo/mod.rs`; `mod foo { }` inline.
- **2018 edition**: `mod foo;` can use `foo.rs` directly (no `mod.rs` required).

## R18 — Pin<T>
- **`Pin<T>`**: Ensures value won't be moved after pinning.
- **Needed** for self-referential structs (pointers to self's fields).
- **Async**: Futures may contain self-references; must be pinned before polling.
- **`Unpin`**: Type that can be moved freely (most types are `Unpin`).

## R19 — Macros
- **Declarative (`macro_rules!`)**: Pattern-based text transformation, hygienic.
- **Procedural**: Rust functions that generate code (`derive`, `attribute`, `function-like`).
- **Hygiene**: Macros don't accidentally capture variables from caller scope.

## R20 — Zero-Cost Abstractions
- **Iterators**: Inlined loops, no allocation overhead.
- **Generics**: Monomorphization — separate code generated per type, no vtable indirection.
- **Trait static dispatch**: Methods inlined at call site.
- **Result**: High-level code compiles to same machine code as hand-written C.
