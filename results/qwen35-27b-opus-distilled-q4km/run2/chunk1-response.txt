# Networking Answers

## N1 — Layer 2 vs Layer 3 Switch

| Layer 2 Switch | Layer 3 Switch |
|----------------|----------------|
| Operates at Layer 2 (Data Link) | Operates at Layers 2 & 3 (Data Link + Network) |
| Forwards based on MAC address | Routes based on IP + forwards on MAC |
| Uses MAC address table | Uses MAC table + routing table |
| No routing capabilities | Can route between VLANs/subnets |
| Cheaper, simpler | More expensive, feature-rich |

## N2 — Network and Broadcast Address Calculation

**IP: 10.0.5.37/20**

```
/20 = 255.255.240.0
Network bits: 20, Host bits: 12

10.0.5.37   = 00001010.00000000.00000101.00100101
Mask /20    = 11111111.11111111.11110000.00000000
AND result  = 00001010.00000000.00000000.00000000 = 10.0.0.0
```

- **Network address:** 10.0.0.0
- **Broadcast address:** 10.0.15.255
- **Host range:** 10.0.0.1 – 10.0.15.254

## N3 — TCP Three-Way Handshake

```
Client                          Server
  |                               |
  |-------- SYN (seq=x) ---------->|
  |                               |
  |<------- SYN-ACK (seq=y, ack=x+1)-----|
  |                               |
  |-------- ACK (ack=y+1) -------->|
  |                               |
  |<------- Connection Established ------|
```

**If final ACK is lost:** The server considers the connection established (it received the SYN and sent SYN-ACK). The client retransmits the ACK. The server simply acknowledges data in its next segment. No connection failure occurs.

## N4 — SNAT vs DNAT

| SNAT (Source NAT) | DNAT (Destination NAT) |
|-------------------|------------------------|
| Changes source IP | Changes destination IP |
| Outbound traffic | Inbound traffic |
| Hides internal clients | Exposes internal servers |

**Examples:**
- **SNAT:** Internal host 10.0.0.5 accesses internet → source changed to gateway's public IP 203.0.113.1
- **DNAT:** External request to 203.0.113.1:80 → destination changed to internal web server 10.0.0.10:80

## N5 — SSL Certificate Subject Name Mismatch Causes

1. **Wrong hostname in URL** (e.g., accessing `http://example.com` when cert is for `www.example.com`)
2. **Certificate issued for different domain** (wrong domain during CSR creation)
3. **Missing SAN (Subject Alternative Name)** entry for the accessed hostname

## N6 — VLAN vs VxLAN

| VLAN | VxLAN |
|------|-------|
| 802.1Q tagging | MAC-in-UDP encapsulation |
| 12-bit VID (4096 VLANs) | 24-bit VNI (16M segments) |
| Layer 2 only | Layer 2 over Layer 3 |
| Broadcast domain limited to switch | Can span data centers |

**Choose VxLAN when:** Multi-tenant cloud environments, need >4096 segments, overlay networks across physical infrastructure.

## N7 — Policy-Based Routing Fix

**Problem:** Traffic from eth1's subnet uses default route via eth0 (asymmetric routing).

**Solution:**
```bash
# Create custom routing table
echo "200 eth1_table" >> /etc/iproute2/rt_tables

# Add route for eth1's subnet
ip route add 192.168.1.0/24 dev eth1 src 192.168.1.5 table eth1_table

# Add policy rule: traffic FROM eth1 uses eth1_table
ip rule add from 192.168.1.0/24 table eth1_table

# Verify
ip rule show
ip route show table eth1_table
```

## N8 — BGP Path Selection (in order)

1. Highest **LOCAL_PREF**
2. Shortest **AS_PATH**
3. Lowest **ORIGIN** type (IGP < EGP < INCOMPLETE)
4. Lowest **MED** (Multi-Exit Discriminator)
5. **eBGP** over iBGP paths
6. Lowest **IGP metric** to next-hop
7. Oldest path (for eBGP)
8. Lowest **Router ID**
9. Lowest **cluster-list** length
10. Lowest **peer address**

## N9 — MTU Math: VxLAN over IPsec

```
Physical MTU: 1500 bytes
- IP header: 20 bytes
- ESP header: 20-36 bytes (use 36 for worst case)
- ESP trailer: 4 bytes
- ESP auth: 12 bytes
= IPsec overhead: 72 bytes

Remaining: 1500 - 72 = 1428 bytes

- Outer IP: 20 bytes
- Outer UDP: 8 bytes
- VxLAN header: 8 bytes
= VxLAN overhead: 36 bytes

Remaining: 1428 - 36 = 1392 bytes

- Inner Ethernet: 14 bytes
- Inner IP: 20 bytes
- Inner TCP: 20 bytes
= Inner headers: 54 bytes

Maximum inner payload: 1392 - 54 = 1338 bytes
```

## N10 — ARP and Gratuitous ARP

**ARP (Address Resolution Protocol):** Resolves IPv4 addresses to MAC addresses on a local network.

**Gratuitous ARP solves:**
- Duplicate IP detection (if someone responds, IP is taken)
- Updating switch MAC tables after NIC replacement
- Failover notification in HA setups

## N11 — Public vs Private IP Addresses

| Public IP | Private IP |
|-----------|------------|
| Routable on internet | Not routable on internet |
| Unique globally | Reused across networks |
| Assigned by ISP/RIR | Assigned internally |

**RFC 1918 Private Ranges:**
- 10.0.0.0 – 10.255.255.255 (10.0.0.0/8)
- 172.16.0.0 – 172.31.255.255 (172.16.0.0/12)
- 192.168.0.0 – 192.168.255.255 (192.168.0.0/16)

## N13 — DHCP DORA Process

1. **Discover:** Client broadcasts DHCPDISCOVER (0.0.0.0 → 255.255.255.255)
2. **Offer:** Server responds with DHCPOFFER (proposed IP)
3. **Request:** Client broadcasts DHCPREQUEST (accepting offer)
4. **Acknowledge:** Server sends DHCPACK (lease confirmed)

## N14 — Hub vs Switch vs Router

| Device | OSI Layer | Function |
|--------|-----------|----------|
| Hub | Layer 1 | Broadcasts to all ports (shared collision domain) |
| Switch | Layer 2 | Forwards based on MAC address (separate collision domains) |
| Router | Layer 3 | Routes between networks based on IP |

## N15 — Half-Duplex vs Full-Duplex

| Half-Duplex | Full-Duplex |
|-------------|-------------|
| Send OR receive at once | Send AND receive simultaneously |
| CSMA/CD required | No collisions possible |
| 50% bandwidth efficiency | 100% bandwidth efficiency |

**Modern Ethernet:** Full-duplex (since 100BASE-TX, universally in switched networks)

## N16 — TTL and Traceroute

**TTL (Time To Live):** Prevents packets from circulating forever. Decremented by 1 at each hop; packet dropped when TTL=0.

**Traceroute exploits this:**
1. Sends packet with TTL=1 → first hop drops it, returns ICMP Time Exceeded
2. Sends packet with TTL=2 → second hop drops it, returns ICMP
3. Continues until destination responds

## N17 — NAT Gateway Types

| Type | Description | Use Case |
|------|-------------|----------|
| Static NAT | 1:1 fixed mapping | Exposing specific server |
| Dynamic NAT | Pool of public IPs | Multiple internal hosts |
| PAT (NAPT) | Many:1 with port translation | Most common (home routers) |

## N18 — ECMP Routing

**How it works:** Multiple equal-cost paths to destination. Packets distributed across paths using hash.

**Hashing strategies:**
- 5-tuple hash (src IP, dst IP, src port, dst port, protocol)
- 2-tuple hash (src IP, dst IP)
- XOR-based hashing

**Problem with stateful firewalls:** Asymmetric flows (request via path A, response via path B) cause firewall to drop return traffic (no session state).

**Solution:** Use flow-based hashing ensuring bidirectional traffic uses same path.

## N19 — TCP Window Scaling Problem

**Problem:** Bandwidth-Delay Product (BDP) = 10MB, but TCP window = 64KB. This means only 64KB can be "in flight" before waiting for ACK.

Throughput limited to: 64KB / RTT

With RTT of 100ms: Max throughput = 64KB / 0.1s = 640KB/s (far below available bandwidth)

**TCP Window Scaling (RFC 1323):** Adds a scale factor (shift count 0-14) to the window field. Allows effective window up to 1GB (65535 × 2^14).

**Solution:** Enable with `tcp_window_scaling=1` (default in modern kernels).

## N20 — 802.1Q Trunk Configuration

**Frame format on wire:**
```
| Dest MAC (6) | Src MAC (6) | 802.1Q Tag (4) | EtherType (2) | Payload | FCS (4) |
                                    ↑
                            Priority(3)+VID(12)+DE(1)
```

**Linux configuration:**
```bash
# Create VLAN sub-interfaces
ip link add link eth0 name eth0.10 type vlan id 10
ip link add link eth0 name eth0.20 type vlan id 20
ip link add link eth0 name eth0.30 type vlan id 30

# Assign IPs
ip addr add 10.0.10.5/24 dev eth0.10
ip addr add 10.0.20.5/24 dev eth0.20
ip addr add 10.0.30.5/24 dev eth0.30

# Bring up interfaces
ip link set eth0.10 up
ip link set eth0.20 up
ip link set eth0.30 up
```

# Linux Answers

## L1 — Hard Link vs Symbolic Link

| Hard Link | Symbolic Link |
|-----------|---------------|
| Points to inode directly | Points to filename/path |
| Cannot cross filesystems | Can cross filesystems |
| Cannot link directories | Can link directories |
| No separate disk entry | Separate inode, stores path |
| Original and link indistinguishable | Broken if target deleted |

find /var/log -type f -size +100M
```

Or with human-readable sizes:

find /var/log -type f -size +100M -exec ls -lh {} \;
```

## L3 — State D (Uninterruptible Sleep)

**Meaning:** Process waiting for I/O (disk, network). Cannot be interrupted because it's in kernel space waiting for hardware.

**Can you kill it with kill -9?** No. SIGKILL cannot interrupt state D. The process will only respond when I/O completes. If stuck indefinitely, usually indicates:
- Hardware failure
- NFS server unreachable
- Kernel bug

## L4 — cgroups v1 vs v2

| cgroups v1 | cgroups v2 |
|------------|------------|
| Hierarchies per subsystem | Single unified hierarchy |
| Controllers in separate trees | All controllers in one tree |
| File-based config | File-based, cleaner design |
| Legacy | Modern, recommended |

**systemd prefers v2 because:** Unified hierarchy simplifies management, better integration with systemd slices, more consistent behavior.

## L5 — nftables vs iptables

| nftables | iptables |
|----------|----------|
| Unified framework (replaces iptables, ip6tables, arptables) | Separate tables for IPv4/IPv6/ARP |
| More efficient kernel data structures | Legacy, less efficient |
| Better syntax, supports sets/maps | More verbose |
| Native support for NAT, routing | Requires extensions |

**Kernel handling:** Both can coexist. nftables uses nf_tables kernel module; iptables uses netfilter hooks. nftables is more efficient but iptables remains for compatibility.

## L6 — df Shows 100% but du Shows Less

**Most likely cause:** Deleted files still held open by processes.

When a file is deleted but a process has it open, space isn't freed until the file descriptor is closed.

**Verify:**
```bash
lsof +L1 /var/log    # Lists files with link count < 1
lsof | grep deleted  # Shows deleted but open files
```

## L7 — Linux Boot Process

```
1. UEFI Firmware
   ├─ POST, initialize hardware
   ├─ Load boot manager from EFI System Partition
   └─ Execute bootloader (GRUB)

2. Bootloader (GRUB)
   ├─ Display menu
   ├─ Load kernel image (vmlinuz)
   ├─ Load initramfs
   └─ Pass kernel parameters, jump to kernel

3. Kernel
   ├─ Initialize CPU, memory, devices
   ├─ Mount initramfs as root
   ├─ Execute /init from initramfs

4. Initramfs
   ├─ Load essential drivers
   ├─ Assemble LVM/RAID if needed
   ├─ Mount real root filesystem
   ├─ Execute pivot_root
   └─ Start real init (systemd)

5. systemd
   ├─ Read /etc/systemd/system.conf
   ├─ Start target (default.target → multi-user.target)
   ├─ Start services (network, sshd, etc.)
   └─ Present login prompt
```

## L8 — OOM Killer with High Buff/Cache

**Why available is low:** The 15GB buff/cache is reclaimable but not immediately available. When applications need memory:
- Page cache can be dropped quickly
- Buffers require more work to reclaim
- Kernel's "available" calculation is conservative

The OOM killer fires because:
- Applications request memory faster than cache can be reclaimed
- Memory pressure causes kernel to consider cache as "committed"
- Swap is nearly exhausted (only 1GB)

**Kernel tunables:**
```bash
vm.swappiness=10           # Lower = prefer RAM over swap
vm.vfs_cache_pressure=50  # Higher = reclaim cache more aggressively
vm.overcommit_ratio=50    # Memory overcommit percentage
```

## L9 — ip netns and Containers

`ip netns` creates isolated network namespaces with:
- Separate routing tables
- Separate network devices
- Separate firewall rules
- Separate port spaces

**Container runtimes use it to:**
- Create network namespace per container
- Connect via veth pairs to bridge
- Assign IP from bridge's subnet
- Provide network isolation between containers

## L16 — LVM Architecture

```
Physical Disks
     ↓
Physical Volumes (pvcreate)
     ↓
Volume Group (vgcreate)
     ↓
Logical Volumes (lvcreate)
     ↓
Filesystem (mkfs)
```

**Extend logical volume:**
```bash
# Add new disk as PV
pvcreate /dev/sdb

# Extend VG
vgextend myvg /dev/sdb

# Extend LV
lvextend -L +10G /dev/myvg/mylv

# Resize filesystem
resize2fs /dev/myvg/mylv    # ext4
xfs_growfs /mount/point     # xfs
```

## L17 — I/O Schedulers

| Scheduler | Best For | Characteristics |
|-----------|----------|-----------------|
| mq-deadline | SSDs, databases | Deadline-based, low latency |
| bfq | HDDs, desktops | Fair queuing, good for mixed workloads |

## L18 — High Load, Low CPU Diagnosis

**Load average measures:** Processes in R (running) + D (uninterruptible sleep) states.

**I/O wait inflates load** because blocked processes count toward load average.

**Diagnosis:**
```bash
# Check process states
ps aux | awk '{print $8}' | sort | uniq -c

# Check I/O wait
iostat -x 1

# Check disk utilization
iostat -d 1

# Check network
iftop -n

# Check for D-state processes
ps -eo stat,pid,cmd | grep '^D'
```

## L19 — SELinux Modes and Troubleshooting

| Mode | Behavior |
|------|----------|
| Enforcing | Deny + log violations |
| Permissive | Allow + log violations |
| Disabled | No enforcement, no logging |

**Troubleshoot port binding:**
```bash
# Check current mode
getenforce

# Check denials
ausearch -m avc -ts recent | grep denied

# Check allowed ports for service
semanage port -l | grep http_port_t

# Add port to allowed list
semanage port -a -t http_port_t -p tcp 8080

# Or temporarily set permissive for debugging
setenforce 0
```

## L20 — Page Faults and THP

**Page fault types:**
- **Minor page fault:** Page in memory, just needs TLB update
- **Major page fault:** Page on disk, must be read into memory

**THP (Transparent Huge Pages):** Uses 2MB pages instead of 4KB.

**Benefits:** Fewer TLB entries, better performance for memory-intensive apps.

**Problems:** Memory fragmentation, latency spikes during allocation.

**When to disable:**
- Databases (MySQL, PostgreSQL)
- Real-time applications
- Systems with memory pressure

**Disable:**
```bash
echo never > /sys/kernel/mm/transparent_hugepage/enabled
```
