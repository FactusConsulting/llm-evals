## .NET / C#

**DN1** — A `class` is a reference type (heap-allocated, GC-managed, supports inheritance, nullable). A `struct` is a value type (stack-allocated by default, copied on assignment, no inheritance, sealed). Use a `struct` for small, immutable, data-centric types (e.g., `Point`, `KeyValuePair`) where value semantics and performance (avoiding allocation) matter.

**DN2** — `IEnumerable<T>` represents an in-memory sequence; LINQ methods (`Where`, `Select`) execute client-side. `IQueryable<T>` represents a query over an external source (e.g., SQL database); it stores an expression tree that is translated to the source's query language (e.g., SQL) and executed server-side. This matters because `IQueryable` allows filtering/ordering to happen in the database (reducing data transfer), while `IEnumerable` fetches all data and filters in memory.

**DN3** — `async/await` compiles into a state machine that returns a `Task` (or `ValueTask`). `Task` is heap-allocated; `ValueTask` is a value type that avoids allocation when the operation often completes synchronously or is used in hot paths. Use `ValueTask` for high-performance async methods that may complete synchronously, but only when the consumer awaits once (not multiple times) and you don't need to cache the result.

**DN4** — Dependency injection (DI) is a pattern where the container supplies dependencies. Lifetimes: **Transient** (new instance per resolution), **Scoped** (one instance per scope/request), **Singleton** (one instance for the app). A common bug: injecting a Scoped service (e.g., `DbContext`) into a Singleton captures that scoped instance for the app's lifetime, causing concurrency issues, stale data, and `ObjectDisposedException`. Fix: use `IServiceScopeFactory` to create a scope inside the Singleton, or change the consumer's lifetime.

**DN5** — `string` is immutable, UTF-16, heap-allocated, and supports storage. `ReadOnlySpan<char>` is a stack/ref struct that provides allocation-free slicing and processing of strings (or other memory). Use `Span<T>`/`ReadOnlySpan<T>` for performance-critical parsing or substring operations to avoid allocations. Spans cannot be stored in fields, used in async methods, or boxed.

**DN6** — The .NET GC is a generational, non-deterministic collector. **Gen 0** holds short-lived objects, **Gen 1** is a bridge for objects that survive one collection, **Gen 2** holds long-lived objects. The **Large Object Heap (LOH)** stores objects ≥85 KB; it is not compacted by default. `IDisposable` is needed for unmanaged resources (files, sockets, handles) because the GC only tracks managed memory; you must deterministically release unmanaged resources via `Dispose()`.

**DN7** — `ConfigureAwait(false)` tells the continuation not to capture the current `SynchronizationContext`, so it runs on the thread pool. Default behavior captures the context to resume on the original thread (e.g., UI thread). Use `ConfigureAwait(false)` in library code to avoid deadlocks when blocking on async code; do **not** use it in UI code where you need to update the UI thread. In ASP.NET Core (no sync context), it is unnecessary. It relates to `SynchronizationContext` by controlling where the continuation is posted.

**DN8** — .NET 8/9 features:
- **Primary constructors**: `public class MyService(ILogger<MyService> logger) { ... }` — parameters are injected by DI.
- **Collection expressions**: `List<int> list = [1, 2, 3];` or `int[] arr = [1, 2, 3];`
- **FrozenDictionary**: immutable, optimized for read-heavy access, created via `.ToFrozenDictionary()`.
Example with DI:
```csharp
public class MyService(ILogger<MyService> logger, IConfiguration config)
{
    public void DoWork() => logger.LogInformation(config["Key"]);
}
```

**DN9** — Under high concurrency, `ObjectDisposedException` on `DbContext` usually means the `DbContext` is registered as a Singleton or injected into a Singleton, causing it to be shared across threads and disposed after the first request. EF Core's `DbContext` is **scoped** by default and is not thread-safe. Fix: register it with `AddDbContext` (Scoped), ensure it is not captured in Singletons, and avoid manual disposal. Scoped lifetime matches a request, so each request gets a fresh context.

**DN10** — A `record` is a reference type with value equality, positional syntax, `with` expressions, and built-in cloning. A `class` uses reference equality and is for behavior/identity. A `record struct` is a value type with value equality (can be mutable). Choose `record` for immutable DTOs/data models; `class` for entities with identity or behavior; `record struct` for small, value-semantic data.

**DN11** — `ref` requires the variable to be assigned before passing; allows read/write. `out` requires assignment before return; only write. `in` is a read-only reference (cannot modify). Use `ref` for large structs to avoid copying, `out` for multiple return values, `in` for read-only access to large structs.

**DN12** — Nullable reference types (`string?`) are compile-time annotations enabled with `#nullable enable`; they don't change runtime behavior, only static analysis warnings. Nullable value types (`int?`) are actual `Nullable<T>` structs that can be `null`. Reference types are non-nullable by default under nullable context; value types are always nullable only if declared with `?`.

**DN13** — LINQ (Language Integrated Query) provides querying over collections. Method syntax uses extension methods (`list.Where(x => ...)`); query syntax is declarative (`from x in list where ... select x`) and is translated to method calls. Deferred execution means the query is not executed until enumerated; this allows composition and avoids re-execution only if you materialize once (each enumeration re-runs).

**DN14** — Generic constraints restrict type arguments:
- `where T : class` — reference type.
- `where T : struct` — value type.
- `where T : new()` — parameterless constructor.
- `where T : IComparable<T>` — implements interface.
Combine multiple: `where T : class, IComparable<T>, new()`. Use constraints to enable operations (e.g., `CompareTo`) and ensure type safety.

**DN15** — An `abstract class` can have implementation, fields, constructors, and is single-inheritance. An `interface` is a contract with no state (until C# 8 default methods) and supports multiple inheritance. Default interface methods (C# 8+) allow interfaces to provide implementation, but they still cannot have instance fields. The distinction blurs, but use abstract classes for shared base logic and interfaces for capabilities.

**DN16** — The middleware pipeline is a series of delegates that handle HTTP requests. `app.Use()` adds middleware that can call the next delegate; `app.Run()` is terminal (does not call next); `app.Map()` branches based on path. Ordering matters: exception handling, logging, static files should be early. Exception middleware catches exceptions from downstream, can log/rethrow or handle, and must be placed before other middleware to catch their exceptions.

**DN17** — `Channel<T>` is a modern, async, thread-safe producer-consumer queue with bounded/unbounded options and backpressure. `BlockingCollection<T>` is synchronous, blocking, and older. Bounded channel example:
```csharp
var channel = Channel.CreateBounded<int>(10);
await channel.Writer.WriteAsync(item);
await foreach (var item in channel.Reader.ReadAllAsync()) { ... }
```
Use bounded channels to limit memory and apply backpressure.

**DN18** — Source Generators run at compile time, analyze source code, and generate additional code. They are faster than reflection (no runtime overhead) and more maintainable than IL weaving. An **incremental generator** uses incremental compilation, caches results, and only re-runs on changes, making it more efficient than the older `ISourceGenerator`.

**DN19** — TPL Dataflow provides actor-like blocks: `ActionBlock` (executes a delegate per item), `TransformBlock` (transforms each item), `BufferBlock` (buffers items). It supports async, cancellation, and complex pipelines. `System.Threading.Channels` is simpler and lower-level, ideal for producer-consumer; Dataflow is better for branching, joining, and multi-step pipelines with built-in backpressure.

**DN20** — Minimal APIs use top-level statements and lambda handlers, reducing boilerplate. Controller-based APIs use classes with attributes and MVC. Trade-offs: Minimal APIs are faster to write and have lower overhead, but controllers offer more structure and easier mocking for tests. Minimal APIs support OpenAPI via `AddEndpointsApiExplorer`, route groups (`MapGroup`) for shared prefixes, and endpoint filters (`AddFilter`) for cross-cutting logic.

## Python

**P1** — A `list` is mutable and ordered; a `tuple` is immutable (though it can contain mutable objects). A `set` is mutable, unordered, and unhashable; a `frozenset` is immutable and hashable (usable as dict key).

**P2** — The GIL is a mutex in CPython that serializes bytecode execution, preventing multiple threads from running Python code simultaneously. It affects CPU-bound threads (no parallelism) but not I/O-bound threads (they release the GIL). Workarounds: use `multiprocessing` for CPU-bound tasks, use C extensions, use `asyncio` for I/O, or use alternative interpreters (Jython, IronPython).

**P3** — `copy.copy` creates a shallow copy (new object, nested objects shared); `copy.deepcopy` recursively copies all objects. Example: 
```python
a = [[1], [2]]
b = copy.copy(a)
b[0].append(3)  # a[0] also becomes [1, 3]
```
Shallow copy causes unexpected behavior when mutating nested mutable objects.

**P4** — Decorators are functions that wrap another function. Example:
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.4f}s")
        return result
    return wrapper

@timer
def foo(): ...
```

**P5** — Generators use `yield` to produce values lazily, one at a time, preserving memory. Returning a list builds the entire sequence in memory. `yield from` delegates to another iterable/generator, e.g., `yield from other_gen()`.

**P6** — `asyncio.run()` creates a new event loop, runs a coroutine, and closes it. `asyncio.gather()` schedules multiple coroutines and waits for all results. `asyncio.create_task()` schedules a coroutine as a task and returns immediately. `time.sleep()` blocks the event loop; use `await asyncio.sleep()` to yield control.

**P7** — Python 3 uses the **C3 linearization** algorithm for MRO. For diamond inheritance `D(B, C)` where `B` and `C` inherit `A`, MRO is `D -> B -> C -> A -> object`. `D().who()` returns `"C"` because `C` overrides `who()` and appears before `A` in the MRO (B doesn't override).

**P8** — A metaclass is a class that creates classes; it controls class creation (e.g., registering classes, modifying attributes). `__init_subclass__` is a hook called when a subclass is created, simpler for validation/registration. Use a metaclass for complex class customization (e.g., altering class dict before creation); use `__init_subclass__` for simple subclass hooks.

**P9** — `multiprocessing` uses separate processes (bypasses GIL, CPU-bound), `threading` uses threads (GIL, I/O-bound), `concurrent.futures` provides high-level thread/process pools. Use multiprocessing for CPU-heavy tasks, threading for I/O-bound, and concurrent.futures for simple parallelism. Multiprocessing requires pickling arguments/return values; not all objects are picklable (e.g., lambdas, some locks).

**P10** — `__slots__` is a class attribute that prevents `__dict__`, saving memory and speeding attribute access. It prevents adding new attributes. Use it for classes with many instances and fixed attributes (e.g., data records).

**P11** — A virtual environment isolates Python dependencies per project. `venv` is built-in; `virtualenv` is third-party with more features; `conda` manages environments and packages, works across languages. Use one to avoid dependency conflicts.

**P12** — Comprehensions: list `[expr for x in iterable if cond]`, dict `{k: v for ...}`, set `{expr for ...}`. `map()`/`filter()` are functional and require lambdas; comprehensions are more readable and Pythonic. Prefer comprehensions for clarity; use `map`/`filter` when you already have a function.

**P13** — `==` checks value equality; `is` checks identity (same object). Object interning caches small integers (-5 to 256) and some strings, so `a is b` can be `True` for those values. For other objects, `is` is `False` unless same reference.

**P14** — `*args` collects extra positional arguments as a tuple; `**kwargs` collects extra keyword arguments as a dict. Positional-only parameters are before `/`; keyword-only parameters are after `*`. Example: `def f(a, /, b, *, c):` — `a` positional-only, `b` positional or keyword, `c` keyword-only.

**P15** — Context managers use `with` to ensure cleanup. Implement with `__enter__`/`__exit__` or `@contextmanager` from `contextlib`. Example beyond files: timing:
```python
from contextlib import contextmanager
@contextmanager
def timer():
    start = time.time()
    yield
    print(f"Elapsed: {time.time()-start}")
```

**P16** — Type hinting annotates function signatures. `typing.Union` (or `X | Y`), `Optional` (`Union[T, None]`), `Literal` (specific values), `TypeVar` (generic), `Protocol` (structural typing). Mypy/pyright use these to statically check types, catch errors, and infer types.

**P17** — Dunder methods define behavior. `__repr__` is unambiguous for debugging; `__str__` is readable for `print()`. `__eq__` defines equality; `__hash__` must be consistent (equal objects have equal hashes). Defining `__eq__` without `__hash__` sets `__hash__` to `None`, making instances unhashable. `__getattr__` is called when attribute is missing; `__getattribute__` is called for every attribute access.

**P18** — Descriptors implement `__get__`, `__set__`, `__delete__` to control attribute access. `property` is a descriptor that calls getter/setter methods. `classmethod` and `staticmethod` are descriptors that bind the method differently (class vs no self). Under the hood, they define `__get__` to return bound methods.

**P19** — The import system uses finders to locate modules and loaders to execute them. `sys.path` lists directories; `PYTHONPATH` adds extra paths. `__init__.py` marks a package; namespace packages (without `__init__.py`) allow splitting across directories. Relative imports use `.`/`..`; absolute imports use full module path. Finders/loaders are part of `importlib`.

**P20** — `dataclasses` generates `__init__`, `__repr__`, `__eq__`, etc. `attrs` offers more features (validation, converters) with less boilerplate. `Pydantic` provides runtime validation, parsing, and serialization based on type hints. `__post_init__` runs after `__init__`; `field(default_factory=...)` handles mutable defaults; `frozen=True` makes instances immutable. Dataclasses support inheritance. Choose Pydantic for API data validation; dataclasses for simple internal data structures.
