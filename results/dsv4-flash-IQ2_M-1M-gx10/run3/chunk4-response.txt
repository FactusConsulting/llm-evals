## Go (20 questions)

### G1 — Easy
**Slice vs Array**: Arrays have a fixed length determined at compile time (`[5]int`), while slices are dynamic views into an underlying array (`[]int`). Slices are more common and flexible. When appending to a slice at capacity, Go allocates a new larger backing array (typically doubling), copies existing elements, and returns a new slice header pointing to the new array. The original array is eligible for GC if no longer referenced.

### G2 — Easy
`var x int` declares `x` with zero value (0) and explicit type. `x := 0` uses type inference (int) and is shorthand for declaration + assignment. You **cannot** use `:=` at package level (outside functions) — only inside functions. Also cannot use `:=` when redeclaring with `var` in the same scope, or when the compiler cannot infer the type (e.g., `x := nil`).

### G3 — Medium
A **goroutine** is a lightweight thread managed by the Go runtime, starting with ~2KB stack (grows as needed) vs OS threads with ~1MB fixed stack. Thousands of goroutines can run on a few OS threads. The **GMP model**: G (goroutine), M (OS thread), P (processor/context). The scheduler uses a work-stealing algorithm: each P has a local run queue of goroutines, and M's pull from P's queue. When a goroutine blocks (I/O, channel), the M is released to run other goroutines. This multiplexing is cooperative (preemptive at function calls) and avoids the cost of OS thread context switching.

### G4 — Medium
**Channels** are typed communication pipes. **Unbuffered** channels block the sender until a receiver is ready, and block the receiver until a sender is ready (synchronous). **Buffered** channels have capacity; senders block only when the buffer is full, receivers block only when empty. Sending to a **full buffered channel** blocks the sender until space frees up (or a receiver consumes). Closing a channel signals no more sends; receivers get zero value after close.

### G5 — Medium
The **context package** carries deadlines, cancellation signals, and request-scoped values across API boundaries. It prevents goroutine leaks by propagating cancellation.

```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()

req, err := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
if err != nil { /* handle */ }
resp, err := http.DefaultClient.Do(req)
if err != nil { /* handle timeout/cancel */ }
```

### G6 — Medium
Go interfaces use **implicit satisfaction** (structural typing): a type satisfies an interface if it implements all methods, no explicit `implements` keyword. This differs from Java/C# where classes declare interface implementation. The **empty interface** `interface{}` (or `any` in Go 1.18+) accepts any type. It's powerful for generic containers (e.g., `fmt.Println`) but dangerous because it bypasses type safety — you must type-assert to use the value, risking runtime panics if wrong.

### G7 — Hard
This code is **unsafe** because there's no **happens-before** relationship between the goroutine's writes and the main goroutine's reads. Without synchronization, the compiler/CPU may reorder operations, and the main goroutine may see `ready=true` before `data="hello"` (or never see the writes). Correct alternatives:
1. **Channel**: `done := make(chan struct{}); go func() { data = "hello"; close(done) }(); <-done; fmt.Println(data)`
2. **Mutex**: protect both `data` and `ready` with `sync.Mutex`
3. **Atomic**: use `atomic.Bool` for `ready` with `atomic.LoadBool`/`StoreBool` (still need memory ordering for `data`)

### G8 — Hard
**sync.Mutex** provides exclusive access; **sync.RWMutex** allows multiple readers or one writer. RWMutex is better for read-heavy workloads (multiple readers don't block each other). **sync.Map** is optimized for read-heavy scenarios with distinct keys (e.g., cache), using atomic operations and sharded maps to reduce contention. A regular map + mutex is simpler and faster for write-heavy or single-key access. Trade-offs: sync.Map has higher overhead for writes and small maps; mutex has lower memory overhead but serializes all access.

### G9 — Hard
**Go modules** are the dependency management system. `go.mod` declares module path, Go version, and dependencies with versions. `go.sum` contains cryptographic checksums of module content for integrity verification. `go mod tidy` adds missing dependencies, removes unused ones, and updates `go.sum`. **MVS (Minimum Version Selection)**: for each dependency, selects the minimum version that satisfies all constraints from the module graph. This ensures reproducibility and avoids "dependency hell" — no version conflicts, just the minimum required.

### G10 — Medium
**defer** schedules a function call to run when the enclosing function returns. Multiple defers execute in **LIFO order** (last deferred runs first). Common gotcha: deferring in a loop accumulates calls until the function exits, not per iteration — e.g., closing files in a loop defers all closes until function return, potentially exhausting file descriptors. Fix: use an inner function or close explicitly.

### G11 — Easy
A **pointer** holds the memory address of a value. Zero value is `nil`. Create a pointer to a struct literal with `&StructName{...}` or `new(StructName)`. Example: `p := &Person{Name: "Alice"}`. Dereference with `*p` to access the value.

### G12 — Easy
**init()** runs automatically before `main()` (or package usage), after package-level variable initialization. A package can have **multiple init() functions** — they run in source file order (by file name) and within a file, in declaration order. They cannot be called explicitly. Used for setup: DB connections, config loading, etc.

### G13 — Easy
**make** creates initialized values for slices, maps, and channels (returns non-pointer). **new** allocates zeroed memory for any type and returns a pointer (`*T`). `make([]int, 5)` returns a slice ready to use; `new([]int)` returns a pointer to a nil slice (useless). Use `make` for the three built-in types, `new` for other types when you need a pointer to zero value.

### G14 — Easy
Go uses **explicit error returns**. The `error` interface has `Error() string`. Idiomatic pattern: `if err != nil { return err }` or handle. `errors.Is(err, target)` checks if err wraps target (for sentinel errors like `io.EOF`). `errors.As(err, &target)` finds a specific error type in the chain. `==` only works for direct comparison (no wrapping) and is fragile.

### G15 — Easy
- **map**: zero value is `nil` (read-only, write panics)
- **slice**: zero value is `nil` (len 0, append works)
- **channel**: zero value is `nil` (blocks forever on send/receive)
- **struct**: zero value is all fields zero-valued

### G16 — Medium
A **race condition** occurs when multiple goroutines access shared data without synchronization, and at least one writes. The `-race` flag instruments code to detect races at runtime (using happens-before analysis). Example:
```go
var counter int
for i := 0; i < 1000; i++ {
    go func() { counter++ }() // race!
}
```
Fix with mutex:
```go
var mu sync.Mutex
var counter int
for i := 0; i < 1000; i++ {
    go func() { mu.Lock(); counter++; mu.Unlock() }()
}
```
Or channel: use a channel to send increments to a single goroutine.

### G17 — Medium
**select** waits on multiple channel operations. It differs from `switch` in that it's for channels only and blocks until one case is ready. If **multiple cases are ready**, it picks one **randomly** (to prevent starvation). Timeout example:
```go
select {
case msg := <-ch:
    fmt.Println(msg)
case <-time.After(5 * time.Second):
    fmt.Println("timeout")
}
```

### G18 — Hard
**Escape analysis** determines whether a variable can be allocated on the stack or must go to the heap. The compiler analyzes whether a variable's address escapes the function scope (e.g., returned, stored in a global, passed to a function that stores it). If it escapes, it's heap-allocated. Inspect with `go build -gcflags=-m` (or `-m=2` for more detail). This matters because heap allocation incurs GC pressure and memory overhead; stack allocation is free (just stack pointer adjustment). Common escape causes: returning pointers, storing in interfaces, capturing in closures, passing to `fmt.Println` (interface).

### G19 — Hard
**reflect** provides runtime introspection. `reflect.Type` describes the type (kind, methods, fields), `reflect.Value` holds the actual value and allows reading/writing. Performance costs: reflection is slow (10-100x slower than static dispatch) due to runtime type checks, interface boxing, and lack of compiler optimization. Justified for: generic serialization (JSON), ORMs, testing frameworks, dependency injection. For performance-critical paths, prefer code generation (e.g., `go generate`) or generics (Go 1.18+) to avoid runtime reflection.

### G20 — Hard
**go:embed** embeds files into the compiled binary at compile time. Syntax:
```go
//go:embed file.txt
var content string

//go:embed images/*
var images embed.FS
```
Works with single files (string/[]byte), directories (embed.FS). Limitations: files must be in the module (no absolute paths, no `..`), cannot embed files with names starting with `_` or `.`, and the pattern must match at least one file. `embed.FS` implements `io/fs.FS`, so it works with `fs.ReadFile`, `http.FileServer`, etc. It's ideal for static assets, templates, and migration files.

## Rust (20 questions)

### R1 — Easy
**Ownership** rules:
1. Each value has a single owner (variable).
2. When the owner goes out of scope, the value is dropped (freed).
3. Ownership can be transferred (moved) to another variable; the original becomes invalid.

This ensures memory safety without garbage collection.

### R2 — Easy
**String** owns a heap-allocated UTF-8 buffer (mutable, growable). **&str** is a borrowed reference to a string slice (immutable, fixed length). Use `&str` for function parameters (accepts both `String` and `&str` via deref coercion), `String` when you need to own or modify the data. Example: `fn greet(name: &str)` accepts `greet("Bob")` and `greet(&my_string)`.

### R3 — Medium
**Borrowing** allows using a value without taking ownership. Rules:
- You can have **many shared references** (`&T`) simultaneously.
- You can have **one mutable reference** (`&mut T`) at a time.
- You **cannot** have a shared reference while a mutable reference exists (and vice versa).

The borrow checker enforces these at compile time, preventing data races and dangling references.

### R4 — Medium
**Result<T, E>** represents success (`Ok(T)`) or failure (`Err(E)`). **Option<T>** represents presence (`Some(T)`) or absence (`None`). The `?` operator:
- On `Ok`/`Some`: unwraps the value.
- On `Err`/`None`: returns early from the function with the error (or `None`).

```rust
use std::fs;
use std::io::Error;

fn read_file(path: &str) -> Result<String, Error> {
    let contents = fs::read_to_string(path)?; // returns early on error
    Ok(contents)
}
```

### R5 — Medium
- **Box<T>**: single owner, heap-allocated. Used for recursive types, large data, trait objects.
- **Rc<T>**: single-threaded shared ownership (clone increments refcount). Used for DAGs, graphs.
- **Arc<T>**: thread-safe shared ownership (atomic refcount). Used for concurrent sharing.

`Rc` is not `Send` (refcount not atomic), `Arc` is. `Box` is for exclusive ownership.

### R6 — Medium
**Traits** define shared behavior (like interfaces) but with more power: associated types, default methods, generics. Go interfaces are structural (implicit), Rust traits require explicit `impl`. **Trait objects** (`dyn Trait`) use dynamic dispatch (vtable) — like Go interfaces, but with `Box<dyn Trait>`. **Generics with trait bounds** (`T: Trait`) use static dispatch (monomorphization) — faster, no vtable, but larger binary. Prefer generics for performance, `dyn` for heterogeneous collections.

### R7 — Hard
The function fails because the compiler cannot determine how long the returned reference lives — it could be `x` or `y`, and the caller doesn't know which. Fix with explicit lifetime parameters:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```
This says both inputs and the output share the same lifetime `'a`, so the returned reference is valid as long as both inputs are.

### R8 — Hard
**Send**: type can be transferred across threads (ownership moved). **Sync**: type can be shared across threads (references). `Rc<T>` is not `Send` because its refcount uses non-atomic operations — concurrent increments would race. `Arc<T>` uses atomic refcount, making it `Send` + `Sync`. Most types are `Send`/`Sync` unless they contain raw pointers or non-atomic interior mutability (e.g., `RefCell` is `Send` but not `Sync`).

### R9 — Hard
**async/await** in Rust is **cooperative**: a `Future` is a state machine that yields control when it awaits. The **executor** (e.g., Tokio) polls futures and drives them to completion. Unlike Go's goroutines (preemptive, M:N scheduler), Rust futures are lazy — they only run when polled. This gives finer control (no runtime needed for embedded) but requires manual executor setup. Go's scheduler handles blocking automatically; Rust requires `async` functions to avoid blocking (use `tokio::io` instead of `std::io`).

### R10 — Medium
**unsafe** allows:
1. Dereference raw pointers (`*const T`, `*mut T`).
2. Call unsafe functions (FFI, `std::mem::transmute`).
3. Access/modify mutable static variables.
4. Implement unsafe traits (`Send`, `Sync`).

Justified for FFI, performance-critical low-level code, and when the compiler can't prove safety (e.g., custom allocators). It's not "dangerous" if used correctly — it just bypasses compiler checks.

### R11 — Easy
**Pattern matching** with `match` is exhaustive — the compiler forces you to handle all variants. `if let` is a shorthand for matching a single pattern (ignores others). Example:
```rust
match x {
    1 => println!("one"),
    _ => println!("other"),
}
if let Some(v) = opt { println!("{}", v); }
```
The compiler enforces exhaustiveness: you must cover all enum variants or use `_` wildcard.

### R12 — Easy
**Vec<T>** is a heap-allocated dynamic array (grows/shrinks). **[T; N]** is a fixed-size array on the stack (size known at compile time). When `Vec` exceeds capacity, it allocates a new larger buffer (typically 2x), copies elements, and deallocates the old one. This amortizes push cost to O(1) average.

### R13 — Easy
Rust **enums** are algebraic data types — variants can hold data (like tagged unions). C/Java enums are just named constants. Example:
```rust
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
}
```
**Option<T>** is `Some(T)` or `None`. Rust has **no null** — absence is explicit via `Option`. This eliminates null pointer errors at compile time.

### R14 — Easy
**impl** blocks define methods and associated functions. Methods:
- `&self`: immutable borrow (read-only).
- `&mut self`: mutable borrow (modify).
- `self`: takes ownership (consumes).

Associated functions (no `self`) are called with `Type::func()` (e.g., `String::new()`). They're like static methods in other languages.

### R15 — Easy
**derive** automatically implements traits. Common: `Debug` (formatting), `Clone` (deep copy), `PartialEq` (equality), `Serialize` (serde). You **cannot** derive if the trait requires manual logic (e.g., `Display` needs custom formatting), or if a field doesn't implement the trait (e.g., `Clone` on a type with `Rc` is fine, but `Copy` on a type with `String` is not).

### R16 — Medium
**Cow<'a, T>** (clone-on-write) is an enum: `Borrowed(&'a T)` or `Owned(T)`. It starts borrowed and only clones when you need mutation (`to_mut()`). Useful for read-heavy paths where most inputs are already owned or borrowed. Example:
```rust
fn process(input: &str) -> Cow<'_, str> {
    if input.starts_with("hello") {
        Cow::Borrowed(input) // no allocation
    } else {
        Cow::Owned(format!("hello {}", input)) // allocates
    }
}
```

### R17 — Medium
**Module system**: `mod` declares a module (inline or from file), `use` brings items into scope, `pub` makes items public. File mapping: `src/main.rs` is the crate root; `src/lib.rs` for library. Submodules: `src/foo.rs` for `mod foo;`, `src/foo/bar.rs` for `mod bar;` inside `foo`. **2018 edition** changes: `mod foo;` can find `foo.rs` or `foo/mod.rs` (previously only `mod.rs`), and `use` paths are more uniform (`crate::`, `self::`, `super::`).

### R18 — Hard
**Pin<T>** prevents moving a value after it's created. Needed for **self-referential structs** (a struct with a pointer to its own field) — moving would invalidate the pointer. In **async/await**, futures may contain self-referential state (e.g., borrowing a local across await points), so they must be pinned before polling. **Unpin** is a marker trait: types that are safe to move (most types). `Pin<Box<T>>` for heap-pinned, `Pin<&mut T>` for stack-pinned. You need `Pin` to poll a future.

### R19 — Hard
**Declarative macros** (`macro_rules!`) use pattern matching on tokens — like `match` for syntax. **Procedural macros** generate code from input tokens: derive (adds impls), attribute (e.g., `#[test]`), function-like (e.g., `vec![]`). **Hygiene**: declarative macros are hygienic — local variables don't collide with caller's scope. Procedural macros are less hygienic (can introduce names). Macros enable DSLs, reduce boilerplate, and can be more efficient than runtime code.

### R20 — Hard
**Zero-cost abstractions** mean high-level code compiles to the same machine code as hand-written low-level code. Examples:
- **Iterators**: `v.iter().map(|x| x*2).filter(|x| x>10).sum()` compiles to a tight loop with no allocation — the compiler inlines and optimizes away the abstraction.
- **Generics (monomorphization)**: `fn foo<T: Trait>(x: T)` generates a separate function per concrete type — no vtable, direct calls.
- **Static dispatch**: `T: Trait` is resolved at compile time, unlike `dyn Trait` (vtable). This achieves C-level performance while maintaining Rust's ergonomics and safety.
