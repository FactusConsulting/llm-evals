# JavaScript / TypeScript

## JS1 — Easy: var, let, const & hoisting

- **`var`**: Function-scoped, can be redeclared, hoisted and initialized as `undefined`.
- **`let`**: Block-scoped, cannot be redeclared, hoisted but in Temporal Dead Zone (TDZ) until declaration.
- **`const`**: Block-scoped, cannot be redeclared or reassigned (object properties still mutable), hoisted with TDZ.

**Hoisting**: The compiler moves declarations to the top of their scope. `var` is initialized with `undefined`; `let`/`const` are hoisted but uninitialized (TDZ), so accessing them before declaration throws `ReferenceError`.

## JS2 — Easy: Event loop

The event loop coordinates three structures:

- **Call stack**: LIFO stack for synchronous execution.
- **Microtask queue**: Promises, `queueMicrotask`, `MutationObserver` — drained completely before any macrotask.
- **Macrotask queue**: `setTimeout`, `setInterval`, I/O events, UI rendering.

**Flow**: Execute all synchronous code → drain entire microtask queue → take one macrotask → drain microtask queue → repeat. This guarantees microtasks run before the next macrotask.

## JS3 — Medium: Closures

A **closure** is a function that retains access to its lexical scope even when executed outside that scope.

```js
function makeCounter() {
  let count = 0;
  return () => ++count;
}
const c = makeCounter();
c(); // 1
```

**Classic for-loop closure bug**:
```js
for (var i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 100); // 5,5,5,5,5
}
```
Because `var` is function-scoped, all callbacks share the same `i` after the loop ends.

**Fix**: Use `let` (block-scoped) or an IIFE:
```js
for (let i = 0; i < 5; i++) {
  setTimeout(() => console.log(i), 100); // 0,1,2,3,4
}
```

## JS4 — Medium: Promises, async/await, error handling

- **Promises**: Objects representing eventual completion/failure. Use `.then()`/`.catch()`.
- **async/await**: Syntactic sugar over promises. `await` pauses until the promise settles.

**Error handling**:
- Promises: `.catch()` or `.then(null, rejection)`.
- async/await: `try/catch/finally`.

**`Promise.allSettled` vs `Promise.all`**:
- `Promise.all`: Fails fast — rejects on first rejection.
- `Promise.allSettled`: Waits for all — returns `[{status: 'fulfilled', value}, {status: 'rejected', reason}]`.

## JS5 — Medium: TypeScript interface vs type

**`interface`**: Can be extended/merged (declaration merging), describes object shapes, can be `implements`-ed by classes.

**`type`**: More flexible — unions, intersections, primitives, tuples, mapped types. Cannot be merged.

**When to use each**: Use `interface` for object shapes that may be extended; use `type` for unions, intersections, or complex types.

**Discriminated unions**: A union of types sharing a common discriminant (literal) property:
```ts
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number };
```

## JS6 — Medium: Prototypal inheritance

Every object has a `[[Prototype]]` (via `Object.getPrototypeOf()` or `__proto__`). Property lookup walks the chain.

**`Object.create()`**: Creates a new object with a specified prototype:
```js
const parent = { greet() { return 'hello'; } };
const child = Object.create(parent);
```

**ES6 classes**: Syntactic sugar over prototypes. `class`/`extends` uses the prototype chain; `super()` calls the parent constructor.

## JS7 — Hard: `this` keyword

**4 binding rules (priority order)**:
1. **New binding**: `new` creates a new object; `this` points to it.
2. **Explicit binding**: `call()`, `apply()`, `bind()`.
3. **Implicit binding**: `obj.method()` → `this` = obj.
4. **Default binding**: Global object (or `undefined` in strict mode).

**`bind()`**: Returns a new function with `this` permanently bound. It **cannot be re-bound** — even `call`/`apply`/`new` cannot override it.

## JS8 — Hard: WeakRef and FinalizationRegistry

- **`WeakRef`**: Holds a weak reference to an object — does not prevent GC. Access via `.deref()`, which may return `undefined` if collected.
- **`FinalizationRegistry`**: Registers callbacks to run when objects are garbage collected.

**Use cases**: Caching large objects, tracking resources, memory-sensitive apps.

**Why WeakMap keys must be objects**: WeakMap holds weak references to keys — only objects can be weakly referenced (primitives can't be individually GC'd). This allows keys to be collected when no other references exist.

## JS9 — Hard: V8 optimization

- **Hidden classes**: V8 creates internal class maps for objects with the same shape. Adding properties creates new hidden classes (transitions).
- **Inline caching**: Caches property access based on hidden class — speeds up repeated lookups.

**Deoptimization causes**:
- Adding/removing properties dynamically (changing shape).
- Polymorphic call sites (different hidden classes).
- Using `arguments` object.
- `try/catch` in hot functions.
- `eval` or `with`.
- Not using monomorphic call sites.

## JS10 — Medium: Tree-shaking

**Tree-shaking**: Removing unused code (dead code elimination) during bundling.

**ES modules**: Statically analyzable — imports/exports are known at compile time, enabling tree-shaking.

**CommonJS**: Dynamic — `require()` can be conditional, `module.exports` can be reassigned. Bundlers can't reliably determine what's used, so tree-shaking is ineffective.

## JS11 — Easy: null vs undefined

- `undefined`: Variable declared but not assigned.
- `null`: Explicitly assigned "no value".

`==` treats them as equal (`null == undefined` → `true`); `===` does not.

**Nullish coalescing (`??`)**: Returns right side if left is `null`/`undefined`:
```js
const x = value ?? defaultValue;
```

**Optional chaining (`?.`)**: Short-circuits if property is `null`/`undefined`:
```js
const name = user?.profile?.name;
```

## JS12 — Easy: map, filter, reduce, flatMap

- **`map()`**: Transform each element → new array.
- **`filter()`**: Keep elements passing predicate → new array.
- **`reduce()`**: Accumulate values → single result. Initial value optional (defaults to first element).
- **`flatMap()`**: Maps then flattens one level — useful for nested arrays.

```js
const doubled = [1,2,3].map(x => x * 2);
const evens = [1,2,3,4].filter(x => x % 2 === 0);
const sum = [1,2,3].reduce((acc, x) => acc + x, 0);
const flattened = [[1,2],[3,4]].flatMap(x => x); // [1,2,3,4]
```

## JS13 — Easy: Template literals & tagged templates

**Template literals**: Strings with `${}` interpolation, multi-line support.

**Tagged templates**: Function called with processed template parts:
```js
function escapeHTML(strings, ...values) {
  return strings.reduce((acc, str, i) =>
    acc + str + (i < values.length ? escape(values[i]) : ''), '');
}
const html = escapeHTML`<p>${userInput}</p>`;
```

## JS14 — Easy: Destructuring

```js
// Object
const { name, age = 25, alias: nickname } = person;
// Array
const [first, second, ...rest] = arr;
// Default values
const { a = 1 } = obj;
// Renaming
const { originalName: newName } = obj;
// Rest in destructuring
const { a, ...others } = obj;
```

## JS15 — Easy: for...in vs for...of

- **`for...in`**: Iterates over enumerable string keys (including inherited). Use for objects.
- **`for...of`**: Iterates over iterable values (arrays, strings, maps). Use for arrays.

Avoid `for...in` on arrays because it includes inherited properties and iterates keys as strings.

## JS16 — Medium: TypeScript generics

```ts
// Generic function
function identity<T>(arg: T): T { return arg; }

// Constraint
function logLength<T extends { length: number }>(arg: T): void {
  console.log(arg.length);
}

// Conditional type
type IsArray<T> = T extends any[] ? true : false;

// infer
type ElementType<T> = T extends (infer U)[] ? U : never;
```

## JS17 — Medium: Module systems

- **CommonJS**: `require()`/`module.exports` — synchronous, dynamic, traditional Node.js.
- **ES Modules**: `import`/`export` — static, asynchronous, standardized.

**Node.js handling**: Uses CJS by default; with `"type": "module"` in package.json, `.js` files are treated as ESM. `.mjs` forces ESM, `.cjs` forces CJS.

## JS18 — Hard: TypeScript structural typing

**Structural typing**: Types are compatible if their shapes match — not nominal.

**Excess property checks**: When assigning object literals to typed variables, extra properties cause errors. Only applies to fresh object literals, not variables.

**`extends` vs `satisfies`**:
- `extends`: Constrains generic types or type assertions.
- `satisfies` (TS 4.9): Checks type without changing inferred type.

**Variance (in/out)**:
- `in` (contravariant): Function parameters.
- `out` (covariant): Return types.
- TS 4.7+ allows explicit variance annotations.

## JS19 — Hard: Proxy and Reflect

**Proxy**: Wraps an object to intercept operations:
```js
const handler = {
  get(target, prop, receiver) {
    if (prop === 'secret') throw new Error('Access denied');
    return Reflect.get(target, prop, receiver);
  },
  set(target, prop, value) {
    console.log(`Setting ${prop}`);
    return Reflect.set(target, prop, value);
  }
};
const proxy = new Proxy(obj, handler);
```

**Reflect**: Provides methods for default proxy behavior — used inside handlers.

Use cases: Validation, logging, reactive data binding (Vue 3), access control.

## JS20 — Hard: SharedArrayBuffer and Atomics

**SharedArrayBuffer**: Shared memory between workers — no serialization needed.

**Atomics**: Provides atomic operations (`add`, `load`, `store`, `compareExchange`) on shared memory.

**Web Workers communication**: Workers share the same SharedArrayBuffer; Atomics ensures operations are atomic.

**Ordering guarantees**: Atomics operations are sequentially consistent — no data races.

**Atomics.wait/notify**:
- `Atomics.wait(buffer, index, value)`: Blocks thread until `buffer[index]` changes.
- `Atomics.notify(buffer, index, count)`: Wakes waiting threads.

# Bash

## B1 — Easy: $@ vs $*

- `$@`: Each positional parameter as separate word.
- `$*`: All positional parameters as single word (IFS-dependent).

**"$@" vs "$*"**:
- `"$@"`: Each parameter quoted separately — preserves spaces.
- `"$*"`: All parameters joined into single string with IFS.

## B2 — Easy: set -euo pipefail

- `-e`: Exit on error (non-zero exit status).
- `-u`: Error on unset variables.
- `-o pipefail`: Pipeline returns first non-zero exit status.

Together they make scripts fail fast on unexpected conditions.

## B3 — Medium: $(command) vs `command`

- `$(command)`: Modern command substitution — supports nesting, escaping.
- `` `command` ``: Legacy — harder to nest, escaping issues.

`$((expression))`: Arithmetic expansion — integer math.
`expr`: External command — slower, requires escaping.

## B4 — Medium: Process substitution

`<(command)`: Treats command output as a file descriptor.

```bash
diff <(sort file1) <(sort file2)
```

Useful when a command expects a file argument but you want to pipe output.

## B5 — Medium: Safe file iteration

```bash
find . -type f -print0 | while IFS= read -r -d '' file; do
  echo "$file"
done
```

**Why `for f in $(ls)` is dangerous**: Word-splitting on spaces, glob expansion, filenames with special characters break.

## B6 — Medium: Here document vs here string

**Here document**:
```bash
cat <<EOF
text
EOF
```

**Here string**:
```bash
cat <<< "text"
```

`<<-EOF`: Strips leading tabs (allows indentation).

## B7 — Hard: Redirection order

```bash
cmd > file 2>&1  # stdout to file, then stderr to same file (correct)
cmd 2>&1 > file  # stderr to current stdout, then stdout to file (stderr NOT redirected)
cmd &> file      # both to file (bash-specific)
```

Order matters: `2>&1` must come after `> file` to redirect stderr to the file.

## B8 — Hard: Lock file with cleanup

```bash
lock_dir="/tmp/mylock.$$"
while ! mkdir "$lock_dir" 2>/dev/null; do
  sleep 0.1
done
trap 'rmdir "$lock_dir"' EXIT INT TERM
# critical section
```

**Why mkdir over file**: `mkdir` is atomic — no race condition. File creation with `touch` + check has TOCTOU race.

## B9 — Easy: Quotes

- `'...'`: Literal — no expansion.
- `"..."`: Expansion — variables, command substitution, arithmetic.
- No quotes: Word-splitting, glob expansion.

```bash
var="hello world"
echo '$var'  # $var
echo "$var"  # hello world
echo $var    # hello world (but splits)
```

## B10 — Easy: File checks and test

```bash
[ -f file ]  # exists and is regular file
[ -d dir ]   # exists and is directory
[ -r file ]  # readable
```

**`[ ]` vs `[[ ]]`**: `[[ ]]` is bash-specific — supports `&&`, `||`, pattern matching, no word-splitting. `[ ]` is POSIX — more portable.

## B11 — Easy: Special variables

- `$?`: Exit status of last command.
- `$$`: PID of current shell.
- `$!`: PID of last background job.
- `$#`: Number of positional parameters.

## B12 — Easy: Functions

```bash
foo() { echo "Hello"; }
function foo { echo "Hello"; }  # equivalent
```

Return values: Use `echo` for output, `return` for exit status.

## B13 — Easy: PATH and command resolution

**PATH**: Colon-separated directories searched for executables.

**Builtin vs external**: Builtins are shell-internal (`cd`, `echo`); external are separate binaries (`ls`, `grep`).

Check with `type -t cmd` or `which cmd`.

## B14 — Medium: trap

```bash
trap 'cleanup' EXIT
trap 'echo "Interrupted"; exit 1' INT
trap 'echo "Terminated"; exit 1' TERM
```

**Execution order**: Traps run in order of signal arrival; EXIT trap runs on normal exit.

## B15 — Medium: xargs vs command substitution

```bash
find . -type f -print0 | xargs -0 -P 4 -I {} process_file {}
```

- `xargs -0`: Handles null-delimited input (safe for spaces/newlines).
- `xargs -P`: Parallel execution.
- Command substitution: Captures output as string — unsafe for filenames.

## B16 — Medium: Arrays

```bash
# Indexed
arr=(a b c)
arr+=(d)
echo "${arr[@]}"  # all
echo "${#arr[@]}" # length

# Associative
declare -A assoc
assoc[key]=value
echo "${assoc[@]}"
echo "${!assoc[@]}"  # keys
```

## B17 — Hard: Subshell vs group

- `(...)`: Subshell — variable changes don't propagate.
- `{ ...; }`: Group — runs in current shell, variables persist.

**Pipe into while loop**: The while runs in subshell (pipeline) — variable changes lost. Fix: use `while ... done < <(cmd)` (process substitution).

## B18 — Hard: Signals and job control

- **SIGINT**: Interrupt (Ctrl+C) — can be caught.
- **SIGTERM**: Termination — can be caught.
- **SIGHUP**: Hangup — can be caught.
- **SIGKILL**: Kill — cannot be caught.

Graceful shutdown: Trap SIGTERM, forward to background processes, wait for them.

## B19 — Hard: Parallel log processing

```bash
split -n 4 -d logfile part-
process_file() { ... }
export -f process_file
find . -name "part-*" -print0 | xargs -0 -P 4 -I {} bash -c 'process_file "$@"' _ {}
# Merge
cat part-*.out > merged.out
```

**Trade-offs**: Speed vs memory, error handling via exit codes, partial failures.

## B20 — Hard: exec and file descriptors

```bash
exec 3>file   # open fd 3 for writing
exec 3>&-     # close fd 3
```

**exec**: Replaces current shell process — no return. Used for fd manipulation, running final command.

**Coprocess**: `coproc { command; }` — bidirectional pipe to background process.

# PowerShell

## PS1 — Easy: Write-Output vs Write-Host

- **Write-Output**: Writes to output stream (pipeline) — objects flow downstream.
- **Write-Host**: Writes to console only — not in pipeline.

**Why it matters**: Write-Output feeds the pipeline; Write-Host bypasses it (though PS 5+ writes to information stream).

## PS2 — Easy: Pipeline and ForEach

**Pipeline**: Passes objects between commands — `|` operator.

**ForEach-Object vs foreach**:
- `ForEach-Object`: Pipeline cmdlet — processes one at a time, streams.
- `foreach`: Statement — loads all into memory first.

Use `ForEach-Object` for streaming/large data; `foreach` for small collections.

## PS3 — Medium: PSCustomObject vs hashtable

- **PSCustomObject**: Typed object with properties — for output.
- **hashtable**: Key-value dictionary — for internal data.

```powershell
$obj = [PSCustomObject]@{ Name = 'John'; Age = 30 }
$hash = @{ Name = 'John'; Age = 30 }
```

Convert: `[PSCustomObject]$hash` or `$obj.PSObject.Properties`.

## PS4 — Medium: Error handling

- **Terminating errors**: Stop execution — caught by try/catch.
- **Non-terminating errors**: Continue — handled by `-ErrorAction` or `$ErrorActionPreference`.

`-ErrorAction Stop` converts non-terminating to terminating. `$ErrorActionPreference` sets default.

## PS5 — Medium: Splatting

```powershell
$params = @{
  Path = 'C:\file.txt'
  Force = $true
}
Get-Item @params
```

Splatting passes named parameters; a hashtable as single argument passes one parameter.

## PS6 — Medium: Remoting

- **Invoke-Command -ComputerName**: One-off remote command.
- **Enter-PSSession**: Interactive remote session.

Uses WinRM (WS-Man) by default; PS 7+ supports SSH-based remoting.

## PS7 — Hard: Type system and pipeline behavior

```powershell
function Get-Items {
    $result = @()
    $result += "one"
    return $result
}
$x = Get-Items
$x.GetType().Name  # String, not Object[]
```

**Why**: PowerShell unrolls single-element arrays. When returning one item, it's unrolled to a string.

**0 items**: Returns `$null` (or `@()` if forced).

**Correct pattern**: Use `Write-Output -NoEnumerate` or `return ,$result` (comma operator).

## PS8 — Hard: Scriptblock vs function

**Scriptblock**: `{ ... }` — anonymous code block, can be passed as argument.

**Function**: Named, reusable, has parameters.

Passing to remote: Scriptblocks serialize and execute remotely.

**Double-hop problem**: Credentials don't cross multiple hops. Solutions: CredSSP, Kerberos delegation, or `Invoke-Command -ArgumentList` to pass credentials explicitly.

## PS9 — Easy: @() vs [array]

- `@()`: Array subexpression — wraps results in array.
- `[array]`: Type accelerator — casts to array.

Force single result into array: `@($result)` or `Write-Output -NoEnumerate`.

Indexing `$null` → `$null`; empty array → error.

## PS10 — Easy: Comparison operators

- `-eq`, `-ne`: Equality.
- `-like`, `-notlike`: Wildcard matching.
- `-match`, `-notmatch`: Regex.
- `-contains`: Checks if collection contains value.
- `-in`: Checks if value is in collection.

Case-sensitive variants: `-ceq`, `-clike`, `-cmatch`, etc.

`-contains` vs `-in`: `$collection -contains $value` vs `$value -in $collection`.

## PS11 — Easy: Modules

- **Script module (.psm1)**: PowerShell script with functions.
- **Manifest module (.psd1)**: Metadata file describing module.
- **Binary module**: Compiled .NET assembly.

`Import-Module` loads module into session.

## PS12 — Easy: String interpolation

- `"..."`: Interpolates variables and expressions.
- `'...'`: Literal strings.

```powershell
$name = "World"
"Hello $name"  # Hello World
"2 + 2 = $(2+2)"  # 2 + 2 = 4
```

**Here-string**:
```powershell
@"
multi-line
"@
```

## PS13 — Easy: Get-Member

`Get-Member` shows properties, methods, and note properties of objects.

- **Properties**: Standard properties.
- **Methods**: Callable methods.
- **NoteProperties**: Added properties (e.g., from `Select-Object`).

`Select-Object` selects properties; `Where-Object` filters objects.

## PS14 — Medium: PowerShell classes

```powershell
class Person {
  [string]$Name
  [int]$Age
  Person([string]$name, [int]$age) {
    $this.Name = $name
    $this.Age = $age
  }
}
```

Limitations: No multiple inheritance, limited interface support, constructors must be explicit.

Use classes for complex state/behavior; functions for simple operations.

## PS15 — Medium: CmdletBinding and advanced functions

```powershell
function Get-Thing {
  [CmdletBinding(SupportsShouldProcess=$true)]
  param(
    [Parameter(Mandatory=$true, ValueFromPipeline=$true)]
    [string]$Name
  )
  Begin { }
  Process { }
  End { }
}
```

`[CmdletBinding()]` enables: parameter validation, `-Verbose`, `-Debug`, `-WhatIf`, `-Confirm`.

**Begin/Process/End**: Pipeline processing stages.

## PS16 — Medium: Providers

PowerShell providers expose data stores as drives:

- FileSystem: `C:`, `D:`
- Registry: `HKCU:`, `HKLM:`
- Certificate: `Cert:`
- Environment: `Env:`

```powershell
Get-ChildItem HKLM:\SOFTWARE\Microsoft
Set-Location Cert:\CurrentUser\My
```

## PS17 — Hard: Runspaces

**Runspace**: Isolated execution environment.
**RunspacePool**: Pool of runspaces for parallel execution.
**PowerShell object**: Encapsulates a command to execute.

```powershell
$pool = [runspacefactory]::CreateRunspacePool(1, 10)
$ps = [powershell]::Create()
$ps.RunspacePool = $pool
$ps.AddScript({ ... })
$ps.BeginInvoke()
```

`ForEach-Object -Parallel` (PS 7+) simplifies this.

## PS18 — Hard: PSScriptAnalyzer

Static analysis tool for PowerShell — checks for best practices, security issues, style.

**Rules**: Categories (e.g., `PSUseShouldProcessForStateChangingCommands`).
**Severity**: Error, Warning, Information.
**Custom rules**: Write as PowerShell functions/classes.

Suppress: `#PSScriptAnalyzer -Suppress` or `.psd1` settings.

CI/CD: Run `Invoke-ScriptAnalyzer` in pipeline.

## PS19 — Hard: $using: scope vs -ArgumentList

- `$using:`: Used in scriptblocks for remote/parallel execution — captures variable values.
- `-ArgumentList`: Passes arguments to remote commands.

**Serialization limits**: CLIXML depth limit (5 levels) — complex objects may lose fidelity.

## PS20 — Hard: DSC

**DSC**: Declarative configuration management.

- **Configurations**: Declarative scripts defining desired state.
- **Resources**: Modules implementing configuration logic.
- **LCM**: Local Configuration Manager — applies configurations.

**Windows PowerShell vs PS 7+**: PS 7+ uses `PSDscResources` (newer), Windows PowerShell uses built-in resources.

**Modern replacement**: PowerShell 7+ with `PSResourceGet`, or tools like Ansible, Terraform, Pulumi for infrastructure-as-code.
