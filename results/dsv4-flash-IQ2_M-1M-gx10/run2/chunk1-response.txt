## Networking (20 questions)

**N1 — Easy: Layer 2 vs Layer 3 switch**
A Layer 2 switch forwards frames based on MAC addresses (data link layer). It learns MAC-to-port mappings and floods unknown destinations. A Layer 3 switch also performs routing based on IP addresses (network layer), using hardware ASICs for fast forwarding. L3 switches support inter-VLAN routing, static routes, and sometimes dynamic routing protocols, effectively combining switch and router functionality.

**N2 — Easy: Network/broadcast for 10.0.5.37/20**
/20 means 20 network bits, 12 host bits. Subnet mask: 255.255.240.0. The address 10.0.5.37 falls in the third octet range: 10.0.0.0 – 10.0.15.255. Network address: **10.0.0.0**. Broadcast address: **10.0.15.255**.

**N3 — Medium: TCP three-way handshake**
1. Client sends SYN (seq=x) to server.
2. Server replies with SYN-ACK (seq=y, ack=x+1).
3. Client sends ACK (ack=y+1). Connection established.

If the final ACK is lost, the server has received the client's SYN and sent SYN-ACK, but never gets the ACK. The server considers the connection half-open and will retransmit the SYN-ACK until it times out (typically ~30s–2min). The client, having sent the ACK, considers the connection established and may start sending data. The server will accept the data and complete the handshake implicitly upon receiving the first data segment (since data carries the ACK flag). If no data arrives, the server eventually resets the connection.

**N4 — Medium: SNAT vs DNAT**
- **SNAT** (Source NAT): Rewrites the source IP/port of outgoing packets. Used for outbound internet access from private networks (masquerade). Example: A home router translates 192.168.1.10:5000 → 203.0.113.5:5000 when a user browses the web.
- **DNAT** (Destination NAT): Rewrites the destination IP/port of incoming packets. Used for port forwarding. Example: A router forwards 203.0.113.5:80 → 192.168.1.10:8080 for a web server behind the NAT.

**N5 — Medium: SSL certificate name mismatch causes**
1. The certificate was issued for a different hostname (e.g., `www.example.com` vs `example.com`).
2. The URL uses an IP address or alternate name not present in the certificate's Subject Alternative Name (SAN) field.
3. The certificate is for a wildcard that doesn't cover the subdomain (e.g., `*.example.com` doesn't match `api.example.com`).

**N6 — Medium: VLAN vs VxLAN**
- **VLAN** (802.1Q): Layer 2 segmentation using a 12-bit VLAN ID (max 4094 VLANs). Operates within a single broadcast domain, limited to a physical LAN or data center fabric.
- **VxLAN**: Layer 2 overlay over Layer 3 (UDP port 4789). Uses a 24-bit VNI (16 million segments) and encapsulates Ethernet frames in UDP/IP. Enables multi-tenant isolation across data centers and cloud environments.

Choose VxLAN over VLAN when: scaling beyond 4094 segments, spanning multiple physical sites/data centers, or building overlay networks on top of existing Layer 3 infrastructure (e.g., cloud, SDN).

**N7 — Hard: Asymmetric routing with two NICs**
The host has two interfaces with different subnets. Traffic arriving on eth1 (192.168.1.0/24) is replied via eth0 because the Linux routing table uses the **source address** of the reply. When the kernel sends a reply, it looks up the route to 192.168.1.x; the default route via eth0 (10.0.0.1) matches, so the reply goes out eth0. The source IP is 192.168.1.5, but the packet leaves via eth0 — the remote host sees a source IP from a different subnet than the destination, breaking connectivity.

**Fix with policy-based routing:**
1. Create a separate routing table for eth1 traffic:
   ```
   ip rule add from 192.168.1.5 table 100
   ip route add 192.168.1.0/24 dev eth1 table 100
   ip route add default via 192.168.1.1 table 100
   ```
2. Ensure the main table still handles eth0 traffic. This forces replies to use eth1 as the source interface.

**N8 — Hard: BGP path selection**
BGP selects the best path in this order (highest preference first):
1. **Highest Weight** (Cisco-specific, local to router)
2. **Highest Local Preference** (local policy, prefer exit point)
3. **Shortest AS path** (fewest AS hops)
4. **Lowest origin** (IGP < EGP < incomplete)
5. **Lowest MED** (multi-exit discriminator, when same AS)
6. **Prefer eBGP over iBGP**
7. **Shortest path to IGP** (lowest IGP metric to next hop)
8. **Oldest route** (longest time in table)
9. **Lowest router ID** (tie-breaker)

**N9 — Hard: VxLAN over IPsec MTU math**
Physical MTU = 1500 bytes. Overhead per packet:
- IPsec (ESP) overhead: ~50–60 bytes (varies with auth, padding)
- UDP header: 8 bytes
- VxLAN header: 8 bytes
- Outer IP header: 20 bytes

Total overhead ≈ 20 (outer IP) + 8 (UDP) + 8 (VxLAN) + ~50 (IPsec) = **~86 bytes**. Maximum inner payload = 1500 − 86 = **~1414 bytes**. If the inner Ethernet frame is 1500, the effective MTU for the encapsulated traffic is ~1414 bytes. This requires MSS clamping on TCP (e.g., `ip link set mtu 1414` on the tunnel interface) to avoid fragmentation.

**N10 — Medium: ARP and Gratuitous ARP**
ARP (Address Resolution Protocol) maps IP addresses to MAC addresses on a LAN. A host broadcasts "who has 10.0.0.1?" and the owner replies with its MAC.

Gratuitous ARP is an unsolicited ARP reply announcing a host's IP-to-MAC mapping without being asked. It solves:
- **Duplicate IP detection** (host checks if another host owns its IP)
- **Failover/virtual IP** (e.g., VRRP, keepalived — a backup takes over the VIP and sends GARP to update switches)
- **Updating switch MAC tables** after a NIC change or VM migration

**N11 — Easy: Public vs private IP**
- **Public IP**: Globally routable on the internet, assigned by IANA/RIRs. Used for internet-facing servers.
- **Private IP**: Not routable on the internet, used within private networks. RFC 1918 ranges:
  - 10.0.0.0/8 (10.0.0.0 – 10.255.255.255)
  - 172.16.0.0/12 (172.16.0.0 – 172.31.255.255)
  - 192.168.0.0/16 (192.168.0.0 – 192.168.255.255)

**N12 — Easy: DNS records**
DNS (Domain Name System) translates hostnames to IP addresses.
- **A record**: Maps a hostname to an IPv4 address (e.g., `example.com → 93.184.216.34`).
- **AAAA record**: Maps a hostname to an IPv6 address.
- **CNAME record**: Alias pointing to another hostname (e.g., `www.example.com → example.com`). The target must be an A/AAAA record, not another CNAME.

**N13 — Easy: DHCP DORA**
DHCP (Dynamic Host Configuration Protocol) assigns IP addresses automatically. The four-step process:
1. **D**iscover: Client broadcasts "DHCPDISCOVER" to find servers.
2. **O**ffer: Server replies with "DHCPOFFER" proposing an IP, lease time, gateway, DNS.
3. **R**equest: Client broadcasts "DHCPREQUEST" accepting the offer.
4. **A**ck: Server sends "DHCPACK" confirming the lease.

**N14 — Easy: Hub, switch, router**
- **Hub**: Layer 1 (physical). Repeats all signals to all ports — a shared collision domain.
- **Switch**: Layer 2 (data link). Forwards frames based on MAC addresses, creating separate collision domains per port.
- **Router**: Layer 3 (network). Routes packets based on IP addresses between networks.

**N15 — Easy: Half vs full duplex**
- **Half-duplex**: Communication in one direction at a time (e.g., walkie-talkie). Uses CSMA/CD to avoid collisions.
- **Full-duplex**: Simultaneous bidirectional communication (e.g., telephone). Uses separate transmit/receive paths.
Modern Ethernet links use **full-duplex** (with auto-negotiation), except in rare legacy or misconfigured cases.

**N16 — Medium: TTL and traceroute**
TTL (Time To Live) in IPv4 limits a packet's lifetime. Each router decrements TTL by 1; when it reaches 0, the router drops the packet and sends an ICMP Time Exceeded message back to the source.

Traceroute exploits this by sending packets with TTL=1, 2, 3, ... Each hop that decrements TTL to 0 replies with ICMP Time Exceeded, revealing its IP address. This maps the path hop-by-hop.

**N17 — Medium: NAT gateway types**
A NAT gateway translates private IPs to public IPs for internet access.
- **Static NAT**: One-to-one mapping (private IP ↔ public IP). Used for servers needing consistent external addresses.
- **Dynamic NAT**: Maps a pool of public IPs to a pool of private IPs on demand. Used when more internal hosts than public IPs.
- **PAT (Port Address Translation)**: Many-to-one mapping — multiple private IPs share one public IP, distinguished by source port. Used in home routers (masquerade).

**N18 — Hard: ECMP**
ECMP (Equal-Cost Multi-Path) routing forwards packets across multiple paths with equal metric. A hash of packet headers (e.g., 5-tuple: src IP, dst IP, src port, dst port, protocol) selects the outgoing interface. This preserves flow affinity — all packets of a flow take the same path.

**Problems with asymmetric flows**: If forward and reverse traffic take different paths (e.g., due to different hashing), stateful firewalls (which track connection state) may drop packets because they see only one direction. Solutions include:
- Ensuring symmetric hashing (same hash on both directions)
- Using a single firewall per flow (e.g., policy-based routing)
- Stateless filtering or flow-based tunneling

**N19 — Hard: TCP window scaling**
The problem: The TCP receive window is advertised as a 16-bit field (max 64KB). With a bandwidth-delay product of 10MB, the sender can only transmit 64KB before waiting for an ACK, causing severe underutilization — the link is idle most of the time.

**Solution (RFC 1323)**: TCP window scaling adds a 14-bit scale factor in the SYN handshake. The window field is multiplied by 2^scale (up to 14). With scale=14, the effective window can be up to 1GB. The receiver advertises a larger window, allowing the sender to fill the pipe. Both hosts must negotiate the scale factor during the handshake.

**N20 — Hard: 802.1Q trunk ports**
802.1Q trunk ports carry multiple VLANs on a single link by adding a 4-byte VLAN tag to each Ethernet frame:
- **Tag format**: TPID (0x8100), TCI (PCP 3 bits, CFI/DEI 1 bit, VLAN ID 12 bits). The tag is inserted after the source MAC and before the EtherType/Length.

**Linux configuration** (single NIC, VLANs 10, 20, 30):
```
ip link add link eth0 name eth0.10 type vlan id 10
ip link add link eth0 name eth0.20 type vlan id 20
ip link add link eth0 name eth0.30 type vlan id 30
ip addr add 10.0.10.5/24 dev eth0.10
ip addr add 10.0.20.5/24 dev eth0.20
ip addr add 10.0.30.5/24 dev eth0.30
ip link set eth0 up
ip link set eth0.10 up
...
```
On the wire, each frame carries the VLAN tag. The switch trunk port strips/inserts tags as needed. Untagged frames on the native VLAN (default VLAN 1) are handled by the physical interface.

## Linux (20 questions)

**L1 — Easy: Hard vs symbolic links**
- **Hard link**: A direct directory entry pointing to the same inode. It shares the same data blocks and inode number. Cannot link across filesystems, cannot link directories. Deleting the original doesn't break the link.
- **Symbolic link** (symlink): A special file containing a path to the target. Can cross filesystems, can link directories. If the target is deleted, the symlink becomes dangling (broken).

**L2 — Easy: Find files >100MB under /var/log**
```bash
find /var/log -type f -size +100M
```
This prints all files larger than 100MB. Add `-exec ls -lh {} \;` for details or `-delete` to remove them.

**L3 — Medium: Process state D**
State D (uninterruptible sleep) means the process is blocked on I/O (e.g., disk, NFS) and cannot be interrupted. It's waiting for a kernel operation to complete. `kill -9` cannot kill it because the process isn't running user code — it's in kernel space. The process will only exit when the I/O completes or fails (e.g., NFS timeout). If it's stuck forever, you may need to reboot or fix the underlying I/O issue.

**L4 — Medium: cgroups v1 vs v2**
- **cgroups v1**: Hierarchical, per-controller (CPU, memory, I/O) with separate mount points. Controllers can be independently assigned. Complex and inconsistent.
- **cgroups v2**: Unified hierarchy — all controllers under one mount (`/sys/fs/cgroup`). Uses a single namespace, supports delegation, and has a cleaner API. Controllers are enabled/disabled via `cgroup.controllers` and `cgroup.subtree_control`.

**systemd prefers cgroups v2** because it provides a unified, predictable interface, supports delegation to user services, and simplifies resource management (e.g., `systemd.resource-control`).

**L5 — Medium: nftables vs iptables**
- **iptables**: Legacy packet filtering using a rule-based chain model (INPUT, OUTPUT, FORWARD) with separate tables (filter, nat, mangle). Uses `iptables`/`ip6tables` commands. Backend: xtables.
- **nftables**: Modern replacement with a single framework, simpler syntax, and better performance. Uses `nft` command with a structured configuration (tables, chains, rules). It supports both IPv4 and IPv6 in one tool.

The kernel can handle both simultaneously — nftables and iptables are separate subsystems. However, they can conflict if both try to manage the same hooks. The kernel's netfilter framework allows both, but it's recommended to use one exclusively. On modern distros, nftables is the default (e.g., Debian 11+, RHEL 9).

**L6 — Medium: df vs du discrepancy**
The most likely cause is **deleted files still held open** by a process. When a file is deleted but a process has it open, the inode remains allocated, so `df` shows the space as used, but `du` (which scans the filesystem) doesn't see the file. Other causes: reserved blocks (ext4 reserves 5%), filesystem metadata, or hidden files (e.g., snapshots, LVM).

Diagnose with `lsof +L1 /path` to list processes holding deleted files.

**L7 — Hard: Linux boot process**
1. **UEFI firmware**: Initializes hardware, reads NVRAM variables, and loads the bootloader (e.g., GRUB) from the EFI System Partition (ESP).
2. **Bootloader (GRUB)**: Reads its config (`/boot/grub/grub.cfg`), loads the kernel and initramfs into memory, and passes control to the kernel.
3. **Kernel**: Decompresses itself, initializes CPU, memory, and core subsystems. It then unpacks the initramfs (initial RAM filesystem) into a tmpfs.
4. **initramfs**: A minimal userspace that loads essential drivers (storage, filesystem, crypto) and performs early setup. It mounts the real root filesystem (e.g., `/dev/sda2`) and switches to it via `switch_root` (pivot_root).
5. **Root filesystem**: The kernel mounts the real root (`/`) read-only initially, then remounts read-write.
6. **systemd**: PID 1 starts. It reads `/etc/systemd/system/default.target` (e.g., `multi-user.target`), starts dependencies (mounts, services, sockets), and brings the system to the desired target state.

**L8 — Hard: OOM killer with high buff/cache**
`free -h` shows 60GB used, 1GB available, 15GB buff/cache. The "available" metric accounts for reclaimable cache, but if the system is under memory pressure, the kernel may still invoke the OOM killer. Why:
- **buff/cache** includes reclaimable page cache, but some pages are **dirty** (need writeback) or **unreclaimable** (e.g., tmpfs, shmem, locked pages).
- The kernel's `vm.min_free_kbytes` and `vm.zone_reclaim_mode` affect how aggressively it reclaims memory.
- If the workload allocates memory faster than the kernel can reclaim cache, the OOM killer fires.

Tunables:
- `vm.vfs_cache_pressure` (higher = more aggressive inode/dentry reclamation)
- `vm.swappiness` (higher = more swap usage)
- `vm.overcommit_memory` (0 = heuristic, 1 = always overcommit, 2 = strict)
- `vm.min_free_kbytes` (reserve memory for the kernel)

**L9 — Medium: ip netns**
`ip netns` creates and manages Linux network namespaces — isolated network stacks (interfaces, routes, ARP tables, iptables). Container runtimes (Docker, Podman) use namespaces to give each container its own virtual network interface, IP address, and routing table. Example:
```bash
ip netns add ns1
ip link add veth0 type veth peer name veth1
ip link set veth1 netns ns1
ip netns exec ns1 ip addr add 10.0.0.1/24 dev veth1
```
This creates a virtual Ethernet pair connecting the host to the namespace.

**L10 — Medium: Signals**
- **SIGTERM** (15): Graceful termination. Can be caught, handled, or ignored. Processes can clean up and exit.
- **SIGKILL** (9): Immediate termination. Cannot be caught, blocked, or ignored. The kernel kills the process.
- **SIGQUIT** (3): Similar to SIGTERM but also generates a core dump. Can be caught.

Only SIGTERM and SIGQUIT can be caught by the process. SIGKILL is uncatchable.

**L11 — Easy: stdout, stderr, stdin**
- **stdin** (0): Standard input — data read by the program.
- **stdout** (1): Standard output — normal output.
- **stderr** (2): Standard error — error messages.

Redirect stderr to a file while keeping stdout on the terminal:
```bash
command 2>error.log
```
To redirect both stdout and stderr to a file: `command >output.log 2>&1`.

**L12 — Easy: chmod 755**
`chmod 755` sets permissions: owner rwx (7), group r-x (5), others r-x (5).
- **7** = read (4) + write (2) + execute (1)
- **5** = read (4) + execute (1)
- **5** = read (4) + execute (1)

This is typical for directories and executables (e.g., `/usr/bin`).

**L13 — Easy: root vs sudo**
- **root**: The superuser with UID 0, bypasses all permission checks. Can do anything.
- **sudo user**: A regular user granted elevated privileges via `/etc/sudoers`. They must authenticate and are subject to policy (e.g., can only run certain commands). sudo logs commands, providing an audit trail. Root has no such restrictions.

**L14 — Easy: Package managers**
A package manager installs, updates, and removes software packages, resolving dependencies.
- **Debian/Ubuntu**: `apt` (frontend) / `dpkg` (backend)
- **RHEL/Fedora**: `dnf` (frontend) / `rpm` (backend)

**L15 — Easy: /etc/fstab**
`/etc/fstab` defines filesystem mount points, options, and dump/fsck order. It's read at boot to mount filesystems. If an entry is misconfigured (e.g., wrong device, bad options), the boot may fail or hang. The system may drop to emergency mode or fail to mount critical filesystems (e.g., `/`), causing a kernel panic or read-only root.

**L16 — Medium: LVM**
LVM (Logical Volume Manager) provides flexible storage management:
- **Physical Volume (PV)**: A disk or partition (e.g., `/dev/sda1`) initialized for LVM.
- **Volume Group (VG)**: A pool of PVs (e.g., `vg0`).
- **Logical Volume (LV)**: A virtual disk carved from the VG (e.g., `/dev/vg0/lv_data`), mounted as a filesystem.

Extend an LV on a running system:
```bash
# Add a new PV
pvcreate /dev/sdb1
vgextend vg0 /dev/sdb1
# Extend the LV
lvextend -L +10G /dev/vg0/lv_data
# Resize the filesystem
resize2fs /dev/vg0/lv_data   # ext4
xfs_growfs /dev/vg0/lv_data  # XFS
```

**L17 — Hard: I/O schedulers**
The Linux block layer uses I/O schedulers to reorder/merge requests:
- **mq-deadline**: Default for most devices. Provides per-request deadlines (read/write), ensuring fairness and low latency. Good for SSDs and general workloads.
- **bfq** (Budget Fair Queuing): Provides per-process fairness and low latency, ideal for interactive/desktop workloads and shared storage.
- **none** (noop): No reordering — passes requests directly to the device. Best for NVMe/SSDs with high parallelism and hardware schedulers.

Change at runtime:
```bash
echo bfq > /sys/block/sda/queue/scheduler
```
Or via `udev` rules for persistence.

**L18 — Hard: Load average**
Load average measures the **number of runnable and uninterruptible tasks** in the kernel run queue, averaged over 1/5/15 minutes. It includes tasks waiting for I/O (state D), so disk I/O can inflate it even with low CPU usage.

Diagnosis:
- **CPU**: `top`/`mpstat` — check %CPU, run queue length.
- **Disk**: `iostat -x 1` — check %util, await, svctime. High await with low %util suggests contention.
- **Network**: `sar -n DEV` or `nload` — check throughput, errors, drops.

If load is high but CPU is low, check `vmstat` for `b` (blocked) processes and `iostat` for disk I/O.

**L19 — Hard: SELinux**
SELinux enforces **mandatory access control (MAC)** using policies that label processes, files, and ports. Each subject (process) has a security context (e.g., `system_u:system_r:httpd_t:s0`), and the kernel checks rules (allow/deny) for each access.

Modes:
- **Enforcing**: Policy is enforced; violations are denied and logged (AVC).
- **Permissive**: Policy is not enforced but violations are logged (for troubleshooting).
- **Disabled**: SELinux is off entirely (no labeling, no checks).

Troubleshoot a daemon failing to bind a non-standard port:
1. Check AVC logs: `ausearch -m avc -ts recent` or `journalctl -t setroubleshoot`.
2. Find the port type: `semanage port -l | grep <port>`.
3. Add the port to the policy: `semanage port -a -t httpd_port_t -p tcp 8080`.
4. Restart the service and verify.

**L20 — Hard: Page faults and THP**
When a process accesses a virtual page not in physical memory, the CPU raises a page fault:
- **Minor fault**: The page is in memory but not mapped in the process's page table (e.g., shared pages, COW). Fast — just updates the page table.
- **Major fault**: The page must be read from disk (swap, mmap file). Slow — involves I/O.

**Transparent Huge Pages (THP)**: The kernel automatically uses 2MB (or 1GB) pages instead of 4KB pages for large memory regions. Benefits: fewer TLB misses, lower page table overhead. Risks: higher memory fragmentation, larger allocation latency, and potential for more memory usage (huge pages are not reclaimed as easily).

Disable THP when: applications have unpredictable memory access patterns, suffer from latency spikes due to khugepaged, or when memory fragmentation is a concern. Disable via:
```bash
echo never > /sys/kernel/mm/transparent_hugepage/enabled
```
Or in kernel cmdline: `transparent_hugepage=never`.
