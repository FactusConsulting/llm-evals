## JavaScript / TypeScript (20 questions)

**JS1 — Easy:**
`var` is function-scoped, hoisted (initialized as `undefined`), and can be redeclared. `let` and `const` are block-scoped, hoisted but in a temporal dead zone (TDZ) — accessing before declaration throws `ReferenceError`. `let` can be reassigned; `const` cannot (though object properties can be mutated). Hoisting is the JS engine's behavior of moving declarations to the top of their scope during compilation. Function declarations are fully hoisted; `var` declarations are hoisted with initialization to `undefined`; `let`/`const` are hoisted but not initialized (TDZ).

**JS2 — Easy:**
The event loop coordinates the call stack (where synchronous code runs), the microtask queue (Promise callbacks, `queueMicrotask`, `MutationObserver`), and the macrotask queue (setTimeout, setInterval, I/O events). When the call stack empties, the event loop processes all microtasks first (draining the queue), then picks one macrotask. This ensures microtasks run before the next macrotask, enabling predictable async ordering.

**JS3 — Medium:**
A closure is a function that retains access to its lexical scope even when executed outside that scope. Practical example: a counter factory:
```js
function makeCounter() {
  let count = 0;
  return () => ++count;
}
```
The classic for-loop closure bug: `var` in a loop creates one shared variable; callbacks capture the same `i`:
```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100); // logs 3, 3, 3
}
```
Fix: use `let` (block-scoped, new binding per iteration), or wrap in an IIFE, or use `.bind(null, i)`.

**JS4 — Medium:**
Promises represent eventual completion. `async/await` is syntactic sugar over Promises. Error handling: `.catch()` for Promises; `try/catch` for async/await. `Promise.all` rejects fast on first rejection (fail-fast). `Promise.allSettled` waits for all to settle and returns `[{status: 'fulfilled', value}, {status: 'rejected', reason}]` — never rejects. Use `allSettled` when you need all results regardless of failures (e.g., batch API calls).

**JS5 — Medium:**
`interface` is a compile-time-only construct that supports declaration merging and is best for object shapes, class contracts, and public APIs. `type` is more flexible — supports unions, intersections, mapped types, tuples, and computed types. Use `type` for unions/intersections, complex transformations; `interface` for object shapes and extending. Discriminated unions: a union of object types each with a common discriminant property (e.g., `type: 'circle' | 'square'`), enabling exhaustive type narrowing via switch.

**JS6 — Medium:**
Prototypal inheritance: objects inherit from other objects via `[[Prototype]]`. `Object.create(obj)` creates a new object with `obj` as its prototype — enabling clean delegation without constructors. ES6 classes are syntactic sugar over prototypes: `class Foo {}` creates a constructor function with `Foo.prototype`; `extends` sets up prototype chains; `super` calls parent constructor. Under the hood, `new` creates an object, sets prototype, and binds `this`.

**JS7 — Hard:**
`this` is determined by how a function is called. Binding rules (priority order):
1. **New binding** — `new` creates a new object and sets `this` to it.
2. **Explicit binding** — `call`, `apply`, `bind` override `this`.
3. **Implicit binding** — method call: `obj.method()` sets `this` to `obj`.
4. **Default binding** — standalone function call: `this` is `undefined` in strict mode, global object otherwise.

`bind()` returns a new function with `this` permanently bound. You **cannot** re-bind a bound function — even `call`/`apply` on a bound function cannot change `this` (it ignores them). Arrow functions ignore all binding rules — `this` is lexically captured.

**JS8 — Hard:**
`WeakRef` holds a weak reference to an object — it doesn't prevent GC. `FinalizationRegistry` lets you register callbacks that run when objects are garbage collected. Use cases: caching large objects (e.g., image buffers) where you don't want to keep memory alive, or cleaning up external resources (e.g., closing file handles). WeakMap keys must be objects because WeakMap uses weak references — only objects can be weakly referenced (primitives can't be tracked by GC). This lets the key-value pair be collected when the key is no longer reachable, preventing memory leaks in caches.

**JS9 — Hard:**
V8 optimizations:
- **Hidden classes**: V8 creates internal class maps for objects with the same shape; adding properties in different orders creates different hidden classes (deoptimization).
- **Inline caching**: V8 caches property lookup results based on hidden class; monomorphic (one shape) is fastest, polymorphic (2–4 shapes) is slower, megamorphic is slowest.
- **Deoptimization triggers**: adding/removing properties dynamically, changing object shape, using `delete`, accessing out-of-bounds array indices, mixing types in arrays, using `eval`, `with`, or `arguments` object. Patterns that cause deoptimization: `obj.newProp = x` after object creation, sparse arrays, `Array.prototype` modifications.

**JS10 — Medium:**
Tree-shaking removes unused exports from bundles. ES modules are statically analyzable — imports/exports are known at compile time, enabling dead-code elimination. CommonJS is dynamic (`require` can be conditional, `module.exports` is mutable), so bundlers can't reliably determine what's used. ES modules also enable `sideEffects: false` in package.json to allow aggressive shaking. CommonJS requires heuristics (e.g., `cjs-module-lexer`) and often can't fully shake.

**JS11 — Easy:**
`null` is an explicit absence of value (typeof `"object"`); `undefined` is an uninitialized variable (typeof `"undefined"`). `==` treats them as equal (`null == undefined` → `true`); `===` does not. Nullish coalescing `??` returns the right side only for `null`/`undefined` (unlike `||` which also treats `0`, `''`, `false` as falsy). Optional chaining `?.` short-circuits if the left side is `null`/`undefined`: `obj?.a?.b`.

**JS12 — Easy:**
`map()` transforms each element and returns a new array. `filter()` returns elements passing a predicate. `reduce()` accumulates: `arr.reduce((acc, val) => acc + val, 0)` — the initial value is the first `acc`; without it, `acc` is the first element. `flatMap()` maps then flattens one level — useful for one-to-many transformations (e.g., `[1,2,3].flatMap(x => [x, x*2])` → `[1,2,2,4,3,6]`), avoiding nested arrays.

**JS13 — Easy:**
Template literals use backticks, support `${expr}` interpolation, and multi-line strings. Tagged templates: a function receives the string parts array and interpolated values:
```js
function escapeHtml(strings, ...values) {
  return strings.reduce((acc, str, i) => 
    acc + str + (i < values.length ? String(values[i]).replace(/[&<>"']/g, m => ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[m])) : ''), '');
}
const name = '<script>';
escapeHtml`<p>${name}</p>`; // <p>&lt;script&gt;</p>
```

**JS14 — Easy:**
Destructuring unpacks values from objects/arrays. Object: `const { a, b: renamed, c = 1 } = obj` — `b` is renamed to `renamed`, `c` gets default `1` if undefined. Array: `const [first, , third = 3] = arr` — skips second, default for third. Rest operator `...` collects remaining: `const { a, ...rest } = obj` or `const [head, ...tail] = arr`. Also works in function params: `function f({ x, y }) {}`.

**JS15 — Easy:**
`for...in` iterates over enumerable string keys (including inherited ones) — designed for objects. `for...of` iterates over iterable values (arrays, strings, Maps, Sets) — designed for collections. Avoid `for...in` on arrays because it includes inherited properties, iterates in arbitrary order, and includes non-index keys; use `for...of` or `.forEach()` instead.

**JS16 — Medium:**
Generics: `function identity<T>(arg: T): T { return arg; }`. Constraints: `function logLength<T extends { length: number }>(arg: T): void {}`. Conditional types: `type IsArray<T> = T extends any[] ? true : false`. `infer` extracts types: `type ElementType<T> = T extends (infer U)[] ? U : never;` — practical example: `type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;` used to extract function return types.

**JS17 — Medium:**
CommonJS: synchronous, `require`/`module.exports`, used by Node.js historically. ES Modules: asynchronous, `import`/`export`, static and analyzable. Node.js supports both: `.cjs` forces CommonJS, `.mjs` forces ESM, and `"type": "module"` in package.json makes `.js` files ESM. Node uses `require` for CJS and `import` for ESM; ESM can import CJS via default export, but CJS cannot `require` ESM (must use dynamic `import()`).

**JS18 — Hard:**
TypeScript's structural typing: types are compatible if shapes match, not by name. Excess property checks: when assigning an object literal to a typed variable, TS errors on extra properties (but not when assigning a variable). `extends` checks assignability (a type is assignable to another); `satisfies` (TS 4.9) checks a value's type against a type without changing the inferred type — `const x = { a: 1 } satisfies Record<string, number>`. Variance: `in` (contravariant — function parameters) and `out` (covariant — return types) modifiers in TS 4.7+ control how generic types relate; `in` allows safe function assignment, `out` allows safe return type assignment.

**JS19 — Hard:**
`Proxy` wraps an object to intercept operations via handler traps (`get`, `set`, `apply`, `has`, `deleteProperty`). `Reflect` provides default behavior for traps. Example — reactive data binding:
```js
const reactive = (obj, onChange) => new Proxy(obj, {
  set(target, prop, value) {
    target[prop] = value;
    onChange(prop, value);
    return true;
  }
});
```
Also used for validation (reject invalid sets), logging (log all gets), and function call interception (`apply` trap).

**JS20 — Hard:**
`SharedArrayBuffer` allows multiple threads (Web Workers) to share memory. `Atomics` provides atomic operations (`add`, `load`, `store`, `compareExchange`) that are guaranteed to be atomic and ordered. Workers communicate by sharing a `SharedArrayBuffer` and using `Atomics` to synchronize. Ordering: operations are sequentially consistent — all threads see the same order of atomic operations. `Atomics.wait` blocks a thread until a value changes; `Atomics.notify` wakes waiting threads — used for producer-consumer patterns. Note: SharedArrayBuffer requires cross-origin isolation (COOP/COEP headers) for security.

## Bash (20 questions)

**B1 — Easy:**
`$@` and `$*` both expand to positional parameters. Unquoted, they're identical (all args, word-split). Quoted: `"$@"` expands each argument as a separate word (preserves spaces); `"$*"` joins all arguments into a single word with the first char of `IFS` (usually space). Use `"$@"` for safe argument passing.

**B2 — Easy:**
- `set -e`: exit immediately if any command returns non-zero (errexit).
- `set -u`: error on unset variables (nounset).
- `set -o pipefail`: pipeline returns the rightmost non-zero exit code (not just the last command).
- `set -euo pipefail` is the standard "strict mode" for robust scripts.

**B3 — Medium:**
`$(command)` and `` `command` `` both do command substitution. `$()` is preferred: easier to nest (`$(echo $(date))`), handles quoting better, and is more readable. `$((expression))` does arithmetic expansion (integer math): `echo $((2+3))` → `5`. `expr` is an external command that's slower and requires escaping (`expr 2 + 3`), and is legacy.

**B4 — Medium:**
Process substitution `<(command)` creates a file descriptor (e.g., `/dev/fd/63`) that acts as a named pipe — the command's output is readable as a file. Use when a command expects a file argument. Example:
```bash
diff <(sort file1.txt) <(sort file2.txt)
```
Also useful for `while read` loops without subshell issues: `while read line; do ...; done < <(command)`.

**B5 — Medium:**
Use `find` with `-print0` and `while IFS= read -r -d ''`:
```bash
find . -type f -print0 | while IFS= read -r -d '' file; do
  process "$file"
done
```
Or use `for` with glob: `for f in *.txt; do ...` (safe if no spaces in glob). `for f in $(ls)` is dangerous because `$(ls)` splits on IFS (spaces), breaking filenames with spaces, and `ls` output is for humans, not programmatic use.

**B6 — Medium:**
Here document `<<EOF` feeds stdin from a script block:
```bash
cat <<EOF
Hello $USER
EOF
```
Here string `<<<` feeds a single string: `cat <<< "hello"` (adds trailing newline). `<<-EOF` strips leading tabs (allows indented heredocs for readability):
```bash
if true; then
  cat <<-EOF
    indented content
  EOF
fi
```

**B7 — Hard:**
- `cmd > file 2>&1`: redirects stdout to file, then stderr to the same file (both go to file).
- `cmd 2>&1 > file`: redirects stderr to current stdout (terminal), then stdout to file — stderr goes to terminal, stdout to file.
- `cmd &> file`: bash shorthand for `> file 2>&1` (both to file).

The order matters: `2>&1` copies stderr to wherever stdout currently points. In the second, stdout hasn't been redirected yet when `2>&1` runs, so stderr goes to the terminal.

**B8 — Hard:**
```bash
lock_dir="/tmp/mylock.$$"
while ! mkdir "$lock_dir" 2>/dev/null; do
  # wait for lock
  sleep 0.1
done
trap 'rmdir "$lock_dir"' EXIT INT TERM
# critical section
```
`mkdir` is atomic — only one process succeeds. File creation (`touch`) can race (check-then-create is not atomic). Trap on EXIT, INT, TERM ensures cleanup. For SIGTERM specifically, trap `TERM` and `exit` after cleanup. Use `mkdir` with a PID file inside for ownership. For stale locks, check PID liveness.

**B9 — Easy:**
- Single quotes `'...'`: literal — no expansion. `echo '$HOME'` → `$HOME`.
- Double quotes `"..."`: expansion but no word-splitting. `echo "$HOME"` → `/home/user`.
- No quotes: expansion + word-splitting + globbing. `echo $HOME` → `/home/user` (but splits if spaces).

Example: `var="a b"; echo $var` → `a b` (split); `echo "$var"` → `a b` (one arg); `echo '$var'` → `$var`.

**B10 — Easy:**
- `-f file`: exists and is regular file; `-d`: directory; `-r`: readable; `-w`: writable; `-x`: executable; `-e`: exists.
- `[ ]` (test) is POSIX-compliant, uses external `test` builtin; `[[ ]]` is bash-specific, more features: pattern matching (`[[ $str == foo* ]]`), regex (`[[ $str =~ ^foo ]]`), no word-splitting, supports `&&`/`||` directly. Use `[[ ]]` in bash scripts.

**B11 — Easy:**
- `$?`: exit status of last command — check success/failure.
- `$$`: current shell PID — for temp files, logging.
- `$!`: PID of last background job — to `wait` or `kill` it.
- `$#`: number of positional arguments — validate input count.

**B12 — Easy:**
```bash
foo() { echo "Hello $1"; }
function foo { echo "Hello $1"; }  # equivalent, but foo() is more portable
```
Return values: use `echo` for stdout (capture with `$(foo)`), `return` for exit status (0–255). Functions can modify global variables. `function foo {}` is bash-specific; `foo() {}` is POSIX-compliant.

**B13 — Easy:**
`PATH` is a colon-separated list of directories where bash looks for executables. Bash resolves commands: builtins first (unless `enable -n`), then PATH lookup (hash table caches results). Builtins (e.g., `cd`, `echo`, `read`) are part of the shell; external commands (e.g., `ls`, `grep`) are separate binaries. Check with `type -a cmd` or `which cmd`; `type` shows if it's a builtin, alias, or external.

**B14 — Medium:**
`trap 'command' SIGNAL` sets a handler. Common:
```bash
trap 'cleanup' EXIT      # always runs on script exit
trap 'echo interrupted' INT   # Ctrl-C
trap 'echo terminated' TERM   # kill
```
Execution order: when a signal arrives, bash runs the trap handler, then resumes (or exits if handler exits). For multiple signals, traps run in order received; EXIT trap runs after INT/TERM handlers if the script exits. Use `trap -` to reset. For graceful shutdown, trap TERM, clean up, then `exit 0`.

**B15 — Medium:**
`xargs` reads stdin and builds/runs commands; command substitution `$(...)` captures output as a string. `xargs` handles large inputs efficiently (batches), while `$(...)` loads everything into memory. For filenames:
```bash
find . -type f -print0 | xargs -0 -P 4 -I {} process {}
```
`-0` handles spaces/newlines (null-delimited); `-P` runs parallel jobs (e.g., `-P 4` = 4 processes). Without `-0`, xargs splits on whitespace — dangerous for filenames.

**B16 — Medium:**
Arrays: `arr=(a b c)`; append: `arr+=(d)`; iterate: `for i in "${arr[@]}"`; length: `${#arr[@]}`. Associative arrays: `declare -A assoc; assoc[key]=value`; iterate: `for k in "${!assoc[@]}"`; length: `${#assoc[@]}`. Arrays are 0-indexed, support `"${arr[@]}"` for all elements; associative arrays use string keys, no ordering guarantee. Syntax differences: `$arr` gives first element; `${arr[1]}` indexes; `${!arr[@]}` gives keys/indices.

**B17 — Hard:**
Subshell `(...)` runs in a child process — variable changes don't propagate to parent; exit code is the last command's. Group `{ ...; }` runs in the current shell — variables persist; exit code is last command's. Piping into `while` creates a subshell (in most shells), so variable changes are lost:
```bash
echo -e "a\nb" | while read line; do count=$((count+1)); done
echo $count  # 0 — lost
```
Fix: use process substitution `while ... done < <(echo ...)` or `coproc`, or `bash -c` with explicit output.

**B18 — Hard:**
Signals: SIGINT (Ctrl-C, interrupt), SIGTERM (graceful termination, `kill` default), SIGHUP (hangup — terminal closed), SIGKILL (cannot be caught). Job control: `&` backgrounds a job; `jobs` lists; `kill %1` sends signal. Graceful shutdown with background processes:
```bash
trap 'kill $pid1 $pid2; wait; exit 0' TERM INT
cmd1 & pid1=$!
cmd2 & pid2=$!
wait
```
This traps TERM/INT, kills children, waits, and exits cleanly. SIGKILL can't be trapped — always use SIGTERM for graceful.

**B19 — Hard:**
```bash
#!/bin/bash
process_file() {
  local file="$1"
  # processing logic
  awk '{...}' "$file" > "$file.out"
}
export -f process_file  # for xargs
split -n 4 -d big.log part_  # split into 4 parts
find . -name 'part_*' -print0 | xargs -0 -P 4 -I {} bash -c 'process_file "$1"' _ {}
# merge
cat part_*.out > merged.out
```
Performance: parallel processing reduces wall-clock time but uses more CPU/memory; split creates overhead (I/O). Error propagation: `xargs` returns non-zero if any job fails; use `-P` with `--max-args` carefully; collect exit codes per job (e.g., write to files) for granular error handling.

**B20 — Hard:**
`exec` replaces the current shell process with the command (no return). Running normally forks a child. `exec` for FD manipulation:
```bash
exec 3>file.txt   # open FD 3 for writing
exec 3>&-         # close FD 3
exec 4<&0         # duplicate stdin to FD 4
```
Coprocess: `coproc myproc { command; }` — starts a background process with stdin/stdout as FDs (`myproc[0]` for output, `myproc[1]` for input). Use for bidirectional communication with a long-running process (e.g., a server or interactive program). Example: `coproc sqlite3 db.sqlite; echo "SELECT * FROM t;" >&"${sqlite3[1]}"; read -u "${sqlite3[0]}" result`.

## PowerShell (20 questions)

**PS1 — Easy:**
`Write-Output` writes to the success output stream (pipeline) — objects flow through the pipeline. `Write-Host` writes directly to the host (console) — bypasses the pipeline, so it can't be captured or piped. Use `Write-Output` for data; `Write-Host` for user-facing messages (or `Write-Information` in modern PowerShell). This matters because `$x = Write-Output "hi"` captures; `$x = Write-Host "hi"` sets `$x` to `$null`.

**PS2 — Easy:**
The pipeline passes objects (not text) from one command to the next. `ForEach-Object` is a cmdlet that processes pipeline input one object at a time (streaming, memory-efficient). `foreach` statement is a language construct that iterates over a collection in memory (all at once). Use `ForEach-Object` for pipeline processing (large data, streaming); `foreach` for in-memory collections where you need the full array or better performance (no pipeline overhead).

**PS3 — Medium:**
`[hashtable]` is an unordered key-value collection (`@{key=value}`) — keys are strings, values are objects. `[PSCustomObject]` is a structured object with properties (`[PSCustomObject]@{Name='John'; Age=30}`) — has property names, supports `Select-Object`, formatting, and proper pipeline output. Use hashtable for lookups/dictionaries; PSCustomObject for output objects. Convert: `[PSCustomObject]$hashtable` (keys become properties); `$obj.PSObject.Properties | ForEach-Object { $ht[$_.Name] = $_.Value }` for reverse.

**PS4 — Medium:**
Terminating errors stop execution (can be caught with `try/catch`); non-terminating errors continue (each error is written to error stream, script continues). `-ErrorAction Stop` converts non-terminating to terminating; `$ErrorActionPreference = 'Stop'` does it globally. `try/catch` catches terminating errors; `catch` can filter by exception type. `$Error` is the error history array. `-ErrorAction SilentlyContinue` suppresses display; `-ErrorAction Continue` (default) displays and continues.

**PS5 — Medium:**
Splatting passes parameters as a hashtable or array: `$params = @{Path='C:\'; Recurse=$true}; Get-ChildItem @params`. It improves readability and reduces line length. Difference from passing a hashtable as a single parameter: splatting expands the hashtable into individual named parameters; passing `$params` as an argument sends one hashtable object to a `-Hashtable` parameter (rare). Splatting also works with arrays for positional parameters: `$args = @('a','b'); cmd @args`.

**PS6 — Medium:**
PowerShell remoting uses WinRM (WS-Management protocol, port 5985/5986) by default. `Invoke-Command -ComputerName` runs a scriptblock on remote machines and returns results (one-off). `Enter-PSSession` creates an interactive session (like SSH). PowerShell 7+ supports SSH-based remoting (port 22) via `Invoke-Command -HostName`. WinRM requires WSMan config; SSH remoting uses OpenSSH. Both support `-Session` for reusable connections.

**PS7 — Hard:**
PowerShell functions output **all** output to the pipeline — including `return` and unassigned statements. The function:
```powershell
function Get-Items {
    $result = @()
    $result += "one"
    return $result
}
```
`$result += "one"` creates `@("one")` (array). `return $result` outputs the array. But PowerShell **unwraps** single-element arrays — `$x` becomes a string `"one"`, not an array. `$x.GetType().Name` → `String`. If the function returns 0 items (e.g., `$result` is empty `@()`), `$x` is `$null` (empty array is unwrapped to `$null`). Correct pattern: use `Write-Output -NoEnumerate` or `return ,$result` (comma wraps in array) to preserve array semantics.

**PS8 — Hard:**
A `[scriptblock]` is a block of code (`{ ... }`) that can be invoked; a function is a named scriptblock with parameters. Scriptblocks are first-class objects — pass them to `Invoke-Command -ScriptBlock`. Double-hop problem: when you remote into a machine, credentials don't propagate to a second hop (e.g., accessing a file server). Solutions: CredSSP (delegates credentials, but insecure), `Invoke-Command -ArgumentList` (pass explicit credentials), or Kerberos with constrained delegation. `-ArgumentList` passes parameters to the scriptblock, avoiding the need for credential delegation.

**PS9 — Easy:**
`@()` creates an array; `[array]` is a type accelerator that casts to array. Force single result into array: `$x = @($result)` or `@($result)` — wraps even single items. Indexing `$null` returns `$null` (no error); indexing an empty array `@()[0]` returns `$null` (no error, but `@()[0]` is `$null`). `$null[0]` → `$null`; `@()[0]` → `$null` (both safe). `@()[5]` → `$null` (no error for empty array).

**PS10 — Easy:**
Comparison operators: `-eq` (equal), `-ne` (not equal), `-like` (wildcard), `-match` (regex), `-contains` (collection contains value), `-in` (value in collection). Case-sensitive variants: `-ceq`, `-cne`, `-clike`, `-cmatch`. `-contains` is used on a collection: `$arr -contains 'x'`; `-in` is used on a value: `'x' -in $arr`. Both check membership, but syntax differs. `-like` uses `*` wildcards; `-match` uses regex.

**PS11 — Easy:**
A module is a package of functions, cmdlets, and variables. Script module (`.psm1`) contains PowerShell code; manifest module (`.psd1`) is a metadata file (version, author, dependencies) that describes the module; binary module (`.dll`) is compiled C#. `Import-Module` loads the module: finds it in `$env:PSModulePath`, reads the manifest, imports the `.psm1` or `.dll`. Modules can export functions via `Export-ModuleMember`.

**PS12 — Easy:**
Double quotes `"..."` interpolate: `"Hello $name"` expands variables; `"$(Get-Date)"` expands expressions. Single quotes `'...'` are literal — no expansion. Here-string: `@"..."@` (double-quoted, interpolates) and `@'...'@` (single-quoted, literal) — used for multi-line strings. Example: `$name = "World"; "Hello $name"` → `Hello World`; `'Hello $name'` → `Hello $name`.

**PS13 — Easy:**
`Get-Member` reveals object properties, methods, and note properties (added properties not from the type). `Get-ChildItem | Get-Member` shows `Name`, `FullName`, etc. Properties are type-defined; NoteProperties are added at runtime (e.g., `Select-Object` adds `@{Name=...}`). `Select-Object` picks/creates properties (columns); `Where-Object` filters rows (objects). `Select-Object -First 5` limits; `Where-Object { $_.Size -gt 100 }` filters.

**PS14 — Medium:**
PowerShell classes (v5+) are `class Foo { [int]$Prop; Foo([int]$p) { $this.Prop = $p } }`. They differ from C#: no interfaces (until PS 7.3 added some support), limited inheritance (single, no abstract classes initially), constructors are simplified, no access modifiers (all public), no generics (initially). Use classes for complex stateful objects with methods; use functions for stateless operations. Classes are slower than functions for simple tasks; functions are more PowerShell-idiomatic.

**PS15 — Medium:**
`[CmdletBinding()]` makes a function an advanced function — adds `-Verbose`, `-Debug`, `-ErrorAction`, `-WhatIf`, `-Confirm` parameters. `SupportsShouldProcess` enables `-WhatIf`/`-Confirm` for write operations. `DefaultParameterSetName` selects a parameter set when none specified. `ValueFromPipeline` lets a parameter accept pipeline input. `Begin` (setup), `Process` (per-input-object), `End` (cleanup) blocks — `Process` runs once per pipeline object; without `Process`, the function runs once.

**PS16 — Medium:**
Providers expose data stores as file systems. `Get-ChildItem` works across providers: `Get-ChildItem C:\` (FileSystem), `Get-ChildItem HKLM:\` (Registry), `Get-ChildItem Cert:\` (Certificate), `Get-ChildItem Env:` (Environment). Registry access: `Set-Location HKLM:\Software\...`, `Get-ItemProperty`, `New-ItemProperty`. Each provider supports `Get-ChildItem`, `Set-Location`, `Get-Item`, `New-Item`, etc., with provider-specific parameters.

**PS17 — Hard:**
Runspaces are PowerShell sessions that can run in parallel. `[runspace]` is a single session; `[runspacepool]` manages multiple; `[powershell]` object executes commands. `ForEach-Object -Parallel` (v7+) is simpler: `1..10 | ForEach-Object -Parallel { $_ * 2 } -ThrottleLimit 5`. Manual runspace management: create `[runspacepool]`, create `[powershell]` instances, invoke asynchronously, collect results. Thread safety: runspaces share no state — variables must be passed explicitly (`$using:` or `-ArgumentList`); use `[hashtable]` for shared state with locking.

**PS18 — Hard:**
PSScriptAnalyzer is a static analysis tool for PowerShell. It enforces best practices via rules (e.g., `PSUseShouldProcessForStateChangingCommands`, `PSAvoidUsingWriteHost`). Rules have severity levels: `Error`, `Warning`, `Information`, `None`. Custom rules: write a script that implements `IDynamicScriptRule` or use `-CustomRulePath`. Suppress: `# PSScriptAnalyzer -RuleName 'PSAvoidUsingWriteHost'` or `-SuppressOnly`. CI/CD: run `Invoke-ScriptAnalyzer -Path . -Recurse` in pipelines, fail on `Error` severity.

**PS19 — Hard:**
`$using:` scope passes variables to remote sessions, background jobs, and `ForEach-Object -Parallel` — it captures the variable's value at invocation time. `-ArgumentList` passes parameters explicitly. Serialization limits: CLIXML (PowerShell's XML serialization) has a depth limit (default 2) — deeply nested objects lose fidelity; complex objects (e.g., custom classes) may be deserialized as `PSObject` with property bags, losing methods. `$using:` works for simple types; for complex objects, use `-ArgumentList` or `[System.Management.Automation.PSSession]` with explicit serialization.

**PS20 — Hard:**
DSC is a declarative configuration management system. **Configurations** are scripts that define desired state; **Resources** are modules that implement the logic (e.g., `File`, `Service`, `Registry`); **LCM** (Local Configuration Manager) is the agent that applies configurations and enforces state (push or pull modes). Windows PowerShell DSC uses `Start-DscConfiguration`; PowerShell 7+ has `[DSCv2]` (experimental) and `PSResourceGet` for newer workflows. Modern IaC replaced DSC with: **Azure Arc**, **Terraform**, **Ansible**, **Bicep**, and **Pulumi** — cloud-native, cross-platform, and more flexible than DSC's Windows-centric model.
