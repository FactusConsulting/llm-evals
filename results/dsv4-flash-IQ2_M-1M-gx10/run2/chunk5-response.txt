## .NET / C#

**DN1** — A `class` is a reference type (allocated on the heap, passed by reference), while a `struct` is a value type (allocated inline, passed by value). Use a `struct` for small, immutable, and logically single-value data types (e.g., `Point`, `Complex`, `Guid`) where value semantics are desired and copying is cheap. Avoid structs for large or frequently-mutated objects.

**DN2** — `IEnumerable<T>` represents in-memory, deferred execution over a collection (LINQ to Objects). `IQueryable<T>` represents an expression tree that is translated to a query (e.g., SQL) and executed on the server. For database queries, `IQueryable` allows filtering/sorting to be pushed to the database (reducing memory and network), whereas `IEnumerable` fetches the entire result set into memory first.

**DN3** — `async/await` uses the compiler to create a state machine that yields control back to the caller when awaiting an incomplete operation, resuming on completion. `Task` is a reference type representing an async operation; `ValueTask` is a value type that avoids heap allocation when the result is likely to be synchronous or when the operation completes quickly. Use `ValueTask` for hot paths (e.g., `IAsyncEnumerable` methods) where allocation overhead matters, but be aware it can only be awaited once.

**DN4** — Dependency injection (DI) in .NET is a container that resolves dependencies. **Transient** creates a new instance per resolution; **Scoped** creates one instance per request/scope; **Singleton** creates one instance for the app's lifetime. A common bug is injecting a Scoped service (e.g., `DbContext`) into a Singleton, causing the scoped instance to be captured and reused across requests, leading to stale data or `ObjectDisposedException`.

**DN5** — `string` is immutable and creates a new string for every operation (e.g., `Substring`). `ReadOnlySpan<char>` is a stack-allocated, ref-like type that provides a view over a string without allocation. Use `Span<T>` for high-performance parsing, slicing, or processing of strings where allocation-free operations are critical (e.g., in hot paths or libraries).

**DN6** — The .NET GC is a generational, non-deterministic collector. **Gen 0** holds short-lived objects; **Gen 1** holds survivors from Gen 0; **Gen 2** holds long-lived objects. The **Large Object Heap (LOH)** stores objects >85KB and is collected rarely. `IDisposable` is needed for unmanaged resources (files, sockets, handles) because the GC cannot track them; you must deterministically release them via `Dispose()` or `using`.

**DN7** — By default, `await` captures the current `SynchronizationContext` (e.g., UI thread) to resume on it. `ConfigureAwait(false)` tells the continuation to run on the thread pool, avoiding the context capture. Use it in library code to improve performance and avoid deadlocks. Do **not** use it in UI code where you need to update UI controls, or in ASP.NET Core where the context is not needed (it's already thread-pool based).

**DN8** — **Primary constructors** (C# 12) allow parameters directly in the class declaration. **Collection expressions** (`[1,2,3]`) create collections concisely. **FrozenDictionary** (in `System.Collections.Frozen`) is an immutable, read-optimized dictionary. Example:
```csharp
public class MyService(ILogger<MyService> logger) {
    public void DoWork() => logger.LogInformation("Working");
}
// DI: services.AddSingleton<MyService>();
```

**DN9** — The likely cause is that the `DbContext` is registered as a Singleton or injected into a Singleton, or a scoped `DbContext` is disposed prematurely (e.g., by a middleware). Under high concurrency, the shared `DbContext` is disposed by one request while another is using it. Fix: ensure `DbContext` is registered as **Scoped** (the default) and never injected into Singletons. EF Core's `DbContext` is not thread-safe and must be scoped per request.

**DN10** — A `record` is a reference type with value equality, built-in cloning (`with`), and a positional syntax. A `record struct` is a value type with the same features. Use `record` for DTOs, immutable data, and domain objects where equality is based on properties. Use `class` for mutable, identity-based objects (e.g., entities with IDs). Use `record struct` for small, immutable value types.

**DN11** — `ref` passes a reference to an already-initialized variable (can read/write). `out` passes a reference to an uninitialized variable (must be assigned before return). `in` passes a read-only reference (cannot modify). Use `ref` for large structs to avoid copying, `out` for return values via parameters, and `in` for read-only access to large structs.

**DN12** — Nullable reference types (`string?`) are compile-time annotations that enable static analysis to detect nullability issues. They do not change runtime behavior. Nullable value types (`int?`) are `Nullable<T>` value types that can be `null` at runtime. `#nullable enable` enables the feature for the file.

**DN13** — LINQ (Language Integrated Query) is a set of methods for querying collections. Method syntax (`list.Where(x => x > 5)`) is fluent; query syntax (`from x in list where x > 5 select x`) is syntactic sugar that the compiler translates to method syntax. Deferred execution means the query is not executed until enumerated (e.g., via `foreach` or `.ToList()`), allowing lazy evaluation and composition.

**DN14** — Generic constraints restrict type arguments. `where T : class` (reference type), `where T : struct` (value type), `where T : new()` (parameterless constructor), `where T : IComparable<T>` (implements interface). Combine multiple constraints with commas, e.g., `where T : class, IComparable<T>`, to require both a reference type and an interface.

**DN15** — An `abstract class` can have implementation, state, and constructors; an `interface` is a pure contract (no state). Default interface methods (C# 8+) allow interfaces to have implementations, but they still cannot have state. This blurs the line, but abstract classes remain for shared implementation and interfaces for capability contracts.

**DN16** — The middleware pipeline is a series of delegates that handle requests. `app.Use()` adds a middleware that can short-circuit or call the next delegate. `app.Map()` branches the pipeline based on a path. `app.Run()` is a terminal middleware that ends the pipeline. Ordering matters: exception-handling middleware must be early to catch exceptions from downstream. Middleware runs in the order added.

**DN17** — `Channel<T>` is a modern, async-first, thread-safe producer-consumer queue. It supports bounded channels for backpressure (producers wait when full). `BlockingCollection<T>` is older, synchronous, and uses locks. Example:
```csharp
var channel = Channel.CreateBounded<int>(10);
await channel.Writer.WriteAsync(1);
await foreach (var item in channel.Reader.ReadAllAsync()) { ... }
```

**DN18** — Source Generators run at compile time to generate C# code, avoiding runtime reflection overhead. They differ from reflection (runtime) and IL weaving (post-compilation). An **incremental generator** (`IIncrementalGenerator`) caches intermediate results and only re-runs on changed inputs, making it faster than the older `ISourceGenerator`.

**DN19** — TPL Dataflow provides building blocks for concurrent pipelines. `ActionBlock<T>` processes each item, `TransformBlock<TIn,TOut>` transforms items, `BufferBlock<T>` buffers items. It supports parallelism, bounded capacity, and completion propagation. `System.Threading.Channels` is simpler and more lightweight for basic producer-consumer, but Dataflow offers more advanced constructs (e.g., `JoinBlock`, `BatchBlock`) for complex pipelines.

**DN20** — Minimal APIs use lambdas and top-level statements to define endpoints with less boilerplate. They differ from controllers by not having classes, attributes, or model binding. Trade-offs: Minimal APIs are less structured, harder to unit test (no classes), but support OpenAPI via `AddOpenApi()`. Route groups (`MapGroup`) allow shared prefixes/filters, and endpoint filters (`AddFilter`) provide cross-cutting concerns (e.g., validation) without middleware.

## Python

**P1** — A `list` is mutable and ordered; a `tuple` is immutable and ordered. A `set` is mutable, unordered, and contains unique elements; a `frozenset` is immutable and hashable (usable as a dict key).

**P2** — The GIL is a mutex in CPython that serializes execution of Python bytecode, preventing multiple threads from running CPU-bound code simultaneously. It affects CPU-bound multi-threaded programs. Workarounds: use `multiprocessing` (separate processes), use `asyncio` for I/O-bound tasks, or use C extensions that release the GIL.

**P3** — `copy.copy` creates a shallow copy (references to nested objects are shared). `copy.deepcopy` recursively copies all objects. Example: `a = [[1], [2]]; b = copy.copy(a); b[0].append(3)` modifies `a[0]` because the inner list is shared.

**P4** — Decorators are functions that wrap another function. Example:
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start}s")
        return result
    return wrapper
```

**P5** — Generators use `yield` to produce values lazily, one at a time, without storing the entire sequence in memory. They differ from returning a list by being memory-efficient and supporting infinite sequences. `yield from` delegates to another generator (e.g., `yield from gen2`).

**P6** — `asyncio.run()` creates and runs an event loop for a coroutine. `asyncio.gather()` runs multiple coroutines concurrently and waits for all. `asyncio.create_task()` schedules a coroutine as a task without blocking. `time.sleep()` blocks the event loop, preventing other tasks from running; use `await asyncio.sleep()` instead.

**P7** — Python 3 uses the **C3 linearization** algorithm for MRO. For diamond inheritance `D(B, C)` where `B` inherits `A` and `C` overrides `who()`, the MRO is `D -> B -> C -> A`. `D().who()` prints `"C"` because `C` overrides `A` and `B` does not override it, so `C` is found first.

**P8** — A metaclass is the class of a class, controlling class creation (e.g., registering classes, adding methods). `__init_subclass__` is a hook called when a subclass is created, simpler for subclass customization. Use a metaclass for complex class transformations (e.g., ORMs, abstract base classes); use `__init_subclass__` for simple hooks like auto-registration.

**P9** — `threading` is for I/O-bound tasks (GIL limits CPU-bound). `multiprocessing` uses separate processes for CPU-bound tasks (bypasses GIL). `concurrent.futures` provides a high-level interface (`ThreadPoolExecutor`, `ProcessPoolExecutor`). Multiprocessing requires pickling arguments and return values, which can fail for non-picklable objects (e.g., lambdas, locks).

**P10** — `__slots__` prevents the creation of a `__dict__` per instance, saving memory. Use it for classes with many instances and fixed attributes. It prevents adding new attributes dynamically and requires `__slots__` in subclasses to avoid `__dict__`.

**P11** — A virtual environment isolates Python dependencies for a project. `venv` is built-in and minimal; `virtualenv` is third-party with more features (faster, supports older Python); `conda` is a package manager and environment manager that can install non-Python dependencies.

**P12** — List/dict/set comprehensions are concise, readable ways to build collections: `[x for x in range(10)]`, `{k: v for ...}`, `{x for x in ...}`. `map()` and `filter()` are functional alternatives. Prefer comprehensions for readability and performance; use `map`/`filter` when you have a callable and want a lazy iterator.

**P13** — `==` compares value equality; `is` compares object identity (memory address). Object interning caches small integers (-5 to 256) and some strings, so `a is b` can return `True` for these immutable objects because they are reused.

**P14** — `*args` collects extra positional arguments into a tuple; `**kwargs` collects extra keyword arguments into a dict. Positional-only parameters are defined before `/` (e.g., `def f(a, /, b)`), keyword-only after `*` (e.g., `def f(a, *, b)`).

**P15** — Context managers use the `with` statement to set up and tear down resources. Implement with `__enter__`/`__exit__` or the `@contextmanager` decorator (generator-based). Example beyond files: `with threading.Lock():` or a custom timer:
```python
@contextmanager
def timer():
    start = time.time()
    yield
    print(f"Elapsed: {time.time()-start}")
```

**P16** — Type hinting annotates function signatures. `Union[int, str]`, `Optional[int]` (same as `Union[int, None]`), `Literal["a", "b"]`, `TypeVar("T")` for generics, and `Protocol` for structural typing. Tools like mypy/pyright use these to statically check types, catch errors, and infer types.

**P17** — Dunder methods define Python's data model. `__repr__` is for debugging (unambiguous), `__str__` for display (readable). `__eq__` defines equality; if you define `__eq__` without `__hash__`, Python sets `__hash__` to `None`, making the object unhashable. `__getattr__` is called when an attribute is not found; `__getattribute__` is called for every attribute access.

**P18** — Descriptors implement `__get__`, `__set__`, `__delete__` to control attribute access. `property` is a descriptor that calls getter/setter methods. `classmethod` and `staticmethod` are descriptors that bind the method to the class or ignore the instance, respectively.

**P19** — The import system uses finders to locate modules (via `sys.path`, `PYTHONPATH`) and loaders to execute them. Relative imports (`.module`) are within a package; absolute imports (`package.module`) are from `sys.path`. `__init__.py` marks a directory as a package. Namespace packages allow packages without `__init__.py`. A finder returns a module spec; a loader executes the module.

**P20** — `dataclasses` generates `__init__`, `__repr__`, `__eq__`, etc. `attrs` is a third-party library with more features (validators, converters). `Pydantic` adds runtime validation, serialization, and JSON schema. `__post_init__` runs after `__init__` for custom logic. `field(default_factory=list)` avoids mutable defaults. `frozen=True` makes instances immutable. Dataclasses handle inheritance by merging fields. Choose Pydantic for data validation and API schemas; dataclasses for simple containers.
