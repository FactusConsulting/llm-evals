## Go

**G1** — **Array** has a fixed size defined at compile time; **Slice** is a dynamic window into an array (containing a pointer, length, and capacity). When a slice reaches capacity, `append` allocates a new, larger underlying array, copies existing elements, and returns a new slice header.

**G2** — `var x int` declares a variable with its zero value (0); `x := 0` is short-hand declaration and initialization. `:=` cannot be used at the package level (global scope) or when redeclaring a variable without at least one new variable on the left side.

**G3** — A **goroutine** is a lightweight thread managed by the Go runtime, not the OS. OS threads have large stacks (~2MB); goroutines start small (~2KB). The **GMP model** consists of **G** (Goroutine), **M** (OS Thread/Machine), and **P** (Processor/Logical Context). P schedules Gs onto Ms to maximize CPU utilization and handle blocking syscalls.

**G4** — Channels are typed conduits for communication. **Unbuffered** channels require a sender and receiver to be ready simultaneously (rendezvous). **Buffered** channels allow sending without a receiver until the buffer is full. Sending to a full buffered channel blocks the goroutine until space is available.

**G5** — `context` manages cancellation, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

**G6** — Go uses **structural typing** (implicit satisfaction); if a type implements the methods of an interface, it satisfies it without an explicit `implements` keyword. `interface{}` (or `any`) can hold any value. It is powerful for generic-like behavior but dangerous because it bypasses compile-time type safety, requiring runtime type assertions.

**G7** — This is a **data race**. Go does not guarantee that changes to `ready` in one goroutine are immediately visible to another without synchronization. The loop may run forever or read `data` before it is initialized. **Fix:** Use `sync.Mutex`, `sync.WaitGroup`, or a channel to signal completion.

**G8** — `sync.Mutex` is exclusive; `sync.RWMutex` allows multiple concurrent readers OR one writer. `sync.Map` is optimized for cases where keys are stable and reads heavily outweigh writes, or when multiple goroutines read/write disjoint sets of keys. Regular maps with a mutex are generally faster for most common use cases.

**G9** — `go.mod` defines the module path and dependency versions; `go.sum` contains cryptographic checksums for reproducibility. `go mod tidy` removes unused dependencies and adds missing ones. **MVS** selects the *minimum* version of a dependency that satisfies all constraints in the dependency graph.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO** (Last-In, First-Out) order. **Gotcha:** Defers inside a loop do not execute until the function exits, which can lead to resource exhaustion (e.g., open file descriptors).

**G11** — A pointer is a variable that stores the memory address of another value. The zero value is `nil`. Create a pointer to a struct literal using the address-of operator: `p := &User{Name: "Alice"}`.

**G12** — `init()` runs before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the files, and packages are initialized in dependency order.

**G13** — `new(T)` allocates zeroed memory for a type and returns a pointer `*T`. `make` is used only for **slices, maps, and channels**, initializing their internal data structures and returning the initialized value (not a pointer).

**G14** — Go uses explicit return values for errors. The `error` interface is any type with an `Error() string` method. `errors.Is` checks if an error wraps a specific sentinel error; `errors.As` checks if an error is of a specific type. `==` only works for non-wrapped sentinel errors.

**G15** — **Map**: `nil`; **Slice**: `nil`; **Channel**: `nil`; **Struct**: all fields set to their respective zero values.

**G16** — A race condition occurs when two goroutines access the same memory concurrently and at least one access is a write. `-race` is a runtime detector that flags these.
*Fix:* Use `sync.Mutex`: `mu.Lock(); count++; mu.Unlock()`.

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, it blocks until one of its cases can proceed. If multiple are ready, one is chosen pseudo-randomly. Timeout: `case <-time.After(1 * time.Second):`.

**G18** — **Escape Analysis** determines if a variable can stay on the stack or must "escape" to the heap. If a pointer to a local variable is returned or shared, it moves to the heap. Inspect via `go build -gcflags="-m"`. Heap allocation increases GC pressure and reduces performance.

**G19** — `reflect.Type` represents the static type; `reflect.Value` represents the dynamic value. Reflection is slow due to runtime type checking and boxing. It is justified for generic libraries (e.g., `json.Marshal`) where types are unknown at compile time; otherwise, code generation is preferred.

**G20** — `go:embed` allows embedding files/folders into the binary at compile time. It uses `embed.FS` to provide a read-only virtual filesystem. It is limited to static files and interacts with `io/fs.FS` to allow the same code to read from either the embedded binary or the disk.

## Rust

**R1** — **Ownership** ensures memory safety without a GC. Rules: 1. Each value has a variable called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable string. `&str` is an immutable slice (reference) to a string. Use `&str` in function signatures for flexibility (accepts both `String` and `&str`).

**R3** — Borrowing allows access without taking ownership. **Shared references** (`&T`) allow multiple readers. **Mutable references** (`&mut T`) allow one writer. You cannot have a mutable reference while any other reference (shared or mutable) exists.

**R4** — `Result<T, E>` handles recoverable errors (`Ok`/`Err`); `Option<T>` handles presence/absence (`Some`/`None`). The `?` operator unwraps `Ok`/`Some` or returns the error/None early.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path) // returns Result
}
```

**R5** — `Box<T>`: Single ownership, heap allocation. `Rc<T>`: Reference counted, single-threaded shared ownership. `Arc<T>`: Atomic reference counted, thread-safe shared ownership.

**R6** — **Traits** define shared behavior. Go interfaces are implicit; Rust traits are explicit. `T: Trait` (Generics) uses **static dispatch** (monomorphization). `dyn Trait` (Trait Objects) uses **dynamic dispatch** via a vtable.

**R7** — The compiler doesn't know which reference (`x` or `y`) the return value refers to. **Fix:** Add lifetime annotations to tell the compiler the return value lives as long as the inputs:
`fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { ... }`

**R8** — `Send` allows transferring ownership between threads; `Sync` allows sharing references between threads. `Rc<T>` is not `Send` because its reference counter is not atomic. `Arc<T>` uses atomic operations for the counter, making it safe for concurrent use.

**R9** — `async` functions return a `Future`, which is a state machine. The **executor** (e.g., Tokio) polls the `Future` until it is complete. Go's goroutines are managed by a built-in runtime scheduler; Rust's async is "lazy" and requires a library-provided executor.

**R10** — `unsafe` allows bypassing the borrow checker. You can: 1. Dereference raw pointers, 2. Call unsafe functions, 3. Access/mutate static mutable variables. It is justified for FFI, low-level hardware access, or extreme performance optimizations.

**R11** — `match` is an exhaustive pattern matcher; the compiler forces you to handle all possible cases. `if let` is syntactic sugar for matching a single pattern and ignoring the rest.

**R12** — `Vec<T>` is a heap-allocated dynamic array; `[T; N]` is a fixed-size stack array. When a `Vec` exceeds capacity, it reallocates a larger block of memory (usually doubling) and copies elements.

**R13** — Rust enums are **Algebraic Data Types**; they can hold data (e.g., `Option<T>` is `Some(T)` or `None`). This eliminates `null` and forces the developer to handle the "absent" case explicitly.

**R14** — `impl` blocks define methods. `&self` is an immutable borrow, `&mut self` is a mutable borrow, and `self` consumes the object. Associated functions (e.g., `String::new()`) do not take `self` and are called on the type itself.

**R15** — `derive` automatically implements traits. Common: `Debug` (printing), `Clone` (duplication), `PartialEq` (comparison). You cannot derive a trait if any field in the struct does not implement that trait.

**R16** — `Cow` (Clone-on-Write) allows a value to be either borrowed or owned. It avoids allocation by using the borrowed version until mutation is required, at which point it clones the data into an owned `String` or `Vec`.

**R17** — `mod` declares a module, `use` brings paths into scope, and `pub` controls visibility. In Rust 2018+, modules map directly to the file system (e.g., `mod a` looks for `a.rs` or `a/mod.rs`), and absolute paths (`crate::...`) were introduced.

**R18** — `Pin<T>` prevents a value from being moved in memory. This is critical for **self-referential structs** (where a field points to another field in the same struct), which are common in `async` state machines. `Unpin` is a marker trait for types that are safe to move.

**R19** — `macro_rules!` (declarative) uses pattern matching to expand code. Procedural macros (derive, attribute, function-like) are Rust functions that manipulate the AST. **Hygiene** ensures macros don't accidentally capture variables from the surrounding scope.

**R20** — Zero-cost abstractions mean you don't pay for what you don't use. **Monomorphization** generates a specialized version of a generic function for every concrete type used, allowing the compiler to inline and optimize as if the code were written specifically for that type.
