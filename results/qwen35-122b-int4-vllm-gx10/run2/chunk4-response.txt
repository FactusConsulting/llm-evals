

## Go (20 questions)

**G1 — Easy:**
An **array** has a fixed length defined at compile time and is a value type (copying copies the whole array). A **slice** is a dynamic view over an array, containing a pointer, length, and capacity. When appending to a slice that exceeds its capacity, Go allocates a new, larger underlying array, copies the data, and updates the slice header to point to the new array.

**G2 — Easy:**
`var x int` explicitly declares a variable with a type. `x := 0` is a short variable declaration that infers the type from the value. You **cannot** use `:=` at the package level (outside functions) or if the variable already exists in the current scope (unless at least one variable on the left is new).

**G3 — Medium:**
A **goroutine** is a lightweight thread managed by the Go runtime, not the OS. It has a small initial stack (2KB) that grows dynamically. The **GMP model** schedules goroutines (G) onto OS threads (M) via logical processors (P). The scheduler multiplexes many Gs onto fewer Ms, allowing efficient concurrency without OS thread overhead.

**G4 — Medium:**
Channels are typed conduits for communication between goroutines. An **unbuffered channel** blocks the sender until a receiver is ready (synchronous). A **buffered channel** holds a queue of values; sending blocks only when the buffer is full. Sending to a full buffered channel blocks the sender until space opens.

**G5 — Medium:**
The **context** package carries deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
client.Do(req) // Cancels if > 5s
```

**G6 — Medium:**
Go uses **implicit interface satisfaction**: a type implements an interface if it has the required methods (duck typing). Java/C# require explicit `implements`. The **empty interface** (`interface{}` or `any`) accepts any type. It is powerful for generic containers but dangerous because it bypasses compile-time type checking, requiring runtime type assertions.

**G7 — Hard:**
This is unsafe due to the **Go Memory Model**. There is no "happens-before" guarantee between the write to `data` and `ready` without synchronization. The compiler/CPU may reorder instructions, or the reading goroutine may see `ready=true` before `data="hello"`.
**Fix:** Use `sync/atomic` for `ready`, a `sync.Mutex`, or a channel to signal completion.

**G8 — Hard:**
`sync.Mutex` allows exclusive access. `sync.RWMutex` allows multiple readers or one writer. Use `sync.Map` for high-contention, read-heavy maps where keys are disjoint; otherwise, a regular `map` with a `Mutex` is faster and simpler. `sync.Map` avoids locking overhead for reads but has higher memory overhead and complexity.

**G9 — Medium:**
Go modules manage dependencies. `go.mod` declares requirements and versions. `go.sum` stores cryptographic checksums for integrity. `go mod tidy` adds missing requirements and removes unused ones. **MVS (Minimum Version Selection)** selects the lowest version of a dependency that satisfies all requirements in the dependency graph to ensure reproducibility.

**G10 — Medium:**
`defer` schedules a function call to run when the surrounding function returns. Multiple defers execute in **LIFO** (Last In, First Out) order. **Gotcha:** In a loop, `defer` captures the loop variable by reference, often causing all defers to use the final value. Fix by passing the variable as an argument to an anonymous function.

**G11 — Easy:**
A **pointer** holds the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: value}`.

**G12 — Easy:**
`init()` is a special function for package initialization. It runs automatically before `main()` starts. A package can have multiple `init()` functions; they execute in declaration order within the package. Packages are initialized in dependency order.

**G13 — Easy:**
`new(T)` allocates zeroed memory for type `T` and returns a pointer `*T`. `make(T, ...)` initializes slices, maps, or channels and returns the value `T` (not a pointer). `new` works with any type; `make` works only with reference types.

**G14 — Easy:**
Go uses explicit error handling. The `error` interface requires an `Error() string` method. Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error matches a target (handling wrapped errors). `errors.As` extracts a specific error type from a wrapped chain. `==` only checks exact equality.

**G15 — Easy:**
Composite types: **Map** (nil), **Slice** (nil), **Channel** (nil), **Struct** (zero values of fields). Note: nil slices/maps/channels are valid but empty; operations on them may panic (e.g., writing to nil channel).

**G16 — Medium:**
A **race condition** occurs when multiple goroutines access shared memory concurrently, and at least one writes. The `-race` flag uses dynamic instrumentation to detect data races at runtime.
**Fix:** Protect shared state with `sync.Mutex` or use channels to serialize access.

**G17 — Medium:**
`select` waits on multiple channel operations. Unlike `switch`, it operates on channels. If multiple cases are ready, one is chosen **pseudo-randomly**. To implement a timeout: `case <-time.After(d):`.

**G18 — Hard:**
**Escape analysis** determines if a variable can live on the stack or must "escape" to the heap. The compiler decides based on scope and usage (e.g., returning a pointer to a local variable forces heap allocation). Inspect with `go build -gcflags="-m"`. Heap allocation increases GC pressure; stack allocation is faster.

**G19 — Hard:**
`reflect` allows runtime type inspection. `reflect.Type` describes the type; `reflect.Value` holds the data. Reflection is slow due to dynamic dispatch and boxing. It is justified for generic libraries (pre-Go 1.18) or serialization; otherwise, code generation (e.g., `go generate`) is preferred for performance.

**G20 — Hard:**
`go:embed` embeds files into the binary at compile time. It supports single files, directories, and patterns. It implements `io/fs.FS`. **Limitations:** Files must exist at build time; paths are relative to the package; cannot embed dynamic content.

## Rust (20 questions)

**R1 — Easy:**
**Ownership** ensures memory safety without garbage collection. Rules: 1. Each value has one owner. 2. When the owner goes out of scope, the value is dropped. 3. Values can be moved or borrowed, but not copied (unless `Copy` trait is implemented).

**R2 — Easy:**
`String` is an owned, growable, heap-allocated string. `&str` is an immutable borrowed view (slice) of UTF-8 data. Use `&str` for function inputs (flexible, no allocation) and `String` for outputs or when ownership is required.

**R3 — Medium:**
**Borrowing** allows referencing data without taking ownership. Rules: You can have either one mutable reference (`&mut T`) OR any number of immutable references (`&T`), but not both simultaneously. The **borrow checker** enforces this at compile time to prevent data races.

**R4 — Medium:**
`Result<T, E>` handles recoverable errors; `Option<T>` handles absence of value. The `?` operator propagates errors/None up the call stack.
```rust
fn read_file(path: &str) -> Result<String, io::Error> {
    fs::read_to_string(path)
}
```

**R5 — Medium:**
`Box<T>`: Heap allocation, single owner. `Rc<T>`: Reference counting, single-threaded shared ownership. `Arc<T>`: Atomic reference counting, thread-safe shared ownership. Use `Box` for heap data, `Rc` for graph structures in single threads, `Arc` for shared state across threads.

**R6 — Medium:**
**Traits** define shared behavior (similar to interfaces). Go interfaces are implicit; Rust traits require explicit `impl`. A **trait object** (`dyn Trait`) uses dynamic dispatch (vtable). A **generic** (`T: Trait`) uses static dispatch (monomorphization), usually faster.

**R7 — Hard:**
It fails because the compiler cannot infer which reference (`x` or `y`) the return value borrows from. Both inputs must share a lifetime.
**Fix:**
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8 — Hard:**
`Send` indicates a type can be transferred across threads. `Sync` indicates `&T` can be shared across threads. `Rc<T>` is not `Send` because reference counting is not atomic. `Arc<T>` uses atomic operations, making it `Send` and `Sync`.

**R9 — Medium:**
Rust `async/await` compiles to state machines. A **Future** is a lazy computation that produces a value. An **executor** (e.g., Tokio) polls futures to completion. Unlike Go's preemptive goroutines, Rust async is cooperative; tasks yield control explicitly via `.await`.

**R10 — Medium:**
`unsafe` bypasses borrow checker and type safety. 3 things: 1. Dereference raw pointers. 2. Call unsafe functions. 3. Access mutable static variables. Justified for FFI, low-level hardware access, or implementing safe abstractions over unsafe primitives.

**R11 — Easy:**
**Pattern matching** deconstructs values. `match` requires **exhaustiveness** (all cases covered). `if let` handles a single pattern. `match` is more powerful for multiple branches and guards.

**R12 — Easy:**
`Vec<T>` is a growable array on the heap. `[T; N]` is a fixed-size array on the stack. When `Vec` exceeds capacity, it allocates a new larger block (usually 2x), copies elements, and frees the old block.

**R13 — Easy:**
Rust **enums** can hold data (sum types), unlike C/Java enums which are just integers. `Option<T>` is an enum (`Some(T)` | `None`) that replaces null, forcing explicit handling of absence.

**R14 — Easy:**
`impl` defines methods. `&self` borrows immutably, `&mut self` borrows mutably, `self` consumes ownership. **Associated functions** (like `String::new()`) do not take `self` and are called on the type itself.

**R15 — Easy:**
The `derive` macro automatically implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. You **cannot** derive traits that require custom logic (e.g., `Drop`, `Deref`) or where the default implementation is unsafe/incorrect.

**R16 — Medium:**
`Cow<'a, T>` (Clone on Write) holds either a borrowed reference or an owned value. It avoids cloning if no mutation occurs. Useful for functions that might modify a string but often don't, saving allocation overhead.

**R17 — Medium:**
`mod` declares a module. `pub` makes items public. `use` brings items into scope. In 2018 edition, `mod.rs` is optional (file name matches module name), and path resolution is more intuitive (relative to crate root).

**R18 — Hard:**
`Pin<T>` prevents a value from being moved in memory. Needed for **self-referential structs** and `async` tasks where pointers to internal fields must remain valid. `Unpin` indicates a type is safe to move (most types implement this automatically).

**R19 — Hard:**
**Declarative macros** (`macro_rules!`) are pattern-based templates. **Procedural macros** (derive, attribute, function-like) generate code via Rust AST manipulation. **Hygiene** ensures macro variables don't accidentally capture or conflict with surrounding scope variables.

**R20 — Hard:**
**Zero-cost abstractions** mean high-level features compile to code as efficient as hand-written C. **Iterators** are inlined. **Generics** are monomorphized (specialized per type). **Traits** use static dispatch when possible. No runtime overhead for abstraction layers.
