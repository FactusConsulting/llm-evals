

## JavaScript / TypeScript

**JS1 — Easy:**
`var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but in the "Temporal Dead Zone" (cannot access before declaration). `const` requires initialization and prevents reassignment of the binding (not the value). Hoisting is the JS engine moving declarations to the top of their scope during compilation.

**JS2 — Easy:**
The event loop manages execution. The **Call Stack** executes synchronous code. **Microtask Queue** (Promises, `queueMicrotask`) runs after the stack clears but before rendering. **Macrotask Queue** (setTimeout, I/O) runs after microtasks. Order: Stack → Microtasks → Render → Macrotasks.

**JS3 — Medium:**
A closure is a function bundled with its lexical environment.
*Example:* `function makeAdder(x) { return function(y) { return x + y; }; }`
*Bug:* Loop closures capture the same variable reference.
*Fix:* Use `let` in the loop (block scope) or an IIFE to create a new scope per iteration.

**JS4 — Medium:**
Promises represent async operations. `async/await` is syntactic sugar over Promises. Errors in Promises use `.catch()`; in `async/await`, use `try/catch`. `Promise.all()` fails fast on the first rejection. `Promise.allSettled()` waits for all to finish, returning status (fulfilled/rejected) for each.

**JS5 — Medium:**
`interface` is for defining object shapes (extends well, open for merging). `type` is for unions, primitives, and tuples. Use `interface` for public API shapes, `type` for complex unions. Discriminated unions use a literal property (tag) to narrow types (e.g., `{ type: 'success', data } | { type: 'error', msg }`).

**JS6 — Medium:**
JS uses prototypal inheritance: objects link to other objects via `[[Prototype]]`. `Object.create(proto)` creates an object with `proto` as its prototype. ES6 `class` is syntactic sugar over prototypes; `extends` sets up the prototype chain, `super` calls the parent constructor.

**JS7 — Hard:**
`this` refers to the execution context. Binding rules (priority): 1. `new` binding (instance), 2. Explicit binding (`call`, `apply`, `bind`), 3. Implicit binding (object method), 4. Default binding (global/undefined). `bind()` returns a new function with `this` permanently bound; it cannot be re-bound.

**JS8 — Hard:**
`WeakRef` holds a weak reference to an object (allows GC). `FinalizationRegistry` runs a callback when a registered object is garbage collected. `WeakMap` keys must be objects because primitives cannot be weakly referenced (they are values, not references). This prevents memory leaks by allowing keys to be GC'd.

**JS9 — Hard:**
V8 uses **Hidden Classes** (maps) for property access optimization. **Inline Caching** caches the location of properties based on hidden classes. **Deoptimization** occurs when assumptions break (e.g., adding properties to an object after optimization). Patterns causing deopt: dynamic property addition, `arguments` object usage, mixing types in arrays.

**JS10 — Medium:**
Tree-shaking removes unused code. It works with ES Modules (static `import`/`export` allows static analysis). CommonJS (`require`) is dynamic and evaluated at runtime, making static analysis impossible for most bundlers, preventing effective tree-shaking.

**JS11 — Easy:**
`null` is an assignment value (no value). `undefined` means uninitialized. `null == undefined` is true; `null === undefined` is false. `??` (nullish coalescing) returns the right side if left is `null` or `undefined`. `?.` (optional chaining) safely accesses nested properties without throwing if intermediate is nullish.

**JS12 — Easy:**
`map()` transforms elements. `filter()` selects elements. `reduce()` accumulates values (requires initial value for empty arrays to avoid undefined). `flatMap()` maps then flattens one level; useful for transforming arrays into nested arrays and flattening them in one pass.

**JS13 — Easy:**
Template literals use backticks (`` ` ``) for multiline strings and interpolation (`${}`). Tagged templates pass raw strings and values to a function. *Example:* `html\`<div>${user}</div>\`` where the tag function escapes HTML to prevent XSS.

**JS14 — Easy:**
Destructuring extracts values from arrays/objects. `const { a, b } = obj` or `const [x, y] = arr`. Defaults: `const { a = 1 } = obj`. Renaming: `const { a: alias } = obj`. Rest operator `...` collects remaining properties/elements into a new object/array.

**JS15 — Easy:**
`for...in` iterates over enumerable *keys* (including prototype chain). `for...of` iterates over iterable *values* (strings, arrays, maps). Avoid `for...in` on arrays because it iterates indices as strings and includes inherited properties; use `for...of` or standard loops.

**JS16 — Medium:**
Generics allow reusable components with flexible types. Constraints: `T extends string`. Conditional types: `T extends U ? X : Y` (if T is U, return X, else Y). `infer` extracts types within conditional types (e.g., `infer R` in `Promise<R>`). *Example:* `type Unwrap<T> = T extends Promise<infer R> ? R : T;`

**JS17 — Medium:**
CommonJS (`require`/`module.exports`) is synchronous and dynamic. ES Modules (`import`/`export`) are asynchronous, static, and support tree-shaking. Node.js supports both; `"type": "module"` in `package.json` treats `.js` files as ESM. Without it, `.js` defaults to CJS.

**JS18 — Hard:**
TypeScript uses structural typing (duck typing). Excess property checks apply to object literals assigned to variables (prevents typos). `extends` checks assignability; `satisfies` checks assignability without widening the type (preserves literal types). Variance (`in`/`out`) controls how generic types relate to subtyping (covariant/contravariant).

**JS19 — Hard:**
`Proxy` intercepts operations (get, set, has, etc.). `Reflect` provides default behavior for these operations. *Example:* A reactive store uses a Proxy to track dependencies on `get` and trigger updates on `set`. `Reflect.get(target, key)` is used inside the handler to maintain default behavior.

**JS20 — Hard:**
`SharedArrayBuffer` allows shared memory between Web Workers. `Atomics` provides atomic operations (load, store, add, wait, notify) to prevent race conditions. `Atomics.wait` blocks a worker until notified; `Atomics.notify` wakes waiting workers. Guarantees sequential consistency for atomic operations.

## Bash

**B1 — Easy:**
`$@` expands to separate quoted arguments; `$*` expands to a single string. `"$@"` preserves argument boundaries (safe for loops). `"$*"` joins them with the first character of IFS (usually space). Always use `"$@"` for argument passing.

**B2 — Easy:**
`set -e`: Exit on error. `-u`: Error on undefined variables. `-o pipefail`: Pipeline fails if any command fails (not just the last). Essential for robust scripting.

**B3 — Medium:**
`$(command)` is modern command substitution (nestable, readable). `` `command` `` is legacy. `$((expression))` is arithmetic expansion. `expr` is an external command (slower, legacy). Prefer `$(( ))` for math.

**B4 — Medium:**
Process substitution `<(cmd)` creates a named pipe (e.g., `/dev/fd/63`) appearing as a file. *Example:* `diff <(sort file1) <(sort file2)` compares sorted outputs without creating temp files.

**B5 — Medium:**
`for f in $(ls)` breaks on spaces/newlines. Use `while IFS= read -r -d '' file; do ... done < <(find . -print0)` or `find ... -exec`. `ls` is for humans; `find` is for scripts.

**B6 — Medium:**
Here-doc (`<<EOF`) reads multiple lines until EOF. Here-string (`<<<`) passes a single string to stdin. `<<-EOF` allows leading tabs to be stripped (indentation friendly).

**B7 — Hard:**
1. `cmd > file 2>&1`: Stdout to file, then stderr to stdout (file). Both to file.
2. `cmd 2>&1 > file`: Stderr to stdout (terminal), then stdout to file. Stdout to file, stderr to terminal.
3. `cmd &> file`: Shorthand for both to file.
Order matters because redirections are processed left-to-right.

**B8 — Hard:**
```bash
lock_file="/tmp/my.lock"
mkdir "$lock_file" && trap 'rmdir "$lock_file"' EXIT
# Do work
```
`mkdir` is atomic on POSIX (fails if exists). `trap` ensures cleanup on exit/SIGTERM. Avoid `touch` + `flock` for simple locking if `mkdir` suffices.

**B9 — Easy:**
Single quotes (`'`) preserve literal strings (no expansion). Double quotes (`"`) allow variable/command expansion. No quotes splits on whitespace. *Example:* `echo $var` (expands), `echo '$var'` (literal), `echo $var` (splits if spaces).

**B10 — Easy:**
`[ -f file ]` (file), `[ -d dir ]` (directory), `[ -r file ]` (readable). `[[ ]]` is a bash keyword (safer, supports `&&`, `||`, pattern matching). `[ ]` is the `test` command (POSIX compatible).

**B11 — Easy:**
`$?`: Exit status of last command. `$$`: Current PID. `$!`: PID of last background job. `$#`: Number of arguments. *Use:* Check `$?` for errors, log `$$` for unique IDs.

**B12 — Easy:**
Define: `foo() { ... }` or `function foo { ... }`. Return values: Use `exit code` (`return 0`) or `echo` (capture via `$(foo)`). Bash functions cannot return data directly like other languages.

**B13 — Easy:**
`PATH` is a colon-separated list of directories searched for executables. Bash checks builtins first, then PATH. `type cmd` shows if it's a builtin, function, or file. `which cmd` finds the path.

**B14 — Medium:**
`trap 'cmd' SIGNAL`. `EXIT` runs on script end. `ERR` runs on error (bash 4+). `INT` (Ctrl+C), `TERM` (kill). Order: Signal handler runs, then script exits. Multiple traps for same signal overwrite previous.

**B15 — Medium:**
`xargs` builds command lines from stdin. `command substitution` captures output. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P N` runs N jobs in parallel.

**B16 — Medium:**
Indexed: `arr=(a b)`, `arr+=("c")`, `${#arr[@]}`. Associative: `declare -A map`, `map[key]=val`. Iterate: `for k in "${!map[@]}"; do`. Associative arrays require `declare -A`.

**B17 — Hard:**
Subshell `(...)` runs in a child process (variables lost). Group `{ ...; }` runs in current shell (variables persist). Piping `cmd | while` creates a subshell for the loop, losing variable changes. Use process substitution `while ... < <(cmd)` to fix.

**B18 — Hard:**
`SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (terminal hangup), `SIGKILL` (force kill, uncatchable). Handle graceful shutdown with `trap 'cleanup' TERM INT`. Wait for background jobs (`wait`) before exiting.

**B19 — Hard:**
```bash
split -l 1000 log.txt log_part_
for f in log_part_*; do
  (process "$f" > "${f}.out") &
done
wait
cat log_part_*.out > final.log
```
Trade-off: Parallelism vs I/O contention. Check exit codes in `wait` loop or use `set -o pipefail` with `xargs -P`.

**B20 — Hard:**
`exec` replaces the current shell process (no return). `exec 3>file` opens FD 3. `exec 3>&-` closes it. Coprocess: `coproc cmd` creates a background process with FDs for stdin/stdout. Useful for interactive CLI tools.

## PowerShell

**PS1 — Easy:**
`Write-Output` sends to pipeline (can be captured). `Write-Host` writes to console host (cannot be captured). Use `Write-Output` for functions/scripts; `Write-Host` only for user-facing logs.

**PS2 — Easy:**
Pipeline passes objects. `ForEach-Object` is a cmdlet (processes one by one, slower). `foreach` is a language statement (loops array in memory, faster). Use `foreach` for in-memory arrays, `ForEach-Object` for streaming pipelines.

**PS3 — Medium:**
`[hashtable]` (`@{}`) is key-value, unordered. `[PSCustomObject]` (`[pscustomobject]@{}`) is ordered, supports type hints, better for output. Convert: `New-Object PSObject -Property $hash`. Use hashtable for config, PSCustomObject for data objects.

**PS4 — Medium:**
Terminating errors stop execution (use `throw` or `-ErrorAction Stop`). Non-terminating continue (default). `-ErrorAction` overrides per cmdlet. `$ErrorActionPreference` sets global default. `try/catch` handles terminating errors.

**PS5 — Medium:**
Splatting passes a hashtable as parameters: `@params`. `Get-Command @params`. Differs from passing hashtable as a single argument (which binds to the first parameter). Useful for dynamic parameter lists.

**PS6 — Medium:**
`Invoke-Command` runs remotely (one-off). `Enter-PSSession` opens interactive shell. Uses WinRM (HTTP/HTTPS) or SSH. WinRM is default on Windows; SSH is cross-platform (PS 7+).

**PS7 — Hard:**
PowerShell unwraps arrays returned from functions. If `$result` has 1 item, `$x` is that item. If 0 items, `$x` is `$null`. Correct pattern: `return @( ... )` to force array return. `GetType().Name` will be `Object[]` or `String` depending on count.

**PS8 — Hard:**
`[scriptblock]` is code without a name. Functions are named scriptblocks. Pass scriptblocks via `-ScriptBlock` or `-ArgumentList`. Double-hop: Remote session cannot access credentials for a second hop. Solve with `CredSSP` or `RunAs` with stored credentials.

**PS9 — Easy:**
`@()` forces array context. `[array]` is a type cast. `$null` indexed returns `$null`. Empty array indexed returns `$null`. Force array: `$x = @($result)`.

**PS10 — Easy:**
`-eq` (equals), `-like` (wildcard), `-match` (regex), `-contains` (collection check). Case-insensitive by default. `-ceq` is case-sensitive. `-contains` checks if collection has item; `-in` checks if item is in collection (reverse).

**PS11 — Easy:**
Module: Reusable code package. `.psm1` (script), `.psd1` (manifest), Binary (compiled). `Import-Module` loads them. Manifest defines exports, dependencies, version.

**PS12 — Easy:**
`"..."` interpolates variables (`$var`). `'...'` is literal. Expressions: `"${var}"` or `"$(cmd)"`. Here-string: `@" ... "@` for multiline strings with interpolation.

**PS13 — Easy:**
`Get-Member` (`gm`) lists properties/methods. Properties: Data. Methods: Actions. NoteProperties: Added dynamically. `Select-Object` picks properties. `Where-Object` filters objects.

**PS14 — Medium:**
Classes (v5+) define types. Similar to C# but limited (no multiple inheritance, limited interfaces). Use for complex data structures or stateful objects. Functions are better for stateless logic/cmdlets.

**PS15 — Medium:**
`[CmdletBinding()]` makes a function a cmdlet (supports `-Verbose`, `-Debug`). `SupportsShouldProcess` enables `-WhatIf`. `ValueFromPipeline` allows piping. `Begin/Process/End` blocks handle pipeline streaming.

**PS16 — Medium:**
Providers expose data stores as file systems. `Get-ChildItem` works on `FileSystem`, `Registry`, `Certificate`, `Env`. Access registry: `Get-ChildItem HKLM:\Software`.

**PS17 — Hard:**
Runspaces allow parallel execution. `[runspace]` is a session. `[runspacepool]` manages multiple. `ForEach-Object -Parallel` (v7+) uses runspaces internally. Manual runspace management offers more control but is complex.

**PS18 — Hard:**
PSScriptAnalyzer enforces standards (rules). Severity: Error, Warning, Info. Custom rules via script. Suppress with `# PSScriptAnalyzer: disable`. Integrates into CI via `Invoke-ScriptAnalyzer`.

**PS19 — Hard:**
`$using:` copies local variables to remote scope (serialized). `-ArgumentList` passes arguments to scriptblocks. Serialization limits: Complex objects may lose methods/properties (become PSObject). Depth limit applies to nested objects.

**PS20 — Hard:**
DSC configures systems declaratively. Configurations define resources. LCM applies config. Windows PowerShell uses MOF files. PS 7+ uses DSC v3 (JSON/YAML). Replaced in cloud by ARM/Bicep/Terraform, but DSC remains for on-prem/VM config.
