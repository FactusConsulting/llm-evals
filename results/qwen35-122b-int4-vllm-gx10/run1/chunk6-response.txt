

JS1 — **var, let, const & Hoisting**
`var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but reside in the Temporal Dead Zone (TDZ) until declaration. `const` requires initialization. Hoisting is the JS engine moving declarations to the top of their scope during compilation.

JS2 — **Event Loop**
The Event Loop monitors the Call Stack and Task Queues. When the stack is empty:
1.  **Microtask Queue** (Promises, `queueMicrotask`) is processed first.
2.  **Macrotask Queue** (`setTimeout`, I/O) is processed next.
This ensures microtasks run before the next render or macrotask.

JS3 — **Closures & Loop Bug**
A closure is a function bundled with its lexical environment.
*Bug:* `for (var i=0; i<3; i++) { setTimeout(() => console.log(i), 100); }` logs `3, 3, 3` because `var` is function-scoped.
*Fix:* Use `let` (block-scoped) or an IIFE to capture the current `i` value.

JS4 — **Promises & Error Handling**
`Promise` represents a future value. `async/await` is syntactic sugar for promises. Errors in `async` functions throw exceptions caught by `try/catch`. `Promise.all` fails fast on first rejection. `Promise.allSettled` waits for all to finish (success or failure) and returns status objects.

JS5 — **Interface vs Type & Discriminated Unions**
`interface` defines object shapes (mergeable, extends). `type` defines primitives, unions, intersections, and tuples. Use `interface` for public API shapes, `type` for complex unions. Discriminated unions use a literal property (tag) to narrow types (e.g., `{ type: 'a', val: string } | { type: 'b', val: number }`).

JS6 — **Prototypal Inheritance**
Objects delegate properties to a prototype chain. `Object.create(proto)` creates an object with `proto` as its `[[Prototype]]`. ES6 `class` is syntactic sugar over prototype manipulation; `extends` sets the prototype chain, `super` calls parent constructor.

JS7 — **`this` Binding Rules**
`this` depends on call context. Priority:
1.  **New Binding:** `new Func()` → new instance.
2.  **Explicit:** `call`, `apply`, `bind` → specified object.
3.  **Implicit:** `obj.method()` → `obj`.
4.  **Default:** `func()` → global/undefined (strict).
`bind()` returns a new function with `this` permanently bound. You can bind a bound function, but the first `this` is fixed.

JS8 — **WeakRef & FinalizationRegistry**
`WeakRef` holds a weak reference to an object, allowing GC. `FinalizationRegistry` registers callbacks to run after an object is GC'd. `WeakMap` keys must be objects because weak references only work on objects (primitives are copied). This prevents memory leaks from map keys.

JS9 — **V8 Optimization**
V8 uses JIT compilation. **Hidden Classes** optimize property access by tracking object shape. **Inline Caching** caches lookup results for specific shapes. **Deoptimization** occurs when assumptions break (e.g., adding properties dynamically, `eval`, `arguments` usage), reverting to slower code.

JS10 — **Tree-shaking**
Tree-shaking removes unused code. Works with **ES Modules** because imports are static (analyzable at build time). **CommonJS** uses dynamic `require()`, making static analysis impossible, so tree-shaking is ineffective without transpilation.

JS11 — **null, undefined & Operators**
`null` = intentional absence. `undefined` = uninitialized. `null == undefined` is true; `null === undefined` is false. `??` (Nullish Coalescing) returns RHS only if LHS is `null`/`undefined`. `?.` (Optional Chaining) safely accesses nested properties without throwing.

JS12 — **Array Methods**
`map()` transforms elements. `filter()` selects elements. `reduce()` accumulates values (requires initial value for empty arrays). `flatMap()` maps then flattens one level (useful for nested arrays).

JS13 — **Template Literals & Tagged Templates**
Backticks `` ` `` allow interpolation `${}`. Tagged templates call a function with raw strings and values: `tag`template`. Example: `sql`SELECT * FROM ${table}`` can sanitize inputs to prevent SQL injection.

JS14 — **Destructuring**
Extracts values from arrays/objects. `const { a, b } = obj`. `const [x, y] = arr`. Defaults: `const { a = 1 } = {}`. Renaming: `const { a: alias } = obj`. Rest: `const { ...rest } = obj`.

JS15 — **for...in vs for...of**
`for...in` iterates over enumerable **keys** (strings), including prototype chain. `for...of` iterates over **values** of iterable objects. Avoid `for...in` on arrays due to prototype pollution and non-numeric keys.

JS16 — **TypeScript Generics**
Generics allow reusable type parameters. `extends` constrains types (e.g., `T extends string`). Conditional types: `T extends U ? X : Y`. `infer` extracts types within conditional types (e.g., `infer R` in `Promise<R>`).

JS17 — **Module Systems**
**CommonJS:** `require()`/`module.exports`, dynamic, runtime resolution. **ES Modules:** `import`/`export`, static, compile-time analysis. Node.js supports both; `"type": "module"` in `package.json` treats `.js` as ESM.

JS18 — **Structural Typing & Variance**
TS uses structural typing (shape-based). **Excess Property Checks** apply to object literals assigned to types. `extends` checks assignability. `satisfies` checks type without widening the type. **Variance** (TS 4.7+) controls generic type compatibility (in/out).

JS19 — **Proxy & Reflect**
`Proxy` wraps an object to intercept operations (get, set, apply). `Reflect` provides default behavior for these operations. Example: `new Proxy(target, { get(t, k) { console.log(k); return t[k]; } })` for logging.

JS20 — **SharedArrayBuffer & Atomics**
`SharedArrayBuffer` allows shared memory between Web Workers. `Atomics` provides atomic read/write/compare-and-swap operations. `Atomics.wait` blocks a worker until notified; `Atomics.notify` wakes waiters. Requires specific security headers (COOP/COEP).

B1 — **$@ vs $***
`$@` expands to separate quoted arguments (`"$1" "$2"`). `$*` expands to a single string (`"$1 $2"`). `"$@"` preserves argument boundaries (spaces); `"$*"` joins them with IFS (default space).

B2 — **set -euo pipefail**
`-e`: Exit on error. `-u`: Error on unset variables. `-o pipefail`: Pipeline fails if any command fails (not just the last). Essential for robust scripting.

B3 — **Command Substitution & Arithmetic**
`$(cmd)` is modern, nestable, preferred. `` `cmd` `` is legacy. `$((expr))` is arithmetic expansion. `expr` is legacy external command. Use `$(( ))` for math.

B4 — **Process Substitution**
`<(cmd)` creates a named pipe (e.g., `/dev/fd/63`) appearing as a file. Useful for commands expecting filenames: `diff <(sort a) <(sort b)`.

B5 — **Safe File Iteration**
`for f in $(ls)` breaks on spaces/newlines. Use `for f in *` or `while IFS= read -r f; do ... done < <(find . -print0)`. `find -print0` + `read -d ''` handles special chars.

B6 — **Here Document vs String**
`<<EOF` (heredoc) feeds multi-line input to stdin. `<<<` (here string) feeds a single string. `<<-EOF` strips leading tabs (indentation) from the heredoc.

B7 — **Redirection Order**
`cmd > file 2>&1`: Stdout to file, then stderr to stdout (file).
`cmd 2>&1 > file`: Stderr to stdout (console), then stdout to file. Stderr goes to console.
`cmd &> file`: Both stdout and stderr to file (bash shorthand).

B8 — **Locking Function**
Use `mkdir` for locking (atomic).
```bash
lock() { mkdir "$1.lock" 2>/dev/null; }
unlock() { rmdir "$1.lock" 2>/dev/null; }
trap unlock EXIT
```
`mkdir` fails if dir exists (race condition safe). `trap` ensures cleanup on SIGTERM/EXIT.

B9 — **Quoting**
`'...'` literal (no expansion). `"..."` expands vars/commands. No quotes splits on whitespace/glob.
Example: `echo $var` (expands), `echo '$var'` (literal), `echo *` (glob).

B10 — **File Tests & [[ ]]**
`-f` (file), `-d` (dir), `-r` (readable). `[[ ]]` is a keyword (safer, supports `&&`, `||`, pattern matching). `[ ]` is a command (requires spaces, less safe).

B11 — **Special Variables**
`$?` last exit code. `$$` current PID. `$!` last background PID. `$#` argument count.
Use `$?` for error checks, `$$` for temp file names.

B12 — **Functions**
`function foo {}` or `foo() {}`. Return values via `exit code` (`return 0`) or `stdout` (`echo`). `echo` is preferred for data.

B13 — **PATH & Commands**
`PATH` is colon-separated list of dirs. Bash searches `PATH` for external commands. `type -a cmd` shows if builtin or external. `builtin cmd` forces builtin.

B14 — **trap**
`trap 'cmd' SIGNAL`. `EXIT` runs on script end. `ERR` on error (bash 4+). `INT` (Ctrl+C), `TERM` (kill). Order: Signal handler runs, then script exits.

B15 — **xargs**
`xargs` builds command lines from stdin. `find -print0 | xargs -0` handles spaces. `xargs -P N` runs N jobs in parallel. Better than `while read` for performance.

B16 — **Arrays**
Indexed: `arr=(a b)`, `arr+=("c")`, `${#arr[@]}`. Associative: `declare -A arr`, `arr[key]=val`. Iterate: `for k in "${!arr[@]}"`.

B17 — **Subshell vs Group**
`(...)` subshell (new PID, vars lost). `{ ...; }` group (same PID, vars persist). Piping `while` creates subshell, losing variable updates. Use process substitution `< <(cmd)` to fix.

B18 — **Signals & Job Control**
`SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (terminal close), `SIGKILL` (force). Handle `trap 'cleanup' TERM INT`. `wait` for background jobs to ensure graceful shutdown.

B19 — **Parallel Log Processing**
```bash
split -l 1000 log.txt part.
xargs -P 4 -I {} process {} < part.*
cat part.*.out > result.txt
```
Trade-off: Speed vs I/O overhead. Errors: Check exit codes of `xargs` or use `set -o pipefail`.

B20 — **exec & FD**
`exec` replaces current shell (no return). `exec 3>file` opens FD 3. `exec 3>&-` closes. Coprocess: `cmd |& cat` or `exec 3< <(cmd)`. Used for persistent bidirectional communication.

PS1 — **Write-Output vs Write-Host**
`Write-Output` sends to pipeline (can be captured). `Write-Host` writes directly to console (cannot be captured). Use `Write-Output` for scripting logic.

PS2 — **Pipeline & ForEach**
Pipeline streams objects. `ForEach-Object` (cmdlet) processes stream item-by-item (memory efficient). `foreach` (statement) loads entire collection into memory first. Use `ForEach-Object` for large data.

PS3 — **PSCustomObject vs Hashtable**
`[hashtable]` = key/value pairs (`@{}`). `[PSCustomObject]` = typed object (`[pscustomobject]@{}`). Convert: `[PSCustomObject]$ht`. Use Hashtable for config, PSCustomObject for output.

PS4 — **Error Handling**
Terminating errors stop execution (caught by `try/catch`). Non-terminating continue. `-ErrorAction Stop` forces termination. `$ErrorActionPreference` sets global default.

PS5 — **Splatting**
`@params` passes hashtable keys as named parameters. `cmd @params`. Differs from `cmd $params` (passes hashtable as single arg). Useful for dynamic parameter lists.

PS6 — **Remoting**
`Invoke-Command` runs cmd on remote. `Enter-PSSession` interactive shell. Uses WinRM (HTTP/HTTPS) or SSH. WinRM requires config; SSH works cross-platform.

PS7 — **Type System & Pipeline**
`$result += "one"` creates array. Returns array. If 0 items, returns `null` (unless initialized `@()`). Correct pattern: `return $result` ensures array type, or `Write-Output $result`.

PS8 — **ScriptBlock & Double-Hop**
`[scriptblock]` is code. Pass via `-ArgumentList`. Double-hop: Cred not forwarded to 3rd hop. Solve: `CredSSP` auth or `Invoke-Command` with `-Credential`.

PS9 — **@() vs [array]**
`@()` subexpression forces array (even if null). `[array]` casts. `$null[0]` throws. `(@($null))[0]` is safe. Use `@()` to ensure array context.

PS10 — **Comparison Operators**
`-eq` (equal), `-like` (wildcard), `-match` (regex). `-contains` (collection has item), `-in` (item in collection). Case-sensitive variants: `-ceq`, `-clike`.

PS11 — **Modules**
Module = package. `.psm1` (script), `.psd1` (manifest), `.dll` (binary). `Import-Module` loads. Manifest defines exports/dependencies.

PS12 — **String Interpolation**
`"..."` expands `$var`. `'...'` literal. `$()` for expressions. Here-string: `@" ... "@` for multi-line strings with interpolation.

PS13 — **Get-Member**
`Get-Member` (gm) inspects object. Properties (data), Methods (actions). `Select-Object` picks props. `Where-Object` filters objects.

PS14 — **PowerShell Classes**
v5+ classes. Similar to C# but limited (no multiple inheritance, limited constructors). Use for complex data structures or validation logic within modules.

PS15 — **CmdletBinding**
`[CmdletBinding()]` makes function advanced. Enables `-Verbose`, `-Debug`, `-WhatIf`. `SupportsShouldProcess` adds confirmation. `Begin/Process/End` blocks handle pipeline streaming.

PS16 — **Providers**
Providers expose data stores as drives (FileSystem, Registry, Cert). `Get-ChildItem HKLM:\Software`. `Set-Location` works across providers.

PS17 — **Runspaces & Parallel**
`[runspace]` = thread. `[runspacepool]` = pool. `ForEach-Object -Parallel` (v7+) uses runspaces internally. Manual runspace management allows finer control over concurrency.

PS18 — **PSScriptAnalyzer**
Static code analysis tool. Rules check best practices. Severity: Error, Warning, Info. Suppress with `# PSSA: disable`. Integrate into CI via `Invoke-ScriptAnalyzer`.

PS19 — **$using: & Serialization**
`$using:` copies local vars to remote scope. `-ArgumentList` passes args. Serialization (CLIXML) limits depth/complexity. Complex objects may lose methods or become generic.

PS20 — **DSC**
Desired State Configuration. Configurations define resources (files, services). LCM applies config. Windows PowerShell native. PowerShell 7+ limited. Replaced by ARM/Bicep/Terraform/Ansible for cloud infra.
