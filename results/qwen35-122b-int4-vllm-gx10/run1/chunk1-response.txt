

N1 — **Layer 2 vs. Layer 3 Switch**
A Layer 2 switch forwards frames based on MAC addresses within a broadcast domain (VLAN). A Layer 3 switch can perform IP routing (forwarding packets based on IP addresses) between VLANs or subnets, effectively acting as a router with switch port density. L3 switches use hardware ASICs for routing, offering higher throughput than traditional routers.

N2 — **Network and Broadcast Address**
*   **IP:** 10.0.5.37/20
*   **Subnet Mask:** 255.255.240.0 (Block size 16 in the 3rd octet).
*   **Network Address:** 10.0.0.0 (5 falls in the 0–15 range).
*   **Broadcast Address:** 10.0.15.255.

N3 — **TCP Three-Way Handshake**
1.  **SYN:** Client sends SYN to Server.
2.  **SYN-ACK:** Server acknowledges SYN and sends its own SYN.
3.  **ACK:** Client acknowledges Server's SYN.
**Lost Final ACK:** The server retransmits the SYN-ACK. If the client receives the retransmission, it sends another ACK. If the server times out, it resets the connection.

N4 — **SNAT vs. DNAT**
*   **SNAT (Source NAT):** Modifies the source IP of outgoing packets. *Example:* Internal hosts (10.0.0.x) accessing the internet appear as the gateway's public IP.
*   **DNAT (Destination NAT):** Modifies the destination IP of incoming packets. *Example:* Port forwarding public IP:80 to internal web server 10.0.0.5:80.

N5 — **SSL Certificate Mismatch Causes**
1.  The Common Name (CN) or Subject Alternative Name (SAN) in the certificate does not match the requested hostname.
2.  The client is accessing the server via an IP address instead of the domain name.
3.  The certificate is issued for a different domain (e.g., `www.example.com` vs `example.com`) or is a wildcard that doesn't cover the specific subdomain.

N6 — **VLAN vs. VxLAN**
*   **VLAN:** Layer 2 isolation using 802.1Q tags. Limited to 4094 IDs. Requires L2 adjacency.
*   **VxLAN:** Layer 2 over Layer 3 encapsulation (UDP). Supports 16 million IDs. Extends L2 segments across L3 boundaries.
*   **Choice:** Use VxLAN in cloud/data center environments requiring massive scale, multi-tenancy, or overlay networks across routed infrastructure.

N7 — **Asymmetric Routing Fix**
**Why:** Linux uses the default route (eth0) for all traffic unless specified otherwise. Reply traffic follows the routing table, ignoring the incoming interface.
**Fix:** Use Policy-Based Routing (PBR).
1.  Create a custom table: `ip route add default via 192.168.1.1 dev eth1 table 100`
2.  Add a rule: `ip rule add from 192.168.1.0/24 table 100`
This ensures traffic sourced from eth1's subnet returns via eth1.

N8 — **BGP Path Selection Order**
1.  **Weight** (Cisco proprietary, highest wins).
2.  **Local Preference** (Highest wins, within AS).
3.  **Locally Originated** (Locally injected routes preferred).
4.  **AS Path Length** (Shortest wins).
5.  **Origin Type** (IGP < EGP < Incomplete).
6.  **MED** (Lowest wins).
7.  **eBGP over iBGP**.
8.  **IGP Metric** to next hop.

N9 — **MTU Implication (VxLAN over IPsec)**
**Overhead Calculation:**
*   Physical MTU: 1500 bytes.
*   VxLAN Overhead: 50 bytes (14 Eth + 20 IP + 8 UDP + 8 VXLAN).
*   IPsec Overhead (ESP): ~50 bytes (16 IV + 16 Auth + Padding + ESP Header).
*   Total Overhead: ~100 bytes.
*   **Max Inner Payload:** 1500 - 100 = **1400 bytes**.
*   *Solution:* Enable Jumbo Frames (MTU 9000) on the physical interface to accommodate encapsulation without fragmentation.

N10 — **ARP and Gratuitous ARP**
*   **ARP:** Resolves IPv4 addresses to MAC addresses on a local network.
*   **Gratuitous ARP:** An ARP request sent by a host for its own IP.
*   **Solves:** Updates other hosts' ARP caches (e.g., after VM migration) and detects IP address conflicts (if a reply is received).

N11 — **Public vs. Private IP**
*   **Public:** Routable on the internet.
*   **Private:** Reserved for internal networks, not routable on the public internet.
*   **RFC 1918 Ranges:**
    1.  10.0.0.0 – 10.255.255.255 (10/8)
    2.  172.16.0.0 – 172.31.255.255 (172.16/12)
    3.  192.168.0.0 – 192.168.255.255 (192.168/16)

N12 — **DNS Records**
*   **DNS:** Translates domain names to IP addresses.
*   **A Record:** Maps hostname to IPv4 address.
*   **AAAA Record:** Maps hostname to IPv6 address.
*   **CNAME Record:** Maps an alias name to a canonical (true) domain name.

N13 — **DHCP and DORA**
*   **DHCP:** Protocol for dynamically assigning IP configuration.
*   **DORA Process:**
    1.  **Discover:** Client broadcasts to find servers.
    2.  **Offer:** Server offers an IP.
    3.  **Request:** Client requests the offered IP.
    4.  **Acknowledge:** Server confirms lease.

N14 — **Hub, Switch, Router**
*   **Hub:** Layer 1. Broadcasts all traffic to all ports. No intelligence.
*   **Switch:** Layer 2. Forwards frames based on MAC addresses. Isolates collision domains.
*   **Router:** Layer 3. Routes packets between different networks based on IP addresses.

N15 — **Half vs. Full Duplex**
*   **Half-Duplex:** Communication in one direction at a time (like a walkie-talkie). Prone to collisions.
*   **Full-Duplex:** Simultaneous two-way communication (like a phone call).
*   **Modern Ethernet:** Uses Full-Duplex exclusively (auto-negotiation).

N16 — **TTL and Traceroute**
*   **TTL:** Time To Live. A counter decremented by each router hop. Prevents infinite loops.
*   **Traceroute:** Sends packets with increasing TTL values (1, 2, 3...). When TTL hits 0, the router drops the packet and sends an ICMP "Time Exceeded" message back, revealing its IP.

N17 — **NAT Gateway Types**
*   **Static NAT:** One-to-one permanent mapping (Public IP <-> Private IP).
*   **Dynamic NAT:** Maps private IPs to a pool of public IPs on a first-come basis.
*   **PAT (Port Address Translation):** Many-to-one mapping. Multiple private IPs share one public IP using different source ports.

N18 — **ECMP and Asymmetric Flows**
*   **ECMP:** Routes traffic across multiple equal-cost paths using a hash (src/dst IP, ports).
*   **Problem:** If forward and return traffic take different paths, a stateful firewall on one path may drop the return packet because it lacks connection state context.
*   **Solution:** Ensure symmetric routing or use stateful synchronization between firewalls.

N19 — **TCP Window Scaling**
*   **Problem:** BDP (10MB) > Window Size (64KB). The sender stops transmitting while waiting for ACKs, underutilizing the link.
*   **Solution:** TCP Window Scaling (RFC 1323) adds a shift count to the window field, allowing window sizes up to 1GB. This enables the sender to fill the pipe.

N20 — **802.1Q Trunk and Linux VLANs**
*   **Trunk:** Carries multiple VLANs over a single link using 4-byte 802.1Q tags.
*   **Linux Config:** Create sub-interfaces: `ip link add link eth0 name eth0.10 type vlan id 10`.
*   **Frame Format:** [Dest MAC][Src MAC][802.1Q Tag][EtherType][Payload][FCS].

L1 — **Hard Link vs. Symbolic Link**
*   **Hard Link:** Direct reference to the same inode (file data). Cannot span filesystems. Deleting original doesn't delete data.
*   **Symbolic Link:** A pointer file containing a path to the target. Can span filesystems. Deleting target breaks the link.

L2 — **Find Large Files**
`find /var/log -type f -size +100M`

L3 — **Process State D**
*   **Meaning:** Uninterruptible sleep (usually waiting on I/O, e.g., disk or NFS).
*   **Kill:** No. `kill -9` cannot terminate a process in state D. It requires the I/O operation to complete or a hardware reset.

L4 — **cgroups v1 vs. v2**
*   **v1:** Hierarchical, separate controllers (cpu, memory, blkio). Inconsistent interfaces.
*   **v2:** Unified hierarchy, single mount point. More consistent and efficient.
*   **Systemd:** Prefers v2 for better resource management and isolation.

L5 — **nftables vs. iptables**
*   **iptables:** Legacy, multiple tables (filter, nat, mangle), slower rule processing.
*   **nftables:** Successor, single table, unified syntax, faster kernel processing.
*   **Kernel:** `iptables-nft` translates iptables commands to nftables rules in the kernel.

L6 — **Disk Full but du Low**
*   **Cause:** Files deleted while still open by a process. Space is not freed until the file handle is closed.
*   **Check:** `lsof | grep deleted`.

L7 — **Linux Boot Process**
1.  **UEFI:** Initializes hardware, loads bootloader.
2.  **Bootloader (GRUB):** Loads kernel and initramfs into memory.
3.  **Kernel:** Initializes drivers, mounts root filesystem (via initramfs).
4.  **Initramfs:** Temporary root to prepare real root (decrypt, load drivers).
5.  **Root FS:** Switches to real root.
6.  **Systemd:** PID 1, starts services and targets.

L8 — **OOM with High Cache**
*   **Why:** `available` memory estimates reclaimable cache. If memory pressure is sudden, the kernel may not reclaim cache fast enough before OOM triggers.
*   **Tunables:** `vm.vfs_cache_pressure` (reclaim inode/dentry cache), `vm.swappiness` (prefers swap vs cache), `vm.min_free_kbytes`.

L9 — **ip netns**
*   **Function:** Creates and manages Network Namespaces (isolated network stacks).
*   **Containers:** Runtimes (Docker, containerd) use namespaces to give each container its own IP, routing table, and interfaces.

L10 — **Signals**
*   **SIGTERM (15):** Graceful termination. Catchable.
*   **SIGKILL (9):** Force kill. Cannot be caught or ignored.
*   **SIGQUIT (3):** Quit (often dumps core). Catchable.

L11 — **Stdout, Stderr, Stdin**
*   **Stdout (1):** Normal output.
*   **Stderr (2):** Error output.
*   **Stdin (0):** Input.
*   **Redirect:** `command 2> error.log` (sends stderr to file, stdout remains on terminal).

L12 — **chmod 755**
*   **Action:** Sets permissions to `rwxr-xr-x`.
*   **Digits:**
    *   7 (Owner): Read (4) + Write (2) + Execute (1).
    *   5 (Group): Read (4) + Execute (1).
    *   5 (Other): Read (4) + Execute (1).

L13 — **Root vs. Sudo**
*   **Root:** UID 0. Direct access to all system resources.
*   **Sudo:** Regular user executing commands with elevated privileges via `/etc/sudoers`. Provides audit trails and granular control.

L14 — **Package Managers**
*   **Definition:** Software to install, update, and remove packages.
*   **Debian/Ubuntu:** `apt` (frontend), `dpkg` (backend).
*   **RHEL/Fedora:** `dnf` (frontend), `rpm` (backend).

L15 — **/etc/fstab**
*   **Use:** Defines filesystem mount points and options at boot.
*   **Misconfiguration:** Can cause boot failure (dropped to emergency shell) unless `nofail` option is used.

L16 — **LVM**
*   **Concept:** Abstracts physical disks into logical volumes.
*   **Components:** PV (Physical Volume), VG (Volume Group), LV (Logical Volume).
*   **Extend:** `lvextend -L +10G /dev/vg/lv` followed by `resize2fs` (ext4) or `xfs_growfs` (xfs).

L17 — **I/O Schedulers**
*   **mq-deadline:** Optimized for latency (SSDs).
*   **bfq:** Budget Fair Queueing (fairness, HDDs).
*   **none:** No scheduling (NVMe drives handle queues internally).
*   **Change:** `echo mq-deadline > /sys/block/sda/queue/scheduler`.

L18 — **Load Average Diagnosis**
*   **Meaning:** Average number of processes in running or uninterruptible sleep state.
*   **I/O Wait:** Inflates load average even if CPU is idle.
*   **Diagnosis:** `top` (check `%wa`), `iostat -x` (check `%util`/await), `vmstat 1` (check `si/so` for swap).

L19 — **SELinux Troubleshooting**
*   **Enforcement:** Enforcing (blocks), Permissive (logs only), Disabled (off).
*   **Troubleshoot:** Check logs (`/var/log/audit/audit.log`), use `ausearch -m avc`, or `setsebool -P httpd_can_network_connect 1` for specific ports.

L20 — **Page Faults and THP**
*   **Page Fault:** CPU requests memory not currently mapped.
*   **Minor:** Page exists in RAM (copy-on-write).
*   **Major:** Page must be read from disk (swap/file).
*   **THP:** Uses 2MB pages instead of 4KB. Reduces TLB misses but increases latency during allocation/compaction.
*   **Disable:** For latency-sensitive apps (e.g., databases) to prevent allocation stalls. `echo never > /sys/kernel/mm/transparent_hugepage/enabled`.
