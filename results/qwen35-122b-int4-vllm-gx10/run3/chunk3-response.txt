

T1 — **tofu plan** generates an execution plan showing what changes will be made without applying them. **tofu apply** executes the changes defined in the plan (or automatically generates and applies a plan if no plan file is provided). Plan is for review; apply is for execution.

T2 — **State** is a file (`terraform.tfstate`) that maps real-world resources to your configuration. **Remote state** stores this file in a shared backend (e.g., S3, GCS). It is important for team collaboration, state locking (preventing concurrent writes), and storing sensitive data securely outside of version control.

T3 — **count** creates resources based on an integer index (0, 1, 2...). **for_each** creates resources based on a map or set of strings (key-value pairs). **for_each** is preferred when resources need stable identities (keys) that don't shift if an item is removed from the middle of a list, preventing unintended recreation.

T4 — OpenTofu detects this as **drift**. During `tofu plan`, it compares the state file against the actual cloud infrastructure. If differences are found, it proposes changes to either revert the manual change or update the state to match the manual change, depending on the configuration.

T5 —
```hcl
resource "aws_instance" "web" {
  for_each = toset(["web1", "web2", "web3"])
  ami           = "ami-123456"
  instance_type = "t2.micro"
  tags = {
    Name = each.key
  }
}
```

T6 — **terraform_remote_state** reads outputs from another state file. **Outputs** pass data from child modules to the root module. The recommended alternative for sharing data between root modules is to **refactor into a single root module** or use a **module composition pattern** where one root calls the other as a child, avoiding direct state coupling which creates fragile dependencies.

T7 — **Why:** Outputs are evaluated during the plan/refresh phase, but `remote-exec` provisioners run during the apply phase. If an output depends on data created by the provisioner, it is empty during the plan. **Fix:** Ensure the resource consuming the output has a `depends_on` referencing the `null_resource`, or restructure to avoid outputs depending on provisioner side-effects (e.g., use a data source to read the file after creation).

T8 — **tofu import** maps existing infrastructure to a resource in the state file. **Limitations:** It doesn't generate code; you must write the HCL manually. **Import block (1.5+):** Allows declaring imports directly in HCL (`import { id = "..." to = ... }`), enabling version-controlled import plans and better integration with `tofu plan`.

T9 — A **variable** is an input parameter for a module or root configuration. An **output** is a value exposed from a module or root configuration for use elsewhere. Variables configure resources; outputs expose resource attributes.

T10 — A **provider** is a plugin that interacts with APIs (e.g., AWS, Azure). If you run `tofu plan` without `tofu init`, it fails because the provider plugins are not downloaded and the backend is not configured. `init` initializes the working directory.

T11 — **.terraform.lock.hcl** records the exact versions of providers and modules used. It should be committed to ensure all team members and CI/CD pipelines use identical provider versions, preventing unexpected behavior due to upstream updates.

T12 — **tofu destroy** removes all resources managed by the state. To target a single resource, use the `-target` flag: `tofu destroy -target=aws_instance.web1`. Note: This can leave orphaned dependencies.

T13 — A **data source** retrieves information from existing infrastructure (read-only) rather than managing it. **Example:** Use `data "aws_ami" "latest"` to find the latest Ubuntu AMI ID instead of creating a new AMI resource.

T14 — **variables** are inputs passed into a module (external configuration). **locals** are internal variables calculated within the module. Use **locals** for computed values, aliases, or complex expressions that don't need to be exposed as module inputs.

T15 — **create_before_destroy:** Recreates a resource with a new ID before deleting the old one (useful for immutable infrastructure). **prevent_destroy:** Blocks deletion of the resource (useful for critical data stores). **ignore_changes:** Ignores specific attribute changes in the plan (useful for attributes managed externally, like tags updated by a script).

T16 — A **moved block** tells OpenTofu that a resource has changed address (e.g., moved from one module to another) without changing its identity. It updates the state file to point to the new address, preventing OpenTofu from destroying and recreating the resource during refactoring.

T17 — OpenTofu builds a **dependency graph** based on resource references. **Implicit dependencies** are inferred from attribute references (e.g., `aws_instance.web.vpc_id = aws_vpc.main.id`). **Explicit dependencies** use `depends_on`. `depends_on` forces serialization, reducing parallelism. Use sparingly only when implicit dependencies are insufficient (e.g., external API calls).

T18 — 1. **Split State:** Break into multiple state files/modules to reduce graph size. 2. **Provider Parallelism:** Increase `parallelism` in provider config. 3. **Remove Unused Data Sources:** Filter out unnecessary lookups. 4. **Use `refresh_only`:** Skip plan generation if only state refresh is needed. *Tradeoff:* Splitting state increases management overhead; higher parallelism may hit API rate limits.

T19 — **State locking** prevents concurrent writes (e.g., via DynamoDB). If a lock isn't released (crash), the state is locked. **Fix:** Use `tofu force-unlock <LOCK_ID>`. **Risk:** If another process is actually writing, forcing unlock can corrupt state. Only use if you are certain no other operation is running.

T20 — 1. Backup local state. 2. Configure new S3 backend in `backend` block. 3. Run `tofu init -migrate-state`. 4. Confirm migration when prompted. 5. Verify by running `tofu plan` (should show no changes). 6. Verify S3 bucket contains the state file and DynamoDB lock table is active.

A1 — A **playbook** is a YAML file containing a list of plays (tasks). A **role** is a reusable directory structure containing tasks, vars, handlers, etc. A **task** is a single unit of work (module invocation) within a playbook or role.

A2 — **ansible_facts** is a dictionary of system information gathered by the `setup` module. Access OS family via `ansible_facts['os_family']` or `ansible_os_family`.

A3 — **command:** Runs a command without shell features (safe, idempotent). **shell:** Runs via shell (supports pipes, variables, less safe). **raw:** Executes without Python on the target (used for bootstrapping or minimal environments). Use **command** by default; **shell** for complex logic; **raw** for initial setup.

A4 — **Idempotency** means running a task multiple times yields the same result without side effects. **Idempotent:** `yum install htop` (installs if missing, does nothing if present). **Not Idempotent:** `command: echo "log"` (appends log every time).

A5 —
```yaml
- name: Install htop
  package:
    name: "{{ 'htop' if ansible_os_family == 'Debian' else ['epel-release', 'htop'] }}"
    state: present
```

A6 — Precedence (Low to High): Role defaults < Inventory file vars < Group vars < Host vars < Play vars < Task vars < **Extra vars** (`-e`). `set_fact` acts like host vars but is set at runtime.

A7 — Use **serial** to limit concurrency.
```yaml
- hosts: rke2_nodes
  serial:
    - 3
    - 47
  tasks:
    - name: Install RKE2
      ...
    - name: Wait for node ready
      wait_for: ...
```
Group the first 3 nodes in a specific inventory group if strict ordering is required before the rest start.

A8 — **ansible-vault** encrypts sensitive data. To encrypt a single variable, use `ansible-vault encrypt_string "secret_value" --name "my_var"`. Paste the resulting encrypted string into the vars file. The file itself remains unencrypted, but the value is protected.

A9 — An **inventory** defines the hosts and groups Ansible manages. **Static:** A text file (INI/YAML) manually edited. **Dynamic:** A script that queries a cloud API (e.g., AWS EC2) to generate the inventory at runtime.

A10 — `ansible webservers -m shell -a "df -h"`

A11 — A **handler** is a task that runs only if notified (triggered) by another task. It differs from a regular task because it executes once at the end of the play, even if notified multiple times. Trigger via `notify: handler_name`.

A12 — **ansible.cfg** configures Ansible behavior. Common settings: `inventory` (path), `remote_user` (SSH user), `host_key_checking` (security), `forks` (parallelism).

A13 — **register** saves the output of a task to a variable. Use it in subsequent tasks via `when: registered_var.rc == 0` or `debug: var=registered_var.stdout`.

A14 — **import_tasks** is static (processed at parse time); conditionals apply to the import itself. **include_tasks** is dynamic (processed at runtime); conditionals apply to the execution of the included tasks. Use **import** for static structure, **include** for runtime logic.

A15 — **Ansible Galaxy** is a repository for roles and collections. Use `requirements.yml` to list dependencies, then run `ansible-galaxy install -r requirements.yml` to install them.

A16 — **Connection plugins** define how Ansible connects. **ssh:** Standard SSH (Linux/Unix). **local:** Runs on the control node itself. **network_cli:** For network devices (Cisco, Juniper) using CLI protocols. Use **ssh** for servers, **network_cli** for switches/routers.

A17 — **delegate_to** runs a task on a different host (e.g., localhost) while iterating over others. **run_once** executes the task only once across the batch. **Example:** Gather facts on a remote host, then delegate a task to localhost to update a load balancer config using that data, with `run_once: true`.

A18 — 1. **Increase forks:** `forks = 50` in ansible.cfg. 2. **Pipelining:** `pipelining = True` reduces SSH connections. 3. **Fact Caching:** Use `redis` or `jsonfile` to avoid re-gathering facts. 4. **Mitogen:** Accelerates execution via persistent connections. *Tradeoff:* Higher forks/Mitogen increase memory usage; caching requires infrastructure.

A19 — **{{ }}** prints variables. **{% %}** control flow (loops, if). **{# #}** comments.
```jinja2
upstream backend {
{% for server in servers %}
  server {{ server.ip }}:{{ server.port }};
  # Health check: {{ server.name }}
{% endfor %}
}
```

A20 — 1. **serial:** `serial: 5` (deploy 5 at a time). 2. **Pre-task:** Deregister from Load Balancer (LB). 3. **Deploy:** Update app. 4. **Health Check:** `uri` module to verify `/health`. 5. **Post-task:** Register to LB. 6. **Rollback:** Use `block/rescue`. If health check fails in `block`, `rescue` reverts the deployment and re-registers the old version.
