

## Networking (20 questions)

**N1 — Easy: What is the difference between a Layer 2 switch and a Layer 3 switch?**
A Layer 2 switch forwards frames based on MAC addresses within a broadcast domain. A Layer 3 switch can perform routing (forwarding packets based on IP addresses) between VLANs or subnets while maintaining switching speeds. L2 operates at the Data Link layer; L3 operates at both Data Link and Network layers.

**N2 — Easy: A host has IP 10.0.5.37/20. What is the network address and broadcast address?**
Mask /20 = 255.255.240.0. Block size in the 3rd octet is 16 (256-240). The subnet range is 10.0.0.0 to 10.0.15.255.
*   **Network Address:** 10.0.0.0
*   **Broadcast Address:** 10.0.15.255

**N3 — Medium: Explain the TCP three-way handshake. What happens if the final ACK is lost?**
1.  Client sends SYN.
2.  Server responds with SYN-ACK.
3.  Client sends ACK.
If the final ACK is lost, the server retransmits the SYN-ACK after a timeout. The client ignores the retransmission (as it already sent the ACK) but the server eventually times out and closes the connection if no ACK is received.

**N4 — Medium: What is the difference between SNAT and DNAT? Give a practical example of each.**
*   **SNAT (Source NAT):** Modifies the source IP of outgoing packets. Example: Internal hosts (10.0.0.x) accessing the internet appear as the gateway's public IP.
*   **DNAT (Destination NAT):** Modifies the destination IP of incoming packets. Example: Port forwarding public IP:80 to internal server 10.0.0.5:80.

**N5 — Medium: You run `curl -v https://example.com` and get `SSL: certificate subject name does not match target host name`. List 3 possible causes.**
1.  The URL hostname differs from the Common Name (CN) or Subject Alternative Name (SAN) in the certificate (e.g., accessing `www.example.com` but cert is for `example.com`).
2.  The certificate was issued for a different domain entirely.
3.  A wildcard certificate is used incorrectly (e.g., cert is `*.example.com` but accessing `sub.sub.example.com`).

**N6 — Medium: Explain the difference between a VLAN and a VxLAN. When would you choose VxLAN over VLAN?**
*   **VLAN:** Layer 2 segmentation using 802.1Q tags. Limited to 4094 IDs. Requires L2 adjacency.
*   **VxLAN:** Layer 3 overlay encapsulating L2 frames in UDP. Supports 16M IDs. Spans across routed networks.
*   **Choice:** Choose VxLAN for cloud environments, multi-tenant isolation beyond 4094 VLANs, or extending Layer 2 domains across Layer 3 boundaries.

**N7 — Hard: A Linux host has two NICs: eth0 (10.0.0.5/24, default gw 10.0.0.1) and eth1 (192.168.1.5/24). Traffic arriving on eth1 from 192.168.1.0/24 is being replied via eth0. Why, and how do you fix it with policy-based routing?**
*   **Why:** The default route points to eth0. Return traffic matches the default route, ignoring the source interface. Reverse Path Filtering (rp_filter) may also drop asymmetric packets.
*   **Fix:** Create a custom routing table and rule.
    1.  `ip rule add from 192.168.1.5 table 100`
    2.  `ip route add default via 192.168.1.1 dev eth1 table 100`
    3.  Ensure `rp_filter` is set to loose mode (2) if necessary.

**N8 — Hard: Explain how BGP path selection works. List at least 5 attributes in the correct order of preference.**
BGP selects the best path based on a deterministic sequence of attributes. Top 5 preferences:
1.  **Weight** (Cisco proprietary, local to router).
2.  **Local Preference** (Higher is better, within AS).
3.  **Locally Originated** (Network/Aggregate/Redistribute).
4.  **AS Path** (Shorter is better).
5.  **Origin Code** (IGP < EGP < Incomplete).

**N9 — Hard: What is the MTU implication of running VxLAN over an IPsec tunnel? Show the math for the maximum inner payload if the physical MTU is 1500.**
Encapsulation adds overhead, reducing the effective MTU for inner payloads.
*   **Physical MTU:** 1500 bytes.
*   **Overhead:**
    *   Outer Ethernet: 14 bytes
    *   Outer IP: 20 bytes
    *   UDP: 8 bytes
    *   VxLAN: 8 bytes
    *   IPsec ESP (Header + IV + Auth + Padding): ~56 bytes (conservative estimate)
    *   **Total Overhead:** ~106 bytes.
*   **Max Inner Payload:** 1500 - 106 = **1394 bytes**.
*   *Solution:* Increase physical MTU (Jumbo Frames) or reduce inner MTU on endpoints.

**N10 — Medium: What is the purpose of ARP, and what problem does Gratuitous ARP solve?**
*   **ARP:** Resolves IPv4 addresses to MAC addresses on a local network.
*   **Gratuitous ARP:** An ARP reply sent without a request. It solves: 1. Updating ARP caches on other hosts (e.g., after VM migration). 2. Detecting IP address conflicts (if another host replies).

**N11 — Easy: What is the difference between a public IP address and a private IP address? List the three private IPv4 ranges defined in RFC 1918.**
*   **Public:** Routable on the global internet.
*   **Private:** Reserved for internal networks, not routable on the public internet.
*   **RFC 1918 Ranges:**
    1.  10.0.0.0 – 10.255.255.255 (10/8)
    2.  172.16.0.0 – 172.31.255.255 (172.16/12)
    3.  192.168.0.0 – 192.168.255.255 (192.168/16)

**N12 — Easy: What is DNS, and what is the difference between an A record, a CNAME record, and an AAAA record?**
*   **DNS:** Domain Name System, translates hostnames to IP addresses.
*   **A Record:** Maps hostname to IPv4 address.
*   **AAAA Record:** Maps hostname to IPv6 address.
*   **CNAME Record:** Maps hostname to another hostname (alias).

**N13 — Easy: What is DHCP, and what four-step process (DORA) does a client use to obtain an IP address from a DHCP server?**
*   **DHCP:** Dynamic Host Configuration Protocol, automates IP assignment.
*   **DORA:**
    1.  **D**iscover (Client broadcasts request).
    2.  **O**ffer (Server proposes an IP).
    3.  **R**equest (Client accepts the offer).
    4.  **A**cknowledge (Server confirms lease).

**N14 — Easy: What is the difference between a hub, a switch, and a router? At which OSI layer does each primarily operate?**
*   **Hub:** L1 (Physical). Broadcasts all traffic to all ports.
*   **Switch:** L2 (Data Link). Forwards frames based on MAC addresses.
*   **Router:** L3 (Network). Routes packets based on IP addresses between networks.

**N15 — Easy: Explain the difference between half-duplex and full-duplex communication. Which mode do modern Ethernet links use?**
*   **Half-Duplex:** Data flows in one direction at a time (shared medium, collisions possible).
*   **Full-Duplex:** Data flows simultaneously in both directions (dedicated paths, no collisions).
*   **Modern:** Modern Ethernet links use **Full-Duplex**.

**N16 — Medium: What is the purpose of the TTL field in an IP packet? How does traceroute exploit it to map the network path?**
*   **TTL:** Time To Live. Prevents packets from looping infinitely by decrementing at each hop; packet is dropped if TTL reaches 0.
*   **Traceroute:** Sends packets with incrementing TTL (1, 2, 3...). When a router drops a packet (TTL=0), it sends back an ICMP "Time Exceeded" message, revealing its IP.

**N17 — Medium: Explain what a NAT gateway does. What is the difference between static NAT, dynamic NAT, and PAT (port address translation)?**
*   **NAT Gateway:** Translates private IPs to public IPs for internet access.
*   **Static NAT:** One-to-one permanent mapping (Private IP <-> Public IP).
*   **Dynamic NAT:** Maps private IPs to a pool of public IPs (one-to-one, but not permanent).
*   **PAT (NAPT):** Many-to-one mapping using unique source ports (Multiple private IPs share one public IP).

**N18 — Hard: Explain how ECMP (Equal-Cost Multi-Path) routing works. What hashing strategies are commonly used, and what problems can arise with asymmetric flows when stateful firewalls are involved?**
*   **ECMP:** Routes traffic across multiple paths with equal cost to increase bandwidth/redundancy.
*   **Hashing:** Uses 5-tuple (Src IP, Dst IP, Src Port, Dst Port, Protocol) to ensure packets of the same flow take the same path.
*   **Problem:** If hashing is inconsistent or paths change, return traffic may take a different path. A stateful firewall on the return path may drop packets because it lacks the connection state (conntrack entry) established on the forward path.

**N19 — Hard: A TCP connection between two hosts shows high latency but packet captures show no drops. The bandwidth-delay product is 10MB but the TCP window size maxes out at 64KB. Explain the problem and how TCP window scaling (RFC 1323) solves it.**
*   **Problem:** The TCP Receive Window (64KB) is smaller than the Bandwidth-Delay Product (10MB). The sender fills the pipe and waits for ACKs, underutilizing the link (throughput capped at Window/RTT).
*   **Solution:** TCP Window Scaling adds a shift count to the window field, allowing window sizes > 64KB (up to 1GB), enabling full pipe utilization over high-latency links.

**N20 — Hard: Describe how 802.1Q trunk ports work. A server with a single NIC needs to communicate on VLANs 10, 20, and 30. Explain how to configure this on Linux using sub-interfaces and what the frame format looks like on the wire.**
*   **802.1Q:** Inserts a 4-byte tag into the Ethernet frame between Source MAC and EtherType.
*   **Linux Config:** Create VLAN sub-interfaces (e.g., `eth0.10`, `eth0.20`, `eth0.30`) using `ip link add link eth0 name eth0.10 type vlan id 10`.
*   **Frame Format:** [Dest MAC (6)] [Src MAC (6)] [802.1Q Tag (4)] [EtherType (2)] [Payload] [FCS (4)].

## Linux (20 questions)

**L1 — Easy: What is the difference between a hard link and a symbolic link?**
*   **Hard Link:** Direct reference to the same inode (file data). Cannot span filesystems or link directories. Deleting original doesn't delete data.
*   **Symbolic Link:** A file containing a path to another file. Can span filesystems. Deleting original breaks the link (dangling).

**L2 — Easy: How do you find all files larger than 100MB under /var/log?**
`find /var/log -type f -size +100M`

**L3 — Medium: A process is in state D (uninterruptible sleep). What does this mean, and can you kill it with kill -9?**
*   **Meaning:** Process is waiting for I/O (usually disk) to complete. It cannot be interrupted by signals.
*   **Kill:** No. `kill -9` sends SIGKILL, which is ignored in D state. The process must wait for I/O to finish or the system must be rebooted.

**L4 — Medium: Explain the difference between cgroups v1 and cgroups v2. Which does systemd prefer and why?**
*   **v1:** Hierarchical, separate controllers (cpu, memory, io) mounted separately. Inconsistent interfaces.
*   **v2:** Unified hierarchy, single mount point, consistent interface across controllers.
*   **Preference:** systemd prefers **cgroups v2** for better resource management consistency and unified control.

**L5 — Medium: What is the difference between nftables and iptables? How does the kernel handle both simultaneously?**
*   **Difference:** `iptables` uses legacy netfilter hooks with multiple tables/chains. `nftables` is the successor, using a unified table/chain/flow structure and more efficient bytecode.
*   **Kernel:** `iptables` commands are translated to `nftables` rules in modern kernels (compatibility layer), but `nftables` is the native backend.

**L6 — Medium: You run `df -h` and see a filesystem at 100%, but `du -sh /*` totals far less. What is the most likely cause?**
Files have been deleted but are still held open by running processes. The space is not freed until the process closes the file handle. Check with `lsof | grep deleted`.

**L7 — Hard: Explain the Linux boot process from UEFI firmware to a running systemd target. Cover: firmware, bootloader, kernel, initramfs, root, systemd.**
1.  **UEFI:** Initializes hardware, loads bootloader (e.g., GRUB).
2.  **Bootloader:** Loads Kernel and Initramfs into memory.
3.  **Kernel:** Initializes drivers, mounts Initramfs.
4.  **Initramfs:** Temporary root filesystem containing tools to mount the real root.
5.  **Root:** Real root filesystem is mounted.
6.  **Systemd:** PID 1 starts, executes targets (e.g., multi-user.target).

**L8 — Hard: A server has 64GB RAM but only 2GB swap. free -h shows 60GB used, 1GB available, 15GB of that is buff/cache. The OOM killer fires. Explain why available can be low even with high buff/cache, and what kernel tunables affect this behavior.**
*   **Why:** `available` estimates memory available for new apps without swapping. If anon memory (app data) is exhausted, OOM fires even if cache is reclaimable. Cache is only reclaimed if apps request memory.
*   **Tunables:** `vm.swappiness` (prefers swap vs cache), `vm.vfs_cache_pressure` (pressure to reclaim inode/dentry cache).

**L9 — Medium: What does `ip netns` do, and how is it used by container runtimes?**
*   **Function:** Creates/manages Network Namespaces (isolated network stacks).
*   **Containers:** Runtimes (Docker/Podman) create a new netns for each container, assigning virtual interfaces (veth pairs) to connect the container namespace to the host namespace.

**L10 — Medium: Explain the difference between SIGTERM, SIGKILL, and SIGQUIT. Which can be caught by the process?**
*   **SIGTERM (15):** Graceful termination request. **Catchable.**
*   **SIGKILL (9):** Immediate force kill. **Not catchable.**
*   **SIGQUIT (3):** Quit and dump core. **Catchable.**

**L11 — Easy: What is the difference between stdout, stderr, and stdin? How do you redirect stderr to a file while still displaying stdout on the terminal?**
*   **Stdout (1):** Standard output (normal data).
*   **Stderr (2):** Standard error (error messages).
*   **Stdin (0):** Standard input.
*   **Redirect:** `command 2> error.log` (Stdout goes to terminal, Stderr goes to file).

**L12 — Easy: What does the chmod 755 command do? Explain what each digit represents.**
Sets permissions to `rwxr-xr-x`.
*   **7 (Owner):** Read (4) + Write (2) + Execute (1).
*   **5 (Group):** Read (4) + Execute (1).
*   **5 (Other):** Read (4) + Execute (1).

**L13 — Easy: What is the difference between the root user and a user with sudo privileges?**
*   **Root:** UID 0, unrestricted access to all system resources by default.
*   **Sudo:** Regular user granted specific elevated privileges via `/etc/sudoers`. Actions are logged and restricted by policy.

**L14 — Easy: What is a package manager? Name the default package managers for Debian/Ubuntu and RHEL/Fedora.**
*   **Definition:** Tool to install, update, and manage software packages and dependencies.
*   **Debian/Ubuntu:** `apt` (frontend), `dpkg` (backend).
*   **RHEL/Fedora:** `dnf` (frontend), `rpm` (backend).

**L15 — Easy: What is the /etc/fstab file used for? What happens if an entry is misconfigured?**
*   **Usage:** Static configuration file defining how disk partitions and filesystems are mounted at boot.
*   **Misconfiguration:** Boot may hang waiting for a device, or drop to emergency/rescue mode if `nofail` is not specified.

**L16 — Medium: Explain what LVM (Logical Volume Manager) is. What are physical volumes, volume groups, and logical volumes, and how do you extend a logical volume on a running system?**
*   **LVM:** Abstraction layer for disk management.
*   **PV:** Physical disk/partition.
*   **VG:** Pool of storage from PVs.
*   **LV:** Virtual partition carved from VG.
*   **Extend:** `lvextend -L +10G /dev/vg_name/lv_name` followed by `resize2fs` (ext4) or `xfs_growfs` (xfs).

**L17 — Hard: Explain how the Linux kernel's I/O scheduler works. Compare mq-deadline, bfq, and none schedulers. When would you choose each, and how do you change the scheduler for a block device at runtime?**
*   **Function:** Orders disk requests to optimize latency/throughput.
*   **mq-deadline:** Prioritizes requests by deadline. Good for SSDs/latency-sensitive.
*   **bfq:** Budget Fair Queueing. Good for fairness on HDDs/rotational.
*   **none:** Passthrough. Best for NVMe (hardware handles queueing).
*   **Change:** `echo mq-deadline > /sys/block/sda/queue/scheduler`.

**L18 — Hard: A system is experiencing intermittent high load averages but CPU usage is low. Explain what load average actually measures on Linux, why I/O wait can inflate it, and how you would diagnose whether the bottleneck is CPU, disk, or network using standard tools.**
*   **Load:** Count of runnable processes + uninterruptible sleep (D state) processes.
*   **I/O Wait:** Processes waiting on disk I/O enter D state, inflating load without using CPU.
*   **Diagnosis:** `top` (check %wa), `iostat -x` (check %util/await on disk), `sar` (historical), `netstat`/`ss` (network).

**L19 — Hard: Explain how SELinux enforces mandatory access control. What is the difference between enforcing, permissive, and disabled modes? How do you troubleshoot a daemon that fails to bind a non-standard port due to SELinux policy?**
*   **MAC:** Enforces access based on security labels (contexts), not just UID/GID.
*   **Modes:** Enforcing (blocks & logs), Permissive (logs only), Disabled (off).
*   **Troubleshoot:** Check `ausearch -m avc` or `/var/log/audit/audit.log`. Use `setsebool -P httpd_can_network_connect 1` or `semanage port -a -t http_port_t -p tcp 8080` to allow the port.

**L20 — Hard: Describe how the Linux kernel's virtual memory subsystem handles page faults. What is the difference between a minor and a major page fault? How does transparent huge pages (THP) affect application performance, and when would you disable it?**
*   **Page Fault:** Occurs when accessing a page not currently mapped in RAM. Kernel loads it.
*   **Minor:** Page is in memory (swap/cache), just needs mapping.
*   **Major:** Page must be read from disk (swap/file).
*   **THP:** Uses 2MB pages instead of 4KB. Reduces TLB misses but can cause latency spikes due to memory compaction.
*   **Disable:** For latency-sensitive apps (e.g., databases) via `echo never > /sys/kernel/mm/transparent_hugepage/enabled`.
