

DN1 — **Class vs Struct:** Classes are reference types (allocated on heap), structs are value types (allocated on stack or inline). Classes support inheritance; structs do not. Use structs for small, immutable data types (e.g., coordinates, complex numbers) to reduce allocation overhead and improve cache locality. Avoid structs for large data or mutable state.

DN2 — **IEnumerable vs IQueryable:** `IEnumerable<T>` executes queries in-memory (LINQ to Objects). `IQueryable<T>` builds an expression tree translated to a query language (e.g., SQL) by the provider (LINQ to SQL/EF). This matters for databases: `IQueryable` filters server-side (efficient), while `IEnumerable` pulls all data to client-side before filtering (inefficient).

DN3 — **Async/Await & Task vs ValueTask:** `async/await` uses a state machine to suspend execution without blocking threads. `Task` always allocates an object on the heap. `ValueTask` is a struct that wraps a `Task` or a result, avoiding allocation if the operation completes synchronously. Use `ValueTask` for high-frequency async methods (e.g., I/O in hot paths) to reduce GC pressure.

DN4 — **Dependency Injection:** DI injects dependencies rather than creating them. Lifetimes: **Transient** (new instance per request), **Scoped** (one instance per HTTP request), **Singleton** (one instance per app lifetime). **Bug:** Injecting a Scoped service into a Singleton creates a "Captive Dependency," where the Scoped service lives as long as the Singleton, potentially holding stale data or disposed resources.

DN5 — **string vs ReadOnlySpan<char>:** `string` is immutable, heap-allocated, and null-terminated. `ReadOnlySpan<char>` is a stack-only view over contiguous memory (array, string, buffer). Use `Span<T>` for high-performance string manipulation (parsing, slicing) to avoid allocations and copies.

DN6 — **GC & IDisposable:** GC manages memory via generations: Gen 0 (short-lived), Gen 1 (medium), Gen 2 (long-lived). LOH (Large Object Heap) stores objects >85KB, collected less frequently. `IDisposable` is needed for unmanaged resources (files, DB connections) because the GC doesn't know when to release them deterministically.

DN7 — **ConfigureAwait:** Default `await` captures the `SynchronizationContext` (e.g., UI thread or ASP.NET request context). `ConfigureAwait(false)` releases the context, allowing continuation on any thread pool thread. Use `false` in libraries or performance-critical code. Do NOT use in UI code or ASP.NET Core middleware where request context (e.g., `HttpContext`) is required.

DN8 — **.NET 8/9 Features:** **Primary Constructors:** Parameters on class definition injected into constructor. **Collection Expressions:** `[1, 2, ..list]` for array/list creation. **FrozenDictionary:** Immutable, optimized for read-only lookups.
*Example:*
```csharp
public class MyService(MyDbContext context, ILogger<MyService> logger) : IService { }
// Registered via DI container automatically
```

DN9 — **ObjectDisposedException Diagnosis:** Likely cause: `DbContext` (Scoped) injected into a Singleton service, or `DbContext` used after the request scope ends (e.g., in a background task). **Fix:** Ensure `DbContext` is Scoped. If background work is needed, inject `IDbContextFactory` to create new contexts per operation, or use a separate Scoped scope via `IServiceScopeFactory`.

DN10 — **Record vs Class:** `record` provides value-based equality (structural) and immutability features (withers). `class` provides reference equality. `record struct` combines value semantics with struct performance. Choose `record` for DTOs/immutable data, `class` for domain entities with identity, `record struct` for high-performance value objects.

DN11 — **ref, out, in:** `ref` passes by reference (must be initialized). `out` passes by reference (must be assigned inside method). `in` passes by reference for read-only (avoids copy for large structs). Use `in` for large structs passed to methods where mutation isn't needed.

DN12 — **Nullable Reference Types:** `string?` indicates a reference type that may be null (compiler warnings). `int?` is `Nullable<int>`, a value type wrapper. NRTs are static analysis hints; `int?` is runtime type safety. Enable via `#nullable enable` or project settings.

DN13 — **LINQ:** Language Integrated Query. **Method Syntax:** `list.Where(x => x > 5)` (fluent, lambda). **Query Syntax:** `from x in list where x > 5 select x` (SQL-like). **Deferred Execution:** Query isn't executed until enumerated (e.g., `foreach`, `ToList()`).

DN14 — **Generic Constraints:** Limit types for `T`. `where T : class` (reference), `where T : struct` (value), `where T : new()` (public parameterless constructor), `where T : IComparable<T>` (interface). Combine constraints to enforce multiple requirements (e.g., `where T : class, IDisposable`).

DN15 — **Abstract vs Interface:** Abstract class can have state (fields) and partial implementation. Interface defines a contract (no state pre-C# 8). **Default Interface Methods (C# 8+):** Allow interfaces to provide implementation, blurring the line but still not allowing state. Use Abstract for "is-a" with shared code, Interface for "can-do" capabilities.

DN16 — **Middleware Pipeline:** `app.Use()` adds middleware that can call `next()`. `app.Map()` branches the pipeline based on path. `app.Run()` is terminal (no `next`). Order matters: first added runs first. Exception Handling Middleware (`app.UseExceptionHandler`) wraps the pipeline to catch and handle errors globally.

DN17 — **Channel<T>:** Async producer-consumer queue. `BlockingCollection` is sync-blocking. **Bounded Channel:** Limits capacity; producers await when full (backpressure).
*Example:* `var channel = Channel.CreateBounded<int>(10);` Producer awaits `WriteAsync` when buffer is full.

DN18 — **Source Generators:** Compile-time code generation (Roslyn). Faster than reflection (no runtime cost) and safer than IL weaving (compile-time errors). **Incremental Generators:** Cache previous results and only re-run on changes, drastically improving build times compared to `ISourceGenerator`.

DN19 — **TPL Dataflow:** High-level pipeline library. `ActionBlock` (sink/consumer), `TransformBlock` (map), `BufferBlock` (queue). Compared to `Channels`: Dataflow offers built-in linking, propagation of completion, and options (max degree of parallelism), while Channels are lower-level and more flexible for custom backpressure logic.

DN20 — **Minimal APIs:** `app.MapGet("/path", () => "Hello")`. Less boilerplate than Controllers (no classes/attributes). **Trade-offs:** Harder to unit test (integration tests preferred), less structured middleware support. **Route Groups:** `app.MapGroup("/api")` prefixes routes. **Endpoint Filters:** Middleware-like logic specific to endpoints (e.g., logging, auth).

P1 — **List vs Tuple, Set vs Frozenset:** List is mutable, Tuple is immutable. Set is mutable and unordered, Frozenset is immutable and hashable. Use Tuples/Frozensets as dictionary keys or for fixed data structures.

P2 — **GIL:** Global Interpreter Lock prevents multiple native threads from executing Python bytecode simultaneously. Affects CPU-bound multithreading. Workarounds: `multiprocessing` (separate processes), C-extensions (release GIL), or async I/O for I/O-bound tasks.

P3 — **Deep vs Shallow Copy:** `copy()` creates a new object but references nested objects (shallow). `deepcopy()` recursively copies nested objects. **Example:** `list_a = [[1]]; list_b = copy(list_a); list_b[0].append(2)` modifies `list_a` too.

P4 — **Decorators:** Wrapper function that modifies behavior.
```python
import time, functools
def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        res = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start}")
        return res
    return wrapper
```

P5 — **Generators:** Functions that yield values one at a time (lazy). `yield` pauses execution. `yield from` delegates to another generator. Differ from lists by not storing all data in memory, enabling infinite sequences.

P6 — **Asyncio:** Event loop manages coroutines. `asyncio.run()` starts the loop. `gather()` waits for multiple tasks concurrently. `create_task()` schedules a coroutine. `time.sleep()` blocks the loop; use `await asyncio.sleep()` to yield control.

P7 — **MRO:** Method Resolution Order uses C3 Linearization. Order: D -> B -> C -> A. `D().who()` searches D (no), B (no), C (yes). Prints "C". Diamond inheritance resolves ambiguity by prioritizing left-to-right in inheritance list.

P8 — **Metaclass:** Class of a class (controls class creation). `__init_subclass__` is a hook called when a class is subclassed (simpler, no metaclass needed). **Use Case:** Metaclass for enforcing API contracts across many classes; `__init_subclass__` for registering subclasses automatically.

P9 — **Multiprocessing vs Threading:** Threading shares memory (GIL limited, good for I/O). Multiprocessing has separate memory (true parallelism, good for CPU). `concurrent.futures` abstracts both. **Serialization:** Multiprocessing requires arguments to be picklable (cannot pass lambdas/threads).

P10 — **__slots__:** Declares fixed attributes, preventing `__dict__` creation. Saves memory (approx 40-50% reduction for many instances). Prevents dynamic attribute assignment. Use for memory-intensive classes with fixed attributes.

P11 — **Virtual Environment:** Isolated Python environment for dependencies. `venv` (stdlib, Python 3.3+), `virtualenv` (third-party, faster), `conda` (package manager + env, handles non-Python libs). Use to avoid dependency conflicts.

P12 — **Comprehensions:** Concise syntax for creating lists/dicts/sets (`[x for x in y]`). Faster than `map/filter` loops. Prefer for readability and performance unless logic is complex.

P13 — **== vs is:** `==` checks value equality. `is` checks identity (same memory address). **Interning:** Python caches small integers (-5 to 256) and some strings, so `a is b` may be True for them even if created separately.

P14 — **args/kwargs:** `*args` collects positional args as tuple. `**kwargs` collects keyword args as dict. `/` enforces positional-only args. `*` enforces keyword-only args.

P15 — **Context Managers:** Manage resources (`with open...`). `__enter__`/`__exit__` defines class behavior. `@contextmanager` decorator wraps a generator. **Example:** Database transaction commit/rollback.

P16 — **Type Hinting:** Static type annotations. `Union[A, B]` (A or B), `Optional[A]` (A or None), `Literal[1]` (specific value), `TypeVar` (generic), `Protocol` (structural typing). `mypy`/`pyright` check types without running code.

P17 — **Data Model:** Dunder methods define behavior. `__repr__` (debug), `__str__` (user). `__eq__` defines equality; defining `__eq__` sets `__hash__` to None (unhashable) unless explicitly defined. `__getattr__` (attribute missing), `__getattribute__` (all attribute access).

P18 — **Descriptors:** Objects defining `__get__`, `__set__`, `__delete__`. Control attribute access. `property` is a descriptor for managed attributes. `classmethod`/`staticmethod` are descriptors that bind methods to class or unbound.

P19 — **Import System:** `sys.path` searches for modules. `__init__.py` marks packages (optional for namespace). Relative (`.`) vs Absolute (`pkg.module`). **Finder:** Locates module. **Loader:** Executes module code. Namespace packages allow splitting packages across directories.

P20 — **Dataclasses:** Auto-generate `__init__`, `__repr__`, etc. `attrs` is more feature-rich; `Pydantic` adds validation. `__post_init__` runs after init. **Frozen:** Immutable. **Choice:** Use Pydantic for API validation (JSON parsing), dataclasses for internal data structures.
