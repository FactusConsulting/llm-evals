

## JavaScript / TypeScript

**JS1 — Easy:**
`var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but reside in the Temporal Dead Zone (TDZ) until declaration. Hoisting is the mechanism where declarations are moved to the top of their scope during compilation. `const` requires initialization at declaration.

**JS2 — Easy:**
The event loop manages execution concurrency. It prioritizes the **Call Stack** (synchronous code). Once empty, it processes the **Microtask Queue** (Promises, `queueMicrotask`) before the **Macrotask Queue** (setTimeout, I/O, UI rendering). Microtasks run to completion before the next macrotask.

**JS3 — Medium:**
A closure is a function bundled with its lexical environment, allowing access to outer variables after the outer function returns.
*Bug:* Loop `var` is shared across iterations.
*Fix:* Use `let` (block scope) or an IIFE to create a new scope per iteration.
```javascript
// Bug
for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i), 100); } // 3, 3, 3
// Fix
for (let i = 0; i < 3; i++) { setTimeout(() => console.log(i), 100); } // 0, 1, 2
```

**JS4 — Medium:**
`Promise` represents a future value. `async/await` is syntactic sugar over Promises. Errors in Promises use `.catch()`; in `async/await`, use `try/catch`.
`Promise.all` fails fast if any promise rejects. `Promise.allSettled` waits for all to finish, returning status (fulfilled/rejected) for each.

**JS5 — Medium:**
`interface` is extensible (declaration merging) and preferred for defining object shapes in libraries. `type` supports unions, primitives, and tuples. Use `interface` for public APIs, `type` for complex types.
**Discriminated Unions:** A union of objects with a common literal property (tag) used to narrow types in `switch` statements.

**JS6 — Medium:**
JavaScript uses prototypal inheritance: objects delegate to a prototype object. `Object.create(proto)` creates an object with `proto` as its `[[Prototype]]`. ES6 `class` is syntactic sugar; `extends` sets up the prototype chain, and `super` calls the parent constructor.

**JS7 — Hard:**
`this` refers to the execution context. Binding rules (priority):
1. `new` binding (constructor).
2. Explicit binding (`call`, `apply`, `bind`).
3. Implicit binding (method call `obj.method()`).
4. Default binding (global/undefined in strict mode).
`bind()` returns a new function with `this` permanently bound. It cannot be re-bound.

**JS8 — Medium:**
`WeakRef` holds a weak reference to an object, allowing GC to collect it. `FinalizationRegistry` registers callbacks to run after an object is GC'd. `WeakMap` keys must be objects because primitives cannot be weakly referenced (they are value-based, not identity-based), enabling GC of keys when no other references exist.

**JS9 — Hard:**
V8 uses JIT compilation. **Hidden Classes** optimize property access by tracking object shapes. **Inline Caching** caches lookup locations for properties. **Deoptimization** occurs when assumptions break (e.g., adding properties dynamically, using `eval`, or mixing types), forcing fallback to slower interpreter code.

**JS10 — Medium:**
Tree-shaking removes unused code. It works with **ES Modules** because imports/exports are static and analyzable at build time. **CommonJS** uses dynamic `require()`, making static analysis impossible, so unused code often remains bundled.

**JS11 — Easy:**
`null` is an assignment value (no value). `undefined` means uninitialized. `==` coerces types (`null == undefined` is true). `===` checks type and value (`null === undefined` is false). `??` returns right side if left is `null`/`undefined`. `?.` safely accesses nested properties without throwing.

**JS12 — Easy:**
`map()` transforms elements. `filter()` selects elements. `reduce()` accumulates values (initial value prevents undefined first iteration). `flatMap()` maps then flattens one level; useful for transforming arrays into single-level arrays.

**JS13 — Easy:**
Template literals use backticks (`` ` ``), support interpolation (`${}`), and multiline strings. **Tagged templates** pass string parts and values to a function.
```javascript
function safe(strings, ...values) {
  return strings.reduce((acc, str, i) => acc + str + escape(values[i]), '');
}
```

**JS14 — Easy:**
Destructuring unpacks values from arrays/objects.
```javascript
const { a, b = 1 } = obj; // Object
const [x, ...rest] = arr; // Array
```
`...` (rest) gathers remaining elements. Default values assign if the property is `undefined`.

**JS15 — Easy:**
`for...in` iterates over enumerable **property keys** (including inherited). `for...of` iterates over **values** of iterable objects (arrays, strings). Avoid `for...in` on arrays due to order uncertainty and inherited properties.

**JS16 — Medium:**
**Generics** allow type parameters (`T`). **Constraints** (`extends`) limit types (e.g., `T extends string`). **Conditional Types** (`T extends U ? X : Y`) choose types based on conditions. **`infer`** extracts types within conditional types (e.g., extracting return type).

**JS17 — Medium:**
**CommonJS:** `require()`/`module.exports`, dynamic, synchronous. **ES Modules:** `import`/`export`, static, asynchronous. Node.js supports both via `.cjs`/`.mjs` extensions or `"type": "module"` in `package.json` (enables ESM).

**JS18 — Hard:**
TypeScript uses **structural typing** (duck typing). **Excess property checks** apply only to object literals assigned to variables/parameters. `extends` checks assignability; `satisfies` checks assignability but preserves literal types. **Variance** (4.7+) controls how generic types relate (in/out) for function parameters.

**JS19 — Hard:**
`Proxy` intercepts operations (get, set, has, apply). `Reflect` provides default behavior for these operations.
```javascript
const handler = { get(target, prop) { console.log(prop); return target[prop]; } };
const proxy = new Proxy(obj, handler);
```
Used for validation, logging, or reactivity.

**JS20 — Hard:**
`SharedArrayBuffer` allows shared memory between Web Workers. `Atomics` provides atomic operations (load, store, add, wait, notify). `Atomics.wait` blocks a worker until notified; `Atomics.notify` wakes waiters. Guarantees ordering via memory fences.

## Bash

**B1 — Easy:**
`$@` expands to separate arguments; `$*` expands to a single string. `"$@"` preserves argument boundaries (safe for loops); `"$*"` joins them with the first character of IFS (usually space).

**B2 — Easy:**
`set -e`: Exit on error. `set -u`: Error on unset variables. `set -o pipefail`: Pipeline fails if any command fails (not just the last).

**B3 — Medium:**
`$(command)` is preferred over `` `command` `` (nesting is easier). `$((expression))` is arithmetic expansion (internal); `expr` is an external command (slower, legacy).

**B4 — Medium:**
Process substitution `<(cmd)` creates a named pipe (e.g., `/dev/fd/63`).
```bash
diff <(sort file1) <(sort file2)
```
Useful when commands expect filenames but you want to feed stream output.

**B5 — Medium:**
`for f in $(ls)` breaks on spaces/newlines. Safe iteration:
```bash
for f in *; do ...; done
# or
find . -name "*.txt" -print0 | while IFS= read -r -d '' f; do ...; done
```

**B6 — Medium:**
`<<EOF` (Here Document) reads multiple lines until EOF. `<<<` (Here String) passes a single string to stdin. `<<-EOF` allows leading tabs to be stripped for indentation.

**B7 — Hard:**
1. `cmd > file 2>&1`: Stdout to file, then stderr to stdout (file). **Both to file.**
2. `cmd 2>&1 > file`: Stderr to original stdout (terminal), then stdout to file. **Stdout to file, stderr to terminal.**
3. `cmd &> file`: Bash shorthand for both to file.

**B8 — Hard:**
Use `mkdir` for locking (atomic).
```bash
lock_dir="/tmp/mylock"
trap 'rmdir "$lock_dir"' EXIT
mkdir "$lock_dir" || exit 1
# Do work
```
`mkdir` fails atomically if dir exists. `trap` ensures cleanup on SIGTERM/EXIT.

**B9 — Easy:**
`'...'` (Single): Literal, no expansion. `"..."` (Double): Expands vars/commands. No quotes: Word splitting/globbing.
Example: `echo $var` (expands), `echo '$var'` (prints literal).

**B10 — Easy:**
`-f` (file), `-d` (directory), `-r` (readable). `[[ ]]` is Bash-specific (safer, supports regex `=~`), `[ ]` is POSIX `test`.

**B11 — Easy:**
`$?`: Last exit code. `$$`: Current shell PID. `$!`: Last background PID. `$#`: Argument count.

**B12 — Easy:**
`function foo {}` vs `foo() {}` (mostly equivalent). Return values are exit codes (`return 0`). Output is via `echo`/`stdout`.

**B13 — Easy:**
`PATH` is a colon-separated list of directories searched for executables. `type cmd` shows if it's builtin, alias, or file. Builtin commands are part of the shell binary.

**B14 — Medium:**
`trap 'cmd' SIGNAL`. `EXIT` runs on script exit. `ERR` runs on error (if set). `INT`/`TERM` handle interrupts. Order: Signal handler runs, then script continues or exits.

**B15 — Medium:**
`xargs` builds command lines from stdin. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P N` runs N jobs in parallel.

**B16 — Medium:**
Indexed: `arr=(a b)`, `${arr[@]}`, `${#arr[@]}`. Associative: `declare -A arr`, `arr[key]=val`. Iterate: `for k in "${!arr[@]}"; do ...`.

**B17 — Hard:**
`(...)` Subshell: Forks, variables lost on exit. `{ ...; }` Group: Same shell, variables persist. Piping `while` creates a subshell, so variable changes inside loop are lost.

**B18 — Hard:**
`SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (terminal hangup), `SIGKILL` (uncatchable). Use `trap` to handle SIGTERM gracefully (cleanup, exit). Background jobs inherit traps unless ignored.

**B19 — Hard:**
Split log: `split -l 10000 large.log part_`. Process: `xargs -P 4 -I {} ./process.sh {}`. Merge: `cat part_* > result.log`. Errors: Check exit codes of parallel jobs (e.g., `set -o pipefail` or check `wait` status).

**B20 — Hard:**
`exec` replaces the current shell process. `exec 3>file` opens FD 3. `exec 3>&-` closes it. Coprocess (`coproc`) creates a bidirectional pipe for interactive communication with a background process.

## PowerShell

**PS1 — Easy:**
`Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console (bypasses pipeline). Use `Write-Output` for scripting/piping; `Write-Host` for user-facing logs.

**PS2 — Easy:**
Pipeline passes objects. `ForEach-Object` (cmdlet) processes stream items one-by-one (memory efficient). `foreach` (statement) iterates over a collection (loads all into memory). Use cmdlet for large streams.

**PS3 — Medium:**
`[PSCustomObject]` creates a strongly typed object. `[hashtable]` is a dictionary. Convert: `[PSCustomObject]$ht`. Use hashtable for dynamic keys, PSCustomObject for structured data/serialization.

**PS4 — Medium:**
Terminating errors stop execution (caught by `try/catch`). Non-terminating continue. `-ErrorAction Stop` forces non-terminating to terminate. `$ErrorActionPreference` sets global default.

**PS5 — Medium:**
Splatting passes a hashtable as parameters: `@params`. `Get-Command @params`. Differs from passing hashtable as a single argument (which would be `$params`).

**PS6 — Medium:**
`Invoke-Command` runs commands remotely (one-off). `Enter-PSSession` starts an interactive session. Uses WinRM (default) or SSH.

**PS7 — Hard:**
PowerShell unwraps single-item arrays. If 1 item, returns object. If 0 items, returns `$null`.
*Fix:* `return @($result)` or `Write-Output $result -NoEnumerate`.

**PS8 — Hard:**
`[scriptblock]` is code. Double-hop: Credentials don't forward to 3rd server. Solve with CredSSP authentication or `Invoke-Command -ArgumentList` (pass data, not creds).

**PS9 — Easy:**
`@()` forces array context. `[array]` casts. `$null[0]` returns `$null`. Empty array `@()[0]` returns `$null`.

**PS10 — Easy:**
`-eq` (case-insensitive), `-ceq` (case-sensitive). `-contains` checks if collection has item. `-in` checks if item is in collection (reverse). `-like` uses wildcards.

**PS11 — Easy:**
Module = package. `.psm1` (script code), `.psd1` (manifest metadata), `.dll` (binary). `Import-Module` loads them.

**PS12 — Easy:**
`"..."` interpolates `$var`. `'...'` literal. `$()` inserts expressions. Here-string: `@" ... "@` for multiline strings.

**PS13 — Easy:**
`Get-Member` (gm) inspects object properties/methods. `Select-Object` selects properties. `Where-Object` filters objects. `NoteProperty` = custom property added at runtime.

**PS14 — Medium:**
Classes (v5+) define types. Limited inheritance (no multiple). Use for data models. Functions are better for logic/automation.

**PS15 — Medium:**
`[CmdletBinding()]` enables advanced features (parameters, help). `SupportsShouldProcess` adds `-WhatIf`. `Begin/Process/End` blocks handle pipeline streaming.

**PS16 — Medium:**
Providers abstract data stores (FileSystem, Registry). `Get-ChildItem` works on `HKLM:`. Access registry: `Get-ItemProperty HKLM:\Software\...`.

**PS17 — Hard:**
Runspaces = threads. `ForEach-Object -Parallel` (v7) manages runspaces automatically. Manual runspace pools offer more control but require thread-safe code.

**PS18 — Hard:**
PSScriptAnalyzer = static analysis/linting. Rules check best practices. Severity: Error, Warning, Info. Suppress with `[Diagnostics.CodeAnalysis.SuppressMessageAttribute]`. CI: Fail build on errors.

**PS19 — Hard:**
`$using:` copies local vars to remote scope. `-ArgumentList` passes args. Serialization (CLIXML) has depth limits; complex objects may fail or lose methods.

**PS20 — Hard:**
DSC = declarative config. Resources define state. LCM applies config. Legacy in modern infra; replaced by Terraform, Ansible, Azure Bicep, or ARM templates.
