## JavaScript / TypeScript

**JS1**: `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped; `let` allows reassignment, `const` does not. **Hoisting** is the JS engine's behavior of moving declarations to the top of their scope during the compilation phase.

**JS2**: The **Event Loop** manages the execution of multiple chunks of your script. The **Call Stack** handles synchronous code. When an async operation finishes, it enters a queue. **Microtasks** (Promises, `queueMicrotask`) have higher priority and are cleared entirely before the **Macrotask queue** (setTimeout, setInterval, I/O) is processed.

**JS3**: A **closure** is a function that remembers the lexical environment in which it was created. *Example*: A function returning another function that increments a private counter. *Bug*: Using `var` in a `for` loop creates one variable for all iterations. *Fix*: Use `let` (creates a new binding per iteration) or an IIFE.

**JS4**: `Promise` represents a future value. `async/await` is syntactic sugar for Promises. Error handling: `.catch()` for Promises, `try/catch` for `await`. `Promise.all` rejects immediately if any promise fails; `Promise.allSettled` waits for all to complete regardless of outcome.

**JS5**: `interface` is primarily for defining object shapes and supports declaration merging (extending via multiple interfaces). `type` is more flexible (unions, primitives, tuples). **Discriminated Unions** use a common literal property (e.g., `type: 'circle' | 'square'`) to allow TypeScript to narrow the type in a switch/if block.

**JS6**: JS uses **prototypal inheritance**: objects inherit from other objects via a prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is "syntactic sugar" over prototypes; it defines methods on the prototype and uses `super()` to link to the parent prototype.

**JS7**: `this` refers to the execution context. **Binding Rules (Priority)**: 1. `new` (constructor), 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (object method), 4. Default (`window`/`undefined` in strict mode). `bind()` returns a new function with `this` fixed; it cannot be re-bound.

**JS8**: `WeakRef` allows a reference to an object without preventing GC. `FinalizationRegistry` triggers a callback after an object is GC'd. `WeakMap` keys must be objects because the map holds a "weak" reference to the key; if the key is only held by the WeakMap, it can be garbage collected.

**JS9**: V8 uses **Hidden Classes** (Shapes) to track object layouts. **Inline Caching (IC)** remembers where properties are located to skip lookup. **Deoptimization** occurs when an object's "shape" changes (e.g., adding properties in a different order), forcing V8 to drop optimized machine code and return to interpreted bytecode.

**JS10**: **Tree-shaking** is the removal of unused code. ESM (`import/export`) is statically analyzable, allowing tools to determine what is unused. CommonJS (`require`) is dynamic (can be inside an `if` block), making it nearly impossible for bundlers to safely remove "unused" code.

**JS11**: `undefined` means a variable was declared but not assigned; `null` is an intentional assignment of "no value." `==` performs type coercion; `===` is strict. `??` (nullish coalescing) returns the RHS only if LHS is `null` or `undefined`. `?.` (optional chaining) short-circuits if the chain is `null`/`undefined`.

**JS12**: `map` transforms each element; `filter` removes elements; `reduce` aggregates into a single value. `reduce` with an initial value uses that as the starting accumulator. `flatMap` maps then flattens the result by one level, useful for mapping one element to zero or many.

**JS13**: Template literals use backticks (`` ` ``) for interpolation. **Tagged templates** pass the string parts and interpolated values to a function. *Example*: `sql`SELECT * FROM users WHERE id = ${id}` could be a tag that automatically escapes the `id` to prevent SQL injection.

**JS14**: **Destructuring** unpacks values from arrays/objects. `const {name, age = 20} = user` (object), `const [first, ...rest] = arr` (array). The **rest operator** (`...`) collects remaining elements into a new array/object.

**JS15**: `for...in` iterates over enumerable keys (including prototype chain); `for...of` iterates over iterable values. Avoid `for...in` on arrays because it iterates indices as strings and may pick up inherited properties.

**JS16**: **Generics** allow types to be passed as parameters. `extends` constrains a type (e.g., `T extends string`). **Conditional types** (`T extends U ? X : Y`) choose a type based on a condition. `infer` extracts a type from a pattern (e.g., extracting the return type of a function).

**JS17**: **CommonJS** (`require`) is synchronous and used in Node.js. **ESM** (`import`) is static and standard. Node.js handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM.

**JS18**: TS is **structural**: if it looks like a duck, it's a duck. **Excess property checks** occur only on object literals passed directly to a typed parameter. `satisfies` validates a type without narrowing the variable's type. **Variance**: Covariance (out) allows subtypes; Contravariance (in) allows supertypes.

**JS19**: `Proxy` intercepts operations (get, set, apply) on an object. `Reflect` provides a mirror API to perform the default behavior of those operations. *Example*: A Proxy can be used for **reactive data binding** by triggering a UI update whenever a `set` trap is triggered.

**JS20**: `SharedArrayBuffer` allows memory sharing between Workers. `Atomics` provides atomic operations (add, load, store) to prevent race conditions. `Atomics.wait` puts a thread to sleep until `Atomics.notify` wakes it up, enabling low-latency synchronization.

## Bash

**B1**: `$*` expands to all arguments as a single string. `$@` expands to all arguments as separate words. `"$*"` is one quoted string; `"$@"` preserves the original quoting/spacing of each individual argument.

**B2**: `set -e` (exit immediately if a command fails), `-u` (exit if an unset variable is referenced), `-o pipefail` (the pipeline return status is the status of the last command to exit with a non-zero status).

**B3**: `$(command)` is the modern syntax for command substitution; `` `command` `` is the legacy version (harder to nest). `$((expression))` is for integer arithmetic; `expr` is an external utility that is slower and requires more quoting.

**B4**: **Process substitution** `<(command)` makes the output of a command appear as a file. *Example*: `diff <(ls dir1) <(ls dir2)` compares the directory listings without creating temporary files.

**B5**: Use `find . -print0 | xargs -0` or `while IFS= read -r -d '' file`. `for f in $(ls)` is dangerous because it performs word splitting on spaces/newlines in filenames.

**B6**: `<<EOF` is a **here-document** (multiline input). `<<<` is a **here-string** (passes a single string to stdin). `<<-EOF` strips leading tab characters from the input lines.

**B7**: `cmd > file 2>&1` (stdout to file, then stderr to stdout $\rightarrow$ both in file). `cmd 2>&1 > file` (stderr to stdout, then stdout to file $\rightarrow$ stderr goes to screen, stdout to file). `&> file` is a bashism that redirects both.

**B8**: Use `mkdir lockdir` because it is an atomic operation at the OS level (unlike `touch` which can have race conditions). Use `trap 'rmdir lockdir' EXIT` to ensure cleanup on SIGTERM/EXIT.

**B9**: `'...'` (literal, no expansion), `"..."` (allows variable/command expansion), no quotes (allows word splitting and globbing). *Example*: `echo "$VAR"` vs `echo $VAR` (the latter splits if `$VAR` contains spaces).

**B10**: `-f` (file), `-d` (directory), `-r` (readable). `[ ]` is the POSIX `test` command; `[[ ]]` is a Bash keyword that supports regex (`=~`), avoids word splitting, and is generally safer.

**B11**: `$?` (exit status of last cmd), `$$` (PID of current shell), `$!` (PID of last background process), `$#` (number of positional arguments).

**B12**: `foo() { ... }` is standard; `function foo { ... }` is Bash-specific. Functions return an exit status (0-255) via `return`. To return data, `echo` the result and capture it via `$(foo)`.

**B13**: `PATH` is a colon-separated list of directories searched for executables. **Builtins** (e.g., `cd`) run inside the shell; **External** (e.g., `ls`) are binaries. Use `type -a <cmd>` to check.

**B14**: `trap 'cmd' SIGNAL` executes `cmd` when `SIGNAL` is received. Common: `EXIT`, `ERR`, `INT`, `TERM`. If multiple signals arrive, they are queued; the trap handler runs sequentially.

**B15**: `xargs` reads from stdin; command substitution `$(...)` captures output. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P N` runs $N$ processes in parallel.

**B16**: Arrays: `arr=(1 2)`, `${arr[0]}`. Associative: `declare -A map`, `map[key]=val`. Iterate with `for i in "${arr[@]}"`. Length is `${#arr[@]}`.

**B17**: `(...)` is a subshell (forks process, variables don't leak back). `{ ... }` is a group (same process). Piping into a `while` loop creates a subshell, meaning variables modified inside the loop are lost.

**B18**: `SIGINT` (Ctrl+C), `SIGTERM` (polite request to stop), `SIGHUP` (terminal closed), `SIGKILL` (forced, cannot be trapped). Handle graceful shutdown by trapping `SIGTERM` and killing child PIDs.

**B19**: `split -l 1000 log.txt` $\rightarrow$ `xargs -P 4 -n 1 ./process_chunk` $\rightarrow$ `cat results_*`. Trade-off: Parallelism increases speed but can saturate I/O. Error propagation: check exit codes of the `xargs` process.

**B20**: `exec` replaces the current shell process with the new command. `exec 3>file` opens file descriptor 3 for writing. A **coprocess** (`coproc`) creates a two-way pipe for bidirectional communication between the shell and a background process.

## PowerShell

**PS1**: `Write-Output` sends objects to the pipeline (can be captured). `Write-Host` writes directly to the console (cannot be captured/piped).

**PS2**: The pipeline passes objects, not text. `ForEach-Object` is a pipeline cmdlet (lazy evaluation); `foreach` is a language statement (faster, loads all into memory first).

**PS3**: `[PSCustomObject]` is an ordered object with properties; `[hashtable]` is an unordered key-value pair. Convert: `[PSCustomObject]$hash` or `(Get-PSCustomObject).GetEnumerator()`.

**PS4**: **Terminating errors** stop execution; **Non-terminating** (e.g., file not found) continue. `-ErrorAction Stop` converts non-terminating to terminating. `try/catch` only catches terminating errors.

**PS5**: **Splatting** passes a hashtable of parameters using `@params` instead of `$params`. It makes code cleaner than passing 10 individual arguments.

**PS6**: `Invoke-Command` runs a script block on remote machines; `Enter-PSSession` starts an interactive session. It uses **WinRM** (WS-Man) or **SSH**.

**PS7**: PowerShell unrolls arrays. If `Get-Items` returns 1 item, `$x` is that item. If 2, it's an array. If 0, it's `$null`. **Correct pattern**: Force array with `@(Get-Items)`.

**PS8**: A `[scriptblock]` is a piece of code `{...}` that can be passed as an object. **Double-hop**: A remote session cannot pass credentials to a second remote machine. Solve via **CredSSP** or `-Authentication` delegation.

**PS9**: `@()` is the array creation operator; `[array]` is the type. `@()` ensures the result is an array even if the command returns a single item. Indexing `$null` returns `$null`; indexing an empty array returns `$null`.

**PS10**: `-eq` (equal), `-like` (wildcard `*`), `-match` (regex). Case-insensitive by default; use `-ceq` for case-sensitive. `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection.

**PS11**: A module is a package of functions/classes. `.psm1` (code), `.psd1` (manifest/metadata). `Import-Module` loads the module into the current session.

**PS12**: `"..."` interpolates; `'...'` is literal. Use `"$($expression)"` for complex expressions. Here-strings `@" ... "@` allow multi-line literals.

**PS13**: `Get-Member` shows properties/methods of an object. **Properties** are data; **Methods** are actions; **NoteProperties** are added dynamically. `Select-Object` filters columns; `Where-Object` filters rows.

**PS14**: PS Classes (v5+) provide basic OOP. They lack full C# interface support. Use classes for structured data models and functions for operational logic.

**PS15**: `[CmdletBinding()]` makes a function an "Advanced Function." `SupportsShouldProcess` enables `-WhatIf`/`-Confirm`. `Begin`, `Process`, and `End` blocks handle pipeline streaming.

**PS16**: Providers map different data stores to a drive-like interface. `Get-ChildItem` works on `HKLM:\` (Registry) just like `C:\` (FileSystem).

**PS17**: A **Runspace** is an isolated execution environment (thread). `ForEach-Object -Parallel` (v7) simplifies this by managing a runspace pool automatically for parallel execution.

**PS18**: `PSScriptAnalyzer` is a static analysis tool. It uses rules (e.g., "Avoid using `Write-Host`) with severity levels. Integrate into CI/CD to fail builds on linting errors.

**PS19**: `$using:var` injects a local variable into a remote/parallel scope. Serialization limits (CLIXML) mean very deep or complex objects may lose data or fail to serialize when sent over the network.

**PS20**: **DSC** is declarative (defines "what" the state should be). The **LCM** (Local Configuration Manager) enforces the state. Modern infrastructure-as-code (Terraform/Ansible) has largely replaced it for cloud-scale orchestration.
