## JavaScript / TypeScript

**JS1**: `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and exist in a "Temporal Dead Zone" until declared. `const` prevents re-assignment of the identifier. **Hoisting** is the JS engine's behavior of moving declarations to the top of their scope during the compilation phase.

**JS2**: The **Event Loop** manages the execution of code, collecting and processing events, and executing queued sub-tasks. 
- **Call Stack**: Where synchronous code is executed (LIFO).
- **Microtask Queue**: Higher priority; handles `Promise` callbacks and `queueMicrotask`. Processed immediately after the current stack clears and before the next macrotask.
- **Macrotask Queue**: Lower priority; handles `setTimeout`, `setInterval`, and I/O. Processed one at a time per loop iteration.

**JS3**: A **closure** is a function that remembers its lexical scope even when executed outside that scope. 
*Example*: A function returning another function that increments a private counter.
*Loop Bug*: Using `var` in a `for` loop with `setTimeout` causes all callbacks to see the final value of the variable. 
*Fix*: Use `let` (which creates a new binding for every iteration) or an IIFE.

**JS4**: A **Promise** represents the eventual completion (or failure) of an async operation. `async/await` is syntactic sugar over Promises, making async code look synchronous. 
- **Error Handling**: Promises use `.catch()`; `async/await` uses `try/catch`.
- **Promise.all**: Rejects immediately if *any* promise fails.
- **Promise.allSettled**: Waits for *all* promises to complete regardless of whether they fulfilled or rejected.

**JS5**: `interface` is primarily for defining object shapes and supports "declaration merging" (adding fields to the same interface across files). `type` is a type alias and can define primitives, unions, and tuples. 
- **Use Interface**: For public APIs and object structures. 
- **Use Type**: For complex unions or utility types. 
- **Discriminated Unions**: A type that includes a common literal property (a "tag") used to narrow the type in a switch/if block.

**JS6**: JS uses **prototypal inheritance**, where objects inherit directly from other objects via a prototype chain. `Object.create(proto)` creates a new object with the specified prototype. **ES6 Classes** are "syntactic sugar"; they still use prototypes under the hood, but provide a cleaner `class`/`extends` syntax.

**JS7**: `this` refers to the execution context. 
**Binding Rules (Priority)**: 1. `new` binding, 2. Explicit binding (`call`, `apply`, `bind`), 3. Implicit binding (object method), 4. Default binding (global/undefined). 
`bind()` returns a **new function** with `this` permanently bound. Once bound, it cannot be re-bound.

**JS8**: `WeakRef` allows holding a reference to an object without preventing its garbage collection (GC). `FinalizationRegistry` lets you register a callback to run after an object is GC'd. 
**WeakMap keys** must be objects because the map holds a "weak" reference to the key; if the key object is otherwise unreachable, it can be GC'd, and the entry is automatically removed.

**JS9**: V8 optimizes via:
- **Hidden Classes (Shapes)**: Assigns a hidden class to objects with the same properties in the same order.
- **Inline Caching (IC)**: Remembers where a property was found in a hidden class to skip lookup next time.
- **Deoptimization**: Occurs when the engine's assumptions fail (e.g., changing the "shape" of an object by adding properties in a different order or changing types).

**JS10**: **Tree-shaking** is the removal of unused code during the build process. 
- **ES Modules (ESM)**: Use static `import`/`export`, allowing the bundler to determine exactly what is used at compile time.
- **CommonJS (CJS)**: Uses dynamic `require()`, meaning dependencies are resolved at runtime, making it nearly impossible for tools to safely determine what code is unused.

**JS11**: `null` is an intentional assignment of "no value"; `undefined` means a variable has been declared but not yet assigned. 
- `null == undefined` is `true` (coercion); `null === undefined` is `false`.
- `??` (Nullish Coalescing): Returns RHS only if LHS is `null` or `undefined`.
- `?.` (Optional Chaining): Short-circuits and returns `undefined` if the reference is nullish.

**JS12**: 
- `map()`: Creates a new array by transforming every element.
- `filter()`: Creates a new array with elements that pass a predicate.
- `reduce()`: Accumulates array values into a single value. The initial value serves as the starting point for the accumulator.
- `flatMap()`: Maps each element and then flattens the result by one level. Useful for removing elements (returning `[]`) or expanding one element into many.

**JS13**: **Template literals** use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** are functions that parse template literals. 
*Example*: `sql`tag`SELECT * FROM users WHERE id = ${id}`. The function receives the string parts and the interpolated values separately, allowing it to sanitize the input to prevent SQL injection.

**JS14**: **Destructuring** unpacks values from arrays or objects into variables.
- **Object**: `const { name, age: userAge } = user;` (renaming `age` to `userAge`).
- **Array**: `const [first, second = 'default'] = arr;` (default value).
- **Rest**: `const { a, ...rest } = obj;` collects remaining properties into a new object.

**JS15**: `for...in` iterates over **enumerable keys** (including inherited ones). `for...of` iterates over **iterable values** (arrays, maps, sets). 
Avoid `for...in` on arrays because it iterates over indices as strings and may include custom properties added to the `Array.prototype`.

**JS16**: **Generics** allow components to work over a variety of types.
- **Constraints**: `<T extends string>` ensures `T` is a string or subtype.
- **Conditional Types**: `T extends string ? 'yes' : 'no'` chooses a type based on a condition.
- **Infer**: `type GetReturnType<T> = T extends (...args: any[]) => infer R ? R : any` extracts a type from another type.

**JS17**: 
- **CommonJS**: `require`/`module.exports`. Synchronous. Standard in older Node.js.
- **ESM**: `import`/`export`. Asynchronous/Static. Standard in browsers and modern Node.
- **Node.js**: Handles both. `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM. Otherwise, `.mjs` is ESM and `.cjs` is CommonJS.

**JS18**: **Structural Typing** means if two types have the same shape, they are compatible, regardless of their name. 
- **Excess Property Checks**: Occur when assigning an object literal directly to a type; TS prevents adding properties not defined in the type.
- **extends vs satisfies**: `extends` creates a subtype; `satisfies` validates that a value matches a type without widening the type (preserving the most specific type).
- **Variance**: Covariance (out) allows a more specific type; Contravariance (in) allows a more general type.

**JS19**: **Proxy** wraps an object to intercept operations (get, set, etc.). **Reflect** provides methods that mirror Proxy traps.
*Example*: A reactive state object where the `set` trap triggers a UI re-render whenever a property is changed.

**JS20**: `SharedArrayBuffer` provides a memory area shared between the main thread and Web Workers. `Atomics` provides atomic operations (add, load, store) to prevent race conditions. `Atomics.wait` puts a thread to sleep until a value changes, and `Atomics.notify` wakes it up.

## Bash

**B1**: `$*` and `$@` both represent all positional parameters. 
- `"$*"`: Expands to a single string, joined by the first character of `IFS`.
- `"$@"`: Expands to separate quoted strings (preserves spaces/arguments exactly as passed).

**B2**: `set -euo pipefail`
- `-e`: Exit immediately if a command exits with a non-zero status.
- `-u`: Treat unset variables as an error and exit.
- `-o pipefail`: The return value of a pipeline is the status of the last command to exit with a non-zero status, or zero if all exit successfully.

**B3**: `$(command)` is the modern syntax for command substitution; it is nestable and more readable than the legacy backticks `` `command` ``. `$((expression))` is for shell arithmetic (fast, internal); `expr` is an external binary and slower.

**B4**: **Process Substitution** `<(command)` allows the output of a command to be treated as a file. 
*Example*: `diff <(ls dir1) <(ls dir2)` compares the file lists of two directories without creating temporary files.

**B5**: Use `while IFS= read -r line` or `find -print0 | xargs -0`. `for f in $(ls)` is dangerous because it performs word splitting on the output of `ls`, breaking filenames containing spaces or newlines.

**B6**: 
- **Here-doc** (`<<EOF`): Redirects a multi-line block of text to a command.
- **Here-string** (`<<<`): Redirects a single string to a command.
- `<<-EOF`: Strips leading tab characters from the input lines (useful for indentation).

**B7**: 
- `cmd > file 2>&1`: Stdout goes to `file`, then stderr is redirected to where stdout is currently going (`file`). Result: both in `file`.
- `cmd 2>&1 > file`: Stderr is redirected to current stdout (the screen), then stdout is redirected to `file`. Result: stderr on screen, stdout in `file`.
- `cmd &> file`: Bash shortcut to redirect both stdout and stderr to `file`.

**B8**: Use `mkdir lockdir` because it is an atomic operation at the OS level.
```bash
lock_dir="/tmp/myscript.lock"
cleanup() { rm -rf "$lock_dir"; exit; }
trap cleanup SIGTERM SIGINT EXIT
if mkdir "$lock_dir" 2>/dev/null; then
    # critical section
else
    echo "Locked"; exit 1
fi
```

**B9**: 
- `'...'` (Single): Literal string. No expansion.
- `"..."` (Double): Interpolates variables and commands.
- No quotes: Subject to word splitting and globbing.
*Example*: `echo "$VAR"` vs `echo '$VAR'`. The first prints the value; the second prints the literal characters `$VAR`.

**B10**: `-f` (file exists), `-d` (is directory), `-r` (is readable). 
`[ ]` is the POSIX standard `test` command. `[[ ]]` is a Bash extension that supports regex (`=~`), logical operators (`&&`, `||`) without escaping, and doesn't require quoting variables to prevent word splitting.

**B11**: 
- `$?`: Exit status of last command (use for error checking).
- `$$`: PID of current shell (use for unique temp files).
- `$!`: PID of last background process (use for `wait`).
- `$#`: Number of positional arguments (use for input validation).

**B12**: Defined as `foo() { ... }` or `function foo { ... }`. The former is POSIX compliant. Functions return an exit status (0-255) via `return`. To return data, use `echo` and capture it with command substitution: `result=$(foo)`.

**B13**: `PATH` is a colon-separated list of directories the shell searches for executables. 
- **Builtin**: Internal to the shell (e.g., `cd`, `echo`).
- **External**: A binary file on disk (e.g., `ls`, `grep`).
- Check using `type -a <command>`.

**B14**: `trap` catches signals and executes a command. 
`trap 'cleanup_func' EXIT ERR INT TERM`. 
Execution order: Signals are handled as they arrive. `EXIT` is a pseudo-signal that triggers whenever the shell exits, regardless of the cause.

**B15**: Command substitution `$(...)` returns the output as a string. `xargs` converts stdin into arguments for a command. 
- `find . -print0 | xargs -0 rm`: Handles spaces/newlines by using the null character as a delimiter.
- `xargs -P <num>`: Runs up to `<num>` processes in parallel.

**B16**: 
- **Indexed**: `arr=(a b c)`; append: `arr+=("d")`; length: `${#arr[@]}`; iterate: `for i in "${arr[@]}"`.
- **Associative**: `declare -A assoc`; `assoc[key]="val"`; iterate: `for k in "${!assoc[@]}"`.
Associative arrays allow string keys, whereas indexed arrays only allow integers.

**B17**: 
- **Subshell** `(...)`: Runs in a separate process. Variable changes are lost to the parent.
- **Group** `{ ...; }`: Runs in the current process. Variable changes persist.
Piping into a `while` loop (`cmd | while...`) creates a subshell, so variables modified inside the loop are lost once the loop ends.

**B18**: 
- `SIGINT`: Interrupt (Ctrl+C).
- `SIGTERM`: Termination request (polite kill).
- `SIGHUP`: Hangup (terminal closed).
- `SIGKILL`: Immediate kill (cannot be trapped).
Graceful shutdown: Use `trap` to catch `SIGTERM` and kill background PIDs stored in a variable.

**B19**: 
```bash
split -l 1000 large.log chunk_
export -f process_func
ls chunk_* | xargs -P 4 -I {} bash -c 'process_func "{}" > "{}.out"'
cat *.out > final_result
```
Trade-offs: Disk I/O for chunks vs memory. Error propagation: `xargs` returns non-zero if any process fails, but specific failures must be logged to files.

**B20**: `exec` replaces the current shell process with the new command (no return to shell). 
- **FD Manipulation**: `exec 3>file` opens FD 3 for writing to `file`; `exec 3>&-` closes it.
- **Coprocess**: `coproc myproc { ... }` creates a background process with two-way communication via pipes (`myproc` variable holds the FD).

## PowerShell

**PS1**: `Write-Output` sends objects to the pipeline (can be captured or passed to another cmdlet). `Write-Host` writes directly to the console host (bypasses the pipeline), making it useless for data processing.

**PS2**: The pipeline passes objects from one cmdlet to the next. 
- `ForEach-Object`: A pipeline cmdlet; processes objects one-by-one as they arrive (streaming).
- `foreach` statement: A language keyword; loads the entire collection into memory first, then iterates. Use `foreach` for speed on small sets, `ForEach-Object` for large datasets.

**PS3**: `[hashtable]` is a key-value pair collection (unordered by default). `[PSCustomObject]` is a structured object with properties. 
- **Use Hashtable**: For lookups or passing parameters (splatting).
- **Use PSCustomObject**: For returning data from functions.
- **Convert**: `[PSCustomObject]$myHash` or `New-Object PSObject -Property $myHash`.

**PS4**: 
- **Non-terminating**: Error occurs, but the script continues (e.g., `Get-Item` on a missing file).
- **Terminating**: Stops execution (e.g., syntax error).
- `-ErrorAction Stop` converts a non-terminating error into a terminating one, allowing it to be caught by a `try/catch` block. `$ErrorActionPreference` sets the global default.

**PS5**: **Splatting** is passing a collection of parameter values using `@` instead of `$`.
*Example*: `$params = @{ Path = 'C:\'; Filter = '*.txt' }; Get-ChildItem @params`.
Unlike passing a hashtable as a single argument, splatting expands the hashtable into individual named parameters.

**PS6**: 
- `Invoke-Command`: Runs a script block on remote machines and returns results.
- `Enter-PSSession`: Starts an interactive 1-to-1 session.
It uses **WinRM** (WS-Management) by default over HTTP/HTTPS, but PowerShell 7+ supports **SSH** for cross-platform remoting.

**PS7**: The pipeline "unrolls" collections. If a function returns an array, the pipeline emits each element individually. 
- In the example, `$x` will be an `Object[]` if multiple items are returned, but a single `String` if only one is returned. 
- If 0 items, it returns `$null`. 
- **Correct Pattern**: Wrap the call in `@(Get-Items)` to force the result into an array regardless of count.

**PS8**: A `[scriptblock]` is a piece of code stored as an object `{ ... }`, whereas a function is a named scriptblock. 
- **Double-hop**: When a remote session tries to access a *second* remote resource, credentials aren't passed. 
- **Solution**: Use **CredSSP** for delegation or pass credentials explicitly via `-ArgumentList` and `Param()`.

**PS9**: `@()` is the array subexpression operator (ensures the result is an array). `[array]` is a type cast. 
Indexing into `$null` in PowerShell does not throw an error; it returns `$null`. Indexing into an empty array also returns `$null`.

**PS10**: 
- `-eq` (Equal), `-ne` (Not Equal), `-like` (Wildcards `*`), `-match` (Regex), `-contains` (Collection contains value), `-in` (Value is in collection).
- Case-sensitive versions start with `c` (e.g., `-ceq`).
- `-contains` is `Collection -contains Value`; `-in` is `Value -in Collection`.

**PS11**: A module is a package of functions/variables. 
- `.psm1`: Script module containing the logic.
- `.psd1`: Manifest containing metadata (version, author, dependencies).
- **Binary**: Compiled .NET DLL.
`Import-Module` loads the module into the current session.

**PS12**: 
- `"..."` (Double): Interpolates variables.
- `'...'` (Single): Literal string.
- Expressions: Use `$($expression)` inside double quotes.
- **Here-string**: `@" ... "@` allows multi-line strings without escaping quotes.

**PS13**: `Get-Member` shows the properties and methods of an object. 
- **Properties**: Data values.
- **Methods**: Actions the object can perform.
- **NoteProperties**: Custom properties added dynamically.
- `Select-Object` picks specific properties (columns); `Where-Object` filters objects (rows).

**PS14**: PS Classes provide strong typing and encapsulation. They differ from C# classes by being more dynamic and having limited support for interfaces. Use a class for complex data models; use a function for operational tasks.

**PS15**: `[CmdletBinding()]` turns a function into an **Advanced Function**, enabling common parameters like `-Verbose` and `-WhatIf`. 
- `SupportsShouldProcess`: Enables `-WhatIf` and `-Confirm`.
- `ValueFromPipeline`: Allows the function to accept input from the pipeline.
- `Begin/Process/End`: `Begin` runs once at start, `Process` runs for every object in the pipeline, `End` runs once at the end.

**PS16**: Providers map different data stores to a drive-like interface. `Get-ChildItem` works on `FileSystem::`, `Registry::`, `Cert::`, and `Env::`. 
Registry access: `cd HKLM:\Software` allows navigating the registry as if it were a folder structure.

**PS17**: 
- `[runspace]`: An isolated execution environment with its own state.
- `[runspacepool]`: A collection of runspaces for reuse.
- `ForEach-Object -Parallel` (v7+): A high-level abstraction that manages a runspace pool automatically to execute script blocks in parallel.

**PS18**: **PSScriptAnalyzer** is a static code analysis tool. It uses **Rules** to check for best practices (e.g., avoiding `Write-Host`). 
- **Severity**: Error, Warning, Information.
- **Suppression**: Use `[Diagnostics.CodeAnalysis.SuppressMessageAttribute()]`.
- **CI/CD**: Integrated via `Invoke-PSScriptAnalyzer` in build pipelines to fail builds on linting errors.

**PS19**: 
- `$using:var`: Used in `Invoke-Command` or `-Parallel` to bring a local variable into the remote/parallel scope.
- `-ArgumentList`: Used in `Start-Job` to pass values.
- **Serialization**: Objects are serialized via **CLIXML**. Complex .NET objects may lose their methods or private state during this process.

**PS20**: **DSC** is a declarative system for maintaining environment state. 
- **Configuration**: The "what" (desired state).
- **Resource**: The "how" (the logic to make it so).
- **LCM**: The engine on the target node that applies and monitors the configuration.
In PS 7+, DSC has moved toward a cross-platform model (DSC v3). Modern IaC has largely shifted to **Terraform, Ansible, or Bicep**.
