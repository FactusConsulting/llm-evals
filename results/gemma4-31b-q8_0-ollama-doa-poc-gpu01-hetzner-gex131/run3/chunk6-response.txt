## JavaScript / TypeScript

**JS1**
*   **var**: Function-scoped, can be redeclared, hoisted and initialized as `undefined`.
*   **let**: Block-scoped, cannot be redeclared in the same scope, hoisted but stays in the "Temporal Dead Zone" (TDZ) until declaration.
*   **const**: Block-scoped, cannot be redeclared or reassigned. Must be initialized at declaration.
*   **Hoisting**: The behavior where declarations (functions and variables) are moved to the top of their containing scope during the compilation phase.

**JS2**
The **Event Loop** is a mechanism that allows JS to perform non-blocking I/O operations despite being single-threaded.
1.  **Call Stack**: Executes synchronous code.
2.  **Microtask Queue**: Higher priority. Contains `Promise` callbacks, `MutationObserver`, and `queueMicrotask`. Processed immediately after the stack clears and before the next macrotask.
3.  **Macrotask Queue**: Lower priority. Contains `setTimeout`, `setInterval`, and I/O. Processed one at a time, followed by a full flush of the microtask queue.

**JS3**
A **closure** is a function that remembers its lexical scope even when executed outside that scope.
*   **Example**: A function returning another function that increments a private counter.
*   **Loop Bug**: Using `var` in a `for` loop with asynchronous callbacks (like `setTimeout`) causes all callbacks to reference the final value of the variable.
*   **Fix**: Use `let` (which creates a new binding for every iteration) or an IIFE to capture the current value.

**JS4**
*   **Promise**: An object representing the eventual completion (or failure) of an async operation.
*   **async/await**: Syntactic sugar for Promises. `async` functions return a promise; `await` pauses execution until the promise settles.
*   **Error Handling**: Promises use `.catch()`; `async/await` uses `try/catch` blocks.
*   **Promise.all**: Rejects immediately if *any* promise fails.
*   **Promise.allSettled**: Waits for *all* promises to settle (either fulfilled or rejected) and returns an array of their outcomes.

**JS5**
*   **Interface**: Primarily for defining object shapes. Supports "declaration merging" (adding fields to the same interface in different files). Best for public APIs and classes.
*   **Type**: An alias for any type (unions, primitives, tuples). Cannot be merged. Best for complex logic and unions.
*   **Discriminated Unions**: A type that combines multiple types with a common literal property (the "discriminant") used to narrow the type in a switch or if-statement.

**JS6**
*   **Prototypal Inheritance**: Objects inherit properties and methods from other objects via a prototype chain (`__proto__`).
*   **Object.create(proto)**: Creates a new object with the specified object as its prototype.
*   **ES6 Classes**: Syntactic sugar over prototypes. `class` defines a constructor and methods that are actually added to the prototype of the resulting objects.

**JS7**
`this` refers to the execution context.
**Binding Rules (Priority Order):**
1.  **New Binding**: `this` is the newly created object.
2.  **Explicit Binding**: `call()`, `apply()`, or `bind()` explicitly sets `this`.
3.  **Implicit Binding**: `this` is the object to the left of the dot (e.g., `obj.method()`).
4.  **Default Binding**: In non-strict mode, `window`/`global`; in strict mode, `undefined`.
*   **bind()**: Returns a new function with `this` permanently bound. It cannot be re-bound.

**JS8**
*   **WeakRef**: Allows holding a reference to an object without preventing it from being garbage collected (GC).
*   **FinalizationRegistry**: Allows registering a callback that runs after an object has been GC'd.
*   **WeakMap**: Keys must be objects because the map holds a "weak" reference to the key. If the object key is deleted elsewhere, the entry is automatically removed from the WeakMap, preventing memory leaks.

**JS9**
*   **Hidden Classes**: V8 assigns a "shape" to objects. If two objects have the same properties in the same order, they share a hidden class, allowing optimized property access.
*   **Inline Caching (IC)**: V8 remembers where a property was found in a hidden class to skip the lookup next time.
*   **Deoptimization**: Occurs when V8's assumptions are proven wrong (e.g., a function that always took integers suddenly receives a string).
*   **Bad Patterns**: Changing the order of property assignment or adding/deleting properties dynamically (changing the "shape").

**JS10**
*   **Tree-shaking**: The process of removing unused code from the final bundle.
*   **ES Modules (ESM)**: Use static `import`/`export`, allowing the bundler to determine exactly what is used at build time.
*   **CommonJS (CJS)**: Uses dynamic `require()`. Because imports can happen inside `if` statements or be computed strings, the bundler cannot safely determine what is unused, making tree-shaking ineffective.

**JS11**
*   **null**: Intentional absence of any object value.
*   **undefined**: A variable has been declared but not yet assigned a value.
*   **Comparison**: `null == undefined` is `true` (coercion); `null === undefined` is `false`.
*   **Nullish Coalescing (??)**: Returns RHS if LHS is `null` or `undefined` (ignores `0` or `""`).
*   **Optional Chaining (?.)**: Short-circuits and returns `undefined` if the reference is `null` or `undefined`.

**JS12**
*   **map()**: Creates a new array by transforming every element.
*   **filter()**: Creates a new array containing only elements that pass a predicate.
*   **reduce()**: Reduces an array to a single value. The initial value serves as the starting accumulator; if omitted, the first element is used.
*   **flatMap()**: Maps each element using a mapping function, then flattens the result into a new array (depth 1). Useful for removing items or expanding one item into many.

**JS13**
*   **Template Literals**: Strings enclosed in backticks (`` ` ``) allowing multi-line strings and interpolation `${}`.
*   **Tagged Templates**: A function called with a template literal. The function receives the string parts and the interpolated values separately.
*   **Example**: `sql`tag for preventing SQL injection:
    `const query = sql`SELECT * FROM users WHERE id = ${userId}`;` (The `sql` function escapes `userId`).

**JS14**
*   **Destructuring**: Unpacking values from arrays or properties from objects into distinct variables.
*   **Object**: `const { name, age: userAge = 25 } = user;` (renaming and default value).
*   **Array**: `const [first, second] = [10, 20];`.
*   **Rest Operator (...)**: Collects remaining elements into an array: `const [first, ...rest] = [1, 2, 3];` (`rest` becomes `[2, 3]`).

**JS15**
*   **for...in**: Iterates over **enumerable keys** (strings) of an object.
*   **for...of**: Iterates over **iterable values** (arrays, maps, sets).
*   **Avoid for...in on arrays**: It iterates over indices as strings and may include inherited properties from the prototype chain, leading to bugs.

**JS16**
*   **Generics**: Allow creating reusable components that work with multiple types (e.g., `Array<T>`).
*   **Constraints (`extends`)**: Limits the types a generic can accept: `<T extends { length: number }>`.
*   **Conditional Types**: `T extends U ? X : Y` (If T is assignable to U, result is X, else Y).
*   **infer**: Used within conditional types to extract a type from another: `T extends Promise<infer U> ? U : T`.

**JS17**
*   **CommonJS**: `require`/`module.exports`. Synchronous. Standard for older Node.js.
*   **ES Modules**: `import`/`export`. Asynchronous/Static. Standard for browsers and modern Node.js.
*   **Node.js Handling**: Node uses `.mjs` for ESM and `.cjs` for CJS.
*   **"type": "module"**: In `package.json`, this tells Node to treat all `.js` files in that directory as ES Modules.

**JS18**
*   **Structural Typing**: TS checks if the *shape* of an object matches the required type, regardless of the explicit class/interface name.
*   **Excess Property Checks**: Occur when assigning an object literal directly to a type; TS prevents adding properties not defined in the type to catch typos.
*   **extends vs satisfies**: `extends` creates a subtype/constraint. `satisfies` validates that an object matches a type without changing the object's inferred type (prevents widening).
*   **Variance**: Covariance (out) allows a more specific type; Contravariance (in) allows a more general type.

**JS19**
*   **Proxy**: Wraps an object to intercept and redefine fundamental operations (get, set, delete).
*   **Reflect**: A built-in object providing methods that mirror Proxy traps, used to perform the default action inside a trap.
*   **Example**: Reactive data binding. A Proxy `set` trap can trigger a UI re-render whenever a property is changed.

**JS20**
*   **SharedArrayBuffer**: A memory buffer that can be shared between the main thread and Web Workers.
*   **Atomics**: Provides atomic operations (e.g., `Atomics.add`, `Atomics.load`) to prevent race conditions when accessing shared memory.
*   **Wait/Notify**: `Atomics.wait` puts a thread to sleep until a specific index in the buffer changes; `Atomics.notify` wakes up sleeping threads.

## Bash

**B1**
*   `$*`: All positional parameters as a single string.
*   `$@`: All positional parameters as separate strings.
*   `"$*"`: All arguments joined by the first character of `IFS` into one string.
*   `"$@"`: Each argument is individually quoted; preserves spaces within arguments.

**B2**
`set -euo pipefail`
*   `-e`: Exit immediately if a command exits with a non-zero status.
*   `-u`: Treat unset variables as an error and exit.
*   `-o pipefail`: The return value of a pipeline is the status of the last command to exit with a non-zero status, or zero if all exit successfully.

**B3**
*   `$(command)` vs `` `command` ``: Both perform command substitution. `$(...)` is preferred because it is nestable and handles backslashes more predictably.
*   `$((expression))` vs `expr`: `$((...))` is a shell builtin for integer arithmetic (fast). `expr` is an external binary (slow, requires external process).

**B4**
**Process Substitution** `<(command)` allows the output of a command to be treated as a file.
*   **Example**: `diff <(ls dir1) <(ls dir2)`. This compares the output of two `ls` commands without needing to create temporary files.

**B5**
Use `while IFS= read -r line` or `find -print0 | xargs -0`.
`for f in $(ls)` is dangerous because it performs word splitting on the output of `ls`. If a filename contains a space, Bash treats it as two separate files.

**B6**
*   **Here Document (`<<EOF`)**: Redirects a multi-line block of text to a command.
*   **Here String (`<<<`)**: Redirects a single string to a command's stdin.
*   **`<<-EOF`**: Strips leading tab characters from the input lines, allowing the block to be indented for readability.

**B7**
1.  `cmd > file 2>&1`: Stdout goes to `file`, then Stderr is redirected to where Stdout is currently going (`file`). Result: Both in `file`.
2.  `cmd 2>&1 > file`: Stderr is redirected to current Stdout (the terminal), then Stdout is redirected to `file`. Result: Stderr in terminal, Stdout in `file`.
3.  `cmd &> file`: Bash shorthand for redirecting both Stdout and Stderr to `file`.

**B8**
```bash
lock_dir="/tmp/myscript.lock"
cleanup() { rmdir "$lock_dir" 2>/dev/null; }
trap cleanup EXIT SIGTERM SIGINT

if mkdir "$lock_dir" 2>/dev/null; then
    # Critical section
    echo "Locked"
else
    echo "Failed to acquire lock" && exit 1
fi
```
`mkdir` is preferred because it is an atomic operation at the kernel level; two processes cannot create the same directory simultaneously.

**B9**
*   **Single quotes (' ')**: Literal strings. No expansion. `'Hello $USER'` $\rightarrow$ `Hello $USER`.
*   **Double quotes (" ")**: Allows parameter expansion and command substitution. `"Hello $USER"` $\rightarrow$ `Hello john`.
*   **No quotes**: Subject to word splitting and globbing. `echo $VAR` will split if `$VAR` contains spaces.

**B10**
*   `-f`: File exists and is a regular file.
*   `-d`: Directory exists.
*   `-r`: File is readable.
*   `[ ]`: POSIX standard test. Requires quoting variables to avoid word splitting.
*   `[[ ]]`: Bash extension. Supports regex (`=~`), globbing, and doesn't require quoting variables.

**B11**
*   `$?`: Exit status of the last command (0 = success).
*   `$$`: PID of the current shell.
*   `$!`: PID of the last background process.
*   `$#`: Number of positional parameters passed to the script.

**B12**
*   **Definition**: `foo() { ... }` (POSIX) or `function foo { ... }` (Bash).
*   **Return values**: `return` only returns an exit status (0-255). To return data, use `echo` and capture it with `result=$(foo)`.

**B13**
*   **PATH**: A colon-separated list of directories the shell searches for executable binaries.
*   **Resolution**: Aliases $\rightarrow$ Functions $\rightarrow$ Builtins $\rightarrow$ PATH binaries.
*   **Builtin vs External**: Builtins (e.g., `cd`, `echo`) run inside the shell process. Externals (e.g., `ls`, `grep`) are separate binaries.
*   **Check**: Use `type -a <command>`.

**B14**
`trap 'command' SIGNAL`
*   `EXIT`: Runs when the script finishes.
*   `ERR`: Runs when a command fails (if `set -e` is not used).
*   `INT`: Ctrl+C.
*   `TERM`: `kill` command.
*   **Order**: Signals are handled as they arrive; `EXIT` is always the final trigger.

**B15**
*   **xargs**: Converts stdin into arguments for a command. Command substitution `$(...)` captures output into a string.
*   **Spaces/Newlines**: `find . -print0 | xargs -0` uses the null character as a delimiter, which is the only character not allowed in filenames.
*   **-P**: Runs `xargs` commands in parallel (e.g., `-P 4` for 4 processes).

**B16**
*   **Indexed Array**: `arr=(a b c)`. Append: `arr+=("d")`. Length: `${#arr[@]}`. Iterate: `for i in "${arr[@]}"`.
*   **Associative Array**: `declare -A assoc`. `assoc[key]="val"`. Length: `${#assoc[@]}`. Iterate: `for k in "${!assoc[@]}"`.
*   **Difference**: Indexed use integers; Associative use strings as keys.

**B17**
*   **Subshell `(...)`**: Runs in a separate process. Variable changes are lost when it exits.
*   **Group `{ ...; }`**: Runs in the current process. Variable changes persist.
*   **Piping to while**: `cat file | while read line; do ... done` creates a subshell for the `while` loop, so variables modified inside the loop are lost.

**B18**
*   **SIGINT**: Interrupt (Ctrl+C).
*   **SIGTERM**: Termination request (polite).
*   **SIGHUP**: Hangup (terminal closed).
*   **SIGKILL**: Forced kill (cannot be trapped).
*   **Graceful Shutdown**: Use `trap` to catch `SIGTERM`, set a flag, and use `wait` to ensure background children finish.

**B19**
```bash
split -l 10000 large.log chunk_
process_chunk() { grep "ERROR" "$1" > "$1.res"; }
export -f process_chunk
ls chunk_* | xargs -P 4 -I {} bash -c 'process_chunk "{}"'
cat chunk_*.res > final_errors.log
```
*   **Trade-offs**: I/O bottleneck vs CPU gain.
*   **Errors**: `xargs` returns non-zero if any child fails; use a wrapper script to log specific chunk failures.

**B20**
*   **exec**: Replaces the current shell process with the new command (no return to shell).
*   **FD Manipulation**: `exec 3>file` opens file descriptor 3 for writing. `exec 3>&-` closes it.
*   **Coprocess**: `coproc myproc { sleep 10; }`. Creates a two-way pipe between the shell and the process. Used for long-running background tasks that need bidirectional communication.

## PowerShell

**PS1**
*   **Write-Output**: Sends objects to the pipeline. This is the standard way to return data.
*   **Write-Host**: Writes directly to the console host. It bypasses the pipeline, meaning the data cannot be captured by another cmdlet.

**PS2**
*   **Pipeline**: Passes objects (not text) from one cmdlet to another.
*   **ForEach-Object**: A cmdlet used in the pipeline (`... | ForEach-Object { ... }`). It processes items one-by-one (streaming).
*   **foreach statement**: A language keyword (`foreach ($item in $list) { ... }`). It loads the entire collection into memory first.

**PS3**
*   **Hashtable**: A key-value pair collection (`@{ key = 'val' }`). Unordered by default.
*   **PSCustomObject**: A structured object with properties (`[PSCustomObject]@{ key = 'val' }`). Ordered and behaves like a class instance.
*   **Conversion**: Cast a hashtable using `[PSCustomObject]$myHash`.

**PS4**
*   **Terminating**: Stops execution (e.g., syntax error).
*   **Non-terminating**: Reports error but continues (e.g., `Get-Item` on a missing file).
*   **Interaction**: `-ErrorAction Stop` converts a non-terminating error into a terminating one, allowing it to be caught by a `try/catch` block. `$ErrorActionPreference` sets the global default.

**PS5**
**Splatting** is passing a collection of parameter values to a command using `@` instead of `$`.
```powershell
$params = @{ Path = 'C:\temp'; Filter = '*.txt'; Recurse = $true }
Get-ChildItem @params
```
Unlike passing a hashtable as a single argument, splatting expands the hashtable into individual named parameters.

**PS6**
*   **Invoke-Command**: Runs a script block on one or more remote computers and returns the result.
*   **Enter-PSSession**: Starts an interactive 1-to-1 remote shell.
*   **Protocol**: Uses WinRM (WS-Management) over HTTP/HTTPS. PowerShell 7+ also supports SSH.

**PS7**
The pipeline **unwraps** arrays.
*   **Result**: If `Get-Items` returns an array of 1 item, the pipeline unwraps it, and `$x` becomes a single object (String). If 0 items, `$x` is `$null`.
*   **GetType().Name**: Will be `String` (for 1 item) or throw an error (for `$null`).
*   **Correct Pattern**: Wrap the call in `@(...)` to force the result to remain an array: `$x = @(Get-Items)`.

**PS8**
*   **Scriptblock**: A block of code `{ ... }` treated as an object.
*   **Remote Session**: Pass a scriptblock to `Invoke-Command -ScriptBlock { ... }`.
*   **Double-Hop**: When a remote session tries to access a *second* remote resource, credentials are not delegated.
*   **Solution**: Use CredSSP for delegation or pass credentials explicitly via `-ArgumentList` and `Param()`.

**PS9**
*   **@()**: Array subexpression operator. Ensures the result is an array even if only one item is returned.
*   **[array]**: Type cast to an array.
*   **Indexing**: Indexing into `$null` returns `$null`. Indexing into an empty array also returns `$null`.

**PS10**
*   **Operators**: `-eq` (equal), `-ne` (not equal), `-like` (wildcards `*`), `-match` (regex), `-contains` (collection contains value), `-in` (value is in collection).
*   **Case-sensitivity**: Prefix with `c` (e.g., `-ceq`) for case-sensitive; `i` (e.g., `-ieq`) for case-insensitive (default).
*   **-contains vs -in**: `$array -contains $val` vs `$val -in $array`.

**PS11**
*   **Module**: A package of functions, variables, and cmdlets.
*   **.psm1**: Script module containing the actual code.
*   **.psd1**: Manifest module containing metadata (version, author, dependencies).
*   **Binary Module**: A compiled .NET assembly (DLL).
*   **Import-Module**: Loads the module's exported members into the current session.

**PS12**
*   **Interpolation**: `" "` (double quotes) allow variables to be expanded. `' '` (single quotes) are literal.
*   **Expressions**: Use the subexpression operator: `"The date is $($Get-Date)"`.
*   **Here-String**: `@" ... "@` allows multi-line strings without escaping quotes.

**PS13**
*   **Get-Member**: Introspects an object to show its Properties, Methods, and Events.
*   **NoteProperties**: Properties added dynamically to an object (e.g., via `Add-Member`).
*   **Select-Object**: Picks specific properties to keep.
*   **Where-Object**: Filters objects based on a condition.

**PS14**
*   **Classes**: Introduced in v5 for strong typing and structured data.
*   **Differences**: Unlike C#, they are more flexible but have limited inheritance (no multiple inheritance) and simpler constructors.
*   **Usage**: Use classes for complex data models/state; use functions for procedural tasks and pipeline-oriented logic.

**PS15**
*   **[CmdletBinding()]**: Turns a function into an "Advanced Function," enabling common parameters like `-Verbose` and `-WhatIf`.
*   **SupportsShouldProcess**: Enables `-WhatIf` and `-Confirm`.
*   **ValueFromPipeline**: Allows the parameter to accept input directly from the pipeline.
*   **Blocks**: `Begin` (runs once at start), `Process` (runs once per pipeline object), `End` (runs once at finish).

**PS16**
**Providers** map different data stores to a drive-like interface.
*   **Examples**: `FileSystem`, `Registry` (`HKLM:`, `HKCU:`), `Certificate`, `Environment`.
*   **Registry Access**: You can use `cd HKLM:\Software` and `Get-ChildItem` to browse the registry as if it were a folder structure.

**PS17**
*   **Runspace**: An isolated execution environment (thread) with its own state.
*   **RunspacePool**: A collection of runspaces used to manage concurrency.
*   **Parallelism**: `ForEach-Object -Parallel` (v7+) is a high-level wrapper that manages runspaces automatically. Manual management is used for complex, long-lived background threads.

**PS18**
*   **PSScriptAnalyzer**: A static code analysis tool for PowerShell.
*   **Enforcement**: It checks code against a set of rules (e.g., "Avoid using Write-Host").
*   **Severity**: Error, Warning, Information.
*   **Suppression**: Use `[Diagnostics.CodeAnalysis.SuppressMessageAttribute()]`.
*   **CI/CD**: Integrated via `Invoke-ScriptAnalyzer` in build pipelines to fail builds on linting errors.

**PS19**
*   **$using:scope**: Used in `Invoke-Command` or `-Parallel` to reference a variable from the local session.
*   **-ArgumentList**: Passes variables as a positional array to the remote block's `Param()` block.
*   **Serialization**: Objects are serialized to CLIXML. Complex objects (like active DB connections or certain .NET types) lose their state/methods during this process.

**PS20**
*   **DSC**: A declarative platform for maintaining environment configuration.
*   **Components**: **Configurations** (the desired state), **Resources** (the "how-to" for a specific setting), **LCM** (the engine that applies and monitors the state).
*   **Evolution**: Windows PS DSC was WMI-based. PS 7+ DSC is cross-platform. Modern IaC (Terraform, Ansible, Kubernetes) has largely replaced DSC for cloud-scale infrastructure.
