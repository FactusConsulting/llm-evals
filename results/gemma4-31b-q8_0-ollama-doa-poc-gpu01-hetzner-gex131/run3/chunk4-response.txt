## Go

**G1 — Easy:** An **array** has a fixed size defined at compile time; it is a value type. A **slice** is a descriptor for a contiguous segment of an array, consisting of a pointer, a length, and a capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array, copies the existing elements over, and returns a new slice pointing to the new array.

**G2 — Easy:** `var x int` declares a variable with its zero value (0 for int) and can be used at the package or function level. `x := 0` is short-variable declaration, which infers the type and is only allowed **inside functions**. You cannot use `:=` at the package level or when you want to declare a variable without initializing it immediately.

**G3 — Medium:** A **goroutine** is a lightweight thread managed by the Go runtime. Unlike OS threads (which have large fixed stacks, ~2MB), goroutines start with a small stack (~2KB) that grows/shrinks dynamically. The **GMP model** handles scheduling: **G** (Goroutine), **M** (Machine/OS Thread), and **P** (Processor/Logical Context). P holds the local run queue of Gs and schedules them onto M.

**G4 — Medium:** Channels are typed conduits for communication between goroutines. **Unbuffered channels** are synchronous; the sender blocks until a receiver is ready. **Buffered channels** have a capacity; the sender only blocks when the buffer is full. If you send to a full buffered channel, the goroutine blocks until a receiver removes a value.

**G5 — Medium:** The `context` package manages deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
_, err := http.DefaultClient.Do(req)
```

**G6 — Medium:** Go uses **structural typing** (implicit satisfaction). A type satisfies an interface by implementing its methods; no `implements` keyword is needed. This differs from Java/C# where satisfaction must be explicit. `interface{}` (or `any`) is the empty interface; since every type implements zero methods, every type satisfies it. It is powerful for generic containers but dangerous because it bypasses compile-time type safety, requiring runtime type assertions.

**G7 — Hard:** Go does not guarantee that a write to a variable in one goroutine is immediately visible to another without synchronization. The provided code is unsafe because the compiler or CPU may cache `ready` in a register or reorder instructions, leading to an infinite loop or reading `data` before it is initialized. **Correct alternatives:** Use `sync.Mutex`, `atomic.Bool`, or a channel to signal completion.

**G8 — Hard:** `sync.Mutex` provides exclusive access. `sync.RWMutex` allows multiple concurrent readers OR one exclusive writer, improving performance for read-heavy workloads. `sync.Map` is optimized for two cases: (1) when the entry for a given key is only ever written once but read many times, or (2) when multiple goroutines read, write, and overwrite entries for disjoint sets of keys. A regular map with a mutex is generally faster for most common use cases due to less interface overhead.

**G9 — Hard:** Go modules manage dependencies. `go.mod` defines the module path and required dependency versions. `go.sum` contains cryptographic checksums to ensure dependencies aren't tampered with. `go mod tidy` adds missing module requirements and removes unused ones. **MVS (Minimum Version Selection)** selects the *lowest* version of a dependency that satisfies all constraints in the graph, ensuring reproducible builds.

**G10 — Medium:** `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. **Gotcha:** Using `defer` inside a loop can lead to resource exhaustion (e.g., open file descriptors) because the deferred calls don't execute until the function exits, not the loop iteration.

**G11 — Easy:** A pointer holds the memory address of a value. The zero value of a pointer is `nil`. To create a pointer to a struct literal, use the address-of operator: `p := &User{Name: "Alice"}`.

**G12 — Easy:** `init()` is a special function used for package initialization. It runs once per package before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source files, after all imported packages have been initialized.

**G13 — Easy:** `new(T)` allocates zeroed memory for a type `T` and returns a pointer `*T`. `make` is used only for **slices, maps, and channels**; it initializes the internal data structure and returns the type itself (not a pointer).

**G14 — Easy:** Go treats errors as values. The `error` interface requires an `Error() string` method. The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error is (or wraps) a specific error value; `errors.As` checks if an error is (or wraps) a specific error type and casts it. `==` only checks for direct equality.

**G15 — Easy:** 
- **Map:** `nil`
- **Slice:** `nil`
- **Channel:** `nil`
- **Struct:** All fields set to their respective zero values.

**G16 — Medium:** A race condition occurs when two or more goroutines access the same memory concurrently, and at least one access is a write. The `-race` flag enables a runtime detector that finds these conflicts.
*Fix:*
```go
var mu sync.Mutex
var count int
// In goroutine:
mu.Lock()
count++
mu.Unlock()
```

**G17 — Medium:** `select` is like a `switch` but for channel operations. It blocks until one of its cases can run. If multiple cases are ready, one is chosen **pseudo-randomly**. A timeout is implemented using `time.After`:
```go
select {
case res := <-ch:
    fmt.Println(res)
case <-time.After(1 * time.Second):
    fmt.Println("timeout")
}
```

**G18 — Hard:** Escape analysis is the compiler's process of deciding whether a variable can be allocated on the stack or must "escape" to the heap. If a variable is referenced outside the function scope (e.g., returning a pointer to a local variable), it escapes. Inspect via `go build -gcflags="-m"`. It matters because heap allocations increase GC pressure and reduce performance.

**G19 — Hard:** `reflect` allows a program to inspect its own structure. `reflect.Type` represents the static type; `reflect.Value` represents the dynamic value. Performance costs are high due to runtime checks and boxing. Reflection is justified for generic libraries (e.g., `json.Marshal`); otherwise, code generation (e.g., `stringer`) is preferred for performance.

**G20 — Hard:** `go:embed` allows embedding files into the binary. `//go:embed file.txt` embeds a file as a `string` or `[]byte`. `//go:embed folder/*` embeds a directory as an `embed.FS`. It is read-only and static. It interacts with `io/fs.FS`, allowing the embedded filesystem to be used interchangeably with the OS filesystem.

## Rust

**R1 — Easy:** Ownership is Rust's system for managing memory without a GC. Rules: 1. Each value has a variable called its **owner**. 2. There can only be **one owner** at a time. 3. When the owner goes **out of scope**, the value is dropped.

**R2 — Easy:** `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is a borrowed string slice (a pointer and a length). Use `&str` in function signatures for arguments to accept both `String` and `&str` (via deref coercion), making the function more flexible.

**R3 — Medium:** Borrowing allows accessing data without taking ownership. The borrow checker enforces: 1. You can have **either** one mutable reference (`&mut T`) **or** any number of immutable references (`&T`) at any given time. 2. References must always be valid (no dangling pointers).

**R4 — Medium:** `Result<T, E>` handles recoverable errors (`Ok` or `Err`). `Option<T>` handles presence/absence (`Some` or `None`). The `?` operator unwraps a `Result`/`Option` or returns the error/None to the caller.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5 — Medium:** `Box<T>` is for heap allocation. `Rc<T>` (Reference Counted) allows multiple owners in a **single-threaded** context. `Arc<T>` (Atomic Reference Counted) allows multiple owners across **multiple threads**.

**R6 — Medium:** Traits define shared behavior (similar to interfaces). Unlike Go, they must be explicitly implemented. `T: Trait` (Generics) uses **static dispatch** (monomorphization), creating a copy of the function for each type. `dyn Trait` (Trait Objects) uses **dynamic dispatch** via a vtable, allowing for heterogeneous collections.

**R7 — Hard:** Lifetimes ensure references don't outlive the data they point to. The example fails because the compiler doesn't know if the returned reference points to `x` or `y`, and thus cannot guarantee it remains valid. **Fix:** `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { ... }` (telling Rust the return value lives as long as the shortest input).

**R8 — Hard:** `Send` indicates a type can be transferred between threads. `Sync` indicates a type can be shared between threads via references. `Rc<T>` is not `Send` or `Sync` because its reference counter is not atomic; concurrent updates would cause data races. `Arc<T>` uses atomic operations for the counter, making it thread-safe.

**R9 — Hard:** Rust's `async` is a state-machine transformation. A `Future` is a trait with a `poll` method that returns `Poll::Ready` or `Poll::Pending`. The **executor** (e.g., Tokio) polls futures when they are woken up. Unlike Go's preemptive scheduler, Rust's async is **cooperative** and requires an external runtime.

**R10 — Medium:** `unsafe` allows bypassing some borrow checker rules. You can: 1. Dereference raw pointers. 2. Call unsafe functions (FFI). 3. Access/modify mutable static variables. It is justified for low-level hardware access, FFI, or building high-performance primitives (like `Vec`).

**R11 — Easy:** Pattern matching uses `match` to handle all possible values of an enum or type. `match` is **exhaustive** (the compiler forces you to cover all cases). `if let` is syntactic sugar for matching only one specific pattern while ignoring others.

**R12 — Easy:** `[T; N]` is a fixed-size array on the stack. `Vec<T>` is a growable array on the heap. When `Vec` exceeds capacity, it allocates a new larger block of memory (usually doubling), copies elements, and frees the old block.

**R13 — Easy:** Rust enums are **sum types**; they can hold data in each variant. This is more powerful than C/Java enums. `Option<T>` is an enum with `Some(T)` and `None`. Rust has no `null` to eliminate null-pointer exceptions at compile time.

**R14 — Easy:** `impl` blocks define methods for a type. `&self` is an immutable borrow, `&mut self` is a mutable borrow, and `self` takes ownership. **Associated functions** (like `String::new()`) do not take `self` and are called on the type itself.

**R15 — Easy:** `derive` is a procedural macro that automatically implements traits. Examples: `Debug` (printing), `Clone` (duplicating), `PartialEq` (equality), `Serialize` (serde). You cannot derive a trait if any of the struct's fields do not also implement that trait.

**R16 — Medium:** `Cow<'a, T>` (Clone-on-Write) allows a value to be either borrowed or owned. It avoids allocation if the data doesn't need to be modified. Example: A function that cleans a string; if the string is already clean, it returns a borrow (`&str`); if it needs changes, it allocates a new `String`.

**R17 — Medium:** `mod` declares a module, `use` creates a shortcut to a path, and `pub` makes items visible. Files map to modules (e.g., `src/network.rs` is `mod network`). In 2018, `extern crate` became mostly unnecessary, and path-based imports were simplified.

**R18 — Hard:** `Pin<T>` ensures a value cannot be moved in memory. This is critical for **self-referential structs** (where a field points to another field in the same struct), which are common in `async` futures. `Unpin` is an auto-trait for types that are safe to move (most types).

**R19 — Hard:** `macro_rules!` are **declarative macros** (pattern matching on tokens). **Procedural macros** (derive, attribute, function-like) are functions that take a `TokenStream` and return a `TokenStream`. **Hygiene** prevents macros from accidentally capturing or shadowing variables in the scope where they are called.

**R20 — Hard:** Zero-cost abstractions mean you don't pay for what you don't use. **Iterators** are inlined into loops by the compiler. **Generics** use monomorphization (generating specific code for each type), avoiding runtime boxing. **Static dispatch** allows the compiler to call functions directly rather than through a vtable.
