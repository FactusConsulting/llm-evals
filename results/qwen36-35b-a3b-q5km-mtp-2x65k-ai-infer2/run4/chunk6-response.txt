JS1 — `var` is function-scoped and hoisted with `undefined`. `let`/`const` are block-scoped and hoisted but enter a Temporal Dead Zone (TDZ) until declaration. Hoisting is JS's behavior of moving declarations to the top of their scope during compilation before execution.

JS2 — The event loop continuously checks if the call stack is empty. When empty, it processes the microtask queue (promises, `queueMicrotask`) until empty, then renders, then processes one macrotask (setTimeout, I/O, UI events). Microtasks always run before macrotasks, enabling promise resolution to interrupt pending timers.

JS3 — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: `function makeCounter() { let i=0; return () => ++i; }`. Classic bug: `for (var i=0; i<3; i++) setTimeout(()=>console.log(i), 0)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped), IIFE, or `setTimeout(..., 0, i)`.

JS4 — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that pauses execution until the promise settles, making async code read synchronously. Error handling: `try/catch` with `await`, or `.catch()`/second `.then()` arg. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all promises, returning an array of `{status, value/reason}` objects.

JS5 — `interface` defines object shapes, supports declaration merging/extension, and erases at runtime. `type` is a broader alias supporting unions, intersections, tuples, and mapped types. Use `interface` for APIs/objects, `type` for primitives/unions. Discriminated unions: types sharing a common literal property (discriminator) used in `switch`/`if` for exhaustive type narrowing.

JS6 — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar: `class` defines a constructor and prototype methods; `extends` sets up prototype linkage; `super` calls parent constructor/methods.

JS7 — `this` is dynamically bound based on call site. Priority order: 1. `new` (new instance), 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (`obj.method()`), 4. Default (`window` or `undefined` in strict mode). `bind()` returns a new function with `this` permanently bound. It cannot be re-bound.

JS8 — `WeakRef` holds a weak reference that doesn't prevent GC. `FinalizationRegistry` executes a callback when a target is GC'd. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the engine can track them for GC; if keys were primitives, the engine couldn't know when to remove entries, causing unbounded memory growth.

JS9 — V8 optimizes via: Hidden Classes (shape descriptors for fast property access), Inline Caching (caches hidden class pointers at call sites), and Deoptimization (reverts to slower code when assumptions break). Deopt patterns: polymorphic property access, `delete`, `with`, `eval`, dynamic types in loops, or adding properties to objects with different shapes.

JS10 — Tree-shaking removes unused exports at build time. It works with ES modules because `import`/`export` are static and evaluated at compile time, enabling static analysis. CommonJS uses dynamic `require()` evaluated at runtime, so bundlers can't safely analyze dependency graphs for dead code elimination.

JS11 — `null` is intentional absence of value; `undefined` is uninitialized. `==` coerces types (`null == undefined` → `true`); `===` checks type+value (`false`). `??` returns right operand if left is `null`/`undefined`. `?.` safely accesses nested properties without throwing on `null`/`undefined`.

JS12 — `map` transforms elements, `filter` keeps matching ones, `reduce` accumulates to a single value. `reduce` with initial value prevents type errors on empty arrays and sets accumulator type. `flatMap` maps then flattens one level; useful for transforming arrays and flattening results in one pass (e.g., splitting strings into words).

JS13 — Template literals use backticks, support `${expr}` interpolation and multi-line strings. Tagged templates call a function with an array of string parts and interpolated values. Example: `function html(strings, ...values) { return strings.reduce((acc, s, i) => acc + s + (values[i] ? escapeHtml(values[i]) : ''), ''); }`

JS14 — Destructuring unpacks values. Object: `{a, b: renamed} = obj`. Array: `[first, ...rest] = arr`. Defaults: `{a = 1} = obj`. Rest operator `...` collects remaining into array/object. Works in parameters too: `function foo({x, y = 0, ...rest}) {}`.

JS15 — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, maps). Avoid `for...in` on arrays because it iterates keys, not values, includes inherited properties, and order isn't guaranteed.

JS16 — Generics use type parameters (`<T>`) for reusable type-safe code. Constraints: `T extends SomeType` limits T. Conditional types: `T extends U ? X : Y` for branching. `infer` extracts types in conditional contexts. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T;`

JS17 — CJS uses `require`/`module.exports` (synchronous, runtime, module-per-file). ESM uses `import`/`export` (static, async, top-level, native). Node supports both via `.mjs`/`.cjs` extensions or `"type": "module"` in `package.json`, which defaults `.js` to ESM.

JS18 — Structural typing checks compatibility by shape, not names. Excess property checks apply only to object literals assigned directly to typed variables, not to variables holding references. `extends` is a constraint/assignment. `satisfies` checks type without widening, preserving the original type. Variance: `in` (contravariant, parameters), `out` (covariant, returns), `in out` (bivariant). TS 4.7+ enforces stricter variance and introduces `satisfies`.

JS19 — `Proxy` wraps objects to intercept operations (get, set, apply, etc.). `Reflect` mirrors Proxy traps and provides default behavior. Example: validation proxy intercepting `set` to check types. `Reflect.apply(target, thisArg, args)` handles function calls. Use for reactive data binding, logging, or immutable state.

JS20 — `SharedArrayBuffer` shares memory between main thread and Web Workers. `Atomics` provides atomic operations and synchronization. Communication via shared buffer reads/writes. Ordering: sequential consistency via `Atomics.store`/`load`. `Atomics.wait` blocks until value changes; `Atomics.notify` wakes threads. Requires cross-origin isolation headers.

B1 — `$@` expands to separate quoted arguments (`"$1" "$2"`). `$*` expands to a single quoted string (`"$1 $2 ..."`). `"$@"` preserves individual arguments; `"$*"` joins them with the first character of `$IFS`.

B2 — `set -e`: exit on command failure. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the exit status of the last non-zero command. Together: strict, fail-fast scripting.

B3 — `$(command)` is modern command substitution, supports nesting, preferred over backticks `` `command` ``. `$((expression))` is arithmetic expansion, evaluates math directly. `expr` is an external command, slower, and unsafe with special characters.

B4 — Process substitution `<(command)` creates a file descriptor (e.g., `/dev/fd/XX`) for command output. Use when a command expects a file but needs dynamic input. Example: `diff <(sort file1) <(sort file2)`.

B5 — Use `find . -print0 | while IFS= read -r -d '' f; do ...` or safe globbing `for f in *; do ...`. `for f in $(ls)` breaks on spaces/newlines, parses `ls` output (unsafe, misses hidden files, breaks on special chars).

B6 — Here document `<<EOF` passes multi-line input as stdin. Here string `<<<` passes a single line. `<<-EOF` strips leading tabs (not spaces) from the heredoc body for indentation.

B7 — `cmd > file 2>&1`: stdout → file, then stderr → wherever stdout points (file). `cmd 2>&1 > file`: stderr → terminal (stdout's original location), then stdout → file. `cmd &> file`: bash shorthand for `> file 2>&1`. First two differ due to left-to-right redirection evaluation order.

B8 — `mkdir` is atomic on POSIX filesystems, preventing race conditions. 
```bash
lock() {
  local lockdir="/tmp/mylock.$$"
  trap 'rm -rf "$lockdir"' EXIT INT TERM
  if ! mkdir "$lockdir" 2>/dev/null; then
    echo "Locked" >&2; exit 1
  fi
  # critical section
}
```
`mkdir` succeeds only if the directory doesn't exist, making it a safe lock.

B9 — Single quotes: literal, no expansion. Double quotes: allow `$var`/`` `cmd` `` expansion, preserve spaces. No quotes: word splitting and globbing occur. Example: `var="hello world"; echo '$var'` → `$var`; `echo "$var"` → `hello world`; `echo $var` → `hello world` (split).

B10 — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash keyword: supports `&&`, `||`, `=~`, no word splitting/globbing, safer. `[` is an external command (or builtin) with stricter syntax and POSIX compliance.

B11 — `$?`: exit status of last command (error checking). `$$`: PID of current shell (logging/temp files). `$!`: PID of last background process (job control). `$#`: number of positional parameters (argument validation).

B12 — `func() { commands; }` or `function func { commands; }` (latter allows optional parens, bash prefers former). Return values: `return <int>` (exit code 0-255). Use `echo` or global variables for data.

B13 — `PATH`: colon-separated directories bash searches for executables. Resolves: PATH → builtins → aliases. Builtin: compiled into shell (`cd`, `echo`). External: separate binary. Check with `type` or `command -v`.

B14 — `trap 'cmd' SIGNAL`. Handles EXIT, ERR, INT, TERM. Execution order: traps run in LIFO order for the same signal. ERR triggers on non-zero exit. Multiple signals: pending signals handled after current command finishes; order depends on shell but typically LIFO for same signal.

B15 — `xargs` builds/executes commands from stdin. Differs from command substitution (which loads all into memory). `find -print0 | xargs -0` handles spaces/newlines safely. `xargs -P N` runs N processes in parallel.

B16 — Arrays: `arr=(a b c)`, `${arr[0]}`, `${arr[@]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${!assoc[@]}`. Associatives require bash 4+, use string keys, and lack numeric indexing.

B17 — Subshell `(...)`: runs in child process, variable changes lost. Group `{ ...; }`: runs in current shell, variables persist. Piping to `while` creates a subshell, so variable changes inside are lost. Fix: `while ... done < <(cmd)` or `shopt -s lastpipe` (bash 4.2+, non-interactive).

B18 — SIGINT (Ctrl+C, interrupt), SIGTERM (graceful stop), SIGHUP (terminal close/reconnect), SIGKILL (forced kill, uncatchable). Graceful shutdown: trap SIGTERM, cleanup, kill background jobs (`kill $(jobs -p)`), exit. Job control: `jobs`, `fg`, `bg`, `wait`.

B19 — 
```bash
split -l 10000 log.log log_part_
find . -name "log_part_*" -print0 | xargs -0 -P 4 -I {} bash process.sh {}
cat log_part_* > merged.log
```
Trade-offs: CPU vs I/O, splitting/merging overhead. Error propagation: check exit codes, use temp dirs, aggregate errors, `set -o pipefail`, and log failures per chunk.

B20 — `exec` replaces the current shell process or redirects file descriptors. `exec 3>file` opens fd 3, `exec 3>&-` closes it. Coprocess: `coproc cmd` creates bidirectional pipe, runs in background. Use for persistent IPC without explicit fd management.

PS1 — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console (bypasses pipeline, breaks chaining). Matters because pipeline consumers expect objects, not console output.

PS2 — Pipeline streams objects between cmdlets. `ForEach-Object`: processes each object in pipeline (streaming, memory efficient). `foreach` statement: iterates over collection in memory (faster for large collections, but loads all into memory). Use `ForEach-Object` for streaming/large data, `foreach` for in-memory collections.

PS3 — `[PSCustomObject]`: strongly typed, ordered, pipeline-friendly. `[hashtable]`: unordered, key-value, faster lookups. Convert: `[PSCustomObject]@{Key="Val"}` or `@($obj.PSObject.Properties | ForEach-Object { @{($_.Name) = $_.Value} })`.

PS4 — Terminating: stops execution (`throw`, `Stop-Process`). Non-terminating: continues, sets `$Error[0]`. `-ErrorAction` overrides preference. `$ErrorActionPreference`: global default. `try/catch` only catches terminating errors. Use `-ErrorAction Stop` to convert non-terminating to terminating.

PS5 — Splatting: `@params` passes hashtable keys as named parameters. Example: `Get-ChildItem @commonParams`. Differs from passing hashtable as single param: splatting expands keys to parameters, while passing as single param treats it as one argument.

PS6 — `Invoke-Command -ComputerName`: one-off remote command. `Enter-PSSession`: interactive remote session. Protocol: WS-Management (WinRM). PS 7+ supports SSH remoting via `Enable-PSRemoting -Transport SSH`.

PS7 — `$result += "one"` creates an array, but `return $result` returns a single string if only one item. `$x.GetType().Name` → `String`. If 0 items, returns `$null`. Correct pattern: `[array]$result = @()` or `return ,$result` (comma forces array). PS pipeline auto-flattens arrays.

PS8 — `[scriptblock]`: code container, serializable. Functions are named scriptblocks with parameters. Pass to remote: `Invoke-Command -ScriptBlock $sb -ArgumentList $args`. Double-hop: auth fails when remote session accesses another resource. Solve with CredSSP (less secure), Kerberos delegation, or pass data via `-ArgumentList`/temp files.

PS9 — `@()` forces array, `[array]` is type constraint. Force single result: `,$singleItem`. Indexing `$null` → `$null`. Indexing empty array `@()` → `$null`. `@()` prevents enumeration pitfalls.

PS10 — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (collection contains value), `-in` (value in collection). Case-sensitive: `-ceq`, `-clike`, `-cmatch`. `-contains` checks if collection has value (`$col -contains $val`), `-in` checks if value is in collection (`$val -in $col`).

PS11 — Module: collection of cmdlets/functions. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies, version). Binary: compiled DLL. `Import-Module` loads module, searches `$env:PSModulePath`, runs `.psm1` or loads DLL.

PS12 — `"..."` allows expansion (`$var`, `` ` ``). `'...'` literal. Expressions: `` "$(Get-Date)" ``. Here-string: `@"..."@` or `@'...'@` (multi-line, expansion control).

PS13 — `Get-Member`: shows object members. Pipeline: `Get-Process | Get-Member`. Properties: data. Methods: actions. NoteProperties: added properties. `Select-Object`: projects/renames properties. `Where-Object`: filters objects.

PS14 — Classes: v5+, C#-like syntax. Limitations: no multiple inheritance, limited interface support, constructors must match signature, no access modifiers (public by default). Use classes for complex data/models, functions for scripting/automation.

PS15 — `[CmdletBinding()]`: enables advanced function features. `SupportsShouldProcess`: `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: default param set. `ValueFromPipeline`: binds pipeline input. `Begin`/`Process`/`End`: pipeline processing blocks (init, per-item, cleanup).

PS16 — Providers: abstract data stores as drives. `Get-ChildItem` works on `HKLM:`, `Cert:`, `Env:`. Registry accessed like filesystem: `Get-ChildItem HKLM:\SOFTWARE`. Providers translate cmdlets to provider-specific operations.

PS17 — Runspaces: lightweight execution environments. `[runspacepool]`: manages multiple runspaces. `[powershell]` object: adds commands, invokes. `ForEach-Object -Parallel` (v7+): built-in parallelism with throttling. Manual runspace: more control, complex setup, better for long-running/stateful jobs.

PS18 — PSScriptAnalyzer: linting tool. Rules: syntax/style/security checks. Severity: error, warning, info. Custom rules: PowerShell scripts. Suppress: `#pragma disable`, `.psake.ps1`, IDE settings. CI/CD: run in pipeline, fail on errors, integrate with GitHub Actions/Azure DevOps.

PS19 — `$using:var`: serializes variable into remote session/job/parallel. `-ArgumentList`: passes as parameters. Serialization limits: CLIXML depth (default 64), breaks on circular refs, complex objects. Affects: large nested objects, custom classes with methods. Workaround: convert to hashtable, use `-ArgumentList` carefully.

PS20 — DSC: declarative config management. Configurations: desired state code. Resources: building blocks (File, Service, Package). LCM: agent that applies config. WinPS vs PS7: PS7 uses OpenDSC, cross-platform, improved performance. Replaced by: Ansible, Terraform, Chef, Puppet, or native cloud IaC (ARM, Bicep, Pulumi).
