DN1 — **class vs struct**: `class` is a reference type (heap-allocated, supports inheritance, nullable, GC-managed). `struct` is a value type (stack/inline-allocated, copy-on-assign, no inheritance, non-nullable by default). Use `struct` for small, immutable, short-lived data that doesn't require inheritance (e.g., coordinates, IDs, math vectors). Avoid if large or frequently mutated due to copy overhead.

DN2 — **IEnumerable<T> vs IQueryable<T>**: `IEnumerable<T>` enumerates in-memory (LINQ to Objects). `IQueryable<T>` represents an expression tree that can be translated to remote queries (LINQ to SQL/EF). Distinction matters because `IQueryable` pushes filtering/paging to the database, reducing memory/network overhead. `IEnumerable` pulls all rows first, then filters in memory.

DN3 — **async/await, Task vs ValueTask**: `async/await` compiles to a state machine that captures context, yields control, and resumes when the awaited operation completes, avoiding thread blocking. `Task` is a reference type with heap allocation overhead. `ValueTask` is a value type that avoids allocation when the async operation completes synchronously. Use `ValueTask` in hot paths or when methods complete synchronously most of the time.

DN4 — **DI lifetimes & Scoped-in-Singleton bug**: DI manages object creation/lifecycle via a container. `Transient`: new instance per injection. `Scoped`: one instance per DI scope (usually HTTP request). `Singleton`: one instance per app lifetime. Bug: Injecting a `Scoped` service into a `Singleton` captures it for the Singleton's lifetime, causing stale state, memory leaks, or thread-safety issues. Fix: Use `IServiceScopeFactory` to create scopes manually or inject via factory/delegate.

DN5 — **string vs ReadOnlySpan<char>, Span<T>**: `string` is immutable, heap-allocated, and causes allocations/copies for slicing/trimming. `ReadOnlySpan<char>` is a stack-only, zero-allocation view over memory (strings, arrays, buffers). `Span<T>` is the mutable counterpart. Use `Span<T>`/`ReadOnlySpan<T>` for high-performance parsing, avoiding allocations in hot paths. Requires `ref`/`unsafe` semantics and isn't directly GC-tracked.

DN6 — **GC, Generations, LOH, IDisposable**: GC traces live objects, reclaims unreachable memory, and compacts the heap. `Gen 0`: short-lived, frequent collections. `Gen 1`: buffer. `Gen 2`: long-lived, infrequent. Objects survive collections and are promoted. `LOH`: objects >85KB, not compacted (causes fragmentation), collected only with Gen 2. `IDisposable` enables deterministic cleanup of unmanaged resources (handles, native memory). GC only manages managed memory; finalizers are non-deterministic.

DN7 — **ConfigureAwait(false), SynchronizationContext**: Default `await` captures the current `SynchronizationContext` (UI thread, ASP.NET request context) and resumes there. `ConfigureAwait(false)` bypasses context capture, resuming on any thread pool thread. Use in libraries/background code to prevent deadlocks and improve scalability. Do NOT use in UI apps or code that explicitly requires context (e.g., legacy `HttpContext.Current`). Context capture enforces thread affinity; false breaks it.

DN8 — **.NET 8/9 features**: 
- **Primary constructors**: Parameters declared in type signature, auto-scoped to members. Reduces boilerplate.
- **Collection expressions**: `[1, 2, 3]`, `[..array]`, `[..list]`. Cleaner, more readable than `new[]` or `AddRange`.
- **FrozenDictionary**: Immutable, optimized for lookup-heavy, rarely-changing collections. Uses perfect hashing, lower memory, faster lookups than `Dictionary`.
- **DI Example**: `public record MyService([FromKeyedServices("db")] IDb db);` (requires `Microsoft.Extensions.DependencyInjection` keyed services).

DN9 — **ObjectDisposedException on DbContext under high concurrency**: Likely cause: DbContext registered as `Transient` or shared/static, but EF Core requires per-request scoping. DbContext is thread-unsafe and holds DB connections/change tracking. Fix: Register as `AddDbContext<DbContext>(ServiceLifetime.Scoped)`. Ensure DI creates a new instance per HTTP request. Scoped = one instance per DI scope (request). Transient = new per injection. Singleton = shared across all (causes race conditions/disposal conflicts).

DN10 — **record vs class, record struct**: `record` is reference-type, immutable by default, value-based equality, supports `with` expression. `class` is mutable, reference equality, inheritance-heavy. `record struct` is value-type, immutable, value equality, zero-allocation. Choose `record` for domain models/DTOs. Choose `record struct` for performance-critical, small, immutable data. Choose `class` for mutable, long-lived, or inheritance-heavy objects.

DN11 — **ref, out, in**: `ref`: Pass by reference, must be initialized before call, read/write. `out`: Pass by reference, must be assigned inside method, can be uninitialized before call (multiple returns). `in`: Pass by reference, read-only (avoids copy for large structs). Use `ref` for modifying existing values, `out` for parsing/multiple returns, `in` for performance with large structs.

DN12 — **Nullable reference types vs value types**: NRT (`string?`) is a compile-time warning system to prevent null reference exceptions. Doesn't change runtime behavior. `#nullable enable` turns it on. Nullable value types (`int?`) are runtime `Nullable<T>`, can hold `null` or a value. NRT is compile-time only; value type `?` changes runtime representation. NRT catches bugs early; value type `?` is for optional numeric/struct values.

DN13 — **LINQ, method vs query syntax, deferred execution**: LINQ unifies querying across collections, DBs, XML. Method syntax (`.Where(...)`) is fluent, chainable, preferred for complex ops. Query syntax (`from x in list where ...`) is SQL-like, compiles to method syntax. Deferred execution: Query isn't executed until enumerated (`.ToList()`, `foreach`). Allows composition, lazy evaluation, and remote translation.

DN14 — **Generic constraints**: `where T : class` (reference type), `where T : struct` (value type, non-nullable), `where T : new()` (parameterless constructor), `where T : IComparable<T>` (implements comparison). Combine when you need specific capabilities: `where T : class, IComparable<T>, new()` for flexible, type-safe collections/algorithms. Use constraints to enable compiler-checked operations without boxing or runtime checks.

DN15 — **abstract class vs interface, default methods**: Abstract class: can have state, constructors, non-public members, implementation. Single inheritance. Interface: contract only, multiple inheritance, public members. C# 8+ default interface methods allow interfaces to have implementations, blurring the line and enabling backward-compatible API evolution. Interfaces still cannot hold instance fields/state.

DN16 — **Middleware pipeline, Use/Map/Run, ordering, exception handling**: Sequential request processing. `Use()`: adds middleware. `Map()`: branches by path prefix. `Run()`: terminal, no `next`, ends pipeline. Ordering matters: auth before routing, error handling at end, static files early. `UseExceptionHandler` catches unhandled exceptions, logs, returns error response. Should be early but after critical setup to catch framework-level errors.

DN17 — **Channel<T> vs BlockingCollection<T>, backpressure**: `Channel<T>` is modern, async-native, supports bounded/unbounded, built-in backpressure. `BlockingCollection<T>` is older, sync-focused, wraps concurrent collections, less async-friendly. Example: `var ch = Channel.CreateBounded<int>(new(100) { FullMode = BoundedChannelFullMode.Wait });` Producers `WriteAsync`, consumers `ReadAsync`. Backpressure blocks producers when full, preventing memory exhaustion.

DN18 — **Source Generators, incremental generators**: Compile-time code generation via Roslyn APIs. Output C# source files. Faster/safer than reflection (runtime, slower, harder to optimize) and IL weaving (modifies compiled IL, breaks tooling/debugging). Incremental generators (`ISourceGenerator` replacement) use a caching pipeline, only run when inputs change. Faster, better IDE support, avoids full compilation re-runs.

DN19 — **TPL Dataflow, blocks vs Channels**: Pipeline/actor model for async data processing. `BufferBlock<T>`: stores items. `TransformBlock<TIn, TOut>`: processes & outputs. `ActionBlock<T>`: processes, no output. vs Channels: Channels are simpler, async-first, better for producer-consumer. Dataflow offers richer composition (fan-out/in, completion propagation, backpressure tuning), better for complex, multi-stage pipelines.

DN20 — **Minimal APIs vs Controllers, trade-offs, route groups, filters**: Minimal APIs: lightweight, inline handlers, less boilerplate, faster startup. Controllers: attribute-based, rich model binding, better for complex APIs. Trade-offs: Minimal APIs harder to test (inline), middleware integration is direct, OpenAPI requires Swashbuckle/NSwag. Controllers have better separation of concerns. Route groups: `app.MapGroup("/api").WithTags("Users")` for prefix/metadata. Endpoint filters: `builder.AddFilter(...)` for cross-cutting concerns (auth, validation) at route level, replacing middleware for specific paths.

P1 — **list vs tuple, set vs frozenset**: List: mutable, ordered, indexed, allows duplicates. Tuple: immutable, ordered, fixed size, heterogeneous, unpackable. Set: mutable, unordered, unique elements, hash-based. Frozenset: immutable set, hashable, can be dict key or set element.

P2 — **GIL**: Mutex allowing only one thread to execute Python bytecode at a time. Prevents memory management race conditions. Affects CPU-bound multithreading (no parallelism). I/O-bound workloads benefit (threads release GIL during I/O). Workarounds: Multiprocessing, C extensions (release GIL), asyncio, alternative interpreters (GraalPy, PyPy STM).

P3 — **deepcopy vs copy**: `copy.copy()`: shallow copy. Creates new object, references same nested objects. `copy.deepcopy()`: recursively copies all nested objects. Example: `a = [[1,2]]; b = copy.copy(a); b[0].append(99); print(a)` → `[[1, 2, 99]]` because inner list is shared.

P4 — **Decorators, timing example**: Functions that wrap others to extend behavior. Example:
```python
import time, functools
def log_time(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter()-start:.4f}s")
        return result
    return wrapper
```

P5 — **Generators, yield, yield from**: Functions that yield values lazily, maintaining state between yields. Memory efficient vs lists (no upfront storage/computation). `yield from`: delegates to another generator/collection, simplifying nested iteration and forwarding exceptions/returns.

P6 — **asyncio, run/gather/create_task, time.sleep**: Single-threaded scheduler for coroutines. `asyncio.run()`: entry point, creates loop, runs coroutine, closes loop. `asyncio.gather()`: runs multiple coroutines concurrently, returns results in order. `asyncio.create_task()`: schedules coroutine for background execution, returns Task. `time.sleep()` blocks the event loop thread; use `await asyncio.sleep()` instead.

P7 — **MRO, C3 linearization, diamond inheritance**: MRO: order Python searches for methods. Python 3 uses C3 linearization (ensures monotonicity & left-to-right order). Diamond: `D(B, C)` inherits `A`. MRO: `D → B → C → A`. `D().who()` checks B (not found) → C (found) → returns `"C"`. Prints `C`.

P8 — **Metaclass vs __init_subclass__**: Metaclass: class of a class, controls creation (`__new__`, `__init__`). Powerful but complex. `__init_subclass__`: class method called when subclass is created. Simpler, instance-level. Use metaclass for framework-level registration, schema enforcement, or automatic attribute modification. Use `__init_subclass__` for plugin systems, automatic registration, or setting defaults on subclasses.

P9 — **multiprocessing vs threading vs concurrent.futures, pickling**: Threading: I/O bound, shares memory, GIL limits CPU parallelism. Multiprocessing: CPU bound, separate processes, bypasses GIL, higher overhead. `concurrent.futures`: high-level API wrapping both. Pickling: multiprocessing serializes args/results via pickle. Fails for lambdas, open handles, C extensions. macOS uses `spawn` (requires pickling), Linux uses `fork` (copies memory, less pickling).

P10 — **__slots__**: Declares fixed attributes, prevents `__dict__` creation. Use for memory optimization, performance, preventing accidental attributes. Impact: significantly reduces memory per instance (no dict overhead). Prevents dynamic attribute addition. Can't be used with `__dict__` or inheritance without care.

P11 — **Virtual environments, venv vs virtualenv vs conda**: Isolated Python environment with its own packages/interpreter. Prevents dependency conflicts. `venv`: standard library, lightweight, pure Python. `virtualenv`: third-party, more features, historically preferred. `conda`: package + environment manager, handles non-Python binaries, data science focused, heavier.

P12 — **Comprehensions vs map/filter**: Comprehensions: `[x for x in lst if cond]`, `{k:v for ...}`, `{x for ...}`. Pythonic, readable, often faster. `map`/`filter`: functional, return iterators, lazy. Prefer comprehensions for readability/simple logic. Use map/filter for performance with built-ins or complex pipelines.

P13 — **== vs is, interning, small integers**: `==`: value equality. `is`: identity (same object). Interning: Python caches small integers (-5 to 256) and some strings for memory/performance. `a is b` returns True for small ints because they reference the same cached object.

P14 — **\*args, \*\*kwargs, /, \***: `*args`: collects extra positional args into tuple. `**kwargs`: collects extra keyword args into dict. `/`: positional-only parameters (before `/`). `*`: keyword-only parameters (after `*`). Usage: flexible APIs, forwarding arguments, enforcing calling conventions.

P15 — **Context managers, __enter__/__exit__ vs @contextmanager**: Ensure setup/teardown (`with` statement). `__enter__`/`__exit__`: class-based, explicit control. `@contextmanager`: generator-based, simpler. Example (DB):
```python
class DBConn:
    def __enter__(self): self.conn = connect(); return self.conn
    def __exit__(self, *e): self.conn.close()
```

P16 — **Type hinting, Union, Optional, Literal, TypeVar, Protocol, mypy/pyright**: Static annotations for IDE/tooling, not enforced at runtime. `Union[A, B]`: either type. `Optional[T]` = `Union[T, None]`. `Literal["a","b"]`: exact value constraint. `TypeVar`: generic type variable with constraints. `Protocol`: structural subtyping (duck typing). `mypy`/`pyright`: static analyzers that check types against hints, catch bugs pre-runtime.

P17 — **Data model (dunder methods), repr/str, eq/hash, getattr/getattribute**: `__repr__`: unambiguous, developer-focused. `__str__`: readable, user-focused. `__eq__`: value equality. `__hash__`: hash for dict/set keys. `__getattr__`: called when attribute not found. `__getattribute__`: called for every access (use carefully). Defining `__eq__` without `__hash__` sets `__hash__ = None`, making instances unhashable.

P18 — **Descriptors, protocol, property/classmethod/staticmethod**: Objects implementing `__get__`, `__set__`, `__delete__`. Control attribute access. `property`: uses descriptor to run getter/setter on access. `classmethod`: descriptor binds method to class, passes class as first arg. `staticmethod`: descriptor ignores instance/class, returns raw function. All are descriptors under the hood.

P19 — **Import system, relative/absolute, sys.path, __init__.py, namespace packages, finder/loader**: Relative: `from . import mod` (package-relative). Absolute: `from pkg import mod` (sys.path root). `sys.path`: search directories. `PYTHONPATH` appends to it. `__init__.py`: marks directory as package, runs on import. Namespace packages: omit `__init__.py` (PEP 420), allows splitting package across directories. Finder: locates modules. Loader: loads/compiles module. `importlib` standardizes this.

P20 — **dataclasses vs attrs/Pydantic, __post_init__, frozen, inheritance, Pydantic choice**: `dataclasses`: built-in, generates `__init__`, `__repr__`, `__eq__`, `__hash__`. Simple, fast. `attrs`: more flexible, validation, converters, better inheritance. `Pydantic`: runtime validation, serialization, type coercion, schema generation. `__post_init__`: runs after `__init__` for validation. `frozen=True`: immutable, auto-generates `__hash__`. Inheritance: dataclasses handle it well but can be tricky with `__init__` overrides. Choose Pydantic for strict validation, serialization/deserialization, API models, or dynamic type coercion.
