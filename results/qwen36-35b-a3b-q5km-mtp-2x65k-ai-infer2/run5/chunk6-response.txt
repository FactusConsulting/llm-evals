JS1 — `var` is function-scoped and hoisted with initialization to `undefined`. `let` and `const` are block-scoped, hoisted but in a Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment. Hoisting moves declarations to the top of their scope before execution, but only declarations (not initializations) are hoisted for `let`/`const`.

JS2 — The event loop monitors the call stack and task queues. When the stack is empty, it pushes the next macrotask (e.g., `setTimeout`, I/O). After each macrotask, it drains the entire microtask queue (e.g., `Promise.then`, `queueMicrotask`) before returning to the macrotask queue. This ensures async promise callbacks run before UI repaints or timers.

JS3 — A closure is a function that retains access to its lexical scope even when executed outside it. Example: `function makeCounter() { let i=0; return () => ++i; }`. The classic `for` loop bug uses `var`, causing all timeouts to share the same `i` (logs `3,3,3`). Fix: use `let` (block scope), wrap in an IIFE, or pass `i` as a third argument to `setTimeout`.

JS4 — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that pauses execution until resolution, enabling synchronous-style error handling via `try/catch`. `Promise.all` rejects immediately on the first rejection. `Promise.allSettled` waits for all promises to settle, returning an array of `{status, value/reason}` objects.

JS5 — `interface` defines object shapes, supports declaration merging, and cannot contain runtime code. `type` is a broader alias supporting unions, intersections, tuples, and mapped types. Use `interface` for public APIs/objects, `type` for primitives/unions. Discriminated unions use a common literal property (e.g., `type: 'a' | 'b'`) to enable safe type narrowing.

JS6 — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar: `extends` uses `Object.setPrototypeOf` on the constructor and `Object.create` on the prototype chain, preserving the prototype model.

JS7 — `this` is dynamically bound based on call site. Priority: 1. `new` (new instance), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (`window` or `undefined` in strict mode). `bind()` returns a new function with fixed `this`. It cannot be re-bound; subsequent `bind`/`call`/`apply` calls are ignored.

JS8 — `WeakRef` holds a weak reference that doesn't prevent garbage collection. `FinalizationRegistry` executes a callback when weakly referenced objects are collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the GC can track them; when a key is collected, the entry is automatically removed, preventing memory leaks.

JS9 — V8 uses hidden classes (shape inference for fast property access) and inline caching (caches shape info at call sites for O(1) lookups). Deoptimization occurs when assumptions break (e.g., dynamic property addition, `delete`, type changes, `eval`/`with`), forcing fallback to slower interpreter. Avoid polymorphic property access and `delete` in hot paths.

JS10 — Tree-shaking removes unused exports at build time. It works reliably with ES modules because imports/exports are static and parseable. CommonJS uses dynamic `require()`, evaluated at runtime, making static analysis impossible. Side effects in `package.json` can disable tree-shaking if modules mutate globals.

JS11 — `null` is intentional absence; `undefined` is uninitialized. `==` coerces types (`null == undefined` is `true`), `===` checks type/value (`false`). `??` returns right operand only if left is `null`/`undefined` (unlike `||` which catches `0`/`""`). `?.` safely accesses nested properties, returning `undefined` instead of throwing.

JS12 — `map` transforms, `filter` selects, `reduce` accumulates to a single value. `reduce` with an initial value prevents `undefined` on empty arrays and sets accumulator type. `flatMap` maps then flattens one level; useful for transforming and flattening nested data in a single pass without nested loops.

JS13 — Template literals use backticks, support multi-line strings and `${expr}` interpolation. Tagged templates call a function with an array of string parts and interpolated values. Example: `html` function escapes expressions to prevent XSS in dynamic HTML generation.

JS14 — Destructuring unpacks values: `{a, b: renamed} = obj`, `[a, b] = arr`. Default values: `a = 1`. Rest operator collects remaining: `const {a, ...rest} = obj` or `[a, ...rest] = arr`. Rest must be last and captures all remaining properties/elements.

JS15 — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, maps). Avoid `for...in` on arrays: it iterates keys, not values, includes inherited properties, and doesn't guarantee order.

JS16 — Generics use type parameters: `function id<T>(arg: T): T`. Constraints: `T extends string | number`. Conditional types: `type NonNullable<T> = T extends null | undefined ? never : T`. `infer` extracts types: `type ElementType<T> = T extends (infer U)[] ? U : T`.

JS17 — CommonJS: dynamic, synchronous, `require`/`module.exports`, Node default historically. ES Modules: static, asynchronous, `import`/`export`, browser/Node native. `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM instead of CJS.

JS18 — Structural typing checks compatibility by shape, not names. Excess property checks apply only to object literals assigned to variables/interfaces, not function arguments. `extends` defines assignability; `satisfies` validates type without widening. Variance: `in` (contravariant parameters), `out` (covariant returns), `in out` (bivariant).

JS19 — `Proxy` wraps objects to intercept operations (`get`, `set`, `apply`, etc.). `Reflect` mirrors traps and provides default behavior. Example: validation proxy intercepts `set` to check types before assignment, throwing on invalid data.

JS20 — `SharedArrayBuffer` shares memory between main thread and Web Workers. `Atomics` provides atomic operations on typed arrays in SAB. Ordering: sequential consistency via `Atomics`. `Atomics.wait` blocks until value changes/timeout; `Atomics.notify` wakes threads. Requires cross-origin isolation headers.

B1 — `$@` expands to separate quoted words (`"$1" "$2"`), `$*` expands to a single quoted string (`"$1 $2 ..."`). `"$@"` preserves individual arguments. `"$*"` joins them using the first character of `IFS`.

B2 — `set -e`: exit immediately on command failure. `set -u`: treat unset variables as errors. `set -o pipefail`: pipeline returns the exit status of the last non-zero command, not just the final command.

B3 — `$(command)` is modern, nestable, and preferred. `` `command` `` is legacy, harder to nest. `$((expression))` is bash arithmetic expansion. `expr` is an external command, slower, and legacy.

B4 — Process substitution `<(cmd)` creates a file descriptor (e.g., `/dev/fd/63`) with `cmd`'s output. Used when a command expects a file but needs dynamic input. Example: `diff <(sort file1) <(sort file2)`.

B5 — Use `find ... -print0 | while IFS= read -r -d '' f; do ...` or `for f in *; do ...` with quotes. `for f in $(ls)` breaks on spaces/globs/newlines, parses `ls` output (dangerous), and fails on special characters.

B6 — Here doc `<<EOF` passes multi-line input to stdin. `<<-EOF` strips leading tabs. Here string `<<<` passes a single string to stdin.

B7 — `cmd > file 2>&1`: stdout → file, stderr follows stdout → file. `cmd 2>&1 > file`: stderr → terminal (original stdout), stdout → file. `cmd &> file`: bash shorthand for `> file 2>&1`. First two differ because redirections evaluate left-to-right.

B8 — ```bash
lock_dir="/tmp/mylock"
cleanup() { rm -rf "$lock_dir"; }
trap cleanup EXIT INT TERM
if mkdir "$lock_dir" 2>/dev/null; then
  echo "Lock acquired"
  # critical section
else
  echo "Lock held by PID $(cat "$lock_dir/pid")"
  exit 1
fi
echo $$ > "$lock_dir/pid"
```
`mkdir` is atomic on POSIX, preventing race conditions. File creation isn't atomic and can be overwritten.

B9 — Single quotes: literal, no expansion. Double quotes: variable/command expansion, preserves spaces. No quotes: word splitting and globbing. Example: `var="a b"; echo $var` → `a b`; `echo "$var"` → `a b`; `echo '$var'` → `$var`.

B10 — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin supporting `&&`, `||`, regex, no word splitting/globbing on RHS. `[` is POSIX external `test`, stricter and less feature-rich.

B11 — `$?`: exit status of last command. `$$`: PID of current shell. `$!`: PID of last background process. `$#`: number of positional parameters.

B12 — `foo() { ... }` or `function foo { ... }` (latter is bash-specific). Return values: `return <int>` (0-255 exit code). Use `echo` for stdout or global variables for complex returns.

B13 — `PATH` is colon-separated dirs bash searches for executables. Resolves by checking `PATH`, then builtins, then hash table. Builtin: compiled into shell (`cd`, `echo`). External: separate binary. `type cmd` or `command -v cmd` shows which.

B14 — `trap 'cleanup' EXIT INT TERM`. `EXIT` runs on normal exit. `ERR` runs on non-zero exit. `INT`/`TERM` run on signals. Execution order: traps run LIFO for same signal; `EXIT` runs last.

B15 — `xargs` builds/executes commands from stdin. Command substitution captures output into a variable. `xargs -0` + `find -print0` handles spaces/newlines safely. `xargs -P N` runs N processes in parallel.

B16 — Arrays: `arr=(a b c)`, `${arr[0]}`, `${#arr[@]}`, `for i in "${arr[@]}"; do`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${!assoc[@]}`. Associative uses string keys and requires `declare -A`.

B17 — Subshell `(...)` runs in child process; variable changes are lost. Group `{ ...; }` runs in current shell; variables persist. Piping to `while` creates a subshell, so variable changes inside are lost. Fix: `while ...; done < <(cmd)`.

B18 — `SIGINT` (Ctrl+C, interrupt), `SIGTERM` (graceful stop), `SIGHUP` (terminal hangup), `SIGKILL` (uncatchable, force kill). Handle graceful shutdown: trap `SIGTERM`, kill background jobs, `wait`, cleanup.

B19 — ```bash
split -l 10000 log.log part_
find part_* -print0 | xargs -0 -P 4 -I {} bash process.sh {}
cat part_* > merged.log
```
Trade-offs: CPU vs I/O, split/merge overhead. Error propagation: use `set -o pipefail`, check exit codes, aggregate errors in a temp file.

B20 — `exec` replaces the current shell or redirects FDs. `exec 3>file` opens FD 3. `exec 3>&-` closes it. Coprocess: `coproc cmd` creates bidirectional pipe for async communication. Use for persistent background services or interactive tools.

PS1 — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console (bypasses pipeline, breaks automation). Matters because pipelines expect objects, not formatted text.

PS2 — Pipeline streams objects between cmdlets. `ForEach-Object` processes each object in the pipeline (streaming, memory efficient). `foreach` statement iterates over a collection in memory (faster for large collections, but loads all into memory).

PS3 — `[PSCustomObject]`: strongly typed, ordered, pipeline-friendly. `[hashtable]`: unordered, untyped, faster lookups. Convert: `[PSCustomObject]@{key="val"}` or `@($obj.PSObject.Properties | ForEach-Object { $_.Name = $_.Value })`.

PS4 — Terminating errors stop execution (throw exception). Non-terminating errors continue, set `$Error`. `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors.

PS5 — Splatting `@params` passes a hashtable's keys as named parameters. Differs from passing a hashtable as a single param: splatting expands to named parameters, enabling dynamic passing and validation.

PS6 — `Invoke-Command -ComputerName`: one-off remote command. `Enter-PSSession`: interactive remote session. Uses WS-Management (WinRM) by default. PS7+ supports SSH transport via `New-PSSession -HostName ...`.

PS7 — `$result += "one"` creates an array, but returning a single item doesn't wrap it. `$x.GetType().Name` → `String`. If 0 items, returns `$null`. Correct pattern: `[array]$result = @()` or `return ,$result` to force array.

PS8 — `[scriptblock]` is a code container; functions are named scriptblocks with parameters. Pass to remote: `Invoke-Command -ScriptBlock $sb -ArgumentList $args`. Double-hop: auth fails when remoting to B then to C. Solve with `-ArgumentList` (preferred), CredSSP, or constrained endpoints.

PS9 — `@()` forces array. `[array]` is type constraint. Single result into array: `,$result`. Indexing `$null` → error. Indexing empty array → `$null`.

PS10 — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right in left). Case-sensitive: `-ceq`, `-clike`, `-cmatch`. `-contains` checks if collection contains value. `-in` checks if value is in collection.

PS11 — Module: collection of functions/cmdlets. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies). Binary: compiled DLL. `Import-Module` loads into session, searches `$env:PSModulePath`.

PS12 — `"..."` interpolates variables/expressions. `'...'` literal. Expressions: `$(expr)` or `${expr}`. Here-string: `@"..."@` for multi-line, preserves formatting.

PS13 — `Get-Member`: shows object members. Properties: data. Methods: actions. NoteProperties: custom added properties. `Select-Object`: projects/selects properties. `Where-Object`: filters objects.

PS14 — Classes (v5+): C#-like. Limitations: no multiple inheritance, limited interface support, constructors must match signature, no access modifiers. Use classes for complex data models, functions for scripting/utility.

PS15 — `[CmdletBinding()]`: enables advanced features. `SupportsShouldProcess`: enables `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: sets default param set. `ValueFromPipeline`: binds pipeline input. Begin/Process/End: pipeline processing blocks (init, per-object, cleanup).

PS16 — Providers abstract data stores as drives. `Get-ChildItem` works on Registry (`HKLM:`), Certificates (`Cert:`), Environment (`Env:`). Registry accessed like filesystem: `Get-ChildItem HKLM:\SOFTWARE`.

PS17 — Runspaces: lightweight execution contexts. `[runspacepool]`: manages multiple runspaces. `[powershell]`: object to add commands. `ForEach-Object -Parallel` (v7+): built-in parallelism with throttling. Manual runspace: more control, complex, requires serialization.

PS18 — PSScriptAnalyzer: linting tool. Rules: static analysis checks. Severity: warning/error/info. Custom rules: PowerShell scripts. Suppress: `#pragma disable` or config file. CI/CD: run in pipeline, fail on errors.

PS19 — `$using:` serializes local variable into remote session/job. `-ArgumentList` passes values directly. Serialization limits: CLIXML depth/size limits, breaks on complex objects/circular refs. Use `-ArgumentList` for primitives, `$using:` for simple vars.

PS20 — DSC: declarative config management. Configurations: desired state definitions. Resources: building blocks (File, Service). LCM: agent that applies config. WinPS DSC: Windows-only, XML-based. PS7 DSC: cross-platform, YAML/JSON, integrated with PowerShell. Replaced/supplemented by Ansible, Terraform, Chef, or native cloud IaC.
