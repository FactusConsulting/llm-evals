## Kubernetes

**K1** — A **Deployment** manages stateless workloads: pods are interchangeable, have random names, and are replaced without preserving identity. A **StatefulSet** manages stateful workloads: pods have stable, unique network IDs (e.g., `app-0`, `app-1`), ordered deployment/scaling, and stable persistent storage per pod.

**K2** — `kube-proxy` watches the API server and creates iptables/IPVS rules that map the Service's ClusterIP:Port to the backend Pod IPs:Ports. When traffic hits the ClusterIP, the kernel's netfilter redirects it to one of the healthy pod IPs using round-robin or least-connection balancing.

**K3** — A **PersistentVolume (PV)** is a cluster-provisioned storage resource (static). A **PersistentVolumeClaim (PVC)** is a user's request for storage. A **StorageClass** is a dynamic provisioning template. Relation: A PVC binds to an existing PV or triggers a StorageClass to dynamically create a PV, which is then bound to the PVC.

**K4** — 1. `kubectl logs <pod> --previous` to check crash reason. 2. `kubectl describe pod` for Exit Codes, OOMKilled events, or probe failures. 3. Verify resource limits/requests match actual usage. 4. Check app dependencies (DB connectivity, env vars, startup commands, file permissions).

**K5** — CoreDNS provides internal DNS resolution for `Service` and `Pod` names. If CoreDNS pods are down, internal service discovery fails (pods can't resolve each other by name), but direct IP communication and external DNS resolution remain unaffected.

**K6** — The scheduler uses **filtering** to remove nodes that fail requirements (insufficient resources, taints, node selectors, affinity/anti-affinity). It then **scores** remaining nodes based on factors like: 1) LeastRequestedPriority (balances CPU/memory), 2) NodeAffinity/TaintToleration weights, 3) InterPodAffinity/AntiAffinity, 4) Resource allocation fairness. Highest score wins.

**K7** — Yes, it will schedule: 3.5GB + 256Mi < 4GB. At runtime, Kubernetes enforces the 512Mi limit via cgroups. If the container exceeds 512Mi, the kernel OOM killer terminates it (exit code 137), regardless of the request value.

**K8** — Client → External LB (routes to Ingress Controller IP) → Ingress Controller (NGINX) reads Ingress resource → matches host/path → routes to Kubernetes Service → Service resolves to Endpoints (pod IPs) → kube-proxy/iptables redirects traffic to pod IP → pod receives request.

**K9** — A `NetworkPolicy` restricts pod-to-pod traffic using selectors and rules. Default behavior (no policies): all ingress/egress allowed. When applied: only traffic matching the policy is allowed; all other traffic is denied.

**K10** — `RollingUpdate` gradually replaces old pods with new ones (zero downtime). `Recreate` terminates all old pods before starting new ones (downtime). Choose `Recreate` for stateful apps that cannot run concurrent versions, or when strict sequential updates are required.

**K11** — A namespace provides virtual cluster isolation for resources. Default namespaces: `default`, `kube-system`, `kube-public`.

**K12** — `kubectl describe pod` shows detailed runtime state. Unlike `get`, it reveals: 1) Pod events (scheduling, pull, probe failures), 2) Container status details (restart count, last state, exit codes), 3) Resource usage, volume mounts, and environment variables.

**K13** — A `ConfigMap` stores non-sensitive configuration data. Pods consume it via: 1) Environment variables (`envFrom` or `env.valueFrom.configMapKeyRef`), 2) Volume mounts (files appear in the pod's filesystem).

**K14** — `ClusterIP`: internal cluster-only access. `NodePort`: exposes the service on each node's IP at a static port (30000-32767). `LoadBalancer`: provisions a cloud provider external load balancer with a public IP.

**K15** — A `DaemonSet` ensures a copy of a pod runs on every node (or matching nodes). Use it for node-level agents (logging, monitoring, metrics collection) instead of a Deployment, which would require manual pod placement.

**K16** — **Taints** repel pods from nodes; **tolerations** allow pods to schedule on tainted nodes. **Node affinity** attracts pods to nodes. Use case: Taints for dedicated GPU nodes (repel general workloads), Affinity for zone-aware scheduling (attract pods to specific AZs).

**K17** — An Operator is a custom controller that manages complex, stateful applications using CRDs and custom reconciliation logic. Unlike standard controllers, it encodes operational knowledge (backups, upgrades, failover) into code, solving the need for manual intervention in stateful workloads.

**K18** — etcd uses a **linearizable** consistency model via Raft. If quorum is lost, the cluster becomes read-only/unwritable. If 2/3 etcd nodes are permanently lost, quorum cannot be formed; recovery requires restoring from the latest etcd snapshot + WAL, or adding a new node and restoring the cluster state.

**K19** — `Role`/`ClusterRole` define permissions (verbs/resources). `RoleBinding`/`ClusterRoleBinding` bind roles to users/groups/serviceaccounts.
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: dev
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: dev-pod-reader
  namespace: dev
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — Default `ndots:5` causes Kubernetes to append each search domain suffix before querying upstream, generating excessive DNS queries. Fix: set `dnsConfig: options: [{name: "ndots", value: "2"}]` in the pod spec, or use FQDNs with a trailing dot (`service.namespace.svc.cluster.local.`).

## Development

**D1** — `merge` preserves history with a merge commit; `rebase` rewrites history into a linear timeline. Avoid rebasing on shared/public branches to prevent forcing others to reconcile divergent histories.

**D2** — TCP is connection-oriented, reliable, and ordered; UDP is connectionless, unreliable, and low-latency. TCP: HTTP, SMTP. UDP: DNS, VoIP/Video streaming.

**D3** — A race condition occurs when concurrent threads/processes access shared state without synchronization, leading to unpredictable results. Example: two threads incrementing a shared counter without a mutex, resulting in lost updates.

**D4** — Symmetric encryption uses one key for encrypt/decrypt (fast). Asymmetric uses a public/private key pair (secure key exchange). TLS uses asymmetric encryption for the handshake/key exchange, then switches to symmetric encryption for bulk data transfer.

**D5** — Each Dockerfile instruction creates an immutable image layer. Layer caching speeds up builds by reusing unchanged layers. Best practice: order instructions from least to most frequently changing (e.g., install dependencies before copying source code).

**D6** — 1. Check upstream service logs/metrics for errors. 2. Verify rate limiting/throttling configs. 3. Check resource exhaustion (CPU/memory limits). 4. Inspect load balancer/ingress health checks. Order: application → infrastructure → network.

**D7** — CAP theorem states a distributed system can only guarantee two of three: Consistency, Availability, Partition tolerance. CP example: CockroachDB/HBase (prioritize data correctness during network splits). AP example: DynamoDB/Cassandra (prioritize uptime, allow stale reads).

**D8** — Horizontal scaling adds more instances; vertical scaling increases resources of existing instances. Horizontal scaling requires: stateless design, external load balancing, distributed data stores, and message queues.

**D9** — An environment variable is a dynamic key-value pair passed to processes. Persist across sessions: add `export VAR=value` to `~/.bashrc` or `~/.profile`, then run `source ~/.bashrc`.

**D10** — JSON is a strict, machine-friendly key-value format. YAML is indentation-based and human-readable. JSON advantage: universal parsing, strict syntax. YAML advantage: readability, supports comments, less verbose.

**D11** — A REST API is an architectural style using standard HTTP methods. GET: retrieve resource. POST: create new resource. PUT: replace/update resource. DELETE: remove resource.

**D12** — Version pinning locks dependencies to exact versions (e.g., `package@1.2.3`). It ensures reproducible builds, prevents unexpected breaking changes, and simplifies debugging.

**D13** — Compiled languages translate source to machine code before execution (C, Rust). Interpreted languages execute source line-by-line at runtime (Python, JavaScript). Note: many modern languages use hybrid JIT/AOT compilation.

**D14** — A reverse proxy sits in front of servers, routing client requests to backend services. A forward proxy sits in front of clients, routing outbound requests (often for filtering/anonymity). Examples: Nginx (reverse, API gateway/routing), Squid (forward, corporate proxy/caching).

**D15** — A deadlock occurs when two+ processes wait indefinitely for each other's resources. Coffman conditions: 1. Mutual exclusion, 2. Hold and wait, 3. No preemption, 4. Circular wait.

**D16** — Eventual consistency guarantees all replicas will converge without further updates. Cassandra uses tunable consistency levels (`ONE`, `QUORUM`, `ALL`, `SERIALIZABLE`). For read-after-write, clients use `QUORUM` or `SERIALIZABLE` with client-side retries to ensure they see their own writes.

**D17** — mTLS requires both client and server to present and verify certificates. Handshake: ClientHello → ServerHello+Cert → ServerKeyExchange → ClientKeyExchange+Cert → CertificateVerify → Finished. Both sides validate certs against a trusted CA. Used in service meshes (Istio), zero-trust networks, and internal microservices.

**D18** — A hash table maps keys to values via a hash function. Collision resolution: chaining (linked lists/arrays per bucket) vs open addressing (linear/quadratic probing, double hashing). Average time complexity: O(1) for insert/lookup/delete. Worst case: O(n) if all keys collide.

**D19** — A circuit breaker prevents cascade failures by failing fast when a downstream service is unhealthy. States: Closed (normal), Open (fail fast, timer expires), Half-open (send limited probe requests). Relates to retries: retries with exponential backoff should be bounded; the circuit breaker trips faster than retries would, preventing retry storms.

**D20** — Optimistic concurrency assumes no conflicts, checking at commit (row versioning/ETag). Pessimistic concurrency locks resources during transactions (`SELECT FOR UPDATE`). Choose optimistic for read-heavy/low-contention workloads; choose pessimistic for high-write contention or critical financial transactions requiring strict isolation.
