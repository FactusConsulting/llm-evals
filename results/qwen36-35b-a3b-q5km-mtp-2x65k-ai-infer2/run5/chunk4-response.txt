## Go

**G1** — A slice is a lightweight descriptor (`ptr`, `len`, `cap`) referencing a contiguous array segment; an array is a fixed-size value type. When appending to a slice at capacity, Go allocates a new backing array (typically doubling capacity), copies existing elements, and returns a new slice pointing to it.

**G2** — `var x int` declares with explicit type and zero value; `x := 0` infers type and requires at least one new variable on the left. You cannot use `:=` outside functions, when redeclaring all variables on the left, or when type inference is ambiguous/insufficient.

**G3** — A goroutine is a lightweight, multiplexed execution context managed by the Go runtime. Unlike OS threads (heavy, 1:1 kernel mapping), goroutines are M:N scheduled. The GMP model: `G` (goroutine), `M` (OS thread/machine), `P` (processor/context). The scheduler multiplexes Gs onto Ms using Ps for work-stealing and preemption.

**G4** — Channels are typed conduits for communication and synchronization. Unbuffered channels block both sender and receiver until both are ready. Buffered channels have a capacity; sends block only when full, receives block only when empty. Sending to a full buffered channel blocks until a receiver consumes an element.

**G5** — `context` propagates deadlines, cancellation, and request-scoped values across API boundaries. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, http.MethodGet, "http://example.com", nil)
http.DefaultClient.Do(req) // cancels automatically on timeout
```

**G6** — Go uses implicit interface satisfaction (duck typing); types implement interfaces by implementing methods, with no `implements` keyword. Unlike Java/C#, interfaces are not tied to classes. `interface{}`/`any` matches any type, enabling generics/abstraction, but is dangerous because type assertions can panic and compile-time safety is lost.

**G7** — The code has a data race: `ready` is written in one goroutine and read in another without synchronization, violating Go's memory model (no happens-before guarantee). Fix: use `atomic.Bool` for `ready`, or `sync.Once`/a channel to signal completion, ensuring `data` is visible.

**G8** — `sync.Mutex` provides exclusive access; `sync.RWMutex` allows concurrent readers or a single writer. `sync.Map` is optimized for high-read, low-write workloads or keys unknown at compile time. Trade-off: `sync.Map` has higher overhead for frequent writes or known-key maps; a regular `map` + `Mutex` is faster for write-heavy or static-key scenarios.

**G9** — `go.mod` declares module path, Go version, and direct dependencies. `go.sum` stores cryptographic hashes of dependency versions for integrity. `go mod tidy` removes unused deps, adds missing ones, and updates `go.sum`. MVS (Minimum Version Selection) picks the lowest compatible version for each dependency to avoid version bloat and conflicts.

**G10** — `defer` schedules a function call to run after the surrounding function returns. Multiple defers execute in LIFO order. Gotcha in loops: variables are captured by reference at defer execution time, not declaration. Fix by passing values as arguments (`defer f(x)`) or shadowing in the loop (`x := x; defer f(x)`).

**G11** — A pointer holds a memory address. Zero value: `nil`. Pointer to a struct literal: `&MyStruct{Field: value}`. Go automatically handles address-taking for struct literals in many contexts.

**G12** — `init()` runs automatically before `main()` at program startup. It executes once per package. A package can have multiple `init()` functions; they run in declaration order. Complex initialization logic should be avoided in `init()` to maintain predictability.

**G13** — `make(T, args)` initializes slice, map, or channel and returns the initialized `T` (not a pointer). `new(T)` allocates zeroed memory and returns `*T`. `make` is for reference types that require initialization; `new` is for any type but returns a pointer to zero value.

**G14** — Go uses `error` interface (`Error() string`). Idiomatic pattern: `if err != nil { return err }`. `errors.Is(err, target)` checks if `err` wraps `target`. `errors.As(err, &target)` extracts the concrete type from the error chain. `==` only checks exact equality, failing with wrapped errors.

**G15** — Map: `nil` (use `make`). Slice: `nil` (len=0, cap=0). Channel: `nil` (blocks forever). Struct: zero values of each field. All are safe to use but may panic if dereferenced/used without initialization.

**G16** — A race occurs when concurrent goroutines access shared data without synchronization, with at least one write. `-race` flag instruments code at compile/runtime to detect conflicting accesses. Fix: wrap shared state with `sync.Mutex` or communicate via channels. Example: `mu.Lock(); counter++; mu.Unlock()`.

**G17** — `select` waits on multiple channel operations, like a `switch` for channels. If multiple cases are ready, one is chosen pseudo-randomly. Timeout: `case <-time.After(d):`. Blocks until at least one case is ready or default is present.

**G18** — Escape analysis determines if variables live on stack or heap. Escapes if: address taken, returned, stored in heap-allocated struct, or size unknown at compile time. Inspect with `go build -gcflags="-m"`. Matters because heap allocations trigger GC, impacting latency and throughput.

**G19** — `reflect.Type` holds type metadata; `reflect.Value` holds the actual value/data. Costs: slow, bypasses compile-time checks, causes allocations. Justified for serialization, ORMs, or generic utilities. Prefer code generation (`go generate`, `stringer`) for performance-critical paths.

**G20** — `//go:embed` compiles static files/directories into the binary. Returns `embed.FS` implementing `io/fs.FS`. Supports glob patterns. Limitations: only static files, no runtime generation, patterns limited to compile-time known paths. Interacts with `io/fs.FS` for standard file operations (`fs.ReadFile`, `fs.WalkDir`).

## Rust

**R1** — Ownership ensures memory safety without GC. Rules: 1. Each value has exactly one owner. 2. Only one owner at a time. 3. Owner drops value when out of scope. Moves transfer ownership; clones duplicate data.

**R2** — `String` is an owned, heap-allocated, growable string. `&str` is a borrowed string slice (fat pointer to data + length). Use `String` when ownership/modification is needed; use `&str` in signatures for borrowing/reading to avoid allocations.

**R3** — Borrowing lets you reference data without taking ownership. Rules: either one `&mut T` OR any number of `&T`, but never both simultaneously. Enforced at compile time to prevent data races and dangling references.

**R4** — `Result<T, E>` represents success (`Ok`) or error (`Err`). `Option<T>` represents `Some(T)` or `None`. `?` propagates errors/returns early. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

**R5** — `Box<T>`: single-owner heap allocation. `Rc<T>`: reference-counted, single-threaded shared ownership. `Arc<T>`: atomic reference-counted, thread-safe shared ownership. Use `Box` for owned heap data, `Rc` for shared single-threaded data, `Arc` for shared multi-threaded data.

**R6** — Traits define shared behavior with optional default implementations and associated types. Unlike Go, Rust requires explicit `impl Trait for Type` blocks. `dyn Trait` creates a trait object (dynamic dispatch, vtable). `T: Trait` is a generic bound (static dispatch, monomorphization).

**R7** — Fails because the compiler cannot determine which input lifetime the return value should borrow. Fix by annotating lifetimes: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { if x.len() > y.len() { x } else { y } }`.

**R8** — `Send`: safe to transfer ownership across threads. `Sync`: safe to share `&T` across threads. `Rc<T>` isn't `Send`/`Sync` due to non-atomic reference counting. `Arc<T>` uses atomic operations, making it `Send` + `Sync` for concurrent use.

**R9** — `async/await` compiles to a state machine implementing `Future`. `Future::poll` advances execution. An executor (e.g., Tokio) drives futures to completion. Differs from Go: Rust futures are lazy, require explicit executors, and use cooperative polling; Go uses implicit M:N runtime scheduling with preemptive goroutines.

**R10** — `unsafe` bypasses compiler safety checks. Three operations: dereference raw pointers, call `unsafe` functions, implement `unsafe` traits. Justified for FFI, low-level sys ops, or performance-critical code where safety is provably maintained.

**R11** — Pattern matching exhaustively handles enum variants. `match` must cover all cases (compiler enforces exhaustiveness). `if let` handles a single case concisely. Compiler warns/errors on missing variants in `match`.

**R12** — `Vec<T>`: heap-allocated, dynamic size. `[T; N]`: stack-allocated (usually), fixed size. When `Vec` exceeds capacity, it allocates a new buffer (typically 2x), copies elements, drops old buffer, and updates pointer.

**R13** — Enums are algebraic data types; variants can hold data. Unlike C/Java, they don't implicitly convert to integers and support rich data per variant. `Option<T>` = `Some(T)` | `None`. Rust eliminates `null` to prevent null pointer exceptions at compile time.

**R14** — `impl` blocks define methods. `&self`: borrows instance. `&mut self`: mutates instance. `self`: consumes instance. Associated functions (e.g., `String::new()`) don't take `self`, acting like static constructors or utility functions.

**R15** — `#[derive]` auto-implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if trait requires custom logic, contains non-derivable fields (e.g., `Fn` closures, raw pointers, or `PhantomData` with complex bounds).

**R16** — `Cow<'a, T>` (Clone-on-Write) holds either `&'a T` (borrowed) or `Box<T>` (owned). Useful when a function might return borrowed or owned data. Avoids allocation if input already matches; clones only when mutation is requested.

**R17** — `mod` declares a module, `use` imports items into scope, `pub` exposes them. File system: `mod.rs` or `mod_name/mod.rs`. Rust 2018 changed path resolution to `crate::`, `super::`, `self::` and removed `extern crate`, simplifying module imports.

**R18** — `Pin<T>` guarantees a value's memory location won't move. Needed for self-referential structs and async (futures may hold refs to their own fields). `Unpin` is a marker trait indicating pinning is irrelevant (default for most types).

**R19** — Declarative macros (`macro_rules!`) use pattern matching and are hygienic (no variable capture). Procedural macros: `derive` (struct/enum), `attribute` (custom attrs), `function-like`. Hygiene ensures macro-expanded identifiers don't leak or collide with surrounding scope.

**R20** — Zero-cost abstractions provide high-level ergonomics with no runtime overhead vs hand-written code. Iterators compile to tight loops. Generics use monomorphization (type-specific code at compile time). Traits default to static dispatch. Together, they yield C-like performance with safety.
