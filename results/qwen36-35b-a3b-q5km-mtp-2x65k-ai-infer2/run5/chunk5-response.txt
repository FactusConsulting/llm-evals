DN1 — **class vs struct**: `class` is a reference type (heap-allocated, supports inheritance/polymorphism, nullable). `struct` is a value type (stack/inline-allocated, copy-on-assignment, no inheritance). Use `struct` for small, immutable, short-lived data that doesn't need inheritance (e.g., coordinates, IDs, math vectors). Avoid if large or frequently boxed.

DN2 — **IEnumerable<T> vs IQueryable<T>**: `IEnumerable<T>` executes in-memory (LINQ-to-Objects). `IQueryable<T>` builds expression trees translated by a provider (e.g., EF Core) into remote queries (e.g., SQL). Distinction matters because `IQueryable` pushes filtering/pagination to the database, reducing memory/network overhead. `IEnumerable` pulls all data first, then filters client-side.

DN3 — **async/await, Task vs ValueTask**: `async/await` compiles to a state machine that yields control during I/O-bound waits, resuming when completed without blocking threads. `Task` is a reference type with heap allocation overhead. `ValueTask` is a value type that avoids allocation when operations complete synchronously. Use `ValueTask` for high-frequency async methods that often complete synchronously (e.g., caching, in-memory lookups).

DN4 — **DI lifetimes & Scoped-in-Singleton bug**: DI injects dependencies instead of creating them. `Transient`: new instance per injection. `Scoped`: one instance per DI scope (e.g., HTTP request). `Singleton`: one instance per app lifetime. Injecting a `Scoped` service into a `Singleton` captures it for the app's lifetime, causing stale state, memory leaks, and thread-safety violations. DI containers typically throw or warn against this.

DN5 — **string vs ReadOnlySpan<char>, Span<T> usage**: `string` is immutable, heap-allocated, and causes allocations/copies during slicing. `ReadOnlySpan<char>` is a stack-allocated, zero-allocation view over memory. Use `Span<T>`/`ReadOnlySpan<T>` for high-performance string/byte processing, parsing, or slicing where you want to avoid GC pressure and copying contiguous memory.

DN6 — **GC, Generations, LOH, IDisposable**: GC traces live objects and reclaims unreachable memory. `Gen 0`: short-lived, frequent collections. `Gen 1`: buffer. `Gen 2`: long-lived, infrequent. Objects promote when they survive collections. `LOH` (Large Object Heap) holds objects >85KB, collected only during Gen 2, and isn't compacted by default (fragmentation risk). `IDisposable` enables deterministic cleanup of unmanaged resources (handles, native memory); GC only manages managed memory.

DN7 — **ConfigureAwait(false) vs default**: Default captures the current `SynchronizationContext` (or `TaskScheduler`), resuming continuations on the same context (e.g., UI thread). `ConfigureAwait(false)` skips context capture, resuming on any thread pool thread. Use in libraries/shared code to prevent deadlocks and improve performance. Do NOT use in top-level app code that needs to update UI or access request-scoped data. `SynchronizationContext` dictates where continuations run; bypassing it avoids context starvation.

DN8 — **.NET 8/9 features**: Primary constructors inline constructor parameters, auto-generating fields/properties. Collection expressions (`[1, 2, 3]`, `[.. arr]`) simplify creation. `FrozenDictionary` is an immutable, lookup-optimized dictionary using perfect hashing for lower memory/CPU overhead. Example:
```csharp
public class MyService(string connectionString) : IMyService { }
// Registration: builder.Services.AddSingleton<IMyService>(sp => 
//     new MyService(sp.GetRequiredService<IConfiguration>()["Conn"]));
```

DN9 — **ObjectDisposedException on DbContext under high concurrency**: Likely cause: `DbContext` registered as `Transient`/`Singleton` or shared across requests/threads. `DbContext` is not thread-safe and must be scoped per request. Fix: `builder.Services.AddDbContext<MyContext>(options => ..., ServiceLifetime.Scoped)`. EF Core ties `DbContext` lifetime to DI scopes; `Scoped` ensures one instance per HTTP request, isolating change tracking and connections.

DN10 — **record vs class, record struct**: `record` is a reference type with value-based equality, `init`-only properties, and `with` expression for copying. `class` uses reference equality and is mutable. `record struct` applies record semantics to a value type (zero GC pressure, value equality). Choose `record` for DTOs/domain data needing value equality, `record struct` for performance-critical immutable data, `class` for mutable/stateful objects.

DN11 — **ref, out, in**: `ref`: pass by reference, requires initialization, read/write. `out`: pass by reference, must be assigned in method, caller need not initialize. `in`: pass by reference, read-only, avoids copying large structs. Use `ref` for modifying existing values, `out` for multiple returns/parsing, `in` for large structs where you want zero-copy but guarantee immutability.

DN12 — **Nullable reference types vs value types**: NRTs (`string?`) are compile-time annotations distinguishing nullable from non-nullable reference types (`#nullable enable`). `int?` is a runtime feature (`Nullable<T>`) allowing value types to hold null. NRTs provide compile-time warnings for potential `NullReferenceException`; `int?` is a wrapper type with `HasValue`/`Value` and no compile-time null-safety checks.

DN13 — **LINQ, method vs query syntax, deferred execution**: LINQ unifies querying across collections, DBs, XML. Method syntax (`.Where(...)`) is fluent, supports all operators, preferred for complex chains. Query syntax (`from x in ...`) compiles to method syntax, better for simple SQL-like reads. Deferred execution means the query isn't executed until enumerated (e.g., `foreach`, `.ToList()`), enabling composition and lazy evaluation.

DN14 — **Generic constraints**: `where T : class` (reference type), `where T : struct` (value type, non-nullable), `where T : new()` (parameterless constructor), `where T : IComparable<T>` (implements comparison). Combine constraints (e.g., `where T : class, IComparable<T>, new()`) to enable specific operations like sorting, instantiation, or interface calls on generic types.

DN15 — **abstract class vs interface, default interface methods**: Abstract classes can have state, constructors, and partial implementations but support single inheritance. Interfaces define contracts. C# 8+ default interface methods allow interfaces to contain implementations, bridging the gap without breaking implementers. Interfaces still cannot hold instance fields/state.

DN16 — **Middleware pipeline, Use/Map/Run, ordering, exception handling**: Pipeline processes requests sequentially. `app.Use()` adds middleware, can call `await next()` or short-circuit. `app.Map()` branches for specific paths. `app.Run()` is terminal (no `next()`). Ordering matters: auth/rate-limiting early, static files before MVC, exception handling early to catch downstream errors. `UseExceptionHandler` catches unhandled exceptions, logs, and returns error responses.

DN17 — **Channel<T> vs BlockingCollection<T>, backpressure**: `Channel<T>` is modern, async-first, high-performance, supports bounded/unbounded with built-in backpressure. `BlockingCollection<T>` is older, sync/blocking, wraps `ConcurrentQueue`. Bounded channel example:
```csharp
var ch = Channel.CreateBounded<int>(new BoundedChannelOptions(10) { FullMode = BoundedChannelFullMode.Wait });
await ch.Writer.WriteAsync(item); // blocks/pauses when full
await foreach (var item in ch.Reader.ReadAllAsync()) { ... }
```
Backpressure prevents memory exhaustion by pausing producers when the buffer is full.

DN18 — **Source Generators, incremental generators**: Source generators inject C# source at compile-time, enabling type-safe, zero-runtime-overhead code generation. Faster than reflection (runtime inspection) and safer than IL weaving (post-compile assembly modification). Incremental generators (`IncrementalGenerator`) use a caching pipeline that only runs when inputs change, dramatically reducing compilation overhead vs legacy `ISourceGenerator`.

DN19 — **TPL Dataflow, blocks vs Channels**: `ActionBlock` processes items (side effects), `TransformBlock` maps input→output, `BufferBlock` stores items manually. Dataflow offers rich composition (fan-out/in, completion propagation, backpressure tuning). `System.Threading.Channels` is simpler, async-first, better for straightforward producer-consumer pipelines. Use Dataflow for complex, multi-stage workflows; Channels for lightweight async queues.

DN20 — **Minimal APIs vs Controllers, trade-offs, route groups, filters**: Minimal APIs are lightweight, inline handlers with less boilerplate and faster startup. Controllers offer attribute routing, model binding, filters, and richer ecosystem. Trade-offs: Minimal APIs are harder to test inline, have limited middleware integration, and rely on Swashbuckle/NSwag for OpenAPI (improving). Route groups (`app.MapGroup("/api")`) prefix/tag endpoints. Endpoint filters (`AddFilter`) handle cross-cutting concerns (auth, validation) without full middleware.

P1 — **list vs tuple, set vs frozenset**: `list` is mutable, ordered, indexed, allows duplicates. `tuple` is immutable, ordered, fixed-size, heterogeneous, supports unpacking. `set` is mutable, unordered, unique elements, supports math ops. `frozenset` is immutable, hashable, usable as dict keys or set elements.

P2 — **GIL**: Global Interpreter Lock is a mutex allowing only one thread to execute Python bytecode at a time in CPython. It blocks true parallel CPU execution in multithreaded workloads. Workarounds: `multiprocessing`, C extensions releasing GIL, `asyncio` for I/O-bound tasks, or alternative runtimes (GraalPy, PyPy STM).

P3 — **deepcopy vs copy**: `copy.copy()` creates a shallow copy (new container, shared nested objects). `copy.deepcopy()` recursively copies all nested objects. Shallow copy bug:
```python
a = [[1, 2], [3, 4]]
b = copy.copy(a)
b[0].append(99)  # a becomes [[1, 2, 99], [3, 4]] because inner lists are shared
```

P4 — **Decorators, execution time**: Decorators wrap functions to extend behavior. Example:
```python
import time, functools
def log_time(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.4f}s")
        return result
    return wrapper
```

P5 — **Generators, yield, yield from**: Generators use `yield` to produce iterators lazily, preserving state between yields. Unlike lists, they use constant memory and can represent infinite sequences. `yield from` delegates to another generator/iterable, simplifying nesting and properly forwarding exceptions/return values.

P6 — **asyncio event loop, run/gather/create_task, time.sleep**: Event loop schedules async tasks and I/O events. `asyncio.run()` creates loop, runs coroutine, closes loop. `asyncio.gather()` runs multiple coroutines concurrently and returns results in order. `asyncio.create_task()` schedules a coroutine for concurrent execution, returning immediately. `time.sleep()` blocks the entire event loop thread; use `asyncio.sleep()` instead.

P7 — **MRO, C3 linearization, diamond inheritance**: Python 3 uses C3 linearization to compute MRO, ensuring monotonicity and consistent left-to-right depth-first resolution. For `D(B, C)` where `B,C` inherit `A`, MRO is `[D, B, C, A, object]`. `D().who()` searches `D`→`B` (no `who`)→`C` (has `who`), returning `"C"`. C3 resolves diamond inheritance without ambiguity.

P8 — **Metaclass vs __init_subclass__**: Metaclass controls class creation (`__new__`/`__init__`), powerful but complex. `__init_subclass__` is a class method called when a subclass is created, simpler and instance-aware. Metaclass use case: ORM model registration, enforcing class-level contracts. `__init_subclass__` use case: auto-registering subclasses in a registry or setting default attributes without metaclass overhead.

P9 — **multiprocessing vs threading vs concurrent.futures, pickling**: Threading: I/O-bound, shares memory, GIL-limited CPU parallelism. Multiprocessing: CPU-bound, separate processes, bypasses GIL, higher overhead. `concurrent.futures`: high-level API unifying both via `ThreadPoolExecutor`/`ProcessPoolExecutor`. Multiprocessing serializes args/results via `pickle`; fails for lambdas, open handles, or unserializable objects. macOS uses `spawn` (requires pickling), Linux uses `fork` (copies memory).

P10 — **__slots__**: Declares a fixed set of attributes, preventing `__dict__` creation. Use when memory is critical or creating millions of instances. Prevents dynamic attribute addition and `__weakref__` (unless explicitly listed). Memory impact: significant reduction (no dict overhead per instance), faster attribute access.

P11 — **Virtual environments, venv vs virtualenv vs conda**: Isolated Python environments with independent packages/interpreters. Prevents dependency conflicts and ensures reproducibility. `venv`: standard library, lightweight. `virtualenv`: third-party, more features, backward compatible. `conda`: package + environment manager, handles non-Python binaries, data-science focused.

P12 — **Comprehensions vs map/filter**: Comprehensions (`[x for x in lst if cond]`) are Pythonic, readable, and often faster. `map()`/`filter()` return lazy iterators, functional style. Prefer comprehensions for readability/simple logic. Use `map`/`filter` when chaining lazy operations or applying C-implemented functions for marginal performance gains.

P13 — **== vs is, object interning**: `==` checks value equality (`__eq__`). `is` checks object identity (same memory address). CPython interns small integers (-5 to 256) and some strings for performance. `a is b` returns `True` for small ints because they reference the same cached object. Not guaranteed for larger ints or strings.

P14 — **\*args, \*\*kwargs, /, \***: `*args` collects extra positional args into a tuple. `**kwargs` collects extra keyword args into a dict. `/` marks parameters as positional-only. `*` marks parameters as keyword-only. Used for flexible APIs, argument forwarding, and enforcing calling conventions.

P15 — **Context managers**: Ensure deterministic cleanup (`try/finally` equivalent). Implement via `__enter__`/`__exit__` (class-based) or `@contextmanager` (generator-based). Example (DB session):
```python
@contextmanager
def db_session():
    conn = get_conn()
    try: yield conn
    finally: conn.close()
```

P16 — **Type hinting, Union, Optional, Literal, TypeVar, Protocol, mypy/pyright**: Static annotations for tooling, not runtime-enforced. `Union[X, Y]`: either type. `Optional[X]`: `Union[X, None]`. `Literal["a"]`: exact value. `TypeVar`: generic placeholder with constraints. `Protocol`: structural subtyping (duck typing). `mypy`/`pyright` analyze code against hints, catching type errors pre-runtime.

P17 — **Data model (dunder methods)**: `__repr__`: unambiguous, dev-focused. `__str__`: readable, user-focused. `__eq__`: value equality. `__hash__`: hashability (immutable objects). `__getattr__`: fallback when attribute missing. `__getattribute__`: called for every access (dangerous). Defining `__eq__` without `__hash__` sets `__hash__ = None`, making instances unhashable (can't be dict keys/set members).

P18 — **Descriptors**: Objects implementing `__get__`, `__set__`, `__delete__` that control attribute access on owner classes. `property`, `classmethod`, and `staticmethod` are descriptors that modify `__get__` behavior. Under the hood, they're stored in the class dict and invoked via the descriptor protocol during attribute lookup, enabling computed attributes and method binding.

P19 — **Import system**: Relative imports (`from .mod import x`) resolve relative to the package. Absolute imports (`from pkg.mod import x`) resolve from `sys.path`. `PYTHONPATH` prepends to `sys.path`. `__init__.py` marks packages (optional in 3.3+ for namespace packages). Namespace packages split across directories without `__init__.py`. `Finder` locates modules in `sys.path`; `Loader` compiles/imports them. Standardized via `importlib`.

P20 — **dataclasses vs attrs/Pydantic**: `dataclasses` (built-in) auto-generates `__init__`, `__repr__`, `__eq__`. `attrs` (third-party) offers more flexibility/validation. `Pydantic` adds runtime validation, serialization, type coercion, and ORM integration. `__post_init__` runs after init for custom logic. `field(default_factory=list)` avoids mutable default bugs. `frozen=True` makes instances immutable. Choose `Pydantic` for API models, validation, and serialization; `dataclasses` for simple, fast data containers.
