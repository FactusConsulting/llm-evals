## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted with initialization to `undefined`. `let`/`const` are block-scoped, hoisted but in a Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment of the binding (not the value). Hoisting moves declarations to the top of their scope during compilation, but initializations stay in place.

**JS2** — The event loop continuously checks the call stack. When empty, it flushes the microtask queue (promises, `queueMicrotask`), then renders, then executes one macrotask (setTimeout, I/O, UI). Microtasks run before the next macrotask, ensuring promise resolution isn't delayed by timers.

**JS3** — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: counter factory. Classic bug: `for (var i=0; i<3; i++) setTimeout(() => console.log(i), 0)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped), IIFE, or `setTimeout(fn, 0, i)` to capture by value.

**JS4** — `Promise` represents async completion. `async/await` is syntactic sugar that pauses execution until resolution. Error handling: `try/catch` with `await`, `.catch()` or second `async` param with promises. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all, returning `{status, value/reason}` per promise.

**JS5** — `interface` defines object shapes, supports declaration merging/extension, erased at runtime. `type` is an alias supporting primitives, unions, intersections, tuples. Use `interface` for APIs/objects, `type` for unions/primitives. Discriminated unions: types sharing a common literal property used to narrow types via `switch`/`if`.

**JS6** — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar: `extends` uses `Object.setPrototypeOf` on the constructor and `Object.create` on the prototype chain.

**JS7** — `this` is determined by call site. Priority: 1. `new` (new instance), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (`window` or `undefined` in strict mode). `bind()` returns a new function with `this` permanently bound. It cannot be re-bound.

**JS8** — `WeakRef` holds a weak reference that doesn't prevent GC. `FinalizationRegistry` runs callbacks when weakly referenced objects are collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the engine can track their lifecycle; when a key is GC'd, the entry is automatically removed.

**JS9** — V8 uses hidden classes (shapes) to optimize property access. Inline caching (IC) caches shape lookups at call sites. Deoptimization occurs when assumptions break: dynamic property addition, type polymorphism, `delete`, `with`, or `arguments` usage. Code patterns causing deopt: changing object shapes mid-execution, mixing types in arrays, or using `delete`.

**JS10** — Tree-shaking removes unused exports at build time. Works natively with ES modules due to static `import`/`export` syntax. CommonJS uses dynamic `require()`, evaluated at runtime, preventing static analysis. CJS also often executes side effects at top-level scope, breaking tree-shaking assumptions.

**JS11** — `null` is intentional absence; `undefined` is uninitialized/missing param. `==` coerces types (`null == undefined` is `true`); `===` checks type/value (`false`). `??` returns right operand if left is `null`/`undefined`. `?.` safely accesses nested properties, returning `undefined` instead of throwing.

**JS12** — `map()` transforms, `filter()` keeps matching elements, `reduce()` accumulates to a single value. Initial value in `reduce()` prevents errors on empty arrays and sets accumulator type. `flatMap()` maps then flattens one level; useful for transforming and flattening in a single pass.

**JS13** — Template literals use backticks, support `${}` interpolation and multi-line strings. Tagged templates call a function with an array of string parts and substitution values. Example: `html` function that escapes `${}` values to prevent XSS in dynamic HTML generation.

**JS14** — Destructuring unpacks values. Object: `{a, b: renamed} = obj`. Array: `[a, b] = arr`. Defaults: `a = 1`. Rest operator: `const {a, ...rest} = obj` collects remaining properties into a new object. Works symmetrically for arrays.

**JS15** — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, maps). Avoid `for...in` on arrays: iterates keys not values, includes inherited properties, and doesn't guarantee order.

**JS16** — Generics use type parameters for reusable code. Constraints: `T extends SomeType`. Conditional types: `T extends U ? X : Y`. `infer` extracts types in conditional context. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T`.

**JS17** — CJS: synchronous, `require()`/`module.exports`, dynamic resolution. ESM: standard, static `import`/`export`, async. Node.js supports both via `.mjs` or `"type": "module"` in `package.json`. ESM enables tree-shaking, top-level await, and strict module scope.

**JS18** — Structural typing: compatibility based on shape, not name. Excess property checks apply only to object literals assigned to variables/types, not indexed access. `extends` checks assignment compatibility. `satisfies` checks shape without widening the inferred type. TS 4.7+ enforces strict contravariance for function parameters (`in`), covariance for returns (`out`).

**JS19** — `Proxy` wraps objects to intercept operations (get, set, apply, etc.). `Reflect` mirrors Proxy traps and provides default behavior. Example: validation proxy that checks types on assignment. Practical uses: reactive frameworks (Vue 3), immutable data, logging, and access control.

**JS20** — `SharedArrayBuffer` shares memory between main thread and workers. `Atomics` provides atomic read/write/compare-exchange. Communication: read/write SAB, use `Atomics.wait` (blocks until value changes/timeout) and `Atomics.notify` (wakes threads). Guarantees sequential consistency for atomic ops. Requires Cross-Origin Isolation headers.

## Bash

**B1** — `$@` preserves each argument as a separate word when quoted `"$@"`. `$*` joins all args into one string using the first char of IFS. `"$@"` is safe for iteration; `"$*"` breaks on spaces and merges arguments.

**B2** — `set -e`: exit on command failure. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the rightmost non-zero exit code. Together, they enforce strict error handling.

**B3** — `$(command)` is preferred over `` `command` ``: nestable, clearer, POSIX-compliant. `$((expression))` is shell arithmetic expansion. `expr` is an external command, slower, and prone to quoting/escaping issues.

**B4** — Process substitution `<(command)` creates a `/dev/fd/X` file descriptor with the command's output. Used when a command expects a file argument but needs dynamic input. Example: `diff <(sort file1) <(sort file2)`.

**B5** — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous: breaks on spaces/globs, executes output as commands if unquoted, and loses newlines.

**B6** — Here document `<<EOF` feeds multi-line input until `EOF`. Here string `<<<` feeds a single line. `<<-EOF` strips leading tabs (not spaces) for indentation, keeping scripts readable.

**B7** — `cmd > file 2>&1`: stdout → file, then stderr → stdout's target (file). `cmd 2>&1 > file`: stderr → terminal (stdout's original target), then stdout → file. `cmd &> file` is bash shorthand for the first. They differ because redirections evaluate left-to-right.

**B8** — ```bash
lock_dir="my.lock"
cleanup() { rmdir "$lock_dir" 2>/dev/null; }
trap cleanup EXIT ERR INT TERM
mkdir "$lock_dir" 2>/dev/null || { echo "Locked"; exit 1; }
# ... work ...
```
`mkdir` is atomic on POSIX, preventing race conditions. `trap` ensures cleanup on normal exit, errors, or signals.

**B9** — Single quotes `'...'`: literal, no expansion. Double quotes `"..."`: variable/command/glob expansion. No quotes: word splitting and globbing. Example: `var="hello world"; echo $var` → `hello world` (split), `echo "$var"` → `hello world`, `echo '$var'` → `$var`.

**B10** — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin: supports `&&`, `||`, `=~`, no word splitting/globbing on RHS. `[ ]` is POSIX `test`: requires spaces, safer for cross-shell compatibility.

**B11** — `$?`: last exit code (error checking). `$$`: current PID (logging/temp files). `$!`: last background PID (`wait`). `$#`: argument count (validation).

**B12** — `foo() { ... }` (POSIX) or `function foo { ... }` (bash). Return values: `return <int>` (exit code), `echo` for stdout, global variables, or `declare -n` namerefs.

**B13** — `PATH` is colon-separated dirs bash searches. Resolves builtins first, then external binaries in `PATH`. Builtins are shell-compiled (fast); external are separate binaries. `type cmd` or `command -v cmd` shows which is used.

**B14** — `trap 'cleanup' EXIT ERR INT TERM`. Signals interrupt execution; traps run sequentially. `ERR` fires on non-zero exit. Multiple signals queue and process in order. Use `trap - INT` to ignore or re-raise.

**B15** — `xargs` builds commands from stdin, handles batching. `find -print0 | xargs -0` safely handles spaces/newlines. `-P N` runs N processes in parallel. Cmd substitution `$(...)` loads entire output into memory; `xargs` streams.

**B16** — Arrays: `arr=(a b c)`, `${arr[0]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[@]}`. Associative requires `declare`, supports string keys, and uses different syntax for iteration.

**B17** — Subshell `(...)`: child process, variable changes lost. Group `{ ...; }`: current shell, variables persist. Piping `cmd | while read` runs `while` in subshell; changes lost. Fix: process substitution `< <(cmd)` or `shopt -s lastpipe`.

**B18** — SIGINT (Ctrl+C, interrupt), SIGTERM (graceful kill), SIGHUP (terminal close), SIGKILL (uncatchable). Graceful shutdown: trap TERM/INT, kill background jobs (`kill $(jobs -p)`), `wait`, then cleanup. Job control: `jobs`, `fg`, `bg`, `wait`.

**B19** — ```bash
split -l 10000 log.txt log.part.
find . -name "log.part.*" -print0 | xargs -0 -P 4 -I {} bash process.sh {}
cat log.part.* > merged.log
```
Trade-offs: CPU vs I/O bound, splitting/merging overhead. Error propagation: check `$?` per job, use `set -o pipefail`, aggregate non-zero exits, and fail fast or log failures.

**B20** — `exec` replaces the shell process or manipulates file descriptors. `exec 3>file` opens FD 3; `exec 3>&-` closes it. Coprocess: `coproc cmd` creates bidirectional FDs. Use for persistent IPC without spawning new processes, reducing overhead.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console, bypassing the pipeline. Matters because `Write-Host` breaks chaining, isn't suitable for automation, and mixes output with data streams.

**PS2** — Pipeline streams objects. `ForEach-Object` is a cmdlet, processes each object, supports `-Parallel`. `foreach` is a language construct, requires the entire collection in memory, faster. Use `ForEach-Object` for streaming/large data, `foreach` for known collections.

**PS3** — `[PSCustomObject]`: ordered, strongly typed, supports methods. Hashtable: unordered, dynamic key-value pairs. Convert: `[PSCustomObject]@{a=1}` or `New-Object PSObject -Property @{}`. Use PSCustomObject for structured data, hashtables for dynamic/config.

**PS4** — Terminating errors stop execution and are caught by `try/catch`. Non-terminating errors continue and log to `$Error`. `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors; use `-ErrorAction Stop` to convert non-terminating.

**PS5** — Splatting: `@params` hashtable passed to a cmdlet. `@{Path='.'; Recurse=$true} | Get-ChildItem`. Differs from single param: passes multiple named params cleanly. Single hashtable param expects one argument matching a parameter name.

**PS6** — `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` creates an interactive session. Uses WS-Management (WinRM) by default. PowerShell 7+ supports SSH remoting via OpenSSH.

**PS7** — `$result += "one"` creates an array. If 1 item, returns `String`; if 0, returns `$null`. `$x.GetType().Name` will be `String` or `Object[]`. Correct pattern: `[array]$result = @(); return $result` or consistently use `Write-Output`. Always cast return to `[array]` if count varies.

**PS8** — `[scriptblock]` is anonymous code; function is named. Pass to remote via `-ArgumentList` (serializes) or `-ScriptBlock` param. Double-hop: auth fails when remoting to a second server. Solve with CredSSP (insecure), Kerberos delegation, or pass data via `-ArgumentList`/`Invoke-Command`.

**PS9** — `@()` is array subexpression (forces collection). `[array]` is type constraint. Force single result: `@($single)`. Indexing `$null` throws; indexing empty array returns `$null`.

**PS10** — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive: `-ceq`, `-clike`, `-cmatch`, `-ccontains`, `-cin`. `-contains` checks if collection contains value; `-in` checks if value is in collection.

**PS11** — Module: collection of commands. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies). Binary: compiled DLL. `Import-Module` loads, searches `$env:PSModulePath`, runs `.psd1`/`.psm1`, exports commands.

**PS12** — `"..."` expands variables/expressions. `'...'` literal. Expressions: `"Value: $(Get-Date)"`. Here-string: `@"..."@` for multi-line, preserves formatting and indentation.

**PS13** — `Get-Member` explores object members. Properties (data), Methods (actions), NoteProperties (custom). `Select-Object` picks properties/creates new objects. `Where-Object` filters objects based on a scriptblock.

**PS14** — Classes (v5+): define types, support properties/methods/constructors. Limitations: no multiple inheritance, limited interface support, no generics, simpler than C#. Use classes for complex data/models, functions for simple tasks.

**PS15** — `CmdletBinding`: enables advanced features. `SupportsShouldProcess`: `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: parameter groups. `ValueFromPipeline`: accepts pipeline input. `Begin`/`Process`/`End`: pipeline processing lifecycle.

**PS16** — Providers: abstract data stores. `Get-ChildItem` works on FileSystem, Registry, Cert, Env. Registry accessed via `HKLM:\` or `Registry::`. Treated like file system for navigation and filtering.

**PS17** — Runspaces: execution environments. `[runspace]`: single thread. `[runspacepool]`: thread pool. `[powershell]`: cmdlet runner. `ForEach-Object -Parallel` (v7+): easy parallelism. Manual runspace: complex, full control, thread-safe via synchronization primitives.

**PS18** — PSScriptAnalyzer: linting tool. Rules: syntax, performance, best practices. Severity: error, warning, info. Suppress: `#pragma disable`, `.psake.ps1`, or config file. CI/CD: run in pipeline, fail on errors, enforce standards.

**PS19** — `$using:` scope serializes variables for remote/parallel jobs. `-ArgumentList` also serializes. Limits: CLIXML depth (~64), complex objects may fail. Use simple types or serialize to JSON/CSV for large/complex data.

**PS20** — DSC: configuration management. Configurations: declarative code. Resources: building blocks (File, Package, Service). LCM: applies config, checks drift. WinPS vs PS7: PS7 uses OpenDSC, cross-platform. Replaced by: Ansible, Terraform, Chef, Puppet, or native cloud IaC.
