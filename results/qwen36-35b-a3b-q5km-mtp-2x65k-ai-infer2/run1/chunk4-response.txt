**G1** — A slice is a runtime descriptor containing a pointer to a backing array, length, and capacity. An array is a fixed-size value type where the size is part of the type. When appending to a slice that exceeds its capacity, Go allocates a new backing array (typically doubling capacity), copies existing elements, updates the slice header, and returns the new slice.

**G2** — `var x int` declares a variable with explicit type and zero value. `x := 0` is a short variable declaration that infers type and requires at least one new variable on the left side. You cannot use `:=` outside functions, when all variables on the LHS are already declared, or alongside `var`.

**G3** — A goroutine is a lightweight, user-space thread managed by the Go runtime. Unlike OS threads (1:1 kernel mapping), goroutines use M:N scheduling. The GMP model: `G` (goroutine state), `M` (OS thread executing code), `P` (processor context holding run queue). The scheduler multiplexes Gs onto Ms, enabling efficient concurrency with minimal overhead.

**G4** — Channels are typed conduits for communication and synchronization. Unbuffered channels block both sender and receiver until both are ready. Buffered channels have a capacity; sends block only when full, receives block only when empty. Sending to a full buffered channel blocks until a receiver consumes an element.

**G5** — The `context` package propagates deadlines, cancellation signals, and request-scoped values across API boundaries. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
resp, err := http.GetContext(ctx, "https://example.com")
```
If the request exceeds 5s, `ctx` is cancelled and the HTTP client aborts.

**G6** — Go uses implicit interface satisfaction (duck typing): a type implements an interface if it has the required methods, with no `implements` keyword. Unlike Java/C#, no declaration is needed. `interface{}` (Go 1.18+ `any`) matches any type. It enables generic-like flexibility but is dangerous because type assertions can panic at runtime and bypass compile-time safety.

Correct alternatives: use `atomic.Bool` for `ready` and `atomic.String` for `data`, or signal readiness via a channel: `ch := make(chan struct{}); go func(){ data="hello"; close(ch) }(); <-ch; fmt.Println(data)`.

**G8** — `sync.Mutex` provides exclusive access; `sync.RWMutex` allows multiple concurrent readers or one writer. `sync.Map` is optimized for read-heavy workloads with disjoint key sets or keys known at compile time. Trade-offs: `sync.Map` has higher read overhead and worse write performance; a regular `map` + `sync.RWMutex` is generally faster for mixed workloads.

**G9** — `go.mod` declares the module path, Go version, and direct dependencies. `go.sum` stores cryptographic hashes of dependency versions for integrity verification. `go mod tidy` removes unused dependencies, adds missing ones, and updates versions. MVS (Minimum Version Selection) resolves the dependency graph to the lowest compatible versions that satisfy all requirements, preventing version skew.

**G10** — `defer` schedules a function call to run after the surrounding function returns. Multiple defers execute in LIFO order. Common loop gotcha: variables captured by deferred closures are evaluated at defer execution time, not declaration time. Fix by passing values as arguments: `defer func(v int) { fmt.Println(v) }(i)` or create a new scope.

**G11** — A pointer holds a memory address. Its zero value is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: value}`. The compiler automatically takes the address of the literal.

**G12** — `init()` runs automatically before `main()` executes. It runs once per package. A package can have multiple `init()` functions; they execute in declaration order. They are typically used for setup, but complex logic should be avoided to maintain predictability.

**G13** — `new(T)` allocates zeroed memory for type `T` and returns a `*T`. `make(T, args)` initializes and returns a ready-to-use `T` (only for slices, maps, channels). `new` returns a pointer; `make` returns the value itself.

**G14** — Go uses `error` interface (`Error() string`) for error handling. Idiomatic pattern: `if err != nil { return err }`. `errors.Is(err, target)` checks if `err` wraps `target`. `errors.As(err, &target)` extracts the concrete type from the error chain. `==` only matches exact types, failing with wrapped errors.

**G15** — Zero values: `map` → `nil` (use `make`), `slice` → `nil` (len=0, cap=0), `channel` → `nil` (blocks forever), `struct` → zero values of each field. All are safe to use except `nil` maps/channels which panic or block.

**G16** — A race condition occurs when concurrent goroutines access shared data without synchronization, leading to undefined behavior. `-race` flag instruments the binary to detect conflicting reads/writes at runtime. Example fix with mutex:
```go
var mu sync.Mutex; var counter int
go func() { mu.Lock(); counter++; mu.Unlock() }()
```
Or via channel: `ch := make(chan int, 1); ch <- counter`.

**G17** — `select` waits on multiple channel operations, similar to `switch` but for channels. If multiple cases are ready, one is chosen pseudo-randomly. Timeout implementation: `case <-time.After(d): // timeout`.

**G18** — Escape analysis determines whether variables allocate on the stack or heap. Variables escape if: address is taken, returned, stored in a heap-allocated struct, or size is unknown at compile time. Inspect with `go build -gcflags="-m"`. Heap allocations trigger GC, impacting latency and throughput; stack allocations are faster and GC-free.

**G19** — `reflect.Type` provides type metadata; `reflect.Value` provides runtime value access. Costs: significantly slower than direct calls, bypasses compile-time checks, and allocates. Justified for serialization, ORMs, or generic utilities. Prefer code generation (`go generate`, `stringer`) for performance-critical paths to avoid reflection overhead.

**G20** — `//go:embed` embeds files/directories into the binary at compile time. Syntax: `var f embed.FS` with `//go:embed path/...`. Works with `io/fs.FS` for standard file operations. Limitations: paths must be relative, no symlinks, embeds at compile time (not runtime), and large files increase binary size.

**R1** — Ownership ensures memory safety without a GC. Three rules: 1. Each value has exactly one owner. 2. Only one owner at a time. 3. When the owner goes out of scope, the value is dropped. This prevents leaks and dangling references.

**R2** — `String` is a heap-allocated, growable, owned string. `&str` is a borrowed reference to UTF-8 bytes. Use `String` when you need ownership or mutation. Use `&str` in function signatures to avoid allocations; Rust automatically coerces `&String` to `&str` via deref.

**R3** — Borrowing allows temporary access without transferring ownership. Rules: 1. Either one `&mut T` or any number of `&T` references. 2. All references must be valid (no dangling). The borrow checker enforces these at compile time to prevent data races and use-after-free.

**R4** — `Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents `Some(T)` or `None`. The `?` operator propagates errors/returns early. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

**R5** — `Box<T>`: heap-allocates, single owner, moves data. `Rc<T>`: reference-counted, single-threaded shared ownership. `Arc<T>`: atomic reference-counted, thread-safe shared ownership. Use `Box` for large/recursive types, `Rc` for shared read-only data, `Arc` for concurrent shared data.

**R6** — Traits define shared behavior with optional method implementations. Like Go interfaces but explicit. `dyn Trait`: trait object, dynamic dispatch via vtable, heap-allocated, enables heterogeneous collections. `T: Trait`: generic with static dispatch (monomorphization), zero-cost, type-specific code generation.

**R7** — Fails because lifetime elision rules don't apply when multiple input references exist and one is returned; the compiler can't determine which input outlives the output. Fix by explicitly tying lifetimes:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** — `Send`: type can be transferred across threads. `Sync`: type's shared reference (`&T`) is safe across threads. `Rc<T>` isn't `Send`/`Sync` due to non-atomic reference counting. `Arc<T>` uses atomic ref counts, making it `Send`+`Sync` (if `T` is), enabling safe concurrent sharing.

**R9** — `async/await` compiles to a state machine implementing `Future`. `Future::poll` advances execution. An executor (e.g., Tokio) drives futures, handles I/O, and schedules tasks. Differs from Go: Go uses a built-in M:N runtime with preemptive/cooperative scheduling; Rust uses explicit, user-chosen executors, lazy futures, and no built-in runtime.

**R10** — `unsafe` bypasses compiler safety checks. Three operations: 1. Dereference raw pointers. 2. Call `unsafe` functions. 3. Implement `unsafe` traits. Justified for FFI, low-level sys ops, performance-critical code, or building safe abstractions over unsafe foundations.

**R11** — Pattern matching exhaustively checks enum variants. `match` binds values and requires exhaustiveness (compiler enforces coverage or `_` wildcard). `if let` is concise for single-case matching. The compiler guarantees no unhandled variants in `match`, preventing runtime errors.

**R12** — `Vec<T>` is heap-allocated with dynamic size. `[T; N]` is stack-allocated (usually) with fixed compile-time size. When `Vec` capacity is exceeded, it allocates a larger buffer (typically doubles), moves/copy elements, and drops the old buffer.

**R13** — Rust enums are algebraic data types: each variant can hold data. Unlike C (integer-backed) or Java (class-based). `Option<T>` replaces `null` with `Some(T)` or `None`, forcing explicit handling and eliminating null pointer exceptions.

**R14** — `impl` blocks define methods. `&self`: immutable borrow (can't modify). `&mut self`: mutable borrow (can modify). `self`: takes ownership (consumes). Associated functions (e.g., `String::new()`) don't take `self` and act like static methods, often used as constructors.

**R15** — `#[derive]` auto-implements common traits. Examples: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if: fields lack the trait (e.g., `Fn`), custom logic is required, or the trait demands specific behavior (e.g., `Drop`).

**R16** — `Cow<'a, T>` (Clone on Write) borrows or owns data. Useful when a function might return borrowed or owned data. Example:
```rust
fn process(s: &str) -> Cow<str> {
    if s.contains("x") { Cow::Owned(s.to_uppercase()) } else { Cow::Borrowed(s) }
}
```
Avoids allocation when no transformation occurs.

**R17** — `mod` declares a module, `use` imports names, `pub` exposes them. File system maps: `mod.rs` or `mod_name/mod.rs`. Rust 2018 removed `extern crate`, improved path resolution (`use crate::foo`), and allowed `mod` declarations in parent directories, simplifying module organization.

**R18** — `Pin<T>` guarantees a value won't be moved in memory. Required for self-referential structs and async/await (futures may hold refs to their own fields). `Unpin` is auto-implemented; pinning has no effect. Types that must not move implement `!Unpin` and require `Pin`.

**R19** — Declarative macros (`macro_rules!`) use pattern matching on token trees and are hygienic (no variable capture). Procedural macros (`derive`, `attribute`, `function-like`) operate on parsed ASTs. Hygiene ensures macro-generated identifiers don't collide with caller scope, preventing subtle bugs.

**R20** — Zero-cost abstractions compile to efficient machine code. Iterators use loop unrolling and eliminate bounds checks. Generics use monomorphization (type-specific code generation). Traits use static dispatch. Together, they provide high-level ergonomics and safety while matching hand-written C performance.
