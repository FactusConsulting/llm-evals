**G1** — Arrays have fixed size and are value types (copied on assignment). Slices are dynamic views over underlying arrays, containing a pointer, length, and capacity. Appending to a full slice triggers reallocation: the runtime allocates a new backing array (typically doubling capacity), copies existing elements, and returns a new slice pointing to it.

**G2** — `var x int` declares a variable with explicit type and zero value. `x := 0` is a short variable declaration that infers type and requires at least one new variable on the left. You cannot use `:=` outside functions, when redeclaring all variables on the left, or when explicit type annotation is required (e.g., `var x int = 0` vs `x := 0` where type inference might not match intent).

**G3** — Goroutines are lightweight, user-space threads managed by the Go runtime (~2KB initial stack, grows/shrinks). OS threads are kernel-managed, heavier, and 1:1. The GMP model: `G` (goroutine), `M` (OS thread/machine), `P` (processor/context). The scheduler multiplexes Gs onto Ms using Ps to maintain work-stealing, preemption, and cache locality.

**G4** — Channels are typed conduits for communication and synchronization. Unbuffered channels block both sender and receiver until both are ready. Buffered channels have a capacity; send blocks only when full, recv blocks only when empty. Sending to a full buffered channel blocks until a receiver consumes an element or the channel is closed.

**G5** — `context` propagates deadlines, cancellation signals, and request-scoped values across API boundaries. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
resp, err := client.Do(req) // cancels if timeout hits
```

**G6** — Go uses implicit interface satisfaction (duck typing). Unlike Java/C#, you don't declare `implements`; any type satisfying the method set automatically implements the interface. `interface{}`/`any` matches any type. Powerful for generics/JSON, but dangerous because type assertions can panic at runtime and bypass compile-time safety.

**G7** — Go's memory model guarantees happens-before ordering only via synchronization primitives. The code races: `ready` and `data` are accessed concurrently without sync, allowing compiler/CPU reordering and cache visibility issues. Fix with channels, `sync/atomic` (e.g., `atomic.Bool`), or `sync.Once`/`WaitGroup`.

**G8** — `sync.Mutex` provides exclusive access. `sync.RWMutex` allows concurrent readers or a single writer. `sync.Map` is optimized for high-read, low-write workloads or keys unknown at compile time. Trade-off: `sync.Map` has higher per-operation overhead and memory usage vs `map+Mutex` when access patterns are predictable and keys are known.

**G9** — Modules manage dependencies. `go.mod` declares module path, Go version, and direct dependencies. `go.sum` stores cryptographic hashes for integrity verification. `go mod tidy` removes unused deps, adds missing ones, and updates `go.sum`. MVS (Minimum Version Selection) picks the lowest compatible version for each dependency across the entire graph, preventing version skew.

**G10** — `defer` schedules a function call to run after the surrounding function returns. Executes in LIFO order. Gotcha in loops: variables captured by deferred closures are evaluated at defer execution time, not declaration time. Fix by passing values as arguments: `defer func(v int) { fmt.Println(v) }(i)`.

**G11** — A pointer holds a memory address. Zero value is `nil`. Create pointer to struct literal: `p := &MyStruct{Field: val}`. Pointers are reference types; dereference with `*p`.

**G12** — `init()` runs automatically before `main()`, once per package. Multiple `init()` functions in a file execute top-to-bottom. Across packages, dependencies initialize first. Order is deterministic but not guaranteed between unrelated packages.

**G13** — `make(T, args)` initializes slice, map, or channel (returns initialized `T`, not `*T`). `new(T)` allocates zeroed memory and returns `*T`. Use `make` for reference types, `new` for any type when you need a pointer to zero value.

**G14** — Errors implement `error` interface (`Error() string`). Idiomatic: `if err != nil { handle }`. `errors.Is(err, target)` checks if `err` wraps `target`. `errors.As(err, &target)` extracts typed error from chain. `==` only checks direct equality, ignoring wrapped errors.

**G15** — Map: `nil` (read-only, write panics). Slice: `nil` (len=0, cap=0). Channel: `nil` (blocks forever). Struct: zero values of each field. All are safe to use in read-only contexts.

**G16** — Race condition: concurrent unsynchronized access to shared mutable data. `-race` flag instruments runtime to detect conflicting accesses. Example: `var c int; go func(){c++}(); c++`. Fix: `sync.Mutex` around accesses, or channel-based communication.

**G17** — `select` waits on multiple channel operations. Like `switch` but for channels. If multiple cases ready, picks one pseudo-randomly. Timeout: `case <-time.After(d):`. Blocks until at least one case is ready.

**G18** — Escape analysis determines stack vs heap allocation. Escapes if: address taken, size unknown at compile time, escapes function scope, or returned. Inspect with `go build -gcflags="-m"`. Matters because heap allocations trigger GC, impacting latency and throughput.

**G19** — `reflect.Type` holds type metadata; `reflect.Value` holds actual data. Costs: slow, bypasses compile-time checks, allocates. Justified in frameworks/serialization when code generation isn't feasible. Prefer code generation for performance-critical paths.

**G20** — `go:embed` compiles files/dirs into binary. `//go:embed pattern` supports files, `*` for directories (recursive). Limitations: only compile-time known paths, no runtime generation. Returns `embed.FS` implementing `io/fs.FS`, enabling standard filesystem APIs like `os.ReadDir` or `http.FS`.

**R1** — Ownership: 1. Each value has exactly one owner. 2. Only one owner at a time. 3. Owner drops value when out of scope. Prevents double-free, use-after-free, and data races at compile time.

**R2** — `String`: owned, heap-allocated, growable UTF-8 string. `&str`: borrowed string slice (reference to UTF-8 bytes). Use `String` for ownership/modification, `&str` for borrowing/reading (zero-copy, preferred in signatures).

**R3** — Borrowing: `&T` (shared, immutable) allows multiple references. `&mut T` (exclusive, mutable) allows exactly one reference. Rules: references must be valid, no aliasing + mutation, no dangling references. Enforced by borrow checker at compile time.

**R4** — `Result<T, E>`: `Ok(T)` or `Err(E)`. `Option<T>`: `Some(T)` or `None`. `?` unwraps `Ok`/`Some` or returns early on `Err`/`None`. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

**R5** — `Box<T>`: single owner, heap allocation. `Rc<T>`: reference-counted, single-threaded shared ownership. `Arc<T>`: atomic reference-counted, thread-safe shared ownership. Use `Arc<T>` + `Mutex<T>` for concurrent shared mutable state.

**R6** — Traits: explicit implementation, can have default methods/associated types. Go interfaces: implicit, duck-typing. `dyn Trait`: dynamic dispatch via vtable (runtime cost). `T: Trait`: static dispatch via monomorphization (zero-cost, compile-time).

**R7** — Fails because return lifetime is ambiguous. Fix with explicit lifetime: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`. Note: this forces both inputs to outlive the return, which is often semantically wrong; returning `String` is usually preferred.

**R8** — `Send`: safe to transfer ownership across threads. `Sync`: safe to share `&T` across threads. `Rc<T>` not `Send`/`Sync` due to non-atomic ref count. `Arc<T>` uses atomic ref count, making it `Send`/`Sync` (if `T` is).

**R9** — `async fn` returns a `Future` (state machine). `await` yields control until ready. Executor (Tokio) polls futures to completion. Differs from Go: Go uses preemptive M:N scheduling in runtime; Rust uses cooperative executors, futures are lazy, and async requires explicit pinning/lifetime management.

**R10** — `unsafe` bypasses compiler safety. 3 actions: dereference raw pointers, call `unsafe` functions, implement `unsafe` traits, access/modify `static mut`. Justified for FFI, low-level concurrency primitives, or performance-critical code where safety is proven.

**R11** — `match`: exhaustive pattern matching, binds values. `if let`: concise for single case. Compiler enforces exhaustiveness in `match`, warning on missing cases. `if let` does not require exhaustiveness.

**R12** — `Vec<T>`: heap-allocated, dynamic size. `[T; N]`: stack-allocated (usually), fixed compile-time size. Vec reallocates (typically doubles capacity) and moves data when capacity exceeded.

**R13** — Enums: algebraic data types, can hold heterogeneous payloads. Differ from C/Java: can carry data, support pattern matching. `Option<T>`: `Some(T)` or `None`. No `null` because `Option` forces explicit handling, eliminating null pointer exceptions.

**R14** — `impl` block defines methods. `&self`: borrows immutably. `&mut self`: borrows mutably. `self`: consumes ownership. Associated functions (`Self::new()`) don't take `self`, acting as factories/static methods.

**R15** — `derive` macro auto-implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if trait requires custom logic or contains incompatible fields (e.g., `Fn` closures, raw pointers for `Send`/`Sync`).

**R16** — `Cow<'a, T>` (Clone-on-Write): holds either `&'a T` or `T`. Useful when function might return borrowed or owned data. Avoids allocation if input already matches desired format; only clones when mutation is needed.

**R17** — `mod`: declares module. `use`: brings items into scope. `pub`: exposes outside module. File system: `mod.rs` or `mod_name/mod.rs`. Rust 2018: path resolution changed to crate-relative by default, `extern crate` removed, `use` can start with crate name.

**R18** — `Pin<T>` guarantees memory location doesn't change. Needed for self-referential structs and async/await (futures may store pointers to their own fields). `Unpin`: marker trait indicating type can be safely moved. Most types are `Unpin`; async futures are `!Unpin`.

**R19** — `macro_rules!`: declarative, pattern-matching, hygienic (macro-local namespaces). Procedural: `derive` (struct/enum impl), `attribute` (custom attributes), `function-like`. Hygiene: prevents variable capture, ensures macro expansions don't clash with surrounding code.

**R20** — Zero-cost abstractions: high-level features compile to efficient machine code. Iterators: compiled to loops, no allocation. Generics: monomorphization creates type-specific code. Trait static dispatch: inline calls. Achieves C-like performance with safety/ergonomics.
