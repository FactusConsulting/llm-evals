**K1** — A **Deployment** manages stateless workloads with interchangeable, randomly named pods. A **StatefulSet** manages stateful workloads requiring stable network IDs, ordered deployment/scaling, and persistent storage tied to each pod.

**K2** — The Endpoint Controller populates the Service's `endpoints` list with pod IPs. `kube-proxy` watches Services and endpoints, then programs node-level `iptables` or `IPVS` rules that load-balance traffic hitting the ClusterIP:Port to the backend pod IPs:Ports.

**K3** — **PersistentVolume (PV)** is a cluster-wide storage resource (statically provisioned or dynamically created). **PersistentVolumeClaim (PVC)** is a user's request for storage. **StorageClass** defines the provisioning template (e.g., SSD, replication). A PVC binds to a matching PV; if none exists, the StorageClass dynamically provisions one.

**K4** — 1. `kubectl logs <pod> --previous` to check crash reason. 2. `kubectl describe pod` for Exit Codes, OOMKilled events, or probe failures. 3. Verify resource requests/limits vs node capacity. 4. Check app dependencies (DB connectivity, missing config files, invalid entrypoint).

**K5** — CoreDNS provides internal DNS resolution for `<service>.<namespace>.svc.cluster.local` and pod FQDNs. If CoreDNS pods are down, internal service discovery fails, but direct pod IP communication and external DNS resolution remain unaffected.

**K6** — The scheduler first **filters** nodes that fail constraints (insufficient resources, taints, node selectors, affinity/anti-affinity). It then **scores** remaining nodes using priority functions. Factors: 1) LeastRequested/BalancedResourceAllocation (CPU/memory utilization), 2) NodeAffinity/TaintToleration, 3) InterPodAffinity/AntiAffinity, 4) TopologySpreadConstraints.

**K7** — Node free memory: 4GB − 3.5GB = 500Mi. Since 256Mi (request) < 500Mi, the pod **will be scheduled**. At runtime, using 600Mi exceeds the 512Mi limit → the kernel OOM killer terminates the container (`OOMKilled`), and the pod restarts per its restart policy.

**K8** — Client → External LB (routes to Ingress controller IP) → Ingress Controller (NGINX) parses Ingress resource → matches host/path → forwards to Kubernetes Service → Service routes to Endpoints (pod IPs) → `kube-proxy`/`iptables` redirects to pod → application handles request.

**K9** — A `NetworkPolicy` restricts pod-to-pod and pod-to-external traffic using selectors, ports, and protocols. Default behavior (no policies): all traffic allowed. When applied: all traffic is denied by default; only traffic explicitly matching the policy's ingress/egress rules is permitted.

**K10** — **RollingUpdate** gradually replaces old pods with new ones (zero downtime). **Recreate** terminates all old pods before starting new ones (downtime). Choose Recreate for stateful apps, database migrations, or when shared locks/resources prevent concurrent versions.

**K11** — A namespace provides logical isolation within a cluster. Default namespaces: `default`, `kube-system`, `kube-public`, `kube-node-lease`.

**K12** — `kubectl describe pod` shows detailed state, events, container statuses, resource limits/requests, environment variables, volume mounts, and probe configurations. `kubectl get pod` only shows basic status, age, and restart count.

**K13** — A ConfigMap stores non-sensitive configuration data. Pods consume it via: 1) Environment variables (`envFrom` or `env.valueFrom.configMapKeyRef`), 2) Volume mounts (files appear in the container filesystem).

**K14** — **ClusterIP**: internal cluster-only access. **NodePort**: exposes the service on a static port on each node's IP. **LoadBalancer**: provisions a cloud provider LB that routes to the NodePort/ClusterIP.

**K15** — A DaemonSet ensures a pod runs on every node (or a subset via selector). Use for node-level agents: logging (Fluentd), monitoring (node-exporter), CNI plugins, or storage daemons. Deployments are for application workloads.

**K16** — **Taints/Tolerations** are node-level "repel" rules. Taints mark nodes to repel pods; tolerations allow pods to schedule on tainted nodes. **Node Affinity** is a node-level "attract" rule. Use case: Taints for dedicated GPU nodes; Affinity for zone-aware scheduling.

**K17** — An Operator is a custom controller that manages complex stateful applications using CRDs and custom reconciliation logic. Unlike standard controllers (which just sync desired vs actual state), Operators encode operational knowledge (backups, upgrades, failover, scaling). Solves manual ops for stateful services.

**K18** — etcd uses **Raft consensus** with linearizable reads/writes. If quorum is lost, the cluster becomes read-only/unwritable. Recovery from 2/3 node loss: restore from a recent snapshot (`etcdctl snapshot restore`), or use `--force-new-cluster` (emergency, loses last committed transaction).

**K19** — RBAC controls access via Roles/ClusterRoles (permissions) and RoleBindings/ClusterRoleBindings (grants to users/groups/SA). Manifest:
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: dev
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: dev-pod-reader
  namespace: dev
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — Default `ndots:5` causes the resolver to try 5 suffixes (`.svc.cluster.local`, `.cluster.local`, etc.) before querying external DNS, causing 5 queries per lookup. Fix: set `dnsConfig: ndots: 2` in the pod spec, or use FQDNs with a trailing dot (`service.namespace.svc.cluster.local.`).

---

**D1** — `git merge` preserves history with a merge commit. `git rebase` rewrites history by replaying commits linearly. Avoid rebasing on shared/public branches or when multiple developers are actively committing to the same branch.

**D2** — **TCP**: connection-oriented, reliable, ordered, flow/congestion control. **UDP**: connectionless, unreliable, low-latency. TCP: HTTP, SMTP. UDP: DNS, VoIP, live video streaming.

**D3** — A race condition occurs when concurrent threads/processes access shared state without synchronization, leading to unpredictable results. Example: two threads incrementing a shared counter without a mutex → final value < expected due to lost updates.

**D4** — **Symmetric**: same key for encryption/decryption (fast). **Asymmetric**: public/private key pair (secure key exchange). TLS uses asymmetric crypto for the handshake (authenticating server/client and exchanging a session key), then switches to symmetric crypto for bulk data encryption.

**D5** — Each Dockerfile instruction creates a read-only image layer. Layer caching reuses unchanged layers. Best practice: order instructions from least to most frequently changing (e.g., copy `package.json`/dependencies first, then source code) to maximize cache hits.

**D6** — Order: 1. Check service health/endpoints registration. 2. Review upstream application logs for errors/timeouts. 3. Verify resource limits (CPU throttling, OOMKilled). 4. Check downstream dependencies (DB, cache, external APIs). 5. Inspect load balancer/ingress health check failures.

**D7** — CAP theorem: a distributed system can only guarantee two of Consistency, Availability, Partition tolerance. **CP**: Distributed SQL (CockroachDB, HBase) – prioritizes data accuracy over availability during network splits. **AP**: Cassandra, DynamoDB – prioritizes availability, allows stale reads.

**D8** — **Horizontal**: add more nodes/instances. **Vertical**: increase CPU/RAM of existing node. Patterns enabling horizontal scaling: stateless design, externalized state (DB/cache), load balancing, sharding/partitioning, asynchronous messaging (queues).

**D9** — An environment variable is a dynamic value passed to processes. Persist across sessions: add `export VAR=value` to `~/.bashrc` or `~/.profile`, then run `source ~/.bashrc`.

**D10** — **JSON**: strict syntax, key-value pairs, arrays. **YAML**: indentation-based, human-readable, supports comments. JSON advantage: universal parsing, strict schema validation. YAML advantage: readability, less boilerplate, easier for config files.

**D11** — A REST API uses HTTP methods to manipulate resources. **GET**: retrieve. **POST**: create. **PUT**: replace/update. **DELETE**: remove.

**D12** — Version pinning locks dependencies to exact versions (e.g., `package@1.2.3`). Critical for reproducible builds, security auditing, and preventing unexpected breaking changes from upstream updates.

**D13** — **Compiled**: source → machine code before execution (C, Rust). **Interpreted**: source → executed line-by-line at runtime (Python, JavaScript). (Note: modern languages often use JIT compilation, blurring the line.)

**D14** — **Reverse proxy**: sits in front of servers, routes client requests to backends. Use cases: Nginx (load balancing, SSL termination), HAProxy (high-performance TCP/HTTP routing). **Forward proxy**: sits in front of clients, routes outbound requests. Use case: corporate proxy for content filtering/caching.

**D15** — A deadlock occurs when two+ processes wait indefinitely for each other's resources. Coffman conditions: 1. Mutual exclusion. 2. Hold and wait. 3. No preemption. 4. Circular wait.

**D16** — Eventual consistency guarantees all replicas converge without requiring immediate synchronization. Cassandra uses tunable consistency levels (`ONE`, `QUORUM`, `ALL`, `LOCAL_QUORUM`, `SERIAL`). For read-after-write consistency, use `QUORUM` for both reads and writes (ensures overlap), or `SERIAL`/`LWT` for strict ordering.

**D17** — mTLS authenticates both client and server via X.509 certificates. Handshake: ClientHello → ServerHello+Cert → ServerKeyExchange → ClientKeyExchange+Cert → verify certs → derive session keys. Commonly used in: service meshes (Istio/Linkerd), internal microservices, zero-trust architectures.

**D18** — A hash table maps keys to values via a hash function → array index. Collision resolution: **chaining** (linked lists at each bucket), **open addressing** (linear/quadratic probing, double hashing). Complexity: Average O(1) insert/lookup/delete. Worst O(n) if all keys collide.

**D19** — A circuit breaker prevents cascade failures by failing fast when a downstream service is unhealthy. States: **Closed** (normal), **Open** (fail fast, trip after error threshold), **Half-open** (test with limited requests). Relates to retries: circuit breakers should wrap retry logic to prevent retry storms; exponential backoff reduces load during recovery.

**D20** — **Optimistic**: assumes no conflicts, checks at commit (row versioning, `UPDATE ... WHERE version = ?`). **Pessimistic**: locks resources during read/write (`SELECT FOR UPDATE`, row locks). Choose optimistic for high read/low write contention; pessimistic for high write contention or critical financial transactions.
