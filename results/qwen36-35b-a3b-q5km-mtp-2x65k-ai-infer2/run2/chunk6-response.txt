## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted with `undefined` initialization. `let`/`const` are block-scoped, hoisted but stay in the Temporal Dead Zone until declaration. `const` prevents reassignment. Hoisting moves declarations to the top of their scope during compilation; `var` initializes as `undefined`, while `let`/`const` remain uninitialized until execution reaches them.

**JS2** — The event loop continuously checks the call stack and queues. When the stack is empty, it processes the microtask queue (Promises, `queueMicrotask`) completely, then picks one macrotask (setTimeout, I/O, UI rendering) to push onto the stack. This ensures async callbacks run in a predictable, non-blocking order.

**JS3** — A closure is a function that retains access to its outer lexical scope. Example: `function makeCounter() { let i=0; return () => ++i; }`. The classic bug: `for (var i=0; i<3; i++) setTimeout(() => console.log(i), 100)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped), IIFE, or `setTimeout(..., 0, i)`.

**JS4** — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that pauses execution until the promise settles, making code sequential. Error handling: `try/catch` for `await`, `.catch()` or second `.then()` arg for promises. `Promise.all` fails fast on first rejection; `Promise.allSettled` waits for all promises, returning an array of `{status, value/reason}` objects.

**JS5** — `interface` defines only shapes, supports declaration merging, and is ideal for object contracts/APIs. `type` is broader: supports unions, intersections, primitives, mapped types, and utility types. Use `interface` for extensible object shapes, `type` for unions/intersections. Discriminated unions use a common literal property (e.g., `type: 'a' | 'b'`) to narrow types in `switch`/`if` statements.

**JS6** — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar: `class` defines a constructor and attaches methods to `prototype`; `extends` sets up the prototype chain via `Object.setPrototypeOf`.

**JS7** — `this` is dynamically bound based on call site. Priority order: 1. `new` (new instance), 2. Explicit (`call`/`apply`/`bind`), 3. Implicit (`obj.method()`), 4. Default (`global`/`undefined` in strict mode). `bind()` returns a new function with `this` permanently locked. You cannot re-bind it; calling `.bind()` again returns another bound function but doesn't override the original lock.

**JS8** — `WeakRef` holds a weak reference that doesn't prevent GC. `FinalizationRegistry` fires a callback when weakly referenced objects are collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the engine can track them for GC; if keys were primitives, entries would never be cleaned up, causing memory leaks.

**JS9** — V8 optimizes via: Hidden Classes (shape optimization for fast property access), Inline Caching (caches hidden class pointers at call sites), and Deoptimization (reverts to slower code when assumptions break). Patterns causing deopt: dynamic property addition, type polymorphism, `eval`/`with`, `arguments` object, and `try/catch` in tight loops.

**JS10** — Tree-shaking removes unused exports at build time. It works with ES Modules because `import`/`export` are static and evaluated at compile time, enabling static analysis. CommonJS uses dynamic `require()`, evaluated at runtime, so bundlers can't safely determine which exports are actually used.

**JS11** — `null` = intentional absence of value; `undefined` = variable declared but not assigned. `==` coerces types (`null == undefined` is `true`); `===` checks type and value (`false`). `??` returns right operand only if left is `null`/`undefined`. `?.` safely accesses nested properties, short-circuiting to `undefined` instead of throwing.

**JS12** — `map()` transforms elements, `filter()` keeps matching ones, `reduce()` accumulates to a single value. Initial value in `reduce()` prevents type errors on empty arrays and sets the accumulator's type. `flatMap()` maps then flattens one level; useful for transforming arrays while expanding elements (e.g., splitting strings into arrays).

**JS13** — Template literals use backticks, support `${expr}` interpolation and multi-line strings. Tagged templates call a function with an array of string parts and interpolated values. Example: `function html(strings, ...vals) { return strings.reduce((acc, s, i) => acc + s + (vals[i] ? escapeHtml(vals[i]) : ''), ''); }`

**JS14** — Destructuring unpacks values: `{a, b: renamed} = obj` (object), `[first, ...rest] = arr` (array). Default values: `a = 1`. Rest operator `...` collects remaining elements. Works in function parameters too, enabling clean API design and avoiding index-based access.

**JS15** — `for...in` iterates over enumerable string keys (including inherited), meant for objects. `for...of` iterates over iterable values (arrays, strings, maps), skipping non-iterable. Avoid `for...in` on arrays because order isn't guaranteed, includes inherited properties, and is slower.

**JS16** — Generics use type parameters for reusable code. Constraints: `function id<T extends string | number>(x: T)`. Conditional types: `type NonNullable<T> = T extends null | undefined ? never : T`. `infer` extracts types in contexts: `type Unpack<T> = T extends Promise<infer U> ? U : T`.

**JS17** — CJS (`require`/`module.exports`) is synchronous, runtime-evaluated, module-per-file. ESM (`import`/`export`) is static, async, native. Node.js supports both via `.mjs` or `"type": "module"` in `package.json`, which tells Node to treat `.js` files as ESM.

**JS18** — Structural typing checks compatibility by shape, not names. Excess property checks apply only to object literals assigned directly to variables/types, not to properties accessed later. `extends` checks assignability; `satisfies` checks if an expression matches a type without widening, preserving the original type. Variance (`in`/`out`/`in out`) controls covariance/contravariance for generic parameters; TS 4.7+ tightened rules around `satisfies` and structural compatibility.

**JS19** — `Proxy` wraps objects to intercept operations (get, set, apply, etc.). `Reflect` mirrors Proxy traps and provides default behavior. Example: validation proxy intercepts `set` to check types. `Reflect.get(target, prop, receiver)` ensures correct `this` binding and prototype chain traversal.

**JS20** — `SharedArrayBuffer` shares memory between main thread and Web Workers. `Atomics` provides atomic operations for synchronization. Communication happens via reading/writing the shared buffer. Ordering guarantees use sequential consistency via `Atomics.store`/`load`. `Atomics.wait` blocks until a value changes or timeout; `Atomics.notify` wakes waiting threads. Requires cross-origin isolation headers.

## Bash

**B1** — `$@` expands to separate quoted words (`"$1" "$2"`), preserving individual arguments. `$*` expands to a single quoted string (`"$1 $2 ..."`). `"$@"` is safe for argument passing; `"$*"` joins them with the first char of IFS.

**B2** — `set -e`: exit immediately on command failure. `set -u`: treat unset variables as errors. `set -o pipefail`: pipeline returns the exit status of the last non-zero command. Together, they enforce strict error handling and prevent silent failures.

**B3** — `$(command)` is modern, nestable, and preferred. `` `command` `` is legacy and harder to nest. `$((expression))` is bash-native arithmetic expansion. `expr` is an external command, slower, and lacks bash's built-in arithmetic features.

**B4** — Process substitution `<(...)` creates a file descriptor pointing to a command's output. Used when commands expect files but you have streams. Example: `diff <(sort file1) <(sort file2)` compares sorted contents without temp files.

**B5** — Use `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous because it breaks on spaces/globs, performs unnecessary word splitting, and fails on special characters or newlines.

**B6** — Here doc `<<EOF` passes multi-line input to stdin. Here string `<<<` passes a single string. `<<-EOF` strips leading tabs (not spaces) for indentation, keeping scripts readable.

**B7** — Redirections evaluate left-to-right. `cmd > file 2>&1`: stdout → file, then stderr → stdout (file). `cmd 2>&1 > file`: stderr → original stdout (terminal), then stdout → file. `cmd &> file` is bash shorthand for the first. The first two differ because `2>&1` in the second redirects stderr before stdout is redirected to the file.

**B8** — ```bash
lock_dir="/tmp/mylock"
cleanup() { rmdir "$lock_dir" 2>/dev/null; }
trap cleanup EXIT INT TERM
if ! mkdir "$lock_dir"; then echo "Locked"; exit 1; fi
# ... critical section ...
```
`mkdir` is atomic on POSIX, avoiding TOCTOU race conditions. `trap` ensures cleanup on normal exit or signals.

**B9** — Single quotes `'...'`: literal, no expansion. Double quotes `"..."`: allow `$`, `` ` ``, `\`, `!`. No quotes: triggers word splitting and globbing. Example: `var="hello world"; echo '$var'` → `$var`; `echo "$var"` → `hello world`; `echo $var` → `hello world` (split into two args).

**B10** — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash keyword: no word splitting/globbing, supports `&&`, `||`, `=~`. Safer for variables and complex conditions.

**B11** — `$?`: exit status of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: number of positional parameters.

**B12** — `func() { commands; }` or `function func { commands; }`. Return values: `return <int>` (exit code 0-255), or `echo`/`printf` to stdout and capture. Bash functions share global scope; use `local` for isolation.

**B13** — `PATH`: colon-separated directories bash searches for executables. Resolves by checking dirs in order. Builtin: compiled into shell (`cd`, `echo`). External: separate binaries (`ls`, `grep`). Check with `type` or `command -v`.

**B14** — `trap 'cleanup' EXIT INT TERM`. `ERR` triggers on command failure. Execution order: signals interrupt, trap runs, then shell exits/continues. Multiple signals are queued or handled sequentially depending on implementation; traps run in the order they're registered.

**B15** — `xargs` builds and executes commands from stdin. Differs from substitution (which expands inline). `find -print0 | xargs -0` handles spaces/newlines safely. `xargs -P N` runs N processes in parallel, improving throughput for I/O-bound tasks.

**B16** — Arrays: `arr=(a b c)`, `${arr[0]}`, `${arr[@]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${!assoc[@]}`. Associative requires `declare -A`, supports string keys, and lacks numeric indexing.

**B17** — `(...)`: subshell, isolated scope, changes don't affect parent. `{ ...; }`: group command, same scope, changes persist. Piping into `while` runs the loop in a subshell, so variable changes are lost. Fix: process substitution `while read ... done < <(cmd)`.

**B18** — `SIGINT` (Ctrl+C, interrupt), `SIGTERM` (graceful stop), `SIGHUP` (terminal hangup), `SIGKILL` (force kill, uncatchable). Handle graceful shutdown: trap `TERM`, wait for background jobs (`wait $!`), cleanup, then `exit`.

**B19** — ```bash
split -l 10000 log.log part_
find parts_ -type f -print0 | xargs -0 -P 4 -I {} bash process.sh {}
cat part_* > merged.log
```
Trade-offs: CPU vs I/O, overhead of splitting/merging. Error propagation: check exit codes, use temp dirs, aggregate failures, and exit non-zero if any job fails.

**B20** — `exec` replaces the current shell process or redirects FDs. `exec 3>file` opens FD 3. `exec 3>&-` closes it. Coprocess: `coproc cmd` runs cmd in background, connects stdin/stdout to FDs. Use for persistent IPC without subshell overhead.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console (bypasses pipeline, breaks automation). Matters because pipelines expect structured objects, not formatted text.

**PS2** — Pipeline streams objects between cmdlets. `ForEach-Object`: processes each object in the pipeline (streaming, memory efficient). `foreach`: loops over a collection in memory (faster for small sets, loads all into memory). Use `ForEach-Object` for large streams, `foreach` for known collections.

**PS3** — `[PSCustomObject]`: strongly typed, ordered, pipeline-friendly, supports methods/properties. `[hashtable]`: unordered, untyped, faster for lookups. Convert: `[PSCustomObject]@{Key="Val"}`. Use custom objects for output/pipelines, hashtables for config/lookups.

**PS4** — Terminating errors stop execution (exceptions, `throw`, `-ErrorAction Stop`). Non-terminating errors continue, set `$Error`. `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors.

**PS5** — Splatting: `@params` passes a hashtable's keys as named parameters. `@{Verbose=$true, ErrorAction='Stop'}`. Differs from passing a hashtable as a single parameter because it expands to individual arguments.

**PS6** — `Invoke-Command -ComputerName`: runs one-off remote command. `Enter-PSSession`: interactive remote session. Uses WS-Management (WinRM) by default. PS 7+ supports SSH remoting via `New-PSSession -HostName`.

**PS7** — `$result += "one"` creates a new array each iteration. Returns `Object[]`. If 0 items, `$result` is `$null`. Correct pattern: `[System.Collections.Generic.List[string]]::new()` or `@()` with `.Add()`, or simply `return @("one")`.

**PS8** — `[scriptblock]`: code container, can be passed around. Functions are named scriptblocks with parameters. Pass to remote: `Invoke-Command -ScriptBlock $sb -ArgumentList $args`. Double-hop: auth fails when remoting to a second server. Solve with CredSSP (insecure) or `-ArgumentList` to pass data, or use Kerberos delegation.

**PS9** — `@()` forces array. `[array]` casts to array. Indexing `$null` returns `$null`. Indexing `@()` returns `$null`. `@()` ensures consistent array behavior and prevents pipeline enumeration surprises.

**PS10** — `-eq`/`-ne`: equality/inequality. `-like`/`-match`: wildcard/regex. `-contains`/`-in`: membership. Case-sensitive: `-ceq`, `-clike`, `-cmatch`, `-ccontains`, `-cin`. `-contains` checks if collection contains value (`$col -contains $val`). `-in` checks if value is in collection (`$val -in $col`).

**PS11** — Module: collection of functions/cmdlets. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies). Binary: compiled DLL. `Import-Module` loads into session, searches `$env:PSModulePath`.

**PS12** — `"..."`: double quotes, allows interpolation `$var`. `'...'`: single quotes, literal. Expressions: `$($expr)`. Here-string: `@"..."@` for multi-line, preserves formatting, supports interpolation.

**PS13** — `Get-Member`: shows object members. Pipeline: `cmd | Get-Member`. Properties: data. Methods: actions. NoteProperties: added properties. `Select-Object`: projects properties. `Where-Object`: filters objects.

**PS14** — Classes: v5+, C#-like. Limitations: no multiple inheritance, limited interface support, constructors must match signature, no access modifiers (public by default). Use classes for complex data/models, functions for scripting/logic.

**PS15** — `CmdletBinding()`: enables advanced features. `SupportsShouldProcess`: `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: default param set. `ValueFromPipeline`: binds pipeline input. `Begin`: runs once. `Process`: runs per pipeline object. `End`: runs once after pipeline.

**PS16** — Providers: abstract data stores. `Get-ChildItem` works on FileSystem, Registry (`HKLM:\`), Certificates (`Cert:\`), Environment. Registry accessed like FS: `Get-ChildItem HKLM:\SOFTWARE`.

**PS17** — Runspaces: lightweight execution contexts. `[runspacepool]`: manages multiple runspace threads. `[powershell]`: object to add commands. `ForEach-Object -Parallel` (v7+): built-in parallelism with automatic runspace management. Manual: create pool, add runspace, dispatch jobs, collect results. Thread safety: avoid shared state, use thread-safe collections.

**PS18** — PSScriptAnalyzer: linting tool. Rules: predefined checks (naming, style, security). Severity: Error, Warning, Information. Custom rules: PowerShell scripts. Suppress: `#pragma disable`, `.editorconfig`. CI/CD: run in pipeline, fail on errors.

**PS19** — `$using:`: serializes local variable into remote session/job. `-ArgumentList`: passes values as parameters. Serialization limits: CLIXML depth (default 64), complex objects may fail or lose types. Use `-ArgumentList` for simple data, `$using:` for convenience, but be aware of serialization overhead.

**PS20** — DSC: declarative config management. Configurations: desired state definitions. Resources: building blocks (File, Service, Package). LCM: agent that applies config. WinPS DSC: Windows-only, MOF files. PS 7+: cross-platform, JSON/YAML, uses `PackageManagement`/`PSDesiredStateConfiguration`. Replaced/supplemented by Ansible, Terraform, Chef, or native cloud IaC.
