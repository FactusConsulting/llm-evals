**JS1** `var` is function-scoped, hoisted with initialization to `undefined`, and re-declarable. `let`/`const` are block-scoped, hoisted but in a Temporal Dead Zone (TDZ) until declaration, and `const` prevents reassignment. Hoisting is the compiler behavior of moving declarations to the top of their scope during the creation phase.

**JS2** The event loop continuously checks the call stack. When empty, it flushes the microtask queue (promises, `queueMicrotask`, `MutationObserver`) completely, then processes one macrotask (setTimeout, setInterval, I/O, UI render), repeating. Microtasks always run before the next macrotask, enabling promise resolution to interrupt pending timers.

**JS3** A closure is a function that retains access to its lexical scope even after the outer function returns. Example: a counter factory. Classic bug: `for (var i=0; i<3; i++) setTimeout(()=>console.log(i), 0)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped), IIFE, or pass `i` as a 3rd arg to `setTimeout`.

**JS4** `Promise` represents an async value. `async/await` is syntactic sugar that pauses execution until the promise settles, making async code read synchronously. Error handling: `try/catch` with `await`, or `.catch()`/`.then(null, err)` with promises. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all, returning `{status: 'fulfilled'|'rejected', value|reason}` for each.

**JS5** `interface` defines object shapes, supports declaration merging/extension, and erases at runtime. `type` is a broader alias supporting unions, intersections, tuples, and primitives. Use `interface` for public APIs/objects, `type` for unions/primitives. Discriminated unions use a common literal property (tag) to narrow types in `switch`/`if` statements.

**JS6** JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar: `extends` sets `[[Prototype]]`, `super` calls parent constructor/methods, and `new` invokes `[[Construct]]` which sets `this` and returns the instance.

**JS7** `this` is dynamically bound based on call site. Priority: 1. `new` (constructor), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (`window` or `undefined` in strict mode). `bind()` returns a new function with permanently fixed `this`. It cannot be re-bound by `call`/`apply` or another `bind`.

**JS8** `WeakRef` holds a weak reference that doesn't prevent GC. `FinalizationRegistry` runs a callback when weakly referenced objects are collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the engine can track their lifecycle; when the key is GC'd, the entry is automatically removed, preventing memory leaks.

**JS9** V8 optimizes via hidden classes (shape inference for fast property access), inline caching (caches shape info at call sites), and deoptimization (reverts to slower code when assumptions break). Deopt triggers: dynamic property addition/removal, `delete`, `arguments` object, `eval`/`with`, inconsistent types, or `try/catch` in tight loops.

**JS10** Tree-shaking removes unused exports at build time. It works with ES modules because imports/exports are static and analyzable at compile time. CommonJS uses dynamic `require()`, evaluated at runtime, so bundlers can't statically determine dependencies, making dead code elimination ineffective.

**JS11** `null` is intentional absence; `undefined` is uninitialized/missing. `==` coerces types (`null == undefined` is `true`), `===` checks type+value (`false`). `??` returns right operand if left is `null`/`undefined`. `?.` safely accesses nested properties without throwing on `null`/`undefined`.

**JS12** `map()` transforms, `filter()` selects, `reduce()` accumulates to a single value. Initial value in `reduce()` sets the accumulator start and prevents errors on empty arrays. `flatMap()` maps then flattens one level; useful for transforming and flattening nested structures in a single pass without double iteration.

**JS13** Template literals use backticks, support `${expr}` interpolation and multi-line strings. Tagged templates call a function with an array of string parts and interpolated values. Example: `function html(strings, ...vals) { return strings.reduce((acc, s, i) => acc + s + (vals[i] ? escapeHtml(vals[i]) : ''), ''); }`

**JS14** Destructuring unpacks arrays/objects. Object: `{a, b} = obj`. Array: `[a, b] = arr`. Defaults: `{a = 1} = obj`. Renaming: `{a: newName} = obj`. Rest: `const {a, ...rest} = obj` collects remaining properties into a new object.

**JS15** `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, maps). Avoid `for...in` on arrays because it iterates keys, not values, includes prototype properties, and doesn't guarantee order.

**JS16** Generics use type parameters for reusability. Constraints: `function id<T extends string | number>(x: T)`. Conditional types: `type NonNullable<T> = T extends null | undefined ? never : T`. `infer` extracts types: `type ElementType<T> = T extends (infer U)[] ? U : T`.

**JS17** CommonJS: dynamic, synchronous, `require`/`module.exports`, Node default. ES Modules: static, async, `import`/`export`, browser/Node native. Node uses CJS by default; `"type": "module"` in `package.json` makes `.js` files use ESM. `.mjs` always ESM, `.cjs` always CJS.

**JS18** Structural typing: compatibility based on shape, not names. Excess property checks apply only to object literals assigned to variables/types, not to properties accessed later. `extends` defines assignability. `satisfies` checks type without widening, preserving the original type. TS 4.7+ uses `in`/`out` modifiers on function types to control parameter/return variance.

**JS19** `Proxy` wraps objects to intercept operations (get, set, apply, etc.). `Reflect` mirrors traps and provides default behavior. Example: validation proxy intercepts `set` to check types. Practical: Vue 3 uses `Proxy` for reactive data binding by tracking property access/mutation.

**JS20** `SharedArrayBuffer` shares memory between main thread and Web Workers. `Atomics` provides atomic operations and synchronization with sequential consistency. `Atomics.wait` blocks until a value changes or timeout. `Atomics.notify` wakes waiting threads. Requires cross-origin isolation headers for security.

**B1** `$@` expands to separate quoted words (`"$1" "$2"`), preserving individual arguments. `$*` expands to a single quoted string (`"$1 $2 ..."`). `"$@"` is safe for iteration; `"$*"` joins with the first character of `IFS`.

**B2** `set -e`: exit on command failure. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the rightmost non-zero exit code, catching failures in intermediate commands.

**B3** `$(command)` is modern, supports nesting, and is easier to read. `` `command` `` is legacy. `$((expression))` is bash's built-in arithmetic expansion (fast, no subshell). `expr` is an external utility, slower, and legacy.

**B4** Process substitution `<(cmd)` creates a temporary file descriptor. Example: `diff <(sort file1) <(sort file2)` compares sorted files without creating temp files on disk.

**B5** Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous because word splitting breaks on spaces, globbing expands patterns, and newlines are lost.

**B6** Here doc `<<EOF` feeds multi-line input. Here string `<<<` feeds a single line. `<<-EOF` strips leading tabs (not spaces) for indentation in scripts.

**B7** `cmd > file 2>&1`: stdout → file, then stderr → wherever stdout points (file). `cmd 2>&1 > file`: stderr → terminal (stdout's original location), then stdout → file. `cmd &> file` is bash shorthand for the first. Order matters because redirections are processed left-to-right.

**B8** 
```bash
LOCK="/tmp/mylock"
cleanup() { rm -rf "$LOCK"; }
trap cleanup EXIT INT TERM
if ! mkdir "$LOCK" 2>/dev/null; then echo "Locked"; exit 1; fi
# ... work ...
```
`mkdir` is atomic on POSIX filesystems, preventing race conditions. `trap` ensures cleanup on exit or signals.

**B9** Single quotes: literal, no expansion. Double quotes: allow `$`, `` ` ``, `\`, `!` expansion. No quotes: word splitting, globbing, expansion. Example: `var="hello world"; echo '$var'` → `$var`; `echo "$var"` → `hello world`; `echo $var` → `hello world` (but splits/globs).

**B10** Check: `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin supporting `&&`, `||`, `=~`, and prevents word splitting/globbing on the RHS. `[ ]` is POSIX `test`, stricter and less feature-rich.

**B11** `$?`: last exit code (error checking). `$$`: script PID (logging/locking). `$!`: last background job PID (`wait`). `$#`: number of positional parameters (argument validation).

**B12** Define: `func() { ...; }` or `function func { ...; }`. Return values: `return` only sets exit status (0-255). For data, `echo`/`printf` to stdout and capture via `$()`.

**B13** `PATH` is colon-separated dirs bash searches for executables. Resolution: PATH → builtins → hash table. Builtin: compiled into shell (`cd`, `echo`). External: separate binary. Check: `type cmd` or `command -v cmd`.

**B14** `trap` registers handlers: `trap 'cleanup' EXIT ERR INT TERM`. `ERR` fires on command failure, `EXIT` on script end, signals interrupt. Multiple signals queue and handle sequentially unless ignored. Use `trap - SIGNAL` to reset.

**B15** `xargs` builds commands from stdin, handling quoting/splitting safely. `find -print0 | xargs -0` handles spaces/newlines. `-P N` runs N processes in parallel. Command substitution `$(...)` loads all output into memory first.

**B16** Arrays: `arr=(a b c)`, `${arr[0]}`, `${arr[@]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${!assoc[@]}`. Associative requires `declare -A`, uses string keys, and lacks numeric indexing.

**B17** Subshell `(...)` runs in a child process; variable changes are lost. Group `{ ...; }` runs in current shell; variables persist. Piping into `while` runs the loop in a subshell. Fix: process substitution `< <(cmd)` or `shopt -s lastpipe` (bash 4.2+).

**B18** SIGINT (Ctrl+C, interrupt), SIGTERM (graceful stop, catchable), SIGHUP (terminal close, reload), SIGKILL (force kill, uncatchable). Graceful shutdown: trap SIGTERM, set flag, `wait` on bg jobs, cleanup. Job control: `jobs`, `fg`, `bg`, `wait`.

**B19** `split -l 10000 log.txt log_part_`, then `find . -name "log_part_*" -print0 | xargs -0 -P 4 -I {} bash -c 'process "$1"' _ {}`. Merge results. Trade-offs: CPU vs I/O bound, splitting/merging overhead. Error propagation: check `$?`, use `set -o pipefail`, aggregate non-zero exits.

**B20** `exec` replaces the shell process or manipulates file descriptors. `exec 3>file` opens FD 3, `exec 3>&-` closes it. Coprocess: `coproc cmd` runs cmd in background, connects stdin/stdout to FDs. Use for persistent background services or IPC without temp files.

**PS1** `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console, bypassing the pipeline and breaking chaining. Matters because pipelines expect structured objects, not formatted text.

**PS2** Pipeline streams objects. `ForEach-Object` is a cmdlet, processes one-by-one, supports `-Parallel` (v7), and handles streaming. `foreach` is a language construct, faster for in-memory collections, but loads everything into memory. Use `ForEach-Object` for streaming/large data, `foreach` for collections.

**PS3** `[PSCustomObject]` is ordered, strongly typed, pipeline-friendly. Hashtable is unordered, dynamic. Convert: `[PSCustomObject]@{Key="Val"}`. Use `[PSCustomObject]` for structured data/models, hashtable for dynamic/config.

**PS4** Terminating errors stop execution (caught by `try/catch`). Non-terminating continue (logged to `$Error`). `-ErrorAction` overrides per-cmdlet. `$ErrorActionPreference` sets global default. `try/catch` only catches terminating errors.

**PS5** Splatting passes a hashtable as named parameters: `@{Path="."; Recurse=$true} | Get-ChildItem`. Improves readability, supports dynamic param sets, and avoids long parameter lists. Differs from single param by distributing keys to matching parameters.

**PS6** `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` starts interactive remote session. Uses WS-Management (WinRM) by default. PS 7+ supports SSH transport via OpenSSH.

**PS7** `@()` forces array. `+=` on array creates a new array each time (slow). `Get-Items` returns `Object[]`. `$x.GetType().Name` → `Object[]`. If 0 items, returns `$null`. Correct pattern: use `[System.Collections.Generic.List[string]]::new()` or wrap output in `@()` consistently.

**PS8** `[scriptblock]` is a code container, serializable. Function is a named scriptblock with parameters. Pass to remote via `-ArgumentList` or `$using:`. Double-hop: auth fails when remoting to a second server. Solve with CredSSP (insecure), Kerberos delegation, or `-ArgumentList` to avoid second hop.

**PS9** `@()` forces array, `[array]` casts. Force single to array: `@($single)`. Index `$null` → error. Index empty array → `$null`. `@()` prevents enumeration pitfalls when cmdlets return single items.

**PS10** `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (collection contains value), `-in` (value in collection). Case-sensitive: `-ceq`, `-clike`, `-cmatch`. `-contains` checks left side; `-in` checks right side (PS 3+).

**PS11** Module: collection of functions/cmdlets. `.psm1`: script code. `.psd1`: manifest (metadata, dependencies). Binary: compiled `.dll`. `Import-Module` loads into session, searches `$env:PSModulePath`.

**PS12** Interpolation: `"Hello $name"`. `"..."` expands, `'...'` literal. Expressions: `"Value: $(Get-Date)"`. Here-string: `@"..."@` for multi-line, preserves formatting and indentation.

**PS13** `Get-Member` explores object members. Properties (data), Methods (actions), NoteProperties (custom). `Select-Object` picks properties/creates calculated props. `Where-Object` filters objects.

**PS14** Classes (v5): `class MyClass { [string]$Prop; MyClass([string]$p) { $this.Prop = $p } }`. Limitations: no multiple inheritance, limited interfaces (PS 7.2+), no virtual/abstract. Use classes for structured data/models, functions for logic.

**PS15** `CmdletBinding` enables advanced features. `SupportsShouldProcess`: `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: controls param sets. `ValueFromPipeline`: binds pipeline input. `Begin`/`Process`/`End`: lifecycle blocks. `Process` runs per pipeline object.

**PS16** Providers abstract data stores. `Get-ChildItem` works on FileSystem, Registry, Cert, Env. Registry accessed via `HKLM:\` or `Registry::`. Treats keys as directories, values as files.

**PS17** Runspaces: execution environments. `[runspace]`: single thread. `[runspacepool]`: thread pool. `[powershell]`: adds pipeline. `ForEach-Object -Parallel` (v7+) uses runspace pool automatically. Manual: create pool, add scripts, invoke, manage state. Thread safety: runspace pool isolates runs; share data via files/queues.

**PS18** `PSScriptAnalyzer`: linting tool. Rules: syntax, style, performance. Severity: error, warning, info. Custom rules: `.ps1` scripts. Suppress: `#pragma disable`, config file, or IDE. CI/CD: run in pipeline, fail on errors.

**PS19** `$using:` scope serializes variables for remote/jobs/parallel. `-ArgumentList` passes values. Limits: CLIXML serialization depth (default 64), complex objects may fail or lose types. Workaround: convert to hashtable/JSON, or use `-ArgumentList` carefully.

**PS20** DSC: config management. Configurations: declarative code. Resources: building blocks (File, Package, Service). LCM: applies configs, checks drift. WinPS vs PS7: PS7 uses OpenDSC, cross-platform, modular. Replaced in modern IaC by Ansible, Terraform, Chef, or native cloud IaC, but DSC remains in Windows ecosystems.
