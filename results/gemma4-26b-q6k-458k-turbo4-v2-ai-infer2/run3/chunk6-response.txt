## JavaScript / TypeScript (20 questions)

**JS1** — `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but reside in a "Temporal Dead Zone" (TDZ) until declaration. Hoisting is the engine's behavior of moving declarations to the top of their scope.

**JS2** — The Event Loop manages execution. The **Call Stack** handles synchronous tasks. When the stack is empty, the loop checks the **Microtask Queue** (Promises, `queueMicrotask`) first, then the **Macrotask Queue** (setTimeout, I/O). Microtasks always execute before the next macrotask.

**JS3** — A closure is a function that "remembers" its lexical scope even when executed outside it. Example: `function outer() { let x = 10; return () => x; }`. The classic loop bug: using `var` in a `for` loop causes all iterations to share the same final value. Fix: use `let` to create a new binding per iteration.

**JS4** — `Promise` represents an eventual value. `async/await` is syntactic sugar for Promises, making async code look synchronous. `try/catch` handles errors in `async` functions. `Promise.all` rejects if *any* promise fails; `Promise.allSettled` waits for all to finish, regardless of outcome.

**JS5** — `interface` is primarily for defining object shapes and supports declaration merging. `type` is for aliases, unions, and primitives. Use `interface` for public APIs/extensibility; use `type` for complex logic/unions. **Discriminated unions** use a common literal property (e.g., `type: 'success' | 'error'`) to narrow types.

**JS6** — Objects inherit properties via the prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar over prototypal inheritance; it provides a cleaner syntax for constructors and methods but uses the same underlying mechanism.

**JS7** — `this` refers to the execution context. 1. **Default**: global/undefined. 2. **Implicit**: the object before the dot. 3. **Explicit**: via `call`, `apply`, or `bind`. 4. **New**: the newly created instance. `bind()` returns a new function with a fixed `this`; it cannot be re-bound.

**JS8** — `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` runs a callback after an object is GC'd. `WeakMap` keys must be objects so that if the object is no longer referenced elsewhere, the entry can be GC'd.

**JS9** — V8 uses **Hidden Classes** (shapes) to track object properties. **Inline Caching** optimizes property access by remembering where they are. **Deoptimization** occurs when an object's shape changes (e.g., adding properties later), forcing V8 to fall back to slower lookups.

**JS10** — Tree-shaking removes unused code. ESM is static, allowing tools to trace imports/exports at build time. CommonJS is dynamic (`require` can be inside an `if`), making it impossible to determine used code without running it, thus preventing effective shaking.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable hasn't been assigned. `==` performs type coercion; `===` checks both value and type. `??` (nullish coalescing) returns the right side if the left is `null` or `undefined`. `?.` (optional chaining) stops evaluation if the reference is `null/undefined`.

**JS12** — `map()` transforms every element; `filter()` selects elements based on a predicate; `reduce()` accumulates elements into a single value. `reduce` uses an initial value to prevent errors on empty arrays. `flatMap()` maps and then flattens the result by one level.

**JS13** — Template literals use backticks (`` ` ``) for interpolation. **Tagged templates** are functions that parse the template literal. Example: `sql`SELECT * FROM users`` where `sql` is a function receiving the string parts and interpolated values.

**JS14** — Destructuring extracts values from arrays/objects. `const {a, b: c} = obj` renames `b` to `c`. `const [first, ...rest] = arr` uses the **rest operator** to collect remaining elements into a new array.

**JS15** — `for...in` iterates over enumerable *keys* (including inherited ones). `for...of` iterates over *values* of an iterable. Avoid `for...in` on arrays because it iterates indices as strings and includes non-index properties.

**JS16** — **Generics** allow reusable components. **Constraints**: `T extends string`. **Conditional Types**: `T extends string ? A : B`. **Infer**: `type GetType<T> = T extends (infer U)[] ? U : never`.

**JS17** — CommonJS uses `require/module.exports` (synchronous, Node-centric). ESM uses `import/export` (static, browser/Node). Node handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM.

**JS18** — TS is structural (shapes matter, not names). **Excess property checks** apply to object literals. `extends` is for subtyping; `satisfies` checks a type without changing the inferred type. **Variance**: `in` (contravariant) and `out` (covariant) define how sub/super types relate in complex structures.

**JS19** — `Proxy` intercepts operations (get, set, etc.); `Reflect` provides the default logic for those operations. Example: A Proxy can validate that a `set` operation only accepts numbers.

**JS20** — `SharedArrayBuffer` provides raw shared memory. `Atomics` provides atomic operations (add, load, store) to prevent race conditions. `Atomics.wait/notify` allows threads to sleep/wake based on memory changes.

## Bash (20 questions)

**B1** — `$@` represents all arguments as separate words. `$*` represents all arguments as a single string. `"$@"` preserves argument boundaries; `"$*"` joins them into one string.

**B2** — `-e`: exit on error; `-u`: error on unset variables; `-o pipefail`: return non-zero if any command in a pipeline fails.

**B3** — `$(command)` is command substitution (executes and returns output). `$((expression))` is arithmetic expansion. `expr` is an external utility for math.

**B4** — `<(command)` is process substitution; it creates a temporary file descriptor that acts like a file. Use it with `diff <(cmd1) <(cmd2)` to compare outputs of two commands.

**B5** — Use `while IFS= read -r file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous because it splits filenames containing spaces into multiple items.

**B6** — `<<EOF` is a here-doc (multi-line string). `<<<` is a here-string (single string). `<<-EOF` strips leading tabs from the lines.

**B7** — `cmd > file 2>&1`: stdout goes to file, stderr follows stdout to file. `cmd 2>&1 > file`: stderr goes to where stdout *was* (usually terminal), then stdout goes to file. `&> file`: both stdout and stderr go to file.

**B8** — Use `mkdir lockdir` because `mkdir` is an atomic operation at the OS level, preventing race conditions. Use `trap 'rmdir lockdir' EXIT INT TERM` to ensure cleanup.

**B9** — `'...'` is literal; `"..."` allows interpolation and globbing; no quotes allow word splitting and globbing. `echo "$VAR"` vs `echo $VAR`.

**B10** — `[ -f file ]` (file), `[ -d dir ]` (directory), `[ -r file ]` (readable). `[[ ]]` is a bash keyword that is more robust, handles empty strings better, and supports regex.

**B11** — `$?`: exit code of last command; `$$`: PID of current shell; `$!`: PID of last background job; `$#`: number of arguments.

**B12** — `foo() { ... }` is standard. `function foo { ... }` is a bashism. Return values are via `return n` (exit status 0-255) or `echo` (output).

**B13** — `PATH` is a colon-separated list of directories. Bash searches them in order. `builtin` is part of the shell (e.g., `cd`); `external` is a file in PATH (e.g., `ls`). Use `type -a cmd` to check.

**B14** — `trap 'command' SIGNAL` executes a command on a signal. Order depends on signal arrival, but `EXIT` is always last.

**B15** — `xargs` converts stdin to arguments. `xargs -0` with `find -print0` handles special characters. `xargs -P N` runs N processes in parallel.

**B16** — `arr=(1 2)`; `arr+=("3")`; `${#arr[@]}` (length); `for i in "${!arr[@]}"` (indices). Associative: `declare -A map`; `map[key]=val`.

**B17** — `(...)` is a subshell (new process/scope). `{ ...; }` is a group command (current shell/scope). Pipes create subshells, so variables changed inside a `while` loop in a pipe are lost.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (polite kill), `SIGHUP` (terminal closed), `SIGKILL` (immediate/unblockable). Use `trap` to catch `TERM` and kill child processes before exiting.

**B19** — `split -l 1000 log.txt tmp_` -> `ls tmp_* | xargs -P 4 my_func`. Trade-off: higher CPU/IO usage vs speed. Error propagation requires checking exit codes of all parallel jobs.

**B20** — `exec` replaces the current shell with a new process. `exec 3>file` opens FD 3. `exec 3>&-` closes it. A coprocess `coproc mycmd` allows bidirectional communication with a background process.

## PowerShell (20 questions)

**PS1** — `Write-Output` sends objects to the pipeline; `Write-Host` writes directly to the console. `Write-Output` is essential for script composability.

**PS2** — The pipeline passes objects one by one. `ForEach-Object` is a pipeline cmdlet (streaming/low memory); `foreach` is a language statement (loads entire collection into memory).

**PS3** — `[PSCustomObject]` is an ordered collection of properties; `[hashtable]` is an unordered key-value pair. Convert: `[PSCustomObject]@{...}`.

**PS4** — Terminating errors stop execution; non-terminating errors continue. `-ErrorAction` and `$ErrorActionPreference` determine if errors become terminating. `try/catch` only catches terminating errors.

**PS5** — Splatting: `@params = @{a=1; b=2}; Cmdlet @params`. It's cleaner than passing a single hashtable as one argument.

**PS6** — `Invoke-Command` is for remote execution (one-to-many); `Enter-PSSession` is interactive. Uses WinRM (WS-Man) or SSH.

**PS7** — `Get-Items` returns `[object[]]`. If 0 items, it might return `$null`. Correct pattern: `[array]$x = Get-Items`. `GetType().Name` would be `Object[]`.

**PS8** — `[scriptblock]` is a block of code. Double-hop: a remote session cannot use the first session's credentials to access a third machine. Solve with CredSSP or `ArgumentList`.

**PS9** — `@()` is an empty array. `[array]` is the type. Indexing `$null` returns `$null`.

**PS10** — `-eq` (equality), `-like` (wildcard), `-match` (regex). `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection. `-ceq` is case-sensitive.

**PS11** — `.psm1` (script module), `.psd1` (manifest), Binary (DLL). `Import-Module` loads them into the session.

**PS12** — `"..."` is interpolated; `'...'` is literal. Use `$var` or `$(expr)` inside `"..."`. Here-strings: `@""@`.

**PS13** — `Get-Member` shows members. `Select-Object` picks properties; `Where-Object` filters objects.

**PS14** — PS classes are simpler than C# (no multiple inheritance/interfaces). Use classes for data structures; use functions for logic.

**PS15** — `[CmdletBinding()]` makes a function behave like a cmdlet (adds `-Verbose`, etc.). `Begin/Process/End` allows streaming data through the pipeline.

**PS16** — Providers map data (Registry, FileSystem) to a drive-like interface. `cd Registry::HKEY_LOCAL_MACHINE`.

**PS17** — `[runspace]` is a single thread. `[runspacepool]` manages multiple. `ForEach-Object -Parallel` (v7+) uses a runspace pool internally for efficiency.

**PS18** — `PSScriptAnalyzer` is a static analysis tool. Rules can be suppressed with `# PSScriptAnalyzer Ignore`. It integrates into CI/CD via `Invoke-PSScriptAnalyzer`.

**PS19** — `$using:var` passes a local variable into a remote/parallel scope. Serialization: objects are converted to CLIXML, which can strip methods and complex types.

**PS20** — DSC uses **Configurations** (desired state) and **Resources** (implementation). The **LCM** (Local Configuration Manager) enforces the state. Modern replacement: Terraform/Ansible.
