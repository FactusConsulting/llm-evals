## Go

**G1** — An **array** has a fixed size, and its size is part of its type. A **slice** is a descriptor (a header containing a pointer to an underlying array, a length, and a capacity). When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array, copies the old elements, and returns a new slice pointing to this new array.

**G2** — `var x int` declares a variable with its zero value (0). `x := 0` is short variable declaration, which declares and initializes simultaneously. You **cannot** use `:=` at the package level (outside of a function).

**G3** — A **goroutine** is a lightweight, user-space thread managed by the Go runtime. An **OS thread** is managed by the kernel and is much heavier. The **GMP model** consists of **G** (Goroutines), **M** (Machine/OS Threads), and **P** (Processors/Contexts). The scheduler multiplexes many Gs onto a smaller number of Ms using Ps to ensure efficient CPU utilization and work-stealing.

**G4** — Channels are primitives for communication between goroutines. An **unbuffered channel** requires both sender and receiver to be ready (synchronous). A **buffered channel** allows sending until the buffer is full (asynchronous up to capacity). Sending to a full buffered channel blocks the sender until space is available.

**G5** — The `context` package handles cancellation, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
// If the request takes > 2s, it is automatically canceled.
```

**G6** — Go uses **implicit satisfaction**: if a type implements all methods of an interface, it satisfies it (no `implements` keyword). `interface{}` (or `any`) can hold any value, making it powerful for generic programming but dangerous because it bypasses type safety, requiring type assertions that can panic.

**G7** — This is unsafe due to **memory visibility** issues. The compiler or CPU might reorder instructions, or the change to `ready` might not be visible to the loop in another thread. The correct alternatives are using `sync/atomic` (e.g., `atomic.Bool`) or a `sync.Mutex` to create a "happens-before" relationship.

**G8** — `sync.Mutex` is exclusive (one holder). `sync.RWMutex` allows multiple concurrent readers OR one writer. `sync.Map` is optimized for cases where keys are stable and reads significantly outnumber writes. A regular map + `Mutex` is generally faster for high-write workloads or when the key set changes frequently.

**G9** — `go.mod` defines the module path and dependencies. `go.sum` contains cryptographic checksums of dependencies to ensure integrity. `go mod tidy` removes unused modules and adds missing ones. **MVS (Minimum Version Selection)** selects the highest version of a module that satisfies all requirements in the dependency graph.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common gotcha is using `defer` inside a loop; the deferred calls won't execute until the *outer* function returns, potentially causing resource exhaustion.

**G11** — A **pointer** stores the memory address of a value. The zero value of a pointer is `nil`. You create a pointer to a struct literal using the address-of operator: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs after package-level variables are initialized but before `main()`. A package can have multiple `init()` functions, and they execute in the order they appear in the source code.

**G13** — `make` initializes built-in types (slice, map, channel) and returns an initialized value. `new` allocates zeroed memory for any type and returns a pointer to it.

**G14** — Errors are values implementing the `error` interface (a single `Error() string` method). The idiomatic pattern is `if err != nil`. `errors.Is` checks if an error matches a specific target (including wrapped errors), while `errors.As` checks if an error can be assigned to a specific type.

**G15** — **Map**: `nil` (but writing to nil map panics). **Slice**: `nil`. **Channel**: `nil`. **Struct**: All fields set to their respective zero values.

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one is a write. The `-race` flag uses instrumentation to detect these at runtime.
*Fix:* Use `sync.Mutex` to wrap the critical section or use a channel to serialize access.

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, it blocks until one case can proceed. If multiple are ready, one is chosen **pseudo-randomly**. A timeout is implemented via `case <-time.After(d):`.

**G18** — **Escape analysis** determines if a variable can stay on the stack or must "escape" to the heap. Variables escape if they are returned as pointers, are too large for the stack, or are passed to interfaces. Inspect via `go build -gcflags="-m"`. Heap allocation is more expensive due to GC pressure.

**G19** — `reflect.Type` describes the type metadata; `reflect.Value` holds the actual data. Reflection is slow because it involves runtime type checking and prevents many compiler optimizations. Use it for generic libraries; use **code generation** for performance-critical paths.

**G20** — `//go:embed` includes file content into the binary at compile time. It supports single files, directories, or multiple files. It integrates with `embed.FS`, which implements `io/fs.FS`. Limitations include files being restricted to the module directory and the inability to use variables for filenames.

## Rust

**R1** — Ownership: 1. Each value has a single owner. 2. When the owner goes out of scope, the value is dropped. 3. Ownership can be moved.

**R2** — `String` is an owned, heap-allocated buffer. `&str` is an immutable slice (a view). Use `&str` in function signatures to allow the function to accept both `String` and `&str`.

**R3** — Borrowing allows accessing data without taking ownership. Rules: You can have either **any number of immutable references** (`&T`) OR **exactly one mutable reference** (`&mut T`) at any given time. You cannot have both simultaneously.

**R4** — `Result<T, E>` represents success (`Ok`) or failure (`Err`). `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>`: Single ownership on the heap. `Rc<T>`: Reference counted (non-atomic, single-threaded). `Arc<T>`: Atomic reference counted (thread-safe).

**R6** — **Traits** define shared behavior. Unlike Go interfaces (implicit), Rust traits are explicit. `dyn Trait` uses **dynamic dispatch** (vtable lookup), while `T: Trait` uses **static dispatch** (monomorphization/generics).

**R7** — It fails because the compiler cannot guarantee how long the returned reference lives. Fix: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8** — `Send` means ownership can be transferred to another thread. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send` because its reference count is not atomic, leading to data races. `Arc<T>` uses atomic operations, making it `Send` and `Sync`.

**R9** — `async` transforms a function into a state machine that implements the `Future` trait. `await` polls the future. Unlike Go's goroutines (managed by a runtime scheduler), Rust's futures are "lazy" and require an **executor** (like Tokio) to drive them to completion.

**R10** — `unsafe` allows: 1. Dereferencing raw pointers. 2. Calling FFI functions. 3. Mutating static variables. It is justified when interfacing with hardware, C libraries, or implementing low-level data structures.

**R11** — `match` is a powerful pattern matching tool that must be **exhaustive** (all possible patterns must be covered). `if let` is a concise way to handle a single pattern, ignoring others.

**R12** — `Vec<T>` is a growable, heap-allocated array. `[T; N]` is a fixed-size array, usually on the stack. When a `Vec` exceeds capacity, it allocates a larger block of memory and moves the elements.

**R13** — Rust enums are **sum types** (can hold data per variant). `Option<T>` is an enum (`Some(T)` or `None`), which provides type-safe null handling, eliminating null-pointer exceptions.

**R14** — `impl` defines methods for a type. `&self` borrows immutably; `&mut self` borrows mutably; `self` consumes the value (moves ownership). **Associated functions** (like `String::new()`) do not take `self` and are called via the type.

**R15** — `derive` is a procedural macro that automatically implements traits. Examples: `Debug` (formatting), `Clone` (deep copy), `PartialEq` (equality). You cannot derive a trait if its implementation requires custom logic or if its bounds aren't met.

**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that can hold either borrowed or owned data. It avoids allocation if the data is only read, but clones the data only when a mutation is attempted.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. The 2018 edition simplified the module system by making paths relative to the crate root by default, reducing the need for `extern crate`.

**R18** — `Pin<T>` ensures that the data it points to cannot be moved in memory. This is critical for **self-referential structs** (common in `async` state machines). `Unpin` is a marker trait for types that are safe to move even after being pinned.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching. **Procedural macros** are compiler plugins (derive, attribute, or function-like). **Hygiene** ensures that macro-generated identifiers do not accidentally collide with local variables.

**R20** — Zero-cost abstractions mean you don't pay for what you don't use. **Iterators** compile down to efficient loops; **Generics** use monomorphization (generating specific code for each type); **Trait static dispatch** allows the compiler to inline calls, making them as fast as manual C code.
