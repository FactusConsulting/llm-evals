## Kubernetes

**K1** — A **Deployment** manages stateless applications where pods are interchangeable. A **StatefulSet** manages stateful applications, providing stable, unique network identifiers (hostnames) and persistent storage bindings that persist across pod rescheduling.

**K2** — A ClusterIP service uses a virtual IP (VIP). Traffic hitting the VIP is intercepted by `kube-proxy` (via iptables or IPVS rules) on the node, which performs Destination Network Address Translation (DNAT) to route the packet to a specific pod IP.

**K3** — A **PersistentVolume (PV)** is the actual storage resource (e.g., an EBS volume). A **PersistentVolumeClaim (PVC)** is a request for storage by a user. A **StorageClass (SC)** is a template that enables dynamic provisioning. The relationship: A user creates a PVC referencing an SC, and the SC automatically provisions a PV to satisfy that PVC.

**K4** — 1. `kubectl logs <pod>` to check application errors. 2. `kubectl describe pod <pod>` to check for OOMKilled or failed probes. 3. Check environment variables and ConfigMaps/Secrets. 4. Check node resources (is the node out of disk/memory?).

**K5** — CoreDNS provides service discovery via DNS within the cluster. If CoreDNS pods are down, pods cannot resolve service names (e.g., `my-svc.namespace.svc.cluster.local`), causing internal communication to fail.

**K6** — The scheduler uses two phases: **Filtering** (Predicates) removes nodes that don't meet requirements (e.g., insufficient CPU). **Scoring** (Priorities) ranks remaining nodes. Factors include: **Resource availability** (CPU/RAM), **Node Affinity/Taints**, and **Data Locality**.

**K7** — **Yes**, it will be scheduled. The node has 500Mi available (4GB - 3.5GB), which is greater than the 256Mi request. However, if it uses 600Mi at runtime, it exceeds its `limit.memory` (512Mi) and will be **OOMKilled**.

**K8** — External LB $\rightarrow$ Ingress Controller (e.g., NGINX) $\rightarrow$ Service (ClusterIP) $\rightarrow$ Endpoints (list of Pod IPs) $\rightarrow$ `kube-proxy` (iptables/IPVS rules) $\rightarrow$ Application Pod.

**K9** — A **NetworkPolicy** defines L3/L4 traffic rules between pods. By default, if no policy exists, all traffic is allowed. Once a policy is applied to a pod, that pod becomes "isolated," and only traffic explicitly allowed by the policy is permitted.

**K10** — **RollingUpdate** replaces old pods with new ones gradually to ensure zero downtime. **Recreate** kills all old pods before starting new ones. Choose **Recreate** when an application cannot run two versions simultaneously (e.g., a database with a single-writer requirement).

**K11** — A **Namespace** provides logical isolation within a cluster. Default namespaces include `default`, `kube-system`, and `kube-public`.

**K12** — `kubectl describe pod` provides deep inspection. Unlike `get`, it shows: **Events** (recent lifecycle changes), **Container Status/Reason** (e.g., CrashLoopBackOff), and **Volume/Node assignments**.

**K13** — A **ConfigMap** stores non-confidential configuration data. Consumption methods: 1. As **Environment Variables** in the container. 2. As **Files/Volumes** mounted into the container.

**K14** — **ClusterIP**: Internal access only. **NodePort**: Exposes service on a static port on every Node's IP. **LoadBalancer**: Provisions an external cloud load balancer to route traffic to the service.

**K15** — A **DaemonSet** ensures that a copy of a specific pod runs on every (or selected) node. Use it for infrastructure tasks like log collectors (Fluentd) or monitoring agents (Prometheus Node Exporter).

**K16** — **Taints** are applied to nodes to repel pods; **Tolerations** are applied to pods to allow them to stay on tainted nodes. **Node Affinity** attracts pods to specific nodes. *Use case:* Taint a node with a GPU for specialized workloads; use affinity to ensure a high-performance pod lands on that specific node.

**K17** — An **Operator** is a custom controller that uses **Custom Resource Definitions (CRDs)** to manage complex, application-specific logic (e.g., managing a database cluster's backups/scaling). Standard controllers manage generic resources; Operators manage the entire lifecycle of a specific software product.

**K18** — etcd uses the **Raft** consensus algorithm. If quorum (majority) is lost, the cluster becomes read-only or fails. To recover from losing 2/3 nodes, you must restore from a known good snapshot onto a new 3-node cluster.

**K19** — **Role**: Permissions in a namespace. **ClusterRole**: Permissions cluster-wide. **RoleBinding**: Grants Role to a user in a namespace. **ClusterRoleBinding**: Grants ClusterRole to a user cluster-wide.
```yaml
# RBAC Manifest
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: my-namespace
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: my-namespace
subjects:
- kind: User
  name: developer-user
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — With `ndots:5`, a query for `google.com` triggers searches for `google.com.namespace.svc.cluster.local`, then `google.com.svc.cluster.local`, etc., before trying the actual domain. Fix: Use `dnsConfig` in the pod spec to set `ndots: 1` or use a fully qualified domain name (FQDN) with a trailing dot (e.g., `google.com.`).

## Development

**D1** — **Merge** combines histories by creating a new merge commit. **Rebase** rewrites history by moving commits to a new base for a linear timeline. Avoid rebasing on **public/shared branches** as it breaks history for others.

**D2** — **TCP** is connection-oriented and reliable (HTTP, SSH). **UDP** is connectionless and faster (DNS, VoIP).

**D3** — A **race condition** occurs when two threads access shared data simultaneously, and the outcome depends on the timing of execution. *Example:* Two threads incrementing `counter++` without a lock; both read `5`, both increment to `6`, and the final value is `6` instead of `7`.

**D4** — **Symmetric**: Same key for encryption/decryption (AES). **Asymmetric**: Public/Private key pair (RSA). In **TLS**, asymmetric encryption is used during the handshake to securely exchange a symmetric key, which is then used for the actual data transfer.

**D5** — A **layer** is a read-only filesystem change in an image. **Layer caching** means Docker reuses layers from previous builds. Best practice: Order Dockerfile commands from "least frequently changed" to "most frequently changed" to maximize cache hits.

**D6** — 1. Check application logs (is the app crashing?). 2. Check service health/readiness probes. 3. Check upstream/backend dependencies. 4. Check Load Balancer/Ingress capacity/errors.

**D7** — **CAP**: Consistency, Availability, Partition Tolerance. **CP (Consistency/Partition)**: Etcd/Zookeeper (prioritizes data accuracy over uptime). **AP (Availability/Partition)**: Cassandra (prioritizes uptime over immediate consistency).

**D8** — **Horizontal**: Adding more instances (nodes/pods). **Vertical**: Adding more resources (CPU/RAM) to an existing instance. Patterns: Statelessness and Load Balancing enable horizontal scaling.

**D9** — An **environment variable** is a dynamic value used by processes. To persist on Linux, add `export VAR=value` to your `~/.bashrc` or `~/.zshrc` file.

**D10** — **JSON** is strict, uses braces/commas, and is machine-friendly. **YAML** is human-readable, uses indentation, and supports comments. *Advantage JSON:* Strictness/Parsing speed. *Advantage YAML:* Readability.

**D11** — **REST API**: An interface using HTTP. **GET** (Retrieve), **POST** (Create), **PUT** (Update/Replace), **DELETE** (Remove).

**D12** — **Version pinning** is specifying an exact version (e.g., `v1.2.3`). It is vital for **reproducible builds**, ensuring the same code runs in Dev, Staging, and Prod without unexpected breaking changes from dependency updates.

**D13** — **Compiled**: Converted to machine code before execution (C++, Rust). **Interpreted**: Executed line-by-line by a runtime (Python, JavaScript).

**D14** — A **Reverse Proxy** sits in front of servers to protect them (Nginx, HAProxy). A **Forward Proxy** sits in front of clients to hide them (Squid). *Nginx use case:* SSL termination. *Squid use case:* Web filtering in an office.

**D15** — A **deadlock** is a state where processes are stuck waiting for each other. **Coffman conditions**: 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual Consistency** means data will be consistent across all nodes given enough time without updates. **Cassandra** uses tunable consistency: `ONE` (fastest, least consistent), `QUORUM` (majority), or `ALL` (slowest, most consistent).

**D17** — **mTLS** requires both client and server to present certificates. **Handshake**: 1. Client Hello $\rightarrow$ 2. Server sends Cert $\rightarrow$ 3. Client verifies Server $\rightarrow$ 4. Client sends its own Cert $\rightarrow$ 5. Server verifies Client $\rightarrow$ 6. Session keys established. Commonly used in **Service Meshes** (Istio/Linkerd).

**D18** — A hash table maps keys to indices via a hash function. **Chaining** uses linked lists at each index to handle collisions. **Open Addressing** searches for the next empty slot (probing). **Complexity**: Avg: $O(1)$ for all; Worst: $O(n)$ for all.

**D19** — A **Circuit Breaker** prevents a failing service from dragging down the whole system. **Closed**: Normal operation. **Open**: Failures detected; requests fail immediately without calling the service. **Half-Open**: Periodically allows a few requests to see if the service recovered. It works with **exponential backoff** to prevent overwhelming a recovering service.

**D20** — **Optimistic**: Assumes no conflict; checks version/timestamp at commit (MVCC). **Pessimistic**: Locks the resource immediately (e.g., `SELECT FOR UPDATE`). Use **Optimistic** for high-concurrency/low-contention; use **Pessimistic** for high-contention/critical data integrity.
