## Kubernetes (20 questions)

**K1** — **Deployment** manages stateless applications with interchangeable replicas. **StatefulSet** manages stateful applications, providing stable, unique network identifiers (e.g., `pod-0`, `pod-1`) and persistent storage that persists across rescheduling.

**K2** A **Service of type ClusterIP** creates a virtual IP. **kube-proxy** (running on every node) manages `iptables` or `IPVS` rules that intercept traffic to that ClusterIP and redirect it to the actual IP addresses of the backend Pods (Endpoints).

**K3** **PersistentVolume (PV)** is a piece of storage in the cluster. **PersistentVolumeClaim (PVC)** is a user's request for storage. **StorageClass** is a template that allows for dynamic provisioning. A user creates a **PVC** referencing a **StorageClass**, which automatically creates a **PV**.

**K4** 1. `kubectl logs <pod>` to check application errors. 2. `kubectl describe pod <pod>` to check for exit codes or OOMKilled. 3. Check `Liveness/Readiness` probe configurations. 4. Check environment variables and ConfigMaps/Secrets for missing required data.

**K5** **CoreDNS** provides service discovery via DNS names. If CoreDNS pods are down, internal service-to-service communication via DNS names will fail, and external resolution will also break.

**K6** The scheduler follows two phases: **Filtering** (predicates) to find nodes that meet requirements (e.g., enough CPU/RAM) and **Scoring** (priorities) to rank remaining nodes. Factors include: **Resource availability**, **Node Affinity/Anti-affinity**, and **Taints/Tolerations**.

**K7** **Yes**, it will be scheduled because $3.5\text{GB} + 256\text{Mi} < 4\text{GB}$. However, if it uses $600\text{Mi}$ at runtime, it exceeds its $512\text{Mi}$ limit and will be **OOMKilled** (Out of Memory Killed).

**K8** External Request $\rightarrow$ **External Load Balancer** $\rightarrow$ **Ingress Controller** (e.g., NGINX) $\rightarrow$ **Service** (via Endpoints) $\rightarrow$ **kube-proxy** (routing via iptables/IPVS) $\rightarrow$ **Application Pod**.

**K9** A **NetworkPolicy** is a firewall rule for Pods. By default, all Pods can talk to all Pods. Once a NetworkPolicy is applied to a Pod, it enters "default deny" mode for anything not explicitly allowed by that policy.

**K10** **RollingUpdate** replaces old pods with new ones gradually to ensure zero downtime. **Recreate** kills all old pods before starting new ones. Choose **Recreate** when the application cannot run two versions simultaneously (e.g., due to database schema conflicts or singleton requirements).

**K11** A **Namespace** provides logical isolation within a cluster. Default namespaces: `default`, `kube-system`, `kube-public`.

**K12** `kubectl describe pod` provides deep inspection. Unlike `get`, it shows: **Events** (lifecycle history), **Container Status/Exit Codes**, and **Volume Mounts/ConfigMaps**.

**K13** A **ConfigMap** stores non-confidential data in key-value pairs. Consumption methods: 1. As **Environment Variables**. 2. As **Files in a Volume** mounted into the pod.

**K14** **ClusterIP**: Internal access only. **NodePort**: Exposes the service on a static port on every Node's IP. **LoadBalancer**: Provisions a cloud provider's external load balancer to route to the service.

**K15** A **DaemonSet** ensures exactly one copy of a Pod runs on every node. Use it for **system-level services** like logging agents (Fluentd) or monitoring (Prometheus Node Exporter).

**K16** **Taints** are applied to nodes to repel pods. **Tolerations** are applied to pods to allow them to stay on tainted nodes. **Node Affinity** is used to attract pods to specific nodes. *Use case:* Taint a node with a GPU to keep general pods off; use Affinity to ensure a ML pod lands on that GPU node.

**K17** An **Operator** is a custom controller that uses **Custom Resource Definitions (CRDs)** to manage complex, domain-specific applications. Unlike standard controllers (which manage generic resources like Pods), Operators encode human operational knowledge (e.g., how to back up a specific database).

**K18** etcd uses the **Raft** consensus algorithm. If quorum is lost, the cluster becomes read-only or fails. To recover from losing 2/3 nodes, you must restore from a known good backup to a new 3-node etcd cluster to re-establish quorum.

**K19** **Role**: Permissions in a namespace. **ClusterRole**: Permissions cluster-wide. **RoleBinding**: Grants Role to a user in a namespace. **ClusterRoleBinding**: Grants ClusterRole to a user cluster-wide.

```yaml
# Role
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: dev-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
# RoleBinding
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: dev-ns
subjects:
- kind: User
  name: developer-user
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** With `ndots:5`, a lookup for `google.com` triggers searches for `google.com.default.svc.cluster.local`, etc., causing latency. Fix via `dnsConfig`:
```yaml
spec:
  dnsConfig:
    options:
      - name: ndots
        value: "1"
```

## Development (20 questions)

**D1** **Merge** combines histories by creating a new commit. **Rebase** rewrites history by moving commits to a new base. Avoid rebasing **public/shared branches** as it breaks history for others.

**D2** **TCP** is connection-oriented and reliable (HTTP, SSH). **UDP** is connectionless and fast (DNS, VoIP).

**D3** A **race condition** occurs when two threads access shared data simultaneously, and the outcome depends on the timing. *Example:* Two threads incrementing `counter++` at the same time; both read `5`, both write `6`, but the result should have been `7`.

**D4** **Symmetric**: One key for both encryption/decryption. **Asymmetric**: Public key encrypts, private key decrypts. In **TLS**, asymmetric is used for the initial handshake/key exchange, and symmetric is used for the actual data transfer.

**D5** A **layer** is a read-only filesystem diff. **Layer caching** means Docker reuses layers from previous builds. Best practice: Put frequently changing instructions (like `COPY . .`) at the end of the Dockerfile to maximize cache hits.

**D6** 1. Check **Service/Pod health** (is the app actually running?). 2. Check **Load Balancer/Ingress** (is routing correct?). 3. Check **Upstream/Dependencies** (is the DB down?). 4. Check **Resource exhaustion** (is the app OOMing or CPU throttled?).

**D7** **CAP**: Consistency, Availability, Partition Tolerance. You can only have two. **CP (Zookeeper)**: Prioritizes consistency; if a partition occurs, it stops accepting writes. **AP (Cassandra)**: Prioritizes availability; it accepts writes even if nodes can't talk, resolving conflicts later.

**D8** **Horizontal**: Adding more instances (scaling out). **Vertical**: Adding more CPU/RAM to one instance (scaling up). Enabled by **statelessness** and **load balancing**.

**D9** An **environment variable** is a dynamic value used by processes. To persist in Linux, add `export KEY=VALUE` to your `~/.bashrc` or `~/.zshrc`.

**D10** **JSON** is data-interchange focused (fast parsing). **YAML** is human-readable/configuration focused. *Advantage JSON:* Machine efficiency. *Advantage YAML:* Readability/Comments.

**D11** **GET**: Retrieve data. **POST**: Create data. **PUT**: Replace/Update data. **DELETE**: Remove data.

**D12** **Version pinning** (e.g., `library==1.2.3`) ensures that every build uses the exact same code, preventing "it worked yesterday" bugs caused by breaking changes in dependencies.

**D13** **Compiled**: Converted to machine code before execution (C++, Go). **Interpreted**: Executed line-by-line by an interpreter (Python, JavaScript).

**D14** **Reverse Proxy**: Sits in front of servers to protect them (e.g., Nginx). **Forward Proxy**: Sits in front of clients to hide them (e.g., Squid).

**D15** 1. **Mutual Exclusion**, 2. **Hold and Wait**, 3. **No Preemption**, 4. **Circular Wait**.

**D16** **Eventual consistency** means data will eventually be the same across all nodes. **Cassandra** uses tunable consistency: `ONE` (fastest), `QUORUM` (majority), or `ALL` (slowest/strongest).

**D17** **mTLS** requires both client and server to present certificates. **Handshake**: Client sends Hello $\rightarrow$ Server sends Cert $\rightarrow$ Client verifies $\rightarrow$ Client sends its Cert $\rightarrow$ Server verifies $\rightarrow$ Key exchange. Used in **Service Meshes (Istio/Linkerd)**.

**D18** A hash function maps a key to an index. **Collision resolution**: **Chaining** (linked list at index) or **Open Addressing** (probing next available slot). **Complexity**: Avg $O(1)$, Worst $O(n)$.

**D19** **Circuit Breaker** prevents cascading failures. **Closed**: Requests pass. **Open**: Requests fail immediately (protecting the service). **Half-Open**: Allows limited test requests to see if the service recovered. It works with **retries** and **exponential backoff** to avoid hammering a struggling service.

**D20** **Optimistic**: Assumes no conflict; checks version at commit (e.g., `WHERE version=1`). **Pessimistic**: Locks the resource (e.g., `SELECT FOR UPDATE`). Use **Optimistic** for high concurrency/low contention; use **Pessimistic** for high contention/critical data.
