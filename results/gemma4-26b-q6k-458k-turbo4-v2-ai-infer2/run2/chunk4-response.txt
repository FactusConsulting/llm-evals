## Go

**G1** — An **array** has a fixed size defined at compile time. A **slice** is a descriptor (header) containing a pointer to an underlying array, a length, and a capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array (usually doubling in size), copies the old elements, and returns a new slice descriptor pointing to the new array.

**G2** — `var x int` declares a variable and initializes it to its zero value (`0`). `x := 0` is short-hand declaration and initialization. You **cannot** use `:=` at the package level (outside of functions); you must use `var` there.

**G3** — A **goroutine** is a lightweight user-space thread managed by the Go runtime. Unlike an **OS thread**, which has a large fixed stack (e.g., 1-2MB), goroutines start with a very small stack (approx 2KB) that grows/shrinks dynamically. The **GMP model** consists of **G** (Goroutines), **M** (Machine/OS Threads), and **P** (Processors/Contexts). The scheduler maps $M$ goroutines onto $P$ processors, which are then scheduled onto $M$ OS threads.

**G4** — **Channels** are pipes used for communication between goroutines. An **unbuffered channel** is synchronous; the sender blocks until a receiver is ready. A **buffered channel** allows sending up to $N$ values without blocking. If you send to a **full buffered channel**, the sender blocks until a receiver removes a value.

**G5** — The `context` package handles cancellation signals, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
// If 100ms passes, the request is canceled.
```

**G6** — Go uses **implicit satisfaction**: if a type implements all methods of an interface, it satisfies that interface automatically (no `implements` keyword). This differs from Java/C# which require explicit declaration. `interface{}` (or `any`) can hold any value. It is **powerful** because it allows generic-like behavior, but **dangerous** because it bypasses compile-time type safety, requiring type assertions.

**G7** — This is unsafe due to the lack of a "happens-before" relationship. The compiler or CPU might reorder instructions, making `ready = true` visible before `data = "hello"`. Correct alternatives: use `sync.Mutex` or `atomic.Value`/`atomic.Bool` to ensure memory visibility and ordering.

**G8** — `sync.Mutex` is an exclusive lock (one owner). `sync.RWMutex` allows multiple concurrent readers OR one single writer. Use `sync.Map` for scenarios with high concurrency, stable keys, and frequent reads/disjoint writes. A regular `map` + `sync.Mutex` is generally faster for high-frequency writes to the same keys or when the map is small.

**G9** — `go.mod` defines the module path and specific dependency versions. `go.sum` contains cryptographic checksums to ensure dependency integrity. `go mod tidy` adds missing modules and removes unused ones. **MVS (Minimum Version Selection)** selects the lowest version of a module that satisfies all requirements in the graph.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common gotcha: using a loop variable in a deferred closure (the closure captures the variable by reference, so all defers might see the final value of the loop).

**G11** — A **pointer** stores the memory address of a value. The zero value of a pointer is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs after package-level variables are initialized but before `main()`. A package can have multiple `init()` functions, and they execute in the order they appear in the source code (and after dependencies).

**G13** — `make` allocates and **initializes** (zeroes) memory for slices, maps, and channels, returning an initialized descriptor. `new` allocates zeroed memory for any type and returns a **pointer** to it.

**G14** — Errors are values implementing the `error` interface (a `Error() string` method). Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error wraps a specific value; `errors.As` checks if an error can be assigned to a specific type.

**G15** — 
- **Map**: `nil`
- **Slice**: `nil`
- **Channel**: `nil`
- **Struct**: Zero-initialized (e.g., `0`, `""`, `false`)

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one is a write. The `-race` flag uses a runtime detector to find these.
*Fix:*
```go
var mu sync.Mutex
mu.Lock()
count++
mu.Unlock()
// OR use a channel to serialize access.
```

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, it blocks until one case can proceed. If multiple are ready, one is chosen **pseudo-randomly**. A timeout is implemented via `case <-time.After(d):`.

**G18** — **Escape analysis** determines if a variable can stay on the stack or must move to the heap. Variables escape to the heap if: they are returned as pointers, are too large for the stack, or are passed to an interface. Inspect via `go build -gcflags="-m"`. Heap allocation is more expensive due to GC pressure.

**G19** — `reflect.Type` describes the type metadata; `reflect.Value` holds the actual data. Reflection is slow because it happens at runtime. Use reflection for generic libraries (like JSON encoders), but prefer **code generation** (like `easyjson`) for performance-critical paths.

**G20** — `//go:embed` instructs the compiler to include file contents in the binary. It supports single files, directories, or patterns. It integrates with `io/fs.FS`. Limitations: files must be in the same module and cannot be outside the module root.

## Rust

**R1** — **Ownership** is Rust's memory management system. Rules: 1. Each value has a single owner. 2. When the owner goes out of scope, the value is dropped. 3. Ownership can be moved (transferred).

**R2** — `String` is an owned, heap-allocated buffer. `&str` is an immutable slice (view) into a string. Use `&str` in function signatures to allow callers to pass both `String` and `&str`.

**R3** — **Borrowing** allows accessing data without taking ownership. Rules: You can have either **one** mutable reference (`&mut T`) OR **any number** of immutable references (`&T`) at any given time, but not both.

**R4** — `Result<T, E>` represents success/failure; `Option<T>` represents presence/absence. The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>`: Single owner, heap allocation. `Rc<T>`: Reference counted, single-threaded. `Arc<T>`: Atomic reference counted, thread-safe.

**R6** — **Traits** define shared behavior (like Go interfaces but more powerful). `dyn Trait` is a **trait object** (runtime dispatch via vtable). `T: Trait` is a **generic with a trait bound** (compile-time monomorphization).

**R7** — It fails because the compiler cannot guarantee the returned reference lives as long as the inputs. Fix with explicit lifetimes:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** — `Send` means a type can be moved to another thread. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send/Sync` because its reference count is not atomic. `Arc<T>` uses atomic operations, making it safe for concurrent use.

**R9** — Rust's async is **pull-based**. A `Future` is a state machine that does nothing until `poll()` is called. The **executor** (e.g., Tokio) manages the polling loop. Unlike Go's goroutines (which are managed by a runtime scheduler), Rust's async is a library-level abstraction.

**R10** — `unsafe` allows bypassing certain compiler checks. You can: 1. Dereference raw pointers. 2. Call FFI functions. 3. Mutate `static mut` variables. It is justified for low-level hardware access or performance-critical optimizations where you can prove safety.

**R11** — `match` is a powerful pattern matching tool. `if let` is a concise way to handle a single pattern. The compiler enforces **exhaustiveness**: all possible patterns must be covered.

**R12** — `Vec<T>` is a growable, heap-allocated array. `[T; N]` is a fixed-size array on the stack. When a `Vec` exceeds capacity, it reallocates a larger buffer and moves elements.

**R13** — **Enums** are "sum types" that can hold data. `Option<T>` is an enum (`Some(T)` or `None`), which eliminates the need for `null` and prevents null-pointer exceptions.

**R14** — `impl` defines methods for a type. `&self` (immutable borrow), `&mut self` (mutable borrow), `self` (consumes/moves the value). **Associated functions** (like `String::new()`) do not take `self`.

**R15** — `#[derive]` is a macro that automatically implements traits. Examples: `Debug`, `Clone`, `PartialEq`, `Serialize`. You cannot derive a trait if its implementation requires custom logic that the macro cannot generate.

**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that allows for both borrowed and owned data. It avoids allocation if the data is only read; it only clones if a mutation is attempted.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. The 2018 edition simplified module paths, making them more intuitive and reducing the need for `super`.

**R18** — `Pin<T>` ensures that the data at a specific memory address does not move. This is vital for `async` futures, which often contain self-referential pointers. `Unpin` is a marker trait for types that are safe to move even when pinned.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching. **Procedural macros** are functions that run at compile time (derive, attribute, or function-like). **Hygiene** ensures that macro-generated identifiers do not accidentally clash with local variables.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use. **Monomorphization** (generics) creates specialized code for each type, avoiding runtime overhead. **Iterators** are optimized by the compiler to be as fast as manual loops.
