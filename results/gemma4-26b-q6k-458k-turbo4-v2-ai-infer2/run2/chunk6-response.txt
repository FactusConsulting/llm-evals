## JavaScript / TypeScript (20 questions)

**JS1** — `var` is function-scoped and hoisted with an initial value of `undefined`. `let` and `const` are block-scoped and hoisted but reside in a "Temporal Dead Zone" (TDZ), meaning they cannot be accessed before declaration.

**JS2** — The event loop manages execution. The **Call Stack** handles synchronous code. When an async operation completes, its callback enters the **Microtask Queue** (Promises, `queueMicrotask`). The **Macrotask Queue** (setTimeout, setInterval, I/O) is processed one task at a time, with the microtask queue being fully emptied between macrotasks.

**JS3** — A closure is a function that "remembers" its lexical scope even when executed outside that scope. *Example:* A function returning another function that increments a private counter. *Bug:* Using `var` in a `for` loop causes all closures to share the same final value. *Fix:* Use `let` to create a new binding per iteration.

**JS4** — `Promise` represents an eventual value. `async/await` is syntactic sugar for Promises, making async code look synchronous. Error handling: `try/catch` works with `await`; with raw Promises, use `.catch()`. `Promise.all` rejects if *any* fail; `Promise.allSettled` waits for all to finish regardless of outcome.

**JS5** — `interface` is primarily for defining object shapes and supports declaration merging. `type` is more flexible, allowing unions, intersections, and primitives. Use `interface` for public APIs/objects and `type` for complex logic/unions. **Discriminated unions** use a common literal property (e.g., `type: 'success' | 'error'`) to allow TS to narrow types in a conditional block.

**JS6** — JavaScript uses prototypal inheritance where objects inherit properties from their prototype. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is "syntactic sugar" over the existing prototype-based system.

**JS7** — `this` refers to the execution context. 1. **Default**: `window`/`undefined`. 2. **Implicit**: The object before the dot (`obj.method()`). 3. **Explicit**: Using `call`, `apply`, or `bind`. 4. **New**: The newly created instance. `bind()` returns a new function with a fixed `this`; it cannot be re-bound to a different context.

**JS8** — `WeakRef` allows holding a reference to an object without preventing it from being garbage collected (GC). `FinalizationRegistry` allows a callback when an object is GC'd. `WeakMap` keys must be objects so that if the object is no longer referenced elsewhere, it can be collected, preventing memory leaks.

**JS9** — V8 uses **Hidden Classes** (shapes) to track object properties efficiently. **Inline Caching** optimizes property access by remembering offsets. **Deoptimization** occurs when code assumptions fail (e.g., an object's shape changes by adding properties dynamically). Patterns like changing object shapes frequently cause deoptimization.

**JS10** — Tree-shaking is dead-code elimination. It works with **ES Modules** because imports/exports are static. **CommonJS** uses `require()`, which is dynamic/runtime-based, making it nearly impossible for bundlers to determine what is unused at build time.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion; `===` checks both value and type. `??` (nullish coalescing) returns the right side only if the left is `null` or `undefined`. `?.` (optional chaining) safely accesses properties without throwing if the parent is nullish.

**JS12** — `map()` transforms each element; `filter()` selects elements based on a predicate; `reduce()` accumulates elements into a single value. `reduce()` with an initial value prevents errors on empty arrays. `flatMap()` maps each element to an array and then flattens the result by one level.

**JS13** — Template literals use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** allow a function to parse the template literal. *Example:* `` sql`SELECT * FROM users` `` where `sql` is a function that escapes inputs.

**JS14** — Destructuring extracts values from arrays/objects. `const {a, b} = obj` (object), `const [a, b] = arr` (array), `const {a = 1} = obj` (default), `const {a: newA} = obj` (rename). The rest operator `...` collects remaining elements into a new array/object.

**JS15** — `for...in` iterates over enumerable **keys** (including prototype). `for...of` iterates over **values**. Avoid `for...in` on arrays because it iterates over indices/keys and may include inherited properties.

**JS16** — **Generics** allow reusable components. **Constraints** (`T extends U`) limit the type. **Conditional types** (`T extends U ? X : Y`) act like ternary operators for types. **`infer`** allows TS to "guess" a type within a conditional. *Example:* `type Unpack<T> = T extends Array<infer U> ? U : T;`.

**JS17** — **CommonJS** (`require`) is synchronous and used in Node.js. **ESM** (`import`) is static and standard. Node.js handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM.

**JS18** — TS is **structural** (if it looks like a duck, it is a duck). **Excess property checks** apply when assigning an object literal directly to a type. `satisfies` checks if a value matches a type without widening the type of the variable. **Variance**: `in` (contravariant) means a subtype can be used where a supertype is expected; `out` (covariant) means a supertype can be used where a subtype is expected.

**JS19** — `Proxy` intercepts operations (get, set, etc.). `Reflect` provides the default implementation of those operations. *Example:* A Proxy can intercept `set` to validate that a property is a string before allowing assignment.

**JS20** — `SharedArrayBuffer` allows multiple Web Workers to share the same raw memory. `Atomics` provides thread-safe operations (add, load, store) to prevent race conditions. `Atomics.wait` pauses a thread until `Atomics.notify` is called.

## Bash (20 questions)

**B1** — `$*` is a single string of all arguments. `$@` is a list of separate arguments. `"$@"` (quoted) preserves individual arguments as distinct entities, whereas `"$*"` (quoted) joins them into one string.

**B2** — `set -e` (exit on error), `set -u` (exit if variable is unset), `set -o pipefail` (return the exit code of the first command in a pipe that fails, rather than the last).

**B3** — `$(command)` is command substitution (executes command and returns output). `` `command` `` is the older syntax for the same. `$((expression))` is for arithmetic evaluation; `expr` is an external utility for the same purpose.

**B4** — Process substitution `<(command)` creates a temporary file descriptor. *Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands as if they were files.

**B5** — Use `while read -r line; do ... done < file`. `for f in $(ls)` is dangerous because it performs word splitting on filenames containing spaces, treating one file as multiple items.

**B6** — `<<EOF` is a here-doc (multi-line string). `<<<` is a here-string (single string). `<<-EOF` strips leading tab characters from the input.

**B7** — `cmd > file 2>&1` redirects stdout to file, then stderr to stdout (so stderr goes to file). `cmd 2>&1 > file` redirects stderr to stdout (terminal), then stdout to file (so stdout goes to file, but stderr stays in terminal). `&> file` redirects both to the file.

**B8** — Use `mkdir lockdir` because `mkdir` is an atomic operation at the kernel level. A function should use `trap 'rmdir lockdir; exit' INT TERM EXIT`.

**B9** — `'...'` (literal, no expansion), `"..."` (interpolates variables), no quotes (word splitting and globbing occur). *Example:* `echo "$VAR"` vs `echo $VAR`.

**B10** — `[ -e file ]` (exists), `[ -d dir ]` (directory), `[ -r file ]` (readable). `[[ ]]` is a bash keyword that is more powerful, supports regex (`=~`), and doesn't require quoting variables to prevent errors.

**B11** — `$?` (exit status of last command), `$$` (PID of current script), `!$` (PID of last background job), `$#` (number of arguments).

**B12** — `foo() {}` is standard; `function foo {}` is a bashism. Return values are handled via `return n` (status code 0-255) or by printing to stdout.

**B13** — `PATH` is a colon-separated list of directories. Bash searches `PATH` for commands. A **builtin** (e.g., `cd`) is inside the shell; an **external** (e.g., `ls`) is a file on disk. Use `type -a command` to check.

**B14** — `trap 'command' SIGNAL` sets a handler. For cleanup, use `trap 'cleanup' EXIT INT TERM`. If multiple signals arrive, they are queued/handled sequentially.

**B15** — `xargs` converts stdin to arguments. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P N` runs N processes in parallel.

**B16** — Declare: `arr=(a b c)`. Append: `arr+=(d)`. Iterate: `for i in "${arr[@]}"`. Length: `${#arr[@]}`. Associative: `declare -A assoc`.

**B17** — `(...)` is a subshell (new process, new variable scope). `{ ...; }` is a group command (same process, same scope). Piping into a `while` loop creates a subshell, so variable changes inside the loop are lost in the parent.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (graceful termination), `SIGHUP` (terminal closed), `SIGKILL` (immediate kill). Use `trap` to catch `SIGTERM` and clean up background processes.

**B19** — `split` the file, use `xargs -P` to run a function on chunks, then `cat` the results. *Trade-off:* High CPU/IO usage. *Error propagation:* Check exit codes of each chunk.

**B20** — `exec` replaces the current shell with the new command. `exec 3>file` opens FD 3 for writing. `exec 3>&-` closes it. A **coprocess** (`coproc cmd`) allows two-way communication between the shell and a background process.

## PowerShell (20 questions)

**PS1** — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console. This matters because `Write-Host` output cannot be captured by subsequent pipeline commands.

**PS2** — The pipeline passes objects. `ForEach-Object` is a cmdlet designed for the pipeline (one by one). `foreach` is a language keyword (faster, processes the whole collection at once).

**PS3** — `[PSCustomObject]` is an object with properties. `[hashtable]` is a key-value collection. Use `[PSCustomObject]` for data structures in pipelines; use `hashtable` for lookups. Convert via `[PSCustomObject]@{...}`.

**PS4** — **Terminating** errors stop execution; **non-terminating** errors continue. `$ErrorActionPreference` (e.g., 'Stop', 'Continue') and `-ErrorAction` on cmdlets control how these are handled.

**PS5** — Splatting uses a hashtable to pass parameters: `$params = @{Name='A'; Age=1}; Get-User @params`. It differs from passing a single hashtable because it unpacks the keys into individual parameters.

**PS6** — `Invoke-Command` runs on remote computers (one-to-many). `Enter-PSSession` is an interactive session (one-to-one). Both use **WinRM** (WS-Man) or **SSH**.

**PS7** — PowerShell's pipeline is strongly typed. If a function returns an array, `$x.GetType().Name` is `Object[]`. If it returns 0 items, it might be `$null`. The correct pattern is to ensure a consistent return type, e.g., `@($result)`.

**PS8** — A `[scriptblock]` is a block of code. To pass to remote, use `Invoke-Command -ScriptBlock { ... }`. The **double-hop** problem occurs when a remote session tries to access a *second* remote resource; solve with **CredSSP** or **Kerberos Delegation**.

**PS9** — `@()` creates an empty array. `[array]` is a type. Indexing into `$null` results in an error/null; indexing an empty array returns nothing.

**PS10** — `-eq` (equality), `-match` (regex), `-contains` (checks if collection contains value), `-in` (checks if value is in collection). Case-sensitive versions start with `c` (e.g., `-ceq`).

**PS11** — `.psm1` is a script module (logic). `.psd1` is a manifest (metadata). Binary modules are `.dll` files. `Import-Module` loads them into the session.

**PS12** — `"..."` interpolates. `'...'` is literal. Use `$()` for expressions: `"Time: $(Get-Date)"`. Here-strings: `@""@`.

**PS13** — `Get-Member` shows properties/methods. `Select-Object` picks specific properties; `Where-Object` filters objects based on criteria.

**PS14** — PowerShell classes are simplified versions of C# classes. They support inheritance but have limited interface support compared to C#. Use classes for complex data models and functions for procedural tasks.

**PS15** — `[CmdletBinding()]` makes a function "advanced." It enables `-ErrorAction`, `-WhatIf`, and `-Verbose`. `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` blocks allow lifecycle management during pipeline processing.

**PS16** — Providers allow PowerShell to treat different stores (Registry, Cert, Env) as drives. `Get-ChildItem Registry::HKEY_LOCAL_MACHINE` works like a file system.

**PS17** — A `[runspace]` is a single thread. A `[runspacepool]` manages multiple. `ForEach-Object -Parallel` (v7+) is a high-level wrapper for managing runspaces for parallel tasks.

**PS18** — `PSScriptAnalyzer` is a linter. It uses rules to check code quality. You can suppress rules using `# PSScriptAnalyzer Ignore: RuleName`. It integrates into CI/CD via `Invoke-PSScriptAnalyzer`.

**PS19** — `$using:var` passes a local variable into a remote/parallel scope. Serialization limits: complex objects are converted to **CLIXML**, which can lose type/method information during the round-trip.

**PS20** — **DSC** uses **Configurations** (code), **Resources** (implementation), and the **LCM** (the engine on the node). Modern IaC (Terraform, Ansible, Azure Automanage) has largely superseded DSC for cloud-scale orchestration.
