## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but remain in the "Temporal Dead Zone" (TDZ) until declaration, making them inaccessible. `const` prevents reassignment.

**JS2** — The Event Loop manages asynchronous execution. The **Call Stack** handles synchronous code. When an async operation completes, its callback enters the **Microtask Queue** (Promises, `queueMicrotask`). The **Macrotask Queue** (setTimeout, setInterval, I/O) is processed one task at a time. After every macrotask, the engine exhausts the entire Microtask Queue before moving to the next macrotask.

**JS3** — A closure is a function that "remembers" its lexical scope even when executed outside that scope. 
*Example:* `const counter = () => { let count = 0; return () => ++count; };`
*Bug:* Using `var` in a `for` loop with an async callback; all callbacks reference the same final value. 
*Fix:* Use `let` in the loop header to create a new binding for each iteration.

**JS4** — `Promise` represents a future value. `async/await` is syntactic sugar for Promises. `async` functions return Promises; `await` pauses execution until the Promise settles. Error handling: `try/catch` works with `await`. `Promise.all` rejects if *any* promise fails; `Promise.allSettled` waits for all to finish, returning an array of objects describing the outcome of each.

**JS5** — `interface` is primarily for defining object shapes and supports "declaration merging" (adding properties to the same interface later). `type` is for unions, primitives, and aliases. Use `interface` for public APIs/extensible objects; use `type` for complex logic/unions. **Discriminated unions** use a common literal property (a "tag") to allow TypeScript to narrow down a type within a union.

**JS6** — JavaScript uses prototypal inheritance where objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar over this mechanism; it uses the `prototype` property under the hood.

**JS7** — `this` refers to the execution context. 
*Binding Rules:* 1. **New** (constructor), 2. **Explicit** (`call`, `apply`, `bind`), 3. **Implicit** (the object before the dot), 4. **Default** (global object or `undefined` in strict mode). `bind()` returns a new function with a fixed `this`. You cannot re-bind a function once `bind` has been called.

**JS8** — `WeakRef` allows you to hold a reference to an object without preventing it from being garbage collected. `FinalizationRegistry` allows you to register a callback that runs after an object is GC'd. `WeakMap` keys must be objects so that if the object is no longer referenced elsewhere, the entry can be GC'd.

**JS9** — V8 uses **Hidden Classes** (shapes) to optimize property access. **Inline Caching** remembers the offset of properties in these shapes. **Deoptimization** occurs when an object's shape changes (e.g., adding a property later), forcing V8 to drop to a slower, generic lookup.

**JS10** — Tree-shaking is the removal of dead code. It relies on static analysis of ES Modules (`import`/`export`). CommonJS (`require`) is dynamic; because imports can be conditional or computed at runtime, the bundler cannot safely determine what is unused, preventing effective tree-shaking.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion; `===` does not. `??` (nullish coalescing) returns the right side only if the left is `null` or `undefined`. `?.` (optional chaining) short-circuits and returns `undefined` if the reference is nullish.

**JS12** — `map()` creates a new array by transforming every element. `filter()` creates a new array with elements that pass a test. `reduce()` reduces an array to a single value. If an initial value is provided, `reduce` starts there; otherwise, it uses the first element. `flatMap()` maps then flattens the result by one level, useful for handling nested arrays.

**JS13** — Template literals use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** allow a function to parse the template literal. 
*Example:* `const sql = (strings, ...vals) => strings.reduce((acc, str, i) => acc + str + (vals[i] || ''), '');`

**JS14** — Destructuring extracts values from arrays/objects. 
*Object:* `const {name, age = 25} = user;` 
*Array:* `const [first, ...rest] = list;` 
*Renaming:* `const {name: userName} = user;`. The `...rest` operator collects remaining elements into a new array/object.

**JS15** — `for...in` iterates over enumerable *keys* (indices/properties). `for...of` iterates over *values*. Avoid `for...in` on arrays because it iterates over all enumerable properties (including prototype chain) and doesn't guarantee order.

**JS16** — **Generics** allow reusable components. 
*Constraint:* `<T extends string>` (T must be a string). 
*Conditional:* `T extends U ? X : Y` (returns X if T is U, else Y). 
*Infer:* `type GetReturn<T> = T extends (...args: any[]) => infer R ? R : any;` (extracts return type).

**JS17** — **CommonJS** uses `require`/`module.exports` (synchronous, Node.js default). **ESM** uses `import`/`export` (static, browser/modern Node). In `package.json`, `"type": "module"` tells Node to treat `.js` files as ESM.

**JS18** — TypeScript is structural (if it looks like a duck, it is a duck). **Excess property checks** occur when assigning an object literal to a type that has more properties. `extends` is for subtyping; `satisfies` validates a type without changing the inferred type. **Variance**: `in` (contravariant) relates to input parameters; `out` (covariant) relates to return values.

**JS19** — `Proxy` wraps an object to intercept operations (get, set, etc.). `Reflect` provides methods to perform those same operations (e.g., `Reflect.get`). 
*Example:* A Proxy can intercept `set` to validate that a value is a number before assigning it.

**JS20** — `SharedArrayBuffer` is a memory buffer shared between Web Workers. `Atomics` provides static methods to perform thread-safe operations (like `add` or `load`) on that buffer. `Atomics.wait` pauses a worker until a value changes, and `Atomics.notify` wakes it up.

## Bash

**B1** — `$@` represents all arguments as separate words. `$*` represents all arguments as a single string. `"$@"` preserves individual arguments (even with spaces); `"$*"` joins them into one string.

**B2** — `set -e`: exit on error. `set -u`: error on unset variables. `set -o pipefail`: the pipeline exit code is the code of the last command to fail, not just the last command in the pipe.

**B3** — `$(command)` is modern command substitution. `` `command` `` is legacy. `$((expression))` is for arithmetic; `expr` is a legacy external program for math.

**B4** — Process substitution `<(command)` treats the output of a command as a temporary file. 
*Example:* `diff <(ls dir1) <(ls dir2)` compares two directory listings without creating physical files.

**B5** — Use `while read -r line; do ... done < file` or `find . -print0 | xargs -0`. `for f in $(ls)` is dangerous because it splits filenames containing spaces into multiple arguments.

**B6** — `<<EOF` is a here-document (multi-line string). `<<<` is a here-string (single string). `<<-EOF` strips leading tab characters from the document.

**B7** — 
1. `cmd > file 2>&1`: stdout goes to file, stderr is redirected to where stdout is going (the file).
2. `cmd 2>&1 > file`: stderr goes to where stdout *was* (the terminal), then stdout goes to the file.
3. `cmd &> file`: both stdout and stderr go to the file.

**B8** — Use `mkdir lockdir` because `mkdir` is an atomic operation at the OS level (it either succeeds or fails). 
*Function:* `mkdir lock && trap 'rmdir lock' EXIT INT TERM`. 
*Why:* File creation (`touch`) can suffer from race conditions where two processes check for existence and both create it before the other finishes.

**B9** — `'...'` (single): literal string. `"..."` (double): allows variable interpolation. No quotes: allows word splitting and globbing. 
*Example:* `echo "$VAR"` vs `echo $VAR` (the latter might split if `$VAR` has spaces).

**B10** — `-f` (file), `-d` (directory), `-r` (readable). `[[ ]]` is a bash keyword that is safer (no word splitting/globbing issues) and supports regex (`=~`).

**B11** — `$?` (last exit code), `$$` (current PID), `$!` (last background PID), `$#` (number of arguments).

**B12** — `foo() { ... }` is standard. `function foo { ... }` is a bash-ism. Return values are sent via `return` (exit status 0-255) or via `stdout` (`echo`).

**B13** — `PATH` is a colon-separated list of directories. Bash searches these in order. **Builtin** (e.g., `cd`) is part of the shell; **External** (e.g., `ls`) is a file in `PATH`. Use `type -a command` to check.

**B14** — `trap 'command' SIGNAL` executes a command when a signal is caught. `EXIT` (script ends), `ERR` (command fails), `INT` (Ctrl+C), `TERM` (kill). If multiple arrive, they are handled in order of arrival.

**B15** — `xargs` takes stdin and turns it into arguments. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P N` runs N processes in parallel.

**B16** — Indexed: `arr=(a b c)`. Associative: `declare -A arr=([key]=val)`. 
*Iterate:* `for i in "${!arr[@]}"` (keys). 
*Length:* `${#arr[@]}`.

**B17** — `(...)` is a subshell (new process, new variable scope). `{ ...; }` is a group command (same process, same scope). Pipes `|` always create a subshell, so variable changes inside a `while` loop in a pipe are lost to the parent.

**B18** — `SIGINT` (interrupt), `SIGTERM` (terminate), `SIGHUP` (hangup), `SIGKILL` (immediate kill, cannot be trapped). For graceful shutdown: `trap 'cleanup_func' SIGTERM`.

**B19** — `split -l 1000 logfile` -> `xargs -P 4 -I {} my_func {}` -> `cat results > merged`. 
*Trade-off:* Parallelism speeds up processing but increases CPU/IO contention. Error propagation requires checking exit codes of all parallel jobs.

**B20** — `exec` replaces the current shell process with the new command. `exec 3>file` redirects file descriptor 3. A **coprocess** (`coproc cmd`) runs a command in the background with two-way pipes.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline. `Write-Host` sends text directly to the console. `Write-Host` cannot be captured by a variable or redirected.

**PS2** — The pipeline passes objects one by one. `ForEach-Object` is a cmdlet designed for the pipeline. `foreach` is a language keyword that is significantly faster for large collections but requires the whole collection to be in memory.

**PS3** — `[PSCustomObject]` is an object with properties/methods. `[hashtable]` is a key-value collection. Use `[PSCustomObject]` for data structures; `[hashtable]` for lookups. Convert: `[PSCustomObject]@{a=1}` or `$hash.GetEnumerator()`.

**PS4** — **Terminating** errors stop execution (caught by `try/catch`). **Non-terminating** errors continue (not caught by `try/catch`). `$ErrorActionPreference = 'Stop'` turns non-terminating into terminating.

**PS5** — Splatting uses a hashtable to pass parameters. `Invoke-Command @params`. It differs from passing a single hashtable because it unpacks the keys as parameter names.

**PS6** — `Invoke-Command` is for remote execution (one-to-many). `Enter-PSSession` is interactive (one-to-one). Uses WinRM (WS-Man) or SSH.

**PS7** — `+=` on an array creates a *new* array (slow). In the example, `$x.GetType().Name` would be `Object[]` (if items exist) or `Object` (if empty). Correct pattern: `[System.Collections.Generic.List[object]]::new()`.

**PS8** — A `[scriptblock]` is a chunk of code. To pass to remote, use it as a parameter. **Double-hop** occurs when a remote session tries to access a third resource using the first session's credentials. Solve with `CredSSP` or `Enable-WSManCredSSP`.

**PS9** — `@()` creates an empty array. `[array]` is a type. Indexing `$null` throws an error; indexing an empty array returns nothing. To force a single result into an array, use `@($result)`.

**PS10** — `-eq` (equals), `-match` (regex), `-contains` (checks if collection contains value), `-in` (checks if value is in collection). `-ceq` is case-sensitive.

**PS11** — `.psm1` (module logic), `.psd1` (manifest/metadata), Binary (DLL). `Import-Module` loads the module into the session.

**PS12** — `"..."` (interpolated), `'...'` (literal). Use `$()` for expressions: `"Result: $($obj.Prop)"`. Here-strings: `@""@` (must be at start of line).

**PS13** — `Get-Member` shows type info. `Properties` (data), `Methods` (actions), `NoteProperties` (custom data). `Select-Object` picks properties; `Where-Object` filters objects.

**PS14** — PowerShell classes are simpler than C# (no interfaces, limited inheritance). Use classes for complex data models; use functions for procedural logic.

**PS15** — `[CmdletBinding()]` makes a function "Advanced." `SupportsShouldProcess` enables `-WhatIf`. `ValueFromPipeline` allows input via `|`. `Begin/Process/End` blocks allow fine-grained control over pipeline processing.

**PS16** — Providers allow treating different stores as drives. `cd Registry::HKEY_LOCAL_MACHINE`. `Get-ChildItem` works identically across FileSystem, Registry, etc.

**PS17** — A `[runspace]` is a single thread. `[runspacepool]` manages multiple. `ForEach-Object -Parallel` (v7+) uses a runspace pool internally for high-performance parallel execution.

**PS18** — `PSScriptAnalyzer` performs static code analysis. It uses rules and severity levels. Suppress with `# PSScriptAnalyzer -DisableRule RuleName`.

**PS19** — `$using:var` brings a local variable into a remote scope. Serialization: objects are converted to CLIXML; complex types (like file handles) are lost during this process.

**PS20** — **DSC** manages state. **Configurations** are the logic, **Resources** are the implementation, **LCM** is the engine. Modern IaC has largely moved to tools like Terraform, Ansible, or Bicep.
