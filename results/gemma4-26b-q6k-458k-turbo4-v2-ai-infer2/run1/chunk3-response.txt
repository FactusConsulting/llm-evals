## OpenTofu / Terraform

**T1** — `tofu plan` creates an execution plan, showing what actions (create, update, destroy) will be taken without actually making changes. `tofu apply` executes those planned actions to reach the desired state.

**T2** — State is a JSON file mapping your configuration to real-world resources. Remote state is important for team collaboration (shared source of truth), state locking (preventing concurrent runs), and security (storing sensitive data outside local machines).

**T3** — `count` uses an integer index; if you remove an item from the middle of a list, all subsequent resources are shifted/recreated. `for_each` uses a map or set of keys; removing one item only affects that specific resource. `for_each` is preferred for collections of varying items to maintain stability.

**T4** — This is "configuration drift." During `tofu plan`, OpenTofu refreshes the state by querying the provider API. It detects the discrepancy between the real-world resource and the state/config. It will then propose changes to revert the manual modification to match the configuration.

**T5**
```hcl
resource "aws_instance" "web" {
  for_each = toset(["web1", "web2", "web3"])
  ami           = "ami-xxxxxx"
  instance_type = "t3.micro"
  tags = { Name = each.key }
}
```

**T6** — `terraform_remote_state` reads the entire state file of another workspace, creating tight coupling and security risks. The recommended alternative is using **Outputs** passed between modules or using **Data Sources** to fetch specific attributes. This follows the principle of least privilege.

**T7** — This is a race condition. The `null_resource` completes, but the output isn't "ready" or persisted in the state before the next resource attempts to read it. **Fix:** Use a `time_sleep` resource to introduce a delay, or better, use a `check` block or a data source that validates the service is actually reachable before proceeding.

**T8** — `import` brings existing infrastructure under management. Limitation: It only updates the state, it doesn't generate the HCL code. The `import` block (1.5+) allows you to define the import declaratively in code, which can then be used to generate the configuration automatically.

**T9** — A `variable` is an input parameter for a module (external). An `output` is a value returned by a module (internal result).

**T10** — A provider is a plugin that translates OpenTofu code into API calls (e.g., AWS, Azure). If you run `plan` without `init`, OpenTofu will fail because it hasn't downloaded the necessary provider binaries.

**T11** — The `.terraform.lock.hcl` file records the exact versions and hashes of providers used. It should be committed to version control to ensure every environment (Dev, Prod, CI) uses the identical provider versions, preventing "it works on my machine" issues.

**T12** — `tofu destroy` removes all resources managed by the current configuration. To target a single resource: `tofu destroy -target=aws_instance.web_server`.

**T13** — A data source allows you to fetch information from an existing provider resource that is *not* managed by your current OpenTofu code. Example: Using `data "aws_ami"` to find the latest Amazon Linux 2 ID rather than hardcoding an ID.

**T14** — `variable` blocks are for external inputs (passed by users/CI). `locals` are for internal logic/constants. Use `locals` to avoid repeating complex expressions or to transform data within a module without exposing it as an input.

**T15** — 
- `create_before_destroy`: Creates the new resource before deleting the old one (prevents downtime).
- `prevent_destroy`: Stops `tofu destroy` from deleting a critical resource (safety).
- `ignore_changes`: Tells OpenTofu to ignore updates to specific attributes (useful for auto-scaling or manual tags).

**T16** — The `moved` block allows you to rename a resource or move it into a module without OpenTofu thinking the old resource was deleted and a new one was created. It updates the state mapping instead of triggering a recreation.

**T17** — The dependency graph is a directed acyclic graph (DAG). **Implicit** dependencies are created when one resource references another's attribute. **Explicit** dependencies are created via `depends_on`. `depends_on` can reduce parallelism because it forces a strict order, potentially slowing down the run.

**T18** — 
1. **Modularize:** Break large states into smaller, independent state files (reduces the graph size).
2. **`-refresh=false`:** Skips the API refresh phase (faster, but risks drift).
3. **`-target`:** Only plan specific resources (useful for debugging, not for full runs).
4. **Optimize Data Sources:** Reduce the number of expensive data source lookups.

**T19** — State locking prevents two users/processes from writing to the state simultaneously. If a process crashes, the lock remains. You fix it with `tofu force-unlock <lock_id>`. **Risk:** If a write was actually in progress, forcing the unlock can lead to state corruption.

**T20** — 
1. Configure the new backend in your code (e.g., `s3` block).
2. Run `tofu init`. OpenTofu will detect the change and ask to migrate the state.
3. Confirm the migration.
4. Verify by running `tofu state list` to ensure all resources are present and `tofu plan` to ensure no unexpected changes are proposed.

## Ansible

**A1** — A **Task** is a single action. A **Role** is a reusable collection of tasks, variables, and files. A **Playbook** is a collection of "plays" that maps hosts to roles/tasks.

**A2** — `ansible_facts` is a dictionary of system information. Access the OS family via `ansible_facts['os_family']`.

**A3** — `command`: Executes a command without a shell (no pipes/redirects, most secure). `shell`: Executes via `/bin/sh` (allows pipes/redirects). `raw`: Bypasses Python entirely (sends raw text to the socket; used when Python isn't installed).

**A4** — Idempotency means running a task multiple times has the same effect as once. 
- **Idempotent:** `apt: name=nginx state=present`.
- **NOT Idempotent:** `shell: echo "hello" >> /tmp/file`.

**A5**
```yaml
- name: Install htop
  package:
    name: "{{ 'epel-release' if ansible_os_family == 'RedHat' else '' }} htop"
  when: ansible_os_family in ['RedHat', 'Debian']
```
*(Note: A cleaner way is using `when` on separate tasks, but this demonstrates logic in one task).*

**A6** — Order (highest to lowest): `extra_vars` > `set_fact` > `host_vars` > `group_vars` > `role defaults`.

**A7** — Use `serial: 3` in the play. To ensure they are ready, use a `wait_for` task to check a specific port or service status before the play continues to the next batch.

**A8** — Use `ansible-vault encrypt_string 'my_secret_value'`. You can then paste the encrypted block into your vars file.

**A9** — **Static:** A hardcoded file (INI/YAML). **Dynamic:** A script or plugin that queries an API (AWS/GCP) to generate the inventory on the fly.

**A10** — `ansible webservers -m shell -a "df -h"`

**A11** — A **handler** is a special task that only runs if a task notifies it (usually when a change occurs). Trigger it using the `notify` keyword in a task.

**A12** — `ansible.cfg` configures Ansible behavior. Common settings: `inventory`, `remote_user`, `forks`, `gathering`.

**A13** — `register` saves the output of a task into a variable. You use it via `when: result_var.rc == 0`.

**A14** — `import_tasks` is **static** (processed when the playbook is parsed). `include_tasks` is **dynamic** (processed when the execution reaches that line). `include_tasks` allows for conditional evaluation of the included file itself.

**A15** — **Ansible Galaxy** is a hub for roles/collections. Use `ansible-galaxy install -r requirements.yml` to install them.

**A16** — **ssh**: Standard for Linux. **local**: Runs on the control node. **network_cli**: Used for network devices (switches/routers) that don't have Python.

**A17** — `delegate_to` runs a task on a different host. `run_once` runs it only once per play. 
*Example:* 
```yaml
- name: Get remote IP
  set_fact:
    remote_ip: "{{ ansible_default_ipv4.address }}"
  register: ip_info
  delegate_to: localhost
  run_once: true
```

**A18** — 
1. **Forks:** Increase parallel processes.
2. **Pipelining:** Reduces SSH connections.
3. **Fact Caching:** Avoids re-gathering facts.
4. **Mitogen:** A highly optimized connection plugin.

**A19** — `{{ }}` (Variables), `{% %}` (Logic/Control), `{# #}` (Comments).
```jinja2
{% for server in backend_servers %}
upstream myapp {
    server {{ server }}; # Health check enabled
}
{% endfor %}
```

**A20** — 
1. Set `serial: 1` (or small batches).
2. **Pre-task:** Use `uri` module to check health; if bad, stop. Use `shell` to remove server from Load Balancer.
3. **Task:** Update application.
4. **Post-task:** Use `uri` to verify app is up; if OK, add back to Load Balancer.
5. **Rollback:** Wrap tasks in a `block`. If any fail, the `rescue` block triggers to restore the previous state/LB config.
