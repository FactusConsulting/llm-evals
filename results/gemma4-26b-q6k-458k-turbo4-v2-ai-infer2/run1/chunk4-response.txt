## Go

**G1** — An **array** has a fixed size defined at compile time. A **slice** is a descriptor (header) containing a pointer to an underlying array, a length, and a capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array, copies the old data, and returns a new slice pointing to this new array.

**G2** — `var x int` declares a variable with a zero value (0). `x := 0` is short-variable declaration that infers the type. You **cannot** use `:=` at the package level; it is only valid inside function bodies.

**G3** — A **goroutine** is a lightweight, user-space thread managed by the Go runtime. Unlike OS threads, which are heavy and managed by the kernel, goroutines start with small stacks (KB) that grow/shrink. The **GMP model** consists of **G** (Goroutines), **M** (Machine/OS Threads), and **P** (Processors/Context). **P** acts as a resource that allows **G** to run on **M**, enabling efficient work-stealing and scheduling.

**G4** — **Channels** are pipes used for communication between goroutines. An **unbuffered channel** is synchronous; the sender blocks until a receiver is ready. A **buffered channel** allows sending up to its capacity without blocking. If a buffered channel is full, the sender blocks until space becomes available.

**G5** — The `context` package handles cancellation, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
// If the request takes > 100ms, ctx.Done() triggers and the request is canceled.
```

**G6** — Go uses **implicit interface satisfaction**: a type satisfies an interface simply by implementing its methods (no `implements` keyword). `interface{}` (or `any`) can hold any value. It is **powerful** because it allows generic-like behavior before generics, but **dangerous** because it bypasses type safety, requiring type assertions that can panic.

**G7** — This is unsafe due to **instruction reordering**. The compiler or CPU might reorder the writes so `ready = true` happens before `data = "hello"`. Correct alternatives: use `sync.Mutex` or `atomic.Bool` / `atomic.Value` to ensure memory visibility and ordering.

**G8** — `sync.Mutex` is an exclusive lock. `sync.RWMutex` allows multiple concurrent readers OR one single writer. `sync.Map` is optimized for cases where keys are stable and reads significantly outnumber writes (using atomic operations to reduce lock contention). `sync.Map` has higher overhead for simple, write-heavy workloads compared to a `map` + `Mutex`.

**G9** — `go.mod` defines the module path and dependencies. `go.sum` contains cryptographic hashes of dependencies to ensure integrity. `go mod tidy` removes unused dependencies and adds missing ones. **MVS (Minimum Version Selection)** is the algorithm Go uses to pick the lowest version of a module that satisfies all requirements, ensuring reproducible builds.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common gotcha: using a loop variable in a deferred closure (though fixed in Go 1.22, historically it captured the same memory address, causing all defers to see the final loop value).

**G11** — A **pointer** is a variable that stores the memory address of another value. The zero value is `nil`. You create a pointer to a struct literal using the address-of operator: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs automatically when a package is initialized. A package can have multiple `init()` functions, and they execute in the order they appear in the source code (after package-level variables are initialized).

**G13** — `new(T)` allocates zeroed memory for type `T` and returns a `*T`. `make(T, args)` is used for slices, maps, and channels; it initializes the internal data structures and returns an initialized value of type `T`.

**G14** — Errors are values implementing the `error` interface (a single `Error() string` method). Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error matches a specific value (useful for wrapped errors), while `errors.As` checks if an error matches a specific type.

**G15** — **Map**: `nil`. **Slice**: `nil`. **Channel**: `nil`. **Struct**: All its fields are set to their respective zero values.

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one access is a write. The `-race` flag enables a data race detector.
*Fix:*
```go
var mu sync.Mutex
mu.Lock()
count++
mu.Unlock()
```

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, which evaluates expressions, `select` evaluates channel operations. If multiple cases are ready, one is chosen **pseudo-randomly**. A timeout is implemented via `case <-time.After(d):`.

**G18** — **Escape analysis** determines if a variable can reside on the stack or must "escape" to the heap. Variables escape if they are returned from a function, shared via pointers, or are too large. You can inspect this with `go build -gcflags="-m"`. Minimizing heap allocation reduces GC pressure and improves performance.

**G19** — `reflect.Type` describes the type metadata; `reflect.Value` holds the actual data. Reflection is computationally expensive due to runtime overhead and prevents many compiler optimizations. It is justified for generic libraries (like JSON encoders) or when types are unknown until runtime, but **code generation** is preferred for performance-critical paths.

**G20** — `//go:embed` allows including files/directories in the binary at compile time. It supports single files, directories, or multiple patterns. It interacts with `io/fs.FS` by providing an `embed.FS` type that implements the `fs.FS` interface, allowing standard file-system operations on embedded data.

## Rust

**R1** — **Ownership** is Rust's memory management system. Rules: 1. Each value has a single owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated string. `&str` is a borrowed string slice. Use `String` in signatures if the function needs to own the data; use `&str` if the function only needs to read it.

**R3** — **Borrowing** allows access to data without taking ownership. Rules: You can have either **one** mutable reference (`&mut T`) OR **any number** of immutable references (`&T`) at any given time.

**R4** — `Result<T, E>` represents success (`Ok`) or failure (`Err`). `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>` provides heap allocation for a single value. `Rc<T>` (Reference Counted) allows multiple owners in a single-threaded context. `Arc<T>` (Atomic Reference Counted) allows multiple owners across multiple threads.

**R6** — **Traits** define shared behavior (similar to interfaces). `dyn Trait` uses **dynamic dispatch** (vtable lookup at runtime). `T: Trait` uses **static dispatch** (monomorphization at compile time), which is faster but increases binary size.

**R7** — It fails because the compiler cannot guarantee the returned reference lives long enough. Fix with lifetime annotations:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** — `Send` means ownership can be transferred to another thread. `Sync` means a type can be safely shared via references between threads. `Rc<T>` is not `Send` because its reference count is not updated atomically, leading to data races. `Arc<T>` uses atomic operations, making it `Send` and `Sync`.

**R9** — Rust's `async` functions return a `Future` (a state machine). Unlike Go's goroutines (which are managed by a runtime scheduler), Rust's futures are **lazy**; they do nothing unless an **executor** (like Tokio) polls them.

**R10** — `unsafe` allows bypassing certain compiler checks. You can: 1. Dereference raw pointers. 2. Call FFI functions. 3. Mutate static variables. It is justified for low-level hardware access or performance-critical optimizations where the programmer guarantees safety.

**R11** — `match` is for pattern matching and must be **exhaustive** (all possible cases covered). `if let` is a concise way to handle a single pattern match.

**R12** — `[T; N]` is a fixed-size array on the stack. `Vec<T>` is a growable array on the heap. When capacity is exceeded, `Vec` allocates a larger buffer and moves elements.

**R13** — Enums are **sum types** that can hold data in each variant. `Option<T>` is an enum (`Some(T)` or `None`). Rust uses this instead of `null` to force developers to handle the "empty" case explicitly.

**R14** — `impl` blocks define methods. `&self` borrows immutably, `&mut self` borrows mutably, and `self` consumes the value. **Associated functions** (like `String::new()`) do not take `self` and are called on the type itself.

**R15** — `#[derive]` automatically implements a trait. Examples: `Debug` (printing), `Clone` (deep copy), `PartialEq` (equality). You cannot derive a trait if it requires custom logic or if its components don't implement it.

**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that allows for either borrowing or owning. It avoids allocation if you only read the data, but clones it only when you attempt to mutate it.

**R17** — `mod` declares a module, `use` brings it into scope, and `pub` makes it visible. The file system maps to modules (e.g., `mod foo;` looks for `foo.rs`). The 2018 edition simplified module paths, removing the need for many `super` or `crate` prefixes.

**R18** — `Pin<T>` ensures that the data it points to cannot be moved in memory. This is vital for **self-referential structs** (common in `async` state machines). `Unpin` is a marker trait indicating a type is safe to move even when pinned.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching on tokens. **Procedural macros** are functions that act on the AST (derive, attribute, or function-like). **Hygiene** ensures macro-defined variables don't accidentally collide with local variables.

**R20** — These are abstractions that don't add runtime overhead. **Iterators** compile down to efficient loops; **Generics** use monomorphization (generating specific code for each type); **Trait static dispatch** resolves calls at compile time, allowing the compiler to inline code.
