## .NET / C# (20 questions)

DN1 — Easy:  
A class is a reference type allocated on the heap, while a struct is a value type allocated on the stack (or inline in containing objects). Use structs for small, immutable data with no inheritance needs (e.g., Vector3, DateTime).

DN2 — Easy:  
IEnumerable<T> represents in-memory collections (e.g., List<T>) and uses LINQ-to-Objects. IQueryable<T> represents database queries (e.g., Entity Framework) and translates LINQ to SQL. The distinction matters because IQueryable<T> queries are executed on the database, while IEnumerable<T> queries are executed in-memory.

DN3 — Medium:  
async/await uses Tasks to represent asynchronous operations. A Task represents a potentially long-running operation, while ValueTask avoids heap allocation for short-lived operations. Use ValueTask when the async operation is fast and called frequently to reduce GC pressure.

DN4 — Medium:  
Dependency injection (DI) is a design pattern where dependencies are injected into classes rather than created internally. The three lifetimes are:  
- Transient: New instance per request  
- Scoped: New instance per scope (e.g., HTTP request)  
- Singleton: Single instance for the app lifetime  
A common bug is injecting a Scoped service into a Singleton, causing the Scoped service to be shared across requests.

DN5 — Medium:  
string is immutable and heap-allocated, while ReadOnlySpan<char> is a stack-allocated view of a string. Use Span<T> for high-performance string processing (e.g., parsing) to avoid allocations and improve speed.

DN6 — Medium:  
The .NET GC collects garbage in generations (Gen 0, 1, 2) to optimize performance. Gen 0 collects short-lived objects, Gen 1 collects objects surviving Gen 0, and Gen 2 collects long-lived objects. The Large Object Heap (LOH) handles objects >85KB. IDisposable is used for unmanaged resources (e.g., file handles) because the GC doesn't manage them.

DN7 — Hard:  
ConfigureAwait(false) tells the async method not to capture the current SynchronizationContext. Use it in library code to avoid UI thread blocking, but avoid it in UI code to maintain context. It relates to SynchronizationContext by bypassing the default context capture.

DN8 — Hard:  
.NET 8/9 features:  
- Primary constructors: `public class Person(string name, int age) { ... }`  
- Collection expressions: `var list = [1, 2, 3];`  
- FrozenDictionary: Immutable dictionary  
Example with DI:  
```csharp
public class Service([ActivatorUtilitiesConstructor] PrimaryConstructorService(string param) { ... })
```

DN9 — Hard:  
The ObjectDisposedException occurs when DbContext is disposed prematurely. The fix is to ensure DbContext is scoped to the request (e.g., using Scoped lifetime in DI). EF Core's DbContext should be Scoped to match the HTTP request lifetime.

DN10 — Medium:  
record is an immutable reference type with value-based equality, while class is mutable. record struct is an immutable value type. Use record for immutable data, class for mutable objects, and record struct for small, immutable value types.

DN11 — Easy:  
- ref: Pass by reference (modify original)  
- out: Pass by reference (return value)  
- in: Pass by reference (read-only)  
Use ref for mutable parameters, out for returning multiple values, and in for read-only parameters.

DN12 — Easy:  
Nullable reference types (NRTs) use `?` to indicate potential nulls (e.g., `string?`). They differ from nullable value types (e.g., `int?`) by providing compile-time null checks. NRTs help prevent null reference exceptions.

DN13 — Easy:  
LINQ (Language Integrated Query) enables querying collections. Method syntax (e.g., `list.Where(...)`) is more flexible, while query syntax (e.g., `from x in list where ...`) is more SQL-like. Deferred execution means queries aren't executed until enumerated.

DN14 — Easy:  
Generic constraints restrict type parameters:  
- `where T : class`: Reference type  
- `where T : struct`: Value type  
- `where T : new()`: Has parameterless constructor  
- `where T : IComparable<T>`: Implements interface  
Combine constraints when multiple restrictions are needed (e.g., `where T : class, IComparable<T>`).

DN15 — Easy:  
Abstract classes can have implementation and fields, while interfaces define contracts. Default interface methods (C# 8+) allow interface implementations, reducing the need for abstract classes.

DN16 — Medium:  
The middleware pipeline in ASP.NET Core processes requests in order.  
- `app.Use()`: Adds middleware to the pipeline  
- `app.Map()`: Creates branches based on path  
- `app.Run()`: Ends the pipeline  
Order matters (first middleware runs first). Exception handling middleware catches errors and invokes `IExceptionHandler`.

DN17 — Medium:  
Channel<T> is a producer-consumer queue with backpressure. It differs from BlockingCollection<T> by supporting async operations and backpressure. Example:  
```csharp
var channel = Channel.CreateBounded<int>(10);
await channel.Writer.WriteAsync(42);
```

DN18 — Hard:  
Source Generators are compile-time code generators. They differ from reflection (runtime) and IL weaving (post-compile). Incremental generators are preferred for better performance and scalability.

DN19 — Hard:  
TPL Dataflow provides blocks (ActionBlock, TransformBlock, BufferBlock) for pipeline processing. It differs from Channels by offering more control over data flow. Example:  
```csharp
var block = new ActionBlock<int>(x => Console.WriteLine(x));
```

DN20 — Hard:  
Minimal APIs are lightweight alternatives to controller-based APIs. They differ by using endpoint routing and reducing boilerplate. Trade-offs:  
- Testability: Requires manual setup  
- Middleware: Limited support  
- OpenAPI: Requires additional configuration  
Route groups and endpoint filters enable organization and customization.

## Python (20 questions)

P1 — Easy:  
- List: Mutable, ordered  
- Tuple: Immutable, ordered  
- Set: Mutable, unordered, unique  
- Frozenset: Immutable, unordered, unique  

P2 — Easy:  
The GIL (Global Interpreter Lock) allows only one thread to execute Python bytecode at a time. It affects CPU-bound workloads. Workarounds: multiprocessing, asyncio, or C extensions.

P3 — Medium:  
- `copy()`: Shallow copy (copies references)  
- `deepcopy()`: Deep copy (copies nested objects)  
Example:  
```python
a = [[1, 2], [3, 4]]
b = a.copy()
b[0][0] = 5  # a becomes [[5, 2], [3, 4]]
```

P4 — Medium:  
Decorator example:  
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.2f}s")
        return result
    return wrapper
```

P5 — Medium:  
Generators use `yield` to produce values on-the-fly, unlike returning a list. `yield from` delegates to another generator. They save memory for large datasets.

P6 — Medium:  
- `asyncio.run()`: Runs the top-level coroutine  
- `asyncio.gather()`: Runs coroutines concurrently  
- `asyncio.create_task()`: Schedules a coroutine  
`time.sleep()` blocks the event loop; use `asyncio.sleep()` instead.

P7 — Hard:  
Python 3 uses C3 linearization for MRO. Diamond inheritance resolves conflicts by preferring the first parent. Example:  
```python
class A:
    def who(self): return "A"
class B(A):
    pass
class C(A):
    def who(self): return "C"
class D(B, C):
    pass
print(D().who())  # Output: "C" (C overrides A)
```

P8 — Hard:  
- Metaclass: Controls class creation (e.g., ORM)  
- `__init_subclass__`: Hook for subclass initialization  
Use metaclass for class-level customization; use `__init_subclass__` for subclass-specific logic.

P9 — Hard:  
- `multiprocessing`: Parallel processes (CPU-bound)  
- `threading`: Parallel threads (I/O-bound)  
- `concurrent.futures`: High-level interface  
Multiprocessing uses pickling for serialization.

P10 — Medium:  
`__slots__` restricts instance attributes to reduce memory and prevent dynamic additions. Use it for memory optimization in large classes.

P11 — Easy:  
A virtual environment isolates Python dependencies. `venv` is standard, `virtualenv` is third-party, and `conda` manages environments and packages.

P12 — Easy:  
- List/dict/set comprehensions: Concise syntax for creating collections  
- `map()`/`filter()`: Functional equivalents  
Prefer comprehensions for readability and performance.

P13 — Easy:  
- `==`: Value equality  
- `is`: Identity equality  
Object interning caches small integers/strings, causing `a is b` to return True.

P14 — Easy:  
- `*args`: Positional arguments  
- `**kwargs`: Keyword arguments  
- `/`: Positional-only parameters  
- `*`: Keyword-only parameters  

P15 — Easy:  
Context managers handle resources (e.g., files). Example:  
```python
class Timer:
    def __enter__(self):
        self.start = time.time()
    def __exit__(self, *args):
        print(f"Elapsed: {time.time()-self.start}")
with Timer():  # Example beyond file handling
    time.sleep(1)
```

P16 — Medium:  
Type hinting enables static analysis. Examples:  
- `typing.Union`: Multiple types  
- `Optional`: `Union[T, None]`  
- `Literal`: Fixed values  
- `TypeVar`: Generic type  
- `Protocol`: Structural subtyping  
Tools like mypy use these for static checks.

P17 — Medium:  
- `__repr__`: Unambiguous string representation  
- `__str__`: Human-readable string  
- `__eq__`: Equality check  
- `__hash__`: Hash value  
- `__getattr__`: Attribute access  
- `__getattribute__`: Attribute access (overrides `__getattr__`)  
Defining `__eq__` without `__hash__` makes objects unhashable.

P18 — Hard:  
Descriptors control attribute access via `__get__`, `__set__`, `__delete__`. `property`, `classmethod`, and `staticmethod` use descriptors under the hood.

P19 — Hard:  
Python's import system uses finders and loaders.  
- Relative imports: `from . import module`  
- Absolute imports: `from package import module`  
- `sys.path`: Module search path  
- `PYTHONPATH`: Environment variable for paths  
- `__init__.py`: Package marker  
- Namespace packages: Implicit packages without `__init__.py`  

P20 — Hard:  
- `dataclasses`: Simplifies class creation  
- `attrs`: Similar to dataclasses with more features  
- `Pydantic`: Adds validation and serialization  
- `__post_init__`: Initialization hook  
- `field factories`: Custom field creation  
- `frozen`: Immutable dataclasses  
Choose Pydantic for validation and serialization needs.
