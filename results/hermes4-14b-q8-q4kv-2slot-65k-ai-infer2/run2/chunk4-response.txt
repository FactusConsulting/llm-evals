## Go Answers

G1 — Easy: What is the difference between a slice and an array in Go? What happens when you append to a slice that has reached its capacity?
- Array: Fixed-size, declared with `[n]T`, elements contiguous in memory.
- Slice: Dynamic view of an array, declared with `[]T`, has length and capacity.
- When appending to a full slice (length == capacity), Go allocates a new underlying array, copies elements, and returns a new slice with increased capacity.

G2 — Easy: Explain the difference between `var x int` and `x := 0`. When can you NOT use `:=`?
- `var x int`: Explicit declaration, initializes to zero value (0 for int).
- `x := 0`: Short declaration, only allowed inside functions, infers type from RHS.
- Cannot use `:=` at package level, in global scope, or if the variable already exists in the current scope.

G3 — Medium: What is a goroutine, and how does it differ from an OS thread? What is the role of the Go scheduler (GMP model)?
- Goroutine: Lightweight, user-space thread managed by Go runtime.
- OS Thread: Kernel-managed thread, more expensive to create/switch.
- GMP Model: G (goroutine), M (OS thread), P (processor). Scheduler maps Gs to Ms via Ps, multiplexing many Gs onto fewer Ms.

G4 — Medium: Explain how channels work in Go. What is the difference between a buffered and unbuffered channel? What happens when you send to a full buffered channel?
- Channels: Typed communication mechanism between goroutines.
- Unbuffered: Send blocks until receiver is ready.
- Buffered: Holds a fixed number of elements, send blocks only when full.
- Sending to a full buffered channel blocks until space is available.

G5 — Medium: What is the context package used for? Write a minimal example of using context.WithTimeout to cancel a long-running HTTP request.
- Context: Propagates cancellation, deadlines, and request-scoped values.
- Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequest("GET", "https://example.com", nil)
req = req.WithContext(ctx)
resp, err := http.DefaultClient.Do(req)
```

G6 — Medium: Explain Go's interface satisfaction model. How does it differ from Java/C# interfaces? What is the empty interface interface{} (or any) and why is it both powerful and dangerous?
- Interface Satisfaction: Implicit, no explicit declaration needed.
- Java/C#: Explicit implementation via `implements` keyword.
- Empty Interface: `interface{}` (or `any` in Go 1.18+), matches any type.
- Powerful: Allows generic code, but dangerous: bypasses type safety, can lead to runtime errors.

G7 — Hard: Explain Go's memory model regarding goroutine visibility. Why is the following unsafe, and what are the correct alternatives?
```go
var ready bool
var data string

go func() {
    data = "hello"
    ready = true
}()

for !ready {}
fmt.Println(data)
```
- Memory Model: No guarantees about visibility across goroutines without synchronization.
- Unsafe: `ready` and `data` may not be visible to the main goroutine.
- Correct Alternatives: Use `sync/atomic` for `ready`, or use a channel to signal completion.

G8 — Hard: What is the difference between sync.Mutex and sync.RWMutex? When would you use sync.Map vs a regular map with a mutex? What are the performance trade-offs?
- Mutex: Exclusive lock for reads and writes.
- RWMutex: Allows multiple readers or one writer.
- sync.Map: Optimized for read-heavy workloads with frequent key updates.
- Regular Map + Mutex: Simpler, better for write-heavy or when keys are stable.
- Trade-offs: sync.Map has overhead for concurrent reads/writes, regular map + mutex is more predictable.

G9 — Hard: Explain how Go modules work. What is the difference between go.mod and go.sum? What does go mod tidy do, and what is the Minimum Version Selection (MVS) algorithm?
- Go Modules: Dependency management system.
- go.mod: Declares module name, Go version, and dependencies.
- go.sum: Cryptographic checksums of dependencies.
- go mod tidy: Adds missing dependencies and removes unused ones.
- MVS: Algorithm to select the minimal compatible versions of dependencies.

G10 — Medium: What is a defer statement? In what order do multiple defers execute? What is a common gotcha with defer in a loop?
- Defer: Delays execution of a function until surrounding function returns.
- Order: Last deferred first executed (LIFO).
- Gotcha: Defer inside a loop may capture the same variable, leading to unexpected behavior.

G11 — Easy: What is a pointer in Go? What is the zero value of a pointer? How do you create a pointer to a struct literal?
- Pointer: Holds memory address of a value.
- Zero Value: `nil`.
- Creating Pointer: `&struct{...}{}`.

G12 — Easy: Explain Go's init() function. When does it run? Can a package have multiple init() functions, and if so, in what order do they execute?
- init(): Package initialization function.
- Runs after package-level variables are initialized.
- Multiple init() functions: All execute in the order they appear in the source file.

G13 — Easy: What is the difference between make and new in Go? What types does each work with?
- make: Initializes slices, maps, channels.
- new: Allocates zero value of a type.
- make works with slices, maps, channels.
- new works with any type.

G14 — Easy: How does error handling work in Go? What is the error interface, and what is the idiomatic pattern for checking errors? How do errors.Is and errors.As differ from ==?
- Error Handling: Explicit, using error return values.
- error Interface: `error` interface with `Error() string` method.
- Idiomatic Pattern: Check error with `if err != nil`.
- errors.Is: Checks for equality of errors, considering wrapped errors.
- errors.As: Extracts an error of a specific type from a wrapped error.

G15 — Easy: What are Go's built-in composite types (map, slice, channel, struct)? What is the zero value of each?
- Composite Types: map, slice, channel, struct.
- Zero Values:
  - map: `nil`
  - slice: `nil`
  - channel: `nil`
  - struct: All fields zeroed.

G16 — Medium: What is a race condition in Go? How does the -race flag work? Give an example of a data race and show how to fix it with sync.Mutex or a channel.
- Race Condition: Concurrent access to shared data without synchronization.
- -race Flag: Runtime detector for data races.
- Example:
```go
var counter int
var mu sync.Mutex

func increment() {
    mu.Lock()
    counter++
    mu.Unlock()
}
```

G17 — Medium: Explain Go's select statement. How does it differ from a switch? What happens when multiple cases are ready? How do you implement a timeout with select?
- select: Chooses a case to execute based on channel readiness.
- Differs from switch: Only works with channel operations.
- Multiple Cases Ready: Chooses one at random.
- Timeout: Use a channel with a timer.

G18 — Hard: What is escape analysis in Go? How does the compiler decide whether to allocate on the stack or the heap? How can you inspect escape analysis decisions, and why does it matter for performance?
- Escape Analysis: Determines if a variable's address escapes to the heap.
- Stack Allocation: If variable doesn't escape.
- Heap Allocation: If variable escapes.
- Inspection: Use `-gcflags="-m"` to see escape analysis decisions.
- Performance: Stack allocation is faster, heap allocation has GC overhead.

G19 — Hard: Explain Go's reflection package (reflect). What is reflect.Type vs reflect.Value? What are the performance costs, and when is reflection justified vs code generation?
- reflect: Provides runtime inspection and manipulation of types and values.
- reflect.Type: Represents a type.
- reflect.Value: Represents a value.
- Performance Costs: Reflection is slow, should be used sparingly.
- Justification: When code needs to be generic or dynamic.

G20 — Hard: What is the go:embed directive? How does it work for single files, directories, and file systems? What are the limitations, and how does it interact with io/fs.FS?
- go:embed: Embeds files or directories into the binary.
- Single Files: `//go:embed file.txt`
- Directories: `//go:embed dir/`
- File Systems: `//go:embed .`
- Limitations: Only works with Go 1.16+.
- Interaction: Embedded files are accessible via `io/fs.FS`.

## Rust Answers

R1 — Easy: What is ownership in Rust? Explain the three ownership rules.
- Ownership: Rust's memory management system.
- Rules:
  1. Each value has a single owner.
  2. When owner goes out of scope, value is dropped.
  3. Only one owner at a time.

R2 — Easy: What is the difference between String and &str? When would you use each in function signatures?
- String: Owned, heap-allocated string.
- &str: Borrowed, string slice.
- Use String when you need ownership.
- Use &str when you only need a reference.

R3 — Medium: Explain borrowing and the borrow checker. What are the rules for shared (&T) and mutable (&mut T) references?
- Borrowing: Temporary access to a value.
- Borrow Checker: Ensures borrowing rules are followed.
- Rules:
  - At most one mutable reference.
  - Multiple immutable references.
  - References must not outlive the data they point to.

R4 — Medium: What is a Result<T, E> and an Option<T>? How does the ? operator work? Write a function that reads a file and returns its contents or an error.
- Result<T, E>: Represents success (Ok(T)) or error (Err(E)).
- Option<T>: Represents presence (Some(T)) or absence (None).
- ? Operator: Propagates errors.
- Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — Medium: Explain the difference between Box<T>, Rc<T>, and Arc<T>. When would you use each?
- Box<T>: Single ownership, heap allocation.
- Rc<T>: Reference counting, multiple ownership.
- Arc<T>: Thread-safe reference counting.
- Use Box for single ownership.
- Use Rc for multiple ownership in single-threaded contexts.
- Use Arc for multiple ownership in multi-threaded contexts.

R6 — Medium: What are traits in Rust? How do they compare to Go interfaces? What is a trait object (dyn Trait) vs a generic with a trait bound (T: Trait)?
- Traits: Define shared behavior.
- Go Interfaces: Similar, but Rust traits are more flexible.
- Trait Object: `dyn Trait` for dynamic dispatch.
- Generic with Trait Bound: `T: Trait` for static dispatch.

R7 — Hard: Explain lifetimes in Rust. Why does the following fail to compile, and how do you fix it?
```rust
fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() { x } else { y }
}
```
- Lifetimes: Ensure references are valid.
- Failure: Compiler cannot infer lifetimes.
- Fix: Add lifetime annotations:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — Hard: What is Send and Sync in Rust? Why can't you send an Rc<T> across threads? What makes Arc<T> safe for concurrent use?
- Send: Type can be safely transferred across threads.
- Sync: Type can be safely accessed from multiple threads.
- Rc<T>: Not Send because it's not thread-safe.
- Arc<T>: Send and Sync because it's thread-safe.

R9 — Hard: Explain how Rust's async/await works under the hood. What is a Future? What is the role of the executor (e.g., Tokio)? How does this differ from Go's goroutines?
- async/await: Syntactic sugar for working with Futures.
- Future: Represents a value that may not be ready yet.
- Executor: Runs Futures to completion.
- Difference: Go's goroutines are always running, Rust's Futures are lazy.

R10 — Medium: What is unsafe in Rust? Give 3 things you can do in an unsafe block that you can't do in safe Rust. When is unsafe justified?
- Unsafe: Code that bypasses Rust's safety guarantees.
- Things in Unsafe:
  1. Dereference raw pointers.
  2. Call unsafe functions.
  3. Access or modify static variables.
- Justified: When interacting with C code, FFI, or low-level optimizations.

R11 — Easy: What is pattern matching in Rust? How does match differ from if let? What does the compiler enforce about exhaustiveness?
- Pattern Matching: Matches values against patterns.
- match: Exhaustive pattern matching.
- if let: Partial pattern matching.
- Compiler Enforces: Exhaustiveness in match statements.

R12 — Easy: What is the difference between Vec<T> and an array [T; N]? How does Vec manage memory when elements are pushed beyond its current capacity?
- Vec<T>: Dynamic array, heap-allocated.
- [T; N]: Fixed-size array, stack-allocated.
- Vec Memory Management: Grows by allocating a new buffer and copying elements.

R13 — Easy: What are enums in Rust, and how do they differ from enums in C or Java? What is the Option<T> enum, and why does Rust not have null?
- Enums: Sum types, can hold different variants.
- C/Java Enums: Limited to integers.
- Option<T>: Represents presence (Some(T)) or absence (None).
- Rust No Null: To prevent null pointer dereferences.

R14 — Easy: Explain the impl block. What is the difference between methods that take &self, &mut self, and self? What are associated functions (e.g., String::new())?
- impl Block: Defines methods for a type.
- &self: Immutable reference.
- &mut self: Mutable reference.
- self: Consumes the value.
- Associated Functions: Functions defined in impl block, called with type name.

R15 — Easy: What is the derive macro? Give examples of commonly derived traits (Debug, Clone, PartialEq, Serialize). When can you NOT derive a trait?
- derive Macro: Automatically implements traits.
- Examples: Debug, Clone, PartialEq, Serialize.
- Cannot Derive: When trait requires custom implementation.

R16 — Medium: What is Cow<'a, T> (clone on write)? When is it useful? Give an example where it avoids unnecessary allocations compared to always cloning.
- Cow: Clone on write, represents either borrowed or owned data.
- Useful: When data is often read, rarely written.
- Example: Avoiding unnecessary cloning of large strings.

R17 — Medium: Explain Rust's module system. What is the difference between mod, use, and pub? How does the file system map to modules, and what changed between Rust 2015 and 2018 editions?
- Module System: Organizes code into modules.
- mod: Declares a module.
- use: Imports items from modules.
- pub: Makes items public.
- File System: Modules correspond to files and directories.
- Edition Changes: 2018 edition allows modules to be declared in the same file.

R18 — Hard: What is the Pin<T> type and why is it needed? How does it relate to self-referential structs and async/await? What is Unpin?
- Pin<T>: Ensures a value is not moved.
- Needed: For self-referential structs and async/await.
- Unpin: Trait indicating a type can be safely moved.

R19 — Hard: Explain Rust's macro system. What is the difference between declarative macros (macro_rules!) and procedural macros (derive, attribute, function-like)? What are hygiene rules?
- Macro System: Generates code at compile time.
- Declarative Macros: Pattern matching, expansion.
- Procedural Macros: Custom code generation.
- Hygiene Rules: Macros don't capture variables from surrounding code.

R20 — Hard: What are zero-cost abstractions in Rust? Explain how iterators, generics (monomorphization), and trait static dispatch achieve performance comparable to hand-written C while providing high-level ergonomics.
- Zero-Cost Abstractions: High-level features with no runtime overhead.
- Iterators: Optimized to avoid heap allocations.
- Generics: Monomorphization generates specialized code.
- Trait Static Dispatch: Avoids dynamic dispatch overhead.
