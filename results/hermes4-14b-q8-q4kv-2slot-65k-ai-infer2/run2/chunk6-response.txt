## JavaScript / TypeScript (20 questions)

**JS1**  
`var` is function-scoped and hoisted with initial value `undefined`. `let`/`const` are block-scoped and hoisted but not initialized. `const` declares read-only references. Hoisting means variables/functions are moved to the top of their scope during compilation.

**JS2**  
The event loop manages asynchronous operations. The call stack executes synchronous code. The microtask queue (e.g., Promises) runs after the current task completes. The macrotask queue (e.g., setTimeout) runs after the microtask queue. The event loop checks these queues in order.

**JS3**  
A closure is a function that retains access to its lexical scope. Example:
```javascript
function createCounter() {
  let count = 0;
  return function() { return ++count; };
}
const counter = createCounter();
console.log(counter()); // 1
```
The classic for loop closure bug occurs when loop variables are captured by closures. Fix with `let` or an IIFE.

**JS4**  
A `Promise` represents an eventual value. `async/await` syntactic sugar for Promises. Error handling: `try/catch` for `async/await`, `.catch()` for Promises. `Promise.allSettled` waits for all promises to settle (fulfilled/rejected), while `Promise.all` rejects on first failure.

**JS5**  
`interface` defines object shape, `type` can define primitives, unions, tuples, etc. Use `interface` for object shapes, `type` for complex types. Discriminated unions use a common property to narrow types.

**JS6**  
JavaScript uses prototypal inheritance. `Object.create()` creates an object with a specified prototype. ES6 classes are syntactic sugar over prototypes, with `class` syntax and `extends` for inheritance.

**JS7**  
`this` refers to the execution context. Binding rules (priority): 1. `new` binding, 2. explicit binding (`call/apply/bind`), 3. implicit binding (object method), 4. default binding (global/window). `bind()` returns a new function; re-binding is possible.

**JS8**  
`WeakRef` allows holding weak references to objects. `FinalizationRegistry` runs cleanup callbacks when objects are garbage collected. `WeakMap` keys must be objects to allow garbage collection of unused keys.

**JS9**  
V8 optimizes JavaScript via hidden classes (inline caches), inline caching (fast property access), and deoptimization (when assumptions fail). Deoptimization occurs with dynamic property changes, type switches, or complex operations.

**JS10**  
Tree-shaking removes unused code. Works with ES modules (static imports) but not CommonJS (dynamic `require`). CommonJS can't be tree-shaken effectively due to dynamic `require` and side effects.

**JS11**  
`null` is intentional absence, `undefined` is uninitialized. `==` coerces types, `===` checks type and value. `??` returns right-hand side if left is `null`/`undefined`. `?.` safely accesses nested properties.

**JS12**  
`map()` transforms elements, `filter()` selects elements, `reduce()` accumulates values. `reduce()` with initial value starts accumulation. `flatMap()` maps then flattens. Example: `arr.flatMap(x => [x, x*2])`.

**JS13**  
Template literals use backticks for multi-line strings and interpolation. Tagged templates apply functions to parts. Example:
```javascript
function escapeHTML(strings, ...values) {
  return strings.reduce((acc, str, i) => 
    acc + str + escape(values[i]), '');
}
```

**JS14**  
Destructuring extracts values. Object destructuring: `const {a, b} = obj`. Array destructuring: `const [x, y] = arr`. Default values: `const {a = 1} = obj`. Renaming: `const {a: b} = obj`. Rest operator: `const [x, ...rest] = arr`.

**JS15**  
`for...in` iterates over enumerable properties (object keys). `for...of` iterates over iterable values (arrays, strings). Avoid `for...in` on arrays due to inherited properties.

**JS16**  
Generics allow type parameters. Constraints: `T extends U`. Conditional types: `T extends U ? X : Y`. `infer` extracts types. Example: `function identity<T>(arg: T): T { return arg; }`.

**JS17**  
Module systems: CommonJS (`require/module.exports`) for Node.js, ES Modules (`import/export`) for browsers. Node.js handles both via `type: "module"` in `package.json`.

**JS18**  
Structural typing matches shapes. Excess property checks flag extra properties. `satisfies` enforces type without widening. Variance (`in`, `out`) controls type compatibility.

**JS19**  
`Proxy` intercepts operations. `Reflect` provides API for proxies. Example:
```javascript
const handler = {
  get(target, prop) { return prop in target ? target[prop] : 0; }
};
const proxy = new Proxy({}, handler);
```

**JS20**  
`SharedArrayBuffer` allows shared memory. `Atomics` provides atomic operations. Web Workers use shared memory with `Atomics.wait/notify` for synchronization.

## Bash (20 questions)

**B1**  
`$@` expands to quoted arguments, `$*` expands to single string. `"$@"` preserves quoting, `"$*"` joins arguments with IFS.

**B2**  
`set -e` exits on error, `-u` fails on unset variables, `-o pipefail` fails on pipe errors.

**B3**  
`$(command)` is preferred over backticks. `$((expression))` evaluates arithmetic, `expr` is legacy.

**B4**  
Process substitution `<(command)` creates temporary files. Example: `diff <(ls dir1) <(ls dir2)`.

**B5**  
Use `for f in *` or `find` with `-print0` and `xargs -0`. `for f in $(ls)` fails with spaces.

**B6**  
Here document `<<EOF` reads until EOF. Here string `<<<` reads a single string. `<<-EOF` ignores leading tabs.

**B7**  
`cmd > file 2>&1` redirects stdout then stderr. `cmd 2>&1 > file` redirects stderr then stdout. `&>` redirects both. Order matters for redirection.

**B8**  
Lock function:
```bash
lockfile() {
  local lockfile="$1"
  mkdir "$lockfile" || return 1
  trap 'rmdir "$lockfile"' EXIT
  return 0
}
```
`mkdir` is atomic for locking.

**B9**  
Single quotes preserve literals, double quotes allow interpolation, no quotes split on IFS. Example: `echo 'hello'` vs `echo "hello"` vs `echo hello`.

**B10**  
Check file: `-e`, `-d`, `-r`. `[ ]` is POSIX, `[[ ]]` is bash. Example: `if [[ -f file ]]; then ...`.

**B11**  
`$?` last exit code, `$$` PID, `$!` last background PID, `$#` argument count.

**B12**  
Define function: `foo() { ... }` or `function foo { ... }`. Return values via `echo` or `return`.

**B13**  
`PATH` is command search path. Builtins vs external commands. Check with `type -a`.

**B14**  
`trap` sets signal handlers. Example: `trap 'cleanup' EXIT`.

**B15**  
`xargs` builds command lines. `find -print0 | xargs -0` handles spaces. `xargs -P` runs in parallel.

**B16**  
Arrays: `declare -a arr`, append `arr+=(...)`, iterate `for item in "${arr[@]}"`. Associative arrays: `declare -A arr`.

**B17**  
Subshell `(...)` runs in new shell. Group `{ ...; }` runs in current shell. Piping into `while` loses changes.

**B18**  
Signals: `SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (hangup), `SIGKILL` (force kill). Handle with `trap`.

**B19**  
Parallel processing:
```bash
split -l 1000 log.txt part
xargs -P 4 -I {} process.sh {} > results.txt
```

**B20**  
`exec` replaces current process. File descriptors: `exec 3>file`, `exec 3>&-`. Coprocesses: `coproc cmd`.

## PowerShell (20 questions)

**PS1**  
`Write-Output` sends to pipeline, `Write-Host` writes to console. Use `Write-Output` for pipelines.

**PS2**  
Pipeline passes objects. `ForEach-Object` processes pipeline input, `foreach` is a loop.

**PS3**  
`[PSCustomObject]` is an object, `[hashtable]` is a dictionary. Use objects for structured data.

**PS4**  
Terminating errors stop execution, non-terminating errors continue. `-ErrorAction` controls behavior. `try/catch` handles terminating errors.

**PS5**  
Splatting passes parameters as hashtable. Example: `$params = @{Name='value'}; cmd @params`.

**PS6**  
`Invoke-Command` runs commands remotely. `Enter-PSSession` starts interactive session. Uses WinRM/SSH.

**PS7**  
Function returns array. `$x.GetType().Name` is `Object[]`. Return single item with `return $result`.

**PS8**  
`[scriptblock]` is a code block. Pass to remote with `-ArgumentList`. Double-hop solved with CredSSP.

**PS9**  
`@()` creates array, `[array]` casts. Force array: `$array = @($item)`. `$null` vs empty array.

**PS10**  
Comparison operators: `-eq` (equal), `-like` (pattern), `-contains` (array). Case-sensitive variants.

**PS11**  
Module: reusable code. Script module (.psm1), manifest (.psd1), binary. `Import-Module` loads.

**PS12**  
String interpolation: `"..."` allows expressions, `'...'` is literal. Here-string: `@"..."@`.

**PS13**  
`Get-Member` shows object properties. `Select-Object` selects properties, `Where-Object` filters.

**PS14**  
Classes (v5) are simplified C# classes. Limitations: no inheritance, interfaces. Use for complex objects.

**PS15**  
`[CmdletBinding()]` enables advanced functions. `Begin`, `Process`, `End` blocks. `SupportsShouldProcess` for confirmation.

**PS16**  
Providers map resources to file system. `Get-ChildItem` works across providers. Access registry: `Get-ChildItem HKLM:\`.

**PS17**  
Runspaces enable parallel execution. `ForEach-Object -Parallel` (v7+) vs manual runspace management.

**PS18**  
`PSScriptAnalyzer` checks code quality. Rules, severity, custom rules. Integrate with CI/CD.

**PS19**  
`$using:` scope passes variables to remote. `ArgumentList` passes parameters. Serialization limits.

**PS20**  
DSC configures systems. Replaced by infrastructure-as-code tools like Terraform.
