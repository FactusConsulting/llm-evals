## JavaScript / TypeScript (20 questions)

**JS1 — Easy: Explain the difference between var, let, and const. What is hoisting?**  
- `var`: Function-scoped, hoisted to the top of its scope, can be redeclared and updated.  
- `let`: Block-scoped, hoisted but not initialized (TDZ: Temporal Dead Zone), cannot be redeclared but can be updated.  
- `const`: Block-scoped, hoisted but not initialized, cannot be redeclared or updated (but object/array properties can be modified).  
- **Hoisting**: Variables and functions are moved to the top of their scope during compilation. `var` is initialized as `undefined`, while `let`/`const` are not initialized until their declaration is reached.  

**JS2 — Easy: What is the event loop? Explain the relationship between the call stack, microtask queue, and macrotask queue.**  
- **Event Loop**: Mechanism that processes asynchronous operations by continuously checking the call stack and task queues.  
- **Call Stack**: Executes synchronous code. When it’s empty, the event loop checks the queues.  
- **Microtask Queue**: Holds promises (`.then`, `.catch`, `.finally`) and `queueMicrotask()`. Processed after the current task completes, before the next macrotask.  
- **Macrotask Queue**: Holds tasks like `setTimeout`, `setInterval`, I/O, UI events. Processed after the microtask queue is empty.  
- **Order**: Call Stack → Microtask Queue → Macrotask Queue.  

**JS3 — Medium: What is a closure? Give a practical example. What is the classic for loop closure bug, and how do you fix it?**  
- **Closure**: A function that retains access to its lexical scope even when executed outside that scope.  
- **Example**:  
  ```javascript
  function createCounter() {
    let count = 0;
    return function() { return ++count; };
  }
  const counter = createCounter();
  console.log(counter()); // 1
  ```  
- **Closure Bug**: In a `for` loop, the loop variable is shared across iterations, leading to unexpected behavior:  
  ```javascript
  for (let i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100);
  } // Logs 0, 1, 2 (correct with `let`)
  ```  
  **Fix**: Use `let` (block-scoped) instead of `var` (function-scoped) to create a new binding per iteration.  

**JS4 — Medium: Explain Promise, async/await, and how error handling works with both. What is Promise.allSettled vs Promise.all?**  
- **Promise**: Represents an eventual value. Resolves (fulfilled) or rejects.  
- **async/await**: Syntactic sugar for promises. `async` functions return promises, and `await` pauses execution until the promise resolves.  
- **Error Handling**:  
  - **Promises**: `.catch()` or `try/catch` with `await`.  
  - **async/await**: `try/catch` around `await` calls.  
- **Promise.all**: Rejects immediately if any promise rejects.  
- **Promise.allSettled**: Waits for all promises to settle (resolve/reject), returns an array of results.  

**JS5 — Medium: What is the difference between TypeScript's interface and type? When would you use each? What are discriminated unions?**  
- **Interface**:  
  - Can be extended/implemented.  
  - Can be merged (e.g., `interface A { x: number }` and `interface A { y: string }` become `{ x: number; y: string }`).  
  - Used for object shapes and type checking.  
- **Type**:  
  - Can represent primitive types, unions, intersections, and tuples.  
  - Cannot be merged or extended.  
  - Used for complex types (e.g., `type T = string | number`).  
- **Discriminated Unions**: A union type where a common property (discriminant) determines the type of other properties. Example:  
  ```typescript
  type Shape = 
    | { kind: 'circle'; radius: number }
    | { kind: 'square'; side: number };
  ```  

**JS6 — Medium: Explain prototypal inheritance in JavaScript. How does Object.create() work? How do ES6 classes relate to prototypes?**  
- **Prototypal Inheritance**: Objects inherit properties/methods from other objects (prototypes).  
- **Object.create(proto)**: Creates a new object with `proto` as its prototype.  
- **ES6 Classes**: Syntactic sugar over prototypes. Class methods are added to the prototype, and `extends` sets up the prototype chain.  

**JS7 — Hard: Explain the `this` keyword in JavaScript. What are the 4 binding rules (in priority order)? What does bind() return, and can you re-bind it?**  
- **`this`**: Refers to the execution context.  
- **Binding Rules (Priority)**:  
  1. **New Binding**: When a function is called with `new`, `this` is the new object.  
  2. **Explicit Binding**: When `call()`, `apply()`, or `bind()` is used, `this` is set explicitly.  
  3. **Implicit Binding**: When a function is called as a method, `this` is the object before the dot.  
  4. **Default Binding**: When none of the above apply, `this` is the global object (or `undefined` in strict mode).  
- **bind()**: Returns a new function with `this` permanently set. The returned function cannot be re-bound.  

**JS8 — Hard: What is WeakRef and FinalizationRegistry? When would you use them? Explain why WeakMap keys must be objects and how this relates to garbage collection.**  
- **WeakRef**: Allows holding a reference to an object without preventing its garbage collection. Used for caching or memoization.  
- **FinalizationRegistry**: Registers callbacks to be called when an object is garbage collected. Used for cleanup (e.g., releasing native resources).  
- **WeakMap**: Keys must be objects because they are weakly referenced. If the key is garbage collected, the entry is removed. This prevents memory leaks.  

**JS9 — Hard: Explain how the V8 engine optimizes JavaScript. Cover: hidden classes, inline caching, and deoptimization. What coding patterns cause deoptimization?**  
- **Hidden Classes**: V8 assigns hidden classes to objects to optimize property access. Changing property order or adding properties creates new hidden classes.  
- **Inline Caching**: Caches property access patterns to speed up lookups.  
- **Deoptimization**: Occurs when assumptions (e.g., property order) are violated.  
- **Deoptimization Patterns**:  
  - Modifying property order.  
  - Adding/removing properties dynamically.  
  - Using `delete` on properties.  
  - Using `eval` or `with`.  

**JS10 — Medium: What is tree-shaking? How does it work with ES modules vs CommonJS? Why can't CommonJS be tree-shaken effectively?**  
- **Tree-shaking**: Removing unused code (dead code elimination).  
- **ES Modules**: Static imports/exports allow static analysis to identify unused exports.  
- **CommonJS**: Dynamic `require()` and `module.exports` make it impossible to statically determine unused code.

**JS14 — Easy: What is destructuring in JavaScript? Explain object destructuring, array destructuring, default values, and renaming. How does the rest operator (...) work in destructuring?**

**JS16 — Medium: Explain TypeScript generics. What are generic constraints (extends), conditional types (T extends U ? X : Y), and the infer keyword? Give a practical example of each.**

**JS17 — Medium: What is the module system in JavaScript? Explain the differences between CommonJS (require/module.exports), ES Modules (import/export), and how Node.js handles both. What is the "type": "module" field in package.json?**  
- **CommonJS**: Uses `require()` and `module.exports`. Synchronous, dynamic.

- **Excess Property Checks**: Warns about extra properties in object literals when assigning to a type.  
- **extends vs satisfies**:  
  - `extends`: Checks if a type is compatible with another.  
  - `satisfies`: Ensures a value conforms to a type without changing the value’s type.

  - `out`: Contravariant (e.g., function parameters).  

**JS19 — Hard: What are Proxy and Reflect in JavaScript? How do you intercept property access, assignment, and function calls? Give a practical example (e.g., validation, logging, or reactive data binding).**  
- **Proxy**: Wraps an object to intercept operations.  
- **Reflect**: Provides methods to perform operations on objects (e.g., `Reflect.get`, `Reflect.set`).  
- **Example (Validation)**:  
  ```javascript
  const validator = {
    get(target, prop) {
      if (prop in target) return Reflect.get(target, prop);
      throw new Error(`Invalid property: ${prop}`);
    }
  };
  const proxy = new Proxy({}, validator);
  ```  

**JS20 — Hard: Explain SharedArrayBuffer and Atomics in JavaScript. How do Web Workers communicate using shared memory? What are the ordering guarantees, and how does Atomics.wait/Atomics.notify work?**  
- **SharedArrayBuffer**: Allows multiple threads to access the same memory.  
- **Atomics**: Provides atomic operations (e.g., `Atomics.add`, `Atomics.compareExchange`).  
- **Web Workers**: Use `SharedArrayBuffer` to share memory.  
- **Ordering Guarantees**: Operations are atomic and ordered.  
- **Atomics.wait/notify**:  
  - `Atomics.wait()`: Blocks until a condition is met.  
  - `Atomics.notify()`: Wakes up waiting threads.  

## Bash (20 questions)

**B1 — Easy: What is the difference between $@ and $*? What about "$@" vs "$*"?**  
- **$@**: Expands to all positional parameters, preserving word boundaries.  
- **$***: Expands to all positional parameters as a single string.  
- **"$@"**: Expands to all positional parameters, each quoted.  
- **"$***": Expands to all positional parameters as a single string (same as `$*`).  

**B2 — Easy: What does `set -euo pipefail` do? Explain each flag.**  
- **-e**: Exit immediately if a command exits with a non-zero status.  
- **-u**: Treat unset variables as an error.  
- **-o pipefail**: Causes a pipeline to return the exit status of the last command that failed, or zero if all succeed.  

**B3 — Medium: What is the difference between $(command) and `command`? What about $((expression)) vs expr?**  
- **$(command)**: Command substitution (modern, nested).  
- **`command`**: Command substitution (legacy, cannot be nested).  
- **$((expression))**: Arithmetic expansion (modern, supports variables).  
- **expr**: Command for arithmetic operations (legacy, less efficient).  

**B4 — Medium: Explain process substitution (<(command)) and when you would use it. Give a practical example with diff.**  
- **Process Substitution**: Treats the output of a command as a file.  
- **Example**:  
  ```bash
  diff <(sort file1) <(sort file2)
  ```  
  Compares sorted versions of `file1` and `file2` without creating temporary files.  

**B5 — Medium: How do you safely iterate over files with spaces or special characters in their names? Why is `for f in $(ls)` dangerous?**  
- **Safe Iteration**:  
  ```bash
  for f in *; do
    # Use "$f" to handle spaces
  done
  ```  
- **Danger of `for f in $(ls)`**: `ls` splits filenames on spaces, leading to incorrect iteration.  

**B6 — Medium: What is a here document (<<EOF) vs a here string (<<<)? What does <<-EOF do differently?**  
- **Here Document (<<EOF)**: Input until `EOF` is encountered.  
- **Here String (<<<)**: Input a single string.  
- **Here Document with <<-EOF**: Ignores leading tabs when matching `EOF`.  

**B7 — Hard: Explain the difference between these redirections:  
```bash
cmd > file 2>&1
cmd 2>&1 > file
cmd &> file
```  
Why do the first two produce different results?**  
- **`cmd > file 2>&1`**: Redirects stdout to `file`, then redirects stderr to stdout (which is `file`).  
- **`cmd 2>&1 > file`**: Redirects stderr to stdout (which is the terminal), then redirects stdout to `file`.  
- **`cmd &> file`**: Redirects both stdout and stderr to `file`.  
- **Difference**: The first two produce different results because the order of redirections matters.

**B17 — Hard: What is the difference between a subshell (...) and a group command { ...; }? How does each affect variable scope and exit codes? Why does piping into a while loop lose variable changes?**
