## .NET / C# Answers

DN1 — Easy: 
- Class: Reference type, heap-allocated, can have inheritance and polymorphism.
- Struct: Value type, stack-allocated (or inline in containing type), no inheritance (except interfaces), passed by value.
- Use struct for small, immutable data that doesn't require inheritance or polymorphism (e.g., Point, Vector).

DN2 — Easy: 
- IEnumerable<T>: In-memory collection, deferred execution (e.g., List<T>.Where).
- IQueryable<T>: Database query, translated to SQL, executed on the server.
- Distinction matters: IQueryable<T> enables LINQ-to-SQL/EF Core, while IEnumerable<T> is for in-memory operations.

DN3 — Medium: 
- async/await: Asynchronous programming model. async marks a method as async, await suspends execution until a Task completes.
- Task: Represents an asynchronous operation, can be awaited.
- ValueTask: Lightweight alternative to Task for short-lived operations, avoids heap allocation.
- Use ValueTask when the async operation is likely to complete synchronously.

DN4 — Medium: 
- Dependency Injection (DI): Pattern for decoupling object creation from usage.
- Service Lifetimes:
  - Transient: New instance per request.
  - Scoped: New instance per scope (e.g., HTTP request).
  - Singleton: Single instance per application.
- Common bug: Injecting Scoped service into Singleton causes memory leaks and thread-safety issues.

DN5 — Medium: 
- string: Immutable, heap-allocated.
- ReadOnlySpan<char>: Stack-allocated, no heap allocation, faster for string processing.
- Use Span<T> for performance-critical string operations (e.g., parsing).

DN6 — Medium: 
- .NET GC: Automatic memory management.
- Generations: Gen 0 (new objects), Gen 1 (survived Gen 0), Gen 2 (survived Gen 1).
- Large Object Heap (LOH): Objects >85KB, collected less frequently.
- IDisposable: Manual cleanup for unmanaged resources (e.g., file handles). GC handles managed resources.

DN7 — Hard: 
- ConfigureAwait(false): Avoids capturing the current SynchronizationContext, allowing continuation on a thread pool thread.
- Use: UI apps (e.g., WPF, WinForms) to prevent UI thread blocking.
- Don't use: If you need to return to the original context (e.g., ASP.NET Core).
- Relates to SynchronizationContext: Controls where async continuations resume.

DN8 — Hard: 
- .NET 8/9 Features:
  - Primary Constructors: Simplified class initialization.
  - Collection Expressions: Concise collection initialization.
  - FrozenDictionary: Immutable dictionary.
- Example:
```csharp
public class Service([Required] IHttpClientFactory httpClientFactory) : IMyService
{
    public async Task<string> GetDataAsync() => await httpClientFactory.CreateClient().GetAsync("url");
}
```

DN9 — Hard: 
- Cause: DbContext injected as Singleton instead of Scoped.
- Fix: Register DbContext as Scoped in DI container.
- EF Core: DbContext is designed for Scoped lifetime to ensure thread safety and proper disposal.

DN10 — Medium: 
- record: Immutable, value-based equality, auto-generated methods.
- record struct: Immutable struct, value-based equality.
- Choose: record for reference types, record struct for small, immutable value types.

DN11 — Easy: 
- ref: Pass by reference (mutable).
- out: Pass by reference (must be assigned in method).
- in: Pass by reference (immutable).
- Use: ref for performance, out for returning multiple values, in for read-only parameters.

DN12 — Easy: 
- Nullable Reference Types: ? annotation indicates a reference type can be null.
- #nullable enable: Enables nullable context.
- Difference: Nullable reference types (string?) vs nullable value types (int?).

DN13 — Easy: 
- LINQ: Language Integrated Query.
- Method syntax: list.Where(...).
- Query syntax: from x in list where ... select x.
- Deferred execution: Query not executed until enumerated.

DN14 — Easy: 
- Generic Constraints:
  - where T : class: Reference type.
  - where T : struct: Value type.
  - where T : new(): Has parameterless constructor.
  - where T : IComparable<T>: Implements IComparable<T>.
- Combine: Use multiple constraints for complex requirements.

DN15 — Easy: 
- Abstract class: Can have implementation, partial implementation.
- Interface: No implementation (pre-C# 8), default methods (C# 8+).
- Default interface methods: Allow adding new methods to interfaces without breaking existing implementations.

DN16 — Medium: 
- Middleware Pipeline: ASP.NET Core request processing pipeline.
- app.Use(): Add middleware to pipeline.
- app.Map(): Route requests to different middleware branches.
- app.Run(): Terminate pipeline.
- Ordering: Middleware order matters (e.g., authentication before authorization).
- Exception Handling: Use app.UseExceptionHandler().

DN17 — Medium: 
- Channel<T>: Bounded, thread-safe producer-consumer queue.
- BlockingCollection<T>: Unbounded, thread-safe collection.
- Example:
```csharp
var channel = Channel.CreateBounded<int>(10);
await channel.Writer.WriteAsync(42);
int value = await channel.Reader.ReadAsync();
```

DN18 — Hard: 
- Source Generators: Generate code at compile time.
- Difference: Faster than reflection/IL weaving, no runtime overhead.
- Incremental Generator: More efficient than ISourceGenerator, tracks inputs/outputs.
- Preferred: Incremental generators for better performance.

DN19 — Hard: 
- TPL Dataflow: Library for building dataflow pipelines.
- ActionBlock: Executes actions on messages.
- TransformBlock: Transforms messages.
- BufferBlock: Buffers messages.
- Compare: Channels for producer-consumer, TPL Dataflow for complex pipelines.

DN20 — Hard: 
- Minimal APIs: Simplified API development in .NET 6+.
- Difference: No controllers, attributes, or routing configuration.
- Trade-offs: Less testability, limited middleware, no OpenAPI support.
- Route Groups: Organize endpoints.
- Endpoint Filters: Customize request processing.

## Python Answers

P1 — Easy: 
- list: Mutable, ordered.
- tuple: Immutable, ordered.
- set: Mutable, unordered, unique elements.
- frozenset: Immutable, unordered, unique elements.

P2 — Easy: 
- GIL: Global Interpreter Lock, allows only one thread to execute Python bytecode at a time.
- Affects: CPU-bound workloads.
- Workarounds: Multiprocessing, C extensions.

P3 — Medium: 
- copy: Shallow copy (copies references).
- deepcopy: Deep copy (copies all objects).
- Example: Shallow copy of nested list causes unexpected behavior.

P4 — Medium: 
- Decorators: Modify function behavior.
- Example:
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.2f}s")
        return result
    return wrapper
```

P5 — Medium: 
- Generators: Functions that yield values.
- yield: Produces a value and suspends execution.
- yield from: Delegates to another generator.
- Difference: Generators produce values on-the-fly, lists store all values.

P6 — Medium: 
- asyncio event loop: Manages async tasks.
- asyncio.run(): Runs async function.
- asyncio.gather(): Runs multiple async functions concurrently.
- asyncio.create_task(): Schedules async function.
- time.sleep(): Blocks the event loop.

P7 — Hard: 
- MRO: Method Resolution Order.
- Algorithm: C3 linearization.
- Diamond Inheritance: D(B, C), B(A), C(A).
- Output: "C" (C overrides A's who method).

P8 — Hard: 
- Metaclass: Class of a class.
- __init_subclass__: Hook for subclass initialization.
- Use Case: Metaclass for class-level validation, __init_subclass__ for subclass-specific setup.

P9 — Hard: 
- multiprocessing: Parallel execution using separate processes.
- threading: Parallel execution using threads.
- concurrent.futures: High-level interface for asynchronous execution.
- Serialization: Multiprocessing requires pickling objects.

P10 — Medium: 
- __slots__: Restricts instance attributes.
- Use: Reduce memory overhead, prevent dynamic attribute creation.
- Memory Impact: Smaller memory footprint.

P11 — Easy: 
- Virtual Environment: Isolated Python environment.
- Use: Avoid package conflicts.
- Difference: venv (standard), virtualenv (third-party), conda (package manager).

P12 — Easy: 
- List/Dict/Set Comprehensions: Concise way to create collections.
- Relation: Equivalent to map() and filter() but more readable.
- Preference: Comprehensions for readability, map/filter for functional style.

P13 — Easy: 
- ==: Value equality.
- is: Identity equality.
- Object Interning: Small integers and strings are interned.

P14 — Easy: 
- *args: Variable positional arguments.
- **kwargs: Variable keyword arguments.
- /: Positional-only parameters.
- *: Keyword-only parameters.

P15 — Easy: 
- Context Managers: Manage resources (e.g., files).
- Implementation: __enter__/__exit__ or @contextmanager.
- Example: Database connection.

P16 — Medium: 
- Type Hinting: Static type checking.
- typing.Union: Multiple types.
- Optional: Union[T, None].
- Literal: Specific literal values.
- TypeVar: Generic type variable.
- Protocol: Structural subtyping.
- Static Analysis: Tools like mypy/pyright use these for type checking.

P17 — Medium: 
- Data Model: Dunder methods define object behavior.
- __repr__: Unambiguous string representation.
- __str__: Human-readable string representation.
- __eq__: Equality comparison.
- __hash__: Hash value for hashing.
- __getattr__: Attribute access.
- __getattribute__: Attribute access (overrides __getattr__).
- __eq__ without __hash__: Object is unhashable.

P18 — Hard: 
- Descriptors: Objects that define attribute access.
- Descriptor Protocol: __get__, __set__, __delete__.
- Use: property, classmethod, staticmethod.

P19 — Hard: 
- Import System: Mechanism for loading modules.
- Relative vs Absolute Imports: Relative imports use dots, absolute imports use full path.
- sys.path: Module search path.
- PYTHONPATH: Environment variable for module search path.
- __init__.py: Marks directory as package.
- Namespace Packages: Packages without __init__.py.
- Finder: Finds modules.
- Loader: Loads modules.

P20 — Hard: 
- dataclasses: Decorator for generating boilerplate code.
- Comparison: attrs (similar to dataclasses), Pydantic (data validation).
- __post_init__: Custom initialization.
- Field Factories: Lazy initialization.
- Frozen Dataclasses: Immutable dataclasses.
- Inheritance: Dataclasses can inherit from other dataclasses.
- Pydantic: Use for data validation and serialization.
