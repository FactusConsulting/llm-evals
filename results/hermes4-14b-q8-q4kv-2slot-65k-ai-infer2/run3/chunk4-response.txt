## Go (20 questions)

G1 — Easy: 
- An array has a fixed size defined at compile time, while a slice is a dynamically-sized view into an underlying array.
- When you append to a slice that has reached its capacity, Go allocates a new underlying array (typically double the size), copies the existing elements, and returns a new slice pointing to the new array.

G2 — Easy:
- `var x int` declares a variable x of type int and initializes it to the zero value (0).
- `x := 0` is a short variable declaration that declares and initializes x to 0.
- You cannot use `:=` to declare a variable that has already been declared in the same scope.

G3 — Medium:
- A goroutine is a lightweight thread of execution managed by the Go runtime, not the OS. Goroutines are multiplexed onto a smaller number of OS threads.
- The Go scheduler (GMP model) manages goroutines (G), which run on multiple OS threads (P), which are managed by the scheduler (M). This allows efficient concurrency.

G4 — Medium:
- Channels are typed conduits through which you can send and receive values with the channel operator `<-`.
- An unbuffered channel requires a sender and receiver to be ready simultaneously. A buffered channel holds a fixed number of values without a receiver.
- Sending to a full buffered channel blocks until there is space.

G5 — Medium:
- The context package is used to carry deadlines, cancellation signals, and other request-scoped values across API boundaries.
- Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
resp, err := http.Get("https://example.com", ctx)
```

G6 — Medium:
- Go interfaces are satisfied implicitly by any type that implements the methods, without explicit declaration.
- Unlike Java/C#, Go interfaces don't require explicit implementation declaration.
- `interface{}` is the empty interface, which can hold any type. It's powerful for generic programming but dangerous because it bypasses type safety.

G7 — Hard:
- The code is unsafe because the `ready` flag and `data` variable are accessed by multiple goroutines without synchronization, leading to a race condition.
- Correct alternatives: Use a channel to signal readiness, or use `sync.Mutex` to protect access to `ready` and `data`.

G8 — Hard:
- `sync.Mutex` is for exclusive access, while `sync.RWMutex` allows multiple readers or a single writer.
- `sync.Map` is optimized for concurrent access to a map with many goroutines, while a regular map with a mutex is simpler but may have higher contention.
- Trade-offs: `sync.Map` has higher overhead for small maps, while a regular map with a mutex is simpler and more predictable.

G9 — Hard:
- Go modules manage dependencies and versions. `go.mod` defines module path, dependencies, and versions. `go.sum` contains checksums for dependencies.
- `go mod tidy` adds missing and removes unused dependencies.
- MVS (Minimum Version Selection) algorithm selects the smallest version of each dependency that satisfies all requirements.

G10 — Medium:
- `defer` schedules a function call to run after the surrounding function returns.
- Multiple defers execute in LIFO order.
- A common gotcha: using a loop variable in a deferred function can lead to unexpected behavior due to late binding.

G11 — Easy:
- A pointer is a variable that holds the memory address of another variable.
- The zero value of a pointer is `nil`.
- Create a pointer to a struct literal: `&MyStruct{Field: value}`.

G12 — Easy:
- `init()` is a special function that runs before the `main` function.
- A package can have multiple `init()` functions, which execute in the order they appear in the source file.

G13 — Easy:
- `make` initializes slices, maps, and channels. `new` allocates memory for a type and returns a pointer to it.
- `make` works with slices, maps, and channels. `new` works with any type.

G14 — Easy:
- Go uses explicit error handling with the `error` interface.
- The idiomatic pattern is to return an error as the last return value and check it with `if err != nil`.
- `errors.Is` checks for equality using `==` on the underlying error, while `errors.As` checks if the error is of a specific type.

G15 — Easy:
- Built-in composite types: map, slice, channel, struct.
- Zero values: map → nil, slice → nil, channel → nil, struct → all fields zero.

G16 — Medium:
- A race condition occurs when multiple goroutines access shared data concurrently without proper synchronization.
- The `-race` flag enables the race detector to find data races.
- Example: Accessing a shared variable without a mutex. Fix: Use `sync.Mutex` or a channel.

G17 — Medium:
- `select` waits on multiple channel operations. It differs from `switch` by waiting on channel operations.
- If multiple cases are ready, one is chosen at random.
- Implement a timeout with `select` and a `time.After` channel.

G18 — Hard:
- Escape analysis determines whether a variable should be allocated on the stack or heap.
- The compiler decides based on whether the variable escapes the current function.
- Inspect with `-gcflags="-m"`. It matters for performance as heap allocations are slower.

G19 — Hard:
- The `reflect` package provides runtime reflection.
- `reflect.Type` represents the type of a value, while `reflect.Value` represents the value itself.
- Reflection has performance costs and should be used judiciously. Code generation is often preferred for performance-critical code.

G20 — Hard:
- The `go:embed` directive embeds files into the binary.
- It works for single files, directories, and file systems.
- Limitations: Only works with files in the same directory or subdirectories. Interacts with `io/fs.FS` for embedded file systems.

## Rust (20 questions)

R1 — Easy:
- Ownership is Rust's system for managing memory. The three rules are: each value has a single owner, ownership is transferred when assigned, and when the owner goes out of scope, the value is dropped.

R2 — Easy:
- `String` is an owned, heap-allocated string. `&str` is a borrowed, immutable string slice.
- Use `String` when you need ownership, and `&str` when you need a reference to a string.

R3 — Medium:
- Borrowing allows temporary access to a value without taking ownership.
- Rules: At any given time, you can have either one mutable reference or any number of immutable references. References must always be valid.

R4 — Medium:
- `Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents presence (`Some(T)`) or absence (`None`).
- The `?` operator propagates errors.
- Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — Medium:
- `Box<T>` is a smart pointer for heap allocation. `Rc<T>` is a reference-counted pointer for single-threaded use. `Arc<T>` is a thread-safe reference-counted pointer.
- Use `Box` for heap allocation, `Rc` for single-threaded shared ownership, and `Arc` for multi-threaded shared ownership.

R6 — Medium:
- Traits define shared behavior. They are similar to Go interfaces but more powerful.
- Trait objects (`dyn Trait`) allow dynamic dispatch, while generic trait bounds (`T: Trait`) allow static dispatch.
- Go interfaces are more limited compared to Rust traits.

R7 — Hard:
- The code fails because the returned string slice may outlive the input slices.
- Fix: Return a `String` instead of a `&str` to ensure ownership.

R8 — Hard:
- `Send` means a type can be safely transferred between threads. `Sync` means a type can be safely accessed from multiple threads.
- `Rc<T>` is not `Send` because it's not thread-safe. `Arc<T>` is `Send` and `Sync` because it uses atomic reference counting.

R9 — Hard:
- Rust's async/await uses futures, which are values that represent asynchronous computations.
- The executor (e.g., Tokio) drives the execution of futures.
- This differs from Go's goroutines, which are managed by the runtime.

R10 — Medium:
- `unsafe` allows bypassing Rust's safety guarantees. Three things you can do: dereference raw pointers, call unsafe functions, and access or modify static mutable variables.
- `unsafe` is justified when performance is critical or when interfacing with unsafe code.

R11 — Easy:
- Pattern matching allows matching values against patterns.
- `match` is exhaustive, while `if let` is not.
- The compiler enforces exhaustiveness for `match` statements.

R12 — Easy:
- `Vec<T>` is a dynamically-sized vector, while `[T; N]` is a fixed-size array.
- `Vec` manages memory by reallocating when elements are pushed beyond capacity.

R13 — Easy:
- Enums in Rust are algebraic data types. They differ from C/Java enums by allowing associated data.
- `Option<T>` is an enum representing presence or absence. Rust does not have null to prevent null pointer dereferences.

R14 — Easy:
- The `impl` block defines methods for a type.
- `&self` is an immutable reference, `&mut self` is a mutable reference, and `self` takes ownership.
- Associated functions are functions defined in the `impl` block that don't take `self`.

R15 — Easy:
- The `derive` macro automatically implements traits.
- Commonly derived traits: `Debug`, `Clone`, `PartialEq`, `Serialize`.
- You cannot derive traits that require custom implementation.

R16 — Medium:
- `Cow<'a, T>` (clone on write) is a smart pointer that can either borrow or own data.
- It's useful when you want to avoid unnecessary cloning. Example: parsing a string that may be modified.

R17 — Medium:
- Rust's module system organizes code into modules.
- `mod` declares a module, `use` imports items, and `pub` makes items public.
- The file system maps to modules. Rust 2018 edition changed how modules are declared.

R18 — Hard:
- `Pin<T>` ensures that a value cannot be moved. It's needed for self-referential structs and async/await.
- `Unpin` is a trait indicating that a type can be safely moved.

R19 — Hard:
- Rust has two types of macros: declarative (`macro_rules!`) and procedural (derive, attribute, function-like).
- Hygiene rules ensure that macros don't accidentally capture variables from the surrounding code.

R20 — Hard:
- Zero-cost abstractions are high-level features that don't incur runtime overhead.
- Iterators, generics (monomorphization), and trait static dispatch achieve performance comparable to hand-written C while providing high-level ergonomics.
