## JavaScript / TypeScript Answers

**JS1 — Easy: Explain the difference between var, let, and const. What is hoisting?**
- `var`: Function-scoped, hoisted to the top of its scope with `undefined` initial value.
- `let`: Block-scoped, hoisted but not initialized (temporal dead zone until declaration).
- `const`: Block-scoped, hoisted but not initialized; cannot be reassigned.
- **Hoisting**: Variables/declarations are moved to the top of their scope during compilation, but assignments remain in place.

**JS2 — Easy: What is the event loop? Explain the relationship between the call stack, microtask queue, and macrotask queue.**
- **Event Loop**: Mechanism that processes asynchronous operations by checking queues after the call stack is empty.
- **Call Stack**: Executes synchronous code in LIFO order.
- **Microtask Queue**: Holds promises' `.then()`/`.catch()` callbacks and `queueMicrotask()`. Processed after the current task completes.
- **Macrotask Queue**: Holds tasks like `setTimeout`, `setInterval`, I/O, and UI events. Processed after microtasks.

**JS3 — Medium: What is a closure? Give a practical example. What is the classic for loop closure bug, and how do you fix it?**
- **Closure**: A function that retains access to its lexical scope even when executed outside that scope.
- **Example**:
  ```javascript
  function createCounter() {
    let count = 0;
    return function() { return ++count; };
  }
  const counter = createCounter();
  console.log(counter()); // 1
  ```
- **Closure Bug**: In a loop, all functions share the same outer scope (e.g., `i` in `for`).
- **Fix**: Use `let` (block-scoped) or an IIFE to capture the current value:
  ```javascript
  for (let i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100); // 0, 1, 2
  }
  ```

**JS4 — Medium: Explain Promise, async/await, and how error handling works with both. What is Promise.allSettled vs Promise.all?**
- **Promise**: Represents an eventual value or error. States: pending, fulfilled, rejected.
- **async/await**: Syntactic sugar for promises. `async` functions return promises; `await` pauses execution until a promise resolves.
- **Error Handling**:
  - **Promises**: `.catch()` for errors, or `try/catch` with `await`.
  - **async/await**: `try/catch` around `await` statements.
- **Promise.all**: Rejects on the first rejection.
- **Promise.allSettled**: Waits for all promises to settle (fulfilled or rejected), returns an array of results.

**JS5 — Medium: What is the difference between TypeScript's interface and type? When would you use each? What are discriminated unions?**
- **Interface**: Declares object shapes, can be extended, and supports declaration merging.
- **Type**: Defines types (including primitives, unions, intersections, etc.) but cannot be extended.
- **Use Cases**:
  - **Interface**: For object shapes, especially when extending or merging.
  - **Type**: For complex types (e.g., unions, tuples) or when declaration merging isn't needed.
- **Discriminated Unions**: A union type with a common property (discriminant) to narrow types:
  ```typescript
  type Shape = Circle | Square;
  interface Circle { kind: "circle"; radius: number; }
  interface Square { kind: "square"; side: number; }
  ```

**JS6 — Medium: Explain prototypal inheritance in JavaScript. How does Object.create() work? How do ES6 classes relate to prototypes?**
- **Prototypal Inheritance**: Objects inherit properties/methods from other objects via a prototype chain.
- **Object.create(proto)**: Creates a new object with `proto` as its prototype.
- **ES6 Classes**: Syntactic sugar over prototypes. `class` defines a constructor and methods, with `extends` setting up the prototype chain.

**JS7 — Hard: Explain the `this` keyword in JavaScript. What are the 4 binding rules (in priority order)? What does bind() return, and can you re-bind it?**
- **`this`**: Context of the current execution, determined by how a function is called.
- **Binding Rules (Priority)**:
  1. **Explicit Binding**: `call()`, `apply()`, `bind()`.
  2. **New Binding**: When a function is called with `new`.
  3. **Implicit Binding**: When a function is a method of an object.
  4. **Default Binding**: When `this` is not explicitly set (global object or `undefined` in strict mode).
- **bind()**: Returns a new function with `this` permanently set. Cannot be re-bound.

**JS8 — Hard: What is WeakRef and FinalizationRegistry? When would you use them? Explain why WeakMap keys must be objects and how this relates to garbage collection.**
- **WeakRef**: Allows holding a weak reference to an object, letting it be garbage collected.
- **FinalizationRegistry**: Registers callbacks to run when an object is garbage collected.
- **Use Cases**: Memory-sensitive caches, avoiding retain cycles.
- **WeakMap Keys**: Must be objects to allow garbage collection of keys when no strong references exist.

**JS9 — Hard: Explain how the V8 engine optimizes JavaScript. Cover: hidden classes, inline caching, and deoptimization. What coding patterns cause deoptimization?**
- **Hidden Classes**: V8 assigns hidden classes to objects for fast property access.
- **Inline Caching**: Caches property access results to speed up repeated lookups.
- **Deoptimization**: Occurs when assumptions (e.g., hidden class) are violated, reverting to slower code.
- **Deoptimization Triggers**: Dynamic property additions, type changes, or `delete` operations.

- **Tree-Shaking**: Removing unused code during bundling.
- **ES Modules**: Static imports/exports allow analyzers to identify unused exports.
- **CommonJS**: Dynamic `require()` and module.exports make unused code detection difficult.

**JS14 — Easy: What is destructuring in JavaScript? Explain object destructuring, array destructuring, default values, and renaming. How does the rest operator (...) work in destructuring?**

**JS15 — Easy: What is the difference between for...in and for...of? What does each iterate over? Why should you avoid for...in on arrays?**

**JS16 — Medium: Explain TypeScript generics. What are generic constraints (extends), conditional types (T extends U ? X : Y), and the infer keyword? Give a practical example of each.**
- **Generics**: Define reusable components with type parameters.
- **Generic Constraints**: `extends` restricts type parameters to specific types.
- **Conditional Types**: `T extends U ? X : Y` selects a type based on a condition.
- **infer**: Extracts types from conditional types.
- **Examples**:
  ```typescript
  // Constraint
  function identity<T extends number>(arg: T): T { return arg; }
  // Conditional Type
  type IsString<T> = T extends string ? true : false;
  // infer
  type ReturnType<T> = T extends (...args: any[]) => infer R ? R : any;
  ```

**JS17 — Medium: What is the module system in JavaScript? Explain the differences between CommonJS (require/module.exports), ES Modules (import/export), and how Node.js handles both. What is the "type": "module" field in package.json?**
- **CommonJS**: Uses `require()` and `module.exports` for synchronous module loading.
- **ES Modules**: Uses `import`/`export` for static module loading.
- **Node.js Handling**: Supports both via `require` (CJS) and `import` (ESM). `"type": "module"` in `package.json` enables ESM.

**JS18 — Hard: Explain TypeScript's structural type system. What are excess property checks, and when do they apply? What is the difference between extends and satisfies? How does variance (in, out) work in TypeScript 4.7+?**
- **Structural Typing**: Types are compatible if they have the same shape, not based on names.
- **Excess Property Checks**: Warns about extra properties in object literals.
- **extends vs satisfies**: `extends` enforces a type; `satisfies` checks against a type without enforcing it.
- **Variance**: `in` (covariant) and `out` (contravariant) control type compatibility in generics.

**JS19 — Hard: What are Proxy and Reflect in JavaScript? How do you intercept property access, assignment, and function calls? Give a practical example (e.g., validation, logging, or reactive data binding).**
- **Proxy**: Wraps an object to intercept operations.
- **Reflect**: Provides methods for object operations.
- **Interception**: Use traps like `get`, `set`, `apply`.
- **Example**:
  ```javascript
  const handler = {
    get(target, prop) { return target[prop] || 'default'; }
  };
  const proxy = new Proxy({}, handler);
  console.log(proxy.foo); // 'default'
  ```

**JS20 — Hard: Explain SharedArrayBuffer and Atomics in JavaScript. How do Web Workers communicate using shared memory? What are the ordering guarantees, and how does Atomics.wait/Atomics.notify work?**
- **SharedArrayBuffer**: Allows multiple agents to share memory.
- **Atomics**: Provides atomic operations on shared memory.
- **Web Workers**: Use `SharedArrayBuffer` and `Atomics` for synchronized communication.
- **Ordering Guarantees**: Atomics ensure operations are atomic and ordered.
- **Atomics.wait/notify**: Pauses and resumes threads based on conditions.

## Bash Answers

**B1 — Easy: What is the difference between $@ and $*? What about "$@" vs "$*"?**
- **$@**: Expands to all positional parameters, each as a separate word.
- **$***: Expands to all positional parameters as a single word.
- **"$@"**: Expands to all positional parameters, each quoted.
- **"$***": Expands to all positional parameters as a single word (may break on spaces).

**B2 — Easy: What does `set -euo pipefail` do? Explain each flag.**
- **-e**: Exit immediately if a command exits with a non-zero status.
- **-u**: Treat unset variables as an error.
- **-o pipefail**: Exit with the status of the last command in a pipeline that failed.

**B3 — Medium: What is the difference between $(command) and `command`? What about $((expression)) vs expr?**
- **$(command)**: Command substitution (modern, preferred).
- **`command`**: Command substitution (legacy, less readable).
- **$((expression))**: Arithmetic expansion (evaluates expressions).
- **expr**: Command-line calculator (less efficient than $((...))).

**B4 — Medium: Explain process substitution (<(command)) and when you would use it. Give a practical example with diff.**
- **Process Substitution**: Allows a command's output to be treated as a file.
- **Example**:
  ```bash

  ```

**B5 — Medium: How do you safely iterate over files with spaces or special characters in their names? Why is `for f in $(ls)` dangerous?**
- **Safe Iteration**: Use `for f in *; do ...; done` or `find -print0 | xargs -0`.
- **Danger of `for f in $(ls)`**: `ls` splits filenames on spaces, leading to incorrect iteration.

**B6 — Medium: What is a here document (<<EOF) vs a here string (<<<)? What does <<-EOF do differently?**
- **Here Document (<<EOF)**: Input until EOF marker.
- **Here String (<<<)**: Input a single string.
- **<<-EOF**: Allows leading tabs in the EOF marker.

**B7 — Hard: Explain the difference between these redirections:
```bash
cmd > file 2>&1
cmd 2>&1 > file
cmd &> file
```
Why do the first two produce different results?**
- **`cmd > file 2>&1`**: Redirects stdout to file, then redirects stderr to stdout (file).
- **`cmd 2>&1 > file`**: Redirects stderr to stdout (original stdout), then redirects stdout to file (stderr goes to original stdout).
- **`cmd &> file`**: Redirects both stdout and stderr to file.
- **Difference**: The order of redirections matters.

**B8 — Hard: Write a bash function that safely creates a lock file with proper cleanup, handles race conditions, and works correctly if the script is killed with SIGTERM. Explain why mkdir is preferred over file creation for locking.**
