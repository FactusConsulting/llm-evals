## .NET / C# (20 questions)

DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?
- Class: Reference type, heap-allocated, supports inheritance, can be null.
- Struct: Value type, stack-allocated (or inline in containing type), no inheritance, always non-null.
- Use struct for small, immutable data types (e.g., Point, Vector) to avoid heap allocation overhead.

DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?
- IEnumerable<T>: In-memory enumeration (LINQ to Objects).
- IQueryable<T>: Represents a query that can be translated to SQL (LINQ to Entities).
- Distinction matters: IQueryable<T> queries are translated to SQL and executed on the database, while IEnumerable<T> queries are executed in-memory. Using IQueryable<T> with Entity Framework enables efficient database queries.

DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?
- async/await: Asynchronous programming model. async marks a method as asynchronous, await suspends execution until a Task completes.
- Task: Represents an asynchronous operation. Can be awaited.
- ValueTask: Lightweight alternative to Task for methods that may complete synchronously. Avoids heap allocation.
- Use ValueTask when the async method may often complete synchronously (e.g., cached results).

DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?
- DI: Pattern for achieving Inversion of Control (IoC). Services are registered with a container and resolved at runtime.
- Lifetimes:
  - Transient: New instance per request.
  - Scoped: New instance per scope (e.g., HTTP request).
  - Singleton: Single instance shared across all requests.
- Bug: Injecting a Scoped service into a Singleton causes the Scoped service to be created once and reused, leading to state corruption under concurrent requests.

DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?
- string: Immutable, heap-allocated.
- ReadOnlySpan<char>: Immutable, stack-allocated (or inline), can point to string, array, or memory.
- Use Span<T> for high-performance, low-allocation scenarios (e.g., parsing, buffer processing).

DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?
- GC: Automatic memory management. Collects unreachable objects.
- Generations: Gen 0 (new objects), Gen 1 (survived Gen 0), Gen 2 (survived Gen 1). Helps optimize collection.
- Large Object Heap (LOH): Special heap for objects >85KB. Collected less frequently.
- IDisposable: Interface for releasing unmanaged resources (e.g., file handles, database connections). GC doesn't manage unmanaged resources.

DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?
- ConfigureAwait(false): Avoids capturing the current SynchronizationContext. Returns to the thread pool.
- Default: Captures the current SynchronizationContext (e.g., UI thread).
- Use ConfigureAwait(false) in library code or when you don't need to return to the original context. Avoid in UI code that requires context-specific execution.
- Relates to SynchronizationContext: Controls where the continuation runs.

DN8 — Hard: Explain the new .NET 8/9 features: primary constructors, collection expressions, and FrozenDictionary. Write a minimal example using primary constructors with DI.
- Primary Constructors: Simplified constructor syntax for classes/records.
- Collection Expressions: Concise way to create collections.
- FrozenDictionary: Immutable dictionary.
- Example:
  ```csharp

  {
      public Service(ILogger logger, string config) { /* ... */ }
  }
  ```

DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?
- Cause: DbContext is registered as Scoped, but injected into a Singleton service. Under high concurrency, the Singleton service outlives the Scoped DbContext, leading to disposal.
- Fix: Ensure DbContext is injected only into Scoped or Transient services. Avoid injecting Scoped services into Singletons.
- Interaction: DbContext is typically Scoped, meaning a new instance per HTTP request. Singletons should not depend on Scoped services.

DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?
- record: Immutable, value-based equality, positional pattern matching.
- class: Mutable, reference-based equality.
- record struct: Immutable, value-based equality, stack-allocated.
- Choose record for immutable data types. Use class for mutable objects. Use record struct for small, immutable value types.

DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?
- ref: Pass by reference (variable must be initialized).
- out: Pass by reference (variable can be uninitialized, must be assigned before return).
- in: Pass by reference (read-only).
- Use ref for modifying the original variable. Use out for returning multiple values. Use in for read-only access.

DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?
- Nullable reference types: Compile-time checks for nullability. ? indicates a reference type can be null.
- #nullable enable: Enables nullable context.
- Difference: Nullable reference types are compile-time checks, while nullable value types (int?) are runtime constructs.

DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?
- LINQ: Language Integrated Query. Provides query capabilities for .NET.
- Method syntax: Fluent API (e.g., list.Where(...)).
- Query syntax: SQL-like syntax (e.g., from x in list where ...).
- Deferred execution: Queries are not executed until enumerated (e.g., ToList(), foreach).

DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?
- Generic constraints: Limit the types that can be used with a generic type.
- where T : class: T must be a reference type.
- where T : struct: T must be a value type.
- where T : new(): T must have a parameterless constructor.
- where T : IComparable<T>: T must implement IComparable<T>.
- Combine constraints when multiple requirements are needed (e.g., where T : class, IComparable<T>).

DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?
- Abstract class: Can have both abstract and concrete members. Can have state.
- Interface: Can only have abstract members (pre-C# 8). Cannot have state.
- Default interface methods: Allow interfaces to have concrete members. Reduces the need for abstract classes in some cases.

DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?
- Middleware pipeline: Sequence of components that handle requests.
- app.Use(): Adds middleware to the pipeline.
- app.Map(): Creates a branch in the pipeline based on path.
- app.Run(): Adds a terminal middleware.
- Ordering: Middleware order determines execution sequence.
- Exception handling: Middleware can catch exceptions and handle them.

DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.
- Channel<T>: Asynchronous producer-consumer queue.
- BlockingCollection<T>: Synchronous producer-consumer collection.
- Example:

DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?
- Source Generators: Generate code during compilation.
- Reflection: Inspect and invoke code at runtime.
- IL weaving: Modify IL at runtime.

DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?
- TPL Dataflow: Library for building dataflow pipelines.

DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?
- Minimal APIs: Simplified API development using endpoint routing.

## Python (20 questions)

P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?
- list: Mutable, ordered, allows duplicates.
- tuple: Immutable, ordered, allows duplicates.
- set: Mutable, unordered, no duplicates.
- frozenset: Immutable, unordered, no duplicates.

P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?
- GIL: Prevents multiple native threads from executing Python bytecodes simultaneously.
- Affects: CPU-bound workloads.
- Workarounds: Use multiprocessing, C extensions, or async I/O.

P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.
- copy: Shallow copy (copies references).
- deepcopy: Deep copy (copies all objects).
- Example: Shallow copy of a list of lists causes changes to nested lists to affect the original.

P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.
- Decorators: Functions that modify other functions.
- Example:
  ```python
  import time
  def timer(func):
      def wrapper(*args, **kwargs):
          start = time.time()
          result = func(*args, **kwargs)
          print(f"{func.__name__} took {time.time() - start} seconds")
          return result
      return wrapper
  ```

P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?
- Generators: Functions that produce a sequence of values using yield.
- yield: Produces a value and suspends execution.
- yield from: Delegates to another generator.
- Difference: Generators produce values on-the-fly, while returning a list produces all values at once.

P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?
- asyncio event loop: Manages asynchronous tasks.
- asyncio.run(): Runs the top-level coroutine.
- asyncio.gather(): Runs multiple coroutines concurrently.
- asyncio.create_task(): Schedules a coroutine to run.
- time.sleep() blocks the event loop. Use asyncio.sleep() instead.

P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?
```python
class A:
    def who(self): return "A"
class B(A):
    pass
class C(A):
    def who(self): return "C"
class D(B, C):
    pass
print(D().who())
```
- MRO: Order in which base classes are searched for methods.
- Algorithm: C3 linearization.
- Diamond inheritance: D inherits from B and C, which both inherit from A.
- Output: "C" because C's who() method is found before A's.

P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.
- Metaclass: Class of a class. Controls class creation.
- __init_subclass__: Hook for initializing subclasses.
- Use case for metaclass: Enforcing class structure. Use case for __init_subclass__: Customizing subclass initialization.

P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?
- multiprocessing: Uses separate processes. Bypasses GIL. Serialization via pickling.
- threading: Uses threads. Affected by GIL for CPU-bound tasks.
- concurrent.futures: High-level interface for threading/multiprocessing.
- Use multiprocessing for CPU-bound tasks. Use threading for I/O-bound tasks. Use concurrent.futures for simplified concurrency.

- __slots__: Restricts instance attributes to a predefined set.
