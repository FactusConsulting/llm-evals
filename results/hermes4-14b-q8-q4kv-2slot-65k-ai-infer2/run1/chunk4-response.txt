## Go Answers

G1 — Easy:  
A slice is a dynamically-sized view into an array, while an array has a fixed size. When you append to a slice that has reached its capacity, Go allocates a new underlying array, copies the elements, and returns a new slice with the updated capacity.

G2 — Easy:  
`var x int` declares a variable `x` of type `int` with the zero value (0). `x := 0` is a short declaration that infers the type. You cannot use `:=` in a function body if the variable already exists in the same scope.

G3 — Medium:  
A goroutine is a lightweight thread managed by the Go runtime. Unlike OS threads, goroutines are multiplexed onto a smaller number of OS threads. The Go scheduler (GMP model: G for goroutine, M for OS thread, P for processor) manages goroutines, allowing efficient concurrency.

G4 — Medium:  
Channels are typed conduits for passing values between goroutines. Unbuffered channels require a receiver to be ready, while buffered channels allow sending up to their capacity without a receiver. Sending to a full buffered channel blocks until space is available.

G5 — Medium:  
The context package manages request-scoped values, cancellation signals, and deadlines. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
resp, err := http.Get("https://example.com", ctx)
```

G6 — Medium:  
Go interfaces are satisfied implicitly if a type implements all methods. Unlike Java/C#, Go doesn't require explicit declaration. `interface{}` (empty interface) accepts any type but can be unsafe if used without type assertions.

G7 — Hard:  
The code is unsafe because `ready` and `data` are written by one goroutine and read by another without synchronization. The loop `for !ready {}` can cause a deadlock if `ready` is never set. Correct alternatives include using channels or mutexes.

G8 — Hard:  
`sync.Mutex` locks for both read and write, while `sync.RWMutex` allows multiple readers or a single writer. Use `sync.Map` for concurrent map access without external locking; it's slower but avoids external mutexes.

G9 — Hard:  
Go modules manage dependencies. `go.mod` lists module requirements, while `go.sum` stores checksums for reproducibility. `go mod tidy` adds missing and removes unused dependencies. MVS selects the minimal version satisfying all requirements.

G10 — Medium:  
`defer` schedules a function call to run after the surrounding function returns. Multiple defers execute in LIFO order. A common gotcha is reusing the same variable in a loop, leading to unexpected behavior.

G11 — Easy:  
A pointer holds the memory address of a value. The zero value is `nil`. Create a pointer to a struct literal with `&MyStruct{}`.

G12 — Easy:  
`init()` runs before `main()` and is used for package initialization. A package can have multiple `init()` functions, which execute in the order they appear in the source file.

G13 — Easy:  
`make` initializes slices, maps, and channels. `new` allocates memory and returns a pointer to the zero value of a type. `make` works with reference types, while `new` works with any type.

G14 — Easy:  
Go uses the `error` interface (`error.Error() string`) for errors. The idiomatic pattern is `if err != nil { ... }`. `errors.Is` checks for a specific error type, while `errors.As` extracts a type from an error chain.

G15 — Easy:  
Built-in composite types:  
- `map`: `nil`  
- `slice`: `nil`  
- `channel`: `nil`  
- `struct`: zero values of its fields

G16 — Medium:  
A race condition occurs when goroutines access shared data concurrently without synchronization. The `-race` flag detects data races. Example fix with `sync.Mutex`:
```go
var mu sync.Mutex
mu.Lock()
data = "hello"
ready = true
mu.Unlock()
```

G17 — Medium:  
`select` waits on multiple channel operations. It differs from `switch` by handling channels. If multiple cases are ready, one is chosen non-deterministically. Timeout with `select`:
```go
select {
case <-done:
    // ...
case <-time.After(5 * time.Second):
    // timeout
}
```

G18 — Hard:  
Escape analysis determines if a variable escapes to the heap. The compiler decides based on usage. You can inspect with `-gcflags="-m"`. Stack allocation is faster, while heap allocation is necessary for long-lived data.

G19 — Hard:  
The `reflect` package provides runtime type inspection. `reflect.Type` describes a type, while `reflect.Value` holds a value. Reflection is slow and should be used sparingly; code generation is often preferred.

G20 — Hard:  
`go:embed` embeds files into the binary. It supports single files, directories, and file systems. Limitations include no support for dynamic paths. It interacts with `io/fs.FS` for embedded file systems.

## Rust Answers

R1 — Easy:  
Ownership in Rust ensures memory safety. Rules:  
1. Each value has exactly one owner.  
2. When the owner goes out of scope, the value is dropped.  
3. Only one mutable reference or multiple immutable references exist at a time.

R2 — Easy:  
`String` is an owned, growable string, while `&str` is a borrowed, immutable string slice. Use `String` when ownership is needed, and `&str` for borrowing.

R3 — Medium:  
Borrowing allows temporary access to data. Rules:  
- At most one mutable reference.  
- Multiple immutable references allowed.  
- References must not outlive the data they point to.

R4 — Medium:  
`Result<T, E>` represents success (`Ok`) or failure (`Err`). `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator propagates errors. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — Medium:  
- `Box<T>`: heap allocation.  
- `Rc<T>`: reference counting for single-threaded use.  
- `Arc<T>`: thread-safe reference counting. Use `Box` for owned data, `Rc` for single-threaded shared ownership, and `Arc` for multi-threaded.

R6 — Medium:  
Traits define shared behavior. Go interfaces are similar but require explicit declaration. Trait objects (`dyn Trait`) allow dynamic dispatch, while generic trait bounds (`T: Trait`) enable static dispatch.

R7 — Hard:  
The code fails because the returned string slice may outlive the inputs. Fix with lifetimes:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — Hard:  
`Send` allows types to be safely transferred between threads. `Sync` allows shared access. `Rc<T>` isn't `Send` because it's not thread-safe. `Arc<T>` is `Send` and `Sync` due to atomic reference counting.

R9 — Hard:  
Rust's `async/await` uses `Future` types. The executor (e.g., Tokio) drives futures to completion. Unlike Go's goroutines, futures are explicit and require an executor.

R10 — Hard:  
`unsafe` allows operations like dereferencing raw pointers, calling unsafe functions, and violating borrowing rules. Justified for FFI, performance-critical code, or when the compiler can't prove safety.

R11 — Easy:  
Pattern matching with `match` or `if let`. `match` requires exhaustiveness, while `if let` handles a single case. The compiler enforces that all variants are covered.

R12 — Easy:  
`Vec<T>` is a growable array, while `[T; N]` is a fixed-size array. `Vec` manages memory by reallocating when capacity is exceeded.

R13 — Easy:  
Enums in Rust are algebraic data types. `Option<T>` represents presence/absence. Rust avoids null by using `Option`.

R14 — Easy:  
`impl` blocks define methods. `&self` is immutable, `&mut self` is mutable, and `self` consumes the value. Associated functions (e.g., `String::new()`) don't require an instance.

R15 — Easy:  
`derive` generates code for traits. Common examples: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive for non-trivial traits or when manual implementation is needed.

R16 — Medium:  
`Cow<'a, T>` (clone on write) avoids unnecessary cloning. Useful when data might be borrowed or owned. Example:
```rust
let s = "hello";
let cow: Cow<str> = Cow::Borrowed(s);
```

R17 — Medium:  
Modules organize code. `mod` declares a module, `use` imports items, and `pub` controls visibility. Rust 2018 simplified module paths.

R18 — Hard:  
`Pin<T>` prevents moving data. Needed for self-referential structs and async/await. `Unpin` indicates types that can be safely moved.

R19 — Hard:  
`macro_rules!` defines declarative macros. Procedural macros (`derive`, `attribute`, `function-like`) generate code at compile time. Hygiene rules prevent variable capture.

R20 — Hard:  
Zero-cost abstractions mean high-level features have no runtime overhead. Iterators, generics (monomorphization), and trait static dispatch achieve this by compiling to efficient machine code.
