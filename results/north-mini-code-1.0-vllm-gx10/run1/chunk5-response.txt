**DN6 — Medium**  
The .NET GC divides objects into **generations** to collect short‑lived objects quickly:  

- **Gen 0**: newly allocated, most objects die here.  
- **Gen 1**: survivors from Gen 0 after a collection.  
- **Gen 2**: long‑lived objects, collected less frequently.  

The **Large Object Heap (LOH)** holds objects ≥ 85 KB; they are allocated directly in Gen 2 and collected only during full GC cycles, which can cause pauses.  

**`IDisposable`** gives deterministic release of unmanaged resources (file handles, sockets, database connections). Even though the GC will eventually finalize objects, waiting for finalizers can lead to resource exhaustion; `IDisposable` lets you free those resources promptly.

**DN7 — Hard**  
`ConfigureAwait(false)` tells an awaiter **not** to capture the current `SynchronizationContext` (e.g., ASP.NET Core’s UI context).  

- **Default (`true`)**: preserves the captured context, causing the continuation to resume on the original thread/context (useful for UI apps to update controls).  
- **`false`**: suppresses context capture, letting the continuation run on the thread pool, which improves performance and avoids deadlocks in async pipelines.  

**When to use `false`**: library code, background services, any place where you don’t need to resume on a specific UI thread and want to avoid deadlocks.  

**When NOT to use `false`**: UI or WinForms/WPF apps where you must update UI elements on the UI thread; you need the captured context to safely invoke UI code.

**DN14 — Easy**  
Generic constraints restrict what types can be used for a type parameter `T`:  

- `where T : class` – `T` must be a reference type (not `struct`, not `null`).  
- `where T : struct` – `T` must be a value type (e.g., `int`, `DateTime`).

You can combine constraints, e.g., `where T : class, IComparable<T>, new()`. The order matters: reference‑type constraints first, then interface, then `new()`.

**DN16 — Medium**  
The ASP.NET Core middleware pipeline is a **delegation chain**: each middleware receives a `RequestDelegate` (the next middleware) and decides whether to handle the request, modify it, or pass it along.  

- `app.Use(...)`: adds middleware that runs **before** the next middleware (typically for request processing, logging, authentication).  
- `app.Map(...)`: conditionally adds a branch of middleware based on the request path (e.g., `app.MapWhen(ctx => ctx.Request.Path.StartsWithSegments("/api"))`).  
- `app.Run(...)`: terminates the pipeline; the provided delegate is the final request handler (e.g., endpoint execution).  

**Ordering matters** because middleware runs in the order it’s added; later middleware runs after earlier ones unless they call `next()`.  

**Exception handling middleware** (e.g., `UseExceptionHandler`) is usually added early; it catches unhandled exceptions, logs them, and can rewrite the response. Because it sits before other middleware, it can intercept errors that would otherwise propagate.

**DN17 — Medium**  
`Channel<T>` (from `System.Threading.Channels`) is a **unbounded or bounded** channel that provides a **producer‑consumer** model with async/await support. `BlockingCollection<T>` is a higher‑level wrapper around a `ConcurrentQueue<T>` that also supports blocking/enumerating but is built on `ThreadPool` synchronization primitives.  

**Example – bounded channel for backpressure:**  

```csharp
var channel = new Channel<int>(new BoundedChannelOptions(10)
{
    FullMode = BoundedChannelFullMode.Wait // block producers when full
});

var writer = ChannelWriter.Create<int>(channel.Writer);
var reader = ChannelReader.Create<int>(channel.Reader);

// Producer task
async Task Producer()
{
    for (int i = 0; i < 100; i++)
    {
        await writer.WriteAsync(i); // blocks if buffer full
    }
    await writer.CompleteAsync();
}

// Consumer task
async Task Consumer()
{
    await foreach (var item in channel.Reader.ReadAllAsync())
    {
        Console.WriteLine(item);
    }
}
```

When the channel fills, `WriteAsync` blocks the producer, providing backpressure to the consumer.

**DN18 — Hard**  
**Source Generators** are compilers that generate C# source code at compile time based on attributes or interfaces in the target project. They differ from:  

- **Reflection**: runs at runtime, inspecting types/methods.  
- **IL Weaving** (PostSharp, Unity): modifies IL after compilation, can be heavy and requires extra assemblies.  

A **Source Generator** runs during compilation, producing new source files that are compiled together with the rest of the code, enabling compile‑time diagnostics, reduced runtime overhead, and better IDE support.

**DN19 — Hard**  
**TPL Dataflow (`System.Threading.Tasks.Dataflow`)** provides reusable, composable dataflow blocks for asynchronous pipelines:  

- **`ActionBlock<T>`**: consumes items, runs a synchronous or async `Action<T>` (or `Func<T, Task>`).  
- **`TransformBlock<TInput, TOutput>`**: applies a transformation function to each input, producing output.  
- **`BufferBlock<T>`**: holds items in a first‑in‑first‑out buffer, allowing producers and consumers to operate at different rates.  

**Comparison with `System.Threading.Channels`**:  
- **Dataflow** is higher‑level, offering built‑in error handling, cancellation support, and visual debugging in Visual Studio.  
- **Channels** are lower‑level, focusing on async/await ergonomics and are more lightweight; they require manual handling of completion and backpressure.  

Both solve producer‑consumer scenarios, but choose Dataflow for complex orchestration and Channels for high‑throughput, low‑allocation pipelines.

**P2 — Easy**  
The **Global Interpreter Lock (GIL)** is a mutex in CPython that prevents multiple native threads from executing Python bytecode simultaneously. It protects internal data structures, making the interpreter single‑threaded for CPU‑bound code.  

**Affected workloads:** pure Python loops, CPU‑intensive calculations, and any code that releases the GIL only briefly.  

**Workarounds:**  
- Use **multiprocessing** to bypass the GIL (spawn separate processes).  
- Use **C extensions** (e.g., NumPy, pandas) that release the GIL or run in native code.  
- Use **asyncio** with async I/O for I/O‑bound tasks.

**P3 — Medium**  
- **Shallow copy** duplicates the container but references the same objects inside.  
- **Deep copy** recursively copies contained objects, creating independent duplicates.

**P4 — Medium**  
A decorator is a callable that wraps another function, extending its behavior without modifying its source.  

**Decorator that logs execution time:**

```python
import time
from functools import wraps

def log_execution_time(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{func.__name__} took {elapsed:.4f} seconds")
        return result
    return wrapper

# Usage
@log_execution_time
def compute():
    time.sleep(0.5)
    return 42
```

The decorator preserves the original function’s name, docstring, and signature via `wraps`.

**P7 — Hard**  

Python 3 uses **C3 linearization** for Method Resolution Order (MRO). It creates a deterministic order by merging the inheritance lists of each class, ensuring monotonicity and no diamond ambiguity.  

Given the classes:

```python
class A:
    def who(self): return "A"
class B(A):
    pass
class C(A):
    def who(self): return "C"
class D(B, C):
    pass
```

The MRO of `D` is `D -> B -> C -> A -> object`. Since `B` does not override `who`, it inherits from `A`. `C` overrides `who` with `"C"`. Therefore `D().who()` returns `"C"`.

- `TypeVar` – defines generic type variables (`T = TypeVar('T')`).  
- `Protocol` – defines structural interfaces (duck‑typing) for static checking.  

Tools like **mypy** or **pyright** read these hints, infer types, and report mismatches, enabling early bug detection and better IDE support.

---

**P17 — Medium**  

Python’s data model defines special **dunder** methods:  

- `__repr__` – unambiguous, developer‑focused representation (`repr(obj)`).  
- `__str__` – human‑readable string (`str(obj)`); defaults to `__repr__` if not defined.  

- `__eq__` – defines value equality; `__hash__` – defines hash for use in hash‑based collections. If you define `__eq__` but not `__hash__`, the object becomes **unhashable** (Python sets `__hash__ = None`).  

- `__getattr__` – called when attribute lookup fails; `__getattribute__` – called for **all** attribute accesses (including existing ones). Overriding `__getattribute__` can break attribute resolution if not careful.

---

**P18 — Hard**  

A **descriptor** implements the **descriptor protocol**: `__get__(self, obj, type=None)`, `__set__(self, obj, value)`, `__delete__(self, obj)`. It defines behavior for attribute access on a class or instance.  

- **`property`** uses descriptors to create read/write/compute‑only attributes.  
- **`classmethod`** and **`staticmethod`** are also descriptors that bind methods differently (to the class or skip instance binding).  

Descriptors enable powerful features like data validation, computed attributes, and metaclass‑level behavior.

---

**P19 — Hard**  

Python’s import system works via **finders** (locate a module) and **loaders** (execute the module).  

- **Absolute import**: `import sys` – looks up names in `sys.path`.  
- **Relative import**: `from . import sibling` – resolves relative to the current package.  

`sys.path` determines where modules are searched; `PYTHONPATH` extends it. `__init__.py` marks a directory as a package (though PEP 420 allows “namespace packages” without it).  

A **finder** (`MetaPathFinder`, `PathEntryFinder`) decides if a module can be found; a **loader** (`SourceFileLoader`, `SourcelessFileLoader`) reads the source and executes it to create a module object.

---

**P20 — Hard**  

**Dataclasses** (`@dataclass`) automatically generate `__init__`, `__repr__`, `__eq__`, `__hash__` (if `frozen=True` or `unsafe_hash=True`), and `__post_init__` for custom logic.  

- **`__post_init__`**: runs after generated `__init__`; useful for computed fields or validation.  
- **Field factories**: `field(default_factory=list)` creates a new mutable default per instance.  
- **Frozen dataclasses**: immutable; cannot assign attributes after creation.  

**Inheritance**: dataclasses support inheritance; child classes inherit parent fields and can add new ones, but `__init__` signatures are combined.  

**Comparison**:  

- **attrs** – similar to dataclasses but more concise (`@attr.s`), supports converters, and has a smaller runtime footprint.  
- **Pydantic** – data‑validation focused; can generate JSON schemas, perform type coercion, and support complex validation rules.  

**When to choose Pydantic over dataclasses:** When you need robust validation, serialization (JSON), configuration management, or dynamic schema generation (e.g., APIs, config files). Dataclasses are fine for simple data containers and when you prefer minimal dependencies.<|END_TEXT|>
