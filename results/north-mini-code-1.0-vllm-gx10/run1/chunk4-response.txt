A **slice** `[]T` is a lightweight view over an underlying array (usually heap‑allocated) with three components: a pointer to the data, a length, and a capacity. Appending to a slice (`append`) may require a new underlying array if the current capacity is exceeded; the runtime copies the old elements to the new array, updates the slice’s pointer/length/capacity, and returns the (possibly new) slice. If capacity is still available, `append` simply stores the new element in‑place and returns the same slice.

**G2** – `var x int` declares a variable `x` with the zero value of `int` (0) and makes `x` usable in the whole scope. `x := 0` is a short‑assignment that also declares `x` **and** initializes it to 0, but it can only be used **inside a function** (or a method body). You cannot use `:=` at package level, to redeclare an existing top‑level variable, or to assign to an already declared variable without a new declaration.

**G3** – A **goroutine** is a lightweight thread managed by the Go runtime, not an OS thread. It runs concurrently on a set of OS threads (the “M”‑threads) scheduled by the Go scheduler. The **GMP model**:  
- **G**oroutine – user‑level coroutine.  
- **M**achine – OS thread that executes Go code.  
- **P**rocessor – a set of runnable goroutines (a work‑stealing queue).  
The scheduler multiplexes Gs onto Ms, switching on preemption, I/O, or `Go` statements, achieving high concurrency with far fewer OS threads than tasks.

**G4** – A **channel** (`chan T`) provides synchronous communication between goroutines. An **unbuffered** channel blocks the sender until a receiver is ready (handshake). A **buffered** channel (`chan T` with capacity `N`) can hold up to `N` values; the sender blocks only when the buffer is full. Sending to a full buffered channel blocks until a receiver consumes an element, after which the send proceeds.

**G5** – `context.Context` carries deadlines, cancellation signals, and other request‑scoped values. It enables cooperative cancellation across APIs that may start background work.  

```go
req, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel() // ensure resources are released

client := &http.Client{}
resp, err := client.Get(req.URL.String()) // replace with actual URL
if err != nil {
    return fmt.Errorf("HTTP request failed: %w", err)
}
defer resp.Body.Close()
```

If the context times out or is cancelled, the underlying HTTP request is aborted via the `Request.Context()` mechanism.

**G6** – Go’s **interface satisfaction** is structural: a type implements an interface implicitly if it provides all the required method signatures, regardless of explicit declaration. Unlike Java/C# where a class must `implements` an interface, Go never “implements” an interface; the compiler checks satisfaction at compile time.  

The **empty interface** `interface{}` (or `any`) can hold values of **any** type. It is powerful because it allows heterogeneous collections and dynamic dispatch, but dangerous because type safety is lost—runtime type assertions (`.(T)`) are needed, and mistakes can cause panics.

**G7** – Go’s memory model guarantees that writes performed by one goroutine become visible to others **only** after proper synchronization (e.g., `sync.Mutex`, atomic operations, or channel communication). The snippet is unsafe because the write to `ready` and `data` are not atomic nor synchronized; the compiler/CPU may reorder or cache them, so the main goroutine may see a stale `ready` value and never observe `data`.  

Correct alternatives:  
- Use `sync.Mutex`/`sync.Once` to protect the writes.  
- Use atomic primitives: `atomic.StoreBool(&ready, true)` and `atomic.LoadBool`.  
- Use a channel to signal completion.  

Example with atomic:

```go
var ready atomic.Bool
var data atomic.Value // stores interface{}; we can store string

go func() {
    data.Store("hello")
    ready.Store(true)
}()

for !ready.Load() {}
fmt.Println(data.Load().(string))
```

**G8** – `sync.Mutex` provides exclusive access; `sync.RWMutex` allows many concurrent readers (`RLock`) but exclusive writer (`Lock`). Use `RWMutex` when reads vastly outnumber writes.  

`sync.Map` is a concurrent hash‑map optimized for scenarios with frequent insertions/deletions and reads, without needing a separate mutex. It trades off higher per‑operation overhead for simplicity and avoids the “forgotten mutex” bug. For workloads with stable keys and high read‑throughput, a regular `map` protected by a `RWMutex` is usually faster because `sync.Map` uses atomic operations and may cause more cache contention.

**G9** – **Go modules** (`go.mod`) provide a declarative, versioned dependency graph. `go.mod` lists required modules, their versions, and replacements. `go.sum` stores cryptographic hashes of downloaded module files to ensure reproducibility and protect against tampering.  

`go mod tidy` adds any missing imports’ dependencies, removes unused ones, and updates `go.mod` to reflect the current module’s needs.  

The **Minimum Version Selection (MVS)** algorithm selects the lowest compatible version of each module that satisfies all requirements, ensuring reproducible builds while allowing upgrades.

**G10** – `defer` schedules a function call to run when the surrounding function returns (either normally or via panic). Multiple `defer`s execute **LIFO** (last‑in, first‑out).  

Gotcha in a loop:

```go
for i := 0; i < 3; i++ {
    defer fmt.Println(i) // prints 2,1,0 (the loop variable captured)
}
```

The loop variable `i` is captured by the closure; by the time the defers run, `i` has its final value (2). Fix by using a local copy:

```go
for i := 0; i < 3; i++ {
    i := i // create a new binding
    defer fmt.Println(i)
}
```

**G11** – A **pointer** holds the memory address of a variable. Its zero value is `nil`. To create a pointer to a struct literal:

```go
p := &struct{ name string }{name: "Alice"}
```

**G12** – `init()` is a special function that the Go compiler automatically calls at package initialization time (after all global variables are set, before the program’s `main`). A package may contain multiple `init()` functions; they are executed in the order they appear in the source files, with files sorted lexicographically by filename.

**G13** – `new(T)` allocates memory for a zero‑initialized value of type `T` and returns a pointer `*T`. It works only for **reference types** (`*T`, `map[K]V`, `chan T`, `func…`).  

`make(T)` allocates and initializes **slice, map, or channel** values and returns the concrete type (not a pointer). It panics if used on other types.

**G14** – Errors are values implementing the `error` interface (`Error() string`). Idiomatic checking:

```go
if err := someFunc(); err != nil {
    return fmt.Errorf("wrapper: %w", err)
}
```

`errors.Is(err, target)` traverses wrapped errors (`Unwrap`) to compare with `target` (useful for sentinel errors). `errors.As(err, &target)` attempts to cast `err` (or any wrapped error) to a specific type. Both are more robust than `==` because they follow the error chain.

**G16** – A **race condition** occurs when two goroutines concurrently access the same data and at least one performs a write, leading to unpredictable results. The `-race` flag instruments the program with thread‑sanitizer‑like checks; it inserts logging and detects data races at runtime, printing a report on failure.  

Example race:

```go
var cnt int
go func(){ cnt++ }()
go func(){ cnt++ }()
fmt.Println(cnt) // may print 1 instead of 2
```

Fix with a mutex:

```go
var mu sync.Mutex
var cnt int
go func(){
    mu.Lock(); defer mu.Unlock(); cnt++
}
go func(){
    mu.Lock(); defer mu.Unlock(); cnt++
}
```

**G17** – `select` chooses one of multiple communication operations (or default) that are ready; it behaves like a `switch` but each case is a channel operation. If multiple cases are ready, the runtime selects **one at random**. Timeouts are expressed with a `case <-time.After(d):` or a buffered channel.  

```go
select {
case <-ch:
    // received
case <-time.After(5 * time.Second):
    // timeout
}
```

**G18** – **Escape analysis** determines whether a variable’s memory must escape the stack (i.e., be allocated on the heap). The compiler allocates on the stack when the variable cannot outlive the stack frame; otherwise it allocates on the heap.  

You can view decisions with `go build -gcflags="-m=2" ./...`. Understanding escape analysis matters because heap allocations incur garbage‑collection overhead; keeping objects on the stack improves performance and reduces GC pressure.

**G19** – `reflect` provides **run‑time type information**. `reflect.Type` describes a type (e.g., `reflect.TypeOf(5)` returns `reflect.TypeOf(int(0))`). `reflect.Value` holds a **value** of that type and allows inspection/manipulation (`.Int()`, `.Set()`, etc.). Reflection is slow (dynamic dispatch, bounds checks) and should be reserved for scenarios like generic libraries, serialization frameworks, or plugin systems where code generation isn’t feasible.

**G20** – `go:embed` embeds files/directories into the program at compile time, producing a `fs.FS` (specifically `embed.FS`).  

- **Single file**: `embed.Files("data.txt")` yields a `*embed.FS` containing that file.  
- **Directory**: `embed.Files("static/...")` embeds all files under `static/`.  
- **File system**: The embedded data implements `io/fs.FS`, so you can use `os.ReadFile`, `fs.ReadFile`, etc., exactly as with the real file system.  

Limitations: only static files (no directories, symlinks, or executable code); you cannot modify embedded files at runtime; large files increase binary size; and the embed directive does not support pattern matching beyond `...`. Interaction with `io/fs.FS` is seamless—`embed.FS` satisfies the interface, enabling use with `filepath.Walk`, `http.FileServer`, etc.

**R1** – **Ownership** is Rust’s core memory‑safety guarantee. Each value has a **owner**; the owner is responsible for freeing the value when it goes out of scope. The three rules:  
1. **Exactly one owner** per value at any time.  
2. **Owner owns the value** → can move it out of scope, transferring ownership.  
3. **If a value has an owner**, you cannot reference it without a **borrow** (reference). No aliasing of mutable data.

**R2** – `String` is a heap‑allocated, owned, mutable UTF‑8 sequence. `&str` is a **slice** of bytes (read‑only) referencing UTF‑8 data, either borrowed from a `String` or a literal. Use `String` when you need ownership and mutation; use `&str` for borrowed, immutable text, e.g., function signatures `fn process(s &str)`.

**R3** – **Borrowing** gives temporary references to a value without taking ownership. The borrow checker enforces:  
- **Shared borrow** (`&T`): multiple concurrent reads allowed, but no mutable access.  
- **Mutable borrow** (`&mut T`): exclusive access, no other borrows (shared or mutable) allowed.  
These rules prevent data races and ensure memory safety at compile time.

**R4** – `Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents presence (`Some(T)`) or absence (`None`). The `?` operator returns the contained value on `Ok`, or propagates the error (`Err`) out of the function, automatically wrapping it in the function’s return `Result`.  

```rust
use std::fs;

fn read_file(path: &str) -> Result<String, std::io::Error> {
    let contents = fs::read_to_string(path)?; // propagates error
    Ok(contents)
}
```

**R5** – `Box<T>` gives owned heap allocation on the heap; useful for recursive types or when you need a value sized at runtime. `Rc<T>` (**Reference Counting**) allows multiple owners sharing immutable data; each clone increments a counter, and the data is freed when the last owner drops. `Arc<T>` is the **atomic** version of `Rc`, safe for concurrent reads/writes across threads. Use `Box` for owned heap data, `Rc` for single‑threaded shared immutable data, `Arc` for thread‑safe shared immutable data.

**R6** – A **trait** defines a interface of behavior (methods). Unlike Java/C# interfaces, Rust traits can have **method implementations** and associated types, and they can be implemented for any type (including external types) via `impl Trait for Type`.  

- **Trait object** (`dyn Trait`) erases the concrete type, storing a pointer to a vtable; it allows heterogeneous collections.  
- **Generic with trait bound** (`T: Trait`) keeps the concrete type known at compile time, enabling monomorphization and zero‑cost abstraction.

**R7** – Lifetimes ensure references remain valid. The function:

```rust
fn longest(x: &str, y: &str) -> &str { … }
```

fails because the compiler cannot guarantee that the returned slice outlives both inputs; it could point into `x` or `y`, but the function’s signature would need to tie the output lifetime to the inputs. Fix:

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

The explicit lifetime `'a` tells the compiler the returned reference lives as long as both inputs.

**R8** – `Send` and `Sync` are marker traits: `Send` indicates a type can be moved to another thread safely; `Sync` indicates it can be referenced from multiple threads (`&T`). `Rc<T>` is **not** `Send`/`Sync` because its internal reference count is mutable (`RcInner` has a `RefCell`). `Arc<T>` wraps the reference count in atomic operations, making it `Send` and `Sync`.

**R9** – Async/await in Rust is built on **Futures**: a trait representing an asynchronous computation that can be polled (`poll`). An `async fn` returns an **impl Future**. An **executor** (e.g., Tokio) drives multiple futures to completion, typically via a event loop that polls them and advances when I/O is ready. Unlike Go’s goroutines (which are green threads scheduled by the Go runtime), Rust’s async tasks are **cooperative**; they yield at `.await` points, and the executor switches between them, often using a single OS thread.

**R10** – `unsafe` blocks allow you to bypass Rust’s safety guarantees. Three typical uses:  
1. Dereferencing raw pointers (`*const T`, `*mut T`).  
2. Calling an external function (FFI) with `extern "C"`.  
3. Accessing mutable static variables (`static mut`).  

Unsafe is justified when interfacing with C, implementing unsafe data structures, or performing low‑level memory operations where you can guarantee safety manually.

**R11** – **Pattern matching** (`match`) examines a value against patterns, with exhaustive checking (compiler warns if a pattern is missing). `if let` is a shorthand for a `match` with a single `Some`/`Ok` pattern, ignoring other arms. The compiler enforces exhaustiveness for `match` to avoid runtime panics.

**R12** – `Vec<T>` is a growable, heap‑allocated array; `[T; N]` is a fixed‑size array stored on the stack (or in the heap if `N` is large). `Vec` manages capacity: when pushes exceed capacity, it allocates a larger slice (typically doubling) and copies existing elements.

**R13** – Rust’s **enums** are algebraic data types; each variant can carry data, unlike C’s plain enums (just integers). The `Option<T>` enum (`Some`, `None`) replaces `null`/`None`, forcing handling of absence and eliminating null‑pointer dereferences.

**R14** – `impl` blocks define methods and associated functions for a type.  
- `&self` → shared reference, immutable access.  
- `&mut self` → mutable reference, can modify.  
- `self` → takes ownership, often used for “consuming” operations.  

Associated functions (`String::new()`) are called on the type without a self parameter, similar to static methods.

**R15** – `#[derive(...)]` generates implementations for common traits. Examples: `Debug` (pretty‑print), `Clone` (duplicate), `PartialEq`/`Eq` (equality), `Serialize`/`Deserialize` (with `serde`). You cannot derive a trait if the compiler cannot generate a sensible implementation (e.g., `Send`/`Sync` are auto‑derived for safe types, but you can manually implement them).

**R16** – `Cow<'a, T>` (**Clone on Write**) is either `Borrow<'a, T>` (view) or `Owned(T)`. It is useful when you might need to borrow data but also possibly own it later. Example: reading a file into `Cow` avoids copying if the file fits in memory as a slice; if mutation is required, it clones on write.

```rust
fn process(data: Cow<str>) -> String {
    match data {
        Cow::Borrowed(s) => s.to_lowercase(),
        Cow::Owned(s) => s.to_lowercase(),
    }
}
```

**R17** – Rust’s module system (`mod`) organizes code. `use` brings names into scope. `pub` controls visibility. Files map to modules: `mod foo;` looks for `foo.rs` or `foo/mod.rs`. Editions 2015 used `mod` declarations inside files; 2018 introduced **declarative modules** and **inline modules** (`mod foo { … }`), allowing more flexible nesting and `pub use` re‑exports.

**R18** – `Pin<T>` ensures a value’s location in memory never moves after being pinned, which is essential for self‑referential structs (e.g., a struct containing a reference to its own data) and for async functions that return pinned futures. `Unpin` is a marker that indicates a type can be safely moved; `Pin` automatically implements `Unpin` for types that are `Unpin`. Async/`await` futures are `Pin` because they need stable addresses for wakers.

**R19** – Rust’s macro system includes:  
- **Declarative macros** (`macro_rules!`) – pattern‑based, hygienic, expanded at call sites.  
- **Procedural macros** – three kinds: `#[derive]`, `#[attribute]`, and function‑like macros. They operate on AST tokens, enabling custom syntax and code generation. Hygiene ensures macros cannot accidentally capture outer variables.

**R20** – **Zero‑cost abstractions** mean ergonomic Rust code compiles to code as efficient as hand‑written C. This is achieved via:  
- **Generics + monomorphization**: each concrete type gets its own optimized code.  
- **Traits + static dispatch**: method calls resolved at compile time, eliminating vtable overhead (unless using `dyn Trait`).  
- **Iterators**: implement `Iterator` and the compiler often vectorizes or unrolls loops, producing the same performance as explicit loops.  

Together they let you write expressive, safe code without runtime penalties.<|END_TEXT|>
