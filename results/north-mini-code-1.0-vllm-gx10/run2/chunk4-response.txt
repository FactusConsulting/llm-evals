An **array** (`[N]T`) is a fixed‑size value that owns its memory. Appending (`append`) grows a slice by copying elements into a new backing array when the current capacity is exceeded; the original array is discarded and the slice now points to the new array.

**G2** – `var x int` declares a variable with the zero value of its type (0) and makes it usable without an initializer. `x := 0` is a short‑variable declaration that infers the type from the right‑hand side and also initializes it. `:=` cannot be used at package level (outside a function) or when the variable already exists (you must use assignment `=`).

**G3** – A **goroutine** is a lightweight thread managed by Go’s runtime, not an OS thread. It runs concurrently on a set of OS threads via a scheduler. The **GMP model** (Goroutine‑M‑Processor) consists of:
- **G** – goroutine descriptor (stack, PC, state)  
- **M** – OS thread (processor) that executes a goroutine  
- **P** – processor (a per‑core work queue of ready Gs)  

The scheduler multiplexes Gs onto Ms, handling preemption, blocking, and scheduling.

**G4** – A **channel** (`chan T`) provides synchronous communication between goroutines.  
- **Unbuffered**: send blocks until a receiver is ready.  
- **Buffered**: channel has a fixed capacity; up to that many sends can succeed without a receiver.  

Sending to a full buffered channel blocks until a receive frees space.

**G5** – `context.Context` carries deadlines, cancellation signals, and request‑scoped values across API boundaries. It enables cooperative cancellation.

```go
defer cancel() // ensure resources are released

resp, err := http.DefaultClient.Get("https://example.com")
if err == nil {
    defer resp.Body.Close()

select {
case <-req.Done():
    fmt.Println("request timed out")
default:
    // handle response
}
```

**G6** – Go’s **interface satisfaction** is structural: a type implements an interface automatically if it provides the required methods, no explicit `implements` keyword. Compared to Java/C#, Go interfaces are **single‑inheritance** and can contain both methods and fields (via structural typing).  

`interface{}` (or `any`) is an **empty interface** that can hold a value of any type. It’s powerful because you can store arbitrary data in a slice, map, or as a return type, but dangerous because type safety is lost—you must use type assertions or `switch` to retrieve the concrete value.

**G8** – `sync.Mutex` provides exclusive lock; `sync.RWMutex` allows one writer or many readers.  
- Use `sync.Map` when you need concurrent reads/writes without pre‑allocating a map and want the runtime to handle eviction of dead keys; it’s optimized for the “many writers, many readers” case but has higher per‑operation overhead than a regular map with a mutex.  
- A regular `map` + `Mutex` gives predictable performance and is simpler for a fixed number of keys.

**G9** – **Go modules** replace GOPATH, providing a reproducible import graph.  
- `go.mod`: declares module path, required version, and replacements.  
- `go.sum`: stores cryptographic hashes of downloaded module files to ensure integrity.  

`go mod tidy` removes unused requirements and adds needed ones, then rewrites `go.mod`. The **Minimum Version Selection (MVS)** algorithm picks the lowest compatible version that satisfies all module requirements, ensuring deterministic builds.

**G10** – `defer` schedules a function to run when the surrounding function returns. Multiple `defers` execute **LIFO** (last‑in, first‑out). Common gotcha: inside a `for` loop, the deferred call captures loop variables; all iterations end up using the final value of those variables. Use a local copy inside the loop or move the defer outside.

**G11** – A **pointer** holds the memory address of a variable. Its zero value is `nil`. To create a pointer to a struct literal: `p := &struct{Name string}{Name: "Alice"}`.

**G12** – `init()` functions are special; they run **automatically** at package initialization time (before `main`). Multiple `init()` functions are allowed; they are executed in the order they appear in the source file, but files are ordered by filename (lexicographically) and within a file, by appearance.

**G13** – `new(T)` allocates zero‑initialized memory for type `T` and returns a pointer `*T`. `make(T)` initializes slices, maps, and channels (returns the concrete type). `new` works for any type; `make` only for those three built‑in types.

**G14** – Errors are values implementing `error` interface (`Error() string`). Idiomatic pattern:

```go
if err := someFunc(); err != nil {
    return err
}
```

`errors.Is` checks if the error (or its wrapped errors) matches a target using `Is` method; `errors.As` attempts to cast to a target type (e.g., `*os.PathError`). Both are safer than `==` because they traverse error wrappers.

**G15** – Built‑in composites and zero values:  
- `map[K]V` → `nil` (not usable until `make`‑ed)  
- `[]T` → `nil` (zero‑length slice)  
- `chan T` → `nil` (closed/uninitialized channel)  
- `struct{}` → zero‑valued fields  

**G16** – A **race condition** occurs when concurrent accesses to shared data can interleave unpredictably, leading to inconsistent state. The `-race` flag adds instrumentation to detect data races at runtime. Example:

```go
var cnt int
go func(){ cnt++ }()
go func(){ cnt++ }()
fmt.Println(cnt) // may print 1 or 2
```

Fix with a mutex:

```go
var mu sync.Mutex
mu.Lock()
defer mu.Unlock()
cnt++
```

or use a channel to serialize increments.

**G17** – `select` chooses one ready case (like `switch`) but blocks until **one** is ready. If multiple are ready, Go picks one **pseudo‑randomly**. A default case prevents blocking. Timeout can be expressed with a `time.After` channel:

```go
select {
case <-ch:
    // received
case <-time.After(5 * time.Second):
    // timeout
}
```

**G18** – **Escape analysis** determines whether a variable’s memory can stay on the stack or must escape to the heap. The compiler allocates on the stack if the variable is not referenced outside the current function (or after the function returns). It can be inspected with `go build -gcflags=-m` (prints escape annotations). Stack allocation reduces GC pressure and improves locality.

**G19** – `reflect.Type` describes a type’s structure (`Kind`, `PkgPath`, etc.). `reflect.Value` holds a **value** of that type, allowing read/write via methods like `Interface()`, `Set()`. Reflection is slower because it uses runtime type information and dynamic dispatch. Use it for generic algorithms (e.g., serialization, CLI tools) where code generation would be excessive; otherwise prefer static APIs.

**G20** – `go:embed` embeds files/directories into the binary at compile time. It works with single files (`embed.go` using `embed.FS`) and directories (use `//go:embed path/*`). Limitations: only static files, no runtime reading from disk, and the embedded data is read‑only. It integrates with `io/fs.FS` via `embed.FS`, allowing `os.ReadFile`‑like operations.

**R1** – **Ownership** is Rust’s unique resource management: each value has a single owner; the owner can move the value, transferring ownership. Rules:  
1. Each value has exactly one owner.  
2. Only one active reference (move) at a time.  
3. When the owner goes out of scope, the value is dropped automatically.

**R2** – `String` is a heap‑allocated, mutable UTF‑8 owned string. `&str` is a borrowed, immutable view into UTF‑8 data (could be a slice of a `String` or a literal). Use `String` when you need ownership/mutation; use `&str` for read‑only references, e.g., function parameters.

**R3** – **Borrowing** lets you refer to a value without taking ownership. The borrow checker enforces:  
- One mutable reference (`&mut T`) at a time, no other references.  
- Any number of immutable references (`&T`), but not with a mutable one.  
- Borrows must not outlive the value.

**R4** – `Result<T, E>` represents success (`Ok`) or failure (`Err`). `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator returns the contained value on `Ok`, or propagates the error out of the function.  

```rust
use std::fs;
fn read_file(path: &str) -> Result<String, std::io::Error> {
    fs::read_to_string(path) // returns Result<String, Error>
}
```

**R5** – `Box<T>` gives owned heap allocation on the heap, allowing recursive types or moving a value onto the heap. `Rc<T>` (`Reference Counting`) enables multiple owners with shared immutable access; uses atomic ref‑count for single‑threaded scenarios. `Arc<T>` is the thread‑safe version of `Rc`, using atomic ref‑counts for multi‑threaded contexts.

**R6** – **Traits** define behavior (method signatures) that types can implement, similar to Go interfaces but with **named** methods and optional default implementations.  
- **Trait object** (`dyn Trait`) erases the concrete type, storing a pointer to a vtable; size is dynamic.  
- **Generic with trait bound** (`T: Trait`) monomorphizes each usage at compile time, yielding zero‑cost static dispatch.

**R8** – `Send` and `Sync` traits mark types safe to send across threads (`Send`) or share across threads (`Sync`). `Rc<T>` is not `Send`/`Sync` because its internal reference count isn’t thread‑safe. `Arc<T>` wraps `Rc` with atomic ref‑counts, making it `Send` and `Sync`.

**R9** – An **async function** returns a **Future** (a trait object). The executor (e.g., Tokio) polls the future, driving it to completion. Under the hood, async/await uses state machines and wakers to suspend/resume. Unlike Go’s goroutines (which are pre‑emptively scheduled green threads), Rust’s async tasks are cooperative; a future runs until it yields, then the executor schedules another task.

**R10** – `unsafe` blocks allow operations the compiler can’t guarantee safe:  
1. Dereferencing raw pointers (`*mut T`/`*const T`).  
2. Calling functions marked `extern "C"` that may violate Rust’s safety guarantees.  
3. Accessing mutable static variables (`static mut`).  

Use `unsafe` only when you have a guarantee (e.g., interfacing with C, implementing safe abstractions).

**R11** – **Pattern matching** (`match`) examines a value against patterns, with exhaustive checking. `if let` is a shorthand for a `match` with a single `Some`/`Ok` pattern. The compiler enforces that `match` covers all possible cases (or uses `_`).

**R12** – `Vec<T>` is a growable, heap‑allocated array; `[T; N]` is a fixed‑size stack array. `Vec` doubles capacity when exceeding it, copying existing elements to the new backing storage.

**R13** – Rust enums are **sum types**: each variant can carry different data, unlike C enums (plain integers) or Java enums (restricted classes). `Option<T>` (`Some`/`None`) eliminates null; absence is represented explicitly, forcing handling of the `None` case.

**R14** – `impl` blocks define methods and associated functions for a type. `&self` borrows immutably (read‑only), `&mut self` borrows mutably (allows mutation), `self` takes ownership (consumes the value). Associated functions (`String::new()`) are called on the type without a receiver.

**R15** – `derive` macro automatically implements common traits. Examples: `Debug`, `Clone`, `PartialEq`, `Serialize` (with `serde`). You cannot derive a trait if it requires custom logic or if the type contains non‑derivable fields (e.g., raw pointers).

**R16** – `Cow<'a, T>` (`Clone on Write`) is either `Borrow<'a, T>` (view) or `Owned(T)`. It avoids cloning when the data can be borrowed, cloning only when mutation is needed. Example: reading a file into `Cow` lets you keep the original bytes if unchanged, or own a `String` if you modify it.

**R17** – Module system (`mod`) defines a module hierarchy. `use` brings names into scope. `pub` controls visibility. Files map to modules (e.g., `mod foo;` looks for `foo.rs`/`foo/mod.rs`). Rust 2018 introduced a file‑based hierarchy and `pub use` re‑exports, simplifying crate structure.

**R18** – `Pin<T>` ensures a value’s location won’t move after being pinned (e.g., when stored in async contexts). It’s needed for self‑referential structs and `async fn` return types where the future must remain at a stable address. `Unpin` auto‑implements `Pin` for types that are safe to move; `Pin` disables moving for `!Unpin` types.

**R19** – Macros are code generation at compile time. Declarative macros (`macro_rules!`) are textual substitution; procedural macros (`derive`, attribute, function‑like) are Rust functions that produce tokens. Hygiene ensures macro definitions don’t pollute the surrounding namespace.

**R20** – **Zero‑cost abstractions**: Rust’s generics are monomorphized, producing specialized code per type at compile time, eliminating runtime overhead. Iterators use static dispatch and `size_hint` for efficient loops.
