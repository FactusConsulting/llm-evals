## Go

**G1** — An array has a fixed length and is a value type; a slice is a dynamic view with a pointer, length, and capacity. Appending to a slice at capacity allocates a new, larger backing array, copies the old elements, and returns a new slice referencing the new array.

**G2** — `var x int` declares `x` with zero value `0`; `x := 0` declares and initializes `x` with inferred type `int`. You cannot use `:=` at package level (outside functions), and you cannot use it if all variables on the left are already declared in the same scope (unless at least one is new).

**G3** — A goroutine is a lightweight, user-space thread managed by the Go runtime, not the OS. Goroutines are multiplexed onto OS threads by the Go scheduler. The GMP model: G (goroutine), M (OS thread/machine), P (logical processor). The scheduler assigns runnable Gs to Ps, which run on Ms, with work stealing and preemption.

**G4** — Channels are typed communication primitives. An unbuffered channel blocks the sender until a receiver is ready, providing synchronization. A buffered channel blocks only when the buffer is full. Sending to a full buffered channel blocks until a receive frees space. Closing a channel signals that no more sends will occur.

**G5** — The `context` package carries deadlines, cancellation signals, and request-scoped values. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

**G6** — Go interfaces are satisfied implicitly: a type implements an interface if it has all required methods. Unlike Java/C#, there is no explicit `implements` declaration. The empty interface `interface{}` (or `any`) accepts any type, making it flexible but dangerous because it bypasses compile-time type safety and requires type assertions or reflection.

**G7** — The code has a data race: `ready` and `data` are accessed from two goroutines without synchronization. The Go memory model does not guarantee that writes in one goroutine are visible to another without explicit synchronization. Correct alternatives: use a channel, `sync.WaitGroup`, `sync.Mutex`, or `atomic` operations.

**G8** — `sync.Mutex` provides exclusive locking; `sync.RWMutex` allows multiple readers or one writer. Use `RWMutex` for read-heavy workloads. `sync.Map` is optimized for specific patterns (e.g., read-mostly, disjoint keys) but has overhead for simple cases; a regular map with a mutex is simpler and often faster under low contention.

**G9** — Go modules use `go.mod` to declare module path, dependencies, and versions. `go.sum` contains cryptographic hashes for dependency integrity. `go mod tidy` adds missing dependencies, removes unused ones, and updates `go.sum`. Minimum Version Selection (MVS) chooses the minimum version that satisfies all transitive requirements, ensuring reproducible builds.

**G10** — `defer` schedules a function call to run when the surrounding function returns. Multiple defers execute in LIFO order. A common gotcha: deferring in a loop accumulates calls until the function exits, not per iteration, which can cause resource leaks or unexpected delays.

**G11** — A pointer stores a memory address. Its zero value is `nil`. To create a pointer to a struct literal: `p := &Struct{Field: value}` or `p := new(Struct)`.

**G12** — `init()` runs automatically after package initialization and before `main`. A package can have multiple `init()` functions; they execute in source order (and across files, in file-name order as presented to the compiler). They are often used for setup that cannot be done in variable initializers.

**G13** — `make` works only with slices, maps, and channels; it returns an initialized, usable value. `new` allocates zeroed memory for any type and returns a pointer to it. `make` returns a non-pointer (slice/map/channel are reference types).

**G14** — Error handling in Go uses the `error` interface (`Error() string`). Idiomatic pattern: `if err != nil { ... }`. `errors.Is` checks for a sentinel error in the chain, `errors.As` finds a specific error type; `==` only works for direct comparison and fails with wrapped errors.

**G15** — Zero values: map → `nil`, slice → `nil`, channel → `nil`, struct → zero value of all its fields (e.g., `0`, `""`, `false`).

**G16** — A race condition occurs when multiple goroutines access shared data and at least one writes without synchronization. The `-race` flag instruments the runtime to detect data races at runtime. Example fix with a mutex:
```go
var mu sync.Mutex
counter := 0
go func() { mu.Lock(); counter++; mu.Unlock() }()
```

**G17** — `select` waits on multiple channel operations. Unlike `switch`, it is for communication. If multiple cases are ready, it picks one randomly. Timeout example:
```go
select {
case res := <-ch:
    // use res
case <-time.After(1 * time.Second):
    // timeout
}
```

**G18** — Escape analysis determines whether a variable is allocated on the stack or heap. If a variable's address escapes the function (e.g., returned, stored in a global, captured by a closure), it goes to the heap. Inspect with `go build -gcflags="-m"`. It matters because heap allocations increase GC pressure and reduce performance.

**G19** — `reflect.Type` describes a type's metadata; `reflect.Value` holds a runtime value. Reflection is slow due to runtime introspection, allocations, and lack of compile-time optimization. It is justified for generic serialization, debugging, or when code generation is impractical.

**G20** — `go:embed` embeds files into the binary. For a single file: `//go:embed file.txt` with a `string` or `[]byte` variable. For directories: use `embed.FS`. Limitations: cannot embed files outside the package directory, cannot use `..`, and files starting with `.` or `_` are ignored. `embed.FS` implements `io/fs.FS`, enabling standard filesystem operations.

## Rust

**R1** — Ownership rules: (1) each value has an owner; (2) only one owner at a time; (3) when the owner goes out of scope, the value is dropped. This prevents memory leaks and double-free errors.

**R2** — `String` owns a heap-allocated UTF-8 buffer; `&str` is a borrowed string slice. In function signatures, use `&str` for read-only access and `String` when you need to take ownership or mutate the string.

**R3** — Borrowing creates references without transferring ownership. Rules: you may have either many shared references (`&T`) or one mutable reference (`&mut T`), and references must not outlive the value they borrow. The borrow checker enforces these rules at compile time.

**R4** — `Result<T, E>` represents success (`Ok`) or failure (`Err`); `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator unwraps `Ok`/`Some` or returns early with `Err`/`None`. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

**R5** — `Box<T>` is a single-owner heap allocation. `Rc<T>` provides shared ownership with non-atomic reference counting (single-threaded). `Arc<T>` is atomic reference counting for thread-safe sharing. Use `Box` for single ownership, `Rc` for shared single-threaded, `Arc` for shared across threads.

**R6** — Traits define shared behavior. Go interfaces are implicit; Rust traits require explicit implementation. A trait object `dyn Trait` uses dynamic dispatch (runtime overhead), while a generic with `T: Trait` is monomorphized (static dispatch, no overhead).

**R7** — The function needs a lifetime parameter to tie the output to the input references. Fix:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** — `Send` means a type can be moved across threads; `Sync` means it can be shared by reference across threads. `Rc<T>` is not `Send` because its reference count is non-atomic and could race. `Arc<T>` uses atomic operations, making it `Send` and `Sync` when `T` is.

**R9** — Rust's async/await is based on `Future` values, which are state machines polled by an executor (e.g., Tokio). Executors manage wakers and drive futures to completion. Unlike Go's preemptive goroutines, Rust futures are cooperative and stackless; they yield at `.await` points.

**R10** — `unsafe` allows: dereferencing raw pointers, calling unsafe functions, accessing mutable statics, implementing unsafe traits, and accessing union fields. It is justified for FFI, low-level performance-critical code, or when invariants can be manually guaranteed.

**R11** — Pattern matching with `match` is exhaustive and can bind variables; `if let` is a concise form for a single pattern. The compiler requires all possible patterns to be covered in `match`, preventing unhandled cases.

**R12** — `Vec<T>` is a heap-allocated dynamic array; `[T; N]` is a fixed-size array on the stack (or inline). When `Vec` exceeds capacity, it reallocates a larger buffer (typically doubling) and copies elements.

**R13** — Rust enums are algebraic data types: variants can carry data. C/Java enums are just constants. `Option<T>` is `Some(T)` or `None`, eliminating null pointer errors. Rust has no `null`; absence is explicit via `Option`.

**R14** — `impl` blocks define methods and associated functions. `&self` borrows immutably, `&mut self` borrows mutably, `self` consumes the value. Associated functions (e.g., `String::new()`) are called on the type, not an instance.

**R15** — `derive` generates trait implementations automatically. Common derivable traits: `Debug`, `Clone`, `PartialEq`, `Serialize` (via serde). You cannot derive traits that require manual logic (e.g., `Display`, `From`) or traits with associated types that need custom implementation.

**R16** — `Cow<'a, B>` is a clone-on-write enum: it can be `Borrowed` or `Owned`. It avoids allocation when you only need to read, and clones only when mutation is required. Example:
```rust
fn normalize(s: &str) -> Cow<'_, str> {
    if s.contains(' ') { Cow::Owned(s.replace(' ', "_")) } else { Cow::Borrowed(s) }
}
```

**R17** — Modules are declared with `mod`, imported with `use`, and made public with `pub`. In Rust 2018, `mod foo;` looks for `foo.rs` (preferred) or `foo/mod.rs`; `use` paths are absolute from the crate root. Rust 2015 used `mod.rs` files and relative paths.

**R18** — `Pin<T>` prevents a type from being moved, which is necessary for self-referential structs. Async futures may contain self-references, so they must be pinned before polling. `Unpin` is an auto-trait indicating a type can be moved freely; most types are `Unpin`.

**R19** — Declarative macros (`macro_rules!`) match token patterns and generate code. Procedural macros (derive, attribute, function-like) operate on the AST and can generate more complex code. `macro_rules!` has hygiene for local variables; procedural macros are unhygienic and require careful naming.

**R20** — Zero-cost abstractions mean high-level constructs compile to efficient machine code without runtime overhead. Iterators are inlined and optimized, generics are monomorphized (no virtual dispatch), and trait bounds enable static dispatch, producing performance comparable to hand-written C while maintaining ergonomics.
