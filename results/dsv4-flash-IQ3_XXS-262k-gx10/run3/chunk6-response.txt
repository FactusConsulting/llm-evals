## JavaScript / TypeScript

**JS1 — Easy:**  
`var` is function-scoped, hoisted (declaration moved to top, initialized as `undefined`), and can be redeclared. `let` and `const` are block-scoped, hoisted but not initialized (temporal dead zone), and cannot be redeclared in the same scope. `const` additionally cannot be reassigned after declaration. Hoisting is the JavaScript engine's behavior of moving declarations to the top of their scope during compilation, affecting `var` (initialized) and `let`/`const` (uninitialized).

**JS2 — Easy:**  
The event loop is a mechanism that handles asynchronous callbacks. The call stack executes synchronous code. When an async operation completes, its callback is placed in a queue: microtasks (e.g., Promise callbacks, `queueMicrotask`) are processed before macrotasks (e.g., `setTimeout`, I/O). The event loop repeatedly checks the call stack; if empty, it processes all microtasks, then one macrotask, then repeats.

**JS3 — Medium:**  
A closure is a function that retains access to its lexical scope even when executed outside that scope. Example: a counter factory returning a function that increments a private variable. The classic for loop closure bug occurs when using `var` in a loop; all closures share the same variable. Fix: use `let` (block-scoped) or an IIFE to capture each iteration's value.

**JS4 — Medium:**  
Promises represent asynchronous operations; `async/await` is syntactic sugar over Promises. Error handling: `.catch()` for Promises, `try/catch` with `await`. `Promise.all` rejects immediately if any promise rejects; `Promise.allSettled` waits for all and returns results with status (`fulfilled`/`rejected`), useful when you need all outcomes.

**JS5 — Medium:**  
`interface` and `type` are both used to define object shapes. `interface` can be extended/merged, `type` can create unions, intersections, and mapped types. Use `interface` for object contracts and `type` for aliases/unions. Discriminated unions are a pattern using a common property (discriminant) to narrow types in a union, e.g., `type Shape = { kind: 'circle'; radius: number } | { kind: 'square'; side: number }`.

**JS6 — Medium:**  
Prototypal inheritance: objects inherit from other objects via the prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar over prototypes; `class` extends uses prototype chains internally.

**JS7 — Hard:**  
`this` is determined by how a function is called. Binding rules (priority): 1) `new` (new object), 2) `call`/`apply`/`bind` (explicit), 3) method call (object context), 4) default (global or `undefined` in strict mode). `bind()` returns a new function with `this` permanently set; you cannot re-bind a bound function's `this` (except with `new`).

**JS8 — Hard:**  
`WeakRef` holds a weak reference to an object, allowing it to be garbage-collected if no strong references exist. `FinalizationRegistry` lets you register callbacks when objects are garbage-collected. Use for caching or tracking resources without preventing GC. `WeakMap` keys must be objects because they are held weakly; if keys were primitives, they couldn't be garbage-collected independently.

**JS9 — Medium:**  
V8 optimizes via hidden classes (maps for object shapes), inline caching (caching property lookup results), and deoptimization when assumptions break. Patterns that cause deoptimization: adding/removing properties dynamically, changing object shapes, using `eval`, `with`, or `try/catch` in hot paths, and accessing out-of-bounds arrays.

**JS10 — Medium:**  
Tree-shaking removes unused exports during bundling. ES modules are statically analyzable, enabling dead-code elimination. CommonJS is dynamic (`require` can be conditional), so bundlers cannot reliably determine unused exports. Thus, CommonJS cannot be effectively tree-shaken.

**JS11 — Easy:**  
`null` is an explicit empty value; `undefined` means a variable not assigned. `null == undefined` is `true`, `null === undefined` is `false`. Nullish coalescing (`??`) returns the right side if left is `null` or `undefined`. Optional chaining (`?.`) short-circuits if the preceding value is `null`/`undefined`.

**JS12 — Easy:**  
`map()` transforms each element and returns a new array. `filter()` returns elements that pass a test. `reduce()` accumulates values; initial value is optional but recommended. `flatMap()` maps and flattens one level, useful for flattening nested arrays or generating multiple items per input.

**JS13 — Easy:**  
Template literals use backticks and allow `${expression}`. Tagged templates call a function with the string parts and interpolated values. Example: `function escape(strings, ...values) { ... }` to sanitize HTML.

**JS14 — Easy:**  
Destructuring extracts values from arrays/objects. Object: `const { a, b } = obj`; array: `const [x, y] = arr`. Default values: `{ a = 1 } = obj`. Renaming: `{ a: alias } = obj`. Rest operator `...` collects remaining elements into an array/object.

**JS15 — Easy:**  
`for...in` iterates over enumerable property keys (including inherited), `for...of` iterates over iterable values (e.g., array elements). Avoid `for...in` on arrays because it includes non-index properties and order is not guaranteed.

**JS16 — Medium:**  
Generics allow reusable functions/classes with type parameters. Constraints: `T extends SomeType`. Conditional types: `T extends U ? X : Y`. `infer` extracts a type from a conditional, e.g., `type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never`.

**JS17 — Medium:**  
CommonJS uses `require`/`module.exports`, synchronous, dynamic. ES Modules use `import`/`export`, asynchronous, static. Node.js supports both; `"type": "module"` in package.json makes `.js` files treated as ES modules.

**JS18 — Hard:**  
TypeScript's structural typing means types are compatible if their members match. Excess property checks occur when assigning an object literal to a typed variable, flagging extra properties. `extends` is for type constraints/inheritance; `satisfies` (TS 4.9) checks a value against a type without changing its inferred type. Variance: `in` (contravariant) for inputs, `out` (covariant) for outputs, controlling assignability.

**JS19 — Hard:**  
`Proxy` and `Reflect` allow intercepting operations. `Proxy` wraps an object with traps (e.g., `get`, `set`, `apply`). `Reflect` provides methods that mirror the traps. Example: validation proxy that checks property assignments.

**JS20 — Hard:**  
`SharedArrayBuffer` allows sharing memory between workers. `Atomics` provides atomic operations (e.g., `add`, `load`, `store`) and synchronization (`wait`, `notify`). Ordering guarantees are relaxed; `Atomics.wait` blocks a worker until notified, `Atomics.notify` wakes waiting workers.

## Bash

**B1 — Easy:**  
`$@` and `$*` both expand to positional parameters. Unquoted, they split words. Quoted: `"$@"` preserves each argument as separate words; `"$*"` joins all arguments into a single string (first char of IFS as separator).

**B2 — Easy:**  
`set -e` exits on error (non-zero command). `set -u` treats unset variables as errors. `set -o pipefail` makes a pipeline return the rightmost non-zero exit status. Combined, they make scripts fail fast and safely.

**B3 — Medium:**  
`$(command)` and backticks both capture command output; `$(...)` is preferred (nesting, quoting). `$((expression))` performs arithmetic; `expr` is an external command, slower and less safe.

**B4 — Medium:**  
Process substitution `<(command)` treats command output as a file descriptor, e.g., `diff <(sort a) <(sort b)`. Useful when a command expects a file argument.

**B5 — Medium:**  
Use `find ... -print0 | while IFS= read -r -d '' file; do ...; done` or `for file in *; do ...` with proper quoting. `for f in $(ls)` splits on spaces/newlines and expands globs, causing errors.

**B6 — Medium:**  
Here document `<<EOF` feeds lines until EOF as stdin. Here string `<<< "string"` feeds a single string. `<<-EOF` strips leading tabs (allows indentation).

**B7 — Hard:**  
`cmd > file 2>&1` redirects stdout to file, then stderr to same file (both to file). `cmd 2>&1 > file` redirects stderr to current stdout (terminal), then stdout to file, so stderr goes to terminal, stdout to file. `cmd &> file` is shorthand for `> file 2>&1` (both to file).

**B8 — Hard:**  
Use `mkdir` for atomic lock: `while ! mkdir /tmp/lock 2>/dev/null; do sleep 0.1; done; trap 'rmdir /tmp/lock' EXIT`. `mkdir` is atomic, avoids race conditions. Trap ensures cleanup on exit, including SIGTERM (trap on EXIT covers normal exit, but also set trap for TERM to exit).

**B9 — Easy:**  
Single quotes preserve literal text. Double quotes allow variable expansion and command substitution. No quotes split words and glob. Example: `echo '$HOME'` prints `$HOME`; `echo "$HOME"` prints home path; `echo $HOME` also prints home but splits if spaces.

**B10 — Easy:**  
`[ -e file ]` exists, `[ -d dir ]` directory, `[ -r file ]` readable. `[[ ]]` is bash builtin with more features (pattern matching, no word splitting), while `[ ]` is POSIX test.

**B11 — Easy:**  
`$?` exit status of last command. `$$` PID of current shell. `$!` PID of last background job. `$#` number of positional parameters.

**B12 — Easy:**  
Functions: `foo() { ...; }` or `function foo { ...; }` (bash-specific). Return values via `return` (exit status) or `echo` to capture output. Use `local` for local variables.

**B13 — Easy:**  
PATH is a colon-separated list of directories. Bash searches PATH for executables. Builtins are shell commands (e.g., `cd`, `echo`), external commands are separate binaries. Use `type -a cmd` to see all, `which` for external.

**B14 — Medium:**  
`trap 'cmd' SIGNAL` sets a handler. Common: `trap 'cleanup' EXIT`, `trap '...' ERR`, `trap '...' INT TERM`. Multiple signals: handlers run in order received; if same signal, last trap wins.

**B15 — Medium:**  
`xargs` builds and executes commands from stdin, while command substitution captures output. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P N` runs N processes in parallel.

**B16 — Medium:**  
Arrays: `arr=(a b c)`, append `arr+=(d)`, iterate `for i in "${arr[@]}"`, length `${#arr[@]}`. Associative arrays: `declare -A assoc`, `assoc[key]=value`, iterate keys with `"${!assoc[@]}"`.

**B17 — Hard:**  
Subshell `( ... )` runs in a child shell, variable changes don't affect parent. Group `{ ...; }` runs in current shell, changes persist. Piping into a while loop runs the loop in a subshell, so variable changes are lost; use process substitution or `shopt -s lastpipe` to avoid.

**B18 — Hard:**  
Signals: SIGINT (Ctrl+C), SIGTERM (terminate), SIGHUP (hangup), SIGKILL (cannot be caught). For graceful shutdown, trap TERM/INT, kill background processes, wait, then exit. Use `trap 'kill $pid; wait' TERM INT`.

**B19 — Hard:**  
Split file with `split -l N`, process each chunk with `xargs -P` calling a function, then `cat` results. Trade-offs: parallel speedup vs overhead, memory, and ordering. Error propagation: use `xargs` exit status or collect per-file status.

**B20 — Hard:**  
`exec` replaces the current shell with a command, or manipulates file descriptors (e.g., `exec 3>file` opens fd 3). Coprocess: `coproc name { command; }` creates a background process with fds for input/output. Useful for interactive communication.

## PowerShell

**PS1 — Easy:**  
`Write-Output` sends objects to the pipeline (output stream). `Write-Host` writes to the console host directly, bypassing the pipeline. Use `Write-Output` for data, `Write-Host` for display-only messages.

**PS2 — Easy:**  
Pipeline passes objects from one command to the next. `ForEach-Object` is a cmdlet that processes pipeline input; `foreach` statement iterates over a collection in memory. Use `ForEach-Object` for streaming, `foreach` for speed with known collections.

**PS3 — Medium:**  
`[PSCustomObject]` is a structured object with properties; `[hashtable]` is a key-value collection. Use PSCustomObject for output, hashtable for lookups. Convert: `[PSCustomObject]$hashtable` or `$hashtable.GetEnumerator()`.

**PS4 — Medium:**  
Terminating errors stop execution; non-terminating errors continue. `-ErrorAction` controls cmdlet behavior; `$ErrorActionPreference` sets default. `try/catch` catches terminating errors; `-ErrorAction Stop` makes non-terminating errors terminating.

**PS5 — Medium:**  
Splatting passes a hashtable of parameters to a command using `@params`. Example: `$params = @{Path='C:\'; Recurse=$true}; Get-ChildItem @params`. It differs from passing a hashtable as a single parameter because splatting expands keys as named parameters.

**PS6 — Medium:**  
PowerShell remoting uses WinRM (HTTP/SOAP) or SSH. `Invoke-Command -ComputerName` runs commands remotely and returns results; `Enter-PSSession` gives interactive shell. Requires configuration (Enable-PSRemoting).

**PS7 — Hard:**  
PowerShell functions output all objects to the pipeline, not just `return`. The example returns an array of one string, but `return` is not needed; the function outputs the array. If 0 items, output is `$null` (no output). Correct pattern: use `Write-Output` or just output objects; avoid `return` for data.

**PS8 — Hard:**  
A scriptblock is a block of code; a function is a named scriptblock with parameters. Pass scriptblocks to remote sessions via `Invoke-Command -ScriptBlock`. Double-hop problem: credentials not passed to second hop; solve with CredSSP or `-ArgumentList` to pass variables.

**PS9 — Easy:**  
`@()` creates an empty array; `[array]` is a type accelerator. Force single result into array: `@($result)`. Indexing `$null` returns `$null`; indexing empty array returns `$null` (or error if out of bounds).

**PS10 — Easy:**  
Comparison operators are case-insensitive by default; prefix `c` for case-sensitive (`-ceq`). `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection (opposite order).

**PS11 — Easy:**  
A module is a package of functions/cmdlets. Script module (`.psm1`) contains PowerShell code; manifest (`.psd1`) describes metadata; binary module (`.dll`) compiled. `Import-Module` loads module into session.

**PS12 — Easy:**  
Double quotes allow variable expansion and subexpressions `$()`; single quotes are literal. Here-string: `@"..."@` for multi-line strings with interpolation.

**PS13 — Easy:**  
`Get-Member` shows properties and methods of objects. Properties are data, Methods are actions, NoteProperties are added by PowerShell. `Select-Object` selects properties; `Where-Object` filters objects.

**PS14 — Medium:**  
PowerShell classes (v5) are similar to C# but with limitations: no multiple inheritance, limited interface support, constructors must be explicit. Use classes for complex state/behavior; functions for simple operations.

**PS15 — Medium:**  
`[CmdletBinding()]` adds advanced function features: parameter validation, `SupportsShouldProcess` enables `-WhatIf`/`-Confirm`, `DefaultParameterSetName` sets default parameter set, `ValueFromPipeline` allows pipeline input. Begin/Process/End blocks handle pipeline input.

**PS16 — Medium:**  
Providers expose data stores as drives. `Get-ChildItem` works on FileSystem, Registry (e.g., `HKLM:\`), Certificate, Environment. Access registry like `Get-ChildItem HKLM:\Software`.

**PS17 — Hard:**  
Runspaces are PowerShell execution environments. `[runspace]` is a single runspace, `[runspacepool]` manages multiple, `[powershell]` object invokes commands. `ForEach-Object -Parallel` (v7+) simplifies parallel execution; manual runspaces give more control.

**PS18 — Hard:**  
PSScriptAnalyzer is a static analysis tool for PowerShell. It enforces rules (e.g., avoid aliases, use approved verbs) with severity levels (Error, Warning, Information). Custom rules can be written. Suppress with `[Diagnostics.CodeAnalysis.SuppressMessageAttribute]` or `# pragma`. Integrate with CI/CD via `Invoke-ScriptAnalyzer`.

**PS19 — Hard:**  
`$using:` is used in `ForEach-Object -Parallel` and background jobs to capture local variables. `-ArgumentList` passes arguments to scriptblocks. Serialization limits: CLIXML depth (default 2) can lose object fidelity; complex objects may become deserialized types.

**PS20 — Hard:**  
DSC is a declarative configuration management platform. Configurations are scripts that generate MOF files; resources are PowerShell modules that implement `Get/Set/Test-TargetResource`; LCM applies configurations. In PowerShell 7+, DSC is not included by default; replaced by tools like Pulumi, Terraform, or Azure Automation State Configuration.
