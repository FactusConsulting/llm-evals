DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?

A class is a reference type; a struct is a value type. Classes are allocated on the heap, support inheritance and polymorphism, and are passed by reference. Structs are allocated on the stack (or inline in containing objects), are copied by value, and cannot be inherited (unless they are records, but still value types). Use a struct when the instance is small, short-lived, immutable, and represents a single value (e.g., a point, a range). Avoid structs for large objects or when boxing is frequent. Also, structs should not be used when you need reference semantics or inheritance.

DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?

IEnumerable<T> is an in-memory sequence that supports forward-only iteration. IQueryable<T> is designed for querying external data sources (e.g., databases) and builds an expression tree that can be translated into a query language (like SQL). The key difference: IQueryable<T> supports lazy, composable queries that are executed on the data source, while IEnumerable<T> executes in memory. For database queries, using IQueryable<T> allows the query to be translated and optimized at the database level (e.g., filtering, sorting, paging) rather than fetching all data into memory first. If you use IEnumerable<T> with a database, the query is executed immediately and all rows are loaded into memory, then filtered locally.

DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?

async/await is a syntactic sugar for asynchronous programming. When you mark a method async, it returns a Task (or ValueTask) that represents the ongoing operation. The compiler transforms the method into a state machine that can yield control at await points. When you await a Task, the method returns to the caller until the task completes, then resumes on the captured synchronization context (if any). Task is a reference type that represents an asynchronous operation; ValueTask is a struct that can avoid allocation when the operation completes synchronously or when you want to reduce overhead in high-frequency paths. Use ValueTask when you expect the operation to complete synchronously often, or when you need to avoid allocations in hot paths. However, ValueTask has limitations: it can only be awaited once, and it is not suitable for caching or multiple awaits.

DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?

Dependency injection (DI) is a design pattern where dependencies are provided to a class rather than created internally. In .NET, the built-in DI container registers services with lifetimes: Transient (created each time they are requested), Scoped (created once per scope, typically per HTTP request), and Singleton (created once for the application lifetime). A common bug is injecting a Scoped service into a Singleton. Since the Singleton lives for the entire app, it captures the Scoped service at construction time, which may be tied to a specific request scope. This can lead to issues like using a DbContext that is disposed after the request ends, causing ObjectDisposedException. The fix is to use a scope factory (IServiceScopeFactory) to create a new scope inside the Singleton when needed, or to change the lifetime of the dependency.

DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?

string is an immutable reference type that stores characters in a contiguous memory block. ReadOnlySpan<char> is a stack-only value type that provides a view over a contiguous sequence of characters, which can be a string, a char array, or unmanaged memory. Span<T> is used for high-performance scenarios where you want to avoid allocations and copying. For string processing, using ReadOnlySpan<char> allows you to operate on substrings without creating new string objects, reducing garbage collection pressure. You would use Span<T> when performance is critical, such as in parsing, formatting, or processing large text data, and when you need to work with memory from different sources (arrays, unmanaged memory, etc.). However, Span<T> is stack-only and cannot be stored in fields or used in async methods across awaits.

DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?

The .NET garbage collector (GC) manages memory for managed objects. It uses a generational model: Gen 0 (short-lived objects), Gen 1 (survivors from Gen 0), Gen 2 (long-lived objects). The GC collects Gen 0 frequently, Gen 1 less often, and Gen 2 rarely. The Large Object Heap (LOH) is for objects larger than 85,000 bytes; it is not compacted and is collected only during Gen 2 collections. IDisposable is for releasing unmanaged resources (e.g., file handles, database connections, COM objects) that the GC cannot manage. Even with a GC, you need IDisposable to deterministically release these resources, because the GC only handles memory, not other system resources. The pattern is to implement Dispose() and call it via using or try/finally.

DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?

By default, when you await a Task, the continuation is scheduled back to the current SynchronizationContext (or TaskScheduler) if one exists. This is important in UI applications (e.g., WinForms, WPF) to update UI controls on the UI thread. ConfigureAwait(false) tells the await to not capture the synchronization context, so the continuation runs on a thread-pool thread, avoiding the overhead of marshaling back to the original context. You should use ConfigureAwait(false) in library code that doesn't need to interact with the UI, to improve performance and avoid deadlocks. You should NOT use it when you need to update UI after the await, or when you are in a context that requires the synchronization context (e.g., ASP.NET Core's request context, though it's less critical there). The SynchronizationContext represents the execution context (e.g., UI thread, request context) that ensures thread-safety for UI or request-specific state.

DN8 — Hard: Explain the new .NET 8/9 features: primary constructors, collection expressions, and FrozenDictionary. Write a minimal example using primary constructors with DI.

Primary constructors (C# 12) allow you to define constructor parameters directly in the class declaration, reducing boilerplate. Collection expressions (C# 12) provide a concise syntax for creating collections, e.g., `[1, 2, 3]` instead of `new int[] {1,2,3}`. FrozenDictionary (in .NET 8) is an immutable dictionary optimized for read-only access, created via `FrozenDictionary.ToFrozenDictionary()`. Example with primary constructors and DI:

```csharp
public class MyService(ILogger<MyService> logger, IConfiguration config)
{
    public void DoWork() => logger.LogInformation(config["Key"]);
}
```

The parameters are captured and used as fields. DI can inject them directly.

DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?

The likely cause is that the DbContext is registered as a Singleton or is being captured in a Singleton service, causing it to be shared across requests. Under high concurrency, multiple threads use the same DbContext, which is not thread-safe, and it may be disposed after one request completes, leading to ObjectDisposedException. The fix is to register DbContext as Scoped (the default in EF Core) so that each request gets its own instance. If you must use a Singleton, you need to create a new DbContext per operation using a factory (IDbContextFactory) or a scope. EF Core's DbContext is designed to be used as a scoped service, matching the request lifetime.

DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?

A record is a reference type that provides value-based equality, with built-in features like with-expressions, deconstruction, and a synthesized ToString(). A class is a reference type with reference equality by default. Records are ideal for immutable data models (DTOs, domain events) where equality is based on content. Record struct is a value type with similar features but as a struct; it's useful for small, immutable data structures that benefit from value semantics and performance. Choose a record when you need value equality and immutability; choose a class when you need mutable state, inheritance, or reference identity.

DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?

ref: The parameter is a reference to the caller's variable; the method can read and modify it. The variable must be initialized before passing. out: Similar to ref, but the method must assign a value to the parameter before returning; the caller doesn't need to initialize. in: The parameter is passed by reference but is read-only; the method cannot modify it. Use ref when you need to modify the caller's variable; use out when you need to return multiple values or when the method always assigns; use in for performance when passing large structs by reference without modification.

DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?

Nullable reference types (NRT) are a compile-time feature that helps prevent null reference exceptions. With `#nullable enable`, reference types are non-nullable by default, and you can use `?` to indicate a reference type can be null (e.g., `string?`). This is enforced by compiler warnings and annotations. Nullable value types (e.g., `int?`) are actual value types that can be null (using Nullable<T>). The difference: NRT is a compile-time annotation, not a runtime change; nullable value types are a runtime representation. NRT helps with static analysis, while nullable value types are a real type.

DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?

LINQ (Language Integrated Query) is a set of methods for querying collections. Method syntax uses extension methods like Where, Select, etc. Query syntax is a declarative SQL-like syntax that is translated to method calls at compile time. Both are equivalent. Deferred execution means the query is not executed until you iterate over it (e.g., with foreach or ToList()). This allows composing queries without immediate execution, and enables lazy evaluation.

DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?

Generic constraints restrict the types that can be used as type arguments. `where T : class` requires a reference type; `where T : struct` requires a value type; `where T : new()` requires a parameterless constructor; `where T : IComparable<T>` requires the type to implement that interface. You can combine constraints, e.g., `where T : class, IComparable<T>, new()`. This ensures the type has the required capabilities.

DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?

An abstract class can have implementation, fields, constructors, and can be inherited by only one class. An interface historically had only declarations, but since C# 8, interfaces can have default implementations. The main difference: a class can implement multiple interfaces but inherit only one abstract class. Abstract classes are used for shared base functionality; interfaces are contracts. Default interface methods allow interfaces to provide optional implementations, making them more like abstract classes, but still allow multiple inheritance.

DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?

Middleware are components that handle HTTP requests and responses in a pipeline. `app.Use()` adds a middleware that can call the next middleware (via `next`). `app.Map()` branches the pipeline based on a path or predicate. `app.Run()` adds a terminal middleware that does not call next. Ordering matters because each middleware can short-circuit or modify the request/response. Exception handling middleware (e.g., UseExceptionHandler) should be placed early to catch exceptions from downstream middleware and provide a unified response.

DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.

Channel<T> is a thread-safe, asynchronous producer-consumer queue introduced in .NET Core 3.0. It supports async read/write and can be bounded to limit capacity. BlockingCollection<T> is an older, synchronous wrapper around a collection that blocks threads. Channel<T> is more efficient and async-friendly. Example: create a bounded channel with capacity 10, producer writes with `WriteAsync`, consumer reads with `ReadAsync`. If the channel is full, the producer awaits until space is available, providing backpressure.

DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?

Source generators are a compiler feature that analyzes code and generates additional C# source files at compile time. They differ from reflection (runtime) and IL weaving (post-compilation) because they run during compilation, are fast, and produce code that is visible and debuggable. Incremental generators (IIncrementalGenerator) cache intermediate results and only re-run when inputs change, improving performance. They are preferred over ISourceGenerator because they are more efficient and support incremental compilation.

DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?

TPL Dataflow provides building blocks for dataflow programming. BufferBlock is a FIFO queue; ActionBlock processes each item with a delegate; TransformBlock transforms input to output. It supports parallelism, backpressure, and complex pipelines. Channels are simpler and more lightweight, but Dataflow offers more control (e.g., batching, guaranteed delivery). For pipeline processing, Dataflow is more powerful, while Channels are better for simple producer-consumer.

DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?

Minimal APIs are a lightweight way to create HTTP APIs with minimal code, using top-level statements and lambda handlers. They differ from controller-based APIs by not requiring classes, attributes, or dependency injection via constructors. Trade-offs: Minimal APIs are simpler and faster to write, but may be less organized for large projects; testability can be achieved by testing the handlers directly, but you lose some features like model binding attributes. Middleware still works, and OpenAPI support is available via AddEndpointsApiExplorer. Route groups allow grouping endpoints with common prefixes; endpoint filters are middleware-like functions that run before/after handlers.

P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?

A list is mutable, ordered, and can be changed; a tuple is immutable, ordered, and cannot be changed after creation. Sets are unordered, mutable, and contain unique elements; frozensets are immutable sets. Use lists for dynamic collections, tuples for fixed data, sets for membership tests and deduplication, frozensets when you need a hashable set (e.g., as dictionary keys).

P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?

The GIL is a mutex in CPython that allows only one thread to execute Python bytecode at a time. It affects CPU-bound multi-threaded programs, preventing true parallelism. I/O-bound programs are less affected because the GIL is released during I/O operations. Workarounds: use multiprocessing (separate processes), use C extensions that release the GIL, or use asyncio for I/O-bound tasks. Python 3.13 introduced an optional free-threaded build.

P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.

copy.copy() creates a shallow copy: the new object is a new container, but the elements are references to the same objects. copy.deepcopy() recursively copies objects. Shallow copy can cause unexpected behavior when you modify a nested mutable object, affecting both copies. Example: `a = [[1,2],[3,4]]; b = copy.copy(a); b[0][0] = 99` changes a[0][0] as well. Deepcopy avoids this.

P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.

Decorators are functions that take another function and extend its behavior. They are applied with `@decorator` syntax. Example:

```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.4f}s")
        return result
    return wrapper

@timer
def foo():
    time.sleep(1)
```

P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?

Generators are functions that use `yield` to produce a sequence of values lazily. They maintain state between calls. Returning a list creates all values at once; generators produce one at a time, saving memory. `yield from` delegates to another generator (or iterable), allowing for flattening and composition.

P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?

asyncio uses an event loop to manage coroutines. `asyncio.run()` is the entry point to run a coroutine and manage the loop. `asyncio.create_task()` schedules a coroutine to run concurrently as a Task. `asyncio.gather()` runs multiple awaitables concurrently and collects results. You can't call `time.sleep()` because it blocks the thread, preventing the event loop from running other tasks; you must use `await asyncio.sleep()`.

P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?

Python 3 uses the C3 linearization algorithm to compute the MRO. It ensures that each class appears after its bases, and that subclasses appear before parents. For diamond inheritance (D(B,C) where B and C inherit from A), the MRO is D, B, C, A. In the example, `D().who()` prints "C" because C overrides `who`, and C appears before A in the MRO. The MRO is D -> B -> C -> A -> object, so the first class with `who` is C.

P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.

A metaclass is a class of a class; it controls class creation. `__init_subclass__` is a hook called when a subclass is created, allowing customization without a metaclass. Use a metaclass when you need to modify the class itself (e.g., register classes, validate attributes). Use `__init_subclass__` for simpler subclass customization, like setting default attributes or enforcing constraints. Example: a metaclass for a registry, `__init_subclass__` for automatically adding a class attribute.

P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?

Threading uses threads within one process, subject to GIL, good for I/O-bound tasks. Multiprocessing uses separate processes, bypasses GIL, good for CPU-bound tasks, but has overhead and requires pickling arguments/results. concurrent.futures provides a high-level interface (ThreadPoolExecutor, ProcessPoolExecutor) for both. Use threading for I/O, multiprocessing for CPU, concurrent.futures for simpler management. Multiprocessing pickles data to send between processes, so objects must be picklable.

P10 — Medium: What is __slots__? When should you use it, and what does it prevent? What is the memory impact?

`__slots__` is a class attribute that restricts the attributes to a fixed set, preventing dynamic attribute creation. It saves memory by not creating a `__dict__` per instance. Use it when you have many instances with known attributes and want to reduce memory usage. It prevents adding new attributes, which can be a feature or a limitation.

P11 — Easy: What is a virtual environment, and why should you use one? What is the difference between venv, virtualenv, and conda?

A virtual environment is an isolated Python environment with its own packages. It prevents dependency conflicts. `venv` is the built-in module (Python 3.3+), `virtualenv` is a third-party tool that is more flexible and works with older Python, `conda` is a package manager that also manages non-Python dependencies and environments. P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?

List comprehensions create lists with a concise syntax: `[expr for item in iterable if condition]`. Dict comprehensions: `{key: value for ...}`, set comprehensions: `{expr for ...}`. They are more readable and often faster than `map()` and `filter()` combined. Use comprehensions for simple transformations; use `map`/`filter` when you have a function to apply and want a functional style.

P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?

`==` checks value equality, `is` checks identity (same object). Object interning is a technique where small integers (-5 to 256) and some strings are cached, so `a is b` can be True for those values because they refer to the same object. For larger integers, `is` may be False.

P14 — Easy: Explain Python's *args and **kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?

`*args` collects extra positional arguments into a tuple, `**kwargs` collects extra keyword arguments into a dict. In function signatures, `/` before parameters marks them as positional-only, `*` after parameters marks them as keyword-only. Example: `def f(a, /, b, *, c):` a is positional-only, b can be positional or keyword, c is keyword-only.

P15 — Easy: What are context managers (with statement)? How do you write one using __enter__/__exit__ vs @contextmanager? Give an example beyond file handling.

Context managers manage resources with setup/cleanup. Implement `__enter__` and `__exit__` in a class, or use `@contextmanager` from contextlib to create a generator-based context manager. Example: a timer context manager that prints elapsed time.

```python
from contextlib import contextmanager

    start = time.time()

    print(f"Elapsed: {time.time()-start:.2f}s")
```

P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How does mypy or pyright use these for static analysis?

Type hints are annotations for function arguments and return types. `Union` allows multiple types, `Optional` is `Union[T, None]`, `Literal` restricts to specific values, `TypeVar` is a generic type variable, `Protocol` defines structural subtyping. Static type checkers like mypy use these to verify type correctness at compile time.

P17 — Medium: Explain Python's data model (dunder methods). What are __repr__ vs __str__, __eq__ vs __hash__, and __getattr__ vs __getattribute__? What happens if you define __eq__ but not __hash__?

Dunder methods define behavior for operators and built-in functions. `__repr__` is for debugging, `__str__` for user-friendly output. `__eq__` defines equality, `__hash__` defines hashability; if you define `__eq__` without `__hash__`, the instance becomes unhashable (hash set to None). `__getattr__` is called when attribute is not found, `__getattribute__` is called for every attribute access.

P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (__get__, __set__, __delete__). How do property, classmethod, and staticmethod use descriptors under the hood?

Descriptors are objects that define `__get__`, `__set__`, or `__delete__` to manage attribute access. `property` is a descriptor that wraps getter/setter/deleter methods. `classmethod` and `staticmethod` are descriptors that modify how the function is bound (class vs instance). They implement `__get__` to return a bound method or the function itself.

P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, __init__.py, and namespace packages work? What is a finder and a loader?

The import system uses `sys.path` to find modules. Absolute imports use the full package path; relative imports use dots (e.g., `from . import module`). `PYTHONPATH` adds directories to `sys.path`. `__init__.py` marks a directory as a package (though namespace packages can exist without it). A finder locates a module, a loader loads it. The import machinery uses finders and loaders to execute imports.

P20 — Hard: What is dataclasses and how does it compare to attrs and Pydantic? Explain __post_init__, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?

`dataclasses` is a standard library module that generates boilerplate for classes (init, repr, eq, etc.). `attrs` is a third-party library with more features (validators, converters). Pydantic is a data validation library that uses type hints for validation and serialization. `__post_init__` runs after `__init__` for additional initialization. Field factories allow default values that are mutable (e.g., `field(default_factory=list)`). Frozen dataclasses make instances immutable. Dataclasses support inheritance, but field ordering can be tricky. Choose Pydantic when you need validation, parsing from external data, or serialization; dataclasses for simple data containers.
