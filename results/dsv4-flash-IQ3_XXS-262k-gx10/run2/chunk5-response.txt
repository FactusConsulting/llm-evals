DN1 — Easy:  
`class` is a reference type (heap-allocated, nullable, supports inheritance/polymorphism). `struct` is a value type (stack/inline, copied by value, cannot be null unless `Nullable<T>`, no inheritance). Use `struct` for small, immutable, frequently copied data (e.g., `Point`, `DateTime`) where value semantics are desired and allocation overhead matters.

DN2 — Easy:  
`IEnumerable<T>` is for in-memory collections (LINQ to Objects) and executes delegates locally. `IQueryable<T>` is for query providers (e.g., EF Core) and builds expression trees that can be translated to SQL, enabling server-side filtering. The distinction matters because `IQueryable` defers execution and pushes operations to the database, reducing data transfer and improving performance.

DN3 — Medium:  
`async/await` uses the compiler to create state machines; `Task` represents an asynchronous operation that may allocate. `ValueTask` is a struct that avoids allocation when the result is already available or when used in high-frequency paths. Use `ValueTask` when you expect synchronous completion often and want to reduce GC pressure, but be aware it can only be awaited once and cannot be cached.

DN4 — Medium:  
Dependency injection (DI) in .NET: `Transient` creates a new instance per resolution, `Scoped` creates one per scope (e.g., HTTP request), `Singleton` creates one for the app lifetime. A common bug is injecting a `Scoped` service into a `Singleton`, which captures the scoped instance and can cause issues like `DbContext` disposal. Fix: use `IServiceScopeFactory` to create a scope inside the singleton, or change lifetimes.

DN5 — Medium:  
`string` is immutable, heap-allocated, UTF-16, and always owns its memory. `ReadOnlySpan<char>` is a stack-only ref struct that can point to any contiguous memory (stack, heap, native) without allocation, enabling zero-copy slicing and processing. Use `Span<T>` for performance-critical string parsing/slicing to avoid substring allocations.

DN6 — Medium:  
The .NET GC uses generations: Gen 0 (short-lived), Gen 1 (survivors), Gen 2 (long-lived). The Large Object Heap (LOH) holds objects >85KB and is collected less frequently. `IDisposable` is needed for unmanaged resources (files, sockets, COM) because the GC only manages managed memory; you must explicitly release unmanaged resources.

DN7 — Hard:  
`ConfigureAwait(false)` tells the continuation not to capture the `SynchronizationContext`, so it runs on a thread-pool thread instead of the original context. Use it in library code to avoid deadlocks and improve performance. Do NOT use it in UI code (e.g., WinForms/WPF) where you need to update UI on the captured context. The default behavior captures the context if present, which can cause deadlocks when blocking on async code.

DN8 — Hard:  
.NET 8/9 features:  
- Primary constructors: `public class MyService(ILogger<MyService> logger) { ... }`  
- Collection expressions: `int[] arr = [1,2,3];`  
- `FrozenDictionary` from `System.Collections.Frozen` for immutable, read-optimized dictionaries.  
Example with DI:  
```csharp
public class MyService(ILogger<MyService> logger, IConfiguration config)
{
    public void DoWork() => logger.LogInformation(config["key"]);
}
```

DN9 — Hard:  
`ObjectDisposedException` on `DbContext` under high concurrency usually means the `DbContext` is registered as `Singleton` or disposed prematurely. EF Core's `DbContext` is not thread-safe and should be `Scoped` per request. Fix: register as `Scoped` (`AddDbContext` does this by default), never manually dispose it, and avoid capturing it in singletons.

DN10 — Medium:  
`record` is a reference type with value equality, immutability (with `init` or positional parameters), and built-in `ToString`/`With` support. `record struct` is a value type with similar features. Use `record` for DTOs, domain events, or immutable data models; use `class` for mutable objects with identity.

DN11 — Easy:  
`ref` requires the variable to be initialized before passing; `out` must be assigned inside the method; `in` is a read-only reference. Use `ref` to modify the caller's value, `out` for multiple return values, and `in` to pass large structs by reference without copying (read-only).

DN12 — Easy:  
Nullable reference types (`string?`) are compile-time annotations that enable warnings for potential null dereferences; they do not change runtime behavior. Nullable value types (`int?`) are `Nullable<T>` structs that actually allow null at runtime. `#nullable enable` enables the feature for reference types.

DN13 — Easy:  
LINQ (Language Integrated Query) provides query capabilities. Method syntax uses extension methods (`list.Where(x => x > 5)`); query syntax is SQL-like (`from x in list where x > 5 select x`). Deferred execution means the query is not executed until enumerated (e.g., in a `foreach`), allowing composition and lazy evaluation.

DN14 — Easy:  
Generic constraints:  
- `where T : class` – reference type  
- `where T : struct` – value type  
- `where T : new()` – parameterless constructor  
- `where T : IComparable<T>` – implements interface  
Combine multiple constraints with commas: `where T : class, IComparable<T>, new()`.

DN15 — Easy:  
`abstract class` can have implementation, fields, constructors, and access modifiers; `interface` historically only declared contracts. Default interface methods (C# 8+) allow interfaces to provide implementations, blurring the distinction. Use abstract classes for shared base logic; interfaces for capability contracts.

DN16 — Medium:  
Middleware pipeline: `app.Use()` adds a middleware that can call the next delegate; `app.Map()` branches the pipeline based on path; `app.Run()` is a terminal middleware that ends the pipeline. Order matters—exception handling middleware should be first to catch exceptions from downstream. Middleware can be short-circuited by not calling `next`.

DN17 — Medium:  
`Channel<T>` is a thread-safe, async-aware producer-consumer queue with support for bounded capacity and backpressure. `BlockingCollection<T>` is older, blocking, and less async-friendly. Example of bounded channel:  
```csharp
var channel = Channel.CreateBounded<int>(10);
await channel.Writer.WriteAsync(1);
await foreach (var item in channel.Reader.ReadAllAsync()) { ... }
```

DN18 — Hard:  
Source Generators run at compile time to generate C# code, avoiding reflection overhead. They differ from reflection (runtime) and IL weaving (post-compilation). Incremental generators (`IIncrementalGenerator`) cache intermediate results and re-run only when inputs change, making them faster and more reliable than `ISourceGenerator`.

DN19 — Hard:  
TPL Dataflow provides `ActionBlock` (process each item), `TransformBlock` (transform items), and `BufferBlock` (buffering). It offers more control (e.g., parallelism, completion propagation) than `System.Threading.Channels`, which is lighter and more focused on producer-consumer patterns. For complex pipelines with branching/joining, Dataflow is better; for simple queues, Channels suffice.

DN20 — Hard:  
Minimal APIs are a lightweight way to build HTTP APIs with less boilerplate than controllers. They use top-level statements and route handlers. Trade-offs: less structure, but still testable via `WebApplicationFactory`; OpenAPI support via `AddEndpointsApiExplorer`; route groups (`MapGroup`) and endpoint filters (`AddFilter`) allow modularization and cross-cutting concerns.

P1 — Easy:  
`list` is mutable, `tuple` is immutable. `set` is mutable, `frozenset` is immutable. Tuples/frozensets are hashable and can be used as dict keys.

P2 — Easy:  
The GIL is a mutex in CPython that serializes bytecode execution, making multi-threading ineffective for CPU-bound tasks. It affects CPU-bound workloads (e.g., loops, math). Workarounds: use `multiprocessing` (separate processes), `asyncio` for I/O-bound, or C extensions that release the GIL.

P3 — Medium:  
`copy.copy` creates a shallow copy (references shared), `copy.deepcopy` recursively copies nested objects. Example:  
```python
a = [[1], [2]]
b = copy.copy(a)
b[0].append(3)  # a[0] also changes
```
Deepcopy avoids this.

P4 — Medium:  
Decorators are functions that wrap another function. Example:  
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.2f}s")
        return result
    return wrapper

@timer
def foo(): ...
```

P5 — Medium:  
Generators use `yield` to produce a sequence lazily, preserving state between iterations. They don't allocate the entire list. `yield from` delegates to another generator (e.g., `yield from subgen()`). Use generators for large/infinite sequences.

P6 — Medium:  
`asyncio.run()` runs a coroutine and manages the event loop. `asyncio.gather()` schedules multiple coroutines concurrently and waits for all. `asyncio.create_task()` schedules a coroutine as a task without blocking. `time.sleep()` blocks the event loop, so use `await asyncio.sleep()`.

P7 — Hard:  
Python 3 uses C3 linearization (MRO). For diamond inheritance `D(B, C)`, MRO is `D -> B -> C -> A -> object`. Since `C` overrides `who()`, `D().who()` returns `"C"` because `C` appears before `A` in MRO.

P8 — Hard:  
A metaclass is a class of a class, controlling class creation (e.g., `type`). `__init_subclass__` is a hook called when a subclass is created. Use metaclasses for complex class customization (e.g., registering classes, modifying attributes); use `__init_subclass__` for simpler cases like validating subclass attributes.

P9 — Hard:  
`threading` is for I/O-bound tasks (GIL releases during I/O). `multiprocessing` uses separate processes for CPU-bound tasks, but requires pickling of arguments/results. `concurrent.futures` provides high-level `ThreadPoolExecutor` and `ProcessPoolExecutor`. Pickling can fail for lambdas, local functions, or non-picklable objects.

P10 — Medium:  
`__slots__` prevents the creation of `__dict__`, saving memory and preventing dynamic attribute assignment. Use it for classes with many instances and fixed attributes. It restricts flexibility but improves performance.

P11 — Easy:  
A virtual environment isolates Python dependencies per project. `venv` is built-in, `virtualenv` is a third-party alternative, `conda` manages packages and environments (also non-Python). Use `venv` for simple projects.

P12 — Easy:  
List/dict/set comprehensions are concise ways to build collections: `[x for x in iterable if cond]`, `{k: v for ...}`, `{x for x in ...}`. `map()` and `filter()` are functional alternatives but less readable. Prefer comprehensions for clarity.

P13 — Easy:  
`==` compares values, `is` compares identity (memory address). Object interning caches small integers (-5 to 256) and some strings, so `a is b` may be `True` for those.

P14 — Easy:  
`*args` collects extra positional arguments into a tuple, `**kwargs` collects keyword arguments into a dict. In function signatures, `/` marks positional-only parameters, `*` marks keyword-only parameters.

P15 — Easy:  
Context managers use `with` to manage resources. Implement with `__enter__`/`__exit__` or `@contextmanager` from `contextlib`. Example: a timer context manager:  
```python
@contextmanager
def timer():
    start = time.time()
    yield
    print(f"Elapsed: {time.time()-start}")
```

P16 — Medium:  
Type hints: `Union` (e.g., `Union[int, str]`), `Optional` (`Optional[int]` = `Union[int, None]`), `Literal` (specific values), `TypeVar` (generic), `Protocol` (structural subtyping). Mypy/pyright use these to catch type errors statically.

P17 — Medium:  
`__repr__` is for debugging (unambiguous), `__str__` for user display. `__eq__` defines equality, `__hash__` must be consistent (if `__eq__` defined without `__hash__`, `__hash__` is set to `None`). `__getattr__` is called only when attribute not found; `__getattribute__` is called for every attribute access.

P18 — Hard:  
Descriptors implement `__get__`, `__set__`, `__delete__`. `property` uses `__get__`/`__set__`; `classmethod` and `staticmethod` are descriptors that bind the method to the class or ignore the instance.

P19 — Hard:  
The import system uses `sys.path` (list of directories) and `PYTHONPATH` to find modules. `__init__.py` marks a directory as a package. Namespace packages (without `__init__.py`) allow implicit packages. Finders locate modules, loaders execute them.

P20 — Hard:  
`dataclasses` is a built-in module for creating data classes with `__init__`, `__repr__`, etc. `attrs` offers more features (validators, converters). `Pydantic` adds validation, serialization, and schema generation. `__post_init__` runs after `__init__`, `field(default_factory=...)` for mutable defaults, `frozen=True` for immutability. Choose Pydantic when you need validation and parsing from external data.
