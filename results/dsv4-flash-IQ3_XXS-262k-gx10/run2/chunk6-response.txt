## JavaScript / TypeScript

**JS1 — Easy:**  
`var` is function-scoped, hoisted (declaration moved to top, initialized as `undefined`), and can be redeclared. `let` and `const` are block-scoped, hoisted but not initialized (temporal dead zone), and cannot be redeclared in the same scope. `const` additionally requires an initializer and cannot be reassigned (though object properties can mutate). Hoisting is the JavaScript engine's behavior of moving declarations to the top of their scope during compilation, affecting `var` (initialized) and function declarations (fully hoisted), while `let`/`const` are hoisted but remain uninitialized until execution reaches them.

**JS2 — Easy:**  
The event loop is the mechanism that handles asynchronous callbacks in JavaScript. The call stack executes synchronous code. When an async operation completes, its callback is placed in a queue. The event loop continuously checks if the call stack is empty; if so, it takes the first callback from the microtask queue (e.g., Promise callbacks, `queueMicrotask`) and processes it, then moves to the macrotask queue (e.g., `setTimeout`, I/O). Microtasks are processed before macrotasks, and each macrotask runs after the current microtask queue is drained.

**JS3 — Medium:**  
A closure is a function that retains access to its lexical scope even when executed outside that scope. Example: a counter factory that returns an increment function capturing a private variable. The classic for loop closure bug occurs when using `var` in a loop: all closures share the same variable, so they see the final value. Fix with `let` (block-scoped) or an IIFE to capture each iteration's value.

**JS4 — Medium:**  
Promises represent asynchronous operations. `async/await` is syntactic sugar over promises, making code look synchronous. Error handling: with promises, use `.catch()`; with async/await, use `try/catch`. `Promise.all` rejects immediately if any promise rejects; `Promise.allSettled` waits for all to settle and returns an array of `{status, value/reason}` objects, never rejecting.

**JS5 — Medium:**  
`interface` and `type` are both used to define shapes. `interface` can be extended/merged (declaration merging), while `type` can create unions, intersections, and mapped types. Use `interface` for object shapes that may be extended, `type` for aliases, unions, and complex types. Discriminated unions are a pattern using a common property (discriminant) to narrow types in a union, e.g., `type Shape = { kind: 'circle'; radius: number } | { kind: 'square'; side: number }`.

**JS6 — Medium:**  
Prototypal inheritance: objects inherit from other objects via the prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar over constructor functions and prototypes; `class` extends uses prototype chains under the hood. Methods are placed on `ClassName.prototype`, and `new` sets the prototype.

**JS7 — Hard:**  
The `this` keyword is determined by how a function is called. Binding rules (priority): 1) `new` binding (new object), 2) explicit binding (`call`, `apply`, `bind`), 3) implicit binding (method call: `obj.method()`), 4) default binding (global object or `undefined` in strict mode). `bind()` returns a new function with `this` permanently set to the provided value; it cannot be re-bound (even with `call`/`apply`), except by using `new` (which overrides it).

**JS8 — Hard:**  
`WeakRef` allows holding a weak reference to an object without preventing garbage collection. `FinalizationRegistry` lets you register callbacks to run when an object is garbage collected. They are used for caching, resource cleanup, or tracking objects without leaking memory. `WeakMap` keys must be objects because they are held weakly; if keys were primitives, they couldn't be garbage collected independently. This enables memory-safe associations.

**JS9 — Hard:**  
V8 optimizes via hidden classes (maps) that track object shapes, inline caching (caching property lookup results), and JIT compilation. Deoptimization occurs when a function's assumptions break, e.g., adding new properties to an object changes its hidden class, or passing different types to a function. Patterns that cause deoptimization: changing object shapes dynamically, using `delete`, accessing out-of-bounds arrays, and using `eval` or `with`.

**JS10 — Medium:**  
Tree-shaking is dead-code elimination during bundling. It works with ES modules because they are statically analyzable (imports/exports are explicit). CommonJS is dynamic (`require` can be conditional), making it hard to determine unused exports, so bundlers cannot reliably tree-shake CommonJS.

**JS11 — Easy:**  
`null` is an explicit empty value; `undefined` is the default for uninitialized variables. `==` compares loosely (null == undefined is true), `===` compares strictly (false). Nullish coalescing `??` returns the right-hand side if the left is `null` or `undefined`; optional chaining `?.` short-circuits if the preceding value is `null`/`undefined`.

**JS12 — Easy:**  
`map()` transforms each element and returns a new array. `filter()` returns elements that pass a test. `reduce()` accumulates values; with an initial value, it starts with that value and processes each element. `flatMap()` maps each element and flattens the result one level, useful for flattening nested arrays or generating multiple items per input.

**JS13 — Easy:**  
Template literals are backtick-delimited strings supporting interpolation (`${expr}`) and multi-line. Tagged templates allow a function to process the template literal's strings and substitutions. Example: a tag function that escapes HTML:
```js
function escapeHtml(strings, ...values) {
  return strings.reduce((acc, str, i) => acc + str + (i < values.length ? escape(values[i]) : ''), '');
}
```

**JS14 — Easy:**  
Destructuring extracts values from objects/arrays into variables. Object destructuring uses `{ prop: localName }` and can set defaults. Array destructuring uses `[a, b]` and can skip elements. The rest operator `...` collects remaining properties/elements into a new object/array.

**JS15 — Easy:**  
`for...in` iterates over enumerable property keys (including inherited), `for...of` iterates over iterable values (e.g., array elements). Avoid `for...in` on arrays because it includes non-index properties and order is not guaranteed.

**JS16 — Medium:**  
Generics allow creating reusable components with type parameters. Constraints (`extends`) limit the type parameter to a shape. Conditional types use `T extends U ? X : Y` to choose types. `infer` extracts a type from a conditional. Example: `type ElementType<T> = T extends (infer U)[] ? U : never;`

**JS17 — Medium:**  
CommonJS uses `require`/`module.exports`, synchronous, used in Node.js by default. ES Modules use `import`/`export`, asynchronous, static. Node.js supports both; `"type": "module"` in package.json makes `.js` files treated as ES modules. CommonJS is the default otherwise.

**JS18 — Hard:**  
TypeScript's structural typing means types are compatible if their members match. Excess property checks occur when assigning an object literal to a typed variable, flagging extra properties. `extends` in generics constrains types; `satisfies` (TS 4.9) checks a value against a type without changing its inferred type. Variance: `in` (contravariant) for inputs, `out` (covariant) for outputs, used in conditional types and function parameters.

**JS19 — Hard:**  
`Proxy` allows custom behavior for operations like property access, assignment, and function calls via traps. `Reflect` provides methods that correspond to default operations, useful inside traps. Example: a validation proxy that checks property values before setting.

**JS20 — Hard:**  
`SharedArrayBuffer` is a fixed-length binary buffer that can be shared between workers. `Atomics` provides atomic operations (e.g., `add`, `load`, `store`) to avoid race conditions. Workers communicate by sharing a `SharedArrayBuffer` and using `Atomics.wait` to block until a condition, and `Atomics.notify` to wake waiting workers. Ordering guarantees are based on the memory model (e.g., `Atomics.store` followed by `Atomics.load` ensures visibility).

## Bash

**B1 — Easy:**  
`$@` and `$*` both expand to positional parameters. Unquoted, they are identical. Quoted: `"$@"` expands each parameter as a separate word (preserving spaces), while `"$*"` expands to a single word with spaces between parameters.

**B2 — Easy:**  
`set -e` exits on any command failure (non-zero exit). `set -u` treats unset variables as an error. `set -o pipefail` makes a pipeline return the exit status of the last command that failed (instead of the last command). Combined, they make scripts more robust.

**B3 — Medium:**  
`$(command)` and backticks both perform command substitution, but `$(...)` is preferred (nesting, quoting). `$((expression))` performs arithmetic expansion; `expr` is an external command that is slower and less safe.

**B4 — Medium:**  
Process substitution `<(...)` creates a file descriptor that a command can read as if it were a file. Example: `diff <(sort file1) <(sort file2)` compares sorted outputs without creating temporary files.

**B5 — Medium:**  
Use `find ... -print0 | while IFS= read -r -d '' file; do ...; done` or `for file in *; do ...` with proper quoting. `for f in $(ls)` splits on spaces, newlines, and globs, leading to errors.

**B6 — Medium:**  
A here document (`<<EOF`) feeds a block of text to a command's stdin. A here string (`<<<`) feeds a single string. `<<-EOF` removes leading tabs (allows indentation) from the here document.

**B7 — Hard:**  
`cmd > file 2>&1` redirects stdout to file, then stderr to the same file (both to file). `cmd 2>&1 > file` redirects stderr to the current stdout (terminal), then stdout to file, so stderr goes to terminal, stdout to file. `cmd &> file` is shorthand for `> file 2>&1` (both to file).

**B8 — Hard:**  
A safe lock using `mkdir` (atomic) with a trap:
```bash
lock_dir="/tmp/mylock.$$"
while ! mkdir "$lock_dir" 2>/dev/null; do
  sleep 1
done
trap 'rmdir "$lock_dir"' EXIT
```
`mkdir` is atomic, so only one process succeeds. Trap on EXIT cleans up even if killed (SIGTERM triggers EXIT? Actually SIGTERM doesn't trigger EXIT unless trapped; add `trap 'rmdir "$lock_dir"; exit' TERM INT`). File creation is not atomic and can have race conditions.

**B9 — Easy:**  
Single quotes preserve literal characters. Double quotes allow variable expansion and command substitution but preserve spaces. No quotes split words and perform globbing. Example: `echo '$HOME'` prints `$HOME`, `echo "$HOME"` prints the value, `echo $HOME` may split if value has spaces.

**B10 — Easy:**  
Use `-f` for file, `-d` for directory, `-r` for readable. `[ ]` is the `test` command (POSIX), `[[ ]]` is a bash keyword with more features (pattern matching, regex, no word splitting).

**B11 — Easy:**  
`$?` exit status of last command. `$$` PID of current shell. `$!` PID of last background job. `$#` number of positional parameters. Use cases: check success, log PID, wait for background job, loop over arguments.

**B12 — Easy:**  
Functions: `foo() { ...; }` or `function foo { ...; }` (both work). Return values via `return` (exit status) or `echo` to capture output. Use `local` for local variables.

**B13 — Easy:**  
`PATH` is a colon-separated list of directories. Bash searches each directory for an executable. Builtins are part of the shell (e.g., `cd`, `echo`), external commands are separate executables. Use `type -a cmd` to see all, `which` for external.

**B14 — Medium:**  
`trap 'command' SIGNAL` sets a handler. For EXIT, it runs on script exit; ERR on any command failure; INT on Ctrl-C; TERM on termination. Multiple signals: handlers run in order of signal arrival, but if a signal arrives while handling another, it may be deferred.

**B15 — Medium:**  
`xargs` reads items from stdin and runs a command with them, handling quoting. Command substitution captures output as a string. For filenames with spaces/newlines, use `find -print0 | xargs -0`. `xargs -P` runs multiple processes in parallel.

**B16 — Medium:**  
Arrays: `arr=(a b c)`, append `arr+=(d)`, iterate `for i in "${arr[@]}"`, length `${#arr[@]}`. Associative arrays: `declare -A assoc`, `assoc[key]=value`, iterate keys with `"${!assoc[@]}"`. Syntax differs: indices vs keys.

**B17 — Hard:**  
A subshell `( ... )` runs in a child shell, variable changes don't affect parent. A group `{ ...; }` runs in current shell, changes persist. Piping into a while loop runs the loop in a subshell (unless `lastpipe`), so variable changes are lost.

**B18 — Hard:**  
Signals: SIGINT (Ctrl-C), SIGTERM (terminate), SIGHUP (hangup), SIGKILL (cannot be caught). To handle graceful shutdown, trap TERM/INT, kill background processes, wait, and exit. Use `trap 'kill $pid; wait' TERM INT`.

**B19 — Hard:**  
Example: split log into chunks, process each with `xargs -P`, then concatenate. Use `split -l 1000 log chunk.` then `find chunk.* -print0 | xargs -0 -P 4 -I {} process {} > {}.out` and `cat chunk.*.out > merged`. Trade-offs: parallel speedup vs overhead, error handling via exit codes and `xargs`'s `--halt` option.

**B20 — Hard:**  
`exec` replaces the current shell with a command, or manipulates file descriptors. `exec 3>file` opens fd 3 for writing. `exec 3>&-` closes it. A coprocess is a background process with two-way communication: `coproc NAME { command; }`, then write to `NAME[0]` and read from `NAME[1]`. Useful for interactive processes.

## PowerShell

**PS1 — Easy:**  
`Write-Output` sends objects to the pipeline (output stream), `Write-Host` writes to the console host directly, bypassing the pipeline. `Write-Output` is preferred for data; `Write-Host` is for display only.

**PS2 — Easy:**  
The pipeline passes objects from one command to the next. `ForEach-Object` is a cmdlet that processes each pipeline object, while `foreach` is a language statement for iterating over a collection. Use `ForEach-Object` in a pipeline, `foreach` for local loops.

**PS3 — Medium:**  
`[PSCustomObject]` is a structured object with named properties; `[hashtable]` is a key-value pair collection. Use `PSCustomObject` for output, `hashtable` for lookups. Convert: `[PSCustomObject]$hashtable` or `$hashtable.GetEnumerator()`.

**PS4 — Medium:**  
Terminating errors stop execution; non-terminating errors continue. `-ErrorAction` overrides `$ErrorActionPreference` for a cmdlet. `try/catch` catches terminating errors. `$ErrorActionPreference = 'Stop'` makes non-terminating errors terminating.

**PS5 — Medium:**  
Splatting passes a collection of parameters to a command using `@params`. Example: `$params = @{Path='C:\'; Recurse=$true}; Get-ChildItem @params`. It differs from passing a hashtable as a single parameter because splatting expands keys as named parameters.

**PS6 — Medium:**  
PowerShell remoting uses WinRM (HTTP/SOAP) or SSH. `Invoke-Command -ComputerName` runs commands remotely and returns results; `Enter-PSSession` gives an interactive session. WinRM is the default, SSH is supported in PS 7+.

**PS7 — Hard:**  
PowerShell functions output all objects to the pipeline, not the return value. In the example, `$result` is an array, but when returned, PowerShell enumerates it, so `$x` becomes a string (if one element) or an array (if multiple). If zero items, `$x` is `$null`. Correct pattern: use `return` with `Write-Output -NoEnumerate` or `@($result)` to force array.

**PS8 — Hard:**  
A scriptblock is a block of code, a function is a named scriptblock with parameters. To pass a scriptblock remotely, use `Invoke-Command -ScriptBlock { ... }`. Double-hop occurs when credentials are needed across multiple remote connections; solve with CredSSP or `-Credential` delegation, or use `Invoke-Command -ArgumentList` to pass variables.

**PS9 — Easy:**  
`@()` is the array subexpression operator, `[array]` is a type accelerator. To force a single result into an array, use `@($result)`. Indexing into `$null` returns `$null`; indexing into an empty array throws an error.

**PS10 — Easy:**  
Comparison operators are case-insensitive by default (`-eq`, `-like`, `-match`). Case-sensitive variants start with `c` (`-ceq`, `-clike`). `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection (opposite order).

**PS11 — Easy:**  
A module is a package of functions, cmdlets, etc. Script module (`.psm1`) contains PowerShell code; manifest module (`.psd1`) describes metadata and dependencies; binary module (`.dll`) is compiled. `Import-Module` loads the module into the session.

**PS12 — Easy:**  
Double quotes allow variable expansion and subexpressions (`$()`), single quotes are literal. Here-strings: `@"..."@` for double-quoted (interpolated), `@'...'@` for single-quoted (literal).

**PS13 — Easy:**  
`Get-Member` shows properties and methods of objects. Properties are data, Methods are actions, NoteProperties are added by PowerShell (e.g., from `Add-Member`). `Select-Object` selects properties, `Where-Object` filters objects.

**PS14 — Medium:**  
PowerShell classes (v5) are similar to C# but with limitations: no multiple inheritance, no interfaces (until PS 7? Actually still limited), constructors are limited, and methods are not overloaded easily. Use classes for complex state and behavior, functions for simple scripts.

**PS15 — Medium:**  
`[CmdletBinding()]` adds advanced function features: parameter validation, `-Verbose`, `-Debug`, etc. `SupportsShouldProcess` enables `-WhatIf`/`-Confirm`. `DefaultParameterSetName` sets the default parameter set. `ValueFromPipeline` allows pipeline input. `Begin` runs once, `Process` runs for each pipeline input, `End` runs once.

**PS16 — Medium:**  
Providers expose data stores as drives. `Get-ChildItem` works on FileSystem, Registry (e.g., `HKLM:\`), Certificate (`Cert:\`), Environment (`Env:`). You can navigate registry like filesystem: `Set-Location HKLM:\Software`.

**PS17 — Hard:**  
Runspaces are PowerShell execution environments. `[runspace]` is a single runspace, `[runspacepool]` is a pool, `[powershell]` is a PowerShell instance. `ForEach-Object -Parallel` (PS 7+) uses runspaces internally. Manual runspace management gives more control but is complex.

**PS18 — Hard:**  
PSScriptAnalyzer is a static analysis tool that checks scripts for style, best practices, and potential errors. It has rules with severity levels (Error, Warning, Information). Custom rules can be written. Suppress with `[Diagnostics.CodeAnalysis.SuppressMessageAttribute]` or `# pragma`. Integrate with CI/CD by running `Invoke-ScriptAnalyzer` and failing on errors.

**PS19 — Hard:**  
`$using:` is used in remote sessions, background jobs, and `ForEach-Object -Parallel` to capture local variables. `-ArgumentList` passes arguments to a scriptblock. Serialization limits: objects are serialized to CLIXML with a depth limit (default 2), so complex objects may lose type information.

**PS20 — Hard:**  
DSC is a declarative configuration management platform. Configurations are scripts that generate MOF files, resources are PowerShell modules that implement `Get/Set/Test-TargetResource`, and the LCM applies configurations. In PowerShell 7+, DSC is not included by default; it's replaced by tools like Pulumi, Terraform, or DSCv3 (in development).
