## Go

**G1** — An array has a fixed length and is a value type; a slice is a dynamic view with pointer, length, and capacity. When appending to a slice at capacity, Go allocates a new larger backing array, copies the old elements, and returns a new slice referencing it.

**G2** — `var x int` declares `x` with zero value (`0`); `x := 0` declares and initializes with type inference. You cannot use `:=` at package scope (only inside functions), and in a short variable declaration at least one variable on the left must be new.

**G3** — A goroutine is a lightweight, user-space thread managed by the Go runtime, not the OS. It has a small growable stack and is multiplexed onto OS threads. The GMP model: G (goroutine), M (OS thread), P (logical processor). The scheduler assigns Gs to Ms via Ps, using work stealing and preemption.

**G4** — Channels are typed communication primitives. An unbuffered channel blocks send until a receiver is ready; a buffered channel has capacity and blocks send only when full. Sending to a full buffered channel blocks until a receive frees space.

**G5** — The `context` package carries deadlines, cancellation signals, and values across API boundaries. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
resp, err := http.DefaultClient.Do(req)
```

**G6** — Go interfaces are structural: a type satisfies an interface implicitly if it implements all methods. Unlike Java/C#, no explicit `implements` declaration. The empty interface `interface{}` (or `any`) accepts every type; it is powerful for generic-like code but dangerous because it requires type assertions and can panic if the type is wrong.

**G7** — The code has a data race: there is no happens-before edge between the goroutine writes and the main goroutine reads. The compiler/CPU may reorder, and the loop may never see `ready`. Correct alternatives: use a channel, `sync.WaitGroup`, `sync.Mutex`, or `atomic.Bool` with proper synchronization.

**G8** — `sync.Mutex` gives exclusive access; `sync.RWMutex` allows multiple readers but only one writer. `sync.Map` is optimized for read-heavy, append-only, or disjoint-key workloads; a regular map with a mutex is simpler and often faster for writes. `sync.Map` has overhead for writes and is not a drop-in replacement.

**G9** — `go.mod` defines the module path, dependencies, and versions; `go.sum` contains cryptographic checksums for dependency integrity. `go mod tidy` adds missing dependencies and removes unused ones. Minimum Version Selection (MVS) chooses the minimal version that satisfies all transitive constraints, ensuring reproducible builds.

**G10** — `defer` schedules a function call to run when the surrounding function returns. Multiple defers execute in LIFO order. A common gotcha: deferring in a loop accumulates calls until the function ends, not per iteration; wrap in an inner function or use explicit cleanup.

**G11** — A pointer stores the memory address of a value; its zero value is `nil`. You can create a pointer to a struct literal with `&Struct{...}`.

**G12** — `init()` runs after package-level variable initialization and before `main()`. A package can have multiple `init()` functions; they execute in file order (lexical by filename) and in source order within a file.

**G13** — `make` works only for slices, maps, and channels, returning an initialized value ready to use. `new` allocates zeroed memory for any type and returns a pointer to it.

**G14** — Errors are values implementing `error` (`Error() string`). Idiomatic handling: `if err != nil { ... }`. `errors.Is` checks for a wrapped sentinel error; `errors.As` finds a specific error type. `==` only works for comparable sentinel errors and does not unwrap.

**G15** — Composite types: map (zero value `nil`), slice (`nil`), channel (`nil`), struct (all fields zero). A nil map/slice/channel behaves like an empty one for reads but cannot be written to without initialization.

**G16** — A race condition occurs when multiple goroutines access the same memory concurrently and at least one writes. The `-race` flag instruments the runtime to detect data races. Example:
```go
var counter int
go func() { counter++ }()
counter++
```
Fix with a mutex:
```go
var mu sync.Mutex
go func() { mu.Lock(); counter++; mu.Unlock() }()
mu.Lock(); counter++; mu.Unlock()
```

**G17** — `select` waits on multiple channel operations; it differs from `switch` because it is channel-specific and blocks until one case is ready. If multiple cases are ready, it picks one randomly. Timeout example:
```go
select {
case v := <-ch:
    // use v
case <-time.After(1 * time.Second):
    // timeout
}
```

**G18** — Escape analysis determines whether a variable is allocated on the stack or heap. If a variable's address escapes (e.g., returned, stored in a global, passed to a goroutine), it goes to the heap. Inspect with `go build -gcflags=-m`. It matters because heap allocations increase GC pressure and reduce performance.

**G19** — `reflect.Type` describes a type's metadata; `reflect.Value` holds a runtime value. Reflection is slow, prevents inlining, and causes allocations. It is justified for generic serialization, debugging, or dynamic dispatch; for performance-critical code, prefer code generation (e.g., `genny`, `stringer`).

**G20** — `//go:embed` embeds files into the binary at compile time. It works for single files, directories (as `embed.FS`), and glob patterns. Limitations: no `../` paths, no absolute paths, and files starting with `.` or `_` are excluded. `embed.FS` implements `io/fs.FS`, enabling standard filesystem operations.

## Rust

**R1** — Ownership rules: (1) each value has a single owner, (2) only one owner at a time, (3) when the owner goes out of scope, the value is dropped. This ensures memory safety without a garbage collector.

**R2** — `String` is an owned, heap-allocated UTF-8 string; `&str` is a borrowed string slice. Use `&str` for read-only parameters to avoid allocation; use `String` when you need ownership or mutation.

**R3** — Borrowing creates references without transferring ownership. Rules: you can have many shared references (`&T`) or one mutable reference (`&mut T`), but not both simultaneously. The borrow checker enforces this at compile time.

**R4** — `Result<T, E>` represents success (`Ok`) or failure (`Err`); `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator unwraps `Ok`/`Some` or returns early with `Err`/`None`. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

**R5** — `Box<T>` gives a single owner on the heap; `Rc<T>` provides shared ownership with non-atomic reference counting (single-threaded); `Arc<T>` is atomic reference counting for multi-threaded use. Use `Box` for heap allocation, `Rc` for shared ownership in one thread, `Arc` for shared across threads.

**R6** — Traits define shared behavior. Go interfaces are structural; Rust traits are nominal and can include associated types, generics, and default methods. A trait object `dyn Trait` uses dynamic dispatch; a generic with `T: Trait` uses static dispatch (monomorphization).

**R7** — The function lacks a lifetime linking the output to the inputs. Fix:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** — `Send` means a type can be moved across threads; `Sync` means it can be shared safely. `Rc<T>` is not `Send` because its reference count is non-atomic and could be corrupted. `Arc<T>` uses atomic operations, making it safe to share across threads.

**R9** — `async`/`await` creates a `Future`, a state machine that is polled by an executor (e.g., Tokio). Futures are stackless and cooperative; goroutines are preemptive and have their own stacks. Executors manage polling and scheduling, whereas Go's runtime schedules goroutines.

**R10** — `unsafe` allows: dereferencing raw pointers, calling unsafe functions, accessing mutable statics, and implementing unsafe traits. It is justified for FFI, low-level performance, or when invariants cannot be expressed in safe Rust.

**R11** — Pattern matching with `match` is exhaustive; the compiler requires all possible cases to be covered. `if let` is a shorthand for matching a single pattern and does not require exhaustiveness.

**R12** — `Vec<T>` is a heap-allocated dynamic array; `[T; N]` is a fixed-size stack array. When `Vec` exceeds capacity, it reallocates a larger buffer (typically doubling) and copies elements.

**R13** — Rust enums can carry data in each variant, unlike C/Java enums. `Option<T>` is `Some(T)` or `None`, eliminating null. Rust avoids null because it causes runtime errors; `Option` forces explicit handling.

**R14** — `impl` blocks define methods. `&self` borrows immutably, `&mut self` borrows mutably, `self` consumes the value. Associated functions (e.g., `String::new()`) are like static methods and do not take `self`.

**R15** — `derive` generates trait implementations automatically. Common: `Debug`, `Clone`, `PartialEq`, `Serialize` (serde). You cannot derive a trait if the type's fields do not implement it, or if the trait has associated types/constraints that cannot be derived.

**R16** — `Cow<'a, T>` is an enum that is either `Borrowed` or `Owned`. It avoids allocation when you only need to read, but clones when mutation is required. Example:
```rust
fn process(s: &str) -> Cow<'_, str> {
    if s.contains("x") {
        Cow::Owned(s.replace("x", "y"))
    } else {
        Cow::Borrowed(s)
    }
}
```

**R17** — `mod` declares a module, `use` imports items, `pub` makes them public. In Rust 2015, a module `foo` could be `foo.rs` or `foo/mod.rs`; in 2018, `foo.rs` is the preferred root, with submodules in `foo/` directory.

**R18** — `Pin<T>` prevents a type from being moved after it is pinned. It is needed for self-referential structs and async futures, which may contain pointers to their own stack. `Unpin` is a marker trait; most types are `Unpin` and can be moved freely.

**R19** — `macro_rules!` are declarative macros using pattern matching; they are hygienic for local variables. Procedural macros (derive, attribute, function-like) operate on token streams and are more powerful but not fully hygienic. Hygiene prevents name collisions.

**R20** — Zero-cost abstractions mean high-level code compiles to efficient machine code without runtime overhead. Iterators are inlined into loops, generics are monomorphized (no virtual dispatch), and trait bounds use static dispatch, matching hand-written C performance.
