JS1 — Easy: Explain the difference between var, let, and const. What is hoisting?

- **var**: Function-scoped, hoisted (declaration is moved to top, initialized as `undefined`), can be redeclared and reassigned.
- **let**: Block-scoped, hoisted but in a temporal dead zone (TDZ) until declaration, cannot be redeclared in the same scope, can be reassigned.
- **const**: Block-scoped, must be initialized at declaration, cannot be reassigned (but object properties can be mutated), also hoisted with TDZ.
- **Hoisting**: JavaScript moves declarations to the top of their scope. `var` declarations are initialized with `undefined`; `let` and `const` are not initialized, causing a ReferenceError if accessed before declaration.

JS2 — Easy: What is the event loop? Explain the relationship between the call stack, microtask queue, and macrotask queue.

- **Call stack**: LIFO structure that tracks function calls.
- **Microtask queue**: Contains promises, `queueMicrotask`, `MutationObserver`. Processed after the current call stack empties, before any macrotask.
- **Macrotask queue**: Contains `setTimeout`, `setInterval`, I/O, UI rendering. Processed one per event loop iteration.
- **Event loop**: Continuously checks if the call stack is empty, then processes all microtasks, then one macrotask, repeating.

JS3 — Medium: What is a closure? Give a practical example. What is the classic for loop closure bug, and how do you fix it?

- **Closure**: A function that retains access to its outer (lexical) scope even after the outer function has returned.
- **Example**: 
  ```js
  function counter() {
    let count = 0;
    return () => ++count;
  }
  const inc = counter();
  inc(); // 1
  ```
- **Classic for loop bug**: Using `var` in a loop, closures capture the variable, not its value at each iteration.
  ```js
  for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100); // logs 3,3,3
  }
  ```
- **Fix**: Use `let` (block-scoped) or an IIFE to capture the value.

JS4 — Medium: Explain Promise, async/await, and how error handling works with both. What is Promise.allSettled vs Promise.all?

- **Promise**: An object representing the eventual completion (or failure) of an asynchronous operation.
- **async/await**: Syntactic sugar over promises. `async` functions return a promise; `await` pauses execution until the promise settles.
- **Error handling**: With promises, use `.catch()`; with async/await, use `try/catch`.
- **Promise.all**: Rejects immediately if any promise rejects; returns an array of results.
- **Promise.allSettled**: Waits for all promises to settle; returns an array of `{status: 'fulfilled'|'rejected', value/reason}`.

JS5 — Medium: What is the difference between TypeScript's interface and type? When would you use each? What are discriminated unions?

- **interface**: Can be extended/merged, primarily for object shapes, supports declaration merging.
- **type**: Can represent any type (primitives, unions, tuples, mapped types, etc.), cannot be merged.

JS7 — Hard: Explain the `this` keyword in JavaScript. What are the 4 binding rules (in priority order)? What does bind() return, and can you re-bind it?

- **`this`** is determined by how a function is called.
- **Binding rules (priority)**:
  1. **new** binding (when used with `new`).
  2. **Explicit** binding (`call`, `apply`, `bind`).
  3. **Implicit** binding (method call: `obj.method()`).
  4. **Default** binding (global object, or `undefined` in strict mode).
- **`bind()`** returns a new function with `this` permanently set to the provided value. You cannot re-bind a bound function's `this` (except when using `new`, which overrides it).

- **WeakRef**: Holds a weak reference to an object, allowing you to retrieve it if it hasn't been garbage collected.
- **FinalizationRegistry**: Registers callbacks to be invoked when objects are garbage collected.
- **Use cases**: Caching, memory management, tracking resources.
- **WeakMap keys must be objects** because they are held weakly; if the key is a primitive, it cannot be garbage collected. This allows the key-value pair to be removed when the key is no longer referenced elsewhere.

JS9 — Hard: Explain how the V8 engine optimizes JavaScript. Cover: hidden classes, inline caching, and deoptimization. What coding patterns cause deoptimization?

- **Hidden classes**: V8 assigns internal "shapes" to objects to optimize property access. Adding/removing properties changes the shape.
- **Inline caching**: Caches property access based on the object's shape to avoid repeated lookups.
- **Deoptimization**: When assumptions about object shapes or types break, V8 reverts to interpreted code.
- **Patterns causing deoptimization**: Changing object shape dynamically, using `eval`, `try/catch` (in some cases), accessing properties with dynamic keys, mixing types in arrays.

  ```js
  const html = escapeHtml`<p>${userInput}</p>`;
  ```

JS16 — Medium: Explain TypeScript generics. What are generic constraints (extends), conditional types (T extends U ? X : Y), and the infer keyword? Give a practical example of each.

- **Generics**: Allow creating reusable components that work with a variety of types.
  ```ts
  function identity<T>(arg: T): T { return arg; }
  ```
- **Constraints**: `T extends U` ensures `T` has the properties of `U`.
  ```ts
  function getLength<T extends { length: number }>(arg: T): number { return arg.length; }
  ```
- **Conditional types**: `T extends U ? X : Y` selects a type based on a condition.
  ```ts
  type IsArray<T> = T extends any[] ? true : false;
  ```
- **`infer`**: Used in conditional types to infer a type from a type.
  ```ts
  type ElementType<T> = T extends (infer U)[] ? U : never;
  ```

JS19 — Hard: What are Proxy and Reflect in JavaScript? How do you intercept property access, assignment, and function calls? Give a practical example (e.g., validation, logging, or reactive data binding).

- **Proxy**: Wraps an object and intercepts operations via a handler.

JS20 — Hard: Explain SharedArrayBuffer and Atomics in JavaScript. How do Web Workers communicate using shared memory? What are the ordering guarantees, and how does Atomics.wait/Atomics.notify work?

- **SharedArrayBuffer**: A fixed-length binary buffer that can be shared between threads (Web Workers).
- **Atomics**: Provides atomic operations (e.g., `Atomics.add`, `Atomics.load`) to ensure synchronization.

B7 — Hard: Explain the difference between these redirections:
```bash
cmd > file 2>&1
cmd 2>&1 > file
cmd &> file
```
Why do the first two produce different results?

- **`cmd > file 2>&1`**: Redirects stdout to file, then stderr to the same file (both go to file).
- **`cmd 2>&1 > file`**: Redirects stderr to the current stdout (terminal), then stdout to file. So stderr goes to terminal, stdout to file.
- **`cmd &> file`**: Redirects both stdout and stderr to file (equivalent to first).
- The order matters because redirections are processed left-to-right.

- **Use classes** for complex stateful objects; **functions** for simple operations.

PS15 — Medium: Explain PowerShell's CmdletBinding and advanced functions. What does [CmdletBinding()] enable? What are SupportsShouldProcess, DefaultParameterSetName, and ValueFromPipeline? How do Begin, Process, and End blocks work?

- **`[CmdletBinding()]`**: Adds advanced function features (parameter validation, `-Verbose`, etc.).
- **`SupportsShouldProcess`**: Enables `-WhatIf` and `-Confirm`.
- **`DefaultParameterSetName`**: Specifies the default parameter set.
- **`ValueFromPipeline`**: Allows the function to accept pipeline input.
- **`Begin`**: Runs once. **`Process`**: Runs for each pipeline input. **`End`**: Runs once after all input.

PS16 — Medium: What is the PowerShell providers system? Explain how Get-ChildItem works across different providers (FileSystem, Registry, Certificate, Environment). How do you access the registry like a file system?

- **Providers**: Expose data stores as drives (e.g., `C:`, `HKLM:`, `Cert:`).
- **`Get-ChildItem`** works on any provider.
- **Registry**: Use `Set-Location HKLM:\Software` and `Get-ChildItem`.

PS17 — Hard: Explain PowerShell's runspaces and thread safety. What is a [runspace], [runspacepool], and [powershell] object? How do you use ForEach-Object -Parallel (v7+) vs manual runspace management for parallel execution?

- **Runspace**: A PowerShell host environment for executing commands.
- **RunspacePool**: A pool of runspaces for parallel execution.
- **`[powershell]`**: Object that represents a PowerShell instance.
- **`ForEach-Object -Parallel`**: Simpler parallel execution in PS7+.
- **Manual runspaces**: More control but complex.

PS18 — Hard: What is PSScriptAnalyzer? How does it enforce coding standards? Explain the difference between rules, severity levels, and custom rules. How do you suppress rules, and how does it integrate with CI/CD pipelines?

- **PSScriptAnalyzer**: Static analysis tool for PowerShell.
- **Rules**: Checks for best practices (e.g., uninitialized variables).
- **Severity levels**: Error, Warning, Information.

PS20 — Hard: Explain Desired State Configuration (DSC). What are configurations, resources, and the Local Configuration Manager (LCM)? How does DSC differ between Windows PowerShell and PowerShell 7+? What replaced it in modern infrastructure-as-code?

- **DSC**: A management platform to ensure system state.
- **Configurations**: Declarative scripts that define desired state.
- **Resources**: Modules that implement the state logic.
- **LCM**: The engine that applies configurations.
- **Differences**: Windows PowerShell uses `Start-DscConfiguration`; PowerShell 7+ uses `Invoke-DscResource` (pull model).
- **Replaced by**: Modern IaC tools like Terraform, Bicep, Ansible, and Pulumi.
