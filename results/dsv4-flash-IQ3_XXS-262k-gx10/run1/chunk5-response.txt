DN1 — Easy:  
A `class` is a reference type stored on the heap; it supports inheritance, polymorphism, and can be `null`. A `struct` is a value type stored inline (stack or embedded), copied by value, cannot be `null` (unless `Nullable<T>`), and does not support inheritance (except interfaces). Use a `struct` for small, immutable, and frequently copied data (e.g., `Point`, `DateTime`) to avoid heap allocations and improve cache locality.

DN2 — Easy:  
`IEnumerable<T>` represents an in-memory sequence and uses delegates; LINQ-to-Objects executes locally. `IQueryable<T>` is designed for query providers (e.g., EF Core) and builds an expression tree that can be translated to SQL, enabling server-side filtering and deferred execution. The distinction matters because `IQueryable` allows the database to optimize the query, whereas `IEnumerable` would fetch all data into memory first.

DN3 — Medium:  
`async/await` compiles into a state machine that yields control at `await` points and resumes on a captured synchronization context. `Task` is a reference type representing an asynchronous operation; `ValueTask` is a struct that avoids allocation when the result is often available synchronously. Use `ValueTask` in high-performance paths where the operation frequently completes synchronously, but note it can only be awaited once and is not suitable for caching.

DN4 — Medium:  
Dependency injection (DI) in .NET registers services with lifetimes:  
- **Transient**: created each time requested.  
- **Scoped**: created once per scope (e.g., per HTTP request).  
- **Singleton**: created once for the application lifetime.  
A common bug is injecting a Scoped service into a Singleton, which captures the scoped instance and causes it to live forever, leading to stale data or concurrency issues. Fix: use `IServiceScopeFactory` to create a new scope inside the Singleton, or change the registration.

DN5 — Medium:  
`string` is immutable, heap-allocated, and has overhead (header, padding). `ReadOnlySpan<char>` is a stack-only ref struct that can point to any contiguous memory (string, array, unmanaged) without allocation. Use `Span<T>` for performance-critical string processing (e.g., slicing, parsing) to avoid allocations and improve cache efficiency.

DN6 — Medium:  
The .NET GC uses generations (Gen 0, 1, 2) based on object age; short-lived objects die in Gen 0, promoted objects move to Gen 1/2. The Large Object Heap (LOH) holds objects >85KB and is not compacted. `IDisposable` is needed for unmanaged resources (files, handles) because the GC does not track them; implement `Dispose` to release them deterministically.

DN7 — Hard:  
`ConfigureAwait(false)` tells the continuation not to capture the current `SynchronizationContext`, avoiding deadlocks in UI/ASP.NET contexts. Use it in library code to improve performance and avoid context capture. Do **not** use it in UI code where you need to update the UI thread. The default behavior captures the context, which can cause deadlocks if you block on the async method (e.g., `.Result`).

DN8 — Hard:  
.NET 8/9 features:  
- **Primary constructors**: `public class MyService(ILogger<MyService> logger)` — parameters are captured and used directly.  
- **Collection expressions**: `int[] arr = [1, 2, 3];`  
- **FrozenDictionary**: immutable, optimized for reads, created via `ToFrozenDictionary()`.  
Example with DI:  
```csharp
public class MyService(ILogger<MyService> logger) {
    public void DoWork() => logger.LogInformation("Working");
}
// Registered as: builder.Services.AddSingleton<MyService>();
```

DN9 — Hard:  
`ObjectDisposedException` on `DbContext` under high concurrency usually means the `DbContext` is registered as a Singleton or captured in a Singleton. EF Core's `DbContext` is not thread-safe and should be scoped per request. Fix: register as `AddDbContext` (Scoped) and never inject it into a Singleton. The DI scoping ensures a new instance per request, avoiding concurrent use.

DN10 — Medium:  
`record` is a reference type with value equality, immutable by default (init-only properties), and supports `with` expressions. `record struct` is a value type with value equality. Choose `record` for immutable data models (DTOs, events), `class` for mutable entities, and `record struct` for small immutable value types.

DN11 — Easy:  
- `ref`: requires initialized variable, can modify the value.  
- `out`: must be assigned inside the method, used for multiple return values.  
- `in`: readonly reference, prevents modification.  
Use `ref` for large structs to avoid copying, `out` for multiple returns, and `in` for performance when passing large structs read-only.

DN12 — Easy:  
Nullable reference types (`?` annotation, `#nullable enable`) are compile-time features that warn about potential null dereferences; they do not change runtime behavior. Nullable value types (`int?`) are actual types that can be `null` and have `HasValue`/`Value` properties. The former is a static analysis tool, the latter is a runtime feature.

DN13 — Easy:  
LINQ (Language Integrated Query) provides query capabilities. Method syntax (`list.Where(x => x > 5)`) uses extension methods; query syntax (`from x in list where x > 5 select x`) is syntactic sugar. Deferred execution means the query is not executed until enumerated, allowing composition and avoiding unnecessary work.

DN14 — Easy:  
Generic constraints:  
- `where T : class` — reference type.  
- `where T : struct` — value type.  
- `where T : new()` — parameterless constructor.  
- `where T : IComparable<T>` — implements interface.  
Combine multiple constraints with commas, e.g., `where T : class, IComparable<T>, new()`.

DN15 — Easy:  
`abstract class` can have implementation, fields, constructors, and is limited to single inheritance. `interface` is a contract with no state (until C# 8 default interface methods). Default interface methods allow implementation in interfaces, but they still cannot have instance fields. Use abstract classes for shared base logic, interfaces for capabilities.

DN16 — Medium:  
Middleware pipeline in ASP.NET Core: `app.Use()` adds a middleware that can call the next delegate; `app.Map()` branches the pipeline based on path; `app.Run()` is a terminal middleware. Order matters—exception handling middleware should be early to catch exceptions from later middleware. Middleware can short-circuit the pipeline.

DN17 — Medium:  
`Channel<T>` is a modern, thread-safe, async producer-consumer queue with support for bounded capacity and backpressure. `BlockingCollection<T>` is older, synchronous, and blocking. Example of bounded channel:  
```csharp
var channel = Channel.CreateBounded<int>(10);
await channel.Writer.WriteAsync(1);
await foreach (var item in channel.Reader.ReadAllAsync()) { ... }
```

DN18 — Hard:  
Source Generators run at compile time to generate C# code, avoiding reflection overhead. They differ from reflection (runtime) and IL weaving (post-compilation). Incremental generators (`IIncrementalGenerator`) cache and reuse results, improving build performance over `ISourceGenerator`.

DN19 — Hard:  
TPL Dataflow (`System.Threading.Tasks.Dataflow`) provides `ActionBlock`, `TransformBlock`, and `BufferBlock` for building pipeline processing with async support and backpressure. It is more powerful than `System.Threading.Channels` for complex pipelines (e.g., multiple producers/consumers, parallelism), while Channels is simpler for basic producer-consumer.

DN20 — Hard:  
Minimal APIs are a lightweight way to build HTTP APIs without controllers. They use top-level statements, route groups (`MapGroup`), and endpoint filters (`AddEndpointFilter`). Trade-offs: less structure, but more flexibility; testability via `WebApplicationFactory`; OpenAPI support via `AddEndpointsApiExplorer`. Controllers offer more conventions and are better for large, structured APIs.

P1 — Easy:  
A `list` is mutable, a `tuple` is immutable. A `set` is mutable and unhashable, a `frozenset` is immutable and hashable. Use tuples for fixed data, lists for dynamic data, sets for unique items, frozensets for immutable sets.

P2 — Easy:  
The GIL (Global Interpreter Lock) is a mutex in CPython that serializes bytecode execution, limiting multi-threading for CPU-bound tasks. It affects CPU-bound workloads, not I/O-bound. Workarounds: use `multiprocessing` (separate processes), use C extensions, or use `asyncio` for I/O.

P3 — Medium:  
`copy.copy` creates a shallow copy (references shared), `copy.deepcopy` recursively copies all objects. Example:  
```python
a = [[1], [2]]
b = copy.copy(a)
b[0].append(3)  # a[0] also changes
```
Deepcopy avoids this.

P4 — Medium:  
Decorators are functions that wrap another function. Example:  
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.2f}s")
        return result
    return wrapper

@timer
def foo(): ...
```

P5 — Medium:  
Generators use `yield` to produce a sequence lazily, returning an iterator. They differ from returning a list by not storing all values in memory. `yield from` delegates to another generator (subgenerator), simplifying flattening.

P6 — Medium:  
`asyncio.run()` runs a coroutine and manages the event loop. `asyncio.gather()` schedules multiple coroutines concurrently and waits for all. `asyncio.create_task()` schedules a coroutine as a task without blocking. `time.sleep()` blocks the event loop; use `await asyncio.sleep()`.

P7 — Hard:  
Python 3 uses C3 linearization (MRO). For diamond inheritance `class D(B, C)`, MRO is `D -> B -> C -> A -> object`. `D().who()` returns `"C"` because `C` overrides `A`'s method and appears before `A` in MRO.

P8 — Hard:  
A metaclass is a class of a class, controlling class creation (e.g., `type`). `__init_subclass__` is a hook called when a subclass is created, simpler for most use cases. Use metaclasses for complex class customization (e.g., registering classes, modifying attributes), `__init_subclass__` for simple hooks.

P9 — Medium:  
`multiprocessing` uses separate processes, bypasses the GIL, but requires pickling for data transfer. `threading` shares memory but is limited by the GIL. `concurrent.futures` provides a high-level interface for both. Use multiprocessing for CPU-bound tasks, threading for I/O-bound, and concurrent.futures for simplicity.

P10 — Medium:  
`__slots__` prevents the creation of `__dict__`, restricting attributes to those declared. It saves memory and improves attribute access speed. Use it for classes with many instances and fixed attributes.

P11 — Easy:  
A virtual environment is an isolated Python environment with its own packages. `venv` is built-in, `virtualenv` is a third-party tool with more features, `conda` is a package manager that also manages environments and non-Python dependencies.

P12 — Easy:  
List/dict/set comprehensions are concise ways to create collections. They are often more readable than `map()`/`filter()` with lambdas. Prefer comprehensions for clarity, `map`/`filter` for functional style or when chaining.

P13 — Easy:  
`==` checks value equality, `is` checks identity (same object). Object interning caches small integers (-5 to 256) and some strings, so `a is b` may return `True` for those.

P14 — Easy:  
`*args` collects extra positional arguments into a tuple, `**kwargs` collects keyword arguments into a dict. Positional-only parameters are marked with `/`, keyword-only with `*` in the signature.

P15 — Easy:  
Context managers use the `with` statement to manage resources. Implement `__enter__`/`__exit__` or use `@contextmanager` from `contextlib`. Example: a timer context manager.

P16 — Medium:  
Type hints are annotations for static analysis. `typing.Union` (or `|`), `Optional` (Union with None), `Literal` (specific values), `TypeVar` (generic), `Protocol` (structural subtyping). Tools like mypy/pyright use these to check types.

P17 — Medium:  
Dunder methods define behavior. `__repr__` is for debugging, `__str__` for display. `__eq__` defines equality, `__hash__` defines hashability; if you define `__eq__` without `__hash__`, `__hash__` is set to `None`, making the object unhashable. `__getattr__` is called when attribute not found, `__getattribute__` is called for every attribute access.

P18 — Hard:  
Descriptors implement `__get__`, `__set__`, `__delete__`. `property` uses `__get__`/`__set__`, `classmethod` and `staticmethod` are descriptors that bind to the class or ignore the instance.

P19 — Hard:  
The import system uses `sys.path` to find modules, `PYTHONPATH` to add paths, `__init__.py` to mark packages, and namespace packages for implicit packages. Finders locate modules, loaders execute them. Relative imports use `.` and `..`, absolute imports use full package path.

P20 — Medium:  
`dataclasses` is a built-in module for creating data classes with `__init__`, `__repr__`, etc. `attrs` offers more features (validators, converters), `Pydantic` adds validation and serialization. `__post_init__` runs after `__init__`, `field(default_factory=...)` for mutable defaults, `frozen=True` for immutability. Choose Pydantic when you need validation and schema parsing.
