**Networking Answers**

N1 — A Layer 2 switch operates at the Data Link layer (Layer 2) and forwards frames based on MAC addresses. A Layer 3 switch operates at the Network layer (Layer 3) and can perform routing between different IP subnets, forwarding packets based on IP addresses.

N2 — IP: 10.0.5.37/20.
*   The subnet mask for /20 is 255.255.240.0.
*   Network Address: 10.0.5.0
*   Broadcast Address: 10.0.15.255

N3 — The TCP three-way handshake establishes a connection:
1.  **SYN (Synchronize):** Client sends a SYN packet to the server.
2.  **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and replies with SYN-ACK.
3.  **ACK (Acknowledge):** Client receives SYN-ACK and sends a final ACK.
If the final ACK is lost, the client will retransmit the ACK (or the server will time out and retransmit SYN-ACK), leading to connection timeouts on the client side until the retransmission succeeds or the connection is aborted.

N4 — **SNAT (Source NAT):** Translates the private source IP address of a host to a public IP address when traffic leaves a private network. *Example: A laptop (192.168.1.10) accessing the internet uses the router's public IP as its source.*
**DNAT (Destination NAT):** Translates a public IP address/port to a private IP address/port when traffic enters a private network. *Example: A public web server IP (203.0.113.5) directs traffic to an internal web server (10.0.0.5).*

N5 — 3 possible causes:
1.  **Hostname Mismatch:** The certificate was issued for a different domain name than the one being accessed (e.g., certificate for `api.example.com` accessed via `example.com`).
2.  **Expired Certificate:** The certificate has passed its validity date.
3.  **Incorrect Configuration:** The server is presenting the wrong certificate file or the certificate chain is incomplete/broken.

N6 — **VLAN (Virtual LAN):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains within the same physical switch infrastructure, using 802.1Q tagging.
**VxLAN (Virtual Extensible LAN):** An overlay networking technology that encapsulates Layer 2 Ethernet frames within Layer 3 UDP packets.
**Choice:** VxLAN is chosen over VLAN when the network needs to scale beyond the 4094 VLAN limit, or when Layer 2 adjacency needs to be stretched across a large, multi-subnet, Layer 3 infrastructure (data center fabric).

N7 — **Why:** The host is likely using the default routing table, which directs all traffic destined for 192.168.1.0/24 (the eth1 subnet) out through the default gateway (10.0.0.1) on eth0, because the routing table entry for 192.168.1.0/24 is missing or less specific than the default route.
**Fix (Policy-Based Routing - PBR):** Use `ip rule` and `ip route` to create a specific routing policy. You would add a rule that checks the source IP address (e.g., `ip rule add from 192.168.1.5 table 10`) and then define a route in a custom routing table (table 10) that directs traffic for 192.168.1.0/24 out via eth1's gateway, bypassing the default route.

N8 — BGP path selection is a complex algorithm used by routers to choose the best path to a destination prefix from multiple available routes. The attributes are evaluated in a strict, ordered sequence.
**5 Attributes (in preference order):**
1.  Weight (Cisco proprietary, highest preference)
2.  Local Preference (Highest is preferred)
3.  Locally Originated (Prefer routes originated locally)
4.  AS Path Length (Shortest path is preferred)
5.  Origin Type (IGP > EGP > Incomplete)

N9 — **MTU Implication:** When running VxLAN over IPsec, the original Ethernet frame (including the VxLAN header) is encapsulated within an IPsec packet, which adds headers (ESP/AH, outer IP header). This consumes significant overhead.
**Math:**
*   Physical MTU: 1500 bytes
*   VxLAN Header Overhead: $\approx 50$ bytes (VNI, UDP, etc.)
*   IPsec Overhead (e.g., ESP + Auth): $\approx 50-70$ bytes
*   Total Overhead $\approx 100$ bytes
*   Maximum Inner Payload = Physical MTU - Total Overhead
*   Maximum Inner Payload $\approx 1500 - 100 = 1400$ bytes.

N10 — **ARP (Address Resolution Protocol):** Maps a known Layer 3 IP address to its corresponding Layer 2 MAC address on a local network segment.
**Gratuitous ARP:** A host sends an ARP reply to its own IP address. It solves the problem of stale ARP caches. It is used to immediately inform other devices on the local network of a host's new MAC address (e.g., after a host changes its NIC or IP address).

N11 — **Public IP:** Globally unique address routable across the public internet.
**Private IP:** Non-globally unique addresses reserved for use within private networks (LANs) and are not routable on the public internet.
**RFC 1918 Ranges:**
1.  10.0.0.0/8
2.  172.16.0.0/12
3.  192.168.0.0/16

N12 — **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses.
*   **A Record:** Maps a domain name to an IPv4 address (e.g., `example.com` $\rightarrow$ 192.0.2.1).
*   **CNAME Record:** Creates an alias, mapping one domain name to another domain name (e.g., `blog.example.com` $\rightarrow$ `example.com`).
*   **AAAA Record:** Maps a domain name to an IPv6 address.

N13 — **DHCP (Dynamic Host Configuration Protocol):** A network management protocol used to automatically assign IP addresses and other network configuration parameters (subnet mask, gateway, DNS servers) to devices on a network.
**DORA Process:**
1.  **Discover:** Client broadcasts a DHCP Discover message.
2.  **Offer:** Server replies with a DHCP Offer, proposing an IP address.
3.  **Request:** Client broadcasts a DHCP Request, formally accepting the offered IP address.
4.  **Acknowledge:** Server replies with a DHCP ACK, finalizing the lease and configuration.

N14 — **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming data to every connected port.
**Switch:** Operates at Layer 2 (Data Link). It learns MAC addresses and forwards frames only to the intended destination port.
**Router:** Operates at Layer 3 (Network). It connects different networks and forwards packets based on IP addresses.

N15 — **Half-Duplex:** Allows data transmission in both directions, but only one direction at a time (e.g., a walkie-talkie).
**Full-Duplex:** Allows simultaneous data transmission and reception over the same link.
Modern Ethernet links use **Full-Duplex** communication.

N16 — **TTL (Time To Live):** A field in the IP header that limits the lifespan or hop count of a packet. Each router that forwards the packet decrements the TTL by one. If the TTL reaches zero, the router discards the packet and typically sends an ICMP Time Exceeded message.
**Traceroute Exploitation:** Traceroute sends a sequence of packets (usually UDP or ICMP) with incrementally increasing TTL values (starting at 1). When the packet hits the first router, the TTL expires, and the router sends back an ICMP Time Exceeded message, revealing the router's IP address. This process repeats until the destination is reached.

N17 — **NAT Gateway:** A device (usually a router or firewall) that performs Network Address Translation, allowing multiple private IP addresses to share a single public IP address when accessing the internet.
*   **Static NAT:** A one-to-one, permanent mapping between a specific private IP and a specific public IP. (e.g., 10.0.0.5 $\leftrightarrow$ 203.0.113.5).
*   **Dynamic NAT:** Maps private IPs to a pool of available public IPs on a first-come, first-served basis.
*   **PAT (Port Address Translation) / NAT Overload:** Maps multiple private IPs to a single public IP by tracking unique source port numbers for each connection. This is the most common form of NAT.

N18 — **ECMP (Equal-Cost Multi-Path):** A routing technique that allows a router to install multiple paths to the same destination prefix if those paths have the same routing metric (cost). Traffic is distributed across these equal-cost links, increasing bandwidth utilization and redundancy.
**Hashing Strategies:** Common strategies include hashing based on the 5-tuple (Source IP, Destination IP, Source Port, Destination Port, Protocol).
**Asymmetric Flow Problem:** If stateful firewalls are involved, asymmetric routing (where traffic enters one path but returns via another) can cause stateful inspection failures. The firewall expects the return traffic to match the state it recorded for the initial outbound flow, which it won't if the return path is different.

N19 — **Problem:** The TCP window size (64KB) is too small relative to the Bandwidth-Delay Product (BDP = Bandwidth $\times$ Round Trip Time). The BDP (10MB) indicates that a large amount of data could be "in flight" during the round trip, but the TCP window limits how much data can be sent before an acknowledgment is required, causing the sender to stall and resulting in high latency despite no packet loss.
**Solution (Window Scaling):** RFC 1323 allows the TCP window size to be negotiated beyond the standard 16-bit limit (65,535 bytes). By using a scaling factor, the effective window size can be increased to match or exceed the BDP, allowing the sender to keep the pipe full and maximizing throughput.

N20 — **802.1Q Trunk Ports:** A mechanism used on switches to allow traffic from multiple VLANs to traverse a single physical link (trunk). The switch inserts a 4-byte tag (the 802.1Q header) into the Ethernet frame, identifying which VLAN the frame belongs to.
**Linux Configuration (Sub-interfaces):** The physical NIC (e.g., `eth0`) is configured as a trunk, and logical sub-interfaces are created for each VLAN:
`eth0.10` (VLAN 10), `eth0.20` (VLAN 20), `eth0.30` (VLAN 30). Each sub-interface is assigned an IP address corresponding to its respective VLAN subnet.
**Frame Format:** The frame structure is standard Ethernet, but it includes the 802.1Q tag immediately after the source MAC address, containing the VLAN ID (VID) for that specific frame.

**Linux Answers**

L1 — **Hard Link:** A directory entry that points directly to the same inode (the data structure containing file metadata) as the original file. Deleting the original name does not delete the data until the last hard link is removed.
**Symbolic Link (Symlink):** A special file that contains a text path pointing to another file or directory. It is a pointer, not a direct reference to the inode.

L2 — `find /var/log -type f -size +100M`

L3 — State D (Uninterruptible Sleep) means the process is waiting for an I/O operation (like disk or network) to complete. It is blocked waiting for a kernel resource. You **cannot** kill it with `kill -9` because the kernel will not terminate it until the underlying I/O operation finishes, as this could lead to data corruption.

L4 — **cgroups v1:** Used a hierarchical, resource-specific model (e.g., CPU controller, Memory controller). It was simpler but less unified.
**cgroups v2:** Implements a unified hierarchy and a unified control plane. It provides a more coherent view of resource management across all controllers.
**Systemd Preference:** Systemd prefers cgroups v2 because its unified hierarchy simplifies resource management, making it easier for systemd to manage services and enforce resource limits consistently across the entire system.

L5 — **iptables:** The older, traditional Linux firewall framework, operating primarily on Netfilter hooks.
**nftables:** The modern replacement for iptables. It is a more flexible, unified, and powerful framework that can handle various packet types and rulesets more efficiently.
**Kernel Handling:** The kernel maintains both systems for backward compatibility. When both are installed, the kernel routes traffic through the Netfilter framework, which processes rules defined by both iptables and nftables, though using nftables is the recommended modern approach.

L6 — The most likely cause is that the filesystem contains a large number of **small files**. The `df -h` command reports disk space usage based on inode count and block allocation, while `du -sh` calculates the total size of the *contents* of the directories. A high inode count can fill the filesystem capacity even if the total data size is small.

L7 — **UEFI Firmware:** Initializes hardware and loads the bootloader (e.g., GRUB2).
**Bootloader (GRUB2):** Reads the kernel image and the initial RAM disk (`initramfs`) from the storage device and loads them into memory.
**Kernel:** The core operating system component loads, initializes drivers, and mounts the root filesystem.
**Initramfs:** A temporary, minimal root filesystem loaded into memory. It contains necessary drivers (like storage drivers) to allow the kernel to find and mount the *real* root filesystem.
**Root Filesystem:** The kernel mounts the actual root partition (e.g., `/`).
**Systemd:** The `init` process (PID 1) starts systemd, which takes over system initialization, managing services, logging, and reaching the final operational target (e.g., `multi-user.target`).

L8 — **Why Available is Low:** The `available` memory metric is calculated as `free + buffers + cache` minus the memory currently used by processes that are *not* actively using the cache. Even if 15GB is `buff/cache`, if the kernel deems that cache is actively needed for I/O operations or if the system is under heavy memory pressure, it might not be counted as immediately "available" for new processes.
**Kernel Tunables:** `vm.swappiness` (controls how aggressively the kernel swaps out anonymous memory) and `vm.vfs_cache_pressure` (controls how aggressively the kernel reclaims memory used for directory and inode caches).

L9 — **`ip netns`:** This command is used to manage network namespaces. A network namespace is an isolated view of the system resources (network interfaces, routing tables, process IDs, etc.).
**Container Runtimes:** Container runtimes (like Docker or Kubernetes) use network namespaces to give each container its own isolated network stack. This means Container A cannot see the network interfaces or routing tables of Container B or the host system unless explicitly configured to do so.

L10 — **SIGTERM (Signal 15):** A polite request for a process to terminate. It allows the process to catch the signal, clean up resources, and exit gracefully.
**SIGKILL (Signal 9):** A forceful, immediate termination signal. The process cannot catch, ignore, or block this signal; the kernel terminates it instantly.
**SIGQUIT (Signal 3):** Requests the process to terminate and usually generates a core dump file for debugging.
**Catchable:** SIGTERM, SIGQUIT, and SIGINT (Ctrl+C) can all be caught by the process.

L11 — **stdin (Standard Input):** Where a program reads input from (default: keyboard).
**stdout (Standard Output):** Where a program writes its normal, expected output to (default: terminal screen).
**stderr (Standard Error):** Where a program writes error messages and diagnostic output to (default: terminal screen).
**Redirection:** `command 2> error.log` redirects stderr to the file. To display stdout on the terminal while redirecting stderr: `command > /dev/tty 2> error.log` (or more simply, `command 2> error.log &> /dev/tty` depending on shell).

L12 — `chmod 755 filename` grants permissions as follows:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = Full control.
*   **5 (Group):** Read (4) + Execute (1) = Can view and run.
*   **5 (Others):** Read (4) + Execute (1) = Can view and run.

L13 — **Root User:** Has absolute, unrestricted privileges over the entire operating system. It can read, write, and modify any file, change system configurations, and manage all processes.
**Sudo Privileges:** A user with `sudo` can execute specific commands as the root user, but this access is restricted by the `/etc/sudoers` file. They cannot arbitrarily change system configurations or access files outside their defined permissions.

L14 — **Package Manager:** A system utility responsible for installing, upgrading, configuring, and removing software packages in a standardized way, managing dependencies automatically.
**Debian/Ubuntu:** APT (Advanced Package Tool)
**RHEL/Fedora:** DNF (Dandified YUM)

L15 — **`/etc/fstab`:** A configuration file that defines how disk partitions, network shares, and other filesystems should be mounted automatically at boot time.
**Misconfiguration:** If an entry is misconfigured (e.g., wrong UUID, incorrect filesystem type, or missing mount point), the system may fail to boot, hang during the mounting phase, or fail to mount the specified filesystem, leading to an unbootable or partially functional system.

L16 — **LVM (Logical Volume Manager):** A storage management abstraction layer that allows administrators to create, manage, and resize logical volumes dynamically, independent of the underlying physical disk layout.
*   **Physical Volumes (PV):** The actual physical storage devices (hard drives, partitions) that LVM uses.
*   **Volume Groups (VG):** A pool of storage capacity created by combining one or more PVs.
*   **Logical Volumes (LV):** The flexible, usable partitions carved out of the VG, which are then formatted and mounted.
**Extend LV:** Use `lvextend -L +[size] /dev/VG_name/LV_name` to increase the size, followed by `resize2fs /dev/VG_name/LV_name` (or equivalent) to extend the filesystem to use the new space.

L17 — **I/O Scheduler:** Determines the order in which read/write requests are serviced by the block device driver, optimizing disk throughput and latency.
*   **mq-deadline:** Prioritizes requests based on deadlines, balancing throughput and latency. Good for mixed workloads.
*   **bfq (Budget Fair Queueing):** Designed for desktop/interactive workloads, ensuring fair bandwidth allocation to different processes, minimizing latency spikes.
*   **none:** Passes I/O requests directly to the hardware without reordering, best for high-performance storage (like NVMe) where the hardware scheduler is superior.
**Change Scheduler:** Use `echo bfq > /sys/block/sdX/queue/scheduler` (where `sdX` is the device name).

L18 — **Load Average:** Measures the average number of processes in the system that are either running or waiting to run (in uninterruptible sleep, D state). It is a measure of system *demand* for CPU time, not just CPU utilization.
**I/O Wait Inflation:** When processes are blocked waiting for slow disk I/O, they enter the D state. The load average counts these waiting processes, artificially inflating the load average even if the CPU itself is idle.
**Diagnosis:**
*   **CPU Bottleneck:** High `us` (user) or `sy` (system) CPU usage in `top`/`htop`.
*   **Disk Bottleneck:** High `%wa` (I/O wait) in `top`/`htop`, confirmed by slow response times in `iostat`.
*   **Network Bottleneck:** High utilization on network interfaces shown by `iftop` or `nload`.

L19 — **SELinux (Security-Enhanced Linux):** Enforces Mandatory Access Control (MAC). Instead of relying solely on DAC (Discretionary Access Control, i.e., standard Linux permissions), SELinux assigns security contexts (labels) to every subject (process) and object (file/port). Access is only granted if the policy explicitly permits the transition between the subject's context and the object's context.
**Modes:**
*   **Enforcing:** SELinux actively denies access based on policy violations.
*   **Permissive:** SELinux logs all policy violations but does *not* deny access, allowing administrators to see what *would* have been blocked.
*   **Disabled:** SELinux is completely inactive.
**Troubleshooting:** Check the audit logs (`/var/log/audit/audit.log`). If a daemon fails to bind a port, check the logs for "denied" messages related to the process context and the port context. You may need to use `semanage port` to explicitly allow the daemon to use that non-standard port.

L20 — **Page Faults:** Occur when a program tries to access a virtual memory address whose corresponding physical memory page is not currently mapped or present in RAM.
**Minor Page Fault:** The required page is not in RAM, but it *is* present on disk (e.g., in the swap file or file cache). The kernel resolves this by loading the page into RAM, but no disk I/O is required to find the page metadata.
**Major Page Fault:** The required page is not in RAM and is not readily available in the cache; the kernel must perform synchronous disk I/O (paging in from swap or the original file) to retrieve the page. This is slow.
**THP (Transparent Huge Pages):** A kernel feature that attempts to automatically coalesce small 4KB memory pages into large 2MB pages to reduce TLB misses and improve performance for large memory allocations.
**Disabling THP:** It should be disabled if an application exhibits unpredictable latency or performance degradation, as the background compaction process required by THP can introduce significant, unpredictable pauses (latency spikes).
