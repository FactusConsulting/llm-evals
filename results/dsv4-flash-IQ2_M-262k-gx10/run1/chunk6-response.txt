# JavaScript / TypeScript

**JS1 — var, let, const & Hoisting**

- **var**: Function-scoped. Can be redeclared and reassigned. Hoisted and initialized to `undefined` at the top of its scope.
- **let**: Block-scoped. Cannot be redeclared, but can be reassigned. Hoisted but in a **temporal dead zone (TDZ)** — accessing before declaration throws `ReferenceError`.
- **const**: Block-scoped. Cannot be redeclared or reassigned (though object properties can be mutated). Must be initialized at declaration. Also hoisted with TDZ.
- **Hoisting**: The JS engine moves all declarations to the top of their scope during compilation. `var` initializes to `undefined`; `let`/`const` remain uninitialized (TDZ) until the declaration line executes.

**JS2 — Event Loop**

- **Call stack**: LIFO structure for synchronous function execution. When empty, the event loop picks up tasks.
- **Microtask queue**: Contains promise callbacks (`.then`, `catch`, `finally`), `queueMicrotask`, `MutationObserver`. Processed **completely** before any macrotask, after each call-stack drain.
- **Macrotask queue**: Contains `setTimeout`, `setInterval`, I/O events, UI rendering. Only **one** macrotask is processed per event-loop iteration.
- **Order**: Execute sync code → drain all microtasks → take one macrotask → repeat. This guarantees microtasks run before the next macrotask, enabling consistent promise semantics.

**JS3 — Closures**

A closure is a function that retains access to its lexical scope even when executed outside that scope.

```js
function makeCounter() {
  let count = 0;
  return () => ++count;
}
const c = makeCounter();
c(); // 1
```

**Classic for-loop bug**:
```js
for (var i = 0; i < 5; i++) {
  setTimeout(() => console.log(i)); // logs 5,5,5,5,5
}
```
Because `var` is function-scoped, all callbacks share the same `i` after the loop ends.

**Fixes**:
1. Use `let` (block-scoped, creates new binding per iteration).
2. IIFE: `for (var i = 0; i < 5; i++) { (function(j){ setTimeout(() => console.log(j)); })(i); }`
3. `setTimeout(console.log, 0, i)` (pass as argument).

**JS4 — Promise, async/await, Error Handling**

- **Promise**: An object representing eventual completion/failure. Has `.then`, `.catch`, `.finally`.
- **async/await**: Syntactic sugar over promises. `async` functions return a promise; `await` pauses execution until the promise settles.
- **Error handling**:
  - Promises: `.catch()` or second argument to `.then`.
  - async/await: `try/catch` blocks.
- **Promise.allSettled**: Waits for all promises to settle (fulfilled or rejected). Returns array of `{status: 'fulfilled', value}` or `{status: 'rejected', reason}`. Never throws.
- **Promise.all**: Fails fast — rejects immediately on the first rejection. Returns array of values if all fulfill.

**JS5 — TypeScript interface vs type**

- **interface**: Can be extended (`extends`), merged (declaration merging), and describes object shapes. Best for object-oriented patterns and public APIs.
- **type**: More flexible — supports unions, intersections, mapped types, tuples, computed properties. Cannot be merged.
- **When to use**: Use `interface` for object shapes that may be extended or need declaration merging; use `type` for unions, intersections, or complex computed types.
- **Discriminated unions**: A union of types that share a common discriminant property (e.g., `type: 'circle' | 'square'`). TypeScript narrows the type based on the discriminant:
```ts
type Shape = { kind: 'circle'; radius: number } | { kind: 'square'; side: number };
function area(s: Shape) {
  if (s.kind === 'circle') return Math.PI * s.radius ** 2;
}
```

**JS6 — Prototypal Inheritance**

- Every object has a `[[Prototype]]` (accessed via `Object.getPrototypeOf` or `__proto__`). Property lookup walks the prototype chain.
- **Object.create(proto, props)**: Creates a new object with the given prototype. Example:
```js
const animal = { speak() { return '...'; } };
const dog = Object.create(animal);
dog.speak(); // inherited
```
- **ES6 classes**: Syntactic sugar over prototypes. `class Foo {}` creates a constructor function; `extends` sets up the prototype chain (`Foo.prototype` inherits from `Bar.prototype`). Methods are on `prototype`, not the instance.

**JS7 — The `this` Keyword**

**Binding rules (priority order)**:
1. **New binding**: `new` creates a new object and binds `this` to it.
2. **Explicit binding**: `call`, `apply`, `bind` override `this`.
3. **Implicit binding**: Method call on an object (`obj.method()` → `this` = `obj`).
4. **Default binding**: Global object (or `undefined` in strict mode).

**bind()**: Returns a **new function** with `this` permanently bound. You **cannot re-bind** a bound function — calling `bind` again on a bound function returns a new function with the original `this` (the first bind wins).

**JS8 — WeakRef and FinalizationRegistry**

- **WeakRef**: Holds a weak reference to an object — does not prevent garbage collection. Access via `.deref()` (returns object or `undefined` if collected).
- **FinalizationRegistry**: Registers a callback that runs when a target object is garbage collected.
- **Use cases**: Caching large objects, tracking resource cleanup, memory-sensitive memoization.
- **Why WeakMap keys must be objects**: WeakMap holds keys weakly — if keys were primitives (strings/numbers), they have no identity and cannot be tracked for GC. Objects have identity and can be collected when no other references exist.

**JS9 — V8 Optimization**

- **Hidden classes**: V8 creates internal "hidden classes" (maps) to describe object shapes. Adding properties in different orders creates different hidden classes, causing deoptimization.
- **Inline caching (IC)**: V8 caches property access based on the hidden class. Monomorphic access (same shape) is fast; polymorphic access (multiple shapes) degrades to slow path.
- **Deoptimization**: When assumptions break (e.g., adding a new property to an object, changing a variable's type), V8 bails out to interpreted code.
- **Patterns causing deoptimization**:
  - Adding properties dynamically after object creation.
  - Changing the type of a variable (e.g., number → string).
  - Creating objects with different property order.
  - Using `delete` on properties.
  - Mixing types in arrays (e.g., `[1, 'a', 2]`).

**JS10 — Tree-shaking**

- **Tree-shaking**: Removing unused exports/modules during bundling (dead-code elimination).
- **ES modules**: Static `import`/`export` declarations allow bundlers to statically analyze the dependency graph and drop unused code.
- **CommonJS**: `require` is dynamic (can be called conditionally, computed paths), making it impossible to statically determine what's used. Bundlers often cannot safely tree-shake CommonJS.
- **Why CommonJS can't be effectively tree-shaken**: `module.exports` is mutable, and `require` can be called at runtime with arbitrary expressions, so the bundler must assume everything is used.

**JS11 — null vs undefined, == vs ===, ?? and ?.**

- **null**: Explicitly assigned "no value" (type `object`).
- **undefined**: Variable declared but not assigned (type `undefined`).
- `null == undefined` → `true` (loose equality treats them as equal).
- `null === undefined` → `false` (different types).
- **Nullish coalescing (`??`)**: Returns right side if left is `null` or `undefined`; otherwise left. Unlike `||`, it doesn't treat `0`, `''`, `false` as falsy.
- **Optional chaining (`?.`)**: Short-circuits if the object before `?.` is `null`/`undefined`, returning `undefined` instead of throwing.

**JS12 — map, filter, reduce, flatMap**

- **map**: Transforms each element → returns new array of same length.
- **filter**: Returns elements that pass a predicate → may shorten array.
- **reduce**: Accumulates values into a single result. With an initial value, the accumulator starts at that value and the callback runs for every element; without it, the first element is the accumulator and iteration starts at index 1.
- **flatMap**: Maps each element then flattens one level. Useful for one-to-many transformations (e.g., splitting strings, nested arrays).

**JS13 — Template Literals & Tagged Templates**

- Template literals use backticks and `${}` for interpolation.
- **Tagged templates**: A function receives the string parts array and the interpolated values:
```js
function html(strings, ...values) {
  const escape = s => s.replace(/&/g, '&amp;').replace(/</g, '&lt;');
  return strings.reduce((acc, str, i) => acc + str + (values[i] ? escape(values[i]) : ''), '');
}
const user = '<script>';
html`<div>${user}</div>`; // escapes the user input
```

**JS14 — Destructuring**

- **Object**: `const { a, b } = obj;`
- **Array**: `const [x, y] = arr;`
- **Default values**: `const { a = 1 } = obj;` or `const [x = 1] = arr;`
- **Renaming**: `const { a: newName } = obj;`
- **Rest**: `const { a, ...rest } = obj;` collects remaining properties; `const [first, ...rest] = arr;` collects remaining elements.

**JS15 — for...in vs for...of**

- **for...in**: Iterates over **enumerable string keys** (including inherited properties). Used for objects.
- **for...of**: Iterates over **iterable values** (arrays, strings, maps, sets). Used for collections.
- **Avoid for...in on arrays**: It iterates indices as strings (`"0"`, `"1"`), includes inherited enumerable properties, and can break if array methods are added to `Array.prototype`.

**JS16 — TypeScript Generics**

- **Generic constraints**: `T extends U` restricts `T` to types assignable to `U`:
```ts
function logLength<T extends { length: number }>(arg: T): T { console.log(arg.length); return arg; }
```
- **Conditional types**: `T extends U ? X : Y`:
```ts
type IsArray<T> = T extends any[] ? true : false;
```
- **infer keyword**: Extracts a type from a conditional:
```ts
type ElementType<T> = T extends (infer E)[] ? E : never;
type A = ElementType<string[]>; // string
```

**JS17 — Module System**

- **CommonJS**: `require`/`module.exports`. Synchronous, dynamic, Node.js default. Used in `.cjs` files or when `"type": "commonjs"`.
- **ES Modules**: `import`/`export`. Asynchronous, static, browser-native. Used in `.mjs` files or when `"type": "module"`.
- **Node.js handling**: Node supports both. It detects module type via file extension or `package.json` `"type"` field. ESM can import CJS (default export is `module.exports`), but CJS cannot `require` ESM synchronously.
- **`"type": "module"`**: Makes `.js` files in the package use ESM syntax by default.

**JS18 — TypeScript Structural Type System**

- **Structural typing**: Types are compatible if their shapes match — no nominal identity needed.
- **Excess property checks**: When assigning an **object literal** to a typed variable, TS errors on properties not in the target type. These checks apply only to fresh object literals, not variables.
- **extends vs satisfies**:
  - `extends` (in generic constraints or `interface extends`) checks assignability.
  - `satisfies` (TS 4.9+) checks that a value matches a type **without** changing the inferred type — preserves literal types.
- **Variance (TS 4.7+)**: `in` marks a type parameter as contravariant (used in input positions), `out` marks it as covariant (output positions). This improves type safety for function parameters and return types.

**JS19 — Proxy and Reflect**

- **Proxy**: Wraps an object to intercept operations via handler traps (`get`, `set`, `apply`, `has`, `deleteProperty`, etc.).
- **Reflect**: Provides default behavior for each trap (e.g., `Reflect.get`, `Reflect.set`).
- **Example — validation**:
```js
const user = { name: 'Alice', age: 30 };
const proxy = new Proxy(user, {
  set(target, prop, value) {
    if (prop === 'age' && (typeof value !== 'number' || value < 0)) {
      throw new TypeError('Invalid age');
    }
    return Reflect.set(target, prop, value);
  }
});
proxy.age = 25; // OK
proxy.age = -5; // throws
```

**JS20 — SharedArrayBuffer and Atomics**

- **SharedArrayBuffer**: A buffer that can be shared between Web Workers (and the main thread) via `postMessage`. Allows concurrent memory access.
- **Atomics**: Provides atomic operations (`Atomics.add`, `Atomics.load`, `Atomics.store`, `Atomics.exchange`, `Atomics.compareExchange`) that are guaranteed to be atomic and ordered.
- **Communication**: Workers receive a `SharedArrayBuffer` via `postMessage` and read/write it directly — no copying.
- **Ordering guarantees**: Atomics operations are sequentially consistent — all workers observe the same order of atomic operations.
- **Atomics.wait/notify**: Synchronization primitives. `Atomics.wait` blocks a thread until `Atomics.notify` is called on the same location. Used for producer-consumer patterns.

# Bash

**B1 — $@ vs $***

- `$@`: Each positional parameter is a **separate word** (preserves spaces within arguments).
- `$*`: All positional parameters as **one word** (joined by the first character of `IFS`, usually space).
- `"$@"`: Each parameter quoted separately — preserves argument boundaries.
- `"$*"`: All parameters as a **single string** — loses boundaries.
- **Rule**: Always use `"$@"` to preserve argument integrity.

**B2 — set -euo pipefail**

- `-e`: Exit immediately if any command returns non-zero (unless in a condition, loop, or with `||`).
- `-u`: Treat unset variables as an error (exit with `bash: var: unbound variable`).
- `-o pipefail`: A pipeline fails if **any** command in it fails (not just the last).
- Together: fail fast on errors, catch unset variables, and ensure pipelines propagate failures.

**B3 — $(command) vs `command`; $((expression)) vs expr**

- `$(command)`: Modern command substitution. Supports nesting (`$(echo $(date))`), easier to read, handles backslashes correctly.
- `` `command` ``: Legacy. Nesting requires escaping (`\`), backslash handling is inconsistent.
- `$((expression))`: Arithmetic expansion — integer math, fast, built-in.
- `expr`: External command, slower, requires escaping (`expr 1 + 1`), legacy.

**B4 — Process Substitution**

- `<(command)`: Treats the command's output as a **file descriptor** (e.g., `/dev/fd/63`). Useful when a command expects a file argument.
- **Example with diff**:
```bash
diff <(sort file1.txt) <(sort file2.txt)
```
- Also useful for `while read` loops without subshell issues: `while read line; do ...; done < <(command)`.

**B5 — Safe File Iteration**

- **Safe pattern**:
```bash
find . -type f -print0 | while IFS= read -r -d '' file; do
  echo "Processing: $file"
done
```
- **Why `for f in $(ls)` is dangerous**: `$(ls)` splits on whitespace (spaces, tabs, newlines). Filenames with spaces or special characters (globs, `*`, `?`) break the loop or cause unintended expansion.

**B6 — Here Document vs Here String**

- **Here document** (`<<EOF`): Multi-line input redirected to a command. Example:
```bash
cat <<EOF
Hello
World
EOF
```
- **Here string** (`<<<`): Single string redirected to stdin. Example: `bc <<< "1+2"`.
- `<<-EOF`: Strips **leading tabs** from the here-document body (allows indented content for readability).

**B7 — Redirection Order**

```bash
cmd > file 2>&1   # stdout → file, then stderr → same file (both to file)
cmd 2>&1 > file   # stderr → current stdout (terminal), then stdout → file (stderr NOT in file)
cmd &> file       # both stdout and stderr → file (bash-specific shorthand)
```
- **Why different**: Redirections are processed **left to right**. In the second form, `2>&1` duplicates stderr to the *current* stdout (terminal), then `> file` changes stdout to the file — stderr still points to the terminal.

**B8 — Safe Lock File**

```bash
lock_dir="/tmp/mylock.$$"
cleanup() {
  rm -rf "$lock_dir"
  exit
}
trap cleanup EXIT TERM INT

# mkdir is atomic — only one process can create it
while ! mkdir "$lock_dir" 2>/dev/null; do
  sleep 0.1
done
echo "Lock acquired"
# ... critical section ...
```
- **Why mkdir over file creation**: `mkdir` is **atomic** — only one process can succeed. `touch`/file creation has a race window (check-then-create is not atomic). `mkdir` also works on NFS and is portable.

**B9 — Quotes**

- **Single quotes** (`'...'`): Literal — no expansion, no globbing.
- **Double quotes** (`"..."`): Expansion (variables, `$()`), but **no word splitting or globbing**.
- **No quotes**: Expansion + word splitting + globbing.
- **Example**:
```bash
var="hello world"
echo $var        # splits into "hello" and "world"
echo "$var"      # "hello world"
echo '$var'      # "$var" (literal)
```

**B10 — File Checks & test**

- `-e file`: exists; `-d file`: directory; `-r file`: readable.
- `[ ]` (POSIX test): External command (or builtin), supports basic tests, word splitting applies.
- `[[ ]]` (bash extended): Builtin, supports `&&`, `||`, regex matching (`=~`), glob matching, no word splitting. **Prefer `[[ ]]` in bash scripts**.

**B11 — Special Variables**

- `$?`: Exit status of the last command.
- `$$`: PID of the current shell.
- `$!`: PID of the last background job (`cmd &`).
- `$#`: Number of positional parameters.
- **Use cases**: `$?` for error checking; `$$` for temp file names; `$!` to wait/kill a background job; `$#` to validate argument count.

**B12 — Functions**

- **Definition**: `foo() { ...; }` (POSIX) or `function foo { ...; }` (bash-specific). Both work in bash; `foo()` is more portable.
- **Return values**: `return` sets exit status (0–255). To return data, use `echo` (captured via `$(foo)`).
- **Example**:
```bash
add() { echo $(($1 + $2)); }
sum=$(add 3 4)  # sum=7
```

**B13 — PATH & Command Resolution**

- **PATH**: Colon-separated list of directories where bash looks for executables.
- **Resolution**: Bash checks: aliases → functions → builtins → `$PATH` (external commands).
- **Builtin**: Shell-internal (e.g., `cd`, `echo`, `read`). **External**: Separate executable (e.g., `/bin/ls`).
- **Check**: `type -a cmd` shows all matches; `which cmd` shows external path.

**B14 — trap**

- **Syntax**: `trap 'commands' SIGNAL`.
- **Common signals**: `EXIT` (any exit), `ERR` (command failure), `INT` (Ctrl+C), `TERM` (kill).
- **Example**:
```bash
cleanup() { rm -f /tmp/tempfile; }
trap cleanup EXIT
trap 'echo "Interrupted"; cleanup; exit 1' INT TERM
```
- **Multiple signals**: Traps run in the order signals are received. If `INT` and `TERM` arrive simultaneously, both handlers run (in signal delivery order). `EXIT` trap always runs last.

**B15 — xargs vs Command Substitution**

- **xargs**: Reads stdin and executes a command with arguments. Handles large inputs efficiently, supports parallelism (`-P`).
- **Command substitution**: `$(cmd)` captures output as a string — subject to word splitting, unsafe for filenames.
- **Safe with spaces/newlines**:
```bash
find . -type f -print0 | xargs -0 -I{} echo "Found: {}"
```
- **xargs -P**: Runs multiple processes in parallel. Example: `find . -name "*.log" -print0 | xargs -0 -P 4 gzip`.

**B16 — Bash Arrays**

- **Indexed arrays**:
```bash
arr=(a b c)          # declare
arr+=(d)             # append
echo "${arr[0]}"     # access
echo "${#arr[@]}"    # length
for i in "${arr[@]}"; do echo "$i"; done  # iterate
```
- **Associative arrays** (bash 4+):
```bash
declare -A assoc
assoc[key]=value
echo "${assoc[key]}"
echo "${#assoc[@]}"  # number of keys
for key in "${!assoc[@]}"; do echo "$key: ${assoc[$key]}"; done
```
- **Differences**: Indexed arrays use numeric indices; associative use string keys. Syntax differs (`declare -A` required).

**B17 — Subshell vs Group Command**

- **Subshell** (`(...)`): Runs in a child shell. Variable changes **do not propagate** to the parent. Exit code is the last command's.
- **Group** (`{ ...; }`): Runs in the current shell. Variable changes **persist**. Exit code is the last command's.
- **Pipes create subshells**: `cmd | while read ...; do ...; done` — the `while` runs in a subshell, so variable changes are lost. Fix: use process substitution (`while ...; done < <(cmd)`) or `bash` with `lastpipe` (`shopt -s lastpipe`).

**B18 — Signals & Job Control**

- **SIGINT** (2): Interrupt (Ctrl+C) — can be caught.
- **SIGTERM** (15): Termination request — can be caught, graceful shutdown.
- **SIGHUP** (1): Hangup (terminal closed) — can be caught.
- **SIGKILL** (9): Kill — **cannot** be caught or ignored.
- **Graceful shutdown with background processes**:
```bash
cleanup() {
  echo "Shutting down..."
  kill $bg_pid 2>/dev/null
  wait $bg_pid 2>/dev/null
  exit 0
}
trap cleanup TERM INT
bg_pid=$(some_long_process & echo $!)
while true; do sleep 1; done
```

**B19 — Parallel Log Processing**

```bash
process_file() {
  local file="$1"
  # ... process and output to stdout ...
  echo "Processed: $file"
}
export -f process_file

split -n 4 -d logfile part_   # split into 4 parts
find . -name "part_*" -print0 | xargs -0 -P 4 -I{} bash -c 'process_file "$1"' _ {}

# Merge results
cat part_*.out > merged.out
```
- **Performance trade-offs**: Parallelism improves CPU-bound work but adds overhead (process creation, I/O contention). Too many processes can cause thrashing.
- **Error propagation**: Capture exit codes per job (`xargs` returns non-zero if any job fails). Use `-P` with `--max-args` and check `$?` per batch, or write per-file status files.

**B20 — exec & Coprocesses**

- **exec**: Replaces the current shell with a command (no return). Also used for file descriptor manipulation.
- **FD manipulation**:
```bash
exec 3>file.txt   # open FD 3 for writing
echo "Hello" >&3
exec 3>&-         # close FD 3
```
- **Coprocess** (`coproc`): Background process with bidirectional pipes:
```bash
coproc myproc { command; }
echo "input" >&"${myproc[1]}"
read output <&"${myproc[0]}"
```
- **Use cases**: Interactive processes (e.g., a database client, a REPL) where you need to send commands and read responses.

# PowerShell

**PS1 — Write-Output vs Write-Host**

- **Write-Output**: Writes to the **output stream** (pipeline). Objects flow to the next command or are captured in a variable.
- **Write-Host**: Writes to the **host** (console) only — bypasses the pipeline. Cannot be captured or piped.
- **Why it matters**: The pipeline depends on the output stream. `Write-Host` is for user-facing display; `Write-Output` is for data. In PowerShell 5+, `Write-Host` is essentially `Write-Information` with host display.

**PS2 — Pipeline & ForEach**

- **Pipeline**: Passes objects between commands (`|`). Each command receives the previous command's output objects.
- **ForEach-Object**: A cmdlet that processes each pipeline object. Streams — memory-efficient for large data.
- **foreach statement**: A language keyword that iterates over a collection. Faster for in-memory collections, but does not stream (loads all into memory).
- **When to use**: Use `ForEach-Object` for pipeline processing (streaming); use `foreach` for iterating a known collection with better performance.

**PS3 — PSCustomObject vs Hashtable**

- **PSCustomObject**: An object with named properties. Supports methods, formatting, and property access via dot notation.
- **Hashtable**: Key-value pairs (`@{key=value}`). Used for dictionaries, splatting, or temporary data.
- **When to use**: Use `PSCustomObject` for structured output (e.g., to export to CSV/JSON); use hashtable for lookups or parameter splatting.
- **Convert**:
```powershell
$obj = [PSCustomObject]@{ Name = 'John'; Age = 30 }
$hash = @{}
$obj.PSObject.Properties | ForEach-Object { $hash[$_.Name] = $_.Value }
```

**PS4 — Error Handling**

- **Terminating errors**: Stop execution. Caught by `try/catch`. Can be thrown with `throw`.
- **Non-terminating errors**: Continue execution. Controlled by `-ErrorAction` or `$ErrorActionPreference`. Written to error stream.
- **-ErrorAction**: Per-command override (`Stop`, `Continue`, `SilentlyContinue`, `Ignore`, `Inquire`).
- **$ErrorActionPreference**: Default for all commands (`Stop` makes all errors terminating).
- **try/catch**: Catches terminating errors only. `finally` runs cleanup.

**PS5 — Splatting**

- **Splatting**: Pass parameters as a hashtable using `@`:
```powershell
$params = @{ Path = 'C:\temp'; Recurse = $true; ErrorAction = 'Stop' }
Get-ChildItem @params
```
- **Difference from passing a hashtable**: Splatting expands the hashtable into individual parameters. Passing a hashtable as a single argument sends one object (e.g., `-Hashtable $hash`).

**PS6 — PowerShell Remoting**

- **Invoke-Command -ComputerName**: Runs a command on a remote machine and returns results. One-off, non-interactive.
- **Enter-PSSession**: Starts an interactive session with a remote machine.
- **Protocol**: Uses **WinRM** (WS-Management) by default, or **SSH** (PowerShell 6+).
- **WinRM**: Microsoft's implementation of WS-Man, typically on port 5985/5986. Requires WinRM configuration.

**PS7 — Type System & Pipeline Unrolling**

```powershell
function Get-Items {
    $result = @()
    $result += "one"
    return $result
}
$x = Get-Items
$x.GetType().Name  # String (not Object[])
```
- **Why**: PowerShell **unrolls** collections. When a function returns a single-item array, PowerShell enumerates it and outputs the item itself, not the array.
- **Zero items**: Returns `$null` (or nothing), not an empty array.
- **Correct pattern**: Use `Write-Output -NoEnumerate` or the comma operator:
```powershell
function Get-Items {
    $result = @()
    $result += "one"
    return ,$result  # comma preserves array
}
```

**PS8 — Scriptblock vs Function; Double-Hop**

- **Scriptblock**: A code block `{ ... }` that can be passed as an argument, invoked with `&`, or used with `Invoke-Command`.
- **Function**: A named scriptblock with parameters, scope, and advanced features.
- **Passing to remote**: `Invoke-Command -ScriptBlock { ... } -ComputerName PC1`.
- **Double-hop problem**: When you connect to PC1 and then try to access PC2, your credentials don't propagate (Kerberos doesn't forward by default).
- **Solutions**: 
  - **CredSSP**: Delegates credentials (security risk).
  - **Kerberos delegation**: Set up SPN and delegation.
  - **-ArgumentList**: Pass explicit credentials/arguments to the remote session.

**PS9 — @() vs [array]**

- **@()**: Array subexpression — wraps a single item in an array. `@(5)` → array with one element.
- **[array]**: Type cast — forces array type.
- **Force single result into array**: `@($result)` or `Write-Output -NoEnumerate`.
- **Indexing $null**: `$null[0]` → `$null` (no error). Empty array `@()[0]` → `$null` (no error). Both return `$null`, but `$null` is not an array.

**PS10 — Comparison Operators**

- **-eq/-ne**: Equality/inequality.
- **-like/-notlike**: Wildcard matching (`*`, `?`).
- **-match/-notmatch**: Regex matching.
- **-contains**: Tests if a **collection** contains a value.
- **-in**: Tests if a **value** is in a collection.
- **Case-sensitive variants**: `-ceq`, `-cne`, `-clike`, `-cmatch`, etc.
- **-contains vs -in**: `-contains` is collection-centric (`$collection -contains $value`); `-in` is value-centric (`$value -in $collection`). Functionally similar but read differently.

**PS11 — Modules**

- **Script module** (.psm1): Contains PowerShell functions/scripts.
- **Manifest module** (.psd1): Metadata file (version, author, dependencies, root module).
- **Binary module**: Compiled .NET assembly (.dll) with cmdlets.
- **Import-Module**: Loads a module into the session. Searches `$env:PSModulePath`. Can import by name, path, or from the gallery.

**PS12 — String Interpolation**

- `"..."`: Interpolates variables and expressions (`$var`, `$(1+2)`).
- `'...'`: Literal — no interpolation.
- **Expressions**: `"Result: $(2 + 3)"` → `Result: 5`.
- **Here-string**:
```powershell
$text = @"
Line 1
Line 2
"@
```
- Here-strings use `@"..."@` (double-quoted, interpolates) or `@'...'@` (single-quoted, literal).

**PS13 — Get-Member & Object Exploration**

- **Get-Member**: Shows properties, methods, and events of objects in the pipeline.
- **Properties**: Regular properties (e.g., `Name`, `Length`).
- **Methods**: Callable functions (e.g., `.ToString()`).
- **NoteProperties**: Added properties (e.g., from `Select-Object` or `Add-Member`).
- **Select-Object**: Selects specific properties (projection).
- **Where-Object**: Filters objects based on criteria.

**PS14 — PowerShell Classes**

- Introduced in v5.0. Define with `class` keyword.
- **Differences from C#**: No multiple inheritance, no interfaces (until v6+), limited constructor overloading, no access modifiers (all public).
- **Limitations**: Cannot inherit from C# classes directly (except via binary modules), no abstract classes (until v6+), no generics.
- **When to use**: Use classes for complex stateful objects with methods; use functions for simple operations or pipeline processing.

**PS15 — CmdletBinding & Advanced Functions**

- `[CmdletBinding()]` makes a function an **advanced function** — adds `-Verbose`, `-Debug`, `-ErrorAction`, `-WhatIf`, etc.
- **SupportsShouldProcess**: Enables `-WhatIf`/`-Confirm` for destructive operations.
- **DefaultParameterSetName**: Specifies which parameter set is used when none is specified.
- **ValueFromPipeline**: Accepts pipeline input for a parameter.
- **Begin/Process/End blocks**: 
  - `Begin`: Runs once (initialization).
  - `Process`: Runs for each pipeline input object.
  - `End`: Runs once (cleanup).

**PS16 — Providers**

- **Providers**: Expose data stores as a file system. Examples: `FileSystem`, `Registry`, `Certificate`, `Environment`, `Alias`, `Function`.
- **Get-ChildItem** works across providers: `Get-ChildItem HKCU:\Software` lists registry keys; `Get-ChildItem Cert:\CurrentUser` lists certificates.
- **Registry access**: `Set-Location HKCU:\Software\Microsoft` then `Get-ChildItem` or `Get-ItemProperty`.

**PS17 — Runspaces & Parallel Execution**

- **Runspace**: A PowerShell session environment (independent of the main session).
- **RunspacePool**: A pool of runspaces for concurrent execution.
- **[powershell] object**: A PowerShell instance that can execute commands in a runspace.
- **ForEach-Object -Parallel** (v7+): Simple parallel execution:
```powershell
1..10 | ForEach-Object -Parallel { $_ * 2 } -ThrottleLimit 5
```
- **Manual runspace management**: More control (state, reuse, complex synchronization) but more code.

**PS18 — PSScriptAnalyzer**

- **PSScriptAnalyzer**: Static analysis tool for PowerShell code quality.
- **Rules**: Coding standards (e.g., `PSUseShouldProcessForStateChangingFunctions`, `PSAvoidUsingWriteHost`).
- **Severity levels**: `Error`, `Warning`, `Information`.
- **Custom rules**: Can be written as PowerShell modules.
- **Suppress**: `[Diagnostics.CodeAnalysis.SuppressMessage('RuleName', 'Justification')]`.
- **CI/CD**: Integrate via `Invoke-ScriptAnalyzer` in build pipelines (e.g., Azure DevOps, GitHub Actions).

**PS19 — $using: Scope & Serialization**

- **$using:**: Passes variables from the caller's scope to remote sessions, background jobs, and `ForEach-Object -Parallel`.
- **-ArgumentList**: Alternative for passing parameters to scriptblocks.
- **CLIXML serialization**: Objects are serialized to CLIXML when crossing boundaries. Depth limit is **5** (default) — deeper nested objects lose fidelity.
- **Effects**: Complex objects (e.g., custom classes, live objects) may be deserialized as `PSObject` shells, losing methods and type identity.

**PS20 — Desired State Configuration (DSC)**

- **DSC**: Declarative configuration management for Windows.
- **Configurations**: Scripts that define the desired state (e.g., `Configuration WebServer { ... }`).
- **Resources**: Modules that implement the actual changes (e.g., `File`, `Service`, `Package`).
- **LCM (Local Configuration Manager)**: The engine that applies configurations and enforces state.
- **Windows PowerShell vs PS7**: DSC is built into Windows PowerShell (v4+). In PowerShell 7+, DSC is **not included** — it's deprecated in favor of external tools.
- **Modern replacements**: Tools like **Ansible**, **Terraform**, **Azure Automation**, or **PowerShell DSC for Linux** (community). Microsoft now pushes **Azure Policy** and **Bicep** for cloud infrastructure.
