## .NET / C#

**DN1 — Class vs Struct:**
A **class** is a reference type allocated on the heap; it supports inheritance, can be null, and is garbage-collected. A **struct** is a value type stored inline (often on the stack); it does not support inheritance (except interfaces) and is copied by value. Use a struct for small, immutable, logically-single-value types (e.g., `Point`, `Complex`) where copying is cheaper than heap allocation and you don't need polymorphism.

**DN2 — IEnumerable<T> vs IQueryable<T>:**
`IEnumerable<T>` represents an in-memory sequence and uses LINQ-to-Objects; operations execute on the client side. `IQueryable<T>` represents a query against an external data source (e.g., SQL database); it builds an expression tree that is translated to the source's query language (e.g., SQL) and executed server-side. For database queries, `IQueryable` lets you compose filters (`Where`, `Select`) that are translated to SQL, avoiding fetching all rows into memory. `IEnumerable` would pull the entire result set and filter in memory.

**DN3 — async/await, Task vs ValueTask:**
`async`/`await` creates a state machine that yields control to the caller while awaiting an asynchronous operation, preventing thread blocking. `Task` is a heap-allocated reference type representing an async operation; it's reusable and suitable for most scenarios. `ValueTask` is a value type that avoids heap allocation, useful when the operation often completes synchronously or in high-performance hot paths. Use `ValueTask` for methods that frequently return synchronously or when allocation overhead matters (e.g., library code with tight loops).

**DN4 — Dependency Injection:**
DI in .NET registers services with lifetimes: **Transient** (created each time requested), **Scoped** (created once per request/scope), **Singleton** (created once for app lifetime). A common bug is injecting a Scoped service into a Singleton—this creates a **captive dependency**, where the Singleton holds a Scoped service that lives forever, defeating the Scoped lifetime. Fix by using `IServiceScopeFactory` to create a scope inside the Singleton or changing the consuming service's lifetime.

**DN5 — string vs ReadOnlySpan<char>:**
`string` is immutable, heap-allocated, and UTF-16 encoded; slicing creates new strings. `ReadOnlySpan<char>` is a stack/ref-based view over memory with no allocation; slicing is O(1) and allocation-free. Use `Span<T>`/`ReadOnlySpan<T>` for performance-critical string processing (e.g., parsing, searching) where you want to avoid allocations and can work with stack-allocated buffers or existing memory.

**DN6 — .NET Garbage Collector:**
The GC manages managed memory in generations: **Gen 0** (short-lived objects), **Gen 1** (survivors of Gen 0), **Gen 2** (long-lived objects). The **Large Object Heap (LOH)** holds objects > 85KB; it's not compacted by default (to avoid performance hits). `IDisposable` is needed for unmanaged resources (files, sockets, DB connections) because the GC only handles managed memory; you must explicitly release unmanaged resources via `Dispose()` or `using` statements.

**DN7 — ConfigureAwait(false):**
By default, `await` captures the current `SynchronizationContext` (or `TaskScheduler`) and resumes on that context (e.g., UI thread). `ConfigureAwait(false)` tells the continuation to not capture the context, resuming on the thread pool instead. Use it in **library code** to avoid deadlocks and improve performance; do **not** use it in UI code where you need to update UI controls on the main thread.

**DN8 — .NET 8/9 Features:**
- **Primary constructors**: `public class Point(int x, int y) { ... }`—parameters are in scope for the class body.
- **Collection expressions**: `int[] arr = [1, 2, 3];` or `[..existing]` for spreading.
- **FrozenDictionary**: immutable, optimized for read-only access; created via `.ToFrozenDictionary()`.
- Example with primary constructors and DI:
```csharp
public class MyService(ILogger<MyService> logger) : IMyService
{
    public void DoWork() => logger.LogInformation("Working");
}
// Registered as: builder.Services.AddSingleton<IMyService, MyService>();
```

**DN9 — ObjectDisposedException on DbContext:**
Likely cause: the `DbContext` is registered as **Scoped** but used in a **Singleton** or captured across threads, or disposed manually. Under high concurrency, a shared/disposed context throws `ObjectDisposedException`. EF Core's `DbContext` should be **Scoped**—one per request—and never manually disposed (the DI container handles it). Fix: register `DbContext` as Scoped, don't dispose it manually, and don't inject it into Singletons; use `IServiceScopeFactory` if needed.

**DN10 — record vs class:**
A **record** is a reference type with **value equality** (based on properties), built-in `ToString`, equality operators, and `with` expressions for non-destructive mutation. A **class** uses reference equality by default. A **record struct** is a value type with value equality. Use records for immutable data models, DTOs, and when you need value semantics; use classes for objects with identity and mutable state.

**DN11 — ref, out, in:**
- `ref`: variable must be initialized before passing; method can read/write it.
- `out`: variable doesn't need initialization; method must assign it before returning.
- `in`: read-only reference; method cannot modify it.
Use `ref` for large structs that need modification, `out` for return values via parameters, `in` for read-only access to large structs to avoid copying.

**DN12 — Nullable reference types:**
With `#nullable enable`, `?` on a reference type (e.g., `string?`) is a **compile-time annotation** indicating the variable may be null; the compiler enforces null checks. `int?` is a **nullable value type** (`Nullable<int>`), which is a runtime wrapper allowing `int` to be null. Reference type annotations don't change runtime behavior—they only enable compile-time analysis to prevent null reference exceptions.

**DN13 — LINQ:**
LINQ (Language Integrated Query) provides querying over collections. **Method syntax**: `list.Where(x => x > 5)` uses extension methods. **Query syntax**: `from x in list where x > 5 select x` is translated to method syntax. **Deferred execution** means the query is not executed until enumerated; this allows composition (e.g., adding more filters) without extra cost.

**DN14 — Generic constraints:**
- `where T : class` — T must be a reference type.
- `where T : struct` — T must be a value type.
- `where T : new()` — T must have a parameterless constructor.
- `where T : IComparable<T>` — T must implement the interface.
Combine multiple constraints: `where T : class, IComparable<T>, new()`.

**DN15 — abstract class vs interface:**
An **abstract class** can have implementation, fields, constructors, and state; supports single inheritance. An **interface** is a pure contract (no implementation until C# 8 default methods); supports multiple inheritance. Default interface methods (C# 8+) allow adding new methods to interfaces without breaking existing implementers, blurring the distinction but still not providing state.

**DN16 — Middleware pipeline:**
- `app.Use()`: adds middleware to the request pipeline (e.g., `app.UseMiddleware<MyMiddleware>()`).
- `app.Map()`: creates a branch (e.g., `app.MapGet("/path", handler)`).
- `app.Run()`: terminal middleware that ends the pipeline.
Ordering matters—middleware runs in the order added. Exception handling middleware should be placed early to catch exceptions from later middleware.

**DN17 — Channel<T>:**
`Channel<T>` is a modern async producer-consumer primitive supporting async writes/reads and backpressure. `BlockingCollection<T>` is synchronous and blocking. Bounded channels have a capacity; when full, producers await until space is available. Example:
```csharp
var channel = Channel.CreateBounded<int>(10);
await channel.Writer.WriteAsync(item);
await foreach (var item in channel.Reader.ReadAllAsync()) { ... }
```

**DN18 — Source Generators:**
Source generators generate C# code at compile time, avoiding runtime reflection overhead. They differ from reflection (runtime) and IL weaving (post-compilation IL modification) by working on source text during compilation. **Incremental generators** cache results and only regenerate when inputs change, improving build performance; they are preferred over `ISourceGenerator` because they support incremental compilation.

**DN19 — TPL Dataflow:**
`System.Threading.Tasks.Dataflow` provides building blocks: `ActionBlock` (processes messages), `TransformBlock` (transforms input to output), `BufferBlock` (buffers messages). It supports complex pipelines with branching, joining, and backpressure. `System.Threading.Channels` is simpler and more lightweight for basic producer-consumer; Dataflow is better for multi-stage pipelines with transformation and fan-out/fan-in.

**DN20 — Minimal APIs:**
Minimal APIs use top-level statements and lambdas for endpoints, reducing boilerplate vs controller-based APIs (which use classes, attributes, and model binding). Trade-offs: Minimal APIs are simpler and faster to write but can be less testable (though endpoint filters help); OpenAPI support is built-in via `AddEndpointsApiExplorer()`. **Route groups** (`MapGroup`) share prefixes/filters; **endpoint filters** run before/after handlers, providing middleware-like logic for specific endpoints.

## Python

**P1 — list vs tuple:**
A **list** is mutable (can add/remove elements), while a **tuple** is immutable (fixed size) and hashable if its elements are hashable. A **set** is mutable, unordered, and contains unique elements; a **frozenset** is immutable and hashable. Use tuples for fixed data, lists for dynamic collections, sets for membership tests, and frozensets for hashable set constants.

**P2 — GIL:**
The **GIL** (Global Interpreter Lock) ensures only one thread executes Python bytecode at a time, limiting CPU-bound multi-threading. It affects CPU-bound workloads (e.g., computation) but not I/O-bound (e.g., network, file). Workarounds: use `multiprocessing` (separate processes), C extensions that release the GIL, or `asyncio` for I/O concurrency.

**P3 — deepcopy vs copy:**
`copy.copy()` creates a **shallow copy**—the object is new but nested objects are shared. `copy.deepcopy()` recursively copies all nested objects. Shallow copy causes unexpected behavior when modifying nested mutable objects:
```python
import copy
a = [[1], [2]]
b = copy.copy(a)
b[0].append(3)  # a[0] also becomes [1, 3]
```

**P4 — Decorators:**
Decorators are functions that wrap other functions to extend behavior. Example timing decorator:
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.2f}s")
        return result
    return wrapper

@timer
def foo(): ...
```

**P5 — Generators and yield:**
Generators are functions that use `yield` to produce values lazily, one at a time, instead of building a full list. They are memory-efficient for large datasets. `yield from` delegates to another generator (e.g., `yield from gen2`). Unlike returning a list, generators don't store all values in memory and can be infinite.

**P6 — asyncio:**
`asyncio` uses an **event loop** to run coroutines concurrently. `asyncio.run()` creates and runs the event loop for a top-level coroutine. `asyncio.gather()` runs multiple coroutines concurrently and waits for all. `asyncio.create_task()` schedules a coroutine as a task without blocking. You can't call `time.sleep()` because it blocks the thread; use `await asyncio.sleep()` to yield control to the event loop.

**P7 — MRO:**
Python 3 uses the **C3 linearization** algorithm for MRO. For diamond inheritance `class D(B, C)` where `B` and `C` inherit from `A`, the MRO is `D → B → C → A`. `D().who()` prints `"C"` because `C` overrides `who()` and appears before `A` in the MRO.

**P8 — Metaclass:**
A **metaclass** is a class that creates classes (e.g., `type`). `__init_subclass__` is a hook called when a subclass is created. Use a metaclass for class-level registration, validation, or modifying class creation (e.g., ORMs, frameworks). Use `__init_subclass__` for simpler subclass customization (e.g., auto-registering subclasses). Practical use: a metaclass that registers all classes in a registry; `__init_subclass__` for adding attributes to subclasses.

**P9 — multiprocessing vs threading vs concurrent.futures:**
- `multiprocessing`: uses separate processes, bypasses the GIL, ideal for CPU-bound tasks.
- `threading`: uses threads, limited by the GIL, ideal for I/O-bound tasks.
- `concurrent.futures`: high-level API for both (e.g., `ThreadPoolExecutor`, `ProcessPoolExecutor`).
Multiprocessing requires arguments to be **picklable** (serializable), which can fail for complex objects (e.g., lambdas, file handles).

**P10 — __slots__:**
`__slots__` prevents the creation of a `__dict__` per instance, saving memory. Use it for classes with many instances and fixed attributes. It prevents adding new attributes dynamically. Memory impact: significantly reduces memory usage for large numbers of instances.

**P11 — Virtual environment:**
A virtual environment isolates Python dependencies per project. `venv` is built-in and lightweight; `virtualenv` is third-party with more features (e.g., faster, supports older Python); `conda` is a package manager + environment manager that also handles non-Python packages (e.g., C libraries). Use one to avoid dependency conflicts.

**P12 — Comprehensions:**
- List: `[x for x in range(10)]`
- Dict: `{k: v for k, v in items}`
- Set: `{x for x in range(10)}`
They are more readable and Pythonic than `map()`/`filter()`, which are functional alternatives. Prefer comprehensions for clarity; use `map`/`filter` when you have a function to apply and want a functional style.

**P13 — == vs is:**
`==` checks **value equality**; `is` checks **identity** (same object). Object interning caches small integers (-5 to 256) and some strings, so `a is b` can return `True` for small integers because they reference the same cached object. Use `==` for value comparison and `is` for `None` or singleton checks.

**P14 — *args and **kwargs:**
`*args` captures extra positional arguments as a tuple; `**kwargs` captures extra keyword arguments as a dict. Positional-only parameters (before `/`) cannot be passed as keywords; keyword-only parameters (after `*`) must be passed as keywords. Example: `def f(a, /, b, *, c): ...`—`a` is positional-only, `b` can be positional or keyword, `c` is keyword-only.

**P15 — Context managers:**
The `with` statement ensures setup/cleanup. Class-based: implement `__enter__`/`__exit__`. Decorator-based: use `@contextmanager` from `contextlib`. Example beyond files—timing:
```python
from contextlib import contextmanager
@contextmanager
def timer():
    start = time.time()
    yield
    print(f"Elapsed: {time.time()-start}")
```

**P16 — Type hinting:**
- `typing.Union[int, str]` — multiple types.
- `Optional[int]` — `Union[int, None]`.
- `Literal["a", "b"]` — specific values.
- `TypeVar("T")` — generic type variable.
- `Protocol` — structural typing (duck typing).
Tools like `mypy`/`pyright` use these for static analysis to catch type errors before runtime.

**P17 — Data model:**
- `__repr__`: unambiguous representation for debugging.
- `__str__`: readable representation for `print()`.
- `__eq__`: equality; `__hash__`: hash value. Defining `__eq__` without `__hash__` makes objects unhashable (Python sets `__hash__` to `None`).
- `__getattr__`: called when attribute is not found; `__getattribute__`: called for every attribute access.

**P18 — Descriptors:**
Descriptors implement `__get__`, `__set__`, `__delete__` to manage attribute access. `property` uses `__get__`/`__set__`; `classmethod` binds the method to the class; `staticmethod` doesn't bind. Under the hood, these are descriptor objects stored on the class.

**P19 — Import system:**
`sys.path` is a list of directories searched for modules; `PYTHONPATH` adds directories. `__init__.py` marks a directory as a package; **namespace packages** are packages without `__init__.py` (PEP 420). A **finder** locates the module (e.g., `PathFinder`), and a **loader** loads it (e.g., `SourceFileLoader`). The import system uses finders/loaders via `sys.meta_path`.

**P20 — dataclasses vs attrs vs Pydantic:**
`dataclasses` is built-in, simple, with `__post_init__` for validation and `field(default_factory=...)` for mutable defaults; `frozen=True` makes instances immutable. `attrs` offers more features (validators, converters, slots). `Pydantic` provides runtime validation, serialization, and schema generation (e.g., for APIs). Choose `dataclasses` for simple internal data; `attrs` for advanced class creation; `Pydantic` for data validation, settings management, and API schemas.
