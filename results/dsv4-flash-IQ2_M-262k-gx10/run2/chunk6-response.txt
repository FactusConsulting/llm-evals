# JavaScript / TypeScript

**JS1 — var, let, const, hoisting**
- `var`: function-scoped, hoisted and initialized to `undefined`, can be redeclared.
- `let`: block-scoped, hoisted but in temporal dead zone (TDZ) until declaration, cannot be redeclared.
- `const`: block-scoped, hoisted with TDZ, must be initialized, cannot be reassigned (objects still mutable).
- **Hoisting**: declarations are moved to the top of their scope at compile time. `var` initializes with `undefined`; `let`/`const` remain uninitialized until the declaration line (TDZ).

**JS2 — Event loop**
- **Call stack**: synchronous execution context — functions pushed/popped.
- **Microtask queue**: promises, `queueMicrotask`, `MutationObserver` — drained completely before any macrotask.
- **Macrotask queue**: `setTimeout`, `setInterval`, I/O events — one per event-loop iteration.
- **Loop**: if call stack is empty → process all microtasks → then one macrotask → repeat. This guarantees microtasks run before the next macrotask.

**JS3 — Closures**
- **Closure**: a function retaining access to its lexical scope even when executed outside it.
- **Example**:
```js
function createCounter() {
  let count = 0;
  return () => ++count;
}
```
- **Classic for-loop bug**: `var` shares one scope:
```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100); // 3, 3, 3
}
```
- **Fix**: use `let` (block-scoped) or an IIFE:
```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100); // 0, 1, 2
}
```

**JS4 — Promise, async/await, error handling**
- **Promise**: object representing eventual completion/failure (pending, fulfilled, rejected).
- **async/await**: syntactic sugar over promises; `async` returns a promise, `await` pauses until settled.
- **Error handling**: `.catch()` for promises; `try/catch` for async/await; `finally` for cleanup.
- **Promise.all**: rejects immediately on first rejection (fail-fast).
- **Promise.allSettled**: waits for all; returns `[{status, value/reason}]` — never rejects.

**JS5 — TypeScript interface vs type**
- **interface**: object shapes, supports `extends` and declaration merging; good for public APIs/class contracts.
- **type**: unions, intersections, mapped types, tuples, primitives; more flexible but cannot merge.
- **Discriminated unions**: union of types sharing a discriminant property (e.g., `type: 'circle' | 'square'`), enabling type narrowing via switch.

**JS6 — Prototypal inheritance**
- Objects inherit from other objects via `[[Prototype]]`; property lookup walks the chain.
- **Object.create()**: creates a new object with a specified prototype:
```js
const animal = { speak() { return '...'; } };
const dog = Object.create(animal);
```
- **ES6 classes**: syntactic sugar over prototypes; `extends` uses `Object.create` under the hood; `super` calls parent constructor.

**JS7 — `this` binding rules (priority order)**
1. **New binding**: `new` creates a new object and binds `this` to it.
2. **Explicit binding**: `call`, `apply`, `bind`.
3. **Implicit binding**: `obj.method()` binds `this` to `obj`.
4. **Default binding**: global object (or `undefined` in strict mode).
- **bind()**: returns a new function with `this` permanently bound; cannot be re-bound with `call`/`apply`, but `new` ignores the binding.

**JS8 — WeakRef and FinalizationRegistry**
- **WeakRef**: holds a weak reference to an object (doesn't prevent GC); access via `.deref()` (may return `undefined`).
- **FinalizationRegistry**: registers callbacks when objects are garbage collected.
- **Use cases**: caching large objects, resource tracking, memory-sensitive apps.
- **WeakMap keys must be objects**: GC tracks objects by reference; primitives can't be tracked. WeakMap holds weak references to keys — if a key is GC'd, the entry is removed.

**JS9 — V8 optimization**
- **Hidden classes**: internal shape descriptors (maps) for objects to optimize property access.
- **Inline caching**: caches property lookups based on hidden class.
- **Deoptimization causes**: dynamic property addition/removal, inconsistent object shapes, changing prototypes, `eval`, `with`, `delete`, non-monomorphic call sites.
- **Best practices**: keep object shapes consistent, avoid dynamic property addition, use monomorphic functions.

**JS10 — Tree-shaking**
- **Tree-shaking**: removing unused code during bundling.
- **ES modules**: statically analyzable — imports/exports known at compile time → effective tree-shaking.
- **CommonJS**: dynamic `require`/`module.exports` — bundlers can't reliably determine exports → limited tree-shaking.
- **Why CommonJS fails**: `module.exports` can be assigned at runtime, making static analysis impossible.

**JS11 — null vs undefined, == vs ===, ??, ?.**
- **null**: explicitly assigned "no value"; **undefined**: default for uninitialized variables.
- `null == undefined` → `true`; `null === undefined` → `false` (`==` coerces).
- **Nullish coalescing (??)**: returns right side if left is `null`/`undefined`:
```js
const x = value ?? defaultValue;
```
- **Optional chaining (?.)**: short-circuits if property is `null`/`undefined`:
```js
const name = user?.profile?.name;
```

**JS12 — map, filter, reduce, flatMap**
- **map()**: transforms each element → new array.
- **filter()**: returns elements passing a predicate.
- **reduce()**: accumulates values; initial value optional (if omitted, uses first element).
- **flatMap()**: maps then flattens one level — useful for nested arrays:
```js
[1, 2, 3].flatMap(x => [x, x * 2]); // [1, 2, 2, 4, 3, 6]
```

**JS13 — Template literals and tagged templates**
- **Template literals**: strings with `${}` interpolation, multi-line support.
- **Tagged templates**: function called with processed strings and interpolated values:
```js
function sql(strings, ...values) {
  return strings.reduce((acc, str, i) => acc + str + (values[i] || ''), '');
}
const query = sql`SELECT * FROM users WHERE id = ${id}`;
```

**JS14 — Destructuring**
- **Object**: `const { name, age } = person;`
- **Array**: `const [first, second] = arr;`
- **Default values**: `const { name = 'Unknown' } = person;`
- **Renaming**: `const { name: userName } = person;`
- **Rest**: `const { name, ...rest } = person;` — collects remaining properties/elements.

**JS15 — for...in vs for...of**
- **for...in**: iterates over enumerable string keys (including inherited) — for objects.
- **for...of**: iterates over iterable values (arrays, strings, maps) — for arrays.
- **Avoid for...in on arrays**: includes inherited properties, order not guaranteed, includes non-index keys.

**JS16 — TypeScript generics**
- **Generics**: functions/classes that work with multiple types:
```js
function identity<T>(arg: T): T { return arg; }
```
- **Constraints**: `T extends U` — T must be assignable to U.
- **Conditional types**: `T extends U ? X : Y` — type-level if/else.
- **infer**: extracts types from conditional types:
```js
type ElementType<T> = T extends (infer U)[] ? U : never;
```

**JS17 — Module systems**
- **CommonJS**: `require`/`module.exports` — synchronous, used in Node.js.
- **ES Modules**: `import`/`export` — asynchronous, static, used in browsers and modern Node.
- **Node.js handling**: supports both; `.cjs` for CommonJS, `.mjs` for ESM, or `"type": "module"` in package.json for ESM.
- **"type": "module"**: makes `.js` files treated as ES modules.

**JS18 — TypeScript structural typing**
- **Structural typing**: types compatible if shapes match (duck typing).
- **Excess property checks**: extra properties in object literals cause errors; applies only to fresh literals, not variables.
- **extends vs satisfies**: `extends` constrains a type; `satisfies` checks a value against a type without changing its inferred type.
- **Variance (in/out)**: `in` (contravariant) for inputs, `out` (covariant) for outputs; TypeScript 4.7+ allows explicit variance modifiers.

**JS19 — Proxy and Reflect**
- **Proxy**: wraps an object to intercept operations via handler traps.
- **Reflect**: provides default behavior methods (`Reflect.get`, `Reflect.set`).
- **Example**:
```js
const validator = new Proxy(target, {
  set(obj, prop, value) {
    if (prop === 'age' && value < 0) throw new Error('Invalid');
    return Reflect.set(obj, prop, value);
  }
});
```

**JS20 — SharedArrayBuffer and Atomics**
- **SharedArrayBuffer**: shared memory between workers.
- **Atomics**: atomic operations (add, load, store, wait, notify) on shared memory.
- **Web Workers**: use `postMessage` with SharedArrayBuffer to share memory.
- **Ordering**: Atomics provide sequential consistency; `Atomics.wait` blocks until value changes; `Atomics.notify` wakes waiting threads.

# Bash

**B1 — $@ vs $***
- **$@**: each positional parameter as a separate word.
- **$***: all parameters as a single word (joined with IFS).
- **"$@"**: preserves each argument separately — safe for spaces.
- **"$*"**: joins all arguments into one string — loses separation.

**B2 — set -euo pipefail**
- **-e**: exit on error (non-zero exit status).
- **-u**: treat unset variables as errors.
- **-o pipefail**: pipeline returns the last non-zero exit status.
- **Combined**: prevents silent failures and unset variable bugs.

**B3 — $(command) vs `command`, $((expression)) vs expr**
- **$(command)**: command substitution — preferred over backticks (easier nesting, escaping).
- **`command`**: legacy backtick form — harder to nest, escaping issues.
- **$((expression))**: arithmetic expansion — integer math.
- **expr**: external command — slower, requires escaping.

**B4 — Process substitution**
- **<(command)**: creates a file descriptor (e.g., `/dev/fd/N`) that the command writes to.
- **Use case**: when a command expects a file argument:
```bash
diff <(sort file1) <(sort file2)
```

**B5 — Safe file iteration**
- **Use `find` with `-print0` and `while read -d ''`**:
```bash
find . -type f -print0 | while IFS= read -r -d '' file; do
  echo "$file"
done
```
- **Why `for f in $(ls)` is dangerous**: word-splitting on spaces, glob expansion, special characters break it.

**B6 — Here document vs here string**
- **Here document (<<EOF)**: redirects multi-line input to a command.
- **Here string (<<<)**: redirects a single string (adds newline).
- **<<-EOF**: strips leading tabs (allows indentation).

**B7 — Redirection order**
- **`cmd > file 2>&1`**: stdout to file, then stderr to stdout (both to file).
- **`cmd 2>&1 > file`**: stderr to current stdout (terminal), then stdout to file — stderr goes to terminal, not file.
- **`cmd &> file`**: both stdout and stderr to file (bash-specific).

**B8 — Lock file with cleanup**
```bash
lock_dir=/tmp/mylock
if mkdir "$lock_dir"; then
  trap 'rmdir "$lock_dir"' EXIT
  # critical section
else
  echo "Already running" >&2
  exit 1
fi
```
- **Why mkdir**: atomic operation — either succeeds or fails. File creation with `touch` can race (check-then-create is not atomic).

**B9 — Quotes**
- **Single quotes**: literal — no expansion.
- **Double quotes**: expansion allowed ($var, command substitution), but no word-splitting.
- **No quotes**: word-splitting and glob expansion.
```bash
var="hello world"
echo '$var'  # $var
echo "$var"  # hello world
echo $var    # hello world (but splits)
```

**B10 — File checks, [ ] vs [[ ]]**
- **Checks**: `-e` (exists), `-d` (directory), `-r` (readable), `-f` (regular file).
- **[ ]**: POSIX test — external command, word-splitting, no regex.
- **[[ ]]**: Bash builtin — more features (regex, &&, ||), no word-splitting.

**B11 — $?, $$, $!, $#**
- **$?**: exit status of last command.
- **$$**: PID of current shell.
- **$!**: PID of last background job.
- **$#**: number of positional parameters.

**B12 — Functions**
- **Definition**: `foo() { ... }` or `function foo { ... }` (both work; `function` is bash-specific).
- **Return**: `return` for exit status; `echo` for output (captured via command substitution).
- **Scope**: variables are global unless `local` is used.

**B13 — PATH, builtins vs external**
- **PATH**: colon-separated directories for command lookup.
- **Resolution**: bash checks builtins first, then PATH.
- **Builtin**: built into shell (e.g., `cd`, `echo`).
- **External**: separate binary (e.g., `ls`, `grep`).
- **Check**: `type -a command` or `which`.

**B14 — trap**
- **Syntax**: `trap 'command' SIGNAL`
- **Common signals**: EXIT, ERR, INT, TERM.
- **Order**: multiple signals — traps run in order received; EXIT trap runs on any exit.
- **Example**:
```bash
trap 'cleanup' EXIT
trap 'echo "Interrupted"; exit 1' INT
```

**B15 — xargs vs command substitution**
- **xargs**: reads stdin and builds commands — handles spaces correctly with `-0`.
- **Command substitution**: `$(...)` — word-splits, unsafe for filenames.
- **find -print0 | xargs -0**: null-delimited, safe for spaces/newlines.
- **xargs -P**: parallel execution (e.g., `-P 4` for 4 processes).

**B16 — Arrays**
- **Indexed**: `arr=(a b c)`, append `arr+=(d)`, iterate `for i in "${arr[@]}"`, length `${#arr[@]}`.
- **Associative**: `declare -A map`, `map[key]=value`, iterate `for k in "${!map[@]}"`, length `${#map[@]}`.
- **Syntax differences**: associative arrays need `declare -A`; keys can be arbitrary strings.

**B17 — Subshell vs group command**
- **Subshell (...)**: runs in child shell — variable changes don't propagate.
- **Group { ...; }**: runs in current shell — variables persist.
- **Pipe into while loop**: runs in subshell (unless `lastpipe` or `shopt -s lastpipe`), so variable changes are lost.

**B18 — Signals and job control**
- **SIGINT**: interrupt (Ctrl+C) — can be caught.
- **SIGTERM**: termination — can be caught for graceful shutdown.
- **SIGHUP**: hangup (terminal closed) — can be caught.
- **SIGKILL**: cannot be caught — immediate kill.
- **Graceful shutdown**: trap SIGTERM, kill background jobs, wait for them.

**B19 — Parallel log processing**
```bash
split -n 4 log.txt part-
process() { grep -c "error" "$1" > "$1.count"; }
export -f process
find . -name "part-*" -print0 | xargs -0 -P 4 -I {} bash -c 'process {}'
cat *.count | awk '{sum += $1} END {print sum}'
```
- **Trade-offs**: CPU/memory vs speed; error handling via exit codes and `xargs` failure detection.

**B20 — exec, file descriptors, coprocesses**
- **exec**: replaces the shell process (no return) or redirects file descriptors.
- **FD manipulation**: `exec 3>file` opens FD 3; `exec 3>&-` closes it.
- **Coprocess**: `coproc name { command; }` — runs in background with stdin/stdout pipes.
- **Use case**: interactive communication with a long-running process.

# PowerShell

**PS1 — Write-Output vs Write-Host**
- **Write-Output**: writes to the output stream (pipeline) — objects are passed forward.
- **Write-Host**: writes to the console only — not in pipeline.
- **Importance**: Write-Output enables composability; Write-Host is for display only.

**PS2 — Pipeline, ForEach-Object vs foreach**
- **Pipeline**: passes objects between commands.
- **ForEach-Object**: pipeline-based, processes one object at a time — memory-efficient.
- **foreach statement**: collects all items first — faster for small collections, but memory-heavy.
- **When**: use ForEach-Object for streaming; `foreach` for small in-memory collections.

**PS3 — PSCustomObject vs hashtable**
- **[PSCustomObject]**: proper object with properties — good for output.
- **[hashtable]**: key-value dictionary — internal data structure.
- **Conversion**: `[PSCustomObject]@{key='value'}` or `$ht.GetEnumerator()`.

**PS4 — Error handling**
- **Terminating errors**: stop execution — caught by try/catch.
- **Non-terminating errors**: continue execution — handled by `-ErrorAction` or `$ErrorActionPreference`.
- **-ErrorAction**: per-command; `$ErrorActionPreference` is global default.
- **try/catch**: catches terminating errors; `-ErrorAction Stop` makes non-terminating errors terminating.

**PS5 — Splatting**
- **Splatting**: pass parameters as a hashtable:
```powershell
$params = @{ Path = 'file.txt'; Force = $true }
Get-Item @params
```
- **Difference**: splatting expands parameters individually; passing a hashtable as a single argument.

**PS6 — PowerShell remoting**
- **Invoke-Command -ComputerName**: runs commands on remote machines (one-off).
- **Enter-PSSession**: interactive session.
- **Protocol**: WinRM (WS-Man) by default; SSH in PowerShell 7+.

**PS7 — Type system and pipeline behavior**
- **Function output**: PowerShell collects all output into an array.
- **The bug**: when returning a single item, PowerShell unrolls it — `$x` is a string, not an array.
- **Zero items**: returns `$null` or empty.
- **Fix**: use `Write-Output -NoEnumerate` or `return ,$result` (comma operator).

**PS8 — Scriptblock vs function, double-hop**
- **Scriptblock**: `{ ... }` — anonymous code block.
- **Function**: named scriptblock with parameters.
- **Remote scriptblock**: passed to `Invoke-Command -ScriptBlock`.
- **Double-hop**: credentials don't propagate to a second remote machine. Solve with CredSSP or `-ArgumentList` to pass credentials explicitly.

**PS9 — @() vs [array]**
- **@()**: array subexpression — wraps output in an array.
- **[array]**: type cast — forces array.
- **Force single result into array**: `@($result)` or `[array]$result`.
- **Indexing $null**: returns `$null`; empty array returns `$null` too (no error).

**PS10 — Comparison operators**
- **-eq, -ne**: equality.
- **-like, -notlike**: wildcard matching.
- **-match, -notmatch**: regex matching.
- **-contains**: checks if collection contains a value.
- **-in**: checks if value is in collection (right side is collection).
- **Case-sensitive variants**: `-ceq`, `-clike`, `-cmatch`, etc.

**PS11 — Modules**
- **Script module (.psm1)**: contains functions.
- **Manifest module (.psd1)**: metadata (version, dependencies).
- **Binary module**: compiled C# code.
- **Import-Module**: loads module into session.

**PS12 — String interpolation**
- **"..."**: interpolates variables and expressions.
- **'...'**: literal strings.
- **Expressions**: `"Value: $($obj.Property)"`.
- **Here-string**: `@"..."@` for multi-line strings.

**PS13 — Get-Member, Select-Object vs Where-Object**
- **Get-Member**: shows properties, methods, note properties.
- **Properties**: built-in; **Methods**: functions; **NoteProperties**: added at runtime.
- **Select-Object**: chooses properties (projection).
- **Where-Object**: filters objects (predicate).

**PS14 — PowerShell classes**
- **Syntax**: `class Foo { [int]$Prop; Foo() {} }`.
- **Differences from C#**: no interfaces, limited inheritance, no generics.
- **Limitations**: single inheritance, no abstract classes, constructors limited.
- **When**: use classes for complex state; functions for simple operations.

**PS15 — CmdletBinding and advanced functions**
- **[CmdletBinding()]**: adds cmdlet features (parameter validation, `-Verbose`, `-ErrorAction`).
- **SupportsShouldProcess**: enables `-WhatIf`/`-Confirm`.
- **DefaultParameterSetName**: specifies default parameter set.
- **ValueFromPipeline**: accepts pipeline input.
- **Begin/Process/End**: blocks for initialization, per-item processing, cleanup.

**PS16 — Providers**
- **Providers**: expose data stores as drives (FileSystem, Registry, Certificate, Environment).
- **Get-ChildItem**: works across providers — `Get-ChildItem HKLM:\` for registry.
- **Registry access**: `Set-Location HKLM:\Software\...`.

**PS17 — Runspaces and parallelism**
- **[runspace]**: isolated PowerShell environment.
- **[runspacepool]**: pool of runspaces for parallel execution.
- **[powershell]**: object for invoking commands in a runspace.
- **ForEach-Object -Parallel**: simpler parallel execution (v7+).
- **Thread safety**: runspaces are not thread-safe; use synchronization.

**PS18 — PSScriptAnalyzer**
- **PSScriptAnalyzer**: static analysis tool for PowerShell.
- **Rules**: coding standards (e.g., `PSUseShouldProcessForStateChangingFunctions`).
- **Severity levels**: Error, Warning, Information.
- **Custom rules**: write as PowerShell functions.
- **Suppress**: `# PSScriptAnalyzer -Suppress` or `-ExcludeRule`.
- **CI/CD**: integrate via `Invoke-ScriptAnalyzer` in build pipelines.

**PS19 — $using: scope vs -ArgumentList**
- **$using:**: used in remote sessions, background jobs, and `ForEach-Object -Parallel` to capture variables.
- **-ArgumentList**: passes parameters to scriptblocks.
- **Serialization limits**: CLIXML depth (default 2) — complex objects may lose fidelity.
- **Effects**: large objects may be truncated or lose methods.

**PS20 — DSC**
- **DSC**: Desired State Configuration — declarative configuration.
- **Configurations**: scripts that define desired state.
- **Resources**: modules that implement configuration (e.g., `File`, `Service`).
- **LCM**: Local Configuration Manager — applies configurations.
- **PowerShell 7+**: DSC is deprecated; replaced by tools like Ansible, Terraform, or Azure Automation.
