# Networking Answers

## N1 — Easy: Layer 2 vs Layer 3 Switch
A **Layer 2 switch** operates at the data link layer (OSI Layer 2) and forwards frames based on MAC addresses. It learns MAC addresses and builds a MAC table but does not understand IP addresses or routing. A **Layer 3 switch** operates at both Layer 2 and Layer 3, capable of routing packets between VLANs (inter-VLAN routing) using IP addresses and routing protocols. It combines switching and routing, often using hardware-based routing for speed.

## N2 — Easy: Network and Broadcast Address for 10.0.5.37/20
- **Network address:** 10.0.0.0
- **Broadcast address:** 10.0.15.255

Calculation: /20 mask = 255.255.240.0. ANDing the IP with the mask gives 10.0.0.0. Setting all host bits to 1 gives 10.0.15.255.

## N3 — Medium: TCP Three-Way Handshake
1. Client sends **SYN** (with sequence number X)
2. Server responds with **SYN-ACK** (acknowledging X+1, with its own sequence number Y)
3. Client sends **ACK** (acknowledging Y+1)

**If the final ACK is lost:** The server remains in SYN-RECEIVED state and retransmits the SYN-ACK after a timeout. The client considers the connection established and may send data. If the client receives the retransmitted SYN-ACK, it sends another ACK. If not, the server eventually gives up and closes the connection.

## N4 — Medium: SNAT vs DNAT
- **SNAT (Source NAT):** Changes the source IP address of outgoing packets. Used for outbound traffic, e.g., a home router translating a private IP (192.168.1.10) to its public IP (203.0.113.1) for internet access.
- **DNAT (Destination NAT):** Changes the destination IP address of incoming packets. Used for port forwarding, e.g., forwarding traffic to port 80 on a public IP to a web server at 192.168.1.100:80.

## N5 — Medium: SSL Certificate Hostname Mismatch Causes
1. Certificate issued for a different hostname (e.g., `www.example.com` instead of `example.com`)
2. Certificate for a different domain entirely (e.g., wildcard for `*.otherdomain.com`)
3. Server presenting a default certificate for another virtual host on the same IP

## N6 — Medium: VLAN vs VxLAN
- **VLAN:** Layer 2, uses 802.1Q tagging, 12-bit VLAN ID (4096 VLANs), limited to a single broadcast domain/physical network.
- **VxLAN:** Layer 2 overlay over Layer 3, uses UDP encapsulation, 24-bit VNI (16 million segments), spans multiple data centers/clouds.

**Choose VxLAN over VLAN** when: scaling beyond 4096 segments, extending Layer 2 across data centers, supporting multi-tenant environments with overlapping IPs, or building SDN overlays.

## N7 — Hard: Asymmetric Routing with Two NICs
**Why:** The kernel uses the routing table to determine the source IP/interface for replies. Since the default route is via eth0 (10.0.0.1), replies to traffic on eth1 use eth0 unless a specific route exists for 192.168.1.0/24. The kernel's "weak host model" allows this.

**Fix with policy-based routing:**
```
ip rule add from 192.168.1.5 table 100
ip route add 192.168.1.0/24 dev eth1 table 100
ip route add default via 192.168.1.1 table 100
```
Also enable ARP filtering:
```
sysctl -w net.ipv4.conf.all.arp_filter=1
sysctl -w net.ipv4.conf.eth1.arp_filter=1
```

## N8 — Hard: BGP Path Selection Attributes (in order)
1. **Highest Local Preference** (or Weight)
2. **Shortest AS path**
3. **Origin type** (IGP < EGP < incomplete)
4. **Lowest MED** (Multi-Exit Discriminator)
5. **eBGP over iBGP**
6. **Lowest Router ID**
7. **Shortest path length**

## N9 — Hard: VxLAN over IPsec MTU Math
- VxLAN overhead: Outer IP (20) + UDP (8) + VxLAN header (8) = **36 bytes**
- IPsec overhead: ESP header (8) + trailer (2) + ICV (16) = **~26 bytes**
- Total overhead: **62 bytes**
- **Maximum inner payload:** 1500 - 62 = **1438 bytes**

## N10 — Medium: ARP and Gratuitous ARP
**ARP** maps IP addresses to MAC addresses on a local network. **Gratuitous ARP** is an unsolicited ARP broadcast that announces a host's IP-to-MAC mapping. It solves: duplicate IP detection, updating other hosts' ARP caches during failover/IP changes, and informing switches of MAC addresses for port learning.

## N11 — Easy: Public vs Private IP Addresses
- **Public IP:** Globally unique, routable on the internet.
- **Private IP:** Not routable on the internet, used within private networks.

**RFC 1918 private ranges:**
- 10.0.0.0/8 (10.0.0.0 – 10.255.255.255)
- 172.16.0.0/12 (172.16.0.0 – 172.31.255.255)
- 192.168.0.0/16 (192.168.0.0 – 192.168.255.255)

## N12 — Easy: DNS Record Types
- **A record:** Maps domain to IPv4 address (e.g., example.com → 192.0.2.1)
- **AAAA record:** Maps domain to IPv6 address (e.g., example.com → 2001:db8::1)
- **CNAME record:** Maps domain to another domain name (alias), not an IP (e.g., www.example.com → example.com)

## N13 — Easy: DHCP and DORA Process
**DHCP** automatically assigns IP addresses and network configuration. **DORA process:**
1. **Discover:** Client broadcasts DHCPDISCOVER
2. **Offer:** Server responds with DHCPOFFER
3. **Request:** Client broadcasts DHCPREQUEST
4. **Ack:** Server sends DHCPACK confirming the lease

## N14 — Easy: Hub vs Switch vs Router
- **Hub:** Layer 1 (Physical), broadcasts data to all ports
- **Switch:** Layer 2 (Data Link), forwards frames based on MAC addresses
- **Router:** Layer 3 (Network), forwards packets based on IP addresses

## N15 — Easy: Half-Duplex vs Full-Duplex
- **Half-duplex:** One direction at a time (e.g., walkie-talkie)
- **Full-duplex:** Both directions simultaneously (e.g., telephone)

**Modern Ethernet links use full-duplex** mode, requiring dedicated point-to-point connections.

## N16 — Medium: TTL and Traceroute
**TTL** limits the number of hops a packet can traverse. Each router decrements TTL by 1; when TTL reaches 0, the router discards the packet and sends an ICMP Time Exceeded message. **Traceroute** sends packets with incrementing TTL values (1, 2, 3...), causing each router to send back an ICMP Time Exceeded message, revealing its IP address and mapping the path hop by hop.

## N17 — Medium: NAT Gateway and Types
A **NAT gateway** translates private IPs to public IPs (and vice versa) for traffic crossing network boundaries.
- **Static NAT:** One-to-one mapping (private ↔ public), used for servers
- **Dynamic NAT:** Maps a pool of public IPs to a pool of private IPs, temporary
- **PAT (Port Address Translation):** Many private IPs share one public IP, distinguished by source ports (most common, e.g., home router)

## N18 — Hard: ECMP Routing
**ECMP** forwards packets to the same destination over multiple equal-cost paths, distributing traffic based on a hash of packet header fields.

**Hashing strategies:**
- 5-tuple: Source IP, dest IP, source port, dest port, protocol
- 3-tuple: Source IP, dest IP, protocol
- 2-tuple: Source IP, dest IP

**Problems with asymmetric flows:** Stateful firewalls track connection state; if packets take different paths, the firewall may see only one direction and drop the connection. Solutions include consistent hashing (e.g., 5-tuple) to ensure all packets in a flow take the same path.

## N19 — Hard: TCP Window Scaling
**Problem:** The TCP receive window is limited to 64KB (16-bit window field). With a bandwidth-delay product of 10MB, the sender can only have 64KB in flight, underutilizing the link and increasing latency due to waiting for ACKs.

**Solution:** TCP window scaling (RFC 1323) adds a scale factor (up to 2^14), allowing windows up to 1GB. This lets the sender have more data in flight, filling the pipe and reducing latency.

## N20 — Hard: 802.1Q Trunk Ports and Linux Sub-interfaces
**802.1Q trunk ports** carry traffic for multiple VLANs by adding a 4-byte VLAN tag to the Ethernet frame (TPID 0x8100, PCP, DEI, VLAN ID).

**Linux configuration:**
```
ip link add link eth0 name eth0.10 type vlan id 10
ip link add link eth0 name eth0.20 type vlan id 20
ip link add link eth0 name eth0.30 type vlan id 30
ip addr add 10.0.10.1/24 dev eth0.10
ip addr add 10.0.20.1/24 dev eth0.20
ip addr add 10.0.30.1/24 dev eth0.30
ip link set eth0 up
ip link set eth0.10 up
ip link set eth0.20 up
ip link set eth0.30 up
```

**Frame format on wire:** [Dest MAC][Src MAC][0x8100][VLAN ID][EtherType][Payload][FCS]

# Linux Answers

## L1 — Easy: Hard Link vs Symbolic Link
- **Hard link:** Direct pointer to the same inode, same inode number, cannot span filesystems, cannot link to directories. Deleting the original doesn't break the hard link.
- **Symbolic link (symlink):** Special file containing the path to the target, can span filesystems, can link to directories. Deleting the target breaks the symlink.

## L2 — Easy: Find Files Larger Than 100MB
```
find /var/log -type f -size +100M
```

## L3 — Medium: Process in State D (Uninterruptible Sleep)
State D means the process is waiting for I/O (e.g., disk/network) and cannot be interrupted. It's in a kernel-level operation. **You cannot kill it with `kill -9`** because it can't handle signals. The process exits only when the I/O completes or fails. If I/O never completes, the process may be stuck indefinitely; you may need to fix the underlying I/O issue or reboot.

## L4 — Medium: cgroups v1 vs v2
- **cgroups v1:** Separate hierarchies per subsystem, complex to manage, controllers independently mounted.
- **cgroups v2:** Single unified hierarchy for all controllers, simpler, supports delegation, better resource control.

**systemd prefers cgroups v2** because it's simpler, more consistent, supports delegation, and integrates better with systemd's resource control features.

## L5 — Medium: nftables vs iptables
- **iptables:** Traditional packet filtering using netfilter, separate tables (filter, nat, mangle, raw), rule-based match-action model.
- **nftables:** Modern replacement, single framework with simpler/flexible syntax, supports sets, maps, concatenations.

**Kernel handles both simultaneously** because they're separate subsystems using the same netfilter hooks. Both can run, but mixing them for the same functionality is not recommended.

## L6 — Medium: df Shows 100% but du Shows Less
**Most likely cause:** Deleted files still held open by processes. When a file is deleted but a process has it open, space isn't released until the process closes it. `df` includes these files; `du` only counts linked files.

Other causes: reserved blocks (ext4 reserves 5%), files hidden by mount points, sparse files.

## L7 — Hard: Linux Boot Process
1. **UEFI Firmware:** Initializes hardware, performs POST, reads UEFI boot entries, loads bootloader (e.g., GRUB) from EFI System Partition.
2. **Bootloader (GRUB):** Loads kernel and initramfs into memory, reads grub.cfg, may load filesystem modules.
3. **Kernel:** Initializes hardware, sets up memory management, starts first user-space process, loads initramfs.
4. **Initramfs:** Temporary root filesystem with essential drivers/tools, mounts the real root filesystem, runs `/init`.
5. **Root Filesystem:** Initramfs mounts the real root (e.g., /dev/sda1) and switches to it (pivot_root). Kernel runs `/sbin/init` (systemd).
6. **systemd:** Starts as PID 1, reads configuration, starts default target (e.g., multi-user.target), launches services, mounts filesystems from /etc/fstab, starts login prompt.

## L8 — Hard: Low Available Memory with High Buff/Cache
**Why available can be low:** Available memory = free + reclaimable buff/cache. If most buff/cache is not reclaimable (e.g., dirty pages needing writeback, kernel pages), available memory is low. The OOM killer fires when the kernel can't reclaim memory quickly enough.

**Kernel tunables:**
- `vm.swappiness`: Swap aggressiveness
- `vm.min_free_kbytes`: Minimum free memory
- `vm.vfs_cache_pressure`: Inode/dentry cache reclamation
- `vm.dirty_ratio` / `vm.dirty_background_ratio`: Dirty page thresholds
- `vm.overcommit_memory`: Overcommitment policy

## L9 — Medium: `ip netns` and Container Runtimes
`ip netns` manages **network namespaces**, providing isolated network stacks (interfaces, routing tables, firewall rules). Container runtimes (Docker, containerd) use network namespaces to give each container isolated networking. The runtime creates a namespace, assigns veth pairs to connect the container to the host/bridge, and configures IP addresses/routes within the namespace.

## L10 — Medium: SIGTERM vs SIGKILL vs SIGQUIT
- **SIGTERM (15):** Graceful termination request, can be caught/cleaned up. Default signal from `kill`.
- **SIGKILL (9):** Forceful termination, cannot be caught/ignored/handled. Kernel immediately kills the process.
- **SIGQUIT (3):** Similar to SIGTERM but generates a core dump, can be caught.

**SIGTERM and SIGQUIT can be caught; SIGKILL cannot.**

## L11 — Easy: stdin, stdout, stderr
- **stdin (0):** Standard input stream
- **stdout (1):** Standard output for normal program output
- **stderr (2):** Standard error for error messages

**Redirect stderr to a file while displaying stdout:**
```
command 2>error.log
```

## L12 — Easy: chmod 755
`chmod 755` sets:
- **7 (owner):** read (4) + write (2) + execute (1)
- **5 (group):** read (4) + execute (1)
- **5 (others):** read (4) + execute (1)

Owner has full access; group and others have read/execute.

## L13 — Easy: Root User vs Sudo User
- **Root user:** Superuser with full access to all resources, bypasses permissions.
- **User with sudo privileges:** Regular user granted specific root-level commands via `/etc/sudoers`, must authenticate with their own password, doesn't have full root access unless granted.

## L14 — Easy: Package Managers
A **package manager** automates installation, upgrade, configuration, and removal of software packages.
- **Debian/Ubuntu:** `apt` (with `dpkg` underlying)
- **RHEL/Fedora:** `dnf` (with `rpm` underlying)

## L15 — Easy: /etc/fstab
`/etc/fstab` defines how disk partitions/devices/filesystems are mounted at boot (device, mount point, filesystem type, options, dump, fsck order).

**If misconfigured:** System may fail to boot (critical filesystem), mount may fail, system may hang trying to mount a non-existent device. You may need recovery mode to fix it.

## L16 — Medium: LVM
**LVM** provides flexible disk space management.
- **Physical Volume (PV):** Physical disk/partition used by LVM
- **Volume Group (VG):** Collection of PVs acting as a storage pool
- **Logical Volume (LV):** Virtual disk created from the VG, mountable as a filesystem

**Extend a logical volume on a running system:**
```
pvcreate /dev/sdb
vgextend myvg /dev/sdb
lvextend -L +10G /dev/myvg/mylv
resize2fs /dev/myvg/mylv   # for ext4
xfs_growfs /dev/myvg/mylv  # for XFS
```

## L17 — Hard: I/O Schedulers
The **I/O scheduler** manages the order of I/O requests to block devices.
- **mq-deadline:** Multi-queue deadline scheduler, prevents starvation, good default for most workloads.
- **bfq (Budget Fair Queue):** Fair queuing, per-process fairness, low latency, good for interactive/desktop.
- **none:** No scheduling, device handles its own queueing, best for NVMe/high-performance devices.

**Change scheduler at runtime:**
```
echo mq-deadline > /sys/block/sda/queue/scheduler
```

## L18 — Hard: High Load Average with Low CPU
**Load average** measures processes running/waiting for CPU plus processes in uninterruptible sleep (D state). **I/O wait inflates it** because processes waiting for I/O are counted even without CPU usage.

**Diagnosis:**
- **CPU:** `top` or `mpstat` — if CPU low but load high, likely I/O
- **Disk:** `iostat` — high `%iowait` or `await` indicates disk bottleneck
- **Network:** `netstat`/`ss` for connections, `iftop`/`nload` for throughput — high usage with low CPU indicates network bottleneck

Also check `/proc/loadavg` and `/proc/stat`.

## L19 — Hard: SELinux
**SELinux** enforces mandatory access control (MAC) by labeling processes/files/resources with security contexts and using policies to define allowed interactions.

**Modes:**
- **Enforcing:** Enforces policies, denies unauthorized access
- **Permissive:** Logs violations but doesn't deny
- **Disabled:** SELinux turned off

**Troubleshoot daemon failing to bind non-standard port:**
1. Check denials: `ausearch -m avc -ts recent`
2. Check port context: `semanage port -l | grep <port>`
3. Add port to correct type: `semanage port -a -t <type> -p tcp <port>`
4. Or temporarily set permissive: `setenforce 0`

## L20 — Hard: Page Faults and THP
**Page faults** occur when a process accesses a page not in physical memory. The kernel brings the page into memory.
- **Minor fault:** Page already in memory (e.g., page cache) but not mapped; kernel updates page table entry.
- **Major fault:** Page not in memory, must be read from disk (swap/file), much slower.

**Transparent Huge Pages (THP)** uses larger pages (2MB vs 4KB) to reduce page table overhead and improve TLB hit rates, benefiting memory-intensive workloads. However, it can cause: increased memory usage, higher page fault latency, memory fragmentation.

**When to disable THP:** For latency-sensitive applications, applications with large memory footprints prone to fragmentation, or databases with their own memory management.

**Disable THP:**
```
echo never > /sys/kernel/mm/transparent_hugepage/enabled
```
