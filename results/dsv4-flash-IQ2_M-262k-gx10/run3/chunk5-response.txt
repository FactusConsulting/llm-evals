## .NET / C#

**DN1** — A `class` is a reference type (allocated on the heap, passed by reference), while a `struct` is a value type (allocated inline, passed by value). Use a `struct` for small, immutable, logically single-value data (e.g., `Point`, `Complex`), where copying is cheap and identity is not important. Avoid `struct` for large or mutable types.

**DN2** — `IEnumerable<T>` represents an in-memory sequence and uses LINQ-to-Objects; `IQueryable<T>` represents a queryable data source (e.g., a database) and builds expression trees that can be translated to SQL. The distinction matters because `IQueryable` defers execution and pushes filtering to the server, while `IEnumerable` fetches all data into memory first.

**DN3** — `async/await` allows non-blocking execution: `await` suspends the method, releasing the thread, and resumes when the task completes. `Task` is a heap-allocated reference type; `ValueTask` is a value type that avoids allocation when the result is often synchronous or hot. Use `ValueTask` for high-performance paths where the result is frequently available immediately.

**DN4** — Dependency injection lifetimes: **Transient** (new instance per resolution), **Scoped** (one instance per request/scope), **Singleton** (one instance for the app). A common bug is injecting a Scoped service (e.g., `DbContext`) into a Singleton, causing the scoped instance to be captured and reused across requests, leading to concurrency issues. Fix: resolve scoped services inside a scope (`IServiceScopeFactory`) or use `IHttpContextAccessor`.

**DN5** — `string` is immutable, heap-allocated, and UTF-16; `ReadOnlySpan<char>` is a stack-allocated view over memory, enabling slicing and processing without allocations. Use `Span<T>` for performance-critical string processing (e.g., parsing large strings, avoiding substring allocations) where memory efficiency matters.

**DN6** — The GC uses generations: **Gen 0** (short-lived), **Gen 1** (mid-lived), **Gen 2** (long-lived). The **Large Object Heap (LOH)** holds objects >85KB and is not compacted. `IDisposable` is needed for unmanaged resources (files, sockets) because the GC cannot track them; `Dispose()` provides deterministic cleanup.

**DN7** — `ConfigureAwait(false)` tells the continuation not to capture the `SynchronizationContext`, so it runs on the thread pool, avoiding deadlocks in UI/ASP.NET contexts. Use it in library code (no UI context needed); do **not** use it in UI code where you need the context to update controls. The default captures the context if one exists.

**DN8** — .NET 8/9 features: **Primary constructors** (`public class MyService(ILogger<MyService> logger)`), **collection expressions** (`int[] arr = [1,2,3];`), and **FrozenDictionary** (immutable, optimized for reads). Example with DI:
```csharp
public class MyService(ILogger<MyService> logger) {
    public void DoWork() => logger.LogInformation("Working");
}
// Registered as scoped in DI
```

**DN9** — `ObjectDisposedException` on `DbContext` under high concurrency usually means the `DbContext` is scoped but injected into a Singleton or shared across threads. EF Core's `DbContext` is designed for scoped lifetime (one per request). Fix: register `DbContext` with `AddDbContext` (scoped by default) and never inject it into Singletons; use `IServiceScopeFactory` to create scopes if needed.

**DN10** — A `record` is a reference type with value equality, built-in `ToString`, deconstruction, and `with` expressions; a `record struct` is a value type with similar features. Use `record` for immutable data models (DTOs), `class` for mutable behavior, and `record struct` for small, immutable value data.

**DN11** — `ref` passes by reference (must be initialized), `out` passes by reference (must be assigned before return), `in` passes by reference but read-only. Use `ref` to modify caller's variable, `out` for multiple return values, `in` for performance with large structs.

**DN12** — Nullable reference types (`string?`) are compile-time annotations that warn about potential nulls; nullable value types (`int?`) are `Nullable<T>` structs with runtime semantics. Reference types are checked by the compiler, value types are checked at runtime.

**DN13** — LINQ is a set of methods for querying collections. Method syntax (`list.Where(...)`) is fluent and composable; query syntax (`from x in list where ...`) is declarative. **Deferred execution** means the query is not executed until enumerated, allowing lazy evaluation and re-execution.

**DN14** — Generic constraints: `where T : class` (reference type), `where T : struct` (value type), `where T : new()` (parameterless ctor), `where T : IComparable<T>` (implements interface). Combine multiple constraints with commas, e.g., `where T : class, IComparable<T>, new()`.

**DN15** — An `abstract class` can have implementation, fields, and constructors; an `interface` is a pure contract. Default interface methods (C# 8+) allow interfaces to have implementation, blurring the distinction. Use abstract for shared base, interface for capability.

**DN16** — Middleware pipeline: `app.Use()` adds middleware, `app.Map()` branches the pipeline (e.g., `MapGet`), `app.Run()` is terminal middleware. Order matters: exception handling should be early. Use `UseExceptionHandler` for global exception handling.

**DN17** — `Channel<T>` is a modern async producer-consumer with bounded channels for backpressure; `BlockingCollection<T>` is synchronous and blocking. `Channel` is async-first and more efficient. Example:
```csharp
var channel = Channel.CreateBounded<int>(10);
await channel.Writer.WriteAsync(1);
var item = await channel.Reader.ReadAsync();
```

**DN18** — Source Generators generate code at compile time, avoiding reflection overhead. **Incremental generators** (`IIncrementalGenerator`) cache results and are faster than `ISourceGenerator`. Used for serialization, DI, and logging.

**DN19** — TPL Dataflow: `ActionBlock` (process each item), `TransformBlock` (transform), `BufferBlock` (buffer). `System.Threading.Channels` is simpler for producer-consumer; Dataflow offers more control (parallelism, completion). Use Dataflow for complex pipelines, Channels for simple backpressure.

**DN20** — Minimal APIs are lightweight, use lambdas, and have less boilerplate; controller-based APIs are structured, support attributes, and are easier to test with MVC. Minimal APIs have route groups and endpoint filters for cross-cutting concerns. Trade-offs: minimal is faster to write, controllers better for large apps.

## Python

**P1** — A `list` is mutable, a `tuple` is immutable. A `set` is mutable and unhashable, a `frozenset` is immutable and hashable.

**P2** — The GIL is a global lock in CPython that allows only one thread to execute Python bytecode at a time. It affects CPU-bound tasks (not I/O-bound). Workarounds: use `multiprocessing`, C extensions, or `asyncio` for I/O.

**P3** — `copy.copy` is shallow (copies top-level, references nested objects); `copy.deepcopy` recursively copies all objects. Shallow copy can cause unexpected behavior when nested mutable objects are shared (e.g., modifying a list inside a copied dict affects the original).

**P4** — Decorators are functions that wrap other functions. Example:
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.2f}s")
        return result
    return wrapper
```

**P5** — Generators use `yield` to produce values lazily, one at a time, saving memory. `yield from` delegates to another generator. Returning a list materializes all values at once.

**P6** — `asyncio.run()` creates an event loop, runs a coroutine, and closes it. `asyncio.gather()` runs multiple coroutines concurrently. `asyncio.create_task()` schedules a coroutine as a task. `time.sleep()` blocks the loop; use `asyncio.sleep()`.

**P7** — Python 3 uses **C3 linearization** for MRO. For diamond `D(B, C)` where B and C inherit A, MRO is `D, B, C, A, object`. `D().who()` returns `"C"` because C overrides `who` and comes before A in the MRO.

**P8** — A metaclass is a class that creates classes. `__init_subclass__` is a hook called when a subclass is created. Use a metaclass for class-level customization (e.g., registering classes); use `__init_subclass__` for simpler subclass hooks.

**P9** — `multiprocessing` uses separate processes (bypasses GIL, requires pickling), `threading` uses threads (GIL, shared memory), `concurrent.futures` provides high-level thread/process pools. Use multiprocessing for CPU-bound, threading for I/O-bound, concurrent.futures for simplicity.

**P10** — `__slots__` prevents `__dict__`, saving memory and speeding attribute access. Use it for many instances with fixed attributes.

**P11** — A virtual environment isolates Python dependencies. `venv` is built-in, `virtualenv` is third-party (more features), `conda` is a package manager + environment manager.

**P12** — List/dict/set comprehensions are concise syntax for creating collections. `map()` and `filter()` are functional alternatives. Prefer comprehensions for readability, `map`/`filter` when using existing functions.

**P13** — `==` checks equality, `is` checks identity. Object interning caches small integers (-5 to 256), so `a is b` may be `True` for small ints.

**P14** — `*args` collects positional args into a tuple, `**kwargs` collects keyword args into a dict. Positional-only `/` and keyword-only `*` markers enforce parameter passing style.

**P15** — Context managers use `with` for cleanup. Write with `__enter__`/`__exit__` or `@contextmanager`. Example: timing code:
```python
from contextlib import contextmanager
@contextmanager
def timer():
    start = time.time()
    yield
    print(f"Elapsed: {time.time()-start}")
```

**P16** — Type hinting uses annotations for static analysis. `typing.Union`, `Optional` (Union[T, None]), `Literal` (specific values), `TypeVar` (generic), `Protocol` (structural typing). Mypy/pyright use these to check types.

**P17** — Dunder methods: `__repr__` (unambiguous), `__str__` (readable), `__eq__` (equality), `__hash__` (hashable). If `__eq__` is defined without `__hash__`, `__hash__` is set to `None` (unhashable). `__getattr__` is called when attribute not found; `__getattribute__` is called for every attribute access.

**P18** — Descriptors define `__get__`, `__set__`, `__delete__`. `property` uses `__get__`/`__set__`, `classmethod` uses `__get__` to bind class, `staticmethod` uses `__get__` to return the function.

**P19** — The import system uses a **finder** to locate modules and a **loader** to load them. `sys.path` includes directories, `PYTHONPATH` adds to it. `__init__.py` marks packages; namespace packages allow split packages. Relative imports use dots, absolute use full paths.

**P20** — `dataclasses` generates `__init__`, `__repr__`, `__eq__`, etc. `attrs` is more feature-rich; `Pydantic` adds validation and serialization. `__post_init__` for post-init logic, `field(default_factory=...)` for mutable defaults, `frozen=True` for immutability. Choose Pydantic for data validation, dataclasses for simple data containers.
