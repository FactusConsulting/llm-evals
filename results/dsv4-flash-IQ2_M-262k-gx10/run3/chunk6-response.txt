# JavaScript / TypeScript (20 questions)

**JS1 — Easy: var, let, const & hoisting**

- `var`: Function-scoped, can be redeclared/reassigned, hoisted and initialized to `undefined`.
- `let`: Block-scoped, reassignable but not redeclarable, hoisted but in Temporal Dead Zone (TDZ) until declaration.
- `const`: Block-scoped, immutable binding (must be initialized), hoisted but in TDZ.
- **Hoisting**: JS moves declarations to the top of their scope during compilation. `var` initializes to `undefined`; `let`/`const` remain uninitialized (TDZ) until the declaration line executes.

**JS2 — Easy: Event loop & queues**

- **Call stack**: LIFO for synchronous execution.
- **Microtask queue**: Promises, `queueMicrotask`, `MutationObserver` — drained completely before macrotasks.
- **Macrotask queue**: `setTimeout`, `setInterval`, I/O events, UI rendering — one per event-loop iteration.
- **Order**: Execute call stack → drain all microtasks → run one macrotask → repeat.

**JS3 — Medium: Closures & for-loop bug**

- **Closure**: Function retaining access to its lexical scope even when executed outside it.
- **Example**:
  ```js
  function makeCounter() {
    let count = 0;
    return () => ++count;
  }
  ```
- **Classic bug**: `for (var i = 0; i < 5; i++) { setTimeout(() => console.log(i), 100); }` → logs `5` five times because `var` is function-scoped.
- **Fix**: Use `let` (block-scoped) or wrap in an IIFE: `for (var i = 0; i < 5; i++) { (j => setTimeout(() => console.log(j), 100))(i); }`.

**JS4 — Medium: Promises, async/await, error handling, allSettled vs all**

- **Promise**: Object representing eventual completion/failure.
- **async/await**: Syntactic sugar over promises; `await` pauses until settlement.
- **Error handling**: `.catch()` for promises; `try/catch` for async/await.
- **`Promise.all`**: Rejects immediately on first rejection (fail-fast).
- **`Promise.allSettled`**: Waits for all to settle; returns `[{status: 'fulfilled'|'rejected', value|reason}]`.

**JS5 — Medium: TypeScript interface vs type & discriminated unions**

- **`interface`**: Object shape, supports declaration merging, can be `extends`ed.
- **`type`**: More flexible — unions, tuples, primitives, mapped types, computed properties.
- **Use `interface`** for object shapes that may be extended; **`type`** for everything else.
- **Discriminated union**: Union of types sharing a common discriminant (e.g., `type: 'circle' | 'square'`) enabling type narrowing:
  ```ts
  type Shape = { kind: 'circle'; radius: number } | { kind: 'square'; side: number };
  function area(s: Shape) { if (s.kind === 'circle') return Math.PI * s.radius ** 2; }
  ```

**JS6 — Medium: Prototypal inheritance, Object.create, ES6 classes**

- **Prototypal inheritance**: Objects inherit from other objects via `[[Prototype]]` chain.
- **`Object.create(proto)`**: Creates a new object with `proto` as its prototype (can also pass property descriptors).
- **ES6 classes**: Syntactic sugar over prototypes — `class Foo extends Bar` uses the same prototype chain under the hood; `super` calls parent constructor.

**JS7 — Hard: `this` binding rules**

- **Priority order**:
  1. `new` binding (highest)
  2. Explicit binding: `call`, `apply`, `bind`
  3. Implicit binding: `obj.method()` — `this` = object
  4. Default binding: global/window (or `undefined` in strict mode)
- **`bind()`** returns a new function with `this` permanently fixed. You **cannot re-bind** a bound function — subsequent `call`/`apply`/`bind` are ignored.

**JS8 — Hard: WeakRef, FinalizationRegistry, WeakMap keys**

- **`WeakRef`**: Holds a weak reference to an object; allows GC. Use for caches/maps that shouldn't prevent collection.
- **`FinalizationRegistry`**: Registers callbacks invoked when objects are GC'd (e.g., cleanup resources).
- **WeakMap keys must be objects** because keys are held weakly — if keys were primitives, they couldn't be tracked for GC. When the key object is collected, the entry is removed.

**JS9 — Hard: V8 optimization**

- **Hidden classes**: V8 assigns internal class structures to objects based on property order/shape to optimize property access.
- **Inline caching**: Caches property lookups based on hidden class to avoid repeated dictionary lookups.
- **Deoptimization**: When assumptions break (e.g., adding new properties, changing shapes), V8 falls back to slow paths.
- **Patterns causing deoptimization**: Adding properties after object creation, inconsistent object shapes, `delete obj.prop`, changing function parameter types dynamically, using `arguments` object.

**JS10 — Medium: Tree-shaking**

- **Tree-shaking**: Dead-code elimination during bundling — removes unused exports.
- **ES modules**: Static `import`/`export` allow bundlers to statically analyze usage at build time.
- **CommonJS**: Dynamic `require()` makes static analysis unreliable; bundlers can't know what's used, so tree-shaking is ineffective.

**JS11 — Easy: null vs undefined, == vs ===, ?? and ?.**

- **`null`**: Explicitly assigned "no value" (typeof `object`).
- **`undefined`**: Default for uninitialized variables.
- **`==`**: `null == undefined` → `true`; **`===`**: `false`.
- **`??` (nullish coalescing)**: Returns right side only if left is `null`/`undefined`.
- **`?.` (optional chaining)**: Short-circuits if property access is `null`/`undefined`.

**JS12 — Easy: map, filter, reduce, flatMap**

- **`map()`**: Transforms each element → new array.
- **`filter()`**: Returns elements passing a predicate.
- **`reduce()`**: Accumulates values; initial value is the first argument to the accumulator:
  ```js
  [1,2,3].reduce((acc, n) => acc + n, 0); // 6
  ```
- **`flatMap()`**: Maps then flattens one level — useful for nested arrays (e.g., `[1,2].flatMap(x => [x, x*2])` → `[1,2,2,4]`).

**JS13 — Easy: Template literals & tagged templates**

- **Template literals**: Backtick strings with `${}` interpolation and multi-line support.
- **Tagged templates**: Function receives string parts and interpolated values:
  ```js
  function escapeHTML(strings, ...values) {
    return strings.reduce((acc, str, i) => {
      const val = values[i - 1] || '';
      return acc + str + String(val).replace(/[&<>"']/g, m => ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[m]));
    }, '');
  }
  const userInput = '<script>';
  escapeHTML`<p>${userInput}</p>`; // "<p>&lt;script&gt;</p>"
  ```

**JS14 — Easy: Destructuring & rest**

- **Object**: `const { a, b } = obj;`
- **Array**: `const [x, y] = arr;`
- **Default values**: `const { a = 1 } = obj;`
- **Renaming**: `const { a: newName } = obj;`
- **Rest**: `const { a, ...rest } = obj;` — collects remaining properties; `const [head, ...tail] = arr;` for arrays.

**JS15 — Easy: for...in vs for...of**

- **`for...in`**: Iterates over enumerable property **keys** (including inherited).
- **`for...of`**: Iterates over **values** of iterables (arrays, strings, Maps, Sets).
- **Avoid `for...in` on arrays**: Includes inherited properties, order not guaranteed, and includes array methods if extended.

**JS16 — Medium: TypeScript generics, constraints, conditional types, infer**

- **Generics**: `function identity<T>(x: T): T { return x; }`
- **Constraints**: `function f<T extends Lengthwise>(x: T): number { return x.length; }`
- **Conditional types**: `type IsArray<T> = T extends any[] ? true : false;`
- **`infer`**: Extract types: `type ElementType<T> = T extends (infer U)[] ? U : never;` — used in `ReturnType`, `Parameters`, etc.

**JS17 — Medium: Module systems**

- **CommonJS**: Synchronous, `require`/`module.exports`, Node.js default.
- **ES Modules**: Static, `import`/`export`, browser & modern Node.
- **Node.js**: Supports both — `.mjs` extension or `"type": "module"` in `package.json` for ESM; `.cjs` for CommonJS.
- **`"type": "module"`**: Makes `.js` files in the package treated as ES modules.

**JS18 — Hard: Structural typing, excess property checks, extends vs satisfies, variance**

- **Structural typing**: Types compatible based on shape, not name.
- **Excess property checks**: Applied only to **object literals** assigned to variables — extra properties cause errors (not for variables/type assertions).
- **`extends`**: Type-level constraint (e.g., generic constraint).
- **`satisfies`**: Value-level check that preserves the inferred type (TS 4.9+):
  ```ts
  const config = { port: 3000 } satisfies Record<string, unknown>;
  ```
- **Variance (TS 4.7+)**: `in` (contravariant) for inputs, `out` (covariant) for outputs; explicit annotations via `interface Foo<in T>` / `out T`.

**JS19 — Hard: Proxy & Reflect**

- **`Proxy`**: Wraps an object to intercept operations via handler traps (`get`, `set`, `apply`, `has`, `deleteProperty`, etc.).
- **`Reflect`**: Provides default behavior methods (`Reflect.get`, `Reflect.set`, etc.).
- **Example** (validation):
  ```js
  const user = { age: 25 };
  const proxy = new Proxy(user, {
    set(target, prop, value) {
      if (prop === 'age' && (value < 0 || value > 150)) throw new Error('Invalid age');
      return Reflect.set(target, prop, value);
    }
  });
  proxy.age = 30; // OK
  proxy.age = -1; // throws
  ```

**JS20 — Hard: SharedArrayBuffer, Atomics, Web Workers**

- **`SharedArrayBuffer`**: Shared memory between workers (same origin).
- **`Atomics`**: Provides atomic operations (`add`, `load`, `store`, `exchange`, `compareExchange`) on shared memory.
- **Communication**: Workers share a `SharedArrayBuffer`; use `Atomics` for synchronization (e.g., producer-consumer).
- **Ordering**: Operations are atomic but not sequentially consistent unless using memory barriers (`Atomics` with proper semantics).
- **`Atomics.wait`**: Blocks a thread until notified (only in workers); **`Atomics.notify`**: Wakes waiting threads.

# Bash (20 questions)

**B1 — Easy: $@ vs $* and "$@" vs "$*"**

- **Unquoted**: `$@` and `$*` behave the same — each positional parameter undergoes word splitting.
- **`"$@"`**: Each parameter is quoted separately — preserves spaces within each argument.
- **`"$*"`**: All parameters joined into a single string separated by the first character of `IFS` (usually space).

**B2 — Easy: `set -euo pipefail`**

- **`-e`**: Exit immediately if a command returns non-zero.
- **`-u`**: Treat unset variables as an error (with `bash` expansion).
- **`-o pipefail`**: Pipeline returns the last non-zero exit status (not just the last command).

**B3 — Medium: $(command) vs `command`; $((expression)) vs expr**

- **`$(command)`** and `` `command` ``: Both are command substitution, but `$()` is preferred — easier nesting, better escaping, no backtick parsing issues.
- **`$((expression))`**: Arithmetic expansion — integer math, faster, built-in.
- **`expr`**: External command — slower, requires escaping (`expr 1 + 1`), less robust.

**B4 — Medium: Process substitution**

- **`<(command)`**: Treats command output as a file descriptor (e.g., `/dev/fd/N`).
- **Use case**: Compare outputs without temp files:
  ```bash
  diff <(sort file1) <(sort file2)
  ```
- Also useful for feeding multiple commands into a single stdin.

**B5 — Medium: Safe file iteration**

- **Safe pattern**:
  ```bash
  find . -type f -print0 | while IFS= read -r -d '' file; do
    echo "Processing: $file"
  done
  ```
  Or use globbing: `for f in *; do ...; done` (handles spaces correctly).
- **`for f in $(ls)` is dangerous**: Word splitting breaks filenames with spaces; glob expansion may also misfire.

**B6 — Medium: Here documents vs here strings**

- **Here document** (`<<EOF`): Feeds multi-line input to a command:
  ```bash
  cat <<EOF
  Hello
  World
  EOF
  ```
- **Here string** (`<<<`): Feeds a single string with trailing newline: `grep pattern <<< "$var"`.
- **`<<-EOF`**: Allows leading tabs in the document (stripped), enabling indented code.

**B7 — Hard: Redirection order**

```bash
cmd > file 2>&1   # stdout → file, then stderr → stdout (both to file)
cmd 2>&1 > file   # stderr → current stdout (terminal), then stdout → file (stderr goes to terminal)
cmd &> file       # both stdout and stderr → file (bash-specific)
```
- **Why different**: Redirections are processed left-to-right. In `2>&1 > file`, stderr is duplicated to the *current* stdout (terminal) *before* stdout is redirected to file. In `> file 2>&1`, stdout is redirected first, so stderr follows to file.

**B8 — Hard: Safe lock file with cleanup**

```bash
lock() {
    local lockdir="/tmp/mylock.$$"
    while ! mkdir "$lockdir" 2>/dev/null; do
        sleep 0.1
    done
    trap 'rmdir "$lockdir"' EXIT INT TERM
}
```
- **Why `mkdir` over file creation**: `mkdir` is atomic — only one process can succeed. File creation with `touch` + check has a race window (TOCTOU). `mkdir` also works on NFS (with some caveats).

**B9 — Easy: Quote differences**

- **Single quotes** (`'...'`): No expansion — `echo '$HOME'` → `$HOME`.
- **Double quotes** (`"..."`): Variable expansion, command substitution, but no word splitting — `echo "$HOME"` → `/home/user`.
- **No quotes**: Word splitting + glob expansion — `echo $HOME` → `/home/user` (but splits if spaces).

**B10 — Easy: File checks & test syntax**

- **Checks**: `-e file` (exists), `-d file` (directory), `-r file` (readable), `-f file` (regular file).
- **`[ ]`**: POSIX `test` — external command, word splitting applies.
- **`[[ ]]`**: Bash builtin — more features (pattern matching, `&&`/`||`, no word splitting), preferred in scripts.

**B11 — Easy: $?, $$, $!, $#**

- **`$?`**: Exit status of last command — check success/failure.
- **`$$`**: PID of current shell — used in temp file names.
- **`$!`**: PID of last background job — `kill $!` to stop it.
- **`$#`**: Number of positional parameters — validate argument count.

**B12 — Easy: Functions**

- **Definition**: `foo() { ... }` (POSIX) vs `function foo { ... }` (bash-specific). Both work; `foo()` is portable.
- **Return values**: `return` sets exit status; `echo` outputs data (captured via `$(foo)`).
- **Example**:
  ```bash
  greet() { echo "Hello, $1"; }
  name=$(greet "World")
  ```

**B13 — Easy: PATH, command resolution, builtins vs external**

- **`PATH`**: Colon-separated directories for command lookup.
- **Resolution**: Bash checks builtins first, then `PATH` (unless `enable -n` or `command`).
- **Builtin**: Built into shell (e.g., `cd`, `echo`); **external**: separate binary (e.g., `ls`, `grep`).
- **Check**: `type -t cmd` → `builtin`, `alias`, `file`, etc.; `which cmd` for external path.

**B14 — Medium: trap**

- **Setup**: `trap 'cleanup' EXIT` (runs on script exit), `trap 'handle_err' ERR` (on error), `trap 'handle_int' INT`, `trap 'handle_term' TERM`.
- **Multiple signals**: Bash processes one signal at a time; handlers run in order received. `EXIT` trap runs after all others.
- **Example**:
  ```bash
  trap 'rm -f "$tmpfile"' EXIT
  trap 'echo "Interrupted"; exit 1' INT TERM
  ```

**B15 — Medium: xargs vs command substitution; -0; -P**

- **`xargs`**: Reads stdin and builds commands — handles large inputs, parallel execution.
- **Command substitution**: Captures output as a string — can hit ARG_MAX limits.
- **`find -print0 | xargs -0`**: Null-delimited filenames — safe for spaces/newlines.
- **`xargs -P`**: Runs multiple processes in parallel (e.g., `xargs -P 4 -I {} cmd {}`).

**B16 — Medium: Arrays & associative arrays**

- **Indexed arrays**: `arr=(a b c)`; append `arr+=(d)`; iterate `for i in "${arr[@]}"`; length `${#arr[@]}`.
- **Associative arrays**: `declare -A map`; `map[key]=value`; iterate `for k in "${!map[@]}"`; length `${#map[@]}`.
- **Differences**: Associative arrays require `declare -A`, keys are strings, no numeric indexing.

**B17 — Hard: Subshell vs group; pipe variable loss**

- **Subshell `(...)`**: Runs in child process — variable changes don't propagate to parent.
- **Group `{ ...; }`**: Runs in current shell — variables persist.
- **Pipe loss**: Pipes create subshells, so `while` loop changes are lost:
  ```bash
  echo -e "a\nb" | while read line; do count=$((count+1)); done; echo $count; # 0
  ```
  Fix: Use `while ... done < <(cmd)` (process substitution) or `{ ...; }` with redirection.

**B18 — Hard: Signals & job control**

- **SIGINT**: Interrupt (Ctrl+C) — catchable.
- **SIGTERM**: Termination request — catchable, preferred for graceful shutdown.
- **SIGHUP**: Hangup (terminal closed) — catchable.
- **SIGKILL**: Kill — uncatchable, immediate.
- **Graceful shutdown**:
  ```bash
  trap 'kill $pid1 $pid2; wait; exit 0' TERM INT
  ```

**B19 — Hard: Parallel log processing**

```bash
#!/bin/bash
split -l 1000 log.txt chunk_
process() {
    local file="$1"
    grep -c "error" "$file" > "$file.count"
}
export -f process
find . -name "chunk_*" -print0 | xargs -0 -P 4 -I {} bash -c 'process {}'
cat *.count | awk '{s+=$1} END {print s}'
rm chunk_* *.count
```
- **Trade-offs**: Parallel speedup vs. overhead of splitting/merging; `xargs -P` limits concurrency.
- **Error propagation**: `xargs` returns non-zero if any job fails; use `-P` with `--max-args` and check exit codes.

**B20 — Hard: exec, FD manipulation, coprocesses**

- **`exec`**: Replaces the current shell process (no return) or manipulates FDs.
- **FD manipulation**: `exec 3>file` (open FD 3 for writing), `exec 3>&-` (close FD 3), `exec 3<&0` (duplicate stdin).
- **Coprocess**: `coproc cmd` — runs command in background with FDs for bidirectional communication:
  ```bash
  coproc myproc { cat; }
  echo "hello" >&"${myproc[1]}"
  read -u "${myproc[0]}" response
  ```
- **Use case**: Interactive processes (e.g., a server or REPL) needing bidirectional communication.

# PowerShell (20 questions)

**PS1 — Easy: Write-Output vs Write-Host**

- **`Write-Output`**: Writes to the output stream (pipeline) — objects can be piped, captured, or redirected.
- **`Write-Host`**: Writes to the host (console) — not part of the pipeline, cannot be captured.
- **Why it matters**: `Write-Host` output disappears in scripts; `Write-Output` feeds the pipeline.

**PS2 — Easy: Pipeline, ForEach-Object vs foreach**

- **Pipeline**: Passes objects between commands (streaming).
- **`ForEach-Object`**: Cmdlet that processes each pipeline object — memory-efficient for large data.
- **`foreach` statement**: Faster (no pipeline overhead) but requires collecting all objects first.
- **Use `ForEach-Object`** for streaming; **`foreach`** for small collections or when you need the full collection.

**PS3 — Medium: [PSCustomObject] vs [hashtable]**

- **`[hashtable]`**: Key-value pairs, unordered, mutable, used for lookups/parameters.
- **`[PSCustomObject]`**: Structured object with properties, ordered (via `[ordered]`), used for output.
- **Convert**: `[PSCustomObject]$hashtable` (PS3+) or `$obj | ConvertTo-Hashtable` (PS7+).

**PS4 — Medium: Error handling**

- **Terminating errors**: Stop execution (e.g., `throw`, `Write-Error -ErrorAction Stop`).
- **Non-terminating errors**: Continue but record error (e.g., `Write-Error` default).
- **`-ErrorAction`**: Per-command override (`Stop`, `Continue`, `SilentlyContinue`, etc.).
- **`$ErrorActionPreference`**: Default for all commands.
- **`try/catch`**: Catches terminating errors; `finally` for cleanup.

**PS5 — Medium: Splatting**

- **Splatting**: `@params` expands a hashtable into named parameters:
  ```powershell
  $params = @{ Path = 'file.txt'; Verbose = $true }
  Get-Content @params
  ```
- **Difference**: Passing a hashtable directly (`Get-Content $params`) passes it as a single object, not expanded.

**PS6 — Medium: Remoting**

- **`Invoke-Command -ComputerName`**: Runs commands on remote machines (one-off).
- **`Enter-PSSession`**: Interactive session.
- **Protocol**: WinRM (WS-Man) by default; SSH in PS 7+.
- **Related**: WinRM is Microsoft's implementation of WS-Management; SSH remoting uses OpenSSH.

**PS7 — Hard: Pipeline unrolling & type behavior**

```powershell
function Get-Items {
    $result = @()
    $result += "one"
    return $result
}
$x = Get-Items
$x.GetType().Name  # "String" — not "Object[]"
```
- **Why**: PowerShell unrolls single-item collections — `$x` becomes the string `"one"`.
- **0 items**: `$x` is `$null` (empty array unrolls to `$null`).
- **Correct pattern**: `return ,$result` (comma operator) or `Write-Output -NoEnumerate $result`.

**PS8 — Hard: Scriptblocks vs functions; double-hop**

- **Scriptblock**: Anonymous code block `{ ... }`; **function**: named with parameters.
- **Pass to remote**: `Invoke-Command -ScriptBlock { ... } -ComputerName PC`.
- **Double-hop**: Credentials don't propagate to a second remote hop.
- **Solutions**: CredSSP (delegates credentials) or `Invoke-Command -ArgumentList` with explicit credentials.

**PS9 — Easy: @() vs [array]; indexing**

- **`@()`**: Array subexpression — wraps results in an array.
- **`[array]`**: Type accelerator — casts to array.
- **Force array**: `@($result)` or `Write-Output -NoEnumerate`.
- **Indexing**: `$null[0]` → `$null` (no error); `@()[0]` → error (index out of bounds).

**PS10 — Easy: Comparison operators**

- **`-eq`/`-ne`**: Equality; **`-like`/`-notlike`**: Wildcard; **`-match`/`-notmatch`**: Regex.
- **Case-sensitive**: `-ceq`, `-clike`, `-cmatch`, etc.
- **`-contains`**: Checks if a collection contains a value: `$arr -contains 'x'`.
- **`-in`**: Checks if a value is in a collection: `'x' -in $arr` (PS3+).

**PS11 — Easy: Modules**

- **Module**: Package of functions/cmdlets/variables.
- **Script module** (`.psm1`): PowerShell code.
- **Manifest module** (`.psd1`): Metadata (version, dependencies, author).
- **Binary module** (`.dll`): Compiled C# code.
- **`Import-Module`**: Loads module into session; `Get-Module` lists loaded modules.

**PS12 — Easy: String interpolation**

- **`"..."`**: Interpolates variables (`$var`) and expressions (`$(1+2)`).
- **`'...'`**: Literal strings — no interpolation.
- **Here-string** (`@"..."@`): Multi-line strings with interpolation; `@'...'@` for literal.

**PS13 — Easy: Get-Member & object exploration**

- **`Get-Member`**: Shows object members (properties, methods).
- **Properties**: Data; **Methods**: Actions; **NoteProperties**: Added properties (e.g., from `Add-Member`).
- **`Select-Object`**: Chooses/renames properties; **`Where-Object`**: Filters objects by criteria.

**PS14 — Medium: PowerShell classes**

- **Classes** (v5+): `class Foo { [int]$Prop; Foo() {} [void]Method() {} }`.
- **Differences from C#**: No interfaces (until PS7), no multiple inheritance, dynamic type system, no access modifiers (all public).
- **Limitations**: Constructors limited, no explicit interfaces (PS5), no abstract classes (until PS7).
- **Use classes** for complex stateful objects; **functions** for simple operations.

**PS15 — Medium: CmdletBinding & advanced functions**

- **`[CmdletBinding()]`**: Makes function behave like a cmdlet — adds `-Verbose`, `-Debug`, `-ErrorAction`, parameter validation.
- **`SupportsShouldProcess`**: Enables `-WhatIf`/`-Confirm`.
- **`DefaultParameterSetName`**: Specifies default parameter set.
- **`ValueFromPipeline`**: Accepts pipeline input.
- **Blocks**: `Begin` (setup), `Process` (per-object), `End` (cleanup).

**PS16 — Medium: Providers**

- **Providers**: Expose data stores as drives (FileSystem, Registry, Certificate, Environment).
- **`Get-ChildItem`** works on any provider drive.
- **Registry**: `Get-ChildItem HKCU:\Software` — navigate like filesystem; `Set-ItemProperty` to modify.

**PS17 — Hard: Runspaces & parallelism**

- **`[runspace]`**: Execution environment; **`[runspacepool]`**: Pool of runspaces; **`[powershell]`**: Command to execute.
- **`ForEach-Object -Parallel`** (v7+): Simple parallel execution:
  ```powershell
  1..10 | ForEach-Object -Parallel { $_ * 2 } -ThrottleLimit 4
  ```
- **Manual runspaces**: More control (threads, synchronization) but complex.

**PS18 — Hard: PSScriptAnalyzer**

- **PSScriptAnalyzer**: Static analysis tool for PowerShell.
- **Rules**: Checks for best practices (e.g., uninitialized variables, cmdlet naming).
- **Severity levels**: Error, Warning, Information.
- **Custom rules**: Extend via modules.
- **Suppress**: `#Requires -Version 5` or `[Diagnostics.CodeAnalysis.SuppressMessage]`.
- **CI/CD**: Run `Invoke-ScriptAnalyzer -Path . -Recurse` in build pipeline.

**PS19 — Hard: $using: scope vs -ArgumentList; serialization**

- **`$using:`**: Captures variable values in remote/parallel contexts:
  ```powershell
  $x = 5
  Invoke-Command -ScriptBlock { $using:x } -ComputerName PC
  ```
- **`$args`/`-ArgumentList`**: Passes parameters explicitly.
- **CLIXML serialization**: Depth limit (default 2 in PS5, 5 in PS7) — complex objects may lose fidelity (e.g., methods, types).

**PS20 — Hard: Desired State Configuration (DSC)**

- **DSC**: Declarative configuration management.
- **Configurations**: Declarative scripts (`Configuration` keyword).
- **Resources**: Implementations (e.g., `File`, `Service`, `Package`).
- **LCM**: Local Configuration Manager — applies configs, reports compliance.
- **Windows PowerShell vs PS7+**: Windows PowerShell uses WMI/COM; PS7+ uses DSC v2 (pull/push, cross-platform).
- **Modern replacement**: Tools like Ansible, Terraform, Azure Automation, or Pulumi for infrastructure-as-code.
