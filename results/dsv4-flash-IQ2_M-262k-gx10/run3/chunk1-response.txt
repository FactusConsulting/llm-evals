## Networking (20 questions)

### N1 — Layer 2 vs Layer 3 switch
A **Layer 2 switch** operates at the Data Link layer (OSI Layer 2). It forwards frames based on MAC addresses, maintains a MAC address table, and does not understand IP addresses or routing. It simply learns MAC addresses and forwards frames to the correct port or floods unknown destinations.

A **Layer 3 switch** operates at the Network layer (OSI Layer 3). It can route packets between VLANs/subnets based on IP addresses, has built-in routing functionality, and can perform inter-VLAN routing without requiring an external router. It combines switching and routing in one device, often using hardware-based routing for performance.

### N2 — Network and broadcast address for 10.0.5.37/20
- **Subnet mask**: /20 = 255.255.240.0
- **Network address**: 10.0.0.0
- **Broadcast address**: 10.0.15.255

The /20 mask covers 20 bits for the network portion. The third octet (240) means the network uses 4 bits for the network and 4 bits for the host. 10.0.5.37 falls in the 10.0.0.0/20 range (which spans 10.0.0.0 through 10.0.15.255).

### N3 — TCP three-way handshake and lost final ACK
The three-way handshake:
1. Client sends **SYN** (with sequence number X)
2. Server responds with **SYN-ACK** (acknowledging X+1, with its own sequence number Y)
3. Client sends **ACK** (acknowledging Y+1)

If the final ACK is lost:
- The server has established the connection (it received SYN and sent SYN-ACK), but the client hasn't confirmed.
- The server will retransmit the SYN-ACK until it receives the ACK or times out (typically ~30 seconds).
- The client may retransmit the ACK if it doesn't receive data from the server.
- The connection is in a **half-open state** from the server's perspective. The server considers the connection established, but the client may not have fully established it. Data can still flow, but the server may eventually time out and reset the connection if the ACK never arrives.

### N4 — SNAT vs DNAT
**SNAT (Source NAT)**: Changes the source IP address of outgoing packets. Used for internet sharing, where private IPs are translated to a public IP for outbound traffic. Example: A home router translates 192.168.1.10 (private) to 203.0.113.5 (public) when a device accesses the internet.

**DNAT (Destination NAT)**: Changes the destination IP address of incoming packets. Used for port forwarding. Example: A router receives traffic on public IP 203.0.113.5:80 and forwards it to internal server 192.168.1.10:80.

### N5 — SSL certificate name mismatch causes
1. **Wrong hostname in URL**: The certificate was issued for `www.example.com` but you accessed `example.com` (or vice versa).
2. **Certificate for a different domain**: The certificate was issued for a completely different domain (e.g., `wrongdomain.com` instead of `example.com`).
3. **Using IP address instead of hostname**: The certificate has a CN/SAN for the hostname, but you accessed the site via IP address (e.g., `https://203.0.113.5`).

### N6 — VLAN vs VxLAN
**VLAN**:
- Layer 2 segmentation, uses 12-bit VLAN ID (max 4096 VLANs)
- Limited to a single Layer 2 domain
- Traditional for campus networks and small data centers
- Uses 802.1Q tagging on Ethernet frames

**VxLAN**:
- Layer 2 overlay over Layer 3 (UDP encapsulation)
- Uses 24-bit VNI (up to 16 million segments)
- Encapsulates Ethernet frames in UDP/IP (port 4789)
- Designed for data centers with multi-tenant environments and large-scale virtualization

**Choose VxLAN over VLAN when**:
- You need more than 4096 segments
- You need to extend Layer 2 across Layer 3 boundaries (e.g., across data center fabrics)
- You're building a cloud/virtualized environment with multi-tenancy
- You need to span multiple physical locations

### N7 — Asymmetric routing with two NICs
**Problem**: Linux uses a single routing table (the `main` table) with a default route via eth0 (10.0.0.1). When traffic arrives on eth1 (192.168.1.5), the kernel looks up the destination address in the routing table. Since the destination is 192.168.1.0/24, the kernel checks for a route to that subnet. If there's no specific route for 192.168.1.0/24 in the main table, it falls back to the default route via eth0, causing replies to go out eth0.

**Fix with policy-based routing**:
1. Create a separate routing table for eth1's subnet:
   ```bash
   ip route add 192.168.1.0/24 dev eth1 table 100
   ip route add default via 192.168.1.1 table 100
   ```
2. Add a policy rule to use table 100 for traffic from eth1:
   ```bash
   ip rule add from 192.168.1.0/24 lookup 100
   ```
3. Enable reverse path filtering (rp_filter) to prevent spoofing:
   ```bash
   sysctl -w net.ipv4.conf.all.rp_filter=2
   ```

### N8 — BGP path selection
BGP selects the best path in this order:
1. **Highest weight** (locally configured, Cisco-specific)
2. **Highest local preference** (local to the router, used for outbound traffic)
3. **Prefer locally originated routes** (routes originated by the local router)
4. **Shortest AS path** (fewest AS hops)
5. **Lowest origin type** (IGP < EGP < incomplete)
6. **Lowest MED** (multi-exit discriminator, used for inbound traffic)
7. **Prefer eBGP over iBGP**
8. **Lowest IGP metric to next hop**
9. **Longest match** (more specific prefix)
10. **Oldest route** (for eBGP)
11. **Lowest router ID** (or originator ID)

### N9 — MTU implications of VxLAN over IPsec
Physical MTU: 1500 bytes

Overhead breakdown:
- **IPsec overhead**: ~50-60 bytes (ESP header 8 + IV 8-24 + padding + auth trailer)
- **VxLAN overhead**: 50 bytes (outer Ethernet 14 + outer IP 20 + UDP 8 + VXLAN header 8)

Total overhead: ~100-110 bytes

**Maximum inner payload**: 1500 - 100-110 = **~1390-1400 bytes**

More precisely: 1500 - 50 (IPsec) - 50 (VxLAN) = **1400 bytes** (assuming ~50 bytes IPsec overhead). This means the inner Ethernet frame's MTU must be reduced to ~1400 bytes, and the inner IP payload to ~1386 bytes.

### N10 — ARP and Gratuitous ARP
**ARP (Address Resolution Protocol)**: Resolves IP addresses to MAC addresses on a local network. When a host needs to send a packet to another host on the same subnet, it broadcasts an ARP request asking "who has IP X?" and the owner responds with its MAC address.

**Gratuitous ARP**: An ARP announcement sent without being prompted by an ARP request. It solves:
- **Duplicate IP detection**: A host announces its IP to check if another host already uses it.
- **MAC address changes**: When a host's MAC changes (e.g., failover, VM migration), it sends a gratuitous ARP to update all other hosts' ARP caches.
- **Announcing a new IP**: When a host acquires a new IP address, it announces it to the network.

### N11 — Public vs Private IP addresses
**Public IP**: Globally routable, assigned by IANA/RIRs, used on the internet. Unique worldwide.

**Private IP**: Not routable on the internet, used within private networks. Must be translated by NAT to access the internet.

**RFC 1918 private ranges**:
- 10.0.0.0/8 (10.0.0.0 – 10.255.255.255)
- 172.16.0.0/12 (172.16.0.0 – 172.31.255.255)
- 192.168.0.0/16 (192.168.0.0 – 192.168.255.255)

### N12 — DNS and record types
**DNS (Domain Name System)**: Translates human-readable domain names to IP addresses.

- **A record**: Maps a hostname to an IPv4 address (e.g., `example.com → 93.184.216.34`)
- **AAAA record**: Maps a hostname to an IPv6 address (e.g., `example.com → 2606:2800:220:1:248:1893:25c8:1946`)
- **CNAME record**: An alias that points to another hostname (canonical name). E.g., `www.example.com → example.com`. CNAMEs cannot point to IP addresses directly.

### N13 — DHCP and DORA
**DHCP (Dynamic Host Configuration Protocol)**: Automatically assigns IP addresses, subnet masks, gateways, DNS servers, and other network configuration to clients.

**DORA process**:
1. **Discover**: Client broadcasts `DHCPDISCOVER` to find available DHCP servers.
2. **Offer**: Server responds with `DHCPOFFER` containing an available IP and configuration.
3. **Request**: Client broadcasts `DHCPREQUEST` to accept the offer.
4. **Ack**: Server sends `DHCPACK` confirming the lease.

### N14 — Hub, Switch, Router
- **Hub**: Operates at **Layer 1 (Physical)**. Broadcasts all data to all ports, no intelligence, no filtering. All devices share the same collision domain.
- **Switch**: Operates at **Layer 2 (Data Link)**. Forwards frames based on MAC addresses, maintains a MAC address table, isolates collision domains per port.
- **Router**: Operates at **Layer 3 (Network)**. Routes packets based on IP addresses, connects different networks, determines the best path.

### N15 — Half-duplex vs Full-duplex
- **Half-duplex**: Communication in one direction at a time. Only one device can transmit at a time (e.g., walkie-talkie). Uses CSMA/CD for collision detection.
- **Full-duplex**: Communication in both directions simultaneously. Both devices can transmit and receive at the same time (e.g., telephone). No collisions.
- **Modern Ethernet** uses **full-duplex** with auto-negotiation. Full-duplex requires no collision detection and doubles throughput.

### N16 — TTL field and traceroute
**TTL (Time to Live)**: Limits how many hops a packet can traverse. Each router decrements TTL by 1. When TTL reaches 0, the router drops the packet and sends an ICMP Time Exceeded message back to the source.

**Traceroute exploits TTL**:
1. Sends packets with TTL=1. The first router decrements to 0, drops the packet, and sends ICMP Time Exceeded, revealing its IP.
2. Sends packets with TTL=2. The second router drops them, revealing its IP.
3. Continues incrementing TTL until the destination is reached or max hops is hit.

This maps the network path hop by hop.

### N17 — NAT gateway
**NAT gateway**: Translates private IP addresses to public IP addresses for internet access. It maintains a translation table to map internal addresses to external addresses.

- **Static NAT**: One-to-one mapping, permanent. Used for servers that need consistent public IPs (e.g., web servers).
- **Dynamic NAT**: Maps private IPs to a pool of public IPs, temporary. When a private host initiates traffic, it grabs an available public IP from the pool.
- **PAT (Port Address Translation)**: Many private IPs to one public IP, differentiated by port numbers. Also called NAT overload. Most common for home/small office internet sharing.

### N18 — ECMP routing
**ECMP (Equal-Cost Multi-Path)**: Routes traffic across multiple paths that have equal metric/cost. The router distributes flows across multiple next hops.

**Hashing strategies**:
- Hash on source IP only
- Hash on destination IP only
- Hash on source + destination IP
- Hash on 5-tuple (source IP, destination IP, source port, destination port, protocol)

**Problems with asymmetric flows**:
- If forward traffic takes path A and return traffic takes path B, **stateful firewalls** may drop packets because they only see one direction of the flow.
- This breaks NAT, firewall state tracking, and any stateful inspection.
- Solutions: Ensure symmetric hashing (same hash for both directions), use consistent hashing, or use stateless load balancing.

### N19 — TCP window scaling
**Problem**: The TCP window size field is 16 bits, maxing out at 64KB. With a bandwidth-delay product of 10MB, the sender can only transmit 64KB before waiting for ACKs. This severely underutilizes the link, causing high latency and low throughput.

**Solution (RFC 1323 window scaling)**:
- Adds a **window scale factor** (shift count) to the TCP header options.
- The window field is multiplied by 2^scale factor.
- This allows windows up to 1GB (scale factor of 14).
- The sender can fill the pipe by transmitting enough data to cover the bandwidth-delay product.

### N20 — 802.1Q trunk ports and Linux sub-interfaces
**802.1Q trunk ports**: A single physical link carries multiple VLANs by tagging frames with VLAN IDs. The trunk port adds a 4-byte 802.1Q tag to each frame.

**Linux configuration for VLANs 10, 20, 30**:
```bash
# Load 8021q module
modprobe 8021q

# Create sub-interfaces
ip link add link eth0 name eth0.10 type vlan id 10
ip link add link eth0 name eth0.20 type vlan id 20
ip link add link eth0 name eth0.30 type vlan id 30

# Assign IPs and bring up
ip addr add 10.0.10.1/24 dev eth0.10
ip addr add 10.0.20.1/24 dev eth0.20
ip addr add 10.0.30.1/24 dev eth0.30
ip link set eth0.10 up
ip link set eth0.20 up
ip link set eth0.30 up
```

**Frame format on the wire**:
```
[Destination MAC (6)] [Source MAC (6)] [802.1Q Tag (4)] [EtherType (2)] [Payload]
```
The 802.1Q tag contains:
- TPID (0x8100) — 2 bytes
- TCI (Tag Control Info) — 2 bytes: 3-bit priority, 1-bit CFI/DEI, 12-bit VLAN ID

## Linux (20 questions)

### L1 — Hard link vs symbolic link
**Hard link**: A direct pointer to the same inode. Multiple hard links share the same inode number. Cannot cross filesystems, cannot link directories. Deleting the original doesn't break the link (the inode remains until all links are removed).

**Symbolic link (symlink)**: A file that contains the path to the target. Can cross filesystems, can link directories. If the target is deleted, the symlink becomes broken (dangling).

### L2 — Find files larger than 100MB under /var/log
```bash
find /var/log -type f -size +100M
```

### L3 — Process in D state (uninterruptible sleep)
**D state** means the process is in **uninterruptible sleep**, typically waiting for I/O (usually disk). The process is blocked in a kernel operation (e.g., disk read/write) and cannot be interrupted by signals.

**Can you kill it with kill -9?** No. The kernel cannot deliver signals to a process in D state because the process is blocked in kernel space. The process will only exit when the I/O operation completes or fails. If the I/O never completes (e.g., a stuck NFS mount), the process may remain in D state indefinitely.

### L4 — cgroups v1 vs v2
**cgroups v1**:
- Hierarchical, but each controller (CPU, memory, I/O) has its own hierarchy.
- Multiple hierarchies can exist simultaneously.
- Complex and inconsistent.

**cgroups v2**:
- Unified hierarchy — all controllers in a single hierarchy.
- Cleaner design, supports delegation to unprivileged processes.
- Better resource management and accounting.

**systemd prefers cgroups v2** because it's simpler, more consistent, and provides better support for resource management and delegation. Modern distributions default to cgroups v2.

### L5 — nftables vs iptables
**nftables**: Modern replacement for iptables. Uses a single framework with a simpler, more consistent syntax. Better performance, supports more features (e.g., sets, maps, concatenations).

**iptables**: Legacy packet filtering framework. Uses separate tables (filter, nat, mangle, raw), each with chains. More complex and verbose.

**Kernel handling**: nftables and iptables are **separate subsystems** in the kernel. They can coexist, but you shouldn't use both for the same rules. The kernel has separate hooks for each. nftables uses the `nf_tables` module, while iptables uses `ip_tables`/`ip6_tables`. Both can be loaded simultaneously, but they operate independently.

### L6 — df shows 100% but du shows less
**Most likely cause**: **Deleted files still held open by processes**. When a file is deleted but a process still has it open, the space isn't released until the process closes the file. `df` shows the filesystem as full, but `du` doesn't see the deleted files.

**Diagnosis**: Use `lsof +L1` to find files that are deleted but still open.

### L7 — Linux boot process
1. **UEFI firmware**: Initializes hardware, reads EFI variables, loads the bootloader (e.g., GRUB) from the EFI System Partition.
2. **Bootloader (GRUB)**: Loads the kernel and initramfs into memory, passes control to the kernel.
3. **Kernel**: Initializes hardware, decompresses itself, mounts the initramfs as a temporary root filesystem.
4. **Initramfs**: Contains minimal drivers and tools. Loads necessary kernel modules (e.g., storage drivers), mounts the real root filesystem.
5. **Root filesystem**: Kernel switches to the real root (pivot_root), runs `/sbin/init` (systemd).
6. **systemd**: Starts the default target (`multi-user.target` or `graphical.target`), launches services, mounts filesystems from `/etc/fstab`.

### L8 — OOM killer with high buff/cache
**Why available can be low even with high buff/cache**:
- `available` = `free` + reclaimable `buff/cache`. If buff/cache is mostly **dirty pages** (not yet written to disk) or **unreclaimable** (e.g., pages pinned by processes), it doesn't count as available.
- The OOM killer fires when the kernel determines there's insufficient available memory for new allocations.

**Kernel tunables that affect this**:
- `vm.swappiness`: Controls how aggressively the kernel swaps anonymous pages vs cache.
- `vm.vfs_cache_pressure`: Controls how aggressively the kernel reclaims inode/dentry cache.
- `vm.min_free_kbytes`: Minimum free memory the kernel tries to maintain.
- `vm.overcommit_memory`: Controls memory overcommit policy.

### L9 — ip netns
**`ip netns`** creates and manages **network namespaces** — isolated network stacks with their own interfaces, routing tables, firewall rules, and socket addresses.

**Used by container runtimes**: Docker, containerd, and other container runtimes use network namespaces to give each container its own isolated network stack. The runtime creates a new netns for each container, assigns virtual interfaces (veth pairs), and configures routing/NAT within that namespace.

### L10 — SIGTERM, SIGKILL, SIGQUIT
- **SIGTERM** (15): Termination signal. Can be caught/handled. Allows the process to clean up and exit gracefully.
- **SIGKILL** (9): Kill signal. **Cannot be caught, ignored, or handled**. Immediately terminates the process. The kernel forcibly kills the process.
- **SIGQUIT** (3): Similar to SIGTERM but also generates a **core dump**. Can be caught/handled.

**Which can be caught**: SIGTERM and SIGQUIT can be caught. SIGKILL cannot.

### L11 — stdout, stderr, stdin
- **stdin** (fd 0): Standard input — where the program reads input.
- **stdout** (fd 1): Standard output — where the program writes normal output.
- **stderr** (fd 2): Standard error — where the program writes error messages.

**Redirect stderr to a file while displaying stdout on terminal**:
```bash
command 2>error.log
```
This sends stderr to `error.log` while stdout still goes to the terminal.

### L12 — chmod 755
**755** sets permissions:
- **Owner**: rwx (7 = read + write + execute)
- **Group**: r-x (5 = read + execute)
- **Others**: r-x (5 = read + execute)

Each digit represents:
- 4 = read
- 2 = write
- 1 = execute
- 7 = 4+2+1 (rwx)
- 5 = 4+1 (r-x)

### L13 — Root vs sudo user
**Root user**: UID 0, has full access to everything. Can read/write any file, change any configuration, bypass all permissions.

**User with sudo privileges**: A regular user (UID > 0) that has been granted sudo access. They can run commands as root using `sudo`, but only for commands they're authorized to run (per `/etc/sudoers`). They don't have root's full access unless granted.

### L14 — Package manager
**Package manager**: A tool for installing, updating, and removing software packages, resolving dependencies, and managing repositories.

- **Debian/Ubuntu**: `apt` (Advanced Package Tool), with `dpkg` as the underlying package format tool.
- **RHEL/Fedora**: `dnf` (formerly `yum`), with `rpm` as the underlying package format tool.

### L15 — /etc/fstab
**`/etc/fstab`** (File System Table) defines how filesystems are mounted at boot. Each entry specifies: device, mount point, filesystem type, options, dump flag, fsck order.

**If an entry is misconfigured**:
- The system may fail to boot (if the filesystem is critical).
- The filesystem may not mount, or may mount with wrong options.
- If the entry is for a non-critical filesystem, boot may continue but the filesystem won't be available.
- A wrong device name or UUID can cause the mount to fail.

### L16 — LVM
**LVM (Logical Volume Manager)**: Provides flexible storage management by abstracting physical storage into logical volumes.

- **Physical Volumes (PV)**: Physical disks or partitions (e.g., `/dev/sda1`).
- **Volume Groups (VG)**: A pool of physical volumes (e.g., `vg0`).
- **Logical Volumes (LV)**: Virtual partitions carved from the VG (e.g., `/dev/vg0/lv_root`).

**Extend a logical volume on a running system**:
```bash
# Extend the LV
lvextend -L +10G /dev/vg0/lv_root

# Resize the filesystem (ext4)
resize2fs /dev/vg0/lv_root
# Or for XFS
xfs_growfs /dev/vg0/lv_root
```

### L17 — I/O schedulers
**mq-deadline**: Multi-queue deadline scheduler. Balances latency and throughput. Provides per-request deadlines to prevent starvation. Good for SSDs and general-purpose workloads.

**bfq (Budget Fair Queuing)**: Provides fairness and low latency. Each process gets a budget of I/O. Good for desktops, interactive workloads, and systems with mixed workloads.

**none**: No scheduling. Passes requests directly to the device. Best for NVMe SSDs with high parallelism and their own internal scheduling.

**Change at runtime**:
```bash
echo bfq > /sys/block/sda/queue/scheduler
```

### L18 — High load average with low CPU
**Load average** measures the number of processes in **running** or **uninterruptible (D state)** state. I/O wait inflates it because processes waiting for I/O are counted as active.

**Why I/O wait inflates load**: When processes block on disk I/O, they enter D state and are counted in the load average, even though they're not consuming CPU.

**Diagnosis**:
- `iostat -x 1`: Shows disk utilization, I/O wait, and queue lengths.
- `vmstat 1`: Shows CPU usage, run queue, and I/O wait.
- `top` / `htop`: Shows D-state processes and CPU usage.
- `sar -d 1`: Historical disk activity.
- `netstat` / `ss`: Network connections and throughput.

### L19 — SELinux
**SELinux (Security-Enhanced Linux)**: Implements **Mandatory Access Control (MAC)** using policies. Every process and file has a security context (label). The kernel enforces policy rules that define which subjects can access which objects.

**Modes**:
- **Enforcing**: Policy is enforced, denials are logged.
- **Permissive**: Policy is not enforced, but denials are logged (for troubleshooting).
- **Disabled**: SELinux is turned off entirely.

**Troubleshoot a daemon failing to bind a non-standard port**:
1. Check `/var/log/audit/audit.log` for denials:
   ```bash
   ausearch -m avc -ts recent
   ```
2. Use `sealert` to get human-readable explanations:
   ```bash
   sealert -l /var/log/audit/audit.log
   ```
3. Add the port to the SELinux policy:
   ```bash
   semanage port -a -t http_port_t -p tcp 8080
   ```

### L20 — Page faults and THP
**Page fault**: Occurs when a process accesses memory that isn't in its working set (not mapped to the process).

- **Minor fault**: The page is already in memory (e.g., shared pages) but not mapped to the process. Fast, no disk I/O.
- **Major fault**: The page must be read from disk (swap or file). Slow, involves disk I/O.

**THP (Transparent Huge Pages)**: Uses 2MB pages instead of 4KB pages. Reduces TLB misses and improves performance for large memory workloads. However, it can cause:
- Higher latency for memory allocation (due to page compaction)
- Memory fragmentation
- Issues for databases and real-time systems

**When to disable THP**: For applications with high memory allocation/deallocation patterns, databases (e.g., Oracle, MongoDB), or real-time systems where latency spikes are unacceptable. Disable via:
```bash
echo never > /sys/kernel/mm/transparent_hugepage/enabled
```
