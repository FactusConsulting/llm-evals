
**Go**

**G1** – An array has a fixed size that is part of its type (`[N]T`). A slice is a descriptor (`ptr, len, cap`) that references an underlying array; its length can change. When `append` exceeds the slice’s capacity, Go allocates a new, larger backing array (typically doubling), copies the old elements, and returns a slice pointing to the new array.

**G2** – `var x int` declares a variable at package or function scope and zero‑initializes it. `x := 0` is a short variable declaration, usable only inside a function; it cannot be used at package level, cannot redeclare the same variable in the same block, and cannot be used for struct fields or map elements.

**G3** – A goroutine is a lightweight user‑space thread managed by the Go runtime. An OS thread is scheduled by the kernel. The GMP model: **G**oroutine (runnable unit), **M**achine (OS thread), **P**rocessor (local runqueue and resources). The scheduler assigns Gs to Ms via Ps, pre‑emptively switching when a G blocks or after a time slice.

**G4** – A channel mediates communication and synchronization. An unbuffered channel blocks the sender until a receiver is ready (and vice‑versa). A buffered channel holds up to its capacity values; sending to a full buffered channel blocks until space is freed, receiving from an empty buffered channel blocks until a value is available.

**G5** – `context` propagates cancellation, deadlines, and request‑scoped values. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, err := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
if err != nil { log.Fatal(err) }
resp, err := http.DefaultClient.Do(req)
// handle resp or err
```

**G6** – Interface satisfaction is implicit: any type that implements all methods of an interface satisfies it, no `implements` keyword needed. Unlike Java/C# where implementation must be declared. `interface{}` (or `any` in Go 1.18) holds any value; it’s powerful for generic containers but loses compile‑time type safety, requiring type assertions or type switches.

**G7** – Without synchronization, the write to `data` may not be visible to the reader due to reordering or CPU caches → a data race. Correct patterns:
```go
var ready chan struct{}
var data string
go func() {
    data = "hello"
    close(ready) // signal
}()
<-ready
fmt.Println(data)
```
or use `sync.Mutex`/`sync.WaitGroup` or atomic.Bool.

**G8** – `sync.Mutex` grants exclusive access. `sync.RWMutex` allows many concurrent readers or a single writer. Use RWMutex when reads vastly outnumber writes. `sync.Map` provides a lock‑free‑ish map optimized for many reads and occasional writes (append‑only or cache‑like); it has higher per‑operation overhead than a plain map+mutex but scales better under high read contention on many cores.

**G9** – A Go module is a collection of packages versioned together. `go.mod` declares the module path and its dependencies (with minimum versions). `go.sum` contains cryptographic checksums of exact module versions to guarantee integrity. `go mod tidy` adds missing dependencies, removes unused ones, and ensures `go.mod`/`go.sum` reflect the actual build list. Minimum Version Selection (MVS) picks the *lowest* versions of each dependency that satisfy all version constraints, avoiding diamond‑problem upgrades.

**G10** – `defer` schedules a function call to run after the surrounding function returns. Multiple defers execute in LIFO order. Gotcha: a `defer` inside a loop is executed only after the function ends, so resources (e.g., file handles) accumulate; fix by wrapping the loop body in another function or calling a helper that does the defer inside each iteration.

**G11** – A pointer holds the memory address of a variable. Its zero value is `nil`. Create a pointer to a struct literal with `&MyStruct{Field: value}`.

**G12** – `init()` runs after all imported packages are initialized and before `main.main` (or test main). A package may have many `init` functions; they run in the order they appear within each file, and files are processed in lexical order (typically alphabetical) as presented to the Go tool.

**G13** – `make` creates slices, maps, and channels and returns an initialized value (not a pointer). `new(T)` allocates zeroed storage for type `T` and returns a `*T`. `make` works only with the three built‑in reference types; `new` works with any type.

**G14** – The `error` interface is `type error interface { Error() string }`. Idiomatic check:
```go
if err != nil {
    return err // or wrap/log
}
```
`errors.Is(err, target)` walks the error chain (via `Unwrap`) to see if `target` is present. `errors.As(err, &target)` extracts the error into a concrete type if it matches. Both are preferable to `==` which only matches the exact error value.

**G15** – Built‑in composite types: array, slice, map, channel, struct (also function and interface). Zero values: array → each element zero; slice → `nil`; map → `nil`; channel → `nil`; struct → each field zero‑valued.

**G16** – A race occurs when two goroutines access the same variable with at least one write, without synchronization. Example:
```go
var counter int
go func(){ counter++ }()
go func(){ counter++ }()
time.Sleep(time.Second)
fmt.Println(counter) // may be 1 or 2
```
Fix with a mutex:
```go
var mu sync.Mutex
go func(){ mu.Lock(); counter++; mu.Unlock() }()
// same for second goroutine
```
or use a channel to serialize updates.

**G17** – `select` blocks until one of its case communications can proceed, then executes that case (pseudo‑random if multiple are ready). Unlike `switch`, cases are channel ops. Timeout pattern:
```go
select {
case res := <-ch:
    // use res
case <-time.After(500 * time.Millisecond):
    fmt.Println("timeout")
}
```

**G18** – Escape analysis decides whether a variable can live on the stack or must be moved to the heap based on whether its address escapes the function (e.g., returned, stored in a global, or sent on a channel). Inspect with `go build -gcflags=-m`. Stack allocation avoids GC pressure and is faster; heap allocation incurs GC overhead.

**G19** – `reflect.Type` describes a type; `reflect.Value` holds a value of that type. Reflection is slow due to indirection, inability to inline, and runtime type checks. It’s justified for generic libraries (`encoding/json`, `fmt`) where compile‑time generics aren’t enough; otherwise prefer code generation (`go generate`) or interfaces.

**G20** – `//go:embed` tells the compiler to include files or directories in the binary. Examples:
```go
//go:embed hello.txt
var hello string

//go:embed assets/*
var assets embed.FS
```
Limitations: requires Go 1.16+, only readable via `embed.FS` (implements `io/fs.FS`), cannot embed files >2 GB without custom handling, and the embedded data is read‑only. The resulting `embed.FS` can be used wherever an `io/fs.FS` is expected (e.g., `http.FS`).

**Rust**

**R1** – Ownership rules: (1) Each value has a single owner. (2) When the owner goes out of scope, the value is dropped. (3) Only one mutable reference **or** any number of immutable references may exist at a time, and references must not outlive the data they point to.

**R2** – `String` owns a heap‑allocated, growable UTF‑8 buffer. `&str` is a borrowed string slice (view) into existing UTF‑8 data. Use `String` when you need ownership or mutation; use `&str` for read‑only parameters or when you just need a view.

**R3** – Borrowing: `&T` (shared) allows many readers; `&mut T` (exclusive mutable) allows one writer. The borrow checker enforces that you cannot have a `&mut T` coexist with any `&T`, and that all references are valid for the lifetime of the data.

**R4** – `Result<T, E>` encodes success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` encodes presence (`Some(T)`) or absence (`None`). The `?` operator propagates errors or unwraps `Option`s, returning early on `Err`/`None`. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let mut f = std::fs::File::open(path)?;
    let mut s = String::new();
    f.read_to_string(&mut s)?;
    Ok(s)
}
```

**R5** – `Box<T>`: unique ownership of a heap allocation. `Rc<T>`: reference‑counted pointer for shared ownership **within a single thread**. `Arc<T>`: atomically reference‑counted, safe for sharing across threads. Use `Box` for exclusive ownership, `Rc` for cheap shared read‑only (or with interior mutability) in one thread, `Arc` when you need thread‑shared ownership.

**R6** – Traits define shared behavior (methods, associated types). Like Go interfaces but can have default implementations and associated types. A trait object `dyn Trait` erases the concrete type and uses a vtable (dynamic dispatch). A generic `T: Trait` is monomorphized (static dispatch), producing a copy per concrete type, usually faster but larger binary.

**R7** – The function lacks lifetime parameters, so the compiler cannot guarantee the returned reference lives long enough. Fix by tying the output lifetime to the inputs:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** – `Send`: safe to transfer ownership of a type across threads. `Sync`: safe to share `&T` between threads (i.e., `T` is `Sync` if `&T` is `Send`). `Rc` uses non‑atomic reference counts, so it isn’t `Send`/`Sync`. `Arc` uses atomic increments/decrements, making it both `Send` and `Sync`.

**R9** – An `async fn` returns a type that implements `Future`. A `Future` is a state machine whose `poll` method advances it toward completion; it yields when waiting on an I/O operation. An executor (e.g., Tokio’s runtime) repeatedly polls futures until they resolve. Unlike Go’s goroutines, which are managed by a built‑in scheduler and are stackful, Rust futures are stackless and require an external executor to drive them.

**R10** – In `unsafe` you can: (1) dereference raw pointers (`*const T`, `*mut T`); (2) call unsafe functions or methods (including FFI); (3) implement unsafe traits (e.g., `Send`, `Sync` manually); (4) access or modify mutable statics; (5) read/write fields of unions. Use `unsafe` when you have verified safety (e.g., interfacing with C, writing lock‑free data structures, or performing performance‑critical checks that the compiler cannot prove).

**R11** – Pattern matching lets you destructure values. `match` is exhaustive; the compiler forces you to handle every variant (or use `_`). `if let` matches a single pattern and is shorthand for `match` with one arm; it does **not** require exhaustiveness.

**R12** – `Vec<T>` is a growable, heap‑allocated buffer with length and capacity. `[T; N]` is a fixed‑size array stored inline (stack or wherever the variable lives). When `Vec::push` exceeds capacity, the vector allocates a new buffer (commonly doubling size), copies existing elements, and frees the old buffer.

**R13** – Enums are algebraic data types that can hold data in each variant, unlike C/Java enums which are just integer constants. `Option<T>` is defined as `enum Option<T> { Some(T), None }`. By making the absence case explicit, Rust eliminates null pointers; you must handle `None` explicitly.

**R14** – An `impl block` defines methods for a type. `&self` → read‑only borrow, `&mut self` → mutable borrow, `self` → takes ownership (move). Associated functions have no receiver (e.g., `String::new()`) and act like constructors or namespaced functions.

**R15** – `derive` macro auto‑generates trait implementations. Commonly derived: `Debug`, `Clone`, `PartialEq`, `Eq`, `Hash`, `Serialize` (via `serde`). You cannot derive traits that require custom logic (e.g., `Display`, `From`, `Drop`) or traits with associated types/generic constraints that the derive mechanism doesn’t support.

**R16** – `Cow<'a, T>` (Clone‑On‑Write) is `enum Cow<'a, T> { Borrowed(&'a T), Owned(T) }`. It lets an API accept either borrowed or owned data without cloning unless mutation is needed. Example:
```rust
fn shout(s: Cow<'_, str>) -> Cow<'_, str> {
    if s.contains('a') {
        Cow::Owned(s.to_uppercase())
    } else {
        s
    }
}
```
If the input is already owned and needs mutation, we clone; if it’s a borrow and no change, we avoid allocation.

**R17** – Module system: `mod` declares a module; `use` brings names into scope; `pub` controls visibility. The file system mirrors the module tree: `src/main.rs` or `src/lib.rs` is the crate root; a module `foo` can be `src/foo.rs` or `src/foo/mod.rs`. The 2018 edition simplified paths (`crate::`, `super::`), removed the need for `extern crate`, and made `pub(restricted)` etc. available.

**R18** – `Pin<T>` guarantees that the value pointed to will not be moved in memory after being pinned. This is essential for self‑referential structs (e.g., async futures that store pointers to their own fields) because moving would invalidate those internal pointers. `Unpin` is a marker trait indicating a type does not rely on pinning safety; types that implement `Unpin` can be moved even when wrapped in `Pin`.

**R19** – Rust macros: declarative (`macro_rules!`) match token trees and produce code; procedural macros (custom `derive`, attribute, function‑like) receive a `TokenStream`, parse it, and return a new `TokenStream`. Both macro systems obey hygiene: identifiers introduced inside a macro cannot accidentally capture or clash with identifiers from the surrounding code unless explicitly exported.

**R20** – Zero‑cost abstractions mean high‑level constructs compile to code with no runtime overhead compared to hand‑written C. Iterators are lazy and compile to tight loops via inlining. Generics are monomorphized, producing a concrete copy per type (no virtual dispatch). Trait objects use dynamic dispatch only when needed; otherwise static dispatch via monomorphization gives direct calls. Thus you get ergonomic syntax without sacrificing performance.
