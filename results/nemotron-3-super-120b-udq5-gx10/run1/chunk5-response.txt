
**DN1** – A `class` is a reference type allocated on the heap; a `struct` is a value type allocated inline (stack or containing object). Use a struct for small, immutable data that behaves like a primitive (e.g., `Point`, `DateTime`) to avoid heap allocation and indirection. Avoid structs when they need inheritance, polymorphic behavior, or large size (> ~16 bytes) because copying can be costly.

**DN2** – `IEnumerable<T>` represents a forward‑only, pull‑based sequence; LINQ to Objects enumerates it in‑process. `IQueryable<T>` builds an expression tree that can be translated to another query language (e.g., SQL). The distinction matters because `IQueryable` lets the provider (EF Core) apply filters on the database side, reducing data transfer; using `IEnumerable` after a query forces client‑side evaluation.

**DN3** – `async/await` compiles the method into a state machine that yields control when awaiting an incomplete `Task`. When the awaited task completes, the continuation resumes on the captured `SynchronizationContext` (unless `ConfigureAwait(false)`). `Task` is a reference type representing a promise; `ValueTask` is a struct that can wrap either a `Task` or a successful result, avoiding allocation when the operation completes synchronously. Use `ValueTask` for high‑throughput APIs where synchronous completion is common (e.g., buffered reads, in‑memory caches).

**DN4** – Dependency Injection (DI) registers services with lifetimes: **Transient** (new instance each request), **Scoped** (single instance per logical scope – e.g., per HTTP request), **Singleton** (single instance for the app lifetime). Injecting a scoped service into a singleton is a common bug because the singleton holds a reference to a scoped instance created on the first request and reuses it across subsequent requests, leading to state leakage or disposed‑object errors.

**DN5** – `string` is an immutable heap‑allocated reference type; `ReadOnlySpan<char>` is a stack‑only view over contiguous memory (string, char[], stackalloc, etc.) without allocation. Use `Span<T>`/`ReadOnlySpan<T>` for high‑performance slicing, parsing, or buffering where you need to avoid temporary string allocations (e.g., tokenizers, network parsers).

**DN6** – .NET GC is a generational, tracing collector. Objects start in Gen 0; survivors are promoted to Gen 1 then Gen 2. Gen 0 collections are frequent and cheap; Gen 2 occurs less often. The Large Object Heap (LOH) holds objects ≥ 85 KB (arrays, large strings) and is collected only during Gen 2. `IDisposable` provides deterministic release of unmanaged resources (file handles, sockets) that the GC cannot finalize promptly; it lets callers free resources via `using` or `Dispose()`.

**DN7** – By default, `await` captures the current `SynchronizationContext` (or `TaskScheduler`) and resumes the continuation on it. `ConfigureAwait(false)` tells the awaiter not to capture the context, allowing continuation on a thread‑pool thread. Use `ConfigureAwait(false)` in library code to avoid deadlocks and unnecessary context switches; do **not** use it in UI/ASP.NET core code that relies on the captured context (e.g., accessing `HttpContext` after an await).

**DN8** – .NET 8/9:  
- Primary constructors let you declare constructor parameters directly in the class/record signature; they become fields/properties.  
- Collection expressions (`[1, 2, 3]`) create arrays/lists/spans with a concise syntax.  
- `FrozenDictionary<TKey,TValue>` is an immutable, hash‑based dictionary optimized for read‑only lookups.  

Minimal DI example with primary constructor:
```csharp
public class WeatherService(IHttpClientFactory http) : IWeatherService
{
    private readonly IHttpClientFactory _http = http;
    public async Task<string> GetForecastAsync(string city)
    {
        var client = _http.CreateClient();
        return await client.GetStringAsync($"https://api.weather.com/{city}");
    }
}
```
Registered as `builder.Services.AddScoped<IWeatherService, WeatherService>();`

**DN9** – Under high concurrency, a singleton or scoped `DbContext` is being disposed while another request still uses it. Likely cause: registering `DbContext` as **Singleton** (or capturing it in a singleton service) instead of **Scoped**. EF Core’s `DbContext` is not thread‑safe and should match the HTTP request scope. Fix: register with `AddDbContext<AppDbContext>(options => …)` (default is Scoped) and ensure no singleton holds a direct reference; use `IDbContextFactory<AppDbContext>` if you need to create contexts inside a singleton.

**DN10** – `record` is a reference type with value‑based equality, immutable properties (by default), and built‑in `With` support. `class` is reference type with reference equality unless overridden. `record struct` is a value‑type record (immutable struct with value equality). Choose `record` when you need immutable data objects with reference semantics (e.g., DTOs). Choose `record struct` for small immutable data where you want value semantics without heap allocation. Use plain `class` when you need mutability, inheritance, or reference identity.

**DN11** – `ref` passes a variable by reference; the called method can read and write the caller’s variable. `out` is like `ref` but the caller does not need to initialize the variable before the call; the method must assign a value before returning. `in` passes by reference but is read‑only; the caller guarantees the argument won’t be modified, allowing the compiler to avoid copying large structs. Use `ref` for mutable updates, `out` for try‑pattern returns, `in` for large struct inputs where you want to avoid copying.

**DN12** – Nullable reference types (`string?`) are a compile‑time annotation; the runtime still treats them as normal references, but the compiler warns when you might dereference null. Nullable value types (`int?`) are actually `Nullable<T>` structs with a `HasValue` flag. The `?` syntax works for both, but the underlying mechanics differ: reference nullability is a compiler feature; value nullability is a real type.

**DN13** – LINQ (Language Integrated Query) provides query operators over `IEnumerable<T>`/`IQueryable<T>`. Method syntax chains extension methods (`list.Where(x=>x>0)`). Query syntax (`from x in list where x>0 select x`) is syntactic sugar that translates to method calls. Both use deferred execution: the query is not evaluated until you enumerate the result (e.g., `foreach` or `ToList()`), allowing composition.

**DN14** – Generic constraints limit type arguments:  
- `where T : class` – T must be a reference type.  
- `where T : struct` – T must be a non‑nullable value type.  
- `where T : new()` – T must have a parameterless constructor (often used with factories).  
- `where T : IComparable<T>` – T must support comparison.  
Combine constraints (e.g., `where T : struct, IComparable<T>`) when you need both a value type and comparability.

**DN15** – An `abstract class` can contain state, constructors, and mixed abstract/concrete members; a class can inherit only one base. An `interface` defines a contract; a class can implement many interfaces. C# 8 added default interface methods, letting interfaces provide implementation, narrowing the gap: you can now add behavior to interfaces without breaking implementers, but interfaces still cannot have instance fields or constructors.

**DN16** – ASP.NET Core middleware pipeline processes requests via delegates. `app.Use()` inserts a middleware that can call `next()` to continue the pipeline (both before and after). `app.Run()` terminates the pipeline (no further middleware). `app.Map()` branches the pipeline based on path, creating a sub‑pipeline. Order matters: earlier middleware sees the request first; exception handling middleware (`UseExceptionHandler`, `UseDeveloperExceptionPage`) should be registered early to catch exceptions from later components.

**DN17** – `Channel<T>` is an async‑awaitable, producer‑consumer queue supporting bounded/unbounded capacities, single/multiple readers/writers, and completion signaling. Compared to `BlockingCollection<T>` (which blocks threads), `Channel` avoids thread‑pool threads waiting and integrates naturally with async code. Example bounded channel for back‑pressure:
```csharp
var channel = Channel.CreateBounded<int>(new BoundedChannelOptions(100)
{
    FullMode = BoundedChannelFullMode.Wait
});

// Producer
await channel.Writer.WriteAsync(value);

// Consumer
while (await channel.Reader.WaitToReadAsync())
{
    while (channel.Reader.TryRead(out var item))
    {
        Process(item);
    }
}
```

**DN18** – Source Generators run during compilation, inspecting syntax and emitting additional C# source files that are compiled into the assembly. Unlike reflection (runtime inspection) or IL weaving (post‑compile IL modification), they work at compile time, giving zero runtime overhead and better tooling. An `ISourceGenerator` runs for each compilation; an `IncrementalGenerator` (introduced in .NET 5) allows the generator to cache inputs and only re‑run when relevant parts change, improving build performance.

**DN19** – TPL Dataflow provides in‑process message‑passing blocks. `ActionBlock<T>` executes an action for each message. `TransformBlock<TInput,TOutput>` transforms messages and outputs them. `BufferBlock<T>` simply buffers messages. Blocks can be linked to form pipelines with built‑in back‑pressure and support for degree of parallelism. Compared to `System.Threading.Channels`, Dataflow offers richer block types and built‑in linking, while Channels is lower‑level, higher‑performance, and more suited for custom async pipelines.

**DN20** – Minimal APIs let you define endpoints directly on `WebApplication` with lambda expressions, reducing boilerplate. They differ from controller‑based APIs by lacking explicit classes, attribute routing, and model binding infrastructure; however, they still support dependency injection, filters, and OpenAPI generation via `AddEndpointsApiExplorer`. Trade‑offs: Minimal APIs are great for microservices and simple services; controllers provide better organization, versioning, and testability for large apps. Route groups (`app.MapGroup("/api/v1")`) share prefixes and middleware; endpoint filters (`AddEndpointFilter`) let you cross‑cut concerns (validation, logging) similar to middleware but scoped to endpoints.

**P1** – `list` is mutable, ordered, allows duplicates; `tuple` is immutable, ordered, fixed size. `set` is mutable, unordered, hash‑based, no duplicates; `frozenset` is immutable version of a set (hashable, usable as dict key or set element).

**P2** – The GIL is a mutex protecting Python object internals, allowing only one thread to execute Python bytecode at a time. It limits CPU‑bound multithreaded workloads (pure Python loops). Workarounds: use multiprocessing, C extensions that release the GIL (NumPy, I/O), or alternative implementations (Jython, IronPython, PySTM) that lack a GIL.

**P3** – `copy.copy()` makes a shallow copy: top‑level object duplicated, but nested objects are references. `copy.deepcopy()` recursively copies all nested objects. Example:
```python
a = [[1, 2], [3, 4]]
b = copy.copy(a)
b[0][0] = 99   # a becomes [[99, 2], [3, 4]] because inner list shared
```
Deep copy avoids this by duplicating inner lists.

**P4** – Decorator that logs execution time:
```python
import time, functools
def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        end = time.perf_counter()
        print(f"{func.__name__} took {end-start:.4f}s")
        return result
    return wrapper
```
Use `@timer` above any function.

**P5** – Generators produce items lazily via `yield`, preserving state between calls. Returning a list builds the whole collection in memory up front. `yield from` delegates to another generator or iterable, flattening iteration. Example:
```python
def gen():
    yield from range(3)
    yield from "ab"
```
Yields 0,1,2,'a','b'.

**P6** – `asyncio.run()` creates a new event loop, runs the supplied coroutine, and closes the loop. `asyncio.gather()` awaits multiple coroutines concurrently, returning results in order. `asyncio.create_task()` schedules a coroutine to run on the current loop and returns a `Task` object. `time.sleep()` blocks the thread; inside an async function you must use `await asyncio.sleep()` to yield control.

**P7** – Python 3 uses C3 linearization for MRO. For the hierarchy:
- MRO of D: D → B → C → A → object.
`D().who()` looks up `who` in D (none), then B (none), then C (found) → returns `"C"`.

**P8** – A metaclass (`type` subclass) controls class creation (`__new__`, `__init__`). Use `__init_subclass__` for simple per‑subclass customization without a metaclass (e.g., auto‑registering subclasses). Practical metaclass use: enforce coding standards or add class‑level properties (e.g., ORM declarative base). `__init_subclass__` use: automatically register plugin classes in a registry.

**P9** – `threading`: OS threads, share memory, GIL limits CPU parallelism. Good for I/O‑bound work. `multiprocessing`: separate processes, each with its own GIL and memory; data must be pickled to transfer between processes. Use for CPU‑bound parallelism. `concurrent.futures`: high‑level API wrapping threads (`ThreadPoolExecutor`) or processes (`ProcessPoolExecutor`). Serialization implication: multiprocessing requires objects to be picklable; complex objects (e.g., open file handles, lambdas) may fail.

**P10** – `__slots__` declares a fixed set of attributes, replacing the per‑instance `__dict__` with a tuple‑like storage. Prevents accidental attribute creation and reduces memory overhead (often ~50% less per instance). Use when you have many instances of a simple class and need memory efficiency; avoid when you need dynamic attributes or multiple inheritance with conflicting slots.

**P11** – A virtual environment isolates package installations from the system Python. `venv` is built‑in (Python 3.3+). `virtualenv` is an older third‑party tool with extra features (e.g., custom Python interpreters). `conda` is a language‑agnostic environment manager that also handles non‑Python packages and binary dependencies. Use any to avoid version conflicts; `venv` suffices for most pure‑Python projects.

**P12** – List/set/dict comprehensions build collections in a single readable expression, applying an optional filter. They are often clearer than `map()`/`filter()` with lambda. Prefer comprehensions for simple transformations; use `map`/`filter` when you already have a function and want lazy iteration (in Python 3 they return iterators, similar to comprehensions).

**P13** – `==` compares value equality; `is` compares object identity (same memory address). Small integers (−5 to 256) and short strings are interned, so separate literals may refer to the same object, making `is` true. Do not rely on interning for equality; use `==` for value checks.

**P14** – `*args` collects positional arguments into a tuple; `**kwargs` collects keyword arguments into a dict. Positional‑only parameters (`/`) appear before `/` and can only be passed positionally. Keyword‑only parameters (`*`) appear after `*` (or a bare `*`) and must be passed by name. Example:
```python
def f(a, b, /, c, *, d, e=0): ...
```
`a,b` positional only; `c` can be positional or keyword; `d,e` keyword only.

**P15** – Context managers define `__enter__` (setup) and `__exit__` (teardown). The `with` statement calls them automatically, even on exceptions. Using `@contextmanager` from `contextlib` turns a generator into a CM. Example beyond files: timing block:
```python
from contextlib import contextmanager
import time
@contextmanager
def timer():
    start = time.perf_counter()
    yield
    print(f"Elapsed: {time.perf_counter()-start:.4f}s")
```
Usage: `with timer(): do_work()`

**P16** – Type hinting adds static type information. `Union[A,B]` means either type; `Optional[T]` is `Union[T, None]`. `Literal[1, "ok"]` restricts to specific values. `TypeVar` enables generic functions/classes (`T = TypeVar('T')`). `Protocol` defines structural subtyping (duck typing) for static checkers. Tools like `mypy`/`pyright` analyze code against these hints, flagging mismatches before runtime.

**P17** – `__repr__` aims for an unambiguous, developer‑focused representation (ideally evaluable). `__str__` targets end‑user readability. `__eq__` defines equality; `__hash__` must be consistent with `__eq__` if the object is hashable (used in sets/dicts). Defining `__eq__` without `__hash__` makes the class unhashable (`__hash__` set to `None`), preventing use in sets or as dict keys. `__getattr__` is invoked for missing attributes; `__getattribute__` intercepts *all* attribute access (use with care to avoid recursion).

**P18** – Descriptors implement the protocol `__get__(self, obj, objtype)`, `__set__(self, obj, value)`, `__delete__(self, obj)`. `property` is a descriptor that manages attribute access. `classmethod` and `staticmethod` are also descriptors: they return bound/unbound methods based on whether accessed via class or instance. Descriptors enable reusable attribute logic (e.g., type‑checked fields, lazy properties).

**P19** – Import system:  
1. **Finder** locates a module (built‑in, file‑system, zip, etc.) using `sys.path` entries.  
2. **Loader** loads the module’s code and creates a module object.  
`sys.path` initialized from `PYTHONPATH`, script directory, and installation‑specific paths. Relative imports (e.g., `from . import mod`) use the package’s `__name__` to resolve; absolute imports use top‑level names. `__init__.py` can be empty (marks a directory as a package) or contain initialization code. Namespace packages (PEP 420) allow splitting a package across multiple directories without `__init__.py`. The import machinery caches loaded modules in `sys.modules`.

**P20** – `dataclasses` auto‑generates `__init__`, `__repr__`, `__eq__`, `__hash__`, etc., based on class‑annotated fields. `field()` lets you specify defaults, factories (`default_factory`), comparison/include/exclude, etc. Frozen dataclasses (`frozen=True`) make instances immutable (generates `__setattr__` raising). Inheritance works: parent fields are inherited; child can override. `attrs` offers similar features with more flexibility (converters, validators, slots). `Pydantic` adds runtime validation, serialization, and parsing (based on annotations) and is preferable when you need complex validation, JSON schema generation, or integration with FastAPI. Choose plain `dataclasses` for simple data carriers; `attrs` when you want extra features without heavy validation; `Pydantic` when validation, serialization, and API integration are primary concerns.
