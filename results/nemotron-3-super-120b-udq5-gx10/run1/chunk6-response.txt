
**JS1** – `var` is function‑scoped and hoisted; `let` and `const` are block‑scoped, not hoisted in the same way (they exist in a temporal dead zone until declaration). `const` creates a read‑only binding (the value cannot be reassigned, though objects/arrays can be mutated). Hoisting moves declarations to the top of their scope during the compilation phase; only the identifier is hoisted, not the initialization.

**JS2** – The event loop continuously checks the call stack. When the stack is empty, it takes the oldest task from the macrotask queue (e.g., setTimeout, I/O callbacks) and runs it. After each macrotask, it processes all microtasks (promise reactions, queueMicrotask) until the microtask queue is empty, then repeats. This ordering gives microtasks higher priority than the next macrotask.

**JS3** – A closure is a function that retains access to variables from its lexical scope after the outer function has returned.  
*Example:*  
```js
function makeCounter() {
  let count = 0;
  return function() { return ++count; };
}
const c = makeCounter(); // c closes over `count`
```  
*Classic for‑loop bug:*  
```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // prints 3 three times
}
```  
Because `var` is function‑scoped, the callback captures the same `i` variable, which ends up as 3. Fixes: use `let i` (block‑scoped) or wrap in an IIFE: `setTimeout((function(j){return()=>console.log(j);})(i),0)`.

**JS4** – A `Promise` represents a future value; `async` functions return a promise implicitly, and `await` pauses execution until the promise settles. Errors propagate: rejected promises throw in `await` and can be caught with `try/catch`; `.catch()` handles rejections in promise chains. `Promise.all([p1,p2])` resolves when all resolve, rejecting on the first rejection. `Promise.allSettled` waits for all to settle (either fulfill or reject) and returns an array of status objects, never rejecting.

**JS5** – `interface` describes object shape and can be reopened (declaration merging); `type` creates a type alias for any type (primitives, unions, tuples, etc.) and cannot be reopened. Use `interface` for public APIs that may be augmented; use `type` for complex aliases, mapped types, or when you need features like `&` intersections. Discriminated unions are union types where a common literal property (the discriminant) lets TypeScript narrow members:  
```ts
type Shape = {kind:"circle", r:number} | {kind:"square", side:number};
function area(s:Shape){ if(s.kind==="circle") return Math.PI*s.r**2; else return s.side**2; }
```

**JS6** – Prototypal inheritance: objects have an internal `[[Prototype]]` link to another object; property lookup walks this chain. `Object.create(proto, descriptors?)` creates a new object whose `[[Prototype]]` is `proto`. ES6 `class` syntax is syntactic sugar: `class C extends B {}` creates a constructor function whose prototype inherits from `B.prototype` via `Object.setPrototypeOf`.

**JS7** – `this` binding rules (applied in order):  
1. **New binding** – if called with `new`, `this` is the newly created object.  
2. **Explicit binding** – `call`, `apply`, `bind` set `this` to the supplied argument.  
3. **Implicit binding** – when called as a method (`obj.fn()`), `this` is the preceding object.  
4. **Default binding** – otherwise, `this` is `global` (or `undefined` in strict mode).  
`bind()` returns a new function with `this` permanently bound; you cannot re‑bind that bound function (another `bind` just wraps it again).

**JS8** – `WeakRef<T>` holds a weak reference to an object, allowing it to be garbage‑collected while still accessible if alive. `FinalizationRegistry` registers a callback to run when a registered object is GC’d. Use them for caching or cleanup without preventing collection. `WeakMap` keys must be objects because only objects can be weakly held; primitives are immutable and would be compared by value, defeating the weak‑reference semantics and causing memory leaks if allowed.

**JS9** – V8 optimizes via hidden classes (maps) that track object shapes; inline caching stores likely property offsets for fast access. When assumptions break (e.g., adding properties dynamically, changing prototypes), V8 deoptimizes the compiled code back to the interpreter. Patterns causing deopt: deleting properties, adding properties after creation, using `with`, polymorphic call sites, or mixing different hidden classes heavily.

**JS10** – Tree‑shaking eliminates dead code by analyzing the ES module import/export graph; unused exports are dropped. ES modules are static, enabling this analysis. CommonJS uses dynamic `require()` calls whose arguments may be runtime values, so static analysis cannot safely determine what’s used, preventing effective tree‑shaking.

**JS11** – `null` is an intentional absence of any object value; `undefined` means a variable has been declared but not assigned, or a missing property/return. `null == undefined` is true (both are falsy and loosely equal); `null === undefined` is false (different types). Nullish coalescing `??` returns the right‑hand side when the left is `null` or `undefined`. Optional chaining `?.` short‑circuits property access if the left side is `null` or `undefined`.

**JS12** – `map` returns a new array of transformed values. `filter` returns a new array with elements that pass a predicate. `reduce` accumulates a single value: `arr.reduce((acc,cur,i,src)=>..., initialValue)`. If omitted, the first element becomes the initial accumulator and iteration starts at index 1. `flatMap` maps then flattens one level; useful when a mapping may produce zero or multiple items (e.g., splitting strings into words).

**JS13** – Template literals are back‑ticked strings allowing embedded `${expression}` and multiline text. Tagged templates parse the literal into an array of raw strings and the evaluated expressions, passing them to a tag function.  
*Example (HTML escape):*  
```js
function html(strings, ...values) {
  return strings.reduce((acc, s, i) => acc + s + (values[i]??'').replace(/[&<>"']/g, m=>({ '&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;' }[m]), '');
}
const name = "<script>";
console.log(html`Hello ${name}!`); // Hello &lt;script&gt;!
```

**JS14** – Destructuring unpacks values from arrays or objects into distinct variables.  
*Object:* `{a, b=c, d: e} = obj` → `a=obj.a`, `b=obj.b||c`, `e=obj.d`.  
*Array:* `[x, , y] = arr` → first and third elements.  
Rest operator (`...`) gathers remaining elements into an array: `[first, ...rest] = arr`. In objects, `{x, ...others} = obj` puts remaining enumerable own properties into `others`.

**JS15** – `for...in` iterates over an object's enumerable **string** keys (including inherited ones). `for...of` iterates over iterable objects (arrays, strings, maps, sets) yielding their values. Avoid `for...in` on arrays because it may visit non‑numeric properties and the order of indices is not guaranteed; use `for...of` or a classic loop for numeric indices.

**JS16** – Generics let you parameterize types.  
*Constraint:* `function foo<T extends Animal>(x:T){}` ensures `T` has an `Animal` shape.  
*Conditional type:* `type IsString<T> = T extends string ? true : false`.  
*Infer:* `type ReturnType<T> = T extends (...args:any)=>infer R ? R : never;` extracts a function’s return type.  
*Example:*  
```ts
type Pair<T> = [T, T];
function wrap<T>(v:T): Pair<T> { return [v,v]; }
```

**JS17** – CommonJS uses `require()`/`module.exports`; ES Modules use `import`/`export`. Node.js treats a file as ES module if its nearest `package.json` has `"type":"module"` or the file ends with `.mjs`; otherwise it’s CommonJS. You can interop via `import` of a CJS default export (`import fs from 'fs'`) and `require` of an ESM (`const mod = require('./mod.js')` returns the namespace object).

**JS18** – TypeScript’s structural system checks shape, not nominal names. Excess property checks occur when assigning an object literal to a typed target; unknown properties trigger an error unless the target has an index signature. `extends` creates a derived type or constraint; `satisfies` (TS 4.9) lets you verify a value matches a type without widening its literal variance. Variance modifiers (`in` for contravariant, `out` for covariant) apply to generic type parameters in interfaces/declarations to control subtyping of function parameters and return types.

**JS19** – `Proxy` wraps a target object and lets you define traps (`get`, `set`, `apply`, etc.) that intercept operations. `Reflect` provides mirror functions that forward to the target, useful inside traps.  
*Example (validation):*  
```js
function validate(target, rules){
  return new Proxy(target, {
    set(obj,prop,value){
      if(rules[prop] && !rules[prop](value)) throw new Error(`Invalid ${prop}`);
      return Reflect.set(obj,prop,value);
    }
  });
}
const api = validate({age:0},{age:n=>n>=0 && n<=150});
api.age = 25; // ok
api.age = -1; // throws
```

**JS20** – `SharedArrayBuffer` provides a raw binary buffer that can be shared between the main thread and workers. `Atomics` offers static methods (`Atomics.store`, `load`, `add`, `wait`, `notify`) that guarantee atomic read‑modify‑write operations and enable thread synchronization. A worker can `Atomics.wait` on an int32 index, blocking until another thread calls `Atomics.notify` on the same index, providing a futex‑like mechanism. Ordering follows the hardware memory model; `Atomics` operations are sequentially consistent by default, ensuring visibility across threads.

**B1** – `$@` expands to each positional parameter as separate words; `$*` expands to a single word containing all parameters separated by the first character of `IFS`. Quoted: `"$@"` preserves each parameter as a separate quoted word; `"$*"` joins them into one string.

**B2** – `set -e` exits on any command that returns non‑zero (except in certain contexts). `set -u` treats unset variables as an error when expanded. `set -o pipefail` makes a pipeline’s exit status the status of the last command to exit non‑zero, or zero if all succeed. Together they cause the script to abort early on errors, undefined vars, or failing pipeline stages.

**B3** – `$(command)` is command substitution (POSIX) that runs `command` and substitutes its stdout; backticks `` `command` `` do the same but are harder to nest. `$((expression))` performs arithmetic expansion; `expr` is an external command for integer arithmetic or string operations, less efficient and requires spaces.

**B4** – Process substitution `<(command)` creates a named pipe (or `/dev/fd`) whose contents are the stdout of `command`; you can read from it as a file. Example: `diff <(sort file1) <(sort file2)` compares sorted outputs without temporary files.

**B5** – Use a null‑delimited loop: `while IFS= read -r -d '' f; do … done < <(find . -type f -print0)`. `for f in $(ls)` breaks on spaces/newlines because word splitting occurs on the unquoted expansion; also `ls` output is not safe for parsing.

**B6** – Here‑document `<<EOF` feeds lines to a command’s stdin until a line containing only the delimiter. Here‑string `<<<"string"` feeds the string as stdin. `<<-EOF` strips leading tabs (not spaces) from each line of the heredoc, allowing indentation in scripts.

**B7** –  
`cmd > file 2>&1` → stdout redirected to file, then stderr redirected to wherever stdout currently points (the file). Result: both stdout and stderr go to `file`.  
`cmd 2>&1 > file` → stderr first duplicates stdout (still the terminal), then stdout redirected to file; stderr stays on terminal. Hence only stdout goes to file.  
`cmd &> file` is a bash shortcut equivalent to the first form (both to file).

**B8** –  
```bash
lockfile() {
  local lock="/tmp/mylock.$$.lock"
  if mkdir "$lock" 2>/dev/null; then
    trap 'rm -rf "$lock"' EXIT INT TERM
    return 0
  else
    return 1
  fi
}
```
`mkdir` is atomic; if it succeeds we hold the lock. The trap cleans up on normal exit or signals. Using a file (`> lock`) can suffer from race conditions between check and create; `mkdir` either creates the directory or fails atomically.

**B9** – Single quotes prevent any expansion; double quotes allow variable, command, and arithmetic expansion; no quotes cause word splitting and pathname expansion. Example: `var="*"; echo $var` → lists files; `echo "$var"` → literal `*`; `echo '$var'` → `$var`.

**B10** – `[ -e file ]` (test) checks existence; `[ -d file ]` directory; `[ -r file ]` readable. `[[ … ]]` is a bash keyword that provides pattern matching (`==`), regex (`=~`), and doesn’t perform word splitting or globbing on its contents, making it safer and more feature‑rich.

**B11** – `$?` exit status of last command; `$$` PID of the shell; `$!` PID of most recent background command; `$#` number of positional parameters. Use `$?` for error checking, `$$` for temp‑file naming, `$!` to wait on a background job, `$#` to validate argument count.

**B12** – Functions: `foo() { … }` or `function foo { … }` (the latter is a bash‑only keyword). Return status via `return N` (0‑255); to return data, echo/capture or modify a variable passed by name. Example: `foo(){ echo "$1*2" | bc; }` then `result=$(foo 5)`.

**B13** – `PATH` is a colon‑separated list of directories searched for executables. Bash checks each directory in order; if a command contains a slash it’s taken as a path. Builtins (e.g., `cd`, `echo`) are looked up before PATH; use `type -a cmd` to see all implementations, `command -v cmd` to get the external version, `builtin cmd` to force the builtin.

**B14** – `trap 'handler' SIGNAL` registers a handler. Common traps: `EXIT` (run on script exit), `ERR` (when a command fails, if `set -e`/`pipefail`), `INT` (Ctrl‑C), `TERM` (kill). Order: signals are queued; if multiple arrive before the handler runs, the handler is invoked once per signal, but the exact order follows delivery.

**B15** – `xargs` reads items from stdin and invokes a command with them as arguments; command substitution `$(…)` captures stdout as a string. To handle spaces/newlines, use `find … -print0 | xargs -0`. `-P N` runs up to N processes in parallel.

**B16** – Indexed arrays: `arr=(a b c)`; append: `arr+=(d)`; length: `${#arr[@]}`; iterate: `for e in "${arr[@]}"; do …`. Associative arrays (bash 4+): `declare -A map`; set: `map[key]=value`; length: `${#map[@]}`; iterate keys: `for k in "${!map[@]}"; do …`. No nested arrays; values are strings.

**B17** – `( … )` runs commands in a subshell: separate environment, variable changes don’t affect parent. `{ …; }` is a group command: runs in the current shell, variables persist, but still needs a semicolon or newline before `}`. Piping into a `while` loop creates a subshell for the loop, so variable modifications inside are lost unless you use `lastpipe` option or redirect the loop (`while …; do … done < file`).

**B18** – Signals: `SIGINT` (interrupt, Ctrl‑C), `SIGTERM` (terminate request), `SIGHUP` (hangup, often used to reload config), `SIGKILL` (force kill, cannot be caught). To handle graceful shutdown, trap `TERM`/`INT`, set a flag, and have background loops check the flag; use `wait` to reap children before exiting.

**B19** –  
```bash
#!/usr/bin/env bash
set -euo pipefail
process_chunk(){   # receives a file path
    # e.g., count errors
    grep -c ERROR "$1"
}
export -f process_chunk   # needed for subshells
split -l 1000000 big.log chunk_
for f in chunk_*; do
    echo "$f"
done | xargs -P 4 -I{} bash -c 'process_chunk "$@" _' _ {}
# results are printed; you can collect them into a file or sum them
```
Trade‑off: parallelism reduces wall‑clock time but increases CPU/I/O contention; error propagation requires checking each job’s exit status (e.g., store PIDs and `wait`). Use `set -e` inside the worker or capture `$?` and exit non‑zero on failure.

**B20** – `exec` replaces the current shell process with the given command (no new PID). Without a command, `exec` manipulates file descriptors: `exec 3>file` opens fd 3 for writing; `exec 3>&-` closes it. To make a coprocess: `coproc myproc { while read -r line; do echo "[$line]"; done; }` then read/write via `${myproc[0]}` and `${myproc[1]}`. Useful for bidirectional communication with a long‑running process without spawning a new subshell each time.

**PS1** – `Write-Output` sends objects down the pipeline (can be captured, filtered, etc.). `Write-Host` writes directly to the host console, bypassing the pipeline; output cannot be captured or redirected. Use `Write-Output` for cmdlet‑like behavior; `Write-Host` only for pure console messages.

**PS2** – The pipeline passes objects from one command to the next; each cmdlet processes each object as it arrives. `ForEach-Object` (`%`) is a pipeline cmdlet that receives objects and runs a script block per object. `foreach` statement is a language construct that enumerates a collection *before* entering the loop; it does not participate in the pipeline and is faster for simple in‑memory arrays.

**PS3** – `[PSCustomObject]` is a typed object with properties; `[hashtable]` is a dictionary of key/value pairs. Use a PSCustomObject when you need a fixed schema, methods, or to output structured data; use a hashtable for dynamic key‑value storage. Convert: `[PSCustomObject]@@{Name='Bob';Age=30}` or `$hash | [PSCustomObject]::new($hash)`.

**PS4** – Terminating errors stop pipeline execution unless caught; non‑terminating errors (e.g., write‑error) let the pipeline continue. `-ErrorAction` (SilentlyContinue, Stop, etc.) overrides `$ErrorActionPreference` for a single command. `try { … } catch [System.Exception] { … }` catches terminating errors; to catch non‑terminating errors you must set `-ErrorAction Stop` or `$ErrorActionPreference = 'Stop'`.

**PS5** – Splatting passes a collection as a set of named parameters: `@params = @{ Name='Bob'; Age=30 }; New-Object -TypeName PSObject -Property @params`. It differs from passing a hashtable as a single positional argument, which would bind the whole hashtable to the first parameter.

**PS6** – PowerShell remoting uses WS‑Management over HTTP/HTTPS (WinRM). `Invoke-Command -ComputerName` runs a script block on remote machines and returns results; `Enter-PSSession` starts an interactive session. Remoting can also work over SSH in PS 7+ (`-HostName`). The underlying protocol is the same; the client authenticates via CredSSP, Kerberos, or basic.

**PS7** – In the function, `$result` is an array; `return $result` returns the array as a single pipeline object. Thus `$x.GetType().Name` is `Object[]`. If the function returns zero items (`$result = @()`), the return statement yields `null` (because returning an empty array is treated as no output), so `$x` becomes `$null` and accessing `.GetType()` throws. Correct pattern: explicitly output the array (`return ,$result`) or write it (`$result`) to preserve the array wrapper, or simply omit `return` and let the array flow.

**PS8** – `[scriptblock]` is a literal piece of code that can be invoked with `&`. A function is a named scriptblock with its own scope. You can pass a scriptblock to a remote session via `-ArgumentList` (it gets serialized) or using `Invoke-Command -ScriptBlock { … } -ArgumentList $sb`. The double‑hop problem occurs when credentials used for the first hop cannot be delegated to a second remote machine; solve with CredSSP (enables delegation) or Kerberos constrained delegation, or use `Invoke-Command -Authentication Kerberos -EnableNetworkAccess`.

**PS9** – `@()` forces an array (even if empty or single element). `[array]` is a type literal; casting `[array]$x` ensures `$x` is an array. Indexing into `$null` returns `$null`; indexing into an empty array returns `$null` as well (no error). To safely get first element, use `$arr[0]` which yields `$null` if missing.

**PS10** – Comparison operators: `-eq`/`-ne` equality, `-like`/`-notlike` simple wildcard, `-match`/`-notmatch` regex, `-contains` checks if a collection contains a value (returns bool), `-in` checks if a value is in a collection (returns bool). Case‑sensitive versions prefix with `c` (`-ceq`, `-clike`, etc.). `-contains` tests collection ∋ value; `-in` tests value ∈ collection (order of operands swapped).

**PS11** – A module is a reusable package of functions, variables, etc. Script module (`.psm1`) contains code; manifest module (`.psd1`) metadata that can also import other modules and define required version, GUID, etc. Binary module is a compiled DLL. `Import-Module` loads the module, making its exported commands available; with a manifest you can also specify `-MinimumVersion`, `-RequiredVersion`.

**PS12** – Double‑quoted strings (`"..."`) expand variables, subexpressions (`$(…)`), and escape characters; single‑quoted strings (`'...`) are literal. Interpolation: `"The value is $x"` or `"The sum is $(($a+$b))`. Here‑string: `@" ... "@` (or `@' ... '@`) allows multiline quoting with the same expansion rules as double/single quotes depending on the opening quotes.

**PS13** – `Get-Member` shows an object’s members (properties, methods, noteproperties, etc.). In the pipeline, you can pipe any object to `gm` to inspect it. `Select-Object` picks or renames properties; `Where-Object` filters objects based on a scriptblock or comparison.

**PS14** – PowerShell classes (v5+) resemble C# classes but are limited: no parameterless constructor overloads, no static constructors, no interfaces (you can implement interfaces only via `class MyClass : IInterface {}` but interface members must be implemented), no property initializers with expressions, and no async methods (until v7). Use a class when you need encapsulation, methods, and inheritance; otherwise a function or advanced function is simpler.

**PS15** – `[CmdletBinding()]` makes a function behave like a cmdlet: supports `-Verbose`, `-Debug`, `-ErrorAction`, `-WhatIf`, `-Confirm`. `SupportsShouldProcess` enables `-WhatIf`/`-Confirm`. `DefaultParameterSetName` selects which parameter set to use when ambiguous. `ValueFromPipeline` allows a parameter to accept pipeline input. Blocks: `begin` runs once before pipeline input, `process` runs for each input object, `end` runs once after all input.

**PS16** – Providers expose data stores as PSDrives (e.g., `C:` for filesystem, `HKLM:` for registry). `Get-ChildItem` works across providers by using the PSDrive name. Example: `Get-ChildItem HKLM:\Software\Microsoft` lists registry subkeys as if they were files. You can navigate with `Set-Location`, create items with `New-Item`, etc.

**PS17** – A `[runspace]` is an isolated execution environment; a `[runspacepool]` manages multiple runspaces for reuse. The `[powershell]` object holds a pipeline to run in a runspace. `ForEach-Object -Parallel` (PS 7+) automatically creates a runspacepool and invokes the script block per input item, handling throttling via `-ThrottleLimit`. Manual runspace management gives finer control (e.g., sharing state, custom initialization) but requires more boilerplate.

**PS18** – PSScriptAnalyzer is a static checker that parses scripts and reports violations of rules (e.g., PSAvoidUsingWriteHost, PSUseDeclaredVarsMoreThanAssign). Rules have severity levels (Error, Warning, Information). You can suppress specific lines with `# <# PSAvoidUsingWriteHost #>` or via a `settings.psd1` file. In CI/CD, invoke `Invoke-ScriptAnalyzer` and fail the build on any Error or based on a threshold.

**PS19** – `$using:` allows a script block invoked in a child session (job, remote, `-Parallel`) to access variables from the parent scope without explicit argument passing. `$args`/`-ArgumentList` are used when you need to pass values explicitly; they are serialized via CLIXML, which has a depth limit (default 32). Complex or deeply nested objects may be truncated; to avoid this, pass only needed primitives or use `$using:` to reference the parent variable directly (which avoids serialization).

**PS20** – DSC (Desired State Configuration) lets you declare a configuration block that defines resources (e.g., `File`, `WindowsFeature`, `Service`) and their desired state. The Local Configuration Manager (LCM) applies the configuration, enforces drift correction, and reports status. In Windows PowerShell DSC is MOF‑based; in PowerShell 7+ DSC resources are often PowerShell‑based and can target Linux/macOS via the `PSDesiredStateConfiguration` module. Modern IaC (e.g., Terraform, Ansible, Pulumi) has largely supplanted DSC for cross‑platform cloud infrastructure, though DSC remains useful for Windows server configuration management.
