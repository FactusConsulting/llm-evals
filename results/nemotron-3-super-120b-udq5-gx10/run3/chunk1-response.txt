
**Networking**

**N1** – A Layer 2 switch forwards frames based on MAC addresses and operates only within a single broadcast domain (VLAN). A Layer 3 switch adds routing capabilities: it can make forwarding decisions based on IP addresses, maintain a routing table, and interconnect multiple VLANs/subnets while still performing high‑speed L2 switching for traffic that stays within the same VLAN.

**N2** – 10.0.5.37/20 → subnet mask 255.255.240.0.  
Network address: 10.0.0.0 (first address where host bits are zero).  
Broadcast address: 10.0.15.255 (host bits all ones).  

**N3** – TCP three‑way handshake:  
1. Client → SYN (seq = x).  
2. Server → SYN‑ACK (seq = y, ack = x+1).  
3. Client → ACK (seq = x+1, ack = y+1).  
If the final ACK is lost, the server retransmits its SYN‑ACK (after its timeout) because it never received the ACK; the client, having already sent the ACK, will ignore duplicate SYN‑ACKs and keep the connection in ESTABLISHED state. The connection will eventually be established after the server’s retransmission is answered, or it will abort after exceeding retry limits.

**N4** – SNAT (Source NAT) rewrites the source IP/port of outbound packets; DNAT (Destination NAT) rewrites the destination IP/port of inbound packets.  
*Example SNAT*: A corporate NAT gateway changes internal 10.0.0.5:12345 to public 203.0.113.10:54321 for traffic to the Internet.  
*Example DNAT*: A load balancer maps incoming 203.0.113.10:80 to internal server 10.0.0.20:8080.

**N5** – Possible causes of “certificate subject name does not match target host name”:  
1. The certificate is issued for a different hostname (e.g., www.example.com) while you accessed example.com.  
2. The certificate uses an IP address in the Subject Alternative Name (SAN) but you connected via a hostname.  
3. The certificate is expired or uses a wildcard that does not cover the specific sub‑domain you requested.

**N6** – VLAN (802.1Q) tags Ethernet frames with a 12‑bit VLAN ID, limited to 4094 VLANs and confined to a single LAN segment. VxLAN encapsulates the original Ethernet frame in UDP (port 4789) plus a 24‑bit VNI, allowing up to 16 million overlay networks and spanning Layer 3 boundaries. Choose VxLAN when you need more than 4094 isolated networks, multi‑tenant data‑center interconnects, or to stretch L2 across routed IP fabrics.

**N7** – Reply via eth0 occurs because the routing table selects the default route (via eth0) for the destination address (the source of the incoming packet). The kernel does not perform “reverse path forwarding” by default. Fix with policy‑based routing:  
```
# Create a separate routing table for eth1
echo 200 >> /etc/iproute2/rt_tables
ip rule add from 192.168.1.0/24 table 200 priority 100
ip route add default via 192.168.1.1 dev eth1 table 200
```
Now packets with source in 192.168.1.0/24 are looked up in table 200 and sent out eth1.

**N8** – BGP path selection order (higher preference first):  
1. Highest **Weight** (Cisco‑proprietary).  
2. Highest **Local Preference**.  
3. Prefer locally originated routes (network/aggregate).  
4. Shortest **AS_PATH** length.  
5. Lowest **Origin** type (IGP < EGP < INCOMPLETE).  
6. Lowest **MED** (if same neighboring AS).  
7. Prefer eBGP over iBGP paths.  
8. Lowest IGP metric to BGP next‑hop.  
9. If still tied, oldest route (for stability).  
10. Lowest router ID / cluster‑list length / neighbor address.

**N9** – VxLAN adds 50 bytes of overhead (14 B Ethernet + 20 B IP + 8 B UDP + 8 B VxLAN header). IPsec tunnel (ESP) adds:  
- ESP header = 8 B,  
- ESP trailer = 2 B (padding) + pad length + next header (1 B) + authentication (if used, e.g., 12 B for HMAC‑SHA1) – assume 0 B auth for simplicity.  
Typical ESP overhead ≈ 20 B (8 B header + up to 12 B auth).  
Total overhead ≈ 50 B (VxLAN) + 20 B (IPsec) = 70 B.  
Maximum inner payload = physical MTU – overhead = 1500 – 70 = **1430 bytes**. (If using ESP‑NULL encryption and no auth, overhead is 8 B → 1422 B; adjust per actual ESP settings.)

**N10** – ARP resolves an IPv4 address to a MAC address on the local link. Gratuitous ARP (unsolicited ARP reply/request) is used to:  
- Announce a change in MAC‑IP binding (e.g., after NIC failover).  
- Detect duplicate IP addresses (if another host replies).  
- Update neighbor caches in switches/hosts without waiting for traffic.

**N11** – Public IP addresses are globally routable on the Internet; private IP addresses are reserved for internal use and not routed publicly. RFC 1918 private ranges:  
- 10.0.0.0 – 10.255.255.255 (10/8)  
- 172.16.0.0 – 172.31.255.255 (172.16/12)  
- 192.168.0.0 – 192.168.255.255 (192.168/16)

**N12** – DNS translates domain names to IP addresses.  
- **A record**: maps a name to an IPv4 address.  
- **AAAA record**: maps a name to an IPv6 address.  
- **CNAME record**: creates an alias; the target name is looked up for its A/AAAA record (cannot coexist with other record types for the same name).

**N13** – DHCP dynamically assigns IP configuration. DORA process:  
1. **D**iscover – client broadcasts DHCPDISCOVER.  
2. **O**ffer – server replies with DHCPOFFER (unicast or broadcast).  
3. **R**equest – client broadcasts DHCPREQUEST for the chosen offer.  
4. **A**ck – server sends DHCPACK, confirming the lease.

**N14** – Hub: physical layer (L1) device; repeats electrical signals to all ports, no intelligence.  
Switch: data link layer (L2) device; forwards frames based on MAC address, creates separate collision domains per port.  
Router: network layer (L3) device; routes packets based on IP address, connects different subnets, performs NAT, firewalling, etc.

**N15** – Half‑duplex: a device can either transmit **or** receive at any given time (shared medium, CSMA/CD). Full‑duplex: simultaneous transmit and receive on separate pairs (modern Ethernet switches use full‑duplex; half‑duplex is legacy, only seen on hubs or very old NICs).

**N16** – TTL (Time‑to‑Live) limits the number of hops a packet can traverse; each router decrements it, discarding the packet when TTL reaches 0 and sending an ICMP Time‑Exceeded. Traceroute sends packets with incrementally increasing TTL values; each hop returns a Time‑Exceeded, revealing the path.

**N17** – NAT gateway translates private addresses to a public address for outbound traffic (and vice‑versa for inbound).  
- **Static NAT**: one‑to‑one fixed mapping (e.g., 10.0.0.5 ↔ 203.0.113.10).  
- **Dynamic NAT**: maps from a pool of public addresses on a first‑come, first‑served basis.  
- **PAT (Port Address Translation)**: many‑to‑one mapping using different source ports (the most common form of NAT).

**N18** – ECMP installs multiple equal‑cost routes to the same destination; traffic is spread across them using a hash of packet fields (commonly: source IP, destination IP, source port, destination port, protocol). Asymmetric flows (different paths forward vs. reverse) can break stateful firewalls that expect both directions on the same interface, causing dropped sessions. Solutions: enable flow‑affinity (consistent hashing), use symmetric routing, or bypass firewall for return traffic.

**N19** – High latency with no loss but tiny TCP window (64 KB) limits throughput: max throughput = window / RTT. With a 10 MB BDP, the window should be ≈ 10 MB to fill the pipe. The small window is due to missing window‑scale option. Enabling TCP window scaling (RFC 1323) allows the advertised window to be shifted left by a scale factor (up to 14), letting the window grow to hundreds of kilobytes or megabytes, thus utilizing the available bandwidth.

**N20** – 802.1Q trunk carries multiple VLANs by tagging frames with a 4‑byte VLAN tag (TPID 0x8100, PRI, CFI, VID). On Linux, create sub‑interfaces for each VLAN:  
```
ip link add link eth0 name eth0.10 type vlan id 10
ip link add link eth0 name eth0.20 type vlan id 20
ip link add link eth0 name eth0.30 type vlan id 30
ip addr add 10.10.10.2/24 dev eth0.10
ip addr add 10.20.20.2/24 dev eth0.20
ip addr add 10.30.30.2/24 dev eth0.30
ip link set up dev eth0.10 eth0.20 eth0.30
```
On the wire, an Ethernet frame looks like:  
[Dest MAC][Src MAC][0x8100][PCP|DEI|VID][EtherType][Payload][FCS] where the VLAN tag follows the source MAC and precedes the EtherType.

**Linux**

**L1** – Hard link: another directory entry pointing to the same inode; shares data blocks, same inode number, cannot span filesystems. Symbolic link (soft link): a separate file containing a pathname to the target; has its own inode, can point across filesystems, can be dangling if target removed.

**L2** – `find /var/log -type f -size +100M` (or `-size +100000k`). Add `-print` or pipe to `ls -lh` for details.

**L3** – State D (uninterruptible sleep) means the process is waiting on hardware or a kernel resource (e.g., disk I/O) and cannot be interrupted by signals, including SIGKILL. It will remain in D until the event completes; you cannot kill it with `kill -9` until the wait ends.

**L4** – cgroups v1: hierarchical controllers each with its own mount point; complex, legacy. cgroups v2: unified hierarchy, single mount point, improved delegation, no internal processes, better API. systemd prefers v2 because it provides a cleaner, unified resource‑management model and eliminates the need for multiple hierarchies.

**L5** – nftables is the successor to iptables; uses a single netfilter framework with a more expressive rule syntax and atomic updates. The kernel can run both iptables (via the `iptables_nf` compatibility layer) and nftables simultaneously, but they operate on separate netfilter hooks; mixing them can lead to unpredictable packet traversal, so it’s best to choose one.

**L6** – Most likely cause: deleted files still held open by a process (the space is freed only when the last file descriptor closes). `df` shows the allocated blocks; `du` only counts directory entries. Use `lsof +L1` or check `/proc/<pid>/fd` to find the offending process.

**L7** – Boot flow:  
1. **UEFI firmware** runs, reads UEFI variables, loads the **bootloader** (e.g., GRUB) from the EFI System Partition.  
2. Bootloader loads the **Linux kernel** image and optionally an **initramfs** into memory, passes kernel command line.  
3. Kernel decompresses, initializes hardware, mounts the initramfs as temporary rootfs.  
4. Initramfs scripts load necessary modules, locate the real root device, mount it, and pivot_root to the real filesystem.  
5. Kernel starts **systemd** (PID 1) as the init system.  
6. Systemd reads its configuration, starts units according to the default target (usually `graphical.target` or `multi-user.target`), bringing up services, sockets, etc., until the system reaches the desired target.

**L8** – `available` memory = free + reclaimable cache (buff/cache) that can be quickly freed. Even with large buff/cache, if the kernel cannot reclaim enough (e.g., due to locked pages, slab fragmentation, or high `vm.min_free_kbytes`), available may appear low, triggering the OOM killer. Tunables: `vm.min_free_kbytes`, `vm.extra_free_kbytes`, `vm.swappiness`, `vfs_cache_pressure`, `zone_reclaim_mode`. Adjusting these can make more memory reclaimable sooner.

**L9** – `ip netns` creates, lists, and manages network namespaces, isolating network interfaces, routing tables, iptables rules, etc. Container runtimes (docker, containerd, cri‑o) launch each container in its own network namespace, then move the container’s veth peer into that namespace and configure IP addresses, providing network isolation.

**L10** – SIGTERM: polite termination request; can be caught, blocked, or ignored. SIGKILL: immediate termination; cannot be caught or ignored. SIGQUIT: similar to SIGTERM but also generates a core dump; can be caught/ignored. Only SIGTERM and SIGQUIT are catchable; SIGKILL is not.

**L11** – stdin (fd 0) is input, stdout (fd 1) normal output, stderr (fd 2) diagnostic output. To redirect stderr to a file while keeping stdout on the terminal: `command 2>error.log` (stdout still goes to terminal) or `command 2>error.log 1>&1` (explicit). To keep both but also log stderr: `command 2>error.log`.

**L12** – `chmod 755 file` sets permissions:  
- Owner: 7 → rwx (read, write, execute).  
- Group: 5 → r‑x (read, execute).  
- Others: 5 → r‑x (read, execute).  
Each digit is the sum of bits: 4 = read, 2 = write, 1 = execute.

**L13** – root user (UID 0) has unrestricted privileges. A user with sudo privileges can execute specific commands as root (or another user) after authenticating, according to `/etc/sudoers`; they do not have permanent UID 0 and are limited to the allowed commands.

**L14** – Package manager: tool that automates installing, upgrading, configuring, and removing software packages from repositories. Defaults:  
- Debian/Ubuntu → **APT** (`apt-get`/`apt`).  
- RHEL/Fedora → **DNF** (Fedora 22+, RHEL 8) – older used **YUM**.

**L15** – `/etc/fstab` lists filesystems to be mounted at boot (or with `mount -a`). Each line specifies device, mount point, filesystem type, options, dump, fsck order. A misconfigured entry can cause boot to drop into maintenance mode, prevent mounting of critical partitions, or lead to read‑only mounts if the filesystem cannot be accessed.

**L16** – LVM abstracts physical storage into logical volumes.  
- **Physical Volume (PV)**: a block device or partition marked for LVM (`pvcreate`).  
- **Volume Group (VG)**: pool of one or more PVs (`vgcreate`).  
- **Logical Volume (LV)**: virtual block device carved from a VG (`lvcreate`).  
To extend an LV online:  
```
lvextend -L +10G /dev/vg0/lv0   # add 10 GB
resize2fs /dev/vg0/lv0          # grow ext4 filesystem (or xfs_growfs for XFS)
```
The LV and filesystem can be resized while mounted (if supported).

**L17** – The I/O scheduler decides the order of pending block I/O requests.  
- **mq-deadline**: multi‑queue version of deadline scheduler; aims to limit latency, good for mixed workloads.  
- **bfq**: Budget Fair Queuing; provides per‑process I/O bandwidth guarantees, suitable for desktop/interactive workloads.  
- **none**: no scheduling (pass‑through); relies on underlying hardware queueing, optimal for SSDs/NVMe where internal queuing is sufficient.  
Choose mq-deadline for general servers, bfq for workstations needing low latency per app, none for high‑performance SSDs. Change at runtime: `echo bfq > /sys/block/sda/queue/scheduler`.

**L18** – Load average shows the average number of processes in the run‑queue **plus** those waiting for uninterruptible I/O (state D) over 1, 5, 15 minutes. High load with low CPU % indicates many processes blocked on I/O (disk, network, or locks). Diagnose:  
- `iostat -xz 1` → look at `%util` and await times for devices.  
- `vmstat 1` → `si`, `so` (swap), `bi`, `bo` (block I/O), `wa` (I/O wait).  
- `pidstat -d` or `iotop` to see per‑process I/O.  
- `netstat -i` or `sar -n DEV` for network interface utilization.  
If disk `%util` is high → disk bottleneck; if network interface shows high drops/errors → network; if CPU `%user+%sys` is high → CPU bound.

**L19** – SELinux enforces MAC via type enforcement: each process and file has a security context (user:role:type:level). Policies define allowed transitions (e.g., a httpd_t process may read files with type httpd_sys_content_t). Modes:  
- **Enforcing**: policy is loaded and violations are blocked (audit logged).  
- **Permissive**: policy is loaded but violations are only logged, not blocked.  
- **Disabled**: no policy loaded; no SELinux overhead.  
To troubleshoot a daemon failing to bind a non‑standard port:  
1. Check audit log: `ausearch -m avc -ts recent` or `grep avc /var/log/audit/audit.log`.  
2. Identify the denied operation (e.g., name_bind) and the port/type.  
3. Create a local policy module: `audit2allow -m myhttpd < /var/log/audit/audit.log` → `semodule -i myhttpd.pp`.  
4. Alternatively, use `semanage port -a -t http_port_t -p tcp <port>` to tell SELinux the port is allowed for httpd.

**L20** – On a page fault, the MMU traps to the kernel.  
- **Minor fault**: the page is already in physical memory (e.g., copy‑on‑write, shared library) – just update the page table; no disk I/O.  
- **Major fault**: the page is not resident; requires reading from swap or filesystem (disk I/O).  
Transparent Huge Pages (THP) automatically coalesce 2 MB (or 1 GB) pages to reduce TLB misses. Benefits: large‑scale memory‑intensive apps (databases, HPC) see lower fault rates and better throughput. Drawbacks: can cause latency spikes during allocation/compaction, and inefficient memory use for sparse workloads. Disable THP when running latency‑sensitive or memory‑fragmented apps: `echo never > /sys/kernel/mm/transparent_hugepage/enabled` (and similarly for `defrag`).
