
**JavaScript / TypeScript**

**JS1** – `var` is function‑scoped and hoisted; its declaration is moved to the top of the scope and initialized with `undefined`. `let` and `const` are block‑scoped; they are hoisted but not initialized (Temporal Dead Zone). `const` creates a read‑only binding (the value cannot be reassigned, though objects/arrays can be mutated). Hoisting refers to the mechanism where variable and function declarations are moved to the top of their containing scope during the compilation phase.

**JS2** – The event loop continuously checks the call stack. When the stack is empty, it takes the first task from the **macrotask queue** (e.g., setTimeout, I/O callbacks) and runs it. After each macrotask, it processes all **microtasks** (Promise reactions, queueMicrotask) until the microtask queue is empty, then repeats. This gives microtasks higher priority than subsequent macrotasks.

**JS3** – A closure is a function that retains access to variables from its lexical scope even after that scope has exited.  
```js
function makeCounter() {
  let count = 0;
  return function() { return ++count; };
}
const c = makeCounter(); // c closes over `count`
```
*Classic for‑loop bug*:  
```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // prints 3 three times
}
```
`var` is function‑scoped, so the callback captures the same `i` whose final value is 3. Fixes: use `let` (block‑scoped) or bind the value via an IIFE: `setTimeout((j)=>()=>console.log(j))(i)`.

**JS4** – A `Promise` represents a future value; `.then`/`catch` attach callbacks. `async/await` is syntactic sugar: `async` returns a Promise; `await` pauses until the settled Promise resolves/rejects, throwing on rejection. Error handling: `try { await p } catch(e){}` works like synchronous try/catch; unhandled Promise rejections can be caught with `.catch` or `window.onunhandledrejection`. `Promise.all([p1,p2])` resolves when all settle successfully; rejects on first rejection. `Promise.allSettled` waits for all to settle (fulfilled or rejected) and returns an array of status objects, never rejecting.

**JS5** – `interface` describes object shape and can be reopened (declaration merging); `type` creates a type alias for any type (primitives, unions, tuples, mapped types) and cannot be reopened. Use `interface` for public APIs that may be augmented; use `type` for complex aliases, unions, or when you need features like tuple types. *Discriminated unions* are union types where a common literal property (the discriminant) lets TypeScript narrow members:  
```ts
type Shape = {kind:"circle", r:number} | {kind:"square", side:number};
function area(s:Shape) {
  if (s.kind === "circle") return Math.PI * s.r ** 2; // s narrowed
}
```

**JS6** – Prototypal inheritance: objects have an internal `[[Prototype]]` link to another object; property lookup walks this chain. `Object.create(proto, descriptors?)` creates a new object whose `[[Prototype]]` is `proto`. ES6 `class` syntax is syntactic sugar over the same mechanism: `class C extends B {}` sets `C.prototype.__proto__ = B.prototype` and the constructor function’s `[[Prototype]]` to `B`.

**JS7** – `this` binding rules (applied in order):  
1. **New binding** – if called with `new`, `this` is the newly created object.  
2. **Explicit binding** – `call`, `apply`, `bind` set `this` to the supplied argument.  
3. **Implicit binding** – when called as a method (`obj.fn()`), `this` is the preceding object.  
4. **Default binding** – otherwise, `this` is `global` (or `undefined` in strict mode).  
`Function.prototype.bind` returns a new function with `this` permanently bound (and optionally pre‑filled args). You cannot re‑bind that bound function; calling `bind` again on it returns another bound function but does not change the original binding.

**JS8** – `WeakRef<T>` holds a weak reference to an object, allowing it to be garbage‑collected while still accessible if alive. `FinalizationRegistry` registers a callback to run when a registered object is GC’d. Use them for caching or cleanup without preventing collection. `WeakMap` keys must be objects because only objects can be weakly held; primitives are immutable and would always be reachable, defeating the weak‑reference purpose. When the key object is GC’d, the entry is automatically removed, letting the value be collected if no other references exist.

**JS9** – V8 optimizes hot functions:  
- **Hidden classes (maps)**: V8 creates a hidden class for an object shape; adding properties in the same order yields the same hidden class, enabling fast inline property access.  
- **Inline caching (IC)**: Caches the result of a property lookup at a call site; if the hidden class matches, it uses the cached offset.  
- **Deoptimization**: If assumptions break (e.g., adding a property changes hidden class, or a function receives unexpected types), V8 discards optimized code and falls back to the interpreter.  
Patterns causing deopt: polymorphic property access, `with`, `eval`, changing prototype after creation, mixing numeric and string keys in arrays, or using `arguments` object in a way that prevents optimization.

**JS10** – Tree‑shaking eliminates dead code by analyzing the ES module import/export graph; unused exports are omitted. ES modules are static, so bundlers can determine at build time what is used. CommonJS (`require`) uses dynamic calls; the module’s exports can’t be known statically without executing code, so tree‑shaking is ineffective (bundlers must conservatively keep everything).

**JS11** – `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned, or a missing property/return. `==` performs type coercion: `null == undefined` is true; both are false‑ish but not equal to `0`, `""`, or `false`. `===` checks strict equality without coercion, so `null === undefined` is false. Nullish coalescing `??` returns the right‑hand side when the left is `null` or `undefined` (not other falsy values). Optional chaining `?.` short‑circuits property access if the left side is `null` or `undefined`.

**JS12** – `map` returns a new array of callback results. `filter` returns a new array of elements where callback returns truthy. `reduce` accumulates: `arr.reduce((acc,cur,index,src)=>..., initialValue)`. If `initialValue` is omitted, the first element becomes the initial accumulator and iteration starts at index 1. `flatMap` maps then flattens one level (`arr.map(...).flat()`), useful when a callback may produce zero or multiple outputs.

**JS13** – Template literals are back‑ticked strings allowing interpolation `${expr}` and multiline text. Tagged templates parse the literal into an array of raw strings and the evaluated substitutions, then pass them to a tag function. Example (HTML escaping):  
```js
function html(strings, ...values) {
  return strings.reduce((acc, s, i) => acc + s + (values[i] ?? '').replace(/[&<>"']/g, c => ({
    '&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'
  })[c]), '');
}
const name = "<script>";
console.log(html`Hello ${name}!`); // Hello &lt;script&gt;!
```

**JS14** – Destructuring unpacks values. Object: `{a, b = 2, c: ren} = obj` extracts `a`, default `b`, renames `c` to `ren`. Array: `[x, y, ...rest] = arr`. Rest operator (`...`) gathers remaining elements into an array (or object properties). In function params, `...args` collects arguments.

**JS15** – `for...in` iterates over an object's enumerable **property keys** (including inherited ones). `for...of` iterates over **iterable values** (arrays, strings, Maps, Sets, etc.) using the object's `Symbol.iterator`. Avoid `for...in` on arrays because it yields indices as strings and may include non‑numeric enumerable properties, leading to unexpected order and performance issues.

**JS16** – Generics let you parameterize types. Constraints: `function foo<T extends Base>(x:T){}` ensures `T` has `Base` members. Conditional types: `T extends U ? X : Y` chooses a branch based on a type test. `infers` extracts a type: `type ReturnType<T> = T extends (...args:any)=>infer R ? R : never;` gives the return type of a function. Example:  
```ts
type PromiseValue<T> = T extends Promise<infer V> ? V : never;
type Getter<Obj, Key extends keyof Obj> = Obj[Key] extends (...args:any)=>infer R ? R : never;
```

**JS17** – JavaScript modules:  
- **CommonJS**: synchronous `require()`/`module.exports`; Node treats files as CJS unless `"type":"module"` in package.json.  
- **ES Modules**: static `import`/`export`; Node loads them as ESM when file extension is `.mjs` or `"type":"module"` is set, or when using `"exports"` field.  
Node can load both; `import` can load a CJS module (its `module.exports` becomes the default export), while `require` cannot load ESM unless `--experimental-modules` or using `import()` dynamic import.

**JS18** – TypeScript’s structural type system matches types by shape, not nominal names. Excess property checks occur when assigning an object literal to a typed target; unknown properties trigger an error (prevents typos). They apply only to fresh object literals, not to variables or results of functions. `extends` creates a derived type or constraint; `satisfies` (TS 4.9) lets you verify that an expression matches a type without changing its inferred type, useful for preserving literal variance. Variance modifiers (`in` for contravariant, `out` for covariant) on type parameters (TS 4.7) let you declare that a generic is safe in input or output positions, e.g., `type ReadOnlyList<out T> = readonly T[];`.

**JS19** – `Proxy` creates an object that intercepts fundamental operations via a handler object (`get`, `set`, `apply`, `has`, `deleteProperty`, etc.). `Reflect` provides mirror functions that forward to the default behavior, making it easy to implement traps that delegate. Example (validation):  
```js
const validator = {
  set(target, prop, value) {
    if (prop === 'age' && typeof value !== 'number') throw new TypeError('age must be number');
    return Reflect.set(target, prop, value);
  }
};
const person = new Proxy({name:'', age:0}, validator);
person.age = 25; // ok
person.age = 'twenty'; // throws
```

**JS20** – `SharedArrayBuffer` provides a raw binary buffer that can be accessed concurrently by multiple agents (main thread, workers). `Atomics` offers static methods (`Atomics.store`, `load`, `add`, `sub`, `and`, `or`, `xor`, `wait`, `notify`, `isLockFree`) that guarantee atomic read‑modify‑write operations and provide a futex‑like waiting mechanism. Workers postMessage the buffer (transferable) and then use `Atomics.wait` to block until another agent calls `Atomics.notify` on the same index, enabling efficient synchronization. Ordering guarantees: operations on a single index are atomic; there is no guarantee of ordering across different indices unless you use additional synchronization (e.g., locks built with Atomics). `Atomics.wait` returns `"ok"`, `"not-equal"`, or `"timed-out"`; it may spuriously wake, so loops re‑check the condition.

**Bash**

**B1** – `$@` expands to each positional parameter as a separate word; `$*` expands to a single word containing all parameters separated by the first character of `IFS`. When quoted: `"$@"` preserves each parameter as a separate quoted word; `"$*"` yields one quoted string with parameters joined by `IFS` (default space). Use `"$@"` to safely forward arguments.

**B2** – `set -e` exits the script if any command returns a non‑zero status (except in certain contexts). `set -u` treats unset variables as an error when expanded. `set -o pipefail` makes a pipeline’s return status the value of the last command to exit with non‑zero, or zero if all succeed. Combined they cause the script to abort on errors, catch misspelled vars, and not hide failures in pipelines.

**B3** – `$(command)` is modern command substitution; backticks `` `command` `` are legacy and harder to nest. `$((expression))` performs arithmetic expansion; `expr` is an external command for integer arithmetic or string operations, less efficient and requires spaces around operators.

**B4** – Process substitution `<(command)` creates a named pipe (or `/dev/fd/*`) that behaves like a file containing the command’s stdout. Useful for comparing command outputs without temporary files: `diff <(sort file1) <(sort file2)`.

**B5** – Iterate safely with `while IFS= read -r -d '' f; do … done < <(find . -type f -print0)`. Using `for f in $(ls)` breaks on spaces/newlines because word splitting occurs on the unquoted result; also `ls` output is not meant for parsing.

**B6** – Here‑document `<<EOF` feeds lines to a command’s stdin until a line containing only the delimiter. Here‑string `<<<"string"` feeds the string as stdin. `<<-EOF` strips leading tabs (not spaces) from each line of the heredoc, allowing indentation in scripts.

**B7** –  
- `cmd > file 2>&1` redirects stdout to `file`, then redirects stderr to wherever stdout currently points (the file). Result: both stdout and stderr go to `file`.  
- `cmd 2>&1 > file` first redirects stderr to stdout (still the terminal), then redirects stdout to `file`. Stderr still goes to terminal, stdout to file.  
- `cmd &> file` is a bash shorthand for redirecting both stdout and stderr to `file`. The first two differ because redirections are processed left‑to‑right, changing where each stream points at the moment of the redirection.

**B8** –  
```bash
lockfile() {
  local lock="/tmp/mylock.$$.lock"
  while ! mkdir "$lock" 2>/dev/null; do
    sleep 0.1   # back‑off
  done
  # lock acquired
  trap 'rm -rf "$lock"' EXIT INT TERM
  # … critical section …
}
```
`mkdir` is atomic; if it succeeds, we hold the lock. The trap ensures cleanup on normal exit or signals. Using a file (`> lock`) is prone to race conditions between check and create; `mkdir` avoids that because either the directory is created (we got the lock) or it already exists (someone else holds it).

**B9** – Single quotes `'` prevent all expansion; literal text. Double quotes `"` allow variable, command, and arithmetic expansion, but prevent globbing and word splitting. No quotes cause word splitting and pathname expansion. Example: `var="a b"`; `echo $var` → two words; `echo "$var"` → one word; `echo '$var'` → literal `$var`.

**B10** – `[ -e file ]` (test) checks existence; `[ -d file ]` directory; `[ -r file ]` readable. `[[ … ]]` is bash’s keyword version: supports `&&`, `||`, pattern matching (`==`), regex (`=~`), and doesn’t perform word splitting or globbing inside, making it safer and more expressive.

**B11** – `$?` exit status of last command. `$$` PID of the current shell. `$!` PID of most recent background command. `$#` number of positional parameters. Use `$?` for error checking, `$$` for temp‑file naming, `$!` to wait on a background job, `$#` to validate argument count.

**B12** – Functions: `foo() { … }` or `function foo { … }`; both are identical except the `function` keyword is optional. Return status via `return N` (0‑255) or by echoing a value and capturing it (`result=$(foo)`). Variables inside are function‑scoped unless declared `local`.

**B13** – `PATH` is a colon‑separated list of directories searched for executables. Bash checks each directory in order; if a command contains a slash, it’s treated as a pathname and not looked up in PATH. Builtins (e.g., `cd`, `echo`) are shell‑internal; external commands are files in PATH. Use `type -a cmd` to see all implementations (builtins, aliases, functions, files).

**B14** – `trap 'handler' SIGNAL` registers a handler. Example: `trap 'cleanup' EXIT ERR INT TERM`. Handlers run when the signal is delivered; multiple traps stack (later overrides earlier for same signal). Order of execution when multiple signals arrive is undefined but they are queued and handled sequentially as the shell returns to the main loop.

**B15** – `xargs` reads items from stdin and invokes a command with them; command substitution `$(cmd)` expands to the command’s stdout as arguments (subject to word splitting). To handle spaces/newlines, use `find … -print0 | xargs -0`. `-P N` runs up to N processes in parallel.

**B16** – Indexed arrays: `arr=(a b c)`; append `arr+=(d)`; length `${#arr[@]}`; iterate `for i in "${!arr[@]}"; do … done`. Associative arrays (bash 4+): declare `-A assoc`; `assoc[key]=value`; length `${#assoc[@]}`; iterate over keys `for k in "${!assoc[@]}"; do … done`. Syntax differs: normal arrays use integer indices; associative require string keys and must be declared.

**B17** – `( … )` runs commands in a subshell: gets a copy of the environment; variable changes don’t affect parent. `{ …; }` is a group command: runs in the current shell, so variable modifications persist. Piping into a `while` loop creates a subshell for the loop (due to the pipeline), so variable changes inside the loop are lost unless you use `lastpipe` option or redirect the loop’s input differently.

**B18** – Signals: `SIGINT` (Ctrl‑C) interrupt; `SIGTERM` request to terminate; `SIGHUP` hang‑up (often used to reload config); `SIGKILL` forced kill cannot be caught. Bash runs trap handlers for catchable signals. To handle graceful shutdown with background jobs, trap `TERM`/`INT`, send `kill` to background PIDs, then `wait` for them before exiting.

**B19** – Parallel log processing:  
```bash
#!/usr/bin/env bash
set -euo pipefail
tmpdir=$(mktemp -d)
trap 'rm -rf "$tmpdir"' EXIT

split -l 100000 -d logfile "$tmpdir/part-"   # split into chunks
export -f process_chunk   # make function available to subshells
find "$tmpdir" -name 'part-*' -print0 |
  xargs -0 -P 4 -I {} bash -c 'process_chunk "$@" > "${1}.out"' _ {} "$tmpdir/$(basename {})"

cat "$tmpdir"/part-*.out > merged.log
```
`xargs -P` runs up to 4 jobs concurrently. Errors propagate via `set -e`; each chunk’s failure aborts the whole script unless you capture `$?` per chunk. Trade‑off: parallelism reduces wall‑clock time but increases CPU/I/O contention and memory usage.

**B20** – `exec` replaces the current shell process with the given command (no new process). Without a command, `exec` only modifies file descriptors. Example: `exec 3>out.log` opens fd 3 for writing; `exec 3>&-` closes it. To redirect all output of a script: `exec >logfile 2>&1`. A coprocess (`coproc NAME { … }`) creates a background process with two pipes (`NAME[0]` read, `NAME[1]` write) allowing bidirectional communication; useful for interactive protocols (e.g., ssh, dbus) where you need to send commands and read responses without deadlocking.

**PowerShell**

**PS1** – `Write-Output` sends objects down the pipeline (the default output stream). `Write-Host` writes directly to the host console, bypassing the pipeline; output cannot be captured or redirected. Use `Write-Output` (or simply write the value) when you want the result to be usable by downstream commands; `Write-Host` for purely informational messages that should not interfere with pipeline data.

**PS2** – The pipeline passes objects from one command to the next; each command processes each object as it arrives. `ForEach-Object` (`%`) is a cmdlet that receives pipeline input and executes a script block per object. `foreach` statement is a language construct that iterates over a collection already in memory; it does not participate in the pipeline. Use `ForEach-Object` when you need to stream data (e.g., large files) and `foreach` when you already have the collection and want faster in‑memory iteration.

**PS3** – `[PSCustomObject]` is a typed object with properties accessible via dot notation; `[hashtable]` is a dictionary of key/value pairs. Use a PSCustomObject when you need a structured object with methods, property validation, or to emit in the pipeline. Use a hashtable for simple lookup tables or splatting. Conversion: `[PSCustomObject]$hash` creates an object with the hashtable’s properties; `$obj.PSObject.Properties` yields a hashtable‑like view.

**PS4** – Terminating errors stop pipeline execution unless caught; non‑terminating errors (e.g., write‑error) let the pipeline continue. `-ErrorAction` (SilentlyContinue, Stop, etc.) overrides `$ErrorActionPreference` for a single command. `try { … } catch { … }` catches terminating errors; to catch non‑terminating errors you must set `-ErrorAction Stop` or `$ErrorActionPreference = 'Stop'`.

**PS5** – Splatting (`@params`) passes a collection of name/value pairs as individual parameters to a command. Example:  
```powershell
$opts = @{ Path = 'file.txt'; Encoding = 'UTF8' }
Get-Content @opts
```
Passing a hashtable as a single argument (`Get-Content $opts`) would treat the hashtable itself as the `Path` argument, causing an error. Splatting expands the keys as parameter names.

**PS6** – PowerShell remoting uses WS‑Management over HTTP/HTTPS (WinRM) by default; SSH subsystem is available in PowerShell 7+. `Invoke-Command -ComputerName` runs a script block on one or more remote machines and returns results; it does not leave an interactive session. `Enter-PSSession` starts an interactive remote session (like `ssh`). Both rely on the same underlying WS‑Man listener; SSH uses the `ssh` subsystem instead of WinRM.

**PS7** – In the function, `$result` is an array; returning it makes the pipeline unwrap the array, so `$x` receives the array’s elements individually. When the function returns one element (`"one"`), `$x` becomes that string, and `$x.GetType().Name` is `String`. When the function returns zero items, the pipeline yields `$null`; `$x` is `$null` and accessing `.GetType()` throws (you’d need to guard). Correct pattern: explicitly return the array wrapped, e.g., `return ,$result` (the comma preserves the array) or write `return $result` and then capture with `$x = & { Get-Items }` to avoid unrolling, or use `[void]` to suppress unrolling.

**PS8** – `[scriptblock]` is a type representing executable code; a function is a named scriptblock with metadata. You can pass a scriptblock to a remote session via `Invoke-Command -ScriptBlock { … } -ArgumentList $arg`. The double‑hop problem occurs when a remote session tries to use credentials to access a second remote resource (e.g., accessing a file share). Solutions: enable CredSSP (`Enable-WSManCredSSP`) or use `Invoke-Command -Authentication Kerberos -ComputerName … -ScriptBlock { … } -ArgumentList …` with constrained delegation, or use `New-PSSession` with `-UseSSL` and `-Credential` and then `Invoke-Command -Session $s -ScriptBlock { … } -ArgumentList …` where the second hop is allowed via Kerberos delegation.

**PS9** – `@()` forces an array (even if empty or single element). `[array]` is a type literal; casting `[array]$x` converts `$x` to an array (if it isn’t already). Indexing into `$null` returns `$null`; indexing into an empty array returns `$null` as well (out‑of‑bounds yields `$null`). To guarantee at least one element, use `@($value)` or `[array]$value`.

**PS10** – Comparison operators: `-eq`, `-ne` (equality); `-like`, `-notlike` (simple wildcard); `-match`, `-notmatch` (regex); `-contains` checks if a collection contains a value (left‑hand side is collection); `-in` checks if a value is in a collection (right‑hand side is collection). Case‑sensitive variants prefix with `c` (`-ceq`, `-clike`, etc.). `-contains` is collection‑centric; `-in` is value‑centric, allowing natural reading: `5 -in 1,2,3,4,5` is true.

**PS11** – A PowerShell module is a reusable package of commands, functions, variables, etc. Types:  
- **Script module** (`.psm1`) – contains PowerShell code.  
- **Manifest module** (`.psd1`) – metadata that can import script modules, binary modules, or manage versioning.  
- **Binary module** (compiled DLL) – contains compiled cmdlets (C#).  
`Import-Module` loads the module, making its exported commands available in the session; it reads the manifest if present, otherwise loads the `.psm1` directly.

**PS12** – String interpolation: double‑quoted strings (`"..."`) evaluate expressions inside `$()` or `${}`; single‑quoted strings (`'...')` treat everything literally. Here‑string (`@" ... "@` or `@' ... '@`) allows multiline literals with the same quoting rules as the outer delimiters. Example:  
```powershell
$name = "World"
"Hello $name"          # Hello World
'Hello $name'          # Hello $name
@"Line1
Line2 $name
Line3"@"               # multiline with interpolation
```

**PS13** – `Get-Member` (`gm`) shows an object’s members: properties, methods, noteproperties (static properties), aliasproperties, scriptproperties, etc. `Select-Object` picks or renames properties; `Where-Object` filters objects based on a scriptblock or comparison. `Get-Member` is for inspection; the others transform the pipeline.

**PS14** – PowerShell classes (v5+) resemble C# classes but are limited: no parameterless constructors (you must define `new()`), no static constructors, no interfaces (you can implement interfaces via `class MyClass : IInterface {}` but only a subset of .NET interfaces work), no property accessors with different visibility, and no nested types. Use a class when you need encapsulation, methods, and inheritance; otherwise a function or advanced function is simpler.

**PS15** – `[CmdletBinding()]` makes a function behave like a compiled cmdlet, enabling features: `-WhatIf`, `-Confirm`, `-ErrorAction`, `-ErrorVariable`, etc. SupportsShouldProcess adds `-WhatIf`/`-Confirm` support. DefaultParameterSetName selects which parameter set to use when ambiguous. ValueFromPipeline allows a parameter to accept pipeline input. Blocks: `begin` runs once before pipeline input, `process` runs for each pipeline object, `end` runs once after all input.

**PS16** – Providers expose data stores as PSDrives (e.g., `C:` for filesystem, `HKLM:` for registry, `Cert:` for certificates, `Env:` for environment variables). `Get-ChildItem` (`ls`, `dir`) works across providers by treating the drive as a namespace; you can `cd HKLM:\Software\MyApp` and then `Get-ChildItem` to list registry keys as if they were files.

**PS17** – A `[runspace]` is an isolated execution environment with its own state, pipelines, and session. A `[runspacepool]` groups runspaces for reuse, enabling throttled parallel execution. The `[powershell]` object represents a PowerShell instance that can contain one or more runspaces. `ForEach-Object -Parallel` (PS 7+) internally creates a runspacepool and invokes the script block per input item, handling synchronization. Manual runspace management gives more control (e.g., sharing state, custom throttling) but requires more boilerplate.

**PS18** – PSScriptAnalyzer is a static code checker that parses scripts and validates against rules (e.g., PSAvoidUsingWriteHost, PSUseDeclaredVarsMoreThanAssign). Rules have severity levels (Error, Warning, Information). You can suppress specific rules with `#pragma warning suppress PSAvoidUsingWriteHost` or via `SuppressMessage` attribute. In CI/CD, invoke `Invoke-ScriptAnalyzer` and fail the build on errors/warnings above a threshold.

**PS19** – `$using:` scope imports variables from the calling session into a child job, background job, or remote session (e.g., `Start-Job -ScriptBlock { param($x) … } -ArgumentList $using:myVar`). `$args`/`-ArgumentList` passes values explicitly; they are serialized via CLIXML. Serialization depth is limited (default 32); complex nested objects may be truncated or cause errors. To avoid limits, pass simple types or use `$using:` with `-ArgumentList` referencing objects that survive serialization (or use `Invoke-Command -Session $s -ScriptBlock { … } -ArgumentList $using:obj` where the object is marked `[Serializable]` or is a PSObject with limited depth).

**PS20** – Desired State Configuration (DSC) is a declarative management platform. A **configuration** is a PowerShell script block that uses built‑in or custom **resources** (e.g., `File`, `Service`, `WindowsFeature`) to describe the desired state. The **Local Configuration Manager (LCM)** is the engine that applies, monitors, and enforces the configuration on a node. In Windows PowerShell, DSC relied on MOF files and the LCM; PowerShell 7+ moved to a cross‑platform, imperative‑friendly approach with the `PSDesiredStateConfiguration` module, but the classic DSC is largely superseded by IaC tools like **ARM/Bicep**, **Terraform**, **Ansible**, or **Chef/Puppet**. Modern infrastructure‑as‑code prefers those tools over DSC for cloud and cross‑platform scenarios.
