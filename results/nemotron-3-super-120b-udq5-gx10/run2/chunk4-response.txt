
**Go**

**G1** – An array has a fixed size that is part of its type (`[N]T`). A slice is a descriptor (`ptr, len, cap`) that references an underlying array; its length and capacity can change. When `append` exceeds the slice’s capacity, Go allocates a new, larger backing array (typically doubling), copies the old elements, and returns a slice pointing to the new array.

**G2** – `var x int` declares a variable at package or function scope and zero‑initializes it. `x := 0` is a short variable declaration, only legal inside a function, and declares and initializes `x` using type inference. You cannot use `:=` at package level, nor to redeclare the same variable in the same block unless at least one new variable is also declared.

**G3** – A goroutine is a lightweight thread managed by the Go runtime. It starts with a small (~2 KB) stack that grows/shrinks as needed, unlike an OS thread which has a fixed, usually larger stack allocated by the kernel. The GMP model: **G**oroutine (runnable unit), **M** OS thread, **P**rocessor (holds a local runqueue). The scheduler assigns Gs to Ms via Ps, pre‑emptively switching based on work availability and syscalls.

**G4** – A channel is a typed conduit for communication. An unbuffered channel blocks the sender until a receiver is ready and vice‑versa. A buffered channel holds up to its capacity values; sends block only when the buffer is full, receives block only when empty. Sending to a full buffered channel blocks until space becomes available (or the sender is unblocked by a close or select).

**G5** – `context` carries cancellation signals, deadlines, and request‑scoped values across API boundaries. Minimal example:

```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
resp, err := http.DefaultClient.Do(req)
// handle err, resp
```

**G6** – Interface satisfaction is implicit: any type that implements all methods of an interface automatically satisfies it, no `implements` keyword. Contrast with Java/C# where you must declare `implements`. The empty interface `interface{}` (alias `any`) can hold a value of any type; it’s powerful for generic containers but loses compile‑time type safety, requiring type assertions or switches to recover the concrete type.

**G7** – The Go memory model guarantees visibility only when there is proper synchronization (mutex, channel, atomic). Without it, the write to `data` may not be visible to the reader loop, causing a data race. Correct alternatives: use a `sync.WaitGroup`, a channel, or an `atomic.Bool`/`sync.Mutex` to publish `ready` after `data` is written.

**G8** – `sync.Mutex` provides exclusive lock. `sync.RWMutex` allows many concurrent readers or a single writer. `sync.Map` is optimized for read‑heavy workloads with many reads and few writes; it avoids mutex contention on reads but is slower for writes and iteration compared to a regular map + mutex, which is simpler and faster when reads/writes are balanced or write‑heavy.

**G9** – Go modules manage dependency versioning. `go.mod` declares the module path and its direct dependencies with minimum versions. `go.sum` contains cryptographic checksums of exact module versions to ensure integrity. `go mod tidy` removes unused dependencies, adds missing ones, and synchronizes `go.mod` and `go.sum`. The Minimum Version Selection (MVS) algorithm picks the lowest versions that satisfy all requirements, avoiding version diamond problems.

**G10** – `defer` schedules a function call to run after the surrounding function returns. Multiple defers execute in LIFO order. Gotcha: a `defer` inside a loop defers each iteration but all run only after the function ends, potentially accumulating resources (e.g., file handles). Fix by wrapping the loop body in another function or calling a helper that does the defer inside the loop.

**G11** – A pointer holds the memory address of a variable. Its zero value is `nil`. Create a pointer to a struct literal with `&MyStruct{...}` or `new(MyStruct)` (which returns `*MyStruct` zero‑initialized).

**G12** – `init()` runs after all imported packages are initialized and before `main.main` (or package init for libraries). A file may contain multiple `init` functions; they execute in lexical order within the file, then files are processed in alphabetical order. A package can have many `init`s; overall order is deterministic but not guaranteed across builds unless you rely on explicit dependencies.

**G13** – `make` creates initialized slices, maps, and channels (allocating their internal data structures) and returns the value (not a pointer). `new` allocates zeroed storage for any type and returns a pointer to it (`*T`). Use `make` for the three built‑in types that need internal buffers; `new` for pointers to other types.

**G14** – The `error` interface is `type error interface { Error() string }`. Idiomatic handling:

```go
if err != nil {
    return err // or wrap/log
}
```

`errors.Is(err, target)` walks the error chain via `Unwrap` to see if `err` matches a sentinel value. `errors.As(err, &targetType)` checks if `err` (or its chain) is of a specific type and assigns it. Both are safer than `==`, which only matches the exact error value.

**G15** – Built‑in composite types: array, slice, map, channel, struct. Zero values: array – each element zeroed; slice – `nil`; map – `nil`; channel – `nil`; struct – each field zeroed according to its type.

**G16** – A race condition occurs when two goroutines access shared memory concurrently with at least one write, without synchronization. The `-race` flag instruments the code to detect such accesses. Example:

```go
var counter int
go func(){ counter++ }()
go func(){ counter++ }()
time.Sleep(time.Millisecond)
fmt.Println(counter) // may be 1
```

Fix with `sync.Mutex` or `atomic.AddInt64(&counter, 1)`.

**G17** – `select` waits on multiple channel operations, picking one that is ready. If several are ready, it chooses pseudo‑randomly. Unlike `switch`, which evaluates expressions, `select` only works on channel sends/receives (and a default). Timeout pattern:

```go
select {
case res := <-ch:
    // use res
case <-time.After(2 * time.Second):
    // timeout
}
```

**G18** – Escape analysis determines whether a variable’s address escapes the function. If it does not escape, the compiler allocates it on the stack; otherwise it goes to the heap. Inspect with `go build -gcflags=-m`. Matters because heap allocation incurs GC pressure; stack allocation is cheaper and avoids GC.

**G19** – `reflect.Type` describes a type; `reflect.Value` holds a value of that type and allows inspection/modification. Reflection is slow due to runtime type information and allocations; justified for generic libraries (`encoding/json`, `fmt`) or when static types are unknown. For performance‑critical code, prefer code generation (`go generate`) or interfaces.

**G20** – `//go:embed` tells the Go compiler to include files or directories in the binary. It can bind to a `[]byte`, `string`, or `embed.FS`. Limitations: requires Go 1.16+, embedded files must be accessible at build time, and very large embeds (>2 GB) may hit OS limits. `embed.FS` implements `io/fs.FS`, allowing use with `fs.Sub`, `http.FS`, etc.

**Rust**

**R1** – Ownership rules: (1) Each value has a single owner. (2) When the owner goes out of scope, the value is dropped. (3) Ownership can be moved (transfer) or borrowed (references). Only one mutable reference **or** any number of immutable references may exist at a time, and references must be valid for their lifetime.

**R2** – `String` is an owned, heap‑allocated, mutable UTF‑8 buffer. `&str` is an immutable borrowed slice (view) into UTF‑8 data. Use `String` when you need ownership or to mutate the text; use `&str` for read‑only parameters or when you only need a view.

**R3** – Borrowing: shared reference `&T` allows multiple readers; mutable reference `&mut T` grants exclusive read/write access. The borrow checker enforces that you cannot have a mutable reference coexist with any other reference to the same data, and that all references are valid for their inferred lifetimes.

**R4** – `Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents presence (`Some(T)`) or absence (`None`). The `?` operator propagates errors: if the operand is `Err(e)`, return `Err(e)` from the enclosing function; if `Ok(v)`, unwrap `v`. For `Option`, `?` returns `None` or unwraps `Some`. Example:

```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

**R5** – `Box<T>`: heap allocation with a single owner. `Rc<T>`: reference‑counted pointer for shared ownership **within a single thread** (not thread‑safe). `Arc<T>`: atomic reference‑counted pointer, safe to share across threads. Use `Box` for exclusive ownership, `Rc` for cheap shared read‑only data in one thread, `Arc` when you need shared ownership across threads.

**R6** – Traits define shared behavior (like interfaces) but can also have associated types, default methods, and const items. A trait object `dyn Trait` erases the concrete type and uses a vtable for dynamic dispatch; a generic `T: Trait` is monomorphized, producing a copy of the function per concrete type (static dispatch). Trait objects incur indirection; generics give zero‑cost abstraction but increase compile time and binary size.

**R7** – The function lacks a lifetime tying the returned reference to the inputs, so the compiler cannot guarantee the reference lives long enough. Fix by adding an explicit lifetime:

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** – `Send`: safe to transfer ownership of the type to another thread. `Sync`: safe to share a reference (`&T`) between threads. `Rc` uses a non‑atomic reference count, so it is neither `Send` nor `Sync`. `Arc` uses atomic operations for the count, making it both `Send` and `Sync`.

**R9** – An `async fn` returns a type that implements `Future`. A `Future` is a state machine whose `poll` method advances it toward completion; it yields when waiting on an I/O operation. An executor (e.g., Tokio’s runtime) drives futures by repeatedly calling `poll` until they return `Ready`. Unlike Go’s goroutines, which are managed by a built‑in scheduler and can be pre‑empted at safe points, Rust futures are lazy and require an external executor to make progress.

**R10** – In an `unsafe` block you can: (1) dereference raw pointers (`*const T`, `*mut T`); (2) call functions or methods marked `unsafe`; (3) implement or access `unsafe` traits; (4) read/write mutable static variables; (5) access fields of unions. Use `unsafe` when you need to interact with foreign code, implement low‑level data structures, or perform optimizations where you can uphold the safety invariants yourself.

**R11** – Pattern matching lets you destructure values and bind variables. `match` evaluates a value against multiple arms; `if let` is a shorthand for matching a single pattern with an optional else. The compiler enforces exhaustiveness: every possible variant of the type must be covered, unless a `_` wildcard is used.

**R12** – `Vec<T>` is a growable, heap‑allocated buffer; `[T; N]` is a fixed‑size array stored on the stack (or in the data segment). When `Vec`’s length exceeds its capacity, it allocates a new, larger buffer (commonly doubling capacity), copies or moves the existing elements, and frees the old buffer.

**R13** – Enums are algebraic data types that can hold data in each variant, unlike C/Java enums which are essentially integer constants. `Option<T>` is defined as `enum Option<T> { Some(T), None }`; it forces explicit handling of the absent case, eliminating null pointers.

**R14** – An `impl block` defines methods associated with a type. `&self` – read‑only borrow; `&mut self` – mutable borrow; `self` – takes ownership (move). Associated functions have no receiver (e.g., `String::new()`) and act like constructors or namespaced functions.

**R15** – `derive` macro automatically generates trait implementations for a struct or enum. Commonly derived: `Debug`, `Clone`, `PartialEq`, `Eq`, `Hash`, `Serialize` (via `serde`). You cannot derive traits that require custom logic (e.g., `Display`, `FromStr`) or traits with associated types/generic constraints that the compiler cannot infer without guidance.

**R16** – `Cow<'a, T>` (Clone‑On‑Write) is an enum: `Borrowed(&'a T)` or `Owned(T)`. It lets an API accept either borrowed or owned data without cloning unless mutation is needed. Example:

```rust
fn shout(s: &str) -> Cow<str> {
    if s.contains('a') {
        Cow::Owned(s.to_uppercase())
    } else {
        Cow::Borrowed(s)
    }
}
```

If the input already satisfies the condition, no allocation occurs.

**R17** – Module system: `mod` declares a module; `use` brings names into scope; `pub` controls visibility. The file system mirrors the module tree: `src/main.rs` or `src/lib.rs` is the crate root; a module `foo` can be `src/foo.rs` or `src/foo/mod.rs`. The 2018 edition simplified paths (`crate::`, `super::`) and removed the need for `extern crate`; visibility rules became more uniform.

**R18** – `Pin<T>` guarantees that the value pointed to will not be moved in memory after being pinned. This is essential for self‑referential structs (e.g., async futures that store pointers to their own fields) because moving would invalidate those internal pointers. `Unpin` is a marker trait indicating a type can be safely moved even when pinned; most types implement `Unpin` automatically, so you only need `Pin` for `!Unpin` types.

**R19** – Rust macros: declarative (`macro_rules!`) match token trees and produce code; procedural macros (custom `derive`, attribute, function‑like) receive a `TokenStream`, parse it, and output a new `TokenStream`. Hygiene ensures macros do not accidentally capture or clash with identifiers from the call site; they operate in a separate syntactic scope.

**R20** – Zero‑cost abstractions mean high‑level constructs compile to code with no runtime overhead compared to hand‑written C. Iterators are lazy and compile to inline loops; generics are monomorphized, producing a concrete copy per type; trait dispatch uses static monomorphization (or inline) when possible, eliminating vtable indirection. Thus you get safety and expressiveness without sacrificing performance.
