
**JavaScript / TypeScript**

**JS1** – `var` is function‑scoped and hoisted; `let` and `const` are block‑scoped, not initialized until their declaration (Temporal Dead Zone). Hoisting moves declarations to the top of their scope; `var` gets an initial `undefined`, while `let/const` remain uninitialized.

**JS2** – The event loop continuously checks the call stack. When the stack is empty, it pulls the oldest task from the macrotask queue (e.g., setTimeout, I/O). After each macrotask, it drains the microtask queue (promise reactions, queueMicrotask) until empty, then repeats.

**JS3** – A closure is a function that retains access to variables from its outer lexical scope after that scope has exited.  
*Example:* `function makeCounter(){ let c=0; return()=>++c; }`  
*Classic for‑loop bug:* `for(var i=0;i<3;i++) setTimeout(()=>console.log(i),0)` prints `3,3,3` because `i` is shared. Fix with `let` (`for(let i…)`) or wrap in an IIFE: `setTimeout((function(j){return()=>console.log(j);})(i),0)`.

**JS4** – A `Promise` represents a future value; `.then`/`catch` handle fulfillment/rejection. `async/await` is syntactic sugar that makes asynchronous code look synchronous; errors are caught with `try/catch`. `Promise.all` resolves when all promises settle successfully, rejecting on the first rejection. `Promise.allSettled` waits for all to settle (fulfill or reject) and returns an array of status objects.

**JS5** – `interface` describes object shape and can be reopened/declared merged; `type` creates a type alias for any type (primitives, unions, tuples, etc.) and cannot be reopened. Use `interface` for public object contracts that may be augmented; use `type` for complex aliases, mapped types, or when you need features like `&` intersections. Discriminated unions use a common literal property (the discriminant) to narrow types: `type Shape = {kind:"circle", r:number}|{kind:"square", side:number};`.

**JS6** – Prototypal inheritance: objects have an internal `[[Prototype]]` link to another object; property lookup walks this chain. `Object.create(proto)` creates a new object whose `[[Prototype]]` is `proto`. ES6 `class` syntax is syntactic sugar over the same prototype mechanism; `class Foo {}` creates a constructor function whose `prototype` holds methods.

**JS7** – `this` binding priority: 1) **New binding** (`new Foo()`), 2) **Explicit binding** (`call/apply/bind`), 3) **Implicit binding** (`obj.foo()`), 4) **Default binding** (global or `undefined` in strict mode). `bind()` returns a new function with `this` permanently bound; you cannot change that binding later, but you can call `bind` again on the returned function to produce another bound function.

**JS8** – `WeakRef<T>` holds a weak reference to an object, allowing it to be GC‑collected while still accessible if alive. `FinalizationRegistry` registers a callback to run when a registered object is GC’d. Use them for caching or cleanup without preventing collection. `WeakMap` keys must be objects because only objects can be weakly held; primitives are immutable and would stay alive forever, defeating the purpose.

**JS9** – V8 optimizes via hidden classes (shape transitions) for fast property access, inline caching (caching method lookups based on observed hidden classes), and deoptimization when assumptions break (e.g., adding a property after many accesses, changing prototype, using `with`, or mixing types in arrays). Patterns causing deopt: polymorphic property access, deleting properties, changing `__proto__`, using `eval`/`with`, or storing mixed types in a packed array.

**JS10** – Tree‑shaking eliminates dead code by analyzing ES module import/export graphs; unused exports are dropped. ES modules are static, enabling this analysis. CommonJS uses dynamic `require`/`module.exports`, which cannot be statically determined, so tree‑shaking is ineffective; bundlers must keep the whole module.

**JS11** – `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` treats both as equal (`null == undefined` true) and coerces other types; `===` checks strict type and value, so they differ. Nullish coalescing `??` returns the right‑hand side when the left is `null` or `undefined`. Optional chaining `?.` short‑circuits property access if the left side is `null` or `undefined`.

**JS12** – `map` returns a new array of transformed values; `filter` returns elements that satisfy a predicate; `reduce` accumulates a single value, optionally starting with an initial value (second argument). `flatMap` maps then flattens one level; useful when a mapping may produce zero or multiple items per input (e.g., splitting strings into words).

**JS13** – Template literals use backticks and allow `${expression}` interpolation. Tagged templates parse the literal into an array of raw strings and the evaluated expressions, passing them to a tag function.  
*Example (HTML escape):*  
```js
function html(strings, ...values) {
  return strings.reduce((acc, s, i) => acc + s + (values[i] ?? '').replace(/[&<>"']/g, c=>({ '&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;' }[c]), '');
}
const name = "<script>";
console.log(html`Hello ${name}!`); // Hello &lt;script&gt;!
```

**JS14** – Destructuring unpacks values. Object: `{a, b = 2, c: newName} = obj` (renaming with `:`, default `=`). Array: `[x, y, ...rest] = arr`. Rest operator gathers remaining elements into an array (or object properties). Works similarly in both contexts.

**JS15** – `for…in` iterates over enumerable **property keys** (strings) of an object, including inherited ones. `for…of` iterates over **iterable values** (arrays, strings, maps, sets, etc.). Avoid `for…in` on arrays because it yields indices as strings and may include non‑numeric enumerable properties, leading to unexpected order and performance issues.

**JS16** – Generics let you parameterize types. Constraints: `function foo<T extends Base>(x: T) {}` ensures `T` has `Base` members. Conditional types: `type IsString<T> = T extends string ? true : false`. `infers` extracts a type: `type ReturnType<T> = T extends (...args:any)=>infer R ? R : never`.  
*Examples:*  
- Constraint: `function length<T extends {length:number>}(x:T){return x.length;}`  
- Conditional: `type NonNullable<T> = T extends null | undefined ? never : T;`  
- Infer: `type PromiseValue<T> = T extends Promise<infer V> ? V : never;`

**JS17** – CommonJS uses `require()`/`module.exports`; ES Modules use `import`/`export`. Node.js treats files as CJS unless `"type":"module"` in `package.json` (or `.mjs` extension) makes them ESM; you can intermix via `import()` dynamic import or `createRequire`. ESM supports static analysis, top‑level await, and proper cyclic handling.

**JS18** – TypeScript’s structural system matches types by shape, not nominal brand. Excess property checks occur when assigning object literals to typed targets; only known properties are allowed unless indexed signatures or type assertions are used. `extends` creates a derived type or constraint; `satisfies` (TS 4.9) validates that an expression matches a type without changing its inferred type. Variance (`in`/`out`) on generic parameters (TS 4.7) marks contravariant (`in`) and covariant (`out`) positions, enabling safer generic usage in function parameters and return types.

**JS19** – `Proxy` creates an object that intercepts operations via handlers (`get`, `set`, `apply`, etc.). `Reflect` provides mirror functions that forward to the target, useful inside proxies.  
*Example (validation):*  
```js
const validator = {
  set(target, prop, value) {
    if (prop === 'age' && typeof value !== 'number') throw new TypeError('age must be number');
    return Reflect.set(target, prop, value);
  }
};
const person = new Proxy({}, validator);
person.age = 25; // ok
person.age = 'twenty'; // TypeError
```

**JS20** – `SharedArrayBuffer` provides a raw binary buffer that can be shared between the main thread and Web Workers. `Atomics` offers static methods (`Atomics.store`, `load`, `add`, `wait`, `notify`) for safe read‑modify‑write operations with defined memory ordering (sequentially consistent by default). Workers postMessage the buffer; each side can `Atomics.wait` on an index to block until another thread `Atomics.notify`s the same index, enabling mutex‑like coordination.

**Bash**

**B1** – `$@` expands to each positional parameter as separate words; `$*` expands to a single word containing all parameters separated by the first character of `IFS`. Quoted: `"$@"` preserves each parameter as a separate quoted word; `"$*"` yields one quoted string with parameters joined by `IFS[0]`.

**B2** – `set -e` exits on any command returning non‑zero (unless in conditional). `set -u` treats unset variables as an error. `set -o pipefail` makes a pipeline’s exit status the status of the last command to exit non‑zero (or zero if all succeed). Together they cause scripts to fail fast and avoid silent bugs.

**B3** – `$(command)` and backticks `` `command` `` both capture command output; `$(…)` is preferred for nesting and readability. `$((expression))` performs arithmetic expansion; `expr` is an external command for arithmetic or string operations, slower and less flexible.

**B4** – Process substitution `<(command)` creates a named pipe (or `/dev/fd`) whose contents are the command’s stdout, allowing it to be used as a file input. Example: `diff <(sort file1) <(sort file2)` compares sorted outputs without temporary files.

**B5** – Safely iterate with `while IFS= read -r -d '' f; do … done < <(find . -type f -print0)`. Using `for f in $(ls)` breaks on spaces/newlines because word splitting occurs on the unquoted expansion, and `ls` output is not safe for parsing.

**B6** – Here document `<<EOF` feeds lines to a command’s stdin until a line containing only the delimiter. Here string `<<<"data"` feeds a single string. `<<-EOF` strips leading tabs from each line of the document (allowing indentation in scripts).

**B7** –  
- `cmd > file 2>&1`: stdout → file, then stderr redirected to wherever stdout currently points (the file). Result: both streams in `file`.  
- `cmd 2>&1 > file`: stderr → current stdout (usually terminal), then stdout → file. Result: stderr goes to terminal, stdout to file.  
- `cmd &> file` is shorthand for redirecting both stdout and stderr to `file`. The order matters because redirections are processed left‑to‑right.

**B8** –  
```bash
lockfile() {
  local lock_dir="/tmp/mylock.$$"
  if mkdir "$lock_dir" 2>/dev/null; then
    trap 'rm -rf "$lock_dir"' EXIT INT TERM
    return 0
  else
    echo "Lock already held" >&2
    return 1
  fi
}
```
`mkdir` is atomic; if it succeeds we hold the lock. The trap removes the directory on script exit or signals, ensuring cleanup even on SIGTERM. Using a file (`> lock`) is not atomic and can suffer from race conditions between check and creation.

**B9** – Single quotes `'` prevent all expansion; double quotes `"` allow variable, command, and arithmetic expansion but not pathname expansion or word splitting. No quotes perform full expansion (word splitting, globbing). Example: `var="a b"`; `echo $var` → two words; `echo "$var"` → one word; `echo '$var'` → literal `$var`.

**B10** – `[ -e file ]` (or `test -e file`) checks existence; `[ -d file ]` for directory; `[ -r file ]` for readable. `[[ … ]]` is a bash keyword that provides pattern matching (`==`), regex (`=~`), and avoids word splitting/globbing inside, making it safer and more feature‑rich than `[ ]`.

**B11** – `$?` – exit status of the most recent foreground pipeline. `$$` – PID of the current shell. `$!` – PID of the most recent background command. `$#` – number of positional parameters passed to the script or function. Use `$?` for error checking, `$$` for temp‑file naming, `$!` to wait on a background job, `$#` to validate argument count.

**B12** – Define with `foo() { … }` or `function foo { … }` (both equivalent; the former is POSIX‑style). Return status via `return N` (0‑255); to return data, echo/capture or modify a variable passed by name. Example:  
```bash
add() { echo $(( $1 + $2 )); }
result=$(add 3 5)   # result=8
```

**B13** – `PATH` is a colon‑separated list of directories searched for executables. Bash checks each directory in order; if a command contains a slash it’s taken as a path. Builtins (e.g., `cd`, `echo`) are looked up before PATH; use `type -a cmd` to see all implementations, `command cmd` to bypass aliases/functions and run the external version.

**B14** – `trap 'handler' SIGNAL` registers a handler. Example:  
```bash
cleanup() { echo "Cleaning"; rm -f /tmp/tmpfile; }
trap cleanup EXIT
trap 'echo "Interrupted"; exit 1' INT TERM
trap 'echo "Error on line $LINENO"' ERR
```
When multiple signals arrive, they are queued and handled in the order they are delivered after the current command finishes; `EXIT` runs last regardless of order.

**B15** – `xargs` reads items from stdin and executes a command with them; command substitution `$(…)` captures output as a string. To handle spaces/newlines, use `-0` with NUL‑delimited input: `find . -type f -print0 | xargs -0 -n1 -P4 process`. `-P` runs that many processes in parallel.

**B16** – Indexed arrays: `declare -a arr; arr+=("elem"); for i in "${!arr[@]}"; do …; done; len=${#arr[@]}`. Associative arrays: `declare -A map; map[key]=value; for k in "${!map[@]}"; do …; done; len=${#map[@]}`. Bash does not support multidimensional arrays natively; associative arrays require Bash 4+.

**B17** – Subshell `( … )` runs commands in a separate child process; variable changes do not affect the parent. Group command `{ …; }` runs in the current shell (just a different grouping for redirections). Piping into a `while` loop creates a subshell for the loop body, so variable modifications inside are lost; use process substitution or `mapfile` to avoid.

**B18** – Signals: `SIGINT` (Ctrl‑C) requests graceful interrupt; `SIGTERM` is the default termination request; `SIGHUP` indicates terminal hang‑up; `SIGKILL` cannot be caught and kills immediately. To handle graceful shutdown, trap `TERM`, `INT`, `HUP`; wait for background jobs with `wait`; ensure cleanup runs in the trap.

**B19** –  
```bash
#!/usr/bin/env bash
set -euo pipefail
process_chunk() {
  local chunk=$1
  # e.g., count errors
  grep -c ERROR "$chunk"
}
export -f process_chunk   # needed for subshells
split -l 10000 big.log part_
for f in part_*; do
  echo "$f"
done | xargs -P$(nproc) -I{} bash -c 'process_chunk "$@"' _ {}
# collect results (e.g., sum)
total=0
for f in part_*; do
  total=$(( total + $(process_chunk "$f") ))
done
echo "Total errors: $total"
```
Trade‑offs: parallelism reduces wall‑clock time but increases CPU/I/O contention; error propagation requires checking each chunk’s exit status (`set -e` inside the chunk or inspect `$?`). Using `xargs -P` limits the number of concurrent workers.

**B20** – `exec` replaces the current shell process with the given command (no new PID). Without a command, `exec` manipulates file descriptors: `exec 3>file` opens fd 3 for writing; `exec 3>&-` closes it. To create a coprocess: `coproc myproc { while read -r line; do echo "[$line]"; done; }` then read/write via `${myproc[0]}` (read) and `${myproc[1]}` (write). Useful for bidirectional communication with a long‑running process without managing explicit pipes.

**PowerShell**

**PS1** – `Write-Output` sends objects down the pipeline (the default output stream). `Write-Host` writes directly to the host console, bypassing the pipeline; output cannot be captured or further processed. Use `Write-Output` (or simply leave the value unquoted) for pipeline‑friendly functions; `Write-Host` for purely informational messages.

**PS2** – The pipeline passes objects one‑by‑one from left to right. `ForEach-Object` (`%`) is a cmdlet that receives each object via the pipeline and executes a script block. `foreach` statement is a language construct that enumerates a collection; it does not participate in the pipeline and is faster for simple in‑memory loops. Use `ForEach-Object` when you need to stream data or participate in a larger pipeline; use `foreach` for pure iteration over an already‑in‑memory array.

**PS3** – `[PSCustomObject]` is a typed object with properties accessible via dot notation; `[hashtable]` is a dictionary of key/value pairs. Convert hashtable → PSCustomObject with `[pscustomobject]$hash`. Convert PSCustomObject → hashtable with `$obj.PSObject.Properties | ForEach-Object { @{ $_.Name = $_.Value } }` or simply `$obj | ConvertTo-Json | ConvertFrom-Json` (though less efficient). Use PSCustomObject when you need a stable object shape; use hashtable for quick lookup or configuration bags.

**PS4** – Terminating errors stop pipeline execution unless caught; non‑terminating errors (e.g., from cmdlets with `-ErrorAction SilentlyContinue`) allow continuation. `-ErrorAction` overrides `$ErrorActionPreference` for a single call. `try { … } catch [System.Exception] { … }` catches terminating errors; non‑terminating errors are not caught unless `-ErrorAction Stop` is used or `$ErrorActionPreference` is set to `Stop`.

**PS5** – Splatting passes a collection of parameters as a hash table or array using `@params`. Example:  
```powershell
$opts = @{ Path = 'C:\temp'; Recurse = $true }
Get-ChildItem @opts
```
This is equivalent to `Get-ChildItem -Path $opts.Path -Recurse $opts.Recurse`. Passing a hashtable as a *single* positional argument (`Get-ChildItem $opts`) treats the hashtable itself as the value for the first parameter, not as a collection of parameters.

**PS6** – PowerShell remoting uses WS‑Management (WinRM) over HTTP/HTTPS by default; PowerShell 7+ also supports SSH. `Invoke-Command -ComputerName target { … }` runs a script block on one or more machines and returns results. `Enter-PSSession` starts an interactive session (like `ssh`). Both rely on the same underlying WS‑Man listener; SSH uses the `ssh` subsystem.

**PS7** – In the function, `$result` is an array; returning it causes PowerShell to *unwrap* the array because the pipeline enumerates collections. Thus `$x` receives the elements, not the array itself, so `$x.GetType().Name` is `String` (the first element). If the function returns zero items, `$x` becomes `$null` and accessing `.GetType()` throws. Correct pattern: return the array wrapped in a single‑element array or use the comma operator: `return ,$result` or `return @($result)` to preserve the array as a single pipeline object.

**PS8** – `[scriptblock]` is a literal piece of code that can be invoked with `&`. A function is a named scriptblock with its own scope. You can pass a scriptblock to a remote session via `-ArgumentList` (it gets serialized) or by using `Invoke-Command -ScriptBlock { … } -ArgumentList $sb`. The double‑hop problem occurs when credentials used for the first hop cannot be delegated to a second remote machine; solve with CredSSP (enables delegation) or by using `Invoke-Command -ComputerName second -ScriptBlock { … } -Authentication CredSSP -Credential $cred` or by passing needed data via `-ArgumentList` instead of relying on delegated credentials.

**PS9** – `@()` forces an array (even if empty or single element). `[array]` is a type literal; casting `[array]$x` converts `$x` to an array, but if `$x` is already a scalar it becomes a one‑element array. Indexing `$null` returns `$null`; indexing an empty array (`@()[0]`) returns `$null` as well (no error). To guarantee an array, use `@($value)`.

**PS10** – Comparison operators: `-eq`, `-ne` (equality); `-like`, `-notlike` (wildcard); `-match`, `-notmatch` (regex); `-contains`, `-notcontains` (checks if a collection *contains* a value); `-in`, `-notin` (checks if a value *is in* a collection). Case‑sensitive variants prefix with `c` (`-ceq`, `-clike`, etc.). `-contains` tests membership of a value inside a collection on the left (`$arr -contains $val`). `-in` tests the opposite: `$val -in $arr`. They are not interchangeable; `-contains` expects the collection first.

**PS11** – A PowerShell module is a reusable unit of code. Types:  
- **Script module** (`.psm1`) – contains functions, variables, etc.  
- **Manifest module** (`.psd1`) – metadata file that can accompany a script module or binary module, describing version, GUID, required modules, etc.  
- **Binary module** (`.dll`) – compiled cmdlets (usually C#).  
`Import-Module` loads the module, making its exported commands available; with a manifest you can also specify `-MinimumVersion`, `-RequiredVersion`, etc.

**PS12** – Double‑quoted strings (`"..."`) allow expression expansion: `"The value is $($x)"`. Single‑quoted strings (`'...'` ) treat contents literally, no expansion. Here‑string (`@" ... "@` or `@' ... '@`) spans multiple lines; the double‑quoted version allows interpolation, the single‑quoted version does not. Example:  
```powershell
$name = "World"
@"Hello $name!"@   # Hello World!
@'Hello $name!'@   # Hello $name!
```

**PS13** – `Get-Member` (alias `gm`) shows an object’s members: properties, methods, noteproperties, scriptproperties, etc. `Properties` are .NET properties; `Methods` are methods; `NoteProperties` are static data members added via `Add-Member`. `Select-Object` chooses or renames properties (can also compute calculated properties). `Where-Object` filters objects based on a condition. Use `Select-Object` to shape output; use `Where-Object` to filter.

**PS14** – PowerShell classes (v5+) resemble C# classes but are limited: no parameterless constructors (must define `()`), no static constructors, no interfaces, no partial classes, and inheritance is single‑only. They are useful for encapsulating state and behavior when you need object‑oriented design; otherwise, functions with PSCustomObject returns are simpler and more idiomatic.

**PS15** – `[CmdletBinding()]` makes a function behave like a compiled cmdlet, enabling features: `-Verbose`, `-Debug`, `-ErrorAction`, `-ErrorVariable`, `-WarningAction`, `-WhatIf`, `-Confirm`. `SupportsShouldProcess` adds `-WhatIf`/`-Confirm` support. `DefaultParameterSetName` selects which parameter set to use when ambiguous. `ValueFromPipeline` allows a parameter to accept pipeline input. `Begin`, `Process`, `End` blocks run once at start, once per pipeline object, and once at end, respectively.

**PS16** – Providers expose data stores as PSDrives (e.g., `C:` for filesystem, `HKLM:` for registry). `Get-ChildItem` works across providers by using the PSDrive name: `Get-ChildItem HKLM:\Software`. You can navigate the registry like a file system: `Set-Location HKLM:\`, `Get-ChildItem`, `New-Item`, `Remove-Item`. Other providers include `Cert:\`, `Env:\`, `Variable:\`, `Alias:\`.

**PS17** – A `[runspace]` is an isolated execution environment; a `[runspacepool]` groups runspaces for reuse; a `[powershell]` object holds a pipeline to run in a runspace. `ForEach-Object -Parallel` (PS 7+) automatically creates a runspacepool and invokes the script block per input item, handling throttling via `-ThrottleLimit`. Manual runspace management gives finer control (e.g., sharing state, custom initialization) but requires more boilerplate.

**PS18** – `PSScriptAnalyzer` is a static‑code‑analysis tool that checks scripts against rules (e.g., PSAvoidUsingWriteHost, PSUseDeclaredVarsMoreThanAssign). Rules have severity levels (`Error`, `Warning`, `Information`). Custom rules can be written as scriptblock‑based or AST‑based suppressions via `# <# .SYNOPSIS ... #>` or `SuppressMessage` attributes. In CI/CD, invoke `Invoke-ScriptAnalyzer` and fail the build on any Error‑level results.

**PS19** – `$using:` allows a script block invoked in a remote session, background job, or `ForEach-Object -Parallel` to refer to variables from the calling scope without serialization; the variable’s value is copied into the session’s scope. `$args`/`-ArgumentList` passes values explicitly; they are serialized via CLIXML, which has a depth limit (default 32). Deeply nested objects may be truncated or cause serialization errors; using `$using:` avoids this limit because the variable is transferred by reference within the same process (for local jobs) or via session state (still serialized but with higher limits). For truly large objects, consider passing only needed identifiers or using shared storage.

**PS20** – Desired State Configuration (DSC) defines a declarative configuration (`Configuration` block) that lists resources (e.g., `File`, `Service`, `WindowsFeature`) and their desired state. The Local Configuration Manager (LCM) applies and maintains that state. In Windows PowerShell, DSC relied on MOF files and the DSC engine; PowerShell 7+ uses a cross‑platform DSC implementation based on resources written in PowerShell and the `PSDesiredStateConfiguration` module. Modern IaC (e.g., Terraform, Ansible, Pulumi, AWS CDK) has largely superseded DSC for cloud infrastructure, though DSC remains useful for Windows server configuration drift management.
