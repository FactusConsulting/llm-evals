### **.NET / C# Answers**

**DN1** – A **class** is a reference type (heap-allocated), while a **struct** is a value type (stack-allocated by default). Use a **struct** for small, immutable, performance-critical data (e.g., `Point`, `DateTime`). Avoid structs for large or mutable data due to copying overhead.

**DN2** – `IEnumerable<T>` executes queries in-memory (LINQ-to-Objects), while `IQueryable<T>` builds expression trees for deferred execution (e.g., LINQ-to-SQL). The distinction matters because `IQueryable<T>` translates queries to SQL, avoiding client-side evaluation.

**DN3** – `async/await` enables non-blocking I/O. A **Task** represents an asynchronous operation, while **ValueTask** avoids heap allocation for synchronous completions. Use `ValueTask` for high-performance scenarios (e.g., caching) where the result is often immediately available.

**DN4** – Dependency Injection (DI) in .NET manages object lifetimes. **Transient** (new instance per request), **Scoped** (per HTTP request), **Singleton** (app lifetime). **Bug**: Injecting a **Scoped** service into a **Singleton** causes stale data (the Scoped instance lives longer than intended). Fix: Use `IServiceProvider` or avoid Scoped-in-Singleton.

**DN5** – `string` is immutable and heap-allocated; `ReadOnlySpan<char>` is a stack-allocated or sliced view of chars (zero-copy). Use `Span<T>` for high-performance parsing (e.g., UTF-8 processing) to avoid allocations.

**DN6** – The GC manages memory via **generations** (Gen 0: short-lived, Gen 1: survived Gen 0, Gen 2: long-lived). The **Large Object Heap** (LOH) stores objects >85KB (not compacted by default). **IDisposable** releases unmanaged resources (e.g., file handles) since GC doesn’t handle them.

**DN7** – `ConfigureAwait(false)` avoids capturing `SynchronizationContext` (improves performance in non-UI contexts). **Do not use** in UI apps (e.g., WPF) where context is needed for updates. Default behavior captures context, which can cause deadlocks if `.Result` is called on a task.

**DN8** – **Primary constructors** (C# 12+) allow declaring constructor parameters directly in the class:
```csharp
public class Person(string name) { public string Name { get; } = name; }
```
**Collection expressions** (C# 12+) unify list/array/span initialization:
```csharp
int[] arr = [1, 2, 3];
```
**FrozenDictionary** (immutable, high-performance) is useful for read-only dictionaries. Example with DI:
```csharp
public class Service(IFrozenDictionary<string, int> config) { ... }
```

**DN9** – **Cause**: DbContext is **Scoped**, but high concurrency leads to thread-sharing or premature disposal. **Fix**: Ensure DbContext is **not** shared across threads (use `Async` methods) and avoid `ConfigureAwait(false)` in EF Core. EF Core’s DbContext is **not thread-safe**; each request should get its own instance via DI.

**DN10** – **Record** is immutable by default (value-based equality), while **class** is mutable (reference-based). **Record struct** combines value semantics with struct allocation. Use **record** for DTOs, **record struct** for performance-critical immutable data.

**DN11** – `ref` passes by reference (must be initialized), `out` passes by reference (no initialization required), `in` passes by read-only reference (avoids copying). Use `ref` for large structs, `out` for multiple return values, `in` for read-only parameters.

**DN12** – **Nullable reference types** (`string?`) are compile-time checks for nullability (enabled via `#nullable enable`). **Nullable value types** (`int?`) are runtime nullable (backed by `Nullable<T>`). The former is for static analysis; the latter is for runtime nulls.

**DN13** – **LINQ** (Language Integrated Query) enables query syntax over collections. **Method syntax** (`list.Where(x => x > 1)`) vs **query syntax** (`from x in list where x > 1 select x`) are equivalent. **Deferred execution** means queries execute when enumerated (e.g., `ToList()`).

**DN14** – **Generic constraints** restrict type parameters:
- `where T : class` (must be reference type)
- `where T : struct` (must be value type)
- `where T : new()` (must have parameterless constructor)
- `where T : IComparable<T>` (must implement interface).
Combine constraints for complex requirements (e.g., `where T : class, IComparable<T>, new()`).

**DN15** – **Abstract class** can have state/implementation; **interface** is a contract (no state). **Default interface methods** (C# 8+) allow interfaces to provide implementations, blurring the distinction (but interfaces still can’t have fields).

**DN16** – **Middleware pipeline** processes HTTP requests in order. `app.Use()` runs on every request (short-circuiting if no `next()`). `app.Map()` branches based on path. `app.Run()` terminates the pipeline. **Order matters**: Exception handling middleware should be first to catch errors in subsequent middleware.

**DN17** – **Channel<T>** is a producer-consumer buffer with backpressure (bounded/unbounded). **BlockingCollection<T>** is older and less efficient. Example:
```csharp
var channel = Channel.CreateBounded<int>(10);
await channel.Writer.WriteAsync(1); // Producer
var value = await channel.Reader.ReadAsync(); // Consumer
```

**DN18** – **Source Generators** compile-time code generation (no runtime reflection). Unlike **reflection** (runtime) or **IL weaving** (post-compile), they’re faster and AOT-friendly. **Incremental generators** (preferred) only regenerate when inputs change, improving build performance.

**DN19** – **TPL Dataflow** is a library for actor-based pipelines. `ActionBlock<T>` processes items, `TransformBlock<T>` modifies them, `BufferBlock<T>` stores them. **Vs Channels**: Dataflow is higher-level (blocks as nodes), while Channels are lower-level (raw producer-consumer).

**DN20** – **Minimal APIs** use lambda endpoints (e.g., `app.MapGet("/", () => "Hello")`). **Vs Controllers**: Minimal APIs are lighter but lack built-in testability (use `WebApplicationFactory`), middleware integration, and OpenAPI support (add `SwaggerGen`). **Route groups** (`MapGroup`) organize endpoints; **endpoint filters** add pre/post-processing.

### **Python Answers**

**P1** – **List** (mutable, ordered), **tuple** (immutable, ordered). **Set** (mutable, unordered, unique), **frozenset** (immutable, hashable). Use tuples/sets for keys or immutability.

**P2** – **GIL** (Global Interpreter Lock) allows only one thread to execute Python bytecode at a time. **Affects**: CPU-bound workloads (not I/O-bound). **Workarounds**: Use `multiprocessing` (separate processes), `asyncio` (I/O-bound), or C extensions (e.g., NumPy releases GIL).

**P3** – `copy()` creates a **shallow copy** (nested objects are referenced), while `deepcopy()` duplicates all levels. Example:
```python
import copy
original = [[1, 2], [3, 4]]
shallow = copy.copy(original)
shallow[0][0] = 99  # Modifies original[0][0] too!
deep = copy.deepcopy(original)  # No shared references
```

**P4** – **Decorators** wrap functions to modify behavior. Example (timing decorator):
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"Time: {time.time() - start:.2f}s")
        return result
    return wrapper

@timer
def slow_func(): time.sleep(1)
```

**P5** – **Generators** (`yield`) produce values lazily (memory-efficient). **Vs lists**: Generators don’t store all values in memory. `yield from` delegates to another generator:
```python
def chain(*iterables):
    for it in iterables:
        yield from it
```

**P6** – **asyncio** event loop runs coroutines. `asyncio.run()` starts the loop, `gather()` runs multiple coroutines concurrently, `create_task()` schedules a coroutine. **`time.sleep()`** blocks the thread; use `await asyncio.sleep()` instead.

**P7** – **MRO** (Method Resolution Order) uses **C3 linearization** (Python 3). For diamond inheritance:
```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass
```
MRO: `D -> B -> C -> A`. `D().who()` prints `"C"` because `C` comes before `B` in MRO.

**P8** – **Metaclass** controls class creation (e.g., `type` or custom). **`__init_subclass__`** is simpler for class customization. Example:
- **Metaclass**: Enforce class attributes (e.g., `class Meta(type): ...`).
- **`__init_subclass__`**: Add methods to subclasses automatically:
```python
class Base:
    def __init_subclass__(cls, **kwargs):
        cls.extra = "Added by __init_subclass__"
```

**P9** – **Threading**: Shared memory (GIL-limited). **Multiprocessing**: Separate processes (no GIL, but pickling overhead). **concurrent.futures**: High-level interface for both. Use:
- `threading` for I/O-bound tasks.
- `multiprocessing` for CPU-bound tasks.
- `concurrent.futures.ThreadPoolExecutor`/`ProcessPoolExecutor` for simplicity.

**P10** – **`__slots__`** restricts dynamic attribute creation, saving memory (no `__dict__`). Use for classes with many instances (e.g., `class Point: __slots__ = ['x', 'y']`). Prevents accidental attribute addition.

**P11** – **Virtual environment** isolates dependencies. **venv** (built-in), **virtualenv** (older, more features), **conda** (cross-language, scientific packages). Use `venv` for most Python projects.

**P12** – **Comprehensions** create collections concisely:
```python
squares = [x**2 for x in range(10)]  # List
square_dict = {x: x**2 for x in range(10)}  # Dict
unique_squares = {x**2 for x in range(10)}  # Set
```
**Vs `map`/`filter`**: Comprehensions are often more readable. Use `map`/`filter` for functional-style pipelines.

**P13** – `==` checks value equality, `is` checks identity (same object in memory). **Interning**: Small integers (-5 to 256) are cached, so `a = 1; b = 1; a is b` is `True`.

**P14** – `*args` captures positional arguments (tuple), `**kwargs` captures keyword arguments (dict). **Positional-only** (`/`) and **keyword-only** (`*`) markers:
```python
def func(a, b, /, c, *, d):  # a,b: positional-only; c: positional/keyword; d: keyword-only
    pass
```

**P15** – **Context managers** (`with` statement) handle setup/teardown. Implement via `__enter__`/`__exit__` or `@contextmanager`:
```python
from contextlib import contextmanager
@contextmanager
def timer():
    start = time.time()
    try:
        yield
    finally:
        print(f"Time: {time.time() - start:.2f}s")
```

**P16** – **Type hinting** adds static type checks. Examples:
```python
from typing import Union, Optional, Literal, TypeVar, Protocol
T = TypeVar('T')
class Drawable(Protocol):
    def draw(self) -> None: ...
def process(x: Union[int, str]) -> Optional[Literal["success"]]:
    ...
```
**mypy/pyright** enforce hints statically.

**P17** – **Dunder methods** define Python’s data model:
- `__repr__` (unambiguous, for debugging), `__str__` (readable).
- `__eq__` (equality), `__hash__` (must be consistent with `__eq__`; if you define `__eq__`, define `__hash__` or make the class unhashable).
- `__getattr__` (fallback for missing attributes), `__getattribute__` (intercepts all attribute access).

**P18** – **Descriptors** (`__get__`, `__set__`, `__delete__`) enable custom attribute access. **`property`**, **`classmethod`**, and **`staticmethod`** are descriptors. Example:
```python
class Validated:
    def __set_name__(self, owner, name):
        self.name = name
    def __get__(self, obj, owner):
        return obj.__dict__.get(self.name)
    def __set__(self, obj, value):
        if value < 0: raise ValueError("Must be positive")
        obj.__dict__[self.name] = value
```

**P19** – **Import system**: Modules are loaded via **finders** (locate) and **loaders** (load). **Relative imports** (e.g., `from . import module`) use package hierarchy; **absolute imports** (e.g., `from package import module`) use `sys.path`. **`__init__.py`** marks directories as packages. **Namespace packages** (no `__init__.py`) allow split packages across directories.

**P20** – **`dataclasses`** auto-generates `__init__`, `__repr__`, etc. Features:
- `__post_init__` (post-initialization logic).
- **Field factories** (`field(default_factory=list)`).
- **Frozen dataclasses** (`@dataclass(frozen=True)`).
- **Inheritance**: Fields are inherited; use `super().__post_init__()`.
**Vs `attrs`**: Similar, but `attrs` has more features (e.g., validators). **Vs `Pydantic`**: Pydantic adds runtime validation, serialization, and schema generation (use for APIs/data parsing). Choose `Pydantic` for data validation, `dataclasses` for simple data containers.
