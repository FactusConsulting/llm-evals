### **JavaScript / TypeScript**

**JS1**
- `var`: Function-scoped, hoisted, can be redeclared, no block scope.
- `let`: Block-scoped, hoisted (but not initialized), cannot be redeclared in the same scope.
- `const`: Block-scoped, must be initialized, cannot be reassigned (but object properties can be modified).
- **Hoisting**: Declarations (`var`, `function`) are moved to the top of their scope during compilation. `let`/`const` are hoisted but not initialized (Temporal Dead Zone).

**JS2**
The **event loop** coordinates execution between the **call stack** (synchronous code), **microtask queue** (Promises, `queueMicrotask`, `MutationObserver`), and **macrotask queue** (setTimeout, setInterval, I/O, UI rendering).
- **Order**: Call stack → Microtasks → Macrotasks (next tick).
- **Example**: `setTimeout(() => console.log('macro'), 0)` runs *after* `Promise.resolve().then(() => console.log('micro'))`.

**JS3**
- **Closure**: A function that retains access to its lexical scope even when executed outside it.
  - **Example**:
    ```javascript
    function outer() { const x = 10; return () => x; }
    const inner = outer(); console.log(inner()); // 10
    ```
- **Classic for-loop bug**: All closures in a loop share the same variable (due to `var` hoisting).
  - **Fix**: Use `let` (block-scoped) or an IIFE:
    ```javascript
    for (let i = 0; i < 3; i++) setTimeout(() => console.log(i), 100); // 0, 1, 2
    ```

**JS4**
- **Promise**: Represents an async operation (pending/fulfilled/rejected). Chained with `.then()`/`.catch()`.
- **async/await**: Syntactic sugar over Promises. `await` pauses execution until the Promise settles.
- **Error handling**:
  - Promises: `.catch()` or `try/catch` with `await`.
  - Uncaught errors in Promises trigger `unhandledrejection`.
- **Promise.allSettled**: Waits for all Promises to settle (success/failure), returns an array of `{status, value/reason}`.
- **Promise.all**: Fails fast if any Promise rejects.

**JS5**
- **interface**: Extensible (declaration merging), better for object shapes.
- **type**: Can represent unions, primitives, tuples, or mapped types.
- **Use `interface`** for public APIs/objects; **`type`** for complex types (e.g., `type Point = { x: number; y: number }`).
- **Discriminated unions**: A union of types with a common discriminant property (e.g., `{ type: 'circle'; radius: number } | { type: 'square'; side: number }`).

**JS6**
- **Prototypal inheritance**: Objects inherit directly from other objects (prototype chain). No classes in the classical sense.
- **`Object.create(proto)`**: Creates an object with `proto` as its prototype.
- **ES6 classes**: Syntactic sugar over prototypes. `class` uses `prototype` under the hood (e.g., `class A {}` → `A.prototype`).

**JS7**
- **`this`**: Context-dependent. **4 binding rules (priority order)**:
  1. **New binding**: `new Foo()` → `this` = new instance.
  2. **Explicit binding**: `foo.call(obj)` → `this` = `obj`.
  3. **Implicit binding**: `obj.foo()` → `this` = `obj`.
  4. **Default binding**: `foo()` → `this` = `window` (non-strict) or `undefined` (strict).
- **`bind()`**: Returns a new function with `this` permanently bound. **Cannot be re-bound** (subsequent `bind()` calls are ignored).

**JS8**
- **WeakRef**: Holds a weak reference to an object (doesn’t prevent garbage collection).
- **FinalizationRegistry**: Notifies when an object is garbage-collected (for cleanup).
- **WeakMap**: Keys must be objects (not primitives) because WeakMap uses weak references. If a key is garbage-collected, the entry is removed automatically.
- **Use case**: Caching or metadata tied to object lifetimes.

**JS9**
- **V8 optimizations**:
  - **Hidden classes**: Objects with the same property shape share a hidden class for efficient property access.
  - **Inline caching**: Caches property access patterns (e.g., `obj.x`) to avoid repeated lookups.
  - **Deoptimization**: Occurs when assumptions are violated (e.g., adding a property dynamically after inline caching).
- **Deoptimization triggers**: `try/catch`, `delete`, dynamic property additions, `eval`.

**JS10**
- **Tree-shaking**: Eliminates dead code (unused exports) during bundling.
- **ES Modules**: Static structure (imports/exports are static), enabling tree-shaking.
- **CommonJS**: Dynamic (`require()` can be anywhere), so bundlers cannot statically analyze dependencies → no effective tree-shaking.

**JS11**
- `null`: Intentional absence of a value (type `object`).
- `undefined`: Uninitialized variable or missing property (type `undefined`).
- `==` (loose equality): Coerces types (`null == undefined` → `true`).
- `===` (strict): No coercion (`null === undefined` → `false`).
- **Nullish coalescing (`??`)**: Returns RHS if LHS is `null` or `undefined`.
- **Optional chaining (`?.`)**: Safely accesses nested properties (returns `undefined` if intermediate is `null`/`undefined`).

**JS12**
- `map()`: Transforms each element (returns new array).
- `filter()`: Returns elements matching a condition.
- `reduce()`: Accumulates a value (e.g., `arr.reduce((acc, x) => acc + x, 0)`). Initial value avoids errors on empty arrays.
- `flatMap()`: Maps then flattens by 1 level (useful for nested arrays).

**JS13**
- **Template literals**: Strings with embedded expressions (`` `Hello ${name}` ``).
- **Tagged templates**: A function processes the template (e.g., for escaping):
  ```javascript
  function sql(strings, ...values) { /* sanitize */ }
  sql`SELECT * FROM users WHERE id = ${userId}`;
  ```

**JS14**
- **Destructuring**: Extracts values from objects/arrays.
  - **Object**: `const { a, b: renamed = default } = obj;`
  - **Array**: `const [x, , y] = [1, 2, 3];` (skips index 1).
  - **Rest operator**: `const [first, ...rest] = [1, 2, 3];` (collects remaining elements).

**JS15**
- `for...in`: Iterates over **enumerable property keys** (including inherited ones). Avoid on arrays (order not guaranteed, includes non-index properties).
- `for...of`: Iterates over **iterable values** (arrays, strings, maps, sets). Uses `[Symbol.iterator]`.

**JS16**
- **Generics**: Type-safe abstractions over types.
  - **Constraints**: `function identity<T extends Lengthwise>(arg: T): T { ... }` (T must have `.length`).
  - **Conditional types**: `type NonNullable<T> = T extends null | undefined ? never : T;`
  - **`infer`**: Extracts types (e.g., `type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;`).

**JS17**
- **CommonJS**: Synchronous (`require/module.exports`), Node.js default.
- **ES Modules**: Asynchronous (`import/export`), static analysis, top-level `await`.
- **Node.js**: Supports both. `"type": "module"` in `package.json` enables ES Modules.
- **Interop**: CommonJS can load ES Modules via `createRequire(import.meta.url)`.

**JS18**
- **Structural typing**: Types are compatible if their shapes match (duck typing).
- **Excess property checks**: TypeScript checks for extra properties in object literals (e.g., `const obj: { a: number } = { a: 1, b: 2 }` → error unless type allows `b`).
- **`extends` vs `satisfies`**:
  - `extends`: Defines a subtype (e.g., `interface A extends B {}`).
  - `satisfies`: Checks if a type satisfies another without widening (e.g., `const x = { a: 1 } satisfies { a: number };`).
- **Variance**:
  - `in`: Contravariant (for function parameters).
  - `out`: Covariant (for return types).

**JS19**
- **Proxy**: Intercepts operations (e.g., `get`, `set`, `apply`) on an object.
  - **Example**: Validation:
    ```javascript
    const handler = { set(target, prop, value) { if (value < 0) throw new Error(); target[prop] = value; } };
    const proxy = new Proxy({}, handler);
    ```
- **Reflect**: Provides default implementations for Proxy traps (e.g., `Reflect.get(target, prop)`).

**JS20**
- **SharedArrayBuffer**: Shared memory between threads (Web Workers).
- **Atomics**: Low-level atomic operations for synchronization (e.g., `Atomics.add`, `Atomics.wait`).
- **Ordering guarantees**: Atomics ensure sequential consistency for operations on `SharedArrayBuffer`.
- **`Atomics.wait`/`notify`**: Blocks a thread until `notify` is called (for synchronization).

### **Bash**

**B1**
- `$@`/`$*`: Expand to all positional parameters.
- **Unquoted**: Same (split on IFS, globbing).
- **`"$@"`**: Each parameter as a separate quoted string (safe for iteration).
- **`"$*"`**: All parameters as a single string (joined by IFS).

**B2**
- `set -e`: Exit immediately if a command fails (non-zero exit).
- `set -u`: Treat unset variables as an error.
- `set -o pipefail`: Pipeline fails if any command in the pipeline fails (not just the last one).

**B3**
- `$(command)`: Command substitution (preferred; nests easily, no escaping issues).
- `` `command` ``: Legacy (avoid; hard to nest, escaping issues).
- `$((expression))`: Arithmetic expansion (e.g., `$((2 + 2))`).
- `expr`: External command (slower, less safe; e.g., `expr 2 + 2`).

**B4**
- **Process substitution**: `<(command)` creates a FIFO (named pipe) with the command’s output.
  - **Example**: `diff <(ls dir1) <(ls dir2)` (compares directory listings).
- **Use case**: Compare outputs of commands without temporary files.

**B5**
- **Safe iteration**: Use `while IFS= read -r -d '' file; do ... done < <(find . -print0)` (handles spaces/newlines).
- **Danger of `for f in $(ls)`**: Splits filenames on IFS (spaces/tabs/newlines) and globs wildcards.

**B6**
- **Here document**: `<<EOF` feeds lines to a command until `EOF` (no variable expansion if quoted).
- **Here string**: `<<< "word"` feeds a single word (like `echo "word" | cmd`).
- `<<-EOF`: Allows indentation (leading tabs are stripped).

**B7**
- `cmd > file 2>&1`: Redirects stdout to `file`, then stderr to stdout’s current destination (`file`).
- `cmd 2>&1 > file`: Redirects stderr to stdout (terminal), then stdout to `file` (stderr still goes to terminal).
- `cmd &> file`: Bash shorthand for `> file 2>&1` (both stdout and stderr to `file`).

**B8**
- **Lock file with `mkdir`**:
  ```bash
  lock_dir="/tmp/mylock"
  if mkdir "$lock_dir"; then
    trap 'rm -rf "$lock_dir"' EXIT TERM INT
    # Critical section
  else
    echo "Lock failed" >&2; exit 1
  fi
  ```
- **Why `mkdir`**: Atomic (avoids race conditions with file creation). Cleanup on `EXIT`/`TERM`/`INT`.

**B9**
- **Single quotes**: Literal (no expansion/variables).
- **Double quotes**: Expands variables/commands (`$VAR`, `$(cmd)`), but not globs.
- **No quotes**: Globbing and word splitting apply.
- **Example**:
  ```bash
  echo '$USER'   # $USER
  echo "$USER"   # alice
  echo $USER     # alice (split if IFS contains spaces)
  ```

**B10**
- **File tests**:
  - `[ -e file ]`: Exists.
  - `[ -d file ]`: Is a directory.
  - `[ -r file ]`: Readable.
- **`[ ]` vs `[[ ]]`**:
  - `[ ]`: POSIX `test` command (less features, word splitting).
  - `[[ ]]`: Bash keyword (no word splitting, supports `&&`, `||`, regex `=~`).

**B11**
- `$?`: Exit code of the last command.
- `$$`: Current shell’s PID.
- `$!`: PID of the last background process.
- `$#`: Number of positional parameters.

**B12**
- **Function syntax**:
  - `foo() { ...; }` (POSIX-compliant).
  - `function foo { ...; }` (Bash/Ksh, allows `function foo() { ...; }`).
- **Return values**: Use `return` for exit codes (0-255) or `echo` for output.

**B13**
- **PATH**: Colon-separated list of directories for command resolution.
- **Builtin vs external**: `type cmd` shows if it’s a builtin (e.g., `cd`) or external (e.g., `/bin/ls`).
- **Check**: `command -v cmd` (POSIX) or `which cmd` (non-POSIX).

**B14**
- **`trap`**: Sets up signal handlers.
  - **Example**:
    ```bash
    trap 'echo "Cleanup"' EXIT
    trap 'echo "Error on line $LINENO"' ERR
    ```
- **Order**: Handlers run in reverse order of registration for the same signal.

**B15**
- **`xargs` vs command substitution**:
  - `xargs`: Efficient for large inputs (avoids subshell overhead).
  - **Spaces/newlines**: `find . -print0 | xargs -0 rm` (null-delimited).
  - **Parallel**: `xargs -P 4 -n 1 cmd` (runs 4 processes in parallel).

**B16**
- **Arrays**:
  - Declare: `arr=("a" "b")` or `arr=(); arr+=("a")`.
  - Iterate: `for i in "${arr[@]}"; do echo "$i"; done`.
  - Length: `${#arr[@]}`.
- **Associative arrays** (Bash 4+):
  - Declare: `declare -A assoc; assoc["key"]="value"`.
  - Iterate: `for key in "${!assoc[@]}"; do echo "${assoc[$key]}"; done`.

**B17**
- **Subshell `(cmd1; cmd2)`**: Runs in a child process (variables changes are lost).
- **Group command `{ cmd1; cmd2; }`**: Runs in the current shell (variables persist).
- **Piping into `while`**: Runs in a subshell (variables are lost). Fix: Use process substitution or `shopt -s lastpipe`.

**B18**
- **Signals**:
  - **SIGINT** (Ctrl+C): Interrupt (can be caught).
  - **SIGTERM**: Termination request (can be caught).
  - **SIGHUP**: Terminal closed (can be caught).
  - **SIGKILL**: Immediate termination (cannot be caught).
- **Graceful shutdown**:
  ```bash
  trap 'kill -TERM $bg_pid; wait $bg_pid' TERM
  bg_cmd & bg_pid=$!
  ```

**B19**
- **Parallel log processing**:
  ```bash
  split -l 1000 big.log chunk_
  process() { awk '{print $1}' "$1" > "${1}.processed"; }
  export -f process
  xargs -P 4 -n 1 -I {} process {} < <(ls chunk_*)
  cat chunk_*.processed > result
  ```
- **Trade-offs**: Faster but higher memory usage. Errors in one job don’t stop others (use `set -e` in `process`).

**B20**
- **`exec`**: Replaces the current shell with the command (no new process).
  - **File descriptor manipulation**:
    ```bash
    exec 3> output.txt   # Open fd 3 for writing
    echo "Hello" >&3     # Write to fd 3
    exec 3>&-            # Close fd 3
    ```
- **Coprocess**: Background process with bidirectional communication:
  ```bash
  coproc myproc { cmd; }
  echo "input" >&${myproc[1]}  # Write to stdin
  read -u ${myproc[0]} output  # Read from stdout
  ```

### **PowerShell**

**PS1**
- **`Write-Output`**: Sends objects to the pipeline (can be captured/redirected).
- **`Write-Host`**: Writes directly to the console (bypasses pipeline). Avoid in scripts (breaks piping).

**PS2**
- **Pipeline**: Passes objects between commands (e.g., `Get-ChildItem | Where-Object { $_.Length -gt 100 }`).
- **`ForEach-Object`**: Processes each pipeline object (e.g., `1..3 | ForEach-Object { $_ * 2 }`).
- **`foreach` statement**: Language construct (not pipeline-aware; e.g., `foreach ($i in 1..3) { $i }`).

**PS3**
- **`[PSCustomObject]`**: Lightweight object with properties (e.g., `[PSCustomObject]@{ Name = 'Alice' }`).
- **`[hashtable]`**: Key-value pairs (e.g., `@{ Name = 'Alice' }`).
- **Conversion**: `ConvertTo-Json` or `[PSCustomObject]$hashtable`.

**PS4**
- **Terminating errors**: Stop execution (e.g., `throw`, `Stop-Process -ErrorAction Stop`).
- **Non-terminating errors**: Continue execution (e.g., `Get-Item nonexistent`).
- **Handling**:
  - `-ErrorAction Stop`: Converts non-terminating to terminating.
  - `$ErrorActionPreference = 'Stop'`: Global setting.
  - `try/catch`: Catches terminating errors.

**PS5**
- **Splatting**: Passes parameters from a hashtable/array.
  - **Example**:
    ```powershell
    $params = @{ Path = 'C:\'; Filter = '*.txt' }
    Get-ChildItem @params
    ```
- **Vs hashtable as parameter**: Splatting unpacks the hashtable into named parameters.

**PS6**
- **PowerShell Remoting**: Uses WinRM (Windows) or SSH (PowerShell 7+).
- **`Invoke-Command -ComputerName`**: Runs a command on remote machines (returns results).
- **`Enter-PSSession`**: Interactive session on a remote machine.
- **Double-hop problem**: Credentials aren’t passed to a second remote machine. Fix: Use `CredSSP` or `Invoke-Command -ArgumentList`.

**PS7**
- **Issue**: PowerShell **unrolls arrays** in the pipeline. The function returns a string, not an array.
  - **Output**: `String` (not `Object[]`).
- **Empty case**: Returns `$null` (not an empty array).
- **Fix**: Wrap in `@()`:
  ```powershell
  function Get-Items { @("one") }
  (Get-Items).GetType().Name  # Object[]
  ```

**PS8**
- **`[scriptblock]`**: A block of code (e.g., `{ Get-Process }`).
- **Function**: Named, reusable code block.
- **Passing scriptblocks remotely**:
  ```powershell
  $sb = { Get-Process }
  Invoke-Command -ComputerName Server -ScriptBlock $sb
  ```
- **Double-hop problem**: Scriptblocks are serialized, so credentials/state are lost. Fix: Use `CredSSP` or pass arguments explicitly.

**PS9**
- **`@()`**: Creates an empty array or wraps a single item in an array.
- **`[array]`**: Type accelerator for `System.Array` (rarely used directly).
- **Force single result into array**: `@($result)`.
- **Indexing**:
  - `$null[0]` → Error.
  - `@()[0]` → `$null` (no error).

**PS10**
- **Comparison operators**:
  - `-eq`, `-ne`: Equality/inequality (case-insensitive by default).
  - `-like`: Wildcard matching (`*`, `?`).
  - `-match`: Regex matching.
  - `-contains`: Checks if a collection contains an item.
  - `-in`: Checks if an item is in a collection.
- **Case-sensitive variants**: `-ceq`, `-clike`, `-cmatch`, etc.
- **`-contains` vs `-in`**:
  - `1,2,3 -contains 2` → `$true`.
  - `2 -in 1,2,3` → `$true`.

**PS11**
- **Module**: Reusable package of cmdlets/functions.
  - **Script module (`.psm1`)**: PowerShell code.
  - **Manifest module (`.psd1`)**: Metadata (version, dependencies).
  - **Binary module**: Compiled .NET code.
- **`Import-Module`**: Loads a module into the session.

**PS12**
- **String interpolation**: Variables/expressions in `"..."` are expanded.
  - **Example**: `"Hello $($user.Name)"`.
- **Single quotes**: Literal (no expansion).
- **Here-string**: `@"..."@` (multi-line, interpolated) or `@'...'@` (literal).

**PS13**
- **`Get-Member`**: Inspects object properties/methods.
- **Pipeline exploration**: `Get-Process | Get-Member -MemberType Property`.
- **`Select-Object`**: Selects properties (e.g., `Get-Process | Select-Object Name, Id`).
- **`Where-Object`**: Filters objects (e.g., `Get-Process | Where-Object { $_.CPU -gt 10 }`).

**PS14**
- **PowerShell classes**: Similar to C# but with limitations.
  - **Differences**: No multiple inheritance, limited interfaces, no static constructors.
  - **Example**:
    ```powershell
    class Person { [string]$Name; Person([string]$Name) { $this.Name = $Name; } }
    ```
- **Use classes** for complex stateful objects; **functions** for simple logic.

**PS15**
- **`[CmdletBinding()]`**: Enables advanced features (e.g., `-Verbose`, `-WhatIf`).
- **`SupportsShouldProcess`**: Adds `-WhatIf` and `-Confirm` support.
- **`DefaultParameterSetName`**: Sets the default parameter set.
- **`ValueFromPipeline`**: Binds a parameter to pipeline input.
- **Blocks**:
  - `Begin`: Runs once before processing.
  - `Process`: Runs for each pipeline object.
  - `End`: Runs once after processing.

**PS16**
- **Providers**: Extend PowerShell to work with data stores (e.g., filesystem, registry).
  - **Example**: `Get-ChildItem HKLM:\` (registry).
  - **Navigation**: `cd HKLM:\Software`, `dir cert:\` (certificate store).

**PS17**
- **Runspaces**: Lightweight threads for parallel execution.
  - **`[runspace]`**: Single runspace.
  - **`[runspacepool]`**: Pool of reusable runspaces.
  - **`[powershell]`**: Instance of PowerShell in a runspace.
- **`ForEach-Object -Parallel` (v7+)**: Simplifies parallel execution:
  ```powershell
  1..10 | ForEach-Object -Parallel { $_ * 2 } -ThrottleLimit 4
  ```

**PS18**
- **PSScriptAnalyzer**: Static code analysis for PowerShell.
  - **Rules**: Built-in (e.g., `PSAvoidUsingCmdletAliases`) or custom.
  - **Severity**: Error, Warning, Information.
  - **Suppression**: `# Suppress: PSAvoidUsingCmdletAliases`.
  - **CI/CD**: Integrates with Azure DevOps/GitHub Actions.

**PS19**
- **`$using:`**: Scopes variables for remote sessions/jobs (e.g., `$using:x` in `Invoke-Command`).
- **`$args`/`ArgumentList`**: Passes arguments to scriptblocks.
- **Serialization limits**: CLIXML depth (default: 2). Complex objects may be truncated.
- **Workaround**: Use `-Depth` parameter or simplify objects.

**PS20**
- **DSC (Desired State Configuration)**: Idempotent configuration management.
  - **Components**:
    - **Configurations**: PowerShell scripts defining state.
    - **Resources**: Modules (e.g., `File`, `Service`).
    - **LCM (Local Configuration Manager)**: Applies configurations.
  - **Windows PowerShell vs PS7+**: PS7+ uses a cross-platform LCM.
  - **Replacement**: Modern tools like **Ansible**, **Terraform**, or **Azure Policy** are preferred for IaC.
