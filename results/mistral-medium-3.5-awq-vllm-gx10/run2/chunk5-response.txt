### **.NET / C# Answers**

---

**DN1** — **Class vs Struct**:
- **Class**: Reference type (heap-allocated), supports inheritance, can be `null`.
- **Struct**: Value type (stack-allocated by default), no inheritance (but implements interfaces), cannot be `null` (unless nullable, e.g., `Point?`).
- **Use a struct** when:
  - The type is small (≤ 16 bytes), immutable, and frequently short-lived (e.g., `Point`, `DateTime`).
  - Avoid for large or mutable data (boxing/unboxing overhead).

---

**DN2** — **IEnumerable<T> vs IQueryable<T>**:
- **IEnumerable<T>**: In-memory iteration (LINQ-to-Objects). Executes queries *client-side* (e.g., `list.Where(x => x.Age > 30)`).
- **IQueryable<T>**: Represents a *query* (e.g., for EF Core). Executes *server-side* (SQL translation). Supports deferred execution.
- **Why it matters**: `IQueryable` can optimize database queries (e.g., `Where` → `WHERE` clause in SQL), while `IEnumerable` loads all data first.

---

**DN3** — **async/await**:
- **async/await**: Non-blocking I/O. `async` marks a method as awaitable; `await` suspends execution until the `Task` completes, yielding control to the caller.
- **Task vs ValueTask**:
  - `Task`: Heap-allocated, for long-running or I/O-bound operations.
  - `ValueTask`: Stack-allocated (if result is already available), reduces allocations for high-performance scenarios (e.g., caching).
- **Use `ValueTask`** when:
  - The operation *often* completes synchronously (e.g., in-memory cache hits).
  - Avoid for fire-and-forget or long-running tasks.

---

**DN4** — **Dependency Injection (DI)**:
- **DI**: Decouples dependencies by injecting them (via constructor/property). .NET DI container manages object lifetimes.
- **Lifetimes**:
  - **Transient**: New instance per injection (stateless services).
  - **Scoped**: One instance per request (e.g., `DbContext` in web apps).
  - **Singleton**: One instance for the app lifetime (e.g., `IConfiguration`).
- **Common bug**: Injecting a **Scoped** service (e.g., `DbContext`) into a **Singleton** (e.g., a background service). The `DbContext` may be disposed or shared across requests, causing `ObjectDisposedException` or concurrency issues.
  - **Fix**: Use `Scoped` for request-bound services; avoid `Singleton` for stateful services.

---

**DN5** — **string vs ReadOnlySpan<char>**:
- **string**: Immutable, heap-allocated, UTF-16. Supports `Substring`, `Split`, etc.
- **ReadOnlySpan<char>**: Ref struct (stack-allocated), zero-copy slice of a string/char array. No allocations for substrings.
- **Use `Span<T>`/`ReadOnlySpan<T>`** for:
  - High-performance parsing (e.g., `ReadOnlySpan<char>` in `System.Text.Json`).
  - Avoiding allocations in hot paths (e.g., substring operations).
- **Why not always?** `Span<T>` cannot cross `async` boundaries (ref struct) and is not serializable.

---

**DN6** — **Garbage Collector (GC)**:
- **Generations (Gen 0, 1, 2)**:
  - **Gen 0**: Short-lived objects (collected frequently).
  - **Gen 1**: Survived Gen 0 collection.
  - **Gen 2**: Long-lived objects (collected rarely).
- **Large Object Heap (LOH)**: Objects > 85KB (e.g., large arrays). Collected with Gen 2 (can cause fragmentation).
- **IDisposable**: Manual cleanup for unmanaged resources (e.g., file handles, DB connections). GC only manages *memory*, not external resources.
  - **Why needed**: Unmanaged resources (e.g., `SqlConnection`) require explicit `Dispose()` to avoid leaks.

---

**DN7** — **ConfigureAwait(false)**:
- **Default behavior**: `await` captures the current `SynchronizationContext` (e.g., UI thread or ASP.NET context) and resumes on it.
- **ConfigureAwait(false)**: Avoids capturing the context, resuming on a thread-pool thread. Improves performance in non-UI contexts (e.g., libraries, async I/O).
- **When to use**:
  - **Use**: In libraries or non-UI code to avoid deadlocks (e.g., async code called from `SynchronizationContext` like UI threads).
  - **Avoid**: In UI apps (e.g., WPF) where resuming on the UI thread is required.
- **Relation to `SynchronizationContext`**: `ConfigureAwait(false)` bypasses the context, preventing deadlocks when mixing `async` with `.Result` or `.Wait()`.

---

**DN8** — **.NET 8/9 Features**:
- **Primary constructors**: Declare constructor parameters directly in the class/struct definition.
- **Collection expressions**: `List<int> list = [1, 2, 3];` (unified syntax for lists, arrays, spans).
- **FrozenDictionary**: Immutable, high-performance dictionary (optimized for read-heavy scenarios).
- **Example with DI**:
  ```csharp
  public class MyService(IDependency dep) // Primary constructor
  {
      private readonly IDependency _dep = dep;
  }
  // Registration:
  builder.Services.AddSingleton<MyService>();
  ```

---

**DN9** — **ObjectDisposedException in DbContext**:
- **Cause**: `DbContext` is **Scoped** (per request), but under high concurrency, requests may share a disposed context (e.g., if misconfigured as `Singleton` or reused across requests).
- **Fix**:
  - Ensure `DbContext` is **Scoped** (default in ASP.NET Core).
  - Avoid manually disposing `DbContext` (let DI handle it).
  - For background tasks, create a new scope:
    ```csharp
    using var scope = serviceProvider.CreateScope();
    var dbContext = scope.ServiceProvider.GetRequiredService<MyDbContext>();
    ```
- **EF Core Lifetime**: `DbContext` is not thread-safe. Each request should get its own instance.

---

**DN10** — **record vs class vs record struct**:
- **record**: Immutable by default (value-based equality), `init`-only properties, `with` expressions for non-destructive mutation.
- **class**: Mutable, reference-based equality.
- **record struct**: Value type (stack-allocated) with record features (e.g., `with`).
- **When to use**:
  - **record**: DTOs, immutable data (e.g., API responses).
  - **record struct**: Small, immutable value types (e.g., `Point`).
  - **class**: Mutable objects with identity (e.g., entities with IDs).

---

**DN11** — **ref, out, in**:
- **ref**: Pass by reference (must be initialized).
- **out**: Pass by reference (no initialization required; caller must assign).
- **in**: Pass by read-only reference (avoids copying large structs).
- **Use cases**:
  - `ref`: Modify existing variables (e.g., `Swap(ref a, ref b)`).
  - `out`: Return multiple values (e.g., `TryParse(string, out int)`).
  - `in`: Optimize large structs (e.g., `ReadOnlySpan<char>`).

---

**DN12** — **Nullable Reference Types (NRT)**:
- **NRT (`string?`)**: Compiler-enforced null checks for reference types. Enabled with `#nullable enable`.
- **Nullable value types (`int?`)**: Underlying type (`Nullable<int>`) that can be `null`.
- **Difference**: NRT is a *compile-time* feature (no runtime overhead); `int?` is a runtime nullable wrapper.

---

**DN13** — **LINQ**:
- **LINQ**: Language Integrated Query. Supports query syntax (`from x in list where x > 0 select x`) and method syntax (`list.Where(x => x > 0)`).
- **Deferred execution**: Queries execute when enumerated (e.g., `ToList()`, `foreach`). Example:
  ```csharp
  var query = list.Where(x => x > 0); // Not executed yet
  var results = query.ToList(); // Executes here
  ```

---
**DN14** — **Generic Constraints**:
- **`where T : class`**: `T` must be a reference type.
- **`where T : struct`**: `T` must be a value type.
- **`where T : new()`**: `T` must have a parameterless constructor.
- **`where T : IComparable<T>`**: `T` must implement `IComparable<T>`.
- **Combining constraints**: `where T : class, IComparable<T>, new()` (e.g., for a generic `SortedList<T>`).

---
**DN15** — **Abstract Class vs Interface**:
- **Abstract class**: Can have state (fields), partial implementations, and access modifiers (`private`, `protected`).
- **Interface**: Pure contract (no state), all members are `public`.
- **Default interface methods (C# 8+)**: Interfaces can provide implementations (e.g., `void ILogger.Log() => Console.WriteLine("Default");`). Useful for versioning without breaking changes.

---
**DN16** — **ASP.NET Core Middleware Pipeline**:
- **`app.Use()`**: Adds middleware to the pipeline. Runs on *every* request (e.g., `app.UseAuthentication()`).
- **`app.Map()`**: Branches the pipeline based on conditions (e.g., `app.Map("/api", ConfigureApi)`).
- **`app.Run()`**: Terminal middleware (short-circuits the pipeline).
- **Ordering**: Middleware runs in the order added. Exception handling middleware should be *first* to catch errors from subsequent middleware.
- **Exception handling**: Use `app.UseExceptionHandler()` early in the pipeline.

---
**DN17** — **Channel<T> vs BlockingCollection<T>**:
- **`Channel<T>`**: Modern, async-friendly producer-consumer pattern. Supports bounded/unbounded buffers and backpressure.
- **`BlockingCollection<T>`**: Synchronous, thread-safe collection (blocks on `Add`/`Take`).
- **Example (bounded channel for backpressure)**:
  ```csharp
  var channel = Channel.CreateBounded<int>(capacity: 10);
  // Producer
  await channel.Writer.WriteAsync(1);
  // Consumer
  var value = await channel.Reader.ReadAsync();
  ```

---
**DN18** — **Source Generators**:
- **Source Generators**: Compile-time code generation (e.g., `System.Text.Json` serializers). Run during compilation, emit C# files.
- **vs Reflection/IL Weaving**:
  - **Reflection**: Runtime type inspection (slow, no AOT support).
  - **IL Weaving**: Post-compile modification (e.g., Fody). Harder to debug.
- **Incremental Generator**: Only processes changed files (faster builds). Preferred over `ISourceGenerator` for large projects.

---
**DN19** — **TPL Dataflow**:
- **TPL Dataflow**: Library for in-process message passing (actor model). Blocks:
  - **`ActionBlock<T>`**: Processes items asynchronously.
  - **`TransformBlock<T, U>`**: Transforms input to output.
  - **`BufferBlock<T>`**: Stores items for later processing.
- **vs `Channel<T>`**:
  - **Dataflow**: More structured (blocks with explicit connections), supports backpressure.
  - **Channels**: Simpler, lighter-weight, better for async streams.

---
**DN20** — **Minimal APIs**:
- **Minimal APIs**: Lightweight, route-focused APIs (introduced in .NET 6). Example:
  ```csharp
  app.MapGet("/hello", () => "Hello World!");
  ```
- **vs Controllers**:
  - **Pros**: Less boilerplate, faster to write, integrates with `IResult`.
  - **Cons**: Harder to test (no built-in `ControllerBase`), limited OpenAPI support (but improved in .NET 8).
- **Route Groups**: Group endpoints with a common prefix:
  ```csharp
  var group = app.MapGroup("/api");
  group.MapGet("/users", () => GetUsers());
  ```
- **Endpoint Filters**: Add metadata or modify behavior (e.g., validation, logging).

### **Python Answers**

---
**P1** — **list vs tuple vs set vs frozenset**:
- **list**: Mutable, ordered, allows duplicates. `[1, 2, 3]`.
- **tuple**: Immutable, ordered, allows duplicates. `(1, 2, 3)`.
- **set**: Mutable, unordered, unique elements. `{1, 2, 3}`.
- **frozenset**: Immutable, unordered, unique elements. `frozenset({1, 2, 3})`.

---
**P2** — **Global Interpreter Lock (GIL)**:
- **GIL**: Mutex that allows only one thread to execute Python bytecode at a time (per process).
- **Affected workloads**: CPU-bound tasks (e.g., math, loops). I/O-bound tasks (e.g., network requests) are less affected (threads release GIL during I/O).
- **Workarounds**:
  - **Multiprocessing**: Bypass GIL with separate processes (but higher memory overhead).
  - **C Extensions**: Release GIL in C code (e.g., NumPy, `ctypes`).
  - **Async I/O**: For I/O-bound tasks (e.g., `asyncio`).

---
**P3** — **deepcopy vs copy**:
- **`copy.copy()`**: Shallow copy (new object, but nested objects are references).
- **`copy.deepcopy()`**: Recursively copies all nested objects.
- **Shallow copy pitfall**:
  ```python
  original = [[1, 2], [3, 4]]
  shallow = copy.copy(original)
  shallow[0][0] = 99  # Modifies original[0][0] too!
  ```

---
**P4** — **Decorators**:
- **Decorator**: Function that wraps another function to modify its behavior.
- **Example (log execution time)**:
  ```python
  import time
  def log_time(func):
      def wrapper(*args, **kwargs):
          start = time.time()
          result = func(*args, **kwargs)
          print(f"{func.__name__} took {time.time() - start:.2f}s")
          return result
      return wrapper

  @log_time
  def slow_function():
      time.sleep(1)
  ```

---
**P5** — **Generators and yield**:
- **Generator**: Function that yields values one at a time (lazy evaluation). Uses `yield` instead of `return`.
- **vs List**: Generators are memory-efficient (no full list in memory).
- **`yield from`**: Delegates to another generator (e.g., flatten nested generators).
  ```python
  def flatten(nested):
      for sublist in nested:
          yield from sublist
  ```

---
**P6** — **asyncio**:
- **Event Loop**: Single-threaded, non-blocking I/O. Runs coroutines concurrently.
- **`asyncio.run()`**: Starts the event loop and runs a coroutine.
- **`asyncio.gather()`**: Runs multiple coroutines concurrently, waits for all.
- **`asyncio.create_task()`**: Schedules a coroutine to run "in the background" (returns a `Task`).
- **Why not `time.sleep()`**: Blocks the entire thread (and event loop). Use `await asyncio.sleep()` instead.

---
**P7** — **Method Resolution Order (MRO)**:
- **Algorithm**: C3 linearization (Python 3). Ensures consistent order in multiple inheritance.
- **Diamond Inheritance Example**:
  ```python
  class A: pass
  class B(A): pass
  class C(A): pass
  class D(B, C): pass
  print(D.mro())  # [D, B, C, A, object]
  ```
  - **Output**: `D().who()` prints `"C"` because `C` comes before `B` in MRO (due to `D(B, C)`).

---
**P8** — **Metaclass vs __init_subclass__**:
- **Metaclass**: Controls class creation (e.g., `type` or custom). Use for advanced class customization (e.g., ORMs, singletons).
  ```python
  class Meta(type):
      def __new__(cls, name, bases, attrs):
          attrs["version"] = 1.0
          return super().__new__(cls, name, bases, attrs)

  class MyClass(metaclass=Meta):
      pass
  print(MyClass.version)  # 1.0
  ```
- **`__init_subclass__`**: Hook for subclass customization (simpler than metaclasses). Use for validation or registration.
  ```python
  class Base:
      def __init_subclass__(cls, **kwargs):
          cls.registry.append(cls)
          super().__init_subclass__(**kwargs)
  Base.registry = []
  ```

---
**P9** — **Multiprocessing vs Threading vs concurrent.futures**:
- **Threading**: Lightweight, but GIL-limited for CPU-bound tasks. Good for I/O-bound.
- **Multiprocessing**: Bypasses GIL (true parallelism). High memory overhead (separate processes).
- **concurrent.futures**: High-level interface for both:
  - `ThreadPoolExecutor`: Thread-based.
  - `ProcessPoolExecutor`: Process-based.
- **Pickling**: Multiprocessing requires serializable (picklable) objects (e.g., no lambdas, `__dict__` must be picklable).

---
**P10** — **__slots__**:
- **Purpose**: Pre-allocates space for attributes, reducing memory usage and speeding up access.
- **Example**:
  ```python
  class Point:
      __slots__ = ["x", "y"]
      def __init__(self, x, y):
          self.x = x
          self.y = y
  ```
- **Impact**: Saves ~40-50% memory (no `__dict__`). Prevents dynamic attribute creation.

---
**P11** — **Virtual Environments**:
- **Purpose**: Isolated Python environments for dependency management.
- **venv**: Built-in (Python 3.3+). Lightweight.
- **virtualenv**: Third-party, supports older Python versions.
- **conda**: Cross-language (Python/R), manages non-Python dependencies (e.g., NumPy, CUDA).

---
**P12** — **Comprehensions**:
- **List**: `[x*2 for x in range(5)]`.
- **Dict**: `{x: x*2 for x in range(5)}`.
- **Set**: `{x*2 for x in range(5)}`.
- **vs map/filter**:
  - Comprehensions are often more readable.
  - `map`/`filter` are functional-style (can be chained).
  - Prefer comprehensions for simple transformations.

---
**P13** — **== vs is**:
- **`==`**: Value equality (calls `__eq__`).
- **`is`**: Identity (same object in memory).
- **Object Interning**: Python caches small integers (-5 to 256) and some strings, so `a is b` may be `True` for small integers.
  ```python
  a = 256
  b = 256
  print(a is b)  # True (interned)
  a = 257
  b = 257
  print(a is b)  # False (not interned)
  ```

---
**P14** — **\*args and \*\*kwargs**:
- **`*args`**: Collects positional arguments as a tuple.
- **`**kwargs`**: Collects keyword arguments as a dict.
- **Positional-only (`/`)**:
  ```python
  def foo(a, b, /, c):  # a and b are positional-only
      pass
  ```
- **Keyword-only (`*`)**:
  ```python
  def bar(a, *, b):  # b must be keyword-only
      pass
  ```

---
**P15** — **Context Managers**:
- **Purpose**: Manage resources (e.g., files, locks) with `with` statement.
- **`__enter__`/`__exit__`**:
  ```python
  class MyContext:
      def __enter__(self):
          print("Enter")
          return self
      def __exit__(self, exc_type, exc_val, exc_tb):
          print("Exit")
  with MyContext():
      pass
  ```
- **`@contextmanager`**:
  ```python
  from contextlib import contextmanager
  @contextmanager
  def timer():
      start = time.time()
      try:
          yield
      finally:
          print(f"Time: {time.time() - start}")
  ```

---
**P16** — **Type Hinting**:
- **Purpose**: Static type checking (e.g., with `mypy` or `pyright`).
- **Examples**:
  - `Union[int, str]`: Either `int` or `str`.
  - `Optional[int]`: `int | None`.
  - `Literal["a", "b"]`: Only `"a"` or `"b"`.
  - `TypeVar`: Generic types (e.g., `T = TypeVar("T")`).
  - `Protocol`: Structural subtyping (duck typing).
  ```python
  from typing import Protocol
  class Flyer(Protocol):
      def fly(self) -> None: ...
  def make_fly(f: Flyer) -> None:
      f.fly()
  ```

---
**P17** — **Python Data Model (Dunder Methods)**:
- **`__repr__`**: Unambiguous representation (for debugging). `__str__`: Readable string.
- **`__eq__`**: Value equality. If defined, `__hash__` should also be defined (or set to `None` if unhashable).
- **`__getattr__`**: Called when attribute is not found. `__getattribute__`: Called for *every* attribute access (can break things if not careful).

---
**P18** — **Descriptors**:
- **Protocol**: `__get__`, `__set__`, `__delete__` to customize attribute access.
- **Example**:
  ```python
  class Descriptor:
      def __get__(self, obj, objtype=None):
          return 42
  class MyClass:
      attr = Descriptor()
  print(MyClass().attr)  # 42
  ```
- **Usage**:
  - `property`: Descriptor that wraps getter/setter.
  - `classmethod`/`staticmethod`: Descriptors that bind methods to classes.

---
**P19** — **Import System**:
- **Absolute vs Relative Imports**:
  - Absolute: `from package.module import x`.
  - Relative: `from .module import x` (same package).
- **`sys.path`**: List of directories Python searches for modules.
- **`PYTHONPATH`**: Environment variable to extend `sys.path`.
- **`__init__.py`**: Marks a directory as a package (can be empty in Python 3.3+ with implicit namespace packages).
- **Namespace Packages**: Packages without `__init__.py` (split across directories).
- **Finder/Loader**: `sys.meta_path` finders locate modules; loaders load them.

---
**P20** — **dataclasses vs attrs vs Pydantic**:
- **dataclasses** (Python 3.7+):
  - Auto-generates `__init__`, `__repr__`, etc.
  - Features:
    - `__post_init__`: Post-initialization hook.
    - `field(default_factory=list)`: Mutable defaults.
    - `frozen=True`: Immutable instances.
    - Inheritance: Fields are inherited; use `super().__post_init__()`.
  ```python
  from dataclasses import dataclass, field
  @dataclass
  class Point:
      x: int
      y: int = field(default_factory=lambda: 0)
  ```
- **attrs**: Pre-dataclasses, more features (e.g., validators, converters).
- **Pydantic**: Dataclasses + validation, serialization (JSON), and type coercion. Use for:
  - API request/response models (e.g., FastAPI).
  - Data parsing (e.g., `BaseModel.parse_obj({"x": 1})`).
- **When to choose Pydantic**:
  - Need runtime validation (e.g., `Field(gt=0)`).
  - JSON serialization/deserialization.
  - Integration with frameworks (e.g., FastAPI).
