### **JavaScript / TypeScript**

**JS1**
- `var`: Function-scoped, hoisted, can be redeclared, no block scope.
- `let`: Block-scoped, hoisted (but not initialized), cannot be redeclared in the same scope.
- `const`: Block-scoped, must be initialized, cannot be reassigned (but object properties can be modified).
- **Hoisting**: Declarations (`var`, `function`) are moved to the top of their scope during compilation. `let`/`const` are hoisted but not initialized (Temporal Dead Zone).

**JS2**
The **event loop** coordinates execution between the **call stack** (synchronous code), **microtask queue** (Promises, `queueMicrotask`, `MutationObserver`), and **macrotask queue** (setTimeout, setInterval, I/O, UI rendering).
- **Order**: Call stack → Microtasks → Macrotasks (next tick).
- **Example**: `setTimeout(() => console.log('macro'), 0)` runs *after* `Promise.resolve().then(() => console.log('micro'))`.

**JS3**
- **Closure**: A function that retains access to its lexical scope even when executed outside it.
  - **Example**:
    ```javascript
    function outer() { const x = 10; return () => x; }
    const inner = outer(); console.log(inner()); // 10
    ```
- **Classic for-loop bug**: All timeouts reference the same `i` (var is function-scoped).
  - **Fix**: Use `let` (block-scoped) or an IIFE:
    ```javascript
    for (let i = 0; i < 3; i++) setTimeout(() => console.log(i), 100); // 0, 1, 2
    ```

**JS4**
- **Promise**: Represents an async operation (pending/fulfilled/rejected). Chained with `.then()`/`.catch()`.
- **async/await**: Syntactic sugar over Promises. `await` pauses execution until the Promise settles.
- **Error handling**:
  - Promises: `.catch()` or `try/catch` with `await`.
  - **`Promise.all`**: Fails fast (rejects if any Promise rejects).
  - **`Promise.allSettled`**: Waits for all Promises to settle (never rejects).

**JS5**
- **`interface`**: Extensible (declaration merging), better for object shapes.
- **`type`**: More flexible (unions, tuples, mapped types), cannot be extended.
- **Discriminated unions**: Union types with a common discriminant property (e.g., `{ type: 'A', ... } | { type: 'B', ... }`).

**JS6**
- **Prototypal inheritance**: Objects inherit directly from other objects (prototype chain).
- **`Object.create(proto)`**: Creates an object with `proto` as its prototype.
- **ES6 classes**: Syntactic sugar over prototypes. `class` uses `prototype` under the hood.

**JS7**
- **`this`**: Context-dependent. **4 binding rules (priority order)**:
  1. **New binding** (`new Foo()` → `this` = new instance).
  2. **Explicit binding** (`foo.call(obj)` → `this` = `obj`).
  3. **Implicit binding** (`obj.foo()` → `this` = `obj`).
  4. **Default binding** (strict mode: `undefined`; non-strict: `window`).
- **`bind()`**: Returns a new function with `this` permanently bound. **Cannot be re-bound**.

**JS8**
- **`WeakRef`**: Holds a weak reference to an object (doesn’t prevent GC).
- **`FinalizationRegistry`**: Notifies when a weakly referenced object is GC’d.
- **`WeakMap`**: Keys must be objects (not primitives) because GC can’t track primitives. WeakMaps don’t prevent GC of their keys.

**JS9**
- **Hidden classes**: V8 optimizes objects with stable property shapes (e.g., `obj.a = 1; obj.b = 2`).
- **Inline caching**: Caches property access locations for speed.
- **Deoptimization**: Occurs with dynamic property additions/deletions or `try/catch` in hot paths.
- **Bad patterns**: `delete obj.prop`, `eval`, `with`, or adding properties after object creation.

**JS10**
- **Tree-shaking**: Eliminates dead code (unused exports) during bundling.
- **ES Modules**: Static analysis enables tree-shaking (imports/exports are explicit).
- **CommonJS**: Dynamic `require()` prevents static analysis (cannot tree-shake effectively).

**JS11**
- `null`: Intentional absence of a value.
- `undefined`: Uninitialized variable or missing property.
- `==` (loose equality): Coerces types (`null == undefined` → `true`).
- `===` (strict): No coercion (`null === undefined` → `false`).
- **`??`**: Nullish coalescing (returns RHS if LHS is `null`/`undefined`).
- **`?.`**: Optional chaining (returns `undefined` if LHS is `null`/`undefined`).

**JS12**
- **`map()`**: Transforms each element (returns new array).
- **`filter()`**: Returns elements matching a condition.
- **`reduce()`**: Accumulates a value (initial value avoids first-element bug).
- **`flatMap()`**: Maps then flattens by 1 level (useful for nested arrays).

**JS13**
- **Template literals**: Backtick-delimited strings with `${expression}` interpolation.
- **Tagged templates**: Functions that process template literals (e.g., `sql` tag for SQL injection safety):
  ```javascript
  function html(strings, ...values) { /* escape values */ }
  const name = "O'Reilly";
  html`<div>${name}</div>`; // Safe HTML
  ```

**JS14**
- **Destructuring**: Extracts values from objects/arrays.
  - **Object**: `const { a, b: renamed = default } = obj;`
  - **Array**: `const [x, ...rest] = arr;`
  - **Rest operator**: Collects remaining elements (`...rest`).

**JS15**
- **`for...in`**: Iterates over **enumerable properties** (including prototype chain). Avoid on arrays (order not guaranteed, includes non-index properties).
- **`for...of`**: Iterates over **iterable values** (arrays, strings, maps, sets).

**JS16**
- **Generics**: `function identity<T>(arg: T): T { return arg; }`
- **Constraints**: `T extends SomeType` restricts `T`.
- **Conditional types**: `T extends U ? X : Y` (e.g., `Exclude<T, U>`).
- **`infer`**: Infers types in conditional types (e.g., `ReturnType<T>`).

**JS17**
- **CommonJS**: Synchronous `require/module.exports` (Node.js default).
- **ES Modules**: Asynchronous `import/export` (static, tree-shakeable).
- **Node.js**: Supports both. `"type": "module"` in `package.json` enables ES Modules.

**JS18**
- **Structural typing**: Types are compatible if shapes match (duck typing).
- **Excess property checks**: TypeScript checks for extra properties in object literals (unless type is `any` or indexed).
- **`extends` vs `satisfies`**:
  - `extends`: Subtyping (e.g., `interface A extends B`).
  - `satisfies`: Validates a type without widening it (e.g., `const x = { a: 1 } satisfies { a: number }`).
- **Variance**:
  - `in`: Contravariant (e.g., `type Foo<T> = (x: T) => void`).
  - `out`: Covariant (e.g., `type Bar<T> = () => T`).

**JS19**
- **`Proxy`**: Intercepts operations (e.g., `get`, `set`, `apply`).
- **`Reflect`**: Provides default implementations for Proxy traps.
- **Example**: Validation proxy:
  ```javascript
  const validator = { get(target, prop) { return prop in target ? target[prop] : null; } };
  const obj = new Proxy({ a: 1 }, validator);
  console.log(obj.b); // null (instead of undefined)
  ```

**JS20**
- **`SharedArrayBuffer`**: Shared memory between threads (Web Workers).
- **`Atomics`**: Provides atomic operations (e.g., `Atomics.add`, `Atomics.wait`/`notify` for synchronization).
- **Ordering guarantees**: `Atomics` ensures sequential consistency.
- **`Atomics.wait`**: Blocks a thread until `Atomics.notify` is called on the same index.

### **Bash**

**B1**
- `$@`/`$*`: Expand to all positional parameters.
- **Unquoted**: Same (split on IFS, globbing).
- **`"$@"`**: Each parameter as a separate quoted string (safe for iteration).
- **`"$*"`**: All parameters as a single string (joined by IFS).

**B2**
- `set -e`: Exit immediately if a command fails (non-zero exit).
- `set -u`: Treat unset variables as an error.
- `set -o pipefail`: Pipeline fails if any command in the pipe fails (not just the last).

**B3**
- `$(command)`: Command substitution (preferred; nests easily, no escaping issues).
- `` `command` ``: Legacy (avoid; hard to nest, escaping issues).
- `$((expression))`: Arithmetic expansion (Bash built-in).
- `expr`: External command (slower, less safe).

**B4**
- **Process substitution**: `<(command)` creates a FIFO (file descriptor) with the command’s output.
- **Example**: `diff <(ls dir1) <(ls dir2)` compares directory listings.

**B5**
- **Safe iteration**: `while IFS= read -r -d '' file; do ... done < <(find . -print0)` (handles spaces/newlines).
- **Dangerous**: `for f in $(ls)` splits on IFS and fails with spaces.

**B6**
- **Here document**: `<<EOF` feeds lines to a command until `EOF` (no expansion if quoted: `<<'EOF'`).
- **Here string**: `<<< "string"` passes a single string.
- `<<-EOF`: Strips leading tabs from the delimiter line.

**B7**
- `cmd > file 2>&1`: Redirects stdout to `file`, then stderr to stdout’s *current* location (file).
- `cmd 2>&1 > file`: Redirects stderr to stdout (terminal), then stdout to `file` (stderr still goes to terminal).
- `cmd &> file`: Bash shorthand for `> file 2>&1`.

**B8**
```bash
lock() {
  local lockfile="/tmp/$(basename "$0").lock"
  if ! mkdir "$lockfile" 2>/dev/null; then
    echo "Another instance is running" >&2; exit 1
  fi
  trap 'rm -rf "$lockfile"' EXIT TERM
}
```
- **Why `mkdir`**: Atomic operation (avoids race conditions with file creation).
- **Cleanup**: `trap` removes the lock on exit/SIGTERM.

**B9**
- **Single quotes**: Literal (no expansion/variables).
- **Double quotes**: Expands variables/commands (`$VAR`, `$(cmd)`).
- **No quotes**: Globbing and word splitting (e.g., `*` expands to filenames).

**B10**
- **File tests**:
  - `-e file`: Exists.
  - `-d file`: Is a directory.
  - `-r file`: Readable.
- **`[ ]` vs `[[ ]]`**:
  - `[ ]`: POSIX `test` (less features, word splitting).
  - `[[ ]]`: Bash built-in (no word splitting, supports `&&`, `||`, regex).

**B11**
- `$?`: Exit code of the last command.
- `$$`: Current script’s PID.
- `$!`: PID of the last background process.
- `$#`: Number of positional parameters.

**B12**
- **Functions**:
  - `foo() { ...; }` (POSIX-compliant).
  - `function foo { ...; }` (Bash/Ksh, allows `function foo() { ...; }`).
- **Return values**: Exit code (`return 0` for success) or `echo` for output.

**B13**
- **`PATH`**: Colon-separated list of directories for command resolution.
- **Builtins** (e.g., `cd`, `echo`) vs **external commands** (e.g., `ls`).
- **Check**: `type -a cmd` (shows all locations) or `command -v cmd` (path to executable).

**B14**
- **`trap`**: Sets handlers for signals (e.g., `trap 'cleanup' EXIT ERR`).
- **Order**: Signals are processed in the order they arrive (but handlers run sequentially).

**B15**
- **`xargs`**: Builds commands from stdin (handles spaces with `-0` + `find -print0`).
- **`xargs -P N`**: Runs up to `N` parallel processes.
- **Example**: `find . -print0 | xargs -0 -P 4 rm` (parallel deletion).

**B16**
- **Arrays**: `arr=(); arr+=("item"); ${arr[@]}` (all elements), `${#arr[@]}` (length).
- **Associative arrays**: `declare -A map; map["key"]="value"; ${map[@]}` (all values).
- **Iteration**: `for item in "${arr[@]}"; do ... done`.

**B17**
- **Subshell `(cmd)`**: Runs in a child process (variables changes are lost).
- **Group command `{ cmd; }`**: Runs in the current shell (variables persist).
- **Piping into `while`**: Runs in a subshell (use `while ...; do ... done < file` to avoid).

**B18**
- **Signals**:
  - `SIGINT` (Ctrl+C): Interrupt (can be caught).
  - `SIGTERM`: Termination request (can be caught).
  - `SIGHUP`: Terminal closed (can be caught).
  - `SIGKILL`: Immediate termination (cannot be caught).
- **Graceful shutdown**: Trap `SIGTERM`/`SIGINT`, kill child processes, then exit.

**B19**
```bash
split -l 1000 large.log chunk_
process() { awk '{print $2}' "$1" > "${1}.processed"; }
export -f process
find . -name 'chunk_*' -print0 | xargs -0 -P 4 -n 1 process
cat chunk_*.processed > result
```
- **Trade-offs**: Parallelism speeds up CPU-bound tasks but may overwhelm I/O.
- **Error handling**: Check exit codes in `process()` and propagate with `set -e`.

**B20**
- **`exec`**: Replaces the current shell with the command (no new process).
- **File descriptor manipulation**:
  - `exec 3>file`: Opens `file` for writing on fd 3.
  - `exec 3>&-`: Closes fd 3.
- **Coprocess**: Background process with bidirectional communication:
  ```bash
  coproc myproc { ./script.sh; }
  echo "input" >&${myproc[1]}  # Write to stdin
  read -u ${myproc[0]} output   # Read from stdout
  ```

### **PowerShell**

**PS1**
- **`Write-Output`**: Sends objects to the pipeline (can be captured/redirected).
- **`Write-Host`**: Writes directly to the console (bypasses pipeline). Avoid in scripts (breaks piping).

**PS2**
- **Pipeline**: Passes objects between cmdlets.
- **`ForEach-Object`**: Processes each object in the pipeline (e.g., `1..3 | ForEach-Object { $_ * 2 }`).
- **`foreach` statement**: Language construct (not pipeline-aware; e.g., `foreach ($i in 1..3) { $i }`).

**PS3**
- **`[PSCustomObject]`**: Typed object with properties (e.g., `[PSCustomObject]@{ Name = 'Alice' }`).
- **`[hashtable]`**: Key-value pairs (e.g., `@{ Name = 'Alice' }`).
- **Conversion**: `ConvertTo-Json` or `[PSCustomObject]$hashtable`.

**PS4**
- **Terminating errors**: Stop execution (e.g., `throw`, `Stop-Command`).
- **Non-terminating errors**: Continue execution (e.g., `Write-Error`).
- **Handling**:
  - `-ErrorAction` (e.g., `-ErrorAction Stop` converts non-terminating to terminating).
  - `$ErrorActionPreference` (global default: `Continue`, `Stop`, `SilentlyContinue`).
  - `try/catch`: Catches terminating errors.

**PS5**
- **Splatting**: Passes parameters from a hashtable/array.
  - **Example**: `$params = @{ Path = 'file.txt'; Force = $true }; Get-ChildItem @params`.
  - **Difference**: Splatting unpacks the hashtable; passing as a single parameter sends the hashtable itself.

**PS6**
- **`Invoke-Command -ComputerName`**: Runs a scriptblock on remote machines (returns results).
- **`Enter-PSSession`**: Starts an interactive session on a remote machine.
- **Protocol**: Uses **WinRM** (HTTP/HTTPS) by default. PowerShell 7+ supports **SSH**.

**PS7**
- **Issue**: PowerShell unwraps single-element arrays.
  - **Output**: `Object[]` (array) if multiple items, but `string` (scalar) if one item.
  - **Fix**: Always return an array explicitly:
    ```powershell
    function Get-Items {
        $result = @()
        $result += "one"
        ,$result  # Comma operator forces array
    }
    ```

**PS8**
- **`[scriptblock]`**: A block of code (e.g., `{ Get-Process }`).
- **Function**: Named, reusable code block.
- **Double-hop problem**: Credentials aren’t passed to a second remote session.
  - **Solutions**:
    - **CredSSP**: `Enable-WSManCredSSP` (security risk).
    - **`Invoke-Command -ArgumentList`**: Pass credentials explicitly.

**PS9**
- **`@()`**: Empty array or array subexpression.
- **`[array]`**: Type accelerator for `System.Array`.
- **Force single result into array**: `@($result)` or `,$result`.
- **Indexing**: `$null[0]` throws an error; `@()[0]` returns `$null`.

**PS10**
- **Comparison operators**:
  - `-eq`/`-ne`: Equality/inequality (case-insensitive).
  - `-like`: Wildcard matching (`*`).
  - `-match`: Regex matching.
  - `-contains`: Checks if a collection contains an item.
  - `-in`: Checks if an item is in a collection.
- **Case-sensitive variants**: `-ceq`, `-clike`, etc.
- **`-contains` vs `-in`**: `-contains` is for collections; `-in` is for scalars.

**PS11**
- **Module**: Reusable package of cmdlets/functions.
  - **Script module (`.psm1`)**: PowerShell code.
  - **Manifest module (`.psd1`)**: Metadata (e.g., version, dependencies).
  - **Binary module**: Compiled .NET code.
- **`Import-Module`**: Loads a module into the session.

**PS12**
- **String interpolation**: Variables/expressions in `"..."` are expanded (e.g., `"Hello $name"`).
- **Single quotes**: Literal (no expansion).
- **Here-string**: `@"..."@` (multi-line, interpolated) or `@'...'@` (literal).

**PS13**
- **`Get-Member`**: Lists properties/methods of an object.
- **Pipeline exploration**: `obj | Get-Member -MemberType Property`.
- **`Select-Object`**: Selects properties (e.g., `Get-Process | Select-Object Name, Id`).
- **`Where-Object`**: Filters objects (e.g., `Get-Process | Where-Object { $_.CPU -gt 10 }`).

**PS14**
- **PowerShell classes**: Similar to C# but with limitations (e.g., no generics, single inheritance).
  - **Example**:
    ```powershell
    class Person { [string]$Name; Person([string]$Name) { $this.Name = $Name; } }
    ```
- **Limitations**: No interfaces, no method overloading.
- **Use cases**: Complex data structures or when performance matters.

**PS15**
- **`[CmdletBinding()]`**: Enables advanced features (e.g., `-Verbose`, `-WhatIf`).
- **`SupportsShouldProcess`**: Adds `-WhatIf` and `-Confirm` support.
- **Parameter attributes**:
  - `DefaultParameterSetName`: Sets the default parameter set.
  - `ValueFromPipeline`: Accepts pipeline input.
- **Blocks**:
  - `Begin`: Runs once before processing.
  - `Process`: Runs for each pipeline object.
  - `End`: Runs once after processing.

**PS16**
- **Providers**: Extend the pipeline to data stores (e.g., filesystem, registry).
- **Example**: `Get-ChildItem HKLM:\Software` (registry) or `Get-ChildItem Env:` (environment variables).
- **Registry access**: `cd HKLM:\` then `dir` or `Get-ItemProperty`.

**PS17**
- **Runspaces**: Lightweight threads for parallel execution.
- **`[runspace]`**: Represents a thread.
- **`[runspacepool]`**: Pool of runspaces for efficiency.
- **`[powershell]`**: Instance of PowerShell in a runspace.
- **`ForEach-Object -Parallel` (v7+)**: Simplifies parallel execution:
  ```powershell
  1..10 | ForEach-Object -Parallel { $_ * 2 } -ThrottleLimit 5
  ```

**PS18**
- **PSScriptAnalyzer**: Static code analysis tool for PowerShell.
- **Rules**: Built-in or custom (e.g., `PSAvoidUsingCmdletAliases`).
- **Severity levels**: Error, Warning, Information.
- **Suppression**: `# Suppress: PSAvoidUsingCmdletAliases` or `SuppressMessageAttribute`.
- **CI/CD**: Integrates with Azure DevOps/GitHub Actions via the `PSScriptAnalyzer` module.

**PS19**
- **`$using:`**: For variable scoping in remote sessions/jobs (e.g., `$using:x` in `Invoke-Command`).
- **`$args`/`-ArgumentList`**: Passes arguments to scriptblocks.
- **Serialization limits**: CLIXML has a depth limit (~32 levels). Complex objects may fail to serialize.
- **Workaround**: Use `-ArgumentList` with primitives or simplify objects.

**PS20**
- **DSC (Desired State Configuration)**: Idempotent configuration management.
  - **Configurations**: PowerShell scripts defining desired state.
  - **Resources**: Modules that implement specific configurations (e.g., `File`, `Service`).
  - **LCM (Local Configuration Manager)**: Applies configurations and monitors drift.
- **PowerShell 7+**: DSC is deprecated in favor of **DSC v3** (cross-platform) or modern tools like **Ansible**, **Chef**, or **Puppet**.
- **Replacement**: **Azure Policy**, **Azure Automation State Configuration**, or **Infrastructure as Code (IaC)** tools (e.g., Terraform, ARM templates).
