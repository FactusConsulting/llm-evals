### Go (20 questions)

---

**G1** — Arrays in Go are fixed-size, contiguous memory allocations of a single type, declared with a length (e.g., `[3]int`). Slices are dynamically-sized views into arrays, declared without a length (e.g., `[]int`). When you append to a slice at capacity, Go allocates a new underlying array (typically doubling the capacity), copies existing elements, and returns a new slice pointing to the new array.

---

**G2** — `var x int` declares a variable with package scope (or function scope if inside a function) and initializes it to the zero value (`0`). `x := 0` is a short variable declaration that infers the type and is only valid inside functions. You **cannot** use `:=` for:
- Package-level variables (must use `var`).
- Variables already declared in the same scope (re-declaration is not allowed with `:=` unless at least one new variable is introduced, e.g., `x, y := 1, 2` where `x` is new).

---

**G3** — A goroutine is a lightweight, user-space thread managed by the Go runtime. Unlike OS threads, goroutines are multiplexed onto a smaller number of OS threads (M:N threading) and have minimal overhead (initial stack size ~2KB, grows as needed). The Go scheduler (GMP model) uses:
- **G** (Goroutine): Work unit.
- **M** (Machine): OS thread.
- **P** (Processor): Logical processor (context for scheduling Gs).
The scheduler efficiently distributes goroutines across Ps/Ms, enabling high concurrency with low latency.

---

**G4** — Channels are typed conduits for communication between goroutines.
- **Unbuffered channel**: Synchronous; sends block until a receiver is ready (and vice versa). Created with `make(chan T)`.
- **Buffered channel**: Asynchronous; holds a fixed number of values (specified at creation, e.g., `make(chan T, 10)`). Sends block only when the buffer is full. Receives block when the buffer is empty.
Sending to a full buffered channel blocks the goroutine until space is available.

---

**G5** — The `context` package manages cancellation, timeouts, and request-scoped values across goroutines. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()

req, _ := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
resp, err := http.DefaultClient.Do(req)
if err != nil {
    if ctx.Err() == context.DeadlineExceeded {
        fmt.Println("Request timed out")
    }
    return err
}
defer resp.Body.Close()
```

---
**G6** — Go interfaces are **implicitly satisfied**: A type implements an interface if it has all the interface’s methods (duck typing). Unlike Java/C#, there’s no explicit `implements` keyword. The empty interface `interface{}` (or `any` in Go 1.18+) can hold any type, making it powerful for generic code (e.g., `fmt.Println`). However, it’s dangerous because it bypasses type safety, requiring type assertions or reflection to use the underlying value.

---
**G7** — Go’s memory model guarantees that **happens-before** relationships (e.g., via channel ops or `sync` primitives) ensure visibility across goroutines. The example is unsafe because:
- No synchronization: The `ready` write in the goroutine may not be visible to the main goroutine due to CPU caching or reordering.
- **Fixes**:
  1. Use a channel:
     ```go
     ch := make(chan struct{})
     go func() {
         data = "hello"
         close(ch)
     }()
     <-ch
     fmt.Println(data)
     ```
  2. Use `sync.Mutex` or `sync/atomic` for synchronization.

---
**G8** —
- **`sync.Mutex`**: Provides exclusive access (lock/unlock). Use when only one goroutine should access data at a time.
- **`sync.RWMutex`**: Allows multiple readers (`RLock`) or one writer (`Lock`). Use for read-heavy workloads.
- **`sync.Map`**: A concurrent map optimized for cases with many reads and few writes, or disjoint keys. It uses internal sharding to reduce contention. **Trade-offs**:
  - `sync.Map` has higher overhead for simple cases (use a `map` + `RWMutex` if contention is low).
  - `sync.Map` shines when keys are spread across goroutines (reduces lock contention).

---
**G9** — Go modules are dependency management units. Key files:
- **`go.mod`**: Declares module path, Go version, and dependencies (with versions).
- **`go.sum`**: Records cryptographic hashes of dependencies for reproducibility.
- **`go mod tidy`**: Adds missing dependencies, removes unused ones, and updates `go.sum`.
- **Minimum Version Selection (MVS)**: When resolving dependencies, Go picks the **highest version** of each module that satisfies all requirements (from `go.mod` files in the dependency graph). This avoids "dependency hell" by preferring newer, compatible versions.

---
**G10** — `defer` schedules a function call to run **after** the surrounding function returns. Multiple defers execute in **LIFO** (last-in-first-out) order. **Gotcha in loops**:
```go
for i := 0; i < 3; i++ {
    defer fmt.Println(i) // Prints 2, 1, 0 (not 0, 1, 2)
}
```
The loop variable `i` is shared across iterations. To fix, pass `i` as an argument:
```go
for i := 0; i < 3; i++ {
    defer func(i int) { fmt.Println(i) }(i) // Prints 0, 1, 2
}
```

---
**G11** — A pointer holds the memory address of a value. Zero value: `nil`. Create a pointer to a struct literal:
```go
p := &struct{ X, Y int }{1, 2} // p is *struct{ X, Y int }
```

---
**G12** — `init()` is a special function that runs **automatically** when a package is initialized (before `main()`). A package can have **multiple `init()` functions**, which execute in the order they are declared (file order). Global `init()` runs before `main()`, and package-level `init()` runs when the package is imported.

---
**G13** —
- **`new(T)`**: Allocates memory for `T` (zeroed) and returns `*T`. Works for **any type** (including `int`, `struct`).
- **`make(T, args...)`**: Allocates and initializes **slices, maps, and channels** (e.g., `make([]int, 10)`). Does not work for types like `int` or `struct`.

---
**G14** — Errors are values of type `error` (an interface with `Error() string`). Idiomatic pattern:
```go
data, err := someFunc()
if err != nil {
    return err // or handle
}
```
- `errors.Is(err, targetErr)`: Checks if `err` wraps `targetErr` (recursively).
- `errors.As(err, &targetType)`: Extracts a value of `targetType` from `err`’s chain.
- `==` only checks direct equality (no wrapping).

---
**G15** — Built-in composite types:
- **`map[K]V`**: Zero value is `nil` (not usable; must initialize with `make`).
- **`[]T`**: Zero value is `nil` (length 0, capacity 0).
- **`chan T`**: Zero value is `nil` (sending/receiving blocks forever).
- **`struct{...}`**: Zero value is a struct with all fields zeroed.

---
**G16** — A race condition occurs when multiple goroutines access shared data concurrently without synchronization, leading to undefined behavior. The `-race` flag instruments the program to detect data races at runtime.
**Example race**:
```go
var counter int
go func() { counter++ }()
go func() { counter++ }()
```
**Fix with `sync.Mutex`**:
```go
var (
    counter int
    mu      sync.Mutex
)
go func() {
    mu.Lock()
    counter++
    mu.Unlock()
}()
```
**Fix with channel**:
```go
ch := make(chan int, 1)
ch <- 1 // Initialize
go func() { ch <- <-ch + 1 }()
```

---
**G17** — `select` allows waiting on multiple channel operations. Unlike `switch`, it randomly picks a ready case if multiple are ready. **Timeout example**:
```go
select {
case msg := <-ch:
    fmt.Println(msg)
case <-time.After(1 * time.Second):
    fmt.Println("Timeout")
}
```

---
**G18** — Escape analysis determines whether a variable can live on the **stack** (faster) or must escape to the **heap** (e.g., if referenced outside its scope, like returning a pointer). The compiler decides based on:
- Pointers to local variables returned or passed to other goroutines.
- Variables too large for the stack.
Inspect with `go build -gcflags="-m"` (prints escape analysis decisions). Heap allocations increase GC pressure, so minimizing escapes improves performance.

---
**G19** — The `reflect` package provides runtime type introspection.
- **`reflect.Type`**: Represents a type (e.g., `reflect.TypeOf(x)`).
- **`reflect.Value`**: Holds a value of any type (e.g., `reflect.ValueOf(x)`).
**Performance costs**: Reflection is slow (100x+ slower than static code) due to runtime checks and boxing. **Justified** for:
- Serialization/deserialization (e.g., JSON, protobuf).
- Dynamic behavior (e.g., ORMs, plugins).
**Alternative**: Code generation (e.g., `go generate`) for type-safe, performant code.

---
**G20** — `go:embed` embeds files/directories into the binary at compile time.
- **Single file**: `//go:embed file.txt` → `var content string`.
- **Directory**: `//go:embed dir/*` → `var content embed.FS`.
- **File system**: `embed.FS` implements `io/fs.FS` for nested access.
**Limitations**:
- Only works with static files (not dynamic paths).
- Embedded files are read-only.
- Large files increase binary size.
**Interaction with `io/fs.FS`**: `embed.FS` can be used anywhere `io/fs.FS` is expected (e.g., `http.FileServer`).

### Rust (20 questions)

---
**R1** — Ownership is Rust’s system for managing memory safely without a GC. **Three rules**:
1. Each value has a single **owner**.
2. When the owner goes out of scope, the value is **dropped** (memory freed).
3. Ownership can be **moved** (not copied) via assignment or function arguments.

---
**R2** —
- **`String`**: Owned, heap-allocated, growable UTF-8 string.
- **`&str`**: Immutable **borrow** (slice) of a string (stack or heap). Prefer `&str` for function parameters to accept both `String` and `&str` (use `AsRef<str>` or `Borrow<str>` for generics).

---
**R3** — Borrowing allows temporary access to data without taking ownership. **Rules**:
- **Shared references (`&T`)**: Multiple immutable references allowed, but no mutable references can exist simultaneously.
- **Mutable references (`&mut T`)**: Only one mutable reference allowed in a scope; no immutable references can coexist.
The **borrow checker** enforces these rules at compile time.

---
**R4** —
- **`Result<T, E>`**: Represents success (`Ok(T)`) or failure (`Err(E)`).
- **`Option<T>`**: Represents presence (`Some(T)`) or absence (`None`).
The `?` operator unwraps `Result`/`Option`: returns the value if `Ok`/`Some`, else early-returns the `Err`/`None`.
**Example**:
```rust
use std::fs;
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let contents = fs::read_to_string(path)?; // ? propagates errors
    Ok(contents)
}
```

---
**R5** —
- **`Box<T>`**: Single-owned heap allocation (for large data or recursive types like `enum List { Cons(i32, Box<List>), Nil }`).
- **`Rc<T>`**: Reference-counted **shared ownership** (single-threaded). Clones increment the count; drops decrement it.
- **`Arc<T>`**: Atomic reference-counted (thread-safe version of `Rc`).
**Use cases**:
- `Box`: Ownership without sharing.
- `Rc`: Shared ownership in single-threaded code.
- `Arc`: Shared ownership across threads.

---
**R6** — Traits are Rust’s interface-like abstractions (collections of methods). Unlike Go interfaces:
- Traits can have **default implementations**.
- Traits can be **generic** (e.g., `trait Add<Rhs = Self>`).
- **Trait objects (`dyn Trait`)**: Dynamic dispatch (runtime polymorphism) via pointers (`&dyn Trait` or `Box<dyn Trait>`). Requires the trait to be **object-safe** (no generic methods, `Self` not used in return position).
- **Generics with trait bounds (`T: Trait`)**: Static dispatch (compiler generates specialized code for each `T`). More efficient but less flexible.

---
**R7** — Lifetimes annotate how long references are valid. The example fails because the returned `&str` could outlive the inputs (`x` or `y`). **Fix**:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```
The lifetime `'a` ensures the output lives as long as the inputs.

---
**R8** —
- **`Send`**: Types that can be **safely transferred** across threads (ownership moved).
- **`Sync`**: Types that can be **safely shared** across threads (`&T` is `Send`).
- **`Rc<T>` is not `Send`/`Sync`**: Its non-atomic reference count causes data races if shared across threads.
- **`Arc<T>` is `Send`/`Sync`**: Uses atomic operations for thread-safe reference counting.

---
**R9** — Rust’s `async/await` is built on **state machines**. A `Future` is a pollable computation that resolves to a value (or never completes). The **executor** (e.g., Tokio) drives `Future`s to completion by repeatedly calling `poll()`.
- **Key differences from Go**:
  - Rust futures are **lazy** (do nothing until polled).
  - Go goroutines are **eager** (start immediately).
  - Rust async uses **cooperative multitasking** (futures yield control when awaiting).
  - Go uses **preemptive scheduling** (goroutines can be interrupted).

---
**R10** — `unsafe` bypasses Rust’s safety checks. **Allowed in `unsafe` blocks**:
1. Dereferencing raw pointers (`*const T`, `*mut T`).
2. Calling `unsafe` functions (e.g., `std::mem::transmute`).
3. Implementing `unsafe` traits (e.g., `Send`, `Sync`).
**Justified** for:
- FFI (interfacing with C).
- Low-level systems programming (e.g., OS kernels).
- Performance-critical code (e.g., `Vec`’s internal resizing).

---
**R11** — Pattern matching in Rust is exhaustive and powerful.
- **`match`**: Checks all possible patterns (compiler enforces exhaustiveness).
- **`if let`**: Matches a single pattern (ignores others).
**Example**:
```rust
match some_option {
    Some(x) => println!("{}", x),
    None => println!("None"),
}
```

---
**R12** —
- **`[T; N]`**: Fixed-size array (stack-allocated, size known at compile time).
- **`Vec<T>`**: Heap-allocated, growable array. When capacity is exceeded, it:
  1. Allocates a new buffer (typically 2x size).
  2. Copies elements.
  3. Drops the old buffer.

---
**R13** — Rust enums are **algebraic data types** (ADTs) that can hold data variants (unlike C enums, which are just integers). **Example**:
```rust
enum Option<T> {
    Some(T),
    None,
}
```
Rust has no `null`; `Option<T>` replaces it, forcing explicit handling of absence.

---
**R14** — `impl` blocks define methods and associated functions for types.
- **`&self`**: Immutable borrow (read-only).
- **`&mut self`**: Mutable borrow (modifiable).
- **`self`**: Takes ownership (consumes the value).
**Associated functions** (e.g., `String::new()`) don’t take `self` and are called with `Type::func()`.

---
**R15** — The `#[derive]` macro automatically implements traits for a type. Common derived traits:
- `Debug`: Printable with `{:?}`.
- `Clone`: Creates a deep copy.
- `PartialEq`: Equality comparison (`==`).
- `Serialize`/`Deserialize`: For `serde`.
**Cannot derive** if the trait requires custom logic (e.g., `Add` for operator overloading).

---
**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that either **borrows** (`&'a T`) or **owns** (`T`) data. Useful for avoiding allocations when the borrowed data suffices. **Example**:
```rust
use std::borrow::Cow;
fn capitalize(s: &str) -> Cow<str> {
    if s.chars().all(|c| c.is_ascii_lowercase()) {
        Cow::Owned(s.to_uppercase())
    } else {
        Cow::Borrowed(s)
    }
}
```

---
**R17** — Rust’s module system organizes code into namespaces.
- **`mod`**: Declares a module (maps to a file/directory).
- **`use`**: Brings paths into scope.
- **`pub`**: Makes items accessible outside the module.
**File system mapping**:
- `mod.rs` (Rust 2015) or `lib.rs`/`main.rs` (Rust 2018) defines the root.
- Submodules are files/directories under the parent.
**Rust 2018 edition**: Simplified paths (e.g., `use crate::foo` instead of `use ::foo`).

---
**R18** — `Pin<T>` ensures a value **cannot be moved in memory**, which is critical for:
- **Self-referential structs**: Pointers to fields must remain valid after moves.
- **Async/await**: Futures may contain references to their own fields (e.g., a `Future` holding a `&mut self`).
**`Unpin`**: Marker trait for types that can be safely moved (most types implement this). `Pin<&mut T>` is the most common way to pin data.

---
**R19** — Rust’s macros enable metaprogramming.
- **Declarative macros (`macro_rules!`)**: Pattern-matching based (like `println!`). Hygienic (scopes are isolated).
- **Procedural macros**: Custom logic for:
  - `#[derive]`: Generate trait implementations.
  - Attribute macros: Transform items (e.g., `#[tokio::main]`).
  - Function-like macros: Operate on token streams (e.g., `vec!`).
**Hygiene**: Macros preserve lexical scopes (e.g., variables in a macro won’t accidentally capture outer variables).

---
**R20** — Zero-cost abstractions in Rust provide high-level ergonomics without runtime overhead. Examples:
- **Iterators**: Compile to tight loops (same as hand-written `for` loops).
- **Generics (monomorphization)**: Compiler generates specialized code for each type (no runtime dispatch overhead).
- **Trait static dispatch**: Method calls are resolved at compile time (like C++ templates).
This achieves **C-like performance** while maintaining safety and expressiveness.
