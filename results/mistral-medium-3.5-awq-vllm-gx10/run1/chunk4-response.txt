### Go (20 questions)

---

**G1** — Arrays in Go are fixed-size, contiguous memory allocations of a single type, declared with a length (e.g., `[3]int`). Slices are dynamically-sized views into arrays, declared without a length (e.g., `[]int`). When you append to a slice that has reached its capacity, Go automatically allocates a new underlying array (typically doubling the capacity), copies the existing elements, and returns a new slice pointing to the new array.

---

**G2** — `var x int` declares a variable `x` of type `int` with its zero value (`0`). `x := 0` declares and initializes `x` with type inference. You **cannot** use `:=` outside a function (e.g., at package level) or if the variable was already declared in the same scope.

---

**G3** — A goroutine is a lightweight, independently executing function in Go, managed by the Go runtime (not the OS). Unlike OS threads, goroutines are multiplexed onto a smaller number of OS threads by the Go scheduler (GMP model: Goroutines, Machines, Processors). The scheduler efficiently schedules goroutines across logical processors (P), which are bound to OS threads (M).

---

**G4** — Channels are typed conduits for communication between goroutines. An **unbuffered channel** blocks the sender until a receiver is ready (synchronous). A **buffered channel** (e.g., `make(chan int, 3)`) allows the sender to enqueue up to its capacity without blocking. Sending to a full buffered channel blocks until a receiver frees space.

---
**G5** — The `context` package manages cancellation, timeouts, and request-scoped values across goroutines. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
resp, err := http.DefaultClient.Do(req)
if err != nil {
    if ctx.Err() == context.DeadlineExceeded {
        fmt.Println("Request timed out")
    }
    return err
}
defer resp.Body.Close()
```

---
**G6** — Go interfaces are **implicitly satisfied**: a type satisfies an interface if it implements all its methods (duck typing). Unlike Java/C#, there’s no explicit `implements` keyword. The empty interface `interface{}` (or `any` in Go 1.18+) can hold any type, making it powerful for generic code (e.g., `fmt.Println`). However, it’s dangerous because it bypasses type safety, requiring type assertions or reflection.

---
**G7** — Go’s memory model guarantees that a goroutine’s writes are **not** automatically visible to other goroutines without synchronization. The example is unsafe because the `ready` variable may be cached or reordered by the compiler/CPU, leading to `data` being read before it’s written. **Fixes**:
1. Use a `sync.Mutex` to protect `ready` and `data`.
2. Use a channel to signal readiness:
   ```go
   ch := make(chan struct{})
   go func() {
       data = "hello"
       close(ch)
   }()
   <-ch
   fmt.Println(data)
   ```
3. Use `sync/atomic` for atomic operations on `ready`.

---
**G8** —
- `sync.Mutex`: Provides exclusive access (lock/unlock). Use when only one goroutine should access data at a time.
- `sync.RWMutex`: Allows multiple readers (`RLock`) or one writer (`Lock`). Use for read-heavy workloads.
- `sync.Map`: A concurrent map optimized for cases with many reads and few writes. Use it when you need a concurrent map without explicit locking. **Trade-offs**: `sync.Map` has higher overhead for simple cases; a regular map + mutex is faster for low contention.

---
**G9** — Go modules are the dependency management system. `go.mod` defines the module’s path, Go version, and dependencies. `go.sum` records cryptographic hashes of dependencies for reproducibility. `go mod tidy` adds missing dependencies and removes unused ones. **MVS (Minimum Version Selection)**: When resolving dependencies, Go picks the highest version of each module that satisfies all requirements, but for indirect dependencies, it picks the **minimum version** that satisfies the direct dependencies.

---
**G10** — `defer` schedules a function call to run when the surrounding function returns. Multiple defers execute in **LIFO** (last-in-first-out) order. **Gotcha in loops**: In a loop, deferred functions capture the loop variable by value (not by reference). Fix by passing the variable as a parameter:
```go
for i := 0; i < 3; i++ {
    defer func(i int) { fmt.Println(i) }(i) // Prints 2, 1, 0
}
```

---
**G11** — A pointer holds the memory address of a value. The zero value of a pointer is `nil`. Create a pointer to a struct literal with `&`:
```go
p := &struct{ X int }{X: 10}
```

---
**G12** — `init()` runs automatically when a package is initialized, before `main()`. A package can have **multiple** `init()` functions, which execute in the order they are declared (or in file order if in separate files).

---
**G13** —
- `new(T)`: Allocates zeroed memory for type `T` and returns a pointer (`*T`). Works for any type.
- `make(T, args)`: Allocates and initializes slices, maps, and channels. Does not return a pointer. Example: `make([]int, 0, 10)`.

---
**G14** — Errors are values of type `error` (an interface with `Error() string`). Idiomatic pattern:
```go
resp, err := http.Get(url)
if err != nil {
    return err
}
```
- `errors.Is(err, targetErr)`: Checks if `err` matches `targetErr` or any error in its chain (wrapped with `fmt.Errorf("... %w ...", err)`).
- `errors.As(err, &targetType)`: Checks if `err` can be unwrapped to `targetType`.
- `==` compares errors directly (not recommended for wrapped errors).

---
**G15** — Built-in composite types:
- `map`: Zero value is `nil` (not usable; must initialize with `make`).
- `slice`: Zero value is `nil` (length 0, capacity 0).
- `channel`: Zero value is `nil` (cannot send/receive; must initialize with `make`).
- `struct`: Zero value is a struct with all fields set to their zero values.

---
**G16** — A race condition occurs when multiple goroutines access shared data without synchronization, leading to undefined behavior. The `-race` flag instruments the code to detect data races at runtime.
**Example of a data race**:
```go
var counter int
go func() { counter++ }()
go func() { counter++ }()
```
**Fix with `sync.Mutex`**:
```go
var (
    counter int
    mu      sync.Mutex
)
go func() {
    mu.Lock()
    defer mu.Unlock()
    counter++
}()
```
**Fix with a channel**:
```go
ch := make(chan int, 1)
ch <- 1
go func() { ch <- <-ch + 1 }()
```

---
**G17** — `select` allows a goroutine to wait on multiple channel operations. Unlike `switch`, it randomly picks a ready case if multiple are ready. **Timeout example**:
```go
select {
case msg := <-ch:
    fmt.Println(msg)
case <-time.After(1 * time.Second):
    fmt.Println("Timeout")
}
```

---
**G18** — Escape analysis determines whether a variable can be allocated on the stack (faster) or must escape to the heap (e.g., if it’s referenced outside the current function or its size is unknown at compile time). Inspect decisions with:
```sh
go build -gcflags="-m" main.go
```
**Why it matters**: Stack allocation reduces GC pressure and improves performance.

---
**G19** — The `reflect` package provides runtime type introspection. `reflect.Type` represents a type, while `reflect.Value` holds a value of that type. **Performance costs**: Reflection is slow (100x+ slower than direct access) and should be avoided in hot paths. **Justified uses**: Serialization (e.g., JSON), dynamic method calls, or generic libraries (e.g., `encoding/json`). **Alternative**: Code generation (e.g., `go generate`) for type-safe, performant code.

---
**G20** — `go:embed` embeds files/directories into the binary at compile time. Works for:
- Single files: `//go:embed file.txt`
- Directories: `//go:embed dir/*`
- File systems: `//go:embed dir` (returns `embed.FS`, which implements `io/fs.FS`).
**Limitations**:
- Only works with static files (not dynamic paths).
- Embedded files are read-only.
- Large files increase binary size.
**Interaction with `io/fs.FS`**: `embed.FS` can be used anywhere `io/fs.FS` is expected (e.g., `http.FileServer`).

### Rust (20 questions)

---
**R1** — Ownership is Rust’s system for managing memory safely without a GC. **Rules**:
1. Each value has a single owner.
2. When the owner goes out of scope, the value is dropped.
3. Ownership can be moved (not copied) via assignment or function arguments.

---
**R2** —
- `String`: A growable, heap-allocated UTF-8 string. Owns its data.
- `&str`: An immutable slice (view) into a string (stack or heap). Use `&str` for function parameters when you don’t need to own or modify the string. Use `String` when you need to own or modify the data.

---
**R3** — Borrowing allows temporary access to data without taking ownership. **Rules**:
- **Shared references (`&T`)**: Multiple immutable references allowed, but no mutable references can exist simultaneously.
- **Mutable references (`&mut T`)**: Only one mutable reference allowed, and no immutable references can exist simultaneously.
The borrow checker enforces these rules at compile time.

---
**R4** —
- `Result<T, E>`: Represents success (`Ok(T)`) or failure (`Err(E)`).
- `Option<T>`: Represents some value (`Some(T)`) or none (`None`).
The `?` operator unwraps `Result`/`Option`: returns the value if `Ok`/`Some`, otherwise returns the error/`None` early.
**Example**:
```rust
use std::fs;
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let contents = fs::read_to_string(path)?;
    Ok(contents)
}
```

---
**R5** —
- `Box<T>`: A heap-allocated pointer to `T`. Use for recursive types (e.g., linked lists) or large data to avoid stack overflow.
- `Rc<T>`: Reference-counted pointer for shared ownership (single-threaded). Use when multiple parts of the code need read-only access to the same data.
- `Arc<T>`: Atomic reference-counted pointer for thread-safe shared ownership. Use for concurrent access.

---
**R6** — Traits are Rust’s way of defining shared behavior (similar to Go interfaces but more powerful). **Differences from Go**:
- Traits can have default implementations.
- Traits can be generic.
- Trait bounds (`T: Trait`) are checked at compile time (static dispatch).
- Trait objects (`dyn Trait`) use dynamic dispatch (runtime polymorphism) and require the trait to be **object-safe** (no generic methods, `Self` types, etc.).

---
**R7** — Lifetimes annotate how long references are valid. The example fails because the returned reference (`&str`) could outlive the input references (`x` or `y`). **Fix**: Add a lifetime parameter:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```
This ensures the returned reference lives at least as long as the inputs.

---
**R8** —
- `Send`: A type is `Send` if it can be safely transferred across threads (e.g., `Arc<T>`, `Box<T>` where `T: Send`).
- `Sync`: A type is `Sync` if it can be safely shared between threads (e.g., `Arc<T>` where `T: Sync`).
- `Rc<T>` is **not** `Send`/`Sync` because its reference count is not thread-safe (no atomic operations).
- `Arc<T>` uses atomic operations for thread-safe reference counting, making it `Send`/`Sync` (if `T` is).

---
**R9** — Rust’s `async/await` is built on **Futures**, which are lazy computations that resolve to a value. The `async` keyword transforms a block into a `Future`. The **executor** (e.g., Tokio) polls the `Future` to completion. **Key differences from Go**:
- Rust’s `Future`s are **not** goroutines; they require an executor to run.
- Goroutines are preemptively scheduled; Rust’s `Future`s are cooperatively scheduled (must yield control explicitly, e.g., with `.await`).
- Rust’s async is **zero-cost** (no runtime overhead for unused features).

---
**R10** — `unsafe` bypasses Rust’s safety checks. In `unsafe` blocks, you can:
1. Dereference raw pointers (`*const T`, `*mut T`).
2. Call `unsafe` functions (e.g., `std::mem::transmute`).
3. Access or modify mutable static variables.
**Justified uses**: FFI, low-level systems programming, or performance-critical code where safety is manually ensured.

---
**R11** — Pattern matching in Rust uses `match` to destructure and handle values. `match` is **exhaustive** (must cover all possible cases). `if let` is a shorthand for single-case matching. Example:
```rust
match some_option {
    Some(x) => println!("{}", x),
    None => println!("None"),
}
if let Some(x) = some_option {
    println!("{}", x);
}
```

---
**R12** —
- `Vec<T>`: A growable heap-allocated array. When capacity is exceeded, it reallocates (typically doubling capacity) and copies elements.
- `[T; N]`: A fixed-size stack-allocated array. Size is part of the type.

---
**R13** — Rust enums are **algebraic data types** (ADTs) that can represent multiple variants, each with its own data. Unlike C/Java enums, Rust enums can hold data (e.g., `Option<T>` is `Some(T)` or `None`). Rust avoids `null` by using `Option<T>` to explicitly handle absence.

---
**R14** — `impl` blocks define methods and associated functions for a type.
- `&self`: Immutable reference (read-only).
- `&mut self`: Mutable reference (read-write).
- `self`: Takes ownership (consumes the value).
**Associated functions** (e.g., `String::new()`) don’t take `self` and are called with `Type::func()`.

---
**R15** — The `derive` macro automatically implements traits for a type. Common derived traits:
- `Debug`: For printing with `{:?}`.
- `Clone`: For creating copies.
- `PartialEq`: For equality comparisons (`==`).
- `Serialize`/`Deserialize`: For JSON/other formats (requires `serde`).
**Cannot derive** traits that require custom logic (e.g., `Add` for operator overloading).

---
**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that either borrows (`&'a T`) or owns (`T`) data. It clones the data only when mutation is needed. **Example**:
```rust
use std::borrow::Cow;
fn capitalize(s: &str) -> Cow<str> {
    if s.chars().all(|c| c.is_ascii_lowercase()) {
        Cow::Owned(s.to_uppercase())
    } else {
        Cow::Borrowed(s)
    }
}
```
Here, `Cow` avoids allocation if the string is already uppercase.

---
**R17** — Rust’s module system organizes code into logical units. **Key concepts**:
- `mod`: Declares a module (maps to a file/directory).
- `use`: Brings paths into scope.
- `pub`: Makes items accessible outside the module.
**File system mapping**:
- In Rust 2015, `mod.rs` was required for directories. In Rust 2018, you can use `mod.rs` or a file named after the module (e.g., `lib.rs` for the root).

---
**R18** — `Pin<T>` ensures a value **cannot be moved in memory**, which is critical for self-referential structs (e.g., a struct containing a pointer to its own field). **Why it’s needed**: In async/await, the compiler generates state machines that may contain self-references. `Pin` guarantees these references remain valid. **Unpin**: A marker trait for types that can be safely moved (most types are `Unpin`).

---
**R19** — Rust’s macro system allows metaprogramming. **Types**:
- **Declarative macros (`macro_rules!`)**: Pattern-matching macros (e.g., `println!`). Hygienic by default (variables in the macro don’t leak into the surrounding scope).
- **Procedural macros**: Custom derive macros, attribute macros, or function-like macros. Written as Rust code that manipulates the AST. **Hygiene**: Procedural macros must explicitly handle hygiene (e.g., using `quote!` and `syn` crates).

---
**R20** — Zero-cost abstractions in Rust provide high-level ergonomics without runtime overhead. **Examples**:
- **Iterators**: Compile to tight loops (same performance as hand-written `for` loops).
- **Generics (monomorphization)**: Compile to specialized code for each type (no runtime dispatch overhead).
- **Trait static dispatch**: Method calls on generic types are resolved at compile time (no vtable lookup).
This achieves C-like performance while maintaining safety and expressiveness.
