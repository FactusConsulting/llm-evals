### **JavaScript / TypeScript**

**JS1**
- `var`: Function-scoped, hoisted, can be redeclared, no block scope.
- `let`: Block-scoped, hoisted (but not initialized), cannot be redeclared in the same scope.
- `const`: Block-scoped, hoisted (uninitialized), cannot be reassigned (but object properties can be modified).
- **Hoisting**: Declarations (`var`, `function`) are moved to the top of their scope during compilation. `let`/`const` are hoisted but not initialized (Temporal Dead Zone).

**JS2**
The **event loop** coordinates execution between the **call stack** (synchronous code), **microtask queue** (Promises, `queueMicrotask`, `MutationObserver`), and **macrotask queue** (setTimeout, setInterval, I/O, UI rendering).
- **Order**: Call stack → Microtasks → Macrotasks (next tick).
- **Example**: `setTimeout(() => console.log('macro'), 0)` runs *after* `Promise.resolve().then(() => console.log('micro'))`.

**JS3**
- **Closure**: A function that retains access to its lexical scope even after the outer function has returned.
  - **Example**:
    ```javascript
    function outer() { const x = 10; return () => x; }
    const inner = outer(); console.log(inner()); // 10
    ```
- **Classic for-loop bug**: All closures in a loop share the same variable (due to `var` hoisting).
  - **Fix**: Use `let` (block-scoped) or an IIFE:
    ```javascript
    for (let i = 0; i < 3; i++) setTimeout(() => console.log(i), 100); // 0, 1, 2
    ```

**JS4**
- **Promise**: Represents an async operation (pending/fulfilled/rejected). Chained with `.then()`/`.catch()`.
- **async/await**: Syntactic sugar over Promises. `await` pauses execution until the Promise settles.
- **Error handling**:
  - Promises: `.catch()` or `try/catch` with `await`.
  - Uncaught Promise rejections can be handled with `unhandledrejection` event.
- **`Promise.all`**: Rejects if any Promise rejects. **`Promise.allSettled`**: Waits for all Promises to settle (success/failure).

**JS5**
- **`interface`**: Extensible (declaration merging), better for object shapes.
- **`type`**: Can represent unions, primitives, tuples, etc. Cannot be extended.
- **Use `interface`** for public APIs/objects; **`type`** for complex types (e.g., `type Point = [number, number]`).
- **Discriminated unions**: Union types with a common discriminant property (e.g., `{ type: 'circle', radius: number } | { type: 'square', side: number }`).

**JS6**
- **Prototypal inheritance**: Objects inherit directly from other objects (prototype chain). No classes in the classical sense.
- **`Object.create(proto)`**: Creates a new object with `proto` as its prototype.
- **ES6 classes**: Syntactic sugar over prototypes. `class` uses `prototype` under the hood (e.g., `class A {}` → `A.prototype`).

**JS7**
- **`this`**: Context-dependent. **4 binding rules (priority order)**:
  1. **New binding** (`new Foo()` → `this` = new instance).
  2. **Explicit binding** (`foo.call(obj)` → `this` = `obj`).
  3. **Implicit binding** (`obj.foo()` → `this` = `obj`).
  4. **Default binding** (strict mode: `undefined`; non-strict: `window`).
- **`bind()`**: Returns a new function with `this` permanently bound. **Cannot be re-bound** (subsequent `bind()` calls are ignored).

**JS8**
- **`WeakRef`**: Holds a weak reference to an object (doesn’t prevent garbage collection).
- **`FinalizationRegistry`**: Notifies when a weakly referenced object is garbage-collected.
- **Use case**: Caching large objects without memory leaks.
- **`WeakMap` keys must be objects**: Primitives aren’t weakly referenceable. Garbage collection can reclaim keys if no other references exist.

**JS9**
- **V8 optimizations**:
  - **Hidden classes**: Objects with the same property shape share a hidden class for efficient property access.
  - **Inline caching**: Caches property access locations for faster repeated access.
  - **Deoptimization**: Occurs when assumptions (e.g., object shape) are violated (e.g., adding a property dynamically).
- **Deoptimization triggers**: `try/catch`, `delete`, dynamic property additions, `eval`.

**JS10**
- **Tree-shaking**: Eliminates dead code (unused exports) during bundling.
- **ES Modules**: Static analysis enables tree-shaking (imports/exports are static).
- **CommonJS**: Dynamic `require()` prevents static analysis (e.g., `require(variable)`). Bundlers cannot safely remove unused code.

**JS11**
- **`null`**: Intentional absence of a value (type `object`).
- **`undefined`**: Uninitialized variable or missing property (type `undefined`).
- **`==` vs `===`**:
  - `null == undefined` → `true` (loose equality).
  - `null === undefined` → `false` (strict equality).
- **`??` (nullish coalescing)**: Returns RHS if LHS is `null`/`undefined` (not `0`/`''`/`false`).
- **`?.` (optional chaining)**: Safely accesses nested properties (e.g., `obj?.prop`).

**JS12**
- **`map()`**: Transforms each element (returns new array).
- **`filter()`**: Returns elements matching a condition.
- **`reduce()`**: Accumulates a value. Initial value avoids errors on empty arrays.
  - Example: `[1, 2].reduce((acc, x) => acc + x, 0)` → `3`.
- **`flatMap()`**: Maps then flattens (depth 1). Useful for transforming nested arrays (e.g., `[1, 2].flatMap(x => [x, x*2])` → `[1, 2, 2, 4]`).

**JS13**
- **Template literals**: String interpolation with backticks (`` `Hello ${name}` ``).
- **Tagged templates**: A function processes the template (e.g., `sql` in SQL queries).
  - Example:
    ```javascript
    function html(strings, ...values) {
      return strings.reduce((acc, str, i) =>
        acc + str + (values[i] ? `<b>${values[i]}</b>` : ''), '');
    }
    html`Hello ${'world'}`; // "Hello <b>world</b>"
    ```

**JS14**
- **Destructuring**: Extracts values from objects/arrays.
  - **Object**: `const { a, b: renamed = default } = obj;`
  - **Array**: `const [x, , y] = [1, 2, 3];` (skips index 1).
  - **Rest operator**: `const [first, ...rest] = [1, 2, 3];` → `rest = [2, 3]`.

**JS15**
- **`for...in`**: Iterates over **enumerable property keys** (including inherited ones). Avoid on arrays (order not guaranteed, includes non-index properties).
- **`for...of`**: Iterates over **iterable values** (arrays, strings, maps, sets). Uses `[Symbol.iterator]`.

**JS16**
- **Generics**: Type-safe reusable components.
  - **Constraints**: `function identity<T extends Lengthwise>(arg: T): T { ... }` (requires `length` property).
  - **Conditional types**: `type NonNullable<T> = T extends null | undefined ? never : T;`.
  - **`infer`**: Extracts types (e.g., `type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;`).

**JS17**
- **CommonJS**: Synchronous `require`/`module.exports`. Node.js default.
- **ES Modules**: Static `import`/`export`. Supported in browsers and Node.js with `"type": "module"` in `package.json`.
- **Node.js**: Uses CommonJS by default. ES Modules require `.mjs` extension or `"type": "module"`.

**JS18**
- **Structural typing**: Types are compatible if their shapes match (duck typing).
- **Excess property checks**: TypeScript checks for extra properties in object literals (e.g., `const obj: { a: number } = { a: 1, b: 2 }` → error unless type allows `b`).
- **`extends` vs `satisfies`**:
  - `extends`: Subtyping (e.g., `interface A extends B`).
  - `satisfies`: Checks if a type satisfies another without widening (e.g., `type T = { a: number } satisfies { a: number }`).
- **Variance**:
  - **`in`**: Contravariant (for function parameters).
  - **`out`**: Covariant (for return types).

**JS19**
- **`Proxy`**: Intercepts operations (e.g., `get`, `set`, `apply`).
  - Example (validation):
    ```javascript
    const validator = {
      get(target, prop) {
        if (prop in target) return target[prop];
        throw new Error(`Property ${prop} not allowed`);
      }
    };
    const obj = new Proxy({ a: 1 }, validator);
    ```
- **`Reflect`**: Provides default implementations for Proxy traps (e.g., `Reflect.get(target, prop)`).

**JS20**
- **`SharedArrayBuffer`**: Shared memory between threads (Web Workers).
- **`Atomics`**: Provides atomic operations (e.g., `Atomics.add`, `Atomics.wait`/`notify` for synchronization).
- **Ordering guarantees**: `Atomics` ensures operations are atomic and ordered (no race conditions).
- **`Atomics.wait`**: Blocks a thread until `Atomics.notify` is called on the same buffer index.

### **Bash**

**B1**
- **`$@`**: Expands to all positional parameters as separate words.
- **`$*`**: Expands to all positional parameters as a single word.
- **`"$@"`**: Preserves quoting (safe for filenames with spaces).
- **`"$*"`**: Joins all args into one string (first arg + `IFS` + rest).

**B2**
- **`set -e`**: Exit immediately if a command fails (non-zero exit).
- **`set -u`**: Treat unset variables as an error.
- **`set -o pipefail`**: Pipeline fails if any command in the pipe fails (not just the last one).

**B3**
- **`$(command)`**: Preferred (nested, readable, no escaping issues).
- **`` `command` ``: Legacy (avoid; hard to nest).
- **`$((expression))`**: Arithmetic expansion (e.g., `$((2 + 3))`).
- **`expr`**: External command (slower, deprecated; e.g., `expr 2 + 3`).

**B4**
- **Process substitution**: `<(command)` creates a FIFO (named pipe) with the command’s output.
  - Example: `diff <(ls dir1) <(ls dir2)` (compares directory listings).
- **Use case**: Compare outputs of two commands without temporary files.

**B5**
- **Safe iteration**: Use `while IFS= read -r -d '' file; do ... done < <(find . -print0)` (handles spaces/newlines).
- **Danger of `for f in $(ls)`**: Word splitting and globbing break on filenames with spaces or special chars.

**B6**
- **Here document**: `<<EOF` feeds lines to a command until `EOF` (no variable expansion if quoted).
- **Here string**: `<<< "string"` passes a single string as input.
- **`<<-EOF`**: Allows indentation (tabs are stripped from the delimiter and content).

**B7**
- **`cmd > file 2>&1`**: Redirects stdout to `file`, then stderr to stdout’s current destination (`file`).
- **`cmd 2>&1 > file`**: Redirects stderr to stdout (terminal), then stdout to `file` (stderr still goes to terminal).
- **`cmd &> file`**: Redirects both stdout and stderr to `file` (Bash ≥4).

**B8**
- **Lock file with `mkdir`**:
  ```bash
  lock_dir="/tmp/mylock"
  if mkdir "$lock_dir"; then
    trap 'rm -rf "$lock_dir"' EXIT TERM INT
    # Critical section
  else
    echo "Lock failed" >&2
    exit 1
  fi
  ```
- **Why `mkdir`**: Atomic operation (avoids race conditions with file creation). Cleanup on `EXIT`/`TERM`/`INT`.

**B9**
- **Single quotes (`'...'`)**: Literal (no expansion).
- **Double quotes (`"..."`)**: Expands variables/commands (e.g., `"$VAR"`).
- **No quotes**: Word splitting and globbing (e.g., `*` expands to filenames).

**B10**
- **File tests**:
  - `[ -e file ]`: Exists.
  - `[ -d file ]`: Is a directory.
  - `[ -r file ]`: Is readable.
- **`[[ ]]` vs `[ ]`**:
  - `[[ ]]`: No word splitting, supports `&&`, `||`, regex (`=~`).
  - `[ ]`: POSIX-compliant, requires quoting, uses `-a`/`-o` for AND/OR.

**B11**
- **`$?`**: Exit status of the last command.
- **`$$`**: Current shell’s PID.
- **`$!`**: PID of the last background process.
- **`$#`**: Number of positional parameters.

**B12**
- **Function syntax**:
  - `function foo { ... }` (POSIX).
  - `foo() { ... }` (Bash preferred).
- **Return values**: Use `return` for exit status (0-255) or `echo` for output.
  - Example: `myfunc() { echo "result"; }` → `output=$(myfunc)`.

**B13**
- **`PATH`**: Colon-separated list of directories for command resolution.
- **Builtin vs external**: `type cmd` shows if it’s a builtin (e.g., `cd`) or external (e.g., `/bin/ls`).
- **Check**: `command -v cmd` (returns path or nothing).

**B14**
- **`trap`**: Sets up signal handlers.
  - Example:
    ```bash
    cleanup() { echo "Cleaning up"; }
    trap cleanup EXIT ERR INT TERM
    ```
- **Execution order**: Traps run in reverse order of registration for the same signal.

**B15**
- **`xargs` vs command substitution**:
  - `xargs`: Efficient for large datasets (avoids subshell overhead).
  - Command substitution: Simpler but limited by `ARG_MAX`.
- **`find -print0 | xargs -0`**: Handles filenames with spaces/newlines (null-delimited).
- **`xargs -P N`**: Runs up to `N` parallel processes.

**B16**
- **Arrays**:
  - Declare: `arr=("a" "b")`.
  - Append: `arr+=("c")`.
  - Iterate: `for i in "${arr[@]}"; do echo "$i"; done`.
  - Length: `${#arr[@]}`.
- **Associative arrays** (Bash ≥4):
  - Declare: `declare -A assoc=([key1]="val1" [key2]="val2")`.
  - Iterate: `for key in "${!assoc[@]}"; do echo "${assoc[$key]}"; done`.

**B17**
- **Subshell `( ... )`**: Runs in a child process (variables changes are lost).
- **Group command `{ ...; }`**: Runs in the current shell (variables persist). **Note**: Requires a semicolon or newline before `}`.
- **Piping into `while`**: Runs in a subshell (variables are lost). Fix: Use process substitution or `shopt -s lastpipe` (Bash ≥4.0).

**B18**
- **Signals**:
  - **SIGINT** (Ctrl+C): Interrupt (can be caught).
  - **SIGTERM**: Termination request (can be caught).
  - **SIGHUP**: Terminal closed (can be caught).
  - **SIGKILL**: Immediate termination (cannot be caught).
- **Graceful shutdown**:
  ```bash
  cleanup() { kill -TERM $bg_pid; wait $bg_pid; }
  trap cleanup TERM INT
  bg_command & bg_pid=$!
  wait $bg_pid
  ```

**B19**
- **Parallel log processing**:
  ```bash
  split -l 1000 large.log chunk_
  process() { awk '{print $1}' "$1" > "${1}.processed"; }
  export -f process
  find . -name 'chunk_*' -print0 | xargs -0 -P 4 -n 1 bash -c 'process "$@"' _
  cat chunk_*.processed > result
  ```
- **Trade-offs**: Faster but higher memory usage. Error handling: Check exit codes of `xargs` jobs.

**B20**
- **`exec`**: Replaces the current shell process with the command (no new process).
  - **File descriptor manipulation**:
    - `exec 3>file` (opens fd 3 for writing to `file`).
    - `exec 3>&-` (closes fd 3).
- **Coprocess**: Background process with bidirectional communication.
  - Example:
    ```bash
    coproc myproc { cat; }
    echo "Hello" >&${myproc[1]}
    read -p <&${myproc[0]}; echo "Received: $REPLY"
    ```
- **Use case**: Real-time data processing (e.g., reading/writing to a pipe).

### **PowerShell**

**PS1**
- **`Write-Output`**: Sends objects to the pipeline (can be captured/redirected).
- **`Write-Host`**: Writes directly to the console (bypasses pipeline). Avoid in scripts (not composable).

**PS2**
- **Pipeline**: Passes objects between commands (e.g., `Get-ChildItem | Where-Object { $_.Length -gt 100 }`).
- **`ForEach-Object`**: Processes each pipeline object (e.g., `1..3 | ForEach-Object { $_ * 2 }`).
- **`foreach` statement**: Loop construct (not pipeline-aware; e.g., `foreach ($i in 1..3) { $i }`).

**PS3**
- **`[PSCustomObject]`**: Lightweight object with properties (e.g., `[PSCustomObject]@{ Name = 'Alice' }`).
- **`[hashtable]`**: Key-value pairs (e.g., `@{ Name = 'Alice' }`).
- **Conversion**: `ConvertTo-Json` or `[PSCustomObject]$hashtable`.

**PS4**
- **Terminating errors**: Stop execution (e.g., `throw`, `Stop-Process -ErrorAction Stop`).
- **Non-terminating errors**: Continue execution (e.g., `Get-Item nonexistent`).
- **Error handling**:
  - `-ErrorAction Stop`: Converts non-terminating to terminating.
  - `$ErrorActionPreference`: Global setting (`Stop`, `Continue`, `SilentlyContinue`).
  - `try/catch`: Catches terminating errors.

**PS5**
- **Splatting**: Passes parameters from a hashtable/array.
  - Example:
    ```powershell
    $params = @{ Path = 'C:\'; Filter = '*.txt' }
    Get-ChildItem @params
    ```
- **Difference**: Splatting unpacks the hashtable; passing as a single parameter sends the hashtable itself.

**PS6**
- **PowerShell Remoting**: Uses **WinRM** (Windows) or **SSH** (PowerShell 7+).
- **`Invoke-Command -ComputerName`**: Runs a command on remote machines (returns results).
- **`Enter-PSSession`**: Starts an interactive session.
- **Double-hop problem**: Credentials aren’t passed to a second remote machine. **Solutions**:
  - **CredSSP**: `Enable-WSManCredSSP` (less secure).
  - **`Invoke-Command -ArgumentList`**: Pass credentials explicitly.

**PS7**
- **Issue**: PowerShell **unrolls arrays** in the pipeline.
  - Example output: `String` (not `Object[]`).
  - **Empty array**: Returns `$null`.
- **Correct pattern**: Use `[PSCustomObject][]` or `@()` to force array output:
  ```powershell
  function Get-Items {
    $result = @()
    $result += "one"
    return ,$result  # Comma forces array
  }
  ```

**PS8**
- **`[scriptblock]`**: A block of code (e.g., `{ Get-Process }`).
- **Function**: Named, reusable code block.
- **Passing scriptblocks remotely**:
  ```powershell
  $sb = { Get-Process }
  Invoke-Command -ComputerName Server1 -ScriptBlock $sb
  ```
- **Double-hop problem**: Scriptblocks are serialized; credentials aren’t passed. **Solutions**:
  - **CredSSP**: `Invoke-Command -Authentication CredSSP`.
  - **`$using:` scope**: For local variables in remote sessions.

**PS9**
- **`@()`**: Empty array or array subexpression.
- **`[array]`**: Type accelerator for `System.Array`.
- **Force single result into array**: `,$result` (comma operator).
- **Indexing**:
  - `$null[0]` → Error.
  - `@()[0]` → `$null` (no error).

**PS10**
- **Comparison operators**:
  - `-eq`, `-ne`: Equality/inequality (case-insensitive by default).
  - `-like`: Wildcard matching (`*` = any, `?` = single char).
  - `-match`: Regex matching.
  - `-contains`: Checks if a collection contains an item.
  - `-in`: Checks if an item is in a collection.
- **Case-sensitive variants**: `-ceq`, `-clike`, `-cmatch`, etc.
- **`-contains` vs `-in`**:
  - `1,2,3 -contains 2` → `$true`.
  - `2 -in 1,2,3` → `$true`.

**PS11**
- **Module**: Reusable package of cmdlets/functions.
  - **Script module (`.psm1`)**: PowerShell code.
  - **Manifest module (`.psd1`)**: Metadata (version, dependencies).
  - **Binary module**: Compiled .NET code.
- **`Import-Module`**: Loads a module into the session.

**PS12**
- **String interpolation**: Variables/expressions in `"..."` are expanded (e.g., `"Hello $name"`).
- **Single quotes (`'...'`)**: Literal (no expansion).
- **Here-string**: `@"..."@` (multi-line, interpolated) or `@'...'@` (literal).

**PS13**
- **`Get-Member`**: Lists properties/methods of an object.
- **Pipeline exploration**: `Get-Process | Get-Member -MemberType Property`.
- **`Select-Object`**: Selects properties (e.g., `Get-Process | Select-Object Name, Id`).
- **`Where-Object`**: Filters objects (e.g., `Get-Process | Where-Object { $_.CPU -gt 10 }`).

**PS14**
- **PowerShell classes**: Similar to C# but with limitations.
  - **Differences**: No multiple inheritance, limited interfaces, simpler syntax.
  - **Example**:
    ```powershell
    class Person {
      [string]$Name
      Person([string]$Name) { $this.Name = $Name }
    }
    ```
- **Use classes** for complex stateful objects; **functions** for simple logic.

**PS15**
- **`[CmdletBinding()]`**: Enables advanced features (e.g., `-Verbose`, `-WhatIf`).
  - **`SupportsShouldProcess`**: Adds `-WhatIf` and `-Confirm` support.
  - **`DefaultParameterSetName`**: Sets the default parameter set.
  - **`ValueFromPipeline`**: Accepts pipeline input.
- **Blocks**:
  - **`Begin`**: Runs once before processing.
  - **`Process`**: Runs for each pipeline object.
  - **`End`**: Runs once after processing.

**PS16**
- **Providers**: Extend PowerShell to work with data stores (e.g., filesystem, registry).
  - Example: `Get-ChildItem HKLM:\` (registry).
  - **Navigation**: `cd HKLM:\Software`, `dir cert:\CurrentUser\My`.

**PS17**
- **Runspaces**: Lightweight threads for parallel execution.
  - **`[runspace]`**: Single runspace.
  - **`[runspacepool]`**: Pool of reusable runspaces.
  - **`[powershell]`**: Instance of PowerShell in a runspace.
- **`ForEach-Object -Parallel` (v7+)**: Simplifies parallel execution:
  ```powershell
  1..10 | ForEach-Object -Parallel {
    $_ * 2
  } -ThrottleLimit 5
  ```

**PS18**
- **PSScriptAnalyzer**: Static code analysis for PowerShell.
  - **Rules**: Built-in (e.g., `PSAvoidUsingCmdletAliases`) or custom.
  - **Severity levels**: Error, Warning, Information.
  - **Suppression**: `# Suppress: PSAvoidUsingCmdletAliases`.
  - **CI/CD**: Integrate with Azure DevOps/GitHub Actions.

**PS19**
- **`$using:` scope**: Accesses local variables in remote sessions/background jobs.
  - Example: `Invoke-Command -ComputerName Server1 -ScriptBlock { $using:x }`.
- **`$args`/`-ArgumentList`**: Passes arguments to scriptblocks.
- **Serialization limits**: CLIXML depth (default: 2). Complex objects may be truncated.

**PS20**
- **DSC (Desired State Configuration)**: Declarative configuration management.
  - **Configurations**: PowerShell scripts defining desired state.
  - **Resources**: Modules (e.g., `xWindowsUpdate`) that implement configurations.
  - **LCM (Local Configuration Manager)**: Applies configurations.
- **Differences**:
  - **Windows PowerShell**: Full DSC support.
  - **PowerShell 7+**: Limited DSC (use **DSC v3** or alternatives like **Ansible**).
- **Modern replacement**: **Azure Policy**, **Chef**, **Puppet**, or **Ansible**.
