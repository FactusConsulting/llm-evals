### **.NET / C# Answers**

---

**DN1** — **Class vs Struct**:
- **Class**: Reference type (heap-allocated), supports inheritance, can be `null`.
- **Struct**: Value type (stack-allocated by default), no inheritance (but implements interfaces), cannot be `null` (unless nullable, e.g., `int?`).
- **Use a struct** when:
  - The type is small (≤ 16 bytes), immutable, and frequently instantiated (e.g., `Point`, `DateTime`).
  - Avoid for large or mutable data (due to copying overhead).

---

**DN2** — **IEnumerable<T> vs IQueryable<T>**:
- **IEnumerable<T>**: In-memory iteration (LINQ-to-Objects). Executes queries *locally* (e.g., `List<T>.Where`).
- **IQueryable<T>**: Represents a *database query* (LINQ-to-SQL/EF Core). Executes on the server (e.g., `DbSet<T>.Where` translates to SQL).
- **Why it matters**: `IQueryable` enables server-side filtering/paging (efficient), while `IEnumerable` loads all data first (inefficient for large datasets).

---

**DN3** — **async/await**:
- **How it works**: `async` marks a method as non-blocking. `await` suspends execution until the awaited `Task` completes, yielding control to the caller.
- **Task vs ValueTask**:
  - `Task`: Heap-allocated, supports continuation/chaining.
  - `ValueTask`: Stack-allocated (for high-performance scenarios), avoids heap overhead. Use when:
    - The operation is *synchronous* (e.g., cached results) or *very short-lived*.
    - Avoid for long-running or fire-and-forget operations (use `Task`).
- **Example**:
  ```csharp
  public ValueTask<int> GetCachedValueAsync() => new ValueTask<int>(42); // Sync result
  ```

---

**DN4** — **Dependency Injection (DI)**:
- **Service Lifetimes**:
  - **Transient**: New instance per injection (e.g., stateless services).
  - **Scoped**: One instance per request (e.g., `DbContext` in web apps).
  - **Singleton**: One instance for the app lifetime (e.g., configuration).
- **Common Bug**: Injecting a **Scoped** service (e.g., `DbContext`) into a **Singleton** (e.g., a background service). The `DbContext` may be disposed or shared across requests, causing `ObjectDisposedException` or concurrency issues.
- **Fix**: Use `Scoped` for request-bound services; avoid `Singleton` for stateful services.

---

**DN5** — **string vs ReadOnlySpan<char>**:
- **string**: Immutable, heap-allocated, UTF-16 encoded. Supports `Substring`, but creates new allocations.
- **ReadOnlySpan<char>**: Ref struct (stack-only), zero-copy slice of a string/char array. No allocations for slicing.
- **When to use `Span<T>`**:
  - High-performance parsing (e.g., parsing CSV/JSON without allocations).
  - Avoid for async methods (ref structs cannot cross `await` boundaries).
- **Example**:
  ```csharp
  ReadOnlySpan<char> span = "Hello".AsSpan().Slice(1, 3); // "ell" (no allocation)
  ```

---

**DN6** — **Garbage Collector (GC)**:
- **Generations**:
  - **Gen 0**: Short-lived objects (collected frequently).
  - **Gen 1**: Survived Gen 0 collection.
  - **Gen 2**: Long-lived objects (collected rarely).
- **Large Object Heap (LOH)**: Objects > 85KB (not compacted by default in .NET Core+).
- **IDisposable**: Manual cleanup for unmanaged resources (e.g., file handles). GC only reclaims *memory*, not external resources.
- **Why IDisposable?**: Prevents resource leaks (e.g., `SqlConnection`, `FileStream`).

---

**DN7** — **ConfigureAwait(false)**:
- **Default Behavior**: Captures `SynchronizationContext` (e.g., UI thread or ASP.NET context) to resume on the same thread.
- **ConfigureAwait(false)**: Avoids capturing context, improving performance in non-UI scenarios (e.g., libraries, async I/O).
- **When to Use**:
  - **Use**: In library code or non-UI apps (e.g., ASP.NET Core, console apps).
  - **Avoid**: In UI apps (e.g., WPF, WinForms) where resuming on the UI thread is required.
- **SynchronizationContext**: A mechanism to marshal continuations to a specific thread (e.g., UI thread).

---

**DN8** — **.NET 8/9 Features**:
- **Primary Constructors**: Declare constructor parameters directly in the class/record definition.
- **Collection Expressions**: Unified syntax for creating collections (e.g., `[1, 2, ..list, 3]`).
- **FrozenDictionary**: Immutable, high-performance dictionary (optimized for read-heavy scenarios).
- **Example with DI**:
  ```csharp
  public class MyService(IDbContext db) // Primary constructor
  {
      public void DoWork() => db.SaveChanges();
  }
  // Registration:
  builder.Services.AddSingleton<MyService>();
  ```

---

**DN9** — **DbContext ObjectDisposedException**:
- **Cause**: `DbContext` is **Scoped** (per request), but under high concurrency, requests may share a disposed context (e.g., due to async/await misconfiguration or manual disposal).
- **Fix**:
  - Ensure `DbContext` is **Scoped** (default in ASP.NET Core DI).
  - Avoid manual disposal (let DI handle it).
  - Do not inject `DbContext` into **Singleton** services.
- **EF Core Lifetime**: `DbContext` is not thread-safe. Each request should get its own instance.

---

**DN10** — **record vs class vs record struct**:
- **record**: Immutable by default (value-based equality), `init`-only properties, `with` expressions for copying.
- **class**: Mutable, reference-based equality.
- **record struct**: Value type (stack-allocated) with record features (e.g., `with`).
- **When to Use**:
  - **record**: DTOs, immutable data (e.g., API responses).
  - **class**: Mutable stateful objects.
  - **record struct**: High-performance immutable value types (e.g., `Point`).

---

**DN11** — **ref, out, in**:
- **ref**: Pass by reference (must be initialized).
- **out**: Pass by reference (no initialization required; caller must assign).
- **in**: Pass by read-only reference (avoids copying for large structs).
- **Usage**:
  - `ref`: Modify existing variables (e.g., `Swap(ref a, ref b)`).
  - `out`: Return multiple values (e.g., `TryParse(string, out int)`).
  - `in`: Optimize large structs (e.g., `ReadOnlySpan<char>`).

---

**DN12** — **Nullable Reference Types (NRT)**:
- **? Annotation**: Marks a reference type as nullable (e.g., `string?`). Enabled with `#nullable enable`.
- **Nullable Value Types**: `int?` (supports `null`; backed by `Nullable<T>`).
- **Difference**: NRT is a *compile-time* feature (static analysis), while `int?` is a *runtime* feature.

---

**DN13** — **LINQ**:
- **Method Syntax**: `list.Where(x => x > 0).Select(x => x * 2)`.
- **Query Syntax**: `from x in list where x > 0 select x * 2`.
- **Deferred Execution**: Queries are not executed until enumerated (e.g., `ToList()`, `foreach`). Enables chaining without intermediate allocations.

---

**DN14** — **Generic Constraints**:
- `where T : class`: T must be a reference type.
- `where T : struct`: T must be a value type.
- `where T : new()`: T must have a parameterless constructor.
- `where T : IComparable<T>`: T must implement `IComparable<T>`.
- **Combining Constraints**: `where T : class, IComparable<T>, new()`.

---

**DN15** — **Abstract Class vs Interface**:
- **Abstract Class**: Can have state, constructors, and partial implementations. Supports inheritance (single).
- **Interface**: No state, only method/contract definitions. Supports multiple inheritance.
- **Default Interface Methods (C# 8+)**: Interfaces can provide implementations (e.g., `public void Foo() => Console.WriteLine("Default");`). Useful for API evolution without breaking changes.

---

**DN16** — **Middleware Pipeline**:
- **app.Use()**: Adds middleware to the pipeline (runs on every request). Order matters (e.g., `UseAuthentication` before `UseAuthorization`).
- **app.Map()**: Branches the pipeline based on path (e.g., `Map("/api", ...)`).
- **app.Run()**: Terminal middleware (short-circuits the pipeline).
- **Exception Handling**: Use `app.UseExceptionHandler` early in the pipeline to catch exceptions from subsequent middleware.

---

**DN17** — **Channel<T> vs BlockingCollection<T>**:
- **Channel<T>**: Modern, async-friendly producer-consumer pattern. Supports backpressure (bounded channels).
- **BlockingCollection<T>**: Synchronous, thread-based (blocks on `Add`/`Take`).
- **Example (Bounded Channel)**:
  ```csharp
  var channel = Channel.CreateBounded<int>(capacity: 10);
  await channel.Writer.WriteAsync(1); // Blocks if full
  var value = await channel.Reader.ReadAsync(); // Blocks if empty
  ```

---

**DN18** — **Source Generators**:
- **What**: Compile-time code generation (e.g., auto-implement `INotifyPropertyChanged`).
- **vs Reflection/IL Weaving**:
  - **Reflection**: Runtime inspection (slow, no AOT support).
  - **IL Weaving**: Post-compile modification (e.g., Fody). Source generators are *compile-time* and AOT-friendly.
- **Incremental Generator**: Only processes changed files (faster builds). Preferred over `ISourceGenerator` for large projects.

---

**DN19** — **TPL Dataflow**:
- **Blocks**:
  - `ActionBlock<T>`: Processes input with a delegate.
  - `TransformBlock<T, U>`: Transforms input to output.
  - `BufferBlock<T>`: Stores data for later retrieval.
- **vs Channels**: Dataflow is higher-level (built-in blocks for pipelines), while `Channel<T>` is lower-level (more control over backpressure).
- **Example Pipeline**:
  ```csharp
  var buffer = new BufferBlock<int>();
  var transform = new TransformBlock<int, int>(x => x * 2);
  buffer.LinkTo(transform);
  ```

---
**DN20** — **Minimal APIs**:
- **What**: Lightweight APIs using `app.MapGet()`, `app.MapPost()`, etc.
- **vs Controllers**:
  - **Pros**: Less boilerplate, faster to write, integrates with endpoint routing.
  - **Cons**: Harder to test (no controller abstraction), limited middleware customization.
- **Route Groups**: Group endpoints with a common prefix (e.g., `app.MapGroup("/api")`).
- **Endpoint Filters**: Add metadata or pre/post-processing (e.g., `[Authorize]`).
- **OpenAPI Support**: Works with Swagger (via `AddEndpointsApiExplorer`).

### **Python Answers**

---

**P1** — **List vs Tuple vs Set vs Frozenset**:
- **List**: Mutable, ordered, allows duplicates (e.g., `[1, 2, 3]`).
- **Tuple**: Immutable, ordered, allows duplicates (e.g., `(1, 2, 3)`).
- **Set**: Mutable, unordered, unique elements (e.g., `{1, 2, 3}`).
- **Frozenset**: Immutable version of `set` (hashable, can be a dict key).

---

**P2** — **Global Interpreter Lock (GIL)**:
- **What**: A mutex that allows only one thread to execute Python bytecode at a time (per process).
- **Affected Workloads**: CPU-bound tasks (e.g., math, loops). I/O-bound tasks (e.g., network, file ops) are less affected (threads release the GIL during I/O).
- **Workarounds**:
  - **Multiprocessing**: Bypass the GIL (each process has its own GIL).
  - **Asyncio**: For I/O-bound tasks (single-threaded concurrency).
  - **C Extensions**: Release the GIL in C code (e.g., NumPy, `ctypes`).

---

**P3** — **deepcopy vs copy**:
- **copy()**: Shallow copy (new container, but nested objects are shared).
- **deepcopy()**: Recursively copies all nested objects.
- **Example of Shallow Copy Issue**:
  ```python
  original = [[1, 2], [3, 4]]
  shallow = original.copy()
  shallow[0][0] = 99  # Modifies original[0][0] too!
  ```

---

**P4** — **Decorators**:
- **What**: Functions that modify other functions (e.g., add logging, timing).
- **Example (Timing Decorator)**:
  ```python
  import time
  def timeit(func):
      def wrapper(*args, **kwargs):
          start = time.time()
          result = func(*args, **kwargs)
          print(f"{func.__name__} took {time.time() - start:.2f}s")
          return result
      return wrapper

  @timeit
  def slow_function():
      time.sleep(1)
  ```

---

**P5** — **Generators and yield**:
- **Generators**: Functions that `yield` values one at a time (lazy evaluation).
- **vs List**: Generators are memory-efficient (no precomputed list).
- **yield from**: Delegates to another generator (e.g., `yield from range(10)`).
- **Example**:
  ```python
  def count_up_to(n):
      i = 1
      while i <= n:
          yield i
          i += 1
  ```

---
**P6** — **asyncio**:
- **Event Loop**: Single-threaded, runs async tasks (coroutines).
- **asyncio.run()**: Starts the event loop and runs a coroutine.
- **asyncio.gather()**: Runs multiple coroutines concurrently (returns when all complete).
- **asyncio.create_task()**: Schedules a coroutine to run "in the background" (returns a `Task`).
- **Why not `time.sleep()`**: Blocks the entire thread (and the event loop). Use `await asyncio.sleep()` instead.

---

**P7** — **Method Resolution Order (MRO)**:
- **Algorithm**: C3 Linearization (Python 3).
- **Diamond Inheritance Example**:
  ```python
  class A: pass
  class B(A): pass
  class C(A): pass
  class D(B, C): pass
  print(D.__mro__)  # (<class 'D'>, <class 'B'>, <class 'C'>, <class 'A'>, <class 'object'>)
  ```
  - **Output**: `D().who()` returns `"C"` because `C` comes before `B` in the MRO (due to `D(B, C)`).

---

**P8** — **Metaclass vs __init_subclass__**:
- **Metaclass**: Controls class creation (e.g., `type` or custom). Use for advanced class customization (e.g., ORMs, singletons).
- **__init_subclass__**: Hook called when a class is subclassed (simpler than metaclasses).
- **Example Metaclass**:
  ```python
  class Meta(type):
      def __new__(cls, name, bases, attrs):
          attrs["version"] = 1.0
          return super().__new__(cls, name, bases, attrs)

  class MyClass(metaclass=Meta):
      pass
  print(MyClass.version)  # 1.0
  ```
- **Example __init_subclass__**:
  ```python
  class Base:
      def __init_subclass__(cls, **kwargs):
          cls.version = 2.0

  class Child(Base):
      pass
  print(Child.version)  # 2.0
  ```

---
**P9** — **Multiprocessing vs Threading vs concurrent.futures**:
- **Threading**: Lightweight, but limited by GIL (good for I/O-bound tasks).
- **Multiprocessing**: Bypasses GIL (good for CPU-bound tasks). Uses `pickle` for serialization (no shared memory by default).
- **concurrent.futures**: High-level interface for both (`ThreadPoolExecutor`, `ProcessPoolExecutor`).
- **When to Use**:
  - **Threading**: I/O-bound (e.g., HTTP requests).
  - **Multiprocessing**: CPU-bound (e.g., data processing).
  - **concurrent.futures**: Simplify thread/process pools.

---
**P10** — **__slots__**:
- **What**: Predeclares instance attributes to save memory (avoids `__dict__`).
- **Memory Impact**: Reduces memory usage by ~40-50% for classes with many instances.
- **Example**:
  ```python
  class Point:
      __slots__ = ["x", "y"]
      def __init__(self, x, y):
          self.x = x
          self.y = y
  ```
- **Downside**: Cannot add new attributes dynamically.

---
**P11** — **Virtual Environments**:
- **venv**: Built-in (Python 3.3+), creates isolated environments.
- **virtualenv**: Third-party, supports older Python versions.
- **conda**: Cross-language (Python, R, etc.), manages dependencies and environments (heavier).
- **Why Use**: Isolate project dependencies (avoid conflicts).

---
**P12** — **Comprehensions**:
- **List**: `[x * 2 for x in range(5)]`.
- **Dict**: `{x: x * 2 for x in range(5)}`.
- **Set**: `{x * 2 for x in range(5)}`.
- **vs map/filter**:
  - Comprehensions are more readable for simple transformations.
  - `map`/`filter` are functional-style (can be chained).

---
**P13** — **== vs is**:
- **==**: Value equality (e.g., `1 == 1.0` is `True`).
- **is**: Identity (same object in memory, e.g., `a is b`).
- **Object Interning**: Python caches small integers (-5 to 256) and strings, so `a = 1; b = 1; a is b` is `True`.

---
**P14** — **\*args and \*\*kwargs**:
- **\*args**: Collects positional arguments as a tuple.
- **\*\*kwargs**: Collects keyword arguments as a dict.
- **Positional-Only (/)**: Forces args before `/` to be positional (e.g., `def f(a, b, /, c):`).
- **Keyword-Only (\*)**: Forces args after `*` to be keyword-only (e.g., `def f(a, *, b):`).

---
**P15** — **Context Managers**:
- **with Statement**: Ensures resources are cleaned up (e.g., files, locks).
- **__enter__/__exit__**:
  ```python
  class MyContext:
      def __enter__(self):
          print("Enter")
          return self
      def __exit__(self, exc_type, exc_val, exc_tb):
          print("Exit")
  with MyContext():
      pass
  ```
- **@contextmanager**:
  ```python
  from contextlib import contextmanager
  @contextmanager
  def timer():
      start = time.time()
      yield
      print(f"Time: {time.time() - start}")
  ```

---
**P16** — **Type Hinting**:
- **Union**: `Union[int, str]` (value can be `int` or `str`).
- **Optional**: `Optional[int]` (equivalent to `Union[int, None]`).
- **Literal**: `Literal["a", "b"]` (value must be `"a"` or `"b"`).
- **TypeVar**: Generic types (e.g., `T = TypeVar("T")`).
- **Protocol**: Structural subtyping (duck typing, e.g., `class SupportsClose(Protocol): def close(self): ...`).
- **Tools**: `mypy`/`pyright` perform static type checking.

---
**P17** — **Data Model (Dunder Methods)**:
- **__repr__**: Unambiguous representation (for debugging).
- **__str__**: Readable representation (for users).
- **__eq__**: Equality check. If defined, `__hash__` should also be defined (or set to `None`).
- **__getattr__**: Called when an attribute is not found (fallback).
- **__getattribute__**: Called for *every* attribute access (can break things if not careful).

---
**P18** — **Descriptors**:
- **Protocol**: `__get__`, `__set__`, `__delete__` define how attribute access works.
- **Example**:
  ```python
  class Descriptor:
      def __get__(self, obj, objtype):
          return 42
  class MyClass:
      attr = Descriptor()
  print(MyClass().attr)  # 42
  ```
- **Built-in Descriptors**:
  - `property`: Combines getter/setter/deleter.
  - `classmethod`: Binds a method to the class.
  - `staticmethod`: No binding.

---
**P19** — **Import System**:
- **Relative vs Absolute Imports**:
  - Absolute: `from package.module import x`.
  - Relative: `from .module import x` (within a package).
- **sys.path**: List of directories Python searches for modules.
- **PYTHONPATH**: Environment variable to extend `sys.path`.
- **__init__.py**: Marks a directory as a package (can be empty in Python 3.3+ with "namespace packages").
- **Finder/Loader**: `sys.meta_path` finders locate modules; loaders load them.

---
**P20** — **dataclasses vs attrs vs Pydantic**:
- **dataclasses**: Auto-generates `__init__`, `__repr__`, etc. (Python 3.7+).
  - **Features**: `__post_init__` (post-initialization), `field(default_factory=list)`, `frozen=True` (immutable).
  - **Inheritance**: Works with `dataclass` inheritance.
- **attrs**: Predecessor to `dataclasses` (more features, e.g., validators).
- **Pydantic**: Adds runtime type validation, serialization (JSON), and data parsing.
- **When to Use Pydantic**: For APIs (FastAPI), data validation, or settings management.
- **Example**:
  ```python
  from dataclasses import dataclass, field
  @dataclass
  class Point:
      x: int
      y: int = field(default=0)
      def __post_init__(self):
          if self.x < 0:
              raise ValueError("x must be >= 0")
  ```
