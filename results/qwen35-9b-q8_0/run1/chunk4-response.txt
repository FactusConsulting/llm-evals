## Go (20 questions)

**G1**
Arrays are fixed-size, value types stored contiguously in memory. Slices are dynamic views into an underlying array, storing a pointer, length, and capacity. When appending to a slice at capacity, Go allocates a new backing array (typically 1.5x or 2x the old capacity), copies the existing elements, and updates the slice header.

**G2**
`var x int` declares `x` with a zero value (0). `x := 0` declares and initializes `x`. You cannot use `:=` if the variable is already declared in the current scope (e.g., `var x int; x := 1` is invalid). You also cannot use `:=` in function scopes where the variable is already declared in the enclosing scope (though Go 1.22+ allows `:=` in function scope for new variables).

**G3**
A goroutine is a lightweight thread of execution managed by the Go runtime. Unlike OS threads (heavy, limited count), goroutines are multiplexed onto OS threads. The GMP model (Goroutine, Machine, Processor) manages this: Gs are scheduled onto Ps (processors), which run on Ms (OS threads). The scheduler multiplexes thousands of Gs onto a smaller pool of Ps.

**G4**
Channels are typed conduits for communication between goroutines. Unbuffered channels block the sender until a receiver is ready. Buffered channels hold up to `N` values; sending blocks only if the buffer is full. Sending to a full buffered channel blocks the sender until space is available.

**G5**
The `context` package manages request-scoped values (deadlines, cancellation, keys).
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
resp, err := http.Get("https://example.com", ctx)
```
The request is cancelled if it exceeds 5 seconds or if `cancel()` is called.

**G6**
Go uses implicit interface satisfaction (duck typing); a type implements an interface if it has the required methods. Java/C# require explicit implementation. `interface{}` (or `any`) holds values of any type. It is powerful for generic-like behavior and JSON marshaling but dangerous because type assertions can panic if the type is incorrect.

**G7**
This is unsafe due to a data race. `ready` and `data` are not atomic, and the compiler/GC may reorder writes. The main goroutine may read `data` before the goroutine writes it. Correct alternatives: use `sync/atomic` for `ready` and `data`, or wrap writes/reads in a `sync.Mutex`.

**G8**
`sync.Mutex` allows only one lock (exclusive). `sync.RWMutex` allows multiple concurrent readers but exclusive writers. `sync.Map` is optimized for high read concurrency with fast reads and slower writes (uses a hash table with sharding). Regular maps with mutexes are better for write-heavy workloads or low contention.

**G9**
Go modules manage dependencies. `go.mod` declares the module path and dependencies. `go.sum` stores checksums for security. `go mod tidy` cleans up unused dependencies and updates versions. MVS (Minimum Version Selection) selects the lowest version of a dependency that satisfies all constraints to ensure stability.

**G10**
`defer` schedules a function to run when the surrounding function returns. Multiple defers execute in LIFO (Last-In, First-Out) order. A common gotcha is capturing loop variables by reference; all defers may print the final loop value. Use `:=` to capture the value.

**G11**
A pointer stores the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `&Struct{}`.

**G12**
`init()` runs before `main()`. It executes package-level initializers. A package can have multiple `init()` functions (one per file). They execute in file order, then in the order they appear in the file.

**G13**
`make` allocates and initializes slices, maps, and channels (e.g., `make(map[string]int)`). `new` allocates a zeroed value and returns a pointer (e.g., `new(int)`). `make` works only with slices/maps/channels; `new` works with any type.

**G14**
Go uses explicit error returns. The `error` interface has one method `Error() string`. The idiomatic pattern is `if err != nil`. `errors.Is` checks if an error matches a specific error (useful for wrapped errors). `errors.As` type-asserts an error to a specific type. `==` only compares identity, not wrapped content.

**G15**
Built-in composite types: `map`, `slice`, `channel`, `struct`. Zero values: `nil` (map, channel), empty slice (slice), zero struct (struct).

**G16**
A race condition occurs when two goroutines access shared memory concurrently without synchronization. The `-race` flag uses ThreadSanitizer to detect data races at runtime.
*Race:* `var x int; go func() { x = 1 }(); x = 2`.
*Fix:* `var mu sync.Mutex; mu.Lock(); x = 1; mu.Unlock(); x = 2`.

**G17**
`select` multiplexes on channel operations. Like a `switch` on channels. If multiple cases are ready, one is chosen randomly. To implement a timeout: use `select` with `time.After(d)` alongside the channel operations.

**G18**
Escape analysis determines if a variable escapes the stack frame (e.g., stored in a global or returned). If it escapes, it is allocated on the heap. Inspect with `go build -gcflags="-m"`. It matters because heap allocation incurs GC overhead; stack allocation is faster.

**G19**
`reflect.Type` describes a type (metadata). `reflect.Value` holds the actual data. Reflection is slow (dynamic dispatch). It is justified for dynamic code generation or generic-like behavior where generics aren't available. Code generation (e.g., `go generate`) is preferred for performance.

**G20**
`go:embed` embeds files at compile time. `//go:embed "file.txt"` embeds a file. `//go:embed "dir/*"` embeds a directory. It returns an `io/fs.FS`. Limitations: cannot embed from network, cannot embed from outside the module path, and requires Go 1.16+.

## Rust (20 questions)

**R1**
Ownership ensures memory safety without garbage collection. Rules: 1. Each value has one owner. 2. When the owner goes out of scope, the value is dropped. 3. You can have either immutable references (`&T`) or one mutable reference (`&mut T`), but not both.

**R2**
`String` is an owned, heap-allocated UTF-8 string. `&str` is a borrowed slice of UTF-8 data. Use `String` when you need to own the data (return from functions). Use `&str` for function arguments to avoid unnecessary copies.

**R3**
Borrowing allows accessing data without ownership. `&T` allows immutable access; `&mut T` allows mutable access. Rules: You cannot have multiple mutable references, nor a mutable and immutable reference simultaneously.

**R4**
`Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents presence (`Some(T)`) or absence (`None`). The `?` operator propagates errors/None up the call stack.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)?
}
```

**R5**
`Box<T>` is a heap-allocated pointer with single ownership. `Rc<T>` is a thread-local reference-counted pointer. `Arc<T>` is a thread-safe reference-counted pointer. Use `Box` for single ownership, `Rc` for single-threaded sharing, `Arc` for multi-threaded sharing.

**R6**
Traits define shared behavior. Like Go interfaces but explicit. `dyn Trait` (trait objects) use dynamic dispatch (heap). `T: Trait` (generics) use static dispatch (monomorphization). Generics are preferred for performance.

**R7**
This code compiles in modern Rust due to lifetime elision, but conceptually requires the return reference to live as long as the longer input. If lifetimes differ, it fails. Fix: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8**
`Send` allows moving a type across threads. `Sync` allows shared access. `Rc<T>` is not `Send` because reference counting is not atomic. `Arc<T>` uses atomic reference counting, making it `Send` and `Sync` for safe concurrent use.

**R9**
`async/await` is syntactic sugar over `Future` traits. A `Future` represents a computation that yields a value later. An executor (e.g., Tokio) drives futures to completion. Unlike Go goroutines (OS threads), Rust async tasks are cooperative and lightweight, running on a single thread.

**R10**
`unsafe` blocks allow bypassing safety checks. 3 things: Raw pointers (`*const T`), FFI calls, and `unsafe` functions. Justified for performance-critical code or when interfacing with C libraries.

**R11**
`match` exhaustively matches all variants of an enum. `if let` matches a specific variant. The compiler enforces exhaustiveness in `match`; `if let` is optional.

**R12**
`Vec<T>` is a dynamic array on the heap. `[T; N]` is a fixed-size array (stack or heap). `Vec` reallocates when capacity is exceeded (typically 1.5x growth) to avoid frequent copies.

**R13**
Enums are tagged unions. `Option<T>` is `None` or `Some(T)`. Rust has no null; `Option` replaces it to force explicit handling of absence.

**R14**
`impl` defines methods. `&self` (read), `&mut self` (write), `self` (move). Associated functions (e.g., `String::new()`) take `&Self` or no self.

**R15**
Derive macros generate implementations automatically. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if the struct has private fields (for some traits) or complex logic.

**R16**
`Cow<'a, T>` (Clone on Write) borrows if immutable, clones if mutable. Useful for string processing: `Cow::Borrowed` avoids allocation if the string is already owned.
```rust
let s = Cow::Borrowed("hello");
let mut s = s.into_owned(); // Only clones if mutation needed
```

**R17**
`mod` declares a module. `use` imports items. `pub` makes items public. 2015 edition: `mod` was private by default. 2018 edition: `mod` is public by default. File system maps to modules (e.g., `src/lib.rs` -> `lib` module).

**R18**
`Pin<T>` prevents a value from being moved. Needed for async/await where futures contain pointers to themselves (self-referential). `Unpin` allows moving.

**R19**
`macro_rules!` are declarative (textual replacement). Procedural macros (derive, attribute) are Rust functions that generate code. Hygiene rules ensure macros don't pollute the outer scope with names.

**R20**
Zero-cost abstractions mean high-level code compiles to code as efficient as hand-written C. Iterators, generics (monomorphization), and trait static dispatch are optimized by the compiler at compile time with no runtime overhead.
