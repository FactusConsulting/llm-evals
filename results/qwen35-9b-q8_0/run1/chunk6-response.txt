JS1 — var is function-scoped and hoisted (initialized to undefined). let and const are block-scoped and hoisted (but const/let throw TDZ errors before declaration). Hoisting moves declarations to the top of the scope, but initialization stays in place.

JS2 — The event loop processes the call stack. When the stack is empty, it checks the microtask queue (Promises, queueMicrotask) first. Once microtasks are empty, it processes the macrotask queue (setTimeout, I/O). This ensures async callbacks run after sync code completes.

JS3 — A closure is a function bundled with its lexical scope. Example: `function counter() { let n=0; return () => ++n; }`. The classic bug: `var i` in a loop creates one shared `i` for all closures. Fix: Use `let` (block scope) or an IIFE to capture the current `i`.

JS4 — Promises represent async completion. async/await is syntactic sugar for Promises. Errors in async/await are caught via try/catch. Promise.all rejects on the first failure. Promise.allSettled waits for all and returns status (fulfilled/rejected) for each.

JS5 — Interfaces define shapes (methods/properties) for objects. Types define primitives or unions. Use interfaces for object contracts, types for primitives/complex unions. Discriminated unions are unions with literal types (e.g., `{ type: 'A' } | { type: 'B' }`) to narrow types via property checks.

JS6 — Prototypal inheritance links objects via `[[Prototype]]`. `Object.create(proto)` sets this link. ES6 classes are syntactic sugar; they compile to constructor functions and prototype manipulation.

JS7 — `this` is determined by the call site. Priority: 1. `new` (constructor). 2. Explicit (`bind`, `call`, `apply`). 3. Implicit (object method). 4. Default (window/undefined). `bind()` returns a new function with bound `this`. It can be re-bound.

JS8 — WeakRef holds a weak reference to an object (allows GC). FinalizationRegistry runs a callback when the object is garbage collected. WeakMap keys must be objects (not primitives) because primitives are immutable and cannot be garbage collected independently.

JS9 — V8 uses hidden classes to optimize property access patterns. Inline caching stores type checks. Deoptimization occurs if the pattern changes (e.g., adding a property), forcing a fallback to slower generic execution.

JS10 — Tree-shaking removes unused code via static analysis. ES Modules allow this because imports are static. CommonJS uses dynamic `require`, preventing analysis of usage, so it cannot be tree-shaken effectively.

JS11 — `null` is an explicit value; `undefined` is missing. `==` coerces types (null==undefined is true). `===` checks strict equality. `??` returns the right operand if the left is nullish. `?.` safely accesses properties (returns undefined if null/undefined).

JS12 — `map()` transforms elements. `filter()` reduces to a subset. `reduce()` aggregates to a single value. `reduce()` with an initial value starts accumulation with that value. `flatMap()` maps then flattens one level.

JS13 — Template literals use backticks. Tagged templates pass arguments as an array to a function. Example: `sql` template function receives values to prevent SQL injection.

JS14 — Destructuring extracts values. Object: `{ a: b }`. Array: `[ a, b ]`. Defaults: `a = 1`. Rest: `...rest` collects remaining elements.

JS15 — `for...in` iterates enumerable properties (objects). `for...of` iterates values (iterables). Avoid `for...in` on arrays as it includes inherited properties and is slower.

JS16 — Generics allow type parameters `<T>`. Constraints: `T extends X`. Conditional: `T extends U ? X : Y`. Infer: `infer U` extracts types from conditional types.

JS17 — CommonJS uses `require/module.exports`. ES Modules use `import/export`. Node.js supports both via flags. `"type": "module"` in package.json makes `.js` files ESM by default.

JS18 — Structural typing checks shape, not name. Excess property checks apply to object literals passed to functions. `extends` checks strict equality; `satisfies` checks loose compatibility. Variance: `in` (input) and `out` (output) determine if types are covariant or contravariant.

JS19 — Proxy wraps objects to intercept operations. Reflect provides standard operations. Intercept: `get` (access), `set` (assign), `apply` (call). Example: Validation wrapper or logging middleware.

JS20 — SharedArrayBuffer allows shared memory between threads. Atomics provides wait/notify for synchronization. Workers communicate via SharedArrayBuffer. Ordering guarantees ensure memory visibility. `Atomics.wait` blocks until notified.

B1 — `$@` expands to all arguments as separate words. `$*` expands to all arguments as a single string. `"$@"` preserves spaces in arguments. `"$*"` treats all as one string.

B2 — `-e`: exit on error. `-u`: exit on unset variable. `-o pipefail`: exit if any command in a pipeline fails.

B3 — `$(cmd)` is command substitution (subshell). `cmd` runs in current shell. `$((expr))` is arithmetic expansion. `expr` is an external command for arithmetic.

B4 — `<(cmd)` creates a named pipe (file descriptor). Use for `diff <(cmd1) <(cmd2)` to compare outputs without temp files.

B5 — `for f in $(ls)` splits on whitespace, breaking filenames with spaces. Use `for f in "$@"` or `while read -r f`.

B6 — `<<EOF` is a here document (multi-line). `<<<` is a here string (single line). `<<-EOF` strips leading whitespace from lines.

B7 — `cmd > file 2>&1`: stdout to file, stderr to stdout (file). `cmd 2>&1 > file`: stderr to stdout (terminal), stdout to file. `cmd &> file`: both to file. First two differ because redirection order matters.

B8 — Use `mkdir -p lockdir` and `flock`. `mkdir` is atomic on most filesystems. Trap `EXIT` to remove the lock directory.

B9 — Single quotes: literal. Double quotes: variable expansion. No quotes: globbing. Example: `'echo $var'` vs `"echo $var"`.

B10 — `[ -f ]`, `[ -d ]`, `[ -r ]`. `[ ]` performs word splitting/globbing. `[[ ]]` supports regex and no globbing.

B11 — `$?`: last exit code. `$$`: current PID. `$!`: last background PID. `$#`: number of arguments.

B12 — `function foo` vs `foo() {}` are equivalent. Return values via `return` or `echo`.

B13 — PATH is colon-separated directories. Bash resolves commands by searching PATH. Builtins are in hash table; externals are files. Use `type` to check.

B14 — `trap` sets signal handlers. `EXIT`: always. `ERR`: error. `INT`: Ctrl+C. `TERM`: kill. Execution order: handlers run before script exits.

B15 — `xargs` passes arguments to a command. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P` runs parallel processes.

B16 — Arrays: indexed (`declare -a`). Associative: key-value (`declare -A`). Iterate: `for i in "${arr[@]}"`. Length: `${#arr[@]}`.

B17 — Subshell `(...)` creates new scope (var changes lost). Group `{ ... }` shares scope. Piping into `while` creates a subshell, losing variable changes.

B18 — SIGINT: Ctrl+C. SIGTERM: graceful kill. SIGHUP: hangup. SIGKILL: force. Handle with `trap` and cleanup background jobs.

B19 — `split -l`, `xargs -P`, `cat` results. Trade-off: parallelism vs coordination overhead. Handle errors by checking exit codes in the processing function.

B20 — `exec` replaces the shell. `exec 3>file` redirects FD 3. Coprocess: `coproc` for bidirectional communication. Use for background processes needing input/output.

PS1 — `Write-Output` sends objects to pipeline. `Write-Host` writes to screen. Distinction matters because `Write-Host` breaks pipelines.

PS2 — Pipeline passes objects. `ForEach-Object` is a cmdlet (pipeline). `foreach` is a script block (local scope).

PS3 — `[PSCustomObject]` creates objects with properties. `[hashtable]` is key-value pairs. Convert: `ConvertTo-Json` or `New-Object`.

PS4 — Terminating errors stop the pipeline. Non-terminating continue. `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` handles terminating errors.

PS5 — Splatting `@params` passes a hashtable as arguments. Passing a hashtable as a single parameter treats it as one object.

PS6 — `Invoke-Command` runs a script. `Enter-PSSession` is interactive. Uses WinRM (default) or SSH.

PS7 — Pipeline returns arrays. `Get-Items` returns `@("one")`. `$x.GetType().Name` is `Object[]`. Unexpected because users expect a scalar. Correct pattern: return scalar or ensure array handling.

PS8 — `[scriptblock]` is executable code. Double-hop: Kerberos ticket delegation fails. Solve with CredSSP or `-Credential`.

PS9 — `@()` creates an array. `[array]` casts. Indexing `$null` throws error. Empty array `$arr[0]` returns `$null`.

PS10 — `-eq` numeric. `-like` wildcard. `-match` regex. `-contains` checks array. `-in` checks array. Case-sensitive variants exist (`-ceq`).

PS11 — Module: collection of functions. `.psm1`: code. `.psd1`: manifest. `Import-Module` loads them.

PS12 — Interpolation: `"{0}"`. Here-string: `@"..."@`. Single quotes disable interpolation.

PS13 — `Get-Member` lists properties/methods. `Select-Object` selects props. `Where-Object` filters.

PS14 — Classes: C# like. Limited inheritance. Use for encapsulation.

PS15 — `CmdletBinding` enables advanced functions. `SupportsShouldProcess` adds `-Confirm`. `Process`/`Begin`/`End` blocks handle pipeline flow.

PS16 — Providers: FileSystem, Registry, etc. `Get-ItemProperty` accesses registry like files.

PS17 — `[runspace]` is a thread. `[runspacepool]` manages threads. `-Parallel` (v7+) uses runspace pool.

PS18 — `PSScriptAnalyzer` enforces standards. Rules have severity. Suppress via `# #`. Integrate with CI/CD.

PS19 — `$using:` passes variables by reference (no serialization). `$args` serializes. Limits: CLIXML depth (1000).

PS20 — DSC: config management. Configs, Resources, LCM. Replaced by Ansible/Terraform in modern IaC.
