## Kubernetes (20 questions)

**K1**
A **Deployment** manages stateless applications, ensuring a specified number of replicas are running and supporting rolling updates. A **StatefulSet** manages stateful applications, providing stable network identities (pod names), ordered deployment/termination, and persistent storage per pod.

**K2**
A **ClusterIP** Service creates a virtual IP within the cluster. Traffic is routed via the Service IP to the **Endpoints** object (which lists healthy Pod IPs). **kube-proxy** monitors these endpoints and updates iptables/IPVS rules to forward traffic from the Service IP to the Pod IPs.

**K3**
*   **PersistentVolume (PV):** A piece of storage in the cluster provisioned by an administrator or dynamically.
*   **PersistentVolumeClaim (PVC):** A request for storage by a user (Pod).
*   **StorageClass:** Defines the provisioner and parameters for dynamically provisioning PVs.
*   **Relation:** A PVC requests storage based on a StorageClass; the system creates a matching PV and binds it to the PVC.

**K4**
1.  **Check Logs:** `kubectl logs <pod>` to see application errors.
2.  **Check Events:** `kubectl describe pod <pod>` to see `CrashLoopBackOff` reasons or OOMKilled events.
3.  **Check Probes:** Verify readiness/liveness probe configurations and failure thresholds.
4.  **Check Resources:** Ensure CPU/Memory requests/limits aren't causing eviction or OOM kills.

**K5**
**CoreDNS** is the default DNS server for the cluster, resolving internal service names (e.g., `my-svc.default.svc.cluster.local`) to Pod IPs. If CoreDNS pods are down, internal DNS resolution fails, breaking service discovery and communication between pods.

**K6**
The scheduler follows three phases:
1.  **Filtering:** Removes nodes that don't meet hard constraints (resources, taints, affinity).
2.  **Scoring:** Ranks remaining nodes based on soft constraints (topology spread, node affinity, resource utilization).
3.  **Selection:** Picks the highest-scoring node.
*Factors:* Node Affinity, Taints/Tolerations, Resource Availability (CPU/RAM).

**K7**
*   **Will it schedule?** Yes. The node has 4GB total, 3.5GB requested. Available = 0.5GB (512Mi). Pod requests 256Mi. 256Mi < 512Mi, so it fits.
*   **Runtime behavior:** If the pod uses 600Mi, it exceeds the `limits.memory` (512Mi). The kernel will **OOMKill** the container.

**K8**
1.  **External LB:** Receives traffic on port 80.
2.  **Ingress Controller:** Receives traffic, parses Ingress rules, and routes to the backend Service.
3.  **Service (ClusterIP):** Internal endpoint for the Ingress Controller.
4.  **Endpoints:** List of Pod IPs associated with the Service.
5.  **kube-proxy:** Updates iptables/IPVS to forward traffic from Service IP to Pod IPs.
6.  **Pod:** Application receives the request.

**K9**
A **NetworkPolicy** restricts ingress/egress traffic for pods.
*   **Default behavior:** Without policies, all ingress/egress traffic is **allowed** by default.
*   **With policy:** Traffic is restricted to only what is explicitly allowed (e.g., only from specific pods or namespaces).

**K10**
*   **RollingUpdate:** Updates pods one by one, keeping the desired replica count available (zero downtime).
*   **Recreate:** Terminates all old pods before starting new ones (downtime).
*   **Use Recreate:** When the application cannot handle downtime (e.g., databases) or requires a clean state reset.

**K11**
A **Namespace** provides a virtual cluster within a physical cluster for resource isolation.
*   **Default namespaces:** `default`, `kube-system`, `kube-public`, `kube-node-lease`.

**K12**
`kubectl describe pod` shows detailed metadata and runtime status.
*   **3 pieces of info not in `get`:**
    1.  **Events:** History of pod lifecycle events (e.g., "FailedMount").
    2.  **Conditions:** Detailed status of readiness, liveness, and running states.
    3.  **Node:** The specific node the pod is scheduled on.

**K13**
A **ConfigMap** stores non-confidential configuration data as key-value pairs.
*   **Methods:**
    1.  **Environment Variables:** Injected as env vars in the pod spec.
    2.  **Volume Mounts:** Mounted as files or directories inside the container.

**K14**
*   **ClusterIP:** Internal-only service (default).
*   **NodePort:** Exposes the service on a static port on each Node's IP.
*   **LoadBalancer:** Provisions an external cloud load balancer to expose the service externally.

**K15**
A **DaemonSet** ensures a copy of a Pod runs on all (or a subset of) nodes.
*   **Use case:** Instead of Deployment, use DaemonSet for node-level agents like logging collectors (Fluentd), monitoring agents (Prometheus Node Exporter), or CNI plugins (Calico).

**K16**
*   **Taints/Tolerations:** Taints push pods away from a node; Tolerations allow specific pods to ignore taints.
*   **Node Affinity:** Pulls pods to specific nodes based on labels.
*   **Use Case:** Taints for GPU nodes (only pods with GPU toleration can run); Affinity for placing DBs on specific hardware.

**K17**
An **Operator** is a specialized controller that manages the lifecycle of a complex application (e.g., databases, message queues).
*   **Difference:** Standard controllers manage generic resources (Pods, Deployments); Operators manage custom resources (CRDs) representing the application.
*   **Problem Solved:** Automates complex operations like backups, scaling, upgrades, and self-healing that standard controllers don't handle.

**K18**
Kubernetes uses **Raft** for etcd consistency.
*   **Quorum Loss:** If quorum is lost (e.g., 2/3 nodes down), the cluster becomes unavailable to prevent data corruption.
*   **Recovery:** Restore etcd from a snapshot or rebuild the cluster with new nodes and restore data from a backup.

**K19**
*   **Role/ClusterRole:** Defines permissions (verbs, resources).
*   **RoleBinding/ClusterRoleBinding:** Binds permissions to subjects (users/groups).
*   **Manifests:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: default
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods
  namespace: default
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20**
**ndots** defines how many dots must precede a domain name to be treated as a fully qualified domain name (FQDN). If `ndots` is high (default 5), short names trigger multiple DNS queries (splitting the domain).
*   **Fix:** Add `dnsConfig` to the pod spec:
```yaml
dnsConfig:
  options:
  - name: ndots
    value: "1"
```

## Development (20 questions)

**D1**
*   **Rebase:** Rewrites history to merge changes linearly onto the target branch.
*   **Merge:** Preserves history by creating a merge commit.
*   **Avoid Rebase:** On public/shared branches (e.g., `main`) or when others depend on the commit history.

**D2**
*   **TCP:** Reliable, connection-oriented, ordered delivery. Protocols: HTTP, SSH.
*   **UDP:** Unreliable, connectionless, fast. Protocols: DNS, VoIP.

**D3**
A **race condition** occurs when the behavior of a program depends on the relative timing of events.
*   **Example:** Two threads increment a shared counter. Thread A reads 10, Thread B reads 10. Both write 11. Final result is 11 instead of 12.

**D4**
*   **Symmetric:** Same key for encryption/decryption (e.g., AES). Fast.
*   **Asymmetric:** Public/Private key pair (e.g., RSA). Secure key exchange.
*   **TLS:** Uses Asymmetric encryption to securely exchange a Symmetric key, then uses Symmetric encryption for data transfer.

**D5**
A **layer** is a read-only filesystem created by a Dockerfile instruction.
*   **Caching:** Docker caches layers. Best practice: Place changing instructions (like `COPY` source code) at the bottom of the Dockerfile to maximize cache hits for static layers (like `RUN apt-get`).

**D6**
1.  **Application Logs:** Check for 503 errors or timeouts.
2.  **Health Checks:** Verify the `/health` endpoint returns 200.
3.  **Database Connection:** Ensure the DB is reachable and not overloaded.
4.  **Rate Limiting:** Check if upstream services are throttling requests.

**D7**
**CAP Theorem:** A distributed system can only guarantee two of three: Consistency, Availability, Partition Tolerance.
*   **CP:** Zookeeper (prioritizes data consistency over availability during partitions).
*   **AP:** DynamoDB (prioritizes availability; may return stale data during partitions).

**D8**
*   **Horizontal:** Adding more instances (scale out).
*   **Vertical:** Increasing resources of existing instances (scale up).
*   **Pattern:** Stateless architecture with a Load Balancer enables horizontal scaling.

**D9**
An **environment variable** is a dynamic named value available to processes.
*   **Persist:** Use `export VAR=value` in the current shell, or add `export VAR=value` to `~/.bashrc` or `/etc/environment` for system-wide persistence.

**D10**
*   **JSON:** Data interchange format (strict syntax). Advantage: Machine-readable, strict validation.
*   **YAML:** Configuration format (human-readable). Advantage: Indentation-based, easier to read/write for humans.

**D11**
A **REST API** uses HTTP methods to manipulate resources.
*   **GET:** Retrieve resource.
*   **POST:** Create resource.
*   **PUT:** Replace/Update resource.
*   **DELETE:** Remove resource.

**D12**
**Version pinning** specifies an exact version of a dependency (e.g., `==1.2.3`).
*   **Importance:** Ensures reproducible builds and prevents unexpected breaking changes from upstream updates.

**D13**
*   **Compiled:** Source code translated to machine code before execution (e.g., C++, Rust).
*   **Interpreted:** Source code executed line-by-line by an interpreter (e.g., Python, JavaScript).

**D14**
*   **Reverse Proxy:** Sits in front of servers, forwards client requests to them (e.g., Nginx). Use: SSL termination, load balancing.
*   **Forward Proxy:** Sits in front of clients, forwards client requests to external servers (e.g., Squid). Use: Anonymity, content filtering.

**D15**
A **deadlock** occurs when two or more processes block each other indefinitely.
*   **Coffman Conditions:**
    1.  Mutual Exclusion.
    2.  Hold and Wait.
    3.  No Preemption.
    4.  Circular Wait.

**D16**
**Eventual consistency** means data becomes consistent across replicas over time, not immediately.
*   **Cassandra:** Uses consistency levels (e.g., `ONE`, `QUORUM`, `ALL`). `QUORUM` ensures a majority of replicas acknowledge the write before confirming.

**D17**
**mTLS** requires both client and server to authenticate using certificates.
*   **Handshake:** Client sends cert -> Server verifies -> Server sends cert -> Client verifies -> Key exchange.
*   **Use:** Service Meshes (Istio), internal microservice communication.

**D18**
A **hash table** uses a hash function to map keys to array indices.
*   **Collision:** Chaining (linked list at index) or Open Addressing (probe next slot).
*   **Complexity:** Average O(1) for insert/lookup/delete. Worst case O(n) if all keys hash to the same bucket.

**D19**
**Circuit Breaker** prevents cascading failures by stopping calls to a failing service.
*   **States:**
    1.  **Closed:** Normal operation.
    2.  **Open:** Fail fast (no calls).
    3.  **Half-Open:** Allow limited calls to test recovery.
*   **Relation:** Used with retry policies and exponential backoff to avoid hammering a failing service.

**D20**
*   **Optimistic:** Assumes no conflicts; checks version on commit. (e.g., `SELECT FOR UPDATE` is pessimistic, versioning is optimistic).
*   **Pessimistic:** Locks resources immediately.
*   **Choice:** Optimistic for high concurrency/low conflict; Pessimistic for critical data integrity.
