SC1-A
The pods fail because the upgrade changed the namespace's Pod Security Standards (PSS) from **Baseline** to **Restricted**.
*   **Baseline:** Allows containers to run as root.
*   **Restricted:** Requires `runAsNonRoot: true` AND `runAsUser` (or `runAsGroup`) to be explicitly set.
*   **The Failure:** The manifests have `runAsNonRoot: true` but no `runAsUser`. Kubernetes defaults to the image's USER directive. Since the new Chainguard image defaults to `USER: root`, the admission controller rejects the pod because it attempts to run as root, violating `runAsNonRoot`.

SC1-B
```bash
kubectl get pods --all-namespaces --field-selector=status.phase=CrashLoopBackOff -o jsonpath='{range .items[*]}{.metadata.namespace}{"\t"}{.metadata.name}{"\t"}{json .spec.securityContext}{"\n"}{end}'
```

SC1-C
*   **Image Fix:** Update the Dockerfile to `USER 1000` (or non-root) before the final layer.
*   **Manifest Fix:** Add `securityContext: { runAsUser: 1000, runAsNonRoot: true }` to the pod spec.
*   **CI Gate:** Add a pre-commit hook or CI step that scans Dockerfiles for `USER root` and validates manifests against the Restricted PSS policy (e.g., using `kube-score` or `kubebuilder`).
*   **Rollout:** Use a rolling update with a canary deployment. Deploy the fixed image to a small subset of pods first, verify health, then scale to 100%.

SC2-A
*   **Stale Data:** Cross-region replication is asynchronous. The replica is not immediately up-to-date with the primary. Promoting the replica means any writes that occurred on the primary *after* the replication lag started are lost.
*   **WAL Shipping:** PostgreSQL streams Write-Ahead Logs (WAL) to the replica. If the network is slow or the replica is busy, lag accumulates.
*   **Data Loss:** With asynchronous replication, the RPO (Recovery Point Objective) is the replication lag at the time of failure.
*   **Quantify:** Check `pg_stat_replication` on the promoted instance for `sent_lsn` vs `write_lsn` (if available) or `replay_lag`.

SC2-B
1.  **Import:** `terraform import aws_db_instance.main <new-eu-west-1-arn>`
2.  **Refresh:** `terraform refresh` to update the state file with the new instance's attributes.
3.  **Update Code:** Modify the Terraform code to reference the new ARN (or use `aws_db_instance` data source pointing to the new ID).
4.  **Apply:** `terraform plan` (verify no destroy), `terraform apply`.
5.  **Detach:** Manually detach the old instance from the VPC or security groups if still referenced, or let Terraform manage the lifecycle if the old resource is removed from the code.

SC2-C
*   **Architecture:** Use **Amazon Aurora Global Database**. It supports synchronous replication across regions (RPO < 1s) and automatic failover.
*   **Connection:** Use **RDS Proxy** to manage connection pooling and reduce PgBouncer complexity.
*   **DNS:** Use **Route53 Latency-Based Routing** with health checks. If the primary region fails, Route53 routes traffic to the secondary.
*   **Retry:** Implement application-level retry logic with exponential backoff for transient connection errors.
*   **Recommendation:** Aurora Global DB is recommended over standard RDS because it provides synchronous replication (RPO < 1s) and automatic failover, whereas standard RDS cross-region replication is asynchronous (RPO > 0).

```python
import requests
import json

def check_image_integrity(ecr_url, image_tag, build_log_digest):
    # 1. Get current image manifest
    response = requests.get(f"{ecr_url}/api/v2/images/{image_tag}")
    current_digest = response.json()['imageDigest']
    
    # 2. Compare with build log digest
    if current_digest != build_log_digest:
        print(f"WARNING: Digest mismatch. Expected: {build_log_digest}, Got: {current_digest}")
        return False
    
    # 3. List layers
    layers = response.json()['layers']
    print(f"Image layers: {len(layers)}")
    for layer in layers:
        print(f"  - {layer['digest']}")
    return True
```

SC3-C

SC4-A
1.  **Local Disk:** Kubernetes requires persistent storage (PV/PVC). *Solution:* NFS CSI driver.
2.  **Sticky Sessions:** F5 handles this. *Solution:* Kubernetes Ingress with sticky sessions or application-level session affinity.
3.  **Oracle DB:** Local file system. *Solution:* Migrate to Amazon RDS or Oracle Cloud.
4.  **Mainframe MQ:** Hard to containerize. *Solution:* API Gateway abstraction or MQ on K8s.
5.  **Bare Metal:** Hardware dependencies. *Solution:* Use K8s nodes with matching specs or abstract via CSI.

SC10-A
