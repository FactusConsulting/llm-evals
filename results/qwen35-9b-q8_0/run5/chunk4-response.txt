G1 — Easy: In Go, an array is a fixed-size sequence of elements stored contiguously in memory, while a slice is a dynamic view into an underlying array, containing a pointer, length, and capacity. When appending to a slice that has reached its capacity, Go allocates a new underlying array (typically 1.5x or 2x the current capacity), copies the existing elements, and updates the slice header to point to the new array.

G2 — Easy: `var x int` declares a variable `x` of type `int` with the zero value (0) and makes it accessible in the current scope. `x := 0` declares and initializes `x` to 0, inferring the type as `int`. You cannot use `:=` in a function scope if the variable is already declared in an outer scope (e.g., a package-level variable or an outer function scope), as `:=` implies a new declaration.

G3 — Medium: A goroutine is a lightweight thread of execution managed by the Go runtime. It differs from an OS thread in that it is much smaller (a few kilobytes vs. megabytes) and the runtime multiplexes thousands of goroutines onto a smaller number of OS threads. The GMP model (Goroutine, Machine, Processor) manages this: G represents the goroutine, M represents the OS thread, and P represents the logical processor. The scheduler moves Gs between Ms and Ps to balance load.

G4 — Medium: Channels are typed conduits for sending and receiving values between goroutines. An unbuffered channel blocks the sender until a receiver is ready to receive, and vice versa. A buffered channel holds a fixed number of values; the sender can send up to the buffer size without blocking. If you send to a full buffered channel, the sender blocks until a receiver removes a value.

G5 — Medium: The context package manages cancellation, timeouts, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
resp, err := http.GetWithContext(ctx, "https://example.com")
```
This ensures the request is cancelled if it exceeds 5 seconds.

G6 — Medium: Go uses implicit interface satisfaction: a type implements an interface if it has all the required methods. Java/C# require explicit implementation declarations. The empty interface `interface{}` (or `any`) can hold values of any type, making it flexible for generic-like behavior, but it is dangerous because it disables compile-time type safety, requiring runtime type assertions.

G7 — Hard: This code is unsafe due to data races. The goroutine writes to `data` and `ready` without synchronization, and the main goroutine reads them without synchronization. The Go memory model does not guarantee visibility of writes across goroutines without synchronization. Correct alternatives include using `sync.WaitGroup` with a channel to signal completion, or using `sync.Mutex` to protect the shared state.

G8 — Hard: `sync.Mutex` allows only one writer at a time. `sync.RWMutex` allows multiple concurrent readers but only one writer. `sync.Map` is optimized for read-heavy workloads with concurrent access, avoiding locks for reads by using a hash table with per-bucket locking. Regular maps require a mutex for all access. `sync.Map` trades write performance for read performance and has higher memory overhead.

G9 — Hard: Go modules manage dependencies. `go.mod` defines the module path and required dependencies. `go.sum` stores checksums of dependencies to ensure integrity. `go mod tidy` cleans up `go.mod` by removing unused dependencies and adding missing ones. The Minimum Version Selection (MVS) algorithm ensures that when a dependency has multiple versions, the oldest version satisfying all constraints is selected to maximize compatibility.

G10 — Medium: `defer` schedules a function call to run when the surrounding function returns. Multiple defers execute in Last-In, First-Out (LIFO) order. A common gotcha is using `defer` inside a loop; the deferred function captures the loop variable by reference, so all deferred calls may use the final value of the loop variable unless a new variable is created in each iteration.

G11 — Easy: A pointer holds the memory address of a variable. The zero value of a pointer is `nil`. To create a pointer to a struct literal, use `&Struct{}`.

G12 — Easy: `init()` functions run before `main()` to perform package-level initialization. They run in the order they are defined in the source files. A package can have multiple `init()` functions (e.g., from different files in the package), and they execute in file order.

G13 — Easy: `make` is used to create slices, maps, and channels, allocating memory and initializing them. `new` allocates zeroed memory for a single value of a type and returns a pointer to it. `make` works with slices, maps, and channels; `new` works with any type.

G14 — Easy: Go uses explicit error returns. The `error` interface is defined as `type error interface { Error() string }`. The idiomatic pattern is `if err != nil { ... }`. `errors.Is` and `errors.As` allow checking for specific wrapped errors or extracting specific error types, whereas `==` only checks for identity (same pointer).

G15 — Easy: Built-in composite types are map, slice, channel, and struct. The zero values are: map is `nil`, slice is `nil`, channel is `nil`, and struct is a struct with all fields set to their zero values.

G16 — Medium: A race condition occurs when two or more goroutines access shared data concurrently, and at least one write occurs, without synchronization. The `-race` flag enables the race detector, which uses hardware instructions to detect concurrent access to the same memory location.
```go
// Race
var x int
go func() { x = 1 }()
x = 2
// Fix
var mu sync.Mutex
var x int
go func() { mu.Lock(); x = 1; mu.Unlock() }()
mu.Lock(); x = 2; mu.Unlock()
```

G17 — Medium: `select` allows choosing between multiple channel operations. It differs from `switch` by operating on channels. If multiple cases are ready, one is chosen randomly. To implement a timeout, use a case with a timer channel (e.g., `time.After`) alongside the main channel operations.

G18 — Hard: Escape analysis determines if a variable can be allocated on the stack or must be allocated on the heap. If a variable is accessed outside the function scope (e.g., returned or passed to a goroutine), it escapes the stack. You can inspect this with `go build -gcflags="-m"`. It matters because heap allocations are slower and increase GC pressure.

G19 — Hard: The `reflect` package allows runtime introspection of types and values. `reflect.Type` describes a type, while `reflect.Value` holds the value of a variable. Reflection has high performance costs due to dynamic dispatch and lack of optimization. It is justified for generic-like behavior or serialization, but code generation is preferred for performance-critical paths.

G20 — Hard: `go:embed` embeds files or directories at compile time. It works with single files (`go:embed "file.txt"`) and directories (`go:embed "dir/*"`). It requires the `embed` package. Limitations include that embedded files are not writable at runtime. It interacts with `io/fs.FS` by providing an `FS` interface that can be passed to `http.FileServer` or other file handlers.

R1 — Easy: Ownership is the concept that each value has a single owner responsible for its memory management. The three rules are: 1. Each value has a single owner. 2. When a function takes ownership, the owner transfers it. 3. When a value goes out of scope, its memory is freed.

R2 — Easy: `String` is a growable, heap-allocated string type. `&str` is a reference to a string slice (immutable string data). Use `String` when you need to modify the string or own the data. Use `&str` when you only need to read the data or pass it to functions that don't modify it.

R3 — Medium: Borrowing allows accessing data without taking ownership. The borrow checker ensures memory safety. Rules: 1. You can have multiple immutable references (`&T`). 2. You can have only one mutable reference (`&mut T`) at a time. 3. You cannot have both immutable and mutable references simultaneously.

R4 — Medium: `Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents presence (`Some(T)`) or absence (`None`). The `?` operator propagates errors or unwraps `Option`.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)?
}
```

R5 — Medium: `Box<T>` is a heap-allocated pointer with single ownership. `Rc<T>` is a reference-counted pointer for single-threaded shared ownership. `Arc<T>` is an atomic reference-counted pointer for multi-threaded shared ownership. Use `Box` for recursion or large data, `Rc` for single-threaded sharing, and `Arc` for concurrent sharing.

R6 — Medium: Traits define shared behavior. They are similar to Go interfaces but require explicit implementation. A trait object (`dyn Trait`) allows dynamic dispatch at runtime. A generic with a trait bound (`T: Trait`) uses static dispatch at compile time, which is more performant.

R7 — Hard: This fails because the compiler cannot determine which reference (`x` or `y`) will live longer. The return type `&str` must live as long as the longest reference. Fix: Add lifetime annotations.
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — Hard: `Send` and `Sync` are traits indicating a type can be safely transferred across threads (`Send`) or shared between threads (`Sync`). `Rc<T>` is not `Send` because its reference count is not atomic. `Arc<T>` is `Send` and `Sync` because it uses atomic reference counting.

R9 — Hard: Rust's async/await uses a `Future` trait to represent a computation that may not be complete. The executor (e.g., Tokio) polls the `Future` to drive execution. Unlike Go's goroutines which are OS-thread multiplexed, Rust's async tasks are cooperative and lightweight, often running on a single thread with a work-stealing scheduler.

R10 — Medium: `unsafe` blocks allow bypassing Rust's safety guarantees. You can perform pointer arithmetic, call FFI functions, or access raw pointers. It is justified when interfacing with C libraries or implementing complex algorithms where safety checks are unnecessary overhead.

R11 — Easy: Pattern matching uses `match` to exhaustively match against all possible values of an expression. `if let` is syntactic sugar for a specific pattern match. The compiler enforces exhaustiveness: all possible variants of an enum must be handled, or the code will not compile.

R12 — Easy: `Vec<T>` is a dynamic array that grows on the heap. `[T; N]` is a fixed-size array stored on the stack (or heap if moved). When `Vec` capacity is exceeded, it allocates a new buffer (typically 1.5x or 2x size) and copies elements.

R13 — Easy: Enums define a set of named values. Rust enums are algebraic data types (sum types) with data payloads, unlike C/Java enums which are usually just integers. `Option<T>` is an enum with `Some(T)` and `None`. Rust has no null because `Option` forces explicit handling of absence.

R14 — Easy: The `impl` block defines methods and associated functions for a type. `&self` takes an immutable reference, `&mut self` takes a mutable reference, and `self` takes ownership. Associated functions (static methods) do not take `self` and are called via `Type::function()`.

R15 — Easy: Derive macros automatically generate implementations of traits. Common traits include `Debug`, `Clone`, `PartialEq`, and `Serialize`. You cannot derive a trait if the struct contains types that do not implement the trait (e.g., deriving `Clone` on a struct containing a non-cloneable type).

R16 — Medium: `Cow<'a, T>` (Clone on Write) holds a reference or an owned value. It is useful when you want to avoid cloning if the data is already owned or if you only need to read it. Example: `Cow::Borrowed(s)` avoids cloning a string unless you modify it.

R17 — Medium: The module system organizes code. `mod` declares a module, `use` imports items, and `pub` makes items public. The file system maps to modules (e.g., `src/lib.rs` is the root). Rust 2018 introduced `mod.rs` for module files and improved path resolution.

R18 — Hard: `Pin<T>` ensures a value is not moved in memory, which is required for types with self-references or async tasks that rely on stable memory addresses. `Unpin` is a marker trait that allows a type to be moved. It is needed for async/await to ensure futures remain at a fixed location during polling.

R19 — Hard: Declarative macros (`macro_rules!`) are text substitution with limited power. Procedural macros (derive, attribute, function-like) are Rust functions that generate code. Hygiene rules ensure macros do not accidentally capture variables from the surrounding scope, preventing name collisions.

R20 — Hard: Zero-cost abstractions mean high-level code compiles to the same machine code as hand-written low-level code. Iterators are monomorphized (specialized for the type). Generics use monomorphization. Trait static dispatch resolves at compile time, avoiding runtime overhead. This allows ergonomic code with C-like performance.
