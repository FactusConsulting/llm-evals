JS1 — var is function-scoped and hoisted (initialized as undefined), allowing reassignment and redeclaration. let is block-scoped, cannot be redeclared in the same scope, and is not initialized until declaration. const is block-scoped, cannot be reassigned (though properties can change), and is not initialized until declaration. Hoisting is the mechanism where variable declarations are moved to the top of their scope during compilation, but initialization remains in place (for let/const, creating a "temp dead zone").

JS2 — The event loop continuously checks the call stack. If the stack is empty, it processes the macrotask queue (setTimeout, I/O), then the microtask queue (Promises, queueMicrotask). This ensures microtasks run before the next macrotask. The call stack executes synchronous code; when it empties, the loop picks the next task from the queues.

JS3 — A closure is a function bundled with its lexical environment. Example: `function counter() { let n = 0; return () => n++; }`. The classic bug: `for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i), 0); }` logs 3, 3, 3 because `i` is shared. Fix: Use `let` (block scope) or `setTimeout((i) => console.log(i), 0)` with an IIFE.

JS4 — Promises represent async completion. async/await is syntactic sugar over Promises. Errors in async functions are caught via try/catch. Promise.all rejects if *any* promise rejects. Promise.allSettled waits for *all* to settle (fulfilled or rejected) and returns an array of results, useful when you need all outcomes regardless of failure.

JS5 — Interfaces define shapes for objects and are erased at runtime; types are erased at runtime. Interfaces are preferred for object structures and method definitions; types are preferred for primitives, unions, or complex literal types. Discriminated unions (tagged unions) use a literal type to distinguish union members, enabling type narrowing (e.g., `type Status = { type: 'success'; data: string } | { type: 'error'; code: number }`).

JS6 — Prototypal inheritance links objects via a prototype chain. `Object.create(proto)` creates an object with `proto` as its internal `[[Prototype]]`. ES6 classes are syntactic sugar over prototype-based inheritance; `class` creates a constructor function, and `extends` sets up the prototype chain via `Object.create`.

JS7 — `this` refers to the execution context. Binding rules (priority): 1. Arrow functions (lexical `this`), 2. `new` (constructor context), 3. `call/apply/bind` (explicit binding), 4. Default (global/window or undefined in strict mode). `bind()` returns a new function with `this` permanently bound; it can be re-bound, but the initial binding takes precedence over default binding.

JS8 — WeakRef holds a weak reference to an object, allowing garbage collection if no strong refs exist. FinalizationRegistry allows running code when a WeakRef target is garbage collected. WeakMap keys must be objects (not primitives) because primitives are auto-boxed and treated as strong references; WeakMap is used for metadata storage without preventing GC.

JS9 — V8 optimizes via hidden classes (templates for object shapes) and inline caching (storing type info for fast property access). Deoptimization occurs when assumptions break (e.g., changing object shape, adding properties). Patterns causing deoptimization: mutating object properties, using `with` statements, or changing variable types dynamically.

JS10 — Tree-shaking removes unused code during bundling. ES Modules (static imports) allow static analysis for removal. CommonJS uses dynamic `require()`, so bundlers cannot statically determine usage, preventing effective tree-shaking.

JS11 — `null` is an intentional empty value; `undefined` is a missing value. `==` performs type coercion (e.g., `null == undefined` is true); `===` checks strict equality (no coercion). `??` returns the right operand if the left is `null` or `undefined`. `?.` safely accesses nested properties (returns `undefined` if intermediate is null/undefined).

JS12 — `map()` transforms elements into a new array. `filter()` creates a new array with elements passing a test. `reduce()` accumulates a single value from an array. `reduce` with an initial value avoids the first element being the accumulator. `flatMap()` maps and flattens the result one level deep; useful for transforming nested arrays into a single flat list.

JS13 — Template literals use backticks and allow multi-line strings and variable interpolation `${expr}`. Tagged templates pass template parts as arguments to a function. Example: `sql` tag function that joins parts with semicolons or escapes values to prevent SQL injection.

JS14 — Destructuring extracts values from arrays/objects. Object destructuring: `const { name } = obj`. Array destructuring: `const [first, second] = arr`. Default values: `const { name = 'Guest' } = obj`. Renaming: `const { name: userName } = obj`. Rest operator `...` collects remaining elements/properties into an array.

JS15 — `for...in` iterates over enumerable own and inherited properties (keys); `for...of` iterates over iterable values (elements). Avoid `for...in` on arrays because it iterates over non-numeric keys (like `length` or inherited methods) and doesn't guarantee order.

JS16 — Generics allow functions/classes to work with multiple types while maintaining type safety. Constraints (`extends`) limit the type (e.g., `T extends string`). Conditional types (`T extends U ? X : Y`) select a type based on a condition. `infer` extracts a type from a conditional (e.g., `infer T` in `Array<T>`).

JS17 — The module system defines how code is organized. CommonJS (Node default) uses `require` and `module.exports`. ES Modules use `import`/`export` and are static. Node supports both via `type: "module"` in package.json (ESM) or default CommonJS.

JS18 — TypeScript is structural: types are defined by shape, not declaration. Excess property checks apply to object literals passed to functions (e.g., `createUser({ name, age: 10, extra: 'bad' })` fails). `extends` checks structural compatibility; `satisfies` checks if a value conforms to a type without widening. Variance (in/out) determines if a type parameter is covariant (out) or contravariant (in) based on usage (read vs write).

JS19 — Proxy wraps an object to intercept operations (get, set, call, etc.). Reflect provides standard methods to perform these operations. Example: A Proxy wrapping a data object to log every property access or validate writes before assignment.

JS20 — SharedArrayBuffer allows memory sharing between threads (Web Workers). Atomics provides memory barriers and synchronization primitives. `Atomics.wait` blocks a thread until a value changes or timeout; `Atomics.notify` wakes threads waiting on a specific index. Ordering guarantees ensure memory visibility across threads.

B1 — `$@` expands to all positional parameters as separate words. `$*` expands to all positional parameters as a single string (IFS-separated). `"$@"` preserves word boundaries (safe for filenames). `"$*"` treats arguments as one string (unsafe for filenames with spaces).

B2 — `set -e` exits on error (non-zero exit code). `set -u` treats unset variables as errors. `set -o pipefail` ensures the pipeline fails if any command fails (not just the last).

B3 — `$(command)` performs command substitution (output replacement). `command` (backticks) is legacy but equivalent. `$((expression))` performs arithmetic expansion. `expr` is an external command for string/regex operations (deprecated/slow).

B4 — Process substitution `<(command)` creates a named pipe (FIFO) containing command output. Used when a command needs to read from a file-like input but the input is dynamic. Example: `diff <(ls dir1) <(ls dir2)` compares directory listings without creating temp files.

B5 — Use `while IFS= read -r -d '' file; do ...; done < <(find . -print0)`. `for f in $(ls)` splits by IFS (whitespace), breaking on filenames with spaces or special chars.

B6 — Here document `<<EOF` reads from stdin until EOF. Here string `<<<` passes a string as stdin to a command. `<<-` allows tab indentation before the delimiter.

B7 — `cmd > file 2>&1`: stdout to file, then stderr redirected to stdout (file). `cmd 2>&1 > file`: stderr to stdout (terminal), then stdout to file (stdout lost). `cmd &> file`: both stdout and stderr to file (bash 4+). First two differ because redirection order matters; `2>&1` copies the *current* fd 2 to fd 1 before fd 1 is redirected.

B8 — Use `mkdir -p "$lockdir/$pid"` to create a directory lock. Check `if [ -d "$lockdir/$pid" ]; then exit 1; fi`. Use `trap "rm -rf '$lockdir'" EXIT` for cleanup. `mkdir` is atomic on POSIX systems, preventing race conditions better than file creation (`touch`).

B9 — Single quotes preserve literal characters (no expansion). Double quotes allow variable expansion and globbing. No quotes allow globbing and variable expansion. Example: `'echo $HOME'` prints literal `$HOME`; `"echo $HOME"` prints path.

B10 — `[ -f file ]` checks regular file. `[ -d dir ]` checks directory. `[ -r file ]` checks readable. `[ ]` uses word splitting/globbing; `[[ ]]` is a keyword, supports pattern matching and no word splitting.

B11 — `$?` is last command exit code. `$$` is current shell PID. `$!` is last background process PID. `$#` is number of arguments passed to a function/script.

B12 — `function foo {}` and `foo() {}` are equivalent. Return values via `echo` (stdout) or `return` (exit code 0-255).

B13 — `PATH` is a colon-separated list of directories. Bash searches these for executables. Builtins are internal (e.g., `cd`); external are binaries. Use `type command` to check.

B14 — `trap 'cmd' signal` sets handler. `EXIT` runs on script exit. `ERR` runs on command error. `INT` (Ctrl+C) and `TERM` (kill) run on termination. Order: signals are queued; handlers run in FIFO order.

B15 — `xargs` executes commands with arguments. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P` runs parallel processes.

B16 — Arrays: `arr=(1 2 3)`. `arr+=("4")`. `${#arr[@]}` length. Associative: `declare -A assoc`. `assoc[key]=val`. Iterate via `for key in "${!assoc[@]}"`.

B17 — Subshell `(...)` creates a new process; variables don't persist. Group `{ ... }` runs in current shell; variables persist. Piping into `while` creates a subshell, so variable changes inside the loop are lost.

B18 — Signals: `SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (hangup), `SIGKILL` (unblockable). Use `trap 'cleanup' TERM INT` and `wait` for background jobs to ensure graceful shutdown.

B19 — `split -l 1000 file part_` splits file. `xargs -P 4 -I {} bash -c 'process {}'` runs parallel. Merge results via `cat part_*`. Trade-off: parallelism vs I/O contention. Error handling: check exit codes in each job and aggregate.

B20 — `exec` replaces the shell process with the command. `exec 3>file` redirects fd 3. Coprocess `coproc NAME { command }` creates a background process with stdin/stdout connected to pipes. Used for interactive shells or streaming data.

PS1 — `Write-Output` sends object to pipeline. `Write-Host` writes to console (bypasses pipeline). Distinction matters because `Write-Host` breaks data flow in pipelines.

PS2 — Pipeline passes objects. `ForEach-Object` is a cmdlet (pipeline-aware). `foreach` is a statement (script block). `ForEach-Object` is preferred for pipelines; `foreach` for simple iteration.

PS3 — `[PSCustomObject]` creates a proper object with properties (pipeline-friendly). `[hashtable]` is a generic collection (not pipeline-friendly). Convert via `[PSCustomObject]@{ Key = $value }`.

PS4 — Terminating errors stop execution. Non-terminating errors continue. `-ErrorAction Stop` makes errors terminating. `try/catch` catches terminating errors. `$ErrorActionPreference` sets default behavior.

PS5 — Splatting `@params` passes a hashtable as individual arguments. Passing a hashtable as a single parameter requires `@` to expand. Example: `Get-Item @params`.

PS6 — `Invoke-Command` runs a script remotely. `Enter-PSSession` creates an interactive session. Uses WinRM (default) or SSH (PowerShell 7+).

PS7 — Functions returning arrays return an array object. If empty, returns `$null` (not an empty array). Correct pattern: `return $result` where `$result` is initialized as `@()`.

PS8 — `[scriptblock]` is a compiled block of code. Pass via `-ScriptBlock`. Double-hop: remote session authenticates to remote server, which tries to authenticate to another server. Solve with CredSSP or `-ArgumentList` (serializes arguments).

PS9 — `@()` creates an array. `[array]` is a type cast. Force single result: `@($result)`. Indexing `$null` throws error; empty array returns `$null` or empty.

PS10 — `-eq` numeric/string equality. `-like` wildcard matching. `-match` regex. `-contains` checks if element exists in array. `-in` checks if value is in array (equivalent to `-contains`). Case-sensitive variants: `-ceq`, `-clike`, `-cmatch`.

PS11 — Module is a collection of functions/classes. `.psm1` is script module (code). `.psd1` is manifest (metadata). Binary is compiled DLL. `Import-Module` loads the module into session.

PS12 — Interpolation: `"${variable}"`. Single quotes `'...'` no interpolation. Here-string: `@"..."@` for multi-line.

PS13 — `Get-Member` lists properties/methods. `Properties` are data, `Methods` are functions, `NoteProperties` are metadata. `Select-Object` selects properties; `Where-Object` filters objects.

PS14 — Classes in v5 are C#-like but limited (no interfaces, limited inheritance). Use classes for encapsulation/state; functions for logic.

PS15 — `[CmdletBinding()]` enables advanced function features. `SupportsShouldProcess` adds `-WhatIf`/`-Confirm`. `ValueFromPipeline` allows piping objects into the function. `Begin/Process/End` blocks handle streaming.

PS16 — Providers abstract namespaces (FileSystem, Registry). `Get-ChildItem` works on both. Registry access: `Get-ChildItem HKLM:\Software`.

PS17 — Runspaces are execution contexts. `[runspacepool]` manages them. `ForEach-Object -Parallel` (v7+) uses thread pool. Manual runspace management gives more control but is verbose.

PS18 — PSScriptAnalyzer enforces rules (e.g., `PSUseDeclaredVarsMoreThanAssignments`). Severity: Info, Warning, Error. Suppress via `# # scriptanalyzer disable`. Integrate via CI/CD (e.g., GitHub Actions).

PS19 — `$using:` passes variables to remote sessions/background jobs. `-ArgumentList` serializes arguments. CLIXML depth limits complex object serialization (e.g., nested arrays).

PS20 — DSC manages configuration state. Configurations define desired state; Resources implement actions. LCM enforces state. PowerShell 7+ uses DSC on Linux/Windows. Modern IaC: Terraform/Ansible (DSC is legacy for config management).
