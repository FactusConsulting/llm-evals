G1 — Easy: In Go, an array is a fixed-size sequence of elements stored contiguously in memory, while a slice is a dynamic view into an array (a descriptor containing a pointer, length, and capacity). When you append to a slice that has reached its capacity, Go allocates a new underlying array (typically 1.5x the current capacity), copies the existing elements, and updates the slice descriptor to point to the new array.

G2 — Easy: `var x int` declares a variable `x` of type `int` with the zero value (0) and allows reassignment later. `x := 0` declares and initializes `x` in the same statement (short variable declaration). You cannot use `:=` outside of a function scope (e.g., in package-level scope) or when redeclaring a variable that already exists in the current scope.

G3 — Medium: A goroutine is a lightweight thread of execution managed by the Go runtime. It differs from an OS thread in that it is much smaller (kilobytes vs megabytes) and the runtime multiplexes thousands of goroutines onto a smaller number of OS threads. The GMP model (Goroutine, Machine, Processor) manages this: G represents the goroutine, M represents the OS thread, and P represents the logical processor. The scheduler moves Gs between Ms and Ps to balance load.

G4 — Medium: Channels are typed conduits for sending and receiving values between goroutines. An unbuffered channel blocks the sender until a receiver is ready to receive. A buffered channel of size N allows up to N sends to be queued without blocking. When sending to a full buffered channel, the sender blocks until space becomes available or the channel is closed.

G5 — Medium: The context package carries deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
resp, err := http.GetWithContext(ctx, url)
```

G6 — Medium: Go uses implicit interface satisfaction: a type implements an interface if it has all the required methods. Java/C# require explicit implementation declarations. `interface{}` (or `any`) accepts any type, making it flexible for generic-like behavior, but it disables compile-time type safety and incurs runtime type assertions, which can be dangerous if not handled carefully.

G7 — Hard: This code is unsafe due to data races. The goroutine writes to `data` and `ready` without synchronization, and the main goroutine reads them without synchronization. The Go memory model does not guarantee visibility of writes across goroutines without synchronization. Correct alternatives include using `sync.WaitGroup` with a channel to signal completion, or using `sync.Mutex` to protect the shared state.

G8 — Hard: `sync.Mutex` allows only one writer at a time. `sync.RWMutex` allows multiple concurrent readers but only one writer. `sync.Map` is optimized for read-heavy workloads with concurrent access, avoiding locks for reads by using a hash table with per-bucket locking. Regular maps require a mutex for all access. `sync.Map` trades write performance for read scalability and is not suitable for storing complex values or requiring iteration.

G9 — Hard: Go modules manage dependencies. `go.mod` defines the module path and required dependencies. `go.sum` stores checksums for security verification. `go mod tidy` cleans up the `go.mod` file by removing unused dependencies and adding missing ones. The Minimum Version Selection (MVS) algorithm selects the lowest version of a dependency that satisfies all constraints in the dependency graph.

G10 — Medium: `defer` schedules a function call to run when the surrounding function returns. Multiple defers execute in Last-In, First-Out (LIFO) order. A common gotcha is using `defer` inside a loop; the deferred function captures the loop variable by reference, so all deferred calls may use the final value of the loop variable.

G11 — Easy: A pointer holds the memory address of a variable. The zero value of a pointer is `nil`. To create a pointer to a struct literal, use `&Struct{}`.

G12 — Easy: `init()` functions run before `main()` to perform package-level initialization. They run in the order they are defined within the package. A package can have multiple `init()` functions (e.g., `init()` and `init2()`), and they execute in the order of their definition.

G13 — Easy: `make` creates slices, maps, and channels, initializing them with zero values or specified capacity. `new` allocates a zero value of a type and returns a pointer to it. `make` works with slices, maps, channels; `new` works with any type.

G14 — Easy: Go uses explicit error returns. The `error` interface is defined as `type error interface { Error() string }`. The idiomatic pattern is `if err != nil { ... }`. `errors.Is` and `errors.As` allow checking for specific wrapped errors or extracting typed errors, whereas `==` only checks identity.

G15 — Easy: Built-in composite types are map, slice, channel, and struct. The zero values are: map is `nil`, slice is `nil`, channel is `nil`, and struct is a struct with all fields set to their zero values.

G16 — Medium: A race condition occurs when two or more goroutines access shared data concurrently, and at least one write occurs, without synchronization. The `-race` flag enables the race detector, which uses hardware instructions to detect concurrent accesses. Example: Two goroutines incrementing a counter without a mutex. Fix: Wrap the increment in `sync.Mutex` lock/unlock or use an atomic operation.

G17 — Medium: `select` is a multi-way branch statement that waits on multiple channel operations. It differs from `switch` in that it handles channel operations. If multiple cases are ready, one is chosen randomly. To implement a timeout, use a `case <-time.After(timeout)` alongside other channel operations.

G18 — Hard: Escape analysis determines if a variable can be allocated on the stack or must be allocated on the heap. If a variable is accessed outside the current function scope (e.g., returned or passed to a function that escapes), it escapes to the heap. You can inspect this with the `-m` flag. It matters because heap allocations are slower and generate garbage collection pressure.

G19 — Hard: The `reflect` package allows runtime introspection and manipulation of types and values. `reflect.Type` describes a type, while `reflect.Value` represents a value of that type. Reflection is slow and incurs significant overhead. It is justified for dynamic code generation or generic-like behavior where generics are not available, but code generation is preferred for performance.

G20 — Hard: `go:embed` embeds files or directories at compile time. It works for single files (`go:embed "file.txt"`) and directories (`go:embed "dir/*"`). It requires the `embed` package. Limitations include that embedded files are read-only and cannot be modified at runtime. It interacts with `io/fs.FS` by providing an `FS` interface that can be passed to functions expecting an `io.ReaderAt` or similar.

R1 — Easy: Ownership is the concept that each value in Rust has a single owner. The three rules are: 1. Each value has one owner at a time. 2. When the owner goes out of scope, the value is dropped. 3. You can have multiple references to the value, but only one mutable reference at a time.

R2 — Easy: `String` is an owned, heap-allocated string type. `&str` is a borrowed slice of UTF-8 bytes. Use `String` when you need to own the data (e.g., function arguments that might be modified). Use `&str` when borrowing data (e.g., function arguments that are read-only).

R3 — Medium: Borrowing allows accessing data without taking ownership. The borrow checker enforces: 1. You cannot have a mutable reference and a shared reference to the same data simultaneously. 2. You cannot have multiple mutable references to the same data simultaneously. 3. References must be valid for the duration of their scope.

R4 — Medium: `Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents presence (`Some(T)`) or absence (`None`). The `?` operator propagates errors or unwraps `Option`.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let mut file = std::fs::File::open(path)?;
    let mut contents = String::new();
    file.read_to_string(&mut contents)?;
    Ok(contents)
}
```

R5 — Medium: `Box<T>` is a heap-allocated pointer with single ownership. `Rc<T>` is a reference-counted pointer for single-threaded shared ownership. `Arc<T>` is an atomic reference-counted pointer for multi-threaded shared ownership. Use `Box` for recursive types or large data. Use `Rc` for single-threaded sharing. Use `Arc` for concurrent sharing.

R6 — Medium: Traits define shared behavior. They are similar to Go interfaces but require explicit implementation. A trait object (`dyn Trait`) allows dynamic dispatch (runtime polymorphism). A generic with a trait bound (`T: Trait`) allows static dispatch (compile-time polymorphism), which is generally more performant.

R7 — Hard: This fails because the compiler cannot determine which reference (`x` or `y`) will live longer. The function returns a reference to one of the inputs, but the compiler doesn't know which one. Fix: Add lifetime annotations: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

R8 — Hard: `Send` and `Sync` are marker traits indicating a type can be safely transferred across threads (`Send`) or shared between threads (`Sync`). `Rc<T>` is not `Send` because its reference count is not atomic. `Arc<T>` is `Send` and `Sync` because it uses atomic reference counting, making it safe for concurrent access.

R9 — Hard: Rust's async/await is built on `Future` traits. A `Future` represents a computation that will eventually complete. The executor (e.g., Tokio) polls the `Future` to drive execution. Unlike Go's goroutines which are OS-thread multiplexed, Rust's async tasks are cooperative and run on a single thread (usually), reducing context switching overhead.

R10 — Medium: `unsafe` blocks allow bypassing Rust's safety guarantees. You can perform raw pointer dereferencing, call FFI functions, or use `unsafe` types like `*mut T`. It is justified when interfacing with C, implementing `unsafe` traits, or when performance requires zero-cost abstractions that the compiler cannot verify.

R11 — Easy: Pattern matching uses `match` to exhaustively match against a value. `if let` is a shorthand for a single match arm. The compiler enforces exhaustiveness: all possible variants of an enum must be handled, or the code will not compile.

R12 — Easy: `Vec<T>` is a growable array on the heap. `[T; N]` is a fixed-size array on the stack (or heap if moved). When a `Vec` is pushed beyond capacity, it allocates a new larger buffer (typically 1.5x or 2x) and copies elements.

R13 — Easy: Enums define algebraic data types with variants. Rust enums are exhaustive and type-safe, unlike C enums which are integers. `Option<T>` is an enum with `Some(T)` and `None`. Rust avoids nulls to prevent null pointer dereference errors.

R14 — Easy: `impl` blocks define methods and associated functions for a type. `&self` takes an immutable reference (allows borrowing). `&mut self` takes a mutable reference (allows modification). `self` takes ownership (consumes the value). Associated functions are defined with `fn` and do not take `self` (e.g., `String::new()`).

R15 — Easy: Derive macros automatically implement traits. Common traits include `Debug`, `Clone`, `PartialEq`, `Serialize`. You cannot derive traits that require complex logic or unsafe code (e.g., `Send` or `Sync` usually require manual implementation or specific configurations).

R16 — Medium: `Cow<'a, T>` (Clone on Write) holds either a borrowed reference or an owned clone. It is useful when you want to avoid cloning if the data is already borrowed, but clone if you need to modify it. Example: `Cow::Borrowed(s)` avoids allocation if `s` is not modified, `Cow::Owned(s.to_string())` allocates if modified.

R17 — Medium: Modules organize code. `mod` declares a module. `use` imports items. `pub` makes items public. The file system maps to modules (e.g., `src/lib.rs` is the root). Rust 2018 introduced `mod.rs` files and improved module visibility rules.

R18 — Hard: `Pin<T>` ensures a value is not moved in memory. It is needed for types that rely on stable memory addresses (e.g., async tasks with pinned references). `Unpin` is a marker trait that allows a type to be moved. Without `Pin`, async runtimes might move a task, invalidating internal references.

R19 — Hard: Declarative macros (`macro_rules!`) are text substitution with limited power. Procedural macros (derive, attribute, function-like) are Rust functions that generate code. Hygiene rules ensure macros do not accidentally capture variables from the surrounding scope, preventing name collisions.

R20 — Hard: Zero-cost abstractions are high-level constructs that compile down to efficient machine code without runtime overhead. Iterators are monomorphized (specialized for each type). Generics are specialized at compile time. Trait static dispatch allows calling trait methods without dynamic dispatch overhead, achieving C-like performance with Rust-like ergonomics.
