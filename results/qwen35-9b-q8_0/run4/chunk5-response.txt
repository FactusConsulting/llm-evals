DN1 — In C#, a `class` is a reference type (allocated on the heap), while a `struct` is a value type (allocated on the stack or inline within another object). Structs are immutable by default (unless mutable fields are added) and do not support inheritance. Use `struct` for small, immutable data structures (e.g., coordinates, colors) to avoid heap allocation overhead and improve performance. Avoid structs for large objects or objects that need to be shared across threads without copying.

DN2 — `IEnumerable<T>` represents a sequence of items and is executed immediately (e.g., LINQ to Objects). `IQueryable<T>` represents a query that is translated into a provider-specific language (e.g., SQL) and executed remotely (e.g., database). This distinction matters for databases because `IQueryable` allows the provider to optimize the query plan before execution, whereas `IEnumerable` forces materialization of the entire dataset into memory before filtering.

DN3 — `async/await` enables asynchronous programming by breaking long-running operations into smaller tasks without blocking threads. A `Task` represents an asynchronous operation. A `ValueTask` is a lightweight wrapper that can either return a value directly or a `Task`, avoiding unnecessary allocation when the operation completes synchronously. Use `ValueTask` for methods that are frequently synchronous (e.g., local cache lookups) to reduce GC pressure.

DN4 — Dependency Injection (DI) is a design pattern where objects receive their dependencies from an external source rather than creating them internally. The three lifetimes are: `Transient` (new instance every time), `Scoped` (new instance per request/context), and `Singleton` (one instance for the application lifetime). A common bug is injecting a `Scoped` service into a `Singleton`, causing the Scoped service to live longer than its intended scope, leading to memory leaks or stale data.

DN5 — `string` is immutable and backed by a `char[]` (or `Span<char>` in newer versions). `ReadOnlySpan<char>` is a lightweight, stack-allocated view over memory without copying. Use `Span<T>` (or `Span<char>`) for high-performance string processing to avoid allocations when manipulating substrings or buffers. It is ideal for scenarios like parsing or serialization where copying strings is expensive.

DN6 — The .NET GC manages memory in generations: Gen 0 (short-lived), Gen 1 (medium-lived), and Gen 2 (long-lived). The Large Object Heap (LOH) stores objects larger than 85KB. `IDisposable` is needed for the GC because it cannot manage unmanaged resources (e.g., file handles, database connections) deterministically; `Dispose` ensures these are released immediately upon use.

DN7 — `ConfigureAwait(false)` tells the async method not to capture the current `SynchronizationContext`. Default behavior (`true`) marshals back to the original context (e.g., UI thread). Use `ConfigureAwait(false)` in library code or background tasks to avoid deadlocks and context switching overhead. Do NOT use it in UI code (WinForms/WPF) where the context is required to update the UI.

DN8 — Primary constructors allow defining constructor parameters directly on the class declaration (C# 12). Collection expressions simplify creating collections (e.g., `[1, 2, 3]`). `FrozenDictionary` is a thread-safe, immutable dictionary. Example:
```csharp
public class MyService : IMyService {
    public MyService(string name) => Name = name;
}
// Usage
var services = new ServiceCollection();
services.AddMyService();
var provider = services.BuildServiceProvider();
```

DN9 — The likely cause is that `DbContext` is being disposed prematurely or reused incorrectly due to misconfigured DI lifetimes. EF Core's `DbContext` should be `Scoped`. If a Singleton service holds a reference to a Scoped `DbContext`, the `DbContext` might be disposed when the request ends while the Singleton persists. Fix: Ensure `DbContext` is registered as `Scoped` and never injected into `Singleton` services.

DN10 — `record` is a reference type designed for immutability and value-based equality (auto-generates `Equals`, `GetHashCode`, `ToString`). `record struct` is a value type with the same features. Use `record` for DTOs and domain entities that are reference types. Use `record struct` for small, immutable value objects (e.g., `Point`, `Money`) to avoid heap allocation.

DN11 — `ref` allows passing a reference to a variable to modify it in place. `out` requires the variable to be initialized before the call and is used to return multiple values. `in` is like `ref` but the variable cannot be modified inside the method. Use `ref` for mutable state, `out` for returning multiple values, and `in` for read-only access to large structures to avoid copying.

DN12 — Nullable reference types (`string?`) are a compile-time feature to track potential nulls, distinct from nullable value types (`int?` which is `Nullable<int>`). `string?` does not change runtime behavior but enables null safety warnings. `int?` is a value type that can hold `null` at runtime.

DN13 — LINQ (Language Integrated Query) allows querying data using C# syntax. Method syntax uses method calls (e.g., `list.Where(...)`), while query syntax uses SQL-like keywords (`from x in list where ...`). Both compile to the same IL. Deferred execution means the query is not executed until the result is enumerated (e.g., `ToList()`).

DN14 — Generic constraints restrict the types that can be used for a type parameter. `where T : class` ensures T is a reference type. `where T : struct` ensures T is a value type. `where T : new()` allows creating a default instance. `where T : IComparable<T>` ensures comparability. Combine constraints to enforce multiple requirements (e.g., `where T : class, IComparable<T>`).

DN15 — An `abstract class` can have state (fields) and partial implementations. An `interface` (prior to C# 8) could only have method signatures. Default interface methods (C# 8+) allow interfaces to have implementations, blurring the distinction. Use `abstract class` for shared state and logic. Use `interface` for defining contracts and multiple inheritance of behavior.

DN16 — Middleware is a pipeline of components that handle requests and responses. `app.Use()` adds middleware to the pipeline. `app.Map()` creates a sub-path branch. `app.Run()` executes middleware at the end of the pipeline. Ordering matters because middleware executes in the order added. Exception handling middleware (e.g., `UseExceptionHandler`) should be placed early to catch errors from subsequent middleware.

DN17 — `Channel<T>` is a thread-safe, bounded queue for producer-consumer patterns. `BlockingCollection<T>` wraps a `ConcurrentQueue<T>` and a `BlockingCollection<T>`. `Channel<T>` offers better performance and backpressure control. Example:
```csharp
var channel = Channel.CreateBounded<int>(10);
// Producer
await channel.Writer.WriteAsync(1);
// Consumer
var item = await channel.Reader.ReadAsync();
```

DN18 — Source Generators are compilers that generate code at compile time. They differ from reflection (runtime) and IL weaving (runtime). Incremental generators update only changed code, improving build times. `ISourceGenerator` is the base interface; incremental generators implement `IncrementalGenerator`. Use incremental generators for performance in large projects.

DN19 — TPL Dataflow is a library for building dataflow pipelines using blocks. `ActionBlock` processes items and performs an action. `TransformBlock` transforms items. `BufferBlock` buffers items. It compares to `System.Threading.Channels` by offering higher-level abstractions for pipeline logic (e.g., `Select`, `Where`) but is heavier and less flexible for custom buffering strategies.

DN20 — Minimal APIs are a lightweight way to build APIs without controllers. They differ by offering less boilerplate but less built-in testability and middleware support. Trade-offs: Faster development, less code, but harder to test complex middleware. Route groups organize routes. Endpoint filters allow cross-cutting concerns (e.g., logging) without controllers.

P1 — A `list` is mutable and ordered. A `tuple` is immutable and ordered. A `set` is unordered and contains unique elements. A `frozenset` is an immutable set. Use `list` for ordered collections, `tuple` for fixed-size data, `set` for uniqueness checks, and `frozenset` for hashable sets.

P2 — The GIL (Global Interpreter Lock) prevents multiple threads from executing Python bytecode simultaneously on a single CPU core. It affects CPU-bound workloads. Workarounds include using `multiprocessing` (separate processes), C extensions, or moving CPU-bound tasks to native code (e.g., Rust, C++).

P3 — `copy` creates a shallow copy (nested objects are shared). `deepcopy` creates a deep copy (all nested objects are copied). Example:
```python
a = [[1, 2], [3, 4]]
b = copy.copy(a)
b[0][0] = 99
print(a[0][0]) # 99 (unexpected)
```

P4 — Decorators are functions that modify other functions. Example:
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start:.2f}s")
        return result
    return wrapper
```

P5 — Generators use `yield` to return values and pause execution, saving memory compared to returning a list. `yield from` delegates to another generator. Use generators for large datasets to avoid loading everything into memory.

P6 — The event loop manages async tasks. `asyncio.run()` runs the main event loop. `asyncio.gather()` waits for multiple tasks. `asyncio.create_task()` schedules a task. `time.sleep()` blocks the event loop; use `await asyncio.sleep()` instead.

P7 — Python uses C3 Linearization for MRO. In the diamond inheritance example, `D` inherits from `B` and `C`, which both inherit from `A`. MRO is `[D, B, C, A, object]`. `D().who()` calls `B`'s `who` (inherited from `A`), which is not overridden in `B`, so it returns `"A"`. Wait, `C` overrides `who`. MRO: `D -> B -> C -> A`. `B` has no `who`, so it looks at `C`. `C` has `who`, so it returns `"C"`.

P8 — A metaclass is the class of a class. `__init_subclass__` is called when a subclass is defined. Use `__init_subclass__` for simple subclass hooks. Use metaclasses for complex class creation logic (e.g., ORM models). Example: `__init_subclass__` for logging class creation; metaclass for enforcing abstract methods.

P9 — `multiprocessing` uses separate processes (bypasses GIL). `threading` uses threads (shared memory, GIL limited). `concurrent.futures` provides a high-level interface for both. Use `multiprocessing` for CPU-bound tasks. Serialization (pickling) is required for `multiprocessing` to pass data between processes.

P10 — `__slots__` restricts the attributes a class can have, reducing memory usage. It prevents dynamic attribute creation. Use `__slots__` for classes with many instances (e.g., data models). It prevents adding new attributes at runtime.

P11 — A virtual environment isolates dependencies. `venv` is built-in. `virtualenv` is a third-party tool. `conda` manages environments and packages (including non-Python). Use `venv` for standard Python projects. Use `conda` for scientific computing.

P12 — List comprehensions create lists. Dict comprehensions create dicts. Set comprehensions create sets. They are more readable than `map()` and `filter()`. Use comprehensions for simple transformations; use `map`/`filter` for functional style or when using lambdas.

P13 — `==` checks value equality. `is` checks identity (same object in memory). Object interning caches small integers and strings. `a is b` returns `True` for small integers (e.g., 0-256) because they are cached.

P14 — `*args` collects positional arguments. `**kwargs` collects keyword arguments. `/` marks positional-only parameters. `*` marks keyword-only parameters. Example: `def f(a, /, b, *, c):`.

P15 — Context managers manage resources (e.g., files). Use `__enter__` and `__exit__` for custom classes. Use `@contextmanager` for generators. Example:
```python
@contextmanager
def timer():
    start = time.time()
    try:
        yield
    finally:
        print(time.time() - start)
```

P16 — Type hinting provides static type information. `Union` allows multiple types. `Optional` is `Union[T, None]`. `Literal` restricts to specific values. `TypeVar` enables generics. `Protocol` defines structural subtyping. Tools like `mypy` use these to catch type errors at development time.

P17 — `__repr__` is for debugging (unambiguous). `__str__` is for users (readable). `__eq__` defines equality. `__hash__` defines hashability. Defining `__eq__` without `__hash__` makes the object unhashable (cannot be used in sets/dicts).

P18 — Descriptors control attribute access. `__get__`, `__set__`, `__delete__` define behavior. `property` uses descriptors to manage attribute access. `classmethod` and `staticmethod` are descriptors that bind methods to the class or instance.

P19 — Imports load modules. Relative imports use `.` (e.g., `from . import x`). Absolute imports use full paths. `sys.path` controls search paths. `PYTHONPATH` adds directories. `__init__.py` makes a directory a package. Namespace packages allow packages without `__init__.py`. Finders locate modules; loaders load them.

P20 — `dataclasses` simplify class creation (auto-generate `__init__`, `__repr__`). `attrs` is similar but more flexible. `Pydantic` adds validation and serialization. Use `__post_init__` for initialization logic. `frozen` makes instances immutable. Use Pydantic for API validation and complex data models; use `dataclasses` for internal data structures.
