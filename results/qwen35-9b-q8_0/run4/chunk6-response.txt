JS1 — Easy: `var` is function-scoped and hoisted (initialized as `undefined`), allowing redeclaration. `let` and `const` are block-scoped and do not hoist values (temporal dead zone). `const` cannot be reassigned. Hoisting is the movement of declarations to the top of their scope during compilation.

JS2 — Easy: The event loop continuously checks the call stack. If empty, it checks the macrotask queue (setTimeout, I/O). If empty, it checks the microtask queue (Promises, queueMicrotask). Microtasks run before the next macrotask.

JS3 — Medium: A closure captures variables from the outer scope. Example: `function counter() { let c=0; return () => ++c; }`. The classic bug is `for (var i=0; i<3; i++) { setTimeout(() => console.log(i), 0); }` logs `3` three times. Fix: use `let` (block scope) or `i => { setTimeout(() => console.log(i), 0); }` (IIFE).

JS4 — Medium: Promises represent async completion. `async/await` is syntactic sugar over Promises. Errors in `await` throw exceptions. `Promise.all` rejects if any promise rejects. `Promise.allSettled` waits for all to settle (fulfilled or rejected) and returns results.

JS5 — Medium: Interfaces define shapes for objects/classes (nominal typing in TS). Types define primitive unions or complex shapes. Use interfaces for class-like structures; types for primitives or unions. Discriminated unions use a literal type on a property to distinguish union members (e.g., `type Status = { type: 'success' } | { type: 'error' }`).

JS6 — Medium: JS uses prototypes. `Object.create(proto)` creates an object with `proto` as its internal `[[Prototype]]`. ES6 classes are syntactic sugar over prototype chains (`class` creates a constructor function, `extends` sets up the prototype chain).

JS7 — Hard: `this` refers to the execution context. Priority: 1. Explicit binding (`call`, `apply`, `bind`). 2. Implicit binding (method call). 3. New binding (constructor). 4. Default binding (global/undefined). `bind()` returns a new function with `this` permanently bound. It can be re-bound, but the initial binding takes precedence over implicit binding.

JS8 — Hard: `WeakRef` holds a weak reference to an object (allowing GC). `FinalizationRegistry` allows cleanup when a weakly referenced object is garbage collected. `WeakMap` keys must be objects because primitives are boxed and would be collected, breaking the map. This enables storing metadata without preventing GC.

JS9 — Hard: V8 uses hidden classes for property layout optimization. Inline caching stores type checks for faster execution. Deoptimization occurs when assumptions fail (e.g., adding a property to an object, changing types), reverting to slower interpretation. Patterns causing deoptimization: mutating object properties, changing variable types.

JS10 — Medium: Tree-shaking removes unused code. ES Modules use static imports, allowing static analysis. CommonJS uses dynamic `require`, preventing static analysis of imports, so unused exports cannot be removed.

JS11 — Easy: `null` is an intentional absence of value; `undefined` is a missing value. `==` performs type coercion (`null == undefined` is true). `===` checks strict equality. `??` returns the right operand if the left is `null` or `undefined`. `?.` safely accesses nested properties (returns `undefined` if path breaks).

JS12 — Easy: `map()` transforms elements. `filter()` returns a new array of elements passing a test. `reduce()` aggregates elements into a single value. `reduce` with an initial value avoids the first element being used as the accumulator. `flatMap()` maps and flattens the result one level deep.

JS13 — Easy: Template literals use backticks and allow expressions `${}`. Tagged templates pass raw string segments to a function. Example: `const sql = db` + `query` + `;`. Tagged: `const sql = sqlTag` + `query` + `;` (function receives parts and delimiters).

JS14 — Easy: Destructuring extracts values from arrays/objects. Object: `{ name } = obj`. Array: `[first, second] = arr`. Defaults: `{ name = 'default' }`. Renaming: `{ name: newName }`. Rest: `{ ...rest }` collects remaining properties.

JS15 — Easy: `for...in` iterates enumerable own and inherited properties (objects). `for...of` iterates iterable values (arrays, strings). Avoid `for...in` on arrays as it iterates indices and inherited properties, potentially skipping holes.

JS16 — Medium: Generics allow components to work with multiple types. Constraints (`extends`) limit types. Conditional types (`T extends U ? X : Y`) select based on type. `infer` extracts types from conditional types. Example: `function identity<T>(arg: T): T { return arg; }`.

JS17 — Medium: CommonJS uses `require`/`module.exports` (Node default). ES Modules use `import`/`export` (static). Node handles both via `type: "module"` in `package.json` or `.mjs` extension. `type: "module"` makes all imports ES modules.

JS18 — Hard: Structural typing checks shape, not names. Excess property checks occur at object literal creation (not assignments). `extends` allows excess properties; `satisfies` enforces strict adherence (no excess). Variance: `in` (contravariant) for input, `out` (covariant) for output.

JS19 — Hard: `Proxy` creates a proxy object to intercept operations. `Reflect` provides default behavior. Intercept access (`get`), assignment (`set`), and calls (`apply`). Example: `new Proxy(obj, { get: (target, prop) => console.log('get', prop), set: (target, prop, val) => console.log('set', prop, val) })`.

JS20 — Hard: `SharedArrayBuffer` allows memory sharing between threads (Web Workers). `Atomics` provides atomic operations (`wait`, `notify`) on shared memory. Ordering guarantees: `wait` blocks until `notify` is called. Used for synchronization without locks.

B1 — Easy: `$@` is all arguments as separate words. `$*` is all arguments as a single string (IFS separated). `"$@"` preserves word boundaries (safe). `"$*"` treats arguments as one string (unsafe for spaces).

B2 — Easy: `set -e` exits on error. `set -u` exits on undefined variable. `set -o pipefail` exits if any command in pipeline fails.

B3 — Medium: `$(command)` is command substitution (output). `command` is a subshell (in `if`/`while`). `$((expr))` is arithmetic expansion. `expr` is an external command for string/regex matching.

B4 — Medium: Process substitution `<(command)` creates a named pipe/file descriptor. Used when a command needs to read from stdin but another command needs to read from a file. Example: `diff <(ls dir1) <(ls dir2)`.

B5 — Medium: Use `while IFS= read -r -d '' file; do ...; done < <(find . -print0)`. `for f in $(ls)` splits by IFS (spaces/newlines), breaking filenames with spaces.

B6 — Medium: `<<EOF` starts a here document (input to stdin). `<<<` is a here string (input to stdin). `<<-` allows tab indentation for the delimiter.

B7 — Hard: `cmd > file 2>&1`: stdout to file, stderr to stdout (file). `cmd 2>&1 > file`: stderr to stdout (pipe), then stdout to file (stderr lost). `cmd &> file`: both stdout and stderr to file. First two differ because redirection order matters.

B8 — Hard: Use `mkdir -p "$lockdir/$pid"` for locking. Check `if [ ! -d "$lockdir/$pid" ]; then mkdir ...; else exit 1; fi`. Cleanup via `trap`. `mkdir` is atomic on POSIX systems (racy file creation).

B9 — Easy: Single quotes preserve everything literally. Double quotes allow variable expansion and globbing. No quotes allow globbing and variable expansion. Example: `'echo $HOME'` prints literal `$HOME`. `"echo $HOME"` prints path.

B10 — Easy: `[ -f file ]` (file), `[ -d dir ]` (dir), `[ -r file ]` (readable). `[ ]` is POSIX (word splitting). `[[ ]]` is Bash (no word splitting, regex support).

B11 — Easy: `$?` is last command exit code. `$$` is current PID. `$!` is last background PID. `$#` is number of arguments.

B12 — Easy: `function foo {}` and `foo() {}` are equivalent. Return values via `echo` or `return` (exit code 0-255).

B13 — Easy: `PATH` is a colon-separated list of directories. Bash searches these for executables. Builtins are internal (e.g., `cd`). External are in `PATH`. Use `type` or `command -v` to check.

B14 — Medium: `trap 'cmd' signal`. `EXIT` runs on script end. `ERR` runs on command failure. `INT` (Ctrl+C), `TERM` (kill). Order: `EXIT` handlers run last.

B15 — Medium: `xargs` processes arguments. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P` runs parallel processes.

B16 — Medium: Arrays: `arr=(1 2)`. `arr+=("3")`. `${#arr[@]}` length. Associative: `declare -A arr`. `arr[key]=val`. `for key in "${!arr[@]}"`.

B17 — Hard: Subshell `(...)` changes variables locally (parent unaffected). Group `{ ... }` shares variables. Piping creates a subshell, so `while` loop variable changes don't persist.

B18 — Hard: Signals: `SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (hangup), `SIGKILL` (unblockable). Use `trap` to handle `TERM` and `INT` to stop background jobs (`kill $!`).

B19 — Hard: `split -l 1000 file part_` | `xargs -P 4 -I {} process {}` | `cat part_* > merged`. Trade-off: parallelism vs I/O overhead. Handle errors by checking exit codes in `xargs` or using `set -o pipefail`.

B20 — Hard: `exec` replaces the shell with the command. `exec 3>file` redirects FD 3. Coprocess: `coproc NAME { command }`. Use for background processes with stdin/stdout redirection.

PS1 — Easy: `Write-Output` sends object to pipeline. `Write-Host` writes to console (breaks pipeline). Distinction matters for piping data to other commands.

PS2 — Easy: Pipeline passes objects. `ForEach-Object` is a cmdlet (pipeline). `foreach` is a statement (script block). Use `ForEach-Object` for pipeline processing; `foreach` for iteration over variables.

PS3 — Medium: `[PSCustomObject]` creates a proper object with properties. `[hashtable]` is a dictionary-like object. Convert: `[PSCustomObject]@{ Key = $Value }` or `$obj | ConvertTo-Json`.

PS4 — Medium: Terminating errors stop execution. Non-terminating continue. `-ErrorAction Stop` makes errors terminating. `try/catch` catches terminating errors. `$ErrorActionPreference` sets default.

PS5 — Medium: Splatting `@params` passes hashtable as named arguments. Passing hashtable as single arg requires `@` to expand. Example: `Get-Item @params`.

PS6 — Medium: `Invoke-Command` runs remote script. `Enter-PSSession` creates interactive session. Uses WinRM (default) or SSH.

PS7 — Hard: Function returning array creates array object. `$result += "one"` creates array. `return $result` returns array. `$x.GetType().Name` is `Object[]`. If empty, returns `Object[]` (empty). Correct pattern: `return $result` or `return $null`.

PS8 — Hard: `[scriptblock]` is a compiled block. Functions are defined in scope. Pass scriptblock to remote via `-ScriptBlock`. Double-hop: Credential delegation fails. Solve with CredSSP or `-ArgumentList` (serialization).

PS9 — Easy: `@()` creates array. `[array]` is type. Force single to array: `@($var)`. Indexing `$null` throws error. Empty array `@()` returns empty.

PS10 — Easy: `-eq` numeric/string equality. `-like` wildcard. `-match` regex. `-contains` checks array membership. `-in` checks if value is in array. Case-sensitive variants: `-ceq`, `-clike`.

PS11 — Easy: Module is a collection of functions/classes. `.psm1` is script module (compiled). `.psd1` is manifest (metadata). `Import-Module` loads them.

PS12 — Easy: Interpolation: `"Hello $name"`. Single quotes `'...'` no interpolation. Here-string: `@"..."@` (multiline).

PS13 — Easy: `Get-Member` shows properties/methods. `Properties` (data), `Methods` (actions), `NoteProperties` (metadata). `Select-Object` selects properties. `Where-Object` filters.

PS14 — Medium: Classes in v5 are C#-like but limited (no interfaces, limited inheritance). Use classes for encapsulation/state; functions for logic.

PS15 — Medium: `[CmdletBinding()]` enables advanced functions. `SupportsShouldProcess` adds `-WhatIf`/`-Confirm`. `ValueFromPipeline` allows piping objects. `Begin/Process/End` blocks handle streaming.

PS16 — Medium: Providers abstract namespaces. `Get-ChildItem` works on FileSystem, Registry, etc. Registry: `Get-ChildItem HKLM:\Software`.

PS17 — Hard: Runspaces are threads. `[runspacepool]` manages them. `[powershell]` object executes. `ForEach-Object -Parallel` (v7+) uses thread pool. Manual runspace management for complex control.

PS18 — Hard: PSScriptAnalyzer enforces rules (e.g., `PSUseDeclaredVarsMoreThanAssignments`). Severity: Info, Warning, Error. Suppress via `# # scriptanalyzer disable`. CI/CD via `Invoke-ScriptAnalyzer`.

PS19 — Hard: `$using:` passes variables to background jobs/parallel. `-ArgumentList` serializes arguments. Serialization limits (CLIXML depth) affect complex objects (e.g., nested arrays).

PS20 — Hard: DSC manages configuration state. Configurations define desired state. Resources implement actions. LCM applies config. Replaced by Configuration Management as Code (e.g., Ansible, Terraform) in modern IaC.
