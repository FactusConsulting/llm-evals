## Kubernetes (20 questions)

**K1**
A **Deployment** manages stateless applications, ensuring a specified number of replicas are running. Pods are interchangeable, and updates happen via rolling updates. A **StatefulSet** manages stateful applications, providing stable network identities (e.g., `pod-0`), ordered deployment/termination, and persistent storage per pod.

**K2**
A **ClusterIP** Service creates a virtual IP within the cluster. The Service controller updates **Endpoints** with the IPs of matching pods. **kube-proxy** watches these Endpoints and creates iptables (or IPVS) rules on each node to forward traffic from the Service IP to the specific Pod IPs.

**K3**
*   **PersistentVolume (PV):** A piece of storage in the cluster provisioned by an administrator or dynamically.
*   **PersistentVolumeClaim (PVC):** A request for storage by a user (specifies size, access mode).
*   **StorageClass:** Defines how to dynamically provision PVs (e.g., AWS EBS).
*   **Relation:** A PVC requests storage based on a StorageClass; the controller creates a matching PV, which the PVC binds to.

**K4**
1.  **Logs:** `kubectl logs <pod>` to check for application errors.
2.  **Events:** `kubectl describe pod <pod>` to check for OOMKilled or probe failures.
3.  **Probes:** Check Liveness/Readiness probe configurations and thresholds.
4.  **Resources:** Check if CPU/Memory requests exceed node capacity or if limits are too low.

**K5**
**CoreDNS** provides the internal DNS server for the cluster, resolving Service names to Pod IPs. If CoreDNS pods are down, internal service discovery fails (pods cannot resolve other services), breaking communication within the cluster. External DNS resolution may still work if configured via upstream resolvers.

**K6**
The scheduler follows three phases:
1.  **Filtering:** Removes nodes that don't meet hard constraints (taints, node selectors, resource requests).
2.  **Scoring:** Assigns a score to remaining nodes based on preferences.
3.  **Factors:**
    *   **LeastAllocated:** Prefers nodes with fewer resources used.
    *   **MostAllocated:** Prefers nodes with more resources used (bin-packing).
    *   **NodeAffinity:** Respects affinity rules defined in the pod spec.

**K7**
**Yes**, the pod will be scheduled. The node has 3.5GB available, and the pod requests 256Mi. However, if the runtime usage hits 600Mi, it exceeds the **limit** of 512Mi. The container will be **OOMKilled** by the kubelet.

**K8**
1.  **External LB:** Receives traffic on port 80.
2.  **Ingress Controller:** Receives traffic, matches rules, and forwards to the backend Service.
3.  **Service (ClusterIP):** Routes traffic to the Pod IP based on Endpoints.
4.  **Endpoints:** Contains the current list of healthy Pod IPs.
5.  **kube-proxy:** Maintains iptables/IPVS rules to forward traffic from Service IP to Pod IP.

**K9**
A **NetworkPolicy** restricts network traffic to/from pods. By default, if no NetworkPolicy exists, **all ingress and egress traffic is allowed**. When a policy is applied, it defaults to **deny all** traffic unless explicitly allowed by the policy rules.

**K10**
**RollingUpdate** replaces old pods with new ones gradually (zero downtime). **Recreate** kills all old pods before starting new ones (downtime). Choose **Recreate** for stateful applications (e.g., databases) where downtime is acceptable or required for data consistency.

**K11**
A **Namespace** is a virtual cluster within a physical cluster, used to isolate resources. Default namespaces created are: **default**, **kube-system**, **kube-public**, and **kube-node-lease**.

**K12**
`kubectl describe pod` shows detailed status and events. Three pieces of info not in `get`:
1.  **Events:** History of pod lifecycle events (e.g., "FailedMount").
2.  **Conditions:** Detailed readiness/liveness status.
3.  **Node Name:** Which specific node the pod is running on.

**K13**
A **ConfigMap** stores non-confidential configuration data as key-value pairs. Pods consume it via:
1.  **Environment Variables:** `envFrom` or `env`.
2.  **Volume Mount:** Mounting as a directory or file inside the container.

**K14**
*   **ClusterIP:** Internal cluster access only (default).
*   **NodePort:** Exposes the service on a static port on every node's IP.
*   **LoadBalancer:** Provisions an external cloud load balancer to expose the service externally.

**K15**
A **DaemonSet** ensures a copy of a Pod runs on all (or selected) nodes. Use it instead of a Deployment for node-level services like **logging agents (Fluentd)**, **monitoring agents (Prometheus Node Exporter)**, or **CNI plugins**.

**K16**
*   **Taints/Tolerations:** Taints push pods away; Tolerations allow specific pods to ignore taints.
*   **Node Affinity:** Pulls pods to specific nodes based on labels.
*   **Use Case:** Taints for GPU nodes (prevent general pods from running there). Affinity for placing DB pods on specific hardware.

**K17**
An **Operator** is a custom controller that encapsulates the logic to manage the lifecycle of a complex application (e.g., backups, scaling, upgrades). It differs from a standard controller by implementing domain-specific logic. It solves the "how to manage complex stateful apps" problem.

**K18**
Kubernetes uses **Raft** for etcd consistency. A quorum (N/2 + 1) is required for writes/reads. If 2 out of 3 nodes are lost, only 1 remains, breaking quorum. The cluster becomes unavailable. **Recovery:** Restore the lost nodes from a snapshot backup to re-establish quorum.

**K19**
*   **Role:** Defines permissions in a namespace.
*   **ClusterRole:** Defines permissions cluster-wide.
*   **RoleBinding:** Binds a Role to a user/group in a namespace.
*   **ClusterRoleBinding:** Binds a ClusterRole to a user/group cluster-wide.

**Manifests:**
```yaml
# Role: Read-only access to pods/logs in 'dev' namespace
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: dev
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
# RoleBinding: Bind to 'developer' group
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods
  namespace: dev
subjects:
- kind: Group
  name: developers
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20**
**ndots** (default 5) determines how many dots a domain name must have to be treated as absolute. If a domain has fewer dots, it is treated as relative and search domains are appended, causing excessive queries. **Fix:** Add `dnsConfig` to the pod spec:
```yaml
dnsConfig:
  options:
    - name: ndots
      value: "1"
```

## Development (20 questions)

**D1**
**Rebase** rewrites history to make a branch linear (commits are moved). **Merge** preserves history and creates a merge commit. Avoid rebasing on **public/shared branches** (e.g., main) as it rewrites history for others.

**D2**
**TCP** is connection-oriented, reliable, and ordered. **UDP** is connectionless, unreliable, and unordered.
*   **TCP:** HTTP, SSH.
*   **UDP:** DNS, VoIP.

**D3**
A **race condition** occurs when the outcome depends on the timing of concurrent events.
*   **Example:** Two threads check if `balance > 0` and then deduct $10. If both pass the check before either deducts, the balance is deducted twice, causing an overdraft.

**D4**
**Symmetric** uses one shared key (fast, e.g., AES). **Asymmetric** uses public/private keys (slow, e.g., RSA).
*   **TLS:** Asymmetric keys exchange a session key securely. Symmetric encryption is then used for the actual data transfer to ensure speed.

**D5**
A **layer** is a filesystem snapshot in a container image. **Layer caching** speeds up builds by reusing unchanged layers. Best practice: Place `COPY` of dependencies before `RUN` commands to maximize cache hits.

**D6**
1.  **Logs:** Check application logs for errors.
2.  **Dependencies:** Check if the database or upstream service is reachable.
3.  **Health Checks:** Verify if the liveness/readiness probes are passing.
4.  **Infrastructure:** Check if the Load Balancer or firewall is blocking traffic.

**D7**
**CAP Theorem:** A distributed system can only guarantee two of three: **Consistency**, **Availability**, or **Partition Tolerance**.
*   **CP:** Zookeeper (prioritizes data consistency over availability during network splits).
*   **AP:** Cassandra/DynamoDB (prioritizes availability; may return stale data during splits).

**D8**
**Horizontal:** Adding more instances (nodes). **Vertical:** Adding more CPU/RAM to existing instances.
*   **Pattern:** Horizontal scaling requires **stateless** applications and a **Load Balancer** to distribute traffic.

**D9**
An **environment variable** is a dynamic variable in the environment. To persist across sessions on Linux:
*   `export VAR=value` in your shell profile (e.g., `~/.bashrc` or `~/.zshrc`).
*   Or set it in `/etc/environment` for system-wide persistence.

**D10**
**JSON** is a data interchange format (strict, machine-readable). **YAML** is a human-readable data serialization format.
*   **JSON Advantage:** Strict validation, widely supported.
*   **YAML Advantage:** Readability, indentation-based structure.

**D11**
A **REST API** uses HTTP methods to manipulate resources.
*   **GET:** Retrieve data.
*   **POST:** Create new data.
*   **PUT:** Replace/Update existing data.
*   **DELETE:** Remove data.

**D12**
**Version pinning** specifies an exact version of a dependency (e.g., `1.2.3`). It is important for **reproducible builds** to ensure the same code runs in different environments and to prevent unexpected breaking changes.

**D13**
**Compiled** languages are translated to machine code before execution (fast). **Interpreted** languages are translated line-by-line at runtime (flexible).
*   **Compiled:** C, Go.
*   **Interpreted:** Python, JavaScript.

**D14**
A **Reverse Proxy** sits in front of servers (handles SSL, caching). A **Forward Proxy** sits in front of clients (handles filtering, anonymity).
*   **Reverse:** Nginx (SSL termination).
*   **Forward:** Squid (Corporate internet access).

**D15**
A **deadlock** occurs when processes are blocked forever waiting for resources held by each other.
*   **Conditions:**
    1.  Mutual Exclusion.
    2.  Hold and Wait.
    3.  No Preemption.
    4.  Circular Wait.

**D16**
**Eventual consistency** means data converges to a consistent state after some time. Cassandra uses **Tunable Consistency Levels** (e.g., ONE, QUORUM, ALL) to balance performance and consistency. Read-after-write consistency is handled by routing reads to the node that wrote the data or waiting for replication.

**D17**
**mTLS** requires both client and server to authenticate using certificates.
*   **Handshake:** Client sends certificate -> Server verifies -> Server sends certificate -> Client verifies -> Key Exchange.
*   **Use:** Service Mesh (Istio), API security, internal microservice communication.

**D18**
A **hash table** uses an array and a hash function to map keys to indices.
*   **Collision:** Chaining (linked list at index) or Open Addressing (probing next slot).
*   **Complexity:** Average O(1), Worst O(n) (due to collisions).

**D19**
**Circuit Breaker** prevents cascade failures by stopping calls to a failing service.
*   **Closed:** Normal operation.
*   **Open:** Fail fast (no calls).
*   **Half-Open:** Test calls allowed to see if service recovered.
*   **Relation:** Retries are disabled when Open; Exponential Backoff is used when Half-Open.

**D20**
**Optimistic:** Assumes no conflict; checks on commit (e.g., `SELECT FOR UPDATE` or CAS). **Pessimistic:** Locks resources immediately.
*   **Optimistic:** High concurrency, low contention (e.g., counters).
*   **Pessimistic:** Critical data integrity (e.g., bank transactions).
