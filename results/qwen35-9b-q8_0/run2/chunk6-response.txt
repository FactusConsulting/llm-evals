JS1: `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and hoisted but not initialized (Temporal Dead Zone). `const` cannot be reassigned. Hoisting is the parsing phase where declarations are moved to the top of their scope.

JS2: The event loop continuously checks the call stack. If empty, it checks the microtask queue (Promises, `queueMicrotask`) first, then the macrotask queue (setTimeout, I/O). Microtasks run before the next macrotask.

JS3: A closure is a function bundled with its lexical environment. Example: `function counter() { let c=0; return () => ++c; }`. The classic bug: `for (var i=0; i<3; i++) setTimeout(() => console.log(i), 0)` logs `3,3,3` because `i` is shared. Fix: use `let` (block scope) or `i => setTimeout(..., i)`.

JS4: Promises represent async completion. `async/await` is syntactic sugar over Promises. Errors in `await` throw synchronously. `Promise.all` rejects on the first failure; `Promise.allSettled` waits for all to settle (fulfilled or rejected) and returns an array of results.

JS5: Interfaces define shapes for objects/classes (nominal typing in TS). Types define primitive shapes or unions. Use interfaces for class-like structures; types for primitives or unions. Discriminated unions use a literal type to distinguish union members (e.g., `type Status = { type: 'success', data: string } | { type: 'error', code: number }`).

JS6: JS uses prototypes. `Object.create(proto)` creates an object with `proto` as its internal `[[Prototype]]`. ES6 classes are syntactic sugar over prototype chains (`class` creates a constructor function, `extends` sets the prototype).

JS7: `this` refers to the object executing the function. Priority: 1. Explicit binding (`call`, `apply`, `bind`). 2. Implicit binding (method call `obj.method()`). 3. Default binding (global `window` or `undefined` in strict mode). 4. New binding (`new Constructor()`). `bind()` returns a new function with `this` permanently bound; it can be re-bound.

JS8: `WeakRef` holds a weak reference to an object (GC can collect it). `FinalizationRegistry` allows cleanup when a weakly referenced object is GC'd. `WeakMap` keys must be objects because primitives are boxed and not suitable for weak tracking; this allows the map to be garbage collected if the key is no longer referenced elsewhere.

JS9: V8 uses hidden classes for property access optimization. Inline caching stores type info to skip checks. Deoptimization occurs when assumptions fail (e.g., adding a property to an object after creation, changing types). Patterns causing deoptimization: dynamic property addition, `Object.defineProperty`, `delete`, or changing types in loops.

JS10: Tree-shaking removes unused code. ESM uses static imports, allowing static analysis. CJS uses dynamic `require`, making imports dynamic and unanalyzable by bundlers, preventing tree-shaking.

JS11: `null` is an intentional absence of value; `undefined` is a missing value. `==` performs type coercion; `===` checks strict equality. `??` returns the right operand if the left is `null` or `undefined`. `?.` safely accesses nested properties (returns `undefined` if path is broken).

JS12: `map()` transforms elements; `filter()` returns a subset; `reduce()` aggregates to a single value. `reduce` with an initial value avoids the first element being the accumulator. `flatMap()` maps and flattens the result one level deep (useful for nested arrays).

JS13: Template literals use backticks and allow expressions `${expr}`. Tagged templates pass parts of the string as arguments to a function. Example: `sql` tag function receives strings and values separately to prevent SQL injection.

JS14: Destructuring extracts values from arrays/objects. Object: `{ a, b } = obj`. Array: `[a, b] = arr`. Defaults: `{ a = 1 }`. Renaming: `{ a: x }`. Rest: `{ ...rest }` collects remaining properties.

JS15: `for...in` iterates enumerable own and inherited properties (use for objects). `for...of` iterates iterable values (use for arrays). Avoid `for...in` on arrays as it includes inherited properties and order is not guaranteed.

JS16: Generics allow components to work with multiple types. `extends` constrains types (e.g., `T extends string`). Conditional types `T extends U ? X : Y` branch based on type. `infer` extracts a type from a conditional (e.g., `Extract` utility).

JS17: CommonJS uses `require`/`module.exports` (Node default). ES Modules use `import`/`export` (static). Node supports both via `type: "module"` in `package.json` (ESM) or default CJS. `type: "module"` makes `.js` files ESM.

JS18: Structural typing checks shape, not names. Excess property checks occur at object literal creation (not assignments). `extends` allows excess properties; `satisfies` enforces strictness (no excess). Variance: `in` (contravariant) for input, `out` (covariant) for output.

JS19: `Proxy` creates a wrapper object to intercept operations. `Reflect` provides default behavior. Intercept access via `get`, assignment via `set`, calls via `apply`. Example: A proxy wrapping a data object to log changes before updating.

JS20: `SharedArrayBuffer` allows memory sharing between threads (Workers). `Atomics` provides wait/notify for synchronization. Ordering guarantees: `Atomics.wait` blocks until notified. `Atomics.notify` wakes up waiting threads. Requires `SharedArrayBuffer` support.

B1: `$@` is an array of positional parameters; `$*` is a single string of all parameters. `"$@"` expands to individual arguments (preserves spaces); `"$*"` expands to one string (spaces lost).

B2: `set -e` exits on error; `-u` treats unset vars as errors; `-o pipefail` propagates pipe errors.

B3: `$(cmd)` is command substitution (output); `command` is a subshell (group). `$((expr))` is arithmetic expansion; `expr` is an external command for string/regex.

B4: `<(cmd)` creates a named pipe (FIFO) for reading. Use with `diff` to compare a file against a command output without saving to disk: `diff file <(cmd)`.

B5: Use `while IFS= read -r -d '' file; do ...; done < <(find . -print0)`. `for f in $(ls)` splits on whitespace, breaking filenames with spaces.

B6: `<<EOF` starts a here document (multiple lines). `<<<` is a here string (single line). `<<-` allows tab indentation for the delimiter.

B7: `cmd > file 2>&1`: stdout to file, then stderr to file. `cmd 2>&1 > file`: stderr to stdout (original), then stdout to file (stderr lost). `cmd &> file`: redirects both to file (sh/bash).

B8: Use `mkdir -p "$lockdir/$pid"` to create a directory lock. Use `trap` to `rm -rf` on exit. `mkdir` is atomic on most filesystems, preventing race conditions better than file creation.

B9: Single quotes preserve everything literally. Double quotes allow variable expansion and globbing. No quotes allow globbing and variable expansion. Example: `'echo $HOME'` prints literal `$HOME`; `"echo $HOME"` prints path.

B10: `[ -f file ]` checks file; `[ -d dir ]` checks directory; `[ -r file ]` checks readable. `[ ]` uses word splitting; `[[ ]]` is a keyword (safer, supports regex `=~`).

B11: `$?` is last exit code; `$$` is current PID; `$!` is last background PID; `$#` is number of arguments.

B12: `foo() { ... }` or `function foo { ... }`. Return values via `echo` or `return` (exit code 0-255).

B13: `PATH` is a colon-separated list of directories. Bash searches these for executables. Builtins are internal (e.g., `cd`); externals are in `PATH`. Use `type` to check.

B14: `trap 'cmd' signal` sets a handler. `EXIT` runs on script exit; `ERR` on command failure; `INT`/`TERM` on signals. Order: `EXIT` handlers run last.

B15: `xargs` executes commands with arguments. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P 4` runs 4 parallel processes.

B16: Arrays: `arr=(1 2)`, `${arr[@]}`. Associative: `declare -A arr`, `arr[key]=val`. Syntax differs; associative uses string keys.

B17: Subshell `(...)` isolates variables; `{ ... }` shares variables. Piping into `while` runs the loop in a subshell, losing variable changes.

B18: `SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (hangup), `SIGKILL` (unkillable). Use `trap` to kill background processes on `TERM`.

B19: `split -l 1000 file part_` | `xargs -P 4 -I {} bash -c 'process {}'` | `cat part_*`. Trade-off: parallelism vs coordination. Handle errors by checking exit codes in the merge step.

B20: `exec` replaces the shell process. `exec 3>file` redirects FD 3. Coprocess: `coproc NAME { command }`. Use for interactive background processes.

PS1: `Write-Output` sends object to pipeline; `Write-Host` writes to console (bypasses pipeline). Distinction matters for piping data to other commands.

PS2: Pipeline passes objects. `ForEach-Object` is a cmdlet (pipeline-aware); `foreach` is a statement (script block). Use `ForEach-Object` for pipeline processing.

PS3: `[PSCustomObject]` creates an object with properties; `[hashtable]` is a generic key-value store. Convert: `@{a=1} | ConvertTo-Json` or `[PSCustomObject]@{a=1}`.

PS4: Terminating errors stop the script; non-terminating continue. `-ErrorAction Stop` makes errors terminating. `try/catch` catches terminating errors.

PS5: Splatting: `$params = @{a=1; b=2}; New-Item @params`. Passes hashtable as named arguments.

PS6: `Invoke-Command` runs a script remotely; `Enter-PSSession` creates an interactive session. Uses WinRM (default) or SSH.

PS7: `Get-Items` returns an array. `$x` is an array. `GetType().Name` is `Object[]`. If empty, it's still an array. Correct pattern: `return $result` (implicit array) or `[PSCustomObject]@{}`.

PS8: `[scriptblock]` is a compiled block. Pass via `-ArgumentList` or `-ScriptBlock`. Double-hop: remote session authenticates to another remote session. Solve with CredSSP or `-Authentication None` (if trusted).

PS9: `@()` creates an array; `[array]` is a type. Force single to array: `@($var)`. Indexing `$null` throws; empty array returns `$null`.

PS10: `-eq` numeric/string equality; `-like` wildcard; `-match` regex. `-ceq` is case-sensitive. `-contains` checks if element exists in array; `-in` checks if value is in array (similar, but `-contains` is optimized for arrays).

PS11: Module is a collection of functions/classes. `.psm1` is code; `.psd1` is manifest (exports). `Import-Module` loads them.

PS12: `"..."` allows `$var` expansion; `'...'` does not. `@"..."@` is a here-string (multiline).

PS13: `Get-Member` lists properties/methods. `Select-Object` selects properties; `Where-Object` filters. NoteProperties are static strings.

PS14: Classes are objects with methods. Limited inheritance (single). Use for encapsulation; functions for scripts.

PS15: `[CmdletBinding()]` enables advanced functions. `SupportsShouldProcess` adds `-WhatIf`/`-Confirm`. `Begin`/`Process`/`End` blocks handle pipeline input.

PS16: Providers abstract namespaces. `Get-ChildItem` works on FileSystem, Registry, etc. Registry: `Get-ChildItem HKLM:\SOFTWARE`.

PS17: `Runspace` is a thread. `RunspacePool` manages them. `ForEach-Object -Parallel` (v7+) uses threads. `PowerShell` object manages runspace.

PS18: `PSScriptAnalyzer` checks code style/rules. Rules have severity (Error, Warning). Suppress via `# #PSA: disable`. CI integration via `Invoke-ScriptAnalyzer`.

PS19: `$using:` passes variables to remote/background jobs. `-ArgumentList` serializes arguments. Limits: CLIXML depth (complex objects fail).

PS20: DSC configures Windows state (resources, configurations, LCM). Replaced by Ansible/Terraform for IaC, though DSC remains for Windows config management.
