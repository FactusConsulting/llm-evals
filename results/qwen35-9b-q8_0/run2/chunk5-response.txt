DN1 — Classes are reference types stored on the heap; structs are value types stored on the stack (or inline in heap objects). Use structs for small, immutable data (e.g., coordinates, enums) to avoid heap allocation overhead and enable value semantics (pass-by-value). Avoid structs for large objects or objects with methods that rely on reference equality.

DN2 — `IEnumerable<T>` executes queries in memory (client-side); `IQueryable<T>` builds an expression tree executed by a provider (server-side). This matters for databases because `IQueryable` allows the provider (e.g., EF Core) to translate the query into SQL, whereas `IEnumerable` forces all data to load into memory before filtering.

DN3 — `async/await` uses state machines to suspend execution without blocking threads. `Task` represents an asynchronous operation; `ValueTask` is a lightweight wrapper that avoids allocation if the result is already available (synchronous). Use `ValueTask` in performance-critical paths where the operation is often synchronous (e.g., `ReadValueTask`), but avoid it if the operation is always asynchronous to prevent boxing overhead.

DN4 — Dependency Injection (DI) allows injecting dependencies rather than creating them. Lifetimes: `Transient` (new per request), `Scoped` (new per request scope), `Singleton` (new per app lifetime). Common bug: Injecting a `Scoped` service into a `Singleton`. The Singleton holds a reference to the Scoped service, but the Scoped service is disposed at the end of the request, causing `ObjectDisposedException` on subsequent requests.

DN5 — `string` is a reference type with internal UTF-16 encoding; `ReadOnlySpan<char>` is a stack-allocated view over memory (zero-copy). Use `Span<T>` for high-performance, zero-allocation memory operations (e.g., parsing, string manipulation) to avoid heap allocations and GC pressure.

DN6 — The GC manages memory in generations: Gen 0 (short-lived), Gen 1 (medium), Gen 2 (long-lived). The Large Object Heap (LOH) stores objects >85KB. `IDisposable` is needed for deterministic cleanup of unmanaged resources (files, DB connections) because the GC is non-deterministic and cannot free unmanaged resources immediately.

DN7 — `ConfigureAwait(false)` tells the awaiter not to capture the current `SynchronizationContext`. Use it in library code or high-concurrency scenarios to avoid deadlocks in UI apps (where context is required). Do NOT use it in UI code (WinForms/WPF) or when you need to resume on the original context (e.g., ASP.NET Core default context).

DN8 — Primary constructors (C# 12) allow parameters in class definitions. Collection expressions create collections inline. `FrozenDictionary` is immutable.
Example:
```csharp
public class Person(string name) { public string Name { get; } = name; }
// DI Registration
builder.Services.AddSingleton(new Person("Alice"));
```

DN9 — Cause: `DbContext` is registered as `Scoped`, but accessed in a `Singleton` or after the request scope ends. Fix: Ensure `DbContext` is registered as `Scoped` and never accessed outside the scope (e.g., in a Singleton background service). Use `UseDbContext` pattern or `IDbContextFactory` for background tasks.

DN10 — `record` is immutable by default, uses structural equality, and generates `Equals/GetHashCode`. `class` is mutable and uses reference equality. `record struct` is a value-type record. Choose `record` for DTOs/Entities; `record struct` for small value objects (e.g., Point).

DN11 — `ref`: pass-by-reference (read/write), `out`: pass-by-reference (write only), `in`: pass-by-reference (read only). Use `ref` for modifying large structs; `out` for returning multiple values; `in` for passing large structs without copying.

DN12 — Nullable Reference Types (`string?`) are compile-time annotations to detect null risks. Nullable Value Types (`int?`) are value types that can hold `null` (equivalent to `Nullable<int>`). `string?` requires `#nullable enable` and affects nullability analysis.

DN13 — LINQ is Language Integrated Query. Method syntax is more concise; query syntax is more readable for complex chains. Deferred execution means the query isn't executed until the result is enumerated (e.g., `ToList()`).

DN14 — Constraints limit generic type arguments. `class`: reference types; `struct`: value types; `new()`: allows `new T()`; `IComparable<T>`: enables sorting. Combine constraints (e.g., `where T : class, IComparable<T>`) to enforce multiple rules.

DN15 — Abstract classes can have state and multiple inheritance (via interfaces); interfaces define contracts. Default interface methods (C# 8+) allow interfaces to have implementation, blurring the line. Use abstract classes for shared state/behavior; interfaces for contracts.

DN16 — Middleware processes requests sequentially. `Use()` adds to the pipeline; `Map()` branches the pipeline (prefix-based); `Run()` executes immediately. Ordering matters (first in, first out). Exception handling middleware wraps the pipeline to catch and log errors.

DN17 — `Channel<T>` is a bounded, high-performance queue with built-in backpressure. `BlockingCollection<T>` wraps a `ConcurrentQueue` and blocks on take/put. Use `Channel<T>` for producer-consumer patterns with backpressure (e.g., `Channel.CreateBounded<T>(100)`).

DN18 — Source Generators run at compile-time to generate code. They differ from reflection (runtime) and IL weaving (post-build). Incremental generators only regenerate code for changed files, improving build times. Preferred over `ISourceGenerator` (non-incremental) for large projects.

DN19 — TPL Dataflow provides a graph-based pipeline. `ActionBlock` (sink), `TransformBlock` (process), `BufferBlock` (buffer). Compare to `Channels`: Dataflow is higher-level (graph), Channels are lower-level (queues). Use Dataflow for complex dependency graphs; Channels for simple producer-consumer.

DN20 — Minimal APIs are lightweight, declarative endpoints. Controllers offer structure (models, views, routing). Minimal APIs have less boilerplate but can be harder to test in isolation. OpenAPI is supported for both. Route groups organize endpoints; endpoint filters handle cross-cutting concerns (e.g., auth).

P1 — Lists are mutable sequences; tuples are immutable. Sets are mutable unordered collections; frozensets are immutable. Use tuples for returning multiple values; sets for uniqueness checks.

P2 — The GIL prevents multiple threads from executing Python bytecode simultaneously. It affects CPU-bound workloads (no speedup with threads). Workarounds: `multiprocessing` (separate processes), C extensions, or using async I/O for I/O-bound tasks.

P3 — `copy` creates a shallow copy (nested objects are references); `deepcopy` creates a deep copy (nested objects are copied). Shallow copy fails if nested objects are modified (e.g., `a[0] = 5` affects `b[0]`).

P4 — Decorators wrap functions. Example:
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start:.2f}s")
        return result
    return wrapper
```

P5 — Generators use `yield` to return values lazily (one at a time), saving memory. `yield from` delegates to another generator. Prefer generators for large datasets; lists for small, random-access data.

P6 — `asyncio.run()` starts the event loop. `gather()` runs coroutines concurrently. `create_task()` schedules a coroutine. `time.sleep()` blocks the thread; use `await asyncio.sleep()` to yield control to the event loop.

P7 — Python uses C3 Linearization for MRO. `D(B, C)` inherits `B` then `C`. `B` inherits `A`. `C` overrides `A`. MRO: `D -> B -> C -> A`. `who` is found in `C`. Output: `C`.

P8 — Metaclasses control class creation. `__init_subclass__` is a simpler hook for class creation logic. Use metaclasses for complex class manipulation (e.g., ORM models); use `__init_subclass__` for simple validation or registration.

P9 — `multiprocessing` uses separate processes (bypasses GIL); `threading` uses threads (GIL limited); `concurrent.futures` abstracts both. Multiprocessing requires pickling (serialization) of objects. Use multiprocessing for CPU-bound; threading for I/O-bound.

P10 — `__slots__` restricts dynamic attribute creation to save memory. Prevents `__dict__` overhead. Use for classes with many instances (e.g., game objects). Prevents adding new attributes dynamically.

P11 — Virtual environments isolate dependencies. `venv` is built-in; `virtualenv` is a wrapper; `conda` manages environments + packages (binary dependencies). Use `venv` for standard Python projects.

P12 — Comprehensions are concise syntax for loops. `map()` applies a function; `filter()` filters items. Prefer comprehensions for readability; `map/filter` for functional style or when using external libraries.

P13 — `==` checks value equality; `is` checks identity (same object). Integers are interned (cached) for small values (-5 to 256), so `is` returns True for them. Use `==` for value comparison.

P14 — `*args` collects positional args; `**kwargs` collects keyword args. `/` marks positional-only parameters; `*` marks keyword-only parameters. Use positional-only for internal APIs; keyword-only for clarity.

P15 — Context managers manage resources (e.g., files). `__enter__`/`__exit__` is low-level; `@contextmanager` (from `contextlib`) is higher-level. Use `@contextmanager` for simple logic (e.g., `with open(...) as f:`).

P16 — Type hinting enables static analysis. `Union` (multiple types), `Optional` (Union with None), `Literal` (specific values), `TypeVar` (generic types), `Protocol` (structural typing). Tools like `mypy` check types at runtime.

P17 — `__repr__` for debugging; `__str__` for users. `__eq__` defines equality; `__hash__` defines hashability. Defining `__eq__` without `__hash__` makes the object unhashable (cannot be in a set/dict).

P18 — Descriptors manage attribute access. `property` uses descriptors for getters/setters. `classmethod`/`staticmethod` use descriptors to bind methods. Descriptors allow customizing attribute behavior (e.g., validation).

P19 — Imports locate modules. Relative imports use `.`; absolute use full path. `sys.path` controls search order. `__init__.py` makes a directory a package. Finders locate modules; loaders load code. Namespace packages allow distributed packages.

P20 — `dataclasses` reduce boilerplate for data structures. `attrs` is faster/more flexible. `Pydantic` adds validation/serialization. Use `__post_init__` for initialization logic. Choose Pydantic for APIs/serialization; dataclasses for internal data models.
