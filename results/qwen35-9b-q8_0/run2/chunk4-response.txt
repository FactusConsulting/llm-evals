G1 — Easy: A slice is a descriptor (pointer, length, capacity) referencing an underlying array; an array is a fixed-size value type. When appending to a full slice, Go allocates a new underlying array (typically double the capacity), copies the existing elements, and returns a new slice descriptor.

G2 — Easy: `var x int` declares `x` with a zero value; `x := 0` declares and initializes `x`. You cannot use `:=` if the variable is already declared in the current scope. Historically, `:=` was not allowed at package level (outside functions), though Go 1.22+ permits it.

G3 — Medium: A goroutine is a lightweight user-space thread managed by the Go runtime; an OS thread is kernel-managed. The GMP model (Goroutine, Machine, Processor) allows the scheduler to multiplex thousands of goroutines onto a smaller pool of OS threads and processors.

G4 — Medium: Channels are typed conduits for communication. Unbuffered channels block on both send and receive until the other side is ready. Buffered channels block on send only if full. Sending to a full buffered channel blocks until space is available.

G5 — Medium: The `context` package manages cancellation, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
resp, err := http.Get(ctx, "https://example.com")
```

G6 — Medium: Go uses implicit interface satisfaction (duck typing); Java/C# require explicit interface declaration. `interface{}` (or `any`) holds any type, enabling generics and JSON marshaling, but sacrifices type safety and incurs runtime type checks.

G7 — Hard: This is unsafe due to a data race. `ready` is not atomic, so the main goroutine may read `false` after the worker writes `true` but before memory visibility is guaranteed. Use `sync/atomic` for `ready` or `sync.Mutex` to ensure visibility and atomicity.

G8 — Medium: `sync.Mutex` allows only one lock; `sync.RWMutex` allows multiple readers or one writer. `sync.Map` optimizes read-heavy workloads by avoiding locks for reads, but has higher write overhead. Regular maps with mutexes are better for write-heavy or complex logic.

G9 — Medium: Go modules manage dependencies. `go.mod` defines the module path and requirements; `go.sum` stores checksums for security. `go mod tidy` cleans unused dependencies. The Minimum Version Selection (MVS) algorithm picks the lowest version satisfying constraints.

G10 — Medium: `defer` schedules a function to run after the current function returns. Multiple defers execute in LIFO (Last-In, First-Out) order. In a loop, defers capture the loop variable by reference, causing all to use the final value.

G11 — Easy: A pointer holds a memory address. The zero value is `nil`. Create a pointer to a struct literal with `&Struct{}`.

G12 — Medium: `init()` runs before `main` to initialize package-level variables. A package can have multiple `init()` functions (one per file). They execute in file order, then package order.

G13 — Easy: `make` allocates slices, maps, and channels (zero-initialized). `new` allocates any type, zero-initializes it, and returns a pointer.

G14 — Easy: Errors implement the `error` interface (`Error() string`). The idiomatic check is `if err != nil`. `errors.Is` checks for wrapped errors; `errors.As` performs type assertion on wrapped errors.

G15 — Easy: Built-in composites are map, slice, channel, and struct. Zero values: map `nil`, slice `nil`, channel `nil`, struct zero values (0, false, empty string).

G16 — Medium: A race condition occurs when concurrent goroutines access shared memory without synchronization. The `-race` flag uses ThreadSanitizer to detect unsynchronized access. Fix with `sync.Mutex` or channels.
```go
var mu sync.Mutex
mu.Lock()
// critical section
mu.Unlock()
```

G17 — Medium: `select` handles multiple channel operations like a switch on channels. If multiple cases are ready, one is chosen randomly. Use `select` with `time.After` to implement timeouts.

G18 — Hard: Escape analysis determines if a variable escapes the stack to the heap. The compiler decides based on usage (e.g., returning a pointer). Use `go build -gcflags="-m"` to inspect. It matters for GC pressure and performance.

G19 — Hard: `reflect.Type` represents static type information; `reflect.Value` represents dynamic values. Reflection is slow due to runtime overhead. It is justified for serialization, dynamic dispatch, or code generation.

G20 — Hard: `go:embed` embeds files at compile time. It supports single files, directories, and `io/fs.FS`. Limitations: files must be in the package directory, and it is compile-time only.

R1 — Easy: Ownership ensures memory safety. Rules: 1. Each value has one owner. 2. Move ownership on copy. 3. Borrowing rules prevent data races.

R2 — Easy: `String` is an owned heap-allocated string; `&str` is a borrowed slice of UTF-8 bytes. Use `String` for ownership/creation; use `&str` for borrowing/reading.

R3 — Medium: Borrowing allows temporary access without ownership. `&T` allows immutable access; `&mut T` allows mutable access. You cannot have multiple `&mut T` references to the same data.

R4 — Medium: `Result<T, E>` handles errors; `Option<T>` handles nulls. The `?` operator propagates errors.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)?
}
```

R5 — Medium: `Box<T>` is a heap-allocated pointer (single owner). `Rc<T>` is a thread-local reference count. `Arc<T>` is a thread-safe reference count. Use `Arc` for shared ownership across threads.

R6 — Medium: Traits define behavior; Go interfaces are implicit. `dyn Trait` (trait objects) enable polymorphism at runtime. Generics with trait bounds (`T: Trait`) enable compile-time polymorphism.

R7 — Hard: This fails because the compiler cannot determine which reference (`x` or `y`) lives longer. Fix by adding a lifetime parameter:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — Hard: `Send` allows transfer across threads; `Sync` allows shared access. `Rc<T>` is not `Send` because its reference count is not atomic. `Arc<T>` uses atomic reference counting, making it `Send` and `Sync`.

R9 — Hard: Rust's `async/await` compiles to state machines (Futures). An executor (e.g., Tokio) drives these futures. Unlike Go's goroutines, Rust's async is cooperative and non-blocking by design.

R10 — Medium: `unsafe` blocks allow pointer arithmetic, raw pointers, and FFI. They are justified for performance-critical code or interfacing with C, but must be minimized.

R11 — Easy: Pattern matching exhaustively covers all cases. `match` enforces exhaustiveness; `if let` is a shorthand for a single pattern.

R12 — Easy: `Vec<T>` is a dynamic array; `[T; N]` is a fixed-size array. `Vec` reallocates and copies/moves elements when capacity is exceeded.

R13 — Easy: Enums are algebraic data types. C/Java enums are integers; Rust enums are distinct types. `Option<T>` is `Some(T)` or `None`, eliminating nulls.

R14 — Easy: `impl` defines methods. `&self` borrows immutably; `&mut self` borrows mutably; `self` consumes. Associated functions (e.g., `String::new()`) take no `self`.

R15 — Easy: Derive macros generate trait implementations. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if the struct has private fields (for some traits) or complex dependencies.

R16 — Medium: `Cow<'a, T>` (Clone-on-Write) borrows if immutable, clones if mutable. It avoids unnecessary allocations when the data is read-only.
```rust
let cow = Cow::Borrowed("hello");
let mut cow = Cow::Owned("hello".to_string());
```

R17 — Medium: `mod` defines modules; `use` imports; `pub` exposes. 2018 edition maps filenames to module paths (e.g., `mod.rs` in `src/mod`).

R18 — Hard: `Pin<T>` prevents a value from being moved. It is needed for async/await to ensure futures remain at a stable memory address. `Unpin` allows moving.

R19 — Hard: `macro_rules!` are declarative; procedural macros (derive, attribute) manipulate ASTs. Hygiene rules prevent macro-generated names from colliding with outer scope.

R20 — Hard: Zero-cost abstractions compile to efficient machine code. Generics monomorphize; iterators compile to loops; traits compile to vtables or direct calls, matching C performance.
