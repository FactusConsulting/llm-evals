G1 — Easy: Arrays are fixed-size, value types stored on the stack (or heap if large). Slices are dynamic views into an underlying array, storing a pointer, length, and capacity. When appending to a slice at capacity, Go allocates a new backing array (typically 1.5x growth), copies elements, and updates the slice header.

G2 — Easy: `var x int` declares `x` with a zero value (0). `x := 0` declares and initializes `x`. `:=` cannot be used if the variable is already declared in the current scope, or in function bodies where the variable already exists. It is also not allowed in `main` if the variable is already defined.

G3 — Medium: A goroutine is a lightweight user-space thread managed by the Go runtime. OS threads are heavier and managed by the kernel. The GMP model consists of G (goroutine), M (machine/OS thread), and P (processor). The scheduler multiplexes Gs onto Ps, which run on Ms, allowing thousands of goroutines to run on fewer OS threads.

G4 — Medium: Channels are typed conduits for communication. Unbuffered channels block the sender until a receiver is ready. Buffered channels hold up to `N` values; senders block only if full. Sending to a full buffered channel blocks until space is available or the channel is closed.

G5 — Medium: The `context` package manages request-scoped values, cancellation, and deadlines.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
resp, err := client.Get(ctx, url)
```
This ensures the request stops if it exceeds 5 seconds.

G6 — Medium: Go uses implicit interface satisfaction (duck typing); Java/C# require explicit implementation. `interface{}` (or `any`) accepts any type, enabling generic-like behavior, but is dangerous due to runtime type assertions and potential panics.

G7 — Hard: This is unsafe due to data races and memory reordering. `ready` and `data` are not atomic. The compiler may reorder writes, or the main thread may read `data` before `ready` is set. Correct alternatives: use `sync.Mutex` to protect writes, or `sync/atomic` for simple flags, or channels to signal readiness.

G8 — Hard: `sync.Mutex` allows exclusive access. `sync.RWMutex` allows multiple concurrent readers but exclusive writers. `sync.Map` is optimized for high-concurrency read-heavy workloads (hash table with specific locking), but has higher write overhead than a `map` with a `Mutex`.

G9 — Hard: `go.mod` defines the module path and dependencies. `go.sum` stores checksums for security. `go mod tidy` cleans up unused dependencies and ensures versions match constraints. MVS (Minimum Version Selection) picks the lowest version satisfying all constraints to ensure stability.

G10 — Medium: `defer` schedules a function to run after the current function returns. Multiple defers execute in LIFO (Last-In, First-Out) order. Gotcha: Defers capture loop variables by reference, so all defers in a loop may use the final loop value unless a new variable is created.

G11 — Easy: A pointer stores a memory address. The zero value is `nil`. Create a pointer to a struct literal with `&Struct{}`.

G12 — Medium: `init()` runs before `main()`. A package can have multiple `init()` functions (one per file). They execute in file order, then function order within each file.

G13 — Easy: `make` allocates and initializes slices, maps, and channels. `new` allocates zeroed memory and returns a pointer (`*T`). `make` works only for slices/maps/channels; `new` works for any type.

G14 — Easy: Errors are values implementing the `error` interface (`Error() string`). Idiomatic check: `if err != nil`. `errors.Is` checks for wrapped errors (e.g., `os.ErrNotExist`). `errors.As` type asserts to a specific error type.

G15 — Easy: Map (key-value), Slice (ordered list), Channel (communication), Struct (named fields). Zero values: `nil` (map, channel), empty slice, zero struct.

G16 — Medium: A race condition occurs when concurrent access to shared data lacks synchronization. The `-race` flag uses ThreadSanitizer to detect unsynchronized reads/writes. Fix: Protect with `sync.Mutex` or synchronize via channels.

G17 — Medium: `select` multiplexes channel operations. Like a switch on channels. If multiple cases are ready, one is chosen randomly. Timeout: `case <-time.After(d)`.

G18 — Hard: Escape analysis determines if a variable escapes the stack frame. If it does (e.g., stored in a map or returned), it goes to the heap. Inspect with `go build -gcflags="-m"`. It matters for GC overhead and memory locality.

G19 — Hard: `reflect.Type` describes a type; `reflect.Value` holds the data. Reflection is slow due to dynamic dispatch. Justified for dynamic code generation or generic libraries; avoided in performance-critical paths.

G20 — Hard: `go:embed` embeds files at compile time. Supports files, directories, and `io/fs.FS`. Limitations: paths must be static; cannot embed runtime-generated content. Interacts with `io/fs.FS` by embedding the FS interface.

R1 — Easy: Ownership ensures memory safety. Rules: 1. Each value has one owner. 2. Move ownership on copy. 3. Borrowing (`&`) allows read-only access; `&mut` allows mutation but no aliasing.

R2 — Easy: `String` is an owned heap buffer. `&str` is a borrowed slice. Use `String` for owned data (returning from functions). Use `&str` for function arguments to avoid unnecessary copies.

R3 — Medium: Borrowing rules prevent data races. You can have multiple `&T` references, but only one `&mut T`. You cannot have a `&mut T` and a `&T` simultaneously.

R4 — Medium: `Result<T, E>` handles errors explicitly. `Option<T>` handles absence. `?` propagates errors.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let mut file = std::fs::File::open(path)?;
    let mut contents = String::new();
    file.read_to_string(&mut contents)?;
    Ok(contents)
}
```

R5 — Medium: `Box<T>` is a single-owner heap pointer. `Rc<T>` is reference-counted (single thread). `Arc<T>` is atomic reference-counted (multi-thread). Use `Box` for trees, `Rc` for single-threaded sharing, `Arc` for concurrent sharing.

R6 — Medium: Traits define behavior. `dyn Trait` enables dynamic dispatch (vtable). `T: Trait` enables static dispatch (monomorphization). Static dispatch is faster; dynamic is flexible.

R7 — Hard: Fails because the compiler cannot determine which reference (`x` or `y`) lives longer. Fix: Return `String` (owned) or add lifetime annotations: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

R8 — Hard: `Send` allows transfer across threads; `Sync` allows shared access. `Rc<T>` is not `Send` because ref counts are not atomic. `Arc<T>` is `Send` + `Sync` because it uses atomic operations for ref counting.

R9 — Hard: `async/await` compiles to state machines implementing `Future`. An executor (Tokio) polls these futures. Unlike Go's preemptive goroutines, Rust's async is cooperative and non-blocking, relying on the executor to drive progress.

R10 — Medium: `unsafe` blocks allow pointer casting, raw pointers, and FFI. Justified for performance-critical code, FFI, or when interacting with unsafe external libraries.

R11 — Easy: `match` is exhaustive; `if let` is partial. The compiler enforces that all enum variants are handled in `match`.

R12 — Easy: `Vec<T>` is dynamic; `[T; N]` is fixed. `Vec` reallocates when capacity is exceeded (typically 1.5x growth strategy).

R13 — Easy: Enums are tagged unions. `Option<T>` is `None | Some(T)`. Rust avoids nulls to prevent null pointer dereferences; use `Option` instead.

R14 — Easy: `impl` defines methods. `&self` borrows immutably; `&mut self` borrows mutably; `self` takes ownership. Associated functions (`fn`) do not take `self`.

R15 — Easy: Derive macros generate code (e.g., `#[derive(Debug)]`). Cannot derive if fields don't implement the trait (e.g., `Clone` on a type without `Clone`).

R16 — Medium: `Cow<'a, T>` clones only if mutation is required. Useful for string processing: borrow if immutable, clone if mutable, avoiding unnecessary heap allocations.

R17 — Medium: `mod` defines a module; `use` imports; `pub` exposes. File system maps to modules (e.g., `mod.rs`). 2018 edition improved module resolution and allowed `mod` in `lib.rs`.

R18 — Hard: `Pin<T>` prevents a value from being moved. Needed for async to ensure self-referential structs (e.g., `&mut self` inside a future) remain valid. `Unpin` allows moving.

R19 — Hard: `macro_rules!` are declarative (hygienic). Procedural macros (derive, attribute) are functions generating code. Hygiene prevents macro-generated names from clashing with outer scope.

R20 — Hard: Zero-cost abstractions compile to efficient machine code. Generics monomorphize (compile per type). Iterators are lazy. Traits compile to vtables or direct calls, incurring no runtime overhead compared to hand-written C.
