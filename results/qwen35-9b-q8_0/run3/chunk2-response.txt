K1 — Deployment manages stateless applications and scales pods independently. StatefulSet manages stateful applications, providing stable network IDs, persistent storage, and ordered deployment/termination.

K2 — A ClusterIP Service creates a virtual IP within the cluster. kube-proxy updates iptables (or IPVS) rules to forward traffic from the Service IP to the IP addresses listed in the Service's Endpoints object.

K3 — A PersistentVolume (PV) is a cluster-wide storage resource. A PersistentVolumeClaim (PVC) is a request for storage resources. A StorageClass defines the provisioner and parameters for dynamically creating PVs when a PVC is created.

K4 — 1. Check `kubectl logs <pod>` for application errors. 2. Check `kubectl describe pod <pod>` for Events (CrashLoopBackOff reasons). 3. Verify Liveness/Readiness probe configurations. 4. Check resource limits (CPU/Memory) against node capacity.

K5 — CoreDNS runs as a Service to handle internal DNS queries (e.g., `my-pod.default.svc.cluster.local`). If CoreDNS pods are down, internal service discovery fails, and pods cannot resolve other services or the cluster API server.

K6 — The scheduler first **filters** nodes (must have resources, no taints). Then it **scores** remaining nodes based on factors like Node Affinity, Pod Topology Spread, and Local Storage. Finally, it selects the node with the highest score.

K7 — Yes, it will be scheduled because the request (256Mi) is less than available memory (3.5GB). However, if it uses 600Mi at runtime, it exceeds the limit (512Mi), triggering an OOMKilled event.

K8 — External LB receives traffic -> Ingress Controller (NGINX) parses rules -> Routes to Service ClusterIP -> kube-proxy updates iptables -> Traffic forwarded to Pod IP via Endpoints -> Application receives request.

K9 — A NetworkPolicy restricts network traffic. By default, if no policy exists, all ingress and egress traffic is **allowed**. When a policy is applied, it defaults to **deny** traffic not explicitly allowed by the rules.

K10 — RollingUpdate updates pods gradually (zero downtime). Recreate kills all pods before starting new ones. Choose Recreate for stateful applications (e.g., databases) where downtime is acceptable or required.

K11 — A namespace is a virtual cluster within a cluster for resource isolation. Default namespaces are `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

K12 — It shows detailed status, conditions, and events. Three pieces of info not in `get`: 1. Events (reasons for state changes), 2. Node name/IP, 3. Container restart counts.

K13 — A ConfigMap stores non-confidential configuration data. Pods consume it via: 1. Environment variables, 2. Mounting as a volume (files).

K14 — ClusterIP: Internal cluster access only. NodePort: Exposes service on a static port on each node. LoadBalancer: Provisions an external cloud load balancer.

K15 — A DaemonSet ensures a copy of a Pod runs on every node. Use it for system-level tasks like logging agents (Fluentd), monitoring (Prometheus Node Exporter), or network plugins.

K16 — Taints repel pods; Tolerations allow specific pods to ignore taints. Node Affinity is a soft/hard preference for node selection. Use Taints for GPU nodes; use Affinity for placing pods in specific zones.

K17 — An Operator is a custom controller that encapsulates the logic to manage an application's lifecycle (install, upgrade, backup). It solves complex stateful management problems that standard Deployments cannot handle.

K18 — Kubernetes uses Raft consensus for etcd. If quorum is lost (e.g., 2/3 nodes down), the cluster becomes unavailable. Recovery requires restoring etcd from a snapshot on a healthy node and rejoining the cluster.

K19 — Role/ClusterRole defines permissions. RoleBinding/ClusterRoleBinding links permissions to subjects.
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: default
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods
  namespace: default
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

K20 — `ndots` defines how many dots must precede a domain to be treated as a fully qualified domain name (FQDN). If low (default 1), short names trigger many queries. Fix: Add `dnsConfig: { options: { ndots: 1 } }` to the pod spec.

D1 — Rebase rewrites history to make it linear; Merge preserves history with a merge commit. Avoid rebasing on shared branches (public history) to prevent confusion for others.

D2 — TCP is connection-oriented, reliable, ordered (HTTP, SSH). UDP is connectionless, unreliable, fast (DNS, VoIP).

D3 — A race condition occurs when the outcome depends on the timing of concurrent events. Example: Two threads incrementing a shared counter simultaneously without locks, resulting in lost updates.

D4 — Symmetric uses one shared key (fast). Asymmetric uses public/private keys (secure key exchange). TLS uses Asymmetric to exchange a session key, then Symmetric for data encryption.

D5 — A layer is a read-only filesystem snapshot. Layer caching speeds up builds by reusing unchanged layers. Best practice: Combine commands to minimize layers (e.g., `RUN apt-get update && apt-get install -y ...`).

D6 — 1. Check application logs for errors. 2. Verify health check endpoint status. 3. Check database connectivity/latency. 4. Review recent configuration changes or resource limits.

D7 — CAP theorem states a system can only guarantee 2 of 3: Consistency, Availability, Partition Tolerance. CP: Zookeeper (strong consistency). AP: DynamoDB (eventual consistency).

D8 — Horizontal adds more instances (stateless). Vertical upgrades CPU/RAM (stateful). Horizontal scaling requires stateless architecture and load balancing.

D9 — An environment variable is a key-value pair. To persist across sessions on Linux, use `export VAR=value` in the shell or add it to `.bashrc`/`.zshrc`.

D10 — JSON is a data interchange format (strict, machine-readable). YAML is a human-readable config format (indentation-based). JSON advantage: strict validation. YAML advantage: readability.

D11 — REST uses HTTP methods to manipulate resources. GET (retrieve), POST (create), PUT (replace/update), DELETE (remove).

D12 — Version pinning locks dependencies to a specific version. It ensures builds are reproducible and prevents unexpected breaking changes from upstream updates.

D13 — Compiled languages translate source to binary before execution (C++, Rust). Interpreted languages translate source to machine code at runtime (Python, JavaScript).

D14 — Reverse proxy sits in front of servers (Nginx, HAProxy). Forward proxy sits in front of clients. Use Reverse for load balancing/SSL termination; Forward for bypassing firewalls.

D15 — A deadlock occurs when processes wait indefinitely for each other. Conditions: Mutual Exclusion, Hold and Wait, No Preemption, Circular Wait.

D16 — Eventual consistency means data converges over time. Cassandra uses consistency levels (ONE, QUORUM, ALL) to tune trade-offs between speed and data accuracy during reads/writes.

D17 — mTLS authenticates both client and server using certificates. Handshake: Client sends cert -> Server verifies -> Server sends cert -> Client verifies -> Secure channel established. Used in Service Mesh (Istio).

D18 — Hash table maps keys to indices. Chaining uses linked lists at buckets; Open Addressing probes for empty slots. Average O(1), Worst O(n) for all operations.

D19 — Circuit Breaker stops calls to a failing service. Closed (normal), Open (fail fast), Half-Open (test recovery). Prevents cascade failures by stopping traffic to unhealthy services.

D20 — Optimistic assumes no conflict (check version on write). Pessimistic locks rows before access. Choose Optimistic for high concurrency reads; Pessimistic for critical data integrity (e.g., `SELECT FOR UPDATE`).
