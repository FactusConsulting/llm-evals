## .NET / C# (20 questions)

**DN1**
Classes are reference types (allocated on the heap); structs are value types (allocated on the stack or inline in another object). Structs are copied by value, classes by reference. Use structs for small, immutable data structures (e.g., coordinates, enums) to avoid heap allocation overhead and improve cache locality. Avoid structs for large objects or objects with many references.

**DN2**
`IEnumerable<T>` represents a sequence and executes immediately (or lazily in memory). `IQueryable<T>` represents a query that is translated into a provider-specific language (e.g., SQL) and deferred until enumeration. This distinction matters for databases because `IQueryable` allows the LINQ provider to push the query logic to the database, whereas `IEnumerable` forces data retrieval into memory before filtering.

**DN3**
`async/await` uses a state machine to suspend execution without blocking a thread. `Task` is a reference type (allocates memory); `ValueTask` is a struct that avoids allocation if the result is already available (e.g., synchronous completion). Use `ValueTask` for I/O-bound operations where the result is often ready immediately (e.g., `ReadValue`), reducing GC pressure.

**DN4**
Dependency Injection (DI) allows external classes to provide dependencies, promoting loose coupling. Lifetimes: `Transient` (new instance per request), `Scoped` (new instance per request scope, e.g., HTTP request), `Singleton` (one instance per app lifetime). **Bug:** Injecting a `Scoped` service into a `Singleton`. The `Singleton` lives for the app lifetime, but the `Scoped` service is disposed when the request ends. Accessing the `Scoped` service later throws `ObjectDisposedException`.

**DN5**
`string` is an immutable reference type backed by a char array. `ReadOnlySpan<char>` is a zero-cost view over memory (stack or heap) without copying. Use `Span<T>` (or `ReadOnlySpan<T>`) for high-performance string processing to avoid allocations and copying, especially in tight loops or when working with unmanaged memory.

**DN6**
The GC uses a generational approach: Gen 0 (short-lived), Gen 1 (medium-lived), Gen 2 (long-lived). Objects are promoted upon survival. The Large Object Heap (LOH) stores objects >85KB. `IDisposable` is needed for deterministic cleanup of unmanaged resources (files, DB connections) because the GC is non-deterministic and cannot free unmanaged memory immediately.

**DN7**
`ConfigureAwait(false)` tells the awaiter not to capture the current `SynchronizationContext`. Default behavior captures it to resume on the original context (e.g., UI thread). Use `ConfigureAwait(false)` in library code to avoid deadlocks in high-concurrency scenarios. Do NOT use it in UI code (WinForms/WPF) where the context is required to update the UI.

**DN8**
*   **Primary Constructors:** C# 12 feature allowing constructor parameters in the class declaration (`class Person(string name) { ... }`).
*   **Collection Expressions:** C# 12 feature for creating collections (`var list = [1, 2, 3];`).
*   **FrozenDictionary:** Immutable dictionary introduced in .NET 8.
*   **Example:**
    ```csharp
    public class MyService(string name) : IMyService {
        public string Name { get; } = name;
    }
    // DI Registration
    builder.Services.AddSingleton<IMyService, MyService>();
    ```

**DN9**
**Cause:** `DbContext` is registered as `Scoped`. If injected into a `Singleton`, the `Singleton` holds the reference. When the request ends, the `Scoped` service is disposed. If the `Singleton` is accessed later (e.g., in a background task or subsequent request), it throws `ObjectDisposedException`.
**Fix:** Do not inject `Scoped` services into `Singleton`. Instead, inject `IServiceScopeFactory` into the `Singleton` to create scopes on demand, or ensure the `Singleton` is not accessed outside the request scope.

**DN10**
`record` is an immutable reference type with value semantics (equality based on content). `record struct` is an immutable value type. Use `record` for DTOs and immutable reference data. Use `record struct` for small, value-based data (e.g., `Point`, `Rect`) to avoid heap allocation.

**DN11**
`ref`: Pass by reference (allows modification). `out`: Pass by reference (must be assigned before return). `in`: Pass by reference (read-only, prevents modification). Use `ref` for large structs to avoid copying. Use `out` for initialization. Use `in` for large structs that should not be modified.

**DN12**
Nullable Reference Types (`string?`) are a compile-time feature to track nullability. `#nullable enable` activates it. Nullable Value Types (`int?`) are value types that can hold `null` (equivalent to `Nullable<int>`). Reference types are null by default; value types are not (unless boxed).

**DN13**
LINQ is Language Integrated Query. Method syntax is fluent (`list.Where(...)`). Query syntax is SQL-like (`from x in list where ...`). Deferred execution means the query is not executed until the result is enumerated (e.g., `ToList()`).

**DN14**
Generic constraints limit the types `T` can be. `class`: Reference type. `struct`: Value type. `new()`: Parameterless constructor exists. `IComparable<T>`: Implements interface. Combine constraints using commas (e.g., `where T : class, IComparable<T>`).

**DN15**
Abstract classes can have state and single inheritance. Interfaces define behavior only (multiple inheritance). Default interface methods (C# 8+) allow interfaces to provide implementation, reducing the need for abstract classes for shared behavior.

**DN16**
Middleware pipeline processes requests sequentially. `app.Use()` adds middleware to all requests. `app.Map()` adds middleware to specific routes (sub-applications). `app.Run()` adds terminal middleware. Ordering matters: earlier middleware runs first. Exception handling middleware wraps the pipeline to catch unhandled exceptions.

**DN17**
`Channel<T>` is an async, bounded buffer supporting backpressure. `BlockingCollection<T>` is a sync collection wrapping a `ConcurrentQueue`. Use `Channel<T>` for high-performance producer-consumer patterns with backpressure. Example: `Channel.CreateBounded<int>(100)` limits queue size, blocking producers if full.

**DN18**
Source Generators compile-time code generation. Reflection is runtime inspection. IL Weaving modifies IL at build time. Incremental generators only run when source changes, making them faster than `ISourceGenerator` (which runs every build). Preferred for performance and incremental builds.

**DN19**
TPL Dataflow (`ActionBlock`, `TransformBlock`, `BufferBlock`) creates a graph of blocks for complex pipelines. `System.Threading.Channels` is a linear producer-consumer buffer. Use Dataflow for complex, branching pipelines; use Channels for simple, linear pipelines.

**DN20**
Minimal APIs are lightweight endpoints defined via `app.MapGet()`. Controllers use MVC pattern with routing and DI. Minimal APIs are faster to write but harder to test (less mocking). Controllers have better OpenAPI support and middleware integration. Route groups organize endpoints; endpoint filters apply logic to specific endpoints.

## Python (20 questions)

**P1**
Lists are mutable sequences; tuples are immutable. Sets are mutable unordered collections; frozensets are immutable. Use tuples for fixed data (e.g., coordinates). Use frozensets for set operations where immutability is required (e.g., dictionary keys).

**P2**
The GIL (Global Interpreter Lock) ensures only one thread executes Python bytecode at a time. It affects CPU-bound workloads (no speedup with threads). Workarounds: `multiprocessing` (bypasses GIL), C-extensions (e.g., NumPy), or `asyncio` for I/O-bound tasks.

**P3**
`copy` creates a shallow copy (nested objects are references). `deepcopy` creates a deep copy (nested objects are copied). Example: `a = [[1]]; b = copy.copy(a); b[0][0] = 2; print(a)` prints `[[2]]` because `a` and `b` share the inner list.

**P4**
Decorators wrap functions to add behavior.
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start:.2f}s")
        return result
    return wrapper
```

**P5**
Generators use `yield` to pause execution and return values lazily. They differ from lists by not storing all values in memory. `yield from` delegates to another iterable (e.g., `yield from range(10)`).

**P6**
`asyncio` event loop manages async tasks. `asyncio.run()` starts the loop. `asyncio.gather()` waits for all tasks. `asyncio.create_task()` schedules a task. `time.sleep()` blocks the event loop; use `await asyncio.sleep()` instead.

**P7**
MRO (Method Resolution Order) uses C3 Linearization. For `D(B, C)` where `B(A)` and `C(A)`: MRO is `[D, B, C, A]`. `who()` is found in `C` first. Output: `"C"`.

**P8**
Metaclasses control class creation. `__init_subclass__` is a hook called when a subclass is defined (Python 3.6+). Use `__init_subclass__` for simple hooks; use metaclasses for complex class creation logic (e.g., ORM models).

**P9**
`multiprocessing` spawns new processes (bypasses GIL, uses pickling). `threading` shares memory (GIL applies). `concurrent.futures` abstracts both. Multiprocessing requires pickling objects to send between processes.

**P10**
`__slots__` restricts instance attributes to a fixed set. Prevents dynamic attribute creation and saves memory (no `__dict__`). Use for memory-constrained applications (e.g., large datasets).

**P11**
Virtual environments isolate dependencies. `venv` is built-in. `virtualenv` is a legacy third-party tool. `conda` manages packages and environments (cross-language). Use `venv` for Python-only projects.

**P12**
Comprehensions (`[x for x in list]`) are concise and faster than `map()`/`filter()`. Prefer comprehensions for readability; use `map()`/`filter()` for functional style or when chaining.

**P13**
`==` checks value equality; `is` checks identity (same object). Small integers (-5 to 256) are interned (cached), so `a is b` returns `True` for them. Large integers are not interned.

**P14**
`*args` collects positional arguments; `**kwargs` collects keyword arguments. `/` marks positional-only parameters; `*` marks keyword-only parameters.
```python
def f(a, /, b, *, c): ...
```

**P15**
Context managers manage resources (e.g., files). Use `__enter__`/`__exit__` protocol or `@contextmanager` decorator. Example:
```python
from contextlib import contextmanager
@contextmanager
def timer():
    import time
    t = time.time()
    yield
    print(time.time() - t)
```

**P16**
Type hints improve static analysis (mypy/pyright). `Union` (multiple types), `Optional` (Union with None), `Literal` (specific values), `TypeVar` (generic types), `Protocol` (structural typing).

**P17**
`__repr__` (developer representation), `__str__` (user representation). `__eq__` (value equality), `__hash__` (dict key). Defining `__eq__` without `__hash__` makes the object unhashable (cannot be a dict key).

**P18**
Descriptors manage attribute access via `__get__`, `__set__`, `__delete__`. `property` uses a descriptor to get/set values. `classmethod`/`staticmethod` are descriptors that bind to the class or instance.

**P19**
Imports load modules. Relative imports use `.`; absolute use full path. `sys.path` controls search order. `PYTHONPATH` adds directories. `__init__.py` makes a directory a package. Finders locate modules; loaders load code.

**P20**
`dataclasses` reduce boilerplate for data structures. `attrs` offers more control (validators, converters). `Pydantic` adds validation and serialization (JSON). Use Pydantic for APIs/serialization; use dataclasses for internal data models. `__post_init__` runs after initialization.
