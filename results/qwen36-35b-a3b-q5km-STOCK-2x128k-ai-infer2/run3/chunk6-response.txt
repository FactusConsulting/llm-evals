## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted with `undefined`. `let`/`const` are block-scoped, hoisted but in a Temporal Dead Zone (TDZ) until initialization. Hoisting moves declarations to the top of their scope during compilation, but initializations stay in place.

**JS2** — The event loop monitors the call stack and task queues, pushing callbacks to the stack when empty. The call stack runs sync code. Macrotask queue (`setTimeout`, I/O) and microtask queue (`Promise.then`, `queueMicrotask`) hold async callbacks. Microtasks drain completely after each stack pop, before the next macrotask runs.

**JS3** — A closure is a function that retains access to its lexical scope after the outer function returns. Example: a counter factory. Classic bug: `var i` in loops shares one reference, causing timeouts to log the final value. Fix: use `let` (block-scoped) or an IIFE to capture the current value.

**JS4** — `Promise` represents an async operation; `async/await` is syntactic sugar that pauses execution until resolution. Error handling: `try/catch` with `await`, `.catch()` with promises. `Promise.all` fails fast on first rejection; `Promise.allSettled` waits for all to complete, returning `{status, value/reason}` per promise.

**JS5** — `interface` defines object shapes, supports declaration merging/extension, and has no runtime footprint. `type` supports unions, intersections, primitives, and mapped types. Use `interface` for APIs/contracts, `type` for unions/primitives. Discriminated unions use a common literal property to narrow types in `switch`/`if` statements.

**JS6** — Prototypal inheritance delegates property lookups to an object's `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar: `class` defines a constructor, `extends` sets up prototype linkage via `Object.setPrototypeOf`, and methods live on the prototype.

**JS7** — `this` binds dynamically based on call site. Priority: 1. `new` (constructor), 2. explicit (`bind`/`call`/`apply`), 3. implicit (`obj.method()`), 4. default (global/window or `undefined` in strict mode). `bind()` returns a new function with fixed `this`; it cannot be re-bound.

**JS8** — `WeakRef` holds a weak reference that doesn't prevent GC; `FinalizationRegistry` triggers callbacks when weakly referenced objects are collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so GC can track them; when a key is collected, the entry is automatically removed.

**JS9** — V8 optimizes via hidden classes (shape tracking for fast property access), inline caching (caches hidden class lookups at call sites), and deoptimization (reverts to slower code when assumptions break). Deopt triggers: dynamic property addition, type changes, `arguments` object, `with` statement.

**JS10** — Tree-shaking eliminates unused exports at build time. Works with ES modules because imports/exports are static and analyzable at compile time. CommonJS uses dynamic `require()` evaluated at runtime, preventing static analysis and effective tree-shaking.

**JS11** — `null` is intentional absence; `undefined` is uninitialized/missing. `==` coerces (`null==undefined` is true); `===` checks type/value (false). `??` returns right operand if left is `null`/`undefined`. `?.` safely accesses nested properties without throwing on `null`/`undefined`.

**JS12** — `map` transforms, `filter` selects, `reduce` accumulates to a single value. Initial value in `reduce` prevents errors on empty arrays and sets accumulator type. `flatMap` maps then flattens one level; useful for transforming and flattening in a single pass.

**JS13** — Template literals use backticks, support interpolation `${expr}` and multi-line. Tagged templates call a function with an array of string parts and substitution values. Example: `html` tag function escapes values or builds SQL queries safely.

**JS14** — Destructuring unpacks arrays/objects into variables. Object: `{a, b: renamed} = obj`. Array: `[a, b] = arr`. Defaults: `a = 1`. Rest: `const {a, ...rest} = obj` collects remaining keys. Works in function parameters too.

**JS15** — `for...in` iterates enumerable string keys (including inherited); `for...of` iterates iterable values. Avoid `for...in` on arrays because it iterates keys, not values, includes inherited properties, and order isn't guaranteed.

**JS16** — Generics use type parameters for reusability. Constraints: `T extends SomeType`. Conditional types: `T extends U ? X : Y`. `infer`: extracts types in conditional contexts. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T`.

**JS17** — CJS (Node default historically) uses synchronous `require`/`module.exports`, supports object mutation. ESM uses static `import`/`export`, top-level await, async loading. Node supports both via `.mjs` or `"type": "module"` in `package.json`.

**JS18** — Structural typing checks compatibility by shape, not names. Excess property checks apply only to object literals assigned to variables/interfaces, not function arguments. `extends` defines type relationships; `satisfies` checks type without widening. TS 4.7+ makes function parameters strictly contravariant (`in`) by default.

**JS19** — `Proxy` wraps objects to intercept operations (`get`, `set`, `apply`, etc.); `Reflect` provides default trap behavior. Example: validation proxy checking types on assignment. Intercept via `new Proxy(target, { get(t,p){...}, set(t,p,v){...} })`.

**JS20** — `SharedArrayBuffer` enables shared memory between main thread and workers. `Atomics` provides atomic operations and synchronization. Communication: write to SAB, use `Atomics.wait` (blocks until value changes) and `Atomics.notify` (wakes threads). Guarantees sequential consistency with memory barriers.

## Bash

**B1** — `$@` preserves each argument as a separate word; `$*` joins all args into one string (using first char of IFS). `"$@"` expands to separate quoted args; `"$*"` expands to a single quoted string.

**B2** — `set -e`: exit immediately on command failure. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the last non-zero exit status, not just the last command.

**B3** — `$(command)` is preferred over `` `command` ``: supports nesting, easier to read, POSIX-compliant. `$((expression))` is arithmetic expansion. `expr` is an external command, slower, and less safe with special characters.

**B4** — Process substitution `<(command)` creates a `/dev/fd/X` file descriptor with the command's output. Used when a command expects a file argument but needs dynamic input. Example: `diff <(sort file1) <(sort file2)`.

**B5** — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` breaks on spaces/globs, fails on newlines, and parses `ls` output (violates POSIX principles).

**B6** — Here doc `<<EOF` passes multi-line input as stdin. Here string `<<<` passes a single string as stdin. `<<-EOF` strips leading tabs (not spaces) from the heredoc content for indentation.

**B7** — `cmd > file 2>&1`: stdout → file, then stderr → where stdout points (file). `cmd 2>&1 > file`: stderr → original stdout (terminal), then stdout → file (stderr goes to terminal). `cmd &> file`: redirects both to file (bash shorthand).

**B8** — ```bash
lock_dir="/tmp/myapp.lock"
cleanup() { rmdir "$lock_dir" 2>/dev/null; }
trap cleanup EXIT INT TERM
if ! mkdir "$lock_dir" 2>/dev/null; then echo "Locked"; exit 1; fi
# ... script logic ...
```
`mkdir` is atomic on POSIX filesystems, avoiding TOCTOU race conditions. `trap` ensures cleanup on normal exit or signals.

**B9** — Single quotes `'...'`: literal, no expansion. Double quotes `"..."`: allows variable/command expansion, escapes. No quotes: triggers word splitting and globbing. Example: `var="hello world"; echo $var` (splits), `echo "$var"` (one arg), `echo '$var'` (literal).

**B10** — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin: supports `&&`/`||`, regex, no word splitting/globbing on RHS. `[ ]` is POSIX `test`: stricter, requires spaces, no advanced features.

**B11** — `$?`: last exit status (error checking). `$$`: script PID (logging/locking). `$!`: last background job PID (`wait`/`kill`). `$#`: number of positional parameters (arg validation).

**B12** — `foo() { ... }` (POSIX) or `function foo { ... }` (bash-specific, prefers former). Return values: `return <int>` (exit code 0-255), or `echo`/`printf` to stdout and capture via `$()`.

**B13** — `PATH` is colon-separated dirs bash searches for executables. Resolves by checking PATH, then builtins. Builtin: compiled into shell (fast, no fork). External: separate binary (fork+exec). Check: `type cmd` or `command -v cmd`.

**B14** — `trap 'cleanup' EXIT INT TERM`. `EXIT` runs on normal/abnormal exit. `ERR` runs on command failure. Signal order: shell handles signals asynchronously; traps run sequentially when caught. Multiple signals queue or are handled sequentially depending on shell state.

**B15** — `xargs` reads stdin, batches, and executes commands; `$(cmd)` loads all into memory. `xargs -0` + `find -print0` handles spaces/newlines safely. `xargs -P N` runs N processes in parallel.

**B16** — Arrays: `arr=(a b c)`, `${arr[0]}`, `${#arr[@]}`, `for i in "${arr[@]}"; do`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${!assoc[@]}` for keys. Syntax differs; assoc requires `declare -A`.

**B17** — Subshell `(...)`: runs in child process, variable changes lost. Group `{ ...; }`: runs in current shell, variables persist. Piping to `while` creates a subshell, so `while read; do var=1; done < <(cmd)` loses `var`. Fix: use process substitution or redirect from file.

**B18** — `SIGINT` (Ctrl+C, interrupt), `SIGTERM` (graceful kill), `SIGHUP` (terminal close/reload), `SIGKILL` (uncatchable, forces kill). Graceful shutdown: trap `TERM`/`INT`, kill child processes, `wait`, cleanup. Job control: `jobs`, `fg`, `bg`, `wait`.

**B19** — `split -l 10000 log.txt log_part_`, `find . -name "log_part_*" -print0 | xargs -0 -P 4 -I {} bash -c 'process "$1"' _ {}`, merge results. Trade-offs: I/O vs CPU, splitting/merging overhead. Error propagation: check exit codes, use temp dirs, aggregate failures via `set -o pipefail` and explicit status checks.

**B20** — `exec` replaces the current shell process or manipulates file descriptors. `exec 3>file` opens FD 3, `exec 3>&-` closes it. Coprocess: `coproc cmd` creates a bidirectional pipe, used for persistent IPC between shell and external process.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline, preserving types. `Write-Host` writes directly to the console, bypassing the pipeline and breaking chaining. Matters for composability and scripting.

**PS2** — Pipeline streams objects. `ForEach-Object` is a cmdlet, processes stream element-by-element, supports `-Parallel`. `foreach` statement is a language construct, iterates in-memory collections, faster for large datasets, no streaming.

**PS3** — `[PSCustomObject]`: strongly typed, ordered, pipeline-friendly, supports methods. `[hashtable]`: unordered, key-value, no type safety, slower. Convert: `[PSCustomObject]@{...}`. Use custom object for structured data, hashtable for dynamic config.

**PS4** — Terminating errors stop execution and are catchable; non-terminating errors continue and are logged. `-ErrorAction`: `Stop`, `Continue`, `SilentlyContinue`, `Ignore`. `$ErrorActionPreference`: global default. `try/catch` only catches terminating errors.

**PS5** — Splatting: `@params` passes a hashtable's keys as named parameters. `@{Param1='a'; Param2='b'} | Cmdlet`. Differs from single param: splatting expands to named parameters; single param passes the entire hashtable as one argument.

**PS6** — `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` creates an interactive session. Uses WinRM (HTTP/HTTPS) by default; SSH available in PS 7+.

**PS7** — Returns an array even for a single item. `$result += "one"` creates an array. `$x.GetType().Name` is `Object[]`. If 0 items, returns `$null`. Correct pattern: `[array]$result = @()` or avoid `+=`, use `@()` to force array.

**PS8** — `[scriptblock]` is anonymous code; function is named, supports parameters/pipeline. Pass to remote: `-ArgumentList` or `$using:`. Double-hop: auth fails when remoting to a second server. Solve with CredSSP (insecure) or `-ArgumentList` + local processing, or use PSSession with delegation.

**PS9** — `@()` is array subexpression (forces collection); `[array]` is type constraint. Force single result: `@($result)`. Index `$null`: throws. Index empty array: returns `$null`.

**PS10** — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive: `-ceq`, `-clike`, `-cmatch`, `-ccontains`, `-cin`. `-contains` checks if collection contains value; `-in` checks if value is in collection (reversed operands).

**PS11** — Module: collection of commands. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies). Binary: compiled DLL. `Import-Module`: loads into session, searches `$env:PSModulePath`.

**PS12** — String interpolation: `"..."` expands variables/expressions `${expr}`. `'...'` literal. Here-string: `@"..."@` for multi-line. Expressions: `$(...)` or `${...}`.

**PS13** — `Get-Member` explores object members. Properties (data), Methods (actions), NoteProperties (custom). `Select-Object`: picks properties/creates new objects. `Where-Object`: filters objects based on conditions.

**PS14** — Classes (v5): C#-like syntax, but limited. No multiple inheritance, no interfaces (until PS 7.2+), constructors use `class Name { Name() {} }`. Limitations: no access modifiers (public by default), limited reflection. Use for structured data/models, functions for logic.

**PS15** — `CmdletBinding`: enables advanced features. `SupportsShouldProcess`: `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: parameter groups. `ValueFromPipeline`: binds pipeline input. `Begin`/`Process`/`End`: `Begin` runs once, `Process` per pipeline object, `End` once after.

**PS16** — Providers: abstract data stores. `Get-ChildItem` works on FileSystem, Registry, Cert, Env. Registry accessed via `HKLM:\` or `Registry::HKEY_LOCAL_MACHINE\`. Treated like file system for navigation.

**PS17** — Runspaces: execution contexts. `[runspace]`: single thread. `[runspacepool]`: thread pool. `[powershell]`: adds pipeline. `ForEach-Object -Parallel` (v7+): easy, uses runspace pool. Manual: more control, complex setup, better for PS 5.1.

**PS18** — PSScriptAnalyzer: linting tool. Rules: syntax, style, performance. Severity: error, warning, info. Custom rules: PowerShell scripts. Suppress: `#pragma disable`, `.psake.ps1`, or config file. CI/CD: run in pipeline, fail on errors.

**PS19** — `$using:` scope serializes variables from caller to remote/job/parallel. `-ArgumentList` passes as arguments, also serialized. Limits: CLIXML depth (default 64), complex objects may fail or lose types. Affects nested collections, custom objects with methods.

**PS20** — DSC: declarative config. Configurations: desired state code. Resources: building blocks (File, Service, Package). LCM: agent that applies config. WinPS vs PS7: PS7 uses OpenDSC, cross-platform, better performance. Replaced by: Terraform, Ansible, Chef, Puppet, or native cloud IaC.
