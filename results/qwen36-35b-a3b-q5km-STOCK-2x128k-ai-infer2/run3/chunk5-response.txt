DN1 — **class vs struct**: `class` is a reference type (heap-allocated, nullable, supports inheritance/polymorphism). `struct` is a value type (stack/inline-allocated, copy-on-assign, no inheritance, implicitly sealed). Use `struct` for small, immutable, short-lived data that benefits from value semantics (e.g., coordinates, IDs, math vectors). Avoid for large or mutable types due to copy overhead.

DN2 — **IEnumerable<T> vs IQueryable<T>**: `IEnumerable<T>` executes in-memory; LINQ operators translate to delegate-based methods. `IQueryable<T>` builds expression trees that providers (like EF Core) translate to SQL. Distinction matters because `IQueryable` pushes filtering, projection, and pagination to the database, reducing network traffic and memory usage. Using `IEnumerable` on a DB context loads entire tables into memory before filtering.

DN3 — **async/await & Task vs ValueTask**: `async/await` compiles to a state machine that captures context, yields control, and resumes without blocking threads. `Task` is a reference type (heap-allocated). `ValueTask` is a struct that can wrap a synchronous result or an async operation. Use `ValueTask` when an async method frequently completes synchronously or in hot paths to avoid allocation overhead.

DN4 — **DI & Service Lifetimes**: DI containers manage object creation and disposal. `Transient`: new instance each request. `Scoped`: one instance per request/context. `Singleton`: one instance per app lifetime. **Captive dependency bug**: Injecting a `Scoped` service into a `Singleton` keeps the scoped instance alive for the app's lifetime, causing memory leaks, stale state, and thread-safety issues.

DN5 — **string vs ReadOnlySpan<char>**: `string` is immutable, heap-allocated, and GC-managed. `ReadOnlySpan<char>` is a stack-only, zero-allocation view over contiguous memory (string, array, buffer). Use `Span<T>`/`ReadOnlySpan<T>` for high-performance parsing, slicing, and tokenization in hot paths to avoid allocations and string copying.

DN6 — **GC, Generations, LOH, IDisposable**: GC manages managed heap memory automatically. **Gen 0**: short-lived objects, collected frequently. **Gen 1**: buffer between 0 and 2. **Gen 2**: long-lived objects, collected rarely. **LOH**: objects >85KB, collected infrequently, not compacted (causes fragmentation). `IDisposable` is for deterministic cleanup of unmanaged resources (file handles, DB connections, native memory) that the GC doesn't track.

DN7 — **ConfigureAwait(false)**: By default, `await` captures the current `SynchronizationContext` (or `TaskScheduler`) to resume on the same thread/context. `ConfigureAwait(false)` skips capture, allowing continuation on any thread pool thread. **Use**: in libraries to avoid deadlocks and improve throughput. **Don't use**: in UI/desktop apps where context is required for UI updates or thread-affine resources.

DN8 — **.NET 8/9 Features**: 
- **Primary constructors**: `public record Service([FromKeyedServices("db")] IDb db);` reduces boilerplate.
- **Collection expressions**: `int[] arr = [1, 2, 3];` or `var list = [1, 2, ..other];`
- **FrozenDictionary**: immutable, optimized for lookups, uses less memory than `Dictionary`/`ImmutableDictionary`.
Example DI with primary constructor:
```csharp
public record MyHandler([FromKeyedServices("cache")] ICache cache, ILogger<MyHandler> log);
```

DN9 — **DbContext ObjectDisposedException under load**: Likely cause: DbContext is registered as `Transient` but shared across requests, or disposed while async operations are pending. EF Core's `DbContext` is not thread-safe and relies on DI scoping. **Fix**: Register as `Scoped` (default in EF Core templates) so each HTTP request gets a fresh instance. Ensure no manual `Dispose()` calls and avoid capturing DbContext across async boundaries.

DN10 — **record vs class vs record struct**: `record` is a reference type with value-based equality, immutability by default, and positional syntax. `record struct` is the value-type equivalent. Choose `record` for DTOs, domain events, and immutable data. Choose `class` for mutable, reference-heavy, or polymorphic objects. Choose `record struct` for performance-critical, small, immutable data where allocation must be avoided.

DN11 — **ref, out, in**: `ref`: pass by reference, caller must initialize, can be modified. `out`: pass by reference, caller need not initialize, method must assign before return. `in`: pass by reference, read-only, prevents mutation. Use `ref` for input+output, `out` for multiple return values, `in` for large structs to avoid copy while guaranteeing immutability.

DN12 — **Nullable Reference Types (NRT)**: Compile-time warnings for potential null dereferences (`string?`). `#nullable enable` activates. Differs from nullable value types (`int?` = `Nullable<int>`) which have runtime representation (`HasValue`/`Value`). NRTs are erased at runtime; they only affect static analysis. Value types retain nullability at runtime.

DN13 — **LINQ & Deferred Execution**: LINQ unifies querying across data sources. **Method syntax**: fluent, chainable, works with any `IEnumerable`/`IQueryable`. **Query syntax**: SQL-like, compiles to method syntax. **Deferred execution**: queries aren't executed until enumerated (`foreach`, `ToList`, etc.), enabling composition, lazy evaluation, and remote translation (for `IQueryable`).

DN14 — **Generic Constraints**: Restrict `T` to specific types/capabilities. `class`/`struct`/`new()`/`interface`. Combine with commas: `where T : class, IComparable<T>, new()`. Use when algorithms require instantiation, comparison, or reference semantics. Prevents invalid type usage at compile time.

DN15 — **abstract class vs interface**: Abstract classes can have state, constructors, non-virtual methods, and support single inheritance. Interfaces define contracts only, support multiple inheritance. **C# 8+ default interface methods** allow interfaces to provide implementations, blurring the line but still prohibiting state/constructors. Prefer interfaces for contracts, abstract classes for shared implementation/state.

DN16 — **Middleware Pipeline**: Sequential request processing. `app.Use()`: adds middleware, can call `next()` to continue pipeline. `app.Map()`: branches routing based on path prefix. `app.Run()`: terminal middleware, no `next()`. **Ordering matters**: auth/rate-limit before routing, error handling early. Exception handling middleware (`app.UseExceptionHandler`) catches unhandled exceptions, can short-circuit and return error responses.

DN17 — **Channel<T> vs BlockingCollection<T>**: `Channel<T>` is async-first, thread-safe, built for modern async pipelines. `BlockingCollection<T>` is sync-first, wraps `BlockingCollection`/`ConcurrentQueue`. **Bounded channel example**:
```csharp
var ch = Channel.CreateBounded<int>(new BoundedChannelOptions(100) { FullMode = BoundedChannelFullMode.Wait });
// Producers await ch.Writer.WriteAsync() when full (backpressure)
```

DN18 — **Source Generators**: Compile-time code generation via Roslyn APIs. Differs from reflection (runtime overhead) and IL weaving (post-compilation modification). **Incremental generator**: uses `IncrementalGeneratorInitializationContext`, supports caching, incremental compilation, and dependency tracking. Preferred over legacy `ISourceGenerator` for performance, modern .NET compatibility, and better IDE integration.

DN19 — **TPL Dataflow**: Message-passing library for parallel/concurrent pipelines. `ActionBlock`: processes items, no output. `TransformBlock`: processes items, produces output. `BufferBlock`: stores items, no processing. **vs Channels**: Dataflow is higher-level with built-in backpressure, linking, completion propagation, and fault tolerance. Channels are lower-level, more flexible for custom async flows but require manual backpressure handling.

DN20 — **Minimal APIs**: Lightweight, route-to-code pattern. Differs from controllers: less boilerplate, inline handlers, no controller lifecycle. **Trade-offs**: harder to test complex logic, limited middleware integration (improving), OpenAPI via Swashbuckle/NSwag. **Route groups**: `app.MapGroup("/api").WithTags("Users")`. **Endpoint filters**: `WithFilter()` applies cross-cutting concerns (auth, validation) per endpoint without global middleware.

P1 — **list vs tuple, set vs frozenset**: `list` is mutable, ordered, allows duplicates. `tuple` is immutable, ordered, allows duplicates. `set` is unordered, unique elements, mutable. `frozenset` is immutable, hashable, usable as dict keys or set elements.

P2 — **GIL**: Global Interpreter Lock allows only one thread to execute Python bytecode at a time. Affects CPU-bound multithreading. Workarounds: `multiprocessing`, C-extensions that release GIL, `asyncio` for I/O, or alternative interpreters (PyPy STM, Jython).

P3 — **deepcopy vs copy**: `copy` creates a shallow copy (new container, references same nested objects). `deepcopy` recursively copies all nested objects. Shallow copy pitfall:
```python
a = [[1]]; b = copy(a); b[0].append(2); print(a)  # [[1, 2]]
```

P4 — **Decorators**: Functions that wrap others to extend behavior.
```python
import time, functools
def log_time(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        res = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter()-start:.4f}s")
        return res
    return wrapper
```

P5 — **Generators & yield**: Functions that return iterators, pausing/resuming state. `yield` vs list: lazy evaluation, constant memory for large datasets. `yield from`: delegates to another generator, simplifying nested iteration and forwarding exceptions.

P6 — **asyncio event loop**: Single-threaded concurrency manager. `asyncio.run()`: entry point, creates loop, runs coroutine. `asyncio.gather()`: runs multiple coroutines concurrently, returns results. `asyncio.create_task()`: schedules coroutine for later execution. `time.sleep()` blocks the entire event loop thread; use `asyncio.sleep()` instead.

P7 — **MRO**: Method Resolution Order determines attribute lookup path. Python 3 uses **C3 linearization**. Diamond inheritance `D(B, C)` yields MRO: `D → B → C → A`. `D().who()` searches `D` (no), `B` (no), `C` (yes) → prints `"C"`. C3 ensures monotonicity and consistent left-to-right precedence.

P8 — **Metaclass vs __init_subclass__**: Metaclass controls class creation globally (e.g., ORM field registration, singleton enforcement). `__init_subclass__` is a simpler, instance-level hook for subclass registration. Use `__init_subclass__` for plugin/registry patterns. Use metaclass for complex class-level transformations, constraint enforcement, or modifying class dictionaries before instantiation.

P9 — **multiprocessing vs threading vs concurrent.futures**: `multiprocessing` bypasses GIL, true parallelism, heavy overhead, requires pickling. `threading` shares memory, I/O-bound, GIL-limited for CPU. `concurrent.futures` provides high-level `ThreadPoolExecutor`/`ProcessPoolExecutor` APIs. **Pickling**: objects must be serializable; lambdas, open files, and some C-extensions fail.

P10 — **__slots__**: Restricts instance attributes to a fixed set, prevents `__dict__` creation. Use for memory optimization with millions of instances (e.g., data nodes). Prevents dynamic attribute addition. Memory impact: significant per-instance reduction (~40-50%), but adds slight class-creation overhead.

P11 — **Virtual environments**: Isolated Python environments with independent packages/interpreter. Prevents dependency conflicts. `venv`: stdlib, lightweight. `virtualenv`: third-party, more features. `conda`: package + env manager, handles non-Python binaries, data-science focused.

P12 — **Comprehensions vs map/filter**: Comprehensions (`[x for x in ...]`) are eager, often faster, and more readable. `map`/`filter` return lazy iterators, useful for functional pipelines or memory-constrained streams. Prefer comprehensions for simplicity/speed; `map`/`filter` for lazy evaluation or complex functional composition.

P13 — **== vs is**: `==` checks value equality. `is` checks object identity. Object interning caches small integers (-5 to 256) and some strings for performance. `a is b` returns `True` for interned objects, not because values match, but because they reference the same cached object.

P14 — **\*args, \*\*kwargs, /, \***: `*args` collects extra positional args into a tuple. `**kwargs` collects extra keyword args into a dict. `/` marks parameters as positional-only (before `/`). `*` marks parameters as keyword-only (after `*`). Used for API design, enforcing call signatures, and forward/backward compatibility.

P15 — **Context managers**: Ensure setup/teardown (`with` statement). Class-based: `__enter__`/`__exit__`. Function-based: `@contextmanager` with `yield`. Example beyond files: database transactions, temporary directories, lock acquisition, or HTTP request/response lifecycle management.

P16 — **Type hinting**: Static type annotations. `Union`/`Optional`: multiple types or `None`. `Literal`: exact value constraints. `TypeVar`: generic type variables. `Protocol`: structural subtyping (duck typing). `mypy`/`pyright` parse annotations, check types statically without runtime overhead, catching mismatches before execution.

P17 — **Data model (dunders)**: `__repr__`: unambiguous, dev-focused. `__str__`: readable, user-focused. `__eq__`: equality. `__hash__`: hashability. Defining `__eq__` without `__hash__` sets `__hash__ = None`, making instances unhashable (fails in sets/dicts). `__getattr__`: fallback for missing attrs. `__getattribute__`: intercepts all access (dangerous, can cause infinite recursion).

P18 — **Descriptors**: Objects implementing `__get__`, `__set__`, `__delete__` that control attribute access on owner classes. `property` is a data descriptor. `classmethod`/`staticmethod` are non-data descriptors. Under the hood, they're descriptors attached to the class, invoked via the descriptor protocol during attribute lookup, enabling computed attrs, method binding, and static behavior.

P19 — **Import system**: `sys.path`/`PYTHONPATH` define search paths. `__init__.py` marks directories as packages (optional in Python 3.3+ for namespace packages). Relative (`.`) vs absolute (`pkg.mod`) imports. **Finder**: locates modules. **Loader**: loads/executes them. `importlib` provides the API. Namespace packages split across directories without `__init__.py`.

P20 — **dataclasses vs attrs vs Pydantic**: `dataclasses` auto-generates `__init__`, `__repr__`, `__eq__`, etc. `attrs` offers more features/maturity. `Pydantic` adds validation, serialization, and JSON handling. `__post_init__`: custom post-init logic. `field(default_factory=list)`: avoids mutable default pitfalls. `frozen=True`: immutability. Inheritance works but requires careful default handling. Choose `Pydantic` for API boundaries, validation, config management, and serialization.
