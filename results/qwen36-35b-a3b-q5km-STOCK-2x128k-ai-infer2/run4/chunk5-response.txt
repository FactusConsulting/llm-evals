DN1 — **class vs struct**: `class` is a reference type allocated on the heap; `struct` is a value type typically allocated on the stack (or inline). `struct` should be used for small, immutable, short-lived data that represents a single logical value (e.g., coordinates, IDs, math vectors) to avoid heap allocations and enable value semantics.

DN2 — **IEnumerable<T> vs IQueryable<T>**: `IEnumerable<T>` executes queries in-memory; `IQueryable<T>` builds expression trees that are translated to remote queries (e.g., SQL). This matters because `IQueryable` pushes filtering, projection, and sorting to the database, reducing network traffic and memory usage.

DN3 — **async/await & Task vs ValueTask**: `async/await` compiles into a state machine that suspends/resumes execution without blocking threads. `Task` always allocates a heap object; `ValueTask` is a `struct` that avoids allocation when the async operation completes synchronously or reuses a cached task. Use `ValueTask` when the operation frequently completes synchronously or in hot paths.

DN4 — **DI & Service Lifetimes**: DI injects dependencies via constructors/properties. `Transient`: new instance per injection. `Scoped`: one instance per request/context. `Singleton`: one instance per app lifetime. **Captive dependency bug**: injecting a `Scoped` service into a `Singleton` keeps the scoped instance alive for the app's lifetime, causing memory leaks, stale state, and thread-safety issues.

DN5 — **string vs ReadOnlySpan<char>**: `string` is a heap-allocated, immutable reference type. `ReadOnlySpan<char>` is a stack-only, zero-allocation view over contiguous memory. Use `Span<T>`/`ReadOnlySpan<T>` for high-performance parsing, slicing, and buffer manipulation to eliminate allocations and improve cache locality.

DN6 — **GC, Generations, LOH, IDisposable**: The GC manages managed memory. Gen 0: short-lived objects, collected frequently. Gen 1: buffer between 0 and 2. Gen 2: long-lived, collected rarely. LOH: objects >85KB, collected only during Gen 2, not compacted by default. `IDisposable` is needed for unmanaged resources (handles, sockets, DB connections) since the GC only tracks managed memory.

DN7 — **ConfigureAwait(false)**: By default, `await` captures the `SynchronizationContext` (e.g., UI thread) to resume on it. `ConfigureAwait(false)` skips capture, allowing continuation on any thread pool thread. Use in libraries to prevent deadlocks and improve throughput. **Do not** use in UI apps or code that must interact with UI/context-specific resources.

DN8 — **.NET 8/9 Features**: Primary constructors reduce boilerplate by declaring parameters directly in the type signature. Collection expressions (`[1, 2, 3]`, `[..arr]`) simplify array/span creation. `FrozenDictionary` provides read-only, high-performance lookups with minimal memory overhead. Example: `public record MyService([FromKeyedServices("db")] IDb db);`

DN9 — **DbContext ObjectDisposedException**: Caused by sharing a `DbContext` across requests (e.g., caching it as `Singleton`/`static`) or disposing it prematurely. EF Core `DbContext` is designed to be `Scoped` (per-request). Fix: remove caching, rely on DI scoping, and never share instances. Sharing corrupts change tracking and causes disposal conflicts under concurrency.

DN10 — **record vs class**: `record` is a reference type with built-in value-based equality, immutability by default, and positional syntax. `record struct` is the value-type equivalent. Use `record` for DTOs, domain events, or immutable data. Use `class` for mutable, stateful entities. Use `record struct` for performance-critical value types needing value semantics.

DN11 — **ref, out, in**: `ref` passes by reference; variable must be initialized before call. `out` passes by reference; variable must be assigned inside the method. `in` passes by read-only reference; prevents copying large structs. Use `ref` for modification, `out` for multiple return values, `in` for performance with large structs.

DN12 — **Nullable Reference Types (NRTs)**: `?` annotation provides compile-time nullability warnings for reference types. Differs from nullable value types (`int?`) which are actual `Nullable<T>` structs at runtime. NRTs are erased at runtime; they only affect static analysis to prevent `NullReferenceException`.

DN13 — **LINQ**: Language Integrated Query unifies data access. Method syntax (`list.Where(...)`) is composable and preferred in C#. Query syntax (`from x in list where ...`) is syntactic sugar compiled to method syntax. Deferred execution means the query isn't executed until enumeration (e.g., `foreach`, `.ToList()`), allowing composition and lazy evaluation.

DN14 — **Generic Constraints**: `where T : class` (reference type), `struct` (value type), `new()` (parameterless constructor), `IComparable<T>` (supports comparison). Combine with `&` (e.g., `where T : class, IComparable<T>, new()`). Use when algorithms require specific capabilities or object lifecycles.

DN15 — **abstract class vs interface**: Abstract classes provide partial implementation, state, and constructors; support single inheritance. Interfaces define contracts; support multiple inheritance. C# 8+ default interface methods allow implementation in interfaces, narrowing the gap, but abstract classes still uniquely support state, access modifiers, and constructors.

DN16 — **Middleware Pipeline**: Sequence of delegates processing requests/responses. `app.Use()` adds middleware to the pipeline. `app.Map()` branches routing for specific paths. `app.Run()` is a terminal delegate. Order matters: auth/cache before MVC, error handling early. Exception handling middleware catches unhandled exceptions and can branch to error pages or return JSON.

DN17 — **Channel<T>**: Thread-safe producer-consumer queue. Bounded channels (`Channel.CreateBounded`) apply backpressure by blocking producers when full. Differs from `BlockingCollection<T>` (older, less flexible, no async-native design). Example: `var ch = Channel.CreateBounded<int>(new BoundedChannelOptions(100)); await ch.Writer.WriteAsync(item);`

DN18 — **Source Generators**: Compile-time code generation via Roslyn. Differs from reflection (runtime overhead) and IL weaving (post-compile, fragile). Incremental generators (`IIncrementalGenerator`) cache results and only run when inputs change, drastically reducing compilation time. Preferred over legacy `ISourceGenerator` for performance and incremental compilation support.

DN19 — **TPL Dataflow**: Message-passing parallelism library. `ActionBlock` processes items without returning results. `TransformBlock` processes and returns results. `BufferBlock` stores items for later consumption. Compared to `Channels`, Dataflow offers richer routing, completion propagation, and backpressure semantics, but `Channels` are lighter and better for simple streaming pipelines.

DN20 — **Minimal APIs**: Lightweight, delegate-based routing without controllers. Trade-offs: less boilerplate, faster startup, but harder to test complex logic, limited middleware flexibility, and OpenAPI requires Swashbuckle/AutoGen. Route groups (`MapGroup`) organize endpoints by prefix/middleware. Endpoint filters (`AddFilter`) handle validation, auth, and cross-cutting concerns declaratively.

P1 — **list vs tuple, set vs frozenset**: `list` is mutable, ordered. `tuple` is immutable, ordered. `set` is mutable, unordered, unique elements. `frozenset` is immutable set. Use tuples for fixed records, sets for membership testing/deduplication.

P2 — **GIL**: Global Interpreter Lock allows only one thread to execute Python bytecode at a time. Affects CPU-bound multithreading. Workarounds: `multiprocessing`, C-extensions (release GIL), `asyncio` for I/O, or external processes/services.

P3 — **deepcopy vs copy**: `copy` creates a shallow copy (new container, references same inner objects). `deepcopy` recursively copies all nested objects. Example: `a = [[1]]; b = copy(a); b[0].append(2)` modifies `a[0]` too. Use `deepcopy` when nested mutability must be isolated.

P4 — **Decorators**: Functions that wrap other functions to extend behavior. Example:
```python
import time
def timer(f):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = f(*args, **kwargs)
        print(f"{f.__name__}: {time.time()-start:.2f}s")
        return result
    return wrapper
```

P5 — **generators & yield**: `yield` turns a function into a generator, producing values lazily without storing them in memory. Differs from returning a list by enabling streaming and low memory usage. `yield from` delegates to another generator, flattening iteration.

P6 — **asyncio event loop**: Single-threaded concurrency manager. `asyncio.run()` is the entry point. `asyncio.gather()` runs coroutines concurrently and returns results. `asyncio.create_task()` schedules a coroutine to run concurrently and returns a Task object. `time.sleep()` blocks the loop; use `asyncio.sleep()` to yield control.

P7 — **MRO**: Python 3 uses C3 linearization. Diamond inheritance resolves left-to-right, depth-first. MRO for `D(B, C)` is `D → B → C → A`. `D().who()` skips `B` (no override), calls `C.who()`, prints `"C"`.

P8 — **metaclass vs __init_subclass__**: Metaclass controls class creation (type, attributes, methods). Use for complex class-level manipulation (e.g., ORM model registration). `__init_subclass__` is a simpler hook called when a subclass is created. Use for auto-registration, default attribute injection, or validation without metaclass complexity.

P9 — **multiprocessing vs threading vs concurrent.futures**: Threading: I/O bound, GIL-limited. Multiprocessing: CPU bound, separate processes, memory isolation. `concurrent.futures`: high-level API wrapping both. Multiprocessing uses `pickle` for serialization; fails on lambdas, open file handles, or unpicklable objects.

P10 — **__slots__**: Restricts instance attributes to a predefined list. Prevents `__dict__` creation, saving memory and preventing arbitrary attribute assignment. Use when creating many instances of the same class. Trade-off: breaks inheritance flexibility and dynamic attribute addition.

P11 — **virtual environment**: Isolated Python environment preventing dependency conflicts. `venv`: stdlib, lightweight. `virtualenv`: third-party, more features. `conda`: package + env manager, handles non-Python deps, standard in data science.

P12 — **comprehensions vs map/filter**: Comprehensions (`[x for x in lst]`) are Pythonic, readable, and create collections directly. `map`/`filter` return iterators, slightly faster in tight loops, and fit functional pipelines. Prefer comprehensions for clarity; use `map`/`filter` for performance or lazy evaluation.

P13 — **== vs is**: `==` checks value equality. `is` checks object identity. Interning caches small integers (-5 to 256) and some strings. `a is b` returns `True` for interned objects because they reference the same memory address.

P14 — **\*args & \*\*kwargs**: `*args` packs extra positional args into a tuple. `**kwargs` packs extra keyword args into a dict. `/` marks parameters as positional-only. `*` marks parameters as keyword-only. Used for flexible APIs, decorators, and clear parameter intent.

P15 — **context managers**: Ensure setup/teardown via `with`. Implement via `__enter__`/`__exit__` or `@contextmanager`. Example: database transactions, file locks, temp directories, or HTTP request sessions. Guarantees cleanup even on exceptions.

P16 — **type hinting**: Static annotations for dev-time checking. `Union`/`Optional` = multiple types. `Literal` = exact values. `TypeVar` = generic constraints. `Protocol` = structural subtyping. `mypy`/`pyright` parse annotations and report mismatches without runtime overhead.

P17 — **dunder methods**: `__repr__` = unambiguous dev/debug string. `__str__` = user-friendly. `__eq__` = equality, `__hash__` = hashability. Defining `__eq__` without `__hash__` sets `__hash__ = None` (unhashable). `__getattr__` = fallback for missing attrs. `__getattribute__` = always called, use carefully to avoid recursion.

P18 — **descriptors**: Objects implementing `__get__`, `__set__`, `__delete__` to control attribute access. `property`, `classmethod`, `staticmethod` are descriptors. Used for validation, computed attributes, lazy loading, and decorator implementation.

P19 — **import system**: `sys.path`/`PYTHONPATH` define search paths. `__init__.py` marks packages (optional in PEP 420 namespace packages). Relative imports (`.`) vs absolute. Finders locate modules on `sys.meta_path`; loaders compile/execute them. `importlib` provides the runtime API.

P20 — **dataclasses vs attrs vs Pydantic**: `dataclasses` auto-generates `__init__`, `__repr__`, etc. `attrs` is older, more flexible. `Pydantic` adds runtime validation, type coercion, and serialization. `__post_init__` runs after init. `frozen=True` makes instances immutable. Choose Pydantic for API/data validation, complex types, and serialization; dataclasses for simple, fast, validation-free records.
