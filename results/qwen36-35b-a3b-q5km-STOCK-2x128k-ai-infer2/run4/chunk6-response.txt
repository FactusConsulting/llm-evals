## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted with `undefined` initialization. `let`/`const` are block-scoped, hoisted but in a Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment of the binding (not the value). Hoisting moves declarations to the top of their scope during compilation; `var` initializes to `undefined`, while `let`/`const` remain uninitialized until execution reaches them.

**JS2** — The event loop continuously checks the call stack and queues. When the stack is empty, it processes the microtask queue (Promises, `queueMicrotask`, `MutationObserver`) first, then one macrotask (setTimeout, setInterval, I/O, UI rendering). Microtasks run to completion before the next macrotask, ensuring async promise chains execute synchronously relative to each other.

**JS3** — A closure is a function that retains access to its lexical scope even when executed outside it. Example: `function makeCounter() { let i=0; return () => ++i; }`. Classic bug: `for (var i=0; i<3; i++) setTimeout(()=>console.log(i), 0)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped), IIFE, or `setTimeout(..., 0, i)` to capture the value.

**JS4** — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that pauses execution until the promise settles, making async code read synchronously. Error handling: `try/catch` with `await`, or `.catch()`/`.then(null, err)` with promises. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all promises, returning an array of `{status, value/reason}` objects.

**JS5** — `interface` defines object shapes, supports declaration merging/extension, and erases at runtime. `type` is a broader alias (primitives, unions, intersections, tuples). Use `interface` for APIs/objects, `type` for unions/primitives. Discriminated unions: types sharing a common literal property (e.g., `type: 'a' | 'b'`), enabling exhaustive type narrowing via `switch`/`if`.

**JS6** — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar: `class A extends B` sets `A.prototype.__proto__ = B.prototype`, `super()` calls the parent constructor, and `super.method()` calls parent methods.

**JS7** — `this` is determined by call site. Priority order: 1. `new` (new instance), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (`window` or `undefined` in strict mode). `bind()` returns a new function with `this` permanently bound. It cannot be re-bound; subsequent `call`/`apply`/`bind` calls are ignored.

**JS8** — `WeakRef` holds a weak reference that doesn't prevent garbage collection. `FinalizationRegistry` executes a callback when weakly referenced objects are GC'd. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the GC can track when keys become unreachable and clean up entries. Primitives can't be weakly referenced, so they'd cause permanent memory leaks.

**JS9** — V8 optimizes via: Hidden classes (shape inference for fast property access), Inline caching (caches hidden class pointers at call sites for O(1) lookups), and Deoptimization (reverts to slower code when assumptions break). Deopt triggers: dynamic property addition/deletion, type polymorphism, `delete`, `with`, `arguments` object, or changing prototype chains.

**JS10** — Tree-shaking removes unused exports at build time. It works with ES Modules because imports/exports are static and analyzable at compile time. CommonJS uses dynamic `require()`, evaluated at runtime, so bundlers can't statically determine what's unused, making effective tree-shaking impossible.

**JS11** — `null` is intentional absence; `undefined` is uninitialized/missing. `==` coerces types (`null == undefined` is `true`); `===` checks type and value (`false`). `??` returns right operand if left is `null`/`undefined` (ignores `0`/`""`). `?.` safely accesses nested properties without throwing on `null`/`undefined`.

**JS12** — `map()` transforms, `filter()` selects, `reduce()` accumulates to a single value. `reduce()` with initial value prevents errors on empty arrays and defines accumulator type. `flatMap()` maps then flattens by one level; useful for transforming and flattening nested structures in a single pass without double-nesting.

**JS13** — Template literals use backticks, support `${expr}` interpolation and multi-line strings. Tagged templates call a function with an array of string parts and interpolated values. Example: `html`<div>${name}</div>` passes `["<div>", "</div>"]` and `name` to `html()`, which escapes `name` to prevent XSS.

**JS14** — Destructuring unpacks values. Object: `{a, b} = obj`. Array: `[a, b] = arr`. Defaults: `{a = 1} = obj`. Renaming: `{a: newName} = obj`. Rest: `{...rest} = obj` collects remaining properties. Rest in arrays: `[a, ...rest] = arr`.

**JS15** — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, Maps). Avoid `for...in` on arrays: iterates indices as strings, includes inherited properties, not optimized for arrays, and breaks with sparse arrays.

**JS16** — Generics use type parameters for reusability. Constraints: `T extends SomeType` limits T. Conditional types: `T extends U ? X : Y` for branching. `infer` extracts types in conditional contexts. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T`.

**JS17** — CommonJS: dynamic, synchronous, `require`/`module.exports`, Node historical default. ES Modules: static, async, `import`/`export`, browser/Node native. `"type": "module"` tells Node to treat `.js` as ESM. Node supports both via extensions (`.cjs`/`.mjs`) or config.

**JS18** — Structural typing: compatibility based on shape, not names. Excess property checks apply only to object literals assigned to variables/interfaces, not function arguments. `extends`: assignment compatibility. `satisfies`: checks shape without widening, preserves specific type info. Variance: `in` (contravariant, parameters), `out` (covariant, returns), `in out` (bivariant). TS 4.7+ adds `satisfies` and stricter variance checks.

**JS19** — `Proxy` wraps objects to intercept operations (get, set, apply, etc.). `Reflect` mirrors Proxy traps and provides default behavior. Example: validation proxy intercepts `set`, checks type/value before assignment. Reactive binding: Proxy tracks dependencies on `get`, triggers updates on `set`.

**JS20** — `SharedArrayBuffer` shares memory between main thread and Web Workers. `Atomics` provides atomic operations (load, store, add, wait, notify) with memory ordering guarantees. `Atomics.wait` blocks until value changes or timeout. `Atomics.notify` wakes waiting threads. Requires COOP/COEP headers for security.

## Bash

**B1** — `$*` expands to all positional params as a single IFS-separated word. `$@` expands to each param as a separate word. `"$@"` preserves each arg exactly (recommended), `"$*"` joins them into one string.

**B2** — `set -e`: exit on command failure. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the rightmost non-zero exit code. Together, they enforce strict error handling.

**B3** — `$(command)` is modern, nestable, and readable vs legacy `` `command` ``. `$((expression))` is bash's built-in arithmetic expansion (fast, C-style). `expr` is an external command (slower, POSIX, limited syntax).

**B4** — Process substitution `<(cmd)` creates a file descriptor (e.g., `/dev/fd/63`) for a command's output. Use when a command expects a file but you have a stream. Example: `diff <(sort file1) <(sort file2)`.

**B5** — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous: word splitting on spaces/newlines, glob expansion, breaks on special chars, ignores hidden files, and fails on empty results.

**B6** — Here doc `<<EOF` feeds multi-line input. Here string `<<<` feeds a single line. `<<-EOF` strips leading tabs (not spaces) from the heredoc for indentation.

**B7** — `cmd > file 2>&1`: stdout → file, then stderr → where stdout points (file). `cmd 2>&1 > file`: stderr → original stdout (terminal), then stdout → file (stderr stays on terminal). `cmd &> file`: bash shorthand for both to file. Order matters because redirections evaluate left-to-right.

**B8** — ```bash
lock_dir="/tmp/mylock"
cleanup() { rm -rf "$lock_dir"; }
trap cleanup EXIT INT TERM
mkdir "$lock_dir" || { echo "Locked"; exit 1; }
# ... work ...
```
`mkdir` is preferred because it's atomic at the filesystem level; test-then-create races are impossible.

**B9** — Single `'...'`: literal, no expansion. Double `"..."`: allows variable/command expansion, preserves spaces. No quotes: word splitting and globbing occur. Example: `var="hello world"; echo $var` → `hello world`; `echo "$var"` → `hello world`; `echo '$var'` → `$var`.

**B10** — Checks: `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin: supports `&&`/`||`/`=~`, no word splitting/globbing, safer. `[ ]` is POSIX `test`: requires spaces, limited operators, subject to splitting.

**B11** — `$?`: last exit code (error handling). `$$`: script PID (logging/debugging). `$!`: last background job PID (job control). `$#`: number of positional params (argument validation).

**B12** — Define: `foo() { ... }` (POSIX) or `function foo { ... }` (bash). Return values: `return <int>` (exit code 0-255), or `echo`/`printf` to stdout and capture with `$()`.

**B13** — `PATH`: colon-separated dirs bash searches for executables. Resolution: PATH → builtins → aliases. Builtin: compiled into bash (`cd`, `echo`). External: separate binary. Check with `type cmd` or `command -v cmd`.

**B14** — `trap` registers handlers: `trap 'cleanup' EXIT INT TERM ERR`. Execution: LIFO for same signal, `EXIT` runs last. Multiple signals queue and run sequentially. `ERR` triggers on command failure.

**B15** — `$(cmd)` loads all output into memory; `xargs` streams/chunks. Handle spaces: `find ... -print0 | xargs -0 cmd`. `-P N` runs N processes in parallel.

**B16** — Arrays: `arr=(a b c)`, append `arr+=(d)`, iterate `for i in "${arr[@]}"`, length `${#arr[@]}`. Associative: `declare -A assoc`, set `assoc[key]=val`, iterate keys/values similarly. Associative requires explicit declaration and supports string keys.

**B17** — Subshell `(...)`: child process, variable changes lost. Group `{ ...; }`: current shell, variables persist. Piping to `while` creates a subshell, losing changes. Fix: `while read; do ...; done < <(cmd)` (process substitution).

**B18** — Signals: SIGINT (Ctrl+C, interrupt), SIGTERM (graceful stop, default kill), SIGHUP (terminal close/reload), SIGKILL (force kill, uncatchable). Graceful shutdown: trap SIGTERM, set flag, wait for background jobs, cleanup.

**B19** — Split: `split -l 10000 log.txt log_part_`. Parallel: `find . -name "log_part_*" -print0 | xargs -0 -P 4 -I {} bash -c 'process "$1"' _ {}`. Merge: `cat log_part_* > merged.log`. Trade-offs: CPU vs I/O, splitting/merging overhead. Error propagation: capture exit codes, use `set -o pipefail`, aggregate failures, check `xargs` return.

**B20** — `exec` replaces the shell or manipulates FDs. `exec 3>file` opens FD 3, `exec 3>&-` closes it. Coprocess: `coproc cmd` creates bidirectional pipe, allowing script to read/write to cmd's stdin/stdout. Use for persistent background services or interactive tools.

## PowerShell

**PS1** — `Write-Output` sends objects down the pipeline. `Write-Host` writes directly to the console (bypasses pipeline, breaks automation). Matters because pipeline consumers expect objects, not formatted text.

**PS2** — Pipeline streams objects. `ForEach-Object`: processes each object in pipeline (streaming, memory efficient). `foreach` statement: iterates over collection in memory (faster for large collections, loads all). Use `ForEach-Object` for streaming/large data, `foreach` for in-memory collections.

**PS3** — `[PSCustomObject]`: strongly typed, ordered properties, supports methods/events. `[hashtable]`: unordered, dynamic, no type safety. Convert: `[PSCustomObject]@{Key="Val"}`. Use PSCustomObject for structured data, hashtable for dynamic/config.

**PS4** — Terminating errors stop execution (caught by `try/catch`). Non-terminating errors continue (logged to `$Error`). `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors. Use `-ErrorAction Stop` to convert non-terminating to terminating.

**PS5** — Splatting `@params` passes a hashtable's keys as named parameters. `@{Verbose=$true; ErrorAction='Stop'}`. Differs from single param: splatting expands to named parameters, single param passes the entire hashtable as one argument.

**PS6** — `Invoke-Command -ComputerName`: one-off remote commands. `Enter-PSSession`: interactive remote session. Uses WS-Management (WinRM) by default; PowerShell 7+ supports SSH.

**PS7** — Pipeline outputs arrays as a single object if count=1, or array if >1. `Get-Items` returns array. `$x.GetType().Name` → `Object[]`. If 0 items, returns `$null`. Correct pattern: `$result = @(); ...; return ,$result` (comma forces array) or explicit array creation.

**PS8** — `[scriptblock]`: code container, passable. Functions are named scriptblocks. Pass to remote: `Invoke-Command -ScriptBlock $sb`. Double-hop: auth fails when remoting to B then to C. Solve with CredSSP (insecure), Kerberos delegation, or pass data via `-ArgumentList` and execute locally.

**PS9** — `@()` forces array, `[array]` casts. Force single result: `,$single`. Index `$null[0]` → error, `@()[0]` → null/empty. `@()` prevents enumeration pitfalls.

**PS10** — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive: `-ceq`, `-clike`, `-cmatch`, `-ccontains`, `-cin`. `-contains` checks if collection contains value, `-in` checks if value is in collection (reversed operands).

**PS11** — Module: collection of cmdlets/functions. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies). Binary: compiled DLL. `Import-Module` loads into session, checks module path, runs initialization.

**PS12** — Interpolation: `"Hello $name"`. `"..."` expands variables/expressions, `'...'` literal. Expressions: `"Value: $(Get-Date)"`. Here-string: `@"..."@` allows multi-line, preserves formatting, supports interpolation.

**PS13** — `Get-Member`: explores object members. Properties (data), Methods (actions), NoteProperties (custom added). `Select-Object` picks/transforms properties, `Where-Object` filters based on conditions.

**PS14** — Classes (v5): `class MyClass { [string]$Prop; MyClass([string]$p) { $this.Prop = $p } }`. Differ from C#: no interfaces, limited inheritance (single), no access modifiers (public by default), no static members in older versions. Use classes for complex data/models, functions for simple tasks.

**PS15** — `CmdletBinding()`: enables advanced features. `SupportsShouldProcess`: enables -WhatIf/-Confirm. `DefaultParameterSetName`: sets default param group. `ValueFromPipeline`: binds pipeline input. Begin/Process/End: Begin runs once, Process runs per pipeline object, End runs after pipeline finishes.

**PS16** — Providers: abstract data stores as drives. `Get-ChildItem` works on FileSystem, Registry (`HKLM:`), Certificate (`Cert:`), Environment (`Env:`). Registry accessed like FS: `Get-ChildItem HKLM:\SOFTWARE`.

**PS17** — Runspaces: execution environments. `[runspace]`: single thread, `[runspacepool]`: manages multiple runspace threads. `[powershell]`: object to add commands. `ForEach-Object -Parallel` (v7+) uses runspace pool automatically. Manual: create pool, add runspace, invoke, manage threading/serialization.

**PS18** — PSScriptAnalyzer: linting tool. Enforces rules (naming, style, performance). Severity: Error, Warning, Information. Custom rules: C# or PowerShell scripts. Suppress: `#pragma disable` or config file. CI/CD: run in pipeline, fail on errors, generate reports.

**PS19** — `$using:` scope: serializes local variable into remote/session context. `-ArgumentList`: passes values as parameters. Serialization limits: CLIXML depth 64, loses methods/events, converts to hashtables. Complex objects may lose type fidelity.

**PS20** — DSC: declarative config. Configurations: desired state definitions. Resources: building blocks (File, Service, Package). LCM: agent that applies config. WinPS DSC: Windows-only, XML-based. PS7 DSC: cross-platform, YAML/JSON, uses MOF or native formats. Replaced by modern IaC: Terraform, Ansible, ARM/Bicep, but DSC still used in Windows ecosystems.
