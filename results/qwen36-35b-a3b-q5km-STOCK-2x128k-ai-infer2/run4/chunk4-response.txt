G1 — A slice is a runtime descriptor containing a pointer to a backing array, length, and capacity. An array is a fixed-size value type with its data embedded. When you append to a slice at capacity, the runtime allocates a new backing array (typically 2× capacity), copies existing elements, updates the slice header, and returns the new slice.

G2 — `var x int` declares a variable with explicit type and zero value. `x := 0` is a short variable declaration that infers type and requires at least one new variable on the left. You cannot use `:=` outside function bodies, when redeclaring all variables on the left, or when you need to explicitly specify a type (e.g., `var x int = 0` vs `x := 0` where type inference might differ).

G3 — A goroutine is a lightweight, user-space thread managed by the Go runtime. Unlike OS threads (heavy, ~1-2MB stack, 1:1 kernel mapping), goroutines start at ~2KB and grow/shrink dynamically. The GMP model: G = goroutine, M = machine (OS thread), P = processor (execution context/run queue). The scheduler multiplexes Gs onto Ms using Ps, enabling efficient work-stealing and preemption.

G4 — Channels are typed conduits for communication and synchronization. Unbuffered channels block both sender and receiver until both are ready. Buffered channels have a capacity; send blocks only when full, receive blocks only when empty. Sending to a full buffered channel blocks until a receiver consumes an element.

G5 — `context` propagates cancellation, deadlines, timeouts, and request-scoped values across API boundaries. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
client.Do(req) // cancels automatically if timeout hits
```

G6 — Go uses implicit interface satisfaction (duck typing): any type implementing the methods automatically satisfies the interface. Unlike Java/C#, no `implements` keyword is needed. `interface{}` (Go 1.18+) / `any` matches any type. Powerful for generic abstraction, but dangerous because type assertions can panic at runtime and bypass compile-time safety.

G7 — This is a data race. Go's memory model guarantees no cross-goroutine visibility without synchronization. The loop `for !ready {}` may never see `data = "hello"` due to CPU caching/compiler reordering. Fix with `sync.Once`, `atomic.Bool`, or a channel:
```go
var data string
ch := make(chan struct{})
go func() {
    data = "hello"
    close(ch)
}()
<-ch
fmt.Println(data)
```

G8 — `sync.Mutex` provides exclusive access. `sync.RWMutex` allows multiple concurrent readers or one writer. `sync.Map` is optimized for: (1) keys known at compile time, (2) mostly reads with rare writes, or (3) disjoint key sets per goroutine. Trade-offs: `sync.Map` has higher read overhead for small maps and complex internal locking; a regular `map` + `Mutex` is simpler and usually faster for general workloads.

G9 — `go.mod` declares module path, Go version, and direct dependencies. `go.sum` stores cryptographic hashes of dependency versions for integrity verification. `go mod tidy` removes unused dependencies, adds missing ones, and updates versions. MVS (Minimum Version Selection) picks the lowest version of each dependency that satisfies all version constraints in the entire dependency tree.

G10 — `defer` schedules a function call to run after the surrounding function returns. Multiple defers execute in LIFO order. Common loop gotcha: variables captured by deferred closures are evaluated at defer time, not declaration time. Fix by passing as arguments: `defer func(v int) { fmt.Println(v) }(i)` or create a new scope.

G11 — A pointer holds a memory address. Zero value is `nil`. Create a pointer to a struct literal: `p := &MyStruct{Field: value}`. The compiler automatically takes the address of the literal.

G12 — `init()` runs automatically before `main()` after all package variables are initialized. It runs once per package. A package can have multiple `init()` functions; they execute in declaration order. Complex logic should avoid `init()` due to hidden execution order and testing difficulties.

G13 — `make(T, args)` initializes slice, map, or channel and returns the initialized `T` (not a pointer). `new(T)` allocates zeroed memory and returns `*T`. Use `make` for reference types that need initialization; `new` for simple zeroed allocations.

G14 — Go uses explicit error values. `error` is an interface with `Error() string`. Idiomatic: `if err != nil { ... }`. `errors.Is(err, target)` checks if `err` wraps `target`. `errors.As(err, &target)` extracts the concrete type from the error chain. `==` only checks direct equality, failing with wrapped errors.

G15 — Zero values: `map` → `nil` (use `make`), `slice` → `nil` (len=0, cap=0), `channel` → `nil` (blocks forever), `struct` → zero values of each field.

G16 — A race occurs when concurrent goroutines access shared data without synchronization, at least one write. `-race` flag instruments the runtime to detect conflicting accesses and prints stack traces. Example fix with mutex:
```go
var mu sync.Mutex
var counter int
go func() { mu.Lock(); counter++; mu.Unlock() }()
```
Or via channel: `ch := make(chan int, 1); ch <- counter`

G17 — `select` waits on multiple channel operations, like a `switch` for channels. If multiple cases are ready, one is chosen pseudo-randomly. Timeout: `case <-time.After(d):`. Blocks until at least one case is ready or default executes.

G18 — Escape analysis determines if a variable lives on the stack or heap. Escapes if: address taken, returned, stored in heap-allocated struct, or size unknown at compile time. Inspect with `go build -gcflags="-m"`. Matters because heap allocations trigger GC, increasing latency and reducing throughput. Stack allocations are free.

G19 — `reflect.Type` holds type metadata; `reflect.Value` holds the actual value/data. Costs: slow (bypasses compile-time checks), allocates, and disables optimizations. Justified in frameworks, serialization, or when code generation is impractical. Prefer code generation (`go generate`) for performance-critical paths.

G20 — `//go:embed` embeds static files/directories into the binary at compile time. Works with single files, `dir/`, or `**` for recursion. Returns `embed.FS` implementing `io/fs.FS`. Limitations: only static files, no runtime generation, size limits, must be in the same package, and paths are relative to the source file.

R1 — Ownership ensures memory safety without GC. Rules: (1) Each value has exactly one owner. (2) Only one owner at a time. (3) When the owner goes out of scope, the value is dropped. Prevents leaks, dangling pointers, and double-frees.

R2 — `String` is an owned, heap-allocated, mutable UTF-8 string. `&str` is an immutable borrowed string slice. Use `String` when you need ownership or mutation; use `&str` in function signatures to avoid copies and accept both `String` and string literals.

R3 — Borrowing provides references without transferring ownership. `&T`: shared, immutable, multiple allowed. `&mut T`: exclusive, mutable, only one allowed. Rules: no aliasing + mutation simultaneously. The borrow checker enforces these at compile time.

R4 — `Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). `Option<T>` represents `Some(T)` or `None`. `?` propagates errors/returns early. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — `Box<T>`: heap allocation, single owner, used for large/recursive types. `Rc<T>`: reference counting, single-threaded shared ownership. `Arc<T>`: atomic reference counting, thread-safe shared ownership. Use `Box` for ownership, `Rc` for shared read-only, `Arc` for concurrent sharing.

R6 — Traits define shared behavior. Like Go interfaces but explicit. `dyn Trait`: trait object, dynamic dispatch via vtable, enables polymorphism with runtime overhead. `T: Trait`: generic with trait bound, static dispatch via monomorphization, zero-cost. Use generics for performance, trait objects for heterogeneous collections.

R7 — Fails because the compiler cannot determine which input lifetime applies to the return type. Fix with explicit lifetime:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```
Lifetimes tie the return reference to the longer-lived input.

R8 — `Send`: types safe to transfer across threads. `Sync`: types safe to share across threads (`&T: Send` iff `T: Sync`). `Rc<T>` isn't `Send`/`Sync` due to non-atomic ref count. `Arc<T>` uses atomic operations, making it safe for concurrent reference counting and sharing.

R9 — `async` marks a function returning a `Future` (a state machine representing pending work). `await` yields control until the future is ready. The executor (e.g., Tokio) polls futures. Differs from Go: Go uses implicit M:N runtime scheduling; Rust futures are explicit state machines polled by user-provided executors, with no implicit threading.

R10 — `unsafe` bypasses compile-time safety checks. Three things: dereference raw pointers, call `unsafe` functions, implement `unsafe` traits, access/modify `static mut`, violate aliasing rules. Justified for FFI, low-level optimization, or building safe abstractions over unsafe foundations.

R11 — Pattern matching exhaustively checks enum variants. `match` must cover all cases; compiler enforces exhaustiveness and warns on missing branches. `if let` is shorthand for a single case. `match` is preferred for exhaustive logic; `if let` for simple one-case checks.

R12 — `Vec<T>`: heap-allocated, dynamic size. `[T; N]`: stack-allocated (usually), fixed size. When `Vec` exceeds capacity, it allocates a new buffer (typically 2×), copies elements, drops the old buffer, and updates the pointer.

R13 — Enums are algebraic data types; variants can hold data. Unlike C/Java, Rust enums are expressive and memory-efficient. `Option<T>` = `Some(T)` | `None`. Rust has no `null` because `Option` forces explicit handling, eliminating null pointer exceptions.

R14 — `impl` blocks define methods. `&self`: borrows immutably. `&mut self`: borrows mutably. `self`: takes ownership. Associated functions (e.g., `String::new()`) don't take `self`, acting like static constructors or utility functions.

R15 — `#[derive]` auto-implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if the type contains non-derivable fields (e.g., `Fn` closures, raw pointers, or requires custom logic like `Drop` or `Eq` without `PartialEq`).

R16 — `Cow<'a, T>` (Clone-on-Write) holds either `&'a T` (borrowed) or `T` (owned). Useful when a function might return borrowed or owned data. Avoids allocation if input already matches; clones only when mutation is requested, saving memory in read-heavy paths.

R17 — `mod` declares a module, `use` imports items into scope, `pub` exposes them. File system: `mod.rs` or `mod_name/mod.rs`. Rust 2018 changed path resolution: `use` paths are relative to crate root, introduced `crate::`, `super::`, `self::`, and removed `extern crate`.

R18 — `Pin<T>` guarantees a value's memory address won't change. Needed for self-referential structs and async/await, where futures may hold references to their own fields. `Unpin` is auto-implemented; types can opt-out with `!Unpin`. `Pin` ensures `Drop` and `Drop` impls see stable addresses.

R19 — Declarative macros (`macro_rules!`) use pattern matching on token trees. Procedural macros: `derive` (struct/enum), `attribute` (custom attrs), `function-like`. Hygiene ensures macros don't capture or leak identifiers from caller scope, preventing name collisions and enabling safe macro composition.

R20 — Zero-cost abstractions compile to efficient machine code. Iterators: zero overhead, loop unrolling, no bounds checks. Generics: monomorphization generates type-specific code. Traits: static dispatch via monomorphization. Achieves C-like performance while providing safety, composability, and high-level ergonomics.
