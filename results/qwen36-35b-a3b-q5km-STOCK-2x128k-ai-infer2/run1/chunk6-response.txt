JS1 — `var` is function-scoped and hoisted with `undefined`. `let`/`const` are block-scoped and hoisted but enter a Temporal Dead Zone until declaration. `const` prevents reassignment. Hoisting is the JS compilation phase where declarations are moved to the top of their scope before execution.

JS2 — The event loop monitors the call stack and task queues. When the stack is empty, it pushes callbacks from the macrotask queue (setTimeout, I/O). Before each macrotask, it drains the microtask queue (Promise.then, queueMicrotask). Microtasks always run before the next macrotask.

JS3 — A closure is a function that retains access to its lexical scope even after the outer function returns. Example: a counter factory. The classic for-loop bug occurs because `var i` is function-scoped; all callbacks share the same `i` (value 10). Fix: use `let i` (block-scoped) or an IIFE to capture the current value.

JS4 — `Promise` represents an async operation. `async/await` is syntactic sugar that pauses execution until resolution. Errors: use `try/catch` with `await`, or `.catch()` with promises. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all promises, returning an array of `{status, value/reason}` objects.

JS5 — `interface` defines object shapes, supports declaration merging, and is erased at runtime. `type` is a broader alias supporting unions, intersections, tuples, and primitives. Use `interface` for APIs/objects, `type` for unions/primitives. Discriminated unions use a common literal property to narrow types in `switch`/`if` statements.

JS6 — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar over this chain; `extends` sets `[[Prototype]]` and calls the parent constructor.

JS7 — `this` is dynamically bound based on call site. Priority: 1. `new` (constructor instance), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (global/window or `undefined` in strict mode). `bind()` returns a new function with fixed `this`. It cannot be rebound.

JS8 — `WeakRef` holds a weak reference that doesn't prevent GC. `FinalizationRegistry` runs a callback when weakly referenced objects are collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the engine can track GC; when strong references drop, keys are removed automatically.

JS9 — V8 optimizes via hidden classes (shape tracking for fast property access) and inline caching (caches hidden class pointers at call sites). Deoptimization occurs when assumptions break (e.g., dynamic property addition, `delete`, type changes, `with`). Patterns causing deopt: modifying object shapes at runtime, `arguments` object, `eval`.

JS10 — Tree-shaking removes unused exports at build time. It works with ES modules because imports/exports are static and analyzable at compile time. CommonJS uses dynamic `require()`, which executes at runtime, preventing static analysis and making tree-shaking ineffective.

JS11 — `null` is intentional absence; `undefined` is uninitialized. `==` coerces types (`null == undefined` is true); `===` checks type/value (false). `??` returns right operand if left is `null`/`undefined`. `?.` safely accesses nested properties without throwing on `null`/`undefined`.

JS12 — `map()` transforms, `filter()` keeps matching elements, `reduce()` accumulates to a single value. `reduce()` with an initial value prevents errors on empty arrays and sets the accumulator type. `flatMap()` maps then flattens one level; useful for transforming and flattening in a single pass.

JS13 — Template literals use backticks, support `${expr}` interpolation and multi-line strings. Tagged templates call a function with an array of string parts and interpolated values. Example: `html` function that escapes `<>&` to prevent XSS in dynamic content.

JS14 — Destructuring unpacks arrays/objects into variables. Object: `{a, b}` or `{a: x}`. Array: `[a, b]`. Defaults: `const {a = 1} = obj`. Renaming: `{a: newName}`. Rest: `const {a, ...rest} = obj` collects remaining properties. Works identically in arrays.

JS15 — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, maps). Avoid `for...in` on arrays: it iterates keys, not values, includes inherited properties, and doesn't guarantee order.

JS16 — Generics use type parameters for reusable components. Constraints: `T extends SomeType` limits assignable types. Conditional types: `T extends U ? X : Y` for type logic. `infer` extracts types in conditional contexts. Example: `type Unpack<T> = T extends Promise<infer U> ? U : T`.

JS17 — CJS uses dynamic `require()`/`module.exports`, synchronous, Node legacy default. ESM uses static `import`/`export`, async, browser/Node native. Node resolves via `.mjs`/`.cjs` extensions or `"type": "module"` in `package.json` (makes `.js` ESM). `"type": "commonjs"` is default.

JS18 — TS uses structural typing: compatibility based on shape, not names. Excess property checks apply only to object literals assigned to variables/interfaces, not function arguments. `extends` defines assignability; `satisfies` checks type without widening. TS uses bivariance by default; explicit `in`/`out` variance annotations are not supported (unlike C#).

JS19 — `Proxy` wraps objects to intercept operations (get, set, apply, etc.). `Reflect` mirrors Proxy traps and provides default behavior. Example: validation proxy that throws on invalid `set`. Practical uses: reactive frameworks (Vue), immutable data, logging, access control.

JS20 — `SharedArrayBuffer` enables shared memory between main thread and Web Workers. `Atomics` provides atomic operations (load, store, add, wait, notify) with memory barriers. `Atomics.wait` blocks until value changes or timeout; `Atomics.notify` wakes threads. Requires cross-origin isolation headers.

B1 — `$*` expands all args as a single IFS-separated string. `$@` expands each arg as a separate word. `"$@"` preserves each arg as a separate quoted word. `"$*"` joins them into one string. Use `"$@"` for safe arg passing.

B2 — `set -e`: exit on command failure. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the rightmost non-zero exit code. Together, they enforce strict error handling.

B3 — `$(command)` is modern command substitution; `` `command` `` is legacy. `$((expression))` is bash-native arithmetic expansion. `expr` is an external command, slower, with different syntax and exit-code-based success/failure.

B4 — Process substitution `<(cmd)` creates a `/dev/fd/X` file descriptor with the command's output. Used when a command expects file inputs but needs multiple streams. Example: `diff <(sort file1) <(sort file2)`.

B5 — Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous: word splitting breaks on spaces/newlines, glob expansion occurs, and special characters cause errors.

B6 — Here doc `<<EOF` feeds multi-line input to a command. Here string `<<<` feeds a single line. `<<-EOF` strips leading tabs (not spaces) for indentation, keeping scripts readable.

B7 — `cmd > file 2>&1`: stdout → file, then stderr → stdout (now file). `cmd 2>&1 > file`: stderr → original stdout (terminal), then stdout → file (stderr goes to terminal). `cmd &> file`: bash shorthand for both to file. Order matters because redirections evaluate left-to-right.

B8 — ```bash
lock() {
  local lockdir
  lockdir=$(mktemp -d)
  trap 'rm -rf "$lockdir"' EXIT INT TERM
  mkdir "$lockdir" || { echo "Locked"; exit 1; }
  echo "Locked: $lockdir"
}
```
`mkdir` is atomic on POSIX; if it exists, it fails immediately, preventing race conditions. `trap` ensures cleanup on normal exit or signals.

B9 — `'...'`: literal, no expansion. `"..."`: allows variable/command expansion, preserves spaces. No quotes: word splitting and globbing occur. Example: `var="a b"; echo $var` → `a b`; `echo "$var"` → `a b`; `echo '$var'` → `$var`.

B10 — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin: supports `&&`/`||`, regex, no word splitting/globbing, safer for strings and patterns.

B11 — `$?`: last exit code (error handling). `$$`: script PID (logging/locking). `$!`: last background job PID (job control). `$#`: argument count (validation).

B12 — `foo() { ... }` or `function foo { ... }` (latter allows `function foo() {}`). Return values: `return <int>` (exit code), `echo` (stdout), global variables, or `declare -g`. Functions don't have typed returns.

B13 — `PATH` is colon-separated dirs bash searches. Resolves builtins first, then external binaries in `PATH`. Builtins are shell-compiled (fast); externals are separate processes. Check with `type cmd` or `command -v cmd`.

B14 — `trap 'cleanup' EXIT INT TERM`. `ERR` runs on non-zero exit. Signals interrupt execution; handlers run sequentially. Multiple signals queue or are handled based on shell implementation. Use `trap - INT` to reset defaults.

B15 — `xargs` runs commands with args, handles streaming. `find -print0 | xargs -0` safely handles spaces/newlines. `-P N` runs N processes in parallel. Command substitution loads all output into memory first.

B16 — Arrays: `arr=(a b c)`, `${arr[0]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[@]}`, `${!assoc[@]}`. Associative requires declaration, supports string keys, and uses different syntax for iteration.

B17 — Subshell `(...)` runs in a child; changes don't affect parent. Group `{ ...; }` runs in current shell; changes persist. Piping to `while` runs the loop in a subshell, losing variable changes. Fix: `while read; do ...; done < <(cmd)`.

B18 — SIGINT (Ctrl+C, interrupt), SIGTERM (graceful kill), SIGHUP (terminal close), SIGKILL (unhandled, force). Handle graceful shutdown: trap TERM/INT, kill background jobs (`kill %1`), `wait`, then cleanup. Job control uses `jobs`, `fg`, `bg`.

B19 — ```bash
split -l 10000 log.log log.part.
find . -name "log.part.*" -print0 | xargs -0 -P 4 -I {} bash -c 'process "$1" || exit 1' _ {}
cat log.part.* > merged.log
```
Trade-offs: CPU vs I/O, splitting/merging overhead. Error propagation: check exit codes, use temp dirs, aggregate failures, or use `set -o pipefail` in workers.

B20 — `exec` replaces the shell process or redirects FDs. `exec 3>file` opens FD 3; `exec 3>&-` closes it. Coprocess: `coproc cmd` runs cmd in background, connects FDs. Use for persistent IPC without explicit pipes or temp files.

PS1 — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console, bypassing the pipeline. This breaks automation, piping, and redirection.

PS2 — Pipeline streams objects. `ForEach-Object` is a cmdlet, processes element-by-element, supports `-Parallel`. `foreach` is a language construct, requires full array in memory, faster for known collections.

PS3 — `[PSCustomObject]` is ordered, strongly typed, pipeline-friendly. `[hashtable]` is unordered, key-value, no methods. Convert: `[PSCustomObject]@{...}`. Use custom objects for structured data, hashtables for dynamic config.

PS4 — Terminating errors stop execution (catchable). Non-terminating continue (logged). `-ErrorAction` overrides per-command. `$ErrorActionPreference` sets global default. `try/catch` only catches terminating errors.

PS5 — Splatting: `@params` passes a hashtable's keys as named parameters. `func @params`. Differs from single param: passes multiple args at once. Single param would pass the entire hashtable as one argument.

PS6 — `Invoke-Command -ComputerName` runs one-off commands. `Enter-PSSession` creates an interactive session. Uses WS-Management (WinRM) by default. PowerShell 7+ supports SSH transport.

PS7 — Returns an array of strings. `$x.GetType().Name` is `Object[]`. Returns 0 items: `$null`. Correct pattern: `$result = [System.Collections.Generic.List[string]]::new()` or force array `$result = @($result)`.

PS8 — `[scriptblock]` is anonymous code; function is named, supports parameters/pipeline. Pass to remote: `-ArgumentList` or `$using:`. Double-hop: auth fails on second remoting. Solve with `-ArgumentList` (secure) or CredSSP (insecure).

PS9 — `@()` forces array. `[array]` casts to array. Indexing `$null` returns `$null`. Indexing empty array returns `$null`. `@()` ensures consistent array behavior in pipelines.

PS10 — `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive: `-ceq`, `-clike`, `-cmatch`, `-ccontains`, `-cin`. `-contains` checks collection; `-in` checks value.

PS11 — Module: collection of functions/cmdlets. `.psm1`: script code. `.psd1`: manifest (metadata, dependencies). Binary: compiled `.dll`. `Import-Module` loads into session, searches `$env:PSModulePath`.

PS12 — Interpolation: `"..."` expands variables/expressions. `'...'` literal. Expressions: `$(expr)`. Here-string: `@"..."@` for multi-line, preserves formatting and indentation.

PS13 — `Get-Member` shows object properties/methods. Properties: data. Methods: actions. NoteProperties: dynamically added. `Select-Object` picks properties. `Where-Object` filters objects.

PS14 — Classes: v5+, C#-like. Limitations: no multiple inheritance, limited interface support, constructors must match signature, no access modifiers. Use classes for complex data/models, functions for scripting.

PS15 — `CmdletBinding` enables advanced features. `SupportsShouldProcess`: `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: selects params. `ValueFromPipeline`: binds pipeline input. `Begin`/`Process`/`End`: pipeline lifecycle blocks.

PS16 — Providers: abstract data stores. `Get-ChildItem` works on FileSystem, Registry, Cert, Env. Registry accessed via `HKLM:\` or `Registry::`. Treated like files/folders for navigation.

PS17 — Runspaces: execution environments. `[runspace]`: single thread. `[runspacepool]`: thread pool. `[powershell]`: adds pipeline. `ForEach-Object -Parallel`: v7+, easy but limited. Manual runspace: full control, thread-safe, complex.

PS18 — PSScriptAnalyzer: linting tool. Rules: syntax/style checks. Severity: Error, Warning, Information. Custom rules: PowerShell scripts. Suppress: `#pragma disable`, `.editorconfig`. CI/CD: run in pipeline, fail on errors.

PS19 — `$using:` scope serializes variables for remote/parallel. `-ArgumentList` passes values. Serialization limits: CLIXML depth ~64, complex objects may fail. Use simple types or serialize to JSON/CSV.

PS20 — DSC: config management. Configurations: desired state. Resources: components (File, Service). LCM: applies config. WinPS vs PS7: PS7 uses OpenDSC, cross-platform. Replaced by: Ansible, Terraform, Chef, or native cloud IaC.
