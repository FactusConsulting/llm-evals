SC1-A
The failure stems from the Kubernetes Pod Security Standards (PSS) enforcement shift from `baseline` to `restricted`. The `restricted` profile mandates: `runAsNonRoot: true`, explicit `runAsUser` > 0, `allowPrivilegeEscalation: false`, `readOnlyRootFilesystem: true`, and a restricted seccomp profile. The pods have `runAsNonRoot: true` but no explicit `runAsUser`. Kubernetes defaults to the container image's `USER` directive, which is `root` in `cgr.dev/chainguard/static:latest`. This violates the `restricted` policy. Additionally, `restricted` requires `readOnlyRootFilesystem: true`. If the Go/Python apps attempt to write to `/`, `/tmp`, or bind to privileged ports (<1024), the container runtime rejects the operation or the app crashes immediately, resulting in `CrashLoopBackOff`. The upgrade didn't change the images, but the namespace policy enforcement changed, exposing the mismatch.

SC1-C
**Image Fix:** Rebuild the base image with a non-root user (`RUN useradd -u 1000 appuser`), set `USER 1000`, and pin the digest (`cgr.dev/chainguard/static@sha256:...`).
**Manifest Changes:** Add to all containers: `runAsUser: 1000`, `runAsGroup: 1000`, `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`. Add an `emptyDir` volume for `/tmp` if writes are required.
**CI Gate:** Add a `kube-score` or `checkov` step that validates manifests against the `restricted` PSS. Integrate `kyverno` or `opa-gatekeeper` in CI to reject PRs that don't include explicit non-root security contexts.
**Rollout:** Use a rolling update with `maxSurge=25%` and `maxUnavailable=25%`. Monitor `kube_pod_status_phase` and `container_restart_count` metrics. If error rate spikes, pause rollout and revert via `kubectl rollout undo`.

SC2-A
Cross-region PostgreSQL streaming replication is asynchronous by default. WAL segments are shipped from the primary to the replica, but network latency and disk I/O create a lag window. When promoting the replica, any WAL not yet received or replayed is permanently lost. The data loss window equals the replication lag at promotion time. To quantify: check `pg_stat_replication` on the primary for `write_lag`, `flush_lag`, and `replay_lag`. On the replica, compare `pg_last_wal_receive_lsn()` vs `pg_last_wal_replay_lsn()`. The difference in bytes/LSN translates to the lost transaction window.

SC2-C
**RDS Proxy vs PgBouncer:** RDS Proxy pools connections at the database protocol level, handles auth, and reduces connection churn during failover. PgBouncer runs in the app network and can't recover from DB-level connection resets as gracefully. Use RDS Proxy for production.
**Route53 & Retry:** Use Route53 Failover routing with health checks on the RDS endpoint. Implement exponential backoff with jitter in the app connection pool. Ensure all writes are idempotent or wrapped in retryable transactions.
**RPO < 1s:** Asynchronous cross-region replication cannot guarantee <1s RPO. Use **Aurora Global Database**. It replicates data at the storage layer across regions with <1s lag, supports automatic failover in <1 minute, and maintains a single global cluster. Standard RDS cross-region replicas are async and risk data loss during promotion.

SC4-A

4. **IBM MQ Integration:** Legacy protocol. Fix: Use MQ bridge, cloud-native MQ (Amazon MQ), or containerize MQ with persistent volumes.
5. **Bare-Metal Performance:** K8s scheduling overhead. Fix: Use node affinity, dedicated worker nodes, tune JVM heap, and set accurate resource requests/limits.

**SQL Diagnostic Query:**
```sql
SELECT blocked_locks.pid AS blocked_pid,
       blocked_activity.usename AS blocked_user,
       blocking_locks.pid AS blocking_pid,
       blocking_activity.usename AS blocking_user,
       blocked_activity.query AS blocked_statement,
       blocking_activity.query AS current_statement_in_blocking_process
FROM pg_catalog.pg_locks blocked_locks
JOIN pg_catalog.pg_stat_activity blocked_activity ON blocked_activity.pid = blocked_locks.pid
JOIN pg_catalog.pg_locks blocking_locks ON blocking_locks.locktype = blocked_locks.locktype
  AND blocking_locks.database IS NOT DISTINCT FROM blocked_locks.database
  AND blocking_locks.relation IS NOT DISTINCT FROM blocked_locks.relation
  AND blocking_locks.pid != blocked_locks.pid
JOIN pg_catalog.pg_stat_activity blocking_activity ON blocking_activity.pid = blocking_locks.pid
WHERE NOT blocked_locks.granted;
```

SC6-C
**Direct Connect:** Dedicated 10Gbps+ link, BGP routing, lowest latency, predictable cost at scale. Fits zero-trust (app-layer encryption still required). Requires BGP peering and router config.
**Second VPN + ECMP:** Cheap, fast to deploy. IPsec overhead reduces throughput. ECMP balances traffic but doesn't increase aggregate bandwidth beyond tunnel limits. Routing: multiple tunnels, BGP/OSPF.
**Tailscale/Netbird:** WireGuard mesh, zero-config, excellent for dev/test. Not enterprise-grade for 1Gbps backbone or compliance. Overlay routing, no BGP.
**Recommendation:** Direct Connect for production backbone. VPN ECMP for redundancy. Mesh only for dev/staging.

SC7-A
**Manual `tofu apply`:** Bypasses CI, no state locking. Two concurrent applies cause race conditions, state corruption, partial resource creation, or accidental deletions.
**Diverged Helm values:** Untracked changes create environment drift. Hard to reproduce, causes inconsistent deployments, and breaks GitOps reconciliation.

**State Locking:** Prevents concurrent writes. Without it, `tofu apply` can overwrite state files, lose resource IDs, or leave infrastructure in a half-applied state.

SC10-C
**Failover Sequence:**
1. **Detection:** Prometheus/Grafana monitors node/pod health. If >3 consecutive failures + etcd quorum loss, trigger failover.
2. **Validation:** Check for split-brain (Patroni DCS fencing, network partition detection).
3. **DNS Failover:** GSLB (Route53/Azure DNS) updates A/AAAA records to Dallas IP.
4. **Patroni Promotion:** Standby promotes via etcd lock. `synchronous_standby_names` ensures zero data loss.
5. **Redis/RabbitMQ:** Sentinel promotes master. RabbitMQ federation catches up.
6. **MinIO:** Site replication syncs delta. Pre-warmed caches reduce cold start.
7. **State Update:** Ansible/Terraform updates OpenTofu state to reflect new primary.
**Split-Brain:** Patroni etcd DCS uses leader election and fencing. If network partitions, only one side holds etcd lock. Manual override via `patronictl reinit`.
**Failback:** Reverse replication, sync data, update DNS, verify integrity, switch traffic back, decommission old primary.
