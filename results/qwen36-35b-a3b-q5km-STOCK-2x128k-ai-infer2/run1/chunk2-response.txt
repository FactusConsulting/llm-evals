## Kubernetes

**K1** — A **Deployment** manages stateless workloads with interchangeable pods, random names, and no guaranteed startup order. A **StatefulSet** manages stateful workloads with stable, unique network IDs, ordered deployment/scaling, and stable persistent storage per pod.

**K2** — The Endpoint Controller populates the Service's `Endpoints` object with pod IPs. `kube-proxy` watches this and creates iptables/IPVS rules mapping the Service's ClusterIP:Port to the backend pod IPs:Ports. Traffic hitting the ClusterIP is load-balanced across pods via node-level networking.

**K3** — A **PersistentVolume (PV)** is cluster storage provisioned statically or dynamically. A **PersistentVolumeClaim (PVC)** is a user's request for storage. A **StorageClass** defines a template for dynamic PV provisioning. A PVC binds to a PV (or triggers a StorageClass to create one), decoupling storage provisioning from pod lifecycle.

**K4** — 1. `kubectl logs <pod> --previous` to check crash reason. 2. `kubectl describe pod` for Exit Codes, OOMKilled events, or probe failures. 3. Verify resource requests/limits vs node capacity. 4. Check app dependencies, config maps, secrets, and startup commands. 5. Inspect liveness/readiness probe configurations.

**K5** — CoreDNS provides internal DNS resolution for `Service` names and pod FQDNs. If CoreDNS pods are down, internal service discovery fails (pods can't resolve `svc.namespace.svc.cluster.local`), but direct pod IP communication and external DNS resolution remain unaffected.

**K6** — The scheduler uses **filtering** to discard nodes that fail requirements (insufficient resources, taints, node selectors, affinity/anti-affinity). **Scoring** ranks remaining nodes using predicates like `LeastRequestedPriority` (CPU/MEM balance), `NodeAffinity`, `TaintToleration`, `InterPodAffinity`, and `NodeResourcesBalancedAllocation`.

**K7** — Yes, it will schedule. Scheduling uses `requests` (256Mi), not `limits`. 3.5GB + 0.25GB = 3.75GB < 4GB. At runtime, if it uses 600Mi (>512Mi limit), the kubelet enforces the limit, triggers an OOMKilled event, and restarts the container.

**K8** — Client → External LB → Ingress Controller (NGINX) parses the Ingress resource → matches host/path → routes to a Kubernetes **Service** → Service selects pods via **Endpoints** → `kube-proxy` (iptables/IPVS) creates node-level routing rules → traffic hits the target pod IP:port.

**K9** — A **NetworkPolicy** restricts pod-to-pod and pod-to-external traffic using selectors and rules. Default behavior (no policies): all pods can communicate freely. When a policy is applied: only traffic matching the policy is allowed; all other ingress/egress traffic is explicitly denied.

**K10** — **RollingUpdate** gradually replaces old pods with new ones (zero downtime). **Recreate** terminates all old pods before starting new ones (brief downtime). Choose Recreate for single-writer databases, stateful apps requiring atomic config/state replacement, or when zero-downtime isn't feasible.

**K11** — A namespace is a logical cluster partition for resource isolation and multi-tenancy. Default namespaces: `default`, `kube-system`, `kube-public`, `kube-node-lease`.

**K12** — `kubectl describe pod` shows detailed runtime state. Unlike `get`, it reveals: 1. Pod events (scheduling, pull, start, probe failures). 2. Environment variables, volumes, and mount paths. 3. Node assignment, restart count, and container status details (OOMKilled, exit codes).

**K13** — A ConfigMap stores non-sensitive configuration data. Pods consume it via: 1. Environment variables (`envFrom` or `env.valueFrom.configMapKeyRef`). 2. Volume mounts (files appear in the pod's filesystem). 3. Command/arguments (less common).

**K14** — **ClusterIP**: internal-only virtual IP. **NodePort**: exposes the service on a static port on each node's IP. **LoadBalancer**: provisions a cloud provider external LB, routing traffic to NodePort/ClusterIP.

**K15** — A DaemonSet ensures a pod runs on every node (or subset via selector). Use it for cluster-wide daemons: logging agents, metrics collectors, network plugins, or storage drivers. Deployments manage a fixed replica count, not node distribution.

**K16** — **Taints** repel pods from nodes; **tolerations** allow pods to schedule on tainted nodes. **Node affinity** attracts pods to nodes. Taints/tolerations = node-level exclusion/inclusion. Affinity = pod-level preference. Use case taints: mark dedicated GPU nodes. Use case affinity: schedule ML workloads on those nodes.

**K17** — An Operator is a custom controller that manages complex stateful applications using CRDs and domain-specific reconciliation logic. Unlike standard controllers (which sync simple desired vs actual state), Operators automate upgrades, backups, scaling, and self-healing, solving the operational burden of stateful apps.

**K18** — etcd provides linearizable reads and serializable writes. If quorum is lost, the cluster becomes read-only (or completely unavailable depending on config). With 2/3 nodes permanently lost, quorum cannot be restored. Recovery requires restoring from a recent etcd snapshot or adding a new node and bootstrapping from backup.

**K19** — **Role/ClusterRole** define permissions (verbs + resources). **RoleBinding/ClusterRoleBinding** bind roles to users/groups/serviceaccounts. Manifest:
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: dev
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: dev-pod-reader
  namespace: dev
subjects:
- kind: ServiceAccount
  name: developer-sa
  namespace: dev
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — Default `ndots:5` causes the resolver to try 5 parent domains before using search, generating excessive DNS queries for external domains. Fix: set `dnsConfig: ndots: 2` (or lower) in the pod spec, or use FQDNs with a trailing dot to bypass search domains.

## Development

**D1** — `merge` preserves full history with a merge commit. `rebase` rewrites commit history into a linear sequence. Avoid rebasing on shared/public branches or after pushing to remote, as it forces others to rebase and causes history divergence.

**D2** — **TCP**: connection-oriented, reliable, ordered, flow/congestion control. **UDP**: connectionless, unreliable, low-latency. TCP: HTTP, FTP, SMTP. UDP: DNS, VoIP, live streaming, NTP.

**D3** — A race condition occurs when concurrent threads/processes access shared state without synchronization, leading to non-deterministic results. Example: two threads incrementing a shared counter without a mutex, resulting in lost updates.

**D4** — **Symmetric**: single shared key for encryption/decryption. **Asymmetric**: public/private key pair. TLS uses asymmetric crypto for the initial handshake (key exchange & authentication), then switches to symmetric crypto for bulk data transfer (performance).

**D5** — Each Dockerfile instruction creates an immutable image layer. Layer caching reuses unchanged layers. Best practice: order instructions from least to most frequently changing, combine `RUN` commands, and use `.dockerignore` to prevent unnecessary cache invalidation.

**D6** — 1. Check upstream application logs/metrics for errors. 2. Verify resource limits (CPU/memory throttling). 3. Inspect load balancer/ingress health checks and rate limiters. 4. Check dependency health (DB, cache, external APIs). Order: app → infra → network → dependencies.

**D7** — CAP theorem: a distributed system can only guarantee two of three: Consistency, Availability, Partition tolerance. **CP**: banking systems, CockroachDB (prioritize data accuracy over uptime during partitions). **AP**: DNS, Cassandra, DynamoDB (prioritize availability, accept stale reads).

**D8** — **Horizontal**: add more instances/nodes. **Vertical**: increase CPU/RAM of existing instance. Horizontal scaling requires: stateless design, external session storage, load balancers, database sharding/partitioning, and container orchestration.

**D9** — A dynamic named value that influences process behavior. Persist across sessions: add `export VAR=value` to `~/.bashrc` or `~/.profile`, then run `source ~/.bashrc`.

**D10** — **JSON**: strict key-value/array format, universally supported. **YAML**: indentation-based, human-readable, supports comments. JSON advantage: strict parsing & tooling. YAML advantage: readability & less verbosity.

**D11** — REST API: architectural style using standard HTTP methods. **GET**: retrieve resource. **POST**: create new resource. **PUT**: replace/update resource. **DELETE**: remove resource.

**D12** — Locking dependencies to exact versions (e.g., `package-lock.json`, `poetry.lock`). Ensures reproducible builds, prevents unexpected breaking changes, and simplifies debugging across environments.

**D13** — **Compiled**: source code translated to machine code before execution (C, Rust). **Interpreted**: source executed line-by-line by a runtime (Python, JavaScript). Note: many modern languages use JIT compilation (Java, Go).

**D14** — A **reverse proxy** sits in front of servers, routing client requests to backend services. A **forward proxy** sits in front of clients, routing outbound requests (often for filtering/anonymity). Examples: Nginx (SSL termination, load balancing), HAProxy (high-performance TCP/HTTP routing).

**D15** — A deadlock occurs when two+ processes wait indefinitely for each other's resources. Coffman conditions: 1. Mutual exclusion. 2. Hold and wait. 3. No preemption. 4. Circular wait.

**D16** — Eventual consistency guarantees that, without new updates, all replicas will converge to the same state. Cassandra uses tunable consistency levels: `ONE`, `QUORUM`, `LOCAL_QUORUM`, `ALL`, `ANY`. For read-after-write consistency, use `QUORUM` for both reads and writes, or Lightweight Transactions (`SERIALIZABLE`).

**D17** — mTLS authenticates both client and server via X.509 certificates. Handshake: ClientHello → ServerHello+Cert → ServerKeyExchange → ClientKeyExchange+Cert → CertificateVerify → Finished. Used in: service meshes (Istio/Linkerd), internal microservices, zero-trust architectures.

**D18** — A hash table maps keys to values via a hash function. Collisions resolved by **chaining** (linked lists at buckets) or **open addressing** (linear/quadratic probing, double hashing). Time complexity: average O(1) for insert/lookup/delete. Worst O(n) when all keys collide.

**D19** — A circuit breaker prevents cascade failures by stopping calls to a failing service. States: **Closed** (normal), **Open** (failure threshold met, fail fast), **Half-open** (tests with limited requests). Relates to retries: circuit breakers should wrap retry policies; retrying an open circuit wastes resources and amplifies failures.

**D20** — **Optimistic**: assumes no conflict, validates at commit using row versioning/ETags. **Pessimistic**: locks rows during transaction (`SELECT FOR UPDATE`). Choose optimistic for high-read/low-write workloads. Choose pessimistic for high-write contention or critical financial/booking systems.
