## JavaScript / TypeScript

**JS1** `var` is function-scoped and hoisted with initialization (`undefined`). `let`/`const` are block-scoped, hoisted but reside in a Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment. Hoisting: declarations are moved to the top of their scope during compilation before execution.

**JS2** The event loop monitors the call stack and task queues. When the stack empties, it pushes the highest-priority task. Microtasks (Promises, `queueMicrotask`) run immediately after the current stack clears, before any macrotask (setTimeout, I/O, UI render). This ensures async callbacks execute in a deterministic order.

**JS3** A closure is a function that retains access to its lexical scope even when executed outside it. Example: a counter factory. Classic bug: `var i` in a `for` loop shares one reference; `setTimeout` logs the final value (3,3,3). Fix: use `let` (block scope), IIFE, or pass `i` as a 3rd arg to `setTimeout`.

**JS4** `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that pauses execution until resolution. Error handling: `try/catch` with `await`, or `.catch()`/`.catch` on promises. `Promise.all` rejects immediately on first failure. `Promise.allSettled` waits for all, returning `{status, value/reason}` per promise.

**JS5** `interface` defines object shapes, supports declaration merging, and only accepts type definitions. `type` is a broader alias supporting unions, intersections, tuples, and mapped types. Use `interface` for APIs/contracts, `type` for primitives/unions. Discriminated unions: types sharing a common literal property used to narrow the union safely.

**JS6** JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar: `extends` sets `[[Prototype]]`, `super` calls parent constructor, and methods live on the prototype.

**JS7** `this` is dynamically bound based on call site. Priority: 1. `new` (constructor instance), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (`window` or `undefined` in strict mode). `bind()` returns a new function with fixed `this`. It cannot be rebound.

**JS8** `WeakRef` holds a weak reference that doesn't prevent GC. `FinalizationRegistry` triggers a callback when weakly referenced objects are collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the engine can track their lifecycle; when the key is GC'd, the entry is automatically removed.

**JS9** V8 optimizes via hidden classes (shape tracking for fast property access), inline caching (caches hidden class lookups at call sites), and deoptimization (falls back to generic code when assumptions break). Deopt triggers: dynamic property addition/removal, `delete`, type changes, `with`/`eval`, prototype pollution, or `arguments` usage.

**JS10** Tree-shaking removes unused exports at build time. It works with ES modules because imports/exports are static and analyzable at compile time. CommonJS uses dynamic `require()`, evaluated at runtime, so bundlers cannot statically determine what's unused, breaking tree-shaking.

**JS11** `null` is intentional absence; `undefined` is uninitialized. `==` coerces types (`null == undefined` is `true`); `===` checks type+value (`false`). `??` returns right operand if left is `null`/`undefined`. `?.` safely accesses nested properties without throwing on `null`/`undefined`.

**JS12** `map()` transforms, `filter()` keeps matching elements, `reduce()` accumulates to a single value. Initial value in `reduce()` prevents errors on empty arrays and sets accumulator type. `flatMap()` maps then flattens one level; useful for transforming arrays while expanding elements (e.g., splitting strings into arrays).

**JS13** Template literals use backticks, support `${expr}` interpolation and multi-line strings. Tagged templates call a function with an array of string parts and interpolated values. Example: `sql`tag`SELECT * FROM t WHERE id = ${id}``` enables safe parameterization or HTML escaping by processing parts before concatenation.

**JS14** Destructuring unpacks values. Object: `{a, b: renamed} = obj`. Array: `[first, ...rest] = arr`. Defaults: `a = 1`. Rest operator `...` collects remaining elements into an array. Works in function parameters and supports nested patterns.

**JS15** `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, Maps). Avoid `for...in` on arrays: it yields string indices, includes inherited properties, isn't optimized for arrays, and breaks on sparse arrays.

**JS16** Generics use type parameters for reusable code. Constraints: `T extends SomeType`. Conditional types: `T extends U ? X : Y`. `infer` extracts types in conditional contexts. Example: `type Unwrap<T> = T extends Promise<infer U> ? U : T`.

**JS17** CJS uses dynamic `require()`/`module.exports`, synchronous by default, Node legacy. ESM uses static `import`/`export`, async, browser/Node native. Node resolves via `.mjs`/`.cjs` extensions or `"type": "module"` in `package.json` (makes `.js` files ESM by default).

**JS18** Structural typing: compatibility based on shape, not names. Excess property checks apply only to object literals assigned to variables/interfaces, not function arguments. `extends` checks assignability. `satisfies` validates type without widening, preserving the original type. Variance: `in` (contravariant/parameters), `out` (covariant/returns), `in out` (bivariant).

**JS19** `Proxy` wraps objects to intercept operations (get, set, apply, etc.). `Reflect` mirrors Proxy traps and provides default behavior. Example: validation proxy that throws on invalid `set`. Practical uses: reactive frameworks (Vue), immutable data, logging, or access control.

**JS20** `SharedArrayBuffer` shares memory between main thread and Web Workers. `Atomics` provides atomic operations (load, store, add, wait, notify) with sequentially consistent ordering. `Atomics.wait` blocks until value changes or timeout; `Atomics.notify` wakes threads. Requires cross-origin isolation headers.

## Bash

**B1** `$@` expands to separate quoted words (`"$1" "$2"`). `$*` expands to a single quoted string (`"$1 $2 ..."`). `"$@"` preserves individual arguments. `"$*"` joins with the first character of `IFS`.

**B2** `set -e`: exit immediately on command failure. `-u`: treat unset variables as errors. `-o pipefail`: pipeline returns the exit status of the last non-zero command. Together: strict, fail-fast scripting.

**B3** `$(command)` vs `` `command` ``: both are command substitution. `$()` is POSIX-compliant, nestable, and readable. `$((expression))` is arithmetic expansion. `expr` is an external command, slower, and prone to quoting/escaping issues.

**B4** Process substitution `<(...)` creates a temporary file descriptor. Used when a command expects a file argument but needs dynamic input. Example: `diff <(sort file1) <(sort file2)` compares sorted contents without temp files.

**B5** Safe iteration: `while IFS= read -r -d '' file; do ... done < <(find . -print0)`. `for f in $(ls)` is dangerous: breaks on spaces/globs, parses `ls` output (unsafe), misses hidden files, and fails on newlines.

**B6** Here doc `<<EOF` passes multi-line input to stdin. Here string `<<<` passes a single string. `<<-EOF` strips leading tabs (not spaces) for indentation, keeping scripts readable.

**B7** `cmd > file 2>&1`: stdout → file, then stderr → stdout (file). `cmd 2>&1 > file`: stderr → original stdout (terminal), then stdout → file. `cmd &> file`: bash shorthand for the first. Redirections evaluate left-to-right, causing the difference.

**B8** ```bash
lock() {
  local lockdir
  lockdir=$(mktemp -d)
  trap 'rm -rf "$lockdir"' EXIT INT TERM
  if ! mkdir "$lockdir"; then
    echo "Already locked" >&2; exit 1
  fi
}
```
`mkdir` is atomic on POSIX filesystems, avoiding TOCTOU race conditions inherent in file creation.

**B9** Single quotes: literal, no expansion. Double quotes: allow `$`, `` ` ``, `\`, `!`. No quotes: word splitting and globbing. Example: `var="a b"; echo '$var'` → `$var`; `echo "$var"` → `a b`; `echo $var` → `a b` (splits).

**B10** `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash builtin: supports `&&`/`||`, regex, no word splitting/globbing, and is safer for string comparisons.

**B11** `$?`: exit status of last command. `$$`: PID of current script. `$!`: PID of last background job. `$#`: number of positional parameters.

**B12** `func() { ... }` (preferred) or `function func { ... }`. Return values: `return` (exit code 0-255), `echo` to stdout, or global variables. Functions share the parent shell's scope.

**B13** `PATH`: colon-separated directories bash searches for executables. Resolves by checking PATH, then builtins/aliases. Builtin: compiled into shell (fast, no fork). External: separate binary. Check: `type cmd` or `command -v cmd`.

**B14** `trap` registers handlers. `trap 'cleanup' EXIT INT TERM`. `ERR` triggers on non-zero exit. Handlers run LIFO (last registered first). Multiple signals: handled sequentially or ignored based on shell state.

**B15** `xargs` runs commands with arguments, handling whitespace/newlines safely. `find -print0 | xargs -0` handles all filenames. `xargs -P N` runs N processes in parallel. Command substitution loads all output into memory first.

**B16** Arrays: `arr=(a b c)`, `${arr[0]}`, `${#arr[@]}`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${!assoc[@]}`. Associative requires declaration, supports string keys, and uses different syntax for iteration.

**B17** Subshell `(...)` runs in a child process; variable changes are lost. Group `{ ...; }` runs in current shell; variables persist. Piping `cmd | while read; do var=1; done` runs `while` in a subshell. Fix: process substitution `while read; do ... done < <(cmd)`.

**B18** SIGINT (Ctrl+C, interrupt), SIGTERM (graceful stop, catchable), SIGHUP (terminal close/reload), SIGKILL (force kill, uncatchable). Graceful shutdown: trap TERM/INT, kill background jobs, `wait`, cleanup. Job control: `jobs`, `fg`, `bg`, `kill`.

**B19** ```bash
split -l 10000 log.txt part_
find . -name "part_*" -print0 | xargs -0 -P 4 -I {} bash -c 'process "$1" && mv "$1" "$1.done"' _ {}
cat part_*.done > merged.log
```
Trade-offs: CPU parallelism vs I/O overhead. Error propagation: check exit codes, use temp dirs, aggregate failures, and avoid partial merges.

**B20** `exec` replaces the shell process or manipulates file descriptors. `exec 3>file` opens FD 3. `exec 3>&-` closes it. Coprocess: `coproc cmd` creates bidirectional pipe, runs in background, accessible via `${COPROC[0]}` (read) and `${COPROC[1]}` (write). Use for persistent IPC.

## PowerShell

**PS1** `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console, bypassing the pipeline. Matters because pipeline consumers cannot capture `Write-Host` output, breaking chaining and redirection.

**PS2** Pipeline streams objects. `ForEach-Object` processes each object in real-time (memory efficient, streaming). `foreach` statement iterates over a collection in memory (faster for known collections). Use `ForEach-Object` for streaming/large data, `foreach` for performance.

**PS3** `[PSCustomObject]`: ordered, strongly typed, pipeline-friendly. `[hashtable]`: unordered, dynamic, slower. Convert: `[PSCustomObject]@{a=1}`. Use PSCustomObject for APIs/pipelines, hashtable for dynamic config or temporary data.

**PS4** Terminating errors stop execution (throw, `-ErrorAction Stop`). Non-terminating errors continue, set `$Error`. `-ErrorAction` overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors.

**PS5** Splatting: `@params` passes a hashtable as named parameters. Differs from passing a hashtable as a single argument: splatting expands to multiple parameters. Example: `Get-Process @opts`.

**PS6** `Invoke-Command -ComputerName` runs one-off commands remotely. `Enter-PSSession` provides an interactive remote session. Uses WS-Management (WinRM) by default. PowerShell 7+ supports SSH transport.

**PS7** `$result += "one"` creates an array. `return $result` returns an array. `$x.GetType().Name` outputs `Object[]`. If 0 items, returns `$null`. Correct pattern: `[array]$result = @()` or avoid `+=`; use `@()` explicitly to prevent enumeration pitfalls.

**PS8** `[scriptblock]` is a code container; functions are named scriptblocks. Pass to remote via `-ArgumentList` or `$using:`. Double-hop: auth fails when remoting to a second machine. Solve with `-ArgumentList` (pass data, not credentials), CredSSP (insecure), or constrained endpoints.

**PS9** `@()` forces array. `[array]` casts. Single result into array: `@(Get-Item)`. Indexing `$null` throws. Indexing empty array returns `$null`. `@()` prevents pipeline enumeration from breaking array expectations.

**PS10** `-eq` (equal), `-ne` (not), `-like` (wildcard), `-match` (regex), `-contains` (left contains right), `-in` (right contains left). Case-sensitive: `-ceq`, `-clike`, `-cmatch`. `-contains` checks collection membership; `-in` checks value membership (PS 3+).

**PS11** Module: collection of functions/cmdlets. `.psm1`: script module. `.psd1`: manifest (metadata, dependencies). Binary: compiled DLL. `Import-Module` loads into session, searches `$env:PSModulePath`.

**PS12** Interpolation: `"..."` expands variables/expressions. `'...'` literal. Expressions: `$((1+2))` or `${expr}`. Here-string: `@"..."@` for multi-line, preserves formatting and indentation.

**PS13** `Get-Member` shows object properties/methods. Pipeline streams objects; use `Get-Member` to inspect. Properties (data), Methods (actions), NoteProperties (dynamically added). `Select-Object` projects properties; `Where-Object` filters.

**PS14** Classes (v5+): C#-like syntax, limited. No multiple inheritance, no interfaces (PS 7.2+), constructors use `param()`. No access modifiers. Use for structured data/DTOs; functions for logic.

**PS15** `CmdletBinding()` enables advanced features. `SupportsShouldProcess` enables `-WhatIf`/`-Confirm`. `DefaultParameterSetName` sets default param set. `ValueFromPipeline` binds pipeline input. `Begin/Process/End` define pipeline lifecycle.

**PS16** Providers abstract data stores as drives. `Get-ChildItem` works on FileSystem, Registry (`HKLM:`), Cert (`Cert:`), Env (`Env:`). Registry accessed like files: `Get-ChildItem HKLM:\SOFTWARE`.

**PS17** Runspaces: execution contexts. `[runspace]`: single thread. `[runspacepool]`: thread pool. `[powershell]`: command object. `ForEach-Object -Parallel` (PS 7+): simplified parallelism. Manual runspace: more control, complex, requires thread safety.

**PS18** PSScriptAnalyzer: linting tool. Rules: style, performance, correctness. Severity: error, warning, info. Suppress: `#pragma disable`, config file, or IDE. CI/CD: run in pipeline, fail on errors. Custom rules: C# or PowerShell.

**PS19** `$using:` serializes variables into remote/session context. `-ArgumentList` passes values explicitly. Parallel: `$using:` works but has CLIXML depth limits (~1000). Complex objects may lose type fidelity. Use `-ArgumentList` for explicit control.

**PS20** DSC: declarative config. Configurations: desired state. Resources: building blocks (File, Service). LCM: agent that applies config. WinPS DSC: Windows-only, MOF files. PS 7+: cross-platform, JSON/YAML, native improvements. Modern IaC often uses Ansible/Terraform, but DSC remains native for Windows/PS ecosystems.
