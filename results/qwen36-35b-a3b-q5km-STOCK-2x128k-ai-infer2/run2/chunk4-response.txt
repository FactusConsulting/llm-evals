G1 — A slice is a runtime descriptor containing a pointer to a backing array, length, and capacity. An array is a fixed-size value type with its data embedded. When you append to a slice at capacity, the runtime allocates a new backing array (typically 2× capacity), copies existing elements, updates the slice header, and returns the new slice.

G2 — `var x int` declares a variable with explicit type and zero value. `x := 0` is a short variable declaration that infers type and requires at least one new variable on the left. You cannot use `:=` outside function bodies, in `var` statements, or to redeclare an existing variable without introducing a new one.

G3 — A goroutine is a lightweight, user-space thread managed by the Go runtime. Unlike OS threads (heavy, 1:1 kernel mapping), goroutines are multiplexed onto a smaller pool of OS threads. The GMP model: G = goroutine, M = machine (OS thread), P = processor (runtime context/scheduler queue). The scheduler multiplexes Gs onto Ms using Ps, enabling efficient work-stealing and preemption.

G4 — Channels are typed conduits for communication and synchronization. Unbuffered channels block both sender and receiver until both are ready. Buffered channels have a capacity; sends block only when full, receives block only when empty. Sending to a full buffered channel blocks until a receiver consumes an element.

G5 — The `context` package propagates cancellation, deadlines, timeouts, and request-scoped values across API boundaries. Example:
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
client.Do(req) // automatically cancels if timeout hits
```

G6 — Go uses implicit interface satisfaction (duck typing): a type satisfies an interface if it implements the methods. Unlike Java/C#, no `implements` keyword is needed. `interface{}` (Go 1.18+ `any`) matches any type. Powerful for generic abstraction, but dangerous because type assertions can panic at runtime and bypass compile-time safety.

G7 — The code has a data race: `ready` and `data` are accessed concurrently without synchronization. Go's memory model guarantees visibility only through synchronization primitives. Fix with atomics:
```go
var ready atomic.Bool
var data atomic.String
go func() { data.Store("hello"); ready.Store(true) }()
for !ready.Load() {}
fmt.Println(data.Load())
```
Alternatively, use a channel or `sync.Once`.

G8 — `sync.Mutex` provides exclusive locking. `sync.RWMutex` allows multiple concurrent readers or one writer. `sync.Map` is optimized for cases where keys are known at compile time, the map is mostly read, or goroutines access disjoint key sets. Trade-offs: `sync.Map` has higher read latency for common patterns and uses more memory; a regular `map` + `Mutex` is faster for general use.

G9 — `go.mod` declares the module path, Go version, and direct dependencies. `go.sum` stores cryptographic hashes of dependency versions for integrity verification. `go mod tidy` removes unused dependencies, adds missing ones, and updates versions. MVS (Minimum Version Selection) resolves the lowest compatible version for all dependencies to avoid version skew and bloat.

G10 — `defer` schedules a function call to run after the surrounding function returns. Multiple defers execute in LIFO order. Gotcha in loops: closures capture loop variables by reference, so all defers see the final loop value. Fix by passing variables as arguments: `defer func(v int) { ... }(i)` or create a new scope.

G11 — A pointer holds the memory address of a value. Zero value: `nil`. Pointer to a struct literal: `&MyStruct{Field: value}`. Go automatically takes addresses of literals in certain contexts, but `&` is explicit.

G12 — `init()` runs automatically before `main()` at program startup. It executes once per package. A package can have multiple `init()` functions; they run in declaration order. Multiple files in the same package run their `init()` functions in filename order.

G13 — `make(T, args)` initializes slice, map, or channel and returns the initialized `T` (not a pointer). `new(T)` allocates zeroed memory for any type and returns `*T`. Use `make` for reference types that require initialization; `new` for raw allocation.

G14 — Go uses `error` interface (`Error() string`). Idiomatic: `if err != nil { ... }`. `errors.Is(err, target)` checks if `err` wraps `target`. `errors.As(err, &target)` extracts a typed error from the chain. `==` only checks direct equality, not wrapped errors.

G15 — Zero values: `map` → `nil` (use `make`), `slice` → `nil` (len=0, cap=0), `channel` → `nil` (blocks forever), `struct` → zero values of each field.

G16 — A race condition occurs when concurrent goroutines access shared data without synchronization, causing undefined behavior. `-race` flag instruments the runtime to detect conflicting reads/writes. Fix with `sync.Mutex` (lock around shared access) or channels (communicate by sharing memory).

G17 — `select` waits on multiple channel operations, like a `switch` for channels. If multiple cases are ready, one is chosen pseudo-randomly. Timeout: `case <-time.After(d):`. Blocks until at least one case is ready or default is present.

G18 — Escape analysis determines whether variables allocate on the stack or heap. Escapes if: address taken, returned, stored in heap-allocated struct, or size unknown at compile time. Inspect with `go build -gcflags="-m"`. Matters because heap allocations trigger GC, impacting latency and throughput.

G19 — `reflect.Type` holds type metadata; `reflect.Value` holds the actual value/data. Costs: slow, bypasses compile-time checks, causes allocations. Justified in frameworks, serialization, or when code generation isn't feasible. Prefer code generation for performance-critical paths to avoid reflection overhead.

G20 — `go:embed` embeds compile-time known files/directories into the binary. Works with `//go:embed pattern`. Directories embed recursively. Limitations: only static files, no runtime generation. Returns `embed.FS` which implements `io/fs.FS`, enabling standard filesystem APIs (`Open`, `ReadDir`, etc.) on embedded data.

R1 — Ownership ensures memory safety without a GC. Rules: 1) Each value has exactly one owner. 2) Only one owner at a time. 3) Owner drops value when out of scope. Prevents leaks, dangling pointers, and double-frees.

R2 — `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is a borrowed string slice (reference to UTF-8 bytes). Use `String` when you need ownership/modification; use `&str` in signatures for read-only access to avoid allocations and enable borrowing.

R3 — Borrowing allows temporary access without transferring ownership. Rules: 1) Either one `&mut T` or any number of `&T`. 2) References must always be valid. The borrow checker enforces these at compile time, preventing data races and use-after-free.

R4 — `Result<T, E>` represents success (`Ok(T)`) or error (`Err(E)`). `Option<T>` represents `Some(T)` or `None`. `?` propagates errors/returns early. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — `Box<T>`: single-owner heap allocation (use for large/recursive types). `Rc<T>`: reference-counted, single-threaded shared ownership. `Arc<T>`: atomic reference-counted, thread-safe shared ownership. Use `Arc` when sharing across threads; `Rc` for single-threaded sharing.

R6 — Traits define shared behavior. Unlike Go's implicit interfaces, Rust requires explicit `impl Trait for Type`. `dyn Trait` creates a trait object (dynamic dispatch, vtable, heap-allocated, allows heterogeneous collections). `T: Trait` uses static dispatch (monomorphization, zero-cost, type-specific code).

R7 — Fails because the compiler can't determine which input lifetime the return value should borrow. Fix with explicit lifetime annotation:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — `Send`: type can be transferred across threads. `Sync`: type can be shared via `&T` across threads. `Rc<T>` isn't `Send`/`Sync` due to non-atomic reference counting. `Arc<T>` uses atomic ref counting, making it `Send`+`Sync` (if `T` is).

R9 — `async fn` returns a `Future` (state machine). `await` yields control when the future is blocked. The executor (e.g., Tokio) polls futures, manages I/O, and schedules them on threads. Differs from Go: Rust uses explicit futures + external executor with zero hidden allocations; Go uses runtime-managed M:N goroutines with implicit scheduling.

R10 — `unsafe` bypasses compiler safety checks. Three things: 1) Dereference raw pointers. 2) Call `unsafe` functions. 3) Implement `unsafe` traits. Justified when interfacing with C, building safe abstractions, or performance-critical code where safety is proven.

R11 — Pattern matching exhaustively handles enum variants. `match` requires all variants; `if let` is shorthand for a single-arm match. Compiler enforces exhaustiveness in `match` (must handle all variants or use `_`), preventing unhandled cases.

R12 — `Vec<T>`: heap-allocated, dynamic size. `[T; N]`: stack-allocated (usually), fixed size. When `Vec` exceeds capacity, it reallocates (typically 2×), copies elements, and drops old allocation.

R13 — Enums are algebraic data types that can hold data per variant. Unlike C/Java, they're exhaustive, can be generic, and integrate with pattern matching. `Option<T>` = `Some(T)` or `None`. Rust has no `null`, forcing explicit handling and preventing null pointer exceptions.

R14 — `impl` blocks define methods. `&self`: borrowed, read-only. `&mut self`: mutable borrow. `self`: takes ownership. Associated functions (e.g., `String::new()`) don't take `self`, acting like static constructors.

R15 — `#[derive]` auto-implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Can't derive if trait requires custom logic, contains unimplementable fields (e.g., `Fn` closures, raw pointers for `Send`/`Sync`), or needs conditional behavior.

R16 — `Cow<'a, T>` (Clone on Write) borrows data by default, clones only on mutation. Useful for functions returning owned or borrowed data. Example: parsing config where defaults are borrowed, but user overrides clone. Avoids allocation when no mutation occurs.

R17 — `mod` declares a module, `use` brings items into scope, `pub` exposes items. File system: `mod.rs` or `mod_name/mod.rs`. Rust 2018 changed path resolution (`crate::`, `super::`, `self::`), removed `extern crate`, and allowed modules to be declared in root or separate files.

R18 — `Pin<T>` guarantees the value behind the pointer won't be moved. Needed for self-referential structs and async/await (futures may contain internal pointers). `Unpin` is a marker trait indicating pinning doesn't matter. `Pin` ensures methods don't move the value, preserving internal pointer validity.

R19 — Declarative macros (`macro_rules!`) use pattern matching and repetition for compile-time code generation. Procedural macros (derive, attribute, function-like) operate on ASTs. Hygiene rules prevent macro-expanded code from accidentally capturing or rebinding variables from the caller's scope.

R20 — Zero-cost abstractions compile to efficient machine code. Iterators use loop unrolling and eliminate bounds checks. Generics use monomorphization (type-specific code generation). Traits use static dispatch via monomorphization. Together, they provide high-level ergonomics with performance comparable to hand-written C.
