## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted with `undefined` initialization. `let`/`const` are block-scoped, hoisted but in a Temporal Dead Zone (TDZ) until declaration. `const` prevents reassignment of the binding (not the value for objects). Hoisting moves declarations to the top of their scope during compilation; `var` initializes to `undefined`, while `let`/`const` remain uninitialized until execution reaches them.

**JS2** — The event loop monitors the call stack and task queues. When the stack is empty, it pushes the next macrotask (setTimeout, I/O, UI) onto the stack. After each macrotask, it drains the entire microtask queue (Promise.then, queueMicrotask, MutationObserver) before returning to the macrotask queue. This ensures async promise callbacks run before UI updates or timers.

**JS3** — A closure is a function that retains access to its lexical scope even when executed outside it. Example: `function makeCounter() { let i=0; return () => ++i; }`. Classic bug: `for (var i=0; i<3; i++) setTimeout(()=>console.log(i), 0)` logs `3,3,3` because `var` is function-scoped and all closures share the same `i`. Fix: use `let` (block-scoped), IIFE, or `setTimeout(..., 0, i)` to capture the value.

**JS4** — `Promise` represents an async operation's eventual result. `async/await` is syntactic sugar that pauses execution until the promise settles, making async code read synchronously. Error handling: `try/catch` with `await`, or `.catch()`/second `.then()` argument. `Promise.all` rejects immediately on first rejection. `Promise.allSettled` waits for all promises, returning an array of `{status, value/reason}` objects.

**JS5** — `interface` defines object shapes, supports declaration merging/extension, and erases at runtime. `type` creates aliases, supports unions, intersections, tuples, and mapped types. Use `interface` for public APIs/objects, `type` for primitives, unions, or utility types. Discriminated unions: types sharing a common literal property (e.g., `type: 'a' | 'b'`) used with `switch`/`if` for type narrowing.

**JS6** — JS uses prototypal inheritance: objects delegate property lookups to their `[[Prototype]]`. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are syntactic sugar: `class A extends B` sets `A.prototype.__proto__ = B.prototype`, and `super` calls the parent constructor/method. Classes don't introduce a new inheritance model.

**JS7** — `this` is determined by call site. Priority order: 1. `new` (constructor instance), 2. Explicit (`bind`/`call`/`apply`), 3. Implicit (`obj.method()`), 4. Default (global/window or `undefined` in strict mode). `bind()` returns a new function with `this` permanently bound. It cannot be re-bound; subsequent `call`/`apply`/`bind` calls are ignored.

**JS8** — `WeakRef` holds a weak reference that doesn't prevent garbage collection. `FinalizationRegistry` registers a callback when weakly referenced objects are collected. Use for caches, observers, or avoiding memory leaks. `WeakMap` keys must be objects so the GC can track them; when a key is collected, the entry is automatically removed, preventing memory leaks from orphaned data.

**JS9** — V8 optimizes via: Hidden Classes (shape optimization for fast property access), Inline Caching (caches hidden class pointers at call sites to skip prototype lookups), and Deoptimization (reverts to slower code when assumptions break). Deopt triggers: dynamic property addition, type polymorphism, `eval`, `with`, `arguments` object, or changing prototype chains.

**JS10** — Tree-shaking removes unused exports at build time. It works with ES Modules because imports/exports are static and analyzable at compile time. CommonJS uses dynamic `require()`, evaluated at runtime, so bundlers can't statically determine dependencies, making dead code elimination ineffective.

**JS11** — `null` is intentional absence; `undefined` is uninitialized/missing. `==` coerces types (`null == undefined` is `true`); `===` checks type and value (`false`). `??` returns right operand if left is `null`/`undefined` (ignores `0`/`""`). `?.` safely accesses nested properties without throwing on `null`/`undefined`.

**JS12** — `map()` transforms elements, `filter()` keeps matches, `reduce()` accumulates to a single value. Initial value in `reduce()` prevents `undefined` on empty arrays and sets accumulator type. `flatMap()` maps then flattens one level; useful for transforming arrays and flattening results simultaneously (e.g., splitting strings into words).

**JS13** — Template literals use backticks, support `${expr}` interpolation and multi-line strings. Tagged templates call a function with an array of string parts and interpolated values. Example: `html`<div>${name}</div>` passes `["<div>","</div>"]` and `name` to `html()`, which can escape HTML to prevent XSS.

**JS14** — Destructuring unpacks values. Object: `{a, b} = obj`. Array: `[a, b] = arr`. Defaults: `{a = 1} = obj`. Renaming: `{a: newName} = obj`. Rest: `{...rest} = obj` or `[...rest] = arr` collects remaining elements into a new array/object.

**JS15** — `for...in` iterates over enumerable string keys (including inherited). `for...of` iterates over iterable values (arrays, strings, Maps). Avoid `for...in` on arrays because it iterates keys, not values, includes inherited properties, and doesn't guarantee order.

**JS16** — Generics: `function id<T>(x: T): T`. Constraints: `function log<T extends string>(x: T)`. Conditional types: `type NonNull<T> = T extends null ? never : T`. `infer`: extracts types in contexts: `type Elem<T> = T extends (infer U)[] ? U : T`. Practical: type-safe APIs, utility types, conditional mappings.

**JS17** — CommonJS: dynamic, synchronous, `require`/`module.exports`, Node legacy default. ES Modules: static, async, `import`/`export`, browser/Node native. `"type": "module"` in `package.json` tells Node to treat `.js` as ESM. Node supports both via extensions (`.cjs`/`.mjs`) or config. ESM enables tree-shaking and top-level await.

**JS18** — Structural typing: compatibility based on shape, not names. Excess property checks apply only to object literals assigned to variables/interfaces, not function arguments. `extends`: type relationship (assignability). `satisfies`: checks type without widening, preserves original type. Variance: `in` (contravariant, parameters), `out` (covariant, return types), `in out` (bivariant). TS 4.7+ enforces stricter variance and introduces `satisfies`.

**JS19** — `Proxy` intercepts object operations (get, set, apply, etc.). `Reflect` mirrors Proxy traps and provides default behavior. Example: validation proxy intercepts `set`, checks value type before assignment. Practical: reactive frameworks (Vue 3), immutable data, logging, access control.

**JS20** — `SharedArrayBuffer` shares memory between main thread and Web Workers. `Atomics` provides atomic operations for synchronization. Ordering: sequential consistency for Atomics operations. `Atomics.wait` blocks until value changes or timeout. `Atomics.notify` wakes waiting threads. Requires Cross-Origin Isolation (COOP/COOP headers) for security.

## Bash

**B1** — `$@` expands to separate quoted arguments (`"$1" "$2"`). `$*` expands to a single quoted string (`"$1 $2 ..."`). `"$@"` preserves each argument individually. `"$*"` joins them with the first character of IFS.

**B2** — `set -e`: exit immediately on command failure. `set -u`: treat unset variables as errors. `set -o pipefail`: pipeline returns the exit status of the last non-zero command. Together: strict, fail-fast scripting.

**B3** — `$(command)` and `` `command` ``: command substitution. `$(...)` is preferred (nested, readable, POSIX). `$((expression))`: arithmetic expansion. `expr`: external command for arithmetic/string ops, slower, less safe, requires escaping.

**B4** — Process substitution `<(...)` creates a file descriptor from command output. Used when a command expects a file but needs dynamic data. Example: `diff <(sort file1) <(sort file2)` compares sorted contents without temp files.

**B5** — Use `find . -print0 | while IFS= read -r -d '' f; do ...` or globbing `for f in *; do ...`. `for f in $(ls)` is dangerous because word splitting breaks on spaces/newlines, and it parses output instead of iterating files safely.

**B6** — Here document `<<EOF` passes multi-line string as stdin. Here string `<<<` passes a single string. `<<-EOF` strips leading tabs (not spaces) for indentation, keeping scripts readable.

**B7** — `cmd > file 2>&1`: stdout → file, then stderr → wherever stdout points (file). `cmd 2>&1 > file`: stderr → terminal (stdout's original location), then stdout → file. `cmd &> file`: bash shorthand for `> file 2>&1`. First two differ because redirections evaluate left-to-right.

**B8** — `mkdir` is atomic on POSIX filesystems, preventing race conditions. Example:
```bash
lockfile=$(mktemp -d)
trap 'rm -rf "$lockfile"' EXIT INT TERM
if ! mkdir "$lockfile" 2>/dev/null; then
  echo "Locked" >&2; exit 1
fi
# critical section
```
`mkdir` succeeds only if the directory doesn't exist, guaranteeing exclusive access.

**B9** — Single quotes `'...'`: literal, no expansion. Double quotes `"..."`: allow variable/command expansion, preserve spaces. No quotes: word splitting and globbing occur. Example: `var="hello world"; echo '$var'` → `$var`; `echo "$var"` → `hello world`; `echo $var` → `hello world` (splits into two args).

**B10** — `[ -f file ]`, `[ -d dir ]`, `[ -r file ]`. `[[ ]]` is a bash keyword: supports `&&`, `||`, `=~`, no word splitting/globbing, safer. `[` is a POSIX builtin/external command, stricter syntax.

**B11** — `$?`: exit status of last command (error checking). `$$`: PID of current shell (logging/temp files). `$!`: PID of last background process (job control). `$#`: number of positional parameters (argument validation).

**B12** — `func() { commands; }` or `function func { commands; }`. Return values: `return <int>` (exit code 0-255). Use `echo` or global variables for data. Bash functions share scope with the caller.

**B13** — PATH: colon-separated directories bash searches for executables. Resolves: PATH → builtins → aliases. Builtin: compiled into shell (`cd`, `echo`). External: separate binary. Check with `type` or `command -v`.

**B14** — `trap 'commands' SIGNAL`. `EXIT`: normal/abnormal exit. `ERR`: command failure. `INT`/`TERM`: signals. Execution order: traps run in LIFO order for the same signal. `ERR` runs before `EXIT` if a command fails.

**B15** — `xargs` builds/executes commands from stdin. Command substitution evaluates and substitutes output. `xargs -0` + `find -print0` handles spaces/newlines safely. `xargs -P N`: runs N processes in parallel.

**B16** — Arrays: `arr=(a b c)`, `${arr[0]}`, `${#arr[@]}`, `arr+=("d")`. Associative: `declare -A assoc`, `assoc[key]=val`, `${assoc[key]}`, `${!assoc[@]}`. Associative requires `declare -A`, supports string keys, and uses different syntax for iteration.

**B17** — Subshell `(...)`: runs in child process, variable changes lost. Group `{ ...; }`: runs in current shell, variables persist. Piping to `while` creates a subshell, so variable changes inside are lost. Fix: `while ...; do ...; done < <(command)` or redirect.

**B18** — Signals: `SIGINT` (Ctrl+C, interrupt), `SIGTERM` (graceful stop), `SIGHUP` (terminal hangup), `SIGKILL` (unconditional kill, can't be caught). Handle graceful shutdown: trap `TERM`/`INT`, kill background jobs, `wait`, cleanup. Use `wait` to monitor children.

**B19** — Script: `split -l 10000 log.log part_`, `find . -name "part_*" -print0 | xargs -0 -P 4 -I {} bash process.sh {}`, merge results. Trade-offs: CPU vs I/O, splitting/merging overhead. Error propagation: check exit codes, use temp dirs, aggregate errors, exit non-zero if any fail.

**B20** — `exec` replaces the current shell or redirects file descriptors. `exec 3>file` opens fd 3. `exec 3>&-` closes it. Coprocess: `coproc CMD` creates bidirectional pipe. Use for persistent communication with external tools without spawning new processes repeatedly.

## PowerShell

**PS1** — `Write-Output`: sends objects to the pipeline. `Write-Host`: writes directly to the console, bypassing the pipeline. Matters because `Write-Host` breaks pipeline chaining, can't be redirected/captured, and mixes output streams.

**PS2** — Pipeline: streams objects between cmdlets. `ForEach-Object`: processes each object in the pipeline (streaming, memory-efficient). `foreach` statement: loads entire collection into memory, iterates. Use `ForEach-Object` for large streams, `foreach` for small collections or when modifying the collection during iteration.

**PS3** — `[PSCustomObject]`: strongly typed, ordered, pipeline-friendly, supports methods/properties. `[hashtable]`: unordered, untyped, faster for lookups. Convert: `[PSCustomObject]@{Key="Val"}` or `@{Key="Val"} | ForEach-Object {[PSCustomObject]$_}`. Use custom objects for output/pipelines, hashtables for config/lookups.

**PS4** — Terminating: stops execution (exceptions, errors). Non-terminating: continues, sets `$Error[0]`. `-ErrorAction`: overrides `$ErrorActionPreference`. `try/catch` only catches terminating errors. Use `-ErrorAction Stop` to convert non-terminating to terminating for `try/catch`.

**PS5** — Splatting: `@params` passes a hashtable's keys as named parameters. Example: `Get-ChildItem @params`. Differs from passing a hashtable as a single parameter: splatting expands keys to named parameters, enabling dynamic parameter passing and cleaner code.

**PS6** — `Invoke-Command -ComputerName`: runs one-off commands remotely. `Enter-PSSession`: interactive remote session. Protocol: WinRM (HTTP/HTTPS) by default, SSH in PS 7+. WinRM is the underlying service; SSH is an alternative transport in PS 7+.

**PS7** — Pipeline outputs arrays as separate objects. `$result += "one"` creates an array. `return $result` enumerates and outputs each element. `$x.GetType().Name` → `Object[]`. If 0 items, returns `$null`. Correct pattern: `[array]$result = @()` or `return ,$result` to prevent enumeration.

**PS8** — `[scriptblock]`: code container, can be passed around. Functions are named scriptblocks with parameters. Pass to remote: `Invoke-Command -ScriptBlock $sb -ArgumentList $args`. Double-hop: auth fails when remoting to a second server. Solve with CredSSP (less secure) or `-ArgumentList` to pass data directly, or use constrained endpoints.

**PS9** — `@()` forces array. `[array]` casts to array. Single result into array: `@($single)`. Indexing `$null` → error. Indexing empty array → `$null`. `@()` prevents enumeration pitfalls and ensures consistent array behavior.

**PS10** — `-eq`: equality (type-aware, array-aware). `-like`: wildcard match. `-match`: regex. `-contains`/`-in`: membership. Case-sensitive: `-ceq`, `-clike`, `-cmatch`, `-ccontains`, `-cin`. `-contains` checks if collection contains value (`$col -contains $val`). `-in` checks if value is in collection (`$val -in $col`).

**PS11** — Module: collection of cmdlets/functions. `.psm1`: script module (code). `.psd1`: manifest (metadata, dependencies). Binary: compiled DLL. `Import-Module`: loads module, searches `$env:PSModulePath`, runs `.psd1` or `.psm1`.

**PS12** — Interpolation: `"Hello $name"`. `"..."` expands variables/expressions. `'...'` literal. Expressions: `"Value: $(Get-Date)"`. Here-string: `@"..."@` for multi-line, preserves formatting, supports interpolation.

**PS13** — `Get-Member`: shows object properties/methods. Pipeline: stream objects, pipe to `Get-Member` to inspect. Properties: data. Methods: actions. NoteProperties: added dynamically. `Select-Object`: picks properties. `Where-Object`: filters objects.

**PS14** — Classes: v5+, C#-like syntax. Limitations: no multiple inheritance, limited interface support, constructors must match signature, no access modifiers (public by default). Use classes for complex data models, functions for scripting/utility.

**PS15** — `CmdletBinding()`: enables advanced features. `SupportsShouldProcess`: enables `-WhatIf`/`-Confirm`. `DefaultParameterSetName`: sets default param group. `ValueFromPipeline`: binds pipeline input. `Begin/Process/End`: Begin runs once, Process runs per pipeline object, End runs once after pipeline.

**PS16** — Providers: abstract data stores as drives. `Get-ChildItem` works on FileSystem, Registry (`HKLM:`), Certificates (`Cert:`), Environment (`Env:`). Registry accessed like files: `Get-ChildItem HKLM:\SOFTWARE`.

**PS17** — Runspaces: execution environments. `[runspace]`: single. `[runspacepool]`: manages multiple. `[powershell]`: object to add commands. `ForEach-Object -Parallel` (v7+): built-in parallelism with thread pool. Manual runspace: more control, complex setup, better for PS 5.1.

**PS18** — PSScriptAnalyzer: linting tool. Enforces standards via rules (naming, style, performance). Severity: Error, Warning, Information. Custom rules: C# or PowerShell. Suppress: `#pragma` or `.psake.ps1` config. CI/CD: run in pipeline, fail on errors.

**PS19** — `$using:`: serializes local variable into remote session/job. `-ArgumentList`: passes values as parameters. Serialization limits: CLIXML depth (default 64), complex objects may fail or lose types. Use `-ArgumentList` for better control, avoid deeply nested objects.

**PS20** — DSC: declarative config management. Configurations: desired state definitions. Resources: building blocks (File, Service, Package). LCM: agent that applies config. WinPS vs PS7: PS7 uses OpenDSC, cross-platform, modular. Replaced by: Ansible, Terraform, Chef, or native cloud IaC tools.
