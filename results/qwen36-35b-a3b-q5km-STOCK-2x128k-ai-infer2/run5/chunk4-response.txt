G1 — **Slice vs Array**: Arrays are fixed-size value types (`[N]T`). Slices are dynamic, reference-like headers containing a pointer, length, and capacity (`[]T`). When appending to a slice at capacity, Go allocates a new backing array (typically doubling capacity), copies existing elements, and returns a new slice pointing to it.

G2 — **`var x int` vs `x := 0`**: `var` declares with explicit type and zero-initialization. `:=` is short variable declaration: infers type, requires at least one new variable on the left. Cannot use `:=` outside functions, when redeclaring existing variables without introducing a new one, or when type inference is ambiguous.

G3 — **Goroutines vs OS Threads**: Goroutines are lightweight (~2KB initial stack) managed by the Go runtime. OS threads are heavy (~1-2MB stack) managed by the kernel. **GMP Model**: `G` = goroutine, `M` = machine (OS thread), `P` = processor (scheduler context). The runtime scheduler multiplexes Gs onto Ms using Ps, enabling work-stealing and efficient concurrency without blocking OS threads.

G4 — **Channels**: Typed conduits for goroutine communication. **Unbuffered**: blocks sender until receiver is ready. **Buffered**: has capacity; send blocks only when full, recv blocks only when empty. Sending to a full buffered channel blocks until space opens or the channel is closed.

G5 — **Context**: Carries deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
client.Do(req) // automatically cancels if timeout hits
```

G6 — **Interface Satisfaction**: Implicit duck typing; a type satisfies an interface if it implements the method set. Differs from Java/C# (no `implements` keyword, no declaration required). `interface{}` (Go 1.17) / `any` (Go 1.18+) accepts any type. Powerful for flexibility, dangerous because type assertions can panic and compile-time safety is lost.

G7 — **Memory Model & Race**: The code has a data race. Without synchronization, the compiler/CPU may reorder writes, and the reading goroutine may see `ready=true` before `data` is written. **Fixes**: Use `sync.Once` to signal readiness, `atomic.Bool` for `ready`, or a channel to pass `data` directly.

G8 — **Mutex vs RWMutex vs sync.Map**: `sync.Mutex` is exclusive; `sync.RWMutex` allows concurrent reads or exclusive writes. `sync.Map` is optimized for read-heavy workloads, compile-time-known keys, or disjoint key sets. Trade-offs: `sync.Map` has higher overhead per operation and worse cache locality; a regular `map` + `Mutex` is faster for dense, write-heavy, or hot-path scenarios.

G9 — **Go Modules**: `go.mod` declares module path, Go version, and direct dependencies. `go.sum` stores cryptographic checksums of all dependency versions. `go mod tidy` removes unused deps, adds missing ones, and updates `go.sum`. **MVS** (Minimum Version Selection) picks the lowest version of each dependency that satisfies all direct/indirect requirements, preventing unnecessary upgrades.

G10 — **Defer**: Schedules function execution until the surrounding function returns. Executes in LIFO order. **Loop gotcha**: Variables captured by deferred closures are evaluated at defer time, not declaration time. Fix by passing as arguments: `defer func(v int) { fmt.Println(v) }(i)`.

G11 — **Pointers**: Variables storing memory addresses. Zero value: `nil`. Pointer to struct literal: `&MyStruct{Field: value}`.

G12 — **`init()`**: Runs automatically before `main()`, once per package. Multiple `init()` functions execute in declaration order. Can be used for setup but discouraged for complex logic due to hidden execution order.

G13 — **`make` vs `new`**: `make` initializes slice, map, or channel (returns initialized value, not pointer). `new` allocates zeroed memory for any type and returns a pointer. `make` is for built-in reference types; `new` is generic but rarely idiomatic.

G14 — **Error Handling**: Explicit, no exceptions. `error` interface: `Error() string`. Idiomatic: `if err != nil { ... }`. `errors.Is(err, target)` checks against wrapped error chains. `errors.As(err, &target)` extracts specific error types from chains. `==` only matches exact instances, failing with wrapped errors.

G15 — **Composite Zero Values**: `map` → `nil`, `slice` → `nil` (len=0, cap=0), `channel` → `nil`, `struct` → zeroed fields.

G16 — **Race Conditions**: Concurrent unsynchronized access to shared data with at least one write. `-race` flag instruments runtime to detect conflicting accesses. Fix with `sync.Mutex` (lock around shared access) or channels (communicate by sharing memory, don't share memory by communicating).

G17 — **`select`**: Waits on multiple channel operations. Differs from `switch`: evaluates channel readiness, not values. If multiple cases ready, picks one pseudo-randomly. Timeout: `case <-time.After(d):`.

G18 — **Escape Analysis**: Compiler decides stack vs heap allocation. Escapes if: address taken, returned, stored in heap-allocated struct, or size unknown at compile time. Inspect: `go build -gcflags="-m"`. Matters because heap allocations trigger GC, impacting latency and throughput.

G19 — **Reflection**: `reflect.Type` holds type metadata; `reflect.Value` holds value + operations. Costs: slow, bypasses compile-time checks, allocates. Justified for serialization, testing, or generic-like frameworks. Prefer `go generate`/code generation for performance-critical paths.

G20 — **`go:embed`**: Embeds files/dirs into binary at compile time. `//go:embed pattern` binds to `embed.FS`. Works for single files, directories (`dir/*`), and implements `io/fs.FS`. Limitations: only compile-time known files, no runtime generation, binary size increases, requires careful security review for sensitive paths.

R1 — **Ownership**: System ensuring memory safety without GC. Rules: 1) Each value has exactly one owner. 2) Only one owner at a time. 3) Owner drops value when out of scope.

R2 — **`String` vs `&str`**: `String` is owned, heap-allocated, mutable. `&str` is a borrowed, immutable string slice. Use `String` for ownership/modification. Use `&str` in function signatures to accept both `String` and `&str` without allocations (often via `impl AsRef<str>`).

R3 — **Borrowing & Borrow Checker**: Access data without taking ownership. Rules: 1) Either one `&mut T` or multiple `&T` (never both). 2) References must always be valid. Borrow checker enforces these at compile time, preventing use-after-free and data races.

R4 — **`Result`/`Option`/`?`**: `Result<T, E>` = `Ok(T)` or `Err(E)`. `Option<T>` = `Some(T)` or `None`. `?` propagates errors/returns early. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — **`Box`/`Rc`/`Arc`**: `Box<T>`: heap allocation, single owner. `Rc<T>`: reference counting, single-threaded shared ownership. `Arc<T>`: atomic reference counting, thread-safe shared ownership. Use `Box` for large/recursive types, `Rc` for shared read-only single-threaded, `Arc` for shared across threads.

R6 — **Traits vs Go Interfaces**: Traits require explicit `impl Trait for Type`. Go uses implicit satisfaction. `dyn Trait`: dynamic dispatch, vtable, heap-allocated, enables heterogeneous collections. `T: Trait`: static dispatch, monomorphization, zero-cost, type-specific code generation.

R7 — **Lifetimes**: Compiler tracks reference validity. Fails because return type lifetime is ambiguous. Fix:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — **`Send`/`Sync`**: `Send`: safe to transfer ownership across threads. `Sync`: safe to share references across threads. `Rc<T>` isn't `Send`/`Sync` due to non-atomic ref count. `Arc<T>` uses atomic ref counting, making it `Send`+`Sync` (if `T` is).

R9 — **Async/Await**: Compiles to state machines implementing `Future`. `Future::poll` advances state. Executors (Tokio) drive futures to completion. Differs from Go: Go uses M:N green threads (blocking OS threads allowed), Rust uses cooperative async with explicit executors; blocking in async context requires special handling (`spawn_blocking`).

R10 — **`unsafe`**: Bypasses compiler safety checks. 3 capabilities: dereference raw pointers, call `unsafe` functions, implement `unsafe` traits, access/modify `static mut`. Justified when interfacing with C, building safe abstractions, or performance-critical code where safety is proven.

R11 — **Pattern Matching**: `match` exhaustively matches all variants. `if let` matches one case. Compiler enforces exhaustiveness in `match` (warns/errors if variants are missing or `_` is omitted).

R12 — **`Vec<T>` vs `[T; N]`**: `Vec` is heap-allocated, growable. `[T; N]` is fixed-size, usually stack-allocated. Vec reallocates by allocating a larger buffer, copying elements, dropping old storage, and updating pointer/len/cap.

R13 — **Enums**: Algebraic data types; variants can hold data. Richer than C/Java enums. `Option<T>` = `Some(T)` | `None`. No `null` prevents null pointer dereferences and forces explicit handling via `match`/`if let`.

R14 — **`impl` Blocks**: Define methods/associated functions. `&self`: immutable borrow, `&mut self`: mutable borrow, `self`: takes ownership. Associated functions (e.g., `String::new()`) don't take `self`, acting like static constructors.

R15 — **`derive` Macro**: Auto-implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if trait requires custom logic, contains non-deriveable fields (e.g., `Fn` closures, raw pointers without custom impl), or violates trait invariants.

R16 — **`Cow<'a, T>`**: Clone-on-Write. Holds either `&'a T` (borrowed) or `T` (owned). Useful when a function might return borrowed or owned data. Avoids allocation if input already matches desired format; only clones when modification is needed.

R17 — **Module System**: `mod` declares module, `use` imports, `pub` exposes. File system: `mod.rs` or `mod_name.rs` in directory. Rust 2018: path resolution standardized (`crate::`, `super::`, `self::`), `extern crate` removed, modules can be declared in root or separate files flexibly.

R18 — **`Pin<T>`**: Guarantees pointer to inner value doesn't move. Needed for self-referential structs and async/await (futures may hold references to their own fields). `Unpin`: marker trait indicating type can be safely moved. Most types are `Unpin`; async types are `!Unpin`.

R19 — **Macros**: `macro_rules!` (declarative, pattern matching on token trees). Procedural: `derive` (struct/enum), `attribute` (custom attributes), `function-like` (invoked like functions). Hygiene: macros don't capture/leak identifiers from caller scope; bindings are isolated to macro expansion.

R20 — **Zero-Cost Abstractions**: High-level features compile to efficient machine code. Iterators: zero overhead, loop unrolling, no bounds checks. Generics: monomorphization generates type-specific code. Trait static dispatch: inlined calls or direct vtable lookups. Achieves C-like performance with safety and ergonomics.
