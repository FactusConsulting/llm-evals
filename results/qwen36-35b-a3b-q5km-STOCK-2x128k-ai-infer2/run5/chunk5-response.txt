DN1 — **class vs struct**: `class` is a reference type allocated on the heap, supports inheritance, and can be null. `struct` is a value type (typically stack/inline), copied by value, does not support inheritance, and cannot be null (pre-C# 8). Use `struct` for small, immutable, short-lived data that benefits from value semantics (e.g., `Point`, `Vector`, IDs, DTOs without behavior).

DN2 — **IEnumerable<T> vs IQueryable<T>**: `IEnumerable<T>` executes in-memory; LINQ operators translate to delegate-based methods. `IQueryable<T>` holds an expression tree that providers (like EF Core) translate to SQL. Distinction matters because `IQueryable` enables server-side filtering, projection, and pagination, preventing full table loads into memory and reducing network/DB overhead.

DN3 — **async/await & Task vs ValueTask**: `async/await` compiles to a state machine that captures context, yields control, and resumes when the underlying operation completes. `Task` is a reference type (heap-allocated). `ValueTask` is a struct that can wrap a `Task` or a synchronous result. Use `ValueTask` when an async method frequently completes synchronously or returns cached data, avoiding allocation overhead.

DN4 — **DI & Service Lifetimes**: DI manages object creation and lifecycle. `Transient`: new instance per request. `Scoped`: one instance per DI scope (e.g., HTTP request). `Singleton`: one instance per app lifetime. **Captive dependency bug**: Injecting a `Scoped` service into a `Singleton` keeps the scoped instance alive for the app's lifetime, causing memory leaks, stale state, and thread-safety issues.

DN5 — **string vs ReadOnlySpan<char>**: `string` is a heap-allocated, immutable reference type. `ReadOnlySpan<char>` is a stack-only, zero-allocation view over memory. Use `Span<T>`/`ReadOnlySpan<T>` in hot paths for parsing, slicing, or formatting to eliminate allocations and improve cache locality.

DN6 — **GC, Generations, LOH, IDisposable**: GC manages managed heap. `Gen 0`: short-lived objects, collected frequently. `Gen 1`: buffer between 0 and 2. `Gen 2`: long-lived, collected rarely. `LOH`: objects >85KB, compacted infrequently to avoid fragmentation. `IDisposable` is needed for unmanaged resources (file handles, DB connections, native memory) because the GC only tracks managed memory and finalizers are non-deterministic.

DN7 — **ConfigureAwait(false)**: Prevents capturing/restoring the `SynchronizationContext`. Use in **libraries** to avoid deadlocks and improve throughput by allowing continuations to run on any thread. **Do not use** in UI/app code where context is required for UI updates or request-scoped services. Relates to `SynchronizationContext` by breaking the implicit context flow that ASP.NET/WinForms/WPF rely on.

DN8 — **.NET 8/9 Features**: 
- Primary constructors: `public record Service(int Id, string Name);`
- Collection expressions: `int[] arr = [1, 2, 3];`
- `FrozenDictionary<K,V>`: immutable, optimized for lookups, lower memory overhead.
DI example: `builder.Services.AddScoped<Service>();` // Primary constructor params injected automatically.

DN9 — **DbContext ObjectDisposedException under load**: Likely cause: `DbContext` registered as `Singleton` or manually instantiated/shared across requests. EF Core `DbContext` is **not thread-safe**. Fix: Register as `Scoped` (`builder.Services.AddDbContext<MyContext>(...)`). DI scope ensures one instance per HTTP request, aligning with EF Core's unit-of-work design.

DN10 — **record vs class**: `record` is a reference type with value-based equality, immutability by default, and positional syntax. `record struct` is the value-type equivalent. Choose `record` for immutable DTOs/data carriers, `record struct` for performance-critical value types, and `class` for mutable, stateful, or polymorphic objects.

DN11 — **ref, out, in**: `ref`: pass by reference, caller must initialize. `out`: pass by reference, method must assign before return. `in`: pass by reference, read-only. Use `ref` for modifying, `out` for multiple return values, `in` for large structs to avoid copying while preventing mutation.

DN12 — **Nullable Reference Types (NRT)**: `#nullable enable` activates compile-time nullability checks. `?` annotates reference types as nullable/suppresses warnings. Differs from `int?` (nullable value type), which is a runtime `Nullable<T>` struct that actually stores a boolean `HasValue` and allows `null` at runtime. NRTs are compile-time only.

DN13 — **LINQ**: Language Integrated Query. Method syntax (`list.Where(...)`) vs query syntax (`from x in list where ...`) are compiler-translated equivalents. **Deferred execution**: queries don't run until enumerated (`foreach`, `ToList()`). Enables composition, lazy evaluation, and provider-specific translation (e.g., EF Core).

DN14 — **Generic Constraints**: Restrict `T` to enable safe operations. `where T : class` (reference), `struct` (non-nullable value), `new()` (parameterless constructor), `IComparable<T>` (interface). Combine with `&`: `where T : class, IComparable<T>`. Used to enable equality, construction, or sorting without boxing/runtime casts.

DN15 — **abstract class vs interface**: Abstract classes support state, constructors, and implementation; single inheritance. Interfaces define contracts; multiple inheritance. C# 8+ default interface methods allow implementation in interfaces, narrowing the gap, but abstract classes still uniquely support state, constructors, and protected members.

DN16 — **Middleware Pipeline**: `app.Use()` adds middleware that can call `next()` or short-circuit. `app.Map()` branches routing by path. `app.Run()` is terminal (no `next()`). Ordering matters: auth/rate-limit before routing, error handling early. Exception middleware catches unhandled exceptions and can rewrite responses; placed early to catch downstream errors.

DN17 — **Channel<T>**: Async producer-consumer queue. Bounded channels apply backpressure by suspending producers when full. Differs from `BlockingCollection<T>` (sync, older). Example: `var ch = Channel.CreateBounded<int>(100); await ch.Writer.WriteAsync(item);` // blocks/suspends if full.

DN18 — **Source Generators**: Compile-time code generation via Roslyn APIs. Differs from reflection (runtime overhead) and IL weaving (post-compile, e.g., Fody). **Incremental generators** (`IncrementalGeneratorInitializationContext`) replace legacy `ISourceGenerator`: they cache results, track file dependencies, run per-file, and dramatically improve build performance.

DN19 — **TPL Dataflow**: Async message-passing library. `ActionBlock` (processes, no output), `TransformBlock` (processes, outputs), `BufferBlock` (holds messages). Compared to `Channels`: Dataflow offers built-in backpressure, linking, completion propagation, and complex topologies; Channels are simpler, lower-level primitives for basic pipelines.

DN20 — **Minimal APIs**: Lightweight HTTP framework without controllers. Trade-offs: less structured, harder to test complex logic, historically weaker OpenAPI/middleware support (now mature). Route groups (`MapGroup`) organize endpoints. Endpoint filters (`AddFilter`) run per-endpoint for auth, validation, logging, or short-circuiting.

P1 — **list vs tuple / set vs frozenset**: `list` is mutable, ordered, heterogeneous. `tuple` is immutable, ordered, often used for fixed records. `set` is mutable, unordered, unique elements. `frozenset` is immutable/hashable, usable as dict keys or set elements.

P2 — **GIL**: Global Interpreter Lock allows only one thread to execute Python bytecode at a time. Affects CPU-bound single-threaded workloads. Workarounds: `multiprocessing`, C extensions that release GIL, or `asyncio` for I/O-bound concurrency.

P3 — **deepcopy vs copy**: `copy.copy()` creates a shallow copy (new container, same references). `copy.deepcopy()` recursively copies nested objects. Example: `a = [[1]]; b = copy.copy(a); b[0].append(2)` → `a` also changes. Use `deepcopy` when nested mutability must be isolated.

P4 — **Decorators**: Functions that wrap others to extend behavior. Example:
```python
import time, functools
def log_time(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        res = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter()-t0:.4f}s")
        return res
    return wrapper
```

P5 — **generators & yield**: `yield` turns a function into a generator, producing values lazily without building a full list. Memory efficient for large datasets. `yield from` delegates to another generator, flattening iteration.

P6 — **asyncio event loop**: `asyncio.run()` executes the main coroutine and manages the loop. `asyncio.gather()` runs coroutines concurrently, returning results in order. `asyncio.create_task()` schedules a coroutine for later execution. `time.sleep()` blocks the entire loop; use `await asyncio.sleep()` for non-blocking waits.

P7 — **MRO**: Python 3 uses C3 linearization. Diamond inheritance resolves left-to-right, depth-first. MRO for `D(B, C)` is `D → B → C → A`. `D().who()` calls `C.who()` → prints `"C"`. `B` inherits `who` from `A`, but `C` overrides it, and C3 places `C` before `A`.

P8 — **metaclass vs __init_subclass__**: Metaclass (`type`) controls class creation globally; use for complex class-level manipulation (e.g., ORM field registration, auto-registration). `__init_subclass__` is a simpler, instance-level hook called when a subclass is defined; use for lightweight subclass customization (e.g., auto-tagging, plugin discovery).

P9 — **multiprocessing vs threading vs concurrent.futures**: Threading: I/O bound, GIL limits CPU parallelism. Multiprocessing: CPU bound, process isolation, requires pickling. `concurrent.futures` provides a high-level API (`ThreadPoolExecutor`, `ProcessPoolExecutor`). Pickling: objects must be serializable; lambdas, nested functions, and open handles fail.

P10 — **__slots__**: Prevents `__dict__` creation, saving memory and restricting attributes. Use when creating many instances of the same class. Prevents dynamic attribute addition. Memory impact: ~50-70% reduction per instance, but adds slight overhead to attribute access.

P11 — **virtual environment**: Isolates project dependencies. `venv` (stdlib, modern), `virtualenv` (third-party, legacy), `conda` (package + env manager, data science/C++ deps). Prevents dependency conflicts and global pollution.

P12 — **comprehensions**: Concise syntax for creating collections. `map()`/`filter()` return iterators; comprehensions build lists/sets/dicts eagerly. Prefer comprehensions for readability and speed; use `map()`/`filter()` for lazy evaluation or functional pipelines.

P13 — **== vs is**: `==` compares value/equality; `is` compares identity (memory address). Object interning caches small integers (-5 to 256) and some strings. `a is b` returns `True` for interned objects due to shared memory references.

P14 — **\*args / \*\*kwargs**: `*args` collects positional args into a tuple; `**kwargs` collects keyword args into a dict. `/` marks positional-only params; `*` marks keyword-only params. Used for flexible APIs, type safety, and enforcing calling conventions.

P15 — **context managers**: Ensure resource cleanup via `with`. Implement via `__enter__`/`__exit__` or `@contextmanager` (yield). Example: database transactions, file locks, temp directories, or HTTP request sessions.

P16 — **type hinting**: Static annotations for IDEs/linters. `Union`/`Optional` for multiple types, `Literal` for exact values, `TypeVar` for generic constraints, `Protocol` for structural subtyping. `mypy`/`pyright` parse annotations without runtime execution to catch type errors.

P17 — **dunder methods**: `__repr__` (dev/debug), `__str__` (user). `__eq__` defines equality; `__hash__` defines hashability. Defining `__eq__` without `__hash__` makes objects unhashable. `__getattr__` (fallback), `__getattribute__` (always called, override carefully).

P18 — **descriptors**: Objects implementing `__get__`, `__set__`, `__delete__`. `property` uses them for computed attributes. `classmethod`/`staticmethod` are descriptors that manipulate `self`/`cls` binding. Descriptors enable reusable attribute logic across classes.

P19 — **import system**: `sys.path`/`PYTHONPATH` define search order. `__init__.py` marks packages (optional in 3.3+). Namespace packages allow split directories. Relative imports (`.`) vs absolute (`pkg.mod`). Finders locate modules; loaders execute them (`loader.exec_module()`).

P20 — **dataclasses vs attrs/Pydantic**: `dataclasses` auto-generates `__init__`, `__repr__`, `__eq__`. `__post_init__` for validation. `field(default_factory=...)` for mutable defaults. `frozen=True` for immutability. Inheritance works but requires care with `__init__`. Choose **Pydantic** for validation, serialization, JSON/APIs, and runtime type coercion.
