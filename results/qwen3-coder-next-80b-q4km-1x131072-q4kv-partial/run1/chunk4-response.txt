N1 — G1 — Easy: **Array** has fixed size known at compile time, stored on stack or as value; **slice** is a dynamically-sized, reference-like view into an array (or other contiguous memory), consisting of pointer, length, and capacity. When appending to a slice that has reached capacity, Go allocates a new underlying array (usually doubling capacity), copies existing elements, and appends the new element; the original slice variable is updated to point to the new backing array.

N2 — G2 — Easy: `var x int` declares `x` with zero value `0`, can be used at package or function scope. `x := 0` is short variable declaration (type inferred), only allowed **inside functions**, and requires at least one new variable on left-hand side. Cannot use `:=` at package scope, in `for` loop condition with existing vars (unless reassigning), or when reassigning only existing variables (e.g., `x := 5` when `x` already declared in same scope).

N3 — G3 — Medium: A **goroutine** is a lightweight, multiplexed thread managed by Go runtime; starts with small stack (~2KB) that grows/shrinks dynamically. Differs from OS threads: goroutines are user-space, cheaper to create/destroy, and many goroutines share fewer OS threads. The **GMP model** (G = goroutine, M = OS thread, P = processor/context) schedules goroutines: `P`s run `M`s, which execute `G`s; `P`s manage run queues and enable efficient work-stealing, allowing fine-grained concurrency with minimal context-switch overhead.

N4 — G4 — Medium: **Channels** are typed conduits for goroutine communication (send/receive). **Unbuffered**: synchronous; send blocks until receiver ready, and vice versa. **Buffered**: asynchronous up to capacity; send blocks only when buffer full. Sending to a full buffered channel blocks until space becomes available (i.e., a receive happens).

N5 — G5 — Medium: `context` package carries deadlines, cancellation signals, and request-scoped values across API boundaries. Minimal `WithTimeout` example:
```go
req, _ := http.NewRequest("GET", "https://example.com", nil)
ctx, cancel := context.WithTimeout(req.Context(), 2*time.Second)
defer cancel()
req = req.WithContext(ctx)

client := &http.Client{}
resp, err := client.Do(req)
if err != nil {
    log.Fatal("Request failed:", err)
}
defer resp.Body.Close()
```

N6 — G6 — Medium: Go uses **structural interface satisfaction**: a type implements an interface implicitly by having the required methods—no explicit `implements` clause. Differs from Java/C#, where interfaces must be explicitly declared. `interface{}` (or `any`) is the empty interface, implemented by all types. Powerful for generic utilities (e.g., `fmt.Println`), but dangerous due to lack of type safety—requires type assertions or reflection, risking runtime panics.

N7 — G7 — Hard: Go’s memory model requires **happens-before** relationships for visibility across goroutines. The code is unsafe because `ready = true` may be reordered or cached in CPU registers, and the reader goroutine may never see `data` updated (no synchronization). Alternatives: use `sync.Mutex`, `sync/atomic` (e.g., `atomic.StoreInt32(&ready, 1)`), or channels to enforce ordering.

N8 — G8 — Hard: `sync.Mutex` is a mutual exclusion lock (only one holder). `sync.RWMutex` allows multiple readers or one writer—useful when reads dominate. `sync.Map` is a concurrent map optimized for high-throughput read-heavy workloads with low contention; avoids explicit locking but has higher per-operation overhead and no iteration safety. Trade-offs: `sync.Map` better for many small concurrent ops; regular map + `RWMutex` better for complex logic or when iteration needed.

N9 — G9 — Hard: **Go modules** manage dependencies via `go.mod` (module path, Go version, dependencies with versions) and `go.sum` (cryptographic hashes of module versions). `go mod tidy` adds missing/removes unused dependencies and updates `go.mod`/`go.sum`. **Minimum Version Selection (MVS)** picks the highest version required by *any* dependency in the transitive closure—ensures reproducibility and avoids version conflicts.

N10 — G10 — Medium: `defer` schedules a function call to run before the surrounding function returns. Multiple defers execute in **LIFO order** (last-in, first-out). Common loop gotcha: `defer` inside a loop accumulates deferred calls—each iteration adds to the stack; better to wrap in a function or use explicit cleanup.

N11 — G11 — Easy: A **pointer** holds the memory address of a value. Zero value is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: "value"}` or use `new(MyStruct)` then assign fields.

N12 — G12 — Easy: `init()` is a special function run **after package variables are initialized**, before `main()` runs. Each package can have multiple `init()` functions (in different files); they execute in lexical file order (sorted by filename), then in order within each file.

N13 — G13 — Easy: `make()` initializes slices, maps, and channels (returns *initialized* value, not pointer). `new(T)` allocates zeroed memory for any type `T` and returns `*T`. `make` only works for slice/map/channel; `new` works for any type.

N14 — G14 — Easy: Go uses explicit error returns: functions return `(T, error)`. The `error` interface has `Error() string`. Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks equality via `Is()` method (supports wrapping); `errors.As` checks if error matches a target type via `As()`; `==` only checks direct equality, not wrapped errors.

N15 — G15 — Easy: Composite types:  
- `map[K]V`: zero value is `nil` (read-only; panics on write).  
- `slice`: `nil` slice (len=0, cap=0, ptr=nil).  
- `channel`: `nil` (send/receive blocks forever).  
- `struct`: all fields zero-valued.

N16 — G16 — Medium: A **race condition** occurs when two goroutines access shared data concurrently, and at least one writes—leading to undefined behavior. `-race` flag instruments code to detect data races at runtime. Example:
```go
// Unsafe:
var counter int
go func() { for i := 0; i < 1000; i++ { counter++ } }()
go func() { for i := 0; i < 1000; i++ { counter++ } }()
// Fix with mutex:
var mu sync.Mutex
mu.Lock(); counter++; mu.Unlock()
// Or channel:
ch := make(chan struct{}, 1000)
// (use worker goroutines sending to ch to serialize)
```

N17 — G17 — Medium: `select` waits on multiple channel operations; each case must be a send/receive. Differs from `switch`: cases are channel ops, not values. If multiple cases ready, `select` chooses **randomly** (fair). Timeout: use `time.After` in a `case`:
```go
select {
case res := <-ch:
    handle(res)
case <-time.After(2 * time.Second):
    return errors.New("timeout")
}
```

N18 — G18 — Hard: **Escape analysis** determines whether a variable’s lifetime exceeds its stack frame—allocating on heap if it escapes (e.g., returned, stored globally, or captured in closure). Compiler decides based on pointer flow. Inspect with `go build -gcflags="-m"` to see escape decisions. Matters for performance: heap allocations are slower and increase GC pressure.

N19 — G19 — Hard: `reflect` enables runtime introspection: `reflect.Type` describes type metadata; `reflect.Value` holds a value and allows manipulation. Performance cost: reflection bypasses compile-time checks, uses dynamic dispatch, and is ~10–100× slower than direct code. Justified only when no alternative exists (e.g., serialization frameworks, generic utilities before generics). Prefer generics or code generation (e.g., `go generate` + `stringer`) when possible.

N20 — G20 — Hard: `//go:embed` embeds files/directories at compile time into `[]byte` or `fs.FS`. Syntax: `//go:embed file.txt` or `//go:embed dir/*`. Works with `embed.FS` (implements `io/fs.FS`). Limitations: only static paths (no globs with `**`), no runtime modification, files must be in module directory (or subdirs), and embedded data is read-only. For directories: `//go:embed dir` → `fs.FS`.

N21 — R1 — Easy: **Ownership** is Rust’s core memory management model. Three rules:  
1. Each value has a single owner.  
2. Only one owner at a time.  
3. When owner goes out of scope, value is dropped.  
Ensures memory safety without GC.

N22 — R2 — Easy: `String` is an owned, heap-allocated, growable string. `&str` is an immutable string slice (borrowed view into UTF-8 data). Use `&str` in function signatures for read-only input (more flexible, avoids allocation); use `String` when ownership or mutation needed.

N23 — R3 — Medium: **Borrowing** lets you reference data without taking ownership. Borrow checker enforces:  
- At most one `&mut T` reference *or* any number of `&T` at a time.  
- References must be valid (no dangling pointers).  
- No mixing `&T` and `&mut T` simultaneously.  
Violations cause compile-time errors.

N24 — R4 — Medium: `Option<T>` = `Some(T)` or `None`; `Result<T, E>` = `Ok(T)` or `Err(E)`. `?` propagates `Err`/`None` early. Example:
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
// or explicitly:
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?; // returns Err if failed
    Ok(content)
}
```

N25 — R5 — Medium: `Box<T>`: heap-allocated, single-ownership pointer. `Rc<T>`: reference-counted, single-threaded. `Arc<T>`: atomic reference-counted, thread-safe. Use `Box` for large data or trait objects; `Rc` for shared ownership in single-threaded code; `Arc` for multi-threaded sharing.

N26 — R6 — Medium: **Traits** define shared behavior (like interfaces). Rust uses *static dispatch* via generics (`T: Trait`) or *dynamic dispatch* via trait objects (`dyn Trait`). Differs from Go: Rust traits can have default implementations, and are resolved at compile time (no vtable for generics). `dyn Trait` uses a vtable (runtime dispatch), while generics are monomorphized (zero-cost abstraction).

N27 — R7 — Hard: The function fails because compiler can’t infer lifetime of returned `&str` relative to inputs. Fix with explicit lifetime:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```
Lifetimes ensure the returned reference lives at least as long as both inputs.

N28 — R8 — Hard: `Send` = can be transferred across thread boundaries; `Sync` = can be shared between threads (`&T: Send`). `Rc<T>` is not `Send` because its refcount is non-atomic—concurrent modification would cause UB. `Arc<T>` uses atomic refcounting, making it `Send + Sync`.

N29 — R9 — Hard: `async fn` returns a `Future`—a state machine that implements `Future<Output = T>`. `await` suspends the future until ready. **Executor** (e.g., Tokio) polls futures to completion, multiplexing many on few OS threads. Differs from Go: goroutines are preemptively scheduled by runtime; Rust futures are *cooperatively* scheduled—no preemption, so blocking calls (e.g., `std::thread::sleep`) must be async-aware (e.g., `tokio::time::sleep`).

N30 — R10 — Medium: `unsafe` lifts Rust’s safety guarantees. In `unsafe` blocks you can:  
1. Dereference raw pointers.  
2. Call `unsafe` functions (e.g., FFI).  
3. Access/modify mutable statics.  
Justified only when necessary (e.g., FFI, low-level systems code, implementing safe abstractions like `Vec`), and should be minimized.

N31 — R11 — Easy: **Pattern matching** (`match`) deconstructs enums/values exhaustively. `if let` is syntactic sugar for single-case matching. Compiler enforces *exhaustiveness*: all variants must be handled (or `_` wildcard used), preventing unhandled cases at runtime.

N32 — R12 — Easy: `Vec<T>` is a growable heap-allocated array; `[T; N]` is fixed-size on stack. When `Vec` exceeds capacity, it allocates a new buffer (usually doubling capacity), moves elements, and frees old buffer.

N33 — R13 — Easy: Rust enums are **algebraic data types**—each variant can carry data (e.g., `enum Option<T> { Some(T), None }`). Unlike C/Java enums (just integers), Rust enums are type-safe and exhaustive. Rust has no `null`; `Option<T>` replaces it, forcing explicit handling of absence.

N34 — R14 — Easy: `impl` defines methods/associated functions. `&self` borrows immutably; `&mut self` mutably; `self` takes ownership (consumes). Associated functions (e.g., `String::new()`) don’t take `self`, used as constructors.

N35 — R15 — Easy: `#[derive(...)]` auto-implements traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize` (via serde). Cannot derive traits requiring custom logic (e.g., `Eq` if `PartialEq` has special behavior, or traits with methods).

N36 — R16 — Medium: `Cow<'a, T>` = Clone On Write: holds either borrowed (`&'a T`) or owned (`T`). Useful when data may or may not need mutation. Example:
```rust
fn process(s: &str) -> Cow<str> {
    if s.contains(' ') {
        Cow::Owned(s.replace(' ', "_"))
    } else {
        Cow::Borrowed(s)
    }
}
// Avoids allocation if no spaces.
```

N37 — R17 — Medium: `mod` declares modules; `pub` makes items visible outside module; `use` imports items. File system maps to modules: `src/lib.rs` → crate root; `src/foo/mod.rs` or `src/foo.rs` → `foo` module. Rust 2018: `crate::foo::Bar` instead of `::foo::Bar`; `pub use` re-exports; better module path resolution.

N38 — R18 — Hard: `Pin<T>` prevents a value from being moved in memory—critical for self-referential structs (e.g., async generators). `Unpin` trait marks types safe to move (default for most types). `Pin<Box<T>>` pins on heap; used in async/await to ensure futures don’t move after polling starts.

N39 — R19 — Hard: **Declarative macros** (`macro_rules!`) match patterns and expand at compile time (like `println!`). **Procedural macros** (derive, attribute, function-like) are Rust programs that transform ASTs (e.g., `#[derive(Debug)]`). **Hygiene** ensures macro-expanded identifiers don’t conflict with local names (e.g., `let x = 1;` inside macro doesn’t shadow caller’s `x`).

N40 — R20 — Hard: **Zero-cost abstractions** mean abstractions compile to same machine code as hand-written code. Achieved via:  
- **Generics**: monomorphization creates specialized versions at compile time (no vtable).  
- **Iterators**: chained operations (e.g., `.map().filter()`) fused into single loop, no intermediate allocations.  
- **Trait static dispatch**: generics with trait bounds resolve to direct calls (no dynamic dispatch).  
Result: high-level ergonomics with C-like performance.
