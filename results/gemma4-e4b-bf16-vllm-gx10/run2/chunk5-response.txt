## .NET / C# Answers

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
A `class` is a reference type, meaning instances are stored on the heap, and variables hold a reference (pointer) to that memory. It supports inheritance. A `struct` is a value type, meaning instances are stored directly on the stack (or inline within containing types), and variables hold the actual data. Structs are generally used for small, lightweight data structures that represent a single value (e.g., coordinates, color).

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
`IEnumerable<T>` represents a sequence that can be iterated over in memory. When used with LINQ to Objects, the entire query is executed locally on the collection. `IQueryable<T>` represents an expression tree that describes a query. When used with LINQ to Entities (like Entity Framework Core), the expression tree is translated into an appropriate query language (like SQL) and executed on the data source (the database). This distinction matters because `IQueryable<T>` allows for deferred execution and server-side processing, which is crucial for performance in database interactions.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
`async/await` allows asynchronous code to be written in a synchronous-looking manner. The `await` keyword pauses the execution of the current method until the awaited task completes, yielding control back to the caller (or the SynchronizationContext). The compiler transforms the method into a state machine.
A `Task` represents an asynchronous operation that might involve heap allocation for its state machine. A `ValueTask<T>` is a struct that can represent the result synchronously (avoiding heap allocation) or asynchronously (holding a reference to a `Task<T>`). You should use `ValueTask<T>` when the operation is frequently synchronous or when you are concerned about minimizing allocations in high-throughput scenarios, as it can avoid heap allocation entirely if the result is ready immediately.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
Dependency Injection (DI) is a design pattern where components receive their dependencies from an external source (the DI container) rather than creating them internally. This promotes loose coupling and testability.
*   **Transient:** A new instance is created every single time it is requested.
*   **Scoped:** A single instance is created per scope (e.g., per HTTP request in ASP.NET Core).
*   **Singleton:** A single instance is created for the entire application lifetime.
A common bug is injecting a **Scoped** service into a **Singleton** service. Since the Singleton lives for the entire application lifetime, it will hold a reference to the first Scoped instance it receives. This means that every subsequent request that uses that Singleton will reuse the *same* Scoped instance, violating the intended request-specific isolation of the Scoped service.

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
`string` is an immutable, managed reference type in .NET. Any modification creates a new string object. `ReadOnlySpan<char>` (and `Span<char>`) is a stack-allocated, lightweight, non-allocating view over a contiguous block of memory (which could be a string, a character array, etc.). You use `Span<T>` when you need to perform high-performance, low-allocation string or buffer manipulation (e.g., parsing, searching, slicing) without creating intermediate string objects. It allows you to work with memory buffers directly and efficiently.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
The GC automatically manages memory by tracking object reachability. It operates in generations:
*   **Gen 0:** Where short-lived objects are allocated. Collections here are frequent and fast.
*   **Gen 1:** Acts as a buffer between Gen 0 and Gen 2.
*   **Gen 2:** Where long-lived objects reside. Collections here are less frequent and more expensive.
The **Large Object Heap (LOH)** is where objects larger than a certain threshold (typically 85KB) are allocated. The LOH is often not compacted by the GC, leading to memory fragmentation.
You need `IDisposable` for **unmanaged resources** (like file handles, network sockets, database connections, or native memory pointers). The GC only cleans up managed memory; it has no knowledge of external resources that must be explicitly released to prevent resource leaks.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
By default, when an `await` is encountered, the continuation (the code after `await`) attempts to resume on the original `SynchronizationContext` (e.g., the UI thread in WPF/WinForms, or the ASP.NET request context). This ensures thread affinity.
`ConfigureAwait(false)` tells the runtime *not* to capture the current `SynchronizationContext`. The continuation can resume on any available thread pool thread.
**Use it when:** You are in a library or service layer and do not need to interact with UI elements or context-specific state. This prevents deadlocks and improves performance by avoiding context switching overhead.
**Do NOT use it when:** You are writing UI code or code that relies on specific context state (e.g., updating a UI element).

*   **FrozenDictionary:** A dictionary whose contents cannot be changed after creation, offering thread-safe, immutable lookups.

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
**Diagnosis:** The likely cause is that the `DbContext` is being treated as a Singleton or is being reused across multiple concurrent requests/tasks without proper isolation. When high concurrency hits, one request might finish its unit of work and dispose of the context, while another concurrent request attempts to use that now-disposed context, leading to `ObjectDisposedException`.
**Fix:** Ensure the `DbContext` is registered with a **Scoped** lifetime in the DI container (`builder.Services.AddDbContext<AppDbContext>(...)`). This guarantees that a new, isolated instance of the context is created for the duration of each incoming HTTP request.
**Interaction:** EF Core's `DbContext` is designed to be **short-lived** and **request-scoped**. It should *never* be shared across requests. DI scoping enforces this lifecycle management.

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
*   **Class:** A reference type, designed for modeling objects with identity and mutable state.
*   **Record:** A reference type designed for modeling immutable data carriers (Value Objects). Records automatically provide value-based equality (two records are equal if all their properties are equal, regardless of memory location) and support non-destructive mutation (`with` expressions).
*   **Record Struct:** A value type that combines the immutability and value-based equality of a record with the stack allocation benefits of a struct.
**Choice:** Use `class` when identity matters (e.g., a User entity with a unique ID). Use `record` when the data itself matters (e.g., a configuration object, a DTO). Use `record struct` for small, immutable value types where stack allocation is critical.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
All three allow passing arguments by reference, avoiding copying large objects.
*   **`ref`:** The variable must be initialized before being passed to the method, and the method can read or write to it. Used when you want to modify an existing variable.
*   **`out`:** The variable does *not* need to be initialized before being passed. The method *must* assign a value to it before returning. Used when the method is responsible for providing the result.
*   **`in`:** The variable must be initialized, but the method can only read from it (read-only reference). Used for performance when passing large structs to avoid copying, but you don't want the method to modify the original.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
Nullable Reference Types (NRTs) are a compile-time safety feature introduced in C# 8.0. When enabled (`#nullable enable`), the compiler tracks whether a reference type variable is allowed to be `null`. A reference type like `string` becomes `string?` if it can be null.
**Difference from Nullable Value Types (`int?`):**
*   **Value Types (`int?`):** These are wrappers around value types (like `Nullable<int>`). They explicitly represent the concept of "no value" for a primitive type.
*   **Reference Types (`string?`):** These are pointers. The compiler tracks if the pointer itself is allowed to point to `null` (i.e., point to nothing).

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
LINQ (Language Integrated Query) is a set of features in C# that allows developers to write queries against various data sources (collections, databases, XML) using a unified syntax.
*   **Method Syntax:** Uses extension methods (e.g., `list.Where(x => x.Age > 18)`). It is generally preferred in modern C# as it is more fluent.
*   **Query Syntax:** Uses SQL-like syntax (e.g., `from x in list where x.Age > 18`). It is often considered more readable for those familiar with SQL.
**Deferred Execution:** When you write a LINQ query (especially against `IEnumerable<T>`), the query is not executed immediately. Instead, it builds an expression tree or delegates. The query only runs when the results are actually iterated over (e.g., in a `foreach` loop or by calling `.ToList()`).

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
Generic constraints restrict the types that can be used as type arguments for a generic type or method.
*   `where T : class`: T must be a reference type.
*   `where T : struct`: T must be a value type.
*   `where T : new()`: T must have a public parameterless constructor.
*   `where T : IComparable<T>`: T must implement the `IComparable<T>` interface, allowing for comparison operations.
**Combining Constraints:** You combine them using the `&` operator (e.g., `where T : class, new(), IComparable<T>`). This ensures that the type T satisfies *all* specified requirements simultaneously, allowing the generic code to safely call methods or access properties guaranteed to exist on T.

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
*   **Abstract Class:** Can contain both abstract (unimplemented) and concrete (implemented) methods. It can have state (fields) and constructors. A class can only inherit from one abstract class (single inheritance). It defines an "is-a" relationship.
*   **Interface:** Traditionally, it could only define contracts (method signatures). A class can implement multiple interfaces. It defines a capability.
**Change with Default Interface Methods (C# 8+):** Default interface methods allow interfaces to provide a default implementation for some methods. This means an interface can now contain concrete logic, blurring the line. However, the fundamental difference remains: abstract classes can hold state and enforce a strict inheritance hierarchy, while interfaces primarily define contracts, even if those contracts now include default implementations.

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
The middleware pipeline is a series of software components that process HTTP requests sequentially. Each middleware component inspects the request, performs some action (logging, authentication, routing, etc.), and then either passes the request to the next middleware or terminates the request/response cycle.
*   **`app.Use()`:** Registers standard middleware components (e.g., `UseRouting()`, `UseAuthentication()`). These components typically inspect and modify the request/response.
*   **`app.Map()`:** Used to map specific endpoints or sub-pipelines to a specific path prefix. It's often used to isolate functionality (e.g., mapping a health check endpoint).
*   **`app.Run()`:** Terminates the pipeline. It is usually the last piece of middleware, responsible for executing the final endpoint logic or serving static files.
**Ordering:** Ordering is critical. For example, Authentication middleware *must* come before Authorization middleware. If you place routing after authentication, the authentication middleware might run before the request is routed, leading to incorrect behavior.
**Exception Handling:** Exception handling middleware (e.g., `app.UseExceptionHandler()`) must be placed **very early** in the pipeline, usually right after `UseRouting()`, so it can catch exceptions thrown by subsequent middleware or endpoint handlers before they crash the application.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
`Channel<T>` is a modern, asynchronous, thread-safe mechanism for communication between asynchronous producers and consumers. It is designed to work seamlessly with `async/await`.
**Comparison to `BlockingCollection<T>`:** `BlockingCollection<T>` is primarily designed for synchronous producer-consumer scenarios, often blocking threads when the collection is full or empty. `Channel<T>` is inherently asynchronous, using `await` to wait for data without blocking threads.
**Backpressure Example (Bounded Channel):**
```csharp
var channel = Channel.CreateBounded<int>(capacity: 5); // Bounded to 5 items

// Producer (writes)
await channel.Writer.WriteAsync(1); // If capacity is 5, this will await if the buffer is full.

// Consumer (reads)
await foreach (var item in channel.Reader.ReadAllAsync())
{
    // Process item
}
```
If the producer tries to write to a full bounded channel, `WriteAsync` will asynchronously wait until the consumer reads an item, thus applying backpressure.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
**Source Generators (SGs):** These are compile-time code generators. They analyze the syntax trees of the source code *during compilation* and generate new C# source files that are then compiled alongside the original code.
**Difference from Reflection:** Reflection inspects types and members *at runtime*. SGs operate *at compile time*, generating code before runtime, leading to zero runtime overhead for the generated code.
**Difference from IL Weaving:** IL Weaving modifies the Intermediate Language (IL) of an assembly *after* compilation (often at runtime or during deployment). SGs generate *source code* that is compiled normally, which is generally safer and easier to debug than post-compilation IL manipulation.
**Incremental Generator:** An incremental generator only regenerates the code for the parts of the source files that have actually changed since the last compilation. This is preferred over the basic `ISourceGenerator` because it drastically speeds up build times by avoiding unnecessary recompilation of unchanged code.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
TPL Dataflow provides a library of building blocks for creating complex, asynchronous data processing pipelines.
*   **`BufferBlock<T>`:** Acts as a queue. It accepts items and buffers them until a downstream block is ready to process them.
*   **`TransformBlock<TInput, TOutput>`:** Processes incoming items, applies a transformation function, and outputs the result to the next block.
*   **`ActionBlock<T>`:** Executes an action (a side effect) on incoming items without producing an output.
**Comparison to Channels:** Channels are simpler, focusing on point-to-point asynchronous communication (Producer $\rightarrow$ Consumer). TPL Dataflow is more powerful for building complex, multi-stage *pipelines* where data flows through several distinct processing steps (e.g., Fetch $\rightarrow$ Transform $\rightarrow$ Validate $\rightarrow$ Save). Dataflow blocks manage internal state and concurrency limits for each stage, whereas Channels are more focused on the transport mechanism.

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**
**Minimal APIs:** A modern, lightweight approach in ASP.NET Core where API endpoints are defined directly in the `Program.cs` file using lambda expressions, bypassing the need for controllers, actions, and routing attributes.
**Differences from Controllers:** Controllers use a structured, object-oriented approach (classes, methods, attributes). Minimal APIs are function-based and highly concise.
**Trade-offs:**
*   **Testability:** Controllers are often easier to mock and test in isolation due to their clear separation of concerns. Minimal APIs can be slightly harder to test without spinning up a minimal host environment.
*   **Middleware:** Both support the full middleware pipeline.
*   **OpenAPI Support:** Both can support OpenAPI, but controllers often integrate more naturally with established tooling. Minimal APIs require explicit configuration (e.g., using `MapGet` with Swagger/OpenAPI extensions).
**Route Groups & Endpoint Filters:**
*   **Route Groups:** Allow you to apply common prefixes or middleware to a set of related endpoints without repeating the configuration for each one.
*   **Endpoint Filters:** Allow you to inject logic (like authorization checks or logging) that runs *before* or *after* an endpoint handler executes, providing a clean way to cross-cut concerns without cluttering the endpoint lambda itself.

## Python Answers

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**
*   **List vs. Tuple:** Lists (`[]`) are **mutable** (can be changed after creation: append, insert, delete). Tuples (`()`) are **immutable** (cannot be changed after creation). Tuples are generally faster and can be used as dictionary keys because they are hashable.
*   **Set vs. Frozenset:** Sets (`{}`) are **mutable** collections of unique, hashable items. Frozensets are **immutable** versions of sets. Like tuples, frozensets are hashable and can be used as elements within another set or as dictionary keys.

**P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?**
The GIL is a mutex (lock) in the standard CPython interpreter that ensures only one thread executes Python bytecode at any given time, even on multi-core processors.
**Workloads Affected:** CPU-bound tasks (heavy computation, mathematical loops) are severely limited because threads spend most of their time waiting for the GIL to be released, preventing true parallel execution.
**Workarounds:**
1.  **Multiprocessing:** Using the `multiprocessing` module spawns separate OS processes, each with its own Python interpreter and GIL, allowing true parallelism across CPU cores.
2.  **I/O-bound tasks:** For tasks waiting on external resources (network requests, disk I/O), the GIL is released while waiting, allowing other threads to run concurrently, making `threading` effective.

**P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.**
*   **Shallow Copy (`.copy()` or `copy.copy()`):** Creates a new container object, but it populates the new container with *references* to the objects found in the original. If the original object contains mutable objects (like lists), modifying those nested objects in the copy will also modify them in the original.
*   **Deep Copy (`copy.deepcopy()`):** Creates a completely independent copy of the original object and recursively copies all objects found within it. Changes to the copy do not affect the original, and vice versa.
**Example of Shallow Copy Failure:**
```python
original = {'a': [1, 2]}
shallow = original.copy()
shallow['a'].append(3)
print(original) # Output: {'a': [1, 2, 3]} -> Original was modified!
```

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**
A decorator is a design pattern that allows you to modify or enhance the behavior of a function or method without permanently altering its source code. It is essentially a function that takes another function as an argument, adds functionality, and returns a new function.
**Time Logging Decorator:**
```python
import time
from functools import wraps

def timing_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"Function '{func.__name__}' executed in {end_time - start_time:.4f} seconds.")
        return result
    return wrapper

@timing_decorator
def slow_function(n):
    time.sleep(n)
    return f"Slept for {n} seconds"

# slow_function(0.5)
```

**P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?**
A **generator** is a special type of iterator that allows you to declare a function that behaves like an iterator, using the `yield` keyword.
**Difference from Returning a List:** When a function returns a list, it computes *all* the results and stores them in memory immediately before returning the entire list. A generator, using `yield`, computes and returns one item at a time *only when requested* (lazily). This saves significant memory, especially for large datasets.
**`yield from`:** This syntax is used to delegate iteration to another generator or iterable. It allows a generator function to delegate iteration to a sub-generator, effectively chaining generators together seamlessly.

**P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?**
The **asyncio event loop** is the core mechanism that manages and schedules asynchronous operations in Python. It runs in a single thread and monitors multiple I/O operations concurrently. When an `await` is encountered, the function pauses, and the event loop switches context to run another ready task instead of blocking the entire thread.
*   **`asyncio.run(coro)`:** Runs the top-level coroutine and manages the event loop lifecycle (starts, runs, and closes the loop).
*   **`asyncio.gather(*coros)`:** Runs multiple awaitables concurrently and waits for all of them to complete, returning a list of their results.
*   **`asyncio.create_task(coro)`:** Schedules a coroutine to run on the event loop *as soon as possible* without blocking the current execution flow, returning a `Task` object immediately.
**Why `time.sleep()` fails:** `time.sleep()` is a *blocking* call. If called inside an `async` function, it halts the entire thread, which means the event loop cannot switch context to run any other pending tasks, defeating the purpose of asynchronous programming. You must use `await asyncio.sleep(delay)` instead, which yields control back to the event loop.

**P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**
**MRO:** MRO defines the order in which Python searches the base classes of a class to find a specific method or attribute.
**Algorithm:** Python 3 uses the **C3 Linearization Algorithm** to determine the MRO. This algorithm ensures a consistent, predictable, and monotonic ordering that respects the inheritance hierarchy, even in complex scenarios like diamond inheritance.
**Diamond Inheritance Example:**
```python
class A:
    def who(self): return "A"
class B(A):
    pass
class C(A):
    def who(self): return "C"
class D(B, C):
    pass
print(D().who())
```
**Result: `B`'s path is checked first.** The MRO for `D` will be `(D, B, C, A, object)`. When `D().who()` is called, Python checks `D` (no `who`), then checks `B` (no `who`), then checks `C` (which has `who`), and executes `C`'s implementation.

**P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.**
**Metaclass:** A metaclass is the "class of a class." It controls *how* a class itself is created. When you define `class MyClass(metaclass=MyMeta):`, `MyMeta` is responsible for building `MyClass`.
**`__init_subclass__`:** This is a class method available since Python 3.6 that runs *after* a subclass has been created but *before* it is fully initialized. It is used to modify or inspect the subclass *after* it has been defined.
**Comparison & Use Cases:**
*   **Metaclass:** Use when you need to fundamentally alter the *creation* process of a class (e.g., automatically registering all subclasses into a central registry, enforcing strict API contracts at class definition time).
*   **`__init_subclass__`:** Use when you need to perform setup or validation *on* the subclass after it has been defined (e.g., automatically adding default methods or validating that required attributes exist on all subclasses).

**P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?**
*   **Threading:** Best for **I/O-bound** tasks. Threads share the same memory space and are subject to the GIL, so they don't achieve true CPU parallelism.
*   **Multiprocessing:** Best for **CPU-bound** tasks. It bypasses the GIL by creating separate OS processes, allowing true parallel execution across cores.
*   **`concurrent.futures`:** This is a high-level interface that abstracts away the complexity of managing threads or processes. You use `ThreadPoolExecutor` for I/O-bound tasks and `ProcessPoolExecutor` for CPU-bound tasks.
**Serialization Implications (Pickling):** When using `multiprocessing`, data passed between processes must be serialized (pickled) to be sent across process boundaries. This means that complex, non-serializable objects (like open file handles or database connections) cannot be passed directly between processes.

**P10 — Medium: What is __slots__? When should you use it, and what does it prevent? What is the memory impact?**
`__slots__` is a class attribute that explicitly declares the attributes an instance of a class will have.
**What it prevents:** By defining slots, Python skips the creation of the instance dictionary (`__dict__`) for each object. This prevents dynamic attribute assignment (i.e., you cannot add a new attribute to an instance after it has been created unless it's listed in `__slots__`).
**When to use it:** When you are creating a large number of instances of a class (e.g., millions of data points) where memory efficiency is critical.
**Memory Impact:** It significantly reduces the memory footprint of instances because it eliminates the overhead of the per-instance `__dict__`.

**P11 — Easy: What is a virtual environment, and why should you use one? What is the difference between venv, virtualenv, and conda?**
A **virtual environment** is an isolated directory that contains a specific Python interpreter installation and its own set of installed packages.
**Why use it:** It prevents dependency conflicts between different projects. Project A might require Django 2.0, while Project B requires Django 4.0. Without isolation, installing one would break the other.
**Differences:**
*   **`venv`:** The standard, built-in module in Python 3.3+ for creating lightweight virtual environments.
*   **`virtualenv`:** An older, more feature-rich third-party tool that predates `venv` and offers more customization.
*   **`conda`:** A comprehensive package and environment manager (often used in data science) that manages not just Python packages but also non-Python dependencies (like specific versions of NumPy compiled against specific C libraries).

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?**
These are concise, readable syntax sugar for creating collections based on existing iterables.
*   **List Comp:** `[expression for item in iterable if condition]`
*   **Dict Comp:** `{key_expr: value_expr for item in iterable if condition}`
*   **Set Comp:** `{expression for item in iterable if condition}`
**Relation to `map()` and `filter()`:** Comprehensions combine the functionality of `map()` (transformation) and `filter()` (selection) into a single, readable line.
*   `[f(x) for x in iterable if condition]` is equivalent to `list(map(f, filter(condition, iterable)))`.
**Preference:** Comprehensions are generally preferred in Python because they are more idiomatic, faster, and easier to read than chaining `map()` and `filter()`.

**P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?**
*   **`==` (Equality):** Compares the *values* of two objects. It calls the object's `__eq__()` method.
*   **`is` (Identity):** Compares the *identity* of two objects. It checks if both variables point to the exact same object in memory (i.e., if `id(a) == id(b)`).
**Object Interning:** Interning is an optimization technique where Python pre-allocates and reuses immutable objects (like small integers, short strings) in memory.
**Small Integers:** Python automatically interns integers in the range of -5 to 256. When you write `a = 100` and `b = 100`, Python often points both `a` and `b` to the *same* object in memory, so `a is b` returns `True`. This is an optimization, not a guaranteed behavior for all integers.

**P14 — Easy: Explain Python's *args and **kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?**
*   **`*args`:** Collects any number of positional arguments passed to the function into a **tuple**.
*   **`**kwargs`:** Collects any number of keyword arguments passed to the function into a **dictionary**.
*   **Positional-Only (`/`):** Arguments listed before `/` *must* be passed by position; they cannot be passed using a keyword argument name.
*   **Keyword-Only (`*`):** Arguments listed after `*` *must* be passed using their keyword name; they cannot be passed positionally.
**Example:** `def func(a, b, /, c, *, d): ...`
*   `a` and `b` must be positional.
*   `c` can be positional or keyword.
*   `d` must be keyword.

**P15 — Easy: What are context managers (with statement)? How do you write one using __enter__/__exit__ vs @contextmanager? Give an example beyond file handling.**
A context manager is an object that defines the runtime context to be established when executing a `with` statement. It guarantees that setup actions are performed upon entry and teardown actions are performed upon exit, even if errors occur.
*   **`__enter__` / `__exit__`:** The traditional way. `__enter__` is called upon entering the `with` block and returns the resource. `__exit__` is called upon exiting, receiving exception details if one occurred.
*   **`@contextmanager`:** A simpler, generator-based approach from the `contextlib` module. The code before `yield` is the setup (`__enter__`), and the code after `yield` is the teardown (`__exit__`).
**Example (Database Connection Pool):**
```python
from contextlib import contextmanager

@contextmanager
def db_session():
    conn = connect_to_db() # Setup
    try:
        yield conn # Resource provided to 'as' variable
    finally:
        conn.close() # Teardown
```

**P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How does mypy or pyright use these for static analysis?**
Type hinting (PEP 484) allows developers to optionally annotate variables, function parameters, and return values with expected types. This does *not* enforce types at runtime; it provides metadata for static analysis tools.
*   **`Union[A, B]`:** Indicates a value can be of type A OR type B.
*   **`Optional[T]`:** A shorthand for `Union[T, None]`.
*   **`Literal[value]`:** Restricts a variable to only accept a specific, fixed value (e.g., `Literal["read", "write"]`).
*   **`TypeVar`:** A placeholder for types that will be specified later, crucial for writing generic functions/classes.
*   **`Protocol`:** Defines a structural type. Instead of inheriting from a class, a type conforms to a Protocol if it implements the required methods/attributes (Duck Typing enforced statically).
**Static Analysis:** Tools like Mypy or Pyright read these annotations *before* runtime. They traverse the code, checking if the actual usage matches the declared types. If a function expecting an `int` receives a `str`, the tool raises a static type error.

**P17 — Medium: Explain Python's data model (dunder methods). What are __repr__ vs __str__, __eq__ vs __hash__, and __getattr__ vs __getattribute__? What happens if you define __eq__ but not __hash__?**
Dunder methods (double underscore methods) are special methods that define how Python objects interact with built-in operations.
*   **`__repr__` vs `__str__`:** `__repr__` (representation) is intended for developers; it should return an unambiguous string that could ideally recreate the object (`eval(repr(obj)) == obj`). `__str__` (string) is for end-users; it should return a readable, informal string.
*   **`__eq__` vs `__hash__`:** `__eq__` defines value equality (`a == b`). `__hash__` defines how the object is mapped to an integer for use in hash-based collections (sets, dict keys).
*   **`__getattr__` vs `__getattribute__`:** `__getattribute__` is called for *every* attribute access. `__getattr__` is only called if the attribute is *not* found normally.
**Consequence of missing `__hash__`:** If you define `__eq__` (meaning two objects are considered equal) but do not define `__hash__`, Python will raise a `TypeError` if you try to put those objects into a set or use them as dictionary keys, because hashable objects must have a consistent hash value for equal objects.

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (__get__, __set__, __delete__). How do property, classmethod, and staticmethod use descriptors under the hood?**
A **descriptor** is an object attribute that defines how attribute access (getting, setting, or deleting) behaves. It implements one or more of the descriptor protocol methods.
**Protocol:**
*   `__get__(self, instance, owner)`: Called when the attribute is accessed.
*   `__set__(self, instance, value)`: Called when the attribute is assigned a value.
*   `__delete__(self, instance)`: Called when the attribute is deleted.
**Usage:**
*   **`property`:** Uses descriptors to manage attribute access, allowing you to turn a simple attribute into a getter/setter method.
*   **`classmethod`:** The class method descriptor ensures that when the method is called on the class, the first argument (`cls`) is automatically bound to the class itself, not an instance.
*   **`staticmethod`:** The static method descriptor ensures that the method is called without the automatic binding of either `self` or `cls`.

**P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, __init__.py, and namespace packages work? What is a finder and a loader?**
The import system finds modules by searching directories listed in `sys.path`.
*   **`sys.path`:** A list of strings that specifies the search path for modules.
*   **`PYTHONPATH`:** An environment variable that adds directories to `sys.path` before the script runs.
*   **`__init__.py`:** Historically, this file marked a directory as a Python package, allowing imports from it. (Note: In modern Python 3.3+, this is optional for namespace packages).
*   **Namespace Packages:** Packages that do not require an `__init__.py` file. They allow multiple, independent packages to contribute to the same top-level namespace.
**Relative vs. Absolute Imports:**
*   **Absolute:** Imports start from the root of the project/package (e.g., `from my_project.utils import helper`).
*   **Relative:** Imports reference the current package location (e.g., `from . import sibling_module` or `from ..parent import module`).
**Finder and Loader:** When an import statement is executed, Python uses **Finders** (e.g., `PathFinder`) to locate the module based on the name. Once found, a **Loader** (e.g., `SourceFileLoader`) is responsible for reading the module's source code and executing it to create the module object.

**P20 — Hard: What are dataclasses and how does it compare to attrs and Pydantic? Explain __post_init__, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**
**Dataclasses:** A decorator (`@dataclass`) that automatically generates boilerplate methods like `__init__`, `__repr__`, `__eq__`, etc., based on type-hinted class attributes.
**Comparison:**
*   **`attrs`:** A mature library that predates dataclasses, offering similar functionality with more customization hooks.
*   **Pydantic:** A data validation library. It enforces *runtime* data validation against schemas, whereas dataclasses primarily handle boilerplate generation.
**Features:**
*   **`__post_init__`:** A method called immediately after `__init__` finishes, allowing for post-initialization logic (e.g., calculating a derived field).
*   **Field Factories:** Using `field(default_factory=list)` allows you to provide mutable default values safely, preventing all instances from sharing the same default list/dict.
*   **Frozen Dataclasses:** Setting `frozen=True` makes the instance immutable, similar to a `tuple` or `typing.Final`.
**Inheritance:** Dataclasses support inheritance, but you must be careful with `__init__` generation; often, you need to manually define `__init__` or use `__post_init__` to handle inherited fields correctly.
**When to choose Pydantic:** Choose Pydantic when the data coming into your system (e.g., from an API request body or a JSON file) is **untrusted** and **must be validated** against a strict schema before your application logic uses it. Dataclasses assume the input data is already correct.
