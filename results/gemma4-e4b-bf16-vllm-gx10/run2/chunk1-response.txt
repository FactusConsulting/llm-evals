## Networking Answers

**N1 — Easy:** A Layer 2 switch operates primarily at the Data Link Layer (Layer 2) of the OSI model, using MAC addresses to forward frames within the same broadcast domain (VLAN). A Layer 3 switch operates at both Layer 2 and Layer 3. It can perform switching based on MAC addresses (like a L2 switch) but also performs routing between different IP subnets using IP addresses, making it much faster for inter-VLAN routing than a traditional router.

**N2 — Easy:** The IP address is $10.0.5.37/20$.
The subnet mask for $/20$ is $255.255.240.0$.
The network address is found by performing a bitwise AND operation: $10.0.5.37 \text{ AND } 255.255.240.0 = 10.0.0.0$.
The broadcast address is the last address in the range. The range spans $2^{32-20} = 2^{12} = 4096$ addresses. The network starts at $10.0.0.0$ and ends at $10.0.15.255$.
*   **Network Address:** $10.0.0.0$
*   **Broadcast Address:** $10.0.15.255$

**N3 — Medium:** The TCP three-way handshake establishes a reliable connection:
1.  **SYN (Synchronize):** Client sends a segment to the server with the SYN flag set, proposing an initial sequence number ($X$).
2.  **SYN-ACK (Synchronize-Acknowledge):** Server receives the SYN, allocates resources, and replies with a segment having both SYN and ACK flags set, acknowledging the client's sequence number ($X+1$) and proposing its own sequence number ($Y$).
3.  **ACK (Acknowledge):** Client receives the SYN-ACK and sends a final segment with the ACK flag set, acknowledging the server's sequence number ($Y+1$).
If the final ACK is lost, the server will wait for a timeout period. Since it never receives the final ACK, it will eventually time out and tear down the connection attempt, or the client will retransmit the final ACK until the server responds or the client times out.

**N4 — Medium:**
*   **SNAT (Source Network Address Translation):** Translates the *source* IP address of a packet as it leaves a private network, replacing it with a public IP address. This is typically used when internal hosts access the internet.
    *   *Example:* An internal host (192.168.1.10) accesses Google. The router changes the source IP from 192.168.1.10 to the router's public IP (203.0.113.5) before sending it out.
*   **DNAT (Destination Network Address Translation):** Translates the *destination* IP address of a packet as it enters a private network. This is typically used to allow external access to internal servers.
    *   *Example:* An external user accesses a web server at the public IP (203.0.113.5). The router translates the destination IP from 203.0.113.5 to the internal server's private IP (192.168.1.50).

**N5 — Medium:** The error "SSL: certificate subject name does not match target host name" means the hostname you are connecting to does not match the Common Name (CN) or Subject Alternative Name (SAN) listed in the server's SSL certificate. Three possible causes are:
1.  **Incorrect Hostname:** You typed the wrong domain name in the `curl` command.
2.  **Misconfigured Server:** The web server (e.g., Apache/Nginx) is configured with a certificate issued for a different domain name than the one it is currently serving.
3.  **Using an IP Address:** You are connecting using the server's IP address instead of its fully qualified domain name (FQDN), and the certificate was only issued for the FQDN.

**N6 — Medium:**
*   **VLAN (Virtual Local Area Network):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains based on a tag (802.1Q). VLANs are limited by the physical infrastructure (typically 4094 VLAN IDs) and are constrained by the Layer 2 domain boundaries.
*   **VxLAN (Virtual Extensible LAN):** A network virtualization overlay technology that encapsulates Layer 2 Ethernet frames within Layer 3 UDP packets. It uses a VNI (Virtual Network Identifier) instead of an 802.1Q tag.
*   **When to choose VxLAN:** You choose VxLAN when you need to extend Layer 2 segments (like a single broadcast domain) across a large, multi-subnet, Layer 3 infrastructure (e.g., in large data centers or cloud environments). VxLAN overcomes the scalability limitations of VLANs by allowing millions of logical segments (VNIs) over an IP fabric.

**N7 — Hard:**
*   **Why:** The routing decision is based on the source IP address of the packet. When traffic arrives on `eth1` (192.168.1.0/24), the kernel sees the source IP is in the 192.168.1.0/24 subnet. Since the default route points to `eth0` (10.0.0.1), the kernel uses the routing table to determine that the return path for traffic originating from 192.168.1.0/24 should exit via the default gateway interface, which is `eth0`.
*   **How to fix with Policy-Based Routing (PBR):** You must create a routing rule that specifically dictates that traffic originating from the 192.168.1.0/24 subnet must use the `eth1` interface for egress, overriding the default routing table.
    1.  Create a new routing table (e.g., `table 100`).
    2.  Add a route in this new table: `ip route add default via 192.168.1.1 dev eth1 table 100`.
    3.  Create a routing rule that matches the source IP and directs it to the new table: `ip rule add from 192.168.1.0/24 table 100`.

**N8 — Hard:** BGP path selection is a complex process where routers evaluate multiple attributes associated with a received route advertisement to determine the "best" path to a destination prefix. The router selects the path that scores highest based on a predefined sequence of checks.
**5 Attributes in Order of Preference (Simplified):**
1.  **Weight (Cisco proprietary):** Highest is preferred.
2.  **Local Preference (Local to AS):** Highest is preferred.
3.  **Locally Originated:** Routes originated locally are preferred over learned routes.
4.  **AS Path Length:** Shortest AS path is preferred (fewer hops through other Autonomous Systems).
5.  **Origin Type:** IGP (i) > EGP (e) > Incomplete (?) is preferred.

**N9 — Hard:**
*   **MTU Implication:** When running VxLAN over an IPsec tunnel, the original Ethernet frame (which has an MTU of 1500 bytes) must be encapsulated multiple times:
    1.  Original Ethernet Frame (Payload)
    2.  VxLAN Header (adds overhead)
    3.  UDP Header (adds overhead)
    4.  IP Header (adds overhead)
    5.  IPsec Header (adds significant overhead, typically ESP/AH)
    6.  Outer IP Header (adds overhead)
*   **Math:** If the physical MTU is 1500 bytes, the total overhead must be subtracted from 1500 to find the maximum inner payload.
    *   *Typical Overhead Estimate:* VxLAN (50 bytes) + UDP (8 bytes) + IP (20 bytes) + IPsec (e.g., 50-70 bytes depending on mode) + Outer IP (20 bytes).
    *   *Calculation:* Maximum Inner Payload $\approx 1500 - (\text{VxLAN Overhead} + \text{UDP/IP Overhead} + \text{IPsec Overhead} + \text{Outer IP Overhead})$. If we conservatively estimate total overhead at 100 bytes, the maximum inner payload is $1500 - 100 = 1400$ bytes. (The exact value depends on the specific IPsec implementation).

**N10 — Medium:**
*   **Purpose of ARP (Address Resolution Protocol):** ARP maps a known Layer 3 IP address to its corresponding Layer 2 MAC address within a local network segment. A host broadcasts an ARP request asking, "Who has IP X.X.X.X? Tell me your MAC address." The host with that IP replies with an ARP reply containing its MAC address.
*   **Gratuitous ARP:** A host sends out an ARP reply to its *own* IP address without being asked. This solves problems like:
    1.  **Duplicate IP Detection:** A host can announce its presence to ensure no other host is using its IP.
    2.  **MAC/IP Binding Updates:** It forces neighboring devices (like switches) to immediately update their ARP/MAC tables with the host's current MAC address, which is crucial after a host changes its NIC or IP configuration.

**N11 — Easy:**
*   **Public IP Address:** An IP address globally unique and routable on the public internet. It is assigned by an ISP or RIR and is visible to all external networks.
*   **Private IP Address:** An IP address reserved for use within private, local area networks (LANs). These addresses are not routable on the public internet and require NAT to communicate externally.
*   **RFC 1918 Ranges:**
    1.  $10.0.0.0$ to $10.255.255.255$ ($/8$)
    2.  $172.16.0.0$ to $172.31.255.255$ ($/12$)
    3.  $192.168.0.0$ to $192.168.255.255$ ($/16$)

**N12 — Easy:**
*   **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses (like `93.184.216.34`) and vice versa.
*   **Record Types:**
    *   **A Record:** Maps a hostname to an IPv4 address (e.g., `www.example.com` $\rightarrow$ `192.0.2.1`).
    *   **CNAME Record (Canonical Name):** Creates an alias from one domain name to another canonical domain name (e.g., `blog.example.com` $\rightarrow$ `servers.example.com`).
    *   **AAAA Record:** Maps a hostname to an IPv6 address (e.g., `www.example.com` $\rightarrow$ `2001:db8::1`).

**N13 — Easy:**
*   **DHCP (Dynamic Host Configuration Protocol):** A network management protocol used to automatically assign IP addresses and other network configuration parameters (like subnet mask, default gateway, DNS servers) to devices on a network.
*   **DORA Process:**
    1.  **Discover:** Client broadcasts a DHCP Discover message to find available servers.
    2.  **Offer:** DHCP server replies with a DHCP Offer, proposing an IP address and configuration.
    3.  **Request:** Client broadcasts a DHCP Request, formally accepting the offered configuration.
    4.  **Acknowledge:** DHCP server sends a DHCP ACK, finalizing the lease and configuration assignment.

**N14 — Easy:**
*   **Hub:** Operates at Layer 1 (Physical Layer). It is a simple repeater that broadcasts all incoming electrical signals out of every other port, creating one large collision domain.
*   **Switch:** Operates at Layer 2 (Data Link Layer). It learns MAC addresses and forwards frames only to the intended destination port, segmenting collision domains.
*   **Router:** Operates at Layer 3 (Network Layer). It uses IP addresses to forward packets between different networks (subnets), making decisions based on routing tables.

**N15 — Easy:**
*   **Half-Duplex:** Allows data to travel in both directions, but only one direction at a time (e.g., a walkie-talkie). If one device is transmitting, the other must listen.
*   **Full-Duplex:** Allows data to travel simultaneously in both directions (e.g., a telephone call).
*   **Modern Ethernet:** Modern Ethernet links overwhelmingly use **full-duplex** communication.

**N16 — Medium:**
*   **Purpose of TTL (Time To Live):** The TTL field is an 8-bit field in the IP header that specifies the maximum number of hops (routers) a packet can traverse before being discarded. This prevents packets from circulating indefinitely in routing loops.
*   **Traceroute Exploitation:** `traceroute` (or `tracert`) exploits the TTL mechanism. It sends a sequence of packets, starting with TTL=1, then TTL=2, TTL=3, and so on. When a router receives a packet with TTL=1, it decrements the TTL to 0 and drops the packet, sending back an ICMP "Time Exceeded" message. By capturing these ICMP messages, `traceroute` maps the path hop-by-hop.

**N17 — Medium:**
*   **NAT Gateway:** A device (usually a router or firewall) that performs Network Address Translation, allowing multiple devices on a private internal network to share a single public IP address when communicating with the outside world.
*   **Differences:**
    *   **Static NAT:** Maps one specific private IP address to one specific public IP address permanently (1:1 mapping). Used for servers that need a consistent public address.
    *   **Dynamic NAT:** Maps private IP addresses to a pool of available public IP addresses on a first-come, first-served basis.
    *   **PAT (Port Address Translation) / NAT Overload:** The most common form. It maps many private IP addresses to a *single* public IP address by tracking unique source port numbers for each internal connection.

**N18 — Hard:**
*   **ECMP (Equal-Cost Multi-Path):** ECMP allows a router to install multiple paths to the same destination prefix if those paths all have the same administrative cost (metric). Instead of choosing only one path, the router can load-balance traffic across all available equal-cost paths simultaneously, increasing aggregate bandwidth.
*   **Hashing Strategies:** Common strategies involve hashing based on:
    1.  Source IP Address
    2.  Destination IP Address
    3.  Source Port
    4.  Destination Port
    (Often a combination of these is used to ensure flow consistency).
*   **Asymmetric Flows Problem:** If a stateful firewall is involved, asymmetric routing occurs when the outbound traffic takes one path (e.g., Path A) and the return traffic takes a different path (e.g., Path B). Stateful firewalls track connections based on the initial state seen on the ingress interface. If the return packet arrives on an interface the firewall did not expect for that session, it may drop the packet because it doesn't match the established state table entry, breaking the connection.

**N19 — Hard:**
*   **The Problem:** The Bandwidth-Delay Product (BDP) is calculated as Bandwidth $\times$ Round Trip Time (RTT). It represents the maximum amount of unacknowledged data that can be "in flight" on the network path at any given time. If BDP is 10MB, the TCP sender *should* be able to send 10MB worth of data before waiting for an ACK. If the TCP window size is capped at 64KB, the sender is artificially limited to sending only 64KB before stalling, regardless of the network's capacity, leading to high latency and poor throughput.
*   **TCP Window Scaling (RFC 1323):** Standard TCP headers only allow a 16-bit window size, limiting the maximum advertised window to 65,535 bytes (64KB). Window scaling introduces a scaling factor into the TCP header options. This allows the sender and receiver to negotiate a much larger effective window size (up to 1GB or more), enabling the sender to fill the BDP and achieve maximum throughput.

**N20 — Hard:**
*   **802.1Q Trunk Ports:** This standard allows a single physical link (trunk) to carry traffic for multiple VLANs simultaneously. The switch inserts a 4-byte tag (the 802.1Q header) into the Ethernet frame. This tag contains the VLAN ID (VID) that identifies which VLAN the frame belongs to.
*   **Linux Configuration (Sub-interfaces):** To allow a single NIC (`eth0`) to participate in VLANs 10, 20, and 30, you create sub-interfaces, each bound to a specific VLAN ID:
    1.  `eth0.10` (for VLAN 10)
    2.  `eth0.20` (for VLAN 20)
    3.  `eth0.30` (for VLAN 30)
    These sub-interfaces are configured with the appropriate IP addresses for their respective VLANs.
*   **Frame Format on the Wire:** The frame structure is:
    `[Destination MAC] [Source MAC] [802.1Q Tag (VID)] [EtherType] [Payload] [FCS]`
    The 802.1Q tag is inserted between the Source MAC and the EtherType field.

## Linux Answers

**L1 — Easy:**
*   **Hard Link:** A hard link is a directory entry that points directly to the same underlying inode (the data structure containing file metadata) as the original file. If you delete the original file, the data remains accessible via the hard link until the link count reaches zero. They share the exact same data blocks.
*   **Symbolic Link (Symlink):** A symbolic link is a special type of file that contains a text pointer (a path) to another file or directory. It is like a shortcut in Windows. If the original file is moved or deleted, the symlink breaks (becomes a dangling link).

**L2 — Easy:** Use the `find` command:
`find /var/log -type f -size +100M`
*   `-type f`: Specifies that we are looking only for files.
*   `-size +100M`: Specifies that the file size must be greater than 100 Megabytes.

**L3 — Medium:**
*   **State D (Uninterruptible Sleep):** This state means the process is waiting for an I/O operation (like disk read/write or network activity) to complete. The process is blocked waiting for hardware, and it cannot be interrupted by signals (like SIGTERM or SIGKILL).
*   **Killing it:** You **cannot** reliably kill a process in state D using `kill -9` (SIGKILL). Since the kernel is waiting on the hardware driver to complete the I/O, the process is effectively held hostage by the kernel/hardware state. The only way to resolve this is usually to fix the underlying I/O issue (e.g., fix the disk, check the network connection) or reboot the system.

**L4 — Medium:**
*   **cgroups v1:** Used a hierarchical, resource-specific model. Controls were often siloed (e.g., CPU limits were separate from Memory limits). It was less unified and harder to manage across complex workloads.
*   **cgroups v2:** Implements a unified hierarchy. It provides a single, coherent view of resource control across all controllers (CPU, Memory, I/O, etc.). It enforces stricter resource accounting and provides better isolation.
*   **Systemd Preference:** Systemd strongly prefers **cgroups v2** because its unified hierarchy aligns perfectly with systemd's own hierarchical service management model, leading to more predictable and robust resource management for services and containers.

**L5 — Medium:**
*   **iptables:** The older, traditional Linux firewall framework. It uses chains (INPUT, OUTPUT, FORWARD) and tables to process packets sequentially. It is mature but can become complex to manage with many rules.
*   **nftables:** The modern replacement for iptables. It is a more flexible, unified framework that can handle packet filtering, NAT, and routing rules within a single, coherent syntax. It is designed to be more efficient and easier to manage than the legacy system.
*   **Kernel Handling:** The kernel maintains both systems for backward compatibility. When both are installed, the kernel typically routes traffic through the `nftables` framework if it is the active default, but it maintains the necessary compatibility layers to interpret and execute rules defined in the older `iptables` format.

**L6 — Medium:** The most likely cause is that the filesystem contains a large number of **small files** or **metadata overhead**.
`df -h` reports disk usage based on the filesystem block allocation, which includes space used by file system structures (inodes, directory entries, metadata). `du -sh /*` reports the aggregated size of the *contents* of the directories. If you have millions of tiny files, the space consumed by the metadata (inodes) can push the usage to 100% even if the actual data payload is small.

**L7 — Hard:**
1.  **UEFI Firmware:** The system powers on, and the UEFI firmware initializes hardware. It locates the bootloader (e.g., GRUB2) from the EFI System Partition (ESP) and executes it.
2.  **Bootloader (GRUB2):** The bootloader loads the Linux kernel image (`vmlinuz`) and the initial RAM disk (`initrd` or `initramfs`) into memory. It passes kernel command-line arguments (like root device location) to the kernel.
3.  **Kernel:** The kernel initializes core subsystems (memory management, process scheduling, drivers). It mounts the `initramfs` into memory.
4.  **Initramfs:** This minimal root filesystem contains essential drivers and utilities needed to mount the *real* root filesystem. Its primary job is to load necessary storage drivers (e.g., for LVM or encrypted volumes) and then execute the final initialization process.
5.  **Root Filesystem:** The `initramfs` mounts the actual root filesystem (e.g., `/`).
6.  **Systemd:** The kernel executes the first process, which is typically `/sbin/init` (or `systemd`). Systemd takes over, reads configuration files, manages services, mounts remaining filesystems, and brings the entire system to the desired operational state (the target).

**L8 — Hard:**
*   **Why Available is Low:** The `available` memory metric in Linux is calculated as `free + buffers + cache`. However, the OOM killer fires when the system needs memory *immediately* for a new allocation, and the kernel cannot reclaim enough memory quickly enough. While `buff/cache` is available for *reclaiming* (i.e., dropping cached pages to satisfy a request), the OOM killer triggers when the system is under extreme pressure and cannot satisfy the allocation request *before* the process runs out of memory, even if the cache is large.
*   **Kernel Tunables:** Key tunables include:
    *   `vm.swappiness`: Controls the kernel's tendency to swap out anonymous memory. A lower value (e.g., 10) tells the kernel to prefer dropping cache over swapping.
    *   `vm.vfs_cache_pressure`: Controls how aggressively the kernel reclaims memory used for directory and inode caches.

**L9 — Medium:**
*   **`ip netns`:** This command is used to manage network namespaces in Linux. A network namespace is an isolated view of the system resources (network interfaces, routing tables, process IDs, etc.). When you enter a namespace (`ip netns exec <name> bash`), you are operating within a completely isolated environment, unaware of the host's main network configuration.
*   **Container Runtime Usage:** Container runtimes (like Docker or Kubernetes) use network namespaces to provide network isolation for each container. Each container is placed into its own network namespace, giving it its own private set of interfaces, IP addresses, and routing tables, making it appear as an independent machine.

**L10 — Medium:**
*   **SIGTERM (Signal 15):** The standard, polite termination signal. It requests the process to shut down gracefully, allowing it to clean up resources (save files, close connections).
*   **SIGKILL (Signal 9):** The immediate, forceful termination signal. The kernel kills the process instantly; the process has no chance to clean up or catch the signal.
*   **SIGQUIT (Signal 3):** Requests the process to terminate and usually dump a core file for debugging.
*   **Catchable:** **SIGTERM** and **SIGQUIT** can be caught, handled, or ignored by the process using signal handlers. **SIGKILL** cannot be caught or ignored.

**L11 — Easy:**
*   **stdin (Standard Input):** Where a program reads its input from (default is the keyboard).
*   **stdout (Standard Output):** Where a program writes its normal, expected output to (default is the terminal screen).
*   **stderr (Standard Error):** Where a program writes error messages and diagnostic output to (default is the terminal screen).
*   **Redirection:** To redirect stderr to a file (`errors.log`) while keeping stdout on the terminal:
    `command 2> errors.log` (The `2>` redirects file descriptor 2, which is stderr).

**L12 — Easy:** `chmod 755 filename` sets the permissions for the file as follows:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = 7. The owner has full control.
*   **5 (Group):** Read (4) + Execute (1) = 5. The group can read and execute the file.
*   **5 (Others):** Read (4) + Execute (1) = 5. Everyone else can read and execute the file.
This is a common permission set for executable scripts or programs.

**L13 — Easy:**
*   **Root User (UID 0):** The superuser. The root user has unrestricted access to the entire operating system, can modify any file, change any configuration, and manage all processes without needing explicit permission checks.
*   **Sudo Privileges:** A user with `sudo` privileges can execute specific commands as another user (usually root) by prefixing the command with `sudo`. This grants *elevated privileges* for specific tasks, but it does not grant the user the absolute, unrestricted power of the root account at all times.

**L14 — Easy:**
*   **Package Manager:** A system software that automates the process of installing, upgrading, configuring, and removing software packages on a Linux system, ensuring dependencies are met.
*   **Default Managers:**
    *   **Debian/Ubuntu:** `apt` (Advanced Package Tool)
    *   **RHEL/Fedora:** `dnf` (Dandified YUM)

**L15 — Easy:**
*   **`/etc/fstab`:** This file (File System Table) contains static information about the filesystems that the system should mount automatically during boot. It specifies the device, mount point, filesystem type, and mounting options.
*   **Misconfiguration:** If an entry is misconfigured (e.g., wrong UUID, incorrect filesystem type, or pointing to a non-existent device), the system boot process will halt or fail to mount that specific filesystem, potentially leading to a non-bootable state or a severely degraded operational state until the entry is corrected.

**L16 — Medium:**
*   **LVM (Logical Volume Manager):** A storage management abstraction layer that provides flexible volume management on top of physical storage devices. It allows administrators to pool physical storage into flexible units that can be resized, moved, and managed logically, independent of the underlying disk layout.
*   **Components:**
    *   **Physical Volumes (PVs):** The actual physical storage devices (hard drives, partitions) that are designated for use by LVM.
    *   **Volume Groups (VGs):** A pool of one or more PVs. The VG aggregates the raw storage capacity.
    *   **Logical Volumes (LVs):** The virtual partitions carved out of the VG. These are what the operating system sees and mounts (e.g., `/home`, `/var`).
*   **Extending an LV:**
    1.  Ensure there is free space in the Volume Group (VG).
    2.  Extend the Logical Volume using the available space: `lvextend -L +<size> /dev/vg_name/lv_name`.
    3.  Resize the filesystem *on* the LV to recognize the new space: `resize2fs /dev/vg_name/lv_name` (for ext4).

**L17 — Hard:**
*   **I/O Scheduler:** The kernel component responsible for ordering and merging I/O requests (reads/writes) submitted by processes to the block devices (disks). Its goal is to optimize disk head movement and maximize throughput.
*   **Scheduler Comparison:**
    *   **mq-deadline:** A modern scheduler that prioritizes requests based on deadlines, aiming to reduce latency for interactive workloads while maintaining good throughput.
    *   **bfq (Budget Fair Queueing):** Designed specifically for desktop/interactive workloads. It aims to provide "fairness" by ensuring that no single process starves for I/O bandwidth, leading to very low latency for small, random I/O.
    *   **none:** Disables the scheduler, passing requests directly to the device driver. This is best for specialized, high-performance storage arrays where the hardware handles scheduling optimally.
*   **Choice:** Choose **bfq** for interactive servers; **mq-deadline** for general-purpose servers; **none** for specialized storage.
*   **Runtime Change:** Use the `echo` command to write the desired scheduler name to the device's `scheduler` file: `echo bfq > /sys/block/sdX/queue/scheduler`.

**L18 — Hard:**
*   **Load Average Measurement:** The load average measures the average number of processes that are either currently running on the CPU or are in an uninterruptible sleep state (waiting for I/O). It is a measure of system *demand*, not just CPU utilization.
*   **I/O Wait Inflation:** When processes are stuck in I/O wait (waiting for disk or network), they are counted in the load average, even though they are not consuming CPU cycles. High I/O wait inflates the load average, making the system *appear* busy when the CPU itself is idle.
*   **Diagnosis:**
    *   **CPU Bottleneck:** High CPU usage (`top`/`htop`) and high load average.
    *   **Disk Bottleneck:** Low CPU usage, high load average, and high `%wa` (I/O wait percentage) reported by `top`. Use `iostat` to check disk utilization (`%util`) and average wait times.
    *   **Network Bottleneck:** High load average, but low CPU and low `%wa`. Use `netstat` or `ss` to check for excessive connection states, or use `iftop` to monitor interface saturation.

**L19 — Hard:**
*   **SELinux Enforcement:** SELinux (Security-Enhanced Linux) enforces Mandatory Access Control (MAC). Instead of relying solely on traditional Discretionary Access Control (DAC - user/group permissions), SELinux assigns security contexts (labels) to every subject (process) and object (file, port). Access is only granted if the policy explicitly permits the transition between the subject's context and the object's context.
*   **Modes:**
    *   **Enforcing:** SELinux actively denies access based on policy violations.
    *   **Permissive:** SELinux logs all policy violations but does *not* deny access. This is used for auditing.
    *   **Disabled:** SELinux is completely inactive.
*   **Troubleshooting Port Binding:** If a daemon fails to bind a non-standard port, check the audit logs (`/var/log/audit/audit.log`). If SELinux is blocking it, the logs will show a "denied" message related to the process context trying to access the port context. The fix is usually to use `semanage port` to explicitly allow the daemon's context to use that specific port number.

**L20 — Hard:**
*   **Page Fault Handling:** When a process tries to access a virtual memory address whose corresponding physical memory page is not currently mapped or present in RAM, a page fault occurs. The kernel traps this fault, determines the required page, and initiates the necessary action (e.g., loading the page from disk/swap).
*   **Minor vs. Major Page Fault:**
    *   **Minor Page Fault:** The required page is already in physical memory but is mapped to a different virtual address space (e.g., shared libraries). The kernel only needs to update the page table entries; no disk I/O is required.
    *   **Major Page Fault:** The required page is not in physical memory (it might be on disk/swap). The kernel must perform slow I/O operations to load the page from secondary storage into a free physical frame.
*   **THP (Transparent Huge Pages):** THP attempts to automatically use large memory pages (e.g., 2MB instead of 4KB) for memory allocations. This reduces TLB misses and improves performance for large, sequential memory access patterns.
*   **When to Disable:** THP can introduce unpredictable latency spikes (latency jitter) during the background compaction process, which is detrimental to latency-sensitive applications (like high-frequency trading or real-time databases). It is often disabled in such environments.
