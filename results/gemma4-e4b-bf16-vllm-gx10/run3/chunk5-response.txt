## .NET / C# Answers

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
A `class` is a reference type, meaning variables hold a reference to data stored on the heap. It supports inheritance and reference semantics. A `struct` is a value type, meaning variables hold the actual data directly on the stack (or inline within a containing type). Structs are generally used for small, lightweight data structures that represent a single value (e.g., coordinates, colors). They should be used when the type is small, immutable, and represents a value rather than an entity with identity.

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
`IEnumerable<T>` represents a sequence that can be iterated over in memory. When used with LINQ to Objects, the entire query is executed locally on the collection. `IQueryable<T>` represents an expression tree that describes a query. When used with LINQ to Entities (like Entity Framework Core), the expression tree is translated into an appropriate query language (e.g., SQL) and executed on the data source (the database). This distinction matters because `IQueryable<T>` allows for deferred execution and server-side processing, preventing massive data transfer to the application layer.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
`async/await` is syntactic sugar built on top of the `Task` (or `Task<T>`) type. When the compiler encounters `await`, it checks if the awaited operation is complete. If not, it suspends the execution of the current method, returns control to the caller, and registers a continuation to resume execution once the awaited operation completes. A `Task` represents an asynchronous operation that might involve heap allocation. A `ValueTask<T>` is a struct that can represent either a completed result directly (avoiding heap allocation) or a reference to a `Task<T>` if the operation is truly asynchronous. Use `ValueTask<T>` when the operation is frequently synchronous or completes quickly, as it can reduce allocation overhead.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
Dependency Injection (DI) is a design pattern where components receive their dependencies from an external source (the DI container) rather than creating them internally. The three lifetimes are:
1. **Transient:** A new instance is created every single time it is requested.
2. **Scoped:** A single instance is created per scope (typically per HTTP request in ASP.NET Core).
3. **Singleton:** A single instance is created for the entire lifetime of the application.
The common bug is injecting a **Scoped** service into a **Singleton** service. Since the Singleton lives for the entire application lifetime, it will hold a reference to the first Scoped instance it receives. This means that every subsequent request that uses that Singleton will reuse the *same* Scoped instance, violating the intended request-specific isolation of the Scoped service.

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
`string` is an immutable, managed reference type in .NET. Operations on strings often involve creating new string objects, which incurs memory allocation overhead. `ReadOnlySpan<char>` (and `Span<T>`) is a stack-allocated, lightweight structure that provides a safe, high-performance view over a contiguous block of memory (like a string's underlying character array) without copying the data. You use `Span<T>` when you need to perform high-performance, low-allocation string manipulation, parsing, or slicing on existing character data, especially when dealing with raw buffers or network streams.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
The GC automatically manages memory by tracking object reachability. It operates in generations:
* **Gen 0:** New, short-lived objects are allocated here. Collections are frequent and fast.
* **Gen 1:** Objects that survive a Gen 0 collection are promoted here.
* **Gen 2:** Long-lived objects are promoted here. Collections are less frequent but more thorough.
The **Large Object Heap (LOH)** is where objects larger than a certain threshold (typically 85KB) are allocated. The LOH is generally not compacted by the GC, which can lead to memory fragmentation. `IDisposable` is necessary for **unmanaged resources** (like file handles, network sockets, database connections). The GC only manages *managed* memory; it has no knowledge of external resources that must be explicitly released via `Dispose()`.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
By default, when an `await` is encountered, the continuation (the code after `await`) attempts to resume on the original `SynchronizationContext` (e.g., the UI thread in WPF/WinForms, or the ASP.NET Core request context). `ConfigureAwait(false)` tells the runtime *not* to capture the current `SynchronizationContext`.
**Use it when:** You are in a library or service layer and you don't need to resume on the original context. This prevents deadlocks in UI applications and improves performance by avoiding context switching overhead.
**Do NOT use it when:** You are writing UI code or code that specifically relies on being marshaled back to the original context (e.g., updating a UI element).

**DN8 — Hard: Explain the new .NET 8/9 features: primary constructors, collection expressions, and FrozenDictionary. Write a minimal example using primary constructors with DI.**
* **Primary Constructors:** Allow parameters to be defined directly in the class signature, which can then be used to initialize properties or inject dependencies.
* **Collection Expressions:** Provide a concise syntax (`[1, 2, 3]`) for creating collections, replacing verbose constructors.
* **FrozenDictionary:** A dictionary whose contents cannot be changed after creation, offering thread-safe, high-performance lookups.

**Minimal Example (Primary Constructor with DI):**
```csharp
// Assume ILogger is registered in DI

{
    public void DoWork()
    {
        logger.LogInformation("Service initialized via primary constructor.");
    }
}
// In Program.cs: builder.Services.AddScoped<UserService>();
```

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
**Diagnosis:** The likely cause is that the `DbContext` is being treated as a Singleton or is being reused across multiple concurrent requests/tasks without proper isolation. When high concurrency hits, one request might finish its unit of work and dispose of the context, while another concurrent request still holds a reference to that now-disposed context, leading to `ObjectDisposedException`.
**Fix:** Ensure the `DbContext` is registered with a **Scoped** lifetime in the DI container (`builder.Services.AddDbContext<AppDbContext>(...)`). This guarantees that a new, isolated instance of the context is created for every incoming HTTP request scope.
**Interaction:** EF Core's `DbContext` is designed to be *not* thread-safe and *not* shareable across requests. Scoping ensures that each request gets its own isolated instance, adhering to the "one context per unit of work" principle.

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
* **Class:** A reference type, designed for modeling entities with identity (mutable state is common).
* **Record:** A reference type designed for modeling immutable data carriers (Value Objects). Records automatically provide value-based equality (two records are equal if all their properties are equal, regardless of memory location) and offer concise syntax for immutability.
* **Record Struct:** A value type that combines the immutability and value-based equality of a record with the stack/value semantics of a struct.
**Choice:** Use `class` when identity matters (e.g., a `User` entity). Use `record` when the data itself matters (e.g., a `ProductDto`). Use `record struct` for small, immutable value types where heap allocation must be avoided.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
* **`ref`:** The variable must be initialized before being passed to the method. The method can read and modify the original variable. Used when you want to pass an existing variable by reference to be modified.
* **`out`:** The variable does *not* need to be initialized before being passed. The method *must* assign a value to it before returning. Used when the method is responsible for providing a result back to the caller.
* **`in`:** The variable must be initialized, but the method is only allowed to read it (read-only reference). Used for performance optimization when passing large structs to avoid copying them, but you don't want the method to modify them.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
Nullable Reference Types (NRTs) are a compile-time safety feature introduced in C# 8.0. When enabled (`#nullable enable`), the compiler tracks whether a reference type variable is allowed to be null (e.g., `string?`). This helps eliminate `NullReferenceException` at compile time.
**Difference from Nullable Value Types (`int?`):** Value types (like `int`, `DateTime`) cannot inherently be null. `int?` is a wrapper type (`Nullable<int>`) that explicitly allows the value to be null. NRTs apply to reference types (classes, interfaces, strings), whereas `int?` applies to value types.

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
LINQ (Language Integrated Query) is a set of features in C# that allows developers to write queries against various data sources (collections, databases, XML) using a unified syntax.
* **Method Syntax:** Uses extension methods (e.g., `list.Where(x => x.Age > 18)`). This is generally preferred in modern C#.
* **Query Syntax:** Uses SQL-like syntax (e.g., `from x in list where x.Age > 18`). It is often more readable for those familiar with SQL.
**Deferred Execution:** When you write a LINQ query (using either syntax), the query is not executed immediately. Instead, it returns an `IEnumerable<T>` (or `IQueryable<T>`) that *describes* the query. The query only runs when the results are iterated over (e.g., in a `foreach` loop or by calling `.ToList()`).

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
Generic constraints restrict the types that can be used as type arguments for a generic type or method.
* **`where T : class`:** Ensures T is a reference type.
* **`where T : struct`:** Ensures T is a value type.
* **`where T : new()`:** Ensures T has a public parameterless constructor.
* **`where T : IComparable<T>`:** Ensures T implements the `IComparable<T>` interface, allowing you to compare instances of T.
**Combining Constraints:** You combine them using the `&` operator (e.g., `where T : class, new(), IComparable<T>`). This ensures that the type T satisfies *all* specified requirements before the code inside the generic method is compiled.

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
* **Abstract Class:** Can contain fields, constructors, and concrete (implemented) methods, in addition to abstract methods. A class can only inherit from one abstract class (single inheritance). It defines a base implementation blueprint.
* **Interface:** Defines a contract—a set of methods/properties that implementing classes *must* adhere to. Traditionally, it could only define signatures.
**Change with Default Interface Methods (C# 8+):** Interfaces can now contain default implementations for methods. This allows interfaces to provide some baseline behavior while still enforcing a contract. The distinction shifts: Abstract classes are still used for sharing common state and implementation logic, while interfaces are used to define capabilities that disparate classes can adopt.

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
The middleware pipeline is a series of software components that process HTTP requests sequentially. Each middleware component inspects the request, performs some action (logging, authentication, routing), and then either passes the request to the next component or terminates the request/response cycle.
* **`app.Use()`:** Registers middleware that processes the request and passes it down the pipeline (e.g., `UseAuthentication()`, `UseRouting()`).
* **`app.Map()`:** Maps a specific endpoint or set of endpoints to a delegate, effectively short-circuiting the pipeline for that route.
* **`app.Run()`:** Terminates the pipeline, typically used for a simple, single-endpoint application.
**Ordering:** Order is critical. Authentication middleware must come before authorization middleware. Routing must come before endpoint execution.
**Exception Handling:** Exception handling middleware (e.g., `UseExceptionHandler()`) must be placed **at the very beginning** of the pipeline so that it can catch exceptions thrown by any subsequent middleware or endpoint execution.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
`Channel<T>` is a modern, asynchronous, producer-consumer mechanism introduced in .NET Core. It is designed to work seamlessly with `async/await`.
**Comparison to `BlockingCollection<T>`:** `BlockingCollection<T>` is synchronous and thread-blocking, often requiring manual thread management. `Channel<T>` is asynchronous, non-blocking, and integrates naturally with the Task Parallel Library (TPL).
**Backpressure Example (Bounded Channel):** A bounded channel limits the number of items that can be buffered. If the producer tries to write to a full bounded channel, the `WriteAsync()` call will asynchronously wait until a consumer reads an item, thus applying backpressure to the producer.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
**Source Generators (SGs):** Code generators that run during compilation. They analyze the syntax tree of the source code and emit new C# source files that are compiled alongside the original code.
**Difference:**
* **Reflection:** Inspects types and members *at runtime*. SGs operate *at compile time*, eliminating runtime overhead.
* **IL Weaving:** Modifies the Intermediate Language (IL) of compiled assemblies *after* compilation. SGs generate source code that is compiled normally.
**Incremental Generator:** An SG that only regenerates the code files that are affected by changes in the input code, rather than regenerating everything. This drastically speeds up build times. It is preferred over the older `ISourceGenerator` model because it integrates directly with the Roslyn compiler's incremental build system, leading to much faster feedback loops.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
TPL Dataflow provides powerful constructs for building asynchronous, data-flow pipelines.
* **`BufferBlock<T>`:** Acts as a queue, buffering incoming messages until a consumer is ready.
* **`TransformBlock<TInput, TOutput>`:** Receives an input, applies a transformation function to it, and outputs the result. It is the core processing unit.
* **`ActionBlock<T>`:** Receives an input and executes an action (a side effect) on it without producing an output.
**Comparison to Channels:** Channels are simpler, focusing on a direct, asynchronous queue between two points (Producer $\leftrightarrow$ Consumer). TPL Dataflow is more complex and powerful, designed to model complex, multi-stage pipelines where data flows through several distinct processing blocks (e.g., Buffer $\rightarrow$ Transform $\rightarrow$ Action).

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**
**Minimal APIs:** A lightweight, streamlined way to build HTTP APIs directly in the `Program.cs` file using lambda expressions and endpoint routing, bypassing the need for controllers, actions, and MVC infrastructure.
**Differences/Trade-offs:**
* **Controller-based:** More structured, better separation of concerns (MVC pattern), easier for large teams to navigate.
* **Minimal APIs:** Less boilerplate, faster to prototype.
    * **Testability:** Can be slightly harder to test in isolation without mocking the entire host builder setup.
    * **Middleware:** Middleware integration is very direct and explicit in the pipeline setup.
    * **OpenAPI:** Requires explicit configuration (e.g., using Swashbuckle) to generate documentation, whereas controllers often integrate more naturally with standard MVC tooling.
**Route Groups & Endpoint Filters:** Route groups allow applying common middleware or constraints to a set of related endpoints. Endpoint filters allow you to inject logic (like authorization checks or response shaping) that runs before or after the endpoint handler executes, similar to action filters in MVC.

## Python Answers

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**
* **List vs. Tuple:** Lists (`[]`) are mutable (can be changed after creation) and ordered. Tuples (`()`) are immutable (cannot be changed) and ordered.
* **Set vs. Frozenset:** Sets (`{}`) are mutable collections of unique, unordered elements. They are used for fast membership testing. Frozensets are immutable versions of sets. They can be used as elements within other sets or as dictionary keys because they are hashable.

**P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?**
The GIL is a mutex (lock) in the standard CPython interpreter that ensures only one thread executes Python bytecode at any given time, even on multi-core processors.
**Workloads Affected:** CPU-bound tasks (heavy computation, number crunching) are severely limited because threads spend most of their time waiting for the GIL to be released, preventing true parallel execution.
**Workarounds:**
1. **Multiprocessing:** Using the `multiprocessing` module spawns entirely separate Python interpreter processes, each with its own GIL, allowing true parallelism across CPU cores.
2. **I/O-bound tasks:** Using `asyncio` or threading for I/O-bound tasks (network requests, disk reads). During I/O waits, the thread releases the GIL, allowing other threads to run.

**P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.**
* **Shallow Copy (`copy.copy()`):** Creates a new container object, but populates it with *references* to the objects found in the original. If the original object contains mutable objects (like lists), modifying those nested objects in the copy will also modify them in the original.
* **Deep Copy (`copy.deepcopy()`):** Recursively creates new copies of all objects found in the original structure, ensuring the copy is entirely independent of the original.
**Example:**
```python
original = [{'a': 1}]
shallow = copy.copy(original)
shallow[0]['a'] = 99  # Modifies the nested dict in both original and shallow
# original[0]['a'] is now 99, which is unexpected.
```

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**
A decorator is a design pattern that allows you to modify or enhance a function or method without permanently altering its source code. It is essentially a function that takes another function as an argument, adds some functionality, and returns a new function.
**Time Logging Decorator:**
```python
import time
from functools import wraps

def timing_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"Function {func.__name__} executed in {end_time - start_time:.4f} seconds.")
        return result
    return wrapper

@timing_decorator
def slow_function(n):
    time.sleep(n)
    return f"Slept for {n} seconds"

# slow_function(0.5)
```

**P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?**
A **generator** is a special type of iterator that allows you to declare a function that behaves like an iterator, using the `yield` keyword.
**Difference from Returning a List:** When a function returns a list, it computes *all* values immediately and stores them in memory. A generator computes values *lazily*—it yields one value at a time only when requested by the loop. This saves significant memory, especially for large datasets.
**`yield from`:** This delegates iteration to a sub-generator or iterable. It allows a generator to delegate yielding control to another generator, effectively chaining generators together seamlessly.

**P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?**
The **event loop** is the core mechanism of `asyncio`. It manages and schedules the execution of asynchronous tasks. When an `await` is encountered, the coroutine pauses, and the event loop switches context to run another ready task instead of blocking the entire thread.
* **`asyncio.run(coro)`:** Runs the top-level coroutine and manages the event loop lifecycle (starts, runs, and closes the loop).
* **`asyncio.gather(*coros)`:** Runs multiple awaitables concurrently and waits for all of them to complete, returning a list of their results.
* **`asyncio.create_task(coro)`:** Schedules a coroutine to run concurrently on the event loop immediately, returning a `Task` object that can be awaited later.
**Why `time.sleep()` fails:** `time.sleep()` is a *blocking* call. If called inside an `async` function, it halts the entire thread, which in turn halts the event loop, preventing *any* other scheduled tasks from running until the sleep is over, defeating the purpose of asynchronous programming. You must use `await asyncio.sleep(delay)` instead.

**P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**
**MRO:** MRO defines the order in which Python searches the base classes of a class to find a specific method or attribute.
**Algorithm:** Python 3 uses the **C3 Linearization Algorithm**. This algorithm ensures a consistent, predictable, and monotonic ordering that respects the inheritance hierarchy, even in complex diamond structures.
**Diamond Inheritance Example:**
```python
class A:
    def who(self): return "A"
class B(A): pass
class C(A): def who(self): return "C"
class D(B, C): pass
print(D().who()) # Output: C
```
The C3 algorithm dictates that when resolving `D`, it checks `D` $\rightarrow$ `B` $\rightarrow$ `C` $\rightarrow$ `A` $\rightarrow$ `object`. When it reaches `B`, it looks up `who()`. Since `B` inherits from `A`, it checks `A`. When it moves to `C`, it checks `C`. Since `C` defines `who()`, that definition is chosen over the one in `A` because `C` appears later in the inheritance list (`D(B, C)`), and the algorithm prioritizes the most specific definition encountered first in the linearization path.

**P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.**
A **metaclass** is the "class of a class." It controls how a class itself is created. When you define `class MyClass(metaclass=MyMeta):`, `MyMeta` is responsible for building `MyClass`.
* **`__init_subclass__`:** A class method available since Python 3.6. It is called *after* a subclass has been created but *before* it is fully initialized. It is used to modify the subclass *after* it has been defined.
* **Metaclass:** Controls the *creation* process itself. It is used when you need to fundamentally alter the structure or behavior of the class definition before it even exists as a class object.
**Use Cases:**
* **Metaclass:** Implementing ORMs or framework structures where you need to automatically inject methods or properties into every class that uses your framework (e.g., automatically adding a `save()` method to every model).
* **`__init_subclass__`:** Implementing simple registration or validation hooks on subclasses (e.g., automatically registering all subclasses of a base `Plugin` class into a central registry).

**P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?**
* **Threading:** Uses threads within a single process. Best for **I/O-bound** tasks where threads can release the GIL while waiting. Limited by the GIL for CPU-bound work.
* **Multiprocessing:** Uses separate OS processes. Bypasses the GIL, enabling true **CPU-bound** parallelism across cores. Higher overhead due to process creation.
* **`concurrent.futures`:** A high-level abstraction layer that provides a unified interface (`ThreadPoolExecutor` for threads, `ProcessPoolExecutor` for processes) to manage both threading and multiprocessing easily.
**Serialization Implications (Pickling):** When using `multiprocessing`, data passed between processes must be serialized (pickled) to be sent across process boundaries. This means that complex, non-serializable objects (like open file handles or database connections) cannot be passed directly between processes.

**P10 — Medium: What is __slots__? When should you use it, and what does it prevent? What is the memory impact?**
`__slots__` is a class attribute that explicitly declares the attributes an instance of a class will have.
**What it prevents:** It prevents the creation of the instance dictionary (`__dict__`) for each object. Normally, Python uses `__dict__` to store attributes dynamically, which adds memory overhead.
**When to use it:** When you are creating a large number of instances of a class (e.g., millions of data points) and memory efficiency is critical.
**Memory Impact:** It significantly reduces the memory footprint of instances by replacing the dynamic `__dict__` with a fixed, optimized structure based on the defined slots.

**P11 — Easy: What is a virtual environment, and why should you use one? What is the difference between venv, virtualenv, and conda?**
A **virtual environment** is an isolated directory containing a specific Python interpreter and its own set of installed packages.
**Why use it:** It prevents dependency conflicts between different projects. Project A might require Django 2.0, while Project B requires Django 4.0. A virtual environment ensures that installing one package for Project A does not break Project B.
**Differences:**
* **`venv`:** The standard, built-in module in Python 3.3+ for creating lightweight virtual environments.
* **`virtualenv`:** An older, more feature-rich third-party tool that predates `venv` and offers more customization.
* **`conda`:** A comprehensive environment and package manager (often used in data science) that manages not just Python packages but also non-Python dependencies (like specific versions of NumPy compiled against specific C libraries).

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?**
These are concise, readable syntax for creating collections based on existing iterables.
* **List Comp:** `[expression for item in iterable if condition]`
* **Dict Comp:** `{key_expr: value_expr for item in iterable if condition}`
* **Set Comp:** `{expression for item in iterable if condition}`
**Relation to `map()` and `filter()`:** Comprehensions are syntactic sugar that combine the functionality of `map()` (transformation) and `filter()` (selection) into a single, cleaner line.
**Preference:** Comprehensions are generally preferred in Python because they are more idiomatic, readable, and often slightly faster than explicit `map()`/`filter()` calls, especially when combining both transformation and filtering.

**P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?**
* **`==`:** Checks for *equality* of value. It calls the object's `__eq__()` method.
* **`is`:** Checks for *identity*. It checks if two variables point to the exact same object in memory (i.e., if they have the same `id()`).
**Object Interning:** Interning is an optimization technique where Python pre-allocates and reuses immutable objects (like small integers, short strings) in memory.
**Small Integers:** Python caches small integers (typically -5 to 256) to save memory and speed up comparisons. Therefore, `a = 100` and `b = 100` often result in `a is b` being `True` because both variables point to the same cached object. Larger integers are usually not interned and will require a new object creation.

**P14 — Easy: Explain Python's *args and **kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?**
* **`*args`:** Collects any number of positional arguments into a tuple.
* **`**kwargs`:** Collects any number of keyword arguments into a dictionary.
* **Positional-Only (`/`):** Arguments listed before `/` *must* be passed by position and cannot be passed using a keyword argument.
* **Keyword-Only (`*`):** Arguments listed after `*` *must* be passed using their keyword name; positional arguments are not allowed for them.
**Example:** `def func(a, b, /, c, *, d):`
* `a`, `b` must be positional.
* `c` can be positional or keyword.
* `d` must be keyword.

**P15 — Easy: What are context managers (with statement)? How do you write one using __enter__/__exit__ vs @contextmanager? Give an example beyond file handling.**
A context manager is an object that defines the runtime context to be established when executing a `with` statement. It guarantees that setup actions are performed upon entry and teardown actions are performed upon exit, even if errors occur.
* **`__enter__` / `__exit__`:** The traditional way. `__enter__` returns the resource to be used inside the `with` block; `__exit__` handles cleanup (receiving exception details if one occurred).
* **`@contextmanager`:** A simpler, generator-based approach from the `contextlib` module. The code before `yield` is the setup, and the code after `yield` is the teardown.
**Example (Database Connection Pool):** A context manager can manage acquiring a connection from a pool (`__enter__`) and ensuring it is released back to the pool (`__exit__`) automatically.

**P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How does mypy or pyright use these for static analysis?**
Type hinting (PEP 484) allows developers to optionally annotate variables, function parameters, and return values with expected types. This does *not* enforce types at runtime; it is metadata used by static type checkers.
* **`Union[A, B]`:** Indicates a variable can be of type A OR type B.
* **`Optional[T]`:** A shorthand for `Union[T, None]`.
* **`Literal[value]`:** Restricts a variable to only accept a specific, fixed value (e.g., `Literal["success", "error"]`).
* **`TypeVar`:** A placeholder for a type variable, used to write generic functions or classes that can operate on various types while maintaining type safety.
* **`Protocol`:** Defines a structural type. Instead of inheriting from a class, a class conforms to a Protocol if it implements the required methods/attributes (Duck Typing enforced statically).
**Static Analysis:** Tools like Mypy or Pyright read these hints and analyze the code *before* execution. If a function expects an `int` but is passed a `str`, the type checker flags an error, catching bugs early.

**P17 — Medium: Explain Python's data model (dunder methods). What are __repr__ vs __str__, __eq__ vs __hash__, and __getattr__ vs __getattribute__? What happens if you define __eq__ but not __hash__?**
Dunder methods (double underscore methods) are special methods that define how Python objects interact with built-in operators and functions.
* **`__repr__` vs `__str__`:** `__repr__` (representation) should return an unambiguous, developer-friendly string, ideally one that could recreate the object (`repr(obj)`). `__str__` (string) should return a readable, end-user friendly string (`print(obj)`).
* **`__eq__` vs `__hash__`:** `__eq__` defines value equality. `__hash__` defines how an object is mapped to an integer for use in hash-based collections (sets, dict keys).
* **`__getattr__` vs `__getattribute__`:** `__getattr__` is called *only* when a requested attribute is not found normally. `__getattribute__` is called for *every* attribute access, making it powerful but dangerous if not implemented carefully.
**Missing `__hash__`:** If you define `__eq__` but *not* `__hash__`, Python will raise a `TypeError` if you try to use that object as a key in a dictionary or add it to a set, because the hash value is required for lookup.

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (__get__, __set__, __delete__). How do property, classmethod, and staticmethod use descriptors under the hood?**
A **descriptor** is an object attribute that defines how attribute access (getting, setting, or deleting) is handled for that attribute.
**Descriptor Protocol:** An object becomes a descriptor if it implements one or more of these methods:
* **`__get__(self, instance, owner)`:** Called when the attribute is accessed.
* **`__set__(self, instance, value)`:** Called when the attribute is assigned a value.
* **`__delete__(self, instance)`:** Called when the attribute is deleted.
**Usage:**
* **`property`:** Uses descriptors to manage attribute access, allowing you to define getters, setters, and deleters for an attribute.
* **`classmethod` and `staticmethod`:** These are built-in descriptors that modify how the method is bound to the class or instance, respectively.

**P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, __init__.py, and namespace packages work? What is a finder and a loader?**
The import system finds modules by searching directories listed in `sys.path`.
* **`sys.path`:** A list of strings that specifies the search path for modules.
* **`PYTHONPATH`:** An environment variable that adds directories to `sys.path` before the script runs.
* **`__init__.py`:** Historically, this file marked a directory as a Python package, allowing imports from it.
* **Namespace Packages:** A modern feature where a directory *without* an `__init__.py` can still be part of a package structure, allowing multiple, independent packages to contribute to the same top-level namespace.
**Relative vs. Absolute Imports:**
* **Absolute:** Imports start from the root of the package (e.g., `from my_app.utils import helper`).
* **Relative:** Imports reference the current package location (e.g., `from . import sibling_module`).
**Finder and Loader:** When an import is requested, Python uses **Finders** (e.g., `PathFinder`) to locate the module file on `sys.path`. Once found, a **Loader** (e.g., `SourceFileLoader`) is responsible for reading the file content and executing the code to create the module object.

**P20 — Hard: What are dataclasses and how does it compare to attrs and Pydantic? Explain __post_init__, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**
**Dataclasses:** A decorator (`@dataclass`) that automatically generates boilerplate methods like `__init__`, `__repr__`, `__eq__`, etc., based on type-hinted class attributes.
**Comparison:**
* **`attrs`:** A mature library that provides similar functionality to dataclasses but offers more customization hooks.
* **Pydantic:** A data validation library. It enforces *runtime* data validation, type coercion, and serialization/deserialization (e.g., JSON parsing).
**Features:**
* **`__post_init__`:** A method called immediately after the generated `__init__` runs, allowing for custom setup logic (e.g., calculating a derived field).
* **Field Factories:** Using `field(default_factory=list)` allows you to provide mutable defaults (like lists or dicts) safely, preventing all instances from sharing the same default object.
* **Frozen Dataclasses:** Using `frozen=True` makes the instance immutable, similar to a `tuple` or `typing.Final`.
**Inheritance:** Dataclasses support inheritance, but you must be careful with `__init__` generation; often, you need to manually define `__init__` or use `__post_init__` to handle inherited fields correctly.
**When to choose Pydantic:** Choose Pydantic when you are dealing with **external, untrusted data** (API payloads, configuration files) that needs strict validation, coercion, and serialization guarantees. Choose dataclasses when you are modeling **internal, trusted data structures** where boilerplate reduction is the primary goal.
