## Networking Answers

**N1 — Easy:** A Layer 2 switch operates primarily at the Data Link Layer (Layer 2) of the OSI model, using MAC addresses to forward frames within the same broadcast domain (VLAN). A Layer 3 switch operates at both Layer 2 and Layer 3. It can perform MAC address forwarding (like a L2 switch) but also routes packets between different IP subnets using routing protocols and IP addresses (like a router).

**N2 — Easy:** The IP address is $10.0.5.37/20$.
The subnet mask for $/20$ is $255.255.240.0$.
The network address is found by performing a bitwise AND operation: $10.0.5.37 \text{ AND } 255.255.240.0 = 10.0.0.0$.
The broadcast address is the last address in the range: $10.0.0.0$ to $10.0.15.255$. The broadcast address is $10.0.15.255$.

**N3 — Medium:** The TCP three-way handshake establishes a reliable connection:
1. **SYN (Synchronize):** Client sends a segment with the SYN flag set to the server, proposing an initial sequence number (ISN).
2. **SYN-ACK (Synchronize-Acknowledge):** Server receives the SYN, allocates resources, and responds with a segment that has both SYN and ACK flags set, acknowledging the client's ISN and proposing its own ISN.
3. **ACK (Acknowledge):** Client receives the SYN-ACK and sends a final ACK segment, acknowledging the server's ISN.
If the final ACK is lost, the client will retransmit the ACK (or the server will time out waiting for the final ACK and retransmit its SYN-ACK). The connection will remain in a half-open state until the retransmission timers expire, leading to connection timeouts on both sides.

**N4 — Medium:**
*   **SNAT (Source Network Address Translation):** Changes the *source* IP address of a packet as it leaves a private network, typically to a public IP address.
    *   *Example:* A host on a private LAN (e.g., 192.168.1.10) accesses the internet. The router translates the source IP to its public IP (e.g., 203.0.113.5) before sending it out.
*   **DNAT (Destination Network Address Translation):** Changes the *destination* IP address of a packet as it enters a private network.
    *   *Example:* An external user accesses a web server via the public IP (203.0.113.5). The router translates the destination IP to the internal server's private IP (e.g., 192.168.1.50).

**N5 — Medium:** Three possible causes for `SSL: certificate subject name does not match target host name`:
1.  **Incorrect Hostname:** The hostname used in the `curl` command does not match the Common Name (CN) or Subject Alternative Name (SAN) listed in the server's SSL certificate.
2.  **Certificate Mismatch/Misconfiguration:** The server administrator has installed the wrong certificate on the web server, or the certificate was issued for a different domain entirely.
3.  **DNS Resolution Issue (Man-in-the-Middle/Local Cache):** The client might be resolving the hostname to an incorrect IP address (e.g., an old or malicious IP), causing it to connect to a server presenting a certificate for a different domain.

**N6 — Medium:**
*   **VLAN (Virtual Local Area Network):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains based on a tag (802.1Q). It is limited by the physical infrastructure's size and the 4094 VLAN ID limit.
*   **VxLAN (Virtual Extensible LAN):** A network virtualization overlay technology that encapsulates Layer 2 Ethernet frames within Layer 3 UDP/IP packets. It uses a VNI (Virtual Network Identifier) instead of a VLAN ID.
*   **When to choose VxLAN:** VxLAN is chosen over VLAN when the network requires **scalability beyond the 4094 VLAN limit** or when extending Layer 2 domains across **non-contiguous Layer 3 networks** (i.e., spanning different physical subnets).

**N7 — Hard:**
*   **Why:** The traffic arriving on `eth1` (192.168.1.0/24) is destined for a host that is reachable via `eth0` (10.0.0.0/24) *if* the routing table is configured to prefer the 10.0.0.0/24 route for the return traffic, or if the default gateway on `eth1` points to a router that routes back through `eth0`. More commonly, the kernel's routing decision for the *return* traffic is based on the source IP of the original packet (192.168.1.5) and the destination IP of the reply. If the default route points to the 10.0.0.1 gateway, the return traffic will follow that path, even if the ingress interface was `eth1`.
*   **How to fix with Policy-Based Routing (PBR):** PBR allows routing decisions to be made based on criteria other than the destination IP address (e.g., source IP, ingress interface). You would create a routing rule that states: "If traffic originates from the 192.168.1.0/24 subnet, use the routing table associated with `eth1` (or a specific gateway associated with `eth1`) for egress." This is typically done using `ip rule add from 192.168.1.0/24 table X`.

**N8 — Hard:** BGP path selection is a complex algorithm used by BGP speakers to choose the single best path to a destination prefix from multiple learned paths. The attributes are evaluated sequentially; the first attribute that differs determines the preferred path.
The general order of preference (though specific implementations vary slightly) is:
1. **Weight** (Cisco proprietary, highest preference)
2. **Local Preference** (Highest is preferred, used internally within an AS)
3. **Locally Originated** (Prefer paths originated locally)
4. **AS Path Length** (Shortest path is preferred)
5. **Origin Type** (IGP > EGP > Incomplete)
6. **MED (Multi-Exit Discriminator)** (Lowest is preferred, used to influence external peers)

**N9 — Hard:**
*   **MTU Implication:** When running VxLAN over an IPsec tunnel, the original Ethernet frame (which has an MTU of 1500 bytes) is encapsulated multiple times:
    1.  Original Ethernet Frame (Payload)
    2.  VxLAN Header (adds overhead)
    3.  UDP Header (adds overhead)
    4.  IP Header (adds overhead)
    5.  IPsec Header (adds significant overhead, e.g., ESP/AH headers)
    6.  Outer IP Header (adds overhead)
*   **Math:** If the physical MTU is 1500 bytes, the total overhead must be subtracted from 1500 to find the maximum inner payload.
    *   *Typical Overhead Estimate:* VxLAN (50 bytes) + UDP (8 bytes) + IP (20 bytes) + IPsec (e.g., 50-70 bytes depending on mode) + Outer IP (20 bytes).
    *   *Calculation:* Max Inner Payload $\approx 1500 - (\text{VxLAN Overhead} + \text{UDP} + \text{IP} + \text{IPsec} + \text{Outer IP})$. If we conservatively estimate $\approx 100$ bytes of overhead, the maximum inner payload is $1500 - 100 = 1400$ bytes.

**N10 — Medium:**
*   **Purpose of ARP (Address Resolution Protocol):** ARP maps a known Layer 3 IP address to its corresponding Layer 2 MAC address within a local network segment. A host broadcasts an ARP request asking, "Who has IP X.X.X.X? Tell me your MAC address." The host with that IP replies with an ARP reply containing its MAC address.
*   **Gratuitous ARP:** A host sends out an ARP reply to its *own* IP address without being asked. This solves problems like:
    1.  **Duplicate IP Detection:** A host can announce its presence to ensure no other host is using its IP.
    2.  **MAC/IP Binding Updates:** It forces neighboring devices (like switches) to immediately update their ARP/MAC tables with the host's current MAC address, which is crucial after a host changes NICs or moves.

**N11 — Easy:**
*   **Public IP:** An IP address globally unique and routable on the public internet. It must be assigned by an IANA-approved registry.
*   **Private IP:** An IP address reserved for use within private, local area networks (LANs). These addresses are not routable on the public internet and require NAT to communicate externally.
*   **RFC 1918 Ranges:**
    1.  $10.0.0.0/8$
    2.  $172.16.0.0/12$
    3.  $192.168.0.0/16$

**N12 — Easy:**
*   **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses (like `93.184.216.34`) and vice versa.
*   **Record Types:**
    *   **A Record:** Maps a hostname to an IPv4 address (e.g., `www.example.com` $\rightarrow$ `192.0.2.1`).
    *   **CNAME Record (Canonical Name):** Creates an alias from one domain name to another canonical domain name (e.g., `blog.example.com` $\rightarrow$ `servers.example.com`).
    *   **AAAA Record:** Maps a hostname to an IPv6 address (e.g., `www.example.com` $\rightarrow$ `2001:db8::1`).

**N13 — Easy:**
*   **DHCP (Dynamic Host Configuration Protocol):** A network management protocol used to automatically assign IP addresses and other network configuration parameters (subnet mask, gateway, DNS servers) to devices on a network.
*   **DORA Process:**
    1.  **Discover:** Client broadcasts a DHCP Discover message to find available servers.
    2.  **Offer:** DHCP server replies with a DHCP Offer, proposing an IP address configuration.
    3.  **Request:** Client broadcasts a DHCP Request, formally accepting the offered configuration.
    4.  **Acknowledge:** DHCP server sends a final DHCP ACK, confirming the lease and providing all necessary configuration details.

**N14 — Easy:**
*   **Hub:** Operates at Layer 1 (Physical Layer). It is a simple repeater that broadcasts all incoming electrical signals out of every other port, creating one large collision domain.
*   **Switch:** Operates at Layer 2 (Data Link Layer). It learns MAC addresses and forwards frames only to the intended destination port, segmenting collision domains.
*   **Router:** Operates at Layer 3 (Network Layer). It uses IP addresses to forward packets between different networks (subnets), making routing decisions based on the destination IP.

**N15 — Easy:**
*   **Half-Duplex:** Allows data transmission in both directions, but only one direction at a time (e.g., a walkie-talkie). Collisions can occur if both parties transmit simultaneously.
*   **Full-Duplex:** Allows simultaneous transmission and reception of data over the same link (e.g., a telephone call). Collisions are eliminated.
*   **Modern Ethernet:** Modern Ethernet links overwhelmingly use **full-duplex** communication.

**N16 — Medium:**
*   **Purpose of TTL (Time To Live):** The TTL field is an 8-bit field in the IP header that specifies the maximum number of hops (routers) a packet can traverse before being discarded.
*   **Traceroute Exploitation:** `traceroute` (or `tracert`) exploits the TTL mechanism. It sends a sequence of packets, starting with TTL=1. The first router decrements the TTL to 0 and drops the packet, sending back an ICMP "Time Exceeded" message. The next packet is sent with TTL=2, allowing it to reach the second router, which then sends the ICMP message, and so on. This allows the tool to map the path hop-by-hop.

**N17 — Medium:**
*   **NAT Gateway:** A router or firewall device that performs Network Address Translation (NAT), allowing multiple devices on a private internal network to share a single public IP address when accessing the external internet.
*   **Differences:**
    *   **Static NAT:** Maps one specific private IP address to one specific public IP address permanently (1:1 mapping). *Example: Mapping internal server 192.168.1.10 to public IP 203.0.113.10.*
    *   **Dynamic NAT:** Maps private IP addresses to a pool of available public IP addresses on a first-come, first-served basis.
    *   **PAT (Port Address Translation) / NAT Overload:** The most common form. It maps multiple private IP addresses to a *single* public IP address by tracking unique source port numbers for each internal connection.

**N18 — Hard:**
*   **ECMP (Equal-Cost Multi-Path):** A routing technique that allows a router to install multiple paths into its routing table for the same destination prefix, provided all paths have the same administrative cost (metric). The router then distributes traffic across these multiple paths simultaneously.
*   **Hashing Strategies:** Common strategies include hashing based on:
    1.  Source IP Address
    2.  Destination IP Address
    3.  Source and Destination Port Numbers (most granular)
    4.  A combination of the above.
*   **Asymmetric Flows Problem:** If a stateful firewall is involved, asymmetric routing occurs when the outbound traffic takes one path (e.g., Path A) and the return traffic takes a different path (e.g., Path B). Stateful firewalls track connections based on the session state established on the ingress interface. If the return packet arrives on an interface the firewall did not expect for that session, it may be dropped because the state table does not match the incoming packet's expected flow, leading to connection failure.

**N19 — Hard:**
*   **Problem:** The Bandwidth-Delay Product (BDP) is $10 \text{MB}$. This represents the maximum amount of data that can be "in flight" on the network path at any given time. If the TCP window size is capped at $64 \text{KB}$, the sender can only transmit $64 \text{KB}$ before waiting for an acknowledgment (ACK). Since $64 \text{KB} \ll 10 \text{MB}$, the sender spends most of its time idle waiting for ACKs, leading to severe underutilization of the available bandwidth, manifesting as high latency/low throughput.
*   **Solution (TCP Window Scaling):** Standard TCP headers only allow a window size up to $65,535$ bytes. TCP Window Scaling (RFC 1323) introduces a scaling factor into the TCP header. This allows the advertised receive window size to be exponentially larger than $64 \text{KB}$ (up to $1 \text{GB}$ or more), enabling the sender to fill the entire BDP and utilize the available bandwidth efficiently.

**N20 — Hard:**
*   **802.1Q Trunk Ports:** This standard allows a single physical link (trunk) to carry traffic for multiple VLANs simultaneously. The switch inserts a 4-byte **VLAN tag** into the Ethernet frame header. This tag identifies which VLAN the frame belongs to.
*   **Linux Configuration (Sub-interfaces):** On Linux, this is achieved by creating virtual sub-interfaces on the physical NIC.
    1.  The physical interface (`eth0`) is configured as a trunk port (or simply left up).
    2.  Sub-interfaces are created, e.g., `eth0.10`, `eth0.20`, `eth0.30`.
    3.  Each sub-interface is assigned the appropriate VLAN ID and IP address for that VLAN.
    *Example:* `ip link add link eth0 name eth0.10 type vlan id 10` followed by `ip addr add 10.10.10.5/24 dev eth0.10`.
*   **Frame Format on the Wire:** The frame structure is: `[Ethernet Header] + [802.1Q Tag (VLAN ID)] + [Original Ethernet Payload]`. The tag is inserted immediately after the standard Ethernet header fields.

## Linux Answers

**L1 — Easy:**
*   **Hard Link:** A hard link is a directory entry that points directly to the same inode (the data structure containing file metadata and data block pointers) as the original file. If you delete the original filename, the data remains accessible via the hard link until the last link is removed. Hard links cannot span across different filesystems and cannot link to directories.
*   **Symbolic Link (Symlink):** A symbolic link is a special type of file that contains a *text path* pointing to another file or directory. It is like a shortcut. If the original file is moved or deleted, the symlink breaks (becomes a dangling link).

**L2 — Easy:** Use the `find` command:
`find /var/log -type f -size +100M`

**L3 — Medium:**
*   **State D (Uninterruptible Sleep):** This state means the process is waiting for an I/O operation (like disk read/write or network activity) to complete. The process is blocked waiting for hardware, and it cannot be interrupted by signals (like SIGTERM or SIGKILL).
*   **Killing:** Because it is uninterruptible, `kill -9` (SIGKILL) will **not** work. The process must wait for the underlying I/O operation to complete or for the hardware/driver issue causing the wait to be resolved.

**L4 — Medium:**
*   **cgroups v1:** Used a hierarchical, resource-specific model. Controls were often siloed (e.g., CPU controller, Memory controller). It was less unified and often required complex setup for cross-controller management.
*   **cgroups v2:** Implements a unified hierarchy. It provides a single, unified view of resource control across all controllers (CPU, Memory, I/O, etc.). It enforces stricter hierarchy and resource accounting.
*   **Systemd Preference:** Systemd prefers **cgroups v2** because its unified hierarchy and cleaner resource accounting model align better with systemd's own service management structure, leading to more predictable and robust container and service management.

**L5 — Medium:**
*   **iptables:** The older, traditional firewall framework. It operates by chaining rules (INPUT, OUTPUT, FORWARD) and matching packets against those rules.
*   **nftables:** The modern replacement for iptables. It is a more flexible, unified framework that can handle packet filtering, NAT, and connection tracking using a single, more expressive syntax and data structure.
*   **Kernel Handling:** The Linux kernel maintains both systems for backward compatibility. When both are present, the kernel typically routes traffic through the `nftables` framework if it is the active default, but older rulesets might still be processed by the legacy `iptables` hooks until they are fully migrated.

**L6 — Medium:** The most likely cause is that the filesystem contains a large number of **small files** or **metadata overhead** (e.g., many inodes, large directory structures) rather than a few large files. `du` calculates the disk usage of the *contents* of directories, while `df` reports the total block usage of the filesystem, which includes space reserved for metadata and filesystem structures.

**L7 — Hard:**
1.  **UEFI Firmware:** The system powers on, and the UEFI firmware initializes hardware. It locates the bootloader (e.g., GRUB2) from the EFI System Partition (ESP) and executes it.
2.  **Bootloader (GRUB2):** The bootloader loads the Linux kernel image (`vmlinuz`) and the initial RAM disk (`initrd` or `initramfs`) into memory. It passes kernel command-line arguments (like root device location) to the kernel.
3.  **Kernel:** The kernel initializes core subsystems (memory management, process scheduling, drivers). It mounts the `initramfs` into a temporary root filesystem.
4.  **Initramfs:** This minimal, temporary root filesystem contains necessary drivers and scripts to mount the *real* root filesystem (which might be on LVM, encrypted, or a different partition). The `init` process within the initramfs runs scripts to prepare the environment.
5.  **Root Filesystem:** The initramfs mounts the actual root filesystem (e.g., `/`).
6.  **Systemd:** The kernel executes the first process, which is typically `/sbin/init` (or `systemd`). Systemd takes over, reads configuration files, manages services, mounts remaining filesystems, and brings the entire system to the desired operational target (e.g., `multi-user.target`).

**L8 — Hard:**
*   **Why Available is Low:** The `available` memory metric in `free -h` is calculated as `free + buffers + cache`. However, the OOM killer fires when the kernel determines that *active* processes require memory that cannot be satisfied, even if large amounts of memory are marked as `buff/cache`. The kernel prioritizes keeping application memory intact. If the system is under heavy memory pressure (many processes actively requesting memory), the kernel might decide that the memory currently held in cache is not "available" for immediate allocation to a demanding process, leading to the OOM killer invocation.
*   **Kernel Tunables:** Key tunables include:
    *   `vm.swappiness`: Controls the kernel's tendency to swap out anonymous memory. A lower value keeps more data in RAM.
    *   `vm.vfs_cache_pressure`: Controls how aggressively the kernel reclaims memory used for directory and inode caches.

**L9 — Medium:**
*   **`ip netns`:** This command is used to manage network namespaces in Linux. A network namespace is an isolated view of the system resources (network interfaces, routing tables, process IDs, etc.). It allows one process or container to have its own completely isolated networking stack, independent of the host system.
*   **Container Runtime Usage:** Container runtimes (like Docker or Kubernetes) use network namespaces to give each container its own virtual network environment. When a container starts, the runtime creates a new network namespace, moves the container's processes into it, and configures virtual interfaces (like `veth` pairs) within that namespace, effectively isolating its network stack from the host.

**L10 — Medium:**
*   **SIGTERM (Signal 15):** The standard, polite termination signal. It requests the process to shut down gracefully, allowing it to clean up resources (save files, close connections).
*   **SIGKILL (Signal 9):** The forceful, immediate termination signal. The kernel kills the process instantly; the process has no chance to clean up, which can lead to data corruption.
*   **SIGQUIT (Signal 3):** Requests the process to quit, often causing it to dump a core file for debugging purposes before exiting.
*   **Catchable:** **SIGTERM** and **SIGQUIT** can be caught, handled, or ignored by the process using signal handlers. **SIGKILL** cannot be caught or ignored.

**L11 — Easy:**
*   **stdin (Standard Input):** Where a program reads its input from (default: keyboard).
*   **stdout (Standard Output):** Where a program writes its normal, successful output to (default: terminal screen).
*   **stderr (Standard Error):** Where a program writes error messages and diagnostic output to (default: terminal screen).
*   **Redirection:** To redirect stderr to a file (`errors.log`) while keeping stdout on the terminal:
    `command 2> errors.log` (The `2>` redirects file descriptor 2, which is stderr).

**L12 — Easy:** `chmod 755 filename` sets the permissions for the file as follows:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = 7. The owner has full control.
*   **5 (Group):** Read (4) + Execute (1) = 5. The group can read and execute the file.
*   **5 (Others):** Read (4) + Execute (1) = 5. All other users can read and execute the file.

**L13 — Easy:**
*   **Root User (UID 0):** The superuser. The root user has unrestricted access to the entire operating system, can modify any file, change any configuration, and manage all processes without needing explicit permission checks.
*   **Sudo Privileges:** A user with `sudo` privileges can execute specific commands as another user (usually root) by prefixing the command with `sudo`. This grants *elevated privileges* for specific tasks but does not grant the user the absolute, unrestricted power of the root account itself.

**L14 — Easy:**
*   **Package Manager:** A system software that automates the process of installing, upgrading, configuring, and removing software packages on a Linux system, ensuring dependencies are met.
*   **Default Managers:**
    *   **Debian/Ubuntu:** `apt` (Advanced Package Tool)
    *   **RHEL/Fedora:** `dnf` (Dandified YUM)

**L15 — Easy:**
*   **`/etc/fstab`:** This file (File System Table) contains static configuration information that tells the operating system which filesystems to mount at boot time, where to mount them, and what options to use (e.g., read-only, permissions).
*   **Misconfiguration:** If an entry is misconfigured (e.g., incorrect UUID, wrong mount point, or invalid filesystem type), the system will likely **fail to boot** or will boot into a severely degraded state because it cannot mount essential filesystems (like `/home` or `/var`).

**L16 — Medium:**
*   **LVM (Logical Volume Manager):** A storage management abstraction layer that provides flexible volume management on top of physical storage devices. It allows administrators to pool physical storage into flexible units that can be resized and managed dynamically without needing to repartition physical disks.
*   **Components:**
    *   **Physical Volumes (PVs):** The actual physical storage devices or partitions that LVM uses (e.g., `/dev/sdb1`).
    *   **Volume Groups (VGs):** A pool of one or more PVs. The VG aggregates the physical space into a single manageable storage pool.
    *   **Logical Volumes (LVs):** The virtual, flexible partitions carved out of the VG. These are what the operating system sees and mounts (e.g., `/dev/vg_data/lv_home`).
*   **Extending an LV:** On a running system, you first extend the underlying VG (by adding more PVs or shrinking another LV), then you extend the specific LV using `lvextend -L +XG /dev/vg_name/lv_name`, and finally, you resize the filesystem *on* that LV using `resize2fs /dev/vg_name/lv_name`.

**L17 — Hard:**
*   **I/O Scheduler:** The kernel component responsible for ordering and merging I/O requests (reads/writes) destined for block devices (disks) to optimize disk head movement and throughput.
*   **Scheduler Comparison:**
    *   **mq-deadline:** A modern scheduler that prioritizes requests based on deadlines, aiming to prevent starvation while maintaining good throughput. Good for mixed workloads.
    *   **bfq (Budget Fair Queueing):** Designed specifically for desktop/interactive workloads. It aims to provide "fairness" by giving each process a guaranteed budget of I/O time, leading to lower latency for interactive tasks.
    *   **none:** Disables the scheduler, passing requests directly to the device driver. Best for specialized, high-performance storage arrays where the hardware handles scheduling optimally.
*   **Choice:** Choose **bfq** for interactive servers; **mq-deadline** for general-purpose servers; **none** for dedicated high-speed storage.
*   **Runtime Change:** You can change the scheduler for a block device using the `echo` command: `echo bfq > /sys/block/sdX/queue/scheduler` (where `sdX` is the device name).

**L18 — Hard:**
*   **Load Average Measurement:** The load average measures the average number of processes that are either **running** (in the run queue, actively using CPU) or **uninterruptible sleep** (waiting for I/O) over the last 1, 5, and 15 minutes. It is a measure of system *activity*, not just CPU utilization.
*   **I/O Wait Inflation:** When processes are stuck in uninterruptible sleep (state D) waiting for slow disk I/O, they are counted in the load average, even though they are not consuming CPU cycles. This inflates the load average, making the system *appear* overloaded even if the CPU utilization percentage is low.
*   **Diagnosis:**
    *   **CPU Bottleneck:** High CPU usage (`top`/`htop`) and high load average relative to the number of cores.
    *   **Disk Bottleneck:** High load average combined with high `%wa` (I/O Wait) reported by `top`, and slow response times when running `iostat` or `iotop`.
    *   **Network Bottleneck:** High load average combined with high network interface errors/drops reported by `ip -s link`, or high latency observed via `ping`/`mtr`.

**L19 — Hard:**
*   **SELinux Enforcement:** SELinux (Security-Enhanced Linux) enforces Mandatory Access Control (MAC). Unlike traditional DAC (Discretionary Access Control, based on user/group permissions), MAC dictates that *every* subject (process) must have a specific security context, and every object (file, port, socket) must have a corresponding context. The kernel enforces rules defining which contexts can interact with which other contexts, regardless of the UID/GID.
*   **Modes:**
    *   **Enforcing:** SELinux policies are strictly enforced. Any violation is blocked.
    *   **Permissive:** SELinux logs all policy violations (auditing mode) but does *not* block the action. This is used for testing.
    *   **Disabled:** SELinux is completely turned off, reverting to standard DAC.
*   **Troubleshooting Port Binding:** If a daemon fails to bind a non-standard port, check the audit logs (`/var/log/audit/audit.log`). If SELinux is blocking it, the logs will show a denial message related to the process context trying to access the port context. The fix is usually to use `semanage port -a -t http_port_t -p tcp 8080` to explicitly tell SELinux that the daemon's context is allowed to use that port.

**L20 — Hard:**
*   **Page Fault Handling:** A page fault occurs when a process attempts to access a virtual memory address whose corresponding physical memory page is not currently mapped into the process's address space. The kernel traps this fault, determines the required page, and initiates the necessary action (e.g., loading it from disk or allocating a new frame).
*   **Minor vs. Major Page Fault:**
    *   **Minor Page Fault:** The required page is already in physical memory but is mapped to a different process or is shared. The kernel only needs to update the process's page table entries (a fast operation).
    *   **Major Page Fault:** The required page is not in physical memory (it must be loaded from swap space or the original file on disk). This requires the kernel to perform slow I/O operations to fetch the data.
*   **THP Impact:** Transparent Huge Pages (THP) attempts to use large memory pages (e.g., 2MB instead of 4KB) to reduce TLB misses and improve performance for large memory workloads. However, the background compaction process required by THP can introduce unpredictable latency spikes (stuttering) when memory pressure is high.
*   **When to Disable:** Disable THP when applications are highly latency-sensitive (e.g., real-time trading, certain databases) and exhibit poor performance under heavy memory pressure due to compaction overhead.
