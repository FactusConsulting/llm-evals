## Networking Answers

**N1 — Easy:** A Layer 2 switch operates primarily at the Data Link Layer (Layer 2) of the OSI model, using MAC addresses to forward frames within the same broadcast domain (VLAN). A Layer 3 switch operates at both Layer 2 and Layer 3. It can perform MAC address forwarding (like a L2 switch) but also routes packets between different IP subnets using routing protocols and IP addresses (like a router).

**N2 — Easy:** The IP address is $10.0.5.37/20$.
The subnet mask for $/20$ is $255.255.240.0$.
The network address is found by performing a bitwise AND of the IP and the mask: $10.0.5.37 \text{ AND } 255.255.240.0 = 10.0.0.0$.
The broadcast address is the last address in the range: $10.0.0.0$ to $10.0.15.255$. The broadcast address is $10.0.15.255$.

**N3 — Medium:** The TCP three-way handshake establishes a reliable connection:
1. **SYN (Synchronize):** Client sends a segment with the SYN flag set to the server, proposing an initial sequence number (ISN).
2. **SYN-ACK (Synchronize-Acknowledge):** Server receives the SYN, allocates resources, and responds with a segment that has both SYN and ACK flags set, acknowledging the client's ISN and proposing its own ISN.
3. **ACK (Acknowledge):** Client receives the SYN-ACK and sends a final segment with the ACK flag set, acknowledging the server's ISN.
If the final ACK is lost, the client will retransmit the ACK (or the server will time out waiting for the final ACK and retransmit SYN-ACK). The connection will remain in a half-open state until the retransmission timers expire, leading to connection timeouts on both ends.

**N4 — Medium:**
*   **SNAT (Source Network Address Translation):** Changes the source IP address of a packet as it leaves a private network, typically to a public IP address. *Example:* A host on a private LAN (192.168.1.10) accesses the internet. The router changes the source IP from 192.168.1.10 to its public IP (203.0.113.5) before sending it out.
*   **DNAT (Destination Network Address Translation):** Changes the destination IP address of a packet as it enters a private network. *Example:* An external user accesses a web server at the public IP (203.0.113.5). The firewall/router uses DNAT to translate the destination IP to the internal server's private IP (192.168.1.50).

**N5 — Medium:** Three possible causes for `SSL: certificate subject name does not match target host name`:
1.  **Hostname Mismatch:** The hostname used in the `curl` command does not exactly match the Common Name (CN) or one of the Subject Alternative Names (SANs) listed in the server's SSL certificate.
2.  **Incorrect DNS Resolution:** The client resolved the hostname to the wrong IP address, and the server at that IP is presenting a certificate for a different domain.
3.  **Certificate Misconfiguration:** The server administrator incorrectly configured the web server, installing a certificate intended for a different domain onto the target server.

**N6 — Medium:**
*   **VLAN (Virtual Local Area Network):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains based on a tag (802.1Q). It is limited by the physical infrastructure's broadcast domain size (typically 4094 VLANs).
*   **VxLAN (Virtual Extensible LAN):** A network virtualization overlay technology that encapsulates Layer 2 Ethernet frames within Layer 3 UDP/IP packets. It uses a VNI (Virtual Network Identifier) instead of a VLAN ID.
*   **When to choose VxLAN:** VxLAN is chosen over VLAN when the network requires Layer 2 adjacency (L2 extension) across a large, multi-subnet, or geographically dispersed Layer 3 infrastructure (e.g., in large data centers or cloud environments), as it overcomes the 4094 VLAN limit and allows L2 domains to span L3 boundaries.

**N7 — Hard:**
*   **Why:** The routing decision is based on the source IP address of the packet. Since the traffic arriving on `eth1` has a source IP in the $192.168.1.0/24$ range, the kernel's main routing table sees that the best path back to $192.168.1.0/24$ is via the default gateway on `eth0` (10.0.0.1), assuming the default route points toward the $10.0.0.0/24$ network. The kernel uses the source IP to determine the egress interface.
*   **How to fix with policy-based routing (PBR):** You must create a routing rule that specifically dictates that traffic originating from the $192.168.1.0/24$ subnet *must* use `eth1` as the egress interface, overriding the default routing table. This is done using `ip rule` and `ip route` combined with routing marks.
    1.  Mark packets originating from $192.168.1.0/24$: `iptables -t mangle -A OUTPUT -s 192.168.1.0/24 -j MARK --set-mark 10`
    2.  Create a routing rule based on the mark: `ip rule add fwmark 10 table 100`
    3.  Define the specific route in the new table: `ip route add default via 192.168.1.1 dev eth1 table 100` (assuming 192.168.1.1 is the gateway for that subnet).

**N8 — Hard:** BGP path selection is a complex process where routers evaluate multiple attributes to select the single best path to a destination prefix. The process is hierarchical, and attributes are evaluated in a strict order of preference.
**5 Attributes in Order of Preference (Simplified):**
1.  **Weight (Cisco proprietary):** Highest weight is preferred.
2.  **Local Preference (Local to AS):** Highest local preference is preferred.
3.  **Locally Originated:** Prefer routes originated locally.
4.  **AS Path Length:** Shortest AS path is preferred (fewer AS hops).
5.  **Origin Type:** Prefer IGP over EGP over Incomplete.

**N9 — Hard:**
*   **MTU Implication:** When running VxLAN over an IPsec tunnel, the original Ethernet frame (which has an MTU of 1500 bytes) is encapsulated by the VxLAN header, which is then encapsulated by the IPsec header (ESP/AH) and finally by the outer IP header. Each encapsulation adds overhead.
*   **Math:**
    *   Physical MTU = 1500 bytes.
    *   VxLAN Header Overhead $\approx 50$ bytes (VNI, UDP/IP headers).
    *   IPsec Overhead (e.g., ESP + Auth) $\approx 50-70$ bytes.
    *   Total Overhead $\approx 100$ to $120$ bytes.
    *   Maximum Inner Payload $\approx 1500 - (\text{VxLAN Overhead} + \text{IPsec Overhead})$.
    *   If we estimate total overhead at 120 bytes: $1500 - 120 = 1380$ bytes. The maximum inner payload must be less than this value to avoid fragmentation.

**N10 — Medium:**
*   **Purpose of ARP (Address Resolution Protocol):** ARP maps a known Layer 3 IP address to its corresponding Layer 2 MAC address within a local network segment. A host broadcasts an ARP request asking, "Who has IP X.X.X.X? Tell me your MAC address." The host with that IP replies with an ARP reply containing its MAC address.
*   **Gratuitous ARP:** A host sends an ARP reply to its own IP address (a broadcast). This solves problems like **IP address conflicts** (if two hosts claim the same IP, the one that sends the gratuitous ARP will quickly update the ARP caches of neighbors, effectively claiming the address) and **MAC address changes** (e.g., after a host moves or changes NICs, it forces neighbors to update their cache immediately).

**N11 — Easy:**
*   **Public IP:** An IP address globally unique and routable on the public internet. It must be assigned by an ISP or RIR.
*   **Private IP:** An IP address reserved for use within private, local area networks (LANs). These addresses are not routable on the public internet and require NAT to communicate externally.
*   **RFC 1918 Ranges:**
    1.  $10.0.0.0/8$
    2.  $172.16.0.0/12$
    3.  $192.168.0.0/16$

**N12 — Easy:**
*   **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses (like `93.184.216.34`) and vice versa.
*   **Record Types:**
    *   **A Record:** Maps a hostname to an IPv4 address (e.g., `www.example.com` $\rightarrow$ `192.0.2.1`).
    *   **CNAME Record (Canonical Name):** Creates an alias from one domain name to another canonical domain name (e.g., `blog.example.com` $\rightarrow$ `servers.example.com`).
    *   **AAAA Record:** Maps a hostname to an IPv6 address (e.g., `www.example.com` $\rightarrow$ `2001:db8::1`).

**N13 — Easy:**
*   **DHCP (Dynamic Host Configuration Protocol):** A network management protocol used to automatically assign IP addresses and other network configuration parameters (subnet mask, gateway, DNS servers) to devices on a network.
*   **DORA Process:**
    1.  **Discover:** Client broadcasts a DHCP Discover message to find available servers.
    2.  **Offer:** Server replies with a DHCP Offer message, proposing an IP address and configuration.
    3.  **Request:** Client broadcasts a DHCP Request message, formally accepting the offered configuration.
    4.  **Acknowledge:** Server replies with a DHCP ACK message, finalizing the lease and configuration.

**N14 — Easy:**
*   **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming electrical signals out of every other port, creating one large collision domain.
*   **Switch:** Operates at Layer 2 (Data Link). It learns MAC addresses and forwards frames only to the intended destination port, creating smaller collision domains.
*   **Router:** Operates at Layer 3 (Network). It uses IP addresses to forward packets between different networks (subnets), making forwarding decisions based on routing tables.

**N15 — Easy:**
*   **Half-Duplex:** Allows data to travel in both directions, but only one direction at a time (e.g., a walkie-talkie). Collisions can occur if both sides transmit simultaneously.
*   **Full-Duplex:** Allows data to travel simultaneously in both directions (e.g., a telephone call). This eliminates collisions on modern switched networks.
*   **Modern Ethernet:** Modern Ethernet links overwhelmingly use **full-duplex** communication.

**N16 — Medium:**
*   **Purpose of TTL (Time To Live):** The TTL field is an 8-bit field in the IP header that specifies the maximum number of hops (routers) a packet can traverse before being discarded. It prevents packets from circulating indefinitely in routing loops.
*   **Traceroute Exploitation:** `traceroute` (or `tracert`) works by sending a sequence of packets (usually UDP or ICMP) with incrementally increasing TTL values.
    1.  The first packet is sent with TTL=1. The first router decrements it to 0 and drops the packet, sending back an ICMP "Time Exceeded" message. This identifies the first hop.
    2.  The second packet is sent with TTL=2. It passes the first router, is dropped by the second, and sends back "Time Exceeded," identifying the second hop.
    3.  This process continues until the packet reaches the final destination, which responds with a standard ICMP reply.

**N17 — Medium:**
*   **NAT Gateway:** A device (router/firewall) that translates private, non-routable IP addresses used within a local network into one or more public, routable IP addresses when communicating with the external internet.
*   **Differences:**
    *   **Static NAT:** A one-to-one, permanent mapping. A specific private IP is always mapped to a specific public IP (e.g., $192.168.1.10 \leftrightarrow 203.0.113.10$). Used for servers that need to be consistently reachable from the outside.
    *   **Dynamic NAT:** Maps private IPs to a pool of public IPs on a first-come, first-served basis. When a private host initiates traffic, it is assigned an available public IP from the pool for the duration of the session.
    *   **PAT (Port Address Translation) / NAT Overload:** Maps multiple private IPs to a *single* public IP address by tracking unique source port numbers. This allows thousands of internal hosts to share one public IP address.

**N18 — Hard:**
*   **ECMP (Equal-Cost Multi-Path):** ECMP allows a router to install multiple next-hop paths into its routing table for the same destination prefix, provided all paths have the same administrative cost (metric). The router can then load-balance traffic across these multiple paths simultaneously, increasing aggregate bandwidth.
*   **Hashing Strategies:** Common strategies involve hashing the packet header fields, typically using a combination of:
    *   Source IP Address
    *   Destination IP Address
    *   Source Port
    *   Destination Port
    *   The hash function determines which of the available equal-cost paths the packet will take.
*   **Asymmetric Flows Problem:** If a stateful firewall is involved, asymmetric routing occurs when the outbound path (e.g., Path A) is different from the return path (e.g., Path B). The firewall maintains state based on the initial connection seen on Path A. When the return traffic arrives on Path B, the firewall may not recognize the session state, leading to the connection being dropped, even if the paths are technically equal cost.

**N19 — Hard:**
*   **The Problem:** The Bandwidth-Delay Product (BDP) is calculated as Bandwidth $\times$ Round-Trip Time (RTT). It represents the maximum amount of unacknowledged data that can be "in flight" on the network path at any given time. If BDP is 10MB, the TCP sender needs to be able to send 10MB worth of data before receiving an ACK. If the TCP window size is capped at 64KB, the sender can only transmit 64KB before stalling, leading to the pipe being underutilized, resulting in high latency relative to the potential throughput.
*   **TCP Window Scaling (RFC 1323) Solution:** Standard TCP headers limit the advertised window size to 16 bits (max $\approx 64$KB). Window Scaling introduces a scaling factor (SW) into the TCP header. This factor allows the advertised window size to be multiplied by $2^{\text{SW}}$, effectively increasing the maximum window size far beyond 64KB, allowing the sender to fill the BDP and achieve higher throughput.

**N20 — Hard:**
*   **802.1Q Trunk Ports:** This standard allows a single physical link (trunk) to carry traffic for multiple VLANs simultaneously. The switch inserts a 4-byte **VLAN Tag** into the Ethernet frame header. This tag contains the VLAN ID (VID) that identifies which VLAN the frame belongs to.
*   **Linux Configuration (Sub-interfaces):** On Linux, this is achieved by creating virtual network interfaces (sub-interfaces) on the physical NIC, each configured for a specific VLAN ID.
    1.  Physical interface: `eth0`
    2.  VLAN 10: `eth0.10` (configured with IP for VLAN 10)
    3.  VLAN 20: `eth0.20` (configured with IP for VLAN 20)
    4.  VLAN 30: `eth0.30` (configured with IP for VLAN 30)
    The configuration uses the `vlan` module and assigns the appropriate ID to the sub-interface.
*   **Frame Format on the Wire:** The frame structure is: `[Ethernet Header] + [802.1Q Tag (4 bytes)] + [Original Ethernet Payload]`. The tag specifies the VLAN ID (10, 20, or 30) for that specific frame.

## Linux Answers

**L1 — Easy:**
*   **Hard Link:** A hard link is a directory entry that points directly to the same inode (the data structure containing file metadata) as the original file. If you delete the original filename, the data remains accessible via the hard link until the last link is removed. They share the same data blocks.
*   **Symbolic Link (Symlink):** A symbolic link is a special type of file that contains a text pointer (a path) to another file or directory. It is like a shortcut in Windows. If the target file is moved or deleted, the symlink breaks (dangling link).

**L2 — Easy:** Use the `find` command:
`find /var/log -type f -size +100M`

**L3 — Medium:**
*   **State D (Uninterruptible Sleep):** This state means the process is waiting for an event that cannot be interrupted by signals (like I/O completion, disk access, or network activity). The process is blocked waiting for a kernel resource.
*   **Killing:** You **cannot** reliably kill a process in state D using `kill -9` (SIGKILL). Since the process is waiting on the kernel, the kernel will not terminate it until the underlying I/O operation completes. Forcing termination might lead to data corruption or system instability if the I/O operation is critical.

**L4 — Medium:**
*   **cgroups v1:** Used a hierarchical, controller-based model where each resource (CPU, Memory, I/O) was managed by a separate, independent controller. It was less unified and often led to complex interactions between controllers.
*   **cgroups v2:** Implements a unified hierarchy. It uses a single, unified hierarchy structure where controllers are integrated. It provides a more coherent view of resource management across the entire system.
*   **Systemd Preference:** Systemd prefers **cgroups v2** because it offers a cleaner, more consistent, and more robust resource management model, which aligns better with systemd's goal of managing the entire system lifecycle cohesively.

**L5 — Medium:**
*   **iptables:** The older, traditional firewall framework. It operates by chaining rules (INPUT, OUTPUT, FORWARD) and matching packets against those rules.
*   **nftables:** The modern replacement for iptables. It is a more flexible, unified, and powerful framework that uses a single, unified syntax and structure, allowing for more complex rule sets and better performance.
*   **Kernel Handling:** The kernel maintains compatibility layers. When you use `iptables`, the kernel translates those commands into the underlying `nftables` structure (or its legacy implementation). This allows users to continue using `iptables` while the kernel is transitioning to the `nftables` backend.

**L6 — Medium:** The most likely cause is that the filesystem contains a large number of **small files** or **metadata overhead**. `df -h` reports the total allocated blocks used by the filesystem, while `du -sh /*` only sums the *content size* of the directories listed. If the filesystem is heavily used by inodes (e.g., millions of tiny log files), the metadata usage can consume the entire disk space reported by `df`, even if the actual data payload is small.

**L7 — Hard:**
1.  **UEFI Firmware:** The system powers on, and the UEFI firmware initializes hardware. It locates the bootloader (e.g., GRUB2) from the EFI System Partition (ESP) and executes it.
2.  **Bootloader (GRUB2):** The bootloader loads the Linux kernel image (`vmlinuz`) and the initial RAM disk (`initrd` or `initramfs`) into memory. It passes kernel command-line arguments (like root device location) to the kernel.
3.  **Kernel:** The kernel initializes core subsystems (memory management, process scheduling, drivers). It mounts the `initramfs` into a temporary root filesystem.
4.  **Initramfs:** This small, temporary root filesystem contains minimal tools and drivers necessary to locate and mount the *real* root filesystem (which might be on a different partition or require LVM/encryption).
5.  **Root Filesystem:** The `initramfs` executes the first process, typically `/init` or `systemd`. This process uses the information passed by the kernel to mount the actual, persistent root filesystem (e.g., `/`).
6.  **Systemd:** Once the root filesystem is mounted, `systemd` takes over as PID 1. It reads configuration files, starts essential services (networking, logging, etc.), and transitions the system into its desired operational target (e.g., `multi-user.target` or `graphical.target`).

**L8 — Hard:**
*   **Why Available is Low:** The `available` memory metric in `free -h` is calculated as `free + buffers + cache`. However, the OOM killer fires when the system needs memory for *new allocations* that cannot be satisfied by reclaiming buffers/cache, or when the kernel determines that the pressure is too high. Even if 15GB is in `buff/cache`, if the running applications are actively holding onto memory pages that the kernel cannot easily reclaim (e.g., memory locked by processes, or memory pages that are actively being used by the application), the system perceives a shortage of *usable* memory, triggering the OOM killer.
*   **Kernel Tunables:** Key tunables include:
    *   `vm.swappiness`: Controls the kernel's tendency to swap out anonymous memory. A lower value (e.g., 10) keeps more data in RAM.
    *   `vm.vfs_cache_pressure`: Controls how aggressively the kernel reclaims memory used for directory and inode caches.

**L9 — Medium:**
*   **`ip netns`:** This command is used to manage network namespaces. A network namespace is an isolated view of the system resources (network interfaces, routing tables, process IDs, etc.). It allows a process to run in an environment completely isolated from the host system and other namespaces.
*   **Container Runtimes Usage:** Container runtimes (like Docker or Kubernetes) heavily rely on network namespaces. When a container starts, the runtime creates a new network namespace for that container. It then configures virtual network interfaces (like `veth` pairs) to connect this isolated namespace to the host's network bridge, giving the container its own private, isolated network stack.

**L10 — Medium:**
*   **SIGTERM (Signal 15):** The standard, polite termination signal. It requests the process to shut down gracefully, allowing it to clean up resources (save files, close connections).
*   **SIGKILL (Signal 9):** The immediate, forceful termination signal. The kernel kills the process instantly; the process has no chance to clean up, making it "ungraceful."
*   **SIGQUIT (Signal 3):** Requests the process to terminate and usually dump a core file for debugging purposes.
*   **Catchable:** **SIGTERM** and **SIGQUIT** can be caught, handled, or ignored by the process using signal handlers. **SIGKILL** cannot be caught or ignored.

**L11 — Easy:**
*   **stdin (Standard Input):** Where a program reads its input from (default: keyboard).
*   **stdout (Standard Output):** Where a program writes its normal, successful output to (default: terminal screen).
*   **stderr (Standard Error):** Where a program writes error messages and diagnostic output to (default: terminal screen).
*   **Redirection:** To redirect stderr to a file (`errors.log`) while keeping stdout on the terminal:
    `command_name 2> errors.log` (The `2` refers to the stderr file descriptor).

**L12 — Easy:** `chmod 755 filename` sets the permissions for the file as follows:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = 7. The owner has full control.
*   **5 (Group):** Read (4) + Execute (1) = 5. The group can read and execute the file.
*   **5 (Others):** Read (4) + Execute (1) = 5. All other users can read and execute the file.

**L13 — Easy:**
*   **Root User (UID 0):** The superuser. The root user has unrestricted access to the entire operating system, can modify any file, change any configuration, and manage all processes without needing explicit permission checks.
*   **Sudo Privileges:** A user with `sudo` privileges can execute specific commands as another user (usually root) by prefixing the command with `sudo`. This grants *elevated privileges* for specific tasks, but it does not grant the user the absolute, unrestricted power of the root account itself.

**L14 — Easy:**
*   **Package Manager:** A system software that automates the process of installing, upgrading, configuring, and removing software packages on a Linux system, ensuring dependencies are met.
*   **Default Managers:**
    *   Debian/Ubuntu: `apt` (Advanced Package Tool)
    *   RHEL/Fedora: `dnf` (Dandified YUM)

**L15 — Easy:**
*   **`/etc/fstab`:** This file (File System Table) contains static configuration information that tells the operating system which filesystems to mount at boot time, where to mount them, and what options to use (e.g., read-only, permissions).
*   **Misconfiguration:** If an entry is misconfigured (e.g., incorrect UUID, wrong mount point, or invalid filesystem type), the system will likely **fail to mount that filesystem** during the boot sequence. Depending on the severity, this can halt the boot process entirely or result in a non-functional system if a critical partition (like `/home` or `/var`) fails to mount.

**L16 — Medium:**
*   **LVM (Logical Volume Manager):** A storage management abstraction layer that provides flexible volume management on top of physical storage devices. It allows administrators to pool physical storage into flexible units that can be resized and managed logically, independent of the underlying disk layout.
*   **Components:**
    *   **Physical Volumes (PVs):** The actual physical storage devices (e.g., hard drives or partitions) that are designated for use by LVM.
    *   **Volume Groups (VGs):** A pool of one or more PVs. The VG aggregates the raw storage capacity.
    *   **Logical Volumes (LVs):** The virtual partitions carved out of the VG. These are what the operating system sees and mounts (e.g., `/home` LV).
*   **Extending an LV:**
    1.  Extend the underlying PV (if necessary) or add a new PV to the VG.
    2.  Extend the Volume Group: `vgextend <VG_Name> /dev/new_pv`
    3.  Extend the Logical Volume: `lvextend -L +<Size> /dev/<VG_Name>/<LV_Name>`
    4.  Resize the filesystem *on* the LV: `resize2fs /dev/<VG_Name>/<LV_Name>` (for ext4)

**L17 — Hard:**
*   **I/O Scheduler Function:** The I/O scheduler manages the queue of read/write requests destined for a block device. Its job is to reorder and merge these requests to minimize disk head movement (seek time) and maximize throughput, optimizing performance based on the workload characteristics.
*   **Scheduler Comparison:**
    *   **mq-deadline:** A modern scheduler that prioritizes requests based on deadlines, ensuring fairness and preventing starvation, while still optimizing for throughput. Good for mixed workloads.
    *   **bfq (Budget Fair Queueing):** Designed specifically for desktop/interactive workloads. It aims to provide "fairness" by giving each process a guaranteed budget of I/O time, leading to lower latency for interactive tasks.
    *   **none:** Disables the scheduler, passing requests directly to the hardware. Best for specialized, high-performance storage arrays where the hardware handles scheduling optimally.
*   **Choosing/Changing:** Choose **bfq** for desktop responsiveness, **mq-deadline** for general servers, and **none** for specialized hardware. To change at runtime (requires root): `echo bfq > /sys/block/sdX/queue/scheduler` (where `sdX` is the device name).

**L18 — Hard:**
*   **Load Average Measurement:** The load average measures the average number of processes that are either **running** (in the run queue, actively using CPU) or **uninterruptible sleep** (waiting for I/O) over the last 1, 5, and 15 minutes. It is a measure of system *activity*, not just CPU utilization.
*   **I/O Wait Inflation:** When processes are stuck in uninterruptible sleep (D state) waiting for slow disk I/O, they contribute to the load average count, even though they are not consuming CPU cycles. This makes the load average appear high, suggesting CPU saturation when the bottleneck is actually the disk subsystem.
*   **Diagnosis:**
    *   **CPU Bottleneck:** High `us` (user) and `sy` (system) CPU time in `top`/`htop`.
    *   **Disk Bottleneck:** High `%wa` (I/O Wait) in `top`/`htop`, combined with slow response times reported by `iostat` (high average wait time, high utilization).
    *   **Network Bottleneck:** High network interface errors/drops reported by `ip -s link` or high latency observed via `ping`/`mtr`.

**L19 — Hard:**
*   **SELinux Enforcement:** SELinux (Security-Enhanced Linux) enforces Mandatory Access Control (MAC). Instead of relying solely on traditional Discretionary Access Control (DAC - user/group permissions), SELinux assigns **security contexts** (labels) to every subject (process) and object (file, port). Access is only granted if the policy explicitly permits the transition between the subject's context and the object's context.
*   **Modes:**
    *   **Enforcing:** SELinux actively denies access attempts that violate policy and logs the denial.
    *   **Permissive:** SELinux logs all policy violations (acting like it's enforcing) but *never* denies access. This is used for auditing.
    *   **Disabled:** SELinux is completely inactive, relying only on standard DAC permissions.
*   **Troubleshooting Port Binding:** If a daemon fails to bind a non-standard port, check the audit logs (`/var/log/audit/audit.log`). If SELinux is blocking it, the logs will show a `denied` AVC (Access Vector Cache) message. The fix is usually to use `semanage port -a -t <service_type> -p <port_number>` to explicitly tell SELinux that the daemon is allowed to use that port.

**L20 — Hard:**
*   **Page Fault Handling:** A page fault occurs when a process attempts to access a virtual memory address whose corresponding physical memory page is not currently loaded into RAM. The kernel intercepts this fault via a hardware trap.
*   **Minor vs. Major Page Fault:**
    *   **Minor Page Fault:** The required page is not in RAM, but it *is* present on disk (e.g., in the swap file or the original executable file). The kernel only needs to update the page table entry to map the virtual address to the correct physical frame, which is fast.
    *   **Major Page Fault:** The required page is not in RAM and is not easily accessible (e.g., it needs to be read from a slow, remote storage device or is part of a complex memory mapping). The kernel must perform a slow I/O operation to load the page into RAM before the process can continue.
*   **THP Impact:** Transparent Huge Pages (THP) attempts to use large memory pages (e.g., 2MB instead of 4KB) to reduce TLB misses and improve performance for large memory workloads. However, it can cause performance degradation (latency spikes) during memory allocation or heavy write activity because the kernel must perform complex background compaction and merging of small pages into huge pages.
*   **When to Disable:** Disable THP when applications exhibit highly sensitive, low-latency behavior or when memory fragmentation/compaction overhead is observed to negatively impact performance.
