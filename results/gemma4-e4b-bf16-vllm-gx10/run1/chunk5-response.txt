## .NET / C# Answers

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
A class is a reference type, meaning instances are stored on the heap, and variables hold a reference (pointer) to that memory. Structs are value types, meaning instances are stored directly on the stack (or inline within containing types), and variables hold the actual data. You should use a struct when the type is small, immutable, and represents a single value (e.g., a point, a color, or a coordinate).

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
`IEnumerable<T>` represents a sequence that can be iterated over in memory. When used with LINQ to Entities, the entire query is translated and executed on the client side (in memory) after fetching all data. `IQueryable<T>` represents an expression tree that describes the query structure. When used with LINQ to Entities, the provider (like Entity Framework Core) translates this expression tree into the appropriate database query (e.g., SQL) and executes it on the server, which is far more efficient.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
`async/await` allows asynchronous code to be written in a synchronous-looking manner. The `await` keyword pauses the execution of the current method until the awaited `Task` completes, yielding control back to the caller (or the SynchronizationContext). The method returns a `Task` (or `Task<T>`).
A `Task` represents an asynchronous operation that might involve heap allocation. A `ValueTask<T>` is a struct that can represent either a completed result directly (avoiding heap allocation) or a reference to a `Task<T>` if the operation is truly asynchronous. You should use `ValueTask<T>` when the operation is frequently synchronous or completes quickly, as it can reduce allocation overhead.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
Dependency Injection (DI) is a design pattern where components receive their dependencies from an external source (the DI Container) rather than creating them internally.
*   **Transient:** A new instance is created every single time it is requested.
*   **Scoped:** A single instance is created per scope (typically per HTTP request in ASP.NET Core).
*   **Singleton:** A single instance is created for the entire lifetime of the application.
The common bug is **Singleton capturing a Scoped service**. If a Singleton service holds a reference to a Scoped service, that Scoped service instance will be created once when the Singleton is first resolved and will persist for the entire application lifetime, violating the intended per-request scope.

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
`string` is an immutable, managed type in .NET. Operations on strings often involve creating new string objects, which incurs memory allocation overhead. `ReadOnlySpan<char>` (and `Span<T>`) is a stack-allocated, lightweight structure that provides a safe, high-performance view over a contiguous block of memory (like a string's underlying character array) without copying the data. You use `Span<T>` when you need to perform high-performance, low-allocation string manipulation, parsing, or slicing on existing character data.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
The GC automatically manages memory by tracking object reachability. It operates in generations:
*   **Gen 0:** New, short-lived objects are allocated here. Collections are frequent and fast.
*   **Gen 1:** Objects that survive a Gen 0 collection are promoted here.
*   **Gen 2:** Long-lived objects are promoted here. Collections are less frequent but more expensive.
The **Large Object Heap (LOH)** stores objects larger than a certain threshold (typically 85KB). LOH collections are less frequent and can lead to fragmentation.
You need `IDisposable` for **unmanaged resources** (like file handles, network sockets, or database connections). The GC only manages *managed* memory; it does not know how to clean up external resources, so `IDisposable` allows deterministic cleanup via the `using` statement.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
By default, when an `await` is encountered, the continuation (the code after `await`) attempts to resume on the original `SynchronizationContext` (e.g., the UI thread in WPF/WinForms, or the ASP.NET request context).
`ConfigureAwait(false)` tells the runtime that the continuation does *not* need to resume on the original context. It allows the continuation to run on any available thread pool thread.
**Use it when:** You are writing library code or infrastructure code where you don't care about the context (e.g., in a service layer) to avoid potential deadlocks or performance bottlenecks caused by context switching.
**Do NOT use it when:** You are writing UI code or code that specifically relies on being marshaled back to the original context (e.g., updating a UI element).

*   **Primary Constructors:** Allow parameters to be defined directly in the class signature, which can then be used as constructor parameters, simplifying boilerplate code.

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
**Diagnosis:** The likely cause is that the `DbContext` is being reused across multiple concurrent requests or operations within the same scope, or worse, being shared across different scopes. When high concurrency hits, one request might finish and dispose of the context, while another request (still running) tries to use the now-disposed context, leading to `ObjectDisposedException`.
**Fix:** Ensure the `DbContext` is registered with a **Scoped** lifetime in the DI container. This guarantees that a new, isolated instance of the context is provided for the duration of a single HTTP request.
**Interaction:** EF Core's `DbContext` is designed to be **short-lived** and **request-scoped**. Injecting it into a Singleton service is a common anti-pattern that breaks this contract.

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
*   **Class:** A reference type, mutable by default, designed for identity (two instances are different objects even if they have the same data).
*   **Record:** A reference type designed for value equality. It automatically provides `Equals()`, `GetHashCode()`, and often `ToString()` based on its properties.
*   **Record Struct:** A value type that benefits from record semantics (value equality).
**Choice:** Use `record` when the object's state defines its identity (e.g., a DTO or a configuration object). Use `class` when identity matters (e.g., a database entity representing a unique row). Use `record struct` for small, immutable value types that need value equality checks.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
*   **`ref`:** The variable must be initialized before being passed to the method. The method can read and write to it. Used when you want to modify an existing variable.
*   **`out`:** The variable does *not* need to be initialized before being passed. The method *must* assign a value to it before returning. Used when the method is responsible for providing a result back to the caller.
*   **`in`:** The variable must be initialized, but the method can only read from it (read-only reference). Used for passing large structs efficiently without copying them, ensuring the method cannot modify the original data.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
Nullable Reference Types (NRTs) are a compile-time safety feature. When enabled (`#nullable enable`), the compiler tracks whether a reference type variable is allowed to be `null` (e.g., `string?`). If you try to use a non-nullable reference type that might be null, the compiler issues a warning.
**Difference from Nullable Value Types (`int?`):** Value types (like `int`, `DateTime`) cannot inherently be null. `int?` is a wrapper type (`Nullable<int>`) that explicitly allows the value to be `null`. NRTs deal with the *reference* itself being null.

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
LINQ (Language Integrated Query) is a set of features in C# that allows developers to write queries against various data sources (collections, databases, XML) using a unified syntax.
*   **Method Syntax:** Uses extension methods (e.g., `list.Where(x => x.Age > 18)`).
*   **Query Syntax:** Uses SQL-like syntax (e.g., `from x in list where x.Age > 18`).
**Deferred Execution:** When you write a LINQ query (especially against `IEnumerable<T>`), the query is not executed immediately. Instead, it builds an expression tree. The query only runs when the results are actually iterated over (e.g., in a `foreach` loop or by calling `.ToList()`).

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
Generic constraints restrict the types that can be used as type arguments for a generic type or method.
*   `where T : class`: T must be a reference type.
*   `where T : struct`: T must be a value type.
*   `where T : new()`: T must have a public parameterless constructor.
*   `where T : IComparable<T>`: T must implement the `IComparable<T>` interface, allowing for comparison operations.
You combine constraints when the generic type needs to satisfy multiple requirements simultaneously (e.g., needing a type that is both a reference type *and* can be compared).

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
*   **Abstract Class:** Can contain concrete implementation (fields, methods, properties) and abstract members. A class can inherit from only one abstract class (single inheritance). It defines "is-a" relationships and shared base implementation.
*   **Interface:** Defines a contract—a set of members that implementing classes *must* adhere to. A class can implement multiple interfaces.
**Change with Default Interface Methods (C# 8+):** Default interface methods allow interfaces to provide a default implementation for some members. This blurs the line because interfaces can now provide behavior, not just contracts. However, the core distinction remains: abstract classes can hold state (fields), while interfaces primarily define behavior.

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
The middleware pipeline is a series of software components that process HTTP requests sequentially. Each middleware component can inspect, modify, or terminate the request/response cycle.
*   **`app.Use()`:** Adds standard middleware (e.g., Authentication, Routing, CORS). It processes the request and typically calls `next()` to pass control down the pipeline.
*   **`app.Map()`:** Used to map specific endpoints or sub-pipelines to a subset of the application, often used for routing specific paths.
*   **`app.Run()`:** Terminates the pipeline at this point, usually used for a simple endpoint that handles the request entirely without calling `next()`.
**Ordering Matters:** Middleware executes in the order it is added. For example, Authentication must run *before* Authorization, and Routing must run *before* endpoint execution.
**Exception Handling:** Exception handling middleware (e.g., `app.UseExceptionHandler()`) must be placed **early** in the pipeline so that it can catch exceptions thrown by subsequent middleware or endpoint handlers.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
`Channel<T>` is a modern, asynchronous stream abstraction designed for producer-consumer scenarios. It is highly optimized for async/await patterns.
**Comparison to `BlockingCollection<T>`:** `BlockingCollection<T>` is synchronous and thread-blocking. `Channel<T>` is asynchronous and non-blocking, making it ideal for modern async applications.
**Backpressure Example (Bounded Channel):** A bounded channel limits the number of items that can be buffered. If the producer tries to write to a full bounded channel, the `WriteAsync()` call will asynchronously wait until a consumer reads an item, thus applying backpressure to the producer.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
**Source Generators** allow developers to write C# code that generates other C# source code *during* compilation.
*   **Difference from Reflection:** Reflection inspects code *at runtime*. Source Generators operate *at compile time*, generating code before runtime, leading to zero runtime overhead.
*   **Difference from IL Weaving:** IL Weaving modifies the Intermediate Language (IL) of compiled assemblies *after* compilation. Source Generators generate standard C# source files that the compiler then compiles normally.
**Incremental Generator:** An incremental generator only regenerates the code that is affected by changes in its input code, rather than recompiling everything. This drastically speeds up build times, making it superior to a standard `ISourceGenerator` which might re-run unnecessarily.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
TPL Dataflow provides powerful constructs for building data processing pipelines using asynchronous blocks.
*   **`BufferBlock<T>`:** Acts as a queue, buffering incoming messages until a consumer is ready.
*   **`TransformBlock<TInput, TOutput>`:** Receives an input, applies a transformation function, and outputs the result.
*   **`ActionBlock<TInput>`:** Receives an input and executes an action (a side effect) without producing an output.
**Comparison to Channels:** Channels are fundamentally a stream abstraction (a queue/pipe). TPL Dataflow blocks are more sophisticated processing units that encapsulate logic (transformation, action) *and* queuing. Dataflow is better for complex, multi-stage processing pipelines where each stage performs a specific, defined operation.

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**
Minimal APIs allow developers to define HTTP endpoints directly in the `Program.cs` file using lambda expressions, bypassing the need for controller classes and routing attributes.
**Differences/Trade-offs:**
*   **Controller-based:** More structured, better separation of concerns, easier for large teams, mature tooling.
*   **Minimal APIs:** Less boilerplate, faster to prototype, simpler for small services.
*   **Testability:** Controllers are easier to mock/test in isolation. Minimal APIs require more setup to test the entire pipeline.
*   **Middleware:** Both support middleware, but in Minimal APIs, the pipeline setup is more explicit in `Program.cs`.
*   **OpenAPI:** Requires explicit configuration (e.g., using Swashbuckle) to generate documentation, whereas controllers often integrate more naturally with existing conventions.
**Route Groups & Endpoint Filters:** Route groups allow applying common middleware or constraints to a set of related endpoints. Endpoint filters allow you to inject logic (like authorization checks or logging) that runs before or after the endpoint handler executes, regardless of the specific endpoint definition.

## Python Answers

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**
*   **List vs. Tuple:** Lists (`[]`) are **mutable** (can be changed after creation: append, insert, delete). Tuples (`()`) are **immutable** (cannot be changed).
*   **Set vs. Frozenset:** Sets (`{}`) are **mutable** collections of unique, hashable items. Frozensets are **immutable** versions of sets; they can be used as elements within other sets or as dictionary keys because they are hashable.

**P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?**
The GIL is a mutex that protects access to Python objects, preventing multiple native threads from executing Python bytecodes simultaneously within a single process.
**Workloads Affected:** CPU-bound tasks (heavy computation) are severely limited because only one thread can execute Python code at any given moment, negating the benefits of multi-threading for pure Python logic.
**Workarounds:**
1.  **Multiprocessing:** Using separate processes bypasses the GIL entirely, as each process has its own Python interpreter and memory space. Best for CPU-bound tasks.
2.  **Asyncio:** Using cooperative multitasking (async/await) for I/O-bound tasks. While still single-threaded, it efficiently switches context during waiting periods (like network requests) without blocking the GIL.

**P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.**
*   **Shallow Copy (`.copy()` or `copy.copy()`):** Creates a new container object, but populates it with *references* to the objects found in the original. If the original object contains mutable objects (like lists), modifying those nested objects in the copy will also modify them in the original.
*   **Deep Copy (`copy.deepcopy()`):** Recursively creates new copies of all objects found in the original structure, ensuring the copy is entirely independent of the original.
**Example:**
```python
original = {'a': [1, 2]}
shallow = original.copy()
shallow['a'].append(3) # Modifies the list referenced by original['a']
print(original) # Output: {'a': [1, 2, 3]} -> Unexpected behavior
```

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**
A decorator is syntactic sugar that allows you to wrap a function or method, modifying its behavior without permanently altering its source code. It takes a function as input and returns a new, enhanced function.
**Time Logging Decorator:**
```python
import time
from functools import wraps

def timing_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"Function '{func.__name__}' executed in {end_time - start_time:.4f} seconds.")
        return result
    return wrapper

@timing_decorator
def slow_function(n):
    sum([i*i for i in range(n)])

slow_function(100000)
```

**P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?**
A generator is a special type of iterator that allows you to declare a function that behaves like an iterator, using the `yield` keyword.
**Difference from Returning a List:** When a function returns a list, it computes *all* values immediately and stores them in memory. A generator computes values *lazily*—it yields one value at a time only when requested by the loop, saving significant memory for large sequences.
**`yield from`:** This delegates iteration to a sub-generator or iterable. It allows a generator to delegate iteration to another iterable, effectively chaining generators together seamlessly.

**P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?**
The **Event Loop** is the core mechanism of `asyncio`. It manages and schedules coroutines (async functions). It runs in a single thread, monitoring I/O operations and switching execution between tasks whenever one awaits an I/O operation, allowing concurrency without true parallelism.
*   **`asyncio.run(coro)`:** Runs the top-level coroutine and manages the event loop lifecycle (starts, runs, and closes the loop).
*   **`asyncio.gather(*coros)`:** Runs multiple awaitables concurrently and waits for all of them to complete, returning a list of their results.
*   **`asyncio.create_task(coro)`:** Schedules a coroutine to run concurrently on the event loop immediately, returning a `Task` object that can be awaited later.
**Why `time.sleep()` fails:** `time.sleep()` is a *blocking* call. If called inside an `async` function, it halts the entire thread, freezing the event loop and preventing *all* other scheduled tasks from running until the sleep is over. You must use `await asyncio.sleep(delay)` instead, which yields control back to the event loop.

**P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**
MRO is the order in which Python searches the base classes to find a method or attribute. Python 3 uses the **C3 Linearization Algorithm** to ensure a consistent, predictable, and monotonic inheritance order, even in complex hierarchies.
**Diamond Inheritance:** In the provided example, `D` inherits from `B` and `C`, both of which inherit from `A`. C3 ensures that the base class (`A`) is visited only once, and the order respects the inheritance path.
**Output Explanation:** The MRO for `D` is `D -> B -> C -> A -> object`. When `D().who()` is called, Python checks `D` (no `who`), then `B` (no `who`), then `C` (has `who`), so it executes `C`'s implementation, returning `"C"`.

**P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.**
A **Metaclass** is the "class of a class." It controls *how* a class itself is created.
*   **Metaclass Use Case:** Enforcing structural rules across an entire hierarchy. Example: Automatically registering every subclass of a base class into a global registry upon definition.
*   **`__init_subclass__` Use Case:** A simpler hook available since Python 3.6 that runs *after* a subclass has been created but *before* it is fully initialized. It is generally preferred for simpler modifications. Example: Automatically adding a default logging method to every subclass of a base service.
**When to choose:** Use `__init_subclass__` for simple, post-creation modifications. Use a Metaclass when you need to intercept and fundamentally alter the class creation process itself (e.g., modifying attributes or methods before the class object even exists).

**P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?**
*   **Threading:** Best for **I/O-bound** tasks. Threads share memory within one process, making communication fast, but the GIL limits true parallel execution for CPU tasks.
*   **Multiprocessing:** Best for **CPU-bound** tasks. It spawns entirely separate OS processes, bypassing the GIL and achieving true parallelism across CPU cores.
*   **`concurrent.futures`:** A high-level interface that abstracts away the complexity of managing threads or processes. You use `ThreadPoolExecutor` for I/O-bound work and `ProcessPoolExecutor` for CPU-bound work.
**Serialization (Pickling):** Multiprocessing requires that data passed between processes (arguments, return values) be serialized into a byte stream using `pickle`. This process can be slow and fails if the objects are not picklable (e.g., database connections, open file handles).

**P10 — Medium: What is __slots__? When should you use it, and what does it prevent? What is the memory impact?**
`__slots__` is a class attribute that explicitly declares the attributes an instance of a class will have.
**What it prevents:** It prevents the creation of the instance dictionary (`__dict__`) for each object.
**When to use it:** When you are creating a very large number of instances of a class (e.g., millions of data points) where memory efficiency is critical.
**Memory Impact:** It significantly reduces memory consumption because Python no longer needs to store the dynamic attribute dictionary for every object instance.

**P11 — Easy: What is a virtual environment, and why should you use one? What is the difference between venv, virtualenv, and conda?**

**Differences:**

*   **`virtualenv`:** An older, more feature-rich third-party tool that predates `venv` and offers more customization.

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?**
These are concise, readable ways to create collections based on existing iterables.

*   **Dict Comp:** `{key_expr: value_expr for item in iterable if condition}`
*   **Set Comp:** `{expression for item in iterable if condition}`

**P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?**
*   **`==`:** Checks for **equality of value**. It calls the object's `__eq__()` method.
*   **`is`:** Checks for **identity**. It checks if two variables point to the exact same object in memory (i.e., if `id(a) == id(b)`).
**Object Interning:** Python pre-allocates and reuses certain immutable objects (like small integers, short strings) in memory to save space.
**Small Integers:** For small integers (typically -5 to 256), Python interns them. Therefore, if you create `a = 100` and `b = 100`, they might point to the same pre-existing object, causing `a is b` to be `True`.

**P14 — Easy: Explain Python's *args and **kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?**
*   **`*args`:** Collects any number of positional arguments into a tuple.
*   **`**kwargs`:** Collects any number of keyword arguments into a dictionary.
*   **Positional-Only (`/`):** Arguments listed before `/` *must* be passed by position and cannot be passed using a keyword.
*   **Keyword-Only (`*`):** Arguments listed after `*` *must* be passed using their keyword name; positional arguments are not allowed for them.
**Example:** `def func(a, b, /, c, *, d):` requires `a` and `b` positionally, `c` positionally or by keyword, and `d` *only* by keyword.

**P15 — Easy: What are context managers (with statement)? How do you write one using __enter__/__exit__ vs @contextmanager? Give an example beyond file handling.**
A context manager ensures that setup and teardown actions are performed reliably, even if errors occur. The `with` statement handles this automatically.
*   **`__enter__` / `__exit__`:** The traditional way. `__enter__` runs upon entering the `with` block and returns the resource. `__exit__` runs upon exiting (even if an exception occurs) and handles cleanup.
*   **`@contextmanager`:** A simpler decorator from the `contextlib` module. It uses `yield`. The code before `yield` is the setup (`__enter__`), and the code after `yield` is the teardown (`__exit__`).
**Example (Locking):** Using a context manager to acquire and release a threading lock:
```python
import threading
lock = threading.Lock()
with lock: # Setup: lock.acquire()
    # Critical section code
    pass # Teardown: lock.release()
```

**P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How does mypy or pyright use these for static analysis?**
Type hinting (PEP 484) allows developers to optionally annotate variables, function parameters, and return values with expected types. This does *not* enforce types at runtime but enables static analysis tools.
*   **`Union[A, B]`:** The value can be type A OR type B.
*   **`Optional[T]`:** A shorthand for `Union[T, None]`.
*   **`Literal[value]`:** Restricts a variable to only accept a specific, fixed value (e.g., `Literal["red", "green"]`).
*   **`TypeVar`:** A placeholder for a type variable, used to write generic functions/classes that work with multiple types while maintaining type safety.
*   **`Protocol`:** Defines a structural type. A class conforms to a Protocol if it implements the required methods/attributes, regardless of explicit inheritance.
**Static Analysis:** Tools like Mypy or Pyright read these hints *before* runtime. They check if the code adheres to the declared types, flagging potential type errors (e.g., trying to call a string method on an object hinted as an integer).

**P17 — Medium: Explain Python's data model (dunder methods). What are __repr__ vs __str__, __eq__ vs __hash__, and __getattr__ vs __getattribute__? What happens if you define __eq__ but not __hash__?**
Dunder methods (double underscore methods) are special methods that define how Python objects interact with built-in operations.
*   **`__str__` vs `__repr__`:** `__str__` is the "informal" string representation (what `print()` uses). `__repr__` is the "official" string representation, ideally one that could be used to recreate the object (`eval(repr(obj))`).
*   **`__eq__` vs `__hash__`:** `__eq__` defines value equality (`a == b`). `__hash__` defines how the object is mapped to an integer for use in hash-based collections (sets, dict keys).
*   **`__getattr__` vs `__getattribute__`:** `__getattribute__` is called for *every* attribute access. `__getattr__` is only called if the attribute is *not* found normally.
**Consequence of missing `__hash__`:** If you define `__eq__` (meaning two objects can be considered equal) but do not define `__hash__`, Python will raise a `TypeError` if you try to put those objects into a set or use them as a dictionary key, because it cannot reliably hash equal objects.

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (__get__, __set__, __delete__). How do property, classmethod, and staticmethod use descriptors under the hood?**
A descriptor is an object attribute that defines how attribute access (getting, setting, deleting) behaves. It implements one or more of the descriptor protocol methods: `__get__`, `__set__`, and `__delete__`.
**How built-ins use them:**
*   **`property`:** Uses descriptors to allow attribute access syntax (`obj.attr`) while executing methods behind the scenes (getters/setters).
*   **`classmethod`:** The class method descriptor ensures that when called, the first argument passed is the class itself (`cls`), not the instance.
*   **`staticmethod`:** The static method descriptor ensures that when called, the method is bound to the class but receives no implicit first argument (`self` or `cls`).

**P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, __init__.py, and namespace packages work? What is a finder and a loader?**
The import system searches for modules by looking through directories listed in `sys.path`.
*   **`sys.path`:** A list of directories Python searches when an `import` statement is encountered.
*   **`PYTHONPATH`:** An environment variable that adds directories to `sys.path` before the script runs.
*   **`__init__.py`:** Historically, this file marked a directory as a Python package, allowing imports from it. (Less critical in modern Python 3.3+ for namespace packages).
*   **Namespace Packages:** Packages that do not require an `__init__.py` file and allow multiple, independent packages to contribute to the same top-level namespace.
**Finder and Loader:** When an import is requested, Python uses **Finders** (e.g., `PathFinder`) to locate the module file on disk. Once found, a **Loader** (e.g., `SourceFileLoader`) is responsible for reading the file content and executing the code to create the module object.

**P20 — Hard: What are dataclasses and how does it compare to attrs and Pydantic? Explain __post_init__, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**
**Dataclasses:** A decorator (`@dataclass`) that automatically generates boilerplate methods like `__init__`, `__repr__`, `__eq__`, etc., based on type-hinted class attributes.
**Comparison:**
*   **`attrs`:** A mature library that predates dataclasses, offering similar functionality with more customization hooks.
*   **Pydantic:** A data validation library. It enforces *runtime* data validation against schemas (using type hints) and handles serialization/deserialization (JSON parsing) robustly.
**Features:**
*   **`__post_init__`:** A method called immediately after `__init__` finishes, useful for derived logic (e.g., calculating a total from sub-items).
*   **Field Factories:** Using `field(default_factory=list)` allows mutable defaults (like lists or dicts) to be initialized correctly for every instance, avoiding shared state issues.
*   **Frozen Dataclasses:** Setting `frozen=True` makes the instance immutable, similar to a tuple.
**When to choose Pydantic:** Choose Pydantic when you are dealing with **external, untrusted data** (like API payloads or configuration files) and you need guaranteed runtime validation, coercion, and serialization capabilities. Choose dataclasses when you are defining internal, trusted data structures where boilerplate reduction is the primary goal.
