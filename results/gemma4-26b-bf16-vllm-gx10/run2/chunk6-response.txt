## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted with an initial value of `undefined`. `let` and `const` are block-scoped and hoisted but remain in a "Temporal Dead Zone" (TDZ) until initialized. `const` prevents reassignment of the identifier. **Hoisting** is the engine's behavior of moving declarations to the top of their scope during the compile phase.

**JS2** — The **Event Loop** manages asynchronous execution. The **Call Stack** executes synchronous code. When an async operation completes, its callback enters a queue. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority and is emptied completely after every task. The **Macrotask Queue** (setTimeout, setInterval, I/O) is processed one task at a time after the microtask queue is empty.

**JS3** — A **closure** is a function that "remembers" its lexical scope even when executed outside that scope. *Example:* A function returning another function that increments a private counter. *Classic Bug:* Using `var` in a `for` loop with an async operation; all iterations share the same variable instance. *Fix:* Use `let` (which creates a new binding per iteration) or an IIFE.

**JS4** — **Promise** represents a future value. `async/await` is syntactic sugar for Promises. Error handling: `async/await` uses `try/catch`; Promises use `.catch()`. `Promise.all` rejects immediately if *any* promise fails. `Promise.allSettled` waits for all promises to either fulfill or reject and returns an array of descriptors.

**JS5** — **Interface** is primarily for defining object shapes and supports "declaration merging" (adding properties via multiple definitions). **Type** is more flexible, allowing unions, primitives, and tuples. Use `interface` for public APIs/objects; use `type` for complex logic/unions. **Discriminated Unions** use a common literal property (e.g., `type: 'circle' | 'square'`) to allow TypeScript to narrow types in a conditional block.

**JS6** — **Prototypal inheritance** means objects inherit properties from a prototype object via the prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. **ES6 Classes** are "syntactic sugar" over prototypes; they don't introduce a new inheritance model but provide a cleaner syntax for constructor functions and prototype methods.

**JS7** — `this` refers to the execution context. **Binding Rules:** 1. `new` (Constructor), 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (Object method call), 4. Default (Global/Undefined in strict mode). `bind()` returns a **new function** with a fixed `this`. You cannot re-bind a function once it has been bound via `bind()`.

**JS8** — `WeakRef` allows holding a reference to an object without preventing its garbage collection (GC). `FinalizationRegistry` allows running a callback after an object is GC'd. Use them for caches or metadata to avoid memory leaks. **WeakMap** keys must be objects because primitives cannot be tracked for GC in the same way, and the "weakness" relies on the ability to let the key be collected when no other references exist.

**JS9** — V8 uses **Hidden Classes** (shapes) to track object properties efficiently. **Inline Caching** optimizes property access by remembering the offset of a property from previous lookups. **Deoptimization** occurs when the engine's assumptions are broken (e.g., changing an object's shape by adding properties in a different order). Patterns causing deoptimization: changing object shapes frequently or passing different types to the same function (polymorphism).

**JS10** — **Tree-shaking** is dead-code elimination. It works with **ES Modules** because `import/export` are static (analyzable at compile time). **CommonJS** (`require`) is dynamic; modules can be loaded conditionally at runtime, making it impossible for tools to safely determine what is unused without running the code.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion (e.g., `null == undefined` is `true`); `===` checks both value and type. **Nullish coalescing (`??`)** returns the right side only if the left is `null` or `undefined`. **Optional chaining (`?.`)** short-circuits and returns `undefined` if the reference is nullish.

**JS12** — `map()` creates a new array by transforming every element. `filter()` creates a new array with elements that pass a test. `reduce()` accumulates array values into a single result. If an **initial value** is provided, `reduce` starts there; otherwise, it uses the first element and starts at index 1. `flatMap()` maps each element and then flattens the result by one level; useful for handling nested arrays returned by a map.

**JS13** — **Template literals** use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** allow a function to parse the template literal. *Example:* `` sql`SELECT * FROM users WHERE id = ${id}` `` where the `sql` function escapes the `id` to prevent injection.

**JS14** — **Destructuring** extracts values from arrays/objects into variables. *Object:* `const {a, b} = obj;`. *Array:* `const [x, y] = arr;`. *Default:* `const {a = 1} = obj;`. *Renaming:* `const {a: newName} = obj;`. The **rest operator** (`...`) collects remaining elements into a new array/object.

**JS15** — `for...in` iterates over **enumerable property keys** (strings). `for...of` iterates over **iterable values**. Avoid `for...in` on arrays because it iterates over indices as strings and may include inherited properties from the prototype chain.

**JS16** — **Generics** allow functions/classes to work with multiple types. **Constraints** (`T extends U`) limit the type to those possessing certain properties. **Conditional Types** (`T extends U ? X : Y`) act like ternary operators for types. **Infer** allows extracting a type from within another type. *Example:* `type GetReturn<T> = T extends (...args: any[]) => infer R ? R : any;`.

**JS17** — **CommonJS** is the Node.js default (synchronous, `require`). **ES Modules** is the web/modern standard (asynchronous, `import`). Node.js handles both, but ESM is preferred. `"type": "module"` in `package.json` tells Node to treat `.js` files as ES Modules rather than CommonJS.

**JS18** — TS is **structural** (if it looks like a duck, it's a duck). **Excess property checks** occur only during direct object literals; they don't apply when assigning an object to a variable first. `extends` is for subtyping; `satisfies` checks if an expression matches a type without changing the inferred type. **Variance** (`in`/`out`) defines how subtyping of complex types (like functions) relates to subtyping of their components.

**JS19** — **Proxy** wraps an object to intercept operations; **Reflect** provides methods to perform those same operations (often used inside Proxy traps). *Example:* A Proxy trap for `set` can validate that a value is a number before allowing the assignment.

**JS20** — `SharedArrayBuffer` allows multiple Web Workers to point to the same raw memory. **Atomics** provides static methods to perform thread-safe operations (like `add` or `load`) to prevent race conditions. `Atomics.wait` puts a thread to sleep until `Atomics.notify` is called on the same index, enabling efficient synchronization.

## Bash

**B1** — `$@` and `$*` both represent all arguments. `"$@"` preserves arguments as distinct quoted strings (best practice). `"$*"` merges all arguments into a single string separated by the first character of `IFS`.

**B2** — `-e`: Exit immediately if a command fails. `-u`: Treat unset variables as an error. `-o pipefail`: The return value of a pipeline is the status of the last command to exit with a non-zero status.

**B3** — `$(command)` is command substitution (modern, handles nesting). `` `command` `` is the legacy version. `$((expression))` is for arithmetic evaluation. `expr` is an external program for math (slower, more complex syntax).

**B4** — **Process substitution** `<(command)` creates a temporary file descriptor that acts like a file. Use it to compare output of two commands: `diff <(ls dir1) <(ls dir2)`.

**B5** — Use `while read -r f; do ... done < <(find . -print0 | xargs -0)` or `for f in */; do`. `for f in $(ls)` is dangerous because it splits filenames containing spaces into multiple items.

**B6** — **Here doc** (`<<EOF`) passes multi-line input to a command. **Here string** (`<<<`) passes a single string. `<<-EOF` strips leading **tabs** (not spaces) from the input, allowing for indented code blocks.

**B7** — `cmd > file 2>&1`: Redirects stdout to file, then redirects stderr to where stdout is currently pointing (the file). `cmd 2>&1 > file`: Redirects stderr to stdout (the terminal), then redirects stdout to a file. `cmd &> file`: Shorthand for redirecting both to a file.

**B8** — Use `mkdir lockdir` because `mkdir` is an atomic operation at the OS level; if two processes try to `mkdir` the same name, only one succeeds.
```bash
lockdir="mylock"
trap 'rmdir "$lockdir" 2>/dev/null' EXIT INT TERM
if mkdir "$lockdir"; then
  # critical section
  rmdir "$lockdir"
else
  echo "Locked" && exit 1
fi
```

**B9** — `'...'` (Single): Literal string, no expansion. `"..."` (Double): Allows variable expansion and command substitution. `no quotes`: Word splitting and globbing occur. *Example:* `echo "$VAR"` vs `echo '$VAR'` vs `echo $VAR` (if $VAR contains spaces).

**B10** — `[ -f file ]` (file), `[ -d dir ]` (dir), `[ -r file ]` (readable). `[[ ]]` is a Bash keyword that is more powerful, supports regex (`=~`), and doesn't require quoting variables to prevent word splitting.

**B11** — `$?`: Exit status of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: Number of arguments.

**B12** — `foo() { ... }` is the standard POSIX way. `function foo { ... }` is a Bashism. Functions don't "return" values like other languages; they return an exit code (0-255). To "return" data, use `echo` and capture it with `$(foo)`.

**B13** — `PATH` is a colon-separated list of directories. Bash searches these directories in order for an executable. **Builtin** (e.g., `cd`) is inside the shell; **External** (e.g., `ls`) is a file on disk. Use `type <cmd>` to check.

**B14** — `trap` catches signals. `trap 'cleanup' EXIT ERR INT TERM`. If multiple signals arrive, they are handled sequentially. `EXIT` is always the last thing to run.

**B15** — `xargs` converts stdin to arguments for a command. `find -print0 | xargs -0` handles spaces/newlines by using the null character as a delimiter. `xargs -P <N>` runs up to N processes in parallel.

**B16** — **Arrays**: `arr=(a b c)`. Append: `arr+=(d)`. Length: `${#arr[@]}`. Iterate: `for i in "${arr[@]}"`. **Associative Arrays**: `declare -A map`. `map[key]=val`. Length: `${#map[@]}`.

**B17** — `(...)` (Subshell) creates a child process; variables changed inside do not affect the parent. `{ ...; }` (Group) runs commands in the current shell; variables persist. Piping into `while` (`cat file | while...`) creates a subshell, so variable changes inside the loop are lost to the parent.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (Polite kill), `SIGHUP` (Terminal closed), `SIGKILL` (Immediate kill, cannot be caught). For graceful shutdown, use `trap` to catch `SIGTERM` and send signals to background PIDs.

**B19** — Use `split -l` to chunk the log, `xargs -P` to run a function on chunks, and redirect output to temp files. Merge with `cat`. *Trade-off:* Parallelism increases speed but increases I/O contention and makes error tracking harder (use `set -e` in the worker function).

**B20** — `exec` replaces the current shell process with the new command. `exec 3>file` opens file descriptor 3 for writing. `exec 3>&-` closes it. A **coprocess** (`coproc`) runs a command in the background and provides pipes for bidirectional communication.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline (can be captured). `Write-Host` writes directly to the host (screen) and cannot be captured in a pipeline.

**PS2** — The **pipeline** passes objects, not text. `ForEach-Object` is a cmdlet used *inside* a pipeline (efficient for streaming). `foreach` is a language keyword (faster for small/medium collections already in memory).

**PS3** — `[PSCustomObject]` is an ordered collection of properties (best for output). `[hashtable]` is an unordered key-value pair (best for lookups). Convert: `[PSCustomObject]$hash` or `[hashtable]$obj.PSObject.Properties`.

**PS4** — **Terminating** errors stop execution; **Non-terminating** errors continue. `try/catch` only catches terminating errors. Use `-ErrorAction Stop` to turn non-terminating errors into terminating ones. `$ErrorActionPreference = 'Stop'` sets this globally.

**PS5** — **Splatting** passes a hashtable as arguments to a command: `$p = @{Name='X'; Age=1}; Get-User @p`. It is cleaner than long command lines and differs from passing a single hashtable parameter because it "unpacks" the keys into individual parameters.

**PS6** — `Invoke-Command -ComputerName` runs a command on remote machines (one-to-many). `Enter-PSSession` starts an interactive session (one-to-one). Uses **WS-Man** (WinRM) or **SSH**.

**PS7** — In the example, `$result` is an array, but `$result += "one"` can sometimes cause PowerShell to unwrap the array into a single object if not careful. If 0 items are returned, `$x` becomes `$null`. The correct pattern is to initialize `$result = @()` and ensure the function returns the array explicitly.

**PS8** — A `[scriptblock]` is a piece of code; a function is a named, reusable block. Pass via `-ArgumentList`. The **double-hop** problem occurs when a remote session tries to use your credentials to access a *third* machine. Solve with **CredSSP** or **Kerberos Delegation**.

**PS9** — `@()` is an empty array literal; `[array]` is the type. Force single result: `@($result)`. Indexing `$null` returns `$null`; indexing an empty array returns `$null`.

**PS10** — `-eq` (equals), `-like` (wildcard), `-match` (regex), `-contains` (checks if collection contains value), `-in` (checks if value is in collection). `-ceq` is case-sensitive.

**PS11** — **Module**: collection of functions/variables. `.psm1` (Script module), `.psd1` (Manifest/metadata), **Binary** (DLL). `Import-Module` loads it into the session.

**PS12** — `"..."` allows interpolation; `'...'` is literal. Use `$()` for expressions: `"Value is $($obj.Prop)"`. **Here-string**: `@'...'@` (literal) or `@"..."@` (interpolated).

**PS13** — `Get-Member` shows type info. **Properties** (data), **Methods** (actions), **NoteProperties** (added via `Add-Member`). `Select-Object` picks properties; `Where-Object` filters objects.

**PS14** — **Classes** are more rigid/performable than functions. They support inheritance and type safety but lack some of the "loose" flexibility of PowerShell functions. Use classes for complex data structures; functions for tasks.

**PS15** — `[CmdletBinding()]` makes a function behave like a professional cmdlet (adds `-Verbose`, `-ErrorAction`, etc.). `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` blocks allow efficient pipeline processing (Begin once, Process per item, End once).

**PS16** — **Providers** allow PS to treat different data stores as drives. `Get-ChildItem Registry::HKEY_LOCAL_MACHINE\Software` works just like a file system.

**PS17** — A **Runspace** is a single thread of execution. `ForEach-Object -Parallel` (v7+) is a high-level wrapper that manages a **RunspacePool** for you, making parallel execution easy without manual thread management.

**PS18** — **PSScriptAnalyzer** is a static code analysis tool. It uses **Rules** to check for best practices. Severity can be Warning/Error. Suppress via `# PSScriptAnalyzer Ignore: RuleName`. It integrates into CI/CD via `Invoke-ScriptAnalyzer`.

**PS19** — `$using:var` is required to access local variables inside a remote/parallel block. `$args` is for positional arguments. **Serialization** (CLIXML) can lose complex object methods/types when passing objects across boundaries; only the data properties survive.

**PS20** — **DSC** ensures a system reaches a specific state. **Configuration** is the script, **Resource** is the provider (e.g., File, Registry), and **LCM** is the engine on the target machine. In modern infra, DSC is largely replaced by **Terraform** or **Ansible**.
