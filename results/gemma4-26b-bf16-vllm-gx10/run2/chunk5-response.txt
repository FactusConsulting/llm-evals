## .NET / C#

**DN1** — `class` is a reference type (stored on the heap); `struct` is a value type (usually stored on the stack). Use a `struct` for small, immutable data structures (typically < 16 bytes) that have a short lifetime to reduce GC pressure.

**DN2** — `IEnumerable<T>` is for in-memory collections; it uses client-side evaluation. `IQueryable<T>` is for out-of-memory providers (like EF Core); it uses expression trees to translate queries into SQL. Using `IEnumerable` for DB queries pulls the entire table into memory before filtering, causing massive performance hits.

**DN3** — `async/await` allows non-blocking execution by yielding control to the caller during I/O. A `Task` represents an ongoing operation; a `ValueTask` is a value-type wrapper for a `Task`. Use `ValueTask` when the result is often available synchronously (e.g., reading from a buffer) to avoid heap allocation of a `Task` object.

**DN4** — DI manages object creation and lifetimes. **Transient**: new instance every time. **Scoped**: one instance per request/scope. **Singleton**: one instance for the app lifetime. **Bug**: Injecting a Scoped service into a Singleton creates a "Captive Dependency," where the Scoped service lives as long as the Singleton, potentially causing stale data or concurrency issues.

**DN5** — `string` is immutable; every modification creates a new object. `ReadOnlySpan<char>` is a stack-only view into a contiguous memory region. Use `Span<T>` for high-performance slicing/parsing to avoid heap allocations and unnecessary string copying.

**DN6** — The GC manages memory automatically. **Gen 0**: newest, short-lived objects. **Gen 1**: buffer between 0 and 2. **Gen 2**: long-lived objects. **LOH**: Large Object Heap (>85k bytes), collected during Gen 2. `IDisposable` is needed to manually release unmanaged resources (file handles, DB connections) because the GC only manages managed memory.

**DN7** — `ConfigureAwait(false)` tells the runtime not to marshal the continuation back to the original `SynchronizationContext`. Use it in library code to improve performance and prevent deadlocks. Do **not** use it in UI applications (WPF/WinForms) or ASP.NET (Legacy) if you need to access UI elements or `HttpContext` after the `await`.

**DN8** — **Primary Constructors**: parameters defined on the class header. **Collection Expressions**: `int[] x = [1, 2, 3];`. **FrozenDictionary**: an immutable, highly optimized read-only dictionary.
```csharp
public class UserService(IDbContext db) // Primary Constructor
{
    public void DoWork() => db.Save();
}
```

**DN9** — **Cause**: `DbContext` is not thread-safe. High concurrency is likely causing multiple threads to share a single `DbContext` instance. **Fix**: Ensure `DbContext` is registered as `Scoped` (default) and that you are not manually sharing it across threads or using `Task.WhenAll` on tasks that share the same scoped context.

**DN10** — `record` is a reference type with value-based equality. `class` uses reference equality. `record struct` is a value type with value-based equality. Use `record` for DTOs/Data models; use `class` for complex logic/state; use `record struct` for small, high-performance value types.

**DN11** — `ref`: pass by reference (read/write). `out`: pass by reference, must be assigned inside the method. `in`: pass by reference, read-only (prevents copying large structs).

**DN12** — Nullable reference types (`string?`) are a compile-time static analysis feature to prevent `NullReferenceException`. They do not change the underlying type. Nullable value types (`int?`) are syntactic sugar for `Nullable<int>`, which wraps the value in a struct that tracks `HasValue`.

**DN13** — LINQ is Language Integrated Query. **Method syntax** uses extension methods (`.Where()`); **Query syntax** uses SQL-like keywords (`from x in...`). **Deferred execution** means the query is not executed when defined, but when the data is actually iterated (e.g., via `foreach` or `.ToList()`).

**DN14** — Constraints restrict generic types. `T : class` (reference type), `T : struct` (value type), `T : new()` (must have parameterless constructor), `T : IComparable<T>` (must implement interface). Combine them to ensure a type is both a class and implements an interface: `where T : class, IDisposable`.

**DN15** — `abstract class` can have state (fields) and implementation; `interface` defines a contract. **Default Interface Methods** allow interfaces to provide a default implementation, reducing breaking changes when adding methods to interfaces, blurring the line but not replacing the need for abstract classes (which can hold state).

**DN16** — Middleware is a pipeline of components. `app.Use()`: adds middleware that can call the next. `app.Map()`: branches the pipeline based on path. `app.Run()`: terminal middleware (no next). **Ordering matters**: Exception handling must be first to catch errors in subsequent steps.

**DN17** — `Channel<T>` is a high-performance, async-native producer-consumer queue. `BlockingCollection<T>` is synchronous/blocking. **Backpressure**: Use `Channel.CreateBounded<T>(capacity)`; when the channel is full, the producer's `WriteAsync` will asynchronously wait until space is available.

**DN18** — **Source Generators** produce code at compile-time. Unlike **Reflection** (runtime inspection) or **IL Weaving** (post-compile bytecode manipulation), they are part of the compilation process and are "AOT-friendly." **Incremental Generators** are preferred because they only re-run when specific inputs change, significantly improving IDE and build performance.

**DN19** — **TPL Dataflow** is a library for building actor-based pipelines. `ActionBlock` (consumer), `TransformBlock` (processor), `BufferBlock` (queue). Compared to `Channels`, Dataflow is higher-level and handles complex routing/linking, whereas `Channels` is lower-level and optimized for raw throughput.

**DN20** — **Minimal APIs** use lambda expressions for routing instead of Controllers. **Trade-offs**: Minimal APIs are faster and have less overhead but can become messy without strict organization. Controllers offer better structure for large teams. **Route groups** allow shared prefixes/middleware; **Endpoint filters** allow logic to run before/after the handler.

## Python

**P1** — `list` is mutable; `tuple` is immutable. `set` is mutable; `frozenset` is immutable.

**P2** — The GIL is a mutex that allows only one thread to execute Python bytecode at a time. It affects **CPU-bound** workloads (preventing true parallelism). **Workarounds**: Use `multiprocessing` (separate processes) or use C-extensions (like NumPy) that release the GIL.

**P3** — `copy` creates a new object but inserts references to the objects found in the original. `deepcopy` creates a new object and recursively copies all objects found in the original. **Example**: If `a = [[1]]`, `b = a.copy()`, then `b[0][0] = 2` changes `a[0][0]` because the inner list is shared.

**P4** — Decorators wrap a function to modify behavior.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"Time: {time.time() - start}")
        return result
    return wrapper
```

**P5** — Generators use `yield` to return values one at a time, maintaining state. Unlike a `list`, they are lazy and memory-efficient. `yield from` is used to delegate to a sub-generator (flattening).

**P6** — The event loop manages async tasks. `asyncio.run()`: entry point; `asyncio.gather()`: runs multiple coroutines concurrently; `asyncio.create_task()`: schedules a coroutine to run in the background. `time.sleep()` is blocking and stops the entire event loop; use `await asyncio.sleep()` instead.

**P7** — Python uses **C3 Linearization**. In diamond inheritance, it ensures a child is checked before its parents and parents are checked in order. In the example, `D` inherits from `B` then `C`. Since `B` inherits from `A`, and `C` inherits from `A`, the MRO is `D -> B -> C -> A`. `D().who()` calls `B.who()`, which is not defined, so it looks at `C.who()`, returning `"C"`.

**P8** — A **metaclass** is a class of a class (defines how classes are created). `__init_subclass__` is a simpler hook for customizing class creation without a full metaclass. **Use case**: Use `__init_subclass__` for simple registration/validation; use a metaclass for complex logic like automatically injecting methods or enforcing strict API structures.

**P9** — `threading`: shared memory, good for I/O. `multiprocessing`: separate memory, good for CPU-bound. `concurrent.futures`: high-level abstraction for both. **Serialization**: `multiprocessing` requires objects to be "picklable" to be sent between processes.

**P10** — `__slots__` tells Python not to use a `__dict__` for instance attributes, instead allocating a fixed amount of space. It prevents adding arbitrary attributes and significantly reduces memory usage for millions of objects.

**P11** — A virtual environment isolates project dependencies. `venv` is built-in; `virtualenv` is a faster, older alternative; `conda` is a package/environment manager that handles non-Python dependencies (C libraries).

**P12** — Comprehensions are concise ways to create collections. They are generally faster and more readable than `map()`/`filter()`. Use comprehensions for most cases; use `map`/`filter` when you already have a pre-defined function.

**P13** — `==` checks for **equality** (value); `is` checks for **identity** (memory address). **Interning** is an optimization where Python reuses objects for small integers (-5 to 256) and certain strings, making `a is b` return `True`.

**P14** — `*args` collects extra positional arguments into a tuple; `**kwargs` collects extra keyword arguments into a dict. `/` forces arguments before it to be positional-only; `*` forces arguments after it to be keyword-only.

**P15** — Context managers handle setup/teardown.
```python
from contextlib import contextmanager
@contextmanager
def my_ctx():
    print("setup")
    yield
    print("teardown")
# Usage: with my_ctx(): ...
```
**Example**: A database transaction or a temporary directory.

**P16** — Type hinting provides static type information. `Union[int, str]` (either), `Optional[int]` (int or None), `Literal["a"]` (only "a"), `TypeVar` (generic), `Protocol` (structural typing/duck typing). `mypy` uses these to find bugs without running the code.

**P17** — `__repr__` is for developers (unambiguous); `__str__` is for users (readable). `__eq__` checks equality; `__hash__` allows an object to be used in a set/dict. If you define `__eq__` but not `__hash__`, the object becomes unhashable. `__getattr__` is called only if the attribute isn't found; `__getattribute__` is called every time.

**P18** — Descriptors implement the logic for attribute access. `property` is a built-in descriptor. `classmethod` and `staticmethod` are descriptors that change how the method receives the first argument (the class or nothing).

**P19** — **Absolute**: `import package.module`. **Relative**: `from . import module`. `sys.path` is the list of directories searched. `__init__.py` makes a directory a package. **Namespace packages** allow splitting a package across multiple directories. A **Finder** locates the module; a **Loader** loads the code.

**P20** — `dataclasses` is built-in and lightweight. `attrs` is more powerful/feature-rich. `Pydantic` is designed for data validation/parsing (crucial for APIs). **Dataclasses**: use `__post_init__` for logic after init, `field(default_factory=list)` for mutable defaults. **Choose Pydantic** when you need to enforce types at runtime (e.g., parsing JSON).
