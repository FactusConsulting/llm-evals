## Go

**G1** — An **array** has a fixed size defined at compile time; its size is part of its type. A **slice** is a descriptor (header) containing a pointer to an underlying array, a length, and a capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array (usually doubling in size), copies the old elements to the new array, and returns a new slice header pointing to the new memory.

**G2** — `var x int` declares a variable and initializes it to its **zero value** (0). `x := 0` is **short variable declaration**, which declares and initializes in one step. You **cannot** use `:=` outside of function bodies (at the package level).

**G3** — A **goroutine** is a lightweight execution unit managed by the Go runtime, not the OS. Unlike OS threads (which have large stacks, ~1-2MB), goroutines start with small, segmented/growable stacks (~2KB). The **GMP model** consists of **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts). The scheduler maps $G$s onto $M$s using $P$s to ensure efficient work-stealing and CPU utilization.

**G4** — **Channels** are pipes used for communication between goroutines. An **unbuffered channel** requires both sender and receiver to be ready simultaneously (synchronous). A **buffered channel** has a capacity; sends only block when the buffer is full. Sending to a **full buffered channel** blocks the sending goroutine until a receiver removes an item.

**G5** — `context` is used for cancellation signals, deadlines, and passing request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

**G6** — Go uses **implicit satisfaction**: a type satisfies an interface simply by implementing its methods; no `implements` keyword is needed. This is "structural typing" vs Java/C#'s "nominal typing." `interface{}` (or `any`) can hold any value because every type implements at least zero methods. It is **powerful** for generic data handling but **dangerous** because it bypasses type safety, requiring runtime type assertions that can panic.

**G7** — The code is unsafe due to a **data race**. The Go memory model does not guarantee that writes in one goroutine are visible to another without explicit synchronization. The compiler or CPU might reorder instructions or cache `ready` in a register, causing the loop to run forever or `data` to be read as empty. **Alternatives**: Use `sync.Mutex`, `sync/atomic`, or a channel to signal completion.

**G8** — `sync.Mutex` is an exclusive lock (one holder). `sync.RWMutex` allows multiple concurrent readers OR one exclusive writer. Use `sync.Map` for high-concurrency scenarios with **stable keys** (mostly reads/updates) or when multiple goroutines write to disjoint sets of keys. A `map + Mutex` is generally faster for most standard use cases due to lower overhead.

**G9** — **Go modules** manage dependencies. `go.mod` defines the module path and required dependencies. `go.sum` contains cryptographic hashes to ensure dependency integrity. `go mod tidy` adds missing modules and removes unused ones. **MVS (Minimum Version Selection)** selects the *lowest* version of a module that satisfies all constraints in the dependency graph, ensuring reproducible builds.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. **Gotcha**: Using `defer` inside a loop can cause resource exhaustion (e.g., file descriptors) because the deferred calls don't execute until the *outer* function returns, not the loop iteration.

**G11** — A **pointer** is a variable that stores the memory address of another value. The zero value is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs automatically when a package is initialized. It runs after variable declarations but before `main()`. A package can have **multiple** `init()` functions; they execute in the order they appear in the source code.

**G13** — `new(T)` allocates zeroed memory for a type `T` and returns a `*T` (pointer). `make(T, args)` is used only for **slices, maps, and channels**; it initializes the internal data structures and returns an initialized value of type `T` (not a pointer).

**G14** — Errors are values. The `error` interface has one method: `Error() string`. Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error matches a specific value (including wrapped errors), while `errors.As` checks if an error matches a specific type (including wrapped errors). `==` only checks identity/value and fails with wrapped errors.

**G15** — 
- **map**: `nil`
- **slice**: `nil`
- **channel**: `nil`
- **struct**: All fields set to their respective zero values.

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one access is a write. The `-race` flag enables a runtime detector that intercepts memory accesses.
*Example*: `count++` in two goroutines. 
*Fix*: Wrap in `mu.Lock()/Unlock()` or use `atomic.AddInt64(&count, 1)`.

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch` (which evaluates expressions), `select` evaluates channel operations. If multiple cases are ready, one is chosen **pseudo-randomly**. To implement a timeout: `case <-time.After(time.Second):`.

**G18** — **Escape analysis** is a compiler phase that determines if a variable can reside on the **stack** (fast, automatic cleanup) or must "escape" to the **heap** (slower, GC managed). A variable escapes if its address is returned from a function or shared via a pointer to a long-lived object. Inspect via `go build -gcflags="-m"`. Minimizing heap allocations reduces GC pressure and improves performance.

**G19** — `reflect` allows inspecting types and values at runtime. `reflect.Type` describes the type (e.g., `int`, `struct`); `reflect.Value` holds the actual data. **Costs**: Significant CPU and memory overhead due to runtime checks and allocations. **Justification**: Use for generic libraries (JSON encoders, ORMs) where types aren't known at compile time; use **code generation** (e.g., `stringer`) for performance-critical logic.

**G20** — `//go:embed` allows including static files in the binary. It works for single files, directories, or multiple files. It integrates with `io/fs.FS`, allowing you to treat embedded content as a filesystem. **Limitations**: Files must be in the same module; cannot embed files in parent directories; files must be available at compile time.

## Rust

**R1** — **Ownership** manages memory without a GC. Rules: 1. Each value has a variable called its *owner*. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is an immutable string slice (a pointer and a length). Use `&str` in function signatures for maximum flexibility (it accepts both `&String` and `&str`). Use `String` when the function needs to own or modify the data.

**R3** — **Borrowing** allows accessing data without taking ownership. **Rules**: You can have either *any number of immutable references* (`&T`) OR *exactly one mutable reference* (`&mut T`) at any given time, and no references can exist while a mutable reference is active.

**R4** — `Result<T, E>` represents success (`Ok`) or failure (`Err`). `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>`: Single ownership, heap allocation. `Rc<T>`: Reference counted, multiple ownership (single-threaded). `Arc<T>`: Atomic reference counted, multiple ownership (thread-safe).

**R6** — **Traits** define shared behavior (similar to interfaces but more powerful). **Trait Object** (`dyn Trait`) uses dynamic dispatch (runtime lookup via vtable). **Generics with Trait Bounds** (`T: Trait`) use static dispatch (monomorphization at compile time), which is faster.

**R7** — It fails because the compiler cannot determine how long the returned reference lives relative to the inputs. **Fix**: Add lifetime annotations: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8** — `Send` means ownership can be transferred between threads. `Sync` means a type can be safely shared via references between threads. `Rc<T>` is not `Send`/`Sync` because its reference count is not updated atomically, leading to data races. `Arc<T>` uses atomic operations for the count, making it safe.

**R9** — Rust uses a **poll-based** async model. A `Future` is a state machine that does nothing until `poll()` is called. The **executor** (e.g., Tokio) manages the polling loop. Unlike Go's goroutines (which are preemptively scheduled by a runtime), Rust's futures are cooperative and require an executor to drive them to completion.

**R10** — `unsafe` allows bypassing certain compiler checks. You can: 1. Dereference raw pointers. 2. Call unsafe functions (e.g., C FFI). 3. Access/modify mutable static variables. It is justified when implementing low-level primitives (like `Vec`) or interfacing with hardware/C libraries.

**R11** — **Pattern matching** (`match`) is a control flow construct that compares a value against a series of patterns. `if let` is syntactic sugar for a `match` with a single pattern. The compiler enforces **exhaustiveness**: you must handle every possible variant of an enum.

**R12** — `Vec<T>` is a growable heap-allocated array. `[T; N]` is a fixed-size stack-allocated array. When a `Vec` exceeds capacity, it allocates a new, larger block of memory, moves the elements, and deallocates the old block.

**R13** — Rust enums are **sum types** (can hold data in variants). C enums are just integers. `Option<T>` is an enum with `Some(T)` and `None`. Rust has no `null` to prevent null-pointer exceptions; you must explicitly handle the `None` case.

**R14** — `impl` defines methods for a type. `&self` borrows immutably; `&mut self` borrows mutably; `self` consumes the object (takes ownership). **Associated functions** (like `new()`) do not take `self` and are called via the type (e.g., `Type::func()`).

**R15** — `derive` automatically implements traits. Examples: `Debug` (printing), `Clone` (deep copy), `PartialEq` (equality), `Serialize` (to format). You cannot derive a trait if its implementation requires custom logic or if the underlying types do not implement that trait.

**R16** — `Cow<'a, T>` is a "Clone on Write" smart pointer. It can hold either borrowed data or owned data. It is useful for functions that only need to modify data *if* a certain condition is met, avoiding an allocation if the data remains unchanged.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. The file system maps to modules (e.g., `mod foo` looks for `foo.rs` or `foo/mod.rs`). In Rust 2018, the requirement for `mod.rs` was relaxed, allowing modules to be defined in `foo.rs` directly.

**R18** — `Pin<T>` ensures that the data at a pointer address will not move in memory. This is critical for **self-referential structs** (common in `async` state machines) where a pointer inside the struct points to another field in the same struct. `Unpin` is an auto-trait indicating a type is safe to move even when pinned.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching on code tokens. **Procedural macros** act like functions that transform code (derive, attribute, or function-like). **Hygiene** ensures that macro-generated identifiers do not accidentally clash with variables in the scope where the macro is called.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use, and what you do use couldn't be implemented better by hand. **Iterators** are optimized into tight loops; **Generics** use monomorphization (generating specific code for each type) to enable inlining; **Static dispatch** resolves calls at compile time, eliminating the overhead of vtable lookups.
