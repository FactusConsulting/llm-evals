## Kubernetes

**K1** — **Deployment** manages stateless applications; pods are interchangeable and can be replaced by any other pod in the set. **StatefulSet** manages stateful applications; pods have unique, persistent identities (e.g., `web-0`, `web-1`), stable network identifiers, and dedicated persistent storage that persists across rescheduling.

**K2** — A ClusterIP service creates a virtual IP. When traffic hits this IP, `kube-proxy` (using iptables or IPVS) intercepts the packet and performs DNAT (Destination Network Address Translation) to redirect the traffic to one of the backend Pod IPs selected via a random or round-robin load-balancing algorithm.

**K3** — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a request for storage by a user/pod. **StorageClass** is a template that enables dynamic provisioning. **Relationship:** A user creates a PVC; if a matching PV exists, it binds; if not, the StorageClass automatically provisions a new PV to satisfy the PVC.

**K4** — 1. `kubectl logs <pod>` to check application error logs. 2. `kubectl describe pod <pod>` to check for exit codes (e.g., 137 for OOM) or liveness probe failures. 3. `kubectl exec` (if possible) to check environment variables/config. 4. Check node resources/events to see if the pod is being evicted or failing due to infrastructure issues.

**K5** — CoreDNS provides service discovery by resolving Kubernetes service names (e.g., `my-svc.my-ns.svc.cluster.local`) to ClusterIPs. If CoreDNS pods are down, internal service-to-service communication via DNS names will fail, though direct Pod IP communication will still work.

**K6** — The scheduler follows two phases: **Filtering** (Predicates) removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, port conflicts, node selectors). **Scoring** (Priorities) ranks remaining nodes. **Factors:** 1. Resource availability (least requested vs. most requested). 2. Pod Affinity/Anti-affinity. 3. Data locality (matching PVs).

**K7** — **Scheduling:** Yes. The scheduler looks at *requests*. Total requested = 3.5GB + 256Mi $\approx$ 3.75GB. Since 3.75GB < 4GB, it schedules. **Runtime:** If it hits 600Mi, it exceeds the 512Mi limit. The Linux kernel OOM killer will terminate the process within the container (OOMKilled).

**K8** — 1. External LB receives traffic and forwards to the Ingress Controller's NodePort/LoadBalancer IP. 2. Ingress Controller (NGINX) processes the HTTP host/path. 3. Ingress Controller looks up the **Service** via the API server. 4. It bypasses the Service IP and routes directly to the **Endpoints** (Pod IPs) list. 5. `kube-proxy` ensures the network path is open, but the controller sends traffic directly to the Pod IP.

**K9** — A **NetworkPolicy** defines rules for how pods are allowed to communicate. **Default:** All pods can talk to all other pods (allow-all). **Applying one:** Once a policy selects a pod, that pod enters "isolation" mode; it will reject all traffic that is not explicitly allowed by the policy.

**K10** — **RollingUpdate** replaces old pods with new ones gradually, ensuring zero downtime. **Recreate** kills all existing pods before starting new ones. **Choose Recreate** when the application does not support multiple versions running simultaneously (e.g., due to database schema locks or singleton requirements).

**K11** — A **Namespace** is a virtual cluster within a physical cluster used to partition resources. **Defaults:** `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

**K12** — Used for deep inspection of a pod's state. Unlike `get`, it shows: 1. **Events** (recent lifecycle changes/errors). 2. **Container Status** (exact exit codes/reason). 3. **Conditions** (PodScheduled, Ready, etc.).

**K13** — A **ConfigMap** stores non-confidential configuration data in key-value pairs. **Methods:** 1. As **Environment Variables** in the container spec. 2. As **Files in a Volume** mounted into the container.

**K14** — **ClusterIP:** Internal IP only, accessible within the cluster. **NodePort:** Exposes the service on a static port on every Node's IP. **LoadBalancer:** Provisions an external cloud load balancer that routes to the NodePort.

**K15** — A **DaemonSet** ensures that a copy of a specific Pod runs on *all* (or selected) nodes. Use it for background services like log collectors (Fluentd), monitoring agents (Prometheus Node Exporter), or networking plugins.

**K16** — **Taints** are applied to **Nodes** to repel pods (e.g., "don't run here unless you have a specific toleration"). **Tolerations** are applied to **Pods** to allow them to stay on tainted nodes. **Node Affinity** is applied to **Pods** to attract them to specific nodes. **Use Case:** Taint a node with a GPU to prevent standard web pods from using it; use Affinity to ensure a heavy ML pod specifically lands on that GPU node.

**K17** — An **Operator** is a custom controller that uses Custom Resource Definitions (CRDs) to manage complex, stateful applications. Unlike a standard controller (which manages generic objects like Pods), an Operator encodes "human operational knowledge" (e.g., how to perform a database backup or upgrade) into software.

**K18** — **Model:** Raft consensus (strong consistency). **Loss of Quorum:** The cluster becomes read-only or completely unavailable for writes to prevent split-brain. **Recovery:** If 2/3 nodes are lost, you must restore from a recent etcd snapshot onto a new 3-node cluster to re-establish quorum.

**K19** — **RBAC** uses roles to define permissions. **Role** is namespace-scoped; **ClusterRole** is cluster-wide. **RoleBinding** attaches a Role to a user/group in a namespace; **ClusterRoleBinding** attaches a ClusterRole cluster-wide.
**Manifest:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { name: pod-reader, namespace: dev-ns }
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { name: read-pods, namespace: dev-ns }
subjects: [{ kind: User, name: "developer", apiGroup: rbac.authorization.k8s.io }]
roleRef: { kind: Role, name: pod-reader, apiGroup: rbac.authorization.k8s.io }
```

**K20** — By default, `ndots:5` means if a DNS query doesn't contain at least 5 dots, the resolver appends the search domains (e.g., `google.com.svc.cluster.local`, then `google.com.cluster.local`, etc.) before trying the actual name. This causes multiple failed queries for every external request. **Fix:** Use `dnsConfig` in the Pod spec to set `ndots: 1`.

## Development

**D1** — **Merge** combines histories by creating a new "merge commit." **Rebase** rewrites history by moving your commits to the tip of the target branch. **Avoid Rebase** on public/shared branches, as it rewrites history and breaks other developers' local copies.

**D2** — **TCP** is connection-oriented, reliable, and guarantees order (e.g., HTTP, SSH). **UDP** is connectionless, faster, but unreliable/unordered (e.g., DNS, VoIP/Streaming).

**D3** — A **Race Condition** occurs when the timing or order of events affects the correctness of the code. **Example:** Two threads simultaneously executing `counter += 1`. Both read `counter = 10`, both increment to `11`, and both write `11` back, losing one increment.

**D4** — **Symmetric:** Same key for encryption and decryption (fast). **Asymmetric:** Public key encrypts, private key decrypts (secure key exchange). **TLS:** Uses Asymmetric encryption to securely exchange a "session key," then uses Symmetric encryption for the actual data transfer.

**D5** — A **Layer** is a read-only filesystem change (e.g., installing a package). **Caching:** Docker caches layers. Best practice is to put frequently changing instructions (like `COPY . .`) at the bottom and rarely changing ones (like `RUN apt-get install`) at the top to speed up builds.

**D6** — 1. **Check Application Logs** (errors/exceptions). 2. **Check Resource Usage** (CPU/RAM exhaustion/OOM). 3. **Check Downstream Dependencies** (is a DB or API slow/down?). 4. **Check Infrastructure/Network** (Load Balancer health checks or connection limits).

**D7** — **CAP:** Consistency, Availability, Partition Tolerance. You can only have two. **CP (Consistency/Partition):** MongoDB (prioritizes data accuracy; if a partition occurs, it stops accepting writes). **AP (Availability/Partition):** Cassandra (prioritizes uptime; nodes accept writes even if they can't sync immediately).

**D8** — **Horizontal:** Adding more instances (nodes/pods). **Vertical:** Adding more power (CPU/RAM) to existing instances. **Patterns:** Statelessness, Load Balancing, and Sharding/Partitioning.

**D9** — An **Environment Variable** is a dynamic value used by processes. To persist on Linux, add `export VAR_NAME=value` to your `~/.bashrc` or `~/.zshrc` file.

**D10** — **JSON** is data-interchange format (strict, uses braces/brackets). **YAML** is human-readable configuration (uses indentation). **Advantage JSON:** Faster for machines to parse. **Advantage YAML:** Much easier for humans to read/write.

**D11** — **REST API:** An architectural style for networked applications using HTTP. **GET:** Retrieve data. **POST:** Create data. **PUT:** Replace/Update data. **DELETE:** Remove data.

**D12** — **Version Pinning** is specifying exact versions of dependencies (e.g., `react@18.2.0`). It is vital for **reproducible builds**, ensuring that a build today results in the exact same binary as a build six months from now.

**D13** — **Compiled:** Translated to machine code before execution (e.g., C++, Go). **Interpreted:** Executed line-by-line by an interpreter (e.g., Python, JavaScript).

**D14** — **Reverse Proxy:** Sits in front of web servers and forwards client requests to them (e.g., NGINX for load balancing; HAProxy for high availability). **Forward Proxy:** Sits in front of clients and forwards requests to the internet (e.g., a corporate proxy to filter web traffic).

**D15** — A **Deadlock** is a state where a set of processes are blocked because each is holding a resource and waiting for another held by another process. **Coffman Conditions:** 1. Mutual Exclusion. 2. Hold and Wait. 3. No Preemption. 4. Circular Wait.

**D16** — **Eventual Consistency:** If no new updates are made, all reads will eventually return the last updated value. **Cassandra:** Uses "Tunable Consistency." You can specify `ANY`, `ONE`, `QUORUM`, or `ALL` for both reads and writes to balance latency vs. consistency.

**D17** — **mTLS:** Both client and server present certificates to prove identity. **Handshake:** 1. Client sends hello + cert. 2. Server sends hello + cert. 3. Both verify certificates against a trusted CA. 4. They derive a symmetric session key. **Usage:** Service Meshes (Istio/Linkerd) for Zero Trust networking.

**D18** — A **Hash Table** maps keys to indices via a hash function. **Collision Resolution:** 1. **Chaining:** Each index points to a linked list of entries. 2. **Open Addressing:** Finds the next empty slot (linear/quadratic probing). **Complexity:** Avg: $O(1)$ for all; Worst: $O(n)$ (when all keys hash to the same index).

**D19** — **Circuit Breaker:** Prevents a service from repeatedly trying an operation that is likely to fail. **States:** 1. **Closed:** Normal operation; requests pass. 2. **Open:** Failure threshold met; requests fail immediately. 3. **Half-Open:** Periodically allows trial requests to see if the service recovered. **Relation:** It works with **Retries/Exponential Backoff** to prevent "retry storms" from overwhelming a recovering service.

**D20** — **Optimistic:** Assumes conflicts are rare; checks for changes at commit time (e.g., using a `version` column). Best for high-read/low-write systems. **Pessimistic:** Assumes conflicts will happen; locks the record during the transaction (e.g., `SELECT FOR UPDATE`). Best for high-contention/high-value transactions (e.g., banking).
