## Kubernetes

**K1** — **Deployment** manages stateless applications; pods are interchangeable and can be replaced by any other pod in the set. **StatefulSet** manages stateful applications; pods have unique, persistent identities (e.g., `web-0`, `web-1`), stable network identifiers, and dedicated persistent storage that persists across rescheduling.

**K2** — A ClusterIP service creates a virtual IP. When traffic hits this IP, `kube-proxy` (using iptables or IPVS) intercepts the packet and performs DNAT (Destination Network Address Translation) to redirect the traffic to one of the pod IPs listed in the service's **Endpoints** object.

**K3** — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a request for storage by a user/pod. **StorageClass** is a template that allows for dynamic provisioning. **Relationship:** A user creates a PVC; if a matching PV exists, it binds; if not, the StorageClass automatically provisions a new PV to satisfy the PVC.

**K4** — 1. `kubectl logs <pod>` to check application error logs. 2. `kubectl describe pod <pod>` to check for exit codes (e.g., 137 for OOM) or liveness probe failures. 3. `kubectl exec` (if possible) to check environment variables/config. 4. Check node resources/events to see if the pod is being evicted or failing due to infrastructure issues.

**K5** — CoreDNS provides service discovery by resolving Kubernetes service names (e.g., `my-svc.my-ns.svc.cluster.local`) to ClusterIPs. If CoreDNS pods are down, internal service-to-service communication via DNS names will fail, though direct IP communication will still work.

**K6** — The scheduler follows two main phases: **Filtering** (Predicates) removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, port conflicts, node selectors). **Scoring** (Priorities) ranks remaining nodes. **Factors:** 1. Resource availability (least requested vs. most requested). 2. Pod affinity/anti-affinity. 3. Data locality (volume affinity).

**K7** — **Scheduling:** Yes. The scheduler looks at *requests*. 4GB - 3.5GB = 0.5GB (512Mi) available. The request is 256Mi, which fits. **Runtime:** If it hits 600Mi, it exceeds the 512Mi limit. The Linux kernel OOM killer will terminate the process within the container, resulting in an `OOMKilled` status.

**K8** — 1. External LB receives traffic and forwards to the Ingress Controller's NodePort/LoadBalancer IP. 2. Ingress Controller (NGINX) receives the request and matches the Host/Path against Ingress rules. 3. Controller looks up the **Endpoints** for the target Service. 4. Traffic is routed via the pod IP (bypassing the Service IP via the controller's internal logic) to the application pod. `kube-proxy` manages the underlying routing rules.

**K9** — A **NetworkPolicy** defines how groups of pods are allowed to communicate. **Default:** If no policy exists, all pods in the namespace can talk to all other pods (allow-all). **Applying one:** Once a policy selects a pod, that pod enters "isolation" mode; it will only accept traffic explicitly permitted by the policy.

**K10** — **RollingUpdate** replaces old pods with new ones gradually, ensuring zero downtime. **Recreate** kills all existing pods before starting new ones. **Choose Recreate** when the application does not support multiple versions running simultaneously (e.g., due to database schema locks or singleton requirements).

**K11** — A **Namespace** is a virtual cluster within a physical cluster used to partition resources. **Defaults:** `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

**K12** — Used for deep inspection of a pod's state. Unlike `get`, it shows: 1. **Events** (e.g., pulling image, failed probes). 2. **Container Status** (e.g., specific exit codes, restart counts). 3. **Detailed Resource Specs** (e.g., exact volume mounts, lifecycle hooks).

**K13** — A **ConfigMap** stores non-confidential configuration data in key-value pairs. **Methods:** 1. As **Environment Variables** within the container. 2. As **Files/Volumes** mounted into the container's filesystem.

**K14** — **ClusterIP:** Internal-only IP; accessible only within the cluster. **NodePort:** Exposes the service on a static port on every Node's IP. **LoadBalancer:** Provisions an external cloud load balancer that routes to the NodePort.

**K15** — A **DaemonSet** ensures that a copy of a specific pod runs on *all* (or selected) nodes. Use it for background services like log collectors (Fluentd), monitoring agents (Prometheus Node Exporter), or networking plugins.

**K16** — **Taints** are applied to **Nodes** to repel pods (e.g., "don't put anything here unless it's special"). **Tolerations** are applied to **Pods** to allow them to stay on tainted nodes. **Node Affinity** is applied to **Pods** to attract them to specific nodes. **Use Case:** Taint a node with a GPU to prevent web pods from using it; use Node Affinity to ensure a ML pod specifically targets that GPU node.

**K17** — An **Operator** is a custom controller that uses Custom Resource Definitions (CRDs) to manage complex, stateful applications. Unlike a standard controller (which manages generic objects like Pods), an Operator encodes **domain-specific operational knowledge** (e.g., how to perform a database backup or a version upgrade) into software.

**K18** — **Model:** Raft consensus algorithm (strong consistency). **Loss of Quorum:** The cluster becomes read-only or completely unavailable for writes to prevent split-brain. **Recovery:** If 2/3 nodes are lost, you must restore from a recent etcd snapshot onto a new 3-node cluster to re-establish quorum.

**K19** — **RBAC** controls access via roles. **Role:** Permissions within a namespace. **ClusterRole:** Permissions cluster-wide. **RoleBinding:** Grants Role permissions to a user in a namespace. **ClusterRoleBinding:** Grants ClusterRole permissions cluster-wide.
**Manifest:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { name: pod-reader, namespace: dev-ns }
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { name: read-pods, namespace: dev-ns }
subjects: [{ kind: User, name: "developer", apiGroup: rbac.authorization.k8s.io }]
roleRef: { kind: Role, name: pod-reader, apiGroup: rbac.authorization.k8s.io }
```

**K20** — By default, `ndots:5` means if a DNS query doesn't contain at least 5 dots, the resolver appends all search domains in `/etc/resolv.conf` before trying the name as-is. For `google.com`, it tries `google.com.dev-ns.svc.cluster.local`, then `google.com.svc.cluster.local`, etc., causing 4+ failed queries before the real one. **Fix:** Use `dnsConfig` in the Pod spec to set `ndots: 1`.

## Development

**D1** — **Merge** combines histories by creating a new "merge commit"; it preserves the chronological history. **Rebase** rewrites history by moving your commits to the tip of the target branch, creating a linear history. **Avoid rebase** on public/shared branches, as it rewrites history and breaks other developers' local copies.

**D2** — **TCP** is connection-oriented, reliable, and ensures ordered delivery (e.g., HTTP, SSH). **UDP** is connectionless, faster, but unreliable/unordered (e.g., DNS, VoIP/Streaming).

**D3** — A **race condition** occurs when the outcome of a program depends on the unpredictable timing of multiple threads/processes accessing shared data. **Example:** Two threads both read `counter = 10`, both increment it to `11` locally, and both write `11` back, when the result should have been `12`.

**D4** — **Symmetric:** Same key for encryption and decryption (fast). **Asymmetric:** Public key encrypts, private key decrypts (secure key exchange). **TLS:** Uses asymmetric encryption to securely exchange a symmetric session key, then uses symmetric encryption for the actual data transfer.

**D5** — A **layer** is a read-only filesystem change (e.g., installing a package). **Caching:** Docker caches layers. Best practice is to order instructions from "least frequently changed" to "most frequently changed" (e.g., `COPY package.json` before `COPY .`) to maximize cache hits and speed up builds.

**D6** — 1. **Check Application Logs:** Look for exceptions or timeouts. 2. **Check Resource Usage:** Is the service hitting CPU/RAM limits? 3. **Check Downstream Dependencies:** Is a database or external API slow/down? 4. **Check Infrastructure/Network:** Is the Load Balancer or ingress experiencing issues?

**D7** — **CAP:** Consistency, Availability, Partition Tolerance. You can only have two in a distributed system. **CP (Consistency/Partition):** MongoDB (prioritizes data accuracy; if a partition occurs, it stops accepting writes). **AP (Availability/Partition):** Cassandra (prioritizes uptime; nodes accept writes even if they can't talk to others, resolving conflicts later).

**D8** — **Horizontal:** Adding more instances (nodes/pods). **Vertical:** Adding more power (CPU/RAM) to existing instances. **Patterns:** Statelessness (allowing any instance to handle any request) and Load Balancing.

**D9** — An **environment variable** is a dynamic-named value that can affect the behavior of running processes. **Linux Persistence:** Add `export VAR_NAME=value` to your `~/.bashrc` or `~/.zshrc` file.

**D10** — **JSON** is a data format based on key-value pairs and arrays; **YAML** is a human-readable data serialization standard using indentation. **JSON Advantage:** Faster to parse by machines. **YAML Advantage:** Much easier for humans to read and write (supports comments).

**D11** — **REST API:** An architectural style for networked applications using HTTP. **GET:** Retrieve data. **POST:** Create data. **PUT:** Update/Replace data. **DELETE:** Remove data.

**D12** — **Version pinning** is specifying the exact version of a dependency (e.g., `lodash: 4.17.21`). It is vital for **reproducible builds**, ensuring that the code running in production is identical to the code tested in staging, preventing "it works on my machine" bugs caused by silent minor/patch updates.

**D13** — **Compiled:** Translated to machine code before execution (e.g., C++, Go). **Interpreted:** Executed line-by-line by an interpreter at runtime (e.g., Python, JavaScript).

**D14** — A **Reverse Proxy** sits in front of web servers and forwards client requests to them (protects servers). A **Forward Proxy** sits in front of clients and forwards requests to the internet (hides clients). **Reverse Proxies:** NGINX (load balancing), HAProxy (high-performance routing).

**D15** — A **deadlock** is a state where a set of processes are blocked because each is holding a resource and waiting for another resource held by another process. **Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual Consistency:** If no new updates are made, eventually all accesses will return the last updated value. **Cassandra:** Uses "Tunable Consistency." You can specify `ANY`, `ONE`, `QUORUM`, or `ALL` for both reads and writes. To achieve read-after-write, you ensure `R + W > N` (where N is the replication factor).

**D17** — **mTLS:** Both client and server present certificates to prove identity. **Handshake:** 1. Client connects, Server sends cert. 2. Client validates Server cert. 3. Client sends its own cert. 4. Server validates Client cert. 5. Both derive session keys. **Usage:** Service Meshes (Istio/Linkerd) for zero-trust internal networking.

**D18** — A **Hash Table** maps keys to indices via a hash function. **Collision Resolution:** 1. **Chaining:** Each index points to a linked list of entries. 2. **Open Addressing:** Finds the next empty slot (linear/quadratic probing). **Complexity:** Average: $O(1)$ for all. Worst: $O(n)$ (when all keys hash to the same index).

**D19** — **Circuit Breaker:** Prevents a service from repeatedly trying an operation that is likely to fail. **States:** 1. **Closed:** Normal operation; requests pass. 2. **Open:** Failure threshold met; requests fail immediately without calling the service. 3. **Half-Open:** After a timeout, allows a few "test" requests to see if the service recovered. **Relation:** It works with **retries** and **exponential backoff** to prevent "retry storms" from overwhelming a recovering service.

**D20** — **Optimistic:** Assumes conflicts are rare; checks for changes at commit time (e.g., using a `version` column). Best for high-read/low-write systems. **Pessimistic:** Assumes conflicts will happen; locks the record upon reading. Best for high-contention/high-value transactions (e.g., `SELECT FOR UPDATE` in SQL).
