## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted with an initial value of `undefined`. `let` and `const` are block-scoped and hoisted but remain in a "Temporal Dead Zone" (TDZ) until initialized. `const` prevents reassignment of the identifier. **Hoisting** is the engine's behavior of moving declarations to the top of their scope during the compile phase.

**JS2** — The **Event Loop** manages asynchronous execution. The **Call Stack** executes synchronous code. When an async operation completes, its callback enters a queue. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority and is emptied completely after the current task and before the next macrotask. The **Macrotask Queue** (setTimeout, setInterval, I/O) is processed one task at a time per loop iteration.

**JS3** — A **closure** is a function that retains access to its lexical scope even when executed outside that scope. *Example:* A function returning another function that increments a private counter. *Classic Bug:* Using `var` in a `for` loop with an async operation; all iterations share the same variable instance. *Fix:* Use `let` (which creates a new binding per iteration) or an IIFE.

**JS4** — **Promises** represent eventual completion/failure. `async/await` is syntactic sugar for Promises, making async code look synchronous. Error handling: `try/catch` with `async/await`; `.catch()` with Promises. `Promise.all` rejects immediately if *any* promise fails. `Promise.allSettled` waits for all to finish, regardless of outcome, returning an array of status objects.

**JS5** — **Interfaces** are primarily for defining object shapes and support "declaration merging" (adding properties via multiple definitions). **Types** are more flexible, allowing unions, primitives, and intersections. Use `interface` for public APIs/object structures; use `type` for complex logic, unions, or aliases. **Discriminated Unions** use a common literal property (e.g., `type: 'circle' | 'square'`) to allow TypeScript to narrow types in conditional blocks.

**JS6** — **Prototypal inheritance** means objects inherit properties from a prototype object via the prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. **ES6 Classes** are "syntactic sugar" over prototypes; they don't introduce a new inheritance model but provide a cleaner syntax for constructor functions and prototype methods.

**JS7** — `this` refers to the execution context. **Binding Rules:** 1. `new` (Constructor), 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (Object method call), 4. Default (Global/Undefined in strict mode). `bind()` returns a **new function** with a fixed `this`. You cannot re-bind a function once it has been bound via `bind()`.

**JS8** — `WeakRef` allows holding a reference to an object without preventing its garbage collection (GC). `FinalizationRegistry` triggers a callback when an object is GC'd. Use them for caches or metadata associated with objects. **WeakMap** keys must be objects because primitive keys cannot be tracked for GC in the same way, and the "weakness" relies on the object's lifecycle being managed by the GC.

**JS9** — V8 uses **Hidden Classes** (shapes) to track object properties efficiently. **Inline Caching** optimizes property access by remembering where properties were found previously. **Deoptimization** occurs when the engine's assumptions fail (e.g., a function receiving a different object shape than usual). *Patterns causing deoptimization:* Changing object shapes (adding/deleting properties), switching types in a monomorphic function, or using `delete`.

**JS10** — **Tree-shaking** is dead-code elimination. It works with **ES Modules** because `import/export` are static (analyzable at compile time). **CommonJS** (`require`) is dynamic; modules can be loaded conditionally at runtime, making it impossible for bundlers to safely determine what is unused without running the code.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `null == undefined` is `true` (loose equality), but `null === undefined` is `false` (strict equality). **Nullish coalescing (`??`)** returns the right side only if the left is `null` or `undefined`. **Optional chaining (`?.`)** short-circuits and returns `undefined` if the reference is nullish.

**JS12** — `map()` creates a new array by transforming every element. `filter()` creates a new array with elements that pass a test. `reduce()` accumulates array values into a single result. If an **initial value** is provided, `reduce` starts there; otherwise, it uses the first element and starts at index 1. `flatMap()` maps each element and then flattens the result by one level; useful for handling nested arrays returned by a map.

**JS13** — **Template literals** use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** allow a function to parse the template literal. *Example:* `sql``` SELECT * FROM users WHERE id = ${id} `` where the `sql` function escapes the `id` to prevent injection.

**JS14** — **Destructuring** extracts values from arrays/objects into variables. *Object:* `const {a, b} = obj;`. *Array:* `const [x, y] = arr;`. *Default:* `const {a = 1} = obj;`. *Renaming:* `const {a: newName} = obj;`. The **rest operator** (`...`) collects remaining elements into a new array or object.

**JS15** — `for...in` iterates over **enumerable property keys** (strings). `for...of` iterates over **iterable values**. Avoid `for...in` on arrays because it iterates over indices as strings and may include inherited properties from the prototype chain.

**JS16** — **Generics** allow components to work with multiple types. **Constraints** (`<T extends string>`) limit the types allowed. **Conditional Types** (`T extends U ? X : Y`) act like ternary operators for types. **Infer** allows extracting a type from within another type. *Example:* `type GetReturn<T> = T extends (...args: any[]) => infer R ? R : any;`.

**JS17** — **CommonJS** is the Node.js default (synchronous, `require`). **ES Modules** is the web/modern standard (asynchronous, `import`). Node.js handles both, but ESM is preferred. `"type": "module"` in `package.json` tells Node to treat `.js` files as ES Modules rather than CommonJS.

**JS18** — TS is **structural** (if it looks like a duck, it's a duck). **Excess property checks** occur only during direct object literals; they prevent passing extra properties that aren't in the type. `extends` is for subtyping; `satisfies` checks if an expression matches a type *without* changing the inferred type of the expression. **Variance** (`in`/`out`) defines how subtyping of complex types (like functions) relates to subtyping of their components.

**JS19** — **Proxy** wraps an object to intercept operations (get, set, etc.). **Reflect** provides methods to perform the original operations. *Example:* A Proxy with a `set` trap can validate that a property is a number before allowing the assignment via `Reflect.set(target, prop, value)`.

**JS20** — `SharedArrayBuffer` allows multiple threads (Web Workers) to share a raw memory buffer. **Atomics** provides static methods to perform thread-safe operations (add, load, store) to prevent race conditions. `Atomics.wait` pauses a thread until a value changes, and `Atomics.notify` wakes it up.

## Bash

**B1** — `$@` represents all arguments as separate words. `$*` represents all arguments as a single string. `"$@"` (quoted) preserves individual arguments even if they contain spaces; `"$*"` (quoted) joins all arguments into one string separated by the first character of `IFS`.

**B2** — `set -e` (exit immediately if a command fails), `-u` (exit if an uninitialized variable is used), `-o pipefail` (the return value of a pipeline is the status of the last command to exit with a non-zero status).

**B3** — `$(command)` is command substitution (modern, handles nesting well). `` `command` `` is the legacy version. `$((expression))` is for arithmetic expansion. `expr` is an external program for math (slower, more cumbersome).

**B4** — **Process substitution** `<(command)` treats the output of a command as a temporary file. *Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands without creating physical files.

**B5** — Use `while read -r line; do ... done < <(find . -print0) | while IFS= read -r -d '' file; do ... done`. `for f in $(ls)` is dangerous because it splits filenames on whitespace, breaking names like `"My File.txt"` into two iterations.

**B6** — `<<EOF` (here-doc) passes multi-line input to a command. `<<<` (here-string) passes a single string. `<<-EOF` strips leading **tabs** (not spaces) from the input, allowing for cleaner indentation in scripts.

**B7** — 
1. `cmd > file 2>&1`: Redirects stdout to `file`, then redirects stderr to where stdout is currently pointing (`file`). **Correct.**
2. `cmd 2>&1 > file`: Redirects stderr to stdout (the terminal), then redirects stdout to `file`. **Incorrect** (stderr still goes to terminal).
3. `cmd &> file`: Shorthand for redirecting both stdout and stderr to `file`.

**B8** — 
```bash
lockdir="/tmp/mylock"
mkdir "$lockdir" 2>/dev/null || exit 1
trap 'rmdir "$lockdir"; exit' INT TERM EXIT
```
`mkdir` is atomic at the OS level; if two processes try to `mkdir` the same path, only one succeeds. File creation (`> file`) is not inherently atomic for locking purposes.

**B9** — `'...'` (single) treats everything literally. `"..."` (double) allows variable expansion and command substitution. No quotes allow word splitting and globbing. *Example:* `echo '$USER'` prints `$USER`; `echo "$USER"` prints `john`; `echo $USER` (no quotes) works but is unsafe if the variable contains spaces.

**B10** — `[ -f file ]` (file exists/is regular), `[ -d dir ]` (is directory), `[ -r file ]` (is readable). `[[ ]]` is a Bash keyword that is more powerful, supports regex (`=~`), and doesn't require quoting variables to prevent word splitting.

**B11** — `$?` (exit status of last command), `$$` (PID of current script), `$!` (PID of last background job), `$#` (number of arguments).

**B12** — `foo() { ... }` is the standard POSIX way. `function foo { ... }` is a Bashism. Functions return an exit status (0-255) via `return`. To "return" data, use `echo` and capture it with `$(foo)`.

**B13** — `PATH` is a colon-separated list of directories. Bash searches these directories in order for an executable. A **builtin** (e.g., `cd`) is part of the shell; an **external** (e.g., `ls`) is a file in `PATH`. Use `type <cmd>` to check.

**B14** — `trap` catches signals. `trap 'cleanup' EXIT ERR INT TERM`. Execution order: If multiple signals arrive, they are handled sequentially. `EXIT` is always the last thing to run.

**B15** — `xargs` converts stdin to arguments for a command. `find -print0 | xargs -0` handles filenames with spaces/newlines by using the null character as a delimiter. `xargs -P <N>` runs up to N processes in parallel.

**B16** — **Arrays:** `arr=(a b c)`. Append: `arr+=("d")`. Iterate: `for i in "${arr[@]}"`. Length: `${#arr[@]}`. **Associative Arrays:** `declare -A map`. `map[key]="val"`. Iterate: `for k in "${!map[@]}"`.

**B17** — `(...)` (subshell) runs in a child process; variables changed inside do not affect the parent. `{ ...; }` (group command) runs in the current shell; variables persist. Piping into `while` (`cmd | while...`) creates a subshell, so variable changes inside the loop are lost when the loop ends.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (polite kill), `SIGHUP` (terminal closed), `SIGKILL` (immediate, cannot be caught). For graceful shutdown, use `trap` to catch `SIGTERM` and send signals to child PIDs stored in an array.

**B19** — Use `split -l` to chunk the log, `find` the chunks, `xargs -P` to run a function on each, and `cat` the results. *Trade-off:* Parallelism increases speed but consumes more CPU/IO. *Error propagation:* Use `set -e` or check exit codes of `xargs` to ensure the whole pipeline fails if one chunk fails.

**B20** — `exec` replaces the current shell process with the new command. `exec 3>file` opens file descriptor 3 for writing. `exec 3>&-` closes it. A **coprocess** (`coproc cmd`) runs a command in the background and provides pipes (`coproc_out`, `coproc_in`) for two-way communication.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline (can be captured). `Write-Host` writes directly to the host (console) and cannot be captured or redirected via the pipeline.

**PS2** — The **pipeline** passes objects from one command to the next. `ForEach-Object` is a cmdlet used *inside* a pipeline (efficient for streaming). `foreach` is a language keyword used to iterate over a collection already in memory (faster for large, pre-loaded arrays).

**PS3** — `[PSCustomObject]` is an ordered collection of properties (ideal for data/output). `[hashtable]` is an unordered collection of key-value pairs (ideal for lookups). Convert: `[PSCustomObject]@{a=1}` or `[hashtable]$obj`.

**PS4** — **Terminating errors** stop execution (e.g., `throw`). **Non-terminating errors** (e.g., `Get-Item` on a missing file) continue execution. `try/catch` only catches terminating errors unless you set `-ErrorAction Stop` on the cmdlet. `$ErrorActionPreference = 'Stop'` makes all errors terminating.

**PS5** — **Splatting** passes a hashtable as arguments to a command: `$p = @{Name="A"; Age=1}; Get-User @p`. This is cleaner than passing a single hashtable to a parameter named `$params`.

**PS6** — `Invoke-Command -ComputerName` runs a command on remote machines (one-to-many). `Enter-PSSession` starts an interactive session (one-to-one). It uses **WS-Man** (WinRM) or **SSH**.

**PS7** — In the example, `$result` is an `Object[]` (array) because of the `+=` operation. If 0 items are returned, it might be `$null`. The correct pattern is to initialize with `$result = [System.Collections.Generic.List[object]]::new()` and use `.Add()`, or simply let the pipeline handle the output.

**PS8** — A `[scriptblock]` is a piece of code `{ ... }`. To pass it remotely, use `Invoke-Command`. The **double-hop problem** occurs when you use credentials to connect to Server A, and then try to access Server B from Server A (the credentials aren't forwarded). Solve with **CredSSP** or **Kerberos Delegation**.

**PS9** — `@()` creates an array; `[array]` is a type accelerator. To force a single result into an array, use `@($result)`. Indexing into `$null` throws an error; indexing into an empty array returns `$null`.

**PS10** — `-eq` (equality), `-like` (wildcard), `-match` (regex), `-contains` (checks if collection contains value), `-in` (checks if value is in collection). `-ceq` etc. are case-sensitive. `-contains` is `collection -contains value`; `-in` is `value -in collection`.

**PS11** — A **Module** is a collection of functions/cmdlets. `.psm1` is a script module. `.psd1` is a manifest (metadata). **Binary modules** are compiled DLLs. `Import-Module` loads them into the session.

**PS12** — `"..."` allows interpolation: `"Hello $name"`. `'...'` is literal. Use `$()` for expressions: `"Size: $($obj.Size)"`. **Here-strings** use `@"` ... `"@` for multi-line blocks.

**PS13** — `Get-Member` shows the type, properties, and methods of an object. `Select-Object` picks specific properties; `Where-Object` filters objects based on criteria.

**PS14** — **Classes** are more rigid and similar to C#. They support inheritance and methods. **Functions** are more "PowerShell-native" and easier for simple tasks. Classes are better for complex state management; functions are better for pipeline-driven tasks.

**PS15** — `[CmdletBinding()]` makes a function behave like a professional cmdlet (adds `-Verbose`, `-ErrorAction`, etc.). `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` blocks allow fine-grained control over pipeline input processing.

**PS16** — **Providers** allow PowerShell to treat different data stores as drives. `Get-ChildItem Registry::HKEY_LOCAL_MACHINE` works just like `Get-ChildItem C:\`.

**PS17** — A **Runspace** is a single thread of execution. A **RunspacePool** manages multiple runspaces. `ForEach-Object -Parallel` (v7+) is a high-level wrapper that manages a runspace pool for you automatically.

**PS18** — **PSScriptAnalyzer** is a static code analysis tool. It uses **rules** to check for best practices. You can suppress rules with `# PSScriptAnalyzer Ignore`. It integrates into CI/CD via `Invoke-ScriptAnalyzer`.

**PS19** — `$using:var` is used to bring a local variable into a remote/parallel scope. `$args` is for positional arguments. **Serialization limits** occur when objects are converted to XML (CLIXML) to move between sessions; complex objects (like active database connections) lose their methods and "flatten" into data.

**PS20** — **DSC** ensures a system reaches a specific state. **Configurations** are the desired state; **Resources** are the logic to get there; **LCM** is the engine on the node. In modern infra, DSC is often replaced by **Terraform** or **Ansible** for orchestration, though DSC is still used for low-level Windows configuration.
