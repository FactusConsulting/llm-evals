## Go

**G1** — An **array** has a fixed size defined at compile time; its size is part of its type. A **slice** is a descriptor (header) containing a pointer to an underlying array, a length, and a capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array (usually doubling in size), copies the old elements to the new array, and returns a new slice header pointing to the new memory.

**G2** — `var x int` declares a variable and initializes it to its **zero value** (0). `x := 0` is **short variable declaration**, which declares and initializes in one step. You **cannot** use `:=` outside of function bodies (at the package level).

**G3** — A **goroutine** is a lightweight execution unit managed by the Go runtime, not the OS. Unlike OS threads (which have large stacks, ~1-2MB), goroutines start with small, segmented/growable stacks (~2KB). The **GMP model** consists of **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts). The scheduler maps $G$s onto $M$s using $P$s to ensure efficient work-stealing and CPU utilization.

**G4** — **Channels** are pipes used for communication between goroutines. An **unbuffered channel** requires both sender and receiver to be ready simultaneously (synchronous). A **buffered channel** has a capacity; sends only block when the buffer is full. Sending to a **full buffered channel** blocks the sending goroutine until a receiver removes an item.

**G5** — `context` is used for cancellation signals, deadlines, and passing request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

**G6** — Go uses **implicit satisfaction**: a type satisfies an interface simply by implementing its methods; no `implements` keyword is needed. This is "structural typing" vs Java/C#'s "nominal typing." `interface{}` (or `any`) can hold any value because every type implements at least zero methods. It is **powerful** for generic data handling but **dangerous** because it bypasses type safety, requiring runtime type assertions that can panic.

**G7** — This is unsafe due to **memory visibility** issues. Without synchronization, the compiler or CPU may reorder instructions or cache `ready` in a register, meaning the loop might never see the update. The correct alternatives are using `sync.Mutex`, `sync/atomic` (e.g., `atomic.Bool`), or a **channel** to establish a "happens-before" relationship.

**G8** — `sync.Mutex` is an exclusive lock (one holder). `sync.RWMutex` allows multiple concurrent readers OR one exclusive writer. Use `sync.Map` for high-concurrency scenarios with **disjoint keys** or **frequent reads/infrequent writes** (it uses atomic operations to reduce lock contention). A regular map + `Mutex` is faster for most general-purpose use cases with high write contention or small datasets.

**G9** — **Go modules** manage dependencies. `go.mod` defines the module path and specific dependency versions. `go.sum` contains cryptographic hashes to ensure dependency integrity. `go mod tidy` adds missing modules and removes unused ones. **MVS (Minimum Version Selection)** selects the *lowest* version of a module that satisfies all constraints in the dependency graph, ensuring reproducible builds.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common **gotcha** is using `defer` inside a loop; the deferred calls don't execute until the *outer* function returns, which can lead to resource exhaustion (e.g., leaking file descriptors).

**G11** — A **pointer** stores the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `p := &User{Name: "Alice"}`.

**G12** — `init()` runs automatically when a package is initialized. It runs after variable declarations but before `main()`. A package can have **multiple** `init()` functions, and they execute in the order they appear in the source code.

**G13** — `new(T)` allocates zeroed memory for a type `T` and returns a `*T` (pointer). `make(T, args)` is used only for **slices, maps, and channels**; it initializes the internal data structures and returns an initialized value of type `T` (not a pointer).

**G14** — Errors are values. The `error` interface requires an `Error() string` method. The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error matches a specific **value** (useful for wrapped errors), while `errors.As` checks if an error matches a specific **type** (and performs a cast).

**G15** — 
- **map**: `nil` (reading is okay, writing panics).
- **slice**: `nil` (length 0, capacity 0).
- **channel**: `nil` (sending/receiving blocks forever).
- **struct**: All fields set to their respective zero values.

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one access is a write. The `-race` flag enables a runtime detector that intercepts memory accesses.
*Example Fix:*
```go
// Bad: count++ 
// Good:
mu.Lock()
count++
mu.Unlock()
```

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch` (which evaluates expressions), `select` evaluates channel operations. If multiple cases are ready, one is chosen **pseudo-randomly**. A timeout is implemented using `time.After(d)`:
```go
select {
case res := <-ch: // handle res
case <-time.After(time.Second): // timeout
}
```

**G18** — **Escape analysis** is a compiler phase that determines if a variable can reside on the **stack** (fast, automatic cleanup) or must "escape" to the **heap** (slower, requires GC). A variable escapes if its address is returned from a function or if it's too large. Use `go build -gcflags="-m"` to inspect. Minimizing heap allocations reduces GC pressure and improves performance.

**G19** — `reflect.Type` describes the type (e.g., `int`, `struct`), while `reflect.Value` holds the actual data. Reflection is expensive because it bypasses compile-time optimizations and involves runtime type checking. Use it for generic libraries (JSON encoders) but prefer **code generation** (e.g., `stringer`) for performance-critical logic.

**G20** — `//go:embed` allows including static files in the binary. It works with `//go:embed file.txt` (single file), `//go:embed dir/*` (directory), or `//go:embed all:dir` (including hidden files). It returns an `embed.FS`, which implements the `io/fs.FS` interface, making it compatible with standard filesystem functions. Limitations include the files must be in the same module and cannot be outside the module root.

## Rust

**R1** — **Ownership** manages memory without a GC. Rules: 1. Each value has a variable called its *owner*. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is an immutable string slice (a pointer and a length). Use `&str` in function signatures for maximum flexibility (it accepts both `&String` and `&str`). Use `String` when the function needs to own or modify the data.

**R3** — **Borrowing** allows accessing data without taking ownership. Rules: You can have **either** one mutable reference (`&mut T`) **or** any number of immutable references (`&T`) at any given time, but not both simultaneously. This prevents data races at compile time.

**R4** — `Result<T, E>` represents success (`Ok`) or failure (`Err`). `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

**R5** — `Box<T>`: Single ownership, heap allocation. `Rc<T>`: Reference counted, multiple ownership (single-threaded). `Arc<T>`: Atomic reference counted, multiple ownership (thread-safe).

**R6** — **Traits** define shared behavior (similar to interfaces but more powerful). **Trait objects** (`dyn Trait`) use dynamic dispatch (runtime lookup via vtable). **Generics with trait bounds** (`T: Trait`) use static dispatch (monomorphization at compile time), which is faster.

**R7** — It fails because the compiler cannot guarantee how long the returned reference lives relative to the inputs. Fix with **lifetime annotations**:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** — `Send` means ownership can be transferred between threads. `Sync` means a type can be safely shared via references between threads. `Rc<T>` is not `Send`/`Sync` because its reference count is not updated atomically, leading to races. `Arc<T>` uses atomic operations, making it safe for concurrent use.

**R9** — Rust's async is **poll-based**. A `Future` is a state machine that does nothing until `poll()` is called. An **executor** (like Tokio) manages these futures, polling them when they are ready. Unlike Go's goroutines (which are preemptively scheduled by a runtime), Rust futures are **cooperative** and lazy; they only progress when polled.

**R10** — `unsafe` allows bypassing certain compiler checks. You can: 1. Dereference raw pointers. 2. Call unsafe functions. 3. Access/modify mutable static variables. It is justified when interfacing with C code (FFI) or implementing low-level primitives where the compiler cannot prove safety.

**R11** — **Pattern matching** (`match`) allows branching based on the structure of data. `if let` is syntactic sugar for a `match` with a single arm. The compiler enforces **exhaustiveness**, ensuring every possible pattern is handled.

**R12** — `Vec<T>` is a growable heap-allocated array. `[T; N]` is a fixed-size stack-allocated array. When a `Vec` exceeds capacity, it allocates a new, larger block of memory, copies the elements, and deallocates the old block.

**R13** — Rust enums are **sum types** (can hold data in each variant). C enums are just integers. `Option<T>` is an enum with `Some(T)` and `None`. Rust has no `null` to prevent null-pointer exceptions; you must explicitly handle the `None` case.

**R14** — `impl` blocks define methods for a type. `&self` borrows immutably; `&mut self` borrows mutably; `self` consumes the value (takes ownership). **Associated functions** (like `new`) do not take `self` and are called via the type (e.g., `Type::func()`).

**R15** — `derive` automatically implements traits. Examples: `Debug` (printing), `Clone` (deep copy), `PartialEq` (equality), `Serialize` (to format). You cannot derive a trait if its implementation requires custom logic or if the underlying types do not implement that trait.

**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that can hold either borrowed data or owned data. It is useful for functions that only need to modify data if a certain condition is met, avoiding an allocation if the data remains unchanged.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. Files map to modules (e.g., `mod foo;` looks for `foo.rs`). In Rust 2018, the module system was simplified, making it easier to declare modules without needing `mod.rs` files everywhere.

**R18** — `Pin<T>` ensures that the data at a pointer address will not move in memory. This is critical for **self-referential structs** (common in `async` state machines) where a pointer inside the struct points to another field in the same struct. `Unpin` is an auto-trait indicating a type is safe to move even when pinned.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching to expand code. **Procedural macros** act like functions on tokens (derive, attribute, or function-like). **Hygiene** ensures that macro-generated identifiers do not accidentally clash with variables in the scope where the macro is called.

**R20** — Zero-cost abstractions mean you don't pay for what you don't use, and what you do use is as efficient as manual code. **Iterators** are optimized into tight loops; **Generics** use **monomorphization** (generating specific code for each type used, enabling inlining); and **Static Dispatch** resolves method calls at compile time, eliminating runtime overhead.
