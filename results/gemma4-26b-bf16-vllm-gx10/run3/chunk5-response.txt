## .NET / C#

**DN1** — `class` is a reference type (stored on the heap); `struct` is a value type (usually stored on the stack). Use a `struct` for small, immutable data structures (typically < 16 bytes) that have a short lifetime to reduce GC pressure.

**DN2** — `IEnumerable<T>` is for in-memory collections; it uses client-side evaluation. `IQueryable<T>` is for out-of-memory providers (like EF Core); it uses expression trees to translate queries into SQL. Using `IEnumerable` for DB queries causes "N+1" or "Select All" issues because the entire table is pulled into memory before filtering.

**DN3** — `async/await` allows non-blocking execution by yielding control to the caller during I/O. A `Task` represents an ongoing operation; a `ValueTask` is a union of a `T` and a `Task`, used to avoid heap allocation when the result is often available synchronously. Use `ValueTask` in high-throughput paths where the result is frequently already completed.

**DN4** — DI manages object creation and lifetimes. **Transient**: new instance every time. **Scoped**: one instance per request/scope. **Singleton**: one instance for the app lifetime. **Bug**: Injecting a Scoped service into a Singleton creates a "Captive Dependency," where the Scoped service lives as long as the Singleton, potentially causing stale data or concurrency issues.

**DN5** — `string` is immutable; every modification creates a new object. `ReadOnlySpan<char>` is a stack-only view into a contiguous memory region. Use `Span<T>` for slicing and parsing strings/arrays without allocating new memory on the heap, significantly reducing GC pressure.

**DN6** — The GC manages memory automatically. **Gen 0**: newest, short-lived objects. **Gen 1**: buffer between 0 and 2. **Gen 2**: long-lived objects. **LOH**: Large Object Heap (>85k bytes), collected less frequently. `IDisposable` is needed to manually release unmanaged resources (file handles, DB connections) because the GC only manages managed memory.

**DN7** — `ConfigureAwait(false)` tells the runtime not to marshal the continuation back to the original `SynchronizationContext`. Use it in library code to improve performance and prevent deadlocks. Do **NOT** use it in application code (like ASP.NET Core or UI apps) if you need to access context-specific data (like `HttpContext` or UI elements).

**DN8** — **Primary Constructors**: parameters defined on the class header. **Collection Expressions**: `[1, 2, 3]` syntax. **FrozenDictionary**: immutable, optimized for read-heavy workloads.
```csharp
public class UserService(IDbContext db) // Primary Constructor
{
    private readonly IDbContext _db = db;
    public int[] GetIds() => [1, 2, 3]; // Collection Expression
}
```

**DN9** — **Cause**: `DbContext` is not thread-safe. High concurrency is likely causing multiple threads to share a single `Scoped` instance (e.g., via a Singleton or static reference). **Fix**: Ensure `DbContext` is registered as `Scoped` and injected into controllers/services that are also `Scoped`. Never store a `DbContext` in a field of a `Singleton`.

**DN10** — `record` is a reference type with value-based equality. `class` uses reference equality. `record struct` is a value type with value-based equality. Use `record` for DTOs/Data models; use `class` for complex logic/state; use `record struct` for small, high-performance value types.

**DN11** — `ref`: pass by reference (allows modification). `out`: pass by reference, but must be assigned before method returns. `in`: pass by reference, but read-only (prevents modification). Use `in` for large structs to avoid copying.

**DN12** — Nullable reference types (`string?`) are a compile-time static analysis feature to prevent `NullReferenceException`. They do not change the underlying type. Nullable value types (`int?`) are syntactic sugar for `Nullable<int>`, which wraps the value in a struct that tracks `HasValue`.

**DN13** — LINQ is Language Integrated Query. **Method syntax** uses extension methods/lambdas; **Query syntax** uses SQL-like keywords. **Deferred execution** means the query is not executed when defined, but when the data is actually iterated (e.g., via `foreach` or `.ToList()`).

**DN14** — Constraints restrict generic types. `T : class` (reference type), `T : struct` (value type), `T : new()` (must have parameterless constructor), `T : IComparable<T>` (must implement interface). Combine them to ensure a type is both a class and has a constructor: `where T : class, new()`.

**DN15** — `abstract class` can hold state (fields) and implementation; `interface` defines a contract. **Default Interface Methods** allow interfaces to provide implementation, blurring the line, but interfaces still cannot hold instance state (fields).

**DN16** — Middleware is a pipeline of delegates. `app.Use()`: adds middleware that can call `next()`. `app.Map()`: branches the pipeline based on path. `app.Run()`: terminal middleware (no `next()`). **Ordering matters**: Auth must come before Authorization. **Exception handling**: placed early in the pipeline to catch errors from subsequent middleware.

**DN17** — `Channel<T>` is an async-capable producer-consumer queue. `BlockingCollection<T>` is synchronous/blocking. **Backpressure**: Use `Channel.CreateBounded<T>(capacity)`; when the channel is full, the `WriteAsync` call will asynchronously wait (suspend) until space is available.

**DN18** — **Source Generators** produce code at compile-time. Unlike **Reflection** (runtime inspection) or **IL Weaving** (post-compile bytecode manipulation), they are part of the compilation process and are highly performant/debuggable. **Incremental Generators** are preferred because they only re-run when specific inputs change, preventing massive re-compilation times.

**DN19** — **TPL Dataflow** is for actor-like pipelines. `ActionBlock` (consumer), `TransformBlock` (processor), `BufferBlock` (queue). **Comparison**: `Channels` are lightweight and optimized for high-throughput passing of data; `Dataflow` is higher-level, offering complex routing, buffering, and actor-like management.

**DN20** — **Minimal APIs** use lambda expressions instead of Controllers for routing. **Trade-offs**: Faster startup/less boilerplate, but harder to organize large projects without discipline. **Testability**: Similar to controllers. **OpenAPI**: Fully supported via `Microsoft.AspNetCore.OpenApi`. **Route Groups** allow shared prefixes/middleware; **Endpoint Filters** allow logic to run before/after the handler.

## Python

**P1** — `list` is mutable; `tuple` is immutable. `set` is mutable; `frozenset` is immutable.

**P2** — The GIL is a mutex that allows only one thread to execute Python bytecode at a time. It affects **CPU-bound** workloads (multithreading won't help). Workarounds: Use `multiprocessing` (separate memory spaces) or C-extensions (releasing the GIL).

**P3** — `copy` creates a new object but inserts references to the original elements. `deepcopy` recursively copies everything. **Example**: If `a = [[1]]`, `b = a.copy()`, then `b[0][0] = 2` changes `a[0][0]` because the inner list is the same object.

**P4** — Decorators wrap functions.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"Time: {time.time() - start}")
        return result
    return wrapper
```

**P5** — Generators use `yield` to return values one at a time, maintaining state. Unlike a `list`, they are lazy and memory-efficient. `yield from` is used to delegate to a sub-generator (flattening).

**P6** — The event loop manages async tasks. `asyncio.run()`: entry point; `asyncio.gather()`: runs multiple tasks concurrently and waits for all; `asyncio.create_task()`: schedules a task to run in the background. `time.sleep()` is blocking; it stops the entire thread (and loop), preventing other tasks from running. Use `await asyncio.sleep()`.

**P7** — Python uses **C3 Linearization**. In diamond inheritance, it ensures a child is visited before its parents and parents are visited in order.
**Result**: `C`. `D` inherits from `B` then `C`. `B` inherits from `A`. `C` inherits from `A`. The MRO is `D -> B -> C -> A`. Since `C` overrides `who`, it is called.

**P8** — A **metaclass** is a class of a class (defines how classes are created). `__init_subclass__` is a simpler hook for customizing class creation without a full metaclass. **Use case**: Metaclass for complex registry/validation; `__init_subclass__` for simple automatic registration of subclasses.

**P9** — `threading`: shared memory, good for I/O. `multiprocessing`: separate memory, good for CPU-bound. `concurrent.futures`: high-level abstraction (Pools). **Serialization**: `multiprocessing` requires objects to be "picklable" to move them between processes.

**P10** — `__slots__` tells Python not to use a `__dict__` for instance attributes, instead using a fixed array. It prevents adding arbitrary attributes, saves significant memory, and slightly improves attribute access speed.

**P11** — A virtual environment isolates dependencies for a project. `venv` is built-in; `virtualenv` is a faster/older third-party tool; `conda` is a package/environment manager that handles non-Python dependencies (C libraries).

**P12** — Comprehensions are concise syntax for creating collections. They are generally faster and more readable than `map()`/`filter()`. Use comprehensions for most cases; use `map`/`filter` when working with existing functions or very large iterators where laziness is strictly required.

**P13** — `==` checks for **equality** (value); `is` checks for **identity** (memory address). **Interning**: Python caches small integers (-5 to 256) and certain strings to save memory, so `a is b` returns `True` for them.

**P14** — `*args` collects extra positional arguments into a tuple; `**kwargs` collects extra keyword arguments into a dict. `/` forces arguments before it to be positional-only; `*` forces arguments after it to be keyword-only.

**P15** — Context managers handle setup/teardown.
```python
from contextlib import contextmanager
@contextmanager
def my_ctx():
    print("Setup")
    yield
    print("Teardown")
# Usage: with my_ctx(): ...
```
**Example**: A database transaction or a temporary directory.

**P16** — Type hinting provides static type information. `Union[int, str]` (either), `Optional[int]` (int or None), `Literal["a", "b"]` (specific values), `TypeVar` (generics), `Protocol` (structural typing/duck typing). `mypy` uses these to find bugs without running the code.

**P17** — `__repr__` is for developers (unambiguous); `__str__` is for users (readable). `__eq__` compares values; `__hash__` allows an object to be used in a set/dict. If you define `__eq__` but not `__hash__`, the object becomes unhashable. `__getattr__` is called only if attribute isn't found; `__getattribute__` is called every time.

**P18** — Descriptors are objects that define how attribute access works via `__get__`, `__set__`, and `__delete__`. `property`, `classmethod`, and `staticmethod` are all implemented using the descriptor protocol to intercept access to the attribute.

**P19** — **Absolute**: `from pkg.mod import x`. **Relative**: `from .mod import x`. `sys.path` is the list of directories searched for modules. `__init__.py` makes a directory a package. **Namespace packages** allow splitting a package across multiple directories. **Finder** locates the module; **Loader** loads the code.

**P20** — `dataclasses` is built-in and lightweight. `attrs` is more powerful/feature-rich. `Pydantic` is focused on **data validation** and parsing (runtime). Use `Pydantic` for API schemas/external data; use `dataclasses` for internal data structures. `__post_init__` runs after `__init__`. `frozen=True` makes it immutable.
