## .NET / C#

**DN1** — `class` is a reference type (stored on the heap); `struct` is a value type (usually stored on the stack). Use a `struct` for small, immutable data structures (typically < 16 bytes) that have a short lifetime to reduce GC pressure.

**DN2** — `IEnumerable<T>` is for in-memory collections; it uses client-side evaluation. `IQueryable<T>` is for out-of-memory providers (like EF Core); it uses expression trees to translate queries into SQL. Using `IEnumerable` for DB queries causes "N+1" or "Select All" issues because the entire table is pulled into memory before filtering.

**DN3** — `async/await` allows non-blocking execution by yielding control to the caller during I/O. A `Task` represents an ongoing operation; a `ValueTask` is a value-type wrapper for a task that might already be completed. Use `ValueTask` when the result is often available synchronously to avoid heap allocation of a `Task` object.

**DN4** — DI manages object creation and lifetimes. **Transient**: new instance every time. **Scoped**: one instance per request/scope. **Singleton**: one instance for the app lifetime. **Bug**: Injecting a Scoped service into a Singleton creates a "Captive Dependency," where the Scoped service lives as long as the Singleton, potentially causing stale data or concurrency issues.

**DN5** — `string` is immutable; every modification creates a new object. `ReadOnlySpan<char>` is a stack-allocated view into a contiguous memory region. Use `Span<T>` for high-performance slicing and parsing to avoid unnecessary heap allocations and memory copying.

**DN6** — The GC manages memory automatically. **Gen 0**: newest, short-lived objects. **Gen 1**: buffer between 0 and 2. **Gen 2**: long-lived objects. **LOH**: Large Object Heap (>85k bytes), collected during Gen 2. `IDisposable` is used to manually release unmanaged resources (file handles, DB connections) because the GC only manages managed memory.

**DN7** — `ConfigureAwait(false)` tells the runtime not to marshal the continuation back to the original `SynchronizationContext`. Use it in library code to improve performance and prevent deadlocks. Do **NOT** use it in UI applications (WPF/WinForms) or ASP.NET (Legacy) if you need to access UI elements or `HttpContext` after the `await`.

**DN8** — **Primary Constructors**: parameters defined on the class header. **Collection Expressions**: `[1, 2, 3]` syntax. **FrozenDictionary**: immutable, optimized for read-heavy lookups.
```csharp
public class UserService(IDbContext db) // Primary Constructor
{
    public void DoWork() => db.Save();
}
```

**DN9** — **Cause**: `DbContext` is not thread-safe. You are likely sharing a single Scoped `DbContext` instance across multiple concurrent threads (e.g., via `Task.WhenAll` on a single scope). **Fix**: Ensure each concurrent task creates its own scope using `IServiceScopeFactory` to get a unique `DbContext` instance.

**DN10** — `record` is a reference type with value-based equality. `class` uses reference equality. `record struct` is a value type with value-based equality. Use `record` for DTOs/Data models; use `class` for complex logic/state; use `record struct` for small, high-performance value types.

**DN11** — `ref`: pass by reference (read/write). `out`: pass by reference, must be assigned in the method (return multiple values). `in`: pass by reference, read-only (prevents copying large structs).

**DN12** — Nullable Reference Types (`string?`) are a compile-time static analysis feature to prevent `NullReferenceException`. Nullable Value Types (`int?`) are runtime wrappers (`Nullable<T>`) that allow a value type to hold `null`.

**DN13** — LINQ is Language Integrated Query. **Method syntax** uses extension methods/lambdas; **Query syntax** uses SQL-like keywords. **Deferred execution** means the query is not executed when defined, but when the data is actually iterated (e.g., via `foreach` or `.ToList()`).

**DN14** — Constraints restrict generic types. `T : class` (reference type), `T : struct` (value type), `T : new()` (must have parameterless constructor), `T : IComparable<T>` (must implement interface). Combine them to ensure a type is both a class and has a constructor: `where T : class, new()`.

**DN15** — `abstract class` can have state (fields) and implementation; `interface` defines a contract. **Default Interface Methods** allow interfaces to provide implementation, blurring the line, but interfaces still cannot hold instance state (fields).

**DN16** — Middleware is a pipeline of delegates. `app.Use()`: adds middleware that can call the next. `app.Map()`: branches the pipeline based on path. `app.Run()`: terminal middleware (stops the pipeline). **Ordering matters**: Exception handling must be first to catch errors in subsequent steps.

**DN17** — `Channel<T>` is an async-native producer-consumer queue. `BlockingCollection<T>` is synchronous/thread-blocking. **Backpressure**: Use `Channel.CreateBounded<T>(capacity)`; the `WriteAsync` method will asynchronously wait when the channel is full, preventing the producer from overwhelming the consumer.

**DN18** — **Source Generators** produce code at compile-time. Unlike **Reflection** (runtime inspection) or **IL Weaving** (post-compile bytecode manipulation), they are part of the compilation process and are highly performant/debuggable. **Incremental Generators** are preferred because they only re-run when specific inputs change, significantly improving IDE/build performance.

**DN19** — **TPL Dataflow** is a library for actor-based/pipeline processing. `ActionBlock` (consumer), `TransformBlock` (processor), `BufferBlock` (queue). Compared to `Channels`, Dataflow is higher-level and handles complex graph topologies and concurrency limits more easily, whereas `Channels` is a lower-level, high-performance primitive.

**DN20** — **Minimal APIs** use lambda expressions for routing instead of Controllers. **Trade-offs**: Minimal APIs are faster/lighter but can become messy without organization; Controllers offer better structure for large APIs. **Route Groups** allow applying middleware/auth to a set of endpoints. **Endpoint Filters** act like middleware but are scoped to specific endpoints.

## Python

**P1** — `list` is mutable; `tuple` is immutable. `set` is mutable; `frozenset` is immutable.

**P2** — The GIL is a mutex that allows only one thread to execute Python bytecode at a time. It affects **CPU-bound** workloads (preventing true parallelism). **Workarounds**: Use `multiprocessing` (separate processes/GILs) or use C-extensions (like NumPy) that release the GIL during heavy computation.

**P3** — `copy` creates a new object but inserts references to the original nested objects. `deepcopy` recursively copies everything. **Example**: If `a = [[1]]` and `b = copy.copy(a)`, then `b[0][0] = 2` also changes `a[0][0]` because the inner list is the same object.

**P4** — Decorators wrap functions.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"Time: {time.time() - start}")
        return result
    return wrapper
```

**P5** — Generators use `yield` to return values one at a time, maintaining state. Unlike a `list`, they are lazy and memory-efficient. `yield from` is used to delegate to a sub-generator (flattening).

**P6** — The event loop manages async tasks. `asyncio.run()`: entry point; `asyncio.gather()`: runs multiple coroutines concurrently; `asyncio.create_task()`: schedules a coroutine to run in the background. `time.sleep()` is blocking; it stops the entire thread (and the loop), so you must use `await asyncio.sleep()`.

**P7** — Python uses **C3 Linearization**. In diamond inheritance, it ensures a child is checked before its parents and parents are checked in order. In the example, `D` inherits from `B` then `C`. Since `B` inherits from `A`, and `C` inherits from `A`, the MRO is `D -> B -> C -> A`. `D().who()` calls `B.who()`, which is not defined, so it looks at `A.who()`. Wait—actually, `B` inherits from `A`, but `C` overrides `who`. The MRO is `[D, B, C, A, object]`. `D` calls `B`, `B` has no `who`, so it goes to `C`. Result: `"C"`.

**P8** — A **metaclass** is a class of a class (defines how classes are created). `__init_subclass__` is a simpler way to intercept class creation. Use `__init_subclass__` for simple registration/validation; use a **metaclass** for complex logic that requires modifying the class structure before it's even fully created.

**P9** — `threading`: shared memory, good for I/O. `multiprocessing`: separate memory, good for CPU-bound. `concurrent.futures`: high-level abstraction (Pools) for both. **Serialization**: `multiprocessing` requires objects to be "picklable" to be sent between processes.

**P10** — `__slots__` tells Python not to use a `__dict__` for instance attributes, instead using a fixed array. It prevents adding arbitrary attributes, saves significant memory, and slightly improves attribute access speed.

**P11** — A virtual environment isolates project dependencies. `venv` is built-in; `virtualenv` is a faster/older third-party tool; `conda` is a package/environment manager that handles non-Python dependencies (C libraries).

**P12** — Comprehensions are syntactic sugar for creating collections. They are generally more readable and faster than `map()`/`filter()`. Use comprehensions for most cases; use `map`/`filter` when you already have a pre-defined function.

**P13** — `==` checks for **equality** (value); `is` checks for **identity** (memory address). **Interning** is an optimization where Python reuses objects for small integers (-5 to 256) and certain strings.

**P14** — `*args` collects extra positional arguments; `**kwargs` collects extra keyword arguments. `/` forces arguments before it to be positional-only; `*` forces arguments after it to be keyword-only.

**P15** — Context managers handle setup/teardown.
```python
from contextlib import contextmanager
@contextmanager
def my_ctx():
    print("Setup")
    yield
    print("Teardown")
# Usage: with my_ctx(): ...
```
Example: A database transaction or a temporary directory.

**P16** — Type hinting provides metadata for static analysis. `Union[int, str]` (either), `Optional[int]` (int or None), `Literal[1, 2]` (exactly 1 or 2), `TypeVar` (generics), `Protocol` (structural typing/duck typing). `mypy` uses these to find bugs without running the code.

**P17** — `__repr__` is for developers (unambiguous); `__str__` is for users (readable). `__eq__` checks equality; `__hash__` allows an object to be used in a `set` or `dict` key. If you define `__eq__` but not `__hash__`, the class becomes unhashable. `__getattr__` is called only if the attribute isn't found; `__getattribute__` is called *every* time.

**P18** — Descriptors are objects that define how attribute access works via `__get__`, `__set__`, and `__delete__`. `property`, `classmethod`, and `staticmethod` are all implemented using the descriptor protocol to intercept access to the attribute.

**P19** — **Absolute**: `import package.module`. **Relative**: `from . import module`. `sys.path` is the list of directories searched. `__init__.py` makes a directory a package. **Namespace packages** allow splitting a package across multiple directories. A **Finder** locates the module; a **Loader** loads the code.

**P20** — `dataclasses` is built-in; `attrs` is more powerful/feature-rich; `Pydantic` is focused on data validation/parsing (often used with FastAPI). `dataclasses` uses `__post_init__` for logic after `__init__`. Use **Pydantic** when you need to enforce types at runtime (e.g., parsing JSON API requests).
