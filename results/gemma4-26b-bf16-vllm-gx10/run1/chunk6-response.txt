### JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted with `undefined`. `let` and `const` are block-scoped and hoisted but reside in a "Temporal Dead Zone" (TDZ) until declaration. `const` prevents reassignment of the identifier. **Hoisting** is the engine's behavior of moving declarations to the top of their scope during the compile phase.

**JS2** — The **Event Loop** manages asynchronous execution. The **Call Stack** executes synchronous code. When async tasks finish, they enter queues. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority and is emptied completely after every task. The **Macrotask Queue** (setTimeout, setInterval, I/O) is processed one task at a time after the microtask queue is empty.

**JS3** — A **closure** is a function that "remembers" its lexical scope even when executed outside that scope. *Example:* A function returning another function that increments a private counter. *Classic Bug:* Using `var` in a `for` loop with an async operation; all iterations share the same variable instance. *Fix:* Use `let` (creates a new binding per iteration) or an IIFE.

**JS4** — **Promise** represents an eventual value. `async/await` is syntactic sugar for Promises. Error handling: `try/catch` with `async/await`; `.catch()` with Promises. `Promise.all` rejects immediately if *any* promise fails. `Promise.allSettled` waits for all to finish, returning an array of objects describing the outcome of each.

**JS5** — `interface` is primarily for defining object shapes and supports "declaration merging" (adding properties via multiple definitions). `type` is for unions, primitives, and aliases. Use `interface` for public APIs/objects; use `type` for complex logic/unions. **Discriminated Unions** use a common literal property (e.g., `type: 'success' | 'error'`) to allow TypeScript to narrow types in conditional blocks.

**JS6** — **Prototypal inheritance** means objects inherit properties from a prototype object via the prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. **ES6 Classes** are "syntactic sugar" over prototypes; they don't introduce a new inheritance model but provide a cleaner syntax for constructor functions and prototype methods.

**JS7** — `this` refers to the execution context. **Binding Rules:** 1. `new` (Constructor), 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (Object method call), 4. Default (Global/Undefined in strict mode). `bind()` returns a **new function** with a fixed `this`. You cannot re-bind a function once it has been bound.

**JS8** — `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` triggers a callback when an object is GC'd. Use them for caches or metadata to avoid memory leaks. `WeakMap` keys must be objects because primitives cannot be tracked by the GC in the same way, and the map's purpose is to allow the key to be collected when no other references exist.

**JS9** — V8 uses **Hidden Classes** (shapes) to track object properties efficiently. **Inline Caching** optimizes property access by remembering where properties were found previously. **Deoptimization** occurs when the engine's assumptions fail (e.g., a function receiving a different object shape than usual). *Patterns:* Changing object property order, deleting properties (`delete`), or passing inconsistent types to polymorphic functions.

**JS10** — **Tree-shaking** is dead-code elimination. It works with **ES Modules** because `import/export` are static (analyzable at compile time). **CommonJS** (`require`) is dynamic; modules can be loaded conditionally at runtime, making it impossible for tools to safely determine what is unused without running the code.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion; `===` checks value and type. **Nullish coalescing (`??`)** returns the right side only if the left is `null` or `undefined`. **Optional chaining (`?.`)** short-circuits and returns `undefined` if the reference is nullish.

**JS12** — `map()` transforms elements; `filter()` selects elements based on a predicate; `reduce()` accumulates elements into a single value. `reduce` with an initial value uses that value as the first `accumulator`. `flatMap()` maps each element and then flattens the result by one level; useful for handling nested arrays or 1-to-many transformations.

**JS13** — **Template literals** use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** allow a function to parse the template literal. *Example:* `const sql = (strings, ...values) => ...` can escape values to prevent SQL injection.

**JS14** — **Destructuring** extracts values from arrays/objects. *Object:* `const {a, b} = obj;`. *Array:* `const [x, y] = arr;`. *Default:* `const {a = 1} = obj;`. *Renaming:* `const {old: newName} = obj;`. The **rest operator** (`...`) collects remaining elements into a new array/object.

**JS15** — `for...in` iterates over **enumerable property keys** (strings). `for...of` iterates over **iterable values**. Avoid `for...in` on arrays because it iterates over indices as strings and may include inherited properties.

**JS16** — **Generics** allow reusable components. `extends` (constraints) limits the type: `<T extends string>`. **Conditional types** act as ternary operators: `T extends string ? A : B`. `infer` allows extracting types from within other types. *Example:* `type GetReturn<T> = T extends (...args: any[]) => infer R ? R : any;`.

**JS17** — **CommonJS** is synchronous, uses `require`, and is the Node.js default. **ES Modules** are asynchronous, use `import/export`, and are the browser standard. Node.js handles both, but ESM is preferred. `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM.

**JS18** — TS is **structural** (if it looks like a duck, it is a duck). **Excess property checks** occur during direct object literals to prevent typos. `extends` is for subtyping; `satisfies` validates a type without changing the inferred type of the variable. **Variance:** `in` (contravariance) for function arguments; `out` (covariance) for return types.

**JS19** — `Proxy` wraps an object to intercept operations; `Reflect` provides methods to perform those operations. *Example:* A Proxy can intercept `set` to validate that a property is a number before assigning it, using `Reflect.set` to actually perform the write.

**JS20** — `SharedArrayBuffer` allows multiple threads (Workers) to share a raw memory buffer. `Atomics` provides static methods to perform thread-safe operations (add, load, store) to prevent race conditions. `Atomics.wait` puts a thread to sleep until `Atomics.notify` is called on the same index.

### Bash

**B1** — `$@` and `$*` represent all arguments. `"$@"` preserves arguments as distinct quoted strings (best practice). `"$*"` joins all arguments into a single string.

**B2** — `-e`: exit on error; `-u`: error on unset variables; `-o pipefail`: return the exit code of the first command in a pipe that fails.

**B3** — `$(command)` is command substitution (modern). `` `command` `` is the legacy version. `$((expression))` is arithmetic expansion. `expr` is an external command for math (slower/older).

**B4** — **Process substitution** `<(command)` creates a temporary file descriptor that acts like a file. *Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands.

**B5** — Use `while read -r line; do ... done < <(find . -print0) | while IFS= read -r -d '' file; do ... done`. `for f in $(ls)` is dangerous because it splits on whitespace, breaking filenames with spaces.

**B6** — `<<EOF` is a **here-doc** (standard). `<<<` is a **here-string** (passes a string to stdin). `<<-EOF` strips leading **tabs** (not spaces) from the document.

**B7** — `cmd > file 2>&1`: Redirects stdout to file, then redirects stderr to where stdout is currently pointing (the file). `cmd 2>&1 > file`: Redirects stderr to stdout (terminal), then redirects stdout to a file (stderr stays on terminal). `cmd &> file`: Shorthand for both to the file.

**B8** — Use `mkdir lockdir`. `mkdir` is atomic at the OS level; if two processes try, only one succeeds.
```bash
lockdir="mylock"
trap 'rmdir "$lockdir" 2>/dev/null; exit' INT TERM EXIT
if mkdir "$lockdir"; then
  # critical section
  rmdir "$lockdir"
else
  echo "Locked" && exit 1
fi
```

**B9** — `'...'` (Single): Literal string, no expansion. `"..."` (Double): Allows variable expansion and command substitution. `no quotes`: Word splitting and globbing occur. *Example:* `echo "$VAR"` vs `echo '$VAR'` vs `echo $VAR` (if $VAR contains spaces).

**B10** — `[ -f file ]` (file), `[ -d dir ]` (directory), `[ -r file ]` (readable). `[[ ]]` is a Bash keyword that is more powerful, supports regex (`=~`), and doesn't require quoting variables to prevent word splitting.

**B11** — `$?`: exit status of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: number of arguments.

**B12** — `foo() { ... }` is the standard POSIX way. `function foo { ... }` is a Bashism. Functions return an **exit status** (0-255) via `return`. To return data, use `echo` and capture with `$(...)`.

**B13** — `PATH` is a colon-separated list of directories. Bash searches them in order. **Builtin** (e.g., `cd`) is inside the shell; **External** (e.g., `ls`) is a file on disk. Use `type <cmd>` to check.

**B14** — `trap` catches signals. `trap 'cleanup' EXIT ERR INT TERM`. If multiple signals arrive, they are handled sequentially. `EXIT` is always the last to run.

**B15** — `xargs` converts stdin to arguments for a command. `find -print0 | xargs -0` handles spaces/newlines by using a null delimiter. `xargs -P <N>` runs up to N processes in parallel.

**B16** — **Arrays:** `arr=(a b c)`. **Associative:** `declare -A map; map[key]=val`. Append: `arr+=("new")`. Iterate: `for i in "${!arr[@]}"` (keys) or `for i in "${arr[@]}"` (values). Length: `${#arr[@]}`.

**B17** — `(...)` is a **subshell** (new process, loses variable changes). `{ ...; }` is a **group command** (same shell, keeps changes). Piping `cmd | while` runs the loop in a subshell, so variables modified inside are lost to the parent.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (polite kill), `SIGHUP` (terminal closed), `SIGKILL` (immediate, cannot be caught). For graceful shutdown, use `trap` to catch `TERM` and kill child PIDs.

**B19** — Use `split -l` to chunk the log, `find` the chunks, `xargs -P` to run a function on each, and `cat` the results. *Trade-off:* Parallelism speeds up CPU-bound tasks but can overwhelm I/O. Error propagation requires checking exit codes of all `xargs` processes.

**B20** — `exec` replaces the current shell process with the new command. `exec 3>file` opens file descriptor 3 for writing. `exec 3>&-` closes it. A **coprocess** (`coproc`) runs a command in the background and provides pipes for bidirectional communication.

### PowerShell

**PS1** — `Write-Output` sends objects to the **pipeline** (useful for downstream processing). `Write-Host` writes directly to the **host/console** (not part of the pipeline).

**PS2** — The **pipeline** passes whole objects. `ForEach-Object` processes objects one-by-one as they arrive (memory efficient). `foreach ($x in $y)` is a language keyword that loads the entire collection into memory first (faster for small/medium sets).

**PS3** — `[PSCustomObject]` is an ordered collection of properties (best for output). `[hashtable]` is an unordered key-value pair (best for lookups). Convert: `[PSCustomObject]@{k=v}` or `[hashtable]$obj`.

**PS4** — **Terminating** errors stop execution; **Non-terminating** errors (like `Get-ChildItem` missing a file) continue. Use `try/catch` for terminating errors. Use `-ErrorAction Stop` to turn non-terminating errors into terminating ones.

**PS5** — **Splatting** passes a hashtable as arguments: `$params = @{Path='C:\'; Force=$true}; Write-Item @params`. It differs from passing a hashtable as a single parameter because it unpacks the keys as individual parameter names.

**PS6** — `Invoke-Command -ComputerName` runs a command on remote machines (one-to-many). `Enter-PSSession` is an interactive shell (one-to-one). Uses **WS-Man** (WinRM) or **SSH**.

**PS7** — The function returns an **array** because `$result += "one"` forces the type to `[System.Array]`. If 0 items are returned, it returns `$null`. The correct pattern is to use `[System.Collections.Generic.List[string]]` or simply output objects directly without an accumulator array.

**PS8** — A `[scriptblock]` is a piece of code; a function is a named, reusable block. Pass via `-ArgumentList`. The **double-hop** problem occurs when a remote session tries to use your credentials to access a *third* machine. Solve with **CredSSP** or **Kerberos Delegation**.

**PS9** — `@()` is an array literal; `[array]` is a type cast. Force single result: `@($result)[0]`. Indexing `$null` throws an error; indexing an empty array returns `$null`.

**PS10** — `-eq/-ne` are equality/inequality. `-like` uses wildcards (`*`). `-match` uses Regex. `-contains` checks if a collection contains a value. `-in` checks if a value exists in a collection. `-ceq` etc., are case-sensitive.

**PS11** — **Module:** collection of functions/types. `.psm1` (script module), `.psd1` (manifest/metadata), **Binary** (compiled DLL). `Import-Module` loads it into the session.

**PS12** — `"..."` allows interpolation; `'...'` is literal. Use `$()` for expressions: `"Value is $($obj.Prop)"`. **Here-string**: `@'...'@` (literal) or `@"..."@` (interpolated).

**PS13** — `Get-Member` shows type info. **Properties** (data), **Methods** (actions), **NoteProperties** (added dynamically). `Select-Object` picks properties; `Where-Object` filters objects.

**PS14** — **Classes** are strongly typed and support inheritance. They are more rigid than functions. Limitations: No support for `dynamic` types easily, and they are not as "pipeline-native" as functions. Use classes for complex data models; functions for actions.

**PS15** — `[CmdletBinding()]` makes a function behave like a compiled cmdlet (adds `-Verbose`, `-ErrorAction`, etc.). `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` allows handling pipeline input efficiently.

**PS16** — **Providers** allow treating different data stores as a drive. `Get-ChildItem Registry::HKEY_LOCAL_MACHINE` works just like a file system.

**PS17** — A **runspace** is a single thread of execution. `[runspacepool]` manages multiple runspaces. `ForEach-Object -Parallel` (v7) is a high-level wrapper that manages the runspace pool for you.

**PS18** — **PSScriptAnalyzer** is a static code analysis tool. It uses **rules** to check for best practices. Severity: Error, Warning, Info. Suppress via `# PSScriptAnalyzer Ignore: RuleName`. Integrates via CI/CD tasks (e.g., GitHub Actions).

**PS19** — `$using:var` is required to access local variables inside a remote/parallel block. `$args` is for positional parameters. **Serialization limits:** Complex objects are converted to XML (CLIXML); if the object is too deep or contains non-serializable types (like file handles), data is lost.

**PS20** — **DSC** ensures a system reaches a specific state. **Configuration** is the script; **Resource** is the logic; **LCM** is the engine on the node. Windows PowerShell uses WMF; PS7+ is cross-platform. Modern IaC uses **Terraform** or **Ansible**.
