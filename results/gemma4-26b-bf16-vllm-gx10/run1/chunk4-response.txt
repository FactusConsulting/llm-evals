## Go

**G1** — An **array** has a fixed size defined at compile time; its size is part of its type. A **slice** is a descriptor (header) containing a pointer to an underlying array, a length, and a capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array (usually doubling in size), copies the old elements to the new array, and returns a new slice header pointing to the new memory.

**G2** — `var x int` declares a variable and initializes it to its **zero value** (0). `x := 0` is **short variable declaration**, which declares and initializes in one step. You **cannot** use `:=` outside of function bodies (at the package level).

**G3** — A **goroutine** is a lightweight execution unit managed by the Go runtime. Unlike OS threads, which have large stacks (MBs) and require expensive context switches via the kernel, goroutines have small, growable stacks (KBs) and are multiplexed onto OS threads by the Go scheduler. The **GMP model** consists of **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts/resources). The scheduler distributes Gs onto Ms via Ps to ensure efficient CPU utilization and work-stealing.

**G4** — **Channels** are pipes used for communication and synchronization between goroutines. An **unbuffered channel** requires both sender and receiver to be ready simultaneously (synchronous). A **buffered channel** has a capacity; sends only block when the buffer is full. Sending to a **full buffered channel** blocks the sending goroutine until a receiver removes an item.

**G5** — `context` is used for cancellation signals, deadlines, and passing request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

**G6** — Go uses **implicit satisfaction**: a type satisfies an interface simply by implementing its methods; no `implements` keyword is needed. This differs from Java/C# which require explicit declaration. `interface{}` (or `any`) is an interface with zero methods, meaning every type satisfies it. It is **powerful** because it allows for generic data handling, but **dangerous** because it bypasses type safety, requiring runtime type assertions that can panic.

**G7** — The code is unsafe due to a **data race**. The Go memory model does not guarantee that writes in one goroutine are visible to another without explicit synchronization. The compiler or CPU might reorder instructions, or the value might stay in a CPU cache. **Correct alternatives**: Use a `sync.Mutex`, a `channel` to signal completion, or `atomic.Bool` for the `ready` flag.

**G8** — `sync.Mutex` is an exclusive lock (one holder). `sync.RWMutex` allows multiple concurrent readers OR one single writer. Use `sync.Map` for high-concurrency scenarios where keys are stable and the workload is mostly reads/updates to existing keys, or when multiple goroutines read/write disjoint sets of keys. **Trade-offs**: `sync.Map` is optimized for specific patterns but is slower than a `map + Mutex` for general-purpose, heavy-write workloads due to internal interface conversions and cache contention.

**G9** — **Go modules** manage dependencies. `go.mod` defines the module path and specific dependency versions. `go.sum` contains cryptographic hashes of dependencies to ensure integrity. `go mod tidy` adds missing modules and removes unused ones. **MVS (Minimum Version Selection)** is the algorithm used to select the lowest compatible version of a module that satisfies all requirements in the dependency graph, ensuring reproducible builds.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common **gotcha** is using `defer` inside a loop; the deferred calls won't execute until the *outer* function returns, potentially causing resource exhaustion (e.g., leaking file descriptors).

**G11** — A **pointer** is a variable that stores the memory address of another value. The zero value is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs automatically when a package is initialized. It runs after variable declarations but before `main()`. A package **can** have multiple `init()` functions; they execute in the order they appear in the source code.

**G13** — `new(T)` allocates zeroed memory for a type `T` and returns a **pointer** (`*T`). `make(T, args)` is used only for **slices, maps, and channels**; it initializes the internal data structures and returns an **initialized value** of that type.

**G14** — Errors are values. The `error` interface has one method: `Error() string`. The idiomatic pattern is returning `error` as the last return value and checking `if err != nil`. `errors.Is` checks if an error matches a specific value (including wrapped errors), while `errors.As` checks if an error matches a specific type (including wrapped errors). `==` only checks for direct equality and fails with wrapped errors.

**G15** — 
- **map**: `nil`
- **slice**: `nil`
- **channel**: `nil`
- **struct**: All fields set to their respective zero values.

**G16** — A **race condition** occurs when two or more goroutines access the same memory concurrently, and at least one access is a write. The `-race` flag enables a runtime detector that intercepts memory accesses to find unsynchronized concurrent access.
*Example Fix*:
```go
// Bad: count++ (data race)
// Good:
var mu sync.Mutex
mu.Lock()
count++
mu.Unlock()
```

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch` (which evaluates expressions), `select` evaluates channel operations. If multiple cases are ready, one is chosen **pseudo-randomly**. To implement a timeout:
```go
select {
case res := <-ch:
    fmt.Println(res)
case <-time.After(time.Second):
    fmt.Println("timeout")
}
```

**G18** — **Escape analysis** is a compiler phase that determines if a variable can reside on the **stack** (fast, automatic cleanup) or must "escape" to the **heap** (slower, requires GC). A variable escapes if its address is returned from a function, if it's too large for the stack, or if its lifetime is unknown. Inspect via `go build -gcflags="-m"`. It matters because excessive heap allocation increases GC pressure and latency.

**G19** — `reflect` allows inspecting types and values at runtime. `reflect.Type` describes the type (e.g., `int`, `struct`), while `reflect.Value` holds the actual data. **Costs**: It is significantly slower than static code due to runtime overhead and prevents many compiler optimizations. **Justification**: Use it for generic libraries (like JSON encoders) where types aren't known at compile time; use **code generation** (like `protobuf`) for performance-critical paths.

**G20** — `//go:embed` allows including static files in the binary. It works for single files, directories, or multiple files. It interacts with `io/fs.FS` by providing an embedded filesystem. **Limitations**: It only works with `[]byte` or `string` variables and cannot embed files that are not part of the module's filesystem at build time.

## Rust

**R1** — **Ownership** is Rust's memory management system. Rules: 1. Each value has a variable called its *owner*. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is an immutable string slice (a view into a string). Use `&str` in function signatures for maximum flexibility (it accepts both `&String` and `&str`). Use `String` when the function needs to own or modify the data.

**R3** — **Borrowing** allows accessing data without taking ownership. **Rules**: You can have either **one** mutable reference (`&mut T`) OR **any number** of immutable references (`&T`) at any given time, but not both simultaneously. This prevents data races at compile time.

**R4** — `Result<T, E>` represents success (`Ok`) or failure (`Err`). `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator performs early return on error.
```rust
use std::fs::File;
use std::io::{self, Read};

fn read_file(path: &str) -> Result<String, io::Error> {
    let mut s = String::new();
    File::open(path)?.read_to_string(&mut s)?;
    Ok(s)
}
```

**R5** — `Box<T>`: Single ownership, heap allocation. `Rc<T>`: Reference counted, multiple ownership (single-threaded). `Arc<T>`: Atomic reference counted, multiple ownership (thread-safe). Use `Box` for large types/recursion, `Rc` for shared data in one thread, and `Arc` for shared data across threads.

**R6** — **Traits** define shared behavior (similar to interfaces). **Trait Object** (`dyn Trait`) uses dynamic dispatch (runtime lookup via vtable). **Generics with Trait Bounds** (`T: Trait`) use static dispatch (monomorphization at compile time), which is generally faster.

**R7** — It fails because the compiler cannot determine if the returned reference lives as long as `x` or `y`. **Fix**: Add lifetime annotations: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8** — `Send` means ownership can be transferred to another thread. `Sync` means a type can be safely shared between threads via references. `Rc<T>` is not `Send`/`Sync` because its reference count is not updated atomically, leading to races. `Arc<T>` uses atomic operations for the count, making it safe.

**R9** — Rust's async is **poll-based**. A `Future` is a state machine that does nothing until `poll()` is called. An **executor** (like Tokio) manages these futures, polling them when they are ready to make progress. Unlike Go's goroutines (which are preemptively scheduled by a runtime), Rust futures are **cooperative** and require an executor to drive them.

**R10** — `unsafe` allows bypassing certain compiler checks. You can: 1. Dereference raw pointers. 2. Call unsafe functions. 3. Access/modify mutable static variables. It is justified when interfacing with C code (FFI) or implementing low-level primitives that the compiler cannot prove are safe.

**R11** — **Pattern matching** (`match`) allows branching based on the structure of data. `if let` is syntactic sugar for a `match` with a single arm. The compiler enforces **exhaustiveness**, ensuring every possible pattern is handled.

**R12** — `Vec<T>` is a growable heap-allocated array. `[T; N]` is a fixed-size stack-allocated array. When a `Vec` exceeds capacity, it allocates a new, larger block of memory, moves the elements, and deallocates the old block.

**R13** — **Enums** in Rust are "sum types" (can hold data per variant), unlike C enums (integers) or Java enums (objects). `Option<T>` is an enum with `Some(T)` and `None`. Rust has no `null` to eliminate null-pointer exceptions; you must explicitly handle the `None` case.

**R14** — `impl` defines methods for a type. `&self` borrows immutably; `&mut self` borrows mutably; `self` consumes the value (takes ownership). **Associated functions** (like `String::new()`) do not take `self` and are called via the type name.

**R15** — `derive` automatically implements traits. Examples: `Debug` (printing), `Clone` (deep copy), `PartialEq` (equality), `Serialize` (conversion to format). You cannot derive a trait if its implementation requires logic the compiler cannot automatically generate (e.g., custom equality logic).

**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that can hold either borrowed or owned data. It is useful for functions that only need to modify data if it doesn't meet certain criteria, avoiding an allocation if the data is already in the desired state.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. The file system maps to modules (e.g., `mod foo` looks for `foo.rs` or `foo/mod.rs`). In Rust 2018, the "module system" was simplified, removing the requirement for `mod.rs` files in favor of `foo.rs` alongside a `foo/` directory.

**R18** — `Pin<T>` ensures that the data at a specific memory address will not move. This is critical for **self-referential structs** (common in `async` state machines) where a pointer inside the struct points to another field in the same struct. If the struct moved, the pointer would become invalid. `Unpin` is an auto-trait for types that are safe to move even when pinned.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching to expand code. **Procedural macros** act like functions that take code as input and output code (includes `derive`, `attribute`, and `function-like`). **Hygiene** ensures that macro-generated identifiers do not accidentally clash with variables in the scope where the macro is called.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use, and what you do use couldn't be implemented better by hand. **Iterators** are optimized into tight loops; **Generics** use **monomorphization** (generating specific code for each type used, enabling inlining); **Trait static dispatch** resolves calls at compile time, allowing the compiler to optimize across function boundaries.
