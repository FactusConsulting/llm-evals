## Go

**G1** — An **array** has a fixed size defined at compile time. A **slice** is a descriptor for a contiguous segment of an array (containing a pointer, length, and capacity). When `append` exceeds a slice's capacity, Go allocates a new, larger underlying array, copies the old elements, and returns a new slice pointing to this new memory.

**G2** — `var x int` declares a variable and initializes it to its zero value (`0`). `x := 0` is short-variable declaration, which declares and initializes in one step. You **cannot** use `:=` outside of a function body (at the package level).

**G3** — A **goroutine** is a lightweight execution unit managed by the Go runtime, not the OS. Unlike OS threads (which have large stacks and expensive context switches), goroutines start with small, growable stacks and are multiplexed onto OS threads. The **GMP model** consists of **G**oroutines, **M** (Machine/OS Thread), and **P** (Processor/Logical Context). **P** holds the local run queue and allows **M** to execute **G**s; this decoupling allows efficient work-stealing and prevents thread starvation.

**G4** — Channels are pipes for communication. An **unbuffered channel** requires both sender and receiver to be ready simultaneously (synchronous). A **buffered channel** allows sending without a receiver until the buffer is full (asynchronous up to capacity). Sending to a full buffered channel **blocks** the goroutine until a receiver removes an item.

**G5** — `context` manages cancellation signals and deadlines across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
resp, err := http.DefaultClient.Do(req) // Will fail if 100ms passes
```

**G6** — Go uses **implicit satisfaction**: if a type implements all methods of an interface, it satisfies it. Java/C# require explicit `implements` declarations. `interface{}` (or `any`) can hold any value because every type implements at least zero methods. It is **powerful** for generic data handling but **dangerous** because it bypasses type safety, requiring type assertions that can cause runtime panics.

**G7** — This is unsafe due to a **data race**. The Go memory model does not guarantee that writes to `data` or `ready` in one goroutine are visible to another without explicit synchronization. The compiler or CPU might reorder instructions or cache `ready` in a register. **Correct alternatives**: Use `sync.Mutex` to guard the variables or use `atomic.Bool` and `atomic.Value`.

**G8** — `sync.Mutex` is exclusive (one writer OR one reader). `sync.RWMutex` allows multiple concurrent readers but only one writer. Use `sync.Map` when you have a "read-heavy" workload with disjoint keys or frequent updates to existing entries to reduce lock contention. **Trade-off**: `sync.Map` is slower for standard use cases due to internal complexity but scales better under high concurrency for specific patterns.

**G9** — `go.mod` defines the module path and specific versions of dependencies. `go.sum` contains cryptographic hashes of dependencies to ensure integrity. `go mod tidy` removes unused dependencies and adds missing ones. **MVS** (Minimum Version Selection) selects the lowest version of a dependency that satisfies all constraints in the module graph, ensuring reproducible builds.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. **Gotcha**: Using `defer` inside a `for` loop can cause resource exhaustion (e.g., file descriptors) because the deferred calls don't execute until the *entire* function returns, not the loop iteration.

**G11** — A **pointer** holds the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `p := &User{Name: "Alice"}`.

**/G12** — `init()` runs automatically when the package is initialized, before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source code (within the same file) and after all variable initializations.

**G13** — `new(T)` allocates zeroed memory for a type `T` and returns a `*T` (pointer). `make(T, args)` initializes the internal data structures of built-in types (slices, maps, channels) and returns a `T` (the value itself).

**G14** — Errors are values. The `error` interface requires a `Error() string` method. The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error matches a specific error *value* (unwrapping wrapped errors), while `errors.As` checks if an error matches a specific *type*.

**G15** — **Map**: `map[K]V` (nil). **Slice**: `[]T` (nil). **Channel**: `chan T` (nil). **Struct**: `struct{...}` (zeroed fields).

**G1/G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one access is a write. The `-race` flag uses dynamic analysis to detect unsynchronized access.
*Example*: `count++` is not atomic.
*Fix*: Use `mu.Lock(); count++; mu.Unlock()` or `atomic.AddInt64(&count, 1)`.

**G17** — `select` waits on multiple channel operations. Unlike `switch` (which evaluates values), `select` evaluates communication readiness. If multiple cases are ready, one is chosen **pseudo-randomly**. A timeout is implemented using `time.After(duration)` as a case.

**G18** — **Escape analysis** determines if a variable can reside on the **stack** (fast, automatic cleanup) or must "escape" to the **heap** (slower, requires GC). The compiler checks if a variable's lifetime exceeds the function scope or if its size is unknown. Inspect via `go build -gcflags="-m"`. It matters because excessive heap allocation increases GC pressure and latency.

**G19** — `reflect.Type` represents the type metadata; `reflect.Value` represents the actual data. Reflection is computationally expensive due to runtime type checking and prevents many compiler optimizations. Use **code generation** (e.var/stringer) for performance-critical paths and **reflection** for generic libraries (like JSON encoders) where flexibility is required.

**G20** — `//go:embed` allows including static files in the binary. It supports single files, directories, and `embed.FS`. It interacts with `io/fs.FS` to provide a virtual file system. **Limitations**: You cannot embed files that are not part of the module or use relative paths outside the module.

/## Rust

**R1** — **Ownership** manages memory without a GC. Rules: 1. Each value has an owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is a "string slice," a pointer to a sequence of UTF-8 bytes (often in the binary or on the heap). Use `String` when you need to mutate or own the data; use `&str` in function signatures to allow the function to accept both `String` and `&str` (flexibility).

**R3** — **Borrowing** allows accessing data without taking ownership. **Rules**: You can have either **one** mutable reference (`&mut T`) OR **any number** of immutable references (`&T`) at a time, but never both simultaneously.

**R4** — `Result<T, E>` handles recoverable errors; `Option<T>` handles the presence/absence of a value. The `?` operator performs an early return if the result is an `Err` or `None`.
```rust
use std::fs;
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>`: Heap allocation with single ownership. `Rc<T>`: Reference-counted pointer for multiple ownership in a single thread. `Arc<T>`: Atomic reference-counted pointer for multiple ownership across threads (thread-safe).

**R6** — **Traits** are sets of methods (similar to interfaces). **Trait Object** (`dyn Trait`) uses dynamic dispatch (runtime lookup via vtable). **Generics** (`T: Trait`) use static dispatch (monomorphization at compile time), which is faster.

**R7** — It fails because the compiler cannot guarantee that the returned reference lives as long as the input references. **Fix**: Add a lifetime annotation: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8** — `Send` means a type can be transferred between threads. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send` because its reference count is not updated atomically, leading to data races. `Arc<T>` uses atomic operations, making it `Send` and `Sync`.

**R9** — A **Future** is a state machine that represents a computation that might not be finished yet. An **executor** (like Tokio) polls futures to drive them to completion. Unlike Go's goroutines (which are preemptively scheduled by a runtime), Rust's async is **cooperative** and "pull-based"—nothing happens unless the executor polls the future.

**R10** — `unsafe` allows: 1. Dereferencing raw pointers. 2. Calling unsafe functions/methods. 3. Accessing/modifying mutable static variables. It is justified when interfacing with C libraries (FFI) or implementing low-level data structures (like `Vec`) where the compiler cannot prove safety.

**R11** — **Pattern matching** is a way to branch code based on the structure of data. `if let` is "syntactic sugar" for a `match` with a single arm. The compiler enforces **exhaustiveness**, ensuring every possible pattern of an enum is handled.

**R12** — `[T; N]` is a fixed-size array on the stack. `Vec<T>` is a growable heap-allocated buffer. When capacity is exceeded, `Vec` allocates a new, larger block of memory, copies the elements, and deallocates the old block.

**R13** — Rust enums are **sum types** (can hold data in each variant). Unlike C/Java, they are much more powerful. `Option<T>` is an enum (`Some(T)` or `None`). Rust has no `null` to prevent null-pointer exceptions; you must explicitly handle the `None` case.

**R14** — `impl` defines methods for a type. `&self` (immutable borrow), `&mut self` (mutable borrow), and `self` (takes ownership). **Associated functions** (like `String::new()`) do not take `self` and are called via the type, similar to static methods.

**R15** — `#[derive]` automatically implements traits. Examples: `Debug` (printing), `Clone` (explicit duplication), `PartialEq` (equality), `Serialize` (conversion to data format). You cannot derive a trait if the underlying types do not also implement that trait.

**R16** — `Cow` (Clone-on-Write) is a smart pointer that is either borrowed or owned. It is useful when you want to avoid allocation unless you actually need to modify the data. Example: A function that returns a string slice unless it needs to perform a transformation, in which case it returns an owned `String`.

**R17** — `mod` declares a module; `use` brings paths into scope; `pub` makes items visible. The file system maps to modules (e.g., `mod foo` looks for `foo.rs`). In 2018, the "extern crate" requirement was removed, making module management much more intuitive.

**R18** — `Pin<T>` ensures that the data at a pointer does not move in memory. This is critical for **self-referential structs** (common in `async` state machines) where a pointer inside the struct points to another field within the same struct. `Unpin` is a marker trait for types that *can* be safely moved.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching to expand code. **Procedural macros** act like functions that take code as input and output new code (can be `derive`, `attribute`, or `function-like`). **Hygiene** ensures that macro-generated variables do not accidentally clash with variables in the calling scope.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use, and what you do use cannot be implemented more efficiently by hand. **Iterators** are optimized into tight loops; **Generics** use **monomorphization** (generating specific code for each type) to eliminate runtime dispatch; and **Trait static dispatch** allows the compiler to inline code, achieving C-like performance.
