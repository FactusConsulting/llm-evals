## Kubernetes

**K1** — **Deployment** manages stateless pods; it can scale and roll out updates seamlessly. **StatefulSet** manages stateful applications, providing stable, unique network identifiers (pod-0, pod-1) and ordered, persistent storage provisioning.

**K2** — A ClusterIP Service uses `kube-proxy` (via iptables or IPVS) to intercept traffic sent to the Service's Virtual IP (VIP) and perform DNAT (Destination Network Address Translation) to redirect the packet to the IP of a healthy backend pod.

**K/3** — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a request for storage by a user. **StorageClass** is a template that allows for dynamic provisioning of PVs. They relate as: User creates a PVC $\rightarrow$ StorageClass triggers the creation of a PV $\rightarrow$ PVC binds to the PV.

**K4** — 1. `kubectl logs <pod>` to check application errors/stack traces. 2. `kubectl describe pod <pod>` to check for Exit Codes (e.g., 137 for OOM) or Liveness Probe failures. 3. `kubectl exec` (if possible) to check internal file/config availability. 4. Check node-level events or container runtime logs (e.g., `journalctl -u docker`).

**K5** — CoreDNS provides service discovery via DNS names within the cluster. If CoreDNS pods are down, internal service resolution (e.g., `my-svc.my-namespace.svc.cluster.local`) fails, and pods cannot communicate via DNS names, though they can still communicate via direct IP.

**K6** — The scheduler uses two phases: **Filtering** (Predicates) removes nodes that don't meet requirements (e.g., insufficient CPU, Taints, NodeSelector). **Scoring** (Priorities) ranks remaining nodes. Factors include: **Resource Availability** (CPU/RAM), **Pod Affinity/Anti-affinity**, and **Image Locality** (is the image already on the node?).

**K7** — **Yes**, it will be scheduled because the node has 3.5GB used and 0.5GB (51/4096) remaining, which satisfies the 256Mi request. If it uses 600Mi, the pod will be **OOMKilled** because it exceeded its 512Mi limit.

**K8** — 1. External LB receives request $\rightarrow$ 2. Routes to Ingress Controller (NGINX) Pod $\rightarrow$ 3. NGINX matches Ingress rules $\rightarrow$ 4. NGINX looks up the **Endpoints** object (IPs of pods) $\rightarrow$ 5. NGINX forwards traffic to a Pod IP $\rightarrow$ 6. `kube-proxy` (iptables/IPVS) ensures the packet reaches the correct node/pod.

**K9** — A **NetworkPolicy** defines rules for allowed/denied traffic between pods. By default, if no policy exists, all pods can talk to all pods (Allow All). Once a policy is applied to a pod, that pod becomes "isolated," and only traffic explicitly permitted by the policy is allowed.

**K10** — **RollingUpdate** replaces pods one by one to ensure zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when the application does not support multiple versions running simultaneously (e.g., due to database schema incompatibility).

**K11** — A **Namespace** is a virtual cluster within a physical cluster used for isolation. Default namespaces: `default`, `kube-system`, `kube-pod-network.alpha.kubernetes.io` (legacy), and `kube-public`.

**K12** — It is used for deep inspection of a pod's state. It shows: **Container Status** (restarts, exit codes), **Events** (scheduling, pulling, mounting), and **Conditions** (Ready, Initialized, PodScheduled).

**K13** — A **ConfigMap** stores non-confidential configuration data. Methods: 1. **Environment Variables** (mapping keys to env vars). 2. **Volume Mounts** (mounting keys as files in a directory).

**K14** — **ClusterIP**: Internal-only IP. **NodePort**: Exposes the service on a static port on each Node's IP. **LoadBalancer**: Provisions an external cloud load balancer to route traffic to the service.

**K15** — A **DaemonSet** ensures a copy of a specific pod runs on all (or selected) nodes. Use it for background tasks like log collection (Fluentd), monitoring agents (Prometheus Node Exporter), or networking plugins (Calico).

**K16** — **Taints** are applied to **Nodes** to repel pods; **Tolerations** are applied to **Pods** to allow them to stay on tainted nodes. **Node Affinity** is applied to **Pods** to attract them to specific nodes. *Use Case*: Use Taints to keep GPU workloads on GPU nodes; use Affinity to ensure a web app runs on nodes with SSDs.

**K1/17** — An **Operator** is a custom controller that uses CRDs (Custom Resource Definitions) to manage complex, stateful applications. Unlike a standard controller (which manages generic objects like Pods), an Operator encodes "domain-specific" operational knowledge (e.g., how to perform a database backup or upgrade).

**K18** — etcd uses the **Raft** consensus algorithm (strong consistency). If quorum is lost, the cluster becomes read-only or fails. To recover from losing 2/3 nodes: You must restore from a recent snapshot onto a new 3-node cluster, effectively resetting the cluster state to the last known good snapshot.

**K19** — **Role/ClusterRole** define permissions (verbs/resources). **RoleBinding/ClusterRoleBinding** attach those permissions to a User/Group/ServiceAccount.
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: my-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: my-ns
subjects:
- kind: User
  name: "developer"
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — High `ndots` (default 5) causes the resolver to append search domains (e.g., `google.com.my-ns.svc.cluster.local`) for every query, resulting in multiple failed DNS lookups before the final query. **Fix**: Use `dnsConfig` in the Pod spec to set `ndots: 1` or use fully qualified domain names (FQDN) with a trailing dot (e.g., `google.com.`).

## Development

**D1** — **Merge** combines histories by creating a new "merge commit." **Rebase** moves the entire feature branch to begin on the tip of the main branch, creating a linear history. **Avoid rebasing** on public/shared branches, as it rewrites history and breaks other developers' local copies.

**D2** — **TCP** is connection-oriented, reliable, and guarantees order (e.g., HTTP, SSH). **UDP** is connectionless, faster, but unreliable/unordered (e.g., DNS, VoIP/Streaming).

**D3** — A race condition occurs when the outcome of a process depends on the unpredictable timing of threads/processes. *Example*: Two threads incrementing a shared integer `x = x + 1` simultaneously; both read `5`, both calculate `6`, and write `6`, losing one increment.

**D4** — **Symmetric**: Same key for encryption/decryption (fast). **Asymmetric**: Public/Private key pair (secure key exchange). In **TLS**, asymmetric encryption is used to securely exchange a "session key," which is then used with symmetric encryption for the actual data transfer.

**D5** — A layer is a read-only filesystem change. **Best Practice**: Order instructions from least-frequently changed to most-frequently changed. This maximizes **layer caching**, making builds faster by skipping unchanged steps.

**D6** — 1. **Application Logs** (check for crashes/errors). 2. **Upstream Dependencies** (is the DB or a microservice down?). 3. **Resource Exhaustion** (CPU/Memory/Disk on the server). 4. **Network/Load Balancer** (is the LB failing health checks?).

**D7** — **CAP Theorem**: A distributed system can only provide two of three: Consistency, Availability, or Partition Tolerance. **CP (Consistency/Partition)**: Google Spanner (prioritizes data integrity). **AP (Availability/Partition)**: Cassandra (prioritizes uptime/responsiveness).

**D8** — **Horizontal**: Adding more instances (nodes/pods). **Vertical**: Adding more resources (CPU/RAM) to an existing instance. **Patterns**: Statelessness, Load Balancing, and Sharding/Partitioning enable horizontal scaling.

**D9** — An environment variable is a dynamic value used by processes. To make it persistent in Linux, add `export VAR_NAME="value"` to your `~/.bashrc` or `~/.zshrc` file.

**D10** — **JSON** is data-oriented, uses braces/brackets, and is strict. **YAML** is human-readable, uses indentation, and is more flexible. **Advantage JSON**: Faster parsing/standard for APIs. **Advantage YAML**: Easier for humans to write/read configuration.

**D11** — **REST API**: An interface using HTTP. **GET**: Retrieve data. **POST**: Create data. **PUT**: Replace/Update data. **DELETE**: Remove data.

**D12** — Version pinning is specifying exact versions (e.g., `lib-x:1.2.3` instead of `lib-x:latest`). It is vital for **reproducible builds**, ensuring that a build today results in the same binary as a build six months from now.

**D13** — **Compiled**: Code is converted to machine code before execution (e.g., C++, Rust). **Interpreted**: Code is executed line-by-line by an interpreter (e.g., Python, JavaScript).

**D14** — A **Reverse Proxy** sits in front of web servers to handle requests (e.g., NGINX, HAProxy). A **Forward Proxy** sits in front of clients to handle outgoing requests (e.g., Squid). *Use Case*: NGINX for SSL termination/Load Balancing.

**D15** — A deadlock is a state where a set of processes are blocked because each is holding a resource and waiting for another. **Coffman Conditions**: 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual Consistency** means that if no new updates are made, all accesses will eventually return the last updated value. **Cassandra** uses "tunable consistency" via `ConsistencyLevel` (e.g., `ONE`, `QUORUM`, `ALL`). `QUORUM` ensures a majority of nodes acknowledge the write/read, providing a balance of speed and consistency.

**D17** — **mTLS** requires both client and server to present certificates to prove identity. **Handshake**: 1. Client sends "Hello" + Cipher suites. 2. Server sends Certificate + "Hello". 3. Client verifies Server Cert. 4. Client sends its own Certificate. 5. Server verifies Client Cert. 6. Key exchange occurs. **Usage**: Service Meshes (Istio/Linkerd) for Zero Trust networking.

**D18** — A hash table maps keys to indices via a hash function. **Collision Resolution**: **Chaining** (each bucket is a linked list) vs. **Open Addressing** (searching for the next empty slot). **Complexity**: Average: $O(1)$ for all. Worst Case: $O(n)$ (all keys hash to one bucket).

**D19** — A **Circuit Breaker** prevents a failing service from dragging down the whole system. **States**: **Closed** (normal, traffic flows), **Open** (failure detected, traffic blocked immediately), **Half-Open** (testing if the service recovered). It prevents **cascading failures** by failing fast, rather than letting requests pile up and exhaust resources. It works with **Exponential Backoff** to ensure retries don't overwhelm the recovering service.

**D20** — **Optimistic**: Assumes no conflict; checks for changes before committing (uses version/timestamp). **Pessimistic**: Assumes conflict; locks the resource (e.g., `SELECT FOR UPDATE`) until the transaction ends. **Choose Optimistic** for high-concurrency, low-contention systems. **Choose Pessimistic** for high-contention systems where the cost of a rollback is too high.
