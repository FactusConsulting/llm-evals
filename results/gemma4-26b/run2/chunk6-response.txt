## JavaScript / TypeScript

**JS1**
`var` is function-scoped and can be redeclared; `let` and `const` are block-scoped. `const` prevents reassignment of the identifier (though object properties can change). **Hoisting** is the behavior where variable and function declarations are moved to the top of their scope during compilation. `var` is initialized as `undefined`, while `let`/`/const` are hoisted but remain in a "Temporal Dead Zone" until the line of declaration is reached.

**JS2**
The **Event Loop** manages execution. The **Call Stack** tracks the currently executing function. The **Microtask Queue** (Promises, `process.nextTick`) is processed immediately after the current task and before the next macrotask. The **Macrotask Queue** (setTimeout, setInterval, I/O) handles larger tasks. The loop: 1. Execute one macrotask. 2. Execute all microtasks. 3. Render (if browser). 4. Repeat.

**JS3**
A **closure** is a function that retains access to its lexical scope even when executed outside that scope. 
*Example:* `function outer(x) { return () => x; }`. 
*Bug:* Using `var` in a `for` loop with a `setTimeout` causes all callbacks to see the final value of the loop variable. 
*Fix:* Use `let` (which creates a new binding per iteration) or an IIFE to capture the current value.

**JS4**
**Promise**: An object representing the eventual completion/failure of an async operation. **async/await** is syntactic sugar over Promises. Error handling: `try/catch` works with `await`; with raw Promises, use `.catch()`. 
**Promise.all**: Rejects immediately if *any* promise fails. 
**Promise.allSettled**: Waits for all promises to finish, regardless of whether they fulfilled or rejected, returning an array of state objects.

**JS5**
**Interface**: Defines the shape of an object; supports "declaration merging" (adding properties to the same interface later). Use for API contracts. 
**Type**: More versatile; supports unions, primitives, and intersections. Use for complex logic/aliases. 
**Discriminated Unions**: A pattern where multiple types share a common literal property (a "discriminant") to allow type-safe narrowing in `switch` or `if` statements.

**JS6**
**Prototypal Inheritance**: Objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with the specified `proto` as its internal `[[Prototype]]`. **ES6 Classes** are "syntactic sugar" over prototypes; they don't introduce a new inheritance model but provide a cleaner syntax for constructor functions and prototype manipulation.

**JS7**
`this` refers to the execution context. 
**Binding Rules (Priority):** 1. `new` binding (constructor), 2. Explicit binding (`call`/`apply`/`bind`), 3. Implicit binding (object method), 4. Default binding (global/undefined). 
`bind()` returns a **new function** with a fixed `this`. You **cannot** re-bind a function once it has been bound.

**JS8**
**WeakRef** allows holding a reference to an object without preventing garbage collection (GC). **FinalizationRegistry** triggers a callback when an object is GC'd. Use them for metadata/caches that shouldn't cause memory leaks. 
**WeakMap** keys must be objects because if keys were primitives, they couldn't be tracked for GC, and the map would prevent the key from being collected, causing a leak.

**JS9**
V8 uses **Hidden Classes** (shapes) to optimize property access. **Inline Caching** (IC) remembers where properties were found in previous lookups. **Deoptimization** occurs when code assumptions fail (e.g., a function receiving a different object shape than before). 
*Patterns causing deoptimization:* Changing the order of property assignments, adding/deleting properties dynamically, or passing different types to a monomorphic function.

**JS10**
**Tree-shaking** is dead-code elimination. **ES Modules** (ESM) use static `import/export` statements, allowing tools to determine which exports are unused at build time. **CommonJS** (CJS) uses `require()`, which is dynamic (you can wrap it in an `if` statement), making it impossible for static analysis tools to guarantee a module is unused.

**JS11**
`null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion (e.\_`null == undefined` is true); `===` checks both value and type. 
**Nullish coalescing (`??`)** returns the right side only if the left is `null` or `undefined`. 
**Optional chaining (`?.`)** short-circuits and returns `undefined` if the reference is nullish.

**JS12**
`map()`: transforms every element. `filter()`: returns elements passing a test. `reduce()`: accumulates values into a single result. 
**Initial Value**: If provided, `reduce` starts with it; if not, it uses the first element of the array as the accumulator. 
**flatMap()**: Maps each element using a mapping function and then flattens the result by one level. Useful for handling 1-to-many transformations.

**JS13**
**Template Literals** use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). 
**Tagged Templates** are functions that parse the template literal. 
*Example:* `function sql(strings, ...values) { return sanitize(strings, values); }`. This allows custom logic (like escaping) to run on the string components before they are joined.

**JS1/JS14**
**Destructuring** extracts data from arrays/objects into variables. 
*Object:* `const {name} = user;` 
*Array:* `const [first] = list;` 
*Default:* `const {role = 'user'} = user;` 
*Renaming:* `const {name: userName} = user;` 
**Rest operator (`...`)** collects remaining properties/elements into a new array/object.

**JS15**
`for...in` iterates over **enumerable property names** (keys) of an object. `for...of` iterates over **iterable values** (elements) of a collection. 
*Avoid `for...in` on arrays* because it iterates over indices as strings and includes inherited enumerable properties, which can lead to unexpected behavior.

**JS16**
**Generics** allow components to work with multiple types. 
**Constraints (`extends`)**: `function identity<T extends string>(arg: T)` ensures `T` is a string. 
**Conditional Types**: `T extends U ? X : Y` returns `X` if true. 
**`infer`**: Used in conditional types to "extract" a type. 
*Example:* `type Unpack<T> = T extends Array<infer U> ? U : T;` (extracts the element type of an array).

**JS17**
**CommonJS**: Node.js default, synchronous, uses `require`. 
**ES Modules**: Standard, asynchronous/static, uses `import`. 
Node.js handles both via the `package.json` `"type": "module"` field. If set, `.js` files are treated as ESM; if omitted, they are CJS.

**JS18**
**Structural Typing**: If two objects have the same shape, they are compatible. 
**Excess Property Checks**: Apply only to object literals assigned directly to a type. 
**`extends` vs `satisfies`**: `extends` checks if a type matches a shape; `satisfies` checks if a value matches a type *without* widening the type (preserving the specific shape). 
**Variance**: `in` (contravariance) refers to function arguments; `out` (covariance) refers to function return values.

**JS19**
**Proxy** intercepts operations on an object (get, set, etc.). **Reflect** provides methods to perform the default behavior of those operations. 
*Example:* `const p = new Proxy(target, { get(t, prop) { console.log(prop); return Reflect.get(t, prop); } });` This is used for reactive frameworks (like Vue 3) to detect property changes.

**JS20**
**SharedArrayBuffer** allows multiple threads (Workers) to share a single chunk of raw binary memory. **Atomics** provides static methods to perform thread-safe operations (like `add`, `load`, `store`) to prevent race conditions. 
**Communication**: Workers use `postMessage` for messages, but for shared memory, they use `Atomics.wait` (to sleep until a value changes) and `Atomics.notify` (to wake up a waiting thread).

/## Bash

**B1**
`$@` and `$*` both represent all command-line arguments. 
`"$*"` expands to a single string `"arg1 arg2 arg3"`. 
`"$@"` expands to separate strings `"arg1" "arg2" "arg3"`. Always use `"$@"` to preserve word splitting.

**B2**
`set -euo pipefail`: 
`-e`: Exit immediately if a command fails. 
`-u`: Treat unset variables as an error. 
`-o pipefail`: The return value of a pipeline is the status of the last command to exit with a non-zero status.

**B3**
`$(command)` is command substitution (executes command and captures output). 
`` `command` `` is the older, deprecated version of the same. 
`$((expression))` is arithmetic expansion (e.g., `$((1+1))`). 
`expr` is an external utility for math (slower and more cumbersome).

**B4**
**Process Substitution** `<(command)` treats the output of a command as a file. 
*Example:* `diff <(ls dir1) <(ls dir2)` compares the contents of two directories without creating temporary files.

**B5**
Use `while IFS= read -r f; do ... done < <(find . -print0 | xargs -0)` or globbing `for f in ./*; do`. 
`for f in $(ls)` is dangerous because `ls` output is split by whitespace, breaking filenames containing spaces or newlines.

**B6**
**Here Doc** (`<<EOF`): Multi-line input. 
**Here String** (`<<<`): Passes a single string to a command. 
`<<-EOF` (with a hyphen) strips **leading tabs** from the input, allowing for cleaner indentation in scripts.

**B7**
1. `cmd > file 2>&1`: Redirects stdout to `file`, then redirects stderr to the same place as stdout. (Result: both go to file).
2. `cmd 2>&1 > file`: Redirects stderr to stdout (which is still the terminal), then redirects stdout to `file`. (Result: stderr goes to terminal, stdout goes to file).
3. `cmd &> file`: Shorthand for `cmd > file 2>&1`.

**B8**
```bash
lockfile="/tmp/my.lock"
mkdir "$lockfile" || exit 1
trap 'rmdir "$lockfile"; exit' INT TERM EXIT
```
`mkdir` is atomic at the OS level; if two processes try to `mkdir` the same path, only one succeeds. File creation (`> file`) is not atomic and can suffer from race conditions.

**B9**
`'...'`: Single quotes. Literal string, no expansion. 
`"..."`: Double quotes. Allows variable expansion and command substitution. 
`no quotes`: Allows word splitting and globbing. 
*Example:* `echo "$VAR"` (prints value) vs `echo '$VAR'` (prints `$VAR`) vs `echo $VAR` (may break if $VAR contains spaces).

**B10**
`-e` (exists), `-d` (directory), `-r` (readable). 
`[ ]` (test) is the standard POSSH command; `[[ ]]` is a Bash keyword that is more powerful, supports regex (`=~`), and handles empty variables/logical operators more safely without word splitting.

**B11**
`$?`: Exit status of last command. 
`$$`: PID of the current shell. 
`$!`: PID of the last background process. 
`$#`: Number of positional parameters.

**B12**
`foo() { ... }` is the standard/portable way. `function foo { ... }` is a Bash-specific extension. 
To return values, use `echo` or `printf` and capture it via `result=$(foo)`, or use a global variable. `return` only sets the exit status (0-255).

**B13**
`PATH` is a colon-separated list of directories. Bash searches these directories in order for an executable. 
**Builtin**: Part of the shell (e.g., `cd`). 
**External**: A separate file on disk (e.g., `ls`). 
Check with `type <command>` (e.g., `type cd` vs `type ls`).

**B14**
`trap` intercepts signals. 
`trap 'cleanup' EXIT ERR INT TERM`. 
If multiple signals arrive, they are handled sequentially. If a signal is not caught, the default action (usually termination) occurs.

**/B15**
`xargs` takes items from stdin and turns them into arguments for a command. 
`find -print0 | xargs -0` uses the null character as a delimiter, preventing filenames with spaces/newlines from being split. 
`xargs -P <N>` runs up to N processes in parallel.

**B16**
**Arrays**: `arr=(a b c)`. Append: `arr+=(d)`. Iterate: `for i in "${arr[@]}"`. Length: `${#arr[@]}`. 
**Associative Arrays**: `declare -A map`. `map[key]=val`. Iterate: `for k in "${!map[@]}"`. 
Associative arrays allow string keys; standard arrays only allow integer indices.

**B17**
**Subshell** `(...)`: Creates a new process; variables changed inside do not affect the parent. 
**Group Command** `{ ...; }`: Executes in the current shell; variables changed persist. 
**Piping into `while`**: The `while` loop runs in a subshell, so any variable updates inside the loop are lost when the loop finishes.

**B18**
`SIGINT` (Ctrl+C), `SIGTERM` (Request stop), `SIGHUP` (Terminal closed), `SIGKILL` (Immediate kill, cannot be caught). 
For graceful shutdown: Trap `SIGTERM`, then send `SIGKILL` to background processes only after they have finished their cleanup logic.

**B19**
*Logic:* `split -l 1000 log.txt part_`; `ls part_* | xargs -P 4 -I {} bash -c 'process_func {}'`; `cat part_* > merged.log`. 
*Trade-offs:* Parallelism speeds up processing but increases CPU/IO load. 
*Error propagation:* Use `set -e` in the processing function and check exit codes in the main script.

**B20**
`exec` replaces the current shell process with the new command. 
**FD manipulation**: `exec 3>file` opens FD 3 for writing to `file`. `exec 3>&-` closes FD 3. 
**Coprocess**: `coproc myproc`. It allows bidirectional communication via pipes. Use it for long-running background tasks that need to exchange data with the main script.

## PowerShell

**PS1**
`Write-Output` sends objects to the pipeline (can be captured). `Write-Host` writes directly to the host (console) and cannot be captured by a pipeline. This matters because `Write-Host` breaks automation/redirection.

**PS2**
**Pipeline**: Objects are passed one by one. 
**`ForEach-Object`**: A cmdlet that processes objects in the pipeline. 
**`foreach` statement**: A language keyword that iterates over a collection in memory. 
Use `foreach` for small collections (faster); use `ForEach-Object` for large streams to keep memory usage low.

**PS3**
**`[PSCustomObject]`**: An ordered collection of properties; ideal for structured data. 
**`[hashtable]`**: An unordered collection of key-value pairs. 
Use `[PSCustomObject]` for output/data models. Convert via `[PSCustomObject]$myHash`.

**PS4**
**Terminating**: Stops execution (e.g., `throw`). 
**Non-terminating**: Continues execution (e.g., `Write-Error`). 
`try/catch` only catches terminating errors unless `$ErrorActionPreference = 'Stop'` is set. `-ErrorAction` overrides this on a per-cmdlet basis.

**PS5**
**Splatting** (`@params`) passes a hashtable as arguments to a command. 
*Example:* `$p = @{Path='C:\'; Filter='*.txt'}; Get-ChildItem @p`. 
It is cleaner than long command lines and avoids messy escaping.

**PS6**
**`Invoke-Command -ComputerName`**: Runs a command on a remote machine (one-to-many). 
**`Enter-PSSession`**: Interactive-style remote shell (one-to-one). 
Uses **WS-Man** (WinRM) or **SSH**.

**PS7**
The function returns an array, but because of PowerShell's "unrolling" behavior, if the function returns a single object, `$x` becomes a `[System.String]`. If it returns multiple, it's an `[Object[]]`. 
*Correct pattern:* Always cast the result: `[array]$x = Get-Items`.

**PS8**
**`[scriptblock]`**: A block of code that can be executed later. 
**Double-hop**: When you run a command on Remote A, and that command tries to access Resource B, the credentials don't "hop" to B. 
*Solution:* Use **CredSSP** or **Kerberos Delegation**.

**PS9**
`@()` is an empty array; `[array]` is a type. 
To force a single result into an array: `@($result)`. 
Indexing `$null` throws an error; indexing an empty array returns `$null`.

**PS10**
`-eq` (case-insensitive), `-ceq` (case-sensitive). 
`-like` (wildcard `*`), `-match` (regex `~`). 
`-contains` checks if a collection contains a value; `-in` checks if a value exists within a collection.

**PS11**
**`.psm1`**: Script module (contains functions/logic). 
**`.psd1`**: Manifest (metadata/versioning). 
**Binary**: Compiled DLL. 
`Import-Module` loads the module into the current session.

**PS12**
`"..."` (Double quotes) allows variable expansion: `"Hello $name"`. 
`'...'` (Single quotes) is literal: `'Hello $name'`. 
**Here-string**: `@"` ... `"@` (must start on a new line).

**PS13**
**`Get-Member`**: Shows properties/methods of an object. 
**Properties**: Data values. **Methods**: Actions. **NoteProperties**: Custom properties added via `Select-Object`. 
`Select-Object` picks specific properties; `Where-Object` filters objects based on criteria.

**PS14**
**PowerShell Classes** are more restrictive than C# (no full support for all C# features like complex generics). 
Use **Classes** for complex data structures/OOP; use **Functions** for procedural logic/tasks.

**PS15**
`[CmdletBinding()]` makes a function behave like a professional cmdlet (adds `-Verbose`, `-ErrorAction`, etc.). 
**`SupportsShouldProcess`**: Enables `-WhatIf`. 
**`ValueFromPipeline`**: Allows input via `|`. 
**`Begin/Process/End`**: `Begin` runs once, `Process` runs for every object in the pipeline, `End` runs once at the end.

**PS16**
**Providers** allow different data stores to be treated as file systems. 
`Get-ChildItem Registry::HKEY_LOCAL_MACHINE\Software` works just like `Get-ChildItem C:\`.

**PS17**
**Runspace**: A single thread of execution. **RunspacePool**: A collection of reusable runspaces. 
`ForEach-Object -Parallel` (v7) is a high-level abstraction that manages a thread pool for you, making it much easier than manual `[runspacepool]` management.

**PS18**
**PSScriptAnalyzer** is a static code analysis tool. 
It uses **Rules** (e.g., `AvoidUsingWriteHost`). 
**Severity**: Error, Warning, or Info. 
**Suppression**: Use `# PSAvoidUsingWriteHost` in code. 
**CI/CD**: Run `Invoke-ScriptAnalyzer` as a build step to fail builds that violate standards.

**PS19**
`$using:var` is required to pass a local variable into a remote/parallel scope. 
**Serialization**: When passing objects across boundaries (Remote/Jobs), they are converted to **CLIXML**. Complex objects (like open file handles or active database connections) lose their "live" state and become "dead" (data-only) objects.

**PS20**
**DSC** uses **Configurations** (code) to define the state of a machine. 
**Resources** are the building blocks (e.g., `File`, `Registry`). 
**LCM (Local Configuration Manager)** is the engine on the target machine that enforces the state. 
In modern infra, **DSC** is often replaced by **Terraform** or **Ansible** for orchestration, though DSC is still used for deep OS configuration.
