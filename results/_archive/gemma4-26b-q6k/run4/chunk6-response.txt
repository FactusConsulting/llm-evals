## JavaScript / TypeScript

**JS1** — `var` is function-scoped and can be re-declared; `let` and `const` are block-scoped. `const` prevents reassignment of the identifier. **Hoisting** is the behavior where variable and function declarations are moved to the top of their scope during compilation. `var` is initialized as `undefined`, while `let`/`const` are in a "Temporal Dead Zone" until reached.

**JS2** — The **Event Loop** manages asynchronous execution. The **Call Stack** executes synchronous code. When an async operation finishes, its callback enters the **Microtask Queue** (Promises) or **Macrotask Queue** (setTimeout). The loop checks the Microtask queue after every task in the Call Stack; if empty, it pulls one task from the Macrotask queue.

**JS3** — A **closure** is a function that remembers its lexical scope even when executed outside that scope. *Example:* `function outer() { let x = 10; return () => x; }`. The **classic loop bug**: `for (var i=0; i<3; i++) { setTimeout(() => console.log(i), 1); }` prints `3,3,3` because `var` is function-scoped. **Fix**: Use `let` (block-scoped) or an IIFE.

**JS4** — `Promise` represents an eventual value. `async/await` is syntactic sugar for Promises. `async` functions return Promises; `await` pauses execution until the Promise settles. **Error handling**: `try/catch` works with `await`; `.catch()` works with raw Promises. `Promise.all` rejects if *any* fail; `Promise.allSettled` waits for *all* to finish regardless of outcome.

**JS5** — `interface` is primarily for defining object shapes and supports declaration merging. `type` is for aliases, unions, and primitives. Use `interface` for public APIs/objects; use `type` for complex logic/unions. **Discriminated unions** use a common literal property (e.g., `{ type: 'A', val: 1 } | { type: 'B' }`) to allow type narrowing in `switch` statements.

**JS6** — **Prototypal inheritance** means objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with `proto` as its prototype. **ES6 classes** are "syntactic sugar" over prototypes; they don't introduce a new inheritance model but use the same underlying prototype chain.

**JS7** — `this` refers to the object executing the current function. **Binding Rules**: 1. `new` binding (constructor), 2. Explicit binding (`call`/`apply`/`bind`), 3. Implicit binding (object method), 4. Default (global/undefined). `bind()` returns a **new function** with a fixed `this`; it cannot be re-bound.

**JS8** — `WeakRef` allows holding a reference to an object without preventing GC. `FinalizationRegistry` runs a callback when an object is GC'd. **WeakMap** keys must be objects because they are held "weakly"; if the only reference to the key is the WeakMap itself, the key (and value) can be garbage collected, preventing memory leaks.

**JS9** — V8 uses **Hidden Classes** (shapes) to optimize property access. **Inline Caching** remembers where properties are in memory. **Deoptimization** occurs when the engine's assumptions fail (e.g., changing an object's shape by adding properties later). Patterns causing deoptimization: changing types in a loop or adding properties to objects after initialization.

**JS10** — **Tree-shaking** removes unused code. It works with **ES Modules** (`import/export`) because they are static. **CommonJS** (`require`) is dynamic; the engine cannot know what will be required until runtime, making it impossible to safely determine if a module is unused without executing it.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable was declared but not assigned. `==` performs type coercion; `===` checks type and value. **Nullish coalescing** (`??`) returns the right side only if the left is `null` or `undefined`. **Optional chaining** (`?.`) short-circuits if the reference is `null`/`undefined`.

**JS12** — `map()` transforms elements; `filter()` selects elements based on a predicate; `reduce()` accumulates elements into a single value. `reduce` uses an initial value to prevent errors on empty arrays. `flatMap()` maps then flattens one level, useful for handling functions that return arrays.

**JS13** — **Template literals** use backticks (`` ` ``). **Tagged templates** allow a function to parse the template literal. *Example:* `sql`tag`SELECT * FROM users` allows the `sql` function to sanitize inputs to prevent injection.

**JS14** — **Destructuring** extracts values. *Object*: `const {a, b} = obj;`. *Array*: `const [x, y] = arr;`. *Default*: `const {a = 1} = obj;`. *Renaming*: `const {old: newName} = obj;`. **Rest operator** (`...`) gathers remaining elements into a new array/object.

**JS15** — `for...in` iterates over **enumerable properties** (keys) of an object. `for...of` iterates over **iterable values** (elements) of an array. Avoid `for...in` on arrays because it iterates over indices as strings and includes inherited properties.

**JS16** — **Generics** allow reusable components. **Constraints**: `T extends U` (T must be a subtype of U). **Conditional Types**: `T extends string ? number : boolean`. **Infer**: `type GetReturn<T> = T extends (...args: any[]) => infer R ? R : any`.

**JS17** — **CommonJS** uses `require`/`module.exports` (synchronous, runtime). **ESM** uses `import`/`export` (asynchronous, static). Node.js handles both via file extensions or the `"type": "module"` field in `package.json`.

**JS18** — **Structural typing** means if it looks like a duck, it is a duck. **Excess property checks** occur during direct object literals. `extends` is for subtyping; `satisfies` (TS 4.9+) validates a type without changing the inferred type of the variable. **Variance**: `in` (contravariant) for function arguments, `out` (covariant) for return values.

**JS19** — **Proxy** wraps an object to intercept operations. **Reflect** provides methods for the same operations (e.g., `Reflect.get`). *Example*: A Proxy can intercept `set` to validate that a property is a string before allowing the assignment.

**JS20** — `SharedArrayBuffer` allows multiple threads (Workers) to access the same memory. **Atomics** provides static methods to perform thread-safe operations (e.g., `Atomics.add`). `Atomics.wait` puts a thread to sleep until `Atomics.notify` is called, preventing race conditions.

## Bash

**B1** — `$@` is all arguments as separate words; `$*` is all arguments as a single string. `"$@"` preserves word boundaries (safe); `"$*"` joins them with the first character of `IFS`.

**B2** — `set -e` (exit on error), `-u` (error on unset variables), `-o pipefail` (return non-zero if any command in a pipe fails).

**B3** — `$(command)` is command substitution (executes and returns output). `` `command` `` is the older syntax. `$((expression))` is arithmetic expansion. `expr` is an external command for math.

**B4** — **Process substitution** `<(command)` treats the output of a command as a file. *Example*: `diff <(ls dir1) <(ls dir2)` compares the output of two commands without creating temp files.

**B5** — Use `while IFS= read -r f; do ... done < file` or `find ... -print0 | xargs -0`. `for f in $(ls)` is dangerous because it splits on whitespace, breaking names with spaces.

**B6** — `<<EOF` is a **here document** (multi-line string). `<<<` is a **here string** (single string). `<<-EOF` strips leading **tabs** from the lines in the document.

**B7** — `> file 2>&1` redirects stdout to file, then redirects stderr to where stdout is currently pointing (the file). `2>&1 > file` redirects stderr to stdout, then redirects stdout to a file (stderr goes to the terminal). `&> file` is a shorthand for both.

**B8** — Use `mkdir` for locking because `mkdir` is an **atomic** operation at the OS level; if two processes try to `mkdir` the same folder, only one succeeds.
```bash
lockdir="/tmp/mylock"
trap 'rmdir "$lockdir" 2>/dev/null' EXIT INT TERM
if mkdir "$lockdir"; then
  # critical section
  rmdir "$lockdir"
else
  echo "Locked" && exit 1
fi
```

**B9** — `'...'` (literal, no expansion), `"..."` (allows `$VAR` and `` ` ``), no quotes (word splitting and globbing occur). *Example*: `echo '$USER'` prints `$USER`; `echo "$USER"` prints `john`.

**B10** — `[ -f file ]` (file), `[ -d dir ]` (dir), `[ -r file ]` (readable). `[[ ]]` is a bash keyword that is more powerful, handles `&&`/`||` internally, and doesn't require quoting variables to prevent errors.

**B11** — `$?` (exit status of last command), `$$` (PID of current shell), `!` (PID of last background job), `$#` (number of arguments).

**B12** — `foo() { ... }` is the standard POSIX way. `function foo {}` is a bashism. Functions return an **exit status** (0-255) via `return`, not a string value. Use `echo` to "return" strings.

**B13** — `PATH` is a colon-separated list of directories. Bash searches them in order. **Builtin** (e.g., `cd`) is part of the shell; **External** (e.g., `ls`) is a file on disk. Use `type -a command` to check.

**B14** — `trap` catches signals. `trap 'cleanup' EXIT INT TERM`. Order: `EXIT` is always last. If multiple arrive, they are handled sequentially.

**B15** — `xargs` takes stdin and turns it into arguments. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P N` runs N processes in parallel.

**B16** — `arr=(a b c)`. Append: `arr+=(d)`. Iterate: `for i in "${arr[@]}"`. Length: `${#arr[@]}`. **Associative**: `declare -A map=( [key]=val )`.

**B17** — `(...)` creates a **subshell** (new PID, new variable scope). `{ ...; }` is a **group command** (same shell, same scope). Piping into `while` creates a subshell, so variable changes inside the loop are lost to the parent.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (Polite kill), `SIGHUP` (Terminal closed), `SIGKILL` (Immediate/Unstoppable). For graceful shutdown, use `trap` to catch `TERM` and kill child PIDs.

**B19** — Use `split` to break log, `xargs -P` to run a function on chunks, then `cat` or `awk` to merge. *Trade-off*: Parallelism increases speed but complicates error tracking and requires more CPU/IO.

**B20** — `exec` replaces the current shell with the new process. `exec 3>file` opens FD 3 for writing. `exec 3>&-` closes it. A **coprocess** (`coproc`) allows bidirectional communication with a background process via pipes.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the console (UI). `Write-Host` cannot be captured by redirection or pipelines.

**PS2** — `ForEach-Object` is a cmdlet used in a pipeline (streaming). `foreach` is a language keyword (faster, processes the whole collection at once). Use `foreach` for in-memory arrays; `ForEach-Object` for large streams.

**PS3** — `[PSCustomObject]` is an ordered collection of properties (best for data). `[hashtable]` is an unordered key-value pair. Convert: `[PSCustomObject]$obj = [ordered]@{a=1}`.

**PS4** — **Terminating** errors stop execution; **non-terminating** continue. `try/catch` only catches terminating errors. Use `-ErrorAction Stop` to turn non-terminating errors into terminating ones.

**PS5** — **Splatting** passes a hashtable as arguments: `$p = @{Name="A"; Age=1}; Get-User @p`. This is cleaner than passing many individual parameters.

**PS6** — `Invoke-Command` runs on remote machines. `Enter-PSSession` is interactive. Both use **WS-Man** (WinRM) or **SSH**.

**PS7** — The function returns an array, but `$x.GetType().Name` will be `Object[]`. If 0 items, it might be `$null`. The correct pattern is to initialize `$result = [System.Collections.Generic.List[object]]::new()` to ensure it remains an object/array.

**PS8** — A `[scriptblock]` is a piece of code. Pass via `-ArgumentList`. The **double-hop** problem occurs when a remote session tries to access a *third* machine. Solve with **CredSSP** or **Kerberos Delegation**.

**PS9** — `@()` is an array literal. `[array]` is a type. To force a single result into an array, use `@($result)`. Indexing `$null` returns `$null`; indexing an empty array returns `$null`.

**PS10** — `-eq` (equality), `-like` (wildcard), `-match` (regex). `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection. `-ceq` is case-sensitive.

**PS11** — `.psm1` is a script module. `.psd1` is a manifest (metadata). Binary modules are compiled DLLs. `Import-Module` loads them into the session.

**PS12** — `"Hello $name"` (interpolation). `'Hello $name'` (literal). Use `$()` for expressions: `"Result: $($1+1)"`. Here-strings: `@' ... '@` (literal) or `@" ... "@` (interpolated).

**PS13** — `Get-Member` shows properties/methods. `Select-Object` picks specific properties; `Where-Object` filters based on logic.

**PS14** — PowerShell classes are closer to C# but lack full features like interfaces (until recently) or complex generics. Use classes for structured data/logic; functions for simple tasks.

**PS15** — `[CmdletBinding()]` makes a function "advanced" (adds `-Verbose`, `-ErrorAction`, etc.). `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` allow streaming logic.

**PS16** — Providers allow treating Registry (`Registry::HKEY_LOCAL_MACHINE\...`) or Environment variables as drives.

**PS17** — `ForEach-Object -Parallel` (v7) is a high-level wrapper. Manual **Runspaces** provide granular control over a `RunspacePool` for high-performance multi-threading.

**PS18** — `PSScriptAnalyzer` is a static code analysis tool. It uses rules to check for best practices. Suppress via `# PSScriptAnalyzer -DisableRule`.

**PS19** — Use `$using:var` to pass local variables into a remote scope. Serialization limits (CLIXML) mean complex objects (like open file handles) cannot be passed across sessions.

**PS20** — **DSC** uses a **Local Configuration Manager (LCM)** to ensure a machine stays in a "Desired State." It uses **Resources** to define that state. Modern IaC (Terraform/Ansible) has largely superseded it for cloud/multi-platform orchestration.
