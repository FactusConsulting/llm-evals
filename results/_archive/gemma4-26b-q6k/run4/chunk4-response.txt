## Go

**G1** — An **array** has a fixed size defined at compile time. A **slice** is a descriptor (header) containing a pointer to an underlying array, a length, and a capacity. When `append` exceeds capacity, Go allocates a new, larger underlying array (usually doubling it for small slices), copies the old elements, and returns a new slice header.

**G2** — `var x int` declares a variable with its **zero value** (0). `x := 0` is **short variable declaration**, which declares and initializes in one step. You **cannot** use `:=` outside of function bodies (at the package level).

**G3** — A **goroutine** is a lightweight, user-space thread managed by the Go runtime. Unlike OS threads (which have large stacks and high context-switch costs), goroutines start with small stacks (~2KB) that grow dynamically. The **GMP model** consists of **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts). The scheduler maps $G$s onto $M$s via $P$s to ensure efficient CPU utilization and work-stealing.

**G4** — **Channels** are pipes for communication between goroutines. An **unbuffered** channel requires both sender and receiver to be ready simultaneously (synchronous). A **buffered** channel allows sending up to its capacity before blocking. Sending to a **full** buffered channel blocks the sender until a receiver takes a value.

**G5** — `context` manages cancellation, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

**G6** — Go uses **implicit satisfaction**: a type satisfies an interface simply by implementing its methods. Unlike Java/C#, there is no `implements` keyword. `interface{}` (or `any`) is an empty interface that can hold any value. It is powerful for generic-like behavior but dangerous because it bypasses type safety, requiring runtime type assertions.

**G7** — This is unsafe due to **memory visibility** issues; the compiler/CPU may reorder instructions or cache `ready` in a register, so the loop might never see `ready` change. Correct alternatives: use `sync/atomic` for the boolean or, more idiomatically, use a `sync.Mutex` or a channel to establish a "happens-before" relationship.

**G8** — `sync.Mutex` is exclusive (one holder). `sync.RWMutex` allows multiple concurrent readers OR one exclusive writer. Use `sync.Map` for high-concurrency scenarios with many reads and few writes, or when keys are stable. A regular map + `Mutex` is faster for most general cases and heavy write workloads.

**G9** — `go.mod` defines the module path and dependencies. `go.sum` contains cryptographic hashes of dependencies to ensure integrity. `go mod tidy` removes unused modules and adds missing ones. **MVS** selects the *minimal* version required by the dependency graph to ensure reproducible builds.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO** (Last-In, First-Out) order. A common gotcha in a loop is defining `defer` inside the loop; it won't execute until the *function* ends, potentially causing resource exhaustion (e.g., leaking file descriptors).

**G11** — A **pointer** holds the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs automatically when a package is initialized. A package can have multiple `init()` functions, which execute in the order they appear in the source code.

**G13** — `make` initializes built-in types (slice, map, channel) and returns an initialized object ready for use. `new` allocates zeroed memory for any type and returns a pointer (`*T`).

**G14** — Errors are values. The `error` interface has one method: `Error() string`. Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks for specific error values (unwrapping wrapped errors), while `errors.As` checks if an error matches a specific type.

**G15** — **Map**: `nil`. **Slice**: `nil`. **Channel**: `nil`. **Struct**: All fields set to their respective zero values.

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one is a write. The `-race` flag uses a detector to find unsynchronized access. 
*Fix:* `mu.Lock(); count++; mu.Unlock()` or `ch <- 1`.

**G17** — `select` lets a goroutine wait on multiple channel operations. Unlike `switch`, it is used for communication. If multiple cases are ready, one is chosen pseudo-randomly. Timeout: `case <-time.After(time.Second):`.

**G18** — **Escape analysis** determines if a variable can live on the stack or must "escape" to the heap. The compiler moves variables to the heap if they are shared outside the function scope or are too large. Use `go build -gcflags="-m"` to inspect. Heap allocation is slower due to GC pressure.

**G19** — `reflect.Type` describes the type metadata; `reflect.Value` holds the actual data. Reflection is slow because it happens at runtime and bypasses compile-time optimizations. Use it for generic libraries (JSON encoders) but prefer **code generation** (e.g., `stringer`) for performance-critical paths.

**G20** — `//go:embed` allows including static files in the binary. It works for files and directories. It integrates with `io/fs.FS`, allowing you to treat embedded data as a filesystem. Limitations include the inability to embed files that change at runtime.

## Rust

**R1** — **Ownership** is Rust's memory management system. Rules: 1. Each value has one owner. 2. When the owner goes out of scope, the value is dropped. 3. You can have either one mutable reference OR any number of immutable references.

**R2** — `String` is an owned, heap-allocated buffer. `&str` is an immutable slice (view). Use `String` for data you need to own/modify; use `&str` in function signatures for flexibility (it accepts both `&String` and `&str`).

**R3** — **Borrowing** allows accessing data without taking ownership. Rules: You can have many immutable references (`&T`) OR exactly one mutable reference (`&mut T`) at any given time. This prevents data races at compile time.

**R4** — `Result<T, E>` handles success/failure; `Option<T>` handles presence/absence. The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>`: Single ownership, heap allocation. `Rc<T>`: Reference counted (single-threaded). `Arc<T>`: Atomic reference counted (thread-safe).

**R6** — **Traits** define shared behavior (like interfaces). **Trait objects** (`dyn Trait`) use dynamic dispatch (runtime lookup via vtable). **Generics** (`T: Trait`) use static dispatch (monomorphization/compile-time).

**R7** — It fails because the compiler cannot guarantee the returned reference lives long enough. Fix with **lifetimes**: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8** — `Send` means a type can be moved to another thread. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send` because its reference count is not atomic. `Arc<T>` uses atomic operations, making it `Send` and `Sync`.

**R9** — **Future** is a trait representing a computation that will complete. **Async/await** is syntactic sugar to create futures. The **executor** (Tokio) polls futures to make progress. Unlike Go's preemptive scheduler, Rust's async is **cooperative** (tasks must yield).

**R10** — `unsafe` allows bypassing certain compiler checks. You can: dereference raw pointers, call unsafe functions, or mutate static variables. It is justified when interfacing with C (FFI) or implementing low-level primitives.

**R11** — **Pattern matching** (`match`) is exhaustive; the compiler ensures all possible cases are covered. `if let` is a concise way to handle a single pattern match.

**R12** — `[T; N]` is a fixed-size array on the stack. `Vec<T>` is a growable heap-allocated array. When capacity is exceeded, `Vec` allocates a larger buffer and moves elements.

**R13** — Rust enums are **sum types** (can hold data). `Option<T>` is an enum (`Some(T)` or `None`) used to replace `null`, forcing the developer to handle the "empty" case explicitly.

**R14** — `impl` defines methods for a type. `&self` (immutable borrow), `&mut self` (mutable borrow), `self` (consumes ownership). **Associated functions** are called via the type (e.g., `String::new()`) and don't take `self`.

**R15** — `#[derive]` automatically implements traits. Common: `Debug`, `Clone`, `PartialEq`. You cannot derive a trait if its requirements (bounds) aren't met by the type's components.

**R16** — `Cow` (Clone on Write) is a smart pointer that allows for both borrowed and owned data. It avoids allocation if you only read, but clones the data only when you attempt to mutate it.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. Files map to modules (e.g., `mod foo` looks for `foo.rs`). In 2018+, the module tree is more streamlined, removing the need for `mod.rs` in many cases.

**R18** — `Pin<T>` ensures a value does not move in memory. This is required for **self-referential structs** (common in async futures) where a pointer would become invalid if the struct moved. `Unpin` is a marker trait for types that *can* be moved safely.

**R19** — **Declarative** (`macro_rules!`) uses pattern matching on tokens. **Procedural** macros are functions that transform code (Derive, Attribute, Function-like). **Hygiene** ensures macro variables don't accidentally clash with local variables.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use. **Iterators** are optimized into tight loops; **Generics** use **monomorphization** (generating specific code for each type used) to enable inlining and static dispatch, matching C performance.
