DN1 — **Class vs. Struct**: A `class` is a reference type (stored on the heap), while a `struct` is a value type (usually stored on the stack). Use a `struct` for small, immutable data structures (typically < 16 bytes) that have a short lifetime and no identity beyond their values.

DN2 — **IEnumerable vs. IQueryable**: `IEnumerable<T>` is for in-memory collections; LINQ operations are executed in the application's memory. `IQueryable<T>` is for remote data sources (like databases); it builds an expression tree that is translated into SQL and executed on the server. This distinction is vital for performance: `IEnumerable` pulls all data into memory before filtering, whereas `IQueryable` filters at the database level.

DN3 — **Async/Await**: `async/await` provides a way to write asynchronous code that looks synchronous. It uses a state machine to yield control back to the caller when waiting for an I/O operation. `Task` represents an ongoing operation; `ValueTask` is a lightweight alternative for scenarios where the result might already be available synchronously. Use `ValueTask` to reduce heap allocations when a method frequently completes synchronously.

DN4 — **Dependency Injection**: DI is a pattern where objects receive their dependencies from an external source rather than creating them. **Lifetimes**: *Transient* (new instance every time), *Scoped* (one instance per request), *Singleton* (one instance for the app lifetime). **Common Bug**: Injecting a *Scoped* service into a *Singleton* creates a "Captive Dependency," where the Scoped service lives as long as the Singleton, potentially causing stale data or memory leaks.

DN5 — **String vs. ReadOnlySpan<char>**: `string` is an immutable heap-allocated object. `ReadOnlySpan<char>` is a stack-allocated view into a contiguous memory region (heap, stack, or unmanaged). Use `Span<T>` to perform high-performance slicing and parsing without creating new string allocations, significantly reducing GC pressure.

DN6 — **Garbage Collector (GC)**: The GC manages memory automatically. **Generations**: *Gen 0* (newest, most frequent collections), *Gen 1* (buffer between 0 and 2), *Gen 2* (long-lived objects). **LOH**: Large Object Heap (objects > 85,000 bytes) is collected only during Gen 2 collections. **IDisposable**: Used to manually release unmanaged resources (file handles, DB connections) because the GC only manages managed memory.

DN7 — **ConfigureAwait(false)**: By default, `await` attempts to marshal the continuation back to the original `SynchronizationContext` (e.g., UI thread). `ConfigureAwait(false)` tells the runtime it doesn't need to return to that context. Use it in library code to improve performance and prevent deadlocks. Do **not** use it in application-level code where you need to access UI elements or specific context-bound data.

DN8 — **Modern .NET**: *Primary Constructors* allow parameters to be defined on the class header. *Collection Expressions* use `[1, 2, 3]` syntax. *FrozenDictionary* is an immutable, highly optimized read-only dictionary.
```csharp
// Example: Primary Constructor with DI
public class UserService(IUserRepository repo) {
    public User GetUser(int id) => repo.Find(id);
}
```

DN9 — **ObjectDisposedException**: This is likely caused by a race condition where multiple threads are sharing a single `DbContext` instance. `DbContext` is not thread-safe. **Fix**: Ensure the `DbContext` is registered as *Scoped* (the default) and that you are not manually creating a single instance shared across threads. Each request/thread should get its own scope.

DN10 — **Record vs. Class**: `record` provides built-in value-based equality and non-destructive mutation (`with` expression). `class` uses reference equality. Use `record` for DTOs/data containers. Use `record struct` for high-performance, value-based small data structures.

DN11 — **Parameter Modifiers**: `ref` (pass by reference, must be initialized), `out` (pass by reference, must be assigned inside the method), `in` (pass by reference, read-only). Use `in` for large structs to avoid copying while ensuring immutability.

DN12 — **Nullable Reference Types**: `?` on a reference type (e.g., `string?`) tells the compiler to warn if you access it without checking for null. It is a compile-time safety feature. For value types (e.g., `int?`), it is a runtime wrapper (`Nullable<T>`) that allows the type to hold a null value.

DN13 — **LINQ**: Language Integrated Query. *Method syntax* uses extension methods (`.Where()`); *Query syntax* uses SQL-like keywords (`from x in...`). **Deferred execution** means the query is not executed when defined, but when the data is actually iterated (e.g., via `foreach` or `.ToList()`).

DN14 — **Generic Constraints**: `T : class` (reference type), `T : struct` (value type), `T : new()` (must have parameterless constructor), `T : IComparable<T>` (must implement comparison). Combine them to narrow the type: `where T : class, new()`.

DN15 — **Abstract Class vs. Interface**: Abstract classes can hold state (fields) and implementation; interfaces primarily define a contract. **C# 8+**: Default interface methods allow interfaces to provide implementation, blurring the line, but interfaces still cannot hold instance state (fields).

DN16 — **Middleware Pipeline**: A sequence of delegates that handle requests/responses. `app.Use()` (adds middleware that can call the next), `app.Map()` (branches the pipeline based on path), `app.Run()` (terminates the pipeline). **Ordering**: Crucial; e.g., Exception Handling must be first to catch errors in subsequent middleware.

DN17 — **Channel<T>**: A high-performance, async-capable producer-consumer queue. Unlike `BlockingCollection<T>` (which uses thread blocking), `Channel<T>` uses `ValueTask` for non-blocking async operations. **Backpressure**: Use `Channel.CreateBounded<T>(capacity)` to limit the number of items; the producer will asynchronously wait when the channel is full.

DN18 — **Source Generators**: They run during compilation to generate additional C# code based on the existing code. Unlike *Reflection* (runtime inspection) or *IL Weaving* (modifying bytecode), they are type-safe and visible in the IDE. **Incremental Generators** are preferred because they only re-run when specific parts of the syntax tree change, significantly improving build performance.

DN19 — **TPL Dataflow**: A library for building actor-based pipelines. `ActionBlock` (processes data), `TransformBlock` (transforms data), `BufferBlock` (holds data). Compared to `Channels`, TPL Dataflow is higher-level and handles complex routing/buffering/parallelism automatically, whereas `Channels` is a lower-level primitive for simple producer-consumer patterns.

DN20 — **Minimal APIs**: A streamlined way to build APIs without the overhead of Controllers. **Trade-offs**: Controllers offer better organization for large apps; Minimal APIs are faster and more concise. **Support**: They support OpenAPI/Swagger and middleware. **Route Groups** allow applying logic to sets of endpoints; **Endpoint Filters** allow intercepting requests/responses similar to middleware but at the endpoint level.
