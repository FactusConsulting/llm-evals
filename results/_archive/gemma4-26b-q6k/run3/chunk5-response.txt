## Go

**G1** — An **array** has a fixed size defined at compile time; its size is part of its type. A **slice** is a descriptor (header) containing a pointer to an underlying array, a length, and a capacity. When `append` exceeds capacity, Go allocates a new, larger underlying array, copies the old elements, and returns a new slice header pointing to the new memory.

**G2** — `var x int` declares a variable and initializes it to its zero value (`0`). `x := 0` is short variable declaration, which declares and initializes in one step. You **cannot** use `:=` outside of a function body (at the package level) or when you are not declaring a *new* variable in the current scope.

**G3** — A **goroutine** is a lightweight execution unit managed by the Go runtime. Unlike an **OS thread**, which has a large fixed stack (MBs) and requires expensive context switches via the kernel, goroutines have small, growable stacks (KBs) and are multiplexed onto OS threads by the Go scheduler. The **GMP model** consists of **G** (Goroutines), **M** (Machine/OS Threads), and **P** (Processor/Logical Context). `P` holds the local run queue of `G`s, allowing `M` to execute `G`s without constant global lock contention.

**G4** — Channels are pipes used for communication between goroutines. An **unbuffered channel** requires both sender and receiver to be ready simultaneously (synchronous handoff). A **buffered channel** has a capacity; sends only block when the buffer is full. Sending to a **full buffered channel** blocks the sending goroutine until a receiver reads a value.

**G5** — `context` manages request lifecycles, cancellation signals, and deadlines.
```go
ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://slow-url.com", nil)
client.Do(req) // Automatically cancels if 100ms passes
```

**G6** — Go uses **implicit satisfaction**: a type satisfies an interface simply by implementing its methods; no `implements` keyword is needed. This is "structural typing" vs Java's "nominal typing." `interface{}` (or `any`) can hold any value because every type implements at least zero methods. It is **powerful** for generic containers but **dangerous** because it bypasses type safety, requiring frequent type assertions/switches.

**G7** — This is unsafe due to a **data race** and lack of **memory synchronization**. The Go memory model does not guarantee that the write to `data` is visible to the loop before `ready` becomes `true` because the compiler or CPU can reorder instructions. **Correct alternatives**: Use a `sync.Mutex`, `sync/atomic` for the boolean, or a channel to signal completion.

**G8** — `sync.Mutex` is an exclusive lock (one holder). `sync.RWMutex` allows multiple concurrent readers OR one single writer. Use `sync.Map` for "read-heavy" workloads with stable keys or when multiple goroutines write to disjoint sets of keys. **Trade-offs**: `sync.Map` is optimized for specific patterns; for most general cases, a standard `map` + `sync.Mutex` is faster and more predictable.

**G9** — Go modules manage dependencies. `go.mod` defines the module path and dependency versions; `go.sum` contains cryptographic hashes to ensure dependency integrity. `go mod tidy` adds missing modules and removes unused ones. **MVS (Minimum Version Selection)** is the algorithm Go uses to pick the *lowest* version of a module that satisfies all requirements, ensuring reproducible builds.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. **Gotcha**: Using `defer` inside a loop can cause resource exhaustion (e.g., file descriptors) because the deferred calls don't execute until the *outer* function returns, not the loop iteration.

**G11** — A **pointer** is a variable that stores the memory address of another value. The zero value is `nil`. To create a pointer to a struct literal: `p := &User{Name: "Alice"}`.

**G12** — `init()` is a special function that runs automatically when a package is initialized. It runs after variable declarations but before `main()`. A package can have **multiple** `init()` functions, and they execute in the order they appear in the source code.

**G13** — `new(T)` allocates zeroed storage for a type `T` and returns a **pointer** (`*T`). `make(T, ...)` is used only for **slices, maps, and channels**; it initializes the internal data structures and returns an **initialized value** (not a pointer).

**G14** — Errors are values. The `error` interface requires an `Error() string` method. The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error matches a specific target (useful for wrapped errors), while `errors.As` attempts to cast an error to a specific type. `==` only works for simple, non-wrapped errors.

**G15** — 
- **map**: `nil` (can be read, but cannot be written to).
- **slice**: `nil` (length 0, capacity 0).
- **channel**: `nil` (blocks forever on send/receive).
- **struct**: All fields are set to their respective zero values.

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one access is a write. The `-race` flag uses a detector to find these during runtime. 
*Example Fix*:
```go
// Bad: count++ (not atomic)
// Good:
var mu sync.Mutex
mu.Lock()
count++
mu.Unlock()
```

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch` (which evaluates expressions), `select` evaluates channel operations. If multiple cases are ready, one is chosen **pseudo-randomly**. To implement a timeout: `case <-time.After(time.Second):`.

**G18** — **Escape analysis** is the compiler's process of determining if a variable can reside on the **stack** (fast, automatic cleanup) or must "escape" to the **heap** (slower, requires GC). You can inspect this with `go build -gcflags="-m"`. It matters because excessive heap allocation increases GC pressure and latency.

**G19** — `reflect.Type` describes the type (e.g., `int`), while `reflect.Value` holds the actual data. **Costs**: Reflection is significantly slower than static code due to runtime type checking and heap allocations. **Justification**: Use reflection for generic libraries (JSON encoders, ORMs) where types aren't known at compile time; use **code generation** (like `stringer`) for performance-critical tasks.

**G20** — `//go:embed` allows including files into the binary at compile time. It supports single files, directories, or `embed.FS`. It integrates with `io/fs.FS`, allowing you to treat embedded data as a standard filesystem. **Limitations**: It cannot embed files that are excluded by build constraints or files that are not part of the module.

## Rust

**R1** — **Ownership** manages memory without a GC. Rules: 1. Each value has an owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is an immutable string slice (a view into a string). Use `String` when you need to own/mutate data; use `&str` in function signatures for maximum flexibility (it accepts both `String` and `&str`).

**R3** — **Borrowing** allows accessing data without taking ownership. Rules: You can have **either** any number of immutable references (`&T`) **OR** exactly one mutable reference (`&mut T`) at any given time. This prevents data races.

**R4** — `Result<T, E>` handles recoverable errors; `Option<T>` handles presence/absence of a value. The `?` operator performs an early return if the result is an `Err` or `None`.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>`: Single ownership, heap allocation. `Rc<T>`: Reference counted (non-thread-safe) for multiple owners. `Arc<T>`: Atomic reference counted (thread-safe) for multiple owners across threads.

**R6** — **Traits** define shared behavior (like interfaces). `dyn Trait` is a **trait object** (runtime polymorphism via vtable). `T: Trait` is a **generic with a trait bound** (compile-time polymorphism via monomorphization).

**R7** — It fails because the compiler cannot guarantee the returned reference lives long enough. You must use **lifetime annotations**:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** — `Send` means a type can be transferred to another thread. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send`/`Sync` because its reference count is not updated atomically, leading to data races. `Arc<T>` uses atomic operations, making it safe.

**R9** — Rust's async is **poll-based**. A `Future` is a state machine that does nothing until `poll()` is called. An **executor** (like Tokio) manages the polling of futures. Unlike Go's goroutines (which are preemptively scheduled by a runtime), Rust futures are **lazy** and must be explicitly driven by an executor.

**R10** — `unsafe` allows bypassing certain compiler checks. You can: 1. Dereference raw pointers. 2. Call unsafe functions. 3. Access/modify mutable static variables. It is justified when interfacing with C code (FFI) or implementing low-level data structures where the compiler cannot prove safety.

**R11** — **Pattern matching** (`match`) allows destructuring and checking values. `if let` is a concise way to handle a single pattern. The compiler enforces **exhaustiveness**, ensuring every possible value is handled.

**R12** — `Vec<T>` is a growable array on the heap. `[T; N]` is a fixed-size array on the stack. When a `Vec` exceeds capacity, it allocates a larger block of memory, copies the elements, and deallocates the old memory.

**R13** — Rust **enums** are "sum types" (can hold data per variant), unlike C/Java enums which are just named integers. `Option<T>` is an enum (`Some(T)` or `None`). Rust has no `null` to prevent null-pointer exceptions; you must explicitly handle the `None` case.

**R14** — `impl` blocks define methods for a type. `&self` borrows immutably; `&mut self` borrows mutably; `self` consumes the object (takes ownership). **Associated functions** are called via the type (e.g., `String::new()`) and do not take `self`.

**R15** — `derive` automatically implements traits. Examples: `Debug` (printing), `Clone` (deep copy), `PartialEq` (equality), `Serialize` (Serde). You cannot derive a trait if the underlying types do not also implement it (e.g., you can't derive `Clone` if a field is not `Clone`).

**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that can hold either borrowed or owned data. It is useful for functions that only need to mutate data if a certain condition is met, avoiding an allocation if the data remains unchanged.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. In 2018+, the file system mapping became more intuitive (no more `mod.rs` requirement), allowing `name.rs` to represent the module.

**R18** — `Pin<T>` ensures that the data at a pointer cannot be moved in memory. This is critical for **self-referential structs** (common in `async` state machines) where a pointer inside the struct points to another field within the same struct. `Unpin` is an auto-trait indicating a type is safe to move even when pinned.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching to expand code. **Procedural macros** are functions that run at compile time to transform code (derive, attribute, or function-like). **Hygiene** ensures macros don't accidentally capture or clash with variables in the calling scope.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use, and what you do use couldn't be implemented more efficiently by hand. **Iterators** are highly optimized; **Generics** use **monomorphization** (generating specific code for each type used) to eliminate runtime dispatch; and **trait static dispatch** allows the compiler to inline code, matching C's performance.
