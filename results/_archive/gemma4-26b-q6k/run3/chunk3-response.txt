K1 — **Deployment** manages stateless pods where any pod is interchangeable. **StatefulSet** manages stateful applications, providing stable, unique network identifiers and persistent storage that persists across pod rescheduling.

K2 — A **ClusterIP** service creates a virtual IP. Traffic is routed via `kube-proxy` (using iptables or IPVS rules) on each node, which intercepts traffic to the Service IP and performs DNAT to redirect it to one of the backend Pod IPs.

K3 — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a request for storage by a user. **StorageClass** defines "profiles" for storage (e.g., SSD vs HDD) to allow dynamic provisioning. **Relation:** A user creates a PVC; the system uses the StorageClass to automatically provision a PV that matches the PVC's requirements.

K4 — 
1. `kubectl logs <pod>`: Check application-level errors/stack traces.
2. `kubectl describe pod <pod>`: Check for exit codes (e.g., 137 for OOMKilled) and event logs.
3. `kubectl get pod -o yaml`: Verify environment variables, config files, and command arguments.
4. `kubectl exec` (if possible) or running the container locally: Test connectivity to dependencies (DBs, APIs) and check file permissions.

K5 — **CoreDNS** provides service discovery by translating Kubernetes Service names into IP addresses. If CoreDNS pods are down, internal service-to-service communication via DNS names will fail, though direct IP communication will still work.

K6 — The scheduler follows two main phases:
1. **Filtering (Predicates):** Removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, port conflicts, or Taints).
2. **Scoring (Priorities):** Ranks remaining nodes to find the best fit.
**Factors considered:** 
- **Resource Fit:** Preferring nodes with more available capacity.
- **Image Locality:** Preferring nodes that already have the container image downloaded.
- **Affinity/Anti-affinity:** Respecting rules about keeping pods together or apart.

K7 — **Yes**, it will be scheduled because the requested memory (256Mi) + existing requests (3.5GB) is ~3.75GB, which is less than 4GB. However, if it uses **600Mi**, it exceeds its limit (512Mi), and the kernel will trigger an **OOMKill** (Out of Memory Kill) on the container.

K8 — 
1. **External LB** receives the request and forwards it to the **Ingress Controller** (NGINX) via a NodePort or LoadBalancer service.
2. **Ingress Controller** matches the Host/Path rules.
3. The controller looks up the **Endpoints** object associated with the target **Service**.
4. The controller (acting as a proxy) sends the request directly to a **Pod IP**.
5. **kube-proxy** (via iptables/IPVS) ensures the underlying network routing allows this traffic to reach the specific node and pod.

K9 — A **NetworkPolicy** is a set of rules defining how pods are allowed to communicate. By default, if no policy exists, all pods in a namespace can talk to all other pods (**Allow All**). Once a policy is applied to a pod, that pod enters **Isolation mode**, and only traffic explicitly permitted by the policy is allowed.

K10 — **RollingUpdate** replaces old pods with new ones gradually, ensuring zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when the application does not support multiple versions running simultaneously (e.g., due to database schema conflicts or singleton requirements).

K11 — A **Namespace** is a virtual cluster within a physical cluster used to partition resources. Default namespaces: `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

K12 — `kubectl describe` provides deep metadata. Unlike `get`, it shows:
1. **Events:** Recent lifecycle changes or errors (e.g., FailedScheduling).
2. **Container Status:** Detailed exit codes and reason for failure.
3. **Conditions:** Current state of the pod (e.g., PodReady, PodScheduled).

K13 — A **ConfigMap** stores non-confidential data in key-value pairs. 
**Methods:** 
1. As **Environment Variables** in the container.
2. As **Files/Volumes** mounted into the container's filesystem.

K14 — 
- **ClusterIP:** Internal IP, accessible only within the cluster.
- **NodePort:** Exposes the service on a static port on every Node's IP.
- **LoadBalancer:** Provisions an external cloud load balancer to route traffic to the service.

K15 — A **DaemonSet** ensures that a copy of a specific Pod runs on all (or selected) nodes. Use it for **infrastructure tasks** like log collectors (Fluentd), monitoring agents (Prometheus Node Exporter), or networking plugins.

K16 — **Taints** are applied to **Nodes** to repel pods (e.g., "don't put anything here unless it's special"). **Tolerations** are applied to **Pods** to allow them to stay on tainted nodes. 
**Node Affinity** is applied to **Pods** to attract them to specific nodes.
**Use Case:** Use Taints/Tolerations to reserve GPU nodes for ML workloads; use Node Affinity to ensure a web server pod always lands in a specific availability zone.

K17 — An **Operator** is a custom controller that uses **Custom Resource Definitions (CRDs)** to manage complex, stateful applications. Unlike a standard controller (which manages generic objects like Pods), an Operator encodes **domain-specific operational knowledge** (e.g., how to perform a database backup or a version upgrade) into software.

K18 — **etcd** uses the **Raft consensus algorithm** for strong consistency. If quorum is lost, the cluster becomes read-only or non-functional. If 2 out of 3 nodes are lost, you cannot achieve a majority (2/3). **Recovery:** You must restore from a recent snapshot onto a new set of nodes or force a new cluster configuration if the remaining node can be manually reconfigured to act as a single-node cluster.

K19 — **RBAC** controls access via permissions. 
- **Role:** Permissions within a namespace.
- **ClusterRole:** Permissions cluster-wide.
- **RoleBinding:** Grants Role permissions to a user/group in a namespace.
- **ClusterRoleBinding:** Grants ClusterRole permissions cluster-wide.

**Manifest:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: dev-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: dev-ns
subjects:
- kind: User
  name: developer-user
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

K20 — By default, `ndots:5` means if a DNS query doesn't contain at least 5 dots, the resolver appends the search domains in `/etc/resolv.conf` before trying the name as-is. For an external domain like `google.com` (1 dot), the resolver tries `google.com.namespace.svc.cluster.local`, then `google.com.svc.cluster.local`, etc., causing 4+ unnecessary queries. 
**Fix:** Use `dnsConfig` in the Pod spec to set `ndots: 1` or provide a fully qualified domain name (FQDN) ending in a dot (e.g., `google.com.`).

D1 — **Merge** combines histories by creating a new commit. **Rebase** moves the entire branch to begin on the tip of the target branch, creating a linear history. **Avoid rebasing** on public/shared branches, as it rewrites history and breaks other developers' local copies.

D2 — **TCP** is connection-oriented, reliable, and ordered (e.g., HTTP, SSH). **UDP** is connectionless, faster, but unreliable/unordered (e.g., DNS, VoIP).

D3 — A **race condition** occurs when the outcome of a program depends on the unpredictable timing of events. 
**Example:** Two threads both read `counter = 10`, increment it to `11` locally, and then both write `11` back. The final value is `11` instead of the expected `12`.

D4 — **Symmetric:** Same key for encryption and decryption (fast). **Asymmetric:** Public key encrypts, private key decrypts (secure key exchange). In **TLS**, asymmetric encryption is used to securely exchange a symmetric session key, which is then used for the actual data transfer.

D5 — A **layer** is a read-only filesystem change. **Layer caching** means Docker reuses layers if the command and files haven't changed. **Best practice:** Order Dockerfile commands from "least likely to change" to "most likely to change" (e.g., `COPY package.json` before `COPY .`) to maximize cache hits.

D6 — 
1. **Check Application Logs:** Look for internal errors or timeouts.
2. **Check Infrastructure/Resource usage:** Is the service hitting CPU/Memory limits or OOMing?
3. **Check Upstream Dependencies:** Is the database or a downstream API slow/down?
4. **Check Load Balancer/Network:** Are there connection limits or network latency issues?

D7 — **CAP Theorem:** A distributed system can only provide two of: Consistency, Availability, or Partition Tolerance. 
- **CP (Consistency/Partition Tolerance):** **HBase** or **MongoDB** (in certain configs) — they stop responding if they can't guarantee data is up-to-date during a split.
- **AP (Availability/Partition Tolerance):** **Cassandra** or **DynamoDB** — they allow reads/writes even if nodes can't talk, accepting that data might be stale.

D8 — **Horizontal scaling** adds more instances (nodes/pods). **Vertical scaling** adds more resources (CPU/RAM) to existing instances. **Patterns:** Statelessness (allowing any instance to handle any request) and Load Balancing.

D9 — An **environment variable** is a dynamic value used by processes. On Linux, set it in `~/.bashrc` or `~/.profile` using `export VAR_NAME=value`.

D10 — **JSON** is data-oriented and uses braces/brackets; advantage is being highly machine-readable/standard for APIs. **YAML** is human-readable and uses indentation; advantage is being much easier for humans to write/read for configuration.

D11 — **REST API** is an architectural style for networked applications.
- **GET:** Retrieve data.
- **POST:** Create new data.
- **PUT:** Update/Replace existing data.
- **DELETE:** Remove data.

D12 — **Version pinning** is specifying exact versions of dependencies (e.g., `library==1.2.3`). It is vital for **reproducible builds** to ensure that a build today results in the same binary as a build six months from now, preventing "breaking changes" from silent updates.

D13 — **Compiled:** Translated to machine code before execution (e.g., C++, Rust). **Interpreted:** Executed line-by-line by another program (e.g., Python, JavaScript).

D14 — A **Reverse Proxy** sits in front of web servers and forwards client requests to them (protects/balances servers). A **Forward Proxy** sits in front of clients and forwards requests to the internet (hides client identity). 
**Reverse Proxies:** **NGINX** (load balancing), **HAProxy** (high-performance routing).

D15 — A **deadlock** is a state where a set of processes are blocked because each is holding a resource and waiting for another resource held by another process. 
**Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

D16 — **Eventual Consistency** means that given enough time without new updates, all replicas will converge to the same value. **Cassandra** uses **Tunable Consistency**: you can specify `ANY`, `ONE`, `QUORUM`, or `ALL` for both reads and writes to balance latency vs. consistency.

D17 — **mTLS** requires both client and server to present certificates. 
**Handshake:** 1. Client sends certificate; 2. Server sends certificate; 3. Both verify the other's certificate against a trusted CA; 4. They negotiate a symmetric key. 
**Usage:** Commonly used in **Service Meshes** (like Istio) for Zero Trust internal communication.

D18 — A **hash table** maps keys to indices via a hash function. 
- **Chaining:** Each index points to a linked list of entries that hashed to the same index.
- **Open Addressing:** Finds the next available slot in the array (e.g., linear probing).
**Complexity:** 
- **Average:** $O(1)$ for Insert, Lookup, Delete.
- **Worst Case:** $O(n)$ (when all keys hash to the same index).

D19 — A **Circuit Breaker** prevents a service from repeatedly trying an operation that is likely to fail. 
- **Closed:** Normal operation; requests pass through.
- **Open:** Failure threshold reached; requests fail immediately without calling the service.
- **Half-Open:** After a timeout, a few requests are allowed to test if the service has recovered.
It prevents **cascading failures** by giving the failing service time to recover, unlike **retries** which can actually overwhelm a struggling service (unless combined with **exponential backoff**).

D20 — **Optimistic:** Assumes conflicts are rare; checks for changes at commit time (e.g., using a `version` column). Best for high-concurrency, low-contention systems. **Pessimistic:** Locks the record upon reading to prevent others from touching it (e.g., `SELECT FOR UPDATE`). Best for high-contention environments where conflicts are frequent and costly.
