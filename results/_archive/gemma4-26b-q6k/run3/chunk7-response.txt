JS1 — `var` is function-scoped and can be redeclared; `let` and `const` are block-scoped. `const` prevents reassignment of the identifier. Hoisting is the behavior where variable and function declarations are moved to the top of their scope during compilation. `var` is hoisted and initialized as `undefined`; `let`/`const` are hoisted but remain in a "Temporal Dead Zone" until initialized.

JS2 — The event loop manages asynchronous execution. The **Call Stack** executes synchronous code. When an async operation completes, its callback enters a queue. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority and is emptied completely after every task. The **Macrotask Queue** (setTimeout, setInterval, I/O) is processed one task at a time after the microtask queue is empty.

JS3 — A closure is a function that "remembers" its lexical scope even when executed outside that scope. Example: `function outer() { let count = 0; return () => ++count; }`. The classic loop bug: `for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i), 1); }` prints `3, 3, 3` because `var` is function-scoped. Fix: use `let` in the loop header to create a new binding for each iteration.

JS4 — `Promise` represents a future value. `async/await` is syntactic sugar for Promises, making async code look synchronous. Error handling: `try/catch` with `await`, or `.catch()` with Promises. `Promise.all` rejects immediately if *any* promise fails. `Promise.allSettled` waits for all promises to either fulfill or reject and returns an array of objects describing the outcome of each.

JS5 — `interface` is primarily for defining object shapes and supports declaration merging. `type` is more flexible, allowing unions, primitives, and intersections. Use `interface` for public APIs/object structures; use `type` for complex logic/unions. **Discriminated unions** use a common literal property (e.g., `type: 'success' | 'error'`) to allow TypeScript to narrow down the specific type in a conditional block.

JS6 — Prototypal inheritance means objects inherit properties from a prototype object via the prototype chain. `Object.create(proto)` creates a new object with the specified `proto` as its prototype. ES6 `class` is "syntactic sugar" over prototypes; it doesn't change the underlying mechanism but provides a cleaner syntax for constructors and methods.

JS7 — `this` refers to the execution context. 1. **Default** (global/undefined), 2. **Implicit** (object before dot), 3. **Explicit** (`call`, `apply`, `bind`), 4. **New** (constructor). `bind()` returns a *new* function with a fixed `this`. You cannot re-bind a function once it has been bound via `bind()`.

JS8 — `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` triggers a callback after an object is GC'd. Use them for caches or metadata to avoid memory leaks. `WeakMap` keys must be objects because primitives cannot be tracked by GC in the same way, and the map doesn't prevent the key from being collected.

JS9 — V8 uses **Hidden Classes** (shapes) to track object properties efficiently. **Inline Caching** optimizes property access by remembering where properties were found previously. **Deoptimization** occurs when code assumptions fail (e.g., passing a different type to a function). Patterns causing it: changing object shapes (adding/deleting properties) or changing function argument types.

JS10 — Tree-shaking is dead-code elimination. It relies on static analysis of ES Modules (`import`/`export`). CommonJS (`require`) is dynamic; the module can be loaded conditionally at runtime, making it impossible for bundlers to know what is used without executing the code, thus preventing effective tree-shaking.

JS11 — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion (e.g., `null == undefined` is `true`); `===` checks strict equality (e.g., `null === undefined` is `false`). `??` (nullish coalescing) returns the right side only if the left is `null` or `undefined`. `?.` (optional chaining) returns `undefined` instead of throwing if a property in a chain is nullish.

JS12 — `map()` creates a new array by transforming every element. `filter()` creates a new array with elements that pass a test. `reduce()` accumulates array values into a single result. If an initial value is provided, `reduce` starts with it; otherwise, it uses the first element as the accumulator and starts from the second. `flatMap()` maps each element and then flattens the result by one level, useful for handling nested arrays returned by a map.

JS13 — Template literals use backticks (`` ` ``). They allow multi-line strings and interpolation (`${expr}`). **Tagged templates** allow a function to parse the template literal. Example: `function sql(strings, ...values) { return 'SELECT ...'; }`. The function receives the string parts and the evaluated expressions as separate arguments.

JS14 — Destructuring extracts data from arrays/objects into variables. `const {a, b: c} = obj` renames `b` to `c`. `const [x, ...rest] = arr` uses the **rest operator** to collect remaining elements into a new array. Default values: `const {a = 1} = obj`.

JS15 — `for...in` iterates over enumerable *keys* (property names) of an object. `for...of` iterates over *values* of an iterable (like an array). Avoid `for...in` on arrays because it iterates over indices as strings and may include inherited properties.

JS16 — **Generics** allow functions/classes to work with multiple types. **Constraints** (`T extends U`) limit the type to those having specific properties. **Conditional types** (`T extends U ? X : Y`) act like ternary operators for types. **Infer** allows extracting a type from a conditional. Example: `type GetReturn<T> = T extends (...args: any[]) => infer R ? R : any;`.

JS17 — **CommonJS** (Node.js default) uses `require` (synchronous) and `module.exports`. **ES Modules** (ESM) use `import`/`export` (asynchronous/static). Node.js handles both via file extensions (`.cjs` vs `.mjs`) or the `"type": "module"` field in `package.json`, which tells Node to treat all `.js` files in that package as ESM.

JS18 — TS is **structural** (if it looks like a duck, it is a duck). **Excess property checks** apply when assigning an object literal directly to a type. `extends` is for subtyping; `satisfies` checks if an expression matches a type without changing the expression's inferred type. **Variance**: `in` (contravariance) for function arguments, `out` (covariance) for return values.

JS19 — `Proxy` wraps an object to intercept operations; `Reflect` provides methods to perform the default behavior of those operations. Example: `const p = new Proxy(target, { get(t, prop) { console.log(prop); return Reflect.get(t, prop); } });`. This is used for logging, validation, or making data reactive.

JS20 — `SharedArrayBuffer` allows multiple threads (Web Workers) to share a raw memory buffer. `Atomics` provides static methods to perform thread-safe operations (like `add`, `load`, `store`) to prevent race conditions. `Atomics.wait` puts a thread to sleep until `Atomics.notify` is called on the same index, ensuring efficient synchronization.
