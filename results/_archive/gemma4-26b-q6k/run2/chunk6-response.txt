DN1 — **Class vs Struct**: A `class` is a reference type (stored on the heap), while a `struct` is a value type (usually stored on the stack). Use a `struct` for small, immutable data structures (typically < 16 bytes) that have a short lifetime to reduce GC pressure.

DN2 — **IEnumerable vs IQueryable**: `IEnumerable<T>` is for in-memory collections; LINQ operations are executed in the application's memory. `IQueryable<T>` is for out-of-memory data (like databases); it builds an expression tree that is translated into a provider-specific language (like SQL). This distinction matters because `IEnumerable` pulls all data into memory before filtering, whereas `IQueryable` pushes the filter to the database server.

DN3 — **Async/Await**: `async/await` provides a way to write asynchronous code that looks synchronous by yielding control back to the caller during I/O-bound operations. A `Task` represents an ongoing operation. A `ValueTask` is a union-like struct used when an operation might complete synchronously most of the time, avoiding the heap allocation of a `Task` object. Use `ValueTask` when the result is often already available.

DN4 — **Dependency Injection**: DI is a design pattern where objects receive their dependencies from an external source rather than creating them. 
- **Transient**: Created every time they are requested.
- **Scoped**: Created once per client request (e.g., per HTTP request).
- **Singleton**: Created once and shared throughout the application lifetime.
**Common Bug**: Injecting a **Scoped** service into a **Singleton**. Since the Singleton lives forever, it captures the Scoped service, effectively making it a Singleton, which can lead to stale data or disposed object errors.

DN5 — **String vs ReadOnlySpan<char>**: `string` is an immutable heap-allocated object. `ReadOnlySpan<char>` is a stack-allocated view into a contiguous region of memory (heap, stack, or unmanaged). Use `Span<T>` for high-performance slicing and parsing to avoid creating multiple substring allocations on the heap.

DN6 — **Garbage Collector (GC)**: The GC manages memory automatically. 
- **Gen 0**: Short-lived objects (fastest collection).
- **Gen 1**: Buffer between Gen 0 and Gen 2.
- **Gen 2**: Long-lived objects.
- **LOH (Large Object Heap)**: Where objects > 85,000 bytes are stored; these are collected during Gen 2 collections and can cause fragmentation.
- **IDisposable**: Used to manually release unmanaged resources (file handles, DB connections) because the GC only manages managed memory.

DN7 — **ConfigureAwait(false)**: By default, `await` attempts to marshal the continuation back to the original `SynchronizationContext` (e.g., UI thread or ASP.NET request context). `ConfigureAwait(false)` tells the runtime it doesn't need to return to that specific context. Use it in library code to improve performance and prevent deadlocks. Do **not** use it in application-level code where you need to access context-specific data (like `HttpContext.Current` in legacy ASP.NET).

DN8 — **Modern .NET Features**: 
- **Primary Constructors**: Define parameters directly in the class header.
- **Collection Expressions**: `int[] arr = [1, 2, 3];`
- **FrozenDictionary**: An immutable, highly optimized read-only dictionary.
**Example**:
```csharp
public class UserService(IUserRepository repo) { // Primary Constructor
    public User GetUser(int id) => repo.Find(id);
}
```

DN9 — **ObjectDisposedException**: This occurs because `DbContext` is not thread-safe. Under high concurrency, multiple threads are likely trying to use the same `DbContext` instance simultaneously. **Fix**: Ensure `DbContext` is registered as `Scoped` (the default) and that you are not sharing a single instance across threads. If using `Task.WhenAll`, you must create a new scope/context for each task.

DN10 — **Record vs Class**: `record` provides built-in value-based equality and non-destructive mutation (`with` expression). Use `record` for DTOs/data containers. `record struct` is a value-type version of a record. Use `class` when you need identity-based equality or complex inheritance/encapsulation.

DN11 — **Ref, Out, In**:
- **ref**: Passes a variable by reference; must be initialized before passing.
- **out**: Passes a variable by reference; must be assigned a value inside the method.
- **in**: Passes a variable by reference but makes it read-only (prevents copying large structs).

DN12 — **Nullable Reference Types**: The `?` on a reference type (e.g., `string?`) is a compile-time hint to the compiler to warn about potential null dereferences. It does **not** change the underlying type to a value type. `int?` is a `Nullable<int>`, which is a real runtime wrapper for value types.

DN13 — **LINQ**: Language Integrated Query. 
- **Method Syntax**: Uses extension methods (e.g., `.Where()`).
- **Query Syntax**: Uses SQL-like syntax (e.g., `from x in...`).
**Deferred Execution**: The query is not executed when defined, but when the data is actually iterated (e.g., via `foreach` or `.ToList()`).

DN14 — **Generic Constraints**:
- `where T : class`: T must be a reference type.
- `where T : struct`: T must be a value type.
- `where T : new()`: T must have a parameterless constructor.
- `where T : IComparable<T>`: T must implement `IComparable<T>`.
Combine them to narrow the type: `where T : class, new()`.

DN15 — **Abstract Class vs Interface**: An `abstract class` can hold state (fields) and implementation. An `interface` defines a contract. **Default Interface Methods** allow interfaces to provide implementation, blurring the line, but interfaces still cannot hold instance state (fields).

DN16 — **Middleware Pipeline**: A sequence of delegates that handle requests/responses.
- **app.Use()**: Adds middleware that can call the next delegate.
- **app.Map()**: Branches the pipeline based on a path.
- **app.Run()**: A terminal middleware that does not call the next delegate.
**Ordering**: Crucial; e.g., Exception Handling must be first to catch errors in subsequent steps.

DN17 — **Channel<T>**: A high-performance, async-capable queue for producer-consumer patterns. Unlike `BlockingCollection<T>` (which is synchronous/blocking), `Channel<T>` is designed for `async/await`. 
**Backpressure**: Use `Channel.CreateBounded<T>(capacity)`; when the capacity is reached, the producer's `WriteAsync` will asynchronously wait until space is available.

DN18 — **Source Generators**: They run during compilation to inspect code and generate additional source files. Unlike **Reflection** (runtime inspection) or **IL Weaving** (modifying bytecode), they are type-safe and happen at compile time. **Incremental Generators** are preferred because they only re-run when necessary, significantly improving IDE and build performance.

DN19 — **TPL Dataflow**: A library for building actor-based pipelines.
- **ActionBlock**: Processes data with an action.
- **TransformBlock**: Transforms input to output.
- **BufferBlock**: A simple queue.
**vs Channels**: Channels are lower-level, highly optimized for simple producer-consumer, while TPL Dataflow is higher-level, offering complex routing, buffering, and parallelism management.

DN20 — **Minimal APIs**: A streamlined way to build APIs without the overhead of Controllers.
- **Trade-offs**: Controllers offer better organization for massive APIs; Minimal APIs are faster and more lightweight. Testability is similar via `WebApplicationFactory`.
- **Route Groups**: Allow applying middleware/filters to a subset of endpoints.
- **Endpoint Filters**: Act like middleware but are scoped specifically to the endpoint execution.

---

P1 — **List vs Tuple**: `list` is mutable and ordered; `tuple` is immutable and ordered. **Set vs Frozenset**: `set` is mutable; `frozenset` is an immutable version of a set.

P2 — **GIL**: A mutex that protects access to Python objects, preventing multiple native threads from executing Python bytecodes at once. It affects **CPU-bound** workloads (multi-threading won't help). **Workarounds**: Use `multiprocessing` or C-extensions that release the GIL.

P3 — **Deepcopy vs Copy**: `copy.copy()` creates a new object but inserts references to the objects found in the original. `copy.deepcopy()` creates a new object and recursively copies everything found in the original. **Example**: If a list contains a list, changing the inner list in a shallow copy will change it in the original.

P4 — **Decorators**: Functions that wrap other functions.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"Time: {time.time() - start}")
        return result
    return wrapper
```

P5 — **Generators/Yield**: Generators return an iterator that produces values one by one using `yield`, saving memory. Unlike a list, they don't store all values in RAM. `yield from` is used to delegate to a sub-generator.

P6 — **Asyncio**: `asyncio.run()` starts the event loop; `asyncio.gather()` runs multiple coroutines concurrently; `asyncio.create_task()` schedules a coroutine to run. You cannot use `time.sleep()` because it blocks the entire thread, preventing the event loop from switching tasks; use `await asyncio.sleep()` instead.

P7 — **MRO**: Python uses the **C3 Linearization** algorithm. In the provided code, `D` inherits from `B` then `C`. The order is `D -> B -> C -> A`. `D().who()` prints `"B"`'s parent's method if B doesn't have it, but since B doesn't override `who`, it looks at C. However, in this specific code, `B` inherits from `A`, and `C` inherits from `A`. The MRO for `D` is `[D, B, C, A, object]`. Since `B` does not have `who`, it checks `C`. `C` has `who`, so it prints `"C"`.

P8 — **Metaclass**: A class that creates classes. `__init_subclass__` is a simpler way to customize class creation without the complexity of a metaclass. **Use case**: Use `__init_subclass__` for simple registration of subclasses; use a metaclass for complex logic like enforcing attribute presence or modifying class attributes dynamically.

P9 — **Concurrency**:
- **Multiprocessing**: Bypasses GIL by using separate memory spaces (CPU-bound).
- **Threading**: Shared memory, subject to GIL (I/O-bound).
- **concurrent.futures**: High-level abstraction for both.
**Serialization**: `multiprocessing` requires objects to be "picklable" to be sent between processes.

P10 — **\_\_slots\_\_**: Tells Python not to use a `__dict__` for instance attributes, instead using a fixed set of attributes. This significantly reduces memory usage and slightly improves attribute access speed, but prevents adding new attributes at runtime.

P11 — **Virtual Environments**: Isolated Python environments to manage dependencies per project. `venv` is built-in; `virtualenv` is a more feature-rich third-party tool; `conda` is a package and environment manager that handles non-Python dependencies.

P12 — **Comprehensions**: Concise syntax for creating collections. They are generally faster and more readable than `map()`/`filter()`. Use them when the logic is simple; use `map`/`filter` when you already have a pre-defined function.

P13 — **== vs is**: `==` checks for **equality** (value); `is` checks for **identity** (memory address). **Interning**: Python caches small integers and certain strings to save memory; thus `a is b` might be true for `a=10, b=10`.

P14 — **Args/Kwargs**: `*args` collects positional arguments into a tuple; `**kwargs` collects keyword arguments into a dictionary. `/` forces arguments to be positional-only; `*` forces arguments to be keyword-only.

P15 — **Context Managers**: Handle setup/teardown (e.g., `with`).
```python
from contextlib import contextmanager
@contextmanager
def my_ctx():
    print("setup")
    yield
    print("teardown")
# Usage: with my_ctx(): ...
```
**Example**: A database transaction manager or a timer.

P16 — **Type Hinting**: `Union[int, str]` (either), `Optional[int]` (int or None), `Literal[1]` (exactly 1), `TypeVar` (generic), `Protocol` (structural typing). Static analyzers like `mypy` use these to catch type errors without running the code.

P17 — **Data Model**:
- `__repr__`: Official string representation (for devs).
- `__str__`: User-friendly string representation.
- `__eq__` vs `__hash__`: If you define `__eq__`, you must define `__hash__` if you want the object to be usable in a `set` or as a `dict` key.
- `__getattr__` (called if attribute not found) vs `__getattribute__` (called every time).

P18 — **Descriptors**: Objects that define `__get__`, `__set__`, or `__delete__`. They manage attribute access. `property`, `classmethod`, and `staticmethod` are all implemented using the descriptor protocol to intercept method calls.

P19 — **Import System**: **Absolute**: `from pkg.mod import func`. **Relative**: `from .mod import func`. `sys.path` is the list of directories searched. `__init__.py` makes a directory a package. **Finders** locate modules; **Loaders** execute them.

P20 — **Dataclasses**: Automates boilerplate for data classes. `__post_init__` runs after `__init__`. **vs Pydantic**: Pydantic is primarily for **data validation** and parsing (runtime), whereas `dataclasses` is for **data storage** (compile-time/static). Use Pydantic for API request validation; use dataclasses for internal data structures.
