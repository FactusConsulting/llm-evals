G1 — An **array** has a fixed size defined at compile time. A **slice** is a descriptor (header) containing a pointer to an underlying array, a length, and a capacity. When `append` exceeds capacity, Go allocates a new, larger underlying array, copies the old elements, and returns a new slice pointing to the new array.

G2 — `var x int` declares a variable and initializes it to its zero value (`0`). `x := 0` is short variable declaration, which declares and initializes simultaneously. You **cannot** use `:=` outside of a function body (at the package level).

G3 — A **goroutine** is a lightweight execution unit managed by the Go runtime. Unlike OS threads, which have large stacks (MBs) and require expensive context switches via the kernel, goroutines have small, growable stacks (KBs) and are multiplexed onto OS threads by the Go scheduler. The **GMP model** consists of **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts). The scheduler assigns Gs to Ps, which then run on Ms, ensuring efficient work-stealing and load balancing.

G4 — **Channels** are pipes used for communication between goroutines. An **unbuffered channel** requires both sender and receiver to be ready simultaneously (synchronous). A **buffered channel** allows sending up to $N$ elements without a receiver being present (asynchronous). Sending to a full buffered channel **blocks** the sender until a receiver reads a value.

G5 — The `context` package manages request lifecycles, cancellation, and deadlines.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

G6 — Go uses **implicit satisfaction**: a type satisfies an interface simply by implementing its methods. Java/C# require explicit keywords (`implements`). `interface{}` (or `any`) can hold any value because every type implements at least zero methods. It is powerful for generic-like behavior but dangerous because it bypasses type safety, requiring type assertions that can panic.

G7 — This is unsafe due to a **data race**. The Go memory model does not guarantee that writes in one goroutine are visible to another without explicit synchronization. The compiler or CPU might reorder the instructions, or the `ready` flag might be cached in a register, causing the loop to run forever or see `data` as empty. **Alternatives**: Use `sync.Mutex`, `sync/atomic`, or a channel to signal completion.

G8 — `sync.Mutex` is a mutual exclusion lock (one holder at a time). `sync.RWMutex` allows multiple concurrent readers OR one single writer. Use `sync.Map` for high-concurrency scenarios where keys are stable and mostly read, or when multiple goroutines read/write disjoint sets of keys. **Trade-offs**: `sync.Map` is optimized for specific cache-contention patterns but is slower than a `map + Mutex` for general-purpose use.

G9 — **Go modules** manage dependencies. `go.mod` defines the module path and dependency versions; `go.sum` contains cryptographic hashes to ensure dependency integrity. `go mod tidy` adds missing modules and removes unused ones. **MVS** (Minimum Version Selection) picks the *lowest* version of a module that satisfies all constraints, ensuring reproducible builds.

G10 — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common **gotcha** is using `defer` inside a loop; since defers only execute when the *function* returns, not the loop iteration, this can cause resource exhaustion (e.g., leaking file descriptors).

G11 — A **pointer** is a variable that stores the memory address of another value. The zero value is `nil`. To create a pointer to a struct literal: `p := &User{Name: "Alice"}`.

G12 — `init()` is a special function that runs automatically when a package is initialized. It runs after variable declarations but before `main()`. A package can have multiple `init()` functions, and they execute in the order they appear in the source code.

G13 — `new(T)` allocates zeroed memory for a type `T` and returns a pointer (`*T`). `make(T, args)` is used only for slices, maps, and channels; it initializes the internal data structures and returns an initialized value of type `T` (not a pointer).

G14 — Errors are values. The `error` interface requires an `Error() string` method. The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error matches a specific target (useful for wrapped errors), while `errors.As` attempts to cast an error to a specific type. `==` only works for simple error comparisons and fails if the error has been wrapped.

G15 — **Map**: zero value is `nil`. **Slice**: zero value is `nil`. **Channel**: zero value is `nil`. **Struct**: zero value is a struct with all its fields set to their respective zero values.

G16 — A **race condition** occurs when two goroutines access the same memory concurrently and at least one access is a write. The `-race` flag enables the runtime data race detector.
*Example Fix*:
```go
var mu sync.Mutex
var count int
// Fix:
mu.Lock()
count++
mu.Unlock()
```

G17 — `select` lets a goroutine wait on multiple communication operations. Unlike `switch` (which evaluates expressions), `select` blocks until one of its cases can proceed. If multiple are ready, one is chosen **pseudo-randomly**. A timeout is implemented using `time.After(d)`:
```go
select {
case res := <-ch: // handle result
case <-time.After(time.Second): // handle timeout
}
```

G18 — **Escape analysis** determines if a variable can reside on the stack or must "escape" to the heap. If a variable's lifetime exceeds the function scope (e.g., returning a pointer to a local variable), it escapes to the heap. Inspect via `go build -gcflags="-m"`. It matters because heap allocation increases GC pressure and latency.

G19 — `reflect` allows inspecting types at runtime. `reflect.Type` describes the type (name, kind), while `reflect.Value` holds the actual data. **Costs**: It is significantly slower than static code due to runtime overhead and prevents many compiler optimizations. Use it for generic libraries (JSON encoders) but prefer **code generation** (e.g., `stringer`) for performance-critical logic.

G20 — `//go:embed` allows including static files in the binary. It works for single files, directories, or `embed.FS`. It interacts with `io/fs.FS` to provide a filesystem interface. **Limitations**: It cannot embed files that are not part of the module and cannot be used to embed files that are excluded by build constraints.

R1 — **Ownership** manages memory. Rules: 1. Each value has a variable called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

R2 — `String` is an owned, heap-allocated, growable UTF-8 buffer. `&str` is an immutable string slice (a view into a string). Use `String` when you need to modify or own the data; use `&str` in function signatures to allow the function to accept both `String` and `&str` without extra allocations.

R3 — **Borrowing** allows accessing data without taking ownership. **Rules**: You can have either *any number of immutable references* (`&T`) OR *exactly one mutable reference* (`&mut T`) at any given time, and they cannot coexist.

R4 — `Result<T, E>` represents success or failure; `Option<T>` represents presence or absence of a value. The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

R5 — `Box<T>` is for heap allocation of a single value (unique ownership). `Rc<T>` is a Reference Counted pointer for multiple ownership in a single thread. `Arc<T>` is an Atomic Reference Counted pointer for multiple ownership across threads.

R6 — **Traits** define shared behavior (similar to interfaces but more powerful). **Trait Object** (`dyn Trait`) uses dynamic dispatch (runtime lookup). **Generics with trait bounds** (`T: Trait`) use monomorphization (compile-time dispatch), which is faster and allows for static optimization.

R7 — It fails because the compiler cannot guarantee that the returned reference lives as long as the inputs. **Fix**: Add lifetime annotations: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

R8 — `Send` means ownership can be transferred to another thread. `Sync` means it is safe to share references between threads. `Rc<T>` is not `Send` because its reference count is not updated atomically, leading to data races. `Arc<T>` uses atomic operations for the count, making it `Send` and `Sync`.

R9 — Rust's async is **poll-based**. A `Future` is a state machine that returns `Poll::Ready` or `Poll::Pending`. An **executor** (like Tokio) polls futures to drive them to completion. Unlike Go, where goroutines are managed by a runtime scheduler, Rust futures do nothing unless polled by an executor.

R10 — `unsafe` allows bypassing certain compiler checks. 1. Dereferencing raw pointers. 2. Calling unsafe functions. 3. Accessing/modifying mutable static variables. It is justified when interfacing with C libraries (FFI) or implementing low-level data structures where the compiler cannot prove safety.

R11 — **Pattern matching** (`match`) is a control flow construct that compares a value against a series of patterns. `if let` is syntactic sugar for a `match` that only cares about one pattern. The compiler enforces **exhaustiveness**, ensuring all possible patterns are covered.

R12 — `[T; N]` is a fixed-size array on the stack. `Vec<T>` is a growable heap-allocated buffer. When capacity is exceeded, `Vec` allocates a new buffer (usually doubling capacity), copies elements, and deallocates the old buffer.

R13 — **Enums** in Rust are "sum types" (can hold data in each variant), unlike C enums (integers) or Java enums (objects). `Option<T>` is an enum with `Some(T)` and `None`, replacing `null` to force explicit handling of the "empty" case.

R14 — `impl` blocks define methods for a type. `&self` borrows immutably; `&mut self` borrows mutably; `self` consumes the instance (takes ownership). **Associated functions** do not take `self` and are called via the type (e.g., `Type::new()`).

R15 — `#[derive]` automatically implements traits. Examples: `Debug` (printing), `Clone` (copying), `PartialEq` (equality), `Serialize` (conversion to format). You cannot derive a trait if its implementation requires custom logic or if the type's components don't implement that trait.

R16 — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that can hold either borrowed or owned data. It is useful when you mostly read data but occasionally need to modify it, avoiding an allocation unless a mutation occurs.

R17 — `mod` declares a module; `use` brings paths into scope; `pub` makes items public. In Rust 2018, the module system was simplified so that files are modules by default, removing the need for `mod.rs` in many cases.

R18 — `Pin<T>` ensures that the data at a pointer cannot be moved in memory. This is critical for **self-referential structs** (common in `async` state machines) where a pointer inside the struct points to another field within the same struct. `Unpin` is a marker trait for types that *can* be safely moved.

R19 — **Declarative macros** (`macro_rules!`) use pattern matching to expand code. **Procedural macros** act like functions that take code as input and output new code. They include `derive` (adds traits), `attribute` (modifies items), and `function-like` (looks like a function call). **Hygiene** ensures macros don't accidentally capture variables from the surrounding scope.

R20 — **Zero-cost abstractions** mean you don't pay for what you don't use, and what you do use is as efficient as a manual implementation. **Iterators** are optimized into tight loops; **Generics** use monomorphization to create specialized, fast code; **Static dispatch** resolves calls at compile time, allowing inlining.
