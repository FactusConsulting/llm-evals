K1 — **Deployment** is for stateless applications where pods are interchangeable; **StatefulSet** is for stateful applications requiring stable network identifiers, ordered deployment/scaling, and stable persistent storage.

K2 — A **ClusterIP** service uses `kube-proxy` (via iptables or IPVS) on each node to intercept traffic sent to the Service's Virtual IP (VIP) and redirect it to the backend Pod IPs.

K3 — **PersistentVolume (PV)** is the actual storage resource; **PersistentVolumeClaim (PVC)** is a user's request for storage; **StorageClass** is a template that allows for dynamic provisioning of PVs. They relate as: User $\rightarrow$ PVC $\rightarrow$ StorageClass $\rightarrow$ PV.

K4 — 1. `kubectl logs <pod>` to check application errors. 2. `kubectl describe pod <pod>` to check for events (e.g., OOMKilled, Liveness probe failures). 3. Check container entrypoint/command/args for syntax errors. 4. Check environment variables and mounted volumes for missing configuration.

K5 — **CoreDNS** provides service discovery via DNS within the cluster. If CoreDNS pods are down, internal service-to-service communication via DNS names will fail, though direct Pod IP communication will still work.

K6 — The scheduler uses two main phases: **Filtering** (Predicates) to remove nodes that don't meet requirements (e.g., insufficient CPU/RAM, node selectors), and **Scoring** (Priorities) to rank remaining nodes. Factors include: **Resource Fit** (least requested), **Image Locality** (nodes with cached images), and **Affinity/Anti-affinity** rules.

K7 — **Yes**, it will be scheduled because $256\text{Mi} \le (4\text{GB} - 3.5\text{GB})$. However, if it uses $600\text{Mi}$, it exceeds its limit ($512\text{Mi}$), and the kernel will trigger an **OOMKill** (Out of Memory Kill) on the container.

K8 — 1. **External LB** receives traffic and forwards it to the **Ingress Controller** (NGINX) via a NodePort/LoadBalancer. 2. **Ingress Controller** matches the Host/Path rules. 3. It identifies the target **Service**. 4. It uses the **Endpoints** object (populated by the controller) to find the specific **Pod IPs**. 5. Traffic is routed directly to the Pod IP, bypassing the Service VIP to avoid extra hops.

K9 — A **NetworkPolicy** is a set of rules defining how pods are allowed to communicate. By default, if no policy exists, all pods can talk to all other pods (allow-all). Once a policy selects a pod, that pod becomes "isolated," and only traffic explicitly allowed by the policy is permitted.

K10 — **RollingUpdate** replaces pods one by one to ensure zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when the application does not support multiple versions running simultaneously (e.g., a single-instance database schema migration).

K11 — A **Namespace** is a virtual cluster used to partition resources. Default namespaces: `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

K12 — Used to inspect the detailed state of a pod. It shows: **Events** (recent lifecycle changes), **Container Status** (restarts, exit codes), and **Conditions** (PodScheduled, Ready, etc.).

K13 — A **ConfigMap** stores non-confidential data in key-value pairs. Pods consume it via **Environment Variables** or as **Files in a Volume**.

K14 — **ClusterIP**: Internal access only. **NodePort**: Exposes the service on a static port on each Node's IP. **LoadBalancer**: Provisions an external cloud load balancer to route traffic to the service.

K15 — A **DaemonSet** ensures that a copy of a specific Pod runs on all (or selected) nodes. Use it for background tasks like log collection (Fluentd) or monitoring agents (Prometheus Node Exporter).

K16 — **Taints** are applied to **Nodes** to repel pods; **Tolerations** are applied to **Pods** to allow them to stay on tainted nodes. **Node Affinity** is applied to **Pods** to attract them to specific nodes. *Use case*: Taint a node for GPU workloads; use affinity to ensure a high-priority web pod lands on a high-performance node.

K17 — An **Operator** is a custom controller that uses Custom Resource Definitions (CRDs) to manage complex, stateful applications. Unlike standard controllers (which manage generic objects like Pods), Operators encode domain-specific operational knowledge (e.g., how to back up a specific database).

K18 — **etcd** uses the **Raft** consensus algorithm. If quorum is lost, the cluster becomes read-only or fails. To recover from losing 2/3 nodes: you must restore from a recent snapshot onto a new 3-node cluster to re-establish a majority.

K19 — **Role/ClusterRole** defines permissions; **RoleBinding/ClusterRoleBinding** grants those permissions to a user/group.
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: target-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: target-ns
subjects:
- kind: User
  name: "developer"
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

K20 — By default, `ndots:5` causes the resolver to append several search domains (e.g., `google.com.namespace.svc.cluster.local`) before trying the actual domain. This results in multiple failed DNS queries. Fix it by setting `dnsConfig` in the Pod spec:
```yaml
spec:
  dnsConfig:
    options:
      - name: ndots
        value: "1"
```

D1 — **Merge** combines histories; **Rebase** rewrites history by moving commits to a new base. Avoid rebasing **public/shared branches** as it rewrites history and breaks other developers' local copies.

D2 — **TCP** is connection-oriented/reliable (HTTP, SSH); **UDP** is connectionless/unreliable (DNS, VoIP).

D3 — A **Race Condition** occurs when the outcome depends on the timing/sequence of uncontrollable events. *Example*: Two threads incrementing a shared integer `x++` simultaneously; both read `5`, both increment to `6`, and the final value is `6` instead of `7`.

D4 — **Symmetric**: Same key for encryption/decryption. **Asymmetric**: Public key encrypts, private key decrypts. In **TLS**, asymmetric encryption is used to securely exchange a symmetric session key, which is then used for the actual data transfer.

D5 — A **layer** is a read-only filesystem change (e.g., installing a package). **Layer caching** means Docker reuses layers from previous builds; best practice is to put frequently changing instructions (like `COPY . .`) at the bottom of the Dockerfile to maximize cache hits.

D6 — 1. Check **Application Logs** (errors/exceptions). 2. Check **Resource Usage** (CPU/RAM exhaustion). 3. Check **Upstream Dependencies** (DB/API timeouts). 4. Check **Network/Load Balancer** (connection limits/timeouts).

D7 — **CAP**: Consistency, Availability, Partition Tolerance. **CP** (Consistency/Partition): MongoDB (ensures data is correct across nodes but may reject requests if a majority isn't reached). **AP** (Availability/Partition): Cassandra (always responds, but data might be slightly stale).

D8 — **Horizontal**: Adding more instances (nodes/pods). **Vertical**: Adding more resources (CPU/RAM) to an existing instance. **Patterns**: Statelessness, Load Balancing, and Sharding enable horizontal scaling.

D9 — An **environment variable** is a dynamic value used by processes. Set it via `export VAR=value` in `.bashrc` or `.zshrc` to persist across sessions.

D10 — **JSON** is data-interchange format (strict, uses `{}`). **YAML** is human-readable (uses indentation). *Advantage JSON*: Faster for machines to parse. *Advantage YAML*: Easier for humans to read/write.

D11 — **REST API**: Architectural style for networked applications. **GET**: Retrieve; **POST**: Create; **PUT**: Replace/Update; **DELETE**: Remove.

D12 — **Version pinning** is specifying exact versions of dependencies (e.g., `lib-v1.2.3`). It ensures that builds are **reproducible** and prevents breaking changes from automatic updates.

D13 — **Compiled**: Converted to machine code before execution (C++, Go). **Interpreted**: Executed line-by-line by a runtime (Python, JavaScript).

D14 — **Reverse Proxy**: Sits in front of web servers and handles requests (Nginx, HAProxy). *Use case*: Load balancing or SSL termination. **Forward Proxy**: Sits in front of clients to hide them or filter traffic (Squid).

D15 — A **Deadlock** is a state where processes are stuck waiting for each other. **Coffman Conditions**: 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

D16 — **Eventual Consistency**: Data will be consistent across all nodes given enough time. **Cassandra** uses tunable consistency: `ANY`, `ONE`, `QUORUM`, `ALL`. A user can choose `QUORUM` for a balance of speed and consistency.

D17 — **mTLS**: Both client and server present certificates to prove identity. *Handshake*: 1. Client sends hello + cert. 2. Server sends hello + cert + verifies client cert. 3. Both exchange keys. Used in **Service Meshes** (Istio/Linkerd) for Zero Trust security.

D18 — A **Hash Table** maps keys to indices via a hash function. **Chaining** uses linked lists at each index to handle collisions; **Open Addressing** searches for the next empty slot. **Complexity**: Average $O(1)$ for all; Worst case $O(n)$ (if all keys hash to the same index).

D19 — **Circuit Breaker**: 1. **Closed**: Traffic flows normally. 2. **Open**: Errors detected; traffic is blocked immediately to allow the service to recover. 3. **Half-Open**: Periodically allows a few requests to see if the service is healthy. It prevents **cascading failures** by failing fast rather than waiting for timeouts, complementing **exponential backoff** which prevents overwhelming a recovering service.

D20 — **Optimistic**: Assumes no conflict; checks for changes before committing (uses **versioning/ETags**). **Pessimistic**: Assumes conflict; locks the record (e.g., `SELECT FOR UPDATE`). Use **Optimistic** for high-concurrency/low-conflict web apps; use **Pessimistic** for high-conflict/critical financial transactions.
