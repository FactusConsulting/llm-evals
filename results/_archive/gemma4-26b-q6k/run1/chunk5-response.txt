**G1** — An **array** has a fixed size defined at compile time. A **slice** is a descriptor (header) containing a pointer to an underlying array, a length, and a capacity. When `append` exceeds capacity, Go allocates a new, larger underlying array, copies the old elements, and returns a new slice pointing to the new memory.

**G2** — `var x int` declares a variable and initializes it to its zero value (`0`). `x := 0` is short variable declaration, which declares and initializes in one step. You **cannot** use `:=` outside of a function body (at the package level).

**G3** — A **goroutine** is a lightweight execution unit managed by the Go runtime. Unlike OS threads, which have large stacks (MBs) and require expensive context switches via the kernel, goroutines have small, growable stacks (KBs) and are multiplexed onto OS threads by the Go scheduler. The **GMP model** consists of **G** (Goroutines), **M** (Machine/OS Threads), and **P** (Processors/Logical Contexts). `P` acts as a resource that holds the local run queue of `G`s, allowing `M` to execute `G`s efficiently.

**G4** — **Channels** are pipes used for communication between goroutines. An **unbuffered channel** requires both sender and receiver to be ready simultaneously (synchronous). A **buffered channel** has a capacity; sends only block when the buffer is full, and receives only block when the buffer is empty. Sending to a **full buffered channel** blocks the sending goroutine until a receiver reads a value.

**G5** — The `context` package manages request lifecycles, cancellation signals, and deadlines.
```go
ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

**G6** — Go uses **implicit satisfaction**: a type satisfies an interface simply by implementing its methods; there is no `implements` keyword. This allows for decoupled, "duck-typed" behavior. `interface{}` (or `any`) can hold any value because every type implements at least zero methods. It is **powerful** for generic-like behavior but **dangerous** because it bypasses type safety, requiring runtime type assertions that can panic.

**G7** — The code is unsafe due to a **data race**. The Go memory model does not guarantee that writes in one goroutine are visible to another without explicit synchronization. The compiler or CPU might reorder the instructions or cache `ready` in a register, causing the loop to run forever or `data` to appear empty. **Correct alternatives**: Use a `sync.Mutex`, `sync/atomic` for the `ready` flag, or (most idiomatically) use a **channel** to signal completion.

**G8** — `sync.Mutex` is an exclusive lock (one holder). `sync.RWMutex` allows multiple concurrent readers OR one single writer. Use `sync.RWMutex` when you have many reads and few writes. Use `sync.Map` for high-concurrency scenarios where keys are stable (not frequently added/deleted) or when multiple goroutines read/write disjoint sets of keys. **Trade-offs**: `sync.Map` reduces lock contention via atomic operations but is slower for standard use cases than a `map + Mutex`.

**G9** — **Go modules** manage dependencies. `go.mod` defines the module path and dependency versions. `go.sum` contains cryptographic hashes to ensure dependency integrity. `go mod tidy` adds missing modules and removes unused ones. **MVS (Minimum Version Selection)** is the algorithm Go uses to pick the lowest compatible version of a dependency that satisfies all requirements, ensuring reproducible builds.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common **gotcha** is using `defer` inside a loop; the deferred calls don't execute until the *outer* function returns, which can lead to resource exhaustion (e.g., many open file handles).

**G11** — A **pointer** is a variable that stores the memory address of another value. The zero value is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs automatically when a package is initialized. It runs after variable declarations but before `main()`. A package can have **multiple** `init()` functions, and they execute in the order they appear in the source code.

**G13** — `new(T)` allocates zeroed memory for a type `T` and returns a **pointer** (`*T`). `make(T, args)` is used only for **slices, maps, and channels**; it initializes the internal data structures and returns an initialized value (not a pointer).

**G14** — Errors are values. The `error` interface requires a single `Error() string` method. The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error wraps a specific error value (like `io.EOF`), while `errors.As` attempts to cast an error to a specific error type. `==` only works for simple equality and fails if the error is wrapped.

**G15** — 
- **map**: `nil`
- **slice**: `nil`
- **channel**: `nil`
- **struct**: All fields set to their respective zero values.

**G16** — A **race condition** occurs when two or more goroutines access the same memory concurrently, and at least one access is a write. The `-race` flag enables the Go race detector, which instruments code to find unsynchronized access.
*Example Fix*:
```go
// Race: count++
// Fix:
var mu sync.Mutex
mu.Lock()
count++
mu.Unlock()
```

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch` (which evaluates expressions), `select` evaluates channel operations. If multiple cases are ready, one is chosen **pseudo-randomly**. To implement a **timeout**:
```go
select {
case res := <-ch:
    fmt.Println(res)
case <-time.After(time.Second):
    fmt.Println("timeout")
}
```

**G18** — **Escape analysis** is a compiler optimization that determines if a variable can reside on the **stack** (fast, automatically cleaned up) or must "escape" to the **heap** (slower, managed by GC). The compiler decides based on variable scope and whether a pointer to the variable is passed outside the function. Use `go build -gcflags="-m"` to inspect decisions. Minimizing heap allocations reduces GC pressure and improves performance.

**G19** — `reflect.Type` describes the type (e.g., `int`, `struct`), while `reflect.Value` represents the actual data. **Performance cost**: Reflection is significantly slower than static code because it involves runtime type checking and dynamic dispatch. Use it for generic libraries (like JSON encoders), but prefer **code generation** (e.g., `stringer`) for performance-critical logic.

**G20** — `//go:embed` allows including files into the binary at compile time. It supports single files, directories, or patterns. It returns an `embed.FS` which implements the `io/fs.FS` interface. **Limitations**: It cannot embed files that are not part of the module or files that are excluded by build constraints.

---

**R1** — **Ownership** manages memory without a GC. 
1. Each value in Rust has a variable called its *owner*.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable string. `&str` is an immutable string slice (a reference). Use `String` when you need to own/mutate data; use `&str` in function signatures to allow the function to accept both `String` and `&str` (more flexible).

**R3** — **Borrowing** allows accessing data without taking ownership. 
- **Shared references (`&T`)**: You can have any number of immutable references.
- **Mutable references (`&mut T`)**: You can have exactly **one** mutable reference at a time, and no other references (shared or mutable) can exist simultaneously. This prevents data races.

**R4** — `Result<T, E>` is for recoverable errors; `Option<T>` is for values that might be `None`. The `?` operator performs early return if the result is an `Err` or `None`.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

**R5** — `Box<T>`: Single ownership on the heap. `Rc<T>`: Reference counted (non-thread-safe) for multiple owners in a single thread. `Arc<T>`: Atomic reference counted (thread-safe) for multiple owners across threads.

**R6** — **Traits** define shared behavior (similar to interfaces). **Trait objects (`dyn Trait`)** use dynamic dispatch (runtime lookup), allowing for heterogeneous collections. **Generics with trait bounds (`T: Trait`)** use static dispatch (monomorphization), which is faster as the compiler generates specific code for each type.

**R7** — It fails because the compiler cannot guarantee that the returned reference lives as long as the input references. **Fix**: Add lifetime annotations: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8** — `Send` means a type can be transferred to another thread. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send` because its reference count is not updated atomically, leading to data races. `Arc<T>` uses atomic operations, making it `Send` and `Sync`.

**R9** — Rust's async is **poll-based**. A `Future` is a state machine that does nothing until `poll()` is called. An **executor** (like Tokio) manages these futures, polling them when they are ready. Unlike Go's goroutines (which are preemptively scheduled by a runtime), Rust's async is cooperative and requires an external runtime.

**R10** — `unsafe` allows: 1. Dereferencing raw pointers. 2. Calling unsafe functions (e.g., C FFI). 3. Accessing/modifying mutable static variables. It is justified when implementing low-level primitives or interfacing with hardware/C libraries where the compiler cannot prove safety.

**R11** — **Pattern matching** (`match`) is a control flow construct that compares a value against a series of patterns. `if let` is a concise way to handle a single pattern. The compiler enforces **exhaustiveness**, ensuring every possible value of a type is handled.

**R12** — `Vec<T>` is a growable heap-allocated array. `[T; N]` is a fixed-size array on the stack. When a `Vec` exceeds capacity, it allocates a new, larger block of memory on the heap, copies the elements, and deallocates the old memory.

**R13** — **Enums** in Rust are "sum types" (Algebraic Data Types); they can hold data in each variant. In C/Java, enums are just sets of named integers. `Option<T>` is an enum with `Some(T)` and `None`, replacing `null` to force explicit handling of missing values.

**R14** — `impl` blocks define methods for a type. 
- `&self`: Immutable borrow.
- `&mut self`: Mutable borrow.
- `self`: Consumes the object (takes ownership).
**Associated functions** (like `String::new()`) do not take `self` and are called via the type name.

**R15** — `derive` automatically implements traits. Examples: `Debug` (printing), `Clone` (explicit copy), `PartialEq` (equality), `Serialize` (to JSON/etc). You cannot derive a trait if its implementation requires logic the compiler cannot automatically generate (e.g., custom equality).

**R16** — `Cow<'a, T>` is an enum representing either borrowed or owned data. It is useful for functions that only need to mutate data if it doesn't meet certain criteria, avoiding an allocation if the data is already in the desired format.

**R17** — `mod` declares a module; `use` brings paths into scope; `pub` makes items public. The file system maps to modules (e.g., `mod foo;` looks for `foo.rs`). In 2018, the "module system" was simplified, making it easier to declare modules without needing `mod.rs` files.

**R18** — `Pin<T>` ensures that the data it points to cannot be moved in memory. This is critical for **self-referential structs** (common in `async` state machines) where a pointer inside the struct points to another field within the same struct. `Unpin` is an auto-trait for types that *can* be moved safely.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching to replace code. **Procedural macros** are functions that operate on the AST (Abstract Syntax Trees). **Hygiene** ensures that macro-generated code does not accidentally clash with variables in the user's scope.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use, and what you do use couldn't be implemented more efficiently by hand. **Monomorphization** turns generics into specialized code at compile time; **Iterators** are optimized into tight loops; **Static dispatch** resolves method calls at compile time, eliminating runtime overhead.
