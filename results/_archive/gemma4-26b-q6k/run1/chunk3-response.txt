**Kubernetes**

**K1** — A **Deployment** is for stateless applications; pods are interchangeable and can be replaced without identity loss. A **StatefulSet** is for stateful applications; it provides stable, unique network identifiers (pod-0, pod-1) and persistent storage that remains attached to the specific pod identity even after rescheduling.

**K2** — A **ClusterIP** service uses `kube-proxy` (via iptables or IPVS) on each node to intercept traffic sent to the Service's Virtual IP (VIP) and perform DNAT (Destination Network Address Translation) to redirect it to the actual IP of a healthy backend pod.

**K3** — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a request for storage by a user (the "ticket"). **StorageClass** is a template that allows for dynamic provisioning. **Relationship:** A user creates a PVC referencing a StorageClass; the control plane then automatically provisions a PV that matches the PVC's requirements.

**K4** — 
1. `kubectl logs <pod>`: Check application-level errors/stack traces.
2. `kubectl describe pod <pod>`: Check for exit codes (e.g., 137 for OOMKilled) and events.
3. `kubectl get events`: Look for cluster-level issues like failed volume mounts or image pull errors.
4. `kubectl exec` (if possible) or local testing: Verify environment variables, config files, and connectivity to dependencies.

**K5** — **CoreDNS** provides service discovery by translating Kubernetes service names into ClusterIPs. If CoreDNS pods are down, internal service-to-service communication via DNS names will fail, effectively breaking most microservice interactions.

**K6** — The scheduler uses a two-step process:
1. **Filtering (Predicates):** It removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, node selectors, taints).
2. **Scoring (Priorities):** It ranks remaining nodes based on "best fit."
**Factors:** 
- **Resource Availability:** Prefer nodes with more free allocatable capacity.
- **Image Locality:** Prefer nodes that already have the required container images.
- **Affinity/Anti-affinity:** Respecting rules to keep pods together or apart.

**K7** — **Yes**, it will be scheduled because the pod's *request* (256Mi) fits within the remaining 500Mi (3.5GB used + 256Mi < 4GB). However, if it uses **600Mi**, it exceeds its *limit* (512Mi), and the Linux kernel will trigger an **OOMKill** (Out of Memory Kill) on the container.

**K8** — 
1. **External LB** receives the request and forwards it to the **Ingress Controller** (NGINX) service.
2. **Ingress Controller** (running as a pod) receives the traffic and matches the Host/Path against **Ingress** rules.
3. The Controller looks up the **Endpoints** object associated with the target **Service**.
4. **kube-proxy** (via iptables/IPVS) ensures the traffic is routed from the controller pod to the specific **Application Pod** IP.

**K9** — A **NetworkPolicy** is a set of rules defining how pods are allowed to communicate with each other and other network endpoints. By default, if no policy exists, all traffic is allowed (**allow-all**). Once a policy is applied to a pod, it enters "isolation mode," and only traffic explicitly permitted by the policy is allowed.

**K10** — **RollingUpdate** replaces old pods with new ones gradually to ensure zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when the application does not support multiple versions running simultaneously (e.g., due to database schema locks or singleton requirements).

**K11** — A **Namespace** is a virtual cluster within a physical cluster used to partition resources. Default namespaces: `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

**K12** — `kubectl describe` provides deep metadata. Unlike `get`, it shows:
1. **Events:** Recent lifecycle events (e.g., Pulling, Started, Failed).
2. **Container Status:** Specific exit codes and reason (e.g., OOMKilled).
3. **Conditions:** Detailed status of PodReady, PodInitialized, etc.

**K13** — A **ConfigMap** stores non-confidential configuration data in key-value pairs. 
**Methods:** 
1. **Environment Variables:** Injecting keys as env vars in the pod spec.
2. **Volume Mounts:** Mounting the ConfigMap as a file inside the container's filesystem.

**K14** — 
- **ClusterIP:** Internal IP, accessible only within the cluster.
- **NodePort:** Exposes the service on a static port on every Node's IP.
- **LoadBalancer:** Provisions an external cloud load balancer to route traffic to the service.

**K15** — A **DaemonSet** ensures that a copy of a specific pod runs on *all* (or a subset of) nodes in the cluster. Use it for infrastructure tasks like log collectors (Fluentd), monitoring agents (Prometheus Node Exporter), or networking plugins.

**K16** — **Taints** are applied to **Nodes** to repel pods (e.g., "don't put anything here unless it's special"). **Tolerations** are applied to **Pods** to allow them to stay on tainted nodes. **Node Affinity** is applied to **Pods** to attract them to specific nodes.
**Use Case:** Use Taints/Tolerations to reserve GPU nodes for ML workloads; use Node Affinity to ensure a web app runs in a specific availability zone.

**K17** — An **Operator** is a custom controller that uses **Custom Resource Definitions (CRDs)** to manage complex, stateful applications. Unlike a standard controller (which manages simple objects like Pods), an Operator encodes "human operational knowledge" (e.g., how to perform a database backup or upgrade) into software.

**K18** — Etcd uses the **Raft consensus algorithm** for strong consistency. If quorum is lost, the cluster becomes read-only or fails entirely. To recover from losing 2/3 nodes: You must restore from a recent snapshot onto a new 3-node cluster, as the remaining node cannot achieve a majority to elect a leader.

**K19** — **Role** (namespace-scoped permissions), **ClusterRole** (cluster-wide permissions), **RoleBinding** (assigns Role to user in a namespace), **ClusterRoleBinding** (assigns ClusterRole to user cluster-wide).
**Manifest:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: dev-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: dev-ns
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — By default, `ndots:5` means if a name has fewer than 5 dots, the resolver tries appending all local search domains (e.g., `google.com.dev-ns.svc.cluster.local`) before trying the name itself. This causes multiple failed DNS queries. 
**Fix:** Use `dnsConfig` in the Pod spec to set `ndots: 1` or use fully qualified domain names (ending in a dot) to bypass the search path.

**Development**

**D1** — **Merge** combines histories by creating a new "merge commit." **Rebase** moves the entire branch to begin on the tip of the main branch, creating a linear history. **Avoid rebasing** on public/shared branches, as it rewrites history and breaks other developers' work.

**D2** — **TCP** is connection-oriented, reliable, and ensures ordered delivery (e.g., HTTP, SSH). **UDP** is connectionless, faster, but does not guarantee delivery or order (e.g., DNS, VoIP/Streaming).

**D3** — A **race condition** occurs when the outcome of a process depends on the unpredictable timing/sequence of events. 
**Example:** Two threads incrementing a shared variable `counter++` simultaneously. Both read `5`, both add `1`, and both write `6` back, when the result should have been `7`.

**D4** — **Symmetric** uses one shared key for both encryption and decryption. **Asymmetric** uses a public key for encryption and a private key for decryption. In **TLS**, asymmetric encryption is used to securely exchange a symmetric session key, which is then used for the actual data transfer (faster).

**D5** — A **layer** is a read-only filesystem change (e.g., installing a package). **Layer caching** means Docker reuses existing layers if the instruction and context haven't changed. **Best practice:** Order Dockerfile commands from "least likely to change" to "most likely to change" (e.g., `COPY package.json` before `COPY .`) to maximize cache hits.

**D6** — 
1. **Check Application Logs:** Look for internal errors or timeouts.
2. **Check Infrastructure/Resource usage:** Is the service hitting CPU/Memory limits or OOMing?
3. **Check Upstream Dependencies:** Is the database or a third-party API slow/down?
4. **Check Network/Load Balancer:** Are there connection limits or health check failures?

**D7** — **CAP Theorem:** A distributed system can only provide two of three: Consistency, Availability, or Partition Tolerance. 
- **CP (Consistency/Partition Tolerance):** **HBase** (prioritizes data accuracy; if a partition occurs, it shuts down to prevent stale reads).
- **AP (Availability/Partition Tolerance):** **Cassandra** (prioritizes uptime; allows reads/writes during a partition, resolving conflicts later).

**D8** — **Horizontal scaling** adds more instances (nodes/pods). **Vertical scaling** adds more resources (CPU/RAM) to existing instances. **Patterns for horizontal scaling:** Statelessness, Load Balancing, and Sharding/Partitioning.

**D9** — An **environment variable** is a dynamic value used by processes to define configuration. To persist on Linux, add `export VAR_NAME=value` to your `~/.bashrc` or `~/.zshrc` file.

**D10** — **JSON** is data-oriented, uses braces `{}` and brackets `[]`, and is strict. **YAML** is human-readable, uses indentation, and is more concise. **Advantage JSON:** Faster for machines to parse. **Advantage YAML:** Easier for humans to write/read configuration.

**D11** — **REST API** is an architectural style for networked applications. 
- **GET:** Retrieve data.
- **POST:** Create new data.
- **PUT:** Update/Replace existing data.
- **DELETE:** Remove data.

**D12** — **Version pinning** is specifying the exact version of a dependency (e.g., `library==1.2.3` instead of `library>=1.0`). It is vital for **reproducible builds** to ensure that a build today results in the exact same binary as a build six months from now.

**D13** — **Compiled:** Translated to machine code before execution (e.g., C++, Go). **Interpreted:** Read and executed line-by-line by another program (e.g., Python, JavaScript).

**D14** — A **Reverse Proxy** sits in front of web servers and forwards client requests to them (protecting the server). A **Forward Proxy** sits in front of clients and forwards their requests to the internet (hiding the client). 
**Servers:** **NGINX** (use case: Load balancing/SSL termination); **HAProxy** (use case: High-performance TCP/HTTP load balancing).

**D15** — A **Deadlock** is a state where a set of processes are blocked because each is holding a resource and waiting for another held by another process. 
**Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual Consistency** means that if no new updates are made, all accesses will eventually return the last updated value. **Cassandra** uses tunable consistency: `ANY`, `ONE`, `QUORUM`, `ALL`. A user can choose `QUORUM` for a balance of speed and consistency.

**D17** — **mTLS** requires both client and server to present certificates to prove identity. 
**Handshake:** 1. Client connects; 2. Server sends cert; 3. Client verifies; 4. Client sends its own cert; 5. Server verifies; 6. Both exchange symmetric keys. 
**Usage:** Commonly used in **Service Meshes** (like Istio) for zero-trust internal networking.

**D18** — A **Hash Table** uses a hash function to map keys to array indices. 
- **Chaining:** Each index points to a linked list of entries. 
- **Open Addressing:** Finds the next empty slot in the array.
**Complexity:** 
- **Average:** $O(1)$ for insertion, lookup, and deletion. 
- **Worst:** $O(n)$ (when all keys hash to the same index).

**D19** — The **Circuit Breaker** prevents a system from repeatedly trying an operation that is likely to fail.
- **Closed:** Normal operation; requests pass through.
- **Open:** Failure threshold reached; requests fail immediately without hitting the service.
- **Half-Open:** After a timeout, allows a few "test" requests to see if the service recovered.
It prevents **cascading failures** by stopping the "retry storm." It works with **exponential backoff** to ensure retries don't overwhelm a recovering service.

**D20** — **Optimistic:** Assumes conflicts are rare; checks for changes before committing (e.g., using a `version` column). **Pessimistic:** Assumes conflicts will happen; locks the record immediately. 
**Choice:** Use **Optimistic** for high-concurrency web apps (better scaling). Use **Pessimistic** (e.g., `SELECT FOR UPDATE` in SQL) for high-value financial transactions where data integrity is absolute and contention is expected.
