## JavaScript / TypeScript

**JS1**: `var` is function-scoped and hoisted with `undefined`. `let` and `const` are block-scoped and hoisted but remain in a "Temporal Dead Zone" until declaration. `const` prevents reassignment of the identifier. **Hoisting** is the behavior where variable and function declarations are moved to the top of their scope during compilation.

**JS2**: The **Event Loop** manages asynchronous execution. The **Call Stack** tracks function execution (LIFO). The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority and is emptied completely after every task. The **Macrotask Queue** (setTimeout, setInterval, I/O) is processed one task at a time after the microtask queue is empty.

**JS3**: A **closure** is a function that remembers its lexical scope even when executed outside that scope. *Example*: A function returning another function that increments a private counter. *Bug*: Using `var` in a `for` loop with an async callback (all iterations share the same variable). *Fix*: Use `let` to create a new binding for each iteration.

**JS4**: **Promise** is an object representing eventual completion/failure. **async/await** is syntactic sugar for Promises. Error handling: `try/catch` with `async/await`; `.catch()` with Promises. `Promise.all` rejects if *any* promise fails; `Promise.allSettled` waits for all to finish regardless of outcome.

**JS5**: **Interface** is primarily for defining object shapes and supports declaration merging. **Type** is more flexible, allowing unions, primitives, and intersections. Use `interface` for public APIs/extensible objects; use `type` for complex logic/unions. **Discriminated Unions** use a common literal property (e.g., `type: 'circle'`) to narrow types in a union.

**JS6**: **Prototypal inheritance** means objects inherit properties from a prototype object via the prototype chain. `Object.create(proto)` creates a new object with the specified prototype. **ES6 Classes** are "syntactic sugar" over prototypes; they use the same underlying prototype chain mechanism but provide a cleaner syntax.

**JS7**: `this` refers to the execution context. **Binding Rules**: 1. `new` (new instance), 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (the object before the dot), 4. Default (global object or `undefined` in strict mode). `bind()` returns a new function with a fixed `this`. You cannot re-bind a function once it is bound.

**JS8**: `WeakRef` allows holding a reference to an object without preventing GC. `FinalizationRegistry` runs a callback after an object is GC'd. Use them for caches or cleanup logic. `WeakMap` keys must be objects so that if the object is only held as a key, it can be garbage collected, preventing memory leaks.

**JS9**: V8 uses **Hidden Classes** (shapes) to optimize property access and **Inline Caching** to remember where properties are located in memory. **Deoptimization** occurs when code assumptions change (e.g., a property is added to an object with a stable hidden class). *Patterns*: Changing object shapes dynamically or passing different types to the same function.

**JS10**: **Tree-shaking** is dead-code elimination. It works with **ES Modules** because `import/export` are static (analyzable at compile time). **CommonJS** uses `require()`, which is dynamic/runtime, making it impossible for tools to safely determine what is unused without running the code.

**JS11**: `null` is an intentional absence of value; `undefined` means a variable is declared but not assigned. `==` performs type coercion; `===` checks value and type. `??` (nullish coalescing) returns the right side only if the left is `null` or `undefined`. `?.` (optional chaining) short-circuits if the reference is nullish.

**JS12**: `map()` creates a new array by transforming every element. `filter()` creates a new array with elements that pass a test. `reduce()` reduces an array to a single value. With an **initial value**, `reduce` uses it as the starting accumulator. `flatMap()` maps then flattens by one level; useful for handling nested arrays or filtering while mapping.

**JS13**: **Template literals** use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** allow a function to parse the template literal. *Example*: `` const sql = tag`SELECT * FROM ${table}`; `` where `tag` escapes inputs to prevent SQL injection.

**JS14**: **Destructuring** extracts values from arrays/objects. *Object*: `{a, b} = obj`. *Array*: `[a, b] = arr`. *Default*: `{a = 1} = obj`. *Renaming*: `{old: newName} = obj`. The **rest operator** (`...`) collects remaining elements into a new array/object.

**JS15**: `for...in` iterates over enumerable *keys* (properties) of an object. `for...of` iterates over *values* of an iterable (array, string). Avoid `for...in` on arrays because it iterates over indices as strings and may include inherited properties.

**JS16**: **Generics** allow components to work with multiple types. **Constraints** (`T extends U`) limit the types allowed. **Conditional Types** (`T extends U ? X : Y`) act like ternary operators for types. **Infer** extracts a type from within another type. *Example*: `type GetReturn<T> = T extends (...args: any[]) => infer R ? R : never;`

**JS17**: **CommonJS** is synchronous, uses `require`, and is the Node.js default. **ES Modules** are asynchronous, use `import/export`, and are the web standard. Node.js handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ES Modules.

**JS18**: TS is **structural** (shapes matter, not names). **Excess property checks** occur when assigning an object literal directly to a type. `extends` is for adding properties; `satisfies` validates a type without changing the inferred type of the variable. **Variance** (4.7+) handles how subtyping works for function parameters (`in`) and return types (`out`).

**JS19**: `Proxy` wraps an object to intercept operations (get, set, etc.). `Reflect` provides methods to perform those same operations (often used inside a Proxy). *Example*: A Proxy can intercept `set` to validate that a property is a number before assigning it.

**JS20**: `SharedArrayBuffer` allows multiple threads (Web Workers) to share a raw memory buffer. `Atomics` provides static methods to perform thread-safe operations (add, load, store) to prevent race conditions. `Atomics.wait/notify` allows a thread to sleep until another thread signals it.

## Bash

**B1**: `$@` represents all arguments as separate words. `$*` represents all arguments as a single string. `"$@"` preserves individual arguments (even with spaces); `"$*"` merges them into one string.

**B2**: `set -e` (exit on error), `-u` (exit on unset variables), `-o pipefail` (return exit code of the last command in a pipe that failed).

**B3**: `$(command)` is command substitution (executes and returns output). `` `command` `` is the older, less robust version. `$((expression))` is for arithmetic evaluation. `expr` is an external program for math.

**B4**: **Process substitution** `<(command)` treats the output of a command as a temporary file. *Example*: `diff <(ls dir1) <(ls dir2)` compares the output of two commands without creating physical files.

**B5**: Use `while read -r f; do ... done < <(find . -type f)`. `for f in $(ls)` is dangerous because it splits filenames containing spaces or newlines into multiple items.

**B6**: `<<EOF` is a **here document** (multi-line input). `<<<` is a **here string** (passes a single string to stdin). `<<-EOF` strips leading tabs from the document.

**B7**: 
1. `cmd > file 2>&1`: Redirects stdout to file, then redirects stderr to where stdout is currently pointing (the file).
2. `cmd 2>&1 > file`: Redirects stderr to stdout (the terminal), then redirects stdout to the file. Result: stderr goes to terminal, stdout to file.
3. `cmd &> file`: Redirects both stdout and stderr to the file.

**B8**:
```bash
lockdir="/tmp/mylock"
mkdir "$lockdir" 2>/dev/null || exit 1
trap 'rmdir "$lockdir" 2>/dev/null' EXIT SIGTERM SIGINT
# Critical section here
```
`mkdir` is atomic at the OS level; if two processes try to `mkdir` the same path, only one succeeds. File creation (`> file`) is not inherently atomic for locking.

**B9**: `'...'` (single) treats everything literally. `"..."` (double) allows variable expansion and command substitution. No quotes allow word splitting and globbing. *Example*: `echo '$USER'` prints `$USER`; `echo "$USER"` prints `root`.

**B10**: `-e` (exists), `-d` (directory), `-r` (readable). `[ ]` is the standard POSH/POSIX test; `[[ ]]` is a Bash extension that is more powerful, supports regex (`=~`), and handles empty variables more gracefully without word splitting.

**B11**: `$?` (exit status of last command), `$$` (PID of current script), `$!` (PID of last background job), `$#` (number of arguments).

**B12**: `foo() { ... }` is the standard way. `function foo {}` is a Bash-specific extension. Both work similarly. Return values are handled via `return` (exit status 0-255) or by printing to stdout and capturing it with `$(foo)`.

**B13**: `PATH` is a colon-separated list of directories. Bash searches them in order. **Builtins** (e.g., `cd`) are inside the shell; **external** (e.g., `ls`) are files in `PATH`. Use `type <command>` to check.

**B14**: `trap` catches signals. `trap 'cleanup' EXIT ERR INT TERM`. Execution order depends on the signal; if multiple arrive, they are handled sequentially. `EXIT` is always called when the shell exits.

**B15**: `xargs` converts stdin to arguments. `find -print0 | xargs -0` handles filenames with spaces/newlines by using the null character as a delimiter. `xargs -P <N>` runs up to N processes in parallel.

**B16**: **Arrays**: `arr=(a b c)`. **Associative**: `declare -A map; map[key]=val`. Append: `arr+=("new")`. Iterate: `for i in "${!arr[@]}"; do ... done`. Length: `${#arr[@]}`.

**B17**: `(...)` is a **subshell** (new process, new variable scope). `{ ...; }` is a **group command** (same shell, same scope). Piping into a `while` loop creates a subshell, so variable changes inside the loop are lost when the loop ends.

**B18**: `SIGINT` (Ctrl+C), `SIGTERM` (termination request), `SIGHUP` (terminal closed), `SIGKILL` (immediate kill, cannot be caught). For graceful shutdown, use `trap` to catch `SIGTERM` and kill child PIDs.

**B19**:
```bash
process_log() { grep "$1" log.txt >> result.txt; }
export -f process_log
split -l 1000 log.txt part_
ls part_* | xargs -P 4 -I {} bash -c 'process_log "$0"' {}
rm part_*
```
*Trade-offs*: Parallelism speeds up processing but increases I/O contention. Error propagation is hard; use `set -e` or check exit codes of `xargs` processes.

**B20**: `exec` replaces the current shell process with the new command. `exec 3>file` opens a file descriptor. `exec 3>&-` closes it. A **coprocess** (`coproc`) allows a background process to communicate with the shell via pipes.

## PowerShell

**PS1**: `Write-Output` sends objects to the pipeline. `Write-Host` writes directly to the host (console). `Write-Host` cannot be captured by a pipeline, making it bad for automation.

**PS2**: The **pipeline** passes objects from one command to the next. `ForEach-Object` is a cmdlet designed for the pipeline (efficient for large streams). `foreach` is a language keyword (faster for in-memory collections).

**PS3**: `[PSCustomObject]` is an ordered object with properties, ideal for data output. `[hashtable]` is an unordered collection of key-value pairs. Use `[PSCustomObject]` for structured data; convert via `[PSCustomObject]$hash`.

**PS4**: **Terminating** errors stop execution; **non-terminating** continue. `-ErrorAction` (per command) and `$ErrorActionPreference` (global) control this. `try/catch` only catches terminating errors (unless `ErrorAction` is set to `Stop`).

**PS5**: **Splatting** passes a hashtable as parameters to a command: `$p = @{Name='A'}; Get-Service @p`. It is cleaner than long command lines. It differs from passing a single hashtable parameter because it unpacks the keys as parameter names.

**PS6**: **Remoting** allows running commands on remote machines. `Invoke-Command -ComputerName` runs a scriptblock on the target. `Enter-PSSession` is interactive. It uses **WS-Management (WinRM)** or **SSH**.

**PS7**: The function returns an **Object[]** (array) because `$result +=` converts the array to a new array each time. If 0 items, it returns `$null`. The correct pattern is to use the pipeline: `foreach ($i in $items) { $i }` or return a collection directly.

**PS8**: A **scriptblock** is a block of code `{}`. To pass to remote sessions, use `Invoke-Command`. The **double-hop problem** occurs when a remote session cannot use your credentials to access a *third* machine. Solve with **CredSSP** or **JEA**.

**PS9**: `@()` is an empty array; `[array]` is the type. To force a single result into an array, use `@($result)`. Indexing `$null` returns `$null`; indexing an empty array returns `$null`.

**PS10**: `-eq` (equals), `-like` (wildcard), `-match` (regex), `-contains` (checks if collection contains value), `-in` (checks if value is in collection). `-ceq` is case-sensitive. `-contains` is for collections; `-match` is for string pattern matching.

**PS11**: A **module** extends PowerShell functionality. `.psm1` is the script, `.psd1` is the manifest (metadata), and binary modules are DLLs. `Import-Module` loads them into the session.

**PS12**: `"..."` allows interpolation (`"$var"`). `'...'` is literal. Use `$()` for expressions: `"Result: $($obj.Prop)"`. **Here-strings** (`@"..."@`) allow multi-line strings without escaping quotes.

**PS13**: `Get-Member` shows the type, properties, and methods of an object. **Properties** are data; **Methods** are actions; **NoteProperties** are custom properties added to an object. `Select-Object` picks properties; `Where-Object` filters objects.

**PS14**: **PowerShell Classes** are more formal than functions. They are closer to C# but lack some advanced features like full interface implementation in older versions. Use classes for complex data structures; use functions for procedural logic.

**PS15**: `[CmdletBinding()]` makes a function behave like a professional cmdlet (adds `-Verbose`, `-ErrorAction`, etc.). `SupportsShouldProcess` enables `-Confirm`. `ValueFromPipeline` allows input via `|`. `Begin`, `Process`, and `End` allow fine-grained control over pipeline execution.

**PS16**: **Providers** allow PowerShell to treat different data stores (Registry, Cert, Env) like a file system. `Get-ChildItem Registry::HKEY_LOCAL_MACHINE` works just like `Get-ChildItem C:\`.

**PS17**: A **runspace** is a single thread of execution. A **runspacepool** manages multiple runspaces. `ForEach-Object -Parallel` (v7+) is a high-level wrapper that manages a thread pool automatically.

**PS18**: **PSScriptAnalyzer** is a static analysis tool. It uses **rules** to check code against best practices. You can suppress rules with `#PSScriptAnalyzer Ignore`. It integrates into CI/CD via `Invoke-ScriptAnalyzer`.

**PS19**: `$using:var` is used to bring a local variable into a remote/parallel scope. `$args` is for positional parameters. **Serialization** occurs when passing objects over the wire; complex objects (like active handles) may lose their methods/type identity when converted to CLIXML.

**PS20**: **DSC** manages system configuration. **Configurations** are the desired state; **Resources** are the logic to reach that state; **LCM** is the engine on the node. DSC (Windows) is pull/push based; in modern infra, it has been largely replaced by **Terraform** and **Ansible**.
