## Go

**G1**: An **array** has a fixed size defined at compile time; its size is part of its type. A **slice** is a descriptor for a contiguous segment of an array, containing a pointer, length, and capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array, copies the old elements to it, and returns a new slice descriptor pointing to the new array.

**G2**: `var x int` declares a variable and initializes it to its **zero value** (0). `x := 0` is **short variable declaration**, which declares and initializes in one step. You **cannot** use `:=` outside of a function body (at the package level).

**G3**: A **goroutine** is a lightweight, application-level thread managed by the Go runtime. Unlike OS threads, which have large fixed stacks (MBs), goroutines start with small, growable stacks (KBs). The **GMP model** consists of **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts). The scheduler multiplexes $M$ goroutines onto $N$ OS threads using $P$ to ensure efficient work-stealing and non-blocking execution.

**G4**: **Channels** are typed conduits used for communication and synchronization between goroutines. An **unbuffered channel** requires both sender and receiver to be ready simultaneously (synchronous). A **buffered channel** allows sending until the buffer is full. Sending to a **full buffered channel** blocks the sender until a receiver takes a value.

**G5**: The `context` package manages deadlines, cancellation signals, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

**G6**: Go uses **implicit satisfaction**: a type satisfies an interface simply by implementing its methods; no `implements` keyword is needed. This allows for decoupling. `interface{}` (or `any`) is an interface with zero methods, meaning every type satisfies it. It is **powerful** because it allows for generic data handling, but **dangerous** because it bypasses type safety and requires type assertions/reflections.

**G7**: The code is unsafe due to **memory visibility** issues. Without explicit synchronization, the compiler or CPU may reorder instructions or cache `ready` in a register, meaning the loop might never see `ready` change to `true`, or it might see `ready == true` but still see the old value of `data`. **Correct alternatives**: Use `sync.Mutex`, `sync/atomic`, or a **channel** to establish a "happens-before" relationship.

**G8**: `sync.Mutex` provides exclusive access. `sync.RWMutex` allows multiple simultaneous readers OR one exclusive writer. Use `sync.RWMutex` when you have many readers and infrequent writers. Use `sync.Map` for "append-only" workloads or when multiple goroutines read/write disjoint sets of keys to reduce lock contention. `sync.Map` has higher overhead for standard use cases but scales better under heavy contention.

**G9**: **Go modules** manage dependencies. `go.mod` defines the module path and dependency requirements. `go.sum` contains cryptographic hashes to ensure dependency integrity. `go mod tidy` adds missing dependencies and removes unused ones. **MVS (Minimum Version Selection)** selects the *lowest* version of a dependency that satisfies all constraints in the graph, ensuring reproducible builds.

**G10**: `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In-First-Out)** order. A common **gotcha** is using `defer` inside a loop; since defers only execute when the *function* returns, not the loop iteration, this can cause resource exhaustion (e.g., leaking file descriptors).

**G11**: A **pointer** is a variable that stores the memory address of another value. The zero value is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: "val"}`.

**G12**: `init()` is a special function that runs automatically when a package is initialized. It runs after variable declarations but before `main()`. A package can have **multiple** `init()` functions; they execute in the order they appear in the source code (within the same package) and in the order of package dependency resolution.

**G13**: `make` is used for **slices, maps, and channels**; it initializes the internal data structures and returns an initialized (non-nil) value. `new` allocates zeroed memory for any type and returns a **pointer** to that memory.

**G14**: Error handling is explicit. `error` is a built-in interface with an `Error() string` method. The idiomatic pattern is to return `error` as the last return value and check `if err != nil`. `errors.Is` checks if an error matches a specific value (useful for wrapped errors), while `errors.As` checks if an error matches a specific type.

**G15**: 
- **Map**: `map[K]V`. Zero value: `nil`.
- **Slice**: `[]T`. Zero value: `nil`.
- **Channel**: `chan T`. Zero value: `nil`.
- **Struct**: `struct{...}`. Zero value: All fields set to their respective zero values.

**G16**: A **race condition** occurs when two or more goroutines access the same memory concurrently, and at least one access is a write. The `-race` flag enables the runtime data race detector.
*Example*: Two goroutines incrementing `count++`. 
*Fix*: Wrap the increment in a `sync.Mutex` or use `atomic.AddInt64`.

**G17**: `select` lets a goroutine wait on multiple communication operations. Unlike `switch` (which evaluates values), `select` evaluates channel operations. If multiple cases are ready, one is chosen **pseudo-randomly**. To implement a timeout:
```go
select {
case res := <-ch:
    fmt.Println(res)
case <-time.After(time.Second):
    fmt.Println("timeout")
}
```

**G18**: **Escape analysis** is a compiler phase that determines if a variable can reside on the **stack** or must "escape" to the **heap**. If a variable's lifetime exceeds the function scope (e.g., returning a pointer), it escapes to the heap. You can inspect this with `go build -gcflags="-m"`. It matters because heap allocation requires garbage collection, which adds latency and CPU overhead.

**G19**: `reflect` allows inspecting and manipulating objects at runtime. `reflect.Type` describes the type (e.g., `int`, `struct`), while `reflect.Value` holds the actual data. Reflection is **slow** due to runtime overhead and prevents some compiler optimizations. It is justified for generic libraries (like JSON encoders) but should be replaced by **code generation** (like `protobuf`) in performance-critical paths.

**G20**: `//go:embed` allows including static files in the binary at compile time. It works with `string`, `[]byte`, or `embed.FS`. It can embed single files or entire directories. It is limited to files within the same module and accessible via the `io/fs` interface.

## Rust

**R1**: **Ownership** is Rust's memory management system. Rules: 1. Each value has a variable called its *owner*. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2**: `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is an immutable string slice (a pointer and a length). Use `&str` in function signatures for maximum flexibility (it accepts both `&String` and `&str`). Use `String` when you need to own or modify the data.

**R3**: **Borrowing** allows accessing data without taking ownership. 
- **Shared references (`&T`)**: You can have any number of them, but the data cannot be mutated.
- **Mutable references (`&mut T`)**: You can have exactly one at a time, and no shared references can exist simultaneously. This prevents data races at compile time.

**R4**: `Option<T>` represents a value that might be absent (`Some(T)` or `None`). `Result<T, E>` represents success (`Ok(T)`) or failure (`Err(E)`). The `?` operator performs early return: if the result is `Err`, it returns the error; otherwise, it unwraps the `Ok` value.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5**: `Box<T>` is for heap allocation (owning). `Rc<T>` (Reference Counted) is for multiple ownership in a single thread. `Arc<T>` (Atomic Reference Counted) is for multiple ownership across multiple threads.

**R6**: **Traits** define shared behavior (similar to interfaces). Unlike Go, Rust uses **generics with trait bounds** (`T: Trait`) for **static dispatch** (resolved at compile time, zero cost) and **trait objects** (`&dyn Trait`) for **dynamic dispatch** (resolved at runtime via vtable).

**R7**: It fails because the compiler cannot determine if the returned reference refers to `x` or `y`, so it cannot guarantee the lifetime of the result. 
*Fix*: Add lifetime annotations: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8**: `Send` means a type can be transferred to another thread. `Sync` means a type can be safely shared between threads via references. `Rc<T>` is not `Send` or `Sync` because its internal reference count is not updated atomically, leading to data races. `Arc<T>` uses atomic operations, making it safe for concurrent use.

**R9**: Rust's async is **poll-based**. A `Future` is a state machine that does nothing until `poll()` is called. The **executor** (like Tokio) manages the polling of futures. Unlike Go's "always-on" goroutines, Rust futures are lazy and only make progress when polled, allowing for zero-cost async without a heavy runtime built into the language.

**R10**: `unsafe` allows bypassing certain compiler checks. You can: 1. Dereference raw pointers. 2. Call unsafe functions. 3. Access/modify mutable static variables. It is justified when interfacing with C code (FFI) or implementing low-level data structures that the compiler cannot prove safe.

**R11**: **Pattern matching** (`match`) allows destructuring data. `match` is **exhaustive** (must cover all cases). `if let` is a concise way to handle a single pattern and ignore others.

**R12**: `Vec<T>` is a growable, heap-allocated array. `[T; N]` is a fixed-size stack-allocated array. When a `Vec` exceeds capacity, it allocates a larger block of memory on the heap, copies the elements, and deallocates the old memory.

**R13**: **Enums** in Rust are "sum types" (can hold data in each variant), unlike C enums (integers). `Option<T>` is an enum (`Some(T)` or `None`) used to handle the absence of a value, effectively eliminating `null` pointer exceptions.

**R14**: `impl` blocks define methods for a type. `&self` borrows immutably; `&mut self` borrows mutably; `self` consumes the value (takes ownership). **Associated functions** do not take `self` and are called via `Type::func()`.

**R15**: `derive` automatically implements common traits. Examples: `Debug` (printing), `Clone` (deep copy), `PartialEq` (equality), `Serialize` (serde). You cannot derive a trait if the type's components do not also implement that trait.

**R16**: `Cow` (Clone-on-Write) is a smart pointer that can be either borrowed or owned. It is useful for functions that only need to mutate data if it's actually changed. It avoids allocation if the data remains borrowed.

**R17**: `mod` declares a module; `use` brings it into scope; `pub` makes it visible. Files map to modules (e.g., `mod foo` looks for `foo.rs`). Since 2018, the `mod.rs` pattern is no longer required; you can use `foo.rs` and `foo/` directory.

**R18**: `Pin<T>` ensures that the data it points to cannot be moved in memory. This is critical for **self-referential structs** (common in `async` state machines) where moving the struct would invalidate internal pointers. `Unpin` is a marker trait for types that *can* be safely moved.

**R19**: **Declarative macros** (`macro_rules!`) use pattern matching to expand code. **Procedural macros** are functions that act on the AST (Abstract Syntax Tree) and can be `derive`, `attribute`, or `function-like`. **Hygiene** ensures that macro-generated identifiers do not accidentally clash with variables in the user's scope.

**R20**: **Zero-cost abstractions** mean you don't pay for what you don't use. **Iterators** are optimized into tight loops; **Generics** use **monomorphization** (generating specific code for each type at compile time) to eliminate runtime dispatch; **Trait static dispatch** resolves calls at compile time. This allows high-level code to compile to the same machine code as manual C.
