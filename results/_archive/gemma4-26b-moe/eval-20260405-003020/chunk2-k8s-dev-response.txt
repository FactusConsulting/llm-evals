## Kubernetes

**K1** — **Deployments** manage stateless applications where pods are interchangeable; they use random hashes for pod names. **StatefulSets** manage stateful applications (like databases) providing stable, unique network identifiers and persistent storage bindings that persist across rescheduling.

**K2** — A **ClusterIP** service creates a virtual IP. When traffic hits this IP, `kube-proxy` (via iptables or IPVS) intercepts the request and performs DNAT (Destination Network Address Translation) to redirect the traffic to one of the pod IPs associated with the service's selector.

**K3** — **PersistentVolume (PV)** is the actual storage resource in the cluster. **PersistentVolumeClaim (PVC)** is a user's request for storage. **StorageClass** defines "profiles" of storage (e.g., SSD vs HDD) to allow dynamic provisioning. A user creates a PVC, which the control plane matches to a PV (or uses a StorageClass to create a new PV automatically).

**K4** — 1. `kubectl logs <pod>` to check application errors. 2. `kubectl describe pod <pod>` to check for exit codes (e.g., 137 for OOMKilled) or liveness probe failures. 3. `kubectl exec` into a running container (if possible) to check local files/configs. 4. Check resource limits/requests to see if the node is under pressure.

**K5** — **CoreDNS** provides service discovery by translating Kubernetes service names into ClusterIPs. If CoreDNS pods are down, internal pod-to-pod communication via service names will fail, and pods will be unable to resolve external domain names.

**K6** — The scheduler follows a two-step process:
1. **Filtering (Predicates):** It removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, Taints, NodeSelectors).
2. **Scoring (Priorities):** It ranks remaining nodes based on "best fit."
**Factors:** Resource availability (least requested), Pod Affinity/Anti-affinity, and Data Locality (topology spread).

**K7** — **Scheduling:** Yes. The node has 3.5GB requested, and the pod requests 256Mi (~0.25GB). $3.5 + 0.25 = 3.75\text{GB}$, which is $\le 4\text{GB}$. 
**Runtime:** If the pod uses 600Mi, it exceeds its 512Mi limit. The Linux kernel will trigger an **OOMKill** (Out of Memory Kill) on the container.

**K8** — 1. **External LB** receives traffic and forwards it to the **Ingress Controller** (NodePort/LoadBalancer). 2. **Ingress Controller** (NGINX) reads the HTTP host/path and matches it to an **Ingress Resource**. 3. The Controller looks up the **Service** associated with that Ingress. 4. The Controller bypasses the Service IP and routes directly to the **Endpoints** (the actual Pod IPs) via the network plugin. `kube-proxy` ensures the underlying networking allows this path.

**K9** — A **NetworkPolicy** is a set of rules defining how pods are allowed to communicate with each other and other network endpoints. **Default:** If no policy exists, all traffic is allowed (allow-all). **Applying one:** Once a policy selects a pod, that pod becomes "isolated"; all traffic not explicitly permitted by the policy is denied.

**K10** — **RollingUpdate** replaces old pods with new ones gradually to ensure zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when you have a singleton requirement (e.g., two pods cannot write to the same database volume simultaneously) or when the application cannot handle two versions running at once.

**K11** — A **Namespace** is a virtual partition within a cluster used to isolate resources and users. Default namespaces: `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

**K12** — Used to inspect the detailed state of a pod. It shows: **Events** (scheduling, pulling, starting), **Container Status/Exit Codes**, and **Node/IP assignment**.

**K13** — A **ConfigMap** stores non-confidential data in key-value pairs. 
**Methods:** 1. As **Environment Variables** in the container. 2. As **Files/Volumes** mounted into the container filesystem.

**K14** — **ClusterIP:** Internal only; reachable only within the cluster. **NodePort:** Exposes the service on a static port on every Node's IP; reachable via `<NodeIP>:<NodePort>`. **LoadBalancer:** Provisions an external cloud load balancer that routes to the NodePort.

**K15** — A **DaemonSet** ensures that a copy of a specific Pod runs on all (or selected) nodes in the cluster. Use it for background services like log collectors (Fluentd), monitoring agents (Prometheus Node Exporter), or networking plugins.

**K16** — **Taints** are applied to *nodes* to repel pods (e.g., "don't put pods here unless they can handle GPU"). **Tolerations** are applied to *pods* to allow them to stay on tainted nodes. **Node Affinity** is applied to *pods* to attract them to specific nodes. 
**Use Case:** Use Taints to keep general workloads off master nodes; use Affinity to ensure a web server pod always lands on a node with an SSD.

**K17** — An **Operator** is a software extension that uses Custom Resource Definitions (CRDs) to manage complex, stateful applications. Unlike a **Standard Controller** (which only manages built-in objects like Pods), an Operator encodes "human operational knowledge" (e.g., how to backup a specific DB) into code to automate lifecycle tasks like scaling, upgrades, and recovery.

**K18** — **Consistency:** etcd uses the Raft consensus algorithm (strong consistency). 
**Loss of Quorum:** The cluster becomes read-only or completely non-functional because the control plane cannot commit new state. 
**Recovery:** If 2/3 nodes are lost, you cannot reach quorum. You must restore from a recent etcd snapshot onto a new 3-node cluster.

**K19** — **RBAC** controls access to the Kubernetes API. **Role** is namespace-scoped; **ClusterRole** is cluster-wide. **RoleBinding** grants permissions in a specific namespace; **ClusterRoleBinding** grants permissions cluster-wide.
**Manifest:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: dev-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: dev-ns
subjects:
- kind: User
  name: developer-user
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — The `ndots:5` setting tells the resolver that if a DNS name has fewer than 5 dots, it should append the search domains in `/etc/resolv.conf` (e.g., `svc.cluster.local`) before trying the name as-is. This causes multiple failed internal lookups for every external request (e.g., `google.com` becomes `google.com.svc.cluster.local.cluster.local...`). 
**Fix:** Use `dnsConfig` in the Pod spec to set `ndots: 1` or use fully qualified domain names (ending in a dot, e.g., `google.com.`) in the application.

## Development

**D1** — **Merge** combines histories by creating a new "merge commit." **Rebase** rewrites history by moving your commits to the tip of the target branch. Avoid rebasing **public/shared branches**, as it rewrites history and breaks other developers' local copies.

**D2** — **TCP** is connection-oriented, reliable, and ensures ordered delivery (e.g., HTTP, SSH). **UDP** is connectionless, faster, but "unreliable" (no guarantee of delivery or order) (e.g., DNS, VoIP/Streaming).

**D3** — A **race condition** occurs when the timing or order of events affects the correctness of a program. 
**Example:** Two threads both read `balance = 100`. Thread A adds 50 and writes 150. Thread B adds 30 and writes 130. The final balance is 130 instead of 180 because Thread B overwrote Thread A's update.

**D4** — **Symmetric:** Same key for encryption and decryption (fast). **Asymmetric:** Public key encrypts, private key decrypts (secure key exchange). In **TLS**, asymmetric encryption is used to securely exchange a symmetric session key, which is then used for the actual data transfer.

**D5** — A **layer** is a read-only filesystem change in a container image. **Caching:** Docker caches layers. If a layer changes (e.g., a `COPY` command), all subsequent layers are invalidated. **Best Practice:** Order commands from "least likely to change" to "most likely to change" (e.g., install OS packages first, then copy source code last).

**D6** — 1. **Check Application Logs** (is the app crashing or overloaded?). 2. **Check Resource Usage** (CPU/RAM saturation). 3. **Check Downstream Dependencies** (is a DB or 3rd party API slow?). 4. **Check Network/Load Balancer** (is the LB dropping connections?).

**D7** — **CAP:** In a distributed system, you can only provide two of Consistency, Availability, or Partition Tolerance. 
**CP (Consistency/Partition):** MongoDB (prioritizes data integrity; may reject requests if a majority of nodes aren't reachable). 
**AP (Availability/Partition):** Cassandra (prioritizes uptime; nodes accept writes even if they can't talk to others, leading to temporary inconsistency).

**D8** — **Horizontal:** Adding more instances (nodes/pods). **Vertical:** Adding more power (CPU/RAM) to existing instances. **Patterns:** Statelessness (allowing any instance to handle any request) and Load Balancing.

**D9** — An **environment variable** is a dynamic value used by processes to configure behavior. To persist on Linux, add `export VAR_NAME=value` to your `~/.bashrc` or `~/.zshrc` file.

**D10** — **JSON** is data-interchange format using braces/brackets. **YAML** is human-readable using indentation. **JSON Advantage:** Strict syntax, easy for machines to parse. **YAML Advantage:** Highly readable, supports comments.

**D11** — A **REST API** is an architectural style for networked applications using HTTP. 
**GET:** Retrieve data. **POST:** Create data. **PUT:** Replace/Update data. **DELETE:** Remove data.

**D12** — **Version pinning** is specifying exact versions of libraries (e.g., `lib==1.2.3`). It is vital for **reproducible builds** to ensure that a build today results in the same binary as a build six months from now, preventing "it works on my machine" bugs caused by silent dependency updates.

**D13** — **Compiled:** Translated to machine code before execution (e.g., C++, Rust). **Interpreted:** Executed line-by-line by another program (e.g., Python, JavaScript).

**D14** — A **Reverse Proxy** sits in front of servers and forwards client requests to them (protects servers). A **Forward Proxy** sits in front of clients and forwards requests to the internet (hides clients). 
**Reverse Proxies:** 1. **NGINX** (Load balancing/Static content). 2. **HAProxy** (High-performance load balancing).

**D15** — A **deadlock** is a state where a set of processes are blocked because each is holding a resource and waiting for another held by another process. **Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual Consistency** means that if no new updates are made, eventually all accesses will return the last updated value. **Cassandra** uses "Tunable Consistency" via the `Consistency Level` (CL) parameter. You can set `CL=ONE` (fast, low consistency), `CL=QUORUM` (majority of nodes must agree), or `CL=ALL` (highest consistency, lowest availability).

**D17** — **mTLS** requires *both* client and server to present certificates to prove identity. 
**Handshake:** 1. Client sends certificate. 2. Server validates client. 3. Server sends its certificate. 4. Client validates server. 5. They exchange keys to establish a symmetric session. 
**Use Case:** Service-to-service communication in a Zero Trust architecture (e.g., Istio/Service Mesh).

**D18** — A **Hash Table** uses a hash function to map keys to array indices. 
**Collision Resolution:** 1. **Chaining:** Each index points to a linked list of entries. 2. **Open Addressing:** Finds the next empty slot in the array. 
**Complexity:** Average: $O(1)$ for all. Worst Case: $O(n)$ (if all keys hash to the same index).

**D19** — The **Circuit Breaker** prevents a system from repeatedly trying an operation that is likely to fail. 
**States:** 1. **Closed:** Normal operation; requests pass through. 2. **Open:** Failures exceeded threshold; requests fail immediately without hitting the service. 3. **Half-Open:** After a timeout, allows a few "test" requests to see if the service recovered. 
**Relation:** It works with **Retries** (which attempt to fix transient errors) and **Exponential Backoff** (which prevents overwhelming a recovering service) to provide a layered defense against cascading failure.

**D20** — **Optimistic:** Assumes conflicts are rare; checks for changes before committing (e.g., using a `version` column). Better for high-throughput, read-heavy systems. **Pessimistic:** Locks the record immediately upon reading to prevent others from changing it (e.g., `SELECT FOR UPDATE`). Better for high-contention, write-heavy systems where conflicts are frequent.
