## Kubernetes (20 questions)

**K1** — A **Deployment** manages stateless applications where pods are interchangeable and can be replaced without concern for identity. A **StatefulSet** is used for stateful applications, providing stable, unique network identifiers and persistent storage that persists across pod rescheduling.

**K2** — A **ClusterIP** service creates a virtual IP. When traffic hits this IP, `kube-proxy` (using iptables or IPVS rules) intercepts the request and performs load balancing to distribute traffic to the IP addresses of the underlying Pods.

**K3** — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a request for storage by a user. **StorageClass** is a template that allows for dynamic provisioning of PVs. Relation: A user creates a PVC referencing a StorageClass, which triggers the automatic creation of a PV.

**K4** — 
1. `kubectl logs <pod-name>`: Check application-level error messages/stack traces.
2. `kubectl describe pod <pod-name>`: Check Kubernetes events (e.g., Liveness probe failures, OOMKilled).
3. Check resource limits: Ensure the pod isn't hitting memory limits.
4. Check container image/entrypoint: Verify the command/args are correct and the image exists.

**K5** — **CoreDNS** provides service discovery by translating service names into IP addresses. If CoreDNS pods are down, internal service-to-service communication via DNS names will fail, and pods will be unable to resolve external domains unless they have a fallback mechanism.

**K6** — The scheduler follows two main phases:
1. **Filtering (Predicates):** Removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, Taints/Tolerations).
2. **Scoring (Priorities):** Ranks remaining nodes.
**Factors:** Resource availability (least requested), Node Affinity (matching labels), and Image Locality (minimizing pull time).

**K7** — **Yes, it will be scheduled.** The node has 500Mi available (4GB - 3.5GB), which satisfies the 256Mi request. However, if the pod uses **600Mi** at runtime, it exceeds its `limits.memory` of 512Mi, and the Linux kernel will trigger an **OOMKill** (Out of Memory Kill) to terminate the process.

**K8** — 
1. **External LB** receives the request and forwards it to the **Ingress Controller** (NGINX).
2. **Ingress Controller** matches the host/path and looks up the **Service** configuration.
3. The controller bypasses the Service IP and looks at the **Endpoints** object to find the direct Pod IPs.
4. Traffic is routed directly to the **Application Pod** via its IP.

**K9** — A **NetworkPolicy** defines rules for how pods are allowed to communicate. By default, if no policy exists, all traffic is allowed (open). Once a policy selects a pod, that pod becomes isolated, and only traffic explicitly permitted by the policy is allowed.

**K10** — **RollingUpdate** replaces pods one-by-one to ensure zero downtime. **Recreate** kills all existing pods before starting new ones, causing downtime. Choose **Recreate** when an application cannot handle two different versions running simultaneously (e.g., a legacy database schema migration).

**K11** — A **Namespace** is a virtual partition within a cluster to isolate resources. Default namespaces: `default`, `kube-system`, and `kube-public`.

**K12** — `kubectl describe pod` shows:
1. **Events:** A chronological log of recent actions/errors.
2. **Container Status:** Specific exit codes (e.g., Exit Code 137).
3. **Mounts/Volumes:** Detailed list of attached storage and paths.

**K13** — A **ConfigMap** stores non-confidential configuration data. Consumption methods:
1. As **Environment Variables** within the container.
2. As **Files** mounted into a volume.

**K14** — **ClusterIP:** Internal-only IP. **NodePort:** Exposes the service on a static port on every Node's IP. **LoadBalancer:** Provisions a cloud provider's load balancer to expose the service externally.

**K15** — A **DaemonSet** ensures that a copy of a specific pod runs on every (or selected) node in the cluster. Use it for infrastructure tasks like log collectors (Fluentd) or monitoring agents (Prometheus Node Exporter).

**K16** — **Taints** are applied to **Nodes** to repel pods (e.g., "don't put any pods here unless they are special"). **Tolerations** are applied to **Pods** to allow them to stay on tainted nodes. **Node Affinity** is applied to **Pods** to attract them to specific nodes. 
*Use Case:* Taint a node for GPU workloads; use Affinity to ensure a high-performance pod lands on that specific node.

**K17** — An **Operator** is a method of packaging operational knowledge into software. It uses **Custom Resource Definitions (CRDs)** and a custom controller to automate complex, stateful tasks (like database backups or scaling) that a standard controller cannot handle.

**K18** — etcd uses the **Raft** consensus algorithm. If the **quorum** (majority) is lost, the cluster becomes read-only and cannot commit new changes. To recover from losing 2 of 3 nodes, you must restore from a backup to a new set of nodes or manually reconfigure the remaining node to form a new cluster.

**K19** — **Role** is namespace-scoped; **ClusterRole** is cluster-wide. **RoleBinding** attaches a Role to a user/group in a namespace; **ClusterRoleBinding** attaches a ClusterRole cluster-wide.
*Manifest:*
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: my-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: my-ns
subjects:
- kind: User
  name: "developer"
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — `ndots:5` means if a DNS query has fewer than 5 dots, the resolver appends search domains (e.g., `google.com` becomes `google.com.svc.cluster.local...`). This causes multiple failed lookups. Fix this in the pod spec using `dnsConfig` to set `ndots: 1` or use fully qualified domain names (ending in a `.`).

## Development (20 questions)

**D1** — **Merge** combines histories by creating a new "merge commit." **Rebase** rewrites history by moving your changes onto the tip of the target branch. Avoid rebasing **public/shared branches** as it rewrites history and breaks other developers' work.

**D2** — **TCP** is connection-oriented and reliable (guarantees delivery). **UDP** is connectionless and fast (no delivery guarantee). 
*TCP:* HTTP, SSH. *UDP:* DNS, VoIP.

**D3** — A **race condition** occurs when the outcome of a program depends on the unpredictable timing of multiple threads accessing shared data. *Example:* Two threads executing `counter++` simultaneously; both read `5`, both increment to `6`, and write `6` back, losing one increment.

**D4** — **Symmetric:** Same key for encryption/decryption. **Asymmetric:** Public key encrypts, private key decrypts. In **TLS**, asymmetric encryption is used during the initial handshake to securely exchange a symmetric key, which is then used for the actual data session.

**D5** — A **layer** is a read-only filesystem snapshot in a container image. **Layer caching** means Docker reuses layers from previous builds. Best practice: Place instructions that change least frequently (e.g., OS installation) at the top of the Dockerfile to maximize cache hits.

**D6** — 
1. Check **Application Logs** (errors/exceptions).
2. Check **Service/Endpoint Health** (is the target actually running?).
3. Check **Resource Usage** (CPU/Memory exhaustion).
4. Check **Upstream/Downstream dependencies** (is a database or external API failing?).

**D7** — **CAP Theorem:** A distributed system can only provide two of three: Consistency, Availability, Partition Tolerance. 
*CP (Consistency/Partition):* **Zookeeper** (stops accepting writes if quorum is lost). 
*AP (Availability/Partition):* **Cassandra** (allows writes even if nodes are disconnected).

**D8** — **Horizontal scaling** adds more instances (nodes/pods). **Vertical scaling** increases the capacity of existing instances (more CPU/RAM). Patterns: Statelessness, Load Balancing, and Database Sharding.

**D9** — An **environment variable** is a dynamic value used to configure a process. To persist on Linux, add `export VAR_NAME="value"` to your `~/.bashrc` or `~/.profile` file.

**D10** — **JSON** is strict and machine-friendly. **YAML** is human-readable and uses indentation. 
*JSON advantage:* Faster parsing/standardization. *YAML advantage:* Readability/Comments.

**D11** — **REST API** is an architectural style for networked applications. 
*GET:* Retrieve data. *POST:* Create data. *PUT:* Update/Replace data. *DELETE:* Remove data.

**D12** — **Version pinning** is specifying the exact version of a dependency (e.g., `requests==2.25.1`). It is vital for **reproducible builds**, ensuring the same code runs identically in dev, staging, and production.

**D13** — **Compiled:** Translated to machine code before execution (C++, Rust). **Interpreted:** Executed line-by-line by an interpreter (Python, Ruby).

**D14** — A **Reverse Proxy** sits in front of servers to protect/balance them (e.g., NGINX). A **Forward Proxy** sits in front of clients to hide their identity (e.g., a corporate proxy). 
*Reverse Proxy Servers:* NGINX (Load balancing), HAProxy (High availability).

**D15** — A **deadlock** is a state where processes are stuck waiting for each other. **Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual consistency** means data will be consistent across all nodes given enough time without new updates. **Cassandra** uses tunable consistency: `ONE` (fast, low consistency), `QUORUM` (majority), or `ALL` (slow, high consistency).

**D17** — **mTLS** requires both client and server to present certificates. 
*Handshake:* Client sends "Hello" $\rightarrow$ Server sends Cert $\rightarrow$ Client verifies $\rightarrow$ Client sends its own Cert $\rightarrow$ Server verifies $\rightarrow$ Both derive a symmetric key. Commonly used in **Service Meshes** (Istio/Linkerd).

**D18** — A **hash table** maps keys to indices via a hash function. 
*Collision Resolution:* **Chaining** (linked list at the index) or **Open Addressing** (finding the next empty slot). 
*Complexity:* Avg: $O(1)$ for all. Worst: $O(n)$ (all keys hash to one index).

**D19** — A **Circuit Breaker** prevents a failing service from crashing the whole system. 
*States:* **Closed** (normal), **Open** (failing fast, no requests sent), **Half-Open** (testing if the service recovered). It prevents cascade failures by stopping retries during an outage, allowing the service to recover.

**D20** — **Optimistic:** Assumes low contention; checks for version changes before committing (e.g., using a `version` column). **Pessimistic:** Assumes high contention; locks the resource immediately (e.g., `SELECT FOR UPDATE`). Use Optimistic for high-read/low-write; Pessimistic for high-write/high-contention.
