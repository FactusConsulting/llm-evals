## Go

**G1** — An **array** has a fixed size defined at compile time. A **slice** is a descriptor containing a pointer to an underlying array, a length, and a capacity. When you `append` to a slice and it exceeds its capacity, Go allocates a new, larger underlying array (usually doubling in size), copies the old elements, and returns a new slice descriptor.

**G2** — `var x int` declares a variable and initializes it to its zero value (0). `x := 0` is short variable declaration; it declares and initializes in one step via type inference. You **cannot** use `:=` at the package level (outside functions); it is only valid inside function bodies.

**G3** — A **goroutine** is a lightweight, user-space thread managed by the Go runtime. Unlike an **OS thread**, which is heavy and managed by the kernel, goroutines are multiplexed onto OS threads using the **GMP model**: **G** (Goroutine), **M** (Machine/OS Thread), and **P** (Processor/Context). The scheduler moves Gs between Ms to ensure high concurrency with minimal overhead.

**G4** — **Channels** are pipes used for communication between goroutines. An **unbuffered channel** is synchronous; the sender blocks until a receiver is ready. A **buffered channel** allows sending up to $N$ elements before blocking. Sending to a full buffered channel blocks the sender until space becomes available.

**G5** — The `context` package handles cancellation, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
// If 2s pass, the request is canceled automatically.
```

**G6** — Go uses **implicit interface satisfaction**: a type satisfies an interface simply by implementing its methods (no `implements` keyword). This allows for decoupled design. `interface{}` (or `any`) can hold any value, making it powerful for generic programming but dangerous because it bypasses type safety, requiring type assertions that can panic if incorrect.

**G7** — This is unsafe due to a **data race** and lack of synchronization. The `for` loop might see `ready = true` but the CPU/compiler might have reordered the writes or cached `data`, so the loop sees `ready` as true but `data` as empty. **Correct alternatives**: Use `sync.Mutex`, `sync/atomic`, or a channel to signal completion.

**G8** — `sync.Mutex` provides exclusive access (one holder). `sync.RWMutex` allows multiple concurrent readers OR one exclusive writer. Use `sync.Map` for high-concurrency scenarios with stable keys and frequent reads/disjoint writes; a regular map with a `Mutex` is better for frequent writes or small, simple maps.

**G9** — `go.mod` tracks dependencies and versions. `go.sum` contains cryptographic hashes of dependencies to ensure integrity. `go mod tidy` removes unused dependencies and adds missing ones. **MVS (Minimum Version Selection)** is the algorithm Go uses to pick the lowest version of a module that satisfies all constraints in the dependency graph.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common gotcha: using `defer` inside a long-running loop can cause resource exhaustion (e.g., file descriptors) because the deferred calls don't run until the *outer* function returns, not the loop iteration.

**G11** — A **pointer** is a variable that stores the memory address of another value. The zero value of a pointer is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs automatically when the package is initialized. A package can have multiple `init()` functions, and they execute in the order they appear in the source file (after all imported packages are initialized).

**G13** — `new(T)` allocates zeroed memory for type `T` and returns a `*T`. `make(T, ...)` is used only for **slices, maps, and channels**; it initializes the internal data structures (headers) and returns the value itself (not a pointer).

**G14** — Errors are values implementing the `error` interface (a `Error() string` method). Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error matches a specific value (including wrapped errors), while `errors.As` checks if an error matches a specific type.

**G15** — **Map**: `nil`. **Slice**: `nil`. **Channel**: `nil`. **Struct**: All fields set to their respective zero values.

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one access is a write. The `-race` flag enables a dynamic detector.
*Example Fix*:
```go
var mu sync.Mutex
var count int
// Inside goroutine:
mu.Lock()
count++
mu.Unlock()
```

**G17** — `select` lets a goroutine wait on multiple channel operations. Unlike `switch` (which checks values), `select` blocks until one case can proceed. If multiple are ready, one is chosen pseudo-randomly. Implement timeout via `case <-time.After(d):`.

**G18** — **Escape analysis** is a compiler optimization to decide if a variable can live on the **stack** (fast, auto-cleaned) or must "escape" to the **heap** (slower, GC-managed). You can inspect this with `go build -gcflags="-m"`. It matters because excessive heap allocation increases GC pressure and latency.

**G19** — `reflect.Type` describes the type metadata; `reflect.Value` holds the actual data. Reflection is computationally expensive due to runtime overhead and loss of type safety. Use it for generic libraries (like JSON encoders), but prefer **code generation** (e.g., `easyjson`) for performance-critical paths.

**G20** — `//go:embed` allows embedding files into the binary at compile time. It supports single files or entire directories. It integrates with `embed.FS`, which implements the `io/fs.FS` interface, allowing you to treat embedded data as a standard filesystem.

## Rust

**R1** — **Ownership** is Rust's core memory management concept. Rules: 1. Each value has a variable called its *owner*. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable string. `&str` is an immutable string slice (a view). Use `&str` in function signatures for maximum flexibility (it accepts both `String` and `&str`). Use `String` when you need to own or mutate the data.

**R3** — **Borrowing** allows accessing data without taking ownership. Rules: You can have either **one** mutable reference (`&mut T`) OR **any number** of shared references (`&T`) at any given time, but never both simultaneously.

**R4** — `Result<T, E>` represents success (`Ok`) or failure (`Err`). `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator propagates errors upward.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>`: Single ownership, heap allocation. `Rc<T>`: Reference counted, single-threaded. `Arc<T>`: Atomic reference counted, thread-safe. Use `Arc` when sharing data across threads.

**R6** — **Traits** define shared behavior (similar to interfaces). `dyn Trait` is a **trait object** (dynamic dispatch via vtable, runtime cost). `T: Trait` is a **generic with a trait bound** (static dispatch via monomorphization, zero runtime cost).

**R7** — It fails because the compiler cannot guarantee that the returned reference lives as long as the inputs. **Fix**: Add lifetime annotations: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8** — `Send` means ownership can be transferred between threads. `Sync` means a reference can be shared between threads. `Rc<T>` is not `Send/Sync` because its reference count is not updated atomically, leading to data races. `Arc<T>` uses atomic operations, making it safe.

**R9** — Rust's async is **cooperative**. A `Future` is a state machine that must be "polled" to make progress. The **executor** (like Tokio) manages these polls. Unlike Go, where the runtime manages threads (M:N), Rust's async is "zero-cost" because it doesn't require a heavy runtime by default.

**R10** — `unsafe` allows bypassing compiler safety checks. You can: 1. Dereference raw pointers. 2. Call FFI (C functions). 3. Mutate static variables. It is justified when interfacing with hardware, C libraries, or implementing low-level primitives.

**R11** — `match` is a control flow operator that performs pattern matching. Unlike `if let` (which handles one case), `match` is **exhaustive**; the compiler forces you to handle every possible pattern.

**R12** — `[T; N]` is a fixed-size array on the stack. `Vec<T>` is a growable, heap-allocated buffer. When a `Vec` exceeds capacity, it reallocates a larger buffer (usually doubling) and moves elements.

**R13** — Rust enums are **sum types** (can hold data per variant). `Option<T>` is an enum with `Some(T)` and `None`. Rust has no `null`; `Option` forces developers to explicitly handle the "nothing" case, preventing null pointer exceptions.

**R14** — `impl` defines methods for a type. `&self` (shared borrow), `&mut self` (exclusive borrow), `self` (consumes ownership). **Associated functions** (like `new()`) do not take `self` and are called via the type name.

**R15** — `#[derive]` is a macro that automatically implements common traits like `Debug` (printing), `Clone` (deep copy), `PartialEq` (equality), and `Serialize` (Serde). You cannot derive a trait if it requires custom logic or if its dependencies don't implement it.

**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that allows for both borrowed and owned data. It is useful for avoiding allocations: if you only read, it stays a borrow; if you need to mutate, it clones the data into an owned version.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. In the 2018 edition, the module system was simplified to allow more direct pathing and removed the requirement for `extern crate`.

**R18** — `Pin<T>` ensures that the data at a specific memory address cannot be moved. This is vital for **self-referential structs** (common in `async` futures) where moving the struct would invalidate internal pointers. `Unpin` is a marker trait for types that *can* be safely moved.

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching. **Procedural macros** are functions that act on the AST (derive, attribute, or function-like). **Hygiene** ensures that macro-generated code doesn't accidentally collide with local variable names.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use. **Iterators** are optimized into tight loops; **Generics** use **monomorphization** (generating specialized code for each type used), and **static dispatch** resolves calls at compile time, making them as fast as hand-written C.
