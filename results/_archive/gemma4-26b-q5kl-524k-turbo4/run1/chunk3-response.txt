## OpenTofu / Terraform

**T1** — `tofu plan` is a dry run that compares the current state against the configuration to determine the execution plan. `tofu apply` executes the actions proposed in the plan to reach the desired state.

**T2** — State is a JSON file mapping your configuration to real-world resources. Remote state is important for team collaboration (shared source of truth) and provides state locking to prevent concurrent modifications.

**T3** — `count` uses an integer index (0, 1, 2...), making it difficult to remove items from the middle without shifting indices. `for_each` uses a map or set of strings, making it stable; removing one item doesn't affect the others. `for_each` is preferred for collections of distinct resources.

**T4** — This is "drift." During the next `tofu plan`, OpenTofu refreshes the state by querying the cloud API. It detects the discrepancy and proposes an update (or recreation) to align the real resource with the configuration.

**T5**
```hcl
resource "example_vm" "web" {
  for_each = toset(["web1", "web2", "web3"])
  name     = each.key
}
```

**T6** — `terraform_remote_state` creates tight coupling and requires access to the entire state file (security risk). The recommended alternative is using **Data Sources** (to fetch specific attributes) or a dedicated Key/Value store (like AWS SSM Parameter Store or HashiCorp Vault) to publish specific outputs.

**T7** — The `null_resource` provisioner runs during the *apply* phase, but the output is calculated during the *plan/apply* phase. If the output depends on a file created by `remote-exec`, the file doesn't exist until the provisioner finishes. **Fix:** Use a `local_file` resource or a `data` source that waits for the file to exist, or ensure the output is not called until the provisioner completes.

**T8** — `tofu import` is a CLI command to bring existing resources under management. The `import` block (1.5+) is declarative; it allows you to define the import in code, making it easier to review and version control, whereas the CLI command is imperative and manual.

**T9** — A `variable` is an input parameter for a module. An `output` is a return value exported by a module.

**T10** — A provider is a plugin that enables OpenTofu to interact with specific APIs (AWS, Azure, etc.). If you run `plan` without `init`, OpenTofu will fail because it hasn't downloaded the necessary provider binaries.

**T11** — It is the dependency lock file. It ensures all team members and CI/CD pipelines use the exact same version of providers, ensuring reproducibility.

**T12** — `tofu destroy` removes all managed resources. To target a single resource: `tofu destroy -target=module.name.resource_type.resource_name`.

**T13** — A data source is a read-only way to fetch information. Example: Using `data "aws_ami"` to find the latest Amazon Linux 2 ID instead of hardcoding it.

**T14** — `variable` is for external input (user-provided). `locals` are for internal logic and derived values. Use `locals` to avoid repeating complex expressions or to transform input variables.

**T15** — 
- `create_before_destroy`: Creates the new resource before deleting the old one (useful for zero-downtime).
- `prevent_destroy`: Prevents accidental deletion of critical resources (e.g., a production DB).
- `ignore_changes`: Tells OpenTofu to ignore specific attributes (e.g., tags modified by an external process).

**T16** — The `moved` block allows you to rename a resource or move it into a module in the code without OpenTofu destroying and recreating it. It updates the state file to reflect the new address.

**T17** — Implicit dependencies are created when one resource references an attribute of another. Explicit dependencies are defined via `depends_on`. `depends_on` forces a specific order but limits parallelism because OpenTofu cannot calculate the graph efficiently, potentially slowing down execution.

**T18** — 
1. **State Splitting:** Break large states into smaller, decoupled workspaces/repos (reduces refresh time).
2. **`-refresh=false`:** Skip the refresh phase during plan (faster, but risks drift).
3. **Targeting:** Use `-target` to only plan specific parts (useful for debugging, but risky for full runs).
4. **S3/Backend Optimization:** Use a faster backend or reduce the number of resources per state file.

**T19** — State locking prevents two users from running `apply` simultaneously, which prevents corruption. If a crash occurs, the lock remains. You break it with `tofu force-unlock <LOCK_ID>`. **Risk:** Manually breaking a lock can lead to state corruption if another process is actually writing to it.

**T20** — 
1. Configure the new `backend "s3"` block in your code.
2. Run `tofu init -migrate-state`.
3. OpenTofu will detect the local state and ask to copy it to S3.
4. Verify by running `tofu state list` and checking the S3 bucket for the `.tfstate` file.

## Ansible

**A1** — A **Task** is a single action. A **Role** is a collection of tasks, variables, and files organized for reuse. A **Playbook** is the orchestration file that maps plays (tasks/roles) to hosts.

**A2** — `ansible_facts` is a dictionary of system information. Access OS family via `ansible_facts['os_family']`.

**A3** — `command` executes a command without a shell (no pipes/redirects). `shell` runs via `/bin/sh` (supports pipes/logic). `raw` executes via SSH without requiring Python on the target (used for bootstrapping).

**A4** — Idempotency means running a task multiple times results in the same state. 
- **Idempotent:** `apt: name=nginx state=present` (only installs if missing).
- **NOT Idempotent:** `shell: echo "hello" >> /tmp/file` (appends every time).

**A5**
```yaml
- name: Install htop
  package:
    name: "{{ 'epel-release' if ansible_os_family == 'RedHat' else omit }}"
  when: ansible_os_family == 'RedHat'

- name: Install htop (RedHat)
  yum: name=htop state=present
  when: ansible_os_family == 'RedHat'

- name: Install htop (Debian)
  apt: name=htop state=present
  when: ansible_os_family == 'Debian'
```
*(Note: A cleaner way is using `package` with conditional names or separate tasks).*

**A6** — Order (lowest to highest): `role defaults` < `group_vars` < `host_vars` < `set_fact` < `extra_vars`.

**A7** — Use `serial: 3` in the playbook to process in batches of 3. To ensure the first 3 are fully ready before the rest, use a `wait_for` task or a `pause` after the first batch.

**A8** — `ansible-vault` encrypts files. To encrypt a single variable, use `ansible-vault encrypt_string 'my_secret_value' --name 'my_var'`.

**A9** — An inventory is a list of managed hosts. **Static** is a hardcoded file. **Dynamic** is a script or plugin that queries a cloud provider (AWS/GCP) for the current list of hosts.

**A10** — `ansible webservers -m shell -a "df -h"`

**A11** — A **handler** is a special task that only runs if notified by another task that reported a `changed` status. It runs at the end of the play.

**A12** — `ansible.cfg` configures Ansible behavior. Settings: `inventory`, `remote_user`, `forks`.

**A13** — `register` saves the output of a task into a variable. You access it via `{{ variable_name.stdout }}`.

**A14** — `import_tasks` is static (parsed at start); `include_tasks` is dynamic (parsed at runtime). `include_tasks` allows for conditional loading of tasks.

**A15** — Galaxy is a community hub for roles/collections. Use a `requirements.yml` file listing the roles/collections, then run `ansible-galaxy install -r requirements.yml`.

**A16** — `ssh` is the default (uses Python). `local` runs on the control node. `network_cli` is used for network devices (switches/routers) that don't have Python.

**A17** — `delegate_to` runs a task on a different host. `run_once` runs it once for the whole play. 
**Example:**
```yaml
- name: Log deployment to central server
  shell: echo "Deployed" >> /logs/deploy.log
  delegate_to: localhost
  run_once: true
```

**A18** — 
1. **Forks:** Increase `forks` in `ansible.cfg` to run more parallel processes.
2. **Pipelining:** Enable `pipelining = True` to reduce SSH connections.
3. **Fact Caching:** Use a Redis/JSON cache for facts to avoid re-gathering.
4. **Mitogen:** Use the Mitogen plugin to optimize SSH execution.

**A19** — `{{ }}` is for expressions; `{% %}` is for control logic; `{# #}` is for comments.
```jinja2
upstream backend_servers {
{% for host in backend_list %}
  server {{ host }}; # Health check: active
{% endfor %}
}
```

**A20** — 
1. Use `serial: 5` to roll in batches.
2. **Pre-task:** Remove host from Load Balancer (using `uri` or cloud module).
3. **Task:** Update app.
4. **Post-task:** `uri` module to check `/health`.
5. **Rollback:** Wrap in a `block`. If a task fails, the `rescue` block re-adds the host to the LB and reverts the version.
