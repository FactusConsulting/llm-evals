## JavaScript / TypeScript (20 questions)

**JS1** — `var` is function-scoped; `let` and `const` are block-scoped. `var` is hoisted and initialized as `undefined`. `let` and `const` are hoisted but reside in the "Temporal Dead Zone" (TDZ) until the declaration is reached, making them inaccessible.

**JS2** — The Event Loop manages asynchronous execution. The **Call Stack** handles synchronous tasks. When an async task finishes, its callback enters the **Microtask Queue** (Promises, `queueMicrotask`) or the **Macrotask Queue** (setTimeout, setInterval). The loop processes the entire Microtask queue before moving to the next Macrotask.

**JS3** — A **closure** is a function that remembers its lexical scope even when executed outside that scope. *Example:* A function returning a counter function. *Bug:* Using `var` in a `for` loop with `setTimeout` causes all callbacks to see the final value of the variable. *Fix:* Use `let` (block scope) or an IIFE to create a unique scope for each iteration.

**JS4** — `Promise` represents an eventual value. `async/await` is syntactic sugar for Promises. Error handling: `try/catch` is used with `async/await`; `.catch()` is used with raw Promises. `Promise.all` rejects immediately if *any* promise fails; `Promise.allSettled` waits for all to complete, regardless of success/failure.

**JS5** — `interface` is primarily for defining object shapes and supports "declaration merging" (adding properties to the same interface later). `type` is for aliases, unions, and primitives. Use `interface` for public APIs/objects; use `type` for complex unions or intersections. **Discriminated unions** use a common literal property (e.g., `{ type: 'A' } | { type: 'B' }`) to allow type narrowing via `switch` or `if`.

**JS6** — JavaScript uses **prototypal inheritance**, where objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with the specified `proto` as its internal `[[Prototype]]`. ES6 `class` is "syntactic sugar" that simplifies the syntax for creating constructor functions and managing the prototype chain.

**JS7** — `this` refers to the execution context. **Binding Priority:** 1. `new` keyword (constructor), 2. Explicit binding (`call`, `apply`, `bind`), 3. Implicit binding (the object calling the method), 4. Default (global object or `undefined` in strict mode). `bind()` returns a **new function** with a fixed `this`; it cannot be re-bound.

**JS8** — `WeakRef` allows holding a reference to an object without preventing it from being garbage collected (GC). `FinalizationRegistry` allows a callback to run after an object is GC'd. `WeakMap` keys must be objects so that if the only reference to the key is the `WeakMap` itself, the key (and value) can be GC'd.

**JS9** — V8 optimizes via **Hidden Classes** (assigning a "shape" to objects to speed up property access) and **Inline Caching** (remembering where properties were found). **Deoptimization** occurs when the engine's assumptions are broken (e.g., changing an object's shape by adding properties in a different order or changing a property type), forcing it to fall back to slower, generic code.

**JS10** — **Tree-shaking** is the removal of unused code during build. It works with **ES Modules** because `import/export` are static (analyzable at build time). **CommonJS** (`require`) is dynamic; the engine cannot know what is being required until runtime, making effective tree-shaking impossible.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion (null == undefined is true); `===` checks both value and type. `??` (nullish coalescing) returns the right side only if the left is `null` or `undefined`. `?.` (optional chaining) short-circuits and returns `undefined` if the reference is nullish.

**JS12** — `map()` transforms each element; `filter()` selects elements based on a predicate; `reduce()` accumulates elements into a single value. `reduce()` uses an initial value to prevent errors on empty arrays and defines the starting point of the accumulator. `flatMap()` maps each element and then flattens the result by one level, useful for handling nested arrays returned by a map.

**JS13** — Template literals use backticks (`` ` ``). **Tagged templates** allow a function to parse the template literal. *Example:* `const sql = (strings, ...values) => ...;` This is used to sanitize inputs to prevent SQL injection by intercepting the strings and values separately.

**JS14** — **Destructuring** extracts values from arrays/objects. *Object:* `const {a, b} = obj`. *Array:* `const [x, y] = arr`. *Default:* `const {a = 1} = obj`. *Renaming:* `const {a: newName} = obj`. The **rest operator** (`...`) collects remaining elements into a new array/object.

**JS15** — `for...in` iterates over enumerable **keys** (properties) of an object. `for...of` iterates over **values** of an iterable. Avoid `for...in` on arrays because it iterates over indices as strings and may include inherited properties.

**JS16** — **Generics** allow reusable components. **Constraints:** `<T extends string>` ensures `T` is a string. **Conditional Types:** `T extends U ? X : Y` returns a type based on a condition. **Infer:** `type GetType<T> = T extends (arg: infer U) => void ? U : never;` extracts the argument type `U`.

**JS17** — **CommonJS** (`require`/`module.exports`) is the legacy Node.js standard. **ES Modules** (`import`/`export`) is the JS standard. Node.js handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM.

**JS18** — TS is **structural** (types are compatible if their shapes match). **Excess property checks** apply when assigning object literals directly to a type. `extends` is for subtyping; `satisfies` checks if an expression matches a type without widening it to that type. **Variance:** `in` (contravariant) for function arguments; `out` (covariant) for function return values.

**JS19** — `Proxy` wraps an object to intercept operations (get, set, etc.). `Reflect` provides methods to perform the default behavior of those operations. *Example:* `const p = new Proxy(target, { get(t, prop) { console.log(prop); return Reflect.get(t, prop); } });`

**JS20** — `SharedArrayBuffer` allows multiple Web Workers to share the same memory. `Atomics` provides atomic operations (like `Atomics.add`) to prevent race conditions. `Atomics.wait` puts a thread to sleep until `Atomics.notify` is called on that index.

## Bash (20 questions)

**B1** — `$@` represents all arguments as separate words. `$*` represents all arguments as a single string. `"$@"` (quoted) preserves individual arguments with spaces; `"$*"` (quoted) joins all arguments into one string separated by the first character of `IFS`.

**B2** — `-e`: Exit immediately if a command fails. `-u`: Treat unset variables as an error. `-o pipefail`: The pipeline return code is the value of the last command to exit with a non-zero status.

**B3** — `$(command)` is command substitution (modern). `` `command` `` is the legacy version. `$((expression))` is arithmetic expansion. `expr` is an external command for math.

**B4** — **Process substitution** `<(command)` treats the output of a command as a file. *Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands as if they were files.

**B5** — Use `while read -r line; do ... done < file` or `find . -print0 | xargs -0 ...`. `for f in $(ls)` is dangerous because it splits on whitespace, breaking filenames containing spaces.

**B6** — **Here document** (`<<EOF`) is for multi-line blocks. **Here string** (`<<<`) is for a single string. `<<-EOF` strips leading **tabs** (not spaces) from the input.

**B7** — `cmd > file 2>&1` redirects stdout to file and stderr to where stdout is (the file). `cmd 2>&1 > file` redirects stderr to stdout (the terminal), then redirects stdout to the file (stderr stays on terminal). `&> file` redirects both to the file.

**B8** — Use `mkdir lockdir` because `mkdir` is an atomic operation at the kernel level, preventing race conditions. Use `trap 'rmdir lockdir' EXIT INT TERM` to ensure cleanup.

**B9** — `'...'` (single) is literal. `"..."` (double) allows variable interpolation. *Example:* `echo '$VAR'` prints `$VAR`; `echo "$VAR"` prints the value. No quotes: `echo $VAR` allows word splitting/globbing.

**B10** — `[ -f file ]` (file), `[ -d dir ]` (directory), `[ -r file ]` (readable). `[[ ]]` is a bash keyword that is safer, handles empty variables better, and supports regex (`=~`).

**B11** — `$?`: Exit status of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: Number of arguments.

**B12** — `foo() {}` is standard. `function foo {}` is bash-specific. Return values are sent via `stdout` (`echo`), while `return` only sends an exit code (0-255).

**B13** — `PATH` is a list of directories searched for commands. **Builtin** commands are inside the shell; **External** are files in `PATH`. Use `type -a command` to see all versions.

**B14** — `trap 'cleanup' SIGNAL`. `EXIT` is the catch-all that runs when the script finishes. If multiple signals arrive, they are handled sequentially.

**B15** — `xargs` reads items from stdin. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P <N>` runs up to `N` processes in parallel.

**B16** — `arr=(a b c)` (declare), `arr+=("d")` (append), `${#arr[@]}` (length), `${arr[@]}` (all elements). **Associative arrays** require `declare -A arr` and use string keys.

**B17** — `(...)` is a **subshell** (new PID, new environment). `{ ...; }` is a **group command** (same shell, same environment). Pipes `|` always create a subshell, which is why variable changes inside a `while` loop fed by a pipe are lost.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (polite request to stop), `SIGHUP` (terminal closed), `SIGKILL` (immediate, cannot be caught). For graceful shutdown, `trap` `SIGTERM` to kill background PIDs.

**B19** — `split -l 1000 log.txt part_` -> `ls part_* | xargs -P 4 -I {} bash -c 'process_func {}'`. *Trade-off:* Parallelism increases speed but complicates error tracking. Use `wait` to ensure all jobs finish.

**B20** — `exec` replaces the current shell process with the new command. `exec 3>file` opens FD 3 for writing. `exec 3>&-` closes it. A **coprocess** (`coproc`) runs a command in the background with two-way pipes.

## PowerShell (20 questions)

**PS1** — `Write-Output` sends objects to the pipeline; `Write-Host` writes directly to the host (screen). `Write-Output` is essential for passing data to the next command.

**PS2** — `ForEach-Object` is a cmdlet that processes items one-by-one in the pipeline. `foreach` is a language keyword that processes a whole collection at once (faster, but requires the whole collection in memory).

**PS3** — `[PSCustomObject]` is an ordered collection of properties; `[hashtable]` is an unordered key-value pair. Use `[PSCustomObject]` for data structures; use `[hashtable]` for lookups. Convert: `[PSCustomObject]@{k=v}`.

**PS4** — **Terminating** errors stop execution; **non-terminating** errors continue. `try/catch` only catches terminating errors. Set `$ErrorActionPreference = 'Stop'` to make non-terminating errors terminating.

**PS5** — **Splatting** passes a hashtable as arguments: `@params = @{Name="X"; Age=10}; Get-User @params`. This is cleaner than passing a single hashtable as one parameter.

**PS6** — `Invoke-Command` is for remote execution (can be one-to-many); `Enter-PSSession` is for interactive sessions. Uses **WinRM** (WSMan) or **SSH**.

**PS7** — `$result += "one"` on an empty array creates a new array every time (inefficient). `$x.GetType().Name` on an empty array is `Object[]`. Correct pattern: `[System.Collections.Generic.List[string]]@()`.

**PS8** — A **scriptblock** is a block of code. **Double-hop** occurs when a remote session tries to access a *third* machine; it fails because credentials aren't passed through. Solve with **CredSSP** or Kerberos delegation.

**PS9** — `@()` is an empty array literal. `[array]` is a type. Indexing `$null` returns `$null`. To force a single result into an array, use `@($result)`.

**PS10** — `-eq` (equality), `-match` (regex), `-contains` (checks if a collection contains a value), `-in` (checks if a value is in a collection). `-ceq` is the case-sensitive version of `-eq`.

**PS11** — `.psm1` is a script module (logic); `.psd1` is a manifest (metadata); Binary is a DLL. `Import-Module` loads the module into the session.

**PS12** — `"$var"` is interpolated; `' $var '` is literal. Use `$()` for expressions: `"Result: $(1+1)"`. **Here-string**: `@""@` (starts with `@"` and ends with `"@` on a new line).

**PS13** — `Get-Member` shows the type of an object. **Properties** (data), **Methods** (actions), **NoteProperties** (manually added). `Select-Object` picks properties; `Where-Object` filters objects.

**PS14** — **Classes** are formal, support inheritance, and are more rigid than functions. Use classes for complex data models; use functions for procedural tasks.

**PS15** — `[CmdletBinding()]` enables common parameters (`-Verbose`, etc.). `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` allows efficient pipeline handling.

**PS16** — **Providers** allow PowerShell to treat different stores (Registry, Cert, Env) as drives. `cd Registry::HKEY_LOCAL_MACHINE` works like a file system.

**PS17** — A **runspace** is a single thread. `ForEach-Object -Parallel` (v7+) uses a thread pool. Manual runspace management is more complex but offers finer control over concurrency.

**PS18** — **PSScriptAnalyzer** is a static code analysis tool. Suppress rules with `# PSScriptAnalyzer -Exclude RuleName`. It integrates into CI/CD to enforce linting.

**PS19** — `$using:var` passes a local variable into a remote/parallel scope. **Serialization** (CLIXML) can strip complex types (like file handles or database connections) during transmission.

**PS20** — **DSC** is declarative configuration. **LCM** (Local Configuration Manager) is the engine that applies it. In modern IaC, it is largely replaced by **Azure Automanage**, **Ansible**, or **Terraform**.
