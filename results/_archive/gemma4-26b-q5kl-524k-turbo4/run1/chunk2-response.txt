## Kubernetes

**K1** — **Deployment** manages stateless applications where pods are interchangeable; **StatefulSet** manages stateful applications, providing stable network identifiers, ordered deployment/scaling, and persistent storage mapping per pod.

**K2** — A **ClusterIP** service creates a virtual IP. `kube-proxy` on each node intercepts traffic to that IP and uses `iptables` or `IPVS` rules to perform DNAT, routing the request to the IP of one of the backend pods.

**K3** — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a request for storage by a user. **StorageClass** is a template that allows for dynamic provisioning of PVs. The relationship: A user creates a PVC referencing a StorageClass, which triggers the creation of a PV.

**K4** — 1. `kubectl logs <pod>` to check application errors. 2. `kubectl describe pod <pod>` to check events and exit codes (e.g., Exit Code 137 for OOM). 3. Check **Liveness/Readiness probes** for configuration errors. 4. Check resource limits/requests to see if the pod is being throttled or killed.

**K5** — **CoreDNS** provides service discovery via DNS names. If CoreDNS pods are down, internal service-to-service communication via DNS names will fail, and pods will be unable to resolve external domains unless hardcoded via IP.

**K6** — The scheduler follows two phases: **Filtering** (removing nodes that don't meet requirements like CPU/RAM, Taints, or NodeSelectors) and **Scoring** (ranking remaining nodes). It considers factors like **Resource Availability** (least requested), **Image Locality** (node already has the image), and **Node Affinity/Anti-affinity**.

**K7** — **Yes**, it will be scheduled because the node has 512Mi available (4GB - 3.5GB). However, if it uses 600Mi, it exceeds its limit (512Mi), and the Linux kernel will trigger an **OOMKill** (Out of Memory) on the process.

**K8** — External LB $\rightarrow$ Ingress Controller (NGINX) $\rightarrow$ Service (via Endpoints/IPs) $\rightarrow$ `kube-proxy` (iptables/IPVS rules) $\rightarrow$ Application Pod.

**K9** — A **NetworkPolicy** is a firewall for pods. By default, if no policy exists, all pods can communicate with all other pods (allow-all). Once a policy is applied to a pod, it enters "isolation mode," where only traffic explicitly allowed by the policy is permitted.

**K10** — **RollingUpdate** replaces pods one-by-one to ensure zero downtime. **Recreate** kills all old pods before starting new ones. Choose **Recreate** when performing breaking database schema changes or when two versions of the app cannot run simultaneously.

**K11** — A **Namespace** is a logical partition within a cluster. Default namespaces include `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

**K12** — `kubectl describe pod` shows: **Events** (history of the pod), **Container Status/Exit Codes**, and **Resource Requests/Limits**. `get pod` only shows basic status/age/restarts.

**K13** — A **ConfigMap** stores non-confidential configuration data. Pods can consume it via **Environment Variables** or by mounting it as a **Volume** (files).

**K14** — **ClusterIP**: Internal-only IP. **NodePort**: Exposes the service on a static port on every Node's IP. **LoadBalancer**: Provisions an external cloud load balancer to route traffic to the service.

**K15** — A **DaemonSet** ensures a copy of a pod runs on every (or selected) node. Use it for infrastructure tasks like **logging agents** (Fluentd), **monitoring** (Prometheus Node Exporter), or **networking plugins**.

**K16** — **Taints** are applied to nodes to *repel* pods; **Tolerations** are applied to pods to allow them to stay on tainted nodes. **Node Affinity** is applied to pods to *attract* them to specific nodes. *Use case:* Taint a GPU node to prevent general pods from landing there; use Affinity to ensure a heavy ML pod specifically targets that GPU node.

**K17** — An **Operator** is a custom controller that uses **CRDs (Custom Resource Definitions)** to manage complex, stateful applications. Unlike standard controllers (which manage generic resources like Pods), an Operator encodes domain-specific operational knowledge (e.g., how to perform a database backup or a version upgrade).

**K18** — etcd uses the **Raft** consensus algorithm. If the **quorum** (majority) is lost, the cluster becomes read-only and cannot accept writes. If 2 out of 3 nodes are lost, the cluster is dead. Recovery requires restoring from a backup or adding new nodes to form a new quorum.

**K19** — **Role** (namespace-scoped permissions), **ClusterRole** (cluster-wide), **RoleBinding** (links Role to User/Group), **ClusterRoleBinding** (links ClusterRole to User/Group).
*Manifest:*
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { name: pod-reader, namespace: dev }
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { name: read-pods, namespace: dev }
subjects: [{ kind: User, name: "developer", apiGroup: rbac.authorization.k8s.io }]
roleRef: { kind: Role, name: pod-reader, apiGroup: rbac.authorization.k8s.io }
```

**K20** — With `ndots:5`, if a DNS query is not a fully qualified domain name (FQDN), the resolver tries appending search domains multiple times, causing latency. Fix this in the pod spec using `dnsConfig`:
```yaml
spec:
  dnsConfig:
    options:
      - name: ndots
        value: "1"
```

## Development

**D1** — **Merge** combines histories and is non-destructive. **Rebase** rewrites history to create a linear timeline. **Avoid rebasing** on public/shared branches as it rewrites history and breaks other developers' work.

**D2** — **TCP** is connection-oriented and reliable (HTTP, SSH). **UDP** is connectionless and fast (DNS, VoIP).

**D3** — A **race condition** occurs when the timing of events affects the correctness of the code. *Example:* Two threads simultaneously executing `counter = counter + 1` on a shared variable, resulting in a lost increment.

**D4** — **Symmetric** uses one key for both encryption and decryption (AES). **Asymmetric** uses a public/private key pair (RSA). In **TLS**, asymmetric encryption is used to securely exchange a symmetric session key, which is then used for the actual data transfer.

**D5** — A **layer** is a read-only filesystem snapshot. To optimize caching, place instructions that change least frequently (e.g., `RUN apt install`) at the top of the Dockerfile and instructions that change often (e.g., `COPY . .`) at the bottom.

**D6** — 1. Check **Backend/Upstream health** (is the app actually running?). 2. Check **Load Balancer/Ingress logs** (is the request reaching the proxy?). 3. Check **Resource usage** (is the pod OOMing or CPU throttled?). 4. Check **Network/Connectivity** (can the proxy reach the pod IP?).

**D7** — **CAP Theorem**: Consistency, Availability, Partition Tolerance. **CP (Consistency/Partition)**: MongoDB (prioritizes data accuracy over availability during a split). **AP (Availability/Partition)**: Cassandra (prioritizes uptime over immediate consistency).

**D8** — **Horizontal** scaling adds more instances (nodes/pods). **Vertical** scaling adds more resources (CPU/RAM) to existing instances. Patterns: **Statelessness** and **Load Balancing** enable horizontal scaling.

**D9** — An **environment variable** is a dynamic value used to configure software. On Linux, use `export VAR=value` in `~/.bashrc` or `~/.profile` to persist across sessions.

**D10** — **JSON** is strict and machine-friendly (fast parsing). **YAML** is human-readable and supports comments.

**D11** — **REST API**: An architectural style using HTTP. **GET** (Read), **POST** (Create), **PUT** (Replace/Update), **DELETE** (Remove).

**D12** — **Version pinning** is specifying exact versions of dependencies (e.g., `package==1.2.3`). It ensures **reproducible builds** by preventing unexpected breaking changes from automatic updates.

**D13** — **Compiled**: Transformed to machine code before execution (C++, Go). **Interpreted**: Read and executed line-by-line at runtime (Python, JavaScript).

**D14** — A **Reverse Proxy** protects/balances servers (NGINX, HAProxy). A **Forward Proxy** protects clients (Squid).

**D15** — A **deadlock** is a state where processes are stuck waiting for each other. **Coffman Conditions**: 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual Consistency** means data will eventually be identical across all nodes. **Cassandra** uses tunable consistency: `ONE` (fastest, lowest consistency), `QUORUM` (majority), or `ALL` (highest consistency, lowest availability).

**D17** — **mTLS** requires both client and server to present certificates. **Handshake**: Client sends cert $\rightarrow$ Server verifies $\rightarrow$ Server sends cert $\rightarrow$ Client verifies. Commonly used in **Service Meshes** (e.g., Istio) for zero-trust networking.

**D18** — A **hash table** maps keys to indices via a hash function. **Chaining** uses linked lists at each index to handle collisions. **Open Addressing** finds the next available slot. **Complexity**: Avg $O(1)$ for insertion/lookup/deletion; Worst $O(n)$.

**D19** — A **Circuit Breaker** prevents cascading failures. **Closed**: Normal operation. **Open**: Requests fail immediately to allow the service to recover. **Half-Open**: Periodically tests the service. It relates to **retries** by stopping retries when the circuit is "Open" to avoid overwhelming a failing service.

**D20** — **Optimistic**: Assumes no conflict; checks version/timestamp at commit (e.g., MVCC). **Pessimistic**: Locks the resource immediately (e.g., `SELECT FOR UPDATE`). Use **Optimistic** for low-contention environments; **Pessimistic** for high-contention environments where conflicts are frequent.
