## JavaScript / TypeScript (20 questions)

**JS1** — `var` is function-scoped and hoisted with an initial value of `undefined`. `let` and `const` are block-scoped and hoisted but remain in a "Temporal Dead Zone" (TDZ) until the declaration is reached, making them inaccessible. `const` prevents reassignment of the identifier.

**JS2** — The event loop manages asynchronous execution. The **Call Stack** handles synchronous tasks. When an async task completes, its callback enters the **Microtask Queue** (Promises, `queueMicrotask`). The **Macrotask Queue** (setTimeout, I/O) is processed after the microtask queue is completely empty.

**JS3** — A **closure** is a function that retains access to its lexical scope even when executed outside that scope. 
*Example:* A function returning another function that increments a private counter. 
*Bug:* Using `var` in a `for` loop with `setTimeout` causes all callbacks to share the same variable instance (printing the final value). 
*Fix:* Use `let` in the loop header to create a new binding for every iteration.

**JS4** — A **Promise** represents a future value. `async/await` is syntactic sugar for Promises, making async code look synchronous. Error handling: `async/await` uses `try/catch`, while Promises use `.catch()`. `Promise.all` rejects immediately if *any* promise fails; `Promise.allSettled` waits for all to finish, regardless of success/failure.

**JS5** — **Interfaces** are primarily for defining object shapes and support "declaration merging." **Types** are more flexible, allowing unions, primitives, and aliases. Use `interface` for public APIs/objects; use `type` for complex unions or aliases. **Discriminated unions** use a common literal property (a "tag") to distinguish between members of a union.

**JS6** — JS uses **prototypal inheritance** where objects inherit properties from a prototype object (`__proto__`). `Object.create(proto)` creates a new object with the specified prototype. **ES6 Classes** are "syntactic sugar" over the existing prototype-based system; they don't introduce a new inheritance model.

**JS7** — `this` refers to the execution context. 
**Binding Priority:** 1. `new` (constructor), 2. Explicit (`call`/`apply`/`bind`), 3. Implicit (object method), 4. Default (global/undefined). 
`bind()` returns a new function with a fixed `this`. You cannot re-bind a function that has already been bound.

**JS8** — `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` executes a callback when an object is GC'd. Keys in a `WeakMap` must be objects so that if the key is no longer referenced elsewhere, it can be collected, preventing memory leaks.

**JS9** — V8 optimizes via **Hidden Classes** (assigning a "shape" to objects to speed up property access) and **Inline Caching** (remembering where properties are located in memory). **Deoptimization** occurs when code becomes "polymorphic" (e.g., passing objects with different shapes to the same function), forcing V8 to drop to a slower execution path.

**JS10** — **Tree-shaking** is dead-code elimination. It works with **ES Modules** because `import/export` is static (analyzable at build time). **CommonJS** (`require`) is dynamic; imports can happen inside conditionals, making it impossible for bundlers to safely determine if a module is unused.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion; `===` checks both value and type. **Nullish coalescing (`??`)** returns the right side only if the left is `null` or `undefined`. **Optional chaining (`?.`)** short-circuits and returns `undefined` if the reference is nullish.

**JS12** — `map()` transforms elements; `filter()` selects elements based on a predicate; `reduce()` accumulates elements into a single value. `reduce()` uses an initial value to prevent errors on empty arrays. `flatMap()` maps each element and then flattens the result by one level, useful for cleaning up nested arrays.

**JS13** — **Template literals** use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** allow a function to parse the template literal. 
*Example:* `sql``` `SELECT * FROM users WHERE id = ${id}` `` where the `sql` function escapes the `id` to prevent injection.

**JS14** — **Destructuring** extracts values from arrays/objects into variables. 
*Object:* `const {a, b} = obj;` 
*Array:* `const [x, y] = arr;` 
*Default:* `const {a = 1} = obj;` 
*Renaming:* `const {a: newName} = obj;` 
*Rest:* `const {a, ...rest} = obj;` collects remaining properties into a new object.

**JS15** — `for...in` iterates over enumerable **keys** (properties) of an object. `for...of` iterates over **values** of an iterable. Avoid `for...in` on arrays because it iterates over indices as strings and may include inherited properties.

**JS16** — **Generics** allow reusable components. 
*Constraint:* `function identity<T extends string>(arg: T)` (T must be a string). 
*Conditional:* `type IsString<T> = T extends string ? true : false`. 
*Infer:* `type GetType<T> = T extends Array<infer U> ? U : never` (extracts the element type).

**JS17** — **CommonJS** (`require`) is synchronous and used in Node.js. **ES Modules** (`import`) are static and standard. Node.js handles both, but ESM is preferred. Setting `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM.

**JS18** — JS is **structurally typed** (if it looks like a duck, it is a duck). **Excess property checks** apply when assigning an object literal directly to a type. `extends` is for subtyping; `satisfies` checks if an expression matches a type without narrowing the type. **Variance** (`in` for contravariant, `out` for covariant) defines how subtyping relates to complex types like functions.

**JS19** — `Proxy` intercepts operations (get, set, etc.); `Reflect` provides methods to perform those same operations. 
*Example:* A Proxy can intercept `set` to validate that a property is a number before allowing the assignment.

**JS20** — `SharedArrayBuffer` allows multiple Web Workers to share the same raw memory. `Atomics` provides thread-safe operations (like `add`, `load`, `store`) to prevent race conditions. `Atomics.wait` pauses a thread until a value changes, and `Atomics.notify` wakes it up.

## Bash (20 questions)

**B1** — `$*` represents all arguments as a single string. `$@` represents all arguments as separate quoted strings. `"$@"` is the gold standard for preserving arguments exactly as they were passed.

**B2** — `set -e` (exit on error), `set -u` (error on unset variables), `set -o pipefail` (return non-zero if any command in a pipe fails).

**B3** — `$(command)` is command substitution (executes command and returns output). `$((expression))` is arithmetic expansion. `expr` is an external command for math, whereas `$((...))` is a shell builtin.

**B4** — **Process substitution** `<(command)` treats the output of a command as a temporary file. 
*Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands.

**B5** — Use `while read -r line; do ... done < file` or globbing `for f in *; do ... done`. `for f in $(ls)` is dangerous because it splits on whitespace, breaking filenames with spaces.

**B6** — `<<EOF` is a **here document** (multi-line input). `<<<` is a **here string** (single string input). `<<-EOF` strips leading **tabs** from the heredoc lines.

**B7** — 
1. `cmd > file 2>&1`: Redirects stdout to file, then redirects stderr to where stdout is going (the file).
2. `cmd 2>&1 > file`: Redirects stderr to stdout (terminal), then redirects stdout to a file.
3. `cmd &> file`: Redirects both stdout and stderr to the file.

**B8** — Use `mkdir lockdir` because `mkdir` is an atomic operation at the kernel level (it fails if the directory exists). 
*Script:* `trap 'rmdir lockdir; exit' INT TERM EXIT; mkdir lockdir || exit 1`.

**B9** — `'...'` (single) is literal (no expansion). `"..."` (double) allows variable expansion. No quotes allow word splitting and globbing. 
*Example:* `echo "$VAR"` vs `echo '$VAR'` vs `echo $VAR`.

**B10** — `-e` (exists), `-d` (directory), `-r` (readable). `[[ ]]` is a bash keyword that is more powerful and safer (handles empty strings/regex) than the `[ ]` (test) command.

**B11** — `$?` (exit status of last command), `$$` (PID of current script), `$!` (PID of last background job), `$#` (number of arguments).

**B12** — `foo() {}` is the standard POSIX way. `function foo {}` is a Bash extension. Functions return an exit code via `return 0-255`, not a value. To "return" data, use `echo`.

**B13** — `PATH` is a list of directories searched for commands. **Builtins** (e.g., `cd`) are inside the shell; **External** commands (e.g., `ls`) are files in `PATH`. Use `type -a command` to see all versions.

**B14** — `trap` catches signals. `trap 'cleanup_func' EXIT ERR INT TERM`. `EXIT` is always executed last.

**B15** — `xargs` reads items from stdin. `find -print0 | xargs -0` handles filenames with spaces/newlines. `xargs -P N` runs N processes in parallel.

**B16** — `arr=(a b c)` (indexed). `declare -A assoc=( [key]=val )` (associative). Append: `arr+=("new")`. Length: `${#arr[@]}`.

**B17** — `(...)` is a **subshell** (new process, new scope). `{ ...; }` is a **group command** (same shell, same scope). Piping `cmd | while` creates a subshell, so variables changed inside the loop are lost to the parent.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (polite kill), `SIGHUP` (terminal closed), `SIGKILL` (immediate/unblockable). Use `trap` to catch `TERM` and kill child processes.

**B19** — Use `split -l 1000 logfile` to chunk, then `xargs -P 4 -I {} bash -c 'process_func {}'` to process. Use `wait` to ensure all parallel jobs finish.

**B20** — `exec` replaces the current shell process with the new command. `exec 3>file` opens FD 3. `exec 3>&-` closes it. A **coprocess** (`coproc cmd`) allows bidirectional communication with a background process.

## PowerShell (20 questions)

**PS1** — `Write-Output` sends objects to the **pipeline** (can be captured). `Write-Host` sends text directly to the **host/screen** (cannot be captured).

**PS2** — `ForEach-Object` is a cmdlet used in pipelines. `foreach` is a language keyword that is significantly faster but requires the entire collection to be in memory first.

**PS3** — `[PSCustomObject]` is an ordered collection of properties. `[hashtable]` is an unordered key-value pair. Convert: `[PSCustomObject]@{key='val'}`.

**PS4** — **Terminating** errors stop execution; **non-terminating** errors continue. `try/catch` only catches terminating errors. Use `-ErrorAction Stop` to turn a non-terminating error into a terminating one.

**PS5** — **Splatting** passes a hashtable as arguments: `$p = @{Name='Bob'; Age=30}; Get-User @p`. This is cleaner than passing individual parameters.

**PS6** — `Invoke-Command` is for remote execution (one-to-many). `Enter-PSSession` is for interactive sessions. They use **WinRM** (WS-Man) or **SSH**.

**PS7** — In the example, `$result` is an array. If the function returns nothing, `$x` becomes `$null`. Calling `.GetType()` on `$null` throws an error. Correct pattern: `$x = @(Get-Items)`.

**PS8** — A `[scriptblock]` is a piece of code. The **double-hop problem** occurs when a remote session tries to use its credentials to access a *third* machine. Solve with **CredSSP** or **Kerberos Delegation**.

**PS9** — `@()` is an empty array literal. `[array]` is a type. Indexing `$null` returns nothing; indexing an empty array returns nothing. To force a single result into an array, use `@(result)`.

**PS10** — `-eq` (equality), `-like` (wildcard), `-match` (regex), `-contains` (checks if a collection contains a value), `-in` (checks if a value is in a collection). Case-sensitive versions use `-ceq` or `-clike`.

**PS11** — `.psm1` is a script module. `.psd1` is a manifest. Binary modules are DLLs. `Import-Module` loads them into the session.

**PS12** — `"..."` allows `$var` interpolation. `'...'` is literal. Use `$()` for expressions: `"Result: $($1+1)"`. `@""@` is a **here-string** for multi-line blocks.

**PS13** — `Get-Member` shows the type, properties, and methods of an object. `Select-Object` picks specific properties; `Where-Object` filters the objects themselves.

**PS14** — **Classes** are more rigid than functions. They support inheritance but have limited support for interfaces compared to C#. Use classes for complex data structures; use functions for logic.

**PS15** — `[CmdletBinding()]` makes a function behave like a real cmdlet (adds `-Verbose`, `-Debug`). `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` blocks allow efficient pipeline processing.

**PS16** — **Providers** allow PowerShell to treat different data stores (Registry, Cert, Env) as drives. `cd Registry::HKEY_LOCAL_MACHINE` works because of the Registry provider.

**PS17** — `[runspace]` is a single thread. `[runspacepool]` manages multiple. `ForEach-Object -Parallel` (v7) is a high-level wrapper that manages runspaces automatically.

**PS18** — **PSScriptAnalyzer** is a static code analysis tool. Rules have severity (Error, Warning, Info). Suppress with `# PSScriptAnalyzer -DisableRule RuleName`.

**PS19** — `$using:var` passes a local variable into a remote scope. **Serialization** occurs when objects are sent over the wire; complex objects are converted to **CLIXML**, which can strip methods and custom properties.

**PS20** — **DSC** is declarative configuration. **LCM** (Local Configuration Manager) is the engine on the target node. In modern IaC, DSC is often replaced by **Azure Automanage** or tools like **Terraform/Ansible**.
