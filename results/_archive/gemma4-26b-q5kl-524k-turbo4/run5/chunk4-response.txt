## Go

**G1** — An **array** has a fixed size defined at compile time. A **slice** is a descriptor containing a pointer to an underlying array, a length, and a capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array (typically doubling in size), copies the old elements to the new array, and returns a new slice descriptor pointing to the new memory.

**G2** — `var x int` declares a variable with its zero value (0). `x := 0` is short-variable declaration, which declares and initializes. You **cannot** use `:=` outside of function bodies (at the package level).

**G3** — A **goroutine** is a lightweight, user-space thread managed by the Go runtime. Unlike an **OS thread**, which has a large, fixed stack (MBs), a goroutine starts with a tiny stack (KBs) that grows/shrinks dynamically. The **GMP model** consists of **G** (Goroutines), **M** (Machine/OS Threads), and **P** (Processor/Context). The scheduler maps $G$s onto $M$s using $P$s to ensure efficient work-stealing and CPU utilization.

**G4** — **Channels** are pipes used for communication between goroutines. An **unbuffered channel** requires a synchronous handshake (sender and receiver must be ready simultaneously). A **buffered channel** allows sending up to $N$ values before blocking. Sending to a **full** buffered channel blocks the sender until a receiver takes a value.

**G5** — The `context` package handles cancellation, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
// If the timeout hits, the request is canceled automatically.
```

**G6** — Go uses **implicit interface satisfaction** (duck typing); if a type implements the methods, it satisfies the interface. This differs from Java/C# where implementation must be explicit (`implements`). `interface{}` (or `any`) can hold any value, making it powerful for generic data but dangerous because it bypasses compile-time type safety, requiring type assertions.

**G7** — This is unsafe due to **memory visibility** issues. Without synchronization, the compiler or CPU may reorder instructions or cache `ready` in a register, so the loop might never see the update. **Correct alternatives**: Use `sync.Mutex`, `sync/atomic` (e.g., `atomic.Bool`), or a channel to signal completion.

**G8** — `sync.Mutex` is an exclusive lock (one holder). `sync.RWMutex` allows multiple concurrent readers OR one exclusive writer. Use `sync.Map` for high-concurrency scenarios with disjoint keys or read-heavy workloads where keys are stable; a regular map with a `Mutex` is faster for most general-purpose, write-heavy, or small-scale use cases.

**G9** — `go.mod` tracks dependencies and versions. `go.sum` contains cryptographic checksums of dependencies to ensure integrity. `go mod tidy` adds missing modules and removes unused ones. **MVS (Minimum Version Selection)** is the algorithm Go uses to select the lowest version of a module that satisfies all constraints in the dependency graph.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common **gotcha** is using `defer` inside a loop; the deferred calls don't execute until the *outer* function returns, which can lead to resource exhaustion (e.g., leaking file descriptors).

**G11** — A **pointer** is a variable that stores the memory address of another value. The zero value of a pointer is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs automatically when a package is initialized. It runs once per package. A package can have **multiple** `init()` functions, and they execute in the order they appear in the source files (and after package-level variable initializations).

**G13** — `make` is used for slices, maps, and channels; it initializes the internal data structures and returns an initialized value. `new` allocates zeroed memory for any type and returns a **pointer** to it.

**G14** — Errors are values. The `error` type is a built-in interface with an `Error() string` method. The idiomatic pattern is `if err != nil`. `errors.Is` checks if an error matches a specific value (including wrapped errors), while `errors.As` checks if an error matches a specific type and performs a type conversion.

**G15** — **Map**: `nil`. **Slice**: `nil`. **Channel**: `nil`. **Struct**: All fields set to their respective zero values.

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently, and at least one access is a write. The `-race` flag enables the data race detector.
*Example Fix*:
```go
// Unsafe: go func() { count++ }()
// Safe:
var mu sync.Mutex
mu.Lock()
count++
mu.Unlock()
```

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, which evaluates values, `select` evaluates channel readiness. If multiple cases are ready, one is chosen **pseudo-randomly**. Implement a timeout using `case <-time.After(duration):`.

**G18** — **Escape analysis** is a compiler optimization that determines if a variable can reside on the stack or must "escape" to the heap. If a variable's lifetime exceeds the function scope (e.g., returning a pointer), it moves to the heap. Inspect via `go build -gcflags="-m"`. Reducing heap allocations improves performance by reducing GC pressure.

**G19** — `reflect.Type` describes the type metadata; `reflect.Value` holds the actual data. Reflection is computationally expensive due to runtime overhead and prevents many compiler optimizations. Use it for generic libraries (like JSON encoders), but prefer **code generation** (e.g., `stringer`) for performance-critical paths.

**G20** — `//go:embed` allows embedding files into the binary at compile time. It supports single files and directories. It integrates with `embed.FS`, which implements the `io/fs.FS` interface, allowing you to treat embedded data as a standard filesystem.

## Rust

**R1** — **Ownership** is Rust's memory management system. Rules: 1. Each value has a variable called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable string. `&str` is an immutable string slice (a reference). Use `String` when you need to own or mutate the data; use `&str` in function arguments to allow the function to accept both `String` and `&str` without extra allocations.

**R3** — **Borrowing** allows accessing data without taking ownership. Rules: You can have **either** any number of immutable references (`&T`) **OR** exactly one mutable reference (`&mut T`) at any given time.

**R4** — `Result<T, E>` represents success/failure; `Option<T>` represents presence/absence. The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>` is for heap allocation with a single owner. `Rc<T>` (Reference Counted) allows multiple owners within a single thread. `Arc<T>` (Atomic Reference Counted) allows multiple owners across multiple threads.

**R6** — **Traits** define shared behavior. Unlike Go interfaces, Rust traits can have default implementations and can be implemented for existing types. `dyn Trait` uses **dynamic dispatch** (vtable lookup at runtime), while `T: Trait` uses **static dispatch** (monomorphization at compile time).

**R7** — It fails because the compiler cannot guarantee the returned reference lives long enough. Fix using **lifetime annotations**:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** — `Send` means a type can be transferred between threads. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send/Sync` because its reference count is not updated atomically, leading to data races. `Arc<T>` uses atomic operations, making it safe for concurrent use.

**R9** — A **Future** is a trait representing a value that will eventually be available. **Async/await** is syntactic sugar that transforms functions into state machines. The **executor** (e.g., Tokio) is responsible for polling futures to completion. Unlike Go's stackful goroutines, Rust uses **stackless** futures, which are more memory-efficient but require an external executor.

**R10** — `unsafe` allows bypassing certain compiler checks. You can: 1. Dereference raw pointers. 2. Call FFI functions. 3. Access/mutate mutable statics. It is justified when interfacing with hardware, C libraries, or implementing low-level data structures.

**R11** — **Pattern matching** is a powerful control flow mechanism. `match` is exhaustive (all cases must be covered). `if let` is a concise way to handle a single pattern. The compiler enforces that every possible value of an enum is handled.

**R12** — `Vec<T>` is a heap-allocated, growable array. `[T; N]` is a fixed-size array on the stack. When a `Vec` exceeds capacity, it reallocates a larger block of memory and moves the elements.

**R13** — Rust **enums** are "sum types" (can hold data). `Option<T>` is an enum (`Some(T)` or `None`). Rust has no `null` to prevent null-pointer exceptions; you must explicitly handle the `None` case.

**R14** — `impl` defines methods for a type. `&self` borrows immutably; `&mut self` borrows mutably; `self` consumes the value (moves it). **Associated functions** (like `new`) do not take `self` and are called on the type itself.

**R15** — `#[derive]` is a macro that automatically implements common traits. Examples: `Debug`, `Clone`, `PartialEq`, `Serialize`. You cannot derive a trait if the type contains members that do not also implement that trait.

**R16** — `Cow<'a, T>` (Clone on Write) is a smart pointer for "copy-on-write" semantics. It holds either borrowed or owned data. It avoids allocation if you only read, but clones the data only when you attempt to mutate it.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. The file system maps to modules (e.g., `mod foo` looks for `foo.rs`). The 2018 edition simplified module resolution by removing the need for `extern crate`.

**R18** — `Pin<T>` ensures that the data at a specific memory address cannot be moved. This is critical for **self-referential structs** used in `async/await`. `Unpin` is a marker trait indicating that a type is safe to move even when pinned.

**R19** — `macro_rules!` are **declarative** (pattern matching on code). **Procedural** macros (derive, attribute, function-like) are compiler plugins that act on the AST. **Hygiene** ensures that macro-generated code does not accidentally collide with local variable names.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use. **Iterators** compile to efficient loops; **Generics** use **monomorphization** (generating specialized code for each type used), and **trait static dispatch** allows the compiler to inline calls, matching the performance of hand-written C.
