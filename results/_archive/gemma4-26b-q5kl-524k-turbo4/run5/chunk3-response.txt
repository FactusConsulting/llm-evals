## OpenTofu / Terraform

**T1** — `tofu plan` is a dry-run that shows what changes (create, update, destroy) will occur without applying them. `tofu apply` executes those changes to reach the desired state.

**T2** — State is a JSON file mapping your configuration to real-world resources. Remote state is important for collaboration (shared source of truth) and safety (state locking to prevent concurrent writes).

**T3** — `count` uses an index (integer), making it hard to remove items from the middle of a list without recreating others. `for_each` uses keys (map/set), allowing you to add/remove specific items without affecting others. `for_each` is preferred for collections of varying items.

**T4** — OpenTofu detects "drift" during the next `plan`. It compares the state file against the actual cloud API. If a VM was modified, OpenTofu will attempt to revert the manual change to match the configuration.

**T5**
```hcl
resource "example_vm" "web" {
  for_each = toset(["web1", "web2", "web3"])
  name     = each.key
}
```

**T6** — `terraform_remote_state` reads the entire state file of another workspace, which creates tight coupling. The recommended alternative is using **Outputs** from one module passed as **Inputs** to another, or using a shared data source (like AWS SSM or Consul) to decouple them.

**T7** — This is a race condition. The `null_resource` output is evaluated during the graph walk, but the `remote-exec` happens during the apply phase. Because the output is not tied to a resource that *waits* for the provisioner, the dependency graph thinks it's ready. **Fix:** Use `depends_on` in the dependent resource pointing to the `null_resource`.

**T8** — `tofu import` brings existing infrastructure under management. Limitations: It only updates the state, not the code. The `import` block (1.5+) is declarative; you define the resource in code and run `plan`, allowing OpenTofu to generate the configuration for you.

**T9** — A `variable` is an input parameter for a module. An `output` is a value exported by a module to be used by others.

**T10** — A provider is a plugin that translates HCL into API calls. If you run `plan` without `init`, it will fail because the provider binaries haven't been downloaded to the `.terraform` directory.

**T11** — It is the dependency lock file. It should be committed to ensure every environment (Dev, Prod, CI) uses the exact same provider versions, preventing "it works on my machine" issues.

**T12** — `tofu destroy` removes all managed resources in the state. To target one: `tofu destroy -target=resource_type.name`.

**T13** — A data source is a read-only data fetch. Example: `data "aws_ami" "latest"` to fetch the newest Amazon Linux ID without hardcoding it.

**T14** — `variable` blocks are for external inputs (user-provided). `locals` are for internal, derived logic (e.g., `name = "${var.env}-${var.project}"`). Use `locals` to keep code DRY and hide complexity.

**T15** — 
- `create_before_destroy`: Creates the new resource before deleting the old one (prevents downtime).
- `prevent_destroy`: Stops accidental deletion of critical resources (e.g., a production DB).
- `ignore_changes`: Tells OpenTofu to ignore specific attributes (e.g., tags added by an external process).

**T16** — A `moved` block allows you to rename a resource or move it into a module in the code without OpenTofu destroying and recreating the physical resource.

**T17** — The graph is built by analyzing resource references. **Implicit** dependencies are created automatically when one resource references another's attribute. **Explicit** dependencies use `depends_on`. `depends_on` forces sequential execution, reducing parallelism and slowing down the plan/apply.

**T18** — 
1. **Split State:** Break a monolithic state into smaller ones (Tradeoff: increased complexity in passing data).
2. **Targeted Refresh:** Use `-refresh=false` (Tradeoff: state might be stale).
3. **Increase Parallelism:** Use `-parallelism=n` (Tradeoff: risk of hitting Cloud API rate limits).
4. **Reduce Resource Count:** Use `data` sources instead of managing everything in one workspace.

**T19** — State locking prevents two users from running `apply` simultaneously. If a CI crashes, the lock remains. You break it with `tofu force-unlock <LOCK_ID>`. **Risk:** If you force-unlock while another process is actually writing, you will corrupt the state file.

**T20** — 
1. Write the new `backend "s3" { ... }` block in your code.
2. Run `tofu init`.
3. Tofu will detect the change and prompt: "Do you want to copy existing state to the new backend?" Type `yes`.
4. Verify by running `tofu state list` to ensure all resources are present.

## Ansible

**A1** — A **Task** is a single action. A **Playbook** is a list of plays (orchestration). A **Role** is a structured collection of tasks, vars, and files for reuse.

**A2** — `ansible_facts` is a dictionary of system info. Access OS family via `ansible_facts['os_family']`.

**A3** — `command` (no shell features, most secure), `shell` (uses `/bin/sh`, allows pipes/redirects), `raw` (runs command via SSH without needing Python on the target).

**A4** — Idempotency means running a task multiple times results in the same state. 
- **Idempotent:** `apt: name=nginx state=present`.
- **NOT Idempotent:** `shell: echo "hello" >> /etc/motd`.

**A5**
```yaml
- name: Install htop
  package:
    name: htop
    state: present
  when: ansible_os_family == "Debian"
# (Note: In a real scenario, you'd use a conditional or a loop with different names)
```
*Better approach:*
```yaml
- name: Install htop on Debian
  apt: name=htop state=present
  when: ansible_os_family == "Debian"

- name: Install htop on RedHat
  yum: name=epel-release state=present
  when: ansible_os_family == "RedHat"
```

**A6** — (Highest to Lowest): `extra_vars` > `set_fact` > `host_vars` > `group_vars` > `role defaults`.

**A7** — Use `serial: 3` in the playbook to process in batches. Use `wait_for` to ensure the agent is listening on its port before moving to the next batch.

**A8** — `ansible-vault` encrypts files/vars. To encrypt a single variable, use `ansible-vault encrypt_string 'my_password'`.

**A9** — **Static:** A hardcoded list of hosts. **Dynamic:** A script or plugin that queries a cloud provider (AWS/GCP) to generate the list at runtime.

**A10** — `ansible webservers -m shell -a "df -h"`

**A11** — A **handler** is a special task that only runs if "notified" by another task. It is triggered via the `notify` keyword and usually runs at the end of the play.

**A12** — It configures Ansible behavior. Settings: `inventory`, `remote_user`, `forks`.

**A13** — `register` saves the output of a task into a variable. You use it later via `{{ variable_name }}`.

**A14** — `import_tasks` is static (processed when the playbook is parsed). `include_tasks` is dynamic (processed at runtime). `include_tasks` allows for conditional logic during the loop/run.

**A15** — Galaxy is a community hub for roles/collections. Use a `requirements.yml` file listing the roles/collections, then run `ansible-galaxy install -r requirements.yml`.

**A16** — `ssh` (standard Linux/Unix), `local` (runs on the control node), `network_cli` (specialized for network switches/routers).

**A17** — `delegate_to` runs a task on a different host. `run_once` ensures a task runs only once for the whole play. 
*Example:* `delegate_to: localhost` + `run_once: true` to save a remote log file to the local machine.

**A18** — 
1. **Forks:** Increase `forks` in `ansible.cfg` (Tradeoff: higher CPU/RAM on control node).
2. **Pipelining:** Enable `pipelining = True` (Tradeoff: requires `requiretty` to be disabled in SSH).
3. **Fact Caching:** Use a Redis/JSON file for facts (Tradeoff: avoids re-gathering facts every time).
4. **Mitogen:** Use the Mitogen plugin (Tradeoff: significantly faster but changes how execution works).

**A19** — `{{ }}` (Expression), `{% %}` (Logic), `{# #}` (Comment).
```jinja2
upstream nginx_backend {
{% for server in backend_servers %}
  server {{ server }}; # Health check: active
{% endfor %}
}
```

**A20** — 
1. Set `serial: 1` (or small batches).
2. Use a `block` containing the deployment task.
3. Use `uri` module to check the app health.
4. If `uri` fails, the `rescue` block triggers a rollback (e.g., re-installing the previous version).
5. Use `notify` to remove the node from the Load Balancer before the task starts.
