## Kubernetes (20 questions)

**K1** — **Deployment** is used for stateless applications where pods are interchangeable. **StatefulSet** is used for stateful applications (like databases) where pods require stable, unique identities (network IDs and persistent storage) that persist across restarts.

**K2** — A **ClusterIP** service uses `kube-proxy` (via iptables or IPVS) on each node to intercept traffic sent to the Service's virtual IP and route it to the IP addresses of the underlying Pods listed in the Service's **Endpoints** object.

**K3** — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a request for storage by a user. **StorageClass** is a template that allows for dynamic provisioning of PVs. A PVC references a StorageClass to automatically trigger the creation of a PV.

**K4** — 1. `kubectl logs <pod>` to check application errors. 2. `kubectl describe pod <pod>` to check for exit codes or OOMKilled events. 3. Check **Liveness/Readiness probes** in the manifest. 4. Check **Resource limits** (is it hitting an OOM limit?).

**K5** — **CoreDNS** provides service discovery within the cluster via DNS names. If CoreDNS pods are down, pods will be unable to resolve internal service names (e.g., `my-svc.my-namespace.svc.cluster.local`) or external domains if the upstream is unreachable.

**K6** — The scheduler follows two phases: **Filtering** (Predicates) to remove nodes that don't meet requirements, and **Scoring** (Priorities) to rank remaining nodes. Factors include: **Resource availability** (CPU/RAM), **Node Affinity/Taints**, and **Image locality**.

**K7** — **Yes**, it will be scheduled because the request (256Mi) is less than the available capacity (500Mi remaining). However, if it uses **600Mi** at runtime, it exceeds the limit (512Mi), and the kernel will trigger an **OOMKilled** event.

**K8** — External Traffic $\rightarrow$ **External Load Balancer** $\rightarrow$ **Ingress Controller** (e.g., NGINX) $\rightarrow$ **Ingress Resource** rules $\rightarrow$ **Service** $\rightarrow$ **Endpoints** $\rightarrow$ **kube-proxy/iptables** $\rightarrow$ **Pod**.

**K9** — A **NetworkPolicy** is a firewall for pods. By default, if no policy exists, all ingress/egress is allowed. Once a policy is applied to a pod, it acts as an "allow-list"; any traffic not explicitly permitted by a policy is denied.

**K10** — **RollingUpdate** replaces pods one-by-one to ensure zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when an application cannot handle two versions running simultaneously (e.g., certain database schema migrations).

**K11** — A **Namespace** is a logical partition within a cluster. Default namespaces: `default`, `kube-system`, and `kube-public`.

**K12** — `kubectl describe` provides deep metadata: **Events** (recent lifecycle changes), **Container Status** (reason for failure), and **Mounts/Volumes** details.

**K13** — A **ConfigMap** stores non-confidential configuration data. Consumption methods: 1. As **Environment Variables** in the pod spec. 2. As **Files/Volumes** mounted into the container.

**K14** — **ClusterIP**: Internal-only access. **NodePort**: Exposes the service on a static port on every Node's IP. **LoadBalancer**: Provisions an external cloud load balancer to route traffic to the service.

**K15** — A **DaemonSet** ensures a copy of a pod runs on every (or selected) node. Use it for infrastructure tasks like **logging agents** (Fluentd) or **monitoring agents** (Prometheus Node Exporter).

**K16** — **Taints** are applied to **Nodes** to repel pods (e.g., "don't put anything here unless it tolerates this taint"). **Node Affinity** is applied to **Pods** to attract them to specific nodes. *Use case:* Taint a node with a GPU to prevent general workloads from wasting resources; use Affinity to ensure a heavy ML pod lands on that GPU node.

**K17** — An **Operator** is a method of packaging, deploying, and managing a complex application using **Custom Resource Definitions (CRDs)** and a custom controller. It automates operational knowledge (like backups or scaling) that a standard controller (which only manages basic pod lifecycles) cannot.

**K18** — etcd uses the **Raft consensus algorithm**. If quorum is lost, the cluster becomes read-only or fails. If 2/3 nodes are lost, the cluster is dead. Recovery requires restoring from a **backup** or manually re-initializing a new etcd cluster and re-joining the remaining node.

**K19** — **Role**: Namespace-scoped permissions. **ClusterRole**: Cluster-wide permissions. **RoleBinding**: Grants Role to a user in a namespace. **ClusterRoleBinding**: Grants ClusterRole to a user cluster-wide.
*Manifest:*
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: my-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: my-ns
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — `ndots:5` causes the resolver to append multiple search domains (e.g., `domain.com.namespace.svc.cluster.local`) before trying the actual name. To fix, use `dnsConfig` in the Pod spec to set `ndots: 1`.

## Development (20 questions)

**D1** — **Merge** combines histories by creating a new commit; it is non-destructive. **Rebase** moves the entire feature branch to begin on the tip of the main branch, rewriting history. Avoid rebasing **public/shared branches** as it breaks history for others.

**D2** — **TCP** is connection-oriented and reliable (HTTP, SSH). **UDP** is connectionless and faster (DNS, VoIP).

**D3** — A **race condition** occurs when multiple threads access shared data simultaneously, and the outcome depends on the timing of execution. *Example:* Two threads incrementing a shared integer `x++` at the same time might both read `5` and both write `6`, resulting in `6` instead of `7`.

**D4** — **Symmetric**: Same key for encryption/decryption. **Asymmetric**: Public/Private key pair. In **TLS**, asymmetric encryption is used for the initial handshake (to securely exchange a session key), and symmetric encryption is used for the actual data transfer (for speed).

**D5** — A **layer** is a read-only filesystem change. **Layer caching** means Docker reuses layers that haven't changed. Best practice: Order `Dockerfile` commands from least frequent to most frequent changes to maximize cache hits.

**D6** — 1. Check **Application logs** (internal errors). 2. Check **Service/Pod health** (is the app actually running?). 3. Check **Load Balancer/Ingress** (is the entry point healthy?). 4. Check **Downstream dependencies** (is a database or API it calls down?).

**D7** — **CAP**: Consistency, Availability, Partition Tolerance. **CP** (Consistency/Partition): Zookeeper (prioritizes data accuracy). **AP** (Availability/Partition): Cassandra (prioritizes uptime/responsiveness).

**D8** — **Horizontal**: Adding more instances (nodes/pods). **Vertical**: Adding more resources (CPU/RAM) to existing instances. Patterns: **Statelessness** and **Load Balancing**.

**D9** — An **environment variable** is a dynamic value used by processes. To persist on Linux, add `export VAR_NAME=value` to your `~/.bashrc` or `~/.zshrc`.

**D10** — **JSON** is strict and machine-friendly (Advantage: easy to parse). **YAML** is human-readable (Advantage: supports comments and cleaner syntax).

**D11** — **REST API**: An architectural style for networked applications. **GET** (Read), **POST** (Create), **PUT** (Replace/Update), **DELETE** (Remove).

**D12** — **Version pinning** is specifying exact versions of dependencies. It ensures **reproducible builds** by preventing unexpected breaking changes when a library is updated.

**D13** — **Compiled**: Converted to machine code before execution (e.g., C++, Go). **Interpreted**: Executed line-by-line by a runtime (e.g., Python, JavaScript).

**D14** — A **Reverse Proxy** protects the server (e.g., NGINX for load balancing; HAProxy for high availability). A **Forward Proxy** protects the client (e.g., Squid for web filtering).

**D15** — A **deadlock** is a state where processes are stuck waiting for each other. **Coffman Conditions**: 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual consistency** means data will be consistent across all nodes given enough time. **Cassandra** uses tunable consistency: `ONE` (fastest), `QUORUM` (majority), or `ALL` (slowest/strongest).

**D17** — **mTLS** requires both client and server to present certificates. **Handshake**: Client sends cert $\rightarrow$ Server verifies $\rightarrow$ Server sends cert $\rightarrow$ Client verifies. Used heavily in **Service Meshes** (e.g., Istio) for zero-trust networking.

**D18** — **Hash Table**: Maps keys to indices via a hash function. **Chaining** (linked lists at indices) vs. **Open Addressing** (finding next empty slot). **Complexity**: Avg: $O(1)$ for all; Worst: $O(n)$.

**D19** — **Circuit Breaker**: Prevents cascading failure. **Closed**: Normal operation. **Open**: Fail fast without calling the service. **Half-Open**: Periodically test the service. It works with **retries/exponential backoff** to allow a failing system time to recover without being overwhelmed.

**D20** — **Optimistic**: Assumes no conflict; checks version at commit (e.g., `WHERE version=1`). Use for **low contention**. **Pessimistic**: Locks the resource immediately (e.g., `SELECT FOR UPDATE`). Use for **high contention**.
