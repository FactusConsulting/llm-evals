## JavaScript / TypeScript (20 questions)

**JS1** — `var` is function-scoped; `let` and `const` are block-scoped. `const` prevents reassignment of the identifier. **Hoisting** is JavaScript's behavior of moving declarations to the top of their scope during compilation. `var` is hoisted and initialized as `undefined`; `let`/`const` are hoisted but remain in a "Temporal Dead Zone" (TDZ) until the line is executed.

**JS2** — The **Event Loop** manages asynchronous execution. The **Call Stack** handles synchronous functions. When an async operation completes, its callback enters a queue. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority than the **Macrotask Queue** (setTimeout, setInterval, I/O). The loop checks the stack; if empty, it exhausts the entire Microtask queue before moving to the next single Macrotask.

**JS3** — A **closure** is a function that "remembers" its lexical scope even when executed outside that scope. *Example:* A function returning another function that increments a private counter. *Classic Bug:* Using `var` in a `for` loop with `setTimeout`; all timeouts end up using the final value of the variable. *Fix:* Use `let` (which creates a new binding per iteration) or an IIFE.

**JS4** — `Promise` represents an eventual completion/failure. `async/await` is syntactic sugar for working with Promises. Error handling: `async/await` uses `try/catch` blocks; Promises use `.catch()`. `Promise.all` rejects immediately if *any* promise fails. `Promise.allSettled` waits for all promises to either fulfill or reject, returning an array of descriptors.

**JS5** — `interface` is primarily for defining object shapes and is extensible via declaration merging; `type` is more flexible, allowing unions, primitives, and intersections. Use `interface` for public APIs/objects; use `type` for complex logic/unions. **Discriminated unions** use a common literal property (a "tag") to allow TypeScript to narrow types in a `switch` or `if` block.

**JS6** — **Prototypal inheritance** means objects inherit properties from a prototype object via the `[[Prototype]]` chain. `Object.create(proto)` creates a new object with `proto` as its prototype. **ES6 classes** are "syntactic sugar" over prototypes; they don't introduce a new inheritance model but provide a cleaner syntax for the same underlying prototype-based mechanism.

**JS7** — `this` refers to the execution context. **Binding Rules (Priority):** 1. `new` binding (constructor), 2. Explicit binding (`call`, `apply`, `bind`), 3. Implicit binding (the object calling the method), 4. Default binding (global object or `undefined` in strict mode). `bind()` returns a **new function** with a fixed `this` context; it cannot be re-bound.

**JS8** — `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` executes a callback after an object is GC'd. `WeakMap` keys must be objects so that if the key is no longer reachable elsewhere, the entry can be GC'd. This prevents memory leaks in large caches.

**JS9** — **V8 Optimizations:** **Hidden Classes** (Shapes) track object properties to optimize access; **Inline Caching** remembers property offsets; **Deoptimization** occurs when the engine's assumptions fail. *Causes:* Changing the order of property assignment, adding properties dynamically to objects, or passing different types to the same function (polymorphism).

**JS10** — **Tree-shaking** is dead-code elimination. It works with **ES Modules** because `import/export` are static (analyzable at compile time). **CommonJS** (`require`) is dynamic/runtime-based, making it difficult for bundlers to prove a module is unused without executing the code, thus preventing effective tree-shaking.

**JS11** — `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion (e.g., `null == undefined` is `true`); `===` checks both value and type (`null === undefined` is `false`). **Nullish coalescing (`??`)** returns the RHS only if the LHS is `null` or `undefined`. **Optional chaining (`?.`)** short-circuits to `undefined` if the reference is nullish.

**JS12** — `map()` transforms each element; `filter()` returns a subset; `reduce()` accumulates elements into a single value. `reduce()` with an **initial value** prevents errors on empty arrays and provides a starting point for the accumulator. `flatMap()` maps each element and then flattens the result by one level, useful for cleaning up nested arrays.

**JS13** — **Template literals** use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** allow a function to parse the template literal. *Example:* `sql``` where the function receives the string parts and values separately to sanitize inputs and prevent SQL injection.

**JS14** — **Destructuring** extracts values from arrays or objects. *Object:* `const {a, b} = obj`. *Array:* `const [x, y] = arr`. *Default:* `const {a = 1} = obj`. *Renaming:* `const {a: newName} = obj`. The **rest operator** (`...`) collects remaining elements into a new array/object.

**JS15** — `for...in` iterates over **enumerable property keys** (strings). `for...of` iterates over **iterable values**. Avoid `for...in` on arrays because it iterates over indices as strings and may include inherited properties from the prototype chain.

**JS16** — **Generics** allow reusable components. `extends` (Constraint): `function identity<T extends string>(arg: T)`. **Conditional Types**: `T extends U ? X : Y` returns X if T is a subtype of U. **`infer`**: Used in conditional types to extract a type from within another (e.g., `ReturnType<T>`).

**JS17** — **CommonJS** (`require`) is the legacy Node.js standard (synchronous). **ES Modules** (`import`) is the JS standard (asynchronous/static). Node.js handles both via the `.mjs` extension or `"type": "module"` in `package.json`.

**JS18** — **Structural Typing:** If the shapes match, the types match. **Excess property checks** apply when assigning an object literal directly to a type. `extends` is for subtyping; `satisfies` ensures an object meets a type without widening the variable's inferred type. **Variance:** `in` (contravariance) relates to function arguments; `out` (covariance) relates to return values.

**JS19** — `Proxy` wraps an object to intercept operations; `Reflect` provides the same methods as the Proxy traps but returns values normally. *Example:* A Proxy can intercept `get` to log access or `set` to validate that a value is a number before assignment.

**JS20** — `SharedArrayBuffer` allows multiple Web Workers to point to the same memory. **Atomics** provides static methods to perform thread-safe operations (like `Atomics.add` or `Atomics.wait`) to prevent race conditions. `Atomics.wait` pauses a thread until `Atomics.notify` is called on a specific index.

## Bash (20 questions)

**B1** — `$@` represents all arguments as separate words. `$*` represents all arguments as a single string. `"$@"` (quoted) is preferred as it preserves arguments with spaces as distinct entities; `"$*"` (quoted) merges everything into one string.

**B2** — `-e`: Exit immediately if a command fails. `-u`: Treat unset variables as an error. `-o pipefail`: The return value of a pipeline is the status of the last command to exit with a non-zero status.

**B3** — `$(command)` is command substitution (executes command and returns output). `` `command` `` is the older syntax. `$((expression))` is for arithmetic expansion. `expr` is an external command for math (slower and less capable than `$(( ))`).

**B4** — **Process substitution** `<(command)` treats the output of a command as a file. *Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands as if they were files.

**B5** — Use `find -print0 | xargs -0` or `for f in */;`. `for f in $(ls)` is dangerous because it performs word splitting on spaces and globbing on special characters, breaking filenames.

**B6** — `<<EOF` is a **here document** (multiline). `<<<` is a **here string** (single line). `<<-EOF` strips leading **tabs** (not spaces) from the document.

**B7** — `cmd > file 2>&1`: Redirects stdout to file, then redirects stderr to where stdout is currently pointing (the file). `cmd 2>&1 > file`: Redirects stderr to stdout (terminal), then redirects stdout to file (stderr stays on terminal). `cmd &> file`: Redirects both stdout and stderr to the file.

**B8** — Use `mkdir` because `mkdir` is an atomic operation at the kernel level; if two processes try to `mkdir` the same directory, only one succeeds.
```bash
lockdir="/tmp/mylock"
if mkdir "$lockdir" 2>/dev/null; then
    trap 'rmdir "$lockdir"' EXIT INT TERM
    # critical section
else
    echo "Locked" && exit 1
fi
```

**B9** — `'...'` (Single): Literal string, no expansion. `"..."` (Double): Allows variable expansion (`$VAR`) and command substitution. No quotes: Performs word splitting and globbing. *Example:* `echo '$HOME'` prints `$HOME`; `echo "$HOME"` prints `/home/user`.

**B10** — `[ -f file ]` (file), `[ -d dir ]` (directory), `[ -r file ]` (readable). `[[ ]]` is a bash keyword that is more robust, handles empty variables better, and supports regex (`=~`).

**B11** — `$?`: Exit status of last command. `$$`: PID of current script. `$!`: PID of last background process. `$#`: Number of arguments.

**B12** — `function foo {}` and `foo() {}` are mostly identical in Bash, though `foo()` is more portable. Return values are passed via `echo` (stdout) or `return` (exit status 0-255).

**B13** — `PATH` is a colon-separated list of directories. Bash searches them in order. **Builtin** (e.g., `cd`) is part of the shell; **External** (e.g., `ls`) is a file in `PATH`. Use `type -a command` to check.

**B14** — `trap 'cleanup_func' EXIT INT TERM`. `EXIT` triggers on script end; `INT` (Ctrl+C) and `TERM` (kill) trigger on signals. Signals are handled as they arrive; if multiple arrive, they are queued.

**B15** — `xargs` reads items from stdin. `find -print0 | xargs -0` handles spaces/newlines by using the null character as a delimiter. `xargs -P N` runs N processes in parallel.

**B16** — `arr=(val1 val2)`. Append: `arr+=("new")`. Length: `${#arr[@]}`. Iterate: `for i in "${arr[@]}"`. Associative: `declare -A map`.

**B17** — `(...)` is a **subshell** (new process, new scope). `{ ...; }` is a **group command** (same process, same scope). Piping into a `while` loop creates a subshell, so variable changes inside the loop are lost to the parent.

**B18** — `SIGINT` (Interrupt/Ctrl+C), `SIGTERM` (Termination/Polite), `SIGHUP` (Hangup/Terminal closed), `SIGKILL` (Immediate/Cannot be caught). Use `trap` to catch `TERM` and clean up background processes.

**B19** — Use `split` to chunk the file, `xargs -P` to run a function on chunks. *Trade-off:* Parallelism increases speed but increases CPU/IO contention. *Error propagation:* Check exit codes of `xargs` or use a wrapper that logs failures to a file.

**B20** — `exec` replaces the current shell process with the new command. `exec 3>file` opens FD 3 for writing. `exec 3>&-` closes it. A **coprocess** (`coproc`) allows two-way communication via pipes.

## PowerShell (20 questions)

**PS1** — `Write-Output` sends objects to the pipeline. `Write-Host` sends text directly to the host (console). `Write-Host` cannot be captured by redirection or pipelines.

**PS2** — `ForEach-Object` is a cmdlet that processes pipeline input one by one. The `foreach` statement is a language keyword that iterates over a collection already in memory. Use `foreach` for speed on large in-memory arrays; use `ForEach-Object` for memory efficiency in pipelines.

**PS3** — `[PSCustomObject]` is an ordered collection of properties. `[hashtable]` is an unordered key-value pair. Use `[PSCustomObject]` for data passing; use `[hashtable]` for lookups. Convert: `[PSCustomObject]@{Name="A"; Value=1}`.

**PS4** — **Terminating** errors stop execution; **Non-terminating** errors continue. `-ErrorAction` (e.g., `Stop`, `SilentlyContinue`) controls this. `try/catch` only catches terminating errors unless `ErrorAction` is set to `Stop`.

**PS5** — **Splatting** uses a hashtable to pass parameters: `$p = @{Path="C:\"; Force=$true}; Get-Item @p`. This is cleaner than passing many individual arguments.

**PS6** — `Invoke-Command` runs code on remote computers (one-to-many). `Enter-PSSession` is an interactive session. Both use **WSMan/WinRM** (default) or **SSH**.

**PS7** — The function returns an array. If empty, `$x` becomes `$null`. `$x.GetType()` fails because you cannot call methods on `$null`. *Correct pattern:* `[array]$result = @()` or check `if ($null -ne $x)`.

**PS8** — `[scriptblock]` is a piece of code. To pass it remotely, use `Invoke-Command -ScriptBlock { ... }`. The **double-hop problem** occurs when a remote machine cannot use your credentials to access a third machine. Solve with **CredSSP** or Kerberos delegation.

**PS9** — `@()` is an empty array; `[array]` is a type. To force a single result into an array, use `@($result)`. Indexing `$null` returns `$null`.

**PS10** — `-eq` (equality), `-match` (regex), `-contains` (checks if a collection contains a value), `-in` (checks if a value is in a collection). Case-sensitive variants use `-ceq`, `-cmatch`, etc.

**PS11** — `.psm1` is a script module (logic). `.psd1` is a manifest (metadata). Binary modules are compiled DLLs. `Import-Module` loads them into the session.

**PS12** — `"..."` allows interpolation. `'...'` is literal. Use `$()` for expressions: `"Value is $($obj.Prop)"`. A **here-string** is `@'...'@` (literal) or `@"..."@` (interpolated).

**PS13** — `Get-Member` shows the type and members of an object. `Select-Object` picks specific properties; `Where-Object` filters objects based on criteria.

**PS14** — PowerShell classes are wrappers around .NET classes. They support inheritance but are less flexible than C# (e.g., limited interface implementation). Use **classes** for complex data structures; use **functions** for procedural tasks.

**PS15** — `[CmdletBinding()]` makes a function behave like a cmdlet (enabling `-Verbose`, etc.). `SupportsShouldProcess` enables `-WhatIf`. `Begin/Process/End` blocks allow efficient pipeline processing.

**PS16** — **Providers** allow PowerShell to treat different data stores (Registry, Certificate, Environment) as a file system. `cd Registry::HKEY_LOCAL_MACHINE` works because of the Registry provider.

**PS17** — A `[runspace]` is a single thread of execution. `ForEach-Object -Parallel` (v7+) is a high-level way to run tasks in parallel using a runspace pool internally.

**PS18** — **PSScriptAnalyzer** is a static code analysis tool. It uses rules to check for best practices. Rules have severity (Error, Warning, Info). Suppress with `# PSScriptAnalyzer -DisableRule`.

**PS19** — `$using:var` is used to pass local variables into a remote/parallel scope. **Serialization** (CLIXML) can strip complex object methods/types, leaving only the raw data.

**PS20** — **DSC** uses **Configurations** (code) and **Resources** (logic) managed by the **LCM** (Local Configuration Manager). In modern infra, DSC is often replaced by **Terraform** or **Ansible**.
