## Kubernetes (20 questions)

**K1** — **Deployment** manages stateless applications where pods are interchangeable. **StatefulSet** manages stateful applications, providing stable, unique network identifiers (pod names) and persistent storage that stays with the pod even if rescheduled.

**K2** — A **ClusterIP** service uses `kube-proxy` (via iptables or IPVS) to create a virtual IP. When traffic hits this IP, the proxy intercepts it and performs DNAT (Destination Network Address Translation) to route the packet to one of the healthy pod IPs listed in the service's **Endpoints** object.

**K3** — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a user's request for storage (the "ticket"). **StorageClass** is a template that allows for dynamic provisioning; when a PVC is created, the StorageClass automatically provisions a PV of the requested type.

**K4** — 
1. `kubectl logs <pod>`: Check application-level errors/stack traces.
2. `kubectl describe pod <pod>`: Check for OOMKilled, Liveness probe failures, or scheduling issues.
3. Check **Resource Limits**: Ensure the pod isn't hitting CPU/Memory limits.
4. Check **Liveness/Readiness Probes**: Ensure the application isn't failing its health checks.

**K5** — **CoreDNS** provides service discovery via DNS within the cluster. If CoreDNS pods are down, internal service-to-service communication via DNS names will fail, and external resolution (via upstream) will also fail.

**K6** — The scheduler follows two main phases:
1. **Filtering (Predicates):** Removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, Taints).
2. **Scoring (Priorities):** Ranks remaining nodes to find the "best" fit.
**Factors:** Node resource availability, Pod affinity/anti-affinity, and Image locality (preferring nodes that already have the container image).

**K7** — **Yes**, it will be scheduled. The node has 500Mi available (4GB - 3.5GB), and the pod only requests 256Mi. However, if it uses **600Mi** at runtime, it will exceed its `limit.memory` (512Mi) and be terminated by the kernel with an **OOMKilled** error.

**K8** — 
1. **External LB** receives the request and forwards it to the **Ingress Controller** (e.g., NGINX).
2. The **Ingress Controller** looks up the host/path rules and identifies the target **Service**.
3. The Service's **Endpoints** object provides the specific Pod IPs.
4. **kube-proxy** (via iptables/IPVS) ensures the traffic is routed from the controller to the correct Pod IP.

**K9** — A **NetworkPolicy** defines how groups of pods are allowed to communicate with each other and other network endpoints. By default, if no policy exists, all traffic is allowed (open). Once a policy is applied to a namespace, it acts as an "allow-list"; any traffic not explicitly permitted by a policy is denied.

**K10** — **RollingUpdate** replaces pods one-by-one to ensure zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when you have a singleton requirement (e.g., a database that cannot have two instances running simultaneously) or when a breaking schema change requires no overlap between versions.

**K11** — A **Namespace** is a logical partition within a cluster to provide isolation. Default namespaces: `default`, `kube-system`, and `kube-public`.

**K12** — `kubectl describe` provides:
1. **Events** (e.g., "Successfully pulled image", "Failed to mount volume").
2. **Container Status** (e.g., "Terminated", "Reason: Error").
3. **Detailed Node/IP information** (e.g., Pod IP, Node name).

**K13** — A **ConfigMap** stores non-confidential configuration data. 
**Methods:** 
1. Injecting values as **Environment Variables**.
2. Mounting the ConfigMap as a **Volume** (files).

**K14** — 
- **ClusterIP:** Internal-only access (default).
- **NodePort:** Exposes the service on a static port on every Node's IP.
- **LoadBalancer:** Provisions an external Load Balancer from a cloud provider to route traffic to the service.

**K15** — A **DaemonSet** ensures that a copy of a specific pod runs on all (or selected) nodes in the cluster. Use it for infrastructure tasks like **logging agents** (Fluentd) or **monitoring agents** (Prometheus Node Exporter).

**K16** — **Taints** are applied to **Nodes** to repel pods (e.g., "don't run anything here unless it's a specialized pod"). **Tolerations** are applied to **Pods** to allow them to stay on tainted nodes. 
**Node Affinity** is applied to **Pods** to attract them to specific nodes.
**Use Case:** Taint a node with GPUs to ensure only ML workloads (with the correct toleration) run there; use Node Affinity to ensure a web server always runs on a node in a specific Availability Zone.

**K17** — An **Operator** is a custom controller that uses **Custom Resource Definitions (CRDs)** to automate complex, domain-specific operational knowledge (like managing a database cluster). Unlike a standard controller (which manages generic objects like Pods), an Operator manages the *entire lifecycle* of a specific application (backups, upgrades, scaling).

**K18** — etcd uses the **Raft consensus algorithm**. If the **quorum** (majority) is lost, the cluster becomes read-only and cannot commit new changes. To recover from losing 2 out of 3 nodes, you must restore the etcd state from a **backup** onto a new set of nodes to re-establish a majority.

**K19** — **Role** (namespace-scoped permissions), **ClusterRole** (cluster-wide permissions), **RoleBinding** (links Role to User in a namespace), **ClusterRoleBinding** (links ClusterRole to User cluster-wide).

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: target-namespace
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: target-namespace
subjects:
- kind: User
  name: developer-user
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — The `ndots:5` setting in `/etc/resolv.conf` tells the resolver that if a name has fewer than 5 dots, it must append several search domains (e.g., `svc.cluster.local`, etc.) before trying the name as-is. This causes multiple failed DNS queries for every external request. 
**Fix:** Use `dnsConfig` in the Pod spec to set `ndots: 1` or use a fully qualified domain name (ending in a `.`) in the application code.

## Development (20 questions)

**D1** — **Merge** combines histories by creating a new "merge commit." **Rebase** rewrites history by moving your commits to the tip of the target branch. **Avoid rebasing** on public/shared branches, as it rewrites history and breaks other developers' local copies.

**D2** — **TCP** is connection-oriented and reliable (HTTP, SSH). **UDP** is connectionless and faster (DNS, VoIP).

**D3** — A **race condition** occurs when the outcome depends on the timing of uncontrollable events. 
**Example:** Two threads executing `counter += 1` simultaneously; both read `10`, both increment to `11`, and the final value is `11` instead of `12`.

**D4** — **Symmetric** uses one key for both encryption/decryption. **Asymmetric** uses a public/private key pair. In **TLS**, asymmetric encryption is used during the initial handshake to securely exchange a session key, which is then used with symmetric encryption for the actual data transfer.

**D5** — A **layer** is a read-only filesystem snapshot. **Layer caching** means Docker reuses layers if the instruction and files haven't changed. **Best practice:** Order Dockerfile commands from "least frequently changed" to "most frequently changed" to maximize cache hits.

**D6** — 
1. Check **Application Logs** (errors/exceptions).
2. Check **Service/Pod Health** (Are they passing readiness probes?).
3. Check **Resource Constraints** (Is the app hitting CPU/Memory limits?).
4. Check **Upstream Dependencies** (Is a database or external API down?).

**D7** — **CAP Theorem:** Consistency, Availability, Partition Tolerance. 
**CP (Consistency/Partition):** ZooKeeper (prioritizes data accuracy over availability). 
**AP (Availability/Partition):** Cassandra (prioritizes uptime/response over immediate consistency).

**D8** — **Horizontal scaling** adds more instances (nodes/pods). **Vertical scaling** adds more resources (CPU/RAM) to an existing instance. **Patterns:** Statelessness (allows any instance to handle any request) and Load Balancing.

**D9** — An **environment variable** is a dynamic value used by processes. To persist in Linux, add `export VAR_NAME=value` to your `~/.bashrc` or `~/.profile` file.

**D10** — **JSON** is a strict, machine-readable format. **YAML** is a human-readable, indentation-based format. **JSON advantage:** Faster parsing/smaller footprint. **YAML advantage:** Supports comments and is easier for humans to write/read.

**D11** — **REST API** is an architectural style for networked applications. 
- **GET:** Retrieve data.
- **POST:** Create new data.
- **PUT:** Update/Replace existing data.
- **DELETE:** Remove data.

**D12** — **Version pinning** is specifying exact versions of dependencies (e.g., `lib-v1.2.3` instead of `lib-latest`). It is vital for **reproducible builds**, ensuring the same code produces the same binary every time.

**D13** — **Compiled** languages are converted to machine code before execution (C++, Go). **Interpreted** languages are executed line-by-line by a runtime (Python, Ruby).

**D14** — A **reverse proxy** sits in front of servers to protect them (e.g., NGINX for load balancing). A **forward proxy** sits in front of clients to hide them (e.g., a corporate proxy). 
**Reverse Proxy examples:** NGINX (Load Balancing), HAProxy (SSL Termination).

**D15** — A **deadlock** is a state where processes are stuck waiting for each other. **Coffman Conditions:** 
1. Mutual Exclusion. 2. Hold and Wait. 3. No Preemption. 4. Circular Wait.

**D16** — **Eventual consistency** means data will be consistent across all nodes *eventually*, but not immediately. **Cassandra** uses tunable consistency: `ONE` (fastest, lowest consistency), `QUORUM` (majority), or `ALL` (slowest, highest consistency).

**D17** — **mTLS** requires both client and server to present certificates. 
**Handshake:** Client sends "Hello" + Cert $\rightarrow$ Server verifies $\rightarrow$ Server sends its Cert $\rightarrow$ Client verifies $\rightarrow$ Session keys exchanged. 
**Usage:** Commonly used in **Service Meshes** (like Istio) for zero-trust internal communication.

**D18** — A **hash table** maps keys to indices via a hash function. 
**Collision Resolution:** **Chaining** (linked lists at each index) or **Open Addressing** (finding the next empty slot). 
**Complexity:** Average $O(1)$ for all; Worst case $O(n)$.

**D19** — A **circuit breaker** stops requests to a failing service to prevent **cascading failures**. 
- **Closed:** Normal operation. 
- **Open:** Service is failing; requests fail fast immediately. 
- **Half-Open:** Periodically allows a few requests to see if the service recovered. 
**Relation:** It works with **retries** and **exponential backoff** to ensure we don't overwhelm a recovering system.

**D20** — **Optimistic** assumes conflicts are rare; it checks for changes (e.g., via a version number) only at the time of commit. **Pessimistic** assumes conflicts will happen; it locks the resource immediately (e.g., `SELECT FOR UPDATE`). 
**Choice:** Use Optimistic for high-read/low-write systems; use Pessimistic for high-contention/critical financial transactions.
