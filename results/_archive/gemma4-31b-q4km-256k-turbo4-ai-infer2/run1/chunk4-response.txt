## Go

**G1** — An **array** has a fixed size defined at compile time; a **slice** is a dynamic window into an underlying array. When a slice reaches its capacity during an `append`, Go allocates a new, larger underlying array (usually doubling in size), copies the existing elements, and updates the slice pointer.

**G2** — `var x int` declares a variable with its zero value (`0`); `x := 0` is short-variable declaration that infers the type. You **cannot** use `:=` at the package level (global scope) or when redeclaring a variable without a new variable in the assignment.

**G3** — A **goroutine** is a lightweight thread managed by the Go runtime, not the OS. The **GMP model** consists of **G** (Goroutine), **M** (Machine/OS Thread), and **P** (Processor/Logical Context). The scheduler multiplexes Gs onto Ms using Ps to handle work-stealing and efficient scheduling.

**G4** — Channels are typed conduits for communication. **Unbuffered** channels block the sender until a receiver is ready (synchronous). **Buffered** channels allow sending up to the buffer capacity without blocking. If a buffered channel is full, the sender blocks until space is made.

**G5** — The `context` package manages deadlines, cancellation signals, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
```

**G6** — Go uses **implicit satisfaction**: if a type implements the methods of an interface, it satisfies it (no `implements` keyword). Java/C# use explicit declaration. `any` (empty interface) can hold any value; it is powerful for generic-like behavior but dangerous because it bypasses compile-time type safety, requiring runtime type assertions.

**G7** — Go's memory model does not guarantee that a write in one goroutine is immediately visible to another without synchronization. The example is unsafe because `ready` and `data` are accessed concurrently without a "happens-before" relationship. **Fix:** Use `sync.Mutex`, `sync/atomic`, or a channel to signal completion.

**G8** — `sync.Mutex` is an exclusive lock; `sync.RWMutex` allows multiple concurrent readers or one writer. Use `sync.Map` for high-contention scenarios with disjoint keys or read-heavy workloads to reduce lock contention. Trade-off: `sync.Map` is slower for simple cases due to internal interface casting and complexity.

**G9** — `go.mod` defines the module path and dependencies; `go.sum` stores cryptographic checksums for reproducibility. `go mod tidy` removes unused modules and adds missing ones. **MVS (Minimum Version Selection)** selects the lowest version of a dependency that satisfies all constraints in the graph.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. **Gotcha:** Placing `defer` inside a loop can cause resource exhaustion because they don't execute until the function exits, not the loop iteration.

**G11** — A pointer stores the memory address of a value. The zero value is `nil`. Create a pointer to a struct literal using the address-of operator: `p := &User{Name: "Alice"}`.

**G12** — `init()` runs before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the file, and packages are initialized in the order of their imports.

**G13** — `make` initializes slices, maps, and channels (returning an initialized object). `new` allocates zeroed memory for any type and returns a pointer to it.

**G14** — Errors are values implementing the `error` interface. Idiom: `if err != nil { return err }`. `errors.Is` checks if an error wraps a specific target; `errors.As` attempts to cast an error to a specific type. `==` only works for sentinel errors and doesn't handle wrapped errors.

**G15** — **Map:** `nil`. **Slice:** `nil`. **Channel:** `nil`. **Struct:** Fields are set to their respective zero values.

**G16** — A race condition occurs when two goroutines access shared memory concurrently and at least one is a write. The `-race` flag enables a runtime detector. **Fix:** Use a `sync.Mutex` to wrap the shared variable or use a channel to pass ownership of the data.

**G17** — `select` blocks until one of its channel operations can proceed. Unlike `switch` (which evaluates values), `select` handles communication. If multiple cases are ready, one is chosen **pseudo-randomly**. Timeout: `case <-time.After(1 * time.Second):`.

**G18** — Escape analysis determines if a variable can stay on the stack or must move to the heap. If a variable is referenced outside the function scope, it "escapes" to the heap. Inspect via `go build -gcflags="-m"`. Heap allocation increases GC pressure and reduces performance.

**G19** — `reflect.Type` represents the static type; `reflect.Value` represents the dynamic value. Reflection is slow due to runtime checks and heap allocations. It is justified for generic libraries (e.g., JSON encoders) where types aren't known at compile time; otherwise, code generation is preferred.

**G20** — `go:embed` allows embedding files/folders into the binary at compile time. It returns a `string`, `[]byte`, or `embed.FS` (for directories). It is read-only and integrates with `io/fs.FS` for a standardized filesystem abstraction.

## Rust

**R1** — Ownership ensures memory safety without a GC. Rules: 1. Each value has one owner. 2. When the owner goes out of scope, the value is dropped. 3. Assigning a value to another variable **moves** ownership.

**R2** — `String` is an owned, heap-allocated, growable string. `&str` is an immutable slice (reference) to a string. Use `&str` in function signatures to accept both `String` and `&str` (via deref coercion).

**R3** — The borrow checker enforces: 1. You can have either one mutable reference (`&mut T`) OR any number of immutable references (`&T`) at any given time. 2. References must always be valid (cannot outlive the owner).

**R4** — `Result<T, E>` handles recoverable errors; `Option<T>` handles optionality (Some/None). The `?` operator returns the error early if the result is `Err`.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path).map_err(|e| e) // or just return the result
}
```

**R5** — `Box<T>`: Heap allocation (single ownership). `Rc<T>`: Reference counted (single-threaded shared ownership). `Arc<T>`: Atomic reference counted (thread-safe shared ownership).

**R6** — Traits define shared behavior. Go interfaces are implicit; Rust traits are explicit. `T: Trait` uses **static dispatch** (monomorphization), creating a version of the function for every type. `dyn Trait` uses **dynamic dispatch** (vtable), allowing heterogeneous collections.

**R7** — The compiler doesn't know which input reference the return value refers to. **Fix:** Add lifetime annotations to specify that the return value lives as long as the shortest input: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8** — `Send` means a type can be transferred between threads; `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send`/`Sync` because its reference counter is not atomic. `Arc<T>` uses atomic operations for the counter, making it thread-safe.

**R9** — Rust's `async` is a state-machine transformation. A `Future` is a trait with a `poll` method. An **executor** (like Tokio) polls the future until it returns `Ready`. Go's goroutines are managed by a runtime scheduler; Rust's async is "lazy" and requires an external executor.

**R10** — `unsafe` allows bypassing certain borrow checker rules. You can: 1. Dereference raw pointers. 2. Call unsafe functions. 3. Access/mutate static mutable variables. It is justified for FFI, implementing low-level data structures, or extreme performance optimizations.

**R11** — Pattern matching (`match`) is exhaustive; the compiler forces you to handle all possible enum variants. `if let` is syntactic sugar for matching a single pattern while ignoring others.

**R12** — `Vec<T>` is a heap-allocated growable array; `[T; N]` is a fixed-size stack array. When a `Vec` exceeds capacity, it reallocates a larger block of memory and copies elements (amortized O(1) push).

**R13** — Rust enums are **Algebraic Data Types** (can hold data per variant). `Option<T>` is an enum (`Some(T)` or `None`), replacing `null` to force explicit handling of the "empty" case.

**R14** — `impl` blocks define methods. `&self` (immutable borrow), `&mut self` (mutable borrow), `self` (consumes/takes ownership). Associated functions (e.g., `String::new()`) do not take `self` and are called on the type itself.

**R15** — `derive` automatically implements traits. Common: `Debug`, `Clone`, `PartialEq`. You cannot derive a trait if any field within the struct does not also implement that trait.

**R16** — `Cow` (Clone-on-Write) allows a value to be either borrowed or owned. It avoids allocation by keeping data as a reference until mutation is required, at which point it clones the data.

**R17** — `mod` declares a module, `use` brings paths into scope, `pub` makes items visible. In Rust 2018, the module system was simplified to map more naturally to the file system (e.g., `mod.rs` became optional in favor of `name.rs`).

**R18** — `Pin<T>` ensures a value cannot be moved in memory. This is critical for **self-referential structs** (where a field points to another field in the same struct), which are common in `async` futures. `Unpin` is a marker trait for types that are safe to move.

**R19** — `macro_rules!` are declarative (pattern matching). Procedural macros (derive, attribute, function-like) are compiler plugins that manipulate the AST. Rust macros are **hygienic**, meaning they don't accidentally capture variables from the surrounding scope.

**R20** — Zero-cost abstractions mean you don't pay for what you don't use. **Monomorphization** generates specialized code for each generic type at compile time, removing the need for runtime boxing/casting, resulting in performance identical to hand-written C.
