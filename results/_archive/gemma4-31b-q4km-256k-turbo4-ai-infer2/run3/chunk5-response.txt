## .NET / C#

**DN1**: A **class** is a reference type (allocated on the heap), while a **struct** is a value type (usually allocated on the stack or inline). Use a struct for small, immutable data structures (e.g., a `Point` or `Color`) to reduce GC pressure and improve memory locality.

**DN2**: `IEnumerable<T>` is for in-memory collections; it pulls all data into memory before filtering. `IQueryable<T>` is for providers (like EF Core) and translates LINQ expressions into a query (e.g., SQL) to be executed on the server. This distinction prevents "over-fetching" data from the database.

**DN3**: `async/await` uses a state machine to yield control back to the caller while waiting for I/O, preventing thread blocking. `Task` is a class (heap allocation); `ValueTask` is a struct. Use `ValueTask` for methods that often complete synchronously to avoid unnecessary heap allocations.

**DN4**: DI is a pattern to achieve inversion of control. **Transient**: New instance every time. **Scoped**: One instance per request. **Singleton**: One instance for the app lifetime. **Bug**: "Captive Dependency"—injecting a Scoped service into a Singleton. The Scoped service is held for the app's life, potentially causing memory leaks or stale data.

**DN5**: `string` is an immutable heap object. `ReadOnlySpan<char>` is a stack-based view into a contiguous region of memory. Use `Span<T>` for high-performance slicing and parsing (e.g., parsing a CSV) to avoid creating multiple substring allocations.

**DN6**: The GC uses generations to optimize: **Gen 0** (short-lived), **Gen 1** (buffer), **Gen 2** (long-lived). The **LOH (Large Object Heap)** stores objects > 85KB to avoid expensive memory compaction. `IDisposable` is needed for unmanaged resources (file handles, sockets) because the GC only manages memory, not OS handles.

**DN7**: `ConfigureAwait(false)` tells the runtime not to marshal the continuation back to the original `SynchronizationContext` (e.g., UI thread). Use it in libraries to avoid deadlocks and improve performance. Do NOT use it in UI code where you must update the UI on the main thread.

**DN8**: **Primary Constructors**: Parameters defined directly in the class declaration. **Collection Expressions**: `int[] arr = [1, 2, 3];`. **FrozenDictionary**: Immutable, highly optimized for read-heavy lookups.
*Example:* `public class OrderService(IDbContext db) { public void Save() => db.SaveChanges(); }`

**DN9**: Cause: A `DbContext` is Scoped. If a background thread or a Singleton service tries to use a Scoped `DbContext` after the request has ended, the context is disposed. **Fix**: Use `IServiceScopeFactory` to create a new scope manually within the background task.

**DN10**: **Record**: Reference type with value-based equality. **Class**: Reference type with identity-based equality. **Record Struct**: Value type with value-based equality. Use records for DTOs/immutable data; classes for behavior/state; record structs for small, immutable value-objects.

**DN11**: `ref`: Pass by reference (must be initialized). `out`: Pass by reference (must be assigned inside the method). `in`: Pass by reference (read-only). Use `out` for returning multiple values; `ref` for modifying an existing value; `in` for large structs to avoid copying.

**DN12**: Nullable reference types (`string?`) are a static analysis feature to prevent `NullReferenceException`. They are metadata for the compiler. `int?` (Nullable<T>) is a wrapper struct that actually changes the type at runtime.

**DN13**: LINQ (Language Integrated Query) provides a unified way to query data. **Method syntax** uses lambdas; **Query syntax** looks like SQL. **Deferred execution** means the query is not executed until you iterate over it (e.g., via `foreach` or `.ToList()`).

**DN14**: Constraints restrict `T`. `class`: Reference type. `struct`: Value type. `new()`: Must have a parameterless constructor. `IComparable<T>`: Must implement the interface. Combine them (e.g., `where T : class, new()`) to ensure a type is both a reference type and instantiable.

**DN15**: **Abstract class**: "Is-a" relationship, can hold state/fields. **Interface**: "Can-do" contract. **Default Interface Methods** allow adding logic to interfaces without breaking existing implementations, blurring the line but still lacking the ability to hold instance state.

**DN16**: Middleware is a chain of delegates. `Use()` adds logic and calls `next()`. `Map()` branches the pipeline based on path. `Run()` is terminal (no `next()`). Order matters because middleware is executed sequentially; exception handling must be first to catch errors from subsequent middleware.

**DN17**: `Channel<T>` is an async producer-consumer queue. `BlockingCollection` is synchronous/blocking. Bounded channels provide backpressure by limiting the number of items in the queue; the producer will asynchronously wait (or return false) when the limit is reached.

**DN18**: **Source Generators** generate C# code during compilation. Reflection happens at runtime; IL weaving happens post-compile. **Incremental Generators** are preferred because they only re-generate code for changed files, significantly improving IDE performance.

**DN19**: TPL Dataflow is a block-based pipeline. `ActionBlock` (consumes), `TransformBlock` (maps), `BufferBlock` (queues). Compared to `Channels`, TPL Dataflow is higher-level, providing built-in orchestration and complex graph topologies.

**DN20**: Minimal APIs remove the `Controller` boilerplate. Trade-offs: Faster startup and less code, but can become cluttered. **Route groups** organize endpoints; **Endpoint filters** provide cross-cutting logic (like validation) similar to Action Filters in MVC.

## Python

**P1**: **List**: Mutable, ordered. **Tuple**: Immutable, ordered. **Set**: Mutable, unique elements. **Frozenset**: Immutable, unique elements.

**P2**: The **GIL** prevents multiple native threads from executing Python bytecodes at once. It affects CPU-bound workloads. Workarounds: Use `multiprocessing` (separate processes) or write performance-critical parts in C/Rust.

**P3**: `copy` is shallow (copies references to nested objects); `deepcopy` is recursive (creates new copies of nested objects). *Example*: If you shallow copy a list of lists, modifying a nested list in the copy will modify the original.

**P4**: A decorator is a function that wraps another function.
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        res = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.4f}s")
        return res
    return wrapper
```

**P5**: **Generators** use `yield` to produce values lazily, saving memory. `yield from` delegates to another generator/iterable. Unlike returning a list, generators don't store the whole sequence in memory.

**P6**: The event loop manages async tasks. `run()` starts the loop; `gather()` runs tasks concurrently and waits for all; `create_task()` schedules a coroutine. `time.sleep()` blocks the entire thread, stopping the loop; use `await asyncio.sleep()` to yield control.

**P7**: Python uses **C3 Linearization** for MRO. In diamond inheritance, it searches depth-first, left-to-right, but ensures no class is visited before its children. In the example, `D` inherits from `B` then `C`. Since `C` overrides `who()`, `D().who()` prints **"C"**.

**P8**: A **metaclass** is a class that creates classes. `__init_subclass__` is a simpler hook for customizing child classes. Use metaclasses for deep framework magic (e.g., Django models); use `__init_subclass__` for simple registration of subclasses.

**P9**: **Threading**: I/O bound (GIL limited). **Multiprocessing**: CPU bound (separate GILs). **concurrent.futures**: High-level abstraction for both. Multiprocessing requires **pickling** (serialization) to move data between processes, which can be slow for large objects.

**P10**: `__slots__` tells Python not to create a `__dict__` for instances. Use it to save memory and prevent the addition of dynamic attributes. It significantly reduces memory overhead for millions of small objects.

**P11**: A virtual environment isolates dependencies. `venv` is the standard library tool; `virtualenv` is a more feature-rich precursor; `conda` manages non-Python binaries and environments.

**P12**: Comprehensions are concise ways to create collections. `map`/`filter` are functional equivalents. Prefer comprehensions for readability and speed in most Pythonic cases.

**P13**: `==` checks for value equality; `is` checks for identity (memory address). **Interning** caches small integers (-5 to 256) and some strings, so `a is b` may be True for small ints because they point to the same cached object.

**P14**: `*args` collects positional args into a tuple; `**kwargs` collects keyword args into a dict. `/` marks parameters as positional-only; `*` marks subsequent parameters as keyword-only.

**P15**: Context managers handle setup/teardown. Use `__enter__`/`__exit__` in a class or `@contextmanager` generator. *Example*: A database transaction manager that commits on exit or rolls back on exception.

**P16**: Type hinting provides static analysis. `Union` (A or B), `Optional` (A or None), `Literal` (specific value), `TypeVar` (generics), `Protocol` (structural typing/interfaces). `mypy` uses these to find bugs without running the code.

**P17**: `__repr__` (developer-facing), `__str__` (user-facing). `__eq__` (equality), `__hash__` (for sets/dicts). If you define `__eq__` without `__hash__`, the object becomes unhashable. `__getattr__` is called if attribute isn't found; `__getattribute__` is called for every access.

**P18**: Descriptors implement `__get__`, `__set__`, and `__delete__`. `property`, `classmethod`, and `staticmethod` are all implemented as descriptors that control how attributes are accessed.

**P19**: `sys.path` is the search list for modules. Absolute imports start from the root; relative use `.`. `__init__.py` marks a directory as a package. **Finders** locate the module; **Loaders** load the code into memory.

**P20**: `dataclasses` automate boilerplate. `attrs` is more powerful; `Pydantic` adds runtime validation. `__post_init__` allows logic after initialization. Use Pydantic for API data validation (parsing/coercion) and dataclasses for internal data structures.
