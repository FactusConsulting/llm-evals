## JavaScript / TypeScript

**JS1**: `var` is function-scoped and can be redeclared. `let` and `const` are block-scoped; `const` cannot be reassigned. **Hoisting** is the behavior where declarations (not initializations) are moved to the top of their scope during the compilation phase, allowing functions and `var` to be referenced before they appear in the code.

**JS2**: The **Event Loop** manages asynchronous execution. The **Call Stack** handles synchronous code. When the stack is empty, the loop checks the **Microtask Queue** (Promises, `queueMicrotask`) and executes all tasks there before moving to the **Macrotask Queue** (setTimeout, I/O, UI rendering).

**JS3**: A **closure** is a function that remembers the lexical environment in which it was created. *Example*: A function returning another function that increments a private counter. *Bug*: Using `var` in a `for` loop creates one shared variable for all closures; fix by using `let` in the loop header to create a new binding for each iteration.

**JS4**: `Promise` represents a future value. `async/await` is syntactic sugar for promises, making async code look synchronous. Error handling: `try/catch` with `await` or `.catch()` with promises. `Promise.all` rejects immediately if any promise fails; `Promise.allSettled` waits for all to complete regardless of outcome.

**JS5**: `interface` is primarily for defining object shapes and supports declaration merging (extending via multiple definitions). `type` is more flexible, supporting unions, tuples, and aliases. **Discriminated Unions** use a common literal property (e.g., `type: 'circle' | 'square'`) to allow TypeScript to narrow types in a switch/if block.

**JS6**: JS uses **prototypal inheritance**, where objects inherit from other objects via a prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is syntactic sugar; it still uses prototypes under the hood but provides a cleaner syntax for constructors and methods.

**JS7**: `this` refers to the execution context. **Binding Priority**: 1. `new` (constructor), 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (object method), 4. Default (`window` or `undefined` in strict mode). `bind()` returns a new function with a fixed `this`; it cannot be re-bound.

**JS8**: `WeakRef` allows a "weak" reference to an object that doesn't prevent garbage collection (GC). `FinalizationRegistry` triggers a callback after an object is GC'd. `WeakMap` keys must be objects because the map holds a weak reference to the key; if the key is only held by the WeakMap, it can be GC'd.

**JS9**: V8 uses **Hidden Classes** (shapes) to track object properties. **Inline Caching (IC)** remembers where properties are located in memory to skip lookup. **Deoptimization** occurs when an object's shape changes (e.g., adding properties in different orders), forcing V8 to drop optimized machine code and revert to interpreted bytecode.

**JS10**: **Tree-shaking** is the removal of unused code. ESM (`import/export`) is statically analyzable, allowing tools to determine what is unused. CommonJS (`require`) is dynamic, meaning dependencies are resolved at runtime, making it nearly impossible for bundlers to safely remove "unused" exports.

**JS11**: `null` is an intentional absence of value; `undefined` means a variable was declared but not assigned. `==` performs type coercion; `===` is strict. `??` (nullish coalescing) returns the right side only if the left is `null` or `undefined`. `?.` (optional chaining) short-circuits to `undefined` if a property in the chain is null/undefined.

**JS12**: `map()` transforms each element; `filter()` returns elements meeting a condition; `reduce()` aggregates an array into a single value. If `reduce` has an initial value, it's used as the first `accumulator`. `flatMap()` maps then flattens the result by one level, useful for removing empty slots or expanding one element into many.

**JS13**: **Template literals** use backticks for interpolation (`${}`). **Tagged templates** pass the string parts and expressions to a function. *Example*: `sql`tag`SELECT * FROM users WHERE id = ${id}` could be used to automatically escape `id` to prevent SQL injection.

**JS14**: **Destructuring** unpacks values from arrays or objects into variables. `const {name, age = 20} = user` (object) or `const [first, ...rest] = arr` (array). The **rest operator** (`...`) collects remaining elements into a new array/object.

**JS15**: `for...in` iterates over enumerable keys (including inherited ones); `for...of` iterates over iterable values (arrays, maps). Avoid `for...in` on arrays because it iterates over indices as strings and may include properties added to `Array.prototype`.

**JS16**: **Generics** allow types to be passed as parameters. `extends` (constraint): `T extends string` ensures T is a string. **Conditional types**: `T extends string ? 'yes' : 'no'`. `infer` extracts a type from a pattern: `type GetReturn<T> = T extends (...args: any[]) => infer R ? R : any`.

**JS17**: **CommonJS** (`require`) is synchronous and used in Node.js. **ESM** (`import`) is static and standard. Node.js supports both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM. Otherwise, `.mjs` is ESM and `.cjs` is CommonJS.

**JS18**: TS uses a **structural type system** (if it looks like a duck, it's a duck). **Excess property checks** occur only on object literals assigned to a type. `extends` is for subtyping; `satisfies` validates a value against a type without narrowing the value's type. **Variance**: Covariance (out) allows a more specific type; Contravariance (in) allows a more general type.

**JS19**: `Proxy` intercepts operations (get, set, etc.) on an object. `Reflect` provides a mirror API to perform the original operation. *Example*: A Proxy can implement "reactive" data binding by triggering a UI update whenever a `set` trap is intercepted.

**JS20**: `SharedArrayBuffer` allows memory sharing between the main thread and Web Workers. `Atomics` provides atomic operations (add, load, store) to prevent race conditions. `Atomics.wait` puts a thread to sleep until `Atomics.notify` wakes it up.

## Bash

**B1**: `$@` is a list of all arguments; `$*` is all arguments as a single string. `"$@"` (quoted) preserves individual arguments exactly as passed; `"$*"` joins them into one string separated by the first character of `IFS`.

**B2**: `set -e` (exit immediately if a command fails), `-u` (exit if an unset variable is referenced), `-o pipefail` (the pipeline return status is the status of the last command to exit with a non-zero status, not the last command in the pipe).

**B3**: `$(command)` is the modern syntax for command substitution; `` `command` `` is the legacy version (harder to nest). `$((expression))` is shell arithmetic (fast, internal); `expr` is an external binary (slower).

**B4**: **Process substitution** `<(command)` makes the output of a command appear as a file. *Example*: `diff <(ls dir1) <(ls dir2)` compares the contents of two directories without creating temporary files.

**B5**: Use `while read -r file` or `find . -print0 | xargs -0`. `for f in $(ls)` is dangerous because it performs word splitting on filenames containing spaces or newlines, treating one file as multiple arguments.

**B6**: `<<EOF` is a **here-doc** (multiline input); `<<<` is a **here-string** (passes a single string as stdin). `<<-EOF` strips leading tab characters from the input lines for better indentation.

**B7**: `> file 2>&1` sends stdout to file, then redirects stderr to where stdout is currently going (the file). `2>&1 > file` redirects stderr to the *original* stdout (the terminal), then redirects stdout to the file. `&> file` is a bash shortcut for both.

**B8**: Use `mkdir lockdir` because it is an atomic operation at the OS level. Use `trap 'rmdir lockdir' EXIT SIGTERM SIGINT` to ensure cleanup. `mkdir` is preferred over `touch` because two processes can `touch` a file simultaneously, but only one can successfully `mkdir` a directory.

**B9**: `' '` (single) is literal; `" "` (double) allows variable expansion and command substitution; no quotes allow word splitting and globbing. *Example*: `echo "$var"` vs `echo $var` (the latter splits if `$var` contains spaces).

**B10**: `-f` (file), `-d` (directory), `-r` (readable). `[ ]` is the POSIX standard `test` command; `[[ ]]` is a Bash extension that is more powerful, handles empty variables better, and supports regex (`=~`).

**B11**: `$?` (exit status of last command), `$$` (PID of current shell), `$!` (PID of last background process), `$#` (number of arguments).

**B12**: `foo() { ... }` is POSIX; `function foo { ... }` is Bash-specific. Functions return values via `echo` (captured by `$( )`) or `return` (only for 0-255 exit codes).

**B13**: `PATH` is a colon-separated list of directories searched for executables. Bash checks: Aliases $\rightarrow$ Functions $\rightarrow$ Builtins $\rightarrow$ PATH. Use `type -a command` to see all definitions of a command.

**B14**: `trap 'cmd' SIGNAL` executes `cmd` when the signal is caught. Order: signals are handled as they arrive. `EXIT` is a pseudo-signal triggered when the shell exits.

**B15**: `xargs` reads items from stdin and executes a command. `find -print0 | xargs -0` uses the null character as a delimiter to handle spaces/newlines. `xargs -P N` runs up to N processes in parallel.

**B16**: Arrays: `arr=(1 2 3)`, `${arr[@]}` to access all. Associative: `declare -A assoc=([k]=v)`. Length: `${#arr[@]}`. Associative arrays require `declare -A` and use string keys.

**B17**: `( )` creates a subshell (forks process, variables don't leak back). `{ ...; }` is a group (runs in current shell). Piping into a `while` loop creates a subshell, so variables modified inside the loop are lost when the pipe ends.

**B18**: SIGINT (Ctrl+C), SIGTERM (polite request to stop), SIGHUP (terminal closed), SIGKILL (forced kill, cannot be trapped). Graceful shutdown: `trap 'cleanup' SIGTERM` and `kill -TERM` background PIDs.

**B19**: Use `split -l` to chunk the log, `xargs -P` to process chunks in parallel, and `cat` to merge. Trade-off: Parallelism increases CPU usage but can be bottlenecked by Disk I/O. Error propagation: use a wrapper script that exits non-zero on failure.

**B20**: `exec` replaces the current shell process with the new command. `exec 3>file` opens file descriptor 3 for writing. A **coprocess** (`coproc`) creates a background process with two-way pipes (stdin/stdout) for bidirectional communication.

## PowerShell

**PS1**: `Write-Output` sends objects to the pipeline (can be processed by other cmdlets). `Write-Host` writes directly to the console (bypasses the pipeline). This matters because `Write-Host` cannot be captured or filtered.

**PS2**: The pipeline passes objects. `ForEach-Object` is a cmdlet that processes objects one-by-one as they arrive (streaming). `foreach` is a language statement that requires the entire collection to be in memory first.

**PS3**: `[PSCustomObject]` is an ordered object with properties; `[hashtable]` is an unordered key-value pair. Use `[PSCustomObject]` for data output. Convert: `[PSCustomObject]$hash`.

**PS4**: **Terminating errors** stop the script; **non-terminating** (e.g., file not found) continue. `-ErrorAction Stop` converts a non-terminating error into a terminating one, allowing it to be caught by `try/catch`.

**PS5**: **Splatting** passes a hashtable of parameters using `@params` instead of `-param value`. *Example*: `$p = @{Path='C:\'; Recurse=$true}; Get-ChildItem @p`. It improves readability over long command lines.

**PS6**: `Invoke-Command` runs a script block on a remote machine and returns results. `Enter-PSSession` starts an interactive session. They use **WinRM** (WS-Man) or **SSH** (in PS 7+).

**PS7**: The pipeline "unwraps" arrays. If `Get-Items` returns an array, the pipeline sends each element individually. If it returns 0 items, it returns `$null`. Correct pattern: wrap the call in `@(Get-Items)` to ensure an array is always returned.

**PS8**: A `[scriptblock]` is a first-class object `{ ... }` that can be passed as a parameter. The **double-hop problem** occurs when a remote session tries to access a second remote resource. Solve via **CredSSP** or passing credentials via `-ArgumentList`.

**PS9**: `@()` is the array literal; `[array]` is the type. Indexing into `$null` returns `$null` in PowerShell, whereas indexing into an empty array returns `$null` (or errors depending on the version/context).

**PS10**: `-eq` (equal), `-like` (wildcard `*`), `-match` (regex). Case-insensitive by default; use `-ceq` for case-sensitive. `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection (inverse of `-contains`).

**PS11**: A module is a package of functions/classes. `.psm1` contains code; `.psd1` is a manifest (version, author). `Import-Module` loads the module into the current session.

**PS12**: `" "` allows interpolation; `' '` is literal. Use `"$($expression)"` (sub-expression) to evaluate code inside a string. A **here-string** `@" ... "@` allows multi-line strings without escaping.

**PS13**: `Get-Member` shows the object's type, properties, and methods. `Select-Object` filters properties (columns); `Where-Object` filters objects (rows). NoteProperties are properties added dynamically at runtime.

**PS14**: PS Classes (v5+) provide strong typing and inheritance. They are simpler than C# classes (no interfaces). Use classes for structured data models; use functions for logic and pipeline-friendly tools.

**PS15**: `[CmdletBinding()]` makes a function an "Advanced Function," enabling `-WhatIf` and `-Confirm` via `SupportsShouldProcess`. `Begin` (setup), `Process` (per-object logic), and `End` (cleanup) blocks optimize pipeline performance.

**PS16**: Providers map different data stores (Registry, Certs) to a drive-like interface. `Get-ChildItem` works on all. You can access the registry via `cd HKLM:\` and navigate it like a folder.

**PS17**: A **runspace** is an isolated execution environment (thread). `ForEach-Object -Parallel` (v7) abstracts runspace management to run blocks in parallel. Manual management involves `[runspacepool]` for fine-grained control.

**PS18**: `PSScriptAnalyzer` is a static analysis tool. It uses rules (e.g., "Avoid using `Write-Host`) with severity levels. Rules can be suppressed via attributes or a config file and integrated into CI/CD to fail builds on bad code.

**PS19**: `$using:var` is used to pass local variables into a remote/parallel scope. `-ArgumentList` is the older method for `Start-Job`. Serialization (CLIXML) has depth limits; very complex objects may be truncated or lose type fidelity.

**PS20**: **DSC** is declarative; you define the *state* (e.g., "Service X must be running"), and the **LCM** (Local Configuration Manager) enforces it. In modern infra, DSC has been largely superseded by Terraform, Ansible, or Kubernetes.
