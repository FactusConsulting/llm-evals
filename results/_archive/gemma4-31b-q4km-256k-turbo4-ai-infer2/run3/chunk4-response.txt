## Go

**G1**: An **array** has a fixed size defined at compile time; a **slice** is a dynamic window into an underlying array. When a slice reaches capacity and you `append`, Go allocates a new, larger underlying array, copies the existing elements, and updates the slice pointer.

**G2**: `var x int` declares a variable with a zero value (0); `x := 0` is short-variable declaration (declares and initializes). You **cannot** use `:=` at the package level (global scope) or when redeclaring a variable without adding a new one.

**G3**: A **goroutine** is a lightweight "green thread" managed by the Go runtime, not the OS. The **GMP model** consists of **G** (Goroutine), **M** (Machine/OS Thread), and **P** (Processor/Logical Context). The scheduler multiplexes Gs onto Ms using Ps to balance load and handle syscalls.

**G4**: Channels are typed conduits for communication. **Unbuffered** channels block the sender until a receiver is ready (synchronous). **Buffered** channels have a capacity; they only block the sender when the buffer is full. Sending to a full buffered channel blocks the goroutine until space is available.

**G5**: The `context` package manages deadlines, cancellation signals, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

**G6**: Go uses **implicit satisfaction** (structural typing); if a type implements the methods of an interface, it satisfies it without an explicit `implements` keyword. `interface{}` (or `any`) can hold any value. It is powerful for generic-like behavior but dangerous because it bypasses compile-time type safety, requiring runtime type assertions.

**G7**: Go's memory model does not guarantee that a write in one goroutine is visible to another without synchronization. The example is unsafe because `ready` and `data` are accessed concurrently without a "happens-before" relationship. **Fix**: Use `sync.Mutex`, `atomic.Bool`, or a channel to signal completion.

**G8**: `sync.Mutex` is an exclusive lock; `sync.RWMutex` allows multiple concurrent readers OR one writer. Use `sync.Map` for high-contention scenarios where keys are stable or disjoint, or when reads heavily outweigh writes. Regular maps with a mutex are generally faster for low-contention or small datasets.

**G9**: `go.mod` defines the module path and dependencies; `go.sum` stores cryptographic checksums for reproducibility. `go mod tidy` adds missing modules and removes unused ones. **MVS (Minimum Version Selection)** selects the lowest version of a dependency that satisfies all constraints in the graph.

**G10**: `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In-First-Out)** order. **Gotcha**: Defers inside a loop do not execute until the function returns, which can lead to resource exhaustion (e.g., open file descriptors).

**G11**: A pointer stores the memory address of a value. The zero value is `nil`. Create a pointer to a struct literal using the address-of operator: `ptr := &MyStruct{Field: "val"}`.

**G12**: `init()` runs automatically before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the file, and packages are initialized in dependency order.

**G13**: `make` initializes slices, maps, and channels (returning an initialized object). `new` allocates zeroed memory for any type and returns a pointer to it.

**G14**: Errors are values implementing the `error` interface. Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error wraps a specific target; `errors.As` attempts to cast a wrapped error to a specific type. `==` only checks for exact identity.

**G15**: 
- Map: `nil`
- Slice: `nil`
- Channel: `nil`
- Struct: All fields set to their respective zero values.

**G16**: A race condition occurs when two goroutines access the same memory concurrently and at least one is a write. The `-race` flag enables a runtime detector. 
**Fix**: Use `sync.Mutex` to lock the critical section or use a channel to pass ownership of the data.

**G17**: `select` blocks until one of its channel operations can proceed. Unlike `switch` (which evaluates values), `select` handles communication. If multiple cases are ready, one is chosen **pseudo-randomly**. Timeout: `case <-time.After(duration):`.

**G18**: Escape analysis determines if a variable can stay on the **stack** (fast) or must move to the **heap** (slower, GC pressure). If a variable's reference is returned or shared across goroutines, it "escapes." Inspect via `go build -gcflags="-m"`.

**G19**: `reflect.Type` represents the static type; `reflect.Value` represents the dynamic value. Reflection is slow and bypasses type safety. It is justified for generic libraries (e.g., `json.Unmarshal`) where the type is unknown at compile time.

**G20**: `go:embed` allows embedding files/folders into the binary at compile time. It returns a `string`, `[]byte`, or `embed.FS` (implementing `io/fs.FS`). Limitations: embedded files are read-only and cannot be modified at runtime.

## Rust

**R1**: Ownership ensures memory safety without a GC. Rules: 1. Each value has one owner. 2. When the owner goes out of scope, the value is dropped. 3. Ownership can be moved (transferred).

**R2**: `String` is an owned, heap-allocated, growable string. `&str` is an immutable slice (reference) to a string. Use `&str` in function signatures to accept both `String` and `&str`.

**R3**: Borrowing allows temporary access. **Shared references (`&T`)** allow multiple concurrent readers. **Mutable references (`&mut T`)** allow exactly one writer and no readers. The borrow checker enforces these rules at compile time.

**R4**: `Result<T, E>` handles recoverable errors; `Option<T>` handles absence of value. The `?` operator unwraps `Ok`/`Some` or returns the `Err`/`None` early.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path) // returns Result
}
```

**R5**: `Box<T>` is a heap allocation (single owner). `Rc<T>` is a reference-counted pointer for single-threaded shared ownership. `Arc<T>` is an Atomic Reference Counted pointer for multi-threaded shared ownership.

**R6**: Traits define shared behavior. Go interfaces are implicit; Rust traits are explicit. `dyn Trait` uses **dynamic dispatch** (vtable), while `T: Trait` uses **static dispatch** (monomorphization/generics).

**R7**: Lifetimes ensure references don't outlive their data. The example fails because the compiler doesn't know which input (`x` or `y`) the return reference points to. **Fix**: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8**: `Send` means a type can be moved to another thread; `Sync` means a type can be shared between threads. `Rc<T>` is not `Send`/`Sync` because its reference count is not atomic. `Arc<T>` uses atomic operations for the count, making it thread-safe.

**R9**: `async` functions return a `Future` (a state machine). An **executor** (like Tokio) polls the future until it completes. Unlike Go's runtime-integrated scheduler, Rust's async is library-based and "pull-based" (lazy).

**R10**: `unsafe` allows bypassing certain borrow checker rules. You can: 1. Dereference raw pointers. 2. Call unsafe functions. 3. Mutate static variables. It is justified for FFI, hardware access, or extreme performance optimizations.

**R11**: `match` is an exhaustive pattern match; `if let` is a concise way to match a single pattern. The compiler forces `match` to cover all possible enum variants.

**R12**: `Vec<T>` is a growable heap-allocated array; `[T; N]` is a fixed-size stack-allocated array. When a `Vec` exceeds capacity, it reallocates a larger block of memory (usually doubling) and moves elements.

**R13**: Rust enums are **Algebraic Data Types** (can hold data per variant). `Option<T>` is an enum (`Some(T)` or `None`), replacing `null` to force explicit handling of the "empty" case.

**R14**: `impl` blocks define methods. `&self` is an immutable borrow, `&mut self` is a mutable borrow, and `self` consumes the object. Associated functions (like `String::new()`) do not take `self` and are called on the type.

**R15**: `derive` automatically implements traits. Common: `Debug`, `Clone`, `PartialEq`. You cannot derive a trait if the struct contains a field that does not implement that trait.

**R16**: `Cow<'a, T>` (Clone-on-Write) allows a value to be either borrowed or owned. It avoids allocation by using the borrowed version until mutation is required, at which point it clones the data.

**R17**: `mod` declares a module, `use` brings paths into scope, and `pub` controls visibility. In 2018+, modules map directly to the file system (`mod a` looks for `a.rs` or `a/mod.rs`), and `extern crate` is largely obsolete.

**R18**: `Pin<T>` prevents a value from being moved in memory. This is critical for **self-referential structs** (where a field points to another field in the same struct), which are common in `async` state machines. `Unpin` is a trait for types that are safe to move.

**R19**: `macro_rules!` are declarative (pattern-based). Procedural macros (derive, attribute, function-like) are compiler plugins that manipulate the AST. Rust macros are **hygienic**, meaning they don't accidentally capture variables from the surrounding scope.

**R20**: Zero-cost abstractions mean you don't pay for what you don't use. **Monomorphization** generates specialized code for each generic type at compile time, allowing the compiler to inline and optimize as if the code were hand-written for that specific type.
