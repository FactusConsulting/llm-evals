## Go

**G1** — An **array** has a fixed size known at compile time; a **slice** is a descriptor (pointer, length, capacity) pointing to an underlying array. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array (usually doubling the size), copies the existing elements, and returns a new slice header.

**G2** — `var x int` declares a variable with its zero value (`0`); `x := 0` is short-variable declaration (declares and initializes). You **cannot** use `:=` at the package level (global scope); it is only available inside functions.

**G3** — A **goroutine** is a lightweight "green thread" managed by the Go runtime, not the OS. OS threads have large stacks (MBs); goroutines start small (KBs). The **GMP model** consists of **G** (Goroutine), **M** (Machine/OS thread), and **P** (Processor/Logical context). The scheduler assigns Gs to Ps, which run on Ms to achieve efficient M:N scheduling.

**G4** — **Channels** are typed conduits for communication. **Unbuffered** channels are synchronous; the sender blocks until a receiver is ready. **Buffered** channels have a capacity; the sender only blocks when the buffer is full. Sending to a full buffered channel blocks the goroutine until space becomes available.

**G5** — The `context` package manages deadlines, cancellation signals, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

**G6** — Go uses **implicit satisfaction** (structural typing); a type satisfies an interface by implementing its methods, without an explicit `implements` keyword. Java/C# use explicit interfaces. `any` (or `interface{}`) is a type that accepts any value. It is powerful for generic containers but dangerous because it bypasses compile-time type safety, requiring runtime type assertions that can panic.

**G7** — Go's memory model does not guarantee that a write in one goroutine is immediately visible to another without synchronization. The provided code is unsafe because it creates a **data race** on `ready` and `data`. The loop may run forever or read stale data. **Correct alternatives:** Use `sync.Mutex`, `sync.Atomic`, or a channel to signal completion.

**G8** — `sync.Mutex` is an exclusive lock. `sync.RWMutex` allows multiple concurrent readers OR one writer. Use `sync.Map` for cases with high contention where keys are stable and reads far outweigh writes, or when multiple goroutines read/write disjoint sets of keys. `sync.Map` avoids some lock contention but is slower for simple use cases due to internal interface casting.

**G9** — **Go modules** are the dependency management system. `go.mod` defines the module path and required versions; `go.sum` stores cryptographic checksums for reproducibility. `go mod tidy` adds missing modules and removes unused ones. **MVS (Minimum Version Selection)** selects the lowest version that satisfies all constraints in the dependency graph.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. **Gotcha:** Placing `defer` inside a loop can lead to resource exhaustion because the defers don't execute until the *function* returns, not the loop iteration.

**G11** — A **pointer** is a variable that stores the memory address of another value. The zero value is `nil`. To create a pointer to a struct literal: `ptr := &MyStruct{Field: "val"}`.

**G12** — `init()` functions run before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the files, with dependencies resolved first (imported packages' `init` functions run before the current package's).

**G13** — `new(T)` allocates zeroed memory for type `T` and returns a pointer `*T`. `make` is used only for **slices, maps, and channels**, initializing the internal data structure and returning the initialized type (not a pointer).

**G14** — Error handling is explicit via the `error` interface. The idiom is `if err != nil { return err }`. `errors.Is` checks if an error wraps a specific sentinel value; `errors.As` checks if an error is of a specific type and casts it. `==` only works for basic sentinel values and fails if the error is wrapped.

**G15** — **Map:** `nil`; **Slice:** `nil`; **Channel:** `nil`; **Struct:** all fields set to their respective zero values.

**G16** — A **race condition** occurs when two goroutines access the same memory concurrently and at least one is a write. The `-race` flag enables a runtime detector that finds these.
*Fix:* Use `sync.Mutex`: `mu.Lock(); count++; mu.Unlock()` or use a channel to pass ownership of the data.

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, it blocks until one of its cases can proceed. If multiple are ready, one is chosen **pseudo-randomly**. Timeout: `case <-time.After(1 * time.Second):`.

**G18** — **Escape analysis** determines if a variable can be allocated on the stack or must "escape" to the heap. If a variable is referenced outside the function scope (e.g., returned as a pointer), it goes to the heap. Inspect via `go build -gcflags="-m"`. Heap allocation increases GC pressure and reduces performance.

**G19** — `reflect.Type` represents the static type; `reflect.Value` represents the dynamic value. Reflection is slow because it bypasses compile-time optimizations and requires runtime type checking. It is justified for generic libraries (e.g., `json.Unmarshal`) where the type is unknown at compile time.

**G20** — `go:embed` allows embedding files/folders into the binary at compile time. It returns a `string`, `[]byte`, or `embed.FS` (for directories). It interacts with `io/fs.FS`, allowing the binary to treat embedded files as a virtual filesystem. Limitation: embedded files are read-only.

## Rust

**R1** — **Ownership** ensures memory safety without a GC. Rules: 1. Each value has a variable called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable string. `&str` is an immutable slice (a pointer and length) pointing to a string stored elsewhere (heap, binary, or stack). Use `&str` in function signatures for maximum flexibility (accepts both `String` and `&str`).

**R3** — The **borrow checker** enforces: you can have either **one mutable reference** (`&mut T`) OR **any number of immutable references** (`&T`) to a value at any given time. This prevents data races.

**R4** — `Result<T, E>` handles recoverable errors (`Ok`/`Err`); `Option<T>` handles optionality (`Some`/`None`). The `?` operator unwraps `Ok`/`Some` or returns the `Err`/`None` early.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path) // returns Result
}
```

**R5** — `Box<T>`: Single ownership, heap allocation. `Rc<T>`: Reference counted, single-threaded shared ownership. `Arc<T>`: Atomic reference counted, thread-safe shared ownership.

**R6** — **Traits** define shared behavior. Unlike Go's implicit interfaces, Rust traits must be explicitly implemented. `T: Trait` (Static Dispatch) uses monomorphization (fast, generates code for each type). `dyn Trait` (Dynamic Dispatch) uses a vtable (slower, allows heterogeneous collections).

**R7** — The compiler cannot determine which input reference the return value refers to. It needs a **lifetime annotation** to ensure the returned reference doesn't outlive the inputs.
*Fix:* `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { ... }`

**R8** — `Send` means a type can be transferred between threads; `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send` because its reference count is not atomic (non-thread-safe). `Arc<T>` uses atomic operations for the count, making it `Send` and `Sync`.

**R9** — `async` functions return a `Future`, which is a state machine. A **Future** does nothing until it is polled. The **executor** (e.g., Tokio) manages the polling loop. Go's goroutines are managed by a built-in runtime scheduler; Rust's async is library-based and "lazy."

**R10** — `unsafe` allows bypassing certain borrow checker rules. You can: 1. Dereference raw pointers. 2. Call unsafe functions. 3. Access/mutate static mutable variables. It is justified for FFI (C-interop) or implementing low-level data structures (like `Vec`).

**R11** — **Pattern matching** (`match`) is a powerful control flow that must be **exhaustive** (all possibilities covered). `if let` is syntactic sugar for matching only one specific pattern and ignoring the rest.

**R12** — `Vec<T>` is a growable heap-allocated array; `[T; N]` is a fixed-size stack-allocated array. When a `Vec` exceeds capacity, it reallocates a larger block of memory, copies elements, and updates the pointer.

**R13** — Rust enums are **Algebraic Data Types**; they can hold data within their variants. `Option<T>` is an enum (`Some(T)` or `None`), replacing `null` to force the developer to handle the "absent" case explicitly.

**R14** — `impl` blocks define methods. `&self` is an immutable borrow; `&mut self` is a mutable borrow; `self` takes ownership (consumes the object). **Associated functions** (like `String::new()`) do not take `self` and are called on the type itself.

**R15** — `derive` is a procedural macro that auto-implements traits. Examples: `Debug` (formatting), `Clone` (duplication), `PartialEq` (equality), `Serialize` (via Serde). You cannot derive a trait if the type contains a field that does not implement that trait.

**R16** — `Cow<'a, T>` (Clone-on-Write) allows a value to be either borrowed or owned. It avoids allocation by staying as a borrow until a mutation is required, at which point it clones the data into an owned version.

**R17** — `mod` declares a module; `use` brings paths into scope; `pub` makes items visible. Files map to modules (e.g., `src/network.rs` is `mod network`). In 2018, `extern crate` was largely replaced by the module system and `Cargo.toml`.

**R18** — `Pin<T>` ensures a value cannot be moved in memory. This is critical for **self-referential structs** (where a field points to another field in the same struct), which are common in `async` state machines. `Unpin` is a trait for types that are safe to move.

**R19** — `macro_rules!` are **declarative** (pattern matching on tokens). **Procedural macros** are functions that operate on the AST (derive, attribute, function-like). **Hygiene** ensures that macros don't accidentally capture variables from the surrounding scope.

**R20** — **Zero-cost abstractions** mean you don't pay for what you don't use. **Monomorphization** generates specialized code for each generic type, removing the need for runtime dispatch. Iterators are optimized by the compiler into loops as efficient as hand-written C.
