## JavaScript / TypeScript

**JS1**: `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and reside in the "Temporal Dead Zone" until declared. `const` prevents reassignment. **Hoisting** is the JS engine's behavior of moving declarations to the top of their scope during the compilation phase.

**JS2**: The **Event Loop** manages execution. The **Call Stack** handles synchronous code. When async tasks finish, they enter queues: **Microtask Queue** (Promises, `queueMicrotask`) has priority over the **Macrotask Queue** (setTimeout, setInterval, I/O). The loop pushes microtasks to the stack immediately after the current execution finishes, before moving to the next macrotask.

**JS3**: A **closure** is a function that remembers the environment in which it was created, even after the outer function has returned. *Example*: A function returning a counter. *Bug*: Using `var` in a `for` loop creates one shared variable for all closures. *Fix*: Use `let` in the loop header to create a new binding for every iteration.

**JS4**: `Promise` represents a future value. `async/await` is syntactic sugar for Promises. Errors in `async` functions are caught via `try/catch`. `Promise.all` rejects immediately if any promise fails; `Promise.allSettled` waits for all to complete regardless of outcome.

**JS5**: `interface` is primarily for defining object shapes and supports declaration merging (extending). `type` is more flexible (unions, primitives, tuples). Use `interface` for public APIs/classes; `type` for complex logic. **Discriminated Unions** use a common literal property (e.g., `type: 'circle' | 'square'`) to allow TS to narrow types in `switch/if` blocks.

**JS6**: JS uses **prototypal inheritance**: objects inherit from other objects via a prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is "syntactic sugar" over prototypes; `extends` sets the prototype chain, and `super()` calls the parent constructor.

**JS7**: `this` refers to the execution context. **Binding Priority**: 1. `new` (new object), 2. Explicit (`call`/`apply`/`bind`), 3. Implicit (object method), 4. Default (`window`/`undefined` in strict mode). `bind()` returns a new function with a fixed `this`; it cannot be re-bound.

**JS8**: `WeakRef` allows holding a reference to an object without preventing GC. `FinalizationRegistry` triggers a callback after an object is GC'd. `WeakMap` keys must be objects because the map holds a "weak" reference to the key; if the key is only held by the WeakMap, it can be garbage collected.

**JS9**: V8 uses **Hidden Classes** (Shapes) to track object layouts. **Inline Caching (IC)** remembers where properties are located in memory to skip lookups. **Deoptimization** occurs when an object's "shape" changes (e.g., adding properties in a different order), forcing V8 to drop to slower, generic access.

**JS10**: **Tree-shaking** is the removal of unused code. ES Modules (ESM) use static `import`/`export`, allowing the bundler to determine what is unused at build time. CommonJS (`require`) is dynamic, meaning the bundler cannot safely determine what is used without executing the code, making tree-shaking ineffective.

**JS11**: `null` is an intentional absence of value; `undefined` means a variable was declared but not assigned. `==` performs type coercion; `===` checks value and type. `??` (nullish coalescing) returns the right side only if the left is `null` or `undefined`. `?.` (optional chaining) returns `undefined` if a property in the chain is nullish.

**JS12**: `map` transforms each element; `filter` returns elements meeting a condition; `reduce` aggregates an array into a single value. `reduce` with an initial value uses that value as the first `accumulator`. `flatMap` maps then flattens the result by one level, useful for removing empty results or expanding one element into many.

**JS13**: Template literals (backticks) allow interpolation `${}` and multiline strings. **Tagged templates** pass the template strings and values to a function. *Example*: `sql`tagged templates can escape inputs to prevent SQL injection by processing the strings and values separately.

**JS14**: **Destructuring** unpacks values from arrays/objects. `const {a, b = 1} = obj` (object), `const [x, y] = arr` (array). Renaming: `const {a: newName} = obj`. The **rest operator** `...` collects remaining elements into a new array/object.

**JS15**: `for...in` iterates over enumerable **keys** (including inherited ones). `for...of` iterates over **values** of iterables. Avoid `for...in` on arrays because it iterates over indices as strings and may include non-numeric properties added to the array prototype.

**JS16**: **Generics** allow reusable components. `extends` (Constraint): `T extends string` ensures T is a string. **Conditional Types**: `T extends U ? X : Y` returns X if T is a subtype of U. `infer` extracts types from patterns: `type GetReturn<T> = T extends (...args: any[]) => infer R ? R : never`.

**JS17**: **CommonJS** (`require`/`module.exports`) is synchronous and used in legacy Node. **ESM** (`import`/`export`) is static and standard. Node handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM.

**JS18**: TS is **structural**: if two types have the same shape, they are compatible. **Excess property checks** occur only on object literals passed directly to a typed variable. `extends` is for subtyping; `satisfies` validates a value against a type without changing the inferred type of the variable. **Variance**: Covariance (out) allows wider types; Contravariance (in) allows narrower types.

**JS19**: `Proxy` intercepts object operations (get, set, etc.). `Reflect` provides a mirror API to perform the original operation. *Example*: A Proxy can validate that a property value is a number before allowing a `set` operation, providing built-in validation.

**JS20**: `SharedArrayBuffer` provides memory shared between the main thread and Web Workers. `Atomics` provides atomic operations (add, load, store) to prevent race conditions. `Atomics.wait` puts a thread to sleep until a value changes, and `Atomics.notify` wakes it up.

## Bash

**B1**: `$*` is all arguments as one string; `$@` is all arguments as separate strings. `"$*"` (quoted) is one string; `"$@"` (quoted) preserves the original argument boundaries (essential for files with spaces).

**B2**: `set -e`: Exit immediately if a command fails. `-u`: Treat unset variables as errors. `-o pipefail`: A pipeline returns the exit code of the last command to fail, not just the last command in the pipe.

**B3**: `$(command)` is the modern, nestable way to capture output; `` `command` `` is the legacy version. `$((expression))` is for shell arithmetic; `expr` is an external binary that is slower and requires more quoting.

**B4**: **Process substitution** `<(command)` makes the output of a command appear as a file. *Example*: `diff <(ls dir1) <(ls dir2)` compares the directory listings without creating temporary files.

**B5**: Use quotes `"$f"` and avoid `for f in $(ls)`. The latter fails because `ls` output is split by whitespace. Use `while IFS= read -r f` or a glob `for f in *.txt`.

**B6**: `<<EOF` is a **here-doc** (multiline input); `<<<` is a **here-string** (single string input). `<<-EOF` strips leading tab characters from the input, allowing the code to be indented for readability.

**B7**: `> file 2>&1` sends stdout to file, then redirects stderr to where stdout is (the file). `2>&1 > file` redirects stderr to the current stdout (screen), then redirects stdout to the file. `&> file` is a Bash shorthand for both.

**B8**: Use `mkdir lockdir` because it is an atomic operation at the OS level (unlike `touch`). Use `trap 'rmdir lockdir' EXIT SIGTERM SIGINT` to ensure cleanup.

**B9**: `'...'` (Single): Literal string. `"..."` (Double): Interpolates variables. No quotes: Subject to word splitting and globbing. *Example*: `echo $VAR` (splits if $VAR has spaces), `echo "$VAR"` (preserves spaces).

**B10**: `-f` (file), `-d` (directory), `-r` (readable). `[ ]` is the POSIX standard `test`. `[[ ]]` is a Bash extension that supports regex (`=~`), doesn't require quoting variables, and is generally safer.

**B11**: `$?` (exit status of last command), `$$` (PID of current script), `$!` (PID of last background process), `$#` (number of arguments).

**B12**: `foo() { ... }` is the standard POSIX way. `function foo { ... }` is a Bash-ism. Functions return values via `echo` (captured by command substitution) or via `return N` (exit status 0-255).

**B13**: `PATH` is a colon-separated list of directories searched for binaries. Bash checks: Aliases $\rightarrow$ Functions $\rightarrow$ Builtins $\rightarrow$ PATH. Use `type -a <cmd>` to see all versions of a command.

**B14**: `trap 'cmd' SIGNAL` executes `cmd` when the signal arrives. Order: depends on the signal's arrival time. Common signals: `EXIT` (script end), `INT` (Ctrl+C), `TERM` (kill).

**B15**: `xargs` reads from stdin; command substitution `$(...)` puts output into a string. Use `find . -print0 | xargs -0` to handle spaces/newlines. `xargs -P N` runs N processes in parallel.

**B16**: Arrays: `arr=(a b c)`, append `arr+=("d")`, length `${#arr[@]}`, iterate `for i in "${arr[@]}"`. Associative arrays: `declare -A assoc`, `assoc[key]=val`.

**B17**: `(...)` is a subshell (forks a process; variables changed inside are lost). `{ ...; }` is a group (runs in current shell). Piping into a `while` loop creates a subshell, so variables modified inside the loop are lost.

**B18**: `SIGINT` (Interrupt), `SIGTERM` (Terminate - polite), `SIGHUP` (Hangup), `SIGKILL` (Forced - cannot be trapped). Handle graceful shutdown by trapping `SIGTERM` and killing background children.

**B19**: Use `split -l` to chunk the log, `xargs -P` to run the processing function on chunks, and `cat` to merge. Trade-off: Parallelism increases speed but consumes RAM/CPU; error propagation requires checking exit codes of the `xargs` process.

**B20**: `exec` replaces the current shell process with the new command. `exec 3>file` opens file descriptor 3 for writing. A **coprocess** `coproc` creates a two-way pipe for bidirectional communication between the script and a background process.

## PowerShell

**PS1**: `Write-Output` sends objects to the pipeline (can be captured/filtered). `Write-Host` writes directly to the console (bypasses the pipeline).

**PS2**: The pipeline passes objects. `ForEach-Object` is a cmdlet that processes objects one-by-one as they arrive. The `foreach` statement is a language keyword that requires the entire collection to be in memory first.

**PS3**: `[PSCustomObject]` is a structured object with properties (ordered). `[hashtable]` is a key-value pair (unordered). Convert: `[PSCustomObject]$obj = [PSCustomObject]$hashtable`.

**PS4**: **Terminating errors** stop execution; **non-terminating** errors just print a warning. `-ErrorAction Stop` converts a non-terminating error into a terminating one, allowing it to be caught by `try/catch`.

**PS5**: **Splatting** passes a hashtable as named parameters using `@params` instead of `$params`. *Example*: `$p = @{Path='C:\'; Recurse=$true}; Get-ChildItem @p`.

**PS6**: `Invoke-Command` runs a script block on remote machines (one-off). `Enter-PSSession` starts an interactive session. It uses WinRM (WS-Man) or SSH.

**PS7**: The function returns an array. If it returns 0 items, it returns `$null`. If it returns 1 item, it returns the object itself (unwrapping). Correct pattern: Use `Write-Output` or explicitly cast the return as `[PSCustomObject[]]`.

**PS8**: A `[scriptblock]` is a block of code `{...}` that can be passed as an object. The **double-hop problem** occurs when credentials are lost when jumping from Server A $\rightarrow$ B $\rightarrow$ C. Solve with CredSSP or by passing credentials via `-ArgumentList`.

**PS9**: `@()` is the array literal; `[array]` is the type. Indexing into `$null` returns `$null` (no error). Indexing into an empty array returns `$null`.

**PS10**: `-eq` (equal), `-like` (wildcard `*`), `-match` (regex). `-ceq` is case-sensitive. `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection (inverse of `-contains`).

**PS11**: A module is a package of functions/variables. `.psm1` contains code; `.psd1` is a manifest (versioning/dependencies). `Import-Module` loads the module into the current session.

**PS12**: `"..."` interpolates; `'...'` is literal. Use `"$($expression)"` for complex expressions. A **here-string** `@" ... "@` allows multiline strings without escaping.

**PS13**: `Get-Member` shows the object's type, properties, and methods. `Select-Object` filters properties (columns); `Where-Object` filters objects (rows).

**PS14**: PS Classes (v5+) provide structured data and methods. They are simpler than C# classes (no interfaces). Use a class for complex state/data models; use a function for logic/tasks.

**PS15**: `[CmdletBinding()]` makes a function an "Advanced Function." It enables `-WhatIf`, `-Confirm`, and `Begin/Process/End` blocks for pipeline streaming.

**PS16**: Providers map different data stores to a drive-like interface. `Get-ChildItem` works on `C:\` (FileSystem), `HKLM:\` (Registry), and `Env:\` (Environment variables).

**PS17**: A **runspace** is an isolated execution environment (thread). `ForEach-Object -Parallel` (v7) simplifies this. Manual runspaces provide finer control over threading and state.

**PS18**: `PSScriptAnalyzer` is a static analysis tool. It uses rules (e.g., "Avoid using `Write-Host`). Rules have severity (Warning, Error). Integrate in CI/CD to fail builds on coding standard violations.

**PS19**: `$using:var` is used to pass local variables into remote sessions or parallel blocks. Complex objects are serialized via CLIXML; if the object is too deep or contains non-serializable types, data is lost.

**PS20**: **DSC** is declarative configuration. The **LCM** (Local Configuration Manager) ensures the system stays in the desired state. In modern infra, DSC is often replaced by Terraform, Ansible, or Azure Automanage.
