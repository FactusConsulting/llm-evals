## Kubernetes

**K1 — Easy:** A **Deployment** manages stateless pods; replicas are interchangeable, and any pod can handle a request. A **StatefulSet** manages stateful pods; pods have a stable, ordinal index (e.g., `pod-0`, `pod-1`), stable network identities, and dedicated persistent storage that persists across pod rescheduling.

**K2 — Easy:** A **ClusterIP** is a virtual IP assigned to a Service. `kube-proxy` (via iptables or IPVS) intercepts traffic sent to this IP and load-balances it across the backend pods' actual IP addresses based on the Service's selector.

**K3 — Medium:** 
- **PersistentVolume (PV):** A piece of storage in the cluster (the actual "disk").
- **PersistentVolumeClaim (PVC):** A user's request for storage (the "ticket").
- **StorageClass (SC):** A blueprint for dynamically provisioning PVs.
**Relation:** A user creates a PVC $\rightarrow$ the PVC matches a StorageClass $\rightarrow$ the SC automatically provisions a PV $\rightarrow$ the PVC binds to that PV.

**K4 — Medium:** 
1. `kubectl logs <pod>`: Check application-level crashes or stack traces.
2. `kubectl describe pod <pod>`: Check for `OOMKilled` (memory limit) or failed Liveness/Readiness probes.
3. Check ConfigMaps/Secrets: Ensure all required environment variables or mounted files are present.
4. Check Events: Look for scheduling issues or image pull errors in the event log.

**K5 — Medium:** **CoreDNS** provides service discovery. It allows pods to resolve service names (e.g., `my-svc.namespace.svc.cluster.local`) to IPs. If CoreDNS is down, pods cannot resolve internal service names, effectively breaking all internal communication between microservices.

**K6 — Hard:** The scheduler uses a two-step process:
1. **Filtering (Predicates):** Removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, NodeSelector mismatch, Taints).
2. **Scoring (Priorities):** Ranks remaining nodes.
**Factors:** Resource availability (least requested), Image locality (node already has the image), and Affinity/Anti-affinity rules.

**K7 — Hard:** **Yes, it will be scheduled.** Total requested on node = $3.5\text{GB} + 256\text{Mi} \approx 3.75\text{GB}$, which is less than 4GB. However, if the pod uses 600Mi at runtime, it exceeds its **limit** (512Mi) and will be **OOMKilled** by the kubelet.

**K8 — Hard:** 
External LB $\rightarrow$ Ingress Controller (NGINX) $\rightarrow$ Ingress Rule (Host/Path) $\rightarrow$ Service $\rightarrow$ Endpoints (Pod IPs) $\rightarrow$ Pod. 
`kube-proxy` manages the iptables/IPVS rules that ensure traffic hitting the Service IP is routed to a healthy Pod IP listed in the Endpoints object.

**K9 — Medium:** A **NetworkPolicy** is an L3/L4 firewall for pods. By default (no policy), all pods can talk to all pods. Once a NetworkPolicy is applied to a pod, that pod enters "default-deny" mode for any traffic not explicitly allowed by the policy.

**K10 — Medium:** **RollingUpdate** replaces pods gradually to ensure zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when the application cannot handle two different versions of the code running simultaneously (e.g., a breaking database schema migration).

**K11 — Easy:** A **namespace** is a logical partition of a cluster. Default namespaces: `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

**K12 — Easy:** It provides detailed metadata. It shows: **Events** (why a pod failed), **Container Status** (restarts, exit codes), and **Resource Limits/Requests** (which `get pod` does not show).

**K13 — Easy:** A **ConfigMap** stores non-confidential configuration. Consumption methods:
1. As **environment variables** injected into the container.
2. As **files** mounted as a volume.

**K14 — Easy:** 
- **ClusterIP:** Internal only; accessible only within the cluster.
- **NodePort:** Exposes the service on a static port on every Node's IP.
- **LoadBalancer:** Provisions a cloud provider LB that routes to the NodePort/ClusterIP.

**K15 — Easy:** A **DaemonSet** ensures one copy of a pod runs on every node (or a subset of nodes). Use it for infrastructure services like log collectors (Fluentd), monitoring agents (Prometheus Node Exporter), or CNI plugins.

**K16 — Medium:** 
- **Taints/Tolerations:** Taints are applied to *nodes* to repel pods. Tolerations are applied to *pods* to allow them to stay on tainted nodes. (Use case: Dedicating GPU nodes to specific workloads).
- **Node Affinity:** Applied to *pods* to attract them to specific nodes. (Use case: Ensuring a pod runs on a node with an SSD).

**K17 — Medium:** An **Operator** is a custom controller using a Custom Resource Definition (CRD). While a standard controller manages built-in objects, an Operator encodes domain-specific operational knowledge (e.g., how to backup a Postgres DB). It solves the problem of automating complex, stateful application lifecycles.

**K18 — Hard:** etcd uses the **Raft** consensus algorithm. If quorum (majority) is lost, the cluster becomes read-only or unavailable. If 2/3 nodes are lost, quorum is lost. Recovery requires restoring from a snapshot to a new cluster or forcing a new cluster configuration with the remaining node.

**K19 — Hard:** 
- **Role:** Permissions within a namespace. **ClusterRole:** Cluster-wide permissions.
- **RoleBinding:** Links a User/Group to a Role. **ClusterRoleBinding:** Links to a ClusterRole.
**Manifests:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { name: pod-reader, namespace: my-ns }
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { name: dev-binding, namespace: my-ns }
subjects: [{ kind: User, name: "developer" }]
roleRef: { kind: Role, name: pod-reader, apiGroup: rbac.authorization.k8s.io }
```

**K20 — Hard:** `ndots:5` causes the resolver to append internal search domains (e.g., `.svc.cluster.local`) to every query. An external query like `google.com` results in 4 failed internal lookups before trying the absolute name. 
**Fix:** Set `dnsConfig: { ndots: 1 }` in the pod spec or use a fully qualified domain name (ending with a dot: `google.com.`).

## Development

**D1 — Easy:** **Merge** combines histories and creates a merge commit. **Rebase** rewrites history by moving the base of a branch to a new commit. Avoid rebasing public/shared branches as it rewrites commit IDs and breaks other developers' histories.

**D2 — Easy:** **TCP** is connection-oriented, reliable, and ordered (HTTP, SSH). **UDP** is connectionless, faster, and allows packet loss (DNS, VoIP).

**D3 — Medium:** A **race condition** occurs when the outcome depends on the non-deterministic timing of multiple threads accessing shared data. 
*Example:* Two threads incrementing a shared variable `count++`. Both read `10`, both increment to `11`, and write back `11` instead of the expected `12`.

**D4 — Medium:** **Symmetric:** Same key for encryption/decryption (AES). **Asymmetric:** Public key encrypts, private key decrypts (RSA). 
**TLS:** Uses asymmetric encryption to securely exchange a symmetric session key, which is then used for the actual data transfer for performance.

**D5 — Medium:** A **layer** is a read-only snapshot of the filesystem at a specific Dockerfile instruction. Caching: Docker re-uses layers if the instruction and files haven't changed. **Best practice:** Put stable instructions (OS, dependencies) at the top and frequently changing code at the bottom to maximize cache hits.

**D6 — Medium:** 
1. **Logs:** Check application logs for unhandled exceptions.
2. **Health Checks:** Check if the service is failing Liveness/Readiness probes.
3. **Resources:** Check for CPU/Memory spikes (throttling).
4. **Upstream:** Check if a downstream dependency (DB, API) is timing out.

**D7 — Hard:** **CAP Theorem:** A distributed system can only provide two of three: Consistency, Availability, and Partition Tolerance. 
- **CP (Consistency/Partition):** MongoDB (defaults to strict consistency; if a partition occurs, some nodes become unavailable).
- **AP (Availability/Partition):** Cassandra (allows reads/writes during partition; data eventually converges).

**D8 — Medium:** **Horizontal:** Adding more machines (scaling out). **Vertical:** Adding more CPU/RAM to one machine (scaling up). 
**Patterns:** Statelessness (no session affinity), Load Balancing, and Database Sharding enable horizontal scaling.

**D9 — Easy:** An **environment variable** is a dynamic value stored by the OS. To persist on Linux, add `export VAR_NAME=value` to the shell configuration file (e.g., `~/.bashrc` or `~/.zshrc`).

**D10 — Easy:** **JSON** is a strict, lightweight data format (fast parsing). **YAML** is a superset of JSON, more human-readable and supports comments. 
- JSON advantage: Ubiquitous and strict. 
- YAML advantage: Easier for humans to write/edit config files.

**D11 — Easy:** **REST** is an architectural style for APIs using HTTP.
- **GET:** Retrieve data.
- **POST:** Create new resource.
- **PUT:** Update/Replace resource.
- **DELETE:** Remove resource.

**D12 — Easy:** **Version pinning** is specifying an exact version of a dependency (e.g., `1.4.2` instead of `^1.4.0`). It ensures that every build uses the exact same code, preventing "it works on my machine" bugs caused by silent dependency updates.

**D13 — Easy:** **Compiled:** Translated to machine code before execution (C++, Rust). **Interpreted:** Read and executed line-by-line by a runtime (Python, JavaScript).

**D14 — Medium:** A **Forward Proxy** acts on behalf of the client (hides client IP). A **Reverse Proxy** acts on behalf of the server (hides server IP). 
- **NGINX:** Load balancing/SSL termination.
- **HAProxy:** High-performance TCP/HTTP load balancing.

**D15 — Medium:** A **deadlock** is a state where two or more threads are blocked forever, each waiting for the other to release a resource. 
**Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16 — Hard:** **Eventual Consistency** means that if no new updates are made, all accesses to that item will eventually return the last updated value. 
**Cassandra:** Uses tunable consistency. `QUORUM` (majority of nodes must agree) provides a balance. Read-after-write consistency is achieved if $R + W > N$ (Read + Write nodes > Total replicas).

**D17 — Hard:** **mTLS** requires both client and server to present certificates. 
**Handshake:** Server sends cert $\rightarrow$ Client verifies server $\rightarrow$ Client sends its own cert $\rightarrow$ Server verifies client $\rightarrow$ Symmetric key established. 
**Usage:** Commonly used in Service Meshes (Istio/Linkerd) for zero-trust internal communication.

**D18 — Hard:** A **hash table** uses a hash function to map keys to array indices. 
- **Collision Resolution:** **Chaining** (linked lists at each index) or **Open Addressing** (searching for the next empty slot).
- **Complexity:** Average: $O(1)$ for all. Worst: $O(n)$ if all keys hash to the same index.

**D19 — Hard:** A **Circuit Breaker** prevents a failing service from crashing the whole system.
- **Closed:** Requests flow normally.
- **Open:** Requests fail immediately (fast-fail) without hitting the service.
- **Half-Open:** Allows a few probe requests to see if the service has recovered.
**Relation:** It complements retries; while retries attempt to fix transient errors, the circuit breaker stops retries from overwhelming a dead service.

**D20 — Hard:** 
- **Optimistic:** Assume no conflict; check for changes at commit time (e.g., using a `version` column). If the version changed, the transaction fails. (Use for low-contention).
- **Pessimistic:** Lock the resource immediately (e.g., `SELECT FOR UPDATE`). (Use for high-contention where conflicts are frequent).
