## .NET / C#

**DN1 — Easy:** A `class` is a reference type (allocated on the heap), while a `struct` is a value type (usually allocated on the stack). Use a `struct` for small, immutable data structures (typically < 16 bytes) that have a short lifetime to reduce GC pressure.

**DN2 — Easy:** `IEnumerable<T` is a read-only forward-only iterator for in-memory collections. `IQueryable<T>` is designed for remote data sources (like SQL); it stores an expression tree that allows the provider (EF Core) to translate the query into SQL and execute it on the database server. The distinction matters because `IEnumerable` would pull all data into memory before filtering, whereas `IQueryable` filters at the source.

**DN3 — Medium:** `async/await` allows non-blocking asynchronous programming by transforming a method into a state machine. `Task` represents an ongoing operation and is a class (heap allocation). `ValueTask` is a struct; use it when a method often returns synchronously (e.g., from a cache), as it avoids heap allocation in those cases.

**DN4 — Medium:** DI is a pattern where dependencies are provided to a class rather than the class creating them. 
- **Transient:** New instance every time requested.
- **Scoped:** One instance per client request (e.g., HTTP request).
- **Singleton:** One instance for the app lifetime.
**Common Bug:** "Captive Dependency"—injecting a Scoped service into a Singleton. The Scoped service is held alive for the app's lifetime, potentially causing memory leaks or stale data (e.g., a `DbContext` that never closes).

**DN5 — Medium:** `string` is an immutable heap object. `ReadOnlySpan<char>` is a ref-struct that provides a window into a contiguous region of memory without copying. Use `Span<T>` for high-performance slicing and parsing to eliminate unnecessary allocations and reduce GC overhead.

**DN6 — Medium:** The GC uses generations to optimize collection: Gen 0 (short-lived), Gen 1 (buffer), Gen 2 (long-lived). The Large Object Heap (LOH) handles objects > 85KB to avoid expensive memory compaction. `IDisposable` is needed for *unmanaged* resources (file handles, sockets) because the GC only manages memory, not external OS handles.

**DN7 — Hard:** `ConfigureAwait(false)` tells the runtime that the continuation does not need to resume on the original `SynchronizationContext` (e.g., the UI thread). Use it in library code to avoid deadlocks and improve performance. Do NOT use it in application-level code where you need to update UI elements.

**DN8 — Hard:** 
- **Primary Constructors:** Define parameters directly in the class declaration.
- **Collection Expressions:** `int[] arr = [1, 2, 3];`
- **FrozenDictionary:** An immutable dictionary optimized for read-heavy scenarios.
**Example:**
```csharp
public class UserService(IUserRepository repo) // Primary Constructor
{
    public void GetUser(int id) => repo.Find(id);
}
```

**DN9 — Hard:** `DbContext` is not thread-safe. The `ObjectDisposedException` occurs because a Scoped `DbContext` is being accessed by multiple concurrent threads (e.g., `Task.WhenAll` calling a service that uses the same scoped context). **Fix:** Use `IDbContextFactory<T>` to create a fresh context per operation or ensure sequential access.

**DN10 — Medium:** A `record` is a class with built-in value-based equality. A `record struct` is a value-type version of this. Use `record` for DTOs/immutable data; use `class` for behavior-heavy objects; use `record struct` for small, immutable value-objects.

**DN11 — Easy:** 
- `ref`: Pass by reference; variable must be initialized before passing.
- `out`: Pass by reference; method *must* assign a value before returning.
- `in`: Pass by reference; read-only (cannot be modified).

**DN12 — Easy:** Nullable reference types (`string?`) are a compiler-level feature to prevent `NullReferenceException` by forcing the developer to handle nulls. Nullable value types (`int?`) are actual types (`Nullable<T>`) that wrap a value type to allow nulls.

**DN13 — Easy:** LINQ (Language Integrated Query) provides a consistent way to query data. Method syntax uses extension methods (`.Where()`), while query syntax looks like SQL. **Deferred execution** means the query is not executed until the sequence is iterated (e.g., via `foreach` or `.ToList()`).

**DN14 — Easy:** Constraints restrict the types `T` can be:
- `where T : class`: Must be a reference type.
- `where T : struct`: Must be a value type.
- `where T : new()`: Must have a parameterless constructor.
- `where T : IComparable<T>`: Must implement the interface.
Combine them (e.g., `where T : class, new()`) to ensure the type is both a reference type and instantiable.

**DN15 — Easy:** An abstract class defines a "is-a" relationship and can hold state; an interface defines a "can-do" contract. Default interface methods (C# 8+) allow interfaces to provide a default implementation, reducing the need for abstract base classes for shared logic.

**DN16 — Medium:** Middleware is a chain of delegates. `Use()` adds logic and can call `next()`; `Map()` branches the pipeline based on a path; `Run()` is a terminal middleware. Order is critical; exception handling middleware must be placed first to catch errors from all subsequent middleware.

**DN17 — Medium:** `Channel<T>` is a high-performance async producer-consumer queue. `BlockingCollection<T>` is synchronous and blocks threads. Bounded channels provide backpressure by limiting the number of items in the queue, forcing the producer to await when the channel is full.

**DN18 — Hard:** Source Generators execute during compilation to generate C# code. Unlike reflection (runtime) or IL weaving (post-compile), they are type-safe and fast. **Incremental generators** cache results of previous runs, significantly improving IDE performance by only regenerating code when relevant inputs change.

**DN19 — Hard:** TPL Dataflow provides blocks for data pipelines. `ActionBlock` (consumes), `TransformBlock` (maps), `BufferBlock` (buffers). Compared to `Channels`, TPL Dataflow is higher-level, offering built-in orchestration and complex graph topologies.

**DN20 — Hard:** Minimal APIs use a lightweight routing model without controllers. Trade-offs: faster startup and less boilerplate, but can become disorganized in large apps. Route groups organize endpoints; endpoint filters provide cross-cutting concerns (like validation) similar to Action Filters in MVC.

## Python

**P1 — Easy:** `list` is mutable and ordered; `tuple` is immutable and ordered. `set` is a mutable collection of unique elements; `frozenset` is the immutable version of a set.

**P2 — Easy:** The GIL is a mutex that allows only one thread to execute Python bytecode at a time. It affects CPU-bound workloads. Workarounds include using the `multiprocessing` module (separate processes) or using C-extensions (like NumPy) that release the GIL.

**P3 — Medium:** `copy` (shallow) creates a new object but references the same nested objects. `deepcopy` recursively copies everything. 
**Example:** If you shallow copy a list of lists `[[1], [2]]`, modifying a nested list in the copy will modify the original.

**P4 — Medium:** A decorator is a function that wraps another function to modify its behavior.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        res = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start}s")
        return res
    return wrapper
```

**P5 — Medium:** Generators use `yield` to produce values one at a time (lazy evaluation), saving memory compared to lists. `yield from` allows a generator to delegate to another iterable or generator.

**P6 — Medium:** `asyncio` uses a single-threaded event loop. `run()` starts the loop; `gather()` runs multiple coroutines concurrently; `create_task()` schedules a coroutine for execution. `time.sleep()` blocks the entire thread, stopping the event loop; `await asyncio.sleep()` yields control back to the loop.

**P7 — Hard:** Python uses the C3 Linearization algorithm for MRO. In the diamond example, the order is `D -> B -> C -> A`. `D().who()` prints **"C"** because `C` is the first class in the MRO that implements `who()` before reaching the base class `A`.

**P8 — Hard:** A metaclass is a "class of a class" that defines how classes are created. Use `__init_subclass__` for simple registration or validation of subclasses. Use a metaclass for complex logic like modifying class attributes at creation time or enforcing strict API constraints across a hierarchy.

**P9 — Hard:** 
- `threading`: I/O bound, shared memory, limited by GIL.
- `multiprocessing`: CPU bound, separate memory, bypasses GIL.
- `concurrent.futures`: High-level wrapper for both.
**Serialization:** `multiprocessing` requires objects to be "picklable" to be sent between processes.

**P10 — Medium:** `__slots__` tells Python not to use a dynamic `__dict__` for instances. It prevents the creation of new attributes at runtime and significantly reduces memory usage per object.

**P11 — Easy:** A virtual environment isolates dependencies for a project. `venv` is the standard library tool; `virtualenv` is a more powerful predecessor; `conda` manages both Python and non-Python binary dependencies.

**P12 — Easy:** Comprehensions provide a concise way to create collections. They are generally faster and more readable than `map()` and `filter()`. Use comprehensions for clarity; use `map`/`filter` when working with existing lazy iterators.

**P13 — Easy:** `==` checks for value equality; `is` checks for identity (memory address). Small integers (typically -5 to 256) are "interned" by Python, meaning they point to the same memory address, so `a is b` returns `True` for them.

**P14 — Easy:** `*args` collects positional arguments into a tuple; `**kwargs` collects keyword arguments into a dictionary. `/` marks arguments before it as positional-only; `*` marks arguments after it as keyword-only.

**P15 — Easy:** Context managers manage resources. Using `__enter__`/`__exit__` is the class-based approach; `@contextmanager` is the generator-based approach. Example: A database transaction manager that commits on success and rolls back on exception.

**P16 — Medium:** Type hinting provides static analysis. `Union` (A or B), `Optional` (A or None), `Literal` (specific values), `TypeVar` (generics), `Protocol` (structural typing/interfaces). `mypy` and `pyright` use these to find bugs without running the code.

**P17 — Medium:** 
- `__repr__` (developer-facing, unambiguous) vs `__str__` (user-facing, readable).
- `__eq__` (equality) vs `__hash__` (for dict keys/sets).
- `__getattr__` (called if attribute not found) vs `__getattribute__` (called every time).
If you define `__eq__` but not `__hash__`, the object becomes unhashable and cannot be used as a dictionary key.

**P18 — Hard:** Descriptors are objects that define `__get__`, `__set__`, and `__delete__`. They intercept attribute access. `property`, `classmethod`, and `staticmethod` are all implemented as descriptors.

**P19 — Hard:** Python searches `sys.path` for modules. Absolute imports are preferred for clarity. `__init__.py` makes a directory a package. Namespace packages (PEP 420) allow splitting a package across multiple directories without `__init__.py`. Finders locate modules; loaders load the code.

**P20 — Hard:** `dataclasses` reduce boilerplate for data-holding classes. `attrs` is more feature-rich; `Pydantic` adds runtime type validation. `__post_init__` allows logic after initialization. Use Pydantic when you need strict runtime validation (e.g., parsing JSON API requests).
