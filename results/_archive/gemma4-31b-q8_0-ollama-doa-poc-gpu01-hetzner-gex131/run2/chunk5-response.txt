## .NET / C#

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
A `class` is a reference type stored on the heap; it supports inheritance and is passed by reference. A `struct` is a value type stored typically on the stack (or inline within a class); it does not support inheritance (except from interfaces) and is passed by value. Use a `struct` for small, immutable data structures (e.g., coordinates, complex numbers) to reduce GC pressure and improve memory locality.

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
`IEnumerable<T>` is for in-memory collections; filtering happens on the client side (the entire dataset is loaded into memory first). `IQueryable<T>` is for remote data sources (like EF Core); it stores an expression tree that is translated into a provider-specific query (e.g., SQL). This distinction is critical for performance: `IQueryable` ensures filtering happens at the database level, minimizing data transfer.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
`async/await` transforms a method into a state machine, allowing the thread to be released to the pool while waiting for an I/O operation to complete. A `Task` is a class (heap-allocated) representing an ongoing operation. A `ValueTask` is a struct that can wrap either a `Task` or a synchronously produced result. Use `ValueTask` in high-frequency methods where the result is often already available (e.g., reading from a cached buffer) to avoid unnecessary heap allocations.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
DI is a pattern where dependencies are provided to a class rather than created internally.
- **Transient:** Created every time they are requested.
- **Scoped:** Created once per client request (connection).
- **Singleton:** Created once for the lifetime of the application.
**Common Bug:** "Captive Dependency." If a Singleton depends on a Scoped service, the Scoped service is effectively promoted to a Singleton, which can lead to memory leaks or stale data (e.g., a `DbContext` staying open forever).

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
A `string` is a heap-allocated, immutable object. `ReadOnlySpan<char>` is a ref-struct that provides a view into a contiguous region of memory (stack, heap, or unmanaged) without allocating new memory. Use `Span<T>` or `ReadOnlySpan<T>` for high-performance parsing or slicing (e.g., `Slice()` instead of `Substring()`) to eliminate temporary string allocations and reduce GC overhead.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
The GC uses a mark-and-sweep algorithm.
- **Gen 0:** Short-lived objects (most frequent collections).
- **Gen 1:** Buffer zone for objects surviving Gen 0.
- **Gen 2:** Long-lived objects.
**LOH (Large Object Heap):** Objects > 85,000 bytes go here; they are not compacted by default to avoid expensive memory moves.
**IDisposable:** GC only manages memory. `IDisposable` is used to manually release unmanaged resources (file handles, database connections, sockets) immediately rather than waiting for the GC.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
By default, `await` captures the current `SynchronizationContext` (e.g., UI thread or ASP.NET request context) to resume execution on that same context. `ConfigureAwait(false)` tells the runtime it doesn't need to resume on the captured context.
- **Use it:** In library code to avoid deadlocks and improve performance.
- **Do NOT use it:** In UI code where you must update UI elements on the main thread.

**DN8 — Hard: Explain the new .NET 8/9 features: primary constructors, collection expressions, and FrozenDictionary. Write a minimal example using primary constructors with DI.**
- **Primary Constructors:** Allow parameters to be defined directly in the class declaration.
- **Collection Expressions:** Use `[]` syntax for arrays, lists, and spans (e.g., `int[] x = [1, 2, 3];`).
- **FrozenDictionary:** A read-only dictionary optimized for extremely fast lookups after creation.
**Example:**
```csharp
public class OrderService(IDbContext db, ILogger logger) // Primary Constructor
{
    public async Task Process() => logger.LogInformation("Processing with {db}", db);
}
```

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
**Cause:** Likely a "fire-and-forget" task or an async method not being awaited. The request scope ends, the DI container disposes of the `DbContext` (which is Scoped by default), but a background thread is still trying to use it.
**Fix:** Ensure all async calls are awaited, or if a background task is required, inject `IServiceScopeFactory` to create a manual scope and a new `DbContext` instance within that background thread.

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
- **Record:** A class with built-in value-based equality (instead of reference equality) and concise syntax for immutable data.
- **Record Struct:** A value-type version of a record; provides value-based equality but lives on the stack.
- **Choice:** Use `record` for DTOs/immutable models. Use `class` for objects with complex behavior/identity. Use `record struct` for small, high-performance data packets.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
- **ref:** Pass by reference; variable must be initialized before being passed. Used for read/write.
- **out:** Pass by reference; variable does not need initialization, but the method *must* assign a value before returning. Used to return multiple values.
- **in:** Pass by reference; read-only. Prevents copying large structs to improve performance.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
Nullable reference types (`string?`) are a compile-time static analysis feature to prevent `NullReferenceException`; they do not change the runtime type. Nullable value types (`int?`) are a runtime wrapper (`Nullable<T>`) that allows a value type to represent a null state.

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
LINQ (Language Integrated Query) provides a consistent way to query data.
- **Method Syntax:** Uses extension methods and lambda expressions (more flexible/common).
- **Query Syntax:** SQL-like declarative syntax (easier for complex joins).
**Deferred Execution:** The query is not executed when defined, but when the result is iterated (e.g., via `foreach` or `.ToList()`).

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
Constraints restrict the types that can be used as generic arguments:
- `class`: Must be a reference type.
- `struct`: Must be a non-nullable value type.
- `new()`: Must have a public parameterless constructor.
- `IComparable<T>`: Must implement the specified interface.
Combine them when a type must meet multiple criteria (e.g., `where T : class, IEntity, new()`).

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
Abstract classes can hold state (fields) and provide partial implementation; they support single inheritance. Interfaces define a contract; they support multiple inheritance. Default interface methods allow interfaces to provide a default implementation, blurring the line by allowing interfaces to evolve without breaking existing implementations.

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
Middleware are components that handle requests/responses in a sequence.
- `Use()`: Can call the next middleware in the pipeline.
- `Map()`: Branches the pipeline based on the request path.
- `Run()`: A terminal middleware; it does not call `next()`.
**Ordering:** Critical because requests flow through them sequentially (e.g., Auth must come before the Controller).
**Exception Handling:** Usually placed first in the pipeline to catch exceptions thrown by any subsequent middleware.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
`Channel<T>` is a high-performance, async-native producer-consumer queue. `BlockingCollection<T>` is synchronous and blocks threads.
**Backpressure:** By using `Channel.CreateBounded<T>(capacity)`, the `WriteAsync` method will asynchronously wait (suspend) when the channel is full, preventing the producer from overwhelming the consumer.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
Source Generators inspect code during compilation and generate additional C# source code.
- **Reflection:** Happens at runtime (slow).
- **IL Weaving:** Modifies the compiled assembly (complex, happens post-compile).
**Incremental Generators:** Use a cached pipeline to only re-generate code for the specific parts of the syntax tree that changed, significantly improving IDE performance compared to `ISourceGenerator` which often re-ran on every keystroke.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
TPL Dataflow is an actor-based library for building processing pipelines.
- `ActionBlock`: Receives data and performs an action (sink).
- `TransformBlock`: Receives data, transforms it, and passes it on (map).
- `BufferBlock`: Acts as a FIFO queue.
**Comparison:** `Channels` are low-level, lightweight primitives for simple producer-consumer scenarios. `TPL Dataflow` is for complex directed graphs with built-in buffering and concurrency management.

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**
Minimal APIs allow defining endpoints directly in `Program.cs` without the overhead of Controllers.
- **Trade-offs:** Less boilerplate and faster startup, but can become cluttered in large apps. Testability is similar via `WebApplicationFactory`. OpenAPI (Swagger) is fully supported.
- **Route Groups:** `app.MapGroup("/api/users")` allows sharing common middleware/auth for a set of endpoints.
- **Endpoint Filters:** Allow running logic before/after an endpoint (similar to Action Filters in MVC).

## Python

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**
- **List:** Mutable, ordered sequence.
- **Tuple:** Immutable, ordered sequence.
- **Set:** Mutable collection of unique elements.
- **Frozenset:** Immutable version of a set (can be used as a dictionary key).

**P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?**
The GIL is a mutex that allows only one thread to execute Python bytecode at a time. It affects **CPU-bound** workloads (multithreading won't provide a speedup). Workarounds include using the `multiprocessing` module (separate processes), writing extensions in C/Rust, or using Python 3.13's experimental "nogil" build.

**P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.**
`copy` (shallow) creates a new object but inserts references to the items found in the original. `deepcopy` recursively copies everything.
**Example:** `list_a = [[1, 2]]`; `list_b = copy.copy(list_a)`. If you do `list_b[0][0] = 99`, `list_a[0][0]` also becomes `99` because the inner list was shared.

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**
Decorators are functions that wrap other functions to modify their behavior.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.4f}s")
        return result
    return wrapper
```

**P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?**
Generators are functions that return an iterator using `yield`. Unlike lists, they produce values lazily (one at a time), saving memory. `yield from` is used to delegate the generation of values to another iterable or generator.

**P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?**
The event loop manages and schedules asynchronous tasks on a single thread.
- `asyncio.run()`: Entry point that starts the loop and runs a coroutine.
- `asyncio.gather()`: Runs multiple coroutines concurrently and waits for all to finish.
- `asyncio.create_task()`: Schedules a coroutine to run in the background immediately.
`time.sleep()` is blocking; it stops the entire thread, including the event loop, preventing other tasks from running. Use `await asyncio.sleep()`.

**P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**
Python 3 uses the **C3 Linearization** algorithm. In diamond inheritance, it ensures a class is always checked before its parents and that the order of parents in the class definition is preserved.
In the example: `D(B, C)` $\rightarrow$ `B` is checked, then `C`, then `A`. Since `C` overrides `who()`, `D().who()` prints **"C"**.

**P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.**
A metaclass is the "class of a class"; it defines how a class is constructed.
- `__init_subclass__`: A simpler way to customize subclassing (e.g., registering a subclass in a registry).
- **Metaclass:** Used for deeper modification of class creation (e.g., enforcing API constraints or automatically adding methods).
**Use case:** `__init_subclass__` for a plugin system; Metaclass for an ORM (like Django) to map class attributes to DB columns.

**P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?**
- **Threading:** Best for I/O-bound tasks (shared memory, limited by GIL).
- **Multiprocessing:** Best for CPU-bound tasks (separate memory, bypasses GIL).
- **concurrent.futures:** A high-level wrapper providing `ThreadPoolExecutor` and `ProcessPoolExecutor`.
**Pickling:** `multiprocessing` must serialize (pickle) data to send it between processes. Objects that cannot be pickled (e.g., open file handles, some lambdas) will cause errors.

**P10 — Medium: What is __slots__? When should you use it, and what does it prevent? What is the memory impact?**
`__slots__` tells Python not to use a dynamic dictionary (`__dict__`) for instance attributes. Use it in classes with millions of instances to significantly reduce memory usage and slightly increase attribute access speed. It prevents the dynamic addition of new attributes to the instance at runtime.

**P11 — Easy: What is a virtual environment, and why should you use one? What is the difference between venv, virtualenv, and conda?**
A virtual environment is an isolated directory containing a specific Python version and set of libraries to avoid dependency conflicts.
- `venv`: Standard library, lightweight.
- `virtualenv`: Older, more features (e.g., supports older Python versions).
- `conda`: Manages both Python and non-Python binary dependencies (common in Data Science).

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?**
They are concise ways to create collections: `[x for x in list if cond]`. They are essentially syntactic sugar for `map()` and `filter()`. Comprehensions are generally preferred in Python for readability and are often slightly faster than the functional equivalents.

**P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?**
- `==`: Checks for value equality.
- `is`: Checks for identity (do they point to the same memory address?).
**Interning:** Python caches small integers (typically -5 to 256) and certain strings to save memory. Therefore, two different variables assigned `10` will point to the same cached object, making `is` return `True`.

**P14 — Easy: Explain Python's *args and **kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?**
- `*args`: Collects extra positional arguments into a tuple.
- `**kwargs`: Collects extra keyword arguments into a dictionary.
- `/`: Arguments before `/` must be positional.
- `*`: Arguments after `*` must be keyword-only.

**P15 — Easy: What are context managers (with statement)? How do you write one using __enter__/__exit__ vs @contextmanager? Give an example beyond file handling.**
Context managers handle setup and teardown logic.
- `__enter__`/`__exit__`: Class-based implementation.
- `@contextmanager`: Generator-based implementation (using `yield`).
**Example:** A database transaction manager that commits on success and rolls back on exception.

**P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How does mypy or pyright use these for static analysis?**
Type hinting provides optional static types for variables/functions.
- `Union[A, B]`: Either type A or B.
- `Optional[A]`: Either type A or `None`.
- `Literal[1]`: Exactly the value 1.
- `TypeVar`: Used for generics.
- `Protocol`: Defines structural typing (static duck typing).
`mypy`/`pyright` scan the code without running it to find type mismatches.

**P17 — Medium: Explain Python's data model (dunder methods). What are __repr__ vs __str__, __eq__ vs __hash__, and __getattr__ vs __getattribute__? What happens if you define __eq__ but not __hash__?**
Dunder (Double-Under) methods allow objects to hook into Python's built-in behavior.
- `__repr__`: For developers (unambiguous). `__str__`: For users (readable).
- `__eq__`: Defines equality. `__hash__`: Allows object to be used in sets/dicts.
- `__getattr__`: Called only if attribute isn't found. `__getattribute__`: Called for *every* attribute access.
If you define `__eq__` without `__hash__`, the class becomes unhashable (cannot be a dict key).

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (__get__, __set__, __delete__). How do property, classmethod, and staticmethod use descriptors under the hood?**
A descriptor is an object that defines how another object's attribute is accessed. The protocol consists of `__get__`, `__set__`, and `__delete__`.
- `property`: A descriptor that manages getters and setters.
- `classmethod`/`staticmethod`: Descriptors that modify how the function is bound to the class or instance when accessed.

**P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, __init__.py, and namespace packages work? What is a finder and a loader?**
- **Absolute:** `import pkg.mod`. **Relative:** `from . import mod`.
- `sys.path`: List of directories Python searches for modules.
- `PYTHONPATH`: Env var that appends to `sys.path`.
- `__init__.py`: Marks a directory as a package. **Namespace packages** omit this to allow a package to be spread across multiple directories.
- **Finder:** Locates the module. **Loader:** Loads the module into memory.

**P20 — Hard: What is dataclasses and how does it compare to attrs and Pydantic? Explain __post_init__, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**
`dataclasses` (std lib) automate `__init__`, `__repr__`, and `__eq__`.
- `__post_init__`: Logic run after the generated `__init__`.
- `field(default_factory=list)`: Prevents "mutable default argument" bugs.
- `frozen=True`: Makes the instance immutable.
- **Inheritance:** Fields are concatenated from base to child.
**Pydantic vs Dataclasses:** Use Pydantic when you need **runtime data validation** and type coercion (e.g., parsing JSON API requests), as `dataclasses` only provide type hints without enforcement.
