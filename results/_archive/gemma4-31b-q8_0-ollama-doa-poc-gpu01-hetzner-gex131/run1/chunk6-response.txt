## JavaScript / TypeScript

**JS1**
*   **var**: Function-scoped, hoisted (initialized as `undefined`), allows re-declaration.
*   **let**: Block-scoped, hoisted (Temporal Dead Zone - cannot access before declaration), no re-declaration in same scope.
*   **const**: Block-scoped, hoisted (TDZ), requires initialization, cannot be reassigned (though object properties can be mutated).
*   **Hoisting**: The JS engine moves declarations to the top of their scope during the compilation phase.

**JS2**
*   **Event Loop**: A mechanism that monitors the Call Stack and Task Queues. If the Call Stack is empty, it pushes the next pending task onto the stack.
*   **Call Stack**: LIFO structure tracking active function calls.
*   **Microtask Queue**: Higher priority. Contains `Promise` callbacks, `queueMicrotask`, `MutationObserver`. Processed entirely before the next macrotask.
*   **Macrotask Queue**: Lower priority. Contains `setTimeout`, `setInterval`, `setImmediate`, I/O. Processed one task per loop iteration.

**JS3**
*   **Closure**: A function that remembers its lexical scope even when executed outside that scope.
*   **Example**: A private counter: `function createCounter() { let count = 0; return () => ++count; }`.
*   **Loop Bug**: Using `var` in a `for` loop with async calls (e.g., `setTimeout`) causes all callbacks to see the final value of the variable because `var` is function-scoped.
*   **Fix**: Use `let` in the loop header, which creates a new binding for every iteration.

**JS4**
*   **Promise**: An object representing the eventual completion (or failure) of an async operation.
*   **async/await**: Syntactic sugar over Promises. `async` functions return a Promise; `await` pauses execution until the Promise settles.
*   **Error Handling**: Promises use `.catch()`; async/await uses `try...catch` blocks.
*   **Promise.all**: Fails fast; rejects immediately if any promise rejects.
*   **Promise.allSettled**: Waits for all promises to settle (either fulfill or reject) and returns an array of outcomes.

**JS5**
*   **Interface**: Primarily for defining object shapes. Supports "declaration merging" (adding fields to the same interface in different files).
*   **Type**: An alias for any type (unions, primitives, tuples, intersections). Cannot be merged.
*   **Usage**: Use `interface` for public APIs/objects; use `type` for complex unions or utility types.
*   **Discriminated Unions**: A type that combines a set of types with a common literal property (the "discriminant") used to narrow the type in a switch/if block.

**JS6**
*   **Prototypal Inheritance**: Objects inherit properties and methods from other objects via a prototype chain (`__proto__`).
*   **Object.create(proto)**: Creates a new object with the specified object as its prototype.
*   **ES6 Classes**: Syntactic sugar over prototypes. `class` defines a constructor and methods on the `.prototype` property of the class function.

**JS7**
*   **this**: Refers to the execution context of the current function.
*   **Binding Rules (Priority)**: 1. `new` binding, 2. Explicit binding (`call`, `apply`, `bind`), 3. Implicit binding (object method), 4. Default binding (global/undefined).
*   **bind()**: Returns a new function with `this` permanently bound. It cannot be re-bound by subsequent `bind`, `call`, or `apply` calls.

**JS8**
*   **WeakRef**: Allows holding a reference to an object without preventing it from being garbage collected (GC).
*   **FinalizationRegistry**: A callback mechanism that triggers when a WeakRef'd object is GC'd.
*   **WeakMap**: Keys must be objects because the map holds a "weak" reference to the key. If the key object has no other references, it can be GC'd, and the entry is automatically removed.

**JS9**
*   **Hidden Classes**: V8 assigns a "shape" to objects. If two objects have the same properties in the same order, they share a hidden class.
*   **Inline Caching (IC)**: V8 remembers where a property was found in a hidden class to skip the lookup next time.
*   **Deoptimization**: Occurs when the engine's assumptions (e.g., "this variable is always an integer") are violated, forcing it to fall back to interpreted bytecode.
*   **Patterns**: Changing object shapes (adding/deleting properties dynamically) or changing variable types.

**JS10**
*   **Tree-shaking**: Dead code elimination that removes unused exports from the final bundle.
*   **ESM vs CJS**: ESM uses static `import`/`export` (analyzable at compile time). CJS uses dynamic `require()` (analyzable only at runtime).
*   **CJS Limitation**: Because `require` can be conditional or dynamic, the bundler cannot guarantee a piece of code is unused.

**JS11**
*   **null**: Intentional absence of value.
*   **undefined**: Variable declared but not assigned.
*   **Comparison**: `null == undefined` is `true` (coercion); `null === undefined` is `false`.
*   **?? (Nullish Coalescing)**: Returns RHS only if LHS is `null` or `undefined` (ignores `0`, `""`, `false`).
*   **?. (Optional Chaining)**: Short-circuits and returns `undefined` if the reference is `null` or `undefined`.

**JS12**
*   **map()**: Creates a new array by transforming every element.
*   **filter()**: Creates a new array containing elements that pass a predicate.
*   **reduce()**: Accumulates array values into a single value. If an initial value is provided, it's used as the first accumulator; otherwise, the first element of the array is used.
*   **flatMap()**: Maps each element and then flattens the result by one level. Useful for removing items or expanding one item into many.

**JS13**
*   **Template Literals**: Strings enclosed in backticks (`` ` ``) allowing multi-line strings and interpolation `${}`.
*   **Tagged Templates**: A function called with a template literal. The function receives the string parts and the interpolated values separately.
*   **Example**: `sql`tag: `sql`SELECT * FROM users WHERE id = ${id}`` (used to sanitize inputs to prevent SQL injection).

**JS14**
*   **Destructuring**: Unpacking values from arrays or properties from objects into distinct variables.
*   **Object**: `const { name, age } = user;`
*   **Array**: `const [first, second] = colors;`
*   **Defaults/Renaming**: `const { name: userName = 'Guest' } = user;`
*   **Rest (...)**: Collects remaining elements into an array: `const [first, ...rest] = array;`.

**JS15**
*   **for...in**: Iterates over enumerable **keys** (strings) of an object.
*   **for...of**: Iterates over **values** of an iterable (Array, Map, Set, String).
*   **Arrays**: Avoid `for...in` on arrays because it iterates over all enumerable properties (including custom prototype properties) and returns indices as strings, not numbers.

**JS16**
*   **Generics**: Allow components to work over a variety of types while maintaining type safety (`<T>`).
*   **Constraints**: `T extends string` ensures `T` is a string or a subtype.
*   **Conditional Types**: `T extends U ? X : Y` (if T is assignable to U, result is X, else Y).
*   **infer**: Used within conditional types to extract a type from another (e.g., `T extends Promise<infer U> ? U : T` extracts the resolved type of a Promise).

**JS17**
*   **CommonJS**: `require`/`module.exports`. Synchronous. Standard in older Node.js.
*   **ES Modules**: `import`/`export`. Asynchronous/Static. Standard in browsers and modern Node.js.
*   **Node.js Handling**: Node uses `.cjs` for CommonJS and `.mjs` for ESM.
*   **"type": "module"**: In `package.json`, this tells Node to treat all `.js` files in that directory as ES Modules.

**JS18**
*   **Structural Typing**: TS checks if the "shape" matches, not the explicit name/declaration.
*   **Excess Property Checks**: Occur when assigning an object literal directly to a type; TS prevents adding properties not defined in the type to catch typos.
*   **extends vs satisfies**: `extends` creates a subtype relationship; `satisfies` validates that a value matches a type without changing the resulting type (prevents widening).
*   **Variance**: Covariance (out) allows a more specific type; Contravariance (in) allows a more general type. TS uses this to ensure function arguments and return types are safe.

**JS19**
*   **Proxy**: Wraps an object to intercept fundamental operations (get, set, delete).
*   **Reflect**: A built-in object providing methods for interceptable JS operations (often used inside Proxy handlers to perform the default action).
*   **Example**: Validation: A Proxy `set` trap that throws an error if a value is not a number before assigning it to the target object.

**JS20**
*   **SharedArrayBuffer**: A memory buffer that can be shared between the main thread and Web Workers.
*   **Atomics**: Provides atomic operations (add, load, store) to prevent race conditions on `SharedArrayBuffer`.
*   **Communication**: Workers access the same memory address rather than passing messages via `postMessage`.
*   **wait/notify**: `Atomics.wait` puts a thread to sleep until a specific index in the buffer changes; `Atomics.notify` wakes up sleeping threads.

## Bash

**B1**
*   `$*` and `$@`: Both represent all positional parameters.
*   `"$*"`: Expands to a single string, with parameters separated by the first character of `IFS` (usually a space).
*   `"$@"`: Expands to separate quoted strings (e.g., `"arg 1" "arg 2"`), preserving spaces within arguments.

**B2**
*   `-e`: Exit immediately if a command exits with a non-zero status.
*   `-u`: Treat unset variables as an error and exit immediately.
*   `-o pipefail`: The return value of a pipeline is the status of the last command to exit with a non-zero status, or zero if all exit successfully.

**B3**
*   `$(command)` vs `` `command` ``: Both are command substitutions. `$(...)` is preferred because it is nestable and handles backslashes more predictably.
*   `$((expression))` vs `expr`: `$((...))` is shell arithmetic (built-in, fast). `expr` is an external binary (slow, requires escaping).

**B4**
*   **Process Substitution**: `<(command)` allows the output of a command to be treated as a file.
*   **Example**: `diff <(ls dir1) <(ls dir2)` compares the file lists of two directories without creating temporary files.

**B5**
*   **Safe Iteration**: Use `while IFS= read -r file; do ... done < <(find . -type f -print0 | tr '\0' '\n')` or better: `find . -type f -print0 | xargs -0`.
*   **Danger of `for f in $(ls)`**: The shell performs word splitting on the output of `ls`, breaking filenames containing spaces or newlines into multiple arguments.

**B6**
*   **Here Document (`<<EOF`)**: Redirects a multi-line block of text to a command.
*   **Here String (`<<<`)**: Redirects a single string to a command's stdin.
*   **`<<-EOF`**: Strips leading tab characters from the input lines, allowing the block to be indented for readability.

**B7**
*   `cmd > file 2>&1`: Stdout goes to `file`, then Stderr is redirected to where Stdout is currently going (`file`). Result: Both in `file`.
*   `cmd 2>&1 > file`: Stderr is redirected to current Stdout (the screen), then Stdout is redirected to `file`. Result: Stderr on screen, Stdout in `file`.
*   `cmd &> file`: Bash shortcut to redirect both Stdout and Stderr to `file`.

**B8**
*   **Locking**: `mkdir lockdir` is atomic at the OS level; if the directory exists, it fails. `touch` is not atomic (race condition between check and create).
*   **Function**:
    ```bash
    lock_it() {
      mkdir /tmp/mylock || exit 1
      trap 'rmdir /tmp/mylock; exit' INT TERM EXIT
    }
    ```
*   **Cleanup**: `trap` ensures the lock is removed even if the script is killed.

**B9**
*   **Single quotes ('')**: Literal strings. No expansion. `'Hello $USER'` $\rightarrow$ `Hello $USER`.
*   **Double quotes ("")**: Interpolates variables and commands. `"Hello $USER"` $\rightarrow$ `Hello alice`.
*   **No quotes**: Subject to word splitting and globbing. `echo $VAR` (if `$VAR` is "a b") $\rightarrow$ two arguments.

**B10**
*   **Checks**: `-f` (file), `-d` (directory), `-r` (readable).
*   **`[ ]` vs `[[ ]]`**: `[ ]` is the POSIX `test` command. `[[ ]]` is a Bash keyword that supports regex (`=~`), logical operators (`&&`, `||`) without escaping, and doesn't require quoting variables to prevent word splitting.

**B11**
*   `$?`: Exit status of the last command (0 = success).
*   `$$`: PID of the current shell.
*   `$!`: PID of the last background process.
*   `$#`: Number of positional parameters passed to the script/function.

**B12**
*   **Definition**: `foo() { ... }` (POSIX) or `function foo { ... }` (Bash). The former is more portable.
*   **Return Values**: Functions return an exit status (0-255) via `return`. To return data, use `echo` and capture it via command substitution: `result=$(foo)`.

**B13**
*   **PATH**: A colon-separated list of directories the shell searches for executable files.
*   **Resolution**: Shell checks aliases $\rightarrow$ functions $\rightarrow$ builtins $\rightarrow$ PATH directories.
*   **Builtin vs External**: Builtins (e.g., `cd`, `echo`) run inside the shell process. Externals (e.g., `ls`, `grep`) are separate binaries.
*   **Check**: Use `type -a <command>`.

**B14**
*   **Trap**: `trap 'command' SIGNAL`.
*   **Handlers**: `trap 'cleanup' EXIT` (runs on any exit), `trap 'error_handler' ERR` (runs on non-zero exit).
*   **Order**: Signals are handled as they arrive. If multiple signals are trapped by the same command, that command runs once per signal.

**B15**
*   **xargs vs Substitution**: Substitution `$(...)` loads the entire output into memory as arguments. `xargs` reads from stdin and executes commands in batches, avoiding "Argument list too long" errors.
*   **Spaces/Newlines**: `find . -print0 | xargs -0` uses the null character as a delimiter.
*   **-P**: `xargs -P 4` runs up to 4 processes in parallel.

**B16**
*   **Indexed Arrays**: `arr=(a b c)`. Append: `arr+=("d")`. Iterate: `for i in "${arr[@]}"; do`. Length: `${#arr[@]}`.
*   **Associative Arrays**: `declare -A assoc`. `assoc[key]="val"`. Iterate: `for k in "${!assoc[@]}"; do`.
*   **Difference**: Indexed use integers; Associative use strings as keys.

**B17**
*   **Subshell `(...)`**: Forks a new process. Variable changes inside are lost to the parent.
*   **Group `{ ...; }`**: Executes in the current shell. Variable changes persist.
*   **Pipes**: In Bash, piping into a `while` loop (e.g., `cat file | while read line`) creates a subshell, so variables modified inside the loop are lost.

**B18**
*   **Signals**:
    *   `SIGINT`: Interrupt (Ctrl+C).
    *   `SIGTERM`: Termination request (polite).
    *   `SIGHUP`: Hangup (terminal closed).
    *   `SIGKILL`: Immediate kill (cannot be trapped).
*   **Graceful Shutdown**: Use `trap` to catch `SIGTERM`, then send `SIGTERM` to all child PIDs stored in an array.

**B19**
*   **Script**:
    ```bash
    split -l 1000 large.log chunk_
    ls chunk_* | xargs -P 4 -I {} bash -c "process_func {} > {}.out"
    cat *.out > final_results.txt
    ```
*   **Trade-offs**: Parallelism increases CPU usage but reduces wall-clock time. I/O can become a bottleneck.
*   **Errors**: Use `set -e` or check exit codes of `xargs` (though `xargs` only returns non-zero if the last command fails).

**B20**
*   **exec**: Replaces the current shell process with the new command (no return to shell).
*   **FD Manipulation**: `exec 3>file` opens file descriptor 3 for writing. `exec 3>&-` closes it.
*   **Coprocess**: `coproc myproc { ... }` runs a command in the background with two-way communication via pipes (`myproc.in` and `myproc.out`). Used for long-running background daemons.

## PowerShell

**PS1**
*   **Write-Output**: Sends objects to the pipeline. Other cmdlets can process this data.
*   **Write-Host**: Writes directly to the console (host). It bypasses the pipeline, meaning the data cannot be captured or passed to another cmdlet.

**PS2**
*   **Pipeline**: Passes objects (not text) from one cmdlet to another.
*   **ForEach-Object**: A pipeline cmdlet. Processes items one-by-one as they arrive (streaming).
*   **foreach statement**: A language keyword. Loads the entire collection into memory first, then iterates. Faster for small sets, but memory-intensive for large ones.

**PS3**
*   **[PSCustomObject]**: A structured object with fixed properties. Better for outputting tables/CSV.
*   **[hashtable]**: A key-value pair collection. Better for lookups and passing parameters.
*   **Conversion**: `[PSCustomObject]$hash` converts a hashtable to an object.

**PS4**
*   **Terminating**: Stops execution (e.g., syntax error). Caught by `try/catch`.
*   **Non-terminating**: Prints an error but continues (e.g., `Get-Item` on a missing file).
*   **Interaction**: `-ErrorAction Stop` converts a non-terminating error into a terminating one, allowing it to be caught by `try/catch`. `$ErrorActionPreference` sets the global default.

**PS5**
*   **Splatting**: Passing a hashtable of parameters using `@` instead of `$`.
*   **Example**: `$params = @{ Path = 'C:\'; Filter = '*.txt' }; Get-ChildItem @params`.
*   **Difference**: Passing a hashtable as a parameter (`-MyParam $hash`) passes the *entire* hashtable as a single argument; splatting expands the hashtable into individual named parameters.

**PS6**
*   **Invoke-Command**: Runs a script block on one or more remote computers and returns results.
*   **Enter-PSSession**: Starts an interactive 1-to-1 remote shell.
*   **Protocol**: Uses WinRM (WS-Management) by default, but PowerShell 7+ supports SSH.

**PS7**
*   **Implicit Behavior**: PowerShell "unrolls" arrays in the pipeline.
*   **Result**: `$x` will be an `Object[]` (array) if multiple items are returned, but a single `String` if only one item is returned.
*   **0 items**: Returns `$null`.
*   **Correct Pattern**: Wrap the call in `@(...)` to force the result to always be an array: `$x = @(Get-Items)`.

**PS8**
*   **Scriptblock**: A block of code `{ ... }` that can be passed as an object.
*   **Remote Session**: Passed via `-ScriptBlock` parameter in `Invoke-Command`.
*   **Double-Hop**: When a remote session tries to access a *second* remote resource (e.g., Server A $\rightarrow$ Server B). Solved via CredSSP or by passing credentials explicitly via `-ArgumentList`.

**PS9**
*   **@()**: Array subexpression operator. Ensures the result is an array even if 0 or 1 items are returned.
*   **[array]**: Type cast to an array.
*   **Indexing**: Indexing into `$null` in PowerShell returns `$null` rather than throwing an exception (unlike C#).

**PS10**
*   **Operators**: `-eq` (equal), `-ne` (not equal), `-like` (wildcards `*`), `-match` (regex), `-contains` (collection contains value), `-in` (value is in collection).
*   **Case-sensitivity**: By default, they are case-insensitive. Prefix with `c` (e.g., `-ceq`) for case-sensitive.
*   **-contains vs -in**: `-contains` is called on the collection (`$list -contains 'a'`); `-in` is called on the value (`'a' -in $list`).

**PS11**
*   **Module**: A package of functions, variables, and cmdlets.
*   **.psm1**: Script module containing the actual code.
*   **.psd1**: Manifest module containing metadata (version, author, dependencies).
*   **Binary Module**: A compiled .NET assembly (DLL).
*   **Import-Module**: Loads the module into the current session.

**PS12**
*   **Interpolation**: `"..."` (double quotes) allows variable expansion. `'...'` (single quotes) is literal.
*   **Expressions**: Use the subexpression operator `$()` inside double quotes: `"The date is $(Get-Date)"`.
*   **Here-string**: `@"` ... `"@` allows multi-line strings without escaping quotes.

**PS13**
*   **Get-Member**: Introspects an object to show its Properties, Methods, and Events.
*   **NoteProperties**: Calculated properties added dynamically (e.g., via `Select-Object`).
*   **Select-Object**: Filters **properties** (columns).
*   **Where-Object**: Filters **objects** (rows) based on a condition.

**PS14**
*   **Classes**: Introduced in v5 for strong typing and OOP.
*   **Differences**: Unlike C#, they are more flexible with types but have limited support for interfaces and complex generics.
*   **Usage**: Use classes for complex data models; use functions for procedural tasks/automation.

**PS15**
*   **CmdletBinding**: Turns a function into an "Advanced Function," enabling common parameters like `-Verbose`, `-Debug`, and `-WhatIf`.
*   **SupportsShouldProcess**: Enables `-WhatIf` and `-Confirm`.
*   **ValueFromPipeline**: Allows the function to accept input directly from the pipeline.
*   **Blocks**: `Begin` (runs once at start), `Process` (runs once per pipeline object), `End` (runs once at finish).

**PS16**
*   **Providers**: A layer that allows PowerShell to treat different data stores (Registry, Certs, Env) as drives.
*   **Get-ChildItem**: Works identically across providers (e.g., `Get-ChildItem C:\` vs `Get-ChildItem HKLM:\`).
*   **Registry**: Accessed via `CD HKLM:\` or `Get-Item 'HKLM:\Software\...'`.

**PS17**
*   **Runspaces**: Isolated execution environments. A `RunspacePool` manages a set of runspaces for efficiency.
*   **Parallelism**: `ForEach-Object -Parallel` (v7+) simplifies parallel execution by managing runspaces internally. Manual runspace management is used for complex, long-lived asynchronous tasks.

**PS18**
*   **PSScriptAnalyzer**: A static code analysis tool.
*   **Enforcement**: Checks code against a set of rules (e.g., "Avoid using Write-Host").
*   **Severity**: Error, Warning, Information.
*   **Suppression**: Use `[Diagnostics.CodeAnalysis.SuppressMessageAttribute()]`.
*   **CI/CD**: Integrated via `Invoke-ScriptAnalyzer` in build pipelines to fail builds on linting errors.

**PS19**
*   **$using: scope**: Used in `Invoke-Command` or `-Parallel` to reference a variable from the local session.
*   **-ArgumentList**: Passes variables as a positional array to the remote block (accessed via `$args`).
*   **Serialization**: Objects are serialized via CLIXML. Deeply nested or complex .NET objects may lose data or fail to deserialize if they exceed depth limits.

**PS20**
*   **DSC**: A declarative platform for maintaining environment state.
*   **Components**: `Configuration` (the desired state), `Resource` (the logic to apply state), `LCM` (the engine on the target node that enforces state).
*   **Evolution**: Windows PowerShell DSC was agent-based. PowerShell 7+ moved toward "DSC v3" (cross-platform).
*   **Replacement**: Largely replaced by Terraform, Ansible, or Azure Automanage/Guest Configuration.
