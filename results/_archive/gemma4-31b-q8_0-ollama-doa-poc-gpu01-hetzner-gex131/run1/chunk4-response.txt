## Go

**G1** — An **array** has a fixed size defined at compile time; it is a value type. A **slice** is a descriptor for a contiguous segment of an array, consisting of a pointer, a length, and a capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array, copies the existing elements over, and returns a new slice pointing to the new array.

**G2** — `var x int` declares a variable with its zero value (0 for int) and can be used at the package or function level. `x := 0` is short-variable declaration, which infers the type and is only allowed inside functions. You **cannot** use `:=` at the package level or when you want to declare a variable without initializing it immediately.

**G3** — A **goroutine** is a lightweight thread managed by the Go runtime. Unlike OS threads (which have large stacks, ~2MB), goroutines start with a small stack (~2KB) that grows dynamically. The **GMP model** consists of **G** (Goroutine), **M** (Machine/OS Thread), and **P** (Processor/Logical Context). P schedules Gs onto Ms, allowing Go to multiplex thousands of goroutines onto a small number of OS threads.

**G4** — Channels are typed conduits for communication between goroutines. **Unbuffered channels** are synchronous; the sender blocks until a receiver is ready. **Buffered channels** have a capacity; the sender only blocks when the buffer is full. If you send to a full buffered channel, the goroutine blocks until a receiver removes a value.

**G5** — The `context` package manages deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
_, err := http.DefaultClient.Do(req)
```

**G6** — Go uses **implicit satisfaction**: a type implements an interface by implementing its methods; no `implements` keyword is needed. This allows for decoupled, structural typing. `interface{}` (or `any`) is the empty interface; since every type implements zero methods, every type satisfies it. It is powerful for generic containers but dangerous because it bypasses compile-time type safety, requiring runtime type assertions.

**G7** — Go does not guarantee that a write to a variable in one goroutine is immediately visible to another without synchronization. The loop `for !ready {}` might run forever because the compiler may optimize it into an infinite loop, assuming `ready` never changes. **Correct alternatives**: Use `sync.Mutex`, `atomic.Bool`, or a channel to signal completion.

**G8** — `sync.Mutex` provides exclusive access. `sync.RWMutex` allows multiple concurrent readers OR one exclusive writer, improving performance for read-heavy workloads. `sync.Map` is optimized for two cases: (1) when the entry for a given key is only ever written once but read many times, or (2) when multiple goroutines read, write, and overwrite entries for disjoint sets of keys. A regular map with a mutex is generally faster for most common use cases.

**G9** — Go modules manage dependencies. `go.mod` defines the module path and required versions; `go.sum` contains cryptographic checksums to ensure builds are reproducible. `go mod tidy` removes unused modules and adds missing ones. **MVS (Minimum Version Selection)** selects the *minimum* version of a dependency that satisfies all constraints in the graph, ensuring stability and determinism.

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. **Gotcha**: Defers in a loop do not execute until the function returns, not at the end of the loop iteration, which can lead to resource exhaustion (e.g., open file descriptors).

**G11** — A pointer holds the memory address of a value. The zero value of a pointer is `nil`. To create a pointer to a struct literal, use the address-of operator: `p := &User{Name: "Alice"}`.

**G12** — `init()` is a special function used for package initialization. It runs after package-level variables are initialized but before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source files.

**G13** — `new(T)` allocates zeroed memory for a type `T` and returns a pointer `*T`. `make` is used only for **slices, maps, and channels**; it initializes the internal data structure and returns the type itself (not a pointer).

**G14** — Go treats errors as values. The `error` interface requires an `Error() string` method. The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error is (or wraps) a specific error value; `errors.As` checks if an error is (or wraps) a specific error type and casts it. `==` only checks the immediate value and fails if the error is wrapped.

**G15** — 
- **Map**: `nil`
- **Slice**: `nil`
- **Channel**: `nil`
- **Struct**: All fields set to their respective zero values.

**G16** — A race condition occurs when two or more goroutines access the same memory concurrently, and at least one access is a write. The `-race` flag enables a runtime detector that finds these.
*Fix:*
```go
var mu sync.Mutex
var count int
// In goroutine:
mu.Lock()
count++
mu.Unlock()
```

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, it blocks until one of its cases can run. If multiple cases are ready, one is chosen pseudo-randomly. A timeout is implemented using `time.After`:
```go
select {
case res := <-ch: // handle res
case <-time.After(1 * time.Second): // handle timeout
}
```

**G18** — Escape analysis is the compiler's process of deciding whether a variable can be allocated on the stack or must "escape" to the heap. If a variable is referenced outside the function scope (e.g., returning a pointer), it is heap-allocated. Inspect via `go build -gcflags="-m"`. Heap allocation increases GC pressure and reduces performance.

**G19** — `reflect` allows a program to inspect its own structure. `reflect.Type` represents the static type; `reflect.Value` represents the dynamic value. Reflection is slow and bypasses type safety. It is justified for generic libraries (JSON encoders, ORMs). Code generation (e.g., `stringer`) is preferred for performance as it moves the cost to compile time.

**G20** — `go:embed` allows embedding files into the binary. `//go:embed file.txt` embeds a file as a `string` or `[]byte`. `//go:embed folder/*` embeds a directory as an `embed.FS`. It is read-only and fixed at compile time. It implements the `io/fs.FS` interface, allowing the same code to read from the embedded filesystem or the OS filesystem.

## Rust

**R1** — Ownership is Rust's system for managing memory without a GC. Rules: 1. Each value has a variable called its **owner**. 2. There can only be **one owner** at a time. 3. When the owner goes **out of scope**, the value is dropped.

**R2** — `String` is an owned, heap-allocated, growable UTF-8 string. `&str` is a borrowed string slice (a pointer and a length). In function signatures, use `&str` for inputs to accept both `String` and `&str` (via deref coercion), and `String` only if the function must take ownership.

**R3** — Borrowing allows accessing data without taking ownership. The borrow checker enforces: 1. You can have **either** one mutable reference (`&mut T`) **or** any number of immutable references (`&T`) at any given time. 2. References must always be valid (no dangling pointers).

**R4** — `Result<T, E>` handles recoverable errors (`Ok` or `Err`); `Option<T>` handles presence/absence (`Some` or `None`). The `?` operator unwraps `Ok`/`Some` or returns the `Err`/`None` to the caller.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    Ok(std::fs::read_to_string(path)?)
}
```

**R5** — `Box<T>` is a pointer to heap-allocated memory. `Rc<T>` (Reference Counted) allows multiple owners in a **single-threaded** context. `Arc<T>` (Atomic Reference Counted) allows multiple owners across **multiple threads**.

**R6** — Traits define shared behavior (similar to interfaces). Go interfaces are implicit; Rust traits are explicit. `T: Trait` (Generics) uses **static dispatch** (monomorphization), creating a copy of the function for each type. `dyn Trait` (Trait Objects) uses **dynamic dispatch** via a vtable, allowing for heterogeneous collections.

**R7** — Lifetimes ensure references don't outlive the data they point to. The example fails because the compiler doesn't know if the returned reference points to `x` or `y`. Fix:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

**R8** — `Send` indicates a type can be transferred between threads. `Sync` indicates a type can be shared between threads via references. `Rc<T>` is not `Send` or `Sync` because its reference counter is not atomic; incrementing it from two threads would cause a data race. `Arc<T>` uses atomic operations for the counter, making it thread-safe.

**R9** — Rust's async is a **poll-based state machine**. A `Future` is a trait with a `poll` method that returns `Poll::Ready` or `Poll::Pending`. The **executor** (e.g., Tokio) manages a queue of futures and polls them when they are woken. Go's goroutines are preemptive and managed by a runtime scheduler; Rust's async is cooperative and requires an external executor.

**R10** — `unsafe` allows bypassing some borrow checker rules. You can: 1. Dereference raw pointers (`*const T`, `*mut T`). 2. Call unsafe functions (FFI). 3. Access/modify mutable static variables. It is justified for low-level hardware access, FFI, or implementing high-performance data structures (like `Vec`).

**R11** — Pattern matching uses `match` to handle all possible values of an enum or type. `match` is **exhaustive** (the compiler errors if a case is missing). `if let` is syntactic sugar for a `match` that only cares about one specific pattern, ignoring the rest.

**R12** — `[T; N]` is a fixed-size array allocated on the stack. `Vec<T>` is a growable, heap-allocated vector. When `Vec` exceeds its capacity, it allocates a new larger block of memory (usually doubling), copies the elements, and frees the old block.

**R13** — Rust enums are **sum types** (Algebraic Data Types); they can hold data in each variant. C/Java enums are typically just named integers. `Option<T>` is an enum with `Some(T)` and `None`. Rust has no `null` to eliminate null-pointer exceptions at compile time.

**R14** — `impl` blocks define methods for a type. `&self` is an immutable borrow, `&mut self` is a mutable borrow, and `self` consumes the object (takes ownership). **Associated functions** (like `String::new()`) do not take `self` and are called on the type itself.

**R15** — `derive` is a procedural macro that automatically implements traits. Common ones: `Debug` (printing), `Clone` (duplicating), `PartialEq` (equality), `Serialize` (serde). You cannot derive a trait if any field within the struct does not also implement that trait.

**R16** — `Cow<'a, T>` (Clone-on-Write) is a smart pointer that can either be borrowed or owned. It avoids allocation by staying borrowed until a mutation is required, at which point it clones the data. Example: A function that cleans a string only if it contains invalid characters; otherwise, it returns the original borrowed slice.

**R17** — `mod` declares a module, `use` brings paths into scope, and `pub` makes items visible. In Rust 2015, modules required `mod.rs`. In 2018+, you can use `folder.rs` alongside a `folder/` directory to define the module and its sub-modules.

**R18** — `Pin<P>` ensures that the data pointed to by `P` cannot be moved in memory. This is critical for **self-referential structs** (where a field points to another field in the same struct), which are common in `async` blocks. `Unpin` is an auto-trait for types that are safe to move (most types).

**R19** — **Declarative macros** (`macro_rules!`) use pattern matching to replace code. **Procedural macros** are functions that take a token stream as input and produce a token stream as output (`derive`, `attribute`, `function-like`). **Hygiene** ensures that macros do not accidentally capture variables from the scope where they are invoked.

**R20** — Zero-cost abstractions mean you don't pay for what you don't use. **Monomorphization** generates concrete code for each generic type used, eliminating runtime dispatch. **Iterators** are optimized by LLVM into loops as efficient as hand-written C. **Static dispatch** (via traits) allows the compiler to inline calls, removing the overhead of virtual function tables.
