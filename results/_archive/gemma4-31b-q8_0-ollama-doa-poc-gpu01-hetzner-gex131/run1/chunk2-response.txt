## Kubernetes

**K1 — Easy: What is the difference between a Deployment and a StatefulSet?**
A **Deployment** is for stateless applications; pods are interchangeable, have random hashes in their names, and can be terminated/replaced in any order. A **StatefulSet** is for stateful applications (e.g., databases); pods have a sticky identity (pod-0, pod-1), are created/scaled in a strict ordinal sequence, and maintain a 1-to-1 mapping with their own PersistentVolumeClaims.

**K2 — Easy: How does a Kubernetes Service of type ClusterIP route traffic to pods?**
A ClusterIP provides a stable virtual IP. `kube-proxy` (running on every node) manages the routing rules (via `iptables` or `IPVS`). When traffic hits the ClusterIP, the rules intercept it and load-balance it across the current list of healthy Pod IPs associated with the Service's selector (the Endpoints object).

**K3 — Medium: Explain the difference between a PersistentVolume, a PersistentVolumeClaim, and a StorageClass. How do they relate?**
*   **PersistentVolume (PV):** A piece of storage in the cluster provisioned by an admin or dynamically (the "actual" disk).
*   **PersistentVolumeClaim (PVC):** A user's request for storage (size, access mode).
*   **StorageClass (SC):** A "profile" that defines different types of storage (e.g., SSD vs HDD) and allows for dynamic provisioning.
**Relation:** A user creates a **PVC** $\rightarrow$ the **SC** sees the request and automatically provisions a **PV** $\rightarrow$ the **PVC** binds to that **PV**.

**K4 — Medium: A pod is stuck in CrashLoopBackOff. Describe your troubleshooting steps.**
1.  `kubectl logs <pod>`: Check application stdout/stderr for panic or configuration errors.
2.  `kubectl describe pod <pod>`: Check "Events" for OOMKilled, failed probes, or image pull errors.
3.  Check Environment Variables/Secrets: Ensure all required ConfigMaps/Secrets are present and correctly named.
4.  Check Liveness/Readiness Probes: Verify if the probe is hitting the wrong port or timing out before the app is ready.

**K5 — Medium: What is the role of CoreDNS in a Kubernetes cluster? What happens to DNS resolution if the CoreDNS pods are down?**
CoreDNS provides service discovery. It maps Service names (e.g., `my-svc.my-namespace.svc.cluster.local`) to their ClusterIPs. If CoreDNS pods are down, pods cannot resolve other services by name, causing internal communication to fail, though communication via direct IP would still work.

**K6 — Hard: Explain how the Kubernetes scheduler decides which node to place a pod on.**
The scheduler follows a two-step process:
1.  **Filtering (Predicates):** It removes nodes that cannot host the pod (e.g., insufficient CPU/RAM, node selector mismatch, taints the pod doesn't tolerate).
2.  **Scoring (Priorities):** It ranks remaining nodes to find the "best" fit.
**Factors considered:**
*   **Resource Fit:** Preferring nodes where the pod's request leaves the most balanced resource distribution.
*   **Affinity/Anti-Affinity:** Placing pods near (or far from) other pods/nodes.
*   **Image Locality:** Preferring nodes that already have the container image cached.

**K7 — Hard: You have a pod with requests.memory: 256Mi and limits.memory: 512Mi. The node has 4GB RAM with 3.5GB already requested. Will the pod be scheduled? What happens if it actually uses 600Mi at runtime?**
**Scheduling:** Yes. The scheduler looks at *requests*. $3.5\text{GB} + 256\text{Mi} \approx 3.75\text{GB}$, which is $\le 4\text{GB}$.
**Runtime:** If the pod uses 600Mi, it exceeds its *limit* (512Mi). The Linux kernel will trigger an Out-Of-Memory (OOM) event, and the kubelet will terminate the container with the status `OOMKilled`.

**K8 — Hard: Explain the full lifecycle of a request hitting a Kubernetes Ingress backed by an NGINX ingress controller.**
1.  **External LB:** Traffic hits a Cloud Load Balancer, which forwards it to the NodePort of the NGINX Ingress Controller pods.
2.  **Ingress Controller:** NGINX receives the request and matches the Host/Path against its configured Ingress rules.
3.  **Endpoints:** NGINX does *not* typically route to the Service ClusterIP; instead, it looks up the **Endpoints** object to get the actual Pod IPs.
4.  **Pod:** NGINX forwards the request directly to a Pod IP.
*(Note: `kube-proxy/iptables` are bypassed by NGINX for performance, though they are used if the controller is configured to use the Service IP).*

**K9 — Medium: What is a NetworkPolicy? If no NetworkPolicy exists in a namespace, what is the default behavior? What happens when you apply one that selects certain pods?**
A NetworkPolicy is an L3/L4 firewall for pods.
*   **Default:** All pods are "non-isolated" and accept traffic from any source.
*   **Applying a policy:** Once a policy selects a pod, that pod becomes "isolated." It will drop all traffic that is not explicitly allowed by the policy (Default Deny).

**K10 — Medium: Explain the difference between RollingUpdate and Recreate deployment strategies. When would you choose Recreate?**
*   **RollingUpdate:** Gradually replaces old pods with new ones. Ensures zero downtime.
*   **Recreate:** Kills all existing pods before starting new ones. Causes downtime.
**Choose Recreate when:** The application does not support running two different versions simultaneously (e.g., a breaking database schema change where the old code cannot read the new schema).

**K11 — Easy: What is a Kubernetes namespace, and what are the default namespaces created in a new cluster?**
A namespace is a virtual cluster used to partition resources for different teams or environments.
**Defaults:** `default` (user apps), `kube-system` (cluster components), `kube-public` (publicly readable), and `kube-node-lease` (heartbeats).

**K12 — Easy: What is `kubectl describe pod <name>` used for? Name at least 3 pieces of information it shows that `kubectl get pod` does not.**
It provides detailed metadata and status of a pod.
**Extra info:** 1. Events (e.g., Pulling image, Failed scheduling). 2. Container status (Exit codes, restart counts). 3. Volume mount details.

**K13 — Easy: What is a ConfigMap, and how can a pod consume it? Name at least two different methods.**
A ConfigMap stores non-confidential configuration data in key-value pairs.
**Consumption methods:** 1. As environment variables. 2. As files mounted in a volume.

**K14 — Easy: What is the difference between a Service of type ClusterIP, NodePort, and LoadBalancer?**
*   **ClusterIP:** Internal IP; only reachable from within the cluster.
*   **NodePort:** Exposes the service on a static port on every Node's IP.
*   **LoadBalancer:** Provisions an external cloud load balancer that routes to the NodePort.

**K15 — Easy: What is a DaemonSet, and when would you use one instead of a Deployment?**
A DaemonSet ensures that all (or some) nodes run a copy of a specific pod.
**Use case:** Infrastructure agents like log collectors (Fluentd), monitoring agents (Prometheus Node Exporter), or CNI plugins.

**K16 — Medium: What are taints and tolerations? How do they differ from node affinity, and give a practical use case for each?**
*   **Taints/Tolerations:** Taints are applied to *nodes* to repel pods. Tolerations are applied to *pods* to allow them to stay on tainted nodes. (Use case: Taint a node with GPUs so only GPU-enabled pods can be scheduled there).
*   **Node Affinity:** Applied to *pods* to attract them to specific nodes. (Use case: Ensure a pod runs on a node in a specific availability zone).

**K17 — Medium: Explain what a Kubernetes Operator is. How does it differ from a standard controller, and what problems does the Operator pattern solve?**
An Operator is a custom controller that uses a **Custom Resource Definition (CRD)** to manage a complex application. While a standard controller manages generic resources (like Pods), an Operator encodes "domain-specific knowledge" (e.g., how to perform a MySQL backup or a MongoDB shard upgrade) into software to automate the full lifecycle of stateful apps.

**K18 — Hard: Explain the etcd consistency model used by Kubernetes. What happens to the cluster if the etcd quorum is lost? How do you recover from a situation where 2 out of 3 etcd nodes are permanently lost?**
etcd uses the **Raft** consensus algorithm for strong consistency.
*   **Quorum Loss:** If a majority of nodes are down, etcd becomes read-only or unavailable. The K8s API server cannot update state, meaning no new pods can be scheduled and no changes can be made.
*   **Recovery:** You cannot regain quorum with 1/3 nodes. You must restore from a snapshot to a new single-node cluster and then re-bootstrap the cluster to add new members.

**K19 — Hard: Describe how Kubernetes RBAC works. Explain the relationship between Role, ClusterRole, RoleBinding, and ClusterRoleBinding. Write the manifests for read-only pod/log access in one namespace.**
*   **Role:** Permissions within a specific namespace.
*   **ClusterRole:** Permissions cluster-wide (or a template for Roles).
*   **RoleBinding:** Grants a Role to a user/group in a specific namespace.
*   **ClusterRoleBinding:** Grants a ClusterRole to a user/group cluster-wide.

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: dev-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "watch", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: dev-ns
subjects:
- kind: User
  name: "developer-user"
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20 — Hard: You notice pod DNS resolution is slow (>5s) for external domains. Explain how ndots causes this and how to fix it.**
By default, `ndots` is 5. If a DNS query has fewer than 5 dots (e.g., `google.com`), K8s tries to resolve it as a local service first by appending search paths (e.g., `google.com.my-ns.svc.cluster.local`). This causes multiple failed queries before finally trying the external DNS.
**Fix:** Set `dnsConfig` in the pod spec to `ndots: 1` or use a Fully Qualified Domain Name (FQDN) by adding a trailing dot (e.g., `google.com.`).

## Development

**D1 — Easy: What is the difference between git rebase and git merge? When should you avoid rebasing?**
*   **Merge:** Combines branches by creating a "merge commit," preserving the exact history of how branches diverged and joined.
*   **Rebase:** Moves the entire feature branch to begin on the tip of the main branch, rewriting history for a linear timeline.
**Avoid rebasing:** Public or shared branches. Rewriting history on a shared branch causes conflicts for everyone else.

**D2 — Easy: Explain the difference between TCP and UDP. Name 2 protocols that use each.**
*   **TCP:** Connection-oriented, guarantees delivery, ordered packets, slower due to handshake/acknowledgments. (HTTP, SSH).
*   **UDP:** Connectionless, "fire and forget," no guarantee of delivery, faster. (DNS, VoIP/Streaming).

**D3 — Medium: What is a race condition? Give a concrete example.**
A race condition occurs when the output of a program depends on the unpredictable timing or sequence of multiple threads accessing shared data.
**Example:** Two threads incrementing a shared variable `count = 0`. Both read `0`, both add `1`, and both write `1` back. The final value is `1` instead of `2`.

**D4 — Medium: Explain the difference between symmetric and asymmetric encryption. How are both used together in TLS?**
*   **Symmetric:** Same key for encryption and decryption (Fast, e.g., AES).
*   **Asymmetric:** Public key encrypts, private key decrypts (Slow, e.g., RSA).
**TLS:** Asymmetric encryption is used during the "handshake" to securely exchange a symmetric "session key." Once the session key is established, symmetric encryption is used for the actual data transfer for efficiency.

**D5 — Medium: What is a container image layer? How does layer caching affect Dockerfile best practices?**
Each instruction in a Dockerfile (e.g., `RUN`, `COPY`) creates a read-only layer. Docker caches these layers. If a layer changes, all subsequent layers must be rebuilt.
**Best Practice:** Order instructions from "least likely to change" to "most likely to change." (e.g., Copy `package.json` and run `npm install` *before* copying the rest of the source code).

**D6 — Medium: You have a REST API returning HTTP 503 intermittently. Describe 4 things you would check, in order.**
1.  **Load Balancer/Ingress Logs:** Is the 503 coming from the LB (no healthy backends) or the app itself?
2.  **Pod Status/Events:** Check for `OOMKilled` or frequent restarts (CrashLoopBackOff).
3.  **Application Logs:** Look for timeouts, connection pool exhaustion, or unhandled exceptions.
4.  **Downstream Dependencies:** Check if the database or a third-party API is timing out or rate-limiting the app.

**D7 — Hard: Explain the CAP theorem. Give a real-world example of CP and AP.**
CAP states a distributed system can only provide two of three: **Consistency** (all nodes see same data), **Availability** (every request gets a response), and **Partition Tolerance** (system works despite network splits).
*   **CP (Consistency/Partition):** MongoDB (in default config). It will stop accepting writes if a primary cannot be elected to ensure data consistency.
*   **AP (Availability/Partition):** Cassandra. It allows writes to any node during a split, resolving conflicts later (eventual consistency).

**D8 — Medium: What is the difference between horizontal and vertical scaling? What architectural patterns enable horizontal scaling?**
*   **Vertical:** Adding more CPU/RAM to a single machine.
*   **Horizontal:** Adding more machines to the pool.
**Patterns:** Statelessness (no session data on server), Load Balancing, Database Sharding, and Asynchronous Messaging (Queues).

**D9 — Easy: What is an environment variable? How do you set one that persists across shell sessions on Linux?**
An environment variable is a dynamic value available to a process and its children.
**Persistence:** Add the export command (e.g., `export API_KEY=123`) to the user's shell profile file, such as `~/.bashrc` or `~/.zshrc`.

**D10 — Easy: What is JSON, and how does it differ from YAML? Name one advantage of each.**
Both are data serialization formats. JSON is stricter and uses brackets/braces; YAML is a superset of JSON that uses indentation.
*   **JSON Advantage:** Faster parsing and universal support in browsers/APIs.
*   **YAML Advantage:** Much more human-readable and supports comments.

**D11 — Easy: What is a REST API? Explain the difference between GET, POST, PUT, and DELETE.**
REST is an architectural style for networked applications using HTTP.
*   **GET:** Retrieve a resource.
*   **POST:** Create a new resource.
*   **PUT:** Update/Replace an existing resource.
*   **DELETE:** Remove a resource.

**D12 — Easy: What is version pinning in dependency management, and why is it important?**
Version pinning is specifying the exact version of a library (e.g., `requests==2.25.1` instead of `requests>=2.0`). It ensures **reproducible builds**, preventing the app from breaking when a dependency releases a new version with breaking changes.

**D13 — Easy: What is the difference between a compiled language and an interpreted language? Give two examples of each.**
*   **Compiled:** Source code is translated to machine code by a compiler before execution. (C++, Rust).
*   **Interpreted:** Source code is read and executed line-by-line by an interpreter at runtime. (Python, Ruby).

**D14 — Medium: Explain what a reverse proxy is and how it differs from a forward proxy. Name two common servers.**
*   **Forward Proxy:** Sits in front of *clients* to hide them or filter their outgoing requests.
*   **Reverse Proxy:** Sits in front of *servers* to hide them, provide load balancing, or handle SSL termination.
**Servers:** Nginx (Load balancing/Static content), HAProxy (High-performance TCP/HTTP balancing).

**D15 — Medium: What is a deadlock? What four conditions (Coffman conditions) must hold?**
A deadlock is a state where two or more threads are blocked forever, each waiting for a resource held by the other.
**Coffman Conditions:**
1.  **Mutual Exclusion:** Only one process can use a resource at a time.
2.  **Hold and Wait:** A process holds a resource while waiting for another.
3.  **No Preemption:** Resources cannot be forcibly taken away.
4.  **Circular Wait:** A closed chain of processes exists where each waits for the next.

**D16 — Hard: Explain eventual consistency. How do Cassandra handle read-after-write consistency?**
Eventual consistency guarantees that if no new updates are made, all accesses to a data item will eventually return the last updated value.
**Cassandra:** Uses **Tunable Consistency**. You can specify the number of nodes that must acknowledge a read/write. To achieve read-after-write consistency (Strong Consistency), you ensure that $R + W > N$ (where $R$ is read quorum, $W$ is write quorum, and $N$ is replication factor).

**D17 — Hard: What is mTLS? Explain the handshake and where it is used.**
mTLS (Mutual TLS) is where both the client and server authenticate each other using certificates.
**Handshake:**
1.  Server sends its certificate $\rightarrow$ Client verifies it.
2.  Server requests the Client's certificate.
3.  Client sends its certificate $\rightarrow$ Server verifies it.
4.  Both agree on a symmetric session key.
**Usage:** Commonly used in **Service Meshes** (e.g., Istio) to secure pod-to-pod communication.

**D18 — Hard: Explain how a hash table works internally. Collision resolution? Time complexity?**
A hash table uses a hash function to map keys to indices in an array.
**Collision Resolution:**
*   **Chaining:** Each array index points to a linked list of all entries that hashed to that index.
*   **Open Addressing:** If a collision occurs, the system searches for the next empty slot (Linear Probing).
**Complexity:**
*   **Average:** $O(1)$ for insertion, lookup, and deletion.
*   **Worst Case:** $O(n)$ (when all keys hash to the same index).

**D19 — Hard: What is a circuit breaker pattern? Explain the three states and its relation to retries.**
It prevents a system from repeatedly trying to call a failing service, which avoids cascading failures.
*   **Closed:** Normal operation; requests pass through.
*   **Open:** Failure threshold reached; requests fail immediately without calling the service.
*   **Half-Open:** After a timeout, a few requests are let through to see if the service has recovered.
**Relation:** While retries attempt to fix transient errors, the circuit breaker stops retries from overwhelming a dying service. **Exponential backoff** is used during retries to space out requests.

**D20 — Hard: Difference between optimistic and pessimistic concurrency control? Give examples.**
*   **Pessimistic:** Locks the record immediately to prevent others from modifying it. Use for high-contention data. (Example: `SELECT ... FOR UPDATE` in SQL).
*   **Optimistic:** Allows modifications but checks if the record was changed by someone else before committing. Use for low-contention data. (Example: Using a `version` column; `UPDATE ... WHERE version = 5`).
