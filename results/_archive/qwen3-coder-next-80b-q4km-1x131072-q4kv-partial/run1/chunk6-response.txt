## **JavaScript / TypeScript (20 questions)**

**JS1 — Easy:**  
- `var`: Function-scoped, hoisted (initialized as `undefined`), can be redeclared.  
- `let`: Block-scoped, hoisted but not initialized (TDZ), cannot be redeclared.  
- `const`: Block-scoped, must be initialized at declaration, cannot be reassigned (but object properties can change).  
- **Hoisting**: Declaration (not initialization) is moved to top of scope during compilation. `var` and `function` declarations are hoisted; `let`/`const` are hoisted but in TDZ until declared.

**JS2 — Easy:**  
- **Event loop**: Continuously checks call stack and task queues, executing code when stack is empty.  
- **Call stack**: Tracks function calls (LIFO).  
- **Microtask queue**: Higher priority; processed after each macrotask. Includes `Promise.then`, `queueMicrotask`, `MutationObserver`.  
- **Macrotask queue**: Lower priority; includes `setTimeout`, `setInterval`, I/O callbacks.  
- Order: Execute macrotask → process *all* microtasks → render → next macrotask.

**JS3 — Medium:**  
- **Closure**: Function + its lexical environment (variables from enclosing scope).  
  ```js
  function makeCounter() {
    let count = 0;
    return () => ++count;
  }
  const counter = makeCounter();
  counter(); // 1, 2, ...
  ```
- **Classic bug**:  
  ```js
  for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 0); // Logs 3,3,3
  }
  ```
  Fix: Use `let` (block-scoped), or wrap in IIFE, or pass `i` as arg.

**JS4 — Medium:**  
- **Promise**: Represents async operation (pending → fulfilled/rejected).  
- **async/await**: Syntactic sugar over promises. `async` returns a promise; `await` pauses until resolved.  
- **Error handling**:  
  - Promises: `.catch()` or second arg to `.then()`.  
  - `async/await`: `try/catch`.  
- **`Promise.all`**: Rejects on *first* rejection.  
- **`Promise.allSettled`**: Waits for *all* to settle (returns array of `{status, value/reason}`).

**JS5 — Medium:**  
- **`interface`**: Extensible (declaration merging), only describes object shapes, supports `implements`.  
- **`type`**: Can union/intersect, represent primitives/tuples/literals, *cannot* be merged.  
- **Use `interface`** for object shapes (especially public APIs); **`type`** for unions, primitives, mapped types.  
- **Discriminated unions**: Union of objects with a common `discriminant` property (e.g., `kind: 'A' | 'B'`). Enables type narrowing.

**JS6 — Medium:**  
- **Prototypal inheritance**: Objects inherit directly from other objects (no classes).  
- `Object.create(proto)`: Creates new object with `proto` as its `__proto__`.  
- **ES6 classes**: Syntactic sugar over prototypes. `class Foo { ... }` defines constructor + methods on `Foo.prototype`. `extends` sets `Sub.prototype.__proto__ = Super.prototype`.

**JS7 — Hard:**  
- **`this`**: Dynamic binding based on *how* function is called.  
- **Binding rules (priority)**:  
  1. `new` (binds to new object)  
  2. Explicit (`call`, `apply`, `bind`)  
  3. Context (`obj.method()`)  
  4. Default (global/window or `undefined` in strict mode)  
- `bind()` returns a *new* function with `this` permanently set. **Cannot re-bind** (per spec, `bind` returns a non-constructable/non-callable internal [[BoundTargetFunction]]).

**JS8 — Hard:**  
- **`WeakRef`**: Holds weak reference to object (doesn’t prevent GC). `deref()` returns target or `undefined`.  
- **`FinalizationRegistry`**: Register cleanup callback when object is GC’d.  
- **Use cases**: Caches, memoization, avoiding memory leaks in long-lived objects.  
- **`WeakMap` keys must be objects**: Allows GC to collect keys when no other refs exist. If keys were primitives, GC couldn’t track them reliably.

**JS9 — Hard:**  
- **V8 optimizations**:  
  - **Hidden classes**: Objects with same shape share hidden class (fast property access).  
  - **Inline caching (IC)**: Caches type info for property accesses (monomorphic → polymorphic → megamorphic).  
  - **Deoptimization**: When assumptions violated (e.g., changing object shape), compiled code deopts to interpreter.  
- **Patterns causing deoptimization**:  
  - Adding/deleting properties after creation  
  - Using non-numeric indices on arrays  
  - Mixing types in arrays/objects  
  - `eval`, `with`, `arguments.callee`

**JS10 — Medium:**  
- **Tree-shaking**: Dead code elimination (removes unused exports).  
- **ES modules**: Static structure → static analysis possible → tree-shakeable.  
- **CommonJS**: Dynamic `require()` → runtime resolution → impossible to statically analyze → not tree-shakeable (bundlers like Webpack can’t reliably remove unused exports).

**JS11 — Easy:**  
- **`null`**: Intentional absence of value.  
- **`undefined`**: Uninitialized/missing value.  
- `null == undefined` → `true`; `null === undefined` → `false`.  
- **Nullish coalescing (`??`)**: Returns RHS if LHS is `null` or `undefined`.  
- **Optional chaining (`?.`)**: Safely access nested properties: `obj?.a?.b`.

**JS12 — Easy:**  
- **`map(fn)`**: Transforms each element → new array.  
- **`filter(fn)`**: Keeps elements where `fn` is truthy.  
- **`reduce(fn, init)`**: Accumulates array into single value. `init` sets initial accumulator; without it, first element is initial accumulator (may cause issues if array empty).  
- **`flatMap(fn)`**: `map` + `flat(1)`. Useful for transforming + flattening nested arrays (e.g., mapping each item to an array).

**JS13 — Easy:**  
- **Template literals**: Backtick-quoted strings with interpolation: `` `Hello ${name}` ``.  
- **Tagged templates**: Function called with template literal parts:  
  ```js
  function htmlEscape(strings, ...values) {
    return strings.reduce((result, str, i) => 
      result + str + (values[i] ?? '').replace(/[&<>"']/g, c => `&#${c.charCodeAt(0)};`), '');
  }
  const safe = htmlEscape`<div>${userInput}</div>`;
  ```

**JS14 — Easy:**  
- **Destructuring**: Extract values from arrays/objects into variables.  
  - Object: `const { a, b: c } = obj;` (renaming `b` → `c`)  
  - Array: `const [x, , z] = arr;`  
  - Defaults: `const { a = 1 } = obj;`  
  - Rest: `const { a, ...rest } = obj;`  
- **Rest operator (`...`)**: Collects remaining elements (in destructuring or function params).

**JS15 — Easy:**  
- **`for...in`**: Iterates over *enumerable* **property keys** (including prototype chain).  
- **`for...of`**: Iterates over *iterable* **values** (e.g., arrays, strings, Maps).  
- **Avoid `for...in` on arrays**: Iterates over keys (strings), includes prototype properties, order not guaranteed.

**JS16 — Medium:**  
- **Generics**: Type parameters (`<T>`) for reusable components.  
  ```ts
  function identity<T>(x: T): T { return x; }
  ```
- **Constraints (`extends`)**: Restrict type parameter:  
  ```ts
  function loggingIdentity<T extends { length: number }>(x: T): T { ... }
  ```
- **Conditional types**:  
  ```ts
  type IsString<T> = T extends string ? true : false;
  ```
- **`infer`**: Extract type in conditional:  
  ```ts
  type First<T extends any[]> = T extends [infer F, ...any[]] ? F : never;
  ```

**JS17 — Medium:**  
- **CommonJS**: `require()`/`module.exports` (synchronous, Node.js default pre-ESM).  
- **ES Modules**: `import`/`export` (static, async, supports tree-shaking).  
- **Node.js**: Supports both via `type` field in `package.json`:  
  - `"type": "module"` → `.js` = ESM  
  - `"type": "commonjs"` or missing → `.js` = CJS  
  - `.cjs` = always CJS; `.mjs` = always ESM.

**JS18 — Hard:**  
- **Structural type system**: Types compared by structure, not names.  
- **Excess property checks**: Only for *object literals* assigned directly to typed variables (prevents typos):  
  ```ts
  interface Person { name: string; }
  const p: Person = { name: "A", age: 30 }; // Error: 'age' not in Person
  ```
- **`extends` vs `satisfies`**:  
  - `extends`: Type constraint (e.g., `T extends U`).  
  - `satisfies`: Runtime assertion + compile-time refinement (keeps original type for inference):  
    ```ts
    const config = { a: 1 } satisfies { a: number; b?: number };
    // config inferred as { a: number }
    ```
- **Variance (`in`, `out`)**: TypeScript 4.7+ supports `in` (contravariant) and `out` (covariant) in mapped types for generics (e.g., `type ReadOnly<T> = out { readonly [K in keyof T]: T[K] }`).

**JS19 — Hard:**  
- **`Proxy`**: Intercepts operations on objects (get, set, apply, etc.).  
- **`Reflect`**: Reflective operations (e.g., `Reflect.get`, `Reflect.set`) that mirror Proxy traps.  
- **Example (validation)**:  
  ```ts
  const validator = {
    set(target, prop, value) {
      if (prop === 'age' && typeof value !== 'number') {
        throw new TypeError('Age must be a number');
      }
      return Reflect.set(target, prop, value);
    }
  };
  const person = new Proxy({}, validator);
  person.age = 30; // OK
  person.age = 'thirty'; // Throws
  ```

**JS20 — Hard:**  
- **`SharedArrayBuffer`**: Shared memory buffer (used across workers).  
- **`Atomics`**: Atomic operations (e.g., `Atomics.add`, `Atomics.compareExchange`) to prevent race conditions.  
- **Web Workers**: Communicate via `postMessage`; with `SharedArrayBuffer`, use `Atomics.wait()`/`notify()` for synchronization:  
  ```ts
  // Worker 1
  Atomics.wait(sharedArray, 0, 0); // Wait until value at index 0 is changed
  // Worker 2
  Atomics.store(sharedArray, 0, 1);
  Atomics.notify(sharedArray, 0, 1); // Wake one waiter
  ```
- **Ordering**: `Atomics` operations are sequentially consistent; `wait`/`notify` provide low-level signaling.

## **Bash (20 questions)**

**B1 — Easy:**  
- `$@`: Each argument as separate word (preserves spaces).  
- `$*`: All arguments as single word (joined by first char of `$IFS`, usually space).  
- `"$@"` → `"arg1" "arg2"` (safe).  
- `"$*"` → `"arg1 arg2"` (unsafe for spaces).

**B2 — Easy:**  
- `set -euo pipefail`:  
  - `-e`: Exit on error (`set -e`).  
  - `-u`: Error on undefined variables (`set -u`).  
  - `-o pipefail`: Pipeline fails if *any* command fails (not just last).  
  Improves robustness.

**B3 — Medium:**  
- `$(command)` and `` `command` ``: Command substitution (same). `$(...)` is preferred (nestable, clearer).  
- `$((expression))`: Arithmetic expansion (e.g., `$((2+3))`).  
- `expr`: External command for arithmetic (slower, e.g., `expr 2 + 3`).

**B4 — Medium:**  
- **Process substitution**: `<(command)` creates a temp file descriptor (e.g., `/dev/fd/63`).  
- **Use case**: Compare outputs without temp files:  
  ```bash
  diff <(sort file1) <(sort file2)
  ```

**B5 — Medium:**  
- **Safe iteration**:  
  ```bash
  while IFS= read -r -d '' file; do
    echo "$file"
  done < <(find . -print0)
  ```
- **Why `for f in $(ls)` is dangerous**:  
  - Splits on `$IFS` (spaces/newlines)  
  - Expands glob patterns  
  - Fails on special filenames.

**B6 — Medium:**  
- **Here document (`<<EOF`)**: Multi-line input to command.  
- **Here string (`<<<`)**: Single-line string input.  
- `<<-EOF`: Strips leading *tabs* (not spaces) from lines.

**B7 — Hard:**  
- `cmd > file 2>&1`: Redirect stdout → file, then stderr → stdout (both to file).  
- `cmd 2>&1 > file`: Redirect stderr → stdout (still terminal), *then* stdout → file (stderr lost).  
- `cmd &> file`: Bash shorthand for `> file 2>&1` (both to file).  
- **Key**: Order matters for redirections.

**B8 — Hard:**  
- **Safe lock file with `mkdir`**:  
  ```bash
  lockdir=/tmp/mylock
  if mkdir "$lockdir"; then
    trap 'rmdir "$lockdir"' EXIT
    # critical section
  else
    echo "Lock held" >&2
    exit 1
  fi
  ```
- **Why `mkdir`?**: Atomic (no race condition); file creation (`touch`) is not atomic.

**B9 — Easy:**  
- `'...'`: No expansion (literal).  
- `"..."`: Expands variables/commands (`$var`, `$(cmd)`).  
- No quotes: Word splitting + glob expansion.  
- **Example**:  
  ```bash
  var="a b"
  echo '$var'   # $var
  echo "$var"   # a b
  echo $var     # a b (but splits into two args)
  ```

**B10 — Easy:**  
- **Tests**:  
  - `-e file`: exists  
  - `-d file`: directory  
  - `-r file`: readable  
- **`[ ]` vs `[[ ]]`**:  
  - `[ ]` (POSIX `test`): Basic, requires quoting, no regex.  
  - `[[ ]]` (bash): Safer (no word splitting/globbing), supports regex (`=~`), pattern matching (`==`).

**B11 — Easy:**  
- `$?`: Exit status of last command.  
- `$$`: PID of current shell.  
- `$!`: PID of last background job.  
- `$#`: Number of positional parameters.  
- **Use cases**: Check success (`if [ $? -ne 0 ]`), log PID, wait for background job (`wait $!`), validate args.

**B12 — Easy:**  
- **Define**: `foo() { ... }` or `function foo { ... }` (same).  
- **Return values**: Use `return` (exit code, 0–255) or `echo` (output for capture).  
- **Capture output**: `result=$(foo)`.

**B13 — Easy:**  
- **`PATH`**: Colon-separated list of directories to search for commands.  
- **Resolution**: Checks `PATH` in order; builtins checked first.  
- **Builtin vs external**:  
  - Builtin: Part of shell (e.g., `cd`, `echo`).  
  - External: Separate executable (e.g., `/bin/ls`).  
- **Check**: `type cd` → builtin; `type ls` → `/bin/ls`.

**B14 — Medium:**  
- **`trap`**: Run command on signal.  
  ```bash
  trap 'cleanup' EXIT INT TERM
  ```
- **Execution order**: Traps run *after* command completes; multiple signals queue (but `SIGKILL`/`SIGSTOP` can’t be trapped).  
- **`ERR`**: Runs on non-zero exit (if `set -e` off).

**B15 — Medium:**  
- **`xargs` vs command substitution**:  
  - `xargs`: Builds args from stdin (avoids arg list overflow).  
  - `$()`: Substitution may overflow args.  
- **Handle spaces**: `find . -print0 | xargs -0 rm`.  
- **`xargs -P`**: Parallel execution (e.g., `-P4` for 4 jobs).

**B16 — Medium:**  
- **Indexed arrays**:  
  ```bash
  arr=(a b c)
  arr+=("d")
  echo "${#arr[@]}"  # length
  for x in "${arr[@]}"; do ...; done
  ```
- **Associative arrays**:  
  ```bash
  declare -A map
  map[key]=value
  for k in "${!map[@]}"; do ...; done
  ```
- **Key difference**: Associative arrays use strings as keys; indexed use integers.

**B17 — Hard:**  
- **Subshell `(...)`**: New process; changes to variables/`cd` lost.  
- **Group `{ ...; }`**: Same process; changes persist.  
- **Piping into `while`**: Creates subshell → variable changes lost:  
  ```bash
  echo "a" | while read x; do count=$((count+1)); done
  echo $count  # 0 (unchanged)
  ```
  Fix: Use process substitution or redirect from file.

**B18 — Hard:**  
- **Signals**:  
  - `SIGINT` (Ctrl+C), `SIGTERM` (graceful kill), `SIGHUP` (terminal hangup), `SIGKILL` (force kill, uncatchable).  
- **Graceful shutdown**:  
  ```bash
  cleanup() { kill $bg_pid 2>/dev/null; rm -f /tmp/lock; }
  trap cleanup EXIT INT TERM
  sleep 100 & bg_pid=$!
  wait
  ```

**B19 — Hard:**  
- **Parallel log processing**:  
  ```bash
  split -l 10000 large.log chunk_
  for chunk in chunk_*; do
    (process "$chunk" > "$chunk.out") &
  done
  wait
  cat chunk_*.out > results.log
  ```
- **Trade-offs**: I/O contention, disk space, error propagation (check exit codes per job).  
- **Error handling**: Use `|| exit 1` in subshells or track exit codes.

**B20 — Hard:**  
- **`exec`**: Replaces current process (no fork).  
- **FD manipulation**:  
  ```bash
  exec 3>file      # Open FD 3 for writing
  exec 3>&-        # Close FD 3
  exec 3<file      # Read from FD 3
  ```
- **Coprocess**: Two-way pipe:  
  ```bash
  coproc cat
  echo "data" >&${COPROC[1]}
  read line <&${COPROC[0]}
  ```
  Use for interactive protocols (e.g., FTP, SMTP).

## **PowerShell (20 questions)**

**PS1 — Easy:**  
- **`Write-Output`**: Sends to pipeline (can be captured/redirected).  
- **`Write-Host`**: Writes directly to console (bypasses pipeline).  
- **Why it matters**: `Write-Host` output is lost in pipelines; `Write-Output` preserves data flow.

**PS2 — Easy:**  
- **Pipeline**: Passes objects (not text) between commands.  
- **`ForEach-Object`**: Cmdlet (pipeline-aware, scriptblock).  
- **`foreach` statement**: Language keyword (immediate execution, no pipeline).  
- **Use `ForEach-Object`** for pipeline chaining; **`foreach`** for simple loops.

**PS3 — Medium:**  
- **`[PSCustomObject]`**: Strongly typed, supports properties/methods, pipeline-compatible.  
- **`[hashtable]`**: Unordered key-value pairs, no type safety.  
- **Convert**:  
  - `[PSCustomObject]@{a=1}` → object  
  - `[hashtable]$obj.PSObject.Properties | ForEach-Object { $_.Name, $_.Value }`  
  - `[PSCustomObject]@{a=1} -as [hashtable]` (not direct; use `@{}` + `.GetEnumerator()`).

**PS4 — Medium:**  
- **Terminating errors**: Stop execution (e.g., `throw`, invalid cmdlet syntax).  
- **Non-terminating**: Continue (e.g., file not found).  
- **Error handling**:  
  - `-ErrorAction Stop`: Converts non-terminating → terminating.  
  - `$ErrorActionPreference = 'Stop'`: Global setting.  
  - `try/catch`: Only catches terminating errors.

**PS5 — Medium:**  
- **Splatting**: Pass params via hashtable:  
  ```powershell
  $params = @{ Path = 'C:\test.txt'; Force = $true }
  Remove-Item @params
  ```
- **Difference**: Splatting expands hashtable into params; passing hashtable as single param passes the object itself.

**PS6 — Medium:**  
- **Remoting**:  
  - `Invoke-Command -ComputerName`: One-off remote command.  
  - `Enter-PSSession`: Interactive session (interactive shell).  
- **Protocol**: WinRM (HTTP/HTTPS) or SSH (in PowerShell 7+).  
- **WinRM**: Windows Remote Management (SOAP-based).

**PS7 — Hard:**  
- **Unexpected result**:  
  ```powershell
  function Get-Items {
      $result = @()
      $result += "one"
      return $result
  }
  $x = Get-Items
  $x.GetType().Name  # String (not ArrayList!)
  ```
  **Why**: PowerShell unrolls single-element arrays.  
- **Empty return**: `$x` is `$null`.  
- **Correct pattern**:  
  ```powershell
  return , $result  # Unary comma forces array
  # or
  [array]$result += "one"
  ```

**PS8 — Hard:**  
- **`[scriptblock]`**: Executable code block (e.g., `{$x = 1}`).  
- **Function**: Named, reusable scriptblock with metadata.  
- **Remote scriptblock**:  
  ```powershell
  Invoke-Command -ComputerName "srv" -ScriptBlock { $using:x }
  ```
- **Double-hop problem**: Credentials don’t delegate to second hop (e.g., local → server → file share).  
  **Solutions**: CredSSP (enable-credssp), Kerberos delegation, or `-ArgumentList`.

**PS9 — Easy:**  
- **`@()`**: Array subexpression (ensures array, even if single item).  
- **`[array]`**: Type accelerator for `System.Array`.  
- **Force single into array**: `@($single)`.  
- **Indexing**:  
  - `$null[0]` → `$null`  
  - `@()[0]` → `$null`  
  - Both safe (no exception).

**PS10 — Easy:**  
- **Comparison operators**:  
  - `-eq`, `-ne`: Equal/not equal  
  - `-like`, `-match`: Pattern match (`-like` uses `*`, `-match` uses regex)  
  - `-contains`, `-in`: Collection membership (`-contains` in pipeline; `-in` for RHS)  
- **Case-sensitive**: `-ceq`, `-clike`, etc. (default is case-*insensitive*).  
- **`-contains` vs `-in`**:  
  - `$arr -contains "x"`  
  - `"x" -in $arr`

**PS11 — Easy:**  
- **Module**: Package of cmdlets/functions.  
  - **Script module (`.psm1`)**: Contains PowerShell code.  
  - **Manifest module (`.psd1`)**: Metadata (version, dependencies).  
  - **Binary module**: Compiled .NET assembly (`.dll`).  
- **`Import-Module`**: Loads module into session (adds cmdlets to scope).

**PS12 — Easy:**  
- **String interpolation**: `"Hello $name"` (variables/expressions in `"`).  
- **Single quotes**: Literal (`'Hello $name'`).  
- **Expressions**: `"Result: $(2+3)"`.  
- **Here-string**:  
  ```powershell
  @"
  Line 1
  Line 2
  "@
  ```

**PS13 — Easy:**  
- **`Get-Member`**: Shows object members (properties/methods).  
- **Properties**: Data fields; **Methods**: Functions; **NoteProperties**: Custom properties added (e.g., `Select-Object`).  
- **`Select-Object`**: Project properties (like `SELECT` in SQL).  
- **`Where-Object`**: Filter objects (like `WHERE`).

**PS14 — Medium:**  
- **PowerShell classes**:  
  ```powershell
  class Person {
      [string]$Name
      Person([string]$n) { $this.Name = $n }
  }
  ```
- **Differences from C#**: No interfaces, no inheritance (except `class : base`), no overloading, no static methods (in v5–7).  
- **Use classes** for complex data models; **functions** for procedural logic.

**PS15 — Medium:**  
- **`CmdletBinding`**: Enables advanced function features (parameter validation, pipeline support).  
- **Key attributes**:  
  - `SupportsShouldProcess`: Enables `-WhatIf`/`-Confirm`.  
  - `DefaultParameterSetName`: Default param set.  
  - `ValueFromPipeline`: Accepts pipeline input.  
- **Blocks**:  
  - `Begin`: Run once (init)  
  - `Process`: Per pipeline object  
  - `End`: Run once (cleanup)

**PS16 — Medium:**  
- **Providers**: Abstract data stores (e.g., FileSystem, Registry, Certificate).  
- **`Get-ChildItem`**: Works across providers (e.g., `Get-ChildItem HKLM:\SOFTWARE`).  
- **Registry access**: Treat as paths: `HKLM:\SOFTWARE\Microsoft`.

**PS17 — Hard:**  
- **Runspaces**: Lightweight threads for parallel execution.  
  - `[runspace]`: Single thread.  
  - `[runspacepool]`: Pool of runspaces.  
  - `[powershell]`: Host for script execution.  
- **`ForEach-Object -Parallel`**: Uses runspace pool internally (v7+).  
- **Manual vs `-Parallel`**: Manual gives more control (error handling, resource limits); `-Parallel` is simpler.

**PS18 — Hard:**  
- **PSScriptAnalyzer**: Static analysis tool (linting).  
- **Rules**: Code quality checks (e.g., `PSUseDeclaredVarsMoreThanAssignments`).  
- **Severity**: Error/warning/info.  
- **Custom rules**: Define via `ScriptAnalyzerRules.psd1`.  
- **CI/CD**: Integrate via `Invoke-ScriptAnalyzer` (e.g., in Azure DevOps/GitHub Actions).

**PS19 — Hard:**  
- **`$using:` scope**: Embeds variable *value* at compile time (serializes).  
- **`$args`/`-ArgumentList`**: Pass variables at runtime (also serialized).  
- **Serialization limits**: CLIXML depth (default 2), max object graph size. Complex objects may truncate.  
- **Best practice**: Use simple types (strings, numbers) in remoting.

**PS20 — Hard:**  
- **DSC**: Declarative config management.  
  - **Configuration**: DSL script defining desired state.  
  - **Resources**: Modules (e.g., `File`, `Registry`).  
  - **LCM**: Local Configuration Manager (applies config).  
- **Windows vs PowerShell 7+**:  
  - Windows: Uses WMI/WinRM, full DSC.  
  - PowerShell 7+: Limited DSC (no LCM), replaced by **Desired State Configuration (DSC) for Linux/Unix** and **Infrastructure-as-Code (IaC)** tools (e.g., Ansible, Terraform).  
- **Modern replacement**: Azure Policy, Terraform, Ansible.
