**Networking Answers**

N1 — A Layer 2 switch operates at the Data Link Layer (Layer 2) and forwards frames based on MAC addresses within the same broadcast domain. A Layer 3 switch operates at the Network Layer (Layer 3) and can route packets between different IP subnets, performing routing functions similar to a traditional router, but often with higher throughput due to specialized hardware.

N2 — IP: 10.0.5.37/20.
The subnet mask for /20 is 255.255.240.0.
Network Address: 10.0.4.0
Broadcast Address: 10.0.15.255

N3 — The TCP three-way handshake establishes a connection:
1. **SYN (Synchronize):** Client sends a SYN packet to the server, proposing an initial sequence number (ISN).
2. **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and replies with a SYN packet (proposing its own ISN) and an ACK acknowledging the client's SYN.
3. **ACK (Acknowledge):** Client receives SYN-ACK and sends a final ACK back to the server, confirming receipt.
If the final ACK is lost, the client will retransmit the ACK (or the server will time out and retransmit the SYN-ACK), leading to connection timeouts or retransmissions until the connection is established or fails.

N4 — **SNAT (Source Network Address Translation):** Changes the source IP address of a packet as it leaves a private network, typically to allow multiple internal hosts to share one public IP when accessing the internet. *Example: An internal host (10.0.0.5) accessing Google uses the router's public IP (203.0.113.10) as its source.*
**DNAT (Destination Network Address Translation):** Changes the destination IP address of a packet as it enters a private network, typically to direct external traffic to a specific internal server. *Example: An external user accessing a web server at the public IP (203.0.113.10) is redirected by the router to the internal web server (10.0.0.5).*

N5 — 3 possible causes:
1. **Hostname Mismatch:** The certificate was issued for a different domain name than the one being accessed (e.g., certificate for `dev.example.com` accessed via `example.com`).
2. **Expired Certificate:** The certificate has passed its validity date.
3. **Incorrect Configuration:** The server is presenting the wrong certificate file or the certificate chain is incomplete/broken.

N6 — **VLAN (Virtual Local Area Network):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains on the same physical switch infrastructure, using 802.1Q tagging.
**VxLAN (Virtual Extensible LAN):** A network virtualization overlay technology that encapsulates Layer 2 Ethernet frames within Layer 3 UDP packets.
You choose VxLAN over VLAN when you need to scale beyond the 4094 VLAN limit, or when you need to extend Layer 2 domains across a large, multi-subnet, or geographically dispersed IP network (i.e., bridging L2 across L3 boundaries).

N7 — This is likely due to the host's routing table preferring the default gateway (10.0.0.1) for all traffic, even if the destination is reachable via eth1. The kernel routes based on the longest prefix match.
**Fix using Policy-Based Routing (PBR):** You must create a routing policy that specifically dictates that traffic originating from the 192.168.1.0/24 subnet must use the eth1 interface (or its associated gateway) for egress, overriding the default route. This is typically done using `ip rule` and `ip route` commands.

N8 — BGP path selection is a complex process where routers evaluate multiple attributes to determine the "best" path to a destination prefix. The process is sequential; the first attribute that provides a definitive preference is used.
5 attributes in order of preference (simplified):
1. **Weight** (Cisco proprietary, highest preference)
2. **Local Preference** (Highest is preferred within an AS)
3. **AS Path Length** (Shortest path is preferred)
4. **Origin Type** (IGP > EGP > Incomplete)
5. **MED (Multi-Exit Discriminator)** (Lowest is preferred by the receiving AS)

N9 — When running VxLAN over IPsec, the encapsulation adds significant overhead:
1. Original Ethernet Frame (14 bytes header)
2. VxLAN Header (50 bytes)
3. UDP Header (8 bytes)
4. IP Header (20 bytes)
5. IPsec Overhead (ESP/AH headers + padding, typically 30-50 bytes)
The total overhead is substantial. If the physical MTU is 1500 bytes, the maximum inner payload must account for all these headers.
*Calculation:* Max Inner Payload = Physical MTU - Total Overhead
Max Inner Payload $\approx 1500 - (14 + 50 + 8 + 20 + 40) = 1368$ bytes.

N10 — **ARP (Address Resolution Protocol):** Maps a known Layer 3 IP address to its corresponding Layer 2 MAC address within a local subnet. It works by broadcasting an ARP request asking, "Who has this IP? Tell me your MAC."
**Gratuitous ARP:** A host sends an ARP reply to its own IP address (a broadcast). It solves problems like stale ARP caches on other devices, ensuring that if a host changes its MAC address or moves to a new port, the network quickly updates its mapping without waiting for a device to initiate communication.

N11 — **Public IP Address:** Globally unique address routable across the public internet.
**Private IP Address:** Non-globally unique addresses reserved for use within private networks (LANs) and are not routable on the public internet without NAT.
RFC 1918 Private IPv4 Ranges:
1. 10.0.0.0/8
2. 172.16.0.0/12
3. 192.168.0.0/16

N12 — **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses.
**A Record:** Maps a hostname to an IPv4 address (e.g., `www.example.com` $\rightarrow$ 192.0.2.1).
**CNAME Record:** Creates an alias, mapping one hostname to another canonical hostname (e.g., `blog.example.com` $\rightarrow$ `servers.example.com`).
**AAAA Record:** Maps a hostname to an IPv6 address.

N13 — **DHCP (Dynamic Host Configuration Protocol):** A network management protocol used to automatically assign IP addresses and other network configuration parameters (subnet mask, gateway, DNS servers) to devices on a network.
**DORA Process:**
1. **Discover:** Client broadcasts a DHCP Discover message to find available servers.
2. **Offer:** Server responds with a DHCP Offer, proposing an IP address configuration.
3. **Request:** Client broadcasts a DHCP Request, formally accepting the offered configuration.
4. **Acknowledge:** Server sends a DHCP ACK, finalizing the lease and configuration details.

N14 — **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming electrical signals out of every other port, creating one large collision domain.
**Switch:** Operates at Layer 2 (Data Link). It learns MAC addresses and forwards frames only to the intended destination port, segmenting collision domains.
**Router:** Operates at Layer 3 (Network). It forwards packets between different IP networks based on IP addresses, defining network boundaries.

N15 — **Half-Duplex:** Allows data transmission in both directions, but only one direction at a time (e.g., a walkie-talkie). Collisions can occur.
**Full-Duplex:** Allows simultaneous data transmission and reception over the same link. Collisions are eliminated.
Modern Ethernet links overwhelmingly use **full-duplex** communication.

N16 — **TTL (Time To Live):** A field in the IP header that specifies the maximum number of hops (routers) a packet can traverse before being discarded. This prevents packets from circulating indefinitely in routing loops.
**Traceroute Exploitation:** Traceroute works by sending a sequence of packets (usually UDP or ICMP) with incrementally increasing TTL values (starting at 1). When the packet reaches the first router, the TTL expires, and the router sends back an ICMP "Time Exceeded" message, revealing the router's IP address. This process repeats until the destination is reached.

N17 — **NAT Gateway:** A device (usually a router or firewall) that translates private, internal IP addresses into one or more public IP addresses when traffic crosses the boundary between a private network and the public internet.
**Static NAT:** A one-to-one, permanent mapping where a specific private IP is always translated to a specific public IP (e.g., Server A $\rightarrow$ Public IP X). Used for servers that need to be consistently reachable from the outside.
**Dynamic NAT:** Maps private IPs to a pool of available public IPs on a first-come, first-served basis.
**PAT (Port Address Translation) / NAT Overload:** Maps multiple private IPs to a single public IP by tracking unique source port numbers for each internal connection. This allows thousands of internal hosts to share one public IP.

N18 — **ECMP (Equal-Cost Multi-Path):** A routing technique that allows a router to install multiple next-hop paths into its routing table for the same destination prefix, provided all paths have the same routing metric (cost). Traffic is distributed across these paths.
**Hashing Strategies:** Common strategies include hashing based on the source IP, destination IP, source port, and destination port.
**Asymmetric Flow Problem:** If stateful firewalls are involved, asymmetric routing occurs when the request packet takes one path (e.g., Path A) and the return/response packet takes a different path (e.g., Path B). The firewall on Path A will not have a corresponding state entry for the return traffic arriving on Path B, causing the connection to be dropped.

N19 — The problem is **Bandwidth-Delay Product (BDP) limitation**. BDP = Bandwidth $\times$ Round Trip Time (RTT). If the BDP is 10MB, the TCP sender needs a window large enough to fill that pipe. If the TCP window size is capped at 64KB, the sender cannot transmit enough data to keep the high-latency link saturated, leading to the connection waiting for acknowledgments (high latency) even if no packets are dropped.
**TCP Window Scaling (RFC 1323):** This extension allows the TCP header to negotiate a window size much larger than the standard 16-bit limit (65,535 bytes). By scaling the window size, the sender can advertise a much larger receive window, allowing the pipe to be filled and maximizing throughput over high-BDP links.

N20 — **802.1Q Trunk Ports:** A mechanism used on switches to allow traffic from multiple VLANs to traverse a single physical link (trunk). It achieves this by inserting a 4-byte tag (the VLAN tag) into the Ethernet frame header.
**Linux Configuration (Sub-interfaces):** On the physical interface (e.g., `eth0`), you create virtual sub-interfaces, one for each VLAN ID:
`eth0.10` (for VLAN 10), `eth0.20` (for VLAN 20), `eth0.30` (for VLAN 30).
Each sub-interface is configured with the appropriate IP address for its respective VLAN.
**Frame Format:** The frame on the wire will contain the standard Ethernet header, followed by the 802.1Q tag (which specifies the VLAN ID), followed by the original Layer 2 payload.

**Linux Answers**

L1 — **Hard Link:** A directory entry that points directly to the same inode (the data structure containing file metadata) as the original file. Deleting the original name does not delete the data until the last hard link is removed. They share the same data blocks.
**Symbolic Link (Symlink):** A special file that contains a text path pointing to another file or directory. It is a pointer, not a pointer to the data itself. If the target file is moved or deleted, the symlink breaks (dangling link).

L2 — `find /var/log -type f -size +100M`

L3 — State D (Uninterruptible Sleep) means the process is waiting for an I/O operation (like disk read/write) to complete, and it cannot be interrupted by signals (including `SIGKILL`). This usually indicates a kernel-level block or driver issue. You generally *cannot* kill it with `kill -9` because the kernel is actively managing the I/O operation, and forcing termination could lead to data corruption.

L4 — **cgroups v1:** Used a hierarchical, resource-specific model where controllers (CPU, Memory, I/O) were managed somewhat independently. It was complex and often led to resource contention issues.
**cgroups v2:** Implements a unified hierarchy and a unified control plane. It enforces stricter resource isolation and provides a more coherent view of resource usage across all controllers.
Systemd prefers **cgroups v2** because it offers a cleaner, more robust, and unified resource management model, which aligns better with systemd's goal of managing the entire system lifecycle coherently.

L5 — **iptables:** The older, traditional Linux firewall framework. It operates by chaining rules (INPUT, OUTPUT, FORWARD) and uses tables (filter, nat, mangle).
**nftables:** The modern replacement for iptables. It is a unified framework that combines the functionality of iptables, ip6tables, arptables, etc., into a single, more flexible, and efficient syntax.
The kernel handles both by maintaining compatibility layers. When `iptables` rules are loaded, they are translated and managed internally by the kernel's networking stack, which is increasingly migrating its core logic to the `nftables` framework.

L6 — The most likely cause is **inode usage**. `df -h` reports disk space usage based on the number of inodes (metadata structures) used by files. `du -sh` reports the total *data* size. If a filesystem contains millions of tiny files (e.g., session files, cache entries), it can exhaust the available inodes even if the total data size is small.

L7 — **UEFI Firmware:** Initializes hardware and locates the bootloader.
**Bootloader (e.g., GRUB):** Reads configuration, locates the Linux kernel image, and loads it into memory.
**Kernel:** Initializes core OS components, detects hardware, and mounts the initial root filesystem.
**Initramfs (Initial RAM Filesystem):** A small, temporary root filesystem loaded into memory. It contains necessary drivers and scripts to mount the *real* root filesystem (which might be on a complex partition or LVM setup).
**Root Filesystem:** The kernel mounts the actual root partition defined in the boot configuration.
**Systemd:** The `init` process starts. Systemd takes over, reads its configuration, and executes services sequentially, eventually reaching the target state (e.g., `multi-user.target` or `graphical.target`) to bring the system to a fully running state.

L8 — The OOM killer fires when the kernel determines that the system is critically low on *usable* memory, not just total free memory. Even with 15GB in `buff/cache`, this memory is reclaimable. If processes are actively demanding memory, and the available memory (which includes reclaimable cache) is insufficient to satisfy the immediate demands of running processes, the OOM killer targets processes to free up RAM.
**Kernel Tunables:** `vm.swappiness` (controls how aggressively the kernel swaps out anonymous memory) and `vm.vfs_cache_pressure` (controls how aggressively the kernel reclaims memory used for directory and inode caches).

L9 — `ip netns` is used to create and manage network namespaces. A network namespace provides an isolated view of the system resources (network interfaces, routing tables, process IDs, etc.) for a specific process or group of processes.
Container runtimes (like Docker or Kubernetes) use namespaces to achieve container isolation. Each container is typically placed into its own network namespace, giving it its own private set of network interfaces and IP addresses, completely isolated from the host's network stack.

L10 — **SIGTERM (Signal 15):** A polite request for a process to terminate. The process can catch this signal, perform cleanup (save state, close files), and exit gracefully.
**SIGKILL (Signal 9):** A forceful, immediate termination signal. The process cannot catch, ignore, or block this signal; the kernel terminates it instantly.
**SIGQUIT (Signal 3):** Requests the process to terminate and usually generates a core dump file for debugging. It can be caught by the process.

L11 — **stdin (Standard Input):** Where a program reads its input from (default: keyboard).
**stdout (Standard Output):** Where a program writes its normal, successful output to (default: terminal screen).
**stderr (Standard Error):** Where a program writes error messages and diagnostic output to (default: terminal screen).
To redirect stderr to a file while displaying stdout on the terminal: `command 2> error.log` (or `command &> /dev/tty` if you want to keep stdout on the terminal while redirecting stderr).

L12 — `chmod 755 filename` sets permissions as follows:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = Full access.
*   **5 (Group):** Read (4) + Execute (1) = Can read and run, but not modify.
*   **5 (Others):** Read (4) + Execute (1) = Can read and run, but not modify.

L13 — **Root User (UID 0):** Has absolute, unrestricted access to the entire operating system. It can read, write, modify, or delete any file, change system configurations, and manage all processes without restriction.
**Sudo Privileges:** A user with `sudo` privileges can execute specific commands as another user (usually root) by prefixing the command with `sudo`. This grants *limited* elevated access, allowing administrators to restrict which commands a user can run, providing a layer of accountability and security that the root user lacks.

L14 — **Package Manager:** A system software that automates the installation, upgrading, configuration, and removal of software packages on a Linux system.
**Debian/Ubuntu:** APT (Advanced Package Tool)
**RHEL/Fedora:** DNF (Dandified YUM)

L15 — `/etc/fstab` (File System Table) is a configuration file that defines how disk partitions, network shares (NFS/Samba), and other filesystems should be mounted automatically at boot time.
If an entry is misconfigured (e.g., incorrect UUID, wrong mount point, or invalid filesystem type), the system may fail to boot completely, halt during the mounting phase, or mount the filesystem incorrectly, leading to data inaccessibility.

L16 — **LVM (Logical Volume Manager):** A storage management abstraction layer that allows administrators to pool physical storage devices into flexible volumes, independent of the underlying hardware layout.
**Physical Volumes (PV):** The actual physical storage devices (hard drives, partitions) that are designated to be used by LVM.
**Volume Groups (VG):** A pool of one or more PVs, aggregating their total storage capacity into a single logical pool.
**Logical Volumes (LV):** The usable, flexible partitions carved out of a VG.
**Extending an LV:** On a running system, you first extend the underlying PV/VG (e.g., by adding a new disk or resizing an existing one), then use `lvextend` to increase the size of the LV within the VG, and finally use `resize2fs` (or equivalent) to expand the filesystem to utilize the new space.

L17 — The I/O scheduler manages how the kernel queues and schedules read/write requests to block devices to optimize disk throughput and latency.
**mq-deadline:** Prioritizes requests based on deadlines, aiming to prevent starvation of requests waiting too long. Good for mixed workloads.
**bfq (Budget Fair Queueing):** Designed specifically for desktop/interactive workloads. It aims to provide "fairness" by giving each process a proportional share of I/O bandwidth, leading to better perceived responsiveness.
**none:** Disables the scheduler, allowing the underlying hardware or driver to manage I/O directly. Best for high-performance storage arrays or specialized hardware where the kernel scheduler adds unnecessary overhead.
**Changing Scheduler:** Use the `echo` command to write the desired scheduler name to the device's `scheduler` file: `echo bfq > /sys/block/sdX/queue/scheduler`.

L18 — **Load Average:** Measures the average number of processes in the system that are either running (in CPU time) or waiting for resources (in uninterruptible sleep, D state). It is a measure of system *demand*, not just CPU utilization.
**I/O Wait Inflation:** When processes are blocked waiting for slow disk I/O, they enter the D state. While they aren't consuming CPU cycles, they are still counted in the load average, artificially inflating the metric and suggesting the CPU is overloaded when the bottleneck is actually the disk.
**Diagnosis:**
*   **CPU Bottleneck:** High load average, high `%us` (user) and `%sy` (system) CPU usage, low `%wa`. Use `top` or `htop`.
*   **Disk Bottleneck:** High load average, high `%wa` (I/O wait) CPU usage, and slow response times reported by `iostat` or `iotop`.
*   **Network Bottleneck:** High load average, but low CPU usage, coupled with high queue lengths or errors reported by `netstat` or `ss`.

L19 — **SELinux (Security-Enhanced Linux):** Enforces Mandatory Access Control (MAC). Instead of relying solely on DAC (Discretionary Access Control, i.e., standard Linux permissions), SELinux assigns security contexts (labels) to every subject (process) and object (file, port). Access is only granted if the policy explicitly permits the transition between the subject's context and the object's context.
**Modes:**
*   **Enforcing:** SELinux actively denies access based on policy violations.
*   **Permissive:** SELinux logs all policy violations but does *not* deny access, allowing administrators to see what *would* have been blocked.
*   **Disabled:** SELinux is completely inactive.
**Troubleshooting:** Check the audit logs (`/var/log/audit/audit.log`). If a daemon fails to bind a port, check the logs for AVC (Access Vector Cache) denials. If denied, you must use `semanage` or `audit2allow` to create a specific policy exception allowing that process context to use that port context.

L20 — **Page Fault:** An event that occurs when a program tries to access a virtual memory address whose corresponding physical memory page is not currently loaded into RAM.
**Minor Page Fault:** The required page is already in physical memory but is mapped to a different location or needs to be brought into the process's address space (e.g., copy-on-write). This is fast.
**Major Page Fault:** The required page is not in physical memory at all (it might be on disk/swap). The kernel must perform a slow I/O operation to load the page from secondary storage into RAM.
**THP (Transparent Huge Pages):** THP attempts to automatically coalesce small, standard 4KB memory pages into large 2MB or 1GB huge pages to reduce TLB (Translation Lookaside Buffer) misses, improving performance for large memory workloads.
**Disabling THP:** You disable it when applications exhibit unpredictable latency spikes or when the workload is highly sensitive to memory access patterns, as the background compaction process used by THP can introduce unpredictable latency jitter.
