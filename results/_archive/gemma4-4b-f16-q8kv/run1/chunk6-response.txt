**DN1**
A **class** is a reference type, meaning instances are stored on the heap, and variables hold a reference (memory address) to that instance. A **struct** is a value type, meaning instances are stored directly on the stack (or inline within their containing type). You should use a struct for small, simple, immutable data aggregates (e.g., a point, a color) where heap allocation overhead is undesirable.

**DN2**
**IEnumerable<T>** represents a sequence that can be iterated over in memory. It executes iteration immediately when enumerated. **IQueryable<T>** represents an expression tree that describes a query. This distinction matters because `IQueryable<T>` allows the query logic (e.g., `Where`, `Select`) to be translated into a database-specific query language (like SQL) and executed on the database server, minimizing data transfer and processing load on the application server.

**DN3**
`async/await` allows asynchronous code to be written in a synchronous-looking style. When an `await` keyword is encountered on an awaitable task, execution is suspended, control is returned to the caller, and the thread is freed up to do other work. When the awaited operation completes, execution resumes from that point.
A **Task** is a general-purpose asynchronous operation wrapper. A **ValueTask<T>** is a struct optimized for scenarios where the result is often available synchronously (i.e., the operation doesn't need to await). You should use `ValueTask<T>` when the operation is frequently synchronous, as it avoids the heap allocation overhead associated with creating a `Task` object.

**DN4**
Dependency Injection (DI) is a design pattern where components receive their dependencies from an external source (the DI Container) rather than creating them internally.
The lifetimes are:
1. **Transient:** A new instance is created every single time it is requested.
2. **Scoped:** A single instance is created per scope (typically per HTTP request in ASP.NET Core).
3. **Singleton:** A single instance is created for the entire application lifetime.
A common bug is injecting a **Scoped** service into a **Singleton** service. The Singleton instance is created once and holds a reference to the Scoped service. If the scope ends (e.g., the HTTP request finishes), the Scoped service might be disposed, but the Singleton still holds a reference to the now-disposed object, leading to `ObjectDisposedException` or incorrect state.

**DN5**
A **string** is an immutable sequence of characters stored on the managed heap. Any modification creates a new string object. **ReadOnlySpan<char>** is a stack-allocated, type-safe view over a contiguous block of memory (which could be a string, a character array, etc.). You use `Span<T>` (or `ReadOnlySpan<T>`) for high-performance, zero-copy string processing, buffer manipulation, and parsing, as it avoids heap allocations and copying data when slicing or inspecting parts of existing memory buffers.

**DN6**
The .NET Garbage Collector (GC) automatically manages memory by tracking object references. It operates in generations:
*   **Gen 0:** Where short-lived objects are allocated. Collections here are frequent and fast.
*   **Gen 1:** Acts as a buffer between Gen 0 and Gen 2.
*   **Gen 2:** Where long-lived objects reside. Collections here are less frequent but more expensive.
The **Large Object Heap (LOH)** is a separate area for objects larger than 85KB. Objects in the LOH are generally not compacted by the GC, which can lead to memory fragmentation.
**IDisposable** is an interface used for deterministic cleanup. You need it when an object manages unmanaged resources (like file handles, network sockets, or database connections) that the GC cannot automatically release. Implementing `IDisposable` allows the developer to explicitly call `Dispose()` to free these resources immediately.

**DN7**
`ConfigureAwait(false)` tells the runtime that the continuation of the asynchronous method does not need to resume on the original `SynchronizationContext` (e.g., the UI thread context).
**When to use it:** In library code or background services where the continuation logic does not interact with UI elements. This prevents potential deadlocks and reduces overhead by avoiding context switching.
**When NOT to use it:** In UI code (WPF, WinForms, MAUI) where the continuation *must* resume on the UI thread to safely update the user interface.
This relates to the **SynchronizationContext** because the context captures the specific execution environment (like the UI thread). If you don't configure it to continue on that context, the code might run on a thread pool thread, causing UI access violations.

**DN8**
**Primary Constructors** allow you to define constructor parameters directly in the class signature, which can then be used to initialize properties or inject dependencies.
**Collection Expressions** (`[...]`) provide a concise syntax for creating collections.
**FrozenDictionary** is an immutable dictionary, ensuring its contents cannot be changed after creation.

*Minimal Example using Primary Constructors with DI:*
```csharp
// Assume ILogger is registered in DI
public class UserService(ILogger<UserService> logger)
{
    public void DoWork()
    {
        logger.LogInformation("Service initialized via primary constructor.");
    }
}
// In Program.cs: builder.Services.AddScoped<UserService>();
```

**DN9**
The likely cause is that the `DbContext` instance is being reused across multiple, concurrent HTTP requests or threads without proper isolation. Since `DbContext` is not thread-safe, high concurrency causes race conditions, leading to state corruption or the `ObjectDisposedException` if the underlying connection/scope is prematurely closed.
**The Fix:** Ensure that `DbContext` is registered with the **Scoped** lifetime in the DI container. EF Core's `DbContext` lifetime *must* align with the DI scope (usually Scoped) so that a new, isolated instance is provided for every incoming request, guaranteeing thread safety and proper resource management.

**DN10**
A **class** is a mutable reference type, designed to model complex entities with behavior. A **record** is a reference type optimized for data transfer; it automatically provides value equality (two records are equal if all their properties are equal, regardless of memory location) and often includes built-in immutability features. A **record struct** is a value type that inherits the value equality semantics of a record.
Choose a **class** when the object has complex behavior, mutable state, or needs to participate in inheritance hierarchies. Choose a **record** when the object is primarily a data carrier (DTO, model) and immutability is desired.

**DN11**
*   **ref:** Passes the variable by reference, and the variable *must* be initialized before being passed to the method. It allows the method to modify the original variable.
*   **out:** Passes the variable by reference, but the variable *does not* need to be initialized before being passed. The method *must* assign a value to the variable before returning. Used primarily for returning multiple values from a method.
*   **in:** (C# 7.2+) Passes the variable by reference, but guarantees that the method will treat it as read-only. This is used for performance optimization when passing large structs without copying them, while ensuring the method cannot modify the original data.

**DN12**
**Nullable Reference Types** (enabled by `#nullable enable`) allow the compiler to track whether a reference type variable might hold `null`. The `?` annotation explicitly marks a reference type as nullable (e.g., `string?`).
**Nullable Value Types** (e.g., `int?`, `DateTime?`) are structs that wrap a value type and can hold a `null` state. They are distinct from reference types.
The difference is that NRTs are a *compile-time* safety feature for reference types, whereas nullable value types are a *runtime* feature allowing value types to represent the absence of a value.

**DN13**
**LINQ** (Language Integrated Query) is a set of features in C# that allows developers to write queries against various data sources (collections, databases, XML) using a unified syntax.
*   **Method Syntax:** Uses extension methods chained onto the collection (e.g., `list.Where(x => x > 5).OrderBy(x => x)`).
*   **Query Syntax:** Uses SQL-like syntax (`from x in list where x > 5 select x`).
**Deferred Execution** means that the query expression is not executed immediately when it is defined. Instead, the query is compiled into an execution plan, and the actual data retrieval/filtering only happens when the results are enumerated (e.g., in a `foreach` loop or by calling `.ToList()`).

**DN14**
Generic constraints restrict the types that can be used as type arguments for a generic type.
*   `where T : class`: T must be a reference type.
*   `where T : struct`: T must be a value type.
*   `where T : new()`: T must have a public parameterless constructor.
*   `where T : IComparable<T>`: T must implement the `IComparable<T>` interface, allowing instances of T to be compared to each other.
You combine multiple constraints using commas (e.g., `where T : class, new(), IComparable<T>`) to enforce that the type must satisfy all specified requirements simultaneously.

**DN15**
An **abstract class** can contain both abstract members (methods/properties without implementation) and concrete members (fully implemented methods/properties). It can also hold state (fields). It defines a base blueprint that derived classes must extend.
An **interface** defines a contract—a set of methods and properties that implementing classes *must* adhere to, without providing any implementation details.
**Default Interface Methods (C# 8+)** allow interfaces to provide default implementations for methods. This blurs the line because an interface can now provide *some* implementation, but it still fundamentally defines a contract of *behavior*, whereas an abstract class defines a base *type* and implementation structure.

**DN16**
The middleware pipeline is a series of software components that process HTTP requests and responses sequentially in ASP.NET Core. Each middleware component has the opportunity to inspect, modify, or terminate the request/response cycle.
*   **`app.Use()`:** Adds middleware components (e.g., Authentication, Routing, CORS). These are typically used for cross-cutting concerns.
*   **`app.Map()`:** Maps specific endpoints or routes to handlers.
*   **`app.Run()`:** Terminates the pipeline, usually by executing the final endpoint handler.
**Ordering matters critically:** For example, Authentication middleware must run *before* the endpoint middleware that relies on the authenticated user's identity.
**Exception Handling Middleware** must be placed early in the pipeline (usually near the beginning) so that it can catch exceptions thrown by subsequent middleware or endpoint logic and return a standardized error response instead of letting the application crash.

**DN17**
**Channel<T>** is a modern, asynchronous, thread-safe mechanism for communication between asynchronous producers and consumers. It is designed to work seamlessly with `async/await`.
**BlockingCollection<T>** is an older, synchronous collection designed for producer-consumer scenarios, often blocking the calling thread until an item is available or the collection is marked complete.
You use **bounded channels** to enforce **backpressure**. If the channel has a defined maximum capacity, and the producers attempt to write more items than the consumers can process, the producer will asynchronously await until space becomes available in the channel, preventing the producer from overwhelming the consumer or exhausting memory.

**DN18**
**Source Generators** are a compile-time feature in .NET that allows developers to write code that generates other C# source code during the compilation process.
They differ from **reflection** because reflection inspects types and members *at runtime*; Source Generators generate the code *before* runtime. They differ from **IL weaving** because IL weaving modifies the Intermediate Language (IL) of compiled assemblies *after* compilation; Source Generators generate clean, standard C# source code that is compiled normally.
An **incremental generator** is preferred because it only regenerates the code files that are directly affected by changes in the source code it depends on. This drastically reduces build times by avoiding unnecessary recompilations of dependent projects.

**DN19**
**TPL Dataflow** is a library for building complex, asynchronous, concurrent pipelines using blocks that process data streams.
*   **ActionBlock:** Executes an action (a delegate) on incoming messages. It is designed for fire-and-forget processing.
*   **TransformBlock:** Executes an action that takes an input message and transforms it into an output message.
*   **BufferBlock:** Acts as a queue, buffering incoming messages until a consumer is ready to process them.
TPL Dataflow is superior for building complex, multi-stage, structured pipelines where data flows through several distinct processing steps. **Channels** are better suited for simpler, asynchronous producer-consumer patterns where the focus is on reliable, backpressured data transfer between two points.

**DN20**
**Minimal APIs** are a lightweight, streamlined way to build HTTP endpoints directly within the `Program.cs` file using lambda expressions and minimal boilerplate, contrasting with the traditional controller-based approach.
**Trade-offs:**
*   **Testability:** Can be slightly harder to unit test in isolation compared to dedicated controller classes, though endpoint testing is straightforward.
*   **Middleware:** Middleware is applied globally or per-endpoint via simple configuration.
*   **OpenAPI Support:** Requires explicit configuration (e.g., using Swashbuckle) to generate OpenAPI documentation, whereas controllers often integrate more naturally with established conventions.
**Route Groups** allow grouping related endpoints to apply common configurations (like versioning or specific middleware). **Endpoint Filters** allow developers to inject logic (like authorization checks or logging) that runs before or after an endpoint executes, similar to action filters in MVC.

**P1**
A **list** (`list`) is a mutable, ordered sequence that allows duplicate elements. A **tuple** (`tuple`) is an immutable, ordered sequence. A **set** (`set`) is a mutable, unordered collection of unique elements. A **frozenset** (`frozenset`) is an immutable version of a set, meaning it can be used as an element within another set or as a dictionary key.

**P2**
The **GIL (Global Interpreter Lock)** is a mutex that protects access to Python objects, ensuring that only one thread can execute Python bytecode at any given time within a single process. It prevents true parallel execution of CPU-bound code across multiple threads. It primarily affects **CPU-bound workloads**. Workarounds include using the `multiprocessing` module (which spawns separate processes, each with its own GIL) or using libraries written in C/C++ (like NumPy) that explicitly release the GIL during heavy computation.

**P3**
A **shallow copy** creates a new container object, but it populates this new container with *references* to the objects found in the original. If the original object contains mutable objects (like lists or dictionaries), modifying those nested objects in the copy will also modify them in the original, leading to unexpected behavior. A **deep copy** recursively creates entirely new copies of all objects found in the original structure, ensuring complete independence.

*Example of shallow copy failure:*
```python
original = [{'value': 1}]
shallow_copy = original.copy()
shallow_copy[0]['value'] = 99  # Modifies the nested dict in both
print(original[0]['value']) # Output: 99 (Unexpected)
```

**P4**
A decorator is a design pattern in Python that allows you to wrap a function or method, modifying its behavior without permanently altering its source code. They are syntactic sugar for passing a function to another function and returning a new, wrapped function.

*Decorator to log execution time:*
```python
import time
from functools import wraps

def timing_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"Function {func.__name__} executed in {end_time - start_time:.4f} seconds.")
        return result
    return wrapper

@timing_decorator
def slow_function(n):
    time.sleep(n)
    return f"Slept for {n}"

slow_function(0.5)
```

**P5**
**Generators** are functions that use the `yield` keyword instead of `return`. They produce a sequence of results lazily—one item at a time, only when requested. This is highly memory efficient for large datasets because the entire sequence is never held in memory simultaneously. Returning a list computes and stores the entire sequence upfront.
**`yield from`** is used to delegate iteration to a sub-generator. It allows a generator function to delegate part of its operation to another generator, effectively chaining generators together.

**P6**
The **asyncio event loop** is the core mechanism that manages and runs asynchronous code in Python. It monitors I/O operations (like network requests or disk reads) and switches execution between tasks when one task is waiting for an external event, allowing the single thread to handle many concurrent operations efficiently.
*   `asyncio.run(coro)`: Runs the top-level coroutine and manages the event loop lifecycle.
*   `asyncio.gather(*coros)`: Runs multiple awaitables concurrently and waits for all of them to complete.
*   `asyncio.create_task(coro)`: Schedules a coroutine to run concurrently on the event loop without blocking the current execution flow.
You cannot call `time.sleep()` inside an `async` function because `time.sleep()` is a *blocking* call. It halts the entire thread, freezing the event loop and preventing any other scheduled tasks from running. You must use `await asyncio.sleep(delay)` instead, which yields control back to the event loop.

**P7**
**MRO (Method Resolution Order)** dictates the order in which Python searches the class hierarchy to find a method or attribute. Python 3 uses the **C3 Linearization Algorithm**. This algorithm ensures a consistent, deterministic, and monotonic ordering that respects the local precedence order (the order classes are listed in the inheritance definition) while avoiding infinite loops in complex inheritance structures.
In the diamond inheritance example, the MRO for `D` will be `D -> B -> C -> A -> object`. Because `B` is listed before `C` in `class D(B, C)`, Python checks `B`'s path first. Since `B` inherits from `A`, and `C` also inherits from `A`, the method resolution stops at the first definition encountered in the linearized order, which is `A`'s definition via `B`. Therefore, `D().who()` prints `"A"`.

**P8**
A **metaclass** is the "class of a class." It controls *how* a class itself is created. When Python encounters `class MyClass(BaseClass):`, the metaclass is responsible for constructing the `MyClass` object.
**`__init_subclass__`** is a special method that runs *after* a subclass has been created, allowing you to perform actions based on the inheritance relationship (e.g., validating attributes or setting defaults on the subclass).
*   **Metaclass Use Case:** Enforcing a strict API structure across many classes (e.g., ensuring every class inheriting from `BaseAPI` has a specific required method signature).
*   **`__init_subclass__` Use Case:** Automatically setting a default logging level for all subclasses of a configuration class based on a class attribute defined in the subclass.

**P9**
*   **Threading:** Uses threads within the same process, sharing memory. Best for **I/O-bound** tasks (waiting for network/disk). Limited by the GIL for CPU-bound tasks.
*   **Multiprocessing:** Uses separate OS processes, bypassing the GIL. Best for **CPU-bound** tasks (heavy computation).
*   **concurrent.futures:** Provides a high-level, unified interface (`ThreadPoolExecutor` for threads, `ProcessPoolExecutor` for processes) to manage and submit tasks to either thread or process pools.
**Serialization Implications:** When using `multiprocessing`, data must be passed between separate memory spaces (processes). This requires **pickling**—the process of serializing the Python object into a byte stream—before it can be sent, and then unpickling it on the receiving end.

**P10**
`__slots__` is a class attribute that explicitly declares the attributes an instance of a class is allowed to have. When defined, Python skips creating the instance's internal `__dict__` (the standard dictionary used to store instance attributes).
**When to use it:** When you are creating a very large number of instances of a class and memory efficiency is critical.
**What it prevents:** It prevents dynamic attribute assignment (you cannot add a new attribute to an instance after it has been created).
**Memory Impact:** It significantly reduces the memory footprint of each instance because the overhead of maintaining the instance dictionary is eliminated.

**P11**
A **virtual environment** is an isolated directory that contains a specific Python interpreter and its own set of installed packages. It ensures that the dependencies required for one project do not conflict with the dependencies of another project on the same system.
*   **venv/virtualenv:** Standard, lightweight tools built into Python or available as a package, designed specifically for creating isolated Python environments.
*   **conda:** A comprehensive package and environment manager, often used in data science, that manages not just Python packages but also non-Python dependencies (like specific versions of compilers or scientific libraries).

**P12**
Comprehensions provide a concise, readable syntax for creating collections based on existing iterables.
*   **List Comprehension:** `[x * 2 for x in numbers if x > 0]`
*   **Dict Comprehension:** `{k: v * 2 for k, v in items.items()}`
*   **Set Comprehension:** `{x for x in numbers}` (automatically handles uniqueness)
They are generally preferred over explicit `map()` and `filter()` because they are more idiomatic, readable, and often slightly faster in CPython. `map()` applies a function to every item; `filter()` selects items based on a predicate; comprehensions combine both operations concisely.

**P13**
*   **`==` (Equality):** Compares the *values* of two objects. It calls the object's `__eq__` method.
*   **`is` (Identity):** Compares the *identity* of two objects, checking if they refer to the exact same object in memory (i.e., if they have the same `id()`).
**Object Interning** is an optimization where Python pre-caches and reuses immutable objects (like small integers, e.g., -5 to 256, and short strings). When you create `a = 100` and `b = 100`, Python often points both variables to the *same* cached object in memory, causing `a is b` to return `True`.

**P14**
*   **`*args`:** Collects any number of positional arguments passed to the function into a tuple named `args`.
*   **`**kwargs`:** Collects any number of keyword arguments passed to the function into a dictionary named `kwargs`.
**Positional-only (`/`):** Arguments listed before the `/` must be passed positionally; they cannot be passed using a keyword argument name.
**Keyword-only (`*`):** Arguments listed after the `*` must be passed using their keyword name; they cannot be passed positionally.

**P15**
Context managers are objects that define the setup and teardown logic for a block of code, ensuring that cleanup actions (like closing a file or releasing a lock) happen reliably, even if exceptions occur within the block.
*   **`__enter__` / `__exit__`:** Defining these methods on a class makes it a context manager. `__enter__` runs upon entering the `with` block and returns the resource; `__exit__` runs upon exiting, handling cleanup.
*   **`@contextmanager`:** A simpler decorator from the `contextlib` module that allows you to write a context manager using a generator function. The code before `yield` is setup; the code after `yield` is teardown.
*Example beyond file handling:* Managing a database transaction scope. The `__enter__` method starts the transaction, and the `__exit__` method commits or rolls back the transaction based on whether an exception occurred.

**P16**
Type hinting is the practice of adding optional static type annotations to variables, function parameters, and return values in Python. This does not change runtime behavior but allows external tools like **mypy** or **pyright** to perform static analysis, catching type errors before the code is ever run.
*   **`typing.Union[A, B]`:** Indicates a variable can be of type A OR type B.
*   **`typing.Optional[A]`:** A shorthand for `Union[A, None]`, indicating the variable can be A or None.
*   **`typing.Literal[value1, value2]`:** Restricts a variable to only accept one of the specified literal values (e.g., `Literal["success", "error"]`).
*   **`typing.TypeVar`:** A placeholder used to define generic types, similar to generics in C#.
*   **`typing.Protocol`:** Defines structural typing (duck typing). It specifies that any class implementing the protocol must possess certain methods or attributes, regardless of its explicit inheritance.

**P17**
Python's **data model** (dunder methods) allows objects to behave according to Python's syntax.
*   **`__repr__`:** The "official" string representation, intended for developers. It should ideally be unambiguous and allow recreation of the object (e.g., `MyClass(arg1=1)`).
*   **`__str__`:** The "informal" string representation, intended for end-users (readable).
*   **`__eq__`:** Defines how two objects are compared for equality (`a == b`).
*   **`__hash__`:** Defines the hash value of an object, used by dictionaries and sets for fast lookups.
If you define `__eq__` but not `__hash__`, Python will raise a `TypeError` if you try to use that object as a key in a dictionary or add it to a set, because the object cannot be reliably hashed.

**P18**
A **descriptor** is an object attribute that defines how attribute access (getting, setting, or deleting) is handled for the attribute it describes. It implements the descriptor protocol: `__get__`, `__set__`, and `__delete__`.
*   **Property:** Uses descriptors to allow attribute access syntax (`obj.attr`) while executing methods behind the scenes (getters/setters).
*   **classmethod:** Uses descriptors to ensure the method is bound to the class itself, not an instance.
*   **staticmethod:** Uses descriptors to ensure the method is bound to neither the class nor the instance, acting like a regular function namespaced within the class.

**P19**
Python's import system locates and loads modules based on paths defined in `sys.path`.
*   **Absolute Imports:** Start from the root of the package structure (e.g., `from my_package import module`).
*   **Relative Imports:** Use dots (`.`) to refer to modules relative to the current package (e.g., `from . import sibling_module`).
*   **`sys.path`:** A list of directories Python searches when an `import` statement is encountered.
*   **`__init__.py`:** Historically, this file marked a directory as a Python package, allowing it to be imported.
*   **Namespace Packages:** Allow a single package to be split across multiple directories without requiring an `__init__.py` in every subdirectory.
A **finder** is responsible for locating the module (finding the correct path). A **loader** is responsible for loading the module (executing the code and creating the module object).

**P20**
**Dataclasses** are a decorator (`@dataclass`) that automatically generates boilerplate methods (`__init__`, `__repr__`, `__eq__`, etc.) for classes primarily intended to hold data.
**Pydantic** is a data validation library that uses Python type hints to enforce strict data schemas at runtime. It handles parsing data from external sources (like JSON) and validates it against the defined types.
*   **`__post_init__`:** A method in dataclasses that runs immediately after `__init__` completes, allowing for post-initialization logic (e.g., derived field calculation).
*   **Field Factories:** Used with `field()` to provide default values that are computed dynamically rather than being static constants.
*   **Frozen Dataclasses:** Set `frozen=True` to make the instance immutable, preventing attribute changes after creation.
Dataclasses interact with inheritance by allowing subclasses to inherit the generated methods, though complex inheritance can require manual overrides.
**Choose Pydantic over dataclasses** when you need robust, runtime data validation, serialization/deserialization (e.g., converting JSON to an object and back), or strict schema enforcement from external inputs.
