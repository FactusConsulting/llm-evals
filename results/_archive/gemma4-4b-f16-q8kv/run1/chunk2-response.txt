**Networking Answers**

N1 — A Layer 2 switch operates at the Data Link layer (Layer 2) and forwards frames based on MAC addresses within the same broadcast domain. A Layer 3 switch operates at the Network layer (Layer 3) and can perform routing between different IP subnets, forwarding packets based on IP addresses.

N2 — IP: 10.0.5.37/20.
The subnet mask for /20 is 255.255.240.0.
Network Address: 10.0.5.0
Broadcast Address: 10.0.15.255

N3 — The TCP three-way handshake establishes a connection:
1. **SYN (Synchronize):** Client sends a SYN packet to the server, proposing an initial sequence number (ISN).
2. **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and replies with a SYN-ACK packet, acknowledging the client's SYN and sending its own ISN.
3. **ACK (Acknowledge):** Client receives SYN-ACK and sends a final ACK packet, acknowledging the server's SYN.
If the final ACK is lost, the client will retransmit the ACK (or the server will time out and retransmit the SYN-ACK), eventually leading to a connection timeout or successful retransmission, depending on the TCP stack implementation and retransmission timers.

N4 — **SNAT (Source Network Address Translation):** Changes the source IP address of a packet as it leaves a private network, typically to allow multiple internal hosts to share one public IP when accessing the internet. *Example: A host 10.0.0.5 accessing Google uses the router's public IP as its source.*
**DNAT (Destination Network Address Translation):** Changes the destination IP address of a packet as it enters a private network, typically to forward external traffic to a specific internal server. *Example: An external user accessing a web server at public IP 203.0.113.10 is translated by the firewall to the internal server 192.168.1.5.*

N5 — 3 possible causes:
1. **Hostname Mismatch:** The certificate was issued for a different domain name than the one being accessed (e.g., certificate for `dev.example.com` accessed via `example.com`).
2. **Expired Certificate:** The certificate has passed its validity date.
3. **Incorrect Configuration:** The server is presenting the wrong certificate file or the certificate chain is incomplete/broken.

N6 — **VLAN (Virtual Local Area Network):** A logical segmentation mechanism operating at Layer 2, confining broadcast domains within a single physical switch infrastructure. It is limited by the 4094 tag limit and the physical topology of the switch.
**VxLAN (Virtual Extensible LAN):** A network virtualization overlay technology that encapsulates Layer 2 Ethernet frames within Layer 3 UDP packets. It solves the scalability limitations of VLANs by using a 24-bit identifier (VNI), allowing for over 16 million logical segments.
**Choice:** VxLAN is chosen when the network requires massive scalability (more than 4094 segments), needs to span across Layer 3 boundaries (e.g., connecting distant data centers), or requires multi-tenancy isolation across a large, complex infrastructure.

N7 — **Why:** The host is likely using the default routing table, which directs all traffic destined for 192.168.1.0/24 (the eth1 subnet) out through the default gateway (10.0.0.1) on eth0, because the routing table entry for 192.168.1.0/24 might be missing or less specific than the default route.
**Fix (Policy-Based Routing - PBR):** Use `ip rule` and `ip route` to create a specific routing policy.
1. Add a route specifically for the 192.168.1.0/24 subnet pointing out eth1's gateway (or directly via eth1's interface).
2. Add a rule that directs traffic originating from or destined for 192.168.1.0/24 to use this specific route table.
*Example concept: `ip rule add from 192.168.1.0/24 table 100` followed by `ip route add 192.168.1.0/24 dev eth1 src 192.168.1.5 table 100`.*

N8 — BGP path selection is a deterministic process used by routers to choose the best path among multiple available routes to the same destination prefix. The router evaluates attributes in a strict, ordered sequence.
**5 Attributes (in preference order):**
1. **Weight** (Cisco proprietary, highest preference)
2. **Local Preference** (Highest is preferred, used internally)
3. **Locally Originated** (Prefer routes originated locally)
4. **AS Path Length** (Shortest path is preferred)
5. **Origin Type** (IGP > EGP > Incomplete)

N9 — **MTU Implication:** When running VxLAN over IPsec, the original Ethernet frame (which is already encapsulated by VxLAN) is then encapsulated *again* by IPsec (which adds headers for ESP/AH and potentially outer IP headers). This adds significant overhead.
**Math:**
*   Physical MTU: 1500 bytes
*   VxLAN Header Overhead: $\approx 50$ bytes (VNI, UDP, etc.)
*   IPsec Overhead (ESP/AH + outer IP): $\approx 50-70$ bytes
*   Total Overhead: $\approx 100$ bytes
*   Maximum Inner Payload: $1500 - 100 = 1400$ bytes (This is a conservative estimate; exact overhead depends on IPsec mode and specific headers).

N10 — **ARP (Address Resolution Protocol):** ARP maps a known Layer 3 IP address to its corresponding Layer 2 MAC address on a local network segment. It works by broadcasting an ARP request asking, "Who has this IP? Tell me your MAC."
**Gratuitous ARP:** A host broadcasts an ARP request for its *own* IP address. It solves problems like:
1. **Duplicate IP Detection:** If another host replies to the gratuitous ARP, the sender knows its IP is already in use.
2. **Cache Refresh:** It forces neighboring devices (switches/hosts) to immediately update their ARP caches with the host's current MAC address, which is crucial after a host changes NICs or moves.

N11 — **Public IP:** Globally unique address routable across the public internet.
**Private IP:** Non-globally unique addresses reserved for use within private, internal networks (LANs) and are not routable on the public internet without NAT.
**RFC 1918 Ranges:**
1. 10.0.0.0/8
2. 172.16.0.0/12
3. 192.168.0.0/16

N12 — **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses (like `93.184.216.34`).
**Record Differences:**
*   **A Record:** Maps a hostname to an IPv4 address (e.g., `www.example.com` $\rightarrow$ `192.0.2.1`).
*   **AAAA Record:** Maps a hostname to an IPv6 address (e.g., `www.example.com` $\rightarrow$ `2001:db8::1`).
*   **CNAME Record (Canonical Name):** Creates an alias, mapping one domain name to another domain name (e.g., `blog.example.com` $\rightarrow$ `servers.hostingprovider.com`).

N13 — **DHCP (Dynamic Host Configuration Protocol):** A network management protocol used to automatically assign IP addresses and other network configuration parameters (subnet mask, gateway, DNS servers) to devices on a network.
**DORA Process:**
1. **Discover:** Client broadcasts a DHCP Discover message to find available servers.
2. **Offer:** Server responds with a DHCP Offer, proposing an IP address and configuration.
3. **Request:** Client broadcasts a DHCP Request, formally accepting the offered configuration.
4. **Acknowledge:** Server sends a DHCP ACK, finalizing the lease and configuration.

N14 — **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming electrical signals to every connected port, creating one large collision domain.
**Switch:** Operates at Layer 2 (Data Link). It learns MAC addresses and forwards frames only to the intended destination port, segmenting collision domains.
**Router:** Operates at Layer 3 (Network). It connects different networks (subnets) and forwards packets based on IP addresses, making routing decisions.

N15 — **Half-Duplex:** Allows data transmission in both directions, but only one direction at a time (e.g., a walkie-talkie). Collisions can occur if both sides transmit simultaneously.
**Full-Duplex:** Allows simultaneous data transmission and reception over the same link in both directions. Collisions are eliminated at the physical layer.
Modern Ethernet links use **Full-Duplex** communication.

N16 — **TTL (Time To Live):** A field in the IP header that specifies the maximum number of hops (routers) a packet can traverse before being discarded. It prevents packets from circulating indefinitely in routing loops.
**Traceroute Exploitation:** Traceroute works by sending a sequence of packets (usually UDP or ICMP) with incrementally increasing TTL values (starting at 1). When the packet reaches the first router, the TTL expires, and the router sends back an ICMP "Time Exceeded" message, revealing the router's IP address. By incrementing TTL, the path is mapped hop-by-hop.

N17 — **NAT Gateway:** A device (usually a router or firewall) that translates private, internal IP addresses into one or more public IP addresses when traffic passes between a private network and the public internet.
**Differences:**
*   **Static NAT:** Maps one specific private IP address to one specific public IP address permanently (1:1 mapping). Used for servers that need consistent external access.
*   **Dynamic NAT:** Maps private IP addresses to a pool of available public IP addresses on a first-come, first-served basis.
*   **PAT (Port Address Translation) / NAT Overload:** Maps many private IP addresses to a single public IP address by tracking unique source port numbers for each internal connection. This is the most common form used in homes/offices.

N18 — **ECMP (Equal-Cost Multi-Path):** A routing technique that allows a router to install multiple next-hop paths into the routing table for the same destination prefix, provided all paths have the same administrative cost (metric). Traffic is distributed across these paths.
**Hashing Strategies:** Common strategies include hashing based on the 5-tuple (Source IP, Destination IP, Source Port, Destination Port, Protocol).
**Asymmetric Flow Problem:** If stateful firewalls are involved, asymmetric routing occurs when the request packet takes one path (e.g., Path A) and the return/response packet takes a different path (e.g., Path B). The firewall on Path A will not have a corresponding state entry for the return traffic arriving on Path B, causing the connection to be dropped.

N19 — **Problem:** The TCP window size dictates how much unacknowledged data the sender can transmit before receiving an ACK. The Bandwidth-Delay Product (BDP) is the maximum amount of data that can be "in flight" on the network path at any given time ($\text{BDP} = \text{Bandwidth} \times \text{RTT}$). If the BDP is 10MB, the sender needs a window size of at least 10MB to fully utilize the link. Since the window is capped at 64KB, the sender is constantly waiting for ACKs, leading to severe underutilization and high latency relative to the potential throughput.
**Solution (TCP Window Scaling):** RFC 1323 introduced the Window Scale option during the TCP handshake. This option allows the TCP header to negotiate a window size much larger than the standard 16-bit limit (65,535 bytes), enabling the sender to advertise a window size large enough to match the BDP and keep the pipe full.

N20 — **802.1Q Trunk Ports:** This standard allows a single physical link (trunk) to carry traffic for multiple VLANs simultaneously. It achieves this by inserting a 4-byte tag (the VLAN tag) into the Ethernet frame header.
**Linux Configuration (Sub-interfaces):** On Linux, this is typically done using VLAN sub-interfaces on the physical NIC.
*Example: `eth0.10`, `eth0.20`, `eth0.30`.*
Each sub-interface is configured with the specific VLAN ID and IP address for that VLAN.
**Frame Format:** The frame format is standard Ethernet, but between the Source MAC and EtherType fields, the 4-byte 802.1Q tag is inserted. This tag contains the TPID (Tag Protocol Identifier) and the TCI (Tag Control Information), which specifies the VLAN ID (VID).

**Linux Answers**

L1 — **Hard Link:** A hard link is a directory entry that points directly to the same inode (the data structure containing file metadata) as the original file. It is essentially another name for the same data. Deleting one hard link does not delete the data until the last link is removed.
**Symbolic Link (Symlink):** A symbolic link is a special type of file that contains a text path pointing to another file or directory. It is a pointer, not a direct reference to the inode.

L2 — `find /var/log -type f -size +100M`

L3 — **State D (Uninterruptible Sleep):** This state means the process is waiting for an I/O operation (like disk read/write) to complete. The kernel cannot interrupt this process, even with `kill -9` (SIGKILL), because it is blocked waiting for hardware. The process is effectively stuck until the I/O completes.

L4 — **cgroups v1:** Used a hierarchical, controller-based model where resources (CPU, Memory, I/O) were managed by separate, independent controllers. It was less unified.
**cgroups v2:** Implements a unified hierarchy and a unified control plane. It uses a single hierarchy structure and a unified set of controllers, providing better resource isolation and management consistency.
**Systemd Preference:** Systemd prefers cgroups v2 because its unified hierarchy and cleaner resource management model align better with systemd's own service management structure, leading to more predictable and robust container/service isolation.

L5 — **iptables:** The older, traditional Linux firewall framework. It uses chains (INPUT, OUTPUT, FORWARD) and tables to process packets sequentially.
**nftables:** The modern replacement for iptables. It is a more flexible, unified framework that can handle packet filtering, NAT, and routing rules using a single, unified syntax and structure.
**Kernel Handling:** The kernel maintains compatibility layers. When `iptables` commands are run, the kernel translates those rules into the underlying data structures used by the `nftables` framework, allowing older tools to function while the modern kernel infrastructure is utilized.

L6 — The most likely cause is **Inodes exhaustion**. The filesystem might have plenty of free data blocks, but if every available inode (the structure that stores metadata about a file) has been used up, the system cannot create new files, leading to 100% usage reported by `df -h`, even if the total data size (`du -sh`) is low.

L7 — **Boot Process:**
1. **UEFI Firmware:** Initializes hardware, runs POST, and locates the bootloader partition.
2. **Bootloader (e.g., GRUB):** Loads the Linux kernel image and the initial RAM disk (`initramfs`) into memory.
3. **Kernel:** Takes control. It initializes core drivers, mounts the `initramfs` root filesystem, and prepares the environment.
4. **Initramfs:** A minimal, temporary root filesystem containing necessary drivers (like storage controllers) to mount the *real* root filesystem.
5. **Root Filesystem:** The kernel mounts the actual root partition (e.g., `/`).
6. **Systemd:** The kernel executes the first process, PID 1, which is `systemd`. Systemd then takes over, managing services, mounting remaining filesystems, and reaching the final operational target (e.g., `multi-user.target`).

L8 — **Why Available is Low:** The `available` memory metric is calculated as `free + buffers + cache`. However, the OOM killer fires when the system needs memory for *new* allocations, and the kernel determines that even if it aggressively reclaims cache/buffers, the remaining memory is insufficient for the requested allocation, or the memory pressure is too high. High `buff/cache` means the kernel is using RAM efficiently for disk caching, but this memory is reclaimable, not guaranteed for running processes.
**Kernel Tunables:** `vm.swappiness` (controls how aggressively the kernel swaps out anonymous memory) and `vm.vfs_cache_pressure` (controls how aggressively the kernel reclaims memory used for directory and inode caches).

L9 — **`ip netns`:** This command is used to manage network namespaces. A network namespace is an isolated view of the system resources (network interfaces, routing tables, process IDs, etc.).
**Container Runtime Use:** Container runtimes (like Docker or Kubernetes) use network namespaces to give each container its own isolated network stack. When a container starts, it is placed into a dedicated network namespace, meaning its `eth0` interface, IP address, and routing table are completely separate from the host's network stack.

L10 — **SIGTERM (Signal 15):** A polite request for a process to terminate. The process can catch this signal, perform cleanup (save state, close files), and exit gracefully.
**SIGKILL (Signal 9):** A forceful, immediate termination signal. The process cannot catch, ignore, or block this signal; the kernel terminates it instantly.
**SIGQUIT (Signal 3):** Requests the process to terminate and usually generates a core dump file for debugging. The process *can* catch this signal.

L11 — **stdin (Standard Input):** Where a program reads input from (default: keyboard).
**stdout (Standard Output):** Where a program writes its normal, expected output to (default: terminal screen).
**stderr (Standard Error):** Where a program writes error messages and diagnostic output to (default: terminal screen).
**Redirection:** To redirect stderr to a file (`errors.log`) while keeping stdout on the terminal: `command 2> errors.log`.

L12 — `chmod 755 filename` sets permissions as follows:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = Full control.
*   **5 (Group):** Read (4) + Execute (1) = Can read and run, but not modify.
*   **5 (Others):** Read (4) + Execute (1) = Can read and run, but not modify.

L13 — **Root User:** The superuser (UID 0). The root user has unrestricted access to the entire operating system, can modify any file, change system configurations, and manage all processes without restriction.
**Sudo Privileges:** A user with `sudo` privileges can execute specific commands as another user (usually root) by prefixing the command with `sudo`. This grants elevated permissions only for specific, authorized actions, providing accountability and limiting the scope of potential damage compared to being the root user.

L14 — **Package Manager:** A system utility responsible for installing, upgrading, configuring, and removing software packages in a standardized way, managing dependencies automatically.
**Managers:**
*   Debian/Ubuntu: `apt` (Advanced Package Tool)
*   RHEL/Fedora: `dnf` (Dandified YUM)

L15 — **`/etc/fstab`:** This file defines static information about filesystems, telling the operating system which filesystems to mount at boot time, where to mount them, and what options to use.
**Misconfiguration:** If an entry is misconfigured (e.g., incorrect UUID, wrong mount point, or invalid filesystem type), the system may fail to mount that filesystem during boot, potentially leading to a boot failure, an inability to access critical data, or the system booting into emergency mode.

L16 — **LVM (Logical Volume Manager):** A storage management abstraction layer that provides flexible volume management, allowing administrators to resize, snapshot, and manage storage volumes independently of the underlying physical disk layout.
**Components:**
*   **Physical Volumes (PV):** The actual physical storage devices (disks or partitions) that LVM uses.
*   **Volume Groups (VG):** A pool of storage capacity created by combining one or more PVs.
*   **Logical Volumes (LV):** The virtual, flexible partitions carved out of a VG that the operating system sees and mounts.
**Extension:** To extend an LV on a running system:
1. Extend the underlying PV (if necessary).
2. Extend the VG to include the new space.
3. Extend the LV using `lvextend -L +[size] /dev/vgname/lvname`.
4. Resize the filesystem on the LV using `resize2fs` (for ext4) or `xfs_growfs`.

L17 — **I/O Scheduler:** Determines the order in which read/write requests are serviced by the block device driver, optimizing disk throughput and latency.
**Scheduler Comparison:**
*   **mq-deadline:** Prioritizes requests based on deadlines, aiming to prevent starvation of requests waiting too long. Good for mixed workloads.
*   **bfq (Budget Fair Queueing):** Designed for desktop/interactive workloads. It aims to provide "fair" bandwidth allocation to different processes, minimizing latency spikes for interactive tasks.
*   **none:** Passes I/O requests directly to the hardware driver without reordering. Best for devices or workloads where the driver/hardware handles scheduling optimally (e.g., NVMe SSDs).
**Runtime Change:** Use the `echo` command to write the desired scheduler name to the device's `scheduler` file: `echo bfq > /sys/block/sdX/queue/scheduler`.

L18 — **Load Average:** Measures the average number of processes in the system that are either running or waiting to run (in uninterruptible sleep, D state). It is a measure of system *demand* for CPU time, not necessarily CPU utilization.
**I/O Wait Inflation:** If the system is waiting heavily on slow disk I/O, processes enter the D state. These waiting processes contribute to the load average, making it appear as if the CPU is overloaded, even if the CPU utilization percentage is low.
**Diagnosis:**
*   **CPU Bottleneck:** High `us` (user) or `sy` (system) time in `top`/`htop`.
*   **Disk Bottleneck:** High `%wa` (I/O wait) in `top`/`htop`, coupled with high utilization reported by `iostat` on the disk device.
*   **Network Bottleneck:** High queue lengths or packet drops reported by interface statistics (`ip -s link`) or high latency observed via `ping`/`mtr`.

L19 — **SELinux Enforcement:** SELinux enforces Mandatory Access Control (MAC). Instead of relying solely on traditional Discretionary Access Control (DAC - user/group permissions), SELinux assigns security contexts (labels) to every subject (process) and object (file/port). Access is only granted if the policy explicitly permits the transition between the subject's context and the object's context.
**Modes:**
*   **Enforcing:** SELinux actively denies access based on policy violations.
*   **Permissive:** SELinux logs all policy violations but does *not* deny access, allowing administrators to see what *would* have been blocked.
*   **Disabled:** SELinux is completely inactive, relying only on DAC.
**Troubleshooting:** Check the audit logs (`/var/log/audit/audit.log`). If a daemon fails to bind a port, check if the policy prevents the process context from accessing that port context. You may need to use `semanage port` to explicitly allow the daemon's context to use the non-standard port.

L20 — **Page Faults:** A page fault occurs when a program tries to access a virtual memory address whose corresponding physical memory page is not currently loaded into RAM. The kernel intercepts this fault and handles it.
**Minor Page Fault:** Occurs when the required page is already in physical memory but is mapped to a different location (e.g., copy-on-write). The kernel simply updates the page table entry; no disk I/O is required.
**Major Page Fault:** Occurs when the required page is not in physical memory at all (it might be on disk/swap). The kernel must halt the process, locate the page on disk, load it into a free physical frame, update the page tables, and then resume the process. This involves slow disk I/O.
**THP (Transparent Huge Pages):** THP attempts to automatically coalesce small, standard 4KB memory pages into large 2MB or 1GB huge pages to reduce TLB misses and improve performance for memory-intensive applications.
**Disabling THP:** It should be disabled if an application exhibits unpredictable performance or high latency spikes, as the background compaction process required by THP can introduce significant, non-deterministic latency pauses.
