**DN1**
A `class` is a reference type, meaning instances are stored on the heap, and variables hold a reference (pointer) to that memory location. A `struct` is a value type, meaning instances are typically stored on the stack (or inline within containing types), and variables hold the actual data. You should use a `struct` for small, immutable data structures (like coordinates or color definitions) where performance benefits from stack allocation outweigh the complexity of value semantics.

**DN2**
`IEnumerable<T>` represents a sequence that can be iterated over. It supports deferred execution; it only executes the query when you start iterating (e.g., in a `foreach` loop). `IQueryable<T>` represents an expression tree. It allows the query logic to be translated into an executable query (like SQL) *before* execution. The distinction matters because `IEnumerable<T>` executes the filtering/projection in memory on the client side, while `IQueryable<T>` pushes the filtering/projection down to the database server, which is vastly more efficient for large datasets.

**DN3**
`async/await` allows asynchronous code to be written in a synchronous-looking style. When an `await` keyword is encountered on an awaitable task, control is returned to the caller, freeing up the thread to do other work. When the awaited operation completes, execution resumes from that point.
*   **Task:** Represents an asynchronous operation that might return a value or throw an exception. It is generally used for I/O-bound operations.
*   **ValueTask:** A struct optimization used when the result of an asynchronous operation is often available synchronously (i.e., the operation completes immediately). It avoids heap allocation when the result is synchronous, reducing GC pressure. Use `ValueTask` when you expect the operation to complete synchronously often.

**DN4**
Dependency Injection (DI) is a design pattern where components receive their dependencies from an external source (the DI Container) rather than creating them internally. This promotes loose coupling and testability.
*   **Transient:** A new instance is created every single time it is requested.
*   **Scoped:** A single instance is created per scope (e.g., per HTTP request in ASP.NET Core).
*   **Singleton:** A single instance is created for the entire application lifetime.
A common bug is injecting a **Scoped** service into a **Singleton** service. Since the Singleton lives for the entire application lifetime, it holds a reference to the Scoped service. If the Scoped service relies on request-specific context (like an `HttpContext` or `DbContext`), that context will be captured and reused across unrelated requests, leading to data corruption or unexpected state sharing.

**DN5**
`string` is an immutable reference type in C#. Operations on a string (like concatenation or slicing) always create a new string object on the heap. `ReadOnlySpan<char>` is a stack-allocated, memory-safe view over a contiguous block of memory (which could be a string, a character array, or a portion of one).
You use `Span<T>` (or `ReadOnlySpan<T>`) when you need high-performance, low-allocation string or buffer manipulation, such as parsing input streams or processing network packets. It avoids the overhead of creating new string objects during intermediate processing steps.

**DN6**
The .NET Garbage Collector (GC) is an automatic memory management system that reclaims memory occupied by objects that are no longer reachable by the application. It operates in generations to optimize collection frequency.
*   **Gen 0:** The youngest generation. Most short-lived objects are allocated here and collected frequently.
*   **Gen 1:** Acts as a buffer between Gen 0 and Gen 2. Objects surviving Gen 0 collections are promoted here.
*   **Gen 2:** Contains long-lived objects. Collections here are less frequent but more expensive.
The **Large Object Heap (LOH)** is a separate area for objects larger than a threshold (typically 85KB). Objects here are not compacted by the GC, which can lead to memory fragmentation.
`IDisposable` is used for deterministic cleanup of *unmanaged* resources (like file handles, network sockets, or database connections). You need it because the GC only manages *managed* memory; it has no knowledge of external resources that must be explicitly released.

**DN7**
`ConfigureAwait(false)` tells the runtime that the continuation of the asynchronous method does not need to resume on the original synchronization context.
*   **When to use:** In library code or infrastructure components where you do not need to interact with UI elements or request-specific context (like ASP.NET Core request context). Using it prevents deadlocks and improves performance by avoiding the overhead of capturing and restoring the context.
*   **When NOT to use:** In UI code (WPF, WinForms) or when writing code that *must* interact with the specific context it was called from (e.g., updating a UI element).
This relates to `SynchronizationContext`: when present (like in a UI thread), it captures the context. If you await without `ConfigureAwait(false)`, the runtime tries to marshal the continuation back onto that captured context.

**DN8**
*   **Primary Constructors:** Allow parameters to be defined directly in the class/struct declaration, which are automatically used to initialize properties or fields.
*   **Collection Expressions:** Provide a concise syntax (`[1, 2, 3]`) for creating collections, replacing verbose `new List<T> { ... }`.
*   **FrozenDictionary:** A dictionary whose contents cannot be changed after creation, offering thread-safe, immutable lookups with potential performance benefits over standard immutable collections.

*Minimal Example:*
```csharp
// Using primary constructor to inject ILogger and configure the service
public class UserService(ILogger<UserService> logger) 
{
    private readonly ILogger<UserService> _logger = logger;

    public void DoWork()
    {
        _logger.LogInformation("Service initialized via primary constructor.");
    }
}

// In Program.cs (Minimal API setup)
builder.Services.AddScoped<UserService>();
```

**DN9**
The likely cause is that the `DbContext` is being treated as a Singleton or is being improperly scoped across multiple concurrent requests. When high concurrency hits, multiple threads might attempt to use the same, already disposed `DbContext` instance, leading to `ObjectDisposedException`.
**Fix:** Ensure that `DbContext` is registered with the **Scoped** lifetime in the DI container (`builder.Services.AddDbContext<AppDbContext>(...)`). **DN10**
*   **Class:** A reference type. It is mutable by default. It models an entity or object that requires identity (i.e., two instances with the same data might still be considered different objects).
*   **Record:** A reference type designed for modeling immutable data. It automatically provides value-based equality (two records are equal if all their properties are equal, regardless of memory location).
*   **Record Struct:** A value type that inherits the value-based equality semantics of a record.
**Choice:** Use a `class` when identity matters (e.g., a User entity with a unique ID). Use a `record` when you are modeling data transfer objects (DTOs) or value objects where equality is based on content. Use a `record struct` for small, immutable value types where stack allocation is desired.

**DN11**
*   **`ref`:** Passes the variable by reference. The original variable can be modified inside the method, and the change persists outside. It must be initialized before the call.
*   **`out`:** Passes the variable by reference, but the method is responsible for assigning a value to it before returning. The variable does *not* need to be initialized before the call. Used when the method's primary purpose is to return multiple values.
*   **`in`:** Passes the variable by reference, but the method is restricted from modifying the original variable. It is used for performance optimization when passing large structs to avoid copying them, ensuring the data remains read-only.

**DN12**
**Nullable Reference Types (NRTs):** Enabled via `#nullable enable`. The `?` annotation (e.g., `string?`) tells the compiler that a reference type variable *might* hold `null`. The compiler then enforces null checks, preventing potential `NullReferenceException`s at compile time.
**Nullable Value Types:** (e.g., `int?`, `DateTime?`). These are structs that wrap a value type and can explicitly hold the `null` state. They are used when a value type might legitimately be absent.
The key difference is that NRTs deal with *references* (objects), while nullable value types deal with the *absence of a value* for a primitive type.

**DN13**
**LINQ (Language Integrated Query):** A set of features in C# that allows developers to write queries against various data sources (collections, databases, XML) using a unified syntax.
*   **Method Syntax:** Uses extension methods on the collection (`list.Where(x => x.Age > 30)`). This is generally preferred in modern C# as it is more fluent and composable.
*   **Query Syntax:** Uses SQL-like syntax (`from x in list where x.Age > 30 select x`). This is often preferred for readability when the query logic closely mirrors SQL.
**Deferred Execution:** When using LINQ to query collections (like `List<T>`), the query is not executed immediately upon definition. Instead, the query expression is built and only executed when the results are enumerated (e.g., in a `foreach` loop or by calling `.ToList()`).

**DN14**
Generic constraints restrict the types that can be used as type arguments for a generic type.
*   `where T : class`: T must be a reference type.
*   `where T : struct`: T must be a value type.
*   `where T : new()`: T must have a public parameterless constructor.
*   `where T : IComparable<T>`: T must implement the `IComparable<T>` interface, allowing for comparison operations.
You combine constraints (e.g., `where T : class, new()`) when the generic type needs to satisfy multiple requirements simultaneously—for instance, if you need to instantiate the type (`new()`) and ensure it is a reference type (`class`).

**DN15**
*   **Abstract Class:** A class that cannot be instantiated directly. It can contain both abstract (unimplemented) and concrete (implemented) methods. It defines a base contract and can share common implementation logic among derived classes.
*   **Interface:** A contract that defines *what* a class must do, but not *how*. It historically contained only method signatures.
**Change with Default Interface Methods (C# 8+):** Default interface methods allow interfaces to provide a default implementation for a method. This blurs the line because an interface can now provide concrete behavior, making it capable of sharing implementation logic, similar to an abstract class, though it still cannot hold state or enforce inheritance hierarchy in the same way.

**DN16**
The middleware pipeline is a series of software components (middleware) that process HTTP requests and responses sequentially in ASP.NET Core. Each middleware component has the opportunity to inspect, modify, or terminate the request/response cycle.
*   **`app.Use()`:** Registers middleware that executes in the pipeline (e.g., Authentication, Routing, CORS). It typically calls `next()` to pass control to the next component.
*   **`app.Map()`:** Used to map specific endpoints or routes to handlers, often used for lightweight, non-pipeline-altering endpoints.
*   **`app.Run()`:** Terminates the pipeline for the current request, usually used as the final endpoint handler.
**Ordering Matters:** Middleware executes in the order it is registered. For example, Authentication must run *before* Authorization.
**Exception Handling:** Exception handling middleware (e.g., `app.UseExceptionHandler()`) must be placed *early* in the pipeline so that it can catch exceptions thrown by subsequent middleware or endpoint handlers.

**DN17**
`Channel<T>` is a type-safe, asynchronous stream abstraction introduced in .NET Core. It is designed for producer-consumer scenarios, allowing multiple producers to write data and multiple consumers to read it asynchronously.
**Comparison to `BlockingCollection<T>`:** `BlockingCollection<T>` is synchronous and thread-safe, often used in older multi-threaded scenarios. `Channel<T>` is inherently asynchronous, integrates seamlessly with `async/await`, and is the modern, preferred choice for async backpressure management.
**Bounded Channel Example:** By creating a bounded channel (`Channel.CreateBounded<T>(capacity)`), you enforce backpressure. If the channel is full, the producer attempting to write to it will asynchronously await until a consumer reads an item, freeing up space.

**DN18**
**Source Generators:** A compile-time feature in .NET that allows developers to write C# code that generates other C# source code during the compilation process. This generated code is then compiled alongside the original code.
**Difference from Reflection/IL Weaving:**
*   **Reflection:** Inspects metadata at *runtime*. Slow and requires runtime overhead.
*   **IL Weaving:** Modifies the Intermediate Language (IL) *after* compilation, often requiring specialized tooling.
*   **Source Generators:** Modify the *source code* before compilation, resulting in highly optimized, statically verifiable code with zero runtime overhead.
**Incremental Generator:** An incremental generator only re-runs its logic when the specific source files it depends on have changed, rather than re-running the entire generator for every build. This significantly speeds up build times.

**DN19**
**TPL Dataflow:** A library providing powerful, composable building blocks for creating asynchronous data processing pipelines.
*   **ActionBlock:** Executes an action (a delegate) asynchronously and concurrently. It is designed to process items and execute a specific task on them.
*   **TransformBlock:** Executes an action that transforms an input item into an output item. It is used when data needs to be processed and changed as it moves through the pipeline.
*   **BufferBlock:** Acts as a queue, buffering incoming messages until a consumer is ready to process them.
**Comparison to Channels:** Channels are a simpler, lower-level stream abstraction (like a queue). TPL Dataflow provides higher-level, pre-built *processing units* (blocks) that manage concurrency, throttling, and data transformation logic automatically, making it ideal for complex, multi-stage pipelines.

**DN20**
**Minimal APIs:** A lightweight, streamlined way to build HTTP endpoints directly in the `Program.cs` file using lambda expressions and minimal boilerplate, bypassing the traditional MVC/Controller structure.
**Differences from Controllers:**
*   **Controllers:** Use classes, attributes, and MVC conventions; better separation of concerns for large applications.
*   **Minimal APIs:** Highly concise; excellent for microservices or simple APIs.
**Trade-offs:**
*   **Testability:** Controllers are often easier to mock and test in isolation. Minimal APIs can be slightly harder to test without spinning up the host environment.
*   **Middleware:** Both support middleware, but the structure is different.
*   **OpenAPI Support:** Requires explicit configuration (e.g., using Swashbuckle) in Minimal APIs, whereas controllers often integrate more naturally with standard scaffolding.
**Route Groups & Endpoint Filters:** Route groups allow applying common middleware or configuration to a set of related endpoints. Endpoint filters allow you to inject logic (like authorization checks or logging) that runs *before* or *after* the endpoint handler executes, regardless of the specific route.

**P1**
*   **List vs. Tuple:** A `list` is mutable (you can add, remove, or change elements after creation). A `tuple` is immutable (its contents cannot be changed after creation).
*   **Set vs. Frozenset:** A `set` is a mutable collection of unique, hashable items. A `frozenset` is an immutable version of a set. Frozensets can be used as elements within other sets or as dictionary keys, whereas mutable sets cannot.

**P2**
The **Global Interpreter Lock (GIL)** is a mutex that protects access to Python objects, ensuring that only one thread executes Python bytecode at any given time within a single process.
*   **Workloads Affected:** CPU-bound tasks (heavy computation, mathematical loops). Because only one thread can run bytecode at a time, threading offers no true parallelism for CPU-bound work in CPython.
*   **Workarounds:**
    1.  **Multiprocessing:** Using separate processes bypasses the GIL entirely, allowing true parallel execution across multiple CPU cores.
    2.  **I/O-bound tasks:** For tasks waiting on external resources (network, disk), the GIL is released during the wait time, allowing other threads to run, making threading effective for I/O concurrency.

**P3**
*   **Shallow Copy (`.copy()` or `copy.copy()`):** Creates a new container object, but it populates the new container with *references* to the objects found in the original. If the original object contains mutable objects (like lists), modifying those nested objects in the copy will also affect the original.
*   **Deep Copy (`copy.deepcopy()`):** Creates a completely independent copy of the original object and recursively copies all objects found within it.
**Example of Shallow Copy Issue:**
```python
original = {'a': [1, 2]}
shallow = original.copy()
shallow['a'].append(3) # Modifying the nested list
print(original) # Output: {'a': [1, 2, 3]} -> Original was modified!
```

**P4**
Decorators are syntactic sugar in Python that allow you to wrap a function or class, modifying its behavior without permanently altering its source code. They are essentially functions that take another function as an argument and return a new function.
**Logging Decorator Example:**
```python
import time
from functools import wraps

def timing_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"Function '{func.__name__}' executed in {end_time - start_time:.4f} seconds.")
        return result
    return wrapper

@timing_decorator
def calculate_heavy_thing(n):
    sum([i*i for i in range(n)])

calculate_heavy_thing(100000)
```

**P5**
**Generators and `yield`:** A generator is a special type of iterator that produces a sequence of results one at a time, on demand, using the `yield` keyword. Instead of building the entire sequence in memory, it pauses its execution state between calls and resumes exactly where it left off when the next item is requested.
**Difference from Returning a List:** Returning a list forces the entire sequence to be computed and stored in memory immediately. Generators are memory-efficient, especially for infinite or very large sequences.
**`yield from`:** This delegates the iteration to another generator or iterable. It allows a generator function to delegate iteration to a sub-generator, effectively chaining generators together seamlessly.

**P6**
The **asyncio event loop** is the core mechanism in Python's asynchronous programming. It is a single-threaded loop that manages and dispatches I/O-bound tasks. When an asynchronous function encounters an `await` call (e.g., waiting for a network response), it yields control back to the event loop, allowing the loop to switch context and run other ready tasks instead of blocking the entire thread.
*   **`asyncio.run(coro)`:** Runs the top-level coroutine and manages the event loop lifecycle (starts, runs, and closes the loop).
*   **`asyncio.gather(*coros)`:** Runs multiple awaitables concurrently and waits for all of them to complete, returning a list of their results.
*   **`asyncio.create_task(coro)`:** Schedules a coroutine to run concurrently on the event loop immediately, returning a `Task` object that can be awaited later.
**Why `time.sleep()` fails:** `time.sleep()` is a *blocking* call. When called inside an `async` function, it halts the entire thread, which in turn halts the single-threaded event loop, preventing any other scheduled tasks from running. You must use `await asyncio.sleep(delay)` instead, which is a non-blocking yield point.

**P7**
**MRO (Method Resolution Order):** The algorithm Python uses to determine the order in which base classes are searched when looking up a method or attribute in a class hierarchy.
**Algorithm:** Python 3 uses the **C3 Linearization Algorithm**. This algorithm ensures a consistent, predictable, and monotonic ordering that respects the inheritance structure, particularly handling diamond inheritance correctly.
**Diamond Inheritance Example:**
```python
class A: def who(self): return "A"
class B(A): pass
class C(A): def who(self): return "C"
class D(B, C): pass
print(D().who()) # Output: C
```
The C3 algorithm dictates that when resolving `D`, it checks `D`'s bases in order (`B`, then `C`). When it hits `B`, it checks `B`'s bases (`A`). When it hits `C`, it checks `C`'s bases (`A`). Because `C` was listed *after* `B` in the definition `class D(B, C)`, and the algorithm prioritizes the order of inheritance, it resolves the method from `C`'s path first, leading to `"C"`.

**P8**
**Metaclass:** A metaclass is the "class of a class." It controls *how* a class itself is created. When you define a class, Python calls its metaclass to construct the class object.
*   **`__init_subclass__`:** A class method available since Python 3.6. It is called automatically *after* a subclass has been created, allowing you to inspect or modify the subclass *after* it exists.
*   **Metaclass:** Controls the *creation* process itself. It is called *before* the subclass object is finalized.
**Practical Use Cases:**
*   **`__init_subclass__`:** Used for enforcing configuration or adding default methods to all subclasses (e.g., ensuring every subclass implements a specific logging method).
*   **Metaclass:** Used for fundamentally altering the structure or behavior of a class definition (e.g., automatically registering every class that inherits from a base class into a global registry upon definition).

**P9**
*   **Threading:** Uses threads within a single process. Best for I/O-bound concurrency where the GIL is released during waiting periods. Low overhead.
*   **Multiprocessing:** Uses separate OS processes. Bypasses the GIL, enabling true CPU parallelism across cores. High overhead due to process creation.
*   **`concurrent.futures`:** A high-level interface that abstracts away the complexity of managing threads or processes. It provides `ThreadPoolExecutor` (for I/O) and `ProcessPoolExecutor` (for CPU).
**When to Use:**
*   **Threading:** Concurrent I/O tasks (e.g., fetching 10 URLs).
*   **Multiprocessing:** CPU-intensive calculations (e.g., image processing).
*   **`concurrent.futures`:** When you want a unified, clean API to choose between thread or process execution based on the workload.
**Serialization Implications:** Multiprocessing requires data passed between processes to be serialized (pickled). This serialization/deserialization adds overhead and limits the types of objects that can be safely passed.

**P10**
`__slots__` is a class attribute that tells Python not to use a dynamic dictionary (`__dict__`) to store instance attributes. Instead, it reserves a fixed, predefined set of slots for attributes.
**When to Use:** When creating classes that are instantiated millions of times (e.g., data points, nodes in a graph) where memory footprint is critical.
**What it Prevents:** It prevents the creation of `__dict__` for instances of that class, which saves memory. It also prevents the dynamic addition of new attributes to an instance after it has been created.
**Memory Impact:** Significant memory reduction, as the overhead of the instance dictionary is eliminated.

**P11**
A **virtual environment** is an isolated directory that contains a specific Python interpreter installation and its own set of installed packages.
**Why Use One:** It prevents dependency conflicts between different projects. Project A might require Django 2.0, while Project B requires Django 4.0. Virtual environments allow both projects to exist on the same machine without interfering with each other's dependencies.
**Differences:**
*   **`venv`:** The standard, built-in module in Python 3.
*   **`virtualenv`:** An older, third-party tool that is more feature-rich and compatible with older Python versions than `venv`.
*   **`conda`:** A comprehensive environment and package manager (often used in data science) that manages not just Python packages but also non-Python dependencies (like specific versions of NumPy compiled against specific C libraries).

**P12**
*   **List Comprehension:** `[expression for item in iterable if condition]` (Creates a list).
*   **Dict Comprehension:** `{key: value for item in iterable if condition}` (Creates a dictionary).
*   **Set Comprehension:** `{expression for item in iterable if condition}` (Creates a set).
**Relation to `map()` and `filter()`:** Comprehensions are syntactic sugar that combine the functionality of `map()` (transformation) and `filter()` (selection) into a single, readable line.
**Preference:** Comprehensions are generally preferred in modern Python because they are more concise, idiomatic, and often easier to read than chaining `map()` and `filter()` calls.

**P13**
*   **`==` (Equality Operator):** Compares the *values* of two objects. It calls the object's `__eq__` method.
*   **`is` (Identity Operator):** Compares the *identity* of two objects. It checks if both variables point to the exact same object in memory (i.e., if `id(a) == id(b)`).
**Object Interning:** A memory optimization technique where Python pre-allocates and reuses immutable objects (like small integers, short strings) to save memory and speed up comparisons.
**Small Integers:** Python often interns integers in the range of -5 to 256. Therefore, `a = 100` and `b = 100` will point to the same object in memory, causing `a is b` to return `True`, even though they are distinct variables.

**P14**
*   **`*args`:** Collects an arbitrary number of positional arguments into a tuple.
*   **`**kwargs`:** Collects an arbitrary number of keyword arguments into a dictionary.
*   **Positional-Only (`/`):** Arguments placed before `/` must be passed by position and cannot be passed using a keyword (e.g., `def func(a, b, /):`).
*   **Keyword-Only (`*`):** Arguments placed after `*` must be passed using their keyword name (e.g., `def func(*, c, d):`).
This allows for precise control over how a function must be called, improving API stability and clarity.

**P15**
**Context Managers (`with` statement):** A mechanism that ensures setup and teardown actions are executed reliably, even if errors occur within the block.
*   **`__enter__` / `__exit__`:** The standard way to implement a context manager by defining these two dunder methods in a class. `__enter__` runs on entry (returns the resource), and `__exit__` runs on exit (handles cleanup, receiving exception details).
*   **`@contextmanager`:** A simpler decorator from the `contextlib` module. It uses a `yield` statement. The code before `yield` is the setup (`__enter__`), and the code after `yield` is the teardown (`__exit__`).
**Example Beyond File Handling:** Managing a database transaction. The setup is `connection.begin()`, and the teardown (in `__exit__`) is `connection.commit()` or `connection.rollback()` if an exception occurred.

**P16**
**Type Hinting:** The practice of using annotations (e.g., `name: str`, `age: int`) to indicate the expected types of variables, function arguments, and return values. It does *not* enforce types at runtime; it is metadata for static analysis tools.
*   **`typing.Union[A, B]`:** Indicates a variable can be of type A OR type B.
*   **`Optional[T]`:** A shorthand for `Union[T, None]`.
*   **`Literal[value]`:** Restricts a variable to only accept a specific, fixed set of constant values (e.g., `Literal["read", "write"]`).
*   **`TypeVar`:** A placeholder for a type variable, used to write generic functions or classes that maintain type safety across different types.
*   **`Protocol`:** Defines a structural type. Instead of inheriting from a base class, a class conforms to a `Protocol` if it implements all the methods/attributes defined in that protocol (Duck Typing enforced statically).
**Static Analysis:** Tools like Mypy or Pyright read these hints and check the code *before* execution. If you try to pass an integer where a string is hinted, the tool raises a static type error.

**P17**
**Data Model (Dunder Methods):** These are special methods (like `__init__`, `__str__`) that Python calls automatically when specific operations are performed on an object.
*   **`__repr__` vs `__str__`:** `__repr__` (representation) is intended for developers; it should return an unambiguous string that, ideally, could recreate the object (`repr(obj)`). `__str__` (string) is for end-users; it should return a readable, informal string (`print(obj)`).
*   **`__eq__` vs `__hash__`:** `__eq__` defines value equality (when two objects are considered equal). `__hash__` generates an integer hash value for the object.
**If `__eq__` is defined but not `__hash__`:** Python will raise a `TypeError` if you try to use that object as a key in a dictionary or add it to a set. This is because the fundamental contract of hashable objects is that if two objects are equal (`a == b`), they *must* produce the same hash (`hash(a) == hash(b)`).

**P18**
**Descriptors:** Objects in Python that define how attribute access (getting, setting, or deleting) works for other objects. They implement the descriptor protocol.
**Descriptor Protocol:** A descriptor object must implement one or more of these methods:
*   `__get__(self, instance, owner)`: Called when the attribute is accessed.
*   `__set__(self, instance, value)`: Called when the attribute is assigned a value.
*   `__delete__(self, instance)`: Called when the attribute is deleted.
**How Built-ins Use Them:**
*   **`property`:** Uses descriptors to manage attribute access, allowing you to define getters, setters, and deleters for an attribute.
*   **`classmethod`:** Uses descriptors to ensure the method is bound to the class, not the instance.
*   **`staticmethod`:** Uses descriptors to ensure the method is bound neither to the class nor the instance, behaving like a regular function within the class namespace.

**P19**
**Import System:** Python uses a sophisticated system to locate and load modules. When `import module_name` is called, Python searches directories listed in `sys.path`.
*   **Relative Imports:** Imports within the same package structure, using dots (e.g., `from . import utils` or `from ..models import User`). They require the module to be part of a package.
*   **Absolute Imports:** Imports starting from the top-level package name (e.g., `from my_app.utils import helper`).
**Components:**
*   **`sys.path`:** A list of directories Python searches when resolving imports.
*   **`PYTHONPATH`:** An environment variable that adds directories to `sys.path` before the script runs.
*   **`__init__.py`:** Historically marked a directory as a Python package. While less strictly required in modern Python (namespace packages), it still plays a role in package initialization.
*   **Namespace Packages:** Allow multiple, unrelated packages to contribute to the same top-level namespace without being physically located in the same directory.
**Finder and Loader:** A **Finder** is responsible for locating the module (i.e., finding the correct path). A **Loader** is responsible for loading the module's code into memory and executing it.

**P20**
**Dataclasses:** A decorator (`@dataclass`) that automatically generates boilerplate methods (like `__init__`, `__repr__`, `__eq__`) for classes primarily used to hold data.
**Comparison:**
*   **`attrs`:** A mature, highly configurable library that predates dataclasses and offers deep customization.
*   **Pydantic:** A library focused on data validation and serialization. It uses type hints to enforce structure *and* validates incoming data against those types (e.g., ensuring a string field is actually a valid email format).
**Features:**
*   **`__post_init__`:** A method called immediately after `__init__` finishes, allowing for post-initialization logic (e.g., calculating a derived field).
*   **Field Factories:** Using `field(default_factory=list)` allows you to provide mutable default values safely, preventing all instances from sharing the same list object.
*   **Frozen Dataclasses:** Setting `frozen=True` makes the instance immutable, similar to a `dataclass` record in C#.
**Inheritance:** Dataclasses support inheritance, but you must be careful with `__init__` generation; often, you need to manually define `__init__` or use `__post_init__` to handle inherited fields correctly.
**When to Choose Pydantic:** Choose Pydantic when the data coming into your system (API requests, configuration files) needs to be *validated* against a strict schema. Choose dataclasses when you are modeling internal, trusted data structures where validation is handled elsewhere.
