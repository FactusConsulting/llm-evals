**Networking Answers**

N1 — A Layer 2 switch operates at the Data Link Layer (L2) and uses MAC addresses to forward frames within a single broadcast domain (VLAN). A Layer 3 switch operates at the Network Layer (L3) and uses IP addresses to route packets between different subnets, effectively combining the high-speed switching capabilities of L2 with the routing intelligence of a router.

N2 — The subnet mask for /20 is 255.255.240.0.
*   **Network Address:** 10.0.0.0
*   **Broadcast Address:** 10.0.15.255

N3 — The TCP three-way handshake establishes a connection:
1.  **SYN (Synchronize):** Client sends a SYN packet to the server, proposing an initial sequence number (ISN).
2.  **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and replies with a SYN-ACK, acknowledging the client's ISN and proposing its own ISN.
3.  **ACK (Acknowledge):** Client receives SYN-ACK and sends a final ACK, confirming the connection parameters.
If the final ACK is lost, the client will not receive a response and will eventually time out, triggering a retransmission of the final ACK (or the entire segment, depending on the implementation), leading to connection delays.

N4 — **SNAT (Source Network Address Translation):** Translates the source IP address of a packet as it leaves a private network, typically to allow multiple internal hosts to share a single public IP when accessing the internet. *Example: A laptop (10.0.0.5) accessing Google uses the router's public IP as its source address.*
**DNAT (Destination Network Address Translation):** Translates the destination IP address of a packet as it enters a private network, typically to direct external traffic to a specific internal server. *Example: An external user accessing a web server at the public IP 203.0.113.10 is redirected by the firewall to the internal server 192.168.1.5.*

N5 — Three possible causes for `SSL: certificate subject name does not match target host name`:
1.  **Hostname Mismatch:** The domain name used in the browser/curl command does not exactly match the Common Name (CN) or Subject Alternative Name (SAN) listed in the certificate.
2.  **Incorrect Configuration:** The web server (e.g., Apache/Nginx) is configured to serve the certificate for the wrong hostname.
3.  **Certificate Issuance Error:** The certificate was issued for a different domain entirely.

N6 — **VLAN (Virtual Local Area Network):** A logical segmentation mechanism operating at Layer 2, using 802.1Q tagging to segment broadcast domains within a single physical switch infrastructure. VLANs are limited to 4094 segments.
**VxLAN (Virtual Extensible LAN):** A network virtualization overlay technology that encapsulates Layer 2 Ethernet frames within a Layer 3 UDP/IP packet. This allows L2 segments to span across large, multi-subnet L3 networks.
You would choose VxLAN over VLAN when you need to extend Layer 2 adjacency (e.g., VM mobility) across a large, geographically dispersed, or complex L3 spine-and-leaf network, overcoming the 4094 segment limit of VLANs.

N7 — This occurs because the host's routing table defaults to using the primary interface (eth0) for all traffic unless a specific route dictates otherwise. The kernel sees the destination (192.168.1.x) as reachable via the default gateway (10.0.0.1) because the default route is on eth0.
**Fix using Policy-Based Routing (PBR):**
1.  Create a new routing table (e.g., `table 100`).
2.  Add a specific route to this new table pointing traffic destined for 192.168.1.0/24 out via eth1's gateway.
3.  Create a routing rule (`ip rule`) that directs all traffic originating from the 192.168.1.0/24 subnet to use `table 100`.

N8 — BGP path selection is a complex decision process used by routers to determine the best path to a destination prefix. The attributes are evaluated sequentially; the first attribute that provides a definitive preference determines the path.
**Order of Preference (Top 5):**
1.  **Weight** (Cisco proprietary, highest preference)
2.  **Local Preference** (Highest preferred within an AS)
3.  **AS Path Length** (Shorter path is preferred)
4.  **Origin Code** (IGP > EGP > Incomplete)
5.  **MED (Multi-Exit Discriminator)** (Lower is preferred, used to influence external peers)

N9 — When running VxLAN over an IPsec tunnel, the encapsulation adds significant overhead:
*   Inner Payload (Original L2 Frame)
*   VxLAN Header (8 bytes)
*   UDP Header (8 bytes)
*   Outer IP Header (20 bytes)
*   IPsec Overhead (ESP/AH headers + padding/ICV, typically 30-50 bytes)
If the physical MTU is 1500 bytes, the maximum inner payload is calculated by subtracting all overheads from 1500. Assuming a conservative IPsec overhead of 40 bytes:
$1500 - (\text{VxLAN} + \text{UDP} + \text{Outer IP} + \text{IPsec}) = 1500 - (8 + 8 + 20 + 40) = 1500 - 76 = 1424$ bytes.

N10 — **ARP (Address Resolution Protocol):** ARP is used to map a known Layer 3 IP address to its corresponding Layer 2 MAC address on a local network segment.
**Gratuitous ARP:** This is an ARP request sent by a host to itself (or broadcasted without a specific request). It solves the problem of stale ARP caches. It is used proactively when a host changes its IP address or MAC address, forcing neighboring devices to update their ARP tables immediately, preventing communication failures.

N11 — **Public IP Address:** An IP address globally unique and routable across the public internet.
**Private IP Address:** An IP address reserved for use within private, internal networks (LANs) and is not routable on the public internet.
**RFC 1918 Private IPv4 Ranges:**
1.  10.0.0.0 to 10.255.255.255 (Class A private)
2.  172.16.0.0 to 172.31.255.255 (Class B private)
3.  192.168.0.0 to 192.168.255.255 (Class C private)

N12 — **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses.
*   **A Record:** Maps a domain name to an IPv4 address (e.g., `example.com` $\rightarrow$ 192.0.2.1).
*   **CNAME Record:** Creates an alias, mapping one domain name to another domain name (e.g., `blog.example.com` $\rightarrow$ `example.com`).
*   **AAAA Record:** Maps a domain name to an IPv6 address.

N13 — **DHCP (Dynamic Host Configuration Protocol):** A network management protocol that automatically assigns IP addresses and other network configuration parameters (subnet mask, gateway, DNS servers) to devices on a network.
**DORA Process:**
1.  **Discover:** Client broadcasts a DHCP Discover message to find available servers.
2.  **Offer:** Server replies with a DHCP Offer, proposing an IP address and lease terms.
3.  **Request:** Client broadcasts a DHCP Request, formally accepting the offered IP address.
4.  **Acknowledge:** Server replies with a DHCP ACK, finalizing the lease and configuration.

N14 — **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming data to every connected port, creating a single collision domain.
**Switch:** Operates at Layer 2 (Data Link). It learns MAC addresses and forwards frames only to the intended destination port, segmenting collision domains.
**Router:** Operates at Layer 3 (Network). It uses IP addresses to determine the best path for packets to travel between different networks (subnets).

N15 — **Half-Duplex:** Allows data to travel in both directions, but only one direction at a time (e.g., a walkie-talkie).
**Full-Duplex:** Allows data to travel simultaneously in both directions (e.g., a telephone call).
Modern Ethernet links overwhelmingly use **Full-Duplex** communication.

N16 — **TTL (Time To Live):** A field in the IP header that limits the lifespan of a packet. Each router that forwards the packet decrements the TTL by one. If the TTL reaches zero, the router discards the packet and sends an ICMP Time Exceeded message back to the source.
**Traceroute Exploitation:** Traceroute works by sending a sequence of packets (usually UDP or ICMP) with incrementally increasing TTL values (starting at 1). When the first router receives the packet with TTL=1, it drops it and sends an ICMP Time Exceeded message back, revealing the identity of the first hop. This process continues until the destination is reached.

N17 — **NAT Gateway:** A device (usually a router or firewall) that translates private, non-routable IP addresses used internally into one or more public, routable IP addresses when communicating with the external internet.
*   **Static NAT:** A one-to-one, permanent mapping between a specific private IP and a specific public IP. (e.g., 192.168.1.10 $\leftrightarrow$ 203.0.113.10).
*   **Dynamic NAT:** Maps private IPs to a pool of available public IPs on a first-come, first-served basis.
*   **PAT (Port Address Translation) / NAT Overload:** Maps many private IPs to a single public IP by tracking unique source port numbers for each internal connection. This is the most common form of NAT.

N18 — **ECMP (Equal-Cost Multi-Path):** A routing technique that allows a router to install multiple next-hop paths into the routing table for the same destination prefix, provided all paths have the same administrative cost. Traffic is distributed across these paths.
**Hashing Strategies:** Common strategies hash the packet headers (e.g., Source IP, Destination IP, Source Port, Destination Port) to ensure that all packets belonging to the same flow (session) consistently take the same path.
**Asymmetric Flow Problem:** If a stateful firewall is involved, asymmetric routing occurs when the outbound packet takes Path A, but the return packet takes Path B. The firewall maintains a state table based on the initial session setup (Path A). When the return packet arrives via Path B, the firewall does not recognize the session state and drops the packet, breaking the connection.

N19 — **Bandwidth-Delay Product (BDP):** BDP = Bandwidth $\times$ Round Trip Time (RTT). It represents the maximum amount of unacknowledged data that can be "in flight" on the network pipe at any given time.
**The Problem:** If the TCP window size (the amount of data the sender can transmit before receiving an ACK) is smaller than the BDP, the sender will transmit data, but the pipe will fill up before the sender can transmit enough data to keep the pipe full. The connection stalls, leading to high latency even if the network link is fast.
**Solution (Window Scaling):** TCP Window Scaling (RFC 1323) extends the standard 16-bit TCP window field to 32 bits. This allows the sender and receiver to negotiate a much larger advertised window size, enabling the sender to fill the entire BDP capacity of the link, thus maximizing throughput and minimizing latency.

N20 — **802.1Q Trunk Ports:** This standard allows multiple VLANs to traverse a single physical link. It achieves this by inserting a 4-byte tag (the VLAN ID) into the Ethernet frame header.
**Linux Configuration (Sub-interfaces):** A single physical interface (`eth0`) is configured with multiple virtual sub-interfaces, each bound to a specific VLAN ID:
`sudo ip link add link eth0 name eth0.10 type vlan id 10`
`sudo ip addr add 10.0.10.5/24 dev eth0.10`
(Repeat for VLAN 20 and 30).
**Frame Format on the Wire:** The frame structure is: Ethernet Header $\rightarrow$ **802.1Q Tag (VLAN ID)** $\rightarrow$ Original Ethernet Header $\rightarrow$ Payload.

**Linux Answers**

L1 — **Hard Link:** A hard link is a directory entry that points directly to the same inode (the data structure containing file metadata and data blocks) as the original file. If you delete the original file, the data remains accessible via the hard link until the last link is removed. They share the same data.
**Symbolic Link (Symlink):** A symbolic link is a special file that contains a text path pointing to another file or directory. It is a pointer, not a pointer to the data itself. If the original file is moved or deleted, the symlink breaks (dangling link).

L2 — `find /var/log -type f -size +100M`

L3 — State D (Uninterruptible Sleep) means the process is blocked waiting for an I/O operation to complete (e.g., waiting for a disk read or network response). The kernel cannot interrupt this wait state because it is waiting on hardware, not a software signal. Therefore, `kill -9` (SIGKILL) will fail to terminate the process until the underlying I/O operation completes.

L4 — **cgroups v1:** Uses a hierarchical structure where controllers (like CPU, Memory) are mounted separately. It is less unified and can lead to complexity when managing resources across different controllers.
**cgroups v2:** Implements a unified hierarchy and a unified control plane. All controllers share a single hierarchy, making resource management simpler, more consistent, and more efficient.
Systemd prefers cgroups v2 because its unified model provides a cleaner, more predictable, and more robust framework for managing the lifecycle and resource constraints of services and containers.

L5 — **iptables:** The older, traditional firewall framework that uses Netfilter hooks within the Linux kernel. It is powerful but can become complex due to its multiple table/chain structure.
**nftables:** The modern replacement for iptables. It is a unified framework that simplifies the syntax, uses a single table structure, and is designed to be more flexible and performant.
The kernel handles both via the **Netfilter** framework. While `iptables` commands still often work via compatibility layers, `nftables` is the modern, native implementation path for firewall rules in the kernel.

L6 — The most likely cause is that the filesystem usage is being inflated by **inodes** or **deleted files held open by a running process**. If a process deletes a large file but keeps the file descriptor open, the space is marked as free by the process but still counts against the filesystem usage until the process releases the descriptor.

L7 — **UEFI Firmware:** Initializes hardware and locates the bootloader.
**Bootloader (e.g., GRUB):** Reads the kernel image and passes necessary parameters to it.
**Kernel:** Loads into memory, initializes core subsystems (memory management, process scheduling), and mounts the initial root filesystem.
**Initramfs (Initial RAM Filesystem):** A small, temporary root filesystem loaded into RAM. Its purpose is to contain the necessary drivers and scripts to mount the *real* root filesystem (which might be on a complex device like LVM or encrypted).
**Root Filesystem:** The kernel mounts the actual, persistent root partition.
**Systemd:** The `init` system takes over. Systemd reads configuration files, starts essential services, and transitions the system through various targets (e.g., multi-user.target, graphical.target) until the system is fully operational.

L8 — The `available` memory metric is calculated as `free` memory plus reclaimable `buff/cache`. However, if the system is under extreme memory pressure, the kernel might determine that even the reclaimable cache is insufficient to satisfy a large, contiguous memory request from a new process, leading to the OOM killer firing.
**Kernel Tunables:** `vm.swappiness` controls the kernel's tendency to swap out anonymous memory. A lower value (e.g., 10) tells the kernel to prefer dropping caches over swapping, while a higher value (e.g., 60) encourages swapping sooner. `vm.min_free_kbytes` sets the minimum amount of memory the kernel must keep free.

L9 — **`ip netns`** is used to manage **network namespaces**. A network namespace provides a complete isolation boundary for networking resources (network interfaces, routing tables, firewall rules, sockets).
Container runtimes (like Docker or Kubernetes) use network namespaces to give each container its own isolated network stack. When a container starts, it is placed into a new network namespace, meaning its network configuration is completely separate from the host's network configuration.

L10 — **SIGTERM (Signal Terminate):** The standard, polite request for a process to shut down. It allows the process to catch the signal, clean up resources (save state, close files), and exit gracefully. **Catchable.**
**SIGKILL (Signal Kill):** A non-catchable, immediate termination signal sent directly to the kernel. The process is stopped instantly without any chance to clean up. **Uncatchable.**
**SIGQUIT (Signal Quit):** Requests the process to quit and typically generates a core dump file, allowing developers to debug the state of the process at the time of termination. **Catchable.**

L11 — **STDOUT (Standard Output, FD 1):** The primary stream for normal program output.
**STDERR (Standard Error, FD 2):** The stream reserved for error messages and diagnostic output.
**STDIN (Standard Input, FD 0):** The stream from which the program reads input (usually the keyboard).
To redirect stderr to a file while displaying stdout on the terminal: `command 2> error.log`. (This redirects FD 2, leaving FD 1 untouched).

L12 — `chmod 755` sets permissions as follows:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = rwx
*   **5 (Group):** Read (4) + Execute (1) = r-x
*   **5 (Others):** Read (4) + Execute (1) = r-x
This grants the owner full control, while the group and others can read and execute the file/directory.

L13 — **Root User:** Has absolute, unrestricted privileges over the entire operating system. It can modify any file, change any configuration, and manage any process without restriction.
**Sudo Privileges:** A standard user granted the ability to execute *specific* commands with elevated privileges, as defined in the `/etc/sudoers` file. This is a controlled, audited mechanism that limits the user's power compared to the root user.

L14 — A package manager is a system utility that automates the process of installing, upgrading, configuring, and removing software packages while automatically resolving and managing dependencies between those packages.
*   **Debian/Ubuntu:** APT (Advanced Package Tool)
*   **RHEL/Fedora:** DNF (Dandified YUM)

L15 — The `/etc/fstab` (filesystem table) file contains static configuration information that tells the operating system which filesystems (local disks, network shares, etc.) to mount at boot time, along with their mount points and options.
If an entry is misconfigured (e.g., incorrect UUID, wrong filesystem type, or incorrect mount point), the system may fail to boot completely, or it may boot but fail to mount critical partitions or network resources, leading to an unstable or unusable system.

L16 — **LVM (Logical Volume Manager):** An abstraction layer that pools physical storage devices into flexible volumes, allowing administrators to manage storage dynamically without being tied to the physical layout of the disks.
*   **Physical Volume (PV):** A physical storage device (disk or partition) that is designated to be used by LVM.
*   **Volume Group (VG):** A pool of one or more PVs. It represents the total available storage capacity.
*   **Logical Volume (LV):** A virtual partition carved out of a VG. This is the volume that the operating system sees and mounts.
**Extending an LV:** First, extend the VG if necessary (by adding more PVs). Then, use `lvextend -L +[size] /dev/VG_NAME/LV_NAME`. Finally, resize the filesystem *on* the LV using `resize2fs /dev/VG_NAME/LV_NAME` (or `xfs_growfs` for XFS).

L17 — The I/O scheduler manages the queue of pending read/write requests to a block device, deciding the optimal order to service them to optimize for throughput, latency, or fairness.
*   **mq-deadline:** Prioritizes requests based on deadlines, balancing throughput and low latency. Good for mixed workloads.
*   **bfq (Budget Fair Queueing):** Focuses on fairness and latency, ensuring that interactive processes receive timely service. Excellent for desktop/interactive workloads.
*   **none:** Passes I/O requests directly to the device driver without reordering. Best for modern, high-performance storage like NVMe, where the device controller handles scheduling internally.
**Changing Scheduler:** At runtime, you change it by writing the desired scheduler name to the device's scheduler file: `echo bfq > /sys/block/sdX/queue/scheduler`.

L18 — **Load Average:** Measures the average number of processes that are either currently running on a CPU or are in an uninterruptible sleep state (D state, waiting for I/O). It is a measure of system *activity* and *contention*, not just CPU utilization.
**I/O Wait Inflation:** When processes are stuck in the D state waiting for slow disk or network I/O, they contribute to the load average count, even though they are not consuming CPU cycles. This inflates the load average, making the system *appear* busy even if `top` shows low CPU usage.
**Diagnosis:**
*   **Disk Bottleneck:** Use `iostat -x 1` to check `%util` (utilization) and average wait times for the disk devices.
*   **CPU Bottleneck:** Use `top` or `htop` to check `%us` (user) and `%sy` (system) CPU usage.
*   **Network Bottleneck:** Use `ss -s` or `netstat -s` to check for high queue depths or errors on network interfaces.

L19 — **SELinux (Security-Enhanced Linux):** Implements Mandatory Access Control (MAC). Unlike standard Discretionary Access Control (DAC, which relies on user/group permissions), SELinux enforces system-wide policies that dictate exactly what a process (subject) is allowed to do to a resource (object), regardless of the owner's permissions.
*   **Enforcing Mode:** SELinux actively denies any action that violates the defined policy.
*   **Permissive Mode:** SELinux logs all policy violations (AVC denials) but allows the action to proceed. This is used for auditing.
*   **Disabled Mode:** SELinux is completely inactive, relying only on standard DAC.
**Troubleshooting:** If a daemon fails to bind a port, check the audit logs (`/var/log/audit/audit.log`) for an **AVC denial**. The denial message will specify the required permission. You then use `semanage` or policy tools to create a specific policy exception (e.g., allowing the daemon context to bind to that port).

L20 — A **Page Fault** occurs when a process attempts to access a virtual memory address whose corresponding page is not currently mapped into physical RAM.
*   **Minor Page Fault:** The required page is not in RAM but is already present in the system's page cache (e.g., swapped out to the swap partition or file cache). The kernel can resolve this quickly by simply remapping the page in memory.
*   **Major Page Fault:** The required page is not in RAM and is not in the cache. The kernel must initiate a slow I/O operation to load the page from secondary storage (disk/swap) into physical RAM.
**THP (Transparent Huge Pages):** THP automatically merges small, standard 4KB memory pages into large 2MB or 1GB pages. This reduces the overhead associated with the Translation Lookaside Buffer (TLB) misses, improving performance for memory-intensive applications.
**When to Disable:** THP can introduce unpredictable latency spikes (latency jitter) during the background compaction process. It should be disabled when applications have highly random memory access patterns or require strict, predictable low-latency performance.
