**Networking Answers**

N1 — A Layer 2 switch operates at the Data Link Layer (Layer 2) and forwards frames based on MAC addresses within the same broadcast domain. A Layer 3 switch operates at the Network Layer (Layer 3) and can route packets between different IP subnets, performing routing functions like a traditional router, but often with higher throughput due to specialized hardware.

N2 — IP: 10.0.5.37/20.
The subnet mask for /20 is 255.255.240.0.
Network Address: 10.0.5.0
Broadcast Address: 10.0.15.255

N3 — The TCP three-way handshake establishes a connection:
1. **SYN (Synchronize):** Client sends a SYN packet to the server, proposing an initial sequence number (ISN).
2. **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and replies with a SYN-ACK, acknowledging the client's SYN and sending its own ISN.
3. **ACK (Acknowledge):** Client receives SYN-ACK and sends a final ACK, acknowledging the server's ISN.
If the final ACK is lost, the client will retransmit the ACK (or the server will time out and retransmit the SYN-ACK), leading to connection timeouts on the client side until the retransmission succeeds or the connection attempt fails.

N4 — **SNAT (Source Network Address Translation):** Translates the source IP address of a packet as it leaves a private network to a public IP address. *Example:* A host (10.0.0.5) accessing the internet uses the firewall's public IP as its source address.
**DNAT (Destination Network Address Translation):** Translates the destination IP address of a packet as it enters a private network. *Example:* An external user accessing a web server at the public IP (203.0.113.10) is redirected by the firewall to the internal server's private IP (192.168.1.5).

N5 — 3 possible causes:
1. **Hostname Mismatch:** The certificate was issued for a different domain name than the one being accessed (e.g., certificate for `dev.example.com` accessed via `example.com`).
2. **Expired Certificate:** The certificate has passed its validity date.
3. **Incorrect Configuration:** The server is presenting the wrong certificate file or the certificate chain is incomplete/broken.

N6 — **VLAN (Virtual Local Area Network):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains based on a tag (802.1Q) within a single physical switch infrastructure.
**VxLAN (Virtual Extensible LAN):** An overlay networking technology that encapsulates Layer 2 Ethernet frames within Layer 3 UDP packets.
**When to choose VxLAN:** When you need to extend Layer 2 segments (broadcast domains) across a large, multi-subnet, or geographically dispersed data center fabric (i.e., when VLAN limits of 4094 are insufficient, or when routing between segments is required).

N7 — **Why:** The host is using its default routing table, which points to the 10.0.0.1 gateway (eth0). When traffic arrives on eth1 (192.168.1.x), the kernel determines the return path based on the destination IP's subnet, which is 192.168.1.0/24. Since the default route is active, the kernel might incorrectly route the return traffic back through the default gateway (eth0) if the routing logic isn't explicitly aware of the ingress interface's subnet.
**Fix (Policy-Based Routing - PBR):** Use `ip rule` and `ip route` to define a specific routing table for traffic originating from or destined for the 192.168.1.0/24 subnet, forcing the return traffic to use the eth1 interface.
*Example:* `ip rule add from 192.168.1.0/24 table 100` and `ip route add default via 192.168.1.1 dev eth1 table 100`.

N8 — BGP path selection is a complex decision process used by routers to choose the best path to a destination prefix from multiple available routes. The attributes are evaluated sequentially.
**5 Attributes in Preference Order (Simplified):**
1. **Weight** (Cisco proprietary, highest preference)
2. **Local Preference** (Highest is preferred, used internally)
3. **AS Path Length** (Shortest path is preferred)
4. **Origin Type** (IGP > EGP > Incomplete)
5. **MED (Multi-Exit Discriminator)** (Lowest is preferred, used by external peers)

N9 — **MTU Implication:** When VxLAN (Layer 2 frame) is encapsulated inside an IPsec tunnel (Layer 3/4), the packet size increases due to the outer IP header, the UDP header (if used), and the IPsec overhead (ESP/AH headers and padding).
**Math:**
*   Physical MTU = 1500 bytes.
*   VxLAN Header Overhead $\approx 50$ bytes (VNI, UDP/IP headers).
*   IPsec Overhead (ESP/AH) $\approx 50-70$ bytes.
*   Maximum Inner Payload = Physical MTU - (VxLAN Overhead + IPsec Overhead)
*   Maximum Inner Payload $\approx 1500 - (50 + 70) = 1380$ bytes.

N10 — **ARP (Address Resolution Protocol):** Maps a known Layer 3 IP address to its corresponding Layer 2 MAC address on a local network segment. It works by broadcasting an ARP request asking, "Who has this IP? Tell me your MAC."
**Gratuitous ARP:** A host sends an ARP request for its *own* IP address. This solves problems like:
1. **Duplicate IP Detection:** If another host responds, the sender knows its IP is already in use.
2. **Cache Refresh:** It forces neighboring devices (switches/hosts) to immediately update their ARP caches with the host's current MAC address, which is crucial after a host changes its MAC or moves to a new port.

N11 — **Public IP:** Globally unique address routable across the public internet.
**Private IP:** Non-globally unique addresses reserved for use within private networks (LANs) and are not routable on the public internet without NAT.
**RFC 1918 Ranges:**
1. 10.0.0.0 to 10.255.255.255 (/8)
2. 172.16.0.0 to 172.31.255.255 (/12)
3. 192.168.0.0 to 192.168.255.255 (/16)

N12 — **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses (like 93.184.216.34).
**A Record:** Maps a hostname to an IPv4 address (e.g., `www.example.com` $\rightarrow$ 192.0.2.1).
**CNAME Record:** Creates an alias, mapping one domain name to another canonical domain name (e.g., `blog.example.com` $\rightarrow$ `servers.example.com`).
**AAAA Record:** Maps a hostname to an IPv6 address.

N13 — **DHCP (Dynamic Host Configuration Protocol):** A network management protocol used to automatically assign IP addresses and other network configuration parameters (subnet mask, gateway, DNS servers) to devices on a network.
**DORA Process:**
1. **Discover:** Client broadcasts a DHCP Discover message to find available servers.
2. **Offer:** Server responds with a DHCP Offer, proposing an IP address and configuration.
3. **Request:** Client broadcasts a DHCP Request, formally accepting the offered configuration.
4. **Acknowledge:** Server sends a DHCP ACK, finalizing the lease and configuration.

N14 — **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming electrical signals out of every other port, creating one large collision domain.
**Switch:** Operates at Layer 2 (Data Link). It learns MAC addresses and forwards frames only to the intended destination port, segmenting collision domains.
**Router:** Operates at Layer 3 (Network). It forwards packets between different IP networks based on IP addresses, creating separate broadcast domains.

N15 — **Half-Duplex:** Allows data transmission in both directions, but only one direction at a time (e.g., a walkie-talkie). Collisions can occur.
**Full-Duplex:** Allows simultaneous data transmission and reception over the same link (e.g., a phone call). Collisions are eliminated.
Modern Ethernet links use **Full-Duplex** communication.

N16 — **TTL (Time To Live):** A field in the IP header that specifies the maximum number of hops (routers) a packet can traverse before being discarded. It prevents packets from circulating indefinitely in routing loops.
**Traceroute Exploitation:** Traceroute works by sending a sequence of packets (usually UDP or ICMP) with incrementally increasing TTL values (starting at 1). When the packet reaches the first router, the TTL expires, and the router sends back an ICMP "Time Exceeded" message, revealing the router's IP address. This process is repeated until the destination is reached.

N17 — **NAT Gateway:** A device (usually a firewall or router) that performs Network Address Translation, allowing multiple private IP addresses to share a single public IP address when communicating with the outside world.
**Static NAT:** A one-to-one, permanent mapping. A specific private IP is always mapped to a specific public IP (e.g., 192.168.1.10 $\leftrightarrow$ 203.0.113.10). Used for servers.
**Dynamic NAT:** Maps private IPs to a pool of available public IPs on a first-come, first-served basis.
**PAT (Port Address Translation) / NAT Overload:** Maps multiple private IPs to a single public IP by tracking unique source port numbers. This is the most common form of NAT used in homes/offices.

N18 — **ECMP (Equal-Cost Multi-Path):** A routing technique that allows a router to install multiple paths to the same destination prefix if those paths have the same routing metric (cost). The router distributes traffic across these equal-cost links, increasing aggregate bandwidth.
**Hashing Strategies:** Common strategies include hashing based on the 5-tuple (Source IP, Destination IP, Source Port, Destination Port, Protocol).
**Asymmetric Flow Problem:** If a stateful firewall is involved, traffic might enter via Path A (e.g., Link 1) but the return traffic might exit via Path B (e.g., Link 2) due to ECMP load balancing. The firewall, which maintains state based on the ingress interface, may drop the return packet because it never saw the initial connection setup on the egress interface, causing connection failure.

N19 — **Problem:** The TCP window size dictates the maximum amount of unacknowledged data a sender can transmit before receiving an ACK. The Bandwidth-Delay Product (BDP) is the maximum amount of data that can be "in flight" on the network path ($BDP = Bandwidth \times RoundTripTime$). If the BDP (10MB) is much larger than the TCP window size (64KB), the sender is forced to stop transmitting data and wait for ACKs, leading to severe underutilization and high latency, even if the network path itself is clear.
**Solution (TCP Window Scaling):** RFC 1323 extends the standard 16-bit TCP window field to 32 bits. This allows the advertised window size to exceed 65,535 bytes, enabling the sender to fill the entire BDP buffer and maximize throughput.

N20 — **802.1Q Trunk Ports:** A mechanism used on switches to allow multiple VLANs to traverse a single physical link. The switch inserts a 4-byte tag (the 802.1Q header) into the Ethernet frame. This tag contains the VLAN ID (VID), identifying which VLAN the frame belongs to.
**Linux Configuration (Sub-interfaces):** The physical interface (e.g., `eth0`) is configured as a trunk, and logical sub-interfaces are created for each VLAN:
`ip link add link eth0 name eth0.10 type vlan id 10`
`ip addr add 10.0.10.5/24 dev eth0.10`
(Repeat for .20 and .30).
**Frame Format on Wire:** The frame structure is standard Ethernet, but immediately following the destination/source MAC addresses, the 802.1Q tag is inserted, containing the specific VLAN ID (e.g., 10, 20, or 30).

**Linux Answers**

L1 — **Hard Link:** A directory entry that points directly to the same inode (the data structure containing file metadata and data blocks) as the original file. Deleting the original name does not delete the data until the last hard link is removed.
**Symbolic Link (Symlink):** A special file that contains a text path pointing to another file or directory. It is a pointer, not a direct reference to the inode. If the target file is moved or deleted, the symlink breaks (dangling link).

L2 — `find /var/log -type f -size +100M`

L3 — **State D (Uninterruptible Sleep):** The process is waiting for an I/O operation (e.g., disk read/write) to complete. It is blocked at the kernel level and cannot be interrupted by signals.
**Kill -9:** No, `kill -9` (SIGKILL) cannot terminate a process in state D because the process is not running user-space code; it is waiting for hardware/kernel I/O completion. The process must wait for the I/O operation to finish or fail naturally.

L4 — **cgroups v1:** Used a hierarchical, controller-based model where resources (CPU, Memory, I/O) were managed by separate, independent controllers. It was complex to manage interactions between controllers.
**cgroups v2:** Implements a unified hierarchy and a unified control plane. It uses a single, unified hierarchy where all controllers share a common structure, simplifying resource management and ensuring better isolation.
**Systemd Preference:** Systemd prefers cgroups v2 because its unified hierarchy and cleaner resource accounting model integrate much more cleanly with systemd's own service management and dependency tracking.

L5 — **iptables:** The older, traditional Linux firewall framework. It operates using chains (INPUT, OUTPUT, FORWARD) and tables.
**nftables:** The modern replacement for iptables. It uses a more flexible, unified syntax and structure, allowing for more complex rule sets and better performance by operating closer to the kernel's netfilter hooks.
**Kernel Handling:** The Linux kernel's Netfilter framework is the underlying mechanism for both. `nftables` is the modern API/implementation that replaces the older `iptables` API, but both ultimately hook into the same kernel packet processing pipeline.

L6 — The most likely cause is **Inodes exhaustion**. The filesystem might have run out of available inodes (the data structures that store file metadata), even if the total disk space (blocks) is not full. Every file, regardless of size, consumes one inode.

L7 — **Boot Process:**
1. **UEFI Firmware:** Initializes hardware, checks boot order, and loads the bootloader (e.g., GRUB).
2. **Bootloader (GRUB):** Reads the kernel image and the `initramfs` (initial RAM filesystem) from the disk and loads them into memory.
3. **Kernel:** Takes control. It initializes core drivers, mounts the `initramfs`, and executes the first process (`init` or `systemd`).
4. **Initramfs:** A minimal root filesystem loaded into RAM. It contains necessary drivers (like storage drivers) to locate and mount the *real* root filesystem.
5. **Root Filesystem:** The kernel mounts the actual root partition (e.g., `/`).
6. **Systemd:** Systemd takes over as PID 1. It reads configuration files, starts services sequentially based on dependencies, and reaches a final target state (e.g., `multi-user.target` or `graphical.target`), resulting in a running system.

L8 — **Why Available is Low:** The `available` memory metric is calculated as `free + buffers + cache`. However, the OOM killer fires when the kernel determines that *active* processes require memory that cannot be satisfied, even if large amounts of memory are marked as `buff/cache`. If the system is under heavy memory pressure (many processes actively trying to allocate memory), the kernel might reclaim cache aggressively, but if the demand exceeds the physical RAM plus swap, the OOM killer triggers.
**Kernel Tunables:** `vm.swappiness` (controls how aggressively the kernel swaps out anonymous memory) and `vm.vfs_cache_pressure` (controls how aggressively the kernel reclaims memory used for directory and inode caches).

L9 — **ip netns:** This command allows the creation and management of network namespaces. A network namespace is an isolated view of the system resources (network stack, process IDs, mount points, etc.).
**Container Runtimes:** Container runtimes (like Docker or Kubernetes) use network namespaces to provide network isolation for each container. Each container runs in its own isolated network namespace, meaning its network stack (IP addresses, routing tables, interfaces) is completely separate from the host's network stack and other containers.

L10 — **SIGTERM (15):** A polite request for the process to shut down. It allows the process to catch the signal, clean up resources (save state, close files), and exit gracefully.
**SIGKILL (9):** A forceful, immediate termination signal. The process cannot catch, ignore, or block this signal; the kernel terminates it instantly.
**SIGQUIT (3):** Requests the process to terminate and usually generates a core dump file for debugging. It can be caught by the process.

L11 — **stdin (Standard Input):** Where a program reads input from (default: keyboard).
**stdout (Standard Output):** Where a program writes its normal, expected output to (default: terminal screen).
**stderr (Standard Error):** Where a program writes diagnostic messages, errors, and warnings to (default: terminal screen).
**Redirection:** `command 2> error.log` redirects stderr to the file. To display stdout on the terminal while redirecting stderr: `command > output.log 2>&1` (This redirects stdout to the file, and then redirects stderr to the same location as stdout). *Correction for the prompt:* To display stdout on the terminal while redirecting stderr: `command 2> error.log`

L12 — `chmod 755 filename` grants permissions:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = Full control.
*   **5 (Group):** Read (4) + Execute (1) = Can view and run the file.
*   **5 (Others):** Read (4) + Execute (1) = Can view and run the file.

L13 — **Root User:** Has absolute, unrestricted privileges over the entire operating system. It can read, write, modify, or delete any file, change any configuration, and manage any process without restriction.
**Sudo Privileges:** A user with `sudo` can execute specific commands as the root user, but this access is controlled and audited. They cannot arbitrarily change system configurations or access files they are not explicitly permitted to manage via the `sudoers` file.

L14 — **Package Manager:** A system utility responsible for installing, upgrading, configuring, and removing software packages in a standardized, dependency-aware manner.
**Debian/Ubuntu:** APT (Advanced Package Tool)
**RHEL/Fedora:** DNF (Dandified YUM)

L15 — **Purpose:** `/etc/fstab` (File System Table) defines how disk partitions, network shares, and other file systems should be mounted automatically at boot time.
**Misconfiguration:** If an entry is misconfigured (e.g., wrong UUID, incorrect mount point, or invalid filesystem type), the system may fail to mount that partition during boot, potentially leading to a boot failure or a degraded system state, depending on the severity of the error.

L16 — **LVM (Logical Volume Manager):** A storage management abstraction layer that provides flexible volume management, allowing administrators to resize, snapshot, and manage storage volumes independently of the underlying physical disk layout.
**Components:**
*   **Physical Volumes (PV):** The actual physical storage devices (disks or partitions) that LVM uses.
*   **Volume Groups (VG):** A pool of storage capacity created by combining one or more PVs.
*   **Logical Volumes (LV):** The usable, flexible partitions carved out of a VG.
**Extend LV:** 1. Extend the underlying PV/VG (e.g., add a new disk to the VG). 2. Extend the LV using `lvextend -L +XG /dev/VG_NAME/LV_NAME`. 3. Resize the filesystem on the LV using `resize2fs /dev/VG_NAME/LV_NAME` (for ext4).

L17 — **I/O Scheduler:** Determines the order in which read/write requests are serviced by the block device driver to optimize disk throughput and latency.
**Schedulers Comparison:**
*   **mq-deadline:** Prioritizes requests based on deadlines, balancing throughput and latency. Good for mixed workloads.
*   **bfq (Budget Fair Queueing):** Designed for desktop/interactive workloads. It aims to provide fair bandwidth allocation to different processes, minimizing latency spikes for foreground tasks.
*   **none:** Passes requests directly to the hardware without reordering. Best for high-performance storage (like NVMe SSDs) where the hardware scheduler is superior.
**Runtime Change:** Use the `echo` command: `echo bfq > /sys/block/sdX/queue/scheduler` (where sdX is the device name).

L18 — **Load Average:** Measures the average number of processes in the system that are either running or waiting to run (in uninterruptible sleep, D state). It is a measure of system *demand* for CPU time, not necessarily CPU utilization.
**I/O Wait Inflation:** If the system is waiting heavily on slow disk I/O, processes enter the D state. These D-state processes are counted in the load average, artificially inflating the metric, even if the CPU itself is idle.
**Diagnosis:**
*   **CPU Bottleneck:** High load average AND high `%us` or `%sy` in `top`/`htop`.
*   **Disk Bottleneck:** High load average AND high `%wa` (I/O Wait) in `top`/`htop`. Use `iostat` to check disk utilization (`%util`).
*   **Network Bottleneck:** High load average AND high network queueing/drops visible via `netstat` or `ss`.

L19 — **SELinux Enforcement:** SELinux enforces Mandatory Access Control (MAC). Instead of relying solely on traditional Discretionary Access Control (DAC - user/group permissions), SELinux assigns security contexts (labels) to every subject (process) and object (file/port). Access is only granted if the policy explicitly permits the transition between the subject's context and the object's context.
**Modes:**
*   **Enforcing:** SELinux actively denies access based on policy violations.
*   **Permissive:** SELinux logs all policy violations but does *not* deny access, allowing administrators to see what *would* have been blocked.
*   **Disabled:** SELinux is completely inactive.
**Troubleshooting Port Binding:** Check the audit logs (`/var/log/audit/audit.log`) for AVC denials. If a daemon fails to bind a non-standard port, the policy likely needs a specific rule added to allow that process context to bind to that port context (e.g., using `semanage port`).

L20 — **Page Faults:** Occur when a program tries to access a virtual memory address whose corresponding physical memory page is not currently mapped or present in RAM.
**Minor Page Fault:** The required page is not in RAM, but it *is* present on disk (e.g., in the swap file or file system). The kernel resolves this by loading the page into RAM, but no disk I/O is required to find the page metadata.
**Major Page Fault:** The required page is not in RAM and is not easily accessible (e.g., it needs to be read from the original executable file on disk, or it's a completely new page). This requires significant disk I/O.
**THP (Transparent Huge Pages):** THP attempts to automatically coalesce small 4KB memory pages into large 2MB or 1GB huge pages to reduce TLB misses and improve performance for large memory workloads.
**When to Disable:** THP can introduce unpredictable latency spikes (latency jitter) during the background compaction process. It should be disabled in latency-sensitive applications or real-time systems where consistent, low latency is paramount.
