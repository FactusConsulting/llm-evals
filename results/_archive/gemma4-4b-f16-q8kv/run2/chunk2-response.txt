**Networking Answers**

N1 — A Layer 2 switch operates at the Data Link Layer (Layer 2) and forwards frames based on MAC addresses. A Layer 3 switch operates at the Network Layer (Layer 3) and can perform routing between different IP subnets, forwarding packets based on IP addresses.

N2 — For 10.0.5.37/20:
*   The subnet mask is 255.255.240.0.
*   The network address is **10.0.32.0**.
*   The broadcast address is **10.0.47.255**.

N3 — The TCP three-way handshake establishes a connection:
1.  **SYN (Synchronize):** Client sends a SYN packet to the server.
2.  **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and replies with SYN-ACK.
3.  **ACK (Acknowledge):** Client receives SYN-ACK and sends a final ACK.
If the final ACK is lost, the client will retransmit the ACK (or the server will time out and retransmit the SYN-ACK), leading to connection timeouts on the client side until the retransmission succeeds or the connection attempt fails.

N4 — **SNAT (Source Network Address Translation):** Translates the source IP address of a private host to a public IP address when communicating externally. *Example: A laptop (192.168.1.10) accessing Google uses the router's public IP as its source.*
**DNAT (Destination Network Address Translation):** Translates the destination IP address of an external request to a private IP address on the internal network. *Example: An external user accessing a web server at the public IP 203.0.113.5 is redirected by the firewall to the internal server 10.0.0.5.*

N5 — 3 possible causes:
1.  **Hostname Mismatch:** The certificate was issued for a different domain name than the one being accessed (e.g., certificate for `api.example.com` accessed via `example.com`).
2.  **Expired Certificate:** The certificate has passed its validity date.
3.  **Incorrect Configuration:** The server is presenting the wrong certificate file or the certificate chain is incomplete/broken.

N6 — **VLAN (Virtual Local Area Network):** A logical segmentation mechanism within a single physical switch, using 802.1Q tagging to separate broadcast domains at Layer 2.
**VxLAN (Virtual Extensible LAN):** A network virtualization overlay technology that encapsulates Layer 2 Ethernet frames within Layer 3 UDP packets.
You choose VxLAN over VLAN when you need to scale beyond the 4094 VLAN limit, or when you need to extend Layer 2 segments across a large, multi-subnet, or geographically dispersed IP fabric (L3 underlay).

N7 — This is likely due to **routing asymmetry** or **default gateway configuration**. The host knows the route to 192.168.1.0/24 via eth1, but the return path (the gateway's response) is being routed back to the default gateway (10.0.0.1) via eth0, causing the return traffic to be dropped or misdirected.
**Fix using Policy-Based Routing (PBR):** You must configure a routing policy on the Linux host that dictates: "If traffic is sourced from 192.168.1.0/24, use the routing table associated with eth1 (or specifically route traffic destined for 192.168.1.0/24 out eth1)." This is typically done using `ip rule` and `ip route` commands.

N8 — BGP path selection is a complex algorithm used by routers to choose the best path to a destination prefix from multiple available routes. The attributes are evaluated in a strict order of preference.
**5 Attributes (in order of preference):**
1.  Weight (Cisco proprietary, highest preference)
2.  Local Preference (Highest is preferred)
3.  Locally Originated (Prefer routes originated locally)
4.  AS Path Length (Shortest AS path is preferred)
5.  Origin Type (IGP > EGP > Incomplete)

N9 — When running VxLAN over IPsec, the encapsulation adds significant overhead:
*   Original Frame Size: 1500 bytes (MTU)
*   VxLAN Header Overhead: $\approx 50$ bytes (VNI, UDP, etc.)
*   IPsec Overhead (ESP/AH): $\approx 50-70$ bytes (depending on encryption/auth)
*   Total Overhead: $\approx 100-120$ bytes.
Maximum Inner Payload = Physical MTU - Total Overhead
Maximum Inner Payload $\approx 1500 - 120 = \mathbf{1380 \text{ bytes}}$.

N10 — **ARP (Address Resolution Protocol):** Maps a known Layer 3 IP address to its corresponding Layer 2 MAC address on a local network segment.
**Gratuitous ARP:** A host sends an ARP reply to its own IP address. It solves the problem of **stale ARP caches**. If a host changes its MAC address or moves to a new port, sending a gratuitous ARP immediately informs all neighbors of the new mapping, preventing traffic black-holing.

N11 — **Public IP:** Globally unique address routable on the public internet.
**Private IP:** Non-globally unique addresses reserved for use within private networks (LANs) and are not routable on the public internet.
**RFC 1918 Ranges:**
1.  10.0.0.0/8
2.  172.16.0.0/12
3.  192.168.0.0/16

N12 — **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses.
*   **A Record:** Maps a hostname to an IPv4 address (e.g., `www.example.com` $\rightarrow$ 192.0.2.1).
*   **CNAME Record:** Creates an alias, mapping one hostname to another canonical hostname (e.g., `blog.example.com` $\rightarrow$ `servers.example.com`).
*   **AAAA Record:** Maps a hostname to an IPv6 address.

N13 — **DHCP (Dynamic Host Configuration Protocol):** A network management protocol used to automatically assign IP addresses and other network configuration parameters (subnet mask, gateway, DNS servers) to devices on a network.
**DORA Process:**
1.  **Discover:** Client broadcasts a DHCP Discover message.
2.  **Offer:** Server replies with a DHCP Offer, proposing an IP address.
3.  **Request:** Client broadcasts a DHCP Request, formally accepting the offered IP.
4.  **Acknowledge:** Server replies with a DHCP ACK, finalizing the lease and configuration.

N14 — **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming electrical signals out of every other port, creating one large collision domain.
**Switch:** Operates at Layer 2 (Data Link). It learns MAC addresses and forwards frames only to the intended destination port, segmenting collision domains.
**Router:** Operates at Layer 3 (Network). It connects different networks (subnets) and forwards packets based on IP addresses, making routing decisions.

N15 — **Half-Duplex:** Allows data to travel in both directions, but only one direction at a time (e.g., a walkie-talkie).
**Full-Duplex:** Allows data to travel simultaneously in both directions (e.g., a phone call).
Modern Ethernet links overwhelmingly use **full-duplex** communication.

N16 — **TTL (Time To Live):** A field in the IP header that limits the lifespan of a packet. Each router that forwards the packet decrements the TTL by one. If the TTL reaches zero, the router discards the packet and typically sends an ICMP Time Exceeded message back to the source.
**Traceroute Exploitation:** Traceroute works by sending a sequence of packets (usually UDP or ICMP) with incrementally increasing TTL values (starting at 1). When the packet hits the first router, the TTL expires, and the router sends back an ICMP Time Exceeded message, revealing the router's IP address. This process repeats until the destination is reached.

N17 — **NAT Gateway:** A device (usually a router or firewall) that translates private, internal IP addresses into one or more public IP addresses when traffic leaves the private network, allowing multiple internal hosts to share a single public IP.
*   **Static NAT:** A one-to-one, permanent mapping. A specific private IP is always mapped to a specific public IP (e.g., 10.0.0.5 $\leftrightarrow$ 203.0.113.5). Used for servers.
*   **Dynamic NAT:** Maps private IPs to a pool of available public IPs on a first-come, first-served basis.
*   **PAT (Port Address Translation) / NAT Overload:** Maps multiple private IPs to a single public IP by tracking unique source port numbers. This is the most common form of NAT used in homes/offices.

N18 — **ECMP (Equal-Cost Multi-Path):** A routing technique that allows a router to install multiple paths to the same destination prefix if those paths have the exact same routing metric (cost). The router can then load-balance traffic across all these available paths.
**Hashing Strategies:** Common strategies include hashing based on the 5-tuple (Source IP, Destination IP, Source Port, Destination Port, Protocol).
**Asymmetric Flow Problem:** If a stateful firewall is involved, asymmetric flows occur when the request packet takes one path (e.g., Path A) but the return response packet takes a different path (e.g., Path B). The firewall on Path A will not have a corresponding entry for the return traffic on Path B, causing the connection to be dropped.

N19 — **The Problem:** The Bandwidth-Delay Product (BDP) is the maximum amount of unacknowledged data that can be "in flight" on the network path at any given time (BDP = Bandwidth $\times$ Round Trip Time). If the TCP window size (the advertised buffer size) is smaller than the BDP, the sender will stop transmitting data prematurely, waiting for acknowledgments, thus underutilizing the available bandwidth and causing high latency relative to the potential throughput.
**Solution (TCP Window Scaling):** RFC 1323 extends the standard TCP header to allow the advertised window size to exceed the 16-bit limit (65,535 bytes). This allows the sender to advertise a window size large enough to fill the BDP, ensuring the pipe remains full and maximizing throughput.

N20 — **802.1Q Trunk Ports:** A mechanism that allows multiple VLANs to traverse a single physical link. The switch tags each frame with a 4-byte VLAN tag (the 802.1Q header) indicating which VLAN the frame belongs to.
**Linux Configuration (Sub-interfaces):** The physical NIC (e.g., `eth0`) is configured as a trunk, and logical sub-interfaces are created for each VLAN:
*   `eth0.10` (VLAN 10): Configured with IP address for VLAN 10.
*   `eth0.20` (VLAN 20): Configured with IP address for VLAN 20.
*   `eth0.30` (VLAN 30): Configured with IP address for VLAN 30.
**Frame Format:** The frame on the wire will contain the standard Ethernet header, followed by the **802.1Q tag** (which includes the TPID and the VLAN ID/VID), followed by the original Layer 2 payload.

**Linux Answers**

L1 — **Hard Link:** A directory entry that points directly to the same inode (the data structure containing file metadata) as the original file. Deleting the original name does not delete the data until the last hard link is removed.
**Symbolic Link (Symlink):** A special file that contains a text path pointing to another file or directory. It is a pointer, not a direct reference to the inode.

L2 — `find /var/log -type f -size +100M`

L3 — State D (Uninterruptible Sleep) means the process is waiting for an I/O operation (like disk or network) to complete, and it cannot be interrupted by signals (including `SIGKILL`). Attempting to kill it with `kill -9` will fail because the kernel is blocked waiting for the hardware operation to finish.

L4 — **cgroups v1:** Used a hierarchical, resource-specific model where controllers (CPU, Memory, I/O) were managed somewhat independently.
**cgroups v2:** Implements a unified, hierarchical control structure. It enforces a strict hierarchy where resources are managed consistently across all controllers, providing a more coherent and predictable resource accounting model.
Systemd prefers **cgroups v2** because its unified hierarchy simplifies resource management, improves predictability, and aligns better with modern container orchestration needs.

L5 — **iptables:** The older, traditional Linux firewall framework, operating primarily on chains (INPUT, FORWARD, OUTPUT) and tables.
**nftables:** The modern replacement for iptables. It is a more flexible, unified framework that can handle packet filtering, NAT, and routing rules using a single, consistent syntax and data structure.
The kernel handles both by maintaining compatibility layers. When `iptables` rules are loaded, they are translated and managed internally by the kernel's networking stack, which is increasingly migrating functionality to the `nftables` framework.

L6 — The most likely cause is **inode usage**. `df -h` reports disk space usage based on the number of allocated inodes (metadata structures). `du -sh` reports the actual data size. If a filesystem contains millions of tiny files (e.g., session files, cache entries), it can exhaust the available inode count (100%) even if the total data size is small.

L7 — **UEFI Firmware:** Initializes hardware and locates the bootloader.
**Bootloader (e.g., GRUB):** Reads configuration, locates the Linux kernel image, and loads it into memory.
**Kernel:** Initializes core OS components, detects hardware, and mounts the initial root filesystem.
**Initramfs (Initial RAM Filesystem):** A small, temporary root filesystem loaded into memory. It contains necessary drivers and scripts to mount the *real* root filesystem (which might be on a complex device like LVM or encrypted).
**Root Filesystem:** The kernel mounts the actual, persistent root partition.
**Systemd:** The primary init system takes control, reads configuration, manages services, and transitions the system through various targets (e.g., multi-user.target) until the system is fully operational.

L8 — The OOM killer fires when the kernel determines that memory pressure is critical. Even if `buff/cache` is high, the `available` memory metric is calculated by subtracting buffers/cache from total memory *and* accounting for memory that is currently locked or reserved by processes that cannot be easily reclaimed. If processes are holding onto memory that the kernel cannot safely reclaim (or if the system is under heavy pressure from non-pageable memory usage), `available` will be low, triggering the OOM killer despite high cache usage.
**Tunables:** `vm.swappiness` (controls how aggressively the kernel swaps out anonymous memory) and `vm.min_free_kbytes` (sets the minimum amount of memory the kernel should keep free).

L9 — `ip netns` is used to create and manage **network namespaces**. A network namespace provides an isolated view of the network stack (interfaces, routing tables, firewall rules) for a process or group of processes.
Container runtimes (like Docker or Kubernetes) use network namespaces to ensure that each container has its own isolated network environment, preventing one container from seeing or interfering with the network configuration of another.

L10 — **SIGTERM (Signal Terminate):** A polite request for a process to shut down. The process can catch this signal, clean up resources, and exit gracefully.
**SIGKILL (Signal Kill):** A forceful, immediate termination signal. The process cannot catch, ignore, or block this signal; the kernel terminates it instantly.
**SIGQUIT (Signal Quit):** A request to terminate, often causing the process to dump a core file for debugging. It *can* be caught by the process.

L11 — **stdin (Standard Input):** Where a program reads input from (usually the keyboard).
**stdout (Standard Output):** Where a program writes its normal, expected output to (usually the terminal screen).
**stderr (Standard Error):** Where a program writes error messages and diagnostic output to (usually the terminal screen).
To redirect stderr to a file while displaying stdout on the terminal: `command 2> error.log` (or `command &> /dev/null` if you want to discard both).

L12 — `chmod 755 filename` sets permissions as follows:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = Full control.
*   **5 (Group):** Read (4) + Execute (1) = Can read and run the file.
*   **5 (Others):** Read (4) + Execute (1) = Can read and run the file.

L13 — **Root User:** Has absolute, unrestricted privileges over the entire operating system. It can modify any file, change any configuration, and manage any process.
**Sudo Privileges:** A user with `sudo` can execute specific commands as the root user, but this access is usually restricted by configuration files (`/etc/sudoers`). They cannot arbitrarily change system settings or access files they are not explicitly permitted to manage.

L14 — **Package Manager:** A system utility used to automate the installation, upgrading, configuration, and removal of software packages on a Linux system.
**Debian/Ubuntu:** APT (Advanced Package Tool)
**RHEL/Fedora:** DNF (Dandified YUM)

L15 — `/etc/fstab` (File System Table) is a configuration file that defines how disk partitions, network shares, and other file systems should be mounted automatically at boot time.
If an entry is misconfigured (e.g., wrong UUID, incorrect mount point, or invalid filesystem type), the system may fail to boot, halt during the mounting phase, or mount the filesystem incorrectly, leading to data corruption or an unbootable state.

L16 — **LVM (Logical Volume Manager):** A storage management abstraction layer that allows administrators to create, manage, and resize logical volumes dynamically, independent of the underlying physical disk layout.
*   **Physical Volumes (PV):** The actual physical storage devices (hard drives, partitions) that LVM uses.
*   **Volume Groups (VG):** A pool of storage capacity created by combining one or more PVs.
*   **Logical Volumes (LV):** The flexible, usable partitions carved out of the VG that the operating system mounts.
**Extending an LV:** 1. Extend the underlying PV (if necessary). 2. Extend the VG to include the new space. 3. Extend the LV using `lvextend`. 4. Resize the filesystem on the LV using `resize2fs` (for ext4) or equivalent.

L17 — **I/O Scheduler:** Determines the order in which read/write requests are serviced by the block device driver to optimize disk throughput and latency.
*   **mq-deadline:** Prioritizes requests based on deadlines, balancing throughput and latency. Good for mixed workloads.
*   **bfq (Budget Fair Queueing):** Designed for desktop/interactive workloads, ensuring fair bandwidth allocation to different processes, minimizing latency spikes.
*   **none:** Passes I/O requests directly to the device driver without reordering. Best for high-performance storage (like NVMe) where the device handles scheduling internally.
**Changing Scheduler:** Use the `echo` command: `echo bfq > /sys/block/sdX/queue/scheduler` (where `sdX` is the device name).

L18 — **Load Average:** Measures the average number of processes in the system that are either running or waiting to run (in uninterruptible sleep, D state). It is a measure of system *demand*, not just CPU utilization.
**I/O Wait Inflation:** If processes are stuck waiting for slow disk I/O, they remain in the 'D' state, contributing to the load average even if the CPU utilization percentage is low.
**Diagnosis:**
*   **CPU Bottleneck:** High `us` (user) or `sy` (system) time in `top`/`htop`.
*   **Disk Bottleneck:** High `%wa` (I/O wait) in `top`, confirmed by high utilization metrics from `iostat`.
*   **Network Bottleneck:** High packet drops or high utilization reported by `iftop` or `netstat`.

L19 — **SELinux (Security-Enhanced Linux):** Enforces Mandatory Access Control (MAC). Instead of relying solely on traditional Discretionary Access Control (DAC - user/group permissions), SELinux assigns security contexts (labels) to every subject (process) and object (file/port). Access is only granted if the policy explicitly permits the transition between the subject's context and the object's context.
*   **Enforcing:** SELinux actively denies access based on policy violations.
*   **Permissive:** SELinux logs policy violations but does *not* deny access, allowing administrators to audit without breaking functionality.
*   **Disabled:** SELinux is completely inactive.
**Troubleshooting:** Check the audit logs (`/var/log/audit/audit.log`). If a daemon fails to bind a port, the policy likely prevents it. You can temporarily set the context to permissive (`setenforce 0`) to confirm, or use `semanage port` to explicitly allow the daemon to use that port in the policy.

L20 — **Page Fault:** An event where a program tries to access a virtual memory address whose corresponding physical memory page is not currently loaded into RAM.
*   **Minor Page Fault:** The required page is already in physical memory but is mapped to a different location or needs to be brought into the process's address space (e.g., copy-on-write). This is fast.
*   **Major Page Fault:** The required page is not in physical memory and must be retrieved from secondary storage (disk/swap). This is slow, involving I/O.
**THP (Transparent Huge Pages):** Attempts to automatically coalesce small 4KB memory pages into large 2MB pages to reduce TLB misses and improve performance for large memory workloads.
**Disabling THP:** You disable it when applications exhibit unpredictable behavior, suffer from latency spikes, or when the overhead of the kernel's THP management outweighs the benefits, as THP can sometimes introduce significant latency during page promotion/demotion.
