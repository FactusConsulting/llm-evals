**K1** — A **Deployment** manages stateless applications, treating pods as interchangeable with no stable identity, allowing parallel updates. A **StatefulSet** manages stateful applications, assigning stable, unique network identities (pod names) and stable storage, ensuring ordered deployment and graceful termination.

**K2** — A ClusterIP Service creates a virtual IP within the cluster. `kube-proxy` (via iptables or IPVS) intercepts traffic destined for this IP and performs Destination NAT (DNAT), redirecting it to the IP addresses of the pods listed in the Service's **Endpoints**.

**K3** — A **PersistentVolume (PV)** is a piece of storage provisioned by the cluster (static or dynamic). A **PersistentVolumeClaim (PVC)** is a request for storage resources. A **StorageClass** defines the provisioner and parameters for dynamic PVs. **Relation:** A StorageClass enables dynamic PV creation; a PVC binds to a PV (static or dynamic) to mount storage to a pod.

**K4** — 1. **Check Logs:** `kubectl logs <pod>` to see application errors. 2. **Check Events:** `kubectl describe pod <pod>` to look for `CrashLoopBackOff` events or OOMKilled. 3. **Check Probes:** Verify liveness/readiness probes aren't failing. 4. **Check Resources:** Ensure CPU/Memory limits aren causing OOM (check `kubectl top pod`).

**K5** — **CoreDNS** provides DNS resolution for services and pods within the cluster. If CoreDNS pods are down, internal service discovery fails (pods cannot reach services by name), and external access to cluster services via DNS breaks.

**K6** — The scheduler **filters** nodes based on hard constraints (taints, resources). It then **scores** nodes based on preferences. **Factors:** 1. **Node Affinity/Preferences:** Pod affinity rules. 2. **Resource Availability:** CPU/Memory headroom. 3. **Pod Priority:** Higher priority pods preempt lower ones.

**K7** — **Yes**, the pod will be scheduled. Node has 4GB (4096Mi), 3.5GB (3584Mi) used. Available = 512Mi. Pod requests 256Mi, which fits. If runtime usage hits 600Mi, it exceeds the **limit** (512Mi), causing the container to be **OOMKilled**.

**K8** — 1. **External LB:** Receives traffic. 2. **Ingress Controller:** Inspects Host/Path rules. 3. **Service:** ClusterIP routes to pods. 4. **Endpoints:** List of Pod IPs. 5. **kube-proxy:** iptables rules DNAT traffic to Pod IPs. 6. **Pod:** Application receives request.

**K9** — A **NetworkPolicy** restricts ingress/egress traffic. **Default:** If no policy exists, all traffic is allowed. **Applied:** When a policy selects pods, traffic is denied unless explicitly allowed by the policy rules.

**K10** — **RollingUpdate** updates pods gradually (zero downtime). **Recreate** stops all pods, then starts new ones. Choose **Recreate** for stateful apps (e.g., databases) that require a full stop to migrate data or avoid data corruption.

**K11** — A **Namespace** provides logical isolation of resources. **Default namespaces:** `default`, `kube-system`, `kube-public`, `kube-node-lease`.

**K12** — `kubectl describe` shows detailed metadata. **3 pieces:** 1. **Events** (history of pod actions). 2. **Conditions** (Ready, Running status details). 3. **Node Name** (which node the pod is on).

**K13** — A **ConfigMap** stores non-confidential key-value data. **Methods:** 1. **Volume Mount:** Mount as a directory or file. 2. **Environment Variables:** Inject as env vars in the pod spec.

**K14** — **ClusterIP:** Internal cluster access only. **NodePort:** Exposes a port on every node's IP. **LoadBalancer:** Provisions an external cloud load balancer to expose the service externally.

**K15** — A **DaemonSet** ensures a copy of a pod runs on all (or selected) nodes. Use it for **system-level tasks** like logging (Fluentd), monitoring (Prometheus Node Exporter), or network plugins (Calico), where one pod per node is required.

**K16** — **Taints** push pods away from a node; **Tolerations** allow specific pods to ignore taints. **Node Affinity** pulls pods to specific nodes based on labels. **Use Case:** Taints for GPU nodes (only pods with GPU toleration run there); Affinity for placing DBs on specific hardware.

**K17** — An **Operator** is a custom controller that manages the lifecycle of a complex application (e.g., backups, upgrades). It differs from standard controllers (like Deployment) by implementing domain-specific logic. It solves problems where standard Kubernetes primitives cannot handle complex operational tasks.

**K18** — etcd uses **Raft consensus** for strong consistency. If **2 out of 3 nodes are lost**, the quorum is lost, and the cluster becomes unavailable. **Recovery:** You cannot recover from a single remaining node. You must restore etcd from a **backup snapshot** or rejoin a new node with data from the remaining node (if data is consistent), but restoring from backup is the standard procedure.

**K19** — **RBAC** controls permissions. **Role** (namespace) or **ClusterRole** (cluster) defines permissions. **Binding** links a Role to a User/Group.
**Manifests:**
```yaml

  namespace: dev

  kind: Role
  name: pod-reader
```

**K20** — **ndots** > 1 causes the resolver to split domain names into multiple queries (e.g., `a.b.c` becomes 3 queries). **Fix:** Set `ndots` to 1 in the pod's DNS config:
```yaml
spec:

    options:
    - name: ndots
      value: "1"
```

**D1** — **Rebase** rewrites history to make it linear (commits change). **Merge** preserves history (creates a merge commit). **Avoid Rebase** on public/shared branches or when others are working on the same commits, as it invalidates their history.

**D2** — **TCP** is reliable, ordered, connection-oriented (HTTP, SSH). **UDP** is unreliable, unordered, connectionless (DNS, Video Streaming).

**D3** — A **race condition** occurs when program behavior depends on the timing of events. **Example:** Two threads increment a shared counter `count++` without locks; the final value may be less than expected due to lost updates.

**D4** — **Symmetric** uses one key (e.g., AES). **Asymmetric** uses public/private keys (e.g., RSA). **TLS:** Uses Asymmetric for key exchange (handshake), then Symmetric for encrypting the actual data transfer.

**D5** — A **layer** is a read-only filesystem in a container image. **Caching:** Docker caches layers; changing a line in a `RUN` command invalidates subsequent layers. **Best Practice:** Combine commands in one `RUN` instruction to maximize cache hits.

**D6** — 1. **Check App Logs:** Look for 503 errors. 2. **Check Upstream:** Verify database/API connectivity. 3. **Check Resources:** Verify OOM or CPU throttling. 4. **Check Load Balancer:** Verify health check endpoints are passing.

**D7** — **CAP Theorem:** A distributed system can only guarantee 2 of 3: Consistency, Availability, Partition Tolerance. **CP:** ZooKeeper (prioritizes data consistency). **AP:** Cassandra (prioritizes availability during network partitions).

**D8** — **Horizontal:** Add more instances (stateless). **Vertical:** Add more resources to existing instance (stateful). **Patterns:** Stateless apps, Load Balancers, and Microservices enable horizontal scaling.

**D9** — An **environment variable** is a dynamic name-value pair. To persist across sessions, add `export VAR=value` to your shell profile (e.g., `~/.bashrc` or `~/.profile`).

**D10** — **JSON** is strict, machine-readable text. **YAML** is human-readable, indentation-based. **JSON Advantage:** Strict validation. **YAML Advantage:** Readability for humans.

**D11** — **REST** is an architectural style using HTTP. **GET:** Retrieve data. **POST:** Create data. **PUT:** Replace data. **DELETE:** Remove data.

**D12** — **Version pinning** locks dependencies to specific versions (e.g., `==1.2.3`). It is important to ensure **reproducible builds** and prevent unexpected breaking changes from upstream updates.

**D13** — **Compiled** languages translate source to binary (e.g., C++, Go). **Interpreted** languages execute source via a VM (e.g., Python, Ruby).

**D14** — **Reverse Proxy:** Server-side (client -> proxy -> server). **Forward Proxy:** Client-side (client -> proxy -> internet). **Reverse:** Nginx (load balancing). **Forward:** Squid (caching/anonymity).

**D15** — A **deadlock** is when threads block each other forever. **Conditions:** 1. Mutual Exclusion. 2. Hold and Wait. 3. No Preemption. 4. Circular Wait.

**D16** — **Eventual Consistency** means data converges over time. **Cassandra:** Uses **Consistency Levels** (ONE, QUORUM, ALL) to tune read-after-write consistency. **Tunable:** You can choose between speed (ONE) and accuracy (ALL).

**D17** — **mTLS** verifies both client and server identities. **Handshake:** Client sends cert -> Server verifies -> Server sends cert -> Client verifies. **Use:** Service Mesh (Istio), secure database connections.

**D18** — **Hash Table:** Array indexed by hash function. **Chaining:** Collisions stored in linked lists. **Open Addressing:** Collisions stored in next slot. **Complexity:** Avg O(1), Worst O(n) for insert/lookup/delete.

**D19** — **Circuit Breaker** prevents cascade failures. **States:** **Closed** (normal), **Open** (fail fast), **Half-Open** (test recovery). **Retry:** Uses exponential backoff to avoid hammering the service during the "Open" state.

**D20** — **Optimistic:** Check conflicts on commit (CAS). **Pessimistic:** Lock rows immediately. **Choose Optimistic** for high concurrency read-heavy. **Choose Pessimistic** for critical data integrity (e.g., banking transactions). **Example:** `SELECT FOR UPDATE` (Pessimistic).
