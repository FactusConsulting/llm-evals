**K1** — A Deployment manages stateless applications with no stable pod identity, allowing flexible scaling and rolling updates. A StatefulSet manages stateful applications with stable, unique pod identities (DNS names) and ordered deployment/termination, often requiring persistent storage.

**K2** — A ClusterIP Service creates a virtual IP within the cluster. kube-proxy (running on nodes) creates iptables/IPVS rules to forward traffic from the Service IP to the Pod IPs listed in the Service's Endpoints object.

**K3** — A PersistentVolume (PV) is a cluster-wide storage resource provisioned by an admin. A PersistentVolumeClaim (PVC) is a user request for storage. A StorageClass defines the provisioner and parameters for dynamically creating PVs. Relationship: StorageClass -> PV -> PVC.

**K4** — 1. Check container logs (`kubectl logs <pod>`) for errors. 2. Check health probes (liveness/readiness) for misconfigurations. 3. Check resource limits (OOMKilled) via `kubectl describe pod`. 4. Check image pull errors or missing ConfigMaps/Secrets.

**K5** — CoreDNS provides DNS resolution for services and pods within the cluster. If CoreDNS pods are down, internal service discovery fails (pods cannot resolve service names), and external DNS resolution for cluster services breaks.

**K6** — The scheduler first **filters** nodes based on hard constraints (taints, affinity, resource availability). Then it **scores** remaining nodes based on preferences. Factors: 1. Taints/Tolerations, 2. Node Affinity, 3. Resource Requests (CPU/Memory).

**K7** — Yes, the pod will be scheduled because the request (256Mi) is less than available memory (4GB - 3.5GB = 512Mi). However, if runtime usage exceeds the limit (600Mi > 512Mi), the kubelet will OOMKill the container.

**K8** — External LB -> Ingress Controller Pod (terminates SSL, routes based on rules) -> Service (ClusterIP) -> Endpoints (Pod IPs) -> kube-proxy (iptables rules) -> Application Pod.

**K9** — A NetworkPolicy restricts ingress/egress traffic. Default behavior is "allow all" traffic. Applying a policy restricts traffic to/from the selected pods based on labels and rules.

**K10** — RollingUpdate updates pods gradually (no downtime). Recreate kills all old pods before starting new ones (downtime). Choose Recreate for stateful apps (e.g., databases) where zero replicas are required during update.

**K11** — A Namespace is a logical partition for resources. Default namespaces: `default`, `kube-system`, `kube-public`, `kube-node-lease`.

**K12** — `kubectl describe` shows detailed metadata. 3 extra pieces: 1. Events (history of pod actions), 2. Conditions (Ready, Running status), 3. Container Status (RestartCount, State).

**K13** — A ConfigMap stores non-confidential key-value data. Methods: 1. Mount as a volume (directory/files), 2. Inject as environment variables.

**K14** — ClusterIP: Internal cluster access only. NodePort: Exposes a port on every node's IP. LoadBalancer: Exposes an external IP via a cloud provider's load balancer.

**K15** — A DaemonSet ensures a copy of a pod runs on all (or selected) nodes. Use for system-level tasks like logging (Fluentd), monitoring (Prometheus), or network plugins (Calico) instead of Deployments.

**K16** — Taints (node side) push pods away; Tolerations (pod side) allow pods to ignore taints. Node Affinity (pod side) pulls pods to specific nodes. Use case: Taints for GPU nodes; Affinity for placing DBs on specific hardware.

**K17** — An Operator is a custom controller that manages the lifecycle of a specific application (e.g., backups, upgrades). Standard controllers manage generic resources (Pods). Operators solve complex, domain-specific management problems.

**K18** — etcd uses Raft consensus. If 2/3 nodes are lost, quorum is lost, and the cluster becomes unavailable. Recovery: Restore etcd data from a snapshot backup and rejoin the nodes to the cluster.
