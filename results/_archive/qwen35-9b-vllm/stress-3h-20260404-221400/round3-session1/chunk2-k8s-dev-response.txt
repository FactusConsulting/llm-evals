## Kubernetes (20 questions)

**K1**
A **Deployment** manages stateless applications, ensuring a specific number of replicas with no stable identity. It supports rolling updates and rollbacks. A **StatefulSet** manages stateful applications, providing stable, unique network identifiers (pod names) and stable storage. It ensures ordered deployment and graceful shutdown.

**K2**
A ClusterIP Service creates a virtual IP within the cluster. `kube-proxy` (via iptables or IPVS) intercepts traffic destined for this IP. It performs DNAT (Destination Network Address Translation) to forward the traffic to the IP addresses of the pods listed in the Service's **Endpoints**.

**K3**
A **PersistentVolume (PV)** is a cluster-wide resource representing actual storage provisioned by an admin or cloud provider. A **PersistentVolumeClaim (PVC)** is a request for storage resources (size, access mode) made by a user. A **StorageClass** defines the provisioner and parameters (e.g., IOPS, type) used to dynamically create PVs. Relationship: StorageClass -> PV -> PVC.

**K4**
1. **Check Logs:** `kubectl logs <pod> --previous` to see why the container exited.
2. **Check Probes:** Verify `liveness` and `readiness` probe configurations and failure thresholds.
3. **Check Resources:** Inspect `events` for `OOMKilled` or CPU throttling.
4. **Check Image:** Verify the image tag exists and is accessible (pull errors).
5. **Check Init Containers:** Ensure init containers are not crashing or hanging.

**K5**
CoreDNS provides DNS resolution for services, pods, and nodes within the cluster (e.g., resolving `my-pod.my-namespace.svc.cluster.local`). If CoreDNS pods are down, internal DNS resolution fails. Services become unreachable via DNS, Ingress fails to route traffic, and pod-to-pod communication breaks.

**K6**
The scheduler performs **Filtering** (nodes that satisfy taints/tolerations, node selectors, and resource requests) and **Scoring** (ranking valid nodes). Factors considered include:
1. **Node Affinity:** Hard or soft constraints on node labels.
2. **Resource Availability:** Ensuring CPU/memory fits.
3. **Pod Anti-Affinity:** Spreading pods across nodes to avoid single points of failure.
4. **Topology Spread:** Distributing pods across zones or regions.

**K7**
**Yes**, the pod will be scheduled. The node has 4GB total, 3.5GB requested, leaving 0.5GB (512Mi) available. The pod requests 256Mi, which fits. However, if the runtime uses 600Mi, it exceeds the **limit** of 512Mi. The container will be **OOMKilled** (Out Of Memory Killed).

**K8**
1. **External LB:** Receives traffic and forwards to the Ingress Controller.
2. **Ingress Controller (NGINX):** Parses the Ingress rules and routes to the backend Service.
3. **Service (ClusterIP):** Acts as the internal endpoint for the Ingress Controller.
4. **Endpoints:** List of Pod IPs associated with the Service.
5. **kube-proxy/iptables:** Intercepts traffic to the Service IP and DNATs it to the specific Pod IP.
6. **Pod:** Receives the request and serves the application.

**K9**
A **NetworkPolicy** restricts ingress and egress traffic to/from pods. If no NetworkPolicy exists, the **default behavior is to allow all traffic** (ingress and egress). When a policy is applied, it restricts traffic to/from the selected pods based on the defined rules (e.g., allow only from specific namespaces).

**K10**
**RollingUpdate** updates pods gradually (e.g., 25% at a time), maintaining availability. **Recreate** scales the deployment to 0 replicas, updates the image, then scales back up. Choose **Recreate** for stateful applications (e.g., databases) where downtime is acceptable or required to ensure data consistency during the update.

**K11**
A **Namespace** is a logical partition for organizing resources (names, quotas). Default namespaces created in a new cluster are: **default**, **kube-system**, **kube-public**, and **kube-node-lease**.

**K12**
`kubectl describe` shows detailed information including **Events** (history of actions), **Conditions** (Ready, Running), and **Node Name**. `kubectl get` only shows summary status (e.g., Running, Age, Restarts).

**K13**
A **ConfigMap** stores non-confidential configuration data as key-value pairs. Pods consume it via:
1. **Environment Variables:** `envFrom` or `env`.
2. **Volume Mount:** Mounting the ConfigMap as a directory or file in the container filesystem.

**K14**
**ClusterIP**: Internal cluster communication only. **NodePort**: Exposes the service on a static port on every node's IP. **LoadBalancer**: Provisions an external cloud load balancer to expose the service to the internet.

**K15**
A **DaemonSet** ensures a copy of a pod runs on all (or a subset of) nodes. Use it for system-level tasks like logging (Fluentd), monitoring (Prometheus Node Exporter), or network plugins (Calico). A Deployment manages a fixed number of replicas, not one per node.

**K16**
**Taints** are on nodes (repel pods). **Tolerations** are on pods (allow taints). **Node Affinity** is on pods (attract to nodes with specific labels).
*   **Taint Use Case:** GPU nodes (taint `nvidia.com/gpu: NoSchedule`) to ensure only specific pods run there.
*   **Affinity Use Case:** Critical DB pods (affinity) to run on specific nodes for performance.

**K17**
An **Operator** is a custom controller that extends Kubernetes to manage complex applications (e.g., databases, message queues). It differs from standard controllers (like Deployment) by implementing custom logic for lifecycle management (backups, upgrades, scaling). It solves the problem of "how to manage complex application logic within the Kubernetes ecosystem."

**K18**
Kubernetes uses the **Raft consensus algorithm** in etcd. A quorum (majority of nodes) is required to maintain consistency. If 2 out of 3 nodes are lost, the cluster loses quorum and becomes unavailable. **Recovery:** Restore etcd from a recent snapshot or backup. You cannot recover data from the remaining node alone if it lacks the lost data.

**K19**
**Role** defines permissions in a namespace. **ClusterRole** defines permissions cluster-wide. **RoleBinding** binds a Role to a user/group in a namespace. **ClusterRoleBinding** binds a ClusterRole cluster-wide.
**Manifests:**
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: default
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods
  namespace: default
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20**
`ndots` defines the minimum number of dots in a domain name before it is split into multiple queries. If `ndots > 1` (e.g., 2), a domain like `google.com` is split into `google` and `com`, causing multiple DNS queries and latency. **Fix:** Set `dnsConfig.ndots: 1` in the pod spec to ensure single-query resolution.

## Development (20 questions)

**D1**
**Rebase** rewrites commit history to make it linear (commits are moved). **Merge** preserves history by creating a new merge commit. Avoid rebasing on **public/shared branches** or branches with unpushed commits that others might be working on, as it rewrites history.

**D2**
**TCP** is connection-oriented, reliable, and ordered (e.g., HTTP, SSH). **UDP** is connectionless, unreliable, and fast (e.g., DNS, RTP/Video Streaming).

**D3**
A **race condition** occurs when the outcome depends on the timing of concurrent events. **Example:** Two threads increment a shared counter `count++`. If they read the value, increment, and write back simultaneously, one increment is lost.

**D4**
**Symmetric** uses one shared key (e.g., AES). **Asymmetric** uses a public/private key pair (e.g., RSA). **TLS** uses Asymmetric encryption to securely exchange a session key (handshake), then uses Symmetric encryption to encrypt the actual data transfer for performance.

**D5**
A **layer** is a read-only filesystem image added to a container. **Layer caching** speeds up builds by reusing unchanged layers. Best practice: Combine `RUN` commands to reduce layers and avoid `ARG` or `ENV` changes in the same layer to maximize cache hits.

**D6**
1. **Check App Logs:** Look for 503 errors or exceptions.
2. **Check Readiness Probes:** Ensure the pod is marked ready.
3. **Check Upstream Dependencies:** Verify database or API connectivity.
4. **Check Resource Limits:** Ensure CPU/Memory limits aren't causing throttling or OOM.

**D7**
**CAP Theorem:** A distributed system can only guarantee two of three: Consistency, Availability, Partition Tolerance. **CP Example:** ZooKeeper (prioritizes consistency). **AP Example:** DynamoDB/Cassandra (prioritizes availability during partition).

**D8**
**Horizontal Scaling** adds more instances (nodes/pods). **Vertical Scaling** increases resources (CPU/RAM) of existing instances. Horizontal scaling is enabled by **stateless architecture** and **load balancers** that distribute traffic.

**D9**
An **environment variable** is a key-value pair used by the OS or applications. To persist across shell sessions on Linux, use `export VAR=value` or add it to `.bashrc`/`.zshrc`.

**D10**
**JSON** is a strict, machine-readable data format. **YAML** is human-readable, using indentation. **JSON Advantage:** Strict validation. **YAML Advantage:** Readability for humans.

**D11**
A **REST API** uses HTTP methods to manipulate resources. **GET** retrieves data. **POST** creates new data. **PUT** replaces/updates existing data. **DELETE** removes data.

**D12**
**Version pinning** locks dependencies to a specific version (e.g., `==1.2.3`). It is important for **reproducible builds** to prevent unexpected breaking changes when upstream libraries update.

**D13**
**Compiled languages** translate source code to machine code (binary) before execution (e.g., C++, Rust). **Interpreted languages** execute source code line-by-line via an interpreter (e.g., Python, JavaScript).

**D14**
A **Reverse Proxy** sits in front of servers (e.g., Nginx, HAProxy) to handle client requests. A **Forward Proxy** sits in front of clients (e.g., Squid) to route requests to the internet. **Reverse Use Case:** Load balancing. **Forward Use Case:** Anonymity/Content filtering.

**D15**
A **deadlock** occurs when threads block each other indefinitely. **Coffman Conditions:** 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16**
**Eventual consistency** means data converges over time without immediate guarantees. **Cassandra** handles read-after-write by allowing reads to return stale data unless a consistency level is specified. **Tunable Consistency Levels:** ONE (1 replica), QUORUM (majority), ALL (all replicas).

**D17**
**mTLS** requires both client and server to authenticate using certificates. **Handshake:** Client sends cert -> Server verifies -> Server sends cert -> Client verifies. **Use Case:** Service-to-service communication (e.g., Istio Service Mesh).

**D18**
A **hash table** uses an array and a hash function to map keys to indices. **Chaining** uses linked lists at indices; **Open Addressing** probes for the next slot. **Time Complexity:** Average O(1), Worst O(n) (due to collisions).

**D19**
**Circuit Breaker** prevents cascade failures. **Closed:** Normal operation. **Open:** Fail fast (stop calls). **Half-Open:** Test with limited calls. **Retry:** Uses exponential backoff to retry failed requests when the circuit is Half-Open.

**D20**
**Optimistic Concurrency** checks for conflicts on commit (e.g., `SELECT ... FOR UPDATE` is pessimistic, but versioning is optimistic). **Pessimistic** locks rows immediately. **Optimistic** is chosen for high concurrency read-heavy workloads. **Pessimistic** is chosen for critical data integrity (e.g., banking transactions).
