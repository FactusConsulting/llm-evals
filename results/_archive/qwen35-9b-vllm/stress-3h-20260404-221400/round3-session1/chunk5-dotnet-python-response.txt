## .NET / C# (20 questions)

**DN1**
Classes are reference types (allocated on heap, support inheritance/virtual methods). Structs are value types (allocated on stack, no virtual methods, no inheritance). Use structs for small, immutable data (e.g., coordinates, colors) to avoid heap allocation overhead and enable value semantics.

**DN2**
`IEnumerable<T>` executes queries in memory (LINQ to Objects). `IQueryable<T>` builds an expression tree translated to SQL (LINQ to DB). This distinction matters because `IEnumerable` cannot be translated to SQL, so using it on a `DbContext` prevents database queries from executing efficiently.

**DN3**
`async/await` uses a state machine to yield control back to the thread pool. `Task` is a reference type wrapper for an asynchronous operation. `ValueTask` is a union of `Task` and a result value, avoiding allocation if the operation completes synchronously. Use `ValueTask` in hot paths where the operation is often synchronous to reduce GC pressure.

**DN4**
Dependency Injection (DI) allows injecting dependencies rather than creating them. Lifetimes: **Transient** (new instance per request), **Scoped** (new instance per request scope, e.g., HTTP request), **Singleton** (one instance per app lifetime). Common bug: Injecting a Scoped service into a Singleton causes a memory leak because the Scoped service is never disposed when the request ends.

**DN5**
`string` is immutable and allocates memory. `ReadOnlySpan<char>` is a view over existing memory (stack or heap) with zero-copy access. Use `Span<T>` (or `ReadOnlySpan`) for high-performance processing of buffers (e.g., parsing strings) to avoid unnecessary allocations and copying.

**DN6**
GC manages memory in generations: **Gen 0** (short-lived), **Gen 1** (medium), **Gen 2** (long-lived). Objects age up generations. **Large Object Heap (LOH)** stores objects >85KB. `IDisposable` is needed for unmanaged resources (files, handles) because the GC cannot know when to release them; `Dispose` must be called explicitly (via `using`).

**DN7**
Default `await` captures the `SynchronizationContext` (e.g., UI thread) to resume. `ConfigureAwait(false)` suppresses this, resuming on any thread pool thread. Use `false` in libraries to avoid deadlocks and improve performance. Do **not** use `false` in UI applications (WPF/WinForms) if you need to update UI controls, as it bypasses the context.

**DN8**
Primary constructors allow parameters in class definitions (C# 12/.NET 8). Collection expressions create collections inline (e.g., `new List<int>{1, 2}`). `FrozenDictionary` is an immutable dictionary. Example:
```csharp
class MyService : IMyService {
    public MyService(string name) { /* ... */ }
}
// Usage
var service = new MyService("test");
```
(Note: Primary constructors in classes are a .NET 8 feature).

**DN9**
Cause: `DbContext` is likely registered as Singleton or Transient, or shared across requests, causing concurrent disposal. EF Core `DbContext` is typically Scoped. Fix: Ensure `DbContext` is registered as Scoped in DI. If using a Singleton API, ensure the `DbContext` is created per request (e.g., via `IHostedService` or middleware) rather than injected globally.

**DN10**
`record` is a reference type with value equality and immutability by default. `record struct` is a value type with value equality. Use `record` for DTOs/objects. Use `record struct` for small, immutable data structures (e.g., `Point`) to avoid heap allocation.

**DN11**
`ref`: read/write access to variable. `out`: write-only (must be assigned before return). `in`: read-only reference (prevents modification, improves performance). Use `in` for large structs passed by reference where the method doesn't modify them.

**DN12**
`?` on reference types (e.g., `string?`) enables nullable reference types (compile-time warnings for nulls). `int?` is a nullable value type (struct), representing `int` or `null`. Nullable reference types are a compile-time feature; nullable value types are runtime types.

**DN13**
LINQ is Language Integrated Query. Method syntax (`list.Where(...)`) is more flexible; query syntax (`from x in list where ...`) is more readable. **Deferred execution** means the query isn't executed until the result is iterated (e.g., `ToList()`).

**DN14**
Constraints limit generic types. `class`: reference type. `struct`: value type. `new()`: parameterless constructor exists. `IComparable<T>`: implements interface. Combine constraints (e.g., `where T : class, new()`) to enforce multiple rules simultaneously.

**DN15**
Abstract classes can have state, constructors, and multiple inheritance (via interfaces). Interfaces (pre-C# 8) could not have state or constructors. C# 8+ interfaces support default methods and properties, narrowing the gap, but abstract classes are still preferred for shared implementation and state.

**DN16**
Middleware pipeline processes requests sequentially. `app.Use()` adds middleware to the pipeline. `app.Map()` creates a sub-tree (branching). `app.Run()` executes immediately and returns (no pipeline). Ordering matters (earlier runs first). Exception middleware wraps the pipeline to catch errors and return 500 responses.

**DN17**
`Channel<T>` is a bounded/unbounded queue for producer-consumer with built-in backpressure. `BlockingCollection<T>` is unbounded and uses locks. Use `Channel<T>` (bounded) for backpressure to prevent memory exhaustion when consumers are slow.

**DN18**
Source Generators compile code at build time. They differ from reflection (runtime) and IL weaving (post-build). **Incremental generators** only recompile when source changes, making them faster than full `ISourceGenerator` runs. Preferred for performance and incremental builds.

**DN19**
TPL Dataflow provides pipeline components: `ActionBlock` (sink), `TransformBlock` (process), `BufferBlock` (buffer). It abstracts threading. Compare to `System.Threading.Channels`: Dataflow is higher-level (handles buffering/flow control), Channels is lower-level (lighter weight, manual flow control).

**DN20**
Minimal APIs use `app.MapGet/Post` instead of Controllers. Trade-offs: Less boilerplate, harder to test (no controller base classes), middleware still works, OpenAPI requires `AddOpenApi`. Route groups organize endpoints. Endpoint filters allow cross-cutting concerns (e.g., auth) without middleware.

## Python (20 questions)

**P1**
Lists are mutable sequences. Tuples are immutable sequences. Sets are mutable unordered collections. FrozenSets are immutable sets. Use tuples for fixed data; lists for dynamic data.

**P2**
The GIL prevents multiple threads from executing Python bytecode simultaneously on one CPU core. It affects CPU-bound workloads. Workarounds: Use `multiprocessing` (separate processes), C-extensions (Cython), or `asyncio` for I/O-bound tasks.

**P3**
`copy` creates a shallow copy (nested objects share references). `deepcopy` creates a deep copy (nested objects are duplicated). Example: `a = [[1]]; b = copy(a); b[0][0] = 2` modifies `a` because the inner list is shared.

**P4**
Decorators wrap functions. Example:
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start:.2f}s")
        return result
    return wrapper
```

**P5**
Generators use `yield` to return values and pause execution, saving memory compared to returning a list. `yield from` delegates to another iterable/generator. Use generators for large datasets to avoid loading everything into memory.

**P6**
`asyncio.run()` starts the event loop. `asyncio.gather()` waits for all tasks. `asyncio.create_task()` schedules a task. `time.sleep()` blocks the event loop; use `await asyncio.sleep()` instead.

**P7**
Python uses C3 Linearization for MRO. In the diamond example: `D` inherits from `B` and `C`. `C` overrides `A`. MRO order: `D -> B -> C -> A`. `D().who()` resolves to `C.who()` because `C` appears before `A` in the MRO. Output: "C".

**P8**
Metaclasses control class creation. `__init_subclass__` is a hook called when a subclass is defined (Python 3.6+). Use metaclasses for global control (e.g., ORM models). Use `__init_subclass__` for simpler, localized customization (e.g., adding default methods to subclasses).

**P9**
`multiprocessing` creates separate processes (bypassing GIL). `threading` creates threads (shared memory, GIL limited). `concurrent.futures` abstracts both. Multiprocessing requires pickling (serialization) of objects; threading does not.

**P10**
`__slots__` prevents the creation of `__dict__` for instances, saving memory and speeding up attribute access. It prevents dynamic attribute assignment (e.g., `obj.new_attr = 1` raises `AttributeError`). Use for memory-critical classes.

**P11**
Virtual environments isolate dependencies. `venv` is built-in. `virtualenv` is a 3rd party wrapper (more features). `conda` manages environments and packages (binary dependencies). Use `venv` for standard Python projects.

**P12**
Comprehensions `[x for x in list]` are concise syntax for `map`/`filter`. Prefer comprehensions for readability; use `map`/`filter` for functional style or when chaining multiple operations.

**P13**
`==` checks value equality. `is` checks identity (same object in memory). Integers -5 to 256 are interned (cached), so `a is b` returns True for small integers even if created separately.

**P14**
`*args` collects positional args; `**kwargs` collects keyword args. `/` marks positional-only parameters (before `*`). `*` marks keyword-only parameters (after `*`).

**P15**
Context managers manage resources (e.g., files). `__enter__`/`__exit__` is the low-level protocol. `@contextmanager` (from `contextlib`) allows writing context managers as generators. Example: `with lock:`.

**P16**
Type hinting enables static analysis. `Union` (multiple types), `Optional` (Union with None), `Literal` (exact values), `TypeVar` (generic types), `Protocol` (structural typing). Tools like `mypy` check these hints.

**P17**
`__repr__` for debugging (unambiguous). `__str__` for users (readable). `__eq__` defines equality; defining it without `__hash__` makes the object unhashable (cannot be in a set/dict).

**P18**
Descriptors manage attribute access. `__get__`, `__set__`, `__delete__` define behavior. `property`, `classmethod`, `staticmethod` are implemented using descriptors.

**P19**
Imports resolve modules via `sys.path`. Relative imports use `.` (current package). Absolute imports use full path. `__init__.py` makes a directory a package. Namespace packages allow packages across directories without `__init__.py`. Finders locate modules; loaders load them.

**P20**
`dataclasses` (stdlib) generate boilerplate. `attrs` adds more features (validators). `Pydantic` adds validation/serialization (JSON). Use `__post_init__` for initialization logic. Choose Pydantic for API validation/serialization; dataclasses for internal data structures.
