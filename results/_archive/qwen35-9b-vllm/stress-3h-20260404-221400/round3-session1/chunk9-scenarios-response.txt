SC1-A
The pods fail because the Pod Security Standards (PSS) enforcement level changed from **Baseline** to **Restricted**.
1.  **Baseline:** Allows containers to run as root.
2.  **Restricted:** Requires containers to run as a non-root user (`runAsNonRoot: true`) and mandates that a specific user ID is set (`runAsUser`).
3.  **The Conflict:** The manifest sets `runAsNonRoot: true` but does not set `runAsUser`. Kubernetes calculates the effective user from the container image. The new base image (`cgr.dev/chainguard/static:latest`) defaults to `USER root`.
4.  **Result:** Kubernetes sees `runAsNonRoot: true` but the image provides `USER root`. This violates the Restricted standard, causing the admission controller to reject the pod, resulting in `CrashLoopBackOff`.
