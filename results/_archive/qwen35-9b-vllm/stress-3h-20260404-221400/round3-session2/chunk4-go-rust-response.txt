## Go (20 questions)

**G1**
Arrays are fixed-size, value types stored contiguously in memory. Slices are dynamic, reference types pointing to an underlying array with a length and capacity. When a slice reaches capacity, `append` allocates a new underlying array (usually double the size), copies the old data, and returns a new slice pointing to it.

**G2**
`var x int` declares a variable `x` with type `int` and initializes it to the zero value (`0`). `x := 0` is a short declaration that initializes `x` to `0` and infers the type. You cannot use `:=` at the package level (top of a file) or when the variable already exists.

**G3**
A goroutine is a lightweight thread managed by the Go runtime. It differs from an OS thread in that it is much smaller (stack starts at 2KB) and the runtime multiplexes many goroutines onto fewer OS threads. The GMP model (Goroutine, Machine, Processor) allows the scheduler to manage runnable goroutines across OS threads efficiently.

**G4**
Channels allow safe communication between goroutines. An unbuffered channel blocks the sender until a receiver is ready. A buffered channel holds up to `N` values. Sending to a full buffered channel blocks the sender until space is available or the channel is closed.

**G5**
The `context` package manages cancellation, deadlines, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
// Use ctx in HTTP request: req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
```

**G6**
Go interfaces are implicit; a type satisfies an interface if it has all required methods. Java/C# require explicit implementation. `interface{}` (or `any`) accepts any type, enabling generic-like behavior, but it disables compile-time type safety and requires runtime type assertions, making it dangerous.

**G7**
This is unsafe due to a data race. `ready` is not atomic, and `data` is accessed by the goroutine and the main goroutine without synchronization. The main goroutine might read `data` before the goroutine writes it. Correct alternatives: use `sync.WaitGroup`, `sync.Mutex`, or `atomic.Bool`.

**G8**
`sync.Mutex` allows only one writer. `sync.RWMutex` allows multiple concurrent readers but exclusive writers. `sync.Map` is optimized for high read concurrency with sparse data (no locking for reads), while a regular map with a mutex is better for high write concurrency or dense data.

**G9**
Go modules manage dependencies. `go.mod` declares the module path and dependencies. `go.sum` stores checksums for security. `go mod tidy` cleans up unused dependencies and updates versions. MVS (Minimum Version Selection) picks the lowest version of a dependency that satisfies all constraints.

**G10**
`defer` schedules a function call to run when the surrounding function returns. Multiple defers execute in LIFO (Last-In, First-Out) order. A common gotcha is capturing loop variables; the deferred function captures the variable by reference, so all closures end up with the final loop value.

**G11**
A pointer holds the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `var p *MyStruct = &MyStruct{Field: "value"}`.

**G12**
`init()` runs before `main()`. A package can have multiple `init()` functions (e.g., in different files). They execute in alphabetical order of the filename.

**G13**
`make` allocates and initializes slices, maps, and channels (e.g., `make(map[string]int)`). `new` allocates a zeroed value of a type and returns a pointer (e.g., `new(int)`). `make` does not work with structs or pointers.

**G14**
Go uses an `error` interface. The idiomatic check is `if err != nil`. `errors.Is` checks if an error wraps a specific target error. `errors.As` type-asserts an error to a specific type, handling wrapping.

**G15**
Composite types: `map[K]V` (zero: `nil`), `[]T` (slice) (zero: `nil`), `chan T` (zero: `nil`), `struct` (zero: zero values of fields).

**G16**
A race condition occurs when two goroutines access shared data concurrently without synchronization. The `-race` flag enables the race detector. Fix: protect shared data with `sync.Mutex` or use channels for communication.

**G17**
`select` chooses a case based on channel readiness. If multiple cases are ready, one is chosen randomly. It differs from `switch` which evaluates expressions. Implement a timeout using `select` with a `time.After` channel.

**G18**
Escape analysis determines if a variable lives on the stack or heap. If a variable is used outside the current function, it escapes to the heap. Use `go build -gcflags="-m"` to inspect. Heap allocation increases GC pressure; stack allocation is faster.

**G19**
`reflect.Type` represents a type; `reflect.Value` represents a value of that type. Reflection is slow due to runtime overhead. It is justified for generic-like behavior or serialization, but code generation (e.g., `go generate`) is preferred for performance.

**G20**
`go:embed` embeds files at compile time. It supports single files, directories, and file systems (`io/fs.FS`). Limitations: paths must be relative to the package root, and the file must exist at build time.

## Rust (20 questions)

**R1**
Ownership ensures memory safety. Rules: 1. Each value has one owner. 2. When the owner goes out of scope, the value is dropped. 3. Only one mutable reference or any number of immutable references can exist.

**R2**
`String` is an owned, heap-allocated UTF-8 string. `&str` is a borrowed slice of UTF-8 data. Use `&str` in function signatures for performance (avoids cloning) unless ownership is required.

**R3**
Borrowing allows accessing data without taking ownership. Immutable references (`&T`) allow multiple readers. Mutable references (`&mut T`) allow modification but only one at a time. The borrow checker enforces these rules to prevent data races.

**R4**
`Result<T, E>` represents success (`Ok`) or failure (`Err`). `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator propagates errors.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)?
}
```

**R5**
`Box<T>` is a heap-allocated pointer (single owner). `Rc<T>` is a thread-local reference-counted pointer. `Arc<T>` is a thread-safe reference-counted pointer. Use `Arc` for shared ownership across threads.

**R6**
Traits define behavior. Go interfaces are implicit; Rust traits are explicit. `dyn Trait` uses dynamic dispatch (vtable). Generic with trait bound (`T: Trait`) uses static dispatch (monomorphization), which is faster.

**R7**
This fails because the compiler cannot determine which reference (`x` or `y`) lives longer. Fix: Add explicit lifetimes (`fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`) or return owned data (`-> String`).

**R8**
`Send` means a type can be moved across threads. `Sync` means it can be shared via references. `Rc<T>` is not `Send` because ref counts are not atomic. `Arc<T>` uses atomic ref counts, making it `Send` and `Sync`.

**R9**
Rust's async uses a state machine (Future trait) rather than OS threads. An executor (e.g., Tokio) polls Futures. Go uses M:N scheduling where goroutines are multiplexed onto OS threads. Rust's async is often more lightweight for I/O but requires an executor.

**R10**
`unsafe` blocks allow pointer arithmetic, dereferating raw pointers, and calling FFI. Justified when interfacing with C or when performance requires bypassing the borrow checker (e.g., `unsafe impl`).

**R11**
Pattern matching (`match`) is exhaustive; the compiler enforces all cases are handled. `if let` is partial and skips other cases.

**R12**
`Vec<T>` is a growable heap array. `[T; N]` is a fixed-size stack array. When `Vec` capacity is exceeded, it reallocates to a larger buffer and copies elements.

**R13**
Rust enums are tagged unions (data + tag). C/Java enums are typically just integer constants. `Option<T>` is an enum with `Some(T)` and `None`. Rust has no null to prevent null pointer dereferences.

**R14**
`impl` defines methods for a type. `&self` borrows immutably, `&mut self` borrows mutably, `self` takes ownership. Associated functions (e.g., `String::new`) do not take `self`.

**R15**
`derive` generates implementations automatically. Common traits: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if the struct has private fields or complex types that don't support the trait.

**R16**
`Cow<'a, T>` (Clone On Write) holds a reference if immutable, or a clone if mutable. Useful for avoiding unnecessary allocations when processing strings that might be modified.

**R17**
`mod` defines a module. `use` imports items. `pub` makes items public. The file system maps to modules (e.g., `src/lib.rs` is the root). Rust 2018 edition changed path resolution to be more explicit.

**R18**
`Pin<P>` prevents a type from being moved in memory. Needed for self-referential structs or async tasks where the memory address must remain stable (e.g., `Pin<&mut T>`). `Unpin` allows moving.

**R19**
Declarative macros (`macro_rules!`) are text substitution. Procedural macros (derive, attribute, function-like) are Rust code that generates code. Hygiene rules prevent macro variables from leaking into the outer scope.

**R20**
Zero-cost abstractions mean high-level code compiles to the same machine code as hand-written low-level code. Iterators avoid allocations, generics use monomorphization (compile-time specialization), and traits use static dispatch (no vtable overhead).
