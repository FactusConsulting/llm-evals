## JavaScript / TypeScript (20 questions)

**JS1** — `var` has function scope and is hoisted (initialized as `undefined`). `let` has block scope and is hoisted but uninitialized (temporal dead zone). `const` has block scope and immutable binding. Hoisting moves declarations to the top of their scope.

**JS2** — The event loop processes the call stack. When empty, it checks the microtask queue (Promises, `queueMicrotask`) before the macrotask queue (`setTimeout`, I/O). This ensures microtasks run before the next macrotask.

**JS3** — A closure is a function bundled with its lexical environment. Example: `function makeCounter() { let c=0; return () => ++c; }`. The classic bug is `var i` in a loop closure; fix with `let i` or an IIFE to capture the current iteration value.

**JS4** — Promises represent async completion. `async/await` is syntactic sugar. Errors are caught via `try/catch`. `Promise.all` rejects on the first failure; `Promise.allSettled` waits for all and returns status for each.

**JS5** — Interfaces define object shapes (methods/properties). Types define primitives, unions, or tuples. Use interfaces for complex objects; types for primitives or unions. Discriminated unions are unions with literal types + a distinguishing property.

**JS6** — JS is prototypal: objects link to prototypes via `[[Prototype]]`. `Object.create(proto)` sets the prototype. ES6 classes are syntactic sugar that compile to prototype chains under the hood.

**JS7** — `this` refers to the execution context. Binding rules (priority): 1. Explicit (`bind`), 2. Implicit (object method), 3. Default (global/undefined), 4. New (constructor). `bind()` returns a new function with bound `this`; it can be re-bound.

**JS8** — `WeakRef` holds a weak reference to an object (can be GC'd). `FinalizationRegistry` runs a callback when the object is GC'd. `WeakMap` keys must be objects because they are weakly held, allowing GC to reclaim them if no strong references exist.

**JS9** — V8 optimizes via hidden classes (shape of objects), inline caching (optimizing hot paths), and deoptimization (reverting optimizations if shape changes). Patterns causing deoptimization: adding/removing properties, changing property types, or modifying object structure.

**JS10** — Tree-shaking removes unused code. ES modules allow static analysis of imports/exports. CommonJS uses dynamic `require`, so bundlers cannot analyze dependencies effectively, preventing tree-shaking.

**JS11** — `null` is an object (empty); `undefined` is uninitialized. `==` coerces types; `===` checks strict equality. `??` returns the right operand if the left is `null` or `undefined`. `?.` safely accesses nested properties.

**JS12** — `map` transforms, `filter` selects, `reduce` aggregates. `reduce` with an initial value avoids the first element being the accumulator. `flatMap` maps and flattens the result one level deep.

**JS13** — Template literals use backticks and allow expressions `${}`. Tagged templates pass raw string segments to a function. Example: `sql` tag function to escape strings for SQL queries.

**JS14** — Destructuring extracts values from objects/arrays. Object: `{ a }`. Array: `[ a ]`. Defaults: `{ a = 1 }`. Renaming: `{ a: b }`. Rest operator `...` gathers remaining elements.

**JS15** — `for...in` iterates enumerable keys (objects); `for...of` iterates values (iterables). Avoid `for...in` on arrays as it includes non-enumerable properties and prototype chain.

**JS16** — Generics allow reusable types. Constraints: `T extends U`. Conditional types: `T extends U ? X : Y`. `infer` extracts a type from a conditional type. Example: `Array<T>` or `Pick<T, K>`.

**JS17** — CommonJS uses `require/module.exports` (Node default). ES Modules use `import/export` (browser/Node with `type: "module"`). `type: "module"` in `package.json` enables ES module resolution.

**JS18** — TypeScript is structural: shape matters. Excess property checks apply to object literals. `extends` checks excess properties; `satisfies` does not. Variance (in/out) determines if a type is covariant or contravariant in generics.

**JS19** — `Proxy` intercepts operations (get, set, call). `Reflect` provides standard operations. Example: A proxy that logs property access or validates assignments before setting.

**JS20** — `SharedArrayBuffer` allows shared memory between threads. `Atomics` provides atomic operations (wait/notify). Workers communicate via shared memory; `Atomics.wait` blocks until `Atomics.notify` is called.

## Bash (20 questions)

**B1** — `$@` expands to positional parameters as separate words; `$*` expands as a single string. `"$@"` preserves word boundaries; `"$*"` joins with the first IFS character (usually space).

**B2** — `set -e` exits on error, `-u` exits on unset variables, `-o pipefail` exits if any command in a pipeline fails.

**B3** — `$(cmd)` is command substitution; `cmd` in backticks is legacy syntax. `$((expr))` is arithmetic expansion; `expr` is an external command for string matching.

**B4** — Process substitution `<(cmd)` creates a named pipe. Example: `diff <(sort file1) <(sort file2)` compares sorted versions without creating temp files.

**B5** — `for f in $(ls)` is dangerous due to word splitting on spaces. Use `for f in *` or `while IFS= read -r -d '' f` with `find -print0`.

**B6** — `<<EOF` is a here document (multiline input). `<<<` is a here string (single line input). `<<-EOF` strips leading whitespace from lines.

**B7** — `cmd > file 2>&1`: stdout to file, stderr to stdout (file). `cmd 2>&1 > file`: stderr to stdout (terminal), stdout to file. `cmd &> file`: both stdout and stderr to file.

**B8** — Use `mkdir -p lockfile` for atomic locking. Add `trap 'rm -rf lockfile' EXIT` for cleanup. Handle `SIGTERM` to ensure cleanup before exit.

**B9** — Single quotes `'...'` prevent expansion; double quotes `"..."` allow variable expansion; no quotes allow globbing. Example: `echo 'a $b'` vs `echo "a $b"`.

**B10** — `-f` checks file, `-d` checks directory, `-r` checks readable. `[ ]` is POSIX test; `[[ ]]` is Bash-specific, supports regex and no word splitting.

**B11** — `$?` is last exit code, `$$` is current PID, `$!` is last background PID, `$#` is number of arguments. Use `$?` to check command success.

**B12** — `function foo {}` and `foo() {}` are equivalent. Return values via `echo` or exit codes (`exit 0`).

**B13** — `PATH` defines command search order. Bash resolves builtins first, then external commands. `type -a` shows which one is used.

**B14** — `trap` sets signal handlers. `EXIT` handlers run last. Order: signals arrive, handlers execute, then `EXIT` handlers.

**B15** — `xargs` batches commands. `xargs -0` handles null-delimited input (from `find -print0`). `xargs -P` runs parallel processes.

**B16** — Arrays: indexed (`arr[0]`). Associative: key-value (`declare -A`). Syntax: `arr+=("val")` vs `arr[key]="val"`.

**B17** — Subshell `(...)` creates new scope; group `{ ... }` shares scope. Piping into `while` creates a subshell, losing variable changes.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (hangup), `SIGKILL` (force). Use `trap` to handle signals and cleanup background processes.

**B19** — Use `split` to divide log, `xargs -P` to process in parallel, and `cat` to merge. Trade-off: parallelism vs overhead. Handle errors by checking exit codes.

**B20** — `exec` replaces the shell. `exec 3>file` redirects FD 3. Coprocess: `coproc name` runs a command with FDs accessible to the parent.

## PowerShell (20 questions)

**PS1** — `Write-Output` sends objects to the pipeline; `Write-Host` writes to the screen. Distinction matters because `Write-Host` breaks pipelines.

**PS2** — Pipeline passes objects. `ForEach-Object` processes pipeline objects; `foreach` is a script block for variables. Use `ForEach-Object` for pipeline data.

**PS3** — `[PSCustomObject]` is an object with properties; `[hashtable]` is key-value pairs. Convert: `[PSCustomObject]@{Key=Value}`.

**PS4** — Terminating errors stop execution; non-terminating continue. `-ErrorAction` controls behavior. `try/catch` handles terminating errors.

**PS5** — Splatting `@params` passes a hashtable as named arguments. Passing a hashtable as a single parameter requires explicit assignment.

**PS6** — `Invoke-Command` runs one-way; `Enter-PSSession` is interactive. Uses WinRM (default) or SSH (PowerShell 7+).

**PS7** — Functions returning arrays behave as objects. Returning 0 items results in an empty array. Correct pattern: `return $result` or `return $null` if empty.

**PS8** — `[scriptblock]` is executable code. Double-hop: Kerberos authentication fails in remote sessions. Solve with CredSSP or `-ArgumentList`.

**PS9** — `@()` creates an array; `[array]` is a type. Force array: `@($x)`. Indexing `$null` throws an error; empty array returns nothing.

**PS10** — `-eq` (equal), `-like` (wildcard), `-match` (regex). Case-sensitive variants: `-ceq`, `-clike`. `-contains` checks list membership; `-in` checks single value.

**PS11** — Modules: script (`.psm1`), manifest (`.psd1`), binary. `Import-Module` loads them.

**PS12** — Interpolation: `"..."` allows `${var}`; `'...'` does not. Here-string: `@"..."@` for multiline.

**PS13** — `Get-Member` explores objects. Properties (data), Methods (functions), NoteProperties (metadata). `Select-Object` selects properties; `Where-Object` filters.

**PS14** — Classes (v5) are dynamic. Limitations: no strict inheritance, no interfaces. Use classes for encapsulation; functions for scripts.

**PS15** — `[CmdletBinding()]` enables advanced functions. `SupportsShouldProcess` adds `-WhatIf/-Confirm`. `Begin/Process/End` blocks for streaming.

**PS16** — Providers: FileSystem, Registry, Certificate. `Get-ChildItem` works across providers. Registry accessed like a file system.

**PS17** — Runspaces: `[runspace]` (thread), `[runspacepool]` (pool), `[powershell]` (pipeline). `ForEach-Object -Parallel` (v7+) vs manual runspace management.

**PS18** — `PSScriptAnalyzer` enforces standards. Rules have severity levels. Suppress with `# #`. Integrate with CI/CD via `Invoke-ScriptAnalyzer`.

**PS19** — `$using:` passes variables to remote/background jobs. `$args` passes positional. Serialization limits (CLIXML depth) affect complex objects.

**PS20** — DSC: configurations, resources, LCM. Windows PowerShell vs PS7+ (PowerShell Core). Modern IaC: Ansible, Terraform, or Bicep.
