## .NET / C# (20 questions)

**DN1**
Classes are reference types (allocated on heap, support inheritance/virtual methods). Structs are value types (allocated on stack, no virtual methods, no inheritance). Use structs for small, immutable data (e.g., coordinates, colors) to avoid heap allocation overhead and enable value semantics.

**DN2**
`IEnumerable<T>` executes queries in memory (LINQ to Objects). `IQueryable<T>` builds expression trees translated to SQL (LINQ to DB). This distinction matters because `IEnumerable` cannot be translated to SQL, causing performance issues when querying databases.

**DN3**
`async/await` uses a state machine to yield control back to the thread pool. `Task` is a reference type wrapper for an operation. `ValueTask` is a union of `Task` and a result, avoiding allocation for short-lived operations. Use `ValueTask` when the operation is synchronous or very short-lived to reduce GC pressure.

**DN4**
Dependency Injection (DI) allows injecting dependencies rather than creating them. Lifetimes: **Transient** (new instance per request), **Scoped** (new instance per request scope, e.g., HTTP request), **Singleton** (one instance per app lifetime). **Common Bug:** Injecting a Scoped service into a Singleton causes a memory leak because the Scoped service is never disposed when the request ends.

**DN5**
`string` is immutable and boxed (allocates on heap). `ReadOnlySpan<char>` is a view into memory (stack or heap) with zero-copy access. Use `Span<T>` for high-performance, zero-copy processing of buffers (e.g., parsing binary data) to avoid allocations.

**DN6**
GC manages memory in generations: **Gen 0** (short-lived), **Gen 1** (medium), **Gen 2** (long-lived). **Large Object Heap (LOH)** stores objects >85KB. `IDisposable` is needed for unmanaged resources (files, DB connections) because the GC does not know when to release them; it relies on `Dispose()` calls.

**DN7**
`ConfigureAwait(false)` prevents the async method from capturing the current `SynchronizationContext`. Use it in library code to avoid deadlocks in UI apps (where the context is the UI thread). Do **not** use it in UI code (e.g., Blazor, WPF) where you need to marshal back to the UI thread.

**DN8**
**Primary Constructors:** Class parameters defined in the class declaration (C# 12). **Collection Expressions:** `new List<int> { 1, 2 }`. **FrozenDictionary:** Immutable dictionary.
*Example:*
```csharp
class Service : IMyService {
    public Service(string name) { /* ... */ }
}
// Usage: var s = new Service("test");
```
(Note: Primary constructors in classes are C# 12/preview; in C# 12 they are stable).

**DN9**
**Cause:** `DbContext` is typically Scoped. If configured as Singleton or accessed statically, multiple threads may dispose it simultaneously.
**Fix:** Ensure `DbContext` is registered as `Scoped`. Use `UseDbContext` in DI. Avoid static `DbContext` instances.

**DN10**
**Record:** Reference type with value equality and immutability by default. **Record Struct:** Value type with value equality. Use **Record** for DTOs/Entities (reference semantics). Use **Record Struct** for small, immutable data (e.g., `Point`).

**DN11**
`ref`: Read/write reference. `out`: Write-only (caller receives value). `in`: Read-only reference (C# 7.2+). Use `in` for large structs to prevent accidental modification and improve performance.

**DN12**
`?` on reference types (e.g., `string?`) enables nullable reference type analysis (compile-time warnings). `int?` is a nullable value type (struct) that can hold `null` at runtime.

**DN13**
LINQ is Language Integrated Query. **Method Syntax:** `list.Where(...)`. **Query Syntax:** `from x in list where ...`. Both are identical. **Deferred Execution:** Queries are not executed until the result is enumerated (e.g., `ToList()`).

**DN14**
Constraints limit generic types. `class`: reference type. `struct`: value type. `new()`: parameterless constructor. `IComparable<T>`: interface. Combine constraints (e.g., `where T : class, new()`) to enforce multiple rules simultaneously.

**DN15**
**Abstract Class:** Can have state, constructors, and multiple inheritance (no). **Interface:** No state (pre-C# 8), no constructors. **C# 8+ Interfaces:** Can have default method implementations, narrowing the distinction (e.g., `interface` vs `abstract class` with default methods).

**DN16**
Middleware pipeline processes requests sequentially. `app.Use()` adds middleware to the pipeline. `app.Map()` branches the pipeline (e.g., for sub-apps). `app.Run()` executes immediately. **Order:** Top-to-bottom. **Exception Handling:** Middleware can catch exceptions and return 500 responses.

**DN17**
`Channel<T>` is a bounded/unbounded queue with backpressure (producer waits if full). `BlockingCollection<T>` is unbounded and does not support backpressure. Use `Channel<T>` for producer-consumer patterns requiring flow control.

**DN18**
**Source Generators:** Compile-time code generation. Faster than reflection. **Incremental:** Only regenerates code when source changes (preferred for large projects). **ISourceGenerator:** Runs on every build (slower). Incremental is preferred for performance.

**DN19**
**TPL Dataflow:** High-level pipeline. `ActionBlock` (sink), `TransformBlock` (process), `BufferBlock` (buffer). **Comparison:** `Channels` is lower-level (no built-in transformation logic), Dataflow is higher-level (easier to compose pipelines).

**DN20**
**Minimal APIs:** `app.MapGet(...)`. No controllers. **Trade-offs:** Less boilerplate, but harder to test (no DI injection by default), requires `AddOpenApi` for Swagger. **Route Groups:** `app.MapGroup(...)`. **Endpoint Filters:** Middleware-like logic attached to specific endpoints.

## Python (20 questions)

**P1**
**List:** Mutable sequence. **Tuple:** Immutable sequence. **Set:** Mutable unordered collection of unique items. **Frozenset:** Immutable set.

**P2**
**GIL:** Locks bytecode execution to one thread per process. Affects CPU-bound multi-threading. **Workarounds:** Multiprocessing (separate processes), C-extensions (release GIL), or async I/O (non-blocking).

**P3**
`copy` creates a shallow copy (container is new, contents are references). `deepcopy` creates new copies of contents. **Example:** `a = [[1]]; b = copy(a); b[0].append(2); print(a)` -> `a` changes because `b[0]` points to the same list.

**P4**
Decorators wrap functions.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start:.2f}s")
        return result
    return wrapper
```

**P5**
Generators use `yield` to return values and pause state. They differ from lists by being lazy (memory efficient). `yield from` delegates to another iterable/generator.

**P6**
`asyncio.run()` starts the event loop. `asyncio.gather()` waits for all tasks. `asyncio.create_task()` schedules a task. `time.sleep()` blocks the loop; use `await asyncio.sleep()` instead.

**P7**
Python uses **C3 Linearization** for MRO.
MRO for `D(B, C)`: `[D, B, C, A]`.
Lookup `who`: D (no), B (no), C (yes -> "C").
**Output:** `C`.
**Reason:** `B` inherits from `A`, `C` overrides `who`. `D` inherits `B` first, but `B` has no `who`, so it falls to `C`.

**P8**
**Metaclass:** Class of a class. **`__init_subclass__`:** Hook called when a subclass is defined (Python 3.6+). **Use Case:** Metaclass for global control (e.g., ORM base classes). `__init_subclass__` for per-class logic (e.g., adding methods to specific subclasses).

**P9**
**Threading:** Shared memory, GIL limits CPU parallelism. **Multiprocessing:** Separate processes, no GIL, requires pickling. **`concurrent.futures`:** Abstraction layer. Use **Multiprocessing** for CPU-bound tasks; **Threading** for I/O-bound tasks.

**P10**
`__slots__` prevents `__dict__` creation, saving memory and preventing dynamic attributes. **Impact:** Faster attribute access, less memory, but no dynamic attributes.

**P11**
**Virtual Environment:** Isolates dependencies. `venv` (stdlib), `virtualenv` (3rd party), `conda` (manages packages + envs, binary dependencies). Use `venv` for standard Python projects.

**P12**
Comprehensions: `[x for x in list]`, `{k: v for k, v in dict}`, `{x for x in list}`. Equivalent to `map()` and `filter()` but more readable. Prefer comprehensions for simple transformations.

**P13**
`==` checks value equality. `is` checks identity (same object). **Interning:** Python caches small integers (e.g., -5 to 256), so `a is b` returns `True` for these values even if created separately.

**P14**
`*args` (positional), `**kwargs` (keyword). `/` marks positional-only parameters (e.g., `def f(a, /, b)`). `*` marks keyword-only (e.g., `def f(a, *, b)`).

**P15**
Context managers manage resources (e.g., files). `__enter__/__exit__` is the protocol. `@contextmanager` (from `contextlib`) is a generator-based decorator. **Example:** `with open(...) as f:`.

**P16**
Type hinting for static analysis. `Union` (multiple types), `Optional` (Union[None, T]), `Literal` (exact values), `TypeVar` (generic types), `Protocol` (structural typing). Tools like `mypy` check these.

**P17**
`__repr__` (debug), `__str__` (user). `__eq__` (equality), `__hash__` (dict key). Defining `__eq__` without `__hash__` sets `__hash__` to `None` (unhashable).

**P18**
**Descriptors:** Objects that control attribute access (`__get__`, `__set__`, `__delete__`). `property`, `classmethod`, `staticmethod` are descriptors. They intercept access to attributes.

**P19**
**Imports:** Relative (`.`) vs Absolute (`module`). `sys.path` determines search order. `__init__.py` makes a directory a package. **Namespace packages:** No `__init__.py`. **Finder/Loader:** Finder finds modules, Loader loads them.

**P20**
**Dataclasses:** Auto-generate `__init__`, `__repr__`, etc. `__post_init__` for logic. `frozen` for immutability. **Pydantic:** Adds validation and serialization. Use **Pydantic** for API data validation; **Dataclasses** for internal logic.
