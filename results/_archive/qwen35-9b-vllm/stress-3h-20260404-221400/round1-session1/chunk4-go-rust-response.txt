G1 — Easy: Arrays are fixed-size, value types stored contiguously in memory. Slices are dynamic, reference types pointing to an underlying array with a length and capacity. Appending to a full slice allocates a new underlying array (usually double the capacity), copies the old data, and returns a new slice pointing to the new array.

G2 — Easy: `var x int` declares a variable with a zero value (`0`) without initializing it. `x := 0` is a short variable declaration that initializes `x` to `0`. You cannot use `:=` if the variable is already declared in the current scope (e.g., inside a function where `x` exists). `:=` is also not allowed in package-level declarations.

G3 — Medium: A goroutine is a lightweight thread managed by the Go runtime (M:N scheduling), whereas an OS thread is a heavy kernel resource (1:1). The GMP model consists of G (goroutine), M (machine/OS thread), and P (processor). The scheduler maps Gs to Ps, and Ps to Ms, allowing efficient multiplexing of thousands of goroutines across fewer OS threads.

G4 — Medium: Channels allow safe communication between goroutines. Unbuffered channels block until a receiver is ready; buffered channels store up to `N` values. Sending to a full buffered channel blocks the sender until a receiver removes an item.

G5 — Medium: The `context` package manages request-scoped values (cancellation, deadlines, values).
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
resp, err := http.Get("https://example.com", &http.Client{Timeout: 0})
// Use ctx in request: http.Get(ctx, "https://example.com")
```

G6 — Medium: Go interfaces are implicit (satisfied by implementing methods), whereas Java/C# require explicit implementation. `interface{}` (or `any`) accepts any type, enabling generic-like behavior without generics, but it forces dynamic dispatch (runtime type checks), impacting performance and type safety.

G7 — Hard: This code is unsafe due to data races and lack of memory ordering. `ready` is not atomic, and there is no memory barrier. The compiler may reorder writes, or the CPU may not see `data` before `ready` becomes true. Correct alternatives: use `sync.WaitGroup` (wait for completion), `sync.Mutex` (protect shared state), or `atomic.Bool` (for simple flags).

G8 — Hard: `sync.Mutex` allows only one writer; `sync.RWMutex` allows multiple concurrent readers but exclusive writers. `sync.Map` is optimized for high-concurrency read-heavy workloads (no locking for reads, optimized writes). Regular maps with mutexes are better for low contention or complex logic requiring atomicity. `sync.Map` trades off write performance for read scalability.

G9 — Hard: Go modules manage dependencies. `go.mod` declares the module path and requirements; `go.sum` stores checksums for security. `go mod tidy` cleans up unused dependencies and updates versions. MVS (Minimum Version Selection) selects the minimum version of a transitive dependency that satisfies all direct dependencies' constraints.

G10 — Medium: `defer` schedules a function call to run when the surrounding function exits. Multiple defers execute in LIFO (Last-In, First-Out) order. A common gotcha is capturing loop variables: `defer` captures the variable by reference, so all defers in a loop may see the final loop value.

G11 — Easy: A pointer holds the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `var p *MyStruct = &MyStruct{}`.

G12 — Easy: `init()` runs before `main()`. A package can have multiple `init()` functions (e.g., in different files). They execute in the order of file declaration within the package.

G13 — Easy: `make` allocates and initializes slices, maps, and channels (e.g., `make(map[string]int)`). `new` allocates a zero value of a type on the heap (e.g., `new(int)` returns `*int`). `make` works only for slice/map/channel; `new` works for any type.

G14 — Easy: Errors are values implementing the `error` interface (`Error() string`). Idiomatic check: `if err != nil`. `errors.Is` checks if an error wraps a specific target error; `errors.As` type-asserts an error to a specific type. `==` only checks identity (same pointer).

G15 — Easy: Composite types: `map[K]V` (zero: `nil`), `[]T` (slice) (zero: `nil`), `chan T` (zero: `nil`), `struct` (zero: zero values of fields).

G16 — Medium: A race condition occurs when two goroutines access shared data concurrently without synchronization. The `-race` flag uses ThreadSanitizer to detect unsynchronized access. Fix: protect with `sync.Mutex` or use channels for communication.
```go
var x int
// Goroutine 1: x++
// Goroutine 2: x++
// Fix: mutex.Lock(); x++; mutex.Unlock()
```

G17 — Medium: `select` chooses a ready channel case. If multiple are ready, it picks one randomly. If none are ready, it blocks. Implement timeout: `select { case <-ch: ...; case <-time.After(d): ... }`.

G18 — Hard: Escape analysis determines if a variable escapes the stack frame (heap allocation). The compiler checks if a variable is used outside the function. Inspect with `go build -gcflags="-m"`. It matters because heap allocation incurs GC overhead; stack allocation is faster.

G19 — Hard: `reflect` allows runtime introspection. `reflect.Type` describes a type; `reflect.Value` holds the value. Reflection is slow (dynamic dispatch, indirection). Justified for configuration, serialization, or dynamic code generation; avoid in performance-critical paths.

G20 — Hard: `go:embed` embeds files at compile time. Supports files, directories, and `io/fs.FS`. Limitations: paths must be static at compile time; cannot embed from external URLs. Interacts with `io/fs.FS` by embedding the FS into the binary.

R1 — Easy: Ownership means each value has a single owner responsible for its memory. Rules: 1. Each value has one owner. 2. When the owner goes out of scope, the value is dropped. 3. You can have multiple references, but only one mutable reference at a time.

R2 — Easy: `String` is an owned heap-allocated string; `&str` is a borrowed slice of UTF-8 bytes. Use `String` when you need to own the data; use `&str` for function arguments to avoid unnecessary copies.

R3 — Medium: Borrowing allows accessing data without ownership. Immutable references (`&T`) allow multiple readers. Mutable references (`&mut T`) allow modification but only one at a time. The borrow checker enforces no aliasing (no mutable + immutable reference to same data simultaneously).

R4 — Medium: `Result<T, E>` holds success (`Ok`) or failure (`Err`). `Option<T>` holds `Some` or `None`. `?` propagates errors/panics.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)?
}
```

R5 — Medium: `Box<T>` is a heap pointer (single owner). `Rc<T>` is a thread-local reference-counted pointer. `Arc<T>` is an atomic reference-counted pointer for multi-threading. Use `Box` for single ownership on heap; `Rc` for single-threaded sharing; `Arc` for concurrent sharing.

R6 — Medium: Traits define behavior. Go interfaces are implicit; Rust traits are explicit. `dyn Trait` (trait object) uses vtables (dynamic dispatch). Generic `T: Trait` uses monomorphization (static dispatch), which is faster and more type-safe.

R7 — Hard: This fails because the compiler cannot determine which reference (`x` or `y`) lives longer than the return value. Fix: Add a lifetime annotation.
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { ... }
```

R8 — Hard: `Send` means a type can be sent across threads; `Sync` means it can be shared between threads. `Rc<T>` is not `Send` because its reference count is not atomic. `Arc<T>` uses atomic reference counting, making it safe for concurrent use.

R9 — Hard: Rust async uses state machines (Futures). A `Future` is a type that can be polled. An executor (e.g., Tokio) drives these futures. Unlike Go's M:N scheduler, Rust async relies on cooperative multitasking via polling, avoiding OS thread overhead but requiring an explicit runtime.

R10 — Medium: `unsafe` blocks allow bypassing safety checks. 3 things: dereferencing raw pointers, calling FFI functions, or accessing non-atomic shared memory. Justified for FFI, low-level hardware access, or when you guarantee safety manually.

R11 — Easy: Pattern matching (`match`) is exhaustive (compiler checks all cases). `if let` is partial (skips if pattern doesn't match). The compiler enforces that `match` covers all possible variants of the type.

R12 — Easy: `Vec<T>` is a growable heap array; `[T; N]` is a fixed-size stack array. When `Vec` capacity is exceeded, it allocates a larger buffer (usually 1.5x or 2x) and copies elements.

R13 — Easy: Rust enums are tagged unions (data + tag). C/Java enums are typically just integer constants. `Option<T>` is an enum with `Some(T)` and `None`. Rust has no null; `Option` replaces it to prevent null pointer dereferences.

R14 — Easy: `impl` defines methods for a type. `&self` borrows the instance; `&mut self` mutably borrows; `self` takes ownership. Associated functions (e.g., `String::new()`) take `&Self` or no self and are called on the type itself.

R15 — Easy: `derive` generates implementations automatically. Common traits: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if the type has complex logic (e.g., custom `Clone` that drops fields) or if the type is not `Copy`/`Clone` compatible.

R16 — Medium: `Cow<'a, T>` (Clone On Write) holds a reference if immutable, or a clone if mutable. Useful for avoiding allocations when data is read-only.
```rust
let s = Cow::Borrowed("hello");
let mut s = Cow::from("hello");
s.to_mut(); // Forces clone if mutable
```

R17 — Medium: `mod` declares a module; `use` imports items; `pub` makes items public. File system maps to modules (e.g., `src/lib.rs` -> `lib` module). Rust 2018 edition changed path resolution to be more explicit (e.g., `mod foo` in `foo.rs`).

R18 — Hard: `Pin<T>` prevents a value from being moved, ensuring its memory address stays stable. Needed for self-referential structs (pointers to self) and async tasks (Futures might be moved). `Unpin` allows a pinned type to be moved.

R19 — Hard: Declarative macros (`macro_rules!`) are text substitution (hygienic). Procedural macros (derive, attribute, function) are Rust code compiled to a macro. Hygiene rules prevent macro variables from leaking into the outer scope.

R20 — Hard: Zero-cost abstractions mean high-level code compiles to code as efficient as hand-written C. Iterators avoid allocations (lazy evaluation). Generics use monomorphization (code generated per type). Traits use static dispatch (resolved at compile time), avoiding vtable overhead.
