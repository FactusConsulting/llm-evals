## JavaScript / TypeScript

**JS1**
`var` is function-scoped and hoisted (initialized as `undefined`). `let` is block-scoped and hoisted (temporal dead zone). `const` is block-scoped, hoisted, and requires initialization. Hoisting is the parsing phase where declarations are moved to the top of their scope.

**JS2**
The event loop processes the call stack. When the stack is empty, it checks the microtask queue (Promises, `queueMicrotask`) before the macrotask queue (callbacks, `setTimeout`). Microtasks run to completion before any macrotask.

**JS3**
A closure is a function bundled with its lexical environment. Example: `function makeCounter() { let c = 0; return () => ++c; }`. The classic bug is `for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i)) }`, which logs `3` three times. Fix: use `let` (block scope) or `i => { setTimeout(() => console.log(i)) }` (arrow function captures current `i`).

**JS4**
Promises represent async completion. `async/await` is syntactic sugar over Promises. Errors in `await` throw synchronously. `Promise.all` rejects if *any* promise rejects. `Promise.allSettled` waits for all to settle (fulfilled or rejected) without rejecting early.

**JS5**
Interfaces define shapes for objects/classes and support method overloading. Types define primitive or union shapes. Use interfaces for object structures; types for primitives/complex unions. Discriminated unions use a literal type to distinguish union members (e.g., `{ type: 'success' } | { type: 'error' }`).

**JS6**
JS uses prototypes. `Object.create(proto)` creates an object with `__proto__` pointing to `proto`. ES6 classes are syntactic sugar over prototype chains; `class` creates a constructor function, and `extends` sets up the prototype chain.

**JS7**
`this` refers to the execution context. Binding rules (priority): 1. Explicit binding (`obj.method()`), 2. Implicit binding (`obj.method()`), 3. `new` binding, 4. Default binding (global/undefined). `bind()` returns a new function with `this` permanently bound. It can be re-bound, but the original binding is lost.

**JS8**
`WeakRef` allows weak references to objects (garbage collectable). `FinalizationRegistry` registers callbacks when an object is GC'd. `WeakMap` keys must be objects because primitives are not GC'd and cannot be weakly referenced.

**JS9**
V8 optimizes via hidden classes (shape of object properties) and inline caching (caching property access locations). Deoptimization occurs if assumptions break (e.g., adding a property to an object that previously had a hidden class without it, or changing property order).

**JS10**
Tree-shaking removes unused code. ES Modules use static `import/export` statements, allowing static analysis. CommonJS uses dynamic `require()`, making static analysis impossible, so it cannot be tree-shaken effectively.

**JS11**
`null` is an empty object value; `undefined` is uninitialized. `==` performs type coercion (e.g., `null == undefined` is true); `===` checks strict equality. `??` returns the right operand if the left is `null` or `undefined`. `?.` safely accesses nested properties (returns `undefined` if path breaks).

**JS12**
`map()` transforms elements; `filter()` returns a subset; `reduce()` aggregates into a single value. `reduce` takes an accumulator and current value. `flatMap()` maps then flattens the result by one level (useful for nested arrays).

**JS13**
Template literals use backticks `` ` `` and allow interpolation `${expr}`. Tagged templates pass raw strings to a function. Example: `sql` tag function joins strings safely to prevent SQL injection.

**JS14**
Destructuring extracts values. Object: `{ a } = obj`. Array: `[ a ] = arr`. Defaults: `{ a = 1 }`. Renaming: `{ a: b }`. Rest `...` collects remaining elements/properties into an array/object.

**JS15**
`for...in` iterates enumerable own and inherited properties (use for objects). `for...of` iterates iterable values (use for arrays). Avoid `for...in` on arrays as it iterates indices and non-array properties.

**JS16**
Generics create reusable components with type parameters. Constraints: `T extends U`. Conditional types: `T extends U ? X : Y`. `infer` extracts types from conditional types (e.g., `Extract`). Example: `Array<T>` or `Pick<T, K>`.

**JS17**
CommonJS uses `require/module.exports` (Node default). ES Modules use `import/export` (browser default). Node supports both via `--experimental-modules` or `"type": "module"` in `package.json`.

**JS18**
TypeScript is structural (types match by shape). Excess property checks apply to object literals passed to constructors/functions. `extends` checks structure; `satisfies` checks structure without excess property checks. Variance: `in` (contravariant) for inputs, `out` (covariant) for outputs.

**JS19**
`Proxy` creates a proxy object to intercept operations. `Reflect` provides standard operations. Intercepts: `get` (access), `set` (assignment), `apply` (calls). Example: A proxy that logs property changes before updating.

**JS20**
`SharedArrayBuffer` allows memory sharing between threads (Web Workers). `Atomics` provides atomic operations (wait/notify) for synchronization. Workers communicate via `postMessage` or shared memory. `Atomics.wait` blocks until notified.

## Bash

**B1**
`$@` expands to each argument as a separate word. `$*` expands to all arguments as a single string. `"$@"` preserves word boundaries (safe). `"$*"` joins with spaces (unsafe for special chars).

**B2**
`set -e`: Exit on error. `set -u`: Error on undefined variable. `set -o pipefail`: Propagate pipe errors.

**B3**
`$(command)` is command substitution (output). `command` is backticks (deprecated). `$((expr))` is arithmetic expansion. `expr` is an external command for string/math operations.

**B4**
Process substitution `<(command)` creates a named pipe (FIFO) so the command output can be read as a file. Example: `diff <(sort file1) <(sort file2)`.

**B5**
Use `while IFS= read -r -d '' file; do ...; done < <(find . -print0)`. `for f in $(ls)` splits on whitespace, breaking files with spaces.

**B6**
`<<EOF` reads until EOF. `<<<` is a here-string (piped to stdin). `<<-` allows indentation of the delimiter.

**B7**
`cmd > file 2>&1`: stdout to file, then stderr to file. `cmd 2>&1 > file`: stderr to stdout (stdout), then stdout to file (stderr lost). `cmd &> file`: both to file. First two differ because redirection order matters.

**B8**
```bash
lock() {
    local lockfile="/tmp/mylock.$$"
    mkdir "$lockfile" 2>/dev/null && return 1
    trap 'rm -f "$lockfile"' EXIT
    mkdir "$lockfile"
}
```
`mkdir` is atomic on most filesystems, preventing race conditions better than `touch`.

**B9**
Single quotes `'...'`: literal, no expansion. Double quotes `"..."`: variable expansion, no glob. No quotes: glob expansion and variable expansion. Example: `echo 'a$b'` vs `echo "a$b"`.

**B10**
`[ -f file ]`, `[ -d file ]`, `[ -r file ]`. `[ ]` uses word splitting; `[[ ]]` is a keyword, safer for globbing and doesn't split.

**B11**
`$?`: Exit status of last command. `$$`: PID of current shell. `$!`: PID of last background process. `$#`: Number of arguments passed to a function/script.

**B12**
`function foo {}` or `foo() {}`. Return values via `echo` or `return` (integer). Functions are global by default.

**B13**
`PATH` is a colon-separated list of directories. Bash searches `PATH` for executables. Builtins are internal (e.g., `cd`); external are in `PATH`. Use `type` or `which` to check.

**B14**
`trap 'cmd' signal`. `EXIT`: script end. `ERR`: command failure. `INT`: Ctrl+C. `TERM`: kill. Order: signals are handled asynchronously; `EXIT` runs last.

**B15**
`xargs` processes arguments from stdin. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P` runs parallel processes.

**B16**
Arrays: `arr=(1 2)`, `${#arr[@]}`. Associative: `declare -A arr`, `arr[key]=val`, `${#arr[@]}`. Syntax differs; associative uses keys.

**B17**
Subshell `(...)` creates a new shell (variables don't persist). Group `{ ... }` shares scope. Piping into `while` runs `while` in a subshell, losing variable changes.

**B18**
Signals: `SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (hangup), `SIGKILL` (unkillable). Use `trap` to handle signals and cleanup background jobs (`wait`).

**B19**
```bash
split -l 1000 log.txt part_
xargs -P 4 -I {} process {}
cat part_* > merged.txt
```
Trade-off: Parallelism vs I/O contention. Handle errors by checking exit codes in the processing function and merging only successful parts.

**B20**
`exec` replaces the current shell with a command. `exec 3>file` redirects FD 3. Coprocess: `coproc name; read -p "Prompt" name`. Used for interactive background processes.

## PowerShell

**PS1**
`Write-Output` sends objects to the pipeline. `Write-Host` writes to the console (bypasses pipeline). Distinction matters for piping data to other commands.

**PS2**
Pipeline passes objects. `ForEach-Object` is a cmdlet (pipeline-aware). `foreach` is a statement (not pipeline-aware). Use `ForEach-Object` for object processing.

**PS3**
`[PSCustomObject]` creates an object with properties. `[hashtable]` is a collection of key-value pairs. Convert: `@{ } | ConvertFrom-Hashtable` or `[PSCustomObject]@{ }`.

**PS4**
Terminating errors stop execution. Non-terminating continue. `-ErrorAction Stop` forces terminating. `try/catch` catches terminating errors.

**PS5**
Splatting `@params` passes a hashtable as named arguments. Passing a hashtable as a single argument treats it as a single object.

**PS6**
`Invoke-Command` runs a script on remote. `Enter-PSSession` opens an interactive session. Uses WinRM (HTTP/HTTPS) or SSH (PowerShell 7+).

**PS7**
Functions returning scalars (strings) are treated as arrays if piped. Returning 0 items results in an empty array. Correct pattern: `return $result` (ensure it's an array or use `@($result)`).

**PS8**
`[scriptblock]` is a block of code. Pass to remote via `-ScriptBlock`. Double-hop: Kerberos ticket delegation fails. Solve with CredSSP (`-Credential`) or `-ArgumentList` (if variables are passed).

**PS9**
`@()` creates an array. `[array]` is a type. Force single result: `@($result)`. Indexing `$null` throws; empty array returns nothing.

**PS10**
`-eq` (equal), `-ne` (not equal), `-like` (wildcard), `-match` (regex), `-contains` (array), `-in` (scalar check). Case-insensitive variants: `-ceq`, `-clike`. `-contains` checks array membership; `-in` checks scalar membership.

**PS11**
Modules are reusable code. `.psm1` (script), `.psd1` (manifest), `.ps1` (binary). `Import-Module` loads the module.

**PS12**
Interpolation: `"${variable}"`. Single quotes `'...'` no interpolation. Here-string: `@"..."@` for multi-line strings.

**PS13**
`Get-Member` lists properties/methods. `Select-Object` selects properties; `Where-Object` filters objects. NoteProperties are read-only.

**PS14**
PowerShell classes (v5) are dynamic. Limited inheritance (no multiple). Use classes for reusable stateful objects; functions for logic.

**PS15**
`[CmdletBinding()]` enables advanced functions. `SupportsShouldProcess` adds `-WhatIf/-Confirm`. `ValueFromPipeline` allows piping objects. `Begin/Process/End` blocks handle streaming.

**PS16**
Providers abstract data access. `Get-ChildItem` works on FileSystem, Registry, etc. Registry: `Get-ChildItem HKCU:\Software`.

**PS17**
Runspaces are threads. `[runspacepool]` manages them. `ForEach-Object -Parallel` (v7+) uses runspaces automatically. Manual management gives more control.

**PS18**
`PSScriptAnalyzer` enforces rules. Rules have severity (Error, Warning, Info). Suppress via `# # nocurly`. Integrate via CI/CD (e.g., GitHub Actions).

**PS19**
`$using:` passes variables to background jobs/parallel. `-ArgumentList` passes arguments. Serialization limits (CLIXML depth) affect complex objects (e.g., nested arrays).

**PS20**
DSC manages configuration state. Configurations define desired state; Resources implement actions. LCM applies them. DSC is legacy; modern IaC uses Ansible/Terraform.
