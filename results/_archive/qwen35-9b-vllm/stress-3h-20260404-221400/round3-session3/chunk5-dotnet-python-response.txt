**DN1** — Classes are reference types (allocated on heap, identity-based equality); structs are value types (allocated on stack, value-based equality). Use structs for small, immutable data (e.g., coordinates) to avoid heap allocation overhead and enable value semantics (pass by value).

**DN2** — `IEnumerable<T>` executes queries in memory (LINQ to Objects); `IQueryable<T>` builds expression trees translated to SQL (LINQ to DB). This distinction matters because `IEnumerable` cannot be translated to SQL, while `IQueryable` allows database providers to optimize queries.

**DN3** — `async/await` uses state machines to suspend execution without blocking threads. `Task` is a reference type; `ValueTask` is a struct optimized for short-lived operations to avoid boxing/allocations. Use `ValueTask` when the method is often synchronous or returns a result immediately, reducing GC pressure.

**DN4** — Dependency Injection (DI) allows injecting dependencies rather than creating them. Lifetimes: Transient (new instance per request), Scoped (new per request), Singleton (one instance per app). Common bug: Injecting a Scoped service into a Singleton. The Scoped service is never disposed when the request ends, causing memory leaks.

**DN5** — `string` is immutable and allocates memory; `ReadOnlySpan<char>` is a view over existing memory with zero-copy access. Use `Span<T>` for high-performance, zero-copy processing of buffers (e.g., parsing binary data) to avoid unnecessary allocations.

**DN6** — GC manages memory in generations: Gen 0 (short-lived), Gen 1 (medium), Gen 2 (long-lived). Large Object Heap (LOH) stores objects >85KB. `IDisposable` is needed for deterministic cleanup of unmanaged resources (files, DB connections) because GC is non-deterministic.

**DN7** — Default `await` captures the `SynchronizationContext` (e.g., UI thread). `ConfigureAwait(false)` suppresses this. Use `false` in libraries to avoid deadlocks in library consumers; do NOT use in UI apps where context is required for UI updates.

**DN8** — Primary constructors allow parameters in class definitions (C# 12/.NET 8+). Collection expressions create collections inline. `FrozenDictionary` is immutable. Example: `class Service(string name) : IService { ... }` allows DI registration via constructor injection directly in the class definition.

**DN9** — Cause: `DbContext` is Scoped, but if injected into a Singleton or misconfigured, it may be disposed prematurely or held too long. Fix: Ensure `DbContext` is Scoped per request. EF Core expects `DbContext` to be disposed after use; misaligned lifetimes cause `ObjectDisposedException`.

**DN10** — Records provide value-based equality and immutability by default. `class` is mutable with reference equality. `record struct` is a value type with value equality. Choose records for DTOs/immutable data; classes for mutable state.

**DN11** — `ref`: read/write reference. `out`: write-only (caller receives value). `in`: read-only reference (performance optimization). Use `in` for large structs passed by reference to prevent copying while ensuring safety.

**DN12** — `?` on reference types (e.g., `string?`) enables nullable reference types for compile-time safety. `int?` is a nullable value type (struct) representing `null` or a value. They differ in semantics and allocation (nullable ref types are metadata, nullable value types are structs).

**DN13** — LINQ is Language Integrated Query. Method syntax is `list.Where(...)`. Query syntax is `from x in list where ...`. Both are equivalent. Deferred execution means queries aren't run until the result is enumerated (e.g., `ToList()`).

**DN14** — Constraints limit generic types. `class` (reference), `struct` (value), `new()` (parameterless ctor), `IComparable<T>` (interface). Combine constraints (e.g., `where T : class, new()`) to enforce multiple requirements simultaneously.

**DN15** — Abstract classes can have state/constructors; interfaces cannot (pre-C# 8). C# 8+ interfaces support default methods and properties. Use abstract classes for shared implementation/state; interfaces for contracts/abstractions.

**DN16** — Middleware pipeline processes requests sequentially. `app.Use()` adds middleware to the pipeline. `app.Map()` creates a sub-tree for specific routes. `app.Run()` executes immediately and stops the pipeline. Order matters for logic flow; exception middleware should be near the end to catch all errors.

**DN17** — `Channel<T>` supports bounded/unbounded queues with backpressure. `BlockingCollection<T>` is unbounded and lacks backpressure. Use bounded `Channel<T>` for producer-consumer scenarios to prevent memory exhaustion.

**DN18** — Source Generators compile code at build time. Reflection is runtime; IL weaving is runtime. Incremental generators update only changed files (faster builds) vs `ISourceGenerator` (full rebuild). Incremental is preferred for large projects.

**DN19** — TPL Dataflow provides pipeline blocks: `ActionBlock` (sink), `TransformBlock` (process), `BufferBlock` (buffer). It is higher-level than `Channels`, handling pipeline logic automatically, whereas `Channels` requires manual management of producers/consumers.

**DN20** — Minimal APIs are procedural (`app.MapGet`). Controllers use classes. Trade-offs: Minimal APIs are lighter but harder to test (less DI) and require manual OpenAPI configuration. Route groups organize endpoints; endpoint filters add logic to specific routes.

**P1** — Lists are mutable sequences; tuples are immutable. Sets are mutable collections of unique items; `frozenset` is immutable. Use tuples for fixed data; lists for dynamic data.

**P2** — GIL prevents multiple threads from executing Python bytecode simultaneously. It affects CPU-bound workloads. Workarounds: Multiprocessing (separate processes), C-extensions (C-level threading), or async I/O.

**P3** — `copy` creates a shallow copy (nested objects share references); `deepcopy` creates a full copy. Example: `l1 = [[1]]; l2 = copy(l1); l2[0][0] = 2` modifies `l1` because the inner list is shared.

**P4** — Decorators wrap functions. Example:
```python
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start}")
        return result
    return wrapper
```

**P5** — Generators use `yield` to return values lazily (one at a time). Returning a list creates all items upfront. `yield from` delegates to another iterable. Generators save memory for large datasets.

**P6** — Event loop drives async tasks. `asyncio.run()` starts the loop. `gather()` waits for all tasks. `create_task()` schedules a task. `time.sleep()` blocks the loop; use `asyncio.sleep()` instead.

**P7** — Python uses C3 Linearization for MRO. For `D(B, C)`, MRO is `D -> B -> C -> A`. `B` has no `who`, `C` has `who`. Thus `D().who()` returns "C".

**P8** — Metaclasses control class creation. `__init_subclass__` (Python 3.6+) is a hook for subclass creation (easier than metaclasses). Use metaclasses for runtime control (e.g., modifying class attributes); use `__init_subclass__` for simpler hooks (e.g., adding default methods).

**P9** — Threading shares memory (GIL limit); Multiprocessing uses separate processes (no GIL). `concurrent.futures` abstracts both. Multiprocessing requires pickling (serialization) of objects; threading does not.

**P10** — `__slots__` prevents `__dict__` creation, saving memory and preventing dynamic attributes. Use for classes with many instances (e.g., data models). It prevents adding new attributes at runtime.

**P11** — Virtual environments isolate dependencies. `venv` is built-in; `virtualenv` is a 3rd party tool; `conda` manages environments + packages (binary dependencies). Use `venv` for standard Python projects.

**P12** — Comprehensions `[x for x in ...]` are concise loops. `map()` applies a function; `filter()` filters items. Comprehensions are often faster and more readable than functional equivalents.

**P13** — `==` checks value equality; `is` checks identity (same object). Small integers (0-256) are interned, so `is` returns True. Large integers or strings are not interned by default.

**P14** — `*args` collects positional args; `**kwargs` collects keyword args. `/` marks positional-only parameters; `*` marks keyword-only parameters. Example: `def f(a, /, b, *, c): ...`

**P15** — Context managers manage resources (e.g., files). `__enter__/__exit__` is the protocol. `@contextmanager` (generator) is easier to write. Example: `with open(...)` or `with lock:`.

**P16** — Type hinting enables static analysis. `Union` (multiple types), `Optional` (Union[None, T]), `Literal` (exact values), `TypeVar` (generic types), `Protocol` (structural typing). Tools like `mypy` check these hints.

**P17** — `__repr__` for debugging; `__str__` for users. `__eq__` for equality; `__hash__` for dict keys. Defining `__eq__` without `__hash__` sets `__hash__` to `None`, making the object unhashable.

**P18** — Descriptors control attribute access via `__get__`, `__set__`, `__delete__`. `property`, `classmethod`, `staticmethod` are descriptors. They allow custom behavior for attribute access.

**P19** — Imports search `sys.path`. Relative imports use `.`; absolute use module names. `__init__.py` defines packages. Namespace packages allow imports without `__init__.py`. Finders locate modules; loaders load them.

**P20** — `dataclasses` (stdlib) generate boilerplate. `attrs` adds more features. `Pydantic` adds validation/serialization. `__post_init__` runs after init. Use Pydantic for complex validation; dataclasses for simple data structures.
