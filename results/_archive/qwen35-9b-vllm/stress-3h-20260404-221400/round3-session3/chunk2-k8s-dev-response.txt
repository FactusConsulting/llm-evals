K1 — Easy: What is the difference between a Deployment and a StatefulSet?
A Deployment manages stateless applications. Pods are interchangeable, have no stable identity, and updates happen in parallel. A StatefulSet manages stateful applications. Pods have stable, unique identities (hostname), are deployed in order, and support stable storage (PVCs) that persist across restarts.

K2 — Easy: How does a Kubernetes Service of type ClusterIP route traffic to pods?
The Service creates a virtual IP (ClusterIP) within the cluster. kube-proxy (running on nodes) creates iptables or IPVS rules to forward traffic from the Service IP to the Pod IPs listed in the Service's Endpoints object.

K3 — Medium: Explain the difference between a PersistentVolume, a PersistentVolumeClaim, and a StorageClass. How do they relate?
A PersistentVolume (PV) is a piece of storage provisioned by the admin (static or dynamic). A PersistentVolumeClaim (PVC) is a request for storage resources made by a user. A StorageClass defines the provisioner and parameters for dynamically creating PVs. Relationship: A StorageClass enables dynamic provisioning of PVs, which are then bound to PVCs.

K4 — Medium: A pod is stuck in CrashLoopBackOff. Describe your troubleshooting steps (at least 4 distinct checks).
1. Check container logs (`kubectl logs <pod>`) for application errors.
2. Check container health probes (liveness/readiness) to ensure they aren't failing.
3. Check resource limits (CPU/Memory) for OOMKilled or CPU throttling.
4. Check image pull errors or misconfigured environment variables/configmaps.

K5 — Medium: What is the role of CoreDNS in a Kubernetes cluster? What happens to DNS resolution if the CoreDNS pods are down?
CoreDNS provides the DNS service for the cluster, resolving service names, pod names, and external domains. If CoreDNS is down, internal service discovery fails (pods cannot reach each other by name), and external DNS resolution (e.g., accessing `google.com`) will fail or timeout.

K6 — Hard: Explain how the Kubernetes scheduler decides which node to place a pod on. Cover: filtering, scoring, and at least 3 specific factors it considers.
The scheduler first **filters** nodes based on hard constraints (taints/tolerations, resource availability, node affinity). It then **scores** the remaining nodes based on soft constraints. Factors include: Node affinity rules, available CPU/Memory resources, and Pod priority/preemption.

K7 — Hard: You have a pod with requests.memory: 256Mi and limits.memory: 512Mi. The node has 4GB RAM with 3.5GB already requested. Will the pod be scheduled? What happens if it actually uses 600Mi at runtime?
Yes, it will be scheduled. Available RAM = 4GB - 3.5GB = 0.5GB (512Mi). The pod requests 256Mi, which fits. However, if the runtime usage exceeds the limit (600Mi > 512Mi), the kubelet will OOMKill the container.

K8 — Hard: Explain the full lifecycle of a request hitting a Kubernetes Ingress backed by an NGINX ingress controller, all the way to the application pod. Include at least: external LB, ingress controller, Service, Endpoints, kube-proxy/iptables.
1. Request hits External Load Balancer.
2. LB routes to NGINX Ingress Controller Pod.
3. Ingress Controller matches rules and routes to the backend Service.
4. Service IP (ClusterIP) routes to Pod IPs via Endpoints.
5. kube-proxy on the node intercepts traffic via iptables rules and forwards it to the specific Pod IP.
6. Pod receives the request.

K9 — Medium: What is a NetworkPolicy? If no NetworkPolicy exists in a namespace, what is the default behavior? What happens when you apply one that selects certain pods?
A NetworkPolicy controls ingress/egress traffic to/from pods. By default, if no policy exists, all traffic is allowed. When a policy is applied, it restricts traffic to/from the selected pods (e.g., only allowing traffic from specific pods or namespaces).

K10 — Medium: Explain the difference between RollingUpdate and Recreate deployment strategies. When would you choose Recreate?
RollingUpdate updates pods gradually (zero downtime). Recreate stops all old pods before starting new ones (downtime). Choose Recreate for stateful applications (e.g., databases) where concurrent access is unsafe or for apps requiring exclusive resource access during updates.

K11 — Easy: What is a Kubernetes namespace, and what are the default namespaces created in a new cluster?
A namespace is a logical partition for resources (names, quotas). Default namespaces are: `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

K12 — Easy: What is `kubectl describe pod <name>` used for? Name at least 3 pieces of information it shows that `kubectl get pod` does not.
It provides detailed status and metadata. 3 examples: Events (recent pod events), Conditions (Ready, Running status), and Node name (which node the pod is running on).

K13 — Easy: What is a ConfigMap, and how can a pod consume it? Name at least two different methods.
A ConfigMap stores non-confidential configuration data as key-value pairs. Methods: 1. Mount as a volume (files in `/etc/...`). 2. Inject as environment variables.

K14 — Easy: What is the difference between a Service of type ClusterIP, NodePort, and LoadBalancer?
ClusterIP: Internal cluster access only. NodePort: Exposes a port on every node's IP. LoadBalancer: Provisions an external cloud load balancer to expose the service externally.

K15 — Easy: What is a DaemonSet, and when would you use one instead of a Deployment?
A DaemonSet ensures a copy of a pod runs on all (or a subset of) nodes. Use it for node-level tasks like logging agents (Fluentd), monitoring (Prometheus Node Exporter), or network plugins (Calico), rather than running arbitrary application workloads.

K16 — Medium: What are taints and tolerations? How do they differ from node affinity, and give a practical use case for each?
Taints push pods away from a node; tolerations allow specific pods to ignore taints. Node affinity pulls pods to specific nodes based on labels. Use case: Taints/Tolerations for GPU nodes (prevent general pods from running there). Node affinity for placing DBs on specific hardware.

K17 — Medium: Explain what a Kubernetes Operator is. How does it differ from a standard controller, and what problems does the Operator pattern solve?
An Operator is a custom controller that manages the lifecycle of a specific application type (e.g., MySQL, Kafka). Standard controllers manage generic resources (Pods, Deployments). Operators solve complex lifecycle problems (backups, upgrades, scaling) that standard controllers cannot handle.

K18 — Hard: Explain the etcd consistency model used by Kubernetes. What happens to the cluster if the etcd quorum is lost? How do you recover from a situation where 2 out of 3 etcd nodes are permanently lost?
etcd uses Raft consensus for strong consistency. If quorum is lost (e.g., 2/3 nodes down), the cluster becomes unavailable. Recovery from permanent loss of 2 nodes is impossible without a snapshot backup; you must restore etcd from a snapshot or rejoin a new node if the cluster was reconfigured.

K19 — Hard: Describe how Kubernetes RBAC works. Explain the relationship between Role, ClusterRole, RoleBinding, and ClusterRoleBinding. A developer needs read-only access to pods and logs in a single namespace — write the RBAC manifests.
Role/ClusterRole define permissions. RoleBinding/ClusterRoleBinding link permissions to users/groups.
Manifests:
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: default
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods
  namespace: default
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

K20 — Hard: You notice pod DNS resolution is slow (>5s) for external domains. Explain how ndots in /etc/resolv.conf inside a pod causes excessive DNS queries, and how you would fix it using dnsConfig in the pod spec.
`ndots` defines the minimum number of dots required to split a domain name. If set high (e.g., 5), a domain like `google.com` (1 dot) is treated as having 5 dots, causing the resolver to query 5 different names. Fix: Set `dnsConfig: { options: { ndots: 1 } }` in the pod spec.

D1 — Easy: What is the difference between git rebase and git merge? When should you avoid rebasing?
Rebase rewrites history to make it linear (commits moved). Merge preserves history with a merge commit. Avoid rebasing on public/shared branches or commits that others have based their work on, as it breaks history for others.

D2 — Easy: Explain the difference between TCP and UDP. Name 2 protocols that use each.
TCP is connection-oriented, reliable, and ordered (HTTP, SSH). UDP is connectionless, unreliable, and fast (DNS, RTP/Video).

D3 — Medium: What is a race condition? Give a concrete example in any language.
A race condition occurs when the outcome depends on the timing of concurrent events. Example: Two threads incrementing a shared counter `count++` without locks; the final value may be less than expected due to lost updates.

D4 — Medium: Explain the difference between symmetric and asymmetric encryption. How are both used together in TLS?
Symmetric uses one key for encryption/decryption (fast). Asymmetric uses public/private key pairs (slower). TLS uses asymmetric for the handshake (key exchange) and symmetric for the actual data transfer (session key).

D5 — Medium: What is a container image layer? How does layer caching affect Dockerfile best practices?
Layers are stacked read-only filesystems. Caching speeds up builds if layers don't change. Best practice: Combine `RUN` commands to reduce layers and place `COPY`/`ADD` instructions (changing files) at the end of the Dockerfile.

D6 — Medium: You have a REST API returning HTTP 503 intermittently. Describe at least 4 things you would check, and in what order.
1. Check application logs for errors.
2. Check the health check endpoint status.
3. Check load balancer health status (is the pod marked unhealthy?).
4. Check database connectivity (is the backend down?).

D7 — Hard: Explain the CAP theorem. Give a real-world example of a system that chooses CP over AP, and one that chooses AP over CP.
CAP states a system can only guarantee 2 of 3: Consistency, Availability, Partition Tolerance. CP example: ZooKeeper (prioritizes data consistency). AP example: DynamoDB (prioritizes availability during partition).

D8 — Medium: What is the difference between horizontal and vertical scaling? What architectural patterns enable horizontal scaling?
Horizontal adds more instances (stateless). Vertical adds more resources to existing instances (stateful). Horizontal scaling requires stateless architecture and a load balancer to distribute traffic.

D9 — Easy: What is an environment variable? How do you set one that persists across shell sessions on Linux?
An environment variable is a key-value pair available to processes. To persist across sessions, add it to `~/.bashrc` or `~/.profile` and run `source ~/.bashrc`.

D10 — Easy: What is JSON, and how does it differ from YAML? Name one advantage of each format.
JSON is a strict data interchange format (machine-readable). YAML is a human-readable data serialization format. JSON advantage: Strict validation. YAML advantage: Readability and indentation-based structure.

D11 — Easy: What is a REST API? Explain the difference between GET, POST, PUT, and DELETE HTTP methods.
REST is an architectural style using HTTP methods. GET retrieves data (idempotent). POST creates data (not idempotent). PUT replaces data (idempotent). DELETE removes data (idempotent).

D12 — Easy: What is version pinning in dependency management, and why is it important for reproducible builds?
Version pinning locks dependencies to specific versions (e.g., `==1.2.3`). It ensures builds are reproducible and prevents unexpected breaking changes from upstream updates.

D13 — Easy: What is the difference between a compiled language and an interpreted language? Give two examples of each.
Compiled languages translate code to machine code before execution (C++, Go). Interpreted languages execute code line-by-line at runtime (Python, Ruby).

D14 — Medium: Explain what a reverse proxy is and how it differs from a forward proxy. Name two common reverse proxy servers and a use case for each.
Reverse proxy sits in front of servers (client -> proxy -> server). Forward proxy sits in front of clients (client -> proxy -> internet). Reverse: Nginx (SSL termination). Forward: Squid (Corporate internet access).

D15 — Medium: What is a deadlock? What four conditions (Coffman conditions) must hold simultaneously for a deadlock to occur?
A deadlock is when threads wait for each other indefinitely. Conditions: Mutual Exclusion, Hold and Wait, No Preemption, Circular Wait.

D16 — Hard: Explain the concept of eventual consistency. How do distributed databases like Cassandra handle read-after-write consistency, and what tunable consistency levels exist?
Eventual consistency means data converges over time without immediate synchronization. Cassandra allows tunable consistency levels: ONE (1 replica), QUORUM (majority), ALL (all replicas).

D17 — Hard: What is mTLS (mutual TLS)? Explain the full handshake process, including how both client and server authenticate each other. Where is mTLS commonly used in infrastructure?
mTLS requires both client and server to present certificates. Handshake: Client sends cert -> Server verifies -> Server sends cert -> Client verifies. Used in Service Meshes (Istio) and secure microservice communication.

D18 — Hard: Explain how a hash table works internally, including collision resolution strategies (chaining vs. open addressing). What is the time complexity for insertion, lookup, and deletion in average and worst cases?
Hash table uses an array and hash function. Chaining uses linked lists at indices; Open Addressing stores collisions in the array. Average: O(1). Worst: O(n) (all collisions).

D19 — Hard: What is a circuit breaker pattern in microservices? Explain its three states (closed, open, half-open) and how it prevents cascade failures. How does it relate to retry policies and exponential backoff?
Circuit breaker stops calls to a failing service. Closed (normal), Open (fail fast), Half-Open (test recovery). Prevents cascade by stopping traffic. Retries use exponential backoff to avoid overwhelming the service during recovery.

D20 — Hard: Explain the difference between optimistic and pessimistic concurrency control in databases. When would you choose each? Give a concrete example using database features (e.g., row versioning, SELECT FOR UPDATE).
Optimistic checks for conflicts at commit time (CAS). Pessimistic locks rows immediately. Choose Optimistic for low contention (web apps). Choose Pessimistic for high contention (banking). Example: Optimistic uses `version` column; Pessimistic uses `SELECT ... FOR UPDATE`.
