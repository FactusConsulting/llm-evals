## Networking (20 questions)

**N1**
A Layer 2 switch forwards frames based on MAC addresses using a CAM table. A Layer 3 switch performs routing based on IP addresses using a routing table, allowing inter-VLAN communication without a separate router.

**N2**
Network Address: 10.0.4.0. Broadcast Address: 10.0.15.255.
*Calculation:* /20 mask (255.255.240.0) affects the third octet. 10.0.5.37 falls in the 10.0.4.0/20 block (range 10.0.4.0–10.0.15.255).

**N3**
The handshake is: 1. Client sends SYN. 2. Server sends SYN-ACK. 3. Client sends ACK. If the final ACK is lost, the server retransmits the SYN-ACK. The client will eventually timeout and retransmit SYN, eventually causing the connection to fail or reset.

**N4**
SNAT (Source NAT) changes the source IP of outgoing packets (e.g., internal server accessing the internet). DNAT (Destination NAT) changes the destination IP of incoming packets (e.g., external user accessing an internal web server).
*Example:* SNAT: `iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE`. DNAT: `iptables -t nat -A PREROUTING -d 10.0.0.5 -j DNAT --to-destination 192.168.1.5`.

**N5**
1. The certificate is self-signed or not trusted by the client.
2. The certificate's Common Name (CN) or Subject Alternative Name (SAN) does not match `example.com`.
3. The client is connecting via IP address instead of the hostname, and the cert lacks a SAN for that IP.

**N6**
VLANs are Layer 2 segmentation on physical switches using 802.1Q tags. VxLANs are Layer 2 over Layer 3 tunneling using UDP encapsulation. Choose VxLAN for overlay networks, multi-tenant cloud environments, or when spanning across different physical subnets where VLANs are limited.

**N7**
Traffic arrives on eth1 but returns via eth0 because the routing table has a default route via eth0, and the return traffic matches that default.
*Fix:* Create a policy routing table (e.g., table 100). Add a rule: `ip rule add from 192.168.1.0/24 table 100`. Add a route: `ip route add 192.168.1.0/24 dev eth1 table 100`.

**N8**
BGP path selection order:
1. Weight (Cisco proprietary, local).
2. Local Preference (global within AS).
3. Locally originated routes.
4. AS Path length (shorter is better).
5. Origin type (IGP < EGP < Incomplete).
6. MED (Multi Exit Discriminator).
7. eBGP vs iBGP.
8. IGP metric to next hop.

**N9**
VxLAN adds ~50 bytes overhead (8-byte VxLAN header + 8-byte UDP + 20-byte IP). IPsec adds ~40 bytes (ESP header + payload). Total overhead ~90 bytes.
*Max Inner Payload:* 1500 - 90 = 1410 bytes.
*Note:* Exact overhead depends on IPsec mode (Transport vs Tunnel) and headers.

**N10**
ARP resolves IPv4 addresses to MAC addresses. Gratuitous ARP is sent by a host to announce its IP/MAC mapping to the network, used for IP conflict detection or when a host changes its MAC address.

**N11**
Public IPs are globally routable. Private IPs are reserved for internal use. RFC 1918 ranges:
1. 10.0.0.0/8
2. 172.16.0.0/12
3. 192.168.0.0/16

**N12**
DNS resolves hostnames to IPs.
*   **A Record:** Maps hostname to IPv4 address.
*   **CNAME Record:** Maps one hostname to another (alias).
*   **AAAA Record:** Maps hostname to IPv6 address.

**N13**
DHCP assigns IP addresses dynamically. DORA process:
1.  **Discover:** Client broadcasts DHCP Discover.
2.  **Offer:** Server broadcasts DHCP Offer.
3.  **Request:** Client broadcasts DHCP Request.
4.  **Acknowledge:** Server sends DHCP Ack.

**N14**
*   **Hub:** Layer 1. Broadcasts all traffic to all ports.
*   **Switch:** Layer 2. Forwards frames based on MAC addresses.
*   **Router:** Layer 3. Routes packets between networks based on IP addresses.

**N15**
Half-duplex allows transmission in only one direction at a time (collision domain). Full-duplex allows simultaneous transmission and reception. Modern Ethernet links use full-duplex.

**N16**
TTL (Time To Live) limits the number of hops a packet can traverse. Traceroute exploits this by sending packets with incrementing TTL values; each router decrements TTL and sends an ICMP Time Exceeded message when TTL reaches 0, revealing the path.

**N17**
A NAT Gateway translates IP addresses between networks.
*   **Static NAT:** One-to-one fixed mapping (internal IP <-> external IP).
*   **Dynamic NAT:** Many-to-many mapping from a pool of external IPs.
*   **PAT (Port Address Translation):** Many-to-one mapping using unique port numbers (common in home routers).

**N18**
ECMP routes traffic across multiple equal-cost paths using hash functions (typically based on source/destination IP and ports).
*Problem:* Asymmetric flows occur if packets of the same flow take different paths. Stateful firewalls may drop return traffic if the state was established on a different path than the return path.

**N19**
The Bandwidth-Delay Product (BDP) is 10MB. The TCP window is capped at 64KB. Since 64KB < 10MB, the sender cannot fill the pipe, limiting throughput.
*Solution:* TCP Window Scaling (RFC 1323) allows the window size to exceed 64KB (up to 1GB) by scaling the window value, enabling the sender to utilize the full BDP.

**N20**
802.1Q inserts a 4-byte VLAN tag into the Ethernet frame.
*Linux Config:* `ip link add link eth0 name eth0.10 type vlan id 10`.
*Frame Format:* Standard Ethernet Header (14 bytes) + VLAN Tag (4 bytes) + Payload + FCS (4 bytes). The EtherType changes from 0x0800 to 0x8100.

## Linux (20 questions)

**L1**
A hard link points directly to the inode (data is shared). A symbolic link is a separate file containing a path to the target. Hard links cannot span filesystems; symlinks can. Deleting the original file does not affect hard links, but breaks symlinks.

**L2**
`find /var/log -type f -size +100M`

**L3**
State D (Uninterruptible Sleep) means the process is waiting for I/O (e.g., disk access). It cannot be killed with `kill -9` (SIGKILL) because the kernel ignores the signal while waiting for I/O.

**L4**
Cgroups v1 uses separate hierarchies for resources (cpu, memory, etc.). Cgroups v2 uses a unified hierarchy. Systemd prefers v2 for simplicity and unified control.

**L5**
iptables is the legacy netfilter interface. nftables is the new, unified, and faster interface. The kernel handles both by translating iptables rules into nftables rules internally (iptables is a frontend to nftables).

**L6**
The most likely cause is that files were deleted but still open by a process (file descriptors). `df` counts inodes, while `du` counts disk usage of closed files.

**L7**
UEFI Firmware -> Bootloader (GRUB) -> Kernel (bzImage) -> Initramfs (provides drivers) -> Root Filesystem Mount -> systemd (PID 1) -> Target (multi-user).

**L8**
"Available" memory is Total - Used - Buff/Cache. High buffer/cache reduces "Available". OOM fires if available memory is insufficient for new allocations. Tunables: `vm.min_free_kbytes` (keeps a reserve), `vm.swappiness` (controls swap usage).

**L9**
`ip netns` creates/manages network namespaces. Container runtimes (Docker/Podman) use namespaces to isolate network stacks (interfaces, routes, DNS) from the host and other containers.

**L10**
*   **SIGTERM (15):** Graceful termination; process can catch and clean up.
*   **SIGKILL (9):** Immediate termination; cannot be caught or ignored.
*   **SIGQUIT (3):** Graceful termination with debugging info; can be caught.

**L11**
stdout (1), stderr (2), stdin (0).
*Redirect stderr to file, stdout to terminal:* `command > file 2>&1` (redirects stdout to file, then redirects stderr to stdout's destination). Or `command 2> file`.

**L12**
`chmod 755`:
*   **7 (Owner):** rwx (Read, Write, Execute).
*   **5 (Group):** r-x (Read, Execute).
*   **5 (Others):** r-x (Read, Execute).

**L13**
Root (UID 0) has unrestricted access. Sudo users have elevated privileges for specific commands but require authentication (password) and are subject to sudoers restrictions.

**L14**
A package manager automates software installation, updates, and removal.
*   Debian/Ubuntu: `apt` (high-level) / `dpkg` (low-level).
*   RHEL/Fedora: `dnf` (high-level) / `rpm` (low-level).

**L15**
`/etc/fstab` defines filesystem mount points. Misconfiguration (e.g., wrong UUID or mount options) prevents the system from booting or mounting the filesystem, potentially requiring a rescue environment.

**L16**
LVM manages storage as logical volumes.
*   **PV:** Physical disk partition.
*   **VG:** Pool of PVs.
*   **LV:** Volume created from VG.
*   *Extend:* `lvextend -L +10G /dev/vg/lv` followed by `resize2fs /dev/vg/lv` (for ext4).

**L17**
I/O schedulers order requests for latency/throughput.
*   **mq-deadline:** Good for SSDs (latency).
*   **bfq:** Good for HDDs (fairness).
*   **none:** No scheduling (good for NVMe).
*   *Change:* `echo mq-deadline > /sys/block/sda/queue/scheduler`.

**L18**
Load average measures runnable + wait processes. I/O wait inflates load because processes wait for disk.
*Diagnosis:* Use `top` (check %wa), `iostat -x 1` (check util%), `netstat` (check network). If %wa is high, bottleneck is disk.

**L19**
SELinux enforces Mandatory Access Control (MAC) via policies.
*   **Enforcing:** Blocks violations.
*   **Permissive:** Logs violations but allows.
*   **Disabled:** No enforcement.
*   *Troubleshoot:* Check `/var/log/audit/audit.log`. Use `audit2allow` to generate a policy or `setsebool -P httpd_can_network_connect 1` for specific booleans.

**L20**
Page faults occur when accessing memory not in RAM.
*   **Minor:** Page is in swap; kernel swaps it back in.
*   **Major:** Page is not in memory; kernel reads from disk (slow).
*   **THP:** Transparent Huge Pages reduce TLB misses but can cause fragmentation and stall. Disable if latency is critical (`echo never > /sys/kernel/mm/transparent_hugepage/enabled`).
