## .NET / C# (20 questions)

**DN1**
Classes are reference types (allocated on the heap); structs are value types (allocated on the stack). Structs are copied by value, classes by reference. Use structs for small, immutable data (e.g., coordinates, colors) to avoid heap allocation overhead and enable value semantics. Do not use structs for large data or if you need polymorphism/virtual methods.

**DN2**
`IEnumerable<T>` executes queries in memory (LINQ to Objects). `IQueryable<T>` builds an expression tree that translates to SQL (LINQ to DB). This distinction matters because `IEnumerable` cannot be translated to SQL, while `IQueryable` allows the database provider to optimize the query.

**DN3**
`async/await` uses a state machine to suspend execution without blocking a thread. `Task` is a reference type wrapper for an operation. `ValueTask` is a union of `Task` and a result, avoiding allocation if the operation completes synchronously. Use `ValueTask` for CPU-bound operations or when the caller expects a result immediately without the overhead of a `Task` object.

**DN4**
Dependency Injection (DI) allows injecting dependencies rather than creating them. Lifetimes: **Transient** (new instance per request), **Scoped** (new instance per request scope, e.g., HTTP request), **Singleton** (one instance per application lifetime). **Common Bug:** Injecting a Scoped service into a Singleton. The Scoped service is never disposed when the request ends, causing memory leaks and `ObjectDisposedException`.

**DN5**
`string` is immutable and heap-allocated. `ReadOnlySpan<char>` is a view over memory (stack or heap) without copying. Use `Span<T>` for zero-copy processing of buffers (e.g., parsing binary data) to improve performance and reduce GC pressure.

**DN6**
The GC manages memory in generations: **Gen 0** (short-lived), **Gen 1** (medium), **Gen 2** (long-lived). Objects are promoted upon collection. The **Large Object Heap (LOH)** stores objects >85KB. `IDisposable` is needed for unmanaged resources (files, DB connections) because the GC does not know when to release them; `Dispose` ensures deterministic cleanup.

**DN7**
Default `await` captures the `SynchronizationContext` (e.g., UI thread) to resume. `ConfigureAwait(false)` suppresses this. Use `ConfigureAwait(false)` in library code to avoid deadlocks on UI threads. Do **not** use it in UI code if you need to update the UI, as it will deadlock.

**DN8**
**Primary Constructors:** Class parameters defined in the class declaration (C# 12). **Collection Expressions:** `new List<int>{1, 2}`. **FrozenDictionary:** Immutable dictionary.
*Example:*
```csharp
public class MyService(string name) : IService { /* ... */ }
// In Program.cs
builder.Services.AddMyService(); // Registers the class
```

**DN9**
**Cause:** `DbContext` is typically Scoped. If a Singleton service holds a reference to a Scoped `DbContext`, the `DbContext` is never disposed when the request ends. High concurrency triggers the disposal of the `DbContext` while the Singleton is still using it.
**Fix:** Ensure `DbContext` is Scoped and never injected into a Singleton. Use `Scoped` lifetime for `DbContext`.

**DN10**
**Record:** Immutable reference type with value-based equality. **Class:** Mutable, reference-based equality. **Record Struct:** Immutable value type with value-based equality. Use records for DTOs/Entities (immutability + equality). Use classes for mutable state. Use record structs for small value objects.

**DN11**
`ref`: Read/write reference. `out`: Write-only reference (must be assigned before return). `in`: Read-only reference (C# 7.2+). Use `in` for large structs passed to methods to prevent copying and ensure the method cannot modify the caller's data.

**DN12**
`?` on reference types (e.g., `string?`) enables nullable reference types (compile-time warnings). `int?` is a nullable value type (struct) representing `int` or `null`. Nullable reference types are a compile-time feature; nullable value types are runtime types.

**DN13**
LINQ is Language Integrated Query. Method syntax (`list.Where(...)`) and query syntax (`from x in list where ...`) are syntactic sugar for the same underlying methods. **Deferred execution:** Queries are not executed until the result is enumerated (e.g., `ToList()`).

**DN14**
Constraints limit generic types. `class`: Reference type. `struct`: Value type. `new()`: Parameterless constructor exists. `IComparable<T>`: Implements interface. Combine constraints (e.g., `where T : class, new()`) to enforce multiple rules simultaneously.

**DN15**
**Abstract Class:** Can have state, constructors, and partial implementation. **Interface:** Contract only (pre C# 8). C# 8+ interfaces can have default method implementations. Use abstract classes for shared implementation/state; interfaces for contracts/abstractions.

**DN16**
Middleware pipeline processes requests sequentially. `app.Use()` adds middleware to the pipeline. `app.Map()` creates a sub-tree (branching). `app.Run()` executes immediately and stops the pipeline. Order matters: Authentication early, Logging late. Exception middleware wraps errors in `HttpContext` and handles them.

**DN17**
`Channel<T>` is a bounded/unbounded queue with backpressure. `BlockingCollection<T>` is unbounded and does not support backpressure. Use `Channel.CreateBounded(10)` for producer-consumer scenarios where the producer should pause if the buffer is full.

**DN18**
**Source Generators:** Compile-time code generation. Faster than reflection. **Incremental:** Only regenerates code for changed files (preferred for large projects). **ISourceGenerator:** Generates code for all projects (slower). Incremental is preferred for performance.

**DN19**
**TPL Dataflow:** High-level pipeline. `ActionBlock` (sink), `TransformBlock` (process), `BufferBlock` (buffer). **Comparison:** Dataflow is higher-level (blocks handle buffering/flow control); `Channels` are lower-level primitives requiring manual flow control.

**DN20**
**Minimal APIs:** `app.MapGet` syntax. No controllers. **Trade-offs:** Less boilerplate, but harder to test (no controller base classes), less OpenAPI support out-of-box (needs `AddOpenApi`), middleware configuration is manual. Route groups organize endpoints; endpoint filters add logic to specific endpoints.

## Python (20 questions)

**P1**
**List:** Mutable, ordered, allows duplicates. **Tuple:** Immutable, ordered, allows duplicates. **Set:** Mutable, unordered, no duplicates. **Frozenset:** Immutable, unordered, no duplicates.

**P2**
**GIL:** Locks bytecode execution to one thread per process. Affects CPU-bound multi-threading (no speedup). Workarounds: Multiprocessing (separate processes), C-extensions (release GIL), or async I/O (non-blocking).

**P3**
`copy`: Shallow copy (container copied, contents referenced). `deepcopy`: Deep copy (container and contents copied). **Example:** `a = [[1]]; b = copy(a); b[0].append(2);` results in `a` also changing to `[[1, 2]]`.

**P4**
Decorators wrap functions.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start:.2f}s")
        return result
    return wrapper
```

**P5**
Generators use `yield` to return values and pause execution. They are lazy (memory efficient). `yield from` delegates to another iterable. `return` stops execution immediately.

**P6**
Event loop manages async tasks. `asyncio.run()` starts the loop. `asyncio.gather()` waits for all tasks. `asyncio.create_task()` schedules a task. `time.sleep()` blocks the loop; use `await asyncio.sleep()` instead.

**P7**
**MRO:** C3 Linearization. Order: D -> B -> C -> A. `who` is defined in C. `D().who()` returns "C".
*Explanation:* Python searches the MRO list. B does not override `who`, so it falls through to C.

**P8**
**Metaclass:** Class of a class. **`__init_subclass__`:** Hook called when a subclass is defined (Python 3.6+). **Use Case:** Metaclass for global control (e.g., ORM base classes); `__init_subclass__` for specific class logic (e.g., adding attributes to subclasses).

**P9**
**Threading:** Shared memory, GIL limited. **Multiprocessing:** Separate memory, no GIL. **concurrent.futures:** Abstraction layer. **Serialization:** Multiprocessing requires pickling (objects must be serializable).

**P10**
`__slots__`: Prevents `__dict__` creation. Saves memory (no per-instance dict). Prevents dynamic attribute assignment. Use for memory-critical classes.

**P11**
**Virtual Environment:** Isolated Python environment. `venv`: Standard library. `virtualenv`: 3rd party (more features). `conda`: Environment + package manager (binary dependencies).

**P12**
Comprehensions: `[x for x in list]`. Syntax sugar for `map`/`filter`. Prefer for readability; use `map`/`filter` for simple transformations.

**P13**
`==`: Value equality. `is`: Identity (same object). **Interning:** Small integers (e.g., -5 to 256) are cached. `a is b` returns True for these values even if created separately.

**P14**
`*args`: Positional varargs. `**kwargs`: Keyword varargs. `/` marks positional-only parameters. `*` marks keyword-only parameters.

**P15**
Context managers manage resources. `with` statement. `__enter__/__exit__` (class-based) or `@contextmanager` (generator-based). **Example:** `with open(...)` or custom `with` for database connections.

**P16**
Type hinting for static analysis. `Union`: Multiple types. `Optional`: `Union[T, None]`. `Literal`: Specific values. `TypeVar`: Generic types. `Protocol`: Structural typing (duck typing). Used by `mypy`/`pyright`.

**P17**
`__repr__`: Developer representation. `__str__`: User representation. `__eq__`: Equality. `__hash__`: Hash for dict/set keys. Defining `__eq__` without `__hash__` sets `__hash__` to `None` (unhashable).

**P18**
**Descriptors:** Protocol for attribute access (`__get__`, `__set__`, `__delete__`). `property`, `classmethod`, `staticmethod` use descriptors to manage access logic.

**P19**
**Import System:** `sys.path` determines search order. Relative (`.`) vs Absolute (`module`). `__init__.py` makes a package. Namespace packages (no `__init__.py`). **Finder/Loader:** Finder locates module, Loader executes it.

**P20**
**Dataclasses:** Auto-generate `__init__`, `__repr__`, etc. `__post_init__` for logic. `Pydantic` adds validation/serialization. **Inheritance:** Dataclasses support it. **Choice:** Use Pydantic for validation/APIs; Dataclasses for internal data structures.
