G1 — Easy: Arrays are fixed-size value types; slices are dynamic views into arrays (array + offset + length). Arrays are copied on assignment; slices are references. When a slice reaches capacity, `append` allocates a new underlying array (typically 1.25x or 2x growth) and copies the data, then extends the slice.

G2 — Easy: `var x int` declares `x` with a zero value (0) but does not initialize it in the statement. `x := 0` declares and initializes `x` to 0. You cannot use `:=` if `x` is already declared in the current scope (e.g., `var x int; x := 1` is invalid).

G3 — Medium: A goroutine is a lightweight user-space thread managed by the Go runtime. OS threads are kernel-managed and heavier. The GMP model consists of G (goroutine), M (machine/OS thread), and P (processor). The scheduler multiplexes Gs onto Ps, allowing thousands of goroutines to run on fewer OS threads.

G4 — Medium: Channels allow goroutines to communicate. Unbuffered channels block send until a receive is ready. Buffered channels hold up to N items. Sending to a full buffered channel blocks until a receiver consumes an item.

G5 — Medium: The `context` package manages request-scoped values (cancellation, deadlines, values).
```go
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
resp, err := http.Get("https://example.com", &http.Client{Timeout: 0}) // Use ctx in request
```
Ideally: `http.Get(ctx, ...)` to pass the context.

G6 — Medium: Go interfaces are implicit (duck typing); Java/C# require explicit implementation. `interface{}` (or `any`) holds any type, enabling generic-like behavior or JSON marshaling, but it loses type safety and requires type assertions.

G7 — Hard: This is unsafe due to data races and reordering. `ready` and `data` are not atomic/synchronized. The compiler may reorder writes, and the loop spins without yielding. Correct alternatives: use `sync.WaitGroup`, channels, or atomic operations (`sync/atomic`).

G8 — Hard: `sync.Mutex` blocks all readers; `sync.RWMutex` allows concurrent reads. `sync.Map` is optimized for high read concurrency (sharded hash map) but has slower writes. Regular map + mutex is slower for reads but consistent for writes.

G9 — Hard: `go.mod` defines module path and dependencies. `go.sum` stores checksums for security verification. `go mod tidy` removes unused dependencies and updates versions. MVS (Minimum Version Selection) picks the lowest version satisfying all constraints.

G10 — Medium: `defer` executes after the function returns (or panics), in LIFO order. Gotcha: Loop variables are captured by reference, not value.
```go
for i := 0; i < 3; i++ {
    defer func() { fmt.Println(i) }()
}
// Prints 3, 3, 3
```

G11 — Easy: A pointer holds the memory address of a variable. The zero value is `nil`. Create a pointer to a struct literal with `&Struct{}`.

G12 — Easy: `init()` runs before `main`. A package can have multiple `init()` functions (e.g., `init()` and `init2()`). They execute in declaration order.

G13 — Easy: `make` allocates slices, maps, and channels (initializing underlying storage). `new` allocates a zeroed value on the heap and returns a pointer. `make` works for slices/maps/channels; `new` works for any type.

G14 — Easy: Errors are values implementing the `error` interface (`Error() string`). Idiomatic check: `if err != nil`. `errors.Is` checks for wrapped errors (e.g., `errors.Is(err, target)`). `errors.As` type-asserts to a specific error type.

G15 — Easy: Map (key/value pairs), Slice (dynamic array view), Channel (send/receive), Struct (named fields). Zero values: map(nil), slice(nil), channel(nil), struct(all fields zero).

G16 — Medium: A race condition is concurrent access to shared data without synchronization. The `-race` flag uses ThreadSanitizer to detect unsynchronized access. Fix: Protect with `sync.Mutex` or use channels for communication.

G17 — Medium: `select` multiplexes channel operations like a switch. If multiple cases are ready, one is chosen non-deterministically. Use `time.After` in a `select` case to implement timeouts.

G18 — Hard: Escape analysis determines if a variable escapes the stack frame (heap allocation). The compiler checks if pointers to local variables are returned or stored. Inspect with `-gcflags="-m"`. It matters for performance (heap allocation is slower and triggers GC).

G19 — Hard: `reflect.Type` describes a type; `reflect.Value` holds the data. Reflection is slow (dynamic dispatch). Justified for generic config or dynamic code; code generation (e.g., `go generate`) is preferred for performance-critical paths.

G20 — Hard: `//go:embed` embeds files at compile time. Supports files, directories, and `io/fs.FS`. Limitations: files must be in the same package, no symlinks, and the path must be relative to the package root.

R1 — Easy: Ownership means one owner is responsible for memory. Rules: 1. Each value has one owner. 2. Move on copy. 3. When owner goes out of scope, memory is freed.

R2 — Easy: `String` is an owned heap string. `&str` is a borrowed string slice. Use `String` when returning ownership or modifying. Use `&str` for function arguments to avoid copying.

R3 — Medium: Borrowing allows access without ownership. Immutable `&T` can be shared; mutable `&mut T` is exclusive. Rules: No aliasing (cannot have `&mut` and `&` to same data simultaneously).

R4 — Medium: `Result<T, E>` handles errors; `Option<T>` handles null. `?` propagates errors.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)?
}
```

R5 — Medium: `Box<T>` is a heap pointer (single owner). `Rc<T>` is a thread-local reference count. `Arc<T>` is a thread-safe reference count. Use `Box` for ownership transfer, `Rc` for single-threaded sharing, `Arc` for multi-threaded sharing.

R6 — Medium: Traits define behavior. Go interfaces are implicit; Rust traits are explicit. `dyn Trait` (trait objects) allow heterogeneous collections. Generic `T: Trait` allows homogeneous collections with compile-time dispatch.

R7 — Hard: Fails because the compiler cannot guarantee `x` or `y` lives long enough to return the reference. Fix: Add lifetime annotation.
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — Hard: `Send` means transferable across threads; `Sync` means safe to share. `Rc<T>` is not `Send` because ref counts are not atomic. `Arc<T>` uses atomic ref counts, making it `Send` and `Sync`.

R9 — Hard: Rust async uses `Future` trait (polling). An executor (e.g., Tokio) drives futures. Go uses M:N scheduling (kernel threads mapped to goroutines). Rust is cooperative (polling), Go is preemptive (scheduler).

R10 — Medium: `unsafe` blocks allow: 1. Pointer arithmetic. 2. Raw pointers (`*const T`). 3. FFI (calling C). Justified for FFI or performance-critical code where safety is known.

R11 — Easy: `match` is exhaustive (must cover all cases). `if let` is partial. The compiler enforces exhaustiveness for `match` (unless `..` is used).

R12 — Easy: `Vec<T>` is dynamic heap storage. `[T; N]` is fixed size (stack or heap). `Vec` reallocates and copies elements when capacity is exceeded.

R13 — Easy: Enums are algebraic data types (variants + data). Rust enums are exhaustive (no null). `Option<T>` is `Some(T)` or `None`.

R14 — Easy: `impl` defines methods. `&self` borrows immutably; `&mut self` borrows mutably; `self` takes ownership. Associated functions (static methods) take `Self` (e.g., `String::new()`).

R15 — Easy: `derive` generates code for traits. Common: `Debug`, `Clone`, `PartialEq`, `Serialize`. Cannot derive if the struct contains fields that do not implement the trait (e.g., `Clone` on a struct with a non-cloneable field).

R16 — Medium: `Cow<'a, T>` (Clone on Write) borrows if immutable, clones if mutable. Useful for string processing to avoid allocation when data is already owned.
```rust
let s = Cow::Borrowed("hello");
let mut s = s;
s.to_mut(); // Forces clone if mutation needed
```

R17 — Medium: `mod` defines a module; `use` imports; `pub` makes public. 2015: `mod foo` in `foo.rs`. 2018: `mod foo` in `foo/mod.rs` or `foo.rs` inside `foo/` directory.

R18 — Hard: `Pin<T>` prevents a value from being moved. Needed for async types (self-referential structs). `Unpin` removes the restriction. Without `Pin`, async tasks might invalidate internal pointers.

R19 — Hard: `macro_rules!` is declarative (textual matching). Procedural macros (derive, attribute, function) parse Rust AST. Hygiene rules prevent macro names from leaking into outer scope.

R20 — Hard: Zero-cost abstractions mean no runtime overhead. Generics use monomorphization (compile-time specialization). Trait static dispatch uses vtables (no dynamic dispatch overhead). Iterators are state machines on the stack.
