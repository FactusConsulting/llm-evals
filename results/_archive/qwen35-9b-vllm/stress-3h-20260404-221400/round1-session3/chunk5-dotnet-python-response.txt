## .NET / C# (20 questions)

**DN1**
Classes are reference types (allocated on heap, support inheritance/virtual methods). Structs are value types (allocated on stack, no virtual methods, no inheritance). Use structs for small, immutable data (POD-like) to avoid heap allocation overhead and boxing.

**DN2**
`IEnumerable<T>` executes queries in memory (LINQ to Objects). `IQueryable<T>` builds expression trees translated to SQL (LINQ to DB). This distinction matters because `IEnumerable` cannot be translated to SQL, causing performance issues when querying databases.

**DN3**
`async/await` uses a state machine to yield control back to the thread pool. `Task` is a reference type wrapper for an operation. `ValueTask` is a union of `Task` and a result, avoiding allocation for synchronous operations. Use `ValueTask` for CPU-bound methods or when you know the result is available immediately to reduce GC pressure.

**DN4**
Dependency Injection (DI) allows injecting dependencies rather than creating them. Lifetimes: `Transient` (new instance per request), `Scoped` (new instance per request scope, e.g., HTTP request), `Singleton` (one instance per app lifetime). **Bug:** Injecting a `Scoped` service into a `Singleton` causes the Scoped service to outlive its scope, leading to memory leaks or stale data (e.g., disposed DbContext).

**DN5**
`string` is immutable and boxed. `ReadOnlySpan<char>` is a view into memory without copying. Use `Span<T>` (or `ReadOnlySpan`) for high-performance processing of large buffers (e.g., parsing binary data) to avoid allocations and copying.

**DN6**
GC uses generations: Gen 0 (short-lived), Gen 1 (medium), Gen 2 (long-lived). Objects age up generations. Large Object Heap (LOH) stores objects >85KB. `IDisposable` is needed for unmanaged resources (files, DB connections) because the GC cannot track them; it relies on the developer to call `Dispose`.

**DN7**
`ConfigureAwait(false)` tells the awaiter not to capture the `SynchronizationContext`. Use it in library code to prevent deadlocks in UI apps (where the context is the UI thread). Do NOT use it in UI code (WinForms/WPF/Blazor) where you need to resume on the UI thread.

**DN8**
Primary constructors allow parameters in the class declaration. Collection expressions create collections inline. `FrozenDictionary` is an immutable dictionary.
*Example:*
```csharp
class Service(int id, string name) { /* ... */ }
// DI usage:
builder.Services.AddTransient<IService, Service>();
// Or using primary constructor in a factory:
class ServiceFactory { public Service Create(int id, string name) => new(id, name); }
```

**DN9**
**Cause:** A `Scoped` `DbContext` is injected into a `Singleton` service. The Singleton persists, but the DbContext is disposed at the end of the request, causing `ObjectDisposedException` on subsequent requests.
**Fix:** Ensure `DbContext` is registered as `Scoped` and never injected into a `Singleton`. Use `DbContextFactory` or `AddDbContext` with `Lifetime.Scoped` explicitly.

**DN10**
`record` is immutable, value-based equality, and auto-generates `Equals`/`GetHashCode`. `class` is mutable, reference-based equality. `record struct` is an immutable value type. Choose `record` for DTOs/Entities, `record struct` for small immutable values (e.g., coordinates).

**DN11**
`ref`: read/write reference. `out`: write-only (caller receives value). `in`: read-only reference (C# 7.2+). Use `in` for large structs to prevent accidental modification and improve performance.

**DN12**
`?` on reference types (e.g., `string?`) enables nullable reference type analysis (compile-time warnings). `int?` is a nullable value type (struct), which is always boxed and has a default value of `null`.

**DN13**
LINQ is Language Integrated Query. Method syntax (`list.Where(...)`) is verbose but explicit. Query syntax (`from x in list where ...`) is declarative. Deferred execution means the query isn't run until the result is enumerated (e.g., `ToList()`).

**DN14**
Constraints limit generic types. `class`: reference type. `struct`: value type. `new()`: parameterless constructor exists. `IComparable<T>`: implements interface. Combine constraints (e.g., `where T : class, new()`) to enforce multiple rules simultaneously.

**DN15**
Abstract classes can have state and single inheritance. Interfaces define contracts (multiple inheritance). C# 8+ default interface methods allow interfaces to have implementation, blurring the line, but abstract classes still allow state and constructors.

**DN16**
Middleware pipeline processes requests sequentially. `app.Use()` adds middleware to the pipeline. `app.Map()` branches the pipeline (e.g., for sub-apps). `app.Run()` executes immediately. Order matters (top-down). Exception middleware wraps the pipeline to catch errors and return 500 responses.

**DN17**
`Channel<T>` is a bounded/unbounded queue with backpressure support. `BlockingCollection<T>` is unbounded and lacks backpressure. Use `Channel<T>` (bounded) for producer-consumer scenarios where you need to prevent memory overflow when consumers are slow.

**DN18**
Source Generators compile code at build time. They differ from reflection (runtime) and IL weaving (post-build). Incremental generators only re-run when source changes, making them faster than `ISourceGenerator` (which runs every build). Preferred for performance in large solutions.

**DN19**
TPL Dataflow provides high-level pipeline components. `ActionBlock` (sink), `TransformBlock` (process), `BufferBlock` (buffer). Compared to `Channels`, Dataflow is higher-level (handles buffering/errors automatically) but less flexible for custom logic.

**DN20**
Minimal APIs are lightweight endpoints defined via `app.MapGet/Post`. They differ from Controllers (no classes, less boilerplate). Trade-offs: Easier to write, harder to test (less DI wiring), requires manual OpenAPI configuration. Route groups (`app.MapGroup`) organize endpoints. Endpoint filters allow cross-cutting concerns.

## Python (20 questions)

**P1**
Lists are mutable sequences. Tuples are immutable sequences. Sets are mutable unordered collections. FrozenSets are immutable sets. Use tuples for fixed data, lists for dynamic data.

**P2**
The GIL prevents multiple threads from executing Python bytecode simultaneously on one CPU core. It affects CPU-bound workloads. Workarounds: Multiprocessing (bypasses GIL), C-extensions (NumPy), or Async I/O (for I/O-bound tasks).

**P3**
`copy` creates a shallow copy (nested objects are references). `deepcopy` creates a deep copy (nested objects are duplicated). Shallow copy fails if nested mutable objects are modified (e.g., `d['nested'].append(1)` affects both copies).

**P4**
Decorators wrap functions.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start:.2f}s")
        return result
    return wrapper
```

**P5**
Generators use `yield` to pause execution and return values lazily. They differ from lists by not storing all values in memory. `yield from` delegates to another iterable (e.g., `yield from other_generator`).

**P6**
`asyncio.run()` starts the event loop. `asyncio.gather()` waits for multiple tasks to complete. `asyncio.create_task()` schedules a coroutine. `time.sleep()` blocks the loop; use `await asyncio.sleep()` instead.

**P7**
Python uses C3 Linearization for MRO.
Order: `D -> B -> C -> A`.
`D` inherits from `B` and `C`. `B` inherits `A`. `C` overrides `A`.
Lookup: `D` checks `B`, then `C`. `C` has `who`, so `D().who()` returns "C".

**P8**
Metaclasses control class creation. `__init_subclass__` (Python 3.6+) is a hook called when a subclass is defined. Use `__init_subclass__` for simple hooks (e.g., adding attributes). Use metaclasses for complex runtime control (e.g., modifying class attributes dynamically).

**P9**
`multiprocessing` spawns processes (no GIL, separate memory). `threading` spawns threads (shared memory, GIL limits CPU). `concurrent.futures` provides a high-level interface for both. Multiprocessing requires pickling (serialization) of arguments; threading does not.

**P10**
`__slots__` prevents the creation of `__dict__` for instances, saving memory and speeding up attribute access. It prevents dynamic attribute assignment (e.g., `obj.new_attr = 1` raises `AttributeError`).

**P11**
Virtual environments isolate dependencies. `venv` is built-in. `virtualenv` is a 3rd party tool with more features. `conda` manages environments and packages (including non-Python binaries). Use `venv` for standard Python projects.

**P12**
Comprehensions `[x for x in list]` are concise syntax for `map`/`filter`. They are generally preferred for readability over explicit loops. Dict/Set comprehensions create mappings/sets directly.

**P13**
`==` checks value equality. `is` checks identity (same object in memory). Integers -5 to 256 are interned (cached), so `a is b` returns `True` for small integers even if created separately.

**P14**
`*args` collects positional arguments. `**kwargs` collects keyword arguments. `/` marks positional-only parameters (e.g., `def f(a, /, b)`). `*` marks keyword-only parameters (e.g., `def f(a, *, b)`).

**P15**
Context managers manage resources (e.g., files). `__enter__/__exit__` is the low-level protocol. `@contextmanager` (from `contextlib`) allows writing generators as context managers. Example: `@contextmanager` for database connections.

**P16**
Type hinting enables static analysis. `Union` (multiple types), `Optional` (Union with None), `Literal` (exact values), `TypeVar` (generic types), `Protocol` (structural typing). Tools like `mypy` check these hints for errors.

**P17**
`__repr__` for debugging (unambiguous). `__str__` for users (readable). `__eq__` defines equality; defining it without `__hash__` makes the object unhashable (cannot be in a set/dict).

**P18**
Descriptors manage attribute access. `__get__`, `__set__`, `__delete__`. `property`, `classmethod`, `staticmethod` are implemented using descriptors. `property` is a descriptor that intercepts attribute access.

**P19**
Imports resolve modules. Relative imports use `.` (e.g., `from . import x`). Absolute imports use full path. `sys.path` determines search order. `__init__.py` makes a directory a package. Namespace packages allow packages across directories without `__init__.py`. Finders locate modules; loaders load them.

**P20**
`dataclasses` auto-generate `__init__`, `__repr__`, etc. `attrs` is a faster, more feature-rich alternative. `Pydantic` adds validation and serialization (JSON). Use `Pydantic` for API data validation; use `dataclasses` for internal data structures. `__post_init__` allows initialization logic.
