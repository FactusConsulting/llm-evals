K1 — Easy: What is the difference between a Deployment and a StatefulSet?
A Deployment manages stateless applications. Pods are interchangeable, and updates happen in parallel. A StatefulSet manages stateful applications. Pods have stable, unique network identities (hostname), stable storage (persistent volumes), and ordered deployment/termination.

K2 — Easy: How does a Kubernetes Service of type ClusterIP route traffic to pods?
The Service creates a virtual IP (ClusterIP) within the cluster. kube-proxy (running on nodes) creates iptables or IPVS rules to forward traffic from the Service IP to the Pod IPs listed in the Service's Endpoints object.

K3 — Medium: Explain the difference between a PersistentVolume, a PersistentVolumeClaim, and a StorageClass. How do they relate?
A PersistentVolume (PV) is a cluster-wide resource representing actual storage (e.g., a disk). A PersistentVolumeClaim (PVC) is a request for storage by a user. A StorageClass defines the provisioner and parameters for dynamic PVC creation. Relation: A PVC requests storage; if dynamic, the StorageClass determines how the PV is provisioned.

K4 — Medium: A pod is stuck in CrashLoopBackOff. Describe your troubleshooting steps (at least 4 distinct checks).
1. Check container logs (`kubectl logs <pod>`) for application errors.
2. Check container status for OOMKilled or ExitCode errors.
3. Verify readiness/liveness probes are not failing.
4. Check resource limits (CPU/Memory) against node capacity.
5. Verify environment variables and ConfigMaps are mounted correctly.

K5 — Medium: What is the role of CoreDNS in a Kubernetes cluster? What happens to DNS resolution if the CoreDNS pods are down?
CoreDNS provides DNS resolution for services, pods, and namespaces within the cluster. If CoreDNS pods are down, internal service discovery fails (pods cannot resolve service names), and external DNS resolution for the cluster may break depending on configuration, though external internet access might remain.

K6 — Hard: Explain how the Kubernetes scheduler decides which node to place a pod on. Cover: filtering, scoring, and at least 3 specific factors it considers.
The scheduler first **filters** nodes that satisfy hard constraints (taints/tolerations, node selectors, resource availability). Then it **scores** remaining nodes based on preferences. Factors include: Node affinity/anti-affinity, Priority class, and resource utilization (e.g., spreading pods across nodes).

K7 — Hard: You have a pod with requests.memory: 256Mi and limits.memory: 512Mi. The node has 4GB RAM with 3.5GB already requested. Will the pod be scheduled? What happens if it actually uses 600Mi at runtime?
Yes, the pod will be scheduled because the request (256Mi) fits in the remaining capacity (4GB - 3.5GB = 0.5GB). If it uses 600Mi at runtime, it exceeds the limit (512Mi), triggering an OOMKilled event and restarting the container.

1. Client request hits External Load Balancer.

K9 — Medium: What is a NetworkPolicy? If no NetworkPolicy exists in a namespace, what is the default behavior? What happens when you apply one that selects certain pods?
A NetworkPolicy controls ingress/egress traffic to/from pods. Default behavior: All traffic is allowed. When applied, it restricts traffic to/from the selected pods based on rules (e.g., allow only from specific pods or namespaces).

K10 — Medium: Explain the difference between RollingUpdate and Recreate deployment strategies. When would you choose Recreate?
RollingUpdate updates pods gradually, keeping the application available. Recreate kills all old pods before starting new ones. Choose Recreate for stateful applications (e.g., databases) that cannot tolerate downtime or require zero replicas during updates.

K11 — Easy: What is a Kubernetes namespace, and what are the default namespaces created in a new cluster?
A namespace is a logical partition for resources. Default namespaces are: `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

K12 — Easy: What is `kubectl describe pod <name>` used for? Name at least 3 pieces of information it shows that `kubectl get pod` does not.
`describe` shows detailed status and metadata. Three pieces of info: 1. Events (history of pod actions), 2. Container status (restart count, state), 3. Node name and resource usage details.

K13 — Easy: What is a ConfigMap, and how can a pod consume it? Name at least two different methods.
A ConfigMap stores non-confidential configuration data as key-value pairs. Methods: 1. Mount as a volume (files), 2. Inject as environment variables.

K14 — Easy: What is the difference between a Service of type ClusterIP, NodePort, and LoadBalancer?
ClusterIP: Internal cluster access only. NodePort: Exposes service on a static port on every node. LoadBalancer: Provisions an external cloud load balancer to expose the service externally.

K15 — Easy: What is a DaemonSet, and when would you use one instead of a Deployment?
A DaemonSet ensures a copy of a Pod runs on all (or selected) nodes. Use it for node-level tasks like logging agents (Fluentd), monitoring (Prometheus Node Exporter), or network plugins (Calico), rather than running multiple replicas of an app.

K16 — Medium: What are taints and tolerations? How do they differ from node affinity, and give a practical use case for each?
Taints push pods away; tolerations pull pods in (node-side restriction). Node affinity pulls pods in based on node labels (node-side preference). Use case: Taints for GPU nodes (only pods with tolerations can run). Use case: Affinity for placing critical DBs on specific hardware.

K17 — Medium: Explain what a Kubernetes Operator is. How does it differ from a standard controller, and what problems does the Operator pattern solve?
An Operator is a custom controller that manages the lifecycle of a specific application type. Standard controllers manage generic resources (Pods, Deployments). Operators solve complex lifecycle problems (backups, upgrades, scaling) that standard controllers cannot handle natively.

K18 — Hard: Explain the etcd consistency model used by Kubernetes. What happens to the cluster if the etcd quorum is lost? How do you recover from a situation where 2 out of 3 etcd nodes are permanently lost?
etcd uses Raft consensus for strong consistency. If quorum is lost (e.g., 2/3 nodes down), the cluster becomes unavailable. Recovery: Since 1 node remains (insufficient for quorum), the cluster cannot self-heal. You must restore etcd data from a snapshot or backup and rejoin the cluster.

K19 — Hard: Describe how Kubernetes RBAC works. Explain the relationship between Role, ClusterRole, RoleBinding, and ClusterRoleBinding. A developer needs read-only access to pods and logs in a single namespace — write the RBAC manifests.
Role/ClusterRole define permissions. RoleBinding/ClusterRoleBinding grant those permissions to users/groups.
Manifests:
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: default
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods
  namespace: default
subjects:
- kind: User
  name: developer
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

K20 — Hard: You notice pod DNS resolution is slow (>5s) for external domains. Explain how ndots in /etc/resolv.conf inside a pod causes excessive DNS queries, and how you would fix it using dnsConfig in the pod spec.

D1 — Easy: What is the difference between git rebase and git merge? When should you avoid rebasing?
Rebase rewrites history to make it linear; merge preserves history with a merge commit. Avoid rebasing on public/shared branches or branches with unpushed commits that others might be working on.

D2 — Easy: Explain the difference between TCP and UDP. Name 2 protocols that use each.
TCP is reliable, ordered, connection-oriented. UDP is unreliable, fast, connectionless. TCP: HTTP, SSH. UDP: DNS, Video Streaming.

D3 — Medium: What is a race condition? Give a concrete example in any language.
A race condition occurs when the outcome depends on the timing of concurrent events. Example: Two threads incrementing a shared counter `count++` without locks; the final value may be less than expected due to lost updates.

D4 — Medium: Explain the difference between symmetric and asymmetric encryption. How are both used together in TLS?
Symmetric uses one key for encryption/decryption (fast). Asymmetric uses public/private key pairs (secure key exchange). TLS uses Asymmetric to exchange a session key, then Symmetric to encrypt the actual data transfer.

D5 — Medium: What is a container image layer? How does layer caching affect Dockerfile best practices?
Layers are read-only filesystem stacks. Caching speeds up builds if layers don't change. Best practice: Combine `RUN` commands to reduce layers and place `COPY` of changing files (like `requirements.txt`) after static files to invalidate cache only when needed.

D7 — Hard: Explain the CAP theorem. Give a real-world example of a system that chooses CP over AP, and one that chooses AP over CP.
CAP theorem states a distributed system can only guarantee 2 of 3: Consistency, Availability, Partition Tolerance. CP: ZooKeeper (prioritizes data consistency). AP: DynamoDB (prioritizes availability during partition).

D8 — Medium: What is the difference between horizontal and vertical scaling? What architectural patterns enable horizontal scaling?
Horizontal adds more instances; Vertical increases resources of existing instances. Horizontal scaling requires stateless applications and a load balancer to distribute traffic.

D9 — Easy: What is an environment variable? How do you set one that persists across shell sessions on Linux?
An environment variable is a dynamic name-value pair. To persist across sessions, add `export VAR=value` to `~/.bashrc` or `~/.profile`.

JSON is strict, machine-readable text. YAML is indentation-based, human-readable. JSON advantage: Strict validation. YAML advantage: Readability and comments.

D11 — Easy: What is a REST API? Explain the difference between GET, POST, PUT, and DELETE HTTP methods.
REST is a stateless architectural style using HTTP. GET: Retrieve data. POST: Create new resource. PUT: Replace/Update resource. DELETE: Remove resource.

D12 — Easy: What is version pinning in dependency management, and why is it important for reproducible builds?
Version pinning locks specific versions of libraries. It ensures builds are reproducible and prevents unexpected breaking changes from upstream updates.

D13 — Easy: What is the difference between a compiled language and an interpreted language? Give two examples of each.
Compiled languages translate source to binary before execution (C++, Rust). Interpreted languages execute source code directly via an interpreter (Python, JavaScript).

D14 — Medium: Explain what a reverse proxy is and how it differs from a forward proxy. Name two common reverse proxy servers and a use case for each.
Reverse proxy sits in front of servers (client -> proxy -> server). Forward proxy sits in front of clients (client -> proxy -> internet). Reverse: Nginx (SSL termination). Forward: Squid (Corporate internet access).

D15 — Medium: What is a deadlock? What four conditions (Coffman conditions) must hold simultaneously for a deadlock to occur?
Deadlock is when threads wait for each other indefinitely. Conditions: Mutual Exclusion, Hold and Wait, No Preemption, Circular Wait.

D16 — Hard: Explain the concept of eventual consistency. How do distributed databases like Cassandra handle read-after-write consistency, and what tunable consistency levels exist?
Eventual consistency means data converges over time. Cassandra uses tunable consistency levels: ONE (1 replica), QUORUM (majority), ALL (all replicas) to balance latency and consistency.

D17 — Hard: What is mTLS (mutual TLS)? Explain the full handshake process, including how both client and server authenticate each other. Where is mTLS commonly used in infrastructure?
mTLS requires both parties to present certificates. Handshake: Client sends cert -> Server verifies -> Server sends cert -> Client verifies. Used in Service Meshes (Istio) and secure internal APIs.

D18 — Hard: Explain how a hash table works internally, including collision resolution strategies (chaining vs. open addressing). What is the time complexity for insertion, lookup, and deletion in average and worst cases?
Hash table uses a hash function to map keys to indices. Chaining uses linked lists at indices; Open Addressing probes for empty slots. Average: O(1). Worst: O(n) (all collisions).

D19 — Hard: What is a circuit breaker pattern in microservices? Explain its three states (closed, open, half-open) and how it prevents cascade failures. How does it relate to retry policies and exponential backoff?
Circuit breaker stops calls to failing services. Closed: Normal. Open: Fails immediately. Half-Open: Tests with limited calls. Prevents cascade by stopping traffic. Retries use exponential backoff to avoid overwhelming the service during recovery.

D20 — Hard: Explain the difference between optimistic and pessimistic concurrency control in databases. When would you choose each? Give a concrete example using database features (e.g., row versioning, SELECT FOR UPDATE).
Optimistic checks for conflicts on commit (row versioning). Pessimistic locks rows immediately (SELECT FOR UPDATE). Choose Optimistic for high concurrency/low conflict. Choose Pessimistic for critical data integrity/high conflict.
