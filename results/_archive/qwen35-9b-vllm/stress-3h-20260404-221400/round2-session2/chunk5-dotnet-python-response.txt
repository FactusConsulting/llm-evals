**DN1** — In C#, a `class` is a reference type (allocated on the heap) and supports inheritance and virtual methods. A `struct` is a value type (allocated on the stack) and is immutable by default (unless mutable fields exist). Use `struct` for small, performance-critical data structures (e.g., coordinates, colors) where copying is cheaper than allocation and garbage collection overhead is undesirable.

**DN2** — `IEnumerable<T>` executes queries in memory (LINQ to Objects), while `IQueryable<T>` builds an expression tree translated into SQL (LINQ to DB). This distinction matters because `IQueryable` allows the provider (e.g., Entity Framework) to push the query logic to the database, whereas `IEnumerable` forces client-side evaluation, which is inefficient for large datasets.

**DN3** — `async/await` uses a state machine to suspend execution without blocking a thread. `Task` is a reference type wrapper for an asynchronous operation. `ValueTask` is a union of a `Task` and a result value, avoiding allocation when the operation completes synchronously. Use `ValueTask` for I/O-bound operations or CPU-bound operations where the result is known immediately to reduce GC pressure.

**DN4** — Dependency Injection (DI) allows injecting dependencies rather than creating them. Lifetimes: `Transient` (new instance per request), `Scoped` (new instance per request scope, e.g., HTTP request), `Singleton` (one instance per application lifetime). A common bug is injecting a `Scoped` service into a `Singleton`, causing the service to never be disposed, leading to memory leaks.

**DN5** — `string` is immutable and boxed (allocates on heap). `ReadOnlySpan<char>` is a view over existing memory (stack or heap) with no allocation. Use `Span<T>` for high-performance processing of buffers (e.g., parsing, serialization) to avoid unnecessary allocations and copying.

**DN6** — The GC manages memory in generations: Gen 0 (short-lived), Gen 1 (medium), Gen 2 (long-lived). Objects are promoted upon surviving collections. The Large Object Heap (LOH) stores objects >85KB. `IDisposable` is needed for unmanaged resources (files, handles) because the GC cannot track them; it relies on the developer to call `Dispose()`.

**DN7** — `ConfigureAwait(false)` tells the awaiter not to resume on the captured `SynchronizationContext`. Use it in library code or background tasks to avoid deadlocks in UI apps (WinForms/WPF/Blazor). Do NOT use it in UI code where you need to update the UI thread, as it will prevent the context from capturing the UI thread.

**DN8** — Primary constructors (C# 12) allow parameters in the class declaration. Collection expressions (e.g., `new List<int>{1, 2}`) create collections inline. `FrozenDictionary` is an immutable dictionary. Example: `class Service(IServiceProvider sp, string name) { ... }` (Note: Primary constructors in C# 12 allow this syntax directly).

**DN9** — The likely cause is that `DbContext` is registered as `Scoped` but accessed from a `Singleton` or shared across requests. EF Core's `DbContext` is not thread-safe. Fix: Ensure `DbContext` is scoped to the request (e.g., `services.AddScoped<DbContext>()`) and never inject it into a Singleton.

**DN10** — `record` is a reference type with value-based equality and immutability by default. `record struct` is a value type with value-based equality. Choose `record` for DTOs/objects with identity. Choose `record struct` for small, value-like data (e.g., `Point`).

**DN11** — `ref` allows read/write access to the variable's memory. `out` allows write-only access (caller receives value). `in` allows read-only access to the variable's memory (C# 7.2+). Use `ref` for mutable data, `out` for return values, `in` for large read-only data to prevent accidental modification.

**DN12** — Nullable reference types (`string?`) are a compile-time feature to track potential nulls. Nullable value types (`int?`) are actual structs that can hold `null`. The former is a type system feature; the latter is a runtime type.

**DN13** — LINQ is Language Integrated Query. Method syntax uses methods (`.Where()`), query syntax uses keywords (`from...where`). Both are equivalent. Deferred execution means the query is not executed until the result is enumerated (e.g., `ToList()`).

**DN14** — Generic constraints restrict type parameters. `class` (reference types), `struct` (value types), `new()` (parameterless constructor), `IComparable<T>` (interface). Combine constraints (e.g., `where T : class, IComparable<T>`) to enforce multiple requirements on the type.

**DN15** — Abstract classes can have state and members; interfaces cannot (pre-C# 8). C# 8+ interfaces can have default methods and properties. Use abstract classes for shared implementation/state. Use interfaces for contracts and decoupling.

**DN16** — Middleware processes requests sequentially. `app.Use()` adds middleware to the pipeline. `app.Map()` branches the pipeline (e.g., for sub-apps). `app.Run()` executes immediately. Order matters (e.g., Authentication before Logging). Exception handling middleware catches unhandled exceptions and returns a response.

**DN17** — `Channel<T>` is a bounded/unbounded queue with backpressure support. `BlockingCollection<T>` is unbounded and lacks backpressure. Use `Channel<T>` for producer-consumer scenarios where you need to limit memory usage (bounded) and handle backpressure.

**DN18** — Source Generators compile code at build time. Reflection is runtime. IL weaving (e.g., Fody) modifies IL post-compile. Incremental generators only recompile changed files, improving build speed. Use incremental generators for performance in large projects.

**DN19** — TPL Dataflow provides high-level blocks (`ActionBlock`, `TransformBlock`, `BufferBlock`) for pipeline processing. `System.Threading.Channels` is lower-level, offering more control over the buffer and cancellation. Dataflow is easier for complex pipelines; Channels for lightweight, custom pipelines.

**DN20** — Minimal APIs use `app.MapGet` instead of Controllers. They reduce boilerplate but lack built-in DI container wiring and OpenAPI support (requires `Microsoft.OpenApi` NuGet). Route groups organize endpoints. Endpoint filters allow cross-cutting concerns without controllers.

**P1** — `list` is mutable and ordered; `tuple` is immutable and fixed-size. `set` is unordered and mutable; `frozenset` is unordered and immutable.

**P2** — The GIL prevents multiple threads from executing Python bytecode simultaneously on one CPU core. It affects CPU-bound workloads. Workarounds: Use `multiprocessing` (separate processes) or C-extensions (e.g., NumPy) that release the GIL.

**P3** — `copy` creates a shallow copy (nested objects are shared). `deepcopy` creates a deep copy (nested objects are duplicated). Shallow copy fails if nested mutable objects are modified (e.g., `list.append` in a copied list affects the original).

**P4** — Decorators wrap functions. Example:
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start:.2f}s")
        return result
    return wrapper
```

**P5** — Generators use `yield` to return values lazily (one at a time). Returning a list creates all items upfront. `yield from` delegates to another iterable (e.g., `yield from range(10)`).

**P6** — `asyncio.run()` starts the event loop. `asyncio.gather()` waits for all tasks. `asyncio.create_task()` schedules a task. `time.sleep()` blocks the event loop; use `await asyncio.sleep()` instead.

**P7** — Python uses C3 Linearization for MRO. For `D(B, C)`, MRO is `[D, B, C, A]`. `D.who()` looks up `who`: D (no), B (no), C (yes, returns "C"). Thus, it prints "C". (Note: If B had `who`, it would return B's value).

**P8** — Metaclasses control class creation. `__init_subclass__` is a hook called when a subclass is defined (cleaner for subclass-specific logic). Metaclasses (e.g., `type`) control the class object itself. Use `__init_subclass__` for simple hooks (e.g., adding attributes to subclasses). Use metaclasses for complex logic (e.g., modifying the class dict).

**P9** — `multiprocessing` spawns processes (no GIL, separate memory). `threading` spawns threads (shared memory, GIL). `concurrent.futures` abstracts both. Multiprocessing requires pickling (serialization) of objects to pass between processes.

**P10** — `__slots__` prevents the creation of `__dict__` for instances, saving memory and preventing dynamic attribute assignment. Use it for classes with many instances (e.g., data models). It prevents adding new attributes at runtime.

**P11** — A virtual environment isolates dependencies. `venv` is built-in. `virtualenv` is a 3rd-party wrapper. `conda` manages environments and packages (including binaries) for scientific computing.

**P12** — Comprehensions are concise syntax for `map`/`filter`. List: `[x for x in ...]`. Dict: `{k: v for ...}`. Set: `{x for ...}`. Prefer comprehensions for readability; use `map`/`filter` for functional style or when chaining.

**P13** — `==` checks value equality; `is` checks identity (same object). Integers 0-256 are interned (cached), so `a is b` returns `True` for small integers even if created separately.

**P14** — `*args` collects positional arguments into a tuple. `**kwargs` collects keyword arguments into a dict. `/` marks positional-only parameters. `*` marks keyword-only parameters (must be passed as `key=value`).

**P15** — Context managers manage resources (e.g., files). `__enter__`/`__exit__` is the low-level protocol. `@contextmanager` (from `contextlib`) uses a generator. Example: `with lock:` (using a custom lock class).

**P16** — Type hinting enables static analysis. `Union` (multiple types), `Optional` (Union with None), `Literal` (exact values), `TypeVar` (generic types), `Protocol` (structural typing). Tools like `mypy` check these hints.

**P17** — `__repr__` for debugging (dev), `__str__` for users. `__eq__` for equality, `__hash__` for dict/set keys. Defining `__eq__` without `__hash__` sets `__hash__` to `None`, making the object unhashable.

**P18** — Descriptors manage attribute access via `__get__`, `__set__`, `__delete__`. `property` uses a descriptor. `classmethod`/`staticmethod` use descriptors to bind methods to the class or instance.

**P19** — Relative imports use `.` (e.g., `from . import x`). Absolute imports use full path. `sys.path` determines search order. `__init__.py` makes a directory a package. Namespace packages (no `__init__.py`) allow distributed packages. Finders locate modules; loaders load them.

**P20** — `dataclasses` auto-generate `__init__`. `attrs` adds more features (e.g., validators) via C extension. `Pydantic` adds validation/serialization (JSON). Use `__post_init__` for initialization logic. Use `frozen` for immutability. Choose Pydantic for complex validation/serialization needs.
