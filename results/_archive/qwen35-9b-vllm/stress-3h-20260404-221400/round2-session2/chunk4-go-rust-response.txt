G1 — Easy: In Go, an **array** is a fixed-size, contiguous sequence of values stored on the stack (or heap if large) and passed by value. A **slice** is a descriptor containing a pointer to an underlying array, a length, and a capacity; it is passed by reference. When you **append** to a slice, if the underlying array's capacity is exceeded, Go allocates a new, larger array, copies the old elements, and updates the slice descriptor to point to the new array.

G2 — Easy: `var x int` declares a variable `x` and initializes it to the zero value (0). `x := 0` declares and initializes `x` in a single step. You **cannot** use `:=` at the package level (top of a file) or if a variable with the same name already exists in the current scope. `:=` is only allowed inside functions for new variables.

G3 — Medium: A **goroutine** is a lightweight user-level thread managed by the Go runtime, whereas an OS thread is a heavy kernel resource. The **GMP model** consists of G (goroutine), M (OS thread), and P (processor). The scheduler multiplexes Gs onto Ms, allowing thousands of goroutines to run on fewer OS threads.

G4 — Medium: Channels allow goroutines to communicate. An **unbuffered channel** blocks the sender until a receiver is ready. A **buffered channel** acts as a queue of size N. If you send to a **full buffered channel**, the sender blocks until the receiver removes an item or the channel is closed.

G5 — Medium: The **context** package manages request-scoped values (like cancellation, deadlines, and values) across goroutines.
```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
resp, err := http.Get(ctx, "https://example.com")
```
This ensures the request is cancelled if it exceeds 5 seconds.

G6 — Medium: Go uses **implicit interface satisfaction** (any type with the required methods implements the interface), whereas Java/C# require explicit implementation. `interface{}` (or `any`) is the empty interface, capable of holding any type. It is powerful for generic-like behavior but dangerous because it bypasses type safety, leading to runtime panics on type assertions.

G7 — Hard: This code is unsafe due to a **data race**. The `ready` boolean is not atomic, and the main goroutine reads it without synchronization. The `data` assignment is also not guaranteed to be visible to the main goroutine immediately. Correct alternatives include using `sync/atomic.Bool`, `sync.WaitGroup`, or `sync.Mutex` to ensure visibility and ordering.

G8 — Hard: `sync.Mutex` allows only one writer at a time. `sync.RWMutex` allows multiple concurrent readers but exclusive writers. `sync.Map` is optimized for high-concurrency read-heavy workloads (no locking for reads) but has slower writes compared to a regular `map` protected by a `Mutex`.

G9 — Hard: **Go modules** manage dependencies. `go.mod` declares the module path and dependencies. `go.sum` stores checksums for security. `go mod tidy` cleans up unused dependencies and ensures versions match `go.mod`. The **Minimum Version Selection (MVS)** algorithm selects the lowest version of a dependency that satisfies all constraints.

G10 — Medium: `defer` schedules a function call to run when the surrounding function returns. Multiple defers execute in **LIFO** (Last-In, First-Out) order. A common gotcha is deferring inside a loop: the deferred function captures the loop variable by reference, so all deferred calls use the loop's final value.

G11 — Easy: A **pointer** (`*T`) holds the memory address of a value. The zero value of a pointer is `nil`. To create a pointer to a struct literal, use `&Struct{}`.

G12 — Easy: The `init()` function runs automatically when a package is loaded, before `main()`. A package can have multiple `init()` functions (e.g., in different files), and they execute in the order of their declaration within the package.

G13 — Easy: `make` allocates and initializes built-in types (slices, maps, channels). `new` allocates a zero value of a type and returns a pointer to it. `make` works with slices/maps/channels; `new` works with any type.

G14 — Easy: Go uses an `error` interface (`error interface{ Error() string }`). The idiomatic check is `if err != nil`. `errors.Is` checks if an error wraps a specific error value. `errors.As` performs a type assertion to find a specific error type within a wrapped error chain.

G15 — Easy: Built-in composite types are **map**, **slice**, **channel**, and **struct**. Their zero values are: `nil` (map, slice, channel) and zero values for struct fields (e.g., `0`, `""`, `false`).

G16 — Medium: A **race condition** occurs when two goroutines access shared data concurrently without synchronization. The `-race` flag enables the Go race detector. Example:
```go
var x int
go func() { x++ }()
go func() { x++ }()
```
Fix: Use `sync.Mutex` to lock access to `x`.

G17 — Medium: `select` handles multiple channel operations. If multiple cases are ready, Go chooses one **randomly**. It differs from `switch` by supporting channel operations. To implement a timeout, use `select` with a `time.After` case.

G18 — Hard: **Escape analysis** determines if a variable lives on the stack or heap. If a variable is used outside the function (e.g., returned), it escapes to the heap. You can inspect this with `go build -gcflags="-m"`. It matters because heap allocation incurs GC overhead.

G19 — Hard: The **reflect** package allows runtime introspection. `reflect.Type` represents the type, `reflect.Value` represents the value. Reflection is slow (dynamic dispatch) and should be avoided in performance-critical paths; it is justified for serialization or generic-like behavior where generics aren't available.

G20 — Hard: `go:embed` embeds files or directories at compile time. It supports single files, directories, and `io/fs.FS`. Limitations include path resolution (must be relative to the package) and inability to embed external URLs. It interacts with `io/fs.FS` to provide an in-memory filesystem.

R1 — Easy: **Ownership** means each value has a single owner responsible for its memory. The three rules: 1. Each value has one owner. 2. When the owner goes out of scope, the value is dropped. 3. When a value is moved, the new owner takes responsibility.

R2 — Easy: `String` is an owned, heap-allocated UTF-8 string. `&str` is a borrowed slice of UTF-8 bytes. Use `String` when you need to own the data (e.g., return value). Use `&str` for function arguments to avoid unnecessary allocations.

R3 — Medium: **Borrowing** allows accessing data without ownership. Immutable references (`&T`) allow reading. Mutable references (`&mut T`) allow reading and writing. Rules: 1. Only one mutable reference at a time. 2. No aliasing (no two mutable references). 3. No mutable reference while immutable references exist.

R4 — Medium: `Result<T, E>` holds `Ok(T)` or `Err(E)`. `Option<T>` holds `Some(T)` or `None`. The `?` operator propagates errors (returns immediately if `Err`).
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)?
}
```

R5 — Medium: `Box<T>` is a heap-allocated pointer (single owner). `Rc<T>` is a thread-local reference-counted pointer. `Arc<T>` is an atomic reference-counted pointer for multi-threading. Use `Box` for single ownership on heap, `Rc` for single-threaded sharing, `Arc` for multi-threaded sharing.

R6 — Medium: **Traits** define behavior. Go interfaces are implicit; Rust traits are explicit. `dyn Trait` (trait objects) use dynamic dispatch (vtable). Generic with trait bound (`T: Trait`) uses static dispatch (monomorphization), which is faster.

R7 — Hard: This fails because the compiler cannot guarantee that `x` or `y` lives long enough to return the reference. Fix: Add a lifetime parameter.
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

R8 — Hard: `Send` means a type can be sent across threads. `Sync` means it can be shared (multiple references). `Rc<T>` is not `Send` because ref-counting isn't atomic. `Arc<T>` uses atomic ref-counting, making it `Send` and `Sync`.

R9 — Hard: Rust's `async/await` compiles to state machines implementing the `Future` trait. An **executor** (e.g., Tokio) drives these futures. Unlike Go's M:N scheduling, Rust's async is cooperative and relies on the executor to yield control.

R10 — Medium: `unsafe` blocks allow bypassing safety checks. You can: 1. Dereference raw pointers. 2. Call FFI functions. 3. Disable bounds checking. It is justified for FFI, performance-critical code, or when interfacing with unsafe C libraries.

R11 — Easy: **Pattern matching** (`match`) is exhaustive; the compiler enforces all cases are covered. `if let` is partial and allows falling through. `match` is preferred for `Result` or `Option` handling.

R12 — Easy: `Vec<T>` is a growable heap array. `[T; N]` is a fixed-size stack array. When `Vec` capacity is exceeded, it allocates a larger buffer and copies elements (usually doubling capacity).

R13 — Easy: Rust **enums** are tagged unions (can hold data of different types). C/Java enums are just integer constants. `Option<T>` is an enum with `Some(T)` and `None`. Rust has no null; `Option` replaces it to prevent null pointer dereferences.

R14 — Easy: The `impl` block defines methods for a type. `&self` borrows immutably, `&mut self` borrows mutably, `self` consumes the value. Associated functions (e.g., `String::new`) take `&Self` or no self and are called on the type.

R15 — Easy: **Derive macros** generate code automatically. Common traits: `Debug`, `Clone`, `PartialEq`, `Serialize`. You cannot derive if the struct contains fields that do not implement the trait (e.g., `Clone` on a struct with a non-cloneable field).

R16 — Medium: `Cow<'a, T>` (Clone on Write) holds a reference if immutable, or a clone if mutable. It avoids allocation when the data is read-only. Example: `Cow::Borrowed(data)` avoids cloning if the string is not modified.

R17 — Medium: `mod` declares a module, `use` imports items, `pub` makes items public. The file system maps to modules (e.g., `src/mod.rs` maps to `mod`). The 2018 edition changed path resolution to allow `mod` directories with `mod.rs` or `lib.rs`.

R18 — Hard: `Pin<T>` prevents a value from being moved in memory. It is needed for self-referential structs or async tasks where the memory address must remain stable. `Unpin` trait allows relaxing this constraint.

R19 — Hard: **Declarative macros** (`macro_rules!`) are text substitution. **Procedural macros** (derive, attribute, function-like) are Rust code that generates code. Hygiene rules ensure macros don't pollute the global scope (e.g., `!` is not a macro name).

R20 — Hard: **Zero-cost abstractions** mean high-level code compiles to the same machine code as hand-written C. Iterators avoid heap allocation. Generics use **monomorphization** (compile specific types). Traits use **static dispatch** (resolved at compile time), avoiding runtime overhead.
