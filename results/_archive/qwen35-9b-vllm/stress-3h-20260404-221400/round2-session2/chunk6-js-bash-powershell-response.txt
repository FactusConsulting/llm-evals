## JavaScript / TypeScript

**JS1**
`var` is function-scoped and hoisted (initialized as `undefined`). `let` is block-scoped and not hoisted (temporal dead zone). `const` is block-scoped and cannot be reassigned (but properties can). Hoisting is the process where declarations are moved to the top of their scope during the compilation phase.

**JS2**
The event loop manages asynchronous execution. The call stack executes synchronous code. When the stack is empty, the event loop checks the microtask queue (Promises, `queueMicrotask`) first, then the macrotask queue (setTimeout, I/O). Microtasks run before the next macrotask.

**JS3**
A closure is a function bundled with its lexical environment. Example: `function outer() { let x = 1; return function() { return x; }; }`. The classic bug is `for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i)) }` (logs 3,3,3). Fix: use `let` (block scope) or `i => { ... }` (IIFE).

**JS4**
Promises represent async completion. `async/await` is syntactic sugar over Promises. Errors in `await` throw synchronously. `Promise.all` rejects if *any* promise rejects. `Promise.allSettled` waits for all to settle (fulfilled/rejected) and returns results without rejecting early.

**JS5**
Interfaces define shapes (properties/methods) and are erased at runtime. Types define values (primitives, unions, objects) and are erased. Use interfaces for object shapes; types for primitives or complex value logic. Discriminated unions use a literal type to distinguish union members (e.g., `{ type: 'success' } | { type: 'error' }`).

**JS6**
JS uses prototypes. `Object.create(proto)` creates an object with `__proto__` pointing to `proto`. ES6 classes are syntactic sugar over prototype chains; `class A extends B` creates a constructor function and sets the prototype to `B.prototype`.

**JS7**
`this` refers to the execution context. Binding rules (priority): 1. Explicit binding (`obj.method()`), 2. Implicit binding (method call), 3. `new` binding (constructor), 4. Default binding (global/undefined). `bind()` returns a new function with `this` permanently bound. It can be re-bound, but the original binding is lost.

**JS8**
`WeakRef` holds a weak reference to an object (can be GC'd). `FinalizationRegistry` runs a callback when an object is GC'd. `WeakMap` keys must be objects (not primitives) because primitives are interned and cannot be garbage collected, which would prevent the map from ever being cleaned up.

**JS9**
V8 optimizes via hidden classes (shape of objects) and inline caching (caching property access locations). Deoptimization occurs when assumptions break (e.g., adding a property to an object, changing a function's signature). Patterns causing deoptimization: mutating objects, adding properties, changing function arity.

**JS10**
Tree-shaking removes unused code. It works with ES Modules (static imports) because the dependency graph is known at build time. CommonJS uses dynamic `require()`, so the bundler cannot statically analyze usage, preventing effective tree-shaking.

**JS11**
`null` is an empty object value; `undefined` is a missing value. `==` performs type coercion (e.g., `null == undefined` is true); `===` checks strict equality. `??` returns the right operand if the left is `null` or `undefined`. `?.` safely accesses nested properties (returns `undefined` if path is broken).

**JS12**
`map` transforms elements; `filter` creates a new array of matching elements; `reduce` aggregates elements into a single value. `reduce` takes an accumulator and current value. `flatMap` maps then flattens the result by one level (useful for nested arrays).

**JS13**
Template literals use backticks `` ` `` and allow interpolation `${expr}`. Tagged templates pass raw string parts to a function. Example: `sql` tag function joins parts with quotes to prevent SQL injection.

**JS14**
Destructuring extracts values. Object: `{ a } = obj`. Array: `[ a ] = arr`. Defaults: `{ a = 1 }`. Renaming: `{ a: b }`. Rest operator `...` collects remaining elements/properties into an array/object.

**JS15**
`for...in` iterates over enumerable own and inherited properties (use for objects). `for...of` iterates over iterable values (use for arrays). Avoid `for...in` on arrays as it iterates over indices and non-array properties, potentially including inherited ones.

**JS16**
Generics allow reusable types. Constraints: `T extends U` restricts T. Conditional types: `T extends U ? X : Y` (branching). `infer` extracts a type from a conditional type. Example: `type Result<T> = T extends string ? string : number`.

**JS17**
CommonJS uses `require`/`module.exports` (Node default). ES Modules use `import`/`export` (browser default). Node supports both via `--experimental-modules` or `"type": "module"` in `package.json`. The latter makes all imports ES modules.

**JS18**
Structural types check shape, not declaration. Excess property checks apply to object literals passed to constructors/functions. `extends` checks structural compatibility; `satisfies` checks if a value satisfies a type without widening. Variance: `in` (input) and `out` (output) determine if a generic type is covariant or contravariant.

**JS19**
`Proxy` creates a proxy object to intercept operations. `Reflect` provides standard operations. Intercepts: `get` (access), `set` (assignment), `apply` (function call). Example: A proxy that logs property access before returning the value.

**JS20**
`SharedArrayBuffer` allows memory sharing between threads (Web Workers). `Atomics` provides atomic operations (wait, notify, exchange). Workers communicate via `postMessage` or shared memory. `Atomics.wait` blocks until notified or timeout; `Atomics.notify` wakes up waiting threads.

## Bash

**B1**
`$@` expands to each argument as a separate word. `$*` expands to all arguments as a single string (space-separated). `"$@"` preserves word boundaries (safe for loops). `"$*"` treats all args as one string.

**B2**
`set -e`: Exit on error. `set -u`: Error on undefined variable. `set -o pipefail`: Propagate pipe errors. Together, they make scripts robust against silent failures.

**B3**
`$(cmd)` performs command substitution (output). `command` is a group command (subshell). `$((expr))` is arithmetic expansion. `expr` is an external command for string/math operations (slower, deprecated).

**B4**
Process substitution `<(cmd)` creates a named pipe (FIFO) so a command can read from it. Example: `diff <(sort file1) <(sort file2)` compares sorted versions without creating temp files.

**B5**
Use `while IFS= read -r -d '' file; do ...; done < <(find . -print0)`. `for f in $(ls)` splits on whitespace, breaking files with spaces into multiple variables.

**B6**
`<<EOF` reads until EOF. `<<<` is a here string (reads from a variable). `<<-EOF` allows indentation of the delimiter.

**B7**
`cmd > file 2>&1`: stdout to file, then stderr to stdout (file). `cmd 2>&1 > file`: stderr to stdout (terminal), then stdout to file (file). `cmd &> file`: both stdout and stderr to file. First two differ because redirection order matters.

**B8**
Use `mkdir -p lockdir` and `touch lockdir/lock`. Check existence with `test -e`. Use `flock` for atomic locking. If script is killed, `trap` on EXIT cleans up. `mkdir` is atomic on most filesystems, avoiding race conditions compared to file creation.

**B9**
Single quotes `'...'`: literal, no expansion. Double quotes `"..."`: variable expansion, no glob. No quotes: variable expansion + glob. Example: `echo 'a b'` (literal) vs `echo "a $b"` (variable).

**B10**
`-f` (file), `-d` (directory), `-r` (readable). `[ ]` uses word splitting/globbing; `[[ ]]` does not and supports extended patterns. `[[ ]]` is safer for variables.

**B11**
`$?`: Exit status of last command. `$$`: PID of current shell. `$!`: PID of last background process. `$#`: Number of arguments passed to a function/script.

**B12**
`function foo {}` or `foo() {}`. Return values via `echo` or `return` (integer). To return strings, use `echo` or `printf`.

**B13**
`PATH` is a colon-separated list of directories. Bash searches `PATH` for executables. Builtins are internal (e.g., `cd`); externals are in `PATH`. Use `type -a` to check.

**B14**
`trap 'cmd' signal`. `EXIT`: cleanup on exit. `ERR`: on error. `INT`: Ctrl+C. `TERM`: kill. Order: signals are handled asynchronously; `EXIT` runs last.

**B15**
`xargs` processes arguments from stdin. `find -print0 | xargs -0` handles spaces/newlines. `xargs -P n` runs `n` processes in parallel.

**B16**
Arrays: `arr=(a b c)`. Associative: `declare -A assoc`. Access: `arr[0]` vs `assoc[key]`. Length: `${#arr[@]}` vs `${#assoc[@]}`.

**B17**
Subshell `(...)` creates a new shell (variables don't persist). Group `{ ... }` shares scope. Piping into `while` runs the loop in a subshell, so variable changes are lost.

**B18**
`SIGINT` (Ctrl+C), `SIGTERM` (kill), `SIGHUP` (hangup), `SIGKILL` (unkillable). Use `trap` to stop background jobs (`kill -TERM $pid`) and wait for them.

**B19**
Split log: `split -l 10000 file part_`. Process: `xargs -P 4 -I {} process {}.` Merge: `cat part_* > merged`. Trade-off: parallelism vs I/O overhead. Handle errors by checking exit codes in the processing function.

**B20**
`exec` replaces the current shell process. `exec 3>file` redirects FD 3. Coprocess: `coproc name; read -p "Prompt" <&${name[0]} >&${name[1]}`. Used for interactive background tasks.

## PowerShell

**PS1**
`Write-Output` sends objects to the pipeline. `Write-Host` writes to the console (bypasses pipeline). Distinction matters because `Write-Host` breaks piping.

**PS2**
Pipeline passes objects. `ForEach-Object` is a cmdlet (pipeline-aware). `foreach` is a statement (not pipeline-aware). Use `ForEach-Object` for object processing.

**PS3**
`[PSCustomObject]` creates a proper object with properties. `[hashtable]` is a collection of key-value pairs. Convert: `@{a=1} | ConvertTo-Json` or `[PSCustomObject]@{...}`.

**PS4**
Terminating errors stop execution. Non-terminating continue. `-ErrorAction Stop` forces termination. `try/catch` catches terminating errors. `$ErrorActionPreference` sets default behavior.

**PS5**
Splatting `@params` passes a hashtable as named arguments. Passing a hashtable as a single argument treats it as a single object. Splatting is cleaner for cmdlets with many parameters.

**PS6**
`Invoke-Command` runs a script on a remote computer. `Enter-PSSession` opens an interactive session. Uses WinRM (HTTP/HTTPS) or SSH (PowerShell 7+).

**PS7**
Functions returning scalars (strings) in a pipeline are treated as arrays. `Get-Items` returning "one" becomes `System.String[]`. Correct pattern: `return $result` (array) or `return $result[0]` (scalar) depending on intent.

**PS8**
`[scriptblock]` is a block of code. Pass to remote via `-ScriptBlock`. Double-hop: remote server authenticates to another server. Solve with CredSSP (`-Credential`) or `-ArgumentList` (if variables are needed).

**PS9**
`@()` creates an array. `[array]` is a type. Force single result: `@($result)`. Indexing `$null` throws; indexing empty array returns `$null`.

**PS10**
`-eq` (equals), `-ne` (not equals), `-like` (wildcard), `-match` (regex), `-contains` (array), `-in` (scalar check). Case-sensitive variants: `-ceq`, `-clike`. `-contains` checks array membership; `-in` checks scalar membership.

**PS11**
Modules are reusable code. `.psm1` (script module), `.psd1` (manifest), `.ps1` (binary). `Import-Module` loads the module.

**PS12**
Interpolation: `"${variable}"`. Single quotes `'...'` disable interpolation. Here-string: `@"..."@` (multiline).

**PS13**
`Get-Member` lists properties/methods. `Select-Object` selects properties. `Where-Object` filters objects. NoteProperties are user-defined.

**PS14**
PowerShell classes are dynamic, not compiled like C#. No strict inheritance hierarchy. Use classes for encapsulation/state; functions for logic.

**PS15**
`[CmdletBinding()]` enables advanced features. `SupportsShouldProcess` adds `-WhatIf/-Confirm`. `ValueFromPipeline` allows piping objects. `Begin/Process/End` blocks handle streaming.

**PS16**
Providers abstract namespaces. `Get-ChildItem` works on FileSystem, Registry (`HKLM:`), Certificate (`Cert:`). Registry access: `Get-ItemProperty HKLM:\Software`.

**PS17**
`[runspace]` is a thread. `[runspacepool]` manages them. `[powershell]` object executes commands. `ForEach-Object -Parallel` (v7+) is easier than manual runspace management.

**PS18**
`PSScriptAnalyzer` enforces rules (e.g., `PSUseShouldProcess`). Severity: Info, Warning, Error. Suppress with `# #`. Integrate via CI/CD (e.g., GitHub Actions).

**PS19**
`$using:` passes variables to background jobs/parallel. `-ArgumentList` passes arguments. Serialization limits (CLIXML depth) restrict complex objects (e.g., nested arrays).

**PS20**
DSC manages configuration state. Configurations define desired state. LCM applies them. Modern replacement: Ansible, Terraform, or PowerShell Desired State Configuration (DSC) is largely replaced by cross-platform tools or native config management.
