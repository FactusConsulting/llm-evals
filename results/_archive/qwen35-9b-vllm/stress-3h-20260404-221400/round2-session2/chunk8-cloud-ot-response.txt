CL1 — IaaS provides virtualized hardware (e.g., AWS EC2). PaaS provides a platform for development (e.g., AWS Elastic Beanstalk). SaaS provides ready-to-use applications (e.g., Salesforce).

CL2 — In IaaS, the provider manages hardware/network/OS; you manage OS/App. In managed Kubernetes, the provider manages the control plane; you manage nodes/workloads. In SaaS (M365), the provider manages everything including data; you manage user access.

CL3 — A VPC is a logical isolation boundary. A subnet is an IP range within a VPC. A Security Group is a stateful firewall attached to instances. A NACL is a stateless firewall attached to subnets. Layering: VPC contains Subnets; NACL filters traffic at the subnet boundary; Security Groups filter traffic at the instance boundary. Stateful means return traffic is allowed automatically (SG); Stateless means rules must be explicitly defined for both directions (NACL).

CL4 — A Landing Zone provides a standardized foundation (networking, identity, logging). OUs organize accounts hierarchically. Guardrails enforce policies (e.g., no public S3). Shared networking uses a Transit Gateway (AWS) or Hub-and-Spoke (Azure) to connect accounts. Centralized logging aggregates logs (e.g., CloudTrail) for audit. Single-account approaches limit isolation, make scaling difficult, and increase risk of lateral movement.

CL5 — IaC manages infrastructure via code. Terraform/OpenTofu uses a declarative state file. Pulumi uses programming languages (Python/Go). CloudFormation/Bicep are native provider tools. Crossplane manages infrastructure as Kubernetes resources. Choose Terraform for multi-cloud portability; Pulumi for complex logic; CloudFormation for deep AWS integration; Crossplane for K8s-native workflows.

CL6 — HPA scales pod count based on CPU/Memory. VPA scales pod resource requests. Cluster Autoscaler adds/removes nodes. KEDA scales based on external events (e.g., Kafka messages). Use KEDA over HPA when scaling must be triggered by external events (e.g., queue depth) rather than internal resource utilization.

CL7 — RPO is data loss tolerance; RTO is downtime tolerance. Active-Active replicates workloads in both regions; Active-Passive keeps one primary. Sync replication ensures zero data loss but high latency; Async allows latency but risks data loss. DNS failover directs traffic to the healthy region. Pilot Light (minimal standby), Warm Standby (partial resources), Multi-site Active-Active (full resources). Active-Active is most resilient but most expensive.

CL8 — GitOps stores desired state in Git. CD pipelines sync Git to K8s. ArgoCD is K8s-native; FluxCD is cloud-native. Secrets are managed via Sealed Secrets or External Secrets Operator (integrating with HashiCorp Vault). Manual changes cause drift; GitOps tools detect drift and automatically revert or alert to reconcile the state.

CL9 — Use StatefulSet for ordered, stable pod identities. Use Local Persistent Volumes (LocalPath) for low-latency storage. Use a Headless Service for DNS-based service discovery. Use Init Containers to prepare filesystems. Mount ConfigMaps as volumes for config files. Use Pod Disruption Budgets to ensure availability during scaling.

CL10 — A Service Account is a K8s identity. Workload Identity binds K8s SAs to cloud IAM roles (e.g., AWS IRSA). Mounting credentials in pods is bad because it requires rotation and exposes secrets. Workload Identity federation allows pods to assume cloud roles without storing keys, solving the rotation and security issue.

CL11 — Object storage (S3/Blob) stores files as objects; Block storage (EBS/Disk) is raw disks for DBs; File storage (EFS/Files) is shared filesystems. Object is for unstructured data; Block for high-performance DBs; File for shared app data. Object storage offers 99.999999999% durability; Block/File offer high availability within zones/regions.

CL12 — Zero Trust assumes no trust by default. Network Policies restrict pod-to-pod traffic. Service Mesh (Istio) enforces mTLS. Pod Identity binds workloads to identities. Admission Controllers (OPA) enforce policies. Image signing ensures supply chain security. Falco monitors runtime behavior. Unlike perimeter security, Zero Trust verifies every request regardless of origin.

CL13 — A CDN caches content at edge locations closer to users. It works by routing requests to the nearest cache. Services: AWS CloudFront, Azure CDN. Use a CDN for static assets (images, video) to reduce latency; serve directly from origin for dynamic, personalized content.

CL14 — A Region is a geographic area with data centers. An Availability Zone (AZ) is a physically isolated location within a Region. Deploy across AZs to protect against zone-level failures. Zonal resources are single-AZ; Regional resources span multiple AZs.

CL15 — A managed database (RDS/Cloud SQL) handles patching, backups, scaling, and HA. Running on a VM requires you to manage OS, patches, backups, and failover logic manually.

CL16 — IAM Users are individuals; Groups organize users; Roles are permissions attached to users or services. Policies define permissions. Least Privilege means granting only the minimum permissions required for a task. Apply it by using specific policies rather than broad admin roles.

CL17 — Serverless executes code in response to events without managing servers. Lambda (AWS), Functions (Azure), Cloud Functions (GCP). Cold starts occur when a function is invoked after inactivity, causing latency. Serverless is poor for long-running processes or high-latency requirements.

CL18 — Ingress resource is the K8s standard. Gateway API is the newer, more flexible standard. Cloud LB annotations offload traffic to the provider. Service Mesh ingress gateways handle mTLS and observability. TLS termination can happen at the edge (Cloud LB) or at the Ingress. Use Gateway API for multi-protocol support and standardization.

CL19 — Reserved Instances/Savings Plans commit to usage for discounts. Spot instances offer lower cost for interruptible workloads. Right-sizing matches instance size to workload. Storage tiering moves infrequent data to cheaper storage. FinOps involves visibility, allocation, and optimization. Tools: AWS Cost Explorer, CloudHealth. Showback charges teams for usage; Chargeback bills them directly.

CL20 — Use Kubernetes as a common runtime to abstract infrastructure. Terraform manages infrastructure portably. Networking uses Interconnects (Direct Connect/ExpressRoute). Identity uses federation (OIDC/SAML). Multi-cloud is justified for risk avoidance or specific regional requirements, but unnecessary complexity if a single cloud meets all needs.

OT1 — The Purdue Model (ISA-95) defines 7 levels of enterprise control. Level 0: Physical Process. Level 1: Basic Control (PLCs). Level 2: Supervisory Control (SCADA). Level 3: Enterprise Control (MES). Level 4: Business Planning (ERP). Level 5: Business Management. Level 6: Corporate Management.

OT2 — IT networks prioritize data availability and confidentiality. OT networks prioritize safety and reliability. Standard IT patching can disrupt OT operations or introduce vulnerabilities to safety-critical systems, so patching must be tested and scheduled during maintenance windows.

OT3 — An IDMX (Industrial DMZ) separates IT and OT networks. Traffic flows from IT to OT (e.g., for monitoring) but not directly from OT to IT. Direct connectivity from Level 4 (IT) to Level 1 (Control) is dangerous because a compromise in IT could directly impact physical safety or production.

OT4 — Modbus TCP (L1), OPC UA (L1/L2), EtherNet/IP (L1), PROFINET (L1), MQTT (L2/L3). Modbus/OPC UA/EtherNet/IP/PROFINET operate at the control level (L1/L2) for real-time data. MQTT operates at the supervisory level (L2/L3) for messaging.

OT5 — A data diode allows traffic in only one direction (e.g., OT to IT). A firewall allows bi-directional traffic based on rules. Use a hardware data diode when preventing data exfiltration from OT to IT is critical (e.g., SCADA to corporate). The limitation is that it cannot block inbound traffic.

OT6 — Data flows from PLC -> Historian -> Edge Gateway -> MQTT Broker -> Cloud. Security boundaries are placed at the Edge Gateway (OT to IT) and the MQTT Broker (DMZ). The Edge Gateway validates and sanitizes data before sending to the cloud.

OT7 — A Zone is a logical boundary of assets with similar security requirements. A Conduit is a connection between zones. Model: Zone 1 (Corporate), Zone 2 (Engineering), Zone 3 (SCADA), Zone 4 (PLCs/SIS). Conduits connect zones via firewalls or DMZs. SIS is often isolated in a separate zone.

OT8 — Design VLANs for each production line and function (Engineering, SCADA). Place firewalls between VLANs. Use Layer 3 switches for routing. Remote access uses a Jump Host with MFA. Transition without stopping production by migrating line-by-line or using parallel networks.

OT9 — SIS is for safety (emergency shutdown); BPCS is for process control. IEC 61511 defines functional safety. SIS must be isolated to prevent ransomware from locking down safety systems. If ransomware reaches SIS, it could cause physical damage or loss of life.

OT10 — PLCs are for discrete control in small systems. DCS is for continuous control in large plants. SCADA is for monitoring and remote control. They can coexist; PLCs control machines, SCADA monitors them, DCS manages large processes.

OT11 — Remote access should use a Jump Host (Bastion) with MFA and session recording. Vendor access is time-limited. RDP directly to an HMI is unacceptable because it bypasses security controls and exposes the control system directly to the internet.

OT12 — Detection: Use IDS/IPS and anomaly detection on network traffic. Inventory: Maintain a known asset list. Response: Isolate the compromised segment, notify the control room. The operator ensures physical safety and decides on production shutdown.

OT13 — An HMI allows operators to monitor and control the process. It differs from an engineering workstation, which is used for configuration and logic editing, not real-time operation.

OT14 — A historian stores time-series process data. It is important for trend analysis and compliance. A plant historian stores operational data (Level 3); an enterprise historian aggregates data for business analysis (Level 4).

OT15 — Ladder logic is a programming language resembling relay logic. It is executed by PLCs. It remains dominant due to operator familiarity and legacy system compatibility.

OT16 — An RTU is a ruggedized controller for remote locations. It differs from a PLC in that it is designed for harsh environments and simpler logic. RTUs are deployed in remote pipelines or oil rigs; PLCs are in factories.

OT17 — Analog signals are continuous (4-20mA, 0-10V). Digital signals are discrete (0/1). 4-20mA is preferred over 0-20mA because it allows distinguishing between a live zero (4mA) and a broken wire (0mA).

OT18 — Asset inventory is the foundation of security. Passive monitoring (sniffing) is safe; active scanning (pinging) can disrupt OT operations and is dangerous. Use passive tools like Wireshark or specialized OT scanners.

OT19 — MITRE ATT&CK for ICS maps adversary tactics to OT environments. Tactics include Reconnaissance (e.g., T1590), Execution (e.g., T1059), Persistence (e.g., T1098). It differs from Enterprise ATT&CK by including ICS-specific techniques. Use it to identify gaps in detection capabilities.

OT20 — Log collection uses agents or syslog without impacting real-time operations. SIEM integrates OT logs with IT logs. OT rules focus on protocol anomalies (e.g., Modbus errors). Staffing requires OT engineers to triage alerts. False positives are high due to noisy industrial environments. Unauthorized firmware changes trigger an immediate quarantine of the asset and verification by the OT team.
