SC1-A
The pods fail because the cluster's Pod Security Standard (PSS) was upgraded from **Baseline** to **Restricted**.
1.  **Baseline:** Allows containers to run as root.
2.  **Restricted:** Prohibits running as root.
3.  **Interaction:** The manifest sets `securityContext.runAsNonRoot: true`. In Kubernetes, if `runAsNonRoot` is true, the `runAsUser` field must be explicitly set to a non-zero value.
4.  **Image Issue:** The new base image (`cgr.dev/chainguard/static:latest`) defaults to `USER root`. Since the manifest does not override `runAsUser`, the container attempts to run as root.
5.  **Result:** The Restricted PSS enforces that the container must not run as root. Kubernetes rejects the pod creation or kills it immediately, resulting in `CrashLoopBackOff`.

SC2-A
1.  **Stale Data:** Promoting a cross-region read replica involves asynchronous replication. The replica may lag behind the primary by minutes or hours.
2.  **Replication Lag:** PostgreSQL streams WAL (Write-Ahead Log) records. If the replica is behind, it has not received all committed transactions from the primary.
3.  **Data Loss:** Any transaction committed on the primary after the replica's last sync point is lost upon failover.
4.  **Quantification:** Check `pg_stat_replication` (if accessible) or the RDS console's "Replication Lag" metric. The "lag" value indicates the time window of potential data loss.
