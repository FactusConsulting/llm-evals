**JS1** — `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped. `const` cannot be reassigned. Hoisting moves declarations to the top of their scope, but `let`/`const` remain in a Temporal Dead Zone (TDZ) until execution reaches the declaration.

**JS2** — The event loop processes the call stack. When the stack is empty, it checks the microtask queue (Promises, `queueMicrotask`) before the macrotask queue (`setTimeout`, I/O). Microtasks run to completion before any macrotask.

**JS3** — A closure is a function bundled with its lexical environment. Example: `function makeCounter() { let count = 0; return () => ++count; }`. The classic bug is `var i` in a loop; fix by using `let` or `var i = i` inside the loop.

**JS4** — `Promise` represents an async operation. `async/await` is syntactic sugar. Errors are caught via `try/catch`. `Promise.all` rejects on the first error; `Promise.allSettled` waits for all to resolve/reject without failing early.

**JS5** — `interface` defines object shapes (methods/properties) and is erased at runtime. `type` defines primitives or unions. Use `interface` for objects, `type` for primitives/complex unions. Discriminated unions use literal types (e.g., `{ type: 'A' }`) to distinguish union members.

**JS6** — Objects inherit from a prototype chain. `Object.create(proto)` sets the prototype. ES6 classes are syntactic sugar that compile to prototype-based inheritance (constructor functions + prototype properties).

**JS7** — `this` binding rules (priority): 1. Explicit (`call`, `apply`, `bind`), 2. Implicit (object method), 3. `new` (constructor), 4. Default (global/undefined). `bind()` returns a new function with `this` permanently bound; it can be re-bound.

**JS8** — `WeakRef` holds a weak reference to an object (allowing GC). `FinalizationRegistry` notifies when a weakly referenced object is GC'd. `WeakMap` keys must be objects (weakly referenced) so they can be garbage collected if no other references exist.

**JS9** — V8 optimizes via hidden classes (object shapes) and inline caching (type checks). Deoptimization occurs if assumptions change (e.g., adding a property to an optimized object), reverting to slower execution.

**JS10** — Tree-shaking removes unused code. ESM uses static imports, allowing analysis. CJS uses dynamic `require`, preventing static analysis.
