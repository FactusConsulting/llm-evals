## .NET / C#

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
A **class** is a reference type (stored on the heap); an instance is accessed via a reference. A **struct** is a value type (usually stored on the stack or inline within its parent object) and is copied by value. 
**When to use a struct:** Use structs for small, immutable data structures that are logically grouped (e.g., `Point`, `Color`, `ComplexNumber`) and where performance gains from avoiding heap allocation outweigh the overhead of copying the value.

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
`IEnumerable<T>` is for in-memory collections; it uses "LINQ to Objects." `IQueryable<T>` is for out-of-memory data sources like databases; it uses "LINQ to SQL" (or other providers).
**Why it matters:** If you cast a database query to `IEnumerable` before filtering, the entire table might be loaded into memory first. `IQueryable` allows the LINQ provider to translate the filter into a SQL `WHERE` clause, ensuring only the necessary rows are fetched from the DB.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
`async/await` works via a state machine generated by the compiler that yields control back to the caller while waiting for an operation to complete without blocking the thread. 
A **Task** is a class allocated on the heap to represent an asynchronous operation. **ValueTask** is a struct used to represent an operation that *might* complete synchronously.
**When to use ValueTask:** Use `ValueTask` in high-performance scenarios where the method often completes synchronously (e.g., reading from a cache) and you want to avoid the allocation overhead of a `Task` object.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
DI is a design pattern where objects receive their dependencies from an external container rather than creating them internally.
1. **Transient:** Created every time they are requested.
2. **Scoped:** Created once per client request (or scope).
3. **Singleton:** Created once and live for the application lifetime.
**Common Bug:** "Captive Dependency." If you inject a Scoped service into a Singleton, the Scoped service will be held alive as long as the Singleton exists, effectively making it behave like a Singleton, which can cause memory leaks or database connection exhaustion.

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
A `string` is a heap-allocated object; slicing a string creates a new string copy. `ReadOnlySpan<char>` provides aview over a contiguous region of memory without allocating new memory. 
**When to use Span:** Use it for high-performance parsing (e.g., CSV/JSON parsers) where you need to slice strings frequently. It reduces GC pressure by avoiding unnecessary allocations on the heap.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is the Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
The GC manages memory by identifying unreachable objects. It uses **Generations**: Gen 0 (short-lived objects), Gen 1 (buffer), and Gen 2 (long-lived). The **Large Object Heap (LOH)** handles objects >85k bytes and is collected less frequently because compaction is expensive.
**IDisposable:** The GC only manages managed memory. You need `IDisposable` to manually release unmanaged resources (file handles, database connections, COM objects) that the GC cannot track directly.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
By default, `await` attempts to resume execution on the captured `SynchronizationContext` (like the UI thread or an ASP.NET request context). `ConfigureAwait(false)` tells the runtime it doesn't matter which thread resumes the method.
**When to use:** Use it in library code to avoid deadlocks and improve performance.
**When NOT to use:** Do not use it if you are updating UI elements or accessing thread-local data that requires the original context.

**DN8 — Hard: Explain the new .NET 8/9 features: primary constructors, collection expressions, and FrozenDictionary. Write a minimal example using primary constructors with DI.**
*   **Primary Constructors:** Allow defining constructor parameters directly in the class header for cleaner syntax.
*   **Collection Expressions:** New unified syntax `[1, 2, 3]` for arrays, lists, etc.
*   **FrozenDictionary:** A highly optimized read-only dictionary designed for scenarios where the dictionary is built once and read many times.

```csharp
// Example of Primary Constructor with DI
public class OrderService(IDbContext dbContext) // Primary Constructor
{
    public List<Order> GetOrders() => dbContext.Orders.ToList();
}
```

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
The likely cause is **Thread Safety**. `DbContext` is not thread-safe. Under high concurrency, multiple threads are trying to use the same instance simultaneously (likely because it was injected as a Singleton or shared across threads).
**Fix:** Ensure the `DbContext` is registered as **Scoped**. In ASP.NET Core, this ensures one instance per HTTP request. If using background tasks, you must manually create a scope (`IServiceScopeFactory`) to resolve a new context for each task execution.

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
A `record` is a class/struct that provides built-in functionality for value-based equality and non-destructive mutation (`with` expressions). A `record struct` combines the value-type behavior of a struct with the syntax of a record. 
**Choice:** Use `record` for DTOs, events, or any data-centric object where equality is based on values rather than reference identity.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
*   `ref`: The variable must be initialized before passing; the method can modify it.
*   `out`: The variable doesn't need initialization; the method *must* assign it a value. Used for returning multiple values.
*   `in`: Passes by reference but prevents the method from modifying the value (read-only reference). Useful for large structs to avoid copying costs.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
Nullable Reference Types are a compiler feature that warns you if a reference type might be null. They don't change runtime behavior—they just provide static analysis safety. Nullable Value Types (like `int?`) actually allow the underlying type to hold a `null` state via a wrapper.

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
LINQ (Language Integrated Query) allows querying data using C# syntax. 
**Method Syntax:** Uses extension methods (`.Where`, `.Select`). **Query Syntax:** More SQL-like, easier for complex joins/groupings.
**Deferred Execution:** The query isn't executed when defined; it only executes when you iterate over it (e.g., via `foreach` or `.ToList()`).

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
Constraints restrict what types can be used as a generic argument.
*   `class`: Must be a reference type.
*   `struct`: Must be a value type.
*   `new()`: Must have a public parameterless constructor.
*   `IComparable<T>`: Must implement the interface.
Combine them when needed (e.g., `where T : class, new()`) to ensure a type is both a reference type and has a default constructor.

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
An **Abstract Class** provides a base identity ("is-a") and can hold state (fields). An **Interface** defines a contract ("can-do"). 
Default Interface Methods allowed interfaces to provide implementation logic without breaking existing implementations. This narrowed the gap because interfaces can now contain code, but they still cannot store instance state (fields).

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
The pipeline is a series of components that handle requests/responses sequentially.
*   `app.Use()`: Executes logic and calls the next middleware (`next()`).
*   `app.Map()`: Branches the pipeline based on path/rules.
*   `app.Run()`: A terminal middleware; it doesn't call `next()`.
**Ordering:** Middleware executes in order. Exception handling must be at the top so it can catch errors from all subsequent middlewares.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
`Channel<T>` is a high-performance async-friendly queue. Unlike `BlockingCollection`, which blocks threads, Channels use `ValueTask` and non-blocking waits. 
**Backpressure Example:** Use a **Bounded Channel**. If the channel capacity is reached, the producer will asynchronously wait (suspend) until space becomes available, preventing the system from being overwhelmed by too many items in memory.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
Source Generators generate C# source code during compilation rather than inspecting code at runtime (Reflection) or modifying existing binaries (IL Weaving). They are safer and faster.
**Incremental Generators** cache results based on input changes. This allows the compiler to skip re-generating code if the inputs haven't changed, significantly speeding up build times compared to standard generators.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
TPL Dataflow provides "blocks" that represent units of work connected in a graph.
*   `ActionBlock`: Performs an action (e.g., save to DB).
*   `TransformBlock`: Takes input, transforms it, and passes it on.
*   `BufferBlock`: Acts as a buffer between blocks.
**Comparison:** `System.Threading.Channels` is lower-level; use it for simple producer/consumer pipes. TPL Dataflow is higher-level; use it for complex graphs with branching, joining, and sophisticated parallelism.

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**
Minimal APIs provide a way to build HTTP endpoints without the overhead of Controllers. 
**Trade-offs:** They offer better performance and less boilerplate but can become harder to organize in very large projects compared to Controller's structured approach. 
**Route Groups:** Use `.MapGroup()` to share common logic across multiple routes. **Endpoint Filters:** Allow applying logic (like Auth or Logging) specifically to certain endpoints rather than globally via middleware.

## Python

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**
A **list** is mutable; a **tuple** is immutable. A **set** is an unordered collection of unique elements; a **frozenset** is an immutable version of a set. Because `frozenset` is immutable, it is hashable and can be used as a dictionary key, whereas a regular `set` cannot.

**P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?**
The GIL is a mutex that allows only one thread to execute Python bytecode at a time. It affects **CPU-bound** tasks (e.g., heavy math), making multi-threading ineffective for speedup on multiple cores. Workarounds include using the `multiprocessing` module (separate memory spaces) or writing C extensions in Cython/C++.

**P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.**
*   `copy`: Creates a new object but inserts references to the original nested objects.
*   `deepcopy`: Recursively creates copies of all nested objects.
**Example:** If you have a list containing another list (`a = [[1]]`) and perform a shallow copy `b = a.copy()`, changing `b[0][0]` will also change `a[0][0]`.

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**
Decorators wrap a function to modify its behavior without changing its source code.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.perf_counter() - start:.4f}s")
        return result
    return wrapper
```

**P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?**
Generators use `yield` to produce values one at a time (lazy evaluation), saving memory by not storing the entire sequence in RAM. Returning a list requires allocating space for every item immediately. `yield from` is used to delegate to a sub-generator.

**P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?**
The event loop manages multiple concurrent tasks on a single thread using cooperative multitasking. 
*   `asyncio.run()` starts the loop.
*   `asyncio.gather()` runs multiple coroutines concurrently and waits for all.
*   `asyncio.create_task()` schedules a coroutine to run but doesn't wait for it.
You cannot use `time.sleep()` because it blocks the *entire thread*, stopping the event loop; you must use `await asyncio.sleep()`.

**P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**
Python uses **C3 Linearization**. In the provided code, D inherits from B then C. The order is [D, B, C, A]. Since B doesn't override `who`, it looks at its parent A. However, since C overrides `who`, and C comes before A in the search path of D, the result is "C".

**P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.**
A metaclass is a class factory—a class that creates classes. Use them for complex logic like Singleton patterns or registering types into a registry. `__init_subclass__` is a simpler way to customize class creation during subclassing without needing a full metaclass.
*   Metaclass: Implementing a custom ORM where every model needs specific behavior.
*   `__init_subclass__`: Adding a simple attribute to all subclasses automatically.

**P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?**
*   `threading`: Good for I/O-bound tasks (waiting on network).
*   `multiprocessing`: Good for CPU-bound tasks (bypasses GIL).
*   `concurrent.futures`: High-level abstraction over both. 
**Pickling:** Multiprocessing requires objects to be serialized via `pickle`. Objects containing non-serializable items (like open file handles or database connections) will crash the process.

**P10 — Medium: What is __slots__? When should you use it, and what does it prevent? What is the memory impact?**
`__slots__` tells Python not to create a `__dict__` for instances of a class. It prevents dynamic attribute assignment but significantly reduces memory usage by allocating only enough space for specified attributes. Use this when creating millions of small objects.

**P11 — Easy: What is a virtual environment, and why should you use one? What is the difference between venv, virtualenv, and conda?**
Virtual environments isolate project dependencies so different projects can have conflicting versions of libraries.
*   `venv`: Standard library tool for envs.
*   `virtualenv`: Older, more feature-rich version of venv.
*   `conda`: A package/environment manager that handles non-Python dependencies (C++ libs, etc.).

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?**
Comprehensions are "Pythonic" ways to build collections in a single line. They are generally faster than `map()` or `filter()` because they avoid function call overhead inside the loop. Prefer comprehensions for readability; use `map`/`filter` if you already have an existing function to apply.

**P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?**
`==` checks value equality; `is` checks identity (memory address). **Interning** is when Python reuses the same memory for common objects like short strings or small integers (-5 to 256) to save space. This is why `a = 10; b = 10; a is b` returns `True`.

**P14 — Easy: Explain Python's *args and **kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?**
*   `*args`: Collects extra positional arguments into a tuple.
*   `**kwargs`: Collects extra keyword arguments into a dictionary.
*   `/`: Arguments before this must be positional only.
*   `*`: Arguments after this must be passed as keywords.

**P15 — Easy: What are context managers (with statement)? How do you write one using __enter__/__exit__ vs @contextmanager? Give an example beyond file handling.**
Context managers ensure resources are cleaned up (e.g., closing a DB connection). You can use the class method (`__enter__`/`__exit__`) or the `@contextmanager` decorator which uses a generator with `yield`. Example: A database transaction manager that commits on success and rolls back on error.

**P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How does mypy or pyright use these for static analysis?**
Type hints provide metadata about types without affecting runtime behavior. 
*   `Union[int, str]`: Either int or string.
*   `Optional[int]`: `int | None`.
*   `Literal["A", "B"]`: Must be exactly "A" or "B".
*   `TypeVar`: Generic variables.
*   `Protocol`: Structural subtyping (Static Duck Typing).
Mypy/Pyright analyze code to find type mismatches before execution.

**P17 — Medium: Explain Python's data model (dunder methods). What are __repr__ vs __str__, __eq__ vs __hash__, and __getattr__ vs __getattribute__? What happens if you define __eq__ but not __hash__?**
Dunder methods allow objects to hook into built-in behaviors.
*   `__repr__`: Developer-facing string representation.
*   `__str__`: User-friendly string.
*   `__eq__`: Equality logic; `__hash__`: Hashability for sets/dicts.
If you define `__eq__` but not `__hash__`, the object becomes unhashable because it can no longer guarantee a stable hash value based on its equality rules.

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (__get__, __set__, __delete__). How do property, classmethod, and staticmethod use descriptors under the hood?**
Descriptors are objects that define how attribute access (`obj.attr`) behaves. The protocol involves `__get__`, `__set__`, and `__delete__`. 
Properties are "data descriptors" (they have `__set__`). `classmethod` and `staticmethod` are also descriptors; they intercept the lookup process to ensure they are called on the class rather than the instance.

**P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, __init__.py, and namespace packages work? What is a finder and a loader?**
Python searches `sys.path` (which includes `PYTHONPATH`) to find modules. **Absolute:** Full path from root. **Relative:** Relative to current package (requires `.` or `..`). `__init__.py` marks directories as packages. **Namespace Packages** allow multiple directories/packages to share one name without an `__init__.py`. A **Finder** locates the module file; a **Loader** actually executes it into memory.

**P20 — Hard: What is dataclasses and how does it compare to attrs and Pydantic? Explain __post_init__, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**
Dataclasses provide boilerplate-free classes for data storage. 
*   `__post_init__`: Logic run after initialization.
*   `field(default_factory=...)`: Used for mutable defaults like lists.
*   `frozen=True`: Makes instances immutable.
Inheritance works by inheriting fields and methods. Choose **Pydantic** when you need runtime validation, serialization (JSON), or complex nested schema enforcement that standard dataclasses don't handle natively.
