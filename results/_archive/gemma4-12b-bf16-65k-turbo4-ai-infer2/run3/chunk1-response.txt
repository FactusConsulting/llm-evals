## Networking

**N1 — Easy: What is the difference between a Layer 2 switch and a Layer 3 switch?**
A Layer 2 switch operates at the Data Link layer and forwards frames based on MAC addresses using a CAM table. A Layer 3 switch operates at the Network layer; it performs standard switching functions but also possesses routing capabilities, allowing it to forward packets based on IP addresses using a routing table.

**N2 — Easy: A host has IP 10.0.5.37/20. What is the network address and broadcast address?**
The mask /20 means the first 20 bits are the network prefix. In the third octet, this corresponds to increments of 16 ($2^4$). Since .5 falls within the range of $10.0.0.0$ to $10.0.15.255$:
*   **Network Address:** 10.0.0.0
*   **Broadcast Address:** 10.0.15.255

**N3 — Medium: Explain the TCP three-way handshake. What happens if the final ACK is lost?**
The process is: Client sends **SYN**, Server responds with **SYN-ACK**, Client sends **ACK**. If the final ACK is lost, the server will not receive confirmation that the connection is established. The server will keep the connection in a "half-open" state (SYN_RECV) until it times out or retransmits the SYN-ACK. The client, having sent its ACK, believes the connection is open.

**N4 — Medium: What is the difference between SNAT and DNAT? Give a practical example of each.**
*   **SNAT (Source NAT):** Changes the source IP of an outgoing packet. *Example:* Multiple internal users accessing the internet through a single public gateway.
*   **DNAT (Destination NAT):** Changes the destination IP of an incoming packet. *Example:* A web server sitting behind a Load Balancer where traffic hits the LB's public IP but is routed to a private backend IP.

**N5 — Medium: You run `curl -v https://example.com` and get `SSL: certificate subject name does not match target host name`. List 3 possible causes.**
1.  The certificate was issued for a different domain (e.g., `example.net`).
2.  You are accessing the site via an IP address instead of the FQDN specified in the cert.
3.  A proxy/load balancer is presenting a certificate meant for a different internal service.

**N6 — Medium: Explain the difference between a VLAN and a VxLAN. When would you choose VxLAN over VLAN?**
VLANs are Layer 2 segments limited by the 802.1Q header, which allows only 4,096 IDs and requires physical proximity or complex spanning-tree setups. VxLAN is an overlay technology that encapsulates L2 frames into UDP packets (Layer 3), allowing for millions of segments across a routed infrastructure. Choose VxLAN for large-scale data centers or multi-tenant clouds.

**N7 — Hard: A Linux host has two NICs... Traffic arriving on eth1 from 192.168.1.0/24 is being replied via eth0. Why, and how do you fix it with policy-based routing?**
This is **Asymmetric Routing**. The default gateway points to eth0, so the kernel chooses eth0 as the return path regardless of the ingress interface. To fix this, use `ip rule` to create a specific route based on the source IP:
1. Create a new routing table (e.g., `table 100`).
2. Add a route in that table: `ip route add default via 192.168.1.1 dev eth1 table 100`.
3. Add a rule: `ip rule add from 192.168.1.0/24 lookup 100`.

**N8 — Hard: Explain how BGP path selection works. List at least 5 attributes in the correct order of preference.**
BGP selects the best path by evaluating attributes in a specific hierarchy. If there is a tie, it moves to the next attribute. Order:
1. Weight (Cisco proprietary)
2. Local Preference
3. AS_Path Length
4. Origin Type
5. MED (Multi-Exit Discriminator)

**N9 — Hard: What is the MTU implication of running VxLAN over an IPsec tunnel? Show the math for the maximum inner payload if the physical MTU is 1500.**
VxLAN adds ~50 bytes; IPsec adds ~50–70+ bytes depending on encryption mode and headers. Total overhead $\approx$ 120 bytes.
*   Physical MTU = 1500.
*   Overhead = 120.
*   Max Inner Payload = $1500 - 120 = 1380$ bytes. To avoid fragmentation, you must set the MSS (Maximum Segment Size) accordingly.

**N10 — Medium: What is the purpose of ARP, and what problem does Gratuitous ARP solve?**
ARP maps Layer 3 IP addresses to Layer 2 MAC addresses. **Gratuitous ARP** is an unsolicited ARP response used by a host to announce its IP/MAC mapping to the network. It solves two problems: detecting IP address conflicts and updating the ARP caches of neighboring devices when a failover occurs (e.g., VRRP/HSRP).

**N11 — Easy: What is the difference between a public IP address and a private IP address? List the three private IPv4 ranges defined in RFC 1918.**
Public IPs are globally unique and routable on the internet. Private IPs are for internal use only and are not routable over the public internet.
RFC 1918 Ranges:
1.  `10.0.0.0 – 10.255.255.255`
2.  `172.16.0.0 – 172.31.255.255`
3.  `192.168.0.0 – 192.168.255.255`

**N12 — Easy: What is DNS, and what is the difference between an A record, a CNAME record, and an AAAA record?**
DNS translates human-readable names to IP addresses.
*   **A:** Maps a name to an **IPv4** address.
*   **CNAME:** An alias that points one domain name to another (e.g., `www` $\rightarrow$ `example.com`).
*   **AAAA:** Maps a name to an **IPv6** address.

**N13 — Easy: What is DHCP, and what four-step process (DORA) does a client use to obtain an IP address from a DHCP server?**
DHCP automatically assigns dynamic IPs to hosts. The DORA process is:
1. **D**iscover (Client broadcasts to find a server).
2. **O**ffer (Server offers an IP).
3. **R**equest (Client requests that specific IP).
4. **A**cknowledge (Server confirms the lease).

**N14 — Easy: What is the difference between a hub, a switch, and a router? At which OSI layer does each primarily operate?**
*   **Hub:** Layer 1 (Physical). Broadcasts all incoming data to all ports.
*   **Switch:** Layer 2 (Data Link). Forwards frames based on MAC addresses.
*   **Router:** Layer 3 (Network). Forwards packets based on IP addresses.

**N15 — Easy: Explain the difference between half-duplex and full-duplex communication. Which mode do modern Ethernet links use?**
Half-duplex allows communication in both directions but only one at a time (like a walkie-talkie). Full-duplex allows simultaneous two-way communication. Modern Ethernet uses **full-duplex**.

**N16 — Medium: What is the purpose of the TTL field in an IP packet? How does traceroute exploit it to map the network path?**
TTL prevents packets from looping infinitely by decrementing with every hop; if it hits 0, the packet is dropped. `traceroute` sends packets with increasing TTL values (1, 2, 3...). Each router along the path decrements the TTL and returns an ICMP "Time Exceeded" message, allowing the tool to identify each hop's IP.

**N17 — Medium: Explain what a NAT gateway does. What is the difference between static NAT, dynamic NAT, and PAT (port address translation)?**
A NAT gateway translates private IPs to public IPs for internet access.
*   **Static NAT:** One-to-one mapping (Private $\leftrightarrow$ Public) - used for hosting servers.
*   **Dynamic NAT:** Maps internal IPs to a pool of public IPs on a first-come, first-served basis.
*   **PAT (Port Address Translation):** Many-to-one mapping using different source ports to allow multiple hosts to share one public IP.

**N18 — Hard: Explain how ECMP (Equal-Cost Multi-Path) routing works. What hashing strategies are commonly used, and what problems can arise with asymmetric flows when stateful firewalls are involved?**
ECMP allows a router to split traffic across multiple paths with equal costs. It uses hashing algorithms based on the **5-tuple** (Source/Dest IP, Source/Dest Port, Protocol). If a firewall is stateful, it expects both directions of a flow to pass through the same firewall instance; if ECMP hashes the return path differently than the outgoing path, the firewall will drop the "out-of-state" packet.

**N19 — Hard: A TCP connection between two hosts shows high latency but packet captures show no drops... Explain the problem and how TCP window scaling (RFC 1323) solves it.**
The Bandwidth-Delay Product (BDP) determines the maximum amount of data that can be in flight. If BDP > 64KB (the default max window size), the sender must stop and wait for ACKs before sending more, capping throughput regardless of bandwidth. RFC 1323 introduces a "Window Scale" factor, allowing the window size to exceed 64KB by using a multiplier.

**N20 — Hard: Describe how 802.1Q trunk ports work. A server with a single NIC needs to communicate on VLANs 10, 20, and 30. Explain how to configure this on Linux using sub-interfaces and what the frame format looks like on the wire.**
Trunk ports carry traffic for multiple VLANs by adding an 802.1Q tag (VLAN ID) to the Ethernet frame header. On Linux, you create virtual interfaces: `eth0.10`, `eth0.20`, etc., which are bound to the physical `eth0`. The frame on the wire includes a **TPID** (Tag Protocol Identifier) and a **TCI** (Tag Control Information) field containing the VLAN ID.

## Linux

**L1 — Easy: What is the difference between a hard link and a symbolic link?**
A hard link points directly to the inode (the data on disk); creating one doesn't change the file count but adds a name. A symbolic link (symlink) is a separate file that contains the path to another file; deleting the original file breaks the symlink.

**L2 — Easy: How do you find all files larger than 100MB under /var/log?**
`find /var/log -type f -size +100M`

**L3 — Medium: A process is in state D (uninterruptible sleep). What does this mean, and can you kill it with kill -9?**
State D means the process is waiting for an I/O operation (like a hung NFS mount or failing hardware) and cannot be interrupted by signals. You **cannot** kill it with `kill -9`; it will only die once the kernel returns from the system call.

**L4 — Medium: Explain the difference between cgroups v1 and cgroups v2. Which does systemd prefer and why?**
cgroups v1 used separate hierarchies for different controllers (memory, CPU, etc.). cgroups v2 uses a unified hierarchy where all controllers are shared. Systemd prefers **v2** because it provides better resource accounting and consistent behavior across all subsystems.

**L5 — Medium: What is the difference between nftables and iptables? How does the kernel handle both simultaneously?**
nftables is the successor to iptables; it has its own bytecode and engine. The kernel handles both via the `iptables-nft` abstraction layer, which translates legacy iptables commands into nftables expressions.

**L6 — Medium: You run `df -h` and see a filesystem at 100%, but `du -sh /*` totals far less. What is the most likely cause?**
The most common reason is that there are **deleted files still held open** by active processes. Since the file descriptor is still open, the space isn't reclaimed until the process closes it or terminates.

**L7 — Hard: Explain the Linux boot process...**
1.  **Firmware:** UEFI initializes hardware and loads the Boot Manager.
2.  **Bootloader:** GRUB/systemd-boot loads the Kernel and Initramfs.
3.  **Kernel:** Initializes drivers and mounts the temporary root.
4.  **Initramfs:** Provides necessary drivers (e.g., for RAID/NFS) to mount the real root FS.
5.  **Root FS:** Systemd (PID 1) starts up and takes over management of all services.

**L8 — Hard: A server has 64GB RAM but only 2GB swap... The OOM killer fires. Explain why available can be low even with high buff/cache, and what kernel tunables affect this behavior.**
"Available" memory accounts for physical RAM minus the amount needed for "dirty" pages and non-reclaimable cache. If a process requests a large contiguous block, the kernel may fail to find it despite having free space. Tunables include `vm.min_free_kbytes` (minimum reserved) and `vm.swappiness` (how aggressively to swap).

**L9 — Medium: What does `ip netns` do, and how is it used by container runtimes?**
It manages **Network Namespaces**, which isolate network stacks (interfaces, routing tables, IP addresses). Container runtimes (like Docker/Podman) use these namespaces to give each container its own isolated network environment.

**L10 — Medium: Explain the difference between SIGTERM, SIGKILL, and SIGQUIT. Which can be caught by the process?**
*   **SIGTERM:** Request to terminate; the process can catch this and perform cleanup.
*   **SIGQUIT:** Requests termination and produces a core dump; can be caught.
*   **SIGKILL:** Immediate forced kill; **cannot** be caught or ignored by the process.

**L11 — Easy: What is the difference between stdout, stderr, and stdin? How do you redirect stderr to a file while still displaying stdout on the terminal?**
Stdout = standard output, Stderr = error output, Stdin = standard input.
To redirect only stderr to a file: `command 2> error.log`

**L12 — Easy: What does the chmod 755 command do? Explain what each digit represents.**
The digits represent permissions for [Owner][Group][Others].
*   **7 (4+2+1):** Owner has Read, Write, Execute.
*   **5 (4+1):** Group has Read, Execute.
*   **5 (4+1):** Others have Read, Execute.

**L13 — Easy: What is the difference between the root user and a user with sudo privileges?**
The root user is the superuser with unrestricted access to all files and commands. A user with sudo privileges is a normal user who can execute specific commands as root based on rules defined in `/etc/sudoers`.

**L14 — Easy: What is a package manager? Name the default package managers for Debian/Ubuntu and RHEL/Fedora.**
A tool used to install, update, and remove software packages.
*   Debian/Ubuntu: **APT** (Advanced Package Tool).
*   RHEL/Fedora: **DNF** (or YUM).

**L15 — Easy: What is the /etc/fstab file used for? What happens if an entry is misconfigured?**
It defines how disk partitions are mounted at boot time. If misconfigured (e.g., wrong UUID or incorrect mount options), the system may hang during boot or fail to mount critical volumes like `/` or `/home`.

**L16 — Medium: Explain what LVM (Logical Volume Manager) is... how do you extend a logical volume on a running system?**
LVM abstracts physical storage into Logical Volumes. 
*   **PV:** Physical partition/disk.
*   **VG:** Pool of PVs.
*   **LV:** Slice of a VG.
To extend: `lvextend -L +2G /dev/vg0/lv_name` followed by `resize2fs /dev/vg0/lv_name` (for ext4) or `xfs_growfs /mountpoint` (for XFS).

**L17 — Hard: Explain how the Linux kernel's I/O scheduler works. Compare mq-deadline, bfq, and none schedulers.**
Schedulers manage the order in which I/O requests are sent to the block device.
*   **mq-deadline:** Good for low latency; prioritizes reads over writes.
*   **bfq:** Fair queuing; good for desktop responsiveness.
*   **none:** No scheduling; used for NVMe/SSDs where hardware handles parallelism.
Change at runtime: `echo "none" > /sys/block/sda/queue/scheduler`.

**L18 — Hard: A system is experiencing intermittent high load averages but CPU usage is low... Explain what load average actually measures on Linux, why I/O wait can inflate it, and how you would diagnose whether the bottleneck is CPU, disk, or network using standard tools.**
Load average measures processes in a **runnable state** (R) OR **uninterruptible sleep** (D). High load with low CPU % usually means many processes are stuck in D state waiting for I/O. 
Diagnosis: Use `iostat` or `iotop` for Disk, `top`/`uptime` for Load, and `sar -n NetDev` for Network.

**L19 — Hard: Explain how SELinux enforces mandatory access control. What is the difference between enforcing, permissive, and disabled modes? How do you troubleshoot a daemon that fails to bind a non-standard port due to SELinux policy?**
SELinux uses security contexts to restrict process actions based on central policies.
*   **Enforcing:** Policy is active; violations are blocked.
*   **Permissive:** Policy is active; violations are logged but allowed.
*   **Disabled:** Policy is off entirely.
Troubleshooting: Check `/var/log/audit/audit.log`, then use `audit2allow --system` to generate a custom policy module for the specific daemon.

**L20 — Hard: Describe how the Linux kernel's virtual memory subsystem handles page faults... Difference between minor and major page fault? How does transparent huge pages (THP) affect application performance, and when would you disable it?**
A **Page Fault** occurs when a program tries to access a page not currently in physical RAM. 
*   **Minor:** Page is in RAM but not mapped to the process's MMU. Fast fix.
*   **Major:** Page must be fetched from disk. Slow operation.
**THP** groups small pages into large blocks (e.g., 2MB). It reduces TLB misses but can cause "stalls" during allocation or high fragmentation. Disable THP if an application shows high tail latency or jitter.
