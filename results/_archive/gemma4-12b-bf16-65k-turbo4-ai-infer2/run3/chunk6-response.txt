## JavaScript / TypeScript

**JS1 — Easy:** `var` is function-scoped and can be re-declared; `let` and `const` are block-scoped. `const` prevents reassignment of the variable identifier itself (but not the contents of objects/arrays). **Hoisting** is the behavior where variable and function declarations are moved to the top of their containing scope during the compilation phase before execution.

**JS2 — Easy:** The event loop allows JS to perform non-blocking I/O despite being single-threaded. The **Call Stack** handles synchronous code. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority than the **Macrotask Queue** (`setTimeout`, `setInterval`). After every macrotask, the engine clears the entire microtask queue before moving to the next macrotask.

**JS3 — Medium:** A closure is a function that "remembers" its lexical scope even when executed outside that scope. Example: A private counter function returning an incrementer. The classic bug occurs in `for` loops using `var` inside a `setTimeout`. Fix: Use `let`, which creates a new binding for each iteration.

**JS4 — Medium:** Promises represent eventual completion of an async operation. `async/await` provides syntactic sugar over Promises. Error handling uses `.catch()` or `try/catch`. `Promise.all` rejects if *any* promise fails; `Promise.allSettled` waits for all promises to finish regardless of success or failure.

**JS5 — Medium:** Interfaces are primarily for defining object shapes and support declaration merging. Types can define primitives, unions, and aliases. Use **Interfaces** for public APIs/objects; use **Types** for complex logic like Unions. **Discriminated Unions** use a common literal property (e.g., `type: 'success'`) to allow type narrowing via switch statements.

**JS6 — Medium:** Prototypal inheritance means every object has a prototype link (`__proto__`). `Object.create(proto)` creates a new object with a specific prototype. ES6 classes are not "real" classes but syntactical sugar over the existing prototypal system.

**JS7 — Hard:** `this` refers to the execution context. Binding rules in priority order: 1. (New), 2. Explicit (`call`/`apply`/`bind`), 3. Implicit (Method call), 4. Default (Global/Undefined). `bind()` returns a *new* function; once bound, it cannot be re-bound.

**JS8 — Hard:** `WeakRef` allows holding a weak reference to an object that doesn't prevent garbage collection (GC). `FinalizationRegistry` allows running a callback after an object is GC'd. `WeakMap` keys must be objects because they don't hold strong references, allowing the engine to reclaim memory when no other references exist.

**JS9 — Hard:** V8 uses **Hidden Classes** (shapes) to track object structures and **Inline Caching** to speed up property access by remembering previous results. **Deoptimization** occurs when code becomes "megamorphic" (too many different shapes for one call site). Patterns causing this include changing object shapes dynamically or using arrays as maps.

**JS10 — Medium:** Tree-shaking removes unused exports from the final bundle. It works via static analysis of ES Modules (`import/export`). CommonJS (`require`) is dynamic—it can execute arbitrary logic during import—making it nearly impossible for compilers to determine what is actually used at build time.

**JS11 — Easy:** `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion (e.g., `null == undefined` is true); `===` checks strict equality. Nullish coalescing (`??`) returns right side if left is null/undefined. Optional chaining (`?.`) allows safe access to nested properties that might be null/undefined.

**JS12 — Easy:** `map()` transforms every element into a new array; `filter()` selects elements based on a predicate; `reduce()` accumulates values into a single result. If no initial value is provided, `reduce` uses the first element as the accumulator. `flatMap()` applies a map and flattens the result by one level, useful for operations returning multiple results per input.

**JS13 — Easy:** Template literals use backticks (\`) and `${}` for interpolation. **Tagged templates** allow passing the template string to a function, enabling custom logic like HTML escaping or SQL query parameterization before rendering.

**JS14 — Easy:** Destructuring extracts values from arrays/objects into distinct variables. Object destructuring: `{name} = obj`. Array destructuring: `[a, b] = arr`. Default values: `const {x = 10} = obj`. Rest operator (`...`) collects remaining items into an array/object.

**JS15 — Easy:** `for...in` iterates over all enumerable *properties* (keys) of an object (including inherited ones). `for...of` iterates over *values* of an iterable. Avoid `for...in` on arrays because it may return non-index properties or prototype methods.

**JS16 — Medium:** Generics allow creating reusable components with type safety. **Constraints** (`T extends Base`) limit what types can be passed. **Conditional Types** act like ternary operators at the type level. `infer` allows extracting types from expressions (e.g., getting the return type of a Promise's `.then()` block).

**JS17 — Medium:** CommonJS is synchronous and uses `module.exports`/`require`. ES Modules are static, support top-level await, and use `import`/`export`. Node.js handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM.

**JS18 — Hard:** TS uses structural typing (if it looks like a duck, it's a duck). Excess property checks only occur during literal assignments. `extends` defines inheritance requirements; `satisfies` validates that a value matches a type without widening its inferred type. Variance describes how subtyping behaves under different positions (Input vs Output).

**JS19 — Hard:** `Proxy` intercepts operations (get/set/has) on an object. `Reflect` provides the mirror API for those same operations. Example: A Proxy can intercept a `set` operation to validate that a user's age remains within a specific range before updating state.

**JS20 — Hard:** `SharedArrayBuffer` allows multiple threads (Web Workers) to share memory. `Atomics` provide thread-safe operations (like `add`, `wait`, `notify`) to prevent race conditions. Web Workers communicate via `postMessage` or by reading/writing to shared buffers using atomic instructions.

## Bash

**B1 — Easy:** `$@` expands to all arguments as separate quoted strings (safer); `$*` expands all arguments as a single string joined by spaces. Use `"$@"` to preserve spaces in filenames.

**B2 — Easy:** `-e`: Exit immediately if a command fails. `-u`: Treat unset variables as errors. `-o pipefail`: Ensure the exit code of a pipeline is the highest non-zero exit code of any command in the pipe.

**B3 — Medium:** `$(command)` and `` `command` `` are both command substitutions; the latter is deprecated. `((expression))` evaluates arithmetic expressions and returns 0 if true; `expr` is an external utility used for basic math but is slower than built-in arithmetic.

**B4 — Medium:** Process substitution `<(command)` makes the output of a command look like a file descriptor. Example: `diff <(ls dir1) <(ls dir2)` allows comparing two dynamic outputs without creating temporary files.

**B5 — Medium:** Use `find -print0 | xargs -0`. This handles special characters because it uses null bytes as delimiters instead of whitespace/newlines. `for f in $(ls)` is dangerous because it splits on spaces, breaking paths with spaces into multiple items.

**B6 — Easy:** Here Doc (`<<EOF`) captures multi-line input until a delimiter. Here String (`<<<`) treats content as literal strings (no expansion). `<<-EOF` strips leading tabs from the here doc block.

**B7 — Hard:**
1. `cmd > file 2>&1`: Redirects stdout to file, then stderr to where stdout *was* (terminal). Result: Stderr goes to terminal.
2. `cmd 2>&1 > file`: Redirects stderr to stdout, then stdout to file. Result: Both go to file.
3. `cmd &> file`: Shorthand for both going to file.

**B8 — Hard:** Using `mkdir` for locking is preferred because `mkdir` is an atomic operation at the filesystem level; if the directory exists, it fails immediately. A script should use `trap 'rm -f /tmp/lock' ERR INT TERM` to ensure cleanup.

**B9 — Easy:** Single quotes ('...') are literal (no interpolation); Double quotes ("...") allow variable expansion and command substitution; No quotes treat words as separate arguments and perform globbing/word splitting. Example: `echo "Value: $x"` vs `echo 'Value: $x'`.

**B10 — Easy:** `-f` checks files, `-d` directories, `-r` readability. `[ ]` is the standard POS1 test; `[[ ]]` is a Bash extension that supports regex (`=~`), logical operators (`&&`, `||`), and handles word splitting more safely.

**B11 — Easy:** `$?` last exit code; `$$` current PID; `$!` PID of last background job; `$#` number of positional parameters passed to the script.

**B12 — Easy:** Functions can be defined with `foo() {}` or `function foo {}`. To return values, you must capture the output via subshell: `result=$(foo)`.

**B13 — Easy:** PATH defines where shell looks for executables. Shells check builtins first, then PATH. Use `type -p <cmd>` to see if it's a builtin; use `which <cmd>` to find external paths.

**B14 — Medium:** `trap` catches signals (SIGINT, SIGTERM). Set up handlers using `trap 'cleanup_func' SIGNAL`. When multiple signals arrive simultaneously, they are handled sequentially based on signal priority/handling logic in the kernel.

**B15 — Medium:** Command substitution runs once per line (slow); `xargs` processes streams efficiently. `xargs -P N` allows parallel execution of $N$ processes. Use `-0` with `find -print0` to handle filenames containing newlines/spaces correctly.

**B16 — Medium:** Arrays: `arr=(a b c)`; length `${#arr[@]}`. Associative arrays: `declare -A map`; `map[key]=val`. Iteration uses `${!map[@]}` for keys and `${map[@]}` for values. Length is `${#map[@]}`.

**B17 — Hard:** Subshell `(...)` creates a child process; variables changed inside do not persist outside. Grouping `{ ...; }` stays in the current shell. Piping into a while loop (`cmd | while...`) puts the loop in a subshell, meaning any variable updates inside the loop disappear when the pipe finishes.

**B18 — Hard:** Signals: SIGINT (Ctrl+C), SIGTERM (standard kill), SIGHUP (terminal closed), SIGKILL (forceful). For graceful shutdown, use `trap` on TERM/INT to send signals to background jobs using `jobs -p` or `kill 0`.

**B19 — Hard:** Script logic: `split -l 1000 logfile > chunk_*.log`, then `ls chunk_*.log | xargs -P 4 -n 1 processing_func`, finally `cat result_* > final.log`. Error propagation requires checking `$?` within the parallel function and logging failures to an error file.

**B20 — Hard:** `exec` replaces the current shell process with another command. File descriptors: `exec 3>file` opens FD 3 for writing. A coprocess is created via `coproc my_cmd`, providing two-way communication between the script and the command's stdin/stdout.

## PowerShell

**PS1 — Easy:** `Write-Output` sends objects down the pipeline; `Write-Host` sends text directly to the console host. Using `Write-Host` inside a pipeline breaks the flow of data because it doesn't pass objects forward.

**PS2 — Easy:** The pipeline passes objects from left to right. `ForEach-Object` (the cmdlet) processes items one by one in the pipeline (slow but handles streaming). `foreach ($x in $y)` is a language statement that loads all items into memory first (faster for small sets).

**PS3 — Medium:** `[hashtable]` is a key-value map; `[PSCustomObject]` allows property access (`$obj.Prop`) and behaves like a real object. Convert using `[pscustomobject]@{Key=Value}`.

**PS4 — Medium:** Terminating errors stop execution; non-terminating do not. `-ErrorAction Stop` converts non-terminating errors into terminating ones so they can be caught by `try/catch`. `$ErrorActionPreference` sets the global default behavior.

**PS5 — Medium:** Splatting uses a hashtable to pass parameters: `@params = @{Path="C:\"; Name="Test"}; Get-Item @params`. This is cleaner than long command lines and more readable than passing a single hashtable as an argument, which might be misinterpreted as a single string value.

**PS6 — Medium:** `Invoke-Command` runs a script block on a remote machine once. `Enter-PSSession` provides an interactive shell. Both use WinRM (WSMan) or SSH (in PS7+).

**PS7 — Hard:** PowerShell's pipeline returns objects. If a function returns one item, it's that object; if zero, it's null; if multiple, it's an array. The prompt example results in a `System.Object` because of how types are inferred. Correct pattern: Always cast the return type explicitly or ensure the function always returns an array using `@()`.

**PS8 — Hard:** A ScriptBlock is a code block passed as data; a Function is a named entity with scope. Double-hop occurs when a remote server cannot access a third server because credentials aren't forwarded. Solve via CredSSP or by passing specific arguments/data rather than full credentials.

**PS9 — Easy:** `@()` creates an array literal; `[array]` declares a type. Force a single result into an array using `$a += $val`. Indexing into `$null` usually returns nothing but can cause errors depending on the version and context.

**PS10 — Easy:** `-like` uses wildcards (`*`, `?`); `-match` uses Regex. Case sensitivity variants like `-ceq` enforce strict casing. `-contains` checks if a collection contains a value; `-in` checks if a value exists within a collection (conceptually similar but different syntax).

**PS11 — Easy:** `.psm1` is a script module; `.psd1` is a manifest file containing metadata (version, requirements); binary modules are compiled DLLs. `Import-Module` loads these into the current session.

**PS12 — Easy:** Interpolation: `"Value: $var"`. Single quotes '...' prevent interpolation. Here-string: `@ "..." @` allows multi-line strings without escaping internal quotes.

**PS13 — Easy:** `Get-Member` shows properties (data), methods (actions), and NoteProperties (metadata). `Select-Object` filters which *properties* of an object pass through; `Where-Object` filters which *objects* themselves pass through.

**PS14 — Medium:** PowerShell classes are C#-based objects with inheritance/interfaces. They have stricter typing than functions. Use Classes for complex state management or when needing to model data structures that require specific types across multiple scripts.

**PS15 — Medium:** `[CmdletBinding()]` enables standard parameters like `-Verbose`, `-WhatIf`, and `-Confirm`. `SupportsShouldProcess` adds `-WhatIf`. Begin/Process/End blocks handle streaming input—`Process` runs once per item in the pipeline, while `Begin`/`End` run at start/finish.

**PS16 — Medium:** Providers allow PS to treat different sources (Registry, Filesystem) as similar objects. `Get-ChildItem` uses provider-specific cmdlets. Access registry via `Get-Item HKCU:\Software\...`.

**PS17 — Hard:** Runspaces provide isolated threads of the engine. A [runspacepool] manages a pool of these. ForEach-Object -Parallel (v7+) is the modern way to achieve parallelism without manually managing thread safety or runspace lifecycle.

**PS18 — Hard:** PSScriptAnalyzer checks code against best practices. Rules have severity levels (Warning, Error). Suppress rules using `#PSCmdlet` or custom attributes. Integrate into CI/CD by running it during the build/test phase to fail builds on errors.

**PS19 — Hard:** `$using:` injects local variables into remote sessions; `$args` passes values explicitly. Serialization limits: CLIXML depth can cause issues with very deep object trees (e.g., deeply nested arrays), requiring flattening before passing.

**PS20 — Hard:** DSC defines "Desired State" for infrastructure. LCM (Local Configuration Manager) enforces that state. Difference: Windows PowerShell was more manual; PS7+ focuses on cross-platform and integrates better with tools like Terraform/Ansible for cloud resources while keeping DSC for OS configuration.
