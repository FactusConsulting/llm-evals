## Go

**G1 — Easy:** An **array** has a fixed length; its size is part of its type. A **slice** is a descriptor containing a pointer to an underlying array, a length, and a capacity. When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array, copies the existing elements over, and returns a new slice header pointing to this new memory.

**G2 — Easy:** `var x int` declares a variable with the zero value (`0`) in the current scope. `x := 0` uses short variable declaration to declare and initialize `x`. You cannot use `:=` in the global scope or if the variable name is already declared in the same block/scope.

**G3 — Medium:** A **goroutine** is a lightweight thread managed by the Go runtime, not the OS. It starts with a small stack (approx 2KB) that grows as needed. The **GMP model** consists of: **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts). The scheduler maps Gs onto Ms via Ps to balance load across CPU cores efficiently.

**G4 — Medium:** Channels are typed conduits for communication. **Unbuffered channels** block the sender until a receiver is ready; **Buffered channels** allow sending until the buffer is full. Sending to a full buffered channel blocks the goroutine until space becomes available.

**G5 — Medium:** The `context` package manages deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
func doRequest(ctx context.Context) {
    ctx, cancel := context.WithTimeout(ctx, 2*time.Second)
    defer cancel() // Ensure resources are freed
    req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
    // ... execute request
}
```

**G6 — Medium:** Go uses **implicit satisfaction**: if a type implements all methods in an interface, it satisfies it automatically. Java/C# require explicit `implements`. `interface{}` (or `any`) can hold any value but loses type safety, requiring type assertions or reflection, which can lead to runtime panics if not handled carefully.

**G7 — Hard:** This is unsafe because there is no synchronization between the goroutine writing to `ready` and the main loop reading it. The compiler/CPU might reorder instructions or cache the value of `ready`, leading to an infinite loop or reading stale data. Correct alternatives include using `sync.WaitGroup`, `channels`, or `atomic.Bool`.

**G8 — Hard:** `sync.Mutex` allows only one owner; `sync.RWMutex` allows multiple readers OR one writer. Use `sync.Map` for high-concurrency scenarios with many reads and few writes where keys are stable. A regular map + Mutex is often faster for low contention or write-heavy workloads due to less internal overhead.

**G9 — Hard:** `go.mod` defines the module's dependencies and version requirements; `go.sum` contains cryptographic hashes to ensure dependency integrity. `go mod tidy` removes unused modules and adds missing ones. **MVS (Minimum Version Selection)** is the algorithm Go uses to resolve conflicting versions by selecting the highest minimum version required by all dependencies.

**G10 — Medium:** `defer` schedules a function call to run immediately before the surrounding function returns. They execute in LIFO (Last-In, First-Out) order. A common gotja: if you use `defer` inside a loop that runs many times, the deferred functions won't run until the *entire* function finishes, potentially causing memory/resource leaks.

**G11 — Easy:** A pointer holds the memory address of a value. The zero value of a pointer is `nil`. You create a pointer to a struct literal using the address-of operator: `p := &MyStruct{Field: 1}`.

**G12 — Easy:** `init()` runs automatically before `main()`. It can be defined in multiple files within a package; they execute in lexical order (alphabetical file name). Package initialization follows a dependency graph order.

**G13 — Easy:** `new(T)` allocates memory for type `T`, zeroes it, and returns a pointer (`*T`). `make(T, args)` initializes internal structures for slices, maps, and channels and returns an initialized value of type `T`. Only slices, maps, and channels work with `make`.

**G14 — Easy:** Go treats errors as values. The `error` interface has one method: `Error() string`. Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error matches a specific instance (like `io.EOF`); `errors.As` checks if an error matches a specific type (type assertion). Both are safer than `==` because they handle wrapped errors.

**G15 — Easy:** Composite types: **Map** (zero: `nil`), **Slice** (zero: `nil`), **Channel** (zero: `nil`), **Struct** (zero: all fields at zero value). Note: Reading from/writing to a `nil` map causes panic, but writing to a `nil` slice is allowed via `append`.

**G16 — Medium:** A race condition occurs when two goroutines access the same memory concurrently and at least one is a write. `-race` uses instrumentation to detect these at runtime.
*Fix:* Use `sync.Mutex`:
```go
mu.Lock()
data = "new"
mu.Unlock()
```

**G17 — Medium:** `select` blocks until one of its cases can proceed; it's like a switch for channels. If multiple cases are ready, Go picks one pseudo-randomly. Timeout implementation:
```go
select {
case res := <-ch: // success
case <-time.After(1 * time.Second): // timeout
}
```

**G18 — Hard:** Escape analysis determines if a variable lives on the stack or heap. Variables that outlive their scope or are too large often "escape." You inspect this with `go build -gcflags="-m"`. It matters because heap allocation involves GC overhead and slower access than stack memory.

**G19 — Hard:** `reflect.Type` describes the structure (fields, methods); `reflect.Value` holds the actual data. Reflection is slow due to dynamic dispatch and lack of compiler optimizations. Justified in generic libraries (like JSON encoders) where types aren't knownat compile time. Otherwise, use code generation (e.g., Protobuf).

**G20 — Hard:** `go:embed` allows including static files into the binary at compile time. For directories, it embeds all files recursively. Limitations include OS restrictions on certain file types. It integrates with `io/fs.FS`, allowing you to treat embedded files as a filesystem.

## Rust

**R1 — Easy:** Ownership is Rust’s way of managing memory without a garbage collector. Rules: 1. Each value has a variable called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2 — Easy:** `String` is an owned, heap-allocated buffer; `&str` is an immutable reference (slice) to a string. Use `String` when you need to own/mutate the data; use `&str` for function arguments to allow both `String` and literal strings.

**R3 — Medium:** Borrowing lets you access data without taking ownership. **Shared references (`&T`)**: many can exist simultaneously, but they are immutable. **Mutable references (`&mut T`)**: Only one can exist at a time, and no other shared references can exist during that period. This prevents data races.

**R4 — Medium:** `Option<T>` represents a value that might be absent (replaces null). `Result<T, E>` represents success or error. The `?` operator returns early if an error occurs.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?; // Returns Err immediately if it fails
    Ok(content)
}
```

**R5 — Medium:** `Box<T>` provides heap allocation with single ownership. `Rc<T>` allows multiple owners in a single-threaded context (reference counting). `Arc<T>` is the thread-safe version of `Rc`, allowing multi-threaded shared ownership.

**R6 — Medium:** Traits define shared behavior (like interfaces). A **Trait Object** (`dyn Trait`) uses dynamic dispatch (vtable), while a generic bound (`T: Trait`) uses monomorphization (static dispatch/inlining). Go's interfaces are similar to traits but lack the explicit "impl" syntax for specific types.

**R7 — Hard:** Lifetimes ensure references don't outlive their data. This fails because the compiler doesn't know which input lives longer. Fix by adding lifetime annotations:
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { ... }
```

**R8 — Hard:** `Send` means a type can be moved to another thread; `Sync` means it can be accessed from multiple threads simultaneously. `Rc<T>` is not `Send`/`Sync` because its internal reference count isn't updated atomically. `Arc<T>` uses atomic operations for the counter, making it safe across threads.

**R9 — Medium:** Rust async is "lazy." A `Future` is a state machine that does nothing until polled. The executor (Tokio) manages polling these futures on a thread pool. Unlike Goroutines (which have their own stacks and preemptive scheduling), Rust futures are cooperative and multiplexed onto OS threads.

**R10 — Medium:** `unsafe` allows bypassing some compiler checks. 3 examples: Dereferencing raw pointers, calling FFI functions, or accessing mutable statics. Justified when writing low-level primitives, drivers, or high-performance wrappers where safety can be proven manually.

**R11 — Easy:** Pattern matching (`match`) is exhaustive; the compiler forces you to handle all cases. `if let` is used when you only care about one specific pattern match.

**R12 — Easy:** `Vec<T>` is a growable array on the heap. An array `[T; N]` has a fixed size known at compile time. When `Vec` exceeds capacity, it reallocates memory (usually doubling) and moves elements.

**R13 — Easy:** Rust enums are Sum Types (can hold data). C/Java enums are just named integers. `Option<T>` replaces null by forcing the developer to explicitly handle the "None" case, preventing NullPointerExceptions.

**R14 — Easy:** `impl` defines methods for a type. `&self` takes an immutable reference, `&mut self` takes a mutable reference, and `self` consumes the object (moves ownership). **Associated functions** don't take `self` as an argument (like constructors).

**R15 — Easy:** The `derive` macro automatically implements traits like `Debug`, `Clone`, `PartialEq`. You cannot derive traits that require manual implementation or those involving complex logic not covered by the procedural macro rules.

**R16 — Medium:** `Cow<'a, T>` allows using borrowed data (`&str`) but switching to owned data (`String`) only when mutation occurs. It avoids cloning unless absolutely necessary.

**R17 — Medium:** `mod` declares a module, `use` brings items into scope, `pub` makes them visible. In 2018 edition, modules can be organized more flexibly across files without needing explicit `mod` declarations in every file if they follow certain naming conventions.

**R18 — Hard:** `Pin<P>` ensures that a value's memory address won't change. This is required for types containing self-referential pointers (common in async futures where a future might point to its own fields). `Unpin` is a marker trait; most types are `Unpin` (can be moved safely).

**R19 — Hard:** Declarative macros (`macro_rules!`) perform pattern matching on code. Procedural macros act as functions that take tokens and return tokens (e.g., `#[derive]`). **Hygiene** ensures that a macro doesn't accidentally capture variables from the surrounding scope it wasn't intended to touch.

**R20 — Hard:** Zero-cost abstractions mean you don't pay for what you don't use. Iterators compile down to loops with no overhead. Generics use monomorphization (creating specific versions of functions at compile time), and Trait Static Dispatch uses direct calls rather than vtables, achieving C speeds while maintaining high-level safety/abstraction.
