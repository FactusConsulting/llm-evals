## .NET / C#

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
A **class** is a reference type, meaning variables hold a pointer to the memory location of the object on the heap. A **struct** is a value type, where the variable holds the actual data directly (usually on the stack). You should use a **struct** for small, immutable data structures that are frequently created and destroyed (e.g., `Point`, `Color`, or custom coordinate types) where minimizing heap allocations improves performance.

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
`IEnumerable<T>` represents an in-memory collection; LINQ operations performed on it are executed by iterating over the entire collection in memory. `IQueryable<T>` represents a query expression tree; LINQ operations are translated into SQL/provider-specific commands and executed at the source (the database). This matters because using `IEnumerable` with a large database table would pull every row into application memory before filtering, whereas `IQueryable` filters at the database level.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
`async/await` is a syntactic sugar that transforms methods into state machines managed by the compiler to handle asynchronous execution without blocking threads. A `Task` is a class representing an ongoing operation (allocates memory on the heap). `ValueTask` is a struct used to represent an operation that might complete synchronously. You should use `ValueTask` in high-frequency methods where the result is often available immediately (e.g., reading from a cache), as it avoids the allocation overhead of a `Task` object.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
Dependency Injection (DI) is a design pattern where objects receive their dependencies from an external source rather than creating them internally. 
1. **Transient**: Created every time they are requested.
2. **Scoped**: Created once per client request (common in web requests).
3. **Singleton**: Created once for the lifetime of the application.
A common bug is "Captive Dependency": Injecting a **Scoped** service into a **Singleton**. Because the Singleton lives forever, it will hold onto the Scoped service indefinitely, preventing its disposal and potentially causing thread safety issues or stale data because the Scoped service was intended to be short-lived.

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
Strings are immutable; any slicing operation (`Substring`) creates a new string object on the heap. `ReadOnlySpan<char>` provides a view into a contiguous region of memory without allocating new memory. You should use `Span<T>`/`ReadOnlySpan<T>` during high-performance parsing or buffer manipulation (like JSON parsing or protocol handling) to eliminate unnecessary allocations and reduce GC pressure.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
The GC manages managed memory automatically. It uses a generational approach: **Gen 0** contains short-lived objects (collected frequently), **Gen 1** acts as a buffer, and **Gen 2** holds long-lived objects (collected less often). The **Large Object Heap (LOH)** handles objects >85KB, which are not compacted by default to avoid performance hits. **IDisposable** is required because the GC only manages *managed* memory. You still need `IDisposable` to release *unmanaged* resources like file handles, database connections, or network sockets that the GC cannot track.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
By default, `await` captures the current `SynchronizationContext` (e.g., the UI thread context in WinForms/WPF). This means the continuation runs on the same thread context. `ConfigureAwait(false)` tells the runtime not to marshal the continuation back to that context. Use it in library code to improve performance and prevent deadlocks. Do **not** use it if your code specifically needs to update UI elements directly from the task completion.

**DN8 — Hard: Explain the new .NET 8/9 features: primary constructors, collection expressions, and FrozenDictionary.**
1. **Primary Constructors**: Allow declaring constructor parameters directly in the class header, simplifying DI boilerplate.
2. **Collection Expressions**: A unified syntax (`[1, 2, 3]`) for initializing arrays, lists, and spans.
3. **FrozenDictionary**: An immutable dictionary optimized for read-heavy scenarios where the keys are known at startup.
*Example:*
```csharp
public class OrderService(IDbContext db) // Primary Constructor
{
    private readonly IDbContext _db = db;
}
// Usage with Collection Expression
var ids = [101, 102, 103];
```

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
The issue is likely "Thread Safety" or "Scope Leakage." `DbContext` is not thread-safe. Under high concurrency, multiple threads might be trying to use the same instance of a context simultaneously (e.g., if it was incorrectly registered as a Singleton). The fix is ensuring the `DbContext` is registered as **Scoped**. In DI, Scoped means one instance per HTTP request; however, if an async operation outlives the request scope (like a background task), the context will be disposed by the DI container while the task still tries to access it. Fix: Use a `IServiceScopeFactory` to create a manual scope for background tasks.

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
A **record** provides built-in value-based equality and non-destructive mutation (`with` expressions) compared to a standard **class**, which uses reference equality. A **record struct** combines the memory efficiency of a value type with the features of a record. Choose a **record** for DTOs/Data models where data integrity and comparison are key; choose a **record struct** for very small, high-performance data structures that need records' syntax but must avoid heap allocation.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
- `ref`: Passes an argument by reference; the method can read or modify it. The variable must be initialized before being passed.
- `out`: Passes by reference; the method *must* assign a value before returning. Used when a method needs to return multiple values.
- `in`: Passes by reference as read-only. Used to pass large structs efficiently without copying them on the stack while ensuring the method doesn't modify the original.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
Nullable Reference Types (NRT) are a compiler feature that warns you if a non-nullable variable might be null at compile time. They don't change runtime behavior; they just provide static analysis. A nullable value type (`int?`) is a wrapper (`Nullable<T>`) that actually allows a primitive to hold a null state at runtime. NRTs only apply to reference types (like `string` or `class`).

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
LINQ (Language Integrated Query) provides a way to query data using standard C# syntax. **Method syntax** uses extension methods and lambdas; **Query syntax** resembles SQL. **Deferred Execution** means the query isn't executed when it is defined, but rather when the result is iterated over (e.g., via `.ToList()` or a `foreach` loop), allowing for efficient composition of queries.

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
Generic constraints restrict what types can be used as the generic argument `T`. 
- `: class`: Must be a reference type.
- `: struct`: Must be a value type.
- `: new()`: Must have a parameterless constructor.
- `: IComparable<T>`: Must implement that specific interface/base class.
You combine them (e.g., `where T : class, new()`) when you need both a reference type with a public constructor and other logic.

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
An **abstract class** defines an "is-a" relationship and can hold state (fields). An **interface** defines a contract ("can-do"). Default interface methods allow interfaces to provide a default implementation without breaking existing classes implementing that interface. This narrows the gap by allowing interfaces to evolve with logic while still not being able to store instance state (fields) like a class.

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
The pipeline is a series of components that process requests sequentially. 
- `app.Use()`: Executes code and calls the next middleware; allows branching or short-circuiting.
- `app.Map()`: Branches the pipeline based on path/conditions.
- `app.Run()`: A terminal middleware; it executes and stops the request from moving further.
Ordering matters because each piece modifies the response/request for subsequent pieces. Exception handling middleware works by wrapping the entire execution in a try-catch block early in the pipeline to catch exceptions thrown by downstream middlewares.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
`Channel<T>` is a high-performance, async-native library for producer-consumer scenarios. Unlike `BlockingCollection<T>`, which blocks threads when full/empty, `Channel<T>` uses non-blocking asynchronous waits (`WaitToReadAsync`). For **backpressure**, you use a **Bounded Channel**: if the channel's capacity is reached, the `WriteAsync` call will asynchronously wait until space becomes available, preventing the producer from overwhelming the consumer.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
Source Generators generate C# source code during compilation based on existing code metadata. 
- **Reflection**: Inspects code at runtime (slow).
- **IL Weaving**: Modifies compiled binaries (complex).
- **Source Generators**: Create new files at compile time (fast, safe).
An **Incremental Generator** caches results between builds; it only re-runs if the input changes. It is preferred because it significantly speeds up build times compared to standard generators that regenerate everything every time.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
TPL Dataflow provides "blocks" for building complex pipelines. 
- `ActionBlock`: Consumes data and performs an action.
- `TransformBlock`: Takes input, transforms it, and passes it on.
- `BufferBlock`: Acts as a buffer/queue.
Compared to `System.Threading.Channels`, TPL Dataflow is higher-level with built-in support for degree of parallelism and complex branching logic, while Channels are lower-level and more lightweight for simple producer-consumer patterns.

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**
Minimal APIs provide a way to create HTTP endpoints using `MapGet`/`MapPost` without the overhead of Controllers. 
- **Trade-offs**: They are faster to develop but can become disorganized at scale compared to Controller's organization. Testability remains high via `WebApplicationFactory`. Middleware still applies globally or per group. Route groups use `.WithEndpointBehavior()` or grouping methods like `.MapGroup("/api")`. Endpoint filters allow applying logic (like Auth) across multiple routes easily.

## Python

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**
A **list** is mutable; a **tuple** is immutable. A **set** is an unordered collection of unique elements that is mutable; a **frozenset** is the immutable version of a set.

**P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?**
The GIL is a mutex that allows only one thread to execute Python bytecode at a time. It affects **CPU-bound** tasks (e.g., heavy math), making multi-threading ineffective for speedup. Workarounds include using the `multiprocessing` module (separate processes with their own GILs), writing C extensions in C/Rust, or offloading work to external services.

**P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.**
A **shallow copy** creates a new object but populates it with references to the same objects found in the original. A **deepcopy** recursively copies every nested object. 
*Example*: If you have a list containing another list (`a = [[1]]`), a shallow copy `b = a[:]` results in both lists sharing the inner list. Modifying `b[0][0] = 9` will change `a`.

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**
Decorators wrap a function to modify its behavior without changing its source code.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"Time taken: {time.perf_counter() - start}")
        return result
    return wrapper
```

**P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?**
Generators use `yield` to produce values one at a time, maintaining state between calls. Unlike returning a list (which builds the entire collection in memory), generators are "lazy." `yield from` allows a generator to delegate part of its execution to a sub-generator/iterable.

**P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?**
The event loop manages multiple concurrent coroutines on a single thread by switching tasks when they hit I/O waits. 
- `asyncio.run()`: Entry point for the loop.
- `asyncio.gather()`: Runs multiple coroutines concurrently and returns results.
- `asyncio.create_task()`: Schedules a coroutine to run independently in the background.
You cannot use `time.sleep()` because it blocks the *entire* thread, preventing the event loop from switching to other tasks; you must use `await asyncio.sleep()`.

**P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**
Python uses **C3 Linearization** to determine MRO. In diamond inheritance (`D(B, C)`, where `B(A)` and `C(A)`), it ensures that base classes are visited only once and in the correct order.
In your example: `print(D().who())` prints `"C"`. This is because `D` inherits from `B` then `C`. Since `B` doesn't override `who`, but `C` does, and `C` appears before `A` in the search path of `D`, the logic finds `C.who()`.

**P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.**
A **metaclass** is a class factory—it defines how a class itself is constructed. Use a **metaclass** when you need to modify the behavior of class creation across many subclasses (e.g., registering every new subclass into a global registry automatically). Use `__init_subclass__` for simpler hooks during child construction; it’s cleaner than metaclasses if you just need to perform an action whenever a class is inherited.

**P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?**
- **Multiprocessing**: Separate memory/processes. Best for CPU-bound tasks. 
- **Threading**: Shared memory space. Best for I/O-bound tasks.
- **Concurrent.futures**: A high-level API to manage both processes and threads easily.
*Pickling*: Multiprocessing requires objects to be "picklable" (serializable) to move them between processes. Objects like open file handles or database connections cannot be pickled and will throw errors.

**P10 — Medium: What is __slots__? When should you use it, and what does it prevent? What is the memory impact?**
`__slots__` tells Python not to create a dynamic dictionary (`__dict__`) for instance attributes. You should use it when creating millions of instances where memory efficiency is critical. It prevents adding arbitrary new attributes at runtime but significantly reduces the memory footprint per object.

**P11 — Easy: What is a virtual environment, and why should you use one? What is the difference between venv, virtualenv, and conda?**
A virtual environment isolates project dependencies so that different projects can have different versions of libraries without conflict. `venv` is the standard library tool; `virtualenv` is an older, more feature-rich third-party tool; `conda` manages non-Python dependencies as well as Python packages.

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?**
Comprehensions are concise ways to build collections in one line. They are functionally equivalent to `map()` (transformation) and `filter()` (selection). Comprehensions are generally preferred in Python because they are considered more readable ("Pythonic") than nested function calls like `list(map(f, list_comp))`.

**P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?**
`is` checks identity (same memory address); `==` checks equality (value). **Interning** is the practice where Python reuses existing objects for common values. Small integers (-5 to 256) are interned by default, which is why `a is b` returns true for these numbers even if created separately.

**P14 — Easy: Explain Python's *args and **kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?**
- `*args`: Collects extra positional arguments into a tuple.
- `**kwargs`: Collects extra keyword arguments into a dictionary.
- `/`: Arguments before this must be positional only.
- `*`: Arguments after this must be passed as keywords (e.g., `func(x, *, y)` requires calling `func(1, y=2)`).

**P15 — Easy: What are context managers (with statement)? How do you write one using __enter__/__exit__ vs @contextmanager? Give an example beyond file handling.**
Context managers manage resources automatically (setup/teardown). Use class methods with `__enter__`/`__exit__` for complex state; use `@contextmanager` decorator for simple logic. Example: Managing a database connection pool or a thread lock.

**P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How do mypy or pyright use these for static analysis?**
Type hints provide metadata about types to improve code clarity and catch bugs via static analysis tools like **mypy**. 
- `Union[int, str]`: Either int or str.
- `Optional[int]`: Union of int and None.
- `Literal["A", "B"]`: Only specific values allowed.
- `TypeVar`: For generic programming.
- `Protocol`: Structural subtyping ("duck typing" but checked statically).

**P17 — Medium: Explain Python's data model (dunder methods). What are __repr__ vs __str__, __eq__ vs __hash__, and __getattr__ vs __getattribute__? What happens if you define __eq__ but not __hash__?**
Dunder methods allow objects to hook into built-in behavior.
- `__repr__`: Developer-facing string representation.
- `__str__`: User-friendly string representation.
- `__eq__` / `__hash__`: Equality check and hashability. If you define `__eq__` without `__hash__`, the object becomes unhashable (cannot be in a set/dict) because its identity is no longer sufficient to determine uniqueness.
- `__getattr__`: Called only when an attribute is *not* found; `__getattribute__`: Called every time any attribute is accessed.

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (__get__, __set__, __delete__). How do property, classmethod, and staticmethod use descriptors under the hood?**
Descriptors are objects that define how attributes are accessed on other objects. The **descriptor protocol** allows for custom logic during access (`__get__`), assignment (`__set__`), or deletion (`__delete__`). Properties, `classmethod`, and `staticmethod` are all implemented as descriptors—they intercept the standard attribute lookup process to provide specialized behaviors like method binding or value validation.

**P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, __init__.py, and namespace packages work? What is a finder and a loader?**
Python searches modules using `sys.path`. Absolute imports start from the root; relative imports use `.`. `PYTHONPATH` adds directories to search paths. `__init__.py` marks a directory as a package (though optional since 3.3). A **finder** locates the module file; a **loader** executes the code to create the module object. Namespace packages allow multiple files/directories to share one name without an `__init__.py`.

**P20 — Hard: What is dataclasses and how does it compare to attrs and Pydantic? Explain __post_init__, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**
- **Dataclasses**: Standard library tool for data containers.
- **attrs**: More powerful but requires external dependency.
- **Pydantic**: Focuses on runtime data validation and serialization.
`__post_init__`: Runs after the generated init. `field(default_factory=...)`: Handles mutable defaults correctly. Use **frozen=True** for immutability. Choose **Pydantic** when validating incoming JSON or API payloads where strict type enforcement at runtime is required.
