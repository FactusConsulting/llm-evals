## JavaScript / TypeScript

**JS1 — Easy:** `var` is function-scoped and hoisted; `let` and `const` are block-scoped and not hoisted in the same way (they exist in a Temporal Dead Zone). `const` prevents reassignment of the variable identifier itself. **Hoisting** is the JS engine's behavior of moving declarations to the top of their scope during the creation phase before execution.

**JS2 — Easy:** The **Event Loop** is a mechanism that allows JS to perform non-blocking I/O by offloading operations to the system kernel. It manages the **Call Stack** (synchronous execution), the **Microtask Queue** (Promises, MutationObservers - high priority), and the **Macrotask Queue** (setTimeout, setInterval, I/O - lower priority). Microtasks are processed immediately after every task or microtask completion until the queue is empty.

**JS3 — Medium:** A **closure** is a function that remembers its lexical scope even when executed outside that scope. 
*Example:* A counter factory: `function makeCounter() { let count = 0; return () => ++count; }`.
*Loop Bug:* Using `var` inside a loop with an async operation causes all closures to reference the final value of the iterator. *Fix:* Use `let`, which creates a new binding for each iteration.

**JS4 — Medium:** `Promise` represents a value that will be available in the future. `async/await` is syntactic sugar over Promises, making asynchronous code look synchronous. Error handling: use `.catch()` for Promises and `try/catch` for `async/await`. **Promise.allSettled** waits for all promises to complete (regardless of success/failure) and returns statuses; **Promise.all** rejects immediately if any promise fails.

**JS5 — Medium:** An **interface** defines a contract (shape) and can be merged/extended; it disappears at runtime. A **type** alias can represent primitives, unions, and intersections but cannot be merged. Use interfaces for public APIs/objects; use types for complex logic like Unions or Tuples. **Discriminated Unions** use a common literal property (e.g., `type: 'success'`) to allow TS to narrow down types via switch statements.

**JS6 — Medium:** JS uses **Prototypal Inheritance**: every object has a `__proto__` pointing to another object. `Object.create(proto)` creates a new object with a specific prototype. ES6 classes are "syntactic sugar" over this—they don't create real classes but instead define methods on the prototype chain.

**JS7 — Hard:** `this` refers to the execution context. Binding rules (priority): 1. New (`new`), 2. Explicit binding (`call`, `apply`, `bind`), 3. Implicit binding (method call), 4. Default binding (global/undefined). `bind()` returns a *new* function with a fixed `this`. You cannot re-bind a bound function because its `this` is already locked.

**JS8 — Hard:** `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` allows running a callback when an object is GC'd. Use them for memory management in caches. **WeakMap keys must be objects** because they are held weakly; if the only reference to a key is inside a WeakMap, it can be collected by the GC, ensuring no memory leaks.

**JS9 — Hard:** V8 uses **Hidden Classes** (shapes) to track property layouts and **Inline Caching** to remember where properties are located in memory. If you change the order of property assignments or delete properties, the engine creates a new hidden class, causing "deoptimization" as the cache misses. Coding patterns like adding dynamic properties to objects frequently cause this.

**JS10 — Medium:** Tree-shaking removes unused code during bundling. It works best with **ES Modules (ESM)** because imports are static (determined at compile time). **CommonJS (CJS)** is dynamic (`require()`), meaning the bundler doesn't know what will be imported until runtime, making tree-shaking nearly impossible.

**JS11 — Easy:** `null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion (e.g., `null == undefined` is true); `===` checks strict equality. **Nullish coalescing (`??`)** returns the right side if left is null/undefined. **Optional chaining (`?.`)** allows accessing nested properties without checking if parent exists.

**JS12 — Easy:** `map()` transforms every element into a new array; `filter()` returns elements matching a condition; `reduce()` accumulates values into a single result. With an initial value, `reduce` starts accumulation from that point. `flatMap()` maps then flattens one level deep—useful for processing lists where one item might produce multiple results.

**JS13 — Easy:** Template literals use backticks (\`) and `${}` interpolation. **Tagged templates** allow passing the string parts to a function. *Example:* `` const sql = html`SELECT * FROM users WHERE id = ${id}`; `` where the tag function can sanitize the `id`.

**JS14 — Easy:** Destructuring extracts data from arrays or objects: `const { name } = user;`. Default values: `const [a, b = 1] = [5];`. Renaming: `const { name: userName } = user;`. The **rest operator (...)** collects remaining elements into a new array/object.

**JS15 — Easy:** `for...in` iterates over enumerable property keys (including inherited ones). `for...of` iterates over iterable values (like Array elements). Avoid `for...in` on arrays because it may return indices as strings and include prototype properties.

**JS16 — Medium:** Generics allow creating reusable components with type safety. `extends` provides constraints (`T extends number`). Conditional types (`T extends U ? X : Y`) act like ternary operators for types. `infer` allows extracting types from other types (e.g., getting the return type of a function).

**JS17 — Medium:** CJS uses `require()` (synchronous, dynamic); ESM uses `import`/`export` (asynchronous-friendly, static). Node handles both but requires `"type": "module"` in `package.json` to treat `.js` files as ESM. Otherwise, Node defaults to CJS.

**JS18 — Hard:** TS is structural (if it looks like a duck, it's a duck). **Excess property checks** only apply when assigning an object literal directly to a variable; they don't apply if passed as an argument. `extends` is for inheritance/subtyping; `satisfies` ensures an expression matches a type without widening its inferred type. Variance defines how subtyping of complex types works (contravariance for inputs, covariance for outputs).

**JS19 — Hard:** `Proxy` intercepts operations (get, set, etc.) on an object. `Reflect` provides methods to perform those same actions (useful inside Proxy traps). *Example:* A Proxy can intercept a 'set' trap to validate that a user's age input is always positive before updating the state.

**JS20 — Hard:** `SharedArrayBuffer` allows multiple threads (Web Workers) to share memory. `Atomics` provide thread-safe operations (add, load, wait) to prevent race conditions. They use shared memory rather than message passing. `Atomics.wait`/`notify` allow one worker to sleep until another wakes it up via a specific index in an Int32Array.

## Bash

**B1 — Easy:** `$@` expands to all arguments as separate words (preserving spaces); `$*` expands to all arguments as a single string. `"$@"` preserves individual quoted arguments; `"$*"` joins them into one string.

**B2 — Easy:** `set -euo pipefail`. `-e`: Exit immediately if a command fails. `-u`: Error if using uninitialized variables. `-o pipefail`: Ensure the exit code of a pipeline is the code of the last failed command.

**B3 — Medium:** `$(command)` and `` `command` `` are both command substitutions (backticks are deprecated). `$(())` is for arithmetic expansion (integer math), while `expr` is an external utility used for older shell scripts.

**B4 — Medium:** Process substitution `<(command)` creates a temporary file descriptor that behaves like a file but runs a command. *Example:* `diff <(ls dir1) <(ls dir2)` compares two directory listings without creating temp files.

**B5 — Medium:** Use `find . -name "*pattern*"` or globbing with quotes: `for f in *.txt; do ...`. `for f in $(ls)` is dangerous because it splits on whitespace, breaking filenames containing spaces.

**B6 — Easy:** Here doc (`<<EOF`) allows multi-line input. Here string (`<<<`) takes a single line/string as input. `<<-EOF` ignores leading tabs in the here document (useful for indented code blocks).

**B7 — Hard:** 
1. `cmd > file 2>&1`: Redirects stdout to file, then redirects stderr to where stdout was going (file).
2. `cmd 2>&1 > file`: Redirects stderr to stdout (still pointing at terminal), then redirects stdout to file. Result: Stderr goes to terminal, Stdout goes to file.
3. `cmd &> file`: Modern bash shortcut to redirect both to file simultaneously.

**B8 — Hard:**
```bash
lock_file="/tmp/mylock"
mkdir "$lock_file" 2>/dev/null && { echo "Locked"; } || { echo "Failed"; exit 1; }
# Cleanup via trap
trap 'rmdir "$lock_file" 2>/dev/null' EXIT INT TERM
```
*Why mkdir?* It is an atomic operation at the filesystem level—if two processes try it simultaneously, only one succeeds. File creation can have race conditions depending on flags.

**B9 — Easy:** Single quotes ('') are literal strings (no expansion). Double quotes ("") allow variable expansion (`$VAR`). No quotes treat content as shell commands or split by whitespace. *Example:* `echo "Value: $VAR"` vs `echo 'Value: $VAR'`.

**B10 — Easy:** `-f` checks for a regular file, `-d` for directory, `-r` for readable. `[[ ]]` is a keyword that supports globbing and logical operators without word splitting issues; `[ ]` is the older POSIX test command.

**B11 — Easy:** `$?`: Exit code of last command. `$$`: PID of current shell. `$!`: PID of last background job. `$#`: Number of arguments passed to script.

**B12 — Easy:** `foo() { ... }` and `function foo {}` are mostly identical in Bash. To return values, use `echo` inside the function and capture with `result=$(foo)`, or set a global variable.

**B13 — Easy:** `PATH` is a colon-separated list of directories searched for executables. Resolution order: 1. Aliases, 2. Builtins, 3. Functions, 4. Executables in PATH. Check via `type -a <command>` (e.g., `type -a cd` shows it as a builtin).

**B14 — Medium:** `trap 'cleanup_cmd' SIGNAL`. Set up handlers for EXIT (script end), ERR (non-zero exit), INT (Ctrl+C), TERM (kill). If multiple signals arrive, they are queued/handled sequentially based on signal priority.

**B15 — Medium:** `xargs` takes standard input and executes commands; command substitution `$(...)` runs a command and replaces itself with output. Use `find . -print0 | xargs -0 -P 4` to handle spaces safely (`-0`) and run in parallel (`-P`).

**B16 — Medium:** Arrays: `arr=(val1 val2)`. Associative arrays: `declare -A map`. Append: `arr+=("new")`. Length: `${#arr[@]}`. Associative arrays require `declare -A` and use keys like `map[key]=val`.

**B17 — Hard:** Subshell `(...)` creates a new process; variables changed inside do not affect the parent. Group `{ ...; }` runs in current shell; changes persist. Piping into a while loop `cmd | while read line; do var=... done` happens in a subshell because of the pipe, so `var` is lost after the loop ends.

**B18 — Hard:** Signals: SIGINT (Interrupt/Ctrl+C), SIGTERM (Termination request), SIGHUP (Terminal hangup), SIGKILL (Force kill). To handle gracefully, use `trap` to catch TERM/INT and perform cleanup before exiting. Background processes are managed via `&` and job control signals.

**B19 — Hard:**
```bash
split -l 10000 large_log.log chunk_
ls chunk_* | xargs -P 4 -n 1 ./process_func
cat <(ls chunk_* | xargs -P 4 -n 1 ./process_func) > final_result
```
*Trade-offs:* Parallelism increases speed but risks out-of-order results or high I/O contention. Error propagation requires checking exit codes within the parallel worker.

**B20 — Hard:** `exec` replaces the current shell process with another command. For file descriptors: `exec 3>file` opens FD 3 for writing. `exec 3>&-` closes it. A **coprocess** (`coproc`) creates a background process with a bidirectional pipe; used when you need to send data back and forth to a long-running background task.

## PowerShell

**PS1 — Easy:** `Write-Output` sends objects into the pipeline; `Write-Host` writes directly to the console (host). Use `Write-Output` if the next command needs that data.

**PS2 — Easy:** The pipeline passes *objects*, not just text. `ForEach-Object` is used in pipelines (streaming); `foreach` statement is faster for processing collections already in memory.

**PS3 — Medium:** `[PSCustomObject]` is an object with properties; `[hashtable]` is a key-value collection. Convert via `[PSCustomObject]$obj | Get-Member` or `($obj).GetEnumerator()`.

**PS4 — Medium:** Terminating errors stop execution; non-terminating do not. `-ErrorAction` sets behavior per command, `$ErrorActionPreference` sets global default. `try/catch` only catches terminating errors unless `-ErrorAction Stop` is used.

**PS5 — Medium:** Splatting uses a hashtable to pass parameters:
```powershell
$params = @{ Path = "C:\"; Force = $true }
Get-ChildItem @params
```
It improves readability over long one-liners and allows dynamic parameter construction.

**PS6 — Medium:** Remoting allows running commands on remote machines. `Invoke-Command` runs a block of code remotely; `Enter-PSSession` provides an interactive shell. It uses WinRM (WSMan) by default but can use SSH in newer versions.

**PS7 — Hard:** PowerShell's pipeline handles objects implicitly. In the example, if `Get-Items` returns nothing, `$x` becomes `$null`. If it returns values, `$x` is an array. The correct pattern for returning specific types consistently is using `[PSCustomObject]` inside the function to ensure property consistency.

**PS8 — Hard:** A scriptblock `{...}` is a block of code; a function is a named reusable unit with parameters. Pass scriptblocks via `Invoke-Command -ScriptBlock`. **Double-hop** occurs when a machine tries to access a third machine using credentials from the first. Solve via CredSSP or passing arguments directly via `-ArgumentList`.

**PS9 — Easy:** `@()` ensures the result is an array even if only 1 item exists. `[array]` forces type casting. Indexing into `$null` results in an error/null depending on version; indexing into an empty array `[ ]` usually returns null or errors out.

**PS10 — Easy:** Comparison operators: `-eq`, `-like` (wildcards), `-contains` (checks if value exists in collection). Case sensitivity is toggled by adding `c` (e.g., `-ceq`). `-contains` checks existence; `-in` checks if a single value is part of a list.

**PS11 — Easy:** Modules are units of functionality. `.psm1` contains logic, `.psd1` is the manifest (metadata like version/author), and binary modules are compiled DLLs. `Import-Module` loads them into the session.

**PS12 — Easy:** Double quotes (`"`) allow interpolation (`$var`); single quotes (`'`) are literal. Expressions can be included inside double quotes. **Here-strings** use `@"`...`"@` to preserve newlines exactly as written.

**PS13 — Easy:** `Get-Member` shows properties, methods, and NoteProperties (metadata). Properties are data attributes; Methods are actions you can perform. `Select-Object` filters columns; `Where-Object` filters rows based on conditions.

**PS14 — Medium:** PowerShell classes are for strict typing and structure but lack full C# inheritance/interfaces support. Use Classes when you need complex object modeling or multiple instances with shared state; use functions for procedural tasks.

**PS15 — Medium:** `[CmdletBinding()]` enables standard parameters (`-Verbose`, etc.). `SupportsShouldProcess` adds `-WhatIf`/`-Confirm`. `Begin`, `Process`, and `End` blocks handle input streaming: `Begin` runs once at start, `Process` runs for every item in the pipeline, `End` runs once at completion.

**PS16 — Medium:** Providers allow PS to treat different sources (Registry, FileSystem) like a unified file system. You access registry via `HKLM:` or `HKCU:` providers just like folders.

**PS17 — Hard:** Runspaces provide isolated execution environments. A `runspace` is an instance of the engine; `runspacepool` manages many runspaces. `ForEach-Object -Parallel` (v7+) simplifies this by managing threads internally without manual runspace management.

**PS18 — Hard:** `PSScriptAnalyzer` checks code against rules (e.g., "no variables should be global"). It integrates into CI/CD as a linting step. Rules have severity levels (Warning, Error). Suppress using `#PSCmdlet` or `[Diagnostics.CodeAnalysis]`.

**PS19 — Hard:** `$using:` allows accessing local variables inside remote sessions/parallel jobs. `$args` handles passed parameters. **CLIXML depth** limits how deep nested objects can be serialized across the wire—complex nested objects may fail if they exceed these limits.

**PS20 — Hard:** DSC defines a desired state (e.g., "Service X must be running"). LCM enforces that state on nodes. In modern infra, it has been largely superseded by Terraform and Ansible for provisioning, while DSC remains relevant for configuration drift management in Windows environments.
