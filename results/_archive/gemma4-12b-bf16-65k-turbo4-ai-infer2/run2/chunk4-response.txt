## Go

**G1 — Easy: What is the difference between a slice and an array in Go? What happens when you append to a slice that has reached its capacity?**
An **array** has a fixed size defined at compile time; its length is part of its type. A **slice** is a descriptor for a contiguous segment of an underlying array (containing a pointer, length, and capacity). When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array, copies the existing elements over, and returns a new slice header pointing to this new memory.

**G2 — Easy: Explain the difference between `var x int` and `x := 0`. When can you NOT use `:=`?**
`var x int` declares a variable with the zero value (`0`) and can be used at the package or function level. `x := 0` uses short variable declaration, which infers the type from the right side. You cannot use `:=` outside of functions (at the package level) or if the variable has already been declared in the same scope.

**G3 — Medium: What is a goroutine, and how does it differ from an OS thread? What is the role of the Go scheduler (GMP model)?**
A **goroutine** is a lightweight thread managed by the Go runtime, not the OS. They have smaller stacks (starting at ~2KB) compared to OS threads (~1MB+). The **GMP model** manages them: **G** represents Goroutines, **M** represents Machine threads (OS threads), and **P** represents Processors (logical resources/context). The scheduler maps Gs onto Ms via Ps to ensure efficient execution and work-stealing across cores.

**G4 — Medium: Explain how channels work in Go. What is the difference between a buffered and unbuffered channel? What happens when you send to a full buffered channel?**
Channels are typed conduits for communication. An **unbuffered** channel blocks the sender until a receiver is ready. A **buffered** channel allows sending up to its capacity without blocking. If a buffered channel is full, the sender blocks until space becomes available (or another goroutine receives a value).

**G5 — Medium: What is the context package used for? Write a minimal example of using context.WithTimeout to cancel a long-running HTTP request.**
The `context` package carries deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel() // Ensure resources are freed
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
```

**G6 — Medium: Explain Go's interface satisfaction model. How does it differ from Java/C# interfaces? What is the empty interface interface{} (or any) and why is it both powerful and dangerous?**
Go uses **implicit satisfaction**: a type satisfies an interface simply by implementing its methods; no explicit `implements` keyword is needed. In Java/C#, you must explicitly declare implementation. The empty interface `interface{}` can hold any value, making it powerful for generic handling but dangerous because it bypasses type safety, requiring type assertions or reflections which can cause panics if handled incorrectly.

**G8 — Hard: What is the difference between sync.Mutex and sync.RWMutex? When would you use sync.Map vs a regular map with a mutex? What are the performance trade-offs?**
A `Mutex` allows only one goroutine at a time. An `RWMutex` allows multiple concurrent readers OR one writer. Use `sync.Map` when you have many concurrent reads/updates to disjoint keys across many cores; otherwise, a standard map with a `Mutex` is usually faster for low-contention scenarios due to less overhead.

**G9 — Hard: Explain how Go modules work. What is the difference between go.mod and go.sum? What does go mod tidy do, and what is the Minimum Version Selection (MVS) algorithm?**
`go.mod` defines requirements and dependencies. `go.sum` contains cryptographic hashes of those dependencies to ensure integrity. `go mod tidy` removes unused modules and adds missing ones. **MVS** is the algorithm that selects the highest minimum version required by all dependencies in the graph.

**G10 — Medium: What is a defer statement? In what order do multiple defers execute? What is a common gotcha with defer in a loop?**
`defer` schedules a function call to run immediately before the surrounding function returns. They execute in LIFO (Last-In, First-Out) order. A common gotify is using `defer` inside a loop (e.g., closing a file); it won't close until the *function* ends, potentially exhausting resources if the loop runs many times.

**G11 — Easy: What is a pointer in Go? What is the zero value of a pointer? How do you create a pointer to a struct literal?**
A pointer holds the memory address of a value. The zero value of a pointer is `nil`. You can create one to a struct literal using the address-of operator: `p := &MyStruct{Field: 1}`.

**G12 — Easy: Explain Go's init() function. When does it run? Can a package have multiple init() functions, and if so, in what order do they execute?**
`init()` runs automatically before `main()`. It runs after variable initialization but before any other code. A package can have multiple `init()` functions; they execute in the order they are defined in the source files.

**G13 — Easy: What is the difference between make and new in Go? What types does each work with?**
`new` allocates memory and returns a pointer to a zeroed value (works on any type). `make` allocates and **initializes** memory for specific built-in types: slices, maps, and channels.

**G14 — Easy: How does error handling work in Go? What is the error interface, and what is the idiomatic pattern for checking errors? How do errors.Is and errors.As differ from ==?**
Errors are values returned as the last return parameter. The `error` interface is an interface with a `Error() string` method. Idiom: `if err != nil { ... }`. `errors.Is` checks if an error matches a specific target (like `io.EOF`), while `errors.As` checks if an error can be cast/asserted into a specific custom error type.

**G15 — Easy: What are Go's built-in composite types (map, slice, channel, struct)? What is the zero value of each?**
*   Map: `nil`
*   Slice: `nil`
*   Channel: `nil`
*   Struct: A struct where all fields are set to their respective zero values.

**G16 — Medium: What is a race condition in Go? How does the -race flag work? Give an example of a data race and show how to fix it with sync.Mutex or a channel.**
A race condition occurs when two goroutines access the same memory concurrently and at least one is a write. The `-race` flag enables a runtime detector that instruments memory accesses to find unsynchronized concurrent access. 
*Fix:* Wrap the shared variable access in a `sync.Mutex` lock/unlock block or pass the data through a channel.

**G17 — Medium: Explain Go's select statement. How does it differ from a switch? What happens when multiple cases are ready? How do you implement a timeout with select?**
`select` lets a goroutine wait on multiple communication operations. Unlike `switch`, which evaluates expressions, `select` blocks until one case can proceed. If multiple cases are ready, one is chosen pseudo-randomly. Timeout is implemented using `time.After(d)` which returns a channel.

**G18 — Hard: What is escape analysis in Go? How does the compiler decide whether to allocate on the stack or the heap? How can you inspect escape analysis decisions, and why does it matter for performance?**
Escape analysis determines if a variable's lifetime exceeds the scope of the function. If so, it "escapes" to the heap. Stack allocation is faster and cheaper than heap (which requires GC). You can inspect this using `go build -gcflags="-m"`. It matters because excessive heap allocations increase GC pressure.

**G19 — Medium: Explain Go's reflection package (reflect). What is reflect.Type vs reflect.Value? What are the performance costs, and when is reflection justified vs code generation?**
Reflection allows inspecting/manipulating types at runtime. `reflect.Type` describes the structure; `reflect.Value` represents the actual data. Reflection is slow due to dynamic dispatch and lack of compile-time checks. Use it only when necessary (e.g., JSON encoders); otherwise, use Code Generation (like `stringer`) for better performance.

**G20 — Hard: What is the go:embed directive? How does it work for single files, directories, and file systems? What are the limitations, and how does it interact with io/fs.FS?**
`go:embed` allows including static assets into the binary. Files/directories result in a `embed.FS` or `embed.TS` type. Limitations include not being able to embed certain OS paths or specific restricted files. It integrates with `io/fs.FS`, allowing you to treat embedded content as a standard filesystem.

## Rust

**R1 — Easy: What is ownership in Rust? Explain the three ownership rules.**
Ownership is Rust’s memory management system without a garbage collector. Rules: 1. Each value has a variable called its owner. 2. There can be only one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2 — Easy: What is the difference between String and &str? When would you use each in function signatures?**
`String` is an owned, heap-allocated string that can grow. `&str` is a borrowed string slice (a pointer + length). Use `String` when you need to own/mutate data; use `&str` for function arguments where you only need read access.

**R3 — Medium: Explain borrowing and the borrow checker. What are the rules for shared (&T) and mutable (&mut T) references?**
Borrowing allows using a value without taking ownership. The Borrow Checker enforces: You can have either *any number* of immutable references OR *exactly one* mutable reference at a time. You cannot have both simultaneously.

**R4 — Medium: What is a Result<T, E> and an Option<T>? How does the ? operator work? Write a function that reads a file and returns its contents or an error.**
`Option<T>` handles values that might be absent (`Some(T)` or `None`). `Result<T, E>` handles operations that can fail (`Ok(T)` or `Err(E)`). The `?` operator returns early if an error occurs, propagating it up the call stack.
```rust
fn read_file() -> Result<String, std::io::Error> {
    std::fs::read_to_string("test.txt") // Returns Result automatically
}
```

**R5 — Medium: Explain the difference between Box<T>, Rc<T>, and Arc<T>. When would you use each?**
`Box<T>` provides heap allocation (single owner). `Rc<T>` (Reference Counted) allows multiple owners in a single-threaded context. `Arc<T>` (Atomic Reference Counted) allows multiple owners across threads by using atomic operations for the counter.

**R6 — Medium: What are traits in Rust? How do they compare to Go interfaces? What is a trait object (dyn Trait) vs a generic with a trait bound (T: Trait)?**
Traits define shared behavior. Unlike Go's implicit satisfaction, Rust requires explicit implementation of traits for types. **Trait objects** (`dyn`) use dynamic dispatch (vtable), while generics with bounds use monomorphization (static dispatch/compile-time generation).

**R8 — Hard: What is Send and Sync in Rust? Why can't you send an Rc<T> across threads? What makes Arc<T> safe for concurrent use?**
`Send` means ownership can be transferred between threads. `Sync` means a type can be shared between threads via references. `Rc<T>` uses non-atomic reference counting, which causes data races on the counter when accessed by multiple threads. `Arc<T>` uses atomic operations for the count, making it thread-safe.

**R9 — Hard: Explain how Rust's async/await works under the hood. What is a Future? What is the role of the executor (e.g., Tokio)? How does this differ from Go's goroutines?**
Rust futures are "lazy" state machines; nothing happens until polled. An **executor** (like Tokio) manages polling these futures. Unlike Goroutines (which are preemptive and managed by the runtime), Rust's async is cooperative and requires an external executor to drive progress.

**R10 — Medium: What is unsafe in Rust? Give 3 things you can do in an unsafe block that you can't do in safe Rust. When is unsafe justified?**
`unsafe` allows bypassing some compiler checks. You can: dereference raw pointers, call FFI functions, or access mutable static variables. It is justified when interfacing with C libraries, writing low-level data structures, or performance-critical kernels where safety is manually verified.

**R11 — Easy: What is pattern matching in Rust? How does match differ from if let? What does the compiler enforce about exhaustiveness?**
Pattern matching allows branching based on structure. `match` is for complex patterns; `if let` is a shorthand for matching a single case. The compiler enforces **exhaustiveness**, requiring all possible variants (especially in Enums) to be handled.

**R12 — Easy: What is the difference between Vec<T> and an array [T; N]? How does Vec manage memory when elements are pushed beyond its current capacity?**
An array has a fixed size at compile time. A `Vec` is a growable heap-allocated buffer. When capacity is exceeded, `Vec` reallocates a larger chunk of memory (usually doubling), copies existing items, and updates the pointer.

**R13 — Easy: What are enums in Rust, and how do they differ from enums in C or Java? What is the Option<T> enum, and why does Rust not have null?**
Rust enums can hold data (Algebraic Data Types). In C/Java, enums are just named integers. Rust doesn't have `null`; it uses `Option<T>` to explicitly represent "nothing," forcing developers to handle the empty case safely.

**R14 — Easy: Explain the impl block. What is the difference between methods that take &self, &mut self, and self? What are associated functions (e.g., String::new())?**
The `impl` block defines methods for a type. `&self` borrows the instance (read-only); `&mut self` borrows mutably; `self` consumes the instance (moves ownership). **Associated functions** don't take a `self` parameter and are called like static methods (`Type::func()`).

**R15 — Easy: What is the derive macro? Give examples of commonly derived traits (Debug, Clone, PartialEq, Serialize). When can you NOT derive a trait?**
Derive macros automatically implement common traits. You cannot derive traits if any field within the struct/enum also fails to implement that trait (or requires manual implementation).

**R16 — Medium: What is Cow<'a, T> (clone on write)? When is it useful? Give an example where it avoids unnecessary allocations compared to always cloning.**
`Cow` allows a value to be either borrowed or owned. It is useful when you often return a reference but occasionally need to return an owned copy. Example: A function that returns a string only if it contains "special" characters; otherwise, it returns a `&str`. This avoids allocating a new `String` unless necessary.

**R17 — Medium: Explain Rust's module system. What is the difference between mod, use, and pub? How does the file system map to modules, and what changed between Rust 2015 and 2018 editions?**
`mod` declares a module, `use` brings paths into scope, and `pub` makes items visible outside the module. In 2015, files were strictly mapped to modules. In 2018, the system became more flexible, allowing for nested modules in single files and better handling of internal visibility.

**R18 — Hard: What is the Pin<T> type and why is it needed? How does it relate to self-referential structs and async/await? What is Unpin?**
`Pin` ensures that a value cannot be moved in memory. This is required for **self-referential structs** (where a pointer points to another field within the same struct). Async blocks are often self-referential because they store local variables across await points. `Unpin` is a marker trait indicating a type *can* be safely moved (most types are `Unpin`).

**R19 — Hard: Explain Rust's macro system. What is the difference between declarative macros (macro_rules!) and procedural macros (derive, attribute, function-like)? What are hygiene rules?**
Declarative macros (`macro_rules!`) use pattern matching on code. Procedural macros are functions that take tokens as input and return new tokens (similar to compilers). Macros are "hygienic," meaning they don't accidentally capture or collide with variables in the surrounding scope unless explicitly designed to do so.

**R20 — Hard: What are zero-cost abstractions in Rust? Explain how iterators, generics (monomorphization), and trait static dispatch achieve performance comparable to hand-written C while providing high-level ergonomics.**
Zero-cost abstraction means you don't pay for what you don't use. **Iterators** compile down to efficient loops; **Generics/Monomorphization** generate specific machine code for each concrete type at compile time (no runtime overhead); **Static Dispatch** via traits allows the compiler to inline calls directly rather than using pointers to jump to logic.
