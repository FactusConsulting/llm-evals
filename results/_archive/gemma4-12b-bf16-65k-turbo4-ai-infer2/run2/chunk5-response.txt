## .NET / C#

**DN1 — Easy: What is the difference between class and struct in C#? When should you use a struct?**
A **class** is a reference type (stored on the heap), while a **struct** is a value type (usually stored on the stack or inline within another object). Use a struct for small, immutable data structures that are short-lived and have a small memory footprint (e.g., a `Point` or `Color` object). Avoid structs if they are large, mutable, or need to be passed around frequently as references, as copying value types can incur performance overhead.

**DN2 — Easy: Explain the difference between IEnumerable<T> and IQueryable<T>. Why does this distinction matter for database queries?**
`IEnumerable<T>` is designed for in-memory collections; LINQ operations are executed locally on the data already loaded into memory. `IQueryable<T>` is designed for out-of-memory data sources (like databases); it stores an expression tree that allows the provider (e.g., Entity Framework) to translate the query into SQL. This matters because using `IEnumerable` with a database often results in "client-side evaluation," where all records are pulled into memory before filtering, causing massive performance hits.

**DN3 — Medium: How does async/await work in C#? What is a Task vs a ValueTask? When should you use ValueTask?**
`async/await` uses a state machine generated by the compiler to suspend execution of a method until an asynchronous operation completes without blocking the calling thread. A `Task<T>` is a heap-allocated object representing an ongoing operation. `ValueTask<T>` is a struct used to reduce allocations when the result of an operation is often available synchronously (e.g., reading from a cache). Use `ValueTask` in high-frequency methods where most calls return immediately.

**DN4 — Medium: Explain dependency injection in .NET. What are the three service lifetimes (Transient, Scoped, Singleton), and what is a common bug when injecting a Scoped service into a Singleton?**
DI is a design pattern where objects receive their dependencies from an external container rather than creating them internally. 
1. **Transient**: Created every time they are requested.
2. **Scoped**: Created once per request (e.g., one instance per HTTP request).
3. **Singleton**: Created once and live for the application's lifetime.
**Common Bug:** "Captive Dependency." If you inject a Scoped service into a Singleton, the Scoped service will be held alive for the entire life of the Singleton, potentially causing memory leaks or stale data because it never gets disposed/reset as intended by its scope.

**DN5 — Medium: What is the difference between string and ReadOnlySpan<char> for string processing? When would you use Span<T> and why?**
A `string` is immutable; any manipulation (like `Substring`) creates a new string object on the heap. `ReadOnlySpan<char>` provides aview over a contiguous region of memory without allocating new objects. Use `Span<T>` for high-performance parsing, buffer management, or slicing strings to minimize Garbage Collector (GC) pressure.

**DN6 — Medium: Explain how the .NET garbage collector works. What are generations (Gen 0, 1, 2)? What is Large Object Heap? What is IDisposable and why do you need it if you have a GC?**
The GC uses a generational approach: Gen 0 contains short-lived objects (collected most frequently), Gen 1 acts as a buffer, and Gen 2 contains long-lived objects. The **Large Object Heap (LOH)** stores objects >85KB and is collected less frequently. You need `IDisposable` because the GC only manages managed memory; it cannot automatically clean up unmanaged resources like file handles, database connections, or network sockets.

**DN7 — Hard: What is the difference between ConfigureAwait(false) and the default behavior? When should you use it, and when should you NOT? How does this relate to SynchronizationContext?**
By default, `await` attempts to resume execution on the original `SynchronizationContext` (e.g., the UI thread). `ConfigureAwait(false)` tells the runtime that resuming on the captured context is not required. Use it in library code to avoid deadlocks and improve performance. Do **not** use it if you specifically need to access UI elements directly after an await call.

**DN8 — Hard: Explain the new .NET 8/9 features: primary constructors, collection expressions, and FrozenDictionary.**
*   **Primary Constructors**: Allow declaring constructor parameters directly in the class header for cleaner syntax.
*   **Collection Expressions**: A unified syntax (`[1, 2, 3]`) to initialize arrays, lists, and spans.
*   **FrozenDictionary**: An immutable dictionary optimized for high-speed read operations where the keys are known at startup.

**DN9 — Hard: You have a .NET API that works fine under low load but throws ObjectDisposedException on the DbContext under high concurrency. Diagnose the likely cause and explain the fix. How does EF Core's DbContext lifetime interact with DI scoping?**
The issue is likely "Thread Safety." `DbContext` is not thread-safe; sharing one instance across multiple concurrent threads causes disposal errors or race conditions. In standard DI, `DbContext` is **Scoped**. If you are manually starting background tasks from a controller and passing the scoped context into them, they will fail as the request scope ends while the task continues. Fix: Inject `IDbContextFactory<T>` and create a new context per unit of work/task.

**DN10 — Medium: What is the difference between record and class in C#? What about record struct? When would you choose each?**
A `record` provides built-in value-based equality (equality based on values rather than reference). A `class` is for identity-based logic. A `record struct` combines the value-type performance of a struct with the syntax/equality features of a record. Choose `record` for DTOs and data models where immutability and easy comparison are needed.

**DN11 — Easy: What is the difference between ref, out, and in parameter modifiers in C#? When would you use each?**
*   `ref`: The variable must be initialized before being passed; allows modification inside the method. Use for swapping variables.
*   `out`: Does not need to be initialized before passing; the method *must* assign it. Use for returning multiple values.
*   `in`: Passes by reference but prevents modification inside the method. Use for large structs to avoid copying overhead without allowing side effects.

**DN12 — Easy: Explain nullable reference types in C# (the ? annotation and #nullable enable). How do they differ from nullable value types (int?)?**
Nullable Reference Types (`string?`) are a compile-time feature that warns you if a reference might be null, helping prevent NullReferenceExceptions. They don't change runtime behavior. Nullable Value Types (`int?`) are actual wrappers (`Nullable<T>`) because value types cannot naturally be null.

**DN13 — Easy: What is LINQ? Explain the difference between method syntax (list.Where(...)) and query syntax (from x in list where ...). What is deferred execution?**
LINQ (Language Integrated Query) provides a uniform way to query data. **Method Syntax** uses extension methods and lambdas; **Query Syntax** mimics SQL/SQL-like structure. **Deferred Execution** means the query isn't executed when defined, but rather when iterated over (e.g., via `foreach` or `.ToList()`).

**DN14 — Easy: What are generic constraints in C#? Explain where T : class, where T : struct, where T : new(), and where T : IComparable<T>. When would you combine multiple constraints?**
Constraints restrict what types can be used as generic arguments. `: class` limits to reference types; `: struct` to value types; `: new()` ensures a parameterless constructor exists; `: IComparable<T>` allows sorting. Combine them to enforce specific behaviors (e.g., `where T : class, new()`).

**DN15 — Easy: What is the difference between abstract class and interface in C#? How did default interface methods (C# 8+) change this distinction?**
An **abstract class** can hold state (fields) and provide shared implementation for related classes. An **interface** defines a contract. Default interface methods allow interfaces to have logic without breaking existing implementations, narrowing the gap by allowing "mix-in" behavior that was previously only possible with abstract classes.

**DN16 — Medium: Explain the middleware pipeline in ASP.NET Core. What is the difference between app.Use(), app.Map(), and app.Run()? How does ordering matter, and how does exception handling middleware work?**
Middleware components form a request/response pipeline. `app.Use()` executes and passes control forward; `app.Map()` branches based on route; `app.Run()` terminates the pipeline. Order matters because they execute sequentially (e.g., Auth must come before Routing). Exception handling middleware works by wrapping the subsequent calls in a try-catch block to catch errors from downstream.

**DN17 — Medium: What is Channel<T> in .NET? How does it compare to BlockingCollection<T>? Give an example of using bounded channels for producer-consumer backpressure.**
`Channel<T>` is a high-performance, async-friendly producer-consumer queue. Unlike `BlockingCollection`, which blocks threads synchronously, Channels use `ValueTask` and non-blocking async waits. For backpressure, you set a **Bounded Capacity**: if the channel is full, the producer's `WriteAsync` will asynchronously wait until space becomes available.

**DN18 — Hard: Explain Source Generators in .NET. How do they differ from reflection and IL weaving? What is an incremental generator, and why is it preferred over ISourceGenerator?**
Source Generators generate C# source code during compilation. Reflection inspects metadata at runtime (slow); IL Weaving modifies existing binaries (complex/risky). Incremental generators are "smart" generators that only re-generate code when specific inputs change, significantly improving build times compared to standard `ISourceGenerator`.

**DN19 — Hard: What is the System.Threading.Tasks.Dataflow library (TPL Dataflow)? Explain ActionBlock, TransformBlock, and BufferBlock. How does it compare to System.Threading.Channels for pipeline processing?**
TPL Dataflow provides an actor-model approach where data flows through blocks. `ActionBlock` performs an action; `TransformBlock` maps input to output; `BufferBlock` acts as a buffer. While TPL Dataflow is higher-level and easier for complex branching/joining logic, `System.Threading.Channels` is lower-level, faster, and better for simple high-throughput pipelines.

**DN20 — Hard: What are Minimal APIs in .NET? How do they differ from controller-based APIs? What are the trade-offs in terms of testability, middleware, and OpenAPI support? How do route groups and endpoint filters work?**
Minimal APIs provide a streamlined way to create endpoints using `MapGet`/`MapPost` directly on the app builder. Trade-offs: They have less boilerplate but can become messy without organization. Testability remains high via integration tests. Route groups allow logical grouping of routes with shared metadata, and Endpoint Filters allow reusable logic (like Auth or Logging) applied to specific sets of endpoints.

## Python

**P1 — Easy: What is the difference between a list and a tuple? What about a set vs a frozenset?**
A **list** is mutable; a **tuple** is immutable. A **set** is a mutable collection of unique items; a **frozenset** is an immutable version of a set. Use tuples/frozensets when you need hashable collections (e.g., as dictionary keys).

**P2 — Easy: Explain the GIL (Global Interpreter Lock). What types of workloads does it affect, and what are the workarounds?**
The GIL prevents multiple native threads from executing Python bytecode simultaneously. It affects CPU-bound tasks (heavy math/processing). Workarounds include using the `multiprocessing` module (separate memory spaces), writing C extensions in C++/Rust, or using libraries like NumPy that release the GIL during heavy computation.

**P3 — Medium: What is the difference between deepcopy and copy? Give an example where shallow copy causes unexpected behavior.**
`copy` creates a new object but fills it with references to the original nested objects. `deepcopy` recursively copies all nested objects. Example: If you have a list containing another list (`L = [[1]]`), a shallow copy results in two lists pointing to the *same* inner list. Modifying one modifies both.

**P4 — Medium: Explain Python decorators. Write a decorator that logs the execution time of any function.**
Decorators wrap a function to modify its behavior. 
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        res = func(*args, **kwargs)
        print(f"Time taken: {time.perf_counter() - start}")
        return res
    return wrapper
```

**P5 — Medium: What are generators and yield? How do they differ from returning a list? What is yield from?**
Generators use `yield` to produce values lazily (one at a time), saving memory by not storing the entire result set. Returning a list requires allocating memory for every item immediately. `yield from` allows a generator to delegate part of its operations to a sub-generator/iterable.

**P6 — Medium: Explain Python's asyncio event loop. What is the difference between asyncio.run(), asyncio.gather(), and asyncio.create_task()? Why can't you call time.sleep() inside an async function?**
The event loop manages tasks on a single thread using non-blocking I/O. `asyncio.run()` starts the loop; `gather()` runs multiple coroutines concurrently; `create_task()` schedules a coroutine to run in the background. `time.sleep()` blocks the *entire* thread, stopping the event loop; `await asyncio.sleep()` yields control back to the loop.

**P7 — Hard: Explain Python's MRO (Method Resolution Order). What algorithm does Python 3 use? What happens with diamond inheritance, and why does the following print what it does?**
Python uses **C3 Linearization**. In your example, D inherits from B then C. The MRO is [D, B, C, A]. Since B doesn't define `who`, it looks at its parent A. Output: "A". If B had defined `who`, it would be "B".

**P8 — Hard: What is a metaclass? When would you use __init_subclass__ vs a metaclass? Give a practical use case for each.**
A metaclass is a class factory (a class that creates classes). Use `__init_subclass__` for simple logic like registering subclasses or setting default attributes. Use a Metaclass when you need to modify the class creation process itself (e.g., enforcing strict API rules on all subclasses) or implementing the Singleton pattern via class-level state.

**P9 — Hard: Explain the difference between multiprocessing, threading, and concurrent.futures in Python. When would you use each? What are the serialization implications of multiprocessing (pickling)?**
*   **Threading**: Shared memory; good for I/O bound tasks.
*   **Multiprocessing**: Separate memory space; bypasses GIL; good for CPU-bound tasks.
*   **Concurrent.futures**: High-level wrapper for both. 
Pickling requires objects to be serializable. Objects with non-serializable states (like open file handles or database connections) cannot be passed between processes.

**P10 — Medium: What is \_\_slots\_\_? When should you use it, and what does it prevent? What is the memory impact?**
`__slots__` tells Python not to create a `__dict__` for instances of a class, instead allocating only enough space for fixed attributes. Use it when creating millions of small objects to significantly reduce memory footprint by preventing dynamic attribute overhead.

**P11 — Easy: What is a virtual environment, and why should you use one? What is the difference between venv, virtualenv, and conda?**
Virtual environments isolate project dependencies so different projects can have conflicting versions of libraries. `venv` is the standard library tool; `virtualenv` is an older, more feature-rich third-party tool; `conda` is a cross-platform package/environment manager that handles non-Python dependencies too.

**P12 — Easy: Explain list comprehensions, dict comprehensions, and set comprehensions. How do they relate to map() and filter()? When would you prefer one over the other?**
Comprehensions are syntactic sugar for creating collections in a single line. They are generally preferred for readability. `map()` and `filter()` are functional tools; use them if you already have an iterator or need to pass a function as a first-class object without using lambdas.

**P13 — Easy: What is the difference between == and is in Python? What is object interning, and why does a is b sometimes return True for small integers?**
`==` checks value equality; `is` checks identity (memory address). **Interning** pre-allocates certain objects (like small integers -5 to 256) during startup. Because these are reused, `a is b` returns true because both point to the same interned memory location.

**P14 — Easy: Explain Python's *args and **kwargs. How do positional-only (/) and keyword-only (*) parameter markers work in function signatures?**
`*args` collects extra positional arguments into a tuple; `**kwargs` collects extra keyword arguments into a dictionary. `/` indicates that all parameters before it must be positional only; `*` indicates that all parameters after it must be passed as keywords.

**P15 — Easy: What are context managers (with statement)? How do you write one using \_\_enter\_\_/\_\_exit\_\_ vs @contextmanager? Give an example beyond file handling.**
Context managers handle setup/teardown logic automatically. Use `__enter__`/`__exit__` for complex stateful management or `@contextmanager` with a generator for simpler tasks like managing a database connection pool or a thread lock.

**P16 — Medium: What is type hinting in Python? Explain typing.Union, Optional, Literal, TypeVar, and Protocol. How does mypy or pyright use these for static analysis?**
Type hints provide metadata about types without enforcing them at runtime. `Union` allows multiple types; `Optional` is Union[T, None]; `Literal` restricts values to specific constants; `TypeVar` handles generics; `Protocol` defines structural subtyping (duck typing). Mypy uses these to perform static checks to catch bugs before the code runs.

**P17 — Medium: Explain Python's data model (dunder methods). What are \_\_repr\_\_ vs \_\_str\_\_, \_\_eq\_\_ vs \_\_hash\_\_, and \_\_getattr\_\_ vs \_\_getattribute\_\_? What happens if you define \_\_eq\_\_ but not \_\_hash\_\_?**
Dunder methods allow objects to hook into built-in behaviors. `__repr__` is for developers (debugging); `__str__` is for users. If you define `__eq__` but not `__hash__`, the object becomes unhashable because equality implies that two "equal" items must have the same hash value.

**P18 — Hard: What are descriptors in Python? Explain the descriptor protocol (\_\_get\_\_, \_\_set\_\_, \_\_delete\_\_). How do property, classmethod, and staticmethod use descriptors under the hood?**
Descriptors are objects that define how attribute access works (`__get__`, etc.). The `property` decorator creates a descriptor that manages logic during get/set calls; `classmethod` and `staticmethod` are also descriptors that manage how the method is bound to the instance or class.

**P19 — Hard: Explain Python's import system in detail. What is the difference between relative and absolute imports? How does sys.path, PYTHONPATH, \_\_init\_\_.py, and namespace packages work? What is a finder and a loader?**
Python searches `sys.path` sequentially to find modules. Absolute imports use full paths; relative imports use dots (relative to current package). `PYTHONPATH` adds directories to search path. `__init__.py` marks a directory as a package. A **Finder** locates the module file; a **Loader** executes code to initialize it into memory. Namespace packages allow sub-packages without an `__init__.py`.

**P20 — Hard: What is dataclasses and how does it compare to attrs and Pydantic? Explain \_\_post\_init\_\_, field factories, frozen dataclasses, and how dataclasses interacts with inheritance. When would you choose Pydantic over dataclasses?**
Dataclasses automate boilerplate like `__init__` and `__repr__`. `attrs` offers more advanced features (like custom types); `Pydantic` provides runtime validation and serialization. `__post_init__` runs after initialization for manual setup. Use **Pydantic** when receiving external data that requires strict schema validation or JSON serialization/deserialization.
