**N1** — A Layer 2 switch operates at the Data Link Layer (Layer 2) and forwards frames based on MAC addresses. It builds and uses a MAC address table. A Layer 3 switch operates at the Network Layer (Layer 3) and can perform routing functions, forwarding packets based on IP addresses. It combines the high-speed switching capabilities of L2 devices with the routing intelligence of L3 routers.

**N2** — The subnet mask for /20 is 255.255.240.0.
*   **Network Address:** 10.0.32.0
*   **Broadcast Address:** 10.0.47.255

**N3** — The TCP three-way handshake establishes a connection:
1.  **SYN (Synchronize):** Client sends a SYN packet to the server, proposing an initial sequence number (ISN).
2.  **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and replies with a SYN-ACK, acknowledging the client's SYN and proposing its own ISN.
3.  **ACK (Acknowledge):** Client receives SYN-ACK and sends an ACK back to the server, confirming receipt. The connection is established.
If the final ACK is lost, the server will wait for a timeout period. Upon timeout, the server will retransmit the SYN-ACK. If the client never receives the SYN-ACK, it will retransmit the initial SYN until the connection times out or is successfully established.

**N4** — **SNAT (Source Network Address Translation):** Changes the source IP address of a packet as it leaves a private network, typically to a public IP address. *Example: A host on a private LAN (192.168.1.10) accessing the internet uses the router's public IP as its source address.*
**DNAT (Destination Network Address Translation):** Changes the destination IP address of a packet as it enters a private network. *Example: An external user accessing a web server (public IP: 203.0.113.5) is redirected by the firewall to the internal server's private IP (192.168.1.5).*

**N5** — 3 possible causes for `SSL: certificate subject name does not match target host name`:
1.  **Incorrect Hostname:** The hostname used in the browser/curl command does not match the Common Name (CN) or Subject Alternative Name (SAN) listed in the certificate.
2.  **Wildcard Mismatch:** If a wildcard certificate (`*.example.com`) is used, the specific subdomain requested might not be covered by the wildcard.
3.  **Certificate Issuance Error:** The certificate was issued for a different domain entirely, and the certificate itself is invalid for the target host.

**N6** — **VLAN (Virtual LAN):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains within the same physical switch infrastructure, using 802.1Q tagging.
**VxLAN (Virtual Extensible LAN):** An overlay networking technology that encapsulates Layer 2 Ethernet frames within Layer 4 UDP packets, allowing L2 segments to span across multiple Layer 3 networks (IP underlay).
You would choose VxLAN over VLAN when you need to scale beyond the 4094 VLAN limit, or when you need to stretch Layer 2 domains across geographically dispersed or routed networks (i.e., when the underlying network is routed, not switched).

**N7** — The traffic is being replied via eth0 because the Linux kernel uses the routing table to determine the best path for return traffic. Since eth0 is configured with the default gateway (10.0.0.1), the kernel assumes that traffic destined for the external network (or the network associated with the default route) should exit via eth0.
To fix this with policy-based routing (PBR), you must use `ip rule` and `ip route` to define a routing policy based on the source IP address. You would add a rule stating: "If the source IP is 192.168.1.5, use the routing table associated with eth1."

**N8** — BGP path selection is a complex process where routers choose the best path to a destination based on a sequence of attributes. The selection process is deterministic.
The general order of preference (though specific implementations may vary slightly) is:
1.  Weight (Cisco proprietary, highest preference)
2.  Local Preference (Highest is preferred)
3.  AS Path Length (Shortest is preferred)
4.  Origin Type (IGP > EGP > Incomplete)
5.  MED (Multi-Exit Discriminator - Lowest is preferred)
6.  ... (Further attributes like eBGP vs iBGP, etc.)

**N9** — When running VxLAN over an IPsec tunnel, the encapsulation process adds multiple layers: Ethernet $\rightarrow$ VxLAN Header $\rightarrow$ UDP Header $\rightarrow$ IP Header $\rightarrow$ ESP/AH Header (IPsec).
The physical MTU (1500 bytes) must accommodate all these headers.
*   Standard Ethernet Frame Overhead: 14 bytes (L2)
*   VxLAN Overhead: 50 bytes (VNI, UDP, etc.)
*   IPsec Overhead (ESP): Typically 30-50 bytes (depending on padding/auth)
*   Total Overhead $\approx 14 + 50 + 30 = 94$ bytes.
Maximum Inner Payload = Physical MTU - Total Overhead = $1500 - 94 = 1406$ bytes.

**N10** — **ARP (Address Resolution Protocol):** ARP is used to map a known Layer 3 IP address to its corresponding Layer 2 MAC address within a local subnet. It works by broadcasting an ARP request asking, "Who has this IP address? Tell me your MAC address."
**Gratuitous ARP:** This is an ARP request sent by a host to itself (or broadcasted without a specific request). It solves the problem of stale ARP caches. It is used to announce a host's presence, update its MAC address in the local ARP table, or confirm that a host has taken over an IP address.

**N11** — **Public IP Address:** An IP address globally unique and routable on the public internet. It must be assigned by an IANA-approved regional registry.
**Private IP Address:** An IP address reserved for use within private networks (LANs) and is not routable on the public internet.
The three private IPv4 ranges (RFC 1918) are:
1.  10.0.0.0/8
2.  172.16.0.0/12
3.  192.168.0.0/16

**N12** — **DNS (Domain Name System):** DNS is a hierarchical naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses (like 93.184.216.34).
*   **A Record:** Maps a domain name to an IPv4 address (e.g., `www.example.com` $\rightarrow$ 192.0.2.1).
*   **CNAME Record (Canonical Name):** Creates an alias from one domain name to another (e.g., `blog.example.com` $\rightarrow$ `servers.example.com`).
*   **AAAA Record:** Maps a domain name to an IPv6 address.

**N13** — **DHCP (Dynamic Host Configuration Protocol):** DHCP is a network management protocol that automatically assigns IP addresses and other network configuration parameters (subnet mask, gateway, DNS servers) to devices on a network.
The DORA process is:
1.  **Discover:** Client broadcasts a DHCP Discover message to find available servers.
2.  **Offer:** Server responds with a DHCP Offer, proposing an IP address and configuration.
3.  **Request:** Client broadcasts a DHCP Request, formally accepting the offered configuration.
4.  **Acknowledge:** Server sends a DHCP ACK, finalizing the lease and confirming the configuration.

**N14** — **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming electrical signals to every connected port, creating a single collision domain.
**Switch:** Operates at Layer 2 (Data Link). It intelligently forwards frames based on MAC addresses to the specific destination port, creating smaller collision domains.
**Router:** Operates at Layer 3 (Network). It connects different networks and forwards packets between them based on IP addresses, making routing decisions.

**N15** — **Half-Duplex:** Allows data transmission in both directions, but only one direction at a time (e.g., a walkie-talkie). Collisions can occur if both sides transmit simultaneously.
**Full-Duplex:** Allows simultaneous data transmission in both directions (e.g., a telephone call). Collisions are eliminated.
Modern Ethernet links overwhelmingly use **full-duplex** communication.

**N16** — The **TTL (Time To Live)** field in an IP packet is a counter that limits the lifespan of the packet. Each router that forwards the packet decrements the TTL by one. When the TTL reaches zero, the router discards the packet and typically sends an ICMP Time Exceeded message back to the source.
**Traceroute** exploits this by sending a sequence of packets with incrementally increasing TTL values (starting at 1). The first router receives the packet, decrements TTL to 0, and sends back an ICMP Time Exceeded message, revealing its IP address. Subsequent packets reveal the next hop, mapping the path hop-by-hop.

**N17** — A **NAT Gateway** acts as a translator between a private internal network and the public internet, allowing internal devices to communicate externally using a shared public IP address.
*   **Static NAT:** Maps a single private IP address to a single, fixed public IP address permanently (1:1 mapping). Used for servers that need consistent external access.
*   **Dynamic NAT:** Maps private IP addresses to a pool of available public IP addresses on a first-come, first-served basis.
*   **PAT (Port Address Translation) / NAT Overload:** Maps multiple private IP addresses to a single public IP address by tracking unique source port numbers for each internal connection. This is the most common form of NAT used in homes/offices.

**N18** — **ECMP (Equal-Cost Multi-Path):** ECMP allows a router to use multiple paths to reach the same destination if those paths have the same routing metric (cost). The router distributes traffic across these available paths, increasing aggregate bandwidth and redundancy.
**Hashing Strategies:** Common strategies include hashing based on the 5-tuple (Source IP, Destination IP, Source Port, Destination Port, Protocol).
**Asymmetric Flows Problem:** If stateful firewalls are involved, asymmetric flows (where traffic enters one interface/firewall and returns via a different interface/firewall) can cause state tracking failures. The firewall expects the return packet to match the state it recorded for the outbound packet, and if the return path is different, the firewall may drop the packet as unsolicited.

**N19** — **The Problem:** The Bandwidth-Delay Product (BDP) is the maximum amount of unacknowledged data that can be "in flight" on the network path at any given time ($\text{BDP} = \text{Bandwidth} \times \text{Round Trip Time}$). If the TCP window size (the advertised buffer size) is smaller than the BDP, the sender will stop transmitting data while waiting for acknowledgments, leading to the pipe being underutilized, resulting in high latency despite no packet loss.
**Solution (TCP Window Scaling):** RFC 1323 introduced the TCP Window Scale option. This option allows the TCP header to negotiate a window size much larger than the standard 16-bit limit (65,535 bytes), effectively allowing the sender to fill the entire BDP pipe, thus maximizing throughput and reducing perceived latency.

**N20** — **802.1Q Trunk Ports:** This standard allows a single physical link to carry traffic for multiple VLANs simultaneously. It achieves this by inserting a 4-byte tag (the VLAN tag) into the Ethernet frame header. This tag identifies which VLAN the frame belongs to.
**Linux Configuration (Sub-interfaces):** On Linux, you configure this using VLAN sub-interfaces on the physical NIC. For example, if `eth0` is the physical interface:
*   `eth0.10` (VLAN 10)
*   `eth0.20` (VLAN 20)
*   `eth0.30` (VLAN 30)
Each sub-interface is configured with an IP address belonging to its respective VLAN subnet.
**Frame Format:** The frame format includes the standard Ethernet header, followed by the 4-byte 802.1Q tag (which contains the VLAN ID), followed by the original Layer 2 payload.

**L1** — **Hard Link:** A hard link is a directory entry that points directly to the same inode (the metadata structure) on the filesystem as the original file. Deleting one hard link does not delete the data until the last link is removed. They share the exact same data blocks.
**Symbolic Link (Symlink):** A symbolic link is a special file that contains a text path pointing to another file or directory. It is a pointer or shortcut; it has its own inode and data block containing the path string.

**L2** — Use the `find` command:
`find /var/log -type f -size +100M`

**L3** — State D (Uninterruptible Sleep) means the process is waiting for an I/O operation (e.g., disk read/write, network response) to complete, and it cannot be interrupted by signals. The kernel is blocked waiting for hardware.
No, you **cannot** kill it with `kill -9` (SIGKILL). SIGKILL is a signal that the kernel delivers immediately, but if the process is blocked waiting for hardware I/O, the kernel cannot deliver the signal until the I/O operation completes, meaning the process remains stuck in state D until the I/O finishes or the underlying hardware/device fails.

**L4** — **cgroups v1:** Used resource control based on hierarchical controllers (e.g., CPU, Memory). It is less unified and often required separate controllers for different resource types.
**cgroups v2:** Implements a unified hierarchy and a unified control plane. It enforces resource limits more coherently across all controllers, providing a cleaner, more predictable resource management model.
Systemd prefers **cgroups v2** because it offers a modern, unified, and more robust resource management model that aligns better with its service management architecture.

**L5** — **iptables:** The older, traditional Linux firewall framework. It uses chains (INPUT, OUTPUT, FORWARD) and tables to process packet rules.
**nftables:** The modern replacement for iptables. It is a more flexible, unified, and efficient framework that supports complex expressions and can handle multiple protocols and packet types within a single rule set.
The kernel handles both by maintaining compatibility layers. When `iptables` rules are loaded, the kernel translates them into the underlying `nftables` structure for execution, allowing older tools to function while the kernel uses the modern backend.

**L6** — The most likely cause is that the filesystem contains a large number of **small files**. The `df -h` command reports the total disk space used (blocks allocated), while `du -sh` calculates the total size of the *contents* of the directories. If there are millions of tiny files, the metadata overhead (inodes, directory entries) can consume a significant portion of the disk space, causing `df` to report 100% usage even if the actual data payload is small.

**L7** — 1. **UEFI Firmware:** The system powers on, and the UEFI firmware initializes hardware. It locates the bootloader (e.g., GRUB2) on the EFI partition and executes it.
2. **Bootloader (GRUB2):** The bootloader loads the Linux kernel image and the initial RAM disk (`initramfs`) into memory and passes control to the kernel.
3. **Kernel:** The kernel initializes core subsystems (memory management, drivers). It mounts the `initramfs`, which contains minimal drivers needed to access the real root filesystem.
4. **Initramfs:** The `initramfs` executes scripts to load necessary drivers (e.g., storage drivers) and mounts the actual root filesystem (`/`).
5. **Root Filesystem:** The kernel transitions control to the first user-space process, which is typically `systemd`.
6. **Systemd:** `systemd` takes over, reads its configuration, starts essential services (networking, logging, etc.), and eventually reaches a target state (e.g., `multi-user.target`), resulting in a fully running system.

**L8** — Even with high `buff/cache`, the `available` memory can be low if the kernel is aggressively caching data that is *not* immediately reclaimable, or if the processes are holding onto memory that the kernel cannot easily swap out. The OOM killer fires when the kernel determines that the system is critically low on memory *and* cannot satisfy the memory requests of running processes.
**Kernel Tunables:** Key tunables include `vm.swappiness` (controls how aggressively the kernel swaps out anonymous memory) and `vm.vfs_cache_pressure` (controls how aggressively the kernel reclaims memory used for directory and inode caches). Lowering `swappiness` can force the kernel to keep more data in RAM before resorting to swap.

**L9** — `ip netns` is used to manage network namespaces in Linux. A network namespace provides an isolated view of the system resources, including network interfaces, routing tables, process IDs, and mount points.
Container runtimes (like Docker or Kubernetes) use network namespaces to isolate containers. Each container is placed into its own network namespace, giving it its own private network stack (its own IP address, routing table, and interfaces), making it appear as an independent machine to the outside world.

**L10** — **SIGTERM (15):** The standard termination signal. It politely asks the process to shut down, allowing it to clean up resources before exiting. It **can** be caught.
**SIGKILL (9):** The immediate, non-catchable termination signal. The kernel forces the process to stop instantly, preventing any cleanup. It **cannot** be caught.
**SIGQUIT (3):** Causes the process to terminate and usually generates a core dump file for debugging. It **can** be caught.

**L11** — **stdin (Standard Input):** Where a program reads input from (usually the keyboard).
**stdout (Standard Output):** Where a program writes its normal, expected output to (usually the terminal screen).
**stderr (Standard Error):** Where a program writes error messages and diagnostic information to (usually the terminal screen).
To redirect stderr to a file while displaying stdout on the terminal:
`command 2> error.log` (This redirects file descriptor 2, stderr, to the file).

**L12** — `chmod 755 filename` sets the permissions for the file:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = Full control.
*   **5 (Group):** Read (4) + Execute (1) = Can view and run.
*   **5 (Others):** Read (4) + Execute (1) = Can view and run.
In summary, the owner has full control, while the group and others can only read and execute the file.

**L13** — **Root User (UID 0):** The superuser. It has unrestricted access to the entire operating system, can modify any file, change system configurations, and manage all processes without restriction.
**Sudo Privileges:** A user with `sudo` privileges can execute specific commands as the root user, but only for those commands explicitly allowed by the `/etc/sudoers` file. This grants granular, audited access without giving the user full, persistent root access.

**L14** — **Package Manager:** A system utility used to automate the installation, upgrading, configuration, and removal of software packages on an operating system.
*   **Debian/Ubuntu:** APT (Advanced Package Tool) or dpkg.
*   **RHEL/Fedora:** DNF (Dandified YUM) or Yum.

**L15** — The `/etc/fstab` (filesystem table) file defines how disk partitions, network shares, and other filesystems should be mounted at boot time.
If an entry is misconfigured (e.g., incorrect UUID, wrong mount point, or invalid filesystem type), the system may fail to mount that partition during boot, potentially leading to a boot failure or a degraded system state, depending on whether the mount is marked as `noauto` or `nofail`.

**L16** — **LVM (Logical Volume Manager):** LVM is a layer of abstraction that sits between the physical storage devices and the filesystem. It allows administrators to manage storage dynamically, resizing, moving, and combining storage volumes without needing to physically repartition disks.
*   **Physical Volumes (PV):** The actual physical storage devices (e.g., hard drives or partitions) that LVM uses.
*   **Volume Groups (VG):** A pool of storage capacity created by combining one or more PVs.
*   **Logical Volumes (LV):** The virtual partitions carved out of the VG that are then formatted and mounted as filesystems.
To extend an LV: 1. Extend the underlying PV (if necessary). 2. Extend the VG to include the new space. 3. Use `lvextend` to increase the size of the specific LV. 4. Use `resize2fs` (or equivalent) to expand the filesystem to fill the new LV space.

**L17** — **I/O Scheduler:** Determines the order in which read/write requests are serviced by the block device driver to optimize disk throughput and latency.
*   **mq-deadline:** Prioritizes requests based on deadlines, balancing throughput and latency. Good for mixed workloads.
*   **bfq (Budget Fair Queueing):** Designed for desktop/interactive workloads. It aims to provide fair bandwidth allocation to different processes, minimizing latency spikes for interactive tasks.
*   **none:** Bypasses the scheduler entirely, passing requests directly to the hardware. Best for high-performance storage arrays or specialized workloads where the storage controller handles scheduling.
You change the scheduler at runtime using the `echo` command: `echo bfq > /sys/block/sdX/queue/scheduler` (where `sdX` is the device name).

**L18** — **Load Average:** Measures the average number of processes in the system that are either running or waiting to run (in uninterruptible sleep, D state). It is a measure of system demand, not just CPU utilization.
**I/O Wait Inflation:** When processes are blocked waiting for slow disk or network I/O, they enter the D state. Since the load average counts these waiting processes, high I/O wait inflates the load average, making the system *appear* overloaded even if the CPU utilization is low.
**Diagnosis:**
*   **CPU Bottleneck:** Use `top` or `htop` and check the `%CPU` column. If it's consistently near 100% across all cores, the CPU is the bottleneck.
*   **Disk Bottleneck:** Use `iostat -x 1` or `iotop`. High `%util` (utilization) on the disk device, coupled with high wait times (`await`), indicates disk saturation.
*   **Network Bottleneck:** Use `iftop` or `nload` to monitor interface throughput and check for packet drops or high utilization on the network interface.

**L19** — **SELinux (Security-Enhanced Linux):** SELinux enforces Mandatory Access Control (MAC). Instead of relying solely on traditional Discretionary Access Control (DAC - user/group permissions), SELinux assigns security contexts (labels) to every subject (process) and object (file/port). Access is only granted if the policy explicitly permits the transition between the subject's context and the object's context.
*   **Enforcing:** SELinux actively denies access based on policy violations.
*   **Permissive:** SELinux logs policy violations but does *not* deny access, allowing administrators to see what *would* have been blocked.
*   **Disabled:** SELinux is inactive, and only DAC rules apply.
To troubleshoot a daemon failing to bind a non-standard port: Check the audit logs (`/var/log/audit/audit.log`). If SELinux is blocking it, the log will show a denial. You must then use `semanage port` to explicitly tell SELinux that the daemon is allowed to use that specific port/context.

**L20** — **Page Faults:** A page fault occurs when a program tries to access a memory page that is not currently loaded into physical RAM. The kernel intercepts this fault and handles it.
*   **Minor Page Fault:** The required page is already in memory (e.g., in the page cache or shared memory) but needs to be mapped into the process's address space. This is fast.
*   **Major Page Fault:** The required page is not in physical memory and must be retrieved from secondary storage (disk/swap). This requires I/O and is significantly slower.
**THP (Transparent Huge Pages):** THP attempts to automatically coalesce small, standard 4KB memory pages into larger 2MB pages to reduce TLB misses and improve memory management efficiency.
**When to Disable:** THP can introduce unpredictable latency spikes (latency jitter) during the background compaction process, especially in latency-sensitive, high-throughput applications (like real-time databases or high-frequency trading). In such cases, disabling THP (`echo never > /sys/kernel/mm/transparent_hugepage/enabled`) is often preferred for predictable performance.
