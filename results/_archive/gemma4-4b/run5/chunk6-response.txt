## JavaScript / TypeScript (20 questions)

JS1 — The difference is scope and reassignment. `var` is function-scoped and hoisted (can be accessed before declaration, initialized to `undefined`). `let` is block-scoped and hoisted (but enters the Temporal Dead Zone, preventing access before declaration). `const` is block-scoped and requires immediate initialization; it cannot be reassigned (though object/array contents can be mutated). Hoisting is JavaScript's behavior of moving declarations to the top of their scope during compilation, but not the initialization of function expressions or variable assignments.

JS2 — The Event Loop is the mechanism that manages the execution of asynchronous code in JavaScript. It continuously checks the Call Stack and the queues. The Call Stack holds synchronous function calls. When an async operation (like `setTimeout` or network request) completes, its callback is placed in the appropriate queue. The Microtask Queue (e.g., Promises, `queueMicrotask`) is processed entirely after the current script finishes, before the next macrotask. The Macrotask Queue (e.g., `setTimeout`, I/O) is processed one task at a time after the microtask queue is empty.

JS3 — A closure is the ability of a function to remember and access variables from its lexical scope even after that scope has finished executing. Example: A function factory that returns a counter. The counter variable persists in the closure's scope. The classic for loop closure bug occurs when using `var` in a loop; the callback functions all reference the *same* final value of the loop variable. The fix is to use `let` (which creates a new binding for each iteration) or pass the index/value into the callback function.

JS4 — A Promise is an object representing the eventual completion (or failure) of an asynchronous operation. `async/await` is syntactic sugar built on top of Promises, allowing asynchronous code to be written in a synchronous-looking style using `await`. Error handling with Promises uses `.catch()`, while with `async/await`, standard `try...catch` blocks are used. `Promise.all()` rejects immediately if *any* input promise rejects. `Promise.allSettled()` waits for *all* input promises to either fulfill or reject, returning an array of status objects describing the outcome of each.

JS5 — An `interface` in TypeScript defines a contract—a set of properties and methods that an object must adhere to. It is purely structural and cannot contain implementation logic. A `type` alias can define primitives, unions, intersections, tuples, or complex object shapes, and *can* include logic (like mapped types). Use `interface` for defining object shapes that might be implemented by classes or for declaration merging. Use `type` for unions, intersections, or complex type aliases. Discriminated unions are a union type where each member has a common, literal property (the "discriminant"). This allows TypeScript to narrow the type safely using a `switch` statement on that property.

JS6 — Prototypal inheritance means objects inherit properties and methods directly from other objects (their prototypes), rather than through classes. `Object.create(proto)` creates a new object whose internal `[[Prototype]]` link points directly to the provided `proto` object. ES6 classes are syntactic sugar over JavaScript's existing prototypal inheritance mechanism. When you define a class, JavaScript internally sets up the prototype chain behind the scenes to mimic classical inheritance.

JS7 — The `this` keyword refers to the object that is currently executing the function. Its value is determined dynamically based on *how* the function is called. The 4 binding rules in priority order are: 1. `new` binding (when called with `new`). 2. Explicit binding (`.call()`, `.apply()`, `.bind()`). 3. Implicit binding (when called as a method on an object). 4. Default binding (when called globally/in strict mode, `this` is `undefined` or the global object). `bind()` returns a *new* function with the specified `this` context permanently bound. Yes, you can re-bind the returned function using `.bind()` again, though it is usually redundant.

JS8 — `WeakRef` allows you to hold a weak reference to an object. A weak reference does not prevent the garbage collector from reclaiming the object if no strong references remain. `FinalizationRegistry` allows you to register a callback function that will be executed *after* the garbage collector has finalized an object referenced by a `WeakRef`. They are used for cleanup tasks (e.g., removing listeners) without creating memory leaks. WeakMap keys must be objects because primitives (like strings or numbers) are compared by value, meaning multiple distinct objects with the same primitive value would map to the same entry, defeating the purpose of object identity tracking.

JS9 — V8 optimizes JS using several techniques. **Hidden Classes** (or Maps) allow V8 to represent objects with the same structure efficiently, avoiding the need to check property names repeatedly. **Inline Caching** stores the expected type and location of an operation (like property access) directly in the machine code, speeding up subsequent calls. **Deoptimization** occurs when V8's assumptions about an object's structure or type prove false (e.g., adding a new property to an object that V8 assumed was fixed). Coding patterns that cause deoptimization include dynamic property addition/deletion, frequent type switching, and using `eval()`.

JS10 — Tree-shaking is a form of dead code elimination performed by bundlers (like Webpack or Rollup). It works by analyzing the static `import`/`export` structure of ES Modules. Since ES Modules are static, the bundler can determine which exported functions or components are actually imported and used, discarding the unused ones. CommonJS (`require()`) is dynamic; since `require('module')` can be called conditionally or based on runtime variables, the bundler cannot statically determine all dependencies, making effective tree-shaking impossible.

JS11 — `null` represents the intentional absence of any object value (a deliberate empty value). `undefined` means a variable has been declared but has not yet been assigned a value. `==` performs type coercion before comparison (e.g., `null == undefined` is true). `===` performs strict comparison, checking both value and type without coercion. Nullish coalescing (`??`) returns the right-hand operand only if the left-hand operand is strictly `null` or `undefined`. Optional chaining (`?.`) allows safe navigation through nested object properties, returning `undefined` immediately if any part of the chain is `null` or `undefined`, preventing runtime errors.

JS12 — `map()` creates a new array by applying a function to every element of the original array, returning a new array of the same length. `filter()` creates a new array containing only elements for which the provided testing function returns `true`. `reduce()` executes a reducer function on each element, resulting in a single output value. With an initial value, `reduce()` starts the accumulation process with that value, ensuring the callback runs at least once, even on an empty array. `flatMap()` maps each element using a function and then flattens the result into a new array by one level, useful when mapping results in an array that themselves return arrays (e.g., mapping categories to lists of items).

JS13 — Template literals (backticks ``) allow embedding expressions directly into strings using `${expression}`. Tagged templates allow a function to intercept and process the string parts and the interpolated values before the final string is constructed. Example (HTML Escaping):
```javascript
const escapeHtml = (strings, ...values) => {
  let result = strings[0];
  values.forEach((value, i) => {
    const escaped = String(value).replace(/[&<>"']/g, match => {
      if (match === '&') return '&amp;';
      if (match === '<') return '&lt;';
      // ... other replacements
      return match;
    });
    result += escaped + strings[i + 1];
  });
  return result;
};
const safeHtml = escapeHtml`<div>Hello ${userInput}</div>`;
```

JS14 — Destructuring is a syntax that allows unpacking values from arrays or properties from objects into distinct variables. **Object Destructuring** pulls properties out based on keys (e.g., `const { name, age } = user;`). **Array Destructuring** pulls values out based on position (e.g., `const [first, second] = arr;`). Default values are assigned if the property/index is missing (e.g., `const { age = 30 } = user;`). Renaming is done using a colon (e.g., `const { name: fullName } = user;`). The rest operator (`...`) collects the remaining, un-destructured properties/elements into a new array or object (e.g., `const { a, ...rest } = obj;`).

JS15 — `for...in` iterates over the *enumerable properties* of an object, including inherited ones (though usually only own properties are intended). `for...of` iterates over the *values* of an iterable object (like Arrays, Strings, Maps). You should avoid `for...in` on arrays because it iterates over keys (indices) as strings, and it can iterate over non-index properties added to the array object, leading to unpredictable iteration order and behavior.

JS16 — Generics allow you to write components that can work over a variety of types while maintaining type safety. **Generic Constraints (`extends`)** restrict the types that can be used with a generic parameter. Example: `function identity<T extends { length: number }>(arg: T): T` ensures `T` has a `length` property. **Conditional Types** allow types to be determined based on a condition. Example: `type IsString<T> = T extends string ? true : false;`. **Infer** is used to infer the type of a variable or function return type based on its usage. Example: `type MyType = infer T;` where `T` takes the type of the variable it is assigned to.

JS17 — The module system defines how code dependencies are managed. **CommonJS** (Node.js standard) uses synchronous `require()` to import and `module.exports` to export. **ES Modules** (standardized JS) use static `import` and `export`. Node.js supports both; files ending in `.js` default to CommonJS unless they contain `"type": "module"` in `package.json` or use `.mjs`. The `"type": "module"` field tells Node.js to treat `.js` files in that project as ES Modules, enabling native `import/export` syntax.

JS18 — TypeScript uses a structural type system, meaning type compatibility is determined by the *shape* of the object (what properties it has and what types they are), not by explicit inheritance declarations. **Excess Property Checks** ensure that an object passed to a function or assigned to a type does not contain properties that are not defined in that type definition. They apply when assigning an object literal to a type. `extends` is used for inheritance (subtyping). `satisfies` is used to assert that an object *conforms* to a type without changing the object's actual type, often used for type checking without losing runtime information. Variance describes how subtyping behaves with generics: `in` (contravariance) means the type can be used in a position expecting a more general type (e.g., `function(in: T)`). `out` (covariance) means the type can be returned from a function (e.g., `function(): out T`).

JS19 — `Proxy` allows you to create an object that wraps another object and intercepts fundamental operations (like property lookups, assignments, function calls) via "traps." `Reflect` is an API that provides standard methods for performing these operations, allowing you to implement custom logic while still adhering to standard JavaScript behavior. Example: Intercepting assignment for validation.
```javascript
const handler = {
  set(target, property, value) {
    if (property === 'age' && typeof value !== 'number') {
      throw new Error('Age must be a number.');
    }
    return Reflect.set(target, property, value);
  }
};
const user = new Proxy({}, handler);
user.age = "twenty"; // Throws error
```

JS20 — `SharedArrayBuffer` provides a way to share raw binary data memory between different execution contexts (like Web Workers). `Atomics` provides methods to perform atomic operations (read-modify-write) on the integer values stored within a `SharedArrayBuffer`. This prevents race conditions when multiple threads access the same memory location. Web Workers communicate by sharing this memory buffer. Ordering guarantees are provided by the atomic operations themselves, ensuring that memory operations appear instantaneous and indivisible to other threads. `Atomics.wait(typedArray, index, expectedValue)` pauses the thread until another thread calls `Atomics.notify()` on that location, signaling a change.

## Bash (20 questions)

B1 — `$@` expands to all positional parameters, treating each parameter as a separate, quoted word (best for iterating over arguments safely). `*` expands to all positional parameters as a single, space-separated string. `"$@"` expands to each argument quoted individually, preserving spaces. `"$*"` expands to all arguments as a single string, separated by the first character of the IFS (Internal Field Separator).

B2 — `set -e`: Exit immediately if a command exits with a non-zero status (error). `set -u`: Treat unset variables as an error and exit immediately. `set -o pipefail`: Causes a pipeline to return a non-zero status if *any* command in the pipeline fails, not just the last one.

B3 — `$(command)` (Command Substitution) executes the command and substitutes its standard output into the current command line. `command` executes the command directly. `((expression))` performs arithmetic evaluation within Bash (integer math). `expr` is an external utility that evaluates expressions, often used for string manipulation or arithmetic, but is slower than Bash's built-in arithmetic expansion.

B4 — Process substitution (`<(command)`) runs a command and makes its standard output available as a temporary file path that the current shell can read from. This is useful when a command needs to be treated as a file argument. Example: `diff <(ls -l) <(ls -l sorted_files.txt)` allows `diff` to compare the output of two separate commands as if they were two distinct files.

B5 — You must use quoting and globbing patterns carefully. The safest way is to use `find` combined with `while read -r` and `find -print0 | xargs -0`. The dangerous `for f in $(ls)` fails because `ls` separates filenames by newlines/spaces, and if a filename contains a space, it is incorrectly split into multiple loop iterations.

B6 — A here document (`<<EOF`) reads multiple lines of input until it encounters the delimiter (`EOF`), preserving newlines and whitespace exactly as written. A here string (`<<<`) passes a single line of text as standard input to a command. `<<-EOF` (here document with a leading tab) allows leading tabs in the input lines to be stripped during processing, which is useful for configuration files.

B7 — `cmd > file 2>&1`: Redirects stdout to `file`, and then redirects stderr (2) to the same location as stdout (1). Both streams go to `file`. `cmd 2>&1 > file`: First, stdout (1) is redirected to `file`. Then, stderr (2) is redirected to the current location of stdout (which is `file`). Both streams go to `file`. The difference is the order of operations; the second command relies on the first redirection being established. `cmd &> file` (or `cmd > file 2>&1`) is a shorthand for redirecting both stdout and stderr to the same file.

B8 — Use `mkdir /tmp/lockfile_name` and then `ln /tmp/lockfile_name /tmp/lockfile_name.lock`. The `mkdir` command is preferred because it is atomic (it either succeeds completely or fails completely), preventing race conditions where two processes might try to create the file simultaneously. To handle cleanup, use `trap 'rm -f /tmp/lockfile_name.lock' EXIT TERM INT`.

B9 — Single quotes (`'...'`) treat everything inside literally; no variable expansion or command substitution occurs. Double quotes (`"..."`) allow variable expansion (`$var`) and command substitution (`$(cmd)`), but still respect escaping (`\"`). No quotes allow word splitting and pathname expansion (globbing), which is dangerous if arguments contain spaces. Example: `echo 'Hello $VAR'` (literal) vs `echo "Hello $VAR"` (expands) vs `echo $VAR` (splits).

B10 — File existence: `[ -f file ]` (is a regular file), `[ -d directory ]` (is a directory). Readability: `[ -r file ]`. `[ ]` is an alias for the `test` command, which returns an exit code (0 for true, 1 for false). `[[ ]]` is a Bash keyword that supports more advanced features like regex matching (`=~`) and logical operators (`&&`, `||`) without requiring external commands.

B11 — `$?`: The exit status of the most recently executed foreground command (0=success, non-zero=failure). `$$`: The Process ID (PID) of the current shell. `$!`: The PID of the most recently backgrounded command. `$#`: The number of positional arguments passed to the script/function.

B12 — Functions are defined using `function name { ... }` or `name() { ... }`. Both are functionally equivalent in modern Bash, though `name() { ... }` is often preferred for brevity. To return values, you typically print the result to stdout, and the calling script captures it using command substitution: `result=$(my_function)`. Bash functions technically only return an exit code (0-255).

B13 — `PATH` is an environment variable containing a colon-separated list of directories where the shell searches for executable commands. Bash resolves commands by iterating through the directories listed in `$PATH` until it finds an executable file matching the command name. A builtin command is a command built directly into the shell (e.g., `cd`, `echo`) and runs within the current shell process. An external command is a separate executable file found in a directory listed in `$PATH`. You can check using `type command_name`.

B14 — `trap` allows you to specify commands to run when the shell receives a specific signal. `trap 'cleanup_script' EXIT`: Runs cleanup when the script exits normally. `trap 'cleanup_script' ERR`: Runs when a command fails (non-zero exit status). `trap 'cleanup_script' INT` (Ctrl+C) and `TERM` (kill) are used for graceful shutdown. Execution order: Signals are handled sequentially based on the trap definition. If multiple signals arrive simultaneously, the OS handles the delivery, but the shell executes the associated traps in the order they were set.

B15 — `xargs` takes standard input and builds and executes command lines from it. Command substitution (`$(cmd)`) captures the output of a command as a string argument. `xargs` is superior for executing commands on a list of inputs. To handle spaces/newlines safely: `find . -type f -print0 | xargs -0 rm`. `-0` tells `xargs` to expect null-terminated input. `-P N` specifies running up to N processes in parallel.

B16 — Standard arrays are indexed numerically (0, 1, 2...). Associative arrays (or hash maps) are indexed by string keys. Declaration: `my_array=(item1 item2)`. Associative: `declare -A my_assoc`. Iteration: Standard uses `for item in "${my_array[@]}"`. Associative uses `for key in "${!my_assoc[@]}"; do echo $key; done`. Length: Standard uses `${#my_array[@]}`. Associative uses `${#my_assoc[@]}`.

B17 — A subshell (`(...)`) executes commands in a separate, child process. Any variables set or modified inside the subshell are lost when it exits, as they do not affect the parent shell's environment. A group command (`{ ...; }`) executes commands in the *current* shell process. Variables modified inside the group persist. Piping into a `while` loop (`while read line; do ... done < file`) runs the loop in a subshell by default, meaning any variable changes made inside the loop body are lost upon loop completion. To prevent this, use process substitution or redirect input: `while IFS= read -r line; do ... done < file`.

B18 — Bash handles signals by delivering them to the running process. `SIGINT` (Interrupt, Ctrl+C) is usually handled by the shell. `SIGTERM` (Terminate) is the standard, graceful shutdown request. `SIGHUP` (Hangup) is often sent when a controlling terminal disconnects. `SIGKILL` (Kill) cannot be caught or ignored; the OS immediately terminates the process. For graceful shutdown, use `trap` to catch `SIGTERM` and `SIGINT`, allowing the script to finish current tasks and clean up background processes before exiting.

B19 — This requires splitting the file, running the function in parallel, and merging.
1. `split -l 10000 large_log.txt split_part_` (Splits into chunks of 10k lines).
2. `find . -name "split_part_*" -print0 | xargs -0 -P 4 -I {} bash -c 'process_file "$@"' _ {}` (Runs `process_file` on 4 chunks in parallel).
3. `cat processed_part_* > merged_results.txt` (Merges results).
Performance trade-offs: Parallelism speeds up I/O-bound tasks but introduces overhead from process creation and context switching. Error propagation is handled by checking the exit code of the `xargs` command or by having the processing function explicitly write an error marker to its output file, which the final merge step can check.

B20 — `exec command` replaces the current shell process entirely with the new command; it does not spawn a child process. This is useful for resource efficiency. For file descriptor manipulation: `exec 3> log.txt` opens file descriptor 3 for writing. `exec 3>&-` closes file descriptor 3. A bash coprocess allows a parent shell to communicate with a child process using named pipes (FIFOs) for bidirectional communication, similar to pipes but managed explicitly by the shell. Use it when you need a persistent, two-way communication channel with a background task that needs to interact with the parent shell's state or receive complex commands.

## PowerShell (20 questions)

PS1 — `Write-Output` sends objects down the pipeline, allowing them to be processed by subsequent cmdlets. `Write-Host` writes directly to the console host, bypassing the pipeline. The distinction matters because objects sent via `Write-Output` retain their type and structure, enabling cmdlets to act upon them; objects written via `Write-Host` are just formatted strings and cannot be piped further.

PS2 — The PowerShell pipeline passes objects, not just strings, from one cmdlet to the next. `ForEach-Object` (or its alias `%`) is a cmdlet that processes objects received from the pipeline. The `foreach` statement is a standard PowerShell language construct used for iterating over collections (arrays, lists) *within* a script block or function, not for processing pipeline input. Use `ForEach-Object` when processing pipeline streams; use `foreach` when iterating over a local collection variable.

PS3 — `[PSCustomObject]` creates a lightweight, dynamic object structure with named properties, ideal for creating structured output that can be easily piped and consumed by other cmdlets. `[hashtable]` is a key-value collection, similar to a dictionary, where you access values by key. Use `[PSCustomObject]` when you need a defined, structured object output. Use `[hashtable]` when you need a flexible, dynamic map structure for configuration or lookups. Conversion: `[PSCustomObject]@{Key = $hashtable.Key}` or `$hashtable | ConvertTo-Object`.

PS4 — PowerShell distinguishes between **Terminating Errors** (which stop the current operation/script execution, like a missing required parameter) and **Non-Terminating Errors** (which are warnings or recoverable issues). `-ErrorAction Stop` forces a non-terminating error to become terminating. `$ErrorActionPreference` sets the default behavior for error handling (e.g., `Stop`, `Continue`, `SilentlyContinue`). `try/catch` allows you to explicitly catch terminating errors, allowing the script to continue execution after handling the exception.

PS5 — Splatting (`@params`) is a technique where you pass a hashtable containing parameter names and their corresponding values to a cmdlet. This allows you to define all parameters in a single, reusable data structure, making scripts cleaner and easier to modify. Example: `Get-Service @params`, where `@params` is `$serviceParams = @{Name = 'Spooler'; Status = 'Running'}`. This differs from passing a hashtable as a single parameter because splatting unpacks the hashtable into individual named parameters recognized by the cmdlet.

PS6 — PowerShell Remoting allows remote execution of cmdlets. `Invoke-Command -ComputerName` executes a script block or cmdlet on a remote machine and returns the results to the local session. `Enter-PSSession` establishes an interactive, persistent session on the remote machine, allowing you to run commands as if you were logged in locally. Both typically use WinRM (Windows Remote Management) over HTTP/HTTPS. While SSH is used for Linux/Unix remoting, WinRM is the native protocol for Windows PowerShell remoting.

PS7 — The issue arises because PowerShell's pipeline implicitly casts objects. When you append a string `"one"` to an empty array `$result = @()`, PowerShell often treats the array as a generic collection of strings, and the return value is treated as a generic object collection. When the function returns 0 items, it returns `$null` or an empty collection, which can be interpreted differently depending on context. The correct pattern is to ensure the function explicitly returns the collection using `return $result` or by using `Write-Output $result` if you want the output stream to contain the collection.

PS8 — A `[scriptblock]` is a block of code that can be passed as a parameter (e.g., to `Invoke-Command`). A function is a named, reusable block of code that can accept parameters and return values. You pass a scriptblock to a remote session using the `-ScriptBlock` parameter of `Invoke-Command`. The double-hop problem occurs when variables defined locally are not available in the remote session's scope. You solve this by using `Invoke-Command -ArgumentList` to explicitly pass variables, or by using `$using:` scope modifier within the scriptblock to access local variables.

PS9 — `@()` creates an empty array object. `[array]` is a type accelerator that forces an object to be treated as an array. To force a single result into an array, wrap it in parentheses: `($single_value)`. Indexing into `$null` throws a terminating error. Indexing into an empty array (`@()`) will result in `$null` being returned for that index, without throwing an error.

PS10 — `-eq` (equals), `-ne` (not equals), `-like` (wildcard matching, uses `*` and `?`), `-match` (regex matching), `-contains` (checks if an array contains a specific element), `-in` (checks if a value is present in a list/array). Case-sensitive variants (`-ceq`, `-clike`, etc.) enforce case sensitivity. The difference between `-contains` and `-in` is that `-contains` checks if the *value* is present in the collection, while `-in` checks if the *value* matches any item in the list (often used with regex or simple membership).

PS11 — A PowerShell module is a container for cmdlets, functions, variables, and data. A **script module (.psm1)** is a script file that defines the module's contents. A **manifest module (.psd1)** is a metadata file that describes the module (version, dependencies, required parameters) but contains no code. A **binary module** contains compiled code (e.g., .dlls). `Import-Module` loads the module's definitions into the current session's scope, making its cmdlets available.

PS12 — String interpolation uses double quotes (`"..."`). Expressions are included by placing them inside curly braces: `"The value is $($variable)"`. Single quotes (`'...'`) treat everything literally, preventing interpolation. A here-string (`@"`...`"@`) allows multi-line strings while still supporting variable interpolation, similar to template literals in JS.

PS13 — `Get-Member` returns a list of properties and methods available on an object. **Properties** are data members (attributes). **Methods** are executable functions associated with the object. **NoteProperties** are properties that are not standard object properties but are metadata attached to the object. `Select-Object` chooses which properties to display. `Where-Object` filters the objects based on a condition applied to their properties.

PS14 — PowerShell classes (v5+) are object-oriented constructs that allow defining custom types, methods, and state. They are similar to C# classes but are more loosely typed and dynamically managed by the PowerShell runtime. Limitations include less strict compile-time checking compared to C#, and inheritance/interface implementation is less rigid than in strongly typed languages. Use a class when you need to model a complex entity with encapsulated state and behavior (e.g., a `User` object). Use a function when you need a reusable block of logic that operates on input without maintaining persistent state.

PS15 — `CmdletBinding()` enables advanced function features, allowing the function to behave like a native cmdlet (e.g., accepting common parameters like `-Verbose`, `-Debug`). `SupportsShouldProcess` allows the cmdlet to check if the user wants to proceed with a potentially destructive action (e.g., `ShouldProcess`). `DefaultParameterSetName` sets the default set of parameters used. `ValueFromPipeline` allows the cmdlet to accept input objects from the pipeline. The pipeline execution follows: `Begin` (setup), `Process` (iterates over input objects, performing the main work), and `End` (cleanup).

PS16 — Providers are objects that allow PowerShell to treat different types of data sources (like the File System, Registry, or Environment Variables) using a unified object model. `Get-ChildItem` uses the provider's specific implementation to list contents. To access the registry like a file system, you use the `Registry` provider: `Get-ChildItem -Path "HKLM:\Software"`.

PS17 — A `[runspace]` is an isolated execution environment where PowerShell commands run. A `[runspacepool]` manages a pool of runspaces to handle concurrent requests efficiently. A `[powershell]` object represents the PowerShell engine itself. For parallel execution in v7+, `ForEach-Object -Parallel` manages the runspace pooling internally, simplifying the code. Manual runspace management is necessary for complex, long-running, or highly customized parallel operations where you need fine-grained control over resource allocation.

PS18 — PSScriptAnalyzer is a static code analysis tool that enforces coding standards and best practices in PowerShell scripts. It uses predefined **rules** (e.g., "Do not use global variables") which are assigned **severity levels** (e.g., Warning, Error). You suppress rules using `#SuppressMessage` comments. It integrates into CI/CD pipelines by running as a pre-commit or build step, failing the build if critical rules are violated.

PS19 — `$using:` scope allows variables defined in the parent scope (the calling script) to be accessed by child processes (like remote sessions or parallel jobs) by explicitly passing them into the child's scope. `$args/-ArgumentList` is used to pass arguments explicitly to a remote session or job. Serialization limits (CLIXML depth) restrict the complexity and depth of objects that can be reliably passed across the WinRM boundary. Deeply nested or very large custom objects may fail serialization, requiring flattening or manual serialization/deserialization.

PS20 — Desired State Configuration (DSC) is a management framework that enables you to define the desired configuration state of a system (e.g., "Ensure IIS is installed and running"). **Configurations** define the desired state. **Resources** are the specific components that implement the desired state (e.g., the `Service` resource ensures a service is running). The **Local Configuration Manager (LCM)** is the engine that enforces the configuration on the target node. In modern infrastructure-as-code, DSC has largely been superseded by cloud-native tools like Ansible, Terraform, and Azure/AWS native configuration services, though DSC remains relevant in deep Windows Server environments.
