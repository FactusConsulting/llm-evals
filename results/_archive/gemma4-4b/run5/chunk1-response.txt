**Networking**

N1 — A Layer 2 switch operates at the Data Link Layer (Layer 2) and forwards frames based on MAC addresses. A Layer 3 switch operates at the Network Layer (Layer 3) and can perform routing functions (forwarding packets based on IP addresses), allowing it to route traffic between different subnets, unlike a pure L2 switch.

N2 — The IP address is 10.0.5.37/20.
*   The subnet mask for /20 is 255.255.240.0.
*   The network address is calculated by masking: $10.0.5.37 \text{ AND } 255.255.240.0 = 10.0.0.0$.
*   The broadcast address is the last address in the range: $10.0.15.255$.

N3 — The TCP three-way handshake establishes a connection:
1.  **SYN (Synchronize):** Client sends a SYN packet to the server, requesting a connection and proposing an initial sequence number (ISN).
2.  **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and replies with a SYN-ACK packet, acknowledging the client's SYN and proposing its own ISN.
3.  **ACK (Acknowledge):** Client receives SYN-ACK and sends a final ACK packet, acknowledging the server's SYN-ACK. The connection is established.
If the final ACK is lost, the client will retransmit the ACK (or the server will time out and retransmit SYN-ACK), leading to connection timeouts on the client side until the retransmission succeeds or the connection attempt fails.

N4 — **SNAT (Source Network Address Translation):** Translates the source IP address of a packet as it leaves a private network, replacing it with a public IP address. *Example: A host on a private LAN (192.168.1.10) accessing the internet uses the router's public IP as its source address.*
**DNAT (Destination Network Address Translation):** Translates the destination IP address of a packet as it enters a private network, redirecting traffic from a public IP to a specific internal private IP. *Example: A public web server IP (203.0.113.5) is configured to forward incoming traffic to an internal web server (192.168.1.50).*

N5 — 3 possible causes:
1.  **Hostname Mismatch:** The certificate was issued for a different domain name than the one being accessed (e.g., certificate is for `api.example.com` but you accessed `example.com`).
2.  **Expired Certificate:** The certificate has passed its validity date.
3.  **Incorrect Configuration:** The server is presenting the wrong certificate, or the certificate chain is incomplete/malformed.

N6 — **VLAN (Virtual LAN):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains within the same physical switch infrastructure, using 802.1Q tagging to carry traffic across trunks.
**VxLAN (Virtual Extensible LAN):** An overlay network technology that encapsulates Layer 2 Ethernet frames within Layer 4 UDP packets, allowing L2 segments to span across Layer 3 networks (IP underlay).
You would choose VxLAN over VLAN when you need to scale beyond the 4094 VLAN limit, or when you need to extend Layer 2 domains across a large, multi-subnet data center fabric (L3 underlay).

N7 — Traffic arriving on eth1 (192.168.1.0/24) is being replied to via eth0 (10.0.0.0/24) because the routing decision is based on the *destination* IP address, not the ingress interface. The kernel uses the main routing table, which likely points the return traffic toward the default gateway (10.0.0.1) via eth0.
**Fix using Policy-Based Routing (PBR):** You must create a routing rule that specifies that traffic originating from the 192.168.1.0/24 subnet *must* use the eth1 interface for egress, overriding the default routing table. This is typically done using `ip rule add from 192.168.1.0/24 table <custom_table>` and then defining the route in that custom table pointing back to the correct gateway/interface.

N8 — BGP path selection is a complex process where routers evaluate multiple attributes to determine the best path to a destination prefix. The process is sequential; the first attribute that provides a definitive preference is used.
**5 Attributes (in general preference order):**
1.  Weight (Cisco proprietary, highest preference)
2.  Local Preference (Highest preference within an AS)
3.  AS Path Length (Shorter is better)
4.  Origin Type (IGP > EGP > Incomplete)
5.  MED (Multi-Exit Discriminator - Lower is better)

N9 — When running VxLAN over an IPsec tunnel, the encapsulation layers are: Original L2 Frame $\rightarrow$ VxLAN Header $\rightarrow$ UDP Header $\rightarrow$ IPsec Header $\rightarrow$ Outer IP Header.
The physical MTU (1500) must accommodate all these headers.
*   VxLAN Header: 50 bytes
*   UDP Header: 8 bytes
*   IPsec Overhead (ESP/AH): Typically 50-70 bytes (assuming ESP with padding/auth)
*   Outer IP Header: 20 bytes
Total Overhead $\approx 50 + 8 + 60 + 20 = 138$ bytes.
Maximum Inner Payload = Physical MTU - Total Overhead = $1500 - 138 = 1362$ bytes.

N10 — **ARP (Address Resolution Protocol):** Maps a known Layer 3 IP address to its corresponding Layer 2 MAC address within a local subnet. It works by broadcasting an ARP request asking, "Who has this IP? Tell me your MAC."
**Gratuitous ARP:** A host broadcasts an ARP request for its *own* IP address. This solves problems like stale ARP caches on other devices, ensuring that neighboring routers and switches immediately update their MAC address tables with the host's current MAC address, which is crucial after a host changes its IP or moves.

N11 — **Public IP Address:** Globally unique, routable IP address assigned by an ISP, allowing direct communication over the public internet.
**Private IP Address:** Non-routable IP address reserved for use within private networks (LANs).
**RFC 1918 Private IPv4 Ranges:**
1.  10.0.0.0 to 10.255.255.255 (/8)
2.  172.16.0.0 to 172.31.255.255 (/12)
3.  192.168.0.0 to 192.168.255.255 (/16)

N12 — **DNS (Domain Name System):** A hierarchical and distributed naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses (like 93.184.216.34).
*   **A Record:** Maps a domain name to an IPv4 address.
*   **CNAME Record (Canonical Name):** Creates an alias, mapping one domain name to another canonical domain name (e.g., `blog.example.com` CNAMEs to `example.com`).
*   **AAAA Record:** Maps a domain name to an IPv6 address.

N13 — **DHCP (Dynamic Host Configuration Protocol):** A network protocol that automatically assigns IP configuration parameters (IP address, subnet mask, default gateway, DNS servers) to devices on a network.
**DORA Process:**
1.  **Discover:** Client broadcasts a DHCP Discover message to find available servers.
2.  **Offer:** Server responds with a DHCP Offer, proposing an IP address and configuration.
3.  **Request:** Client sends a DHCP Request, formally accepting the offered configuration.
4.  **Acknowledge:** Server sends a DHCP ACK, finalizing the lease and providing all necessary configuration details.

N14 — **Hub:** Operates at Layer 1 (Physical). It is a simple repeater that broadcasts all incoming electrical signals to every connected port, creating a single collision domain.
**Switch:** Operates at Layer 2 (Data Link). It learns MAC addresses and forwards frames only to the intended destination port, creating smaller collision domains.
**Router:** Operates at Layer 3 (Network). It connects different networks (subnets) and forwards packets based on IP addresses, making routing decisions.

N15 — **Half-Duplex:** Allows data transmission in only one direction at a time (e.g., a walkie-talkie). If one device is transmitting, the other must listen.
**Full-Duplex:** Allows simultaneous transmission and reception of data over the same link (e.g., a telephone call).
Modern Ethernet links overwhelmingly use **full-duplex** communication.

N16 — The **TTL (Time To Live)** field is an 8-bit counter in the IP header that limits the lifespan of a packet. Each router that forwards the packet decrements the TTL by one. If the TTL reaches zero, the router discards the packet and typically sends an ICMP Time Exceeded message back to the source.
**Traceroute Exploitation:** Traceroute works by intentionally setting the TTL field to 1, 2, 3, and so on. When the TTL is set to 1, the first router decrements it to 0 and sends an ICMP Time Exceeded message, revealing the identity of the first hop. By incrementing the TTL, the traceroute maps the path hop-by-hop until the destination is reached.

N17 — A **NAT Gateway** is a device (usually a router or firewall) that performs Network Address Translation, allowing multiple private devices to share a single public IP address when accessing the internet.
*   **Static NAT:** A one-to-one mapping where a specific private IP is permanently mapped to a specific public IP (e.g., for hosting a server).
*   **Dynamic NAT:** Maps private IPs to a pool of available public IPs on a first-come, first-served basis.
*   **PAT (Port Address Translation) / NAT Overload:** Maps multiple private IPs to a single public IP by tracking unique source port numbers. This is the most common form used in homes/offices.

N18 — **ECMP (Equal-Cost Multi-Path):** Allows a router to install multiple paths in its routing table to the same destination prefix if those paths have the same routing metric (cost). The router can then load-balance traffic across these multiple paths simultaneously.
**Hashing Strategies:** Common strategies include hashing based on the 5-tuple (Source IP, Destination IP, Source Port, Destination Port, Protocol).
**Asymmetric Flows Problem:** If stateful firewalls are involved, asymmetric flows (where traffic enters via one interface/path and returns via another) can cause connection state tracking failures. The firewall might drop the return packet because it never saw the initial outbound packet on the expected interface, leading to connection resets.

N19 — The problem is **Bandwidth-Delay Product (BDP) limitation**. BDP = Bandwidth $\times$ Round Trip Time (RTT). If the BDP is 10MB, the pipe can theoretically hold 10MB of unacknowledged data. If the TCP window size is capped at 64KB, the sender can only inject 64KB into the pipe before waiting for an ACK, regardless of the pipe's capacity. This forces the connection to operate at a much lower throughput than the physical link allows.
**TCP Window Scaling (RFC 1323):** This extension allows the TCP header to carry a much larger advertised receive window size (up to 1GB), effectively increasing the sender's ability to fill the BDP and maximizing throughput over high-latency, high-bandwidth links.

N20 — **802.1Q Trunk Ports:** A mechanism used on switches to allow traffic from multiple VLANs to traverse a single physical link (trunk). It achieves this by inserting a 4-byte VLAN tag into the Ethernet frame header.
**Linux Configuration (Sub-interfaces):** The physical interface (e.g., `eth0`) is configured as a trunk, and logical sub-interfaces are created for each VLAN.
Example: `eth0.10` (for VLAN 10), `eth0.20` (for VLAN 20), etc. Each sub-interface is assigned the appropriate IP address for its respective VLAN.
**Frame Format:** The frame structure is: Ethernet Header $\rightarrow$ **802.1Q Tag (VLAN ID)** $\rightarrow$ Original Ethernet Header $\rightarrow$ Payload.

**Linux**

L1 — **Hard Link:** A directory entry that points directly to the same inode (the metadata structure) as the original file. Both the original name and the hard link name refer to the exact same data blocks on disk. Deleting one link does not delete the data until the last link is removed.
**Symbolic Link (Symlink):** A special file that contains a text path pointing to another file or directory. It is a pointer, not a direct reference to the inode. If the target file is moved or deleted, the symlink breaks (dangling link).

L2 — Use the `find` command:
`find /var/log -type f -size +100M`

L3 — State D (Uninterruptible Sleep) means the process is waiting for an I/O operation (e.g., disk read/write) to complete. The kernel cannot interrupt this wait, even with signals.
No, you generally **cannot** kill it with `kill -9` (SIGKILL). Since the process is blocked waiting for hardware, SIGKILL might not be processed immediately, or the kernel might prevent the termination until the I/O completes, potentially leading to data corruption or system instability if the I/O is critical. The process must complete its I/O cycle naturally.

L4 — **cgroups v1:** Used a hierarchical, resource-specific model (e.g., CPU controller, Memory controller). It was often complex to manage and lacked unified resource control.
**cgroups v2:** Implements a unified hierarchy and a unified control plane. It provides a cleaner, more consistent view of resource usage across all controllers, simplifying management and ensuring better isolation.
Systemd prefers **cgroups v2** because it offers a more modern, unified, and robust resource management model that aligns better with its service management philosophy.

L5 — **iptables:** The older, traditional Linux firewall framework. It uses chains (INPUT, OUTPUT, FORWARD) and tables to process rules sequentially.
**nftables:** The modern replacement for iptables. It uses a more flexible, unified syntax and data structure, allowing for more complex rule sets and better performance by processing rules in a single, optimized structure.
The kernel handles both by maintaining compatibility layers. When `iptables` rules are loaded, they are translated and managed internally by the kernel's networking stack, which is increasingly optimized to use the `nftables` backend for execution.

L6 — The most likely cause is that the filesystem contains a large number of **small files** or **metadata** that are not easily aggregated by `du -sh /*`. `du` calculates the disk usage of the *contents* of the directories, while `df -h` reports the total blocks allocated to the filesystem, which includes metadata overhead, inodes, and block allocation structures that might not be fully reflected in the directory sum.

L7 — **UEFI Firmware:** Initializes hardware and loads the bootloader.
**Bootloader (e.g., GRUB):** Reads the kernel image and the initial RAM disk (`initramfs`) from the storage device and loads them into memory.
**Kernel:** Takes control. It initializes drivers, mounts the root filesystem, and starts the initial userspace process.
**Initramfs:** A minimal, temporary root filesystem loaded into memory. Its job is to contain the necessary drivers (e.g., for storage controllers) to locate and mount the *real* root filesystem.
**Root Filesystem:** The kernel mounts the actual, persistent root filesystem (e.g., ext4).
**Systemd:** The kernel executes `/sbin/init` (which is systemd). Systemd then takes over, managing all services, dependencies, logging, and reaching the final operational target state (e.g., `multi-user.target`).

L8 — The OOM (Out-Of-Memory) killer fires when the kernel determines that memory pressure is critical. Even if `buff/cache` is high, the kernel must reserve a certain amount of memory for active processes and kernel structures. If the *available* memory (memory immediately usable by processes without needing to reclaim cache) drops too low, the OOM killer activates to reclaim memory by terminating processes, even if the total used memory is lower than the physical RAM capacity.
**Kernel Tunables:** `vm.swappiness` (controls how aggressively the kernel swaps out anonymous memory) and `vm.min_free_kbytes` (sets the minimum amount of memory the kernel should keep free).

L9 — `ip netns` allows the creation and management of network namespaces. A network namespace provides an isolated view of the system resources (network interfaces, routing tables, process IDs, etc.) for a specific group of processes.
Container runtimes (like Docker or Kubernetes) use network namespaces to give each container its own isolated network stack. The container sees its own private interfaces, IP addresses, and routing table, completely separate from the host system's network stack.

L10 — **SIGTERM (Signal 15):** A polite request for a process to terminate. The process can catch this signal, perform cleanup (save state, close files), and exit gracefully.
**SIGKILL (Signal 9):** A forceful, immediate termination signal. The process cannot catch, ignore, or block this signal; the kernel terminates it instantly.
**SIGQUIT (Signal 3):** Requests the process to quit, often causing it to dump a core file for debugging. It can be caught by the process.

L11 — **stdout (Standard Output):** Where a program sends normal, expected output (e.g., successful results).
**stderr (Standard Error):** Where a program sends error messages and diagnostic output.
**stdin (Standard Input):** Where a program receives input (e.g., from the keyboard or a pipe).
To redirect stderr to a file while displaying stdout on the terminal:
`command 2> error.log` (This redirects file descriptor 2, stderr, to the file).

L12 — `chmod 755 filename` sets permissions:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = 7. The owner has full control.
*   **5 (Group):** Read (4) + Execute (1) = 5. The group can read and execute, but not write.
*   **5 (Others):** Read (4) + Execute (1) = 5. All other users can read and execute, but not write.

L13 — **Root User (UID 0):** Has absolute, unrestricted privileges over the entire operating system. It can read, write, and modify any file or configuration.
**Sudo User:** A standard user who is granted specific, limited permissions to execute certain commands as another user (usually root) using the `sudo` command. This allows for granular control over what the user can modify, minimizing the risk of accidental system damage.

L14 — **Package Manager:** A system utility used to automate the installation, upgrading, configuration, and removal of software packages on a Linux system.
**Debian/Ubuntu:** APT (Advanced Package Tool) / dpkg.
**RHEL/Fedora:** YUM or DNF (Dandified Yum).

L15 — The `/etc/fstab` (filesystem table) file defines how disk partitions, network shares, and other filesystems should be mounted at boot time.
If an entry is misconfigured (e.g., wrong UUID, incorrect filesystem type, or missing device), the system will fail to mount that filesystem during the boot sequence, potentially halting the boot process or causing the system to boot into a degraded state if the filesystem is critical.

L16 — **LVM (Logical Volume Manager):** A layer of abstraction that sits between physical storage devices and the filesystem. It allows administrators to manage storage flexibly, resizing, moving, and combining physical disks without needing to repartition the underlying hardware.
*   **Physical Volumes (PV):** The actual physical storage devices (e.g., hard drives or partitions) that LVM uses.
*   **Volume Groups (VG):** A pool of storage capacity created by combining one or more PVs.
*   **Logical Volumes (LV):** The virtual partitions carved out of the VG that are then formatted and mounted as filesystems.
**Extending an LV:** 1. Extend the underlying PV (if necessary). 2. Extend the VG to include the new space. 3. Extend the LV using `lvextend`. 4. Resize the filesystem on the LV using `resize2fs` (for ext4).

L17 — The I/O scheduler determines the order in which read/write requests are serviced by the block device driver to optimize throughput and latency.
*   **mq-deadline:** Prioritizes requests based on deadlines, balancing throughput and latency. Good for mixed workloads.
*   **bfq (Budget Fair Queueing):** Designed for desktop/interactive workloads, prioritizing fairness and low latency for individual processes.
*   **none:** Bypasses the scheduler, allowing the hardware or application to manage I/O scheduling directly. Best for high-performance storage arrays or specialized workloads.
**Changing Scheduler:** Use the `echo` command to write the desired scheduler name to the device's `scheduler` file: `echo bfq > /sys/block/sdX/queue/scheduler`.

L18 — **Load Average:** Measures the average number of processes in the run queue (waiting for CPU time) or in uninterruptible sleep (waiting for I/O) over the last 1, 5, and 15 minutes. It is a measure of system *activity*, not just CPU utilization.
**I/O Wait Inflation:** If processes are stuck in uninterruptible sleep (D state) waiting for slow disk I/O, they contribute to the load average, even if the CPU itself is idle.
**Diagnosis:**
*   **CPU Bottleneck:** High `us` (user) and `sy` (system) CPU usage, low `wa` (iowait). Use `top` or `htop`.
*   **Disk Bottleneck:** High `wa` (iowait) percentage in `top`, and high utilization reported by `iostat` or `iotop`.
*   **Network Bottleneck:** High packet drops or high utilization reported by interface statistics (`ip -s link`) or monitoring tools.

L19 — **SELinux (Security-Enhanced Linux):** Enforces Mandatory Access Control (MAC). Instead of relying solely on DAC (Discretionary Access Control, i.e., standard Linux permissions), SELinux assigns security contexts (labels) to every subject (process) and object (file/port). Access is only granted if the policy explicitly permits the transition between the subject's context and the object's context.
*   **Enforcing:** SELinux actively denies access based on policy violations.
*   **Permissive:** SELinux logs violations but does not enforce them, allowing the application to run while logging what *would* have been denied.
*   **Disabled:** SELinux is inactive, relying only on standard DAC.
**Troubleshooting:** Check the audit logs (`/var/log/audit/audit.log`). If a daemon fails to bind a port, the logs will show a `denial` message indicating the process context lacks the necessary permission to bind to that specific port number or network resource. You must then use `semanage` or `chcon` to adjust the policy or context.

L20 — **Page Fault:** An event that occurs when a program tries to access a virtual memory address whose corresponding physical memory page is not currently loaded into RAM.
*   **Minor Page Fault:** The required page is not in RAM, but it *is* present on disk (e.g., in the swap space or file cache). The kernel resolves this quickly by loading the page into RAM without needing to modify the process's memory map significantly.
*   **Major Page Fault:** The required page is not in RAM and is not readily available in the cache; it must be fetched from the original backing store (e.g., the original executable file on disk). This is a slow operation involving significant I/O.
**THP (Transparent Huge Pages):** THP attempts to automatically coalesce small 4KB memory pages into larger 2MB pages to reduce TLB misses and improve memory access efficiency.
**Disabling THP:** You disable it when applications exhibit unpredictable latency spikes or when the workload is highly sensitive to memory access timing (e.g., real-time trading or certain database operations), as the background compaction process used by THP can introduce unpredictable latency jitter.
