**N1**
A Layer 2 switch operates at the Data Link Layer (Layer 2) and forwards frames based on MAC addresses. A Layer 3 switch operates at the Network Layer (Layer 3) and can route packets between different IP subnets using IP addresses, effectively combining the high-speed switching capabilities of L2 with the routing capabilities of a router.

**N2**
The subnet mask for /20 is 255.255.240.0.
*   **Network Address:** 10.0.32.0
*   **Broadcast Address:** 10.0.47.255

**N3**
The TCP three-way handshake establishes a reliable connection:
1.  **SYN (Synchronize):** Client sends a SYN packet to the server, proposing an initial sequence number (ISN).
2.  **SYN-ACK (Synchronize-Acknowledge):** Server receives SYN, allocates resources, and replies with a SYN packet (proposing its own ISN) and an ACK acknowledging the client's SYN.
3.  **ACK (Acknowledge):** Client receives SYN-ACK and sends a final ACK, confirming receipt and completing the handshake.

If the final ACK is lost, the client will retransmit the ACK (or the server will time out waiting for the final ACK and retransmit its SYN-ACK). The connection will eventually time out on the client side, leading to a connection failure, unless the client's retransmission timer expires first.

**N4**
*   **SNAT (Source Network Address Translation):** Changes the source IP address of a packet as it leaves a private network, replacing it with the public IP of the NAT device. *Example: A host on a private LAN (192.168.1.10) accessing the internet uses the router's public IP as its source address.*
*   **DNAT (Destination Network Address Translation):** Changes the destination IP address of a packet as it enters a private network. *Example: An external user accessing a web server via the public IP (203.0.113.5) is redirected by the NAT gateway to the internal server's private IP (192.168.1.50).*

**N5**
1.  **Mismatched Hostname:** The hostname in the certificate (Subject Alternative Name or Common Name) does not exactly match the hostname used in the `curl` request.
2.  **Expired/Invalid Certificate:** The certificate has expired, is revoked, or is otherwise untrusted by the client's CA store.
3.  **Incorrect TLS Configuration:** The client or server is using an outdated or non-standard TLS cipher suite that causes a handshake failure related to identity verification.

**N6**
*   **VLAN (Virtual LAN):** A Layer 2 segmentation mechanism that logically groups devices into broadcast domains within the same physical switch infrastructure, using 802.1Q tagging to carry traffic across trunks. VLANs are limited by the 4094 tag space and the physical constraints of the underlying network.
*   **VxLAN (Virtual Extensible LAN):** A network virtualization overlay protocol that encapsulates Layer 2 Ethernet frames within UDP/IP packets. It uses a 24-bit VXLAN Network Identifier (VNI), allowing for over 16 million logical segments.

You would choose VxLAN over VLAN when you need to extend Layer 2 domains across a large, multi-subnet, or geographically dispersed IP network (i.e., when VLANs cannot span the required distance or scale).

**N7**
The traffic is being replied via eth0 because the Linux kernel uses the routing table to determine the egress interface. Since eth0 has the default gateway (10.0.0.1), the kernel assumes that traffic destined for the 192.168.1.0/24 subnet (which is not directly connected via eth0) must be routed through the default gateway.

To fix this with policy-based routing (PBR), you must create a routing rule that specifically matches traffic originating from or destined for the 192.168.1.0/24 subnet and forces the egress interface to be `eth1`. This is typically done using `ip rule add from 192.168.1.0/24 table X` and then setting the route for that subnet in table X to use `eth1`.

**N8**
BGP path selection is a deterministic process used by routers to choose the best path among multiple valid routes advertised by different peers. The attributes are evaluated sequentially; the first attribute that provides a decisive difference determines the best path.

The standard order of preference (simplified, as there are many tie-breakers) is:
1.  **Weight** (Cisco proprietary, highest preference)
2.  **Local Preference** (Highest is preferred)
3.  **Locally Originated** (Prefer routes originated locally)
4.  **AS Path Length** (Shortest path is preferred)
5.  **Origin Type** (IGP > EGP > Incomplete)

**N9**
When running VxLAN over an IPsec tunnel, the original Layer 2 frame (which is encapsulated by VxLAN) is then encapsulated again by IPsec (which adds headers for encryption and authentication).
*   Physical MTU = 1500 bytes.
*   VxLAN Header Overhead: $\approx 50$ bytes (VNI, UDP, etc.)
*   IPsec Overhead (ESP/AH): $\approx 50-70$ bytes (depending on encryption/auth)
*   Outer IP Header Overhead: 20 bytes.

Maximum Inner Payload = Physical MTU - (VxLAN Overhead + IPsec Overhead + Outer IP Header Overhead)
Maximum Inner Payload $\approx 1500 - (50 + 60 + 20) = 1370$ bytes.

**N10**
ARP (Address Resolution Protocol) is used to map a known Layer 3 IP address to its corresponding Layer 2 MAC address within a local subnet. It works by broadcasting an ARP request asking, "Who has this IP address? Tell me your MAC address."

Gratuitous ARP (GARP) is a packet sent by a host to itself (or broadcasted) containing its own IP-to-MAC mapping. It solves the problem of stale ARP caches. GARP is used to announce a new MAC address for an existing IP (e.g., after a host changes NICs) or to confirm that a host is available, preventing other devices from using an old, cached MAC address.

**N11**
*   **Public IP Address:** An IP address globally unique and routable on the public internet. It must be assigned by an IANA-approved registry.
*   **Private IP Address:** An IP address reserved for use within private, internal networks (LANs). These addresses are not routable on the public internet and require NAT to communicate externally.

The three private IPv4 ranges defined in RFC 1918 are:
1.  10.0.0.0/8
2.  172.16.0.0/12
3.  192.168.0.0/16

**N12**
*   **DNS (Domain Name System):** A hierarchical and decentralized naming system that translates human-readable domain names (like `example.com`) into machine-readable IP addresses (like 93.184.216.34).

*   **A Record:** Maps a domain name to an IPv4 address (e.g., `example.com` $\rightarrow$ 192.0.2.1).
*   **CNAME Record (Canonical Name):** Creates an alias, mapping one domain name to another domain name (e.g., `blog.example.com` $\rightarrow$ `servers.example.com`).
*   **AAAA Record:** Maps a domain name to an IPv6 address (e.g., `example.com` $\rightarrow$ 2001:db8::1).

**N13**
*   **DHCP (Dynamic Host Configuration Protocol):** A network protocol used to automatically assign IP addresses and other network configuration parameters (subnet mask, gateway, DNS servers) to devices on a network.

The DORA process is:
1.  **Discover:** Client broadcasts a DHCP Discover message to find available servers.
2.  **Offer:** Server replies with a DHCP Offer, proposing an IP address and configuration.
3.  **Request:** Client sends a DHCP Request, formally accepting the offered configuration.
4.  **Acknowledge:** Server replies with a DHCP ACK, finalizing the lease and providing the full configuration details.

**N14**
*   **Hub:** A physical layer device (Layer 1) that simply repeats incoming electrical signals to all connected ports, creating a single collision domain.
*   **Switch:** A data link layer device (Layer 2) that learns MAC addresses and forwards frames only to the intended destination port, creating multiple collision domains.
*   **Router:** A network layer device (Layer 3) that forwards packets between different networks (subnets) based on IP addresses.

**N15**
*   **Half-Duplex:** Allows data to travel in both directions, but only one direction at a time (like a walkie-talkie). Collisions can occur if both sides transmit simultaneously.
*   **Full-Duplex:** Allows data to travel simultaneously in both directions (like a telephone call). Collisions are eliminated.

Modern Ethernet links overwhelmingly use **full-duplex** communication.

**N16**
The TTL (Time To Live) field is an 8-bit field in the IP header that specifies the maximum number of hops (routers) a packet can traverse before being discarded.

Traceroute exploits this by sending a sequence of packets, incrementing the TTL value for each subsequent packet. When a router receives a packet with TTL=1, it decrements the TTL to 0, discards the packet, and sends an ICMP "Time Exceeded" message back to the source. By observing which router sends the ICMP message at each TTL increment, traceroute maps the path.

**N17**
A NAT gateway is a network device (usually a router or firewall) that translates private, internal IP addresses into one or more public, external IP addresses when traffic crosses the boundary between a private network and the public internet.

*   **Static NAT:** A one-to-one, fixed mapping. A specific private IP is permanently mapped to a specific public IP (e.g., 192.168.1.10 $\leftrightarrow$ 203.0.113.10). Used for servers.
*   **Dynamic NAT:** Maps private IPs to a pool of available public IPs on a first-come, first-served basis.
*   **PAT (Port Address Translation) / NAT Overload:** Maps many private IPs to a single public IP by tracking unique source port numbers. This allows thousands of internal hosts to share one public IP address.

**N18**
ECMP (Equal-Cost Multi-Path) routing allows a router to use multiple paths to reach the same destination if those paths have the same routing metric (cost). The router distributes traffic across these paths, increasing aggregate bandwidth and providing redundancy.

Common hashing strategies include:
1.  Source IP Address
2.  Destination IP Address
3.  Source/Destination Port Pair

Problems with asymmetric flows arise when traffic enters the network via one path (e.g., Path A) but returns via a different path (e.g., Path B). Stateful firewalls track connections based on the ingress interface. If the return traffic arrives on an interface the firewall doesn't expect for that established session, it may drop the packet, breaking the connection.

**N19**
The problem is **Bandwidth-Delay Product (BDP) limitation**. BDP = Bandwidth $\times$ Round Trip Time (RTT). The BDP (10MB) represents the maximum amount of data that can be "in flight" on the wire at any given time. If the TCP window size is capped at 64KB, the sender can only transmit 64KB before waiting for an ACK, even if the network path could handle 10MB of data. This forces the sender to wait unnecessarily, leading to high latency and underutilization of the link.

TCP Window Scaling (RFC 1323) solves this by allowing the TCP header to negotiate a window size much larger than the standard 16-bit limit (65,535 bytes). This allows the sender to advertise a much larger receive window, enabling the transmission of the full BDP amount of data before waiting for acknowledgments.

**N20**
802.1Q trunk ports allow a single physical link to carry traffic for multiple VLANs simultaneously. The switch inserts a 4-byte **VLAN Tag** into the Ethernet frame header. This tag contains the VLAN ID (VID).

To configure a server with a single NIC for VLANs 10, 20, and 30 on Linux, you create multiple virtual interfaces (sub-interfaces) bound to the physical NIC.
Example: `eth0.10`, `eth0.20`, `eth0.30`.
Each sub-interface is configured with the specific VLAN ID and the corresponding IP address for that VLAN.

The frame format on the wire looks like:
[Ethernet Header] $\rightarrow$ [802.1Q Tag (VID)] $\rightarrow$ [IP Header] $\rightarrow$ [Payload]

**L1**
*   **Hard Link:** A directory entry that points directly to the same inode (the file's metadata structure) as the original file. Both names refer to the exact same data blocks on disk. Deleting one link does not delete the data until the last hard link is removed.
*   **Symbolic Link (Symlink):** A special file that contains a text path pointing to another file or directory. It is a pointer, not a direct reference to the inode. If the target file is moved or deleted, the symlink breaks (dangling link).

**L2**
Use the `find` command:
`find /var/log -type f -size +100M`

**L3**
State D (Uninterruptible Sleep) means the process is waiting for an I/O operation (e.g., disk read/write) to complete. The kernel cannot interrupt this process, even with `SIGKILL` (kill -9), because it is blocked waiting for hardware. This state usually indicates a driver or hardware issue.

**L4**
*   **cgroups v1:** Uses a hierarchical structure where controllers (like CPU, Memory) are attached to processes. It is less unified and often requires separate configuration for each resource type.
*   **cgroups v2:** Implements a unified hierarchy where all controllers are managed under a single hierarchy. It enforces stricter resource isolation and provides a more coherent view of resource usage across the entire system.

Systemd prefers cgroups v2 because it provides a more modern, unified, and robust resource management model, which aligns better with systemd's own service management architecture.

**L5**
*   **iptables:** The older, traditional Linux firewall framework. It operates by chaining rules across tables (filter, nat, mangle) and chains (INPUT, OUTPUT, FORWARD).
*   **nftables:** The modern replacement for iptables. It uses a more flexible, unified syntax and data structure, allowing for more complex rule sets and better performance.

The kernel handles both by maintaining compatibility layers. When you use `iptables`, the kernel translates those commands into the underlying `nftables` ruleset structure, allowing older tools to function while the modern kernel infrastructure uses the more efficient `nftables` backend.

**L6**
The most likely cause is that the filesystem contains a large number of **small files** or **metadata** that are not counted accurately by `du -sh /*` when summing up directory sizes, or the space is consumed by filesystem overhead (e.g., journal files, inode tables, or deleted but unpurged files). `df -h` reports total block usage, while `du` reports file content size.

**L7**
1.  **UEFI Firmware:** The system powers on, and the UEFI firmware initializes hardware and locates the bootloader.
2.  **Bootloader (e.g., GRUB):** The firmware loads the bootloader, which is responsible for finding and loading the Linux kernel image and the initial RAM disk (`initramfs`).
3.  **Kernel:** The kernel starts, mounts the `initramfs` (a temporary root filesystem containing necessary drivers).
4.  **Initramfs:** The initramfs executes scripts to load necessary modules (like storage drivers) to access the real root filesystem.
5.  **Root Filesystem:** The kernel mounts the actual root filesystem (e.g., ext4).
6.  **Systemd:** The kernel executes the first process, PID 1, which is `systemd`. Systemd then takes over, managing services, mounting remaining filesystems, and reaching the final operational target (e.g., `multi-user.target`).

**L8**
The OOM killer fires because the kernel's definition of "available" memory is conservative. While `buff/cache` memory is reclaimable, the kernel must ensure that enough memory remains available for critical system operations, kernel structures, and immediate application needs. If the system is under heavy load, the kernel might deem the *truly* available memory (memory not currently used by processes *and* not needed for immediate kernel operations) too low, triggering the OOM killer, even if large amounts of memory are sitting in cache.

Kernel tunables affecting this include `vm.min_free_kbytes` and `vm.swappiness`. Lowering `vm.swappiness` reduces the kernel's tendency to swap out active processes, keeping more memory available for active use.

**L9**
`ip netns` is used to manage network namespaces. A network namespace is an isolated view of the system resources (network stack, process IDs, mount points, etc.).

Container runtimes (like Docker or Kubernetes) use network namespaces to provide network isolation for containers. Each container is placed into its own dedicated network namespace, meaning it has its own private set of network interfaces, IP addresses, routing tables, and firewall rules, completely isolated from the host and other containers unless explicitly bridged.

**L10**
*   **SIGTERM (Signal 15):** The standard, polite termination signal. It asks the process to shut down gracefully, allowing it time to clean up resources before exiting.
*   **SIGKILL (Signal 9):** A forceful, immediate termination signal. The kernel stops the process instantly; the process cannot catch, ignore, or block this signal.
*   **SIGQUIT (Signal 3):** Requests the process to terminate and usually generates a core dump file for debugging.

Only **SIGTERM** and **SIGQUIT** can be caught by the process using signal handlers.

**L11**
*   **stdin (Standard Input):** Where a program reads input from (default: keyboard).
*   **stdout (Standard Output):** Where a program writes normal, expected output to (default: terminal screen).
*   **stderr (Standard Error):** Where a program writes error messages and diagnostic output to (default: terminal screen).

To redirect stderr to a file while displaying stdout on the terminal:
`command 2> error.log` (This redirects file descriptor 2, stderr, to the file).

**L12**
`chmod 755 filename` sets the permissions for the file:
*   **7 (Owner):** Read (4) + Write (2) + Execute (1) = Full permissions.
*   **5 (Group):** Read (4) + Execute (1) = Read and Execute permissions.
*   **5 (Others):** Read (4) + Execute (1) = Read and Execute permissions.

**L13**
*   **Root User (UID 0):** Has absolute, unrestricted access to the entire operating system. It can read, write, and modify any file, change system configurations, and manage all processes without restriction.
*   **Sudo User:** A standard user who is granted specific, limited permissions via the `sudo` command. They can execute specific commands as the root user, but these permissions are audited and restricted by the `/etc/sudoers` file, preventing them from having blanket root access.

**L14**
A package manager is a system software tool used to automate the installation, upgrading, configuration, and removal of software packages on a Linux system.

*   **Debian/Ubuntu:** APT (Advanced Package Tool)
*   **RHEL/Fedora:** DNF (Dandified YUM) or YUM

**L15**
`/etc/fstab` (File System Table) is a configuration file that defines how disk partitions and network file systems (like NFS) should be mounted automatically at boot time.

If an entry is misconfigured (e.g., incorrect UUID, wrong mount point, or invalid filesystem type), the system may fail to mount that partition during boot, potentially leading to a boot failure or a degraded operational state where the required data/service is unavailable.

**L16**
LVM (Logical Volume Manager) is a layer of abstraction that sits between the physical storage devices and the filesystem. It allows administrators to manage storage flexibly, treating physical disks as pools of storage that can be dynamically carved up into logical volumes.

*   **Physical Volumes (PV):** The actual physical storage devices (disks or partitions) that LVM uses.
*   **Volume Groups (VG):** A pool of storage capacity created by combining one or more PVs.
*   **Logical Volumes (LV):** The virtual partitions carved out of the VG that are then formatted and mounted as filesystems.

To extend an LV:
1.  Extend the underlying PV (if necessary).
2.  Extend the VG to include the new space.
3.  Extend the LV using the available space in the VG (e.g., `lvextend -L +10G /dev/vgname/lvname`).
4.  Resize the filesystem on the LV (e.g., `resize2fs /dev/vgname/lvname`).

**L17**
The I/O scheduler manages the order in which read/write requests are serviced by the block device driver to optimize throughput and latency.

*   **mq-deadline:** Prioritizes requests based on deadlines, ensuring that older requests are serviced before they time out. Good for mixed workloads.
*   **bfq (Budget Fair Queueing):** Designed for desktop/interactive workloads. It aims to provide fair bandwidth allocation to different processes, ensuring low latency for interactive tasks.
*   **none:** Disables the scheduler, allowing the hardware or the application to manage I/O scheduling directly. Best for high-performance storage arrays or specialized workloads where the OS scheduler adds unnecessary overhead.

To change the scheduler at runtime:
`echo bfq > /sys/block/sdX/queue/scheduler` (where `sdX` is the target block device).

**L18**
Load average measures the average number of processes in the runnable state (running or waiting for CPU) over the last 1, 5, and 15 minutes. It is *not* a direct measure of CPU utilization.

I/O wait inflates the load average because processes waiting for disk I/O are counted as "running" or "in process" by the scheduler, even though they are blocked waiting for the disk subsystem, thus increasing the load average count.

Diagnosis:
*   **CPU Bottleneck:** High `us` (user) and `sy` (system) CPU usage in `top`/`htop`.
*   **Disk Bottleneck:** High `%wa` (I/O wait) in `top`/`htop`, coupled with high utilization reported by `iostat` on the disk device.
*   **Network Bottleneck:** High packet drops or high utilization reported by network interface statistics (`ip -s link`) or monitoring tools.

**L19**
SELinux (Security-Enhanced Linux) enforces Mandatory Access Control (MAC). Instead of relying solely on DAC (Discretionary Access Control, i.e., standard Linux permissions), SELinux assigns security contexts (labels) to every subject (process) and object (file/port). Access is only granted if the policy explicitly permits the interaction between the subject's context and the object's context.

*   **Enforcing:** SELinux actively denies access based on policy violations.
*   **Permissive:** SELinux logs policy violations but does *not* deny access, allowing administrators to observe issues without breaking functionality.
*   **Disabled:** SELinux is turned off, reverting to standard DAC.

To troubleshoot a daemon failing to bind a non-standard port:
1.  Set SELinux to **Permissive** mode (`setenforce 0`).
2.  Restart the daemon.
3.  Check the audit logs (`/var/log/audit/audit.log`) for AVC denials related to the port binding attempt.
4.  If the denial is confirmed, use `semanage port` or `semodule` to explicitly allow the daemon context to use that specific port type.

**L20**
A page fault occurs when a program attempts to access a virtual memory address whose corresponding physical memory page is not currently mapped or present in RAM.

*   **Minor Page Fault:** Occurs when the page is not in RAM, but it *can* be found in the system's page cache (swap or file cache). The kernel simply updates the page table entry to map the existing data into physical memory. This is fast.
*   **Major Page Fault:** Occurs when the page is not in RAM and is not in the page cache (i.e., it must be loaded from disk/swap). The kernel must perform a slow I/O operation to fetch the data, causing significant latency.

Transparent Huge Pages (THP) attempts to use large memory pages (e.g., 2MB instead of 4KB) to reduce TLB misses and improve performance for large memory allocations. However, THP can cause performance degradation (latency spikes) during memory compaction or when memory pressure is high, as the kernel must manage these large blocks. You would disable THP (`echo never > /sys/kernel/mm/transparent_hugepage/enabled`) if you observe unpredictable latency or performance jitter in latency-sensitive applications.
