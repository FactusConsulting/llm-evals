## .NET / C#

**DN1 — Easy:** A `class` is a reference type (allocated on the heap), while a `struct` is a value type (usually allocated on the stack or inline). Use a `struct` for small, immutable data structures (e.g., a Point or Complex number) to reduce Garbage Collector (GC) pressure and improve memory locality.

**DN2 — Easy:** `IEnumerable<T` is a forward-only iterator for in-memory collections. `IQueryable<T>` is designed for out-of-process data sources (like SQL). The distinction matters because `IQueryable` translates LINQ expressions into the provider's language (e.g., SQL), filtering data on the database server, whereas `IEnumerable` pulls all data into memory before filtering.

**DN3 — Medium:** `async/await` uses a state machine to allow non-blocking I/O. `Task` is a class representing an ongoing operation (heap allocated). `ValueTask` is a struct used to reduce allocations when a result is often available synchronously. Use `ValueTask` in high-performance paths where the method frequently returns a cached result.

**DN4 — Medium:** DI is a pattern where dependencies are provided to a class rather than created internally. 
- **Transient:** New instance every time requested.
- **Scoped:** One instance per client request (HTTP request).
- **Singleton:** One instance for the app lifetime.
**Bug:** A "Captive Dependency" occurs when a Singleton injects a Scoped service; the Scoped service is effectively promoted to a Singleton, potentially leading to stale data or `ObjectDisposedException`.

**DN5 — Medium:** `string` is an immutable heap object. `ReadOnlySpan<char>` is a ref-struct that provides a view into a contiguous region of memory without allocating a new string. Use `Span<T>` for high-performance parsing or slicing to avoid unnecessary heap allocations and GC pressure.

**DN6 — Medium:** The GC uses a generational approach: **Gen 0** (short-lived), **Gen 1** (buffer), and **Gen 2** (long-lived). The **Large Object Heap (LOH)** handles objects > 85KB to avoid expensive memory compaction. `IDisposable` is needed for unmanaged resources (file handles, sockets) because the GC only manages managed memory and doesn't know when to release external handles.

**DN7 — Hard:** `ConfigureAwait(false)` tells the task to resume on any available thread rather than returning to the original `SynchronizationContext` (e.g., the UI thread). Use it in library code to prevent deadlocks and improve performance. Do NOT use it in code that must interact with UI elements or request-specific contexts.

**DN8 — Hard:** 
- **Primary Constructors:** Define parameters directly in the class declaration.
- **Collection Expressions:** Use `[]` for initializing arrays/lists.
- **FrozenDictionary:** An immutable dictionary optimized for read-heavy scenarios.
```csharp
public class UserService(IDbContext db) { // Primary Constructor
    public void GetUsers() {
        List<string> names = ["Alice", "Bob"]; // Collection expression
    }
}
```

**DN9 — Hard:** The cause is likely a **Captive Dependency** or multi-threaded access to a `DbContext` (which is not thread-safe). If a Singleton service injects a Scoped `DbContext`, the context lives too long. Fix: Use `IServiceScopeFactory` to create a manual scope within the Singleton or ensure the service is registered as Scoped.

**DN10 — Medium:** A `record` is a class with built-in value-based equality. A `record struct` is a value-type with value-based equality. Use `record` for DTOs/immutable data; `class` for behavior-heavy objects; `record struct` for small, immutable value objects.

**DN11 — Easy:** 
- `ref`: Pass by reference; allows reading and modifying the original variable.
- `out`: Pass by reference; requires the method to assign a value before returning.
- `in`: Pass by reference; read-only (prevents modification).

**DN12 — Easy:** Nullable reference types (`string?`) are a compiler-level feature to track potential nulls and prevent `NullReferenceException`. `int?` is a `Nullable<T>` struct that wraps a value type to allow nulls.

**DN13 — Easy:** LINQ (Language Integrated Query) provides a unified way to query data. **Method syntax** uses extension methods (`.Where()`), while **Query syntax** looks like SQL. **Deferred execution** means the query is not executed until the collection is iterated (e.g., via `foreach` or `.ToList()`).

**DN14 — Easy:** Constraints restrict the types used in generics:
- `where T : class`: T must be a reference type.
- `where T : struct`: T must be a value type.
- `where T : new()`: T must have a parameterless constructor.
- `where T : IComparable<T>`: T must implement the interface.
Combine them to ensure a type is both a class and implements a specific interface.

**DN15 — Easy:** An `abstract class` can hold state and provide partial implementation; an `interface` defines a contract. Default interface methods (C# 8+) allow interfaces to provide a default implementation, blurring the line but still preventing interfaces from holding instance state.

**DN16 — Medium:** Middleware are components arranged in a pipeline. `Use()` adds middleware that can call `next()`, `Map()` branches the pipeline based on a path, and `Run()` terminates the pipeline. Order is critical (e.g., Exception Handling must be first to catch errors from subsequent middleware).

**DN17 — Medium:** `Channel<T>` is a high-performance async producer-consumer queue. Unlike `BlockingCollection`, it is fully async. Bounded channels provide backpressure by limiting the number of items in the queue; the producer will asynchronously wait (or return false) when the channel is full.

**DN18 — Hard:** Source Generators produce C# code during compilation. Unlike reflection (runtime) or IL weaving (post-compile), they are type-safe and integrated into the compiler. **Incremental Generators** are preferred because they cache results and only re-run on changed parts of the syntax tree, significantly improving IDE performance.

**DN19 — Hard:** TPL Dataflow provides blocks for data pipelines. `ActionBlock` (consumes), `TransformBlock` (maps), `BufferBlock` (queues). Compared to `Channels`, TPL Dataflow is a higher-level orchestration framework for complex directed graphs of processing.

**DN20 — Hard:** Minimal APIs reduce boilerplate by defining endpoints in `Program.cs`. Trade-offs: Controllers are better for very large apps with complex organization. Route groups allow shared logic/auth for sets of endpoints, and endpoint filters provide a way to run logic before/after the handler.

## Python

**P1 — Easy:** `list` is mutable; `tuple` is immutable. `set` is a mutable collection of unique elements; `frozenset` is the immutable version of a set.

**P2 — Easy:** The GIL is a mutex that allows only one thread to execute Python bytecode at a time. It affects CPU-bound workloads. Workarounds include using the `multiprocessing` module or writing performance-critical parts in C/Rust.

**P3 — Medium:** `copy` (shallow) creates a new object but references the same nested objects. `deepcopy` recursively copies everything. 
*Example:* If you shallow copy a list of lists `[[1]]`, modifying the inner list of the copy will modify the original.

**P4 — Medium:** Decorators wrap a function to modify its behavior.
```python
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        res = func(*args, **kwargs)
        print(f"Time: {time.time() - start}")
        return res
    return wrapper
```

**P5 — Medium:** Generators use `yield` to produce values one at a time (lazy evaluation), saving memory compared to returning a full list. `yield from` allows a generator to delegate to another generator or iterable.

**P6 — Medium:** The event loop manages async tasks. `asyncio.run()` is the entry point; `gather()` runs multiple coroutines concurrently; `create_task()` schedules a coroutine to run in the background. `time.sleep()` blocks the entire thread, stopping the loop; use `await asyncio.sleep()`.

**P7 — Hard:** Python uses **C3 Linearization** for MRO. In diamond inheritance, it searches classes in the order they are listed, then their parents. 
In the example: `D` inherits from `B` then `C`. `B` has no `who()`, so it checks `C`. `C` has `who()`, so it returns **"C"**.

**P8 — Hard:** A metaclass is a class that creates classes. Use `__init_subclass__` for simple customization of subclasses (e.g., registering plugins). Use a metaclass for deep control over class creation (e.g., enforcing API constraints across all subclasses).

**P9 — Hard:** 
- `threading`: I/O bound, shared memory, limited by GIL.
- `multiprocessing`: CPU bound, separate memory, bypasses GIL.
- `concurrent.futures`: High-level wrapper for both.
Multiprocessing requires **pickling** (serialization) to send data between processes, which can be slow for large objects.

**P10 — Medium:** `__slots__` tells Python not to create a `__dict__` for instances, instead allocating a fixed amount of space for specified attributes. This significantly reduces memory usage and slightly increases attribute access speed.

**P11 — Easy:** A virtual environment isolates dependencies for a project. `venv` is the standard library tool; `virtualenv` is a more feature-rich predecessor; `conda` manages both Python and non-Python binary dependencies.

**P12 — Easy:** Comprehensions provide a concise way to create collections. They are generally more readable and faster than `map()` and `filter()`, though `map`/`filter` are useful when using existing functions.

**P13 — Easy:** `==` checks for value equality; `is` checks for identity (memory address). Small integers (typically -5 to 256) are **interned** by Python, so `is` returns `True` for them.

**P14 — Easy:** `*args` collects positional arguments into a tuple; `**kwargs` collects keyword arguments into a dict. `/` marks arguments before it as positional-only; `*` marks arguments after it as keyword-only.

**P15 — Easy:** Context managers handle setup/teardown. Use `__enter__`/`__exit__` in a class or `@contextmanager` with a generator. 
*Example:* A database transaction manager that commits on success and rolls back on exception.

**P16 — Medium:** Type hinting provides static analysis. `Union` (either type), `Optional` (T or None), `Literal` (specific value), `TypeVar` (generic), `Protocol` (structural typing/duck typing). `mypy` uses these to find bugs without running the code.

**P17 — Medium:** 
- `__repr__` (developer-facing), `__str__` (user-facing).
- `__eq__` (equality), `__hash__` (for set/dict keys).
- `__getattr__` (called if attribute not found), `__getattribute__` (called for every access).
If you define `__eq__` but not `__hash__`, the class becomes unhashable (cannot be a dict key).

**P18 — Hard:** Descriptors are objects that define `__get__`, `__set__`, and `__delete__`. `property`, `classmethod`, and `staticmethod` are all implemented as descriptors that intercept attribute access to provide their specific logic.

**P19 — Hard:** Python searches `sys.path` for modules. Absolute imports start from the root; relative imports use `.` or `..`. `__init__.py` marks a directory as a package (though namespace packages don't need it). Finders locate modules; loaders load them into memory.

**P20 — Hard:** `dataclasses` provide a concise way to define data-holding classes. `attrs` is a more powerful precursor; `Pydantic` adds runtime type validation and coercion. `__post_init__` allows logic after the generated `__init__`. Choose Pydantic when you need strict data validation from external input (e.g., JSON APIs).
