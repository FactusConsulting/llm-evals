## JavaScript / TypeScript

**JS1** — `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped; `const` prevents reassignment. **Hoisting** is the JS engine's behavior of moving declarations to the top of their scope during the compilation phase.

**JS2** — The **Event Loop** manages the execution of asynchronous code. The **Call Stack** handles synchronous execution. When an async task finishes, it enters a queue. **Microtasks** (Promises, `queueMicrotask`) have higher priority and are processed immediately after the current stack clears, before **Macrotasks** (setTimeout, setInterval, I/O).

**JS3** — A **closure** is a function that remembers the environment in which it was created. *Example:* A function returning another function that increments a private counter. *Loop bug:* Using `var` in a `for` loop creates one shared variable for all iterations. *Fix:* Use `let` (block-scoped) or an IIFE.

**JS4** — `Promise` represents a future value. `async/await` is syntactic sugar for Promises. Errors are handled via `.catch()` or `try/catch` blocks. `Promise.all` rejects if *any* promise fails; `Promise.allSettled` waits for all to complete regardless of outcome.

**JS5** — `interface` is primarily for defining object shapes and supports declaration merging. `type` is more flexible (unions, primitives, tuples). Use `interface` for public APIs/classes; `type` for complex logic. **Discriminated unions** use a common literal property (e.g., `type: 'circle' | 'square'`) to allow TypeScript to narrow types in a switch/if block.

**JS6** — JS uses **prototypal inheritance**: objects inherit from other objects via a prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is "syntactic sugar" that implements the same prototypal mechanism under the hood.

**JS7** — `this` refers to the execution context. Priority: 1. `new` (newly created object), 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (the object calling the method), 4. Default (global/undefined). `bind()` returns a *new* function with a fixed `this`; it cannot be re-bound.

**JS8** — `WeakRef` allows holding a reference to an object without preventing its garbage collection (GC). `FinalizationRegistry` triggers a callback after an object is GC'd. `WeakMap` keys must be objects so that if the key is no longer referenced elsewhere, the entry can be GC'd.

**JS9** — V8 uses **Hidden Classes** (shapes) to optimize property access. **Inline Caching (IC)** remembers where properties were found to skip lookups. **Deoptimization** occurs when an object's shape changes (e.g., adding properties in different orders), forcing V8 to fall back to a slower, generic lookup.

**JS10** — **Tree-shaking** is the removal of unused code. ES Modules (ESM) use static `import/export`, allowing tools to determine exactly what is used at build time. CommonJS (`require`) is dynamic, meaning the module is evaluated at runtime, making it nearly impossible for tools to safely determine what is unused.

**JS11** — `undefined` means a value hasn't been assigned; `null` is an intentional absence of value. `==` performs type coercion; `===` checks value and type. `??` (nullish coalescing) returns the right side only if the left is `null` or `undefined`. `?.` (optional chaining) short-circuits if the chain is null/undefined.

**JS12** — `map()` transforms each element; `filter()` selects elements based on a predicate; `reduce()` aggregates elements into a single value. `reduce` with an initial value uses that as the starting accumulator. `flatMap()` maps then flattens the result by one level, useful for removing items or expanding one item into many.

**JS13** — Template literals (backticks) allow interpolation. **Tagged templates** pass the string parts and interpolated values to a function. *Example:* `sql`tagged template that escapes inputs to prevent SQL injection by processing the values before joining them into a query.

**JS14** — **Destructuring** unpacks values from arrays/objects. `const {name = 'Guest'} = user` (default value); `const {name: userName} = user` (renaming). The **rest operator** `...` collects remaining elements into a new array/object.

**JS15** — `for...in` iterates over enumerable keys (strings) of an object. `for...of` iterates over values of an iterable (Array, Map, Set). Avoid `for...in` on arrays because it iterates over all enumerable properties (including prototypes) and returns indices as strings.

**JS16** — **Generics** allow reusable components. `extends` constrains a type (e.g., `T extends string`). **Conditional types** (`T extends U ? X : Y`) choose a type based on a condition. `infer` extracts a type from another type (e.g., extracting the return type of a function).

**JS17** — CommonJS uses `require`/`module.exports` (synchronous). ESM uses `import`/`export` (static). Node.js handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM.

**JS18** — **Structural typing** checks if the shape matches, regardless of the name. **Excess property checks** occur when assigning an object literal directly to a type. `extends` is for inheritance/constraints; `satisfies` validates a type without changing the inferred type. **Variance** (Covariance/Contravariance) defines how sub-types relate to their containers (e.g., function arguments are contravariant).

**JS19** — `Proxy` intercepts operations (get, set, etc.) on an object. `Reflect` provides static methods to perform the default behavior of those operations. *Example:* A Proxy can be used for "reactive" data binding by triggering a UI update whenever a `set` trap is called.

**JS20** — `SharedArrayBuffer` allows memory sharing between workers. `Atomics` provides atomic operations (add, load, store) to prevent race conditions. `Atomics.wait` puts a thread to sleep until `Atomics.notify` wakes it up, enabling low-level synchronization.

## Bash

**B1** — `$*` expands to all arguments as a single string. `$@` expands to all arguments. When quoted, `"$*"` is one string; `"$@"` preserves each argument as a separate quoted string (the safest way to handle spaces).

**B2** — `set -e`: Exit immediately if a command fails. `-u`: Treat unset variables as an error. `-o pipefail`: The pipeline return status is the status of the last command to exit with a non-zero status.

**B3** — `$(command)` is the modern syntax for command substitution; `` `command` `` is the legacy version (harder to nest). `$((expression))` is for integer arithmetic; `expr` is an external utility for the same purpose.

**B4** — **Process substitution** `<(command)` makes the output of a command appear as a file. *Example:* `diff <(ls dir1) <(ls dir2)` compares the contents of two directories without creating temporary files.

**B5** — Use `while IFS= read -r file` or `find -print0 | xargs -0`. `for f in $(ls)` is dangerous because it splits filenames containing spaces or newlines into multiple arguments.

**B6** — `<<EOF` (Here Doc) allows multiline input. `<<<` (Here String) passes a single string to stdin. `<<-EOF` strips leading tab characters from the input lines.

**B7** — `> file 2>&1`: Stdout to file, then stderr to stdout (both in file). `2>&1 > file`: Stderr to current stdout (terminal), then stdout to file (stderr stays in terminal). `&> file`: Shorthand for both to file.

**B8** — Use `mkdir lockdir` because it is an atomic operation at the OS level. Use `trap 'rmdir lockdir' EXIT SIGTERM SIGINT` for cleanup. `mkdir` is preferred over `touch` because multiple processes calling `mkdir` simultaneously will result in only one succeeding.

**B9** — `'...'` (Single): Literal string, no expansion. `"..."` (Double): Interpolates variables/commands. No quotes: Subject to word splitting and globbing (e.g., `*` expands to files).

**B10** — `-f` (exists and is file), `-d` (is directory), `-r` (readable). `[ ]` is the POSIX standard `test`. `[[ ]]` is a Bash extension that supports regex (`=~`), logical operators (`&&`, `||`), and doesn't require quoting variables to prevent word splitting.

**B11** — `$?`: Exit status of last command. `$$`: PID of current script. `$!`: PID of last background process. `$#`: Number of arguments passed to script.

**B12** — `foo() { ... }` is standard. `function foo { ... }` is a Bash-ism. Functions return values via `echo` (captured by command substitution) or by setting a global variable; `return` only provides an exit status (0-255).

**B13** — `PATH` is a colon-separated list of directories searched for executables. Builtins (e.g., `cd`) are inside the shell; external commands (e.g., `ls`) are binaries. Use `type -a command` to check.

**B14** — `trap 'cmd' SIGNAL` executes `cmd` when a signal is received. Order: Signals are handled as they arrive. `EXIT` is a pseudo-signal triggered when the shell exits.

**B15** — `xargs` reads from stdin and executes commands. `find -print0 | xargs -0` uses the null character as a delimiter to handle spaces/newlines. `xargs -P N` runs `N` processes in parallel.

**B16** — Indexed: `arr=(1 2)`, `${arr[0]}`. Associative: `declare -A assoc`, `assoc[key]=val`. Append: `arr+=("val")`. Length: `${#arr[@]}`.

**B17** — `( )` (Subshell) runs in a child process; variables changed inside are lost. `{ }` (Group) runs in the current process. Piping into a `while` loop creates a subshell, so variables modified inside the loop are lost after the pipe.

**B18** — `SIGINT` (Ctrl+C), `SIGTERM` (polite kill), `SIGHUP` (terminal closed), `SIGKILL` (forced, cannot be trapped). Graceful shutdown: `trap` signals and kill background PIDs.

**B19** — `split -l 1000 log.txt part_` $\rightarrow$ `ls part_* | xargs -P 4 -I {} ./process.sh {}` $\rightarrow$ `cat results_* > final`. Trade-off: Parallelism increases speed but consumes more RAM/CPU; error propagation requires checking exit codes of the parallel workers.

**B20** — `exec` replaces the current shell process with the new command. `exec 3>file` opens file descriptor 3 for writing. A **coprocess** (`coproc`) creates a two-way pipe between the shell and a background process.

## PowerShell

**PS1** — `Write-Output` sends objects to the pipeline (can be captured). `Write-Host` writes directly to the console (cannot be captured). Using `Write-Host` in a function breaks the pipeline.

**PS2** — The pipeline passes *objects*, not text. `ForEach-Object` is a cmdlet for streaming data in the pipeline. `foreach` is a language statement that requires the entire collection to be in memory first (faster for small sets).

**PS3** — `[hashtable]` is a key-value map (unordered). `[PSCustomObject]` is a structured object with properties. Convert: `$obj = [PSCustomObject]$hash`.

**PS4** — **Terminating errors** stop execution; **non-terminating** errors print a warning and continue. `-ErrorAction Stop` turns a non-terminating error into a terminating one, allowing it to be caught by `try/catch`.

**PS5** — **Splatting** passes a hashtable of parameters using `@`. *Example:* `$params = @{Path='C:\'; Recurse=$true}; Get-ChildItem @params`. It improves readability over long command lines.

**PS6** — `Invoke-Command` runs a script block on a remote machine and returns results. `Enter-PSSession` starts an interactive session. It uses **WinRM** (WS-Man) or **SSH**.

**PS7** — PowerShell "unrolls" collections. If a function returns an array, the pipeline sends items one by one. If it returns 0 items, it returns `$null`. The correct pattern to ensure an array is `@(Get-Items)`.

**PS8** — A `[scriptblock]` is a piece of code `{...}` that can be passed as an argument. The **double-hop problem** occurs when a remote session tries to access a third machine. Solve via **CredSSP** or by passing credentials explicitly.

**PS9** — `@()` is the array sub-expression operator. `[array]` is a type cast. Indexing `$null` in PowerShell returns `$null` rather than throwing an error, which can hide bugs.

**PS10** — `-eq` (equal), `-like` (wildcards `*`), `-match` (regex). Case-sensitive versions start with `c` (e.g., `-ceq`). `-contains` checks if a collection contains a value; `-in` checks if a value is in a collection.

**PS11** — A module is a package of functions/variables. `.psm1` contains the code; `.psd1` is a manifest (versioning, dependencies). `Import-Module` loads the module into the current session.

**PS12** — `"..."` (Double) interpolates variables; `'...'` (Single) is literal. Use `"$($expression)"` for complex expressions. Here-strings `@" ... "@` allow multiline literal strings.

**PS13** — `Get-Member` shows the properties and methods of an object. `Select-Object` filters properties; `Where-Object` filters the objects themselves based on a condition.

**PS14** — PS Classes provide static typing and constructors. They are simpler than C# classes (no interfaces). Use a class for complex data models; use a function for operational logic.

**PS15** — `[CmdletBinding()]` makes a function an "Advanced Function," enabling `-WhatIf` and `-Confirm` via `SupportsShouldProcess`. `Begin` (setup), `Process` (per item), and `End` (cleanup) blocks handle pipeline streaming.

**PS16** — Providers map different data stores (Registry, Certs, Env) to a drive-like interface. You can `cd HKLM:\` to navigate the registry as if it were a folder.

**PS17** — A `runspace` is an isolated execution environment. `runspacepool` manages multiple runspaces. `ForEach-Object -Parallel` (v7+) is a high-level wrapper for runspaces to execute tasks in parallel.

**PS18** — `PSScriptAnalyzer` is a static analysis tool. It uses rules (e.g., "Avoid using Write-Host"). Rules have severity (Warning, Error). It integrates into CI/CD to fail builds if coding standards aren't met.

**PS19** — `$using:var` is used to pass a local variable into a remote/parallel scope. Serialization uses **CLIXML**; very deep or complex objects may lose data or fail to serialize across the network.

**PS20** — **DSC** is a declarative way to manage configuration (State). The **LCM** (Local Configuration Manager) ensures the machine stays in the desired state. Modern IaC (Terraform, Ansible) has largely replaced DSC for cross-platform needs.
