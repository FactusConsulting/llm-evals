## .NET / C#

**DN1**
`class` is a reference type (stored on the heap); `struct` is a value type (usually stored on the stack). Use a `struct` for small, immutable data structures (typically < 16 bytes) that have a short lifetime to reduce GC pressure and avoid heap allocation overhead.

**DN2**
`IEnumerable<T>` is an in-memory collection; it iterates through the entire set. `IQueryable<T>` is designed for out-of-memory providers (like EF Core); it builds an Expression Tree that is translated into a provider-specific language (e.g., SQL). The distinction matters because `IEnumerable` pulls all data into memory before filtering, whereas `IQueryable` allows the database to perform filtering/projection, significantly reducing network traffic and memory usage.

**DN3**
`async/await` allows a thread to yield control back to the caller/pool while waiting for an I/O-bound operation to complete, preventing thread starvation. `Task` represents an asynchronous operation that can be awaited. `ValueTask` is a value-type wrapper around a `Task`. Use `ValueTask` when the result is often available synchronously (e.g., from a cache), avoiding the heap allocation of a `Task` object.

**DN4**
Dependency Injection (DI) is a pattern where objects do not create their dependencies but receive them from an external source.
- **Transient**: Created every time they are requested.
- **Scoped**: Created once per client request (e.g., per HTTP request).
- **Singleton**: Created once and live for the lifetime of the application.
**Common Bug**: Injecting a **Scoped** service into a **Singleton**. This causes "Captive Dependency," where the Scoped service is held alive indefinitely by the Singleton, potentially leading to stale data or `ObjectDisposedException` when the original scope ends.

**DN5**
`string` is a heap-allocated, immutable array of characters. `ReadOnlySpan<char>` is a stack-allocated view into a contiguous region of memory (could be a string, array, or unmanaged memory). Use `Span<T>` for high-performance parsing/slicing to avoid creating new string allocations (substrings) on the heap, which reduces GC pressure.

**DN6**
The GC manages memory by reclaiming objects no longer in use.
- **Gen 0**: Short-lived objects (newly allocated).
- **Gen 1**: Buffer zone for objects surviving Gen 0.
- **Gen 2**: Long-lived objects.
- **LOH (Large Object Heap)**: Objects > 85,000 bytes are allocated here; they are not compacted by default, which can lead to fragmentation.
`IDisposable` is used to manually release **unmanaged** resources (file handles, database connections) because the GC only manages managed memory and does not know when to release OS handles.

**DN7**
`ConfigureAwait(false)` tells the runtime that the continuation (the code after `await`) does not need to resume on the original `SynchronizationContext` (e.g., the UI thread).
- **Use it**: In library/infrastructure code to prevent deadlocks and improve performance.
- **Do NOT use it**: In application-level code where you need to access context-specific data (like `HttpContext.Current` or UI elements).

**DN8**
- **Primary Constructors**: Define parameters directly in the class header.
- **Collection Expressions**: `int[] arr = [1, 2, 3];`
- **FrozenDictionary**: An immutable, highly optimized read-only dictionary.
```csharp
// Example: Primary Constructor with DI
public class UserService(IUserRepository repo) : IUserService {
    public User GetUser(int id) => repo.Find(id);
}
```

**DN9**
**Cause**: A `DbContext` is Scoped by default. If multiple concurrent threads/tasks attempt to use the same `DbContext` instance, it will throw `ObjectDisposedException` or "A second operation was started on this context."
**Fix**: Ensure each asynchronous task/thread creates its own scope or uses a `IDbContextFactory<T>`. Never inject a Scoped `DbContext` into a Singleton or share it across parallel tasks.

**DN10**
`record` is a reference type with built-in value-based equality. `record struct` is a value type with value-based equality.
- **Use `record` (class)**: For complex data models/DTOs where identity is defined by properties.
/ - **Use `record struct`**: For small, high-performance, immutable data packets.

**DN11**
- **`ref`**: Passes by reference; allows modifying the original variable and allows the variable to be null.
- **`out`**: Passes by reference; the method **must** assign a value before returning.
- **`in`**: Passes by reference; the method can read but **cannot** modify the variable (read-only).
Use `ref` for swapping/mutating, `out` for returning multiple values, and `in` for performance with large structs.

**DN12**
**Nullable Reference Types**: `string?` tells the compiler the variable *can* be null, enabling static analysis to catch `NullReferenceException`. `#nullable enable` turns this on for a file/project.
**Nullable Value Types**: `int?` (shorthand for `Nullable<int>`) allows a value type to represent `null`.
The difference is that `int?` is a structural change to the type, whereas `string?` is a compiler-level metadata hint for analysis.

**DN13**
LINQ (Language Integrated Query) provides a uniform way to query data.
- **Method Syntax**: Uses extension methods and lambdas (`.Where(x => x > 0)`).
- **Query Syntax**: Uses SQL-like keywords (`from x in list where x > 0 select x`).
**Deferred Execution**: The query is not executed when defined, but when the data is actually iterated (e.g., via `foreach` or `.ToList()`).

**DN14**
Constraints restrict what types can be used in generics:
- `T : class`: Must be a reference type.
- `T : struct`: Must be a value type.
- `T : new()`: Must have a public parameterless constructor.
- `T : IComparable<T>`: Must implement `IComparable<T>`.
**Combine** them when you need a specific type that also supports specific operations (e.g., `where T : class, new()` for a factory pattern).

**DN15**
An `abstract class` can have state (fields) and implementation; an `interface` defines a contract.
**C# 8+ Change**: Default interface methods allow interfaces to provide a default implementation for methods, blurring the line. However, interfaces still cannot hold instance state (fields).

**DN16**
The middleware pipeline is a sequence of delegates.
- `app.Use()`: Adds a delegate that can call the `next` delegate (can short-circuit).
- `app.Map()`: Branches the pipeline based on a URL path.
- `app.Run()`: A terminal middleware (no `next` call).
**Ordering**: Crucial; e.g., `UseAuthentication` must come before `UseAuthorization`. **Exception Handling**: Usually the first middleware in the pipeline to catch errors from all subsequent stages.

**DN17**
`Channel<T>` is an asynchronous, thread-safe queue for producer-consumer patterns. Unlike `BlockingCollection<T>` (which blocks threads), `Channel<T>` is non-blocking and `async`-friendly.
**Backpressure Example**:
```csharp
var channel = Channel.CreateBounded<int>(10); // Limit capacity to 10
// Producer: await channel.Writer.WriteAsync(item); // Will wait if full
// Consumer: await channel.Reader.ReadAsync();
```

**DN18**
**Source Generators** generate C# code during compilation.
- **vs Reflection**: Reflection happens at runtime (slow, heavy); Generators happen at compile-time (fast, zero runtime cost).
- **vs IL Weaving**: Weaving modifies MSIL bytes; Generators produce actual `.cs` files.
**Incremental Generator**: Uses a cache-aware approach to only re-run when relevant syntax changes, significantly improving IDE/compiler performance compared to the older `ISourceGenerator`.

**DN19**
TPL Dataflow is a library for building actor-based pipelines.
- `ActionBlock`: Executes an `Action` on incoming items.
- `TransformBlock`: Takes an input, transforms it, and produces an output.
- `BufferBlock`: A simple buffer/queue.
**vs Channels**: `Channels` are better for simple, high-performance, low-level producer-consumer queues. `TPL Dataflow` is better for complex, multi-stage processing pipelines with complex routing and buffering logic.

**DN20**
**Minimal APIs** use a lambda-based approach to define endpoints without Controllers.
- **Pros**: Less boilerplate, faster startup, great for microservices.
- **Cons**: Can become messy in large apps; harder to organize than Controllers.
- **Trade-offs**: Testing is slightly more manual (though `WebApplicationFactory` works); OpenAPI (Swagger) is fully supported via `Microsoft.AspNetCore.OpenApi`.
- **Features**: `Route Groups` allow grouping endpoints by prefix; `Endpoint Filters` allow cross-cutting logic (like validation) to be applied to specific groups.

/## Python

**P1**
`list` is mutable; `tuple` is immutable. `set` is a mutable collection of unique elements; `frozenset` is an immutable version of a set (can be used as a dictionary key).

**P2**
The GIL is a mutex that protects access to Python objects, preventing multiple threads from executing Python bytecodes at once. It affects **CPU-bound** workloads (multithreading won't provide speedup). **Workarounds**: Use `multiprocessing` (separate memory spaces) or use C-extensions (like NumPy) that release the GIL during heavy computation.

**P3**
`copy` (shallow) creates a new object but inserts references to the objects found in the original. `deepcopy` creates a new object and recursively copies all objects found in the original.
**Example**: If `list_a = [[1]]` and `list_b = copy(list_a)`, then `list_b[0].append(2)` will also change `list_a[0]` because the inner list is the same reference.

**P4**
Decorators wrap a function to modify its behavior.
```python
import time
def timer_decorator(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"Execution time: {time.time() - start}s")
        return result
    return wrapper

@timer_decorator
def my_func(): time.sleep(1)
```

**P5**
Generators use `yield` to return values one at a time, maintaining state, which is memory-efficient for large datasets. A `list` returns the entire collection at once. `yield from` is used to delegate to a sub-generator (flattening).

**P6**
- `asyncio.run()`: Entry point to run the main coroutine.
- `asyncio.gather()`: Runs multiple coroutines concurrently and waits for all to finish.
- `asyncio.create_task()`: Schedules a coroutine to run on the loop immediately.
**Warning**: `time.sleep()` is a blocking call. It stops the entire event loop thread, preventing all other tasks from progressing. Use `await asyncio.sleep()` instead.

**P7**
Python uses the **C3 Linearization** algorithm.
**Result**: `D().who()` prints `"C"`.
**Reasoning**: In diamond inheritance `D(B, C)`, Python looks at `D`, then `B`, then `C`, then `A`. Since `C` overrides `who` and is found in the MRO before `A`, it executes `C.who()`.

**P8**
A **metaclass** is a class of a class (it defines how a class behaves).
- `__init_subclass__`: A simpler way to intercept class creation. Use this for simple registration or attribute injection.
- **Metaclass**: Use this for complex logic involving the modification of the class's type/metaclass-level behavior (e.g., enforcing strict API structures).

**P9**
- `multiprocessing`: Bypasses GIL by using separate processes (CPU-bound).
- `threading`: Shared memory, subject to GIL (I/O-bound).
- `concurrent.futures`: High-level interface for both (ThreadPool/ProcessPool).
**Serialization**: `multiprocessing` requires data to be "pickled" (serialized) to be sent between processes. Complex objects (like open file handles) cannot be pickled.

**P/10**
`__slots__` tells Python not to use a `__dict__` for an instance, but only a fixed set of attributes.
- **Use when**: You have millions of small objects.
- **Prevents**: Dynamic attribute creation.
- **Impact**: Significant memory savings and slightly faster attribute access.

**P11**
A **virtual environment** isolates project dependencies.
- `venv`: Built-in Python module for lightweight environments.
- `virtualenv`: A more powerful, third-party alternative to `venv`.
- `conda`: A package and environment manager that handles non-Python dependencies (great for Data Science).

**P12**
Comprehensions are syntactic sugar for loops.
- `map()`/`filter()` are functional-style.
- **Preference**: Comprehensions are generally more "Pythonic" and readable. Use `map`/`filter` when you already have a pre-defined function to apply.

**P13**
`==` checks for **equality** (value); `is` checks for **identity** (memory address).
**Interning**: Python caches small integers (usually -5 to 256) and certain strings in memory. `a is b` returns `True` for small integers because they point to the same pre-allocated memory address.

**P14**
- `*args`: Captures extra positional arguments as a tuple.
- `**kwargs`: Captures extra keyword arguments as a dictionary.
- `/`: Forces parameters before it to be **positional-only**.
- `*`: Forces parameters after it to be **keyword-only**.

**P15**
Context managers handle setup/teardown.
```python
from contextlib import contextmanager

@contextmanager
def database_transaction():
    print("Begin")
    yield
    print("Commit")

with database_transaction():
    print("Doing work")
```
**Example**: A custom lock or a temporary directory cleaner.

**P16**
Type hinting provides metadata for static analysis.
- `Union[int, str]`: Can be int or str.
- `Optional[int]`: Can be int or None.
- `Literal[1, 2]`: Must be exactly 1 or 2.
- `TypeVar`: Generic placeholder.
- `Protocol`: Structural subtyping (duck typing).
`mypy` uses these to find type errors without running the code.

**P17**
- `__repr__`: Unambiguous string for developers (should look like code).
- `__str__`: Readable string for users.
- `__eq__` vs `__hash__`: If you define `__eq__`, you must define `__hash__` if you want the object to be hashable (e/g. for dict keys).
- `__getattr__` (called only if attribute not found) vs `__getattribute__` (called for *every* access).

**P18**
A **descriptor** is an object that defines the access logic for an attribute.
The protocol includes `__get__`, `__set__`, and `__delete__`.
`property`, `classmethod`, and `staticmethod` are all implemented using descriptors to manage how the method is accessed via the class or instance.

**P19**
- **Absolute**: `from mypkg.module import func`.
- **Relative**: `from .module import func`.
`sys.path` is the list of directories Python searches. `PYTHONPATH` is an environment variable that extends `sys.path`. `__init__.py` makes a directory a package. **Namespace packages** allow a single package to be spread across multiple directories/locations. **Finders** locate modules; **Loaders** execute them.

**P20**
- `dataclasses`: Built-in, lightweight, focused on data storage.
- `attrs`: More powerful, handles more edge cases/features.
- `Pydantic`: Focused on **data validation** and parsing (runtime).
**Features**: `__post_init__` runs after `__init__`; `field` factories allow default values for mutable types; `frozen=True` makes the dataclass immutable.
**Choice**: Use **Pydantic** when you are consuming external data (JSON/API) and need to validate types at runtime.
