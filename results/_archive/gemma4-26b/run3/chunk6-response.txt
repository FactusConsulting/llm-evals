## JavaScript / TypeScript

**JS1**
`var` is function-scoped and can be redeclared; `let` and `const` are block-scoped. `const` prevents reassignment of the identifier (though object properties can change). **Hoisting** is the behavior where variable and function declarations are moved to the top of their scope during compilation. `var` is initialized as `undefined`, while `let`/`/const` are hoisted but remain in a "Temporal Dead Zone" until the line of declaration is reached.

**JS2**
The **Event Loop** manages execution. The **Call Stack** tracks the currently executing function. The **Microtask Queue** (Promises, `queueMicrotask`) has higher priority. The **Macrotask Queue** (setTimeout, setInterval, I/O) is processed one task at a time after the microtask queue is empty.

**JS3**
A **closure** is a function that retains access to its lexical scope even when executed outside that scope. 
*Example:* `function outer() { let count = 0; return () => ++count; }`. 
*Bug:* Using `var` in a `for` loop with a `setTimeout` causes all callbacks to see the final value of the loop variable. *Fix:* Use `let` (which creates a new binding per iteration) or an IIFE.

**JS4**
`Promise` represents a future value. `async/await` is syntactic sugar over Promises. Error handling in Promises uses `.catch()`; in `async/await`, it uses `try/catch` blocks. `Promise.all` rejects immediately if *any* promise fails. `Promise.allSettled` waits for all promises to complete, regardless of whether they fulfilled or rejected.

**JS5**
`interface` is primarily for defining object shapes and supports "declaration merging" (adding properties to the same name). `type` is more versatile, allowing unions, primitives, and tuples. Use `interface` for public APIs/class contracts; use `type` for complex logic/unions. **Discriminated Unions** use a common literal property (a "tag") to allow type narrowing in `switch` statements.

**JS6**
**Prototypal inheritance** means objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with the specified prototype. **ES6 Classes** are "syntactic sugar" over prototypes; they don't introduce a new inheritance model but provide a cleaner syntax for the underlying prototype chain.

**JS7**
`this` refers to the execution context. **Binding Rules (Priority):** 1. `new` keyword (constructor), 2. Explicit `bind/call/apply`, 3. Implicit (the object before the dot), 4. Default (global object or `undefined` in strict mode). `bind()` returns a new function with a fixed `this`. You **cannot** re-bind a function once `bind` has been called.

**JS8**
`WeakRef` allows you to hold a reference to an object without preventing its garbage collection (GC). `FinalizationRegistry` executes a callback after an object is GC'ed. Use them for caching/metadata. `WeakMap` keys must be objects because if keys were primitives, they couldn't be tracked for GC, and the map would grow indefinitely (memory leak).

**JS9**
V8 optimizes via **Hidden Classes** (assigning a hidden class to objects based on property order) and **Inline Caching** (remembering where properties were found previously). **Deoptimization** occurs when the engine's assumptions are broken (e.g., changing the shape of an object or passing a different type to a function). Patterns like adding/de/leting properties on objects cause deoptimization.

**JS10**
**Tree-shaking** is dead-code elimination. It works with **ES Modules** because `import/export` are static (analyzable at compile time). **CommonJS** uses `require()`, which is dynamic (evaluated at runtime), making it impossible for tools to know for certain which exports are unused without running the code.

**JS11**
`null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion; `===` (strict equality) does not. **Nullish coalescing (`??`)** returns the right side only if the left is `null` or `undefined`. **Optional chaining (`?.`)** short-circuits and returns `undefined` if the reference is nullish.

**JS12**
`map()` transforms each element; `filter()` selects elements based on a predicate; `reduce()` accumulates elements into a single value. If `reduce` has an initial value, the accumulator starts with that value; otherwise, it starts with the first element of the array. `flatMap()` maps then flattens by one level, useful for handling nested arrays or splitting strings into elements.

**JS1:3**
**Template literals** use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** allow a function to parse the template literal. 
*Example:* `const sql = (strings, ...values) => ...` (used to escape values to prevent SQL injection).

**JS14**
**Destructuring** extracts data from arrays/objects. 
*Object:* `const {a, b: newName} = obj;` (renaming). 
*Array:* `const [first, second] = arr;`. 
*Default:* `const {x = 10} = obj;`. 
*Rest:* `const [head, ...tail] = arr;` (collects remaining elements into a new array).

**JS15**
`for...in` iterates over **enumerable properties** (keys) of an object. `for...of` iterates over **iterable values** (elements) of a collection. Avoid `for...in` on arrays because it iterates over indices as strings and includes non-numeric properties added to the prototype.

**JS16**
**Generics** allow reusable components. 
*Constraint:* `function identity<T extends string>(arg: T)`. 
*Conditional Type:* `type IsString<T> = T extends string ? true : false;`. 
*Infer:* `type Unpack<T> = T extends Array<infer U> ? U : T;`.

**JS17**
**CommonJS** uses `require` (synchronous, Node.js default). **ES Modules** use `import` (asynchronous, browser/modern Node). Node.js handles both via the `.mjs` extension or `"type": "module"` in `package.json`. The `"type": "module"` field tells Node to treat `.js` files as ESM.

**JS18**
TypeScript uses **structural typing** (if it looks like a duck, it is a duck). **Excess property checks** apply only to object literals assigned directly to a type. `extends` is for type inheritance; `satisfies` checks if an expression matches a type without changing the inferred type of the expression. **Variance** (in/out) refers to how subtyping of complex types (like functions) relates to subtyping of their components.

**JS19**
`Proxy` intercepts operations on an object. `Reflect` provides methods to perform those operations (e.g., `Reflect.get`). 
*Example:* A Proxy with a `set` trap can validate that a property is always a number before allowing the assignment.

**JS20**
`SharedArrayBuffer` allows multiple threads (Workers) to share a raw block of memory. `Atomics` provides atomic operations (add, load, store) to prevent race conditions. Workers communicate via `postMessage` or by reading/writing to the `SharedArrayBuffer`. `Atomics.wait` puts a thread to sleep until `Atomics.notify` is called on the same index.

## Bash

**B1**
`$@` represents all arguments as separate words. `$*` represents all arguments as a single string. `"$@"` (quoted) preserves arguments with spaces as individual entities; `"$*"` (quoted) merges all arguments into one string separated by the first character of `IFS`.

**B2**
`set -e`: Exit immediately if a command fails. `-u`: Treat unset variables as an error. `-o pipefail`: The return value of a pipeline is the status of the last command to exit with a non-zero status.

**B3**
`$(command)` is command substitution (executes command and captures output). `` `command` `` is the older, deprecated version of the same. `$((expression))` is arithmetic expansion (evaluates math). `expr` is an external utility for math (slower and more complex syntax).

**B4**
**Process substitution** `<(command)` creates a temporary file descriptor that acts like a file. 
*Example:* `diff <(ls dir1) <(ls dir2)` compares the output of two commands as if they were files.

**B5**
Use `while IFS= read -r f; do ... done < <(find . -type f)`. Avoid `for f in $(ls)` because `ls` output is split by whitespace, breaking filenames containing spaces or newlines.

**B6**
**Here document** (`<<EOF`) passes multiple lines to a command. **Here string** (`<<<`) passes a single string. `<<-EOF` strips leading **tabs** from the input, allowing for indented code in scripts.

**B7**
1. `cmd > file 2>&1`: Redirects stdout to `file`, then redirects stderr to the same place as stdout.
2. `cmd 2>&1 > file`: Redirects stderr to stdout (which is still the terminal), then redirects stdout to `file`.
3. `cmd &> file`: Shorthand for `cmd > file 2>&1`.
The difference is the order of redirection: the first one captures both to the file; the second captures stderr to the terminal.

**B8**
```bash
lockdir="/tmp/mylock"
mkdir "$lockdir" 2>/dev/null || exit 1
trap 'rmdir "$lockdir"; exit' INT TERM EXIT
```
`mkdir` is atomic at the OS level; if two processes run it simultaneously, only one succeeds. File creation (`> file`) is not atomic and can suffer from race conditions where two processes "create" the file but one overwrites the other.

**B9**
`'...'`: Literal (no expansion). `"..."`: Allows variable expansion and command substitution. `no quotes`: Allows expansion but is prone to word-splitting and globbing issues.
*Example:* `echo "$VAR"` vs `echo '$VAR'` (prints value vs prints literal `$VAR`).

**/B10**
Use `[ -f file ]` (file), `[ -d dir ]` (directory), and `[ -r file ]` (readable). `[ ]` (test) is the standard POSIX command; `[[ ]]` is a Bash keyword that is more powerful, supporting regex (`=~`) and logical operators (`&&`, `||`) without quoting issues.

**B11**
`$?`: Exit status of last command (use for error checking). `$$`: PID of current script (use for unique temp files). `$!`: PID of the last background process (use for `wait`). `$#`: Number of arguments passed to the script (use for usage validation).

**B12**
`foo() { ... }` is the standard syntax. `function foo {}` is a Bash-specific extension. To "return" a value, use `echo` and capture it with `$(foo)`, as `return` only sets the exit status (0-255).

**B13**
`PATH` is a colon-separated list of directories. Bash searches these directories from left to right for an executable. **Builtin**: part of the shell (e.g., `cd`). **External**: a separate file (e.g., `ls`). Use `type -a command` to see all locations/types.

**B14**
`trap` intercepts signals. `trap 'cleanup' EXIT ERR INT TERM`. If multiple signals arrive, they are queued/handled sequentially. `EXIT` is always triggered when the script finishes.

**B15**
`xargs` reads items from stdin and executes a command. Command substitution `$(...)` executes a command and puts the output into a string. To handle spaces/newlines: `find . -print0 | xargs -0 command`. `xargs -P N` runs N processes in parallel.

**B16**
**Arrays**: `arr=(a b c)`. **Associative Arrays**: `declare -A map; map[key]=val`. 
*Append:* `arr+=("new")`. *Iterate:* `for i in "${arr[@]}"`. *Length:* `${#arr[@]}`.

**B17**
`(...)` (subshell) creates a child process; variables changed inside do not affect the parent. `{ ...; }` (group command) runs in the current shell; variables changed persist. Piping into `while` creates a subshell, so variable changes inside the loop are lost to the parent script.

**B18**
`SIGINT` (Ctrl+C), `SIGTERM` (request stop), `SIGHUP` (terminal closed), `SIGKILL` (cannot be ignored). For graceful shutdown: trap `SIGTERM`, set a flag, and use `wait` to let background jobs finish before exiting.

**B19**
```bash
split -l 1000 log.txt part_
xargs -P 4 -I {} bash -c 'process_func {}' ::: part_*
```
*Trade-offs:* Parallelism speeds up processing but increases CPU/IO contention. *Error propagation:* Use `set -o pipefail` and check the exit status of the `xargs` command.

**B20**
`exec` replaces the current shell process with the new command. `exec 3>file` opens FD 3 for writing to `file`. `exec 3>&-` closes FD 3. A **coprocess** (`coproc`) runs in the background and communicates via pipes, useful for long-running daemons.

## PowerShell

**PS1**
`Write-Output` sends objects to the pipeline (standard output). `Write-Host` writes directly to the console (UI). In a pipeline, `Write-Host` is "invisible" to downstream commands, which can break automation/data processing.

**PS2**
The **Pipeline** passes objects, not text. `ForEach-Object` is a cmdlet designed for the pipeline (streaming). `foreach` is a language keyword (faster, but requires the collection to be in memory). Use `ForEach-Object` for large streams; use `foreach` for small, in-memory collections.

**PS3**
`[PSCustomObject]` is an ordered collection of properties (best for data). `[hashtable]` is an unordered collection of key-value pairs. Use `[PSCustomObject]` for structured output. Convert via `[PSCustomObject]$hash` or `[hashtable]$obj`.

**PS4**
**Terminating errors** stop execution (e.g., syntax error). **Non-terminating** errors (e.g., file not found) continue the script. `$ErrorActionPreference = 'Stop'` turns non-terminating into terminating. `try/catch` only catches terminating errors unless `ErrorAction` is set to `Stop`.

**PS5**
**Splatting** is passing a hashtable as arguments: `$params = @{ Path='C:\'; Force=$true }; New-Item @params`. It is cleaner than long command lines. It differs from passing a single hashtable because the keys are treated as individual parameter names.

**PS6**
`Invoke-Command -ComputerName` runs a command on a remote machine (one-to-many). `Enter-PSSession` starts an interactive session (one-to-one). It uses **WS-Man** (WinRM) or **SSH**.

**PS7**
The result is a `System.Object[]` (array) because `$result += "one"` re-creates the array. If the function returns nothing, it returns `$null`. The correct pattern is to use `[System.Collections.Generic.List[string]]` and `.Add()`.

**PS8**
A `[scriptblock]` is a block of code `{ ... }`. Pass it via `-ArgumentList`. The **double-hop problem** occurs when you use credentials to connect to Server A, and then try to access Server B from Server A (the credentials don't "hop" automatically). Solve with **CredSSP** or **Kerberos Delegation**.

**PS9**
`@()` is an empty array; `[array]` is a type. To force a single result into an array, use `@($result)`. Indexing into `$null` throws an error; indexing into an empty array returns `$null`.

**PS/PS10**
`-eq` (equality), `-ne` (not equal), `-like` (wildcard), `-match` (regex), `-contains` (checks if collection contains value), `-in` (checks if value is in collection). `-ceq` is case-sensitive. `-contains` checks a collection; `-in` checks a single value against a collection.

**PS11**
A **module** is a collection of functions/cmdlets. `.psm1` is a script module (logic). `.psd1` is a manifest (metadata). **Binary modules** are compiled DLLs. `Import-Module` loads the module into the current session.

**PS12**
`"..."` allows variable expansion; `'...'` is literal. Use `$()` for expressions: `"Value is $($x + 1)"`. **Here-strings** (`@" ... "@`) allow multi-line strings without escaping quotes.

**PS13**
`Get-Member` shows the members of an object. **Properties** (data), **Methods** (actions), **NoteProperties** (added via `Select-Object`). `Select-Object` picks specific properties; `Where-Object` filters objects based on criteria.

**PS14**
**PowerShell Classes** are more similar to C# but have limitations (e.g., no full support for all C# features like complex generics). Use classes for structured data/logic; use functions for procedural tasks.

**PS15**
`[CmdletBinding()]` makes a function behave like a professional cmdlet (enables `-Verbose`, `-ErrorAction`, etc.). `SupportsShouldProcess` enables `-WhatIf`. `ValueFromPipeline` allows input via `|`. `Begin`, `Process`, and `End` blocks allow handling stream-based data efficiently.

**PS16**
**Providers** allow different data stores to be treated like a file system. `Get-ChildItem Registry::HKEY_LOCAL_MACHINE\...` allows you to browse the registry as if it were a folder.

**PS17**
A **runspace** is a single-threaded execution environment. A **runspacepool** manages multiple runspaces for efficiency. `ForEach-Object -Parallel` (v7+) uses a runspacepool internally to execute scriptblocks concurrently.

**PS18**
**PSScriptAnalyzer** is a static code analysis tool. It uses **rules** to check for best practices. You can suppress rules using `# PSDefaultAvoid` or `[Diagnostics.CodeAnalysis.SuppressMessage]`. It integrates into CI/CD via `Invoke-PSScriptAnalyzer`.

**PS19**
`$using:var` is required to pass a local variable into a remote/parallel scope. `$args` is for positional parameters. **Serialization limits** occur when objects are sent over the network; complex objects (like open file handles) are stripped of their "live" state and become "dead" (data-only) objects.

**PS20**
**DSC** uses **Configurations** (code) and **Resources** (logic) managed by the **LCM** (Local Configuration Manager) on the target node. In modern infra, DSC is often replaced by **Terraform** or **Ansible** for orchestration, though DSC is still used for node-level configuration.
