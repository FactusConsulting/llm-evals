## Kubernetes

**K1** — **Deployment** manages stateless pods where any pod can replace another (e.g., a web server). **StatefulSet** manages stateful pods with stable, unique network identifiers and persistent storage that persists across rescheduling (e.g., a database).

**K2** — A ClusterIP Service uses `kube-proxy` (via iptables or IPVS) to intercept traffic sent to the Service's Virtual IP (VIP) and perform DNAT (Destination Network Address Translation) to redirect the packet to the IP of a healthy backend Pod.

**K/3** — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a request for storage by a user. **StorageClass** is a template used to dynamically provision PVs based on specific parameters (e.g., SSD vs HDD). They relate as: User $\rightarrow$ PVC $\rightarrow$ StorageClass $\rightarrow$ Automated PV creation.

**K4** — 
1. `kubectl logs <pod>`: Check application-level errors/stack traces.
2. `kubectl describe pod <pod>`: Check K8s events (e.g., OOMKilled, Liveness probe failure).
3. `kubectl exec` (if possible) or container entrypoint check: Verify if the application process is crashing immediately on startup.
4. Check resource limits/ConfigMaps: Ensure the app isn't crashing due to missing environment variables or insufficient memory/CPU.

**K5** — CoreDNS provides service discovery by resolving Kubernetes Service names to Pod IPs. If CoreDNS is down, internal service-to-service communication via DNS names will fail, and pods will be unable to resolve external domains.

**K6** — The scheduler uses two phases: 
1. **Filtering (Predicates):** Removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, Taints, NodeSelector).
2. **Scoring (Priorities):** Ranks remaining nodes. 
**Factors:** Node resource availability, Pod Anti-affinity (to spread pods), and Image Locality (to reduce pull time).

**K7** — **Yes**, it will be scheduled because the scheduler only considers *requests* (256Mi < 3.5GB available). However, if the pod uses 600Mi, it exceeds its 512Mi limit, and the Linux kernel will trigger an **OOMKill** (Out of Memory Kill) on the container.

**K8** — 
1. **External LB** receives the request and forwards it to the **Ingress Controller** (NodePort/LoadBalancer).
2. **Ingress Controller** (NGINX) inspects the HTTP Host/Path rules.
3. The Controller looks up the **Endpoints** object (the list of Pod IPs) associated with the target **Service**.
4. **kube-proxy/iptables** rules on the node intercept the traffic and perform DNAT to the specific **Pod IP**.
5. The request reaches the **Application Pod**.

**K9** — A **NetworkPolicy** is a firewall rule for pods. By default, if no policy exists, all pods can talk to all pods (Allow All). Once a policy is applied to a pod, that pod becomes "isolated," and only traffic explicitly allowed by the policy is permitted.

**K10** — **RollingUpdate** replaces pods one by one to ensure zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when you have a breaking schema change or when two versions of the app cannot run simultaneously (e._g., shared database locks).

**K11** — A namespace is a virtual cluster within a physical cluster used for isolation. Default namespaces: `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

**K12** — `describe` provides deep metadata. It shows: **Container State/Reason** (e.g., Terminated/Error), **Events** (recent cluster actions), and **Resource Limits/Requests**.

**K13** — A ConfigMap stores non-confidential data in key-value pairs. Consumption methods: 
1. As **Environment Variables** in the pod spec.
2. As **Files/Volumes** mounted into the container's filesystem.

**K14** — **ClusterIP**: Internal-only IP (service-to-service). **NodePort**: Exposes the service on a static port on every Node's IP. **LoadBalancer**: Provisions an external cloud load balancer (e.g., AWS ELB) to route external traffic to the service.

**K15** — A **DaemonSet** ensures that a copy of a specific Pod runs on all (or selected) nodes. Use it for infrastructure tasks like log collectors (Fluentd), monitoring agents (Prometheus Node Exporter), or networking plugins (Calico).

**K16** — **Taints** are applied to *Nodes* to repel pods (e.g., "don't run anything here unless it's a GPU job"). **Node Affinity** is applied to *Pods* to attract them to specific nodes. 
**Use Case:** Use Taints to keep workloads off master nodes; use Affinity to ensure a heavy database pod lands on a node with high-performance SSDs.

**K17** — An **Operator** is a custom controller that uses Custom Resource Definitions (CRDs) to manage complex, stateful applications. Unlike a standard controller (which manages generic objects like Pods), an Operator encodes "domain-specific" operational knowledge (e.g., how to perform a database backup or upgrade).

**K18** — Etcd uses the **Raft** consensus algorithm (Strong Consistency). If quorum is lost, the cluster becomes read-only or fails. To recover from 2/3 loss: You must restore from a known good snapshot (backup) onto a new 3-node cluster, as the remaining node cannot reach a majority to elect a leader.

**K19** — **Role/ClusterRole** defines permissions. **RoleBinding/ClusterRoleBinding** attaches those permissions to a User/ServiceAccount.
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: my-namespace
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: my-namespace
subjects:
- kind: User
  name: developer-user
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — With `ndots:5` (default), the resolver tries to append search domains (e.g., `google.com.namespace.svc.cluster.local`) before trying the absolute name. This causes multiple failed DNS queries for every external lookup. **Fix:** Use `dnsConfig` in the Pod spec to set `ndots: 1` or use a trailing dot in the application's connection string (e.g., `google.com.`).

## Development

**D1** — **Merge** combines histories by creating a new "merge commit." **Rebase** rewrites history by moving your changes onto the tip of the target branch. **Avoid rebasing** on public/shared branches, as it rewrites history and breaks other developers' local copies.

**D2** — **TCP** is connection-oriented, reliable, and guarantees order (e.g., HTTP, SSH). **UDP** is connectionless, faster, but unreliable/unordered (e.g., DNS, VoIP/Streaming).

**D3** — A race condition occurs when the outcome of a program depends on the non-deterministic timing of uncontrollable events. 
**Example:** Two threads incrementing the same integer `x = x + 1` simultaneously. Both might read `x=10`, both calculate `11`, and both write `11`, resulting in one lost increment.

**D4** — **Symmetric** uses one key for both encryption and decryption. **Asymmetric** uses a public key for encryption and a private key for decryption. In **TLS**, asymmetric encryption is used during the handshake to securely exchange a "session key," which is then used with symmetric encryption for the actual data transfer (for speed).

**D5** — A layer is a read-only filesystem change. **Best Practice:** Order instructions from "least likely to change" to "most likely to change." This maximizes layer reuse, speeding up builds and reducing storage.

**D6** — 
1. **Application Logs:** Check for internal errors or timeouts.
2. **Upstream Dependencies:** Check if a downstream microservice or database is failing.
3. **Resource Exhaustion:** Check for CPU/Memory spikes or connection pool exhaustion.
4. **Network/Load Balancer:** Check for configuration errors or health check failures.

**D7** — **CAP Theorem** states a distributed system can only provide two of three: Consistency, Availability, or Partition Tolerance. 
**CP (Consistency/Partition):** MongoDB (prioritizes data integrity; may reject writes during a partition). 
**AP (Availability/Partition):** Cassandra (prioritizes uptime; may return stale data during a partition).

**D8** — **Horizontal Scaling** adds more instances (nodes/pods). **Vertical Scaling** adds more resources (CPU/RAM) to an existing instance. **Patterns:** Statelessness (allowing any node to handle any request), Load Balancing, and Sharding.

**D9** — An environment variable is a dynamic value used by processes. To make it persistent on Linux, add `export VAR_NAME=value` to your `~/.bashrc` or `~/profile` file.

**D10** — **JSON** is data-interchange format (syntax-heavy, uses braces/brackets). **YAML** is human-readable configuration (uses indentation). **JSON Advantage:** Faster/easier for machines to parse. **YAML Advantage:** Much easier for humans to read and write.

**D11** — **REST** is an architectural style for networked applications. 
- **GET:** Retrieve data.
- **POST:** Create new data.
- **PUT:** Replace/Update existing data.
- **DELETE:** Remove data.

**D12** — Version pinning is specifying the exact version of a dependency (e.g., `requests==2.25.1`). It is vital for **reproducible builds**, ensuring that a build today results in the exact same binary as a build six months from now, preventing "breaking changes" from unexpected updates.

**D13** — **Compiled:** Translated to machine code before execution (e.g., C++, Rust). **Interpreted:** Executed line-by-line by an interpreter (e.g., Python, JavaScript).

**D14** — A **Reverse Proxy** sits in front of web servers and forwards client requests to them (protecting/balancing the server). A **Forward Proxy** sits in front of clients and forwards requests to the internet (hiding/filtering the client). 
**Reverse Proxies:** NGINX (Load Balancing), HAProxy (High-availability).

**D15** — A deadlock is a state where a set of processes are blocked because each is holding a resource the other needs. **Coffman Conditions:** 
1. Mutual Exclusion. 
2. Hold and Wait. 
3. No Preemption. 
4. Circular Wait.

**D16** — **Eventual Consistency** guarantees that if no new updates are made, all accesses will eventually return the last updated value. **Cassandra** uses "Tunable Consistency" via levels like `ONE` (fast, low consistency), `QUORUM` (majority of nodes must respond), or `ALL` (highest consistency, lowest availability).

**D17** — **mTLS** requires both client and server to present X.509 certificates to prove identity. 
**Handshake:** 1. Client sends "Hello" + Certificate. 2. Server verifies Client Cert and sends its own Certificate. 3. Both verify the chain of trust to a Root CA. 4. They derive a symmetric session key. 
**Usage:** Service Meshes (e.g., Istio) for Zero Trust networking.

**D1/D18** — A **Hash Table** maps keys to indices via a hash function. 
- **Chaining:** Each bucket holds a linked list of entries (handles collisions by appending). 
- **Open Addressing:** Finds another empty slot in the array (e.g., Linear Probing). 
**Complexity:** 
- **Average:** $O(1)$ for Insert, Lookup, Delete. 
- **Worst Case:** $O(n)$ (when all keys hash to the same bucket).

**D19** — A **Circuit Breaker** prevents a failing service from causing a system-wide crash. 
- **Closed:** Normal operation; requests pass through. 
- **Open:** Failure threshold reached; requests fail fast immediately without hitting the service. 
- **Half-Open:** Periodically allows a "test" request to see if the service has recovered. 
It works with **Retry/Exponential Backoff** by ensuring we don't "retry" a service that is already overwhelmed, giving it time to recover.

**D20** — **Optimistic:** Assumes no conflict; checks for changes before committing (e.g., using a `version` column). Best for low-contention environments. **Pessimistic:** Locks the resource immediately upon reading (e.g., `SELECT FOR UPDATE`). Best for high-contention environments where conflicts are frequent and costly.
