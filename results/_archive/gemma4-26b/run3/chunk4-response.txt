## Go

**G1**
An **array** has a fixed size defined at compile time; its size is part of its type. A **slice** is a descriptor for a contiguous segment of an array, containing a pointer, length, and capacity. When `append` exceeds a slice's capacity, Go allocates a new, larger underlying array, copies the old elements, and returns a new slice pointing to the new memory.

**G2**
`var x int` declares a variable and initializes it to its zero value (`0`). `x := 0` is short-hand declaration and initialization. You **cannot** use `:=` outside of a function body (at the package level).

**G3**
A **goroutine** is a lightweight execution unit managed by the Go runtime. Unlike an **OS thread**, which has a large fixed stack (MBs) and requires expensive kernel context switches, goroutines start with a small, growable stack (KBs) and are multiplexed onto OS threads by the **Go Scheduler (GMP model)**.
*   **G (Goroutines):** The application-level tasks.
*   **M (Machine):** The OS thread.
*   **P (Processor):** A resource required to execute Go code; it holds the local run queue of Gs.

**G4**
**Channels** are pipes used for communication between goroutines. An **unbuffered channel** requires both a sender and receiver to be ready simultaneously (synchronous). A **buffered channel** allows sending without an immediate receiver, up/up to its capacity. Sending to a **full buffered channel** blocks the sending goroutine until a receiver removes a value.

**G5**
The `context` package manages deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
// If the request takes > 1s, the context cancels and the request fails.
```

**G6**
Go uses **implicit satisfaction**: a type satisfies an interface simply by implementing its methods. In Java/C#, you must explicitly declare `class MyClass implements Interface`.
`interface{}` (or `any`) can hold any value because every type implements at least zero methods. It is **powerful** for generic data handling but **dangerous** because it bypasses type safety, requiring type assertions or switches that can cause runtime panics.

**G7**
This is unsafe due to a **data race**. The Go memory model does not guarantee that writes to `data` or `ready` in one goroutine are visible to another without explicit synchronization. The loop might see `ready == true` but see an uninitialized or stale `data` due to CPU cache effects or compiler reordering.
**Correct alternatives:** Use `sync/atomic` for the boolean, or use a `sync.Mutex` / `channel` to establish a "happifying" relationship.

**G8**
`sync.Mutex` is an exclusive lock (one writer or one reader). `sync.RWMutex` allows multiple concurrent readers but only one writer.
Use `sync.Map` when you have a "read-heavy" workload with keys that are stable, or when multiple goroutines read, write, and overwrite for disjoint sets of keys.
**Trade-offs:** A regular map + `Mutex` is faster for simple, high-contention write workloads. `sync.Map` reduces cache contention on multi-core systems for specific access patterns but has higher overhead for standard operations.

**G9**
**Go modules** manage dependencies. `go.mod` defines the module path and specific versions of dependencies. `go.sum` contains cryptographic hashes of dependencies to ensure integrity. `go mod tidy` removes unused dependencies and adds missing ones. **MVS (Minimum Version Selection)** is the algorithm Go uses to select the lowest compatible version of a dependency that satisfies all requirements in the graph, ensuring reproducible builds.

**G10**
`defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order.
**Gotcha:** Using `defer` inside a `for` loop can cause resource exhaustion (e.g., not closing files until the entire loop finishes), as the deferred calls only execute when the *function* exits, not the loop iteration.

**G11**
A **pointer** holds the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `p := &User{Name: "Alice"}`.

**G/12**
`init()` runs automatically when the package is initialized, before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source code (within the same file) and in the order of package dependency resolution.

**G13**
`new(T)` allocates zeroed storage for a type `T` and returns a pointer (`*T`). `make(T, args)` is used only for built-in types (**slices, maps, channels**) to initialize their internal data structures and return an initialized value of type `T`.

**G14**
Errors are values. The `error` interface requires a `Error() string` method. The idiomatic pattern is `if err != nil { return err }`.
`errors.Is` checks if an error wraps a specific error (useful for wrapped errors); `errors.As` checks if an error can be assigned to a specific type; `==` only checks for identity/value equality, failing if the error was wrapped with context.

**G1/5**
*   **Map:** `nil`
*   **Slice:** `nil`
*   **Channel:** `nil`
*   **Struct:** Zeroed fields (e.g., `int` is `0`, `string` is `""`).

**G16**
A **race condition** occurs when two goroutines access the same memory concurrently and at least one access is a write. The `-race` flag enables a detector that monitors memory access at runtime.
**Example:**
```go
// Race:
go func() { count++ }() 
// Fix:
var mu sync.Mutex
mu.Lock()
count++
mu.Unlock()
```

**G17**
`select` lets a goroutine wait on multiple communication operations. Unlike `switch` (which evaluates values), `select` evaluates channel readiness. If multiple cases are ready, one is chosen **pseudo-randomly**. A timeout is implemented using `time.After`:
```go
select {
case res := <-ch: // handle result
case <-time.After(2 * time.Second): // handle timeout
}
```

**G18**
**Escape analysis** is the process where the compiler determines if a variable can reside on the stack or must "escape" to the heap. Variables escape if they are returned from a function, shared via pointers, or are too large. You can inspect this with `go build -gcflags="-m"`. It matters because heap allocation increases GC pressure and latency.

**G19**
`reflect.Type` represents the type metadata; `reflect.Value` represents the actual data/value. Reflection is computationally expensive due to runtime type checking and dynamic dispatch. It is justified for generic libraries (like JSON encoders) but should be replaced by **code generation** (e._g., `stringer`) in performance-critical paths.

**G20**
`//go:embed` allows embedding static files into the binary at compile time. It supports single files, directories, and `embed.FS`. It interacts with `io/fs.FS` to provide a virtual file system. **Limitations:** You cannot embed files that are not part of the module or files that are excluded by build constraints.

## Rust

**R1**
1. Each value in Rust has a variable called its **owner**.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the value is dropped.

**R2**
`String` is an owned, heap-allocated, growable UTF-8 string. `&str` is a "string slice," a borrowed reference to a string. Use `String` when you need to modify or own the data; use `&str` in function signatures to allow the function to accept both `String` and `&str` (more flexible).

**R3**
**Borrowing** allows access to data without taking ownership.
*   **Shared Reference (`&T`):** You can have infinite shared references, but you cannot mutate the data.
*   **Mutable Reference (`&mut T`):** You can have exactly **one** mutable reference to a piece of data at a time, and no other references (shared or mutable) can exist simultaneously.

**R4**
`Result<T, E>` represents success (`Ok`) or failure (`Err`). `Option<T>` represents presence (`Some`) or absence (`None`). The `?` operator performs an early return if the result is an `Err`.
```rust
use std::fs;
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = fs::read_to_string(path)?; // returns Err early if fails
    Ok(content)
}
```

**R5**
*   `Box<T>`: Single ownership, heap allocation. Use for large types or recursive structures.
*   `Rc<T>`: Reference counting for multiple ownership in a **single thread**.
*   `Arc<T>`: Atomic reference counting for multiple ownership **across threads**.

**R6**
**Traits** define shared behavior (similar to interfaces).
*   **Trait Object (`dyn Trait`):** Uses dynamic dispatch (runtime lookup via vtable). Used when the concrete type is unknown at compile time.
*   **Generics (`T: Trait`):** Uses static dispatch (monomorphization). The compiler generates specific code for every type used, which is faster.

**R7**
The compiler fails because it cannot guarantee the lifetime of the returned reference. The returned reference might point to `x` or `y`, but the function signature doesn't specify that the return value lives as long as the inputs.
**Fix:** Add a lifetime annotation: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8**
`Send` means a type can be transferred between threads. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send` because its internal reference count is not updated atomically; if two threads increment it simultaneously, the count could become corrupted. `Arc<T>` uses atomic operations, making it `Send` and `String`.

**R9**
Rust's `async` is **poll-based**. A `Future` is a state machine that does nothing until `poll()` is called. An **executor** (like Tokio) manages these futures, calling `poll` repeatedly. Unlike Go, where goroutines are "always-on" and managed by a runtime scheduler, Rust futures are lazy and only progress when driven by an executor.

**R10**
`unsafe` allows bypassing the borrow checker. You can: 1. Dereference raw pointers, 2. Call unsafe functions, 3. Mutate a `static mut` variable. It is justified when interfacing with C (FFI) or implementing low-level data structures (like `Vec`) where the compiler cannot prove safety.

**R11**
**Pattern matching** (`match`) is a control flow construct that compares a value against a series of patterns. `if let` is "syntactic sugar" for a `match` with a single arm. The compiler enforces **exhaustiveness**, meaning every possible value of the type must be handled, preventing unhandled logic errors.

**R12**
`Vec<T>` is a heap-allocated, growable array. `[T; N]` is a fixed-size array on the stack. When a `Vec` exceeds capacity, it allocates a new, larger block of memory on the heap, copies the elements, and deallocates the old memory.

**R13**
Rust **Enums** are "sum types" (algebraic data types); they can hold data in each variant. In C, enums are just integers. `Option<T>` is an enum with `Some(T)` and `None`. Rust has no `null` because `Option` forces the developer to explicitly handle the "nothing" case, preventing null-pointer exceptions.

**R1/4**
*   `&self`: Immutable borrow (read-only).
*   `&mut self`: Mutable borrow (read/write).
*   `self`: Consumes the object (moves ownership).
**Associated functions** are functions defined in an `impl` block that do not take `self` (e.g., constructors like `String::new()`).

**R15**
`#[derive]` automatically implements traits. Examples: `Debug` (printing), `Clone` (duplication), `PartialEq` (equality). You cannot derive a trait if the underlying types do not also implement that trait (e.g., you can't derive `PartialEq` if a field is a type that doesn't support equality).

**R16**
`Cow` (Clone-on-Write) is a smart pointer that allows for efficient handling of data that is mostly read but occasionally modified. It avoids allocation if you only need to read the data; it only clones the data into an owned `String` if you perform a mutation.

**R17**
`mod` declares a module; `use` brings a path into scope; `pub` makes an item accessible to other modules. The file system maps to modules (e.g., `mod foo;` looks for `foo.rs`). In 2018, the "extern crate" requirement was removed, making module management much more intuitive and less reliant on `Cargo.toml` for internal module visibility.

**R18**
`Pin<T>` ensures that the data at a pointer address will not be moved in memory. This is critical for **self-referential structs** (common in `async` state machines), where a pointer inside the struct points to another field within the same struct. If the struct moved, the pointer would become dangling. `Unpin` is a marker trait for types that *can* be moved safely.

**R19**
**Declarative macros** (`macro_rules!`) use pattern matching to expand code (simpler, "syntax-based"). **Procedural macros** are functions that take a stream of tokens as input and output a new stream (more powerful, "compiler-plugin-based"). **Hygiene** ensures that macros do not accidentally capture or pollute the local variable scope of the caller.

**R20**
**Zero-cost abstractions** mean: 1. What you don't use, you don't pay for (no runtime overhead). 2. What you do use, you couldn't hand-code any better.
*   **Iterators:** Compiled into loops as efficient as manual `for` loops.
*   **Generics (Monomorphization):** The compiler generates specialized code for each type, eliminating the overhead of dynamic dispatch.
*   **Trait Static Dispatch:** Resolves method calls at compile time, allowing for inlining.
