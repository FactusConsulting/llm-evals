## Kubernetes

**K1** — **Deployment** manages stateless pods (identical, replaceable); **StatefulSet** manages stateful pods (unique, persistent identity, ordered deployment/scaling, stable network IDs, and stable storage).

**K2** — It uses `kube-proxy` (via iptables or IPVS) to intercept traffic to the Service's Virtual IP (VIP) and perform DNAT (Destination Network Address Translation) to redirect the packet to the IP of a backend pod.

**K3** — **PersistentVolume (PV)** is the actual storage resource (the "disk"). **PersistentVolumeClaim (PVC)** is a request for storage by a user. **StorageClass (SC)** enables dynamic provisioning by defining "profiles" (e.g., SSD vs HDD) that automatically create PVs when a PVC is created.

**K4** — 1. `kubectl logs <pod>` (check application errors/stack traces). 2. `kubectl describe pod <pod>` (check Events for exit codes or OOMKills). 3. Check `LivenessProbe` configuration (is the app failing health checks?). 4. Check environment variables/ConfigMaps (is a required dependency missing?).

**K5** — CoreDNS provides service discovery by resolving Kubernetes Service names to ClusterIPs. If CoreDNS is down, pods cannot resolve internal service names or external domains, breaking inter-service communication.

**K6** — The scheduler uses two phases: **Filtering** (Predicates) removes nodes that don't meet requirements (e.g., insufficient CPU, node selectors, taints). **Scoring** (Priorities) ranks remaining nodes. Factors: 1. **Resource Availability** (CPU/RAM), 2. **Pod Anti-affinity** (spreading pods), 3. **Node Affinity/Taints**.

**K7** — **Yes**, it will be scheduled because 256Mi (request) fits within the remaining 500Mi (4GB - 3.5GB). However, if it uses 600Mi, it exceeds its 512Mi limit, and the kernel will trigger an **OOMKill** (Out of Memory Kill) on the container.

**K8** — 1. **External LB** receives traffic and forwards to **Ingress Controller** (NGINX) IP. 2. **Ingress Controller** matches the Host/Path rules. 3. Controller looks up the **Service** via the Kubernetes API. 4. Controller uses **Endpoints** (pod IPs) to route. 5. **kube-proxy/iptables** ensures the packet reaches the specific pod IP. 6. Traffic hits the **Application Pod**.

**K9** — A **NetworkPolicy** defines rules for L3/L4 traffic. By default, if no policy exists, all traffic is allowed (open). Once a policy selects a pod, that pod becomes "isolated," and only traffic explicitly allowed by a policy is permitted.

**K10** — **RollingUpdate** replaces pods one-by-one to ensure zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when the application does not support multiple versions running simultaneously (e.g., due to database schema locks).

**K11** — A namespace is a virtual cluster partition. Default namespaces: `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

**K12** — Used to debug pod issues. It shows: 1. **Events** (recent cluster actions), 2. **Container Status/Exit Codes**, 3. **Conditions** (e.g., PodReady), 4. **Mounts/Volumes**.

**K13** — A ConfigMap stores non-confidential data in key-value pairs. Methods: 1. **Environment Variables** (injecting keys as env vars), 2. **Volume Mounts** (mounting keys as files in a directory).

**K14** — **ClusterIP**: Internal only (cluster-wide). **NodePort**: Exposes service on a static port on every Node IP. **LoadBalancer**: Provisions an external cloud load balancer (e.g., AWS NLB/ALB) to route to the service.

**K15** — A **DaemonSet** ensures a copy of a pod runs on every (or selected) node. Use it for infrastructure tasks like log collection (Fluentd), monitoring (Prometheus Node Exporter), or networking (Calico).

**K16** — **Taints** are applied to *nodes* to repel pods; **Tolerations** are applied to *pods* to allow them to stay on tainted nodes. **Node Affinity** is a pod-side preference to attract pods to specific nodes. **Use Case**: Use Taints to keep GPU workloads on GPU nodes; use Affinity to ensure a web app prefers nodes in a specific availability zone.

**K1/17** — An **Operator** is a custom controller that uses CRDs (Custom Resource Definitions) to manage complex, stateful applications. Unlike a standard controller (which manages generic objects like Pods), an Operator encodes "domain-specific" operational knowledge (e.g., how to perform a database backup or schema migration).

**K18** — **etcd** uses the Raft consensus algorithm (strong consistency). If quorum is lost, the cluster becomes read-only or fails. To recover from 2/3 loss: You must restore from a known good snapshot onto a new 3-node cluster and reconfigure the cluster membership.

**K19** — **RBAC** uses **Roles/ClusterRoles** (permissions) and **RoleBindings/ClusterRoleBindings** (assigning permissions to users/groups).
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: my-namespace
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: my-namespace
subjects:
- kind: User
  name: "developer-user"
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20** — With a high `ndots` value (default 5), the resolver tries appending search domains (e.g., `google.com.namespace.svc.cluster.local`) before trying the actual name. This causes multiple failed DNS queries. **Fix**: Use `dnsConfig` in the Pod spec to set `ndots: 1`.

## Development

**D1** — **Merge** combines histories (creates a merge commit). **Rebase** rewrites history by moving your commits to the tip of the target branch. **Avoid rebasing** on public/shared branches, as it rewrites history and breaks other developers' local copies.

**D2** — **TCP** is connection-oriented, reliable, and ordered (HTTP, SSH). **UDP** is connectionless, faster, but unreliable/unordered (DNS, VoIP/Streaming).

**D3** — A race condition occurs when the outcome depends on the timing of uncontrollable events. **Example**: Two threads incrementing a shared integer `x++` simultaneously; both read `5`, both calculate `6`, and the final value is `6` instead of `7`.

**D4** — **Symmetric**: Same key for encryption/decryption (fast). **Asymmetric**: Public/Private key pair (secure key exchange). In **TLS**, asymmetric encryption is used to securely exchange a "session key," and then symmetric encryption is used for the actual data transfer.

**D5** — A layer is a read-only filesystem change. **Best Practice**: Order instructions from least frequent to most frequent changes (e.g., `COPY package.json` before `COPY .`). This maximizes **layer caching**, making builds faster by skipping unchanged layers.

**D6** — 1. **Application Logs** (check for crashes/errors). 2. **Upstream/Dependency Health** (is the DB or a microservice down?). 3. **Resource Exhaustion** (CPU/RAM/Disk on the server). 4. **Network/Load Balancer** (is the LB failing to reach the backend?).

**D7** — **CAP**: Consistency, Availability, Partition Tolerance. You can only guarantee two. **CP Example**: Redis or MongoDB (prioritizes data accuracy; may reject writes during partition). **AP Example**: Cassandra or DynamoDB (prioritizes availability; allows stale reads during partition).

**D8** — **Horizontal**: Adding more instances (nodes/pods). **Vertical**: Adding more power (CPU/RAM) to an existing instance. **Patterns**: Statelessness, Load Balancing, and Sharding enable horizontal scaling.

**D9** — An environment variable is a dynamic value used by processes. To make it persistent in Linux, add `export VAR_NAME="value"` to your `~/.bashrc` or `~/.zshrc` file.

**D10** — **JSON** is data-oriented, strict syntax, used for APIs. **YAML** is human-oriented, uses indentation, used for configuration. **Advantage JSON**: Faster to parse/machine-readable. **Advantage YAML**: Much easier for humans to read/write.

**D11** — **REST API**: An interface using HTTP. **GET** (Retrieve), **POST** (Create), **PUT** (Replace/Update), **DELETE** (Remove).

**D12** — Pinning is specifying exact versions (e.g., `library==1.2.3`). It ensures that every build uses the same dependency version, preventing "it works on my machine" bugs caused by unexpected minor/major updates.

**D13** — **Compiled**: Code is converted to machine code before execution (C++, Rust). **Interpreted**: Code is executed line-by/line by an interpreter (Python, Ruby).

**D14** — A **Reverse Proxy** sits in front of web servers and handles requests on their behalf (protecting/caching). A **Forward Proxy** sits in front of clients to intercept their requests (anonymity/filtering). **Servers**: NGINX (Load balancing), Apache (Content management).

**D15** — A state where a set of processes are stuck because each is waiting for a resource held by another. **Coffman Conditions**: 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait.

**D16** — **Eventual Consistency**: Given enough time without updates, all nodes will return the same value. **Cassandra** uses "Tunable Consistency" via levels: `ANY`, `ONE`, `QUORUM`, `ALL`. A developer can choose `QUORUM` for a balance of speed and consistency.

**D17** — **mTLS** requires both client and server to present certificates. **Handshake**: 1. Client sends "Hello" + Certificate. 2. Server sends "Hello" + Certificate. 3. Both verify the CA signature. 4. They derive a symmetric session key. **Usage**: Service Meshes (Istio/Linkerd) for Zero Trust networking.

**D18** — A hash table maps keys to indices via a hash function. **Collision Resolution**: 1. **Chaining** (each index points to a linked list of entries). 2. **Open Addressing** (searching for the next empty slot). **Complexity**: Average: $O(1)$ for all. Worst: $O(n)$ (all keys hash to the same index).

**D19** — A **Circuit Breaker** prevents a failing service from dragging down the whole system. **States**: 1. **Closed** (Normal, traffic flows). 2. **Open** (Failure detected, requests fail immediately). 3. **Half-Open** (Testing if the service recovered). It works with **Retry/Backoff** by ensuring retries don't overwhelm a struggling service, using increasing delays between attempts.

**D20** — **Optimistic**: Assumes no conflict; checks for changes at commit time (uses version/timestamp). **Pessimistic**: Assumes conflict; locks the resource immediately (e.g., `SELECT FOR UPDATE`). **Choose Optimistic** for high-concurrency, low-contention systems. **Choose Pessimistic** for high-contention, critical data integrity (e.g., banking transactions).
