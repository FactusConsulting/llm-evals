## Go

**G1**
An **array** has a fixed size defined at compile time; its size is part of its type. A **slice** is a descriptor for a contiguous segment of an array, containing a pointer, length, and capacity. When `append` exceeds a slice's capacity, Go allocates a new, larger underlying array, copies the old elements, and returns a new slice pointing to the new memory.

**G2**
`var x int` declares a variable and initializes it to its zero value (`0`). `x := 0` is short-hand declaration and initialization. You **cannot** use `:=` outside of a function body (at the package level).

**G3**
A **goroutine** is a lightweight execution unit managed by the Go runtime, not the OS. Unlike OS threads (which have large stacks and high context-switch overhead), goroutines start with small, growable stacks. The **GMP model** consists of **G**oroutines, **M** (Machine/OS Thread), and **P** (Processor/Logical Context). The scheduler maps $G$s onto $M$s via $P$s, allowing efficient multiplexing of many goroutines onto few threads.

**G4**
Channels are pipes for communication. **Unbuffered channels** require both sender and receiver to be ready simultaneously (synchronous). **Buffered channels** allow sending without a receiver until the buffer is full. Sending to a full buffered channel **blocks** the goroutine until space becomes available.

**/G5**
The `context` package manages deadlines, cancellation signals, and request-scoped values.
```go
ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
resp, err := http.DefaultClient.Do(req)
```

**G6**
Go uses **implicit satisfaction**: if a type implements the methods of an interface, it satisfies that interface automatically (no `implements` keyword). This is "structural typing" vs Java's "nominal typing." `interface{}` (or `any`) can hold any value, making it powerful for generic data, but dangerous because it bypasses type safety, requiring type assertions that can cause runtime panches.

**G7**
This is unsafe due to a **data race** and lack of **memory barriers**. The Go memory model does not guarantee that writes in one goroutine are visible to another without explicit synchronization. The `ready = true` might be reordered or cached in a CPU register, so the loop might never see the update. **Correct alternatives**: Use `sync/atomic` for the flag, or use a `channel` to signal completion, or use a `sync.Mutex`.

**G8**
`sync.Mutex` is exclusive (one writer or one reader). `sync.RWMutex` allows multiple concurrent readers but exclusive access for writers. Use `sync.Map` when you have a "read-heavy" workload with disjoint keys or when multiple goroutines read/write/overwrite different keys. **Trade-off**: `sync.Map` has higher overhead for simple cases but scales better under high contention for specific patterns.

**G9**
`go.mod` defines the module path and dependencies. `go.sum` contains cryptographic hashes of dependencies to ensure integrity. `go mod tidy` removes unused dependencies and adds missing ones. **MVS** is an algorithm that selects the *minimum* version of a dependency that satisfies all requirements, ensuring reproducible builds.

**G/10**
`defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. **Gotcha**: Using `defer` inside a `for` loop can cause resource exhaustion (e.g., file descriptors) because the deferred calls don't execute until the *entire* function returns, not the loop iteration.

**G11**
A **pointer** holds the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `p := &User{Name: "Alice"}`.

**G12**
`init()` runs automatically when a package is initialized. It runs after variable declarations but before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source code.

**G13**
`new(T)` allocates zeroed memory for type `T` and returns a `*T` (pointer). `make(T, args)` is used only for built-in types (**slices, maps, channels**) to initialize their internal data structures (length, capacity, etc.) and returns the value itself, not a pointer.

**G14**
Errors are values. The `error` interface requires a `Error() string` method. The idiomatic pattern is `if err != nil { return err }`. `errors.Is` checks if an error matches a specific target (useful for wrapped errors), while `errors.As` attempts to cast an error to a specific type. `==` only checks for identity/value equality and fails with wrapped errors.

**G15**
- **Map**: `nil` (can read, but writing causes panic).
- **Slice**: `nil` (length 0, capacity 0).
/ **Channel**: `nil` (sending/receiving blocks forever).
- **Struct**: All fields initialized to their respective zero values.

**G16**
A **race condition** occurs when multiple goroutines access shared data concurrently and at least one access is a write. The `-race` flag uses a dynamic detector to find unsynchronized accesses.
*Example*: `count++` is not atomic.
*Fix*: Use `mu.Lock(); count++; mu.Unlock()` or use `atomic.AddInt64(&count, 1)`.

**G17**
`select` waits on multiple channel operations. Unlike `switch` (which evaluates values), `select` evaluates communication readiness. If multiple cases are ready, one is chosen **pseudo-randomly**. To implement a timeout: `case <-time.After(duration):`.

**G18**
**Escape analysis** is the process of determining if a variable can reside on the stack or must "escape" to the heap. The compiler moves variables to the heap if they are shared via pointers, returned from functions, or have an unknown size at compile time. Inspect via `go build -gcflags="-m"`. It matters because heap allocation increases GC pressure and latency.

**G1/9**
`reflect.Type` represents the type metadata (e.g., `int`). `reflect.Value` represents the actual data/instance. Reflection is computationally expensive due to runtime type checking and prevents compiler optimizations. Use it for generic libraries (like JSON encoders) but prefer **code generation** (e.g., `stringer`) for performance-critical logic.

**G20**
`//go:embed` allows embedding static files into the binary. It supports single files, directories, or patterns. It integrates with `io/fs.FS`, allowing you to treat embedded files as a virtual file system. **Limitation**: You cannot embed files that are not part of the module or use relative paths outside the module root.

## Rust

**R1**
1. Each value has a variable called its **owner**.
2. There can only be one owner at a time.
3. When the owner goes out of scope, the value is dropped.

**R2**
`String` is an owned, heap-allocated, growable UTF-8 buffer. `&str` is an immutable "string slice" (a pointer and a length). Use `String` when you need to modify or own the data; use `&str` in function arguments to allow the function to accept both `String` and `String` slices.

**R3**
**Borrowing** allows accessing data without taking ownership.
- **Shared references (`&T`)**: You can have infinite shared references, but no mutable references at the same time.
- **Mutable references (`&mut T`)**: You can have exactly one mutable reference, and no other references (shared or mutable) can exist simultaneously.

**R4**
`Result<T, E>` handles recoverable errors; `Option<T>` handles the presence/absence of a value. The `?` operator performs an early return if the result is an `Err` or `None`.
```rust
use std::fs;
use std::io;

fn read_file(path: &str) -> Result<String, io::Error> {
    let content = fs::read_to_string(path)?;
    Ok(content)
}
```

**R5**
- `Box<T>`: Single ownership, heap allocation.
- `Rc<T>`: Reference-counted (non-thread-safe) multiple ownership.
- `Arc<T>`: Atomic reference-counted (thread-safe) multiple ownership.
Use `Box` for recursive types; `Rc` for single-threaded graphs; `Arc` for shared state across threads.

**R6**
**Traits** define shared behavior (similar to interfaces but more powerful).
- **Trait Object (`dyn Trait`)**: Dynamic dispatch; the exact type is unknown at compile time (uses a vtable).
- **Generics (`T: Trait`)**: Static dispatch; the compiler generates specific code for each type (monomorphization).

**R7**
It fails because the compiler cannot guarantee that the returned reference lives as long as the input references.
**Fix**: Add lifetime annotations to link the output lifetime to the inputs:
`fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`

**R/8**
`Send` means a type can be moved to another thread. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send` because its reference count is not updated atomically, leading to data races on the count. `Arc<T>` uses atomic operations, making it `Send` and `Sync`.

**R9**
Rust's `async` is **poll-based**. A `Future` is a state machine that does nothing until `poll()` is called. An **executor** (like Tokio) manages a pool of threads and calls `poll()` on futures. Unlike Go, where goroutines are "always-on" and managed by a runtime-level scheduler, Rust futures are lazy and do nothing unless polled.

**R10**
`unsafe` allows dereferencing raw pointers, calling unsafe functions, and mutating static variables.
**3 things**: 1. Dereferencing a raw pointer. 2. Calling an `unsafe` function. 3. Accessing a `static mut` variable.
**Justification**: When interfacing with C libraries (FFI) or implementing low-level data structures (like `Vec`) where the compiler cannot prove safety.

**R11**
`match` is a pattern-matching construct that compares a value against a series of patterns. `if let` is "syntactic sugar" for a `match` with a single arm. The compiler enforces **exhaustiveness**: every possible value of the type must be covered by a pattern.

**R12**
`Vec<T>` is a heap-allocated, growable array. `[T; N]` is a fixed-size array on the stack. When a `Vec` exceeds capacity, it allocates a new, larger block of memory on the heap and moves the elements.

**R13**
Rust enums are **sum types** (can hold data in each variant). Unlike C enums (integers) or Java enums (objects), Rust enums are powerful algebraic data types. `Option<T>` is an enum with `Some(T)` and `None`. Rust has no `null` to prevent "null pointer exceptions"; you must explicitly handle the `None` case.

**R14**
- `&self`: Immutable borrow of the instance.
- `&mut self`: Mutable borrow of the instance.
- `self`: Consumes the instance (takes ownership).
**Associated functions** are functions defined in an `impl` block that do not take `self` (e.g., constructors like `String::new()`).

**R15**
`#[derive(Trait)]` automatically implements a trait for a struct. Examples: `Debug` (printing), `Clone` (deep copy), `PartialEq` (equality). You **cannot** derive a trait if the implementation requires complex logic that cannot be automatically generated (e.g., `Display`).

**R16**
`Cow` (Clone-on-Write) is a smart pointer that allows for both borrowed and owned data. It is useful when you want to avoid allocation if the data doesn't need modification.
*Example*: A function that returns a `Cow<str>`. If the input string needs no changes, it returns a `Borrowed` variant (no allocation). If it needs a replacement, it returns an `Owned` variant (allocates).

**R17**
`mod` declares a module; `use` brings paths into scope; `pub` makes items visible. The file system maps to modules (e.g., `mod auth` looks for `auth.rs` or `auth/mod.rs`). In 2018, the "module system" was simplified, making it easier to declare modules without needing `mod.rs` files everywhere.

**R18**
`Pin<T>` ensures that the data at a pointer address will not move in memory. This is critical for **self-referential structs** (common in `async` state machines) where a pointer inside the struct points to another field within the same struct. If the struct moved, the pointer would become dangling. `Unpin` is a marker trait for types that *can* be moved safely.

**R19**
- **Declarative (`macro_rules!`)**: Pattern-matching based, easier to write, but limited.
- **Procedural**: More powerful; they act like functions that take code as input and output code. Types: `derive` (for attributes), `attribute` (modifies items), and `function-like` (like `sql!`).
**Hygiene**: A rule ensuring that macros don't accidentally capture variables from the surrounding scope.

**R20**
Zero-cost abstractions mean you don't pay for what you don't use, and what you do use is as efficient as manual code.
- **Iterators**: Compiled into tight loops via monomorphization.
- **Generics**: The compiler generates specialized code for every type used (monomorphization), eliminating runtime dispatch.
- **Trait Static Dispatch**: Uses vtables or direct calls, allowing high-level code to be optimized into the same machine instructions as hand-written C.
