## JavaScript / TypeScript

**JS1**
`var` is function-scoped and can be redeclared; `let` and `const` are block-scoped. `const` prevents reassignment of the identifier, but the underlying object can still be mutated. **Hoisting** is the behavior where variable and function declarations are moved to the top of their scope during compilation. `var` is initialized as `undefined`, while `let`/`const` are hoisted but remain in a "Temporal Dead Zone" until the declaration is reached.

**JS2**
The **Event Loop** manages execution. The **Call Stack** tracks the currently executing function. The **Microtask Queue** (e.g., `Promise` callbacks) has higher priority. The **Macrotask Queue** (e.g., `setTimeout`, `setInterval`) is processed after the microtask queue is empty and the stack is clear.

**JS3**
A **closure** is a function that retains access to its lexical scope even when executed outside that scope. 
*Example:* `function outer() { let count = 0; return () => ++count; }`. 
*Classic Bug:* Using `var` in a `for` loop with an async operation; the loop finishes before the callback runs, and all callbacks reference the same final value of `var`. *Fix:* Use `let` (which creates a new binding per iteration) or an IIFE.

**JS4**
`Promise` represents a future value. `async/await` is syntactic sugar over Promises. Error handling in `async/await` uses `try/catch`. In raw Promises, you use `.catch()`. `Promise.all` rejects immediately if *any* promise fails. `Promise.allSettled` waits for all promises to either fulfill or reject, returning an array of objects describing the outcome of each.

**JS5**
`interface` is primarily for defining object shapes and supports declaration merging. `type` is more flexible, allowing unions, primitives, and intersections. Use `interface` for public APIs/class contracts; use `type` for complex logic/unions. **Discriminated Unions** use a common literal property (a "tag") to allow type narrowing in `switch` or `if` statements.

**JS6**
**Prototypal inheritance** means objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with the specified prototype. **ES6 Classes** are "syntactic sugar" over prototypes; they don't introduce a new inheritance model but provide a cleaner syntax for the existing prototype-based system.

**JS7**
`this` refers to the execution context. **Binding Rules (Priority):** 1. `new` binding, 2. Explicit binding (`call`, `apply`, `bind`), 3. Implicit binding (the object before the dot), 4. Default binding (global object/undefined in strict mode). `bind()` returns a new function with a fixed `this`. You **cannot** re-bind a function that has already been bound via `bind`.

**JS8**
`WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` allows executing a callback after an object is GC'd. Use them for metadata/caches that shouldn't cause memory leaks. `WeakMap` keys must be objects because primitives cannot be tracked for GC, and if keys were primitives, they could never be "collected," leading to leaks.

**JS9**
V8 optimizes via **Hidden Classes** (tracking object shapes) and **Inline Caching** (storing results of property look/lookup). **Deoptimization** occurs when the engine's assumptions are broken (e.g., a property type changes). *Patterns causing deoptimization:* Changing the shape of an object (adding/deleting properties), passing different types to a function (polymorphism), or using `delete`.

**JS10**
**Tree-shaking** is dead-code elimination. **ES Modules** are static, allowing tools to determine which exports are unused at build time. **CommonJS** is dynamic (`require` can be inside an `if` block), making it impossible to know what is used without executing the code. Therefore, CJS cannot be effectively tree-shaken.

**JS11**
`null` is an intentional absence of value; `undefined` means a variable has been declared but not assigned. `==` performs type coercion; `===` checks both value and type. **Nullish coalescing (`??`)** returns the right side only if the left is `null` or `undefined`. **Optional chaining (`?.`)** short-circuits and returns `undefined` if the reference is nullish.

**JS12**
`map()` transforms each element; `filter()` selects elements based on a predicate; `reduce()` accumulates elements into a single value. If `reduce` has an initial value, that value is used as the first `accumulator` and the loop starts at the second element. `flatMap()` maps each element and then flattens the result by one level, useful for handling nested arrays returned by a map function.

**JS13**
**Template literals** use backticks (`` ` ``) for multi-line strings and interpolation (`${}`). **Tagged templates** allow a function to parse the template literal. 
*Example:* `const sql = (strings, ...values) => ...` (to escape values to prevent SQL injection).

**JS14**
**Destructuring** extracts data from arrays/objects into variables. 
*Object:* `const {name: n} = obj;` (renaming). 
*Array:* `const [first] = arr;`. 
*Default:* `const {a = 1} = obj;`. 
*Rest:* `const [head, ...tail] = arr;` (collects remaining elements into a new array).

**JS15**
`for...in` iterates over enumerable **string keys** (properties) of an object. `for...of` iterates over **iterable values** (elements) of a collection. Avoid `for...in` on arrays because it iterates over indices as strings and may include non-index properties added to the array object.

**JS16**
**Generics** allow reusable components. 
*Constraint:* `function identity<T extends string>(arg: T)`. 
*Conditional Type:* `type IsString<T> = T extends string ? true : false;`. 
*Infer:* `type Unpack<T> = T extends Array<infer U> ? U : T;`.

**JS17**
**CommonJS** uses `require` (synchronous, runtime) and `module.exports`. **ESM** uses `import/export` (static, parse-time). Node.js handles both, but ESM is the standard. The `"type": "module"` in `package.json` tells Node.js to treat `.js` files as ESM instead of CJS.

**JS18**
**Structural typing** means compatibility is based on the shape (members), not the name. **Excess property checks** occur only during direct object literals (e.g., `const x: T = { ... }`). `extends` is for subtyping; `satisfies` (TS 4.9+) validates that an expression matches a type *without* widening the type of the expression. **Variance** (in/out) refers to how subtyping of complex types (like functions) relates to their components.

**JS19**
`Proxy` intercepts operations on an object; `Reflect` provides methods to perform those operations (e.g., `Reflect.get`). 
*Example:* A Proxy with a `get` trap that logs every time a property is accessed: `get(target, prop) { console.log(prop); return Reflect.get(target, prop); }`.

**JS20**
`SharedArrayBuffer` allows multiple threads (Workers) to access the same raw memory. `Atomics` provides static methods to perform thread-safe operations (like `add` or `wait`) to prevent race conditions. `Atomics.wait` puts a thread to sleep until `Atomics.notify` is called on the same index, ensuring ordered, synchronized memory access.

## Bash

**B1**
`$*` represents all positional parameters as a single string. `$@` represents all parameters as separate strings. `"$*"` is one single string (space-separated); `"$@"` preserves individual arguments even if they contain spaces.

**B2**
`set -e`: Exit immediately if a command fails.
`set -u`: Treat unset variables as an error.
`set -o pipefail`: The return value of a pipeline is the status of the last command to exit with a non-zero status.

**B3**
`$(command)` is command substitution (executes command and returns output). `` `command` `` is the older, deprecated version. `$((expression))` is arithmetic expansion (calculates math). `expr` is an external utility for math (slower and harder to use).

**B4**
**Process substitution** `<(command)` creates a temporary file-like pipe. Use it when a command expects a file but you want to provide the output of another command. 
*Example:* `diff <(ls dir1) <(ls dir2)` compares the contents of two directories.

**B5**
Use `while read -r f; do ... done < <(find . -print0 | xargs -0)` or globbing `for f in ./*; do`. `for f in $(ls)` is dangerous because it splits filenames containing spaces or newlines into multiple loop iterations.

**B/B6**
`<<EOF` (Here Doc) allows multi-line input. `<<<` (Here String) passes a single string to a command. `<<-EOF` strips leading **tabs** from the input, which is useful for indented scripts.

**B7**
1. `cmd > file 2>&1`: Redirects stdout to `file`, then redirects stderr to the same place as stdout.
2. `cmd 2>&1 > file`: Redirects stderr to where stdout *currently* points (the terminal), then redirects stdout to `file`.
3. `cmd &> file`: Shorthand for `cmd > file 2>&1`.

**B8**
```bash
lockdir="/tmp/mylock"
mkdir "$lockdir" 2>/dev/null || exit 1
trap 'rmdir "$lockdir"; exit' INT TERM EXIT
# ... critical section ...
rmdir "$lockdir"
```
`mkdir` is atomic at the OS level; if two processes try to `mkdir` the same path, only one succeeds. File creation (`> file`) is not inherently atomic for locking.

**B9**
`'...'`: Literal (no expansion). `"..."`: Allows variable/command expansion. `no quotes`: Allows expansion but splits on whitespace (dangerous).
*Example:* `echo '$USER'` prints `$USER`; `echo "$USER"` prints `username`; `echo $USER` (no quotes) might fail if the variable contains spaces.

**

**B10**
`[ -f file ]` (file exists), `[ -d dir ]` (is directory), `[ -r file ]` (is readable). `[[ ]]` is a Bash keyword that is more powerful, supports regex (`=~`), and doesn't require quoting variables to prevent word splitting.

**B11**
`$?`: Exit status of last command. `$$`: PID of current shell. `$!`: PID of last background command. `$#`: Number of arguments.

**B12**
`foo() { ... }` and `function foo { ... }` are similar, but `foo()` is POSIX-compliant. To "return" values, use `echo` and capture with `$(...)`, as `return` only sets the exit status (0-255).

**B13**
`PATH` is a colon-separated list of directories. Bash searches these in order. **Builtin** (e.g., `cd`, `echo`) is part of the shell; **External** (e.g., `ls`, `grep`) is a file in a directory in `PATH`. Use `type -a command` to check.

**B14**
`trap` intercepts signals. `trap 'cleanup' EXIT ERR INT TERM`. If multiple signals arrive, they are handled sequentially. `EXIT` is always the last to run.

**B15**
`xargs` takes stdin and turns it into arguments for a command. `command substitution` executes a command and puts output in a string. Use `find -print0 | xargs -0` to handle filenames with spaces/newlines. `xargs -P N` runs N processes in parallel.

**B16**
`declare -a arr` (indexed); `declare -A assoc` (associative). 
*Append:* `arr+=("val")`. *Iterate:* `for i in "${!arr[@]}"`. *Length:* `${#arr[@]}`.

**B1/B17**
`(...)` (subshell) creates a new process; variables changed inside do not affect the parent. `{ ...; }` (group command) runs in the current shell; variables changed *do* affect the parent. Piping `cmd | while read...` creates a subshell, so variables updated inside the loop are lost when the loop ends.

**B18**
`SIGINT` (Ctrl+C), `SIGTERM` (Request stop), `SIGHUP` (Terminal closed), `SIGKILL` (Immediate kill, cannot be caught). For graceful shutdown: `trap 'kill $(jobs -p)' EXIT` to ensure background children die with the parent.

**B19**
```bash
split -l 1000 log.txt part_
xargs -P 4 -I {} bash -c 'process_func {}' < <(ls part_*)
cat part_* > final.log
```
*Trade-offs:* Parallelism speeds up processing but increases CPU/IO load. *Error propagation:* Use `set -o pipefail` so the `xargs` exit code reflects a failure in any child.

**B20**
`exec` replaces the current shell process with the new command. `exec 3>file` opens FD 3 for writing to `file`. `exec 3>&-` closes FD 3. A **coprocess** (`coproc`) allows a background process to communicate with the shell via pipes, useful for long-running daemons.

## PowerShell

**PS1**
`Write-Output` sends objects to the pipeline (standard output). `Write-Host` writes directly to the host/console. `Write-Host` cannot be captured by a pipeline, making it useless for automation/redirection.

**PS2**
The **Pipeline** passes whole objects between commands. `ForEach-Object` is a cmdlet that processes objects one-by one through the pipeline (memory efficient). `foreach ($x in $y)` is a language keyword that loads the entire collection into memory first (faster for small/medium sets).

**PS3**
`[PSCustomObject]` is an ordered, lightweight object used for data. `[hashtable]` is an unordered collection of key-value pairs. Use `PSCustomObject` for pipeline output. Convert: `[PSCustomObject]$hash` or `[hashtable]$obj`.

**PS4**
**Terminating errors** stop execution (e.g., `throw`). **Non-terminating errors** (e.g., `Remove-Item` on a locked file) continue execution. `$ErrorActionPreference = 'Stop'` turns non-terminating errors into terminating ones, allowing `try/catch` to work.

**PS5**
**Splatting** is passing a hashtable as arguments: `$params = @{ Path='C:\'; Force=$true }; Remove-Item @params`. It is cleaner than long command lines. It differs from passing a single hashtable parameter because it expands the keys as individual named arguments.

**PS6**
`Invoke-Command -ComputerName` runs a command on a remote machine (one-to-many). `Enter-PSSession` starts an interactive session (one-to-one). It uses **WS-Man** (WinRM) or **SSH**.

**PS7**
The function returns an **array** if there are multiple items, but a **single object** (or even a string) if there is one. If 0 items, it returns `$null`. This breaks type-safety. *Correct pattern:* `[array]$result = ...` or use the unary comma operator `,` to force an array.

**PS8**
A `[scriptblock]` is a chunk of code. You pass it via `-ArgumentList` or `$using:`. The **Double-Hop** problem occurs when you use a remote session to access a *third* machine (e.g., `Invoke-Command` -> `SMB share`). Solve it using **CredSSP** or **Kerberos Delegation**.

**PS9**
`@()` is an empty array; `[array]` is a type. To force a single result into an array, use the comma operator: `, $result`. Indexing into `$null` throws an error; indexing into an empty array returns `$null`.

**PS10**
`-eq` (case-insensitive), `-ceq` (case-sensitive). `-like` uses wildcards (`*`); `-match` uses Regex. `-contains` checks if a collection contains a value; `-in` checks if a value exists within a collection.

**PS11**
A **Module** is a collection of functions/cmdlets. `.psm1` is a script module; `.psd1` is a manifest (metadata); **Binary** modules are compiled DLLs. `Import-Module` loads the module into the current session.

**PS1/PS12**
`"..."` (Double quotes) allows interpolation: `"Hello $name"`. `'...'` (Single quotes) are literal. For complex expressions, use `"$($obj.Prop)"`. **Here-strings** (`@" ... "@`) allow multi-line strings without escape characters.

**PS13**
`Get-Member` shows the structure of an object. **Properties** are data; **Methods** are actions; **NoteProperties** are properties added dynamically. `Select-Object` picks specific properties; `Where-Object` filters objects based on criteria.

**PS14**
**Classes** allow for true OOP (encapsulation, inheritance). They differ from C# because they are interpreted/JITed within the PS engine and have limited support for certain advanced C# features. Use **Functions** for simple tasks/scripts; use **Classes** for complex, reusable data structures.

**PS15**
`[CmdletBinding()]` makes a function behave like a professional cmdlet (adds `-Verbose`, `-ErrorAction`, etc.). `SupportsShouldProcess` enables `-WhatIf`. `ValueFromPipeline` allows input via `|`. `Begin`, `Process`, and `End` blocks allow handling stream-based input efficiently.

**PS16**
**Providers** allow different data stores to be treated like a file system. `Get-ChildItem Registry::HKEY_LOCAL_MACHINE\...` works just like `Get-ChildItem C:\...`.

**PS17**
A **Runspace** is a single thread of execution. A **RunspacePool** manages multiple runspaces. `ForEach-Object -Parallel` (v7) uses a runspace pool internally to execute scriptblocks concurrently.

**PS18**
**PSScriptAnalyzer** is a static code analysis tool. It uses **Rules** to check for bad practices. You can suppress rules with `# PSAvoid`. It integrates into CI/CD via `Invoke-ScriptAnalyzer` to fail builds if standards aren't met.

**PS19**
`$using:var` is used to pass a local variable into a remote/parallel scope. `$args` is for positional parameters. **Serialization** occurs when objects move across boundaries (e.g., to a remote session); complex objects (like active file handles) are "flattened" into XML (CLIXML), losing their methods and dynamic properties.

**PS20**
**DSC** uses **Configurations** (code), **Resources** (the "how"), and the **LCM** (the engine on the node). In PS 7+, DSC is often replaced by **Terraform** or **Ansible** for orchestration, while DSC remains for node-level configuration.
