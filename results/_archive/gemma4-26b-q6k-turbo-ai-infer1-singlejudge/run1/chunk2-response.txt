## Kubernetes

**K1 — Easy:** A **Deployment** manages stateless applications (e.g., web servers), where pods can be replaced by any other pod of the same type. A **StatefulSet** manages stateful applications (e.g., databases), providing stable, unique network identifiers and persistent storage mapping for each pod instance.

**K2 — Easy:** A Service of type **ClusterIP** acts as a virtual IP. It uses `kube-proxy` on each node to manage rules (via iptables or IPVS) that intercept traffic sent to the ClusterIP and load balance it across the backend Pod IPs associated with that service's selector.

**K3 — Medium:** A **PersistentVolume (PV)** is a piece of storage in the cluster; a **PersistentVolumeClaim (PVC)** is a request for storage by a user; a **StorageClass** allows dynamic provisioning. The relationship: A user creates a PVC referencing a StorageClass, which triggers the automatic creation of a PV.

**K4 — Medium:** 
1. `kubectl logs <pod>`: Check application errors/stack traces.
2. `kubectl describe pod <pod>`: Check Events for lifecycle issues (e.g., failed probes).
3. `kubectl get events`: Look for system-level failures.
4. Resource checks: Verify if the container is hitting memory limits (OOMKilled).

**K5 — Medium:** CoreDNS provides service discovery via DNS within the cluster. If CoreDNS pods are down, internal service names (e.g., `my-svc.namespace.svc.cluster.local`) will fail to resolve, breaking communication between microservices.

**K6 — Hard:** The scheduler follows two steps: 
1. **Filtering (Predicates):** Removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, node selectors, taints).
2. **Scoring (Priorities):** Ranks remaining nodes based on factors like **Resource Fit** (least requested), **Image Locality** (is image already there?), and **Affinity/Anti-affinity**.

**K7 — Hard:** Yes, it will be scheduled because its request (256Mi) fits in the available capacity (0.5GB left). However, if it uses 600Mi at runtime, it exceeds its limit (512Mi) and the kernel will trigger an **OOMKill** (Out of Memory Kill).

**K8 — Hard:** External Traffic $\rightarrow$ External Load Balancer $\rightarrow$ Ingress Controller Pod $\rightarrow$ Service (via Endpoints list) $\rightarrow$ kube-proxy rules (iptables/IPVS) $\rightarrow$ Target Application Pod.

**K9 — Medium:** A **NetworkPolicy** defines how groups of pods are allowed to communicate with each other. By default, if no policy exists, all pods can talk to all pods (**Allow All**). Once a policy is applied to a pod, it enters "isolation mode," meaning only traffic explicitly permitted by that or other policies is allowed.

**K10 — Medium:** **RollingUpdate** replaces old pods with new ones gradually to ensure zero downtime. **Recreate** kills all existing pods before starting new ones. Choose **Recreate** when the application does not support multiple versions running simultaneously (e.g., due to singleton requirements or database schema locks).

**K11 — Easy:** A **Namespace** is a virtual partition within a cluster for resource isolation. Default namespaces include `default`, `kube-system`, `kube-public`, and `kube-node-lease`.

**K12 — Easy:** It provides detailed status and lifecycle info. Unlike `get`, it shows: 
1. Detailed **Events** (recent history).
2. Specific **Container Status** (restarts, exit codes).
3. **Resource usage/limits** details per container.

**K13 — Easy:** A **ConfigMap** stores non-confidential data in key-value pairs. Consumption methods: 
1. As **Environment Variables**.
2. As **Files in a Volume** mounted into the container.

**K14 — Easy:** 
* **ClusterIP:** Internal access only.
* **NodePort:** Exposes service on a static port on every Node's IP.
* **LoadBalancer:** Provisions an external cloud load balancer to route traffic to the service.

**K15 — Easy:** A **DaemonSet** ensures that exactly one copy of a pod runs on every node. Use it for system-level services like log collectors (Fluentd) or monitoring agents (Prometheus Node Exporter).

**K16 — Medium:** **Taints** are applied to nodes to repel pods; **Tolerations** are applied to pods to allow them onto tainted nodes. **Node Affinity** is used by pods to "attract" themselves to specific nodes. *Use case:* Taint a GPU node so only ML workloads land there; use affinity to ensure a web app lands near its database.

**K17 — Medium:** An **Operator** is a custom controller that uses Custom Resource Definitions (CRDs) to manage complex, domain-specific applications. Unlike standard controllers (which handle generic resources), Operators encode human operational knowledge (e.g., how to backup/restore a specific DB) into software.

**K18 — Hard:** etcd uses the **Raft consensus algorithm**. If quorum ($n/2 + 1$) is lost, the cluster becomes read-only or unavailable. To recover from losing 2/3 nodes: You must restore from a known good snapshot/backup onto a new set of nodes and re-establish a new quorum.

**K19 — Hard:**
* `Role`: Permissions within a namespace.
* `ClusterRole`: Permissions across the whole cluster.
* `RoleBinding`/`ClusterRoleBinding`: Attaches roles to users/groups.

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: dev-ns
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods-binding
  namespace: dev-ns
subjects:
- kind: User
  name: developer-user
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**K20 — Hard:** The `ndots:5` setting in `/etc/resolv.conf` causes the resolver to append search domains (e.g., `google.com.namespace.svc.cluster.local`) for every external query, resulting in multiple failed DNS lookies before finding the real one. **Fix:** Use `dnsConfig` in the Pod spec to set `ndots: 1`.

## Development

**D1 — Easy:** **Merge** combines histories by creating a new commit; **Rebase** rewrites history by moving commits to a new base. Avoid rebasing on **public branches** as it breaks history for other collaborators.

**D2 — Easy:** **TCP** is connection-oriented and reliable (HTTP, SSH). **UDP** is connectionless and fast (DNS, VoIP).

**D3 — Medium:** A race condition occurs when two threads access shared data simultaneously and at least one write occurs, leading to unpredictable results. *Example:* Two threads incrementing `counter++` without a lock might result in only one increment being recorded.

**D4 — Medium:** **Symmetric** uses one key for both encryption/decryption; **Asymmetric** uses a public/private pair. In **TLS**, asymmetric encryption is used to securely exchange a temporary "session key," which is then used with symmetric encryption for the actual data transfer.

**D5 — Medium:** A container image layer is an immutable filesystem change. Layer caching allows Docker to skip rebuilding layers that haven't changed. **Best practice:** Order instructions from "least likely to change" to "most likely" (e.g., install OS deps before copying source code).

**D6 — Medium:** 
1. Check Upstream Service health (is the app actually running?).
2. Check Load Balancer configuration/capacity.
3. Check Application resource usage (OOM or CPU throttling).
4. Check Network connectivity between LB and App.

**D7 — Hard:** CAP: Consistency, Availability, Partition Tolerance. You can only have two. 
* **CP (Consistency/Partition):** Zookeeper (stops accepting writes if it loses quorum).
* **AP (Availability/Partition):** Cassandra (allows writes even if nodes are disconnected, resolving later).

**D8 — Medium:** **Horizontal scaling** adds more instances (nodes); **Vertical scaling** adds more power (CPU/RAM) to existing instances. Patterns enabling horizontal scaling include **Statelessness** and **Load Balancing**.

**D9 — Easy:** An environment variable stores a value for a process. To persist in Linux, add `export VAR=value` to your `~/.bashrc` or `~/.zshrc`.

**D10 — Easy:** **JSON** is data-interchange format; **YAML** is human-readable configuration. JSON advantage: Strict syntax makes it easier for machines to parse reliably. YAML advantage: Highly readable and supports comments.

**D11 — Easy:** A REST API uses HTTP methods: **GET** (retrieve), **POST** (create), **PUT** (replace/update), **DELETE** (remove).

**D12 — Easy:** Version pinning ensures you use specific versions of libraries. It is vital for **reproducible builds**, preventing "it works on my machine" issues caused by unexpected dependency updates.

**D13 — Easy:** **Compiled** languages are converted to machine code before execution (C++, Go). **Interpreted** languages are executed line-by-line by an interpreter (Python, JavaScript).

**D14 — Medium:** A **Forward Proxy** protects clients (hides client identity); a **Reverse Proxy** protects servers (hides server identity/load balances). Servers: Nginx, HAProxy. Use case: Nginx as a load balancer for web apps.

**D15 — Medium:** The four Coffman conditions: 
1. **Mutual Exclusion** (resource held by one).
2. **Hold and Wait** (holding resource while waiting for another).
3. **No Preemption** (cannot force release).
4. **Circular Wait** (chain of processes waiting on each other).

**D16 — Hard:** Eventual consistency means all nodes will eventually have the same data. Cassandra uses tunable levels: `ONE` (fastest), `QUORUM` (majority), or `ALL` (slowest/strongest) to balance speed vs. consistency during reads/writes.

**D17 — Hard:** In **mTLS**, both client and server present certificates. Handshake: Client connects $\rightarrow$ Server sends cert $\rightarrow$ Client verifies $\rightarrow$ Client sends its own cert $\rightarrow$ Server verifies $\rightarrow$ Session key established. Used in **Service Meshes** (Istio/Linkerd) for zero-trust networking.

**D18 — Hard:** A hash table maps keys to indices via a hash function. **Collision resolution**: *Chaining* (linked list at index); *Open Addressing* (find next empty slot). Complexity: Average $O(1)$ for insert/lookup/delete; Worst case $O(n)$.

**D19 — Hard:** The **Circuit Breaker** prevents cascading failures by stopping requests to a failing service. 
* **Closed:** Normal operation.
* **Open:** Service is failing; requests fail immediately.
* **Half-Open:** Testing if service has recovered.
It works with **retries/exponential backoff** to ensure we don't overwhelm a recovering system.

**D20 — Hard:** **Optimistic** assumes conflicts are rare; it checks version numbers before committing (e.g., `WHERE version = 5`). **Pessimistic** assumes conflicts will happen; it locks the record (`SELECT FOR UPDATE`) so no one else can touch it until finished. Use Optimistic for high-concurrency web apps; use Pessimistic for critical financial transactions.
