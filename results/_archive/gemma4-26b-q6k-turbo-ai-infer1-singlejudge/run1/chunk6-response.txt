## JavaScript / TypeScript (20 questions)

**JS1** — `var` is function-scoped; `let` and `const` are block-scoped. `const` prevents reassignment of the identifier. Hoisting is the behavior where variable and function declarations are moved to the top of their containing scope during compilation.

**JS2** — The Event Loop manages execution. The **Call Stack** handles synchronous tasks. When an async task finishes, it enters a queue. **Microtask Queue** (e.g., Promises) has higher priority and runs immediately after the current stack clears. **Macrotask Queue** (e.g., `setTimeout`) runs after microtasks are exhausted.

**JS3** — A closure is a function that "remembers" its lexical scope even when executed outside that scope. *Example:* A function returning another function that increments a counter. *Bug:* Using `var` in a loop causes all closures to share the same final value. *Fix:* Use `let` to create a new binding for each iteration.

**JS4** — `Promise` represents an eventual completion/failure. `async/await` provides syntactic sugar for working with Promises. Error handling: use `.catch()` for Promises or `try/catch` blocks with `await`. `Promise.allSettled` waits for all promises to finish regardless of outcome; `Promise.all` rejects as soon as one fails.

**JS5** — `interface` defines object shapes and supports declaration merging; `type` is more flexible (unions, primitives). Use `interface` for public APIs/objects; use `type` for complex logic/unions. **Discriminated unions** use a common literal property (a "tag") to allow TypeScript to narrow types within a union.

**JS6** — JavaScript uses prototypal inheritance where objects inherit properties from a prototype object. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 classes are "syntactic sugar" over this mechanism; they still use prototypes under the hood.

**JS7** — The `this` keyword refers to the execution context. 1. **New** (constructor), 2. **Explicit** (`call`/`apply`/`bind`), 3. **Implicit** (object method), 4. **Default** (global/undefined in strict mode). `bind()` returns a *new* function with fixed context; it cannot be re-bound.

**JS8** — `WeakRef` allows holding a reference to an object without preventing garbage collection (GC). `FinalizationRegistry` triggers a callback when an object is GC'd. `WeakMap` keys must be objects so that if the only reference to the key is the WeakMap itself, the key and value can be collected.

**JS9** — V8 optimizes via **Hidden Classes** (tracking object shapes) and **Inline Caching** (storing offsets of properties). **Deoptimization** occurs when code assumes a shape but receives another (e.g., adding a property to an object after it was already used). Patterns like changing object structure dynamically cause deopt.

**JS10** — Tree-shaking removes unused code during build time. ESM supports this because imports are static. CommonJS uses `require()`, which is dynamic/runtime, making it impossible for tools to safely determine what is "unused" without running the code.

**JS11** — `null` is an intentional absence; `undefined` means uninitialized. `==` performs type coercion; `===` checks both value and type. `??` (nullish coalescing) returns the RHS only if LHS is `null`/`undefined`. `?.` (optional chaining) stops evaluation if the chain hits `null`/`undefined`.

**JS12** — `map()` transforms elements; `filter()` selects subset; `reduce()` accumulates into one value. An initial value in `reduce()` prevents errors on empty arrays. `flatMap()` maps then flattens results by one level, useful for nested structures.

**JS13** — Template literals use backticks (\`${}\`) for interpolation. Tagged templates allow a function to process the string parts and arguments. *Example:* `` sql`SELECT * FROM users WHERE id = ${id}` `` where the `sql` tag escapes inputs.

**JS14** — Destructuring extracts values from objects/arrays. `{a, b=5} = obj` (object), `[x, y] = arr` (array). Default values: `const {a=1} = obj`. Renaming: `const {old: newName} = obj`. The rest operator `...rest` collects remaining items into a new array/object.

**JS15** — `for...in` iterates over enumerable property keys; `for...of` iterates over iterable values. Avoid `for...in` on arrays because it iterates indices as strings and may include non-index properties.

**JS16** — Generics provide reusable components. **Constraints**: `T extends U` ensures T is a subtype of U. **Conditional Types**: `T extends U ? X : Y` returns type based on condition. **Infer**: `infer T` extracts a type within a conditional block. *Example:* `type Unpack<T> = T extends Array<infer U> ? U : T;`.

**JS17** — CJS uses `require`/`module.exports` (synchronous/runtime). ESM uses `import`/`export` (static/build-time). Node handles both via file extensions or `"type": "module"` in `package.json`, which treats `.js` files as ESM.

**JS18** — TypeScript is structural (shape matters, not name). **Excess property checks** apply to object literals assigned to specific types. `extends` defines subtyping; `satisfies` validates shape without changing the inferred type. **Variance** (`in`/`out`) determines if subtypes can be used where supertypes are expected.

**JS19** — `Proxy` intercepts operations (get, set); `Reflect` provides methods for those same operations. *Example:* A Proxy that logs every time a property is accessed: `new Proxy(obj, { get(t, p) { console.log(p); return Reflect.get(t, p); } })`.

**JS20** — `SharedArrayBuffer` allows multiple threads (Workers) to access the same raw memory. `Atomics` provides thread-safe operations (add, load, store). Workers communicate via `postMessage` normally, but shared buffers allow zero-copy data sharing. `Atomics.wait/notify` manages synchronization between threads.

## Bash (20 questions)

**B1** — `$@` represents all arguments as separate words; `$*` represents them as a single string. `"$@"` preserves individual argument quoting; `"$*"` joins them into one string using the first character of `IFS`.

**B2** — `-e`: exit on error; `-u`: treat unset variables as errors; `-o pipefail`: the pipeline's exit code is the status of the last command to fail, not just the last command in the pipe.

**B3** — `$(command)` executes and captures output; `` `command` `` is legacy syntax for the same. `$((expression))` is arithmetic expansion; `expr` is an external utility for math.

**B4** — Process substitution `<(command)` creates a temporary file descriptor representing the command's output. *Example:* `diff <(ls dir1) <(ls dir2)` compares two directory listings without creating temp files.

**B5** — Use `while read -r f; do ... done < <(find . -print0)`. Avoid `for f in $(ls)` because it performs word splitting on spaces/newlines within filenames, breaking the loop logic.

**B6** — Here document (`<<EOF`) passes multi-line input. Here string (`<<<string`) passes a single string. `<<-EOF` strips leading tab characters from the input lines.

**B7** — `cmd > file 2>&1` redirects stdout to file, then redirects stderr to where stdout was (the file). `cmd 2>&1 > file` redirects stderr to stdout (terminal), then redirects stdout to the file (stderr stays on terminal). `&> file` is shorthand for both.

**B8** — A safe lock: `mkdir lockdir && trap 'rmdir lockdir' EXIT INT TERM`. `mkdir` is preferred because it is an atomic operation at the kernel level, preventing race conditions that occur when checking if a file exists and then creating it.

**B9** — `'...'` treats everything literally. `"..."` allows variable expansion and backslash escapes. No quotes causes word splitting and globbing. *Example:* `echo $VAR` vs `echo "$VAR"`.

**B10** — `-e` (exists), `-d` (directory), `-r` (readable). `[[ ]]` is a bash builtin that is more robust/powerful than the standard `[ ]` (test) command.

**B11** — `$?`: last exit status; `$$`: current PID; `$!`: PID of last background job; `$#`: number of arguments.

**B12** — Defined as `func() {}` or `function func {}`. Functions return via `return n` (exit code 0-255) or by printing to stdout (`echo`).

**B13** — `PATH` is a list of directories searched for commands. Builtin commands are internal to the shell; external commands are binaries in `PATH`. Use `type -a cmd` to check.

**B14** — `trap 'cmd' SIGNAL` sets handlers. Order depends on signal arrival, but usually sequential. Cleanup should cover `EXIT`, `INT` (Ctrl+C), and `TERM`.

**B15** — `xargs` reads stdin into arguments. To handle spaces/newlines: `find . -print0 | xargs -0 ...`. `-P N` runs up to $N$ processes in parallel.

**B16** — Arrays: `arr=(1 2)`; append `arr+=("3")`; length `${#arr[@]}`; iterate `for i in "${arr[@]}"`. Associative arrays: `declare -A map`; access `map[key]`.

**B17** — Subshell `(...)` creates a new process with its own environment; Group `{ ...; }` executes in current shell. Piping into a loop starts a subshell, meaning variable changes inside the loop are lost once the pipe finishes.

**B18** — Signals: SIGINT (interrupt), SIGTERM (terminate), SIGHUP (hangup), SIGKILL (kill immediately). Graceful shutdown uses `trap` to clean up background jobs before exiting.

**B19** — Use `split` for chunks $\rightarrow$ `xargs -P` for processing $\rightarrow$ merge results. Trade-off: Parallelism increases speed but risks IO contention. Error propagation requires checking exit codes of each chunked process.

**B20** — `exec` replaces the current shell with the command. File descriptors: `exec 3>file` opens FD 3 to file; `exec 3>&-` closes it. A coprocess (`coproc`) allows bidirectional communication between the shell and a background process.

## PowerShell (20 questions)

**PS1** — `Write-Output` sends objects down the pipeline; `Write-Host` writes directly to the console. This matters because only `Write-Output` data can be processed by subsequent commands in a pipeline.

**PS2** — The pipeline passes objects. `ForEach-Object` is a cmdlet designed for the pipeline; `foreach` is a language keyword that is significantly faster when iterating over an existing collection in memory.

**PS3** — `[PSCustomObject]` is an ordered, typed object useful for structured data; `[hashtable]` is an unordered key-value pair. Convert via `[pscustomobject]@{...}` or `ConvertFrom-Json`.

**PS4** — Terminating errors stop execution; non-terminating continue. `-ErrorAction Stop` turns non-terminating into terminating. `try/catch` blocks catch terminating errors.

**PS5** — Splatting `@params = @{Name="A"; Val=1}; cmd @params`. It differs from passing a single hashtable because each key maps to a specific parameter name of the command.

**PS6** — `Invoke-Command -ComputerName` runs on remote machines (one-to-many); `Enter-PSSession` starts interactive sessions (one-to-one). Uses WinRM (WSMan) or SSH.

**PS7** — PowerShell tries to "help" with types. If a function returns one item, `$x` becomes that type instead of an array. If 0 items, it's `$null`. Correct pattern: `[array]$x = Get-Items`.

**PS8** — A scriptblock is code in `{}`; functions are named reusable units. To pass to remote: use `-ArgumentList`. The **double-hop problem** occurs when credentials used for the first hop aren't passed to the second; solve via CredSSP or Kerberos delegation.

**PS9** — `@()` creates an empty array; `[array]` casts to one. Force single result: `[array]$val = $single`. Indexing into `$null` results in an error/empty depending on context.

**PS10** — Operators like `-eq`, `-match`, etc., are case-insensitive by default. Use `-ceq`, `-cmatch` for case-sensitive versions. `-contains` checks if a collection has a value; `-in` checks if a value exists within a collection.

**PS11** — Module types: `.psm1` (script), `.psd1` (manifest), Binary (DLL). `Import-Module` loads them into the current session.

**PS12** — Interpolation `"Hello $name"`. `'...'` is literal. Expressions: `"$($obj.prop)"`. Here-string: `@"... "@`.

**PS13** — `Get-Member` shows object structure. Properties and Methods are standard; NoteProperties are added dynamically. `Select-Object` picks properties; `Where-Object` filters objects based on criteria.

**PS14** — PowerShell classes (v5+) allow OOP but have limitations compared to C# regarding complex inheritance and interfaces. Use classes for data models, functions for procedural logic.

**PS15** — `[CmdletBinding()]` makes a function "Advanced," enabling common parameters (`-Verbose`, etc.). It enables `SupportsShouldProcess` (-Confirm) and `ValueFromPipeline`. Blocks: `Begin` (setup), `Process` (per item), `End` (cleanup).

**PS16** — Providers map different storage (Registry, FileSystem) to a drive-like syntax. Access registry via `cd HKCU:\Software`.

**PS17** — Runspaces are lightweight threads. `ForEach-Object -Parallel` (v7+) uses an internal runspace pool automatically. Manual management requires creating `[runspacepool]` objects.

**PS18** — PSScriptAnalyzer is a linter that enforces standards. Rules can be set by severity (Error/Warning). Suppress using `# PSScriptAnalyzer Ignore`. Integrates into CI/CD pipelines.

**PS19** — `$using:var` allows accessing local variables inside remote sessions or parallel blocks. Serialization limits (CLIXML depth) can cause complex objects to lose type information when passed between boundaries.

**PS20** — DSC manages system state. **Configurations** define the desired state; **Resources** implement it; **LCM** (Local Configuration Manager) is the engine on the host. Modern IaC has largely moved toward tools like Terraform or Ansible for cross-platform consistency.
