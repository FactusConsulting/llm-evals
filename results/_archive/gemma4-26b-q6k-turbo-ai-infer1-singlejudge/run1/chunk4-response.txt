## Go

**G1** — An **array** has a fixed size defined at compile time. A **slice** is a descriptor for a contiguous segment of an array (containing a pointer, length, and capacity). When you `append` to a slice that has reached its capacity, Go allocates a new, larger underlying array, copies the old elements, and returns a new slice pointing to this new array.

**G2** — `var x int` declares a variable initialized to its zero value (`0`). `x := 0` is short-variable declaration, declaring and initializing simultaneously via type inference. You cannot use `:=` outside of function bodies or when redeclaring a variable in the same scope without a new identifier.

**G3** — A **goroutine** is a lightweight execution unit managed by the Go runtime, not the OS. Unlike OS threads (which have large stacks and high context-switch costs), goroutines start with small (~2KB) stacks that grow dynamically. The **GMP model** consists of **G**oroutines, **M**achines (OS threads), and **P**rocessors (logical contexts). The scheduler maps $N$ Goroutines onto $M$ Machines using $P$ Processors to ensure efficient concurrency and work-stealing.

**G4** — Channels are pipes used for communication between goroutines. An **unbuffered channel** requires both sender and receiver to be ready simultaneously (synchronous). A **buffered channel** allows sending up to $N$ values before blocking. Sending to a full buffered channel blocks the sender until space becomes available.

**G5** — The `context` package manages request lifecycles, cancellation signals, and deadlines across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
// If 100ms passes, req is canceled automatically.
```

**G6** — Go uses **implicit satisfaction**: a type satisfies an interface simply by implementing its methods; no `implements` keyword is needed. This differs from Java/C# which require explicit declaration. `interface{}` (or `any`) can hold any value because every type implements at least zero methods. It is powerful for generic containers but dangerous because it bypasses type safety, requiring runtime type assertions.

**G7** — The code is unsafe due to a **data race**. Without synchronization, the compiler or CPU might reorder instructions or cache `ready` in a register, meaning the loop might never see `ready = true`. Correct alternatives: use `sync/atomic` for the boolean/string or wrap access in a `sync.Mutex`.

**G8** — `sync.Mutex` provides exclusive access. `sync.RWMutex` allows multiple concurrent readers OR one single writer. Use `sync.Map` when you have many more reads than writes or disjointed keys across many goroutines. A regular map with a mutex is generally faster for low-contention, high-frequency access on a single key set.

**G9** — `go.mod` defines the module path and dependencies. `go.sum` contains cryptographic hashes of those dependencies to ensure integrity. `go mod tidy` removes unused modules and adds missing ones. **MVS (Minimum Version Selection)** selects the highest version required by any dependency in the graph that satisfies all constraints, rather than always picking the "latest."

**G10** — `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO (Last-In, First-Out)** order. A common gotcha: using `defer` inside a loop can cause resource exhaustion (e.g., not closing files until the entire function ends), as they don't execute at the end of each iteration.

**G11** — A pointer holds the memory address of a value. The zero value is `nil`. To create a pointer to a struct literal: `p := &MyStruct{Field: 1}`.

**G12** — `init()` runs after package variables are initialized but before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source code within the package.

**G13** — `new(T)` allocates zeroed storage for type `T` and returns a `*T`. `make(T, args)` initializes built-in types (slices, maps, channels) and returns an initialized value of type `T`.

**G14** — Errors are values implementing the `error` interface (`Error() string`). Idiomatic pattern: `if err != nil { return err }`. `errors.Is` checks if an error wraps a specific target value; `errors.As` attempts to cast an error to a specific type. They differ from `==` because they can traverse the error wrap chain.

**G15** — **Map**: `map[K]V` (zero: `nil`), **Slice**: `[]T` (zero: `nil`), **Channel**: `chan T` (zero: `nil`), **Struct**: `{...}` (zero: all fields set to their respective zero values).

**G16** — A race condition occurs when two goroutines access same memory concurrently and at least one is a write. Fix with Mutex:
```go
var mu sync.Mutex
mu.Lock(); count++; mu.Unlock()
// Or via channel: ch <- 1
```
Use `-race` flag during testing/running to detect these.

**G17** — `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, it blocks until one case is ready. If multiple cases are ready, one is chosen pseudo-randomly. Implement timeout: `case <-time.After(d):`.

**G18** — Escape analysis determines if a variable's lifetime exceeds its scope. If it "escapes" the function, it moves to the **heap**; otherwise, it stays on the **stack**. Inspect via `go build -gcflags="-m"`. Stack allocation is faster as it avoids GC pressure.

**G19** — `reflect.Type` describes the type metadata; `reflect.Value` represents the actual data. Reflection has high performance costs due to runtime inspection and boxing. Use reflection for generic libraries (JSON encoders); use code generation (e.g., Protobuf) for performance-critical paths.

**G20** — `//go:embed` embeds files into the binary at compile time. It supports single files or entire directories (`embed.FS`). Limitations include not being able to embed files outside the module. It integrates with `io/fs` to provide an abstraction of a filesystem.

## Rust

**R1** — 1. Each value has a variable called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2** — `String` is an owned, heap-allocated buffer. `&str` is an immutable slice (view) into a string. In signatures, prefer `&str` for flexibility (it accepts both `String` and `&str`).

**R3** — Borrowing allows accessing data without taking ownership. Rules: You can have either **any number of shared references** (`&T`) OR **exactly one mutable reference** (`&mut T`) at any given time.

**R4** — `Result<T, E>` handles success/failure; `Option<T>` handles presence/absence. The `?` operator performs early return on error.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    let content = std::fs::read_to_string(path)?;
    Ok(content)
}
```

**R5** — `Box<T>`: unique ownership on the heap. `Rc<T>`: multiple owners in a single thread. `Arc<T>`: multiple owners across threads (Atomic Reference Counted).

**R6** — Traits define shared behavior. Unlike Go's implicit interfaces, Rust traits are explicit. A **trait object** (`dyn Trait`) uses dynamic dispatch (runtime), while a **generic with trait bound** (`T: Trait`) uses monomorphization (compile-time static dispatch).

**R7** — It fails because the compiler cannot guarantee that the returned reference lives as long as both inputs. Fix by adding lifetime annotations: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`.

**R8** — `Send` means it's safe to move to another thread; `Sync` means it's safe to share between threads via references. `Rc<T>` is not `Send/Sync` because its internal counter isn't atomic, leading to data races. `Arc<T>` uses atomic operations for the counter, making it safe.

**R9** — Rust async is "pull-based." A `Future` is a state machine that does nothing until polled. An **executor** (like Tokio) polls futures to make progress. This differs from Go, where goroutines are "push-based" and managed preemptively by a runtime scheduler.

**R10** — `unsafe` allows bypassing safety checks. 3 things: dereferencing raw pointers, calling unsafe functions, mutating static variables. Justified when interfacing with C or performing low-level hardware optimizations.

**R11** — Pattern matching (`match`) provides exhaustive checking of all possible patterns. `if let` is syntactic sugar for a single pattern match. The compiler ensures every possible case is covered.

**R12** — `[T; N]` is fixed-size on stack. `Vec<T>` is growable on heap. When capacity is exceeded, `Vec` allocates a larger buffer, copies elements, and deallocates the old one.

**R13** — Rust enums can hold data (sum types). Unlike C/Java enums, they are powerful algebraic data types. `Option<T>` replaces `null`, forcing developers to handle the `None` case explicitly.

**R14** — `impl` defines methods for a type. `&self` borrows immutably; `&mut self` borrows mutably; `self` consumes the object (moves ownership). Associated functions (like `new()`) do not take `self`.

**R15** — `#[derive(Trait)]` automatically implements a trait. Examples: `Debug`, `Clone`, `PartialEq`, `Serialize`. You cannot derive if the underlying fields don't also implement that trait.

**R16** — `Cow<'a, T>` stands for "Clone on Write." It holds either borrowed or owned data. Useful when you only need to clone if you actually modify the data, avoiding unnecessary allocations in read-heavy paths.

**R17** — `mod` declares a module; `use` brings it into scope; `pub` makes it visible. Files map directly to modules (`mod foo;` looks for `foo.rs`). The 2018 edition simplified this by making modules more intuitive and reducing the need for explicit `extern crate`.

**R18** — `Pin<T>` ensures a value doesn't move in memory. This is vital for **self-referential structs** used in `async/await`, where pointers within the struct would become invalid if moved. `Unpin` is an auto-trait indicating a type is safe to move even after being pinned.

**R19** — Declarative macros (`macro_rules!`) use pattern matching on tokens. Procedural macros are functions that run at compile time (derive, attribute, function-like). Hygiene rules ensure macro-generated identifiers don't accidentally clash with local variables.

**R20** — Zero-cost abstractions mean you don't pay for what you don't use. **Iterators** optimize down to efficient loops; **Generics** use monomorphization (generating specific code for each type); **Static dispatch** resolves calls at compile time, allowing inlining.
