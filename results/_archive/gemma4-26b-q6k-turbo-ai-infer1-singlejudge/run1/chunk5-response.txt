## .NET / C#

**DN1** — **Class** is a reference type (stored on the heap), while **struct** is a value type (usually stored on the stack or inline). Use a **struct** for small, immutable data structures (e.g., a `Point` or `Color`) where the overhead of heap allocation outweighs the benefits of reference semantics.

**DN2** — **IEnumerable<T>** is for in-memory collections and supports forward-only iteration. **IQueryable<T>** represents an expression tree that can be translated into a provider-specific language (like SQL). This distinction matters because `IQueryable` allows filtering to happen at the database level via `WHERE` clauses, whereas `IEnumerable` pulls all data into memory before filtering.

**DN3** — **async/await** uses a state machine to allow non-blocking operations. A **Task** represents an ongoing asynchronous operation on the heap. A **ValueTask** is a struct used when the result might already be available synchronously; it reduces allocations by avoiding a Task object creation. Use `ValueTask` in high-frequency methods where results are often cached or immediate.

**DN4** — **Dependency Injection (DI)** manages object lifetimes. **Transient**: new instance every time requested. **Scoped**: one instance per client request (e.g., HTTP request). **Singleton**: one instance for the entire app lifetime. A common bug is "Captive Dependency": injecting a Scoped service into a Singleton makes the Scoped service live as long as the Singleton, breaking its intended lifecycle.

**DN5** — **string** is an immutable heap-allocated object. **ReadOnlySpan<char>** provides a view into a contiguous region of memory without creating new string allocations. Use **Span<T>** for high-performance parsing and slicing to minimize GC pressure and memory copying.

**DN6** — The **GC** manages memory automatically using generations: **Gen 0** (newest), **Gen 1** (buffer), **Gen 2** (old/long-lived). Objects surviving collections move up. The **Large Object Heap (LOH)** is for objects >85k bytes; it isn't compacted by default, leading to fragmentation. **IDisposable** is needed because the GC only manages managed memory; you must manually release unmanaged resources (file handles, sockets) via `Dispose()`.

**DN7** — By default, `await` captures the current **SynchronizationContext**. **ConfigureAwait(false)** tells the runtime not to attempt to resume on the original context. Use it in library code to improve performance and prevent deadlocks. Do NOT use it if your continuation needs to access UI elements or specific request contexts.

**DN8** — **Primary constructors** allow parameters directly in class headers. **Collection expressions** (`[1, 2, 3]`) simplify syntax. **FrozenDictionary** is an immutable, highly optimized dictionary for read-heavy scenarios.
*Example:*
```csharp
public class UserService(IUserRepository repo) { // Primary Constructor
    public User GetUser(int id) => repo.Find(id);
}
var users = [1, 2, 3]; // Collection expression
```

**DN9** — This is likely a **Captive Dependency** or thread-safety issue where multiple threads are sharing a single `DbContext` instance. In EF Core, `DbContext` is not thread-safe. The fix is to ensure `DbContext` is registered as **Scoped** and that each logical operation/request gets its own instance from the DI container.

**DN10** — A **class** uses reference equality; a **record** uses value-based equality. A **record struct** combines both: it's a value type with value-based equality logic. Use records for DTOs/data models where identity is defined by data content rather than memory address.

**DN11** — **ref**: Pass by reference (read/write). **out**: Must be initialized inside the method before returning (write only). **in**: Pass by reference but read-only (prevents copying large structs while ensuring immutability within the method).

**DN12** — **Nullable Reference Types (`string?`)** are compile-time metadata used by the compiler to warn about potential nulls. They do not change the underlying type at runtime. **Nullable Value Types (`int?`)** are wrappers (`Nullable<T>`) that actually allow a value type to represent "null."

**DN13** — **LINQ** provides querying capabilities. **Method syntax** uses extension methods (`.Where()`). **Query syntax** looks like SQL (`from x in y...`). **Deferred execution** means the query isn't executed when defined, but when you iterate over it (e.g., via `foreach` or `.ToList()`).

**DN14** — Constraints restrict generic types: `where T : class` (reference type), `where T : struct` (value type), `where T : new()` (must have parameterless constructor), and `where T : IComparable<T>` (must implement comparison). You combine them to narrow requirements, e.g., `where T : class, IDisposable`.

**DN15** — An **abstract class** can hold state (fields) and provide implementation; an **interface** is primarily a contract. Since C# 8, interfaces can have **default implementations**, making them behave more like abstract classes, though they still cannot hold instance state.

**DN16** — The **middleware pipeline** processes requests sequentially. **app.Use()** allows calling the next middleware; **app.Map()** branches based on path; **app.Run()** is terminal. Order matters because if Exception Handling middleware isn't first, it won't catch errors from subsequent steps.

**DN17** — **Channel<T>** is an async-first producer-consumer queue. Unlike **BlockingCollection<T>**, which blocks threads, Channels use `WaitToWriteAsync`.
*Example:* `var chan = Channel.CreateBounded<int>(10); // Backpressure: Producer waits when full.`

**DN18** — **Source Generators** produce code at compile time using Roslyn. They differ from **Reflection** (runtime inspection) and **IL Weaving** (modifying existing bytes). **Incremental generators** are preferred because they only re-run for changed parts of the syntax tree, significantly improving build speed.

**DN19** — **TPL Dataflow** is a library for building actor-like pipelines. **ActionBlock** (sink), **TransformBlock** (processor), and **BufferBlock** (queue/buffer). Compared to **Channels**, TPL Dataflow is better for complex Directed Acyclic Graphs (DAGs) with many dependencies, while Channels are lighter for simple streams.

**DN20** — **Minimal APIs** allow defining endpoints directly in `Program.cs` without Controllers. They have less boilerplate but can be harder to organize as apps grow. Trade-offs include slightly more manual setup for OpenAPI/Swagger compared to Controller auto-discovery, though route groups and endpoint filters provide excellent structure and modularity.

## Python

**P1** — A **list** is mutable; a **tuple** is immutable. A **set** is a mutable collection of unique elements; a **frozenset** is an immutable version of a set.

**P2** — The **GIL** prevents multiple native threads from executing Python bytecodes at once. It affects **CPU-bound** workloads (limiting multi-core usage). Workarounds: use **multiprocessing** or C extensions like NumPy that release the GIL.

**P3** — **copy()** creates a new object but keeps references to nested objects (**shallow copy**). **deepcopy()** recursively copies everything. *Example:* If you shallow copy a list containing another list, modifying the inner list in the copy will change it in the original.

**P4** — Decorators wrap functions.
```python
import time
def logger(func):
    def wrapper(*args, **kwargs):
        print(f"Running {func.__name__}")
        start = time.time()
        result = func(*args, **kwargs)
        print(f"Took {time.time() - start}s")
        return result
    return wrapper
```

**P5** — **Generators** use `yield` to return values one by one without storing them all in memory. Unlike returning a list, they are lazy. **yield from** allows a generator to delegate part of its operations to another generator/iterable.

**P6** — The **event loop** manages async tasks. `asyncio.run()` starts the loop; `gather()` runs multiple coroutines concurrently; `create_task()` schedules a task for execution. You cannot use `time.sleep()` because it blocks the entire thread (and thus the loop); use `await asyncio.sleep()`.

**P7** — Python uses **C3 Linearization**. In diamond inheritance: D inherits B and C. MRO order is D -> B -> C -> A. For the code provided, `D().who()` prints **"C"** because C's implementation comes before A's in the linearized search path after checking B.

**P8** — A **metaclass** defines how classes themselves are constructed. Use `__init_subclass__` for simple logic like registering subclasses in a registry. Use a **metaclass** when you need to fundamentally alter class creation (e.g., modifying attributes or enforcing strict rules at definition time).

**P9** — **multiprocessing** bypasss GIL via separate processes; **threading** shares memory but is limited by GIL; **concurrent.futures** provides high-level abstractions (`ProcessPoolExecutor`/`ThreadPoolExecutor`). Multiprocessing requires objects to be **pickled** (serialized) to move between processes.

**P10** — **\_\_slots\_\_** tells Python not to create a `__dict__` for instances, using fixed slots instead. This significantly reduces memory usage for millions of small objects but prevents adding new attributes dynamically.

**P11** — A **virtual environment** isolates dependencies per project. **venv** is built into Python; **virtualenv** is an older/more feature-rich alternative; **conda** manages both Python and non-Python binary dependencies (common in Data Science).

**P12** — Comprehensions provide concise syntax for creating collections. They are often more readable than `map()` and `filter()`, especially when performing multiple operations in one line.

**P13** — `==` checks **value equality**; `is` checks **identity** (same object in memory). **Object interning** reuses small integers (-5 to 256) and certain strings to save memory, which is why `a is b` might return True for them.

**P14** — `*args` collects positional arguments as a tuple; `**kwargs` collects keyword arguments as a dict. `/` marks parameters before it as **positional-only**; `*` marks parameters after it as **keyword-only**.

**P15** — Context managers handle setup/teardown. Use `__enter__`/`__exit__` or `@contextmanager`. *Example:* A timer context manager that measures block execution time.

**P16** — Type hinting provides static metadata. `Union[int, str]` means int OR str; `Optional[int]` means int OR None; `Literal["a"]` restricts to specific values; `TypeVar` defines generics; `Protocol` enables structural subtyping. Tools like **mypy** use these to catch type errors without running code.

**P17** — Dunder methods define behavior: `__repr__` (dev view), `__str__` (user view), `__eq__` (equality), `__hash__` (for sets/dicts). `__getattr__` handles missing attributes; `__getattribute__` intercepts *all* access. If you define `__eq__` but not `__hash__`, the object becomes unhashable.

**P18** — **Descriptors** implement `__get__`, `__set__`, and `__delete__`. They allow attributes to have custom logic when accessed. `property`, `classmethod`, and `staticmethod` are all implemented using this protocol under the hood.

**P19** — **Absolute imports** start from the root; **relative** use dots (`.`). `sys.path` is the search list for modules. `__init__.py` makes a directory a package. **Namespace packages** allow splitting one package across multiple directories. A **finder** locates a module, and a **loader** loads its code.

**P20** — **dataclasses** are lightweight structures; **Pydantic** adds runtime validation and type coercion. Use Pydantic for data entering your system (APIs) where validation is critical; use dataclasses for internal data storage. Dataclasses support inheritance and `__post_init__` for extra setup.
