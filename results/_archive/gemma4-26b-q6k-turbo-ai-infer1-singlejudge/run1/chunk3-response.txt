## OpenTofu / Terraform (20 questions)

**T1** — `tofu plan` calculates the execution plan by comparing current state against code, showing what will be created, modified, or destroyed. `tofu apply` executes that plan to reach the desired state.

**T2** — State is a JSON file mapping your configuration to real-world resources. Remote state is critical because it allows team collaboration, provides a "single source of truth," enables state locking to prevent corruption, and keeps sensitive data out of local machines.

**T3** — `count` uses an integer index; if you remove an item from the middle of a list, all subsequent items shift, causing unnecessary recreations. `for_each` uses unique keys; removing one item only affects that specific resource. `for_each` is preferred when managing collections where identity matters more than order.

**T4** — This is called "drift." During the next `plan`, OpenTofu refreshes its state by querying the cloud provider API. It detects the discrepancy between the actual setting and the recorded state/code, then proposes changes in the `plan` to revert the manual change back to the defined code.

**T5**
```hcl
resource "aws_instance" "web" {
  for_each = toset(["web1", "web2", "web3"])
  tags     = { Name = each.key }
}
```

**T6** — `terraform_remote_state` reads the entire state file of another workspace, creating tight coupling and security risks (accessing all secrets). The recommended alternative is to use **Outputs** from one module as **Inputs** for another within a root module, or using specialized Data Sources to decouple them.

**T7** — Provisioners run during the *apply* phase. If the output depends on a file created by a provisioner, that value isn't available until the apply completes. To fix this: ensure the dependency is explicit via `depends_on`, or better yet, avoid provisioners for critical configuration; instead, use a data source or local-exec to write the file and pass it through properly.

**T8** — `tofu import` brings existing infrastructure under management. Its limitation is that it only imports the resource, not its configuration (you must still write the HCL). The `import` block (v1.5+) allows you to declare the import in code, making it repeatable, easier to review in PRs, and capable of importing multiple resources at once.

**T9** — A **variable** is an input parameter used to customize a module/configuration. An **output** is a value exported by a module so other modules can consume it.

**T10** — A provider is a plugin that translates OpenTofu code into API calls for a specific service (e.g., AWS, Azure). Running `tofu plan` without `tofu init` will fail because the required provider binaries have not been downloaded to the `.terraform` directory.

**T11** — It is the Dependency Lock File. It records exact versions and hashes of providers used. Committing it ensures every environment (Dev, CI, Prod) uses the identical provider version, preventing "it works on my machine" issues.

**T12** — `tofu destroy` removes all managed resources in the state. To target one: `tofu destroy -target=aws_instance.example`.

**T13** — A data source is a read-only operation to fetch information from an existing resource or external API. Example: Using `data "aws_ami" "latest"` to find the newest Ubuntu AMI ID instead of hardcoding it.

**T14** — Variables are inputs provided by the user. Locals are internal constants or derived values calculated within the module. Use locals to avoid repetition (DRY) and to perform complex logic/transformations on input variables.

**T15** — 
- `create_before_destroy`: Creates new resource before deleting old (prevents downtime).
- `prevent_destroy`: Stops OpenTofu from destroying a resource (safety mechanism for DBs).
- `ignore_changes`: Tells OpenTofu to ignore updates to specific attributes (useful when external processes like Auto Scaling modify tags/counts).

**T16** — The `moved` block allows you to rename a resource or move it into a module without OpenTofu thinking the old one was deleted and a new one created. It maps the old address to the new address in the state.

**T17** — Implicit dependencies occur when one resource references another's attribute (e.g., `vpc_id = aws_vpc.main.id`). Explicit dependencies use `depends_on`. `depends_on` forces sequential execution, reducing parallelism; it should be used sparingly because it can create "bottlenecks" in the graph where resources that could run in parallel are forced to wait.

**T18** — 
1. **Split State:** Break large states into smaller ones (reduces refresh time per plan).
2. **Targeting:** Use `-target` during development (faster but risky if not careful).
3. **Refresh-only:** Run `tofu plan -refresh=false` to skip API calls (fastest, but ignores drift).
4. **Optimize Providers:** Reduce the number of providers or complex data sources being queried.

**T19** — State locking prevents two users from running `apply` simultaneously. If a CI crashes, the lock remains. You break it with `tofu force-unlock <LOCK_ID>`. The risk is **state corruption**: if you unlock while another process is actually writing, you will corrupt your state file.

**T20** — 
1. Update configuration to include `backend "s3"` and `dynamodb_table`.
2. Run `tofu init -migrate-state`. OpenTofu detects local state and asks to copy it to S3.
3. Confirm the migration.
4. Verify by running `tofu plan`; it should show zero changes (meaning the remote state matches the local code perfectly).

## Ansible (20 questions)

**A1** — A **Playbook** is an orchestration file containing plays; a **Role** is a reusable collection of tasks/vars/files organized for distribution; a **Task** is a single unit of work (e.g., installing a package).

**A2** — `ansible_facts` are system metadata gathered automatically. Access via: `ansible_facts['os_family']`.

**A3** — `command`: Executes a command without a shell (safest, no pipes/redirects). `shell`: Runs through `/bin/sh`, allowing pipes (`|`) and redirects (`>`). `raw`: Bypasses Python entirely (used for bootstrapping systems without Python installed).

**A4** — Idempotency means running a task multiple times results in the same state. 
*Idempotent:* `apt: name=nginx state=present`. 
*Non-idempotent:* `shell: echo "data" >> /file.txt` (appends every time).

**A5**
```yaml
- name: Install htop based on OS
  package:
    name: "{{ 'epel-release' if ansible_os_family == 'RedHat' else 'htop' }}"
    state: present
  # Note: For complex logic like A5 requirements, two tasks or a block is cleaner:
- name: Debian specific
  apt: name=htop state=present
  when: ansible_os_family == "Debian"
- name: RedHat specific
  yum: name={{ item }} state=present
  loop: [epel-release, htop]
  when: ansible_os_family == "RedHat"
```

**A6** — Order (lowest to highest): Role defaults < Group vars < Host vars < Role variables < Play variables < Task variables < Extra vars (`-e`).

**A7** — Use `serial: 3` in your play to process the first 3 hosts. To ensure they *complete* before others start, you might need two separate plays: one with `hosts: group1` and `serial: 3`, then another for the rest of the inventory. Alternatively, use `wait_for` within a task to check service availability.

**A8** — Use `ansible-vault encrypt_string 'my_secret'` to generate an encrypted string, then paste that string directly into your variable file.

**A9** — **Static:** Hardcoded list/file. **Dynamic:** A script or plugin that queries an API (like AWS) to return host information as JSON.

**A10** — `ansible webservers -m shell -a "df -h"`

**A11** — A handler is a special task that only runs if a previous task reports `changed`. You trigger it using the `notify` keyword in a regular task.

**A12** — Configures Ansible behavior. Common settings: `inventory` path, `remote_user`, and `forks` (number of parallel processes).

**A13** — `register` saves the output of a task into a variable. Usage: `{{ my_result.stdout }}`.

**A14** — `import_tasks` is static (processed when playbook is parsed); `include_tasks` is dynamic (processed at runtime). `include_tasks` allows you to use conditionals on the inclusion itself; `import_tasks` does not support this because it's pre-parsed.

**A15** — Galaxy is a hub for roles/collections. Use `ansible-galaxy install -r requirements.yml` to install everything listed in your requirement file.

**A16** — **ssh:** Standard remote execution via SSH. **local:** Runs tasks on the control node. **network_cli:** Specialized connection for network devices (switches/routers) that don't run Python.

**A17** — `run_once` executes a task once per play. `delegate_to` runs a task on a different host than the target. 
*Example:* To register a service in Consul from a web server:
```yaml
- name: Register with Consul
  uri: url=http://consul:8500/...
  run_once: true
  delegate_to: localhost
```

**A18** — 
1. **Forks:** Increase `forks` in `ansible.cfg` (uses more RAM).
2. **Pipelining:** Enable in `ansible.cfg` (reduces SSH overhead, requires `pipelining = True`).
3. **Fact Caching:** Store facts locally to avoid re-gathering every time.
4. **Mitogen:** A plugin that replaces the Ansible execution engine for massive speedups (requires specific environment setup).

**A19** — `{{ }}` is an expression; `{% %}` is a statement (loops/conditionals); `{# #}` is a comment.
```jinja2
upstream myapp {
{% for server in backend_servers %}
    server {{ server }}; # Health check enabled
{% endfor %}
}
```

**A20** — Use `serial: 1` or small batches. 
1. Task: Remove host from Load Balancer (`uri` module).
2. Task: Update application code/config.
3. Task: Restart service and use `uri` module to health check.
4. Task: Re-add to LB.
5. Wrap in `block`/`rescue`: If any step fails, the `rescue` block triggers a rollback task to restore previous version and re-add to LB.
