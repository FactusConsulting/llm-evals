## Kubernetes

**K1** — **Deployment** is for stateless apps; pods are interchangeable and have random hashes in their names. **StatefulSet** is for stateful apps; pods have sticky identities (pod-0, pod-1), ordered deployment/scaling, and stable network IDs.

**K2** — A ClusterIP Service creates a virtual IP. `kube-proxy` manages rules (iptables/IPVS) on every node that intercept traffic to that virtual IP and load-balance it across the Pod IPs listed in the Service's **Endpoints** object.

**K3** — **PV** is the actual storage resource (the "disk"). **PVC** is a user's request for storage (the "ticket"). **StorageClass** is a template for dynamic provisioning. *Relation:* A user creates a PVC $\rightarrow$ K8s looks for a matching PV or uses a StorageClass to provision a new PV $\rightarrow$ PVC binds to PV.

**K4** — 1. `kubectl logs <pod>` (check app crash logs). 2. `kubectl logs <pod> --previous` (check why the last instance died). 3. `kubectl describe pod <pod>` (check Events for OOMKilled or Liveness probe failures). 4. `kubectl exec` (if it stays up briefly) to check config/env vars.

**K5** — CoreDNS provides service discovery (mapping service names to IPs). If CoreDNS pods are down, pods cannot resolve internal service names (e.g., `my-db.namespace.svc.cluster.local`), causing application connection failures.

**K6** — **Filtering:** Removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, Taints, NodeSelector). **Scoring:** Ranks remaining nodes based on "best fit." **Factors:** 1. Resource availability (LeastRequestedPriority). 2. Image locality (does the node already have the image?). 3. Inter-pod affinity/anti-affinity.

**K7** — **Scheduling:** No. The node has 0.5GB available (4GB - 3.5GB), but the pod requests 256Mi. While it fits, if other pods are scheduled simultaneously, it might fail. However, strictly speaking, 256Mi < 512Mi available, so it *will* schedule. **Runtime:** If it hits 600Mi, it exceeds its `limit` (512Mi) and will be **OOMKilled** by the kernel.

**K8** — External LB $\rightarrow$ Ingress Controller (NGINX) $\rightarrow$ NGINX reads Ingress rules $\rightarrow$ NGINX bypasses the Service IP and sends traffic directly to a **Pod IP** (found in the Endpoints list) $\rightarrow$ `kube-proxy`/iptables ensures the packet reaches the correct node/pod.

**K9** — A NetworkPolicy is an L3/L4 firewall for pods. **Default:** All traffic is allowed. **Applying one:** Once a policy selects a pod, that pod becomes "isolated"; it will drop all traffic not explicitly allowed by the policy.

**K10** — **RollingUpdate:** Gradually replaces old pods with new ones (zero downtime). **Recreate:** Kills all old pods before starting new ones. **Choose Recreate** when the app doesn't support two versions running simultaneously (e.g., breaking database schema changes).

**K11** — A namespace is a virtual cluster partition for resource isolation. Defaults: `default` (user apps), `kube-system` (cluster components), `kube-public` (publicly visible), `kube-node-lease` (heartbeats).

**K12** — Used for detailed debugging. It shows: 1. **Events** (e.g., Pulling image, FailedScheduling). 2. **Container Status** (Exit codes, Restart counts). 3. **Resource Limits/Requests** and Volume mounts.

**K13** — A ConfigMap stores non-confidential configuration. Consumption: 1. **Environment Variables** (mapped via `envFrom` or `valueFrom`). 2. **Volume Mounts** (files injected into the pod filesystem).

**K14** — **ClusterIP:** Internal IP only. **NodePort:** Exposes service on a static port on every Node's IP. **LoadBalancer:** Provisions a cloud provider LB that routes to NodePorts.

**K15** — A DaemonSet ensures one copy of a pod runs on every (or selected) node. Use it for **cluster-wide infrastructure** like log collectors (Fluentd) or monitoring agents (Prometheus Node Exporter).

**K16** — **Taints** are on nodes to repel pods; **Tolerations** are on pods to allow them to stay on tainted nodes. **Node Affinity** attracts pods to nodes. *Use cases:* Taint a GPU node so only GPU-enabled pods (with tolerations) land there; use Affinity to ensure a pod lands in a specific Availability Zone.

**K17** — An Operator is a custom controller using **CRDs (Custom Resource Definitions)** to manage complex stateful apps. It differs from standard controllers by encoding **domain-specific operational knowledge** (e.g., how to perform a Postgres backup or failover).

**K18** — etcd uses **Raft** (strong consistency). If quorum is lost (e.g., 2/3 nodes down), the cluster becomes read-only/unavailable for writes. **Recovery:** You must restore from a backup or force a new cluster configuration using the remaining node as the seed.

**K19** — RBAC manages permissions. **Role/RoleBinding** are namespace-scoped; **ClusterRole/ClusterRoleBinding** are cluster-wide.
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { namespace: dev, name: pod-reader }
rules:
- apiGroups: [""]
  resources: ["pods", "pods/log"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { namespace: dev, name: read-pods-binding }
subjects: [{ kind: User, name: "developer", apiGroup: rbac.authorization.k8s.io }]
roleRef: { kind: Role, name: pod-reader, apiGroup: rbac.authorization.k8s.io }
```

**K20** — `ndots:5` means if a query has fewer than 5 dots, K8s tries internal search paths first (e.g., `google.com.default.svc.cluster.local`) before trying the external domain. This causes 4+ failed queries per request. **Fix:** Set `dnsConfig` with `ndots: 1` in the pod spec.

## Development

**D1** — **Merge** preserves history by creating a merge commit. **Rebase** rewrites history by moving the branch base to the tip of the target branch. **Avoid rebasing** on public/shared branches to prevent breaking other developers' histories.

**D2** — **TCP** is connection-oriented, reliable, and ordered (e.g., HTTP, SSH). **UDP** is connectionless, faster, but unreliable (e.g., DNS, VoIP).

**D3** — A race condition occurs when the outcome depends on the non-deterministic timing of events. *Example:* Two threads incrementing a shared variable `count++`. Both read `10`, both increment to `11`, and write `11` back, losing one increment.

**D4** — **Symmetric:** Same key for encrypt/decrypt (fast). **Asymmetric:** Public key encrypts, private key decrypts (slow). **TLS:** Asymmetric encryption is used for the initial handshake to securely exchange a symmetric "session key," which is then used for the actual data transfer.

**D5** — A layer is a read-only snapshot of the filesystem changes from a Dockerfile instruction. **Caching:** Docker reuses layers if the instruction and files haven't changed. *Best practice:* Put infrequently changed instructions (OS install) at the top and frequently changed ones (source code) at the bottom.

**D6** — 1. **Load Balancer/Ingress logs** (Is the request reaching the app?). 2. **Application logs** (Are there timeouts or crashes?). 3. **Resource metrics** (CPU/RAM spikes causing throttling?). 4. **Downstream dependencies** (Is the DB or a 3rd party API timing out?).

**D7** — **CAP:** Consistency, Availability, Partition Tolerance. You can only have 2 of 3 during a network partition. **CP (Consistency/Partition):** MongoDB (stops writes if primary is lost). **AP (Availability/Partition):** Cassandra (allows writes to any node, resolves conflicts later).

**D8** — **Horizontal:** Adding more machines (scaling out). **Vertical:** Adding more CPU/RAM to one machine (scaling up). **Patterns:** Statelessness, Load Balancing, Distributed Caching, Database Sharding.

**D9** — An environment variable is a dynamic value available to processes. To persist on Linux: Add `export VAR_NAME="value"` to `~/.bashrc` or `~/.profile` and run `source ~/.bashrc`.

**D10** — **JSON:** Strict syntax, widely supported by APIs. **YAML:** Human-readable, supports comments and anchors. *Advantage:* JSON is faster for machines to parse; YAML is easier for humans to write/edit (configs).

**D11** — **REST API:** An architectural style using HTTP for state transfer. **GET:** Retrieve data. **POST:** Create data. **PUT:** Update/Replace data. **DELETE:** Remove data.

**D12** — Version pinning is specifying the exact version of a dependency (e.g., `requests==2.25.1`). It prevents "breaking changes" from new releases from crashing the build, ensuring the environment is identical across dev/prod.

**D13** — **Compiled:** Translated to machine code before execution (e.g., C++, Rust). **Interpreted:** Read and executed line-by-line by a runtime (e.g., Python, Ruby).

**D14** — **Forward Proxy:** Sits in front of clients to hide them/filter outgoing traffic. **Reverse Proxy:** Sits in front of servers to load balance/cache/secure incoming traffic. *Examples:* **NGINX** (Load balancing), **Varnish** (HTTP caching).

**D15** — A deadlock is when two or more threads are blocked forever, each waiting for the other to release a resource. **Coffman Conditions:** 1. Mutual Exclusion. 2. Hold and Wait. 3. No Preemption. 4. Circular Wait.

**D16** — Eventual consistency means that if no new updates are made, all reads will eventually return the last updated value. **Cassandra** handles this via **Tunable Consistency**: `QUORUM` (majority of nodes must agree) for strong consistency, or `ONE` for high availability/low latency.

**D17** — **mTLS:** Both client and server present certificates. **Handshake:** 1. Server sends cert $\rightarrow$ Client verifies. 2. Server requests client cert $\rightarrow$ Client sends cert $\rightarrow$ Server verifies. 3. Both derive a session key. **Usage:** Service meshes (Istio, Linkerd) for zero-trust internal communication.

**D18** — A hash table uses a hash function to map keys to array indices. **Collisions:** **Chaining** (linked list at each index) or **Open Addressing** (find next empty slot). **Complexity:** Average: $O(1)$ for all. Worst: $O(n)$ (if all keys hash to the same index).

**D19** — **Circuit Breaker:** Stops requests to a failing service to prevent cascade failure. **States:** **Closed** (traffic flows), **Open** (fails fast immediately), **Half-Open** (tests a few requests to see if service recovered). It complements **Exponential Backoff** by stopping retries entirely when the system is overwhelmed.

**D20** — **Optimistic:** Assume no conflict; check for changes at commit time (e.g., using a `version` column). Use for low-contention systems. **Pessimistic:** Lock the record immediately (e.g., `SELECT FOR UPDATE`). Use for high-contention systems where conflicts are frequent and expensive.
