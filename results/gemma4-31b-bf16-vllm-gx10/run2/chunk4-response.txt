## Go

**G1**: An array has a fixed size defined at compile time; a slice is a descriptor for a contiguous segment of an array (containing a pointer, length, and capacity). When a slice exceeds its capacity during `append`, Go allocates a new, larger underlying array, copies the existing elements, and returns a new slice header.

**G2**: `var x int` declares a variable with its zero value (0). `x := 0` is short-variable declaration that infers the type. You cannot use `:=` outside of functions or when redeclaring a variable without at least one new variable on the left side.

**G3**: A goroutine is a lightweight thread managed by the Go runtime. Unlike OS threads (MBs of stack), goroutines start with ~2KB. The GMP model consists of **G** (Goroutine), **M** (Machine/OS Thread), and **P** (Processor/Context). P schedules Gs onto Ms to achieve efficient M:N multiplexing and work-stealing.

**G4**: Channels are typed conduits for communication. **Unbuffered** channels block the sender until a receiver is ready (synchronous). **Buffered** channels allow sending up to $N$ values without a receiver. Sending to a full buffered channel blocks the sender until a slot opens.

**G5**: `context` manages deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
_, err := http.DefaultClient.Do(req)
```

**G6**: Go uses **structural typing** (implicit satisfaction); if a type implements the methods of an interface, it satisfies it without an explicit `implements` keyword. `interface{}` (or `any`) can hold any value. It is powerful for generic containers but dangerous because it bypasses compile-time type safety, requiring runtime type assertions.

**G7**: Go does not guarantee that a write in one goroutine is visible to another without synchronization. The example is unsafe because the compiler/CPU may reorder instructions or cache `ready` in a register, leading to an infinite loop or reading `data` before it is set. **Correct alternatives**: `sync.Mutex`, `atomic.Value`, or a channel.

**G8**: `sync.Mutex` is a mutual exclusion lock. `sync.RWMutex` allows multiple concurrent readers OR one writer, improving performance for read-heavy workloads. `sync.Map` is optimized for two cases: (1) entries are only written once but read many times, or (2) multiple goroutines read/write/overwrite disjoint sets of keys. Regular maps with mutexes are generally faster for most common use cases.

**G9**: Go modules manage dependencies. `go.mod` defines the module path and required versions; `go.sum` contains cryptographic hashes for reproducibility. `go mod tidy` adds missing modules and removes unused ones. **MVS** selects the *minimum* version that satisfies all constraints, ensuring stability over "latest" versioning.

**G10**: `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO** (Last-In, First-Out) order. **Gotcha**: Using `defer` inside a loop can cause resource exhaustion (e.g., open files) because they don't execute until the function exits, not the loop iteration.

**G11**: A pointer stores the memory address of a value. The zero value is `nil`. Create a pointer to a struct literal using the address-of operator: `p := &User{Name: "Alice"}`.

**G12**: `init()` is used for package initialization. It runs after variable initialization but before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source files (and in the order packages are imported).

**G13**: `new(T)` allocates zeroed memory for type `T` and returns a pointer `*T`. `make` is used only for **slices, maps, and channels**, initializing their internal data structures and returning an initialized value of type `T` (not a pointer).

**G14**: Go uses explicit return values for errors. The `error` interface has one method: `Error() string`. Idiom: `if err != nil { return err }`. `errors.Is` checks if an error wraps a specific target; `errors.As` attempts to cast an error to a specific type. `==` only works for sentinel errors and doesn't handle wrapped errors.

**G15**: 
- Map: `nil`
- Slice: `nil`
- Channel: `nil`
- Struct: All fields set to their respective zero values.

**G16**: A race condition occurs when two goroutines access the same memory concurrently and at least one access is a write. `-race` uses a runtime instrumentation tool to detect these.
*Fix*: Wrap the shared variable in a `sync.Mutex` (`mu.Lock(); count++; mu.Unlock()`) or communicate the value via a channel.

**G17**: `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, it blocks until one of its cases can run. If multiple are ready, one is chosen **pseudo-randomly**. Timeout: `case <-time.After(1 * time.Second):`.

**G18**: Escape analysis determines if a variable can be allocated on the stack or must "escape" to the heap. If a variable is referenced outside the function scope (e.g., returning a pointer), it goes to the heap. Inspect via `go build -gcflags="-m"`. Heap allocation increases GC pressure and reduces performance.

**G19**: `reflect` allows inspecting types at runtime. `reflect.Type` represents the type (e.g., `int`), while `reflect.Value` represents the actual data. Costs include significant CPU overhead and loss of type safety. Reflection is justified for generic libraries (e.g., JSON encoders); code generation is preferred for performance-critical paths.

**G20**: `go:embed` allows embedding files into the binary at compile time. Single files use `string` or `[]byte`; directories use `embed.FS`. It implements `io/fs.FS`, allowing the embedded filesystem to be used interchangeably with the OS filesystem. Limitation: It only supports read-only access.

## Rust

**R1**: Ownership is a system to manage memory without a GC. Rules: (1) Each value has a variable called its owner. (2) There can only be one owner at a time. (3) When the owner goes out of scope, the value is dropped.

**R2**: `String` is a heap-allocated, growable UTF-8 string. `&str` is an immutable slice (a pointer and length) pointing to a string in the heap, stack, or binary. Use `&str` in function signatures for flexibility (it accepts both `String` and `&str`).

**R3**: Borrowing allows accessing data without taking ownership. Rules: You may have **either** one mutable reference (`&mut T`) **or** any number of immutable references (`&T`) at any given time. This prevents data races at compile time.

**R4**: `Result<T, E>` handles recoverable errors; `Option<T>` handles the presence or absence of a value. The `?` operator unwraps a `Result`/`Option` or returns the error/None to the caller.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}
```

**R5**: `Box<T>` is a heap allocation (single ownership). `Rc<T>` is a reference-counted pointer for single-threaded shared ownership. `Arc<T>` (Atomic Reference Counted) is the thread-safe version of `Rc<T>`.

**R6**: Traits define shared behavior (similar to interfaces). Go interfaces are implicit; Rust traits are explicit. `T: Trait` (Generics) uses **static dispatch** (monomorphization), creating a copy of the function for each type. `dyn Trait` (Trait Objects) uses **dynamic dispatch** via a vtable.

**R7**: The compiler doesn't know if the returned reference points to `x` or `y`.
*Fix*: Add lifetime annotations to tell Rust the return value lives as long as the shortest input:
`fn longest<'a>(x: &'a str, y: &'a str) -> &'a str { ... }`

**R8**: `Send` means a type can be transferred to another thread. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send` or `Sync` because its reference count is not updated atomically. `Arc<T>` uses atomic operations for the count, making it thread-safe.

**R9**: Rust's async is **poll-based**. A `Future` is a state machine that does nothing until `poll()` is called. The **executor** (e.g., Tokio) manages a queue of futures and polls them when the waker signals readiness. Go's goroutines are **push-based** and managed by a runtime scheduler that preempts tasks.

**R10**: `unsafe` disables some compiler checks. You can: (1) Dereference raw pointers, (2) Call unsafe functions (FFI), (3) Access/modify mutable static variables. It is justified for low-level hardware access, FFI, or implementing high-performance abstractions (like `Vec`).

**R11**: Pattern matching (`match`) allows branching based on the structure of data. `if let` is syntactic sugar for a `match` with only one pattern. The compiler enforces **exhaustiveness**, meaning every possible value of the type must be handled.

**R12**: `[T; N]` is a fixed-size array on the stack. `Vec<T>` is a growable heap-allocated array. When capacity is exceeded, `Vec` reallocates a larger block of memory (usually doubling), copies elements, and frees the old block.

**R13**: Rust enums are **sum types** (can hold data), unlike C enums which are just integers. `Option<T>` is an enum with variants `Some(T)` and `None`. Rust avoids `null` to eliminate null-pointer exceptions, forcing the developer to handle the `None` case.

**R14**: `impl` blocks define methods for a type. `&self` is an immutable borrow, `&mut self` is a mutable borrow, and `self` takes ownership. Associated functions (like `String::new()`) do not take `self` and are called on the type itself.

**R15**: `derive` automatically implements traits. Examples: `Debug` (printing), `Clone` (deep copy), `PartialEq` (equality), `Serialize` (serde). You cannot derive a trait if the type contains a field that does not implement that trait.

**R16**: `Cow` (Clone-on-Write) allows a value to be either borrowed or owned. It avoids allocation by staying borrowed until a mutation is required, at which point it clones the data. Example: A function that cleans a string only if it contains illegal characters.

**R17**: `mod` declares a module, `use` brings paths into scope, and `pub` makes items visible. Files map to modules (e.g., `src/foo.rs` is `mod foo`). In 2018+, `extern crate` became unnecessary and the module system was simplified to be more intuitive.

**R18**: `Pin<T>` ensures a value cannot be moved in memory. This is critical for **self-referential structs** (where a field points to another field in the same struct), which are common in `async` blocks. `Unpin` is a trait for types that are safe to move (most types).

**R19**: Declarative macros (`macro_rules!`) are pattern-matching based. Procedural macros are functions that operate on the AST (Abstract Syntax Tree). **Hygiene** ensures that macros don't accidentally capture variables from the surrounding scope or introduce name collisions.

**R20**: Zero-cost abstractions mean you don't pay for what you don't use. **Monomorphization** generates specialized code for each generic type, removing runtime overhead. **Iterators** are optimized by the compiler into loops equivalent to C. **Static dispatch** avoids vtable lookups.
