## JavaScript / TypeScript

**JS1**: `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and exist in a "Temporal Dead Zone" until declared. `const` prevents reassignment. **Hoisting** is the JS engine's behavior of moving declarations to the top of their scope during the compilation phase.

**JS2**: The **Event Loop** manages the execution of multiple chunks of your script. The **Call Stack** handles synchronous execution. When async tasks finish, they enter queues: **Microtask Queue** (Promises, `queueMicrotask`) has priority and is emptied completely before the **Macrotask Queue** (setTimeout, setInterval, I/O) is processed.

**JS3**: A **Closure** is a function that remembers its lexical scope even when executed outside that scope. *Example*: A counter function returning an inner function that increments a private variable. *Bug*: Using `var` in a `for` loop creates one variable for all iterations. *Fix*: Use `let` (block-scoped) or an IIFE.

**JS4**: `Promise` represents a future value. `async/await` is syntactic sugar for Promises. Error handling: `.catch()` for Promises, `try/catch` for `await`. `Promise.all` rejects immediately if any promise fails; `Promise.allSettled` waits for all to complete regardless of outcome.

**JS5**: `interface` is primarily for defining object shapes and supports "declaration merging." `type` is a union/alias for any type (primitives, unions, tuples). Use `interface` for public APIs/classes; `type` for complex logic. **Discriminated Unions** use a common literal property (e.g., `kind: 'circle' | 'square'`) to allow TS to narrow types in a switch/if block.

**JS6**: JS uses **Prototypal Inheritance**: objects inherit directly from other objects via a prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is "syntactic sugar" over prototypes; `extends` sets the prototype of the class prototype.

**JS7**: `this` refers to the execution context. **Binding Rules**: 1. `new` binding, 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (object method), 4. Default (global/undefined). `bind()` returns a new function with `this` locked. It cannot be re-bound.

**JS8**: `WeakRef` allows holding a reference to an object without preventing GC. `FinalizationRegistry` triggers a callback after an object is GC'd. `WeakMap` keys must be objects because the map holds a "weak" reference to the key; if the key object is deleted elsewhere, the entry is GC'd.

**JS9**: V8 uses **Hidden Classes** (shapes) to optimize property access. **Inline Caching** remembers where properties were found in previous lookups. **Deoptimization** occurs when a "speculative" optimization fails (e.g., changing the order of property assignment or changing a variable's type), forcing V8 back to interpreted bytecode.

**JS10**: **Tree-shaking** is the removal of unused code. ES Modules (`import/export`) are statically analyzable, allowing tools (Webpack/Rollup) to see what isn't used. CommonJS (`require`) is dynamic (can be inside an `if`), making it impossible to determine usage without running the code.

**JS11**: `undefined` means a variable was declared but not assigned; `null` is an intentional assignment of "no value." `==` performs type coercion; `===` checks value and type. `??` (nullish coalescing) returns the RHS only if LHS is `null` or `undefined`. `?.` (optional chaining) short-circuits to `undefined` if a property in the chain is nullish.

**JS12**: `map()` transforms each element; `filter()` removes elements based on a predicate; `reduce()` aggregates an array into a single value. If an initial value is provided to `reduce()`, it's used as the first accumulator; otherwise, the first element of the array is used. `flatMap()` maps then flattens one level; useful for removing items or expanding one item into many.

**JS13**: **Template literals** use backticks (`` ` ``) for interpolation. **Tagged templates** are functions called with the string parts and interpolated values as arguments. *Example*: `sql`tag`SELECT * FROM users WHERE id = ${id}` could be used to sanitize inputs to prevent SQL injection.

**JS14**: **Destructuring** unpacks values from arrays/objects. *Object*: `const {name, age} = user`. *Array*: `const [first, second] = list`. *Default*: `{name = 'Guest'} = user`. *Renaming*: `{name: userName} = user`. *Rest*: `const {a, ...others} = obj` puts remaining properties into `others`.

**JS15**: `for...in` iterates over enumerable **keys** (strings) of an object (including prototype chain). `for...of` iterates over **values** of iterable objects (Arrays, Maps, Sets). Avoid `for...in` on arrays because it iterates over indices as strings and may include custom properties added to the Array prototype.

**JS16**: **Generics** allow components to work with multiple types. **Constraints**: `<T extends string>` ensures T is a string or subtype. **Conditional Types**: `T extends U ? X : Y` chooses a type based on a condition. **Infer**: `type ReturnType<T> = T extends (...args: any[]) => infer R ? R : any` extracts a type from another.

**JS17**: **CommonJS** (CJS) uses `require`/`module.exports` (synchronous, Node default). **ES Modules** (ESM) use `import`/`export` (asynchronous, browser standard). Node handles both; `"type": "module"` in `package.json` tells Node to treat `.js` files as ESM.

**JS18**: **Structural Typing** (Duck Typing) means if two types have the same shape, they are compatible. **Excess Property Checks** occur only on object literals assigned directly to a type. `extends` is for inheritance/constraints; `satisfies` validates a value matches a type without widening the value's type. **Variance**: Covariance (out) allows subtypes; Contravariance (in) allows supertypes.

**JS19**: `Proxy` wraps an object to intercept operations (get, set, apply). `Reflect` provides methods that mirror Proxy traps. *Example*: A validation proxy that throws an error if a `set` operation attempts to assign a negative number to an `age` property.

**JS20**: `SharedArrayBuffer` provides memory shared between the main thread and Web Workers. `Atomics` ensures thread-safe operations (e.g., `Atomics.add`) to prevent race conditions. `Atomics.wait` puts a thread to sleep until a value changes, and `Atomics.notify` wakes it up.

## Bash

**B1**: `$*` and `$@` both represent all positional parameters. In double quotes: `"$*"` is one single string (joined by first char of `IFS`); `"$@"` is a list of separate strings (preserving spaces in arguments).

**B2**: `set -e`: Exit immediately if a command fails. `-u`: Treat unset variables as an error. `-o pipefail`: Return the exit code of the last command in a pipe that failed, rather than the last command in the pipe.

**B3**: `$(command)` is the modern syntax for command substitution; `` `command` `` is the legacy version (harder to nest). `$((expression))` is for integer arithmetic; `expr` is an external utility that is slower and has more complex escaping rules.

**B4**: **Process Substitution** `<(command)` makes the output of a command appear as a file. *Example*: `diff <(ls dir1) <(ls dir2)` compares the file lists of two directories without creating temporary files.

**B5**: Use `while IFS= read -r line; do ... done < "file.txt"` or `find . -print0 | xargs -0`. `for f in $(ls)` is dangerous because it splits filenames on whitespace, breaking files with spaces.

**B6**: **Here-doc** (`<<EOF`) redirects a block of text to stdin. **Here-string** (`<<< "text"`) passes a single string to stdin. `<<-EOF` strips leading tabs from the input lines, allowing the block to be indented for readability.

**B7**: 1. `> file 2>&1`: Stdout goes to file, then Stderr is redirected to where Stdout is currently going (the file). 2. `2>&1 > file`: Stderr goes to current Stdout (terminal), then Stdout is redirected to file. Result: Stderr stays on terminal. 3. `&> file`: Shorthand for both to file.

**B8**: Use `mkdir lockdir` because it is an atomic operation at the OS level.
```bash
lock() {
  until mkdir /tmp/mylock 2>/dev/null; do sleep 1; done
  trap 'rmdir /tmp/mylock; exit' INT TERM EXIT
}
```
`mkdir` is preferred over `touch` because two processes can `touch` the same file, but only one can `mkdir` a directory of the same name.

**B9**: `'...'` (Single): Literal string, no expansion. `"..."` (Double): Allows variable/command expansion. No quotes: Subject to word splitting and globbing. *Example*: `echo "$VAR"` vs `echo '$VAR'` (prints value vs literal string).

**B10**: `-f` (file exists), `-d` (is directory), `-r` (is readable). `[ ]` is the POSIX standard `test` command. `[[ ]]` is a Bash extension that supports regex (`=~`), logical operators (`&&`, `||`) without escaping, and doesn't require quoting variables to prevent word splitting.

**B11**: `$?`: Exit status of last command. `$$`: PID of current shell. `$!`: PID of last background process. `$#`: Number of arguments passed to script.

**B12**: `foo() { ... }` is the standard way. `function foo { ... }` is a Bash-specific keyword. Functions return an exit status (0-255) via `return`. To return a value, `echo` the result and capture it with `result=$(foo)`.

**B13**: `PATH` is a colon-separated list of directories searched for executables. Bash checks: Aliases $\rightarrow$ Functions $\rightarrow$ Builtins $\rightarrow$ PATH. Builtins (e.g., `cd`) are inside the shell; external commands (e.g., `ls`) are files on disk. Use `type -a command` to check.

**B14**: `trap 'handler' SIGNAL` executes a command when a signal is received. `EXIT` covers normal termination. `INT` (Ctrl+C), `TERM` (kill), `ERR` (command failure). If multiple signals arrive, they are queued; the shell handles them sequentially.

**B15**: Command substitution `$(...)` loads the whole output into memory. `xargs` streams arguments to a command. `find -print0 | xargs -0` uses the null character as a delimiter to handle spaces/newlines. `xargs -P N` runs up to N processes in parallel.

**B16**: **Indexed**: `arr=(a b c)`, append `arr+=("d")`, length `${#arr[@]}`, iterate `for i in "${arr[@]}"`. **Associative**: `declare -A map`, `map[key]="val"`, iterate `for k in "${!map[@]}"`. Associative arrays require Bash 4.0+.

**B17**: `(...)` (Subshell) forks a new process; variables changed inside are lost to the parent. `{ ...; }` (Group) executes in the current shell; variables persist. Piping into a `while` loop (`cmd | while...`) creates a subshell, so variables modified inside the loop are lost.

**B18**: `SIGINT`: Interrupt (Ctrl+C). `SIGTERM`: Polite request to stop. `SIGHUP`: Terminal closed. `SIGKILL`: Immediate forced kill (cannot be trapped). For graceful shutdown: `trap 'kill $(jobs -p); exit' SIGTERM`.

**B19**:
```bash
split -l 1000 log.txt part_
ls part_* | xargs -P 4 -I {} bash -c 'process_func {} > {}.out'
cat *.out > final_result
```
Trade-off: Disk I/O for split files vs memory. Error propagation: Check exit codes of `xargs` or write failed chunks to a log file.

**B20**: `exec` replaces the current shell process with the new command (no return). For FDs: `exec 3>file` opens FD 3 for writing; `exec 3>&-` closes it. A **coprocess** (`coproc cmd`) runs a command in the background with two-way communication via pipes (`/dev/fd/X`).

## PowerShell

**PS1**: `Write-Output` sends objects to the pipeline (can be captured/processed). `Write-Host` writes directly to the console (cannot be captured). Using `Write-Host` in a function breaks the pipeline for downstream cmdlets.

**PS2**: The pipeline passes **objects**, not text. `ForEach-Object` (pipeline) processes items one-by-one as they arrive (streaming). `foreach` (statement) requires the entire collection to be in memory before starting. Use `ForEach-Object` for large datasets.

**PS3**: `[hashtable]` is a key-value pair (unordered). `[PSCustomObject]` is a structured object with properties (ordered). Use hashtables for lookups; PSCustomObjects for data output. Convert: `[PSCustomObject]$hash` or `New-Object PSObject -Property $hash`.

**PS4**: **Non-terminating**: Error occurs, but script continues (e.g., `Get-ChildItem` on a forbidden folder). **Terminating**: Script stops (e.g., syntax error). `-ErrorAction Stop` turns a non-terminating error into a terminating one, allowing it to be caught by `try/catch`.

**PS5**: **Splatting** passes a hashtable of parameters using `@` instead of `$`.
*Example*: `$params = @{ Path = 'C:\'; Recurse = $true }; Get-ChildItem @params`.
Unlike passing a hashtable as a single parameter, splatting expands the hashtable into individual named arguments.

**PS6**: `Invoke-Command` runs a script block on remote machines and returns results. `Enter-PSSession` creates an interactive shell. It uses **WinRM** (WS-Man) by default on Windows, but PowerShell 7+ supports **SSH** for cross-platform remoting.

**PS7**: PowerShell "unrolls" collections. If a function returns an array, the pipeline flattens it.
`$x` will be a `String` (the first element) if the array has 1 item, or an `Object[]` if it has multiple. If 0 items, it's `$null`. **Correct pattern**: Wrap the call in `@(Get-Items)` to force an array.

**PS8**: A `[scriptblock]` is a piece of code `{ ... }` that can be passed as an object. Pass to remote: `Invoke-Command -ScriptBlock { ... }`. **Double-hop**: Credentials aren't delegated to a second remote server. Solve via **CredSSP** or passing credentials explicitly via `-ArgumentList`.

**PS9**: `@()` is the array sub-expression operator (forces result to array). `[array]` is a type cast. Indexing into `$null` returns `$null` (no error), whereas indexing into an empty array also returns `$null`.

**PS10**: `-eq` (equal), `-ne` (not equal), `-like` (wildcards `*`), `-match` (regex), `-contains` (collection contains value), `-in` (value is in collection). Case-sensitive versions start with `c` (e.g., `-ceq`). `-contains` is `Collection -contains Value`; `-in` is `Value -in Collection`.

**PS11**: A module is a package of functions/variables. `.psm1` contains the code; `.psd1` is a manifest (version, author, dependencies). Binary modules are compiled .dlls. `Import-Module` loads the module into the current session.

**PS12**: `"..."` (Double) allows interpolation; `'...'` (Single) is literal. Expressions use sub-expressions: `"Value is $($obj.Prop)"`. **Here-strings** (`@" ... "@`) allow multi-line strings without escaping quotes.

**PS13**: `Get-Member` shows the properties and methods of an object. **Properties** are data; **Methods** are actions; **NoteProperties** are dynamically added properties. `Select-Object` filters properties (columns); `Where-Object` filters objects (rows).

**PS14**: PS Classes provide strong typing and encapsulation. Unlike C#, they are more flexible but limited in inheritance (no multiple inheritance) and interface implementation. Use classes for complex data models; functions for task automation.

**PS15**: `[CmdletBinding()]` makes a function an "Advanced Function," enabling common parameters like `-Verbose`. `SupportsShouldProcess` enables `-WhatIf` and `-Confirm`. `Begin` (setup), `Process` (runs for each pipeline object), `End` (cleanup).

**PS16**: Providers map different data stores to a drive-like interface. `Get-ChildItem` works on `FileSystem:\`, `HKLM:\` (Registry), `Cert:\` (Certificates). You access the registry like a folder: `cd HKLM:\Software\Microsoft`.

**PS17**: A `[runspace]` is an isolated execution environment (thread). `[runspacepool]` manages multiple runspaces. `ForEach-Object -Parallel` (v7+) simplifies this by managing a pool automatically. Manual management is used for complex, long-running asynchronous tasks.

**PS18**: **PSScriptAnalyzer** is a static code analysis tool. It uses **Rules** (e.g., "Avoid using Write-Host") with **Severity** (Error, Warning, Info). Suppress via `[Diagnostics.CodeAnalysis.SuppressMessageAttribute()]`. Integrates into CI/CD via `Invoke-ScriptAnalyzer`.

**PS19**: `$using:var` is used in `Invoke-Command` or `-Parallel` to pull a local variable into the remote/parallel scope. `-ArgumentList` passes values as a positional array. **Serialization**: Objects are converted to CLIXML; deep or complex objects (like active DB connections) cannot be serialized and will be lost.

**PS20**: **DSC** uses a declarative model: "This is how the system should be." **Configurations** define the state; **Resources** implement the change; **LCM** (Local Configuration Manager) enforces the state. In PS 7+, DSC is moving toward a cross-platform version (DSCv3) and is largely superseded by tools like Terraform or Ansible for infra-as-code.
