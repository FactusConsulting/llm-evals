## Go

**G1**: An array has a fixed size defined at compile time; a slice is a descriptor for a contiguous segment of an array (containing a pointer, length, and capacity). When a slice reaches capacity and you `append`, Go allocates a new, larger underlying array, copies the existing elements, and returns a new slice header.

**G2**: `var x int` declares a variable with its zero value (0). `x := 0` is short-variable declaration (declares and initializes). You cannot use `:=` outside of functions or when you only want to assign a value to an existing variable.

**G3**: A goroutine is a lightweight thread managed by the Go runtime. Unlike OS threads (MBs of stack), goroutines start with ~2KB. The GMP model consists of **G** (Goroutine), **M** (Machine/OS Thread), and **P** (Processor/Logical Context). P schedules Gs onto Ms to achieve efficient M:N multiplexing.

**G4**: Channels are typed conduits for communication. **Unbuffered** channels block the sender until a receiver is ready (synchronous). **Buffered** channels allow sending without a receiver until the buffer is full. Sending to a full buffered channel blocks the goroutine.

**G5**: `context` manages deadlines, cancellation signals, and request-scoped values across API boundaries.
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
req, _ := http.NewRequestWithContext(ctx, "GET", "http://example.com", nil)
_, err := http.DefaultClient.Do(req)
```

**G6**: Go uses **structural typing** (implicit satisfaction); if a type implements the methods of an interface, it satisfies it without an explicit `implements` keyword. `interface{}` (or `any`) can hold any value. It is powerful for generic containers but dangerous because it bypasses compile-time type safety, requiring runtime type assertions.

**G7**: Go does not guarantee that a write in one goroutine is visible to another without synchronization. The example is unsafe because the compiler/CPU may reorder instructions or cache `ready` in a register, leading to an infinite loop or reading `data` before it is set. **Correct alternatives**: `sync.Mutex`, `atomic.Value`, or a channel.

**G8**: `sync.Mutex` is a mutual exclusion lock. `sync.RWMutex` allows multiple concurrent readers OR one writer. Use `sync.Map` for caches with high read-to-write ratios or when multiple goroutines read/write disjoint keys. Regular map + Mutex is generally faster for most use cases due to less internal overhead.

**G9**: Go modules manage dependencies. `go.mod` defines the module path and requirements; `go.sum` contains cryptographic hashes for reproducibility. `go mod tidy` adds missing and removes unused modules. **MVS** selects the *minimum* version that satisfies all constraints, ensuring stability over "latest" versioning.

**G10**: `defer` schedules a function call to run immediately before the surrounding function returns. Multiple defers execute in **LIFO** (Last-In-First-Out) order. **Gotcha**: Using `defer` inside a loop can cause resource exhaustion (e.g., open files) because they don't execute until the function exits, not the loop iteration.

**G11**: A pointer stores the memory address of a value. The zero value is `nil`. Create a pointer to a struct literal using the address-of operator: `p := &User{Name: "Alice"}`.

**G12**: `init()` is used for package initialization. It runs after variable initialization but before `main()`. A package can have multiple `init()` functions; they execute in the order they appear in the source files (lexical order of files).

**G13**: `new(T)` allocates zeroed memory for type T and returns a pointer `*T`. `make` is used only for **slices, maps, and channels**, initializing their internal data structures and returning an initialized value of type T.

**G14**: Go uses explicit return values for errors. The `error` interface has one method: `Error() string`. Idiom: `if err != nil { return err }`. `errors.Is` checks if an error wraps a specific target; `errors.As` attempts to cast an error to a specific type. `==` only works for sentinel errors and doesn't handle wrapped errors.

**G15**: 
- Map: `nil`
- Slice: `nil`
- Channel: `nil`
- Struct: All fields set to their respective zero values.

**G16**: A race condition occurs when two goroutines access the same memory concurrently and at least one access is a write. `-race` uses a runtime instrumentation tool to detect these.
*Fix*: Wrap the shared variable in a `sync.Mutex` `Lock()`/`Unlock()` or communicate the value via a channel.

**G17**: `select` lets a goroutine wait on multiple communication operations. Unlike `switch`, it blocks until one of its cases can run. If multiple are ready, one is chosen **pseudo-randomly**. Timeout: `case <-time.After(duration):`.

**G18**: Escape analysis determines if a variable can be allocated on the stack or must "escape" to the heap. If a variable is referenced outside the function scope (e.g., returning a pointer), it goes to the heap. Inspect via `go build -gcflags="-m"`. Heap allocation increases GC pressure, reducing performance.

**G19**: `reflect` allows inspecting types at runtime. `reflect.Type` represents the type; `reflect.Value` represents the actual data. Costs: significant CPU overhead and loss of type safety. Justified for generic libraries (JSON encoders); otherwise, code generation (e.g., `stringer`) is preferred for performance.

**G20**: `go:embed` allows embedding files into the binary. Single files use `string` or `[]byte`; directories use `embed.FS`. It implements `io/fs.FS`, allowing the binary to treat embedded files as a read-only filesystem. Limitation: it only supports read-only access.

## Rust

**R1**: Ownership is a system to manage memory without a GC. Rules: 1. Each value has a variable called its owner. 2. There can only be one owner at a time. 3. When the owner goes out of scope, the value is dropped.

**R2**: `String` is a heap-allocated, growable UTF-8 string. `&str` is an immutable slice (reference) to a string. Use `&str` in function signatures for flexibility (accepts both `String` and literals); use `String` when the function must own the data.

**R3**: Borrowing allows accessing data without taking ownership. **Shared references (`&T`)**: any number of readers, no writers. **Mutable references (`&mut T`)**: exactly one writer, no other readers/writers. This prevents data races at compile time.

**R4**: `Result<T, E>` handles recoverable errors; `Option<T>` handles presence/absence of a value. The `?` operator unwraps a `Result`/`Option` or returns the error/None to the caller.
```rust
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path) // returns Result
}
```

**R5**: `Box<T>`: Heap allocation (single ownership). `Rc<T>`: Reference counted (multiple owners, single-threaded). `Arc<T>`: Atomic Reference Counted (multiple owners, thread-safe).

**R6**: Traits define shared behavior (similar to interfaces). Go interfaces are implicit; Rust traits are explicit. **Trait Object (`dyn Trait`)**: dynamic dispatch (runtime lookup via vtable). **Generic Bound (`T: Trait`)**: static dispatch (monomorphization at compile time).

**R7**: The compiler doesn't know which input reference (`x` or `y`) the return value refers to. Fix by adding lifetime annotations: `fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`. This tells Rust the returned reference lives as long as the shortest input.

**R8**: `Send` means a type can be transferred to another thread. `Sync` means a type can be shared between threads via references. `Rc<T>` is not `Send`/`Sync` because its reference count is not atomic (race condition). `Arc<T>` uses atomic operations for the count, making it thread-safe.

**R9**: Rust's async is **poll-based**. A `Future` is a state machine that does nothing until `poll()` is called. The **executor** (Tokio) manages a queue of futures and polls them when they are woken. Go's goroutines are **push-based** (managed by a runtime scheduler that preempts/switches).

**R10**: `unsafe` disables some compiler checks. You can: 1. Dereference raw pointers. 2. Call unsafe functions (FFI). 3. Access/modify mutable static variables. Justified for low-level hardware access, FFI, or implementing high-performance data structures (e.g., `Vec`).

**R11**: Pattern matching (`match`) allows branching based on the structure of data. `if let` is syntactic sugar for a `match` with only one pattern. The compiler enforces **exhaustiveness**, meaning every possible value of the enum must be handled.

**R12**: `[T; N]` is a fixed-size array on the stack. `Vec<T>` is a growable heap-allocated array. When capacity is exceeded, `Vec` reallocates a larger block of memory (usually doubling), copies elements, and frees the old block.

**R13**: Rust enums are **sum types** (can hold data), unlike C enums (just integers). `Option<T>` is an enum with `Some(T)` and `None`. Rust avoids `null` to eliminate null-pointer exceptions, forcing the developer to handle the `None` case.

**R14**: `impl` blocks define methods for a type. `&self`: immutable borrow. `&mut self`: mutable borrow. `self`: consumes the object (takes ownership). Associated functions (no `self`) are called via `Type::func()` and act like static methods.

**R15**: `derive` automatically implements traits. Examples: `Debug` (formatting), `Clone` (deep copy), `PartialEq` (equality), `Serialize` (serde). You cannot derive a trait if the type contains a field that does not implement that trait.

**R16**: `Cow` (Clone-on-Write) allows a value to be either borrowed or owned. It avoids allocation if the data doesn't need to be modified. Example: A function that cleans a string; if no cleaning is needed, it returns the borrowed `&str`; if cleaning is needed, it allocates a `String`.

**R17**: `mod` declares a module; `use` creates a shortcut to a path; `pub` makes items visible. Files map to modules (e.g., `foo.rs` is `mod foo`). In 2018+, `extern crate` is mostly gone, and the module system became more intuitive with better path resolution.

**R18**: `Pin<T>` ensures a value cannot be moved in memory. This is critical for **self-referential structs** (where a field points to another field in the same struct), which are common in `async` blocks. `Unpin` is a trait for types that are safe to move (most types).

**R19**: `macro_rules!` (declarative) uses pattern matching to replace code. Procedural macros are functions that operate on the AST (Abstract Syntax Tree). **Hygiene** ensures macros don't accidentally capture variables from the surrounding scope or introduce name collisions.

**R20**: Zero-cost abstractions mean you don't pay for what you don't use. **Monomorphization** generates a specialized version of a generic function for every type used, allowing the compiler to inline and optimize it exactly like a hand-written function, avoiding runtime dispatch.
