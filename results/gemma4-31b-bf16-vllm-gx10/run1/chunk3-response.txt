## OpenTofu / Terraform

**T1**: `tofu plan` is a dry run; it compares the current state with the desired configuration and shows what actions will be taken. `tofu apply` executes those actions to reach the desired state.

**T2**: State is a JSON file mapping real-world resources to your configuration. Remote state (e.g., S3, Consul) is critical for team collaboration, providing a single source of truth and preventing state corruption via locking.

**T3**: `count` uses an index (0, 1, 2), while `for_each` uses a map or set of keys. `for_each` is preferred when resources are distinct or may be removed from the middle of a list, as `count` would cause a "shift" and trigger unnecessary recreations of subsequent resources.

**T4**: This is "drift." OpenTofu detects it during the next `plan` by refreshing the state against the actual cloud API. It will propose a change to revert the manual modification back to the configuration's defined state.

**T5**:
```hcl
resource "aws_instance" "vm" {
  for_each = toset(["web1", "web2", "web3"])
  ami           = "ami-12345678"
  instance_type = "t3.micro"
  tags = { Name = each.key }
}
```

**T6**: `terraform_remote_state` reads the entire state file of another project; output values are specific exported variables. The recommended alternative is using a dedicated "Data" resource (e.g., `aws_vpc`) to look up resources by tags/names, as it reduces coupling and security risks associated with sharing full state files.

**T7**: Provisioners run during the resource creation phase, but outputs are evaluated after the apply is complete. The output is empty because the resource hasn't "finished" in a way that populates the output during the first pass. **Fix**: Use a `remote-exec` to write the kubeconfig to a file on a shared disk or use a `null_resource` with a `trigger` to ensure the sequence is strictly enforced, or better yet, use a cloud-init script.

**T8**: `tofu import` brings existing infrastructure into state via CLI. Limitation: it only updates state, not the `.tf` code. The `import` block (1.5+) allows importing via code, enabling `tofu plan` to generate the necessary HCL configuration automatically.

**T9**: A `variable` (input) is a parameter passed into the module (like a function argument). An `output` is a value returned by the module (like a return value) for use by other modules or the user.

**T10**: A provider is a plugin that translates HCL into API calls for a specific platform (AWS, Azure, etc.). Running `plan` without `init` fails because the required provider binaries have not been downloaded to the `.terraform` directory.

**T11**: It is the Dependency Lock File. It records the exact versions and hashes of providers used. Committing it ensures every environment (Dev, Prod, CI) uses the exact same provider version, preventing "it works on my machine" bugs.

**T12**: `tofu destroy` removes all managed infrastructure. To target one resource: `tofu destroy -target=aws_instance.web_server`.

**T13**: A data source fetches information from an external source (read-only). Example: Using `data "aws_ami"` to find the latest Ubuntu AMI ID instead of hardcoding it in a resource.

**T14**: `variables` are external inputs. `locals` are internal constants or computed values. Use `locals` to avoid repeating complex expressions or to transform input variables into a usable format.

**T15**:
- `create_before_destroy`: Creates the new resource before deleting the old one (Use case: Zero-downtime DNS/LB updates).
- `prevent_destroy`: Errors out if a destroy is attempted (Use case: Production databases).
- `ignore_changes`: Ignores drift on specific attributes (Use case: Auto-scaling groups where the cloud provider changes the `desired_capacity`).

**T16**: A `moved` block tells OpenTofu that a resource has changed its address (e.g., moved into a module). This allows the state to be updated without destroying and recreating the physical resource.

**T17**: OpenTofu builds a Directed Acyclic Graph (DAG). **Implicit**: Resource A references `aws_vpc.main.id`. **Explicit**: Using `depends_on`. `depends_on` forces a strict order, reducing parallelism. It should be used sparingly because it can hide architectural flaws and slow down execution.

**T18**:
1. **Modularization**: Split one giant state into smaller states (Tradeoff: More complex orchestration).
2. **`-refresh=false`**: Skip API checks during plan (Tradeoff: Risk of acting on stale data).
3. **Targeting**: Use `-target` for specific changes (Tradeoff: Can lead to inconsistent state).
4. **Parallelism**: Adjust `-parallelism=N` (Tradeoff: May hit API rate limits).

**T19**: Locking prevents concurrent writes to state. If a crash occurs, the lock remains. Manually break it with `tofu force-unlock <LOCK_ID>`. Risk: If another process is actually running, you will cause state corruption.

**T20**: 
1. Add the `backend "s3" { ... }` block to the config.
2. Run `tofu init`. 
3. OpenTofu detects the local state and asks to migrate it to S3. Type `yes`.
4. Verify: Check the S3 bucket for the `.tfstate` file and the DynamoDB table for the lock record.

## Ansible

**A1**: A **task** is a single unit of work (one module call). A **playbook** is a YAML file mapping hosts to a list of tasks. A **role** is a structured bundle of tasks, variables, files, and templates for reuse.

**A2**: `ansible_facts` is a dictionary containing system information gathered at the start of a play. Access OS family via `ansible_facts['os_family']` or `ansible_os_family`.

**A3**: 
- `command`: Safest, doesn't process through a shell (no pipes/redirects).
- `shell`: Runs through `/bin/sh`, allows pipes, redirects, and environment variables.
- `raw`: Bypasses the Python requirement on the target; sends raw SSH commands (used for bootstrapping Python).

**A4**: Idempotency means running the same operation multiple times results in the same state without changing anything after the first run.
- **Idempotent**: `apt: name=nginx state=present` (checks if installed first).
- **NOT Idempotent**: `shell: echo "hello" >> /tmp/log` (appends every time).

**A5**:
```yaml
- name: Install htop
  package:
    name: "{{ 'htop' if ansible_os_family == 'Debian' else 'htop' }}"
  when: ansible_os_family == 'Debian'
- name: Install EPEL and htop
  yum:
    name: "{{ item }}"
    state: present
  with_items: ['epel-release', 'htop']
  when: ansible_os_family == 'RedHat'
```
*(Note: Better to use two separate tasks for clarity, but the prompt asks for a single task file approach).*

**A6**: (Lowest to Highest)
1. Role defaults $\rightarrow$ 2. Inventory group_vars $\rightarrow$ 3. Inventory host_vars $\rightarrow$ 4. Playbook group_vars/host_vars $\rightarrow$ 5. `set_fact` $\rightarrow$ 6. Extra vars (`-e`).

**A7**: 
- Use `serial: 3` to limit the batch size.
- Use separate inventory groups: `[initial_nodes]` and `[remaining_nodes]`.
- Use `wait_for` module to ensure the RKE2 port (e.g., 6443) is open on the first 3 nodes before proceeding to the rest.

**A8**: `ansible-vault` encrypts files or strings. To encrypt a single variable: use `ansible-vault encrypt_string 'my_password' --name 'db_password'`. This allows the rest of the vars file to remain plain text.

**A9**: An inventory is a list of managed nodes. **Static**: A flat file (INI/YAML). **Dynamic**: A script or plugin that queries an API (AWS, GCP) to generate the list of hosts in real-time.

**A10**: `ansible webservers -m shell -a "df -h"`

**A11**: A handler is a task that only runs if "notified" by another task that reported a `changed` status. Trigger it using the `notify: handler_name` keyword.

**A12**: `ansible.cfg` defines global settings. Common settings: `remote_user`, `inventory`, `forks`, and `host_key_checking = False`.

**A13**: `register` captures the output of a task into a variable.
```yaml
- shell: uptime
  register: uptime_result
- debug: msg="{{ uptime_result.stdout }}"
```

**A14**: `import_tasks` is static (processed at playbook parse time). `include_tasks` is dynamic (processed at runtime). Use `include_tasks` for conditional loops; `import_tasks` for better performance and visibility during `--list-tasks`.

**A15**: Ansible Galaxy is a community hub for roles/collections. Use a `requirements.yml` file:
```yaml
roles:
  - name: geerlingguy.nginx
```
Install via: `ansible-galaxy install -r requirements.yml`.

**A16**: Connection plugins determine how Ansible talks to the host.
- `ssh`: Standard for Linux (requires Python).
- `local`: Runs tasks on the control node.
- `network_cli`: Persistent connection for network devices (Cisco/Juniper) that don't support Python.

**A17**: `delegate_to` runs a task on a different host than the current one. `run_once` ensures the task executes only once for the entire batch.
**Example**: Update a load balancer (localhost) with the IP of a remote server:
```yaml
- name: Update LB
  uri: url="http://lb/api" method=POST body="ip={{ ansible_default_ipv4.address }}"
  delegate_to: localhost
  run_once: true
```

**A18**:
1. **Forks**: Increase `forks = 50` in `ansible.cfg` to run tasks on more hosts in parallel.
2. **Pipelining**: Enable `pipelining = True` to reduce the number of SSH connections.
3. **Fact Caching**: Use Redis or JSON files to cache `ansible_facts` so they aren't gathered every run.
4. **Mitogen**: Use the Mitogen plugin to replace the Ansible execution engine for massive speed gains (Tradeoff: Compatibility issues with some modules).

**A19**: 
- `{{ }}`: Variable interpolation.
- `{% %}`: Control structures (loops, ifs).
- `{# #}`: Comments.
**Snippet**:
```jinja2
upstream backend_servers {
{% for host in groups['webservers'] %}
  # Health check for {{ host }}
  server {{ hostvars[host]['ansible_default_ipv4']['address'] }}:80;
{% endfor %}
}
```

**A20**:
1. **Serial**: Set `serial: 20%` to update in batches.
2. **Pre-task**: Use `uri` or a LB module to mark the current node as "down" (drain).
3. **Deployment**: Update the app code/service.
4. **Health Check**: Use `uri` module in a `until` loop to verify the app returns 200 OK.
5. **Post-task**: Mark node as "up" in LB.
6. **Rollback**: Wrap the deployment in a `block`. In the `rescue` section, trigger a task to revert the app version and notify the team.
