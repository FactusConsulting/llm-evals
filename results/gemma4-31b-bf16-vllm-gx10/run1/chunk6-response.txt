## JavaScript / TypeScript

**JS1**: `var` is function-scoped and hoisted (initialized as `undefined`). `let` and `const` are block-scoped and exist in a "Temporal Dead Zone" until declared. `const` prevents reassignment. **Hoisting** is the JS engine's behavior of moving declarations to the top of their scope during the compilation phase.

**JS2**: The **Event Loop** manages the execution of code. The **Call Stack** handles synchronous tasks. When an async task finishes, it enters a queue. **Microtasks** (Promises, `queueMicrotask`) have priority and are drained entirely before the loop moves to the **Macrotask queue** (setTimeout, setInterval, I/O).

**JS3**: A **Closure** is a function that remembers its lexical scope even when executed outside that scope. *Example*: A counter function returning an inner function that increments a private variable. *Bug*: Using `var` in a `for` loop creates one variable for all iterations. *Fix*: Use `let` (block-scoped) or an IIFE.

**JS4**: `Promise` represents a future value. `async/await` is syntactic sugar for Promises. Error handling: `.catch()` for Promises, `try/catch` for `await`. `Promise.all` rejects immediately if any promise fails; `Promise.allSettled` waits for all to complete regardless of outcome.

**JS5**: `interface` is primarily for defining object shapes and supports "declaration merging." `type` is a union/alias for any type (primitives, unions, tuples). Use `interface` for public APIs/classes; `type` for complex logic. **Discriminated Unions** use a common literal property (e.g., `kind: 'circle' | 'square'`) to allow TS to narrow types in a switch/if block.

**JS6**: JS uses **Prototypal Inheritance**: objects inherit directly from other objects via a prototype chain. `Object.create(proto)` creates a new object with `proto` as its prototype. ES6 `class` is "syntactic sugar" over prototypes; `extends` sets the prototype of the class prototype.

**JS7**: `this` refers to the execution context. **Binding Rules**: 1. `new` binding, 2. Explicit (`call`, `apply`, `bind`), 3. Implicit (object method), 4. Default (global/undefined). `bind()` returns a new function with `this` locked. It cannot be re-bound.

**JS8**: `WeakRef` allows holding a reference to an object without preventing GC. `FinalizationRegistry` triggers a callback after an object is GC'd. `WeakMap` keys must be objects because the map holds a "weak" reference to the key; if the key object is deleted elsewhere, the entry is GC'd.

**JS9**: V8 uses **Hidden Classes** (shapes) to optimize property access. **Inline Caching** remembers where properties were found in previous lookups. **Deoptimization** occurs when a "speculative" optimization fails (e.g., changing the type of a variable). *Patterns*: Changing object shapes (adding properties in different orders) or polymorphic functions.

**JS10**: **Tree-shaking** is the removal of unused code. ES Modules (`import/export`) are statically analyzable, allowing tools (Webpack/Rollup) to see what isn't used. CommonJS (`require`) is dynamic (can be inside an `if`), making it impossible to determine usage without running the code.

**JS11**: `undefined` means a variable was declared but not assigned; `null` is an intentional absence of value. `==` performs type coercion (null == undefined is true); `===` checks type and value. `??` (nullish coalescing) returns the RHS only if LHS is `null` or `undefined`. `?.` (optional chaining) short-circuits to `undefined` if a property in the chain is nullish.

**JS12**: `map()` transforms each element; `filter()` removes elements based on a predicate; `reduce()` aggregates an array into a single value. If an initial value is provided to `reduce()`, it's used as the first accumulator; otherwise, the first element of the array is used. `flatMap()` maps then flattens one level; useful for removing elements or expanding one element into many.

**JS13**: **Template literals** use backticks (`` ` ``) for interpolation. **Tagged templates** are functions that parse a template literal. *Example*: `sql`tag`SELECT * FROM users WHERE id = ${id}`. The function receives the string parts and the interpolated values separately, allowing it to escape the values to prevent SQL injection.

**JS14**: **Destructuring** unpacks values from arrays/objects. *Object*: `const {name, age = 20} = user;`. *Array*: `const [first, second] = list;`. *Renaming*: `const {name: userName} = user;`. The **rest operator** (`...`) collects remaining elements into a new array/object.

**JS15**: `for...in` iterates over enumerable **keys** (strings) of an object (including inherited ones). `for...of` iterates over **values** of iterable objects (Arrays, Maps, Sets). Avoid `for...in` on arrays because it iterates over indices as strings and may include custom properties added to the Array prototype.

**JS16**: **Generics** allow components to work with multiple types. **Constraints**: `<T extends string>` ensures T is a string or subtype. **Conditional Types**: `T extends U ? X : Y` chooses a type based on a condition. **Infer**: `type ReturnType<T> = T extends (...args: any[]) => infer R ? R : any` extracts a type from another.

**JS17**: **CommonJS** (CJS) uses `require`/`module.exports` (synchronous). **ES Modules** (ESM) use `import`/`export` (asynchronous/static). Node.js handles both; `.mjs` is ESM, `.cjs` is CJS. `"type": "module"` in `package.json` treats all `.js` files in that directory as ESM.

**JS18**: **Structural Typing** (Duck Typing) means if two types have the same members, they are compatible. **Excess Property Checks** occur when assigning an object literal directly to a type; they prevent typos. `extends` checks if a type is a subtype; `satisfies` validates a type without changing the inferred type of the variable. **Variance**: Covariance (out) allows subtypes; Contravariance (in) allows supertypes.

**JS19**: `Proxy` wraps an object to intercept operations (get, set, apply). `Reflect` provides methods that mirror Proxy traps. *Example*: A validation proxy that throws an error if a `set` operation attempts to assign a negative number to an `age` property.

**JS20**: `SharedArrayBuffer` provides memory shared between the main thread and Web Workers. `Atomics` ensures thread-safe operations (e.g., `Atomics.add`) to prevent race conditions. `Atomics.wait` puts a thread to sleep until a value changes, and `Atomics.notify` wakes it up.

## Bash

**B1**: `$*` and `$@` both represent all positional parameters. In double quotes: `"$*"` is one single string (joined by first char of IFS); `"$@"` is a list of separate strings (preserving original arguments).

**B2**: `set -e`: Exit immediately if a command fails. `set -u`: Treat unset variables as an error. `set -o pipefail`: Return the exit code of the last command in a pipe that failed, rather than the last command in the pipe.

**B3**: `$(command)` is the modern syntax for command substitution; `` `command` `` is the legacy version (harder to nest). `$((expression))` is for integer arithmetic; `expr` is an external utility that is slower and has more complex escaping rules.

**B4**: **Process Substitution** `<(command)` makes the output of a command appear as a file. *Example*: `diff <(ls dir1) <(ls dir2)` compares the output of two commands without creating temporary files.

**B5**: Use `while IFS= read -r line; do ... done < "file.txt"` or `find . -print0 | xargs -0`. `for f in $(ls)` is dangerous because it splits on any whitespace, breaking filenames with spaces.

**B6**: **Here-doc** (`<<EOF`) redirects a multi-line block of text to a command. **Here-string** (`<<<"string"`) passes a single string to stdin. `<<-EOF` strips leading tabs from the input lines, allowing indentation in scripts.

**B7**: 1. `cmd > file 2>&1`: Stdout goes to file, then stderr is redirected to where stdout is currently going (the file). 2. `cmd 2>&1 > file`: Stderr goes to current stdout (terminal), then stdout is redirected to file. Result: stderr stays on terminal. 3. `cmd &> file`: Shorthand for redirecting both to file.

**B8**: Use `mkdir lockdir` because it is an atomic operation at the OS level.
```bash
lock() {
  until mkdir /tmp/mylock 2>/dev/null; do sleep 1; done
  trap 'rmdir /tmp/mylock; exit' INT TERM EXIT
}
```
`mkdir` is preferred over `touch` because two processes can `touch` the same file, but only one can `mkdir` a directory that doesn't exist.

**B9**: `'...'` (Single): Literal string, no expansion. `"..."` (Double): Allows variable/command expansion. No quotes: Subject to word splitting and globbing. *Example*: `echo "$VAR"` vs `echo '$VAR'`.

**B10**: `-f` (file exists), `-d` (is directory), `-r` (is readable). `[ ]` is the POSIX standard `test` command. `[[ ]]` is a Bash extension that supports regex (`=~`), logical operators (`&&`, `||`) without escaping, and doesn't require quoting variables to prevent word splitting.

**B11**: `$?`: Exit status of last command. `$$`: PID of current shell. `$!`: PID of last background process. `$#`: Number of arguments passed to script.

**B12**: `foo() { ... }` is the standard way. `function foo { ... }` is a Bash-specific keyword. Functions return an exit status (0-255) via `return`. To return data, use `echo` and capture it with command substitution.

**B13**: `PATH` is a colon-separated list of directories the shell searches for executables. **Builtins** (e.g., `cd`) run inside the shell; **External** (e.g., `ls`) are separate binaries. Use `type -a command` to check.

**B14**: `trap 'handler' SIGNAL` catches signals. `EXIT` runs when the script ends. `ERR` runs on command failure. `INT` (Ctrl+C), `TERM` (kill). If multiple signals arrive, they are queued; the trap for the current signal executes first.

**B15**: Command substitution `$(...)` loads the whole output into memory. `xargs` reads from stdin and executes commands. `find -print0 | xargs -0` uses the null character as a delimiter to handle spaces/newlines. `xargs -P N` runs N processes in parallel.

**B16**: **Indexed**: `arr=(a b c)`, append `arr+=("d")`, length `${#arr[@]}`, iterate `for i in "${arr[@]}"`. **Associative**: `declare -A map`, `map[key]="val"`, iterate `for k in "${!map[@]}"`. Associative arrays require Bash 4.0+.

**B17**: `(...)` (Subshell) forks a new process; variables changed inside are lost. `{ ...; }` (Group) runs in the current shell; variables persist. Piping into a `while` loop (`cmd | while...`) creates a subshell, so variables modified inside the loop are lost after the loop ends.

**B18**: `SIGINT`: Interrupt (Ctrl+C). `SIGTERM`: Polite request to stop. `SIGHUP`: Terminal closed. `SIGKILL`: Immediate forced stop (cannot be trapped). For graceful shutdown: `trap 'kill $(jobs -p); exit' SIGTERM`.

**B19**:
```bash
split -l 1000 log.txt part_
ls part_* | xargs -P 4 -I {} bash -c 'process_func {} > {}.out'
cat *.out > final_result
```
*Trade-offs*: Disk I/O for split files vs memory. *Errors*: Use `set -e` inside the processing function and check exit codes of `xargs`.

**B20**: `exec` replaces the current shell process with the new command. For FDs: `exec 3>file` opens FD 3 for writing; `exec 3>&-` closes it. A **coprocess** (`coproc cmd`) runs a command in the background with two-way communication via pipes (`${COPROC[0]}` and `${COPROC[1]}`).

## PowerShell

**PS1**: `Write-Output` sends objects to the pipeline (can be captured/processed). `Write-Host` writes directly to the console (cannot be captured). Using `Write-Host` in a pipeline "swallows" the data, preventing downstream cmdlets from receiving it.

**PS2**: The pipeline passes **objects**, not text. `ForEach-Object` is a cmdlet that processes items one-by-one as they arrive (streaming). `foreach` is a language statement that requires the entire collection to be in memory first. Use `ForEach-Object` for large datasets.

**PS3**: `[hashtable]` is a key-value pair collection (unordered). `[PSCustomObject]` is a structured object with properties. Use hashtables for lookups; PSCustomObjects for data records. Convert: `[PSCustomObject]$hash` or `New-Object PSObject -Property $hash`.

**PS4**: **Non-terminating** errors (e.g., `Get-Item` on a missing file) allow the script to continue. **Terminating** errors stop execution. `-ErrorAction Stop` turns a non-terminating error into a terminating one, allowing it to be caught by a `try/catch` block. `$ErrorActionPreference` sets the global default.

**PS5**: **Splatting** passes a hashtable of parameters to a cmdlet using `@`.
*Example*: `$params = @{ Path = 'C:\'; Recurse = $true }; Get-ChildItem @params`.
Unlike passing a hashtable as a single parameter, splatting expands the hashtable into individual named arguments.

**PS6**: `Invoke-Command` runs a script block on remote machines and returns results. `Enter-PSSession` creates an interactive shell. It uses **WinRM** (WS-Man) by default on Windows, but PowerShell 7+ supports **SSH** for cross-platform remoting.

**PS7**: PowerShell "unrolls" collections. If a function returns an array, the pipeline flattens it.
In the example: `$x` will be a `String` (if one item) or `Object[]` (if multiple). If 0 items, it returns `$null`.
*Correct pattern*: Use `Write-Output` and wrap the result in `@()` at the call site to ensure an array.

**PS8**: A `[scriptblock]` is a piece of code `{ ... }` that can be passed as an object. Functions are named scriptblocks. **Double-hop**: A remote session cannot pass credentials to a *second* remote machine. Solve via **CredSSP** (delegation) or passing credentials explicitly via `-ArgumentList`.

**PS9**: `@()` is the array sub-expression operator; `[array]` is the type accelerator. `@(Get-Item ...)` forces the result into an array even if only one item is returned. Indexing into `$null` returns `$null` (no error), whereas indexing an empty array also returns `$null`.

**PS10**: `-eq` (equal), `-ne` (not equal), `-like` (wildcards `*`), `-match` (regex), `-contains` (collection contains value), `-in` (value is in collection). Case-sensitive versions start with `c` (e.g., `-ceq`). `-contains` is `Collection -contains Value`; `-in` is `Value -in Collection`.

**PS11**: A module is a package of functions/variables. `.psm1` contains the code; `.psd1` is a manifest (metadata, versioning). Binary modules are compiled .dlls. `Import-Module` loads the module into the current session.

**PS12**: Double quotes `"..."` allow interpolation; single quotes `'...'` are literal. Use `"$($expression)"` (sub-expression) for complex logic inside strings. **Here-strings** (`@" ... "@`) allow multi-line strings without escaping quotes.

**PS13**: `Get-Member` shows the properties and methods of an object. **Properties** are data; **Methods** are actions; **NoteProperties** are dynamically added properties. `Select-Object` filters *properties* (columns); `Where-Object` filters *objects* (rows).

**PS14**: PS Classes are simplified versions of C# classes. They support basic inheritance and constructors but lack interfaces and advanced generics. Use a **class** for complex data structures/state; use a **function** for procedural tasks.

**PS15**: `[CmdletBinding()]` makes a function an "Advanced Function," enabling common parameters like `-Verbose` and `-ErrorAction`. `SupportsShouldProcess` enables `-WhatIf` and `-Confirm`. `Begin` runs once at start, `Process` runs for every pipeline object, `End` runs once at the end.

**PS16**: Providers map different data stores to a drive-like interface. `Get-ChildItem` works on `FileSystem:\`, `HKLM:\` (Registry), `Cert:\` (Certificates), and `Env:\` (Environment variables). You access the registry as if it were a folder: `cd HKLM:\Software`.

**PS17**: A `Runspace` is an isolated execution environment (thread). `RunspacePool` manages multiple runspaces. `ForEach-Object -Parallel` (v7+) simplifies this by managing a pool automatically. Manual runspace management is used for complex, long-running asynchronous tasks.

**PS18**: **PSScriptAnalyzer** is a static code analysis tool. It uses **Rules** (e.g., "Avoid using Write-Host") with **Severity** (Error, Warning, Info). Suppress rules using `[Diagnostics.CodeAnalysis.SuppressMessageAttribute()]`. It integrates into CI/CD via `Invoke-ScriptAnalyzer`.

**PS19**: `$using:var` is used in `Invoke-Command` or `-Parallel` to pull a local variable into the remote/parallel scope. `-ArgumentList` passes values as a positional array. **Serialization**: Objects are converted to CLIXML; deep or complex objects (like active DB connections) cannot be serialized and will be "deserialized" as static snapshots.

**PS20**: **DSC** is a declarative system to ensure a machine is in a specific state. **Configurations** define the state; **Resources** implement the logic; the **LCM** (Local Configuration Manager) is the engine that applies and monitors the state. In PS 7+, DSC is moving toward a cross-platform version (DSCv3) and is largely superseded by tools like Terraform or Ansible for orchestration.
