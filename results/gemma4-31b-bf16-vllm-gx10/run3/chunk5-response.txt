## .NET / C#

**DN1**: A `class` is a reference type (stored on the heap), while a `struct` is a value type (usually stored on the stack). Use a `struct` for small, immutable data structures (typically < 16 bytes) that represent a single value (e.g., `Point`, `ComplexNumber`) to reduce GC pressure.

**DN2**: `IEnumerable<T>` is for in-memory collections; it performs filtering/sorting on the client side (LINQ to Objects). `IQueryable<T>` is for remote data sources; it translates expressions into a provider-specific language (e.g., SQL) to execute the query on the database server. This distinction prevents "over-fetching" data.

**DN3**: `async/await` allows non-blocking asynchronous operations by suspending the method execution until the awaited task completes, freeing the thread to do other work. `Task` is a class (heap allocated); `ValueTask` is a struct. Use `ValueTask` when the result is often available synchronously to avoid unnecessary allocations.

**DN4**: DI is a pattern where dependencies are provided to a class rather than created internally. 
- **Transient**: New instance every time requested.
- **Scoped**: One instance per client request (web request).
- **Singleton**: One instance for the lifetime of the app.
- **Bug**: Injecting a Scoped service into a Singleton causes "Captive Dependency," where the Scoped service is kept alive indefinitely, potentially leading to memory leaks or stale data (e.g., a `DbContext` that never closes).

**DN5**: `string` is an immutable heap object. `ReadOnlySpan<char>` is a stack-allocated view into a contiguous region of memory. Use `Span<T>`/`ReadOnlySpan<T>` for high-performance slicing and parsing to avoid creating multiple substring allocations.

**DN6**: The GC uses a generational approach: **Gen 0** (short-lived), **Gen 1** (buffer), and **Gen 2** (long-lived). The **Large Object Heap (LOH)** handles objects > 85,000 bytes to avoid expensive memory compaction. `IDisposable` is needed for *unmanaged* resources (file handles, sockets) because the GC only manages *managed* memory.

**DN7**: `ConfigureAwait(false)` tells the task not to marshal the continuation back to the original `SynchronizationContext` (e.g., the UI thread). Use it in library code to improve performance and avoid deadlocks. Do NOT use it in application code that needs to access UI elements or `HttpContext.Current`.

**DN8**: 
- **Primary Constructors**: Define parameters directly in the class declaration.
- **Collection Expressions**: `int[] x = [1, 2, 3];`
- **FrozenDictionary**: An immutable dictionary optimized for read-heavy scenarios.
Example:
```csharp
public class OrderService(IDbContext db) { // Primary Constructor
    public void Save() => db.SaveChanges();
}
```

**DN9**: The cause is likely a `DbContext` being shared across multiple threads (e.g., `Task.WhenAll` calling methods that use the same scoped context). `DbContext` is NOT thread-safe. **Fix**: Create a new scope per concurrent task using `IServiceScopeFactory` to provide a dedicated `DbContext` per thread.

**DN10**: `record` is a class with built-in value-based equality. `record struct` is a value type with value-based equality. Use `record` for DTOs/immutable data; `class` for behavior-heavy objects; `record struct` for small, high-performance value objects.

**DN11**: 
- `ref`: Passes by reference; variable must be initialized before passing.
- `out`: Passes by reference; method MUST initialize the variable before returning.
- `in`: Passes by reference but makes it read-only (prevents copying large structs).

**DN12**: Nullable Reference Types (`string?`) are a compile-time static analysis feature to prevent `NullReferenceException`. They do not change the runtime behavior. Nullable Value Types (`int?`) are `Nullable<T>` structs that actually wrap the value and a boolean flag at runtime.

**DN13**: LINQ (Language Integrated Query) provides a consistent way to query data. **Method syntax** uses extension methods (`.Where()`); **Query syntax** looks like SQL (`from x in...`). **Deferred execution** means the query is not executed when defined, but when the sequence is iterated (e.g., via `foreach` or `.ToList()`).

**DN14**: Constraints restrict the types that can be used as generic arguments.
- `class`: Must be a reference type.
- `struct`: Must be a value type.
- `new()`: Must have a public parameterless constructor.
- `IComparable<T>`: Must implement that interface.
Combine them (e.g., `where T : class, new()`) to ensure the type is both a reference type and instantiable.

**DN15**: An `abstract class` can provide implementation and state; an `interface` defines a contract. Default Interface Methods (C# 8+) allow interfaces to provide a default implementation, blurring the line, but interfaces still cannot hold instance state (fields).

**DN16**: Middleware is a sequence of delegates that handle requests/responses.
- `app.Use()`: Can call the next middleware in the pipeline.
- `app.Map()`: Branches the pipeline based on the URL path.
- `app.Run()`: Terminal middleware; stops the pipeline.
Ordering is critical (e.g., Exception Handling must be first to catch errors from subsequent middleware).

**DN17**: `Channel<T>` is a high-performance producer-consumer queue. Unlike `BlockingCollection<T>`, it is fully `async` (non-blocking). 
Example: `Channel.CreateBounded<T>(100)` creates a channel that blocks the producer (via `WriteAsync`) when the buffer is full, providing backpressure.

**DN18**: Source Generators inspect code during compilation and generate additional C# source files. Unlike reflection (runtime) or IL weaving (post-compile), they are type-safe and fast. **Incremental Generators** are preferred because they cache results and only re-run on changed parts of the syntax tree, preventing IDE lag.

**DN19**: TPL Dataflow provides blocks for processing pipelines.
- `ActionBlock`: Consumes data and performs an action.
- `TransformBlock`: Consumes data, transforms it, and outputs it.
- `BufferBlock`: A simple FIFO queue.
Compared to `Channels`, Dataflow is higher-level and better for complex directed graphs of processing steps.

**DN20**: Minimal APIs remove the `Controller` boilerplate, defining endpoints directly in `Program.cs`. 
- **Trade-offs**: Faster startup and less code, but can become cluttered in large apps. 
- **Route Groups**: `app.MapGroup("/api")` allows shared prefixes/auth. 
- **Endpoint Filters**: Allow cross-cutting logic (like validation) to run before/after the handler.

## Python

**P1**: `list` is mutable; `tuple` is immutable. `set` is a mutable collection of unique elements; `frozenset` is an immutable version of a set (and thus hashable).

**P2**: The GIL is a mutex that allows only one thread to execute Python bytecode at a time. It affects CPU-bound workloads. Workarounds: Use `multiprocessing` (separate GILs per process) or C-extensions (like NumPy) that release the GIL.

**P3**: `copy` (shallow) creates a new object but inserts references to the items in the original. `deepcopy` recursively copies everything. 
Example: A list of lists `[[1]]`. A shallow copy of the outer list still shares the inner list; modifying `copy[0][0]` changes the original.

**P4**: Decorators are functions that wrap other functions to modify their behavior.
```python
import time
def log_time(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        res = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start}s")
        return res
    return wrapper
```

**P5**: Generators use `yield` to produce values one at a time (lazy evaluation), saving memory compared to returning a full list. `yield from` allows a generator to delegate part of its operations to another iterable or generator.

**P6**: The event loop manages asynchronous tasks. 
- `asyncio.run()`: Entry point; creates loop and runs the main coroutine.
- `asyncio.gather()`: Runs multiple coroutines concurrently and waits for all.
- `asyncio.create_task()`: Schedules a coroutine to run in the background.
`time.sleep()` is blocking; it stops the entire thread, preventing the event loop from switching tasks. Use `await asyncio.sleep()`.

**P7**: Python uses **C3 Linearization** for MRO. It ensures a consistent order and avoids visiting the same class twice. In the diamond example, `D` inherits from `B` then `C`. Since `B` inherits from `A`, but `C` also inherits from `A`, the order is `D -> B -> C -> A`. `D().who()` prints `"C"` because `C` overrides `A` and comes before `A` in the MRO.

**P8**: A metaclass is a "class of a class" that defines how classes are constructed. 
- `__init_subclass__`: Simpler way to customize class creation for subclasses (e.g., registering a plugin).
- Metaclass: Used for deeper modification (e.g., modifying the class dictionary before creation).
Use case: Metaclass for enforcing API constraints across all subclasses; `__init_subclass__` for simple registry patterns.

**P9**: 
- `threading`: Shared memory, limited by GIL. Use for I/O-bound tasks.
- `multiprocessing`: Separate memory/GIL. Use for CPU-bound tasks.
- `concurrent.futures`: High-level wrapper for both via `ThreadPoolExecutor` and `ProcessPoolExecutor`.
Multiprocessing requires **pickling** (serialization) to send data between processes, which can be slow and fails for some objects (e.g., lambdas).

**P10**: `__slots__` tells Python not to use a dynamic `__dict__` for instances, but a fixed-size array. Use it for classes with millions of instances to significantly reduce memory usage and slightly increase attribute access speed. It prevents adding new attributes at runtime.

**P11**: A virtual environment is an isolated Python installation. Use it to avoid dependency conflicts between projects. 
- `venv`: Built-in, lightweight.
- `virtualenv`: Older, more features.
- `conda`: Manages non-Python dependencies (C libraries) and environments.

**P12**: Comprehensions provide a concise way to create collections. 
- `[x for x in list if cond]` is equivalent to `filter` + `map`.
Prefer comprehensions for readability and speed in most cases; use `map`/`filter` when working with existing functions or infinite iterators.

**P13**: `==` checks for equality of value; `is` checks for identity (same memory address). **Object interning** caches small integers (usually -5 to 256) and certain strings to save memory, which is why `a is b` is True for small ints.

**P14**: `*args` collects extra positional arguments into a tuple; `**kwargs` collects keyword arguments into a dict. 
- `/`: Arguments before it must be positional-only.
- `*`: Arguments after it must be keyword-only.

**P15**: Context managers handle setup/teardown. 
- `__enter__/__exit__`: Class-based approach.
- `@contextmanager`: Generator-based approach using `yield`.
Example: A database transaction manager that commits on success and rolls back on exception.

**P16**: Type hinting provides static metadata. 
- `Union[int, str]`: Either type.
- `Optional[int]`: `Union[int, None]`.
- `Literal["R", "G", "B"]`: Exactly one of these values.
- `TypeVar`: For generic types.
- `Protocol`: For structural subtyping (static duck typing).
Mypy/Pyright analyze these to find bugs without running the code.

**P17**: Dunder methods define object behavior.
- `__repr__` (for developers/debugging) vs `__str__` (for users).
- `__eq__` (equality) vs `__hash__` (for set/dict keys).
- `__getattr__` (called if attribute isn't found) vs `__getattribute__` (called for every access).
If you define `__eq__` but not `__hash__`, the class becomes unhashable (cannot be a dict key).

**P18**: Descriptors are objects that define `__get__`, `__set__`, or `__delete__`. They allow custom logic when accessing attributes. `property` is a descriptor that manages getters/setters; `classmethod` and `staticmethod` are descriptors that modify how the function is bound to the class/instance.

**P19**: Python searches `sys.path` (current dir, PYTHONPATH, stdlib). 
- **Absolute**: `import pkg.mod`. **Relative**: `from . import mod`.
- `__init__.py`: Marks a directory as a package (optional in Python 3.3+ for namespace packages).
- **Finder**: Locates the module. **Loader**: Loads the module into memory.

**P20**: `dataclasses` automate `__init__`, `__repr__`, and `__eq__`. 
- `__post_init__`: Logic after initialization.
- `field(default_factory=list)`: Prevents mutable default argument bugs.
- `frozen=True`: Makes the instance immutable.
**Pydantic** is preferred over dataclasses when **runtime data validation** and coercion (e.g., parsing JSON strings to ints) are required.
