## Kubernetes

**K1** — **Deployment** is for stateless apps; pods are interchangeable and have random hashes in their names. **StatefulSet** is for stateful apps; pods have sticky identities (pod-0, pod-1), ordered deployment/scaling, and stable network IDs.

**K2** — It uses a virtual IP. The `kube-proxy` on each node manages `iptables` or `IPVS` rules that intercept traffic to the ClusterIP and load-balance it across the Pod IPs listed in the Service's `Endpoints` object.

**K3** — **PV** is the actual storage resource (the "disk"). **PVC** is a user's request for storage (the "ticket"). **StorageClass** is a template for dynamic provisioning (the "menu"). Relation: PVC requests a specific size/access mode $\rightarrow$ StorageClass provisions a PV $\rightarrow$ PV is bound to the PVC.

**K4** — 1. `kubectl logs <pod>` (check app crash logs). 2. `kubectl logs <pod> --previous` (check why the last instance died). 3. `kubectl describe pod <pod>` (check for OOMKilled, Liveness probe failures, or ImagePullBackOff). 4. `kubectl exec` (if it stays up briefly) to check config/env vars.

**K5** — CoreDNS provides service discovery (mapping service names to IPs). If CoreDNS is down, pods cannot resolve internal service names (e.g., `my-db.namespace.svc.cluster.local`) or external domains, causing application failures.

**K6** — **Filtering:** Removes nodes that don't meet requirements (e.g., insufficient CPU/RAM, Taints, NodeSelector). **Scoring:** Ranks remaining nodes based on "best fit." **Factors:** 1. Resource availability (LeastRequestedPriority). 2. Image locality (does the node already have the image?). 3. Inter-pod affinity/anti-affinity.

**K7** — **Scheduling:** No. The node has 500Mi available (4GB - 3.5GB), but the pod requests 256Mi. While it fits, if other pods are scheduled simultaneously, it might fail. However, strictly speaking, 256Mi < 500Mi, so it *will* be scheduled. **Runtime:** If it hits 600Mi, it exceeds its `limit` (512Mi) and will be **OOMKilled** by the kernel.

**K8** — External LB $\rightarrow$ Ingress Controller (NGINX) $\rightarrow$ NGINX reads Ingress rules $\rightarrow$ NGINX looks up the **Endpoints** (Pod IPs) for the Service $\rightarrow$ NGINX forwards traffic directly to a Pod IP (bypassing the Service ClusterIP/kube-proxy for efficiency).

**K9** — A firewall for pods. **Default:** All traffic is allowed. **Applying one:** Once a NetworkPolicy selects a pod, that pod becomes "isolated"; it will drop all traffic not explicitly allowed by the policy.

**K10** — **RollingUpdate:** Gradually replaces old pods with new ones (zero downtime). **Recreate:** Kills all old pods before starting new ones. **Choose Recreate** when the app doesn't support two versions running simultaneously (e.g., breaking database schema changes).

**K11** — A logical partition of a cluster for resource isolation. Defaults: `default` (user apps), `kube-system` (cluster components), `kube-public` (publicly visible), `kube-node-lease` (heartbeats).

**K12** — Used for detailed debugging. It shows: 1. **Events** (e.g., failed scheduling, pulling image). 2. **Container status** (restart count, exit codes). 3. **Resource limits/requests** and Volume mounts.

**K13** — A key-value store for non-confidential config. Consumption: 1. As **environment variables** (injected at startup). 2. As **files in a volume** (mounted as a directory).

**K14** — **ClusterIP:** Internal IP only (internal communication). **NodePort:** Exposes service on a static port on every Node IP (external access). **LoadBalancer:** Provisions a cloud provider LB that routes to NodePorts (production external access).

**K15** — A controller that ensures one copy of a pod runs on every node (or a subset). Use for: Log collectors (Fluentd), Monitoring agents (Prometheus Node Exporter), or CNI plugins.

**K16** — **Taints/Tolerations:** Applied to *Nodes* to repel pods. **Node Affinity:** Applied to *Pods* to attract them to nodes. **Use cases:** Taint a node as "GPU-only" so only GPU-pods (with tolerations) land there. Use Affinity to ensure a pod lands in "Zone-A" for low latency.

**K17** — An Operator is a custom controller using **CRDs** (Custom Resource Definitions) to manage complex stateful apps. It encodes "human operational knowledge" into code. It solves the problem of automating complex day-2 operations (backups, upgrades) that standard controllers can't handle.

**K18** — **Consistency:** Raft consensus (Strong consistency). **Quorum loss:** The cluster becomes read-only or completely unavailable; the API server cannot write state. **Recovery:** If 2/3 are lost, you must restore from a backup or force a new cluster with a single member using `--force-new-cluster`.

**K19** — RBAC controls "who" (Subject) can do "what" (Verb) to "which" (Resource). **Role:** Namespace-scoped. **ClusterRole:** Cluster-wide. **RoleBinding:** Links Subject to Role in a namespace. **ClusterRoleBinding:** Links Subject to ClusterRole cluster-wide.
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { namespace: dev, name: pod-reader }
rules: [{ apiGroups: [""], resources: ["pods", "pods/log"], verbs: ["get", "list", "watch"] }]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { namespace: dev, name: read-pods-binding }
subjects: [{ kind: User, name: "developer", apiGroup: rbac.authorization.k8s.io }]
roleRef: { kind: Role, name: pod-reader, apiGroup: rbac.authorization.k8s.io }
```

**K20** — `ndots:5` means if a name has fewer than 5 dots, K8s tries internal search paths first (e.g., `google.com.default.svc.cluster.local`) before trying the external DNS. This causes 4-5 failed queries per request. **Fix:** Set `dnsConfig` in pod spec: `dnsConfig: { options: [{ name: "ndots", value: "1" }] }`.

## Development

**D1** — **Merge** creates a new "merge commit" preserving history exactly as it happened. **Rebase** rewrites history by moving your commits to the tip of the target branch (linear history). **Avoid rebasing** public/shared branches, as it breaks other developers' histories.

**D2** — **TCP:** Connection-oriented, reliable, ordered (e.g., HTTP, SSH). **UDP:** Connectionless, unreliable, fast (e.g., DNS, DHCP/Streaming).

**D3** — When two or more threads access shared data and try to change it at the same time. **Example:** Two threads incrementing a counter `x = x + 1`. Both read `x=10`, both calculate `11`, both write `11`. The result is `11` instead of `12`.

**D4** — **Symmetric:** Same key for encrypt/decrypt (Fast, e.g., AES). **Asymmetric:** Public key encrypts, Private key decrypts (Slow, e.g., RSA). **TLS:** Asymmetric encryption is used for the initial handshake to securely exchange a symmetric "session key," which is then used for the actual data transfer.

**D5** — A layer is a read-only snapshot of the filesystem changes from a Dockerfile instruction. **Caching:** Docker reuses layers if the instruction and files haven't changed. **Best Practice:** Put infrequently changed instructions (OS updates) at the top and frequently changed ones (source code) at the bottom.

**D6** — 1. **Load Balancer/Ingress logs:** Check if the 503 is coming from the LB or the app. 2. **Pod Health/Restarts:** Check for OOMKills or CrashLoops. 3. **Downstream Dependencies:** Check if the DB or a 3rd party API is timing out. 4. **Resource Saturation:** Check CPU/Memory usage on the pods.

**D7** — **CAP:** In a network partition (P), you must choose between Consistency (C) or Availability (A). **CP (Consistency):** MongoDB (default) or etcd; they stop accepting writes if quorum is lost. **AP (Availability):** Cassandra or DynamoDB; they allow writes to any node and resolve conflicts later.

**D8** — **Horizontal:** Adding more machines (scaling out). **Vertical:** Adding more CPU/RAM to one machine (scaling up). **Patterns:** Statelessness (no local session), Load Balancing, and Distributed Caching.

**D9** — A dynamic-named value that can affect the way running processes behave. **Persistence:** Add `export VAR_NAME=value` to the `~/.bashrc` or `~/.zshrc` file.

**D10** — **JSON:** Strict, bracket-based, widely supported by APIs. **YAML:** Indentation-based, human-readable, supports comments. **Advantage:** JSON is faster for machines to parse; YAML is easier for humans to write/edit (configs).

**D11** — **REST:** An architectural style for networked apps using HTTP. **GET:** Retrieve data. **POST:** Create data. **PUT:** Update/Replace data. **DELETE:** Remove data.

**D12** — Specifying the exact version of a library (e.g., `requests==2.25.1` instead of `requests>=2.0`). **Importance:** Prevents "it works on my machine" bugs caused by a dependency releasing a breaking change in a newer version.

**D13** — **Compiled:** Translated to machine code before execution (Fast, e.g., C++, Rust). **Interpreted:** Read and executed line-by-line by another program (Flexible, e.g., Python, Ruby).

**D14** — **Forward Proxy:** Sits in front of clients to hide them/filter outgoing traffic. **Reverse Proxy:** Sits in front of servers to protect them/load balance. **Examples:** 1. NGINX (Load balancing/SSL termination). 2. HAProxy (High-performance TCP/HTTP routing).

**D15** — A state where two or more threads are blocked forever, each waiting for the other. **Coffman Conditions:** 1. Mutual Exclusion. 2. Hold and Wait. 3. No Preemption. 4. Circular Wait.

**D16** — The guarantee that if no new updates are made, eventually all accesses will return the last updated value. **Cassandra:** Uses "Tunable Consistency." You can set `Write=QUORUM` and `Read=QUORUM` to achieve strong consistency (Read-after-write), or `Write=ONE` for high availability/low latency.

**D17** — **mTLS:** Both client and server present certificates. **Handshake:** 1. Server sends cert $\rightarrow$ Client verifies. 2. Server requests client cert $\rightarrow$ Client sends cert $\rightarrow$ Server verifies. 3. Both derive a session key. **Usage:** Service Mesh (Istio/Linkerd) for zero-trust internal communication.

**D18** — Uses a hash function to map keys to array indices. **Collisions:** **Chaining** (linked list at each index) or **Open Addressing** (find next empty slot). **Complexity:** Average: $O(1)$ for all. Worst: $O(n)$ (if all keys hash to the same index).

**D19** — Prevents a failing service from dragging down others. **States:** **Closed** (Traffic flows), **Open** (Fail fast, no traffic), **Half-Open** (Test a few requests). **Relation:** Retries with exponential backoff handle *transient* faults; Circuit Breakers handle *persistent* faults to prevent cascading failure.

**D20** — **Optimistic:** Assume no conflict; check for changes at commit time (e.g., using a `version` column). Use for low-contention. **Pessimistic:** Lock the record immediately (e.g., `SELECT ... FOR UPDATE`). Use for high-contention/critical financial data.
