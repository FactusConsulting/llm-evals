### Risks and Prerequisites

**Key Risks**
* **Breaking Changes:** Potential incompatibility with existing extensions or deprecated SQL syntax/parameters in Postgres 16.
* **Downtime:** Managed upgrades on DigitalOcean involve service restarts and failover, causing temporary unavailability.
* **Driver Compatibility:** Ensuring `psycopg2 2.9.3` maintains full compatibility with the Postgres 16 wire protocol.
* **Data Integrity:** Risk of corruption during the managed upgrade process.

**Prerequisites**
* **Extension Audit:** Verify all installed extensions (e.g., `pg_stat_statements`, `postgis`) are compatible with Postgres 16.
* **Driver Validation:** Confirm `psycopg2 2.9.3` functions correctly with PG 16 in a local environment.
* **Backup:** Ensure a recent, successful manual snapshot of the production database exists.
* **Upgrade Path:** Confirm DigitalOcean supports a direct 14 $\rightarrow$ 16 upgrade; if not, plan for an intermediate upgrade to 15.

### Migration Plan

1. Audit all currently installed database extensions and their versions.
2. Create a manual snapshot of the production database via the DigitalOcean dashboard.
3. **[Human Approval]** Define and approve the maintenance window and downtime duration.
4. Provision a staging database instance by cloning the production database.
5. Perform the upgrade to Postgres 16 on the staging instance.
6. Deploy a test version of the payments service in a Kubernetes staging namespace connected to the staging database.
7. Execute the full application test suite against the staging environment.
8. **[Human Approval]** Review staging test results and approve the production upgrade.
9. **[External Coordination]** Notify stakeholders of the upcoming service interruption.
10. Scale the payments service Kubernetes deployment to 0 replicas to prevent data drift.
11. Initiate the Postgres 16 upgrade via the DigitalOcean control panel.
12. Monitor the upgrade status until the instance returns to "Running" state.
13. Verify database connectivity and confirm the version via `SELECT version();`.
14. Run database integrity checks and verify extension functionality.
15. Scale the payments service Kubernetes deployment back to the required replica count.
16. Execute smoke tests on the live service to ensure end-to-end connectivity.
17. **[Human Approval]** Final sign-off and closure of the maintenance window.
