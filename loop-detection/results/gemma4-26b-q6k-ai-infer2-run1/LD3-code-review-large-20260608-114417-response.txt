Request Changes

**Issues:**
- **Bug (Goroutine Leak):** `cache/cache.go:30`: The background goroutine spawned in `New` runs an infinite loop with no way to signal its termination. This causes a goroutine leak if multiple `Cache` instances are created and discarded. Add a `Close()` method to gracefully shut down the eviction loop.
- **Performance (Lock Contention):** `cache/cache.go:49-57`: The `evict` function holds the mutex lock while iterating over the entire map. In a production environment with many entries, this will block all other operations (`Get`, `Set`, `Delete`) for the duration of the cleanup, leading to high tail latency.

**Nits:**
- Use `sync.RWMutex` instead of `sync.Mutex` to allow concurrent calls to `Get`.
- The eviction interval is hardcoded to one minute; consider making this configurable via `New`.
- Implement the cache using Go generics (e.g., `Cache[K comparable, V any]`) rather than `interface{}` to improve type safety.
