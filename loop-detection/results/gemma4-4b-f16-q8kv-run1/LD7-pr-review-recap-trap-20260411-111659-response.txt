*   The `jwtSecret` is generated randomly within `init()`. This means that upon every application restart, the secret changes, rendering all previously issued tokens immediately invalid. How is this secret securely managed and persisted across deployments?
*   The implementation includes `GenerateRefreshToken()`, but there is no corresponding logic shown for storing, validating, or revoking these refresh tokens. What is the intended persistence mechanism for refresh tokens, and how will token revocation be handled?
*   The token expiration time is hardcoded to 24 hours in `IssueToken`. Should this duration be configurable via environment variables or configuration files?
*   In `AuthMiddleware`, the extraction relies on `strings.TrimPrefix(authHeader, "Bearer ")`. If the header is present but does not start with "Bearer ", how is this edge case handled before calling `ValidateToken`?
*   When `ValidateToken` returns an error, the middleware returns a generic "unauthorized" 401. Are there specific token validation errors (e.g., expired vs. invalid signature) that should result in different HTTP status codes or logging treatments?
