*   The `jwtSecret` is generated randomly during `init()`. What is the strategy for managing this secret across deployments, as a restart will invalidate all existing tokens?
*   The token expiration is hardcoded to 24 hours. Is there a mechanism to configure this duration, and how is the refresh token flow intended to handle token expiry?

*   In `AuthMiddleware`, the extraction relies on `strings.TrimPrefix`. Is there explicit validation to ensure the header starts exactly with "Bearer " before trimming, to prevent unexpected behavior with malformed headers?
*   When `ValidateToken` fails, the middleware returns a generic `401 Unauthorized`. Should different validation failures (e.g., expired token vs. invalid signature) map to distinct HTTP status codes for better client diagnostics?
*   What is the established pattern for accessing the `userID` and `role` values stored in the request context downstream? Is there a defined context key type or accessor function?
