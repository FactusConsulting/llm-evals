**Issues:**
- `cache/cache.go:21`: **Goroutine Leak.** The `evict` goroutine runs an infinite loop with no mechanism (such as a `context.Context` or a `stop` channel) to terminate. This prevents the `Cache` instance from being properly cleaned up and will cause a leak of goroutines if `New` is called repeatedly.
- `cache/cache.go:53`: **Lock Contention.** The `evict` method holds the `c.mu.Lock()` for the entire duration of the map iteration. For a large number of entries, this will block all `Get`, `Set`, and `Delete` operations for a significant period, causing high latency spikes.
- `cache/cache.go:36`: **Memory Inefficiency.** The `Get` method identifies expired entries but does not remove them from the map. This causes expired entries to persist in memory until the next `evict` cycle, which only occurs once per minute.
