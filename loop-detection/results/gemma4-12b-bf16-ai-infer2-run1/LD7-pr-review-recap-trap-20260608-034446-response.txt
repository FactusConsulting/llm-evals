### PR Review

**Critical Issues & Risks:**

*   **Secret Persistence and Horizontal Scaling:** The `jwtSecret` is generated randomly at runtime during `init()`. This will cause immediate authentication failures in any production environment with multiple instances or during service restarts. Each instance will have its own unique secret, making it impossible for Instance A to validate a token issued by Instance B. We need to load this from an environment variable or a Secret Manager.
*   **Lack of Revocation Mechanism:** By removing Redis, we lose the ability to invalidate sessions immediately. Since JWTs are stateless, there is currently no way to "log out" a user or revoke a compromised token before the 24-hour expiration. How do we plan to handle forced logouts or account suspensions?
*   **Refresh Token Storage:** You've introduced `GenerateRefreshToken`, but there is no logic provided for where these refresh tokens are stored or validated. If we are moving away from Redis entirely, how are these being persisted?
*   **Context Key Collisions:** Using raw strings like `"userID"` and `"role"` as context keys is prone to collisions with other middlewares or libraries. These should be defined as private types (e.g., `type ctxKey int`) to ensure uniqueness.
*   **Hardcoded Expiration:** The 24-hour expiration in `IssueToken` is hardcoded. This should be configurable via configuration files/environment variables to allow for different TTLs based on user roles or security requirements.

**Questions & Suggestions:**

*   **Signing Algorithm:** Given that we are refactoring auth, have we considered using RS256 (asymmetric) instead of HS256? Asymmetric signing allows other microservices to validate tokens using a public key without needing access to the private signing key.
*   **Error Logging:** In `AuthMiddleware`, both a missing header and an invalid token return a generic "unauthorized" error. While this is good for external responses, do we have internal logging to distinguish between a malformed request and a signature mismatch for debugging purposes?
*   **Entropy Check:** In `init()`, there is no check on whether `rand.Read(jwtSecret)` succeeded. Although unlikely to fail, it's best practice to handle potential errors during secret initialization.
