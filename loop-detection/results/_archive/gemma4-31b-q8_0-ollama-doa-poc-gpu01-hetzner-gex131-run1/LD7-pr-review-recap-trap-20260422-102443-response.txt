**auth/jwt.go**

*   **Secret Volatility:** The `jwtSecret` is generated randomly in `init()`. This causes two critical issues:
    1.  All active tokens are invalidated every time the server restarts.
    2.  In a distributed environment with multiple instances, tokens issued by one instance will be rejected by others because each instance has a unique secret. This should be loaded from a secure environment variable or secret manager.
*   **Lack of Revocation:** By removing the Redis session store and moving to stateless JWTs, there is no mechanism to revoke a token (e.g., during logout or if a token is compromised) before the 24-hour expiration.
*   **Refresh Token Orphanage:** `GenerateRefreshToken` is implemented, but there is no logic to store, track, or validate these tokens. If they are not stored in a database/cache, they cannot be used to securely issue new access tokens.
*   **Hardcoded Expiration:** The 24-hour expiration is hardcoded. This should be configurable to allow for security tuning without code changes.

**auth/middleware.go**

*   **Context Key Collisions:** Using raw strings (`"userID"`, `"role"`) as context keys can lead to collisions. Use unexported custom types for context keys.
*   **Fragile Header Parsing:** `strings.TrimPrefix` does not verify that the `Authorization` header actually starts with `"Bearer "`. If the prefix is missing, the code will attempt to validate the entire header string as a JWT, which may lead to confusing error messages or unexpected behavior.
