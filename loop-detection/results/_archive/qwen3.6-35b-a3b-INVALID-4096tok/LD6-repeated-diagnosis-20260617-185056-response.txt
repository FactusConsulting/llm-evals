**Diagnosis:** The service is failing because it starts before DNS resolution is available. The `ping` output confirms `kafka.internal` cannot be resolved, and the journal shows the application exits fatally when it cannot connect to Kafka. The unit file only specifies `After=network.target`, which is a generic marker that does not guarantee the network stack or DNS are fully operational. Consequently, the service starts prematurely, fails to connect, exits with code 1, and systemd restarts it in a loop.

**Proposed Fix:** Update `/etc/systemd/system/data-ingest.service` to wait for the network to be fully online by replacing `After=network.target` with `After=network-online.target` and adding `Wants=network-online.target` under the `[Unit]` section. Then reload the systemd daemon and restart the service:
```bash
systemctl daemon-reload
systemctl restart data-ingest.service
```
