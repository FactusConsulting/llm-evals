**Diagnosis:** The service is stuck in a restart loop because it starts before DNS resolution is fully operational. The unit file specifies `After=network.target`, which only signals that the network subsystem has initialized, not that interfaces are configured or DNS is ready. As a result, `kafka.internal` cannot be resolved, the application exits fatally, and systemd immediately attempts to restart it.

**Proposed Fix:** Edit `/etc/systemd/system/data-ingest.service` to replace `After=network.target` with `After=network-online.target` and add `Wants=network-online.target` in the `[Unit]` section. This ensures systemd waits until the network is fully online and DNS is functional before launching the service. After saving, run `systemctl daemon-reload` and `systemctl restart data-ingest.service`.
