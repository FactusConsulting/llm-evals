**Diagnosis:** The service is trapped in a restart loop because it fails to connect to `kafka.internal:9092` due to DNS resolution failure (`Name or service not known`). The unit file only declares `After=network.target`, which is a weak ordering dependency that only waits for the network management stack to initialize, not for the network to be fully online or for DNS to be functional. As a result, the application starts before DNS is ready, crashes with a fatal connection error, and systemd immediately restarts it per `Restart=always`.

**Proposed Fix:** Update the `[Unit]` section of `/etc/systemd/system/data-ingest.service` to properly wait for the network to be fully online and DNS to be available. Replace `After=network.target` with `After=network-online.target` and add `Wants=network-online.target`. Then apply the changes and restart the service:
```bash
systemctl daemon-reload
systemctl restart data-ingest.service
```
This ensures the service only launches after the network stack and DNS resolution are confirmed operational, eliminating the fatal connection error and breaking the restart loop.
