**Diagnosis:** The service is trapped in an infinite restart loop due to a DNS resolution failure for `kafka.internal`. The `ping` output confirms the hostname cannot be resolved, causing the application to exit with a fatal connection error. The unit file uses `After=network.target`, which only waits for basic network interface initialization, not for DNS resolvers to be fully operational. Combined with `Restart=always`, this guarantees continuous failures.

**Proposed Fix:** 
1. Verify and correct the host's DNS configuration (e.g., `/etc/resolv.conf` or systemd-resolved) so that `kafka.internal` resolves correctly.
2. Modify the systemd unit file to wait for full network readiness by changing `After=network.target` to `After=network-online.target` and adding `Wants=network-online.target`.
3. Run `systemctl daemon-reload` and `systemctl restart data-ingest.service` to apply the changes.
