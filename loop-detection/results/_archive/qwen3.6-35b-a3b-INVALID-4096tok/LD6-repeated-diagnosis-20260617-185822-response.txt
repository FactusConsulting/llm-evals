**Diagnosis:** The service is trapped in a restart loop because it cannot resolve the hostname `kafka.internal`. The `ping` output confirms a DNS resolution failure (`Name or service not known`), which causes the application to exit fatally. Systemd's `Restart=always` directive immediately restarts the failed process, creating the observed loop.

**Proposed Fix:** Resolve the DNS issue by verifying the DNS server configuration, ensuring the `kafka.internal` record exists and is reachable, or adding the correct IP address to `/etc/hosts`. Once DNS resolution is restored, run `systemctl restart data-ingest.service`. Additionally, update the unit file to use `After=network-online.target` and `Wants=network-online.target` to ensure DNS is fully initialized before the service starts.
