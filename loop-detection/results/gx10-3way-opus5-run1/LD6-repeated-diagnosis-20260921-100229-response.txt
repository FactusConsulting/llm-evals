**Diagnosis:** `data-ingest` exits because it cannot reach its Kafka broker. The deeper cause is that the hostname `kafka.internal` does not resolve on `ingest01`: `ping` returns `Name or service not known`. The worker treats this as fatal and exits with status 1. `Restart=always` with `RestartSec=5` then restarts it every ~5 seconds, which explains the restart counter of 47. The log's "connection refused" is almost certainly the application's generic message for a failed connect, because the name can't be resolved at all. The service unit is not the cause, since it only restarts what keeps failing.

**Proposed fix:**
1. Restore name resolution for `kafka.internal` on `ingest01`. Fix the internal DNS record or zone, or the host's resolver configuration in `/etc/resolv.conf` or systemd-resolved. As a stopgap, add a static entry to `/etc/hosts`, e.g. `10.x.x.x kafka.internal`. Once the name resolves to a live broker listening on 9092, the service will start normally.
2. Harden the unit so a dependency outage doesn't cause an endless tight restart loop:
   ```ini
   [Unit]
   After=network-online.target
   Wants=network-online.target
   StartLimitIntervalSec=300
   StartLimitBurst=10

   [Service]
   Restart=on-failure
   RestartSec=15
   ```
   Then run `systemctl daemon-reload && systemctl restart data-ingest.service`.
