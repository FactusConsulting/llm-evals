**Status:** Request Changes

**Concrete Issues:**
- `cache.go:36-44` (Get): Race condition on expiry validation. The map lookup and entry copy occur under the lock, but `time.Now().After(e.expiresAt)` is evaluated after `c.mu.Unlock()`. Between unlocking and the check, `evict()` or `Delete()` could remove the entry, causing `Get` to incorrectly return `true` for a logically deleted or expired key.
- `cache.go:26` & `cache.go:52-64` (New/evict): Goroutine leak. The background `evict` goroutine runs an infinite loop with no shutdown mechanism (e.g., `context.Context` or a stop channel). The cache cannot be safely closed or garbage collected without leaking this goroutine.
- `cache.go:54` (evict): Hardcoded 1-minute eviction interval ignores the configured `ttl`. If `ttl` is shorter than 1 minute, expired entries will linger unnecessarily. Additionally, iterating and deleting from a map under a single lock does not scale well for high-throughput caches.

**Nits/Style:**
- `cache.go:5`: Unused import `"context"`.
- `cache.go:16`: Consider `sync.RWMutex` instead of `sync.Mutex` to allow concurrent reads in `Get` without blocking `Set` or `Delete`.
- `cache.go:54`: Use `time.NewTicker` instead of `time.Sleep` for idiomatic periodic task execution.
