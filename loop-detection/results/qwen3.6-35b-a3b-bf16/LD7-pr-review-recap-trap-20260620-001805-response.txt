**Security & Architecture**
- **Secret Initialization Risk:** `jwtSecret` is generated randomly in `init()`. This invalidates all active tokens on every process restart and breaks multi-instance deployments where instances won't share the same secret. How is the signing secret configured and persisted across the environment?
- **Refresh Token Statelessness Gap:** `GenerateRefreshToken()` creates stateless tokens, but the PR explicitly removes Redis/session storage. Without a backend store, refresh tokens cannot be revoked, rotated, or validated against issuance time. How will the refresh token lifecycle be managed without state?
- **Symmetric Signing Limitation:** `HS256` requires all services to hold the exact signing secret. If verification needs to be distributed or delegated, consider `RS256`/`ES256` to allow public-key verification without exposing the private signing key.

**Code Quality & Go Idioms**
- **Context Key Collision:** Using string literals (`"userID"`, `"role"`) as context keys is unsafe in Go and risks collisions with other packages. Use typed context keys or a dedicated `context` package.
- **Error Masking in `ValidateToken`:** `jwt.ParseWithClaims` already validates the signature, expiration, and structure. Manually returning `jwt.ErrSignatureInvalid` after the type assertion masks the actual underlying error (e.g., `jwt.ErrTokenExpired`). Let `ParseWithClaims` errors propagate or use `errors.Is` for specific checks.
- **Redundant Validation:** The `token.Valid` check is redundant since `jwt.ParseWithClaims` already sets this flag and validates claims. It can be removed to simplify the flow.
- **Header Parsing Robustness:** `strings.TrimPrefix` silently accepts tokens missing the `Bearer ` prefix, passing the raw string to validation. Add explicit prefix validation (`strings.HasPrefix`) to fail fast with a clear 401 response.
- **Missing Import:** The diff uses `strings.TrimPrefix` but the `strings` package is not shown in the import block. Verify it is included in the full file.
