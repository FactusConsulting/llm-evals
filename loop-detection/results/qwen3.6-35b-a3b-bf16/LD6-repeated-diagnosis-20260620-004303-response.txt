**Diagnosis:** The service is stuck in a restart loop because the application starts before DNS resolution is available. The `After=network.target` directive in the unit file is a weak dependency that only waits for the network management stack to initialize, not for actual network connectivity or DNS resolvers to be ready. Consequently, the app fails to resolve `kafka.internal`, exits with a fatal error, and systemd immediately restarts it.

**Proposed Fix:** Update the `[Unit]` section of `/etc/systemd/system/data-ingest.service` to use the strong `network-online.target` dependency, which guarantees the network and DNS are fully initialized before the service starts:
```ini
[Unit]
Description=Data Ingest Worker
After=network-online.target
Wants=network-online.target
```
Reload the systemd configuration and restart the service:
```bash
systemctl daemon-reload
systemctl restart data-ingest.service
```
