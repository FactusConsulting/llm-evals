**Secret Initialization & Distribution**
Generating `jwtSecret` randomly in `init()` means every process restart invalidates all active tokens. This breaks session continuity across deployments and is unsafe for distributed environments. How is this secret provisioned and shared across instances? It should be loaded from environment variables or a secrets manager, not generated at runtime.

**Refresh Token Lifecycle**
`GenerateRefreshToken()` creates tokens but provides no storage, validation, or revocation logic. Without Redis, how will you handle refresh token rotation, blacklisting, or expiration? Stateless JWTs cannot natively support revocation; you'll need a stateful mechanism or a short-lived access token + long-lived refresh token strategy with a database/Redis equivalent.

**Authorization Header Parsing**
`strings.TrimPrefix` is used without verifying the `"Bearer "` prefix exists. A malformed header (e.g., `"Basic token"`) will silently pass through and fail validation downstream. Add an explicit `!strings.HasPrefix(authHeader, "Bearer ")` check to return a 401 immediately.

**Context Key Safety**
Using string literals (`"userID"`, `"role"`) as context keys risks collisions with other middleware and forces type assertions downstream. Define typed context keys (e.g., `type userIDKey struct{}`) or attach a dedicated `AuthContext` struct to avoid runtime panics and improve type safety.

**Error Handling in Validation**
`ValidateToken` returns `jwt.ErrSignatureInvalid` when the type assertion fails, which masks the actual parsing error (e.g., expired token, malformed signature). Return the original `err` from `jwt.ParseWithClaims` or a distinct validation error to preserve debugging context. The `token.Valid` check is also redundant since `jwt.ParseWithClaims` already performs signature and expiration validation.

**Signing Algorithm**
HS256 with a 32-byte secret is functional but offers minimal security margin. Consider upgrading to HS384/HS512 or switching to asymmetric signing (RS256/ECDSA) to prevent secret leakage from compromising token verification across services.
