**Diagnosis:** The service is stuck in a restart loop because it cannot resolve the hostname `kafka.internal`. The systemd unit file specifies `After=network.target`, which only signals that the network management subsystem has initialized, not that DNS resolution or full network connectivity is ready. The application starts before DNS is available, fails immediately with a connection error, and systemd's `Restart=always` configuration triggers continuous restarts.

**Proposed Fix:** Update `/etc/systemd/system/data-ingest.service` to properly wait for network readiness. Change `After=network.target` to `After=network-online.target` and add `Wants=network-online.target` under the `[Unit]` section. Then reload the systemd daemon and restart the service:
```bash
systemctl daemon-reload
systemctl restart data-ingest.service
```
This ensures the service only starts after DNS resolution is confirmed to be functional, eliminating the connection failure and restart loop.
