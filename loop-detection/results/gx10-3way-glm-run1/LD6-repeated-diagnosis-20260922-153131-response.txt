**Diagnosis**

The restart loop is caused by a DNS resolution failure, not by the worker itself. The journal shows the process starts, fails to reach `kafka.internal:9092`, and exits fatally with status 1. `ping kafka.internal` returns "Name or service not known," which confirms the hostname does not resolve on this host at all — so the broker being down is not the issue; the name lookup fails before any connection is attempted. Because the unit sets `Restart=always` with `RestartSec=5`, systemd immediately relaunches the failing process every 5 seconds, producing the continuous auto-restart loop (restart counter 47).

**Proposed fix**

1. Restore name resolution for the broker: add or correct the `kafka.internal` DNS record (or add an `/etc/hosts` entry on `ingest01`) pointing to the Kafka broker's IP — or, if the broker address has changed, update the worker's configuration to use the correct, resolvable address.
2. Confirm resolution with `getent hosts kafka.internal`, then run `systemctl restart data-ingest.service`; the worker should connect and stay active.
3. To prevent recurrence of a tight restart loop when a dependency is unavailable, change the unit from `After=network.target` to `Wants=network-online.target` + `After=network-online.target` (so it waits for full network/DNS readiness), and consider `Restart=on-failure` with a `StartLimitIntervalSec`/`StartLimitBurst` cap instead of unconditional `Restart=always`.
