**Diagnosis:**
The root cause is DNS resolution failure for the Kafka broker hostname `kafka.internal`. The `ping` output confirms the hostname is unknown ("Name or service not known"), causing the application to exit immediately with status 1 when attempting to connect. This triggers the systemd `Restart=always` directive, creating the restart loop.

**Proposed Fix:**
Configure DNS resolution for `kafka.internal` by adding the broker's IP address to `/etc/hosts` or correcting the system's DNS settings. Additionally, update the service unit file to use `After=network-online.target` instead of `network.target` to ensure full network connectivity is established before the service starts.
