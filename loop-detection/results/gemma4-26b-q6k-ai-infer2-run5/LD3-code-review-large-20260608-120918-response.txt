### Issues
- **cache/cache.go:24**: Goroutine leak. The `evict` goroutine started in `New` has no mechanism to be terminated. There should be a `Close()` method that uses a context or a stop channel to signal the background loop to exit, otherwise, these goroutines will accumulate indefinitely as new caches are created.
- **cache/cache.go:50**: Performance bottleneck / Blocking. In `evict`, the mutex `c.mu` is held for the entire duration of the map iteration. For large datasets, this blocks all other operations (`Set`, `Get`, `Delete`) for $O(N)$ time, causing significant latency spikes across the application.

### Nits
- **cache/cache.go:16**: Use `sync.RWMutex` instead of `sync.Mutex` to allow concurrent reads during `Get` calls.
- **cache/cache.go:50**: The eviction interval is hardcoded to one minute; consider making this configurable via the `New` constructor.
