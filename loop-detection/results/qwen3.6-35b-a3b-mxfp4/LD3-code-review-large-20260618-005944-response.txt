**Concrete Issues:**
- `cache/cache.go:24`: `go c.evict()` launches a background goroutine with no shutdown mechanism. This causes a goroutine leak and prevents graceful resource cleanup when the cache is garbage collected or the application needs to terminate.
- `cache/cache.go:34-42`: `Get` releases the mutex before checking expiration. This creates a race window where concurrent `Set` or `Delete` operations can occur between the unlock and the expiry check, leading to inconsistent reads. Additionally, returning `nil, false` for both missing and expired keys is ambiguous if `nil` is a valid cached value.
- `cache/cache.go:54-60`: `evict` holds the write lock while iterating over the entire map. This blocks all `Set`, `Get`, and `Delete` operations for the duration of the sweep, causing severe latency spikes and potential starvation under high concurrency.

**Nits/Style:**
- `cache/cache.go:3`: Unused import `"context"`.
- `cache/cache.go:52`: Hardcoded `time.Minute` sleep interval in `evict` should be a configurable field or replaced with `time.NewTicker` for better control.
- `cache/cache.go:14`: `sync.Mutex` should be changed to `sync.RWMutex` to allow concurrent reads in `Get` and non-blocking eviction sweeps once the lock contention is addressed.
