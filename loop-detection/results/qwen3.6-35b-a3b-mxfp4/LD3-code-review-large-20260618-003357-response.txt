**Concrete Issues:**
1. `cache/cache.go:26` - Goroutine leak: `go c.evict()` launches a background goroutine with no shutdown mechanism. If the `Cache` is garbage collected or the application terminates, this goroutine will run indefinitely. Introduce a `context.Context` or a `done` channel to allow graceful cancellation.
2. `cache/cache.go:36-44` - Race condition (TOCTOU) in `Get`: The expiration check (`time.Now().After(e.expiresAt)`) executes after `c.mu.Unlock()`. Between the unlock and the check, another goroutine could evict or overwrite the entry. Move the expiration validation inside the critical section to ensure atomicity.
3. `cache/cache.go:40-42` - Memory leak on expired access: When `Get` detects an expired entry, it returns `nil, false` but leaves the entry in the map. Expired entries should be deleted immediately while holding the lock to prevent unbounded memory growth for frequently accessed stale keys.
4. `cache/cache.go:54` - Inefficient eviction interval: `time.Sleep(time.Minute)` ignores the configured `ttl`. If `ttl` is shorter than a minute, expired entries will persist in memory unnecessarily. The sleep duration should be dynamic (e.g., `min(time.Minute, c.ttl)`) or the loop should use a ticker that adapts to the TTL.

**Nits / Style:**
1. `cache/cache.go:11` - Use `any` instead of `interface{}` to align with modern Go (1.18+) idioms.
2. `cache/cache.go:16` - Replace `sync.Mutex` with `sync.RWMutex` to allow concurrent reads in `Get` without blocking `Set` or `Delete`.
3. `cache/cache.go:54` - Prefer `time.NewTicker` over a `for` loop with `time.Sleep` for cleaner ticker lifecycle management and easier cancellation integration.
