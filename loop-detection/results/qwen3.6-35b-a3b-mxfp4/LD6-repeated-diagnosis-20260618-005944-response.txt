**Diagnosis:** The service is stuck in a restart loop because it cannot resolve the DNS name `kafka.internal`. The systemd unit file only specifies `After=network.target`, which is a generic marker that does not guarantee DNS resolution or full network connectivity are ready when the service starts. Consequently, the application fails to connect to Kafka, exits with status 1, and systemd immediately restarts it.

**Proposed Fix:** Update the `[Unit]` section of `/etc/systemd/system/data-ingest.service` to depend on `network-online.target` instead of `network.target`, and add a `Wants=network-online.target` directive. Then reload the systemd daemon and restart the service:
```ini
[Unit]
Description=Data Ingest Worker
After=network-online.target
Wants=network-online.target
```
Apply the changes with:
`systemctl daemon-reload`
`systemctl restart data-ingest.service`
