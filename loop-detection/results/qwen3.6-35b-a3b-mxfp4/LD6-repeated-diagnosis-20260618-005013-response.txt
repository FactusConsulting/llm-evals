**Diagnosis:** The service is stuck in a restart loop because it fails to resolve `kafka.internal` when it starts. The unit file only declares `After=network.target`, which is a weak ordering dependency that does not guarantee DNS resolution or full network connectivity is ready. The application crashes on startup due to the DNS failure, systemd immediately restarts it (`Restart=always`), and the cycle repeats.

**Proposed Fix:** Update the `[Unit]` section of `/etc/systemd/system/data-ingest.service` to wait for the network to be fully online before starting the service. Replace the existing dependencies with:
```ini
[Unit]
Description=Data Ingest Worker
Wants=network-online.target
After=network-online.target
```
Then apply the changes and restart the service:
```bash
systemctl daemon-reload
systemctl restart data-ingest.service
```
This ensures systemd waits for DNS and network readiness, preventing the fatal connection error and breaking the restart loop.
