**Diagnosis:** The service is stuck in a restart loop because it cannot resolve the hostname `kafka.internal`. The `ping` output confirms DNS resolution is failing when the service starts. The systemd unit only specifies `After=network.target`, which is a generic target that does not guarantee network interfaces are fully configured or that DNS resolution is available. Consequently, the service starts prematurely, fails to connect to Kafka, exits with status 1, and systemd immediately restarts it.

**Proposed Fix:** Update the `[Unit]` section of `/etc/systemd/system/data-ingest.service` to properly wait for the network to be fully online and DNS to be available. Change `After=network.target` to `After=network-online.target` and add `Wants=network-online.target`. Then apply the changes:
```bash
systemctl daemon-reload
systemctl restart data-ingest.service
```
This ensures the service only starts after DNS resolution is functional, preventing the connection failure and stopping the restart loop.
