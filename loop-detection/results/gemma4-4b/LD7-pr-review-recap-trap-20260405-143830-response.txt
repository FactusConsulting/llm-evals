*   How is the `jwtSecret` managed in production environments? Generating a random secret at runtime via `init()` is not suitable for persistent, secure deployments; a mechanism for external configuration or secrets injection is required.
*   What is the strategy for token revocation (e.g., user logout, account suspension)? Since JWTs are stateless, immediate invalidation requires a blocklist or database check, which is not currently implemented.
*   The access token expiration is hardcoded to 24 hours in `IssueToken`. Is there a plan to make this duration configurable?
*   The `GenerateRefreshToken` function exists, but the associated storage, validation, and refresh flow logic is missing. How will refresh tokens be secured and validated against potential misuse?
*   If the application scales to multiple services, how will token validation be handled if the secret needs to be shared or if asymmetric signing (RS256) becomes necessary?
*   The middleware currently treats all validation errors from `ValidateToken` as a generic "unauthorized" 401. Should specific JWT parsing errors (e.g., expired token vs. invalid signature) be differentiated for logging or client feedback?
