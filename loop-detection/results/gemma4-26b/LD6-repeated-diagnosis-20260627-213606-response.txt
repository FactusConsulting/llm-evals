**Diagnosis:**
The `data-ingest.service` is failing because it cannot resolve the hostname `kafka.internal`. The `ping` command confirms that the DNS resolution for this hostname is failing (`Name or service not known`), which prevents the application from establishing a connection to the Kafka broker. Additionally, the service unit is only dependent on `network.target`, which does not guarantee that name resolution services (like DNS) are fully operational before the service attempts to start.

**Proposed Fix:**
1. Ensure the DNS configuration or `/etc/hosts` file is correctly configured to resolve `kafka.internal`.
2. Update the `[Unit]` section of `/etc/systemd/system/data-ingest.service` to include `network-online.target` and change the dependency to `After=network-online.target` to ensure the network stack and name resolution are fully ready before execution.
