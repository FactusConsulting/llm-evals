**Concrete Issues:**
- `cache.go:26`: `go c.evict()` launches a background goroutine with no shutdown mechanism. If the `Cache` is garbage collected or reused, this causes a goroutine leak. Add a `Close()` method or accept a `context.Context` to cancel the eviction loop.
- `cache.go:41`: `Get` returns `nil, false` on expiration. This is indistinguishable from a missing key or a stored `nil` value. Return a typed result (e.g., `(value, expired bool)`) or use a sentinel error to avoid ambiguity.
- `cache.go:54`: Hardcoded `time.Sleep(time.Minute)` in the eviction loop. This prevents tuning eviction frequency based on workload or TTL. Make it configurable or derive it from `c.ttl`.

**Nits/Style:**
- `cache.go:11`: Use `any` instead of `interface{}` to align with modern Go (1.18+) conventions.
- `cache.go:21`: `New` lacks validation for `ttl <= 0`. Negative or zero TTLs will cause immediate expiration or infinite retention. Add a check and return an error or default to a minimum TTL.
- `cache_test.go:16`: `time.Sleep` in tests is flaky and blocks the test runner. Use `time.After` or `time.NewTimer` for deterministic, non-blocking timeouts.
