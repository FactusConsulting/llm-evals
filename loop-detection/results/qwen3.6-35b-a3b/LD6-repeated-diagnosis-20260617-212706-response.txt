**Diagnosis:** The service is trapped in an infinite restart loop because it cannot resolve the hostname `kafka.internal` at startup. The `After=network.target` dependency only ensures basic network interfaces are up, not that DNS resolution is functional. The application exits fatally on this failure, triggering `Restart=always`.

**Proposed Fix:**
1. Fix the DNS configuration so `kafka.internal` resolves correctly (verify `/etc/resolv.conf`, DNS server reachability, or add a static entry to `/etc/hosts` if appropriate).
2. Update the systemd unit to wait for full network/DNS readiness by replacing `After=network.target` with `After=network-online.target` and adding `Wants=network-online.target`.
3. Run `systemctl daemon-reload` and `systemctl restart data-ingest.service`.
4. Modify the application to implement connection retries with exponential backoff instead of exiting fatally on transient network/DNS failures.
