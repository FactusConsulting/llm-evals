**Diagnosis:** The service is trapped in an infinite restart loop because it cannot resolve the hostname `kafka.internal`. The unit file uses `After=network.target`, which only signals that the network subsystem has been initialized, not that DNS resolution or full network connectivity is available. The application starts prematurely, crashes on connection failure, and systemd immediately restarts it due to `Restart=always`.

**Proposed Fix:** Update the `[Unit]` section of `/etc/systemd/system/data-ingest.service` to wait for full network readiness. Replace `After=network.target` with:
```
Wants=network-online.target
After=network-online.target
```
Then apply the changes and restart the service:
```bash
systemctl daemon-reload
systemctl restart data-ingest.service
```
This ensures DNS and network interfaces are fully configured before the worker attempts to connect to Kafka.
