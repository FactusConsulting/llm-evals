**Diagnosis:** The service is crashing because it starts before DNS resolution is available. The unit file specifies `After=network.target`, which only signals that the network subsystem has been initialized, not that network interfaces are fully configured or DNS is operational. As a result, `kafka.internal` cannot be resolved, the application exits with a fatal error, and systemd enters an auto-restart loop.

**Proposed Fix:** Update the `[Unit]` section of `/etc/systemd/system/data-ingest.service` to wait for the network to be fully online by replacing `After=network.target` with `After=network-online.target` and adding `Wants=network-online.target`. Then apply the changes and restart the service:
```bash
systemctl daemon-reload
systemctl restart data-ingest.service
```
