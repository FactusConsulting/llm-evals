**Root Cause:**
The service is stuck in a restart loop because it cannot resolve the hostname `kafka.internal`. The unit file specifies `After=network.target`, which only indicates that the network management stack has started, not that DNS or actual network connectivity is available. The service starts before DNS is ready, fails to resolve the Kafka broker address, exits with status 1, and systemd immediately restarts it due to `Restart=always`.

**Proposed Fix:**
Update the `[Unit]` section of `/etc/systemd/system/data-ingest.service` to wait for the network to be fully online and DNS to be functional:

```ini
[Unit]
Description=Data Ingest Worker
After=network-online.target
Wants=network-online.target
```

Apply the change and restart the service:
```bash
systemctl daemon-reload
systemctl restart data-ingest.service
```
