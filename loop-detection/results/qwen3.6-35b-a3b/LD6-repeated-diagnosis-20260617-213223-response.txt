**Diagnosis:** The service is trapped in an auto-restart loop because it starts before DNS resolution is available. The unit file specifies `After=network.target`, which only signals that the network management stack has initialized, not that DNS or actual network connectivity is ready. Consequently, the application fails to resolve `kafka.internal`, crashes with a fatal error, and systemd's `Restart=always` policy immediately restarts it.

**Proposed Fix:** Modify the `[Unit]` section of `/etc/systemd/system/data-ingest.service` to replace `After=network.target` with `After=network-online.target` and add `Wants=network-online.target`. This ensures systemd waits until the network is fully up and DNS is operational before launching the service. After saving the changes, run `systemctl daemon-reload` and `systemctl restart data-ingest.service`.
