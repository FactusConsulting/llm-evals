**Secret Lifecycle & Configuration**
The `jwtSecret` is generated in `init()` and held in memory. This means every application restart invalidates all active tokens, causing unexpected user logouts during deployments. Additionally, in-memory generation prevents key rotation. This should be configurable via environment variables or a secrets manager, and the restart behavior should be explicitly documented.

**Refresh Token Architecture**
`GenerateRefreshToken()` produces a random string but provides no storage, validation, or revocation mechanism. Without server-side persistence, refresh tokens cannot be rotated, tracked, or invalidated upon logout or compromise. How does this align with the stated removal of Redis? If refresh tokens are intended to be stateless, they effectively become long-lived access tokens, which contradicts standard JWT security practices.

**Context Key Safety**
Using string literals (`"userID"`, `"role"`) as context keys is a known Go anti-pattern. It risks collisions with other middleware or packages and lacks type safety. Define unexported context key types (e.g., `type userIDKey struct{}`) and use those for `context.WithValue`.

**Token Validation Redundancy**
In `ValidateToken`, `jwt.ParseWithClaims` already validates the signature, expiration, and claims structure. If it returns successfully, `token.Valid` is guaranteed to be true. The subsequent type assertion and `token.Valid` check are redundant. Simplify to return the claims directly after the error check, or clarify if additional custom validation is intended.

**Header Parsing & Error Handling**
`strings.TrimPrefix` is applied to the `Authorization` header without verifying it actually contains the `Bearer ` prefix. Malformed headers will be passed to validation and fail silently with a generic 401. Consider validating the header format first and returning a `400 Bad Request` for malformed requests to improve client debugging and security posture.

**Cryptographic Parameters**
HS256 requires a minimum secret length of 256 bits (32 bytes). The current implementation uses exactly 32 bytes, which is the absolute minimum. For better security margins, consider increasing to 64 bytes or switching to HS512, especially since the secret is currently hardcoded to a fixed length.
