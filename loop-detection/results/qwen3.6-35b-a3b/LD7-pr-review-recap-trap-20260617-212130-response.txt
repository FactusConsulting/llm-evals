**auth/jwt.go**
- **Secret Generation on Restart:** Generating `jwtSecret` randomly in `init()` means every application restart invalidates all active tokens, causing unexpected user logouts. The secret must be deterministic across restarts (e.g., loaded from environment variables or a secrets manager).
- **Refresh Token Persistence:** `GenerateRefreshToken()` returns a random string but does not persist it or bind it to a user/session. Without storage and a revocation mechanism, this token is functionally useless and insecure. How is this token stored, and where is the validation/invalidation logic?
- **Claims Validation:** `ValidateToken` returns claims without validating their contents. Empty or malformed `userID`/`role` values could pass through. Add explicit validation for claim formats before returning them.

**auth/middleware.go**
- **Bearer Prefix Handling:** `strings.TrimPrefix(authHeader, "Bearer ")` does not validate the prefix. Headers like `"Bearer "` or `"Basic xyz"` will pass through, resulting in malformed token strings. Use `strings.HasPrefix` to verify the prefix, slice the remainder, and explicitly reject empty tokens.
- **Context Key Safety:** Using string literals (`"userID"`, `"role"`) as context keys is unsafe. Any other middleware or package using the same string will overwrite or conflict with these values. Define unexported custom types for context keys to ensure type safety and prevent collisions.
- **Error Granularity:** Both missing headers and invalid tokens return a generic `401`. Consider distinguishing between authentication failures (missing/invalid token) and logging the specific error internally to aid debugging without leaking sensitive details to the client.
