**Status:** Request Changes

**Concrete Issues:**
1. `cache.go`, lines 52-63: `evict()` runs indefinitely with no cancellation mechanism. If the `Cache` is replaced or garbage collected, the goroutine will leak. Add a `context.Context` or a `done` channel to `New` and pass it to `evict` to allow graceful shutdown.
2. `cache.go`, line 54: `time.Sleep(time.Minute)` is hardcoded and ignores the configured `ttl`. With a short TTL (e.g., 100ms), expired entries will persist for up to 60 seconds, causing memory bloat and defeating the purpose of the cache. The sleep interval should be derived from `c.ttl` or use a ticker.
3. `cache.go`, lines 36-44: `Get` checks expiration outside the lock and returns `nil, false` for expired entries without removing them. This delays cleanup until the next eviction cycle, causing unnecessary memory retention and potential stale reads during concurrent access. Move the expiry check inside the lock and delete the entry immediately to ensure atomicity.

**Nits/Style:**
1. `cache.go`, line 54: Prefer `time.NewTicker` over `time.Sleep` in a loop for more accurate scheduling and easier cancellation.
2. `cache_test.go`, line 16: `time.Sleep` in tests is flaky and CI-unsafe. Use `time.After` or a ticker with a timeout to make the test deterministic.
3. `cache.go`, line 36: `Get` returns `interface{}`, forcing callers to perform type assertions. Consider using Go generics (`func (c *Cache) Get[V any](key string) (V, bool)`) if the codebase supports Go 1.18+.
