- `cache/cache.go:41`: Goroutine leak. The `evict` goroutine runs an infinite loop with no mechanism (such as a `context.Context` or a stop channel) to terminate, meaning the goroutine will leak for the lifetime of the application even if the `Cache` instance is no longer used.
- `cache/cache.go:58`: Performance/Contention. The `evict` method holds the mutex lock for the entire duration of the map iteration. This will block all `Get`, `Set`, and `Delete` operations for the duration of the cleanup, causing significant latency spikes as the cache grows.

- `cache/cache.go:42`: The eviction interval is hardcoded to one minute; consider making this configurable via `New`.
