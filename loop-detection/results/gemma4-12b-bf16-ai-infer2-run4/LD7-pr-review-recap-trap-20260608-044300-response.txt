### PR Review

**Security & Architecture Risks:**

*   **Ephemeral Secret Generation:** The `jwtSecret` is generated using `rand.Read` inside an `init()` function. This causes all active user sessions to be invalidated every time the application restarts or the pod/container cycles. We need to move this to a persistent configuration (e.g., environment variable or Secret Manager).
*   **Horizontal Scaling Issue:** Because each instance generates its own unique `jwtSecret` at startup, requests will fail if they hit a different instance than the one that issued the token. A shared secret across all instances is required.
*   **Lack of Revocation Mechanism:** By moving to stateless JWTs without a revocation list or "blacklist" check, we lose the ability to immediately invalidate a compromised token or force a logout before the 24-hour expiration. How do we plan to handle account suspensions or manual logouts?
*   **Symmetric vs. Asymmetric Signing:** Using HS256 requires every service that validates the token to have access to the private signing key. Consider switching to RS256 so that downstream services only need the public key for verification.
*   **Context Key Collisions:** In `middleware.go`, context keys are being set as raw strings (`"userID"`, `"role"`). These should use custom types to prevent collisions with other middlewares or third-party libraries.

**Implementation Questions:**

*   **Refresh Token Persistence:** The PR mentions removing Redis dependency, but there is no logic shown for where the `GenerateRefreshToken` output is stored. If it's not in Redis, how are we persisting refresh tokens to validate them during the rotation flow?
*   **Token Expiry Policy:** Is a hardcoded 24-hour expiry appropriate for all user roles? Should this be configurable based on the user's permission level?
*   **Error Handling:** In `ValidateToken`, if `jwt.ParseWithClaims` returns an error, the code returns the raw error from the library. We should ensure these errors don't leak internal implementation details (like signature mismatch specifics) to the client.
