This PR introduces JWT-based authentication, removing Redis for session storage. Key concerns:

1. **JWT Secret Management**: The secret is generated at init() and stored in memory. How is this secret rotated? What happens on server restarts? No configuration for secret rotation or external secret management.

2. **Token Expiration**: Tokens expire after 24 hours. Is there a mechanism for token refresh? The PR adds GenerateRefreshToken but no refresh endpoint or logic in middleware.

3. **Security Risks**: 
   - No token revocation mechanism. How to handle compromised tokens?
   - Hardcoded HS256 algorithm. Should this be configurable?
   - No rate limiting on token validation.

4. **Middleware Changes**: 
   - Authorization header is now required. How does this affect existing clients?
   - No fallback for legacy session cookies during transition.

5. **Error Handling**: 
   - ValidateToken returns ErrSignatureInvalid on invalid claims. Should this be a more specific error?
   - No logging for failed authentication attempts.

6. **Testing**: 
   - No tests for JWT validation edge cases (expired tokens, invalid signatures).
   - No tests for refresh token generation.

7. **Documentation**: 
   - No updated API documentation for new auth flow.
   - No instructions for clients to update to JWT-based auth.

These issues need addressing before merging.
