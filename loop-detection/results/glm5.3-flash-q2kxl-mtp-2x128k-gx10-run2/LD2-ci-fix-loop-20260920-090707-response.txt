## 1. Diagnosis — why attempts 1 and 2 failed

The decisive fact: `*sql.DB` from `database/sql` **already implements `Close() error`** natively (`func (db *DB) Close() error`). A `*sql.DB` value therefore cannot be reported as failing the `Store` check on `Close` if `Store` declares `Close() error` — it would satisfy it for free. Since the compiler does report it, the only consistent conclusion is:

**`Store` declares `Close` with a different signature than `Close() error`** (e.g. `Close()`, `Close() bool`, `Close(ctx context.Context) error`, etc.). The error's own wording — "missing method Close **with correct signature**" — points at a signature mismatch, not an absent method name.

Both prior attempts failed for the same two compounding reasons:

1. **Wrong signature.** They added `Close() error` — precisely the signature `Store` does *not* require. Even applied to the correct type, the interface check would still fail.
2. **Wrong target.** The log says the stub was added to a "sql.DB wrapper", but `store.go:47` passes the raw `db` variable of type `*sql.DB`. Go also forbids defining methods on types owned by another package, so the stub could only exist on a wrapper type that never reaches the `NewCache` call site. From the compiler's viewpoint at line 47, nothing changed — hence byte-identical errors on both runs.

A third `Close() error` stub is therefore guaranteed to fail identically. The fix must match `Store`'s actual declared signature, not guess it.
