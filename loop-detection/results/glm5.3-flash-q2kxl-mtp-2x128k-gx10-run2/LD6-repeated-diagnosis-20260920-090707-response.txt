**Diagnosis**

The restart loop is caused by a DNS resolution failure for the Kafka broker hostname. The worker starts, attempts to connect to `kafka.internal:9092`, fails, and exits with status 1; because the unit has `Restart=always` with `RestartSec=5`, systemd relaunches it every 5 seconds (restart counter 47 ≈ 30 minutes of looping). The decisive evidence is `ping kafka.internal` → `Name or service not known`: the hostname does not resolve on this host at all. This rules out Kafka being down or a firewall/network issue — if the name resolved, the failure mode would be different. The unit file design compounds the problem: `After=network.target` does not guarantee DNS availability at start, and `Restart=always` with a fixed 5-second delay and no rate limiting guarantees an infinite crash loop whenever the broker is unreachable.

**Proposed fix**

1. Restore name resolution for `kafka.internal` on `ingest01`: repair the missing/stale DNS record or add a correct `/etc/hosts` entry — or, if the broker address changed, update the worker's configuration to the correct broker. Then restart the service.
2. Harden the unit so an unreachable broker cannot produce an infinite rapid loop:
   - Replace `After=network.target` with `Wants=network-online.target` and `After=network-online.target`, so DNS/network is actually up before the worker starts.
   - Change `Restart=always` to `Restart=on-failure` and add `StartLimitIntervalSec=300` / `StartLimitBurst=5` to cap repeated failures.
   - Ideally, make the worker retry its Kafka connection with backoff internally instead of exiting immediately on the first failed connect.
