**Review: Block**

**Concrete Issues**

1. **Race condition in `Get`** — `cache/cache.go:30-36`  
   The mutex is unlocked before checking `expiresAt`. A concurrent `Delete` or `Set` can occur between the unlock and the expiry check, causing `Get` to return a stale value or an entry that has already been replaced. The expiry check must be performed while holding the lock.

2. **Goroutine leak** — `cache/cache.go:15, 40-50`  
   The `evict` goroutine runs forever with no stop mechanism. Every call to `New` leaks a goroutine that persists even after the `Cache` is no longer referenced. Add a `done` channel or `context.Context` and a `Close` method to terminate the goroutine.

3. **Unvalidated TTL** — `cache/cache.go:10, 22`  
   If `ttl <= 0`, entries expire immediately (`time.Now().Add(c.ttl)` yields a past timestamp). If a zero TTL is intended to mean "no expiry", this is a correctness bug. Document the expected behavior or validate the input.

**Nits**

- The eviction interval is hardcoded to `time.Minute`; consider making it configurable or a package-level constant.
- Use `sync.RWMutex` to allow concurrent reads without blocking on writes.
- The tests rely on `time.Sleep`, which is flaky; prefer a polling pattern or `require.Eventually`.
