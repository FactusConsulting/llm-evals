**Decision: Block**

**Issues**
- `cache/cache.go:5` — `context` is imported but never used. The package will not compile (`imported and not used`). Remove the import or actually use it.
- `cache/cache.go:26,52-64` — `New` starts an infinite `evict` goroutine with no shutdown path. Every `New` leaks a goroutine and keeps the cache/map reachable forever; the tests also leak goroutines. Add a `Close`/`Stop` mechanism and a `done` channel/context, or avoid the background goroutine.
- `cache/cache.go:38-40` — `Get` reads `e` under the lock but checks `expiresAt` after unlocking. A concurrent `Set` can replace the entry between the read and the expiry check, causing `Get` to return `false` for a key that is now valid. Check expiry while holding the lock and delete the expired entry there.
- `cache/cache.go:54` — eviction runs every minute regardless of `ttl`. With short TTLs (e.g., `100ms` in the test), expired entries remain in the map for up to a minute, retaining memory. Tie eviction cadence to `ttl` or evict expired entries on `Get`/`Set`.

**Nits**
- `cache/cache.go:16` — `sync.Mutex` serializes all reads; use `sync.RWMutex` with `RLock` for `Get` if reads dominate.
- `cache/cache.go:11` — use `any` instead of `interface{}` for modern Go style.
- `cache/cache_test.go:16` — real `time.Sleep(200 * time.Millisecond)` makes the test slow and potentially flaky; use a fake clock or a deterministic expiry test.
