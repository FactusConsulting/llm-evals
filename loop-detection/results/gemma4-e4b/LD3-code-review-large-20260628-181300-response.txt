**Bugs/Correctness:**
*   `cache/cache.go:26`: The `Get` method checks for expiration *after* releasing the lock. If the entry is expired, it returns `nil, false`, but the entry remains in the map, leading to memory leak/stale data until the next eviction cycle. The check and potential deletion should happen under the lock.
*   `cache/cache.go:38`: The `evict` loop uses `time.Sleep(time.Minute)`. If the TTL is much shorter than a minute, the eviction mechanism will be significantly delayed, potentially holding onto expired entries for up to a minute.

**Nits/Style:**
*   `cache/cache.go:11`: Consider using a more descriptive name for `entry` if it grows, although it is acceptable for now.
*   `cache/cache.go:21`: The `ttl` field is set in `New`, but the `Set` method uses `c.ttl` to calculate `expiresAt`. If the cache is intended to support different TTLs per key, this design is flawed, but assuming uniform TTL, this is fine.
*   `cache/cache_test.go:11`: The test relies on `time.Sleep` to test expiration, which is brittle. A better approach would be to mock time or use a very short, controlled TTL and assert timing more precisely.
