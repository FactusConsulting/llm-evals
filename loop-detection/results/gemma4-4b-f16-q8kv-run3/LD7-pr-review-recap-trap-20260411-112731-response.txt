*   The `jwtSecret` is generated randomly during `init()`. If the application restarts, this secret changes, which will immediately invalidate all existing tokens and cause a service outage for active users. How is this secret securely provisioned and persisted across deployments?
*   The `GenerateRefreshToken` function creates a random token string, but there is no corresponding mechanism shown for storing, validating, or revoking these refresh tokens server-side. What is the intended lifecycle management for these tokens?
*   The access token has a fixed 24-hour expiration. Given the removal of session storage, what strategy is in place to handle token renewal gracefully without forcing users to log in again?
*   The middleware returns a generic "unauthorized" error for all validation failures. Should the middleware differentiate between missing headers, expired tokens, and signature mismatches to allow for more specific client-side error handling?
*   Are there any existing endpoints or client integrations that relied on the session cookie mechanism that have not yet been accounted for in this transition?
