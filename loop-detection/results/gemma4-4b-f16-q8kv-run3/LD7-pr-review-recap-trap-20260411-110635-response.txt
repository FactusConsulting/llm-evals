*   The JWT secret is generated randomly during `init()`. What is the strategy for managing this secret across deployments, and how will token validity be maintained if the application restarts and generates a new secret?
*   Since JWTs are stateless, how will immediate token revocation (e.g., user logout, administrative ban) be enforced before the token's expiration time?
*   The `GenerateRefreshToken` function exists, but there is no corresponding storage or validation mechanism shown. What is the intended lifecycle and storage mechanism for these refresh tokens?
*   The token expiration is hardcoded to 24 hours in `IssueToken`. Is this fixed duration appropriate for all user roles, or should this be configurable or role-dependent?
*   The middleware strictly requires the `Authorization: Bearer` header. Are there any existing client integrations or endpoints that might still rely on cookie-based authentication that need a transitional path?
