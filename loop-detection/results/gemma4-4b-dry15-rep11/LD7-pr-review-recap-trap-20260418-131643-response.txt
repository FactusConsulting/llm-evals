### PR Review: LD7 — JWT Refactor

**Security & Implementation Concerns:**

1.  **JWT Secret Management:** The current approach initializes `jwtSecret` using `crypto/rand` during package initialization. Given that this is a critical security component, should the secret be loaded from environment variables or a dedicated secrets manager instead of relying on runtime generation? Furthermore, what safeguards are in place to ensure sufficient cryptographic entropy is available when the application first boots?
2.  **Hardcoded Expiration:** The token lifespan is currently fixed at 24 hours within `IssueToken`. Should this duration be configurable via an environment variable or configuration file to allow for operational flexibility?
3.  **Refresh Token Lifecycle:** The function `GenerateRefreshToken` creates a secure random identifier, but the associated persistence, revocation mechanisms, and usage flow for these tokens are not visible here. How will these generated tokens be validated against active sessions, and what is the intended lifecycle management strategy (e.g., rotation, expiration)?
4.  **Middleware Input Validation:** In `AuthMiddleware`, there is no explicit check for the format of the `Authorization` header beyond checking for its presence. If the header contains non-"Bearer " prefixes, `strings.TrimPrefix` might behave unexpectedly or silently fail, potentially leading to incorrect authorization attempts.

**Architectural & Design Questions:**

5.  **Access Control Granularity:** This middleware successfully authenticates the user based on the token claims (`userID`, `role`). However, does this layer enforce fine-grained Role-Based Access Control (RBAC)? Or is it assumed that subsequent handlers must perform additional checks based on the retrieved role stored in the context? Clarification on where access policy enforcement resides is needed.
6.  **Context Usage Safety:** While passing `UserID` and `Role` into the context is standard, please confirm that downstream services consuming this context are aware of potential concurrency risks and handle context values immutably, especially if multiple layers modify the request object.
