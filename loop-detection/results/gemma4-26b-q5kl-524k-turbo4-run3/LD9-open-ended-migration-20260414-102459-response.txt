**Risks**
* **Downtime:** In-place upgrades on managed services cause downtime; logical replication is required to minimize service interruption.
* **Data Integrity:** Risk of data divergence or loss if logical replication is misconfigured or interrupted.
* **Compatibility:** Potential breaking changes in PostgreSQL 16 or incompatibilities with existing extensions.
* **Performance:** Changes in the PostgreSQL 16 query planner may impact payment processing latency.

**Prerequisites**
* **Snapshot:** A verified manual snapshot of the current PostgreSQL 14 instance.
* **WAL Configuration:** `wal_level` must be set to `logical` on the PostgreSQL 14 instance.
* **Client Compatibility:** Verification that `psycopg2` 2.9.3 and the container's `libpq` are compatible with PostgreSQL 16.
* **Extension Audit:** Confirmation that all currently used extensions are supported in PostgreSQL 16.

**Migration Plan**
1. [Human Approval] Schedule maintenance window.
2. Create a manual snapshot of the PostgreSQL 14 instance.
3. Verify `wal_level` is set to `logical` on the PostgreSQL 14 instance.
4. Provision a new PostgreSQL 16 instance on DigitalOcean.
5. Install and verify all required extensions on the PostgreSQL 16 instance.
6. Establish logical replication from the PostgreSQL 14 instance to the PostgreSQL 16 instance.
7. Monitor replication lag to ensure the PostgreSQL 16 instance is synchronized.
8. [Human Approval] Approve cutover.
9. Scale the Kubernetes deployment to 0 replicas to stop all application writes.
10. Confirm replication lag reaches zero.
11. Update Kubernetes Secrets/ConfigMaps with the new PostgreSQL 16 connection string.
12. Scale the Kubernetes deployment to the original replica count.
13. Run automated smoke tests against the new instance.
14. [Human Approval] Final production sign-off.
