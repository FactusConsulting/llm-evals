**Request changes**

**Concrete issues:**
1. **cache/cache.go:13-16 (evict function)** - The eviction goroutine runs an infinite loop with a fixed `time.Sleep(time.Minute)` delay. This can cause significant latency in removing expired entries (up to one minute). Consider using a time.Ticker or a more frequent sleep interval, and provide a way to stop the goroutine (e.g., a context) to avoid a memory leak when the cache is no longer used.
2. **cache/cache.go:13-16 (evict function)** - The eviction loop iterates over `c.entries` while holding `c.mu`. If the map is large, this can block `Set`, `Get`, and `Delete` operations for a noticeable duration each minute. A safer approach is to copy the keys to evict while holding the lock, then release the lock before performing deletions.
3. **cache/cache.go:13-16 (evict function)** - There is no mechanism to shut down the eviction goroutine. If the `Cache` instance is discarded, the goroutine continues running indefinitely, potentially holding references to the `Cache` and preventing garbage collection. Introduce a context or a close channel to terminate the loop gracefully.

**Style nits (≤3):**
1. **cache/cache.go:10** - The `entry` struct fields (`value` and `expiresAt`) are lowercase, which makes them unexported. If these fields are only used internally (which they are), this is fine, but consider renaming them to `Value` and `ExpiresAt` for consistency with the exported `Cache` type, or keep them lowercase and add a comment explaining the intentional internal encapsulation.
2. **cache/cache_test.go:9 (TestSetGet)** - The test sleeps for `200 * time.Millisecond` to wait for expiration. Using `time.After` or a small loop with `time.Sleep` and a deadline would be more robust against flaky tests on slower machines.
3. **cache/cache_test.go:17 (TestDelete)** - The test sets a very long TTL (`time.Hour`) but never waits for it. While the test's purpose is to verify deletion, adding a short sleep or using a deadline would guard against race conditions if the eviction goroutine runs concurrently.
