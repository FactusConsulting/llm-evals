SCENARIO: LD5 — State Tracking Across Steps
CATEGORY: state-tracking
DIFFICULTY: high

---

You are auditing Kubernetes resource limits across a cluster. You will be given tool output one batch at a time. After each batch, you update your running tally. After the final batch, you produce a summary.

Maintain a running table with columns: Namespace | Deployment | CPU Request | Memory Request | Has Limits? (yes/no)

BATCH 1:
```
Namespace: payments
  deployment/payments-api         cpu: 250m  mem: 512Mi  limits: yes
  deployment/payments-worker      cpu: 100m  mem: 256Mi  limits: no
  deployment/fraud-detector       cpu: 500m  mem: 1Gi    limits: yes
```

After processing batch 1, output your current table. Then continue.

BATCH 2:
```
Namespace: notifications
  deployment/email-sender         cpu: 50m   mem: 128Mi  limits: no
  deployment/sms-gateway          cpu: 200m  mem: 512Mi  limits: yes
Namespace: logging
  deployment/log-aggregator       cpu: 1000m mem: 2Gi    limits: no
  deployment/log-shipper          cpu: 100m  mem: 256Mi  limits: yes
```

After processing batch 2, output your updated table (all rows so far). Then continue.

BATCH 3:
```
Namespace: payments
  deployment/payments-db-proxy    cpu: 300m  mem: 768Mi  limits: yes
Namespace: platform
  deployment/feature-flags        cpu: 50m   mem: 64Mi   limits: no
  deployment/config-service       cpu: 100m  mem: 128Mi  limits: yes
```

After processing batch 3, output your final complete table. Then answer:
- How many deployments are missing limits?
- Which namespace has the highest total CPU request?

Stop after answering these two questions. Do not speculate about additional remediation steps.
